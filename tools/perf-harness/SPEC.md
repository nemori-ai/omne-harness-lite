# @omne-harness/perf-harness

## 总体架构

perf-harness 是性能评测的设施。它回答四件事：一份结果是在什么机器、什么状态下跑出来的；两份结果能不能比；一组读数过没过门；候选相对基准是变快、变慢、没有变化，还是判不了。本成员不发布。

它不认识被测对象。问的是什么、怎样起被测对象、读数从哪来，都由套件带来；套件在顶层 `benchmarks/`，依赖本成员。命令经根脚本 `pnpm run perf` 进入，入口在 `benchmarks/src/cli.ts`，参数与退出码见 `pnpm run perf -- help`。入口用的是本成员的构建产物，改了本成员要先构建。

| 部分 | 目录 | 回答什么 |
| --- | --- | --- |
| 运行环境记录 | `src/environment` | 机器的身份、被测对象、当时的状态、首尾探针；三个标识；时间读数可不可信 |
| 判定 | `src/judgment` | 可比表、规模门、计数门、成对比较、等价、一次运行里逐轮的增长 |
| 结果 | `src/result` | 结果的形状与读写、计数基线、报告 |
| 套件与命令 | `src/suite`、`src/cli.ts` | 套件的契约、改了哪些文件要重跑谁、成对比较的轮次、五条命令 |

## 领域边界

本成员拥有：运行环境记录的字段与取法、三个标识的算法、可比表、各道门与成对比较的判定、结果与计数基线的格式、报告的版式、套件的契约。

本成员不拥有：

- 被测对象的代价模型、负载、场景、门的期望值：归各套件与 [`benchmarks/SPEC.md`](../../benchmarks/SPEC.md)。
- 读数的口径（一步、一次存储读、一次提交）：归 [`packages/storage/SPEC.md`](../../packages/storage/SPEC.md) 的「读数」与 `benchmarks/SPEC.md`。
- 整机运行名额：归 `scripts/with-test-slot.mjs`。`run` 与 `compare` 由入口排进名额，本成员只记录这一次持没持有。
- 性能结论要带哪些条件：归[质量论证](../../docs/architecture/assurance.md#证据与有效范围)。

## 心智模型

- 读数分四类，能不能比各不相同。由步骤决定的计数（`count`）与机器无关，问的是同一件事就能逐项比。时间（`time`）离不开机器与当时的状态，仓库里留着的时间读数只作参考。跟着时钟走的计数（`clocked`）是被测对象在等待时按时间做的事的次数，机器快慢会改变它，所以照时间那样对待，不照计数。没有量纲的比值（`ratio`）在同一台机器上才是一个数。
- 时间类的结论只出自同一次运行里的成对比较。噪声每次现量：基准自己再跑一次，两次的差就是这台机器此刻的噪声。
- 判不了就是判不了。门有三个值：通过、失败、阻塞；成对比较有四个值。阻塞与证据不足都不算通过。
- 一道门先要证明自己判得出错：每道门带一个必过样本与一个必败样本，样本的结局不对，这道门按阻塞算。
- 结果要进公开的仓库，所以记录里没有机器名、用户名、家目录路径与网络地址。取法上就不读这些，不靠事后擦。

## 应然设计

### 运行环境记录

每份结果带四块：

| 块 | 内容 | 用途 |
| --- | --- | --- |
| 机器的身份 | 处理器（型号、架构、插槽、核、每核线程、可用逻辑核、二三级缓存、调频策略、漏洞缓解的摘要）；内存（总量、交换区、透明大页、内存节点）；虚拟化（种类、厂商、机型、容器限额）；系统（发行版、内核主次版本、时钟源、地址空间随机化）；数据目录所在的文件系统与设备（类型、挂载选项、设备类别、调度器）；运行时（Node、V8、SQLite 版本与编译选项摘要、堆选项、线程池） | 算机器配置标识 |
| 被测对象 | 提交、工作树脏不脏、是不是发行产物、装配、负载 | 算装配标识与负载标识 |
| 当时的状态 | 起止时刻；前后的负载；别的进程占的处理器、被宿主机拿走的时间、等盘时间各自的占比；可用内存的起点与最低点；换页量；温控降频次数；数据盘已用比例；持没持有运行名额；占处理器最多的几个别的命令，只记命令名 | 判时间读数可不可信 |
| 探针 | 首尾各一次：一段固定的单线程计算；数据目录下固定次数的小写入加同步；同样设置下固定次数的 SQLite 单行提交。后两样取中位与高分位 | 首尾差得多是这一次有噪声；和本机基线差得多是机器漂了 |

- 取不到的字段写 `unknown` 并写原因，不留空也不猜。不是 Linux 的机器上，机器的身份里靠 `/proc` 与 `/sys` 的字段都是 `unknown`。
- 内核的完整版本与微码只记在旁边，不进标识。
- 探针的临时文件建在数据目录下，用完删掉。
- 机器的事实经一个读取口取（读文件、列目录、解析链接、跑命令、查已用比例），测试换成描述出来的机器。

### 三个标识

- 负载标识 `wl-`：问的是什么。装配标识 `asm-`：被测对象怎样配的。机器配置标识 `cfg-`：在哪跑的，只由机器的身份算出，不含状态。
- 算法：值写成键有序的规范文本，取 SHA-256 的前 12 个十六进制字符。键的先后不影响标识。

### 时间读数可不可信

| 情形 | 时间读数 | 能不能当基线 |
| --- | --- | --- |
| 数据目录在内存文件系统上 | 阻塞 | 不能 |
| Node 的版本不是仓库钉的那个 | 阻塞 | 不能 |
| 首尾探针相差超过一成；开跑前一分钟负载超过可用核数的四分之一；被宿主机拿走的时间超过百分之二 | 可读，状态不合格 | 不能 |
| 工作树脏，或不知道脏不脏 | 可读 | 不能 |
| 探针相对本机基线偏离超过百分之十五 | 可读，探针没守住 | 不影响 |

四条线是候选值，时间类基线标定时用实测校一次。计数不受这张表影响。

### 可比表

| 读数 | 可以比的条件 | 不满足时 |
| --- | --- | --- |
| 由步骤决定的计数 | 负载标识、装配标识、设施主版本相同 | 拒绝，说明哪一个不同 |
| 时间的绝对值，跟着时钟走的计数 | 上一行的条件，加机器配置标识相同、两边状态合格、探针守住 | 阻塞，说明差在哪 |
| 没有量纲的比值 | 上一行的前三个标识相同，两边状态合格 | 状态不合格阻塞；跨机器只并排列，不合成一个数 |

时间的绝对值与跟着时钟走的计数满足条件时也只并排列，不当门。

### 门

- 规模门：一个不该随规模变的读数，在逐档翻倍的规模上各取一个值；每一档不超过前一档的 `1 + 余量` 倍才通过。余量是套件给的常数，缺省为零。每翻一倍涨多少只报告，不参加判定。档不足两个、不是逐档翻倍、某一档没有值，都是阻塞。
- 计数门：实测等于期望值才通过。期望值由套件给，带出处（代价模型的哪一栏）与设计预算；期望值高于设计预算而没有接受记录，判失败。没有期望值是阻塞。
- 增长门与中位门：一次运行 200 轮的一条曲线。中位门拿第 181 到 200 轮的中位数比第 11 到 30 轮的，不超过 1.5 倍通过。增长门把第 11 到 200 轮分成 19 块取块中位数做线性回归，斜率为正、R² 不低于 0.95、预测涨幅超过残差绝对中位差的 3 倍，三条都中才判增长。只用于逐轮的时间类曲线。
- 一道已知会失败的门带接受记录（卡号与原因）：失败时这道门算通过并写明；它不再失败时算失败，提示撤掉接受记录。
- 一份结果的结局：有失败是失败；没有门、或有阻塞，是阻塞；否则通过。

### 成对比较

- 每一轮跑三边：基准、基准再跑一次、候选。三边的先后逐轮轮换，六轮里每一边在每个位置各两次。每一边的每个样本是一个新进程，由套件保证。
- 噪声带是「基准再跑一次」相对基准的变化量的四分位区间；候选的变化量同样取四分位区间与中位数。
- 判定过两关、出四值：候选的区间整个在噪声带之外，而且中位变化不小于「值得管的最小变化」（时间类缺省百分之五），判变快或变慢；噪声带与候选的区间都在正负最小变化之内，判没有变化；其余判证据不足。
- 轮数不少于 10。每轮之后看能不能判，能判就停；到 30 轮仍判不了，报证据不足。
- 一个样本带一组带噪声的读数（墙钟、处理器时间、跟着时钟走的计数），每个读数各判一次；第一个读数决定轮次什么时候停。各读数可以有自己的最小变化，由套件写明，没写的用缺省。主读数是中位变化，另列各边的最小值。任何一个读数判变慢，这次比较就算候选变差。
- 等价先于快慢：每轮先比三边在测量边界上留下的摘要序列。基准两次不同，判输出不稳定、不可判；候选与基准不同，不判快慢，并指出第一处不同。

### 结果、基线与报告

- 一份结果是一个目录里的 `result.json`：设施名与主版本、套件、档、三个标识、运行环境记录、时间读数可不可信、读数、门、样本、摘要序列、这些读数没盖住什么。
- 计数基线一个套件一档一份，放在 `benchmarks/baselines/<套件>.<档>.json`：两个标识、提交、由步骤决定的计数、摘要序列。脏的或不知道脏不脏的工作树出的结果写不成基线。时间与跟着时钟走的计数不进基线。
- 对比计数先照可比表判，再逐项比；没有基线是阻塞。
- 计数也有自对照：比两个提交时基准量两遍。两遍之间不相等的读数不是由步骤决定的，这次的计数比较判阻塞并点名，不拿它去判候选。候选与基准不同时，候选再量一遍：候选自己两遍不相等，同样判阻塞并点名；两遍相等，这个不同才算数。
- 一次运行写几个套件的基线时，全部套件量完之后才写：基线文件在仓库里，先写的一份会让后面的套件量在脏的工作树上。
- 报告是一页文本：结局、每道门、每个样本、能不能比与比的结果、时间读数可不可信及原因、读数、在哪跑的、没盖住什么。

### 套件的契约

套件给出：标识、名称、档、会影响它的路径、读数没盖住什么、成对比较里各读数值得管的最小变化（可以不给）、每一档的负载与装配、`measure`（门要的全部）、`sample`（这一档的工作在一个新进程里做一遍，交回摘要序列与一组带噪声的读数，是成对比较里一边的一轮）。设施给套件一个检出的根与一个空的数据目录，用完删掉。

### 命令

| 命令 | 做什么 |
| --- | --- |
| `env [套件]` | 打印运行环境记录、标识、有没有基线；不跑任何套件 |
| `run [套件…]` | 跑套件，写结果，打印报告；`--write-baseline` 另写计数基线 |
| `compare <基准> <候选>` | 两个提交：基准量两遍、候选量一遍（计数不同时再量一遍），比计数，两边的结果各存一份，再做成对比较。两个结果目录：只比计数 |
| `affected --base <提交>` | 列出这之后的改动会影响的套件 |
| `report <结果目录>` | 重新打印一份结果的报告 |

退出码：0 通过；1 有门失败、计数不同或候选变慢；2 阻塞或用法不对。

## 原则与约束

- 设施不导入任何产品成员，也不导入套件。
- 判定是纯函数，不读时钟、不读文件。
- 期望值不出自上一次实测。设施不提供「把这次的读数记成期望」的路。
- 评测不进准入。

## 不变式

- PH-1 记录里按字面搜不到机器名、用户名、家目录路径、网络地址、数据目录的路径。
- PH-2 同一台机器读两次，机器配置标识相同；机器的身份里任何一个字段变了，标识就变；只记在旁边的字段变了，标识不变。
- PH-3 没有期望值、没有基线、没有门、样本的结局不对，都判阻塞，不判通过。
- PH-4 计数跨负载、跨装配、跨设施主版本，拒绝比较。
- PH-5 仓库里的时间读数不当门：时间的绝对值在可比表里的最好结局是并排列。
- PH-6 摘要序列不同就不判快慢；基准或候选自己两遍不相等的计数，不算两个提交之间的不同。
- PH-7 成对比较少于 10 轮不下结论；去掉轮换、去掉自对照、去掉最小变化那一关，各有一条自测变红。
- PH-8 数据目录在内存文件系统上，或 Node 不是仓库钉的版本，时间读数判阻塞。
