# 派发简报检查规格

本页规定 `brief-check` 的检查项、输出与退出码。用法归 [README](README.md)。规格文件的节名与固定写法归 `delegate` 技能的 `references/closure-spec.md`；本页的解析按它的写法。

## 边界

- `checkBrief(spec, repository, { strict })` 不读文件、时钟或环境。它只经 `BriefRepository` 读仓库：`--base` 提交上的文件与内容、`git grep` 的命中，以及本机上的一个文件是否存在。
- `gitRepository(root, commit)` 用 `git` 实现该接口。所有“在基线上”的核对都读 `commit`，不读工作树。
- `brief-check-cli.ts` 只做参数、路径、输出与退出码。
- 检查不判断规格的内容是否正确，只判断它是否具备派发所需的形状，以及它与基线的事实是否相符。

## 解析

- 二级标题（`## `）划分节。代码围栏里的行不算标题。同名的节只取第一个。
- 「目标边界」下的 `### 写范围` 与 `### 排除的调用方` 取到下一个三级标题为止。
- 节里的固定行写作 `- <标签>：<值>`，冒号可以是全角或半角，值两侧的反引号会去掉。

## 检查项

| #   | 查什么                                                                                                                                                                                                                                             | 级别                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 1   | 十五个二级标题齐全（`developer-task.md` 的十二个字段与三个补充节）。「身份与位置」的六个固定行齐全且非空。`基线` 是 40 位十六进制。`清晰度` 是 `定`、`界`、`探` 之一。`工作树` 是绝对路径（`/…`、`X:\…`、`X:/…` 或 `\\…`）                         | 错误                      |
| 2   | 「写范围」每个列表行都是 ``- `<仓库相对路径>`（新建）? — <推出依据>``。路径不能是绝对路径、含 `\` 或 `..`。推出依据非空。路径一侧（`—` 之前）出现「定义 … 的文件」「及其测试」「或」「先找到」时报描述性写法。没有 `### 写范围` 或没有一行时也报错 | 错误                      |
| 3   | 写范围里没有标「新建」的路径在 `--base` 上存在（`git cat-file -e <base>:<path>`）                                                                                                                                                                  | 错误                      |
| 4   | 调用方或导入方漏在写范围外（算法见下）                                                                                                                                                                                                             | 警告；`--strict` 下为错误 |
| 5   | 「验收清单」里的 `pnpm run <脚本>` 在根或相关成员的 `package.json` 的 `scripts` 里存在。清单引用的仓库相对路径在 `--base` 上存在，或在写范围里                                                                                                     | 错误                      |
| 6   | 「停止条件」去掉 HTML 注释后非空                                                                                                                                                                                                                   | 错误                      |
| 8   | 「方法与知识入口」里有 `- 先读：<路径>` 行，且该路径在本机存在（绝对路径，或相对 `--root`）                                                                                                                                                        | 错误                      |

第 7 项不在本版。节缺失时只报第 1 项，不再就同一节报第 6 项、第 8 项。

### 第 5 项的范围

- 「相关成员」是：根；每个写范围路径的最近一个含 `package.json` 的上级目录；同一行里 `cd <目录>` 的目录。
- 引用的路径只取反引号里的词；代码围栏里取每个词。词必须形如 `a/b.ext`（至少一个 `/`，以扩展名结尾，不含通配符）。以 `tmp/` 或 `..` 开头的词不查，它们是过程产物或检出之外的路径。

### 第 4 项的算法

全部在 `--base` 上用 `git grep`，只查已跟踪的 `.ts`、`.mts`、`.js`、`.mjs` 文件。

1. 从「实施规格」「当前认知」两节取反引号里形如标识符的词（`^[A-Za-z_$][\w$]*$`）。
2. 对每个标识符，在 `git grep -F -w` 命中的文件里找定义：`function`、`const`、`let`、`class`、`interface`、`type` 声明（行首，可带 `export`、`default`、`declare`、`abstract`、`async`），以及 `export { … }` 列表里的名字（可跨行，`export { … } from` 的再导出不算定义）。
3. 对每个定义文件，收集：引用该标识符的其他文件（取每个文件的最小行号）；按相对路径导入该定义文件的模块（`from '…'`，含 `import type` 与 `export … from`，扩展名可有可无，按导入方目录解析后与定义文件比较，同名的另一个文件不算）。
4. 命中文件不在写范围、也不在「排除的调用方」里时，报 `caller-outside-scope: <文件>:<行> references <标识符> (defined in <定义文件>)`。定义文件本身不在这两处时也报，行号是定义所在行。
5. 不含按文件名硬编码的判断。

已知的粗糙处：引用按文字命中，注释与字符串里的同名词也算；同名标识符在多个文件各自定义时，每个定义文件各报一遍。这是警告，不阻断。

## 输出与退出码

- 默认：每条发现一行，`error: <message> [item <N>, line <L>]` 或 `warning: …`。没有行号时省略 `, line <L>`。没有发现时输出为空。
- `--json`：一行 `{"errors":[…],"warnings":[…]}`，每项 `{ "item": 数字, "message": 字符串, "line": 规格文件的行号或 null }`。`--strict` 时第 4 项的发现都在 `errors` 里。
- 退出码：`0` 没有错误；`1` 有错误；`2` 缺少或重复的选项、规格文件读不了、`--base` 不是提交、不在 git 检出里、git 命令失败。
