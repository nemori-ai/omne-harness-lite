# 长期产品与场景观察规格

本模块发现当前长期产品正文及编号场景，为持续覆盖与场景状态提供输入。普通任务由[交付模块](../../../dev-flow/src/delivery/SPEC.md)独立观察。任务关闭、平台阶段与覆盖声明均不能推出产品支持或有效接受。

## 当前产品发现

`readProductTopics(productRoot)`读取当前slug目录的README front matter，发现PD身份、正整数`revision`与`status`。模板目录不参与发现。PD身份必须与slug目录一致，身份全根唯一，产品正文必须存在，所有实际路径须在产品根内。

非法根、缺失或无效元数据、重复身份、目录不符、缺产品正文及越界是输入错误，不能转成零输入成功。合法空根单列未覆盖，不声称全部覆盖。读取不依赖Issue配置、采集或历史任务。

## 编号场景与覆盖

保留既有编号场景解析规则。每个当前PD都进入结果；缺场景正文或没有编号场景时单列未覆盖，不从能力表猜场景，也不把topic过滤掉。未编号内容可能仍表达产品要求，本工具不证明这些要求已经覆盖。

覆盖声明仍按现行契约核对来源、场景与文件，不补造新的PD covers身份格式。找不到声明来源继续报告偏离。场景含义与产品能力支持状态由产品正文维护，工具不复制状态表。

## 观察结果与CLI

`scenarioStatuses(coverage)`只消费长期产品与持续覆盖输入。覆盖声明、执行、有效接受分别报告；没有实际执行或完整接受证据输入时保持`unknown`。零任务、无关联卡或声明覆盖不能作为已交付证据。

`pnpm run acceptance:scenarios`运行长期产品观察；场景CLI拒绝`--config`与`--capture`参数。正常观察退出0；非法输入或工具错误退出2。根`pnpm run check:design`检查现行源、领域对象及生成输入，任务观察沿独立的交付模块运行。

## 持续验证与边界

持续检查须覆盖合法当前PD、缺编号场景、合法空根、身份与修订错误、目录不符、重复身份、缺正文及越界。覆盖检查继续守住现行来源错误反例。

这些结果不证明产品规则已接受、能力已实现、验收已执行、平台已启用或实际宿主已执行。封存产品及Git历史提供出处定位；当前场景从长期产品正文发现。
