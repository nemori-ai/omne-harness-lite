# model-probe

## 总体架构

model-probe 是开发期的模型适配探针，只用 Node 标准库，没有包清单与构建步骤。它做两件事：查 OpenRouter 的公开目录，按显式配置在预算内做缓存与提醒实验。

- 命令入口是 `scripts/model-probe.mjs`，它运行 `src/cli.mjs`。两个命令：`catalog` 与 `run`。参数见 `node scripts/model-probe.mjs --help`。
- 预算账本在 `src/budget.mjs` 与 `src/production-gate.mjs`。`openProductionLedger` 打开批准的账本，账本对象提供预留、`settle`、`reconcile` 与 `acknowledgeBudgetHold`。
- 生命周期可行性实验在 `src/lifecycle.mjs` 的 `probeLifecycle`。

## 领域边界

本工具拥有：公开目录的快照，探针请求的记录，预算账本的规则。

本工具不拥有：

- 生产适配器、模型的认证、最终的运行时验收。
- 模型策略与研究结论：归 `.meta_harness/`。
- 真实账单：账本的估算与预留都不是账单。

## 心智模型

- 付费请求只在显式给出配置、凭证文件、账本与输出目录时发出。没有隐式付费请求、环境凭证回退、重定向或重试。
- 费用不知道就是不知道。缺失的费用阻断后续发送，直到取得实际费用并对账，或显式确认一笔预算预留。

## 应然设计

### 命令

- `catalog --output <文件>` 只做公开读取，把目录快照写进一个不存在的文件。
- `run --config <文件> --snapshot <文件> --credential-file <文件> --ledger <文件> --output <目录>` 按配置发探针请求。五项都必须给。
- 配置的 provider 标签必须出现在已检查的端点目录中。显式缓存模式必须给 `cache.ttl`，工具没有缺省 TTL。前缀大小、输出上限、推理参数按已检查的模型选。
- 记录只含合成的测试内容、不含凭证的请求体、原始响应与用量事实。

### 预算账本

- 批准的总额度是 200 USD（`APPROVED_SCOPE_LIMIT_USD`）。每份账本的 `limitUsd` 不超过它，研究额度 `researchLimitUsd` 不超过 `limitUsd`，打开时传入的额度必须等于账本头里的值。同一次交付的运行共用一个账本。
- 预留按最高的公开输入、写入、输出价格档位与测试输入的保守字节上界估算。估算不是账单。超支中止当前运行。
- 每项当前预留计入总额，研究条目还计入研究额度，已结算条目计入实际费用。求和与比较保留所有小数位。超限的预留在修改账本之前被拒绝。
- 费用缺失、请求中断或遗留的预留阻断后续发送。
- 生产账本入口检查批准的路径、只有所有者可读写的普通文件与独占锁。被强制终止的进程留下独占锁。没有核查请求与账本之前，不删锁重跑。

### 预算预留的确认

`acknowledgeBudgetHold(id, 金额, { reason, source })` 只在以 `{ reconciliation: true }` 打开的账本上可用，针对实际费用仍不可得的 `unknown` 或 `reserved` 条目。

- 金额是正数十进制字符串，不低于原始估算。理由与来源都不能为空。
- 它是预算额度的预留，不是实际费用，也不是费用不会超过的上界。它不填 `actualUsd`，保留条目的未决状态，不发请求，不改额度，不清遗留锁。
- 每次确认向 `budgetHoldAcknowledgments` 追加金额、理由、来源、请求状态与时间。修订金额要再次显式确认，历史保留。
- 普通打开与预留只在未决条目都有针对当前状态的有效确认时放行。新出现的未知费用、`reserved` 变成 `unknown`、损坏的确认记录都重新阻断。

### 结算与对账

- `settle(id, actualUsd)` 用于 `reserved` 条目。维护模式下的 `reconcile(id, actualUsd, { evidence, sha256 })` 要上游证据与它的 SHA-256。两者都以精确的实际费用替换当前的预算占用，保留确认历史，不再重复计入预留。
- 实际费用超过当前预留（没有有效确认时为原始估算）或任一预算时，先持久化真实费用，再报错。工具不自动填零费用或退款。

### 证据的含义

- 目录、定价与缓存配置字段的存在不构成缓存命中的证据。结果区分 `cached_tokens = 0` 与字段缺失。自动缓存可能不报告写入数量。
- `probeLifecycle` 接收已安装的 `@deepseek-ai/cordis` 的 `Context`，以模拟的调用所有者检查真实 effect 的释放。它不验证生产注册表、HTTP 取消或超时策略。

## 原则与约束

- 研究额度低于总额度，为最终实现的验收留出资金。
- 一次批准用多少金额确认预留，由明确的授权决定，示例里的数不构成批准。

## 不变式

- 没有显式的五项参数，`run` 不发任何付费请求。
- 有未确认的未知费用时，账本不放行新的预留。
- 确认预留不写 `actualUsd`。
- 实际费用超限时，真实费用先落盘，再报错。
