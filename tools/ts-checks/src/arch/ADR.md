# N2 视图的布局与导航

日期：2026-10-03。范围：ts-checks 的实际架构报告。
依据：负责人要求参考社区风格、算法与品味。
本记录说明工具实现选择，不接受产品架构边界。行为要求归 [SPEC](SPEC.md)。

保留 N1 事实抽取与既有风险面板。总览汇总直接跨组关系，展开才展示包、服务与事件。
参考 C4 的图例和范围说明、dependency-cruiser 的折叠/焦点、Structurizr 的单模型多视图。
目录组只承担导航，不映射为 C4 的运行容器。

关系图采用锁定的 elkjs 0.12.0 layered。官方内联 bundle 负责位置与路由，原生 SVG 负责展示。
没有引入第二套架构 DSL 或 React 渲染栈。新增代价是约 1.61 MB 的 bundle、异步状态管理和渲染适配。
默认无 worker，真实大图响应时间仍是有限观察之外的缺口。

真实总览 12 组/41 边适应一屏后标签过小，因此默认提供同一投影的依赖矩阵。
行发起、列目标，按种类/变化区分，单元格记录输入身份数。可切回关系图。
矩阵只做排序与定位，不借其形状判断循环、层级或符合性。
组件展开继续关系图，平移/缩放帮助查看局部，侧栏列完整出处。

几何与语义分离。平移/缩放不改变导出集合，过期布局不更新当前图。
失败状态可见，失败时禁用导出。QA 可包装官方 ELK.layout 外部依赖验证拒绝与乱序，
正常离线场景仍运行真实 bundle。N2-A5 保持负责人本人试用，不由本记录代签。

## 2026-10-08：关系图改用 React Flow 展示

依据：负责人要求用 React 19 与最新的 @xyflow/react 美化架构视图。
本记录只推翻 2026-10-03 记录中「没有引入第二套架构 DSL 或 React 渲染栈」的后半句，其余决定不变。

关系图的展示层改为 `src/arch/flow/` 中的 React 岛。@xyflow/react 12.12.0 负责画布、平移、缩放、小地图、节点与边的交互。
ELK 仍只计算位置与路由。边按 ELK 的折线绘制，节点不可拖动，所以屏幕上的图与导出的 SVG 使用同一份几何。
依赖矩阵、侧栏、详情与符合性面板仍是原生 DOM，不迁入 React。

React 19 不再发布浏览器单文件构建。页面在生成时用 esbuild 0.28.2 把 React 19.3.0、@xyflow/react 与岛的代码打成一个 IIFE 并内联，
样式同样内联，`file://` 打开仍不需要网络。代价：ts-checks 新增 react、react-dom、@xyflow/react、esbuild 四个开发依赖，
每次生成页面多约 0.2 秒打包时间，页面多约 430 KB。
SVG 导出不再克隆屏幕上的 SVG，因为节点已是 HTML。导出由同一份 ELK 几何与当前选择直接生成（`flow/export-svg.ts`），
内容与原来一致。大图的响应时间仍在有限观察之外。

## 2026-10-09：复杂度与风险的结构图改用 React Flow 展示

依据：负责人要求把结构图改成与参考架构快照相近的形式：横向的层、带虚线边框的容器、成员卡片与成员间连线。
本记录修改 2026-10-08 记录中「依赖矩阵、侧栏、详情与符合性面板仍是原生 DOM」的范围：结构图也进入 React 岛。
其余原生 DOM 部分不变，包括复杂度面板的明细、函数表、悬停清单、方向发现与例外。

结构图的组件归 `src/metrics/flow/`。同一个 bundle 入口（`flow/main.tsx`）同时设置 `window.ArchitectureFlow` 与 `window.StructureFlow`，页面只内联一份 React。
因此 bundle 改由 `renderPage` 内联一次，`architectureMarkup` 不再内联它。arch 的 bundle 入口由此运行时依赖 `src/metrics/flow/`。
结构图的几何不用 ELK，由 `flow/layout.ts` 按层、组和组内顺序确定地计算。连线默认不全画，用 ELK 按全部边布局会让卡片位置随选择变化。
连线用 React Flow 的贝塞尔边，在屏幕上计算路径。直角走线（smoothstep）让同侧出发的线共用竖段而重叠，所以不用。结构图没有 SVG 导出，所以不要求屏幕与导出共用几何。
画哪些线的规则不变，由 `flow/edges.ts` 实现。原来的三角标记改为卡片上的「入/出」计数，颜色规则不变。
面板隐藏时画布没有尺寸，React Flow 不能适配全图。所以画布第一次有宽度时才挂载结构图。
代价：没有架构数据时，页面也多出约 430 KB 的内联 bundle。

## 2026-10-09：内联数据与三方库按压缩形态嵌入

依据：负责人要求缩小报告页体积，并要求集成的三方库使用压缩版本。

架构数据是页面的主要体积。本仓库当前数据约 48.6 MB，gzip 后约 1.7 MB，转 base64 后约 2.2 MB，整页从约 53.7 MB 降到约 6.2 MB。
页面用浏览器原生的 `DecompressionStream` 解压，不引入解压库。代价：视图在解压完成后才启动，本仓库数据约需 0.4 秒；不支持该 API 的浏览器显示失败原因。
未采用 brotli：压缩率更高，但本仓库数据一次压缩约需 30 秒。

elkjs 的 `elk.bundled.js` 与 @xyflow/react 的样式表都没有发布压缩版本，生成页面时用 esbuild 压缩一次并缓存。
elkjs 的版权声明是普通注释，压缩前摘出并放回压缩代码的开头。React 与 @xyflow/react 的脚本沿用打包时的压缩。

## 2026-10-09：表单控件、折叠区与函数表改用 antd

依据：负责人要求内联 antd 最新版的压缩形态，并把表单等组件改为 antd 实现，函数表与折叠区一并改。

采用 antd 6.6.5。它支持 React 19，不需要兼容补丁。不内联 `dist/antd.min.js`：那是全量 UMD 构建，比按需打包大得多。
antd 进入已有的 esbuild bundle，只打包用到的组件，并按生产模式压缩。代价：bundle 脚本从约 413 KB 增加到约 1026 KB。

页面标记仍写原生控件。bundle 加载时把下拉、复选框、按钮、视图切换与折叠区替换为 antd 组件，id、可见文字与选项照搬。
页面脚本经句柄（`src/arch/flow/controls-api.ts`）读写控件，筛选、布局与跳转逻辑不变。
没有另设隐藏的原生控件做双向同步：两套状态与两棵可访问性树没有边界价值。
函数表改用 antd Table。筛选、排序与 400 行截断仍由页面脚本完成，表格只按给定顺序展示。
仍为原生实现的部分：侧栏的目录组、节点与关系清单，矩阵与关系图，以及符合性面板里按预期变化动态生成的折叠条目。
主题 token 取页面的同一组值，深浅色与减少动态效果跟随系统设置。主色用靛蓝：墨黑派生出的下拉选中项是深灰底，难以阅读；靛蓝与表示本次变更的蓝色相拉开。
函数表与筛选单选只挂载一次，之后只换数据，排序与筛选时不重建。按钮不在两个汉字之间插空格，以保留规格点名的控件文字。
