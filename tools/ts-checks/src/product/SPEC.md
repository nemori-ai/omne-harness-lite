# 当前卡源与历史迁出

本模块选择当前卡源并核对旧卡的 Git 历史。正式产品规则归产品设计，交付流程归 [agent 交付协议](../../../../docs/engineering/agent-delivery.md)。工具不接受成果，不证明迁移授权或业务承接等价。

## 当前来源

`inspectCurrentSources` 接收检出根、产品根及可选配置和采集路径。它读取当前 `stories.md`、交付配置、技术切换记录和显式传入的 GitHub 采集。默认离线执行，不隐式请求平台。

`CurrentSources` 以判别联合区分旧卡与 Issue。旧卡拥有本地路径与场景引用。Issue 拥有稳定身份、旧卡别名及 known 或 unknown 读数。旧卡别名解析分别报告 legacy、issue、unknown 或 conflict。没有采集、缺页和未观察到目标不等于空队列。

`enabled:false` 限制日常派发，不抹掉已经登记的来源切换。Issue 的关闭状态和 Project 阶段只表示平台事实。可读的卡修订与正文可以继续演进，稳定身份与来源别名仍须唯一。

启用日常 Issue 流程但没有采集时，即使没有迁出记录，完整性也为 unknown。禁用且纯旧源的 complete 仅描述本地已知来源，不表示 GitHub 全仓已读。

## 技术切换记录

唯一记录位于 [source-cutovers.json](../../../../docs/engineering/source-cutovers.json)。版本1记录 repository、topic、Git 历史锚点和迁出批次。初始 topics 为空，表示尚无生产迁出。

历史锚点绑定完整 commit、path 与 blob。工具从 Git 原文读取原产品修订和已发到序号。迁出项绑定旧卡原文散列、目标 Issue 身份、首次正文修订与散列、读回证据指针、具名采用记录及真实消费者。采用范围须逐项等于该批移出的卡号。

记录不保存标题、业务正文、价值、交付条件、当前阶段或接受状态。它是技术来源记录，不是第二份工作队列。旧批次和锚点只追加，不修改。文件与配置的仓库身份必须一致。

散列只证明输入绑定。采用权限、业务信息是否完整承接，以及指针是否真的来自首次平台读回，仍需负责人逐项核对。工具为这些判断保留 unknown。

## 同提交的历史处置

`retire.ts` 对任务范围内的提交核对三种处置。`Accepted-Card`、`Voided-Card` 维持旧规则。`Migrated-Card` 是迁出，不能推导接受或作废。每条 trailer 只指一个合法旧卡号。

迁出须在同一提交真正删除旧卡，并新增唯一对应批次。已有批次不能复用。切换记录变化也触发检查，即使提交没有删除卡。空容器退出仍须保留有效历史锚点，不能制造假迁出卡。

合并提交逐个读取父提交。所有父提交共同存在、合并后消失的卡由合并提交负责。新增批次相对所有父批次的并集判断。同批次在父提交中内容不同即冲突。每个父提交的已发到序号分别核对，不按父顺序选择方便的值。

历史采用按该提交的 Git 内容解释，不依赖当前是否启用日常流程。Git 对象缺失、记录非法或读取失败是工具错误，不能作为空成功结果。

## Python 消费者绑定

`sources-cli.ts` 输出版本1的 `current-source-observation`。投影包含绝对 root、productRoot、HEAD，以及当前故事卡文件、切换文件、配置和采集的路径与散列。缺失输入也显式绑定为 null。

必填 `inputRoles` 分别声明默认或显式配置、固定切换源，以及未选择或已选择的采集。角色与 bindings 使用同一规范路径。现存文件、缺失文件的父目录及悬空链接目标均须与 Python `Path.resolve(strict=False)` 一致。显式检出外覆盖仍按实际路径绑定。

`stories.py --source-observation` 核对所有绑定、路径范围、重复项和 HEAD 后消费投影。同一 HEAD 下的文件变化也会使投影过期。过期或非法投影退出2。未迁出的旧前置可解析到唯一迁出 Issue，但条件是否满足仍为 unknown。

绑定集合须恰好覆盖当前 stories 与已选择的输入角色。缺少配置或采集角色、删掉对应绑定、加入未解释路径，均为损坏输入。未选择采集却启用日常流程或含 Issue 目标时，不能声称 complete 或 partial。首次正式发布前的旧无角色临时投影须重新生成，不回退旧模式。

直接运行旧 Python 入口继续检查旧卡。根 `make design-check` 先生成本次投影再调用 Python，不沿用上次临时输出。

## 观察与退出

`make source-status` 支持 `CONFIG`、`CAPTURE` 与 `REPORT`。正常观察退出0，包括偏离与 unknown。输入或执行错误退出2。`card-retire` 保留现有交付硬线，违规退出1；迁出并未增加一条“所有 unknown 都阻断”的规则。

场景报告分别列覆盖声明、执行、接受和当前卡活动。覆盖声明不能推出已交付。流程体检不从当前卡数中扣除旧台账 accepted 登记。对已经迁出的别名，旧台账入口拒绝新增三个事件中的任何一个，并给出 Issue 定位。

## 持续验证

真实临时 Git 仓库测试覆盖历史锚点、同提交迁出、多父合并、追加约束和旧处置。当前来源、场景和流程测试覆盖无采集、部分读取、别名冲突、关闭及 Accepted 阶段不构成接受。Python 测试核对过期绑定及混合来源。

这些检查不证明 PF 迁移已完成、平台原子一致性、人的接受或云端恢复。真实迁出仍需对应批次的业务核对与交付接受。
