# Maintenance policy and file ownership

The maintenance policy consumes private, named file, codec, digest and center-reading operations. The assembly selects the existing providers. These operations do not become public package exports.

The input provider retains one descriptor through parsing, inspection and copying. It owns close and delegates resource registration to the existing snapshot session. The policy receives bytes and physical facts, without a file handle or close authority.

The assembly composes header parsing and the pure input object inside the original input callback. Catalog and offline policy consume this injected operation. They do not select the assembly. The center reader still uses the original snapshot view and checks.

Publication remains exclusive. Visibility occurs before directory confirmation. Cancellation after visibility does not remove the result. Unknown durability and cleanup failures keep their original classification and reporting order. Stop requests cancellation; close waits for actual work.

The public offline factory, backup bytes, source identity and business rules remain unchanged. Original fixtures select the real assembly and retain their assertions, fault gates and timeouts. Independent tests must verify actual files and SQLite, alongside the private operation traces.
