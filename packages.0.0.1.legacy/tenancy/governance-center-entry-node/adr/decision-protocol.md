# Request decisions and protocol effects

The private decision policy receives protocol, correlation and authenticated transaction ports. Business routes remain the sole owners of invocation and failure rules. A separate wire module projects each original schema.

The adapter retains JSON reading, Schema validation, byte encoding and the original storage binding. Projection and contradiction checks keep their shared catch boundary. Schema validation and encoding remain outside that catch and before commit. The caller receives bytes after the actual transaction finishes.

The transaction adapter constructs the five original participant faces in order. The policy retains the observed rollback decision. Credential preparation does not add a second exchange. Public health and lookup-free rejection retain lazy dependency access.

The policy still uses accepted public identity functions. Their existing transitive crypto and canonical JSON dependencies remain visible. This change does not assert a crypto-free shared runtime closure.

Recheck the ordering if projection, validation, encoding or participant lifetime changes. Extra private ports have a cost. Actual byte, fault, SQL and consumer evidence remains necessary before domain acceptance.
