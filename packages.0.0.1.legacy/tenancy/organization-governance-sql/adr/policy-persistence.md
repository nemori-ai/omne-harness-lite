# 策略与记录后端

R1-T5 的结构审阅发现业务源码直接选择 SQL 并操作原事务。私有具名记录面将后端选择留在装配门，使原授权、失败次序和状态转移继续由纯策略拥有。公开能力类型与已接受业务承诺不变。

37 个记录操作保留原投影、排序、锁名、写谓词及 SQL 异常身份。行解码仍在原使用点发生。原当前 StorageUnit 是共同提交的唯一资源，绑定不具有独立终结权。参与面只在每次原 run 内构造，不缓存或改调普通接口。

原 parent 的两条策略写路径共用唯一后端实现。静态验证同时观察唯一后端写、接受填值、解除清空、创建为空及单列结构。迁移模块从唯一常量拥有者消费表名，该拥有者没有运行时依赖。

此分离增加记录操作与装配函数，不能据文件拆分声称复杂度下降。源码闭包、真实 SQL 故障、共同单元、四个独立工厂及制品消费须分别验证。后端变化、公共参与范围或记录表示变化时复核此选择。
