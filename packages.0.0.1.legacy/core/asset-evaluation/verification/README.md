# Asset evaluation verification

Run the package build, typecheck, and full tests. Test pure selection, complete four-layer input, disable fallback, usableBy, workspace drops, cross-asset settings versus permissions, permission helpers, root source, exact durations, fingerprint changes, deterministic replay, and failure priority.

The [normative inputs](../tests/fixtures/evaluation-examples.md) retain independent values and expected results. The root tests and evaluation-input-store tests use the agent-definition owner's fixture. Do not replace these expected results with values generated by evaluate.

Include lossless result reads, duplicate-key rejection, closed DTO members versus open user values, unresolved relations, root projection, default-owner initialization/reuse/retry, and explicit tool-environment options. Input-only fingerprints do not cover options or rule changes.

The two [Alloy models](models/README.md) require positive receipts and their targeted negative controls. Their finite structural claims do not establish source authenticity, actual authorization, concrete value algorithms, JSON parsing, or operational progress.

Real input producers own consistent current facts, authorization, and exact body reads. Real assemblers must reject unresolved references. Pure package checks do not establish those external premises or full Connector/plugin/sub-agent support.
