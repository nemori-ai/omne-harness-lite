# 共同事务参与者的排空

共同事务的提交拥有者是AtomicStorage。某个参与操作返回暂存结果后，外层事务仍可继续。参与者撤除时必须保留已接纳责任，不能把操作返回等同事务结束。

StorageUnit提供observeCompletion：在有效调用帧取得只读结束Promise，在原事务之外等待。本地提交拥有者在write调用结束后解决Promise，区分committed、rolledBack、unknown。该端口不允许参与者决定提交，不打开第二事务，也不执行参与者回调。

仅afterCommit不足以排空：回滚不会通知，参与者会永久等待。由参与者独立read也不能判断外层在途事务是否仍可能提交。结束观察因此属于共同事务协议，不由日志提供者通过计时、轮询或Context寿命推测。

unknown只表示本地拥有的提交调用结束，不证明服务端事务或所有可能writer已经静止，也不解除业务事实保管义务。例如PostgreSQL的COMMIT发送后连接断开，服务端仍可能提交。日志参与者按原完整批次身份认回；没有可靠证据时close保持失败及依赖，不重发。ordinary append的提交拥有者仍由日志提供者承担。

若存储后端只能确认本地调用结束，则返回unknown，不能以超时返回rolledBack。未来跨进程部署须提供同等责任与结果语义。
