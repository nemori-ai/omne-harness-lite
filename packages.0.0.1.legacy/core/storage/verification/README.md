# Storage 验证义务

[公开类型](../src/index.ts)约束形状，[行为规格](../SPEC.md)约束事务、失败、显式共同单元与维护。单次结果归工作树 tmp，本页只维护可复跑义务及限制。

## 提供者符合性

实际提供者调用公开 describeStorageConformance／describeAtomicStorageConformance，测试进程传 runner；core 不自行装载 Vitest。不得用内存实现代替真实文件库。factory 每次建独立实例、指向同一底层库；需要并发的用例必须有真正独立连接及 await 交错。

| 保持的性质 | 必须观察的反例条件 |
|---|---|
| P-1 原子、原异常及返回值 | 回调失败留下部分写；包装原异常；成功后无已提交行 |
| P-2／P-11 唯一冲突 | 冲突后事务废弃；命名索引或主键得到错误约束名 |
| P-3 最新写内读 | 后开始的事务漏前次提交，或读不到自己的写 |
| P-4／P-5 锁序 | 两实例读改写或哨兵互斥丢更新、同进程一方 busy |
| P-6 快照与只读 | 两读夹一次实际完成提交而读值变；只读内写未拒或留下变化 |
| P-7 句柄重开持久 | 关闭重开丢已提交行；跨进程重启另由消费者测，不由此项推导 |
| P-8 分类与关闭 | 瞬时失败假空／旧快照，缺陷折不可用；close 后仍准入或在途部分提交 |
| P-9 删除释放 | 删除后同值仍冲突 |
| P-10 引用两向 | 删除受限与缺失目标未分别报型；套件用自己的父子表，不证明真实业务外键 |
| 普通嵌套拒绝 | 同实例回调中再 read／write 未报 StorageDefect，或影响外层正常收场 |
| P-13 显式单元 | 不同实例参与、逃帧／并发子调用、异常污染被解除、未等在途而提交、提交前通知或通知失败改报业务失败 |

套件有效性必须有代表性错误提供者负控；真实 SQLite 写连接关闭 foreign_keys 并读回后，C-11／C-12 应因引用断言失败，其他用例仍按原条件执行。任意非零退出不等于有效负控。lockRow 空实现等其他变异需各自结果，不能由一种故障推导全部错误可见。

SQLite 与 PostgreSQL 结果分别记录；无 OMNE_TEST_PG_URL 时跳过不是通过。跨进程持久、生产真实外键、两个领域写者的交错、断电同步、PG 版本下限及部署接线由各自消费者验证；本包套件不证明它们。本次迁移不宣称 PG 整体恢复。

## 公共消费与维护

成员 build／typecheck／test 验证分类异常、只折不可用的映射、有序迁移和公开类型；外部消费核根声明及装载闭包、conformance 调用方 runner、实际打包入口与私有路径拒绝。共同事务的完成观察须覆盖 committed／rolledBack／unknown、不在原事务内等待、重取拒绝和提交后通知边界。

维护提供者须证明单 run 排他、关闭拒新且等待原工作、回调及已发 read 真结算、固定副本面对业务并发提交、view 逃逸拒绝、永久隔离先于明文、同工作根跨进程互斥及失败清理仍有保护。有限入口模型不证明物理机制。

资源负控须覆盖：取消或回调拒绝后才完成的 open 仍登记；内部 close 失败被回调捕获仍使 run 失败；正常返回但 isClosed=false 拒绝；句柄仍开时保留两锁和强引用；实际已关但抛错仍报失败、不虚构未关；全部资源收场后才能 clean。只用 signal、日志、期限或 pending 无快照不能证明实际结束。
