# 按需申请独立的持久时间范围

Clock 在每次调用时读取系统墙钟。跨重启非递减还需要持久上界，不能仅靠 Date.now。
周期续约会把主事件循环的调度延迟变成 Clock 不可用。异步 now 允许调用者在范围用尽时等待持久申请，并在回执后重新采样。

持久申请不能进入当前业务写事务使用的同一个 SQLite 库。否则业务事务等待 Clock、Clock 等待业务写锁，会形成等待环。
本包复用 storage-sql 的异步连接和排他机制，独占一个文件。时间策略留在主拥有者，不再增加 Clock 专属 worker 或另一套 RPC。
数据库 worker 单独退出时，main 仍持有排他锁；旧 Clock 未停止前，另一个拥有者不能接管同一文件。

代价是独立资源需要明确初始化与备份底线。manifest 区分未完成初始化与已提供时间的资源，普通打开不能静默重建丢失的资源。
不增加业务数据库与 Clock 的一对一身份协议，因为通用 Clock 的现行承诺没有这条要求。

若未来更换排他机制、允许跨进程同时写 Clock、合并业务与 Clock 的事务边界，或修改 SQLite 的耐久配置，必须重新核对所有权与重启保证。
