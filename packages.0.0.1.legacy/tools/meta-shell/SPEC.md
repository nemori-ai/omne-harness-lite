# Shell behavior

The public interfaces are in src/index.ts. This module owns tool arguments, command composition, retained output, and user output frames. It consumes the current Runtime Context and command facility. It does not own environment placement, terminal identity, resource recovery, or agent advancement.

1. The definition has five commands: help, create_session, execute, close_session, and info. Unknown commands or arguments fail before an external operation. The argument validator compiles schemas when needed and retains its cache within the tool factory.
2. The definition declares allowBackground=true. The preference backgroundThreshold defaults to PT10M and can be configured. This value limits the upper caller's wait. It is not an execution deadline. The executor does not create a background state, timer, or second execution. run_in_background is an upper caller hint.
3. The default shell.initial context value is {cwd, envs}. A configured context key can replace this key. Initial values for creation, one-time execution, and info come from the bound reader. Missing or invalid data fails. The tool never substitutes its own ambient directory or environment. Persistent execution preserves the existing terminal state. Only explicit cwd/envs overrides reach that call.
4. A session_id encodes the original id/generation. The provider checks its scope, generation, permissions, and ownership. The tool does not maintain another terminal table or substitute a new process for an invalid terminal. Creation followed by failed observation returns the created reference with an error. It does not create again.
5. A configured shell executable and argument prefix apply to one-time execution and info. Persistent terminals use their provider's shell. The info query reports observations from the selected environment, not the tool's process. A one-time shell version does not assert a persistent terminal's version.
6. Execute starts one original command and consumes one output reader. Each stream uses incremental UTF-8 decoding. The combined retained byte count is bounded by maxOutputBytes. Provider discards and tool retention discards remain separate observations. Truncated output does not assert byte completeness. Arbitrary chunks can include partial lines, multiple lines, carriage returns, and ANSI sequences.
7. Incremental frames use open/fill/close with toHuman=true and toModel=false. They are bounded by the retained output. A dropped display frame does not stop execution or remove the final result. The final result contains the retained streams, output counts, duration, environment identity, and original exit observation. Exit zero is success. Nonzero, signal, or unknown completion is an isError tool result, not a fabricated runtime exception.
8. Only explicit execution cancellation invokes process.stop. The tool removes the abort listener after observation completes. Releasing an observer or continuing agent advancement does not stop the execution. Observation failure or a model request timeout does not authorize repeating an external command.
9. close_session returns confirmed only when the original provider confirms closure. Unconfirmed closure remains an error with the observed status. It does not invent rollback or replace the original owner. Registering through ./cordis attaches withdrawal to the caller effect. Withdrawal prevents new acquisition; an existing pure executor lease retains its original closure.

10. Help returns an ordinary string. Other expected outcomes return ToolResult with one human-visible and model-visible text block. That block contains the JSON encoding of ShellResultPayload. Successful execution, creation, and closure omit isError. Expected failures set isError=true. ShellBusinessFailure contains kind=rejected and a closed ShellFailureReason. All commands map ContextRead rejection to context:<reason>. A missing value maps to context:missingValue; malformed initial data maps to context:invalidValue. Facility rejection maps to facility:<FacilityFailure.reason>. After successful creation, a terminal-list rejection maps to created:observation:<FacilityFailure.reason>; an absent original terminal maps to created:observation:missing. These prefixes never combine. Argument rejection uses arguments:invalid, arguments:unsupported, or arguments:invalidTerminal. Explicit cancellation before an external operation uses interrupted. Missing or invalid Context is a business failure, not an implementation exception.
11. If creation succeeds but terminal observation fails, the failure payload contains detail.terminal_id with the original encoded id/generation. It has no successful observation field. The reference identifies the created terminal for later closure. Unconfirmed closure returns ShellClosureResult with status=unconfirmed and isError=true. A nonzero, signal, or unknown execution returns ShellExecutionResult with the actual outcome and isError=true. Output collection and the original result Promise have concurrent rejection handlers. Synchronous or asynchronous stop failures also have an immediate rejection handler. An early failure reaches the executor Promise before a pending output drain completes. Unexpected implementation exceptions propagate to the runtime's abnormal failure handling. They do not fabricate a business success or repeat an external operation.

Verification uses meaningful protocol tests and slow tests against the real host provider. Host gate, terminal ownership, and recovery models remain with the host owner. This module adds no background state model. Run records and review evidence belong in the task tmp directory.
