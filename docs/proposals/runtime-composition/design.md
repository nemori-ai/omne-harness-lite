# 共同能力边界与内核映射

本设计以长期身份、业务事实和临时执行分别拥有生命周期为前提。以服务暴露能力，
插件提供实现或注册贡献，运行对象承担本次资源使用；包、服务、实例不一一对应。
依赖的精确含义沿 D-005，新增的交接约束由[已发布组合](../../../spec/compositions/agent-session-binding/v1/contract.md)拥有。

## 能力和数据的归属

| 责任 | 自己拥有的内容 | 交给消费者的表面 |
|---|---|---|
| Agent 原语 | 精确 AgentRef、唯一激活占位、受限句柄、工作账目及退出阶段 | 注册表服务；Factory 注册贡献；实例工作许可与关闭入口 |
| Session | SessionRef、原定义关联、会话生命周期、长期历史及相应业务状态 | 会话管理/读取服务；可撤销的运行附着；明确持久保证的事实读写 |
| 输入与 Run 控制 | 已受理输入、编辑/排序/取批、逻辑 Run/Step、精确控制和恢复裁决 | 执行控制能力；驱动消费获准工作，UI 和 Loop 不再各裁决一遍 |
| 上下文装配 | 本次选用的提示词、历史、摘要、输入、贡献和实际模型内容依据 | 装配能力与有所有者的贡献注册；不是 Session 所有状态的容器 |
| 模型 | 当前模型使用资格、确切请求、流与费用等请求事实 | 模型服务和 OpenRouter 提供者；供应商消息形状作为共享内容的边界投影 |
| 工具执行 | 调用/attempt、实际执行与控制、过程帧语义、结果、后台执行所有权 | 定义/执行/观察能力；会话只关联和消费其事实 |
| 存储、媒体及派生读面 | 存储兑现保存/读回；媒体拥有原件；投影说明来源和水位 | 受管后端；可重建投影和受权读面，不重判 Run 或工具终态 |
| 设置、定义与授权/HITL/预算 | 各自的权威事实、管理操作和业务规则 | 当前判定及所需交接；知道对象 ID、历史曾获准均不等于当前可用 |

SessionRef/AgentRef 直接复用已接受身份契约。Run/Step、输入、调用、请求、上下文
快照和内容引用的完整结构由相应数据与能力专题一次定义；本轮确定语义拥有者，
不提前用 `Record<string, unknown>` 或多个同名 ID 壳充当已定共享协议。

## 三种上下文

Cordis Context 负责运行时服务访问、交互和受管贡献。调用上下文携带该次操作
所需的身份、因果关联、取消/期限与受限能力，范围止于该次调用；来源状态继续
由各能力维护，不能通过往上下文写属性绕过权威操作。模型上下文则是一次请求
选中的内容及来源，须能解释实际送入模型的结果。

scope 只处理参与该协议的贡献可见性/事件路由；它不新增会话可变状态存储，也不
提供租户授权或恶意代码隔离。initiator 提供因果归因，不决定 Session 所有权、
权限或后台执行资源的寿命。

静态提示词保持原文；动态模板使用受控且获准的状态来源。模板版本、状态值和
渲染结果各自表达；渲染触发策略由后续装配专题确定，不能把每次请求组装等同于
每步重渲染。已形成的历史内容不能因提供者卸载而被重新计算成别的文本。

## 四类提供者的组合

| 提供者 | 形态与依赖方向 | 必需操作及产出 |
|---|---|---|
| 当前访问验证 | 授权能力提供服务，Registry 的产品入口消费其受限接口；不依赖具体 IAM 实现 | 针对主体/租户/目标/操作验证当前权利；在准备后的提交边界重新验证，拒绝与不可用可辨 |
| Session 运行附着 | Session 插件提供服务，Factory 消费并将精确附着交给 Registry 的发布过程 | 附着已有 Session；保持租户与原定义关联；提供可撤销的激活资格及发布屏障；精确释放运行附着 |
| Factory/驱动 | Factory 是向 agents 注册的受管贡献；驱动是此次实例内的运行对象 | 私有准备、登记资源、提供实际绑定；发布后按工作许可驱动；退役时收口并证明静止 |
| 资源与贡献提供者 | 后端/能力插件提供所需资源，返回有所有者的使用关系；不为每个资源新建服务 | 绑定新使用、停止新使用、处理在途使用、报告释放与残留；旧清理能力不指向新代际 |

Registry 不静态依赖某个具体 Loop。Factory 插件消费 agents 及自己准备工作所需
的 Session/其他能力，再向 agents 注册一个带精确依赖身份的 FactoryBinding；
该绑定的产品准入必须在必要依赖就绪后才开放，Cordis 的注册时刻不等于可用。
这样保留 Registry 与驱动实现之间的依赖方向，避免相互注入造成装配环。

组件通过公开入口交换契约表面。Session 附着不是 LLM/工具调用的万能对象，
工厂也不能借“自己创建实例”取得删除 Session 或跳过当前权限的资格。当前具体
TypeScript 服务键/包 exports 在实施计划中固定；这些职责不要求四个包装服务。

## Session 附着的提交与撤销

核心竞争是：检查 Session 可激活之后，异步准备尚未完成，Session 已归档、
资格撤销或必要提供者已撤除。解决办法是由 Session 权威提供精确附着，提交时
在共同撤销屏障内验证，再发布同一个 AgentRef；捕获一个可变 Session DTO 无法兑现。

本设计把“可激活性变化的提交”“附着撤销”“Registry 发布/工作准入”接入相同
的可串行裁决边界。单机实现可以在固定顺序的短临界区完成，异步加载、网络检查、
持久写入准备均在临界区外进行；跨进程实现需提供等价线性化与失联封闭行为。
这里没有新建通用分布式事务框架，也没有把两个 Map 称作事务。

权限权威同样必须参加其判定的使用边界。一个将来才回传的允许响应、一个尚未
同步的撤权缓存或普通版本号不足以证明“当前有效”。不能将不同权威的过期快照
拼成统一屏障；无法提供所需同步/有效期保证的提供者不能接入这条产品准入路径。

资格修订只覆盖影响激活的事实；历史追加、标题或无关投影变化不必导致准备作废。
Session 的耐久归档/删除提交及其与活动 Run 的互斥仍由 Session/Run 专题定义。
此处明确它们必须与准入协调；封闭运行准入不等于归档已落盘或旧运行已停止。

## 退出与独立工作

正常退出的顺序沿 D-005：关准入 → 准备及工作收口/确认移交 → 驱动静止 → 资源
按依赖释放 → Session 附着释放 → Registry 释放占位。失败保留原阶段和依赖，
不能以 Cordis 的 disposer 已返回或 Fiber 状态替代真实结算。

后台工具及耐久人类等待由自己的能力持有权威事实与必要资源。旧实例的观察订阅
可以被释放；原调用、等待或结果关联不能只放在该订阅闭包中。下一实例在当前
权限下重新关联原工作，不能通过重新派发来假装恢复。用户 interrupt/cancel
以及 interrupt_then_run 的不同传播由 Run/tools 组合兑现，runtime retire 不自行选择。

工具过程帧的生产、顺序与终态由工具执行拥有；Session 关联来源，上下文选择
实际消费内容，存储兑现约定的保存。临时展示、耐久记录和模型消费分别表达。
具体帧等级、游标、媒体和保留协议继续与工具专题共同设计，本轮不另建 FrameService。

## 取舍与实施门槛

保留原始 Agent 对象供任意插件访问会使权限、附着和代际边界失效；把 Session
插件直接挂在临时 Agent 下则会错误牵连历史与后台工作。采用受限能力和独立
所有者，增加明确的准入/释放协议，换取可验证的失效和退出行为。

仅声明 `inject`、只在准备前检查、或用超时清空占位，都无法覆盖异步竞争和未知
清理。计划撤除须在 Cordis 实际卸载之前履行协作；异常丢失则封闭相关操作并报告
失败/未知。直接使用官方 Cordis，无需修改内核或维持 Typert 兼容外壳。

本轮共同契约可供下游设计消费。进入完整 agent 目标实现前，还须取得实际 Access、
Session、Factory/driver 与资源提供者的符合性映射及相邻能力规格；替身只能验证
局部组合。此处不冒称已具备具体 Session/Run/模型/工具产品闭环的施工条件。
