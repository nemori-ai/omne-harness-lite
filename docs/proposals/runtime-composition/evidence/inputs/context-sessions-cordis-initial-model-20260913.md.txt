# Agent 上下文与会话：Cordis 视角初步模型

日期：2026-09-13。版本：v0.1，讨论候选。目的是让用户初步感知能力、装配形态与生命周期；不是已接受架构、包清单、服务 API 或完整恢复协议。

项目消费基线：`72e5007c874a7dfb82e4b50dc15b33fe05026b9e`。当前 [catalog](../spec/catalog.json) 没有已接受契约。上游研究沿用 `c291e7961a515f6d7af9304e7fd1d257929aef26`，不是已采用的 Cordis 发布版本。Cordis 用官方发布包，选定 DSH 组件 fork 自维护，Agent Loop 自建。

## 1. 先区分装配、能力和数据

Cordis plugin 承担装配、依赖和受管生命周期；service 是消费者通过 Context 解析和调用的能力表面。一个插件可以提供服务，也可以只向现有能力注册贡献。它们不是互斥分类，也不与包、进程一一对应。插件应用产生 Fiber；Fiber 是运行实例，不提供持久业务身份。[官方 Primer](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/docs/cordis-primer.md)、[Fiber](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/docs/cordis-api/fiber.md)。

需要区分三种“上下文”：

- Cordis Context：当前组件访问服务、注册贡献、参与交互的运行环境；随运行资源重建。
- 上下文状态来源：组织、工作区、工具、待决请求等能力拥有的事实，经授权提供给消费者；不堆成一个无边界全局对象。
- 模型请求上下文：某次请求选中的提示词、消息、摘要、工具描述及多模态内容或引用。它是组装结果与证据；不是保存 Cordis Context。

以下分类是本项目根据要求提出的设计推导，上游没有替 OMNE 决定这些业务边界。

## 2. 哪些是插件和服务

表中名称为职责说明，不预先创建同名插件、服务键或独立部署。

| 能力 | 初步承载形态 | 拥有的责任及边界 |
|---|---|---|
| 会话管理 | 插件提供会话管理服务 | 管理稳定 Session 身份、租户/owner、目录、标题、归档、恢复、逻辑删除及关联。须通过权威运行状态检查活动 Run 等条件；归档不隐式取消 Run。服务管理许多会话，单条 Session 不必成为插件。 |
| 会话输入与运行控制 | 自建执行编排提供服务，驱动插件消费 | 统一裁决耐久队列、编辑/调序/取批、单会话最多一个活动 Run、精确 Run 的控制。归属与 Loop 交接一并设计；不能由会话服务、Loop 和 UI 各自裁决一遍。忙时受理输入不依赖当前模型调用结束。 |
| 活跃 Agent 管理与装配 | 插件提供 live registry/创建与释放入口；自建 driver 插件提供实际驱动 | 管理临时运行实例及受约束 handle，按定义、会话事实、授权和环境装配 Context。可用 fork 后的 DSH agent 原语作为基础。是否在线不决定 Session 是否存在；live registry 不是会话目录。 |
| 会话历史记录与读取 | 插件提供逻辑日志/读能力，配合独立存储服务 | 记录与读取历史位置、请求依据和跨能力关联；各类事实由相应能力解释，不能由日志服务重新裁决工具终态或 Run 状态。需要持久确认的操作取得相应存储保证后才能宣称成立；不预设所有状态都用 event sourcing 或同一物理日志。 |
| 存储提供者 | 插件提供或注册后端实现，暴露读写/确认/句柄能力 | 兑现适用故障边界内的数据保存和读回，持有连接、writer 等资源。历史读取不要求目标 Agent、原工具实现或原 driver 在线。Session log 与数据/媒体存储有边界，附件用受治理的可恢复引用关联。 |
| 模型上下文组装 | 插件提供组装服务 | 组合提示词渲染结果、有效历史、已接纳输入、获准的事实/工具信息；输出确定的一次组装结果与来源。驱动决定何时调用；模型边界负责实际合法路由与请求准备，所有请求经 OpenRouter。组装本身不运行 Agent Loop。 |
| 提示词与上下文贡献 | 各事实 owner 的插件注册 section、受控变量、上下文来源或工具指导等条目 | 如工作区摘要、组织规范、当前工具能力、待决请求信息。条目有 owner、范围、使用权限及撤除语义；每个变量/段落不必是插件。记录贡献来源不使其自动成为系统指令。 |
| 历史查询、检索与投影 | 查询服务；纯 fold/筛选作为普通函数，必要索引作为派生状态 | 查询已持久历史并携带来源、位置和时效；缓存/索引可重建，不能重新定义事实。跨会话查询可注册为 Agent 工具，复用相同授权读面；不先要求每种投影各有服务或插件。 |

非破坏压缩可先作为上下文能力中的操作及可注册策略；需要模型时使用既有模型调用能力。摘要结果持久记录，原历史保留。只有独立资源/生命周期或消费者契约确有需要时，才再拆成独立压缩服务。PF-023 要求的窗口检查、一次压缩与切换结果由明确的组合协议实现，不能靠挂一个压缩插件就宣称满足。

跨会话通信的投递、受理和接续走单独授权的协作协议，并进入目标会话的输入/运行规则；普通上下文贡献不会自行取得发送、唤醒、中断权限。它和历史查询是不同操作，可先复用输入与运行控制能力，不先新增通用消息总线。

## 3. 哪些是其他形态

| 对象 | 初步形态 | 生命周期和权威 |
|---|---|---|
| Agent Definition、已发布提示词及模型档案 | 受治理的版本化数据/资产 | 定义可动态管理，存续不依赖插件是否正在挂载；资产管理能力拥有发布/授权，运行装配消费明确版本。提示词可独立发布并由多个 Agent 引用。 |
| Session | 有稳定身份、归属和历史关联的持久业务对象 | 跨多个 Run、多个运行实例存在。关闭、归档与删除有产品含义，不能用 Fiber dispose 代替。 |
| Run、队列项、消息、控制请求 | 各自契约下的身份与状态记录 | 受理、运行、取消与恢复的规则可跨运行实例解释；消息与 Run 不一一对应，连续合格文本可合批。 |
| 活跃 Agent 实例、某次会话执行装配 | 受管运行对象、Context/scope 与 handle | 可由插件/Fiber 承载行为和资源，装配时创建，退出时清理；无需把每个数据对象都逐个应用为插件。运行代际与稳定业务身份分开。 |
| 提示词模板、变量声明、工具 Schema | 数据定义或有 owner 的注册条目 | 有版本、范围和来源；声明存在不代表当前值/提供者可用，发现可见不等于获得执行权限。 |
| 渲染文本、请求上下文与实际请求证据 | 值/快照/日志事实 | 候选组装、实际准备发送、发送与完成可区分；要能解释实际模型、消息、提示、工具与内容来源，不靠日后重跑模板复原。精确保存边界与数据表示待设计。 |
| 摘要、历史视图、检索索引 | 摘要是新增事实；视图/索引是派生状态 | 压缩改变后续选择的有效视图，保留原历史。摘要同样受来源与权限约束。 |
| 状态通知、实时流、注册关系 | 类型化事件、订阅、受管 effect | 适合通知、呈现和扩展；不是默认耐久队列或提交协议。业务必需的约束不能因监听者卸载而消失。 |

静态提示词原样保留，不执行插值；动态模板只引用受控且获准的状态。每次请求组装和每次动态模板重渲染不是同一个操作，渲染触发频率仍待选。已记录的历史不能因原变量插件卸载而改变。[已明确提示词要求与候选边界](../docs/proposals/agent-core/v1/system-prompt.md)。

## 4. 一次会话如何串起来

概念流程：会话管理建立/读取 Session → 输入能力可靠受理、按规则取批 → 执行装配在当前环境建立受管 Agent 运行实例 → 自建 Loop 在合法执行点调用上下文组装 → 取得历史、明确版本的提示词、获准贡献和模型/工具条件 → 保留相应请求依据并通过模型能力调用 OpenRouter → 将真实结果关联回原 Session/Run。

这只展示依赖方向，不固定启动顺序；活跃实例可以复用，空闲会话可以没有实例。上下文组装依赖被选择的能力及条目，整个会话历史读面不硬依赖所有工具和贡献插件。模型准备可能细化请求，最终证据要覆盖实际发送边界，而非只留最初草稿。

长期存在的是 Session 与持久工作事实。临时存在的是驱动、订阅、当前绑定、模型流等运行资源。后台工具和耐久 HITL 等待有各自的生命周期 owner；会话只持有业务关联。原会话实例被回收后，新的实例按持久事实重新关联仍合法的工作，不重新派发同一后台调用，也不复活已取消的 Run。用户明确的 interrupt/cancel 则继续按 PF-013 传播。

工具过程帧沿[协调文档](tool-execution-frames-coordination-20260913.md)的候选分工：tool-execution 产生与解释，存储兑现记录保证，context-sessions 关联、选择并消费；帧不自动全部进入模型上下文。

## 5. 动态性和首版边界

- 定义可以改版，提供者可以装卸，绑定与装配可以更新。未来请求在规定生效点使用新选择；在途请求是保留旧绑定、结束旧使用后切换，还是明确失败，须按具体能力选择，不能混用未经允许的版本/状态。
- 同一 Session 换模型作用于下一 Run；按 PF-023 复核授权、历史模态与窗口，必要时只作一次非破坏压缩。压缩成功而切换失败时保留摘要，模型选择保持原值；历史回复仍保留实际生成模型。换模型不自动结束合法后台工具。
- Context/scope 用于组合及参与该协议的可见性；租户、用户与精确对象权限仍在读写、渲染、检索、投递和执行入口检查。跨会话检索到的内容不能提升为系统指令或新增权限。
- 首版可在单进程内装配这些能力，不需预建远程总线；契约显式表达身份、状态权威、授权、所有权、失败和接续，未来远程实现仍需单独兑现相同语义。
- 尚未选择：具体插件/包数量、正式服务 API、Run/Step 词汇映射、持久事务/确认边界、渲染与替换时机、压缩策略、保留期限、通信唤醒与恢复政策。本轮只给出可讨论的职责模型。
