### 3.2 必须沿用的项目原则

- 本系统是 OMNE harness，以 Cordis 为内核；不称为 Cordis Harness，不把 DSH 当作本项目实现。
- Cordis 直接用官方发布包；其他选定 DSH 组件由本项目 fork 维护。直接修改自有模块中负责的边界，不为保留上游限制制造无独立职责的包装。
- 自建 Agent Loop、Harness、工具协议、治理和各业务能力。
- 能力定义、实现、绑定、组合可动态演化；动态不等于任意无损热迁移。
- 契约保持语言无关：TLA+ 行为、Alloy 结构辅助、JSON Schema 数据；TypeScript 是主要产品实现语言。
- 首版完整交付单机，但身份、权威、失败和依赖边界须支持未来独立扩展；不提前建通用远程框架。
- 从第一天支持租户隔离，区分全局自然人身份与租户成员关系；相关对象和操作显式带租户身份。
- 所有模型请求经 OpenRouter，包括需要模型的压缩等内部操作。
- 用户最新要求优先。需求、研究、候选、决定、正式规格、实现和验证各有地位，不能混同。

权威入口：[AGENTS](../AGENTS.md)、[当前架构](../docs/architecture/README.md)、[系统要求](../docs/requirements/system/constraints.md)、[规格清单](../spec/catalog.json)。

### 3.3 新增已接受运行时契约：本专题的既有依赖

[D-005](../docs/decisions/D-005-agent-runtime.md) 已接受 `data.agent-runtime-identity v1` 和 `capability.live-agent v1`。这是本轮交接必须补入的现状，不是本会话重新设计的成果。

身份定义沿 [data.agent-runtime-identity v1](../spec/data/agent-runtime-identity/v1/contract.md)：

- `SessionRef = {tenantId, sessionId}`，两字段共同确定会话；sessionId 由 Session 权威分配，在租户内不复用，包括逻辑删除以后。
- `AgentRef = {tenantId, sessionId, incarnationId}`，表示一次激活尝试/生命期；incarnationId 在同一 Session 的全部生命期内不复用，包括重启和准备失败。
- 恢复/重新激活同一 Session 使用新的 AgentRef；旧 AgentRef 不自动解析成新实例。
- Run、模型请求、工具调用、Definition 都有各自身份，不能用 incarnationId 替代。
- Context、Handle、工作许可和授权不是上述身份的可反序列化附赠能力。

[capability.live-agent v1](../spec/capabilities/live-agent/v1/contract.md) 对本专题最重要的约束：

| 已接受边界 | 对 context-sessions 的直接含义 |
|---|---|
| 一个部署内一个逻辑运行时协调权威，准备前预留，清理完成后才释放 | 不能另建第二个会话 runtime registry 绕开同 Session 独占激活；独占激活与“最多一个活动 Run”是不同不变量 |
| preparing → ready → closing → releasing → disposed | ready 只证明运行装配可用；不证明 Run 已启动、恢复或完成；清理失败保留阶段/残留 |
| activate 取得既有 SessionRef，不创建长期 Session | 创建会话和恢复会话由应用/组合先取得相应身份与事实，再请求激活 |
| Session attachment 是当前可验证、可撤销的能力绑定 | Session 侧须提供精确身份、原定义关联、激活前提和撤销屏障；不能用调用者传入 DTO 自报合法 |
| 激活发布与 attachment/必要绑定复核受同一屏障保护 | 后续必须解释归档/删除/撤权与激活的竞争，不能以两个独立注册表冒充事务；实际 Run 准入还须重查业务条件 |
| attachment 释放只解除运行附着 | 不删除/结束 Session，不销毁持久事实，不自动代替用户的 interrupt/cancel |
| 运行时拥有活体；Session 拥有长期身份、定义关联、持久历史及业务状态；驱动拥有 Run/输入/请求/控制 | 沿这条分工细化上下文能力，不把全部产品机制塞进 agent fork，也不重复拥有 Run 裁决 |
| 确切绑定和在途使用关系 | 已准入工作不能逐字段吸收新代际配置；提示词/模型/工具配置按各能力边界生效，不要求每个值变化都重建 Agent |
| 必要驱动/服务替换先关准入、收口、释放，再新代际激活 | 这部分已有选择；不要在后续稿中继续一概列为完全待选 |
| 可选贡献一旦被工作使用，就有在途依赖 | 消费能力和贡献 owner 共同兑现撤除；尚无在途撤除策略时拒绝繁忙撤除，不能直接卸载 |
| 旧实例/工作许可/业务执行权都须核对 | AgentRef 正确不证明某个已强停 Run 仍可提交结果 |
| 生命周期事件是进程内观察 | 不能当作 session log、耐久输入确认或恢复凭据 |

完整 Session/Run、日志、恢复、HITL、授权资产和分布式接管仍不在该契约的完整交付范围。其 Session attachment、访问验证、驱动等端口仍需后续能力提供符合性映射。[系统视图](../docs/architecture/agent-runtime.md)可辅助阅读。

### 4.1 系统目标

| 要求 | 对本专题的约束 |
|---|---|
| [运行时与持久状态解耦](../docs/requirements/system/runtime-state-and-continuity.md) | 从持久状态在同构资源下恢复并接续；异构环境有针对性装配。不能仅新建空实例就称恢复；不承诺任意异构热迁移或外部动作恰好执行一次 |
| [完全动态系统](../docs/requirements/system/fully-dynamic-system.md) | 定义、实现、绑定、组合可变；分别解释新使用、在途使用、旧事实与失败后果 |
| [长期稳定与演化](../docs/requirements/system/long-running-and-evolving.md) | 空闲资源可回收，但必要工作、等待、治理关系和记录不能依靠进程常驻才成立 |
| [可观测性与日志](../docs/requirements/system/observability-and-logging.md) | 入口到结局可关联，含执行尝试/版本/环境等关键依据；关键事实与缺口可见，不要求无限保留全部原始内容 |

### 4.2 会话、输入和运行控制：PF-013

[完整正文](../docs/requirements/product/user/PF-013-session-run-lifecycle-and-pending-input-control.md)。

- Session 有稳定租户/owner、Agent 关联，可创建、命名、置顶、过滤、归档、恢复、逻辑删除；组织、设备、运行实例变化不改写原归属。
- 创建重试不产生重复空会话；手动标题不被自动标题覆盖。
- 归档后历史可读、不再接纳新消息；恢复检查原 Agent，不能换 Agent 或空会话冒充恢复。逻辑删除不可恢复、身份不复用，不等于物理擦除。
- 有活动 Run 时归档/删除拒绝；先通过独立控制收口。关闭后未执行队列须有可审计终态，不被恢复意外启动。
- 一个 Session 最多一个活动 Run。队列有界、可靠保存后确认受理，满时拒绝，不丢弃已受理项。
- 按当前已确认顺序消费；队首连续合格文本合批，命令分隔。消息保留独立身份/原文，不能假设一条消息一个 Run。
- 尚未取批项可查看、调序、编辑、移除；取批后冻结，不能追溯改写实际执行输入；并发编辑/取批须统一裁决。
- 忙时普通输入默认 queue；可选择 interrupt_then_run。普通追加文本不直接无损注入在途 LLM/tool call；答复 HITL 走精确请求关联。
- interrupt/resume/cancel 针对精确 Run 及其合法状态。取消是工作终态，恢复/重试不得复活；旧页面和迟到请求不能误控新 Run。
- force_stop 撤销继续执行权，尽力终止执行体并清理/隔离；逻辑停止、物理停止、清理和外部效果未知分别表达。会话级强停可 hold 待执行输入，不能立即自动启动下一轮。
- queue/control 的确认与真实结果跨端、刷新、重建保持一致；临时 token/流式进度不承诺全部耐久重放。

必须保留的控制差异：

| 原 Run 自有、未结算工具 | 普通 interrupt/cancel | interrupt_then_run |
|---|---|---|
| 前台且可合法转后台 | 中断并记录真实结局 | 转后台继续；转换失败则中断 |
| 前台且不可转后台 | 中断并记录真实结局 | 中断并记录真实结局 |
| 已后台执行 | 同样中断并记录真实结局 | 保持后台执行 |

运行时因回收/重建退出与人类明确停止是不同原因；不要把以上动作合成一个 dispose 开关。

### 4.3 模型、提示词、历史与多模态

[PF-023](../docs/requirements/product/user/PF-023-session-model-selection-and-continuity.md)：同一 Session 可切合法模型用于下一 Run，保持历史和工作关联。候选/设置/授权重新求值；历史模态存在而目标能力未知时具名拒绝，不能静默删内容、转写模态或换模型。切换前按目标窗口可配置比例检查，超限先作一次非破坏压缩；失败或压缩后仍超限则拒绝切换。摘要成功而切换失败时摘要保留、模型选择保持原值。历史回复保持实际生成模型，后台工具不因换模型被重派或误停。切换与 Run 准入并发、模型事实来源、估算/费用等还需设计。

[提示词材料](../docs/proposals/agent-core/v1/system-prompt.md)中“用户已明确的要求”仍有价值：提示词可独立创建、管理、发布并供多个 Agent 引用；静态纯文本不插值；动态模板只使用系统控制、获准提供者声明的受限状态集合。模板局部别名可定义，不代表用户可自行注册任意 state_key。模板定义、当前状态值、渲染结果分别表达。**动态渲染时机和频率尚未固定**，不能把“每次请求组装”直接解释为“每 Step 重渲染”。该旧提案中的聚合措辞、已撤回模型和候选 Schema 不自动有效。

[PF-017](../docs/requirements/product/agent/PF-017-cross-session-history-and-background-coordination.md)：获准跨会话查询已持久消息、工作、状态与结果，目标运行时无需驻留。查询、发送、唤醒、中断分别授权；同用户/同租户不自动授予全部权限。结果标识来源和历史位置/时点，区分无匹配、不可访问、不可用、未完成；无权查询不泄漏目标存在。协作请求的提交、受理、排队、答复、无法处理可辨，已经受理的请求不能随原 runtime 丢失；重试不产生新的同一逻辑工作。到达消息遵守目标输入/Run、预算和容量规则。

[PF-009](../docs/requirements/product/user/PF-009-multimodal-input-attachments-and-commands.md) 与 [PF-022](../docs/requirements/product/agent/PF-022-multimodal-response-and-output.md)：输入附件、输出媒体和引用进入历史时应保留相应原件、可读性、来源、交付与权限义务。临时文件路径或 JSONL 中一个 URL 不自动兑现媒体保存。模型能力、原始内容保存和呈现投影分开。

## 5. 已有 context-sessions 初步模型

本节完整保留核心候选，供接手继续；第 3 节列出的已接受运行时边界优先约束它。

### 5.1 三种上下文与承载单位

1. **Cordis Context**：运行时的服务访问、交互和资源登记环境。
2. **上下文状态来源**：各能力拥有的事实，经授权向当前消费者提供。
3. **模型上下文**：某次请求实际选中的提示词、历史、摘要、输入、工具描述及多模态内容/引用。

Plugin 是装配和受管生命周期单位，service 是调用表面；不是互斥选项。插件可提供服务或向现有服务注册贡献。包、插件、服务、运行实例、进程不要求一一对应。

### 5.2 能力划分候选

| 能力 | 初步形态 | 边界 |
|---|---|---|
| 会话管理 | 插件提供 service | 长期身份、归属、定义关联、目录及生命周期；管理很多 Session，单条记录不必是插件 |
| 输入与 Run 控制 | 驱动/执行编排能力提供服务 | 队列、取批和精确控制统一裁决；与会话业务状态/日志和 runtime 准入明确交接，不在 UI/Loop/Session 各裁决一次 |
| 活跃实例管理和装配 | 已接受 live-agent 契约＋Factory/driver 贡献 | 消费 Session attachment，管理临时运行资源；活体目录不是会话目录 |
| 会话日志与历史读取 | 逻辑记录/读取能力 | 顺序、历史位置、来源和请求依据；记录事实但不替工具/Run 权威重新决定结果；不预设所有状态都 event sourcing |
| 存储后端 | 插件提供或注册实现 | 持久确认、读写和资源生命周期；可服务多种记录，不拥有模型上下文选择策略 |
| 模型上下文组装 | 插件提供 service | 消费提示词渲染结果、有效历史、已接纳输入和获准贡献；驱动决定调用时点；最终请求准备变化也须被证据覆盖 |
| 上下文贡献 | 各事实 owner 的插件注册条目 | 组织规范、工作区摘要、变量、工具指导、等待状态等；有来源/范围/权限/撤除规则，一个变量不必一个插件 |
| 历史查询/检索/投影 | 查询服务＋纯函数＋必要派生索引 | 获准历史读面；缓存/索引可重建，不是第二事实权威；可注册为 Agent 工具 |

压缩可先作为上下文能力中的操作和可注册策略；需要模型则消费现有模型能力。摘要作为新增事实保存，后续有效视图可变化、原历史保留。没有独立契约或生命周期需要时，不预建专门压缩框架。

跨会话通信有自己的授权/受理/接续协议，进入目标输入规则；与检索分开。可以复用已有输入与执行能力，不先建立通用消息总线。

### 5.3 数据、运行对象与派生结果

| 概念 | 形态和保存含义 |
|---|---|
| Agent Definition、提示词、模型档案 | 受治理的版本化定义/资产；存续不依赖活体插件挂载 |
| Session | 稳定业务身份和状态；跨 Run 与 AgentRef 存在 |
| Run、队列项、消息、控制请求 | 各自契约下的身份/状态；数量和生命周期不同 |
| 活跃 Agent、Context、handle、订阅和绑定 | 受管运行对象；重建后为新的生命期，不能直接持久化充当恢复格式 |
| 模板/变量声明/工具 Schema | 数据定义或有 owner 的注册条目；声明存在不保证实现和值可用 |
| 渲染结果、组装快照、实际请求依据 | 值或记录；区分准备、实际发送与结果，不能靠将来重跑模板恢复过去文本 |
| 摘要 | 新增事实，保留来源、权限和对应历史范围 |
| 历史有效视图、检索索引、缓存 | 派生状态，可重建；不能改写原事实 |
| 实时流/通知/effect | 运行交互和资源关系，不自动耐久 |

### 5.4 一次工作的概念链路

会话能力创建/读取 Session → 输入能力可靠受理并按规则取批 → 合法运行装配与准入 → 自建 Loop 调用上下文组装 → 读取历史、明确版本的提示词、获准状态和模型/工具条件 → 形成实际请求依据并经 OpenRouter 调用 → 真实结果归回原 Session/Run。

这表示责任/依赖，不固定物理启动顺序：活跃实例可复用，空闲会话可无实例。历史读面不依赖原 driver、模型网络或全部工具插件在线。用户显式取消、依赖撤除、空闲回收、进程故障分别解释。

## 6. 工具内部过程帧的完整协调要点

[工具帧协调稿](tool-execution-frames-coordination-20260913.md)已单独交付；这里保留足够让上下文设计独立接续的结论。

| 责任 | 主责与交付 |
|---|---|
| 工具专有进度、阶段、文本/媒体 payload | 工具实现产生；自报进度不自动成为执行成功 |
| invocation、attempt/代际、生产资格、顺序、终态 | tool-execution；来源要可信，旧尝试不能覆盖新结果或终态 |
| 观察订阅、回放接续、披露资格和缺口 | tool-execution 的观察契约，使用适用授权能力；可有脱离原执行宿主的历史实现 |
| 物理写入确认、位置、完整性、读回及故障 | 存储能力；不重新定义调用终态 |
| Session/Run/请求与调用的因果关联 | 编排及 context-sessions；后来的 Run 不改写原发起关系 |
| 哪些帧/摘要/结果进入模型 | context-sessions/请求组装，保存实际消费依据 |
| UI 流式显示、展开、诊断导出 | 获准消费端；显示成功不表示耐久，也不能从无新帧推断工具结束 |
| 记录等级、保留/裁剪、背压、脱敏及失败政策 | 工具、存储、会话与治理共同收敛，当前未完整定案 |

关键生命周期反例：工具已转后台，原会话运行实例被回收。若生产者或唯一必需记录者跟随该实例退出，合法后台工作或记录保证会消失。因此后台执行和必需记录须有独立、受管 owner；会话实例只持有关联和允许的观察/控制关系。业务关联、权限委托、运行时所有权不可共用一棵隐式树。

必须分别表达产生、保存、展示、送入模型、请求完成；明确允许临时展示的内容和必须持久确认的事实。写入成功但回执丢失时重试辨认原事实。重订阅不能重派工具。迟到、重复、乱序、过期、未持久化、读失败、结果未知有可解释差异。

调用内顺序、跨调用因果、Session 日志位置、界面到达时间不同；媒体保存与帧引用需要明确成立/清理条件。工具帧格式更新后，受承诺历史须有读取/解释路径；不能依赖原工具插件永远驻留。

待共同决定：记录等级/确认点、游标/重放范围、并发故障处理、Session 归档删除与仍活跃后台工作之间的控制/保留义务、提供者和格式更替。不预先要求独立 FrameService、每帧插件或统一物理总日志。

### 7.2 已核对的机制及限制

| 机制/组件 | 可用的起点 | OMNE 仍需承担的部分 |
|---|---|---|
| Cordis service/inject/plugin/Fiber/effect | 声明式能力依赖、装配、实例和注册清理 | 租户、持久身份、业务提交、真实排空与跨进程协调不是自动提供 |

| DSH scope | 对参与该协议的注册/事件做作用域组合 | 不是所有 Cordis API 的通用隔离，也不是租户授权或恶意代码沙箱 |
| dsh-agent | live registry、handle、factory 交接、agent-local setup、initiator | 原始 agent/session 单身份、裸对象访问和退出政策与 OMNE v1 有差异；当前已有定向 fork，按目标规格直接修改 |
| dsh-system-prompt | section/context/variable/tools 贡献、稳定顺序、作用域覆盖、来源快照 | 固定 DSH 身份文本、插值/更新策略、waterfall 改写权和逐次求值不能直接成为 OMNE 约定 |
| dsh-session | 内存追加日志、历史 surface/非破坏替换和派生消息 | append 不等于耐久；缺少完整 OMNE 租户、会话生命周期、Run/输入及控制契约 |
| session-persistence | acquire handle、append/read/stat/flush 等机制 | 受理确认、归档/删除/保留、跨后端业务政策须补；注册后端名称存在不证明已选必需后端可用 |
| JSONL 后端 | 批量 fsync、失败 rollback/truncate、破损尾部修复、本地写锁 | 是本地日志基础，不是 blob store、分布式写入权或后台工作恢复器 |
| projection/cache | 按日志折叠、watermark、可替换缓存 | 不能替代会话/Run/执行的权威状态，缓存丢失应能重建 |
| DSH resume/repair | 重建已记录历史，对未完成工具标未知而不假造成功 | 上游为旧 turn/step 收尾并创建新 loop，不代表找到旧 worker、原 Run 合法接续或已消费批次恢复 |
| DSH Inbox/steer/cancel | 消息身份、splice/fold、结构编辑、取消局部机制 | steer 是下一 Step 输入，不中断在途调用；cancel+followup 是两个动作，不是可恢复的 interrupt_then_run；耐久受理与并发语义要自建 |
| DSH 工具/HITL | 调用/取消/结算、问答和批准的局部结构 | 固定版本没有满足 PF-003 的通用内部帧协议；本地 jobs、等待 Promise 不兑现跨 runtime 连续性 |

### 9.3 可直接用于设计检查的场景

- 两个客户端并发编辑/调序/取批，恢复后消息内容、顺序和实际批次一致。
