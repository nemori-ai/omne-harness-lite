# 首批实施路线选择

本页保留原实施路线对消费者开放和验证范围的约束，来源为
`7e758f21f8f92c1d46fab194fdaf120239b8e11c` 的本路径。任务 DAG、角色派发与进度
已转为临时施工材料；当前接口由成员设计拥有，历史接受归[交付记录](delivery.md)。

## 路线与依赖理由

首个运行节点采用确定性驱动与真实 allow 工具调用，先验证当前身份、授权、
本地预算、Session/Agent、记录与执行责任能共同成立。完整耐久 HITL 和真实
OpenRouter 链路沿原 [M1/M2 范围](scope.md)分别验收；缩小节点不撤销 A01–A32，
也不允许缺席的 ask 路径被放行。当前装配和行为范围归
[local-harness 设计](../../../../apps/local-harness/design.md)。

共享 work-data/records 提供实际公共数据与记录端口，diagnostics 提供受限
诊断面，真实 JSONL/共同准入再供业务 owner 消费。这条依赖保证受控效果等待
真实耐久确认，失败/未知仍有拥有者；不能用类型存在或独立组件通过代替组合。
目录 owner 与关闭责任遵循 [D-011](../../../decisions/D-011-diagnostics-directory-ownership.md)，
JSONL、admission 和业务使用原作用域内的唯一资源权威。

设计接受、提供者实现、产物消费和应用组合是不同证据。组件可在固定接口下
独立实现，开放消费者必须有该组合所需的实际提供者与失败/恢复证据。
[A01–A32](acceptance.md)保留原行为 ID 和反例范围；证据限定实际修订与环境，
不把模型、探针、编译或普通检查扩张为完整产品通过。
