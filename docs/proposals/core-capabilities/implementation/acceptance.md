# 验收标准清单

本表是本批目标函数。全部适用项完成并通过[交付对账](delivery.md)后才可接受整批；
M1 只表示工具审批流程交付，M2 表示真实文本模型流程也已交付。
测试文件/命令在实施时绑定到这些 ID，不以测试数量、覆盖率或上游全绿替代行为判断。

规范编号归[实施规格的依赖表](implementation-spec.md#精确契约依赖)；Cxx 指
[核心组合场景 v1](../../../../spec/compositions/core-work-coordination/v1/scenarios.md)。
下列是本批实施符合性场景，未列入本批的原 Cxx 仍保留其后续交付义务。

A02/A03 还须从真实治理操作建立定义和权益：draft 条件编辑、publish 重试不增版本、
旧发布内容不可改、公开入口不能改官方原件；fork 需要派生权且不继承原动作授权。
外租户定义选用保留原 owner/精确版本，失去权益或停用后阻止新准入且不级联删除
原 Session/历史；只更改本地选用不能制造外部权益。对应 TG-04/05。

A03 的持久授权测试必须实际调用 grant/amend/revoke，覆盖授予者当前资格、
越权扩范围/扩版本拒绝、合法授权跨 Agent/宿主重启仍在、撤销后恢复不复活。
不得以直接预置 grant 表替代管理路径，也不能把一次性 approve 当持久授权。

A11 的设置测试必须实际调用 setOverride/clearOverride/readEffective，覆盖
字段 owner/Schema/合法作用域、未知配置拒绝、条件提交冲突，以及 Session 覆盖→
该用户对定义的覆盖→定义默认的真实生效来源。clear 与保存 false/null 分别
处理；非法值不得当“清除”成功。重启后保存覆盖与有效值一致，组织强约束不被
覆盖削弱；模式变更只影响下一尚未准入动作，不伪造现有 pending 请求的答案。

M1 同时执行 A26 的本地预算 owner 子场景：真实立场/预留/结算与并发额度竞争、
回执去重及 unknown 暴露。P4 再将真实 OpenRouter 的价格/计量接入相同 owner；
P3 不能使用允许一切的预算替身，也不能把任意本地工具推定为免费。

## 判定与环境缺口

离线传输测试可控制各种模型输出和网络交错，但不冒充真实 OpenRouter。真实模型
行为不确定时，拆分判断：协议/授权必须由可控测试稳定验证；线上用固定输入、
明确支持的工具选择设置与人工答复验证一条真实链路，不断言生成文本逐字相等。

A22 需要明确的模型/路由、凭据、允许的测试数据和费用额度，执行时由任务授权
提供。缺少它们可以完成其它已授权工作，但 A22 记未执行、M2 不接受；没有
无限重试或偷偷改用直连模型的通道。测试期间不向外发送仓库私密正文或真实用户数据。

本批不声称所有 D-008 场景均已覆盖。C12/13/14 的命令/复合控制、C17 的后台、
C19 的供应方订阅/账单、C20 的跨模态压缩、C24 的媒体、C25 的暂行撤销，以及
C28 的 slash 部分继续未实现；本批范围内的同类失败义务不得因这些排除项被跳过。
