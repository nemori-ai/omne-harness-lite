# 租户、定义、设置与动作授权（候选）

本页消费[共同契约](shared-contracts.md)和[覆盖记录](requirements.md)。操作均使用
可信主体、明确 tenant、稳定 operationId 和期望修订；去重、冲突和耐久确认依共同
契约。默认没有权限，不能由 Context 可见、同名 ID 或已知链接获得授权。

## 租户与成员

**TG-01**：自然人全局身份与 `(tenantId,userId)` 成员关系分离。首版产品租户有
personal、organization 两类；平台提供者是可信系统主体，不沿用旧候选未定义的
platform 租户管理语义。个人租户创建与唯一有效 owner 成员共同提交；同一自然人
最多一个有效个人租户。组织至少一名有效 `super_admin`，另有 `member`；具体
委派权限使用显式操作集合，不预建一套无需求的 admin/editor 角色层次。

`createTenant`、`addMember`、`changeMember`、`removeMember`、`closeTenant` 由
对应管理主体调用。个人 owner 不可替换为其他人，不允许增加第二名个人成员。
组织 super_admin 可管理本组织成员及适用资产／配置／预算；变更不能移除最后
一名有效 super_admin，转移最高管理资格以一份共同提交完成。成员状态
active／suspended／removed，removed 后重新加入形成新 membership revision，
旧授权依据不因身份相同恢复。所有操作记录操作者和生效修订。

**TG-02**：用户选择当前组织只是新操作的目标上下文；既有 Session 的 tenant、
owner 和原定义关联不可由切换菜单改变。组织不可用、成员失权或目标不匹配明确
拒绝，不回退个人租户。不把同一用户在多个组织的权限和权益合并。个人 Session
正文默认只对 owner 及明确获准主体可读；组织管理员的管理权或财务汇总权不
自动包含私有 Session 内容。紧急运行控制是独立资格，操作不必取得内容读取权。

**TG-03**：关闭租户先进入 closing，封闭新业务准入并保留获准读面／清理；列出
仍活动的 Run、后台调用、未结算决定、财务责任与资产引用。显式控制或交接使其
收口后才能 closed。关闭不是物理擦除、供应方退款或任意外部效果撤销；失败、
未知及剩余责任可查询。已关闭 tenant 身份不复用，重试只认回原关闭操作。

## 定义、权益与选用

**TG-04**：Skill、SlashCommand、Plugin、Agent Definition 具有稳定 DefinitionRef，
owner 与 creator、official/customized 来源分别记录。官方来源仅由受信种入
主体声明；公开管理面不能修改官方原件。草稿 `draftRevision` 可条件编辑，
发布产生不可变精确 version 和内容摘要；发布重试不增版本，修改旧发布内容拒绝。
有引用义务的草稿不能丢弃；已发布定义退役保留原件和历史，不提供无痕硬删除。

操作为 createDraft、editDraft、publish、discardDraft、retireDefinition、readVersions。
有权 Agent 可作为实际作者，owner 取本次明确租户而非创作者身份。fork 需要相应
派生权，新建 DefinitionRef，保留源引用和新 owner；不继承原定义的动作授权。
定义的可配置默认与原件分离，用户覆盖不修改已发布内容。

**TG-05**：`Entitlement` 由有权签发者拥有，绑定受益 tenant、DefinitionRef、版本
范围、use／derive／redistribute 等精确权利及条件、期限和状态；本租户 owner
权益来自所有权，不伪造外部自授。外部权益的暂停/撤销/到期由来源权威确认；
管理员不能把本地选择改成有效外部权益。准入检查当前依据且不借用个人权益。
明示跨租户共享只授予被引用定义在该操作内所需访问，不授予来源租户通用读取。

`Acquisition` 由消费租户拥有，记录精确选用版本、开放配置和 enabled／disabled／
removed；selectVersion、configure、disable、remove 只改变选用关系。发现新版
不自动升级；选用不等于真实装载。停用或移除先检查并报告 Agent／Session／日程
等引用，默认不级联删除、不换目标、不停止已准入调用。可以让相关后续使用明确
阻塞；引用需重选时由各自管理操作承担。操作结果记录受影响引用和后续生效边界。

## 配置与授权事实

**AU-01**：每种设置登记唯一 owner、值 Schema、可配置主体、作用域、默认来源、
缺席规则和生效边界。readEffective 返回已保存覆盖、实际有效值及各依据，不能
用 null/false 代表“清除”。setOverride／clearOverride 条件提交并形成审计。
未知 setting 或错误 scope 拒绝，不把任意插件 JSON 合进全局配置。

本轮需要的已选规则：会话模型取 session → 用户模型偏好 → definition 默认；
忙时输入行为取本次显式值 → 用户偏好 → queue。确认模式取 session 覆盖 →
该用户对本 definition 的覆盖 → definition 默认；定义缺省为 standard。
这些优先关系只适用所列字段。组织/部署强约束参与资格交集，不能伪装普通默认，
也不能通过用户覆盖削弱。权限读取失败不给默认全权，不随机选择中断行为。

**AU-02**：持久授权记录目标 DefinitionRef、受益主体／tenant、适用定义版本集、
动作权限、对象/环境范围、条件、有效期、授予者与状态。用户新授予默认固定当前
精确版本；扩大版本集必须显式表示。重建 Agent 不影响仍有效授权，换 definition
或 fork 不继承；版本更新只在原显式版本集合覆盖时继续使用，不能扩大动作范围。
grant／amend／revoke 均验证授予者当前能授予这些权利，不能授出超出自身资格的
范围。一次性批准另归 HITL，不能由这些操作隐式创建或升级。

设备授权可为逐项操作集合或全权覆盖该设备声明可授予的操作，scope 为当前
Session 或明确的设备持续范围；两维独立。全权不包括硬约束禁止的动作、其他
tenant、其他设备或专属外部账号同意。持续授权耐久保存，撤销影响下一准入；
已开始动作的停止另由其生命周期控制。

## 工具声明和当前判定

**AU-03**：工具命令的 `authorization` 声明至少给出权限名称集合、参数到对象
和范围的解析规则、是否受人类确认控制、允许请求的授予者类型、影响说明和
事前/合格暂行资格引用。规则是受信版本化解析器消费的声明，不是执行任意用户
脚本的机会。无法完整表达动态子动作的工具必须在子动作边界再次解析和准入；
不能只批准工具外壳后产生未经涵盖的网络、文件或设备效果。

声明缺席、未知权限词汇、无法解析目标、定义/实现不匹配或解析器不可用，均
不得作为无需授权处理。工具登记拒绝该可调用贡献，保留可诊断错误；允许帮助
披露时仍说明未就绪。无需额外人类确认的读取也显式声明 `confirmation=none`，
且仍过租户和读取权限门。定义声明不是证明实现没有隐含副作用的安全边界。

**AU-04**：会话确认模式为：

| 模式 | 受控动作有完整有效授权 | 尚缺可向合法主体申请的授权 |
|---|---|---|
| standard | allow | ask |
| confirm | 仍 ask，除非已有绑定该动作的有效一次决定 | ask |
| unattended | allow | deny，原因 human_confirmation_disabled |

任何模式下硬拒绝均 deny。模式不制造 grant；“全权设备授权”作为 AU-02 的有效
授权输入，不是自动跳过硬约束的模式。非人类确认动作在缺少权限时直接 deny，
不能凭 confirmation=none 免权。权限来源不明返回 unavailable，区别于业务
deny，不伪装成可批准请求。模式变更在下一尚未准入动作生效，已有 pending
请求不自动产生答案；实际放行沿待答／取消／重检协议处理。

表中的“完整有效授权”包括本次 Action 可合法消费的耐久一次决定；它仅补足
原请求列出的可授予缺口，不能代替租户资格、硬约束或缺失的专属账号／设备
同意。故无持久 grant 的 standard 路径可以 ask → 合法批准 → 当前重检后
allow，无须暗建持久 grant；confirm 也不对同一可消费决定重复询问。

**AU-05**：evaluateAction 对已经冻结的 Action 依次核对：可信主体及 tenant／
当前成员或合法委托；Session／definition/版本及权益；真实绑定与环境资格；
不可绕过限制与专属同意；当前 grant 和确认模式；需要时合法一次决定。
拒绝／不可用原因按披露资格返回，硬拒绝不能变为 ask。返回 allow、deny、ask
或 unavailable 及可追溯依据。ask 不执行，只给出可合法申请的精确缺口。

**AU-06**：权限判定与真实准入参与[CC-02–CC-04](shared-contracts.md#单机共同提交的实现约束)。
工具装载、预览、模型请求发出时的有效性不足以授权后来调用；批准也不能越过
已经生效的撤权。一次决定只覆盖其 Action，不能由参数名字相同或文本“已批准”
冒领。来源服务失效、撤除、准备失败各自可见；授权 provider 计划卸载先封闭新
准入并保存事实，不能把依赖丢失处理成默认允许。

## 取舍和待实现证据

本候选选择最小角色词表与逐字段配置规则；不保留旧候选 platform 类型、成员
数据“绝对隔离”对共享资产的误读或无版本范围的模糊授权。状态 owner 保持独立，
存储和 Cordis 插件负责实际供给。形式/实现验收必须覆盖最后管理员竞争、跨
tenant 借权、原件发布不可变、旧修订覆盖、grant 撤回／工具换代／模式变更竞争。
认证系统、外部账号同意、发行平台和权益签发的实际连接器继续由具体提供者实现。
