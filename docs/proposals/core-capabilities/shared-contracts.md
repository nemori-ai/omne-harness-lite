# 共同数据、耐久提交与准入协议（候选）

本页提出本轮各能力的共同语义，规范化前仍为候选。身份依赖
[data.agent-runtime-identity v1](../../../spec/data/agent-runtime-identity/v1/contract.md)，
运行附着及资源使用依赖
[composition.agent-session-binding v1](../../../spec/compositions/agent-session-binding/v1/contract.md)。
本文不修改这两个版本；后续规格分离为共享数据、持久记录能力和实际消费它们的组合。

## 身份、引用与内容

**CD-01**：所有身份是不复用的非空不透明字符串，元组按逐字段精确相等比较。
新身份由相应权威分配；调用者生成的去重键不是对象身份或操作凭证。
全局 `UserRef={userId}` 来自认证边界；`MembershipRef={tenantId,userId}` 来自租户
治理。`DefinitionRef={ownerTenantId,definitionId}` 与不可变的 `version` 分开；
租户选用保留原 owner，引用外租户定义须经明确权益，不能复制成匿名本地定义。

`RunRef={SessionRef,runId}` 表示一件逻辑工作；`StepRef={RunRef,stepId}` 表示一次
模型决策及它产出的工具执行批次，或一次具名辅助工作（标题／压缩）。辅助工作
未归入某 Run 时以 `WorkRef={tenantId,workId}` 为归属，并保持到 Session／切换
意图的因果引用；不得为归因虚构用户 Run。工具/模型的逻辑调用分别有 `callId` /
`requestId`；每个实际尝试有新的 `attemptId`，重连沿原 attempt，不算新尝试。
每个执行所有者的 `epoch` 和每份运行资源的 generation 区别于业务身份。

**CD-02**：跨边界请求显式传递可信主体、tenant、目标、操作和因果引用；引用本身
不授予读取、写入或控制权。身份认证、成员/委托权限与因果发起者分别保留。
工具和模型操作都必须关联所属 Step 或具名辅助工作，以便拒绝、费用和恢复归因。
运行对象、Context、句柄、AbortSignal、函数和凭据原文不进入持久数据。

**CD-03**：共享内容为有序块序列；每块有稳定 `blockId` 和明确种类：
`text`、`image`、`audio`、`video`、`file`、`tool_call`、`tool_result`、`deferred_receipt`。
deferred_receipt 引用尚待答的原 request/call/continuation，表示暂挂而非终态结果；
模型适配器须保持这种区分，不能伪造答案来满足供应方工具消息的成对格式。
非文本块引用受治理媒体或精确调用；文件名和宿主路径不代替原件。模型未提供的
内部推理不被构造为内容；实际提供、允许保留的辅助内容须具名来源与披露策略。
输入/输出投影说明每块是模型原生消费、仅作工具可用附件或明确失败，不静默丢块。
媒体块以 delivery=model_native/agent_attachment 保留这项意图；实际投影还须
核对目标能力，不因此字段便声称已发送。输出原生媒体沿原生路径记载，后续
模型消费仍重检；失败记录由调用／输出状态表达，不制造假的空媒体块。

`MediaRef={tenantId,mediaId}` 指向不可变字节和已核实的摘要、长度、MIME；文件名
是元数据，存储地址是提供者私有信息。派生内容使用新 mediaId 并引用来源及处理
动作，不能用转写结果替换原音频却保留原身份。远端临时 URL 不构成耐久媒体引用。

**CD-04**：`Action` 是经命令参数校验、声明解析和实际对象解析后的不可变数据，
至少绑定调用身份、定义版本／命令、声明版本／实现绑定、目标环境、全部影响权限
判定的参数和规范资源对象、所需权限、影响说明及允许的确认路径。批准匹配使用
这些结构值的精确比较；摘要只作索引和完整性辅助，不靠含糊拼接或模型自报生成。
机密参数以不可变秘密版本引用进入记录；秘密轮换或目标解析变化若改变动作含义，
产生新动作，不暗中沿用旧批准。准入后实现接收冻结后的同一参数和资源绑定。

Action 的 attemptId 在 proposed 时分配，仅标识此次待准入尝试；实际执行
身份和执行许可在准入后建立，分配 ID 不代表接纳或执行。换实际尝试产生
新的 Action 和当前判定，不能借相同 callId 复用旧批准。数据 Schema 固定
RunRef.session、StepRef.run 等嵌套字段；同一结构内所有 tenant 必须满足
该操作已核实的归属关系，JSON Schema 的结构验证不代替此动态授权校验。

## 耐久记录能力

**DR-01**：记录能力提供 `readHead`、`readRange`、`commit`、`lookupOperation`、
`acquireWriter`、`closeWriter`。一个 `commit` 含可信 namespace、操作身份、输入
内容摘要、期望修订、一个或多个有 owner 的记录及确定结果；每个批次全部成立或
全部不成立。属于不同状态权威不妨碍它们参加已声明的共同提交，但仅相同提供者
明确支持的协调域内可原子提交；不同文件、服务或远程 store 不自动享有该保证。

记录 envelope 保存 formatVersion、coordinationDomain、commitId、单调序号、
各目标 stream 和前置修订、tenant、主体、因果引用、状态变化类型／版本、数据及
操作结果。业务状态转移由所属能力校验和解释；存储只维护批次、顺序、完整性、
独占写入和去重，不调用任意用户插件判定权限或推断事件含义。

**DR-02**：`commit` 结果区分：`committed(receipt)`、`conflict(currentRevision)`、
`rejected(reason)`、`unavailable`、`unknown(operationRef)`。只有实际耐久确认后
返回 committed；接收进内存、emit、排入写队列或文件 write 返回均不够。
同 namespace／主体／operationId 的相同输入重试返回原结果，异输入返回冲突；
不得把原受理消息还原到编辑前状态。结果未知时只查询／认回同一操作，不换键重试。
已提交后通知失败单独报告 delivery 状态，不能声称写入没发生。

**DR-03**：首版每个协调域只有一份被存储提供者真正强制的写入权；writer epoch
跨重启不复用，旧 epoch 不能追加或提交。读者带确切水位读取完整批次；遇到落后
索引返回水位／重新读取，不能用落后投影判断授权、终态或恢复。读取完好历史与
重新获得执行权分别进行。写入权丢失立即封闭新提交，未知写入先核实再接管。

**DR-04**：首版 JSONL 提供者采用一行一个完整提交 envelope 的项目格式；支持的
OS／文件系统须在实现验收列名，不把网络文件系统视为普通本地盘。批次先校验／
编码，串行写入，完成文件同步及新建／替换所需目录同步后才推进耐久水位和回执。
长度／摘要和序号用于发现截断、乱序和完整行损坏；摘要不构成对恶意修改的签名。
只有最后一个未完成提交的尾部可在持有独占写入权、保全故障原件后修复；完整坏行、
中间缺口或不识别格式拒绝可写恢复，禁止跳过。同步或写入失败不推进已确认水位；
若截回旧水位或确认失败也未知，整个 writer 保持隔离及待核实，不继续追加。

**DR-05**：关闭先禁止新提交、排空并完成同步，再释放 writer；失败保留剩余记录、
责任和可诊断结果。计划更换提供者须冻结该域新写、确认旧 writer 已排空和释放，
核对同一已提交前缀／操作结果后启用新 writer；任一步失败保留明确阻塞，不同时
启动两个写者。读取历史可以有独立可用性。格式升级保存原件并记录转换依据，
不静默覆写原有版本；本版不承诺通用不停机存储迁移。

## 单机共同提交的实现约束

**CC-01**：首版业务协调域由一份明确的准入协调实现服务于本批核心权威，使用
同一有序提交通道，原子关系仅限本契约明确的组合：输入/取批与 Run、动作/批准
消费与执行许可、等待与决定后果、预算预留与调用受理、媒体引用与内容受理。
这不把权威合成一个业务服务，也不要求将知识、制品或外部账单纳入统一事件模型。
实现可以将多个 typed stream 的一批记录放进同一 JSONL 提交，不能先写多个文件
再声称它们已原子成立。能力拆为远程提供者后仍须实现相同协议或发布新契约。

**CC-02**：准备读取、参数解析、外部资格查询和资源取得均在短提交之外完成，
每项带精确版本、所有者和撤销关系。共同提交验证当前身份权限、对象修订、绑定、
工作 epoch、预算和操作去重，按确定顺序裁决；状态 owner 的纯检查不运行任意
插件回调。权限变更、工具失效和执行准入参与同一撤销屏障；不能先独立询问几个
isValid，再在它们可能变化之后写入“已准入”。

**CC-03**：耐久 I/O 与 D-007 的短运行提交明确分开。可先在短提交内为已准备的
操作分配有序位置并封闭冲突状态，再异步持久化该位置。**分配位置即该操作的
逻辑准入点**，并非等待 fsync 后再作第二次同义准入；当时必须通过全部当前
资格检查，取得精确使用并扣住预算。结果对外显示 pending_durability，在该
位置及全部依赖记录形成耐久前缀前，不确认 committed，不产生受控效果。
尚未持久的授权增加或人类答案不可支持准入；同批预算预留可与调用一起提交。

撤权／撤除在同一短门获得位置时，立即封闭之后的位置；位置 n 的调用先准入、
撤权占 n+1 时，n 在耐久确认后仍可执行，因它已在撤权前准入。若要阻止 n，
必须使用精确取消／执行权撤销；不得将普通撤权重解释为强停。授权增加仅在其
耐久确认后可用。仅异步准备而尚未获得逻辑位置的操作不算准入。

写入失败使受影响协调域待核实，未确认位置不能执行，后续位置不能越过缺口。
崩溃恢复在独占 writer 下解释连续、完整、校验有效的 envelope 前缀，包括
崩溃前没有返回回执的完整批次；重新同步确认后，lookupOperation 返回该原批次
committed。可证明尾部仅有不完整批次并已安全截回时，原操作才可返回未提交；
完整损坏或无法确认截回时保持 unknown，不假定没发生。完整有效但未曾回应
的记录可能成立，调用者须接受此未知收敛语义。恢复后实际 attempt 是否已开始
仍另行核实。实现须给出内存状态、水位、失效封闭与恢复映射，不持锁等待 I/O。

**CC-04**：纯粹在内存检查后先执行再异步补授权／调用日志不符合协议。实际
提供者开始前持有已耐久关联的精确 attempt 和受约束执行许可；许可与撤权有
确定准入先后。授权撤回只影响尚未准入动作；已准入动作后续停止归显式控制。
远端身份/许可必须由其权威保证可用到准入点；无法形成等价撤销屏障时返回
unavailable，不能把 TTL 缓存当作“当前授权”。

## 跨能力后果交付与恢复

**CC-05**：不能共同提交的交接使用具体耐久意图：源提交原始事实及待交付后果，
目标用该事实的稳定身份接纳并返回可查询回执，源确认后更新交付状态。响应丢失
查原目标操作；目标拒绝、失联、待重试和已接纳分别可见。源不因发送了通知便
丢弃责任；目标不能从重复通知生成第二份 Run／工具／决定。此协议只保证事实
交付与去重，不保证任意外部副作用恰好发生一次。

**CC-06**：恢复读取 Session、队列、Run、请求、调用、预算、媒体引用和装配意图
的已提交事实，核对格式/契约、定义/实现版本、环境能力和当前权限，再取得新的
运行 epoch。旧运行对象不反序列化。未开始工作可从其合法位置继续；可能已发出
的模型/工具请求先按原 attempt 查询或重新关联，无法核实标 unknown，不自动重发。
明确 cancelled／deleted／superseded 的工作不因恢复、迟到答复或提供者重现复活。

**CC-07**：工程关联包含 operation、commit、水位、tenant、可信主体、Session/
Run/Step/attempt、定义与实现版本、环境及阶段；关键成功/拒绝/未知与控制事实
随所属提交保存，诊断事件可以有界采样但必须显式报告缺口。内容与秘密分别裁剪，
财务汇总不授予正文权限。通知与缓存故障不改变源状态，对外读面显示真实水位
与可达性；需要关键记录却无法保存时阻止新的相关效果。

## 验证责任

JSON Schema 约束值形状；有限模型验证并发转移和错误反例。真实 JSONL 的 fsync、
锁竞争、截断/损坏、故障接管和提交回执须在实现环境执行；本页不声称存储或
授权提供者已实现。跨能力协调需要同一真实组合的验证，不能用各端独立 mock
测试替代。所有版本化公开承诺及反例映射在正式化前接受独立评审。
