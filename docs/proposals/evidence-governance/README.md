# 以性质和证据义务衔接设计与交付

## 任务依据与边界

2026-09-14，用户先要求分析 Cordis 形式结果对本项目建模、架构、spec、skills
和 subagents 的意义，继而要求明确组件提案何时需要证明效应可逆、撤除正确及
接口可交换，最后要求结合讨论，系统规划并推进提案、决策、架构设计、spec 维护
及交付计划撰写规范的优化。这是本轮治理改动的直接授权与需求依据。

用户随后明确要求：定义 `docs/proposals/` 的持久化准入，及 `docs/` 每个直接
子目录的信息性质、职责和准入，补齐局部 AGENTS.md；同时要求强化从目标、
功能需求导出不变量的建模、skills 和 reviewer 引导。本轮据此扩展组织规范和
各目录入口，以及需求—性质—保护—证据的推导与审阅。

本轮沿 D-001 的信息归属、D-002 的接受边界及 D-004 的需求基础补充方法，复用
[现有维护衔接](../design-spec-maintenance/README.md)。不选择产品插件准入、沙盒、
业务补偿或热替换政策，不发布产品契约，也不宣称任意插件已经证明正确。论文及
采用边界的事实见[来源核对](../../research/cordis-proof-boundaries.md)。

## 问题与选择

本提案改变跨任务的知识准入、性质推导及机制接受条件，后续设计与交付需要持续
消费并复议这些选择，因此保留取舍和评审依据。单次排期、分派及进度不具备同样
的长期用途，已移入临时任务材料；本页不以“本轮优化”作为通用入库理由。

现有指导已经区分卸载与外部回滚、模型与实现、接受与交付；缺口是某个候选赖以
成立的性质，如何成为有负责者、有证据门槛、能随变更传播的义务。简单增加证明
文件数量，或把全部组件一律送入同一工具链，不能解决这一问题。

| 选择 | 目的与约束 |
|---|---|
| 按真实依赖衔接各环节 | 架构设计从提案阶段开始；决定固定接受范围，当前架构投影该范围。候选 spec、研究、证明与计划可交错，正式依赖仍需明确接受及版本 |
| 先判断持久化归属 | 提案需有待判断对象、长期取舍价值和可接续内容；当前说明、研究事实和临时排期各归其拥有者。九个 docs 直接子目录的 AGENTS 提供局部准入投影，CLAUDE 仅引用同级 |
| 从需求推导性质 | 任何建模和架构设计先从本次目标、功能需求及全局约束导出或引用不变量、安全/进展性质，明确保护位置和双向覆盖；不从现有代码或测试反向代替需求 |
| 提案逐项说明性质与证据义务 | 记录性质、用途、范围、前提/责任方、所需证据、当前结果和受阻消费；允许引用已有记录，不增加总注册表或强制文件模板 |
| 证明门槛由声明与设计依赖触发 | 新增共享代数性质支撑跨组件组合、或据此放宽控制约束时要求证明；复用有效成果可以完成前提映射，不重复证明整个上游 |
| 关键控制省略或放宽要求机器检查 | 需要本项目新建立的共享代数保证承载租户隔离、唯一写入权或安全撤除等关键保证，且据此省略或放宽控制时，所依赖性质需机器检查证明；初次省略及改变复用前提同样适用，已有证明须满足本次证据级别 |
| 区分语义证明与实现符合性 | 模型中的成功清理不证明实际 disposer；实际发行物、配置、依赖及执行环境的符合性另验。未建模的失败、外部效果和不可信执行保持边界 |
| 接受范围随证据限定 | 允许接受探索或不依赖缺口的部分；不能接受依赖尚未完成必要证明的机制选择，也不能因缩小本轮范围撤销有效需求 |
| 计划显式安排证据生产与消费 | 关键证明/探针是有输入、负责人、完成判据的工作；依赖工作在所需义务闭合后推进，独立工作可继续 |
| 通过既有入口维护 | 方法正文拥有含义，skills 路由，角色各守职责；源配置、两端模型及权限保持，生成物由源重新产生 |

这里的“关键”由提案引用的需求、不变量和失败后果说明，不以包名含 kernel、
组件数量多或模型名称新为依据。不存在共享效应的纯计算无需装卸模型；行为
对顺序敏感时明确顺序或选择其他合法机制，不能改变观察范围来伪造交换性。

## 证据触发与交接设计

复用受控操作且不改变适用前提时，核对精确契约、证明/测试范围及实现使用方式。
自定义局部效应说明前后条件、所有权、保留事实和正确性论证，安排对应失败测试。
新增共享操作并依其可逆、可交换或互不干扰性质支撑跨组件组合时，给出形式命题
及完整证明；复用定理需证明本组件满足其前提。依据这些性质放宽顺序、隔离、
排空或冲突检查时，还须论证这次放宽保留目标保证。

自定义并发装卸、共享资源交接、代际替换或恢复协议，应有与目标性质对应的行为
模型和关键性质检查。若声称有限检查已建立范围外的普遍结论，或机制选择依赖
这样的推广，则需相应证明；契约中的全称要求本身是规范目标，不自动成为已经
证明的事实，也不单独触发新增的证明关卡。复用完整契约与已有适用证据时不重复
造模型。外部输出以业务撤销、补偿或恢复协议描述，不要求
对已经确认不可逆的效果构造不存在的逆操作。

证明定义域、观察关系、前向与逆操作、返回及失败结果都属于命题范围；只验证
最终容器相同不能支持一般交换性。重复清理由调用协议说明，不一概要求数学逆
操作自身幂等。规范模型的环境假设若由另一个能力提供，应能找到该能力的保证
和兑现责任；外部假设不能写成已经强制成立。

要求或语义范围可以在实现证据未齐时接受，但不能同时接受依赖未完成必要证明
的机制选择。机器检查门槛按实际语义判断：首次设计即依赖代数性质省略控制、
修改接口表示或放宽已复用证明的前提，都属于本项目需要建立的保证；已有证明
仍须满足所需级别并完成适用性论证，不因改称“复用”豁免。

提案初审允许未完成义务；决定针对具体选择核对必要证据并固定范围；当前架构
保留已接受范围和缺口；spec 保留同一性质、前提和精确依赖；提供者设计解释
如何兑现；计划安排实现与实证；新反例沿责任和实际消费者反向传播。

## 审阅与接受

用户已授权完成本轮优化；本页保留具体治理变更的待审身份。独立评审不是接受
决定，执行授权不自动接受尚未确定的产品政策。本分支的规范修订作为同一可审阅
变更交付；正式采用时按知识流转记录本轮选择和范围，不虚构新的接受决定。
