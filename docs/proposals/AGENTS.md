# 值得长期追溯的候选设计

这里保存会影响系统保证、消费者或维护责任的待选设计及取舍依据，供后续决定
和精确契约追溯。它不是所有讨论和计划的收集处。

## 准入与转出

先按[提案准入](../maintenance/organization.md#提案的持久化准入)判断：有明确
待判断对象、有长期取舍价值，并有可接续的范围、候选、理由、证据和未决项。
架构边界、跨组件机制、关键实现路径和长期治理选择可以符合这些条件；仅因
用了“设计”一词、改了一个函数或讨论过方案，不自动符合。

当前包/应用说明回到成员设计；事实观察归 research；临时排期、分派和头脑风暴
归 tmp。讨论、评审和候选规格作为附件时，应直接支持该选择及必要复现，不保存
无筛选的会话全文或所有工具输出。

## 流转与读取

提案的[必要内容](../maintenance/knowledge-flow.md#提案需要留下什么)包括从
需求导出的性质及其证据义务。接受后，选择归 decisions，系统视图归 architecture，
精确承诺归 spec，提供者和装配归成员；这里保留当时取舍并导航当前拥有者。

初审可有未知，候选不成为正式依赖。普通局部修复沿现有契约完成，不为填满本目录
额外制造提案；已有历史按后续真实消费整理，不批量改写接受身份。
