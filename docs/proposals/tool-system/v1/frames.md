## 职责与定义声明

过程帧的执行语义、生产生命周期、观察回放及披露入口由工具执行能力拥有。
工具实现提供内容，运行时校验来源和进展边界；context-sessions 拥有会话关联
及模型消费投影，日志/存储兑现写入和读取保证。不要求另建独立 FrameService，
也不要求所有帧写在同一个 Session log。

每项操作可声明它产生的阶段、进度、文本或媒体帧类型，以及精确格式版本、
载荷 Schema、默认记录等级、大小上限和是否允许合并/抽样。类型随工具版本
演化，公共含义复用同一数据契约。工具自定义“success”类型只是一项内容，
不能替代运行时的执行终态，也不能靠自报字段扩大披露资格。

过程原件、脱敏视图、UI 展示、诊断和模型摘要有明确映射及来源。一个帧被多处
消费不产生多个互相竞争的执行事实；模型未读取、UI 未展开或没有新帧都不能
推出工具没有运行或已经结束。

## 生产身份、顺序与终态

运行时给每个获准生产者提供绑定到精确 invocation、attempt 和执行所有权
代次的生产通道。租户、调用目标与权威身份由通道确定，提供者不能任意指定
另一个调用追加记录。多个子生产者由执行所有者分别登记，不共享可伪造的
全局 writer；恢复仍属于同一 attempt，但需重新验证当前所有权。

建议将帧事实身份、当前生产资格与读面顺序分开：运行时给逻辑生产者分配在
该 attempt 内稳定的生产者身份，配合单调来源序号标识一次上报；授权通道的
所有权代次可以变化，不进入原帧的去重键。运行时在单次 attempt 的流内分配
观察位置。相同来源键与相同内容
重试返回原接纳结果，相同键配不同内容报冲突并封锁该生产通道，不能覆盖旧帧。
多生产者的交错按运行时接纳顺序表达；生产时间和到达时间均不能冒充因果顺序。

接管同一逻辑生产者时，运行时先撤销旧通道资格，再将其明确范围交给当前
执行所有者。接管者可以凭新资格查询或补交原待确认键及原始载荷，记录仍关联
原生产来源，并另外记录当前补交者；不能把旧帧改成新序号重报。若承诺跨生产者
重建补交，执行所有者必须耐久保存待确认的键、载荷和序号分配进展。没有这项
证据时，只能查询已确认记录并报告可能缺口，不能猜测内容或创建第二条事实。

上述恢复资格不是复活旧 writer。原通道仍不可写，补交也要服从当前 attempt
的关闭边界；已强停或已封闭的流只允许查询既有确认，未接纳的迟到内容按
迟到诊断/外部事实政策记录，不能重新变成有效进度。新实际执行尝试取得新的
attempt 和生产者范围，不与旧尝试合并。

存储对需记录的帧以稳定身份去重，并维护可解释的顺序与确认回执。观察位置
不是整个 Session 的序号，也不是数据库物理偏移。具体序号编码待 Schema
确定，语义上必须能识别重复、缺口、尝试边界和不同生产者。

执行器报告完成前，应完成此前必需过程记录的提交并关闭生产通道。运行时
收束记录关联该 attempt 的流关闭边界；不能仅凭一条自报进度达到 100% 收束。
强停时立即撤销旧生产资格，已接受内容按其记录义务处理；旧执行者晚到的
诊断或外部效果可以进入标明来源的迟到事实记录，不再成为有效进度或继续权。

工具结果和记录完成是不同事实：实际动作已结束但必需记录未确认时，保存可
取得的结果并显示记录待核实/缺口，不伪造业务执行失败并重试动作。终态的
关闭边界不能用一个看似连续的序号掩盖尚未确定是否写入的内容。

## 记录等级、确认点与故障

建议先用三种语义，具体容量与时限后续确定：

| 记录类别 | 候选保证 | 写入/容量失败时 |
|---|---|---|
| 关键调用事实 | 调用状态、准入/控制依据、结果及必要审计必须有耐久确认 | 不接纳依赖该保证的新动作；已有外部工作按能力受控暂停/停止或标记无法完整记录，不报全部成功 |
| 可回放过程 | 在声明的保留窗口内可从确认位置读取；默认用于需要历史展开的进度 | 有界缓冲/背压，不能将未确认展示标为已保存；重试原帧，过期返回明确缺口 |
| 暂态过程 | 仅在显式声明且策略允许时采用；可低延迟显示，明确无完整回放承诺 | 按已声明合并/丢弃政策处理并显示缺口，不吞掉关键事实 |

等级由操作声明与系统记录/数据治理策略共同决定，提供者不能把关键审计改成
暂态。`emit` 或等待一组可选监听器完成都不是记录确认；必需记录者有可检查
的就绪与写入回执，记录生产与执行所有者的生命周期一致。

需要先展示再确认的内容带暂态/未确认状态，随后用同一身份关联确认或丢失
结论。写入成立而回执丢失，按原身份查询/重试；无法判断时报告待核实，不重新
编号伪造第二条事实。进程丢失前未确认的易失内容不承诺恢复。

慢 UI 不阻塞实际工作，但必须记录的生产可能受存储背压约束。每个执行器需
说明缓冲耗尽时能否暂停生产、停止工作或只能继续并报告观测缺口；没有可兑现
策略时不允许声明相应的完整记录保证。资源上限需要准入阶段核对，而不是
无限堆积内存后才发现后台工作没有记录位置。

媒体若需持久回放，先取得相应媒体/制品能力的有效保存引用，再确认该帧满足
记录要求；暂时未完成可呈现带状态的占位。引用提交失败的孤立内容由保存
能力按明确保留/清理协议处理。保留一行 JSON 不等于图片或文件已经保存。

## 观察、回放与当前授权

观察接口提供当前执行状态、可读取范围、记录等级、流关闭边界及独立游标。
游标绑定调用/尝试、流格式与读取位置，不携带永久授权，也不是共享消费指针。
实时订阅可以提示新位置，读取确认过的内容仍沿同一受治理记录接口。

新订阅、补读、推送、导出与模型消费分别检查相应当前资格；执行权、状态读权
和原始内容读权不等同。跨租户或无权对象的拒绝不泄漏存在性。撤销读权结束
相关订阅效用，但不隐式中断工具工作。

断线重连返回声明范围内的原帧或明确的缺口；至少区分到期、合并/丢弃、未确认、
解码不可用、读取故障与调用结果未知。带缺口的摘要不能伪装完整原件。
历史读取依赖持久记录及兼容解释能力，不依赖原工具插件、worker 或 Session
实例仍在内存中。可用的原始封装也不等于一定有可用的高级 UI 渲染器。

格式更新需保留已承诺历史的解释路径，例如保留精确 Schema 与受控解码能力；
不能为了看旧帧重新启用未经授权的旧工具执行代码。记录后端替换需保留流身份
与游标映射，或在明确边界关闭旧流并提供可追溯接续引用；未具备这项能力时
保持旧后端直到其承诺完成或拒绝替换。

## Cordis 生命周期与 context-sessions 交接

| 组合 | 正向效用与所有者 | 卸载时的逆效用 |
|---|---|---|
| 工具内部生产 | 执行所有者持有生产通道、必需记录关系及资源 | 关闭对应生产资格，处理待确认内容并记录关闭/缺口；不抹除已保存事实 |
| 会话/UI 观察 | 消费实例持有监听、读取关系、缓存和位置 | 移除本观察者，释放其资源；不关闭生产者或其它观察者 |
| 模型投影 | 请求装配持有选用内容及来源记录 | 撤回未来请求的相关派生贡献；已经提交的模型请求不被改写 |
| 帧类型/渲染注册 | 提供者拥有注册，历史读取持有所需解释依据 | 退出当前注册；已承诺历史的读取不能随便失效 |

后台生产者和必需记录者从启动起处于独立执行所有者下。会话回收只撤回观察
效用；普通 Run 中断与 `interrupt_then_run` 的实际控制沿[运行时](runtime.md)
分别执行。没有订阅者不能解除必需记录义务。

向 context-sessions 提供的输入是调用/attempt 及来源 Session/Run/Step、执行
状态、可用记录范围、独立读取位置、格式与缺口说明。对方决定哪些内容进入
历史投影和哪次模型请求，并记录实际消费的原帧位置或摘要来源，不反写执行
状态。不让整个会话服务硬依赖全部工具实现，也不让存储等待模型渲染才提交。

Session 归档/删除、原 Run 结束与后台调用存续之间的跨能力政策尚待共同
收敛。工具层可提供未收束调用、执行控制及保留义务的查询和有条件处理接口；
会话目录操作不得隐式取消工作或删掉执行仍需的记录。逻辑删除后的读取资格、
媒体保留和清理完成需由 Session、执行与数据治理联合明确。

本稿已提出生产身份、重复冲突、顺序范围、终态分离、记录等级及所有权政策。
仍需双方确认：具体保留与背压数值、流位置的数据契约、跨调用历史合并、记录
故障时各执行器可兑现的处置、Session 删除关联与后端迁移承诺。协调稿的原
评审不能代替这些新增选择的评审与接受。
