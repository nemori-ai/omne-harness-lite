# 打断与回来

这份矩阵回答：客户端、调用方或整个服务离开再回来时，一个会话的事实还在不在，进行中的工作是接着做完还是如实收场，排着的消息会不会丢。矩阵的读法与执行规则见[端到端验收矩阵](README.md)。

状态：项目负责人于 2026-11-13 点名了客户端、历史、调用方重装配、服务端有序重启、排着的追加消息这五块，并要求把矩阵收进项目正文持续维护。服务端强杀与模型供应商不可用两块，以及各格的期望，由统筹者按项目要求推出，随验收结果修订。本页规定判据，不宣称现有实现已经通过。

## 范围与标准

适用的部署是第一版的单机发行：一个服务进程，里面是一棵 Cordis 树；页面、页面宿主和服务端在同一台机器上。工具起的 Shell 命令是唯一活在服务进程之外的在途工作。

要的是四样性质。它们各有成立的条件，不是一样。

| 性质 | 意思 | 什么时候必须成立 | 依据 |
| --- | --- | --- | --- |
| 事实不丢 | 确认过的输入、消息、工具结果永远在 | 任何情况，包括强杀 | [已确认业务事实的持久性](../requirements.md#已确认业务事实的持久性sys-durability) |
| 一致、如实 | 起来之后从日志回到说得通的状态；在途的每件事有确定而真实的结局；不挂死、不空转、不装作成功、不悄悄重发 | 任何情况，包括强杀 | [心智模型要点](../../AGENTS.md#心智模型要点)里的「结果不知道就是不知道」；[控制与恢复](../architecture/runtime/control-and-recovery.md) |
| 接续 | 工作像没被打断一样继续 | 执行者还活着，或者结果在它停下之前已经落盘 | [运行时解耦与接续](../requirements.md#运行时解耦与接续sys-runtime-continuity) |
| 故障不扩散 | 一个会话、一个模型出问题，别的照常；提供者不在时答「不可用」 | 任何情况 | [长期运行](../requirements.md#长期运行与持续进化sys-long-running) |

强杀整个服务进程之后，只在内存里的在途工作没了。项目要求明写持久性不涵盖未承诺持久保存的在途流片段，自动故障接管与恰好执行一次也没有定案。所以强杀那一块不要求接续，只要求事实不丢和一致、如实。

## 轴

**轴一：谁离开了又回来。** 定块。

| 块 | 谁离开 | 谁没动 | 标准 |
| --- | --- | --- | --- |
| K 客户端 | 页面、页面宿主 | 服务端全部 | 接续 |
| H 历史 | 用户切出会话再切回 | 服务端全部 | 历史不丢不重，按页加载 |
| R 调用方重装配 | 会话的活体，或 Agent 的活体 | 模型运行时、工具运行时、存储 | 接续 |
| G 服务端有序重启 | 整个服务进程，先有序停止 | 落盘的事实；进程外的工具命令 | 接续：从事实记录停下的地方恢复 |
| Q 排着的追加消息 | 上面任何一种，发生在有消息排着的时候 | 同各自的块 | 这条消息不丢、不重，到该受理时被受理 |
| X 服务端强杀 | 整个服务进程，没有有序停止 | 落盘的事实；进程外的工具命令 | 不要求接续，只要求事实不丢和一致、如实 |
| D 模型供应商不可用 | 模型供应商暂时答不上来 | 其余全部 | 答不可用，不扩散，恢复后能继续 |

**轴二：离开的那一刻，会话处在什么状态。** 定行。

| 代号 | 状态 |
| --- | --- |
| s0 | 空闲：没有进行中的一轮 |
| s1 | 一轮进行中，模型回复在途（正在流式输出） |
| s2 | 一轮进行中，工具命令在跑 |
| s4 | 一轮进行中，并且有追加的消息排着 |

s3（等人决定）与 s5（取消或收尾中）不在这份矩阵里，原因见[不在这份矩阵里的](#不在这份矩阵里的)。代号留给它们，不改作他用。

**轴三：回来的时候，在途的那件事怎样了。** 每行分两种。

| 代号 | 情形 |
| --- | --- |
| t1 | 离开期间它已经做完，回来时结果已经在 |
| t2 | 回来时它还在进行 |

块与状态交叉出的格子：

| 状态 | K 客户端 | R 调用方重装配 | G 有序重启 | X 强杀 |
| --- | --- | --- | --- | --- |
| s0 空闲 | K-0 | R-0 | G-0 | 并入 X-事实 |
| s1 模型在途 | K-1 | R-1 | G-1 | X-1 |
| s2 工具在跑 | K-2 | R-2 | G-2 | X-2 |
| s4 有消息排着 | Q-K | Q-R | Q-G | Q-X |

## 观察点

| 代号 | 观察点 |
| --- | --- |
| o1 | 历史：消息、工具调用与结果都在，不丢、不重、顺序对 |
| o2 | 进行中的一轮：状态显示对；流从当前接上，已经出过的字不丢也不重复 |
| o3 | 结局：这一轮正常结束。X 块里是如实结束 |
| o4 | 排着的消息：被受理、有回复，不丢，不被处理两次 |
| o5 | 之后接着发消息正常 |
| o6 | 副作用不重复：工具命令没有被执行两次，模型调用没有重发 |
| o7 | 系统健康：服务不空转，没有反复刷的告警，同时开着的另一个会话不受影响 |

o6 与 o7 每一格都看，不写进各格的期望。G 块与 X 块执行时，旁边常开一个别的会话，用它看 o7 的「不受影响」。

## K 块：客户端离开再回来，服务端不动

离开的方式有三种。每格三种都试。

- a：刷新页面。关掉页面再打开是同一回事。
- c：页面宿主进程重启，相当于客户端升级。凭据只在宿主进程的内存里，所以要重新登录。
- d：切到别的会话再切回。

| 编号 | 离开时 | 期望 |
| --- | --- | --- |
| K-0 | 空闲 | o1；o5 |
| K-1/t2 | 模型在途，回来时还在流 | o1；o2：状态是进行中，字接着出，之前出过的都在、不重复；o3 |
| K-1/t1 | 模型在途，回来时这一轮已结束（正常结束，或被停止） | o1：看到完整回复；o2：状态是已结束，不再显示进行中 |
| K-2/t2 | 工具在跑，回来时还在跑 | o2：显示工具在执行；o3 |
| K-2/t1 | 工具在跑，回来时已出结果 | o1：调用与结果成对；o3 |
| K-c | 页面宿主重启之后 | 要求重新登录；登录后会话列表、每个会话的历史都在；登录前读不到任何会话内容 |

## H 块：切出再切回，历史的加载与分页

历史从新往旧按页加载。用户向上滑时再加载更旧的一页，不要求一次加载全部。

| 编号 | 情形 | 期望 |
| --- | --- | --- |
| H-1 | 切回一个短会话 | 一次加载完；o1 |
| H-2 | 切回一个长会话（几百条以上） | 只加载最新的一页；首屏出来的时间不随总条数增长；核请求数与返回条数 |
| H-3 | 在长会话里向上滑 | 再加载更旧的一页，接在上面，不重、不漏；一直滑到头，条数等于落盘的条数 |
| H-4 | 加载旧页的同时有新消息到达 | 新消息出现在底部，旧页照常接上，顺序不乱 |
| H-5 | 历史里有工具调用 | 调用与结果成对显示；一条回复并行的多个工具调用各自对上自己的结果 |
| H-6 | 服务端重启之后第一次进入旧会话（服务端是冷读） | 与重启前看到的历史逐条相同 |
| H-7 | 在两个会话之间来回快速切换 | 每次显示的都是当前这个会话的内容，不串台 |

## R 块：会话或 Agent 重装配，工具和模型的运行时不动

重装配有三种：

- a：Agent 实例空闲被回收，之后有新的输入。
- b：Agent 宿主这一行被卸载再装上。
- c：会话提供者这一行被卸载再装上。

b 与 c 需要一个在运行中卸载并重装某一行的入口。没有这个入口时，这一格记「测不了」。

| 编号 | 重装配时 | 方式 | 期望 |
| --- | --- | --- | --- |
| R-0 | 空闲 | a b c | 下一条输入照常开始新的一轮；o1；o5 |
| R-1/t2 | 模型在途，装回来时还在流 | b c | 模型调用没有被取消，也没有重发；流照常出完；结果进日志；新的活体接上；o3；页面开着时状态连贯 |
| R-1/t1 | 模型在途，装回来之前模型已经做完 | b c | 结果已经在日志里；装回来之后直接用它往下走；o3 |
| R-2/t2 | 工具在跑，装回来时还在跑 | b c | 命令没有被停掉，也没有被再起一次；跑完后结果被接上；o3 |
| R-2/t1 | 工具在跑，装回来之前已经跑完 | b c | 结果被接上；o3 |

## G 块：服务端有序停止再起来

每格分两种客户端情形各试一次：页面一直开着，看它会不会自己重连并接上，不需要手工刷新；页面关着，重启后再打开。

| 编号 | 停止时 | 期望 |
| --- | --- | --- |
| G-0 | 空闲 | 起来之后 o1；o5 |
| G-1/单步 | 模型在途，回复之后没有别的事 | 停止过程等这次回复做完才退出，上限是排空期限；回复在日志里；这一轮正常结束 |
| G-1/多步 | 模型在途，回复之后还要调工具、再调模型 | 在途的这次回复不丢；起来之后从停下的地方接着做完；o3 |
| G-1/超时 | 模型在途，到排空期限还没做完（把排空期限配短来触发） | 停止报告如实写还有调用在途；起来之后这一轮如实结束，不挂死 |
| G-2/t1 | 工具在跑，起来之前命令已经跑完 | 结果被认回；o3 |
| G-2/t2 | 工具在跑，起来之后命令还在跑 | 命令没有被停掉；跑完后结果被认回；o3 |

## Q 块：追加的消息排着的时候

| 编号 | 情形 | 期望 |
| --- | --- | --- |
| Q-1 | 一轮进行中追加一条，什么都不打断 | 到该受理的时候被受理，有回复；这一轮能结束；o4 |
| Q-2 | 追加两三条 | 顺序保持；每条都被受理；o4 |
| Q-K | 追加之后用户切出页面，过一会儿回来 | 回来时看得到这条消息的状态（排着，或已被处理）；最终有回复；o4 |
| Q-K2 | 追加之后关掉页面，当前一轮在没有任何客户端的情况下结束 | 这条消息照样被受理并回复；再打开时看得到 |
| Q-取消 | 追加之后停止当前这一轮 | 排着的消息由下一轮取走并得到回复 |
| Q-失败 | 追加之后当前这一轮以失败结束（用 D-1 的办法让它失败） | 排着的消息不丢，由下一轮受理 |
| Q-R | 追加之后会话或 Agent 重装配 | o4 |
| Q-G | 追加之后服务端有序重启 | 起来之后这条消息被受理并回复，不需要人再发一次；o4 |
| Q-X | 追加之后服务端被强杀 | 确认入队的消息重启后还在，被受理并回复；o4 |

## X 块：服务端被强杀

强杀和有序停止只差三件事：没有交还，挂接还标着有人；只在内存里的在途工作没了；没确认的写入可能没落盘。格子只留这三件事各自带出来的。

| 编号 | 强杀时 | 期望 |
| --- | --- | --- |
| X-1 | 模型在途（只在内存里的在途工作） | 这一轮在限定时间内如实结束：这次调用标成中断，花费未知；不挂死、不重发；o5 |
| X-2 | 工具在跑（活在进程外的在途工作） | 命令不被执行第二次；这一轮有确定的结局。是接续还是如实结束，见[没有定的判据](#没有定的判据) |
| X-事实 | 任何状态，含空闲 | 强杀之前确认过的输入、消息、工具结果，起来之后都在；o5 |
| X-健康 | 任何状态 | 起来之后没有会话空转，空闲时 CPU 接近 0，没有反复刷的告警 |

## D 块：模型供应商暂时不可用

| 编号 | 情形 | 期望 |
| --- | --- | --- |
| D-1 | 一轮进行中，模型供应商不可用或超时 | 原因在界面与日志里看得见；别的会话照常；供应商恢复后能继续或能重试。这一轮是等待还是如实失败，见[没有定的判据](#没有定的判据) |

## 次序

K → H → Q 里不带重装配与重启的几格（Q-1、Q-2、Q-K、Q-K2、Q-取消）→ G → Q-G → R → Q-R → D → Q-失败 → X → Q-X。

先测不动服务端的，再测有序的，最后测强杀的：前面的块不通过时，后面的块的现象难以归因。

## 没有定的判据

| 格子 | 没定的是什么 | 两种读法 | 等谁定 |
| --- | --- | --- | --- |
| X-1 | 强杀后模型调用已发出而结果拿不回，这一轮怎样收场 | 如实失败，由人重试；或在预算内自动换一次新调用 | 项目负责人。没定之前按如实失败验 |
| X-2 | 强杀后进程外的命令还在跑或已跑完，结果要不要认回 | 工具规格承诺能认回，就按接续验；没有承诺，就按如实结束验 | 工具契约的拥有者，依据是工具规格里对执行记录的承诺 |
| D-1 | 供应商不可用时这一轮是等待还是失败，等多久 | 等待到恢复；或按策略重试若干次后如实失败 | 模型调用的策略拥有者 |
| H-2 | 「首屏时间不随总条数增长」的数值预算 | 没有阈值时只报告实测与趋势，不宣布达标 | 项目与产品负责人，见[尚待明确的验收条件](../requirements.md#尚待明确的验收条件) |

## 不在这份矩阵里的

每一行写明没过[格子的判据](README.md#格子的判据)的哪一条，以及什么条件下重新收进来。

| 情形 | 没过哪一条 | 去向与重新收进来的条件 |
| --- | --- | --- |
| 模型运行时或工具运行时单独重装配 | 1、2。单进程发行里它们不会单独卸载，升级就是整个进程重启；「提供者不在时调用方答不可用并等待」在 G 的排空阶段与 D-1 里已经看得到 | 交付多进程部署时立成一块 |
| 同一会话两个客户端 | 3、2。客户端只是投影，服务端不认识有几个客户端；一个客户端离开再回来就是 K 块；两个同时发消息是并发 | 并发另立矩阵时收 |
| 存储暂时不可用 | 1、5。单机上存储和服务进程是同一个故障域，没有可靠的端到端触发 | 存储成员的故障用例；存储独立部署时收 |
| 某个工具暂时不可用 | 1。现在交付的工具都在本机 | 交付远程工具（Skill 与 MCP 接入）时收进 D 块 |
| s3 等人决定这一行 | 3。人工介入对客户端的接入还没交付，客户端上答不了 | 人工介入的接入交付时，给 K、R、G、X 各补这一行 |
| s5 取消或收尾中这一行 | 5、2。要卡在很窄的时刻，端到端碰不准；客户端一侧的样子并入 K-1/t1 | 机制层的崩溃矩阵：取消与收尾路径上的切点 |
| 客户端断网再连上 | 1、2。三方都在本机；对服务端它和刷新页面是同一件事 | 交付远程部署时收进 K 块 |
| 没发出去的草稿 | 3、4。草稿没到过服务端，不是事实；产品规则没定 | 产品定了草稿规则之后，归界面的验收 |
| 显式换代 | 3。换代还没交付 | 换代交付时收进 R 块 |
| 恢复没做完又重启 | 5、2。「恢复到一半」只是日志的又一个状态 | 机制层的崩溃矩阵：恢复之后再恢复 |
| 两个会话同时在途时重启 | 2。会话之间互不认识，要看的只是不扩散 | 并入 o7 |
| 契约变更之后的旧会话 | 4。0.1.0 之前旧数据不是验收对象 | 进入 0.1.0、有了兼容承诺之后重新量 |
| 追加消息的回执没到服务端就停了 | 5。端到端切不准「提交了、回执没发出」这一刻 | 会话契约的事务用例：按操作身份认回 |
| 第二个服务进程开同一个状态目录 | 2、5。已有用真实进程的成员用例 | 发行的状态锁用例 |
