# 端到端验收矩阵

本区保存系统级的端到端验收矩阵。一份矩阵把一项系统质量要求展开成一张表：每一格是一个真实会发生的情形，写明在真实的服务和真实的客户端上应当看到什么。负责人、统筹者和验收者用它判断一个阶段的交付在这项要求上是否成立。

本区规定判据，不宣称现有实现已经通过。某一次验收的结果不写在这里，见[执行与记录](#执行与记录)。

## 它和别的验证怎样分工

| 验证 | 回答什么 | 拥有者 |
| --- | --- | --- |
| 本区的矩阵 | 在交付出去的整套系统上，用户和运维会碰到的情形是否都有正确的结果 | 项目负责人定范围与标准，统筹者维护格子 |
| 成员的 `acceptance/` 与测试 | 一个成员的公开承诺是否成立 | 成员拥有者 |
| 机制层的穷举证据：崩溃矩阵、全化表、模型检查 | 一个机制在每个切点、每个状态下是否成立 | 机制的拥有者，方法见[验证说明](../verification.md#组合性质与证明义务) |
| [系统级代表场景](../architecture/assurance.md#系统级代表场景) | 架构要对哪些质量场景给出论证 | 架构负责人 |

矩阵是代表场景在当前阶段的展开。它引用[项目要求](../requirements.md)和架构专题里的承诺，不另立承诺。矩阵和要求对不上时，以要求为准，并报告这一处。

端到端的一格只碰得到少数几个时刻。靠穷举切点才能证全的性质归机制层，矩阵只写明它交给了谁。两层都要有：机制层证明每个切点都对，矩阵证明整套系统装起来之后用户真的看到对的结果。

## 一份矩阵的结构

每份矩阵按同一个次序写，读的人不用重新学一遍：

1. **范围与标准。** 展开哪项要求，适用于哪种部署，每一类情形按哪一档标准判。标准引用要求的原文。
2. **轴。** 独立变化的量各是一条轴。常见的三条：谁在变（定块），变的那一刻系统处在什么状态（定行），回来时在途的事怎样了。
3. **观察点。** 每一格看什么。每一格都要看的观察点单列出来，不重复写进格子。
4. **格子。** 一块一张表。每格有稳定的编号、情形、期望。编号一经使用不改作他用。
5. **次序。** 建议的执行次序，以及哪些格子依赖别的格子的手段。
6. **没有定的判据。** 期望还取决于一个没定的规则时，写明等谁定、两种读法各是什么。
7. **不在这份矩阵里的。** 推得出来但被排除的情形，写明没过哪一条判据、去了哪里、什么条件下重新收进来。

## 格子的判据

一个情形要成为矩阵里的一格，下面五条都要过。推出一批候选之后，逐个拿它们量一遍，没过的写进「不在这份矩阵里的」。

1. **它在交付出去的系统里真的会发生。** 找得到一个真实的触发。只是按对称性推出来的不收。
2. **它带来一个别的格子没有的机制。** 服务端看到的事情和另一格相同时，只留一格。
3. **它属于这份矩阵的那条轴。** 别的轴上的事（并发、界面细节）和还没交付的功能，不放进来。
4. **它的期望在项目现在的承诺之内。** 要求明写了不涵盖或尚未定案的，不当成期望。
5. **它适合端到端测。** 要卡在很窄的时刻、靠穷举才测得全的，归机制层。

## 执行与记录

执行一次验收时：

1. 一块一块测，一块之内一格一格测。每格都用真实的服务、真实的页面或协议客户端。
2. 只用为这次验收新造的账号与会话。不拿旧数据验收，也不在真实用户的状态副本上推进他的会话：副本里的 agent 会真的执行工具。
3. 一格不通过时不当场修。记下格子编号、时刻、现象、证据的位置和看到的事实，接着测下一格。整份测完再统一决定修什么、按什么次序修。
4. 一格没有触发手段时记「测不了」和原因，不算通过。
5. 探针报不通过时，先拿落盘的事实核对，再下结论。探针自己的断言也会错：把界面元素当成正文、读页面太早、提示词让模型只答了一部分。探针错了就改探针重跑这一格，并在结果里写明；系统的现象照实记。
6. 结果按[验证说明](../verification.md#分别表述这六种状态)区分通过、不通过、未执行和未知。

一次验收的结果是过程材料：贴到这一程的卡评论，或留在任务的过程目录。矩阵正文不记哪一格现在通过，也不记时刻、提交号和日志路径。验收中发现期望本身写错了，或少了一格，改矩阵正文；发现实现不符合期望，那是缺陷，不改矩阵。

## 维护

- 新增一份矩阵：在本区加一页，按[一份矩阵的结构](#一份矩阵的结构)写，在[现有矩阵](#现有矩阵)加一行，并在[文档登记](../documentation.json)登记。
- 要求或架构承诺变了：先改它们的拥有者正文，再改受影响的格子。
- 被排除的情形满足了重新收进来的条件（例如交付了多进程部署）：把它从「不在这份矩阵里的」移回格子。
- 一格长期「测不了」：要么补出触发手段，要么按判据第 1 条重新量它该不该留。
- 探针与走查脚本进了仓库之后，在对应的格子上写明用哪一个。只存在于过程目录里的脚本不写进正文。
