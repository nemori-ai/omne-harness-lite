# 重构与迁移

## 何时使用

用于结构、名称、接口、信息位置或提供者变化。行为保持和获准语义修订分别表达；纯重构不能悄悄改变公开保证。文档语义整合还需[文档维护](docs-and-skills.md)。

## 开始需要什么

需要现行公开承诺、拟替代范围、消费者与验证、预期行为保持或已接受新语义、写范围和删除条件。物理移动不授予采用；消费者未知时先查直接和间接读取者。

## 最小上下文

读真实拥有者、公开类型／必要行为、依赖与读取路径。影响面包括装配、Schema 身份、生成器、发布和验证。只追与本次取代相关的消费者，闭包明确后停止扩展。

## 适用共享规范

[包边界](../../workspace.md#使用与维护)、[演进消费者](../publication.md#当前演进与消费者)、[唯一源](../documentation.md#位置与唯一源)、[验证范围](../quality.md#失败未知与完成范围)。

## 工作步骤

1. 用 [pstack how](../skills.md#pstack-方法入口)核实现行职责；边界或方案不明确才用 architect／arena。新含义先取得接受，不把当前实现便利当领域规则。
2. 明确保持和获准改变的承诺及全部消费者。信息迁移按有效信息单元整合，避免全文复制成第二源；记录代码读取、格式和生成输入，不只查链接。
3. 按 [Refactoring playbook](../skills.md#playbook-入口)实施可验证单元。同步真实消费者并按项目阶段政策删除替代实现，保护其它 agent 的改动；独立单元可隔离并行，共享对象及集成拓扑单一负责人，耦合变更串行。Matt to-tickets 的 expand–contract 默认不能引入本阶段不保留的旧实现兼容过渡，无法独立成立的切片组合为同波可验证单元。
4. 使用 blast-radius 和精确契约检查验证消费闭包。工具生成关系只支持其静态范围，重要整体性质仍需组合或行为证据。
5. 在取代范围的源、消费者和验证就绪且接受依据明确时退役旧源。未迁部分保持原责任；交付保持／变化、删除结果、未知与下一拥有者。

## 完成及交付

交付新现行源、消费者切换、实际删除与验证；必要理由随拥有者，迁移计划和单次对照留 tmp。接口身份、采用、兑现与文件位置分别核对，不以路径变化声称语义升级。

## 停止与恢复

语义、Schema 身份或关键消费者未知时仅停该切换／删除，继续独立盘点和其它明确单元。补齐接受和消费证据后恢复，不建未授权兼容层或用旧副本兜底。

## 示例与精确参考

移一个公开类型先找包入口、生成声明和真实消费者，再同批切换。旧目录被链接检索不到，不证明代码读取和模板消费已经切换。
