# 依赖与运行环境变化

## 何时使用

用于依赖版本、运行配置、Node、原生模块、后端或制品环境变化。新公开语义先补设计；仅消费现有包可从[包消费地图](../../context-map.md#消费独立包)开始。

## 开始需要什么

需要当前和拟采用版本、官方来源／变更、实际配置与锁、消费者、环境矩阵、任务权限及验证资源。缺远端或后端资源时仍可查本地源和已知契约，保留覆盖未知。

## 最小上下文

读[workspace 依赖](../../workspace.md#workspace-与依赖)、目标成员／应用 README、公开承诺与构建配置。Cordis 事实先复用已采用 basis／probe，未覆盖部分核对精确官方版本；上游约定不自动成为项目承诺。

## 适用共享规范

[开发环境](../../development.md#准备可用的检出)、[根工具清单](../../../package.json)、[包边界](../../workspace.md#使用与维护)、[独立消费者](../publication.md#当前演进与消费者)、[未知范围](../quality.md#失败未知与完成范围)。

## 工作步骤

1. 核对固定来源与实际版本、接口和运行语义差异。已有研究可复用，缺事实按 harness-design-handbook 的来源核对展开，不凭库名或旧记忆改采用。
2. 定位受影响契约、装配、声明、原生脚本和实际后端，区分已有采用范围与需负责人裁定的新保证。没有专用 pstack playbook 时按条件参考 figure-it-out，不造另一默认流水线。
3. 在范围内按实际 workspace 规则同步成员声明、catalog 和锁，必要消费者按[迁移](refactoring.md)切换。采用或业务保证未定时仅停依赖变更。
4. 验证真实构建、独立制品消费、应用启动和可运行后端，必要时用 pstack blast-radius。依赖脚本执行与发布各自受明确授权及现行操作规则约束。
5. 逐环境报告运行、跳过、失败和未知。缺 PostgreSQL 环境不算该后端通过；开发环境成功不代表生产支持，结果沿评审交付汇总。

## 完成及交付

交付精确版本及依据、消费影响、实际变更、环境覆盖与行为结果。说明未运行平台、后端、恢复或制品路径及下一责任；不将源码可定位当采用／运行证明。

## 停止与恢复

必要运行契约、平台资源或外部动作授权缺失时只停相应操作或结论。源冲突提供具体 API／生命周期反例给拥有者。资源补齐或采用裁定后恢复所选范围，不默认放宽验收。

## 示例与精确参考

升级存储驱动先核对事务与错误语义，再验证公开包和可运行后端。只改 catalog 并构建成功不能声明所有数据库行为兼容。
