# 选择工程场景

本页拥有主场景选择和组合方法。先按预期结果选一个主场景，再补充真实触发的专项义务。具体顺序归场景正文，共享要求归[工作约定](../workflow.md)；不机械运行多套完整 playbook。

## 按任务选择

| 预期结果 | 主场景 | 常见组合 |
|---|---|---|
| 理解、比较、明确目标或设计输入 | [调查与设计](research-and-design.md) | 性能诊断可补性能；调查后不自动实施 |
| 交付已明确的新行为 | [新功能](feature.md) | 新边界补设计，消费者变化补迁移 |
| 解释并修复错误行为 | [缺陷](bug-fix.md) | 慢或泄漏补性能／运行责任 |
| 保持或获准修订行为，换结构／接口 | [重构与迁移](refactoring.md) | 公开保证改变先补设计 |
| 诊断并改善可测指标 | [性能](performance.md) | 行为错误补缺陷，环境改变补依赖 |
| 变更依赖、配置、后端或环境 | [依赖与运行环境](dependencies-and-runtime.md) | 接口变化补迁移，制品补交付 |
| 判断成果、处置发现、完成授权交付 | [评审与交付](review-and-delivery.md) | 被评成果对应场景提供验收与证据 |
| 维护正文、地图、登记、方法或宿主适配 | [文档与技能](docs-and-skills.md) | 新语义回其拥有者，算法改变回工具 |

## 组合与最小阅读

已知局部修复只读缺陷路径、实际成员承诺与受影响检查。新边界需要调查／设计，但既有设计足够时不重复；有代表性性能负载时才读性能专项。共享主题也按条件展开，不将整区设为默认必读。

例如“更换存储驱动但不改公开行为”以依赖为主，补迁移的消费者核对。一次正确性故障伴随性能退化，可以缺陷为主，补基线与重复测量。成果、停止点和未覆盖只由本次任务汇总一次。

## 方法采用与维护

各场景引用[三层方法的固定来源](../skills.md#三层分工)：流程 poteto-mode，写法 Matt，品味 ub-mode。具体正文读取、自动调用和行为证据分别判断。独立写者按[隔离交接](../workflow.md#责任与协作交接)推进，外部动作沿任务授权。

单项长任务、长期协调、独立队列或线性栈从[playbook 选择](../skills.md#playbook-入口)展开；暂停和接续也使用同一入口。规模和终点决定方法，普通局部任务不用建立长期调度层。

场景维护者修改顺序时同步入向路径与必要章节登记。结构检查不能决定步骤正确、实际遵循或结果质量；已接受输入足够就继续工作，缺关键依据只停依赖部分。
