# 文档与技能维护

## 何时使用

用于正文、阅读地图、工程约定、登记、技能、角色或宿主适配的维护。改变工具算法转工具交付；新产品／领域语义回真实拥有者，不靠搬文档决定。

## 开始需要什么

需要本次目标、有效源、采用范围、写路径、消费者与验证。整合说明有效信息如何承接，未写章节继续缺项；候选和过程留 tmp。缺关键语义时仍可盘点来源、锚点和读取者。

## 最小上下文

读被改源与[文档治理](../documentation.md)，再追入向链接、登记、代码／生成输入。需要判断落点、粒度或拆页时展开[维护指南](../../maintenance.md)，已有明确归属的局部文字修复直接沿本页步骤进行。技能源及工具归[agent 能力](../../../.meta_harness/agents/README.md)与[生成入口](../../../.meta_harness/tooling/README.md)。闭包明确后停止扩大阅读。

## 适用共享规范

[唯一源](../documentation.md#位置与唯一源)、[表达排版](../documentation.md#表达与排版)、[维护](../documentation.md#最低内容与维护)、[技能更新](../skills.md#更新与维护传播)。

## 工作步骤

1. 确定含义拥有者和持续材料／过程材料归属。文档整合按有效信息单元重写落位，不复制成第二正文，不以目标目录替代接受。
2. 写作加载 asd-ste100；改 AGENTS 加载 write-agents-md；改 skill 加载当前官方 skill-creator；角色加载 design-subagents。具体入口按根 AGENTS 与宿主提供的真实技能，不能把原版 create-skill 当本项目入口。
3. 写 skill、AGENTS 与子代理简报时用 Matt writing-for-agents 组织上下文指针，pstack technical-writing／unslop 补写作方法。保留条件、未知与要求强度，不能用简化表达改变含义。
4. 修改 canonical 源并同步实际消费者和必要生成，既定生成操作沿工具入口。不直接写宿主产物；方法或加载路线漂移时按需参考 maintain-verification-skill，新的路线才参考 create-verification-skill。
5. 运行文档链接、目标结构及所改源适用检查。skills 或宿主适配还区分生成、发现、实际加载、遵循及行为，必要真实任务另验；重复错误可参考 correct，reflect 的应用边界仍按原文及任务授权。
6. 更新唯一登记和必要地图；未写正文保留标记。报告结构结果、语义复核、实际覆盖和剩余责任；发现、文件读取、原生调用、hook 执行与任务行为分别说明，不用安装或文件存在声称技能已生效。

## 完成及交付

交付当前正文、精确来源与采用、消费者变化、检查及未覆盖。必要方法／行为资源随拥有者，单次研究、评审和执行证据留 tmp。文档有内容不等于规范已采用或 agent 已遵循。

## 停止与恢复

源冲突、采用未定、关键消费者未知时只停依赖切换，继续其它明确信息单元。自有厚指导及 TS／Node 旧页退役须等已采用顶层正文及对应保证承接，当前仍维护其真实引用与登记义务，不提前删除。缺宿主验证资源就保留加载／行为未覆盖；拥有者裁定和必要资源齐备后恢复，不删登记换绿色。

## 示例与精确参考

改 skills.md 的来源先定位引用它的场景和任务入口，再核对必要依赖与实际采用差异。文档链接通过不证明 SessionStart 已注入，更不证明模型按方法完成任务。
