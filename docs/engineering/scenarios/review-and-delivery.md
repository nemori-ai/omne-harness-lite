# 评审、验收与交付

## 何时使用

用于独立判断成果、处置发现、确认可接受范围或执行已授权交付。实现自查不等于独立验收，评审意见不授予接受或发布权。

## 开始需要什么

需要精确被评输入、BASE／候选、规范和契约来源、采用范围、验收、实际环境、已有机器读数及外部动作授权。没有规格时明确缺失，不从提交描述补虚构规格。

## 最小上下文

先读实际成果、[贡献接受](../../../CONTRIBUTING.md#评审与接受)及[验证说明](../../verification.md)。设计复核一次选一个判断对象；实现按风险展开，责任与证据范围明确就停，不为普通交付机械派全部角色。

## 适用共享规范

[风险选择](../quality.md#按成果和风险验证)、[失败未知](../quality.md#失败未知与完成范围)、[完成声明](../workflow.md#完成与交付声明)、[交付权限](../publication.md#提交表达与权限)。

## 工作步骤

1. 固定实际输入和受影响范围，先运行相称工具检查。区分已提交 diff 与当前未提交字节，确保后续结论指向真实候选。
2. 按对象和风险选择评审或验收。pstack interrogate 可补对抗意见；已选 Matt code-review 分别输出 Standards／Spec。其默认三点 diff 至 HEAD 不覆盖未提交改动，需先明确实际覆盖，不擅自提交以满足方法。
3. 把发现对照具体契约或机器证据，由有写权者处置。不能改冻结验收、弱化断言或把评审判断写成用户采用；非阻断未知仍明确责任。
4. 输入改变后复跑受影响检查，从最终字节报告发现与处置。相称检查通过后由有权负责人判断接受范围，意见一致不是接受替代。
5. 准备提交或 PR 表达按[贡献指南](../../../CONTRIBUTING.md#提交与-pr-表达)，方法沿 pstack Opening a PR；已授权的外部动作才进入 Babysit 或 Shipping。没有发布授权时交付可审阅成果、证据与未覆盖，停在外部动作前。

## 完成及交付

交付精确输入、发现及处置、实际检查、范围、未知和下一责任。验收 Pass 仅支持其方法范围；未执行动作不能声明已发布、已合并或远端 CI 通过。

## 停止与恢复

归属、关键验收或权限缺失时暂停相应判断／外部动作，继续独立审阅与整理。未提交字节变动使旧评审过时时核对并复跑，缺环境报告无法验证，不能改判通过。
