# 共享工作约定

本页解释跨场景的输入、范围、责任和交付边界。要求来自被引用的现行项目源；技能提供具体方法。仅在适用条件下展开，不要求每个任务重走完整设计。

## 有效输入与范围

先说明问题、预期结果和受影响范围，定位精确来源、当前承诺及采用状态，按[贡献范围](../../CONTRIBUTING.md#确定变更范围)区分局部修复、新语义和反例。调查结论、候选方案、已接受承诺、当前实现和运行观察分别记录。文件存在、评审意见或测试通过不能代替接受依据。

开始写入前沿[开发准备](../development.md#准备可用的检出)确认检出、分支、已有改动与工具环境。任务指明可写路径、必要输入、成果和验收。已授权的可逆工作持续推进；任务范围不能由技能默认的提交、外部消息或发布步骤扩大。

对于卡片操作，先沿[agent交付操作](agent-delivery.md)核对启用范围、单写责任和当前修订。交付卡组织本次工作，长期承诺继续由各实际拥有者维护；未启用时形成获准任务草稿。

## 最小上下文与方法

按[任务地图](../context-map.md)选择一个[主场景](scenarios/README.md)，读取真实拥有者和局部 AGENTS。只有新保证、源冲突、生命周期交接或消费者变化才展开相应设计和组合约束。责任与本次验证足够明确就停止扩大阅读。

工程方法从[技能引用](skills.md)展开。人读精确原文；agent 加载宿主实际支持的正文及必要参考。方法缺失时不能声称已调用。可独立完成的项目工作继续，依赖该方法的部分标明缺口及下一责任。

## 责任与协作交接

用户已接受独立任务在隔离工作树中并行。每个写者有明确检出、任务分支和责任范围；共享接口、锁文件及集成拓扑由单一负责人维护，耦合工作按依赖串行。不要在执行者仍持有的工作树中并发写入或运行会改变状态的检查。只读调查和复核可并行，委派不转移主会话的检查与结果责任。

每个写者先进入自己的检出，核对 cwd、分支、已有改动与实际工具输入。检查和宿主钩子必须观察该写者的实际候选；从别树启动或使用别树 editable 环境时不能冒称已验证本树。静态源切换不证明 hook 真实执行，新实例加载和实际运行分别取证。

宿主保存的会话目录、当前工具调用的工作目录和进程中的目录可能不同。修改会话目录不能证明当前活动轮已释放旧树，也不能把单次exec的workdir当成宿主hook的cwd。未核实真实消费者前，保留旧树；支持边界与实际观测沿[钩子说明](../../.meta_harness/agents/hooks/README.md)核对。

交接给执行者时明确目标、工作树／分支、写范围、精确输入、完成判断、停止条件和未决。收到交付后核对实际落点、diff 与执行证据，不能直接转述“已完成”。规范、接口、行为和工具的拥有者分别保留责任。

### 工作树清理条件

获准清理时，先盘点未提交与唯一的 ignored 材料、仍存活的执行者、工具环境及其它真实消费者。对需要保留的正式成果，核对其已保存到获准的远端。按任务授权保全唯一临时材料，并读回目标材料。核对来源与保留字节的哈希对应，再修复接续记录中的恢复路径。工作树为clean或分支已合并，都不能证明可以强制删除。停止依赖该树的活动并确认没有活跃消费者后，离开将被移除的目录，再执行获准清理。不能移除执行者仍持有的树。

具体创建、接续和清理操作沿[所选 playbook](skills.md#playbook-入口)，本段拥有项目条件，不另存一套工作树教程。

## 任务跟踪与接续

所选 poteto-mode playbook 的原步骤先进入任务清单。不适用步骤保留并说明跳过理由，不以默认步骤扩大权限。Feature 的吞吐检查点保留阻塞首步、独立工作流、共享可变状态和最小安全拆分四项；不适用项说明原因，阶段边界按实际依赖更新。具体方法从[流程入口](skills.md#playbook-入口)读取，不复制为第二套执行手册。

跨会话任务记录精确目标、分支、已验证成果、下一步与尚缺条件。收到明确暂停要求才用 Pause safely；接续用 Session pickup，先核对实际成果及检查点而非推测上一会话已完成。cloud 环境下成果保存与临时状态分别按[交付保存边界](publication.md#成果保存与跨会话接续)处理，不能等任务退出才首次保存。

## 停止与继续

关键语义、采用依据、权限或必要验证资源缺失时，只暂停依赖部分。向拥有者提供事实、具体反例或问题、影响、选项及可继续条件。继续其它独立工作，保留未知，不自行补默认政策。

依据和范围已经明确时直接执行相称检查，不逐阶段重复请求批准。新依据到达后核对受影响范围再恢复。源和实现冲突不能靠选方便说法、删登记或降低断言消除；按[信息边界](../../AGENTS.md#信息权威与演进边界)返回语义拥有者。

## 完成与交付声明

按[贡献交付](../../CONTRIBUTING.md#形成可审阅的交付)和[验证声明](../verification.md#交付时说明什么)报告目标、实际改变、采用依据、精确输入、已运行检查、结果与未覆盖。已完成、部分完成、未完成和受阻分别说清，下一责任可定位。

声明性能提升须附适用测量；没有测量就不声称提升。除[正式保存例外](documentation.md#四类长期成果与普通任务)外，过程、计划、逐轮评审和单次证据归任务tmp；持续正文只保留当前承诺、必要理由及可复跑资源，归属沿[终态规则](../development.md#终态与过程材料)。正式接受与提交发布仍走其实际拥有者。

## 共享集成与隔离

工作树单写与任务权限继续按本页执行。涉及 work、轨道、main 或 stable 运输时，读取[多层分支规则](integration.md)：Issue 拥有 revision/attempt/route，集成 owner 拥有候选和精确 ref 事务。先观察共同采用状态；pending/原任务豁免不因文件生成而变成新准入。完整运输事实不替代接受。
