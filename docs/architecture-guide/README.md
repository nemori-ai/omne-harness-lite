# omne-harness-lite 架构设计指南

本指南面向参与架构设计的 agent，说明如何描述一个能力可动态增减、实现可替换、结构可演化的系统。设计需要同时解释能力的契约、组合关系、状态权威和变化过程，并让所有权、失败与不变量可检查。

## 规则的适用范围

“必须”“不得”表达保护契约所需的设计义务；“建议”“优先”表达可以说明理由后调整的判断；“例如”“可选择”表达说明或候选政策。具体能力采用哪个替换边界、失败政策或状态机，应在其契约中确定，不能从示例直接推导。

本指南提供建模方法和应当回答的语义问题，不规定所有能力必须采用统一类层次、通用工作流、事件溯源或全套插件机制。专题中列出的状态和关系也是描述工具，是否需要独立实现对象取决于真实职责。

用户明确的新要求优先。没有新观测时，有效决定在有效需求前提和适用范围内是研究、提案、决定三者的最终权威；每份决定至少链接提案或研究，推翻需要可复现、可验证、可因果解释的强理由，详见[知识流转](../maintenance/knowledge-flow.md)。遇到指南、架构、规格或实现冲突，先识别争议概念的归属、适用版本和决策状态，解决后同步相关投影；不能挑选最方便的文字作为依据。本指南的示例不改变已有领域提案的评审状态。

术语的基础定义集中在[概念定义](foundations/concepts.md)，专题拥有该主题的详细判断。引用其他主题时使用链接，不复制另一份定义。目录名按主题命名，不嵌入章节编号；新增内容先判断现有专题是否能够承载，再决定是否拆页，并更新所属索引。

外部资料只用于必要的理论来源或实现语义核对。指南正文应能独立理解；某个库在特定版本的行为，不能未经映射就成为本项目的普遍规则。
