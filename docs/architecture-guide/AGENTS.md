# 本项目的建模方法与判断

这里帮助设计者从目标和需求推导性质，再选择能力边界、操作及组合机制。
方法解释怎样判断；具体系统当前选择由 architecture、decisions 和 spec 分别维护。
本入口沿[知识准入](../maintenance/organization.md#持久化知识的准入)限定范围。

## 准入与转出

对本项目多次建模或架构任务有用、具有明确依据的概念、判断方法和解释性例子，
可进入所属专题。所有权、不变量、观察与失败边界要能支持具体设计判断，例子
仍是方法说明，不自动成为产品契约。

单个能力的选择和讨论按 proposals 准入；精确承诺归 spec；当前提供者细节归
包/应用设计；命令和执行技巧归开发指南或相关 skill，不在本目录复制。

## 按任务进入

从[指南首页](README.md)按问题展开。建模先读或引用
[目标与需求推导性质](assurance/invariants.md#从目标与需求推导性质)，共享组合或
控制放宽再按[证明义务](assurance/composability.md)判断必要证据。

修改方法先核对其来源和适用范围，再同步导航及 skills；普通局部说明不要求通读全部专题。
