# 防御指导的演化与退出

本规范落实 [D-003](../decisions/D-003-defensive-evaluation.md)。[开发模型评估](../evaluation/README.md)及其[协议](../evaluation/protocol.md)规定模型切换前的离线证据协议；`spec/tools/evaluate_developer_model.py REPORT [--schema SCHEMA]` 只产生 `evidence-ready` 或 `needs-completion` 结论。本页规定防御资产的归属、范围和维护。任何采用、降层或退出均须人工审阅并记录；最终是否切换由用户决定，评估 CLI 不授权模型切换或规则变更。

## 分类与归属

| 类别 | 权威归属 | 随什么变化 |
|---|---|---|
| 系统保证 | 所属能力、数据或组合契约 | 仅以相应规范与决定变更；模型升级不是撤销依据 |
| 对保证的设计提醒 | `docs/defensive-patterns.md`，链接具体契约 | 可压缩或按需读取，不能削弱保证 |
| 针对模型弱点的辅助 | 防御模式及评估证据 | 依模型、任务、工具、上下文和收益调整 |
| 环境临时绕行 | 适用的提案、研究或维护记录 | 依赖版本、平台缺陷或修复证据退出 |

每条保留的模式至少说明：所保护的结果、来源证据及故障机制、适用范围和反例、归属的契约/工具/检查、当前使用方式（常驻、按需、条件注入或已退出）、复核触发以及已有验证。复杂故障机制可进入按需创建的 postmortem。模式页不复制系统语义、完整实验日志或事故故事。

新经验先区分系统缺陷、工具表达问题、环境故障、知识缺失和模型行为偏差。能由契约和测试确定的要求回到契约与检查；能由工具反馈避免的误解先修工具；有条件复用价值的经验进入模式或 skill；仅本任务相关的信息留在任务记录。一次严重且机制清楚的失败可支持新增约束，但必须保留其说明范围，频繁出现也不自动证明提示应永久加强。

## 评估、精简与退出

开发主力模型切换前，必须按[评估规范](../evaluation/README.md)对相关辅助比较保留、简化和移除。评估记录候选模型及可辨认版本、推理配置、harness/skill/工具版本、实际加载的指导、任务类别与环境；调优集和独立检验集分离，检查最终产物、错误、副作用及 token、时间、无用工具调用和人工干预。不能以模型自评、版本名称、规则仍在文本中或已有防御下未出错替代对照证据。

评估结论只可为 evidence-ready 或需补充，不能自动授权。人工采用记录须写明：在哪个模型/任务/工具范围改变哪条辅助、关联的评估证据与决定、替代机制、未覆盖范围，以及故障复发时恢复或重新评估的条件。系统保证仍由其契约保护。

模型或工具版本变化、故障复发、任务分布变化、规则冲突或明显执行负担均触发复核。退出的是特定范围的使用方式，不一定删除历史知识；已退出内容从常驻提示、skill 路由和有效索引撤下或指向替代项。相同样本连续通过不能删除仍保护授权、租户隔离或其他系统边界的必要验证。
