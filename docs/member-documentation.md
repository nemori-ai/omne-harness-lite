# 能力组与成员包文档

本页定包组（`packages/<包组>/`）与成员（`packages/<包组>/<成员>/`）里留什么文档。判据归[文档治理](engineering/documentation.md#位置与唯一源)：信息的源头只有一处，约束只有四样，源码已经表达的不写。

## 三处各自拥有的知识

| 位置 | 拥有什么 |
| --- | --- |
| `docs/domains/` | 领域之间的关系：谁拥有什么事实，谁认识谁，跨领域的组合保证由谁承担 |
| `packages/<包组>/SPEC.md` | 这个包组的六样：总体架构、领域边界、心智模型、应然设计、原则与约束、不变式 |
| 源码、用例、形式模型 | 其余一切 |

上层约束下层。源码与测试用来对照设计，不能反过来降低承诺。

## 能力组文档要求

一个包组一份规格 `SPEC.md`。六个二级标题，次序固定：

| 标题 | 装什么 |
| --- | --- |
| 总体架构 | 这个包组由哪几部分组成，各部分怎样协作 |
| 领域边界 | 它拥有什么，不拥有什么；谁认识谁；向外声明哪些端口 |
| 心智模型 | 它是什么，不是什么，拿它怎样量一个设计 |
| 应然设计 | 代码自己说不清的目标语义：失败、未知、取消、恢复、并发下应当怎样。写成规则，不写成实现 |
| 原则与约束 | 做取舍时要守的原则；外部给的硬约束 |
| 不变式 | 永远成立的性质，各带编号、违反的后果、由什么守 |

规格只写应然。不写日期、提交号、卡号、决定编号、实现状态与修订记录。不变式能写成检查或模型的，用一句话指过去，不重复。

现有包组在整体重写之前，旧的 `README.md`、登记与 `docs/` 留着，只许变少。新的语义只写进规格；旧文档里与它矛盾的段落删掉，不在旧文档上补写。

## 成员包文档要求

成员不带文档。成员的边界与不变式是领域的性质，写在包组的规格里；成员只是工程上的拆分。

两种例外：对外发布的成员可以有一份几行的 `README.md`，说它是什么、怎样引入；契约成员的 `api/*.api.md` 是生成的快照，不手工维护。

### 行为契约与完整文档

公开类型和必要的运行时校验拥有数据形状。类型表达不了的行为，例如结果、失败、所有权、生命周期、并发、取消和恢复下应当怎样，写在包组规格的「应然设计」与「不变式」里。

一程的 spec 是那一程的过程材料，不是项目的规格，见[规格分类](engineering/documentation.md#单次交付规格与长期规格)。一程改了应然的，把改的那几句写进包组规格。

### 固定骨架

新成员由包模板生成，必需节点见[包组织](package-organization.md#成员的必选结构)：`package.json`、两份 tsconfig、`vitest.config.ts`、`src/index.ts`、`tests/public-entry.spec.ts`；绑定变体另有 `src/cordis.ts` 与它的用例。没有 Markdown，没有文档登记。

新包组由包组模板生成一份带六个标题的 `SPEC.md`。

### 专题职责

成员没有专题文档。属于约束的写进包组规格，其余以源码为准。

### 目录入口

目录不带 `README.md` 与 `index.md`。

### 占位与完成

没有文档占位。模板生成的源码与包组规格带草稿标记（`PACKAGE_TEMPLATE_DRAFT`、`DOMAIN_TEMPLATE_DRAFT`），写完删掉；结构扫描看到标记报 `draft`。

### 按需专题与持续资源

不为阅读任务另建专题。持续资源随实际义务放在固定目录：Schema 进 `schema/`，模型与证明进 `verification/`，测试输入进 `tests/fixtures/`，可执行验收场景进 `acceptance/`，运行资产进 `resources/`。

## 阅读与维护路径

读：先读根 `AGENTS.md` 的两张图与要点，再读所在包组的规格，然后读源码。

写：改了应然，改包组规格里对应的一节；只是实现变了，不改文档。已有文档与应然矛盾时，改掉或删掉那一段，不在旁边补一段新说法。一程的 spec、plan、取证与验证记录留任务 `tmp/`，一程结束就清。

现有成员的旧文档（`README.md`、`SPEC.md`、`docs/`、登记）在所属包组重写规格时一起处理：属于约束的收进规格，其余删除。

## 检查与结论边界

`pnpm run lint:rules` 带五项整洁检查：文档白名单、规格形状、规格里被禁止的正文形式、被禁止的注释形式、文件与函数行数。现存的违例记在 `tools/product-checks/hygiene-baseline.json`，只许变少。`pnpm run check:docs` 核链接与锚点。

检查通过只说明形状合格，不说明语义充分、设计被接受或行为已兑现。
