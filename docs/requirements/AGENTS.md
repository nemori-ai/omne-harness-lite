# 目标与要求的权威正文

这里保存系统要达到的结果及必须遵守的约束，供后续建模、设计和交付消费。
本入口是[知识准入](../maintenance/organization.md#持久化知识的准入)在需求目录的投影。

## 准入与转出

已由用户确认的系统目标、功能需求和全局约束，以及在授权范围内有明确依据的
细化，可以进入正文；确认范围、来源和未决部分须可辨认。需求由所需结果表述，
不以某个库或当前实现的限制替代目标。

外部系统的事实核对进入 research；尚未选择的机制和有长期取舍价值的候选按
proposals 准入；内部实现方式回到包/应用设计。不能把 agent 的推测或提案中的
偏好写成已经确认的要求。

## 按任务进入

新增、细化或变更要求，读[需求维护](../maintenance/requirements.md)核对身份、
确认和消费基线，从[本目录入口](README.md)定位正文。下游设计从这些要求导出
不变量及安全/进展性质，方法见[需求推导](../architecture-guide/assurance/invariants.md#从目标与需求推导性质)。

普通措辞或链接修正只展开所属条款和相称检查；不因读取本目录而重开已确认范围。
