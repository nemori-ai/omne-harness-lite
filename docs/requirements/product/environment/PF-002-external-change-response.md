# PF-002：外部环境感知与响应

[环境维度](README.md)

主维度：环境。副维度：用户、智能体。2026-09-12 用户逐项介绍中的第二项。

## 已确认要求

**PF-002.C1（用户直接确认）：** 系统能够感知外部环境的变化，并具备对这些变化产生响应、
作出相应行为的能力。

## 来源补充

以下是既有材料补充的解释，来源截止范围尚未确认；本段未作为用户额外确认的
细化承诺登记。继承授权与范围见 [SYS-CONTINUITY](../../system/omne-next-continuity.md)。

系统可以持续关注获准的环境信息，让外部变化
参与正在进行的协作，也可以在适用条件成立时主动发起新的工作。用户没有发出
新的对话消息时，环境变化仍然可以成为系统开展工作的原因。

| 情形 | 产品层面的含义 |
|---|---|
| 运行中的协作感知到变化 | 新信息可以进入当前协作，成为后续判断与行为的输入 |
| 变化触发新的响应工作 | 满足相应条件的变化可以驱动 agent 开始工作，包括此前未在运行的情形 |
| 作出相应行为 | 在适用权限与流程内进行调查、处理、告知或提出需要决定的下一步 |

感知到变化、决定响应和实际采取行为分别表达；感知能力不意味着每次变化都要
触发行动。响应应能关联到引起它的变化，明确已采取的行为与结果；没有新变化、
无法感知、响应失败或结论不确定应能分别说明。

感知范围与响应行为继续遵循[多组织上下文](../user/PF-001-tenant-organization-context.md)中的
数据、权限、行动空间与流程规范。外部变化提供信息，感知或自主响应本身不增加
授权。

补充依据见[第二项来源核对](../../../research/product-feature-sources.md#第二项外部环境感知与响应)。

## 待澄清

具体环境范围、响应条件、时效与失败恢复规则待继续展开；相应能力与机制在后续
建模中定义。

重复变化、失联和恢复时的行为规则仍待明确。来源中的 Channels、Blueprint、State、
Inbound 等结构不自动成为本项目模型；感知与响应也不自动增加授权。

用户随后明确的 [PF-011](../agent/PF-011-future-planning-calendars-and-reminders.md)
进一步确认环境/信源/数据源/连接器信号可引出未来规划及调整；该具体范围按
PF-011 的确认条款生效，不受本页较早来源补充的未确认标记限制。
