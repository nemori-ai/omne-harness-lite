# PF-003：工具执行可观察、生命周期控制与后台接续

[智能体维度](README.md) · [来源核对](../../../research/tool-execution-sources.md)

主维度：智能体。副维度：用户。主归属关注智能体工具执行应具备的能力；用户
维度引用其对观察、披露和控制的影响。2026-09-12 用户逐项介绍中的第三项。

## 已确认要求

用户在本轮明确以下产品要求，并授权从 `omne-next/omne_harness` 检索补充信息。
随后明确继承原系统自动转后台机制，并要求恢复后的智能体运行时重新关联已有
后台调用。确认范围为 C1–C6；来源补充与未决细节分别列于后文。

- **PF-003.C1：执行状态可感知。** 用户应当能够感知工具调用的执行状态。
- **PF-003.C2：内部执行情况可按需披露。** 用户应当能够感知工具内部执行情况；
  内部帧能够按需对用户披露，并支持流式输出。
- **PF-003.C3：中断特定调用。** 用户能够控制工具调用的生命周期，具体包括
  单独中断某一个正在执行的工具调用；控制粒度是该次调用。
- **PF-003.C4：符合声明的调用可手动转后台。** 对于声明可以在后台运行的工具，
  用户能够将正在执行的调用手动切换至后台。后台意味着工具执行脱离会话运行时
  本身，其执行可以跨越会话运行时的重建。
- **PF-003.C5：自动转后台。** 继承原系统的自动离场机制：工具声明自动切换
  阈值及适用的后台形态，前台执行超过阈值后，系统自动将调用转后台，无需等待
  用户手动操作。阈值受系统上限约束，切换应在所属运行的执行预算内完成；具体
  数值和声明形式留待设计。
- **PF-003.C6：恢复后重新关联后台调用。** 智能体运行时重建并恢复后，能够
  与脱离原运行时上下文、在系统后台执行的既有工具调用重新建立联系，继续感知
  其状态、接收过程信息和结果，并按适用权限控制该次调用。重新关联指向原有
  调用，不能用重复派发一件新工作冒充接续。

“后台”是 C4–C6 中的执行生命周期关系，不只是界面收起或用户不再等待。切换后
的调用仍属于 C1–C3 的观察与控制对象；会话运行时重建不应仅因其自身生命周期
变化而终止该后台工作。中断某次调用与让它在后台继续，是分别表达的用户意图。

## 产品场景与含义

以下场景解释上述确认范围，尚不是已经执行的验收或已选定的协议。

| 场景 | 应能表达的产品表现 |
|---|---|
| 一个工具长时间执行 | 用户能够查看该次调用的执行状态，并按需查看内部过程帧；过程内容可以边执行边输出 |
| 多个工具调用同时执行，用户只想停其中一个 | 用户能够定位并中断目标调用，其他调用无需因这个操作一并终止；具体中断结果可被感知 |
| 支持后台的工具正在执行，用户选择转后台 | 用户主动发起切换，该次工具工作在脱离会话运行时后继续执行；只允许启动时指定后台或只按阈值自动切换不足以覆盖此场景 |
| 工具前台执行超过声明的自动切换阈值 | 系统按声明自动转后台；用户手动切换与自动切换都受到支持 |
| 后台工具尚未结束，会话运行时被重建 | 既有后台工作可以继续；恢复后的智能体运行时能重新关联它，继续获取状态、过程与结果，并保留适用的调用控制 |

## 来源补充

[四份来源要求](../../../research/tool-execution-sources.md)支持以下区分。这些是补充
理解和后续核对方向，未作为本项目额外确认的精确承诺登记。

- **调用状态、过程帧与结果分别表达。** 状态回答“现在怎样了”，内部帧说明
  “正在做什么”，结果说明该次调用产出了什么；有进度输出不直接证明调用成功。
- **信息与操作指向同一次调用。** 状态、过程帧、中断和后台切换应能关联到
  同一工具工作，前后台切换或会话重建后仍能辨认归属；具体身份和字段尚未定义。
- **中断的结果需要如实说明。** 用户中断、工具自身失败、中断请求已受理和
  执行实际停止需要区分；停止执行也不等于撤销已经发生的外部效果。
- **过程信息的连续性。** 来源还讨论前后台一致送达、断线重连、执行中重入、
  按序回放和超限可见等条件，可用于后续细化用户如何持续观察过程。
- **后台声明需要可兑现。** 来源把可重建执行上下文作为离场条件之一，用于
  防止后台工作仍隐式依赖已经消失的会话实例；本项目的声明和判定方式待设计。

用户的“内部帧”在本页保持产品含义，未等同于某个旧事件类型、调试协议或消息
Schema。C5 已确认自动离场机制，C6 已确认恢复后的重新关联能力；执行切换时
是否从头重新执行、具体等待模型、中断后的结果编码和后台宿主恢复政策仍需设计。

## 待澄清

- 状态及内部帧的内容范围、粒度、按需披露方式、适用权限，以及没有可披露帧时
  的呈现；实时送达、重入回放、保留、裁剪和时效的具体保证。
- 单次中断的完成判据与时效，执行完成、中断和切后台并发时如何反馈，以及
  对无法确认已停止或已经产生外部效果的调用如何呈现结果。
- 后台能力由谁声明、如何验证，执行中切换的边界和重复执行约束；不支持或
  当前无法切换时的明确反馈，后台工作失败及宿主丢失时的处理。
- 自动切换阈值、系统上限和执行预算的具体关系与配置方式，以及自动切换与
  用户控制同时发生时的处置。
- 恢复后关联后台调用所用的身份、发现和信息接续机制，包括恢复期间已完成
  的调用如何交付真实结果；重新关联能力本身已由 C6 确认。
- 工具中断后是否存在其他生命周期控制，以及整轮执行或会话的控制如何与单次
  调用协调。

这些细节尚未定案，不影响已确认的观察、按需披露、单次中断、手动及自动转后台
和运行时恢复后重新关联的要求。

## 关联要求与当前设计

观察、披露与控制均受 [SYS-TENANT](../../system/constraints.md#sys-tenant) 和
[PF-001](../user/PF-001-tenant-organization-context.md) 的租户、组织上下文及权限约束。
C4–C6 是 [SYS-RUNTIME-CONTINUITY](../../system/runtime-state-and-continuity.md) 的相关产品
场景：会话运行时可以重建，已脱离它的工具工作具有独立生命周期；这不自动给出
后台宿主自身故障时的恢复保证。

[Agent 核心候选](../../../proposals/agent-core/README.md#当前需求对应与缺口)已有工具
定义、执行、结果与离场工作的边界输入，但尚未覆盖本项的完整产品要求。
本次新增要求与现有已确认目标相容；没有需要因此取代的已接受业务决定或规格，
候选模型与旧需求基线的历史状态保持不变。
