# PF-001：原生租户隔离与多组织上下文

[用户维度](README.md)

主维度：用户。副维度：智能体。2026-09-12 用户逐项介绍中的第一项。

## 已确认要求

以下段落及表格为 PF-001 的确认范围。

原生租户隔离义务引用 [SYS-TENANT](../../system/constraints.md#sys-tenant)。对于同一个用户，系统须能够表示其所归属的多个组织，
以及该用户与这些组织的归属关系。

当用户在不同的组织上下文下与 agent 协作时，组织上下文会影响协作中的
**效用（effect）**。系统须能够表达并使相应差异实际生效，至少覆盖以下方面：

| 方面 | 随组织上下文适用的内容 |
|---|---|
| 数据 | 协作所涉及的数据范围及隔离边界 |
| 权限 | 协作中适用的访问与操作权限 |
| 行动空间 | 协作时可用的行动范围 |
| 流程规范 | 协作时应遵循的流程、规则与要求 |

同一用户在组织 A 与组织 B 的上下文中协作时，上述方面可以有不同的效用；
用户身份、多个组织归属和当前协作所处的组织上下文需要能够分别表达。
具体差异随相应组织上下文生效，并继续受[SYS-TENANT](../../system/constraints.md#sys-tenant)
的租户隔离要求约束。

## 待澄清与设计输入

这里的“效用（effect）”沿用用户的产品表述，其精确语义、组织上下文的确定与
变化方式，以及相应规则如何作用于协作，待后续展开。现有[租户契约候选](../../../proposals/tenant-contracts/README.md)
提供已有身份与成员关系的设计输入，其具体契约仍保持候选状态。

本页不将产品表述中的 effect 等同于某种运行时 Effect 类型或实现机制。
