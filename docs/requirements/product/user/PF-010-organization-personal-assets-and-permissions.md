# PF-010：组织级与个人级资产和权限

[用户维度](README.md) · [资产与权益来源核对](../../../research/tenant-asset-and-permission-sources.md)

主维度：用户。副维度：智能体，关联当前上下文内可用资产、定义授权与行动范围。

## 已确认要求

2026-09-12 用户明确：资产和权限区分组织级与个人级；组织成员按照被分配的
角色、权限，在组内共享组织资产和权限。资产种类及 official / customized 的
区分可从 `omne-next` 补充。

C1/C2 记录直接要求及其区分；C3–C7 将源已接受要求中可明确映射的资产清单、
权利关系和用户可观察行为纳入本项。来源的产品要求与历史设计分别标明，不把
源聚合、表结构或运行时注册方式同时接受。

- **PF-010.C1：组织级与个人级分别表达并生效。** 用户拥有个人范围的资产
  和权限，也能在所加入的组织范围内使用共享资产和权限。组织层的资产、权益
  与治理规则共同适用于组织，成员按自己的角色及被授予的权限访问和操作；
  “共享”不要求所有角色都有相同管理权，也不把组织资产复制成每个成员的个人
  所有物。个人权限不会仅因加入组织而共享，组织管理员也不因此获得个人资产
  或私人会话的访问权。
- **PF-010.C2：来源、归属和使用权可分别辨认。** Official 表示官方提供或
  维护的来源，customized（来源常写 custom）表示自定义来源；两者不等于
  组织级和个人级。组织或个人都可能拥有/选用自定义资产，也可能获权使用官方
  资产。官方来源不会自动给所有租户授予使用权，自定义来源也不会自动给作者
  或使用它的 Agent 额外行动权限。来源不能靠任意请求自报来冒充。
- **PF-010.C3：资产清单有类型和明确归属。** 下节四类顶层 Agent 定义资产
  按组织/个人范围管理和展示；类型、稳定定义身份、原定义 owner、适用来源及
  已选用版本可辨。平台组件、模型档案、知识和附件同样需要各自的治理归属，
  但不能为了叫作“资产”而强行套入这四类的发布和权益生命周期。
- **PF-010.C4：拥有、获权和选用是不同事实。** 用户能区分定义所有权、
  使用权益（entitlement）和已选入当前租户资产组合及其版本（acquisition）。
  它们可同时成立；获得权益或选用不会转移定义所有权，也不证明节点已经安装、
  Agent 已激活或某次动作已获准。自己拥有的定义可提供权利依据，无须伪造向
  自己授予的外部权益。
- **PF-010.C5：每次操作使用一个明确上下文内的当前权限。** 组织角色、
  成员关系与当前权益决定谁可代表组织执行什么操作；个人和多个组织的权益
  不自动叠加或相互借用。目标组织不可用或成员失权时明确失败，不静默回退到
  个人范围。角色变更、退出、撤权、权益暂停或到期影响下一道尚未通过的准入；
  旧菜单、缓存和历史成功不能继续当作授权。已开始调用是否停止由独立运行控制
  决定，不能把权益撤销和强停混为一件事。
- **PF-010.C6：自定义资产的创作者与归属可追踪。** 获授权用户或 Agent
  在明确的个人/组织上下文中创作、修订、发布资产；实际作者与定义 owner
  分别记录。在组织范围创作，不因作者是自然人就变成个人资产；Agent 创作也
  不使资产脱离租户治理。草稿可修订，已发布版本保持不可变，后续改变形成新
  版本；发现新版本不静默替换已选用版本。持有使用权不自动获得编辑、fork、
  转让或扩大对外共享的权力。
- **PF-010.C7：用户能按范围看懂自己拥有什么和能做什么。** 资产视图按
  个人与各个获准组织区分，可看出上述多种关系、所选版本和真实可用状态。
  同一官方或外部定义可以在不同范围具有不同关系；一处可见不使其它范围获权。
  无权范围不泄漏资产存在或详情，来源不可用不伪装为成功空清单，读取和操作
  时的权限仍分别核对。

## 资产范围与 official / customized

以下是本轮已核对的种类及其产品边界。前四行是源已接受的**顶层 Agent 资产**；
后面列出相关组件和其它受治理材料，避免把“资产”误读为只有四种数据对象。

| 种类 | 含义及来源区分 | 组织/个人管理边界 |
|---|---|---|
| Skill | 可独立定义、发布、引用的技能；有官方与自定义来源 | 定义所有权、使用权益及版本选择分别治理；用户手动调用见 PF-009 |
| SlashCommand | 可绑定 Skill/Prompt 等上下文的命令定义；有官方与自定义来源 | 独立顶层资产；不包含键盘控制、shell 或系统命令 |
| Plugin | 组件分发与组合资产；有官方与自定义来源，可包含 tool、skill、command、rules、hooks | 内含成员随相应 Plugin 版本和权利治理；独立外部依赖保留自己的身份与权益 |
| Agent Blueprint / Definition | 智能体静态定义，包括官方 Agent 与 custom Agent | 不是会话或运行实例；引用组件不取得组件所有权；sub-agent 定义仍属这一类 |
| Tool、Middleware | 原系统组件来源设计以官方实现为当前边界 | 当前不是独立顶层用户资产；使用权限仍需检查，不能从“可安装 Plugin”推导任意自定义可执行代码权限 |
| Hooks、Rules 等成员 | 可以作为 Plugin 的声明性成员；来源随具体定义及分发材料记录 | 不自动取得独立顶层资产生命周期；自定义可执行扩展的资格与隔离另有设计边界 |
| 模型档案（model profile） | 源最新要求明确 official 与 user customized 同一表形、同一约束，来源可辨 | 官方原档在公开面只读；用户可管理自己的自定义档案。它不是第五类顶层 Agent 资产；组织共享范围仍须专项明确 |
| 知识、经验、报告及附件/文件 | 受治理的信息与工作产物，记录实际来源、作者与归属 | 按各自权限和生命周期管理；不强造 official/customized 二分，知识或文件内容也不自动成为指令或权限 |

四类定义的共享、使用和编辑权依各自当前依据判定。“官方原档只读”和
[PF-006](PF-006-user-settings-and-agent-definition-authorization.md) 的用户覆盖
出厂默认配置可同时成立：用户改变适用的选择、配置或自定义材料，不等于改写
官方发布原件。这里不预选统一的覆盖算法或资产存储模型。

## 可观察场景

| 场景 | 应有表现 |
|---|---|
| 组织有一项共享 Skill，两个成员的角色权限不同 | 使用同一组织资产与权益依据；是否可编辑、发布或调用按各自权限判定 |
| 用户仅在个人范围获权使用某项资产，随后进入组织会话 | 组织操作不能借用个人权益；需要该组织自己的合法依据 |
| 同一官方 Blueprint 被个人与两个组织选用 | 官方定义 owner 保持可辨，各范围的权益、选择版本和使用权限分别生效 |
| 成员在组织上下文中创作 Plugin，之后离开组织 | 作者事实保留，组织资产不自动变为其个人资产；后续组织操作使用最新成员权限 |
| Agent 有权使用某个 Plugin，却请求一项未被授权的外部动作 | 使用权益不替代动作授权；系统按相应门拒绝或发起合法确认 |

## 关联与待明确事项

本项具体展开 [PF-001](PF-001-tenant-organization-context.md) 的资产与权限效用，
全局隔离仍归 [SYS-TENANT](../../system/constraints.md#sys-tenant)。
[PF-006](PF-006-user-settings-and-agent-definition-authorization.md) 定义用户
设置及 Agent 定义级授权，[PF-007](PF-007-system-initiated-hitl.md) 定义系统
授权确认，[PF-009](PF-009-multimodal-input-attachments-and-commands.md) 定义
文件输入及命令操作；这些入口均不改变资产来源或跨组织借权。

待明确：各资产支持的具体管理动作和角色权限矩阵、个人与组织间显式共享/携入
及转让条件、模型档案和其它信息资产的组织共享规则、定义版本与授权延续关系、
官方初始资产集合和后续目录扩展。源当前权益模型为租户级，不以成员人数自动
生成逐席许可；商业授权等额外范围另行定义。
