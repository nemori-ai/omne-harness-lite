# PF-010：个人与组织的资产、设置及权限管理

[用户维度](README.md) · [资产与权益来源核对](../../../research/tenant-asset-and-permission-sources.md) · [管理操作来源核对](../../../research/tenant-management-sources.md)

主维度：用户。副维度：智能体，关联当前上下文内可用资产、定义授权与行动范围。

本项拥有个人/组织的管理范围、可管理对象和操作含义；
[PF-006](PF-006-user-settings-and-agent-definition-authorization.md) 拥有设置
覆盖、Agent 定义级授权及其生效规则。两项保持独立编号并互引，管理操作不再
在 PF-006 重复展开；产品可以提供连续的管理入口，不因文档分篇要求用户分开
操作。这样的归属也避免在一个持续增长的条目中混写管理目录与逐字段效用。

## 已确认要求

2026-09-12 用户明确：资产和权限区分组织级与个人级；组织成员按照被分配的
角色、权限，在组内共享组织资产和权限。资产种类及 official / customized 的
区分可从 `omne-next` 补充。

C1/C2 记录直接要求及其区分；C3–C7 将源已接受要求中可明确映射的资产清单、
权利关系和用户可观察行为纳入本项。来源的产品要求与历史设计分别标明，不把
源聚合、表结构或运行时注册方式同时接受。

同日用户进一步要求：用户能够管理**自己个人租户下**的权限、设置和资产；
在所在组织中具有**超级管理员角色**时，也能管理该组织的这些对象。C8 记录
直接要求；C9/C10 及管理操作表结合本轮要求和来源的有效产品条款细化“CRUD”
的实际含义，不采用旧角色枚举或一套通用于所有对象的数据删除模型。

- **PF-010.C1：组织级与个人级分别表达并生效。** 用户拥有个人范围的资产
  和权限，也能在所加入的组织范围内使用共享资产和权限。组织层的资产、权益
  与治理规则共同适用于组织，成员按自己的角色及被授予的权限访问和操作；
  “共享”不要求所有角色都有相同管理权，也不把组织资产复制成每个成员的个人
  所有物。个人权限不会仅因加入组织而共享，组织管理员也不因此获得个人资产
  或私人会话的访问权。
- **PF-010.C2：来源、归属和使用权可分别辨认。** Official 表示官方提供或
  维护的来源，customized（来源常写 custom）表示自定义来源；两者不等于
  组织级和个人级。组织或个人都可能拥有/选用自定义资产，也可能获权使用官方
  资产。官方来源不会自动给所有租户授予使用权，自定义来源也不会自动给作者
  或使用它的 Agent 额外行动权限。来源不能靠任意请求自报来冒充。
- **PF-010.C3：资产清单有类型和明确归属。** 下节四类顶层 Agent 定义资产
  按组织/个人范围管理和展示；类型、稳定定义身份、原定义 owner、适用来源及
  已选用版本可辨。平台组件、模型档案、知识和附件同样需要各自的治理归属，
  但不能为了叫作“资产”而强行套入这四类的发布和权益生命周期。
- **PF-010.C4：拥有、获权和选用是不同事实。** 用户能区分定义所有权、
  使用权益（entitlement）和已选入当前租户资产组合及其版本（acquisition）。
  它们可同时成立；获得权益或选用不会转移定义所有权，也不证明节点已经安装、
  Agent 已激活或某次动作已获准。自己拥有的定义可提供权利依据，无须伪造向
  自己授予的外部权益。
- **PF-010.C5：每次操作使用一个明确上下文内的当前权限。** 组织角色、
  成员关系与当前权益决定谁可代表组织执行什么操作；个人和多个组织的权益
  不自动叠加或相互借用。目标组织不可用或成员失权时明确失败，不静默回退到
  个人范围。角色变更、退出、撤权、权益暂停或到期影响下一道尚未通过的准入；
  旧菜单、缓存和历史成功不能继续当作授权。已开始调用是否停止由独立运行控制
  决定，不能把权益撤销和强停混为一件事。
- **PF-010.C6：自定义资产的创作者与归属可追踪。** 获授权用户或 Agent
  在明确的个人/组织上下文中创作、修订、发布资产；实际作者与定义 owner
  分别记录。在组织范围创作，不因作者是自然人就变成个人资产；Agent 创作也
  不使资产脱离租户治理。草稿可修订，已发布版本保持不可变，后续改变形成新
  版本；发现新版本不静默替换已选用版本。持有使用权不自动获得编辑、fork、
  转让或扩大对外共享的权力。
- **PF-010.C7：用户能按范围看懂自己拥有什么和能做什么。** 资产视图按
  个人与各个获准组织区分，可看出上述多种关系、所选版本和真实可用状态。
  同一官方或外部定义可以在不同范围具有不同关系；一处可见不使其它范围获权。
  无权范围不泄漏资产存在或详情，来源不可用不伪装为成功空清单，读取和操作
  时的权限仍分别核对。
- **PF-010.C8：个人用户和组织超级管理员具备对应范围的管理能力。** 用户
  可以在自己的个人租户范围内，对权限、设置及资产进行查询、创建、修改、
  撤销/删除等符合对象语义的管理；在所在组织具有超级管理员角色时，可以对
  该组织的上述对象行使完整的适用管理权。每次操作明确目标范围与对象；能
  浏览多个组织不等于能跨组织写入，普通成员也不因共享组织资产取得相同管理权。
  其它角色的委派管理权限仍按相应角色和授权定义。超级管理员的作用域是该
  组织，不因此取得平台全局权限、官方原件编辑权、其它租户或成员私人数据的
  管理权；外部账号同意及其它专属授权仍须有其自己的有效依据。
- **PF-010.C9：管理操作按对象的真实含义提供。** 用户能查看对象、配置和
  授权的详情、来源、当前值/状态及可用动作，并完成下表对应的管理流程。
  设置的创建/更改是建立或修改适用范围的配置，清除覆盖后的实际求值归
  PF-006；授权的授予、调整与撤销分别留痕，不改写过去的同意事实。自定义
  资产的草稿、发布、版本选择、停用、移除和退役分别表达；“删除”须说明在
  删除什么关系或内容，不能把这些操作合成一个无法解释的动作。账号级、
  设备级、会话级设置保留各自真实范围，不能因集中展示在个人/组织管理入口
  就被复制成一套租户级事实。
- **PF-010.C10：管理结果、影响和冲突可理解且可恢复。** 用户能看到修改
  实际是否成立、影响哪些后续使用以及受影响的引用与工作。改版、移除或退役
  前核对相关 Agent 组合、会话、日程及其它依赖；不能默认级联删除、偷偷换
  Agent/版本或把资产停用当作停止活动 Run。多步流程部分成功时分别展示已
  完成和待处理步骤，未知结果后的重试认回同一逻辑操作，过期编辑不能静默
  覆盖别人已确认的修改。当前权限和目标条件在实际操作时核对，旧菜单或预览
  不构成永久授权；审计保留操作者、租户、对象、变更和依据，普通详情、发布
  材料及审计使用秘密引用，不暴露凭据原文。来源故障、权限不足、引用阻断和
  真实空清单分别反馈，不用假成功隐藏管理失败。

## 管理操作范围

2026-09-12 用户对 GAP-4 扩展租户管理：增加订阅额度/用量、账单与预算管理，
并要求逐 Agent Step 的金额统计。该专题唯一正文归
[PF-019](PF-019-tenant-subscription-usage-billing-and-budget.md)，本项保留管理范围
和入口关系，避免把持续增长的财务规则全部放进资产管理正文。

以下按对象展开用户所说的 CRUD；它是管理能力清单，不是统一 API 或数据库
模型。未对某种对象成立的操作要说明原因，不能只提供一个看似可编辑的列表。

| 管理对象 | 用户应能完成的操作 | 生效或退出边界 |
|---|---|---|
| 设置与显式覆盖 | 查看可配置项、作用域、当前选择、默认/继承来源和实际值；建立、修改、清除适用覆盖 | 按 PF-006 求值；清除不等于强制设为 false，也不改写官方默认或其它范围 |
| Agent 定义级及资源/动作授权 | 查看目标、能力/动作、对象、范围、条件及有效状态；授予、调整、撤销有权管理的授权 | 使用 PF-006 的定义身份与当前有效规则；一次性批准、持续授权和专属账号/设备同意分别成立 |
| 组织内角色与权限分配 | 查看成员角色和管理资格；超级管理员按组织治理规则调整、收回相应权限 | 操作不能使组织失去最后一位有效的最高管理者；普通角色不自行升权，成员私人资产不因此变成组织资产 |
| 本租户拥有的四类 Agent 定义 | 查询详情/版本/引用，创建和编辑草稿、发布新版本、丢弃无引用义务的未发布草稿、退役已发布定义 | 沿 C6 保留作者、归属和不可变发布；已发布定义不能被无痕硬删除，历史和使用证据保留 |
| 已获权的官方或外部资产 | 查看权利、选用精确版本、调整开放配置、按权利 fork、停用、从当前组合移除或卸载选用关系 | 改外部封闭内容需有派生权及明确 fork；停用/卸载不删除原定义、不自动撤销外部权益、不强停已有 Run |
| 租户使用权益 | 查看来源、签发者、有效范围与暂停/到期/撤销状态；按当前签发或管理资格授予、暂停、恢复或撤销 | 租户管理员不能伪造外部供应方授予的权益；权益、选用及实际运行权限仍是不同事实 |
| 订阅、额度/用量、账单及预算 | 个人用户与组织中获准管理主体查询、管理对应租户范围，追溯每一步 Agent Step 的金额 | 专项规则归 PF-019；订阅权益、供应方实际计费、用户预算和操作权限分别成立 |
| 模型档案 | 查看 official/customized；创建、编辑、删除有权管理的自定义档案，查看变更依据 | 官方原档公开只读；删除后不再可选，既有引用获得可解释处置，不能变成匿名运行失败 |
| Connector 安装及其授权/配置 | 查看连接与供给状态，按安装来源管理配置、暂停、恢复、卸载和范围变更 | 专项语义归 PF-002；组织政策不代替成员外部账号同意，不合并成员私人内容 |
| 知识、经验、报告与文件等信息资产 | 发现并进入相应对象的获准读取及管理入口，明确当前可修改、移除或保留范围 | 沿各自的数据生命周期和引用义务，不一律套用定义的发布/退役，也不将移除入口冒充物理擦除 |

这里的“超级管理员”保留本轮用户明确的角色含义。原系统的最高治理角色叫
`owner`，另有权限较窄的 `admin`；本项目的名称、继任与完整角色/动作矩阵仍
待定义，不能仅按相似名称映射。用户已经明确的组织管理资格不因此被留作未确认。

## 资产范围与 official / customized

以下是本轮已核对的种类及其产品边界。前四行是源已接受的**顶层 Agent 资产**；
后面列出相关组件和其它受治理材料，避免把“资产”误读为只有四种数据对象。

| 种类 | 含义及来源区分 | 组织/个人管理边界 |
|---|---|---|
| Skill | 可独立定义、发布、引用的技能；有官方与自定义来源 | 定义所有权、使用权益及版本选择分别治理；用户手动调用见 PF-009 |
| SlashCommand | 可绑定 Skill/Prompt 等上下文的命令定义；有官方与自定义来源 | 独立顶层资产；不包含键盘控制、shell 或系统命令 |
| Plugin | 组件分发与组合资产；有官方与自定义来源，可包含 tool、skill、service、command、rules、hooks | 内含成员随相应 Plugin 版本和权利治理；独立外部依赖保留自己的身份与权益；自定义可执行贡献按 PF-016 治理 |
| Agent Blueprint / Definition | 智能体静态定义，包括官方 Agent 与 custom Agent | 不是会话或运行实例；引用组件不取得组件所有权；sub-agent 定义仍属这一类 |
| Tool、Service、Middleware 等实现 | 原系统 Tool/Middleware 来源边界偏向官方；用户后续新增 PF-016，允许获准 Cordis 插件提供自定义 tool/service 等能力 | 不自动成为独立顶层资产；开发、部署、装载与使用分别受当前权限约束，不能从可安装推导任意执行权限 |
| Hooks、Rules 等成员 | 可以作为 Plugin 的声明性成员；来源随具体定义及分发材料记录 | 不自动取得独立顶层资产生命周期；自定义可执行扩展的资格与隔离另有设计边界 |
| 模型档案（model profile） | 源最新要求明确 official 与 user customized 同一表形、同一约束，来源可辨 | 官方原档在公开面只读；用户可管理自己的自定义档案。它不是第五类顶层 Agent 资产；组织共享范围仍须专项明确 |
| 知识、经验、报告及附件/文件 | 受治理的信息与工作产物，记录实际来源、作者与归属 | 按各自权限和生命周期管理；不强造 official/customized 二分，知识或文件内容也不自动成为指令或权限 |

2026-09-12 后续新增 [PF-016](../agent/PF-016-agent-developed-cordis-plugins-and-live-deployment.md)
扩展本表的可执行插件来源范围。它是本项目直接要求，不是 omne-next 原有承诺；
历史来源研究仍保留旧事实。Agent 可开发与部署不意味着可改写官方原件或绕过租户权限。

四类定义的共享、使用和编辑权依各自当前依据判定。“官方原档只读”和
[PF-006](PF-006-user-settings-and-agent-definition-authorization.md) 的用户覆盖
出厂默认配置可同时成立：用户改变适用的选择、配置或自定义材料，不等于改写
官方发布原件。这里不预选统一的覆盖算法或资产存储模型。

## 可观察场景

| 场景 | 应有表现 |
|---|---|
| 组织有一项共享 Skill，两个成员的角色权限不同 | 使用同一组织资产与权益依据；是否可编辑、发布或调用按各自权限判定 |
| 用户仅在个人范围获权使用某项资产，随后进入组织会话 | 组织操作不能借用个人权益；需要该组织自己的合法依据 |
| 同一官方 Blueprint 被个人与两个组织选用 | 官方定义 owner 保持可辨，各范围的权益、选择版本和使用权限分别生效 |
| 成员在组织上下文中创作 Plugin，之后离开组织 | 作者事实保留，组织资产不自动变为其个人资产；后续组织操作使用最新成员权限 |
| Agent 有权使用某个 Plugin，却请求一项未被授权的外部动作 | 使用权益不替代动作授权；系统按相应门拒绝或发起合法确认 |
| 用户切到个人租户，创建一个 Skill 草稿并设置某定义的授权 | 两项操作各有结果、归个人范围；发布和选用不被当作授权自动成立 |
| 组织超级管理员调整组织配置与成员权限 | 在该组织范围实际生效且可审计，不修改成员个人设置或取得私人会话读取权 |
| 用户清除自己的某项设置覆盖 | 按该项既有规则重新求值并显示依据；不把清除误解为关闭或固定恢复旧出厂值 |
| 管理者移除被日程或 Agent 引用的资产选用关系 | 说明依赖影响及阻断/处置，不暗中删除日程、替换定义或强停正在运行的会话 |
| 两个管理页面同时修改同一资产草稿 | 后提交的旧修改不覆盖已确认新内容，提供可理解的冲突和恢复结果 |
