# PF-013：Session、Run 生命周期与运行中输入管理

[用户维度](README.md) · [生命周期与排队输入来源核对](../../../research/session-run-and-pending-input-sources.md)

主维度：用户，关注用户如何管理会话、控制一次运行及安排后续输入。副维度：
智能体，关联执行收口、接续、工具处置以及实际进入模型的内容与顺序。

## 已确认要求

2026-09-12 用户明确要求：在此前单次工具调用生命周期控制之外，用户还能够
控制 **Agent Session 的生命周期**及**一次 Session Run/Turn 的生命周期**；
运行过程中可以追加消息、使用 `interrupt_then_run`，并调整排队消息的顺序或
原位编辑。用户授权综合 `omne-next/omne_harness` 的相关信息补充。

以下 C1/C2、C5/C6/C8 包含这些直接要求；具体操作含义及 C3/C4/C7/C9/C10
按[SYS-CONTINUITY](../../system/omne-next-continuity.md)映射原系统已接受的
产品要求和后续有效修订。来源的实现结构与接口不随之采用，也不表示已经交付。

用户同日进一步强调：`interrupt` 与 `interrupt_then_run` 对执行中工具的
级联效用不同，且要区分前台/后台；C4 及其对照表记录此直接补充与来源细化。

| 用户控制的对象 | 本项中的含义 |
|---|---|
| Session | 具有稳定身份、归属和历史的长期会话，跨多次运行存在 |
| 一次 Run/Turn | 会话内某次具体执行及其接续关系；控制需要辨认当时的实际运行，不能只指向一个可能已过期的“当前运行” |
| 排队消息/命令 | 已受理但尚未被取入执行的输入或有序操作，可以有多项等待 |
| 单次工具调用 | 由 [PF-003](../agent/PF-003-tool-execution-observation-and-control.md) 拥有；本项只定义会话/运行控制如何影响它 |

这里保留用户的 Run/Turn 产品表述；来源中的一次 user turn 也可能指一次消息
提交，不能因此推定“一条消息必有一次独立 Run”。C7 明确多条文本合批，精确
术语、执行分段与模型调用轮次的映射留待规格建模。

### 会话与运行控制

- **PF-013.C1：用户能管理自己的长期 Session。** 用户可以为当前租户范围内
  自己可用且就绪的 Agent 创建会话，取得稳定身份，并在目录中查找、命名、
  置顶、归档、恢复和逻辑删除。创建重试不产生重复空会话，手动标题不被后来
  的自动命名覆盖；组织切换、设备切换或运行时重建不改变原会话的用户与租户
  归属。归档后历史可读、停止接纳新消息；恢复重新检查原 Agent 的可用性，
  不换成别的 Agent 或空白会话冒充成功。逻辑删除形成不可恢复、身份不复用的
  终态，不等于物理擦除。存在活动 Run 时，归档或删除明确拒绝，用户先通过
  独立运行控制处理活动工作；它们不隐式中断 Run。生命周期关闭后的未执行
  队列项有可审计终态，不能被恢复过程意外启动。
- **PF-013.C2：用户能控制一次精确运行。** 支持 `interrupt`、`resume` 和
  `cancel`。中断尽快停止目标的当前执行及对应实时输出，保留已提交的部分
  历史和 Session；继续仅作用于匹配的被中断/等待状态，保持同一会话与逻辑
  目标的接续关系，不承诺复活原进程或原 worker。取消使该次工作终结，自动
  重试或故障恢复不能复活它。旧页面、迟到请求或重复点击不能控制后来启动的
  新 Run；显式会话级控制可以在受理时解析当时的运行，但须保留精确目标和
  作用范围。已受理、已施加、拒绝、已结束、目标过期及结果未知分别可辨。
- **PF-013.C3：提供显式紧急停止及后续队列控制。** 当协作中断不能收敛或
  用户需要紧急停止时，具备相应资格的用户可 `force_stop`：撤销目标执行的
  继续执行权，阻止旧执行者继续提交有效结果，并尽力终止系统可控制的执行体、
  清理或隔离资源。逻辑停止、物理停止、清理及外部效果未知分别反馈，不能
  宣称外部效果已经撤销。对单次 Run 的强停须等停止结果安全确定后再继续
  队列；用户显式选择整个 Session 的紧急停止时，尚未开始的输入进入可见的
  hold 状态，不能立即自动启动下一轮。用户可显式继续队列或逐项/批量撤回；
  队列 hold 不等同于冻结并保存一个仍在执行的进程。
- **PF-013.C4：运行控制的传播范围与工具处置明确。** 普通 Run 中断/取消
  默认覆盖该 Run 自己发起且尚未结算的工具执行，包括已经转到系统后台的
  调用；中断结果逐次可见，不留下声称 Run 已收口而工具无结局的悬空状态。
  `interrupt_then_run` 则按下表保留可继续的后台工作。工具已被明确中断后，
  继续会话不自动恢复或重试该次调用；Agent 后续重新调用是新的决定。对
  sub-agent，取消默认沿结构化后代传播；显式脱离的被委派后代和 `handoff`
  按 [PF-004](../agent/PF-004-subagent-delegation-and-supervision.md) 的关系与
  人类监督规则处理，不从“后台”二字把它们和本 Run 自己的工具混成同一对象。
  普通 Run 控制不能暗中扩大成整个 Session 的紧急停止。

| 本 Run 未完成工具的状态 | `interrupt`（中断 Run） | `interrupt_then_run` |
|---|---|---|
| 前台，符合有效后台声明 | 中断并留下真实结局 | 转后台继续；切换失败则中断 |
| 前台，不可转后台 | 中断并留下真实结局 | 中断并留下真实结局 |
| 已在系统后台运行 | 同样中断并留下真实结局 | 保持后台执行 |

仅停止一件工具仍按 PF-003 精确控制该次调用，不因此停止整个 Run 或其它调用。

运行时自身被重建与用户明确中断 Run 是不同原因；C4 不削弱 PF-003 关于运行时
重建后重新关联仍在后台执行的调用的要求。机器工作转后台也不能伪造 HITL 答复
或绕过尚需用户批准的动作。

### 运行中的追加消息与待执行队列

- **PF-013.C5：忙碌时仍可追加消息并选择到达行为。** 用户在自己的 Session
  正在执行时仍可提交输入，选择 `queue` 或 `interrupt_then_run`。系统默认
  `queue`，允许保存用户默认值，并允许本次发送显式覆盖；实际采用值可见，
  用户默认跨获准客户端一致，读取失败不能随机打断当前工作。`queue` 保持
  当前 Run 继续，新消息耐久等待；追加普通文本不是把内容无损注入正在进行
  的 LLM/tool call。明确回答某个 HITL 请求仍走其专用答复关联，普通补充说明
  则遵循本项的到达和排队规则。等待不是等到 Run 结束：当前 Run 不再等待模型
  响应而又未完成时（这一步已收束，在等工具结果、人类答复或门），队列里的
  用户普通文本应被自动消费、进入该 Run 的下一步，不能干等；命令与非用户
  触发项仍按各自的排队规则处理（2026-09-15 用户补充，见[变更记录](#变更记录)）。
- **PF-013.C6：打断后处理是一份可恢复的整体意图。** `interrupt_then_run`
  同时关联新消息、用户当时观察到的精确 Run 及打断结果。旧工作安全收口后，
  新消息与其它合格的排队文本按当前队列顺序处理，不自动获得独立的紧急通道
  或越序权。如果旧 Run 已自然结束，正常处理队列；如果已换成新 Run，不打断
  新运行，新消息保持待处理，并明确说明目标变化。不能在“旧工作已停但消息
  丢失”或“消息已收下但是否打断未知”时报告完整成功。同次意图重试仍认回
  原消息、目标与结果，不能连锁打断后来运行，也不能恢复后续编辑前的旧文本
  或推翻用户已确认的顺序。
- **PF-013.C7：已受理输入耐久、有界、保序并可合批。** 只有输入内容、稳定
  身份及待处理状态可靠保存后才确认受理；容量满时明确拒绝，不能丢弃或覆盖
  已受理项。单个 Session 同时最多一个活动 Run；待执行文本初始按系统确认
  的受理顺序排列，用户调序后按已确认的当前顺序消费，客户端时间不决定先后。
  队首连续且合格的文本一起进入一次执行，遇到命令则以它分隔；每条消息仍有
  独立身份与内容边界，可关联共同结果，不用摘要改写原文来冒充合批。取批后
  固定成员和内容，之后到达的输入留待下一次，重试不重复执行或扩大批次。
  激活前重新检查当前权限与目标可用性，失效明确阻塞/拒绝，不能换目标或暗中
  删掉不合格成员。尚未取批、已撤回或已清除内容不能通过历史、摘要或恢复
  提前进入模型；已受理事实的耐久保证不冒充未发送草稿或未受理输入的离线续办。
- **PF-013.C8：用户能查看、调序、原位编辑和移除排队项。** 当前队列可展示
  每项内容、相对位置、状态及可用管理操作；用户可调整尚未取批的文本和有序
  命令的位置，原位编辑待发消息，或单独移除某项。编辑明确支持待发送文本，
  附件/多模态内容及命令参数的具体编辑范围结合 PF-009 继续细化。确认后的
  修改改变实际模型输入及执行顺序，保留消息身份、原始受理和修改的可追溯关系，
  不只是本地界面变化。已经取批或运行的内容不能追溯改写，应明确反馈并指向
  相应 Run 控制。编辑、调序、移除与取批或另一设备修改竞争时，结果统一裁决；
  旧视图不覆盖新修改，迟到操作不让已取走项重新入队。队列移除不等同于数据
  物理擦除，也不连带取消其它独立项。
- **PF-013.C9：命令与文本按可见、可调整的安排协作。** 命令定义可以声明
  默认入队位置、是否让已有/后到文本先执行，以及保留或清除等待文本的动作；
  用户确认的后续调序决定实际顺序，不被原默认安排永久锁住。队列项各自独立，
  系统不猜测业务关系或自动建立跨项成功依赖；已经安全结束的失败项不无限
  阻塞下一独立项，效果未知或会话 hold 则不能冒充可继续。清除动作只影响该次
  受理时范围内仍等待的文本，重试不扩大到后来输入。停止/清除等忙时控制可
  及时进入裁决，不排在自己要控制的工作后面；自动安排也不能因持续新输入
  让命令无限等候。按钮、keyboard 和 slash 入口消费同一已定义操作的语义与
  当前权限，客户端不能自行制造命令效果。

### 状态、权限与跨端一致性

- **PF-013.C10：用户可以从获准客户端观察并恢复同一事实。** 当前 Run、
  控制请求及真实结果、待处理/held/运行/终态、确认后的内容与顺序、批次成员
  及相应结果均可辨。健康连接中的入队、编辑、调序、移除和取批变化不需等待
  Run 结束或手动刷新；断线、刷新或运行时重建后恢复到同一已确认事实，不能
  复活被移除的输入或重复施加控制。临时流式进度与耐久历史分别表达，不承诺
  每个临时 token 都可重放。每个访问和控制入口继续检查租户、用户和精确对象
  权限；同租户管理员只有明确获准的运行/紧急控制资格才可介入并记录依据，
  不能因此取得私人 Session 的读取、命名或删除权，技术运行访问也不变成用户
  管理权。权限设置变化不自动终止已经开始的调用，需停止时使用显式控制。

- **PF-013.C11：用户能过滤检索获准会话并管理自主工作。** 2026-09-12
  用户对 GAP-3 明确：由会话生命周期管理、会话过滤检索和面向用户的日程管理
  组合承载。用户能按发起者及来源关系筛选会话，至少区分用户发起与其他 Agent
  发起，并能结合状态、时间、所属 Agent 及关联日程定位工作。发起者与会话
  owner/租户分别表达；用户有权管理的 Agent 发起会话不能只因不是根聊天会话
  就不可发现。筛选结果沿 C1–C10 的相应控制处理，未来安排沿 PF-011 管理。
  过滤不扩大访问权，终止一次运行也不暗中停用产生后续运行的日程；复合入口
  分别报告各项真实结果，不新增未经定义的“全局暂停一切”的独立语义。

Agent 在会话内主动检索其他会话及后台通信的能力，另归
[PF-017](../agent/PF-017-cross-session-history-and-background-coordination.md)；
同一 Session 选择合法模型继续下一轮，另归
[PF-023](PF-023-session-model-selection-and-continuity.md)。上述补充扩展可发现的
会话范围，不把原来源限定根 `user_chat` 的目录范围当作本项目新增过滤要求的上限。

## 可观察场景

| 场景 | 应有表现 |
|---|---|
| 用户在一次长运行中连续排队甲、乙、丙 | 当前工作继续，用户立即看见三项；下一消费点按当前确认顺序合批，并保留三条消息身份 |
| 用户修改乙，并把丙拖到甲之前 | 未取批时确认修改，后续使用丙、甲、修改后的乙；另一窗口和刷新后取得同一结果 |
| 用户点“打断后处理”时旧运行已结束，新运行刚启动 | 新运行不被误停，追加消息仍被保存，并解释原目标已经变化 |
| 同一 Run 有前台工具与已在后台的工具，用户选择中断 Run | 两侧尚未完成的调用都纳入停止；中断与工具失败、外部效果未知分别反馈 |
| 用户选择 `interrupt_then_run`，其中一件工具支持后台 | 该工具可转后台继续，已经在后台的工具保留；新输入仍按统一队列处理 |
| 删除一条排队消息的同时，系统已经取走它 | 不显示虚假删除成功、不改写执行中内容，返回实际状态和相应控制入口 |
| 用户强停整个会话后仍有待执行消息 | 显示 held，等待用户继续或撤回，不马上开始下一轮 |
| 用户对忙碌会话点归档或删除 | 明确拒绝，先处理活动 Run；不能悄悄把目录操作变成运行中断 |
| 请求结果未知后重试，或用户刷新页面 | 找回同一消息、控制及队列结果，不重复提交或恢复旧顺序 |

## 关联与待设计事项

[PF-003](../agent/PF-003-tool-execution-observation-and-control.md) 拥有单次工具
观察、控制和后台接续；[PF-004](../agent/PF-004-subagent-delegation-and-supervision.md)
拥有子智能体关系与人类监督。本项普通聊天的输入管理不自动赋予对子智能体的
消息注入或改写权。[PF-009](PF-009-multimodal-input-attachments-and-commands.md)
拥有输入形态与命令入口，本项拥有它们进入忙碌会话后的运行和队列效果。
[PF-006](PF-006-user-settings-and-agent-definition-authorization.md) 的用户设置
与 [PF-001](PF-001-tenant-organization-context.md) 的组织效用继续适用；
[PF-005](../agent/PF-005-agent-initiated-human-input-and-approval.md) /
[PF-008](PF-008-unified-decision-pool.md) 的准确答复关系不能被普通追加消息替代。
恢复能力消费 [SYS-RUNTIME-CONTINUITY](../../system/runtime-state-and-continuity.md)，
已明确取消的工作不能按普通运行时丢失自动恢复。

待设计：精确术语与状态模型、控制资格及传播范围表示、停止收口和不确定效果
处理、输入/命令身份与批次、编辑冲突和界面、容量与延迟目标、跨端恢复协议，
以及多模态待发内容的编辑规则。原系统的通用耐久 `pause/resume`、用户主动
`retry` 和 `interrupt response` 尚无已接受的完整产品语义，不能从笼统的
“生命周期控制”或旧实现符号直接补成确定动作；本轮保留为待细化范围，来源
差异见[核对记录](../../../research/session-run-and-pending-input-sources.md#来源差异与采用边界)。

[当前候选](../../../proposals/agent-core/README.md#当前需求对应与缺口)尚未覆盖
本项完整要求。本轮不选择 State/Runtime 分工、冻结或持久化框架、队列、控制
协议与投递机制，也不接受源部署绑定或旧兼容接口；没有已接受业务设计或规格
需因此取代，历史需求基线保持原范围。
