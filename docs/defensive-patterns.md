# 防御性研发模式

本页是当前有效防御指导的**唯一**入口：正文、稳定编号、适用范围与复核触发都在这里。
它参考 [DeepSeek Harness 的 defensive patterns](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/defensive-patterns.md)，
但只描述 `omne-harness-lite` 的边界。具体领域保证的权威来源是所属规格和接受决定；
本页不另建一套系统语义。

## 保证、指导与模型辅助

租户隔离、授权、身份、已承诺提交和取消语义等**系统保证**不能因模型升级或提示精简而撤销。
下面的条目是帮助设计、实现和审阅发现风险的**指导**；其中固定步骤、重复提醒和检查清单等
针对模型弱点的**辅助**，可以在明确模型、任务、工具和 prompt 范围内保留、简化或退出。

**切换开发主力模型前要评估有关辅助。**[开发模型评估](../.meta_harness/agents/evaluation/developer-model/README.md)
给出离线协议与固定任务集；它不评估产品 runtime agent，也不自动授权模型采用。
本页同时拥有这些条目的来源、适用范围与复核/退出规则——**不在别处再维护一份**。

模型升级、工具或 prompt 变化、失败复发、边界变更和明显成本负担都会触发复核。
**没有新观察不能仅为重辩而推翻已接受决定。**

## 这些条目从哪来

来自[迁移前的防御文档](../.meta_harness/agents/research/project-baseline/defensive-patterns-before-migration.md.txt)
及其参考资料，并结合[框架治理研究](../.meta_harness/agents/research/framework-governance/README.md)重新限定了语义。

DP 编号供开发模型评估精确说明在比较哪一条提醒。

## 当前指导

### DP-01 独立事实分别报告

超时、取消、信号、退出码、部分输出和错误原因是不同事实。调用方不能把被截断的运行误判为成功。

**适用与限制**：执行结果与外部进程；简单返回值不因此强制引入通用结果框架。
**复核触发**：新结果协议、误报成功。

### DP-02 公共契约两端一致

入口接受多种表示时，归一化为明确的内部结果；出口公开稳定的错误、完成和取消语义。
适配器、middleware 和消费者的错误边界应可区分。

**适用与限制**：适配与公开 API；不要求纯内部函数模拟公共协议。
**复核触发**：边界或适配层变化。

### DP-03 异步状态不可混同

已提交、运行、空闲、完成和结果可归属不是同一状态。后台任务、排队消息、转向和取消
可跨多个 turn；等待和结果归属必须有明确观察范围。

**适用与限制**：长期/异步工作；同步操作无需机械扩充状态机。
**复核触发**：新调度、排队或恢复机制。

### DP-04 释放以可观察终态为准

abort、kill 或 unregister 只是停止请求。释放契约必须说明返回时哪些子任务、监听器、
定时器、文件和服务已经停止，或进入何种可证明终态；**先关闭新入口，再处理运行中工作**。

**适用与限制**：拥有存活任务或资源的对象；终态依契约确定。
**复核触发**：资源泄漏、取消实现变化。

### DP-05 回调故障有边界地隔离

面向独立观察者的 listener、hook 或 disposer 可视为不可信边界：其失败不能静默吞掉，
也不应使调度器无说明地跳过后续观察者、留下半清理状态或假成功。
**但校验、授权和命令回调可能按其契约必须失败**——「捕获后继续」不是所有回调的通用规则。

**适用与限制**：独立观察者；授权/校验失败不可按「捕获继续」处理。
**复核触发**：hook/listener 契约变化。

### DP-06 所有权必须可追踪

每个注册、监听、任务、effect、临时资源和外部句柄都应能说明创建者、释放责任和失效时机。
无法归属的资源不能进入动态内核的长期状态。

**适用与限制**：effect、注册、任务、句柄；普通不可变数据不需专门生命周期对象。
**复核触发**：热替换或所有权转移。

### DP-07 外部输出不声称普遍可逆

网络发送、模型调用、已提交写入和单调分配**不因拥有 disposer 而自动可回滚**。
采用 withholding、幂等键、补偿协议或明确的不可逆边界，恢复语义必须反映真实世界。

**适用与限制**：外部可见写入/发送；纯局部逆操作按自身契约处理。
**复核触发**：外部协议、幂等/补偿变化。

### DP-08 不把环境交给不可信执行

子进程、插件和工具只获得明确授权的环境变量、凭据、目录和能力。临时文件使用私有目录、
不可预测名称和严格权限；**动态加载不是安全边界**。

**适用与限制**：子进程、插件与工具；不能从目录或动态装载推导安全隔离。
**复核触发**：新执行环境、权限改变。

### DP-09 失败阻止假状态提交

组合、重载和依赖刷新只能提交完整的新状态，或按契约报告失败。旧实例是否仍可用、
是否能恢复旧配置、是否必须停止服务，取决于已结束资源和外部输出等具体事实；
**不能普遍承诺旧运行态可恢复**。

**适用与限制**：重载、替换、刷新；不承诺已释放旧实例自动复活。
**复核触发**：提交边界或恢复条件变化。

### DP-10 规格、实现与证据对齐

测试只说明所覆盖的性质，模型检查只说明给定边界和假设。三者任一改变后，
旧证据不能无条件声明新行为仍成立。

**适用与限制**：设计和行为变更；不要求文字修正重跑无关模型。
**复核触发**：规格、模型、实现或假设变化。

## 复核与退出

模型或工具升级、样本中的失败复发、提示冲突、明显执行负担都是共同的复核触发。
每次具体评估把 **DP 编号、所用文本版本/哈希、实际注入位置与未覆盖任务范围**一起记录。

新增故障应补证据；退出应附限定范围的采用决定和替代机制，退出内容从当前路由撤下，
其原始证据仍可沿历史记录回查。**现阶段没有退出记录，也没有真实模型对照结果。**

需要稳定引用某条指导、解释其适用性或保存复核依据时，在本页维护——
证据应针对具体条目和适用范围，**一次没有出错不足以认定提醒可以移除**。
新事实研究按 [research](../.meta_harness/research/README.md) 准入；开发模型的对照实验归
[evaluation](../.meta_harness/agents/evaluation/developer-model/README.md)；
产品不变量的变化回到规格及其决定，**不由提醒的保留或退出代选**。
