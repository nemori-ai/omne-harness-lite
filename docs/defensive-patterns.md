# 防御性研发模式

本页是当前有效防御指导的稳定入口。它参考 [DeepSeek Harness 的 defensive
patterns](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/defensive-patterns.md)，
但只描述 `omne-harness-lite` 的边界。具体领域保证的权威来源是所属规格和接受
决定；本页不另建一套系统语义。

## 保证、指导与模型辅助

租户隔离、授权、身份、已承诺提交和取消语义等**系统保证**不能因模型升级或
提示精简而撤销。下面的条目是帮助设计、实现和审阅发现风险的指导；其中固定
步骤、重复提醒和检查清单等针对模型弱点的**辅助**，可以在明确模型、任务、
工具和 prompt 范围内保留、简化或退出。

[D-003](decisions/D-003-defensive-evaluation.md) 要求切换开发主力模型前评估
有关辅助。[开发模型评估](evaluation/README.md) 给出离线协议与固定任务集；
它不评估产品 runtime agent，也不自动授权模型采用。模式的来源、适用范围、
复核和退出记录由[防御演化维护规则](maintenance/defensive-evolution.md)管理。
模型升级、工具或 prompt 变化、失败复发、边界变更和明显成本负担都会触发复
核。没有新观察不能仅为重辩而推翻已接受决定。

每条指导的稳定身份、来源、适用限制与复核触发见[适用记录](defensive-patterns/catalog.md)。

## 当前指导

### 独立事实分别报告

超时、取消、信号、退出码、部分输出和错误原因是不同事实。调用方不能把被截
断的运行误判为成功。

### 公共契约两端一致

入口接受多种表示时，归一化为明确的内部结果；出口公开稳定的错误、完成和取
消语义。适配器、middleware 和消费者的错误边界应可区分。

### 异步状态不可混同

已提交、运行、空闲、完成和结果可归属不是同一状态。后台任务、排队消息、转
向和取消可跨多个 turn；等待和结果归属必须有明确观察范围。

### 释放以可观察终态为准

abort、kill 或 unregister 只是停止请求。释放契约必须说明返回时哪些子任务、
监听器、定时器、文件和服务已经停止，或进入何种可证明终态；先关闭新入口，
再处理运行中工作。

### 回调故障有边界地隔离

面向独立观察者的 listener、hook 或 disposer 可视为不可信边界：其失败不能
静默吞掉，也不应使调度器无说明地跳过后续观察者、留下半清理状态或假成功。
但校验、授权和命令回调可能按其契约必须失败；“捕获后继续”不是所有回调的
通用规则。

### 所有权必须可追踪

每个注册、监听、任务、effect、临时资源和外部句柄都应能说明创建者、释放责
任和失效时机。无法归属的资源不能进入动态内核的长期状态。

### 外部输出不声称普遍可逆

网络发送、模型调用、已提交写入和单调分配不因拥有 disposer 而自动可回滚。
采用 withholding、幂等键、补偿协议或明确的不可逆边界，恢复语义必须反映真
实世界。

### 不把环境交给不可信执行

子进程、插件和工具只获得明确授权的环境变量、凭据、目录和能力。临时文件使
用私有目录、不可预测名称和严格权限；动态加载不是安全边界。

### 失败阻止假状态提交

组合、重载和依赖刷新只能提交完整的新状态，或按契约报告失败。旧实例是否仍
可用、是否能恢复旧配置、是否必须停止服务，取决于已结束资源和外部输出等具
体事实；不能普遍承诺旧运行态可恢复。

### 规格、实现与证据对齐

测试只说明所覆盖的性质，模型检查只说明给定边界和假设。三者任一改变后，旧
证据不能无条件声明新行为仍成立。
