# D-008：接受本批核心能力与共同准入契约

接受[核心能力提案](../proposals/core-capabilities/README.md)的本轮有限范围，
精确对象从 [catalog](../../spec/catalog.json) 中以本决定为接受依据的 13 个
新 v1 查找。数据、各能力状态和跨能力协调分别拥有规范；既有 D-005/D-007
及其冻结版本继续有效。来源选择和排除项仍按 D-006。

工具的声明解析结果与可调用贡献共同发布，实际调用按当前 tenant、定义、
精确绑定、授权、确认模式及预算判定；系统 ask 形成耐久请求与等待，不依赖
Agent 主动申请。合法一次批准仅覆盖冻结 Action，执行前重检并唯一消费。
普通撤权影响后续准入，精确取消与强停另外封闭执行；受理、耐久、开始、
物理停止、清理及外部未知分别可见。

首版使用有明确范围的共同有序提交域。短提交中的位置分配为逻辑准入点，
受控效果必须等到耐久确认；不持运行时短锁等待 I/O，也不把多个独立写入
冒充原子提交。跨域后果按耐久意图、目标去重及回执交接，不承诺外部效果
恰好一次。此选择保留能力的独立所有权，未来拆分部署须兑现等价协议。

Run 与 continuation 分开，独立问题可分别接续；队列输入、命令领取、复合
打断和强停各有精确目标及恢复出口。模型请求、媒体原件、暂行产物、预算
暴露与供应方账务各自保留事实权威，全部模型请求统一 OpenRouter；具体
adapter 采用项目自有标准 HTTP/SSE 映射，未接受直连或静默模态降级。

这些选择使当前声明、授权、耐久工作和效果边界能够组合。代价是协调提供者、
执行器停止屏障和结果核实必须实际合作，不能仅凭 UI、内存 Promise 或上游
注册机制兑现保证。具体取舍及边界见提案，旧 tenant/model/tool 草案保留来源
身份，不成为本决定的规范依赖。

需求消费为 `dae2df36491c0ab4b8b9a3d16db639dab5ea88b0` 加本次用户明确的
声明登记／系统审批要求，确认条款、路径和可恢复提交由
[消费记录](../proposals/core-capabilities/requirements.md)拥有。
[评审记录](../proposals/core-capabilities/review.md)说明实际发现和处置。

本决定接受目标设计及有限验证工件，不接受全部产品功能已实现。真实提供者
验收、应用 UI、支付执行、具体环境工具、Connector/日程/委托等相邻完整
能力仍按各自范围继续；可按用户追加授权及已接受 D-006 进入定向源码 fork。
fork 起点、目标实现验收和 main 合并仍是不同交付状态。
