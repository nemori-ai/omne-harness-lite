# 日程与Job

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

日程维护Schedule及内含工作描述、候选处置和Job的接受、固定要求、等待/取消与整体结果。它组合日历、执行及通知，不拥有各方原事实。

Job不等于Run，需要agent的执行部分才进入专属作业会话。机械Job、纯通知及系统自用工作不强制Session，工作描述也不自动成为独立资产。

## 模块角色与事实归属

| 模块角色 | 事实与责任 |
| --- | --- |
| 安排与候选 | Schedule、工作描述、当前候选及适用条件 |
| Job接受 | 本次业务身份、固定要求及日历/来源依据 |
| 工作治理 | 等待、启动、取消及未完成责任 |
| 执行组合 | 选择机械/会话等合法路径并承接原结果 |
| 交付组合 | 请求通知并依据各部分判整体完成 |

Job先于作业Session存在，Job 的治理拥有者保存其工作事实，不依赖某个 runtime 持续存活。

## 协作与依赖

消费[日历](../calendars/README.md)版本计算，按业务规则校验并接受候选；实际动作消费工具/机械能力，需要agent的部分使用会话。

业务归属、发起者和通知接收方分开，系统工作不借特殊租户或任意读取私有内容。[通知](../notifications/README.md)确认送达，日程按本次要求判整体成功，Run终态不直接替代Job结果。

## 主路径与交接

1. 根据安排和有效日历依据生成、校验候选。
2. 接受Job时固定本次要求及依据，记录等待或取消责任。
3. 满足当前资格与执行条件后启动允许路径，承接原执行事实。
4. 按本次要求完成通知或其他部分，分别记录结果并判断Job整体终局。

开始前取消成立后不能再启动。执行已完成但通知未达时只恢复交付，不重做动作；日历或配置更新不改已接受要求。

## 契约与验证导航

Schedule/Job契约拥有接受、固定要求、取消及成功含义，日程协调者拥有候选到执行/通知的可靠交接；执行和送达契约由参与方维护。

上层沿[总体业务结构](../../architecture/structure.md)、[结果承接](../../architecture/structure.md#执行事实与结果承接)、[控制恢复](../../architecture/runtime/control-and-recovery.md)。产品依据[产品正文](../../../.meta_harness/design/product/schedules-and-jobs/design.md)，组合核对见[验证](../verification.md)。

## 后续设计与维护

到期认领、候选校验/接受同提交、启动/取消竞争、灾后对账及跨节点调度由日程协调者细化。精确通知对象和投递协议待原拥有者设计，不能以此取消整体结果分责。

局部安排计算沿日历/日程契约；影响实际执行、资格或送达时展开参与方。新工作描述语义待定只停对应路径，不默认一切Job经过Agent。
