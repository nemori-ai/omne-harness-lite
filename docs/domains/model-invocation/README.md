# 模型调用

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

本责任承接模型定义/能力及一次请求的实际执行、原输出、收场、费用和结果保管。模型选择、请求输入计算与执行各有角色，不把它们塞进Session或Agent的内存。

模型不会执行回复中的工具建议。独立调用可以没有Session，调用应用仍承担消费、治理和适用授权。已封闭内容块消费 `packages/common/content-block`。流式步骤消费 `packages/common/stream-arrival`。费用正文仍归本责任。会话在收到流式增量或流完成时记下这笔账。应付金额的取法在调用账目词条里。token 用量的词法在下一句。

token 类别名归本责任。`input` 是类别名的例子。token 用量的 `lexeme` 是整数。带小数位的词法拒绝，拒绝码是 `precision`。

## 模块角色与事实归属

| 模块角色 | 拥有的事实 |
| --- | --- |
| 模型档案/能力 | 可用模态、参数和约束的公开依据 |
| 请求发起适配 | 接受已固定输入与调用身份，明确实际发出 |
| 原调用执行 | 在途状态、原输出、收场和真实尝试 |
| 结果保管/结算 | 待承接内容、费用及清理条件 |
| 实际消费者 | 可靠取得、业务采用和原处理位置，归调用方 |

提供者隐藏传输机制，跨提供者的共享含义由原能力契约维护，不能各自重定义成功。交给会话日志的事实见[模型规格](../../../packages/model/model/SPEC.md#调用和各次真实发出)。

## 协作与依赖

消费[请求组装](../runtime-context/README.md)固定的输入及模型条件，通过公开接口返回原结果。Agent等待不获得生命周期所有权，换代后可按原身份接回。

流式首内容、请求收场、持久保管、ACK和业务采用分别判断。请求参数/模型变化只作用于相应后续请求，不修改原调用。

## 主路径与交接

1. 发起方固定实际模型、参数、内容及声明，创建可追溯调用。
2. 提供者真实发出，保存原输出及收场/费用事实。
3. 需可靠消费的路径先保管内容或可恢复引用，交实际消费者承接。
4. 按模型ACK及保留契约清理，业务继续与否由消费者决定。

查询不可用保持未知，不能凭超时重发。确认自身连续性丢失时按首内容前后规则处理；模型ACK后消费方不能再依赖生产侧完整副本恢复。

## 契约与验证导航

模型公开契约拥有调用、首内容/重试、取消、ACK和保管义务；提供者维护传输与实际结算差异；发起/消费协调者拥有可靠采用关系。精确错误、幂等及同提交随成员维护。

上层沿[模型runtime](../../architecture/runtime/model-runtime.md)、[流式与消费](../../architecture/runtime/streaming-and-consumption.md)、[控制恢复](../../architecture/runtime/control-and-recovery.md)。产品依据[产品正文](../../../.meta_harness/design/product/model-invocation/design.md)，验证见[组合入口](../verification.md)。

## 后续设计与维护

原输出保留窗口、在途内容分段与确认、费用结算、跨进程句柄和可靠消费机制由模型/存储/消费者设计。保留范围未定不会取消可靠承接义务。凭据引用与发送时解析已由 D-04 接受，见[角色与交接](architecture.md#凭据引用与保管)。该节不改写上文的模块角色表。

仅改模型提供者沿共享契约，涉及消费/换代才展开工作和装配。API、平台和通道选择由实际需求决定，本页不规定唯一模型服务。
