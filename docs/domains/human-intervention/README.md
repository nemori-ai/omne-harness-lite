# 人在回路

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

HITL关联原决策请求、面向获准人的呈现和答复，既支持授权决定，也支持信息或方案选择。它不拥有原业务终态，不要求Agent仍在运行才能交回。

[身份/准入](../identity-and-authorization/README.md)解释授权，[原工作](../sessions-and-work/README.md)或工具/扩展拥有等待与后续推进。

## 模块角色与事实归属

| 模块角色 | 拥有的责任 |
| --- | --- |
| 原请求发起方 | 问题含义、原操作/参数和等待位置 |
| 请求保管/关联 | 决策卡片、关联、有效状态及可恢复依据 |
| 呈现/答复接口 | 向当前有资格的人展示并提交答复 |
| 答复交接 | 将有效决定关联回原请求，不生成独立批准副本 |
| 原继续执行者 | 解释答复、核验资格并决定继续或终结 |

卡片显示不是准入事实，多个界面共享同一决定。

## 协作与依赖

呈现不暴露无权读取的原内容，答复者须有当前资格。同一卡片只有一个有效决定，参数变化和已经终局的工作按原规则处理。

答复可以发生在Agent退出、恢复或换代期间。授权、环境和业务前提仍各自核验，普通批准不能解除沙箱要求或明确禁止。

## 主路径与交接

1. 原拥有者创建关联明确的决策请求，保留问题、参数与等待位置。
2. HITL向获准的人呈现，答复接口核验当前卡片及决定资格。
3. 有效答复可靠交回原请求，由原拥有者解释并处理继续条件。
4. 迟到、重复或失效答复按原状态处理，不重开终局工作。

超时不默认批准；失去读取资格不免除合法保管与交接责任。人的决定不证明工具已经执行或外部效果可撤回。

## 契约与验证导航

HITL契约拥有关联、呈现、答复及有效性，原等待/准入契约拥有答复含义和继续条件。精确持久等待、一次有效决定与提交关系随实际协调者维护。

## 后续设计与维护

等待认领、卡片/答复提交、跨进程交接和失效竞态由HITL、原工作或工具/扩展协调者设计。界面可独立替换，但不能创建第二份决定权威。

呈现维护读本契约；新授权或恢复含义再展开原拥有者。必要语义未定只阻塞相应决定路径，不替人补答。
