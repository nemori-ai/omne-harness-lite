# 人在回路协作设计候选

本页保存尚待技术采用的设计，不表示实现、产品接受或阶段承诺。完整必要行为见[human-intervention/human-intervention SPEC](../../../packages/human-intervention/human-intervention/SPEC.md)，产品范围见[产品正文](../../../.meta_harness/design/product/human-intervention/design.md)。

## 责任边界与事实拥有者

| 逻辑角色 | 拥有的事实与责任 | 消费边界 |
|---|---|---|
| 原请求发起方 | 问题含义、原动作/生效参数、来源及等待位置 | Tool 的 Ask/内部等待或 Run 的具体拓展件；不由卡片猜业务 |
| 请求保管与关联 | 卡片身份、原请求关联、原内容与有效状态的可恢复依据 | 多处呈现共享关联；池子不是第二存储权威 |
| 呈现/答复接口 | 获准披露、答复者当前资格、本次提交身份及真实回执 | 卡片内容与一般聊天分流；显示不授准入 |
| 原等待协调者 | 一次有效答复的权威、批次/消费位置、答复和等待一致关系 | 原 Tool 或 Run/拓展协调者判断继续或失效 |
| 授权与设置拥有者 | 授权含义、允许范围、配值资格、已成立表达或权限事实 | HITL 不另算完整权限，不凭答卡改无权设置 |
| 原继续执行者 | 当前前提、有效执行者、原位置继续及业务终态 | 重新核验参数/实现/依据和环境；不授新工作无限许可 |
| 交付面及通知提供者 | 各自呈现、允许提示、通知保管/送达事实 | 不代答、不将已读作为决定或再执行源动作 |

有效答复由原等待协调者在自己的边界写入。它核对答复所带租户与原请求的租户相同，不同则拒绝，跨租户默认拒绝。角色表达逻辑分工，不要求每角色一服务、线程或表。卡片保管与原等待分开实现时仍由具名原等待协调者维护唯一有效决定。共享数据库不自动提供共同提交；内核作用域、disposer 或事件通知也不提供这一保证。
