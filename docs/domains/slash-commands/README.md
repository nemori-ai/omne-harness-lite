# Slash Command

## 范围与边界

本责任维护一个会话此刻能用名字点名什么，以及一段人打的字里哪些斜杠点了名、点中之后交出什么：入口项的种类与位置、名字、识别规则、清单的合成、发送方所见的比对与展开。入口项的事实归交出它的来源：Skill 归 [Skill](../skills/README.md)，提示词命令的持有归[资产](../assets-and-rules/README.md)，系统命令真正做的事归各操作的拥有者。输入到达、待处理、日志与 Run 的承接归[会话与工作](../sessions-and-work/README.md)。

按键、命令面板与按钮是同一条命令的别的触发：客户端外壳的动作表与键位归[共用界面的规格](../../../packages/frontend/SPEC.md#动作与键位)，桌面上的缺省键归[桌面应用](../../../apps/desktop/SPEC.md)，人改过的键存在身份的账号偏好里。shell 命令与模型能调的工具不经斜杠命令。

## 模块角色与事实归属

| 模块角色 | 拥有的决定 |
| --- | --- |
| 识别与匹配 | 一处斜杠是不是候选、按清单绑到什么；补全的候选与采用；客户端、命令行与受理侧共用的一个纯函数 |
| 清单 | 向各入口来源现问，合成一个会话此刻的清单；哪一部分取不到 |
| 解析器 | 受理时按当下的清单再认、比对发送方所见、取内容并展开，答输入、操作请求或拒收 |
| 入口来源 | 各来源自己的项：Skill 的、提示词命令的、系统命令的；命令领域不认识它们是谁 |
| 对外 | 读清单的协议与「可能变了」的观察；输入框助手；「命令与快捷键」页 |

## 协作与依赖

清单是视图：命令领域不存任何来源的事实，每次读都向各来源现问。Skill 装上、卸下、换版、撤权只改 Skill 背后的事实，下一次读就是新的，命令领域不用做任何事。通知只说「可能变了」，用来让人的菜单早一点更新；受理侧从不读客户端的清单，所以通知丢了也不影响对错。

客户端带上它看到的（发送方所见），服务端按当下再认，对不上整条拒收。点了名不放宽 Skill 的读取权，不运行脚本。

## 主路径与交接

1. 交付面拿清单，按同一个识别函数认出命令与引用，给菜单与标记。
2. 发出时带发送方所见。会话受理到解析一步，交给解析器。
3. 解析器按当下的清单再认：开头不能用的命令被拒；所见对不上被拒收。
4. 引用：每份 Skill 的正文各成一块文字块，带来路标记，人的话原样一块；提示词命令：展开成人的消息；系统命令：答一个操作请求，会话用自己的操作去做。
5. 解析器的生效内容是受理前处理的起点；原内容、生效内容与绑定依据在同一次受理提交里成立。之后那一项改了、卸了，不改历史。
