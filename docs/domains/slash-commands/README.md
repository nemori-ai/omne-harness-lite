# Slash Command

## 范围与边界

本责任维护Slash Command的名字、绑定、参数、会话命令集与识别/展开规则。提示词、Skill和系统工作流是不同绑定，键盘控制和shell命令分别归交互及环境机制。

命令的共同持有/来源归assets；输入到达、队列、日志及Run承接归[会话与工作](../sessions-and-work/README.md)。

## 模块角色与事实归属

| 模块角色 | 拥有的决定 |
| --- | --- |
| 命令定义 | 名称、绑定目标、参数声明及保留命名规则 |
| 命令集采用 | 当前可识别集合、来源及变更生效 |
| 识别/展开 | 解析规则、绑定内容取用及展开结果 |
| 交付面适配 | 面向人/机器的识别呈现和预检 |
| 受理协调者 | 重新核验、固定实际输入、入队或交给工作流 |

最后一项由原受理拥有者承担，不成为命令领域的第二份队列或持久日志。

## 协作与依赖

交付面识别命令，来自其他来源的同样斜线文字仍是内容。客户端预检不替代受理侧的当前命令集与Skill资格核验；绑定命令不授权读取或执行Skill。

提示词/Skill展开产生实际用户内容；系统工作流由实际能力执行。命令集变更有登记/撤除边界，不从客户端缓存或同组目录推断当前可用。

## 主路径与交接

1. 交付面按定义识别及解析，预检未知或无资格的命令。
2. 受理侧复核当前集合、绑定及适用资格。
3. 提示词或Skill绑定在受理时取得实际正文，保存原命令与展开内容，按消息路径入队。
4. 系统工作流绑定交原能力执行，不成为普通消息；摘要日志不替代其恢复事实。

展开后Skill更新不改历史正文。绑定撤除或失权按当前受理条件拒绝，不能执行客户端旧展开。
