# Plugin领域交接设计

已接受职责沿[领域入口](README.md)，本页只维护事实拥有者和跨领域交接。工程细化与成员分工见[包组规格](../../../packages/plugin/SPEC.md)。

## 责任与消费者

一份 Plugin 是定义，不是运行着的东西。清单合法，不意味着它已经装上；装上了，不意味着它放的每一项都算数；它放的一项算不算数，由那个拓展点的规矩判。

| 责任 | 事实拥有者 | 交接及拒绝边界 |
| --- | --- | --- |
| 清单的形状、包的判定、成员的摘要、一侧要装的、一侧的状态 | Plugin 的共用契约（两棵树用同一份纯函数） | 清单读不懂、包对不上清单都答出原因，不抛出；不运行代码就算得出装上之后放什么 |
| 一份包合不合格、一次改动会怎样、在持的一份此刻生没生效 | Plugin 这个资产类别 `plugin`；指向别的类别的点的成员由那个类别的正文契约判 | 一个成员不合格或它的类别不可用，整份不发，原因指到成员；影响只读清单，不运行任何东西 |
| 这个主体现在要装哪几份、它们的文件 | 来源。它是接入插件声明的端口，由应用的装配给实现 | 给什么可以因主体而不同。取不到答取不到，不答空表 |
| 谁持有一份 Plugin、同名几份听谁的 | [资产与规则](../assets-and-rules/README.md) | 来源交来的一组里每个名字至多一份；同名两份时两份都不装 |
| 带身份问「要装什么」、分页取文件、收回报、读回报 | Plugin 的接入插件，经协议 `plugin/v1` | 每个操作先核这次登录可以为目标租户行事；规则见[接入层规格](../../../packages/access/SPEC.md) |
| 页面怎样取到一份 Plugin 的文件 | 宿主应用。桌面应用是转发层的一条同源的路，见[桌面应用规格](../../../apps/desktop/SPEC.md#取-plugin-的文件) | 带着登录替页面取；只认三种后缀；不改内容安全策略 |
| 把成员放到点上、换代、卸下 | 装载方。客户端的装载方是 Plugin 的界面模块，服务端的装载方是服务端应用的 `plugin-server` 行 | 只放清单里写过的成员；一份里有一个放不上，这一份什么都不留下。服务端每个租户一个回路，一份 Plugin 一个 fiber |
| 一个点收什么、同键多项怎样答、放上去的东西怎样生效 | 点的拥有者。界面的点归[外壳契约](../../../packages/frontend/SPEC.md#外壳契约)，登记表归 [Dynamis](../../../packages/dynamis/SPEC.md) | Plugin 不替点判；点不认的条目不算数，装载方把它读成这一份装不上 |
| 一个点收不收 Plugin 的代码、怎样把代码交回的东西做成一项 | 那个点的拥有者定，经 `plugin.guest-forms` 放客人写法；做成一项用它导出的做法 | 没有客人写法的点不收代码；客人写法不收交回的东西，这一份装失败并带它说的原因 |
| 交给代码什么 | 客户端：宿主应用给共用的库（桌面应用给 React 与共用界面件），装载方加一个不带「放」的外壳。服务端：只有钉住的口 | 代码文件不写包名。客户端代码拿到的外壳只能切页、提示、读当前租户；服务端代码的上下文里取不到任何受信名 |
| 借给 Plugin 的代码什么口、经口做的事许不许 | 出借口的领域，经自己的适配往 `plugin.ports` 放一项 | 口里以这次调用者的名义调这个领域已有的入口，领域照自己的规矩判；口只来往数据 |
| 一个租户的 Plugin 挂的协议谁调得到 | 入口：整个部署这一层问不到时，按调用者的租户范围再问一次 | 别的租户与没登录的调用者得到的答复与这份协议不存在时相同；规则见[接入层规格](../../../packages/access/SPEC.md#管道) |
| 应用倒下了几次、现在拦不拦 | 底。怎样算归 Dynamis 的 `Floor`，存在哪、怎样认出倒了一次归宿主应用 | 装载方经端口问它；应用不给底时装载方照常装 |
| 没起来的东西怎样对人说 | 画界面的应用 | 外壳只记与列（名字与原因），不决定措辞 |
| 客户端现在的样子（每份的状态、树上的点与部位） | 客户端自己；服务端记的是它最后报的那一份 | 服务端是事实的权威这一条不变：回报是客户端这棵树的投影，客户端不在了，它报的就去掉 |
| 代码在哪个执行域里运行、有什么限额 | [执行环境](../execution-environments/README.md)的受限执行域 | 换放置只换装载方，契约不变；不在受限执行域里运行的代码，隔离只对老实的代码成立，见[没有守住的](README.md#没有守住的) |

## 端口与实现方

Plugin 作为需求方声明下列端口，用自己的词说明需要什么。实现方是集成方，Plugin 不认识实现方。

| 端口 | 回答的问题 | 实现方 |
| --- | --- | --- |
| 来源（`PluginSource`） | 这个主体现在要装哪几份；按位置读一段文件；什么时候可能变了 | 服务端应用的 `plugin-access` 行：这个租户在持的 Plugin（取自资产），与运维者配置的开发目录。开发目录缺省不开，不开时它给空表 |
| 回报的去处（`PluginReports`） | 记下一个客户端报的；这个客户端在不在；列出一个租户的 | 接入成员自带的进程内实现，由行来造，每个租户记的客户端数有上限 |
| 为目标租户行事 | 这次登录能不能为这个租户行事 | 服务端应用用[身份与授权](../identity-and-authorization/README.md)适配 |
| 取代码（装载方的 `code.load`） | 一份 Plugin 的一个文件的模块 | 宿主应用。桌面应用从同源的路动态导入 |
| 底（装载方的 `FloorPort`） | 上一次要装的是哪些、现在拦不拦；记下要装、不要、起来了 | 宿主应用。桌面应用存在本机，每个租户一份；服务端应用存在运维者给的目录里，每个租户一个文件 |
| 类别要的三样（`PluginEffectPorts`） | 这个租户在持的 Plugin；服务端树上此刻的点；这个租户连着的客户端报了什么 | 服务端应用 |
| 服务端怎样放一份（`serverInstall` 的端口） | 持有它的租户的范围；一个点是什么；一个点的客人写法；钉住 `needs` 写的口；取代码成员的文件；放条目 | 服务端应用的 `plugin-server` 行。代码从这一版在本机的包目录导入，导入之前核过文件的字节等于清单写的摘要 |

## 组合保证由谁承担

| 组合保证 | 承担者 | 参与方 | 失败归属 |
| --- | --- | --- | --- |
| 同一个版本读到的内容永远相同 | 来源：版本是内容的摘要 | 接入插件、宿主应用的取文件的路 | 内容与文件表对不上时来源答「这一版不在了」 |
| 一份 Plugin 的贡献一起出现、一起退场 | 装载方：一份占一个自己的作用域 | 外壳契约的 `host`、登记表的座位 | 装载方。放不上的整份撤回并记原因 |
| 装着的向要装的收敛 | 装载方，照一侧的状态表 | 来源的观察：打开时一帧、之后每次可能变了一帧 | 读不到时不动；观察断了重开 |
| 不管装着什么，应用都打得开自带的界面 | 宿主应用的底与装载方 | 外壳：自带的模块各自起来，一个抛出不带倒别的 | 宿主应用。到了上限不再装并写明 |
| 一个租户装的东西别的租户看不到 | 装载方打上租户的作用域；点按发问者的作用域答 | 接入插件核登录可为目标租户行事；入口只按调用者的租户范围问第二次 | 接入插件拒绝；装载方在租户换了或退出时全部撤掉 |
| 一个租户的 Plugin 的代码够不着别的租户 | [四条规则](README.md#隔离与鉴权)：作用域由装载方打上；代码只拿到口；口绑着这次调用者 | 出借口的领域在动手的地方判；入口的第二次问 | 存心越界的代码与运行当中的资源不在这里，见[没有守住的](README.md#没有守住的) |
