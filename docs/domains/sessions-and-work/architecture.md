# 会话与工作的领域关系

状态为待审技术设计。正式维护位置不授予技术接受、实施或支持；精确公开形状仍待定义。

## 责任与事实源

| 拥有者 | 事实和承诺 | 不拥有 |
| --- | --- | --- |
| 输入受理协调者 | 原输入、来源、提交身份、去处责任、拒绝和可靠受理 | 原卡片决定、工具效果、所有系统流程结果 |
| Session治理 | 固定归属、Session log、会话状态、当前模式、关系、归档、会话注册及选择 | 共享资产的内容、权限源、物理执行全部停止 |
| Run推进治理 | 本次工作、承接、attempt、唯一有效推进资格、取消及逻辑终态 | 模型或工具自身生命周期、独立Job终态 |
| 原消费者或消费协调者 | 原位置、可靠取得内容、处理进度及后续责任 | 生产侧真实执行事实、统一清理所有全文 |
| Agent成员 | 在有效资格下求下一步、扩展、发起及消费执行 | Session身份、新Run准入、其他runtime生命 |
| Model和Tool成员 | 原调用、固定输入、执行、真实收场、结果及交付 | Run业务终态、会话自动归档规则 |
| HITL成员 | 原卡片关联、获准呈现、一次有效答复及可靠交回 | 原问题业务含义、批准的权限解释、Run终态 |

日志维护可恢复的会话逻辑事实，消息只占其中一部分。队列、当前 Run、等待及有效推进状态可从日志派生，标明覆盖进度。需要外部执行账、当前权限、共享设置或 Context 数据的查询是组合视图，标明各源，不冒称只靠日志重算的投影。

```mermaid
flowchart TD
    I[入口与合法主体] --> A[受理协调者]
    A --> S[Session事实与当前状态]
    A --> Q[普通输入投影]
    A --> H[原HITL等待]
    A --> C[控制或系统业务拥有者]
    Q --> G[Run与推进治理]
    H --> G
    G --> E[有效Agent推进者]
    E --> M[独立Model执行]
    E --> T[独立Tool执行]
    M --> R[原消费位置与可靠保管]
    T --> R
    R --> G
    C --> G
    G --> S
    S -. 归属及业务控制 .-> M
    S -. 归属及业务控制 .-> T
```

箭头表示契约消费或业务控制，不是进程父子、共同事务或物理部署拓扑。

## 设置声明修订

会话的覆盖或继承声明（SE06）也是装配求值的一类来源。Session 治理为每个会话维护设置声明修订：每采用一次 SE06，修订加一，与这条事实在同一次提交中成立，之后不倒退。修订与会话所选工作区（SE05）一起随[比对代替求值](../../architecture/runtime/assembly-and-change.md#比对代替求值)进入采用依据的快照，由装配入口直接比对。共享设置、租户默认与工作区来源的计数归各自拥有者，见[资产领域关系](../assets-and-rules/architecture.md#变更计数与通知)与[工作区领域交接设计](../workspaces/architecture.md#来源修订计数)。

## 压缩记录

会话历史的持有者在提交压缩记录前核对它与本会话历史对得上，核对与共同提交的步骤见[压缩记录的提交](../../architecture/runtime/session-and-run.md#压缩记录的提交)。对人的历史视图只加标注，不隐藏原消息。
