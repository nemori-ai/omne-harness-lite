# 新增责任、能力与模块

本页指导人和agent为新业务选择责任，保持相关知识就近维护及同一承诺唯一源。正文已获负责人接受，采用范围见[领域入口](README.md#维护与状态)；实际目录政策继续归[workspace](../workspace.md)。

## 先识别责任

明确新增行为、有效要求及采用范围，识别身份、状态、不变量、资格、结果、副作用及资源的拥有者，再找消费者和协调者。新名称、共同流程或相似字段不单独证明新领域。

既有责任能承接的行为先留内部模块。有无法归入现有知识的稳定责任时提议新入口。产品领域及DDD上下文另行确认；能力组、包、插件和进程分别设计。

## 选择扩展路径

| 新增内容 | 路径 |
| --- | --- |
| 内部算法或行为 | 留原拥有者和相称验证，不强制顶层入口或SDK |
| 稳定新业务责任 | 形成事实/协作设计，确认采用后增加入口，不先开空包 |
| 新提供者 | 就近兑现原契约和专属依赖，共用设施仍归自身能力 |
| 专有资产类别 | 复用共同治理，类别拥有专有业务，产品含义先确认 |
| 应用或发行装配 | 应用拥有交互/装配，可复用业务归能力，不反向依赖UI |
| Harness公开操作 | 原能力维护业务，共同契约/SDK/接入按系统分层，域内接口不自动公开 |

确定责任后按[产品包组织](../package-organization.md#新增与扩展)选择能力组及内部模块或成员边界；具体包收益和公开入口要求由该页维护。新组允许增长，现有17个责任入口不是白名单。manifest、目录和消费者切换按[workspace](../workspace.md)及实际迁移任务进行，领域目录不自行授予建包或接口接受。

## 共同契约与专有知识

共同能力只维护实际共同语义。类别通过公开扩展契约参与，维护自己的定义、失败和演化；治理不实现全部类别业务分支。只提取多个消费者确需的同义契约，不因字段相似制造万能基类。

命令识别展开、Skill方法取用、MCP连接发现分别有专有责任，复用持有与采用。Tool拥有动作执行，不接管被调用领域的状态及完成条件。

扩展契约说明身份/版本、所需治理信息、交互、失败、资源及验证责任。具体类型、注册及承载机制由实际拥有者设计，不预设继承树或通用运行框架。

## 阅读和维护顺序

1. 从[责任地图](boundaries.md)找拥有者及必要上游。责任充分明确就停止扩展阅读。
2. 从调用方真实使用形成公开操作、行为及消费者责任。新语义/冲突交拥有者，普通扩展沿有效承诺继续。
3. 判断内部模块、独立成员或新入口，按产品包组织选择目标组并核对模板和检查器支持范围；整体保证指定协调者，不直接写参与方私有状态。
4. 在实际拥有者处维护契约、实现与相称验证。独立使用与Cordis集成分别核对，明确资格、在途结果及释放条件。
5. 同步责任导航、必要专题和唯一登记，消费者切换后退出被替代正文。未完成仍报告缺项，未迁源保持责任。
6. 按[验证入口](verification.md)报告观察、偏离及未覆盖，区分采用、实现、验证，不得通过删除应有目标的登记来掩盖缺项。

方法及技能加载路径由[调查与设计](../engineering/scenarios/research-and-design.md)、[Feature](../engineering/scenarios/feature.md)和[技能入口](../engineering/skills.md)维护。新边界按需用pstack:how/why/architect，整体比较用arena，接口深度沿已采用Matt方法；不另写厚技能指导。

## 扩展仍须保护的边界

独立调用须承担自身授权、资源及结果责任，三runtime寿命和消费位置分开。租户字段、Context和目录不提供隔离；恶意代码、秘密和遥测沿安全约束处理。

跨节点须兑现同一业务语义，本地引用和函数返回不代替可靠交接。缓存、投影、日志和时间戳不替代原权威。重试/降级按实际效果及可配置策略，效果未知不推定可重放。

## 反向核对与测量

假设未来接受设备巡检：若有独立规则及判定结果，可提议责任；消费日程、工具、通知，自己承担组合，不接管执行和送达，不默认Session。此例不是已采用需求。

存储提供者、内部函数及SDK操作分别沿上表，不一律新建领域。新增类别反复修改共同业务分支，或同一决定反复跨多个成员修改时，复核知识边界。

登记、入口及依赖可机械观察，知识归属、寿命和效果仍需评审与真实验证，见[验证入口](verification.md)。未来责任没有固定白名单，新增按明确依据登记。
