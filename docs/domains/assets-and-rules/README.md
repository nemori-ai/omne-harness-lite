# 资产与规则

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

共同治理维护资产身份、定义版本、持有、来源、替换及设置/权限求值。它提供合法可采用候选，不接管每类资产的专有业务或实际执行。

类别行为由[命令](../slash-commands/README.md)、[Skill](../skills/README.md)、[MCP](../mcp/README.md)等拥有者维护。工具类别的资产 body 契约由[工具执行](../tool-execution/README.md)拥有：body 含身份、治理声明与实现引用。设置有效、资产可用、操作获准分别判断。

## 模块角色与事实归属

| 模块角色 | 拥有的知识 |
| --- | --- |
| 定义与版本 | 共同身份、来源及已接受的替换/组合关系 |
| 持有与转移 | 所有权、复制/分享及相应可达性依据 |
| 设置求值 | 来源、缺省与覆盖的本类规则 |
| 权限求值 | 约束、锁定上界、禁止及合法合成依据 |
| 类别提供者 | 专有形状、校验、读取或执行能力 |

类别内容与持有资格分开，设置和权限不共用一个通用合并算法。共享值只提取真实同义部分。

## 协作与依赖

组织、租户、工作区来源及Agent定义按各自规则参与求值。工作区可以贡献资产和配置，但不能授予更高权限，参与也不共享私有配值或凭据。

共同治理通过公开类别契约取得所需信息，不反向导入全部类别实现。[装配](../assembly-and-handoff/README.md)消费求值结果，[准入](../identity-and-authorization/README.md)消费权限依据。读取定义或成功装配不能代替动作授权。

## 主路径与交接

1. 在明确主体与范围下读取获准来源，保留候选身份及版本依据。
2. 按定义选择、替换及本类规则求有效资产，分别求设置和权限。
3. 类别拥有者校验其专有语义，装配协调者决定本次采用及依赖条件。
4. 实际动作仍走对应准入；持有、权限或定义变化按各自生效规则作用于后续使用。工具是例外：跟随当前版的工具持有对已有会话的常驻项只在新定义与首次定义同形时跟随，见[工具规格](../../../packages/tool/tool-contract/SPEC.md#会话常驻规则r1r5)。

变更不改写已捕获输入或历史事实，未知来源不能用猜测定义补齐。

## 契约与验证导航

共同定义/持有及求值契约由各角色拥有，多类别共有语义由原定义维护。类别精确类型、依赖和变化时点随类别成员；跨源采用及一致性由装配协调者定义。

上层沿[系统结构](../../architecture/structure.md)、[装配](../../architecture/runtime/assembly-and-change.md)及安全权限专题。产品依据见[本域产品正文](../../../.meta_harness/design/product/assets-and-rules/design.md)，范围及状态沿该源判断。验证见[组合入口](../verification.md)。

## 后续设计与维护

公开扩展契约、版本/快照取得、来源变化竞态和替换清理由治理、类别及装配成员设计。新的资产类别和通用合成含义须按产品采用确认，不因开放接口存在自行添加。

局部类别任务先读自身入口；共同来源/持有或合成变更再展开本页及相关PF。精确协议不足只暂停依赖的实现，不扩大为全部治理阻塞。
