# MCP接入

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

MCP维护外部端点接入、连接、对端身份、合法发现及能力桥接。端点是资产，共同持有和凭据治理沿原规则；对端动作不是独立资产，各自映射为工具条目。

协议接入不等于[Tool执行](../tool-execution/README.md)，连接恢复也不证明原动作未执行。协议可有非动作能力，本项目桥接范围随已采用客户端，不自动全部开放。

## 模块角色与事实归属

| 模块角色 | 拥有的事实 |
| --- | --- |
| 端点定义/采用 | 接入配置、来源、采用版本及依赖条件 |
| 连接提供者 | 对端身份、连接状态与连接资源 |
| 发现/刷新 | 最近合法能力及其来源，变更与不可用解释 |
| 动作桥接 | 将已发现动作作为工具条目，保留原端点/能力关联 |
| 实际调用 | 原输入、执行及效果，由工具契约和实际提供者负责 |

凭据属于获准租户持有和秘密使用边界，不在共享连接或普通Context里传播。

## 协作与依赖

装配采用获准端点和配置，连接供给发现与调用条件。动作桥接消费工具契约，不让连接服务判Job、Run或调用终态。

连接时限和调用时限分别维护。离线保持最近合法清单的不可用解释，不伪造未发现动作。SDK不因提供系统接入就携带服务端连接、凭据或执行闭包。

## 主路径与交接

1. 核验端点采用及凭据使用资格，建立可解释的连接。
2. 发现/刷新合法能力，提供带来源的当前条目与可用条件。
3. 动作调用走Tool准入，固定原输入后由实际调用提供者执行。
4. 失联或重连分别更新连接/清单状态，原调用继续按执行事实与效果契约收束。

Agent替换、客户端断开或连接恢复不自动取消或重发远端动作。无法确认效果时保留未知，不能把网络错误当作零副作用。

## 契约与验证导航

端点/连接/发现契约维护专有接入，Tool拥有动作结果和控制，秘密拥有者维护凭据使用/释放。跨机制可靠交接由调用协调者定义。

依据为[本域产品设计草案](../../../.meta_harness/design/product/mcp/design.md)；运行边界沿[工具](../../architecture/runtime/tool-runtime.md)与[安全](../../architecture/security/README.md)。验证见[组合入口](../verification.md)。

## 后续设计与维护

具体MCP客户端、认证/刷新/重连机制、非动作桥接范围及动作映射API由端点/连接/Tool拥有者设计。MCP协议SDK与完整Harness公共SDK不同，不默认所有客户端都支持同一桥接。

连接维护先读本契约，效果/恢复再读Tool及原工作；非动作范围未定只暂停相关桥接，不影响已明确动作责任。
