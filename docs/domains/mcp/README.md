# MCP接入

## 范围与边界

MCP维护外部接入点的接入、连接、对端身份、合法发现及能力桥接。接入点是一个在外面的 MCP 服务，加上怎样连到它。接入点是资产，共同持有和凭据治理沿原规则；对端动作不是独立资产。一个接入点在工具入口里是一个工具条目，它的动作是这个工具的命令。

协议接入不等于[Tool执行](../tool-execution/README.md)，连接恢复也不证明原动作未执行。协议里除了动作还有别的能力。本项目采用两样：对端声明的事件（[MCP 事件类型](../../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-mcp-event-type--mcp-事件类型--mcp-event-type)、[MCP 事件订阅](../../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-mcp-event-subscription--mcp-事件订阅--mcp-event-subscription)），与对端带来的技能（[MCP 技能](../../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-mcp-skill--mcp-技能--mcp-skill)）。别的非动作能力不自动开放。

MCP 只按地址接入。系统不替用户把一个命令起成 MCP 服务（命令型，stdio）。本机上长驻的 MCP 服务也是系统之外的服务，系统只看它的地址通不通。命令型接入不在 0.0.0 至 0.1.0 这一阶段，[资产与规则产品正文](../../../.meta_harness/design/product/assets-and-rules/design.md)里 CAP-AR08「命令型接入逐件显式启用的控制」随之不在本阶段。以后要支持命令型，从 Cordis 动态装配的角度另行设计，不走执行环境。

## 模块角色与事实归属

| 模块角色 | 拥有的事实 |
| --- | --- |
| 接入点定义/采用 | 接入配置（名字、地址、怎样认证）、来源、采用版本及依赖条件 |
| 连接提供者 | 对端身份、连接状态与到接入点地址的连接资源 |
| 发现/刷新 | 最近合法能力及其来源，变更与不可用解释 |
| 动作桥接 | 向工具入口登记工具条目来源，按当下事实交出接入点的工具条目，已发现的动作是它的命令，保留原接入点/能力关联 |
| OAuth 的取得与续期 | 一份持有上经 OAuth 取得的凭据的非秘密事实、待完成的那一次取得、客户端登记；令牌与续期材料的本体在秘密保管里 |
| 长任务的看守 | 对端任务的耐久记录，以及它与原调用的关联 |
| 事件 | 对端声明的事件类型；MCP 事件订阅、它收到的位置、收到的事件与缺口 |
| 技能桥接 | 向 `Skills` 入口登记技能条目来源，按当下事实交出对端带的技能，核对文件的大小与摘要 |
| 耐久存储 | 上面几样要跨重启留下的事实，按租户分开 |
| 调用权限 | 每个 MCP 接入点一项权限「调用这个接入点的动作」，由 MCP 类别在资产里声明 |
| 实际调用 | 原输入、执行及效果，由工具契约和实际提供者负责 |

凭据属于获准租户持有和秘密使用边界，不在共享连接或普通Context里传播。连接与发现清单按租户与凭据账号分开，一个租户的调用不经另一个租户的凭据认证的连接执行，也看不到按另一个账号发现的动作清单。本租户缺凭据时，调用按缺凭据失败，不退回组织、官方或其他租户的凭据。

## 协作与依赖

装配采用获准接入点和配置，连接供给发现与调用条件。动作桥接消费工具契约，不让连接服务判Job、Run或调用终态。

连接时限和调用时限分别维护。离线保持最近合法清单的不可用解释，不伪造未发现动作。SDK不因提供系统接入就携带服务端连接、凭据或执行闭包。MCP协议SDK与完整Harness公共SDK不同，不默认所有客户端都支持同一桥接。

动作经工具入口到 agent 手上。MCP 向工具入口登记一个工具条目来源，来源按调用交出这个主体此刻合法可用的接入点。一个接入点是一个工具条目：一个多命令工具，它的每个动作是一个命令。条目是视图，不是登记进工具登记表的工具，所以没有「同步工具表」这一步，也没有两边对不上的时候。agent 用 `Tools` 搜到一个接入点，看到它的动作各一行，看要用的那个动作的用法，调用它。调一个动作就是一次工具调用，受理、结果保管、取消都归 Tool，许不许归 Agent 发起时的放行判断，MCP 是这次调用背后真正发出请求的一方。三个时刻各归谁见[领域交接设计](architecture.md#工具条目来源)。

MCP 的动作一般不常驻。例外是标了常驻的 MCP 接入点：它在采用点成为一条常驻工具，命令是它此刻的动作，进工具声明。之后对端的变化不改这条声明：被点名的动作在发出前按形状复核，撤了或改了参数的不发，别的照常。常驻标记标在接入点的引用上，不做动作名单。

每个 MCP 接入点有一项权限「调用这个接入点的动作」，取值禁止、询问、自动，缺省询问。授权的动作规则可以按来源（能力标识，即类别加名字）匹配，管一个来源的全部条目。权限按接入点一项，不按动作一项，因为动作不是资产，随对端变。接入点缺省询问，所以新登记的接入点上，动作的调用先问人。

对端要求补充输入时，问的是人。MCP 复用[工具](../tool-execution/README.md)内「等人决定」的原语与[人工介入](../human-intervention/README.md)的卡片，不另做一套。

认证是接入点上的事。人在登记接入点或点「连接」的时候完成认证，不是 agent 在会话里向用户发起。凭据交给秘密保管，只给连接用。经 OAuth 取得凭据的流程归本领域：发现、登记、换取与续期。凭据的本体仍归秘密保管。

对端把一次动作做成长任务时，它仍是同一次工具调用。这次调用停泊在 Tool 的等待上，本领域的看守凭耐久的任务记录去问对端，到了终态再把答复交给 Tool。

事件经本领域进来，到消费者为止。本领域向对端订、收下、去重、记位置，再把事件连同标识交给要它的一方。给谁、多急、要不要叫醒一个会话，归[通知](../notifications/README.md)。本领域不认识通知：要事件的一方实现本领域声明的消费者端口。

对端带的技能经 `Skills` 入口到 agent 手上。MCP 向 `Skills` 入口登记一个[技能条目来源](../../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-skill-entry-source--技能条目来源--skill-entry-source)，交出的名字带接入点的前缀。[MCP 技能](../../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-mcp-skill--mcp-技能--mcp-skill)不是资产，怎样搜到与披露归 [Skill](../skills/README.md)。

## 主路径与交接

1. 核验接入点采用及凭据使用资格，建立可解释的连接。
2. 发现/刷新合法能力，提供带来源的当前条目与可用条件。
3. 动作调用经放行判断放行后由 Tool 受理，固定原输入后由实际调用提供者执行。
4. 失联或重连分别更新连接/清单状态，原调用继续按执行事实与效果契约收束。
5. 对端声明了事件或技能时，分别取得它们的清单。有订阅者的事件类型才向对端订；技能在被读到时才取文件。

Agent替换、客户端断开或连接恢复不自动取消或重发远端动作。无法确认效果时保留未知，不能把网络错误当作零副作用。
