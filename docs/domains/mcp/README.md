# MCP接入

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

MCP维护外部接入点的接入、连接、对端身份、合法发现及能力桥接。接入点是一个在外面的 MCP 服务，加上怎样连到它。接入点是资产，共同持有和凭据治理沿原规则；对端动作不是独立资产，各自映射为工具条目。

协议接入不等于[Tool执行](../tool-execution/README.md)，连接恢复也不证明原动作未执行。协议可有非动作能力，本项目桥接范围随已采用客户端，不自动全部开放。

MCP 只按地址接入。系统不替用户把一个命令起成 MCP 服务（命令型，stdio）。本机上长驻的 MCP 服务也是系统之外的服务，系统只看它的地址通不通。命令型接入不在 0.0.0 至 0.1.0 这一阶段，这是负责人 2026-11-12 的裁定，[资产与规则产品正文](../../../.meta_harness/design/product/assets-and-rules/design.md)里 CAP-AR08「命令型接入逐件显式启用的控制」随之不在本阶段。以后要支持命令型，从 Cordis 动态装配的角度另行设计，不走执行环境。

## 模块角色与事实归属

| 模块角色 | 拥有的事实 |
| --- | --- |
| 接入点定义/采用 | 接入配置（名字、地址、怎样认证）、来源、采用版本及依赖条件 |
| 连接提供者 | 对端身份、连接状态与到接入点地址的连接资源 |
| 发现/刷新 | 最近合法能力及其来源，变更与不可用解释 |
| 动作桥接 | 向工具入口登记工具条目来源，按当下事实交出已发现动作的工具条目，保留原接入点/能力关联 |
| 调用权限 | 每个 MCP 接入点一项权限「调用这个接入点的动作」，由 MCP 类别在资产里声明 |
| 实际调用 | 原输入、执行及效果，由工具契约和实际提供者负责 |

凭据属于获准租户持有和秘密使用边界，不在共享连接或普通Context里传播。连接与发现清单按租户与凭据账号分开，一个租户的调用不经另一个租户的凭据认证的连接执行，也看不到按另一个账号发现的动作清单。本租户缺凭据时，调用按缺凭据失败，不退回组织、官方或其他租户的凭据。

## 协作与依赖

装配采用获准接入点和配置，连接供给发现与调用条件。动作桥接消费工具契约，不让连接服务判Job、Run或调用终态。

连接时限和调用时限分别维护。离线保持最近合法清单的不可用解释，不伪造未发现动作。SDK不因提供系统接入就携带服务端连接、凭据或执行闭包。

动作经工具入口到 agent 手上。MCP 向工具入口登记一个工具条目来源，来源按调用交出这个主体此刻合法可用的动作，每个动作是一个工具条目。条目是视图，不是登记进工具登记表的工具，所以没有「同步工具表」这一步，也没有两边对不上的时候。agent 用 `Tools` 搜到一个动作，看用法，调用它。调一个动作就是一次工具调用，准入、结果保管、取消都归 Tool，MCP 是这次调用背后真正发出请求的一方。三个时刻各归谁见[领域交接设计](architecture.md#工具条目来源)。

MCP 的动作一般不常驻。例外是标了常驻的 MCP 接入点：它的动作在采用点成为常驻工具，进工具声明。常驻标记标在接入点的引用上，不做动作名单。

每个 MCP 接入点有一项权限「调用这个接入点的动作」，取值禁止、询问、自动，缺省询问。授权的动作规则可以按来源（能力标识，即类别加名字）匹配，管一个来源的全部条目。权限按接入点一项，不按动作一项，因为动作不是资产，随对端变。接入点缺省询问，所以新登记的接入点上，动作的调用先问人。

对端要求补充输入时，问的是人。MCP 复用[工具](../tool-execution/README.md)内「等人决定」的原语与[人工介入](../human-intervention/README.md)的卡片，不另做一套。

认证是接入点上的事。人在登记接入点或点「连接」的时候完成认证，不是 agent 在会话里向用户发起。凭据交给秘密保管，只给连接用。OAuth 要做，排在 4 号线的最后一程。

## 主路径与交接

1. 核验接入点采用及凭据使用资格，建立可解释的连接。
2. 发现/刷新合法能力，提供带来源的当前条目与可用条件。
3. 动作调用走Tool准入，固定原输入后由实际调用提供者执行。
4. 失联或重连分别更新连接/清单状态，原调用继续按执行事实与效果契约收束。

Agent替换、客户端断开或连接恢复不自动取消或重发远端动作。无法确认效果时保留未知，不能把网络错误当作零副作用。

## 实现现状

上面关于只按地址接入、工具条目来源、常驻的例外、接入点的调用权限、补充输入问人和接入点上的认证，是负责人 2026-11-12 裁定的已接受目标，实现在 4 号线。MCP 领域内已有的实现（连接、清单、调用、可用性状态）在 `packages/mcp` 的成员里，是候选，尚未取得技术接受，见[领域交接设计](architecture.md)。动作进工具入口、凭据的使用、补充输入和 OAuth 都还没有做。会话与 Agent 的动态重装配也还没有做，所以标了常驻的接入点的动作清单在已有会话里不会更新，只对新会话生效。撤销永远立刻生效，不等装配。

## 契约与验证导航

接入点/连接/发现契约维护专有接入，Tool拥有动作结果和控制，秘密拥有者维护凭据使用/释放。跨机制可靠交接由调用协调者定义。

依据为[本域产品设计草案](../../../.meta_harness/design/product/mcp/design.md)；运行边界沿[工具](../../architecture/runtime/tool-runtime.md)与[安全](../../architecture/security/README.md)。验证见[组合入口](../verification.md)。

## 后续设计与维护

具体MCP客户端、重连机制、认证的刷新机制、非动作桥接范围及动作映射API由接入点/连接/Tool拥有者设计。认证的归属已定：在接入点上由人完成。MCP协议SDK与完整Harness公共SDK不同，不默认所有客户端都支持同一桥接。

连接维护先读本契约，效果/恢复再读Tool及原工作；非动作范围未定只暂停相关桥接，不影响已明确动作责任。
