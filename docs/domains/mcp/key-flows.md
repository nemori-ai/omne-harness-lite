# MCP跨领域关键流程

状态：技术协作草案。图表达责任，不指定线程、进程或寿命；完整 INV 与 V 仍为正式成员承接缺项，责任见[正式承接缺口](../../../packages/mcp/docs/architecture.md#完整行为候选的正式承接缺口)。端口的实现方见[领域交接设计](architecture.md#mcp-声明的端口与实现方)，组内路径见[组内流程](../../../packages/mcp/docs/key-flows.md#组内调用路径)。

## F-MC04 动作准入至可靠结果

对应 J-MC04，INV-MC14–17。调用方（会话路径上是 Agent）或独立消费者携带可信主体与原动作/参数/消费位置。动作经工具条目来源到调用方手上：发现经工具入口的目录视图，选定读来源内存里的清单快照，发出前由 MCP 的调用入口复核定义，复核与发出是一步，定义已变就不发。桥接复核接入点和动作当前是否可调，权限按接入点取一项（禁止、询问、自动，缺省询问），不逐动作取。Tool 选择所需实际环境及资源并保护最终发起竞争。准入拒绝、参数不合法或设施不符不执行原动作，原因沿原消费位置返回；不可用沿 dummy 规则收束。

实际提供者发出原调用，Tool 保管固定输入、控制与真实结果/效果。后端已发生而本地承接不明时保留未知，不能把响应错误改成无副作用失败。结果消费者可靠保存结果和原位置，确认后原前方解除交付责任；拒收、失联或无披露权时原结果继续有人保管。转后台仍为原调用，最终收场沿 Tool，不以过程帧代结果。

MCP 一侧的步骤（技术草案）：调用方携带可信主体、接入点引用、对端动作名、参数、预期的定义的内容摘要、关联键与 `signal`，`continueWithInput` 另带 `requestState` 或输入答复（至少一项）与发出代际。MCP 按（租户、主体、关联键）登记在途调用，同一个键已在途时返回「未发出」，原因是关联键重复。MCP 复核接入点仍已采用、当前使用资格、这个动作仍在 MCP 动作清单里且定义的内容摘要相符。接入点未采用时答 `not-available-to-you`，与无权、不存在不可区分。条件不成立时，MCP 返回「未发出」与原因，不发起原动作。准入与参数校验在调用方一侧，见领域[主路径与交接](README.md#主路径与交接)第 3 步。

条件成立时，MCP 发出协议请求，交回[调用结果](../../../packages/mcp/docs/architecture.md#调用结果)。后端已发生而本地承接不明时，MCP 报 `unknown`。MCP 交回的东西与 MCP 一侧的后续如下：

| MCP 交回                | 含义                                                                                                              | MCP 一侧的后续                                                                                               |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 未发出                  | 请求没有发出，没有对端效果。原因含定义已变、关联键重复与需要授权                                                  | 无                                                                                                           |
| `complete`、`toolError` | 对端的结果。`toolError` 是动作自己的失败。`complete` 带 outputSchema 的校验结论                                   | 无                                                                                                           |
| `inputRequired`         | 对端要求输入。`inputRequests`（不可信值，只有 elicitation）与 `requestState` 各自可选，至少有一项；另交出发出代际 | 调用方经 `continueWithInput` 带回答复时，带上 `requestState`（如有）再发原请求。这是协议的多轮请求，不是重发 |
| `task`                  | 对端转为任务执行。交出 `taskId` 与发出代际                                                                        | 调用方经状态口查询、取结果、交回输入答复或取消，不重新发起                                                   |
| `protocolError`         | 错误码与原因。不证明没有效果                                                                                      | 无                                                                                                           |
| `unknown`               | 效果未知，带子因：断流、本地放弃。`signal` 触发或 `cancel` 之后，子因是本地放弃                                   | 不重发，见 F-MC06                                                                                            |

MCP 不保存原调用，也不代答输入请求。依据层：领域[模块角色与事实归属](README.md#模块角色与事实归属)；产品 [J-MC04](../../../.meta_harness/design/product/mcp/design.md#j-mc04-发起一个-mcp-动作)。

## F-MC05 取消和归档后的迟到事实

对应 J-MC05，INV-MC17、INV-MC18、INV-MC20。合法控制指向原调用，Tool 向实际提供者传播支持的取消。未发动作可阻止，已发动作区分合作请求、实际停止和未知。会话归档时，Session 经 Agent 的公开操作控制原 Tool 调用，按 Q04 解除推进依赖；不等共享连接关闭或远端停止。随后迟到响应归原调用，由 Agent 宿主的结果接收方按原调用身份保存效果、账目和必要历史，不恢复 Session，不向无权消费者披露。资源释放只报告实际确认范围。

MCP 一侧的步骤（技术草案）：`ActionInvoker.cancel(access, correlationKey)` 按（租户、主体、关联键）定位在途请求，再按传输发出取消信号，见[组内调用路径](../../../packages/mcp/docs/key-flows.md#组内调用路径)。只有同一租户与同一主体能取消。取消不要求当前使用资格，因为取消只减少效果。已发出的动作，MCP 只答已发出取消信号、没有在途调用或 `unknown`，原调用的结局随后是 `unknown`，子因是本地放弃。取消信号只是请求，不证明实际停止。取消之后到达的迟到响应，MCP 按原关联键与代际识别，不归到新调用。依据层：架构[取消与归档](../../architecture/runtime/control-and-recovery.md#取消与归档)。

## F-MC06 失联、重连与原工作接续

对应 J-MC06，INV-MC06、INV-MC12、INV-MC17–20。连接提供者更新连接状态并在当前条件成立后恢复/发现，供未来调用使用。原调用拥有者查询或对账原身份：已确认结果则只接续未完成消费；查询暂不可用保留未知；真实运行连续性已丢失则按 Tool 失败规则收束。任何分支都不以新连接自动重发。恢复自身再中断，继续原进度与原事实。成员失效不销毁记录，后续访问仍核验当前资格。

断流时 MCP 一侧的交接（技术草案）：

1. 调用已发出后响应流断开，MCP 对这次调用报 `unknown`，带子因。
2. 官方规格要求客户端用新请求号重新发出断流的请求。MCP 对 `tools/call` 不这样做，偏离记录见 [Q-MC04](../../../packages/mcp/docs/architecture.md#q-mc04-原调用dummy可靠结果和恢复的组合协议)。
3. 核查、补偿或另起一次调用由合法调用方决定，见架构[中断与失联](../../architecture/runtime/tool-runtime.md#中断与失联)。
4. 重连产生新的连接代际。旧代际的迟到响应不改变新状态。
5. 调用方在新代际上继续时，按对端时代分开处理，见下表。规则见[组工程设计的应用服务](../../../packages/mcp/docs/architecture.md#应用服务)。

| 操作                           | Streamable HTTP 现代对端                 | Streamable HTTP 旧对端             |
| ------------------------------ | ---------------------------------------- | ---------------------------------- |
| `continueWithInput` 与任务操作 | 用保存的 `requestState` 与 `taskId` 继续 | 在途状态属于旧会话，返回 `unknown` |
| `cancel`                       | 代际已换时返回 `unknown`                 | 同左                               |

## F-MC07 独立消费和有资格的查询

对应 J-MC07、J-MC08，INV-MC03、INV-MC13、INV-MC21–23。程序选择独立操作并显式给出本次主体、目标、用途、控制和结果消费者，缺必需条件只拒绝依赖操作。查询权威读面时标明来源及新鲜度，未知和不存在分开，查询不重做动作。输出及错误不含秘密。退出前已接纳工作保留或可靠交接；MCP 协议客户端能力不授予 Harness 系统闭包或全部非动作能力。

MCP 一侧（技术草案）：未采用的接入点与无权、不存在一样答 `not-available-to-you`。MCP 动作清单在调用方首次经 `refresh` 触发发现之前答「未取得」。

## F-MC08 对端要求补充输入

对应 J-MC04。一次动作调用进行中，对端要求补充输入。问的是人，不是模型。调用的执行体走工具内「等人决定」的原语，把对端给的表单变成人工介入的卡片。人答了，按原调用继续并把答复交对端。人拒绝或没答，把相应的答复告诉对端。这个等待没有超时，没有默认答复，取消不填答案。答复回的是原调用的等待点，不新建一次调用。不另做一套询问机制。

## F-MC09 接入点上的认证

对应 J-MC01。认证是接入点上的事。人在登记接入点，或点「连接」的时候完成它，不是 agent 在会话里向用户发起。凭据交给秘密保管，只给连接用，不进工具的固定请求、清单、日志或模型上下文。凭据缺失或失效时，调用按缺凭据失败，不退回别的租户或别的层的凭据，也不由 agent 去要。OAuth 要做，排在 4 号线的最后一程，前面几程只接静态的凭据。

本页的 F-MC04、F-MC08、F-MC09 里，动作经条目来源进工具入口、补充输入、接入点上的认证是已接受的目标，实现在 4 号线，尚未实现，见[领域页的实现现状](README.md#实现现状)。
