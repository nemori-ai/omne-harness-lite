# 拓展件跨领域关键流程

规则归[领域入口](README.md)与[Loop extensions](../../architecture/runtime/loop-extensions.md)。本页只写跨领域的次序与每一步的失败去处。

## F-LX01 发布并启用一件拓展件

1. 租户把一个目录交给资产发布。资产调用本领域登记的校验：目录合法时投影出声明，不合法时拒绝并说明原因。
2. 资产记版本并换入包的内容，再由调用方记成租户的持有。
3. 租户把这件拓展件的「运行」设置打开。
4. 资产与设置的写入者各在提交之后给出变化信号。
5. 本领域作废这个租户的视图。

发布、持有、设置任一步失败或未知时，按资产各自的原操作规则处理。视图只反映已经提交的事实。

## F-LX02 一次经过读取并运行租户启用的拓展件

1. Loop 走到一处位置。适配成员以协调者类读者读 Runtime Context 里的这一块。
2. Runtime Context 向本领域取当前值。视图有缓存时直接答；没有时本领域按资产与设置的当前事实重算。
3. 适配成员从值里筛出这个位置与维度的成员，按能力名升序排列，交给 Agent。
4. Agent 记下扩展链与第一个成员的调用请求，然后经端口调用。
5. 本领域按记下的精确版本取得实现并运行，交回结果。

| 哪一步答不出 | 去处 |
|---|---|
| 作用域里没有登记这一块，或读者没有资格 | 读不到。Agent 按依赖等待；落终态之后记下未观察 |
| 资产的某一层读不到，或设置读不到 | 视图答读不到，同上 |
| 取实现时版本的材料不可用，或内建实现没有登记 | 不可用。按这件拓展件声明的处置跳过或否决，并留记录 |
| 调用开始后失败 | 报错。按声明的报错处置 |
| 判不明是否开始或是否收场 | 未知。原调用保留，下一次合法推进以重放接续 |

## F-LX03 经过当中的停用、移除与换版

1. 租户停用、移除一件拓展件，或发布它的新版本。写入者给出变化信号，本领域作废视图。
2. 正在进行的经过不受影响：链已经记下。链上还没开始的成员轮到时，本领域按记下的版本取实现。持有已被停用或移除时答不可用。旧版本的包仍在时照常运行。已经开始而结果未知的成员以重放接续；重放时取不到原实现，原调用保持未知，不改答不可用。
3. 下一次经过读到新的视图。

## F-LX04 命令型的一次调用

1. 本领域取这一版在本机的目录，解析解释器的名字，取得运行位置。任一项不成，答不可用，没有进入。
2. 本领域在自己的账本里登记启动意图。
3. 本领域向执行环境获取租约并启动进程，把输入写进标准输入。
4. 启动成功后，本领域在账本里记已启动，然后等结局并计时。到时限时先请求停止，再强制停止。
5. 本领域在账本里记结局与停止状态，释放租约，把观测到的事实归成一个调用结果交回。

| 观测到的事实 | 调用结果 |
|---|---|
| 启动被执行环境拒绝 | 不可用 |
| 启动的答复是未知 | 未知 |
| 退出码是零，标准输出是一份合法的输出 | 输出 |
| 退出码是零，标准输出不合法或超过上限 | 报错：坏输出 |
| 退出码不是零 | 报错：非零退出 |
| 到时限没有收场 | 报错：超时 |
| 启动之后失联 | 未知 |

宿主重启后，本领域先扫自己的账本：登记了启动意图而没有结局的调用，按原获取停掉可能还在的进程。这些调用对 Agent 仍是未知。

## F-LX05 卸下本领域的服务

1. 服务不再接新的调用。视图不再供值。
2. 在途的调用各自收场，结局照常写进账本。
3. Agent 一侧读到的是读不到与不可用，按 F-LX02 的表处理。
