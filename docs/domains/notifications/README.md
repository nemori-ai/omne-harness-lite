# 通知与交付

## 范围与边界

通知承担发送和面向目标的送达，支持有无Schedule/Job来源的独立调用。发送受理、持久送达、已读和源工作完成分别表达。

通知不等于会话消息或遥测，不能用成果提交或模型回复证明目标已收到。

## 模块角色与事实归属

| 模块角色 | 责任 |
| --- | --- |
| 发送入口 | 来源、目标、内容及允许传送的资格 |
| 交付保管 | 未完成的送达责任及可恢复内容/引用 |
| 交付提供者 | 实际渠道发送与可确认的目标交付事实 |
| 查询/关联 | 提供所属契约允许观察的结果与来源关联 |
| 发起业务 | 判断通知结果怎样影响自己的业务完成 |

这是逻辑分工，不裁定通知、发送尝试或投递对象分别有什么身份。

## 协作与依赖

调用方可以是系统或agent，向租户发送不转移源工作所有权，也不自动授予读取该租户私有内容或跨租户传送权限。

通知消费受保护内容和获准目标，向[日程Job](../schedules-and-jobs/README.md)或独立调用方返回自己的交付事实。客户端显示、未确认通道发送或连接在线不能成为送达权威。

## 主路径与交接

1. 发起方明确来源、目标和内容，按传送及读取规则核验资格。
2. 发送被受理时保留本契约要求的交付责任和可恢复依据。
3. 提供者执行交付，分别报告实际发送与可确认送达。
4. 原业务根据交付结果继续，未完成部分按原身份恢复。

恢复送达不重做已经完成的源动作。不可确认结果保持未知，具体重试去重条件由交付契约定义，不用“消息发送成功”掩盖目标未达。
