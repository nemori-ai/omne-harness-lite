# 日历

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

日历维护供应数据、身份、不可变版本、覆盖范围、健康及日期计算语义，可独立消费。它为日程提供依据，不接受Job或判断业务完成。

日历内容不是Runtime Context或存储的业务，工作状态也不随某次计算退出而结束。

## 模块角色与事实归属

| 模块角色 | 拥有的事实或计算 |
| --- | --- |
| 日历定义/治理 | 身份、来源及获准使用范围 |
| 供应与版本 | 原数据、不可变版本、覆盖及健康状态 |
| 日期计算 | 按指定依据解释日期并返回可复核结果 |
| 缓存/查询适配 | 加速取得数据，保持来源/版本及缺失含义 |
| 日程消费者 | 校验候选并决定本次接受，归日程 |

供应健康和计算结果分别报告，不能把缺数据伪装成没有到期工作。

## 协作与依赖

消费者通过公开查询/计算取得来源和版本，按自己的业务要求判断可用性。通知不经日历决定送达，Job接受由[日程](../schedules-and-jobs/README.md)承担。

数据更新不覆盖旧版本，缓存须有失效和范围，派生值可重算但不能替代原依据。时区、期限及先后沿所属业务和跨系统约定，不用一个统一时间值掩盖含义。

## 主路径与交接

1. 供应方取得并维护声明范围的日历依据、版本及状态。
2. 调用方按需要取得可解释版本，日期计算返回带依据结果。
3. 日程校验尚未接受的候选，固定本次Job要求及采用依据。
4. 后续日历更新影响允许更新的候选，不改已经接受的Job。

供应暂时不可用时区分缺数据、覆盖不足及查询失败；具体兜底不伪造成功计算或静默启动动作。

## 契约与验证导航

日历契约拥有版本/覆盖和计算含义，供应提供者拥有读取/刷新及健康，日程契约拥有接受与固定要求。精确算法、缓存、存储及查询API随实际成员。

上层沿[系统业务协作](../../architecture/structure.md)、[时间约定](../../architecture/cross-cutting-concepts.md#时间顺序与版本)及[数据](../../architecture/data-and-state.md)。产品依据[PF-021](../../../.meta_harness/design/product/PF-021-schedule-and-calendar/README.md)，验证见[组合入口](../verification.md)。

## 后续设计与维护

供应选择、覆盖协议、版本保留、算法及日期边界验证由日历/供应成员设计；日程接受并发仍归原协调者。不能以当前库的日期行为定义产品承诺。

只用计算读公开契约即止；涉及候选、刷新或恢复再展开日程和供应。精确机制不足只暂停相应实现，不把日历独立使用变成会话能力。
