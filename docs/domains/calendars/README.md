# 日历

本页维护已接受的目标责任与公开协作，采用范围见[领域入口](../README.md#维护与状态)。本次目标沿源 Python 修订 `a7dbd98f9c5c7a8ead6afbd18896777f0cf1ecd0` 的产品范围，并采用用户确认的环境绑定规则；来源细节与验收映射归[产品正文](../../../.meta_harness/design/product/calendars/design.md)及[成员规格](../../../packages/calendar/calendar/SPEC.md)。目标接受不表示代码、供应提供者或算法验证已经完成。

## 范围与边界

Calendar 维护日历身份、供应依据、不可变版本、覆盖、知识截至、健康和日期计算语义，可独立消费。它不依赖 Schedule、Session、Agent 或工具运行时，不负责 Job 接受和通知送达。

用户环境设置由既有拥有者保存，Calendar 只消费获准读取的选择。Clock 提供横向时间能力，storage 提供保存机制，两者均不接管日期知识。供应状态和计算结果分别表达，缺数据不能变成没有到期工作。

## 模块角色与事实归属

| 模块角色       | 拥有的事实或计算                                                                        |
| -------------- | --------------------------------------------------------------------------------------- |
| 日历定义与治理 | 日历身份、来源、适用范围和获准使用条件                                                  |
| 供应与版本     | 原始依据、校验候选、不可变发布版本、current 指针、覆盖与健康                            |
| 日期计算       | 指定版本的日别、工作日算术及有界日期解释，返回可复核依据                                |
| 查询与缓存适配 | 可重建的查询投影和缓存，保留来源、版本与真实缺失                                        |
| 日程消费者     | Schedule 候选、版本采用政策和 Job 接受，归[日程与 Job](../schedules-and-jobs/README.md) |

各角色是逻辑责任，不规定包、插件或表数。供应实例退出不删除已发布知识或尚未完成的维护责任。

## 协作与依赖

消费者通过公开查询和计算取得明确版本、覆盖与出处，再按自己的业务要求判断可用性。日历读与供应写分开，独立查询不要求供应刷新、Schedule 或会话装配。工具仅是应用服务调用适配，不直接抓取数据或发布版本。

Schedule 区分 `followUserEnvironment` 与 `explicit`。follow 原子采用用户环境的 timezone、calendar 和 revision，只重算未接受未来；explicit 固定日历身份及 timezone，用户偏好切换不改变它。日历身份绑定与版本政策分开，explicit 仍可选择 latest 或 pinned。已经接受的 Job 保存实际采用版本，不随环境或供应更新改写。

## 主路径与交接

1. 供应适配器取得原数据及出处，完成校验，保留失败或 withheld 等真实处置。
2. 日历发布协调者在自身提交边界保存不可变版本、current 指针与回执，再可靠交出发布事件。
3. 查询返回指定或明确解析的版本，日期计算保留覆盖、出处及失败原因。
4. 日程以公开版本守卫保护最终接受；读完再写或收到事件均不能替代同提交保护。

发布成功后的唤醒或通知失败只恢复交接。供应失败时，旧版本可能仍覆盖部分查询；覆盖不足、查询故障和供应故障不得互相替代。流程见[跨领域关键流程](key-flows.md)。

## 后续设计与维护

日历及供应成员须验证真实来源、校验、版本发布、覆盖、缓存和日期算法。第三方日期或数据解析库是实现候选，不因正文提及而成为已安装依赖，也不能替代供应出处、法定知识或数据许可。
