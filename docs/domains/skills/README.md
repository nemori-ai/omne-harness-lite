# Skill

## 范围与边界

Skill维护可复用方法、说明、正文和资源，以及发现、读取和来源记录。它是工作指导，不是Agent Loop本身；读取正文不执行脚本，也不自动加载全部附件。

一个 Skill 是一个目录，入口是 `SKILL.md`，按三层披露。第一层是名字与一句说明，第二层是入口 `SKILL.md` 的正文，第三层是目录里别的文件。读入口正文是一次返回，没有「启用」状态，不改系统提示词。

定义持有及求值复用[资产](../assets-and-rules/README.md)，实际内容采用归消费者。Skill 没有执行通道：目录里的脚本由 Shell 运行，那是一次普通的工具调用，归[工具](../tool-execution/README.md)和执行环境。Skill 的内容是资产里的一个包。Skill 按能力标识向资产要这个包的读口，不认路径，也不认识材料来自官方层还是租户层。目录加载到本机之后在哪是另一件事：单机装配下它是一个事实，`Skills` 把它告诉 agent，供 Shell 使用。

## 模块角色与事实归属

| 模块角色 | 拥有的知识 |
| --- | --- |
| 方法定义 | 名称/说明、正文、资源及声明依赖 |
| 包校验 | 一个目录是不是合法的 Skill，以及从目录到类别声明（名字、说明、依赖）的投影 |
| 发现与取用 | 此刻合法可用的方法、三层披露的读取、列目录及来源 |
| 提交 | 把一个目录交给资产发布之前的量大小、校验和同名情况说明，发布本身归资产 |
| 消费适配 | 工具返回或命令展开的实际内容，保持原采用依据 |

脚本的运行归工具执行与执行环境，Skill 不持有执行权。

第一层的名字与说明可以常驻在系统提示词里，也可以只出现在搜索结果里。常驻是给模型省一步搜索，不是「能用」的前提。让模型知道有某个具体的 Skill，就是把它常驻了，没有「不常驻但在提示词里提一句」的中间状态。方法知识不归工具执行账，也不因Agent换代丢失已经采用的内容。

## 协作与依赖

Skills读取取得内容和来源，Context或消息消费者按各自规则保存/组装。经工具read形成工具返回，经绑定命令展开形成用户消息内容块，不能统一改成一个日志形状。

一个会话里，Skill 以两种方式存在。常驻的简介装进系统提示词，是采用点上定下的记录。`Skills` 能搜到的，是这个主体此刻合法可用的 Skill，按当下的事实现算，不是采用点上记下的集合。租户新装了一个不常驻的 Skill，已有的会话下一次搜索就能看到，这不是重新装配。判一次变化要不要重新装配，只问它改不改已经定下的上下文。

Skill与Tool依赖沿有效产品绑定；MCP动作不是独立资产，不能临时按资产能力标识把它作为Skill组合成员。需要外部服务沿既有依赖语义，不新增隐式执行资格。

## 主路径与交接

1. 按当下事实现算此刻合法可用的 Skill，呈现名称及说明，消费者按任务选择。常驻的简介已在采用点进了系统提示词。
2. 核验当前读取资格，取得正文或明确资源及其来源。
3. 原消费者保留实际内容，按工具返回或命令展开路径采用。
4. 要运行目录里的脚本时，agent 用 Shell 发起一次普通的工具调用，按工具、权限与环境契约处理结果。Skill 不参与这次调用。

正文更新作用于后续取用，不改已记录内容。读取成功不能证明脚本可执行，附件不可取不能伪造完整方法。

## Skills 的五个命令、提交与元技能

agent 经 `Skills` 这一个入口使用 Skill，入口有五个命令。前四个只读，第五个是提交，没有执行命令。入口稳定，背后有多少个 Skill，入口不变。

| 命令 | 做什么 |
| --- | --- |
| 搜索 | 按任务发现此刻合法可用的 Skill，给出第一层 |
| 读入口 | 读 `SKILL.md` 的正文，给出第二层 |
| 按路径读 | 按目录里的路径读别的文件，给出第三层。路径只能指到包里的文件 |
| 列目录 | 列出一个 Skill 目录里的文件 |
| 提交 | 把一个目录发布到租户名下 |

目录里的脚本和参考资料、模板一样，是第三层的文件，按路径读。读到脚本源码不运行它。要运行时，agent 用 Shell：资产一定先加载到本地，单机装配下 Skill 的目录就在本机的文件系统里，agent 从 `Skills` 的读取结果里知道它在本机的位置，直接运行里面的脚本。这是一次普通的 Shell 工具调用，准入、权限、环境与落点、等待、取消和结果保管全照工具执行与执行环境的规则。Skill 不持有执行权，Shell 的许可不因为脚本来自某个 Skill 而放宽，也不因此收紧。Skill 不向 Shell 里的进程注入设置值。防护与隔离不在这一阶段。

依赖不齐时正文读得到。Skill 仍被合法选入、主体有读取权、正文来源正常时，必需依赖缺席不挡读取，缺什么写在搜索结果与这次读取的结果里。读取资格失效时不取原受限内容。

agent 可以用文件工具或 Shell 在自己的执行落点写一个 Skill 的目录，再用提交命令把它发布到租户名下。每次提交都要人点头。人的命令是同一个发布操作的另一个入口，没有第二套发布流程。agent 不能向组织层提交，也不能代用户提升。流程见[提交 Skill](key-flows.md#f-sk09-提交一个-skill-目录)。

元技能是官方层的一个普通 Skill，常驻，教 agent 怎样写 Skill。它没有特殊机制，只是声明不可替换，租户不能用同名的 Skill 盖住它。它与统一语言里的「meta 能力」不同：meta 能力是系统自带的元工具一类，元技能是一个 Skill。
