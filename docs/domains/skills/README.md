# Skill

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

Skill维护可复用方法、说明、正文和资源，以及发现、读取和来源记录。它是工作指导，不是Agent Loop本身；读取正文不执行脚本，也不自动加载全部附件。

定义持有及求值复用[资产](../assets-and-rules/README.md)，实际内容采用归消费者，脚本执行另经[工具](../tool-execution/README.md)和环境。

## 模块角色与事实归属

| 模块角色 | 拥有的知识 |
| --- | --- |
| 方法定义 | 名称/说明、正文、资源及声明依赖 |
| 发现与取用 | 当前合法方法、按需全文/资源读取及来源 |
| 可接入契约 | 本领域提供可接入的契约：用本领域的词交出描述、内容、资源条目、脚本声明与包字节及其来源。认识调用方体系的那一层归集成方 |

常驻概览与实际全文分层。方法知识不归工具执行账，也不因Agent换代丢失已经采用的内容。

## 协作与依赖

Skills读取交出内容和来源，交出后归接收方。接收方按自己的规则保存或组装，Skill不规定统一的日志形状。

Skill与Tool依赖沿有效产品绑定；MCP动作不是独立资产，不能临时按资产能力标识把它作为Skill组合成员。需要外部服务沿既有依赖语义，不新增隐式执行资格。

## 主路径与交接

1. 在当前合法集合中呈现名称及说明，消费者按任务选择。
2. 核验当前读取权，取得正文或明确资源及其来源。
3. 接收方保留实际内容，按自己的路径采用。
4. 需要脚本时，调用方取得脚本声明与包字节，单独发起执行，按工具、权限与环境契约处理结果。

正文更新作用于后续取用，不改已记录内容。读取成功不能证明脚本可执行，附件不可取不能伪造完整方法。

## 契约与验证导航

方法/取用契约维护定义、读取、脚本声明与包字节导出，消息/Context拥有实际内容采用，工具与环境拥有脚本调用及效果；依赖校验由采用/装配契约承担。

依据为[本域产品设计草案](../../../.meta_harness/design/product/skills/design.md)；已接受约束沿[请求组装](../../architecture/runtime/request-context.md)。验证见[组合入口](../verification.md)。

## 后续设计与维护

发现/读取API、资源寻址、来源/版本复核及脚本声明由方法与资源成员设计，脚本执行由Tool与环境成员设计，安装/发布闭包按真实消费者决定。工作方法资产和本仓工程技能采用表分别归自己的拥有者，不能把产品能力本文当作安装指导。

只改方法读取先读本契约；涉及命令、Context或执行再展开相邻责任。新依赖语义待定不阻塞已明确取用责任。
