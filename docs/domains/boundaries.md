# 责任边界与协作

本页维护已接受的领域工程责任地图、事实拥有者和交接，采用范围见[领域入口](README.md#维护与状态)。系统生命周期、隔离和分层来自已接受架构，不能在这里降低。模块关系沿责任入口展开，精确协议随实际接口或协调者。

## 分解依据

按业务知识、事实权威、不变量、变化和维护任务识别责任。同一流程不证明同一模块，独立责任也不自动需要独立包。目录、Context、线程和存储表不定义业务边界。

[三条分解轴](../architecture/structure.md#三条分解轴)提供共同语境。身份与资源、逻辑工作与执行，以及模式、Context 和环境分别判断。不是每项能力都需要全部对象，纯计算、机械Job和通知不强制Session。

## 责任地图

下表拥有者指应有语义及工程维护责任，不指定现有包名。各入口的领域文档维护者负责域内关系与唯一登记，成员形成后明确接口拥有者；共同边界归系统架构负责人维护。

| 入口及性质 | 拥有的事实或决定 | 交接 |
| --- | --- | --- |
| [身份与授权](identity-and-authorization/README.md)，共同治理 | 主体、成员、登录、授权及准入，内部分责 | 配值归规则，HITL交答复，资源操作核验资格 |
| [资产与规则](assets-and-rules/README.md)，共同治理 | 定义、持有、来源及替换，设置/权限各自求值 | 类别拥有专有业务，装配消费合法候选，可用不等于获准 |
| [工作区](workspaces/README.md)，资源能力 | 参与、实例、地址及关联 | 私有权利不因参与共享，环境负责供给和寿命 |
| [会话与工作](sessions-and-work/README.md)，逻辑治理 | 输入承接、Session/Run、推进权和消费位置 | Agent推进，模型/工具拥有原执行，其他Job由业务治理 |
| [装配交接](assembly-and-handoff/README.md)，集成责任 | 求值、采用、结构绑定和换代 | 来源归治理，推进权归工作，runtime保留实际执行；工具实现的换代归工具执行 |
| [Agent推进](agent-progression/README.md)，执行能力 | Loop求值、动作、扩展位置及推进 | 消费模型/工具结果，不拥有被等待执行的寿命 |
| [模型调用](model-invocation/README.md)，执行能力 | 固定输入、原输出、收场和费用 | 保管与消费分别承接，不执行响应内工具建议 |
| [工具执行](tool-execution/README.md)，执行能力 | 固定调用、等待、结果与实际效果；实现的绑定登记与换代 | 准入、环境和被调用业务各有权威；冻结判定交会话执行 |
| [Context](runtime-context/README.md)，数据/派生能力 | 注册/读取与一次请求计算，内部分责 | 原数据归生产者，实际发出归模型，历史不提供授权 |
| [HITL](human-intervention/README.md)，交接能力 | 请求、呈现、答复及关联 | 原拥有者解释并决定继续，答复不扩大权限 |
| [执行环境](execution-environments/README.md)，资源能力 | 落点、设施及供给/释放 | 逻辑工作区、准入及工具效果分别拥有 |
| [日历](calendars/README.md)，业务能力 | 供应、版本、覆盖及计算 | 日程接受Job，Context/存储不解释日历语义 |
| [日程与Job](schedules-and-jobs/README.md)，业务治理 | 描述、候选、接受、等待取消及整体结果 | 消费日历/执行/通知，不接管Run终态或送达 |
| [通知](notifications/README.md)，业务交付 | 独立发送、目标送达及未完成责任 | 来源工作归发起方，执行完成不表示送达 |
| [Slash Command](slash-commands/README.md)，专有类别 | 识别、绑定、参数及展开 | 交付面识别，受理复核，队列/日志及工作流原拥有者承担 |
| [Skill](skills/README.md)，专有类别 | 方法、资源、发现及读取 | 治理拥有持有，消费者拥有采用，脚本另过Tool/环境 |
| [MCP](mcp/README.md)，专有类别 | 端点、连接、合法发现及桥接 | 凭据沿治理，动作沿Tool，连接恢复不授权重发 |

三个类别补充专有知识，不产生第二套资产身份。其他类别按实际拥有者承接，例如工具定义归工具、Loop Extension归Agent/扩展；不要求每个类别自动建领域目录。

## 协作与依赖方向

消费者使用公开契约，提供者兑现相应承诺，装配入口选择实际实现。业务不深导入提供者或反向读取应用装配；双向消息不要求源码依赖成环。关系图、时序和部署分别表达。

客户端通过 [SDK 与接入层](../architecture/layers-and-dependencies.md)使用完整 Harness。业务维护原语义，共同系统契约维护投影，SDK不携带服务端执行、存储或Cordis闭包；域内接口不自动公开。

三runtime管理独立寿命，Session按业务逻辑治理。等待是数据和控制依赖，不授予执行寿命所有权。共同控制须显式发起并分别确认，取消、实际停止与效果撤回不同。

共同治理不反向依赖所有类别实现，专有业务通过公开契约参与。定义与资源分别拥有，通用资产管理不能同时控制连接、脚本、模型与工作终态。

## 关键接缝与组合承担者

| 场景 | 组合承担者 | 必须保持 |
| --- | --- | --- |
| 权限、人工及资源使用 | 动作发起及实际资源操作 | 配值/准入/答复/环境分别成立，适用时点核验 |
| 推进者换代 | 原工作与装配协调者 | 唯一推进权、消费位置及原调用责任保持 |
| 请求形成并发出 | 请求发起方、组装与模型 | 固定实际采用，未来动作重新准入 |
| 执行结束而消费者离线 | 原调用、保管与实际消费者 | 可靠接手前责任继续，采用不等于收场 |
| 工具等待时环境查询失败 | 工具、环境与调用方 | 查询不可用不证明资源丢失，不自动重建重放 |
| Job完成而通知未达 | 日程/Job协调者 | 补送不重做执行，通知确认送达，日程判整体成功 |
| 命令展开Skill后调用MCP并换代 | 受理及工作/调用协调者 | 已采用正文和原输入保持，连接/等待者不覆盖执行事实 |

本表定位责任，不定义认领、同提交或跨节点协议。精确契约及证据随实际协调者，上层约束沿[运行](../architecture/runtime/README.md)、[数据](../architecture/data-and-state.md)与[安全](../architecture/security/README.md)。

## 横向能力与阶段范围

存储按契约保存读取，不拥有业务含义。时间不能替代各业务期限和因果顺序。日志/遥测用于诊断，不替代提交或授权。这些关系沿[跨系统约定](../architecture/cross-cutting-concepts.md)、实际契约及[验证](verification.md)。

Cordis约束集成的装配、注入、作用域和生命周期，领域语义独立。进程及节点归[拓扑](../architecture/deployment/README.md)，不从地图推导一责任一进程。目标能力组及责任映射归[产品包组织](../package-organization.md#责任与能力组)，开发workspace归[源码布局](../workspace.md)。本页拥有业务责任，包组织拥有维护落点；现有包路径不反向定义两者。

持续利益对齐是长期承诺，当前不开展专项设计或实现，不创建空领域。0.0.0至0.1.0允许有收益的破坏性重构，维护有效契约、真实消费者与相称验证。

## 文档内容与登记

应有总页为首页、本文、扩展规则与组合验证，17项入口均需README。负责人已接受这些正文；结构要求、正文接受与产品实现分别判断。

各责任需要六个章节：范围与边界、模块角色与事实归属、协作与依赖、主路径与交接、契约与验证导航、后续设计与维护。须回答本责任问题，通用模板、裸链接与占位不证明内容充分。

根documentation.json维护四个总页，局部登记维护各责任正文及章节，同一目标只登记一次。局部owner依据指责任地图，expectation依据指本节。adopted只表示应有结构获授权，不记录正文或实现状态；本区正文接受范围由首页维护。

新增独立专题先明确阅读任务、责任和必要内容，再登记预期；尚未写出继续报告缺项。占位沿文档治理。可检查、语义正确、人类阅读和运行符合分别判断，不以数量或inspectable冒充完成。

## 后续设计与维护入口

原未决从[架构集中入口](../architecture/README.md#未决事项与后续设计入口)展开，责任页进一步指出依赖范围。无精确成员时，具名能力和协调设计承担后续接口义务，不由目录决定包数或API。

多入口含义变化先收敛事实与组合拥有者，再同步成员及导航。内部算法或既有承诺修复不重做全系统设计。冲突只暂停相关部分，原未迁源继续承担消费者，本轮不删除。
