# 工作区

## 范围与边界

工作区维护逻辑身份、参与、实例、地址和资源来源，支持多租户参与。逻辑工作区、文件路径、实际资源和参与授权分开。

本责任不拥有租户登录或私有权利，实际环境及资源寿命由[执行环境](../execution-environments/README.md)承担。

## 模块角色与事实归属

| 模块角色 | 事实与责任 |
| --- | --- |
| 工作区治理 | 逻辑身份、参与及获准资源关联 |
| 实例和地址 | 逻辑资源到实际实例/位置的关联及有效条件 |
| 来源读取 | 共享/local来源及本工作区允许的资源贡献 |
| 环境适配消费者 | 使用明确关联取得获准设施，不改工作区事实 |

地址用于定位，不是访问许可；实例重建也不自动创造另一个逻辑工作区。

## 协作与依赖

工作区内容按已接受来源规则交[资产/规则](../assets-and-rules/README.md)和[Context](../runtime-context/README.md)，不混成统一覆盖算法。共享实例不使参与租户共享私有资产、设置或凭据。

环境供给消费获准关联；Session使用选定工作区的条件，不成为全部实例与数据的寿命拥有者。

## 主路径与交接

1. 核验参与主体和请求范围，选择有效实例及地址关联。
2. 读取当前主体允许的资源来源，分别交资产、配置与Context消费者。
3. 实际动作取得满足条件的环境，按资源访问契约继续核验。
4. 实例或地址失效时由工作区/环境各自报告，调用方保留原工作和效果归属。

目录不可达不证明托管数据已丢失，不能因此重放原工具或复制其他租户资源。
