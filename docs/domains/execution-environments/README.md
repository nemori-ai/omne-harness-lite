# 执行环境与资源

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。「模块角色与事实归属」表的「条件选择协调」一行按候选修订，待拥有者重新接受。

## 范围与边界

环境提供执行落点、设施、隔离及资源，声明供给、释放和托管数据恢复条件。工作区逻辑身份、实际环境、工具调用及租户权限分开。

可在个人设备或集群采用不同提供者，不能用部署位置改变业务语义或推定热迁移。

## 模块角色与事实归属

| 模块角色 | 知识与责任 |
| --- | --- |
| 条件选择协调（域外：发起协调者与工具宿主） | 按工具/模式及资格确定允许落点 |
| 环境提供者 | 实际设施、资源身份、可用状态和生命周期 |
| 资源/数据托管 | 持有、恢复与清理的明确依据 |
| 执行适配 | 把获准调用交实际设施，不重定义工具业务 |
| 观察/控制 | 查询与控制的实际结果及不可观察解释 |

环境资源不等于Session子对象，逻辑关联不能替代实际关闭确认。

## 协作与依赖

消费获准工作区关联和工具设施要求，同时满足授权与环境策略。环境可用不代表动作获准，HITL也不能无限放宽环境限制。

恶意代码设防沿[执行隔离](../../architecture/security/execution-isolation.md)，包括允许的同进程受限执行设计；普通插件、租户标签或Cordis作用域不能提供隔离。具体Node API/通信机制按已接受边界设计，不能悄悄改成可信第三方前提。

## 主路径与交接

1. 发起方提供合法资源和工具要求，选择满足当前策略的设施。
2. 提供者分配或关联资源，报告就绪及适用条件。
3. 工具按原调用执行，环境分别观察和控制实际资源。
4. 资源失效时区分不可观察、确认丢失及可恢复条件；分别完成数据恢复与资源释放。

环境重建不自动恢复原执行或证明原动作无效果。副作用、迁移和托管数据责任分别核对。

## 契约与验证导航

环境契约拥有设施、资源及可用条件，托管契约拥有数据恢复，工具拥有实际效果。选择/释放/跨节点资源协议随提供者与协调者。

上层沿[运行环境](../../architecture/runtime/execution-environment.md)、[部署拓扑](../../architecture/deployment/README.md)及安全隔离；产品依据[本域产品设计草案](../../../.meta_harness/design/product/execution-environments/design.md)。验证见[组合入口](../verification.md)。

## 后续设计与维护

实际设施目录、隔离机制、限额、资源认领/释放及数据恢复由环境和安全提供者设计。同进程恶意代码的具体保护与验证仍需专门设计，不能从架构要求推定已实现。

局部提供者维护读环境/安全契约；涉及原效果或逻辑数据再读工具与工作区。资源探针不可用时保留未知，不能假报回收或成功。
