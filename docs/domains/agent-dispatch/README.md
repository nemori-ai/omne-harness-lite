# 派发

## 范围与边界

派发让一个会话里的 agent 把一件事交给另一个 agent，并让 agent 之间能递话。它管三件事：一次交托怎样成立与收场；交托唯一的那份报告怎样恰好交回一次；一条消息许不许从一个会话送到另一个会话。

派发是接在核心系统上的插件。核心域的成员不依赖它；去掉它，会话、agent、模型与工具原有的流程不变，只是 agent 手里没有工具 `Agents`。

一个 agent 要另一个 agent 做点什么，有三种事，形状不同：

| 要对方做什么 | 发起方等不等 | 走哪条路 |
| --- | --- | --- |
| 做一份工作，交回一份报告 | 等到报告、失败或撤回 | 派发：`spawn` 或 `delegate` |
| 把一件事整个接过去 | 不等，建成就走 | 派发：`handoff` |
| 知道一句话、答一个问题 | 不等 | 消息 |

派发不是会话的一部分，也不是一次工具调用的一部分。一次派发同时牵着两个会话，放进任何一个会话的日志，另一个会话就得去写别人的日志；派发方那次调用收场之后，报告仍可能才到，所以它也不能住在调用里。派发因此有自己的登记。

## 模块角色与事实归属

| 模块角色 | 责任 |
| --- | --- |
| 派发登记 | 一次派发的身份、方式、目标定义、建出的会话、状态；撤回的请求与结局 |
| 报告 | 一次派发至多一份的报告，以及它交到了哪里 |
| 消息的资格 | 一条消息许不许从这个会话送到那个会话 |
| 对账 | 结果不知道的步骤按原身份重做；进程重建之后接着走 |
| 会话 | 子会话与独立交接出的主会话的身份、关系、层数、值守、归档与级联；会话的目录与过滤；`spawn` 的子会话怎样从派发方的对话分叉 |
| Tool | 派发方那次调用的等待、暂停、收场 |
| Agent 与 Request Context | 被派发的那一轮怎样推进；一次模型请求的输入怎样算 |

这是逻辑分工，不裁定成员的划分。成员见 [Dispatch 规格](../../../packages/dispatch/SPEC.md)。

## 协作与依赖

派发认识会话、Tool 与 Agent 定义目录公开的契约，它们都不认识派发。认识会话的只有一个适配成员：它登记三个输入来源，以系统主体建会话、送输入、读输入的去向、取消一轮。认识 Tool 的也只有一个适配成员：它带来「等报告」这一种等待的请求契约与桥。

派发向[身份与授权](../identity-and-authorization/README.md)问资格：许不许派发，许不许发消息。它以系统主体办事，凭系统动作矩阵里建会话、送输入、读去向三行；它送进会话的输入作者角色是系统提醒，不成为租户里任何人说的话。

找一个 agent 就是找一个会话。谁和我是什么关系、有人还是无人值守、用的哪个定义，都是[会话](../sessions-and-work/README.md)的事实，由会话的目录给出并支持过滤。派发只在这上面添一样：这次派发现在怎样。

被派发的会话是一个普通的会话。子会话无人值守：它的 agent 手里没有要人在场的命令，需要人决定的动作被拒绝；它有疑问就给派发它的 agent 发消息，或写进报告。

## 主路径与交接

带报告的派发：

1. 派发方的 agent 调 `Agents` 的 `dispatch`。派发核资格与上限，用一次提交登记这次派发。
2. 适配成员以系统主体建子会话，起始输入是交给它的工作。会话的身份由派发的身份派生，重做认回同一个。
3. 派发方的调用发起即在后台，挂着等报告的等待，派发方那一轮接着走。命令声明了后台，调用必须带意图，后台调用列表靠它说明这个 agent 在做什么。
4. 被派发的 agent 交回报告，或它的会话安静下来（没有在跑的一轮、待处理的输入与后台调用）而以最近一轮的最终回复为报告。派发用一次提交让报告成立。
5. 派发把报告交给那次调用的等待，调用以它收场，结局作为一条提醒回到派发方，提醒头写明调用的短号与意图。等待已经关了，就把报告作为一条输入送进派发方的会话并叫醒它。

报告交到哪只有两个位置，由 Tool 对「这次等待还在不在」的一次提交裁定，所以不会两处都交，也不会两处都不交。这条性质由模型 `DispatchReport` 守。

交接的形在每一处相同：交的一方凭自己耐久的事实持有请求，接的一方用自己的一次提交接下，结果不知道就按原身份再交。

## 失败、未知与取消

| 发生了什么 | 派发 | 被派发的会话 | 派发方的调用 |
| --- | --- | --- | --- |
| 派发方那一轮被取消或被插队 | 不变 | 不变 | 在后台照旧等，报告到了作为结局提醒送到 |
| 人或 agent 停了这次后台调用 | 不变 | 不变 | 等待关闭，以说明收场；报告以后作输入送到 |
| 进程重建 | 对账接着走 | 不变 | 按 Tool 的恢复规则 |
| 被派发的那一轮失败或被取消，没有报告 | 失败，带原因 | 不变 | 得到失败 |
| 派发方撤回 | 已撤回；请求停那一轮 | 不归档，已有的效果不撤 | 得到撤回 |
| 派发方的会话归档 | 进行中的记为已撤回 | 子会话随父归档；独立交接出的不随 | 等待关闭 |
| 建会话的结果不知道 | 保持原状态，按原身份再建 | 至多一个 | 继续等 |

请求停止、证实停下、外部效果三样分别报告。撤回不声称效果已撤。

## 验证责任

- 报告至多一份、恰好交付一次、撤回与报告互斥、调用总有结果：模型 `DispatchReport`，随成员保存。
- 两端同租户、深度上限、一次受理至多一个会话、消息不改派发：成员的契约测试。
- 会话的关系、值守与目录过滤：[Session 规格](../../../packages/session/SPEC.md)。
- 调用条件与两种等待：[Tool 规格](../../../packages/tool/SPEC.md)。
- 系统主体的三行用途：[Identity 规格](../../../packages/identity/SPEC.md)。
