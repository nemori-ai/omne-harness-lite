# 工具执行

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

工具定义说明可调用动作，工具runtime承担一次实际执行、等待、结果及外部效果。工具入口可以访问领域能力，但不接管该领域事实和业务完成。

独立工具调用不强制Session；环境供给、准入及调用方的业务采用分别负责。工具结果和执行账归本责任。会话在收到工具结果时记下这笔账。同一主体、同一费用来源的更后修订替换先前的已知金额，并标明迟到。流式步骤消费 `packages/common/stream-arrival`。已封闭内容块消费 `packages/common/content-block`。

## 模块角色与事实归属

| 模块角色 | 知识与事实 |
| --- | --- |
| 工具定义 | 装载时由资产的治理声明与实现的形状派生：输入、执行条件、前后台、可编程调用许可及能力声明 |
| 绑定登记表 | 按登记键（来源层、能力身份、资产版本）持有已装载实现的贡献，同键冲突与后继，固定请求按键解析 |
| 换代协调者 | 实现的装载、卸载与替换，按会话引用保留贡献 |
| 发起/准入协调 | 可信调用方式及来源、生效参数、当前资格及环境要求 |
| 执行提供者 | 原调用、运行/内部等待、真实结果和效果确定性 |
| 控制与收场 | 取消、转后台等操作的实际结果 |
| 原消费者 | 结果保管/可靠承接及业务继续，按原契约分责 |

内部等待不是完成，效果未知不同于已知没有执行。原调用和包装工具的业务对象分别拥有。交给会话日志的事实见[工具规格](../../../packages/tool/tool-contract/SPEC.md#必要持久事实与确认)。

工具实现变化时，会话常驻工具的 name 与参数形状在会话内不变。常驻规则与采用点判定见[工具规格](../../../packages/tool/tool-contract/SPEC.md#会话常驻规则r1r5)。Tool 只给冻结判定与原因 `tool-shape-lost`。会话冻结由[会话与工作](../sessions-and-work/README.md)执行。

## 协作与依赖

执行消费当前合法定义、准入及环境条件，按公开接口调用具体能力。MCP动作由[桥接](../mcp/README.md)成为工具条目，连接状态不替代执行账。

人工等待交[HITL](../human-intervention/README.md)，答复回原工具等待点，后续按原资格解释。后台寿命按工具声明管理，不能从Agent或Run结束自动推断其结束。

Agent 脚本组合或编排工具受[可编程调用许可](../../../.meta_harness/design/product/tool-execution/design.md#可编程调用许可)约束。工具作者声明许可，发起协调者提供可信来源，Tool 执行准入核对目标许可。独立 SDK 消费与脚本编排的边界由[定义专题](../../../packages/tool/tool-contract/SPEC.md#可编程调用的定义与准入)细化。

## 主路径与交接

1. 固定实际参数并取得相应准入和环境条件，按定义发起原调用。
2. 提供者执行或进入内部等待，保留原调用及可观察状态。
3. 控制请求明确目标并记录受理与实际收场，外部效果按已知/未知报告。
4. 将原结果交实际消费者，按工具的保留/清理协议完成责任。

环境失联不证明工具未执行。确认连续性丢失也不自动重放原动作；模型有ACK不意味着工具采用同一协议。

## 契约与验证导航

工具契约维护输入、执行/等待、控制及效果，具体提供者维护环境或协议兑现；发起/消费协调者维护资格与可靠交接。工具失败的精确分类由原工具/消息契约细化。

上层沿[工具runtime](../../architecture/runtime/tool-runtime.md)、[执行环境](../../architecture/runtime/execution-environment.md)、[安全](../../architecture/security/README.md)；产品依据[产品正文](../../../.meta_harness/design/product/tool-execution/design.md)。验证见[组合入口](../verification.md)。

## 后续设计与维护

不可用应答分类、执行账、结果保留及可靠恢复、提供者取消能力由工具和协调者设计。不能给不可撤回的外部效果发明通用回滚。

只改一个工具沿自身业务契约及公共执行约定；跨权限/环境/工作消费才展开相关责任。真实效果测试缺环境时报告无法验证，不用mock成功声称兑现。
