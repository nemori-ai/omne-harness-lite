# 运行Context与请求组装

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

本责任包含两块能力。Runtime Context 是作用域内共享数据的供给中介与合并协议：按资格供给块的当前值与变化，核对需要与登记，合并状态块的更新，不拥有任何块的事实。Request Context 是一次模型请求输入的派生计算与装入保证：从历史依据、Runtime Context 读取结果、工具定义与模型档案算出请求候选、装入裁定与压缩计划，不发请求、不固定采用、不保存历史。两者有不同变化理由，不能和执行环境、会话历史或权限合成一个通用 Context 对象。

本域只认通用角色：作用域持有者、生产者、写者、消费者类、集成方、协调者、历史持有者、贡献者。它不导入会话、Agent、模型、工具、执行环境的契约；要供给块、读块、组装请求的一方依赖本域的契约。本版的作用域持有者是会话。

原内容和业务事实归生产者，派生输入不改历史；模型实际发出及收场归[模型调用](../model-invocation/README.md)。

## 模块角色与事实归属

| 模块角色 | 事实或计算 |
| --- | --- |
| 块的语义拥有者 | 块声明：键、形状、消费者类、必需、披露、前值、变化频率、恢复方式 |
| 生产者与写者 | 供给块的当前值；状态块的更新提案 |
| 作用域持有者 | 注册（块与需要绑定的清单）、读取资格的签发与撤销、步提交、变化提醒的追加与保存 |
| 供给中介（Runtime Context） | 登记表、生产者表、需要绑定解析、当前投影、观察链与游标、资格核对、步合并、变化材料 |
| 请求组装（Request Context） | 历史投影、系统提示词组装、工具声明投影、快照与提醒放置、表示选择、预算裁定、七层拼装与覆盖证据 |
| 压缩计划 | 计划、步请求与进度推导；模型调用归协调者 |
| 贡献登记面 | 提示词贡献（有序段、变量）的登记与作用域遮蔽 |
| 发起协调者 | 固定实际采用并复核最终条件；记录覆盖证据与快照锚点 |

不可重算会话数据与可重算投影分别维护，缓存不是第二权威。交给作用域持有者的事实（注册、步提交、变化提醒、压缩转换）分别见 [runtime-context-contract 规格](../../../packages/context/runtime-context-contract/SPEC.md)和 [request-context-contract 规格](../../../packages/context/request-context-contract/SPEC.md)。

## 协作与依赖

集成方知道被集成方；被集成方对外声明自己供什么、要什么，不知道被谁集成。块声明归值的语义拥有者；消费者以自己的形状声明需要；集成方在登记时把需要绑到块并提供翻译。供给中介不是让各方互相认识的通道，也不向任何领域发指令。

作用域持有者决定注册，生产者决定块语义。模型、工具和扩展可以有不同读取资格，工具或扩展私有的结构化授权不因在块里就送给模型。授权域与工具不直接读模式块：授权域声明自己的决定模式需要，由持有者的装配适配器翻译；工具的目标环境是工具自己的设置，会话模式只是设置在会话层的覆盖值，求值归协调者。

请求组装消费合法历史、定义和工具声明，读取结果由协调者以模型资格读得后传入，组装不读供给中介。压缩与模态转换形成可追溯派生，不覆盖原件。Skill 取用和命令展开的实际内容沿自己的原路径进入历史，不偷偷变成系统提示词。

## 主路径与交接

1. 作用域创建时持有者固定注册：汇总消费者的需要与集成方的绑定，必需项固定、可选项可增删；为读者签发读取资格。
2. 执行开始或挂接建立时，读者按资格取得当前完整快照；运行中按游标取变化。空闲期间的推送可丢，下次读当前值。
3. 供给块由生产者发布；状态块的更新随动作结果回到持有者，持有者在步边界合并成步提交。模型可读块的变化经变化材料成为追加的提醒。
4. 发起方以模型资格读取结果、历史依据、提示词贡献、工具定义与模型选择形成请求候选；完整读取时快照提醒锚定在历史尾部，逐请求变化的块进尾部易变提醒。
5. 选择模态表示，核对完整限额；装不下时出压缩计划，修剪步先于摘要步，调用由协调者发起，转换由持有者与协调者共同提交后重算。
6. 扩展改参或输入变化时重新校验，协调者固定本次采用依据后交模型执行，覆盖证据与快照锚点随记录回传。

已发输入不随后续更新改写。预算失败保留原会话与历史，不循环造 Run；移除可选块不删共享源，也不在恢复时无条件加回。

## 契约与验证导航

供给契约拥有声明、需要、注册、资格、读取与步提交；生产者拥有原块；请求计算拥有派生、裁定、计划与覆盖证据；发起协调者拥有一致采用；历史持有者拥有历史视图、共同提交与未结工作集合。快照、压缩、缓存及版本协议随实际成员。

成员分两块各四段：契约、Cordis 服务定义、机制实现、Service 实现，见[能力组](../../../packages/context/README.md)。上层沿 [Runtime Context](../../architecture/runtime/runtime-context.md)、[请求输入](../../architecture/runtime/request-context.md)、[数据与状态](../../architecture/data-and-state.md)。产品依据[运行感知与一次模型请求](../../../.meta_harness/design/product/runtime-context/design.md)。验证覆盖长期积累与资格失效，见[组合入口](../verification.md)。

## 后续设计与维护

完整快照前值可选，状态变化提醒表达获准实际前后关系，见[当前感知规则](../../../.meta_harness/design/product/runtime-context/design.md#5-当前值与变化感知)。精确表示、锚点往返、历史视图读口与 epoch、缓存键由成员契约细化；默认策略数值是可配置初值，另定实际规模和性能数值，不编统一阈值。值的持久化端口归存储线。

只改生产者块不必通读整个运行系统；涉及读取资格、步提交、压缩或请求固定才展开邻接责任。长期会话开销须有可测责任，不能为性能跳过访问控制。
