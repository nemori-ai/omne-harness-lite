# 运行Context与请求组装

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

本责任包含Runtime Context的注册/读取/更新，以及一次模型请求的派生输入计算。两者有不同变化理由，不能和执行环境、会话历史或权限合成一个通用Context对象。

原内容和业务事实归生产者，派生输入不改历史；模型实际发出及收场归[模型调用](../model-invocation/README.md)。

## 模块角色与事实归属

| 模块角色 | 事实或计算 |
| --- | --- |
| 数据生产者 | 原内容、来源、更新及读取资格 |
| 注册与供给 | 当前块、消费者、来源配置及必要关系 |
| 变化/历史适配 | 合法提醒和实际读取关联，不替代当前授权 |
| 请求组装 | 提示词、历史、工具声明、可读块及模型参数的投影 |
| 模态与预算计算 | 按模型能力选表示、评估完整输入及压缩 |
| 发起协调 | 固定实际采用并复核最终条件 |

不可重算会话数据与可重算投影分别维护，缓存不是第二权威。

## 协作与依赖

会话决定注册业务，生产者决定块语义。模型、工具和扩展可以有不同读取资格，工具/扩展私有结构化授权不因在Context中就送给模型。

请求组装消费合法历史、定义和工具声明，压缩/模态转换形成可追溯派生，不覆盖原件。Skill取用和命令展开的实际内容沿自己的原路径进入历史，不偷偷变成系统提示词。

## 主路径与交接

1. attempt按资格取得当前可读块和有效注册关系，空闲期间更新由当前快照承接。
2. 发起方选择适用历史、提示词、工具及模型配置，形成候选模型输入。
3. 选择可用模态表示，核对完整限额，按规则压缩并再次复核。
4. 扩展改参或输入变化时重新校验，固定本次采用依据后交模型执行。

已发输入不随后续更新改写。预算失败保留原会话/历史，不循环造Run；移除可选块不删共享源，也不在恢复时无条件加回。

## 契约与验证导航

供给契约拥有注册/读取及更新，生产者拥有原块和资格，请求计算拥有派生与预算，发起协调者拥有一致采用。快照/压缩/缓存及版本协议随实际成员。

上层沿[Runtime Context](../../architecture/runtime/runtime-context.md)、[请求输入](../../architecture/runtime/request-context.md)、[数据与状态](../../architecture/data-and-state.md)。产品依据[产品正文](../../../.meta_harness/design/product/runtime-context/design.md)、[产品正文](../../../.meta_harness/design/product/runtime-context/design.md)、PF-015。验证覆盖长期积累与资格失效，见[组合入口](../verification.md)。

## 后续设计与维护

完整快照前值可选，状态变化提醒表达获准实际前后关系，见[当前感知规则](../../../.meta_harness/design/product/runtime-context/design.md#5-当前值与变化感知)。精确表示与关联仍待技术设计。索引、增量缓存、压缩算法、工作区指导读取及一致性协议由Context/消息/请求拥有者细化；实际规模和性能数值另定，不编统一阈值。

只改生产者块不必通读整个运行系统；涉及读取资格、压缩或请求固定才展开邻接责任。长期会话开销须有可测责任，不能为性能跳过访问控制。
