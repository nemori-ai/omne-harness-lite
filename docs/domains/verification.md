# 组合验证与符合性

本页维护组合性质、承担者和检查路径，正文已获负责人接受，采用范围见[领域入口](README.md#维护与状态)。验证资源随实际成员、协调应用或工具；单次输出留tmp，不建立第二套SPEC或测试。

## 组合性质与承担者

| 组合 | 要建立的性质 | 证据责任 |
| --- | --- | --- |
| 身份、权限、HITL与资源 | 原主体/范围可核验，答复不扩大资格，继续时条件仍有效 | 准入/资源协调者及参与方 |
| Session、装配与Agent | 唯一推进，换代不丢消费位置，三runtime独立 | 原工作/装配协调者及runtime |
| Context、请求与模型 | 固定采用来源，变化不污染请求，多模态/限额/历史完整 | 发起/组装协调者、生产者与模型 |
| 原执行、保管与消费 | 接手前责任保持，替换不自动重做执行或清理结果 | 原调用/保管/消费者及协调者 |
| 工具、环境与外部服务 | 失联与效果未知分开，恢复不自动重放，准入/资源各自成立 | 工具/环境及实际调用协调者 |
| 日历、Job与通知 | 接受依据固定，结果各自权威，补送不重做执行 | Job协调者及日历/通知 |
| 命令、Skill与MCP | 保留实际展开内容，读不等于脚本执行，连接/实例更新不重发 | 受理/工作协调者及类别、Tool/Context |

协调者维护前提、提交、失败及在途责任，局部通过不证明组合成立。高风险机制首次扩散前取得相称真实组合证据；精确判据随实际契约拥有者。

## 文档是否符合要求

[文档治理](../engineering/documentation.md)维护质量与留空，[责任地图](boundaries.md#文档内容与登记)维护本区内容。根及局部登记唯一拥有预期，inventory观察缺文件/章节、占位和unknown，docs-check核对引用与镜像。

inspectable只表示支持的结构存在。分责是否充分、是否复制精确契约、是否承接上游承诺，须通过表达评审判断；责任选择及计划分别判断。实际人类体验由读者观察，不由作者或agent自查替代。

## 设计与实现如何对照

先定位承诺、拥有者和采用范围，再读取对应修订的公开契约、派生关系及真实证据。包名、导入图和启动成功不反向定义领域或证明全部保证。

| 观察 | 入口及限制 |
| --- | --- |
| 文件、章节与导航 | make docs-check、make docs-inventory，不证明语义或采用 |
| 源码/类型、声明与方向 | [检查工具](../../tools/ts-checks/README_ZH.md)及实际成员，保留解析unknown |
| 入口及安装闭包 | 独立消费实际 exports 和产物，并在 SDK 声明支持的平台上验证；只检查 manifest 不够 |
| 并发、失败、取消和恢复 | 实际协调契约的模型/测试/探针及装配，有限前提不称无条件证明 |
| 长期积累与性能 | 成员冷加载、追加、组装、恢复及资源度量，不编统一阈值 |
| 阅读与维护成本 | 代表任务定位、读取及共同修改观察，目录短不证明效率 |

沿[项目验证](../verification.md)、[质量规范](../engineering/quality.md)、[架构论证](../architecture/assurance.md)和[clean-loop](../clean-loop.md)按风险选检查，不给文档任务强制全套产品测试，不新增门禁。

包目标布局与实际源码分别读取。[产品包组织](../package-organization.md#现有成员与工具适配)列明模板及IC路径投影尚未适配的范围，当前静态结果不自动覆盖新组及角色依赖。工具拥有者须保留原唯一性和精确例外后适配，未覆盖不写成整体符合。

## 报告与口径

报告全量存量、本次增减、未覆盖和无法判定。缺资料、缺实现、待采用、未执行及偏离分别给拥有者/影响；工具不支持的性质由评审和真实验证承接。

比较使用独立登记及依据源。新目标、章节、拥有者或依据字节变化可能成为measurement-change，不把新增覆盖算历史偏离消除。方法见[spec-tools](../../tools/spec-tools/README.md#文档目标与缺项计量)。

高风险规则实际采用后才阻断相应交付，其他按风险处置且红项逐条交代。本区没有运行证据宣称并发、恢复、安全、性能或SDK闭包全部符合。

## 后续验证与阅读任务

用租户冲突、换代中原模型调用、环境失联、HITL迟到、Job完成通知未达及三类别联动定位责任，走到拒绝/失败分支。无人承接下一步是文档缺口，不能只补箭头。

通知对象、跨节点交接、快照/认领/同提交及SDK范围沿[架构未决](../architecture/README.md#未决事项与后续设计入口)和责任页。无成员时保持具名义务，形成实际拥有者后明确交接正文和验证，不凭目录说完成。
