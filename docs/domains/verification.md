# 组合验证与符合性

本页维护组合性质、承担者和检查路径。验证资源随实际成员、协调应用或工具；单次输出留tmp，不建立第二套SPEC或测试。

## 组合性质与承担者

| 组合 | 要建立的性质 | 证据责任 |
| --- | --- | --- |
| 身份、权限、HITL与资源 | 原主体/范围可核验，答复不扩大资格，继续时条件仍有效 | 准入/资源协调者及参与方 |
| Session、装配与Agent | 唯一推进，换代不丢消费位置，三runtime独立；冻结只在采用点成立且不可逆，冻结的会话可以归档，撤销归档回到冻结 | 原工作/装配协调者及runtime |
| Context、请求与模型 | 固定采用来源，变化不污染请求，多模态/限额/历史完整 | 发起/组装协调者、生产者与模型 |
| 原执行、保管与消费 | 接手前责任保持，替换不自动重做执行或清理结果 | 原调用/保管/消费者及协调者 |
| 工具、环境与外部服务 | 失联与效果未知分开，恢复不自动重放，准入/资源各自成立；工具实现的装载、卸载与替换满足[完全动态目标](../requirements.md#完全动态目标sys-dynamic)对工具的判据，验证义务见[工具验证](../../packages/tool/SPEC.md#不变式) | 工具/环境及实际调用协调者 |
| 日历、Job与通知 | 接受依据固定，结果各自权威，补送不重做执行 | Job协调者及日历/通知 |
| 命令、Skill与MCP | 保留实际展开内容，读不等于脚本执行，连接/实例更新不重发 | 受理/工作协调者及类别、Tool/Context |

协调者维护前提、提交、失败及在途责任，局部通过不证明组合成立。高风险机制首次扩散前取得相称真实组合证据；精确判据随实际契约拥有者。
