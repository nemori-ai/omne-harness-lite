# 身份与授权

本页维护已接受的应然模块分工与公开协作，采用范围见[领域入口](../README.md#维护与状态)。引用的上游约束保持原采用范围；正文接受不表示当前代码已实现。

## 范围与边界

本责任承接账号、组织成员、租户、登录和授权治理，并为实际操作提供可信主体及准入依据。账号是全局身份，租户是组织与账号关联下的隔离身份，工作区不是租户的下级身份。

权限配值由[资产与规则](../assets-and-rules/README.md)求值，人工答复由[HITL](../human-intervention/README.md)交付；实际资源操作仍保护自己的访问边界。角色或管理员身份不自动取得他人的私有数据。

## 模块角色与事实归属

| 模块角色 | 拥有的事实与责任 |
| --- | --- |
| 主体与成员治理 | 账号、组织成员、租户关联及有效资格 |
| 登录与入口验证 | 登录状态、当前所选租户及认证材料解释 |
| 授权状态管理 | 原授权、适用操作、作用域和撤销/消耗事实 |
| 动作准入 | 消费权限与授权依据，返回可解释的准入决定 |
| 资源操作 | 使用时核验实际资源及动作条件，记录真实结果 |

这些角色可以独立维护，不合成可任意写全部状态的管理对象。身份、授权依据与资源所有权分别表达。

## 协作与依赖

经登录状态进入治理服务时，治理入口拒绝请求显式租户与该登录当前租户的冲突，调用方先切换或使用匹配登录。这条规则只管治理入口；其他入口按各自的访问契约核对显式租户。匹配只解决入口身份，不代替资源授权。

准入消费已认可的权限来源及当前操作，不依赖UI选中项或Cordis Context作身份默认值。业务、后台、恢复和独立调用均遵循对应访问契约；工作区参与不是权限来源。

## 主路径与交接

1. 入口验证登录及显式范围，拒绝租户冲突。
2. 实际操作确定资源、动作和生效参数，取得适用权限及授权依据。
3. 明确禁止由准入拒绝；需要人判断时交原决策请求，答复按原规则解释。
4. 继续执行前核验当前资格和资源条件，结果由实际能力记录。

资格服务不可用不能伪装允许。等待或撤权后旧批准不自动沿用；原执行是否停止另按控制契约处理，不能从撤权推断零副作用。

## 契约与验证导航

主体/登录契约负责身份和冲突，授权契约负责资格及失效，动作协调者负责判断与实际提交的关系。精确结果集合、缓存失效、同提交及跨节点可信依据随这些拥有者。

上层沿[身份与授权架构](../../architecture/security/identity-and-authorization.md)、[跨系统身份约定](../../architecture/cross-cutting-concepts.md#公共数据模型与身份)。产品依据见[本域产品正文](../../../.meta_harness/design/product/identity-and-authorization/design.md)，范围及状态沿该源判断。组合核对走[验证](../verification.md)。

## 后续设计与维护

组织创作委托及跨系统授权按原架构未决由身份/治理负责人裁定。灾后开放的当前阶段边界归[身份安全架构](../../architecture/security/identity-and-authorization.md#本阶段不提供的打开路径)。精确认证协议、许可凭证、授权缓存和原子核验由对应成员设计，不在本页补默认机制。

局部身份维护读相关契约即止；跨资源、人工或恢复才展开相邻入口。新资格含义未定只暂停相应消费；原登录、准入及资源事实仍有各自拥有者。
