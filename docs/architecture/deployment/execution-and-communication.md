# 执行资源、通信与基础设施

本页说明进程、线程、通信和基础设施应怎样承接运行负载，不规定具体执行引擎或传输实现。

状态：已接受的目标架构。采用范围及阅读路径见[部署入口](README.md)。

## 进程与线程模型

### 按工作负载分配执行资源

模型须同时满足[质量优先级](../drivers-and-constraints.md#取舍优先级)、三个 runtime 的独立生命周期和[不可信代码隔离](../security/execution-isolation.md#插件装配与代码信任)。独立生命周期不要求独占线程或进程，共享执行资源也不能取消已有保证。

| 工作负载 | 执行模型要求 |
|---|---|
| 请求受理、控制和短状态推进 | 单次占用执行资源的工作有界，持续处理就绪请求。不能让长任务占满处理取消、撤权和故障通知所需的全部资源。 |
| 模型连接、文件或网络 I/O 等待 | 使用可挂起的等待方式，不为每个等待中的 Session 或请求保留一个忙等线程。连接、缓冲和句柄仍计入限额。 |
| 上下文处理、内容转换等计算密集工作 | 从接入和控制所需的执行资源中分离，通过有界执行器调度。大任务支持分段、取消或实际可用的终止边界。 |
| 阻塞接口、子进程和外部工具 | 在与其阻塞及故障性质相符的边界运行，不占住服务其他工作的执行线程。监督其真实退出和残留资源。 |
| 主进程内的不可信代码 | 使用受限执行域。限额与终止控制不能依赖其自愿配合，也不能与它争用一个可被其永久阻塞的调度线程。 |

Cordis 生命周期回调和本地事件处理仍占用其宿主线程。将函数写成 `async`、使用 `parallel` 或增加 Fiber 数量，不会把其中的同步计算自动交给其他 CPU 核。工作者需要自己的装配能力时才建立 Cordis 根；只承接数据与计算的工作者使用明确的任务协议即可。

上述分离是执行资源和责任的分离。具体采用任务调度、独立线程还是子进程，由机制设计根据隔离保证、调度成本与测量结果选择。受限执行域的安全要求不能用普通线程池或模块加载替代。

Agent 等待模型、工具或人工决定时，应释放不再使用的活跃计算资源。必要的等待记录、订阅、结果承接和恢复责任继续存在。HITL 不依赖某个线程长期停在调用栈上，恢复时仍按原卡片和原工作身份继续。

### 并发推进与共享状态

优先让各项工作拥有自己的可变状态，跨执行者通过显式交接协调。必须共享的状态由公开契约规定并发访问规则，不能用一个全局锁串行化所有租户与无关工作。

| 并发边界 | 必须保护的性质 |
|---|---|
| 同一 Run 的推进 | 只有当前有效推进者能够提交新的推进。工作认领、交接和失效检查须覆盖跨线程、跨进程及跨节点竞争。 |
| 不同 Run 与三个 runtime | 无关工作可以并行。Agent 等待某次模型请求不夺取模型 runtime 的生命周期或状态所有权。 |
| 控制与完成竞争 | 取消意图、当前推进资格、真实完成和迟到结果分别判断，不以回调抵达顺序替代契约中的生效条件。 |
| 结果与消费 | 交付、可靠承接和确认沿原调用身份进行。消费者替换后从保存的位置接续，不能将重复通知变成重复业务推进。 |
| 动态替换 | 新实例接纳责任之前，明确旧实例还能提交什么。旧实例失去推进权后仍有权报告原调用的真实收场与费用。 |

持有共享状态的排他权限时，不跨越无界外部等待。必须跨边界协调的提交、检查和交接由相应协议保证，不能把取消标志、进程内锁或一条通知当作跨节点原子性。

### 容量、背压与公平性

调度按实际瓶颈分别限制并发和排队，包括模型连接、工具执行、计算任务、存储请求及内容缓冲。限额须覆盖队列长度、积压大小和实际占用，不能只限制活跃任务而允许等待数据无限增长。

过载时由相应操作契约选择有界等待、拒绝或降级，并向调用方暴露结果。拒绝尚未受理的工作与停止已经受理的工作分别处理。已可靠受理的输入不能因内存队列满而静默丢弃。

调度须限制单个租户或单项长任务对共享资源的独占，并处理长期排队工作的饥饿问题。控制、结果承接与清理路径必须获得所需执行机会；优先级也不能让普通工作永远不能推进。具体额度、保留容量和公平策略由调度契约给出并验证。

等待依赖恢复时采用有界重试、退避或通知机制，避免忙等和所有实例同时重试。依赖恢复后的重新受理与结果回收同样受容量约束，不能一次放开全部积压。

## 通信、路由与结果交接

本地调用、线程消息、进程间通信和跨节点通信可以采用不同实现，但不得改变公开契约。跨边界消息携带操作所需的主体、租户、工作、调用及版本信息；接收方核验这些信息与实际连接资格，不能相信发送方自报的权限。

跨边界代理须明确请求身份与去重、授权复核、受理确认、结果保管、取消及恢复协议。调用方的本地 Fiber 撤除时，代理释放观察资源；是否取消远端执行由明确业务控制决定。远端结果不能只以回调形式返回给已经销毁的代理。跨根调用即使位于同一进程，也不能靠隐含共享服务绕过这些责任。

路由区分“把新工作交给可用实例”和“找到原调用的状态或结果”。原调用的路由可变化，但业务身份保持稳定。服务发现只提供候选位置，不证明该实例仍有推进权，也不证明请求已获授权。

超时、断连和节点失联首先表示观察失败。是否重试受原操作的受理、幂等和副作用契约约束。查询失败不表示原工作没有发生，负载均衡器也不能自行重放工具动作。

长连接及流式订阅必须处理慢消费者、断连和重新连接。内存缓冲有界，可靠内容与消费位置按[流式与消费](../runtime/streaming-and-consumption.md)承接。某个界面消费较慢，不能拖住无关租户的全部交付；浏览器已显示内容也不能代替持久确认。

多模态内容和长会话历史应避免在每次调度、跨线程交接或节点路由时整体复制。可按契约使用受控引用、分块读取或传输；引用的权限、寿命与读取失败仍须明确。零复制、共享内存或缓存只在不破坏隔离及所有权时使用，不能作为默认安全前提。

## 环境与基础设施依赖

### 装配声明

每份可运行装配须声明能力绑定、必需与可选依赖、支持的部署范围及失效行为。依赖可用不等于业务就绪；实例只有在能履行所声明的受理与保存保证时，才接纳相应工作。

| 依赖类别 | 装配与提供者须说明的内容 |
|---|---|
| 状态与内容存储 | 持久确认条件、并发协调能力、数据可达范围，以及读写失败和提交未知的表达。 |
| 身份、授权与秘密服务 | 当前准入依据如何取得与失效，凭据作用范围，以及不可用时哪些操作必须拒绝。 |
| 模型与工具服务 | 连接、容量、真实调用身份、失联判据、结果取回及各自允许的恢复方式。 |
| 执行环境 | 所需设施、隔离、节点约束、资源额度、数据保留和实际终止能力。 |
| 运行监督与服务发现 | 实例健康、业务就绪、原工作定位和退出确认分别如何观察。 |
| 时间与调度设施 | 定时触发、时限和跨实例协调依赖哪些时钟或服务，其异常会影响什么。 |
| 观测与遥测 | 采集、缓冲与输出限额，敏感信息处理，以及输出端故障时如何限制影响。 |

必需与可选依赖按操作及能力判断。某个观测输出端失效不应无条件停止全部业务；但必要审计或可靠记录无法履行时，也不能假报对应动作已经成功。具体行为沿拥有者契约执行。

### 本地资源与远端资源

部署描述须区分设备本地路径、节点临时目录、工作区实例、租户持久数据与远端内容引用。不能把一台节点上存在的路径当成集群中任意节点都能读取的资源。

调度受实际资源可达性约束。需要某项本地设施的调用，只能交给具备该设施且获准的执行环境。若无法满足，等待或拒绝沿操作契约处理，不能静默复制私有文件、改变执行位置或扩大授权。

个人设备的休眠、退出和网络中断会影响其承载的执行。装配须声明这些情况下的连接、等待与恢复行为；不能把设备离线期间的工作宣称为持续执行。云端部署也不能假设所有节点、网络和存储总是同时可用。
