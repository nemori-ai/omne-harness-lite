# 执行资源、通信与基础设施

本页维护进程、线程、通信和基础设施承接运行负载的共同机制。具体技术路线与版本归[系统技术基础](../technical-foundations.md#共同技术选择)，实际提供者须兑现本页条件。

状态：已接受的目标架构。采用范围及阅读路径见[部署入口](README.md)。

## 进程与线程模型

### 按工作负载分配执行资源

模型须同时满足[质量优先级](../drivers-and-constraints.md#取舍优先级)、三个 runtime 的独立生命周期和[不可信代码隔离](../security/execution-isolation.md#插件装配与代码信任)。独立生命周期不要求独占线程或进程，共享执行资源也不能取消已有保证。

| 工作负载 | 执行模型要求 |
|---|---|
| 请求受理、控制和短状态推进 | 单次占用执行资源的工作有界，持续处理就绪请求。不能让长任务占满处理取消、撤权和故障通知所需的全部资源。 |
| 模型连接、文件或网络 I/O 等待 | 使用可挂起的等待方式，不为每个等待中的 Session 或请求保留一个忙等线程。连接、缓冲和句柄仍计入限额。 |
| 上下文处理、内容转换等计算密集工作 | 从接入和控制所需的执行资源中分离，通过有界执行器调度。大任务支持分段、取消或实际可用的终止边界。 |
| 阻塞接口、子进程和外部工具 | 在与其阻塞及故障性质相符的边界运行，不占住服务其他工作的执行线程。监督其真实退出和残留资源。 |
| 主进程内的不可信代码 | 使用受限执行域。限额与终止控制不能依赖其自愿配合，也不能与它争用一个可被其永久阻塞的调度线程。 |

Cordis 生命周期回调和本地事件处理仍占用其宿主线程。将函数写成 `async`、使用 `parallel` 或增加 Fiber 数量，不会把其中的同步计算自动交给其他 CPU 核。工作者需要自己的装配能力时才建立 Cordis 根；只承接数据与计算的工作者使用明确的任务协议即可。

上述分离是执行资源和责任的分离。可信计算、专用写Worker及受限JS沿已采用路线实现；实际隔离保证、调度成本和额度由提供者验证。受限执行域的安全要求不能用普通线程池或模块加载替代。

CPU池只用于可信、可限制的计算，完成所有受管异步活动后才归还Worker，禁止留下跨任务continuation。数据库写Worker保持域亲和，不进入随机CPU池。普通异步网络/文件等待使用可挂起I/O，不为每个等待Session或HITL常驻一个忙等线程。阻塞原生调用、PTY、shell、浏览器及不可合作任务根据故障与终止要求选独立进程或其他已验证边界，监督实际子进程和后代退出。

Agent 等待模型、工具或人工决定时，应释放不再使用的活跃计算资源。必要的等待记录、订阅、结果承接和恢复责任继续存在。HITL 不依赖某个线程长期停在调用栈上，恢复时仍按原卡片和原工作身份继续。

### 并发推进与共享状态

优先让各项工作拥有自己的可变状态，跨执行者通过显式交接协调。必须共享的状态由公开契约规定并发访问规则，不能用一个全局锁串行化所有租户与无关工作。

| 并发边界 | 必须保护的性质 |
|---|---|
| 同一 Run 的推进 | 只有当前有效推进者能够提交新的推进。工作认领、交接和失效检查须覆盖跨线程、跨进程及跨节点竞争。 |
| 不同 Run 与三个 runtime | 无关工作可以并行。Agent 等待某次模型请求不夺取模型 runtime 的生命周期或状态所有权。 |
| 控制与完成竞争 | 取消意图、当前推进资格、真实完成和迟到结果分别判断，不以回调抵达顺序替代契约中的生效条件。 |
| 结果与消费 | 交付、可靠承接和确认沿原调用身份进行。消费者替换后从保存的位置接续，不能将重复通知变成重复业务推进。 |
| 动态替换 | 新实例接纳责任之前，明确旧实例还能提交什么。旧实例失去推进权后仍有权报告原调用的真实收场与费用。 |

持有共享状态的排他权限时，不跨越无界外部等待。必须跨边界协调的提交、检查和交接由相应协议保证，不能把取消标志、进程内锁或一条通知当作跨节点原子性。

### 容量、背压与公平性

调度按实际瓶颈分别限制并发和排队，包括模型连接、工具执行、计算任务、存储请求及内容缓冲。限额须覆盖队列长度、积压大小和实际占用，不能只限制活跃任务而允许等待数据无限增长。

过载时由相应操作契约选择有界等待、拒绝或降级，并向调用方暴露结果。拒绝尚未受理的工作与停止已经受理的工作分别处理。已可靠受理的输入不能因内存队列满而静默丢弃。

调度须限制单个租户或单项长任务对共享资源的独占，并处理长期排队工作的饥饿问题。控制、结果承接与清理路径必须获得所需执行机会；优先级也不能让普通工作永远不能推进。具体额度、保留容量和公平策略由调度契约给出并验证。

等待依赖恢复时采用有界重试、退避或通知机制，避免忙等和所有实例同时重试。依赖恢复后的重新受理与结果回收同样受容量约束，不能一次放开全部积压。

### 能力自有资源池与租户调度

资源提供者拥有创建、借用、归还、配置代际、停止准入和真实关闭。数据库连接由storage拥有，HTTP/供应商client由model或具名网络提供者拥有，MCP端点/会话/子进程由MCP拥有，CPU/环境由execution拥有。共同调度算法可以复用，活体池不放common，assembly不接管所有资源。

每个部署profile须明确有限正值的活跃数、租户并发、等待项数、等待字节、单项大小和持有资源预算。缺值、无限默认、非法组合或保留容量不能满足必要控制路径时拒绝启动相应能力。额度是配置与测量输入，不能伪装成已证明的吞吐目标。已受理工作通过持久待办保存，内存队列只调度引用，容量不足延迟派发；未受理请求按公开契约有界等候或拒绝，不静默丢弃。

公平策略采用按租户的deficit round robin。计费单位由执行器声明，至少覆盖计量输入字节或有界任务工作量，配置有限正quantum、单任务上限及租户并发。各租户队首得到累积额度且轮转，长期等待适度老化，不允许优先级永久取消普通工作的服务份额。大任务分段或受执行上界约束，不能以调度公平证明不可抢占任务会及时结束。进展以有限可执行任务、资源最终释放及无永久故障为前提；容量饱和、长期等待及前提失效必须可诊断。

控制、结果保管与清理各有显式保留容量和积压预算，普通工作保留最低服务机会，控制也不能无限独占。在存储域内仍必须经过真实连接，控制消息不能抢占正在执行的同步SQL。结果保管将满或必需审计无法承接时先停相关新准入，不在外部效果已经产生后丢弃结果。

不另设预算服务。一项预算有三列。硬边界由该资源的提供者执行。运行配置是该提供者插件上可序列化的字段。观测读数不是上限。

字段缺失、不是有限正数，或保留容量不够控制路径时，该插件加载失败，fiber 进入 `FAILED`。不允许用缺省表示无限。默认值只是初值。

一个有限正值写入该字段，只有下面六条同时成立。该字段只约束这个提供者自己拥有的一种资源。同一处写明负载。同一处写明平台，包括操作系统和 Node 版本。限额依赖真实库时，写上该库的版本。超限行为只能是有界等待、拒绝或降级。已经受理的工作不因超限被静默丢掉。该数字只属于一个部署 profile。一次测量只证明这次负载和这个平台。

排空超时写在执行关闭协议的装配插件上。它等待仍持有的租约。这段等待的验证平台是 Node v26.0.0。存储关闭期限写在存储提供者插件上。它是一个配置字段。数值仍空着。它等待当前 SQL 结束。存储提供者的平台基线是 Node 24.21.0 内嵌的 SQLite 3.53.4。两条期限是两个字段。

存储关闭期限作用在装配 `close` 的排空阶段。它不是排空完成之后的步骤。SQL 仍在执行时，存储提供者持有这条写连接的租约。语句在期限内结束时，提供者调用 `release`。期限到达而语句未结束时，提供者给出 `incomplete`，并且不释放该租约。此后语句结束，提供者仍不调用 `release`。该租约保持持有，直到装配 `close` 的报告已经确定。装配 `close` 在排空中等待这份租约。排空结束时租约仍被持有，装配报告是 `timed-out`。步骤不执行。报告确定之后的 `release` 不改写这份报告。存储层的结果是 `incomplete`。装配层的结果是 `timed-out`。这条释放限制由存储提供者承担。这使用现行排空分支。把存储关闭放进排空之后的步骤列表，不能产生 `timed-out`。

控制路径的保留容量写在执行调度插件上。结果保管的保留容量写在保管结果的存储提供者插件上。清理保留容量写在会被占满的那个资源提供者自己的插件上。本页不把清理份额合成全进程的一个数字，也不规定这些份额的数字。拥有该插件的成员在自己的配置里给出数字，并写明负载、平台和超限行为。

凭据计算在执行前检查三项。它们是参数上限、同时进行的份数，以及由参数推导的内存乘以在途份数。队列长度是另设的受理上限。它不是这份内存。图像在解码开始时拒绝超限。硬边界包括格式允许列表、最大宽度、最大高度、解码后的最大字节、同时解码的份数和在途字节。`content-block` 只判断封闭块。图像的证据平台由该 profile 写明操作系统和 native 库的名字与版本。profile 未写明这两者时，没有可接受的图像数字预算。

受理检查返回第一个失败原因，然后停止。它不返回原因列表。SQLite 提供者的 `commit` 按此顺序检查：`field_missing`、`participant_repeated`、`facts_not_json`、`unsupported_protocol`、`command_limit`、`queue_full`、`writer_not_current`、`combination_unregistered`、`participant_not_in_combination`。`queue_full` 时不发送，也不增加预留。

### 发出前的联合结果容量预留

结果保管容量由实际保管后端的提供者统一核算，范围覆盖共享该容量的所有Model、Tool及其他已受理调用，而不是各池分别看“当前空闲”。调用发出前，原调用拥有者申请一个覆盖结果、可靠引用、必要收场及迟到费用记录的可兑现上界；业务受理记录与该容量预留在同一真实事务域、同一提交中成立。local装配把原调用参加者和保管容量参加者绑定到该事务域，缺少共同提交能力就不开放此受理模式；不以两个独立reserve/accept RPC假装原子。

提供者持久保存按原调用身份与容量域绑定的预留依据，并在串行提交中保证未分配预留的存量占用加所有未解除调用的整项预留额度不超过有限总预算。预留内实际落盘字节是该额度内的占用，不重复相加，也不因只收到部分结果而减小整项额度。重复受理返回原预留，不新增额度。预算覆盖磁盘、内存缓冲、必要维护及最坏编码开销，各实际保管层有对应保护，不能把有限内存降级为未定额磁盘。已经收回结果但未获准清理的调用仍保留整项预留，不因Agent退出、租约到期或消费者ACK就释放空余额。

输入输出限额须由原调用契约及执行profile说明并由提供者实际兑现。未知或不能保证结果/记录上界的提供者，不准入需要该有限保管保证的调用，不能等外部效果发生后再临时决定截断、丢弃或增加无界存储。对允许有限输出的调用，profile须在发出前固定限制及超限的既定失败/未知语义，验证实际生产端、传输缓冲和保管过程；本页不为原契约新增未经授权的截断例外。

预留与原调用一起跨runtime和资源换代保留。旧执行者可使用已绑定额度承接真实结果，新实例从持久账本认回，不重复计算空闲额。只有原执行和所有迟到收场义务已确定收束、合法承接/保留条件满足且实际删除/归档释放容量后，提供者才以原身份幂等解除相应预留。清理失败仍占额度并停相关新准入，不把期满或ACK当作物理释放。未知提交按原操作查询，不能在结果未知时回收预留。

## 通信、路由与结果交接

本地调用、线程消息、进程间通信和跨节点通信可以采用不同实现，但不得改变公开契约。跨边界消息携带操作所需的主体、租户、工作、调用及版本信息；接收方核验这些信息与实际连接资格，不能相信发送方自报的权限。

跨边界代理须明确请求身份与去重、授权复核、受理确认、结果保管、取消及恢复协议。调用方的本地 Fiber 撤除时，代理释放观察资源；是否取消远端执行由明确业务控制决定。远端结果不能只以回调形式返回给已经销毁的代理。跨根调用即使位于同一进程，也不能靠隐含共享服务绕过这些责任。

路由区分“把新工作交给可用实例”和“找到原调用的状态或结果”。原调用的路由可变化，但业务身份保持稳定。服务发现只提供候选位置，不证明该实例仍有推进权，也不证明请求已获授权。

超时、断连和节点失联首先表示观察失败。是否重试受原操作的受理、幂等和副作用契约约束。查询失败不表示原工作没有发生，负载均衡器也不能自行重放工具动作。

长连接及流式订阅必须处理慢消费者、断连和重新连接。内存缓冲有界，可靠内容与消费位置按[流式与消费](../runtime/streaming-and-consumption.md)承接。某个界面消费较慢，不能拖住无关租户的全部交付；浏览器已显示内容也不能代替持久确认。

多模态内容和长会话历史应避免在每次调度、跨线程交接或节点路由时整体复制。可按契约使用受控引用、分块读取或传输；引用的权限、寿命与读取失败仍须明确。零复制、共享内存或缓存只在不破坏隔离及所有权时使用，不能作为默认安全前提。

### 连接复用与流式缓冲

HTTP池按origin、代理、TLS/mTLS、凭据访问范围及配置代际核对连接资格后复用，显式限制connections、请求和响应缓冲。SDK内部流、SSE parser、消费者队列及reader各自有界；parser字符数不等于原始字节。未消费响应按协议排空或释放，超时/abort/destroy分别报告实际发出与结果未知。热替换后原请求保留旧租约，不给新租户或新凭据偷偷重用旧状态。

MCP按端点和访问范围管理连接，发现结果按端点/协议/能力版本缓存。有状态会话、工作区和stdio子进程不跨租户复用。可复用连接必须满足同一连接资格和可验证状态重置；取消或断连不重放已发出的工具动作，实际效果归Tool及原调用能力认回。隔离边界仍沿[执行隔离](../security/execution-isolation.md)核对。

接入技术路线为HTTP JSON控制与查询、fetch SSE单向观察；精确端点、认证和订阅语义由公开契约拥有。SDK使用Web标准接口，取消观察不取消原工作。实际双向需求成立后再采用WebSocket，不把stdio作为通用浏览器远程接口。网络提供者显式注入dispatcher；租户插件不能修改全局dispatcher或宿主环境，全局策略只由具名应用拥有者管理。认证头按请求传递。

## 环境与基础设施依赖

### 装配声明

每份可运行装配须声明能力绑定、必需与可选依赖、支持的部署范围及失效行为。依赖可用不等于业务就绪；实例只有在能履行所声明的受理与保存保证时，才接纳相应工作。

| 依赖类别 | 装配与提供者须说明的内容 |
|---|---|
| 状态与内容存储 | 持久确认条件、并发协调能力、数据可达范围，以及读写失败和提交未知的表达。 |
| 身份、授权与秘密服务 | 当前准入依据如何取得与失效，凭据作用范围，以及不可用时哪些操作必须拒绝。 |
| 模型与工具服务 | 连接、容量、真实调用身份、失联判据、结果取回及各自允许的恢复方式。 |
| 执行环境 | 所需设施、隔离、节点约束、资源额度、数据保留和实际终止能力。 |
| 运行监督与服务发现 | 实例健康、业务就绪、原工作定位和退出确认分别如何观察。 |
| 时间与调度设施 | 定时触发、时限和跨实例协调依赖哪些时钟或服务，其异常会影响什么。 |
| 观测与遥测 | 采集、缓冲与输出限额，敏感信息处理，以及输出端故障时如何限制影响。 |

必需与可选依赖按操作及能力判断。某个观测输出端失效不应无条件停止全部业务；但必要审计或可靠记录无法履行时，也不能假报对应动作已经成功。具体行为沿拥有者契约执行。

### 本地资源与远端资源

部署描述须区分设备本地路径、节点临时目录、工作区实例、租户持久数据与远端内容引用。不能把一台节点上存在的路径当成集群中任意节点都能读取的资源。

调度受实际资源可达性约束。需要某项本地设施的调用，只能交给具备该设施且获准的执行环境。若无法满足，等待或拒绝沿操作契约处理，不能静默复制私有文件、改变执行位置或扩大授权。

个人设备的休眠、退出和网络中断会影响其承载的执行。装配须声明这些情况下的连接、等待与恢复行为；不能把设备离线期间的工作宣称为持续执行。云端部署也不能假设所有节点、网络和存储总是同时可用。
