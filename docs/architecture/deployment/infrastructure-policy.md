# 阶段后端采用

本页维护存储和消息队列的阶段技术采用边界。它不增加[项目要求](../../requirements.md)，不定义公共存储接口，也不表示相关提供者已交付。单机与集群的目标关系由[部署架构](README.md)维护，精确行为由实际契约和提供者拥有。

## 正式后端的范围

存储和消息队列不提供 in-memory 正式后端。时钟不在这项采用范围内。进程内缓存、缓冲、测试替身和执行状态不因这条规则一律禁止；判断依据是它是否承担正式后端的责任。

取消回调、waiter 等活体句柄的保存、恢复和清理由实际运行时与资源拥有者负责。本页不为它们规定持久化或分布式协议，也不授予丢弃未完成义务的许可。

存储的事务、失败和确认条件由实际公共存储契约拥有，[STORAGE-T01 公共事务与确认契约的承接](../data-and-state.md#storage-t01)定位尚未完成的承接。提供者须明确自己的能力、前提和限制，不能用后端名称代替行为保证。

## 消息队列的采用

消息队列采用 Redis 后端，运输采用 Streams，客户端路线与版本归[系统技术基础](../technical-foundations.md#共同技术选择)。可靠责任由[SQL与Streams可靠交接](../data-and-state.md#sql与streams可靠交接)维护，Streams不成为业务事实的第二权威。公共队列的精确协议及实际提供者仍须承接，目前没有此规则能够指认的正式交付。

后续队列设计须承接上述正式后端边界，明确受理、交接、重复、失联及恢复的精确保证。Redis 的采用选择不证明这些保证已经实现，也不要求为了目录完整先创建空包。

## 当前治理交付

治理宿主的当前限定交付采用 SQLite，实际支持范围须由当前宿主及提供者契约确认，[DEPLOY-T01 治理宿主限定交付的契约承接](infrastructure-policy.md#deploy-t01)及[SQL-T01 SQL 提供者与耐久限制的承接](infrastructure-policy.md#sql-t01)分别维护尚未完成的承接待办。PostgreSQL 的完整治理恢复和消息队列实现不因本页迁出而进入该交付范围。

这个限定不是全系统只能使用 SQLite 的要求。个人设备与集群的装配分别满足[数据可达与故障边界](distributed-storage.md)，阶段选型不能代替跨节点读写、确认或恢复协议。

## 耐久目标与提供者保证

[已确认保存的耐久边界](../data-and-state.md#已确认保存的耐久边界)要求已确认事实能抵御所声明故障范围。当前 Storage 的 P-7 和 SQL 提供者仍声明具体限制，不能据迁移正文或普通重启测试宣称已满足断电耐久目标。

存储契约、提供者和业务确认协调者分别承接这个差距。更强确认条件、配置和物理存储前提需要下层设计与相称验证；迁移不改低目标，也不顺带完成该实现。

## 维护与变更

后端规则变化须明确适用范围、采用依据及实际消费者，再同步相应提供者和检查。单次比较、方案形成和执行结果留任务 `tmp/`；本页只维护当前采用与持续责任。

## 未决问题与待办事项

以下事项沿本页已接受要求继续承接。来源定位不表示现行契约已经完整或验证已通过。

<a id="deploy-t01"></a>
### DEPLOY-T01 治理宿主限定交付的契约承接

本项为契约与装配承接待办。治理宿主的启动配置、共享保护域、迁移、预检、开闸、失败及撤除协议尚须定位当前应用拥有者。已有 SQLite 限定不能被推为全系统后端唯一选择，也不表示 PostgreSQL 或队列已交付。

承接责任为治理应用、启动与关闭协调者及相关提供者。待办是明确当前支持范围和精确装配输入，验证依赖就绪、共享提交、开闸失败及关闭状态；局部停止差距由生命周期专题维护。

[封存来源](../../../apps.0.0.1.legacy/tenancy-host/SPEC.md)仅供核对原范围和消费者；旧接受记录、归档位置与已有测试不能授予冲突设计继续采用。实际限制、待设计输入及验证结果须由各自当前拥有者确认。

<a id="sql-t01"></a>
### SQL-T01 SQL 提供者与耐久限制的承接

本项为提供者契约及符合性待办。SQL 方言、真实事务域、升级、维护、关闭与具体耐久限制须由现行提供者确认。封存 SQL 提供者和 Storage P-7 的限制没有当前关闭证据，普通重启测试不能证明断电耐久。

承接责任为Storage、SQL 提供者、装配及业务确认协调者。待办是定位实际公开入口及提供者配置，将能力映射到公共存储保证，并取得与确认故障范围对应的验证；不以迁移或后端名称宣布差距消除。

[封存来源](../../../packages.0.0.1.legacy/infra/storage-sql/SPEC.md)仅供核对原范围和消费者；旧接受记录、归档位置与已有测试不能授予冲突设计继续采用。实际限制、待设计输入及验证结果须由各自当前拥有者确认。
