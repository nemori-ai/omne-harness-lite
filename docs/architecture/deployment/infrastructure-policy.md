# 阶段后端采用

本页维护存储和消息队列的阶段技术采用边界。它不增加[项目要求](../../requirements.md)，不定义公共存储接口。单机与集群的目标关系由[部署架构](README.md)维护，精确行为由实际契约和提供者拥有。

## 正式后端的范围

存储和消息队列不提供 in-memory 正式后端。时钟不在这项采用范围内。进程内缓存、缓冲、测试替身和执行状态不因这条规则一律禁止；判断依据是它是否承担正式后端的责任。

取消回调、waiter 等活体句柄的保存、恢复和清理由实际运行时与资源拥有者负责。本页不为它们规定持久化或分布式协议，也不授予丢弃未完成义务的许可。

存储的事务、失败和确认条件由实际公共存储契约拥有。提供者须明确自己的能力、前提和限制，不能用后端名称代替行为保证。

## 消息队列的采用

消息队列采用 Redis 后端，运输采用 Streams，客户端路线与版本归[系统技术基础](../technical-foundations.md#共同技术选择)。可靠责任由[SQL与Streams可靠交接](../data-and-state.md#sql与streams可靠交接)维护，Streams不成为业务事实的第二权威。

## 当前治理交付

治理宿主的当前限定交付采用 SQLite，实际支持范围须由当前宿主及提供者契约确认。PostgreSQL 的完整治理恢复和消息队列实现不进入该交付范围。

这个限定不是全系统只能使用 SQLite 的要求。个人设备与集群的装配分别满足[数据可达与故障边界](distributed-storage.md)，阶段选型不能代替跨节点读写、确认或恢复协议。

## 耐久目标与提供者保证

[已确认保存的耐久边界](../data-and-state.md#已确认保存的耐久边界)要求已确认事实能抵御所声明故障范围。
