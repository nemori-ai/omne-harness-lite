# 阶段后端采用

本页维护存储和消息队列的阶段技术采用边界。它不增加[项目要求](../../requirements.md)，不定义公共存储接口，也不表示相关提供者已交付。单机与集群的目标关系由[部署架构](README.md)维护，精确行为由实际契约和提供者拥有。

## 正式后端的范围

存储和消息队列不提供 in-memory 正式后端。时钟不在这项采用范围内。进程内缓存、缓冲、测试替身和执行状态不因这条规则一律禁止；判断依据是它是否承担正式后端的责任。

取消回调、waiter 等活体句柄的保存、恢复和清理由实际运行时与资源拥有者负责。本页不为它们规定持久化或分布式协议，也不授予丢弃未完成义务的许可。

存储的事务、失败和确认条件归[Storage 契约](../../../packages/core/storage/SPEC.md)。提供者须明确自己的能力、前提和限制，不能用后端名称代替行为保证。

## 消息队列的采用

消息队列首先采用 Redis 后端。公共队列协议、Redis 客户端以及是否采用 Streams 尚待具体设计；目前尚无此规则能够指认的正式队列定义与提供者。

后续队列设计须承接上述正式后端边界，明确受理、交接、重复、失联及恢复的精确保证。Redis 的采用选择不证明这些保证已经实现，也不要求为了目录完整先创建空包。

## 当前治理交付

治理宿主的当前限定交付采用 SQLite，具体支持范围由[宿主契约](../../../apps/tenancy-host/SPEC.md)及[SQL 提供者](../../../packages/infra/storage-sql/SPEC.md)维护。PostgreSQL 的完整治理恢复和消息队列实现不因本页迁出而进入该交付范围。

这个限定不是全系统只能使用 SQLite 的要求。个人设备与集群的装配分别满足[数据可达与故障边界](distributed-storage.md)，阶段选型不能代替跨节点读写、确认或恢复协议。

## 耐久目标与提供者保证

[已确认保存的耐久边界](../data-and-state.md#已确认保存的耐久边界)要求已确认事实能抵御所声明故障范围。当前 Storage 的 P-7 和 SQL 提供者仍声明具体限制，不能据迁移正文或普通重启测试宣称已满足断电耐久目标。

存储契约、提供者和业务确认协调者分别承接这个差距。更强确认条件、配置和物理存储前提需要下层设计与相称验证；迁移不改低目标，也不顺带完成该实现。

## 维护与变更

后端规则变化须明确适用范围、采用依据及实际消费者，再同步相应提供者和检查。单次比较、方案形成和执行结果留任务 `tmp/`；本页只维护当前采用与持续责任。
