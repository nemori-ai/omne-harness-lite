# 部署与运行拓扑

本专题说明 Harness 如何映射到进程、线程、节点和基础设施，以及这些部署选择必须保护的运行性质。个人设备和云端集群使用同一套领域语义，通过装配选择提供者、执行位置和资源策略。

基础拓扑是客户端通过公开协议连接常驻 Harness Server。单机将服务及其执行进程放在一台设备上；集群在多份服务实例之外增加接入路由、跨实例工作协调和节点管理。服务内部怎样划分 runtime，与集群怎样分配服务实例分别设计。

## 运行单元与部署图

### 逻辑职责与物理位置

部署以职责、资源需求和故障影响划分运行单元。一个运行单元可以承载多个能力，一个能力也可以由多个实例提供。包、Cordis 插件、Session、runtime、进程和节点不要求一一对应。

| 逻辑职责 | 部署需要承接的工作 | 位置变化时保持的边界 |
|---|---|---|
| 客户端与 SDK | 展示、交互、连接和订阅管理，调用公开契约。 | 客户端缓存不成为服务端事实源，连接断开不等于取消工作。 |
| 服务接入 | 身份核验、请求路由、输入受理、控制请求及结果交付。 | 使用同一公开契约，不能因本地调用而绕过授权或直接修改内部状态。 |
| 治理与协调 | 组织、租户和资产治理，Session/Run 工作治理，调度与推进权协调。 | 不同领域分别拥有状态与规则，不合并成一个全能控制服务。 |
| 三个 runtime | 分别推进 Agent Loop、模型请求和工具执行。 | 生命周期独立，调用与等待不构成级联销毁关系。 |
| 执行环境 | 提供获准的计算、文件、网络和隔离设施。 | 环境与逻辑工作区分别管理，计算位置变化不迁移原调用身份或自动恢复执行。 |
| 状态与内容服务 | 保存权威事实、承接结果与多模态内容，提供受控查询。 | 数据归属、持久确认和访问控制不随进程分拆改变。 |
| 运行监督 | 启停实例、探测健康、限制故障传播，支持替换与资源回收。 | 不代替业务拥有者判定调用结果、授权或外部效果。 |

各职责的内部划分沿[结构与责任](../structure.md)维护。客户端、SDK 和服务端的依赖方向沿[分层与依赖](../layers-and-dependencies.md)维护。治理中心的组织管理职责不等于整套运行系统的所有协调职责，也不能从“中心”一词推导必须由单个进程承载。

### 部署环境与进程组织

部署先区分客户端、Harness 服务实例和集群三个范围，再为每个范围确定进程与节点位置。客户端进程与一个 daemon 服务进程已经构成多进程部署，不要求先把 Agent、模型和工具 runtime 分别拆成服务进程。

Harness Server 是通过公开协议提供 Harness 能力的服务端。一个服务实例可以在自己的进程内，通过 Cordis 装配服务接入、治理和三个 runtime，并连接按需使用的执行进程及后端。runtime 的生命周期独立是责任约束，不规定一类 runtime 对应一个进程。

| 范围 | 主要责任 | 物理映射 |
|---|---|---|
| 客户端 | 交互、调用、展示和订阅，承接人工决定。 | 可以有多个独立进程，位于服务同机或远端。 |
| Harness 服务实例 | 受理并治理工作，推进 Agent，调度模型与工具，承接状态和结果。 | 通常有一个常驻服务进程，按执行需要使用辅助进程；不强制拆分内部 runtime。 |
| 集群 | 将请求和工作分配给服务实例，管理跨实例归属、容量、接管及节点资源。 | 协调多份实例及其节点，相关职责可以组合部署或由基础设施承接。 |

集群层不再实现一套 Agent Loop，也不取代组织、租户或 Session 的业务治理。它按这些治理规则落实工作分配与资格检查。业务拥有者决定工作能否推进，集群机制帮助将合格工作交给合格实例。

## 共同语义

单机与集群装配须保持同一套身份、授权、可靠交接和取消语义。租户不能通过更换接入节点扩大权限；工作也不能因客户端重连或实例重启取得第二个有效推进者。

部署记录区分稳定的业务身份与可替换的物理身份。Session、Run、attempt 和调用关联按各自契约保存；进程、线程、节点、连接及执行环境实例用于定位实际执行。物理身份变化不能改写历史归属。

## 后续部署契约与实现选择

本页确定运行位置可以变化时仍须成立的边界。以下精确契约、机制选择和数值由实际拥有者细化，不能在缺少机制时宣称保证已实现。

| 承接者 | 后续设计与交付内容 |
|---|---|
| 装配与部署维护者 | 单机 Harness 服务及辅助进程的布局，集群实例与节点的映射；每份 Cordis 根、受管分支、必需依赖与可见范围，以及就绪、换代、退出与升级路径。明确 daemon 的启动、停止、客户端发现和进程监督方式。 |
| 调度及 Session/Run 协调拥有者 | 单机与集群提供者共同满足的工作认领、归属查询、推进权失效与提交复核协议，背压、公平性、恢复积压和控制资源策略。 |
| runtime 与执行器拥有者 | 调用方与执行拥有者的资源归属，依赖重跑后的接续，任务、线程和进程分工，以及取消、终止与宿主调用承接。 |
| 不可信代码机制及运行监督拥有者 | 受限执行域、独立终止路径、进程外监督、故障隔离与反复失败处置。 |
| 公开协议、路由及结果服务拥有者 | 客户端到 Harness 服务的协议，集群入口的新请求分配与原工作路由；跨根及远程代理的业务契约，传输、身份认证、原调用定位、受理确认、重连、慢消费者和大内容传输。 |
| 数据及环境提供者 | 状态可达范围、持久与备份前提、计算重建和数据恢复，跨节点设施与资源约束。 |
| 分布式存储提供者及数据拥有者 | 分片与副本布局、跨节点读写、元数据与内容提交、分片迁移、备份恢复及删除；边界见[分布式存储](distributed-storage.md#提供者与验证责任)。 |
| 分布式调度及执行器提供者 | 能力与数据位置选择、全局额度、任务受理、结果交付、节点失联及执行接管；边界见[分布式计算](distributed-compute.md#提供者与验证责任)。 |
| 产品、部署及质量验证拥有者 | 各装配的支持矩阵、容量和性能目标、可用性及恢复指标，以及对应故障与长期负载验证。 |

这些责任同时登记在[架构后续设计入口](../README.md#未决事项与后续设计入口)。本页不选择固定线程数、执行引擎、通信库、数据库或云平台。具体实现须给出符合上述约束的依据；操作命令和部署手册归[使用与部署指南](../../guides/README.md)。
