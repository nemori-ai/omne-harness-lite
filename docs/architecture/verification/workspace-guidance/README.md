# 工作区目录指导的证明边界

本模型约束 [Context 的目录指导规格](../../../../packages/context/SPEC.md#工作区目录指导)。下文的集合结论适用于任意有限的已确认目录集合。三个 TLA+ 模型分别检查有限范围内的事件交错。

## 目录闭包、最小增量与成本

固定一次合法读取的租户、工作区实例、根对象 R、来源版本及读取资格。每个输入目录已由执行设施按对象身份确认为 R 或其后代。设 P(d) 为从 d 到 R 的唯一父链，两个端点都包含。初次附着以 R 为输入。以 D 表示本次确认的目录集合，恢复时用仍须继续工作的已访问目录并加 R。所需来源集合 F 为所有 P(d) 的并集中实际含有 AGENTS.md 且有资格采用的来源。若某位置未知或拒绝，不能推导出 F 已完整。

同一身份含实例、规范作用目录中的 AGENTS.md 源和固定内容标识。令 V 为本次合法有效历史中有完整模型可读原文、来源可核对的身份集合。一个旧摘要、只有引用尚未展开、被裁剪的工具输出、相同但无法确认来源的文本，均不能证明身份在 V 中。令 M = F ∖ V。投递可以给出作用范围清单与已在窗口中的来源引用，只有 M 携带新正文。

发行装配将 Workspace 核实的根对象身份传给宿主；来源探测和正文读取都核对实际打开的根。在允许多种大小写拼写指向同一目录的卷上，宿主从已打开的目录或文件取得规范目录名，再生成来源身份。同一批遇到不同拼写，确认它们指向同一来源需要各自的探测，正文读取和投递只算一份。下文的不同节点探测数以输入已采用规范拼写为前提。

**定理一　遍历恰好覆盖父链并集。** 维护本批已展开节点集合。对每个叶向上，将未出现的节点加入，遇到根直接终止，遇到已展开节点可停止。对已处理叶数归纳。初始为空。新链首次与旧集合相交时，该节点到 R 的后缀已随旧链完整纳入，余下只有新链前缀。无交集时遍历到 R 为止。由此得到的集合恰好是并集，且不调用 R 的 parent。若并发整理，先归并目标再执行此纯计算；只有已经覆盖完整后缀的标记才可作停止条件。探测失败的半条链不能作为已完整检查的可复用后缀。

**定理二　单次增量完整且最小。** 对任一 f∈F，集合排中给出 f∈V 或 f∈M，故 F⊆V∪M。任一 f∈M 均属于 F 且不属于 V，不会重发已有正文，也不会引入旁支。若另一个可交付集合 X 少了 M 中的 f，则 f 也不在 V，故 F⊄V∪X。M 是包含关系下唯一最小的补充正文集合。按来源身份去重，不能以相同正文哈希折叠不同目录的作用范围。该结论不比较传输编码的字节数。根先于子、兄弟按固定规范顺序排列，集合语义不取决于工具回执的先后。

**定理三　并发批次可串行化。** 固定接收窗口，将同一批结果合并后以单写者的一次条件提交发布。若两个准备者都读到相同 V，首个成功提交后修订改变。第二个只能重新读取 V′ 再算差集。以成功提交的顺序归纳，每次追加正文与当时 V 的交为空，新的 V 包含之前和本次追加。仅结果未知时，仍以原操作身份认回。同一提交不能再追加。压缩或资格变化先重建 V，可合法地重新载入已消失的正文。切换改变所需的 F，旧回执使用其受理代际，无法给新实例引入来源。这里的原子前提是持有者在同一提交核验并推进修订；单进程读后再写不能代替该前提。

**进展的条件。** 输入目录和树深有限，每走一步距根的距离严格减少。按规范顺序有限次遍历、探测与差集运算会结束。若来源最终可确定、资格稳定、预算足够，且准备者最终获得可成功提交的修订，则下一输入可用；永久丢回执、持续切换、权限拒绝和存储停机没有无条件进展保证。

**复杂度。** 以 m 表示回执中目录出现次数、k 表示互异目标数、u 表示其祖先并集大小、h 表示最大深度、b 表示本次需输出的正文总字节数。用带 parent 的规范节点身份和哈希集合，归并及父链步骤期望 O(m + u)，每条目标链至多一次在已见节点止步。若用排序确定同级顺序，另计 O(k log k) 次目标键比较；每次比较的路径长度、规范化、哈希和字符串前缀复制都需计入真实 CPU。原型直接切分和比较路径字符串。无有效缓存时至多 u 次目录来源探测，具有可靠版本或内容指纹时只对 M 的内容解引用；缺少该依据时还要读取候选文件字节以确认身份。原文输出至少 Ω(b)。工作空间 O(k + u + |M|)，另加当前可见身份索引与实际正文。热缓存复用必须具有同一来源采用依据和权限，无法验证的负缓存需重新探测。并发文件读取可以限流、共用同一在途读取，释放或取消一个消费者不撤销其他消费者需要的读。单写者仍负责最终的模型正文去重。

## 模型、动作与反例

| 模型 | 表示的交错及边界 | 性质 |
| --- | --- | --- |
| [WorkspaceGuidance](WorkspaceGuidance.tla) · [配置](check.cfg) | A 内两个已发出的工具，两个叶共享祖先；完成任意排序，最多 A→B→A，一次压缩可保留任意已显示子集。只有完成的目录可进入请求，根单独作为已知基线 | 每次成功提交与当时绑定、祖先集合及可见差集相符；旧代际结果不能成为新实例的访问，同一步共享正文只发一次 |
| [GuidanceAppend](GuidanceAppend.tla) · [配置](append.cfg) | 两个写入准备者共享根与共同父目录，分别读取、准备、比较提交。可在任意时点压缩并保留任意子集；提交可返回未知，随后按原操作查回 | 在提交真正生效的位置没有缺项或重复，失去回执不能导致再追加 |
| [GuidanceRecovery](GuidanceRecovery.tla) · [配置](recovery.cfg) | 首个写入者已持久登记原操作，进程可在其正文提交到达前或之后退出。第二个进程查回原身份，或对原修订作条件提交以排除迟到写入。可穿插一次其他提交 | 查回成功必能对应原提交；确认排除后原提交再也无法生效；本例所需正文最终就绪时恰有一份 |

Finish 对应原工具执行结果的接纳，Prepare 是可丢的候选，Commit／Append 是 Session 有修订依据的条件提交，Compact 是有效历史边界的变化，Recover 是按原操作认回。模型中资格与文件内容固定；代码精化还须检验物理路径围栏、分项结果与提交的耐久性、正文所有权、源版本和实际发出的模型请求。

在包根约定的形式工具环境下，在本目录用 TLC 分别执行三份 cfg。负对照将配置中的 Fault 改为 WorkspaceGuidance 的 late、stale、forget、above-root 或 parallel，或 GuidanceAppend 的 without-cas、repeat-unknown。应得到 Safety 反例。例：两个准备者同时把共同根放入各自候选，首个追加成功，另一个若跳过修订检查再追加，就会把根写两遍。

恢复模型的负对照为 no-fence 和 foreign-receipt。前者允许第二个写入者宣布已排除原提交，而原提交仍可成功；后者允许用另一个会话的回执确认本次操作。恢复模型假设事务按同一单调修订原子提交，进程退出不会回滚已提交的记录。模型只检查安全性质，存储持续不可用时没有就绪期限。
