# 安全验证与符合性

本页规定安全设计须留下哪些可核对的保证和证据。测试、审阅与部署核对共同支撑具体范围，不能把文档齐全或静态检查通过当作系统已经安全。

状态：目标架构正文已获项目负责人接受。全系统质量结论由[质量与符合性](../assurance.md)汇总，各能力维护自己的实际验证资源。

## 安全性质与责任

| 性质 | 首要责任 | 需要观察的反例 |
|---|---|---|
| 主体与租户不混淆 | 认证入口、业务接口及调用组合。 | 切换界面或复用连接后，旧对象被当作新租户对象读取。 |
| 授权限制不能被旁路 | 准入、数据拥有者及实际执行边界。 | 明确禁止被模型、模式、HITL 或独立调用覆盖。 |
| 外传满足用途与接收方许可 | 模型、工具、遥测和导出调用方。 | 能读但无权外传的内容出现在实际发送载荷中。 |
| 隔离与共享范围真实 | 运行机制、环境提供者和装配方。 | 通过文件、缓存、环境变量或共享句柄读取其他范围。 |
| 撤权和恢复不复活资格 | 身份、工作拥有者及恢复协调方。 | 旧批准、旧登录或备份恢复的角色重新授权新动作。 |
| 内容不能自授控制权 | 内容接入、上下文组装及动作准入。 | 工具输出或外部文本直接改权限、作批准或跳过检查。 |
| 失败仍保持真实责任 | 各接口及跨边界协调方。 | 失败被显示成允许，未知写被重放，取消后无人保管结果。 |

每项性质须指向实际接口、检查位置及采用条件。发现缺少强制执行的边界时，不用增加一段提示词代替实现责任。

## 代表场景与反例

安全验证至少选择与本次变化相关的真实路径。

1. 两个租户使用同一类资源并交叉提交 ID，核对拒绝与信息披露。
2. 等待人工答复或排队期间撤权，再恢复原工作，核对实际准入点。
3. 明确禁止的动作分别经模型、外部 hook、人工批准和独立接口尝试执行。
4. 向文本、图片、语音或工具输出加入诱导指令，核对实际外传和执行边界。
5. 让环境建立失败或所需隔离缺失，确认没有降级到更宽松环境。
6. 切换凭据、模型接收方或遥测目标，核对实际发送的内容及身份。
7. 恢复含旧登录、成员与角色的备份，核对重新开放条件和未决报告。
8. 在主进程受限执行域内运行蓄意攻击代码，尝试取得宿主对象、其他租户数据及未授予的能力，并验证资源耗尽时的终止和恢复。

这些是选场景的方向，不要求每次修改机械执行全部测试。安全关键边界变化须覆盖其正常、拒绝、并发和失败路径，保留能暴露所声称缺陷的断言。

## 证据范围与偏离

业务模型验证权限与状态规则，接口测试验证调用行为，真实环境验证文件、网络、子进程及运行机制。三者的证据不能相互替代。尤其不能从 TypeScript 类型、进程内模拟对象或一次正常调用推出恶意代码隔离成立。

报告应说明输入修订、运行方式、故障或攻击假设、已检查性质和未覆盖范围。安全日志与测试输出也要筛选秘密，不能为证明没有泄漏而在报告中公开真实凭据。

偏离应能定位到目标条款、实际执行边界、反例及责任人。已知违规、无法判定和未覆盖分别报告；新增数据访问或执行路径缺少必要边界时，不能用其他已通过的检查抵销。

## 未决事项与交付边界

主进程内按恶意代码设防、允许限制 Node API 和交互方式的方向已明确。所需保证见[执行隔离](execution-isolation.md#插件装配与代码信任)，具体机制及验证尚未完成，相应场景不能先算通过。主机管理员与原始备份持有者的首版保护边界已明确，验证报告不得承诺超出该范围的保密性。

普通成员组织创作委托、外部委托的完整协议，以及灾后恢复的可信材料和处置资格由其原拥有者继续承接。它们只限制依赖相应缺口的交付，不阻止已有边界的设计、实现和验证。

本页不新增通用安全认证或全量测试门槛。高风险规则的交付约束沿[质量与证据](../../engineering/quality.md)及实际接受标准执行；完整安全证据须随所交付能力逐步建立。
