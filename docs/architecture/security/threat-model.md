# 保护对象与威胁模型

本页维护整个安全专题共同使用的保护目标、攻击入口和信任前提。其他页在这些前提下定义各自控制，不另行假定调用方、模型或插件天然可信。

状态：目标架构正文已获项目负责人接受。已明确主机与原始数据的保护范围，并要求防范主进程内的恶意代码；具体执行机制尚未选定，不能据本页推断已有实现安全。

## 保护对象与安全目标

| 保护对象 | 须维护的性质 |
|---|---|
| 用户、组织和租户内容 | 按身份、用途和范围访问，禁止未经授权的读取、外传和修改。 |
| 密码、登录出示物、服务凭据与密钥 | 仅在必要环节取得和使用，避免进入普通内容、日志及错误输出。 |
| 资产、权限、模式与装配依据 | 只有获准主体能变更；记录真实采用值，不让内容修改绕过治理。 |
| 工作、结果与账目 | 保留归属和因果关系，防止篡改、重放和伪造完成；按耐久承诺保存。 |
| 文件、进程、网络与计算资源 | 限制使用范围和消耗，防止一个调用扩大到无关资源或拖垮其他工作。 |
| 授权、人工决定与安全证据 | 明确作用对象、有效条件和实际结果，不能复制旧决定以获得新的操作权。 |

机密性、完整性和可用性须分别判断。成功阻止读取不代表可以无界消耗资源，数据加密也不代表有权执行某个动作。

## 参与者与信任边界

系统接收用户、外部应用、模型、工具、插件和其他业务能力的输入。每种输入应明确主体身份、来源、结构和允许产生的效用。经过认证的主体仍可能发出越权请求，可信工具也可能返回来自不可信网站的内容。

以下事实不能互相替代。

- 代码由谁部署，与代码处理的内容是否可信。
- 连接是否受保护，与请求是否代表有效账号和租户。
- 数据位于哪个工作区，与请求者是否有权读写或执行。
- 请求路径字符串，与这次操作实际使用的对象。
- 模型给出了什么建议，与建议对应的实际动作是否获准。
- 插件位于哪个 Cordis 作用域，与插件能访问哪些进程资源。

信任判断须在每次跨边界使用时落实到明确依据。尤其不能把持有对象 ID、路径、句柄或历史批准记录当作完整授权。

## 威胁与控制责任

| 代表性威胁 | 可能经过的入口 | 控制责任 |
|---|---|---|
| 伪造主体或替换租户 | 网络请求、程序化调用、后台任务。 | 认证边界解析可信主体，业务边界校验归属及当前资格。 |
| 越权读取或借服务代操作 | 资源 ID、共享对象、工具调用、管理入口。 | 实际操作方按原调用主体核对权限，避免用自身权限替请求者放行。 |
| 提示注入与内容冒充指令 | 网页、仓库文件、附件、工具结果、共享资产。 | 内容接入保留来源，动作准入独立执行权限检查。 |
| 未获准的数据外传 | 模型请求、工具参数、遥测、导出和错误信息。 | 数据外传方核对接收方、用途与内容范围。 |
| 过期批准或旧状态复活 | 重试、恢复、延迟答复、备份还原。 | 授权及工作拥有者检查当前资格、原身份和有效决定。 |
| 隔离逃逸或共享污染 | 插件、子进程、挂载目录、环境变量、共享缓存。 | 代码装配方和执行环境方声明并落实实际隔离边界。 |
| 资源耗尽 | 超大输入、长流、并发工具、扩展及等待。 | 各资源拥有者实施相应额度、背压、超时和回收。 |

防护须覆盖正常入口之外的后台、重试、恢复和独立调用路径。仅修复某个界面不能证明同一公开能力的其他路径也受保护。

## 保证前提与未覆盖范围

具体部署须声明所信任的操作系统、管理权限、存储和执行环境，以及这些条件不成立时哪些保证失效。不能只用“单机”或“云端”推导安全性。

首版不承诺阻止主机管理员或原始数据、备份持有者读取其中内容。部署者须保护主机、存储目录和备份的访问与分发。这一限制不取消系统内的租户隔离、权限检查和外传控制，也不能用于解释普通业务入口的越权。

系统须支持不可信代码进入主进程，并防范其蓄意窃取数据、读取宿主秘密、绕过授权及耗尽资源。为此允许限制可用 Node API 和交互方式，不承诺任意 Node.js 插件兼容。具体保证由[执行隔离](execution-isolation.md#插件装配与代码信任)拥有。

执行引擎、受控宿主接口和操作系统构成这条代码边界的信任基础。它们的缺陷与进程级崩溃须按真实故障域处理，不能把同进程执行写成独立进程级的故障隔离。安全更新、故障检测与恢复仍是系统责任。

本设计不以模型始终识别恶意指令作为安全前提，不声称能够完全消除提示注入，也不以文档或模型测试代替沙箱、授权和部署条件的验证。物理介质损毁的恢复保证由数据与部署架构分别承接。
