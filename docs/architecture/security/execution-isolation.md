# 执行与资源隔离

本页说明实际代码、工具和子进程可以接触哪些状态与资源。业务授权决定是否允许动作，执行隔离限制动作实际能影响什么，两者须共同成立。

状态：目标架构正文已获项目负责人接受。已明确按恶意代码设防，并允许限制可用的 Node API 和交互方式。本文维护所需保证及已采用受限JS机制；实际提供者和完整隔离profile仍须验证。

## 隔离对象与共享矩阵

| 对象 | 可以共享的范围 | 不能由此推导的保证 |
|---|---|---|
| 租户私有资产、设置与凭据 | 按对应租户及明确授权访问。 | 同一宿主或同一工作区不授予访问权。 |
| 租户级沙箱数据 | 按产品规则供同租户的多个会话和 Agent 使用。 | 不承诺同租户各个 Agent 的文件互相隔离。 |
| 会话级或单次调用沙箱 | 按该环境的作用范围及寿命复用。 | 环境终止不保证其中临时数据已长期保存。 |
| 工作区文件及实例 | 按工作区关系和实际文件环境共享。 | 工作区目录与 `.omne.local` 不自动构成租户安全边界。 |
| 模型、工具及扩展输入 | 只向获准消费者提供相应数据。 | 能获得一个句柄不等于能遍历全部系统数据。 |
| 同进程代码与资源 | 通过满足下文保证的受限执行域提供获准能力。 | Cordis 作用域与模块接口本身不证明能抵御恶意代码。 |

隔离应覆盖数据存储、缓存、订阅、文件、网络和执行资源。不能只在首次建立会话时过滤一次，之后通过共享缓存、事件或句柄泄漏其他租户内容。

## 环境选择与能力暴露

工具声明所需环境与设施，环境选择在当前权限和部署能力内完成。所需隔离不存在、建立失败或无法确认时，拒绝依赖该条件的执行，不能静默退回宿主机或更宽松环境。

宿主机本身不提供租户级隔离。工作目录只确定文件操作的起点，不限制进程还能访问哪些目录。需要文件、网络或子进程限制时，实际提供者须给出相应机制和边界，不能以路径约定宣称已经限制。

环境变量、挂载、网络目标和可调用服务按消费者的需求及授权提供。某个工具获准使用一项凭据，不代表它应获得完整配置仓库。工具也不能借通用桥接接口任意装载插件、取得系统 Context 或访问无关服务。

独立工具调用使用等价的环境和授权契约，无须先创建 Session，但不能省略它所依赖的隔离条件。详细环境生命周期由[执行环境](../runtime/execution-environment.md)维护。

## 插件装配与代码信任

系统须支持不可信代码在主进程内运行，并按其可能蓄意读取秘密、越权操作或耗尽资源设计边界。为实现这些保证，可以限制 Node API、模块加载与交互方式，不要求兼容任意 Node.js 插件。

本文将主进程中承载这类代码、限制其可达数据与能力的运行边界称为受限执行域。它不等同于普通模块、Cordis 作用域或一个 JavaScript 全局对象。代码可以在同一进程内运行，但不因此取得宿主执行权限。

```mermaid
flowchart LR
  subgraph P[Harness 主进程]
    subgraph I[受限执行域]
      U[不可信代码]
    end
    U --> B[受控宿主接口]
    B --> A[身份、授权与资源检查]
    A --> S[获准的系统能力]
    Q[独立于恶意代码协作的限额与终止控制] --> I
  end
  S --> D[对应租户数据或外部资源]
```

图中执行域与宿主处于同一进程，但没有向代码直接开放宿主对象和全部服务。图只表达所需责任，不指定线程、执行引擎或桥接库。

| 所需保证 | 对执行域与宿主的约束 |
|---|---|
| 数据不可任意到达 | 代码只能读取显式提供的输入和获准接口返回的数据，不能遍历宿主内存、其他执行域、其他租户数据或未授予的秘密。 |
| 宿主能力显式授予 | 文件、网络、环境变量、进程、模块加载及原生扩展不直接开放。需要的能力由受控接口提供，并限制资源、主体与用途。 |
| 桥接不能扩大权限 | 不传入原始 Cordis Context、全局服务容器或可任意追索宿主对象的引用。宿主校验跨界请求和返回值，拒绝伪造身份及超范围操作。 |
| 持有能力不能绕过撤权 | 代码持有的接口或句柄仍受实际使用时的授权条件约束。撤权对后续准入生效，不能仅删除发现入口而保留无限权限。 |
| 消耗有界且可终止 | 对执行时间、内存、并发、输出与宿主调用设置可执行的限额。终止不依赖恶意代码自愿检查取消信号，也不能被它阻塞在同一调度线程。 |
| 行为可归属 | 宿主记录代码身份、修订、实际授予能力、关键调用及终止原因。恶意代码自报的结果不能替代这些事实，记录也不能泄漏秘密。 |

执行机制必须分别证明这些边界。不能将普通模块加载、`node:vm` 或 Node 的进程级权限配置视为充分保证。Node 官方明确说明 [`node:vm` 不是安全机制](https://nodejs.org/api/vm.html)，[权限模型不保护同进程恶意代码](https://nodejs.org/api/permissions.html)。具体提供者若不能满足上表，就不能承接这一运行方式，不能以“已经授权加载”免除限制。

受限执行域依赖所采用执行引擎、宿主桥接和操作系统的安全前提。同进程执行仍共享进程故障域，不能承诺任意引擎缺陷、原生崩溃或进程终止只影响一个插件。装配与部署须能识别这类故障、隔离故障实例并按已保存状态恢复；恢复不得把未知外部效果当作未执行直接重放。具体故障域与监督安排由部署架构承接。

终止执行域是停止其中代码继续执行，不表示已准入的宿主调用同时停止。桥接与调用拥有者须继续承接这些调用及迟到结果，按各自取消和交付契约收口，不能只向已销毁的执行域返回结果。独立生命周期与取消责任沿[控制与恢复](../runtime/control-and-recovery.md)及相应模型、工具运行时规则执行。

代码的来源、发布版本、依赖与实际加载身份须可定位。知道谁发布了代码不等于证明代码安全，扫描或签名也不自动授予其读取其他租户数据的权限。插件升级和动态替换仍需遵循原数据、能力及在途工作边界。

## 受限JS profile

受限JS路线及具体引擎基线归[系统技术基础](../technical-foundations.md#共同技术选择)。该profile只接纳受限guest代码与获准模块，不能声称能够安全执行任意Node插件。QuickJS WASM置于专用Worker，由域外监督者控制期限、输入/输出字节和退出。guest runtime限制内存、栈及计算中断，WASM、ArrayBuffer、宿主回调和外部动作的资源另计，不能用Worker resourceLimits覆盖全部内存。

默认不开放文件、网络、进程、Node模块、Cordis Context、宿主对象引用或原生扩展。桥接只接受经过边界校验的数据、范围受限的操作身份及受控返回值，每次实际动作重新核对授权和代际。许可不由guest自报tenant或过去的加载检查授予。宿主请求和返回、并发及pending jobs有有限预算，异常路径释放guest handles并保存原动作实际结果。

默认采用guest Promise及受管pending jobs，不以Asyncify扩大接口。guest销毁只关闭其执行域，不撤回已经获准发出的模型、工具或通知动作。原调用拥有者继续保管晚到结果与费用，取消及未知效果按原协议处理。

桥接预算包含所有emit和最终返回的累计编码字节，也覆盖错误诊断及传输封装。先dump或序列化再检查只能限制已转换的结果，不能证明转换前的分配有界。提供者须另验证大对象、循环引用、BigInt、异常及宿主回调成本，不能用有限算术返回或Worker启动证明CPU、安全或完整输出预算成立。

profile开放前须验证死循环、内存/栈/输出耗尽、恶意模块加载、宿主对象逃逸、桥接权限绕过、撤权竞争、超时和实际退出。QuickJS/Worker名称本身不证明隔离成立，符合性失败就拒绝该profile的执行。需要一般shell、原生扩展或浏览器时，使用明确OS隔离与可终止设施，不回退为未经验证的同进程执行。本页不声明Windows、macOS或任意容器环境已经支持。

## 资源回收与故障边界

资源拥有者明确输入大小、并发、内存、输出和执行时间的适用限额，并提供取消或终止的实际机制。额度和终止效果须在所声明运行方式下验证，不能只给普通函数传一个取消标志就宣称可中断任意代码。

卸载插件、停止准入、取消工作和进程结束分别记录。已发的模型请求、工具及外部副作用不因上层代码退出而自动撤回；必要资源保留至原调用完成或责任可靠交接。

执行环境或代码运行机制失效时，按其真实故障域报告影响。新建环境不证明旧调用已经停止，进程共享也可能扩大故障影响；持续运行要求与具体隔离保证须在实现选择中一起核对。

## 使用时的文件对象

请求路径只是调用方给出的字符串。授权检查的是这次操作实际使用的对象，并且发生在使用时点。相对路径的起点缺省是工作目录。工作目录不是授予根。授予根由声称文件限制的 profile 另行声明。

操作跟随符号链接时，授权针对链接目标。链接路径在授予根内而目标在根外，则使用对象在根外。不能解析目标时，拒绝依赖该解析的文件操作，不退回只检查路径字符串。

声称把文件限制在授予根内的 profile，必须确认使用对象位于该根内，并且使用对象就是所检查的对象。确认不了就拒绝该操作。不能改用路径前缀，也不能退回宿主机。检查和使用之间对象被换掉，而提供者不能证明用到的仍是检查过的对象，则结果是拒绝或未知。

活动句柄只标记一次使用对象及其代际。它不是持久授权，也不是持久数据格式。再次使用时重新检查当前授权。本页不定义句柄字段。

## 进程退出观察

进程已退出只在域外监督者记录到该进程身份的回收状态时成立。回收状态是退出码或终止信号。该监督者不是不可信代码，也不是代码能够占住的同一调度线程。

完成通知、取消请求、取消已受理、`dispose()`、Run 终态、空引用计数、域内代码已停、到点的中断请求、一次查不到、超时或没有返回，都不写成进程已退出。一次查不到保持未知。父进程退出不写子进程的退出。再次读取同一身份的回收状态返回原记录，不创建进程。

当前产品责任候选包括[执行环境](../../../.meta_harness/design/product/execution-environments/README.md)、[工具执行](../../../.meta_harness/design/product/tool-execution/README.md)和[工作区](../../../.meta_harness/design/product/workspaces/README.md)。这些 topic 仍为草案；已接受运行架构继续有效。受限JS路线已经采用，任意Node插件、OS隔离profile和实际提供者的符合性仍须分别承接；现有可信集成契约不因此覆盖不可信代码。
