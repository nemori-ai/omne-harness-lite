## 公共数据模型与身份

### 身份、归属和关联

系统区分以下几类值。它们即使都用字符串传输，也不能互换。

| 值的用途 | 共同约定 |
|---|---|
| 账号、组织、租户及领域对象身份 | 由所属定义规定相等性、有效形状和生命周期。租户由组织与账号共同确定，成员资格失效不创造另一个租户。 |
| 逻辑工作、执行尝试与运行实例身份 | 分别标识持续的工作、一次推进尝试及具体实例。恢复或换实例不能丢失原工作关系。 |
| 提交身份与幂等键 | 在声明的作用域内识别同一次操作。不能以文本相同、追溯 ID 相同或尝试相同推断业务重复。 |
| 地址、附件引用与日志坐标 | 用于定位资源或位置。持有这些值不等于拥有访问许可。 |
| 登录材料、授权依据与交接凭证 | 用于特定边界的资格判定。适用对象、来源与有效条件须能核验。 |
| 日志和遥测的关联标识 | 用于追踪因果和实际执行。不能替代业务身份、授权依据或提交证明。 |

数据归属可由记录封装或已经认证并明确绑定的调用通道携带，不要求每个内容块重复存租户字段。跨边界传递时，接收方须取得并核验必要归属，不能从正文、文件路径、当前界面或进程推断租户。

本页的登录入口租户冲突规则由[身份与授权产品草案](../../.meta_harness/design/product/identity-and-authorization/design.md#加入组织后按明确的租户身份协作)承接产品责任，草案尚待接受。经登录状态进入治理服务的请求，若显式租户与该登录状态当前选中的租户不一致，入口拒绝该请求，不按任一租户继续业务操作。调用方须先切换或使用匹配的登录状态。身份或当前租户无法核验时，按该入口的认证与不可用规则处理，不能伪报为已确认的租户冲突。此规则不改变既有 Session、Run 和后台工作的固定归属，也不改变独立调用按其显式授权依据核验的方式。

### 表示与校验

跨模块共享的语义值由同一公开定义维护。使用者引用该定义，适配器显式转换；不能各自复制一个同名类型，再假定它们含义相同。

外部输入在边界完成表示校验。解析成功只说明形状合法，对象存在性、当前授权、版本可用性及跨记录关联继续由相应拥有者判定。未知判别值按协议声明的拒绝或扩展规则处理，不能静默降成已有值。

使用 JSON 的公共边界须保留契约要求的数值精度，拒绝解码后的重名键等歧义表示。精确数值不能经 JavaScript `Number` 转换后再声称无损。缺席、`null`、空集合和未知分别按字段定义解释，不做隐式互换。身份值的大小写、空白及 Unicode 形式遵循身份契约，适配器不得自行规范化而改变相等性。

多模态内容按结构化块及媒体类型表达。文字、图片和语音都可携带来源与引用，派生表示须能区分于原内容。人可见、模型可见与访问授权分别判断；隐藏于某个显示通道不构成保密边界。附件的可访问性、完整性、保留期和失效处理由内容及存储契约承接。

公共JSON边界先执行严格UTF-8解码，在逐对象扫描时检测解码后重名键，保留数字原词法再交字段codec。禁止注释、尾逗号及空输入，任一语法错误拒绝整份输入。项数、深度、字符串和数字均有有限预算。JSON.parse之后无法找回已丢失的重名键和精度。增量解析必须兑现同一拒绝语义。精确签名与失败种类见[公共 JSON 文本读取](#json-text-reader)。

每份公共形状只有一个拥有源，TS类型和编码从该源派生。校验不默认coercion、填默认或删除字段，拒绝无法保留精度和未知值语义的转换。具体Schema及严格JSON技术路线归[系统技术基础](technical-foundations.md#共同技术选择)，按需加载、首次编译及运行时换代归[缓存机制](data-and-state.md#缓存懒加载与预热)。活体对象、句柄、函数和Context不能进入序列化数据契约。

#### 公共 JSON 文本读取

公共 JSON 文本只有一个纯读取器。它不导入 Cordis、业务存储或插件树。调用方传入字节或已经解码的文本，以及自己的预算。

```ts
readJsonBytes(bytes, limits) -> JsonRead
readJsonText(text, limits) -> JsonRead
```

`readJsonBytes` 对字节做致命 UTF-8 解码，并且不跳过 BOM。`readJsonText` 只接收已经完成致命解码的文本。`readJsonText` 的文本含孤立代理项时抛 `TypeError`。JSON 源码里的 `\u` 转义不因此抛 `TypeError`。文本以 U+FEFF 开头时，结果是 `bom`。

`limits` 有 `maxBytes`、`maxDepth`、`maxItems`、`maxMembers`、`maxStringLength` 和 `maxNumberLength`。每个字段都是 1 到 `Number.MAX_SAFE_INTEGER` 的整数。缺字段、非安全整数或超出该范围抛 `TypeError`。`readJsonBytes` 只接受 `Uint8Array`。`readJsonText` 只接受字符串。参数类型不对时抛 `TypeError`。读取器不提供默认预算。

成功结果的 `kind` 是 `ok`，并带 `value`。每个 JSON 数字的 `kind` 是 `number`，值是源词法 `lexeme`，不转成 JavaScript `number`。对象的 `kind` 是 `object`，以 `entries` 保存键的出现顺序。数组的 `kind` 是 `array`。键 `2` 在键 `1` 之前出现时，结果保持这个顺序。失败结果不带 `value`，也不抛 `SyntaxError`。

失败种类是 `utf8`、`bom`、`empty`、`syntax`、`duplicate-key` 和 `budget`。`syntax` 的原因是 `comment`、`trailing-comma`、`token`、`truncated` 或 `trailing-content`。`duplicate-key` 带从根到父对象的路径，以及解码后的键名。路径中的对象键是字符串，数组下标是数字。`budget` 的名目是 `bytes`、`depth`、`items`、`members`、`string` 或 `number`。

读取器按下列顺序停止。`readJsonBytes` 先拒绝非法 UTF-8，再拒绝 BOM，再拒绝超过 `maxBytes` 的输入。`maxBytes` 是整份输入的 UTF-8 字节长度。`readJsonText` 没有 `utf8` 失败。它先抛出孤立代理项的 `TypeError`，再拒绝 BOM，再按文本的 UTF-8 字节长度拒绝超过 `maxBytes` 的输入。然后两边都拒绝空输入。只含空格、制表符、换行或回车的输入是空输入。

对象键在扫描对应的值之前判定。`maxStringLength` 是解码后的 JavaScript 字符串长度，键和字符串值都用它。解码后的键超过 `maxStringLength` 时，结果是 `budget` `string`。再接受一个成员就会超过 `maxMembers` 时，结果是 `budget` `members`。`maxMembers` 按单个对象计数。键已经出现过时，结果是 `duplicate-key`，并且不再扫描该值。

一个值开始时，先看容器深度，再看项数。根容器的深度是 1。`{` 或 `[` 会使深度加一。加一之后大于 `maxDepth` 时，结果是 `budget` `depth`。项是一份文档里的 JSON 值。容器也算一项。键不算项。同一个 token 上深度和项数都会超限时，结果是 `depth`。`[1]` 在 `maxItems` 为 1 时是 `budget` `items`。

字符串先看原始文本是不是合法 JSON 字符串前缀。未闭合字符串里已经出现非法转义、控制字符或其他非法内容时，结果是 `syntax` `token`，先于长度，也先于 `truncated`。合法字符串的解码长度超过 `maxStringLength` 时，结果是 `budget` `string`。合法但没有写完、并且还在长度预算内时，结果是 `truncated`。数字先按 RFC 8259 核对源词法。不合语法的词法是 `syntax` `token`，出现在文本末尾也一样。合语法的词法长度超过 `maxNumberLength` 时，结果是 `budget` `number`。`maxNumberLength` 是源词法的字符长度。

值没有写完，且尚未发生非法内容、预算或重复键失败时，结果是 `truncated`。

`{"a":1,"a":` 在 `maxMembers` 为 2 时是 `duplicate-key`。`{"a":[` 在 `maxDepth` 为 1 时是 `budget` `depth`。`{"a":` 是 `truncated`。

字段 codec 在读取成功之后运行，由该形状的拥有者持有。缺席的键是 `undefined`。JSON `null` 不是缺席。字段拒绝已经出现的 `""`、`[]` 或 `{}` 时，失败种类是 `empty`。JSON 种类与字段要求不同时，失败种类是 `type`。`encode` 无法保留字段含义时返回 `type` 或 `precision`。它不返回缺席、`null` 或空值失败。读取成功不表示对象存在，也不表示调用方得到授权。

对同一份完整文档，增量读取与一次读取给出同一个 `JsonFailure`。语法引擎在报错之后仍给出的值，或在重复键中保留的某一个值，都不是成功结果。编译、运行时、异步路径和缓存归[缓存机制](data-and-state.md#缓存懒加载与预热)。

## 消息、记录与流

系统分别命名发生的事、记录条目、会话消息、业务通知、流式到达、Cordis 事件和工程遥测，不以一个未加限定的“事件”统称它们。

| 对象或数据 | 作用与边界 |
|---|---|
| 发生的事 | 业务上实际发生的变化，不以观察方是否收到消息为成立条件。 |
| 记录条目 | 按所属契约保存依据或留痕。记录条目不可变，纠正通过追加表达；效力、归属、版本及保留责任须明确。已持久化不等于可送入模型。 |
| 会话消息 | 结构化内容及其消息语义。日志封装承接归属和顺序，消息正文不替代全部运行事实。 |
| 业务通知 | 面向接收方的交付。发送受理、送达和已读分别表达，不从任务执行成功推断通知成功。 |
| 流式到达 | 在途增量与收场信息。流结束不自动证明结果已持久提交，临时流也不自动支持断线重放。 |
| Cordis 事件 | 声明了派发和等待方式的进程内协作机制，不自带持久化或跨节点投递保证。 |
| 工程日志与遥测 | 描述运行状态、诊断和指标，不替代业务账目、授权依据或恢复所需事实。 |

状态计算使用哪些记录，由状态拥有者声明。属于依据的记录与普通留痕分开，投影标明来源和处理进度。模型调用技术记录不因位于会话日志中就自动进入模型上下文。

完整消息、已展示但中断的内容、尚未收场的增量分别按[流式与消费](runtime/streaming-and-consumption.md)处理。不能把所有到达字节都承诺为永久历史，也不能把收场后的内容当作从未发生。通知只能促使消费者读取和核对，不能自行授予推进、访问或 ACK 的资格。

## 接口协议与错误语义

### 共同基础与领域结果

公共 SDK 共用请求关联、错误分类等基础契约，各领域保留自己的结果类型、进度表示和流式接口。基础契约定义一次，由公开能力、SDK 和适配器共同引用；不为统一外观强迫所有操作返回同一个信封。

调用关系按[分层与依赖](layers-and-dependencies.md)组织。SDK 可以简化连接、编解码和错误识别，但不能把异步受理包装成已经执行成功，也不能丢掉原操作的未知结果、外部效果或信息披露限制。

每个公开操作须说明输入与授权、前置状态、何时受理及提交、可观察结果、失败分类、幂等范围、取消效果和恢复路径。只具备函数签名或 DTO 不足以构成完整契约。

### 结果与失败

下列维度按操作实际需要表达，不能被一个成功布尔值覆盖。它们不是所有操作都必须实现的阶段，也不是一组固定错误码。

| 维度 | 调用方必须能够辨认的区别 |
|---|---|
| 表示与传输 | 输入无法解释、没有发出、已发出但没有取得可确认的答复。 |
| 资格与业务受理 | 身份或授权不满足、必要判定不可得、业务条件拒绝、已可靠受理。 |
| 实际执行 | 尚未开始、等待或运行中、已知完成、已知失败、无法确认结果。 |
| 持久与外部效果 | 未成立、已确认成立、无法确认是否成立。操作失败不自动意味着零副作用。 |
| 客户端显示 | 权威结果、带来源和时效的缓存或投影、数据当前不可得。 |

错误须保留可编程识别的分类及所需关联信息，面向人的解释不代替稳定语义。领域拒绝、依赖暂时不可用与实现缺陷有各自出口。适配器不能把任意异常文本转换成一种看似正常的业务失败。每层声明可自行处理的失败、需要交给谁处理的失败及最终结果；交接保留必要关联与已发生的效果，并按披露范围裁剪诊断内容。

错误映射同时遵守信息披露规则。某些入口隐藏对象是否存在，其他入口可以区分不存在与无权访问；共同错误分类不要求向每个调用方暴露相同细节。内部诊断与外部答复可有不同精度，但两者都必须真实。具体可见性和检查次序由该边界契约规定。

结果未知时，调用方查询或认回原操作，或按原契约进入待核实状态。不能因断连、超时或 `unavailable` 就宣称没有效果并自动重做。SDK 的自动重试只用于契约明确允许的范围。

## 并发、取消与恢复

一个逻辑工作可以跨多次尝试、运行实例和物理节点持续。工作身份保持稳定，尝试和实例分别标识；原调用的迟到结果仍归原工作。追踪标识用于关联，幂等键用于判重，两者不能互相替代。

提交方在首次提交前确定并保留提交身份。回执丢失后的同次提交继续使用它；用户主动发起的另一操作使用新身份。具体去重作用域、冲突输入、保留期限及查询方式由操作契约声明，不以全局内容哈希代替。

并发修改须有可核对的预期版本、原子条件或其他明确协调规则。版本冲突、授权变化与存储不可用分别处理。多个写入在同一数据库中执行，不自动构成共同事务；跨拥有者提交的参与者、确认和未知处置见[数据与状态](data-and-state.md)。

取消请求、取消意图被可靠接受、停止新工作、实际执行终止、逻辑终态和资源释放是不同事实。释放观察者、停止等待或关闭客户端连接，不自动取消模型与工具调用。作用域撤除时，已经开始的工作继续按原调用契约交接与收场。

传输缓冲、内存工作集和实际执行并发须有边界及背压。它们不能被当作丢弃已可靠受理输入的理由。受理前的准入与已受理工作的保存责任分开；具体恢复与控制行为归[控制与恢复](runtime/control-and-recovery.md)。

## 时间、顺序与版本

时间点、持续时长、业务期限和计划时间分别建模。对外表示声明单位、精度、时区及允许范围，跨表示转换检查溢出和精度损失。公共时间值由共享契约维护，业务拥有者继续决定到期边界、时间来源及异常时的行为。

等待耗时与重试间隔使用适合计时的时钟；跨节点业务期限不能依赖一个进程的单调时钟值。业务要求可信时间时，时间源不可用不能偷偷改用本机墙钟。是否允许降级及其结果由该业务契约声明。

时间戳、日志位置、因果关联和并发版本分别表达。不同节点时间戳不能制造全局总序；日志位置只在其所属日志及代际范围内比较。计划发生时间、实际受理时间和实际执行时间也不能合为一个字段。

版本须指出版本化的对象。协议版本、数据 Schema 版本、资产内容版本、装配采用版本、投影处理进度和物理实例代际各有含义，不能用一个全局 `version` 代替。读取旧版本所需的解码能力不意味着允许继续以旧协议执行操作。

## 配置与可观测性

### 配置的来源与生效

资产选入、设置覆盖与权限求值采用各自规则，不能归为通用的“内层覆盖外层”。工作区参与其允许的内容和设置供给，不成为权限授予层。完整组合顺序归[装配与变化](runtime/assembly-and-change.md)。

每项配置声明所属对象、合法来源、默认值规则、校验边界、覆盖方式和生效时机。必需配置缺失或非法时，按契约拒绝、保持原有效值或进入明确降级状态，不能自行补默认值。

运行中的输入按类声明捕获时点。已经发出的调用保留实际采用依据；凭据、权限或动态策略在契约规定的时点重新核验。文件改变、注册表更新、配置计算成功和新版本实际生效是不同事实。

可序列化配置与秘密材料、管理权限及活的运行句柄分开。记录采用版本和来源时，不把完整凭据、用户正文或可复用授权写入诊断数据。

### 观测与遥测

每个能力及其组合都须提供足以解释输入到结果的观测。记录明确租户或系统作用域，按工作实际具有的层次关联逻辑工作、尝试、调用与实例，并在相关阶段指出采用的能力版本、装配依据和执行环境。无 Session 的工作也须可追踪，不能伪造一个 Session 来补齐字段。

记录须区分受理、开始、等待、恢复、取消意图与实际结果、失败和未知效果。模型、工具、存储和外部通知各自报告其真实阶段，不能用上层“完成”覆盖下层未知。延迟、排队、吞吐和资源压力的指标须有统计范围与单位，避免把排队时间当执行时间。

观测格式可以共享关联字段与分类约定，具体事件内容由所属能力定义。系统不要求建立一条拥有全部业务事实的全局事件流，也不以特定日志库、遥测后端或导出协议作为领域契约。

采样、丢弃、过期和导出失败须可辨认。关键生命周期、失败和审计事实不能静默采样掉。必要记录不可用时，操作按自身契约暂停、拒绝或标明无法确认，不能假装已记录成功。观测本身的存储、缓冲和导出成本也须受控。

查询与导出执行租户隔离、权限检查和内容保护。开启遥测不授予外传用户数据的权限，导出只面向经过授权的目的地。日志采集和诊断读取不得再次执行原操作。详细目标归[工程观测与结果真实性](../requirements.md#工程观测与结果真实性)，隐私约束归[数据与隐私](security/data-and-privacy.md)。

能力通过注入的结构化观测接口记录行为，Node提供者和输出端由应用选择，具体库及基线归[系统技术基础](technical-foundations.md#共同技术选择)。纯能力不导入Node遥测SDK。OTel提供上下文和运输，不取得业务事实权威；Pino普通输出也不承担账目、授权决定和恢复记录的唯一耐久保存责任。

跨异步等待、线程/进程消息、队列及重建，显式保留获准的租户、主体、原工作、调用、attempt、实例、配置与提供者代际。AsyncLocalStorage仅方便同进程关联，IPC接收方核验显式身份，不把自报trace字段当授权。指标避免无限租户/工作标签，必要明细通过获准日志与trace定位。

输出端、采样、队列项/字节及刷新期限均有界，普通遥测丢弃、延迟、导出失败和保留期造成的缺口可观察。关键生命周期、失败、审计及业务账目按各自可靠责任保存；不能因普通采样或logger transport关闭静默消失。必要记录不可得时按原动作的阻止、保留待补或未知规则执行，不无条件停全部系统，也不伪报动作成功。

秘密和未经授权内容在采集边界排除或脱敏；导出时再次核接收方、处理目的和内容范围。对象toJSON或完整请求dump不成为默认记录接口。输出端故障使用有限本地诊断路径，不能递归记录同一输出失败直至占满资源。关闭核对最后记录、flush实际结果及transport退出，截止时间到达不冒充导出成功。

OTel的forceFlush完成不自动表示每条记录导出成功。提供者核对实际导出数、队列丢弃数、失败诊断及最后未承接记录，导出器报告失败时不能只凭Promise完成声称刷新成功。Pino文件写入与OTel采样/队列导出的职责和有效输出数分别验证，不按发出次数相同就比较吞吐。

## 装配与资源管理

领域能力的公开接口独立于 Cordis，Cordis 绑定负责集成装配、依赖和生命周期。纯数据转换不因被装配使用就必须成为服务。跨进程协议传递声明的数据与能力引用，不传 `Context`、`Fiber`、闭包或物理连接充当远端契约。

资源接口须声明谁创建、谁拥有、谁可以借用、谁负责关闭及何时不再接受新工作。注册撤回、服务替换和运行实例销毁不自动证明原调用已结束；释放前后的允许操作与在途交接按各自生命周期规定。

清理失败或部分完成须可观察，再次关闭的效果由资源契约说明。不能因请求了清理就报告全部释放，也不能无限保留已失去消费者的订阅和缓冲。具体 Cordis 装配约束、独立执行拥有者及退出顺序归[Cordis 与生命周期](deployment/cordis-and-lifecycle.md)。

## 契约演进与符合性

### 维护与检查

共同值和基础契约的拥有者维护公开形状、无法由类型表达的行为、适用版本和相称验证。领域契约引用共同定义，传输适配器证明转换保持其语义；类型相同、可编译或 JSON 可解析不等于行为一致。

接口修改同时核对 SDK、服务端、独立消费者、Schema、持久数据与恢复路径。当前阶段允许有正向收益的破坏性重构，但须迁移实际消费者，删除被替代的现行实现，不能把第一版发布前的政策当作永远没有版本责任。

| 核对范围 | 可采集的证据 | 证据不能单独证明什么 |
|---|---|---|
| 定义与引用 | 导出入口、依赖方向、重复定义、Schema 引用及版本对应检查 | 同形类型具有同一业务含义 |
| 表示转换 | 精确值、未知值、缺席、无效引用和跨边界往返用例 | 当前权限、可靠受理和副作用正确 |
| 操作与恢复 | 受理后断连、提交未知、同次重试、取消竞态、撤权和迟到结果测试 | 未覆盖的故障及无限规模成立 |
| 隔离与观测 | 跨租户反例、错误披露、秘密泄漏、关联连续性及观测故障测试 | 日志存在就等于事实已可靠提交 |
| 提供者替换 | 共享符合性场景及真实组合验证 | 单个 mock 或纯类型检查证明部署可用 |

偏离报告分别列出全量已知差异、本次新增与消除、未覆盖及无法判定项，并给出相关承诺和消费者。高风险规则是否阻断交付，按工程治理的明确清单判断；本页不把所有检查失败升级成新的硬线。
