技术讲解

W1 之后源码里有什么（父分支 aafc0cdc9；W2 增量见文末）

Skill 组仍是三个成员，只有 @omne-harness/skill-contract 有实现：22 个源文件、约 2400 个非空行、13 个测试文件 364 例。另外两个成员仍是模板草稿。读这个成员时按三个入口分开读，三者在 package.json 的 exports 里各占一条。

  • 公开根 .（给调用方）：index.ts 只做重导出。值与品牌在 values.ts、names.ts、digest.ts、media.ts；失败联合在 failures.ts；三个应用服务接口在 services.ts；包检查纯函数在 parse/；类别端口在 contract.ts；资产正文投影在 project.ts。
  • ./provider（给端口实现方）：provider.ts 只重导出 ports.ts 的三个端口类型、PackageInspection、SkillRef、PackageLocator，以及唯一的运行时导出 sealSnapshot。公开根拿不到这些名字，所以调用方无法构造快照、也看不到包定位。
  • ./testing（给实现方自测）：testing.ts 聚合三个套件与三个内存替身。套件返回 ConformanceCase[]，用例用 node:assert/strict 失败，与 tool-contract 同形，不依赖测试框架。

依赖方向

模块图是一棵严格的 DAG，根是 values.ts（只有类型，没有导入）。往上一层是品牌授予与纯函数（names、digest、media），再上一层是 snapshot.ts（用这三者算条目事实）和 parse/（shape → declaration/manifest → package）。contract.ts 复用 parse/shape.ts 的读取器，所以资产正文和 .omne/skill.json 对 scripts、settings 的规则只有一份。testing-* 只依赖端口与值，不被任何非测试模块导入——public-entry.spec.ts 沿 src 的导入图核对这一点。

两条真实的调用路径

  1. 检查一个包。来源把文件字节交给 sealSnapshot(rootName, files)：它逐条算编码、大小、媒体类型与条目摘要，按 UTF-16 码元排序，拒绝重复路径与「文件同时是目录」的前缀冲突，再把快照登记进模块私有的 WeakSet 并以断言式守卫收窄成品牌类型。然后 parseSkillPackage({ snapshot, control, expectedName? })：先 assertSealed（伪造快照抛 TypeError，这是调用方的编程错误），再核对两份控制文件字节的摘要（不符答 version-changed，这是竞争，不是错误），然后 readManifest 解析 SKILL.md 头部（frontmatterOf 逐行找定界，yaml-value.ts 把 YAML 节点转成带预算的纯值）、readDeclaration 解析 .omne/skill.json，所有发现攒进一个列表，最后 firstFinding 按封闭次序（INSPECT_REJECTIONS）取第一条拒绝。名字必须逐字等于包根目录名。
  2. 类别端口。skillBodyContract() 返回 assets 的 BodyContract。judge 的次序是：是真实读取 → 有 name → 等于能力名 → 合 SkillName 词法（name-invalid，本波新增）→ 工具引用合法 → 四个可加字段（description、scripts、settings、package.digest）合形。deriveDeclarations 对每项设置声明产出 setting:<类别>:<名字>。

怎样保证「只能由构造器造出」

两层。类型层：SkillPackageSnapshot 的品牌键是 values.ts 里模块私有的 unique symbol，三个入口都不导出它，不写 as 就造不出这个类型；types.spec-d.ts 证明字面量赋不进去。运行时：{ ...snapshot } 能骗过类型检查，所以 parseSkillPackage 再查 WeakSet。代价写在 SPEC：这是进程内凭证，不可序列化，同一成员被加载成两份实例时互不承认。

还没有的东西

三个应用服务只有接口：PackageInspection（在 ./provider，因为它的调用方是来源与资产登记一侧）、SkillCatalog、SkillAccess。它们的实现、读取 11 步、目录来源都在 W2。

W2 增量 1：@omne-harness/skill-host-local（父分支 478e56381）

第一个真实的端口实现方。4 个源文件 341 行、10 个测试文件 54 例，公开根只有 createDirectorySource(options?) 与三个类型（DirectoryFs、Opened、EntryKind）。三层：

  • fs.ts 是文件系统接缝：四个方法（readdir、lstat、realpath、readFile），名字以字节交出（不是字符串），readFile 交出「打开结果」——普通文件的字节，或「这是目录」「这是别的对象」两种种类。默认实现 nodeFs() 用 O_RDONLY|O_NOFOLLOW|O_NONBLOCK 打开再 fstat，所以最后一段链接不被跟随、FIFO 不会卡住。接缝只做 IO，不分类错误。
  • walk.ts 拥有全部判定：四张错误码表（ROOT/RESOLVE/READ/OPEN，表外一律 unavailable，不带 code 的错误原样抛出）；resolveRoot（realpath + 必须是目录）；collect 的遍历——每个条目一律走同一条路 realpath → isWithin（按路径段比较解析后的根）→ lstat 判种类，不再按 readdir 报告的种类分叉，所以列出之后被换成根外链接的条目拿不到根外字节；目录按祖先集合查环；每次列出先把全部名字严格 UTF-8 解码再按码元序排，所以多处缺陷时答复不随文件系统的列出次序而变；遍历预算 VISIT_BUDGET = 65536 次名字访问，超出按包缺陷答 entry-unreadable。readEntry 给 open 用：同一个 resolveRoot，解析目标后再判根内。
  • directory-source.ts 只把 collect 的结果交给契约的 sealSnapshot，把 readEntry 包成 open；content-store 定位答 package-not-found；open 忽略 digest（本来源不按内容存放，字节是否变了由 Skill 核对）。

它通过契约 ./testing 的 skillPackageSourceConformance()（PS7「按摘要找包」不适用）。权限类失败全部经注入的 DirectoryFs 制造，因为容器以 root 运行，chmod 造不出 EACCES。

W2 增量 2：@omne-harness/skill（父分支 0956ccf01）

通用实现落地：10 个源文件 596 行、11 个测试文件 195 例；契约可加了 475 行的 skillAccessConformance()（15 条，两个夹具世界各跑一遍）与 bodyOffsetOf。公开根只有两个工厂与 SkillPorts：

  • inspection.ts：createPackageInspection(source)——snapshot → 用 open 读两份控制文件 → 交给契约的 parseSkillPackage（它自己核对控制字节的摘要）。来源失败怎样变成服务失败只在 mapping.ts 一张表里，三列：inspect、snapshot、open——第 1 轮它只有两列，pin.ts 里悄悄做了第二次映射，评审抓住后改成了三列。
  • access/ 把组页「读取」的 11 步写成四段函数，失败类型逐段收窄：gate（第 1–3 步：依据身份、读取权、对应；失败是 DescribeFailure）→ materialOf（第 5 步：钉住材料，带依据时就是依据本身）→ pin（第 7 步：取快照比摘要；pin(ports, gated, material, moved, signal?) 由调用方给「材料已变」的失败值，export 传 basis-unavailable，所以编译器证明它不会答 adopted-material-changed）→ verifiedBytes（第 9–10 步：按条目摘要核字节）。describe 在 gate 后结束，list 在 pin 后结束，read/export 走完。checkpoint(signal) 在四个端口调用的前后各查一次，已中止就答 aborted、不再调端口、不交部分内容。
  • access/range.ts：纯函数 sliceRange——页上限 65536、UTF-8 续字节判字符边界、保留 BOM、请求终点 = 请求起点 + 长度、正文范围相对 bodyOffsetOf 给出的闭合定界行之后。

无披露的三条路径（依据不是本身份、读取判定 refused、对应答 none）返回同一个冻结对象；读取判定的答复不在 granted/refused/unknown 里时一律 unknown，不放行。SkillCatalog 仍是接口，W3。

MCP 组三个成员，只有 @omne-harness/mcp-contract 有实现：29 个源文件、约 3700 个非空行、12 个测试文件 298 例（其中两张用例表 classifyOutcomeCases、mergeListingCases 由 ./testing 导出，成员自己的测试与未来实现方共用）。比 Skill 大一半，因为它一边要对协议线（2026-07-28 修订）做分类，一边要给五个端口写符合性套件。三个入口：

  • 公开根 .（给调用方）：index.ts 从 13 个模块重导出，没有自己的函数。值与品牌在 brands.ts、values.ts；接入点正文在 endpoint.ts（parseEndpointBody、launchesLocalCommand、mcpEndpointBodyContract）；清单在 listing.ts（completeListing、digestDefinition）与 catalog.ts（mergeListing、markUnavailable、actionPermissionItems）；结局在 classify.ts（classifyOutcome）与 content.ts（toContentBlocks）；键在 keys.ts；六个应用服务接口在 services.ts。
  • ./provider（给端口与传输实现方）：provider.ts 只有类型——五个端口（AdoptionView、UseEligibility、CredentialUse、ProcessLanding、CatalogStore）、两类凭据句柄（Http/Process）与 McpTransport/McpTransportFactory。没有运行时导出：与 Skill 不同，MCP 的唯一构造器 completeListing 留在公开根，因为它的调用方是本组的应用服务而不是外部实现方。
  • ./testing（给实现方自测）：五个套件 mcp<Port>Conformance() 配五个内存替身 createMemory<Port>()，加 runConformanceCase/NotApplicable。替身自己也要过套件，这是 conformance.spec.ts 做的事。

依赖方向

根是 brands.ts（零导入，15 个 isX 守卫），values.ts 在它之上——与 Skill 相反，因为 MCP 的值类型大多就是品牌本身。json.ts（在 json-text 的 JSON 树上找成员、取文本、算规范字节）与 order.ts（码元比较）是两个无依赖的小工具层。往上：endpoint、listing、classify、content 各自只依赖值与工具；ports 依赖 catalog 与 outcomes；services 与 transport 在最顶上。listing.ts 与 catalog.ts 之间有一条类型环：listing 以 import type 取 catalog 的三个类型，catalog 运行时调用 listing 的 assertComplete。dependency-cruiser 不报，但它说明「清单」与「目录」的切分线还没切干净（见评述）。

三条真实的调用路径

  1. 读接入点正文。parseEndpointBody(body, capabilityName?) 在 json-text 的树上按 SPEC E2 的次序拒绝：结构缺陷 → 名字不符 → 传输未知 → 认证方式未知 → 组合不合法 → 启动声明多了或少了。最后一格交给 transportOf(transport, launch)。isConnectionTarget 用 WHATWG URL 解析：只认小写 https，或回环主机上的小写 http（LOOPBACK_HOSTS），带用户名口令的一律拒绝。
  2. 清单从对端到目录。传输交回的 ListingPage 是 Untrusted；completeListing(pages, basedOn) 逐项核形、算 digestDefinition（规范 JSON 字节的摘要）、按码元排序，然后登记进模块私有 WeakSet。mergeListing(current, listing, expected) 先 assertComplete（伪造抛 TypeError），再只按修订合并：修订不等答 stale，不比内容。markUnavailable 是目录在连接丢失后的降级写法。
  3. 结局分类。classifyOutcome(answer) 把一次 tools/call 的应答收成判别联合：complete / toolError（isError 为真）/ inputRequired（inputRequests 与 requestState 至少一项）/ protocolError（resultType 不认识）。内容由 toContentBlocks 按 type 的读取表转换：text/image/audio 各一函数，resource_link/resource 走协议类型表，不在表里即 type-unknown。任务路径（tasks/get）走同一分类函数，所以两条路径的 inputRequests 形状只有一份。

失败怎样分层

四层，每层一个联合，在 outcomes.ts 与 transport.ts：TransportFailure（not-sent / no-answer / error-answer / answer-malformed）是线上的事实；OperationFailure 在它之上加 Refusal、ConnectionFailure 与 effect-unknown；ReadFailure 只给 current/peer 两个读操作；LostReason/DegradedReason 是连接状态的说明。residual 只在 lost 上出现——这是第 4 轮加进来的：关闭未确认时调用方要知道对端可能还在跑。

还没有的东西

六个应用服务（EndpointInspection、ActionDiscovery、ActionCalls、TaskControl、EndpointStatus、Connections）只有接口，McpServices<P, S> 把它们与 McpPorts/McpConfig 绑在一起。实现、stdio/http 传输、连接表都在 W2。

W2 增量：@omne-harness/mcp 核心（父分支 ff17f7701）

通用实现的下半部分：16 个源文件 2014 行、12 个测试文件 254 例（其中 races.spec.ts 13 条用 deferred 排并发次序）。公开根只有 createMcpCore(ports, config, { now }?)、createInMemoryCatalogStore() 与几个类型；ActionInvoker 与 createMcp 在 W3。四层：

  • 聚合（internal/connection.ts、in-flight.ts）：仅有的两个类，只做状态转移不做 IO。Connection 带代际策略（stdio 每次尝试加一，HTTP 协商成功加一），非法转移抛 TypeError；InFlightCalls 的占位查重是一步。
  • 关口（internal/gate.ts + guard.ts）：S1 只有一份——admit 先采用后资格，交出 GateDecision；两个品牌 AdoptedOnly（只核过采用）与 AdmittedEndpoint（过了资格），需要连接的函数只收后者，伪造或改过正文的令牌被 judge 用 WeakSet 拒绝。guard.ts 在其上组合 admitForUse（未采用或被挡下时顺手关闭该接入点的连接，不变式 6）与 stillAdmitted（发布边界用）。
  • 连接表（internal/table.ts，684 行，整个成员的复杂度都在这里）：键是 JSON.stringify([租户, 持有, 采用修订, 对端账号])。ensure 的次序：每持有一个临界区（inTurn）里重读采用、关掉其他修订的条目、等同键的关闭或拆除、复用或建条目；临界区外建连——取凭据 → 进程落点（stdio）→ 打开传输 → discover，四步都经 untilAborted 受同一个连接时限约束，迟到的句柄/进程/传输由 afterwards 收口（迟到进程先 stop() 再释放句柄，范围不是 tree-confirmed 就进 lingering）。拆除只有一份 teardown（关传输 → 停进程 → 释放句柄），lose、准备失败、重建、关闭都走它；同键同时只有一次关闭、一次拆除、一次建连。
  • 服务（discovery.ts、status.ts、connections.ts、inspection.ts）：工厂返回对象字面量。refresh 是最长的一条路：关口 → ensure（调用方的 signal 不进共享建连，中止只让自己答 kept(cancelled)）→ 读存储得 basedOn → 取页（另起同一上界的时限）→ completeListing → mergeListing → 发布边界：await stillAdmitted（资格 + 重读采用修订）之后，同步核对代际仍当前、未中止，紧挨 store.write(expected = basedOn)，写入冲突答 kept(superseded)。current/peer 只读表，替身计数证明它们不碰传输工厂。
