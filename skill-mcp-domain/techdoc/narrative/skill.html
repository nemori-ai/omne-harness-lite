成员、入口与模块分工

依赖只朝一个方向：skill-contract 在最底层，skill 与 skill-cordis-contract 在组内只依赖它，skill-host-local 依赖其余三个。下文的来源指 SkillPackageSource，读取判定端口指 SkillReadCheck，对应端口指 SkillResolution，依据指 SkillMaterialBasis。

  • skill-contract：纯契约，有三个入口。公开根给调用方：值、守卫、失败、两个服务接口、parseSkillPackage 等纯函数与类别端口 skillBodyContract。./provider 给端口实现方：三个需求端口、PackageInspection、SkillRef、PackageLocator、sealSnapshot 与 isSealedSnapshot。./testing 有五个符合性套件与三个内存替身，套件不依赖测试框架。包检查在 parse/。contract.ts 复用 parse/shape.ts 的 readScripts 与 readSettings，所以 .omne/skill.json 与资产正文的脚本、设置规则只有一份。
  • skill：三个服务的实现。公开根只有三个工厂与类型 SkillPorts。inspection.ts 是检查，catalog.ts 与 match.ts 是目录，access/ 是读取的各段。port-answer.ts、answer-values.ts 与 source-answer.ts 解析端口答复。mapping.ts 是唯一的失败映射表。
  • skill-host-local：公开根导出 createDirectorySource。fs.ts 是文件系统接缝，walk.ts 做全部判定，directory-source.ts 把两者接到来源端口。./cordis 导出插件 skillPlugin。
  • skill-cordis-contract：根入口没有运行导出，不加载 Cordis。./cordis 导出五个抽象 Service 与五个键常量。

关键类型之间的关系

  • sealSnapshot 造出 SkillPackageSnapshot：根名、按路径排序的 PackageEntry 与快照的内容摘要。快照不存字节。
  • SkillDefinition 是检查的结果：SkillManifest、SkillDeclaration、快照与可选的兼容提示。它不含正文。projectAssetBody 把它投影成资产正文，对应端口以 DeclaredProjection 交回这份投影。
  • SkillRef 带包定位，只在 Skill 与对应端口之间传递。依据没有包定位，只指名材料：能力标识、来源层、可选的资产版本与内容摘要。
  • Resolution 有五种答复。CatalogResolution 是其中的 adopted 与 known-unavailable 两种。
  • skill 内部，gate 交出 Gated，pin 交出 Pinned（定位、所钉材料与快照）。read、list 与 export 的结果都以 basis 写出所钉材料。

检查一个包

inspect 收包定位与可选的 expectedName。它调用一次 source.snapshot，再对快照列出的每个控制文件调用一次 source.open。来源失败经 sourceFailureTo 的 inspect 一列按调用点映射。之后 parseSkillPackage 按下列次序判断：

  • assertSealed：伪造的快照抛 TypeError。
  • 控制字节的内容摘要或在场情况与快照不一致：答 version-changed，不做其余判断。
  • 没有 SKILL.md：答 manifest-missing。
  • readManifest 按字节找头部定界，用严格的 YAML 1.2 解析。YAML 有错误或警告时，readByLine 只逐行读 name 与说明。
  • 调用方给了 expectedName 且 name 与它不同：答 name-mismatch。name 与包根目录名不同只带提示 name-differs-from-root。
  • readDeclaration 读 .omne/skill.json。formatVersion 的词形不是 1 时答 declaration-format-unsupported，不做声明的其余判断。
  • firstFinding 按 INSPECT_REJECTIONS 取最前的一条声明发现，之后才是头部的 malformed。通过时，orderedHints 按固定次序写出兼容提示。

资产一侧，skillBodyContract 的 judge 依次查正文与 name、name-mismatch、name-invalid、工具引用，最后查四个可加字段。

端口答复的解析与 describe

端口答复是外来数据。answered(call, parse) 在同一个 try 里调用端口并解析答复。端口 reject、同步抛出、答复不合与读取答复时抛出，都算没有作答。

  • parseResolution(request) 只放行关于所请求身份的答复。带依据时，adopted 引用的来源层、内容摘要与资产版本（依据带资产版本时）还必须等于依据的。
  • parseLawfulSet 遇到一项不合时，整个答复算没有作答。
  • answer-values.ts 经契约守卫与 capabilityId 重新构造每个值，只读自有属性。

describe 只走 gate（第 1 到 3 步），不收 signal。依据指向别的身份、读取判定答 refused、对应端口答 none：三种情形交出同一个冻结对象 NOT_AVAILABLE。读取判定或对应端口答 unknown 或没有作答时，答 unknown。known-unavailable 答 unavailable-stand-in，basis-not-lawful 答 basis-unavailable。通过后，descriptionOf 写出 pinned 或 no-readable-package，不读字节。

read 与关口

  • assertByteRange：范围的起点或长度不是非负整数时抛 TypeError，这时还没有调用端口。
  • 第 1 到 3 步：gate。
  • 第 5 步 materialOf：带依据时，所钉材料就是依据。不带依据且引用没有内容摘要时，答 unsupported。
  • 第 6 步 partOf：资源路径经 toPackagePath 校验。不合法的路径与控制文件都答 bad-path。
  • 第 7 步 pin：快照的内容摘要不等于所钉材料时，交出调用方给的 moved。不带依据时它是 adopted-material-changed，带依据时是 basis-unavailable。
  • 第 9 步 entryAt：条目不在快照中时答 resource-missing。
  • 第 10 步 verifiedBytes：字节的内容摘要不等于条目的内容摘要时，答 version-changed。
  • 第 11 步：读正文时，bodyOffsetOf 给出正文起点。它答 undefined 时，操作答 source-unavailable。sliceRange 每页最多 PAGE_LIMIT（65536）字节，文本的两端落在 UTF-8 字符边界上。

checkpoint(signal) 在每次端口调用之前与之后各查一次。已中止时答 aborted，不再调用端口，也不交部分内容。

summaries、search、list 与 export

  • summaries 收到空的 capabilities 时答空列表，不调用端口。
  • 其他情形先调用对应端口的 adopted。它答 unknown 或没有作答时，整次答 unknown。同一能力标识只留第一条，条目按类别与名字排序。
  • 过滤先于核验。search 用 matches：先做 NFKC 与小写，查询按空白切词，每个词都是「name、换行、说明」拼成的文本的子串时匹配。
  • grantedOf 用 Promise.all 发出读取判定，按条目次序读答复。任一答复是 unknown 或没有作答时，整次答 unknown。否则只交 granted 的条目。

list 在 pin 之后结束，交出除控制文件以外的条目，不读字节。export 总带依据，向 pin 交 BASIS_UNAVAILABLE，所以 ExportFailure 不含 adopted-material-changed。它逐个核对全部条目（含控制文件）。一个条目失败，整次导出就失败。

目录来源

createDirectorySource 只有一个选项 fs，没有索引与缓存。定位不是 directory 时答 package-not-found。open 不看 digest 参数，字节由调用方核对。

  • DirectoryFs 只有四个读操作：readdir、lstat、realpath、readFile。名字以字节交出。readFile 以 O_NOFOLLOW 与 O_NONBLOCK 打开。
  • collect 深度优先遍历。每次列出先严格解码全部名字，再按 UTF-16 码元序访问，所以有多处缺陷时答复固定。
  • visit 对每个名字走同一条路：计入 VISIT_BUDGET（65536），解析链接，isWithin 按整段判断是否在根内，lstat 读种类，再进入目录或读文件。目录按祖先集合查环。
  • 错误码只在 walk.ts 分类，共有 ROOT、RESOLVE、READ、OPEN 四张表。表外的码答 unavailable，不带 code 的错误原样抛出。

directory-source.ts 把遍历结果交给 sealSnapshot。重复路径与前缀冲突答 entry-unreadable。

Cordis 插件：从装载到撤除

skill-cordis-contract 的每个抽象类继承 Service。键只写在 static readonly provide 中，键常量取自它。类不写 inject。Context 增补五个属性，泛型取 unknown。

  • 装载：skillPlugin 经 definePlugin 定义。emptyConfig 只接受缺席、null 与没有字段的普通对象，其他值使加载失败。apply(ctx) 用三个工厂造出服务，再 new 出三个转发子类，例如 HostSkillAccess。
  • 取服务：消费者用 ctx.get(skillAccessKey) 这类调用取实例。
  • 端口缺席：readCheckOf 与 resolutionOf 每次调用都执行 ctx.get。取不到时答 unknown。调用了缺席端口的那一步得到 unknown，操作再按上文的规则答复，不交受保护的内容。检查不用端口，照常工作。
  • 换代：适配器不缓存引用。端口插件换成新实例后，下一次调用就用新实例。
  • 撤除：插件不登记撤除函数。三个服务属于装载插件的 fiber。fiber 卸载后，三个键上的 ctx.get 答 undefined。

值只能由构造器造出

  • 类型层：values.ts 的品牌键是模块私有的 unique symbol。不写类型断言，就写不出 SkillName、PackagePath、SkillPackageSnapshot 等类型。每个品牌只有一个授予处，例如 isSkillName、isPackagePath、sealSnapshot。
  • 运行层：sealSnapshot 把快照登记在模块私有的 WeakSet 中。assertSealed 对复制品抛 TypeError，isSealedSnapshot 对它答假。这是进程内的凭证：快照不能序列化，两份模块实例互不承认。
  • 边界层：对读取判定端口与对应端口的答复，skill 重新构造并冻结每个值，端口事后改不了已解析的值。来源交来的快照必须通过 isSealedSnapshot。

失败怎样分层

  • 文件系统到来源：walk.ts 把错误码收进 SourceFailure 的封闭集合。
  • 来源到服务：只经 mapping.ts。inspect 一列按 snapshot 与 open 两个调用点各有一格。另两列看是否带依据，例如 package-not-found 带依据时是 basis-unavailable，否则是 source-unavailable。
  • 没有作答：读取判定端口与对应端口当作 unknown，来源当作 unavailable。方向是拒绝，服务不抛出。
  • 按操作收窄：SkillFailure 是唯一的联合。GateFailure、DescribeFailure、PinFailure、ReadFailure 逐层加种类。ExportFailure 从 PinFailure 去掉 adopted-material-changed，再加路径与字节类失败。检查另有 InspectFailure。
  • 抛出：契约与服务只在调用方出错时抛出。三种情形是伪造的快照、非法的字节范围、判断失败后仍调用 deriveDeclarations 或 references。

还没有的东西

  • 没有按内容摘要存放包的来源。content-store 定位答 package-not-found。
  • 四个成员中没有真实的读取判定端口与对应端口，测试只用内存替身。真实提供者与 skillPlugin 的组合没有执行。
  • 端口收不到 signal。端口调用不结束时，操作不答复。
  • answered 吞掉的异常没有诊断出口。
  • PAGE_LIMIT 不可配置，export 没有总量上限。声明只支持 formatVersion 为 1，没有方言。
  • 目录来源的快照不是原子的。O_NOFOLLOW 只管最后一段：核对之后、打开之前被换成链接的中间目录会被跟随。
  • 插件撤除时在途操作的答复没有规定。同一 isolate 重复装载没有验证。
  • skill-cordis-contract 不增补 Events，没有 ./testing 入口。读取资产正文时的字符串预算还没有读取方，契约只写了它与 DESCRIPTION_LIMIT 相关的下限。
