现在源码里有什么（W0，父分支 21175c9f9）

Skill 组有三个 workspace 成员，只有一个有真实代码。读源码时从 packages/skills/skill-contract/src/contract.ts 开始，它是全组唯一的实现文件。

  • @omne-harness/skill-contract：纯契约成员。公开根只导出一个工厂 skillBodyContract()。
  • @omne-harness/skill（通用实现）与 @omne-harness/skill-host-local（本地宿主）：模板草稿，入口是 export {} 加草稿标记。

skillBodyContract() 怎样工作

它返回 assets 的类别端口 BodyContract，类别名是 skill。三个操作共用一个私有判断函数 judge：

  1. judge(body, context) 先用 assets 的 isReadBody 确认正文是一次真实读取的结果，再取 name（必须是非空字符串，并且在给出能力名时与它相等，否则 name-mismatch），再取 tools。
  2. tools 可以缺省（按空列表）；出现时每一项必须是 { category: "tool", name }，否则 incomplete-reference。
  3. references 把每一项变成 assets 的 CapabilityId；deriveDeclarations 现在总是返回空声明。判断失败时两者都抛出，这是 assets 的约定。

字段读取不直接解析 JSON，而是经 assets 的 readSnapshot 读已经无损解析好的 JsonValue 树，所以数字字面量与重复键这类问题在读取时就已处理。

W1 之后这里会怎样变

本页随每个闭包合入更新。W1 会让 skill-contract 分成公开根、./provider、./testing 三个入口，并加入值、失败、端口与包检查。届时本节改写为实际的模块分工与调用路径。
