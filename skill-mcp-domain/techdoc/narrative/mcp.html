成员分工与入口

MCP 组有四个成员。mcp 不导入 Cordis，也不导入任何传输。真实传输与 Cordis 插件都在 mcp-host-local。下文「清单」指一次取得的工具列表，「动作目录」指存储里的整份记录 ActionCatalogRecord。

  • mcp-contract：契约，以及每条规则的唯一实现。公开根 . 有值、纯函数、失败类型、服务接口与传输决策层。./provider 只有端口类型。./testing 有端口与传输的符合性套件、内存替身和脚本化传输，产品代码不导入它。
  • mcp：服务实现。createMcp(ports, config) 用 validateConfig 核配置，再由 internal/assembly.ts 的 assemble 建一张连接表、一个在途表与一个任务表。服务共用这三张表，不各建一份。
  • mcp-host-local：本地宿主。根入口的 createLocalTransportFactory 实现传输端口。线路（Line，实现是 StdioLine 与 HttpLine）只搬字节，不做分类。会话 Session 是一个 McpTransport，它用契约的函数组请求、分类、下结论。./cordis 入口导出插件工厂 createMcpPlugin。
  • mcp-cordis-contract：Cordis 服务定义。根入口是 export {}。./cordis 有三个服务与四个需求端口的抽象 Service。每个类只在静态字段 provide 写一次键，键常量取自它。

模块分工

  • 契约的领域函数。parseEndpointBody 解析接入点正文。completeListing 把各页收成完整清单。mergeListing 与 markUnavailable 是动作目录仅有的两种转移。classifyOutcome 把对端答复收成结局。keys.ts 推导对端账号与两种键。
  • 契约的传输决策层。每种传输都用这一份规则。wire.ts 的 classifyWireEvent 把线路事件归入 T8 的应答类。decisions.ts 的 concludeAnswer 得出结论，结论里的 WireAnswer 是传输结算请求的词表。
  • 实现的服务。discovery.ts、calls.ts、tasks.ts、status.ts、connections.ts、inspection.ts。invoker.ts 把调用与任务操作合成 ActionInvoker。
  • 实现的关口。internal/gate.ts 是采用与资格的唯一判定，先问采用，再问资格。internal/guard.ts 在它上面加两件事：接入点被撤采用或被挡下时关闭连接，以及发布边界的复核。
  • 实现的连接表。internal/table.ts 只做编排。建连在 build.ts，拆除在 teardown.ts，失联判定在 lost.ts。三个类都不做 IO：Connection（状态机与代际），InFlightCalls（在途调用），TaskTable（本次运行的任务）。

关键类型怎样相连

  • 接入点到连接。采用端口交出 AdoptedEndpoint。关口把它铸成令牌：AdoptedOnly 已解析正文，AdmittedEndpoint 资格也已通过。令牌登记在 gate.ts 私有的 WeakSet 里，副本不被承认。prepareSettings 从令牌得出凭据绑定、对端账号、传输材料与连接时限。
  • 两种键。connectionKeyOf 含租户、持有、采用修订与对端账号，新的采用修订就是新连接。catalogKeyOf 不含采用修订，采用变化不丢动作目录。
  • 条目与视图。连接表每个键一个 Entry，持有 Connection、传输、进程句柄、凭据句柄、未确认停止的进程（lingering）与在途落点。服务拿到 Ensured：建连答复那一刻的传输、代际、对端与只读视图。服务不写聚合，只经 table.settle 与 table.lose 报告。
  • 答复到结局。传输把 tools/call 的答复交成 PeerAnswer，其他请求交成 Outcome<T, TransportFailure>。classifyOutcome 得出 CallOutcome，调用口再包成 InvokeResult：not-sent 或 sent。

路径一：发现与整份发布

discovery.ts 的 refresh 先走 refreshOrder，再由 answerAtExit 决定答复。

  • 表已关停就不问端口。否则过关口 admitForUse，再用 within 等 table.ensure。调用方的 signal 只结束这次等待，共享的建连继续，这次刷新答 kept（cancelled）。
  • publish 读存储得 basedOn。listPages 在 listing 时限下逐页取，每页之前核一次关停。
  • published 先找让连接失联的页，再调 completeListing，向表报告 page-failed 或 listed，然后调 mergeListing。
  • written 是发布边界。先异步调 stillAdmitted，重判资格并重读采用修订。再紧挨写入同步核对：代际仍是当前代际，信号没有中止。写入以 basedOn 作期望修订，冲突时答 kept（superseded）。

读法：先读 answerAtExit。已发布的结果不改。没有发布时，调用方中止优先于关停，关停优先于这一步本来的答复。

路径二：调用与结局分类

calls.ts 的 perform 是一次调用从占位到答复的唯一拥有者。

  • checkedSend 把请求字段各读一次，用 judgedTree 判值树。参数不是 JSON 对象时抛 TypeError。
  • inFlight.reserve 在一步里查重并占位。占位的 stop 合并调用方的信号与 cancel。
  • prepare 依次走关口、配值、knownActionOf 与 ensure，每次等待都经 under。首次调用要求定义摘要等于 expectedDefinition。续调用只在 issuedAt 那一代连接上发，不为此建连。
  • 发出前在同一段同步执行里再看停止与关停，然后调 transport.call 与 recordSent。
  • answerOf 在 stop 下等答复。停止先到时答 unknown（abandoned），未关停时在作用域里发一次 cancelRequest。答复先到时 applyAnswer 调 classifyOutcome 与 loseIfLost，结局是 task 时记进 TaskTable。

classifyOutcome 按 resultType 分类。缺省或 complete 时看 isError，得 complete 或 toolError。input_required 与 task 各自核必需字段。其他值是 protocolError，没有答复是 unknown。输出校验函数抛出时，结论是 violates（output-check-failed）。

任务操作在 tasks.ts。request 按租户、主体、持有与任务号查表，只有发起者取得到记录。exchange 优先复用同一对端账号的连接，没有时经关口新建。outcomeOf 决定答复。

路径三：连接建立、换代与转 lost

table.ts 的 ensure 先调 assertAdmitted 与 prepareSettings，起 section 时限，再经 turns.inTurn 进入该持有的临界区 begin。begin 重读采用，修订与令牌不同时答 unknown。它关掉同持有下其他采用修订的连接，等同键在途的关闭或拆除。然后它加入在途建连，或复用可用连接，或开始 builder.build。旧连接已 closed 时，新 Connection 的代际从 lastGeneration 接续。

build.ts 的 build 在 build 时限下按次序走：attempt()，拆除旧连接的遗留，取凭据，落点启动进程（只在 stdio），open，discover，ready()。端口调用都经 port.ts 的 ask 与 within。时限之后才交来的传输、凭据句柄与进程，由 late.ts 在作用域里关闭、释放或停止。

代际策略在 Connection 上。stdio 是 on-attempt，失败的尝试也加一。HTTP 是 on-negotiation，ready() 时加一。isCurrent(g) 只在代际相等且状态是 ready 或 degraded 时为真，迟到结果按它丢弃。

转 lost 并标记动作目录只经 build.ts 的 markLost。表关停时的 shutDown 只拆除，不标记。它先同步调 connection.lose(reason)，连接立即拒绝新请求。然后它在 done 里拆除，并用 markUnavailable 标记动作目录。建连失败经 build.ts 的 failed 到这里。服务经 table.lose 到这里：refresh 用 loseOn 等标记结果，调用与任务操作用 loseInScope，不等拆除。

拆除只有 teardown 一份：关传输，停进程，释放凭据句柄。停止范围不是 tree-confirmed 的进程留在 lingering，下次拆除再停。closeEntry 先等在途建连结束，再调 connection.close() 与 teardown。条目只在 forget 一处离表，条件是 forgettable：状态是 closed，并且什么也不持有。

路径四：传输答复与「传输不再可用」标记

Session 先把请求登记成在途项 Pending，相是 authorizing。后台的 sendOut 让凭据句柄授权，组请求，把相改为 sent，交给线路。线路的回报变成契约的 WireEvent，classify 调 classifyWireEvent，apply 执行 concludeAnswer 的结论。

  • 结论是 settle 时结算这个请求。结论带 unusable 时再调 die(cause)：字段 dead 记下第一个原因，其余在途项按相由 lineGoneAnswerOf 结算。
  • 结论是 authorization-required 时，enterDiscovery 调一次句柄的 reportRejection，并开始授权发现。
  • 调用方的信号或 close() 经 stop 按相结算（stopAnswerOf）：授权中答 not-sent，已交线路答 no-answer（abandoned），发现中答 authorization-required。

标记有两个写入点。die 之后才开始的请求由 refused 答带标记的 not-sent。handedOver 在 dead 有值且没有调过 close() 时，用 unusableAnswerOf 给 no-answer 与授权以外的 not-sent 加 unusable。close() 是本方的决定，之后的答复不带标记。

mcp 一侧只读这个标记。lost.ts 的 lostOf 按次序判定：带 unusable 时转 lost，动作目录标 connection-unavailable。是 not-sent（authorization-required）时转 lost，动作目录标 authorization-required。其余答复不改变连接。lostOf 不读失败本身的原因。

路径五：Cordis 插件从装载到撤除

createMcpPlugin(parts) 经 definePlugin 返回名为 mcp 的插件。

  • 装载。配置 Schema mcpPluginConfig 只查形状。取值范围由 createLocalTransportFactory 与 createMcp 在 apply 里检查，不合法时抛 RangeError。函数与本地对象由工厂参数 McpPluginParts 给出，不进配置。
  • 建服务。apply 组 McpPorts：四个需求端口用适配器，存储用 createInMemoryCatalogStore，传输用 createLocalTransportFactory。它调一次 createMcp。
  • 按键提供。HostActionDiscovery、HostActionInvoker、HostEndpointStatus 继承抽象 Service，构造时以类上的 provide 键在装载的 fiber 上提供服务。
  • 每次调用现取端口。adoptionOf 等四个适配器在每次调用时用 ctx.get 按键取端口。端口缺席时答该端口的 unknown，操作不放行。提供者换代后，下一次端口调用用新实例，连接表不重建。
  • 撤除。ctx.effect 登记标签为 mcp.closeAll 的撤除函数。它等 connections.closeAll()，对停止范围是 root-only 或 unconfirmed 的端点写 warn，不捕获 AggregateError。

连接表的 closeAll 先把 shut 置真，之后不再建连。然后它同时做两件事：abandonLandings 释放在途落点带着的凭据句柄，closeEntry 关闭每个条目。两件事都结束后，它收集两者的失败，再调 scope.exit() 取出后台错误。有错误时以 AggregateError 拒绝，没有时交出各端点确认的停止范围。

失败怎样分层

  • 调用方缺陷：抛出。配置不合法抛 RangeError。值树不过 judgeJsonValue、令牌不是关口铸的、清单不是 completeListing 造的、聚合的非法转移，都抛 TypeError。
  • 端口违约：读成答复。ask 把端口的拒绝与同步抛出读成该端口的违约答复。例如存储读成 unavailable，stop() 读成 unconfirmed。会话对凭据句柄用 callHandle 做同样的处理。
  • 线上事实。TransportFailure 按对端效果分四种：not-sent（对端没有生效），no-answer（效果未知），error-answer，answer-malformed。unusable 只出现在前两种上。
  • 操作答复。Refusal 是使用连接之前的拒绝。ConnectionFailure 是请求没能到达对端的连接条件。调用口把这两类与停止、定义变化、动作不可用合成 NotSentReason。refresh 与任务操作用 OperationFailure。current 与 peer 不发请求，用 ReadFailure。
  • 状态说明。ConnectionState 的 lost 带 LostReason 与可选的 residual。动作的不可用原因是 UnavailableReason。
  • 本包的编程错误。作用域保存后台错误，closeAll 把它们交给调用方，之后的错误交 TableRuntime 的 afterExit。会话的缺陷交 SessionOptions 的 reportDefect，对应的在途项按相结算。

还没有的东西

  • 四个需求端口没有真实提供者。继承这四个抽象 Service 的类只在测试与 README 示例里，测试用 ./testing 的内存替身。
  • 插件没有进应用插件树，也没有产品消费者。同一 isolate 重复装载（IC-6）没有决定。撤除没有期限：stop() 或 release() 不答复时，closeAll 也不答复。Streamable HTTP 上的插件旅程没有执行。
  • 没有耐久的 CatalogStore。动作目录、InFlightCalls 与 TaskTable 都只保存一次运行。
  • 不订阅列表变化：传输套件核对没有发出 subscriptions/listen，changedNotified 总是 false。失联的连接不在后台重连，下次使用时重建。
  • 清单不容错：一个不合法的工具让整次取得失败（action-invalid）。
