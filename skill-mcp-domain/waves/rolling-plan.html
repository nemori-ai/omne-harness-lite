单会话 map-reduce 怎样转

本会话同时是 reduce 和两条线（Skill、MCP）的线负责人。map 是每个闭包一个子代理，在各自的工作树里写；reduce 是本会话读交回、评审、合入父分支，并在波末统一核对与写回。

  1. 开波：父分支合并 origin/integration/mainline 的最新头，让依赖的公共成员与 assets 保持最新。冲突在父分支上解决。
  2. reduce 先做共享写：依赖声明、pnpm-lock.yaml、pnpm-workspace.yaml 的 catalog。闭包不碰这些文件。
  3. 写本波每个闭包的规格，跑 brief-check，用 prepare-closures 从父分支头建工作树。
  4. 并行派发。写范围互不相交，一个成员目录同一波只给一个闭包。
  5. 闭包交回后推送闭包分支，开 PR，base 是 PanQiWei/skill-mcp。reduce 读差异、按风险派独立评审，然后在 GitHub 上用 merge commit 合入。不走 gate，不进集成轨道。
  6. 波末：在父分支头跑 preflight、受影响成员的 build、typecheck、test，以及本波成员的差分变异。整波跑一次 admission，基线已知失败单独列出。
  7. 写回：组页的「归 SPEC」项改指成员 SPEC，记派发流水，向你交本波报告。报告只写两个领域本身。
规则内容
共享单写锁文件、catalog、组页、领域页、统一语言只由 reduce 写。闭包需要时在交回里提出，reduce 在下一个合入点处理。
契约稳定契约成员合入后，后续波段只做可加改动。必须破坏时，由 reduce 裁定，并在同一波迁移全部消费者、删除旧入口。
接受级别默认 L2：实现评审。L3 热点逐行读：Skill 的读取关口（对无权主体不披露身份是否存在）；MCP 的连接键隔离、凭据句柄、在途表、stderr 中秘密值的遮盖。
替身边界M2 完结前只用本组 ./testing 的符合性替身。替身通过不说成读取权、资格、凭据或耐久已验证。
已知环境限制容器以 root 运行，「权限被拒」类用例不可靠。基线上 execution-environment-host-local 有 3 处既有失败。本组的权限类用例用注入的文件系统接缝，不依赖真实权限。

W1 契约地基 细粒度 · 2 个闭包并行

目标

把两个纯契约成员做成后续波段能直接依赖的形状：值、失败、服务接口、纯函数、端口与符合性套件，加上封闭「归 SPEC」各项的成员规格。

w1-prep（reduce）

做什么
给两个契约成员声明生产依赖：assets、operation-result、legal-identity、content-block、json-text。重生锁文件，只动 importers。
为什么
两个闭包都要加依赖。锁文件是共享文件，先由 reduce 一次写好。

w1-skill-contract

写范围
packages/skills/skill-contract
交付
  • 迁到 typescript-package@3.0.0 完整骨架，不覆盖现有正文
  • 公开根：值与品牌、SkillFailure 及按操作收窄的失败、三个服务接口与结果值、纯函数 toSkillName、toPackagePath、computeDigest、sealSnapshot、inferMediaType、parseSkillPackage、projectAssetBody
  • skillBodyContract 的可加扩展：description、scripts、settings、package.digest；旧正文仍合法
  • ./provider：三个需求端口、SkillRef、CatalogResolution
  • ./testing：三个端口的符合性套件与内存替身（来源、对应、读取权）
  • schema/：.omne/skill.json 的 JSON Schema
  • SPEC：包格式规则与拒绝次序、内容摘要算法、SafeReason 形状、字节范围单位与 UTF-8 切页、正文起点、默认读取上限、中止结果、声明的 JSON 预算

每个拒绝原因各有一份包样本；纯函数穷举测试；符合性套件对内存替身全绿；实现评审 L2；成员 SPEC 用 design-reviewer 的表达评审

写范围

W2 通用实现与本地来源 细粒度 · 3 个闭包并行

目标

Skill 的首条旅程（已知精确能力 → 描述 → 读正文与资源）在本机目录上跑通；MCP 的连接、关口与清单发现在脚本化的替身传输上跑通。

packages/skills/skill；skill-contract/testing 只做可加改动

  • createSkillAccess 的 describe、read、list：读取 11 步、分页、中止
  • SkillAccess 符合性套件加进 skill-contract/testing

w2-spike（reduce，tmp）

做什么
在任务 tmp 里用官方 client 2.3.1 与 server 2.3.1 写最小往返：协商、tools/list、tools/call、多轮输入、任务，以及 stdio 走外部给的管道。
为什么
确认 SDK 能套进 McpTransport 与 McpTransportFactory。不合的地方带事实回设计，W3 之前改契约（只做可加改动）。
出口Skill 首条旅程用 DirectorySource 加内存的对应与读取权替身跑通；MCP 的 refresh 在替身传输上整份发布清单，迟到结果不覆盖较新的采用；SDK 适配结论写进 W3 规格。

W3 调用、传输与目录 中粒度 · 3 个闭包

w3-mcp-call

成果
ActionInvoker：invoke、continueWithInput、cancel、三个任务操作；方式与 taskSupport 核对；截止转本地放弃；换代后的处理按传输区分。并发发布与取消有行为模型和关键性质检查。
边界
不自动重发；只用替身传输

w3-mcp-host

成果
两种传输的 McpTransportFactory：Streamable HTTP（现代对端，旧对端回退）与 stdio（走 ProcessHandle）；授权发现；本地真实服务端夹具；两种传输共用同一份契约测试。
边界
官方 SDK 只在本成员；进程落点用测试替身；L3

w3-skill-catalog

成果
SkillCatalog 的 summaries 与 search；SkillAccess.export，逐条核对，不交部分包。
边界
不排序、不按常驻筛选、不求可用性
出口本地真实 MCP 服务端上端到端：协商 → 刷新 → 调用（完成、动作错误、多轮输入、任务）→ 取消，两种传输读数一致；Skill 摘要、检索与导出可用。reduce 先把 SDK 加进 catalog 与锁文件。

W4 Cordis 服务键与加固 粗粒度 · 只定成果与边界

  • 预期成果：建 skill-cordis-contract 与 mcp-cordis-contract（服务键与抽象 Service），两个 host-local 的 Cordis 插件部分；五个草稿成员贴采用标识；按风险补 profiling（分页读取、清单刷新）；收齐组页剩余的「归 SPEC」项，请你做候选决定的技术接受。
  • 候选：在 sql-contract 上做耐久的 CatalogStore。只在它不需要跨领域决定时进本波，否则移到 M2 之后。
  • 目标边界：插件不进应用插件树；不接任何真实提供者。

M2 完结之后 粗粒度 · 集成联调

  • 预期成果：两组的需求端口接上真实提供者，并用本组的符合性套件验收提供者；Cordis 插件进应用插件树；与消费者联调：工具一侧从 MCP 已知动作派生工具，会话与 Agent 一侧读取 Skill（#322 Skill 内容读取）；联合验收与端到端。
  • 依赖的外部决定：assets 扩展 deriveDeclarations 的上下文，以派生逐动作权限项；内容存储来源接对象存储契约。
  • 目标边界：本领域仍只交付自己一侧的契约、实现与符合性设施。集成的排程随 M3 规划。
