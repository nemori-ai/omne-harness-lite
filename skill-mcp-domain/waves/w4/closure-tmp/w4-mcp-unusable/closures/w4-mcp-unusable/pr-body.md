## 交付

W4 MCP 线切片 01，闭包 `w4-mcp-unusable`（产品写者）与 `w4-mcp-unusable-guard`（守护写者），卡 #1119。传输的失败答复带「传输不再可用」标记 `unusable`。连接转不转 `lost` 只看这个标记，不再按失败的原因推断。

- **契约 `mcp-contract`。**
  - 失败答复可带可选字段 `unusable`（T1），只由决策层写入。标记是单调的：一旦标出，之后每个请求都标出。`close()` 之后的答复不带标记。
  - T8 中写「传输不再可用」的行（S01–S04、S07、X02）带标记，其余行不带。
  - S5、S7 改为按标记判断；R1 与 S2 的说法改为一致；R7 的 `no-connection` 含「资格不是 `granted`」。
  - 符合性套件按行推出期望的标记。漏标与错标两个违约实现各让套件恰在预期的行变红。
- **`mcp`。**
  - 全函数 `lostOf`（`internal/lost.ts`）取代按原因的三个映射。带标记或 `not-sent`（`authorization-required`）时转 `lost`，其余连接不变。
  - 调用口、任务操作与 `refresh` 都只经它判断。
  - 探索器加性质 P15（不带标记的失败不转 `lost`）、`marks` 场景与负控 N11。成员 SPEC「性质与证据」加 P15。
- **`mcp-host-local`。** 两种真实传输的会话交出带标记的答复。stdio 夹具能实现 X02（关闭 stdin 但进程仍活着）。

依据：W4 MCP 规格第 1 节第 1–8 条、D-W4M-2；契约 T1、T8。

## 验证

- 三个成员的 `build typecheck test` 与 `test:slow` 退出 0（守护写者在 `06773cbcb` 上，之后的提交只改文档）。
- 符合性套件：脚本化传输 219 条；两种真实传输上 `mcp-host-local/tests/conformance.spec.ts` 198 条，全部通过。
- 违约实现：漏标让 S01、S02、S03、S04、S07、X02 变红；错标让 D15、D16、I06、O05、O06、O07、C04 变红。用例比较精确的失败清单。
- 探索器：`marks` 场景没有违例，满足见证断言。负控 N11 让 `marks` 报出 P15 的两个签名。
- 写者对 `lostOf` 与三处调用点做了变红验证（U1–U14）。

已知限制：
- TLA+ 模型表达不了 P15，没有加。
- 慢层 `wide` 场景单独运行约 360 秒，离 600 秒的时限不远。关口 A 面会对照基线与 head 的状态数。
