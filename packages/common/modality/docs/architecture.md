# 内部架构

本文件说明本包怎样兑现 [SPEC.md](../SPEC.md)：包内模块划分、依赖方向、状态与资源归属、关键机制及设计理由。它引用组级与系统级约束，不另立公共规则。

## 模块与依赖

本包只有一个模块 [src/index.ts](../src/index.ts)。它导出类型、冻结列表和五个纯函数，没有状态、资源或配置，也不导入任何模块。

成员位置：`packages/common/modality`，属于 `common` 组。用户于 2026-10-19 指定把多模态的公共定义放进 `packages/common` 的一个成员。该组放至少有两个具名消费者、且原语义拥有者确认含义一致的纯表示，见[组说明](../../README.md)。

依赖方向：本包不依赖其他组，也不依赖 `common` 组内的其他成员，`package.json` 的 `dependencies` 为空。内容块、消息、Model、Tool 以及以后的其他成员可以依赖本包，反方向不允许。本包是叶子，所以内容块以后依赖它不形成环。

## 关键机制与理由

**媒体类型用正则按 RFC 产生式拼成，参数逐槽匹配。** `media-type` 取自 RFC 9110 第 8.3.1 节，`token` 取自第 5.6.2 节，`OWS` 取自第 5.6.3 节，`quoted-string` 取自第 5.6.4 节，`parameters` 与 `parameter` 取自第 5.6.6 节。源码里每个片段是一个常量，常量名对应产生式名，便于逐条对照。不手写逐字符解析器，因为文法很短，几条表达式比一段状态代码更容易与 RFC 对照。

`type "/" subtype` 用一条从开头锚定的正则匹配。余下的文本用一条粘连（`y` 标志）正则逐个匹配参数槽，槽与槽首尾相接，必须覆盖余下的全部文本。一个槽写成 `OWS ";" ( OWS ( parameter / 输入结束 ) )?`：分号后的空白只在后面紧跟参数或输入结束时归这个槽，否则归下一个槽分号前的空白。RFC 的写法 `OWS ";" OWS [ parameter ]` 允许空参数位，若照搬成一条正则，连续空参数位之间的空白可以任意划分，不合文法的输入会引起指数回溯，70 个字符就要约 100 秒。现在的写法每段空白只有一种划分，quoted-string 的两个分支字符集互不重叠，token 后面只能跟不属于 token 的字符，所以回溯只在一个槽之内。逐槽匹配还让回溯栈不随槽数增长：同样的槽如果放进一条正则的 `*` 里，约 400 万字符的参数列表就会耗尽 V8 的回溯栈。100 kB 的对抗输入耗时在几毫秒以内，由测试检查上限。

已知限制：单个引号参数值仍在一条正则内匹配，引号内的片段超过约 838 万个时，V8 的回溯栈耗尽，抛出 `RangeError`。SPEC 把它列为原样传出的引擎资源耗尽（见 [SPEC](../SPEC.md#所有权失败与生命周期)），不另设长度上限。

**规范化归本成员。** 块上的媒体类型可以带参数或大写，例如 `video/mp4;codecs=avc1`。如果每个消费者各写一份去参数、转小写，就会各自写出细微不同的版本。所以 `judgeMediaType` 一次给出规范形式与模态。需要「必须已经是规范形式」的场合，例如转换件的键，用 `isCanonicalMediaType`，不经规范化，仍按精确相等匹配。

**顶层类型决定模态。** 对照用一个只读的 `Map`，键是小写顶层类型。不看子类型、前缀和后缀，所以没有 vendor 例外表需要维护。代价是 `audio/midi` 这类非语音内容也读作 `voice`。全部 `audio/*` 读作 `voice` 是 PanQiWei 于 2026-10-19 的裁定，对照表由本成员拥有，见 [SPEC 判定媒体类型](../SPEC.md#判定媒体类型)。如果以后需要把音乐与语音分开，要新的采用决定，并且要改词表。

**拒绝而不猜。** 不合文法的输入返回 `media-type`，不尝试修剪空白，也不猜扩展名。调用方给出它保存的值，不合格就是调用方的问题。

**返回值冻结，输入不被修改。** `MODALITIES`、`judgeModalities` 的结果和 `missingModalities` 的结果都是冻结数组，避免消费者互相改写共享值。`judgeModalities` 返回新数组，不返回输入数组本身。函数只读取输入，不冻结也不修改调用方传入的数组。

零依赖是刻意的。词表与媒体类型规则是两个以上消费者共同需要的纯表示。让它们各装一份会产生漂移。

## 验证与维护

保证与验证的对应见 [SPEC 验收对照](../SPEC.md#验收对照)。

改变词表、对照表或拒绝原因，要先改 SPEC.md，再同步 Model 与 Tool 两个具名消费者。新增依赖或入口需要新的采用决定。
