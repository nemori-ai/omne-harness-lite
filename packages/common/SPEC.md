# Common

## 总体架构

共同包组回答一个问题：几个领域都要用、含义又必须完全一致的那些纯值，怎样只定义一次。每个成员是一片叶子：一种值的形状、它的文本、它的判定与它的比较。成员之间只有很少的依赖，没有状态、资源、时钟或 Cordis。

| 成员               | 回答的问题                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| `json-text`        | 一份不可信的 JSON 文本怎样在预算内严格读成值树；内存里的值树怎样判定、怎样原样写回文本              |
| `legal-identity`   | 账号、组织、登录状态、工作区、租户与范围层的合法文本、相等与租户组合；行事作用域与访问依据 `Access` |
| `utc-instant`      | UTC 时间点与 SI 秒时长的文本、唯一的比较，以及判定哪个秒 60 存在的闰秒表                            |
| `content-block`    | 一个已封闭的内容块（文本、思考、语音、图、文件，含引用式）长什么样；块身份与标注怎样判              |
| `message`          | 日志里一条消息的字段：六种角色、工具部件、压缩记录、推理续接状态；消息与压缩相对历史的判定          |
| `stream-arrival`   | 一次流式交付上的步骤怎样折成装配；生产者的流引用、游标、帧与观察端口的公共形状                      |
| `call-account`     | 一次模型调用或工具执行的调用账目：快照准入、修订替换、来源小计与应付金额                            |
| `operation-result` | 操作结果的两种形状：带值成功、无值确认，以及失败                                                    |
| `modality`         | 有哪几种模态；一个媒体类型属于哪种模态                                                              |
| `exchange-refs`    | 三个跨域交接的基础值：精确采用、耐久记录定位、消费者位置                                            |
| `retry`            | 一份重试策略怎样解析；「再试一次、等多久，还是预算用尽」的纯判定                                    |

每个领域从成员的公开入口导入值与判定，在自己的边界上先判定再使用。判定成功只说明形状合法；值的含义、存在与资格仍由原拥有者回答。

## 领域边界

本组拥有：这些值的精确文本、形状、判定次序与拒绝码，以及比较与组合的规则。

本组不拥有：任何业务事实与它们的生灭；身份是否存在、成员是否有效、授权是否允许（身份与授权）；时钟与业务期限（各拥有者）；日志、序号与历史的保存（历史持有者）；压缩何时发生、怎样写摘要（压缩策略的拥有者）；哪个模型能消费什么（Model）；账目的持久记录（业务账的拥有者）；失败的词汇（调用方契约）。

本组只依赖彼此与少数通用库，不导入任何领域、存储、服务或 Cordis。

本组声明、由别人实现的端口：

| 端口                                    | 对方                  | 本组需要它做什么                                       |
| --------------------------------------- | --------------------- | ------------------------------------------------------ |
| 流观察端口 `StreamObserver.observe`     | Model、Tool（生产者） | 先交已确认快照，再交增量，按标准原因结束               |
| 原调用 codec（`producer` 与 `resolve`） | Model、Tool           | 把一段调用文本规范化，或答它不合法；本组据此编出流引用 |

本组为别人实现的端口：各成员的公开入口，消费者是凡需要同一表示的领域。值与判定从成员入口导入，不复制定义；契约成员以原名再导出 `Access` 与三个交接引用。

## 心智模型

共同包组是一本词典，不是一个服务。它规定一个词怎么写、两个词是不是同一个，不规定这个词指的东西在不在、能不能用。所以每个判定都只答「形状合法」或「哪一处不合法」：账号文本解析成功不说明账号存在，访问依据构造成功不说明主体可信，一份账目准入成功不说明钱已经付了。

一个值进本组，要有至少两个具名消费者需要同一表示，而且原语义拥有者确认含义一致。进来之后它是叶子：不认识调用它的领域，不带业务规则，不读环境与时钟。

最容易想错的三处：序号不是时间，钟停了不能把序号写成上一个加一；判定返回的是新的副本，调用方之后改输入不影响已返回的值；两个值相等由该家族的相等函数判断，不由对象身份或手写的同形对象判断。

## 应然设计

### 判定的共同形状

- 判定与解析返回结果，不以异常报告不合法的输入：成功带值，失败带一个封闭的拒绝码（必要时带位置）。多个问题同时存在时，按固定次序返回第一个。
- 键集是闭合的：多出的自有键是拒绝，不被保留或忽略。成功值只含该形状的已知键。
- 成功值是新的副本，必要处冻结；不与调用方的输入共享。读取输入时，有访问器的位置不调用 getter，或每个键至多读一次并只用这一次读到的值。
- 成功不证明对象存在、主体可信、内容可读或操作获准。

### JSON 文本

- 读取在调用方给出的六项预算之内进行（字节、深度、项数、成员数、字符串长度、数字长度），预算没有默认值，不合法的预算抛 `TypeError`。第一次不合规就返回失败，不带部分值；失败的停止次序是公开契约。
- 读成的值树保留对象键的顺序，数字保留源文本词素，不转成 JavaScript number。重复键是失败，不挑一个值。
- 值树判定先限访问次数，再检查环、畸形节点与不可读的列表；不调用 getter，异常不外泄；成功值是冻结副本。写出按值树原样写，不加空白，键按树里的顺序。写出的前置是值树已经过判定或来自读取：写出不查重复键、环与共享子树，也不限文本大小；节点形状不对抛 `TypeError`，不返回任何文本。写出自己维护栈，深树不撑破调用栈。
- 字段的 `{ parse, encode }` 留在形状拥有者，读取器只给值树。

### 合法身份

- 原子身份（账号、组织、登录状态、工作区）是家族前缀加 26 个 Crockford 字符，前缀分别是 `acc_`、`org_`、`lgn_`、`wsp_`。错前缀不能解析成另一家族。解析不 trim，不折叠大小写。
- 租户由已解析的组织与账号组成，`tenant()` 是进程内唯一的组合函数；租户不含角色，角色变化不改变租户。
- 合法值只能由本成员的解析与组合产生；手写的同形对象在运行时编码失败、相等为假。值跨进程、跨结构化克隆或跨两份安装时，发送编码后的文本，在另一侧重新解析。
- 行事作用域只有租户与系统两种；没有空租户或缺省租户的形式。系统作用域只有一个值。
- `Access<P>` 是一次调用的访问依据：主体与已解析的租户。它只有一份定义，各契约成员再导出它；构造成功不证明主体可信。租户由调用方显式传入，不从连接、进程、装配或凭据推断。
- 身份类型名只有一份名单，静态检查从它导入，不另写拼写。

### 时间点与时长

- 时间点是 UTC 日历字段加原样的小数位。比较只有 `compareInstants`：先比日历文本，再逐位比小数，不经过 `Date` 或 `Number`。秒 60 排在次日零点之前。解析与编码往返得到原文本。
- 时长只表示 SI 秒；日、月、分、时这类单位是 `calendar-unit`，不是时长。
- 只有闰秒表列为插入的那一天，秒 60 才能解析；表失效之后，表外的秒 60 不能解析，普通时间点照常解析。闰秒表来自 IERS 发布的文件，带来源、版本与失效日；本成员不判断表现在是否过期，调用方用自己的时钟与失效日比较。表里列为删除的那一天，秒 59 不能解析，按 `leap-second` 拒绝。表外的秒 60 在表失效之前按 `leap-second` 拒绝，从失效日起按 `leap-data-expired` 拒绝，因为表不可能知道之后的插入。
- 读闰秒表时，第一行数据必须是 1972-01-01 的基准偏移 10，起点不对的表按截断拒绝；之后每行相对前一行把 TAI-UTC 改 +1 或 -1，否则拒绝。本成员不校验表里的 `#h` 哈希。
- 本组不提供时钟，没有以 `Date.now` 为默认值的参数。墙钟、单调钟与业务时钟是三个读取端口，各归拥有者。
- 时钟失败的规则：单调钟不可用就返回不可用，不改读业务时钟；单调读数低于已记录的下界是 `rollback`；经过的时长大于租约宽度是 `stopped`；墙钟跳动不结束租约。跨进程恢复只用持久记录的开租约业务时刻与宽度，剩余宽度是原宽度减去已经过去的业务时长，不是新的满额宽度。
- 序号不是时间：观察时间不可用时，不把序号改成上一个加一。

### 内容块

- 已封闭的内容块只有文本、思考、语音、图、文件五种，带块身份、可见性标注与必要的媒体字段。工具调用、工具结果与仍在增长的块不是内容块。租户、效力与因果不放在块上。
- 语音、图与文件可以是引用式：引用描述内容的位置与完整性（存储、键、媒体类型、字节数、摘要），不是下载地址、读取能力或外传许可。引用式与内联式不混用。摘要的算法归内容提供者。
- 判定只看形状，不证明内容存在、归属、读取资格或模态可用。历史持有者与请求组装方只保存内容引用，不加载二进制；只有 Model 的发送阶段加载选中的内容。
- 块身份与标注的判定、每种块的开块头键表只有一份，消息与流式到达都用它。

### 消息

- 一条消息是 `{ id, role, blocks }`，角色是六种日志角色之一，`blocks` 非空。消息身份由历史持有者在受理时铸造，本成员只检查不铸造；块身份由各自的铸造方负责在消息内唯一、重放时不变。
- 角色规则：`tool` 消息第一块是结果标记，全消息恰有一个标记，其余是不含思考的内容块；三种调用部件、推理续接状态部件与思考块只在 `assistant` 消息里；标记只在 `tool` 消息里。工具调用的参数是值树，保存判定返回的冻结副本。参数没收齐的调用两位可见性都为假，不参与配对；参数不能解码的调用登记调用身份但不执行。
- 调用与结果按 `callId` 就近配对：一条 `tool` 消息与它之前、离它最近、带同一 `callId` 的调用配成一对。配对完整性只在核对压缩记录时判定。
- 压缩记录是 `compaction` 角色的消息，带覆盖范围、保留名单与派生证据。只有最近一条压缩记录决定模型视图；压缩记录写入之后不变，之后的压缩只能保留它或摘要它。规则 CM-01 到 CM-06 见不变式表。
- 再次压缩只需要增量窗口：上一条压缩记录的保留项、它覆盖范围之后的未覆盖尾项、它本身与之后的条目。判定的代价与窗口大小成线性，不随已被摘要的前缀增长。窗口里的 `tool` 消息由历史持有者给出配对见证。窗口不满足来源关系时答 `source-evidence`，表示判断依据不成立，不表示新摘要写错了。
- 形状失败与历史规则失败分开报告：调用方能区分「这条消息写错了」与「它和这段历史对不上」。窗口的真实与完整由历史持有者负责。
- 推理续接状态：可读的推理文字放思考块，不透明的推理状态放推理续接状态部件，两者用 `pairs` 配对。一条 assistant 消息只属于一个模型，带续接状态时必须带回放描述 `replay`，`replay.at` 恰好列出全部续接状态部件的下标。去掉块形成新消息的投影方必须重写 `at` 与 `pairs`。续接状态不对人展示，不进压缩记录。本成员不解释 `scope`、`format` 与载荷，哪个模型能消费归 Model。载荷是租户数据，随所在消息保存。

### 流式到达

- 一次流式交付的步骤只有开块、填充、封块、削减、结束。步骤不是入站受理，也不是派发；本成员不分配序号，不保存日志，不携带用量与费用。
- 序号由发出该目标的一方分配，作用域是这一个目标；开块序号递增可跳号，块内的填充序号从 0 起逐一加一。重复先于顺序检查：同一身份同一内容是空操作，不同内容是冲突。终态之后的新步骤是迟到。
- 开块头先判定，后复制或求指纹：键集闭合，除 `visibility` 外每个值都是文本；任何键下的深层值在这个键上就被拒绝，不做遍历。
- 工具调用只能用带完整调用部件的显式封块封口；带削减记录的工具调用块永不封口，剩下的文本也许能解码，但不证明模型已经写完。工具结果与推理续接状态没有追加形式，只整块到达。中止、截断、失败收场的终态只带已封口的部件，不当作消息判定；半截调用由流的结算方构造并对整条消息判定。调用方取消不是一个步骤。
- 流引用绑定生产者、原调用的规范文本与一个已发布的流身份；游标绑定完整引用与该流内单调的位置，不同流的位置没有共同顺序。新的派发或发布代次用新的流身份，旧引用不转向后继。规范文本与长度上限是公开契约，超限在解析之前拒绝，不截断。
- 引用的判定先核租户，再解析结构，再比生产者，最后调用生产者的 codec；游标内嵌的引用逐码元等于目标引用，否则是 `foreign-stream`。调用文本不含租户。
- 观察先交已确认快照，再交增量；生产者在同一临界区取得快照并登记其后的订阅，先读快照再普通订阅不满足契约。没有续接游标重放：缺口或断线之后，消费者重新取当前快照。已交出的缺口与结束帧是最终帧；没有终止帧的流尾是连接失败。
- 每次实际输出帧之前，来源核当前资格、租户、流绑定与发布代次；排队内容与较早的检查不授权之后的输出。队列、快照与增量都有声明的上限，超限先撤订阅、丢弃待交数据，再以缺口或容量结束，不丢中间帧继续。中止与迭代器关闭只移除这一次观察，不取消生产者的工作，不确认结果。

### 调用账目

- 模型调用与工具执行用同一形状，用 subject 种类区分。金额是未知、已知或暂估三种之一；未知只有单位。准入只收封闭账的已知键。
- 后一份快照只有修订更大才取代前一份；更低或相同的修订保留先到的。subject 不同是拒绝。
- 小计只加一个来源里已知的金额；暂估与未知不进求和，没有已知项时小计是未知。参与求和的项单位不同是拒绝；单位按精确字符串区分，不换算。十进制相加不经过 `Number`。应付金额优先取账本小计。

### 操作结果

- 两种形状：带值成功 `{ ok: T }`，无值确认 `{ ok: true }`，失败 `{ failure: F }`。两种类型不合并成一个信封。
- 失败的词汇、含义与处置归调用方契约；本成员不检查失败的内容，也不把异常转成失败。

### 模态

- 模态恰有四种：`text`、`image`、`voice`、`video`。名字用 `voice`，不用 `audio`；文件、思考与工具调用不是模态。判定不做大小写折叠，不做别名映射。
- 媒体类型按 RFC 9110 的文法判定，规范形式是小写的 `type/subtype`，参数全部丢弃。模态只看顶层类型：全部 `text/*`、`image/*`、`audio/*`（含音乐）、`video/*` 分别是四种模态，其他顶层类型不属于任何模态。判定不看内容与扩展名。
- 模态与支持范围分开：本成员只说有哪几种，消费者自己声明支持哪几种。缺失模态只做集合差，合法的转换能否补足缺口归消费者。

### 交接引用

- `Adoption` 是一个可以恢复的精确采用：发布者、名字、精确版本与内容摘要。`DurableEvidence` 是一个拥有者的一份耐久记录的定位。`ConsumerRef` 是消费者拥有者登记的稳定位置，生产方原样保存、不解释，它不是执行许可。三者都是四个必需字符串成员的只读记录，不含租户。
- 结构判定、摘要的铸造与算法、跨值不变式留在原域；本成员只发布类型，没有运行时值。

### 重试策略

- 策略是次数上限、总时长上限、间隔表与抖动。成员里没有缺省数值，不读时钟，不用定时器与随机数：随机数由调用方传入，等待由调用方自己做。判定只答再试一次（等多久）还是预算用尽。

## 原则与约束

- 一个值进本组之前，要有两个以上的具名消费者，并由原语义拥有者确认含义一致；本组不接管相邻领域的业务规则或事实权威。
- 每种表示只定义一次。消费者从公开入口导入，不复制类型、判定或拼写；需要的形状变化先改这里，再同步消费者。
- 叶子不依赖领域，不导入存储、服务或 Cordis，不读环境、时钟或网络。
- 判定成功不等于存在、可信或获准；这三件事在原拥有者那里另外核。
- 数值与精度不经 JavaScript number 转换：数字保留词素，十进制按系数与指数运算，时间按文本比较。

## 不变式

| 编号  | 永远成立的性质                                                                         | 违反的后果                               | 由什么守                                                                    |
