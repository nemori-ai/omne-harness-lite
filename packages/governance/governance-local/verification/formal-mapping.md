# 治理的模型、性质与实现的对应

`models/` 下的 TLA+ 模型检查[包组规格](../../SPEC.md)的几组规则。每份配置是正控还是负控、负控应当违反哪一条性质，登记在 [models.json](models.json) 的 `expected` 里，由 `check.py` 读取；`check-contributions.py` 是按租约释放的有限契约预言机。模型只说明在登记的有界实例与前提之内没有这一类缺陷，不证明实现符合；实现由右列的用例核对。

## 权限检查是读，提交点核验

| 模型                    | 实现                                                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 读的三步与判断          | `apps/harness-server/src/rows/governance/permission-basis-read.ts`：一次投影读取租户域事实，另读 Identity 资格与组织层来源 |
| 提交点的核验 `Verified` | Tool 受理的账本提交带条件：同一串只读命令在事务里重跑，`permission-basis-guard-participant.ts` 比较摘要                    |
| 核验不成立后回到 idle   | tool-host-local 的启动协调器收到 `condition-failed` 后重读重判                                                             |
| 另一个域的事实读不到    | 读数的 `unavailable` 变体                                                                                                  |
| 执行修订不在核验里      | 命令清单里没有执行修订的守卫                                                                                               |

模型把租户域的几项事实合成一个；实现逐项核验，任一项不等就不成立，结论不变。

## 前提与没有建模的

- 存储事务是原子的；协调者原样发送保存的请求；完整请求值可以区分。Restart 只表达丢失进程内状态，不验证断电。
- 主体发行、原发布来源的真实性、固定发行映射与执行关口的真实性是外部前提，模型不发行这些资格。
- 恢复类活性只在当前贡献、资格与许可持续合法且消费弱公平时成立。
- 没有建模：SQL 索引与查询代价、任意规模、跨进程部署与分布式租约、散列碰撞、Cordis 运行时内部行为。
- 退出额度的一般论证不依赖模型的小数值：令修订上界为 M、有效租约上限为 C、阈值 T = M − C。新增发布要求两项修订严格低于 T，最后一次成功递增至多到 T；之后至多 C 条租约各退出一次，修订至多到 M；重复退出不递增。
- 目标支撑的一般论证：令支撑关系 S ⊆ 租约 × 目标，可见目标为 range(S)。撤除租约 l 后 S' = { (r, t) ∈ S | r ≠ l }，可见目标为 range(S')，对任意有限关系成立。
