# Governance

## 总体架构

Governance 包组回答一个问题：一个功能或一份资产怎样在运行中把自己的设置项与权限关口声明（治理声明，`GovernanceDefinitionBundle`）交给一个逻辑服务，这个服务当前采用的是哪一整套声明，读者怎样拿到这份当前事实，而这一切都不碰设置的配值、许可与身份资格。

| 成员                  | 回答的问题                                                                                                                                                              |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `governance-contract` | 动态贡献、当前采用与受保护目录的公共协议：命令与查询的输入 Schema、结果类型、原发布来源端口 `GovernanceDefinitionSource`、唯一的 Cordis 服务定义。纯数据与纯类型        |
| `governance-local`    | 本地持久提供者：私有关系与迁移材料、原操作与 SQL 请求保管、Identity 资格保留、完整采用、目录、启动恢复与关闭，以及给受信 SQL 组合用的只读投影参加者与 Cordis 提供者插件 |

工作时，注册者以一次原操作调用 `contribute`，提供者先向原发布来源核对声明，再经 Identity 保留注册资格，把声明副本与一条精确租约（`GovernanceContributionRef`）同提交。装配者看过当前全部租约之后，以两项预期修订与一份完整选择调用 `adopt`，提供者按权威当前集合重算、核对目标与关口事实后整份发布。读者经 `readCatalog` 读管理目录或运行目录；业务领域在自己的动作提交点经只读投影重新核对当前事实。`withdraw` 只撤一条精确租约。每次装配换一个不复用的代次（epoch），先隔离旧代并收完旧代的责任，再接新请求。

## 领域边界

本组拥有：每个租户目的域里一个逻辑服务的治理范围（scope）与它的代次；核验过的不可变声明副本；贡献租约；当前采用（选中的定义与目标，以及每条租约支撑哪些目标）；声明修订与采用修订；每个原操作的请求、执行内容、终态与原回执；向 Identity 发出的资格保留请求的保管记录。

本组不拥有：设置配值与属性锁（Settings）；权限规则的解释（Permissions）；具体许可与消费回执（Authorization）；主体发行、成员资格与资格保留本身（Identity）；声明的发布权威（功能拥有者或 Assets）；资产持有；执行清单的采用（装配与交接领域的采用协调者，`prepare`、`validate`、`read` 三个操作不变）；人的请求与答复（人工介入）。本组的读数是一次观察，不是许可。

## 心智模型

把一个逻辑服务的治理范围想成一块菜单板。每个功能来登记时领到一张自己的租约，租约下挂着它那份不可变声明；同一份声明可以有好几张租约，各自独立。菜单板上「现在供应什么」不是租约的集合，而是装配者一次整份定下的采用：选中的定义与目标，加上每张租约支撑了哪些目标。撤掉一张租约只拿掉它自己的支撑，还有别的支撑的目标留着。

每个有副作用的调用都是一个原操作，身份是命令种类、范围、核验过的主体与 `operationId`。原操作一旦受理，它的请求与执行内容就固定了；结果不知道就按原身份认回，不换身份重做，也不因为来源下线、换了代次或换了组合配置就改写已经提交的结果。代次是围栏：新实例先封住旧代，收完旧代在途的责任，才开门。

最容易想错的地方：读到的当前依据（`GovernanceBasis`）不是许可，动作在自己的提交点重新核对；目录缺来源是不完整，不是空；准入只是一次当前读取，写路径还要经 Identity 保留资格；Cordis 卸载完成不等于业务关闭，关闭以持久隔离、责任结算与调用排空为准。

## 应然设计

### 准入、身份与范围

- 每个入口先核有限结构与字节预算，再核 Access 里的主体、租户与当前资格，然后才处理原操作绑定、版本与业务约束。Schema 解析成功不是资格。
- `scope.tenantRef` 等于 Legal Identity 对 Access 租户的规范编码；Access 租户、主体租户、存储租户与 scope 租户必须一致。租户可见范围指向该租户，组织可见范围指向该租户的组织；公共发布者由受信发行映射核验，不从插件名推断。
- 准入消费受信装配固定的有限委托关系：每项绑定完整主体、scope、一个动作与所需 Identity 资格，同一主体、scope、动作只能有一项。登记委托另外绑定每个 `ownerId` 允许的完整执行关口集合，owner 与关口的对应关系保留，不交叉组合。空配置默认拒绝，没有通配符，委托不从客户端来。
- 目录管理读、运行读、原操作查询、贡献、撤除与采用各自授予，不从一个动作推出另一个。发行真实性、委托范围、来源真实性三者互不替代。
- 入口在第一次异步等待之前捕获命令与 Access 的引用，之后只用这份快照。不存在的对象与无权访问的对象答同一个公开分支。

### 原操作与认回

- 原操作身份是命令种类、完整 scope、核验后的主体与 `operationId`；`generation` 与 epoch 是请求内容，不是另一个命名空间。同身份同业务摘要认回原结果，异摘要答 `conflict`（operation）。业务摘要用规范 JSON，不含传输状态与提供者对象。
- 原操作的状态：受理（保存原请求）、提交中（保存固定执行内容）、已提交（业务效果与原结果同提交）、已中止（封口或业务拒绝）。未终结的不带最终结果。已提交与已中止不再变化。
- 业务写入核对原操作在提交中、执行内容就是保存的那份、epoch 仍开放；已终结先认回。封口与迟到执行竞争同一条原操作记录，先成立者定终态。已失效 epoch 的在途业务以中止结束，不产生新租约。
- `unknown` 只说明调用方没拿到权威结果，不是未提交。`queryOperation` 先核披露资格，只访问已核主体自己的原键，不推进、封口或结算原操作。查无记录不足以答 `not-committed`：要有存储给出的未提交证明，或同域不可逆的封口引用；没有就答 `unknown`。受理而未终结答 `pending`。
- `committed.original` 保留提交时的原结果；`contribute` 重传返回原租约引用与此刻观察到的租约状态，两者分开。重传不创建新租约，不复活已退出的租约。
- 执行内容里的 authority 只由入口从核验结果构造，绑定主体、scope、资格、原发布引用与完整声明摘要；调用方不能自报。

### SQL 请求保管与提交

- 本组全部关系只有一个写者。元数据、贡献变更、采用三条计划路径互斥，一个组合只选其一；调用写者时必须同时调用它需要的计划参加者。采用计划只从同一次 SQL 的当前事实取证据，请求不能携带证据替代它。
- 原操作的每个阶段至多保存一份完整提交请求；首次保存决定内容，相同内容认回，不同内容冲突，不因新组合版本或新命令替换。业务写入要求已保存的执行请求，缺了就回滚。
- 协调者只发送保存并读回确认的请求；回包丢失时按同一 SQL 身份查询，或原样重送。回执须分别对上完整身份、输入摘要、组合版本与清单摘要，成功回执恰有一个本组写者的回复。存储的回滚、存储给出的未提交证明与领域的中止是三件事，不互相推导。
- 首次受理之前查不到原记录时，先按固定受理身份查询；只有存储证明未提交才发受理请求，未知保持未知。受理成功之后再点查当前记录，不让旧受理回执盖住已提交或已封口的状态。受理回执也保存被拒绝的输入，换代之后仍能核验原拒绝。
- 一次调用只执行有限步，不无限轮询；调用方沿同一原身份继续恢复。

### 不可变声明与原发布来源

- `ownerId`、`definitionId`、`version` 唯一决定一个声明摘要。旧租约全部释放后，同版本异摘要仍冲突；同摘要可以由不同原操作持有兄弟租约。本地唯一键只守本地认回，不证明跨租户的版本不变。
- 首次准备贡献时，提供者在第一次异步等待前固定调用方正文，只按完整身份向原发布来源读取，比较完整引用与正文。来源答错误身份、非法声明或异常，答不可用；来源合法而正文不同，答 `conflict`（definition）。相同摘要不掩盖不同正文。来源核验不发登记资格。
- 原发布摘要保持原值，本组不以自己的摘要替换它。恢复时读保存的原执行内容，不要求来源仍在线。
- 每份声明与每个 scope 都有项数与字节预算；预算耗尽答 `limited`，不截断后成功。

### 完整采用

- `adopt` 核对当前声明修订与采用修订、当前 epoch 的全部有效租约、目标与真实关口。完整选择必须恰好覆盖全部有效租约：重复、遗漏、多出、旧 `generation` 或别的 scope 都拒绝。每条租约可以不选目标，但它的设置项与权限项一起进入采用。空集合只在权威候选也为空时可以发布。
- `collection.digest` 是对 `scope`、`declarationRevision`、`complete` 组成的对象做 RFC 8785 规范 JSON 的 UTF-8 字节、取 SHA-256 小写十六进制。`complete` 的每项是租约引用、完整定义引用与选中目标；目标先按各自规范 JSON 文本排序，成员再按规范 JSON 文本排序。提供者用权威当前声明重算，不信调用方自报完整。别的后端遵守同一编码。
- 每个目标必须启用，来源与完整设置定义与声明相同；每个声明的关口必须对上当前实现、动作与解释映射。同一设置身份的不同来源或定义、同一权限身份的不同定义、同一关口的不同映射，拒绝整份采用。这些投影是受信参加者的输入，不是客户端许可。
- 全部检查先于关系替换。成功时在一个事务里替换成员、逐租约目标支撑、选中定义与选中目标，推进采用修订并保存原回执；失败保留旧选择。两个请求持同一采用修订，至多一个成功。

### 当前依据与目录

- `GovernanceBasis` 是一次受保护读取的事实，绑定 scope、epoch、采用修订、声明修订与声明摘要。业务领域经自己的端口在动作排序边界重新核对当前事实；本组的读取不留下持久记录，不预留，不建原操作。业务领域不导入本组取全局状态。
- 管理目录列出有资格查看的声明、未被采用的贡献与禁用目标；运行目录只列当前采用且可用的选择。同定义的未采用兄弟租约不借另一条租约进入运行结果；`selectedTargets` 只表示真实采用。
- 每页重核目录披露资格。游标绑定主体、scope、模式、目标、epoch、两项修订与目标和关口的见证；任一项变化，旧游标答 `conflict`（basis）。单项超过页预算答 `limited`，不跳过。来源不全答 `partial` 并列出 `unavailableOwners`，或答不可用，不伪装成完整的空页。投影读没有答复、答复畸形或页面的 scope 与 epoch 不是本次绑定，答不可用。
- 当前注册声明的事实只要求 scope 开放、epoch 相同、存在该精确定义的有效贡献，不要求设置目标；当前采用声明的事实另要求该定义在当前选中集合里；目标投影在运行模式另要求该目标在当前选中集合里。三者都带完整绑定（scope、epoch、主体、捕获、事务域、定义），读取有字节上限，缺失、撤下、旧代、关闭与超限各答具名的不可用，损坏的正文让事务失败。它们只证明本组的事实，不证明资格、持有、执行器在线或无配值；消费方在自己的事务里核对绑定并消费，旧观察不能代替新读取。

### 精确撤除与退出额度

- `withdraw` 必须匹配完整租约引用与原注册主体。旧 `generation`、另一 `registrationId` 或另一租户的撤除不影响当前租约。撤除在一个事务里删除该租约的目标支撑、退出成员、清理没有支撑的采用投影、推进两项修订并保存原结果；重复撤除答 `already-released`，不推进修订。
- 选中目标等于剩余支撑关系的投影：还有支撑的目标留下，没有支撑的消失，别的租约的支撑不变。外键不能单独保证两者相等，由单事务写者保证。
- 每个 scope 的有效租约有上限。新增贡献与采用要求两项修订都严格低于「修订上界减租约上限」，给全部有效租约各留一次退出；每次真实退出消耗一次修订。
- 受信的生命周期撤除只处理它持有的原操作：先点查原操作与摘要，未终结的封口，已提交的从原命令导出精确租约再撤除；不重新申请资格，不重新查来源，不改原回执，不撤兄弟租约。

### Identity 资格保留

- 写路径先受理原操作，再保存完整资格请求（原操作、主体、租户、目的地址、事务域、请求摘要、资格集合），之后才调用 Identity。目的地址或资格集合变了拒绝替换。
- 保管状态是请求中、持有、已结算。只保管与完整原请求匹配的回执；迟到的持有回执可以保管，但不复活原操作，不把已结算降回持有。被拒绝的保留留在请求中，由调用方决定重试或结束原操作。
- 业务入口先认回原终态，再要求持有，最后调用同事务的业务写者；缺持有答不可用并保留待处理的原操作。业务提交与目的端封口竞争同一原操作。Identity 只有拿到确定终态才释放保留。
- 恢复目的适配器先读不可变原请求，逐字段核对路由、主体、租户、摘要、目的地址、事务域与资格集合，再进入固定的封口阶段；事务内仍复核一次。错误输入不能占住固定的 SQL 身份。查无请求或路由错绑不是释放依据。

### 代次、恢复与关闭

- 每次构造产生不可复用的新 epoch，调用方不能指定旧代；同一 scope 只有一个合法启动者。普通调用不能重新开放 scope。
- 恢复集合包括业务仍在受理或提交中的原操作，以及业务已终结但资格保留还在请求中或持有的原操作。按同一 scope 做有界 keyset 分页；分页不是跨页快照，一轮结束后从头再扫。枚举只给出候选，不证明未提交，不授予重试资格。
- 启动恢复每页同序读取当前 epoch 与每条候选的受理 epoch，只在当前 epoch 是本实例时处理该页，封口前核对原键、请求摘要与受理 epoch，封口后重读持久终态再结算资格。整轮完成、没有未结算责任且本代仍开放，才交出服务；依赖不可用、页预算耗尽或被继任者替换，答不可用且保留持久责任。
- 关闭同步停受理，在一个事务里核对完整 scope 与当前 epoch，退出本代的贡献与选择关系、封口未终结的原操作并关闭 scope；不改已提交回执与 Identity 保管记录，不删设置配值与权限。修订到上界时仍能关闭。只有隔离、调用排空与完整恢复扫描都确认，才答 `closed`；否则答 `pending`，责任保留，同一关闭不并发启动第二次。
- 五个应用方法共用一个提供者生命周期：进入方法先登记在途，再同步捕获输入。共享的 SQL 与 Identity 由装配拥有，本组借用，不关闭它们。

### 调用方清理与 Cordis 装配

- 唯一服务键由契约的服务定义给出，提供者继承它，不另提供同键。注入可见不授予任何业务权限。
- 提供者插件先登记自己的清理责任，再启动运行时，启动恢复完成后才构造服务。启动途中被显式卸载或依赖失效，不发布晚到的服务。
- `contribute` 在第一次异步等待前把清理登记到调用方的 fiber。相同完整原绑定的调用共享一个清理组，任一调用方关闭就关闭整组的入口，不以引用计数延长租约；别的原操作的租约独立。未获准的调用不能加入已有责任组。
- 缺原记录时，先确认组内调用都已返回，再按受理身份取未提交证明；只有权威证明未提交且不在队列中才算清完。有原记录的按精确撤除或封口处理，并确认资格已结算。超时答 `pending`，提供者继续持有并有界重试，每组至多一个在途清理。已卸载调用方的旧引用答不可用。
- `observeClose` 收到首次 `pending` 与最终 `closed`；观察回调不参与完成判定，失败只留诊断。框架的卸载完成不等于 `closed`。进程重启之后，由持久 epoch 隔离与历史恢复接续，不恢复内存里的 Promise。

### 存储

- 本组的关系只属于本组，不建指向 Settings、Assets 或 Identity 私表的外键，不读这些领域的表。声明、注册、当前采用与操作回执在同一租户写域。
- 当前读按 scope、epoch 与状态的索引访问；恢复读固定使用本组的部分索引，索引缺失时拒绝执行，不回退到历史扫描。声明历史不进当前目录的全表输入。
- 迁移材料一次建立全部关系，不启动数据库；新增的迁移不改写已有迁移的字节。材料文件读不到就抛出，不返回空迁移。

## 原则与约束

- 读数不是许可。当前依据、目录与投影只是一次观察；动作在自己的提交点重新核对。
- 结果不知道就是不知道。按原操作身份认回，不换身份重做，不写成成功或失败。
- 原发布拥有者、Identity、受信装配各管一件事：声明真实、主体与资格、委托范围。三者不互相代替。
- 只撤自己的那一份。撤除、清理、关闭都按精确租约与精确代次，不碰兄弟租约与后继实例。
- 不读别人的私表，不保存别人的事实；配值、许可、资格与持有各归原领域，卸载不删它们。
- 预算是有界的：输入、页面、恢复与清理都有上界，超出答 `limited` 或 `pending`，不截断成功，不无限重试。
- 自定义的提交、保管、恢复与准入协议有形式模型与关键性质检查，模型在 `governance-local/verification/`，对照见同目录的 `formal-mapping.md`；有限检查通过不等于实现符合。
