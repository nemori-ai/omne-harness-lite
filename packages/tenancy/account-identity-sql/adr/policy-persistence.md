# 身份策略与持久操作

采用范围：内部职责迁移，沿 AI3 和[公共身份承诺](../../../core/account-identity/SPEC.md)。
采用依据：身份集成设计
及成员 [SPEC](../SPEC.md)；不新增业务政策或跨 owner 事务例外。

原 accounts/logins/records 同时选择业务结果并编写 SQL。现由 identity-data.ts 定义私有数据面，
identity-sql.ts 借用原事务执行具名查询、锁和写。策略保持原凭据、时间、授权、G 和票据判断。
工厂显式构造策略依赖，并在公开参与门绑定原 StorageUnit；原单一提交和错误污染不搬到新端口。

记录形状和解码只有一个拥有者；读取保持原始列表示，在原使用点解码。
表、列、约束、迁移、排序及条件写均保持。内部装配函数供真实工厂与故障夹具共用，
不从公共根导出；普通准入、关闭和票据清理仍归原工厂。

成本是私有操作面、桥接和工厂委托。边界收益是策略不再接收 SQL 或真实存储实例，
可以独立检查业务判断与事务适配。复杂度收益必须实测，分拆文件不表示复杂度下降。
原测试、跨 owner 单元、回滚、通知及四层消费仍是接受前提；端口类型不证明真实组合。
若要改变提交次数、参与范围、错误优先次序或迁移身份，重新核对有效承诺和消费者。
