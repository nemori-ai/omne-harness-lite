# Immutable Model history

Session ingress retains one current content root per tenant, Session and journal generation. A root is a `ModelLogHistory`. It proves captured immutable content, not read permission, current membership, an attempt fence or physical commit.

The private implementation uses Immutable.js 5 List and Map. The List owns one cell per log position. Appends share earlier cells. Each cell memoizes its Model capture, local record interpretation and Session fact interpretation. A response capture exposes its already-judged typed response so semantic consumers can use it without repeating the owner validator. The current root does not retain earlier root objects. Active consumers can retain their own fixed roots.

Sparse position indexes serve dedupe keys, read keys, MessageId, ResponseId and dispatched ResponseId. Read keys include existing Call and dispatch identities. Session fact indexes serve kind, Call and Run. Index values contain positions, not payload copies. Every index belongs to its cut. Later response conflicts or newly satisfied assistant associations cannot change an earlier cut.

Model interpretation has two stages. Capture examines the new suffix in order before association checks. A capture failure is fixed for that cut and its extensions. Association failures are indexed by position. A response only schedules assistants that reference its identity. A new root starts with the last available interpretation checkpoint and folds the remaining cells. Unexpected exceptions do not install a checkpoint. Local selection and modality readers retain their original rules and do not require global Model success. The local model-selection checkpoint belongs to the fixed content root. It shares each cell's captured envelope and record interpretation, inherits the last examined position and durable choice, and checks only its unexamined suffix. A fenced selection record or invalid reserved Model envelope makes that local result unavailable. An unrelated assistant association failure does not. No selection-specific history cache is maintained by CLI or by each selection consumer.

List access has an O(log N) bound. Sparse Map lookup and update have expected O(log N) cost under bounded hash collisions; this is not an unconditional worst-case bound. Immutable.js retains collision buckets. A bucket with C colliding keys can require O(C) lookup or copying, even though large buckets have a secondary lookup index. With bounded collisions, a suffix with K indexed references costs O(K log N) plus its content validation. A selector that reads R indexed positions has conservative O((R + 1) log N) cost, including List access. Collision handling adds the selected bucket cost; it does not decode unrelated log payloads. Call interpretation still checks the selected Call's records. It does not enumerate unrelated Calls. Full enumeration and message materialization cost O(N + output bytes). Compaction in the message projection owner reselects cached blocks without decoding old content.

The mature persistent collections replace a custom version table or tree. Immutable.js stays a private dependency. Public signatures, stored JSON and returned records use ordinary project types.

Each cell records the UTF-8 length of its canonical owned entry. A cut's retained byte count is the empty `{entries:[],tail}` envelope length plus entry lengths and N minus one commas for a nonempty array. The original tail spelling is retained. Tests compare this count with the actual lossless writer, including Unicode and exact numbers. The settlement guard receives the full prefix count at its original position. Candidate bytes remain separately charged.

Session owns retention bounds and borrow lifetime. Each cell reserves 16 logical reference slots for its lazy indexes, in addition to its declared dedupe and read keys. Each retained root reserves another 16 slots in Session accounting. These conservative reservations apply before the lazy indexes are built. A new cut also reserves 16 slots for each earlier cell after its oldest semantic checkpoint: an active cold cut can still build those indexes independently. Warm checkpoints share their roots and only reserve the suffix. The public indexReferences count is the cumulative reservation along that construction path, not a count of live heap pointers. Logical index references are not heap bytes. Persistent tree nodes add a bounded branching and depth factor to those references. Caller-owned materialized output and transient storage reads remain separate resource responsibilities.
