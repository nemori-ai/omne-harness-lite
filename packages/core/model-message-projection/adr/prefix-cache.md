# 模型消息投影与前缀缓存

目标选择：C2。线性冷建作为失效退路，热路径复用不可变前缀。此迁移未新增技术接受。

## C：模型消息投影

| 候选 | 兑现Q6 | 成本、敏感点与风险 | 采用判断 |
|---|---|---|---|
| C1 每请求线性两遍重建＋索引 | 完整fixed-prefix输入；先建压缩／原响应索引，再按序选消息；非消息跳过 | 最少状态，冷O(N)，每轮仍需整扫，不实现用户偏好前缀复用 | 作为正确性参考和失效退路，不作为唯一热路径 |
| C2 单当前缓存＋分段不可变前缀＋引用索引，追加更新 | 固定来源进度、规则／外部输入键；热路径处理Δ；压缩碰旧块时定位首次受影响段，重建后缀或线性冷建；重新缓存 | 缓存键不全会错误复用；必须有一致快照／CAS发布、内存界及损坏降级重建；输出线性成本不可隐藏 | 推荐；不建无限历史多版本缓存，先证明收益和失效正确性 |
| C3 持久物化请求消息表／增量视图 | 每条日志变动更新view和版本；读近O(K)；压缩通过引用索引删除视图项、历史日志保持 | 写放大、规则变化重建协议、跨owner同提交需求；大量历史版本有储存成本；较强适配层可能提前锁定算法 | 有长历史／高频读收益时再采用；目前没有证明必须持久缓存才能满足要求 |

C2不承诺最坏情况hash索引O(1)；需要严格界时可换有序索引O(log N)，冷重建仍不得变O(N log N)。N包括引用边与块，不把一条携带百万引用的条目算常量。
每次追加逐项复制全prefix会在多轮累积O(N²)，因此缓存保分段共享结构；materialize每次仍O(K+B)，这是实际输出成本。


复核条件：高频全失效或内存收益差时测量后调整缓存机制。冷建正确性、字节成本和输出下界保持。供应方prompt cache不属于本地保证。
