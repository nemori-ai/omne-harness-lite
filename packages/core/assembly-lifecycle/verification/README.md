# 装配关闭协议的验证义务

[行为契约](../SPEC.md)拥有控制权、就绪、真实关闭和保有条件。本入口保留持续验证义务，不记录某次通过。

| 范围 | 必须观察 | 可复跑入口与限制 |
| --- | --- | --- |
| 同步资格与一次接管 | 同tick仅首个接管；重复登记或停止后登记阻新资源；onStopping抛错不恢复资格 | [协调器测试](../tests/lifetime.spec.ts)。先核具体用例，受控工作不能证明真实业务已静止 |
| 管理启动 | 登记先于effect及setup；原setup异常保持；effect安装失败与启动取消收尾完整前缀；ready与ACTIVE分开 | [管理启动测试](../tests/cordis.spec.ts)。实际依赖与工厂仍须组合验证 |
| 真实撤除后半程 | 强撤provider后，旧消费者网络或scrypt晚返仍可完成必要CAS或事务；完整消费者先于依赖关闭 | [治理宿主验证](../../../../apps/tenancy-host/verification/README.md)和[CLI验证](../../../../apps/cli/verification/README.md)承担实际组合 |
| 失败与未完成 | setup与close双失败分别保留；未静止不提前拒绝或跳行；超时不造closed；重复close保同一观察 | 实际tests与应用故障驱动。恢复直接effect.close的负控必须复现提前释放，解析或超时错误不算负控 |
| 开放与注册续步 | 两面监听先撤仍同步拒新准入；步骤①或②晚返不交下一步；未兑现与已兑现wait分别观察 | 同一代际真实绑定及应用测试，不以事件缓存或Promise历史成功放行 |

有限状态或枚举仅承担其明确建模的安全条件。无循环等待还须核对真实依赖和交错，进展以前置ready、已接纳业务和close最终返回为条件，不承诺强迫失去响应的外部工作结束。

测试路径由本成员实际tests发现。新增资源或测试改名时同步本入口，不降低义务或以删登记销项。

## 当前机制回归与目标准入

现有协调器测试中的整代同步失效，只描述[当前机制](../README_ZH.md#当前机制与架构偏离)，不是未来装配必须保留的政策。目标验证须构造互不依赖的A、B与A使用的提供者，撤除或替换该提供者时，核对B仍可运行；可选依赖换代也须覆盖该反例。

装配与机制拥有者须验证候选准备、资格切换和原工作交接。关闭结果真实性、未静止保有、失败分别记录等验证义务继续有效。当前产品代码未变，目标反例未在此文档改动中运行，不能报告连续性已满足。
