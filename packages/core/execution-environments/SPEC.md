# execution-environments 行为契约

采用依据：2026-10-04 用户授权采用经审阅的 Tool Runtime r10 设计并实施第二阶段。本期增量沿2026-10-06用户授权的PR1交付，由主会话在选择／表达无剩余阻断后作技术采用；不据此接受产品故事或声明后端已完成。公开形状归 `src/index.ts`；本页只约束类型不能保证的行为。分阶段兑现范围由实际验证证据报告，不以本页存在宣称全部实现。

EE-1 引用只定位，不授权。每次 acquire 核验当次有效依据、设施和落点。禁止、未知、无匹配都不回退到更宽环境。

EE-2 租户与会话必须匹配。实例句柄只提供声明设施，工具不能用它取得全局服务。

EE-3 release 不自动销毁共享环境，不能丢弃仍活动的执行资源。提供者撤除、资源失效和实际停止分别报告；未知停止不写成已停止。

EE-4 环境变化影响后续 acquire；在途执行按原采用值继续，实际资源丧失则明确失败，不重绑定后重做命令。

EE-5 一次工具执行可以不启动命令，也可以创建多个资源。执行身份和资源身份不得混用。每个可能跨进程寿命存活的资源先确认恢复依据，再创建等待许可的资源；确认许可后才能执行用户命令。未知确认不授予许可，恢复不重新授予旧许可。

EE-6 runtime 提供的 ResourceLifecycle 与该次执行绑定，环境提供者不得跨执行使用它。资源许可与执行终局按同一耐久事实顺序判定；终局先提交则拒绝许可，许可先提交也不能抹去后续的物理停止责任。closed 后不得发出新许可或启动新的设施操作，已发生的作用不能因此宣称撤销。

EE-7 停止答复有界，不能确认时返回 pending／unconfirmed 并保留善后责任。资源不存在且仍可能有旧创建到达时，不得报告确认停止；先排空或有效隔离创建，再确认该资源不再执行。新服务可见性不能覆盖旧资源的回收身份。

EE-8 环境提供者撤除先拒新 lease，再使旧设施不可用于新操作并关闭许可写端。已有创建任务、原生控制能力和状态回报口由原提供者的清理闭包保有。停止等待超时不取消清理任务；异步撤除不能在清理完成或耐久恢复责任仍无人承接时宣称完成。观察者 release 不进入此流程，工具不取得 lease 的释放权。

EE-9 描述不授予执行权。设施每次调用核验原 lease 有效性；外部作用已发出但回执未知返回 effectUnknown，不自动重试。recover 只停止合法资源，不重授旧许可。

EE-10（core/execution-environments）RecoveryAccess 独立于用户访问绑定，由应用维护 owner 根据当前物理所有权及耐久会话／资源归属签发并逐次校验。它只能停止、认回、结算既有责任，不允许 acquire、新工具执行或恢复已撤销的用户权限；原用户撤权或登录退出不能阻断系统回收。

EE-11 同一环境 owner 只有一个活体 placement 来源。来源由可信插件贡献，显式接收 scope、当前访问绑定及原调用身份；其结果须对应同一租户、会话、工具定义与执行。缺来源、读取失败、无法决定、不适用和拒绝分别表达，不用引用或 TS 品牌自签权限。第二来源登记拒绝；旧 disposer、晚回执和同名替换不改变新代。

EE-12 绑定层默认恰等，所需设施全部在同一实例满足。never-allow 不取得宿主；always-allow 只给予宿主资格，不抹去目标要求。auto_place 及多候选消歧由显式策略决定，缺策略不能任取第一项或放宽目标。策略只能选择已核验的匹配候选；当前来源输入与实际获取回执不符须释放该次 lease 并保留原清理责任，不假成功。

EE-13 实例身份、代、绑定归属和数据连续性分别表达。描述的bindingLayer须等于binding.kind；查询返回不一致描述拒providerUnavailable，已取得lease的描述不一致先撤使用资格并释放或保留原清理义务，再拒providerUnavailable。stateless 归属必须与原 scope／CallId 均相符，session 核会话与租户，tenant 核租户；同会话同工具的不同调用不能串用单次实例。引用或绑定层不证明数据仍连续；未知不能当已确认。恢复重新获取合法能力，不恢复 JS 句柄，也不因新实例可见而重跑旧作用。

EE-14 lease 的新命令和文件操作逐次核当前访问权、原实例上的作用授权及 lease／来源／提供者是否有效。当前授权读取失败不得执行。配置更新不重写已采用输入或自动重选实例；撤权拒新操作，不自动取消已启动命令。原进程的输出、终局、停止和资源善后仍由原执行及提供者负责。

EE-15 command 实现者必须在终局前提供 stdout／stderr 原始字节流。同管道保序，跨管道只承诺实际观察顺序；输出字节由接收者独占。流是唯一输出正文来源，终局不再重复保存整份聚合输出；重复／并发等待 result 不重复启动命令。输入参数、环境及字节在作用前捕获，环境不隐式继承宿主变量。

EE-16 输出有显式字节缓冲及块大小界限。无人读、慢读或提前退出不能无限缓存、阻塞终局或资源停止；丢弃字节数可观察。终局计数说明传输至完成时的观察／丢弃，不证明读者消费了全部字节。iterator.return／break 只释放读流权，不等同 stop。EOF、进程终局、stop 请求和确认资源已停分别判断；失败或未知回执不得伪造退出码。completed只用于进程完成已确认，exit.unknown只表示退出细节未知；完成事实无法确认时用failed，仍交付截至失联的观察／丢弃计数与已观察时长，不把它们表述为完整进程终局计数。流通道失联不能留一个永不结算的result，须明确failed或由独立控制源确认completed。聚合适配须有界，并消费原流，不能再次 start。

EE-17 类型增补不安装设施或授予操作权限。本期可获取的设施为 command／files；其他键可声明查询，但获取需求遇到未知键明确 unsupportedFacility，不交原始对象。未来设施定义拥有者须同时提供运行时验证、逐操作授权适配和契约验证，之后才能扩展实际获取路径；不能只凭同名字段或 cast 获得能力。

EE-18 文件路径按环境实例解释，不把 cwd 当安全隔离。读／写字节独立持有，大小界限由实现配置；部分写入或回执未知如实报告 effectUnknown，不自动重试。lease 释放或观察者离开不能宣称外部文件作用已撤销。

以下EE-19/20沿2026-10-06用户PR2实施授权，经选择及表达无剩余阻断后技术采用；实现与验证状态另记，不据规格存在宣称完成。

EE-19 resolvePlacement 只读同一租户／会话／原call的当前求值，不授设施或资源许可。调用前后核当前access及原source；notApplicable不伪造placement。读取与acquire不是原子事务，后者必须重读和核对实际requirement；旧读取不能固定未来权限。

查询不适用唯一返回kind:notApplicable，不返回rejected(reason:notApplicable)。调用参数或合法求值输入的形状非法返回invalidInput；前后授权失败保留原原因；读取前无来源或来源读取抛错为policyUnavailable；在途原来源撤除／换代为placementChanged。来源placement回执无法捕获或不对应原scope/call也为placementChanged。其他来源拒绝沿EE-11的合法拒绝值返回。acquire的不适用仍沿原rejected编码，此查询规范不更改它。

EE-20 provider成功仍是原始回执。registry最终核验原source代、placement和选中description后构造EnvironmentAdoption；provider evidence不作为自签权限。公开capture只验证普通数据及内部归属／匹配关系，不证明其来自registry。记录或重读adoption不恢复JS lease，也不重授旧许可；调用者必须保留原租约直至耐久采用确认或原释放/清理责任完成。
