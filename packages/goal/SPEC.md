# Goal

## 总体架构

Goal 包组回答一个问题：一个会话上的一份有限委托，怎样说清「做到什么算完、怎样量、什么时候停」，agent 自己推进时怎样知道还差多少，它想收工时由谁判、判完走哪条路。

它是接在核心系统上的一套插件。核心域（Session、Agent、Model、Tool、Runtime Context、Request Context）的成员都不依赖它；去掉它，核心原有的流程不变，只是会话没有目标，agent 手里没有工具 `Goal`。

| 成员 | 回答的问题 |
| --- | --- |
| `goal-contract` | 目标的纯契约：正文的数据形状、状态、事件、结局、读数与进展清单的值，以及全部纯决定（校验、渲染、转移、差距表、材料打包、出题、读答案）。只依赖 zod |
| `goal` | 目标的定义拥有者：目标的登记、推进与对账、仓储的端口与事务脚本。只依赖契约 |
| `goal-cordis-contract` | 服务定义：目标的服务面在 Cordis 里叫什么 |
| `goal-local` | 本地提供者：SQL 仓储、配置、对账的扫描与唤醒、生命周期 |
| `goal-session` | 认识会话的适配成员：登记三个输入来源；以系统主体送输入；读会话安静不安静、读被引用的工具结果原文 |
| `goal-check` | 认识 Agent 与拓展件的适配成员：内建的终态前扩展，与压缩之后的提醒 |
| `goal-decisions` | 认识 Model 的适配成员：发一次决策调用，认回它的结果 |
| `goal-command` | 认识命令的适配成员：一个官方的入口来源，交出 `/goal` |
| `goal-tools` | 给 agent 的多命令工具 `Goal` |
| `goal-protocol`、`goal-access`、`goal-ui` | 对客户端开放：读目标与差距表；人的设、改、暂停、恢复、取消、照退出收场；目标面板 |
| `goal-bench` | 判定的评测台：用例、重放、打分与报告。不进发行 |

一个目标这样走：人用自己的话说，会话里的 agent 起草正文并调 `Goal` 的 `propose`；工具出一张确认卡片；人确认，目标成立；agent 干活，维护进展清单；它每次想收工，`goal-check` 打包材料、发一次决策调用，转移函数算出下一步：收场、暂停交给人，或否决这次收工并送一条提醒让它接着干。

## 领域边界

本组拥有：目标的正文、修订与来历；目标的状态与结局；读数与差距表；进展清单；判定的材料、题目与答案的解释；续轮的计数；工具 `Goal`；`/goal` 这条命令的提示词。

本组不拥有：

| 事 | 归谁 |
| --- | --- |
| 一轮开不开、怎样受理输入、会话日志 | Session |
| 一轮之内怎样推进、终态前位置、步数上限 | Agent |
| 决策调用的发出、登记、记账与结果保管 | Model |
| 确认卡片的形状、保存、等人的等待、答复 | 人工介入 |
| 斜杠怎样被认出来、清单怎样合成 | 命令 |
| 许不许做一个动作 | 身份与授权。目标不授予任何权限 |
| 什么时候再触发一次工作 | 日程。目标是一次有限的委托，不是持续的责任 |

会话不认识目标。目标的事实存在本组自己的存储里，按引用指到会话；本组不写会话的日志，要会话做的事都经会话公开的操作。会话日志里只有它本来就记的两样：终态前那一次经过的记录，和被受理的系统提醒。

本组声明、由别人实现的端口：读一个会话的工作快照；按引用读一次工具调用的结果；送一条系统提醒；发一次决策调用；出一张问询卡并读回答复。

## 心智模型

目标的正文对干活的 agent 同时是三样东西。约定：做到什么算完，什么时候可以停。目标函数：每条判据带着怎样量，所以 agent 随时读得出还差多少。上下文地图：权威的材料在哪，上下文丢了从哪捡回来。它不是计划，不是进度，不是权限。

一份目标有一个主人。有人值守的会话里，主人是会话里的那个人；无人值守的会话里，主人是建这个会话的一方。凡是改变这份委托的事，都要追得到主人的一个动作。agent 能看、能起草、能记进展，别的都不能。

判定分两半。判定器只观察：每条判据成立没有，每条退出的情形出现没有。下一步怎么走由一个纯函数算。规则放在函数里，模型改不了。

最容易想错的几处：目标决定何时算完，不决定何时再触发，也不决定能做什么；agent 的进展清单是说法，不是证据；判定让目标停下不等于失败，有人值守时是交给人；暂停目标不停当前这一轮，停一轮是另一个动作。

## 应然设计

### 正文

- 目标存成一份有类型的数据。人与 agent 读到的文本由它渲染，渲染是带版本的确定函数；不从文本解析回数据。
- 正文七节：目的、达成、指标、守则、退出、依据、做法。目的与达成必填。达成、指标、守则、退出、依据的每一条有编号，编号由本组发：新加的取下一个号，删掉的号不再用。
- 一条达成判据写明证据从哪来（命令、文件、指标、人确认之一），可以写明证据要显示出什么才算数。指标写明量法（命令与取值路径）、方向、目标，可以有底线与基线。退出的种类是预算、够用、条件、要人定之一，每条写明收场时交什么、算成功还是失败。
- 渲染出来的正文至多 4000 个字符，按 Unicode 码点数。
- 校验不过的正文不成立，答复写明是哪一条的哪个字段。「够用」只能凭已有的达成判据与指标底线算成功。无人值守的会话里证据不能是人确认。退出里没有预算时补一条缺省的。
- 修订是一组按编号的改动。没被点到的条目原样保留。每次修订得到新的修订号，已用的轮数与用量不清零。每个修订留着来历：人的原话、起草者、确认者与时刻。

### 设与改

- 进到「设」只有两条路。协商：会话里的 agent 起草，人在确认卡片上确认。直接：建会话的一方带着自己对这个会话的资格，交来一份合格的正文；人在目标面板上改字段也走这条。
- 确认卡片是人工介入的问询卡，来源是工具。确认是一个选项；人不选选项而提交原话，是要改，原话交回 agent；另一个选项或跳过是不设。
- 写下一个修订要凭一张已答的卡片：答的人是这个会话的成员；卡上的内容摘要等于要写下的数据；卡片起草时照的修订号等于现在的修订号。一张卡只生效一次。卡片由它的拥有者那里读，不取调用方交来的说法。
- 凭卡写下时不给会话送提醒：提议的 agent 正在自己的一轮里，从工具的结果读到已生效。直接入口设下目标时经 `goal.start` 叫醒会话。
- 设目标不改会话的协作模式。目标进行中时，终态前的检查在两种协作模式下都成立。`auto-drive` 的会话里没有目标时，以触发这一轮的那段输入为目的，判据只有一条「这段输入要的事做完了」，用缺省的预算。
- 无人值守的会话里正文冻结，到目标收场为止。

### 状态

状态四个：没有目标、进行中、已暂停、已收场。一个会话同时至多一个没收场的目标。

| 事件 | 谁能发 |
| --- | --- |
| 设、修订、暂停、恢复、取消、照某条退出收场 | 有人值守的会话里的人 |
| 设、取消、中止 | 无人值守的会话的建立者 |
| 观察 | 终态前的检查 |

agent 的工具调用不产生事件。全化表：

| 状态 \ 事件 | 设 | 修订 | 暂停 | 恢复 | 取消 | 照退出收场 | 观察 | 中止 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 没有目标 | 进行中 | 拒绝 | 拒绝 | 拒绝 | 幂等 | 拒绝 | 不变，放行 | 幂等 |
| 进行中 | 拒绝 | 修订号加一 | 已暂停 | 幂等 | 已收场 | 拒绝 | 照裁决表 | 已收场 |
| 已暂停 | 拒绝 | 修订号加一；由确认卡片来的同时恢复 | 幂等 | 进行中 | 已收场 | 暂停的原因是这条退出时已收场，否则拒绝 | 不变，放行 | 已收场 |
| 已收场 | 进行中，新的目标 | 拒绝 | 拒绝 | 拒绝 | 幂等 | 拒绝 | 不变，放行 | 幂等 |

观察带着它开始时的目标、修订号与轮数。与当前的不同时，状态不变，这次收工不放行，按当前的状态重新观察。

### 判定

- 判定只在一轮提出完成候选时发生。取消不经过它。失败候选只观察、放行。
- 材料三层：正文的目的、达成、指标、守则、退出；agent 的进展清单；本组从会话取的证据与自己算的事实。依据与做法不给判定器。材料有总量上限，不随会话变长。
- 进展清单的证据只能是引用，指到本会话里、目标设下之后的一次工具调用。本组取出被引用的原文交给判定器，并补上 agent 没提的：声明的命令有更新的一次运行而结果不同；引用之后又有写文件的调用；目标设下以来写过的路径；判据用到的命令、测试或基准被改过。这些是事实，不预设对错。
- 判定是一次决策调用。每条达成判据、每条守则各是一道选择题，「条件」与「要人定」的退出各是一道是非题，另有一组题问有没有未声明的不可达。本组能直接定的不出题：指标的数、写明看退出码的判据、预算、停滞。
- 一条判据算成立，要选中的是「成立」且概率不低于一条线。概率不够或这一题被拒答，按判不了算，不按成立算。
- 判定用的决策型号是一个设置项，缺省 `openai/gpt-6-luna-decisions`，下一次判定起生效。
- 决策调用失败时本组不重发同一个请求；另起新的请求，至多两次。

裁决表，按次序第一条命中的为准：

| # | 条件 | 有人值守 | 无人值守 |
| --- | --- | --- | --- |
| 1 | 每条判据成立，每个指标到目标，没有守则被违反 | 已收场：达成 | 同左 |
| 2 | 预算到了，某条「够用」凭的都成立 | 已收场：那条退出 | 同左 |
| 3 | 预算到了 | 已收场：预算那条退出 | 同左 |
| 4 | 某条「条件」退出成立 | 已收场：那条退出 | 同左 |
| 5 | 某条「要人定」退出成立 | 已暂停 | 已收场：那条退出 |
| 6 | 未声明的不可达：阻碍的那一题过线，进展清单指到了查得到的调用，试过的那一题过线 | 已暂停 | 已收场：无法达成 |
| 7 | 连续几次观察差距都没有变近 | 已暂停 | 已收场：停滞 |
| 8 | 判定始终答不出 | 已暂停 | 已收场：判定不可用 |
| 9 | 其余 | 进行中，轮数加一，续轮 | 同左 |

「算成功」只来自达成，或正文里写了算成功的退出。无法达成、停滞、判定不可用、执行中止算失败。被取消不算成功也不算失败。

### 续轮与读数

- 续轮是两样一起：否决这次完成候选；经输入来源 `goal.continue` 给会话送一条系统提醒，写明差距表里没合上的几行。这一轮不结束，不开新的一轮。
- 先在本组的存储里按「目标、修订号、轮数」记下这一轮，再送提醒，输入的身份取这个三元组；会话对同一个身份只受理一次。记下了而受理的结果不知道时，按同一个身份再送，不另计一轮。
- 修订改了或删了一条判据、指标或守则，它的读数作废；没被点到的条目读数留着。
- 读数有三个来源：本组跟着工具结果读的（agent 每跑一次声明的命令）；判定的观察；agent 在进展清单里的自述。差距表按编号列出应然、最近的读数、来源与还差多少。agent 经 `Goal show` 随时读它，人在目标面板上读它，续轮的提醒取它没合上的几行。
- 上下文被压缩之后，本组给 agent 送一条提醒：目的、依据一节、差距表里没合上的几行。
- 暂停着时不判、不续，终态前的检查放行；后台结果照常送达，不让目标恢复。恢复时会话没有在跑的一轮，经 `goal.resume` 叫醒它。
- 判定让目标暂停时，这一轮正常完成，本组告诉人为什么停下、还差哪几行。

### 工具 `Goal` 与命令

- 一个多命令工具，只对着调用它的这个会话，命令不带会话参数。`show` 读目标、差距表与进展清单；`propose` 交一份正文或一组改动，出确认卡片；`track` 维护进展清单。`propose` 只在有人值守的会话里提供。
- `/goal` 是一条提示词命令，由本组的官方入口来源交出。它的提示词与 `Goal` 的用法是同一份文字，只讲人要什么与通常怎样做有效，不规定步骤。
- 暂停、恢复、取消不经过模型。

### 判定的评测

- 判定的题目怎样写、材料怎样打包、怎样切请求、线画在哪、用哪个型号，由评测台上的数定，不凭感觉。
- 一个用例是一份冻结的判定输入，加每个编号该答哪一项与哪些答了也算安全。输入由生产上同一个打包函数生成。用例从每条判据都真成立的母本改出，每个只改一处。
- 两道门槛不拿别的指标去换：该答不成立的编号里答了成立的比例；子例里被改的那一条比它在母本里少答了多少成立。
- 用例按母本分开，一份用来调，一份只用来验，另留一份永不参与调。

### 提供者与生命周期

目标的事实只在本组的存储里，运行着的对象不另存。重启之后状态不变，下一次完成候选照常判。每次转移是带修订号的一次条件写，写成了才做动作。

一次转移要给会话送提醒时，这笔欠着的提醒与转移在同一次提交里记下，送到了才销账。送的结果不知道时留着，由对账按同一个身份再送；会话已经不收输入时销账，不再送。

## 原则与约束

- 结果不知道就是不知道：记一轮、送提醒、发决策调用，都按原来的那次操作认回。
- 目标的规则只有一份，人的入口与 agent 的工具都调它。
- 判定器的答复里没有状态，也没有动作。
- 目标不改会话的规则，不改 Agent 的终态规则：它只在已有的位置上答放行或否决。

## 不变式

| 编号 | 性质 | 违反了会怎样 | 由什么守 |
| --- | --- | --- | --- |
| GL-1 | 一个会话同时至多一个没收场的目标 | 两个目标抢同一次收工 | 存储的唯一约束；契约测试 |
| GL-2 | 结局只落一次，落下之后不变 | 报了达成又改口 | 模型 `Goal` 的 `SettledOnce`、`OutcomeMatches` |
| GL-3 | 落「达成」的观察是当期修订 | 旧证据把新目标判成达成 | 模型 `Goal` 的 `AchievedIsFresh` |
| GL-4 | 「算成功」只来自达成或写了算成功的退出 | 失败被说成成功 | `goal-contract` 的转移用例 |
| GL-5 | 目标进行中时，完成候选不会不经裁决就放行 | 目标没完，这一轮却完成了 | 模型 `Goal` 的 `NoSilentPass` |
| GL-6 | 同一轮只计一次，同一条提醒只受理一次 | 重放多算一轮 | 模型 `Goal` 的 `CountedOnce` |
| GL-7 | 轮数不超过预算 | 无限续跑 | 模型 `Goal` 的 `RoundsBounded` |
| GL-8 | 无人值守的会话里目标不会被暂停 | 作业永远不收场 | 模型 `Goal` 的 `NoPauseUnattended` |
| GL-9 | 每次状态变化都追得到主人的动作、裁决表的一行或会话建立者的调用，没有一次来自 agent 的工具调用 | agent 给自己松绑 | 模型 `Goal` 的 `NeverByAgent`；工具的契约测试 |
| GL-10 | 过期的确认卡片不生效 | 拿旧的确认改新的目标 | 模型 `Goal` 的 `CardIsCurrent` |
| GL-11 | 判定的材料总量有上限，与会话的长短无关 | 判定的花费随会话变长 | `goal-contract` 的打包用例 |
| GL-12 | 概率不够或被拒答的一题不算成立 | 拿不准的被当成做完了 | `goal-contract` 的读答案用例；评测台的门槛 |

模型的范围与没有覆盖的东西写在 [`goal/verification/models.json`](goal/verification/models.json)，对应关系见 [`formal-mapping.md`](goal/verification/formal-mapping.md)。
