# 内部架构

本文件说明本包怎样兑现 [SPEC.md](../SPEC.md)：包内模块划分、依赖方向、状态与资源归属、关键机制及设计理由。它引用组级与系统级约束，不另立公共规则。

## 模块与依赖

| 模块                                                  | 职责                                                                                                          | 依赖                                                                             |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| [src/index.ts](../src/index.ts)                       | 公开根：`createDirectorySource` 与 `DirectoryFs` 类型                                                         | 下面两个模块                                                                     |
| [src/directory-source.ts](../src/directory-source.ts) | 把定位分派到遍历或读条目；把遍历结果交给 `sealSnapshot`；把快照缺陷映射为来源失败                             | `walk.ts`、`fs.ts`、`@omne-harness/skill-contract/provider`                      |
| [src/walk.ts](../src/walk.ts)                         | 解析根、递归遍历、解析每个条目、根内判定、访问预算、严格 UTF-8 解码，以及全部分类表；`collect` 与 `readEntry` | `fs.ts` 的类型、`@omne-harness/skill-contract`、`@omne-harness/operation-result` |
| [src/fs.ts](../src/fs.ts)                             | `DirectoryFs` 接缝与默认接缝 `nodeFs`。只做读取，不分类                                                       | `node:fs/promises`                                                               |

依赖只向下：`directory-source.ts` → `walk.ts` → `fs.ts`。本包只依赖 Skill 契约与 `operation-result`，不认识 `@omne-harness/skill` 或任何调用方。

本包没有长期状态。一次 `collect` 调用持有一份遍历状态 `Walk`：已读文件列表与访问计数。只有 `collect` 建它，调用返回之前外面看不到它。默认接缝每读一个文件就打开并关闭一个文件句柄。

## 关键机制与理由

- **文件系统接缝只做读取。**来源只经四个读操作访问文件系统。理由：容器内测试以 root 运行，`chmod` 造不出 `EACCES`。接缝让权限类失败可以在任何用户下测试。接缝以字节交出名字与解析后的路径，并报告打开的对象是什么种类。它不决定任何答复，所以注入的接缝与默认接缝履行同一份契约。测试替身直接包装默认接缝。
- **分类一处决定。**`walk.ts` 里有四张 code 表：根（`ROOT`）、条目解析（`RESOLVE`）、包内读（`READ`）与 `open`（`OPEN`）。另有两张种类表，决定打开的对象不是普通文件时答什么。「表外的 code 答 `unavailable`」与「不带 `code` 的错误原样抛出」也在这里。不带 `code` 的错误说明接缝或来源有缺陷，收束成来源失败会把缺陷变成普通答复（见[防御指导 DP-01](../../../../docs/defensive-patterns.md#dp-01-独立事实分别报告)）。
- **严格 UTF-8。**名字在文件系统上是字节。有损解码会把不是 UTF-8 的名字变成另一个名字，再读时得到 `ENOENT`，永久的包缺陷就成了「此刻不可达」。来源用 `TextDecoder` 的 `fatal` 模式解码名字与解析后的路径，并保留开头的 BOM，使解码出的字符串编码回去仍是原来的字节。
- **每个条目同一路径。**来源不按列出时报告的种类分叉。列出与读取之间，条目可能被换成指向根外的链接。按列出的种类直接读文件会跟随这个链接，借来源之手读出根外字节。所以每个条目都先 `realpath`、再核对在根内、再 `lstat` 读种类。读文件时不跟随最后一段的链接，核对之后被换成链接的文件得到 `ELOOP`。残余窗口见 [SPEC](../SPEC.md#residual-window)。
- **悬空与消失分开。**解析得到 `ENOENT` 时，来源 `lstat` 条目自己：还在就是悬空的链接（包的缺陷），不在就是列出之后消失（正在修改）。
- **根内判定按整段比较。**`isWithin` 把两个路径按分隔符切开再逐段比较。字符串前缀比较会把根 `/x/pkg` 的兄弟 `/x/pkg-sibling` 当成根内。`snapshot` 与 `open` 共用这一个函数。
- **根先解析，根名一处核对。**根自己是链接时，根内判定与根名都以解析后的目录为准。`resolveRoot` 是根名为空的唯一核对处，所以 `sealSnapshot` 的 `invalid-root-name` 是不可达的缺陷，来源以错误拒绝它。
- **成环检测。**每个遍历位置记下从根到它的解析后目录。解析结果是其中之一时答 `entry-unreadable`。实际路径有限，所以无限下降必然重访这条路径上的某个目录，检测因此完整。
- **访问预算。**不成环的链接仍能使访问次数指数增长。一次遍历最多访问 65536 个名字，超出答 `entry-unreadable`。这个数由领域设计裁定。
- **确定的第一个失败。**遍历深度优先，每个目录按名字的码元序。文件系统列出名字的次序不固定，排序使多处缺陷的包总是得到同一个答复。
- **非阻塞读。**默认接缝以 `O_NONBLOCK` 打开文件并读打开对象的种类。列出之后被换成管道的文件不会使读取等待写者。
- **没有类与类型断言。**接缝、来源与遍历位置都是对象字面量与函数。品牌值只经契约的守卫取得：包内路径经 `isPackagePath`，快照经 `sealSnapshot`。
