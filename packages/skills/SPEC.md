# Skill

## 总体架构

Skill 包组回答一个问题：一个目录是不是一个合法的 Skill，以及怎样把它按三层披露读给一个主体，读到的每一段都能说清来自哪一份材料。一个 Skill 是一个目录，入口是 `SKILL.md`，还可以有参考资料、模板与脚本；第一层是名字与一句说明，第二层是 `SKILL.md` 的正文，第三层是目录里别的文件。

| 成员                    | 回答的问题                                                                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skill-contract`        | 值与守卫、快照与内容摘要、包的检查规则与拒绝次序、读取的形状规则、需求端口的要求、`skill` 类别端口，以及端口与服务的符合性套件。纯数据与纯函数，不依赖 Cordis |
| `skill`                 | 目录（摘要与检索）与读取怎样经端口编排：先核读取权，再核对应的材料，再按内容摘要钉住字节。检索的排序用共同成员 `text-search`。不依赖 Cordis，没有状态         |
| `skill-cordis-contract` | Skill 在这套系统里以哪些服务出现：目录与读取两个服务的定义与键。本组不带插件，提供者是装配方                                                                  |
| `skill-host-local`      | 本机目录与已发布的包作为包来源：怎样取一致的快照、读一个条目、说出包在本机的目录，并守住包根；两个判定端口怎样绑定到资产的候选求值                            |

依赖只朝契约：`skill`、`skill-host-local`、`skill-cordis-contract` 都只依赖 `skill-contract`；`skill-host-local` 与 `skill-contract` 另外只认资产的契约，不认资产的本机成员；`skill` 另外只认共同成员 `text-search`。工作时，来源一侧经检查确认一个目录是合法的 Skill 包，资产记下它的声明投影与快照的内容摘要；读者经目录得到此刻合法可用、能读的 Skill 的摘要，再经读取服务读正文或按包内路径读一个资源。每次读取都现场核读取权、现场解析对应的材料，按快照与条目的内容摘要核对字节。agent 经 `Skills` 这一个入口使用 Skill。

## 领域边界

Skill 拥有：一个目录是不是合法的 Skill（包格式、拒绝次序、兼容提示）；快照与内容摘要；从包到资产正文的声明投影；三层的读取与列目录，以及读取结果带的材料依据与本机目录；目录的过滤与检索规则；提交一个目录之前的大小、校验与同名说明。

Skill 不拥有：一个身份此刻对应哪一份材料、哪些身份合法可用、同名的几份听谁的（资产与装配）；主体能不能读（身份与授权）；常驻哪些简介、怎样排序与呈现（会话与 Agent 的采用点）；读出的内容怎样保存与组装（接收方）；脚本怎样运行（Shell 的一次普通工具调用，归工具执行与执行环境）；发布本身（资产）。Skill 没有设置：它不声明设置，也不接受配值。

本组只认通用角色：主体（`Access<P>` 的类型参数）、作用域（调用方给出，不解释）、来源层（端口交来，原样带回）。它不认识会话、工作区、租户层这些调用方体系的词，也不认识材料来自官方、组织、租户还是工作区。

本组声明、由别人实现的端口：

| 端口                 | 对方                                                       | 本组需要它做什么                                                                                           |
| -------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `SkillResolution`    | 资产求值与装配                                             | 答这个能力标识此刻对这个主体合法对应哪一份材料（含包定位与内容摘要），带依据时依据是否合法；答当前合法集合 |
| `SkillReadCheck`     | 身份与授权                                                 | 答这个主体此刻能不能读这个能力标识                                                                         |
| `SkillPackageSource` | 包来源：本组 `skill-host-local` 的本机目录；内容存储归资产 | 按包定位交出一致的快照；按包定位、内容摘要与包内路径交出一个条目的字节；包放在本机目录时说出这个目录       |

本组为别人实现的端口：

| 端口                                    | 对方                            | 本组提供什么                                               |
| --------------------------------------- | ------------------------------- | ---------------------------------------------------------- |
| 类别端口 `BodyContract`（类别 `skill`） | 资产（`packages/assets`）       | 资产正文的判定、包的命名空间与上限、目录的检查（`layout`） |
| `SkillCatalog`、`SkillAccess`           | 读者（`Skills` 入口与独立程序） | 摘要与检索；读取与列目录                                   |
| 服务键 `skillCatalog`、`skillAccess`    | Cordis 装配                     | 两个服务的定义；装配方按自己的租户与存储提供它们           |

## 心智模型

把一个 Skill 想成一本放在架子上的说明书：目录里的文件是书页，快照是给这本书拍的一张不变的照片，内容摘要是照片的指纹。读者先按目录看书名与一句说明，决定要用时读正文，正文指到哪页再翻哪页。Skill 不是工具：它没有参数契约，没有执行体，读一次就是一次返回，系统不记「已启用」。

每次读都是一次独立的问询：此刻你能不能读、此刻这个名字对应哪一本、这本的照片与架子上现在的书还是不是同一本。读者想固定在某一版时，带回上次读到的材料依据；依据只指明要哪一份材料，不授予访问，也不指定位置。

最容易想错的几处：读到脚本不等于能运行它，运行归 Shell，Shell 的许可不因脚本来自 Skill 而放宽或收紧；依赖不齐不挡读正文；无权与不存在对无权主体不可区分；未知不压成空，也不压成拒绝；旧正文与新资源不能拼成一次成功。

## 应然设计

### 包与检查

- 包格式按官方 Agent Skills 规格的 `SKILL.md`，加可选的 `.omne/skill.json`。两者是控制文件，不是资源。
- 检查从来源取一次一致的快照，再解析与校验；不逐文件拼包。检查的结果只有三类：定义、一个拒绝原因、来源失败（`source-unavailable` 或 `version-changed`）。拒绝的包不折成替换件，也不当作空包。拒绝带给包作者看的说明，调用方不据它分支。
- 拒绝原因按固定次序取第一个；同一个包违反几条规则时，先读完全部可读的部分，再取次序最前的一条。次序是：缺 `SKILL.md`、名字不符、声明格式版本不受支持、包外、工具引用无效、格式错。来源在快照阶段答条目不可读或落在包外时，检查以对应的原因结束；包外只来自来源的快照阶段，解析字节本身不产生它。
- 社区与主流宿主接受、原生格式拒绝的几种写法，检查接受并逐项给出兼容提示：头部 YAML 读不出但能逐行读出名字与说明；说明超过 1024 个字符；`metadata` 不是文本映射；名字与包根目录名不同。兼容提示是结果里的数据，不是日志。真正读不了的包仍然拒绝，拒绝原因的集合不因放宽而变。
- 头部按 YAML 1.2 core schema 解析，重复键是解析错误，不强转类型，不认识的字段原样保留、不解释；`allowed-tools` 只是元数据，不授予任何许可。正文保留原字，Skill 不展开占位符，不解释 Markdown。
- 包的身份以头部的名字为准；只有调用方给出期望名字而名字不等于它时，才拒绝为名字不符。目录名不授予身份。
- `.omne/skill.json` 严格读取：注释、尾逗号、空输入、重名键、超出预算都整份拒绝；不填缺省值，不删字段。它只声明依赖（必需的工具），别的字段一律按多出的字段拒绝为格式错，写了 `scripts` 或 `settings` 也一样。Skill 不声明设置、脚本的运行方式、设施与落点，不向 agent 或脚本供给任何值；agent 用了一个 Skill 之后怎样做，写在正文与包里的文件中。脚本是包里的普通文件，和别的资源一样读得到、列得到，由 Shell 运行。
- 包内容不决定常驻、调用面开关、模型选择或预先批准；文件执行位不进入定义的含义。

### 快照与内容摘要

- 快照只能由契约的纯函数构造，来源交出快照时必须用它；同一进程内的登记是快照的凭证，复制出来的值不是快照，快照不能跨进程传递。构造时拒绝空的或含 `/` 的包根名、重复路径与文件与目录的前缀冲突。
- 构造快照有两个入口。`sealSnapshot` 收每个文件的全部字节，用 `packageEntryOf` 从字节算出每个条目的大小、内容摘要、媒体类型与文本或二进制的标记，再交给 `sealEntries`。`sealEntries` 从清单的条目封快照，不收字节，快照的内容摘要由条目重算，所以存下来的清单只核对，不必信任。同一组文件经两个入口封出的快照逐字段相同。一次读一个文件的来源可以自己算条目再调 `sealEntries`，不必把整包放进内存。
- 条目的内容摘要是原字节的 SHA-256；快照的内容摘要只由排序后的包内路径与条目内容摘要算出，包根名不进入，条目的输入次序不影响它。内容摘要相同的两个快照指同一份内容。条目摘要与包摘要的算法归资产（`digestBytes` 与 `packageDigest`），本组导入它们，不另写一份，所以快照的内容摘要就是资产里这个包的摘要，也就是已发布版本的版本号。
- 资源按规范化的包内相对路径寻址：拒绝绝对路径、`..` 段、反斜杠、空段与控制字符。媒体类型按扩展名、再按开头字节推断，扩展名优先；推断不出时缺席，缺席不表示文本。

### 资产正文

- `skill` 资产正文是包的声明投影：名字、说明、必需的工具与快照的内容摘要。正文由纯函数从检查结果派生，内容摘要把正文与包字节对上。
- 名字必须合 Skill 名字的词法。
- 说明的上限（16384 个字符）在检查、资产正文、声明投影与读取的边界上是同一个；读取资产正文的一方给出的字符串预算不能小于它的两倍码元。
- 判断的次序是：正文或名字为空，名字与能力名不符，名字不合词法，工具引用。正文的其他顶层字段不判断，所以已发布版本的记录附带的包清单不影响判断。
- `skill` 正文不派生设置声明项，也不带设置的钩子，所以 Skill 的持有不是设置目标。
- 正文是目录，所以类别端口交出 `layout`：命名空间 `skills`；包的上限是 200 个文件、单个文件 1 MiB、整包 8 MiB（`SKILL_PACKAGE_LIMITS`）。`inspect` 经资产的读口取清单，按清单的路径与摘要读出每个文件并核对摘要，封成快照，再用上面的检查规则检查，合法时投影出资产正文。清单里的路径不是包内路径时拒绝为包不合法（坏路径）；检查的拒绝原因原样放进包不合法的原因；读口失败与摘要对不上答读口失败。读口不给目录名，包根名固定为 `package`，只供检查，不进摘要；期望名字不在这里核，资产发布时由 `judge` 核名字与能力名一致。
- 类别端口交出资产简介的算法：标题是名字，一句说明是正文的说明，事实两条，文件数与必需的工具。它只读资产正文，不读包的字节。Skill 经资产的通用入口新建，方式是传一个目录。

### 目录

- 目录只在端口给出的当前合法集合里取；先按请求的身份过滤或按查询匹配，再只对留下的身份核读取权，只交准许的身份。被拒的身份不出现，也不说明原因；留下的身份中任一个答未知，整次答未知。请求之外与不匹配的身份不核验。
- 空的身份请求答空列表，不问任何端口；合法集合为空答空列表，不是失败。
- 检索按共同成员 `text-search` 的分词与 BM25，文档是名字与说明，参数 `k1`、`b` 由装配给出。空查询匹配全部、按名字排；有查询只留与查询有共同词的身份（就是得分大于零的），只对它们核读取权，再在获准的身份里打分，按得分降序，同分按名字。语料只含获准的身份，读者读不到的身份不改变它看到的次序。检索的次序承载相关度；摘要的次序不承载含义。
- 同一输入得到同一输出；答复不随读取判定的完成次序变化。合法集合里同一能力标识出现多次时只保留第一条，只核验一次。
- 合法已知但此刻不可用的身份作为替换件出现，带最后合法的名字、说明与可以向该主体说明的安全原因；从未合法取得的身份不出现。目录不判定依赖在不在场，不按常驻筛选。

### 读取

- 每个操作都现场核验，不用缓存或此前的成功代替：先比对依据的能力标识与目标（不等即答无权，不问端口），再核读取权，再解析对应的材料。包定位只取自对应端口当场交来的内部引用，内部引用不交给调用方。
- 内容库定位带一个不透明的引用 `ref`，由内容库给出：Skill 不解释它，原样交回内容库。
- 端口交来的引用必须指向所请求的身份；带依据时还必须与依据的来源层、资产版本与内容摘要一致。不合即当作端口没有作答，答未知，不调用来源。
- 读取与列目录先钉住材料：带依据时钉依据所指的材料，不带依据时钉对应端口交来的材料；资产正文没有内容摘要而不带依据时答不支持。
- 快照的内容摘要不等于所钉材料的：带依据答依据不可用，不带依据答已采用的材料已变。读出条目字节后按条目内容摘要核对，不符答版本已变，不交新内容。
- 带同一依据的各页都对同一个快照核对，所以分页不会拼成两个版本；不带依据的各页可能读到不同的合法版本，每页如实标出它读的版本。
- 每页最多 64 KiB；文本按字符边界截取，实际范围如实写出，`complete` 当且仅当这一页之后没有剩余字节。部分结果不是失败。正文的字节范围从正文起点算起，起点由定界行决定；没有合法定界的正文答来源不可用。非法范围是调用方的错误，在问任何端口之前抛出 `TypeError`。
- 读取交出文本或字节，内容块的组装归接收方。按资源路径请求控制文件是坏路径；路径解析后落在包外答包外，不用别的包补齐缺失的资源。
- 读取与列目录的结果带这个版本的包在本机的目录：钉住材料之后问来源，与读到的字节是同一份材料。来源说这套装配不把包放在本机目录时，结果不带目录；来源答不出时整次答来源不可用。目录只告诉读者包在哪，不授予读写它的许可，也不改变读取的核验。
- 读取与列目录在每次调用端口之前与之后都检查调用方的中止信号；已中止就答中止，不再调用端口，不交部分内容。端口收不到信号，已发出的端口调用由端口跑完。
- 依赖不齐不挡读取：Skill 合法选入、主体能读、正文来源正常时，正文照常返回，缺什么写在结果里。读取资格失效时不交原内容。
- 失败是封闭集合：无权、替换件、坏路径、包外、资源缺失、依据不可用、已采用的材料已变、版本已变、来源不可用、不支持、中止、未知。没有开放的「其他」。

### 端口答复

- 服务在边界上把每个端口答复完整解析一次，判别值与载荷都核对，只认自有属性，重新构造并冻结。端口 reject、同步抛出、答复不合或读取答复时抛出，都算端口没有作答：判定端口当作未知，来源当作此刻不可用。服务不因端口违约而抛出。
- 来源失败到服务失败只有一张映射表，按操作与调用点分格；快照阶段答条目缺失或字节不符的来源不守契约，当作此刻不可用。
- 对无权主体，对应端口与读取判定的答复不随身份是否存在而变；不可用的原因只能是可以向该主体说明的文字，不含秘密。

### 本机目录来源

- 本机来源只认目录定位，按内容摘要的定位答找不到包。每次快照都读当前目录，没有索引与缓存；进程重启不改变判定。
- 包根先经 `realpath` 解析；一个路径在根内，当且仅当它按路径分隔符整段以根的各段开头。条目或链接解析后落在根外，整个包不可读。
- 名字按严格 UTF-8 解码；悬空链接、成环、设备、管道与套接字答条目不可读；一次遍历的访问次数有上界；遍历按名字的码元序深度优先，遇到第一个失败就停，所以多处缺陷的答复不随列出次序变。
- 读文件不跟随最后一段的链接，不等写者。快照不是原子的：读取时按条目内容摘要核对字节。来源只读文件系统，没有外部效果，不持有资源。
- 它说出的本机目录就是 `realpath` 之后的包根。
- 目录来源留给读 agent 写的目录与官方的夹具目录；已发布的包走内容库来源。

### 内容库来源

- 内容库来源是 `{ kind: 'content-store', digest, ref }` 定位的来源，经资产的读口读已发布的包。它只认资产的契约，不导入资产的本机成员：装配把「给出一个包的读口」的函数交给它，接本机成员时 `ref` 就是资产引用。目录定位不是它的包，答找不到包。
- 取快照先取清单，再按清单逐个文件读出字节，算出条目，封快照，不把整包放在内存里。清单里的路径不是包内路径，或封快照被拒，答条目不可读。快照的内容摘要由条目重算，必须等于定位里的摘要，否则答字节不符：存下来的清单只核对，不信任。包根名取摘要。
- 一个包摘要只对应一份内容，所以一个摘要的快照不变。来源封好之后按摘要记住它，之后取快照不再读文件，读条目只读它要的那一个文件。记住的只有快照，没有字节，进程内有效，至多 256 个；超出时丢掉最久没用到的，它下次用到时重新封。
- 读条目时，所给摘要不等于定位里的摘要答找不到包，快照里没有这个路径答条目不存在，然后按清单里的路径与摘要从读口读一个文件。读口的失败这样映射：包不存在对包不存在，条目不存在对条目不存在，材料不可用（字节与清单对不上）对字节不符，不可用对不可用。
- 装配另交「说出一个包在本机的目录」的函数，接本机成员时它就是资产的 `locate`：给出目录、说这套装配没有本机目录，或答不可用。

### 判定端口的绑定

- 两个判定端口（`SkillResolution` 与 `SkillReadCheck`）可以绑定到资产的候选求值。装配给四个输入：一个能力身份各层的同名候选（从最宽到最具体，例如官方层的候选清单、租户层按能力身份读到的持有），主体能不能用一个候选，`adopted` 要求值的身份，读取判定。「主体能不能用这个能力」没有通用端口，它是装配的输入；这个输入同时回答主体能不能知道一个被禁用的候选。
- 解析取各层候选，对每一份问使用资格，调资产的 `evaluate`，再翻成五种答复：胜出者翻成已采纳，引用带胜出者的层、版本（合资产版本的形式时）、定位与包摘要，声明投影取胜出者的；候选的内容库定位没有 `ref`，绑定填上候选的资产引用。没有胜出者时，出局者里有主体可知的被禁用候选，就答合法已知但不可用的替换件，名字与说明取最具体的那一份，原因是固定的「已禁用」说明；没有这样的候选而有一份被禁用候选的资格答不知道，答未知；其余答没有。`evaluate` 答读不到，翻成未知。
- 带依据时，依据的层等于胜出者的层，依据带资产版本时它也等于胜出者的版本，才算合法，答已采纳，引用的包摘要取依据的；否则答依据不合法。
- `adopted` 对要求值的每个身份各求值一次，收下已采纳与替换件；任一个答未知，整个答未知。读取判定的输入原样转交。
- 四个输入任一个抛出，对应的答复是未知，不当成没有。
- 已发布的 Skill 的候选从它的版本记录正文读出：名字、说明、依赖的工具与包摘要，定位是内容库定位。说明不是文本时按没有说明处理；正文别的部分不合已发布的 Skill 包的正文形状时，不构成候选。

### `Skills` 入口与提交

- agent 经 `Skills` 这一个入口使用 Skill，入口有五个命令：搜索给第一层，读入口给第二层，按路径读给第三层，列目录看有哪些文件，提交把一个目录发布到租户名下。前四个只读，没有执行命令。入口稳定，背后有多少个 Skill，入口不变。
- 单机装配下，读取结果告诉 agent 这个 Skill 的目录在本机的位置，agent 用 Shell 直接运行里面的脚本；不先读出脚本再写到落点。
- 常驻的简介是采用点上定下的记录；搜索按当下事实现算，新装的不常驻 Skill 下一次搜索就能看到，不经装配。不在系统提示词里点名不常驻的 Skill。
- 提交走资产的发布服务，每次提交都要人确认；agent 不能向组织层提交，也不能代用户提升。
- 元技能是官方层一个普通的、常驻的 Skill，教 agent 写 Skill；它不可替换，没有特殊机制。

### Cordis 装配

- 服务键只由各抽象类的静态 `provide` 给出；方法签名从契约的接口推出。根入口不导入 Cordis。
- 本组只给 `skillCatalog`、`skillAccess` 两个服务的定义，不带插件。提供者是装配方：它用本组的工厂、两个判定端口的绑定与包来源组出服务，按调用里的主体与租户选用哪一套；同一个租户的服务只读这个租户的材料。
- 服务信任调用方已经核过主体的真伪；读取判定核的是这个主体此刻能不能读，例如它是不是这个租户的会话工作主体。

## 原则与约束

- 一个事实一个拥有者：Skill 不求值、不保存采用、不判定准入、不运行脚本，别人的结论只经端口读。
- 只用自己的词：契约不点名调用方，不引入调用方体系的概念。
- 形态与含义分开：字节从哪里来（本机目录、内容存储）与字节表示什么（解析、校验）是两条轴，加一种来源就是加一个来源实现，同一套符合性套件。
- 不变式先于机制：快照不可变，资源按包内路径寻址，不拼版本，未知不压成失败，秘密不进上下文。
- 依据不授予访问；每次读取现场核验；对无权主体不披露身份是否存在。
- 上界都有限：说明、声明预算、页大小、遍历访问次数、包的文件数与字节，以及内容库来源记住的快照数都有明确的数值。
- 读取的关键安全性质要有形式模型与有界穷举探索器两种证据，模型在 `skill` 的 `verification/` 目录；有限检查的通过不等于实现符合。
