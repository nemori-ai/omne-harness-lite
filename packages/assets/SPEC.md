# Assets

## 总体架构

Assets 包组回答三个问题。资产：一项能力有哪些具体实现，谁拥有、谁创作、哪一版已发布、哪一层持有它，这一次求值该用哪一份。设置：一项可配置的东西现在的值是什么、来自哪一层、谁能改、改了怎样保证当下的事实仍成立。权限：一个权限关口的允许范围与生效值是什么，哪些限制下层永远解不开。

| 成员              | 回答的问题                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| `assets`          | 资产的共同契约：能力身份、类别登记表、正文读取与判断。纯数据与纯函数                                               |
| `assets-local`    | 受信部署端的资产发布、版本与持有的持久化，以及持有作为设置目标的当前事实                                           |
| `settings`        | 设置的领域核心：声明校验、纯求值、变更决定、查询与准备提交的应用协议、秘密保管的两个端口、租户层读写面。不依赖存储 |
| `settings-local`  | 设置的本地提供者：独立目标、配值持久化、一致的目录捕获、准备与恢复、来源保留、与身份的资格协调、秘密文件保管       |
| `permissions`     | 权限的纯规则：上界与挑选的求值、配值写入判断、声明式权限上界                                                       |
| `assets-protocol` | 公开协议 `assets/v1` 的协议契约：租户层设置的四个操作。纯数据                                                      |
| `assets-access`   | `assets/v1` 的接入插件：换主体、搬形状、映射结果                                                                   |
| `assets-ui`       | 设置的界面模块：租户层设置的列表、查看、设置与清除                                                                 |

三块各自拥有自己的求值规则，不合成一套通用覆盖算法。`assets` 定义能力身份与类别登记，类别拥有者（Tool、Skill、Agent、MCP、Model 的契约）向它登记正文的读取与判断。`settings` 的核心通过读端口与准备提交端口表达行为，不导入资产或身份；`settings-local` 把它落到共享的 SQL 存储上，配置目标的当前事实由目标拥有者在同一次事务里给出：独立目标由 `settings-local` 自己拥有，资产持有由 `assets-local` 提供投影。`permissions` 只做结构化判断，由应用装配里的准入与租户层读写面调用。客户端经 `assets/v1` 读写租户这一层的设置：界面模块调协议客户端，接入插件凭登录与目标租户向身份换主体，再交给租户层读写面。

## 领域边界

本组拥有：具体资产记录、定义版本与发布、持有及其启禁与替换锁、合法候选的选择；设置的配值、清除、属性锁、求值来源、原操作结果与变化记录；秘密绑定的保管；权限配值的求值规则与写入判断；动态治理贡献的登记、采用与目录。

本组不拥有：组织、成员、登录、角色与资格（身份）；工作区的身份、实例与参与关系（工作区）；装配清单、组合展开与运行采用（装配）；类别的专有声明、内容校验与使用行为（各类别）；授权表达的解释、许可与消费（授权）；人的请求与答复（人工介入）；实际执行与外部效果（执行方）。设置保存成功不代表运行已经改变，权限求值通过不代表动作获准或执行成功。

## 心智模型

资产是一份带版本的定义，持有是某一层说「我用它」的那个关系，设置值挂在持有上，权限是另一种有自己合并规则的设置值。把它们想成一摞透明片：官方、组织、租户、工作区、会话一层层叠上去，每层可以放自己的持有和值，求值时从最具体的一层往外看第一份合法的东西，但外层的锁、上界和主动禁止像钉子一样钉穿所有内层。最容易想错的地方：同名不是同一份，替换一份实现不会把旧实现的值、锁和秘密带过去；锁和禁止只朝内生效，不反向限制外层；被过滤掉的候选不遮蔽外面合法的那一份。

设置的值归设置，配置目标的生死归目标拥有者。一次写入能不能成立，看的是提交那一刻目标拥有者在同一事务里给出的当前事实，不是之前读到的页面、一次准入结论或调用方的断言。目录与求值是投影：从固定的一组事实算出来，事实一变就要重算，旧页不能混着新事实续读。

三种「没有」要分开：本层没配（沿外层往下求）、显式配成 false 或空（是一个值）、读不出来（是故障，不是空也不是默认）。结果不知道就是不知道：已经受理的写入回执丢了，按原操作身份查，不换身份重做，也不写成成功或失败。

## 应然设计

### 能力身份与资产记录

- 能力身份是类别加名字；说明、Schema、子命令、配置和实现包不参与身份。同一身份下可以有多份具体资产记录，各自保留所有者、作者、来源、草稿和发布版本线，同名不自动合并。
- 同一层同一身份至多持有一份。资产记录存在与本层持有分别可查；新副本不能凭同名占用已有持有。
- 资产定义数据、执行实现与承载服务分别标明采用依据，不要求同时换代。不能用「只换实现」绕过替换锁或使用资格。
- 资产 ID、版本、血缘和句柄只用于定位，不是权利证明。成员角色或资格变化不改租户身份、历史作者与既有归属。

### 创作归属、定义与发布

- 人在组织范围合法创作的资产归该组织，在自己租户范围创作的归该租户；作者保留创作时的租户身份。官方资产的作者与所有者是平台，不补造租户。Agent 的产出归它合法提交的工作区或租户，不能直接产出组织资产，也不能替人提升。
- 发布前通过共同校验与类别校验；发布形成不可变版本，之后的修改是新草稿与新版本，不覆盖已发布字节。同一资产与版本对应的类别、名字、正文、来源与声明不可变，同一版本换内容是版本冲突。过期的草稿编辑不能静默覆盖已确认的修改。
- 发布与选版分开。持有固定一个版本或跟随当前版，不指定时跟随。固定版不因新版发布暗换；跟随者在后续求值采用当时的发布版。新的选择只作用于之后的采用点，不改已捕获的调用内容。
- 类别校验、来源或存储不可取得时答可辨的依赖失败，不报告发布成功，不把未核验内容当成合法的空定义。
- 定义可以声明不可替换（immutable）。它只作用于合法采用该版本的那一层以下，不阻止修订草稿、发布新版、禁用或移除，也不自动锁定设置、权限或引用。

### 持有、启禁与移除

- 加入持有要有该层的管理资格与合法权利依据：组织层要组织持有管理资格（由治理模型映射到角色），租户层由本人管理。能使用资产不等于能管理组织持有。加入只让属性可配，不保证会被选入或能执行。
- 新持有是启用的。禁用保留持有、所选版本、全部配值与原回执；管理视图仍列出它，运行视图拒绝它；有权者仍能改它的配置。再启用只解除本层自己的禁用，不解除外层禁用，也不授予执行许可。禁用是持有的一个事实，不是某个配置项的值。
- 移除结束持有且不可逆：同一持有身份不能再被持有或选用，新持有用新身份，不继承旧身份下的设置值。移除不删除设置值与操作结果，但它们退出有效集合。配值写入与移除竞争时，不能报告一个已不存在持有上的有效配置。
- 改版、移除与退役先识别受影响的引用与消费者，不默认级联删除日程、Agent 定义或其他资产，也不把治理变更当成实际工作已停止。官方能力不得清空或禁用。

### 合法候选与替换

- 求值消费明确的组织、租户与可选工作区，依次做禁用过滤、当前使用资格过滤和同身份选择，并保留过滤原因、来源、版本与锁定依据。被禁用或没有使用资格的更具体候选不遮蔽其他合法候选。
- 普通适用顺序是官方、组织、租户、工作区。过滤之后，按层序识别定义的不可替换声明与持有层的替换锁，再选不违反约束的最具体实现。约束只向更具体层生效；同一份资产在下层继续持有不算替换。
- 工作区里共享与本地是同一层，先各自过滤，合法的本地同身份候选优先，没有合法本地时保留共享候选。目录名与地址不构成身份、访问资格或租户私域。
- 替换不移交原资产的设置值、锁定值与凭据。同身份上的锁定权限上界与主动配置的不允许操作继续约束替换件。合法更新失败时不发布混合新旧输入的半份候选。
- 官方能力身份求值为空是缺陷，不是成功配置。meta 能力、官方 Agent 定义等类别例外各自保护。

### 类别提供方与正文

- 类别提供者列出候选并按层值决定的版本交出正文；它不决定本次采用。求值本身不带版本，版本由层值决定。正文一经记入采用依据，同一次执行读的就是这一份，后来的版本不改写它。
- 同一身份没有合法定义时答缺合法定义，资格不成立答候选被拒，类别没有拥有者答无类别拥有者；都不交出空正文。
- 登记表拒绝空类别名与重复登记，找不到类别答未知类别。正文先经一次读取得到冻结副本，判断只接受这份读取结果，对象字面量与伪造的种类被拒；判断不调用传入的函数。判断失败之后，派生声明与引用抛出同一次拒绝的原因。
- 正文是目录的类别另交命名空间、目录的校验与大小上限、从目录到声明的投影。每一层一个根，根下每类别一个命名空间，命名空间下每个名字一个目录；类别按能力身份向资产要包的读口，不认路径。读口只有取清单与按清单里的路径与摘要读一个文件两步，读不出清单之外的东西，字节与摘要对不上答材料不可用。已发布的包只由发布写入，写入后不变；发布按操作身份幂等。

### 组合与流转

- 组合引用能力身份，按完整作用域解析当前合法实现，引用不转移所有权。Plugin 内含成员随 Plugin 的版本与权利治理；无终点的 Agent 定义递归在采用前拒绝；Skill 与 Tool 的配套互引不算递归。Plugin 成员的启用值在展开该 Plugin 时先求。
- 复制、分享与提升都是只有在条件共同成立时才成立的一次操作，按原操作身份认回，不因重试多出一份 v1 或一个版本，不携带源的配值与秘密。复制建立独立资产与同源血缘；分享在确认前没有使用权，成立后跟随源的当前发布版，所有权不动；提升改变所有者且不可逆，Agent 不能发起或确认。

### 设置：声明与目录

- 功能或资产类别拥有每项设置的含义、类型、合法值、默认或无默认、清除后果与采用时点；设置拥有配值与求值。资产设置随当前合法定义派生，不维护第二份字段目录；独立设置从它自己的固定定义与配置目标投影，不伪造资产持有。
- 定义身份是提供者、定义、精确版本与内容摘要；同版本不同摘要拒绝，不 last-write-wins。数字要有单位与上下界，枚举要逐值解释，默认值过同一 Schema；递归引用、远程引用与正则约束拒绝；输入有深度、节点、文本与项数上限。必要元数据缺失的声明不发布。
- 目录按明确的部署与逻辑服务范围、受信主体、目标范围和视图模式返回。管理视图包含可配置但未启用的资产；运行视图只消费调用方核验过的选择，不自己挑目标。登记、合法目标、提供者在线与执行实例存在分别报告。
- 目录捕获每次核验代租户主体并取得新的资格预留，在一个租户事务里读目标拥有者投影与配值；每页重新捕获，依据、查询或登记代际变了答 `basis_changed`，不混代续页。声明缺失的条目从管理视图略去并标 `partial`，运行捕获缺声明答不可用；部分目录不当完整目录用，空目录本身不证明完整。无权查看的目标或项不在错误里泄露。普通目录不返回秘密明文。
- 一次捕获的目标数与字节有上界，超出时拒绝，不截成成功。

### 设置：配值、清除与锁定

- 写入在条件提交边界核验当前资格、目标、声明版本、项存在、取值合法、锁、允许来源与预期配值修订。资产目标还核合法持有，独立目标核实际管理关系。失效编辑、无资格或不合法时当前事实不变。
- 缺省表示本层没提供值；显式 false 是一个值；清除只撤回本层覆盖，重新沿当前来源求取，不等于 false、禁用或固定回退旧默认。null 是否有业务含义由声明决定，未声明时不当清除命令。
- 普通值按默认、组织、租户、工作区、会话的层序取最具体的合法值；有效的外层锁阻止更具体层覆盖。解锁只作用于后续求值。属性锁不锁住整份实现的替换，定义不可替换也不锁住属性。
- 禁用按「任一层为真即禁用」合并，下层 false 打不开上层 true；这条规则不推广到其他设置。
- 会话值不回写租户默认，也不外溢到其他会话。账号偏好独立于组织与租户的资产设置，不参与层序，不授予权限。

### 设置：工作区与同层合并

- 读工作区要有明确选择与合法实例访问关系，不从当前目录补。工作区不提供权限配值，不给其他资产配落点与身份项，不能设属性不可覆盖标记或持有层替换锁；定义自身的不可替换声明不是工作区治理配值，不被过滤掉。
- 共享与本地同层：同项本地显式值优先（包括显式 false），本地缺省才沿用共享值，不对两者取布尔或。选用同名完整本地资产时不再叠加针对共享实现的覆盖。共用实例的本地不是租户私域，求值不读其他参与者租户的私有配值或凭据。
- 本机命令型 MCP 与导入命令型 hook 的启用开关归获准租户自己的设置，默认不启用，工作区资源不能代开；打开后仍守工作区保守权限。

### 设置：投影与生效时点

- 候选求值、装配选入、属性投影、逐项求值依次交接；不依赖还没产生的项集合回改候选。
- 有效值报告保留最终值、采用来源、被过滤或锁定的原因与本次依据。值求出来不代表绑定对象可用、Agent 已装配或动作获准；专有合法集合（如目标模型）仍由类别拥有者检验。
- 工作区资源在实际装配或显式 reload 时读取，不随文件编辑或下一次 Run 默认刷新。候选校验失败不发布半新半旧的有效值。合法的设置变化按该项的使用时点作用于后续输入，不改写已发调用。

### 设置：写入、准备与原操作

- 准备提交端口是配值写入的唯一协议，没有不经准备的直接提交。准备先核实际主体与合法目标，持久保存不可变的根命令与至多一个活跃尝试，不写配值；提交按持久准备取原命令，核调用主体、完整绑定与当前事实，在同一次目的提交里建立业务结果与尝试终态。参数不能替换命令。
- 原操作身份是存储域、主体、完整目标与操作标识；命令摘要排除传输请求标识。同身份同内容重试返回原结果，内容不同答 `operation_conflict`。根的已提交与已中止是不可改写的终态；未知是观察者没取得权威结果，不是持久状态。
- 失败对根的后果：输入无效、无权或绑定不符只拒绝本次请求，不改已有根；已受理且绑定正确的命令在受保护提交中确认修订冲突、定义变化、被锁、不兼容或业务禁止时，尝试终结、根中止，之后重传返回原终态；依据变化只封口当前尝试，普通根仍待决，可以沿不变的原命令重新准备；持有组织来源门的根遇依据变化则封口并中止、清自己的门；依赖不可用或回执丢失时什么都不终结，答未知；每根尝试数有上界，耗尽时根保持待决、可以取消。
- 已终结的根不复活，之后解锁或恢复定义也不重开它；要做新的业务必须用新的操作标识。查询只读根与精确尝试，不封口、不推进、不释放门。取消只取消没成功的根，已提交时返回原成功。
- 准备的持久阶段（准备中）先保存恢复身份，再取得外部保留；保留齐备、当前事实与计划相符并保存完整依据之后才答已准备。准备中的存储结果未知时保留原尝试与可能存在的保留，终态之后迟到的保留回包只用于认回与释放。外部保留请求在发起之前持久保存，回包丢失用原请求认回，已结算的保管不退回 held。
- 秘密项的变更在准备分配任何东西之前拒绝，所以秘密值不进入根、尝试、回执与变化记录。变化记录不含值，分页有上界，不是目录快照。
- 显式 rebase 是维护动作，不暴露给普通租户或工具：要精确的新旧定义引用、预期修订，并对每个已有配值明确保留或丢弃；保留的值须在新定义与新来源下重新通过求值，不按显示名称匹配或自动转换。

### 设置：目标拥有者与来源

- 一次值提交需要同一 SQL 事务里目标拥有者给出的当前事实：当前定义、精确定义引用、授予与有序来源。布尔值、先前的准入结论、缺失的事实或调用方断言都不能授权写入。没有资产时，装配显式产出空的资产投影，不伪造资产所有。
- 独立目标由受信的拥有者能力开通与退役，不是租户设置服务。退役的目标不能以同一完整身份再开通，退役使它退出投影并阻止之后的写入，保留配值与操作历史。拥有者修订与配值修订是两个计数。
- 来源身份包括 ID、拥有者、作用域种类与作用域主体，布局有序、ID 唯一、个数有上界；不从 ID 推断层级。配值记录保存它采用的布局；当前求值与普通写入要求稳定身份与拥有者投影逐项相等；换拥有者、作用域种类、主体或次序要显式 rebase，同一 ID 下换了拥有者或主体的值不能被继承。资格修订与值修订不互相替代；明确无值、不适用与提供者不可用是不同事实。
- 组织来源的配值在唯一组织来源上持久保存，各租户消费同一来源，不各复制一份。来源保留绑定确切来源修订、原业务操作、目的尝试与稳定目的身份，不授予身份资格或许可。目的未确定终态时保留来源；只有具名目的地建立 aborted 或认回 committed 才能释放，记录不存在、超时、卸载都不是释放证明。
- 所有改变来源的写入（首次设置、锁、解锁、删除与 rebase）先拒绝新的重叠保留，再等已有保留结算；提交时重核原管理资格与定义，在同一来源事务写唯一配值、原结果并清精确的门。最终拒绝、合法取消或外部封口当前尝试，与根中止、清门在同一来源事务完成。旧根的迟到收尾不能清后继根的门。恢复分别枚举待决的来源与 held，包括零 held 而根仍待决的来源。数据库不可得时保留待决与原身份，不改用系统授权继续。
- 运行选择只表达消费意图，每个目标仍要新的拥有者与身份资格；选择有容量与寿命上界，观测到时钟回拨后不复活已过期的选择。
- 声明登记的撤下不删除持久配值与操作历史，同一份精确声明重新登记后可以再读到。登记撤下不是写授权的原子撤除；要使目标失效，由目标拥有者退役独立目标或移除、改变资产持有。

### 秘密设置项与秘密保管

- 声明为秘密的设置项，值只保存在秘密保管里，不进入配值、求值来源、变更、提交记录、回执或变化记录；纯求值把来源中的秘密值判为不兼容。秘密不进入原文审计、日志、遥测与来源说明。
- 秘密按绑定保存，键是范围、目标与用途。范围是官方或一个已铸造的租户；目标由具体持有与项标识推出，所以替换后的新实现取不到原实现的秘密，持有移除或定义删项之后旧绑定不能再被写入、查询或取用。用途不同的绑定互相取不到。目标编码只有一处。
- 保管有两个窄端口：管理面（写入、清除、查询有无、按范围列出有无）给秘密项入口与受信部署操作；使用面（按键取用一次）只给装配注入的受信消费方。查询有无不返回值。使用面每次读当前值；没有绑定答 `missing`，已撤销或范围未铸造答 `denied`，读不出答 `unavailable`；都不改选其他范围、目标或用途。选哪一层的引用、缺凭据怎样失败，由类别的凭据契约决定。
- 写入的结果分已写入、未写入、确认未知与拒绝；确认未知不报成功或失败，重试前先查有无。同值重复写入是已写入。秘密文本在边界解析：去首尾空白后非空、无控制字符、长度有上界；拒绝只说明规则，不回显文本。
- 秘密项入口先核该项已声明为秘密、调用者对该范围有配值依据，再交管理面；持有解析不到或项未声明答 `undeclared`，不是秘密答 `not-secret`，资产引用对应多个持有或一个持有有多个在用版本答 `conflict`，这三种都不调用保管。秘密项没有锁。
- 文件保管每次读整个文件、不缓存；写入持文件锁、重读、改、以唯一临时文件加 fsync 加改名发布。锁不按时间被接管。旧文件无法解析时整份是损坏，不修复、不重写。在主目录下新建保管时，秘密只读一次，路径在读秘密前后各核一次为空，新建的目录与文件只对当前用户可读写并读回确认。

### 租户层读写面

- 读写面把租户这一层做成列出、查看、设置、清除四个动作；它只编排，不存配值，不实现权限的求值规则，每次调用都读当时的目录与外层。
- 每个方法先核主体：不是这个租户的登录主体一律 `denied`，不带原因、与不存在看不出区别，不读目录、不问权限、不写；准入读不出答 `unavailable`。
- 一次列出或查看只读一次目录。目录读不出、所要的项不在部分目录里或权限端口读不出时答 `unavailable`，不把残缺的当完整的；目录本身部分时列出标 `partial`。
- 设置的输入在边界严格解析；权限项只收挑选，写入值由权限端口从挑选与本层原有的允许集合组成，本层允许集合原样保留；清除只撤回本层的挑选，本层有允许集合时它留下。
- 写入以调用者给的原操作身份为设置写入的操作标识；同身份同输入答原结果，不同输入答 `conflict`。修订号是目标的修订号，过期由写入的提交判断。结果：有变化答 `written` 带新修订号，无变化 `no-change`，修订或声明不符 `conflict`，上层锁 `not-writable/locked`，越过上界 `not-writable/out-of-bound`，确定没写 `unavailable`，写入抛出或答未知 `unknown`。认回不重做上界核对。

### 权限：上界、挑选与主动禁止

- 求值分别表达锁定的允许集合与未锁的挑选。适用来源是默认、组织、租户、会话；工作区不提供权限配值。拥有者提供的适用约束（如 Agent 定义的权限上界）与四层配值共同构成上界，不能遗漏；必要的外部约束无法核验时不放行依赖它的操作。
- 锁定集合取交集，内层不能突破外层上界；锁成单值是单元素集合，锁成空集该项无可放行结果。未锁值只是挑选，不成为额外上界。共同允许范围非空时，从最具体来源向外取第一个落在界内的挑选；作者默认是最外层挑选。全部挑选都在界外时，对有序分档权限取距最具体挑选最近的界内档位，等距取较严档；没有已定比较关系的类别不猜最近结果。
- 组织、租户或会话主动配置「不允许该操作」时，无论有没有不可覆盖标记，下层挑选、会话模式、自然语言批准或人工介入都不能把它放宽成允许。作者出厂默认的不允许只是最外层挑选，不构成这种限制。这是操作限制，不是禁用整份资产。
- 结果保留实际采用范围、允许集合、有效值与依据。权限只约束相应关口，环境可用、身份认证、资产持有与实际结果各自判断。
- 声明式权限上界按能力身份与关口标识，允许集合只限制允许值，不选值、不授予权限；每份声明的项数与每个允许集合的大小有上界，空集、重复关口与重复值拒绝。上界提及当前定义不支持的值时，消费方报告来源不可用，不删掉这条上界。

### 权限：使用资格与工作区保守权限

- 「谁可以使用它」按治理模型给出的主体范围与「自己」求值；作者没另声明时只限自己。使用资格在同身份择取之前消费：不能使用的自定义件被过滤，其他合法实现仍参与，不清空官方能力。
- 替换件少声明受约束的权限项时，不把该项解释为允许、无约束或不适用；约束无法可靠匹配到实际关口时不开放依赖它的操作。
- 工作区的权限与授权配值在加载时过滤，不允许放宽，也不接受「只收紧」作为旁路。工作区自己提供的 Tool 与 MCP 动作按「问一下」，Loop Extension 只观察；使用、安装、启用、实例化与派发的资格限本次获准挂载者自己。需要放宽时，先合法收进租户持有再配值。
- 使用资格变化不删除会话已知的 Tool、Skill、MCP 身份；当前资格只影响之后的采用与准入。

### 权限：写入与准入

- 组织层写入要治理模型授予的当前组织管理资格，租户层要本人且有合法持有；实际写入核验当前上界与允许项，越界不生效并给出可辨原因。
- 编辑与执行分开判断：编辑采用当前定义、允许的配值层与编辑政策的适用约束，排除被修改层及其内层的原配值；本层旧的禁止不能让有资格的本层管理者永远改不了它。外层主动禁止与允许集合仍限制可能允许操作的新值。
- 当前定义与拟写值合法时，不允许操作的挑选、空的允许集合、只含不允许值的允许集合都是确定的限制，不依赖未知外层就能保存；其余配值要完整的适用当前来源，拟写的允许值都要在共同界内。纯判断不授予写入资格，也不证明材料当前；真实写入把原身份、精确命令、当前定义、适用来源与原项修订绑在一起，在同一事务或来源保留协议下保护这些条件。
- 用户明确选择租户全局允许时，授权解释表达范围，设置与权限核对写入资格，再写成租户权限值，它仍服从组织上界与适用的主动禁止。单次与会话授权不经此路径改持久权限，任何卡片「批准」都不解释成全局写入。
- 撤销、成员失效或上界变化作用于之后的准入，不等于运行停止或外部效果回滚。权限缓存要声明有效条件与失效范围；排队、等人、重装配与恢复之后按原动作当前的条件重新核验，改了参数不能借旧批准。

### 动态治理贡献

- 功能拥有者声明本功能的设置与真实权限关口；公共治理只固定协议、安全边界与求值规则，不维护预知所有功能的枚举。权限声明要有人可读的标题、解释、批准后果、合法档位与有序关系、真实的关口标识；没有关口的权限不能登记。
- 支持的作用域是声明能力，实际作用域是受信输入，两者必须相符；注册者不能新增没有治理语义的范围、伪造组织、租户或会话身份、放宽外层禁止。全局只表示本租户允许的持续选择；只此会话跟随逻辑会话而非运行实例；只此一次跟随原操作与参数，技术重传不能再得一次额度。
- 登记、撤除与采用都绑定原操作身份与请求摘要：同操作同摘要认回原结果，同操作异摘要冲突，未知按原操作查询。撤除只释放精确的贡献租约，旧代不能撤新代；最后一个适用租约退出才撤下该范围的贡献。采用校验全部必要声明与关口之后整份发布，失败保留旧份或明确无可用份，不发布半套。
- 配值的身份含持久命名空间、配置目标、具体来源身份、项与治理层，不用进程号、fiber 路径或临时注册号。卸载只释放实例贡献与执行资源，不删除配值、许可与回执，不重置使用次数，不复活已撤回或已消费的许可；同名的不同资产或提供者不继承原来源的配值或许可；相同来源、相容定义重新装配后，重新核验即可采用合法保存的值。
- 不可变定义的权威来源对一个定义键只对应一个摘要，租户内保存的是已核实的副本；来源不可核实时答不可用，不把局部副本升成全局权威。
- 装配协调者拥有采用围栏：声明的发布、撤除、替换与依赖该采用集合的设置提交、授权消费在同一排序边界核验。卸载先封住新的采用，认回或完成已取得提交权的原操作，再释放物理资源；提交先成立则保留结果，撤除先成立则旧准备不产生新的写入或消费。重启时先隔离旧实例的围栏，再登记本次实例。

### 协议、接入与界面

- `assets/v1` 只有列出、查看、设置、清除四个操作，都要登录、都在消息体里带目标租户，都不算业务访问、不带登录凭证；同一主版本里只能加操作，改已有形状要新的主版本。权限项只收挑选，秘密项交原文，视图里没有秘密的值。除成功与 `not-writable` 外，结果的响应体为空。
- 接入插件先凭登录与目标租户换主体，身份答拒绝或不可得时原样答出，不调读写面；读写面每次调用现取，取不到答 `basis-unavailable`，协议不撤。字段原样转交，读写面的每个结果对一个线上结果，不合并、不改名。读的抛出答 `basis-unavailable`，写在调用开始之后抛出答 `unknown`。插件不持有状态、不缓存配值、不自己认回。
- 界面显示的是服务端的事实：写成功之后重读这一项再画，不在本地推算生效值；写入带当前视图的修订号，冲突时重读。结果未知时不发新的写入，原样再送同一次来认回，认回仍说不出就停在「结果仍未知」由人再确认；从不把未知写成成功或失败。读不出不显示成未设置或默认值，部分列表整张标明不全。旧读取与旧操作的迟到答复一律作废。

### 失败、并发与恢复

- 来源不可用、权限不足、引用阻断、版本冲突与真实的空集合分别可辨；依据缺失不当允许、不当默认值、不借旧缓存放行新动作。可以明确拒绝的分支照样拒绝。
- 已确认的定义、版本、持有、配值、权限与操作结果在进程崩溃、操作系统崩溃或断电恢复后仍可读；介质与整机物理损毁不在这一保证内。回执丢失按原操作查询；取消不回滚已确认的变更；多步操作如实区分已完成与待处理。
- 较旧的求值不以完成较晚为由覆盖已采用的较新结果。持久化的数据不合形状时答失败，不变成空或成功。
- 关闭只停止本实例的准入并等已受理的操作结算，不关闭共享的 SQL 与身份依赖；未解决的资格预留留给身份的恢复。

### Cordis 装配

- 核心成员不依赖 Cordis 与存储；协议契约只依赖公开契约成员。服务键由定义拥有者给出。
- 贡献挂在插件自己的作用域上，卸载即撤下；卸载不删除持久配值、持有、发布历史与原回执。
- 运行时对象（存储、时钟、秘密保管、当前事实生产者）经服务或注入取得，不进可序列化的配置；配置非法使插件失败，不静默回退。

## 原则与约束

- 每样事实只有一个拥有者：资产事实归资产，配值归设置，权限求值规则归权限，目标的生死归目标拥有者，资格归身份。不跨包改私表，经同一事务的具名参加者交换事实。
- 写入的依据是提交那一刻同一事务里的当前事实；读到的页面、准入结论与调用方断言都不是写授权。
- 读不到就是读不到；缺省、显式值、清除与依赖失败分别表达，不用默认值掩盖故障。
- 外层的锁、上界与主动禁止钉穿内层；替换、删项、卸载与重装配都不能解除它们。
- 结果不知道按原操作身份认回，不换身份重做，不写成成功或失败。
- 秘密只在保管里，只交给装配信任的消费方；任何结果、记录与诊断都不带秘密。
- 上限、期限、预算与策略是配置或可替换实现；合法使用会碰到的上限要有分页或排队这样的去处，不截断成成功。
- 自定义的提交、保留、恢复协议要有形式模型与具名负控；模型在 `settings/verification/`，有限检查的通过不等于实现符合。

| DG2   | 释放一个租约不删除兄弟贡献；旧代不能撤新代                                                                     | 一个实例卸载连带撤掉别人的贡献                 | 只有文字                                                                                                                                            |

| DG4   | 卸载与重装配不丢配值与回执，不复活已撤回或已消费的许可                                                         | 重启后权利复活或配置丢失                       | `SettingsComposition` 模型 `UnloadPreservesValue`；`settings-local` 的 `catalog` 用例（卸载后重装读回）                                             |
