# Assets

## 总体架构

Assets 包组回答三个问题。资产：一项能力有哪些具体实现，谁拥有、谁创作、哪一版已发布、哪一层持有它，这一次求值该用哪一份。设置：一项可配置的东西现在的值是什么、来自哪一层、谁能改、改了怎样保证当下的事实仍成立。权限：一个权限关口的允许范围与生效值是什么，哪些限制下层永远解不开。

| 成员              | 回答的问题                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| `assets`          | 资产的共同契约：能力身份、类别的拓展点、正文读取与判断、候选求值 `evaluate`、包的读口与摘要、发布服务与它的授权端口、租户层的管理服务。纯数据与纯函数        |
| `assets-cordis-contract` | 类别拓展点 `assetCategories`、独立设置的贡献口 `independentSettings` 与发布服务 `assetPublishing`、管理服务、按租户订阅资产变化的 Cordis 服务定义，与类别拥有者贡献一个类别、领域贡献一组独立设置用的插件 |
| `assets-local`    | 受信部署端的资产发布、版本与持有的持久化，已发布的包文件的存放与恢复，资产上传，提交之后的变化信号，以及持有作为设置目标的当前事实               |
| `settings`        | 设置的领域核心：声明校验、纯求值、变更决定、查询与准备提交的应用协议、秘密保管的两个端口、租户层读写面、独立设置的贡献口。不依赖存储 |
| `settings-local`  | 设置的本地提供者：独立目标、配值持久化、一致的目录捕获、准备与恢复、来源保留、与身份的资格协调、秘密文件保管       |
| `permissions`     | 权限的纯规则：上界与挑选的求值、配值写入判断、声明式权限上界                                                       |
| `assets-protocol` | 公开协议 `assets/v1` 的协议契约：设置与类别的操作，资产的操作与一条观察。纯数据                                                      |
| `assets-access`   | `assets/v1` 的接入插件：换主体、搬形状、映射结果                                                                   |
| `assets-ui`       | 资产的界面模块：资产页（类别排成一条栏，每类一个窗格）、通用的窗格、设置页；给类别的界面模块提供资产治理口与类别页面的拓展点 |
| `assets-tools` | 给 agent 的多命令工具 `OmneExtensions`：看、发布、启用、禁用、移除行事的那个租户在持的拓展，覆盖此刻登记的全部类别。它只认识资产的三个面与工具契约，要的东西写成端口 |

三块各自拥有自己的求值规则，不合成一套通用覆盖算法。`assets` 定义能力身份与类别的拓展点；类别拥有者（Tool、Skill、Agent、MCP、Model）经服务端的拓展点贡献自己的类别：正文的读取与判断，加这一类的名字与一句说明。`settings` 的核心通过读端口与准备提交端口表达行为，不导入资产或身份；`settings-local` 把它落到共享的 SQL 存储上，配置目标的当前事实由目标拥有者在同一次事务里给出：独立目标由 `settings-local` 自己拥有，资产持有由 `assets-local` 提供投影。`permissions` 只做结构化判断，由应用装配里的准入与租户层读写面调用。客户端经 `assets/v1` 读写租户这一层的设置：界面模块调协议客户端，接入插件凭登录与目标租户向身份换主体，再交给租户层读写面。

## 领域边界

本组拥有：具体资产记录、定义版本与发布、持有及其启禁与替换锁、合法候选的选择；设置的配值、清除、属性锁、求值来源、原操作结果与变化记录；秘密绑定的保管；权限配值的求值规则与写入判断；动态治理贡献的登记、采用与目录。

本组不拥有：组织、成员、登录、角色、资格与账号登录凭据（身份）；工作区的身份、实例与参与关系（工作区）；装配清单、组合展开与运行采用，能力名单的继承与排除（装配与 Agent）；类别的专有声明、内容校验与使用行为（各类别）；授权表达的解释、许可与消费（授权）；人的请求与答复（人工介入）；实际执行与外部效果（执行方）。设置保存成功不代表运行已经改变，权限求值通过不代表动作获准或执行成功。

## 心智模型

资产是一份带版本的定义，持有是某一层说「我用它」的那个关系，设置值挂在持有上，权限是另一种有自己合并规则的设置值。把它们想成一摞透明片：官方、组织、租户、工作区、会话一层层叠上去，每层可以放自己的持有和值，求值时从最具体的一层往外看第一份合法的东西，但外层的锁、上界和主动禁止像钉子一样钉穿所有内层。最容易想错的地方：同名不是同一份，替换一份实现不会把旧实现的值、锁和秘密带过去；锁和禁止只朝内生效，不反向限制外层；被过滤掉的候选不遮蔽外面合法的那一份。

设置的值归设置，配置目标的生死归目标拥有者。一次写入能不能成立，看的是提交那一刻目标拥有者在同一事务里给出的当前事实，不是之前读到的页面、一次准入结论或调用方的断言。目录与求值是投影：从固定的一组事实算出来，事实一变就要重算，旧页不能混着新事实续读。

三种「没有」要分开：本层没配（沿外层往下求）、显式配成 false 或空（是一个值）、读不出来（是故障，不是空也不是默认）。结果不知道就是不知道：已经受理的写入回执丢了，按原操作身份查，不换身份重做，也不写成成功或失败。

## 应然设计

### 能力身份与资产记录

- 能力身份是类别加名字；说明、Schema、子命令、配置和实现包不参与身份。同一身份下可以有多份具体资产记录，各自保留所有者、作者、来源、草稿和发布版本线，同名不自动合并。
- 同一层同一身份至多持有一份。资产记录存在与本层持有分别可查；新副本不能凭同名占用已有持有。
- 资产定义数据、执行实现与承载服务分别标明采用依据，不要求同时换代。不能用「只换实现」绕过替换锁或使用资格。
- 资产 ID、版本、血缘和句柄只用于定位，不是权利证明。成员角色或资格变化不改租户身份、历史作者与既有归属。
- 调用方给出操作所代表的主体、明确的资源范围与当前资格；不从进程、连接或当前目录补租户，提供者不借自身权限替原主体访问别的租户。资产的受信能力与原始 SQL 存储是部署接口，面向租户的装配先核身份资格再交命令；提供者不从资产名字推断官方能力、组织政策或用户授权。

### 创作归属、定义与发布

- 人在组织范围合法创作的资产归该组织，在自己租户范围创作的归该租户；作者保留创作时的租户身份。官方资产的作者与所有者是平台，不补造租户。Agent 的产出归它合法提交的工作区或租户，不能直接产出组织资产，也不能替人提升。
- 发布前通过共同校验与类别校验；发布形成不可变版本，之后的修改是新草稿与新版本，不覆盖已发布字节。同一资产与版本对应的类别、名字、正文、来源与声明不可变，同一版本换内容是版本冲突。过期的草稿编辑不能静默覆盖已确认的修改。
- 发布与选版分开。持有固定一个版本或跟随当前版，不指定时跟随。固定版不因新版发布暗换；跟随者在后续求值采用当时的发布版。新的选择只作用于之后的采用点，不改已捕获的调用内容。会话里常驻工具的跟随另有条件：只在新定义与会话首次装载的定义同形时才跟，这条归 Tool 的[定义、采用与常驻](../tool/SPEC.md#定义采用与常驻)。
- 发布以预期的资产修订为条件，读到的修订不预留；同一版本原样重发不改任何东西，也不让最新版指针后退。资产修订、持有修订与拥有者序号是三个计数。跟随持有的拥有者修订随所跟版本的发布而变，固定持有不随别的版本发布而变。
- 类别校验、来源或存储不可取得时答可辨的依赖失败，不报告发布成功，不把未核验内容当成合法的空定义。
- 定义可以声明不可替换（immutable）。它只作用于合法采用该版本的那一层以下，不阻止声明它的那一层自己修订草稿、发布新版、禁用或移除，也不自动锁定设置、权限或引用。更具体的层发布同名的资产被拒绝，什么都不发布，见「发布到租户这一层」。声明出现之前就已经在持的同名持有不被删除，求值时出局。

### 持有、启禁与移除

- 加入持有要有该层的管理资格与合法权利依据：组织层要组织持有管理资格（由治理模型映射到角色），租户层由本人管理。能使用资产不等于能管理组织持有。加入只让属性可配，不保证会被选入或能执行。
- 新持有是启用的。禁用保留持有、所选版本、全部配值与原回执；管理视图仍列出它，运行视图拒绝它；有权者仍能改它的配置。再启用只解除本层自己的禁用，不解除外层禁用，也不授予执行许可。禁用是持有的一个事实，不是某个配置项的值。
- 移除结束持有且不可逆：同一持有身份不能再被持有或选用，新持有用新身份，不继承旧身份下的设置值。移除不删除设置值与操作结果，但它们退出有效集合。配值写入与移除竞争时，不能报告一个已不存在持有上的有效配置。
- 按能力身份（类别加名字）能读到本域里正持有的那一份，读法是 `readHeldCapability`。它的答复与按持有引用读（`readHolding`）同形，规则也相同：带所选版本的持有、明确的没有，或拒绝。一个域里同一身份至多一份在持的持有，所以至多一个答案；已移除的持有不算在内。还没有任何记录的域答没有，别的域的请求答被禁，存储读失败是拒绝，不是没有。一次读最多读五行：域记录、持有的索引项、持有、资产与所选版本。
- 改版、移除与退役先识别受影响的引用与消费者，不默认级联删除日程、Agent 定义或其他资产，也不把治理变更当成实际工作已停止。官方能力不得清空或禁用，守它的位置见「租户层的管理」。

### 合法候选与替换

- 求值消费明确的组织、租户与可选工作区，依次做禁用过滤、当前使用资格过滤和同身份选择，并保留过滤原因、来源、版本与锁定依据。被禁用或没有使用资格的更具体候选不遮蔽其他合法候选。
- 普通适用顺序是官方、组织、租户、工作区。过滤之后，按层序识别定义的不可替换声明与持有层的替换锁，再选不违反约束的最具体实现。约束只向更具体层生效；同一份资产在下层继续持有不算替换。
- 工作区里共享与本地是同一层，先各自过滤，合法的本地同身份候选优先，没有合法本地时保留共享候选。目录名与地址不构成身份、访问资格或租户私域。
- 替换不移交原资产的设置值、锁定值与凭据。同身份上的锁定权限上界与主动配置的不允许操作继续约束替换件。合法更新失败时不发布混合新旧输入的半份候选。
- 官方能力身份求值为空是缺陷，不是成功配置。meta 能力、官方 Agent 定义等类别例外各自保护。
- 装配选入的能力身份与解析它的实现分开维护：自动继承只开放某层的能力名单，不屏蔽更具体层合法的同身份实现；对能力身份的排除不因换实现失效。继承规则归 Agent 与装配，不推广到所有类别。
- 上面的次序由纯函数 `evaluate` 实现，它只消费调用方交来的事实，不读任何外部状态。输入是从最宽到最具体的有序层：每层带一个不透明的标签，资产不定义层的类型；层的状态是不适用、读不到，或读到一组同名候选。另给一个使用资格的判断，答是、否或不知道。不适用的层当它不存在。被禁用的候选不再问资格。同一层有几份站得住的候选时，取列表里的第一份。
- `evaluate` 的答复三选一：胜出者（哪一层、哪一份），连同每个出局者与原因（禁用、没有资格、被截住，被截住时带截住它的上层标签）；没有胜出者，仍带出局者；读不到，带那一层的标签。任一层读不到，或任一份未被禁用的候选的资格答不知道，答复都是读不到，不跳过：读不到的那一层可能有一份该胜出的候选，也可能有一道禁用。官方能力求值为空是缺陷，报告它是调用方的事，`evaluate` 只如实答没有胜出者。

### 类别提供方与正文

- 类别提供者列出候选并按层值决定的版本交出正文；它不决定本次采用。求值本身不带版本，版本由层值决定。正文一经记入采用依据，同一次执行读的就是这一份，后来的版本不改写它。
- 同一身份没有合法定义时答缺合法定义，资格不成立答候选被拒，类别没有拥有者答无类别拥有者；都不交出空正文。
- 类别是服务端的树上点 `assets.categories` 上的一项：键是类别名，一项的内容就是这一类的贡献；共同的规则见[拓展点的共同契约](../../docs/architecture/cross-cutting-concepts.md#拓展点的共同契约)。一份贡献是正文契约、显示声明（名字与一句说明，都是非空文本；另可带给人看的一行新建提示 `creation`，与给动手写的人看的 `authoring`：这一类怎样写，完整的一份可照抄的例子，几行文本）与这一类的定义放在哪个点上（`point`），另可带一个声明「不经通用入口新建」，另可带这一类自己答的影响与生效情况（`effect`，见「给 agent 的工具」）；显示声明与这两样都不进能力身份与持有引用。空类别名、空的点名、正文契约复制不了的贡献抛装配错误。贡献由贡献它的插件放上，跟着它的作用域，卸下就撤走，只撤自己那一份；撤走不改写、不删除持有、版本与设置值。所有租户看同一组类别，租户不能登记类别。资产的成员不认识任何具体类别。
- 类别的读法 `CategoryView`（`lookup`、`describe`、`atPoint`、`effectOf`、`list`）每次从登记表现读，不另存一份；变化的通知发出时读到的已经是变化之后的类别。同一个类别有两份贡献、两个类别写了同一个命名空间、或两个类别写了同一个点时，放它们的插件都照常就绪，这几个类别都不生效：`lookup` 答没有，`list` 不列，`describe` 答「不可用」并写明是冲突与撞的是谁，两份贡献的判断都不被调用。撤掉多出来的一份立刻恢复。点读不出时 `describe` 也答「不可用」。`atPoint(点)` 答这个点是哪个类别的点：那个类别的列表项，或它「不可用」，或没有类别写这个点；登记表读不出时对任何点都答「不可用」。发布、列出、开始上传与查看一个类别遇到「不可用」时答依据不可用，不答未知类别。命名空间在全部类别里唯一，因为有的来源根只能凭目录名认出类别；一个点只放一个类别的定义，否则名字会互相撞。
- 类别登记时连同它的点一起声明：类别服务的 `contribute(贡献, 点的规矩)` 把这两样在同一个效应里放上，点声明着的时间就是类别登记着的时间。点的规矩由 `heldPoint` 给出：键是定义的名字，一项是一份在持的定义（见「列出与取候选」），同键多项时给树看的读法是最具体的胜出。类别名与工具的点 `tool.tools` 的键公开（[规矩](../dynamis/SPEC.md)写键公开），随[可用性的观察](../access/SPEC.md)到客户端；别的类别的点不公开。类别服务依赖这棵树的登记表服务 `dynamis`，它不在时类别服务不启动。
- 不带登记表的用法有内存里的 `createCategoryPoint`：一份贡献的列表，读法是同一个函数。
- 正文契约可以另交一个纯函数 `summarize`，从一个版本的正文算出[资产简介](../../.meta_harness/design/ubiquitous_language/terms/capabilities-and-composition.md#ul-asset-summary--资产简介--asset-summary)：标题、一句说明、若干条名字加文本的事实。输入是版本记录里的正文（目录型是 `inspect` 投影出的声明）。资产在发布时调用它，结果与版本在同一次提交里存下，随版本不变；读的时候不再算。各项有上界，超出的按码点截到上界；函数抛出或交回的形状不对时这个版本没有简介，发布照常。没有交这个函数的类别，版本没有简介。简介只是文本，资产不解释它，界面只当文本显示。
- 每次用到类别时现查，不在启动时固化。类别不在时，拓展点只是查找答没有；要用这一类契约的读取各自答：发布答未知类别，读包答不可用，启动恢复推迟这一份。设置项的列出、查看、设置与清除用的是发布时存下的设置定义，不用契约，类别不在时照常。正文先经一次读取得到冻结副本，判断只接受这份读取结果，对象字面量与伪造的种类被拒；判断不调用传入的函数。判断失败之后，派生声明与引用抛出同一次拒绝的原因。
- 正文是目录的类别在 `BodyContract` 里另交可选字段 `layout`：命名空间、文件数与单个文件和整包字节的上限，以及 `inspect`。`inspect` 读一个包，检查并投影出声明。每一层一个根，根下每类别一个命名空间，命名空间下每个名字一个目录；类别不认路径。
- 读口 `PackageReader` 是一个包的只读面，只有两步：取清单，与按清单里的路径和摘要读一个文件。它读不出清单之外的东西，字节与摘要对不上答材料不可用，不交任何字节。读口分两步取得：能力标识先经求值得到资产引用与版本，再按 `reader({ assetRef, version })` 要这一版的读口。
- `withinDirectory(包, 子目录)` 给出一个包里一个子目录的读口：清单只有这个子目录下的文件，路径相对这个子目录；读文件时路径不合规矩（空、以 `/` 开头、带 `.` 或 `..` 段）答条目不在，不问原来的包。
- 一个目录合不合一个类别的正文契约，只有一个函数判：`judgePackageContent(契约, 读口, 名字)`。它取清单，核路径与这一类的上限，叫 `inspect`，拼出正文，算包摘要，再叫 `judge`，交出清单、版本与正文，或第一处不合格的原因。发布与上传的提交调它；别的领域要判一个目录是不是这一类的合格内容时也调它，不另写一遍。
- 已发布版本的版本号就是清单的包摘要，算法只有一个，由资产的 `packageDigest` 给出，别的成员导入它，不另写一份。它按包内路径的 UTF-16 码元序取每个条目的路径与条目摘要，条目摘要由 `digestBytes` 对字节算出。大小不进包摘要，因为条目摘要已经固定了字节。
- 已发布的包只由发布写入，写入后不变；发布按操作身份幂等。单机怎样存放、发布与恢复见下一节。

### 列出与取候选

资产给出两样与类别无关的只读能力：按类别分页列出一层在持的资产，按能力身份给出一层的候选。两样都是每次调用现读的视图，不是启动时建好的索引，资产不缓存它们。两样都不判披露资格与使用资格，资格照旧由调用方交给 `evaluate` 的判断回答。

- 层的名字与次序只在 `ASSET_LAYERS` 定一次：官方、组织、租户、工作区。这个次序就是求值的适用次序。
- 每一层的事实由这一层的来源 `AssetLayerSource` 给出。每一层的来源形状相同：`layer`、`list({ category, after, limit })`、`candidates(capability)`。`candidates` 的答复就是求值的 `LayerInput`：不适用、读不出，或读到一组候选。
- `list` 的答复也分三种：这一层不适用、读不出，或读到一页 `{ items, next, completeness }`。请求不合法时答非法，它不是层的状态。`limit` 是 1 到 `MAX_ASSET_PAGE`（100）的整数，超出时答非法，不截成成功。条数没有硬顶：一类有多少份，都能一页一页读完。游标是不透明的文本。
- 列出的一条 `AssetEntry` 是管理视图的一条：能力身份、层、资产引用、选中的版本、选择方式（跟随或固定）、启用与否。被禁用的在内，已移除的不在。列出不做求值。
- `collectCandidates(sources, capability)` 按层的次序向每个来源取一次候选，给出求值要的各层输入。答复的层标签取来源自己的层。来源的承诺被拒时，这一层记读不出。缺的层不补，求值把没有的层当作不适用。同一层给了两个来源是装配错误：函数抛出 `TypeError`，不问任何来源。
- `listAssets(sources, request)` 把各层的列出接成一个跨层的分页。它按层的次序一层一层翻，游标记着翻到哪一层与那一层自己的游标。
  - 一层不适用时跳过它。
  - 一层读不出、或它的承诺被拒时，整页答不可用并带出这一层。它不跳过这一层，已读到的条目也不交出。
  - 一层答非法时，整页答非法。
  - 任何一层的页标了部分，整页标部分。
  - 一层的页带着下一页时，这一页就此交回。一层翻完而这一页还没满，就向下一层要剩下的条数。
- 候选从类别的点上读，见[候选与登记表](../../docs/domains/assets-and-rules/architecture.md#候选与登记表)。点上的一项 `HeldItem` 是资产引用、版本、禁用与否与两把锁，就是求值的一份候选。层与作用域的对应只在 `scopeOfLayer` 与 `layerOfScope` 定一次：官方层是空路径，租户层是 `['tenant', 租户]`；组织层没有定，工作区层不进登记表。`layerInputsOf(读出的条目, 租户)` 把一个租户在点上看得到的条目分成官方与租户两层：别的租户的条目与认不得的作用域不进任何一层，同一层里内容相同的两项算一份，点读不出时两层都答读不出。
- 一项可以多一栏 `within`：这份定义的正文在这一版的包的哪个子目录，没有就是整个包。比较两项时也比它：同一版的整个包与它的一个子目录是两份候选。点的声明不列这一栏（直接持有的项没有它）。一份 plugin 带着的定义就是这样一项，由装载这份 plugin 的一方放在持有它的租户的范围里。
- 官方范围的条目由带来定义的一方经类别服务的 `bring(点名, 条目)` 放上，放的人是调用的那一方；每一项连同它引用的那份正文一起带来；目录型类别的一项可以另带这一版的文件（一个 `PackageReader`）；正文、文件与条目同一个作用域撤下。类别服务的 `official()` 答此刻登记着的类别的点上全部官方条目，各配上带来时的正文，带了文件的连同文件，按类别与名字；点读不出答读不出，不答空。租户范围的条目由本机提供者对上：提供者有一个可选的口 `held`，每次提交有变化，它把这个租户全部在持的读一遍并告诉这个口（`sync`），等它返回才把提交的结果交回，并且先于「变了」的信号；认回一次回执丢了的提交时也告诉。读与告诉排成一队，后一次不带着更早一次读到的内容。告诉不成（读不出，或对方抛出）时提交的结果照实交回，并经 `missed` 说明。打开一个租户的资产的一方调 `syncHeld` 告诉一次。
- 类别服务的 `holdingsOf(租户)` 是这个口的另一头：把收到的全部持有与上一次放的比，变了的换，没了的取走，没变的不动。条目的作用域只取自打开的是哪个租户的资产。类别没登记或不可用的持有不放，并告诉调用方是哪一份；这个类别在这个租户那一层读成读不出，不读成没有，类别登记上之后要把这个租户的持有再对一遍。取走一项不成时这一项仍记着，下一次再取。被禁用的持有仍在点上，带着禁用。
- 一个租户的官方与租户两层由 `heldLayerSource` 造，一个部署只给一处，各类别都用它；工作区层照旧是并在后面的另一个来源。租户的资产打不开、上一次没能把持有告诉登记表、类别不可用或点读不出时，候选答读不出，不答空。不带登记表的用法有内存里的 `createHeldBook`，记下提供者告诉的持有。
- 租户这一层的列出是本机提供者的 `tenantListing`。
  - 列出读 `listHeld`：在持有的部分索引上按类别前缀做区间扫描，按名字升序，一页在一次快照里读完，完整性总是完整。这个读有自己的读处理器 `assets.list`，一次至多读 `3 * MAX_ASSET_PAGE + 2` 行：每条三行，索引项、持有与所选版本的资产简介；简介单独存放，列出不读版本的正文。行数上限只为它放宽，别的读仍是一次最多五行。
  - 版本读 `listVersions`：列出一个资产的全部版本号，在版本键上按资产前缀做区间扫描，按版本号升序，每页至多 `MAX_ASSET_PAGE` 个，带续页游标，一页在一次快照里读完。它与 `listHeld` 共用读处理器 `assets.list`，不读版本记录与正文。没有版本的资产答空的末页；读不出答不可用，不答空。版本记录里没有按时间排的键，所以不按新旧排；要找某一版的调用方翻完各页、逐个按键读版本。资产不解释版本里的设置声明，按声明找版本的匹配由调用方做。
  - 全部在持的读 `held`：给提供者告诉 `held` 这个口用，按类别与名字的次序分页，每页至多 `MAX_ASSET_PAGE` 条，读完为止；与 `listHeld` 共用读处理器 `assets.list`。每条是类别、名字、资产引用、所选的版本与启用与否。
- 偏离：租户这一层的候选上，`immutable` 与 `replaceLocked` 总是否。持有与版本的记录里没有它们的来源，所以租户这一层的候选不会截住更具体的层。记录有了来源之后，候选照记录给。
- 偏离：组织层没有来源。工作区层的来源覆盖有布局的类别：技能、工具与 Agent 定义。模型提供方的点上有官方与租户两层的条目，但这一类不做跨层求值：租户持有的模型提供方定义不会被用上。

### 已发布的包

本节是单机的存放办法，由 `assets-local` 实现。`createAssetsLocal` 的选项 `packageRoot` 是本域放包文件的根目录：一个域一个根，由调用方保证，根下没有租户子目录。没有配根时，这套装配根本没有本地目录：发布答被拒（未配置），读口答不可用，`locate` 答没有，恢复扫描什么也不找。这不是未知。

- `packages` 给四个操作。`publish({ capability, assetRef, from, operationId })` 发布读口 `from` 给出的包。`reader({ assetRef, version })` 给一个版本的读口。`recover()` 是启动时的恢复扫描。`locate({ assetRef, version })` 给一个版本在本机的目录，或答没有；它只在本成员里，不在资产契约里。
- 发布依次核：配了根；类别已登记并交出 `layout`；清单的每个路径落在包根之下（没有空段、`.` 段、`..` 段，没有反斜杠与 NUL），没有重复，也没有一个文件同时是另一个路径的父目录；文件数、单个文件与整包的字节没有超过 `layout` 的上限；`inspect` 接受这个包；类别的 `judge` 接受正文与能力名。路径与上限只用清单核对，不读字节。
- 版本记录的正文是 `inspect` 投影出的声明（必须是对象，且自己不带 `manifest`），加字段 `manifest`：每个条目的路径、大小与摘要。正文有 1 MiB 的版本记录预算，超出时拒绝，不截断。记版本与持有走一次「发布并持有」（`publishAndHold`），带发布开始时读到的资产修订提交。
- 发布被拒的原因是封闭的：未配置；类别没有登记；类别不是目录类别；超出上限（说明是文件数、单个文件还是整包）；包不合法（带规则名）；读口失败；版本记录拒绝（带记录的原因）。任何一种都不留下暂存，也不记版本。
- 读口按键读一个版本记录，类别与名字取自记录。一个读口只读一次记录并记住它；文件在不在每次再看，因为它可能随后才换入。读口先读资产再读版本记录：没有任何记录的域读版本答被禁，读资产答没有。清单取自记录；`open(path, expected)` 先核位置上字节的摘要，再交出这个路径与这个摘要的条目。清单里没有这一条答条目不存在；位置上的字节与清单不符，或版本目录不在，答材料不可用；记录读不出或记录的类别不在，答不可用；没有记录，或记录读不出清单，或类别在而没有 `layout`，答没有这个包。
- `locate` 是异步的，因为它要读版本记录。记录读不出时答不可用，从不答没有，也不抛出。
- 版本与这个租户这一层的持有在同一次提交里写成，持有的三种情形见「发布到租户这一层」。
- 存放：文件在 `<根>/<命名空间>/<名字>/<版本的目录名>/`。版本是 `sha256:<十六进制>`，冒号在 Windows 上不是合法的文件名，所以目录名写成 `sha256-<十六进制>`（`versionDirectoryName`），版本本身不变。版本目录按内容寻址：同名就是同一内容。每个命名空间目录里有一个文件 `.category`，写着类别名，在第一个版本换入之前写好；恢复扫描靠它认类别。发布先把文件放进暂存 `<根>/.staging/<操作标识的摘要>/files/`。换入不删旧版本，旧版本的目录留着。
- 次序：发布是有次序的流程：暂存，换入，再一次提交写版本与持有。换入是一次目录改名，在提交之前，所以记下的版本，它的目录一定已在。版本目录已在（别人换入过同一内容）就丢掉自己的暂存，当作换入完成。提交被拒，或换入之后、提交之前崩溃，留下一个没有记录的版本目录：读者沿记录找版本，看不见它；它只在恢复扫描里删。
- 落盘：记下的版本承诺文件在，所以字节与目录项要先于提交落盘。暂存里每个文件写完即落盘，然后落盘暂存里各层目录、暂存目录与 `<根>/.staging`。换入时，`.category` 写完落盘，改名之后落盘版本目录的父目录、命名空间目录与根目录，之后才提交。实现是 `createPublishedPackages` 输入里可选的 `durability` 端口（装配选项里叫 `packageDurability`），缺省 `nodeDurability`：文件用 `FileHandle.sync()`，目录以只读打开后再 `sync()`。Windows 做不了目录落盘，目录那一步照实跳过。这是对[项目要求](../../docs/requirements.md#已确认业务事实的持久性sys-durability)「断电之后保留已确认的事实」的偏离：在 Windows 上断电之后，记下的版本的文件内容在，目录项不保证在；持有可能指向一个不在的版本目录，读口答材料不可用，不答成别的版本。
- 按状态看发布、读与恢复扫描，下面都是类别在时的结局，类别不在时见读口与恢复扫描两条。状态是这个版本在记录与磁盘上的样子：
  - 没有：不合格的包被拒，什么也不变；合格的包依次暂存、换入、提交。读答没有这个包。恢复扫描什么也不改。
  - 已发布：同一版本再发布不再写版本，持有已经指向它时什么也不写，答 `changed: false`；新版本照「没有」走。读交出内容，位置上的字节不符答材料不可用。恢复扫描什么也不改；版本目录里的文件若算不回目录名里的摘要，报在 `mismatched` 里，原样留着。
  - 只有暂存：读看不见暂存，答没有这个包。同一操作的再发布先清掉自己的暂存，不动别的操作的暂存，再照「没有」走。恢复扫描清掉暂存，计入 `discarded`。
  - 换入了、没有记录：读沿记录找版本，答没有这个包。同一内容再发布时目录已在，丢掉暂存后提交。恢复扫描删掉这个版本目录，计入 `discarded`。
- 操作身份：同一操作标识的再发布认回已提交的回执，答同样的结果，不写任何东西；回执已成时版本目录一定已在。回执是未知答未知；回执是被拒，答同样的被拒或冲突。
- 并发与失败：同一资产同时发布两次，提交核对开始时读到的资产修订，后到的一方答冲突，并清掉自己的暂存；它换入的版本目录若没有记录，留给恢复扫描删。发布流程自己认得的失败（拒绝与冲突）清掉本次操作的暂存。其他失败答未知并带操作标识，暂存留着：调用方用同一标识再问，崩溃由恢复扫描处理。选项 `afterPackageStep` 在暂存之后与换入之后各运行一次，它抛出就代表在那一点崩溃，只给测试用。
- 恢复扫描只清不补：删掉全部暂存，计入 `discarded`；再找没有记录的版本目录，类别在的删掉，计入 `discarded`，类别不在的不动，把它的身份报在 `deferred` 里，类别装回之后的下一次扫描再处理。删版本目录只在恢复扫描里：那时没有在途的发布。这一点的前提是每个域只开一份本机资产；两份各自扫描，会删掉对方刚换入、还没提交的目录。读不出记录时扫描抛出，不当作没有记录而删目录。不符的版本从目录出发找，不从记录出发：版本是清单的包摘要，所以一个版本目录里的文件必须算回目录名里的摘要。它报告的身份是命名空间的类别与目录名里的名字。没有 `.category` 的命名空间与以点开头的目录（包括暂存）不当作版本目录扫。不符的版本只报告，不改。

### 资产上传

[资产上传](../../.meta_harness/design/ubiquitous_language/terms/capabilities-and-composition.md#ul-asset-upload--资产上传--asset-upload)是目录型的内容在发布之前的落脚处，由 `assets-local` 的 `uploads` 实现，与 `packages` 并排。服务端不按客户端给的路径读自己的文件：目录的内容只经这里送达。

- 身份是租户加操作标识。开始时申报能力身份与清单：每个文件的包内路径与字节数。开始依次核：类别已登记、是目录型、没有声明不经通用入口新建；清单的路径合「已发布的包」里的路径规则；文件数、单个文件与整包没有超过 `layout` 的上限。这些只用清单核对，不读字节。被拒的原因说明是哪一条规则、哪一个上限。
- 同一操作标识再开始：清单相同就答各路径已收到的字节数，从那里续传；清单不同答操作冲突。
- 追加带路径、偏移与一段字节。偏移等于这个路径已收到的字节数、且追加之后不超过申报的大小时写入，答新的已收字节数；偏移不等时不写，答现在的已收字节数；超过申报的大小、或路径不在申报里，答不合法。所以重发同一段不改任何字节，收齐的文件不再变。没有这个上传时答没有，客户端从开始重来。
- 一段的上限由入口的大小档定，随开始的答复交给客户端；一个文件、一个包大于一段时分几段送，不因此被拒，也不截断。能拒绝的只有类别声明的上限。
- 提交先查这个操作标识的发布回执，有就答它。没有回执时：没有这个上传答没有；没有收齐答不合法并列出缺的路径；收齐就把这些文件作为读口交给「发布到租户这一层」，结局照它的，发布成功之后清掉这个上传。读口的清单由服务端对收到的字节算摘要得出，客户端不报摘要。
- 提交之前它不是资产：列出、读取、求值都沿记录找，看不见它；从它到资产只有发布这一步。发布途中它被清掉时读口读不到文件，发布答读口失败，不记版本。
- 它不是已确认的事实，丢了只需要重传；写入不要求落盘。放置超过空闲时限的由清扫删掉；一个租户在途的个数到了上限时，新的开始先清最久没动的，清不出才答忙。空闲时限与个数上限是装配给的策略，不写死。启动时的恢复扫描不碰它。

### 发布到租户这一层

- 资产给别的领域一个发布服务 `TenantPublishing`：把一份数据或一个目录发布到一个租户这一层并持有。请求带操作标识、目标租户、主体、能力身份（类别与名字）与内容（数据型的正文，或目录型的读口）。调用方不带预期修订，服务自己在开始时读。
- 许不许每次调用问一次：服务声明端口 `TenantActing`，每次拿请求里的主体与目标租户去问，答准许、拒绝或答不了。能为这个租户行事就能发布，不另设权限项。服务不缓存答复，不从调用方的身份或寿命推出答复。
- 结局八种，分开答：`published`（带版本、持有引用与有没有变化）；`denied`；`unavailable`（身份、判定或存储的依据取不到，或暂存、换入抛出）；`unknown-category`；`invalid`（判定不过、清单不合布局或超限、这一类不经通用入口新建，带原因）；`conflict`（修订对不上，或同一能力身份刚被另一次操作持有，换一个操作标识重发）；`operation-conflict`（同一操作标识、不同输入）；`unknown`（带操作标识，用同一标识重发认回）。拒绝、类别没登记与依据取不到是三个变体，不合成一个失败。
- 同名与不可替换：发布之前问一次这个名字在比租户更宽的层上的状态（可选端口 `standing`，由装配从登记表读）。那里有站得住的不可替换条目或替换锁时答 `invalid`，原因 `irreplaceable-official`，不暂存、不换入、不提交；读不出时答 `unavailable`，不当作没有。预览一次发布的效果与发布问同一个函数，答同一个结论。
- 一个租户这一层同一能力身份至多一份在持的持有，发布按能力身份找它。持有的三种情形：没有在持的就新建一份并跟随最新版；在且跟随就只写版本，读者沿跟随拿到新版；在且固定在旧版就改成固定在新版（发布并持有是持有者明说要新版，不是发布了新版就暗换固定）。
- 持有引用在新建持有时由这次操作生成，对调用方不透明，不由类别与名字推出；同一操作重发得到同一个引用。所以一份持有移除之后，同一能力身份再发布得到的是一份新的持有，不继承旧持有的设置值；发布不恢复任何已移除的持有。资产引用是 `<类别>/<名字>`，版本线不因持有的移除而断。
- 类别的贡献声明了不经通用入口新建时，这个服务对这一类答 `invalid`、原因 `creation-closed`：发布服务就是通用入口。随部署安装的持有不走这个服务。
- 发布只写行事的那个租户：持有的范围必须是请求里的租户，跨租户的请求被拒。已发布的版本不变：同一版本内容不同答冲突。
- 每个租户的本机资产只开一份，发布、读包与持有的读都经它；它打开时恢复一次。
- 新建的方式由正文契约推出：有 `layout` 的是目录型，没有的是数据型，形状分别是 `layout` 与 `schema`；给人看的一句说明是显示声明里可选的 `creation`。贡献另有一个可选的声明「不经通用入口新建」，带着代码或别的随部署才有的东西的类别用它；发行里的类别现在都不声明它。三种方式 `none`、`data`、`directory` 由资产从贡献推出，类别不另报。

### 租户层的管理

- 资产给接入与别的领域一个管理服务 `TenantManagement`：按类别分页列出一个租户在持的资产（官方资产对每个租户视为已持有，所以也在里面），按能力身份看一份，按能力身份取在持那一版的文件，发布（上一节的服务，与从[资产上传](#资产上传)提交），启用、禁用、移除。它不持有状态，每次调用现读。许不许与发布相同：每个方法每次调用拿主体与目标租户去问 `TenantActing`，能为这个租户行事就行，不另设权限项；别的租户的请求被拒，拒绝不披露这份资产存不存在。
- 列出的一行是层来源给的那一条 `AssetEntry`（见「列出与取候选」），再加三样：持有引用、[资产来源](../../.meta_harness/design/ubiquitous_language/terms/circulation-and-entitlement.md#ul-asset-origin--资产来源--asset-origin)、[资产简介](../../.meta_harness/design/ubiquitous_language/terms/capabilities-and-composition.md#ul-asset-summary--资产简介--asset-summary)。被禁用的在内，没有设置项的在内，已移除的不在。列出不做求值。先列这一类的官方资产（管理服务的端口 `official`，按名字），再接租户这一层的；租户这一层以官方来源在持同名一份时（随部署安装进库的，如工具），只按租户这一层的那一行列一次。官方的一行：层是官方，固定持有，启用，持有引用就是官方资产引用，来源官方，简介由类别契约的 `summarize` 求。游标分官方、租户两段，只认列表自己给出的游标，别的答无效。类别没有登记答未知类别；读不出不答成空（官方读不出、租户这一层答不出在不在持某一份官方资产，都答依据取不到），一页不全标不全。
- 看一份答这一行、持有的修订、内容、求值的结局与它有没有设置项；这个能力身份在这一层没有在持的持有、而有一份官方资产时答那份官方资产（修订 0，内容是它的正文，有没有设置项由类别契约的 `settings` 判），两边都没有时答没有。内容：数据型是所选版本的正文；目录型是清单里每个文件的路径与大小，不含文件的字节。求值的结局由 `collectCandidates` 与 `evaluate` 对这一个能力身份现算，用的是存储给出的那几层（官方与租户），与这一类实际被用时求值的是同一组层；结局说的是这一份持有，别的层的一份胜出不算它在用：胜出、出局（禁用、没有资格、被截住）或读不到。
- 取在持那一版的文件（`files`）：目录型答这一版的包（`PackageReader`），数据型答正文，都带版本；这一层没有在持的持有时，有官方资产就答它：带了文件的答这一版的包，没带的答正文；都没有答没有。准入与看一份相同；不许行事答被禁，存储读不到或抛出答依据取不到，不答成没有。随部署安装的在持照样读得出。层存储 `TenantLayerStore` 有同名的读口，按类别有没有目录布局决定交包还是交正文。
- 随部署安装是类别中立的一步：把发行带来的正文发布进租户的资产库，建这一层的持有，钉住这一版，持有的来源记为官方。需要租户层普通设置的官方资产经它进入每个租户，发行的工具与模型供应商都是；类别自己的事（例如工具的治理声明）在它之后各做各的。发行换了正文时发布新的一版并改钉；设置定义没变时，已有的值照旧有效。
- 资产来源由持有的来源记录读出：租户经发布服务得到的持有是自定义的，随部署安装的持有是官方的（官方资产对每个租户视为已持有）。官方的持有不许禁用、不许移除，这两个动作答不可改、原因官方；指向一份官方资产引用的启禁与移除也这样答；它由管理服务守，因为这是人能禁用与移除的唯一入口。
- 启用、禁用、移除按持有引用指，不按能力身份指：人看到的那一份被移除又重建之后，旧引用上的启禁答不可改、移除答没有变化，都不落到新的那一份上。结局分开答：成功；没有变化（已是这个状态，或对已移除的再移除）；没有这份持有；不可改（官方，或已移除的不能再启禁）；被拒；依据取不到；冲突（提交时修订对不上；调用方重读之后用新的操作标识再来）；操作冲突（同一操作标识、不同输入）；不知道（带操作标识）。服务自己读修订，调用方不带。
- 每个提交类的动作按操作标识幂等：同一标识重发答原来的回执，不再写；结果不知道时按同一标识查原结局，答原结局、还没提交过或没有这个操作。
- 移除不删已发布的版本，也不回收它的文件。
- 禁用或移除提交之后，之后的每一次读都看到新的状态：管理视图与候选每次现读，没有一处缓存持有。
- 偏离：移除之前不列出受影响的引用。引用没有反查，所以界面与命令行在提交之前只说明移除不可逆、设置会退出；移除不级联删除别的资产，也不停掉独立的工作。
- 只凭操作标识认回：`recallById` 不要调用方说出原来那次是什么，只带操作标识，答原来那次是哪一种与它的原结局。发布带能力身份与版本；启用或禁用带持有引用、能力身份与改成了什么；移除带持有引用与能力身份。持有改动的能力身份从持有的记录读，读不出时为空，持有引用照给。准入与 `recall` 相同；只认这个租户这一层的操作，别的租户用过的同一标识答没有这次操作。服务判为没有变化、没有写入的那次改动不留操作，也答没有这次操作。层存储 `TenantLayerStore` 有同名的读口，只读不写。

### 组合与流转

- 组合引用能力身份，按完整作用域解析当前合法实现，引用不转移所有权。Plugin 内含成员随 Plugin 的版本与权利治理；无终点的 Agent 定义递归在采用前拒绝；Skill 与 Tool 的配套互引不算递归。Plugin 成员的启用值在展开该 Plugin 时先求。
- 外部引用不因打包、复制或分享变成目标所有；Plugin 内含成员没有单独的顶层卸载。复制或分享发起时核对目标侧有没有外部引用的提供者，缺的当时告知；这条不新增流转的拒绝政策，也不把未知当成不存在。
- 复制、分享与提升都是只有在条件共同成立时才成立的一次操作，按原操作身份认回，不因重试多出一份 v1 或一个版本，不携带源的配值与秘密。复制建立独立资产与同源血缘；分享在确认前没有使用权，成立后跟随源的当前发布版，所有权不动；提升改变所有者且不可逆，Agent 不能发起或确认。流转的方向、确认人与发起资格归产品设计的[流转规则](../../.meta_harness/design/product/assets-and-rules/design.md#与他人协作时选择复制分享或人工提升)。
- 确认与撤回、到期、关系解除竞争时只成立一个终态，不出现既结束又可用的关系；一名确认者失去资格只拒绝他自己的确认。分享只能跟随，接收者只能配本层值、合法替换或移除，不能改内容、复制、再分享或提升。已结束的分享不因重新加入、重新隶属、旧备份或重放的通知复活，重新发起是新关系。

### 设置：声明与目录

- 功能或资产类别拥有每项设置的含义、类型、合法值、默认或无默认、清除后果与采用时点；设置拥有配值与求值。资产设置随当前合法定义派生，不维护第二份字段目录；独立设置从它自己的固定定义与配置目标投影，不伪造资产持有。
- 每项设置属于偏好、绑定、落点与身份、治理四类之一，来源资格按类别核验。功能拥有者只声明自己功能的设置，不借此取得别的配置目标的管理权。
- 定义身份是提供者、定义、精确版本与内容摘要；同版本不同摘要拒绝，不 last-write-wins。摘要由服务端计算，客户端自报的摘要不是事实。数字要有单位与上下界，枚举要逐值解释，默认值过同一 Schema；递归引用、远程引用与正则约束拒绝；输入有深度、节点、文本与项数上限。必要元数据缺失的声明不发布。
- 声明给出可读的名称与用途、默认或无默认、清除后果与采用时点（立即供后续读取、下一业务边界、显式 reload 或创建时初始化，由功能契约选）；本地化缺失时有可读的后备文本。内部键不代替说明，声明里的脚本与 HTML 不执行。客户端的条件显示不承担授权，服务端执行全部校验。
- 分组只管呈现，不决定配置优先级、权限或事务范围；多层分组无环、有深度上限。同组的项可以来自不同目标，跨目标的批量保存不是一个原子操作。
- 同一资产新版的项要重新核兼容，不按同名直接继承。相容不只看版本字符串或 Schema 能否解析：项的含义、目标、动作与参数的解释、关口与权限影响都要相容；没有可核验的变更映射就不自动沿用。默认值变了按当前定义求值，已保存的值仍要满足新约束。
- 可核验的变更映射只有一种：定义的拥有者拿新旧两份定义逐项比，一项的声明一字不差就算这一项没变。一项的声明就是它的全部含义，声明不变时值照旧有效；要让人对一项重新做决定，就改这一项的声明，只改背后实现的行为不算。设置定义的版本只由它的内容推出，内容不变时新版资产沿用同一份设置定义，已有的值无须迁移；内容变了时由拥有者做显式 rebase，没变的项保留，变了或删去的项丢弃，回到缺省。
- 目录按明确的部署与逻辑服务范围、受信主体、目标范围和视图模式返回。管理视图包含可配置但未启用的资产；运行视图只消费调用方核验过的选择，不自己挑目标。登记、合法目标、提供者在线与执行实例存在分别报告。
- 目录捕获每次核验代租户主体并取得新的资格预留，在一个租户事务里读目标拥有者投影与配值；每页重新捕获，依据、查询或登记代际变了答 `basis_changed`，不混代续页。声明缺失的条目从管理视图略去并标 `partial`，运行捕获缺声明答不可用；部分目录不当完整目录用，空目录本身不证明完整。无权查看的目标或项不在错误里泄露。普通目录不返回秘密明文。
- 一次捕获的目标数与字节有上界，超出时拒绝，不截成成功。
- 管理视图不点名目标时，捕获扫这个域里的全部持有，调用方排除的类别除外；排除的类别的持有不进这次捕获，也不占上界。调用方排除的是拥有者明说没有设置的类别，资产不认识具体类别的名字。一类撤下后不在排除之列，它的持有照常捕获：撤走不动数据，设置照常列出。
- 目录捕获是受保护的读：同样经资格预留与目的地封口，确认 committed 结算之后才交回依据，被先行封口的捕获不能成功。它不推进配值修订，不授予写权。
- 一次捕获的用途在 committed 结算时结束：各次捕获的操作号随机，之后没有读者认它的记录。结算之后的预留由本组在这个窗口结束时释放：捕获先向 Identity 释放自己的预留，再发一次 `recall: 'never'` 的清理提交，删掉这次捕获的终态行，并用 `releases` 放掉它的 `settings.capture` 与 `settings.catalog-seal` 回执。释放或清理失败只记一条警告，读照样成功。终态行最后删，所以失败时它还在：同一份目录下一次打开后的第一次捕获，先逐条处理还在的终态行。预留不在的只做清理；预留还持有或已结算的，先经 Identity 结算，结算得出终态再释放与清理；其余的留着，下一次再试。没有走到结算就中断的捕获，也由这一步结算并清掉。aborted 的捕获只在这一步清，不在捕获自己的路径上清：它的终态行挡住还可能迟到的消费。
- 捕获里点名的目标缺失或已退役时拒绝，不从成功的完整结果里略去。已退役的独立目标读出来是已退役，不是不存在；读不出或存的数据不合形状也不变成不存在。持有的资产所选版本没有设置声明时，它不是设置目标，管理列举略去它，不连累别的设置；所选版本缺失或损坏仍答失败。

### 设置：配值、清除与锁定

- 写入在条件提交边界核验当前资格、目标、声明版本、项存在、取值合法、锁、允许来源与预期配值修订。资产目标还核合法持有，独立目标核实际管理关系。失效编辑、无资格或不合法时当前事实不变。预演变更（`previewChange`）只读，不预留资格，不占修订。
- 资产的属性配值依附具体持有与项：没有持有不能给这份资产配值；组织层配值要组织持有管理资格；会话的局部覆盖归会话契约，不能借它改上层共享的持有。自动归档这类租户级设置依附租户对会话能力的持有。
- 缺省表示本层没提供值；显式 false 是一个值；清除只撤回本层覆盖，重新沿当前来源求取，不等于 false、禁用或固定回退旧默认。null 是否有业务含义由声明决定，未声明时不当清除命令。
- 普通值按默认、组织、租户、工作区、会话的层序取最具体的合法值；有效的外层锁阻止更具体层覆盖。解锁只作用于后续求值。属性锁不锁住整份实现的替换，定义不可替换也不锁住属性。
- 禁用按「任一层为真即禁用」合并，下层 false 打不开上层 true；这条规则不推广到其他设置。
- 会话值不回写租户默认，也不外溢到其他会话；改真正共享的资产配值按原作用域影响其他消费者。创建时初始化的项与其他动态继承项各按会话契约，不把全部设置复制一次后永久冻结。账号偏好独立于组织与租户的资产设置，不参与层序，不授予权限。

### 设置：工作区与同层合并

- 读工作区要有明确选择与合法实例访问关系，不从当前目录补。工作区不提供权限配值，不给其他资产配落点与身份项，不能设属性不可覆盖标记或持有层替换锁；定义自身的不可替换声明不是工作区治理配值，不被过滤掉。
- 共享与本地同层：同项本地显式值优先（包括显式 false），本地缺省才沿用共享值，不对两者取布尔或。选用同名完整本地资产时不再叠加针对共享实现的覆盖。共用实例的本地不是租户私域，求值不读其他参与者租户的私有配值或凭据。
- 工作区可配合法的偏好与绑定，绑定只能指向它求值后可见的对象；工作区自己的禁用只作用于它提供的那批资产。AGENTS 等 Runtime Context 的规范文本有自己的规则，不套用设置合并。
- 本机命令型 MCP 与导入命令型 hook 的启用开关归获准租户自己的设置，默认不启用，工作区资源不能代开；打开后仍守工作区保守权限。

### 设置：投影与生效时点

- 候选求值、装配选入、属性投影、逐项求值依次交接；不依赖还没产生的项集合回改候选。
- 有效值报告保留最终值、采用来源、被过滤或锁定的原因与本次依据。值求出来不代表绑定对象可用、Agent 已装配或动作获准；专有合法集合（如目标模型）仍由类别拥有者检验。
- 工作区资源在实际装配或显式 reload 时读取，不随文件编辑刷新。新 Run 的入口比较采用依据与当时的来源，变了才重装，不无条件重读。候选校验失败不发布半新半旧的有效值。合法的设置变化按该项的使用时点作用于后续输入，不改写已发调用。

### 设置：写入、准备与原操作

- 准备提交端口是配值写入的唯一协议，没有不经准备的直接提交。准备先核实际主体与合法目标，持久保存不可变的根命令与至多一个活跃尝试，不写配值；提交按持久准备取原命令，核调用主体、完整绑定与当前事实，在同一次目的提交里建立业务结果与尝试终态。参数不能替换命令。
- 原操作身份是存储域、主体、完整目标与操作标识；命令摘要排除传输请求标识。同身份同内容重试返回原结果，内容不同答 `operation_conflict`。根的已提交与已中止是不可改写的终态；未知是观察者没取得权威结果，不是持久状态。
- 失败对根的后果：输入无效、无权或绑定不符只拒绝本次请求，不改已有根；已受理且绑定正确的命令在受保护提交中确认修订冲突、定义变化、被锁、不兼容或业务禁止时，尝试终结、根中止，之后重传返回原终态；依据变化只封口当前尝试，普通根仍待决，可以沿不变的原命令重新准备；持有组织来源门的根遇依据变化则封口并中止、清自己的门；依赖不可用或回执丢失时什么都不终结，答未知；每根尝试数有上界，耗尽时根保持待决、可以取消。
- 已终结的根不复活，之后解锁或恢复定义也不重开它；要做新的业务必须用新的操作标识。查询只读根与精确尝试，不封口、不推进、不释放门；查询答「没有这条」只是这一次观察，不证明它永远不会提交。取消只取消没成功的根，已提交时返回原成功。
- 已确认的业务失败是这次事务成功保存的 aborted 结果，不是回滚之后声称的终结。存储给出的明确回滚回执证明这次精确尝试不会再提交，据此封口这次尝试，普通根仍可再准备；准备阶段的回滚本身不是业务拒绝。结果未知时不清理，也不换尝试。
- 封口、结算与恢复只读持久的原绑定，不要求当前治理、当前来源快照或重新取得资格；撤权之后，已受理的原义务照样能完成。根终态与一次精确尝试的终态是两个结果：回应外部保留用这次尝试的终态，不用后继尝试提交的根结果。
- 恢复引用编码在身份的不透明目标引用里，按闭合的种类区分目录捕获与准备尝试；终态键区分存储域、主体、操作种类与精确操作身份。操作绑定的主语同样是闭合的种类：一个设置目标，或一次目录快照；目录快照不是设置目标。不从 ID 前缀推断种类；未知种类、多余字段、非规范编码或绑定不一致一律答不可用，身份侧的 held 留着，不回退到旧的封口。
- 目的地封口只交给身份的受信恢复路由：它核对已保存的原请求，不接受调用方声称已经结束。普通用户与工具拿不到 SQL 存储、目的地或装配写权；多个目的地由装配静态路由，不接受客户端给的路由。
- 当前依据至少含一个具名政策，每个政策只有一种解释；需要哪些政策由受信声明与固定的关口映射决定，客户端不能删减。运行选择需不需要由具名权威决定，空值不是免检依据。
- 准备的检查点与就绪、封口与取消（`settings.<阶段>`），以及独立目标当前事实的捕获（`settings.<规则>-current`），各自的存储事务用随机操作键，按构造没有调用方能凭它认回，所以身份声明 `recall: 'never'`，存储不为它们留回执。这些操作由根与尝试的记录认回。提交那一步的身份是尝试身份，照旧留回执。
- 准备的持久阶段（准备中）先保存恢复身份，再取得外部保留；保留齐备、当前事实与计划相符并保存完整依据之后才答已准备。准备中的存储结果未知时保留原尝试与可能存在的保留，终态之后迟到的保留回包只用于认回与释放。外部保留请求在发起之前持久保存，回包丢失用原请求认回，已结算的保管不退回 held。
- 秘密项的变更在准备分配任何东西之前拒绝，所以秘密值不进入根、尝试、回执与变化记录；准备之后定义把一项改成秘密的，提交时同一规则再拦一次。变化记录不含值，分页有上界，不是目录快照。
- 显式 rebase 是维护动作，不暴露给普通租户或工具：要精确的新旧定义引用、预期修订，并对每个已有配值明确保留或丢弃；保留的值须在新定义与新来源下重新通过求值，不按显示名称匹配或自动转换。定义或来源布局不匹配期间，普通目录与求值不采用旧状态，普通写入拒绝，原操作与变化历史仍可读。定义失配时，值投影另带存着的定义引用与配值状态，供定义的拥有者做 rebase。这份事实只交给受信的参加者与受信的只读投影读，例如发行的安装方对账时读它，不提交。对外的读面与求值照旧答定义已变。不经身份预留、以维护身份直接运行的装配，不在资格保持的论证之内。

### 设置：目标拥有者与来源

- 设置目标是资产目标或独立目标，二者之一。资产目标跟着一份持有；独立目标带着声明它的提供者与定义。种类写在目标里，是目标身份的一部分；每个用到目标的地方按种类穷尽分派，不比字符串，不从类别或名字推断种类。
- 领域经设置的贡献口「独立设置」带来自己的独立设置声明。键是提供者与定义，同键的第二份、带治理项的、带秘密项的声明都抛出，原来的一份不动；贡献跟着贡献方的作用域，撤下只释放这一份登记，不碰目标与配值。
- 每个租户按贡献口的当前清单逐组开通独立目标，用到时现取。同一份声明同时只有一次开通在途：同时用到这一组的几次读等同一次开通的结局，不各自提交。一组的结局是就绪或不可用，互不牵连：一组不可用只影响这一组，别的组、资产设置与租户的治理照常。声明方撤下之后，已开通的这一组照常列出，目标带着开通时的定义。
- 一次值提交需要同一 SQL 事务里目标拥有者给出的当前事实：当前定义、精确定义引用、授予与有序来源。布尔值、先前的准入结论、缺失的事实或调用方断言都不能授权写入。当前事实的生产者与这个目标的全部失效写者共享同一个事务域，漏掉一个写者就不能声称守住竞态。没有资产时，装配显式产出空的资产投影，不伪造资产所有。
- 资产目标的当前事实由资产给：在持的那份持有、所选版本、这个版本发布时存下的设置定义与定义引用、授予与来源。任何在持的、所选版本声明了设置的资产，它的普通设置项都能在这一层列出、写入与清除；禁用的持有照样能写。发行的工具另多一项政策：它的权限项按发行带来的治理声明解释与核对。一个资产目标受不受这项政策管，看它是不是发行带来的工具目标，不看类别名；不受它管的资产目标，写入不依赖治理侧的定义目录与发行的出版事实。没有治理声明的资产目标上若有权限类的设置项，列出与查看照常，写入答不可改。
- 准备、就绪、提交各在自己的事务里重读这份当前事实。提交时持有已移除、所选版本换了而定义引用不同、或这一项不在声明里，这次写入不成立，不留下脱离持有的有效配值。
- 独立目标由受信的拥有者能力开通与退役，不是租户设置服务。退役的目标不能以同一完整身份再开通，退役使它退出投影并阻止之后的写入，保留配值与操作历史。拥有者修订与配值修订是两个计数。
- 来源身份包括 ID、拥有者、作用域种类与作用域主体，布局有序、ID 唯一、个数有上界；不从 ID 推断层级。配值记录保存它采用的布局；当前求值与普通写入要求稳定身份与拥有者投影逐项相等；换拥有者、作用域种类、主体或次序要显式 rebase，同一 ID 下换了拥有者或主体的值不能被继承。资格修订与值修订不互相替代；明确无值、不适用与提供者不可用是不同事实。
- 组织来源的配值在唯一组织来源上持久保存，各租户消费同一来源，不各复制一份。来源保留绑定确切来源修订、原业务操作、目的尝试与稳定目的身份，不授予身份资格或许可。目的未确定终态时保留来源；只有具名目的地建立 aborted 或认回 committed 才能释放，记录不存在、超时、卸载都不是释放证明。
- 来源只经具名映射交给权限：owner 作用域或未知主体不当成缺省的租户，作用域里的主体引用不是授权证明。组织层（系统设置域）的写入另要 `organization-settings-manage` 资格，这类目标的每个来源都是同一组织的组织来源，别的布局答不支持；这份资格管设置的变更，不是 Tool 或 Agent 动作的许可。
- 来源门以完整的设置目标为单位，同时保护定义、来源布局、值与锁，不按配置项或继承的来源 ID 分门。明确的空来源清单与缺失的清单不同，缺失不当空。
- 新的 held 要目的地先认出它已保存的完整请求，猜出的路由建不出孤儿 held。源端没有这条保留时，只能按目的地确认的 aborted 记成已结算，迟到的保留拿到这个终态，不新建 held。只读一个来源不做保留，也不使来源保持不变，要它不变就用保留；读不出不是空来源。恢复的短页不代表结束，按游标读到空为止；读不出的项保留 held，留到下一轮。
- 所有改变来源的写入（首次设置、锁、解锁、删除与 rebase）先拒绝新的重叠保留，再等已有保留结算；提交时重核原管理资格与定义，在同一来源事务写唯一配值、原结果并清精确的门。最终拒绝、合法取消或外部封口当前尝试，与根中止、清门在同一来源事务完成。旧根的迟到收尾不能清后继根的门。恢复分别枚举待决的来源与 held，包括零 held 而根仍待决的来源。数据库不可得时保留待决与原身份，不改用系统授权继续。
- 运行选择只表达消费意图，每个目标仍要新的拥有者与身份资格；选择有容量与寿命上界，观测到时钟回拨后不复活已过期的选择。
- 声明登记的撤下不删除持久配值与操作历史，同一份精确声明重新登记后可以再读到。登记撤下不是写授权的原子撤除；要使目标失效，由目标拥有者退役独立目标或移除、改变资产持有。

### 秘密设置项与秘密保管

- 声明为秘密的设置项，值只保存在秘密保管里，不进入配值、求值来源、变更、提交记录、回执或变化记录；纯求值把来源中的秘密值判为不兼容。秘密不进入原文审计、日志、遥测与来源说明。
- 秘密按绑定保存，键是范围、目标与用途。范围是官方或一个已铸造的租户；目标由具体持有与项标识推出（官方资产以自身为持有身份），所以替换后的新实现取不到原实现的秘密，持有移除或定义删项之后旧绑定不能再被写入、查询或取用。用途不同的绑定互相取不到。目标编码只有一处。
- 配置来源与秘密的租户绑定分别判断：合法的组织配置不带来组织共用的秘密或新的引用能力；来源读不出、被拒或不可判定不当作未配置。有效配置一旦固定到需要秘密的目标，秘密缺失、读不出、被拒或依赖失败就停止依赖它的动作，不改选别的层、目标或凭据。保管方交给消费方的依据要能核对所取秘密真属于它的身份、用途与租户绑定，请求字段的回显不算。
- 保管有两个窄端口：管理面（写入、清除、查询有无、按范围列出有无）给秘密项入口与受信部署操作；使用面（按键取用一次）只给装配注入的受信消费方。查询有无不返回值。使用面每次读当前值；没有绑定答 `missing`，已撤销或范围未铸造答 `denied`，读不出答 `unavailable`；都不改选其他范围、目标或用途。选哪一层的引用、缺凭据怎样失败，由类别的凭据契约决定。
- 写入的结果分已写入、未写入、确认未知与拒绝；确认未知不报成功或失败，重试前先查有无。同值重复写入是已写入。秘密文本在边界解析：去首尾空白后非空、无控制字符、长度有上界；拒绝只说明规则，不回显文本。
- 秘密项入口核该项已声明为秘密，再交管理面；调用者对该范围的配值依据由装配在调用入口之前核对。入口不猜持有，不缓存声明快照；持有解析不到或项未声明答 `undeclared`，不是秘密答 `not-secret`，资产引用对应多个持有或一个持有有多个在用版本答 `conflict`，这三种都不调用保管。秘密项没有锁。
- 文件保管每次读整个文件、不缓存；写入持文件锁、重读、改、以唯一临时文件加 fsync 加改名发布。锁不按时间被接管。旧文件无法解析时整份是损坏，不修复、不重写；解析错误不进任何结果，因为它可能引用文件内容。已存的秘密按文件原样读，文本规则只管新写入。多机部署与大量绑定不在文件保管之内：端口不变，换提供者。在主目录下新建保管时，秘密只读一次，路径在读秘密前后各核一次为空，新建的目录与文件只对当前用户可读写并读回确认。

### 租户层读写面

- 读写面把租户这一层做成列出、查看、设置、清除四个动作；它只编排，不存配值，不实现权限的求值规则，每次调用都读当时的目录与外层。
- 每个方法先核主体：不是这个租户的登录主体一律 `denied`，不带原因、与不存在看不出区别，不读目录、不问权限、不写；准入读不出答 `unavailable`。
- 一次列出或查看只读一次目录。目录读不出、所要的项不在部分目录里或权限端口读不出时答 `unavailable`，不把残缺的当完整的；目录本身部分时列出标 `partial`。
- 设置的输入在边界严格解析；权限项只收挑选，写入值由权限端口从挑选与本层原有的允许集合组成，本层允许集合原样保留；清除只撤回本层的挑选，本层有允许集合时它留下。
- 写入以调用者给的原操作身份为设置写入的操作标识；同身份同输入答原结果，不同输入答 `conflict`。修订号是目标的修订号，过期由写入的提交判断。结果：有变化答 `written` 带新修订号，无变化 `no-change`，修订或声明不符 `conflict`，上层锁 `not-writable/locked`，越过上界 `not-writable/out-of-bound`，确定没写 `unavailable`，写入抛出或答未知 `unknown`。认回不重做上界核对。
- 视图的归属由目标的种类推出。目录端口把一个资产目标的视图归到哪份资产，按这一层持有记录里的类别与名字，不按发行清单，不写死类别。这一层已经没有它时，这个视图不列出；持有读不出时整张列表答 `unavailable`，不把残缺的当完整的。独立目标归它自己的提供者与定义，取自目标本身，不经类别拓展点，不伪装成资产。列出时调用方说要资产目标的还是独立目标的，没有两种一起列的读法；两张列表不相交，合起来是全部。
- 权限项上界核对读的外层可能在别的事务域，在写入事务之外读；核对之后、提交之前外层变了，这次写入看不到。执行一侧每次调用都重读各层，所以越界的挑选即使写进去也不生效。

### 权限：上界、挑选与主动禁止

- 求值分别表达锁定的允许集合与未锁的挑选。适用来源是默认、组织、租户、会话；工作区不提供权限配值。拥有者提供的适用约束（如 Agent 定义的权限上界）与四层配值共同构成上界，不能遗漏；必要的外部约束无法核验时不放行依赖它的操作。
- 锁定集合取交集，内层不能突破外层上界；锁成单值是单元素集合，锁成空集该项无可放行结果。未锁值只是挑选，不成为额外上界。共同允许范围非空时，从最具体来源向外取第一个落在界内的挑选；作者默认是最外层挑选。全部挑选都在界外时，对有序分档权限取距最具体挑选最近的界内档位，等距取较严档；没有已定比较关系的类别不猜最近结果。
- 组织、租户或会话主动配置「不允许该操作」时，无论有没有不可覆盖标记，下层挑选、会话模式、自然语言批准或人工介入都不能把它放宽成允许。作者出厂默认的不允许只是最外层挑选，不构成这种限制。这是操作限制，不是禁用整份资产。
- 结果保留实际采用范围、允许集合、有效值与依据。权限只约束相应关口，环境可用、身份认证、资产持有与实际结果各自判断。值的「允许操作」为假表示不许所控操作；为真只表示结构上没有禁止，之后仍可能要人工、环境或别的检查。没有默认挑选、各层也没有挑选时不猜默认档位。权限支持的授权寿命（原调用、逻辑会话、租户）与可配值的治理层是两件事，不互相推导。
- 权限配值在设置里存一份挑选与允许集合。设置的通用属性锁不是权限的允许集合，设置合并出的单个有效值不能替代逐层材料：集成方把各层原配值交给权限求值。设置写入成功不证明权限放行。外部约束是具名的上界或禁止，不是第五个配值层。
- 必要约束的集合由受信集成方决定，不是用户可删的选项：漏掉的或读不出的必要约束都阻止放行；新定义不认识某条约束的档位时答无效输入，调用方不能删掉这条约束重试。求值先解析结构与绑定，再查已知的主动禁止与空交集，它们成立时即使别的来源读不出也明确拒绝，其余缺来源答不可用。来源读不出而已有合法禁止时，提供者把禁止与不可用的来源一起交给求值，不把整份材料丢成默认允许。
- 声明式权限上界按能力身份与关口标识，允许集合只限制允许值，不选值、不授予权限；每份声明的项数与每个允许集合的大小有上界，空集、重复关口与重复值拒绝。上界提及当前定义不支持的值时，消费方报告来源不可用，不删掉这条上界。

### 权限：使用资格与工作区保守权限

- 「谁可以使用它」按治理模型给出的主体范围与「自己」求值。作者没另声明时只限自己：组织与租户持有上指历史作者，工作区来源里指本次会话获准使用工作区的租户，不指共享实例的任意使用者。使用资格在同身份择取之前消费：不能使用的自定义件被过滤，其他合法实现仍参与，不清空官方能力。官方实现不受自定义件的这项限制，但官方的最小构成不等于外部动作无限授权。
- 替换件少声明受约束的权限项时，不把该项解释为允许、无约束或不适用；约束无法可靠匹配到实际关口时不开放依赖它的操作。
- 工作区的权限与授权配值在加载时过滤，不允许放宽，也不接受「只收紧」作为旁路。工作区自己提供的 Tool 与 MCP 动作按「问一下」，Loop Extension 只观察，这是具名类别的保守规则，不是笼统取枚举的最小元素；工作区自声明的自动或更高干预值不生效；使用、安装、启用、实例化与派发的资格限本次获准挂载者自己。需要放宽时，先合法收进租户持有再配值。
- 使用资格变化不删除会话已知的 Tool、Skill、MCP 身份；当前资格只影响之后的采用与准入。

### 权限：写入与准入

- 组织层写入要治理模型授予的当前组织管理资格，租户层要本人：资产目标还要合法持有，租户自己的独立目标要它在本租户的事务域、范围是本租户、来源都在本租户。实际写入核验当前上界与允许项，越界不生效并给出可辨原因。
- 编辑与执行分开判断：编辑采用当前定义、允许的配值层与编辑政策的适用约束，排除被修改层及其内层的原配值；本层旧的禁止不能让有资格的本层管理者永远改不了它。外层主动禁止与允许集合仍限制可能允许操作的新值。执行政策的约束不因编辑对象包含该执行者就被当成编辑资格。
- 当前定义与拟写值合法时，不允许操作的挑选、空的允许集合、只含不允许值的允许集合都是确定的限制，不依赖未知外层就能保存；其余配值要完整的适用当前来源，拟写的允许值都要在共同界内。纯判断不授予写入资格，也不证明材料当前；真实写入把原身份、精确命令、当前定义、适用来源与原项修订绑在一起，在同一事务或来源保留协议下保护这些条件。
- 用户明确选择租户全局允许时，授权解释表达范围，设置与权限核对写入资格，再写成租户权限值，它仍服从组织上界与适用的主动禁止。单次与会话授权不经此路径改持久权限，任何卡片「批准」都不解释成全局写入。
- 放行卡片上的「始终放行」与「始终禁止」走同一条租户层写入：值分别是该项的自动档与禁止档，带当前主体的写资格与预期修订，服从组织上界与主动禁止，结果照实答（已写、没有变化、越界、被锁、无资格、冲突、不可用、未知）。卡片不另开写入口。
- 权限的解释按能力身份与关口标识找声明：声明由能力的类别拥有者登记，不限于发行清单里的工具。一个能力可以有几道关口，每道一条权限定义、一项设置、一条绑定与一条解释；设置页上一道关口一项，租户层的配值、层的上界与会话层的配值都按（能力身份，关口标识）各记各的。找不到声明或关口时答不可用，不回退到静态允许。
- 类别拥有者可以给一份关口模板：一个类别的关口是固定的。这一类每份在持且启用的资产各有一份权限声明，由模板与这个租户当前的持有算出。持有出现时登记并采用；持有移除或禁用时撤回。撤回不删配值与许可。登记与撤回在持有变化时做，不在调用路径上做。
- 撤销、成员失效或上界变化作用于之后的准入，不等于运行停止或外部效果回滚。权限缓存要声明有效条件与失效范围；排队、等人、重装配与恢复之后按原动作当前的条件重新核验，改了参数不能借旧批准。
- 原动作的当前读取：实现引用对应受信发行映射里的精确实现，不从工具名或模型文本推断；来源、修订与必要约束由提供者收集，调用方不能自填或删减；消费方核对结果里的请求与自己发出的完全相同。失败按次序分：输入不合形状；资格确认不成立或不可判定；有资格之后才报绑定不符，不用绑定错误向无权调用者泄露目标事实。缺来源实现时不回退旧的静态允许。
- 权限结果不解除沙箱、外传限制或组织资产流转边界。组织管理员的资产管理角色不开放私有租户内容，成本账目的读取资格不授予调用正文与凭据。

### 动态治理贡献

- 功能拥有者声明本功能的设置与真实权限关口；公共治理只固定协议、安全边界与求值规则，不维护预知所有功能的枚举。权限声明要有人可读的标题、解释、批准后果、合法档位与有序关系、真实的关口标识；没有关口的权限不能登记。
- 支持的作用域是声明能力，实际作用域是受信输入，两者必须相符；注册者不能新增没有治理语义的范围、伪造组织、租户或会话身份、放宽外层禁止。全局只表示本租户允许的持续选择；只此会话跟随逻辑会话而非运行实例；只此一次跟随原操作与参数，技术重传不能再得一次额度。
- 每个入口先核有限的输入与预算，再核受信身份与披露、操作资格，然后才处理原操作绑定、版本、状态与业务约束；结果标签互斥，异常不变成空的成功。
- 登记、撤除与采用都绑定原操作身份与请求摘要：同操作同摘要认回原结果，同操作异摘要冲突，未知按原操作查询。重传可以认回已释放的原租约，但明确答已释放，不重新激活。撤除只释放精确的贡献租约，旧代不能撤新代；最后一个适用租约退出才撤下该范围的贡献。采用校验全部必要声明与关口之后整份发布，失败保留旧份或明确无可用份，不发布半套。
- 配值的身份含持久命名空间、配置目标、具体来源身份、项与治理层，不用进程号、fiber 路径或临时注册号。卸载只释放实例贡献与执行资源，不删除配值、许可与回执，不重置使用次数，不复活已撤回或已消费的许可；同名的不同资产或提供者不继承原来源的配值或许可；相同来源、相容定义重新装配后，重新核验即可采用合法保存的值。
- 不可变定义的权威来源对一个定义键只对应一个摘要，租户内保存的是已核实的副本；来源不可核实时答不可用，不把局部副本升成全局权威。
- 装配协调者拥有采用围栏：声明的发布、撤除、替换与依赖该采用集合的设置提交、授权消费在同一排序边界核验。卸载先封住新的采用，认回或完成已取得提交权的原操作，再释放物理资源；提交先成立则保留结果，撤除先成立则旧准备不产生新的写入或消费。重启时先隔离旧实例的围栏，再登记本次实例。
- 管理操作绑定仍合法的管理定义来源，不伪造运行实例；历史查询、撤回与关闭不依赖已卸载的插件重新上线。

### 给 agent 的工具

- `assets-tools` 给 agent 一个多命令工具 `OmneExtensions`，管行事的那个租户在持的拓展，覆盖此刻登记的全部类别。命令十三个：`help`、`categories`、`list`、`show`、`impact`、`result` 只读；`export` 把在持的一份写进一个目录；`publish`、`enable`、`disable`、`remove` 改动；`settings` 列出在持的一份资产的普通设置项与它们此刻的值，`configure` 写入或清除其中一项。四道关口：`read`「查看」、`export`「取到工作区」、`change`「改动」缺省放行，`configure`「改设置」缺省询问；`settings` 归 `read`。`export` 不动资产，但往磁盘写文件，所以归自己那一道。`dir` 是从这次调用的工作目录算起的路径或绝对路径，能到哪里由绑定照这次调用的文件范围判：端口答「在范围之外」时，工具说是「工作区之外的文件」这项设置拦的、让模型告诉用户，不说成目录不在。工具自己不判许不许，`export` 与四个写命令各给放行说明：动作、类别、名字，发布另给从哪发布，`export` 另给写到哪个工作区目录。
- `settings` 与 `configure` 只管行事的那个租户这一层的普通设置项，写入走租户层设置的同一套准备、就绪与提交，受同样的上界与锁定约束。秘密项只说有没有配，不给值，也不能经它写；权限类的设置项不经它读写，人对权限的持续授权只经放行卡片与设置页给出。`configure` 的放行说明写出资产、设置项的名字与要写的值。
- 声明与规则是定死的文字，不含任何类别名；`category` 与 `name` 是开放的字符串，每次调用拿此刻的类别核，写了一个现在没有的类别时，回执带此刻真有的类别名。类别各自怎样说明、怎样新建，读自类别的登记。
- 一次调用要的东西都由绑定给：行事的租户与主体、资产的三个面（类别的读面、管理服务、发布服务，按调用现取）、读工作区目录的口、往工作区目录写一个包的口，与拓展树此刻的修订号。工具不碰磁盘。模型的参数里没有租户，所以读在持的命令只读行事的那个租户的；四个写命令以这次调用的主体，只在这个租户层上改动，写不到别的租户名下，也写不到组织层。三个面取不到时每个命令答资产此刻读不出，什么都不写。每个成功的结果末尾一行修订号，取不到就不印。
- 写命令的 `id` 就是管理与发布服务的操作标识，工具不自己记。改动之前先按标识认回：认得的是同一个改动就答原回执并标明是认回的，不再写；是别的输入就答冲突，要换一个标识。服务答不知道时结果是失败、原因 `unknown`，叫用同一个标识重发或问 `result`。类别的正文契约拒绝的原因原样带上。
- 改一份已在持的拓展，源头是资产里在持的那一版，不是磁盘上的某个路径。`show` 末尾写明源头：目录型写这一版的文件数、总字节与路径（至多列二十个）；数据型的正文不超过 4096 字节时整段印出，超过时只写大小、叫用 `export` 取。再写怎样改：目录型是取到一个目录、在那里改、从那里发布；数据型是发布一份新的正文。随部署安装的在持，在怎样改之前多一句：它不能就地改。
- `export`（类别、名字、目录）经管理服务的 `files` 取在持那一版，交给写包的口写进工作区的这个目录；数据型当作只有一个文件 `body.json` 的包，内容是正文的 JSON 文本加一个换行。目标不存在或是空目录时才写，写完答写了几个文件、多少字节与文件名，并说下一步：改、问 `impact`、从这个目录发布。目标已有内容时不覆盖，什么都不写：内容恰好就是这一版，答成功并写明已是这一版；不同，答冲突并列出差在哪些路径。路径不是工作区里能放一个目录的地方，或这次调用没有工作区，答无效。写的口答不了或抛出，答依据取不到，写明什么都没写。
- `show` 的源头一段末尾说怎样改它；这一类不经通用入口新建时，说它不能用这个工具改，不说发布。`list` 与 `show` 只答行事的那个租户在持的；随部署装上而租户没有持有的定义不在这里，在拓展树的点上看得到。
- `help` 带 `publish` 与类别时，在这一类怎样新建的一行之后印出类别登记的 `authoring` 原文；没登记就不印。`impact` 带着目录而读不出影响、或 `publish` 被类别的正文契约拒时，原因之后指到这份说明（类别登记了才指）。工具自己不写任何一类的写法。
- 一次改动会怎样、一份在持的此刻怎样，由类别的拥有者答：类别登记时可以带 `effect`（`CategoryEffect`），是两个只来往数据的口：`impact`（`ChangeImpact`，一次发布、启用、禁用或移除会让哪些点上多出、少了或不再生效什么）与 `placement`（`Placement`，在持的一份此刻放在哪些点上、各生没生效，客户端装得怎样）；`effectOf(类别)` 给出它，这个类别不生效时不给。没带的类别由资产答（`heldEffect`）：影响是这个类别的点上的一行（发布与启用是在持，禁用与移除是不再在持），生效情况是资产规则此刻对它的结论（选中、没生效与原因、读不到）。资产的成员不认识登记表，也不认识任何一个类别。两个口只为这次调用行事的租户答。`impact` 整个靠前一个口，口答不了时是失败；`show` 里放在哪与客户端装得怎样靠后一个口，口答不了时那一段写读不到与原因，别的段照常。

### 协议、接入与界面

- `assets/v1` 分两半：设置与类别的六个操作（本条与下一条），资产的操作与一条观察（再下三条）。每个操作都要登录，都不算业务访问、不带登录凭证。设置的四个是租户层设置的列出、查看、设置、清除，在消息体里带目标租户，并带上种类：列出时说要资产目标的（可以再限到一份资产）还是独立目标的；查看、设置与清除指到归属（资产的类别与名字，或独立设置的提供者与定义）加项。没有两种一起列的寻址。视图的头是归属，声明带这一项所在的分组（标识、标题、说明）。权限项只收挑选，秘密项交原文，视图里没有秘密的值。除成功与 `not-writable` 外，结果的响应体为空。
- 列出类别 `list-categories` 不带目标租户：类别是部署级的，每个租户看到的相同。它答这一部署现有的全部类别，每项是标识、名字、一句说明与新建的方式（`none`、`data`、`directory`），按标识的码元序，`after` 与 `limit` 切页。`describe-category` 看一类：名字、说明、新建的方式与给人看的那句提示，数据型另给正文的 `schema`，目录型另给三个上限；类别不在答 `not-found`。接入插件每次调用现取类别拓展点的读面，取不到答 `basis-unavailable`；插件不认识 Cordis 服务，读面由应用的装配交给它。协议没有登记或撤下类别的操作。
- 资产的操作都带目标租户，背后是「租户层的管理」那个服务，一个结局对一个线上结果。读两个：`list-assets`（类别、`after`、`limit`）与 `describe-asset`（类别与名字）。提交六个：`create-asset`（数据型，正文是 JSON）；`begin-asset-upload`、`append-asset-upload`、`commit-asset-upload`（目录型的三步，见「资产上传」）；`set-asset-enabled` 与 `remove-asset`（带持有引用）。提交类的操作在消息体里带调用方给的操作标识，与设置的写相同；消息号不作操作标识（接入规格 AC-5）。一次传目录用开始那一步的操作标识贯穿三步。追加的正文带一段字节，用公开契约的字节叶子。协议的形状里没有服务端本机路径这种来源。
- 认回只有一个操作 `query-asset-operation`：带操作标识与它是哪一种操作，答原操作的结局、还没提交过（`not-committed`）或没有这个操作（`not-found`）。追加的结果不知道时不用它，重发同一段。
- 观察 `observe-assets`：开的时候带目标租户，帧只说变了，没有游标，不带内容。开了先发一帧；之后这个租户的资产每次有已提交的变化就发，连着几次合成一帧；每次发之前重核登录还能不能为这个租户行事，不能就结束。它由资产的变化信号驱动；客户端收到就重读，断开重连之后也重读。
- 接入插件先凭登录与目标租户换主体，身份答拒绝或不可得时原样答出，不调读写面；读写面每次调用现取，取不到答 `basis-unavailable`，协议不撤。这里的读写面指设置的租户层读写面，也指资产的管理服务与变化订阅，规则相同。字段原样转交，读写面的每个结果对一个线上结果，不合并、不改名。读的抛出答 `basis-unavailable`，写在调用开始之后抛出答 `unknown`。插件不持有状态、不缓存配值、不自己认回。
- 界面显示的是服务端的事实：写成功之后重读这一项再画，不在本地推算生效值；写入带当前视图的修订号，冲突时重读。结果未知时不发新的写入，原样再送同一次来认回，认回仍说不出就停在「结果仍未知」由人再确认；从不把未知写成成功或失败。读不出不显示成未设置或默认值，部分列表整张标明不全。旧读取与旧操作的迟到答复一律作废。界面模块不持有登录，不认识宿主与身份，登录门归外壳；租户读不懂时直接显示一句话，不发调用。
- 秘密项在页面上能看状态、设、清。「这一层的秘密」与「部署层的秘密」各显示未配置、可用、已吊销、读不出之一，不显示值或片段。能改时给一个口令框和「设置」，空时不可点；提交时口令框立刻清空，原文只经这一次调用送出，不进状态机的状态、不进提示文字，也不留在页面上。状态里没有原文，所以结果未知时无从原样再送：界面改为重读这一项，让人对照状态，仍标「结果未知」，没有生效由人重新输入；不写成成功或失败。清除与权限项相同。
- 界面模块是客户端树上的插件（成员的 `./cordis` 入口导出 `assetsUiModule`），依赖外壳的 `shell` 服务与 `assets/v1` 的协议客户端：协议客户端出现时往 `pages` 放两项：「资产」页（标识 `assets`，次序 15，在人工介入的「待你决定」与「设置」之间）与「设置」页（标识 `settings`，次序 20）；消失时随作用域卸载撤掉。两页都收到外壳给的当前租户文本，还没有租户时什么都不画、不发调用。资产页只要资产目标的设置项；设置页只要独立目标的，按归属与分组分块，块的标题取分组的标题。一项设置在两页里恰好出现在一页。普通值按声明的类型给控件：枚举给挑选，文本给输入框，布尔给开关，别的普通值只显示；提交、认回与重读与资产页的一行相同。
- 界面模块在客户端的树上提供资产治理口（键 `assetGovernanceKey`，形状 `AssetGovernance`，从 `./cordis` 入口导出）。类别的界面模块拿资产与规则的事实只走这个口，不导入资产的任何成员：它用自己要的形状写键的类型，由应用的装配把这个键交给它。口跟着界面模块的作用域，协议客户端撤下时口也撤下，注入它的类别界面模块随之卸载。
  - `open(租户的文本, 类别)` 给出这一类的视图。租户用外壳给的文本，口自己解析，类别的界面模块不解析租户；文本读不懂时视图直接是「读不出」，不发调用。快照三支：读中；读不出（带原因，不带任何一份资产）；读到了（这一类在持的资产，每一份是列出的一行并带它的设置项，另有这一类新建的方式；列表不全时标不全）。别的类别的资产不在里面。
  - 同一个租户几个类别同时打开，对服务端只读一遍：同一个租户的视图共用一份读取与写入的状态，最后一个视图 `close` 时作废，之后到的答复不算数；换租户就是另开一份。
  - 视图上的改一项、清除一项、设一个秘密、认回、重读一行，是同一套状态机（原来设置页用的那一套）：同一项同时只有一次提交在途；结果不知道时用同一个操作标识认回，不重发。秘密的值只在写出去的那一次请求里，不进快照。
  - 每个视图带一个默认部件 `Row`：给它一项设置的键（`rowKey`），它画这一项的一行，与通用的窗格里的一行相同，读写走的就是这个视图。类别的页面可以自己画某一项，也可以用它。部件挂在视图上、只收一个键，所以类别的界面模块写自己要的视图形状时，宿主的视图仍能赋过去。
  - 口的形状以后只加不改。视图上除了设置的改与清除，另有看一份、数据型新建、目录型新建（交给它一组文件，它分段送并报已收的字节数，数取自服务端的答复）、启用、禁用、移除。这些动作与设置的写共用同一套状态机：同一项同时只有一次提交在途，结果不知道时用同一个操作标识认回，迟到的答复作废。
  - 口在视图开着时观察 `observe-assets`，收到一帧就重读这一类的列表与开着的那一份。
- 资产页的类别排在一条栏里，一类一项。栏里的项是两个来源的并集：贡献了类别页面的类别（拓展点 `assets.category-page`，见下）与 `list-categories` 答的全部类别；一类还没有任何资产时也有一项，人才能在那里新建第一份。次序：贡献的页面在前，照外壳排好的次序（次序、标识）；其余的类别在后，按标识的码元序；都和加载的先后无关。页面开着的时候跟着服务端的类别变：界面模块另依赖连接服务 `connection`，订阅它给的点 `assets.categories` 的键；键变了就再读一遍 `list-categories`，读的时候栏照旧，不显示「正在读取」；键没变的帧不读；连着变几次时只认最后一次读的答复；页面关了就不再订阅。对方不说这个点（修订号 1 的 `access/v1`）时没有可跟的，照旧只在打开时读一次。选中的现算：人点过的那一项还在栏里就是它，否则是栏里次序最前的。外壳的 `navigate` 带着对象来时（对象是一个类别的标识；别的界面模块要去某一类时用 `./cordis` 导出的 `assetsPageTarget(类别)` 得到页面标识与对象），把那一类当作点过的；它只选中那一类，不进任何一份资产的页。没点过时，看到的那一项一旦画出来就算点过，所以之后排到它前面的新类别不把窗格换走。撤下选中的那一项时回落到剩下的里次序最前的；回落不改写点过的是谁，所以类别一时读不出、之后又读到了，回到原来点过的那一项；刚撤下的那一刻点它，这次点击不留下作用。贡献的页面没选中时藏起来不卸下，选中时画它；没带页面的类别用通用的窗格，只画选中的那一个。列表读不出时照实写原因并给「重试」，贡献的页面照样在；列表不全时说出来；一类都没有时也说出来；句子见下一节。一个类别的页面画的时候抛出，只有它那一个窗格显示读不出（外壳的 FE-I14），栏与别的类别照常。
- 通用的窗格只经治理口拿事实（与类别自己的页面拿的是同一个口）：这一类的名字与「新建」（新建的方式是 `none` 时没有），下面是 `assetsCategory` 的位置，再下面是这一类在持的资产，次序照 `list-assets` 的次序。一份资产的一行有简介的标题与一句说明（没有简介时只有名字）、禁用与否、是不是官方来源，以及它有没有哪一层都没填的秘密项。列表不全时说出来，读不出时照实写原因并给「重试」，不显示成空。点一行进入这一份自己的页（资产 › 类别 › 资产名）：页头能回到列表，写着它在哪一类；下面依次是启用、禁用与移除（官方来源的不给，移除在提交之前说明不可逆、设置会退出），它的设置项，`assetsHolding` 的位置，最后是收着的详情：名字、版本、来源、现在能不能用与不能用的原因、简介的几条事实，内容（数据型的正文写成普通的 JSON，目录型的文件清单）。回到列表时列表不重读，焦点回到进来的那一行；这一份离开列表（被移除）时页也随之回到列表。一份资产的设置项只在它自己的页上出现。一项设置是一行：名称、用途、生效的值与来源、本层的值（秘密项只有状态）、何时生效、能不能改与原因；能改时可以改与清除，清除之后会怎样在清除之前说出来；这一项自己的读取、提交与拒绝的提示放在这一行底下。枚举的选项显示声明里给的名字，没有给时显示原值。窗格、详情与设置行的样子见下一节。
- 新建的表单照 `describe-category` 的答复出。数据型：正文的 `schema` 顶层是对象、属性是字符串、枚举、布尔或数字时，每个属性一个控件，必填的标出来；别的形状整份给一个 JSON 文本框，仍能提交。目录型：一个目录选择，选完显示文件数与总字节，超过这一类的上限时先说明，再由人决定提不提交，服务端的答复才算数；遇到符号链接这类读不了的条目说出来，不悄悄跳过。同名的资产已在持时，提交之前写明会成为它的新版本。被拒时显示服务端给的原因。类别交来的文本（简介、提示、原因）只当文本显示，里面的标记不解释。
- 两页都用共用界面件的控件、提示与页面骨架，自己不带按钮、提示这一类基础样式，样式表只写版式，不定义自己的变量。来历见成员的 `UPSTREAM.md`。
- 界面模块的源码里没有任何具体类别的名字。栏里的字与通用窗格的标题取 `list-categories` 给的名字；类别不在那份列表里，或列表读不出时，显示类别的标识。贡献了页面而自带栏里的字的类别，用它自己的字。应用的装配不交类别的名字。
- 资产页开三个[拓展点](../../.meta_harness/design/ubiquitous_language/terms/architecture-core-and-extension.md#ul-extension-point--拓展点--extension-point)，让一个资产类别的领域往资产页里放界面，都从 `./cordis` 入口导出；共同的规则见[拓展点的共同契约](../../docs/architecture/cross-cutting-concepts.md#拓展点的共同契约)。`assetsCategoryPage` 用外壳契约的 `definePoint` 声明，让一个类别整页画自己；另两个用 `defineKeyedPoint` 声明、按类别分键，往通用的窗格里这一类的资产旁边放东西。

  | 问题                     | `assetsCategoryPage`                                               | `assetsCategory`                                                                         | `assetsHolding`                               |
  | ------------------------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- | --------------------------------------------- |
  | 1 叫什么                 | `assets.category-page`（常量 `ASSETS_CATEGORY_PAGE`）              | `assets.category`（常量 `ASSETS_CATEGORY`）                                              | `assets.holding`（常量 `ASSETS_HOLDING`）     |
  | 2 哪一棵树               | 客户端                                                             | 客户端                                                                                   | 客户端                                        |
  | 3 能放几项               | 一列，每个类别至多一项                                             | 按键放，每个键一列                                                                       | 按键放，每个键一列                            |
  | 4 键从哪来               | 一项的标识就是类别名，贡献方自带                                   | 类别的标识，取自栏里选中的这一类                                                         | 同左                                          |
  | 5 宿主给什么             | 当前租户；对象是空的，类别要的事实经治理口拿                       | 当前租户，与 `{ category }`                                                              | 当前租户，与 `{ category, name }`：这一份资产 |
  | 6 这一项交什么           | 标识、次序、栏里的字（没给时用类别的名字或标识）、渲染函数             | 标识、次序、可选的标签、渲染函数                                                         | 同左                                          |
  | 7 什么时候读，变化怎样传 | 渲染时现取并订阅                                                   | 渲染时现取；项放进来或撤下，位置自己重画。贡献方自己读自己的数据、自己同步，资产不替它存 | 同左                                          |
  | 8 出错时                 | 只有这一页显示读不出，栏照常                                       | 只有这一项显示读不出（外壳的 FE-I14）                                                    | 同左                                          |
  | 9 撤下                   | 贡献方的作用域卸载，下一次渲染就没有了；选中的是它时回落           | 贡献方的作用域卸载，下一次渲染就没有了                                                   | 同左                                          |
  | 10 形状怎样变            | 没有版本；对象只加字段                                             | 给对象加字段是相容的；改名字或去掉字段要换拓展点的名字                                   | 同左                                          |
  | 冲突时                   | 同一个类别的第二项抛装配错误（外壳的 `duplicate`），原来的一项不动 | 同一个键下标识相同时抛装配错误                                                           | 同左                                          |

  `assetsCategory` 的位置在通用的窗格上、这一类的标题下面、资产的列表之上；带了自己页面的类别没有通用的窗格，也就没有这个位置。`assetsHolding` 的位置在一份资产自己的页上、它的设置项之后、详情之前。两个位置没有项时都不占地方。贡献可以先于它的类别放进去：列表里没有这一类时它不出现，这一类出现之后它才被用。给谁看、许不许用不由这两个拓展点判断：贡献方画什么，按它自己的协议答的事实来。

### 资产页与设置页的样子

这一节写这两屏用哪一族、长什么样、每个状态说什么。族的画法、状态、反馈与语气的规则在[视觉规范](../../.meta_harness/agents/skills/visual-standard/canonical/SKILL.md)与它的[规则与 token 的索引](../../.meta_harness/agents/skills/visual-standard/canonical/references/rules-index.md)，共用件在[前端规格](../frontend/SPEC.md#共用界面件)，这里不重写。类别带来的页面（如 MCP）在自己的包组规格里写样子，它画的设置行照这里的。

**资产页**（页面标识 `assets`，导航「资产」）

- 族与多重：栏加窗格（共用件 `RailPane`）。左边一条栏，一类一行，是导航行；右边是选中那一类的窗格。类别自己带来的页面与通用的窗格在栏里没有区别。类别的显示声明里没有图标，所以栏的行只写名字。窗口窄于 1100px 时栏变成一条横条，两端渐隐。
- 骨架：页头「资产」，说明「这一层：当前租户」；下面是栏与窗格。类别列表读不出或不全时，那一句通知在栏的上方。
- 加载：类别列表读到之前，窗格处是加载状态「正在读取资产……」；贡献的页面照常在栏里。
- 空：一类都没有时写「资产的各个类别会列在这里。」，提示「这个部署还没有登记任何类别。」。
- 外壳给的租户读不懂时，页头照常，下面一句「外壳给的租户读不懂，资产页不能工作。」，不发调用。

**通用的窗格**

- 族与多重：栏加窗格的一个窗格。窗格标题是这一类的名字，用引导字号；标题右边是主动作「新建」（新建的方式是 `none` 时没有）。下面是 `assetsCategory` 的位置，再下面是资产的行。点一行，窗格换成这一份的页；列表藏起来不卸下，回来时原样。行是过程行的轻重（共用件 `ListReadingRow` 放在 `GlideMenu` 里），一份资产的页是正文的轻重，不是卡片里再套卡片。
- 一行：标题是强的一行（简介的标题，没有简介时是名字）；下面是简介的一句说明，弱墨，最多两行，多出的渐隐；下面至多三个小胶囊：中性的「已禁用」「官方」，与注意语气的「还没填密钥」（一个秘密项在这一层与部署层都未配置时）。启用着的不写「已启用」。整行是进入这一份的目标。
- 一份资产的页：
  - 页头是阅读工具条：左边「回到列表」（Esc 也回去），名字处写「类别 › 资产名」；官方资产在名字下写「官方 · 部署装的，不能禁用或移除。」，本租户的资产在右边有动作：一个 `⋯`（「禁用」或「启用」，能撤销，不问）与移除的图标钮（行内确认：钮变成后果「移除不能撤销，这一份的设置也随之退出。」加「确认移除」与「取消」，红只在「确认移除」上）。
  - 下面依次是：简介的一句说明；「设置」一段，每一项是一行设置（见下），一项都没有时写「这一份没有可以改的设置。」；`assetsHolding` 的位置；收着的「详情」。`assetsHolding` 的一项可以认领这份资产的一些设置项（列出项标识）：「设置」段不画被认领的项，由这一项自己画；被认领的项照样经治理口读写，设置行的规则照旧适用。设置项全被认领时，「设置」段不出现。
- 详情：
  - 一张事实表：名字（等宽）、版本（等宽，太长时截断，全文在提示里）、来源（「官方」或「本租户」）、现在能不能用、简介的几条事实。在用时写「在用」；不在用时写原因的人话，带上哪一层、谁定的：「不在用：已禁用」「不在用：不合这一层的使用条件」「不在用：被上层挡住（谁定的）」「不在用：某一层读不出」。
  - 内容：数据型是 `CodeSurface` 里的「原始定义」，写成普通的 JSON（两格缩进，数字照原文），能复制；目录型是一列文件，名字等宽，大小弱墨（「n 字节」）。
- 新建：按「新建」，表单在窗格里、资产的行上面原地展开，用决定宽度；这时「新建」写成「收起」。表单里依次是服务端给的提示（有时才有）、「名字（必填）」与正文。同名的资产已在持时，名字字段下面一句提示「已有同名的 X：提交后会成为它的新版本。」，弱墨，不是警告。
  - 数据型：每个属性一个控件（开关、单选或输入框），必填的标「（必填）」；不能逐项给时，整份一个「正文（JSON）」文本框。输入不合时，表单里一句弱墨的说明（「「X」不是一个数。」「这不是一段合法的 JSON。」），「提交」不可点。
  - 目录型：「选择目录」；读目录时「正在读取目录……」；读完写「n 个文件，共 b 字节」。读不了的条目列出来；超过这一类的上限时，一句行内通知说哪一项超了，以「服务端多半不收；仍可以提交，以服务端的答复为准。」结尾。
  - 回车不提交，只有「提交」。提交之后：数据型的进度是「正在提交……」；目录型只写真实的字节数「正在上传……服务端已收 x / y 字节」，不画假的进度条。
- 加载：列表读到之前是「正在读取这一类的资产……」；进入的那一份读到之前，详情里是「正在读取这一份……」，重读时旧的内容留着，读到后落定。
- 空：一份都没有时写「这一类的资产会列在这里。」；能新建时加提示「按「新建」加第一份。」。
- 部分：列表不全时，在列表上方说一次「列表不全：有的来源暂时读不出，这里没有列全。」。
- 内容过长：标题在行里换行；说明最多两行后渐隐；版本截断，全文在提示里；正文在 `CodeSurface` 里自己滚。
- 反馈：
  - 启用、禁用：这一行的「已禁用」胶囊原地落定（启用后它离开），不另写回执；已经是这个状态时，动作那里落一个轻的回执「没有变化：已经是这个状态。」。
  - 移除：成功后这一行直接离开，剩下的行不动。
  - 新建：成功时表单下面落一个轻的回执，写「已新建 X。」「已成为 X 的新版本。」或「X 的内容和现在的这一版相同，没有变化。」；新的一行在列表里到达。
  - 动作与新建在途时，只有发起它的那个控件显示等待。没有成立时，一句通知写在动作或表单的下面；结果不明时写那一句并给「认回」，认回进行中不给。
  - 别处来的变化（观察的一帧）只让变了的那一行落定一次。

**设置行**：资产详情里的、设置页上的、治理口默认部件 `Row` 画的，都是这一行。

- 族与多重：一行设置（共用件 `ChoiceRow`）。左边是名称与用途，右边是控件；窄了上下叠。行与行之间只有细线，行不是卡片。
- 生效的值就是控件上显示的值。控件下面一行弱墨的说明字写来源：「这一层设的」「来自组织层」「来自默认」；各层都没有值时写「没有值」。权限项被主动禁止时，值写「被组织主动禁止」或「被租户主动禁止」；上层允许的档位是空的时，写「上层允许的档位是空的，什么都不允许」。完整的事实收进这一行的「详情」：生效的值、来源、这一层的值或挑选、上层只允许哪几档（有上界时）、何时生效、能不能改。行上不再摆这张事实表。
- 控件按值的种类给：权限项与枚举是单选，选项写声明给的名字与说明；文本是输入框加「设置」；布尔是开关加「设置」，开关旁写「开」或「关」，拨了才能交；秘密是口令框加「设置」；别的普通值只显示。
- 普通值的控件可以按值的种类换：本成员声明一个按键选画法的点 `assetsControl`（名字 `assets.control`，常量 `ASSETS_CONTROL`，从 `./cordis` 入口导出；规则见[共用界面的规格](../frontend/SPEC.md#按键选画法的点)）。键是值的种类：声明的 `format` 有就是它；否则有 `enum` 的是 `enum`；否则是 `type`；三样都没有的没有种类，画自带的。宿主给画法这一项的标题、声明的 schema、这一层现在的值（人改过就是改成的值）、能不能动，与一个收新值的口。画法只管选值：人按行上的「设置」才写，「清除」与清除之后那一句照旧在。这个种类没有画法、或画法抛出时，画上一条写的自带的控件。权限项与秘密不经这个点。别的模块经治理口画的设置项也经它。
- 锁住的：这一层不能改时，控件画成只读的值，加一个锁的字形与一句为什么：「被上层锁定」「这一层不能配这一项」「上层已经主动禁止」。不画灰掉的控件。
- 秘密：值永远不回显，也不显示片段。控件那里是这一层的状态词，只有四个：「未配置」「可用」「已吊销」「读不出」；说明字写部署层的状态（「部署层：可用」）。口令框空时「设置」不可点；提交时口令框立刻清空。
- 写入：
  - 单选自己就是回执：选一项就写，控件立刻显示新值，只在这个控件上显示等待；被拒就退回读到的值，在这一行下面写一句通知。
  - 文本与秘密按「设置」才写，只有「设置」显示等待。写成了：文本在「设置」旁落一个「已保存」的回执（第一次到达，之后每次落定）；秘密的回执是状态词变了。和这一层原有的一样时，同一处写「没有变化」，一样轻。
  - 「清除」在这一行的 `⋯` 里，本层有值时才有。按下用行内确认，后果写在确认里（「清除之后：」加声明给的那句），能撤销，用默认的墨色。清除之后这一行落定成新的生效值与来源。
  - 写入在途或结果未知时，这一行不能再写。结果未知时控件停在发出的值上，这一行下面一句通知，带「再确认一次」，认回进行中不给；秘密项的结果未知改为重读这一项，让人对照状态词。
- 加载与读不出：这一项重读时控件上显示等待，词是「正在读取这一项……」；这一项读不出时，控件不画，这一行下面一句通知，带「重试」。

**设置页**（页面标识 `settings`，导航「设置」）

- 族与多重：单列页（`PageColumn` 加 `PageHeader`），按组分段，每组是共用件的段（`Section`）；段的标题与说明来自服务端（如「日历与时区」）。行就是上面的设置行。这一页不出现外观，外观在外壳。
- 骨架：页头「设置」，说明「这一层：当前租户」；下面是各组的段。
- 加载：「正在读取设置……」。空：「不属于资产的设置会按组列在这里。」。部分：页头下面说一次「列表不全：有的来源暂时读不出，这里没有列全。」。读不出：一句通知，带「重试」。外壳给的租户读不懂时，页头照常，下面一句「外壳给的租户读不懂，设置页不能工作。」，不发调用。
- 反馈：与设置行相同。

**用的件**：`PageHeader`、`PageColumn`、`Section`；`RailPane`；`GlideMenu`（栏的行与资产的行）；`Disclosure`（行展开成详情，设置行的「详情」）；`FactList`、`FactRow`；`StatusPill`（「已禁用」「官方」）；`StateWord`（秘密的状态词）；`CodeSurface`；`RecordMenu`（`⋯`）；`InlineConfirm`；`ChoiceRow`；`RadioGroup`、`Input`、`Switch`、`Textarea`、`Button`；`SaveReceipt`；`LoadingState`、`EmptyState`、`InlineNotice`。

**通知与语气**（语气的规则见索引的 C3、C4 与 L7、L8）。状态机给一句通知时带它的种类，只有三种：没有成立（`refused`）、没有发出或没有收到可信的答复（`unavailable`）、结果未知（`unknown`）。界面按种类与出事的地方定语气：

| 句子 | 什么时候 | 语气 |
| --- | --- | --- |
| 种类是 `unavailable` 的读：「没有发出去。」「没有收到可信的答复。」 | 类别列表、资产列表、一份、一项读不出 | 琥珀，带「重试」 |
| 种类是 `refused` 的读：共同的「没有权限，或登录已失效。」「服务端不认这个请求的格式。」，与各处读答拒绝的原因（如「这一项现在看不到了：资产没有持有，或声明里没有这一项。」「资产对上了多份持有或多个在用的版本，读不出唯一的一份。」「服务端暂时读不出需要的依据，稍后再试。」） | 读答了拒绝 | 失败，带「重试」 |
| 写入、启禁、移除、新建没有成立的每一句：种类是 `refused` 的（如「这一项在别处改过了，没有写入。已重新读取。」「被上层锁定，这一层不能改。」「这一档越过了上层允许的范围，没有写入。」「这一份已经移除了。」「服务端现在忙，稍后再试。」「服务端没有收下：…」），与种类是 `unavailable` 的「没有发出去。」「上一次没有生效，可以再试一次。」 | 写入或动作的结果是没有成立 | 失败 |
| 「结果未知，正在确认。」「结果仍未知：这次确认没有说出原来那次写没写。」「结果不明：可能已经改了，也可能没有。认回一下再决定。」「结果不明：可能已经建了，也可能没有。认回一下再决定。」与秘密项的两句结果未知 | 结果未知 | 中性 |
| 「列表不全：有的来源暂时读不出，这里没有列全。」 | 列表不全 | 琥珀 |
| 超过上限的那一句（以「服务端多半不收；仍可以提交，以服务端的答复为准。」结尾） | 选的目录超过这一类的上限 | 琥珀 |
| 「这些条目读不了，没有提交：…」 | 选的目录里有读不了的条目 | 失败 |
| 「这一份已经不在了。」 | 展开的那一份已经不在 | 中性 |
| 「外壳给的租户读不懂，资产页不能工作。」「外壳给的租户读不懂，设置页不能工作。」 | 租户读不懂 | 失败 |

### 失败、并发与恢复

- 来源不可用、权限不足、引用阻断、版本冲突与真实的空集合分别可辨；依据缺失不当允许、不当默认值、不借旧缓存放行新动作。可以明确拒绝的分支照样拒绝。
- 已确认的定义、版本、持有、配值、权限与操作结果在进程崩溃、操作系统崩溃或断电恢复后仍可读；介质与整机物理损毁不在这一保证内。回执丢失按原操作查询；取消不回滚已确认的变更；多步操作如实区分已完成与待处理。
- 较旧的求值不以完成较晚为由覆盖已采用的较新结果。持久化的数据不合形状时答失败，不变成空或成功。
- 声明版本、配值修订、来源计数、目录快照、拥有者修订与采用序号是不同的轴，不压成一个全局版本。配值或锁的原始变化即使被别的来源遮住也推进修订与来源计数；真正的无变化只记原结果，不推进修订。通知丢失时，消费者靠计数与合法重读跟上，不依赖每条通知恰好收到一次；变化通知不是提交依据，也不是实际停止的确认。
- 资产与设置的每次已提交变更之后，写入者给出一条变化信号，带所属的域与该域的修订。信号只说明变了，不带值，不区分类别；消费者据此重读。信号在提交成功之后发出，未提交与结果未知的变更不发。同一进程内信号不丢；跨进程的消费者以域修订的比较补上丢失的信号。域修订可以按域读取。资产这一半挂在每个租户那一份本机资产提交之后的一处，不挂在各个调用方；没有变化的提交不发。
- 偏离：设置写入之后没有这条信号，因为设置的提交不止一处，没有一个必经的点。所以别处改了一项设置，开着的界面要重读才看得到；界面自己写过之后照旧重读。
- 原操作查询与变化读取每次重核披露资格：无权时拒绝，也不暴露这次操作存不存在；撤权可以挡住读回，不推翻已成功的效果。
- 恢复不从旧的允许缓存、备份、新的运行实例或历史成员角色复活已撤销的权利；灾后回退不以旧分享或旧管理员状态重新开放。先前合法的装配可以按原采用条件保留，但不因此无限使用过期的授权。
- 审计保留实际主体、范围、变更与合法依据，程序代理不改变责任。解释与遥测不返回别的租户的私有配值或凭据原文，不把权限通过记成执行成功。
- 关闭只停止本实例的准入并等已受理的操作结算，不关闭共享的 SQL 与身份依赖；未解决的资格预留留给身份的恢复。

### Cordis 装配

- 核心成员不依赖 Cordis 与存储；协议契约只依赖公开契约成员。服务键由定义拥有者给出。权限成员不依赖 Agent 与 Session，不保存配值，不另建设置登记表；纯函数不读数据库、文件、时钟或服务。
- 贡献挂在插件自己的作用域上，卸载即撤下；卸载不删除持久配值、持有、发布历史与原回执。
- 运行时对象（存储、时钟、秘密保管、当前事实生产者）经服务或注入取得，不进可序列化的配置；配置非法使插件失败，不静默回退。

## 原则与约束

- 每样事实只有一个拥有者：资产事实归资产，配值归设置，权限求值规则归权限，目标的生死归目标拥有者，资格归身份。不跨包改私表，经同一事务的具名参加者交换事实。
- 写入的依据是提交那一刻同一事务里的当前事实；读到的页面、准入结论与调用方断言都不是写授权。
- 读不到就是读不到；缺省、显式值、清除与依赖失败分别表达，不用默认值掩盖故障。
- 外层的锁、上界与主动禁止钉穿内层；替换、删项、卸载与重装配都不能解除它们。
- 结果不知道按原操作身份认回，不换身份重做，不写成成功或失败。
- 秘密只在保管里，只交给装配信任的消费方；任何结果、记录与诊断都不带秘密。
- 上限、期限、预算与策略是配置或可替换实现；合法使用会碰到的上限要有分页或排队这样的去处，不截断成成功。
- 独立目标与资产目标跑同一套公开服务的符合性用例；不靠在公共参数里强制要持有，让独立实现违反替换原则。
- 跨进程沿用同一数据契约，提供者要兑现等价的条件提交与一致读取；做不到时明确答不支持或不可用，不静默退化。
- 自定义的提交、保留、恢复协议要有形式模型与具名负控；设置的模型在 `settings/verification/`，目录型发布的次序模型在 `assets-local/verification/`，有限检查的通过不等于实现符合。
