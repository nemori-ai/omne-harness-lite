# permissions长期行为规格

状态：候选、待用户确认。目标位置为`packages/assets/permissions/SPEC.md`，不表示公开API、包或实现存在。本文维护结构化权限配值与求值；[产品正文](../../../.meta_harness/design/product/assets-and-rules/design.md#settings-and-permissions)维护产品含义，[领域架构](../docs/architecture.md)维护责任关系。

## 阶段与长期范围

0.0.0 -> 0.1.0 完整支持 CAP-AR10 的权限声明消费、配值管理和实际求值，并为 CAP-AR05 提供候选使用资格及替换不能解除的权限约束，为 CAP-AR08 提供工作区保守权限。须让实际候选、准入和执行边界取得并遵守本次有效依据，不能仅交付枚举、集合表示或算法说明。支持范围归[产品阶段承诺](../../../.meta_harness/design/product/assets-and-rules/design.md#阶段与版本支持承诺)，成员协作归[阶段映射](../docs/architecture.md#阶段范围)。

自然语言授权、HITL 交互、类别实际执行及环境守卫由各自领域实现，本成员不收回其业务。未选的复制、分享、提升及完整观测产品不成为该阶段的独立交付要求，但所选操作仍守住不可覆盖的权限限制、租户隔离、当前资格、可辨失败及适用耐久保证。

关键旅程及正常、拒绝、取消和恢复交接见[关键流程](../assets/docs/internals.md)，本成员的逐旅程验证落点见[持续验证场景](#journey-verification)。

## 调用方与责任边界

管理入口配置合法持有上的权限项，assets在候选筛选时消费使用资格，authorization在实际动作准入时消费权限结果，类别和执行环境消费各自有效约束。permissions提供可解释的结构化判断，不接管登录、HITL卡片、自然语言授权表达或实际执行。

身份、关系、主体及资源范围均明确输入。纯求值可消费调用方提供材料；读取托管权限事实和写入权限值的边界必须校验实际主体，不能借高权限服务代调用方越权。旧允许结果、队列入站状态、历史句柄或成功装配都不是永久权限。

类别拥有真实权限项及执行关口，资产声明其默认值，各持有层按资格配值。作者不能新增一项系统没有关口执行的权限；项目也不因工程分层另建与设置、资产重叠的第四约束面。

## 配值、允许集合与挑选

<a id="bounds-and-picks"></a>

求值分别表达锁定的允许集合与未锁的挑选值。适用来源为默认、组织、租户、会话，工作区不提供权限配值；作用域和适用规则不能因目录内层而改变。

这些来源说明共同权限配值，不是所有准入约束的穷举。AgentDefinition 等拥有者提供的适用允许约束仍须共同构成有效上界；装配/准入协调者将其可信依据交入判断，不能在四层配值均允许时遗漏更窄约束。本成员不解释 AgentDefinition 的业务模型，也不把它新增为配值层；无法核验必要外部约束时，不放行依赖它的操作。

锁定集合取交集，内层不能突破外层上界。锁成单个值是单元素集合，锁成空集使该项无可放行结果。未锁值只作为更具体来源的挑选，不成为额外上界。共同允许范围非空时，从最具体来源向外取第一个落在界内的挑选；作者默认是最外层挑选。只有所有挑选均在界外时，才进入下述最近档回退。

组织、租户或会话主动将某项权限配为“不允许执行该权限所控制的操作”时，该权限值无论是否带属性不可覆盖标记，都不能被下层挑选覆盖为允许，也不能被会话模式、自然语言批准或 HITL 放宽。这是操作权限限制，不是禁用整份资产。作者出厂默认即使不允许该操作，也只作为最外层挑选，不构成上述主动配置的不可覆盖约束。

这里的属性不可覆盖标记用于权限配值及其允许集合，不是资产定义的 immutable 不可替换声明。定义声明和持有层替换锁归 [assets](../assets/SPEC.md#candidate-resolution)，资产禁用与移除沿 [持有规则](../assets/SPEC.md#holding)和 [settings](../settings/SPEC.md#assignment)维护，不能混成权限值。

对有序分档权限，没有任何挑选落在界内时，按共同界内距最具体挑选最近的档位求取，等距取较严档。该业务规则不等于任意集合都存在通用距离；各分档权限须明确顺序与比较，精确表示在机制表达中补足。没有已定比较关系的类别不得猜一个“最近”结果。

结果保留实际采用范围、允许集合、有效值和关键依据，不将“无需人工”当作“已经成功执行”。有效权限只约束相应关口，环境可用性、身份认证、资产持有和实际结果各自判断。

## 使用资格与同标识实现

<a id="usable-by"></a>

各类共用“谁可以使用它”，按所采用身份治理模型提供的主体范围及“自己”求值，默认团队可按租户角色集合表达，不封闭所有治理模型。作者没有另声明时只限自己，在组织和租户持有上指历史作者；工作区来源中指在本次会话获准使用工作区的租户，不指共享实例的任意使用者。

候选使用资格在assets同标识择取之前消费。不能使用某份自定义件时过滤该份，仍允许其他合法实现参与，不以此清空官方能力。官方实现不受自定义件的这项使用限制；官方最小构成不等于所有外部动作无限授权。

同标识替换后，能力身份上的锁定权限上界及主动配置的不可覆盖操作限制继续约束替换件，后者不因未加锁而丢失。替换件少声明受约束权限项时，不能将该项解释为允许、无约束或“不适用”；锁定项仍按已定最严有效规则处理，主动配置的不允许操作值仍阻止对应操作。约束无法可靠匹配到实际关口时，不开放依赖它的操作，由类型和机制设计补齐表达。具体设置值及凭据不随替换迁移。

使用资格变化不删除会话已知Tool、Skill、MCP身份。当前资格影响合法后续采用与准入，已知能力可由原拥有者呈现不可用原因；未合法取得的能力不因失败新增。Slash Command是人的入口，继续沿其当前可见性及权限规则。

## 工作区与保守权限

<a id="workspace"></a>

工作区权限及授权配值在加载时过滤，不允许放宽，也不接受“只收紧”作为旁路。工作区替换身份、提供资产或设置偏好不授予权限。共用工作区资源不使租户私有权限值互通。

工作区自己提供的Tool及MCP动作按“问一下”执行，Loop Extension按只观察，使用、安装、启用、实例化和派发资格限本次获准挂载者自己。该规定是具名类别的保守规则，不笼统取所有枚举最小元素而得到“无人”。工作区自声明自动或更高干预值不能生效。

需放宽时按合法方式先进入租户持有再配值，具体收进方式由共同流转及类别定义，不借文件路径授予。工作区本机命令启用开关由租户设置拥有；开关打开不解除保守权限，更不能解除宿主执行边界。

## 写入与全局授权表达

<a id="writes"></a>

组织层写入须有所采用治理模型授予的当前组织管理资格，租户层须是本人且有合法持有。实际写入校验当前上界及允许项，不从可见表单、可使用资产或旧卡片推出写设置权。权限越界不生效，返回可辨原因。

用户明确选择租户全局允许时，authorization解释表达范围，settings 与本成员核对写入资格，再由本成员写成租户权限值。该值服从组织上界及当前适用的不可覆盖操作限制，不为Agent授予独立权力，也不把任何卡片“批准”解释为全局写入。其他会话沿共同设置读取，不能继续采用旧“全局也永不写设置”投影。

单次和会话授权表达不通过此路径自动改持久权限。单次按实际明确批准的动作或整批范围绑定，不扩展为Run内任意动作；表达的追加、有效性、终局和清理由authorization及Session相应契约拥有。本成员只交付当前结构化边界，不能在恢复时伪造新的表达。

清除或解锁依本层当前管理资格进行，只改变后续求值，不撤销已经发生的操作或费用。移除持有使其配值退出，禁用持有保留配值。权限值变化和持有开关是不同事实。

## 实际准入、失效与在途行为

<a id="admission-and-revocation"></a>

实际动作准入消费本次主体、资源、有效参数及权限依据。权限缓存必须声明有效条件及失效范围，不将旧允许无限沿用。排队、等人、重装配及恢复后仍按原动作契约核验当前适用条件；改参数或影响判断的绑定不能继续借旧批准。

撤销、成员失效或上界改变作用于相应后续准入，不等于物理运行停止或外部效果回滚。执行方仍按自己的控制和收场协议负责真实结果。停止向失去资格者交付新内容不免除合法执行方的结果保管和账目责任。

权限结果不能解除沙箱、外传限制或组织资产流转边界。组织管理员的资产管理角色不自动开放私有租户内容；成本账目读取的具名资格也不自动授予调用正文和凭据。

## 失败、并发、取消与恢复

<a id="failure-and-recovery"></a>

身份、关系、时间、来源或权限状态不可取得时标明无法判定，阻止依赖允许结论的新动作，不将未知当允许、空界或成功更新。可以明确拒绝的分支继续拒绝。权限配值缺省与权限服务不可用不同，不能用默认值掩盖故障。

配值与锁定、关系解除、定义变化及持有移除竞争时，成功结果必须与适用当前约束共同成立。过期编辑不能覆盖已经确认的新约束。较旧求值不能以完成较晚为由覆盖较新的已采用范围，具体版本及提交协议留机制设计。

持久保存确认前须达到SYS-DURABILITY边界。确认成功的权限配值及结果依据须在进程崩溃、操作系统崩溃或断电恢复后可读；介质及整机物理损毁不在此保证内。确认丢失按原操作查询，不反复新增覆盖或把没收到响应当没写。取消请求不自动撤销已确认修改，多步结果如实区分成立与待处理。

恢复不能从旧允许缓存、备份、运行时新实例或历史成员角色复活已经撤销的权利。安全状态不能可信核实的依赖范围不开放；灾难恢复的专用资格和范围未定，不据此创造恢复管理员或要求普通重启人工批准。

解释及遥测不返回其他租户私有配值或凭据原文，不将权限通过记成实际执行成功。请求方看不到某私有对象时按公开契约一致处理，不借错误文本泄露存在性。

## 持续验证义务与表达缺项

阶段内验证组织未锁“问一下”可被租户合法选自动、锁界不可越过、空界不放行、工作区不提供权限配值、使用资格过滤保留合法回退、权限写入与实际准入消费一致、全局写入须双重核验、单卡许可不扩为整批或后续动作。

分别验证组织、租户及会话主动配置的“不允许执行该项操作”即使未加锁也不能被下层覆盖为允许，作者出厂默认不允许可被合法配值选择允许，二者均不被误当资产禁用。替换件删项不能逃出锁界或主动配置的操作限制；资产定义不可替换不自动锁定权限值。权限服务或约束匹配不可用时不凭默认猜测放行。

组合验证覆盖关系变化、持有移除与写权限竞争、HITL答复后的当前检查、依赖不可用、确认丢失与恢复、已知能力身份及独立执行真实收场。结果解释一致性与秘密不泄露分别检查，静态集合计算不证明整个执行边界安全。

外部上界组合验证四层配值均允许、但适用 AgentDefinition 约束排除原操作时仍拒绝；约束来源不可核验时不按缺省允许。约束通过其拥有者提供，不用新的配值层或身份推测替代。

公开类型、错误集合、分档顺序及距离表示、缓存有效条件、原子准入与版本协议继续由技术设计细化。它们须在完整实施前补齐，不把已选权限能力降为契约文档或独立集合计算。未采用的新权限类别、组织创作委托和灾后恢复角色不在此补定。本文没有选择实际机制，也没有声称实现或验证通过。
