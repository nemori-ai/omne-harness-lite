# 配值限制的安全性

本页论证 [judgePermissionAssignment](../src/assignment.ts) 的确定限制分支。业务承诺归 [SPEC 的写入规则](../SPEC.md#writes)。论证以定义和来源材料合法且绑定正确为前提，不核验材料的真实拥有者。

## 模型与结论

令 V 为当前定义的有限值域，D 为其中 permitsOperation=false 的值集。B 为所有适用上界的交集，r 为写入本层的规则。执行求值保留各层主动禁止，并且选出的有效值必须属于共同界。

若 r.pick 属于 D，该本层原配值构成主动禁止。求值在挑选前拒绝，因此更内层挑选、上界变化和缺失来源均不能让此配值产生允许结果。

若 r.allowedSet 非空且为 D 的子集，则写入后的共同界为 B 与 r.allowedSet 的交集。交集仍为 D 的子集。若能够选出有效值，该值不允许操作；若交集为空，求值拒绝。来源不足时求值不可用，也不发布允许结果。r.allowedSet 为空时，交集直接为空。

因此，在 r 仍参与本次求值的前提下，上述确定限制不会产生 permitsOperation=true。此结论不需要知道缺失来源中的具体上界。它不证明该来源不存在，也不允许把 unavailable 改为 absent。

可能允许操作的配值不使用此豁免。它要求适用当前来源完整，没有适用外层主动禁止，且拟写的所有允许操作值都在共同界内。编辑判断排除将被替换的本层原值及更内层原值；它保留编辑政策明确要求的额外约束。

## 可执行守护

仓库根依次执行以下命令。

```sh
pnpm --dir packages/assets/permissions run build
pnpm --dir packages/assets/permissions run test:fast
pnpm --dir packages/assets/permissions run typecheck
```

[assignment.spec.ts](../tests/assignment.spec.ts) 通过公开判断与求值入口验证写入边界。确定限制检查枚举 8 个外层允许子集、4 个外层挑选、2 种来源可用状态和 3 种限制，共 192 个配置组合。来源不可用时隐藏的子集和挑选不影响材料，因此这不是 192 个互异状态，也不是完整状态空间证明。

其他场景验证默认禁止与编辑资格分离、本层旧禁止可合法替换、外层收紧拒绝旧编辑、外层主动禁止、缺源、清除、额外约束及非法值。测试没有创建真实登录、注册声明或 SQL 事务。

## 组合前提

纯函数不能证明主体有管理资格，不能证明来源完整或最新，也不能阻止校验后到提交前的并发变化。真实写入必须由各拥有者保护原项修订、当前定义、适用来源及原操作身份。清除和确定限制仍须真实写入资格。

定义撤下、配值不再适用、被有资格的管理者替换或能力身份改变后，需要重新判断适用材料。本页不把旧限制或旧允许永久缓存，也不证明生产接线、持久性或独立验收完成。
