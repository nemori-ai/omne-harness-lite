# settings长期行为规格

本页维护共同设置行为及长期阶段义务。当前核心与本地组合的已实现范围见下文，不把完整阶段目标视作已交付。产品含义沿[设置规则](../../../.meta_harness/design/product/assets-and-rules/design.md#settings-and-permissions)，成员关系沿[领域架构](../docs/architecture.md)。

## 阶段与长期范围

0.0.0 -> 0.1.0 完整支持 CAP-AR09 的设置声明消费、配值管理及实际求值，并承担 CAP-AR04 的依附配值与清除、CAP-AR07 的工作区逐项合并、CAP-AR08 的来源过滤及命令型逐件启用。共同设置行为可由不同类别消费，不能只交付项表示或求值说明。支持范围以[产品阶段承诺](../../../.meta_harness/design/product/assets-and-rules/design.md#阶段与版本支持承诺)为准，协作落点见[阶段映射](../docs/architecture.md#阶段范围)。

类别专有设置语义及消费时点由类别维护，本成员拥有共同管理和求值。Plugin 组合展开、完整来源解释及 reload 等未选独立能力保留长期规则，不因下面的交接条款成为该阶段新增交付要求；所选设置操作仍须具备合法来源、当前资格、可消费依据、可辨失败及适用耐久保证。

关键旅程及正常、拒绝、取消和恢复交接见[关键流程](../assets/docs/internals.md)，本成员的逐旅程验证落点见[持续验证场景](#journey-verification)。

## 调用方、输入与边界

Settings 可独立使用，也可由资产通过组合使用。独立目标通过其公开目标策略提供管理资格、来源与生命周期；资产路径在合法持有上配值。assembly 为组合及清单取得有效设置，模型、工具、Agent 和其他类别按各自使用点消费结果。共同核心不要求资产身份或运行实例存在，不接管类别业务或实际执行。

独立求值可仅消费调用方显式提供的数据。读取和写入系统托管材料的边界须核验主体及目标范围，裸租户ID、旧页面或缓存不证明当前配值资格。settings不从当前目录补工作区，不从账号偏好补租户配置。

声明拥有项的含义、合法取值及设置类别；持有层拥有该项配值；求值结果保留采用来源与约束依据。未取得合法声明或来源时不创造该项，不把缺失和依赖失败统称默认值。

## 项声明与配置位置

<a id="declaration"></a>

每项设置声明属于偏好、绑定、落点与身份、治理之一，来源资格按类别核验。功能拥有者声明自己功能的设置，不能因此扩张到其他配置目标的管理权。资产设置随当前合法定义存在，由合法持有及声明投影，不维护第二份独立字段目录；独立设置从其自己的固定定义与合法配置目标投影，不伪造资产持有。

资产属性配值依附具体持有和项，不是脱离资产的全局设置对象。组织持有配值要求“组织持有管理”资格，由所采用治理模型映射到组织角色；租户由本人按资格配租户持有，其他来源沿其明确规则。没有持有不能给该资产配值；会话局部覆盖沿会话所属契约，不能借此修改上层共享持有。

自动归档的租户级设置依附租户对会话能力的持有，沿用本成员的持有配值规则。

账号语言、时区等个人偏好独立于组织和租户资产设置，不参与资产权限层序。改变账号偏好不授予权限，也不把同账号在不同组织的资产配值合并。

## 动态目录与声明解释

<a id="catalog"></a>

统一查询入口按明确部署/逻辑服务范围、受信主体、目标范围及管理/运行模式返回分组目录。管理视图包含可配置但尚未启用的资产；运行视图仅消费已经核验的选入依据。登记、合法目标、提供者在线和执行实例存在分别报告，不能以 Cordis 可见性替代业务资格。

定义提供者必须给出稳定组/项标识、定义版本、可读名称与用途、类型与约束、默认或无默认、清除后果及采用时点。单位、枚举标签、范围和依赖说明在相应类型下必需；本地化缺失时有可读后备文本。目录补充当前可读值、来源、锁定及可操作性原因。内部 key 不代替用户说明，任意脚本/HTML 不作为声明执行，普通目录不返回秘密明文。

分页绑定同一快照、范围、筛选和排序，并在每页读取时核验当前资格。依据失效则要求重建，不混代续页；局部不可用须标明不完整，不能作为完整运行快照采用。无权查看的目标或项不在错误细节泄漏。分组是展示关系，不决定配置优先级、权限或跨目标事务范围。

独立目标与资产目标使用相同查询/命令能力契约，各自策略明确允许来源和操作能力。独立目标不自动继承资产层序，也不能借注册者声明扩张权限。具体模型与窄端口见[内部设计](docs/internals.md#独立核心与组合适配)及[组模型](../docs/settings-composition.md)。

## 配值、清除与锁定

<a id="assignment"></a>

写入在条件提交边界核验当前资格、目标、声明版本、项存在、取值有效性、锁及允许来源，并核对预期配值 revision。资产目标还核验合法持有；独立目标核验其实际管理关系。写入成立后该层明确配值可被查询；失效编辑、无资格、类型或类别不合法时不能静默改变当前事实。

缺省表示本层未提供值，显式false仍是一个有效值。清除只撤回本层覆盖，重新沿当前有效来源求取，不能解释为false、禁用或固定回退旧出厂值。具体值为null时是否具有业务含义由项声明决定，未声明时不得当作清除命令。

资产普通设置值按默认、组织、租户、工作区、会话的适用层序选择最具体合法值。有效外层锁阻止更具体层覆盖。解锁只作用于后续求值，不改历史。设置值锁只保护该具体资产的属性，不自动锁住同能力实现替换。资产定义的不可替换声明和具资格管理者设置的持有层替换锁由 [assets](../assets/SPEC.md#candidate-resolution)执行，settings 不另定义替换算法；定义不可替换也不自动锁定该资产各项设置。

同标识替换件不能接收原具体资产的设置值，包括锁定值和凭据。新实现使用自己的合法配值及声明默认值；能力身份上的锁定权限界和主动配置的不可覆盖操作限制由 [permissions](../permissions/SPEC.md#bounds-and-picks)维持。合法原资产不同层的覆盖与替换整份资产严格分开。

禁用是持有上的专门布尔设置。对适用各层取“任一为真即禁用”，下层false不能打开上层true。禁用保留全部其他配值；移除持有使其配值退出有效状态。不能将该布尔规则推广为所有设置的合并算法。

## 工作区过滤与同层合并

<a id="workspace"></a>

读取工作区前须有明确选择及合法实例访问关系。工作区不提供权限配值，不给其他资产配置落点与身份项，也不能通过治理配值设置属性不可覆盖标记或持有层替换锁。工作区可配合法偏好及绑定，绑定只能指向其求值后可见对象；自己的禁用只影响工作区提供的那批资产。

资产定义自身携带的 immutable 不可替换声明不是工作区治理配值，按 [assets 候选规则](../assets/SPEC.md#candidate-resolution)处理，不能因过滤治理配值而一并删除。声明仍只在合法采用层向更具体层生效，不限制上级、扩大来源资格或自动锁定属性。

自身资产携带落点声明与给其他实现覆盖落点分开。前者不因此取得执行许可，后者在加载时过滤。工作区的普通可采用设置压过租户，仍不能压过上层锁。

共享及local属于同层来源，同项local显式值优先，缺省才沿用共享值，包括显式false，不对两者取布尔或。local可只覆盖共享资产的允许设置，不必复制整个资产。若选用同名完整local资产，则不再叠加针对共享实现的设置覆盖；不能将整份资产替换变成逐字段混合。

共用实例local不是租户私有。求值不得读取其他参与者租户私有资产配值或凭据；共享资源不授予跨租户写设置。AGENTS等Runtime Context规范文本有自身规则，不套用此设置合并。

本机命令型MCP及导入命令型hook的启用开关归获准租户自己的设置，默认不启用，工作区资源不能代开。打开后仍保持工作区保守权限，不向工作区提供持有层替换锁、属性不可覆盖标记或权限配值入口。

## 投影、展开与生效时点

<a id="adoption"></a>

候选求值、装配选入、属性投影、逐项求值依次交接。Plugin成员启用设置影响其展开，展开该Plugin时先求本项，其余不改变组合的设置在实际属性项已知后求值。不得依赖未产生的项集合回改候选。

有效值报告保留最终值、采用来源、被过滤或锁定原因及本次依据。值成功求出不代表绑定对象可用、Agent已装配或动作获准。目标模型等专有合法集合仍由类别拥有者检验，settings不让一个普通字符串越过专用规则。

会话值不回写租户默认，也不外溢到其他会话；修改真正共享的资产配值则按原作用域影响其他消费者。创建时初始化的模式与其他动态继承项分别沿会话契约，不能把全部设置复制一次后永久冻结。

工作区资源在实际装配或显式reload时读取，不以文件编辑、Git同步或下一次Run默认刷新。候选校验失败不发布半新半旧的有效值，不暗中修改已采用清单。成功的合法设置变化按该项使用时点作用于后续输入，不改写已发调用。具体刷新及连续reload交接由assembly拥有。

## 并发、失败、取消与恢复

<a id="failure-and-recovery"></a>

配值修改与持有移除、定义项变化或锁定变化竞争时，成立结果须符合当前事实。不能在移除完成后产生脱离持有的可用配值，也不能用旧项声明写入已经不存在的有效项。过期编辑不能覆盖他人已确认内容。

持久保存确认前须达到SYS-DURABILITY边界。确认成功的配值及其作用域在进程崩溃、操作系统崩溃或断电恢复后可读取；介质及整机物理损毁不在此保证内。响应丢失时查询原操作，不能按未收到响应判断写入未发生。取消请求不自动回滚已确认写入；多步部分完成明确列出事实和待处理，不能统一报成功或失败掩盖结果。

资产、资格、来源、版本或存储不可取得时报告依赖及不可判定范围。真实无覆盖、无项和空结果与依赖失败分别表达。不得伪造默认、假锁或借旧缓存无限允许新动作。明确可核实的拒绝分支仍成立。

凭据及其他秘密仅交给合法消费方，不在表单读取、来源解释、日志、审计或遥测中默认返回原文。读取设置权不自动授予调用正文或其他租户秘密。某项秘密是否可回显由类别精确契约维护，未说明不以调试便利开放。

第三方凭据的秘密值由 settings 的秘密保管统一持有。秘密值与身份、用途、租户绑定按[数据与状态](../../../docs/architecture/data-and-state.md#共同成立的业务事实)保存，读取和使用沿[秘密保护规则](../../../docs/architecture/security/data-and-privacy.md#凭据与秘密生命周期)。identity 只管账号登录凭据。

配置来源与实际秘密的租户绑定分别判断。租户、组织、官方等来源只在类别已有合法声明、持有、来源和锁定规则允许的范围内参与配置求值。合法组织配置不授予组织共用秘密、额外凭据引用能力或新的 `organization` 解析结果。只有原类别来源规则允许继续，且能核实当前来源确实未配置时，才沿原规则继续求值。来源不可读、资格拒绝或依赖不可判定不能当作未配置，本成员不另定统一层序。

有效配置或原请求已经固定到需要秘密的目标后，秘密缺失、不可读、被拒绝或依赖失败时，停止依赖该秘密的动作，不改选其他层、目标或凭据。Model 的唯一 `factory` 例外沿[凭据引用与解析端口](../../model/model-contract/SPEC.md#342-凭据引用与解析端口)及[产品凭据范围](../../../.meta_harness/design/product/model-invocation/design.md#凭据的范围)：本租户没有任何绑定、本次档案确为官方、发送已获准且相应部署确实提供默认凭据，四项须同时成立。已有绑定失败不回退 `factory`；当前引用未匹配、存在性查询为否或配置未求出，都不能单独证明本租户没有任何绑定。[Tool](../../tool/tool-contract/SPEC.md#p15-配置声明与合法装载) 与 [MCP](../../../docs/domains/mcp/README.md) 沿各自本租户缺凭据失败规则，不继承 Model 例外，不退组织、官方或其他租户的凭据。

秘密保管方须向合法消费方提供可核实所取实际秘密属于其身份、用途和租户绑定的依据，不能以请求字段的回显证明实际绑定。类别按各自契约核对实际绑定与本次目标、用途、供应商或端点及原请求是否匹配，不通过更换目标来适应错误绑定。Model 对固定 request、dispatch、接收方与 Supplier 的匹配责任沿[本域采用](https://github.com/nemori-ai/omne-harness-lite/issues/682#issuecomment-6369701412)和[发送核验边界](../../model/model-contract/SPEC.md#342-资格共同提交与实际发送)细化；这不替 settings 定义 Model 专属的匹配字段或轮换协议。秘密绑定的键与取用端口归[秘密设置项](#secret-items)。

## 秘密设置项

<a id="secret-items"></a>

本节是长期行为。端口与值在公开入口的 [secrets.ts](src/secrets.ts)；本地文件提供者是 [settings-local 的 `./secrets`](../settings-local/SPEC.md#secret-custody)。秘密项命令入口尚未交付，现状见[当前核心与本地提供者](#当前核心与本地提供者)。

声明为秘密的设置项，值只保存在秘密保管里。秘密值不进入配值、求值来源、`SettingsChange`、提交记录、回执或变化记录。纯求值继续把来源中的秘密值判为不兼容。

秘密保管按秘密绑定保存秘密。绑定的键是范围、目标和用途：

- 范围是官方或某个已铸造的租户。组织范围在有合法写入入口之前不存在。
- 目标标明秘密属于什么。资产秘密设置项的目标由具体持有与项标识推出，不另行存储引用。官方资产的持有下界以该官方资产本身作为持有身份。
- 用途不同的绑定互相取不到。资产秘密设置项使用同一个用途，各类别凭据使用自己的用途。

目标随具体持有推出，所以同标识替换后的新实现属于另一个持有，取不到原实现的秘密。持有移除后，原目标不再有合法持有，秘密项入口和使用面都拒绝它。定义删去某项后，该项不再声明，它的旧绑定也不再能被写入、查询或取用。这些不可达的旧绑定留在保管里，等清理协议确定后处置。

秘密保管提供两个窄端口，分别给不同的使用方：

| 端口 | 操作 | 使用方 |
| --- | --- | --- |
| 管理面 | 写入、清除、查询有无、按范围列出有无 | 秘密项入口与受信部署操作 |
| 使用面 | 按键取用一次秘密 | 装配时注入的受信类别消费方 |

秘密项入口与普通配值分开：

- 写入和清除先核对该项已声明为秘密、调用者对该范围有配值依据，再交管理面执行。
- 有无由管理面现读，Settings 不另存有无或引用。
- 秘密项的锁定与解锁返回 `unsupported`。这是已知限制：秘密项没有上层锁定，组织范围也不存在，所以没有需要下层服从的秘密锁。
- 写入的结果分为已写入、未写入、确认未知和拒绝。确认未知不报告成功或失败；重试前先查询有无。

查询有无只返回未配置，或已配置加生命状态与配置时刻，不返回值。使用面按键精确取用，每次取用读当前值：同一绑定被替换后，取到的是取用那一刻的值；没有绑定、绑定已撤销或读不出时返回失败，不改选其他范围、目标或用途。选择哪一层的引用、缺凭据时怎样失败，由类别的凭据契约决定。

公开入口的形状（精确类型归 [secrets.ts](src/secrets.ts)）：

- `SecretScope` 是官方或一个 legal-identity 铸造的租户；`SecretTarget` 是 `{ owner, key }`；`SecretBindingKey` 是（范围、目标、用途）。
- `SecretPresence` 是 `unbound`，或 `bound` 加 `life`（`active`、`revoked`、`unreadable`）与 `configuredAt`（utc-instant 的时刻，没有时为 `null`）。它没有值成员。
- `SecretText` 是品牌字符串，只由 `parseSecretText` 造出：去首尾空白后非空、不含 C0 与 DEL 控制字符、不超过 `SECRET_TEXT_MAX_LENGTH`（4096）。拒绝只说明规则，不回显文本。诊断与结果类型不接受 `SecretText`。
- `SecretCustodyManagement.bind(key, secret, configuredAt)` 的结果是 `written`、`not-written`、`unconfirmed`、`denied`；`unbind` 另有 `absent`，成功是 `removed`；`describe` 返回有无、`denied` 或 `unavailable`；`list(scope, after, limit)` 按稳定次序分页，游标不透明且可序列化。`configuredAt` 由调用方给出，没有时为 `null`；保管不读时钟。同值重复写入是 `written`。未铸造的租户范围答 `denied`，不读文件。
- `SecretCustodyUse.use(key)` 同步返回 `{ kind: 'secret', value }`、`missing`（没有绑定）、`denied`（绑定已撤销或范围未铸造）或 `unavailable`（绑定读不出或保管读不出）。

## 持续验证义务与表达缺项

验证未锁覆盖与上层锁、清除与false、同标识替换不迁移秘密、移除与写值竞争、定义删项后的旧值失效、同层local覆盖和跨层禁用的区别、工作区落点过滤、本机命令无法由仓库自启、reload候选失败保留合法旧状态、确认丢失查询原结果。

阶段内验证须覆盖真实配值写入、清除和后续求值，以及工作区获准来源与逐件启用，不仅验证给定输入的纯计算。资产定义不可替换声明不阻止合法的设置覆盖，属性锁也不自动阻止整份合法替换；工作区定义声明与不允许的治理配值分别处理。逐件启用不解除 [permissions 的保守权限](../permissions/SPEC.md#workspace)。

与assembly验证Plugin展开的提前求值和完整清单采用；与assets验证持有配值生命周期；与permissions验证设置变更不授予动作许可。源码闭包及安装不依赖Cordis的验证，与普通求值行为验证分别声明。

自动归档设置须验证无会话能力持有时不能配值，移除该持有后配值退出。第三方秘密须验证身份、用途和租户绑定不串用，绑定值不可读时不回退，读取配值资格不等于取得秘密。

声明组合、目录、应用端口及当前性义务见[组模型](../docs/settings-composition.md)；精确公开类型/Schema、项兼容、提供者事务映射与实现符合性仍须完成。秘密的入口、绑定键与两个端口归[秘密设置项](#secret-items)；绑定版本、轮换与使用点的协调，以及组织范围，仍由秘密保管方与各类别消费契约共同细化；除秘密设置项一节外，本页不新增配置项、引用能力或统一解析协议。权限分档不归本成员。这些表达缺项须在实施前补齐，不能缩减已选设置能力的完整支持。公共草稿发布由 assets 承接，类别上架制度、组织创作委托和长期工作区提升缺项不扩大成所有设置不可用，不补未经决定的角色及配置政策。

独立使用必须验证无资产包依赖也能按合法目标读取、配置和求值；资产组合必须另验证持有失效与声明换代。统一目录须验证分组、必要语义元数据、未启动资产管理、分页换代/撤权、秘密不泄漏和明确局部失败。有限交错模型及证据范围见 [verification](verification/README.md)。

## 当前核心与本地提供者

当前公开源码实现声明校验、纯求值、条件变更与 rebase 决定、查询/命令应用服务和贡献注册。settings-local 实现独立目标、配值持久化、动态目录、Identity 协调与受信部署维护。assets-local 通过真实发布和持有事实接入同一服务。

维护重新采用要求精确旧新定义、预期修订及所有旧值/锁的 retain 或 discard 决定，保留内容必须符合新定义和来源。该能力不从普通租户配值权推导，不直接暴露给 agent tool。完整条件归 [本地规格](../settings-local/SPEC.md)。

秘密保管的两个端口已由本成员定义，文件提供者由 settings-local 的 `./secrets` 兑现，Model 凭据与 harness-server 的 `setup` 已在它之上工作；秘密设置项的命令入口（声明核对、配值依据、目标推导）尚未交付。当前不提供工作区文件来源扫描、最终 UI、HTTP 服务、tools 插件或执行实例采用。上文相应长期义务保持其原拥有者，不能因本地核心完成而宣称整个产品阶段完成。授权历史检查可返回原定义与原状态，但不能把不匹配记录当作当前有效设置采用。
