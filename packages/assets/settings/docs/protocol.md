# 设置应用协议的设计约束

本页细化 [SPEC](../SPEC.md) 的公开输入、结果与稳定身份。精确类型归 [公开入口](../src/index.ts)及其 Schema。纯求值、变更决定、查询/命令应用服务和装配注册已实现；本地托管提供者及真实资产组合分别由 settings-local 和 assets-local 实现。下文的秘密使用和跨域提交义务不能因接口存在而视为完成。

## 公共信封与目标

本地命令携带协议版本、requestId 和明确目标，具体查询输入按公开 Schema。受信调用身份由本地服务边界或远程认证适配取得，不接受客户端自报角色作为资格。结果使用明确成功/失败判别，不回显秘密。HTTP 身份认证和统一网络响应信封尚未交付。

配置目标绑定包含 `policyId`、`targetRef`、`scopeRef`。`policyId` 指向已经接受的宿主策略，不是可执行脚本；另外两项由该策略解释并核验。资产策略核对具体资产持有与来源；独立策略核对自己的配置目标。共同核心不将 `holdingRef` 设为所有请求的必填项。独立使用不意味着允许未登记策略或没有所有者的任意 key。

定义身份包含提供者身份、定义身份、精确版本与内容摘要。项标识在该定义内唯一；配值身份结合配置目标与项身份。同一版本不同摘要拒绝，重装或显示改名不形成新的配值权利。替换另一份具体资产不复用原值；同资产新版的项兼容性必须重新验证，不能按字符串同名直接继承。

## 查询

| 入口 | 必要输入 | 成功结果及限制 |
| --- | --- | --- |
| readCatalog | 部署/逻辑服务范围、目标范围、management/runtime、locale、过滤、页大小；续页 cursor | 分组目录页、snapshotId、basis、nextCursor、完整性状态。runtime 还须带核验过的选择依据；无选择不暗取全部已注册资产 |
| evaluate | 明确目标、固定声明/选择依据、预算 | 完整不可变快照，含值、来源、约束解释和依据；无默认/无值用显式 presence 表达 |
| previewChange | 目标、拟修改项/动作/值、当前视图依据 | 只读预期结果及影响；不预留权限或提交 revision |
| getOperation | 原 operationId 与其目标范围 | committed / rejected / unknown / not_found；not_found 与无权披露按安全外部响应规则处理 |
| readChanges | 授权作用域、游标、页大小 | 变化计数/原因及续读游标；过期要求重新读快照，不暴露秘密值 |

`readCatalog` 的目录页包含 `groups`、`entries` 与来源状态。每个组有稳定 groupId、父组引用（可空）、标题、说明和显示次序；每项引用 groupId、targetBinding、definitionRef 与 itemId。groupId 不充当授权或事务键。

每项 `presentation` 至少有标题、用途与修改后果的可读后备文本，可附本地化 key；`valueSchema` 指向固定且可验证的声明。数字的单位/无量纲、上下界，枚举各值的标签/含义，在适用时明确提供。默认值使用 `absent` 或 `value` 判别，避免 null 被误读。采用说明区分立即供后续读取、下一业务边界、显式 reload 或创建时初始化；选择哪一种由功能契约决定。

`resolution` 分开表示显式配值、生效值、来源、可操作性及原因。当前目录可展示秘密项的安全元数据，不返回秘密明文，也不提供秘密摘要或保管引用的使用服务；读取字段资格与未来使用秘密资格分开。必要元数据缺失导致声明校验失败，不向产品交付以内部 key 充当解释的半成品。

目录可返回 `partial` 与不泄漏隐藏项的来源问题，但 `evaluate` 不把它当 `complete`。当前部署范围不等于全租户范围；账号或运维设置只有对应适配与授权成立才可出现。

## 命令

`setValue`、`clearValue`、`lockProperty`、`unlockProperty` 共享 operationId、payloadDigest、targetBinding、itemId、definitionRef、expectedRevision、明确来源位置。`setValue` 另带值；其他动作不通过 null 充当指令。不可支持的操作能力在目录中明确，直接调用也返回拒绝。

提交端口消费受信资格、目标/定义/锁/来源的当前性条件及本地 revision 条件，在一个被支持的提交范围内共同确认配值、采用计数、原操作结果与待通知事实。跨目标批量命令不在这个原子承诺内。客户端取消不证明未提交；未知结果必须查询原操作，不换 operationId 重放有副作用的创建。

`registerContribution` 与 `releaseContribution` 是装配端口；普通用户配值权不包含登记权。登记描述可序列化，运行时提供者对象通过依赖注入取得；远程适配使用能力引用，不传函数、Context 或数据库句柄。秘密替换/使用另设受限端口，不与普通 setValue 或目录读回共用明文通道。

当前命令应用入口 `change` 采用 `set/clear/lock/unlock` 判别动作。服务器存储提供者计算内容摘要；客户端自报摘要不构成事实。当前公开应用服务与未来网络认证/信封适配分别实现，尚无 HTTP 接入。普通求值拒绝秘密明文。秘密保管的两个窄端口（管理面与使用面）在公开入口 `src/secrets.ts`，由 settings-local 的文件提供者兑现；秘密项命令入口尚未交付。

纯核心拒绝递归引用 Schema、远程引用和正则约束，防止声明触发外部读取或不可控正则工作。支持范围由 `defineSettings` 明确校验，不支持的声明返回失败。数字需单位说明，枚举需逐值解释，声明默认值必须通过同一 Schema。输入有深度、节点、文本及项数上限。

## 错误与重试

错误类别包括输入无效、未获资格、目标/项不存在、定义不兼容、被锁定、修订冲突、依据变化、策略/操作不支持、依赖不可用、预算耗尽、取消及提交结果未知。错误附安全的作用域与重试建议，不附原秘密或未经许可的目标存在证据。

只有依据变化、修订冲突等明确要求重新读取的结果才触发重新建请求。依赖不可用不等于无值，原操作未知不等于可安全重新执行。重试使用原身份及摘要，返回原结果；摘要不同拒绝。

## 提供者符合性

两个宿主策略运行同一公开服务套件：独立目标不需要资产、资产目标不绕过持有；同一字段在不同租户隔离；目录无需启动执行实例；提交不能绕过当前条件；旧游标在撤权后拒绝；元数据不足不发布；默认/false/null/清除有不同结果；提供者失联不返回伪默认；已捕获输入不变。

业务对象合法性、完整采用和真实执行分别由消费者核验。此协议不将查询成功、保存成功与实际采用合并成一个状态。

## 本地目录和维护边界

createSettingsCatalog 每次读取都重验 Identity 资格，在一个租户事务内捕获目标拥有者投影与设置配值。贡献注册表在捕获前后必须同代。分页依据包含完整目标事实、配值、声明可用性、服务实例和有限时间桶。过期或依据变化返回 basis_changed；重启或已观测时钟回拨不会复活旧页。目录不是长期缓存。

运行视图必须带与主体、部署和明确目标绑定的选择引用。createSettingsSelections 提供有容量与寿命上限的本地选择来源，它不授予目标权限，也不是执行实例采用回执。卸载贡献使目录报告不可用并保留配值。配置权由真实目标拥有者控制，撤除声明不能冒充原子撤权。

重新采用通过受信部署端 createSettingsMaintenance.rebase 进行。该端口不是租户命令或 agent tool。每个旧配值和锁必须明确保留或丢弃，保留值在新定义下重新验证。定义/来源变化不会自动迁移同名值。具体条件和事务归 [本地行为](../../settings-local/SPEC.md)。
