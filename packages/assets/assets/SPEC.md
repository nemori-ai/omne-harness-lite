# assets长期行为规格

状态：候选、待用户确认。目标位置为`packages/assets/assets/SPEC.md`。本文约束共同资产治理的非类型行为，不表示公开API、实际包或实现已经存在。产品依据见[产品正文](../../../.meta_harness/design/product/assets-and-rules/design.md)，责任依据见[领域架构](../docs/architecture.md)。

## 阶段与长期范围

0.0.0 -> 0.1.0 完整支持本成员所拥有的 CAP-AR01、02、03、04、05、07，并与 settings、permissions 及实际准入方共同兑现 CAP-AR08。包括共同身份与定义、草稿维护及版本发布、持有管理、合法候选和同标识替换的实际求值、工作区来源接入。不能只保存输入或声明而不兑现公共操作。整体能力及协作分工见[阶段映射](../docs/architecture.md#阶段范围)，支持程度归[产品阶段承诺](../../../.meta_harness/design/product/assets-and-rules/design.md#阶段与版本支持承诺)。

组合展开及流转依赖、完整解释、复制、分享、提升、独立刷新业务和完整治理观测仍维护长期契约，但未选能力不成为该阶段的独立交付要求。阶段内操作必须保留其必要来源与版本依据、资格核验、可辨失败及适用耐久保证。下面流转条款适用于对应能力实际开展时，不以预先实现流转作为草稿发布或候选求值的前提。

关键旅程及正常、拒绝、取消和恢复交接见[关键流程](docs/internals.md)，本成员的逐旅程验证落点见[持续验证场景](#journey-verification)。

## 调用方与责任

治理入口发起定义、持有及流转操作；assembly读取合法候选及采用依据；settings与permissions读取持有、来源和定义属性；资产类别消费共同身份及版本规则。调用方须提供操作所代表的主体、明确资源范围和适用的当前资格，不从进程、连接或当前目录补租户。

纯计算可以消费调用方提供的数据；访问系统托管定义、私有材料或状态时，实际集成边界仍核验资格。提供者不能借自身权限替原主体访问其他租户。资产ID、发布版本、复制血缘和句柄用于定位，不构成权利证明。

assets拥有共同状态与变更结果，类别拥有专有声明与内容校验，assembly拥有整体采用，独立runtime拥有实际执行。共同治理不承担所有类别的调用行为。

## 身份与必要区别

<a id="identity"></a>

能力标识由类别和name构成，说明、Schema、子命令、配置和实现包不参与该身份。具体资产记录在同标识下分别保留所有者、作者、来源、草稿和发布版本线，不因同名自动合并。

同层可有多个同标识资产记录，但一个能力标识至多持有一份。资产记录的存在与本层持有分别可查询；新副本不能通过同名自动占用已有持有。成员角色或资格变化不改租户身份、历史作者及既有资产归属。

资产定义数据、执行实现与承载服务分别标明采用依据。它们不要求一一对应或同时换代；报告可执行前，类别与实际采用者保证数据和实现匹配。不能用“只换实现”绕过替换锁或使用资格。Tool 类别例外：工具资产的 body 带实现引用 `implementation { executor, module, construction }`，定义数据与实现仍分别标识，见 [RFC-0012](../../../docs/rfcs/RFC-0012-tool-dynamics.md#对象链)。

## 定义、草稿与发布

<a id="definition-and-version"></a>

合法创作在明确范围产生具体资产及草稿，并保留实际作者和人或Agent的产出来源。Agent提交仅接受获准工作区或租户位置，不得直接产出组织资产，也不得代用户执行组织提升。工作区提交不自动成为会话租户所有物。

人类在组织范围合法创作的资产归该组织，在自己租户范围创作的归该租户，个人组织的人类创作沿其个人组织归属；作者保留创作时租户身份。官方资产的作者和所有者为平台，不补造租户。Agent 产出归其合法提交的工作区或租户，不能把会话归属或请求者身份当作所有者的通用替代。创作成立时必须保存符合该映射的所有者和作者；角色变化不改历史归属。组织创作的具体委托资格另行细化，不由这个归属映射授予创作权限。

发布前通过适用共同校验和类别校验。发布成功形成不可变版本；后续修订新草稿和新版本，不覆盖已发布字节。过期草稿编辑不能静默覆盖他人已确认修改，应报告冲突和可核实的当前结果。

版本选用与发布分开。持有明确固定版本或跟随当前版，不另指定时跟随当前版，该选择对管理者可见。固定版本不因发现新版暗换，跟随者在后续求值采用当前发布版。例外：对已有会话的工具常驻项，跟随持有只在新定义与会话首次装载的定义同形时才跟，见 [RFC-0012](../../../docs/rfcs/RFC-0012-tool-dynamics.md#会话常驻集合的规则r1r5) 与 Tool 契约的[会话常驻规则](../../tool/tool-contract/SPEC.md#会话常驻规则r1r5)。分享只能跟随，主动确认的重复复制按其规则更新。新的选择只作用于规定后续采用点，不能改变已捕获的调用内容。

定义可携带 immutable 不可替换声明，随本次合法采用的发布版本或工作区定义解释；未采用的草稿不能暗改运行消费者的约束。声明的替换效果归[候选求值](#candidate-resolution)，不表示该资产不能修订草稿、发布新版本、禁用或移除，也不自动锁定设置、权限或引用能力。

类别校验、来源或存储不可取得时，返回可辨的依赖失败，不报告发布成功，也不将未核验内容当合法空定义。具体公开类型、类别扩展协议及发布入口尚待设计，不据此引入新角色或上架政策。

公开接口和并发协议的缺项须在实施前补齐，不取消该阶段草稿维护、发布和选版的公共行为承诺。类别提供正文语义与专有校验，不能将公共发布逻辑全部移交每个类别重复实现。

## 持有、禁用与移除

<a id="holding"></a>

加入须有该范围的管理资格及合法权利依据。组织层加入要求“组织持有管理”资格，由所采用治理模型映射到组织角色；租户层由本人按资格管理。成员不能因可使用资产就管理组织持有。加入使属性可被本层配置，但不保证某个Agent选入或能够实际执行。

禁用保留持有及全部配值；再启用只解除本层自己的禁用，不解除外层禁用。移除结束持有，配值随之退出，不存在脱离持有的可生效配值。配值写入与移除竞争时，不能报告一个已不存在持有上的有效配置。

改版、移除、退役及源删除先识别受影响引用和消费者，说明影响，不默认级联删除日程、Agent定义或其他资产，也不把治理变更当实际工作已停止。官方能力不得清空或禁用。

## 人工提升的长期行为

<a id="promotion"></a>

本节维护 CAP-AR14 的长期承诺，不纳入 0.0.0 -> 0.1.0 的实现范围。

租户到组织提升改变所有者且不可逆，历史作者、原有持有及配值保持，组织不自动新增持有。提升后的既有分享以组织级分享设置重新判断：仍可分享则保留，否则撤回。不得一律撤回、一律保留或凭此增加重新确认要求。提升结果与对应分享处置必须对外呈现一致的当前事实，不能出现已归组织却仍绕过组织分享限制的可用关系。

共享工作区或外部仓库资产允许直接人工提升到组织，不要求先转入租户层。发起人须具来源处置资格，目标组织具备“组织持有管理”资格的人须确认接收；发起、通知或普通写入成功均不等于提升完成。Agent不得代用户发起或确认。托管工作区发起人须为治理所有者或其明确授权的人；外部仓库发起人须提供可核实的资产处置权或明确授权依据。当前来源处置资格和目标组织的“组织持有管理”资格分别核对，依据不可取得或失效时不得完成提升；不得默认以访问、参与、写入或作者身份放行。来源处置、组织接收及适用的分享处置须呈现一致的当前事实；精确提交与恢复协议另行设计。

## 合法候选与替换

<a id="candidate-resolution"></a>

求值消费明确组织、租户及可选工作区，取得获准来源。依次执行禁用过滤、当前使用资格过滤和同标识选择，保留过滤原因、来源、版本及锁定依据。当前不能使用或已禁用的更具体候选，不遮蔽其他合法候选。

普通适用顺序为官方、组织、租户、工作区。在完成禁用及使用资格过滤后，按合法层序识别定义不可替换声明及持有层替换锁，再选择不违反约束的最具体实现。合法采用的资产定义声明 immutable 时，该采用层以下的同标识其他资产不得替换它；不要求持有者另行加锁。持有管理者按资格设置的替换锁独立成立，任一适用约束都不能被下级配值或声明解除。

约束只向更具体层生效，不反向限制上级。同一具体资产在下级继续持有不算替换，选版及配值仍沿各自契约；被禁用或无使用资格的候选不能凭其声明或持有锁截断其他合法候选。未声明 immutable 的定义不引入额外的定义替换限制，已存在的持有锁及类别例外仍有效。

meta能力、official AgentDefinition及其他已采用类别例外分别保护，不以“官方可替换”取消例外。官方能力标识求值为空时报告缺陷，不能作为成功配置。

工作区共享与local在同层先过滤，合法local同标识候选优先，缺少合法local时仍保留共享候选。上层锁不受同层目录优先级影响。目录名和地址不构成身份、访问资格或租户私有保证。

0.0.0 -> 0.1.0 的系统组合须接通实际获准的官方、组织、租户及工作区来源，来源提供者按资格取得材料，assets 执行合法候选及共享、local 同层择取。独立纯计算可消费调用方给定的事实，但不能据此认定实际来源读取、资格核实或系统接入已完成。工作区身份及访问规则由原拥有者提供，不将 local 当租户私域。设置逐项合并归 [settings 工作区规则](../settings/SPEC.md#workspace)，使用资格归 [permissions](../permissions/SPEC.md#usable-by)。

装配选入能力身份与解析该身份的实现分别维护。自动继承只开放某层能力名单，不屏蔽合法更具体层同标识实现；对能力身份的排除不会因换实现失效。该三类继承规则由Agent与assembly拥有，不扩成所有资产类别的统一继承。

替换不移交原具体资产的设置值及凭据。同能力身份的锁定权限上界及主动配置的不可覆盖操作限制均继续约束替换件，删除权限项声明不能使受限操作变为允许，精确规则归 [permissions](../permissions/SPEC.md#bounds-and-picks)。替换来源、定义声明、持有锁及过滤有可消费依据，不能因定义变化暗改历史调用。合法更新失败时不发布混合旧新输入的半份候选，整体清单由assembly决定是否采用。

## 组合与类别扩展

<a id="composition"></a>

本节维护 CAP-AR06 的长期组合及流转依赖行为；共同类别接入不据此扩张为 0.0.0 -> 0.1.0 完整支持任意组合。

组合引用能力标识，当前合法实现按完整作用域解析。引用不转移所有权。Plugin内含成员随Plugin版本及权利治理，不接受单独顶层卸载；外部引用不随复制或分享搬成目标新资产。共同流转入口在复制或分享发起时核对目标侧提供者，源侧有而目标侧缺失的引用须当时告知。不能仅在后续装配报缺失；此义务不新增流转拒绝政策。

无终点的AgentDefinition递归展开须在有效定义采用前拒绝，并说明循环依据。Skill与Tool配套互引各取一份，不被等同递归组装环。当前未支持的组合范围不扩大为永久禁止，新组合须有采用依据及类别保证。

Plugin成员启用值在展开该Plugin时先求，之后再投影实际属性。不能靠将所有属性延迟到展开后而形成不可计算的循环。依赖身份无合法定义时明确指出缺失，已有合法定义但执行暂不可用交给类别及assembly按不可用规则处理。

## 资产复制

<a id="copy"></a>

本节维护 CAP-AR12 的长期复制行为，不纳入 0.0.0 -> 0.1.0 的实现范围。

发起核验源所有权、已发布版本、合法目标层及方向条件。源版本和目标范围固定于原逻辑操作；后续发布不暗换已发通知中的版本。本人型核验同一账号的两侧有效租户；组织型核验同树组织级及源当前管理员，目标确认时核验目标管理员。

本人型合法发起即执行。跨主体发起仅产生待确认通知，尚无目标资产或新版。组织型首次与重复都须目标确认，旧确认不能用于下一次覆盖。禁止团队资产进入个人组织、跨树及未定义方向，不允许通过导出、模板或打包绕过。

首次按目标层建立独立资产、v1和同源血缘，源保留。无既存同标识持有时，同时建立该副本的持有。已有持有时保留原选择，新副本并存；不能借复制自动替换。作者为目标侧实际带入者租户，源作者不变。复制不携带源配值或秘密。目标公开交付人、时间及交付版本，但不因此获得源对象内容读取权。

重复只按目标层的复制血缘匹配原目标资产，整体生成其新版本并采用；不做合并、不覆盖其他层副本、不以能力标识判定更新。不变项的目标配值及锁保留；删除项不参与，新项走默认。源及目标后续修改互不自动传播，目标旧版本仍可查询及回退。无血缘同名资产新增并存，持有选择由目标管理者另决定。

复制确认、目标资产或新版本、血缘、适用的首次持有建立和对外结果需要共同成立。确认应答丢失时按原操作查结果，不能重试产生第二份v1或多加一个版本。并发重复复制不得以较旧未成立写入静默覆盖已确认的新状态；原子协议留机制设计，行为不得依赖碰巧单线程。

## 分享与邀约

<a id="sharing"></a>

本节维护 CAP-AR13 的长期分享行为，不纳入 0.0.0 -> 0.1.0 的实现范围。

只允许所有者按已决定方向发起分享。跨主体邀请未确认前无使用权，本人型合法发起即成立。确认时核验当前目标资格、源资产存在、分享资格、关系和时限，不能只验证邀请创建时条件。

邀约待确认、已确认和结束可辨。发起者撤回、到期或源消失后不可确认；重新发起是新邀约。分享邀请和复制通知各自按部署默认或本次显式时长取期限，不能猜默认数值。确认与撤回、到期及关系解除竞争时，只有符合条件的单一终态成立，不能一边结束一边创建可用权利。

已确认分享持续指向源当前发布版本，所有权不动，接收者可配本层值、合法替换或移除，不能改内容、复制、再分享或提升。已经成立的分享无到期或暂停状态，分享方可撤销；相关成员关系或隶属条件解除时结束。重新加入或重新隶属不复活，旧备份或重放通知不重建已结束权利。

同组织资产的角色使用范围由permissions求值，组织级对本组织成员不新增分享流程。分享给组织由目标管理员确认及移除，给租户由该租户本人确认及移除。普通成员不能代表组织接受。分享无集团强制管辖含义，接收者仍可合法退出。

## 生效、取消、恢复与结果真实性

<a id="failure-and-recovery"></a>

变化通知不是提交依据，也不是实际停止确认。撤销、禁用、移除及资格丧失作用于相应后续求值或准入，已发调用保留原输入及真实收场。会话已知Tool、Skill、MCP身份由其拥有者保留，assets候选过滤不删除该历史，也不向撤权主体泄露新定义。

管理操作取消与提交竞争时核实原操作事实，不假定取消回滚已确认变更。多步操作分别返回已完成与待处理，未完成步骤不能伪造成功。持久保存确认前须达到SYS-DURABILITY边界；进程崩溃、操作系统崩溃或断电恢复后仍可读取已确认定义、版本、持有、关系及操作结果。介质及整机物理损毁不在此保证内。

来源不可用、权限不足、引用阻断、版本冲突和真实空集合分别可辨。无法取得允许依据时不开放依赖动作；对历史快照只可表达原采用事实，不能充当无限有效的新授权。未知结果不报告失败并自动再做一遍，也不报告成功。

秘密值不进入原文审计、遥测及来源说明。观察治理结果不产生虚假的模型或工具执行账。审计保留实际主体、范围、变更和合法依据，不因程序代理改变责任。

## 持续验证义务与未覆盖

0.0.0 -> 0.1.0 须验证本成员的公共操作及实际来源、求值组合，不能只检查表示合法。至少覆盖草稿并发与不可变发布、固定和跟随选版、同层持有唯一、禁用与移除分别处理、合法工作区共享与 local 来源、无资格候选不遮蔽回退、实际来源失败不伪造空集合。

创作归属验证组织、本人租户、个人组织及官方来源分别采用规定的所有者和作者，不能只接受任意格式合法的 owner。Agent 提交到工作区不能被记成会话租户所有，提交到租户不能被记成组织所有；成员退出或改角色后历史作者和归属保持。

不可替换验证覆盖合法上层定义自行声明 immutable、持有未加锁时仍阻止下级其他资产替换、定义声明与持有锁分别生效、同资产在下级继续持有、被过滤候选不锁住回退、下级声明不限制上级，以及声明不冻结属性或阻止合法新版本。替换还须与 permissions 验证未加锁的操作不允许值不能被绕过，与 settings 验证设置及秘密不迁移。

直接提升还须验证只有写入或参与资格者不能发起、来源授权失效不能完成、目标尚未确认不能呈现已接收资产，以及Agent不能代人提升；目标接收与适用分享处置一致。这些直接提升验证属于长期流转义务，不纳入 0.0.0 -> 0.1.0 的交付范围，也不是已运行结果。

长期流转开展时还须验证同名无血缘复制覆盖了目标自建安全件、重复组织复制未等目标确认、分享结束后重入复活、提升全部撤回而组织仍允许分享等反例。Agent不能直接写组织资产、失效 local 不遮蔽合法共享、替换不迁移旧凭据、旧编辑不覆盖新草稿、响应丢失不重做多出版本及治理变化不抹除真实执行效果，则继续约束适用的阶段内公共行为。

组合验证须涵盖当前身份和关系变化、配值与持有共同有效、来源失败保留旧采用状态、已知能力不可用及完整清单采用。单独文件存在或类型通过不证明这些性质。

未覆盖的精确表达包括公开类型及错误集合、操作身份、版本比较、提交与查询协议、扩展契约、类别兼容、来源刷新和原子性机制。直接提升的资格核实与组织接收机制继续细化，组织创作委托不补政策；不将租户提升的全部持有及源侧处置规则自动套到工作区或外部仓库。连接件继续排除。本文不承诺提供者尚未设计的机制或未运行的验证结果。

## 类别提供方

<a id="category-provider"></a>

状态：已由 [技术接受](https://github.com/nemori-ai/omne-harness-lite/issues/264#issuecomment-6186685166) 接受，是该节的现行行为。上文仍是「候选、待用户确认」。本节的接受状态与上文分开。本节不定义编程语言里的类型名。

与上文的关系：

- 「类别扩展协议及发布入口尚待设计」仍然有效。公开类型见[已接受的公开类型](#accepted-public-types)。本节的操作和两个样例仍然有效。
- 「不另指定时跟随当前版」与项目要求里「未写明版本则采用当时的合法胜出者」指向同一选版结果。已捕获的调用内容不因新版本改变。

类别提供者列出候选项，并按点名的版本交出正文。候选项说明六件事：身份与版本、治理所需信息、交互、失败、资源、验证责任。身份是类别加 name。提供者不决定本次采用。来源、类别校验或存储不可取得时，返回可辨的失败，不把未核验内容当成合法空定义。

Cordis 按组合挂载提供者。提供者向装配侧的注册表登记。注册表不导入提供者的实现包。理由见[内部设计](docs/internals.md#category-provider-seam)。

### Tool 样例

成功。求值没有写明版本。提供者交出候选项。身份是 Tool 加 `read_file`。版本是当时的合法胜出者 `v3`。正文是该工具的参数声明和执行说明。装配侧决定这次采用。采用依据记下 `v3` 和当时交出的正文。同一次执行读取这份正文时，读取采用依据里的正文。后来发布的 `v4` 不改写这份依据。尚未发出的后续调用若遇到合法刷新，可以按架构页看到新的定义。已经发出的调用仍使用依据里的正文。

失败。同一身份没有合法定义。提供者返回失败。种类是缺合法定义。不交出空正文。装配侧不形成新的采用依据。

### Skill 样例

成功。求值写明版本 `v2`。提供者按 `v2` 交出正文。正文是该 Skill 的任务指令。固定为 `v2` 不豁免资格。资格不成立时，提供者返回失败，种类是候选被拒绝，不交出正文。正文一经记入采用依据，后续读取仍是这份记录。尚未取用的另一 Skill，后续取用读取当时的合法版本。

失败。身份里的类别没有已接受的拥有者。提供者返回失败。种类是无类别拥有者。装配侧不解释该正文，也不采用。

## 已接受的公开类型

<a id="accepted-public-types"></a>

PanQiWei 于 2026-10-15 接受这组编程类型，记录见 [Issue 272](https://github.com/nemori-ai/omne-harness-lite/issues/272#issuecomment-6194044008)。上文「类别提供方」的操作不变。

共同资产导出 `capabilityId`、`createCategoryRegistry`、`unknownCategory`、`isReadBody` 和 `pinBody`。类别是非空字符串。`register` 拒绝空类别名和重复登记。`lookup` 找不到类别时，`unknownCategory` 返回 `unknown-category`。`readBodyText` 返回的正文是冻结副本。`readSnapshot` 只在参数就是这份副本时返回它，否则返回空。`isReadBody` 表示同一次判断。调用方不能改写副本，也不能在上面安装取值函数。复制失败时抛出，不把它说成 token 语法错误。`pinBody` 再复制这份冻结正文。登记端口时复制的 `schema` 只是冻结副本，不是 `readBodyText` 的结果。成环或无法复制时拒绝。`judge` 和 `pinBody` 不接受它。判断和固定都不读取调用方后来换上的函数。未经 `readBodyText` 的正文被拒绝。判断失败后，声明和引用抛出的错误带上同一次拒绝原因。

`BodyContract` 的字段是 `category`、`schema`、`judge`、`deriveDeclarations`、`references`。正文文本先经 `readBodyText`。它调用 `@omne-harness/json-text` 的 `readJsonText`，不另写解析器。`judge` 只接受这份读取结果。对象字面量、伪造的种类和空条目都返回 `incomplete-reference`。判断不调用传入的函数。`judge` 的失败结果带 `ok: false`。声明和引用接收同一次判断的上下文。判断失败时它们抛出，不返回声明或引用。

本次不调用 `@omne-harness/schema-provider`。`schema` 是类别拥有者随端口给出的说明文档，由同一次文本读取得到。正文是否合法由 `judge` 决定。公开入口是 `readBodyText` 和 `judge`。验证命令是 `pnpm --filter @omne-harness/assets test`。

能力身份是类别加 name。本卡不重新定义 `AccountId`、`OrganizationId`、`TenantId`、`LoginStateId` 或 `ScopeLayerIdentity`。这些值不是本卡的输入，所以本成员不依赖 `@omne-harness/legal-identity`。本成员不依赖装配、Tool 或 Skill 的实现包。Tool 绑定登记表的来源层（`official`、`organization`、`tenant`、`workspace`）与 `ScopeLayerIdentity` 的关系，待识别拥有者后协调，见 [RFC-0012](../../../docs/rfcs/RFC-0012-tool-dynamics.md#绑定登记表g7)。

`@omne-harness/tool-contract` 登记 `tool`。名字与能力名不一致时返回 `name-mismatch`。`composes.skills` 只变成 `skill` 身份引用。`@omne-harness/skill` 登记 `skill`。`tools` 里每一条都必须是 `tool` 身份。读判断不执行正文里的函数。Skill 包不依赖 Tool 包。`@omne-harness/agent-contract` 的 `agentBodyContract` 登记 `AgentDefinition`，正文规则见 Agent 契约的[资产正文契约](../../agent/agent-contract/SPEC.md#资产正文契约)。
