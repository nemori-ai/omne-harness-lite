# Local provider constraints

The behavioral authority is [core/tool-execution-runtime/SPEC.md](../../core/tool-execution-runtime/SPEC.md). This file specifies provider policies that public types cannot enforce.

LP-1 Configuration is a strict ordinary JSON object. `frameQueueBytes` is a nonnegative safe integer. Retry attempts are a positive safe integer. Delay bounds are finite nonnegative milliseconds, with the minimum no greater than the maximum. `resultStorage` identifies the actual injected result store. Unknown configuration fields fail construction.

LP-2 The frame budget bounds the cumulative UTF-8 JSON bytes of accepted author frames for one execution. Capacity rejection preserves the previous assembly and records a quota trim. A zero budget accepts no author frames. It does not suppress the terminal result or treat a stream trim as author failure.

LP-3 Tail conflicts trigger a complete recheck and configured capped exponential delay. A retry does not substitute a new admission proof, executor generation, or author result. Policy exhaustion retains any durable obligation and reports unavailability.

LP-4 Startup enumeration uses private maintenance authority. Unreadable or invalid sessions and unconfirmed resource cleanup prevent readiness. Close retains a failed cleanup obligation for retry; it does not release the journal borrow on a failed recovery attempt. Existing delivery obligations remain in the common log for the application delivery owner.

LP-5 Unsupported execution dependencies fail before author entry. The provider cannot use dependency declaration defaults as resolved settings. backgroundThreshold is an upper caller waiting preference, not an execution dependency. Its declaration does not prevent execution or create a runtime timer. Interactive answers and cost reports cannot return successful reception until their durable protocol is implemented.

LP-6 The close adapter preserves the original runtime.ready Promise. Managed startup also requires successful control retention and current ownership. A retention failure rejects managed readiness without changing the root readiness result. The adapter close starts one original close attempt and remains pending after rejection. The host can observe the retained attempt and explicitly retry the same instance. Concurrent retries share one attempt. The adapter does not schedule retries or change the root retry policy. Successful close is permanent. It does not close shared dependencies or reopen admission.

The managed tool binding uses startAssemblyWork, which registers the outer work before resource creation. Its setup creates the original runtime and its safe work. It first gives that control to the row port, then gives the same reference to ToolRuntimeStartupService, before awaiting runtime.ready. These handoffs give two owners the same control. They are not repeated retention by startRetainedAssemblyWork. The outer close awaits the original safe work.close even after startup failure.

LP-7 The tool environment placement source uses the original public tool observer and CurrentEvaluationInputs. It releases that temporary observer after each read. It verifies the original tenant, session, CallId, live execution, selected asset, version, and tool body. It cannot replace that selection with a newer version or different body. A pure tool returns notApplicable without a permission input read. A missing or ended execution cannot grant placement.

LP-8 Environment permission comes from the original asset-evaluation algorithm and an explicit factoryPermission. The source requires one effective executionEnvironment value and a valid effective targetEnvironment. An empty, unknown, or multiple permission set rejects policyUnavailable. Invalid inputs reject invalidInput. Input IO failure rejects unavailable. A foreign input tenant rejects notAuthorized. Represented identity and evaluation fingerprints locate evidence; they do not grant authority. Each source instance has a new opaque generation.

LP-9 New facility operations re-read current input for the original call. The requested facility must belong to both the original and current requirements. A newly forbidden host effect rejects notAuthorized. A binding outside the original ownership rejects notAuthorized. Re-evaluation does not select or acquire a successor environment. Existing process observation and cleanup remain with their original owner.

LP-10 The Cordis placement plugins are static exports. Their configuration contains only name, factoryPermission, and an explicit unique or reference selection policy. There is no implicit first-candidate policy. The reference must belong to the complete matched set. Trusted root construction can supply a different selection function. The plugin does not accept that function as configuration. Source contribution and its pending calls follow the registering plugin's lifetime.

LP-11 原环境 lease 失效触发原终局路径，旧执行不获取替代环境。只有原 lease.release 确认 released 才放弃活体租约；pending 或异常仍由原执行 owner 持有并承担原释放责任。后续 close 只重试原 lease，失败不假报关闭完成。冷恢复仅维护原资源引用并异常收场，不重建作者栈或租约。单个工具 runtime 关闭不销毁共享环境 registry。

LP-12 Original resource plan, permission, adoption, and terminal decisions share the ToolJournal prefix. Adoption transfers an existing permitted resource only to the original adopted environment. Call release does not destroy that resource. Each later action needs its own plan and permission. Startup maintenance uses recoverOwned for original environment resources, records only matching original keys, and preserves partial failures as pending readiness. It does not replay actions or create substitute resource keys.

Journal 每会话队列开始下一项前，先让 Node 的维护计时器与 IO 运行。恢复后仍执行原准入、拥有者代际及提交检查。让出事件循环不授予资格，不重置超时，不承诺特定调度延迟。关闭仍须排空原已登记任务。


LP-13 The original-issue factory uses the same execution owner, journal codec, invoker, and recovery path as the ordinary factory. Its required trusted support is not JSON configuration. The application composes `toolOriginalIssueMigrations` with the same storage that the Session log participant uses. Each native owner has one execution generation. Each execution retains its full original intent, immutable identity, selected implementation, and live claim.

LP-14 The original participant verifies the shared StorageUnit, current qualification, original owner lifetime and fixed tail before staging intent and the native claim record together. It reads only the original Tool call records, not a complete Session prefix. The Session coordinator retains its own preparation and current-fence checks. A changed tail requires retryFromFacts. An existing Tool intent without the expected native identity is a conflict, not permission for a new claim. A known rollback cannot authorize entry. A later staging attempt replaces its rolled-back claim; the old object remains invalid. Existing committed intent does not issue a new claim. Claim consumption rechecks qualification and the durable original intent. A copied object, another owner's claim, or a claim with no original durable record cannot authorize entry.

LP-15 The native owner treats Session admission and consumption results as separate steps. It verifies the actual original commit before using an issued claim. For an executable request, claim consumption and the original `execution_started` record use the same caller transaction. Both roll back if that transaction fails. A prepared non-executable request consumes its original disposition claim without a start record or author call; it retains the original terminal, account and delivery obligations. The start record identifies the granted execution; it does not prove author entry or a physical effect. The owner enters the author only after observing that transaction committed. An uncertain result retains the original job and claim. When a still-live owner verifies consumed state without having delivered launch or entered the author, it closes the entry gate and uses the original terminal path to record `original_consume_unconfirmed`, its account, and its delivery obligation. It does not manufacture physical cost or success. No result is reclassified as a model Pending or acknowledged through the model protocol.

LP-16 A participant's `stopped` promise remains pending while its original author, terminal write, or owned borrow is unresolved. Job completion and successful return of its implementation and environment allow completion. A task failure rejects that promise. Closing the runtime cannot infer quiescence from a missing intent after uncertain admission. It retains the owner until the original transaction outcome or committed intent is known. Result delivery remains the original delivery owner's responsibility under LP-4.

LP-17 `createToolOriginalIssueVerifier(storage)` provides a trusted read-only check over the original native identity record. It uses the caller's unit and the same storage, without a new transaction. It checks the full original identity, including execution generation. Absence or a different identity returns false. Invalid stored JSON raises StorageDefect. The verifier does not issue or consume a claim, enter the author, or prove physical stop. The root retains the shared storage for existing custody obligations; closing the original job does not delete its identity record.

LP-18 The request producer selects the applicable `after_action` pieces with scope `each`, in their original chain order. The native owner captures this supplied chain without selecting another chain. Its delivery basis excludes pieces for other positions or for scope `batch`. The captured chain must match the chain that the result-delivery owner replays for that execution.

LP-19 `createToolExecutionRecordReader` provides the readOriginalIn part of ToolExecutionRecords over the original log participant. Its trusted construction fixes the tenant, storage and authority, and borrows only sourceIn and readByKeyIn. It reads the call key produced by the Core codec in the caller's actual unit. It does not enumerate Sessions, read their full prefixes, open another transaction or close borrowed dependencies. It checks each returned record with the Tool codec and projects only that original call. Foreign tenant or malformed reference data returns invalidSource before reading. Denied or unavailable sources return unavailable. Other-domain records claiming the Tool key, invalid Tool transitions or mismatched calls return invalidSource. An authorized empty key result returns absent, which never grants execution. Storage defects propagate. This reader supplies no staging, recovery coverage, readiness or physical-stop proof.

LP-20 The original native owner retains an opaque job and its stageTransitionIn and terminalIn participants. Only the original job object can stage a transition. A copied job, another call, or an unissued original cannot stage records. Each operation checks the original native identity and intended entry in the caller's StorageUnit. Transition staging reads only the original call key, validates the Tool state transition, and appends at the actual fixed source. It does not commit the unit or authorize author entry. The caller owns the shared commit and retains uncertain outcomes. The same complete batch is recognized at its original positions; a partial or different batch conflicts. The source propagates storage defects. Closing admission prevents new issue and consumption; the retained original job can still stage its terminal and cleanup records. Releasing that job refuses further staging. An exact original identity can still read its recorded terminal for custody after that release. These participants do not calculate Session late status, enumerate recovery obligations, or prove physical stop. The ordinary execution and cold recovery consumers remain separate migration obligations.

LP-21 Ordinary reads of a known original native job use its own call key in the actual caller unit. The private snapshot contains the actual journal coordinate and only that Tool history; it is not a complete Session prefix. Snapshot, Context, environment and cleanup consumers use this read path. The owner checks its generation before and after reading and retains in-flight reads through close. A known rollback or unstaged rejection has no original record. An uncertain original cannot be reported as absent. A committed original with missing or invalid records remains unavailable. Admission and cold recovery still require their separate consumer migrations; this read path does not satisfy those obligations. Native terminal classification uses the Session input specified in LP-22.

LP-22 A native original job reads its own records to finish. Before staging its terminal, the owner obtains Session's classifyTerminalIn result in the same actual storage unit and applies only that result to the account's late field. The pool does not read the complete Session prefix for this decision. An unavailable classification prevents the commit. A lost commit reply leaves the original terminal recognizable with its original account; recognition does not classify or invoke the author again. The older non-native admission and recovery paths remain separate migration obligations.

LP-23 A prepared non-executable request contains the original adoption and either `unparseable` or `no_such_entry`. It cannot contain a selected implementation or arguments. The native owner preserves the supplied reason and chain; it does not inspect Session history to choose them. The trusted Session admission must verify this reason against the completed original batch in the shared unit. The absence of a token on this path grants no author execution.

LP-24 `createToolExecutionObligations` binds a trusted storage instance, one tenant and an explicit maximum page size. The root owns this read capability; request fields cannot select another dataset or grant maintenance authority. It reads only the native `tool_original_issue` index, whose row and original intent are staged in the same unit. It validates the stored intent, complete original identity, claim and consumption state. It returns references in Session/call order, without filtering consumed or terminal jobs. It does not read Session history or verify current execution permission.

The first native read pins the snapshot before the reader is published, including for an empty index. The consumer runs outside the storage read scope and may commit independent work. Each reader permits one pending `next`; overlap or an invalid row makes the whole borrow unavailable. Callback completion expires the reader, drains pending reads and waits for storage release. Original callback, read and release errors are preserved, in that order. An identical error object is reported once. An expired reader returns unavailable.

This source covers native original rows only. It cannot prove coverage of legacy jobs that did not create those rows, validate their resource cleanup, or establish pool readiness by itself. Cold recovery must pair each returned reference with its actual Tool records and existing maintenance/resource authority. The runtime constructor migration remains required; an empty native index is not proof that a mixed legacy dataset has no obligations.
