# 文件提供者的行为

公开业务承诺归 [Tool Runtime 薄规格](../../core/tool-execution-runtime/SPEC.md)，尤其结果字节、原文引用、终局可见性和恢复读取。此处仅记录文件后端的补充行为。

RF-1 发布使用提供者生成的固定文件身份。相同身份和相同字节可以认回。不同字节不能覆盖已发布文件。

RF-2 返回发布成功前，文件内容及目录项必须完成同步。字节文件先确认，才能发布引用元数据。任一未知步骤不能被当作发布成功。

RF-3 文件名不能携带调用者路径。根目录被替换、文件是符号链接或文件不是普通文件时，读写失败。此检查不声称隔离同权限的恶意 OS 管理者。

RF-4 关闭先拒绝新操作，再排空实际 IO。未关闭的句柄和未完成的临时文件清理由本任保持责任。失败后可以重试关闭，不能报告已关闭。

RF-5 已绑定 writer 仅保留本调用的耐久结果准备权，不依赖原观察者或原用户绑定继续有效。撤权后不能新绑定 writer，普通读取仍受当前授权约束。该 writer 不能选择新的 ref，也不能授予工具新的业务动作。交付确认后关闭该写面。

RF-6 读取作者结果须匹配已确认终局中的原返回。后置消息投影不改变原结果；其他终局胜出时，预存作者内容不可见。读取字节须匹配 scope、引用元数据、固定身份及原字节摘要，不能只凭文件存在返回成功。

RF-7 reader 的可用性来自指定版本的实际实现登记。核验期间撤除或换代则返回不可用，不用旧快照宣布可用。

RF-8 管理绑定在打开文件资源前登记本行 ready/close。打开完成后再次核验本代资格，才能发布结果服务。启动失败仍收尾已取得前缀，不能用 fiber ACTIVE 代替文件根准备完成。

RF-9 `openToolResultCustodySource` 是受信根选择的只读来源。构造输入为同一个 AtomicStorage、SessionLogParticipant、LogAuthority 和原身份核验端口。原身份核验须来自实际 native 原发起拥有者；调用方数据和当前成员角色不能替代它。来源在调用者 Unit 内核原完整身份及原 intent、origin、adoption 和精确终局，不另开事务。坏构造的跨库 Unit 由存储断言暴露。

RF-10 来源复用已发布的作者结果和字节校验。存在作者返回时，缺失或不匹配的持久结果不能通过。引用集合覆盖 raw、作者内容／摘要／附件、嵌套工具结果、媒体派生内容、交付投影及内部消息。每个引用须属于原调用，元数据和摘要须匹配原完整字节。此核验不声称文件发布与 SQLite 保管提交形成跨库原子提交。

RF-11 来源拥有自己的文件读取句柄。关闭先拒新、等待原核验结束，再关闭句柄；不关闭借入的日志或存储。已发布文件没有提供者删除、覆盖或过期路径。现有清理只移除本任未发布的临时文件；Run 结束、writer 关闭和来源关闭都不删除原结果。可信根须继续保有目录及原日志，直到 Session 保管责任结束。RF-3 对同权限 OS 管理者的限制继续适用。

实际 native 工厂、Session 同单元准入／保管／普通交付和文件来源的正常组合由 Session 提供者维护可复跑验证。当前资格、根资产及 Context 输入的受控组合不能替代完整 Session driver、Cordis 或产品环境验收。
