# Files tool behavior

Public shapes belong to [src/index.ts](src/index.ts). Product rules belong to PF-007 Files. Cordis integration follows the shared integration conventions.

1. The pure factory uses explicit policies and a borrowed image codec. It creates its parameter judge unless the caller supplies one. Each call uses only its injected FileFacility, Runtime Context reader, signal, and attachment writer. No ambient filesystem, Shell, provider selection, or background mechanism exists in this tool.
2. Help requires no environment. Other commands resolve relative paths from the current `files.initial` value `{cwd}`. The key is configurable. An absent, invalid, or unauthorized value fails explicitly. A default directory is not a permission fence. Absolute paths retain the selected environment's semantics.
3. Unknown fields and invalid parameter types fail before reading context or calling facilities. Parameter compilation is lazy and cached by the factory-owned judge. Explicit construction limits bound returned reads, pages, edits, targets, writes, images and diff work.
4. Edit matches are literal. An ambiguous match needs a one-based occurrence. Occurrences count every matching start position, including overlapping candidates. Only the selected candidate becomes an edit. Every patch edit uses the same original text coordinates. Overlapping selected edits and duplicate normalized paths fail. Invalid UTF-8 is not silently replaced. CRLF, Unicode and final-newline differences remain significant.
5. All patch files are read and checked before one original `commitBatch` call. Precheck failure or cancellation before submission changes no target through this tool. Conditions are metadata checks, not an atomic lock against external writers. An unknown submission can have partial effects. The tool does not retry or roll back.
6. Recovery calls only `recoverBatch` with the original id and generation. Acknowledged publication, current matches with prepared bytes, and conflicts are separate observations. Recognition does not finish a batch or overwrite external writes.
7. Text results use the existing Unix formatters. Read ranges show byte coordinates, EOF and version. A nonzero byte offset has fragment-local line numbers. Info distinguishes metadata from a bounded NUL/UTF-8 content sample and reports whether the sample is complete. A sample is not a MIME guarantee. Edit and patch return unified diffs generated before submission. Confirmed results label confirmed changes. Unknown results label planned differences. Display truncation is explicit and is not an applicable complete patch. An exhausted diff algorithm budget rejects before submission.
8. Open accepts only fully validated static PNG, JPEG and WebP images within explicit byte, pixel and dimension limits. A filename extension is not evidence. Inspect precedes full decode. Each original decoded handle closes in `finally`, and the call awaits close before attachment publication. A failed or pending close prevents publication. After close, the call checks cancellation before invoking the writer. Cancellation does not imply native work stopped.
9. Open publishes original bytes once through the current call's writer, after validation and a cancellation check. Only a confirmed stored reference permits an ImageBlock and attachment result. Unknown storage receipts return no invented reference and do not claim no write occurred. Cancellation after confirmation does not erase the observed write.
10. Files emits no frames. Help returns a plain success string. Confirmed operations and complete batch recognition return a ToolResult without `isError`. Expected rejection, unknown submission, and recognition requiring attention return a ToolResult with `isError: true`. An unexpected implementation exception propagates to the original invoker. Facility rejections retain their original reason. Registration withdrawal removes discovery but does not invalidate an already borrowed pure executor. Config contains data, not executable dependencies.

This tool produces an image reference. Authorized model-input hydration, model modality availability, frontend display and demo assembly are responsibilities of its consumers.
