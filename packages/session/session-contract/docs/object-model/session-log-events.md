# Session log 的原生业务事件目录

状态为候选，尚未技术接受。本文定义当前采用能力必须保存的事实语义、来源、经由、提交路径、效力与治理后果。[主架构](../../../session/docs/architecture/mechanisms.md#session-log-的事件模型)拥有共同提交、查询和恢复算法，[状态与转移](session-state-transitions.md)拥有守卫与整批归约，[Session SPEC](../../SPEC.md)拥有长期行为义务。

一条事实保存为一个日志条目。读形状是 `HistoryEntry`，身份是 `EntryId`。术语效力归[当前统一语言](../../../../../.meta_harness/design/ubiquitous_language/terms/record-and-context.md)。SE 编号是本文的定位标识，不是已经发布的种类、公开 Schema 或统一语言新词。目录覆盖当前采用的原生业务。插件以后新增事实仍需相应拥有者定义、评审和准入，本文不宣称未来种类已经枚举完。

## 一次操作怎样形成事实

入口提交业务意图及原操作身份。Session 根据当前资格和状态决定结果，调用者不能任填条目、效力或治理变化。普通输入受理、Run 开始、reload、插队和归档各有必要事实组合，沿[完整结果](session-state-transitions.md#命令守卫与完整结果)共同提交。第一批可同时包含创建、已完成初始化和初始消息，仍须能从未创建状态解释整批。

一种事实可以内嵌在更大的条目中。例如归档可以同时表达同批 Run 的被取消终态，相同终态不再另记一份有效决定。合并编码须完整保留本文要求的数据与因果，分开编码须在同一完整批次成立。精确编码由实际成员拥有。

业务写入只经 Session 的命令。任何来源域的事实都经一个变更命令进入日志，邻域不拼写 SE 编号或种类名。

### 共同封套

每个条目继承下列封套。载荷表只列各类必要的业务数据。

| 字段 | 内容 | 来源 |
| --- | --- | --- |
| `id`、提交位置、批次 | 条目身份与它在日志中的位置 | 存储提供者 |
| `kind` | 稳定种类短名，见各族表 | 本目录 |
| `schema` | 该种类载荷的精确采用 | 本目录 |
| 效力 | 依据或留痕 | 本目录与用途变体 |
| `origin.owner` | 事实拥有者：`session`、`agent`、`model`、`tool`、`hitl`、`user`、`runtime-context`、`request-context`、`execution-environment`、`clock`、`authorization` | 命令 |
| `origin.via` | 经由方：`direct`、`agent-participant`、`agent-events`、`session-adapter`、`intake` | 命令 |
| `origin.operation` | 提交它的 `SessionOperationId` | 命令 |
| `origin.source` | 拥有者一侧原记录的耐久证据 | 命令参数 |
| `refs` | 实际存在的 `run`、`attempt`、`consumption`、`input`、`card`、`control`、`target` | 命令参数 |
| `cause` | 同批更早条目或已提交条目的引用 | 归约 |
| 发生时间 | 拥有者报告的发生时间。提交时间记在批次上 | 命令参数与批次 |
| 载荷 | 载荷本身或可恢复的内容引用 | 命令参数 |

`origin.via` 只供人与诊断使用，不参与治理裁定。治理只读种类、`refs` 与载荷。涉及 Run、发起 attempt、步骤、动作和调用的条目保存实际关联，接续 attempt 不覆盖发起身份。跨域事实保存其拥有者、稳定事实身份或版本及核实依据，不能只凭来源自称成功就成为权威。

### 种类短名与演进

`kind` 用 `<族>.<事实>` 形式的稳定短名，SE 编号只在文档中导航。新字段只增加，不改变旧字段含义，`schema` 升版。新事实使用新种类名，旧种类名永不复用。归约器按批次记录的解释版本解释旧条目。未知种类先隔离，不跳过。

## 效力与解释资格

一条事实是否必须记入，见架构[必须进入日志的事实](../../../../../docs/architecture/runtime/session-and-run.md#必须进入日志的事实)。效力沿统一语言的 Deciding、Explaining、Transient。本文用中文「依据」「留痕」表达，不新增英文枚举。只有依据进入其合法消费者的状态转移输入。留痕可以进入历史查询和解释视图，不能改变队列、推进资格、等待或结算责任。瞬态通知、未封口增量及工程采样不能独自支撑恢复路径。

消息种类、是否给模型看、保留期和效力分别判断。消息的可见性归内容块的可见性标注：给模型看的部分进入模型可见历史，给人看的部分进入对人时间线。封套不重复可见性。工具过程若只用于解释可为留痕。业务提醒或费用记录若承担后续工作、对账或结算恢复，其必要部分为依据。条件效力必须在实际成员的用途变体中明确，不能由每次生产者随意填写。本文没有增加成本额度或预算控制业务。

标注是指向旧条目的新条目，用 `refs.target` 引用原条目。压缩覆盖、更正与取消提醒都用标注表达，原条目不变。

治理路径验证当前操作资格。推进路径还验证原 Run 未终结、无有效取消及有效 attempt。外部已发执行的真实报告走原拥有者与合法消费者的承接路径，不能因发起 attempt 失效而丢弃，也不能借报告取得新推进许可。HITL 和授权记录只承接原决定，不产生第二份批准。

## 原生事实类别

38 类事实按事实拥有者分为九族，每族有一个主要来源域。SE 编号不按族连续：SE35（族 C，输入交入结果）、SE36（族 A，常驻工具的首次定义）、SE37（族 H，会话冻结）、SE38（族 C，冻结后解除待处理资格）排在所属族的表尾。以后新增的事实从 SE39 起编号，并在表中写明所属族。

| 族 | SE | 主要来源域 | 主要提交命令 |
| --- | --- | --- | --- |
| A 会话身份与声明 | SE01 至 SE09、SE36 | 用户、装配、设置拥有者、Runtime Context、Tool | `create`、`completeInitialization`、`change`、`configureAutoArchive`、`startRun`、`reload` |
| B 历史消息 | SE10 | 用户、Agent、Request Context、作用域持有者、Tool | `accept`、`recordMessage`、`commitDerived`、`completeExternalConsumption`、`interrupt` |
| C 受理与分流 | SE11、SE12、SE35、SE38 | 用户、HITL、业务拥有者、准入者、Agent 的消息准入、Session 治理 | `accept`、`receive`、`freeze`、`control`、`finishRun` |
| D Run、批次与 attempt | SE13 至 SE17 | Session 治理、Agent | `startRun`、`claim`、`reload`、`release`、`receive`、`control`、`finishRun` |
| E 调用与结果 | SE18 至 SE21 | Agent、Model、Tool、保管者 | `receive`、`bindExternalCall`、`preserveResult`、`completeConsumption`、`completeExternalConsumption` |
| F 扩展与 HITL | SE22、SE23 | Agent 与拓展件拥有者、HITL | `receive`、`accept` |
| G 控制与终态 | SE24 至 SE26 | 用户、Session、Agent、Model、Tool | `control`、`interrupt`、`receive`、`finishRun` |
| H 归档、冻结、关系与空闲 | SE27 至 SE31、SE37 | 用户、Session 治理、Tool 的冻结判定、时钟与空闲输入 | `control`、`setRelation`、`recordIdle`、`considerAutoArchive`、`freeze` |
| I 账目、更正与授权 | SE32 至 SE34 | Model、Tool、语义拥有者、授权拥有者 | `receive`、`commitDerived`、`accept` |

表中载荷继承共同封套，只列必要业务数据。标明「依据」的类别仍须按用途核对合法消费者。Session 保存跨域引用和本会话治理后果，不复制其他拥有者的完整状态机。

### A 会话身份与声明

| 标识 | `kind` | 事实类别与必须区别的情况 | 必要数据、出处及因果 | 效力与治理后果 |
| --- | --- | --- | --- | --- |
| SE01 | `session.created` | 会话创建 | 合法创建者；固定租户、Session、AgentDefinition 标识、用途、执行类型及必需身份，创建输入、确定的初值和采用依据、未完成初始化项及责任 | 依据。从未创建建立身份，单独创建不建立 Run |
| SE02 | `session.initialization-item` | 初始化项处理 | 原初始化项与创建事实；负责方给出取得值、就绪或失败原因、仍缺条件及接续责任 | 依据。更新原项，全体必需项完成才可工作；失败不删除会话或伪装就绪 |
| SE03 | `session.mode-changed` | 三轴模式变更 | 本会话租户；指定维度、新值及当前上界核对依据，关联原操作 | 依据。仅变该维，其他维保持。Agent 要改模式，必须走 HITL，由人显式授权。不能突破结构化禁止 |
| SE04 | `session.model-selected` | 模型选择变更 | 合法用户或明确代办者；合法路由名、原指令及模型拥有者校验依据 | 依据。保存选择；不改已固定请求、不建新 attempt，不因后续调用失败回滚 |
| SE05 | `session.workspace-changed` | 工作区选择变更 | 合法选择者；附着、更换或解除的原目标、合法入口和加载依据 | 依据。更新本会话选择；失败保留原合法状态，不把指定失败改成无工作区 |
| SE06 | `session.declaration-adopted` | 会话覆盖或继承声明采用，含自动归档策略的采用 | 设置拥有者校验后的本会话项、覆盖值或继承声明、来源和版本 | 依据。只改本会话声明，不改租户默认、共享设置或资产内容 |
| SE07 | `session.context-registration-changed` | Context 注册集合变更 | 注册协调者；增加、改变或移除的注册、来源、配置、消费者与必需性依据 | 依据。更新注册关系；必需项不能移除，移除注册不删除共享内容 |
| SE08 | `session.adoption` | 定义、能力与装配实际采用 | 装配协调者；固定定义标识、实际版本、清单、能力绑定、来源裁定、安全交接和原等待引用，以及这次求值的[输入快照](../../../../../docs/architecture/runtime/assembly-and-change.md#比对代替求值)：会话选择与读过的各作用域、各类来源的采用变更计数；本次为常驻工具记下的登记键，按能力身份成对列出 | 依据。保存实际采用；新 Run 采用最新合法版，普通恢复保原版，合法 reload 与新 attempt 共同成立。候选校验失败不覆盖原采用 |
| SE09 | `session.recovery-input-adopted` | 会话自有恢复输入采用，含 Context 状态块的步提交 | 数据拥有者；本会话自有值或不可重算输入、内容或可恢复引用、来源位置及采用依据 | 依据。保留恢复所需输入。外部实时数据仍归原源，前值按具体数据契约可选 |
| SE36 | `session.tool-resident-admitted` | 常驻工具首次纳入常驻集合 | 采用点的候选采用材料；能力身份、资产版本与 shape（name、参数契约、命令表），内容由 Tool 规定；与同批 SE08 关联 | 依据。常驻集合只增不减，同一能力身份只写一次。会话据此恢复常驻工具在会话内不变的 name 与参数形状。当前记下的登记键从 SE08 派生，不另写，规则见 Tool 的 [R4](../../../../tool/tool-contract/SPEC.md#会话常驻规则r1r5) |

SE03 至 SE07 与 SE09 经 `change` 的对应维度提交。Context 状态块的步提交经 `change(context-step-commit)` 写入 SE09。作用域重建后，持有者按日志提交顺序重放 SE07，再从 SE09 归约出每个状态块最近一次步提交的全值。

## 消息、物理结果与流协议

SE10 的六个历史消息变体为 UserMessage、AssistantMessage、ToolMessage、ToolInternalMessage、SystemReminderMessage 和 CompactionMessage，具体形状与块规则归消息契约。SystemMessage 按请求派生，不成为历史消息条目。

本节以下段落是候选修订，技术接受前不扩大本页既有承诺。

压缩记录的形状、模型视图规则与相对历史判定归[消息成员](../../../../common/message/SPEC.md#模型视图)，本文不重述。Session 是历史持有者，按[压缩记录的提交](../../../../../docs/architecture/runtime/session-and-run.md#压缩记录的提交)核对后，在同一次提交中写 SE10 压缩记录与 SE33 标注，标注的 `refs.target` 指向覆盖范围，并开启新的模型可见历史视图。任一步失败，整次提交不成立。摘要只改变后续组装视图，原消息与标注不变。

作用域持有者拉取 Runtime Context 的变化材料，经 `commitDerived` 写 SE10 系统提醒，来源指向变化材料的证据。同一变化材料按操作身份认回。归档后不再追加变化提醒。

assistant 消息中的推理续接状态随所在 SE10 消息的内容块进入日志，不另存。它是租户数据，写入后不改写，换模型也不改写历史。Session 不按推理回放范围建索引，也不缓存筛选结果，规则见架构[推理续接状态的保存](../../../../../docs/architecture/runtime/session-and-run.md#推理续接状态的保存)。

Model 与 Tool 的 open、fill、close、trim、account、finish 是其流协议，不能直接映射为 Session 受理、Run 终态或消费完成。已确认历史消息不可变。在途内容以生产者的保管为耐久边界，Session 不逐片落盘，见[在途内容的局部对账](../../../../../docs/architecture/runtime/streaming-and-consumption.md#在途内容的局部对账)。

Tool 转后台以 SE19 的 Tool 实际确认及 SE21 的合法占位改变当前步骤等待，仍是原执行。占位消息由 Agent 提交，Session 以消息参加写 SE10。后台占位不覆写，后来的真实结果按原消息规则追加提醒。Run 已终结时，结果先登记为结果事实，再经 SE11 的独立投递准入成为后继工作的业务输入，不能只靠执行已收场就自动取得队列资格，也不让原 Run 复活。dummy execution 保存逻辑不可用结果和处理状态，不产生原工具的物理启动、效果或虚构用量。扩展或压缩的内部模型结果回原位置，不写成主流程 AssistantMessage。

归档在同一批中产生作用域释放的恢复任务。对人时间线只记「已发起释放」与读回结果，释放不重复发起新获取。

### 不进入日志的内容

一条事实进入日志，是因为会话以后要据此判断，或人以后要据此理解发生过什么。只为此刻展示或推进的数据不进入日志。下列内容不进入日志，可追溯义务由各自拥有者承担：

| 内容 | 保存在哪里 |
| --- | --- |
| Model 的流片段：open、delta、replace、seal、trim | Model 每次发出的保管批次 |
| Model 的受理、物化、重试决定与供应商诊断 | Model 记录与诊断查询 |
| Tool 的过程块 | Tool 的过程保管，按版本读取 |
| Tool 的内部调度、继续与计时段 | Tool 自己的账本 |
| Tool 内部等待的答复 | 回到工具自身的等待 |
| Agent 的流事件与消息事件 | Agent 的事件序列。消息已在参加时成立；Session 只保存消费游标 |
| Agent 内部执行状态与拓展结论的正文 | Agent 检查点与经过记录 |
| Agent 的接续值 | Agent 检查点。Session 不保存接续值，只保存 `ExecutionRef` |
| 调度器唤醒、提交通知与心跳 | 不保存 |

## 扩展、格式演进与未覆盖

每个可解释种类须由明确拥有者定义封套匹配、用途变体、准入、因果、效力、归约及版本兼容。Agent 拓展结论虽可携带专属内容，它归 Agent 的经过记录，不成为任意 Session 治理写入口。自定义内容不能通过自报留痕而绕过未知语义处理。

Session 治理归约器支持其必需原生语义与已经准入的外域依据。未知相关种类或版本时停止受影响投影，不能将未解释事实当作无等待或无工作。确能证明不影响该投影的已知解释型类别可只保留历史；同一依据也可能只影响其他合法消费者，不强制每个投影计算所有领域。

准确公开 Schema、迁移编码、插件解释注册机制、经过和消费位置的公开身份、跨能力发起/控制/级联/ACK 及连续空闲取证协议仍需实际成员设计。本文没有以源码当前的八种公共事实限制完整目标，也没有证明这些义务已实现。

Loop 具体规则归 [Agent Loop 规格候选](../../../../agent/agent-contract/docs/flows/loop.md)。
