# @omne-harness/session-ui 行为规格

本文件拥有会话界面模块在公开类型以外的必要行为。公开形状是 `src/index.ts` 导出的 `SessionWorkspace` 与 `SessionWorkspaceProps`，导航见 [docs/public-api.md](docs/public-api.md)。

## 范围与依据

- 依据：[RFC-0015](../../../docs/rfcs/RFC-0015-access-dynamic-registration.md) 第 8 节「列出会话」「会话观察」「读历史给出什么」，第 10 节「四部分界面」的「会话管理」「对话」「对话里的卡片」「主场景走一遍」，第 13 节「客户端：树上的一个协议客户端」的重附着一段。契约是 `@omne-harness/session-protocol` 的 `session/v1` 第一版。
- 采用范围：第一条纵线（卡 #1267）。列出自己的会话，选一个接着聊，新建一个；不答问题卡，不调 `stop-call`，不列已归档的会话。
- 对提案的暂时偏离：样式用普通 CSS 文件，不引入 Tailwind 与 Radix；共用界面件与外壳契约两个成员这一程不建，组件直接收协议客户端。会话列表画在组件自己的左边一列，不放进外壳的侧栏区。由统筹会话记入差异表。

## 结果与不变量

<a id="ui-1"></a>**UI-1 结果不知道就是不知道。** 建会话答 `unknown` 或本地 `uncertain` 时不重发，用同一个调用编号调 `query-create-session` 认回。发输入同理，用同一个受理编号调 `query-send-input`。认回仍不知道时停在「结果仍未知」，由人点「再确认一次」再认回。取消答未知时，再点「停止」用同一个控制编号再发一次，那是同一次操作。界面从不把未知写成成功或失败。

<a id="ui-2"></a>**UI-2 历史是权威，流是投影。** 已提交的内容只从 `read-history` 来。进行中的回复来自观察的 `snapshot` 与 `delta`（投影 `model-output-v1`）。历史读到哪里，取最近读完的那一轮读取的 `upper`；状态帧的 `revision` 超过它，就从末尾再读一轮。两者是同一条轴上的会话修订号，`scannedThrough` 是另一条轴，不参与（[协议契约的规定](../session-protocol/SPEC.md#revisions)）。读到一条修订号大于进行中回复锚点的助手消息，进行中那条就被历史里的那一条替换。这一轮结束且历史读到了最新修订时，进行中那条也收起。

<a id="ui-3"></a>**UI-3 不应用对不上的增量。** `delta` 的 `base`（`cursor` 与 `revision`）不等于持有的回复时，不应用，换一代重新观察，等新的快照。

<a id="ui-4"></a>**UI-4 不认识的种类看得见。** 历史条目、消息部件、流的块，三处种类都封闭。表外的种类画成占位，写明种类名。

<a id="ui-5"></a>**UI-5 工具调用与结果只按调用编号配对。** 一个调用的第一个结果是它的结果。配上的工具消息不单独画；没配上的单独画。

<a id="ui-6"></a>**UI-6 问题卡的状态取自对话本身。** 名为 `Ask` 的工具调用画成问题卡：有结果是「已答复」；这一轮已结束或调用之后出现了一轮结束而没有结果，是「已失效」；否则是「等待答复」，卡上写明可以在命令行里答复或在这里取消这一轮。

<a id="ui-7"></a>**UI-7 错误各有一句人话，不吞掉。** 被拒、本地不可用、未知各有一句，显示在出事的那一处（会话、那条输入、取消、历史、会话列表）。

<a id="ui-8"></a>**UI-8 会话列表是投影，以服务端为准。** 列表只来自 `list-sessions`，界面不在本地增删列表项。服务端记一次「活动」的三种提交（建会话、受理一条输入、一轮结束）在界面上看到之后，列表重新读第一页。「更多」读到的一页接在后面，按会话标识去重，不覆盖已有的。读过的页里有一页是 `partial`，列表底部就写「列表可能不全」。归档的会话不列：不传 `includeArchived`，`limit` 也不传，用部署的默认值。

<a id="ui-9"></a>**UI-9 打开已有会话和新建成功之后是同一条路。** 两者都进「会话已打开」：从末尾反向读历史，开观察。界面不另写一套打开的流程。

<a id="ui-10"></a>**UI-10 列表读失败不碰已打开的会话。** 会话列表与会话是两条独立的轴（见[会话管理](#会话管理)），列表的任何答复都不改会话那条轴。

## 全化表

状态拆成三条独立的轴：会话这条轴（还没有会话、建会话中、会话已打开、会话不可用；打开时再分这一轮的三态），会话打开时的观察这条轴（正在连接、在连、断开在重连），以及会话列表这条轴（见[会话管理](#会话管理)）。每格写转到哪与发出的作用；「不变」是这一格的确定答复；「作废」是旧会话、旧一代观察、旧读取编号的迟到答复，一律不变。

列：**无** 还没有会话；**建** 建会话中；**就绪** 会话已打开且没有进行中的一轮（历史已读、观察在连）；**进行** 这一轮进行中；**取消** 取消中；**不可用** 会话不可用。

- 换会话时原会话还没有结论的输入不带走：它们的答复带着原会话的标识，一律作废，和 R1 收掉会话是同一条。受理没受理以那个会话的历史为准，再打开时从历史里看得到。

## 会话管理

会话列表是第三条轴，与会话那条轴正交：列表的事件不改会话，会话的事件只在三处让列表重读（下面第二张表）。两条轴的交叉只有「打开会话」一处，它是会话那条轴的 R30。

列：**未读** 还没读过；**读首页** 正在读第一页（之前读到的照样显示）；**读下页** 正在读「更多」那一页；**已读**；**读失败**。每次读取发一个新的读取编号，编号对不上的答复作废，所以重读的时候在途的旧答复不会落进来。

| 行  | 事件                                   | 未读                                      | 读首页                                                         | 读下页                                                                             | 已读                                                                      | 读失败                            |
| --- | -------------------------------------- | ----------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------- |
| L1  | 读第一页（挂上、活动之后、点「重试」） | 读首页，发 `list-sessions`，`cursor` 为空 | 换一个编号重发，旧答复作废                                     | 读首页，换一个编号；下页的答复作废                                                 | 读首页，照样显示已读到的                                                  | 读首页；`denied` 那种没有可显示的 |
| L2  | 点「更多」                             | 不可达（没有「更多」）                    | 不可达                                                         | 不可达                                                                             | `next` 不为空：读下页，发 `list-sessions`，`cursor` 为 `next`；为空不可达 | 不可达（只有「重试」）            |
| L3  | 列表答 `succeeded`（编号对得上）       | 作废                                      | 已读，用这一页替换                                             | 已读，接在后面，按会话标识去重；`next` 取这一页的；有一页 `partial` 就是 `partial` | 作废                                                                      | 作废                              |
| L4  | 列表答 `denied`（编号对得上）          | 作废                                      | 读失败：「没有权限，或登录已失效。」，不给重试，不再显示列表项 | 同读首页                                                                           | 作废                                                                      | 作废                              |
| L5  | 列表答其他（编号对得上）               | 作废                                      | 读失败：「会话列表暂时读不到。」，给「重试」，照样显示已读到的 | 同读首页                                                                           | 作废                                                                      | 作废                              |

会话那条轴上看到「活动」时，列表执行 L1。判断看转移前后的会话状态，不看事件，所以作废的答复不会触发重读：

| 会话那条轴上的转移                             | 对应的行 | 列表 |
| ---------------------------------------------- | -------- | ---- |
| 建会话中转到会话已打开                         | R2、R6   | L1   |
| 同一个会话里有一条输入新转为「已受理」         | R10、R14 | L1   |
| 同一个会话里这一轮从进行中或取消中转到没有一轮 | R17、R20 | L1   |

列表项怎样显示：

| 字段             | 显示                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| `title`          | 原文；为空时显示「未命名的会话」加会话标识的前 8 个字符                 |
| `lastActivityAt` | 为空时不显示时刻                                                        |
| `lifecycle`      | `active`、`dormant` 不标；`initializing`、`frozen`、`archived` 各标一句 |
| 当前打开的会话   | 这一项标为当前                                                          |

建会话的调用在途时，列表项点不动（R30）。窗口宽度小于 720px 时，列表收成顶部的下拉，由顶栏上的「会话列表」按钮展开，点了一项就收起。

| 历史里出现锚点之后的助手消息    | 进行中的回复收起                                                            | C6   |

## 所有权、失败与生命周期

`SessionWorkspace` 每次挂上建一个驱动器（`src/model/session-driver.ts`），并让它读会话列表的第一页。驱动器独占它开的观察与重连计时，卸下时全部中止；之后到的答复一律丢掉。它不持有登录、不认识宿主与身份；租户读不懂时组件直接显示一句话，不发任何调用。客户端只在发出之前抛错（契约写不出的消息体），驱动器把它当作本地 `unavailable`。

## 组合与验证

- 状态机：`tests/session-machine.spec.ts`，用例名以表的行号开头；会话管理的用例以 L 行号或「活动」开头。
- 内容的合并与对话的条目：`tests/content.spec.ts`。
- 发输入的消息体与 `@omne-harness/sdk` 的 `userTextMessage` 逐字段相同：`tests/user-message.spec.ts`。
- 主场景：`tests/session-workspace.spec.tsx`，假的协议客户端，happy-dom。
- 未覆盖：真实浏览器里的滚动跟随与长回复的重绘次数只在演示页人工看过；与真实服务端的联调归统筹会话。
