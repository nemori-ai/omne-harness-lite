# 内部架构

本文件说明本包怎样兑现 [SPEC.md](../SPEC.md)：包内模块划分、依赖方向、状态与资源归属、关键机制及设计理由。它引用组级与系统级约束，不另立公共规则。

## 模块与依赖

| 模块 | 持有的状态与资源 | 依赖 |
| --- | --- | --- |
| `src/observation.ts`（一次观察） | 帧的生成器、正在等的间隔的取消器、通知的退订函数 | 定位、刷新的预算、帧的翻译、端口 |
| `src/locate.ts`（定位） | 读到哪了、当前这一轮、最近一次主调用、修订号、标记「有新提交待看」 | 端口里的日志读取面、会话契约的 `readCallRegistration` |
| `src/refresh-budget.ts`（刷新的预算） | 当前一档间隔、连续没有新内容的次数、累计等待 | 端口里的策略与诊断 |
| `src/frames.ts`（帧的翻译） | 上一次发出的状态字段 | 无 |
| `src/ports.ts` | 端口类型、默认策略、间隔底线 | 会话与模型两份契约的读取面类型 |
| `src/cordis.ts` | 一个事件监听者与它的监听集合 | 以上全部，加 Cordis 与两份 Cordis 契约 |

依赖方向：`cordis.ts` 到 `observation.ts` 到其余模块。`cordis.ts` 之外的模块不导入 Cordis。本包只依赖会话与模型两份契约和它们的 Cordis 契约，以及 `json-text`、`legal-identity` 等公共小包，不导入接入组的任何成员；这一条由约束登记里的方向行守住。

资源归属：日志读取、通知订阅和计时都归「一次观察」，收场时一起收掉。会话事实归会话日志，本包不存业务状态。

## 关键机制与理由

- 端口。逻辑只认 `SessionObservationPorts`：日志读取、通知、计时、策略、诊断。会话与模型已有的读取面做它的实现，Cordis 的订阅与过滤做薄适配。这样逻辑能对着假实现测，时间由假的 `wait` 推进。
- 标记「有新提交待看」在定位里，不在通知回调里。回调只立标记并唤醒等待；每次定位结束后，一次观察先看标记，立着就立刻再定位。这是「不丢唤醒」的全部机制：它不依赖通知不重复，也不依赖通知不丢，丢了由间隔补上。
- 只读新条目。第一次反向读，之后从上次读到的位置往后读。代价是要保存读到哪了；游标失效时丢掉它，下一次从头读。
- 帧只有一个出口。状态帧只在四个字段有变化时发，所以「第一帧是状态」「不重复发相同的状态」只有一处要守。
- 预算是独立对象。间隔、退避、次数和累计时长是策略，部署之间会变；放在状态机之外，换值不动流程。

边界：流的订阅与它对旧帧的丢弃（旧目标的帧不出现在新目标之后）还没有实现，见 SPEC 的现行限制。接入流这一侧时，要重新判断「一次观察」里的事件循环是否需要拆成两路。

## 验证与维护

保证与验证对应见 SPEC 的「组合与验证」：成员内用例对着假端口，形式模型三在接入组暂留。设计变化时同步 SPEC、本目录其余专题、`tests/`，以及消费者（见 [context.md](context.md)）。
