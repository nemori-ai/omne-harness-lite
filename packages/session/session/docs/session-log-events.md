# Session log 的原生业务事件目录

状态为候选，待用户确认。本文定义当前采用能力必须保存的事实语义、出处、因果、效力与治理后果。[主架构](internals.md#session-log-的事件模型)拥有封套、共同提交、查询和恢复算法，[状态与转移](session-state-transitions.md)拥有守卫与整批归约，[Session SPEC](../SPEC.md)拥有长期行为义务。

正式术语继续使用 Record Entry，event 说明其记录已发生事实的性质。SE 编号是本文的定位标识，不是已经发布的 kind、公开 Schema 或统一语言新词。目录覆盖当前采用的原生业务；插件以后新增事实仍需相应拥有者定义、评审和准入，不能宣称未来种类已经枚举完。

## 一次操作怎样形成事实

入口提交业务意图及原操作身份，Session 根据当前资格和状态决定结果，不能让调用者任填条目、效力或治理变化。普通输入受理、Run 开始、reload、插队和归档各有必要事实组合，沿[完整结果](session-state-transitions.md#命令守卫与完整结果)共同提交。第一批可同时包含创建、已完成初始化和初始消息；仍须能从未创建状态解释整批。

一种事实可以内嵌在更大的条目中。例如 Run 开始可以同时表达首批输入承接。相同承接不再另记一份有效决定。合并编码须完整保留本文要求的数据与因果，分开编码须在同一完整批次成立。精确编码由实际成员拥有。

封套保存稳定身份、租户与 Session、格式和解释版本、可信出处、实际发生时间、效力、寿命宿主及因果。涉及 Run、发起 attempt、step、动作和调用时保存实际关联；接续 attempt 不覆盖发起身份。跨域事实还保存其拥有者、稳定事实身份或版本及核实依据，不能仅凭来源自称成功认作权威。

## 效力与解释资格

一条事实是否必须记入，见架构[必须进入日志的事实](../../../../docs/architecture/runtime/session-and-run.md#必须进入日志的事实)。效力沿统一语言的 Deciding、Explaining、Transient。以下用中文“依据”“留痕”表达，不新增英文枚举。只有依据进入其合法消费者的状态转移输入。留痕可以进入历史查询和解释视图，不能改变队列、推进资格、等待或结算责任。瞬态通知、未封口增量及工程采样不能独撑恢复路径。

消息种类、是否给模型看、保留期和效力分别判断。工具过程若仅用于解释可为留痕；业务提醒或费用记录若承担后续工作、对账或结算恢复，则其必要部分为依据。目录中的条件效力必须在实际成员的用途变体中明确，不能由每次生产者随意填写。本文没有增加成本额度或预算控制业务。

治理路径验证当前操作资格；推进路径还验证原 Run 未终结、无有效取消及有效 attempt。外部已发执行的真实报告走原拥有者与合法消费者的承接路径，不能因发起 attempt 失效而丢弃，也不能借报告取得新推进许可。HITL 和授权记录只承接原决定，不产生第二份批准。

## 原生事实类别

表中载荷继承上述封套，只列必要业务数据。标明“依据”的类别仍须按用途核对合法消费者。Session 保存跨域引用和本会话治理后果，不复制其他拥有者的完整状态机。

| 标识 | 事实类别与必须区别的情况 | 必要数据、出处及因果 | 效力与治理后果 |
| --- | --- | --- | --- |
| SE01 | 会话创建 | 合法创建者；固定租户、Session、AgentDefinition 标识、用途、执行类型及必需身份，创建输入、确定的初值和采用依据、未完成初始化项及责任 | 依据。从未创建建立身份，单独创建不建立 Run |
| SE02 | 初始化项处理 | 原初始化项与创建事实；负责方给出取得值、就绪或失败原因、仍缺条件及接续责任 | 依据。更新原项，全体必需项完成才可工作；失败不删除会话或伪装就绪 |
| SE03 | 三轴模式变更 | 本会话租户；指定维度、新值及当前上界核对依据，关联原操作 | 依据。仅变该维，其他维保持。Agent 要改模式，必须走 HITL，由人显式授权。不能突破结构化禁止 |
| SE04 | 模型选择变更 | 合法用户或明确代办者；合法路由名、原指令及模型拥有者校验依据 | 依据。保存选择；不改已固定请求、不建新 attempt，不因后续调用失败回滚 |
| SE05 | 工作区选择变更 | 合法选择者；附着、更换或解除的原目标、合法入口和加载依据 | 依据。更新本会话选择；失败保留原合法状态，不把指定失败改成无工作区 |
| SE06 | 会话覆盖或继承声明采用 | 设置拥有者校验后的本会话项、覆盖值或继承声明、来源和版本 | 依据。只改本会话声明，不改租户默认、共享设置或资产内容 |
| SE07 | Context 注册集合变更 | 注册协调者；增加、改变或移除的注册、来源、配置、消费者与必需性依据 | 依据。更新注册关系；必需项不能移除，移除注册不删除共享内容 |
| SE08 | 定义、能力与装配实际采用 | 装配协调者；固定定义标识、实际版本、清单、能力绑定、来源裁定、安全交接和原等待引用 | 依据。保存实际采用；新 Run 采用最新合法版，普通恢复保原版，合法 reload 与新 attempt 共同成立。候选校验失败不覆盖原采用 |
| SE09 | 会话自有恢复输入采用 | 数据拥有者；本会话自有值或不可重算输入、内容或可恢复引用、来源位置及采用依据 | 依据。保留恢复所需输入。外部实时数据仍归原源，前值按具体数据契约可选 |
| SE10 | 历史消息成立 | 合法受理、推进或原结果消费者；六类历史消息之一、原块和标注、内容或引用、原输入或调用及入口结论 | 按用途为依据或留痕。只有明确受理为普通输入的消息有队列资格，只有合法原位置处理才解除相应等待 |
| SE11 | 输入受理及分流 | 受理协调者；原提交、来源、内容、原命令及合法展开，普通、卡片、控制或系统业务去处及可靠责任 | 依据。普通消息与待处理资格同批；其他类别保存原目标责任，不能混入普通队列 |
| SE12 | 准入拒绝留痕 | 原准入者；原请求、拒绝依据、必要干预及可反馈原因，不保存不应受理的正文 | 留痕。拒绝不取得队列资格。用途提醒确认前没有受理正文，确认后是新请求 |
| SE13 | Run 开始及初始承接 | 工作治理；新 Run、触发原因、非空完整初始输入集合、顺序、批界与接续位置，可选前继 Run 和采用依据 | 依据。建立唯一未终结 Run，共同解除首批待处理资格；不另写重复首批承接决定 |
| SE14 | 后续完整批次承接 | 有效推进者；原 Run、T1 一致位置、精确合格成员、顺序、批界及原接续位置 | 依据。一次解除对应待处理资格，原消息仍保留；分块不重新挑选批次 |
| SE15 | attempt 开始 | 治理认领者；原 Run、严格递增序号、重建原因、原进度和等待、采用依据 | 依据。建立新推进资格，旧 attempt 永远不再推进；普通通知、挂起恢复和模型内部重试不新增 attempt |
| SE16 | 推进资格交还或撤销 | 治理或合法原执行者；原 attempt、原因、原等待和进度、交还或撤资格的依据 | 依据。不能继续使用原推进资格；不推导 Run 终态或物理全停。由换代、取消或终态已经表达的撤资格不另造第二决定 |
| SE17 | attempt 退出报告 | 可信原实例或资源拥有者；原 attempt、时间、退出原因及可核实归因 | 可选留痕。允许开始后没有退出报告；报告本身不撤资格、不证明独立调用停止 |
| SE18 | 原调用登记与等待依据 | 合法发起者；稳定调用、用途、固定输入或参数引用、实际采用、原动作、原消费位置、所需结果、阻塞范围及交付责任 | 依据。建立可恢复发起和等待责任，登记不冒称物理已发出；Run 外不补造 Run |
| SE19 | 原执行事实承接 | Model 或 Tool 拥有者；原调用的实际发出、真实收场、转换确认或不可确定状态、原事实版本、结果及原因 | 影响对账或等待的部分为依据，纯解释为留痕。保持真实物理事实，不把停止请求当已停止，不把旧状态覆盖新终局 |
| SE20 | 结果可靠保管 | 合法消费者；原结果身份、内容或可恢复引用、保管确认、原位置和后续责任 | 依据。确认结果在消费侧可恢复，不表示已处理完；不能只保存临时句柄就解除生产责任 |
| SE21 | 原位置处理与逻辑结果采用 | 原消费者；原保管、消息、占位或答复，接续 attempt、处理结论、完成进度、判断依据及后续责任 | 依据。按原位置推进处理或拒收，实际处理可终结相关业务等待。后台占位、卸载、不许执行、不可用 dummy 与真实执行结果分别表达 |
| SE22 | 扩展结论与卡片关联采用 | Agent 或扩展拥有者；位置、经过与输入身份、动作或整批范围、原参数和生效参数、结论、原因、原卡片批次及交回责任 | 改变后续判断为依据，纯观测为留痕。可为继续、否决、等待或按契约处理错误；不赋予扩展任意改 Run 状态的权力 |
| SE23 | HITL 原决定交回 | HITL 拥有者及原接收方；原卡片、唯一决定、批次、答复或明确不回答、参数绑定和原接续位置 | 依据。逐卡处理，整批卡片均处理后才可继续原扩展；不回答无批准含义，时间或实例退出不制造答案 |
| SE24 | 控制请求成立 | 具目标控制资格者；稳定控制身份、原目标与范围、主体、原因、优雅或强制级别、处置及传播责任 | 依据。区分单调用、Run、实例交接、插队和归档控制；请求不等于已转换或物理已停止 |
| SE25 | 控制处置与进度 | 原协调者与目标拥有者；原控制、逻辑生效或拒绝、有效目标集合、确认或未知、尚待传播和核对责任 | 依据。按具体控制变更资格与等待，只解除被证明完成的责任；不伪造用户答复或实际执行终态 |
| SE26 | Run 唯一终态 | 治理的唯一终态路径；原 Run、完成或失败或被取消、原因、结果引用、适用检查或取消依据及未收尾效果提示 | 依据。终态不可反转，撤新推进和发起资格；后置扩展、迟到和结算不复活该 Run |
| SE27 | 会话归档成立 | 会话治理；原归档操作、依据、取消的输入/等待/调用资格范围、对同批唯一 Run 被取消终态或已有终态的引用、子方级联及未完责任 | 依据。逻辑归档与必要取消事实同批，拒绝新任务；不等待所有物理执行结束，不删除历史 |
| SE28 | 撤销归档成立 | 具会话管理资格的用户；原归档、新操作、撤销时刻与新空闲起点 | 依据。回休眠，旧取消资格保持；不恢复 Run、任务、卡片、调用或子会话 |
| SE29 | 会话关系采用 | 关系协调者；父子、派发、独立 handoff 或业务关联，双方身份、创建来源、有效关系和原业务依据 | 依据。保存关系及后果；独立 handoff 不成为子方，原创建来源不改。关系集合演进不自动授予重新挂父资格 |
| SE30 | 常驻标记变更 | 具管理自己会话资格的用户；主会话、标记值与原操作 | 依据。主会话豁免自动归档，与子会话互斥；解除采用已有空闲，不影响手动归档 |
| SE31 | 连续空闲依据采用 | 归档协调者；起点、中断或撤销后重置、检查范围及进度、执行拥有者依据、时间、未知区间与失效条件 | 依据。保存可确认区间及归档判据；一次无活动快照不能证明未知期间连续空闲 |
| SE32 | 效果与账目关联 | 原执行或账目拥有者；原调用和实际 Run/发起 attempt、稳定事实或账项、数量单位、时间、结果、确定性及未结责任 | 防重做、对账或结算恢复所需为依据，纯解释为留痕。效果明确发生、未发生或不可确定；费用待结不当零，接续和观察不重复收费 |
| SE33 | 历史解释更正 | 对应语义拥有者；被补充事实、理由、新解释或新增表示、原身份与合法变更依据 | 影响合法后继解释为依据，纯说明为留痕。追加保留原事实；不能反转 Run 终态、恢复取消资格或改写真实外部成功 |
| SE34 | 原授权关联与消费事实承接 | 授权拥有者及合法消费者；原批准/拒绝/撤销/消费依据、明确范围、参数绑定、原工作与位置 | 恢复所需为依据。只承接原授权，单次按原动作或明确批次使用；消费或所属 Run 终态后不能复用。会话授权流水按原范围保留 |

表中的登记、结论、处理和控制均关联原位置，不要求另外建立独立“等待对象”。没有 `wait-ended` 原生类别。结果/答复到达并被原位置可靠处理，或有效业务控制取消原等待，已经是其结束依据。没有单独“变活跃”“变休眠”事件，它们由 Run 开始和终态派生。

## 消息、物理结果与流协议

SE10 的六个历史消息变体为 UserMessage、AssistantMessage、ToolMessage、ToolInternalMessage、SystemReminderMessage 和 CompactionMessage，具体形状与块规则归消息契约。SystemMessage 按请求派生，不成为历史消息条目。

CompactionMessage 必须关联摘要及精确原块集合，Context 拥有其范围与合法性，Session 保证这份消息和必要引用同批成立。摘要只改变后续组装视图，原消息与标注不变。后台占位不覆写，后来的真实结果按原消息规则追加提醒，并经 SE11 的独立投递准入，不能仅靠执行已收场自动取得队列资格。

Model/Tool 的 open、fill、close、trim、account、finish 是其流协议，不能直接映射为 Session 受理、Run 终态或消费完成。已确认历史消息不可变，在途块的局部对账和已展示内容保留沿主架构与流式拥有者继续细化。

Tool 转后台以 SE19 的 Tool 实际确认及 SE21 的合法占位改变当前步骤等待，仍是原执行。dummy execution 保存逻辑不可用结果和处理状态，不产生原工具的物理启动、效果或虚构用量。扩展或压缩的内部模型结果回原位置，不写成主流程 AssistantMessage。

## 扩展、格式演进与未覆盖

每个可解释种类须由明确拥有者定义封套匹配、用途变体、准入、因果、效力、归约及版本兼容。Agent 扩展结论虽可携带专属内容，仍须通过已采用的原位置契约，不成为任意 Session 治理写入口。自定义内容不能通过自报留痕而绕过未知语义处理。

Session 治理归约器支持其必需原生语义与已经准入的外域依据。未知相关类别或版本时停止受影响投影，不能将未解释事实当作无等待或无工作。确能证明不影响该投影的已知解释型类别可只保留历史；同一依据也可能只影响其他合法消费者，不强制每个投影计算所有领域。

准确公开 kind/Schema、迁移编码、插件解释注册机制、经过和消费位置的公开身份、跨能力发起/控制/级联/ACK 及连续空闲取证协议仍需实际成员设计。本文没有以源码当前的八种公共事实限制完整目标，也没有证明这些义务已实现。
