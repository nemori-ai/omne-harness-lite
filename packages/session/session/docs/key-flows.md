# session 关键协作流程

状态为待审技术设计。正式维护位置不授予技术接受、实施或支持；精确公开形状仍待定义。

## 流程适用范围


状态为候选，待用户确认。本页对应[产品关键用户旅程](../../../../.meta_harness/design/product/sessions-and-work/design.md#关键用户旅程)，表达 Session 受理、治理及原结果消费的协作顺序。F-SW 只是文档定位号。事件含义唯一归[SE01 至 SE34](session-log-events.md#原生事实类别)，状态、守卫及完整提交结果唯一归[ST 转移表](session-state-transitions.md#命令守卫与完整结果)。本页不增加状态或事件。

Session 保存会话事实，Agent 决定 Loop 下一步，Model 和 Tool 保存真实执行，HITL 保存卡片决定，授权拥有者解释资格与批准，Context 负责相应输入。图中箭头标明请求、控制、事实或保管交接，参与者是逻辑角色，不表示部署或共同寿命。共同提交只约束本会话必需事实与责任，不包揽外部发起、ACK 或物理停止。下列 flowchart 表示活动与依赖，不是严格 UML 或算法证明。

所有变更先核验作用域、当前资格与原操作。同次已提交操作认回原结果；提交未知保持原身份对账。一次尝试被拒或查询未找到，不能证明所有旧尝试均未提交。只有持久裁定足以阻止旧尝试晚到生效时，才可报告原操作明确未提交。机制归[共同提交算法](internals.md#追加与共同提交算法)。各图中“可靠提交”均受该规则约束。

## F-SW01 创建、版本采用与 reload

对应 [J-SW01](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw01)。创建采用 ST01/ST02，新 Run 采用 ST06，普通接续及 reload 采用 ST08 至 ST11。身份、设置、定义与工作区拥有者提供当前可核验依据，Session 负责本会话采用。换代时，撤销旧推进权和保存接续依据一起成立，否则换代还没发生。原执行不因撤权销毁。

```mermaid
sequenceDiagram
    participant U as 用户或合法创建入口
    participant S as Session 治理
    participant O as 身份与资产拥有者
    participant A as Agent 装配与推进
    U->>S: 创建请求及固定身份、可选工作区
    S->>O: 请求当前资格与合法创建依据
    alt 指定工作区不合法或不可加载
        O-->>S: 失败事实
        S-->>U: 明确失败，不改为空工作区
    else 依据合法
        O-->>S: 已核验依据
        S->>S: 可靠提交创建、初值与初始化责任
        S-->>U: 原会话及就绪或待接续状态
        Note over S,A: 初始化就绪且无初始任务可休眠，无须启动 runtime
    end
    opt 原 Run 存在、未终结且具当前继续资格
        U->>S: 显式 reload 同一定义，接续原工作
        S->>O: 校验新版本及当前采用边界
        alt 候选无效或不能安全交接
            S-->>U: 拒绝本次换代，原合法事实保持
        else 候选合法且可安全交接
            S->>S: 同批保存新采用、新 attempt 与撤旧资格
            S->>A: 交回原 Run、调用、卡片与消费位置
            A-->>S: 原位置接续事实
        end
    end
```

无 Run 时可以校验装配输入，不能创建 attempt；原 Run 已终结后不能用 reload 新增它的 attempt 或恢复推进。上述换代段只表达合法未终结 Run 的交接，不规定其他 reload 产品行为。创建或 reload 回执丢失按原操作核对。普通恢复采用原版本，不走显式 reload。新 Run 采用最新合法发布版本的跨源裁定不能仅靠 Session 尾部 CAS 证明；精确接口及围栏仍属 [SW-M01](internals.md#sw-m01-技术兑现义务)。已固定外部调用保留原输入。

## F-SW02 可靠受理、分流与完整批次

对应 [J-SW02](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw02)，采用 ST03 至 ST07。入口受理协调者拥有提交责任，命令专有行为交命令拥有者。

```mermaid
flowchart TD
    I[带原提交标识的输入请求] --> G{资格、会话与命令判据}
    G -->|拒绝| R[反馈原因，不授予待处理资格]
    G -->|用途提醒不匹配| W[交回用户确认，不保管正文]
    W -->|用户确认后重新发送| I
    G -->|通过| K{确定原去处}
    K -->|普通消息或内容型命令| Q[共同保存消息、展开内容与待处理资格]
    K -->|卡片答复| H[保存去处责任，交原 HITL 位置]
    K -->|控制| C[保存去处责任，交控制处理方]
    K -->|系统业务或流程命令| B[保存业务目标与原拥有者责任]
    Q --> D{提交结果}
    H --> D
    C --> D
    B --> D
    D -->|已提交| ACK[受理回执，通知检查条件]
    D -->|未知| X[沿原标识查询或重试，不换身份]
    X --> D
    ACK --> N{普通待处理输入与原 Run 条件}
    N -->|可开始新 Run| NEW[共同提交首批承接、采用与首次资格]
    N -->|原 Run 可到后续 T1| T[共同提交全部合格输入与原顺序]
    N -->|原位置仍等待或非普通输入| P[保留原去处与接续责任]
```

受理与后续承接是不同提交。首批承接与 Run 创建共同成立，后续 T1 则按原位置确定完整批界。不能从上述通知直接跳到新 Run。存储不可用不报告受理成功，通知丢失由权威状态补查。分块、归档竞争及回执未知的完整结果按 ST 表处理。

## F-SW03 工作推进、结果交接与恢复

对应 [J-SW03](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw03)，采用 ST06 至 ST10、ST14 至 ST16、ST20 和 ST26。Session 的责任止于合法工作及交接，Loop、流式和真实执行仍由各自拥有者维护。正常发出时，发起者在登记时生成稳定调用身份。固定输入、调用身份和准入一起提交。模型受理和结果容量预留在同一真实事务里成立，否则不算已经发出。

```mermaid
sequenceDiagram
    participant S as Session 与 Run 治理
    participant A as 当前合法 Agent 推进者
    participant P as 独立 Model 或 Tool
    participant C as 原消费者与持久状态
    S->>A: 唯一推进资格、原工作与完整输入批次
    A->>S: 登记原动作、调用与等待责任
    A->>P: 在实际边界核验后发起原调用
    P-->>C: 真实结果、原身份与适用费用事实
    alt 先可靠保管
        C->>C: 保存内容或有效引用、原位置与后续责任
        C-->>P: 按原契约确认可靠交接
        C->>S: 取得原位置处理资格，保存合法处理结果
    else 先完成处理
        C->>S: 核对原位置资格与必要扩展结论
        C->>C: 完成处理并可靠保存必要完成事实
        C-->>P: 按原契约确认处理完成
    end
    Note over P,C: Model 须真实收场且当前消费者合法才可 ACK；Tool 沿自身规则
    S->>A: 允许原位置继续或仅处理收尾
    A->>S: 原工作完成、失败或取消依据
    S->>S: 核对完成检查和并发事实，提交唯一终态
    Note over S,P: 流 finish 不形成 Run 终态，真实调用与费用可继续收尾
```

两条交接路径不是两个必须依次执行的阶段。先完成处理分支不强制额外保存一份可重领全文或 SE20；它须保存足以恢复责任的完成依据。先保管分支不要求扩展已完成或工作仍可推进，之后的业务处理另核原资格。消息准入拒绝不改写原执行事实。ACK、生产侧清理和结算各自可查，不能让清理失败回滚已成立交接。

```mermaid
flowchart TD
    R[故障后按原 Session 与 Run 对账] --> G{终态、取消及当前推进资格}
    G -->|已终态或已取消| Z[只接续允许的收尾、保管及结算]
    G -->|可继续| A{原推进者是否有效}
    A -->|有效| SAME[继续同 attempt]
    A -->|须重建且接管有效| NEXT[同 Run 建新 attempt，撤旧资格]
    SAME --> P{原调用与消费事实}
    NEXT --> P
    P -->|仍在途| WAIT[接续原等待，不重发]
    P -->|已收场未交接| TAKE[取原结果，走合法交接分支]
    P -->|已交接待处理| OWN[从消费侧原位置继续]
    P -->|查询失败| UNKNOWN[保持未知并继续对账，不推断失联]
    P -->|确认失去连续性| OWNER[由执行拥有者处理，回原用途]
```

已知工具不可用的逻辑结果只说明未执行原因，恢复不补做工具。实际发起围栏、原消费位置公开形状、ACK 协调和在途耐久仍由 SW-M01 对应拥有者细化。

## F-SW04 出卡、答复与原扩展位置接续

对应 [J-SW04](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw04)中的扩展等待，采用 ST17a、ST17b、ST17c。下图只表达扩展发起的原批次，工具内部 Ask 的答复回 Tool 自身原等待，见[TL-F04](../../../../packages/tool/tool/docs/key-flows.md#tl-f04)。两者不能互换接续位置。出卡、答复交回及处理可以在不同时间提交，各阶段引用已经成立的原事实。

```mermaid
sequenceDiagram
    participant A as Agent 原扩展位置
    participant S as Session 等待与消费治理
    participant H as HITL
    participant U as 获准用户
    participant Z as 原问题与授权拥有者
    A->>H: 请求原问题的卡片
    H-->>A: 卡片身份
    A->>S: 保存出卡关联、原位置与等待责任
    H-->>U: 呈现原卡片
    Note over S,U: 等待不限时，可释放 Agent；普通聊天不回答卡片
    U->>H: 答复或明确不回答
    H->>H: 认回一次有效决定
    H->>S: 可靠交回原决定与责任
    S->>Z: 请求原问题解释，授权类另核批准含义
    Z-->>S: 原范围结论，不回答不批准
    S->>S: 分别保存逐卡处理事实
    alt 本批仍有未处理卡片
        S-->>A: 保持批次阻塞，不先发获准部分
    else 全部处理且原资格仍有效
        S->>A: 回原扩展位置继续判断
    else 原等待已终局失效
        S->>S: 保存真实答复与处置，不恢复原工作
    end
```

接续后可能得到后续结论或再出新卡，不一律跳到工具发起。断线恢复认回原卡片与决定，交回失败保留原责任，不能假造超时答复。插队解除等待的逻辑拒绝来自控制事实，不成为 HITL 的人类决定。精确交接与失效竞态仍归 SW-M01，单次许可消费及参数绑定归授权契约。

## F-SW05 模式变化与模型选择

对应 [J-SW05](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw05)，采用 ST12/ST13。Session 拥有当前值，权限及设置拥有者核对修改资格，模型拥有者裁定合法路由，Context 和 Agent 采用后续输入。

```mermaid
flowchart TD
    U[请求修改本会话选择] --> K{操作类别}
    K -->|三轴模式| M{具资格用户且不突破上界}
    M -->|Agent 或不合法| R[拒绝，原值保持]
    M -->|通过| MC[共同提交被修改维度及回执]
    MC --> CTX[向运行消费者提示，下次使用取得当前值]
    K -->|模型路由| L{合法目标与当前资格}
    L -->|非法或无依据| R
    L -->|合法，含缺凭据目标| LC[共同提交选择及回执，说明可调用性]
    LC --> NEXT[下一尚未固定请求重求模型、组装与检查]
    NEXT -->|条件满足| CALL[按新选择发起请求]
    NEXT -->|压缩后仍不满足| FAIL[原工作报告失败，选择与历史保留]
    MC -->|回执未知| Q[按原操作对账]
    LC -->|回执未知| Q
    Q -->|认回已提交| V[显示原操作实际结果]
```

图中的提交未知分支没有确认变更成功，后续采用须以权威已提交值为准。当前在途或已固定调用不走 NEXT，其输入保持。模型切换不换定义或 attempt。模式初值与恢复值沿 ST01/ST12，不能以租户默认覆盖既有值。实际修改资格及跨源合法目标裁定仍归 SW-M01。

## F-SW06 插队、单调用控制与 Run 取消

对应 [J-SW06](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw06)，采用 ST18、ST19 及 ST20。控制发出、逻辑处置、真实确认分别保存。取消一旦生效，会话就记录 Run 的逻辑终态。真实收场之后另报。强制或非强制只影响停止有多急。

```mermaid
flowchart TD
    U[具资格的控制请求] --> K{明确控制范围}
    K -->|单调用| C[保存原调用控制与传播责任，不撤 Run 资格]
    K -->|插队| I[共同保存加急输入与适用等待处置责任]
    I --> W{当前等待}
    W -->|模型| M[请求中断，保留已到内容，废止未执行动作]
    W -->|工具允许转后台| B[向 Tool 请求原执行转换]
    B --> BC{Tool 真实确认}
    BC -->|转换成立| P[可靠承接占位，解除原步骤等待]
    BC -->|已收场| E[按原真实结果处理]
    BC -->|未知或失败| X[保留未完成责任，不假报转换]
    W -->|工具不允许转后台| T[请求中断，保留效果与逻辑结果]
    W -->|人工卡片| H[控制解除等待，保存有来源的逻辑拒绝]
    W -->|取批或组装| Q[只保存队首加急输入]
    M -->|原等待按契约处置后| CONT[按有效资格回原位置，加急输入沿批次承接]
    T -->|原等待按契约处置后| CONT
    H --> CONT
    Q --> CONT
    P --> CONT
    E --> CONT
    K -->|Run 取消| R[共同保存意图、撤新发起资格与传播责任]
    R --> SEND[控制该 Run 模型及前台工具]
    SEND --> TYPE{取消方式}
    TYPE -->|优雅| WAIT[等待适用收尾，期间不得正常推进]
    TYPE -->|强制且条件成立| END[提交唯一被取消终态，标明未明效果]
    WAIT -->|收尾条件成立| END
    C --> REC[按原目标跟踪真实收场与费用]
    END --> REC
    X --> REC
```

工具转换不重建 Tool、不释放仍在执行的名额；单独请求转后台也可走 ST19b，不额外制造插队消息。Run 取消不隐式传播到后台、子会话及无关 Run 外调用。完成已先成立时保持原终态，控制报告已终结。控制传播失败、回执未知或协调者退出后按原责任接续，不能把未确认停止标成已停止。精确控制与转换协调归 SW-M01。

## F-SW07 归档、级联与撤销

对应 [J-SW07](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw07)，采用 ST21 至 ST23。四态仍只由[原状态图](session-state-transitions.md#四个生命周期视图)解释；下面展示跨参与者顺序。

```mermaid
sequenceDiagram
    participant U as 具资格用户
    participant S as 本 Session 治理
    participant C as 子 Session 治理
    participant P as 独立 Model 与 Tool
    U->>S: 归档请求
    S->>S: 核对本方资格、全部原调用与有效关系范围
    S->>S: 同批取消原处理资格、形成必要唯一终态及归档、保存处置责任
    S-->>U: 本方逻辑归档成立，列明未结级联与实际执行
    par 逐子方业务控制
        S->>C: 按原关系传递归档控制
        C->>C: 独立核对并提交子方归档
        C-->>S: 子方真实进度或未知
    and 独立执行控制
        S->>P: 控制所有关联在途模型与前后台工具
        P-->>S: 真实收场、效果与费用，允许迟到
    end
    Note over S,P: 不要求共同事务或物理全停，失败处置保留可恢复责任
    U->>S: 撤销本方归档
    S->>S: 可靠提交撤销与新的空闲起点
    S-->>U: 回休眠，可显式提交新工作
    Note over S,C: 原任务、调用、卡片与子方均不自动恢复
```

未终结 Run 与归档同批形成一个 SE26，SE27 引用它，已有终态保持。归档后新任务明确拒绝，先受理后归档则取消已受理资格。迟到结果只完成仍合法的保管、历史和结算，不入旧任务队列；撤销归档也不恢复其投递资格。父方撤销不能撤销子方已成立的归档，独立 handoff 排除在子方集合外。关系采用与父归档的并发范围、逐方恢复协议仍归 SW-M01，不用一次快照证明级联完整。

<a id="f-sw08"></a>

## F-SW08 连续空闲取证与自动归档

对应 [J-SW08](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw08)，采用 ST23、ST24a、ST24b，成立后复用 F-SW07 的归档流程。

```mermaid
flowchart TD
    U[合法租户配置或本方常驻操作] --> H{开启自动归档或解除常驻}
    H -->|是| WARN[操作前提示可能立即归档，保留已有空闲]
    H -->|否| SAVE[沿拥有者保存合法设置]
    WARN --> SAVE
    SAVE --> E[读取当前配置、关系、常驻与空闲依据]
    E --> EN{显式启用且无豁免}
    EN -->|否| HOLD[不自动归档，已确认空闲不清零]
    EN -->|是| PROOF[向工作与执行拥有者核实本方及级联子方范围]
    PROOF --> STATE{未结工作、在途调用与连续区间}
    STATE -->|存在新工作| RESET[中断旧区间，按事实重新计时]
    STATE -->|查询未知或区间无法证明| UNKNOWN[保留未知，不报告已满足空闲]
    STATE -->|可确认连续空闲| KEEP[保存或引用有效区间与来源]
    KEEP --> LIMIT{当前时限满足且裁定边界仍有效}
    LIMIT -->|未满足| HOLD
    LIMIT -->|条件已变| E
    LIMIT -->|满足| ARCH[沿 ST21 提交归档及责任]
```

空闲取证可在开关关闭或常驻时独立维护，并不依赖归档结果。子会话常驻拒绝。普通重启、成员失效和配置关闭不清零已成立区间，无法确认的时间不当空闲证明；撤销归档以撤销时刻重新起算。当前合法设置、连续区间及所有在途调用不能只靠本地日志或 CAS 证明。跨源取证及设置接口归 SW-M01。

## F-SW09 历史读取、结果定位与账目核对

对应 [J-SW09](../../../../.meta_harness/design/product/sessions-and-work/design.md#j-sw09)，行为归 SL01 至 SL14、ST25/ST26 及读取规格。Session 只提供获准历史与真实账目关联，不裁定执行成本或以遥测代账本。

```mermaid
sequenceDiagram
    participant U as 合法历史或账目读取者
    participant S as Session 读取与投影
    participant L as 权威日志及有效内容引用
    participant O as 原执行与账目拥有者
    U->>S: 请求获准范围的历史与原工作定位
    S->>S: 当前资格、固定上界与游标核验
    alt 错域、撤权或游标无法核验
        S-->>U: 明确拒绝，不扩大读取范围
    else 核验通过
        S->>L: 按原范围和扫描进度读取
        L-->>S: 原条目、有效引用及来源进度
        S-->>U: 获准历史与续读位置，空页不必然结束
    end
    U->>S: 核对原调用效果与费用
    S->>O: 按实际原身份请求当前事实
    alt 已有真实账项或收场
        O-->>S: 原事实及确定性
        S-->>U: 合法展示，关联实际存在的 Run 与 attempt
    else 未结或查询故障
        S-->>U: 保持待结或未知，不显示为零
    end
    Note over S,L: 更正与摘要追加；投影失效从有效前缀重建，不发外部动作
```
