# 形式模型与规格、代码的对照

本页对照 `session/verification` 下两个有限模型：Agent 推进协调器的等待与重试（`advance-wait`）、控制传播与会话串行队列（`control-propagation`）。条款在包组规格 [`packages/session/SPEC.md`](../../SPEC.md)。模型检查只说明有限范围内的设计性质。`advance-wait` 的 `expect.txt` 是配置预期的机器形式。

## advance-wait

`AdvanceWait.tla` 检查推进协调器的等待与重试。

| 模型                          | 实现及守护                                                     |
| ----------------------------- | -------------------------------------------------------------- |
| `Sample`、`Cancel`、`Elapsed` | 调度等待在采样前登记取消，处理答复前再核信号，完成后移除监听器 |
| `Retry`、`Exhaust`            | 推进的有限退避、原 attempt 重读、次数耗尽诊断                  |
| `OriginalOperation`           | 发起与有界收束复用原身份；未知重放固定请求                     |

配置：`wait` 是正控，无反例；`bad-ignore-abort`、`bad-new-operation`、`bad-skip-wait` 各去掉一条规则，命中各自在 `expect.txt` 里登记的性质。

## control-propagation

`ControlPropagation.tla` 检查控制传播与会话串行队列：控制先保存意图，随后按持久关联传播；未知时按原提交身份查询，不为取得挂接而重发；超过策略上限仍保留进度并报告；同一控制操作重放认回，受理不等于实际停止；每个控制操作一个在途重放；进程内每会话一个串行队列。规格见 SE-10、SE-12。

| 状态变量                      | 含义                                                           |
| ----------------------------- | -------------------------------------------------------------- |
| `cstate`                      | 快照里这个控制的进度：传播中或已对账，已对账由环境的接收产生   |
| `run1`、`run2`                | 第一个 Run 的 active 与终态，第二个 Run 的未开始与已开始       |
| `replaced`                    | 第一个 Run 是否有第二个执行；为真时它的关联不唯一              |
| `lane`                        | 会话串行队列，先进先出，表头是持有者，元素是控制或推进         |
| `ctl`                         | 控制任务：空闲、排队、读取、发送、查询、等待重放间隔           |
| `phase`、`attempts`、`sends`  | 重放记录：发送、查询或停止，每轮计一次的尝试数，出站控制的次数 |
| `outbound`、`target`          | 在途出站的种类与它携带的执行身份                               |
| `pendingUnknown`、`committed` | 一次发送以提交未知结束而没有查询结清；查询已返回已提交         |
| `adv`                         | 后继 Run 的推进任务：空闲或排队                                |
| `closed`、`closeDone`         | 关闭已开始、已返回                                             |

| 动作                                 | 抽象边界                                                                                                         |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `Launch`                             | 触发、发现与启动合并：控制为传播中、任务空闲、阶段不是停止、尝试数未超上限时入队                                 |
| `BeginRead`、`Stop`                  | 串行队列把队列交给任务；串行段内读到实例已关闭、控制不再传播或原关联不唯一时退出并释放队列                       |
| `Send`                               | 串行段内判定后发出一轮出站：阶段为查询时发查询，否则发控制；尝试数加一；正确设计在这里释放队列                   |
| `RespondControl`、`RespondQuery`     | Agent 应答：成功与忙进入等待，拒绝停止，提交未知在同一轮内直接查询；查询已提交则停止，未知则等待，已排除则再入队 |
| `EndWait`、`AbandonOutbound`         | 重放间隔到期或因关闭返回；关闭后任务不再等待未应答的出站，出站保持在途                                           |
| `TriggerAdvance`、`OpenRun`          | 第一个 Run 终态后推进入队，取得队列后开启第二个 Run                                                              |
| `RequestClose`、`CloseDone`          | 关闭开始；所有任务结束后关闭返回                                                                                 |
| `Reconcile`、`Replace`、`FinishRun1` | 环境：控制对账；第一个 Run 出现替换的执行；第一个 Run 正常终结                                                   |

| 性质                                      | 检查                         | 负控与命中的反例                                                                  |
| ----------------------------------------- | ---------------------------- | --------------------------------------------------------------------------------- |
| 只发原关联的执行，取消 Run 关联唯一时才发 | `TargetSafe`                 | `bad-association`：取消 Run 在两个执行之间任选，替换之后发往第二个执行            |
| 结果不明时先查询，不直接重发              | `QueryBeforeResend`          | `bad-skip-query`：提交未知后直接等待，下一轮在未知未结清时再次发送                |
| 查询返回已提交后不再发送                  | `NoSendAfterCommitted`       | `bad-ignore-stopped`：启动忽略停止阶段，已提交之后任务再次入队                    |
| 重放次数不超过上限                        | `ReplayBounded`              | `bad-replay-bound`：去掉循环的上限，Agent 连续答忙时多发一次                      |
| 离开传播中之后不再重放                    | `ReplayOnlyWhilePropagating` | `bad-propagating-filter`：去掉启动与步的过滤，对账之后仍开新一轮                  |
| 活性：控制出站不返回时后继 Run 仍被调度   | `SuccessorProgress`          | `bad-serial-outbound`：把控制出站留在串行段内，控制占住队列表头，推进永远排在后面 |
| 活性：控制出站不返回时实例关闭仍能完成    | `CloseProgress`              | `bad-serial-close`、`bad-close-waits`：出站留在串行段内且关闭不能放弃出站         |

配置：`valid-cancel-run`、`valid-stop-call` 是正控（取消 Run 与停止调用两种控制），预期无反例；`bad-*` 命中上表对应性质。活性性质以弱公平性与环境前提（出站可以永不应答、时钟最终到点）为前提。

对实现的六条结构约束：串行段在出站发出之前结束，只含读快照、核对传播中、解析原关联、尝试数加一与生成目标；每轮都在串行段内重新读取与判定，出站用这一轮生成的目标；提交未知之后的查询在同一轮发出，不加尝试数，结清之前不发新控制；尝试数上限在入队前核对，加一在串行段内；关闭时对出站的等待能结束而出站仍未应答；被放弃出站的迟到应答被丢弃，不改变阶段与尝试数，不再入队。控制传播协调器对这六条逐条成立。

| 模型边界                         | 实现的位置                                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| `Launch`                         | 控制协调器的触发与启动：运行中、阶段为停止、尝试数达到上限的核对                             |
| `BeginRead`、`Stop`              | 步里的串行段只包住规划：读取、找传播中的控制、解析原执行                                     |
| `Send`                           | 规划里尝试数加一与请求生成；出站在串行段外发出                                               |
| `RespondControl`、`RespondQuery` | 交换：成功返回等待，提交未知进入查询，忙与不可用返回等待，其他失败置停止；查询的应答并入未知 |
| `AbandonOutbound`                | 出站 promise 与生命周期信号竞速，控制与查询都使用它                                          |
| `TriggerAdvance`、`OpenRun`      | 推进协调器的检查与在串行段内开 Run                                                           |
| `RequestClose`、`CloseDone`      | 生命周期的关闭：置关闭、中止、等待全部在途任务；放弃的出站不进入在途集合                     |
| `Reconcile`                      | 命令处理器对控制接收的提交；环境动作，不建模提交细节                                         |
