# Frontend

## 总体架构

本组回答两件事：各领域的界面模块与各应用的外壳共用哪些界面件、它们的观感从哪里来；界面外壳与界面模块之间的契约是什么。

| 成员             | 回答的问题                                                                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ui-kit`         | 设计 token、动效、基础控件、图标、字体、流式 Markdown 的包装、主题与字号档的控制器、Agent 形的墨迹、纸的面与翻面：别的界面成员导入什么就得到同一种观感。纯展示，不认识任何领域，不认识任何应用 |
| `shell-contract` | 界面外壳给界面模块的是什么：有哪几个界面插入位置，往里放的一项长什么样，放进去、撤下、登录、租户、切页怎样调。纯契约加一个 Cordis 服务的定义，不含任何外壳的实现，不认识任何领域               |

依赖方向：`ui-kit` 不依赖仓库里任何别的成员，不依赖 Cordis，不依赖任何协议契约，不依赖 Node 内置模块。`shell-contract` 只依赖 Cordis、React 的类型声明与拓展点的机制（`@omne-harness/dynamis`、`@omne-harness/dynamis-cordis`），不依赖客户端装配、任何领域成员与 Node 内置模块。拓展点的机制不是领域，见[分层正文](../../docs/architecture/layers-and-dependencies.md#依赖关系与禁止方向)。领域的界面模块（例如 `session-ui`）和应用的外壳（例如 `apps/desktop`）导入这两个成员，反向不成立。本组两个成员互不依赖。

新增一段界面代码时按下表选位置：

| 这段代码是什么                                           | 放在               |
| -------------------------------------------------------- | ------------------ |
| 与领域无关、只靠属性与事件就能用的控件、图案、样式、动效 | `ui-kit`           |
| 要认识某个领域的数据、协议或文案                         | 那个领域的界面模块 |
| 要认识应用的导航、窗口、登录与连接                       | 应用的外壳         |

## 领域边界

本组拥有：设计语言的数值（颜色、字号、间距、圆角、阴影、动效时长与曲线）、控件与通用件的外观和交互状态、图标、字体、Markdown 的版式、明暗主题与字号档怎样落到页面上、Agent 形与墨框怎样画、纸上的平移、缩放、拖动、改大小、磁吸与翻面怎样做。

本组还拥有界面外壳与界面模块之间的契约：插入位置的名字与种类、一项的形状、每个位置的规矩、`shell` 服务的形状。放进去的东西存在哪、撞了怎样答，归 [Dynamis](../dynamis/SPEC.md) 的登记表，本组不另写存放规则。

本组不拥有：任何领域的界面（会话列表、对话版式、设置页等归各领域的界面模块）、任何应用的外壳的实现（导航、侧栏、标题栏归应用）、登录与登录状态的事实、与服务端的连接、偏好的存储、形此刻该说什么状态（归报告状态的界面模块）。

共用件不认识调用它的是谁：文案由调用者经属性传入，缺省值是中文；失败码到文案的映射归调用者；主题与字号档的读与写由调用者注入。

## 心智模型

共用件是一套语言，不是一个组件仓库。拿它量一个改动：这段样式或交互，换一个领域用还对不对。不对，它属于那个领域。

- 数值只有一处：`ui-kit/src/styles/tokens.css`。组件读语义层，不读调色板层，不写死数值。规格不抄数值。
- 状态由数据属性表达：交互族由 `data-control` 标记，部件由 `data-slot` 标记，状态用 `data-state`、`aria-*`。样式和测试读这些属性，不读类名。
- 动效只有一套时钟：时长与曲线只来自 token，循环动画匀速。只有刚发生的事才动；减少动效时位移改为不透明度变化。
- 明暗两套一次写出：颜色用 `light-dark()`，由 `color-scheme` 切换。控件不写第二套颜色。
- 尺寸只有一个旋钮：字号档的系数 `--omne-size`。token 里的长度都乘它，成员只读 token，所以整个界面一起变大变小。成员的样式里不写 px 与 rem 的数，1px 的细线除外。共用件不带构建插件。
- 颜色只在这几处有含义：墨蓝标出动作、链接与焦点；琥珀标出等人回答的东西（[待答数](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-awaiting-answer-count--待答数--awaiting-answer-count)、等人回答的决策卡片与列表行），别的颜色不表示在等人；绿、琥珀、红是已知事实的成功、注意、失败三种语气，琥珀除了等人回答的东西只作「注意」语气，结果不知道时用中性；红只用在失败的事实与不可撤销的最后一步上。<!-- OD-12 -->
- 断点只有三个：768、1100 与对话区的 1160。
- 形是 agent，不是装饰：一个页面里至多一个形，它只以笔法动；它展开的东西都是墨框，别的浮层都不是墨框。

#### 换画口

共用件里有几样东西是按名字画的：图标集里的每个图标，加上五个通用件。应用可以给共用件一个口，让这些东西在画之前先问它一句；共用件自己不认识外壳，也不认识 plugin。

- 口是一个函数 `Redraw`：`(种类, 名字, 被要求画成什么样, 自带的画法) => 画出来的东西`。应用用 `RedrawProvider` 把它放在页面的根上。种类只有两种：`icon` 与 `piece`。
- 没有口时，每样东西直接画自带的那一份，不多一层元素。口交回 `自带的画法()` 时，画出来的标记与没有口时逐字相同。
- 图标：名字是 `defineIcon` 登记的名字，`iconNames()` 给出全部名字（排过序，不重复）；被要求画成的样子是 `{ name, size, className }`。
- 通用件的五个名字在常量 `PIECES` 里：

  | 名字            | 哪一件                     | 被要求画成的样子                                                                                                                       |
  | --------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
  | `loading`       | `LoadingIndicator`         | `size`、`active`、`counted`、`className`                                                                                               |
  | `empty-state`   | `EmptyState`               | `title`、`hint`、`action`、`role`、`className`                                                                                         |
  | `inline-notice` | `InlineNotice`             | `tone`、`title`、`body`、`detail`、`action`                                                                                            |
  | `figure`        | 形的身体（舞台里那一块墨） | `size`、`phase`（`seated`、`flying` 或 `held`）、`hover`、`doing`（`idle`、`thinking`、`looking`、`writing`、`background`）、`waiting` |
  | `note`          | 说话笺里面的内容（墨框里那一块） | `note`（这块笺此刻的数据）与 `act`（它能做的动作），两样的形状见「墨迹」里的说话笺 |

- 形只交出身体的画法。它在哪个座位、怎样走过去、被按下，都在舞台自己的元素上，换了画法之后照旧。`phase` 只有这一套词，归这个件：`seated` 是停着（坐在座位上，或落定在页面之外的一点），`flying` 是自己在走一程，`held` 是跟着手或留在松手的那一点。离座的形问同一个键、给同一套词，所以交接的那一帧画法收到的没有变。写画法的人不需要知道形画在哪一块画面里。
- 说话笺只交出墨框里面的内容。墨框、它开在哪一边、打开时焦点放在哪、Escape 与点别处收起，都在说话笺自己的元素上，换了画法之后照旧。画法不留自己的一份字：字、说给谁、图都从 `note` 里读，改它们只经 `act`。所以笺从一块画面换到另一块画面，画法收到的是同一份。写画法的人不需要知道笺画在哪一块画面里。
- 口怎样决定画哪一份、画法抛出时怎样落回，是应用的事。桌面应用把它接到外壳的两个按键选画法的点上，见[桌面应用的规格](../../apps/desktop/SPEC.md)。

#### 样式的层

- 界面的每一条样式规则都在层叠层里。次序只写在一处，`src/styles/layers.css`：Tailwind 自己的层（`properties`、`theme`、`base`、`components`、`utilities`），自带的一层 `omne-builtin`，改动的一层 `omne-changes`。
- 共用件、每个界面模块、应用页面的样式都在 `omne-builtin` 里。汇总样式把它引入的每一份放进这一层；界面模块与应用的样式文件自己先引入 `@omne-harness/ui-kit/layers.css`，再把全部规则写在 `@layer omne-builtin` 里。
- 自带的样式只用一层，不按共用件、模块、应用分开。共用件的悬停、按下、选中这套状态规则靠选择器的优先级压过各处的底色规则；分成几层之后层的先后压过优先级，上层的一条底色声明会让下层的状态失效。
- `omne-changes` 是最后一层，自带的样式不往里写。放在它里面的规则盖过自带的，不用提高选择器的优先级；拿掉之后自带的原样回来。
- 不在任何层里的规则比所有层都优先，所以层外不许有规则（FE-I40）。

#### 页的骨架

页的版式只由下面几件搭，规则见[规则与 token 的索引](../../.meta_harness/agents/skills/visual-standard/canonical/references/rules-index.md#s-间距圆角版式断点)的 S6 与 L6。页面不自己画页头下的线、节线与目录栏。文案、记号、时间与动作都由调用者传入。下表的长度是中楷的值，随字号档一起变。容器件与 `ListReadingRow`、`SettingRow` 另收 `className`，`ListReadingRow` 另收 `id`。

| 件                                                                               | 职责                                                                                                                  | 状态                                                                                                           |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `PageHeader({ title, titleId?, description?, actions? })`                        | 页的标题，标题下至多一句说明，右边是这一页的动作。下面一条细线，只由它画。在 `PageColumn` 里它与下面的内容再隔一节    | 有说明时标题与说明隔 4，说明是弱墨的界面字；没有说明只有标题。768 以下动作靠左，页头让开外壳角里的家与抽屉开关 |
| `Section({ id, title, badge?, children })`                                       | 运营页的一节：上面一条细线，强字的节标题，标题下面是正文                                                              | 紧跟 `PageHeader` 的一节不画上线，也不再留上边距：页头的线就是它的线                                           |
| `ListReadingPage({ title, titleId?, description?, actions?, detail, children })` | 列表加阅读的一页：顶上是 `PageHeader`，它的线横跨整个工作区；下面是工作区。外壳的 `main` 已经是地标，这一件是普通的块 | `detail` 为真表示开着一条记录；768 以下开着记录时不画页头，页头与工具条都让开外壳的角                          |
| `ListReadingWorkspace({ detail, empty?, children })`                             | 目录栏与阅读面并排                                                                                                    | 1100 以下并成一栏：开着记录时只有阅读面，没有开时只有目录栏，`empty`（列表空）时只有阅读面                     |
| `ListReadingDirectory({ search?, filters?, children })`                          | 目录栏，宽 252：顶上是搜索，下面是筛选，再下面是只有自己滚动的行列表。搜索、筛选、行与列表里空的文字共用一个内边距    | 1100 以下目录栏单独成页时，内边距等于页的左右边距 40，768 以下是 16                                            |
| `DirectorySearch({ value, onChange, label, clearLabel, maxLength? })`            | 目录栏的搜索字段：搜索字形在字段里，右边一个清除的图标钮                                                              | 没有字时没有清除钮；按清除钮把字清空                                                                           |
| `ListReadingRow({ title, mark?, facts?, time?, selected?, onSelect })`           | 一条记录的一行：弱墨的记号一列，正文一列是强字的标题、至多两行弱墨的事实、最淡的时间。悬停是 `GlideMenu` 的滑动高亮   | `selected` 为真时行带 `aria-current`，底是 `--omne-selected`                                                   |
| `ListReadingMain({ children })`                                                  | 阅读面：上面是工具条，下面是文档或空闲的一句话                                                                        | —                                                                                                              |
| `ReadingToolbar({ name, back?, origin?, children? })`                            | 阅读面的工具条：返回、名字与来源一行、右边的动作，下面一条细线                                                        | 没有返回或没有来源时不留位置；768 以下不写名字                                                                 |
| `ReadingDocument({ children })`                                                  | 阅读面里滚动的文档，阅读量度，居中                                                                                    | —                                                                                                              |
| `ReadingState({ children })`                                                     | 阅读面空闲时的那一句话，放一个 `EmptyState`，没有别的                                                                 | —                                                                                                              |
| `SettingRow({ label, labelId?, controlId?, hint?, notice?, children? })`         | 设置行：左边是名字与一句弱墨的说明，右边是值或控件，这一行自己的失败通知在整行下面。行与行之间一条细线，最后一行不画  | 1100 及以上两半并排，控件靠右；1100 以下两半叠起，控件回到左边。没有值或控件时只有左边                         |

骨架的六个件（`ListReadingPage`、`ListReadingDirectory`、`ListReadingRow`、`ListReadingMain`、`Section`、`SettingRow`）把调用方给的 `data-*` 属性带到自己的根元素上，类型是 `DataAttributes`，和折叠件、状态标是同一种写法；件自己写的 `data-*` 不被盖掉。界面模块靠它把部位的名字挂到这些件的根上。

#### 纸的面

这一组让一个界面模块把东西摆在一张有边的纸上，让人看、挪、改大小、叠起来，并让应用在两面之间翻。它不认识纸上摆的是什么，也不认识摆法存在哪里：纸的大小、网格、每一样的位置与大小都由调用者给，人的手势只交回给调用者。这里的「纸面」指一张可以平移、缩放的纸；应用的正面、反面见「外壳契约」。

| 一块                                | 做什么                                                                                                                   | 规则                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 纸面 `PaperSurface`                 | 一张有边的纸：平移，围着指针缩放，键盘也能平移与缩放                                                                     | 远近在调用者给的上下限里；平移不出纸边，纸比视口小时整张纸留在视口里。看着哪一块记成视口正中对着的纸上那一点加远近，由调用者持有：纸面只画调用者给的值，每变一下回调一次；给的值越界时画夹过的，不回调                                                                                                                                                                                                                                                                                                              |
| 页 `PaperPage`                      | 纸上一样东西的外框：内容在上，名字一行在下；按住名字拖动，四角改大小，键盘挪与改大小；里面画什么归调用者                 | 外框含名字一行，名字一行连同它与内容之间的空高 `PAPER_NAME_LINE`（纸的单位），外框的高是内容的高加它。拖与改大小不出纸边，大小在调用者给的上下限里。手势进行时这一页跟着指针走，那只是预览；松手时把这一次的落点与大小交给调用者，此后画在哪只看调用者给的位置。锁着的一页没有拖动与改大小的把手，键盘也挪不动它。选中时叶的外沿是一圈墨的选中边，线条与墨框的边同一个生成法，按调用者给的 `edgeKey` 定种子，同一页每次选中是同一圈。名字平时不透明度为 0、照样排着，指针在这一页上、焦点在里面、选中或拿着时写出来 |
| 状态栏 `PaperStatus`                | 纸下沿的一条窄栏，两个口：左段放调用者给的控件，右段放调用者给的此刻看着的那一样的信息                                   | 高固定。右段换内容只换不透明度；不再给信息时旧的留一会儿再隐去，读屏读不到它；右段不是 live region。右端留出窗口角上随身入口的位置                                                                                                                                                                                                                                                                                                                                                                                  |
| 纸上的一点 `PaperSpot`              | 把一样东西的中心摆在纸上的一点，例如形座位                                                                               | 不能拖，没有把手；按它不平移纸                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 屏幕上的点换成纸上的点 `usePaperAt` | 纸面里的件把屏幕上的一点换成纸上的一点                                                                                   | 按视口、远近与字号档换算，取整；落在纸外的点夹回纸边                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 拖到纸上                            | 纸面的 `onDropAt` 把放下来的东西连同落点交给调用者                                                                       | 落点是纸上的点，磁吸开着时取整到网格。调用者不给 `onDropAt` 时纸面不接拖放                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 磁吸                                | 纯函数：把这一次手势的落点与内容的大小取整到网格，名字一行不参加取整                                                     | 开关关着时原样交回。只改这一次手势的结果，不动纸上别的东西；改一个方向的大小只改那个方向                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 一叠 `PaperPile`                    | 几页叠在一起的样子：最上面一页露全，下面的错开露出边；展开与收起                                                         | 收着时至多露四页，下面的页不接焦点；展开时每页按调用者给的大小画，每行至多四页，整块收在视口内，Escape 收起。一叠整个拖动，不改大小。哪几页在一叠里、次序怎样、每页多大、开没开归调用者                                                                                                                                                                                                                                                                                                                             |
| 翻面 `FlipLayer`、`useFaceFlip`     | 翻面层与编排：形走到要离开的那一面的纸边，拿住它托到对边，离开的那一面朝对边压窄，折痕处一道墨影，形落进要去那一面的座位 | 整个不超过 1500 毫秒，到点就停在要去的那一面；点任何地方或再翻一次，立刻停在要去的那一面，这一下点只让翻面停下，不落到底下的东西上；减弱动效时直接换。编排是纯的状态机，时钟与要压窄的那一面由宿主交进来                                                                                                                                                                                                                                                                                                            |

- 纸上的长度以纸的单位记：中楷、远近为一时的一个像素。画出来时乘字号档的系数与远近，所以换字号档时纸上的东西跟着整个界面一起变大变小。外框、把手、名字一行的长度只取 token 乘字号档（FE-I21）。
- 只用 CSS 的矩阵变换、指针事件与纯几何函数，不引入做无限画板或拖拽的第三方库：那样的库会绕开 token 与动效的门。
- 每一样只用指针能做的，都能只用键盘做到。下面的一格是纸的网格步长：
  - 焦点在纸面上：方向键平移四格，Shift 加方向键十六格；`=` 或 `+` 放大 1.25 倍，`-` 缩小，`0` 回到一，都围着视口正中。
  - 焦点在一页的把手上：方向键挪一格，Shift 加方向键从右下角改大小一格，Alt 加方向键（可再加 Shift）挪或改一个单位，叫细挪。磁吸开着时细挪的结果照样取整到网格。回车与空格是按下这一页。四角只给指针用，键盘从把手做到同样的位置与大小。
  - Escape 取消正在进行的指针手势，什么都不交回。
- 指针：在纸的空白处，按住拖与滚轮都是平移；按住 ⌘ 或 Ctrl（触控板捏合）加滚轮，在哪里都是围着指针缩放。按下后移过 4 个像素才算拖，没过就松手是按下。

### 图表

图表控件与别的控件一样，与领域无关，只靠属性与事件：给它序列或分解好的数据、各系列的名字与次序，它画出来。它不取数据，不认识用量。

- 颜色与字体只读样式变量：一组图表色 `--omne-chart-*`，明暗两套写在 token 里。图表不接受十六进制颜色，主题切换不需要重新渲染。
- 图表画成 SVG，不画在 canvas 上。它不往页面里插样式表，也不在运行时求值，所以在只放行自有脚本与自有样式的页面策略下能用。
- 每张图有文本的替代：一个可读的标签，和一份同样数据的表格视图。键盘能走到每个数据点。
- 数据为空、只有一个点、全是未知，各有确定的样子，不画成零。
- 图表库只在本块被导入，不出现在本成员的导出类型里。换图表库只改本块。
- 数字的格式化是一个共用函数：千分位、缩写、百分比、带单位的金额；未知有固定的写法，不写成零。

### 主题

`createThemeController({ read, write, system })` 把一个主题偏好（浅色、深色、跟随系统）落到页面：`data-theme` 永远是一个具体的调色板，`data-theme-preference` 记录偏好。偏好的读与写经注入的函数，控制器自己不读写任何存储；偏好在别处变了时，应用调 `adopt(偏好)` 让它重新落到页面，不经 `write`。跟随系统时才持有系统变化的监听，显式选择时放开它。切换时加 `theme-switching` 类冻结过渡，等两帧后放开。

### 字号档

[字号档](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-size-tier--字号档--size-tier)有四档：小楷、中楷、大楷、老花，缺省是中楷。各档的系数在 token 里。

`createSizeController({ read, write })` 把一档落到页面：中楷时 `<html>` 上没有 `data-size`，别的档写 `data-size` 为 `small`、`large` 或 `reading`。`--omne-size` 随 `data-size` 变，token 里的长度都乘它，所以版式在每档下不变。偏好的读与写经注入的函数，控制器自己不读写任何存储；偏好在别处变了时，应用调 `adopt(档)` 让它重新落到页面，不经 `write`（FE-I19）。共用件另给一档一档调的函数：大一档、小一档、回到中楷，以及判断一个按键组合是哪一种的函数。按键绑在哪里、偏好存在哪里，归应用。

### 墨迹

`src/ink/` 画 [Agent 形](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-agent-figure--agent-形--agent-figure)：形的身体、[形座位](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-figure-seat--形座位--figure-seat)、换座位时的一程、[墨框](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-ink-bubble--墨框--ink-bubble)与[告知笺](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-told-note--告知笺--told-note)。它只收状态名、一次性的事实、待答数与座位，不认识会话、通知与任何领域。

- 形画在页面最上面的一层：固定定位，这一层不接指针，只有形自己接指针。共用件不开窗口，所以页面在普通浏览器里也能打开，形在里面照样有座位与一程。形出了页面画在哪归应用（桌面应用见 [`apps/desktop/SPEC.md`](../../apps/desktop/SPEC.md#桌面层)）；共用件只给两样：这一页可以不画形（下面「不在页面里」），和一个没有座位的形（下面「离座的形」）。
- 墨用 canvas 与 SVG 画。位置经 CSSOM 的属性写，不拼样式文本，不插样式表，所以在只放行自有样式的页面策略下能用。
- 一个页面里至多一个形（FE-I18）。座位只给中点，自己不画东西。几个座位同时看得见时，形坐优先级最高的那一个。在 `[inert]` 里、没有接上页面或大小为零的座位不算看得见。没有看得见的座位时，形的墨原地干去。
- 形只以笔法动：写、点、干、重写、走一程。它不旋转、不拉伸、不缩放、不滑动，不用 CSS 动画。没事时帧循环停着。
- 形的大小是 56px 乘字号档的系数，在每个座位上、路上都一样。
- 减弱动效时，形不写、不飞，直接以新的样子出现在新的座位上：在想时停在半墨，在用工具时一点在正中，在写出时一页竖笔不动。
- 翻面时形走的是一程：先到要离开的那一面的纸边，拿着纸边托到对边，托的路与折痕用同一个钟，再落进要去那一面的座位。落座也算在翻面的 1500 毫秒里。翻面停下（到点、被点、再翻一次）时形直接到新座位。收起的那一面上的座位不算看得见；要去的那一面上没有看得见的座位时，形的墨原地干去。
- 拿起与在手：`FigureStage` 给了 `liftable` 时，在形上按下并移动过 4px 算拿起（`LIFT_DISTANCE`），相位是 `held`：座位上什么都不留，形用临界阻尼的弹簧跟着指针（刚度 1100，不滞后、不回弹），路上的墨立刻干掉。没过 4px 就松手，照旧是一下按。拿起、松手、Escape 与指针被取消各调一次 `onHand`，带着指针在视口与屏幕上的坐标与 ⌘、⇧ 两个修饰键；指针动时也调，一帧至多一次。下一次移动看到按键已经松开，当作在那里松手；指针被取消当作 Escape。松手与 Escape 的那一次，`onHand` 返回真表示宿主接手：形留在松手点不动，由页面画着，直到宿主调 `control.goHome()`（从它所在的地方一笔回座位）或把 `away` 设为真。不给 `onHand` 或它不返回真时，松手就是从手下一笔回座位。`FigureStage` 经 `control` 这个属性交出两个函数：`goHome()`，与 `seatPoint()`：形此刻该坐的那个座位在视口里的中点，没有看得见的座位时答 `null`。窗口藏着或最小化不改变座位算不算看得见。形不认识窗口的边：指针出了视口，形照着指针画，被视口裁掉。
- 不在页面里：`away` 为真时这一页不画形，也不出帧；座位照常算。形层里在形该坐的那个座位上留一块和形一样大的「空座」，它看不见，接指针，可访问名称由 `awayLabel` 给；按它调 `onRecall`，不按座位的控件。`away` 回到假时，形还在手里就画在手下，不在手里就在座位上重写。`away` 为真时没有看得见的座位，就没有空座。
- 离座的形 `LooseFigure`：没有座位的形，给应用画在页面之外的那块画面用。它收 `mode`（`hand`：跟着随后给的点；`rest`：落定在一点；`home`：一笔写到一点，写到了调 `onArrived`；`none`：什么都不画）、状态、待答数、大小与减弱动效；`rewriteFirst` 为真时，从在手或落定进到 `home` 先在原地把圆重写一遍，再写回去的那一笔，减弱动效时不重写。身体、状态的笔画、一程与墨色和页面里的形是同一份代码，所以人看到的是同一个形。它自己接指针：按下、拿起、移动、松手、取消、单击与双击各有回调，单击要等过 320ms 确认不是双击；`hand` 而指针按在它身上时它自己跟手。`reach()` 给出它此刻要接指针的矩形。一块画面里至多一个。它的身体和页面里的形问换画口的同一个键 `figure`，`phase` 的给法见「换画口」；它所在的那一页没有口时画自带的。
- 说话笺 `SayBubble`：墨框里从上到下是图的缩略条（每张可以去掉）、「说给谁」的下拉、一个多行字段、一行结局或说明，末行是收起与发送；结局是受理了时末行多一个去对话页的图标钮。它只收数据与回调，不认识会话。回车发送，Shift 加回车换行，输入法组字时不发，Escape 收起；没有字也没有图时发送钮不可用；说明是「现在发不了图」时图不算可发的内容，要有字才能发。笺里有图（发不发得了都算）就算有东西。宽 360px，高随内容；打开时在形身边的四个位置里挑一个整个在给定范围里的，第一个是右下，之后内容变长不换地方。墨正在写时按一个键或按一下，立刻写完，字段一出现就有焦点。字段里的字由调用方给（`note.words`），人每改一次经回调交回，件自己不留；调用方给的字和字段里的不一样时，字段换成调用方给的。受理之后笺里多一块回的话：纯文字，保留换行，不解析 Markdown；最高 240px，超过时在自己里面滚动并停在末尾，人往上翻过就留在他翻到的地方。回的话有三种状态：还在说、说完了、不知道；不知道写成一句中性的话，已经写出的字留着；调用方说后面还有时，末尾多一句「后面的在对话页」。笺里有图而且调用方给了现成的话时，笺旁多一列现成的话，在墨框外面，至多四句，每句一个按钮；正在发时这些按钮不可按，字段只读；`reach()` 给出的矩形把它们算在内。墨框里面的内容问换画口的键 `note`：`note` 是候选、说给谁、字、图、说明、结局、回的话、现成的话；`act` 是改字、选说给谁、发送、按一句现成的话、去掉一张图、去对话页、收起、去系统设置。
- 观测框 `ObservationFrame` 与签 `FigureLabel`：框是沿一个矩形的边走的一笔带口的墨，圆角 10px，口朝形；`covered` 给出的矩形盖住的那几段不画；`closed` 为真时把口合上，回到假时合口的那一笔直接拿掉。口定在框写出来的那一刻离形最近的那一点上，之后形再动口也不动。换一个矩形时旧框原地干去、新框写出来，不滑动。框里铺一层淡彩，`covered` 盖住的地方不铺，`closed` 时更浓。签是形身边的两三行字，写在一小块纸底上，最宽 22em，太长的一行截断；`tone` 是 `hint` 时用提示色。
- 圈出一点 `pointPicture(图, 点, 缩放)`：纯函数，异步，不用画布：PNG 的读写是这个成员自己的纯 TypeScript，只认 8 位、不隔行的 RGB 与 RGBA，别的格式拒绝并说明原因，不答一张坏图；图像数据解压出来比它的尺寸说的长，也拒绝，解压到那个长度就停。答两张 PNG：原图在那一点上加形的一笔圈；以那一点为中心、边长 480 个逻辑点的近看，出了图的部分裁掉，近看上不画圈。圈的墨色与纸气是定死的浅色主题的值，不跟主题：图是交出去的东西，不是界面。点不在图里时答原图一张，字节原样交回。
- 墨迹里画出东西的件都把调用方给的 `data-*` 带到自己的根元素上（类型 `DataAttributes`）：形的一层 `FigureStage`、离座的形、签、说话笺、告知笺、观测框、墨框、墨点。画它们的一方靠它挂部位的名字；件自己不认识部位。座位不画东西，不在内。
- 墨的颜色跟着样子。画在画布元素里的墨（形、墨点、墨框的湿墨、一程的笔迹）读元素的计算样式并记着；根元素的主题变了就重读。样式文本换了不改根元素的属性，所以另有一个口 `inkLookChanged()`：每一个收养改动的样式文本的页面，在换上新文本之后调它，记着的颜色全部作废，画着的那一帧照新的颜色重画。墨框边的浓、淡两种颜色是根上的令牌，部位的令牌改得到；墨框画出来的圆角读 `--omne-radius-window`，和样式里的角是同一个值。
- 墨框是一个件，有浓、淡两种墨。边按框的大小生成，不拉伸；引线从口出来，绕过圆，不穿过圆；边合上之前内容不可见，收起时内容先走。墨框没有焦点环，墨就是边。Escape 收起墨框，焦点回到展开它的控件。
- 告知笺用浓墨，在形的右边，最多三行；第四行能写完全文时写第四行。宿主可以给一个更小的行数上限，不少于两行，写不下的用省略号收住；上限由宿主按它不能盖住的字算。<!-- OD-20 -->
- 待答数用形自己的笔写在口外，用琥珀色。
- 墨点（`InkMotes`）是同一支笔点出来的几粒墨，落在一个不画出来的圆上，口和形的口开在同一处。它不是形：没有那一笔圆，不坐座位，不写待答数，不走一程，所以不算进「一个页面里至多一个形」。它只有点与干：没事静着、帧循环停着；它代表的事在做时（`doing` 不是 `idle`）最旧的一粒干去、原处新点一粒，间歇长短不一；`listening` 时圆心多一粒；`carried` 时只留第一粒，放下时其余的依次点出来。大小与形相同；颜色只有墨；减弱动效时一次到位、不重点。数在 `src/ink/motes.ts` 的 `MOTES` 里。
- 笔法、时长与验收问题的全部规则在[视觉规范的技能](../../.meta_harness/agents/skills/visual-standard/canonical/SKILL.md)里；数都在 `src/ink/` 的具名常量里。

### 技术栈

React、Tailwind 4（无配置文件，`@theme inline` 把 Tailwind 的主题名映射到 `--omne-*` 变量）、Radix、class-variance-authority、Streamdown。这套栈只在本组使用，不进项目顶层的[技术基础](../../docs/architecture/technical-foundations.md)页（负责人已定）。用本成员的应用负责装 `@tailwindcss/vite`，本成员不带构建插件。

### 来历与取舍

设计语言、素材、字体与代码取自外部项目，取了哪几块、改了哪几样见 [UPSTREAM.md](ui-kit/UPSTREAM.md)。取来的代码要符合本仓库：变量前缀是 `--omne-`；没有注释；不用路径别名；不依赖来源自己的桥、偏好与多语言。

中文字体集中写在 `styles/fonts.css` 的 `--omne-font-han`，以后换字体只改这一处。全角标点由随成员带的 `Omne Punctuation` 给出，墨两边的边距取来源同一字形的，墨宽是霞鹜文楷的，破折号与省略号 1 em。<!-- OD-15 --> 它只有全角标点，排在第一位；第二位是随成员带的霞鹜文楷（1.7.0，SIL OFL 1.1，常规与粗体），后面是系统字体回退。霞鹜文楷按字符范围切成 194 片放在 `resources/fonts/lxgw-wenkai/`，每片一条 `@font-face`（`styles/wenkai.css`），页面只取文字用到的那几片。仓耳今楷的许可不许作为应用资产发布，不取。字体栈里不写没有随成员带的字体名：Charter 没有随成员带，阅读字体栈里没有它。<!-- OD-8 -->

界面只有中文。需要文案的件（抽屉的关闭按钮、确认、状态词、行内通知、Markdown 控件）由属性传入文案，缺省值是中文。

#### 插入位置

插入位置写死在常量表 `slots` 里，不在运行期创建。种类是「只放一个」（`one`）或「放一列」（`list`）。

每个位置是登记表上的点。外壳自己的六个位置是 `shell.gate`、`shell.pages`、`shell.sidebar`、`shell.float`、`shell.back`、`shell.say`，规矩在 `shellContracts` 里，写着「构建时就定了」，键不公开（它们在客户端的树上，没有另一棵树要知道）；外壳的服务在构造时把它们声明进目录。附着位置不是一个点：它的名字就是点，或者「点、冒号、键」，点由展示那个对象的界面模块声明（见「带类型的拓展点」）。没有声明的点上放的东西不生效，在客户端的树上列成问题。

| 位置                | 种类 | 一项                                                                                                                                                                         | 谁放                                                         |
| ------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `gate` 登录门       | 一个 | `id`、`render`                                                                                                                                                               | 身份的界面模块。没有登录时外壳只显示它                       |
| `pages` 页面        | 一列 | `id`、`title`、`order`、`icon`（图标名）、可选的 `group`（`primary` 或 `utility`，缺省 `primary`）、可选的 `badge`（显示在导航里标题旁的小标记，返回空值时不显示）、`render` | 会话的对话页、资产的设置页                                   |
| `sidebar` 侧栏区    | 一列 | `id`、`order`、可选的 `group`（同上）、可选的 `rail`（侧栏折成窄条时的渲染函数）、`render`                                                                                   | 会话的会话列表、身份的账号块                                 |
| `float` 浮层        | 一列 | `id`、`order`、`render`                                                                                                                                                      | 要在整个应用之上放一样随身的东西的界面模块：会话的随身入口   |
| `back` 反面         | 一个 | `id`、`render`                                                                                                                                                               | 做应用反面的那一个界面模块：画布的界面模块                   |
| `say` 说话位        | 一个 | `id`、`targets`、`current`、`subscribe`、`say`、`show`、可选的 `pictures`（不画东西）                                                                                        | 接下人对形说的话的那一个界面模块：会话的界面模块             |
| `attached` 附着位置 | 一列 | `id`、`order`、`anchor`（位置的名字）、可选的 `label`（宿主排成页签时用的标签）、`render`                                                                                    | 要把自己的界面附着到别人展示的对象上的界面模块，或应用的装配 |

每个页面项都给 `icon`：侧栏折成窄条时只剩图标。名字不在图标集里时，外壳画「未知」的字形。`group` 只说这一项排在侧栏的哪一段：`primary` 在上，`utility` 在底部；同一段里的次序仍只由 `order` 与 `id` 定。侧栏折成窄条时，外壳画侧栏区各项的 `rail`，没给 `rail` 的项不画。

渲染函数收到的属性由契约定。页面与侧栏区的一项收到 `{ scope }`，侧栏区一项的 `rail` 也收到 `{ scope }`，页面项的 `badge` 也收到 `{ scope }`，`scope` 是当前租户的文本，还没有查到时是 `undefined`。附着位置的一项收到 `{ scope, subject }`，`subject` 是展示它的那个地方给出的对象文本。登录门的一项不收租户，属性是空的。界面模块要的协议客户端不经属性传，它自己从客户端的树上注入。

浮层的一项画在整个应用之上，登录之后才画。它在哪由外壳管，这一项不自己定位。它收到五样：

| 给它的     | 是什么                                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `scope`    | 当前租户的文本                                                                                                                    |
| `grip`     | 一组属性（属性名是常量 `FLOAT_GRIP_ATTRIBUTE`）。这一项把它写在哪个元素上，人就能按住那个元素拖这一项；一处都不写，这一项就拖不动 |
| `corner`   | 这一项现在靠着窗口的哪个角：横向 `start` 或 `end`，纵向同。这一项据此朝窗口里面展开自己的东西                                     |
| `dragging` | 是不是正被拖着                                                                                                                    |
| `note`     | 笺口：请外壳把说话笺写在这一项身边。`there` 说现在开不开得出；`open` 说笺是不是正开在这一项身边；`toggle(元素)` 开在那个元素身边或收起；`close()` 收起 |

外壳对浮层的每一项承诺：缺省在右下角；人拖到哪就留在哪，位置记成「靠哪个角、离那两条边多远」，所以窗口变了它跟着那个角；它永远整个在窗口里；拖只从 `grip` 起，没拖动的一下照常是点，拖过的那一下不算点；没按在 `grip` 上的指针照常归这一项。位置怎样记、记多久归外壳的实现（桌面应用见 [`apps/desktop/SPEC.md`](../../apps/desktop/SPEC.md#页面)）。浮层这一层自己不接指针，所以一项画多大就挡多大。一项渲染时抛出，这一项不画，也不写「读不出」：浮层上没有地方放那一句。

笺口。说话笺只有一块，归外壳（见下面的说话位）。浮层的一项不画它，只经笺口请外壳把它写在自己身边。`there` 为真，是说话位上此刻有一项；为假时 `toggle` 什么都不做，给的元素不在这一项自己画的东西里面时也什么都不做。`toggle(元素)`：笺没开在这一项身边时开，墨框的边从那个元素写出来，开在哪一边照说话笺自己的规矩挑（见「墨迹」）；已经开在这一项身边时收起。笺同一刻至多开在一处：在这一项身边开，开在别处的那一处先收，不管那是别的浮层项身边，还是页面之外的形身边。这一项被拖起来、被撤下，开在它身边的笺收起；收起不丢字。笺口不交出字、图与说给谁：拿到它的代码能把笺开出来，话仍然由人自己写、自己发。

反面的一项是应用的另一面，登录之后才画。登录之后的应用有两面：正面是页面与侧栏，反面是这一项。它收到三样：`scope`，当前租户的文本；`turn()`，宿主交给它的口，调一次就翻到另一面，和人用应用的翻面入口相同；`home()`，调一次等于人按了正面的家：外壳算出家该去哪一页，翻回正面，切到那一页。`turn()` 与 `home()` 都没有结果，这一项不能凭它们判断翻没翻过去。外壳对两面承诺：

- 两面在窗口的一生里都挂着，翻面只换哪一面露着，不卸下哪一面。收起的那一面内容照常在、读取照常跑，但不接指针与键盘、不给形座位。
- 没有人放这一项，或放它的模块缺着必需的需要，应用只有一面，翻面的入口都不出现。露着反面时这一项被撤掉，应用回到正面，不播翻面。它回来时翻面的入口回来，应用不自己翻过去。
- 在反面调 `navigate`，外壳先翻回正面，再把那一页切到前面。
- 浮层在两面之上：翻到哪一面，浮层的各项都在原处。
- 这一项渲染时抛出，反面只有这一项显示读不出；外壳自己的翻面入口照常，所以总能翻回正面。
- 停在哪一面、翻面的入口有哪些、怎样记住，归外壳的实现（桌面应用见 [`apps/desktop/SPEC.md`](../../apps/desktop/SPEC.md#页面)）。翻面的样子用共用界面件的翻面（见「纸的面」）。

说话位的一项不画东西：它让外壳把人对 agent 说的话交出去，而外壳不认识会话。说话笺只有一块，在哪里都由外壳画：窗口里从浮层的一项经笺口写出来，页面之外从形写出来（那里没有界面模块的代码）。这一项给它数据与动作。笺的状态归外壳的实现：开在哪、没发出的字、说给谁、图、结局、回的话（桌面应用见 [`apps/desktop/SPEC.md`](../../apps/desktop/SPEC.md#桌面层)）。十问的答案：

- 名字 `shell.say`，在客户端的树上，只放一个，没有键。两个模块都放时答冲突、都不在位；同一个模块放两次抛出。
- 这一项交数据与带副作用的函数。数据：`targets(scope)` 答候选的表，每个 `{ key, label }`，没读到时答 `undefined`，不答空表；`current(scope)` 答缺省说给谁的键，没有时答 `undefined`；`pictures(scope)` 答这一项此刻认不认识图（修订 2 加的成员，没有它等于不认识）；`subscribe(listener)` 在这三样可能变了时叫一声。函数：`say(scope, to, words, pictures?)`，`to` 是 `{ kind: 'new' }` 或 `{ kind: 'target', key }`，答一个只落定一次的结局：`sent`（受理了，带对象的键）、`failed`（确定没发出，带一句原因）、`unknown`（不知道）；`show(scope, key)` 打开那个对象并把它所在的页切到前面，没有结果。`key` 与 `label` 对外壳只是文本。
- 外壳每次要用时现取这一项，不留着它的函数。`targets` 抛出或答 `undefined`：外壳说「现在读不到可以说给谁」，不让发，不当成没有候选。`say` 抛出：结局记 `unknown`，外壳不重发。
- 撤下：外壳不再接新的 `say`；已经交出去的那一次照它自己的结局落定，它属于放这一项的模块，不随这一项撤下而取消。
- 形状只加不改。这个位置的规矩带主版本 1（`shellContracts` 里这一条的 `version`）；修订 1 没有图，图是修订 2 加的（同一条的 `revision`）：一项多一个可选的 `pictures(scope)`，`say` 多一个可选的图的表。外壳交不交图只看 `pictures(scope)` 此刻答不答真，不看修订号：答真才把图（`{ name, bytes }`）交给 `say`；没有这个成员或答假时不交，并对人明说现在发不了图。它每次现问，不在放项时定死，所以这一项认不认识图可以随别的模块的来去而变。
- 修订 3 加回的话（同一条的 `revision`）。`sent` 的结局多一个可选的 `said`：这句话的标识，对外壳只是文本。一项多一个可选的 `reply(scope, said, listener)`，答一个停止的函数。外壳在一句话受理之后调它一次，留着的只有这一次调用交回的停止的函数。`listener` 每次收到到此刻为止的整段文字与状态，不是增量：`{ text, state }`，`state` 是 `coming`（还在说）、`ended`（说完了）、`unknown`（这一项说不出这一轮怎样了）。文字只含 agent 说的话，不含它调了什么。`ended` 与 `unknown` 之后不再叫。结局里没有 `said`、这一项没有 `reply`，或 `reply` 抛出：外壳只写受理了，不写回的话，也不把它显示成空的回复。外壳同一刻只跟着最后受理的那一句；跟着的那一句换了、租户换了、这一项撤下，外壳调停止的函数。
- `current(scope)` 答 `undefined` 时，外壳缺省说给新的对象（`{ kind: 'new' }`）。
- 这一项拿得到人对形说的话与人交给形的图。能往这个位置放一项的代码就拿得到它们；plugin 的代码在页面里没有隔离，这一条照旧适用。
- 有这一项不等于许用：许不许由放它的模块在 `say` 里按服务端的答复说。

现成的话是说话笺旁的几句：按一句，就连笺里的图带这句话发出去。它是外壳的一个点，不是位置。十问的答案：

- 名字 `shell.say-phrase`，在客户端的树上，按键、每键一条，键是这句话的标识，对外壳只是文本。同一个键上取最具体的那一条。同一层里内容不同的两条答冲突，这个键不算数。
- 条目是数据，不带代码：`{ label, words, order? }`。`label` 是按钮上的字，一行，1 到 12 个字符。`words` 是发出去的话，1 到 400 个字符。`order` 是整数，缺省 100。不合规矩的一条不算数，外壳的答案里写明是谁放的与原因。
- 外壳用和改动同一个作用域发问（`lookScope(租户, 样子)`）。所以一个租户、一套皮肤都可以加自己的几句，别的租户看不见。外壳自带三句，放在对谁都算数的那一层：`shell.expand`「展开讲讲」、`shell.todo`「记成待办」、`shell.keep`「收藏下来」，`order` 是 10、20、30，`words` 与 `label` 相同。更具体的一层在同一个键上放一条，就换掉自带的那一句。
- 算数的各条按 `order` 再按键排，取前四句。`ShellService.phrases()` 答这四句，每句 `{ key, label, words }`；它变了时叫订阅的人。笺里有图、而且说话位此刻认识图时才显示。按一句：发出去的话是这一句的 `words`；人已经写了字时，字另起一行接在后面；图是笺里此刻的全部；说给谁是笺上此刻选的。它和按发送是同一次 `say`，结局与清字的规矩相同。有这一条不等于许用：发不发得出仍由说话位的那一项说。

附着位置让一个界面模块把东西放进另一个界面模块展示的对象里，而两边互不导入：展示对象的界面模块为这个位置起一个名字（`anchor`），调用服务的 `attached(位置的名字, 对象)` 留出位置；别的界面模块或应用的装配往同名的 `anchor` 里放项。位置的名字由展示那个对象的界面模块定，并写在它自己的规格里；契约不认识名字与对象的含义，它们对契约只是文本。

#### 瞬时提示

瞬时提示是外壳交给界面模块的一个口，不是插入位置：界面模块在某一刻说「现在提示这一条」，之后这条提示的寿命归外壳。它的共同规则见[宿主交给贡献方的口](../../docs/architecture/cross-cutting-concepts.md#宿主交给贡献方的口)。

| 问题             | 回答                                                                                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外壳给什么       | 服务 `shell` 上的一个操作：提示一条。交的是数据：`id`、轻重（`info` 或 `attention`）、标题、可选的一行正文、可选的动作（按钮上的字与要去的页面，页面可以带一个对象） |
| 谁画             | 外壳。界面模块不交渲染函数。桌面应用的外壳把它画成告知笺，见应用的规格 <!-- OD-4 -->                                                                                 |
| 寿命             | 外壳定：显示几条、什么时候收回、什么时候不显示。人可以点掉。这些是外壳的选择，写在外壳的规格里                                                                       |
| 同一个 `id` 再来 | 替换原来那一条，不叠加                                                                                                                                               |
| 界面模块卸载     | 它的提示随它的作用域撤掉，排着队的也撤掉                                                                                                                             |
| 给不出时         | 提示是尽力而为的：这个操作没有结果，界面模块不能凭它判断人看没看到                                                                                                   |
| 形状怎样变       | 只加不改；改形状要换名字                                                                                                                                             |

提示不保存任何东西：关掉窗口，没显示完的提示就没有了，再打开不补。要让人之后还找得到的内容，由界面模块自己的页面负责。点提示上的动作等于调 `navigate` 去那一页。

#### 形口

[形口](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-figure-port--形口--figure-port)是外壳交给界面模块的另一个口，同样不是插入位置：界面模块报出它代表的会话此刻在做什么，以及[待答数](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-awaiting-answer-count--待答数--awaiting-answer-count)；外壳把各份报告合起来画 [Agent 形](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-agent-figure--agent-形--agent-figure)。共同规则同样见[宿主交给贡献方的口](../../docs/architecture/cross-cutting-concepts.md#宿主交给贡献方的口)。

| 问题         | 回答                                                                                                                                                                                                                                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 外壳给什么   | 服务 `shell` 上的一个操作：报一份。交的是数据：`doing`，持续的活动，取 `idle`、`thinking`、`looking`、`writing`、`background` 之一；可选的 `moment`，一次性的事实，取 `received`、`landed`、`could-not` 之一，带一个序号，序号变了才算新的一次；可选的 `subject`，一句给读屏的对象文字；可选的 `waiting`，待答数；可选的 `waitingPage`，有待答时按形要去的页面标识 |
| 报什么       | `doing` 与 `moment` 的含义见[桌面应用「Agent 在屏幕上的形」](../../.meta_harness/design/product/desktop-application/design.md#agent-在屏幕上的形)的状态表。`waiting` 只报待答数：决策池里等着人回答的决策卡片的张数。别的计数不经这个口                                                                                                                            |
| 谁画         | 外壳，用共用界面件的墨迹块。界面模块不交渲染函数                                                                                                                                                                                                                                                                                                                   |
| 怎样合       | 同一个界面模块再报一份，替换它上一份。放了当前显示那一页的模块，它的活动是前台的；别的模块报的不是 `idle` 的活动只算 `background`。待答数相加。有待答时按形，去报了待答数的模块给的 `waitingPage`；几个模块都给时，去次序最前的那一页                                                                                                                              |
| 界面模块卸载 | 它的报告随它的作用域撤掉                                                                                                                                                                                                                                                                                                                                           |
| 给不出时     | 报告是尽力而为的：这个操作没有结果。外壳此刻不画形时，报告照样记下，形出现时用最新的那一份                                                                                                                                                                                                                                                                         |
| 形状怎样变   | 只加不改；改形状要换名字                                                                                                                                                                                                                                                                                                                                           |

报告不保存任何东西，也不改服务端的任何事实。外壳把前台的活动说成一句隐藏的状态文字，给读屏用。

#### 放进去与撤下

一处是「位置，加上附着位置的名字，加上标识」；只放一个的位置（登录门、反面）各只有一处。下表按这一处现在放着什么写。

| 位置 \ 这一处的现状          | 空     | 同一个模块已经放了 | 别的模块放了                                   |
| ---------------------------- | ------ | ------------------ | ---------------------------------------------- |
| 只放一个（登录门、反面）     | 放进去 | 抛出               | 两份都在，这一处答冲突，都不画                 |
| 放一列（页面、侧栏区、浮层） | 放进去 | 抛出               | 两份都在，这个标识答冲突，都不画；别的标识照常 |
| 附着位置                     | 放进去 | 抛出               | 同上，只看同一个名字下的同一个标识             |

- 两个模块撞在一处不是装配失败。两份都留在登记表里，这一处答冲突，写明是哪两家；其中一份撤了，另一份立刻生效。答案与谁先放无关，所以两次启动看到的一样。冲突用服务的 `conflicts(位置)` 读，每一处是 `SlotConflict`：位置、附着位置的名字、标识、两家的名字。
- 抛出的是 `ShellAssemblyError`，带 `slot`、`id` 与原因：同一个模块在同一处放了两次是 `duplicate`；放的东西不合法是 `invalid`，例如附着位置的名字不是「宿主.名字」这样的点名。被拒绝的放入不改变登记表，不通知任何人。
- 一个模块放的东西整份出现、整份消失：它在 `apply` 里放的各项在模块就绪时一起可见，读的人看不到只来了一半；`apply` 抛错的模块放的东西从不出现；模块卸载时一起撤掉。这一条由 `dynamis-cordis` 的座位守，见 [Dynamis 规格](../dynamis/SPEC.md)。 `apply` 抛出时别的模块照常：外壳记下这个模块，并往日志里写一行；它卸载、或下一次采用里 `apply` 没有抛出，名字就去掉。`shell.fallen()` 列出现在没起来的，每项是名字与原因：`threw`（启动时抛出）或 `held`（有模块说它停着这一样，例如装载器被底拦下的一份 plugin，经 `shell.markStart(名字, 'held')` 记上、`'gone'` 去掉）。名单变了通知采用的订阅者。外壳只记与列，怎样对人说归画它的应用。
- 标识只在同一处不许重复；不同位置里可以同名。附着位置里，两个互不知道的界面模块在两个名字下可以用同一个标识。
- 放一列的位置按 `order` 升序排，`order` 相同按 `id` 的码元序排，不用区域比较，结果与放进去的先后、加载的次序无关。整个附着位置一起读时，两项的 `order` 与 `id` 都相同就按位置的名字排。
- 放进去的一项绑在调用者的作用域上：`contribute` 把它登记成调用者作用域上的一个效应，作用域卸载时自动撤掉。界面模块不写撤下的代码。撤掉的只是它自己放的，别人放的不动。
- 一个模块可以在自己下面开一个作用域：`shell.host(名字, apply)`。`apply` 拿到的外壳属于这个新作用域，经它放的东西记在这个名字下，随它一起出现、一起撤掉；`dispose()` 只撤这一个作用域，开它的模块卸载时它也跟着卸载。答复里的 `by` 是登记表上实际用的名字：同名的另一个作用域还在时，后来的带后缀。`apply` 抛出时这个作用域不留下任何东西，`host` 把原因抛给调用者。用途是替别人放东西的模块（例如按清单装一份 plugin 的装载器）：每一份各占一个作用域，谁放的、要撤哪一份都分得清（FE-I48）。
- 界面可以在运行中改：令牌、样式、画法与布局这几个点上的条目可以由运行中装上的 plugin 放。放它们的是 plugin 的装载器（一个界面模块），用的是这一节的 `host`、`takesDrawing`、`described` 与没起来的名单；装什么、怎样装、应用起不来时怎样兜住，归 [plugin 包组的规格](../plugin/SPEC.md#客户端的装载器)。外壳不认识 plugin：对它来说那只是又一个模块在它开的作用域里放东西。
- `shell.described()` 答这棵树现在有什么：声明了的点（名字、一句话与整份规矩；一项的数据只能用一组定下的名字时，另带这组名字与各自此刻的值，由外壳的实现经受保护的 `dataKeysOf(点)` 给，别的点不带）与部位（名字、叫什么、是什么、开哪几种改法、在谁里面），都按名字排。它是给「把这棵树说给别处听」的模块用的（例如把客户端的样子报给服务端的装载器）；外壳自己不往外报。
- `shell.takesDrawing(点)` 答这个点现在收不收画法：部位的画法那个点，与声明了的按键选画法的点收；收数据的点、放一列的点、没人声明的名字不收。替别人放画法的模块先问这一句，不往别的点上放函数。
- 一项的内容是渲染函数，取不出内容摘要。契约拿「放它的那个实例」当摘要，所以两个模块放的同名项一定算内容不同。
- 撤掉当前显示的页面时，外壳回到次序最前的一页；一页都没有时主区空着。这一条归外壳的实现。

#### 服务 `shell`

`ShellService` 是抽象类，键是 `shell`。外壳实现它。

| 成员                                                      | 做什么                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `contribute(位置, 一项)`                                  | 往一个插入位置里放一项，绑在调用者的作用域上。它把这一项写成登记表的一个条目，交给服务 `dynamis`；外壳的实现不参与存放                                                                                                                                                                                                                     |
| `declare(规矩)`                                           | 把一个点声明进目录，绑在调用者的作用域上。宿主不直接调它，用拓展点的 `declare(外壳)`                                                                                                                                                                                                                                                       |
| `items(位置)`、`conflicts(位置)`、`subscribe(位置, 监听)` | 读一个位置现在生效的项、现在的冲突，与订阅它的变化。由抽象类照登记表给出，外壳的实现不重写                                                                                                                                                                                                                                                 |
| `login`                                                   | 登录在页面一侧的全部，类型 `ShellLogin`：`state()`、`subscribe(监听)`、`login(凭据)`、`logout()`。契约自己声明这个端口，登录状态 `ShellLoginState` 的四个取值与 `client-assembly` 的 `LoginState` 逐字相同，但契约不依赖客户端装配。应用在装配处把客户端装配的登录状态源交给外壳；两边的形状不一致时，在应用那里编译不过，这就是对上的办法 |
| `scope`                                                   | 当前租户的文本：`get()`、`set(文本)`、`subscribe`。设它的是知道租户的那个界面模块（身份）。登录状态离开「已登录」时外壳把它清空                                                                                                                                                                                                            |
| `navigate(页面的标识, 可选的对象)`                        | 把一个页面切到前面；露着反面时先翻回正面。标识不在时什么都不做，也不翻面。带了对象时，这个页面的 `render` 在 `{ scope, subject }` 里收到它（一段文本，含义归这个页面），用来指到页面上的那一项；它不打开、不改变任何东西                                                                                                                   |
| `page`                                                    | 现在显示在前面的页面的标识：`get()`、`subscribe`，只读；一页都没有时是 `undefined`。界面模块用它判断自己的页面在不在前面，不用它切换页面（切换用 `navigate`）                                                                                                                                                                              |
| `figure(一份报告)`                                        | 见「形口」。已经卸载的调用方，报告直接丢掉，不报错                                                                                                                                                                                                                                                                                         |
| `toast(一条提示)`                                         | 见「瞬时提示」。同一个 `id` 的替换只在同一个界面模块之内；不画提示的外壳、已经卸载的调用方，提示直接丢掉，不报错                                                                                                                                                                                                                           |
| `attached(位置的名字, 对象)`                              | 给出附着位置里 `anchor` 与位置的名字相同的全部项的渲染结果，按存放的次序排；每一项收到 `{ scope, subject }`，`scope` 是外壳当前的租户文本，`subject` 是这里给的对象。位置里的项放进或撤下、租户变了，已经渲染出来的结果跟着变。没有匹配的项时什么都不渲染                                                                                  |
| `arranged(位置的名字, 对象, 排版函数)`                    | 和 `attached` 取同样的项、同样的次序，但不替宿主拼在一起：把每一项的标识、标签、渲染结果（`AttachedEntry`）交给宿主的排版函数，给出排版函数的返回值。没有匹配的项时排版函数收到空表。订阅位置与租户的变化仍在外壳里，宿主不碰存放                                                                                                          |

`login(凭据)` 只交出凭据，答案只有结果，不含任何登录证明：`signed-in`、`auth-failed`、`unknown`、`unavailable`。`logout()` 的结果是 `signed-out` 或 `unknown`。结果不知道就是 `unknown`，不写成成功或失败。

外壳的实现给它画的每一项包一层错误隔离：一项的渲染抛出时，只有这一项显示读不出（FE-I14）。坏了的一项显示什么，归外壳的实现。

外壳一侧读位置用 `ShellSlots`：`items(位置)` 给出现在生效的项（列的位置已经排好序，只放一个的位置最多一项，冲突的不在里面），`conflicts(位置)` 给出现在的冲突，`subscribe(位置, 监听)` 在这个位置的项或冲突变化时通知。抽象类 `ShellService` 实现了 `ShellSlots`：一个位置的项没变时 `items` 给出同一个数组，别的位置变了不通知这个位置的订阅者。一个订阅者在回调里抛错，不挡同一个位置的别的订阅者，外壳记一条诊断。一个点读不出（没有声明，或被声明了两次）时 `items` 答空，和没有东西分不开：要分开，读客户端的树的问题一栏，外壳的实现把它记进日志。服务依赖 `dynamis`（见 [Dynamis 规格](../dynamis/SPEC.md)），应用在装外壳之前把它装到客户端的树上。

#### 带类型的拓展点

展示对象的界面模块要让别的领域往自己的界面里放东西时，用 `definePoint` 或 `defineKeyedPoint` 声明一个[拓展点](../../.meta_harness/design/ubiquitous_language/terms/architecture-core-and-extension.md#ul-extension-point--拓展点--extension-point)。它是附着位置上的一层薄壳：位置的名字与对象对外壳仍然只是文本，薄壳在两头做编解码。共同的规则见[拓展点的共同契约](../../docs/architecture/cross-cutting-concepts.md#拓展点的共同契约)。

| 函数                                | 声明什么                                                                                                                                                                            | 返回的拓展点                                                                                                                               |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `definePoint<S>({ name, subject })` | 名字，与对象 `S` 的编解码 `PointCodec<S>`（`encode` 把对象编成文本，`decode` 把文本解回对象，解不回时给 `undefined`）；可选的 `summary`（一句话说明）与 `key`（键是什么），写进规矩 | `Point<S>`：`name`；这个点的规矩 `contract`；宿主用的 `declare(外壳)` 与 `slot(外壳, 对象, 排版函数)`；贡献方用的 `contribute(外壳, 一项)` |
| `defineKeyedPoint<S>(同上)`         | 同上。这个拓展点按键分                                                                                                                                                              | `KeyedPoint<S>`：`slot` 与 `contribute` 各多一个键。不同的键互不可见                                                                       |

- 拓展点的名字是「宿主.名字」。它的规矩是数据：在客户端的树上，放一列或每键一列，一项交的是纯函数、必有 `render`，同一处多份答冲突，贡献在运行中能变。宿主的界面模块在 `apply` 里给自己的每个点调一次 `declare(外壳)`，把规矩声明进目录；宿主不在时点没有声明，别人放在上面的东西不生效。同一个模块声明两次抛 `ShellAssemblyError`。
- 一项是 `PointItem<S>`：`id`、`order`、可选的 `label`、`render`。`render` 收到 `{ scope, subject }`，`subject` 是解回来的对象。文本解不回对象时这一项不画，不抛出。
- 按不按键分由用哪一个函数定。不按键的拓展点上写不出键。
- 不按键的拓展点，附着位置的名字就是拓展点的名字，所以直接往同名的 `anchor` 里放的项也在里面。按键的拓展点，附着位置的名字是「拓展点的名字、冒号、键」。拓展点的名字里不带冒号。
- 贡献可以先于键放进去。宿主什么时候展示这个键，它什么时候出现。
- 编解码由宿主交进来。薄壳不导入任何协议契约，也不导入 Cordis：它要的外壳写成三个结构类型，`PointContributor`（有 `contribute`）、`PointHost`（有 `arranged`）与 `PointDeclarer`（有 `declare`），服务 `shell` 三样都满足。
- 贡献方不导入宿主的界面模块。宿主从自己的 `./cordis` 入口导出拓展点，应用的装配把它交给贡献方。贡献方只要贡献的一面，类型是 `PointSink<S>` 或 `KeyedPointSink<S>`，并用自己要的对象形状写 `S`。宿主的对象比它宽时可以交过去；对不上时，在应用的装配处编译不过。

#### 按键选画法的点

同一类东西按种类各有各的画法时（一种工具的调用、一种来源的通知、一种内容块），宿主用 `defineRenderPoint<S>({ name, key, summary })` 声明一个点：有人在这个键上放了画法就画它，没有就画宿主自己通用的那一份。所以每个键都画得出东西，新的种类一出现就看得见。

- 声明还写两栏：`subject` 一句话说宿主给画法的 `subject` 是什么、有哪些字段；`example` 是这个点的一项照 plugin 清单里一个代码成员的写法写出来的文本，第一行是成员（单行 JSON），后面是那个文件的最小写法，照抄就装得上。规矩的 `gives` 由 `subject` 拼出：`the scope of the tenant, the subject (<subject>), and generic, the drawing the host uses when nothing is put`。会话、通知、资产与画布的界面模块声明的点都写这两栏；没写 `subject` 的，`gives` 里只说「宿主给的对象」。

- 它是登记表上自己的一个点，不经附着位置：每键一项，一项是 `{ render }`，同一个键上作用域最深的一项算数。整个部署的作用域是空的，一个租户放的只有这个租户看得到（见「改一个部位的样子」里的「谁算数」）。
- 宿主在 `apply` 里调一次 `point.declare(外壳)`，画的时候调 `point.draw(外壳, 键, 对象, 通用的画法, 可选的外框)`。贡献方调 `point.put(外壳, 键, 画法, 作用域, 出处)`，返回撤掉它的函数；放它的模块卸载时也跟着撤掉。出处可以不给，见「改动的投影」。
- 画法收到三样：`scope` 是外壳当前的租户文本，`subject` 是宿主给的对象（类型是 `S`，不编成文本），`generic` 是宿主通用的画法，一个函数，画法可以包着它画。
- 画一个键，全部情形：

  | 这个键上           | 画什么                           |
  | ------------------ | -------------------------------- |
  | 没有画法           | 通用的                           |
  | 有一份算数的       | 这一份；给了外框时，外框包着它   |
  | 算数的那一份抛出   | 通用的，不带外框；别的键不受影响 |
  | 同一层有两份       | 通用的；树上这两项标着冲突       |
  | 放的不是函数       | 通用的                           |
  | 宿主没有声明这个点 | 通用的                           |

- 落回只有一处：`ShellService` 的受保护方法 `fallingBack(取画法, 画, 落回)`。部位的画法与按键的画法都经它。抽象类里的那一份接住调用时抛出的；外壳的实现重写它，把渲染当中才抛出的也接住，并在登记表或租户变了时重画。桌面应用里是一层错误边界，画法换了一份就重新试。换一份画法（含有与无之间）是换一棵子树，里面的元素都是新的：换之前焦点在这一处里一个带部位名的元素里、换完焦点落回页面的，外壳的实现把焦点还给同名部位里同一位置、同一种的元素，文本框的选区一并还上，按新的文字长度截；焦点本不在这一处，或换完已经落在别的元素上，不动它。
- 外壳要的面写成两个结构类型：贡献方要 `RenderPutter`（有 `putDrawing`），宿主要 `RenderDrawer`（有 `drawnAt`），服务 `shell` 两样都满足。贡献方只拿贡献的一面 `RenderPointSink<S>`（名字与 `put`），由应用的装配交给它。
- 键从哪来写在声明里：声明带 `keysFrom`（服务端树上一个公开键的点的名字）时，这个点的键就是那个点现在的键，客户端不另抄一份。`point.keys(连接说的)` 给出三种之一：`any`（没写 `keysFrom`，什么键都行）、`told`（服务端现在说的那些键）、`unavailable`（读不到：没有连接说的，或对方没说这个点）。读不到不是空。「连接说的」写成结构类型 `PublicKeys`（有 `keys(点名)`），客户端装配放在 `connection.server-points` 上的那一项满足它。放画法不核键：键不在服务端说的里面，画法照样放得上，宿主画到这个键时就用它。
- 这个点上的条目不是附着位置的项：`shell.items('attached')` 只收放一列的点上的项。
- 界面模块声明的有九个：放行卡的详情（`human-intervention.release-detail`，键是带种类的值的种类）、消息里的内容块（`session.block-render`，键是块的种类）、工具调用（`session.tool-call`，键是工具的名字，取自服务端的 `tool.tools`）、通知的一行（`notification.entry`，键是来源的名字，取自服务端的 `notification.sources`）、设置项的控件（`assets.control`，键是值的种类）、纸上的一样东西（`canvas.element`，键是种类名，取自服务端的 `canvas.kinds`）、从这一类里挑一个（`canvas.picker`，键同上）、递到纸上的东西怎样收（`canvas.intake`，键是递过来的东西的种类，文件是 `files`）、小应用（`canvas.app-render`，键是小应用的名字，不取自服务端）。各自给画法什么、通用的是什么，写在宿主所在包组的规格里。

#### 部位

部位是界面上说得出名字的一样东西：一个按钮、一块区域、一行。名字用来指它，改它的样子靠的就是这个名字。

- 界面模块用 `definePart({ name, label, summary, within, depths })` 声明一个部位，在 `apply` 里 `part.declare(shell)`，画它的元素上写 `{...part.props}`（就是 `data-omne-part="<名字>"`，属性名是常量 `PART_ATTRIBUTE`）。`data-slot` 照旧标组件的种类，两样互不相干。属性不叫 `data-part`：共用件的墨迹已经用它标一笔的各段，别的界面库也常用这个名字。
- 名字的形状：`<宿主>.<区域>`、`<宿主>.<区域>.<部位>`，至多四段，用点隔开；每段是小写字母、数字、连字符，字母开头。宿主是声明它的界面模块的名字去掉末尾的 `-ui`，和这个模块的拓展点用同一个前缀。名字说它是什么，不说它在哪、长什么样。
- `label` 是给人看的叫法，`summary` 是一句说明，两样都不能空。`within` 是上一级部位的名字，可以不写，可以是别的模块的部位；一个部位不能在自己里面。`depths` 写它开哪几种改法：`tokens`、`style`、`render`，可以一种都不开，不能重复。
- 不合这些规矩的声明当场抛 `ShellAssemblyError`（原因 `invalid`，写明是哪一条），这个模块放的东西整份不出现（FE-I38）。核法是纯函数 `partFault(声明, 宿主)`：合规矩答 `null`，否则答一句原因。
- 外壳自己的部位在 `shell` 下（整个应用是 `shell.app`），由外壳的实现调 `ShellService` 的受保护方法 `declareOwn(声明的列表)` 声明；界面模块不能在 `shell` 下声明。
- 只在某种状态下才画出来的部位，在声明里用 `when` 写一句是什么时候（例如「一轮在跑时」）；一直在的不写。
- 声明进客户端登记表上的点 `shell.parts`：每键一项，键是部位的名字，一项是数据（叫法、说明、上一级、开了哪几种）。这个点由外壳声明，运行中能变。模块卸载，它声明的部位跟着取走。
- 同一个名字的两份声明内容相同算同一个部位；内容不同是冲突：这个名字不代表任何部位，两个模块都列出来。`partsOn(登记表)` 按名字给出现在声明着的部位与冲突；点没有声明时答读不出，不答空表。
- 列表里重复出现的东西是一个部位，不是很多个。名字是承诺：改名是换一个部位，旧名字上的改动不再生效。
- 元素上的名字只经 `part.props` 写。共用件、界面模块与页面的源码和样式里不手写这个属性，自带的样式也不按它选元素（FE-I41）。例外只有一处：没有客户端的树的画面导入不了外壳契约，它从应用里的一个文件取属性名与要用的那几个名字（桌面应用是 `src/page/surface/parts.ts`）；外壳声明这几个部位时用的是同一个文件里的名字，一条用例核属性名与契约里的相同、每个名字都声明过。
- 名字只挂在已有的元素上，不为了挂名字加包裹的元素。一个位置的根是共用件时，靠那个共用件把调用方给的 `data-*` 带到自己的根上（见上面「页的骨架」）；不带的共用件画的位置没有名字：各处的分段选择、提示条、导航旁的数字、图表现在是这样。
- 应用装配出的全部部位钉在 `apps/desktop/tests/client-parts.txt`：名字、叫法、说明、上一级、开了哪几种、什么时候画出来、谁声明的。改一个名字就是改这份清单。

#### 改一个部位的样子

样子的改动是放在登记表上的条目，键是部位的名字。改法有三种：令牌、样式、画法。外壳把现在算数的令牌与样式变成一张样式表，写在 `omne-changes` 这一层里；条目撤掉，下一次生成里就没有它，自带的样子原样回来。页面的次序另有一个点，写在本节末尾。

- 每个改样子的点的规矩都写给只看得到文字的读者：`summary` 第一句说它改的是什么，用用户会说的词（主题、品牌色、样式、画法、页面次序）；`key` 说键是什么、从哪知道有哪些键；`gives` 说一项是什么或宿主给它什么；`example` 是一项照 plugin 清单里一个成员的写法写出来的文本，照抄就装得上（数据成员一行；代码成员一行之后跟文件的最小写法）。例子：令牌在 `shell.app` 上放 `--omne-accent`，样式给 `session.composer.send` 写 `base` 与 `hover`，画法给 `session.transcript.agent-message` 包一层（把 `part` 展开到最外层元素上，`builtIn()` 是原来的画法），布局把两页提到前面。外壳自己的六个位置随应用构建时定，`summary` 末尾写 `Fixed when the app is built: a plugin cannot add to it while the app runs.`，不给 `example`。
- 第一种改法是令牌：点 `shell.tokens`，每键一项，键取自 `shell.parts`，一项是数据 `{ tokens: { 令牌名: 值 } }`。`shell.putTokens(部位, 令牌, 作用域, 文件的位置)` 放一项（最后一样可以不给，见下面值的那一条），返回撤掉它的函数；放它的模块卸载时也跟着撤掉。
- 写到哪：键是 `shell.app` 的，写成页面根上的自定义属性；别的部位，写在带着这个名字的元素上（`[data-omne-part="<名字>"]`），所以只有那一块和它里面的东西读到新值。
- 谁算数：同一个键上作用域最深的一项。整个部署的作用域是空的；一个租户放的是 `['tenant', 租户]`（`tenantScope(租户)`），只有这个租户看得到，没登录时谁的都看不到。
- 样子：外壳有一个值「样子」，是一个名字或没有，由 `shell.wear(名字)` 定。发问的作用域只在 `lookScope(租户, 样子)` 一处造：没登录是整个部署；有租户没有样子是 `tenantScope(租户)`；两样都有是在它后面接 `['look', 名字]`。外壳的每一次发问（令牌、样式、次序、部位的画法、按键选的画法）都用它，所以换样子时各处同一刻换；放在某个样子那一层的条目，只有带着这个样子发问时看得见，并盖过租户这一层同一个键上的。外壳不知道这个名字指什么，谁定它也不归外壳。同一层有两项内容不同是冲突：两项都不算数，自带的样子显示，两家都列出来。
- 自带的那一份：外壳在 `shell.app` 上放一项空的、标着 `builtIn` 的条目，作用域是整个部署。树上因此看得出整个应用现在是谁的样子。值不搬进条目，仍在 `tokens.css`。所以整个部署这一层再往 `shell.app` 上放一项，是和自带的冲突。
- 不合规矩的条目不算数，并说出原因，更浅的一层里合规矩的那一项照常算数：
  - 键不是声明过的部位，或那个部位没有开 `tokens`；
  - 令牌名不是界面的令牌。界面的令牌由外壳的实现说了算（`knowsToken`）；桌面应用里的定义写在[桌面应用的规格](../../apps/desktop/SPEC.md)。外壳的实现能给出令牌的名字表（`dataKeysOf('shell.tokens')`，不空）时，原因写成 `<名字> is not a token of the interface. Nearest: <至多三个>. OmneExtensionPoints show shell.tokens lists them all.`：最接近的是去掉 `--`、`--omne-` 前缀后相同的名字，或编辑距离不超过 `max(2, 名字长度的四分之一)` 的名字，前者在前，再按距离、名字排；没有够近的就不写 `Nearest` 那一句。给不出名字表或表是空的，原因只有第一句；
  - 值不是文字，是空的，或有不许有的东西。
- 值是数据，里面没有能执行、能引外部东西的写法。值里只许有字母、数字、空格与 `# % . , ( ) + * / _ -`；只许调用 `var`、`calc`、`min`、`max`、`clamp` 与写颜色的函数（`rgb`、`rgba`、`hsl`、`hsla`、`hwb`、`lab`、`lch`、`oklab`、`oklch`、`color`、`color-mix`、`light-dark`）。所以 `url(`、`@`、分号、花括号、尖括号、引号、反斜杠、`!` 都进不来。核法是纯函数 `valueFault(值, 文件的位置)`。
- 值可以指到放它的那一方自己的图：写 `file(路径)`。路径是包里的相对路径（用 `/` 分段，每段是字母、数字、点、下划线、连字符，不以点开头，所以写不出 `.` 与 `..`），并且以 `.png`、`.jpg`、`.webp`、`.avif`、`.svg` 之一结尾。放这一项的一方同时给出「文件的位置」：本应用的一段路径，以 `/` 开头和结尾。外壳写样式表时把 `file(路径)` 写成 `url("位置加路径")`。路径不合规矩、不是图、没给位置、位置不是本应用的路径，这一项都不算数并说出原因。值里仍然写不出 `url(`：地址只由外壳拼。外壳不认识 plugin，它只认识「放的一方可以给一个位置」。
- 第二种改法是样式：点 `shell.part-style`，每键一项，键取自 `shell.parts`，一项是数据 `{ style: { base, hover, focus-visible, active, selected, open, disabled } }`，每一格是一组「属性: 值」，哪一格都可以不写。`shell.putStyle(部位, 样式, 作用域, 文件的位置)` 放一项，返回撤掉它的函数。谁算数、冲突、撤掉，和令牌相同。
- 样式写在带着这个部位名字的元素上；`shell.app` 写在页面的根上。每一格一条规则，状态用固定的选择器：`hover`、`focus-visible`、`active` 是同名的伪类；`selected` 是 `aria-selected`、`data-selected`、`aria-current="page"`、`aria-pressed` 为真，或 `data-state` 是 `active`、`checked`；`open` 是 `data-state="open"` 或 `aria-expanded` 为真；`disabled` 是 `:disabled`、`aria-disabled` 为真或带 `data-disabled`。规则按这个先后写出，所以几种状态同时成立时后面的盖过前面的，`disabled` 最后。
- 样式不合规矩的情形：部位没有开 `style`；状态不是这六种之一；属性名不是小写字母与连字符（以 `--` 开头的是令牌，要放到 `shell.tokens`）；值过不了上面那一条值的核法。不合规矩的一项整份不算数。
- 改动的那一层盖过自带的全部规则，包括共用件的状态规则：给一个部位写了平常的底色而没有写悬停的，悬停时显示的就是平常的那个。要悬停时不一样，就把 `hover` 那一格也写上。
- 第三种改法是画法：点 `shell.part-render`，每键一项，键取自 `shell.parts`，一项是 `{ render }`，`render` 是一个渲染函数。`shell.putRender(部位, 画法, 作用域, 出处)` 放一项，返回撤掉它的函数；出处可以不给，见「改动的投影」。谁算数、撤掉，和令牌相同；同一层有两份画法就是冲突，两份都不算数。
- 开了 `render` 的部位由声明它的模块经 `part.draw(外壳, 自带的画法, 给画法的东西)` 画。没有算数的画法时给出自带的画法的结果。有时调那份画法，给它三样：`props` 是模块给的东西，类型是 `definePart<P>` 的 `P`；`part` 是要写在根元素上的名字，就是 `part.props`；`builtIn` 是自带的画法，一个函数，画法可以包着它画。
- 画法抛出时，这个部位落回自带的画法，别的部位不受影响。落回走 `fallingBack`（见「按键选画法的点」）：调用时抛出的抽象类接住，渲染当中才抛出的由外壳的实现接住。
- 画法不合规矩的情形：键不是声明过的部位；部位没有开 `render`；`render` 不是函数。外壳自己的部位不开 `render`：声明里写了的当场抛 `ShellAssemblyError`。
- 页面的次序是一份布局：点 `shell.layout`，每键一项，键只有 `shell.pages`，一项是数据 `{ order: [页面的标识, …] }`。`shell.putLayout('shell.pages', 次序, 作用域)` 放一项，返回撤掉它的函数。谁算数、冲突、撤掉，和令牌相同。
- 布局里写到的页面排在前面，照布局的先后；没写到的照各模块给的次序排在后面；写到而不在的标识略过。`shell.items('pages')` 给出的是排过的次序，次序变了照常通知订阅者。没有算数的布局时是各模块给的次序。布局只排页面，别的位置不动。
- 布局不合规矩的情形：键不是 `shell.pages`；次序里有一项不是文字或是空的；同一个标识写了两次。
- `changesOn(登记表, 发问者的作用域, 认不认得这个令牌, 令牌的名字表)` 是纯函数（名字表是一个函数，只在拒一个名字时才读，可以不给），给出样式表的文字、算数的画法（按部位）与布局（按键）、每个键上现在是谁、不算数的各项与原因、冲突的各项。`shell.changes()` 按外壳正在显示的租户与样子问它；登记表、租户与样子都没变时给出同一份。`shell.changesFor(作用域)` 按给定的作用域问它，不看外壳此刻显示谁、用哪个样子：往某一层放了东西的一方用它问自己放的算不算数。点没有声明时给出空的一层，不抛出。
- `shell.watchChanges(监听)` 在登记表变了、外壳显示的租户变了、或样子变了时通知，返回停止的函数。租户变了由外壳的实现调受保护的 `rescope()` 告诉抽象类：页面的次序与改动都照新的租户重算。
- 桌面应用把这张表作为可构造的样式表挂在页面自己的样式之后；登记表或租户一变就重写。不算数的与冲突的各写一行警告。开了画法的部位画在一层错误边界里，画法换了就重画。

#### 改动的投影

应用可以有不止一块画面在画东西：主窗口的页面之外，还有它画在窗口外面的那一块（桌面应用的[桌面层](../../apps/desktop/SPEC.md#桌面层)）。客户端的树只有一棵，在主窗口的页面里。别的画面没有树，拿到的是改动的投影。这里的「画面」不是[应用的面](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-application-face--应用的面--application-face)：正面与反面都在主窗口的页面里，是同一块画面。

- 改动只算一次。外壳在有树的那一页照「改一个部位的样子」算出此刻算数的改动；别的画面不另算，不自己读要装什么、用哪个样子。
- 投影是可以搬运的数据：`css`，改动那一层的整份样式文本，就是 `changes().css`；`drawings`，一张表，每行是一个点、一个键与那份画法的出处。
- 出处 `DrawingSource` 是 `{ module, export, files }`：`module` 是本应用里的一段路径，内容不会变；`export` 是那个模块里的导出；`files` 是放它的一方的文件在哪，可以没有。放画法的一方在放的时候交出处（`putRender`、`putDrawing` 的最后一个参数）。外壳不认识 plugin：它只认识「一份画法可以带一个出处」。
- 照出处取来模块、用宿主交的东西调一次那个导出，得到一份等价的画法。等价有前提，是放画法那一方的义务：导出只用交给它的东西与自己模块里的东西造画法；不靠同一方别的画法被调过；不靠页面里别的部位在场。plugin 的这一条写在[它的规格](../plugin/SPEC.md#客户端的装载器)里。
- `shell.projection({ points, parts })` 答 `{ css, drawings, unreachable }`。`points` 是按键选画法的点的名字，这些点上每个键现在算数的画法都列；`parts` 是部位的名字，这些部位现在算数的画法都列。算数的画法没有出处时不进 `drawings`，进 `unreachable`（点、键、谁放的）：它在主窗口里算数，到不了别的画面。它和 `changes()` 是同一次发问，所以和主窗口里画的是同一份。纯函数是 `projectionOn(登记表, 发问者的作用域, 范围, 认不认得这个令牌, 令牌的名字表)`，后两样和 `changesOn` 的相同：样式文本要逐字相同，就要同一份对令牌的判定。`unreachable` 里「谁放的」和 `changes()` 里每个键上现在是谁是同一种写法。
- 同一样东西在每块画面上是同一个部位名、同一个件键。别的画面里的元素照样经 `part.props` 带名字，样式文本里按名字选的规则就在那里生效。写皮肤的人不需要知道应用有几块画面。
- 换的时候每块画面各自整套换，不出现半新半旧：一份投影里的每个模块都有了结局（得到了画法，或确定得不到）之前，那块画面整套留在上一份。没得到画法的那个键画自带的，别的键照常。所以别的画面可以比主窗口晚换，晚多少有上界；主窗口不等它们。怎样送、结局怎样定、上界是多少归应用，桌面应用的写法见[它的规格](../../apps/desktop/SPEC.md#桌面层)。

#### 动作与键位

外壳有一个按名字放的拓展点 `shell.actions`：界面模块往里登记[外壳动作](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-shell-action--外壳动作--shell-action)。外壳不认识任何一个动作的含义；按键、命令面板、按钮、系统菜单都只引用动作的名字。

| 问题       | 回答                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------- |
| 一项是什么 | 名字（`<领域>.<动作>`，稳定）、标题、种类（控制或界面动作）、缺省键与它所在的层、两个函数：此刻能不能用及原因，执行 |
| 能不能用   | 只在动作上算一处。按键、面板、按钮、斜杠写法给出同一个原因                                                          |
| 控制       | 执行时调会话协议里已有的操作，并点名界面此刻看到的那一轮或那一次调用；界面落后时得到服务端的拒绝                    |
| 执行出错   | 外壳记一条错误，并用瞬时提示告诉人                                                                                  |
| 撤下       | 随登记它的模块的作用域取走，它的键不再命中                                                                          |

键位的纯函数在外壳契约里，客户端各处用同一份：

- 把一次按键读成和弦名：带 ⌘、Ctrl 或 Alt 时读物理键位，不读打出来的字符（macOS 上 ⌥/ 打出来的是 ÷）；`Mod` 在 macOS 上是 ⌘，别处是 Ctrl。
- 层从里到外：浮层、输入框或当前页、全局。一次按键先查最里面的一层，命中就执行并吞掉；浮层开着时它独占按键，外面的层不查。
- 光标在输入框或别的能打字的地方时，不带修饰键的键是字，不查表；`/` 与 `?` 只在没有打字时是命令。
- 输入法组字时任何键都不处理。
- Esc 只管最里面的一层：关浮层，或把焦点从输入框交还；没有可关的就什么也不做。它不表示批准、删除或停止。
- 判一个键能不能绑：撞了同一层里别的动作，答撞了谁；系统保留的键（拷贝、粘贴、撤销、退出、关窗这一类）与会挡住打字的键（不带修饰键的字母、数字、标点），改不成并说明原因。键只能绑到控制与界面动作上。
- 人改过的键经外壳的点 `shell.keymap` 交给分发器、面板与速查：放一项，给出「动作名到和弦」的改动表与订阅；放它的是持有键位绑定的那个界面模块。往外壳放的每一项都可以由放它的模块自己撤下（`contribute` 交回撤下的函数），清单这类会变的项靠它更新。
- 缺省的一套键随应用发；人改过的是[键位绑定](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-key-binding--键位绑定--key-binding)，存在身份的账号偏好里，客户端只缓存。缺省表在同一层里不许有两个动作抢一个键，这一条是一个检查。

共用界面件有命令面板与键帽两个件。命令面板只认动作表：列出此刻的动作，每条旁边写它的键；不能用的灰着、写着原因、选了不执行。快捷键速查是同一个面板的另一种样子，按层列出此刻能按的键。

#### 界面模块

`defineUiModule({ name, needs, apply })` 返回一个 Cordis 插件。它只依赖 `shell`：外壳在它就加载，外壳不在时不加载。

`needs` 是一组具名的需要，每个是一条引用：

- `needProtocol(协议, { majors, optional })`：要一份协议。认几个主版本时把想要的写在前面；不写时只认契约自己的主版本。它是对点 `connection.protocols` 的引用，键是「协议名/v主版本」。契约只认识这个点的名字，不认识声明它的成员。
- `needPoint(键, { optional })`：要另一个界面模块提供的东西，或别的单项的点上的那一项。

**采用。** 外壳对每个界面模块的引用做一次采用（Dynamis 的 `adopt`）：每条引用钉在点上恰好一项上。必需的引用有一条钉不上，整份采用不可用，并列出缺的每一条。采用不存：`shell.adoption(模块名)` 按此刻的登记表算，`shell.watchAdoptions(监听)` 在登记表变时叫一声。可选的引用指着一个没有人声明的点时算没有，记空。

**`apply` 跟着采用走。** `apply(shell, bound, provide)` 对每一个采用跑一次，跑在一个与模块同名的作用域里。采用换了，上一次放的东西先随那个作用域收回，再跑一次。`apply` 可以返回一个收回函数。所以 `apply` 里建的读法、观察与订阅不会留着上一个采用的。可选的点上的需要来去不重跑 `apply`，界面模块经读口自己跟。

`bound` 给每个需要一格：

- 协议的那一格是这份协议的客户端，它一直在。每次调用按此刻的登记表找钉住的那一项：有就转过去；没有就当场答不可用，观察以不可用结束，不碰传输。
- 点的那一格是读口：`get()` 给此刻的那一项，没有时是 `undefined`；`subscribe(监听)` 在登记表变时叫一声。`attachWhile(读口, 接上)` 做三件事：有就接上，换了先摘再接，没了摘掉。它返回收回函数。

**缺着时放什么。** 必需的需要缺着时 `apply` 照跑。它放的页面与登录门照放，由外壳画成一句说明，写出缺的是哪一条与原因（见应用的规格）。它放在侧栏区、浮层、反面与附着位置上的不放，`provide` 不生效。反面不放，是因为缺着反面的应用就是只有一面的应用：部署没有开放做反面的那个领域时，人看不到一面写着缺什么的纸，也看不到翻面的入口。所以少一份协议只影响引用它的界面模块，别的页面上不会多出一块读不出的东西。

**提供。** `apply` 的第三个参数 `provide(键, 值)` 以这个界面模块的名义声明一个单项的点并放上这一项（`shell.offer`）。点的名字就是键，形状是「宿主.名字」。值是一个对象。界面模块的作用域收回时，这个点与这一项一起收回。

- 键是带类型的键 `ServiceKey<T>`：它就是点名的文本，类型里另带一个形状 `T`，放在函数返回值的位置上。`serviceKey<T>(名字)` 造一个键。所以给得多的键能当给得少的用（`ServiceKey<多>` 能赋给 `ServiceKey<少>`），反过来编译不过。`provide` 的值必须是键的形状。
- 提供方从自己的 `./cordis` 入口导出键。使用方不导入提供方：它用自己要的形状写键的类型，由应用的装配把提供方的键交给它，它写成 `needPoint(键)`。形状对不上时，在应用的装配处编译不过。装配没有交键的那一格指着一个没有人声明的点，读到空。
- 同一个键由两个界面模块提供时，点上有两项，答冲突：引用它的界面模块缺这一条。

## 原则与约束

- 共用件不认识领域，也不认识应用。需要领域知识的界面放进那个领域的界面模块。
- 数值只在 token 里；组件读语义层。
- 控件的交互状态用数据属性表达，不靠类名约定。
- 文案由调用者传入，缺省是中文；共用件不挑错误码的措辞。
- 导航与列表里的计数一律用共用件的计数胶囊。琥珀的样子只给等人回答的数，别的计数用中性的样子。
- 加载、空与出错各只用共用件的一个件；可点的东西只经控件族，成员不写原生控件。
- 状态词只取共用件的状态词表；时刻只经共用件的相对时间件写；图标只画共用件的图标集。
- 动作照[规则与 token 的索引](../../.meta_harness/agents/skills/visual-standard/canonical/references/rules-index.md#a-动作)的 A 节：常用的工具动作是图标钮，名字在提示与可访问名称里；偶尔的动作进一个 `⋯`；带字的 `Button` 只有表单与对话框落定的那一个、对话里要人选的选项、一页唯一的主动作，以及字就是东西本身的对象名与当前值；不需要的动作不画。抬起的件四周留得下它的边线、投影与焦点环，不贴着会裁切的容器的边（S15）。
- 两套主题下，正文与状态词对它所在的面至少 4.5:1，字段边界与焦点至少 3:1。
- 守观感的门集中在桌面应用的 `tests/design-gates/`，扫共用件、桌面应用的页面与它装配的每个界面模块。今天的违规记在基线里，基线只许变小：多一处是新违规，少了而基线没缩也失败。
- 偏好的读写由调用者注入，共用件不自己碰存储。
- 本组不为旧数据写兼容代码；改承诺同步真实消费者，替代实现随改随删。
