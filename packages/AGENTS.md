# 产品能力的维护地图

这里补充产品包的知识归属、公开边界及阅读停止点。目标包组织归[产品包组织](../docs/package-organization.md)，当前成员由[包入口](README.md)及实际workspace发现，系统责任归[领域入口](../docs/domains/README.md)。目录不直接决定DDD上下文、插件、服务或进程。

## 从责任进入拥有者

`packages/<domain>/`聚集相关工程知识，组README解释成员分工、依赖和组合责任；`packages/<domain>/<package>/`拥有公开使用、行为、内部设计及验证。两层文档均按[成员文档要求](../docs/member-documentation.md)维护，不把组入口压成单纯目录表，也不把SPEC当作整套文档。

普通局部修改从所属包README、采用的公开承诺和相关验证开始，责任明确后停止扩展。选择新组、拆包或增加公开保证时，先读产品包组织及所属领域；包从已接受职责和承诺建立，不凭产品设计或目录存在推定就绪。

尚未整合的技术材料从[旧材料入口](../.meta_harness/design/architecture/README.md)定位，按[架构准入规则](../docs/engineering/documentation.md#位置与唯一源)筛选。成员细化须符合docs现行架构；冲突旧设计不得作为规范沿用，源码、模板和测试不能使之成为架构例外。

## 包群与独立能力

能力的契约、实现、专属提供者、集成和验证就近维护。Service定义随公开承诺拥有者；同组不豁免[依赖方向](../docs/package-organization.md#依赖方向与cordis集成)。跨包通过公开exports消费，不穿透兄弟src。

独立使用与Cordis装配分别有依赖和生命周期责任。新建或整改成员先核对[模板支持范围](../docs/development.md#创建和整改产品包)，不手写另一套骨架，不以标识证明行为符合。源码、声明、运行和安装闭包分别核对。

开发工具归tools，产品应用与装配归apps。未定规格的探路件留任务tmp，不在产品包中建立假契约或引用临时实现。构建脚本和版本引用规则沿[workspace](../docs/workspace.md)，本区特定运行限制见[包约束](README.md#硬约束)。

## 维护与验证触发

改变公开契约、资源读取或组合机制时，同批核对成员文档、组导航和真实消费者。精确失败、生命周期及恢复由实际契约拥有者维护；不能通过删页、删登记或缩检查分母隐藏义务。

文档修改沿[维护指南](../docs/maintenance.md)，包修改沿[相称验证](../docs/verification.md)。需要模型、协议或组合保证时读取实际拥有者及必要资源；局部任务不通读全部领域或完整验证矩阵。
