# Schema

## 总体架构

Schema 包组回答一个问题：一份已经读成 `JsonRead` 的 JSON，怎样按它的形状拥有者发布的形状安全地检查，并在一个执行域里只编译一次、并发时共享、失败时不留下坏缓存。本组只放这个检查的提供者，不收集业务形状。

| 成员              | 回答的问题                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------------- |
| `schema-provider` | 对 `JsonRead` 做准入、首次编译与检查，并持有本执行域的编译缓存、槽位与租约；引擎是 Zod 与 Ajv |

形状拥有者用 `defineSchema` 发布一个 `SchemaRef`；执行域创建一个提供者并把它交给域内的调用方；调用方把 `JsonRead` 交给 `validate`（一次检查）或 `lease`（按住一份快照做多次同步检查）。提供者在调用任何编译器之前先遍历定义，挡掉不安全的构造，算出结构摘要；通过之后编译一次，发布不可变的快照；检查的输入是投影后的值，输出只有本组的问题码。执行域关闭时调用 `close`。

## 领域边界

本组拥有：形状定义的准入（排除哪些构造）、结构摘要与修订冲突、首次编译与在途合并、快照、槽位、租约、失败冷却与次数，以及检查结果的问题码与路径。

本组不拥有：严格 JSON 的读取与读取失败的分类（`packages/common` 的 `json-text`）；任何业务形状（各自的拥有者）；字段 codec（形状拥有者）；插件配置的 Standard Schema（Cordis 插件的原拥有者）。本组不是纯文本格式化或纯表示的收纳处。

本组声明、由别人实现的端口：

| 端口                      | 对方                             | 本组需要它做什么                                                 |
| ------------------------- | -------------------------------- | ---------------------------------------------------------------- |
| `JsonRead`、`JsonFailure` | `json-text`（`packages/common`） | 给出已读的值（带源词法与对象键顺序）或读取失败；本组原样转发失败 |
| 形状加载 `load`           | 形状拥有者                       | 交回带修订号、数字模式与定义的形状                               |

本组为别人实现的端口：

| 端口                                                | 对方       | 本组提供什么                         |
| --------------------------------------------------- | ---------- | ------------------------------------ |
| `createSchemaProvider`、`close`                     | 执行域     | 一个执行域一个提供者，带显式预算     |
| `defineSchema`、`zodDefinition` 与 JSON Schema 定义 | 形状拥有者 | 发布形状引用；`refresh` 通知新修订   |
| `validate`、`lease`                                 | 业务调用方 | 一次检查；按住一份快照的多次同步检查 |

## 心智模型

把提供者想成一个执行域里的编译柜台。每种形状一个格子；第一个来的人触发编译，同时来的人一起等这一次结果；编出来的东西是不可变的快照，挂在格子上给后来的人用。形状换了修订，新人用新快照，手里还按着旧快照的人继续用旧的，直到松手。编译失败不挂任何东西，只记下「多久之后才能再试」和「试过几次」。

最容易想错的地方：编译成功不证明定义安全，安全由编译之前的遍历判断；检查的是投影后的值，不是引擎吐出来的值；摘要不一致的同一修订是冲突，不是新版本；快照个数上限不是内存上界。

## 应然设计

### 一次检查

- `validate` 一次完成加载、准入、首次编译与检查；调用方没有公开的「加载、编译、检查」三步。
- 输入已经是读取失败时，答 `unreadable` 并原样带出 `JsonFailure`，不重新分类。

### 准入

- 遍历在调用 `z.compile` 或 Ajv 之前进行。callback、错误回调、`.transform`、`.default`、`.prefault`、`.catch`、`z.lazy` 与强制转换答 `refused`（`unsupported-construct`），调用方的函数被执行零次；引擎自带的检查实现不在此列。遍历深度与节点数有显式上限。
- 有环的 JSON Schema 答 `refused`（`runtime-path-closed`），不当作编译命中，不到达 Ajv。引用只沿 Schema 位置解析（本地指针、`#` 锚点、元组 `items`、`dependencies` 里的 Schema）；属性名列表不是 Schema；`const` 与 `enum` 里的 `$ref` 是数据。无法解析或非法的引用在编译前答 `unsupported-construct`。本组不另写 JSON Schema 解释器。
- Ajv 关闭类型强制、默认值与删除多余属性。

### 缓存键与修订

- 缓存键包括形状 id、修订号、结构摘要、编译器身份与数字投影模式。摘要覆盖一切影响检查结果的定义与依赖：约束参数、字面量的值与种类、正则的源与标志、枚举取值、格式、数组元素与嵌套形状。
- 同一 id、同一修订的结构摘要与仍存活的快照不一致，答 `refused`（`revision-conflict`）；离开当前槽、仍被租约按着的快照也参加这次比较；旧快照不变。

### 投影与问题

- `valid.value` 是投影后的值，引擎输出被丢弃。数字模式由形状拥有者给出，没有全局默认：`exact-or-reject` 只在转换可逆时给出 JavaScript 数字，否则问题码 `precision`，路径 `projection`；`lexeme` 把源词法交给检查器。投影保留对象键的顺序与全部自有键（包括 `__proto__`）。
- 问题码只有 `type`、`empty`、`precision`、`constraint`、`unrecognized-key`；引擎的原始错误只在本组内对照到这些码，调用方不解析文字。问题路径保留空键、字面百分号与数字对象键，数组下标是数字；路径转换不抛出。

### 槽位与预算

- 一个执行域一个提供者，Worker 之间不共享；每个形状 id 一个槽，槽里是一份在途编译、一份就绪快照、一条冷却记录，或仍有租约的旧修订。全部预算字段必填，本组不提供默认值。
- `maxSnapshots` 计入在途项、当前槽与仍被租约按着的旧快照；旧快照从替换它的加载被接纳起就占预算。槽位不足时只淘汰租约数为零且冷却已结束的条目；腾不出来答 `refused`（`budget-exhausted`）。有租约的快照不被淘汰也不被覆盖。准入抛出时，等待者答 `refused`，在途状态清掉，之后的调用不挂起。

### 在途合并与刷新

- 同一键的并发首次调用共享一次加载与一次编译。一个调用取消只让它自己答 `cancelled`，其他等待者继续；全部等待者在编译开始前都取消时，这次编译不留下就绪快照。
- 加载期间到来的 `refresh` 留给之后的消费者：已在等待的调用按本次结果完成，下一次使用重新加载；成功、失败、拒绝与取消都保留这次刷新。结果还没交给等待者时再次 `refresh` 不释放这次占用；这段时间同 id 的新调用共享这份快照。只有发布时仍在等待的调用占一份，提前取消的不扣别人的份额。新版本成功后，这次加载租到的旧快照 `superseded` 为真。

### 失败与冷却

- 编译或加载失败不留下成功缓存，等待者答 `unavailable` 并带 `retryNotBeforeMillis`。冷却未结束时再次调用答同一个 `unavailable`，不再编译。同一修订失败次数到 `maxAttempts` 后答 `refused`（`attempts-exhausted`）。持有旧租约时，新加载的冷却与次数照样保留，旧租约照常检查。

### 租约与关闭

- `lease` 按住准入时的快照，新修订不改它的目标，只让 `superseded` 变真；`release` 让租约数减一，到零之后快照才可回收。
- `close` 停止新准入；已经加入的检查按加入时的快照做完；之后的 `validate` 或 `lease` 答 `refused`（`closed`）；再次 `close` 仍是关闭。

## 原则与约束

- 安全由编译之前的遍历判断，不由编译成功判断；不让调用方的函数在准入之前运行。
- 失败不缓存成成功；冷却与次数上限让失败有界，不无限重编。
- 快照不可变；新修订不改已经按住的租约；摘要冲突如实拒绝。
- 预算是显式配置，没有默认数值；超出答 `refused`，不覆盖有人在用的快照。
- 根入口不导入 Cordis，也不把 Zod 或 Ajv 的类型带进调用方；Zod 与 Ajv 只在引擎适配里出现。
- 业务形状留在原拥有者，本组不新增形状成员；要开放循环 JSON Schema 的运行时检查，先改这份规格。

## 不变式

| 编号  | 永远成立的性质                                                       | 违反的后果                                 | 由什么守                                                                           |
| ----- | -------------------------------------------------------------------- | ------------------------------------------ | ---------------------------------------------------------------------------------- |
| SP-1  | 被排除的构造在任何编译器调用之前被拒绝，调用方函数执行零次           | 准入之前就运行了任意代码                   | `excluded-constructs.spec.ts`                                                      |
| SP-2  | 有环的 JSON Schema 不到达 Ajv，也不记为编译命中                      | 运行时进入无界递归                         | `json-schema.spec.ts`                                                              |
| SP-3  | 同一 id 与修订、摘要不同时答修订冲突，旧快照不变                     | 两份不同的形状共用一个修订号，检查结果漂移 | `revision-conflict.spec.ts`                                                        |
| SP-4  | 检查结果只用本组的问题码，值是投影后的值；不可逆的数字转换不静默成功 | 精度丢失被当作合法值                       | `issue-codes.spec.ts`、`number-projection.spec.ts`、`plain-object.spec.ts`         |
| SP-5  | 同一键的并发首次调用只加载与编译一次；一个调用取消不影响其他等待者   | 重复编译，或一次取消拖垮所有人             | `single-flight.spec.ts`                                                            |
| SP-6  | 失败不留下成功缓存；冷却期内不再编译；次数到上限后拒绝               | 坏的编译产物被复用，或失败无限重试         | `compile-failure.spec.ts`                                                          |
| SP-7  | 有租约的快照不被淘汰或覆盖；新修订不改已有租约的目标                 | 正在检查的人手里的形状被换掉               | `lease.spec.ts`、`budget.spec.ts`                                                  |
| SP-8  | 快照个数不超过 `maxSnapshots`，旧快照从接纳起计入                    | 槽位无界增长                               | `budget.spec.ts`                                                                   |
| SP-9  | 关闭之后不再接纳；已加入的检查按原快照做完                           | 关闭期间仍有新检查进来，或在途检查被打断   | `close.spec.ts`                                                                    |
| SP-10 | 根入口不导入 Cordis，公开类型不带 Zod 或 Ajv 的类型                  | 只要检查的消费者被迫加载 Cordis 或引擎     | 包清单不依赖 Cordis；公开类型不带引擎类型只有文字；`public-entry.spec.ts` 核导出名 |
