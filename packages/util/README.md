# 纯文本格式化

本组放不携带业务事实的文本格式化函数。它不是 `common`。`common` 只在至少两个具名消费者确认同一纯表示后接纳成员。XML 渲染和终端文本排版目前没有这组消费者。

封存实现留在 `packages.0.0.1.legacy/util`。新成员不把那个目录当作运行依赖。

## 责任与范围

本组拥有纯函数的文本输出。调用方提供数据，函数返回字符串或抛出输入错误。本组不解析命令行，不创建状态目录，不读取身份，也不决定某个应用的帮助文案。

## 成员与依赖

| 成员 | 包名 | 拥有的输出 |
| --- | --- | --- |
| [unix-format](unix-format/README.md) | `@omne-harness/unix-format` | 按 Unicode 码位对齐的段落、用法行、表格和结果信封 |
| [xml-format](xml-format/README.md) | `@omne-harness/xml-format` | 按字段声明渲染的 XML 文本 |

两个成员都没有运行时依赖。它们不互相导入。

## 关键协作

应用在自己的命令表里决定帮助文案。需要与本组成员相同版式时，应用调用公开函数。`omne` 当前的 `--help` 原文与 `formatSection`、`formatUsage` 的输出不同，所以 CLI 不依赖 `unix-format`。

## 组合验证

每个成员用自己的表征测试锁定输出。组内没有跨成员组合。CLI 的进程测试单独锁定 `omne --help` 的原文。

## 维护

新增格式化成员时，先说明它为什么不是 `common` 的纯表示，再按成员模板建包。改变某个公开函数的输出时，同时改该成员的测试和 SPEC。不要把封存目录里的同名包改成转发层。
