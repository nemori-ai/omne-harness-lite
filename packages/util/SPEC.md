# Util

## 总体架构

Util 包组回答一个问题：不携带任何业务事实的文本输出（终端文本排版、XML 渲染）由谁写一次，供需要相同版式的调用方直接调用。调用方给数据，函数返回字符串或抛出输入错误。

| 成员          | 回答的问题                                                                |
| ------------- | ------------------------------------------------------------------------- |
| `unix-format` | 按 Unicode 码位对齐的段落、用法行、命令列表、键值、表格、编号行与结果信封 |
| `xml-format`  | 按字段声明把一个值渲染成一个 XML 元素；XML 名字检查与文本转义             |

两个成员都是纯函数，没有运行时依赖，互不导入。输出的字节由各自的表征测试钉住。

## 领域边界

本组拥有：上述函数的输出字节与它们拒绝的输入。

本组不拥有：命令行解析、状态目录、身份；任何应用的帮助文案与命令表（各应用）；Schema 注册与 XML 解析。本组不是 `common`：`common` 只接纳至少两个具名消费者确认的同一纯表示，这两个成员没有这样的消费者组。

本组不声明端口，也不为别人实现端口；调用方直接调用公开函数。应用需要与本组相同的版式时调用它；版式不同就不调用，本组不为迁就某个应用的文案改变输出。

## 心智模型

把这两个成员想成两把尺子：给它数据，它照固定的刻度排出字符串，同样的输入永远得到同样的字节。尺子不知道谁在用它，也不读环境、文件或时钟。

最容易想错的地方：宽度按 Unicode 码位算，不按 UTF-16 码元；每个函数只看自己那几个选项字段，别的字段传了也不读；XML 里非法的字符不是被悄悄删掉，而是抛错。

## 应然设计

### unix-format

- `formatSection(title, body)` 默认输出 `## ${title}` 并把正文的非空行按缩进排出；`markdownCompatible: false` 时标题为 `${title}:`。它只校验 `indent` 与 `markdownCompatible`，类型上不接受 `maxWidth`。
- `formatUsage` 输出一行 `USAGE: ${toolName}(command="${command}", params=${paramsSynopsis})`，概要原样插入，不解析。
- `formatCommandList` 把名字、概要、描述排成三列，名字与概要按码位宽度对齐，描述前有一个 U+2014 破折号；空数组返回空字符串。
- `formatTable` 只校验 `maxWidth`，不因 `indent` 无效而失败。`formatKeyValue` 接受 `Map<string, string>` 或普通记录，不接受自定义的 `ReadonlyMap`。
- 其余函数（键值、表格、列表、编号行、成功、挂起、错误信封）的换行与缩进由表征测试钉住，不另写样例。
- 不加 ANSI 颜色或框线。

### xml-format

- `formatXml` 按 `schema.tag` 输出一个元素，字段按声明顺序出现：`presentation: 'attr'` 写成属性，`'content'` 写成文本内容，不写时按元素处理。`attr` 与 `content` 不带 `attrs`、`itemTag` 或 `itemFields`。同样的字段选择总是渲染出同样的文本。
- 空元素写成自闭合标签。`Set` 与等值数组走同一条渲染路径。一列对象只有每一项都自己渲染时，才不再额外包一层字段元素；混合的列表保留字段元素。嵌套的 `toXml` 只收到 `indentSize` 与 `formatDate`。
- 路径默认只读自有属性；显式字段名 `__proto__` 仍可读。
- XML 1.0 不允许的码位在内容、属性、手工属性与嵌套字段上一律抛 `TypeError`；制表符、换行、回车与普通空格保留。文本按位置转义；元素与属性名先校验再输出。
- `extraFields` 里的名字必须已声明为 `optionalFields`，否则抛错，消息包含 `extraFields not declared as optionalFields`。字段覆盖的路径必须由 schema 声明。

## 原则与约束

- 纯函数：不读环境、不读文件、不导入 Cordis、不导入应用或另一个成员。
- 输出字节由表征测试钉住；改变一个输出字符串或错误消息，同时改这份规格与对应测试。
- 新增格式化成员前先说明它为什么不是 `common` 的纯表示。
- 不为迁就某个应用的帮助文案改函数；应用不用相同版式就不调用。

## 不变式

| 编号 | 永远成立的性质                                                                      | 违反的后果                   | 由什么守                                                                                                             |
| ---- | ----------------------------------------------------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| UT-1 | 同一输入得到同样的输出字节                                                          | 调用方的输出在升级后静默变化 | 两个成员的表征用例（`sections`、`structured`、`numbered`、`envelope`、`format`、`options`）与 `differential.spec.ts` |
| UT-2 | 列宽按 Unicode 码位计算                                                             | 含补充平面字符的列对不齐     | `unix-format` 的 `sections.spec.ts`、`numbered.spec.ts`、`differential.spec.ts`                                      |
| UT-3 | XML 1.0 非法码位在每条渲染路径上抛 `TypeError`，不静默删除                          | 输出不是合法 XML             | `xml-format` 的 `adoption.spec.ts`                                                                                   |
| UT-4 | 未声明为可选字段的 `extraFields` 名字抛错                                           | 调用方拼进 schema 之外的字段 | `xml-format` 的 `format.spec.ts`                                                                                     |
| UT-5 | 两个成员没有运行时依赖，互不导入，也不导入 Cordis；构建产物可以被普通 Node 直接导入 | 纯文本工具拖进框架或应用     | `public-consumer.spec.ts`（两个成员）；`lint:deps`                                                                   |
