# 日历

## 总体架构

日历包组回答一个问题：一个调用方怎样按明确的日历与版本，得到可指认、可复核的日别与工作日计算；这些版本知识又怎样从权威来源发现、校验、一致地发布与保管，并让人看得见它是否健康。

| 成员                       | 回答的问题                                                                                                            |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `calendar-contract`        | 日期值、不可变快照、查询与供应服务端口、请求与结果、错误长什么样。纯数据与 schema，不依赖 Cordis 与存储               |
| `calendar`                 | 纯日期计算、查询应用、供应的解析与政策、供应应用（种子、校验、刷新、健康、恢复）怎样工作。不依赖 Cordis，不选存储后端 |
| `calendar-cordis-contract` | 日历在这套系统里以哪两个服务出现：查询服务与供应服务的定义与键                                                        |
| `calendar-local`           | 本机的发布存储与供应存储、受限的来源获取、发行种子的读取、供应运行器、设置环境投影，以及两个 Cordis 提供者            |
| `calendar-tools`           | 给 agent 的一个只读日历工具：参数与结果、可信上下文的取得、工具贡献的生命周期                                         |

依赖只朝契约：`calendar-local` → {`calendar`、`calendar-cordis-contract`、`calendar-contract`、`sql-contract`}；`calendar-tools` → {`calendar-cordis-contract`、`calendar-contract`、Tool 的公开作者协议}，不依赖 `calendar` 与 `calendar-local`；`calendar` → `calendar-contract`。查询应用先核资格，再解析日历与版本，在一份不可变快照里完成计算并带回实际依据。供应应用把来源材料解析、校验之后，经存储的具名参加者把新版本与当前发布事实在一次提交里写入；提交之后的反应经 outbox 交出。查询与供应可以在不同实例里运行，但消费同一份公开契约，不共用进程或数据库作为前提。

## 领域边界

日历拥有：日历身份与适用范围；不可变的版本知识（覆盖、星期默认表、逐日例外、知识截至、出处）；当前发布指针与发布代际；日期分类与工作日算术；供应的来源政策、校验、待裁、发布、恢复与健康；发行种子与发行把关条件。

日历不拥有：消费者选了哪份日历与时区（设置）；谁能读、能配、能发布（身份与授权）；Schedule 的身份、规则、预览与 Job 的接受、冻结、去重和补跑（日程）；通知的受理与送达（通知）；工具调用的准入、结果保管与长结果的读回（Tool）；SQL 提交与耐久的实际保证（存储提供者）。日历只读既有设置，不保存第二份消费者环境。

本组只认通用角色：可信上下文里的主体与租户、调用方给出的查询范围与依据、原操作身份。

本组需要、由别人提供的：

| 需要                             | 对方                              | 本组需要它做什么                                        |
| -------------------------------- | --------------------------------- | ------------------------------------------------------- |
| 有效环境读取                     | 设置（Settings 的读取与求值协议） | 一次读取同时给出时区、日历与修订；缺值如实答缺失        |
| 读取、配置与发布资格             | 身份与授权                        | 每次操作现场答当前资格；拒绝与未知分开                  |
| 具名命令与事务参加者             | 存储（`sql-contract`）            | 在一个事务域里写入版本、出处、指针、代际、回执与 outbox |
| 反应的承接                       | 健康投影、唤醒与通知的拥有者      | 承接 outbox 里提交之后的反应；重复告知不产生新版本      |
| 工具作者协议、结果保管与 offload | Tool                              | 登记工具贡献，保管完整结果，按当前资格读回              |

本组为别人提供的：

| 提供                                             | 对方                             | 本组提供什么                                 |
| ------------------------------------------------ | -------------------------------- | -------------------------------------------- |
| 查询服务（目录、读取、解析、分类、算术）         | 日程、独立程序、`calendar-tools` | 按明确依据计算并带回实际身份、版本与观察位置 |
| 供应服务（种子导入、刷新、健康、恢复）           | 系统管理入口与装配               | 发布新版本、报告健康与未完责任               |
| 服务键 `calendarQuery`、`calendarSupply`         | Cordis 装配                      | 唯一的服务定义；提供者继承它                 |
| 工具 `calendar`（list、get、effective、resolve） | Tool 与 agent                    | 只读查询，能力只有 `calendar.read`           |

## 心智模型

把一份日历想成一叠写好就不再改的版本，加上一根指向「当前发布」的指针。查询总是先选定一份版本，再在它上面算；指针移走不改旧版，旧版仍能按原样复核。供应是另一条独立的线：发现、取材料、校验、和当前版比较，通过了才在一次提交里铸出新版并挪动指针。查询从不触发供应，供应坏了也不抹掉已经能答的旧版。

计算是固定依据上的偏函数：日期在覆盖内才有分类，覆盖外不猜普通工作日。答不出有四种不同的原因，彼此不冒充：缺选择或版本、覆盖不足、合法地不存在（`null` 是有依据的成功）、预算用尽。日历只做日期计算；什么时候做什么事、Job 接不接受，都是日程的决定。

最容易想错的几处：国家名不是日历身份，美国联邦日历不是全国放假；下载成功不等于发布；超时不等于没发布，要按原操作查回；取消请求被受理不等于发布被阻止；安装时间不是知识截至；一个全局的固定天数代替不了每份日历自己的健康政策。

## 应然设计

### 身份、版本与时间

- 日历身份表达业务适用范围；版本身份表达不可变知识；发布代际表达当前指针的提交次序。内容摘要、供应操作、契约版本、来源版本与运行实例代际各自分开。
- 一份版本保存覆盖、恰好七项的星期默认表、按日期唯一的例外、知识截至、合成时点与出处。半日事实只作出处备注，不改变全天分类。
- 日期只用 ISO 本地日期；分类不依赖当前时间；时区运算显式进行，不靠运行环境的缺省。
- 已发布的版本不可变：修订用新版本表达，同一版本不重绑定数据，当前发布变化不改旧内容；没有下架、到期删除或自动清理。实例退出、缓存失效、存储换代都不删除版本。

### 依据解析与查询

- 目录查询只要合法范围与读取资格，不要求日历身份、生效选择、版本、日期或规则输入；合法空目录与查询失败可区分；它不触发刷新或配置。
- 单历的读取、解析与计算必须明确给出日历身份（或明确请求某个消费者上下文的生效选择），并明确给出指定版本或当前已发布版本。没有生效选择不代选，没有版本不藏缺省。
- `latest` 一次捕获发布代际与版本身份，`pinned` 只读那一版，不随当前发布变化。一次计算只用同一份版本的内容、覆盖与出处，并带回实际采用的依据；直接计算与「先解析再按返回的身份与版本计算」等价。两次查询之间设置或当前版变化时如实报告不同依据，不混用。
- 有效环境必须是同一修订里的时区与日历，不拼两次读取；显式的空日历不被缺省日历替代。
- 读请求取消只停这一次观察；分页与投影标出观察位置，不外推成跨请求的永久快照。

### 日别与工作日算术

- 覆盖内先取逐日例外，没有例外时取星期默认表；覆盖外分类无定义。实际补班、observed 与法定例外不被星期模板覆盖。
- 前后增减 N 个工作日从起始日之后或之前开始数；N 为零返回起始日，即使它不是工作日。区间计数包含两端。合法输入、方向、版本与覆盖不由库的缺省补全；必要路径跨过未知日期时不跳过、不猜。
- 正序找第 N 个工作日：找到目标时只要已检查的前缀有覆盖；答「不存在」或找最后一个时，需要整个区间的依据。
- 合法输入推进越过四位年份的日期域时答覆盖不足，日期为空，并标出越过的是下界还是上界；普通的覆盖缺口带回实际缺失的日期；搜索预算先用尽答搜索上限。

### 有界计算

- 有界求值是另一个函数：合法且有答案的输入可能因预算不足答「受限」，所以它不是原偏函数的精确全化。领域上无答案、没算完、提供者故障与权限拒绝分别表达。
- 每一步是终止、确定、没有隐藏 I/O 的全函数；活动状态每递归一步预算严格减一；已终止的结果在零预算下仍可返回；足够的预算一定取得已有的答案或确定的「不存在」。组合只允许有限层，失败短路，不允许无限重试或无界展开。
- 计算与预览只读：不猜自然语言意图，不改设置、日历或 Schedule，不接受 Job、不扣次数、不触发动作或通知。整体 Schedule 的规则与预览归日程。

### 供应：发现与校验

- 每份日历沿自己的权威发布节奏发现新材料，跟进未来年度与已发布年度的修订；不能只重取固定旧地址就报没有变化。来源分角色：真值、对照、例外来源、远期探测；来源适配只做探测与取得，解析与政策在 `calendar`，不写版本库。
- 下载与格式合法不代替业务校验。校验至少包含格式、日期唯一、覆盖连续、关键锚点、补班合理、来源血统、对照差异、与当前版重叠部分的变化、覆盖不收缩。
- 规范内容相同是无变化。覆盖累积与有新权威出处的合法修订可以发布；覆盖收缩与关键假日缺失不替换当前版；没有新出处的静默重叠修改保留原材料、摘要与差异待裁，不自动接受也不丢弃。
- 声明为两个独立来源时必须实际独立（采集与转录路径不同）；同源转写不满足。补充材料只用于既有检查，不算新的独立对照，不代替真值回链。
- 美国范围只是联邦日历；中国的半天与地方节日等限制留在语义边界里。知识截至只取来源自己的依据（完成的有界扫描、组件修订时点），不能用 HTTP 日期、下载或安装时间代替。

### 发布的一致性与恢复

- 新版本、出处、当前指针与代际、操作回执与发布后的 outbox 由供应拥有者在一次提交里写入；不能先答成功再补版本，不能确认一个指向缺内容、未校验或半份数据的当前版。
- I/O、解析与业务校验在事务之外；提交时复核期望的发布代际、原操作与当前资格；前提变了就重新校验或报冲突，不能用旧校验覆盖后来的发布。同一版本异内容拒绝。
- 发布的版本精确关联原来那份待发布材料；读取当前版先固定版本身份，再读该版的原发布材料并核来源、血统、权威、原文摘要与两个时点。不能用后来「无变化」的回执替代原材料；关联或材料缺失明确失败，不降成空贡献。来源权威引用与本机的原材料引用分开，后者不成为种子的可移植身份。
- 超时、断连、回执丢失不证明发布没发生：保留原日历、待发布材料、提交关联、已确认部分与未知范围，先按原操作查回，不重铸版本、不回退旧数据；已确认的发布只接续未完的反应，仍未知的继续保管。
- 提交之后的反应（健康投影、唤醒、维护提示、通知）失败只留下未完的反应责任，不把发布报告成未发生、不改旧版、不重做发布。确认意图的键在首次发出前保存；同键同内容认回旧结果，同键异内容拒绝；未知时不自动换键，重新获准的确认用新键。
- 维护取消在提交前确认成立时才阻止这次发布；已成立的发布不因取消、停止或退出撤回。取消与提交竞争或效果不可确认时按原操作查回。已经发生的抓取、存储与通知效果如实保留。

### 种子与发行把关

- 发行种子为声明的每份日历带受校验的版本，至少完整覆盖发版日所在的自然年，并含发版时权威已发布的更远覆盖；这不等于从安装日起滚动十二个月。
- 安装先同步校验并落地种子，种子损坏明确失败，不注册一个假就绪的服务；之后才尽力联网刷新。无网不阻止覆盖内的查询；刷新失败保留现有数据与失败事实。重复初始化不重铸同一版本，不用旧种子回退；新种子走同一校验与发布路径。
- 健康与查询能力分开：覆盖与知识截至分别显示，最近成功更新、连续失败、待裁的材料与覆盖余量可观察，按每份日历的政策在覆盖耗尽前告警。
- 发行时任一日历达到严重条件不得发行，警告必须显式声明；政策或状态未知不报通过。阈值由治理拥有者给出，技术提供者不偷填缺省。

### 与日程的接缝

- 日历提供指定版本或当前版本的知识与真实失败；日程拥有最新版的校验与 Job 的接受、已接受要求的冻结、去重、等待、取消与补跑。
- 新版本发布不接受、取消、移动或改写已有 Job 的采用内容，也不生成重复的 Job。跟随用户环境的安排随同一环境修订重算还没接受的未来；显式安排不随用户选择改变日历身份；显式 `latest` 跟随同历发布，`pinned` 保持指定版本；没有用户环境的系统归属不能跟随用户环境。
- 供应恢复不证明漏过的工作已经做了；查询或预算不成为 Job。

### 缓存

- 缓存键含实际身份、不可变版本与影响结果的全部输入；租户的选择与受保护投影再含所有者与资格。缓存只有加速权：不发布版本、不改设置；当前选择或版本变化不造成新旧混合；陈旧的目录与健康投影标出观察位置，不能以投影消失证明版本删除，也不能以旧缓存掩盖查询故障。

### 生命周期与装配

- 提供者停止先拒新准入，再按原操作把待发布材料、已提交的发布、未知结果与 outbox 认回、排空或可靠交接；不能删了注册就宣称业务完成。
- 每个实例只撤自己的注册、监听、计时器、取数观察与存储使用权；两代清理交错时只释放自己的令牌；晚到的结果回到原操作；共享资源只释放自己的使用权。dispose 不回滚发布、下载或通知。部分初始化失败也收口；清理失败报告实际残留。供应计时器只用于唤醒，到期与探测状态在存储里。
- 自己持有的供应应用或运行器由提供者停止；借入的不停止。关闭先拒新调用，再有界排空，报告未完调用与失败。
- 服务定义在 `./cordis`，查询与供应各一个键；定义不授执行资格；提供者继承定义并持有资源，不把资源建在调用方的上下文上。方法不经上下文注入身份，不把本机资源写进跨部署的值。

### 工具

- 一个工具，动作只有 `list`、`get`、`effective`、`resolve`，能力只有 `calendar.read`；工作日判断、计数与移动走 `resolve` 的明确分支，不另复制计算。供应、发布、种子导入与发行管理不默认暴露给 agent。
- 参数不接受可信身份、权限上下文、存储、种子或任意回调；可信上下文每次调用从宿主取得，日历应用仍现场核资格。调用与直接查询的错误、依据与分页含义相同。
- 完整的判别结果交给 Tool 保管与 offload；编码超过上限（16 MiB）明确失败，不以裁剪冒充成功；分页保留游标，分页不是裁剪。

### 设置环境投影

- 本地的设置环境适配从原调用恢复受信主体与已采用的目标映射，一次读取取得时区、日历与修订。缺值保持缺失；部分、错配、非法值与依赖异常答不可用。设置的可读不等于日历的可用，日历的使用权另行判断；适配不发行主体、不改偏好，不为后续 Schedule 写入提供原子当前性。

## 原则与约束

- 一个事实一个拥有者：设置、资格、日程决定、通知与工具保管都经端口读结论，日历不存第二份。
- 版本不可变，事实只追加：修订、撤销、待裁都是新的事实，不改旧的。
- 失败如实分类：缺依据、覆盖不足、合法空、预算用尽、故障与未知各有含义，互不冒充。
- 未知按原操作查回，不重做；只声称实际已阻止或已确认的效果。
- 产品含义（来源优先级、覆盖与健康政策、日别规则）由本组实现，不交给通用库的缺省行为；不建设世界节假日引擎。
- 公共消费不要求同机、同进程或共享数据库；跨部署的值不含运行时对象。
- 改变定义域、空结果、覆盖或预算的语义时，先改形式模型与负控，再改实现；有限模型检查、抽象证明、源码符合性与真实集成是四层不同的证据。
