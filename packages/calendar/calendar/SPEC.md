# calendar/calendar 长期行为候选

本文件维护具名文档目标的完整必要行为。文档目录不成立真实 workspace 成员、公开形状、发布版本或运行能力。整体产品及技术采用尚未接受；阶段清单未选，实现与行为验证未核实。产品范围见[产品正文](../../../.meta_harness/design/product/calendars/design.md)，精确协作、机制与技术缺项见[内部设计](docs/internals.md)。本文件不重复未来公开类型，也不以机制未定取消已明确的行为。

## 责任、消费者与成立前提

日历契约向独立程序、人、agent 适配和日程消费者承诺可指认的版本知识、覆盖、来源、真实健康及按明确依据计算日期。供应/版本拥有者维护原材料、候选、发布事实和未完维护责任；日期计算拥有者保护输入/输出含义；查询适配保留依据和错误；缓存只有加速权，没有发布、设置或业务决定权。

目录查询要求合法查询范围及适用读取资格，允许不筛选。目录不要求日历身份、消费者生效选择或版本输入，也不要求日期或规则输入。单历读取、解析及计算的消费者提供明确日历选择、版本选择和适用读取资格，日期计算还须提供相应日期或规则输入。消费租户当前选择时有明确租户及合法消费者上下文。

供应方提供所声明范围的有效来源、业务校验和合法维护权限。介质、网络、调度和提供者可用性决定相应进展前提；权威尚未发布未来材料时系统不能保证产生未来覆盖。缺失前提明确失败或受阻，不伪造成功或默认许可。

公共供应不归管理员个人租户。租户消费者配置或受保护输入沿真实租户隔离与当前资格，不以系统身份、工具装配或人工答复补读取/写入权限。持久选择归既有设置拥有者；日程独立保存 Schedule 身份、候选及 Job 采用关系；通知独立确认交付。版本知识不依赖 Session 或某次 Run，原工作事实不随计算或供应实例退出结束。

## 操作的前提与结果

| 操作含义 | 必要前提 | 成立结果与失败边界 |
|---|---|---|
| 目录查询 | 合法查询范围及读取资格 | 目录含身份、适用区域、时区、版本集、覆盖、出处、健康；合法空范围和查询失败可区分，不触发刷新/配置 |
| 解析/读取版本 | 显式身份或显式消费者当前选择；显式指定版本或当前已发布版本 | 返回实际身份/版本及观察依据，无选择、无版本、无权和故障不代选；同次计算采用同版知识 |
| 日期分类 | 日期在实际逐日覆盖内 | 返回声明适用范围的全日日别及命中依据；半日备注不变成全日分类，覆盖不足不猜 |
| 工作日增减/统计 | 完整方向/数量或端点、明确版本、必要路径覆盖 | 增减从起始日之外数，零值返回起始日；统计含端点，不跨未知区间伪造答案 |
| 有界日期计算 | 调用方已解释意图，明确规则/时区/边界及必要版本 | 一致结果与解释，只承担日历计算；整体 Schedule 预览及业务政策归日程，不生成工作 |
| 消费者选择配置 | 真实设置写资格、租户及允许值成立 | 由设置保存/确认；日历只解析；回执未知查原设置操作，不产生第二真相 |
| 种子初始化 | 所声明种子有效、范围与发布物条件成立 | 先本地可用再尽力刷新；重复不重铸、不倒退，新种子仍校验；取消/中断查原结果 |
| 维护候选与发布 | 真实供应资格、来源、完整业务校验及提交前提成立 | 新不可变版本及当前发布事实一致成立；退化拒绝、静默修改待裁、未知原操作查询 |
| 健康与发行把关 | 可解释实际状态及有效每历政策 | 健康和查询能力分开，提前风险可见；严重条件阻发行，警告声明，未知不报通过 |

以上是业务操作含义，不固定工具命令、字段、错误码或传输协议。原 Calendars 的 list/get/classify_date/add_workdays/count_workdays 仅是已有只读消费投影，不能据其命名推出独占 API 或管理权限。公开形状技术义务见 Q-CA02。

## 业务不变式

### INV-CA01 身份、适用范围与来源明确

每份业务日历可区别并声明自己的适用范围，每次发布有可定位版本、覆盖、信息截至时点和真实权威出处。国家名不等于完整身份；美国联邦范围不扩大为全国统一放假，同源转写关系不藏成独立来源。内容版本、契约版本、表示版本、运行代际和操作关联分别表达。验证义务 V-CA01。

### INV-CA02 当前资格及租户边界贯穿关键入口

查询、消费者持久切换、供应配置/维护及发布分别核验实际操作资格。标识可猜、对象可见、tool 可发现、HITL 答复可接受、系统发起或曾经有权，不证明当前可执行。租户设置、受保护输入、缓存、索引和后台传递保留同一租户含义；缺失、冲突或未获授权的跨租户访问拒绝，不能回退另一租户。公共供应不伪造系统租户或管理员个人归属。撤权不删除原事实，读取仍受当前资格限制。验证义务 V-CA02。

### INV-CA03 单历选择与版本必须显式且同次一致

目录查询允许不筛选，不要求日历身份、消费者生效选择或版本输入，按合法范围及当前读取资格返回目录和观察位置。

单历读取、解析及计算明确指定日历身份或明确请求指定消费者上下文的生效选择，并明确指定版本或当前已发布版本。无生效选择不代选，无版本选择不藏默认。日历只读既有设置，不能保存第二份消费者环境真相。一次计算捕获实际身份及不可变版本并使用同版内容、覆盖和出处；同样解析依据下直接计算与先解析再按返回身份/版本计算等价。设置或当前版在两次查询间改变时如实报告不同依据，不能混用。验证义务 V-CA03。

### INV-CA04 全日日别如实解释

在所声明范围内按逐日依据返回工作日、法定节假日或其他非工作日，实际补班/observed/法定例外不被星期模板覆盖。供应中的半日事实只保留出处备注，不误报全天非工作日或宣称本候选支持半日计算。具体供应种类及阶段范围须被明确选择，旧首批清单不成为新阶段默认。验证义务 V-CA04。

### INV-CA05 工作日算术边界固定

前后增减 N 个工作日从起始日之后/之前开始数，N 为零返回起始日；区间工作日计数包含两端。合法输入、实际方向、明确版本和必要覆盖不能由库默认补全；必要路径跨未知日期不能跳过未知区间猜结果。精确输入形状由公开契约落实，不改变零值和端点含义。验证义务 V-CA05。

### INV-CA06 缺依据、空结果、故障与未知分开

缺选择、版本不存在、覆盖不足、合法无候选、查询故障和结果未知具有不同可观察含义。覆盖外或有缺口返回边界及不足，不猜普通工作日、不伪造数量/时刻或称没有到期工作。更新健康差不必抹除旧版正确答案，查询故障也不假报供应无变化。未知不证明未发生、已失败或成功。验证义务 V-CA06。

### INV-CA07 计算及预览只读并可复核

相同实际规则、时区与日历版本得到相同日历计算和解释。日程以引用或展开同一实际定义消费日历时含义相同，整体规则与预览仍归日程。计算不猜自然语言意图，不授予后续写权、不改设置/日历/Schedule、不接受 Job、扣次数或触发动作/通知，不预测执行时长与实际重叠。查询取消只终止该请求，不撤回其他事实。验证义务 V-CA07。

### INV-CA08 已发布版本不可变且历史仍可解释

修订通过新版本表达，相同版本不重绑定数据，当前发布选择变化不修改旧内容。保留已发布版本及所承诺原依据，使指定版本查询和历史计算可复核；供应实例退出、缓存失效或来源安排结束不删除版本。不可查询时真实报告，不拿新版替旧版冒充复核。本候选不增加下架、到期删除或自动清理动作。物理归档或存储优化不能缩短已承诺查询范围。验证义务 V-CA08。

### INV-CA09 种子先可用且不因初始化倒退

选择离线种子能力的发布物，为所声明每份日历携带受校验的版本，至少完整覆盖发版日所在自然年，并含发版时权威已发布的更远覆盖；这不等于安装日起滚动十二个月。先落地可查询再尽力联网，无网络不阻止覆盖内使用。安装时间不冒充信息截至。重复初始化不重铸同一版本、不用旧种子回退当前数据；更新种子走同一校验与发布规则。刷新失败保留现有可用数据及失败事实。验证义务 V-CA09。

### INV-CA10 供应发现与业务校验成立才可发布

每历沿自己的权威发布节奏发现新文件，跟进未来年度和已发布年度修订，不能只重取固定旧地址就报没有变化。下载与格式合法不代替业务校验。覆盖累积及跨年合法修订可发布；覆盖收缩、关键假日缺失等退化不替当前版。重叠日期有新可追溯权威出处的变更可校验，无新出处的静默变更保留原材料及差异待裁，不自动接受或丢弃。采用中国原双源范围时需实际独立，不能用同源转写满足。验证义务 V-CA10。

### INV-CA11 版本发布业务单元一致且有并发保护

可解释的新内容、覆盖、出处以及当前发布事实，由供应/版本拥有者在一致提交边界保护；不能确认指向缺内容、未校验或半份数据的当前版。每历并发发布形成可解释顺序，提交时核验有效当前依据和资格；前提已变则重核或报冲突，不能用旧校验覆盖后来发布。新版本在所声明介质/部署前提下达到可抗普通进程、操作系统崩溃和断电的耐久边界后，才确认相关提交成立。精确事务、标识和恢复机制为 Q-CA03 技术义务。验证义务 V-CA11。

### INV-CA12 提交后反应不倒写发布事实

版本已成立后，健康投影、唤醒或维护提示失败只形成未完反应责任，不把发布报告成未发生、不改旧版、不重做源发布。反应方在可靠承接前不让责任无人保管，重复告知不产生新版本。需要通知时只交获准披露的来源/状态，通知受理、送达、已读和供应状态分别成立；通知失败不解除风险或重抓源数据。验证义务 V-CA12。

### INV-CA13 未知按原操作查询并只接续未完部分

超时、断连、响应丢失或一次查询失败不证明初始化/发布没发生。保留原日历、候选、提交关联、已确认部分、未知范围和下一处置拥有者，先查询或对账原发布事实，不能重铸版本、回退旧数据或重复制造独立更新。已确认发布只接续未完反应，仍未知继续保管，不伪造成功或确定失败；恢复再次中断不丢已确认部分。在必要资格、介质、提供者及调度前提成立时继续未完责任或报告明确受阻，不承诺上游永远可用。验证义务 V-CA13。

### INV-CA14 日历更新与业务采用分责

消费者选择切换不改已有 Schedule 保存的日历身份；新版本发布不接受、取消、移动或改写已有 Job 的采用内容与来源，也不生成另一份重复 Job。日历提供指定/当前依据及真实失败；日程拥有最新校验与候选接受同一边界、已接受要求冻结、去重、等待/取消和补跑。供应恢复不证明漏过工作已做，查询或预算不成为 Job。验证义务 V-CA14。

### INV-CA15 取消只声明实际已阻止的效果

查询取消只影响本次计算。维护取消在提交前确认成立时阻止该次发布；已成立发布不因取消/停止/退出撤回。取消与提交竞争或效果不可确认时沿原操作查询，不能把取消请求受理当没有发布。抓取、存储或通知已经发生的效果如实保留，不能据 disposer 声称逆转。对未完成物理停止、资源残留及晚到结果继续有归属。验证义务 V-CA15。

### INV-CA16 缓存与投影不成为权威

缓存以实际身份、不可变版本及影响结果的输入绑定，声明范围、失效与可重建来源；租户输入/选择保留租户隔离和当前读取资格。当前选择或版本变化不造成旧新数据混合，缓存重建不发布候选或改权威设置。目录/健康陈旧投影表明观察位置，不能以投影消失证明版本删除或以旧缓存掩盖查询故障。验证义务 V-CA16。

### INV-CA17 实例换代只撤自身贡献并保管业务责任

运行停止先处理新准入，再按原操作阶段排空、停止或可靠交接，不能删除注册就宣称业务完成。注册、监听、计时器、句柄和临时使用权有本实例拥有者，部分初始化失败仍收口；旧代际清理不删新实例、其他日历/租户或后续合法贡献。共享资源只释放自己的使用权，最终释放归真实资源拥有者。晚到结果回原身份，失效实例不重新发布入口。版本、待裁证据、失败事实及未完责任独立保管；清理失败报告实际残留。独立接口与 Cordis 集成分别验证，装配不提供业务授权、耐久、日期正确或可逆外部效果保证。验证义务 V-CA17。

### INV-CA18 健康与发行条件可观察且有明确政策

覆盖与知识截至分别显示，最近成功更新、连续失败、待裁候选及覆盖余量可观察；按每历有效政策在覆盖耗尽前告警。查询可用不证明持续供应健康，上游未及时发布也不成为猜日期许可。所声明发布物达到任一所含日历的严重数据新鲜度条件时不能发行，警告须显式声明；不能用一个全局固定天数替每历政策。政策或状态缺失/未知时不报通过，治理拥有者落实合法条件，不由技术提供者偷填默认阈值。验证义务 V-CA18。

| V-CA18 健康发行 | 仍可读旧覆盖但连续更新失败、覆盖临期、每历严重/警告条件、未知政策不通过，提示失败不清风险 | 供应治理、发布物 |

算法样例、模型、真实介质故障和组合验证分别有各自覆盖范围；单次回调、mock、结构检查或一次重启不能代替性质证据。自定义并发发布/装卸/交接机制须提供适用行为模型；若机制借新的共享可逆、交换或互不干扰性质省略控制，按手册提交相应证明，关键保证需满足机器检查门槛。本候选没有选择此类机制，也未声称已建立证明。

## 技术缺项与采用界线

Q-CA02 落实公开输入/结果/错误形状、日期及覆盖表示、算法和有界计算映射；Q-CA03 落实来源提供者、候选/发布存储、并发与耐久恢复；Q-CA04 落实既有设置/权限、供应治理政策、维护生命周期和精确 Cordis 集成。它们由对应技术/治理拥有者完成，不能改变上述产品含义或成为 Q-CA01 选 CAP 的前置。

阶段范围仍待负责人选择 CAP-CA01–CAP-CA09 与供应范围；此处完整行为候选不授予全部阶段支持、正式包准入、实现或接受。其他领域的具体规则仅消费其正式拥有者入口。日历提供可复核的日期依据，[日程协调者](../../../docs/domains/schedules-and-jobs/README.md#契约与验证导航)组合整体 Schedule 预览并保护 Job 接受，各事实拥有者维护原有权威。跨域组合由日程协调者及日历、执行、通知等参与方按[领域组合验证](../../../docs/domains/verification.md#组合性质与承担者)共同核对。本成员不接管跨域共同状态或自行造提交协调器。
