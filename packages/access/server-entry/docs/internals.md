# 服务端接入内部设计

行为以[成员行为规格](../SPEC.md)为准。结果含义以公开契约为准。

## 接缝

接入把字节读成治理消息，再把已通过协议检查的请求交给身份与授权的公开入口。它不持有登录表，也不把存储对象放进响应。

公开契约不依赖本成员。

## 验证与维护

改处理次序时只改本成员规格，并核对它没有改写公开契约的结果含义。

## 观察接入的责任选择候选

[行为规格的 #746 候选](../SPEC.md#观察脱离与重附着候选746)把观察组合放在服务端接入。它已承担公开请求到内部能力的转换，能够在登录与租户边界下，组合日志读取、目标查询与生产者观察。组合只需要公开值和端口，不要求 Agent 实例仍存活，也不让 Model 认识会话或公开连接。

Session 也能定位自己的日志，但由它承担观察重附着会把公开观察者的连接、刷新和生产者订阅带入工作治理。Agent 具有首次调用上下文，但由它承担会让重附着依赖可被重装配的实例，与无 Agent 重附着的要求冲突。因此候选不增加独立转发能力，由接入承担必要组合，Session 与 Agent 保留原责任。

| 事实或决定 | 轴与拥有者 | 接入的处置 |
| --- | --- | --- |
| 谁在观察、代哪个租户行事 | 身份与主体签发，identity 与获授权接入 | 消费登录识别，按已有关系签发主体，显式传 Access |
| 哪些日志已提交、调用引用来自哪里 | 工作事实，Session | 只读公开日志中的稳定引用，不维护第二份业务事实 |
| 是否可读日志、调用与生产者内容 | 授权，各实际受保护端口 | 保持各边界核权与失败，引用不作凭据 |
| 调用当前状态和发布目标 | 调用与发布，Model | 按 current 的同边界结果选目标，不推断业务结局 |
| 怎样取得快照与增量 | 内容观察，生产者 | 消费原观察端口，不补造 replay 或跨 ref cursor |
| 何时刷新、忽略旧响应并释放观察资源 | 观察组合，候选 server-entry | 有界刷新，隔离迟到响应，脱离时取消本地观察 |
| 公开订阅形状与连接寿命 | 公开协议，public-contract | 交接缺项，不在本成员新增协议 |
| Agent 的推进与业务调用寿命 | 推进归 Agent，调用归 Model 或 Tool | 观察不控制工作，Agent 不在重附着链路 |

实现时，接入只需为每次观察保留当前选择、查询先后关系及本地资源所有权。这些都是可丢弃的观察状态，不能成为调用事实或权限缓存。旧 ref 失效、新 ref 快照失败与刷新耗尽分别保留原失败和最后已确认事实，不能把任一局部成功记成整条观察已恢复。具体策略与可取消接口待后继公开协议和实现确定。

本候选须由 PanQiWei 本人接受。它不证明网络恢复、跨进程观察连续或撤权后的运行行为。
