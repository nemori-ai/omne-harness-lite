# Access

## 总体架构

接入层回答一件事：客户端和服务端怎样接。两端各是一棵 Cordis 树，中间只有一条连接。

| 成员                     | 回答的问题                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| `public-contract`        | 两端共用的纯数据：消息的外层、对外结果的词汇、一份协议契约长什么样；三组现有消息的编解码       |
| `server-entry`           | 服务端的入口：管道、登记表、观察中枢；现有的治理、会话与 HITL 三个位置                         |
| `access-cordis-contract` | 领域的接入插件用什么服务把协议挂上登记表；管道向身份要的端口                                   |
| `sdk`                    | 客户端怎样按一份协议契约发出调用与观察：协议客户端核心与传输；三个现有位置的客户端与 HTTP 适配 |
| `client-assembly`        | 客户端的装配：连接、服务端现在挂着哪些协议、每个协议一个协议客户端                             |

一次调用这样走：界面模块调协议客户端的方法，协议客户端经连接把消息交给入口，入口的管道建立身份后在登记表里找到处理函数，处理函数在领域的接入插件里，它调领域的公开入口。调用是一问一答，观察是一条事件流。入口自己挂一个内置协议 `access/v1`，它只有一个观察：现在挂着哪些协议。客户端的连接一直订阅它，协议客户端随它长出与收回。

治理、会话与 HITL 三个现有位置各有固定路径与手写的消息组，不经过登记表；它们与管道共用状态码表、在途预算与读消息体的函数。

## 领域边界

接入层拥有消息怎样在两端之间走：外层的形状，身份怎样随每次调用带上，结果用哪些词，判断按什么次序，一个协议现在挂没挂着，结果不知道时两端怎样对待它。

接入层不拥有任何领域的含义。入口与界面外壳不认识任何领域。对客户端开放的三样，协议契约、接入插件、协议客户端与界面模块，都是领域带来的；开不开放由应用的装配决定。登录、主体与资格归身份与授权；会话、Run 与日志归 Session；卡片与答复归人工介入；调用状态与内容流归 Model。接入只核「这个调用者是谁」，不判断他能做什么。

「挂没挂着」和「许不许用」是两件事。入口放行不等于允许。

## 心智模型

服务端是事实的权威，客户端只有投影和缓存。

协议客户端跟着协议走：服务端把一个协议挂上，客户端这边它的协议客户端就长出来；撤了就收回，收回之后它的每个方法都答不可用。

入口是一个只会查表的门卫。它认得每个调用者是谁，认得每个协议挂没挂着，认不得任何业务；认出来的主体原样交给领域，许不许由领域判断。门卫对所有「认不出来」给出一模一样的拒绝，所以调用者从拒绝里试不出对象在不在。

拿这几条量一个设计：客户端里一个离开服务端就没法重新得到的事实，是放错了地方；界面模块里一段处理连接、可用性或重发的代码，是做了协议客户端该做的事；入口里出现一个领域的名字，是把接入插件的事做进了门卫。最容易想错的三处：传输断了不等于没做，提交类的结果就是不知道；观察的取消只结束观察，不是业务控制；挂上不等于开放，开放由装配挑。

## 应然设计

### 一次问

一次问是一个消息号加一份字节。传输能证明一个字节也没发出时，同一份字节再送一次；仍没发出，答「不可用」。字节可能已经发出而没有可信的答复，答「不确定」，不再送。这两个答复只在本地产生，不写成成功，也不写成失败。

消息号只把答复对应到这一次发送，不是去重键，也不进入任何业务身份。只有带着同一消息号的答复才交给这次调用；没有消息号的协议拒绝不记到任何一次调用上。

### 读与写

每个操作在协议契约里标明是读还是写。

写可能在服务端留下效果。它的答复不论是什么，协议客户端都原样交给调用方，不替调用方再问。

读没有效果。读得到「不可用」「不确定」或「依据不可用」时，这只说明现在读不到。协议客户端按装配给它的策略等一会儿再问。再问是一次新的问，用新的消息号。

再问在这三种情形下停止，并把手里的答复交给调用方：策略答不再等；调用方中止了这次调用；这个协议被撤回。

等待在服务端的可用性视图来了新的一帧时提前结束：服务端回来了就立刻再读，不等到点。

策略由应用给。没有拿到策略的协议客户端，每个读只问一次。

### 判断次序

- 一份消息按固定次序处理，前一步给出终端结果就不做后面的步骤：协议读取（严格 JSON、版本、操作名、封闭字段与类型）；登录识别；行事租户；目标租户与主体；部署范围；领域判断。协议拒绝先于一切身份核验与业务读取，没有任何业务效果。
- 严格读取不接受注释、尾逗号与重复键。重复的版本字段不挑一个，整份消息是协议拒绝。服务端不协商版本，按请求的位置选读取方式，不按消息里的版本文本分派。
- 发起者只取登录证明认出的账号；消息体里的账号、组织与租户都是目标。裸账号标识、地址、旧连接与调用者自报的授权结果都不是登录。治理与会话位置的行事主体只在目标租户的账号等于识别出的账号时签发。
- 部署可以声明不提供某些操作：消息通过封闭字段检查之后立刻答「本阶段不提供」，不识别登录，不读取任何业务事实。声明不改变其余操作的结果、次序与披露。

### 对外结果

结果是一个封闭集合。调用者只能依赖结果名与该结果列出的正文；内部诊断可以更细，但不进 SDK 或错误文本。每个结果答一句「调用者能知道什么」，也写明「不能由它推出什么」：

| 结果                 | 调用者可以知道的                       | 不能从该结果推出的                             |
| -------------------- | -------------------------------------- | ---------------------------------------------- |
| `denied`             | 本次不获准                             | 是禁止、无权、登录失效、跨租户，还是对象不存在 |
| `not-visible`        | 与目标不存在同一表现                   | 目标是否存在、属于谁                           |
| `basis-unavailable`  | 现在不能得出允许                       | 已知无权或已知冲突                             |
| `unknown`            | 提交结果没有认回                       | 效果没有发生，或可以安全地自动再做一次         |
| `not-committed`      | 原操作确定没有提交，可以用原标识再发起 | 再发起一定成功                                 |
| `need-decision`      | 要等原决定请求的一次人的答复           | 等待已经批准、拒绝或将超时批准                 |
| `stage-not-provided` | 本阶段或本部署不提供该操作             | 主体是否存在、登录是否有效                     |
| `protocol-rejected`  | 消息不被接受                           | 任何业务事实                                   |

六种结果的正文永远是空对象：`denied`、`protocol-rejected`、`basis-unavailable`、`unknown`、`uniform-auth-failure`、`stage-not-provided`。领域在类型上给不了它们字段。

### 拒绝一致与不披露

- 凡是没能确立调用者是谁、行事租户不符、对象不存在或属于别的租户、主体没有资格，对外都是同一份 `denied`，响应除消息号外逐字节相同，头也相同。
- 状态码只由结果决定，与对象是否存在无关；不同结果可以共用一个状态码，调用者不由状态码推出结果，也不由状态码决定是否再送。
- 秘密只出现在请求里：登录证明、凭据与秘密设置值不进响应、诊断、日志或错误文本。诊断只带代码、路径、协议名与操作名，不带头的值与消息体。

### 未知、再送与认回

- 连接断开、超时与响应丢失使调用者本地保持未知。它不是成功，也不是没有发生。
- 调用者在首次发送前生成业务标识（创建、受理、控制、答复各一种），重试同一意图时保持不变；SDK 不替调用者换它们，客户端也不填写服务端派生的身份。
- 未知之后，调用者用同一组标识原样再送（同内容得到原结果）或用对应的查询认回。确认 `not-committed` 之前，不换新标识重做同一意图。同一标识对应不同内容是 `conflict`，响应不含原内容。
- 存储给不出排除证明时，查询答 `unknown`，不答 `not-committed`。只读操作没有 `unknown`，原样再送即可。
- 服务端派生的业务身份是确定性的：同一意图在崩溃前后、重连之后得到同一身份。创建与受理按租户与标识派生；中断另含登录，因为不同登录不共享中断回执；HITL 答复按租户与答复标识派生，不含登录，换一份登录原样再送仍认回同一次提交。派生的算法归各领域，接入调用它，不另写。
- 客户端不缓存准入允许、登录证明或凭据。清掉投影不把 `unknown` 变成成功或没有发生。

### 名单与分页

- 一份治理名单要么完整，要么整份不可用：成功时数组给出全部当前项并标明完整；任一项读取时判定不了，整份答 `basis-unavailable`。不丢项，不把不可用改成空名单。
- 分页读取的空页不表示读完；读完由显式的标记给出。游标原样交回，不是读取资格，每一页都重新核验当前资格；游标错域、失效或被篡改是 `invalid`。

### 会话创建与设置项

- 公开的定义名只解析成会话创建里公开消息不带的部分：缺省模式与常驻能力名。解析不了的名字是 `invalid`，不给缺省定义。常驻能力只给名字，它的权威、形状与键在创建时由部署的工具来源解析，解析不了的名字使创建失败。缺省模式的采用摘要覆盖模式，改一个缺省也改变创建材料。
- 映射给出的定义缺初始模型选择，是部署的缺口，不是调用者消息的缺陷：创建在调用 Session 之前就拒绝，对外答 Session 不可用的线上结果。
- 设置项只给名字、不给类别时，名字必须在行事租户看得见的资产里恰指一个；多于一个是 `conflict`。

### 会话中断

- 取消一个 Run 与停止一次调用是 Session 中断操作的线上形式，业务事实归 Session。`requested` 表示意图与传播责任已保存，不表示模型流、进程或工具效果已经停止；`ended` 携带目标原有的结局与可追溯来源。已保存的原答案每次重试原样返回，不因对象后来结束而改写。
- 两个中断操作共用控制标识的唯一范围。每次重试都重新核验访问资格，撤权在下一次核验生效。
- 停止一次 Tool 调用在访问裁定之后、会话存在核对之前答 `unsupported`，不写任何记录，与会话是否存在、标识是否用过无关；重新开放属于 Session 的契约修订。

### 会话诊断页

- 诊断页是一个会话的只读组合视图：Session 历史给出 Run 的骨架与调用登记，Agent 给出 Run 怎样结束，Model 与 Tool 给出每次调用实际发生了什么。每个来源各自核资格，一个来源的拒绝或缺失不改变结果，只成为一条带原因的缺口。
- 缺记录时值是 `unknown` 并带原因，不是「没有发生」。来源给出闭合集合之外的值时写 `unknown`，不写成集合里的某个值。页里不带任何自由文本：供应商错误原文、诊断文本、消息正文与工具参数都不进。
- 自新往旧收集 Run：两个 `run.started` 之间的条目属于较新的那个 Run，Run 在自己的 `run.started` 到来时闭合。带 Run 过滤时，扫描在那个 Run 闭合时完成；不带过滤时扫到配置的 Run 个数为止，还有没读的条目或页就有下一页，从收集停下的 Run 之前接着读。只有游标为空的第一次读带 Run 过滤与页大小，续页只带游标。
- 游标封存第一页读到的 Session 上界：续页向更老的条目读，看不到上界之后追加的条目，整次扫描的依据是第一页的上界。
- 一次 Tool 调用在会话日志里是同一消费的两条 `call.bound`：没有生产者的意图登记，与随后的关联。诊断页把它们当一个调用，值取带生产者的那条，位置取第一条登记。
- 一个 Run 的执行事实按拥有者归属：消费等于某个已投影调用的消费，或没有消费而生产者是某个已投影调用登记的生产者，属于那个调用，按调用的位置记；其余属于 Run。事实与它所指的 `call.bound` 在日志里谁先谁后不影响归属。消费在观察路径上写在事实顶层，释放事实的消费写在 `fact` 之下，来自生产者的执行只带 `fact.producer`。
- 计数是封闭的：`run.attempt-released` 的原因不在 Session 契约的集合之内，或 `call.execution-fact` 没有种类，都不计数，不写成别的值。
- 一次调用各次派发的账：读派发记录失败时每笔账都是 `unknown` 并带这次读的原因，另给这次调用一条缺口；记录里没有账的是 `not-recorded`；记录没列出的派发是 `not-found`。来源答 `invalid` 落在携带引用的字段上，读成所有者不认这个引用；落在别的字段上，是本投影自己的请求被拒，只报成所有者没有应答。
- 三项配置（读哪几种条目、一页最多几个 Run、一个 Run 最多几次调用进扇出）同时给出；没给时这个操作答 `basis-unavailable`。Agent、Model、Tool 的某个读口缺席时，投影写对应的缺口，原因是 `unsupported`。

### 会话观察

- 观察是只读视图，不提交会话事实，不控制业务工作。对象是该会话最新登记的、用途为主调用的 Model 调用，随新登记切换；每个新目标与每次重新同步各从一份快照开始，之后只发同一目标的增量。
- 建立成功只表示观察者通过了该会话的读取资格，不表示已有可观察目标。每帧发出之前按原端口重新核对资格。撤权与登录失效都以 `denied` 结束。
- 第一帧是状态或结束；状态先于一切快照、增量、缺口与刷新。帧带从 1 起单调递增的序号，串行发送。
- 接入从会话日志的稳定调用引用定位目标，再向 Model 查当前目标；日志不保存瞬时流引用。查询没有可达性租约：旧目标失效就结束旧观察，从稳定引用重新定位，不沿用旧游标或旧快照基线。切换目标或结束之后迟到的旧快照与旧增量被丢弃。
- 没有目标、目标流结束或生产者观察中断时，接入按有界的刷新策略重定位或重新观察，每轮先发一帧刷新；上界耗尽时以 `refresh-exhausted` 结束，明确交回没有建立观察的事实，不改写调用结局。刷新的间隔、退避、次数与期限是部署配置，默认值只是初值，不做无等待的循环。
- 本地帧队列超出上界时以 `capacity` 结束，不丢弃中间帧冒充连续。名额按登录与按实例各有上界，满了答 `basis-unavailable`。
- 观察的取消只结束观察：它不取消 Model 或 Tool 调用，不触发 Session 推进，不改变结果保管。连接关闭等价于取消。同一登录在同一会话用同一观察标识再次建立时，替换旧观察并给它 `observer-replaced`。重新连接是新的建立，得到新快照；没有跨连接的续接游标。
- 观察失败、目标为空、断线都不能成为重发原调用的依据。

### HITL 位置

- 列卡与读卡的结果是人工介入的查询投影，不是第二份决定权威。一张卡只有一个有效处理：会话入口与待办池读同一张卡、经同一个操作提交，两次并发提交只有一个成立。
- 先核资格，再查原提交的回执：撤权之后原样再送与认回都得到 `denied`，不披露原结果。答复回到哪里由人工介入按原等待决定，客户端不选择。
- HITL 入口面缺席时，HITL 位置的四个操作都答 `stage-not-provided`；给了入口面，配置必须有 HITL 位置引用。
- 入口主体的持有者只在同一次请求的登录识别成功、且目标租户的账号等于识别出的账号之后才被调用，只交出租户与账号，不交出登录。它给出的主体必须是这个租户的入口主体，否则不能拿它调用 HITL。

### 登记表与撤下

- 登记表不认识任何领域：表项按协议名与主版本存，处理函数只当函数调用。同名同主版本的协议任一时刻至多挂着一份；重复挂上报装配错误，已挂的那份不动。
- 「查表并登记成在途」与「读快照并登记订阅者」各是一个同步段，中间不让出执行权。
- 撤下是一个同步段：移除表项、给这份贡献的在途工作发中止、修订号加一、回调订阅者。撤下完成由这份贡献最后一个在途工作离开触发；插件的卸载等它完成。
- 挂上是挂上它的插件作用域上的一个效应，卸载即撤下，接入插件不写撤下的代码。领域服务暂时不在不等于撤下：处理函数每次调用现取领域服务，取不到答 `basis-unavailable`，协议仍挂着。

### 管道

- 新地址是 `/api/<协议名>/v<主版本>/<名字>`。管道依次判：路径合文法、方法、`Host`、`Content-Type`、协议挂着且名字在契约里、在途预算、消息号、身份、按契约的上限读消息体并按契约的编解码读成类型。前一步给出答复就停。
- 未知的操作与没有身份的调用在读消息体之前就被答复；这类答复与每一个 `denied` 都关闭连接，没有身份的调用者不能让服务端读入任意多的数据。
- 身份按契约的身份一栏：不要身份的不读身份头，主体为空；要登录的核验 `Authorization` 头里的登录证明；要行事租户的再用 `Omne-Acting-Tenant` 头签发主体。身份结果不缓存，每次调用都重新识别。管道不读主体里的字段，也不看消息体里的租户，原样交给领域。
- 在等身份端口与读消息体时，同时等撤下的中止与调用者断开：中止答 `basis-unavailable`，断开不答，都不调处理函数。处理函数开始之后调用者断开，不给处理函数发中止，它照常跑完。
- 新地址只在注册表、身份端口、宽限与两个积压上限全部给出时开启；全缺时 `/api/...` 答 404。开启时入口在启动时把内置协议挂上注册表，停止时最后一个撤下。

### 收场

- 处理函数返回结果集里的结果且写得出，原样答复。返回集外的结果、写不出、抛出、或中止之后过了宽限还没返回时，答复只由操作的读写一栏决定：读答 `basis-unavailable`，写答 `unknown`，因为处理函数开始之后提交可能已经发生。收场开始时已中止则不调处理函数，答 `basis-unavailable`。
- 宽限只在中止之后计时，必填，由装配给出。宽限之后迟到的结果丢弃，不写第二次答复。每种情形都先答复，再离开在途集合恰好一次。
- 成功的业务访问在写出答复之后报告，不等报告结束；报告失败不改答复。

### 观察中枢

- 先占名额再附着：每实例一个上限，要登录的观察另计入它那个登录的上限。名额满了答 `basis-unavailable`。同一键（登录证明、地址与消息号）已有观察时，旧的以 `observer-replaced` 结束。
- 占名额时「够不够」的判定与计数加一在同一个同步段里，两个一起通过读取资格的请求不会同时越过上限；被这一次替换的旧观察不占名额。不要登录的观察没有可认的观察者，它的键只属于自己，不会被替换。
- 帧来源先决定建不建立；它的拒绝、抛出、撤下与调用者断开都不建立观察并还回名额。帧来源拿到的是主体，不是「已允许」。
- 中枢只对入口自己的可用性来源按写出的节奏拉帧：上一帧离开写队列才拉下一帧，积压留在帧来源。领域的观察一有帧就被拉取，积压碰到字节上限即结束。
- 每个观察恰好离开一次：结束帧写出之后，或等了宽限还写不出去、断开连接之后。每一种结束都中止给帧来源的信号。帧来源给出契约之外的结束原因、抛出或给出不合契约的帧，以 `unavailable` 结束。
- 每个心跳间隔复核一次登录；登录无效以 `denied` 结束，依据不可用以 `unavailable` 结束。连续一个心跳间隔没有写出字节时写一行心跳注释。

### 可用性

- 内置协议 `access/v1` 只有一个观察 `availability`，不要登录：哪些协议挂着不是秘密，登录本身也是某个协议的操作。它对所有调用者给出同样的字节，不计入每登录的名额。入口在监听的整段时间里都挂着它。
- 订阅的第一帧是快照；之后每次挂上或撤下排一帧变化，变化的基础是修订号减一。一个订阅者积压的变化超过上限时，丢掉它排着的全部变化，下一帧改发完整快照。断线后重新订阅从快照开始。
- 客户端收到基础对不上的变化帧时不应用，改为重新订阅。

### 协议契约与编解码

- 一份协议契约写明名字、主版本、操作与观察。操作写明身份一栏、读写一栏、消息体上限的名字、消息体的编解码与每个结果的正文编解码；观察另写建立值、帧与它自己的结束原因。
- 契约是封闭的：结果集之外的结果、契约之外的栏、缺少成功、给固定结果写编解码，都编译失败。`defineProtocol` 按身份一栏与读写一栏给每个操作补上管道会替领域答的结果；写操作的类型上就有 `unknown`。
- 规则是编解码与类型的唯一来源。读取是严格的，不给出部分读到的值；读写都不因输入不合规而抛出。数值上限只写名字，数值归部署配置。
- 协议契约是纯数据与纯函数，不含 Cordis、存储或服务端的类型；两端用同一份契约。
- 契约里没有叫 `observe` 的操作：客户端按操作名给成员，观察都放在 `observe` 之下，同名的操作会被盖住。`defineProtocol` 拒绝这个名字；不经它构造的契约在客户端核心处被拒。
- 联合规则的各选项互不相交：第一个转换成功的选项胜出，本地值不记录命中了哪个选项。

### 客户端

- 协议客户端核心的结果只有契约的结果，加上两种本地结果「不可用」与「不确定」。答复的结果不认识或正文不合契约是「不确定」。传输负责带上身份，核心看不到登录证明。浏览器里的 `fetch` 给不出「一个字节没发出」的证明，所以在浏览器里失败一律是「不确定」。
- 观察以异步生成器给出帧，结束方式在返回值里：契约里的原因、建立被拒、没发出、不确定、调用方中止。
- 连接一直跟着可用性；观察断了按退避重新订阅，视图不动，协议客户端不收回。协议开放而树上没有它的协议客户端时记一条诊断。
- 协议撤下时，协议客户端先标记已收回再注销服务；之后的调用（含外部留着的旧句柄）在本地答不可用，观察立刻结束；在途调用没发出的答不可用，可能发出的答不确定。换登录或换租户不改变协议客户端。
- 已经建立的观察连接断开后，客户端不自动重连，也不自动发出任何公开操作。

### HTTP 承载

- 承载是本机回环上的 HTTP/1.1：监听地址只能是 `127.0.0.1`，配置给出其他地址时启动失败，不静默改写。`Host` 只接受 `127.0.0.1` 或 `localhost`，挡住借用本机服务的重绑定页面。不发 CORS 头，不跟随重定向。
- 在读消息体之前按路径选择消息体上限，按实际读到的字节计数，不信任 `Content-Length`；超限停止读取并关闭连接。路径、方法、头的失败在读消息之前给出，不调用任何领域。
- 在途请求有一个与管道共用的预算，在读消息体之前预留，用尽时答空正文的 429 并关闭连接；断连不撤销已受理的业务调用。
- 依赖抛出或不可达时，对外结果按调用的种类：读取类依赖答 `basis-unavailable`；提交类调用开始之后答 `unknown`；结果集里没有线上 `unknown` 的提交类操作写出空正文的 500 并关闭连接，表示没有可信答复。接入不把这些情况写成 `denied`、`succeeded` 或 `basis-unavailable`。

## 原则与约束

- 「现在读不到」是会变的状态，不是结局。对它的再问只在协议客户端这一层做，各个界面模块不各写一遍。
- 结果不知道就是不知道。写类操作的未知效果不能靠再发一次去重做。
- 协议客户端核心要能在浏览器里用：它只依赖共同契约与它自己，策略的判定从设置里交进来。
- 客户端一侧的成员只依赖共同契约、协议客户端核心与 Cordis。
- 领域不认识接入层；接入插件调领域的公开入口，不反过来。入口、管道、登记表与观察中枢不导入任何领域。
- 身份每次调用显式带上；入口的身份检查不替代领域的授权判断。
- 策略类的数值（宽限、刷新、名额、帧队列、积压、消息体上限）都是装配给的配置，成员里不写初值。
- 自定义的登记、撤下与可用性协议有形式模型（`server-entry/verification/models/`）；有限检查的通过不等于实现符合，实现由对应的契约测试核对。
