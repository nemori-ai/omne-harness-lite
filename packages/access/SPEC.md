# Access

## 总体架构

接入层回答一件事：客户端和服务端怎样接。两端各是一棵 Cordis 树，中间只有一条连接。

| 成员                     | 回答的问题                                                         |
| ------------------------ | ------------------------------------------------------------------ |
| `public-contract`        | 两端共用的纯数据：消息的外层、对外结果的词汇、一份协议契约长什么样 |
| `server-entry`           | 服务端的入口：管道、登记表、观察中枢                               |
| `access-cordis-contract` | 领域的接入插件用什么服务把协议挂上登记表                           |
| `sdk`                    | 客户端怎样按一份协议契约发出调用与观察：协议客户端核心与传输       |
| `client-assembly`        | 客户端的装配：连接、服务端现在挂着哪些协议、每个协议一个协议客户端 |

一次调用这样走：界面模块调协议客户端的方法，协议客户端经连接把消息交给入口，入口的管道建立身份后在登记表里找到处理函数，处理函数在领域的接入插件里，它调领域的公开入口。调用是一问一答，观察是一条事件流。

## 领域边界

接入层拥有消息怎样在两端之间走：外层的形状，身份怎样随每次调用带上，结果用哪些词，一个协议现在挂没挂着。

接入层不拥有任何领域的含义。入口与界面外壳不认识任何领域。对客户端开放的三样，协议契约、接入插件、协议客户端与界面模块，都是领域带来的；开不开放由应用的装配决定。

「挂没挂着」和「许不许用」是两件事。入口放行不等于允许。

## 心智模型

服务端是事实的权威，客户端只有投影和缓存。

协议客户端跟着协议走：服务端把一个协议挂上，客户端这边它的协议客户端就长出来；撤了就收回，收回之后它的每个方法都答不可用。

拿这两条量一个设计：客户端里一个离开服务端就没法重新得到的事实，是放错了地方；界面模块里一段处理连接、可用性或重发的代码，是做了协议客户端该做的事。

## 应然设计

### 一次问

一次问是一个消息号加一份字节。传输能证明一个字节也没发出时，同一份字节再送一次；仍没发出，答「不可用」。字节可能已经发出而没有可信的答复，答「不确定」，不再送。这两个答复只在本地产生，不写成成功，也不写成失败。

### 读与写

每个操作在协议契约里标明是读还是写。

写可能在服务端留下效果。它的答复不论是什么，协议客户端都原样交给调用方，不替调用方再问。

读没有效果。读得到「不可用」「不确定」或「依据不可用」时，这只说明现在读不到。协议客户端按装配给它的策略等一会儿再问。再问是一次新的问，用新的消息号。

再问在这三种情形下停止，并把手里的答复交给调用方：策略答不再等；调用方中止了这次调用；这个协议被撤回。

等待在服务端的可用性视图来了新的一帧时提前结束：服务端回来了就立刻再读，不等到点。

策略由应用给。没有拿到策略的协议客户端，每个读只问一次。

## 原则与约束

- 「现在读不到」是会变的状态，不是结局。对它的再问只在协议客户端这一层做，各个界面模块不各写一遍。
- 结果不知道就是不知道。写类操作的未知效果不能靠再发一次去重做。
- 协议客户端核心要能在浏览器里用：它只依赖共同契约与它自己，策略的判定从设置里交进来。
- 客户端一侧的成员只依赖共同契约、协议客户端核心与 Cordis。
- 领域不认识接入层；接入插件调领域的公开入口，不反过来。

## 不变式

| 编号 | 永远成立的性质                                                                 | 违反的后果                     | 由什么守                                                                                                  |
| ---- | ------------------------------------------------------------------------------ | ------------------------------ | --------------------------------------------------------------------------------------------------------- |
| AC-1 | 协议客户端不重复发出写类操作；唯一的例外是可证明一个字节也没发出时的那一次再送 | 一个效果发生两次               | `sdk` 的成员用例                                                                                          |
| AC-2 | 读类操作的再问有上界：策略答不再等，就把手里的答复交出去                       | 一个读永远不返回               | `sdk` 的成员用例                                                                                          |
| AC-3 | 协议被撤回之后，它的协议客户端不再发出任何调用，等待中的再问随即结束           | 对一个已经撤掉的协议继续发消息 | `client-assembly` 的成员用例                                                                              |
| AC-4 | 协议客户端核心与客户端一侧的成员不依赖服务端的任何成员                         | 浏览器里的代码带进服务端的实现 | 依赖检查 `pnpm run lint:deps` 的 `sdk-core-stays-portable` 与 `client-side-only-core-contract-and-cordis` |
