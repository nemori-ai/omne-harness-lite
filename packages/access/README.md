# 系统接入能力组

本组维护完整 Harness 的公开接入工程关系。依据为[系统分层](../../docs/architecture/layers-and-dependencies.md)和[目标包组织](../../docs/package-organization.md#sdk与系统接入)。三个子目录目前只有文档目标，均非 workspace 成员。

## 责任与范围

公开契约承接两端共同的操作、数据、事件、错误与边界行为。SDK 承接客户端统一入口。服务端接入承接协议输入、身份材料、能力路由和结果交付。业务含义与权威事实仍归各能力。传输方式、首批操作和客户端环境仍待细化。

## 成员与依赖

| 文档目标 | 预期消费者和依赖 | 下一入口 |
| --- | --- | --- |
| 公开契约 | SDK 与服务端接入共同消费；只引用原能力公开定义 | [public-contract](public-contract/README.md) |
| SDK | 客户端应用消费；依赖公开契约与平台适配 | [sdk](sdk/README.md) |
| 服务端接入 | 应用装配使用；依赖公开契约与能力公开接口 | [server-entry](server-entry/README.md) |

SDK 不依赖服务端私有实现、存储或 Cordis 装配树。业务能力不反向依赖 SDK 或传输处理器。独立能力从自身公开入口消费。

## 关键协作

客户端经 SDK 表达操作并处理结果；服务端接入按同一契约解释输入和输出。入口身份校验不替代能力授权。连接中断或结果未知时，不得推断动作未执行。精确受理、取消、错误及订阅协议由各成员契约拥有者承接。

## 组合验证

公开契约、SDK、服务端接入及实际客户端消费者共同核对两端行为、身份隔离、故障和重连。还需验证 SDK 的源码与发布产物依赖闭包。检查依据见[系统分层的偏离检查](../../docs/architecture/layers-and-dependencies.md#偏离检查与维护责任)。当前没有执行资源或通过证据。

## 维护

改公开操作时，契约拥有者先确认业务拥有者与消费者，再同步 SDK、接入适配及验证。改传输或发布范围时核对实际应用与依赖闭包。组技术拥有者维护关系，成员契约拥有者维护精确行为，文档维护者核对导航与登记；长期个人负责人尚未具名。建包前按[成员文档规范](../../docs/member-documentation.md)和[开发指南](../../docs/development.md#创建和整改产品包)准入。文档落位不授予技术采用。
