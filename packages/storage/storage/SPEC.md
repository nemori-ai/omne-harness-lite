# 存储事务行为

目标位置是 `packages/storage/storage`。本目录只有目标文档，没有 workspace 包或运行入口。PanQiWei 于 2026-10-14 认可本规格的结果模型。本规格不关闭 [SQL-T01](../../../docs/architecture/deployment/infrastructure-policy.md#sql-t01)。已接受的系统行为仍以[数据与状态](../../../docs/architecture/data-and-state.md)为准。

## 参加者

调用方出示操作身份，并在结果未知时用同一身份查询。提交协调者登记参加者和组合版本。事实拥有者提供在 Worker 内执行的同步命令。存储提供者把一个事务域绑到一个数据库身份和一条写连接。

输入与去处、日程定义的完整更新、有效答复与原等待，都走同一次 `commit`。字段留在各自拥有者的命令数据里。本规格不按这三种业务分成三种请求。日历发布、通知送达、模型调用、工具效果和文件发送不在这次数据库提交里。原拥有者只有在观察到已提交回执之后，才执行那些外部效果。

## 操作身份

操作身份至少包含租户、事务域、操作、协议版本和这一次操作的键。身份参数没有默认租户或默认账号。

## 登记、提交与查询

`registerCombination` 把一组参加者名字和一个组合版本登记到一个事务域。提供者按该事务域保存这次登记。协调者进程重启后，登记仍然有效。同路径、同库或同一个 Cordis Context 不会因此变成同一事务。新写者在旧写代际被排除之前不能开始。

`commit` 接收该身份、已登记的组合版本，以及只含版本化数据的命令。命令里没有闭包、数据库句柄或 Context。组合未登记，或命令点名的参加者不在该组合里，调用在受理前拒绝，不写回执，也不叫已回滚。同键且输入摘要相同，返回已保存的回执，不再执行命令。同键且输入摘要不同，返回冲突和已有回执。摘要由提供者按该协议版本公布的规范编码计算，调用方不能自造摘要。更换编码或算法必须更换协议版本。已受理但调用方没有观察到回执时，结果是未知。断开、超时、Worker 退出和取消观察都是未知。

`query` 用原来的身份读取。它能返回已提交回执、明确回滚回执、未知，或未提交。未提交只能由提供者内部构造，并且必须带上五项证明：旧写代际已排除、旧事务已终止、数据库恢复已完成、权威读取已成功、该操作不在其他受理队列。调用方不能自己造出未提交。缺任何一项时，查询仍返回未知。

持久回执只有已提交和明确回滚两种。`commit` 不能返回未提交。

| 操作 | 可以返回的结果 |
| --- | --- |
| `registerCombination` | 登记已保存。名字或版本缺失时拒绝，不写回执 |
| `commit` | 已提交回执、明确回滚回执、未知、键冲突和已有回执、受理前拒绝 |
| `query` | 已提交回执、明确回滚回执、未知、未提交 |

受理前拒绝没有回执。键冲突必须带上已有回执。未提交只出现在 `query`。回执本身不新建 Run，也不发送通知。原拥有者可以在看到已提交回执之后另行执行这些动作。

## 提供者义务

SQLite 提供者使用专用 Worker 里的 `node:sqlite`。基线是 Node 24.21.0 内嵌的 SQLite 3.53.4，路线见[技术基础](../../../docs/architecture/technical-foundations.md#共同技术选择)。一个事务域一条写连接，命令在该连接的 `BEGIN IMMEDIATE` 中执行。`WAL`、`FULL` 和 `foreign_keys` 逐连接读回。Kysely 只构造查询和辅助迁移，不代替这次提交。`node:sqlite` 不承诺用 AbortSignal 打断正在执行的 SQL。需要原子的迁移必须让 DDL、数据和迁移标记在同一连接事务里一起回滚。事务外步骤单独写明中断后如何重入。`FULL` 和普通进程终止不是断电证据。

PostgreSQL 使用独立的 `pg` 与 Kysely 事务租约，不进入 SQLite Worker。它可以提供已提交、明确回滚、未知和按原身份查询。它不自动获得 SQLite 的单写连接、`BEGIN IMMEDIATE`、WAL 读回或文件快照。跨库提交不是本契约。没有集群需求时不建立集群。

这些义务还没有各自的提供者成员。以后的提供者只补充自己的配置、资源和失败，不另写一套公共结果。

## 取消、预算与关闭

排队中的取消只撤下尚未开始的操作。取消观察只释放观察方，原操作仍有结果拥有者。运行中的强制终止不在 `node:sqlite` 路线上承诺。改用已经验证的 interrupt 或独立进程之后，仍然按原身份认回提交。操作、分页、事务大小、锁等待和维护必须有有限上限。上限由提供者声明。锁等待到期是未知，不是已回滚。关闭时先停止新的准入，确认在途读取、语句、备份和消息的责任，再观察连接关闭和 Worker 退出。关闭不能收回已经发出的外部效果。

## 验证义务与未覆盖

后续验证至少覆盖这些场景。租户不同的身份不能读到对方的回执。两个参加者的事实要么同时在已提交回执里，要么都不在。同键同输入返回第一份回执。同键不同输入返回冲突。提交已经完成、响应尚未回到调用方时，查询返回已提交。旧写代际尚未排除时，新写者不能开始，查询也不能返回未提交。需要原子的迁移在后续步骤失败时，DDL、数据和迁移标记一起回到迁移前。排空失败时不报告关闭完成。断电耐久只在有相应故障证据时声明。

本次没有可执行探针。通知运输、真实 PostgreSQL 集群和本机临时输出不在这组证据里。进程重启不能替代断电耐久证据。
