# 存储

## 总体架构

存储包组回答一个问题：几个领域各自拥有的事实，怎样在一次提交里一起成立或一起不成立；结果不知道时，怎样按原来的那次操作认回。它也回答两个附属问题：读怎样拿到一个一致的快照，提供者怎样有界地占用线程、文件与内存。

| 成员              | 回答的问题                                                                                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sql-contract`    | 存储契约长什么样：操作身份、四个操作的结果、静态材料与清单、摘要算法、关闭控制口、Cordis 服务定义。另带内存替身与符合性套件。根入口与 `./worker` 不依赖 Cordis       |
| `sqlite-provider` | 在 SQLite 上怎样兑现契约：每个事务域一个文件与一个写 Worker，组提交，读 Worker 与读屏障，WAL 维护，有界的准入与关闭。纯工厂不依赖 Cordis，绑定插件从 `./cordis` 导出 |

调用方只学四个操作：`registerCombination`、`commit`、`query`、`read`。提交协调者先为一个事务域登记一组参加者与组合版本；各事实拥有者把自己的命令放进同一次 `commit`；提供者在 Worker 里按依赖顺序执行参加者模块，把事实、回执与响应证据在同一个事务里提交。答复是 `unknown` 时，调用方用同一身份 `query`。读只发具名 handler 与版本化输入，由读 Worker 在只读连接上执行。写连接、SQL 文本和写者代际都留在提供者里。

## 领域边界

存储拥有：操作身份的比较规则；提交、认回、查询与读的结果及其封闭的拒绝原因；输入摘要与清单摘要的算法；事务域与作用域的绑定；`_sql_` 前缀的提供者表（绑定、写代际、回执、响应证据、迁移标记、登记）；连接、Worker、快照、组调度与清理；关闭协议里提供者一侧的步骤与报告闩锁。

存储不拥有：任何业务事实的含义与 `facts` 的形状（各参加者拥有者）；领域表（各参加者拥有者）；授权与业务资格（调用 SQL 的领域入口与参加者）；租户目录的实现与目录文件（应用的会话存储组合）；外部效果与通知（原拥有者在看到已提交回执之后另做）；部署怎样选提供者（应用装配）。

存储只认通用角色：调用方、提交协调者、事实拥有者（参加者）、材料拥有者、装配、维护者。SQL 操作不携带主体，不认识调用它的是哪个领域。

本组声明、由别人实现的端口：

## 心智模型

存储是一个公证处，不是一个业务方。几个拥有者把各自的命令交到同一张桌上，公证处按事先登记好的参加者与依赖顺序宣读，全部成立就盖章存档，有一条明确不成立就整份退回并存一份退回记录。它不懂命令的内容，也不判断谁有资格；它只保证「一起成立」与「留下一份能认回的记录」。

存档记录就是认回的依据。调用方不需要先问「我交过没有」，直接交：公证处在执行之前认出同一身份、同一输入的早先记录，就不再执行，原样答那份记录并标明是认回。只有答复丢了或答「不知道」时，调用方才拿原身份来问。不知道就是不知道：环境故障、写锁超时、提交结果不确定，一律答 `unknown`，不写成回滚，也不写成未提交；「确定没提交」要五项证明齐全才说。

最容易想错的四处。注入 `storage` 只是装配范围，不是访问控制。另一作用域看到的和「什么都没有」完全一样。取消只结束观察，不撤回已经开始的语句。关闭、结束 Worker 与插件卸载都不是回滚：迟到完成的写照样持久，由原身份认回。

## 应然设计

### 身份与认回

- 操作身份有五个维度：作用域（`tenant` 或 `system`）、事务域、操作、协议版本、操作键，五项都由调用方给出。认回与 `identity_conflict` 比较完整的五项，再加认回声明 `recall`。另一作用域用相同操作键是另一个操作，既不认回本作用域的回执，也不与它冲突。空租户不是系统作用域；系统作用域取不到租户域，租户作用域也取不到系统域。
- 名字类字段是非空、合法 UTF-16、UTF-8 不超过 1024 字节的字符串；`transactionDomain` 另限 120 字节，因为它决定文件名；摘要类字段是 64 个小写十六进制字符。违反时 `commit` 与 `registerCombination` 答 `field_missing`，`query` 答 `unknown`，`read` 答 `invalid`。
- 新提交只用协议 2。协议 1 的 `commit` 答 `unsupported_protocol`；协议 1 的输入摘要只为认回旧回执保留定义。
- 认回在提交时做。`commit` 的答复带 `recalled`：提供者在执行之前认出同一身份、同一输入的早先回执时，不执行任何命令，答那份回执并标 `true`；本次调用执行出来的回执标 `false`。同一组里同一身份的几个调用只有一个被执行，其余答同一份回执并标 `true`。标记属于答复，不属于保存的回执。所以调用方直接提交，只有答复是 `unknown` 时才在再次发送之前 `query`。
- 同一身份配到不同输入摘要，答 `identity_conflict` 并带已有回执，不执行。
- 身份可以声明 `recall: 'never'`：没有调用方会认回这个操作。提供者不读也不写它的回执；同身份再提交时命令再执行一次，输入不同也不冲突；`query` 答 `not_recallable`；回滚之后不写回滚回执。这类提交的参加者必须自身幂等，认回由调用方用自己的事实完成。不能用自己的事实认回的操作不用这个声明。

### 摘要与材料

- 协议 2 的输入摘要是 `{ scope, combinationVersion, manifestDigest, commands }` 的 RFC 8785 规范文本的 UTF-8 字节的 SHA-256，命令按 `participant` 的 UTF-16 码元升序排列。调用方不传摘要。改变编码就改变协议版本。
- 规范写出只接受严格 JSON：`null`、布尔、有限数、字符串、数组与普通对象，任意深度都如此。`undefined`、BigInt、NaN、Infinity、Date、函数与循环都不是 JSON，写出时拒绝，不转换，不省略。摘要从不对有损的形式计算。
- 材料有参加者、迁移与读 handler 三种。`moduleUrl` 是构建固定的 `file:` URL，不来自请求、配置或消息。模块字节的摘要在构造期与 Worker 加载前各核一次；构造期不符则构造被拒绝，加载时不符则该域隔离。一张表只有一个拥有者；`readTables` 里的表必须归同一组合里的某个参加者。
- 材料目录是一次构建的全部材料，并为租户作用域与系统作用域各声明一个组合。构造期对每个声明组合求清单，不成立则构造被拒绝。
- 组合有效性按次序判：有参加者不在目录中答 `material_unavailable`；否则收齐全部问题（事实依赖成环、需要的事实无人提供、一个事实键两个提供者、一张表两个拥有者、读的表无拥有者、迁移的 `requires` 缺项或成环）后答 `combination_invalid`；否则给出清单。
- 清单摘要由调用方用纯函数算出放进请求，提供者用自己的目录独立再算一次再比较。`moduleUrl` 与读 handler 不进清单，所以同一组合在不同构建路径下摘要相同。

### 登记

- 登记键是（作用域，事务域，组合版本）。参加者排序后比较与保存，列表顺序没有含义。同一事务域可以同时有多个版本的登记，新版本不覆盖旧版本。登记跨重启保留，调用方卸载不删除它。
- 同一登记键已有相同登记，答已保存的登记；参加者或清单摘要不同，答 `registration_conflict`。
- 已登记的域新增版本时，提供者在一个事务里执行该组合待做的迁移并写入登记；迁移失败回滚，答 `domain_unavailable`，已有登记不受影响。登记只在应用并验证了全部待做迁移的同一个事务里保存。
- 第一次成功登记把事务域绑到该作用域；之后另一作用域对同一事务域登记答 `domain_occupied`。这是另一作用域唯一能看出差别的地方。
- 登记与登记拒绝都不写提交回执。

### 准入等待

- `registerCombination`、`commit`、`query`、`read` 发送之前各要一份预留（每域一份、全局一份，写另要请求字节与响应额度，读另要 handler 的 `maxOutputBytes`）。拿不到时不立即拒绝，进入这个准入点的等待列表，按到达顺序在期限内等归还出来的容量。
- 等待列表有上限：每域等待者不超过每域预留数，全局等待者不超过全局预留数，超过立即拒绝。配置关系保证每个到达的请求在容量归还之后都放得下，所以没有永远等不到的请求。
- 新到的请求先进等待列表再参与发放，不直接取用空出来的容量。每次归还、到期或中止都从队头扫一遍：放得下的给预留；只被本域上限挡住的跳过；被全局个数或字节挡住的，这一遍到此为止，后到的不越过它。
- 只按归还出来的容量发放；准入层不重试、不轮询。
- 等待者没有预留，没有发出任何消息，所以它被拒绝或取消都是确定没做，可以用同一身份再调用。等待中的 `commit` 计入待决索引。
- 期限到：`registerCombination` 与 `commit` 答 `queue_full`，`query` 答 `unknown`，`read` 答 `queue_timeout`。期限为 0 时不等待。

### 提交

- 控制侧的拒绝不预留、不发送：关闭、调用时已取消、字段、协议版本、参加者重复、`facts` 不是 JSON、条数与字节与深度超限、排满。请求在 `facts` 之外含非 JSON 值时不抛出，答 `unknown`（`request_not_json`）。
- Worker 侧的拒绝在建立 savepoint 之前判：写者不是当前代际、域不可用、没有登记、清单摘要与登记不同、本构建没有该组合的精确材料、命令的参加者不在登记中、参加者需要的事实其提供者不在本次命令里（沿依赖图传递）。域是 `absent` 或绑定另一作用域时答 `combination_unregistered`，不启动 Worker。
- 多个条件同时成立时答第一个。拒绝不写回执，不执行命令。
- 提供者只执行 `commands` 里的参加者，按依赖图的拓扑序；同时就绪的按名字的 UTF-16 码元升序。这一顺序由组合版本固定，请求改不了。
- `committed` 的响应证据按执行顺序列出全部已执行的参加者；`rolled_back` 列出停止点之前的参加者与停止它的那一个。响应与回执在同一事务里保存，不从当前状态重算。回滚依据是历史证据，不授予以后的动作许可。
- 领域的后续动作（outbox）由参加者写在自己的表里，与回执同一事务；原拥有者看到 `committed` 之后读出并执行。回执不新建 Run，不发通知。
- 取消：调用时已中止答 `cancelled`；等预留时中止答 `cancelled` 且什么都没发出；预留之后中止，调用方立即得到 `unknown`（`observer_detached`），提供者再尝试撤下：还没开始的撤下并归还预留，已开始的按在途操作收场，撤下不写 `rolled_back`。

### 参加者端口与事实格

- 参加者在 Worker 内经端口执行语句，拿不到数据库句柄。端口有 `execute`、`requireFact`、`provideFact`。
- 权限不按语句文本判断。提供者在调用参加者期间设置 SQLite authorizer，拒绝：事务控制与 `SAVEPOINT`；`ATTACH`、`DETACH`、全部 PRAGMA 与扩展加载；DDL 与临时表；写 `ownedTables` 以外的表，读 `ownedTables` 与 `readTables` 以外的表；`_sql_` 表；允许清单以外的函数。触发器与视图的间接访问同样核对。提供者执行自己的事务语句与写回执之前先撤下 authorizer。
- 一条语句失败之后本次端口关闭，参加者捕获错误也打不开它，后面的 `execute` 不再把 SQL 交给 SQLite。
- 事实格按操作新建、按操作销毁。`provideFact` 只能写本参加者声明的键，每键一次，值必须是 JSON；`requireFact` 只能读声明需要的键。违规时端口关闭，回复记 `failed`（`fact_violation`）。操作之间只经数据库共享事实。
- 参加者同步执行，不等待网络、模型、工具或人。模块不跨调用保留影响结果的状态，不产生带外副作用。

### 失败分类

- 参加者回复 `conflict`、`unsupported` 或 `failed`，authorizer 拒绝、事实格违规、参加者抛错、回复非法、回复超限，以及由语句与数据决定的 SQLite 错误（约束、类型不符、范围、过大、语法或模式），都是明确回滚：持久的 `rolled_back` 是真实的历史。
- 其他 SQLite 错误（忙、锁、I/O、满、内存、损坏、权限、协议、中断与未列出的码）与提供者内部错误只进诊断，结果是 `unknown`，不写回滚回执。
- 写锁等待超过 `lockWaitMs`、`COMMIT` 结果不确定、回滚之后回滚回执没写成、`ROLLBACK` 自己失败，都是 `unknown`。
- 提供者不从异常类名推出业务拒绝，适配器不把 `failed` 改写成 `conflict`。

### 组提交

- 同一事务域的多个原操作可以共用一个外层事务，每个原操作一个 savepoint；一次 FULL 提交保存多个身份的事实、响应与回执。合组只是机制次数，不改变任何一个操作的结果。
- 只有每个参加者在该域都可分组的操作才进多操作组，否则单独成组。可分组由三层核验：材料声明 `grouping`（没有默认值，构造期核）；模式不含延迟外键、时间默认值与临时表（域打开时读 `sqlite_schema` 核）；语句只调允许清单里的函数，清单不含时间、随机与连接状态函数（authorizer 核）。延迟外键是唯一能被后续操作修复的约束，所以模式层足以排除「合组后 A 从应失败变为成功」。作者自报不代替核验。
- 组只收集相邻、已预留、可分组的操作，收集期限从第一个操作起算，后到的不延长。屏障（登记、写代际改变、关闭、`query`、`domain-serial` 读、WAL 维护）不被跨越。调用方在 `await commit(A)` 返回后才构造的 `commit(B)` 不与 A 合组，提供者不为等 B 推迟 A。
- 组状态机独占写连接直到本组收场。两个原操作之间只处理关闭与撤下，不执行别的语句，不读暂存回执。
- 本组之前已持久的回执、认回与 Worker 侧拒绝不受本组故障影响。B 明确失败时：撤下 B 的写入，提交新暂存的前缀，再用第二个短事务只写 B 的 `rolled_back` 回执与失败响应；第二个短事务持久才答 `rolled_back`，否则 `unknown`。没有新暂存前缀而 B 的语句结束了整个外层事务时，同样用第二个短事务写 B 的回滚回执。
- 前缀 COMMIT 失败或不确定时前缀与 B 都是 `unknown`，提供者不在新事务里保存 B 的依据，因为它可能观察过前缀的暂存写入。有新暂存前缀而 B 的语句结束了整个外层事务时，前缀与 B 都是 `unknown`，不写回滚回执。批级故障只扩大 `unknown` 的范围，不扩大业务回滚的范围，不伪造业务响应。
- 一个身份在本组的第一次尝试取得解释权；它最终为 `unknown` 时，同摘要与异摘要的等待者都得到 `unknown`。
- 成功组的逻辑顺序是新操作首次执行的先后。外部快照只看到组前或组后的完整状态。
- 预留不因合组而合并：每个调用一份，在结果被收下、确认撤下、发送失败或 Worker 退出时归还一次。受理计数只由控制侧拥有；Worker 只核消息带着预留。

### 查询

- `query(identity)` 在写路径上按完整身份取权威结果。它是排序屏障：当前组结束之后才执行，不进正在执行的外层事务，不读暂存回执，不用读池。
- 持久回执存在，答它与原响应证据。原身份在待决索引里（等预留、排队、已封组、执行中、已暂存、第二个短事务中、结果已发出而预留未归还、等待者、旧代际未结算），答 `unknown`。否则五项证明全部成立才答 `not_committed`：旧写代际已排除、旧事务已终止、数据库恢复已完成、本次权威读取成功、该操作未进受理队列。缺任何一项答 `unknown`。证明由提供者构造，读 Worker 构造不了任何一项，调用方不组装。
- 关闭、字段违规、协议不是 2、排满、域 `absent` 或绑定另一作用域、打开失败、域隔离：都答 `unknown`，不透露另一作用域有没有同键回执。`unopened` 的域由 `query` 触发打开。
- 已发送的 `query` 在观察上界内没有答复，答 `unknown`（`reply_wait_expired`），即使回执已经持久；调用方之后再查。`query` 是 `unknown` 之后的恢复路径，所以它自己的等待也有界。

### 读

- 业务只发具名 handler、协议版本与输入，不能传 SQL。`requestKey` 只用来关联与丢弃迟到响应，不是持久身份，重复时不复用旧结果。读不认回提交，有自己的队列与字节预算。
- 失败都是带原因的 `unavailable`：关闭、请求不能解码、输入超限、没有该 handler、排满、域不可用、缺 handler 需要的迁移标记或索引正在重建、排队超时、运行超时、输出或行数超限、读 Worker 退出、handler 失败或输出不是 JSON。取消是读结果的一种。存储故障不包装成空页或 not-found，提供者不交付截断的结果，不自行发明分页。
- `snapshot` 读取用空闲、无事务的读连接，`BEGIN` 后首个读取固定快照，同一事务内完成全部读取；快照包含调用之前已答 `committed` 的提交。`domain-serial` 读先取连接再申请域的读屏障，屏障与写共用一个到达顺序，轮到时确认当前组已结束再建快照。
- 每次成功返回之前，语句已结束、行已物化、事务已结束。读事务不复用，一次 `read` 一个快照。跨多次 `read` 的分页由领域用自己的固定读根与不可变记录保持范围，不能重建时答 gap、changed 或 unavailable，不拼接不同修订。
- 事务内守卫、`query`、原回执的幂等读，以及可能写入排除记录的读，留在写路径。
- 读连接为 `query_only`，不开共享缓存，不用 `immutable` 模式，不创建数据库；authorizer 只允许对 `readTables` 的 `SELECT` 与允许清单里的函数。handler 的每条语句写 `LIMIT`，提供者以有界迭代取行，超过 `maxRowsRead` 即结束语句。
- 读不需要写 Worker：第一次打开成功时记下域绑定的作用域，之后读只占读 Worker 的名额，不持有域。迁移会改变模式代次时，先停止派发新读、等在途读事务结束、关闭旧连接，再迁移；旧代次的结果不交给新的读。

### 拒绝的定性

- 每个提交拒绝原因是暂时的或确定的。暂时的原因来自存储此刻的状态（关闭、排满、写者不是当前代际、域不可用），同一请求以后可以受理：调用方按依赖等待，到检查时刻用同一身份再提交，这就是一次认回。确定的原因来自请求内容或本构建的装配事实，同一请求再提交得到同一拒绝：调用方不等待，按确定失败处理。带 `recall: 'never'` 的身份只在受理前拒绝之后再提交。
- 读的原因按同一判别分：关闭、排满、域不可用、排队超时、运行超时、Worker 退出是暂时的；不能解码、超限、没有 handler 是确定的。
- 定性的唯一来源是 `commitRejectionNature`；适配成员按它翻译，不另行判断。

### SQL 值与大文本列

- 参数只能是 `null`、布尔（编码为 0 或 1）、有限数、有符号 64 位 `bigint`、字符串或 `Uint8Array`；超出 64 位在执行前失败。读出时 INTEGER 一律 `bigint`，REAL 为有限数，TEXT 为字符串，BLOB 为复制后的字节；其余值拒绝，不隐式转换。行是位置数组。
- `facts` 里的领域位置仍是十进制文本，由领域 codec 转换；`facts` 不能含 `bigint`。`QueryRows` 只在 Worker 内用，不直接作为 HTTP JSON。
- 大文本列的类型是 `BLOB`，存法由 `packText` 与 `unpackText` 唯一给出：首字节是格式标记，`0` 后接原文 UTF-8，`1` 后接原文 UTF-8 的 raw DEFLATE；短于 128 字节用 `0`。没有首字节或标记不认识时抛错，不把字节当原文。读回的文本与写入的逐字节相等。哪一列是大文本列由拥有该列的参加者决定；标识、键与摘要列不用这个格式。
- 读写上限与按文本计的量按解码后的文本计，不按落盘字节计。SQL 不读这些列的内容，约束、索引与条件只用它们是否为 `NULL`。

### 资格与作用域

- 作用域是请求的显式字段，提供者不从 Context、isolate 标签或安装关系推断。
- SQL 不判断资格，也不提供撤权排序。资格核验由参加者在每次提交尝试内做一次，撤权在下一次核验时生效；参加者在事务内读资格事实时，按依赖顺序先于依赖它的写参加者执行。
- 另一作用域的请求得到与 `absent` 相同的结果，含诊断；唯一的例外是登记的 `domain_occupied`。诊断不超过 `maxDiagnosticBytes`，不含 SQL 文本、参数、业务正文或另一作用域的信息；调用方只按 `kind` 与 `reason` 分支。
- 结果都经返回值给出，Promise 不以 reject 报告结果。

### 事务域的打开与迁移

- 每个事务域一个数据库文件，文件名是事务域 UTF-8 字节的小写十六进制，可逆且只由事务域决定。文件内的绑定行在创建事务中写入，之后不改；打开时绑定行与路径推出的标识不同（别名、复制、改名），该域隔离。一个事务域只服务一个作用域，不同租户不共用文件或写 Worker。
- 规则 DO-1：域的打开、恢复、写代际加一、迁移与组合版本升级，只在该域被操作触及时执行；全部成功之后才放行写准入、才保存新的登记。构造期只装载并验证静态材料（配置、材料摘要、handler 输出上限、声明组合与迁移图），不打开数据库，不启动 Worker；不通过时构造被拒绝。
- 已有的域（路径 A）：取得进程内声明与 Worker 名额；打开文件，由 SQLite 结束死连接留下的事务并完成 WAL 恢复；读连接上的 `sqlite_version()`，低于 3.51.3 即隔离，这一核对在启用 WAL 之前；设置并读回 `journal_mode=WAL`、`synchronous=FULL`、`foreign_keys=ON`，读回不符即隔离；核对绑定行；在一个短事务里把写代际加一；在一个 `BEGIN IMMEDIATE` 事务里执行待做迁移、模式核验，补写声明组合的登记。
- 新的域（路径 B）只由 `registerCombination` 创建：建提供者表、写代际置 1、执行迁移与核验、写绑定行与登记，一个事务提交；任一步失败回滚，域保持 `absent`。`commit`、`query`、`read` 触及 `absent` 的域时不创建文件。
- 打开开始时用 `stat` 判断文件在不在：成功是在，`ENOENT` 是不在，其他错误是不知道。不知道不是 `absent`：它是暂时性故障，`commit` 得到 `domain_unavailable`。打开失败时只删除本次打开之前确凿不在的文件。
- 只有内容不对时域才隔离：版本低于下限、PRAGMA 读回不符、绑定行与路径不符、迁移标记与目录不符、声明组合的登记冲突、迁移失败、模块内容不对。暂时性故障（没有名额或声明、不知道文件在不在、打开时的环境类 I/O 错误、读模块时的系统错误、锁等待超时、迁移 COMMIT 不确定）不隔离。模块加载失败不缓存。隔离保持到插件重跑或进程重启。
- 迁移导出同步的 `up` 与 `verify`；`up` 抛错或 `verify` 答失败，整个迁移事务回滚，保持升级前的格式。迁移按 `requires` 的拓扑序执行，平局按（拥有者，编号）升序。迁移标记保存校验和；标记与目录不同或不在目录中即隔离，所以目录不能删除已发布的迁移。迁移端口只允许对本拥有者的表做 DDL 与读写、读 `requires` 闭包所建的表。迁移不接收调用方的 SQL。
- 空闲的 `ready` 域在别人要 Worker 名额时可以让出写 Worker，回到未打开；下一次触及按路径 A 重开。让出不是故障，不改任何事实。

### 写者、读屏障与 Worker

- 同一进程中一个数据库文件只能有一个写 Worker。文件身份是解析链接后的真实路径（win32 上再折叠大小写）。旧代际的写 Worker 退出被观察之前，新代际取不到声明，打开按暂时性故障处理；插件重跑因此不会产生第二个写者。
- 写在打开时把写代际加一并记下写入的值；每次组提交在 `BEGIN IMMEDIATE` 之后读回，值不同或读不到即本组全部 `unknown`，Worker 回滚并退出。
- `domain-serial` 读屏障与同域的写共用一个到达顺序：写只在它前面没有屏障时进入；屏障只在它前面没有任何条目时持有。读不饿死写，写也不饿死读。每一处等待都有上界：写等屏障至多 `lockWaitMs`，到期撤下且没有发送；读等屏障计入 `readQueueTimeoutMs`；屏障持有至多 `readObservationMs`。撤下的条目不保留位置。
- 已发送的 `commit`、`query`、`registerCombination` 的调用方观察上界是 2 × `lockWaitMs`，到期答 `unknown`（`reply_wait_expired`）；它的预留、待决索引项与次序位置保持到 Worker 答复或退出。
- `query` 与控制消息的等待有界，不被持续到达的写饿死。
- 读 Worker 的结果消息带 Worker 代际、请求序号与租约令牌，三者都匹配且请求未结算才接收。迟到消息不改结果，不重复释放资源。连接绑定作用域、事务域、模式代次与 Worker 代际，任一项不符即隔离该连接，不改标签复用。读 Worker 崩溃时在途读答 `worker_exited`，调用方重读得到新快照，提供者不拼接部分结果。
- 全局 Worker 名额计入任何状态的写与读 Worker，观察到退出之前不归还；读 Worker 最多用总名额减去写 Worker 保留名额。名额限制同时在用的 Worker 数，不是部署里的域数。要名额时先关一个空闲读 Worker，再让最久没被持有的空闲域让出。
- 输入、结构化克隆、响应、等待者与结果发送都计入有界预算；提供者先做有界遍历，再分配完整字符串。函数不能经结构化克隆进 Worker，所以 JSON 值核对在控制侧、消息发出之前完成。预算是资源配置，不是租户之间的公平政策。

### WAL 与配置

- 写 Worker 只在两个物理事务之间做维护：定时或 WAL 超过阈值时做 PASSIVE checkpoint。WAL 超过读暂停阈值且 checkpoint 没有进展时，域进入 `read-paused`：停止派发新读，等在途读事务结束，再做 RESTART 或 TRUNCATE checkpoint。仍超过写停止阈值且没有进展时进入 `write-stopped`：新写答 `domain_unavailable`，已预留的按真实结果结算。降回阈值以下即解除。
- 提供者不降低 `synchronous=FULL` 来换吞吐。当 `synchronous` 为 `FULL` 时，普通进程终止证明进程级持久；断电耐久只以相应的故障试验为证据。
- 配置只含可序列化的数据，字段都必填，装配填写采用值；默认值只是初值，不是吞吐或延迟承诺。字段之间的关系（单条命令 ≤ 请求 ≤ 组输入、请求 ≤ 全局在途写字节；诊断 ≤ 回复 ≤ 操作回复 ≤ 组响应预留 ≤ 全局写响应；每域值不大于全局值；读 handler 的 `maxOutputBytes` ≤ 单个读结果 ≤ 全局读结果预留；WAL 阈值单调）在构造期核对，配错时启动失败，不在运行时才发现。

### 关闭

- 关闭有两个发起者，调同一个 `StorageControl.close`：装配关闭适配器在排空阶段调用；绑定插件的受管 effect 在撤除时调用。关闭期限只有一个来源 `closeDeadlineMs`，第一次调用时用单调时钟算出绝对期限，之后不延长。`close` 幂等，每次都在「全部资源已结束」与「期限已到」中较早的时刻答当时的结果。
- 先停止准入：之后新到的操作答 `closing`（`query` 答 `unknown`），不写回执，不进队列。未开始的工作撤下，每份预留归还一次；被撤下的 `commit` 与 `registerCombination` 答 `unknown`（`withdrawn_before_start`）。正在执行的写跑完，Worker 在操作之间确认关闭后不再开始后缀。读事务结束后关连接。全部连接关闭、全部 Worker 退出都已观察到，答 `closed`；期限到时仍有 Worker 未退出，答 `incomplete` 与 `residuals`（域、角色、Worker 代际、租约名、在途原身份，不含 SQL 或业务正文）。
- 期限到时还没收场的 `commit` 答 `unknown`（`close_deadline`），预留由残留 Worker 保留到退出。已给出的结果不被迟到消息改写；迟到完成的写照样持久，由原身份认回。关闭不把在途操作报成回滚，结束 Worker 不是回滚。
- 每个 Worker 启动前取一份关闭租约，租约抛错即停止准入且不启动这个 Worker。向装配发起的关闭答 `incomplete` 时设报告闩锁：残留 Worker 的租约只在它的退出已观察到、且装配已调用 `assemblyReportSettled()` 两者都满足时才释放。只有 `disposal` 发起的得到 `incomplete` 时不设闩锁，退出即释放。`assemblyReportSettled()` 幂等，只解除闩锁。这些是提供者与应用之间的协议，不是 Cordis 的 API。

### 同一个数据库的身份

- 为每个数据库保管缓存、快照或计数的成员，以 `SqlStorage.database` 为键认出两个存储对象背后是不是同一个数据库，不靠对象的形状推断。
- 提供者为自己的每个数据库给出一个对象；同一个数据库上的每个存储对象带同一个对象，不同数据库带不同的对象。转发到另一个存储的包装带那个存储的 `database`。给出另一个对象的转发包装是装配错误，本契约不为它规定陈旧上界。

### Cordis 装配

- 服务定义只在 `sql-contract` 的 `./cordis`：`StorageService`（键 `storage`）、`StorageHostService`（键 `storageHost`）、`TenantDomainsService`（键 `tenantDomains`）、`TenantDomainLookupService`（键 `tenantDomainLookup`）。键表达能力，不以实现命名；不保留 `sqlStorage`、`SqlStorageService` 或任何别名。提供者继承 `StorageService`，不再 provide 同一个键。消费者注入 `storage`，不导入提供者。
- 服务方法转发到提供者宿主持有的函数对象。Worker、队列、结果拥有者与关闭协调器不建在调用方的 Context 上；登记不随调用方的 effect 撤除；Worker 内没有 Cordis Context。卸载调用方之后，原操作仍能收场并认回。
- 运行时对象不进插件树：材料目录、关闭租约口与控制口交接只经 `storageHost` 交入，提供者插件只注入它。`StorageControl` 只有两条取得路径（装配关闭适配器、绑定插件），不作服务属性，不进 Context。插件配置经同步 schema 校验，非法配置使 fiber 失败。
- 一个 isolate 一个 `storage` 提供者。目录查找只读已发布的目录快照：已登记的租户答 `ready` 与事务域，快照里没有的答 `unregistered`，快照不可读答 `unavailable` 而不是 `unregistered`；查找不登记、不迁移、不写目录。写共同提交的行收到 `unregistered` 时不写入。
- 内存替身与契约同源，把全部状态放在一个实例里，按到达顺序串行，持久性声明为 `none`，只建模 `absent`、`ready`、`closed` 三个域状态。替身通过符合性套件不证明需要真实文件、Worker 或 SQLite 的性质；那些只由提供者的测试证明。

### 保证的范围

- L-1：资格核验与提交之间有一次 check→commit 路径的窗口。
- L-3：同时在用的 Worker 数受 `maxWorkers` 限制；空闲的域只在别人要名额时让出写 Worker。一条读连接独占一条线程。
- L-4：跨进程的写者排除不在保证内。
- L-5：单条 SQL 的 CPU 与内存没有硬上限，同步语句没有可用的中断。提供者不终止卡住的 Worker；调用方的等待仍然有界，该域的吞吐在 Worker 退出前为零。
- L-7：材料摘要不防御能写构建目录的攻击者。
- L-8：WAL 阈值不是磁盘空间的硬保证。
- 一次 `commit` 只用一个事务域；第二个库的写入用另一次提交。SQL 写代际只排除 SQL 写者，不排除库外的旧进程；Tool 外部启动的排序归 Tool。

## 原则与约束

- 不知道就是不知道。环境故障与不确定的提交答 `unknown`，不写成回滚，不写成未提交；`not_committed` 只在五项证明齐全时给出。
- 存储不懂业务。`facts` 的含义、领域表、资格与外部效果都归原拥有者；存储只保证一起成立与可认回。
- 外部输出不声称可逆。effect 撤除、Worker 结束与关闭都不撤销已提交的事实或已发出的外部效果。
- 作用域显式、默认拒绝跨租户；拒绝不披露另一作用域的任何事实。注入不是授权。
- 每一处等待都有上界，每一份资源都有预算；上限只影响完成的早晚，不把合法请求判成永远失败。
- 规则改动先改契约与符合性套件，替身与提供者同步跟上；提供者在 SQLite 上的行为只由提供者测试证明。
- 自定义的认回与准入协议有形式模型（`sql-contract/verification/`）；有限检查的通过不等于实现符合。
