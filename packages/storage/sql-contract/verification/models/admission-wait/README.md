# AdmissionWait：准入点的有界等待

本目录的模型检查 sql-contract SPEC 的[准入等待](../../../SPEC.md#准入等待)。写（`commit`）、控制（`registerCombination`）、查询（`query`）与读（`read`）四个准入点用同一个结构，所以只建一个准入点。模型只证明列出的有限状态，不证明实现。

## 1. 建模的对象

一个请求要占本域一个位置、一个全局位置和若干字节。它要么空闲，要么按到达顺序在等待列表里等，要么持有预留，要么已经离开。等待列表有上限：每域的等待者数不超过每域位置数，全局的等待者数不超过全局位置数，超过就立即拒绝。等待者到期或被中止就离开。凡是改变持有者或等待者的一步，最后都从队头扫一遍等待列表：放得下的给预留；只被本域上限挡住的跳过；被全局的个数或字节挡住的，停止这一遍。

| 变量        | 含义                                                   |
| ----------- | ------------------------------------------------------ |
| `phase`     | 每个请求的阶段：空闲、等待、持有、离开                 |
| `queue`     | 等待者，按到达顺序                                     |
| `age`       | 每个等待者已经等了几拍                                 |
| `overtaken` | 有没有一次放行越过了一个更早的、不是被本域挡住的等待者 |

## 2. 性质

| 名称                      | 含义                                                               |
| ------------------------- | ------------------------------------------------------------------ |
| `Bounded`                 | 等待者数不超过上限                                                 |
| `DeadlineKept`            | 没有等待者等过期限                                                 |
| `WithinCapacity`          | 持有的预留不超过个数、字节与每域的上限                             |
| `NoOvertake`              | 不插队：被放行的请求前面，没有一个只因全局资源而没拿到的更早等待者 |
| `NoIdleFit`               | 不晾着：每一步之后，等待列表里没有现在就放得下的请求               |
| `NothingSentWhileWaiting` | 等待者不持有预留，因此什么都没有发出                               |

## 3. 配置

四份配置用同一组取值：4 个请求，3 个域，每域 1 个位置，全局 2 个位置、2 个字节，期限 2 拍。请求 `c` 占 2 个字节，所以它会被全局字节挡住，而它后面的 `d` 放得下。

| 配置        | 去掉的规则                         | 必须命中         |
| ----------- | ---------------------------------- | ---------------- |
| `positive`  | 无                                 | 全部不变式成立   |
| `jump`      | 新来的请求放得下就直接拿，不先排队 | `NoOvertake`     |
| `no-rescan` | 到期与中止之后不重扫               | `NoIdleFit`      |
| `wake-all`  | 扫描时放行全部等待者               | `WithinCapacity` |

## 4. 运行

```
TLA2TOOLS_JAR=<TLC 1.7.4 的 jar> python3 check.py --out <输出目录>
```

`check.py` 要求正配置以 0 退出并完成搜索，每份负控以 12 退出并且只违反点名的那一条。日志、状态目录与带摘要的总结写到 `--out`，不写进本目录。

## 5. 模型到代码

| 模型                     | 代码（`packages/storage/sqlite-provider/src/waiting.ts`）           |
| ------------------------ | ------------------------------------------------------------------- |
| `Arrive` 的立即拒绝      | 等待列表已满。请求永远放不下的情形由配置关系排除，模型里是 `ASSUME` |
| `Arrive` 入队再 `Settle` | `acquire`：先入队，再 `scan`                                        |
| `Release`                | 预留的 `release` 之后 `scan`                                        |
| `Leave`                  | 期限计时器到期或 `signal` 中止：移出等待列表，再 `scan`             |
| `Scan`                   | `scan`：放得下给预留，被本域挡住跳过，被全局挡住停止                |

## 6. 不覆盖

- 关闭：关闭开始时全部等待者答 `closing`，模型里没有这一步。
- 读的期限计入 `readQueueTimeoutMs` 的全程，模型只把它当成一个期限。
- 更大的规模与真实时长不在模型内。
