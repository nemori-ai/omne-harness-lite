# 遥测

## 总体架构

遥测包组回答一个问题：各领域在运行中留下的工程观测（事件、指标、测量段与 Cordis 日志）怎样被同步、有界地准入，写到本地出口，并且每一条没写出的都有计数可查，而发射的一方从不因此等待、出错或泄露自由文本。

| 成员                        | 回答的问题                                                                                                                                          |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `telemetry-contract`        | 定义、字段、绑定、carrier、准入结果与关闭报告长什么样，什么样的值合法。纯数据与纯函数，带一个有界的捕获替身；只依赖 `legal-identity`，不依赖 Cordis |
| `telemetry-cordis-contract` | 遥测在这套系统里以哪一个服务出现：服务定义 `telemetry` 与它的键                                                                                     |
| `telemetry-node`            | 一个 Node 进程里怎样准入、排队、写到本地出口、计数与关闭；禁用实现；Cordis 日志桥；对写出的记录做离线热点聚合                                       |

依赖只朝契约：`telemetry-node` → {`telemetry-cordis-contract`、`telemetry-contract`}，`telemetry-cordis-contract` → `telemetry-contract`。发射领域只依赖纯契约：它在自己的成员里声明定义，经已有的参数拿到 emitter，安装闭包里没有 Cordis。应用装配创建运行时，把它作为 `telemetry` 服务装进插件树，发射方的行按键注入，在行体里构造自己的 facade。运行时同步准入，在后续的一轮事件循环里把队列写到出口；关闭时排空到期限，交出一份关闭报告。写出的 JSON Lines 由运维者在本机离线聚合成热点报告。

## 领域边界

遥测拥有：字段规则、定义、绑定与 carrier 的合法性判定；准入与每个原因的丢弃计数；有界队列与本地出口（应用的写函数，或本组持有的文件）；测量段的开始、结束、过期与释放；关闭报告与它声称的确认边界；禁用实现；Cordis 日志桥；离线热点聚合。

遥测不拥有：各领域的事件目录、字段含义与 facade（各发射领域）；主体签发、铸造、授权与租户核验（身份与授权）；应用装配、`telemetry` 行的配置 schema、关闭顺序、stdout 的唯一写者与关闭报告的去向（应用 `apps/harness-server`）；任何业务终态：一个段的结果只说明这次测量。OTel 链路与指标、远端输出、输出代的换代与 `health()` 不在本组范围。

本组只认通用角色：作用域（由 `legal-identity` 铸造，表达事实属于谁）、部件名与调用方给出的工作、尝试、调用引用。

本组需要、由别人提供的：

| 需要                             | 对方                                          | 本组需要它做什么                                                      |
| -------------------------------- | --------------------------------------------- | --------------------------------------------------------------------- |
| `actingScopeCodec`               | 身份（`packages/common` 的 `legal-identity`） | 判定一个 scope 是不是铸造的值，并给出它的文本形式；本组不复制铸造登记 |
| 时钟、写函数、摘要函数、运行预算 | 应用装配（`apps/harness-server`）             | 交入墙钟与单调时钟、记录的写函数、限频摘要的去处与全部运行预算        |

本组为别人提供的：

| 提供                                               | 对方                                                 | 本组提供什么                                               |
| -------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------- |
| `TelemetryPort`、`Emitter`、`Segment` 与 `define*` | 发射领域（Session、Agent 的 facade；应用的入口诊断） | 绑定作用域、发事件与指标、开段与结束段、登记没能组成的记录 |
| 服务键 `telemetry`（`TelemetryService`）           | Cordis 装配                                          | 唯一的遥测服务定义；提供者继承它                           |
| 运行时、禁用实现、插件工厂与日志桥                 | 应用装配                                             | 创建、装载、显式关闭与关闭报告；把 Cordis 日志接到出口     |
| 捕获替身（`./testing`）                            | 发射领域的测试                                       | 不用 Cordis 断言准入的字段与段归属                         |
| 离线热点聚合与命令                                 | 运维者                                               | 从写出的记录得到段时长分布、事件与日志计数                 |

## 心智模型

把遥测想成挂在业务旁边的一个有界、会丢东西、但丢了会记账的记录口。发射方交出一条记录就走，答复只说「本地收下了」或「因为什么丢了」；它不等出口，不分支，不会因遥测失败而失败。收下不是送达：送到出口、出口确认、后端可查是更靠后的几道边界，每份报告只声称它实际看到的那一道。

字段里没有自由文本：字符串只能是枚举值或受限字符集的引用，秘密靠「根本没有入口」挡住，而不是靠识别。作用域只说事实属于谁，一个租户的工作就标那个租户，进程自身的事实标 `system`；它不授予任何权限，也不能为了方便把租户的事实改标成 `system`。拿不到租户时，这条记录不发，只登记一次丢弃。

最容易想错的几处：「遥测关掉」是在场的禁用提供者，不是缺席，缺席是装配失败；段的结果不是业务终态；过期不靠定时器，只在有活动和关闭时被发现；关闭报告里的「排空完成」不表示有记录写到了出口；日志桥写的 `log` 记录是唯一带自由文本的记录，所以它不外传。

## 应然设计

### 端口操作

- 绑定、发事件、记指标、开段、段内事件、结束段与登记丢弃都同步返回，不等网络，不抛错；每次的工作量以结构上限为界。输入在读取时抛错（例如代理对象）答 `dropped(invalid)`。
- 无效绑定不抛错：得到的 emitter 对每次记录都答 `dropped(invalid)`。
- `Emitter.bind(patch)` 派生新的 emitter，原 emitter 不变；派生只改工作、尝试、调用、`adopted` 与 `links`，其他成员与值为 `undefined` 的成员不生效，派生出的绑定仍要校验。
- emitter 是不可变的值，不登记到任何目录，不持有需要释放的资源，随持有者消失。
- 登记丢弃（`discard(definition, reason)`）只为调用方没能组成的一条记录计数：原因只能是调用方可以声称的 `invalid`、`policy`、`capacity`；定义不是契约接受的定义或原因不在这三个里，答并计 `invalid`；关闭后答 `closed`。它不写出记录，不计入准入。

### 定义与字段

- 字段规则只有 `enum`、`boolean`、`number`、`ref` 四种；metric 的标签只能是 `enum` 或 `boolean`，因为标签的取值个数必须有限。
- `define*` 只校验本次输入，返回冻结的拷贝；非法定义抛 `TypeError`。没有全局注册表：同名的两次定义是两个独立的定义。
- 引用、名字、部件名、字段名与枚举值只允许不含空白的可打印 ASCII，长度按字节计；所以 `Bearer x` 这类文本不合法。
- 校验看实际值，类型不是安全边界。未声明的键（含 symbol 键）、缺少的必填键、非有限数与越界的数、枚举外的值、超长或字符集不符的引用、任何对象值（`Error`、数组、带 `toJSON` 的对象）、带 getter 或 setter 的字段都无效；校验不调用 getter。counter 的值不小于 0。
- 可选字段缺席时合法，在场时照常校验；键在场而值为 `undefined` 不算缺席。
- `validateFields` 与 `validateBinding` 是纯函数，不抛错，答 `ok` 或带闭合原因的 `invalid`；提供者与捕获替身共用它们，规则只写一份。
- 错误先由发射领域转成有限的错误码；原始 `message`、`cause`、`stack` 不进普通记录。

### 作用域与关联

- scope 必须由 `legal-identity` 铸造：用它的编码判定，形状相同的普通对象与铸造值的拷贝都无效。输出 scope 时用同一个编码给出的文本形式。
- 租户的工作标那个租户；进程自身的事实标 `system`，写明部件，不带任何租户标识。
- `links` 与 `adopted` 的元素数、每个引用的字节数有上限；引用只有 `owner` 与 `ref` 两个成员。
- 提供者在绑定时取绑定的冻结快照，保留 scope 的原对象身份；被校验的就是被写出的，调用方之后修改原对象不影响记录。

### Carrier

- carrier 只含版本、trace、span 与采样标志，不带作用域、主体或凭据；格式是 W3C traceparent 的子集（版本只有 `00`，四段，小写十六进制，trace 与 span 不全为零，前后无空白）。
- 解码不合法的输入答 `invalid`，不抛错；编码不合法的身份抛 `TypeError`；编码后再解码得到相同的身份与采样标志。
- 跨进程的接收方重新绑定自己的作用域，把收到的 carrier 放进 `links`，不把入站 trace 与本地租户拼成一条链。carrier 与指标入口为后续的链路与指标留着形状与校验。

### 段

- 每个段有新的 trace 与 span 身份；入站 carrier 只进 `links`。先生成身份再占位置，生成失败答 `dropped(invalid)`，不占位置。
- 打开的段数有上限，满了答 `dropped(capacity)`。
- 结束是幂等的：第一次有效调用结束段并释放位置，之后返回第一次的结果，不再产生记录。结果缺省 `unknown`；不是 `ok`、`failure`、`unknown` 的结果答 `dropped(invalid)`，段不结束。段结束后段内事件答 `dropped(closed)`。
- 段打开超过存活上限即过期（恰好等于上限不过期）：收回位置，计一次 `expired`；之后结束答 `dropped(expired)` 不再计数，段内事件每条答并计 `expired`。存活上限缺省一小时，部署可以覆盖。
- 过期只在开段之前、段内事件与结束之前、每次准入之前、关闭开始时检查，用单调时钟比较，不起定时器。关闭开始时是最后一次检查；之后剩下的段同步释放，不计 `closed`，不写 `segment-end`；这些段之后的结束与事件只计 `closed`，已过期的段的结束答 `closed` 但不再计数。
- 开段可带一个释放回调。提供者在有效结束、发现过期、关闭与占位后回滚时释放段：先提交释放状态、退还位置、断开回调引用，再同步通知一次。释放不表示记录送达，不伪造 `segment-end`，不多计丢弃。回调只做有界清理，不重入遥测端口；回调抛错被隔离，不影响其他段的释放与操作结果。未占位的拒绝不登记回调。

### 准入与出口

- 一条记录按次序判定，第一条不满足的决定结果：已开始关闭答 `closed`；定义无效答 `invalid`（手写的定义也用契约的 `define*` 重新核对）；绑定或字段无效答 `invalid`；序列化后超过单条字节上限答 `invalid`；队列条数或字节将超上限答 `capacity`；其余入队，答 `admitted`。每个丢弃按原因计数。
- 准入不等出口：队列在后续的一轮事件循环里按准入次序写出，每条单独写，一条失败不影响其他条；失败的记录不重试，计一次输出错误。
- 写函数出口：写函数返回即到达本地出口边界。文件出口：同步写在返回之前完成，返回且没有错误即到达本地出口边界；这道边界是操作系统接受了写入，不是落盘。文件打不开时创建运行时就失败，不改用其他出口。
- 运行预算（队列条数与字节、单条字节、开段数、日志文本长度、摘要间隔）都必填、是正整数，由配置给出，本组不给缺省；只有段的存活上限可选。选项在创建时校验一次，非法抛 `TypeError`；运行时取预算的拷贝。
- 自由文本只出现在日志桥产生的 `log` 记录里，不经领域字段规则；其他记录的字段只来自校验接受的值。

### 计数、摘要与关闭

- 准入、各原因的丢弃、输出错误、队列长度与开段数的计数不经过本管线。
- 每次丢弃或输出错误之后可以写一行摘要，两行之间至少隔摘要间隔；摘要不进队列，运行时从不调用 Cordis logger，摘要函数抛错被吞掉；关闭开始之后不再写摘要。
- 关闭按次序：停止准入，做最后一次过期检查并释放其余段；在期限之前把队列同步排空到出口；排空了就结束出口并在剩余时间里等确认，期限到了不再等；交出报告。关闭不拒绝，重复调用得到同一个结果；非有限或负的期限按 0。
- 关闭报告：`droppedBy` 按准入时的七个原因加上 `output`（准入之后在出口写失败）分项，`dropped` 恒等于各项之和，`output` 不是任何准入答复的原因。期限到达时还在队列里的记为 `pending`，不写出。`flush` 有 `pending` 时是期限到达，否则有输出错误时是失败，否则是排空到边界；`boundary` 至少一条写到出口时才是本地出口，空队列的排空不算；`transport` 期限到达时是未确认，从不写已关闭。
- 四道确认边界互不相同，报告不混同：排空返回、本地写函数的回调、collector 协议的确认、后端可查询。

### 禁用实现

- 禁用实现是在场的提供者，与运行时同形：关闭前每次调用答并计 `disabled`；关闭后答 `closed`，不再计数。它的报告不声称任何边界。

### Cordis 装配与日志桥

- 服务键只在抽象 `TelemetryService` 上写一次，提供者继承它，不另写键，不自己提供；消费者只引用键，不引用提供者的实现入口。服务只有端口的方法。
- 发射方的行把键写进注入清单；键缺席时注入它的插件停在等待依赖，遥测缺席是装配失败，不是静默的空操作。一个隔离标签下只有一个遥测提供者。
- 插件只把运行时的端口作为服务提供，不创建资源，没有注入。它的副作用只登记兜底关闭：插件结束时以期限 0 关闭运行时；应用先关闭时兜底什么也不做。兜底不代替应用的显式关闭。一个运行时只有一次生命，重新装载插件需要新的运行时。
- 日志桥导出到 WARN，DEBUG 不导出。它有四个状态：引导（直接写出，并放进有界缓冲，满了计溢出）、就绪（交给运行时准入）、直写（遥测行是禁用实现时，直接写出，不缓冲，不计数）、关闭后（直接写出，计数）。挂上运行时可以先把缓冲的消息标为引导期消息交给运行时，运行时的出口与桥的写函数相同时不回放；挂上、直写与摘下都清空缓冲。遥测行失败或缺席时桥留在引导状态。
- 格式化抛错时用固定文本并计数；写函数抛错时计数，这条消息丢失。桥从不向记日志的一方抛错。

### 离线热点聚合

- 聚合是纯函数：读一组 JSON 文本行，不读文件，不写输出，不抛错。空白行跳过不计；读不懂的行与形状不合的遥测记录计入无效；其他种类的行计入其他种类；跳过的行不中止聚合。
- 筛选只是读者侧的选择，不授予权限：按租户筛时只留这个租户的记录，`system` 的记录（含全部 `log` 记录）不留；按时间筛是左闭右开。
- 段时长按 owner 与 name 分组，给结果分布与 min、p50、p95、p99、max，百分位用最近秩法，不插值，按 p95 降序。段配对只看输入里的行：在窗口内开始、窗口外结束的段计为未结束。
- 命令行的用法错误退出码 2 且标准输出为空；输入读不到退出码 1；其余为 0，输入里的非法行不改变退出码。报告只含 owner、name 与时间，不含字段值与日志正文，只供本机使用。

### 捕获替身

- 捕获替身按调用次序捕获准入的记录，用同一对校验函数判定；无效的不捕获；达到容量（缺省 1024）后答 `capacity`；登记丢弃不捕获记录；丢弃计数包含每一次丢弃。
- 清空先同步释放所有开放段并通知，再清空捕获列表并把计数归零，不写 `segment-end`；旧段句柄的结束与事件答并计 `closed`。替身不导入 Cordis，任何输入都不使它抛错。

## 原则与约束

- 发射永远不阻塞、不抛错：遥测的任何失败只进计数与报告，不回到业务。
- 规则只写一份：校验函数在契约里，提供者与替身共用；提供者重新核对手写的定义而不另写规则。
- 只声称实际看到的边界：准入不是送达，排空不是写到出口，本地出口不是落盘。
- 自由文本没有入口；作用域不授权；不靠识别秘密保护秘密。
- 自监控不经过本管线，没有递归。
- 结构上限是契约的常量，运行预算是部署的配置；预算没有缺省值，非法配置在创建时失败。
- 纯契约与 Cordis 定义分成两个成员：`dependencies` 属于整个包，只依赖纯契约的领域成员的安装闭包里因此没有 Cordis。
