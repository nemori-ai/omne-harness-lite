# tests

本目录承载本包适用的持续测试。测试种类的责任与边界见仓库[包级测试责任与边界](../../../../docs/verification.md#包级测试责任与边界)。

## 允许的内容

`*.spec.ts` 运行测试、`*.spec-d.ts` 类型测试、测试辅助代码，以及 `fixtures/` 下的固定输入。

## 边界

本成员没有生产提供者与运行实现。测试不需要真实存储、服务、宿主资源或 Cordis。测试覆盖本成员自己的纯函数、声明与类型，也检验 `./testing` 公开的替身与套件。替身上的测试只证明契约形状与判据，不证明真实进程、文件系统、授予根核对或隔离。测试不代替组合验证、规格或验收。

## 维护

公开行为或 `SPEC.md` 条款变化时，同步对应测试与本目录 `index.md`。导出变化时，同一次修改要更新 `public-entry.spec.ts`。改 schema 文件时，`need-declaration.spec.ts` 的摘要核对会失败，直到采用身份的 `digest` 同步。

运行方式：在仓库根执行 `pnpm turbo run test --filter=@omne-harness/execution-environment-contract`，或在本包目录执行 `pnpm test` 与 `pnpm typecheck`。`vitest.config.ts` 为 `*.spec-d.ts` 打开了类型检查。

当前缺口：落点的歧义拒绝、获取的幂等与重新核对、租约视图与恢复编排归 [execution-environment](../../execution-environment/README.md) 验证，本目录不覆盖；真实设施行为归提供者成员验证。SPEC 的[持续验证义务](../SPEC.md#持续验证义务)大部分需要组合验证。`operation-schemas.spec.ts` 覆盖三面九操作的 schema（含配额域、原获取描述、查询与恢复查询的答复、采用失败与清理状态）、日期与逐项拒绝，`exports-inventory.spec.ts` 消费共享导出清单工具。`./testing` 的执行环境套件在登记表成员的 `contract-conformance.spec.ts` 运行；它的两条 V-EE32 用例另在本目录 [environment-observe-conformance.spec.ts](environment-observe-conformance.spec.ts) 的受控执行环境上运行，含接受与否定；执行环境与真实宿主提供者套件、V-EE05/18/19/20/22 坏实现否定在 host-local 的 `contract-conformance.spec.ts` 运行；这些进程内测试不证明真实资源耐久或隔离。具名维护者由负责人指定。

[scripted-terminal-facility.spec.ts](scripted-terminal-facility.spec.ts) 覆盖获取归属与代际、同终端 busy、独立终端、固定 terminal 输出、停止两态、基态目录与单次覆盖、未知启动、迟到结果和生命周期关闭。[terminal-conformance.spec.ts](terminal-conformance.spec.ts) 完整接入七条可复用协议用例，两种停止场景各运行一次。它另验证跨获取故障实现被拒、缺少控制明确不适用、套件惰性组装。两者只运行非耐久替身。

[command-retention-conformance.spec.ts](command-retention-conformance.spec.ts) 用脚本命令替身的保留支持跑一次性命令留下的进程的十七条用例（`V-EE28.`、`V-EE30.`、`V-EE31.`），另一获取分「另一保留范围」与「另一租户」两种形状各跑一次。它另验证缺少无账本获取时第六条不适用、套件惰性组装、两个故障实现（同范围共用列表、封闭不停止）被拒。V-EE30 与 V-EE31 的每条用例另有只违反它的主体：在扩展的 `stop`、`output` 或 `list` 外面包一层改答复，或换一个获取。套件拒绝它，用例断言那条检查给出的消息。尾部用例的每个断言各有一个违约主体，另有迟到尾部与丢弃了开头的尾部两种接受。各条用例的不适用分支也各有用例。

[environment-observe-conformance.spec.ts](environment-observe-conformance.spec.ts) 在测试里写一个受控执行环境，只实现 `registerProvider` 与 `observeRetained`，用它跑公开执行环境套件的两条 V-EE32 用例。两条都通过；十四种违约（不问授权、不核绑定、用别的租户或范围问提供者、不去重、交部分列表、观察时分配获取等）各被拒，并断言对应的消息。宿主提供者在 Linux 上的接入见宿主成员的 `tests/command-retention-conformance.spec.ts`。
