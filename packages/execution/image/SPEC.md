# 图像成员行为

状态：技术设计已接受，见 [技术设计接受](https://github.com/nemori-ai/omne-harness-lite/issues/277#issuecomment-6198093789)。本文件拥有[模型](docs/model.md)以外的行为条件。生产上限尚未接受。候选推荐配置 `model-input-balanced` 已在 Linux x86_64、Node 26 上观测，见[推荐配置](docs/budget-profile.md)。步骤见[关键流程](docs/key-flow.md)。Cordis 装配见[集成](docs/cordis.md)。

## 责任与消费者

本成员向保存图像字节的调用方和准备模型输入的调用方提供同一条公开入口。保存图像字节的调用方在成功时保存原始字节和声明。准备模型输入的调用方可以在关闭前取得编码字节。两个调用方都不拥有预算表。

本成员不组装内容块，不保存附件，不发起模型请求，不选择执行落点，不声明隔离，也不描述 `Files()` 或 `Shell()` 的宿主文件使用。

## 预算

`imageBudget` 接收六个维度。格式列表、最大宽、最大高、解码后最大字节、同时解码份数、在途字节。

空格式列表、重复格式、png、jpeg、webp 以外的媒体类型、缺值、非有限数或非正数，在这里拒绝。本成员不填默认整数。成功对象只有 `imageBudget` 能造出来，六个上限不出现在公开字段上。这个对象持有自己的预留表。另一个成功对象持有另一张表。

调用方通过快照读取预留。只有打开和关闭改这张表。

## 打开

`open` 接收完整字节和预算对象。它不接收取消信号或超时。它在第一次检查前复制本次字节，容器检查、解码、`verifiedBytes` 和声明都基于这份拷贝，不受调用方在异步期间修改原缓冲区影响。

成功结果包含打开句柄、声明和 `verifiedBytes`。`verifiedBytes` 的内容与输入相同，但不是输入对象本身。声明包含媒体类型、定向后的宽、定向后的高，以及不可信。拒绝结果没有字节、没有声明、没有句柄。

检查顺序如下。

1. 在光栅出现之前读取容器。只接受单帧 png、jpeg、webp。空字节、截断、非图像、多帧，以及允许列表之外的格式，在这里拒绝。WebP 的 RIFF 声明总长度大于实际字节长度时按截断拒绝。
2. 方向 6、5、7、8 来自 JPEG 的 APP1、PNG 的 `eXIf` 或 WebP 的 `EXIF` 里的 `0x0112`；该标签必须是 TIFF SHORT 类型且 count 为 1，TIFF magic 须为 42，值在 1 到 8 之间。JPEG 中只有标识为 `Exif\0\0` 的 APP1 进入严格 TIFF 检查，其他 APP1（如 XMP）被忽略。不符合这些条件的方向元数据按截断拒绝，避免预读与实际解码对旋转的解释不一致。这三种方向把存储宽高对调后计入预算。输入字节不被改写。
3. 解码后字节按定向宽乘定向高再乘 4 估计。超过最大宽、最大高或该估计时，在光栅出现之前拒绝。
4. 同时解码份数或在途字节已经放不下这次估计时拒绝，并且不占预留。
5. 检查通过后，在第一次等待之前占上这次预留。
6. 解码失败或抛出时，先释放这次预留，再以解码失败拒绝。此时没有句柄。
7. 解码成功时，句柄拥有光栅和这份预留。

调用方停止等待这次 Promise 时，预留保持到这次打开自己结束。停止等待不关闭句柄，也不证明原生工作已停止。

## 编码

编码只存在于打开句柄上。请求只包含 png、jpeg 或 webp。`encode` 在调用时固定本次请求的 format，该 format 决定编码器和结果元数据；调用方在 await 前修改请求对象不影响本次编码。成功字节的方向标记和 EXIF 缓冲都不存在。`verifiedBytes` 保持为输入内容。编码不改变预留。

编码失败时句柄仍打开。对已经关闭的句柄，编码拒绝为已关闭。

## 关闭

关闭要观察到光栅不再被编码占用并释放预留，才返回关闭句柄。编码仍在进行时，关闭保持打开，预留继续占着。没有观察到光栅释放时，句柄保持打开。

同一资源的关闭句柄只有一个。再次关闭返回这同一个对象，不再次释放。关闭句柄上的原生停止只有未被证明。

## 信任与元数据

声明的信任值只有不可信。解码和编码不提高输入的信任。编码输出不携带方向标记和 EXIF 文本。原始输入里的元数据仍留在 `verifiedBytes`。

## 验证

`pnpm --filter @omne-harness/image test` 从公开入口验证预算拒绝、打开前拒绝、单帧打开、方向、编码、关闭和并发，并从 `./cordis` 验证插件加载失败和撤除。

这次命令在 Darwin 25.5.0 arm64、Node v26.0.0 上通过。解码库是 sharp 0.35.3，libvips 8.18.3。本卡对预算和关闭的平台接受只覆盖 Node 26。成员声明的 Node 范围是 `>=26.0.0 <27`。其他 Node 版本没有运行，也不写成已支持。调用方停止等待的用例用的是 2048×2048 的夹具 PNG 和 1 毫秒超时。压缩膨胀用例是一份不足 100 字节的 PNG，IHDR 声明 4096×4096，夹具的解码后字节上限是 1024。它在光栅出现前以 decoded-bytes 拒绝，预留保持 0。这些夹具数字不是生产上限。原生停止仍是未被证明。未在点名平台上运行的原生库不写成已支持。

`node --expose-gc packages/execution/image/verification/budget-profile-smoke.mjs` 在构建后从包名导入公开入口，用候选推荐配置核对正常、接近宽高与像素上限、宽高与像素超限、并发持有、编码进行中与结束后的预留、编码输出、关闭和调用方停止等待的结果，并读取进程 RSS。格式与在途字节拒绝由两份变体配置核对。2026-10-17 在 Linux 5.15 x86_64、Node v26.12.0、sharp 0.35.3、libvips 8.18.3 上三次运行均退出 0。结果、RSS 读数及其限制见[推荐配置](docs/budget-profile.md#观测)。

服务定义、配置和撤除见[集成](docs/cordis.md)。
