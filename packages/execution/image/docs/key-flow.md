# 图像成员关键流程

状态：技术设计已接受，见 [技术设计接受](https://github.com/nemori-ai/omne-harness-lite/issues/277#issuecomment-6198093789)。行为条件在 [SPEC](../SPEC.md)。类型在 [模型](model.md)。

## 建立预算

调用方把六个维度交给 `imageBudget`。空格式列表、重复格式、png、jpeg、webp 以外的媒体类型、缺值、非有限数或非正数，在这里拒绝。成功对象持有一张空的预留表。另一个成功对象持有另一张表。

## 打开

`open` 接收完整字节和预算对象。它不接收取消信号或超时。

1. 在光栅出现之前读取容器。空字节、截断、非图像、多帧，以及允许列表之外的格式，在这里拒绝。
2. 方向 6、5、7、8 来自 JPEG 的 APP1、PNG 的 `eXIf` 或 WebP 的 `EXIF` 里的 `0x0112`。这三种方向把存储宽高对调后计入预算。输入字节不被改写。
3. 解码后字节按定向宽乘定向高再乘 4 估计。超过最大宽、最大高或该估计时，在光栅出现之前拒绝。
4. 同时解码份数或在途字节已经放不下这次估计时拒绝，并且不占预留。
5. 检查通过后，在第一次等待之前占上这次预留。
6. 解码失败或抛出时，先释放这次预留，再以解码失败拒绝。此时没有句柄。
7. 解码成功时，句柄拥有光栅和这份预留。成功结果同时给出声明和与输入内容相同的 `verifiedBytes`。

调用方停止等待这次 Promise 时，预留保持到这次打开自己结束。停止等待不关闭句柄，也不证明原生工作已停止。

## 编码

编码只在打开句柄上发生。请求只包含 png、jpeg 或 webp。成功字节的方向标记和 EXIF 缓冲都不存在。`verifiedBytes` 保持为输入内容。编码不改变预留。

编码失败时句柄仍打开。对已经关闭的句柄，编码拒绝为已关闭。

## 关闭

关闭要观察到光栅不再被编码占用并释放预留，才返回关闭句柄。编码仍在进行时，关闭保持打开，预留继续占着。没有观察到光栅释放时，句柄保持打开。

同一资源的关闭句柄只有一个。再次关闭返回这同一个对象，不再次释放。

保存原始字节的调用方在打开成功后关闭，不调用编码。准备模型输入的调用方可以先编码，再关闭。
