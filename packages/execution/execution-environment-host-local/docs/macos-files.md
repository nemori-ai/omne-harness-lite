# macOS 宿主文件设施

macOS 后端在宿主提供者内部兑现现有 `files` 协议。它不改变 Files 工具、应用配置、租户身份或隔离声明。行为由[宿主规格](../SPEC.md#宿主文件使用)及其文件扩展和根限制各节约束。

## 目录身份与系统调用

Node 没有目录描述符相对的 `openat` 等接口。macOS 的 `/dev/fd/<fd>/<name>` 不能替代 Linux 的 `/proc/self/fd/<fd>/<name>`。因此后端使用公开 POSIX 接口的 C 辅助程序，每个请求在一个进程内持有所需目录描述符。

TypeScript 层冻结请求，检查输入，绑定根的真实路径与设备号、inode。原生层重新打开根并核对身份。从根开始逐段 `openat(O_DIRECTORY | O_NOFOLLOW)`，每段核对设备号。后续创建、删除、复制和改名都相对已经打开的目录。路径中途被改名或被替换成链接，不改变已持有目录对象。

内容操作在打开后核对对象身份和链接数。配置根时，普通文件有多个硬链接即拒绝内容访问。删除与移动只改变根内的名字，不跟随最后一段链接。路径位置判断复用 `hostSegmentsBelowRoot` 的 POSIX 规则。

## 进程与失败

辅助程序源码随 TypeScript 产物发布。首次使用先检查 Command Line Tools，再用 `/usr/bin/cc` 编译。编译产物按源码内容缓存于当前用户的临时目录。缺少工具时不触发安装对话框。P2 在状态目录或系统临时目录中实际创建并删除文件。每个引擎缓存满足与不满足的结果，未知结果在后续请求重试。有根路径的词法拒绝发生在探测之前。

成功结果必须来自完整、有效的协议回复及正常退出。超时、异常退出、无效协议与不完整结果返回未知。部分外部效果不能降为拒绝。进程退出会关闭它持有的描述符，但不会撤销已经写出的字节或目录项。

## 批次

批次仍使用现有清单与逐项发布协议，不提供多路径原子提交。预检失败不写文件；发布中途失败时保留已经确认的回执。恢复只读清单与目标，不继续发布或回滚。待写字节的摘要匹配不是发布回执。恢复的元数据观察也经过原生层的根身份与逐段核对，不用绝对路径 `lstat` 绕过根守卫。

## APFS

默认 APFS 不区分大小写和 Unicode 规范化形式，目录枚举保留创建时的名字。字节序排序、分页、预算与 UTF-8 检查仍由设施规格决定，同一目录项的不同写法仍指向同一对象。批次不承诺别名路径之间的原子性，重复写法可能在逐项发布时发生冲突。

## 验证范围

实现与验证进度由[测试索引](../tests/index.md)记录。Linux 与 macOS 的同一行为断言保持一致；故障注入分别到达 Node 文件调用与原生系统调用边界。平台前提、真实文件系统行为、设施测试与真实模型装配冒烟分别报告，互不替代。

## 发布握手

批次辅助进程先打开全部参与目录并检查目标，再发送 `checked`。TypeScript 将 `staging` 清单持久化后才确认。辅助进程写完临时文件后发送 `staged`，等待 `publishing` 清单持久化。每项发布前询问封门状态，发布后等待该项回执持久化，再进入下一项。管道断开后不开始下一项发布。

部分发布与进程异常都不能表示回滚。创建目标时 `linkat` 成功而删除临时名字失败，仍记发布回执，并按现有诊断接口报告残留。

## 平台选路依据

在 macOS 26.5.1 arm64 的实际实验中，`/dev/fd/<fd>/<name>` 返回 `ENOENT`，不能复用 Linux 的路径桥。`openat` 等公开调用可以把效果固定在已打开的目录上，因此采用 C 辅助程序。`renameatx_np(RENAME_EXCL)` 对已有目标返回 `EEXIST`，用于不覆盖的目录移动。临时第二 APFS 卷上的移动返回 `EXDEV`，映射为 `unsupported`。原生程序不使用私有 API，也不要求管理员权限。
