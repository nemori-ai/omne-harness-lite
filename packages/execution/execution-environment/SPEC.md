# execution/execution-environment 长期行为候选

状态：具名成员目标的完整行为草案。只有文档目录，运行成员及公开类型尚未成立，[局部技术接受](https://github.com/nemori-ai/omne-harness-lite/issues/268#issuecomment-6187949335)仅覆盖文件使用对象授权、进程退出观察和活动句柄的本次对象及代际语义；其余行为草案不因本次接受转正。本规格维护必要行为，不预造方法、事件、Schema、执行引擎或存储字段。技术义务见[问题](../../../.meta_harness/design/product/execution-environments/design.md#未决问题与待定事项)，不能用公开形状未定抹去以下可检验规则。

## 责任、消费者与采用范围

环境对工具发起方、独立调用方、执行适配、工作区/装配消费者、资源控制者、托管数据消费者及 Context 承诺设施、实际落点、资源条件及真实结果。身份与授权拥有准入，工具拥有原执行和外部效果，工作区拥有逻辑身份及参与，Session/Run 拥有逻辑工作，运行时各自拥有物理生命周期。受控宿主接口与原调用拥有者承接越过执行域寿命的宿主工作，本规格不把这些责任并入一个万能环境对象。

独立消费须提供可核验主体及本次要求；系统组合须明确谁提供可信准入、谁保管调用、谁确认数据保存和谁可靠承接结果。库操作成功不证明系统组合成功。采用范围来自[项目要求](../../../docs/requirements.md)、[正式领域](../../../docs/domains/execution-environments/README.md)、[运行环境](../../../docs/architecture/runtime/execution-environment.md)及[执行隔离](../../../docs/architecture/security/execution-isolation.md)。[阶段选择](https://github.com/nemori-ai/omne-harness-lite/issues/268#issuecomment-6189563335)将 J-EE01 至 J-EE08、CAP-EE01 至 CAP-EE12 纳入单机第一版承诺，不表示产品草案整体接受或实现已完成；本稿及检查不授予尚未明确机制的实施准入。

## 身份、选择与准入

### INV-EE01 身份和事实拥有者分别可辨认

原主体、租户、逻辑工作或独立调用来源、工具调用，以及适用的工作区关联、实际环境、资源代际和托管数据各可定位。逻辑关联不合并身份，路径、节点、Context、插件实例或 isolate 不成为租户权限依据。新环境、相同名称的资源或另一节点不得冒充原实例；查询、控制和恢复指向原事实及所属拥有者。活动句柄不是持久数据格式，精确形状由定义拥有者补足。验证义务 V-EE01。

### INV-EE02 逐工具策略与逐调用实际选择

需要环境的工具按本次合法要求和逐工具策略求值，策略仍受当前授权、组织约束和实际设施限制。一个工具的许可不推导另一个工具的许可；会话保存的策略值不冻结实时授权，不变成固定全局执行位置。always-allow 允许直接使用宿主，auto_place 按合法条件选择环境，never-allow 禁止直接落宿主；这些策略不能解除所需隔离或授予额外动作权。词汇沿正式环境正文，部署缺省值不得猜测。新选择影响后续合法调用，不改写原调用。验证义务 V-EE02。

### INV-EE03 必需设施和隔离不得降低满足

环境及宿主声明真实设施、隔离、绑定/复用条件和可用性。没有匹配、建立失败、所需隔离无法确认或访问条件不成立，拒绝依赖该条件的执行并说明原因，不能静默用宿主、较弱环境、其他资源或不同目标补齐。未声明环境需求的工具只使用其明确声明的直接依赖，不能借此扩大可达能力。动作准入通过不等于资源就绪。验证义务 V-EE03。

### INV-EE04 原主体在实际边界继续受约束

跨边界操作显式携带可信租户和适用主体，资源、文件、网络、数据、桥接、查询、后台及恢复使用均核验当前对应资格及用途。跨租户私有访问默认拒绝，共用宿主、工作区或计算实例不授予读取其他租户资产、配置、凭据或数据的权利。HITL 不解除明确禁止及隔离，工作区文件不是落点或权限授予源。已准入原动作按原控制契约收场，历史事实与结果仍保管；后续调用、读取及向消费者披露不能凭旧批准恢复已经撤销的权利。验证义务 V-EE04。

### INV-EE05 实际执行捕获原输入和版本

工具发起时捕获原调用身份、实际参数和实现依据。需要环境者同时固定实际环境、适用工作区、资源入口及相关策略/提供者版本；未声明环境需求者固定其明确直接依赖，不强制创建环境对象。后续选择、更新、重装配或恢复不得改写原采用。准备得到候选、工作区来源校验、正式装配采用、实际设施就绪及工具开始分别确认；任何一项成功不冒充其他项。未执行的旧建议按当前约定核验，不暗改参数或转到新位置。验证义务 V-EE05。

## 资源、状态与数据寿命

### INV-EE06 逻辑工作、runtime、资源和数据不共用寿命

Session 归档、Run 终态、Agent runtime 销毁、插件卸载、停止准入、代码终止、工具完成、资源关闭和数据删除是不同事实。环境资源不是 Session 的隐式子对象；Model/Tool runtime 不因 Agent 句柄释放自动停止。相应业务控制可以发起资源控制，但逻辑状态不代替物理确认。必要资源保留至原调用完成或责任可靠移交，空闲计算可回收，已承诺数据和待交付结果不能随之丢失。验证义务 V-EE06。

### INV-EE07 临时状态边界与实际回收明确

单次调用沙箱不承诺跨调用状态；会话级沙箱有已声明最大连续寿命，不承诺永久数据保存。达到边界后停止依赖旧环境的新准入，要求回收并报告实际控制/关闭结果；失败或不可观察保持待处置及未知，不假报销毁。新实例使用新身份，不复活旧终端状态；无效终端标识由原设施/工具明确失败，不能默认为一次性执行。原调用结果的保管责任独立于临时设施，必须在临时状态消失时仍有可靠承接路径。重要原创产出不能以“可重算”代替已声明保存。验证义务 V-EE07。

### INV-EE08 租户托管数据不随计算消失

租户级沙箱内数据的有效保存寿命与租户生命周期相应，并须可备份、可迁移。租户仍存续且数据未按合法规则删除时，计算停止、替换或空闲回收，以及技术 TTL 或备份副本的保留窗口，不得自行缩短数据寿命。清理副本不能提前删除其唯一有效托管内容。共享按同租户获准范围成立，不承诺该租户各个 agent 的文件互相隔离；并发写入沿实际资源协议返回真实冲突或结果，不伪装互不影响。

备份、数据保存、目标可读和迁移完成分别确认，记录具体数据及版本、目标、已知完成和未知部分。失败保留原数据及处置责任，不复制无权数据、不以新计算就绪证明保存完成。备份或副本窗口、介质、可恢复位置及物理损毁恢复前提由已采用数据和部署契约声明，不在本规格补定数值，也不承诺任意物理损毁后恢复。合法数据删除及租户生命周期结束后的处置按相应数据规则处理，不推出永久留存。验证义务 V-EE08。

### INV-EE09 资源和秘密以最小必要条件提供

子进程只取得该消费者允许的名单中、宿主实际具有的环境变量，不自动继承整份环境；名单不授予凭据或宿主执行权。另行配置的凭据按其所属契约取得，变量同名不构成许可。文件、网络、挂载和可调用能力按原主体、目标、用途及所需范围供给；工作目录只是起点。授权检查使用时点的使用对象。跟随符号链接时检查目标。声称文件限制的 profile 确认不了使用对象仍在授予根内，或确认不了使用对象就是所检查对象，就拒绝，不退回只检查路径字符串。工具、MCP 和 hook 保留自己的执行准入及生命周期，发现、读取或兼容开启不等于运行许可。诊断、Context、日志和遥测不得以正常内容传播秘密值。验证义务 V-EE09。

## 同进程恶意代码与宿主工作

### INV-EE10 受限执行域限制可达数据和能力

须支持不可信代码在主进程内受限运行，按其可能蓄意窃密、越权或耗尽资源设计。只提供明确输入及获准受控接口；不直接开放宿主内存、其他执行域/租户数据、秘密、原始 Cordis Context、服务容器、任意宿主对象、模块加载或原生扩展。跨界请求和返回值由宿主验证，拒绝伪造身份、超范围目标和权限扩大；持有旧接口或句柄仍受实际使用时的条件限制。普通模块、签名、扫描、Cordis 作用域、node:vm 或进程级权限配置均不单独证明这些保证；无法满足者不得承接该运行方式。验证义务 V-EE10。

### INV-EE11 资源消耗有界且不合作代码可终止

所采用机制须对执行时间、内存、并发、输出和宿主调用实施可执行限额，并能在代码不合作时停止域内代码。终止不依赖代码自愿检查信号，不能被它占住负责终止的同一调度线程；配置、超限原因和实际终止事实可定位。数值和监督安排由具名技术设计采用，不把固定配额或具体引擎写成产品默认。执行域仍依赖引擎、桥接及操作系统，同进程共享进程故障域，不能承诺任意原生崩溃只影响单个插件。验证义务 V-EE11。

### INV-EE12 域停止后原宿主调用及迟到结果仍有人承接

域内代码已停止不意味着已准入宿主调用已停。桥接与原调用拥有者须保留原宿主调用、输出、真实效果及结果交接责任，不能只向已销毁的域返回或丢弃迟到结果。当前消费者缺少披露资格时，保管事实仍存在，按原结果/访问契约说明无法交付或继续等待，不向无权方泄露。恢复定位原调用及消费责任，不重新发起已经执行的动作。验证义务 V-EE12。

## 确认、并发、失败与恢复

### INV-EE13 控制请求与实际停止、释放分别确认

取消、超时、停止准入、合作停止、强制终止、设施退出、资源关闭及数据清理各自说明可作用范围、受理、已确认结果、失败与未知。发出取消信号、dispose、Run 终态或空引用计数不证明物理完成。进程已退出只来自域外监督者对该身份记录的退出码或终止信号。父进程退出不写子进程退出。一次查不到保持未知。超时或没有返回不写成进程已退出。资源关闭确认须对应实际资源和代际；失败仍可查询与处置。外部效果按原工具/能力报告，已经提交的效果不因上层退出声称回滚。验证义务 V-EE13。

### INV-EE14 未知保持原身份，不盲目重放效果

查询不可用、答复丢失、超时或重连失败不等于资源不存在、动作未执行或数据未保存。保留已知事实、未知部分、原准备/控制/调用身份及下一查询责任。原计算确定丢失按工具失联规则收束，不自动重放原工具或宿主动作；恢复先查询、等待或对账，仅在有证据支持未发生或安全后续动作时继续。已确认部分只接续未完成责任，不重复分配、覆盖、删除或执行来制造新“成功”。验证义务 V-EE14。

### INV-EE15 准备、持有、回收与确认保持一致

共享或独占按所声明资源条件成立。独占不得向冲突使用者同时确认，共享持有者退出不误回收仍被合法使用的资源。准备、更新、取消与回收按原资源及代际判定，迟到回执不改写新资源、不覆盖较新选择；确已分配但未采用的资源仍有查询和处置责任。

最终准入与实际发起的竞争由具名协调者保护，条件改变不能凭旧批准发起不同动作。需保留的资源关联、控制和不可重建恢复依据在对外确认前达到所声明耐久边界，覆盖普通进程/操作系统崩溃及断电后的读取解释。跨后端或外部效果不能同提交时分别保留已确认事实、未知阶段及恢复责任，不能用“有事务”略过分配成功而登记失败的反例。提交后通知/响应失败不报告成事实未发生。验证义务 V-EE15。

### INV-EE16 恢复数据、计算与原执行分别验证

数据可恢复只说明相应数据条件；新环境就绪只说明可供新合法调用；两者都不证明旧进程、工具或终端已迁移，旧痕迹仍在，原效果未发生或原动作成功。异构恢复核验数据格式、提供者及资源兼容前提，不能默许无条件热迁移。旧事实用于定位原责任，新的操作仍核验当前授权；恢复本身中断后沿原进度继续，不丢失数据、结果或清理拥有者。验证义务 V-EE16。

### INV-EE17 真实落点、痕迹与诊断可定位且守住披露

准备、选择、排队、资源压力、到期、控制、关闭、数据恢复及其拒绝/失败/未知，均关联原主体、工作、调用、适用环境、资源及实际代码/提供者版本。agent 能取得各工具真实落点和上次状态保留情况；无法确认时明确未知，不能从通知成功推定物理完成。Context 按自己的供给协议消费变化，不由环境自动重做原工作。

查询和观测读取相应权威事实并说明新鲜度，不重做业务操作。必要记录失败及观察过期可见，不能静默转为成功或空集合；内容和敏感位置按访问目的裁剪，凭据不进入普通输出。代码自报不能替代宿主记录的授予、调用和终止事实。验证义务 V-EE17。

### INV-EE18 提供者换代和 Cordis 集成保留原责任

环境提供者声明设施、隔离、版本及所需配置的有效条件，不以统一形状虚构不支持能力。换代明确旧引用、新准入、原资源查询、在途调用和结果责任，撤除注册不丢弃旧工作。根领域消费不依赖 Cordis 业务含义；集成沿 IC 的唯一服务定义、公开纯入口、必需/可选依赖、明确租户及撤除责任。内核重跑、作用域可见性和 disposer 不自动兑现数据授权、实际停止、耐久、进展或跨进程保证。验证义务 V-EE18。

| V-EE14 | 查询失败被当不存在，重连/重启/重建盲目重放外部动作；原身份查询及已知/未知事实，无重复效果 |
| V-EE15 | 并发双重独占、准备后登记失败漏资源、迟到准备覆盖取消、确认后断电丢恢复依据；故障注入和真实提交/恢复证据 |
| V-EE16 | 数据可读被宣称原工具已迁移，恢复中断重复覆盖或用旧权限执行；分别核对数据、计算、工具和当前准入 |
| V-EE17 | 查询重做动作、变化通知伪报痕迹保留、诊断泄露秘密或记录故障隐藏；权威事实与合法 Context/观测消费 |
| V-EE18 | 提供者撤除丢在途/资源，inject 重跑被当全局回滚；缺席、换代、旧引用及真实系统组合检查 |

## 技术采用与未覆盖

公开类型、设施协议、准备与控制查询身份、资源竞争/代际核验、准入与发起边界、数据保存/迁移/恢复、结果保管、受限执行机制及部署监督须由具名拥有者形成可实施设计。具体引擎、桥接 API、数值配额、TTL、存储和节点未选，不需要再投票决定已接受的恶意代码边界。

本规格不选择 provider，不承诺任意 Node 插件兼容、跨节点无条件热迁移或通用外部回滚。真实实现、故障、攻击、资源效果及耐久均未核实；长期性质的验证义务保持，实际采用前须补足对应证据。

## 最小调用事实

本节不是已采用的字段、编码或存储。第一版承诺八段旅程，不表示下面的事实已经有公开类型。后续宿主设施按这些事实交接。精确形状仍由定义拥有者补足。原主体、对象代际和未知规则沿 INV-EE01、INV-EE05 与 INV-EE13，本节不另定一套。

一次文件或进程操作的最小交接如下。同一次请求的输入和它的确认用同一个请求身份关联。后一次动作即使路径相同，也是另一个请求。

| 请求输入 | 对应确认 | 结果由谁承接 |
| --- | --- | --- |
| 主体、档位、原调用身份、这次请求身份、请求路径 | 使用对象及其代际，或未解析 | 执行适配核对。观察与控制记下拒绝、完成或未知 |
| 主体、档位、原调用身份、这次请求身份、要启动的进程 | 实际启动的进程身份，或启动失败 | 环境提供者记下启动是否发生。观察与控制只在该进程身份有回收状态时记下已退出 |

完成只表示这次请求所确认的那一项已经成功。读取完成不表示修改完成。启动被接纳不表示进程已经启动，也不表示进程已经退出。

调用例。主体 A 的原调用是 C。第一次请求 R1 读取路径 `link`。执行适配确认使用对象是代际 G1，且 G1 在授予根内。观察与控制记下 R1 对 G1 的读取完成。第二次请求 R2 修改同一路径。R2 必须重新核对使用对象。R1 的完成不能充当 R2 的结果。若 R2 的使用对象在授予根外，执行适配拒绝 R2。观察与控制记下拒绝。结果不是未知，也不改落宿主机。

另一例。主体 A 的原调用是 C，请求 P1 要启动一个子进程。环境提供者接纳了 P1，但进程映像没有启动。观察与控制记下 P1 启动失败，不记成完成，也不记成已退出。后续查询用 C 和 P1 定位这次尝试。另一条成功分支中，P1 实际启动的进程身份是 PID-1，并绑定 C 与 P1。进程已退出只认监督者对 PID-1 的回收状态。受限 JS 档位把 guest 放在主进程内的专用 Worker 里。选用该档位不能据此推导已经创建了一个独立进程。
