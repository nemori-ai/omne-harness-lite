# 执行环境架构

本页说明成员内部怎样分成落点、设施和宿主文件使用。类型在[模型](model.md)。步骤在[关键流程](key-flow.md)。装配在 [Cordis 集成](cordis.md)。公开行为仍归 [SPEC](../SPEC.md)。

状态：宿主文件使用和 `executionEnvironment` 已有公开入口与包测试。成员其余行为仍是技术设计草案。公开必要行为归 [SPEC](../SPEC.md)。本页拥有成员内部的身份区分、准备顺序和宿主文件使用机制。类型归[模型](model.md)。

## 必要身份与采用依据

| 必须区分 | 消费者须取得的依据 | 不能代替它的内容 |
| --- | --- | --- |
| 原主体与工作 | 可信租户、适用主体、Session/Run 或独立调用来源及原调用关联 | 当前 UI、Cordis Context、isolate 或提供者自身权限 |
| 工具要求与策略 | 工具身份、实现/要求版本、实际参数、当前允许范围及资格解释 | 历史初值、工作区文件、其他工具的许可 |
| 实际环境 | 提供者/版本、环境身份、绑定/复用条件、设施与隔离声明、真实节点依据 | 逻辑工作区、路径、Session 或 Agent runtime 身份 |
| 资源与设施状态 | 本次取得关系、实际资源身份及实例代际、持有条件、控制目标和查询关联 | 名字相同的新资源、取消请求、单一引用计数 |
| 托管数据 | 原租户、数据身份、所承诺保留范围、版本/恢复位置及计算关联 | 运行对象内存布局、新环境就绪或目录仍在 |
| 受限执行域 | 代码身份/修订、所授接口及限制、宿主调用关联、终止原因 | 代码自报身份、签名、普通插件作用域 |
| 原调用事实 | 固定的适用环境、工作区、资源入口或明确直接依赖及版本，真实效果、结果与消费责任 | 新选择、最新配置、重试请求或新的调用 ID |

这里规定可辨认的语义，不预造公开字段、ID 编码或每项独立对象。跨异步、重连、换代及恢复保持原关联；需要耐久的事实用可恢复数据表达，不序列化活动句柄。凭据由相应能力保管，不嵌入普通位置、上下文或遥测。

## 准备、执行与资源状态

状态是可观察事实，非未经设计的字段枚举。至少区别尚未准备、准备中、可用、明确不可用、暂时无法确认、停止接纳、关闭处理中、关闭已确认及仍有处置责任。计算状态、设施状态、工具连续性和数据状态各有判断依据，不能用一个“已停止”覆盖。

需要环境的调用按以下责任顺序完成；没有环境需求的调用核对并固定明确直接依赖后交原工具，不经过虚构环境的分配与就绪：

1. 固定原主体、工作和本次要求，取得合法动作准入及适用环境策略。未声明环境需求者使用自己的明确依赖，不额外虚构沙箱选择。
2. 比较候选的设施、隔离、绑定和当前访问条件。拒绝明确禁止、必需条件缺失及隔离无法确认；候选排序、池化和探测由提供者设计。
3. 取得或分配实际资源，保留原准备身份及结果查询依据。已发生分配但登记/响应失败时保留待核对责任，不能把失败当作没有资源。
4. 确认本次实际资源就绪和使用条件，保护最终准入与发起之间的竞争边界；条件改变则明确拒绝或重新取得合法条件，不借旧批准发起不同动作。
5. 将固定的原调用依据交原工具。需要环境者包括实际环境、适用工作区和资源入口；没有环境需求者固定其明确直接依赖，不虚构环境对象。工具拥有实际执行及效果；环境拥有相应资源观察和控制，不能另造工具成功账。
6. 变化由环境记录真实落点及痕迹，通过 Context 的合法供给协议进入消费者视野。通知只是信息，不能证明迁移、保存或停止已经完成。

会话级寿命达到边界即停止依赖旧环境的新准入，并要求实际回收。处置失败或状态不可确认时保持待处置状态和原查询关联，不重新宣布原实例可用；已准入工具及宿主调用仍按原契约收场。单次调用结束也不抹去尚未可靠交付的结果和账。环境身份重建后不复活旧终端会话或声称未保存状态还在。

## 同进程恶意代码边界

[正式执行隔离](../../../../docs/architecture/security/execution-isolation.md)要求支持主进程内受限执行并按恶意代码设防。环境和代码装配方须提供受限可达的数据与能力、受控宿主接口、使用时授权、宿主验证、可归属事实及独立可执行的资源限额。不能把任意宿主对象、Context、服务容器或模块加载入口传给代码。

所采用机制必须验证不合作代码的终止，不能让恶意代码占住负责终止的同一调度线程。时间、内存、并发、输出和宿主调用分别有适用限额；限额值及执行引擎仍是技术采用，普通模块、node:vm 或进程级权限配置不是充分证明。

代码终止后，桥接与原调用拥有者继续承接已经准入的宿主调用和迟到结果。撤去执行域的返回通道不能删除这些事实；结果保管与向当前获准消费者披露分别负责。同进程依赖执行引擎、宿主桥接及操作系统，仍共享进程故障域。监督与恢复按真实影响处理，不承诺任意原生崩溃只伤一个插件。

## 并发、确认与生命周期

共享资源按声明允许多个持有者，独占资源不能向互相冲突的使用者同时确认独占。准备、替换、停止及回收之间的顺序由资源拥有者保持；迟到的准备/控制回执不能改写另一代资源，也不能覆盖较新选择或取消。已分配的迟到资源仍须识别并处置，不因候选失效而漏掉。

需要确认的资源关系、不可重建恢复依据和控制事实在对外确认前满足[数据与状态](../../../../docs/architecture/data-and-state.md)的耐久边界。原子提交可用时保全同一资源的状态与持有关系；跨后端或外部效果不能同提交时，明确各步已确认事实、未知部分、下一拥有者及恢复位置。不能以“使用事务”略过已创建远端资源但本地失败的分支。

逻辑关联、运行资源、工具和数据独立管理。Session 归档与 Run 终态只按自身规则发起控制，环境不从这些状态直接推断物理已停；Agent/Model/Tool runtime 物理寿命也不由环境统一接管。释放空闲计算前核实原调用、待结果及托管责任已经完成或可靠转交，不能从“没有 Agent 句柄”推断资源无人负责。

租户级沙箱内数据的有效保存寿命与租户生命周期相应，由数据托管者兑现。租户仍存续且数据未按合法规则删除时，计算停止、更换或空闲回收，以及技术 TTL，均不能使数据提前失效或删除。备份或副本窗口、介质、可恢复位置及故障恢复前提由数据和部署拥有者明确；清理副本不能提前删除业务所需的唯一有效托管内容。合法删除及租户结束后的处置沿相应数据规则，不推导永久留存；物理介质损毁恢复仍受已声明故障范围约束。

合法变更只影响后续采用，原调用保存原输入及版本。提供者替换说明旧引用、新准入、资源查询及在途结果如何接续；Cordis inject 的卸载重跑不提供这些业务保证。集成按[IC](../../../../docs/architecture/cordis-integration-conventions.md)维护唯一接缝、纯根入口、明确租户及撤除和在途责任。服务键是 `executionEnvironment`，定义在 `./cordis`。这一页不另造插件树。

## 失效、控制与恢复

| 观察或动作 | 本领域允许确认 | 必须保留或交接 |
| --- | --- | --- |
| 查询失败或地址暂不可达 | 当前无法确认 | 原环境、调用、数据及控制查询责任 |
| 原计算实例确定丢失 | 该计算连续性丢失 | 工具按自身规则对账，数据按托管规则恢复 |
| 代码域终止确认 | 域内代码不能继续执行 | 已准入宿主调用、迟到输出与原结果责任 |
| 取消请求受理 | 原控制意图已接纳 | 实际停止、关闭、外部效果及失败分别待确认 |
| 新环境及数据就绪 | 可供新的合法调用 | 原工具不自动迁移，旧痕迹按事实说明 |
| 计算关闭确认 | 该资源已关闭 | 持久数据、结果和未完清理仍按所属契约保存 |

恢复围绕原身份查询、等待或对账，不盲目重发工具或宿主动作。后续读取和执行仍核验当前资格，旧输入不恢复已撤权利；原执行事实和结果仍被可靠保管，不因披露受限而删除。异构数据恢复须满足格式和提供者兼容条件，不能从数据可读推出原执行可热迁移。


## 宿主文件使用

状态：PanQiWei 已接受这一节的设计，见 [技术设计接受](https://github.com/nemori-ai/omne-harness-lite/issues/278#issuecomment-6197369869)。它不改写上文的准备顺序，也不新建设施目录或沙箱实现。

文件使用发生在落点已经算完之后。条件选择仍按已接受规则决定宿主机或沙箱。环境提供者只对宿主机落点提供这一次文件使用。执行适配核对使用对象。观察与控制按同一次请求身份记下一种结果。`Files()` 消费读取、查看、写入和关闭这四项。编辑、补丁、查找和图片附件留在工具。`Shell()` 不进入这次确认。命令碰到的文件也不进入。

一次使用的结果只能是下面一种。

| 结果 | 同时成立的事实 |
| --- | --- |
| 读取已绑定 | 打开到的设备号与 inode 等于授权点名时的对象。字节来自该对象 |
| 查看或写入已绑定 | 对象身份与点名一致。没有把文件字节当作查看或写入的完成载荷 |
| 关闭已完成 | 该句柄代际有成功回执。没有文件字节 |
| 未解析 | 路径上没有对象。没有读取，也没有写入 |
| 拒绝 | 带有拒绝原因。落点保持为请求里的那一个 |
| 未知 | 请求身份仍在。不知道动作是否已经作用到对象上。关闭没有成功回执时用这一结果 |

句柄代际由使用时点的设备号、inode，以及提供者为这次使用发出的代次组成。同一次设施里，成功的读取、查看和写入各发出一个新代次，从 `1` 递增。元数据版本可以参与对象身份。它单独不是原子的外部写入防护。

授权在使用前点名对象的设备号与 inode。点名可以落在工作区目录之外。工作区目录是地址，不是宿主机上的围栏。未点名则拒绝。路径含空字节则拒绝。

调用方（执行适配/授权层）负责按当前授权点名对象，并把点名结果作为 `named` 提供给本设施；本设施只核对打开到的对象与 `named` 一致。`hostObjectToken` 仅按路径识别当前对象的设备号与 inode，不授予访问权，也不替调用方重新核对授权。

宿主机去掉路径末尾的斜杠，然后用 `O_NOFOLLOW` 打开该路径；打开步骤本身拒绝末段是符号链接的情况，不使用先 `lstat` 再打开的竞态预检。末尾的 `.` 或 `..` 不往父路径收。祖先符号链接本身不构成拒绝。打开后读取描述符的设备号与 inode，与 `named` 一致才读取或写入字节。不一致就关闭描述符并且拒绝。这一步关闭失败，也不把已经确认的不一致改成未知。中间目录被换成链接时，若打开到的对象不是点名对象，结果同样是拒绝。平台路径可以经过符号链接到达点名对象。

公开的 Node 文件接口没有 `openat`。核对发生在打开之后。完成的读取或写入可以声称字节属于点名对象。不能声称内核在拒绝前没有打开过另一个对象。声称把文件限制在授予根内的落点，本成员这次不实现。该类请求拒绝，不改由宿主机执行。授予根是该落点声明的根身份。请求不能另带一个绝对路径充当这个根。

撤权之后的下一次使用重新核对当前授权。上一次已经返回的字节留在那一次结果里。同一路径上的后一次请求使用新的请求身份，并重新点名对象。读取、查看和写入在返回结果前关闭自己打开的描述符。关闭是另一次请求。成功回执表示该代次已经发出并且描述符已在那次使用结束时关闭。再关一次仍是成功回执。没有成功回执时结果是未知。路径含空字节在关闭时同样拒绝。已经读到或写到的结果不因关闭失败被抹掉。调用方丢掉引用不是关闭成功。对已经关闭的描述符再次关闭，不是活句柄关闭失败。

写入在身份一致后先把文件截断，再写入新字节。截断已经发生而后续没有写完时，结果是未知。文件可能已经变短。

活句柄关闭失败由包测试覆盖：读取、查看或写入结束时若描述符关闭失败，对应的句柄代次被记为仍有活描述符；再次调用关闭时若实际关闭仍失败，结果保持未知，不抹掉已返回的读取或写入事实。2026-10-16 在 Node v26.0.0、darwin 上，`FileHandle.close()` 对已经关闭的句柄再调用一次没有报错；句柄关闭之后对原来的 fd 调用 `closeSync` 得到 `ERR_OUT_OF_RANGE`。这两次都不是活句柄还开着时关闭失败。

授权决定可以用替身。文件字节、符号链接和对象替换使用真实文件系统。

## 技术后续设计与来源缺项

以下事项由技术或来源拥有者补足，不转成产品默认值投票。公开形状、机制与证据未定不删除既定必要行为。

### Q-EE02 选择、准备与实际发起的协调边界

维护责任：条件协调、环境资源与原工具调用拥有者。

场景：准备完成后取消、权限变更或新选择到达，迟到准备仍可能已分配资源。

待明确：具名技术设计怎样表达原准备身份、资源代际、最终准入与发起、一致确认及迟到资源处置？

既定约束：

- 动作准入、环境就绪、来源校验、装配采用和原工具发起分别确认。
- 没有环境声明者固定明确直接依赖，不虚构环境对象。
- 迟到资源仍须查询和处置，旧合法采用不能复活已撤访问。

处理方向及后果：

- 采用既有资源/调用协调机制并补足真实环境消费者和故障证据。
- 如既有机制不能承载所需保证，形成有明确消费者的专用责任设计。

先核对实际已有公开承诺，再形成技术设计；公开形状、协调机制和耐久证明不得由本候选猜定。

影响：影响 CAP-EE02、03、06 及 INV-EE03、05、15 的可实施性。

### Q-EE03 受限执行域、宿主桥接与监督证据

维护责任：执行隔离、受控宿主接口、工具与部署拥有者。

场景：恶意代码在主进程内尝试窃密、越权或耗尽资源，终止后宿主调用仍可能返回。

待明确：执行、安全、工具和部署拥有者采用什么机制及桥接边界，怎样证明限额、终止与独立结果承接？

既定约束：

- 支持主进程内受限执行且按恶意代码设防已决定。
- 可达数据/能力、宿主验证、使用时授权、可归属事实、限额及不合作终止分别成立。
- 同进程共享进程故障域；域终止不丢弃已准入宿主调用及迟到结果。

处理方向及后果：

- 提交满足全部已定边界的执行机制、受控接口与监督设计及真实攻击证据。
- 提供者不能满足某运行方式时拒绝承接，并准确记录限制；继续补足目标机制。

保留技术义务，核对具体引擎/API/桥接和配额采用范围；不重开恶意代码边界产品投票。

影响：影响 CAP-EE08、09；机制未验证时不能授予不可信代码该运行方式。

### Q-EE04 托管数据与计算分别恢复

维护责任：数据托管、存储与部署拥有者。

场景：租户仍存续时技术 TTL 到期，或计算关闭、节点丢失、备份及迁移响应丢失后，需要保全未合法删除的租户级沙箱数据及原调用事实。

待明确：数据和部署拥有者如何在满足租户级数据寿命的前提下采用保存机制、兼容协议、备份或副本窗口、迁移和恢复机制，并声明故障范围及跨后端进度？

既定约束：

- 租户级沙箱内数据的有效保存寿命与租户生命周期相应；租户存续且数据未按合法规则删除时，计算停止、更换、空闲回收及技术 TTL 不得自行缩短该寿命。
- 数据保留、备份/迁移、目标可读、新计算就绪及原执行恢复分别确认。
- 未知不降为未发生，不重放外部动作，跨租户私有访问默认拒绝。
- 同租户共享数据不承诺 agent 文件互相隔离；不承诺无条件热迁移。
- 备份或副本窗口只约束对应技术副本，清理不能提前删除唯一有效托管内容；合法删除及租户结束后的处置沿相应数据规则，不推出永久留存或任意物理损毁后的恢复保证。

处理方向及后果：

- 在所选提供者范围定义可恢复数据与确认协议，核对技术副本窗口不缩短业务寿命，并验证部分成功、崩溃和响应丢失。
- 不支持的恢复或异构组合明确拒绝，保留原数据、事实及处置责任。

把备份或副本窗口、介质、兼容和故障证据交具名技术采用，满足既定租户级数据寿命；不补固定默认值，不新增产品投票。

影响：影响 CAP-EE05、10、12 及数据耐久、共享冲突与恢复接受证据。

### Q-EE05 设施控制、观察及原结果交接协议

维护责任：设施提供者、原调用与 Runtime Context 拥有者。

场景：终端状态到期、资源释放失败或执行域停止后，需要查询实际状态并把结果交合法消费者。

待明确：提供者和原调用拥有者怎样公开设施状态、控制/查询、终端失效、结果保管与交接的完整必要行为？

既定约束：

- Session、runtime、设施、计算、数据和原调用各有寿命。
- 控制受理不等于实际停止/关闭；查询不重做动作。
- 原结果保管独立于临时设施，披露按当前资格；Context 只消费真实变化。

处理方向及后果：

- 沿实际设施与工具公开承诺定义控制/查询及交接，保留原身份和真实阶段。
- 设施缺少所需控制或观察时明确能力限制，并禁止以成功占位掩盖未知。

技术设计应覆盖真实设施消费者与迟到结果；本候选不指定 API、TTL 或接口编码。

影响：影响 CAP-EE04、09、11、12 及资源关闭、痕迹供给和结果不丢失。

### Q-EE06 运行实现与真实提供者尚未核实

维护责任：实际提供者、实现与验证拥有者。

场景：阶段选择和技术采用需要目标与实际实现的差距，但本轮只完成文档分解。

待明确：实施与接受前由谁固定实际实现/提供者版本、运行条件和真实消费者，并补足哪些证据？

既定约束：

- 本轮未检查运行时代码、提供者、引擎、资源效果或数据耐久。
- 旧 PF 接受、正式目标、候选结构检查和评审不证明已实现。

处理方向及后果：

- 对已选采用范围实际调查、验证，记录实现状态及限制。
- 在证据取得前继续标记未核实，并保留未覆盖条件。

所有能力保持未核实；不写成未实现，也不从目标文档反推运行保证。

影响：影响能力实现状态、阶段接受与后续施工准入。
