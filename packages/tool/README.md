## 责任与范围

工程范围由[领域责任](../../docs/domains/tool-execution/README.md)与[产品正文](../../.meta_harness/design/product/tool-execution/design.md)约束。本组拥有成员分解、公开依赖、组协作及组合验证导航。

## 成员与依赖

目标成员的职责、状态和读取顺序从[tool 入口](tool/README.md)进入，再按任务核对下面的规格与专题。


状态：候选、待用户确认。仅镜像目标知识位置，没有实际 workspace 成员或 package.json。

本组维护工具调用、执行、结果和外部效果的工程知识，服从[领域协作](../../docs/domains/tool-execution/architecture.md)与[冻结包组织](../../docs/package-organization.md)。当前目标仅具名 `tool/tool`，不为定义、runtime、dummy 或前后台再造平行成员。

| 目标成员 | 承担的行为 | 阅读入口 |
| --- | --- | --- |
| tool/tool | 工具定义、逻辑调用、真实执行、内部等待、控制、结果、执行账和原交付责任 | [SPEC](tool/SPEC.md)，以及其引用的同成员专题。 |

产品的[旅程与能力](../../.meta_harness/design/product/tool-execution/design.md#关键用户旅程)、[关键协作流程](tool/docs/key-flows.md)和[成员验证对照](tool/SPEC.md#旅程能力与验证入口)用于定位组合义务，不是另一份业务规则源。

共同持有、设置和权限归 assets；发起与业务采用归实际协调者；环境归 execution；Skill 资源与 MCP 发现连接分别归其成员。Tool 通过公开能力完成包装动作，不接管被调用领域的业务状态。跨组提交和消息采用协议归真实协调者。

成员根入口应可独立消费，不要求启动 Cordis 或完整 Harness；Cordis 集成沿同成员集成入口和现行 IC 约定。契约不依赖自己的提供者、SDK 或应用，提供者和消费者引用同一公开定义，不穿透兄弟成员源码。

后续增加提供者或独立适配须说明实际消费者、安装或平台依赖隔离、替换和验证收益。类型存在、目录变大和插件可能性不足以决定拆包。组不提供合并 SPEC，成员维护完整行为，组维护导航和依赖边界。

组合验证与本组维护由实际发起、环境和消费协调者共同承担，范围见[成员验证义务](tool/SPEC.md#持续验证义务)。目前未运行工具、存储、并发或外部效果测试，候选不能表示已经实现或接受。


工程关系见[组设计](docs/architecture.md)。成员目标已有文档，不等于真实包；公开入口、安装闭包和提供者映射尚待设计。

## 关键协作

目标 tool/tool 统一承接定义、逻辑调用、真实执行、内部等待、控制、结果及执行账。发起协调者与身份治理、环境、HITL 和原消费方分别承担资格、资源及业务采用；Skill 和 MCP 通过公开行为组合，不以方法读取或连接成功代替动作准入。

流程从[组协作入口](docs/key-flows.md)导航到协调成员。

## 组合验证

Tool 验证原调用、dummy、等待、控制、收场与效果；发起和消费协调者共同验证当前资格、排队撤权、可靠承接、归档迟到和提交未知。提供者验证真实环境、传输、隔离及外部效果，缺环境保留无法验证。尚无真实存储、故障、断电或性能执行证据。

## 维护

修改行为同步成员SPEC、原具名专题、实际消费者及相称验证；修改工程分解同步组导航和登记。具名维护人尚缺，由项目负责人指定；职责拥有者不等于已派发个人。产品、组工程和成员机制分别维护唯一正文。
