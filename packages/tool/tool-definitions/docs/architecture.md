# 内部架构

## 模块与依赖

commands 与 protocol 共同提供声明和解析。author 将它们变为 Tool 公共作者。files 与 shell 只认识各自注入的环境类型，不认识具体提供者或授权系统。

files-edits 先构建 Prepared 列表，再执行单次替换或批次提交。shell-output 仅保留当前句柄、每流解码状态和有界首尾窗口。text 拥有 UTF-8 字节计数、首尾截断及 diff 格式。

## 关键机制与理由

文件变更范围先从同一原文计算，以便拒绝重叠并避免较早替换改变后续匹配。expectedVersion 在设施边界消费，作者不声称提供外部 CAS。Shell 不建立会话表，避免调用者寿命成为终端状态权威。

Shell 创建会话时声明 `retain: 'session'`。指定终端的 execute 和 close_session 先通过当前获取的 attach 核验，再使用设施；缺少保留或附着能力时明确拒绝，不创建替代终端。获取及附着的释放由宿主收场负责，作者不保留原获取或复用旧 origin。

Windows 终端结果表示前台执行结束及一次读端观察窗口，不证明持久 shell 退出或业务成功。前台已写入但尚未读到的字节也可能落入后续窗口；空脚本不保证排空。关闭可以释放尚未交付的空闲缓冲，这些字节不能报告为已交付。已封窗的输出及 Tool 已承接结果不适用该释放规则。此采用依据为 R2-D60，未知退出码保持 unknown。

## 验证与维护

工具环境是本包的限权消费投影。工具包可以先于执行提供者升级：运行时检查目录项名称和可选writeEffect，保留终端操作作为可选增强能力。旧设施缺名称时list整体失败，缺保留/附着能力时session操作unsupported且不启动。名称、写效果和保留语义仍由Execution拥有，本包不解析对象令牌或另建提供者。

行为与限制归 [SPEC](../SPEC.md)。修改命令时同步同一张表和公开入口测试。修改设施门面时同步宿主绑定消费者。当前定向 fixture 不证明真实后端安全或耐久。
