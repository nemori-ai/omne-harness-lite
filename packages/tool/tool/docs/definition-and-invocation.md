# 定义、可用性与发起

状态：候选、待用户确认。本页是 [SPEC](../SPEC.md) 的必要行为专题，不定义精确字段。

## 定义完整性与呈现

Tool Definition 和 Tool Execution 分别存在。定义可附带实现，但数据版本、实现身份和实际运行资源分别可辨。定义采用单函数或多命令形态，能力身份沿现行资产规则，不在本稿补名称字符集或长度。

单函数定义具有工具说明、参数约定及每个参数的说明。多命令定义具有工具说明、合法命令清单及每命令一行说明。作者可以仅提供清单，也可以提供全部命令的完整参数；提供的参数每项须带说明。不完整说明不能冒充完整合法定义。

多命令在模型面前始终是紧凑清单和交给所选命令的参数，不展开全部命令参数。提供完整参数时，系统据此校验，用法入口和可选 help 据此答详细用法。仅清单时，系统不能凭空推导参数校验，实际工具判断参数合法性。help 与统一 inspect 结果一致，不熟命令的动作前取得详细用法。

呈现由装配引用的常驻标记决定，Agent Definition 的明确标记优先于 Plugin。工具作者的定义不拥有这一预算选择。非常驻能力通过发现与取用入口可达，已合法纳入的常驻工具也可搜索，标明可直接调用。呈现位置不放宽实际调用授权。元能力入口沿自身不可移除规则，不在本稿重定完整元能力集合。

## 声明与设置

必需依赖是抽象能力名称的合取，不是指定资产、按次猜提供者或“甲或乙”的表达。可选项不写入必需声明，实际使用时探测。缺一个必需提供者则整个工具不可用；同一名称的候选由合法选择满足，不在定义侧暴露候选优先算法。

可选声明包括外部服务、附件存储、目标环境及设施、参数模态、结果模态、后台许可及转后台阈值。未声明服务或附件则不依赖或不产该类附件，环境没有特殊要求，模态缺省文本，后台许可缺省拒绝。未声明不是允许暗用未披露的设施或对外服务，实际使用必须符合声明及资格。

目标环境声明设置形状及默认，落点与身份类不接受工作区配值。转后台阈值是偏好类设置。前台上限和工具并发上限也是偏好，定义和合法配值均未提供时没有该项限制。共同求值、锁定和许可上界归 settings 与 permissions，不用统一覆盖算法改写其语义。

后台许可是作者对调用方式的许可，不是设置。用户可以在许可内选择何时转后台，不能用阈值或人工批准增加未声明许可。等待、发过程帧和此次返回卸载原文属于实际执行行为，不添加为静态必填声明。

附件依赖检查须包含实际消费者的取回能力和读取资格，不能仅以存储连接成功判可用。会话的模型路径还检查参数与结果模态。调用参数需要的模态由实际模型输出满足，结果模态由模型输入或合法转换满足；不能把两端都只认模型输入，也不能因声明缺口跳过实际可读内容检查。独立调用按自身消费者契约处理，不强制绑定模型。

## 已知与可用的动态关系

装配、每次 attempt 开始和必需提供者变化时，重算合法选择、治理及依赖。提供者恢复不独自恢复工具可用性，当前定义、持有和治理仍须成立。

从未合法取得的定义被过滤时，不新增可见身份，不能凭名称编 schema。已知但卸载、撤权、被禁用或依赖失效时，保留最近合法身份和形状，用不可用说明替换。授权撤销后不得为维持同形读取新的未授权内容。合法新定义可以改变后续采用形状，同形不是永久冻结 schema。

同标识还有合法候选时先按共同选择规则更新实现，不跳过候选直接认定不可用。必需绑定不等于服务永远在线；从未取得必需合法定义或 runtime 自身必要依赖不能建立时，按装配失败处理，不能用 dummy 补齐未知定义。

MCP 每个发现动作是工具条目，动作身份和许可沿合法端点，不成为另一个资产持有对象。每次 attempt 开始及显式合法刷新可更新后续清单。失联保留最近合法取得的清单并给原因，未发现过的动作不编造，对端删除的已知动作仍能解释不可用。Skill 读取和脚本执行分别准入，方法读取不授权任意路径脚本或 Shell。

## dummy 的调用语义

调用已知不可用替换件，无论其收到何种参数，都正常返回具体不可用原因，不执行原件。dummy 沿同类别 Tool Execution 保留原动作、原调用和消费位置，不创建真实原工具执行资源，不执行原功能，也不虚构资源或副作用。替换件本身的实际处理开销如实记录，不能一律预设所有用量为零。

恢复可辨这次不可用结果已取得、待处理或已处理。Agent 替换不重发，未来新调用按新的合法条件判断。不可用提示说明缺哪项条件，不能用无意义失败让调用方反复撞相同缺口。逻辑查询和真实启动、计算计量分别表达，精确字段与统计表示仍待后续设计。

## 发起的完整前提

进入运行时管理的真实发起方须取得以下共同匹配的依据。

1. 合法定义、实际实现和明确动作身份。
2. 完整参数及扩展处理后的生效参数，保留原参数。
3. 当前主体、操作、资源、租户和组织范围及有效准入依据。
4. 允许读取的 Context、适用设置、工作区及数据外传资格。
5. 满足工具需要的环境、设施、资源和凭据。
6. 原用途、结果消费位置、控制责任及已有工作关联。

整批动作判断齐备前，不能执行已经批准的部分。人工批准绑定人所见动作和生效参数，只有明确批准整批才覆盖整批。租户全局授权按当前权限设置资格和组织上界写入，不绕过明确禁止，工作区不提权。

准入后选择环境并准备资源，再进入适用并发排队。环境无法满足、准备失败或无法确认隔离时不执行，说明原因，不静默退回宿主或更宽松环境。无特殊环境声明的工具使用明确直接依赖，不凭空造沙箱要求。

同一 Session、同一工具前后台合计并发，上限超出按发起次序排队，不直接拒绝或报执行失败。内部等待仍属未收场执行。转后台不减少计数。独立调用不套虚构的 Session 限额，其显式资源范围及拒绝、排队策略待实际契约承接。

排队后实际发起重新检查有效推进资格、业务状态、当前授权、定义约定及实现匹配。权限收窄不能因为原参数未变就沿用旧允许。无关 reload 不重复人工判断；决定依据已变化时，不自动借旧批准。新资格与启动共同成立的精确边界由协调者明确并验证。

## 固定采用与参数失败

发起后保留固定的定义、实现、参数、设置、授权、Context、工作区、环境和资源入口。后续合法更新影响后续调用，旧调用不能换函数、暗改参数、迁到更宽松环境或自动重发。失效资源按本次契约处理，不保证永远冻结其可用性。

旧模型建议尚未发出时，调用约定或实现绑定改变不自动执行，也不暗中修参数。原因交合法调用方重新判断，单纯文案变化不自动判为不兼容，未经核对也不宣称兼容。

模型参数块未收齐时不解析、不执行。完整块解析不了时，不调用原工具，返回失败并说明参数问题，保留原模型调用块。后续修正参数是新动作，不能借其成功重写原失败。

Agent 创作工具仍须授权和真实提交归属，不能直接生成组织资产或代用户提升。文件写入不等于装载，合法显式装载后新调用才采用。本页不决定同标识创作入口如何拒绝或新增，不能默认覆盖、持有切换或自动发布。

### TL-V01 定义与动态取用

实际组合须验证两种定义完整性、紧凑命令呈现与 help 一致，不熟命令先取用法。让来源撤权、卸载、必需提供者失效和恢复，检查先选同标识合法候选；已知身份有具体不可用结果，未取得身份不猜造，撤权后不读新说明。分别使用模型输入、输出和合法转换构造两端模态反例；附件只有存储但消费者不能取回时不得判可用。Agent 创作只写合法归属，单纯落文件不等装载，不默认组织提交或覆盖。

<a id="tl-v02"></a>
### TL-V02 发起与逻辑结果

实际消费者须验证完整错误与半截参数均不启动原工具，dummy 对任意参数有原调用结果且不编原工具用量。组合验证整批决定未齐、排队撤权、定义或实现绑定变化与隔离失败，确认实际发起前复核且不暗改参数或退到宿主。观察旧执行和新定义并存，旧采用固定；发起提交未知按原身份对账，不重发效果。无 Session 的函数消费及托管调用分别验证其真实依赖，不把纯函数成功作为运行时持久保证。

TOOL-M01、TOOL-M02 的精确形状、围栏和发起有效边界未采用前，上述为持续义务，不能宣称真实行为已通过。
