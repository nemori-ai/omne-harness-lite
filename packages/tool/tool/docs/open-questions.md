# 工具执行的待细化事项

本页维护技术义务和来源缺证，不授予新产品政策或默认机制。原问题ID保持；建议未获采用，既定边界继续有效。完整行为仍读成员SPEC及具名专题。

<a id="tool-e01"></a>
## TOOL-E01 共享来源缺证引用

本ID沿[MODEL-E01](../../../model/model/docs/architecture.md#model-e01)的唯一事项继续。Tool与消息契约拥有者补齐最终块许可和嵌套依据，Model与Context承接；原块和原可见性保持，实际可读模态检查继续，不把过程帧清单当最终全集，不发明递归协议，原结果不因转换失败删除。

<a id="tool-m01"></a>
## TOOL-M01 公开形状与独立函数消费

两种定义形态和两种返回写法已定，但实际参数校验、名称规则、文本转换及公开接口尚未采用。

后续定义拥有者落实精确类型、必要校验、普通返回转换、构造与操作入口，以及独立函数和 runtime 保证分界。

已定边界如下。

- 完整定义有工具和参数说明，多命令清单紧凑。
- 普通返回统一转 ToolResult，只有结构化返回承接附件和卸载。
- 公开函数可不依赖 runtime、Session、租户和存储，系统托管集成仍须资格。

建议尚未采用。公开形状随实际成员维护，不从源码、目录或候选签名猜定。

影响范围。实施前仍缺精确输入，不改变现已确定的行为。

<a id="tool-m02"></a>
## TOOL-M02 发起、队列、等待与控制的兑现协议

动作在排队或等批次卡片期间撤权，工具完成与停止竞争，原等待跨 Agent 退出仍须接续。

相关拥有者设计发起一致性、稳定身份、队列取消、资源时限和限额生效、答复提交、控制实际确认及自身失联判据。

已定边界如下。

- 实际发起前复核当前资格和匹配绑定。
- 无关 reload 不重复批准，变化不能借旧批准。
- 前后台同一执行，等待当前仅前台，Ask 无超时。
- 查询不可用不证明自身失联，确认丢失不自动重放。

建议尚未采用。用反例和相称并发故障验证明确共同边界，不选择存储或线程。

影响范围。机制尚未兑现，已有准入、等待和控制责任完整保留。

<a id="tool-m03"></a>
## TOOL-M03 原结果可靠承接、全文与账目的精确协议

结果保存提交未知、消费者替换、卸载存储失败、历史原文取回和迟到账目同时存在。

Tool、存储与消费协调者明确引用、承接确认、未知提交对账、分页、限额计量、待结算、诊断投影以及旁路消费协议。

已定边界如下。

- Tool 先可靠保管再执行后扩展；消费者先可靠承接或在 Tool 仍保管时先完成处理并保存必要完成事实，两条交接路径均保留原责任，结果不因消息否决丢失。
- 确认耐久含进程崩溃、OS 崩溃与断电。
- 全文没有到期清理规则，不套 Model ACK。
- 成本真实与未知分辨，账目资格不授正文秘密。

建议尚未采用。原结果和原消费位置保留稳定关联，取消业务不增入队资格，不默认造 Run。

影响范围。未运行存储和消费组合；具体旁路后果仍归其拥有者，不填默认政策。

<a id="tool-m04"></a>
## TOOL-M04 已展示过程内容的故障保留衔接

工具已向用户交付过程块，尚未收尾的快照在原 runtime 内存中，工具自身连续性丢失后需要对齐可追溯承诺。

由流式、Tool、存储和交付面技术设计对齐过程观察与故障保留；只有确需改变用户可见保证时再登记具体产品选择。

已定边界如下。

- 已交付过程不能靠最终结果代替。
- 不默认允许已展示内容丢失。
- 不以收场可靠承接或 Model ACK 声称逐片耐久。
- 不自定每片同步落盘、窗口或数据格式。

建议尚未采用。保留已有内容可追溯承诺和具体未覆盖，先完成技术衔接。

影响范围。该故障边界尚不能声明已证明无丢失，其他结果耐久与控制规则继续。
