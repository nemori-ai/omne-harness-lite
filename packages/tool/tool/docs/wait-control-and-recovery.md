# 等待、控制与恢复

状态：候选、待用户确认。本页是 [SPEC](../SPEC.md) 的必要行为专题，不规定线程、进程或传输协议。

## 前后台的关系边界

前台表示当前步骤等待一次工具结果；后台表示该步骤可继续，原调用之后交付最终结果。两者是等待与交付关系，不是两种 Tool runtime 或生命周期。转后台保持同一原执行、采用输入、效果及账目，不启动第二次工具，不要求更换物理执行位置。

工具作者的后台许可缺省不允许，阈值、前台上限、用户手动或插队都不能放宽。允许后台时，适用自动阈值或用户控制可以转换。支持发起时后台的入口仍检查许可，前台位置当场得到原因“发起时就在后台”的占位。已有后台关系不能再次转后台，也不能转回前台。

转后台占位是前台返回，不是实际执行终局。完成后按原消费者交付最终收场，会话有既存占位时以关联提醒到达，无占位时交原工具返回位置。这种消息关系不授权结果自动进入任何新的 Run。独立消费者遵守自身结果入口，无须模拟会话消息。

## 时限和并发适用范围

前台上限只累计在前台实际运行时间，内部等待时间不计，转后台后不计。达到上限时，允许后台则转后台，否则请求中断并说明前台超时。实际中断结果须由执行方报告，不能把到点请求当成物理停止证明。该原因属于有意中断，不自动重试。

没有定义默认和合法配值时，没有前台上限或并发上限。转后台阈值属于偏好且只在许可后台时可用，不等同于前台上限。精确计时、暂停、恢复和并发设置变更对原采用值的协议待实现明确，但不能将恢复重新计时当作绕过已适用上限。

同一会话同一工具的同时执行计入前台、后台及其内部等待；超额按发起次序排队，不当执行失败。排队是尚未实际执行的状态，开始前重核资格。资源准备或控制受理不是完成，真正执行名额何时获取和释放、队列控制如何恢复由后续契约明确，不能转后台释放后漏计仍运行执行。

## 内部等待与有效答复

Tool Wait State 属于工具执行，保存正在等待的内容形状及原等待身份。它不同于 Run 扩展等待，也不同于调用方等待 Tool 结果。本候选的需答复工具只在前台等待，输入可来自人、系统或其他 Agent。

Ask 等人的等待无超时、无默认答案，当前不转后台。前台上限不计算这段时间。释放 Agent 句柄、物理等待资源退出、客户端断线或查询失败，均不作废原仍有效等待，不能以超时推定人拒绝或批准。在工具自身失联的故障分支，须确认原执行终局才使卡片作废，不填答案。合法控制和业务取消的失效分支继续按原规则处理，不要求先发生失联。

答复核对当前主体资格、原请求及仍有效等待。同一卡片只有一次有效决定，决策池和会话界面共享这一决定。卡片和有效决定归 HITL，Tool 保管原等待及接续依据；动作授权解释归身份与授权，不由 Tool 或交付面代定。普通输入继续可靠受理，不能以普通聊天代替原卡片答复。有效答复与等待状态、后续责任共同保存，重复答复不能重复后续效果。

人明确“不回答”表示没有答案，属于有效答复，不是失败，也不授权动作。卡片跳过与明确插队解除按原人工契约记录不同控制原因，不能把无答案填成同意。控制、原执行终局及已取消业务可能使卡片失效，历史答复与关闭事实仍保留。

其他确实占用资源的等待可以依其专有契约设时限，到期按等不到应答处理，不编造应答。Ask 不适用这项时限。未采用具体资源政策时不设统一等待期限。

## 单次控制与实际效果

用户可以在当前资格内单独停止或许可内转后台一次工具，不要求模型或 Run 同步结束。Agent 只能沿既有后台控制规则停止自己发起的后台执行，不能凭获得句柄扩大到其他租户或其他发起者。独立调用者提供明确控制责任及合法范围。

控制绑定原调用和目标，保留发起主体、原因、请求、受理及实际结果。重复控制核对既有结果，不重复建立调用。完成和中断竞争时保存实际先后和效果，不能把真实完成伪报为未执行。控制不能自动撤销历史内容或费用。

用户手动中断、插队转后台、插队中断、前台超时、Run 取消、归档以及 Agent 对自己后台执行的停止，原因分别可辨。归档和 Run 取消先影响业务资格，再传播控制。工具自身异常连续性丢失属于失败，不能和有意中断混成同一原因。

提供者须说明真实控制能力。可请求不等于能强制停止远端，不可撤回操作不能通过 disposer、终止本地等待或关闭连接声称已逆转。控制未完成继续保留跟踪责任和实际缺口，迟到结果归原调用。

## Run 取消与 Session 归档

Run 取消先可靠保存取消意图，撤销新工作推进资格，再向关联模型和前台工具传播停止。后台工具、子会话及无关的 Run 外调用不自动跟随。Tool 报告实际收场，Run 逻辑终态归会话治理，不由已销毁 Agent 最后写回作为必要前提。

Session 归档在业务上取消该会话全部原未完成请求和调用，解除等待及后续推进依赖，不等待所有 Tool 确认物理停止。停止请求向前台和后台工具传播，子会话级联归档沿 Session 规则。归档事实和控制实际结果分别保存。

已发执行可能继续产生真实效果。Tool 继续保管原结果、真实收场和成本，不把归档后的真实成功伪报物理中断。结果不能恢复业务推进、创建 Run 或恢复入队资格。撤销归档不重启旧调用，控制后的真实状态也不倒退。

取消或归档不冒充消费成功。原消费者不再需要推进时，仍按原契约保存必要历史和未结责任，不能双方都删数据。后台与 Run 外结果的旁路采用后果由原消费者维护，不默认归入后继工作。

## 接续原调用与确认自身失联

合法接手者读取原调用、当前工作资格、取消状态、原消费位置及责任，按以下事实接续。

| 可核实事实 | 合法处理 |
| --- | --- |
| 仅 Agent 或等待句柄退出，Tool 仍运行 | 认回原身份和句柄，继续观察或等待，不重发。 |
| Tool 已收场、结果未交接 | 向原生产方取结果，可靠承接后回原位置。 |
| 结果已可靠交接但处理未完 | 从消费侧保存位置继续，不再重跑原工具。 |
| 查询暂时不可用 | 保留未知，按策略等待或报告，不断言丢失。 |
| Tool 自身可靠确认失去连续性 | 失败收束，原因异常中断，不自动重放。 |
| 原工作已终态或已取消 | 仅处理允许的迟到事实、结果和账目，不恢复推进。 |

环境失效、实例丢失和客户端断线按真实故障域判断。换机器或新建环境不证明原调用可以热迁移，恢复字节不证明旧进程停止。确认工具自身丢失的判据、发现和补收协议待提供者与协调者设计，不能仅以单次查不到、超时或无返回判断。

确认为工具自身丢失后，前台原结果位置补失败及异常中断原因，已有后台占位则补原最终结果位置的关联提醒。没有 Agent 的独立消费者也须能辨认这次真实失败，不必为通知造 Session。补收沿原身份，不产生第二次工具，也不使已终态 Run 改终态。

外部效果单独表达已发生、已知未发生或未知。没有结果不证明未执行，失败不证明外部回滚，稳定幂等身份也不证明对端去重。系统不自动重放，合法调用方可以在当前资格内核查、补偿或另起动作，各自记录独立操作和实际结果。

## 持久、资源与退出

原调用和采用依据、有效答复、控制、结果、交接和账目保存确认须包含进程崩溃、操作系统崩溃与断电耐久，不能只存运行实例内存。确认丢失按原身份对账，读取不可用不伪装对象不存在。

长期等待可以释放不再需要的活跃计算资源，但必须保留原等待和接续责任；资源回收不能自行终结业务等待。确实依赖不可恢复物理资源的具体工具须明确其失联和终局边界，不能从概念独立性宣称任意函数都能恢复。

不可信执行域终止不自动停止已准入的宿主调用。桥接与真实调用拥有者承接控制及迟到结果，不能只向已销毁域返回。环境变量、文件、网络与服务只给获准范围，终止机制须独立于恶意代码协作，具体实现另待采用与验证。

已确认持久事实和介质物理损毁分别处理。灾后安全开放不能据旧备份恢复撤权或造管理员，本域不补定未采用的恢复资格。没有可靠保存和准入依赖时，新动作不假装继续；现存原调用仍须保管、报告和对账，不能被集成退出无声遗弃。

## 旅程与持续验证

[TL-J03](../../../../.meta_harness/design/product/tool-execution/design.md#tl-j03)、[TL-J04](../../../../.meta_harness/design/product/tool-execution/design.md#tl-j04)和 [TL-J07](../../../../.meta_harness/design/product/tool-execution/design.md#tl-j07)分别对应 [TL-F03](key-flows.md#tl-f03)、[TL-F04](key-flows.md#tl-f04)和 [TL-F07](key-flows.md#tl-f07)。本页拥有其等待、控制和恢复行为，能力范围见 [SPEC 对照](../SPEC.md#旅程能力与验证入口)。

<a id="tl-v03"></a>
### TL-V03 等待关系与名额

验证未声明后台许可时阈值、上限、手动和插队均不放宽；允许时只向后台转换一次，输入、身份、效果和名额不变。前台实际计时不计内部等待，转后台后停止累计；没有合法值不加限制。前后台与内部等待合计并发，超额顺序排队，转后台不漏计仍运行执行。后台终局只交完成、失败或中断，恢复认回原关系，不启动新工具。

<a id="tl-v04"></a>
### TL-V04 原等待与决定

组合验证 Ask 长期等待、普通消息、不回答、重复或失权答复、卡片出卡后交付面断线、Agent 退出和合法控制。Ask 无超时默认答案或后台，普通输入不代答；有效决定回原等待且只生效一次，出卡、决定成立和处理异步可接续。取消与答复竞争由原拥有者裁定，失效不补答案；查询失败不作废有效卡片，自身丢失分支须确认原执行终局。

<a id="tl-v07"></a>
### TL-V07 控制取消与恢复

验证单次工具停止不自动停止模型或整个 Run；Run 取消只控制前台关联，Session 归档取消全部原未完成业务并请求前后台控制，不等物理全停。完成与停止竞争、归档后的真实结果和费用均按原调用追加，不伪报未执行、不复活工作，撤销归档不重启旧调用。分别故障注入仅 Agent 退出、查询不可用、Tool 自身确认丢失、外部提交未知、保存失败和消费者替换；认回句柄或原结果、不重发，效果未知不写未发生。

持久验证须覆盖进程崩溃、OS 崩溃和断电及唯一附件副本，资源释放或隔离域退出不替代宿主迟到结果责任。无 Session 程序的查询、停止、恢复与真实归属也须验证。TOOL-M02、TOOL-M03 的精确协议未采用和真实故障环境缺失时，保留未覆盖，不用图、mock 或仅进程重启声称完整兑现。
