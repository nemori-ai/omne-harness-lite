# tool/tool 长期行为规格

状态：候选、待用户确认。目标成员尚未因本稿创建，公开形状、提供者和机制未采用。本规格完整维护类型之外的必要行为；精确类型和必要运行时校验须由后续实际公开定义拥有，不从旧实现倒推。

## 用途、调用方与公开边界

本成员向 Agent 动作协调者、独立程序消费者，以及 Skill 脚本和 MCP 动作桥接提供工具定义消费和一次 Tool Execution 的行为。查询、观察、停止及许可内的转后台应可通过公开契约使用，不强制消费者驱动完整 Agent Loop 或创建 Session。

公开执行函数和运行时管理接口分别提供。纯函数或显式依赖的执行闭包可以只处理调用方给出的输入，不依赖 Tool runtime、Session、租户或存储，也不承担只在运行时层成立的持久关联、交接和治理保证。系统托管资源访问及需要接续的执行由实际集成方明确身份、授权、存储和运行时责任，不能把函数层独立使用当成省略这些责任的许可。内部解析、判定、投影、传输适配和执行者同样通过明确输入与依赖可替换、可单独取用。

本成员拥有原逻辑调用、真实执行、内部等待、控制实际结果、真实收场、原结果、效果确定性、执行账及相应交付状态。它不拥有共同资产治理、身份许可、环境设施、包装工具操作的业务对象、Run 终态或模型请求组装。调用某领域接口不直接写该领域私有状态。

根公开入口须可在满足显式依赖后独立使用。Cordis 装配在集成入口适配，同成员定义、行为和提供者不得因共同打包合并生命周期。本规格服从[产品](../../../.meta_harness/design/product/tool-execution/design.md)、[领域协作](../../../docs/domains/tool-execution/architecture.md)、[冻结成员规则](../../../docs/member-documentation.md)和已接受架构。

完整必要专题共同构成本规格。

- [定义、可用性与发起](docs/definition-and-invocation.md)维护定义完整性、前提、匹配、排队及 dummy。
- [结果、过程与保管](docs/results-and-retention.md)维护返回、过程帧、账目、可靠承接、卸载与消息消费边界。
- [等待、控制与恢复](docs/wait-control-and-recovery.md)维护前后台关系、内部等待、取消、故障及迟到。

## 共同不变量

1. 一个逻辑工具调用保留独立原身份和原用途。转后台、消费者替换和换 attempt 不另发一次原调用。
2. 原调用的定义、实现、参数、设置、获准 Context、授权依据、工作区、环境和资源入口相互匹配，发起后不暗换。
3. 已知、可用、获准分别判断。dummy 的归类见产品[定义、已知能力与一次执行](../../../.meta_harness/design/product/tool-execution/design.md#定义已知能力与一次执行)。真实原工具未启动。
4. 前台和后台仅改变调用方等待及结果交付方式，同一次 Tool Execution 的寿命、结果和费用责任不变。转换只从前台到后台，不返回前台，不释放仍运行的并发名额。
5. Agent 或最后句柄退出不取消执行，当前权限和工作状态在实际发起前复核。
6. 控制意图、受理、逻辑取消和物理停止分别可查，外部效果不因资源释放宣称可逆。
7. Tool 先可靠保管真实原结果，再进入执行后扩展和消息准入。消费者可先可靠承接或在 Tool 仍保管时先完成处理，两者按[结果专题](docs/results-and-retention.md#先可靠承接再处理结果)兑现。业务拒绝不丢原结果，不重做效果。
8. 结果回原消费位置。独立调用不造 Session 或 Run，后台和已终态工作不自动指派给后继 Run。
9. 可靠交接前原生产者保管，交接后消费者有足够接续依据，不留下责任空档或重复逻辑承接。一般后台结果仍有合法投递资格时，Session 按其规则承接后继工作；Tool 不自行建 Run，不反转原 Run 终态。
10. 工具全文不套用 Model ACK 清理，不因压缩、归档、Run 结束或已消费删除。
11. 查询失败不等于工具丢失。确认工具自身连续性丢失时，不自动重放，效果和费用未知如实表达。
12. 已确认持久事实经受进程崩溃、操作系统崩溃和断电。确认丢失按原身份对账。

## 身份、作用域与资格

进入运行时管理或访问系统托管资源的调用方声明真实主体、适用租户和组织归属、操作资源范围、原用途、消费和控制责任。工作区及已有 Session、Run、attempt、step、动作关联在适用时保留，不能把 Session、Run、step 三项当成同一步多个效果的唯一身份。独立调用保留自己的工作和调用身份，不生成不存在的关联。

访问系统托管数据与资源时，独立集成方兑现等价的身份、权限、环境和外传契约。模型可读 Context、工具可读 Context 和扩展可读 Context 分别筛选。只给执行所需的输入和获准接口，不能给不可信代码原始 Cordis Context、全局容器或全部宿主数据。

执行前、观察、查询、取结果、消费及导出各自核对当前资格。历史写入授权不能永久授予读取权。成本资格按原租户及组织范围判断，不由账目访问放宽正文、附件和秘密读取。

## 必要持久事实与确认

下表列举本成员须能恢复辨认的业务依据，不规定 Schema、存储表或事件溯源方法。

| 事实范围 | 必须能回答的问题 |
| --- | --- |
| 原逻辑调用与采用依据 | 哪一次、谁发起、为哪项工作、采用什么匹配定义和输入，是否真实启动？ |
| 排队和发起状态 | 当前为何等待，是否仍有发起资格，实际启动或发出是否已经成立？ |
| 内部等待及答复 | 等什么，哪个原等待仍有效，什么有效答复已成立，是否有当前合法处理者？ |
| 控制意图和实际结果 | 谁对哪个目标请求何种控制，是否受理，执行是否真的停止，是否仍待控制或收场？ |
| 真实收场与原内容 | 前台返回还是最终终局，原因是什么，效果已知还是未知，原文和附件在哪里？ |
| 原位置及交接责任 | 内容由谁保管，消费是否已承接，恢复从哪里继续，取消是否已移除业务推进资格？ |
| 执行账和财务关联 | 实际时长、用量、费用、未知或待结算项，原调用和真实尝试是什么？ |

运行资源、订阅和句柄可以重建。权威事实与查询投影须标明来源和覆盖进度，不能凭展示缓存判定准入、终态或交接已经成立。恢复不能仅查 Session log，当前条件和原 Tool 状态各由其拥有者取得。

对上述应保存事实的确认必须在达到普通进程崩溃、操作系统崩溃和断电耐久后发出。已确认多媒体内容的字节或可恢复引用也在此边界内。只指向短寿命沙箱、临时文件或即将失效地址不成立。物理介质可读取及部署满足声明存储条件是前提，介质损毁的灾后政策另待。

事实共同成立、单次受理、有效答复与等待更新、调用发起与当前资格、交接关系解除的精确提交边界由相关拥有者明示。明确未提交和提交结果未知分别处理。未知时使用原身份查询对账，不直接新建有外部效果的调用。

## 结果与失败范围

完成、失败、不可用、转后台、被中断、等不到应答是给调用方的语义结果。转后台是前台返回，不是最终执行完成。当前后台最终收场仅为完成、失败或被中断。完整参数解析失败不执行原工具，按失败说明；未收齐不解析。

能在本层按工具契约解释的结果以正常返回交付，不伪装系统异常。工具实现、资源或保管故障若不能在当前契约内收束，向其外层责任者上交身份、阶段和分类，保留原调用和未结责任。不能把“实现炸了”机械当成功返回，也不能把本层无法可靠保存结果转换成已经交接。

停止新准入、控制已发执行和撤销读取分别处理。关键准入、当前资格或必要保存不可用时，阻止依赖允许或确认的新动作。可选依赖或过程观察故障按实际范围降级。取消等待提交不证明远端回滚；框架 disposer 不证明工具停止或效果撤销。

## 并发、重放与恢复

同一原调用的重复查询、通知、控制和交接须能核对已发生事实，不重复逻辑承接或原账目。工具真实执行的效果是否去重，取决于具体外部操作协议；稳定身份本身不保证外部恰好执行一次。

并发控制、完成、取消、归档、答复和消费者替换须在拥有者处裁定有效结果。原执行真实完成和调用方不再需要结果可以同时为真。不得为维持简化状态表把迟到真实完成改写成物理中断。

Agent 换代后认回原 Tool；工具自身确认丢失后失败收束且不自动重放。新合法动作与恢复原调用分别记录。已终态 Run 只补允许的真实结果或费用，不复活推进。其余具体行为归[等待控制专题](docs/wait-control-and-recovery.md)。

## 持续验证义务

本成员和实际组合须保留可复跑的针对性验证，结论绑定版本、环境、前提和未覆盖。所需证据包括以下范围。

| 验证责任 | 具体反例与必要结果 |
| --- | --- |
| 定义及发起 | 缺参数说明、help 不一致、schema 或实现更新、完整错误参数、半截参数。不得猜用法或执行半截，旧建议不得盲发。 |
| 资格与环境组合 | 一批批准尚未齐备，已批准动作被撤权；排队期间归档；所需隔离失败。不得借旧批准发起或退到宿主。 |
| dummy | 已知不可用和从未取得定义分别处理。dummy 不启动原工具，有原消费结果，不编用量。 |
| 并发与前后台 | 同会话同工具前后台共同计数、按顺序排队、转后台不改原执行身份、阈值不能扩大许可。 |
| 等待与控制 | Ask 长期等待、普通消息、无答案答复、重复或失权答复、Agent 退出。不得超时批准或关闭仍有效原等待。 |
| 独立调用与动态采用 | 三份合法输入依赖齐全、缺失、恢复；旧调用与新定义并存；无 Session 查询和停止。不得偷建 Session 或改旧函数。 |
| 原结果及交接 | 保存失败、提交未知、确认丢失、消费者替换、扩展失败及消息否决。原结果仍有责任者，不重跑效果。 |
| 后台与终态 | 原 Run 已完成，后台结果转换失败；归档后真实结果到达。不得改旧终态、造后继 Run 或恢复入队资格。 |
| 全文及附件 | 卸载摘要、机械首尾、分页新调用、压缩和归档后的取回、地址失效。不能留空链接或套 Model ACK 删除。 |
| 失联与效果 | 查询不可用、仅 Agent 丢失、Tool 自身确认丢失、外部提交未知。不得从查不到推断未执行或自动重放。 |
| 账目与观测 | 重复通知不重计；新调用真实计量；费用迟到、未知；账目读取与正文权限分别核对。 |
| 耐久与安全 | 进程崩溃、OS 崩溃、断电、附件唯一副本、恶意代码和外传。证据覆盖声明的故障与隔离，不能只靠 mock。 |

真实外部效果、控制和隔离缺环境时报告无法验证。长期查询、结果分页、重连快照和排队须有资源边界；具体规模、时间和成本目标仍由相关契约与性能设计明确，不能以“点查询”声称任意全文常数成本。

## 实施前缺项与维护

公开类型、运行时校验、定义格式、名称规则、普通返回的文本转换规则、控制受理与停止确认、队列取消、稳定身份和跨提供者提交协议尚待实际设计。需要持久接续的等待，须明确哪些状态可以恢复和如何判定自身丢失，不能从一个工具函数的异步形状推断已有恢复能力。

最终结果允许块全集及嵌套投影沿 MODEL-E01 保留来源证据缺口，已知文本、图片、模型可见性及实际模态校验仍有效。过程在途内容故障保留需技术衔接。明确缺项见[问题登记](../../../.meta_harness/design/product/tool-execution/design.md#未决问题与待定事项)，不将精确 API、引擎和数值伪装为产品问题。

修改定义、调用匹配、结果保管或控制协议时同步独立消费者、Agent、Session、环境、HITL、Skill、MCP、Context 和相应验证。提供者补自己真实承担的机制与限制，不另写一份更弱的公共保证。当前没有运行实现、存储或故障测试，本稿不授予实施或符合性接受。
