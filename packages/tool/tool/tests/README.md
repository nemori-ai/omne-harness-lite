# tool 成员测试

测试经包名导入本包。行为测试的名字以 [SPEC](../SPEC.md) 所属规则的编号开头，`pnpm exec vitest run -t "<名字前缀>"` 可单独运行。设了 `OMNE_TEST_TIER` 时，vitest 先静态解析用例名再过滤，`it.each` 展开后的完整名字匹配不到，用名字前缀即可。

| 文件                                                   | 检查的行为                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [public-entry.spec.ts](public-entry.spec.ts)           | 根入口只导出 `createIndependentToolScope` 与 `executeTool`。根入口的源码、产物和声明导入图都不含 Cordis、`tool-cordis-contract` 与 `tool-host-local`。清单依赖契约包，不依赖它们。到 Cordis 的生产依赖路径只有经 `kernel-basis` 的两条                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| [independent-scope.spec.ts](independent-scope.spec.ts) | 1：上限不是正安全整数、缺字段、多字段或信号不是 AbortSignal 时拒绝；作用域的 mode 与 signal。3：复制并编号更新，按受理顺序交接；非法更新不占位；并发 emit 顺序；模式固定与封块；无接收者 `unsupported`。4：单条过大 `too-large`；缓冲满 `capacity` 且不排队；未封块累计超限 `too-large`。5：屏障后转发并按 key 共享；同 key 异输入 `conflict`；另一 key `busy`；历史上限拒绝新 key 并保留旧 key；无提供者 `unsupported`；Ask 带 deadline 与非法 deadline `invalid`。6：回答前中止得 `cancelled`，之后新原语 `cancelled`；已交出的回答不撤销。7：`finish` 立即关闭受理并汇合输出；同 exit 同一结果，异 exit `conflict`；有活动等待时 `returned` 失败并关闭等待；`failed` 不等待卡住的输出；取消盖过 `returned`。9：接收者或提供者抛出成为 `unknown` 值；接收者的失败按值返回并破坏屏障 |
| [execute-tool.spec.ts](execute-tool.spec.ts)           | 2：作者拿到 `scope.context`，收尾后得到 R；非独立作用域或非法上限不调用作者，`effect` 为 `not-started`。8：作者抛出走 `finish('failed')`，`effect` 为 `unknown`；`returned` 收尾失败（活动等待、取消）是失败不是成功；R 在屏障成立后才返回                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| [execution.spec-d.ts](execution.spec-d.ts)             | 两个函数的签名与契约包 public-api 接受的形状一致                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| [construction.spec-d.ts](construction.spec-d.ts)       | 构造形状可从根入口导入：配置扩展作者限额，依赖列出 runtime 消费的端口                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| [scope-values.ts](scope-values.ts)                     | 行为测试的构造器与可控端口：逐条放行的接收者、逐条回答的提供者、等待契约与请求                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| [module-graph.ts](module-graph.ts)                     | 导入图遍历工具。各 Tool 包各有一份同样的副本，因为测试不能跨包导入相对路径                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

运行命令为 `OMNE_TEST_TIER=fast pnpm --filter @omne-harness/tool test`。该命令先构建，再运行 vitest，并对 `*.spec-d.ts` 做类型检查。

固定输入归 [fixtures](fixtures/index.md)。目录导航见 [index](index.md)。
