# SnapshotCache：账本事务用上次的快照决定写入

本目录的模型检查 Tool 账本的一条读写规则：账本保留上一次整域读或上一次提交之后的快照，决定下一次写入时不再读存储；纯读先向存储点查一次域修订号，修订号没变才用快照作答。规则归 `tool` 的 [SPEC](../../../SPEC.md#账本事务的快照)。模型只证明列出的有限状态，不证明实现。

## 1. 建模的对象

一个账本域。存储只接受带期望修订号的提交：期望等于当前修订号才写入。写者有两类：带快照的账本，以及任意多个不带快照的其他写者（清扫、另一个进程里的账本）。存储的内容抽象成已写入的写序列，某个修订号下的内容由这个序列决定。

| 变量 | 含义 |
| --- | --- |
| `store` | 已写入的写序列，长度就是域修订号 |
| `cache` | 账本的快照：一个写序列，或没有 |
| `pending` | 账本在途的一次提交：期望修订号与要写的内容 |
| `answered`、`asked` | 最近一次纯读答出的内容，以及它向存储发问时存储的内容 |

## 2. 动作

`OtherCommit`（别的写者提交）、`FullRead`（没有快照时整域读）、`Send`（按快照决定并发出提交，不读）、`Committed`（存储答已提交，快照随同一次写前进）、`Conflict`（存储答冲突，丢掉快照）、`Unknown`（答复丢失，写可能生效也可能没有，丢掉快照）、`PureRead`（点查修订号，相等用快照，不等整域读）。

## 3. 性质

| 名称 | 含义 |
| --- | --- |
| `SnapshotIsStoreAtItsRevision` | 快照的修订号等于存储的修订号时，快照就是存储的内容 |
| `SnapshotIsAPastContent` | 快照总是存储曾经有过的内容。所以按它决定的写要么被存储在同一修订号接受，要么被拒 |
| `PureReadIsFresh` | 纯读答出的是它向存储发问那一刻的内容 |

“按过期快照决定的写不会生效”不需要单列：存储的条件提交保证它，模型里就是 `Committed` 的前提。

## 4. 配置

| 配置 | 去掉的规则 | 必须命中 |
| --- | --- | --- |
| `positive` | 无 | 三条不变式都成立 |
| `assume-applied` | 答复未知时把快照当作已写入而前进 | `SnapshotIsAPastContent` |
| `read-without-check` | 纯读不点查修订号，直接用快照 | `PureReadIsFresh` |

答复未知时保留旧快照不前进也是安全的（它仍是过去的内容）。实现选择丢掉，少一种状态。

## 5. 运行

```
TLA2TOOLS_JAR=<TLC 1.7.4 的 jar> python3 check.py --out <输出目录>
```

## 6. 模型到代码

源码在 `packages/tool/tool/src/ledger-transactions.ts`。

| 模型 | 源码 |
| --- | --- |
| `FullRead` | `readDomain` 与 `whole`：整域读，结果成为保留的快照 |
| `Send` | `transact`：有快照时按它决定，不读 |
| `Committed`、`Conflict`、`Unknown` | `commit`：按答复前进或丢掉快照；`applied` 把写入集作用到记录上 |
| `PureRead` | `read` 与 `current`；`transact` 里不带提交的答复 |

判据用例：`tests/ledger-snapshot.spec.ts`。

## 7. 模型不覆盖的

- 快照怎样由写入集算出（放入、删除、整域删除）。它由用例守：每次提交后的快照与冷读逐条相等。
- 同一进程里并发的两次事务。它们各自提交，后到的被存储拒绝，走 `Conflict`。
- 到期索引。它不进快照。
