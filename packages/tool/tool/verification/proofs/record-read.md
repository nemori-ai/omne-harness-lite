# 单键读取保持域 CAS 的论证

适用范围是 `ToolLedgerStore.readRecord`。本论证不新增状态机，也不证明 SQL 提供者的事务实现。

## 前提与模型

域身份 `d` 包含租户、域种类和域键。域状态为 `D(d) = (r, M)`，`M` 是账本键到记录的有限映射。缺失键记为 `⊥`。

1. 每次成功提交在一个线性化点完成。其条件是 `expected = r`，其结果是原子更新 `M` 并写入调用方提供的新域修订号。调用方不复用旧修订号。
2. 完整读取返回同一线性化点的 `(r, M)`。单键读取返回该点的 `(r, M[k])`。
3. 读取失败返回 `unavailable`，不产生有效快照。实现的修订号与记录不能来自不同的读事务。

定义投影 `πk(r, M) = (r, M[k])`。单键读取是完整快照的投影，但实现只取目标记录。

## 保持的性质

**目标值等价。** 同一线性化点下，单键值由映射定义等于完整快照中该键的值。缺失时两者均为 `⊥`。单键结果不包含可被误认为完整域的记录集合。

**写冲突不变。** 消费者从任一读取取得 `r` 后提交 CAS。没有介入提交时，两种读取的提交条件相同。有任意成功提交介入时，包括只改另一键或空写集的提交，域修订号均推进，因此旧 `r` 的 CAS 均拒绝。单键查询不能把域级冲突降为记录级冲突。

**读取无副作用。** 投影不改变 `D`。因此重复单键读取不影响原提交序列，也不增加生命周期或清理责任。

**域隔离。** 查询先固定完整 `d`，再固定 `k`。改变租户、域种类或域键会选择另一映射，不能取得原域的记录。

## 实现与反例守护

- 内存仓以域内 Map 的 `get(key)` 取值，并复制结果。
- SQL worker 在原 `domain-serial` 读取内查询域修订和 `(tenant, kind, name, key)` 主键。读取不可用和缺失分开返回。端口对格式与请求键再次核对。
- `toolLedgerStoreConformance` 的 `store.record-*` 用例约束缺失、删除、租户和域隔离、引用复制、其他键写入后的旧修订冲突及读取故障。
- SQL 的 `record-read-live.spec.ts` 使用真实 worker，检验完整域超过字节上限时目标读取仍可完成，并检验其他键写入后的旧修订冲突。
- host 的 `runtime-composition/forwarding.spec.ts` 拒绝完整来源域读取，仍要求公开结果读回与原槽恢复成功。撤权和退休竞争仍须拒绝披露。

来源宿主的 `nextRevision`、`nextSourceRevision` 和账本的 `nextRevision` 以递增值兑现修订号前提。本论证不覆盖违规提供相同或回退修订号的自定义写者。

这些运行用例约束实现对前提的符合性，不是对所有执行轨迹的证明。磁盘损坏、进程崩溃和 SQL 调度器的线性化保证仍归各提供者。性能结论另由 W3 的完整历史成本实验给出。
