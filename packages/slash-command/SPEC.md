# Slash Command

## 总体架构

Slash Command 包组回答一个问题：一个会话此刻能用名字点名哪些东西，一段人打的字里哪些斜杠点了名、点的是哪一项，点中之后交出什么。它把各来源交出的[入口项](../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-command-entry--入口项--command-entry)合成一个会话的清单，用一个纯函数认出命令与引用，在会话受理的解析一步里核对发送方所见、取内容并展开。它不存任何来源的事实，不另造队列、日志、流程状态或授权。

下表是责任，不是包。成员按它划分，一个成员可以承担几项。

| 责任 | 回答的问题 |
| --- | --- |
| 识别与匹配 | 一段文字里哪些斜杠是候选，按清单各绑到什么；正在敲的片段该给哪些候选；采用一项之后文字变成什么 |
| 清单 | 向登记着的各入口来源现问，合成这个会话此刻的清单；哪一部分取不到 |
| 解析 | 受理时按当下的清单再认一遍，比对发送方所见，取内容并展开，答输入、操作请求或拒收 |
| 对外 | 读清单的协议与「可能变了」的观察；输入框助手与「命令与快捷键」页 |

识别与匹配是纯契约，不依赖 Cordis 与存储；客户端、命令行与受理侧导入同一个函数。清单与解析在服务端，经 Cordis 接到会话受理与各来源上。

## 领域边界

本组拥有：入口项的形状与三种种类；名字的词法、全名与短名的解析；识别规则；补全与匹配；清单的合成与「无法判断」；发送方所见的形状与比对；解析器的答复；提示词命令的定义校验与展开。

本组不拥有：Skill 的目录、正文与读取权（Skill）；提示词命令的持有、来源、同名替换与锁定（资产）；当前权限（身份与授权）；受理流水线、消息提交、待处理与会话日志（Session）；系统命令真正做的操作（各操作的拥有者）；外壳的动作表、按键分发与键位（客户端外壳与桌面应用）；账号偏好的存储（身份）。

本组声明、由别人实现的拓展点：

| 拓展点 | 实现方 | 本组需要它做什么 |
| --- | --- | --- |
| 入口来源（服务端，按来源的名字放） | Skill、资产、各系统命令的拥有者 | 列出：按宿主给的租户、主体与会话，交这个会话此刻的入口项，或答取不到。取用：被点名时交这一项的内容块，或一个操作请求，或答取不到。可以交一个「我的项可能变了」的订阅 |

本组为别人实现的端口：

| 端口 | 对方 | 本组提供什么 |
| --- | --- | --- |
| 解析器 `session.utterance-resolver` | Session | 把一段要解析的人打的字判成输入（带生效内容）、操作请求或拒收（带原因） |
| 识别与匹配的纯函数 | 交付面、命令行 | 与受理侧同一份识别，及补全的候选与采用 |
| 提示词命令的类别判断 | 资产 | 名字、保留空间、定义与参数声明合不合法，写明第一处不合格 |

入口来源照[拓展点的共同契约](../../docs/architecture/cross-cutting-concepts.md#拓展点的共同契约)答十问，与工具的[条目来源](../tool/SPEC.md#条目来源)同构：在服务端；按来源的名字放，一个名字至多一项；宿主每次显式给租户、主体与会话，不从插件实例或当前客户端推断；每次现取，不缓存；一个来源出错只有它那一部分答依据不可用；撤下时先不接新的取用，在途的各有结局；契约带主版本与修订号。

## 心智模型

清单是一个视图，不是一张表。人每次读、受理每次认，都向各来源现问；Skill 装上、卸下、换版、撤权，只改 Skill 领域背后的事实，下一次读就是新的。通知只说「可能变了」，用来让人的菜单早一点更新，丢了也不影响对错：受理侧从不读客户端的清单。

敲出来的命令带着它看到的东西去：开头是哪条命令、引用了哪几份。服务端照当下认一遍，一样就受理，不一样就整条拒收并说明哪一项变了。它不替人猜原本想要什么。

一处斜杠是不是候选只由文字决定；清单只决定它绑到什么。名字按位置解析：在开头，命令先于 Skill；在句中，只认 Skill。拿掉一项可能让开头的一个短名改绑到另一项，所以「少一项不会多出引用」不成立，靠看得见的标记与所见比对守住。

最容易想错的地方：客户端的清单与预检不是授权；点了名不放宽 Skill 的读取权；取得正文不等于已受理；系统命令的摘要不是那个操作的状态；无权与不存在是同一个回答；清单取不到是无法判断，不是空。

## 应然设计

### 入口项与种类

- 入口项恰有三种：引用型、提示词命令、系统命令。位置由种类定：引用型在任何位置，另两种只在开头。种类名里不出现任何来源的名字；本组的源码不认识来源是谁。
- 每一项带：全名、短名、种类、给人看的一句话、参数提示（命令型）、此刻能不能用及原因、一轮在跑时怎样（系统命令：立刻做或拒绝）、什么时候生效（立刻、下一次模型请求起、下一轮起）。还有只在服务端用的一半：交给哪个来源取用。清单发给客户端时只带公开的一半。
- 控制与界面动作不在清单里。它们是客户端外壳的动作；被敲成 `/stop` 这类写法时由客户端就地执行，不提交。从别处直接送到服务端的这种文字得到「没有这个命令」。

### 名字

- 名字的词法沿 Skill：`[a-z0-9]+(-[a-z0-9]+)*`。全名是 `<空间>:<名字>`，至多 64 个字符；大写照认，折成小写。
- 空间由来源登记时声明，一个来源一个空间。保留空间 `omne-official` 只有装配标为官方的来源能用；租户的东西只经引用型与提示词命令两个来源进来，所以进不了保留空间。同一个空间里两个来源交出同名项，两项都不生效并记一条错误。
- 短名是不带空间的名字。开头：系统命令先于提示词命令先于引用型；句中：只认引用型。全名在任何位置都只指它那一项，按它的种类判位置。

### 识别

一处斜杠是**候选**，要同时满足：

1. 不在代码里：不在一对反引号之间，不在三个反引号围起的块里。
2. 左边：是输入的开头（前面只有空白），或者左边的字符不是英文字母、数字、`_ / . : ~ < \ - = & ? # % @ + $ *` 之一。
3. 斜杠后面紧跟一个合词法的名字，取最长的（可带一个空间前缀）。
4. 右边：名字后面是结尾，或者不是 `/ _ \ = @ *`，也不是「点加字母或数字」。

`\/` 表示这个斜杠是文字。人的话连同反斜杠原样存、原样给模型；只有识别把它当文字。然后查清单：

| 候选在哪 | 清单里 | 结果 |
| --- | --- | --- |
| 开头 | 命令型，能用 | 命令；后面整段是参数，参数里不再认引用 |
| 开头 | 引用型，能用 | 引用；接着认后面的 |
| 开头 | 没有（含无权看见） | 拒绝：没有这个命令 |
| 开头 | 有，此刻不能用 | 拒绝，带原因 |
| 句中 | 引用型，能用 | 引用 |
| 句中 | 其余 | 文字；补全与标记里写明「认得但这里不算」及原因 |

识别的结果是：开头的命令（或没有）、各处引用的区间与全名、提示与被拒的原因、去掉转义之后的文字。同一份文字、同一份清单，结果相同。

### 补全与匹配

- 光标前是「一个候选的斜杠加正在敲的名字片段」时给候选。片段全是名字字符，或全是非英文字符（按说明搜）。斜杠在开头，列命令与引用型；在句中，只列引用型；开头已是一条命令时参数里不给。
- 匹配五档，按档排：一模一样；开头相同；某一段的开头相同；首字母或跳着匹配；说明里有。同一档里：能用的在前，系统命令、提示词命令、引用型的次序，名字短的在前，再按字母。
- 采用一项时写入这个位置能直接用的最短写法，并保证名字与后文分得开：采用之后，那一项在那个位置一定被认出。
- 清单按名字排好；前两档二分找区间，后三档线性扫描，只在前面不够时跑。

### 清单

- 清单 = 向每个登记着的入口来源现问的结果之和，按发问的租户、主体与会话。不存，不靠通知保持正确。
- 一个来源答不出时，它的名字记进清单的 `missing`，其余照常。装配声明应当有的来源不在登记里，也记进 `missing`。清单取不到不是空。
- 「可能变了」的观察合并各来源的变化订阅，帧里不带内容；客户端收到就重读，重连也重读，被拒收「变了」之后也重读，不轮询。

### 解析（受理的解析一步）

Session 的受理流水线在取到来源声明、算出「文字要解析」之后，看会话状态之前，调解析器。只有成员本人经交付面发的输入要解析；系统主体送来的文字不解析。

1. 按当下的清单认这段文字。
2. 开头是候选而被拒：答拒收，带「没有这个命令」或「此刻不能用」及原因，不入队。无权与不存在同一个回答。
3. 请求带了发送方所见，且与认出的不一样：答拒收，写明哪一项变了。所见只比开头的命令与引用的全名集合，不比版本。没带所见的，照认出的受理，回执写明绑定了什么。
4. 一样：取用。解析器只在人的话后面追加，从不改人的话。引用：向来源取每份被引用项此刻胜出的那一版的内容，各成一块文字块，带来路标记（全名、层、版本、包摘要），追加在人的话之后；同一份只带一次。提示词命令：取这一版的提示词，代入参数，作为一块带来路标记的文字块追加在人的话之后。系统命令：答一个操作请求，交 Session 用自己的操作去做。
5. 任何一份取不到：整条答依据不可用，不发出半份，不从旧缓存或别的同名项补。
6. 解析器的生效内容是受理前处理的起点：脱敏这类处理件看到的是展开之后的内容。
7. 原输入、生效内容与绑定到的全名与版本在同一次受理提交里成立。之后那一项改了、卸了，不改历史。

来路标记只能由解析器写；发送方带来的拒收。

### 提示词命令

- 资产的一个类别（`prompt`），目录型：目录里只有一个 `PROMPT.md`，头部写 `name`、`description` 与可选的 `argument-hint`，正文是提示词；工作区里放在 `.omne/prompts/<名字>/`。空间 `prompt`。哪一份生效照资产的层：工作区的盖租户的；工作区那一层只在会话的一轮里有，和 Skill 一样。停用的在清单里灰着并写明原因，取用时当作不在清单里。
- 占位只有两种：定长的位置参数 `$1` 到 `$n`，与剩下的全部 `$ARGUMENTS`。没写占位时参数空一行接在提示词后面。参数按空白切分，引号括起的算一个。
- 发布时的类别判断写明第一处不合格：定义不完整、名字不合词法、想占保留空间、占位超出参数提示的个数（写了参数提示时，`$n` 的 n 不大于它列出的参数个数）。类别的说明带一份可以照抄的最小例子，`OmneExtensions` 的 `help` 按类别给出它。

### 系统命令

- 一个官方来源交出系统命令，取用答会话已有的操作请求。它不产生给模型的消息，不进待处理；做的是那个操作，过它原来的访问裁定。会话里留下命令名、参数与结果摘要。
- 「一轮在跑时怎样」与「什么时候生效」是给人看的声明；真正的拒绝来自原操作自己。要等到安全点的命令与排着的话怎样排先后，没有真的命令需要它之前不定。

### 成员与协议

- 成员：纯契约 `slash-command-contract`（值、识别、匹配、补全、所见、核对、入口来源的形状与判定）；实现 `slash-command`（合成清单，之后的解析器）；Cordis 契约 `slash-command-cordis-contract`（入口来源拓展点的服务与清单服务）；协议 `slash-command-protocol`；接入插件 `slash-command-access`；界面模块 `slash-command-ui`（输入框的帮手：读清单、听「可能变了」、断线重连与被拒收「变了」之后重读，把输入框的逻辑接上会话的界面模块给的助手口）。输入框的逻辑（菜单的四个状态与九种操作、标记、灰字、发不出去的原因与所见）是纯契约里的 `createComposer`。界面模块不依赖纯契约，由应用的装配把它交给界面模块（`createSlashCommandUiModule({ composer })`），所以客户端用的就是受理侧的那个识别函数。命令行直接调纯契约：文字里有斜杠时先读清单、认出所见，随输入交出，回执写所见。Skill 一侧的来源在 `packages/skills/skill-command-source`。提示词命令的类别、哪一份生效与它的入口来源在 `prompt-command-source`，由服务端的一行登记类别、接上来源。
- 协议 `slash-command/1`：读清单 `read-catalog`（租户与会话，答公开的一半与 `missing`），与观察 `observe-catalog`（开在一个会话上，帧只说「可能变了」）。一个登录读某个会话的清单，先要会话自己许它读这个会话；清单按会话的工作主体与这一轮的作用域合成，与这个会话里 agent 经 `Skills` 读到的同一份。

### 失败、取消与生命周期

- 结果分别说清：交付面没发出、拒绝、所见对不上被拒收、依据不可用、已受理、操作已交出、结果未知。
- 回执丢了按原请求认回：同一个请求身份再送，认回原来的结果，不重新展开。
- 来源撤下用作用域的排空：先不接新的取用，在途的各有结局。解析器取不到而装配声明它应当在：需要它的输入答依据不可用。
- 接缝显式携带租户、主体与目标会话。

## 原则与约束

- 清单是视图：每次现问来源，不存，不靠通知保持正确。
- 带上看到的，服务端再判：对不上拒收，不替人猜。
- 一个识别函数，客户端、命令行与受理侧共用。
- 引用不改写人的话，不运行脚本，不放宽读取权。
- 本组不认识任何来源：源码里没有来源的名字。
- 结果不知道就是不知道：按原请求认回，不重新展开，不重做操作。

## 不变式

| 编号 | 永远成立的性质 | 违反的后果 | 由什么守 |
| --- | --- | --- | --- |
| C-I1 | 同一段文字、同一份清单，识别结果相同；客户端、机读面、受理侧用同一个函数 | 人看到的和受理的不一样 | 纯契约里的一个函数；案例表与性质检验 |
| C-I2 | 一处斜杠是不是候选只由文字决定；清单只决定它绑不绑 | 清单一变，路径与网址被认成命令 | 识别函数的构造；性质检验 |
| C-I3 | 开头的候选不在清单里、无权、此刻不能用：拒绝，不入队，不当普通话；无权与不存在同一个回答 | 泄露无权命令的存在，或敲错的命令发给了模型 | 解析器；发行树用例 |
| C-I4 | 句中的候选不在清单里是普通文字 | 句中的路径被拒 | 识别函数；案例表 |
| C-I5 | 命令型只在开头成立 | 句中的一个词触发了系统操作 | 识别函数按位置解析短名；案例表 |
| C-I6 | 受理的含义等于发送方看到的含义；不等就拒收，输入不入队 | 人以为引用了，实际没带上，或反之 | 解析器比对所见；TLC `AsShown` |
| C-I7 | 被撤权或被拿掉的项受理时绑不上，不管客户端相信什么 | 借客户端旧状态拿到无权的内容 | 解析器按当下的清单认；TLC `NoRevoked` |
| C-I8 | 有明确的办法发送任何含斜杠的文字 | 有的话发不出去 | 反斜杠规则；性质检验 |
| C-I9 | 引用不改写人的话；正文各成一块，来路是块的属性，存着的正文逐字不变 | 人的话被改，或正文冒充人说的话 | 展开；来路标记只能由解析器写 |
| C-I10 | 引用不执行脚本，不放宽 Skill 的读取权 | 点名变成提权 | 取正文走 Skill 的读取闸门 |
| C-I11 | 清单取不到是无法判断，不是空；一个来源取不到只有它那一部分无法判断 | 故障被呈现成「没有命令」 | 清单的 `missing` |
| C-I12 | 本组不存任何来源的事实，也不认识任何一个来源是谁 | 装卸一个能力要第三个领域跟着动 | 清单每次现取；源码里没有来源的名字 |
| C-I13 | 系统命令不产生给模型的消息，不进待处理；做的是原操作，过原来的访问裁定 | 系统命令变成一句话发给模型，或绕过访问裁定 | 解析器答操作请求；Session 用自己的操作执行 |
| C-I14 | 只有成员本人经交付面发的输入才解析 | 定时任务或连接件里的文字触发命令 | 来源声明算出的「文字要解析」 |
| C-I15 | 原内容、生效内容与绑定依据在同一次受理提交里成立；之后那一项改了、卸了不改历史 | 历史按新定义被改写，或受理了而依据丢失 | Session 的受理提交 |
