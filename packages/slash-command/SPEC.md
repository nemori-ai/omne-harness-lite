# Slash Command

## 总体架构

Slash Command 包组回答一个问题：用户用一个可辨认的名字主动发起内容输入或系统业务时，这个名字怎样定义、怎样进入一个会话的命令集、怎样被识别与展开，展开的结果又怎样交给原受理与原流程的拥有者，而不另造一份队列、日志、流程状态或授权。

下表是责任，不是包。成员按它划分，一个成员可以承担几项，也可以分开承担；不为未定的归属开空包，不复制同一份公开形状。

| 责任       | 回答的问题                                                             |
| ---------- | ---------------------------------------------------------------------- |
| 命令定义   | 一条命令叫什么、绑定到哪一种目标、带哪些参数声明，定义合不合法         |
| 命令集采用 | 一个会话此刻能识别哪些命令，依据哪一次采用，怎样刷新、怎样撤除         |
| 识别与展开 | 一段输入是不是命令，参数怎样解析，绑定的内容怎样取出并展开成用户内容   |
| 交付面适配 | 人读与机读的交付面怎样用同一份识别定义呈现命令、提示参数、在发送前预检 |

命令定义经资产的合法来源进入命令集采用；采用协调者把一份合法、一致的集合发布给一个会话。交付面按这份集合识别输入开头的命令并预检，发出之后原受理协调者重新核验当前集合、绑定与资格。提示词与 Skill 绑定由识别与展开形成实际用户内容，沿原消息的路径受理；系统流程绑定交给真正的流程拥有者执行。识别与展开可以由显式给出主体、定义与内容来源的程序直接使用，不需要启动 Cordis 或 Agent Loop。

## 领域边界

本组拥有：命令名、保留命名、三种绑定与参数声明的定义校验；一个会话的命令集采用、来源与版本依据、刷新与撤除边界；统一的识别语法、参数校验与展开结果。

本组不拥有：命令的共同持有、来源、同名替换与锁定（资产）；Skill 的正文、资源与读取资格（Skill）；当前权限（身份与授权）；输入受理、消息提交、队列、会话日志与 Run 的承接（Session）；系统流程的准入、执行、结果与恢复（各流程的拥有者）；结构变化时的完整校验与交接（装配）；键盘控制（交互）与 shell 命令（执行环境）；呈现本身（交付面）。原受理协调者是相邻领域的组合责任，不是本组的第二份队列或持久服务。

本组声明、由别人实现的端口：

| 端口           | 对方               | 本组需要它做什么                                                               |
| -------------- | ------------------ | ------------------------------------------------------------------------------ |
| 命令来源       | 资产               | 按有效读取条件给出合法来源与定义版本；不可读时明确失败                         |
| 当前资格       | 身份与授权         | 在发布、展示、受理与展开的边界给出这个主体此刻的资格                           |
| Skill 正文取用 | Skill              | 按原租户、所选方法与读取用途核验后，返回实际正文、版本、来源与范围，或明确失败 |
| 结构交接       | 装配               | 命令集变化改变了捕获的运行结构时，校验完整构成并安全交接                       |
| 流程执行       | 各系统流程的拥有者 | 接过一个合法动作，给出受理、拒绝或未知，并按原操作身份接受查询与控制           |

本组为别人实现的端口：

| 端口       | 对方                           | 本组提供什么                                                       |
| ---------- | ------------------------------ | ------------------------------------------------------------------ |
| 定义校验   | 资产（发布命令时）             | 名字、保留命名空间、绑定与参数声明合不合法                         |
| 当前命令集 | 交付面、Session 的原受理协调者 | 一个会话此刻合法的命令集，带来源、新鲜度与「无法判断」             |
| 识别与展开 | 交付面、Session 的原受理协调者 | 同一份识别定义下的名字、参数与绑定，以及本次合法定义的实际展开内容 |

## 心智模型

把一条命令想成贴在一样已有东西上的快捷签：签上写着名字，后面是一段提示词、一个 Skill 或一个系统流程。按下这张签，相当于用户自己把那段内容打进来，或者亲手去按那个流程的按钮。所以命令的结果总落在别人的路径上：内容走消息的受理与提交，流程走流程自己的执行与恢复。命令只决定「这是哪一张签、签后面是什么、这个人此刻能不能按」。

会话的命令集是采用点上定下的一份记录，不是现算的视图：内容与绑定的变化等用户选择的刷新才采用，但撤权从下一次使用起立刻生效，不等刷新。客户端看到的集合只是投影，受理侧每次都重新核验。

最容易想错的地方：客户端预检通过不是授权；绑定一个 Skill 不放宽 Skill 自己的读取资格；读取成功、展开成功都不等于消息已受理；系统流程的摘要不是流程的状态；无权的命令与不存在的命令得到同一个回答；查不到命令集是「无法判断」，不是空集合。

## 应然设计

### 定义与命名

- 命令名是身份。绑定恰有三种：命令自带的提示词、可取用的 Skill、系统流程。前两种产生用户消息内容；系统流程由实际能力执行，不产生普通消息，也不产生入队资格。
- 绑定与参数声明随定义，不从分层设置读取另一份绑定；绑定目标或参数改变以修订或同名替换表达，不让同一份命令在不同层变成不同定义。参数声明为每一项给人看的提示。
- 系统流程与交付面动作使用保留命名空间 `omne-official`。提示词与 Skill 绑定即使由官方提供也不占用它；保留命名空间按前缀边界保护，不只按现有名单保护。
- 无创作或提交资格、名字非法、定义不完整、来源不可读或绑定无法校验时明确失败：不发布半份命令，不从别的同名来源拼补正文或参数。取得文件不证明命令已进入会话命令集。
- 定义是数据，不为每一条命令建运行时对象。

### 识别与语法

- 只识别经交付面输入、位于开头的至多一条命令。正文中间的斜线文本，以及来自连接件、定时或其他非交付面来源的同样文字，都是普通内容。有一种明确的原样输入方式，让以斜线开头的文本走普通内容路径。
- 声明了参数的命令按声明解析，解析失败不发送；没有声明时，名字之后的整段文本作为自由参数。
- 人读交付面、机读交付面与受理侧的再次解析共用一份识别定义：同一输入得到同一名字、参数与绑定含义。名字编码、前缀边界、分隔符、参数与引用方式、原样输入的拼法与错误形状只有一份定义，不让客户端各自解释。
- 无权的命令不可见；敲下它与敲不存在的名字得到同一个回答，不发送，也不改作普通消息。参数不合法时说明哪里不对并留在交付面，不成为一次入站。

### 命令集与资格

- 会话命令集由合法装配、指定范围的 reload，或系统流程失效后的自动刷新发布。来源读取成功只是候选；定义校验与正式采用分别确认。
- 当前资格在每一次实际使用的边界现核，不等命令集刷新。客户端预检与预展开不能代替受理侧的复核。
- 命令集取不到时回答「无法判断」，不把查询故障当成空集合。
- 交付面的展示是可失效的读面，说明来源与新鲜度，不成为授权依据。断线重连重新取当前读面，不用旧缓存恢复已撤销的资格。
- 命令集不沿用 Tool 与 Skill 的不可用占位规则：无权的入口始终不可见。
- 接缝显式携带可信租户、适用主体与目标 Session；不从 Runtime Context、插件实例、路径或当前客户端推断身份，也不按会话身份反查租户。

### 受理与内容交接

- 受理侧复核目标 Session、当前命令集与绑定、实际资格。名字已失效时具名拒绝：不入队，不触发流程，不回退为普通话；拒绝事实由原受理拥有者记录。
- 提示词绑定在受理时取本次定义的正文与参数。Skill 绑定取得合法的实际正文：正文逐字成为一个内容块，用户参数另成一块，来源是块的属性，不写进正文冒充正文文字。Skill 的读取资格由 Skill 自己核验，命令不借绑定关系替 Skill 放权；只缺必需依赖时，读取照常返回正文并写明缺项。这条路径与工具 read 的返回分开：不执行脚本，不生成 Skill 激活状态，不写成工具执行记录。
- 正文或参数取不到、一致的版本不能成立或资格已失效时，不以空展开或部分正文表示成功。
- 展开后的内容进入落盘前扩展。脱敏作用于展开内容，持久事实是获准保存的结果；否决时原命令与展开正文一起不成为消息正文，拒绝事实可查询、用户可见。命令标注与诊断不成为被拦内容或脱敏前全文的副本。
- 一次受理关联原输入、命令名、合法参数、本次定义与绑定、实际展开内容或可靠引用、来源与范围、原消息位置。原消息拥有者在对外确认之前达到它声明的耐久边界。读取成功、展开成功都不等于消息已受理；命令不建第二份队列，不决定是否新建 Run。
- 固定的实际输入与合法资格在相应的提交边界上共同成立。原子性由具名的同一次提交或跨拥有者的交接协议给出，不从同一个函数调用、同一个进程或同一个数据库推出。
- 回执丢失时按原请求查询原消息，不按更新后的定义重新展开、重复投递。用户再次提交是一次新输入；技术重传按原受理认回，两者不按文字相同混同。
- 之后的命令或 Skill 更新不改历史正文、原输入或已经发出的模型请求。

### 系统流程

- 原受理协调者把合法动作交给真正的流程拥有者。命令受理不产生用户消息或待处理资格；会话只留下命令名、参数与结果摘要。流程是否改日志、控制运行、产生资源或外部效果，由该流程的契约决定。
- 摘要不是流程的状态。摘要丢失不让已发生的效果再执行一次，也不替代流程的实际操作身份、提交与恢复位置。
- 流程服务缺席或拒绝时，先报告这一次真实的失败，再自动刷新会话命令集，使失效的入口不再可见。刷新失败单独可见：不声称命令已消失，不把失败的执行报告成成功；再次使用仍按当前条件核验。
- 取消等待不等于流程物理停止。结果未知按原操作查询，不盲目重做有副作用的动作；迟到的结果归原操作。
- reload 是点名的流程族；别的具体流程不因被举作例子而成为支持承诺。

### 刷新与撤权

- 内容、定义与绑定的变化只在对应范围的 reload 或重新装配时采用，不在用户不知情时暗换。新授予等刷新；撤权从下一次使用起立刻生效。reload 只读取它请求的来源范围。
- 候选不完整、来源故障或校验失败时，保留原采用记录，本次未生效可见，不发布半新半旧的集合；原记录不延续已撤销的权利。
- 只更新注册表数据不要求重建 Agent runtime。同一 Session 的 Agent Definition 标识在创建时固定，刷新只能采用同一标识的新版本，不能更换身份。改变捕获的 Loop、extension 或直接必要入口时，由装配校验完整构成并安全交接：保留原 Run，开始新的 attempt，旧调用、旧清单与结果位置不原地改写。
- 连续刷新、较新的选择、撤权、取消与迟到候选交错时，由采用协调者保护当前合法的状态：旧回调不发布过期的集合，不把旧结果交给新请求，不抹掉他方的合法贡献，不恢复整个旧的全局快照。自定义的换代或恢复协议要有行为模型。

### 失败、取消与生命周期

- 结果分别说清：交付面未发送、受理侧拒绝、已展开未提交、消息已受理、流程已交接、实际完成、部分完成、结果未知。查询不可用不是「没有发生」。
- 取消等待不证明操作没有发生；写入结果未知时先按原身份查询或对账，不盲目重做。
- 必要存储不可用时，依赖持久保证的新动作不假报成功；可选展示的故障不扩成全系统停机。
- 披露、重读与恢复取得内容时都核验当前权利；保管事实不等于永久授权披露。
- 提供者、交付适配与来源读取者各自保管自己的登记、读取句柄与临时资源。卸载先停准入，在途工作可靠交接，再撤自己的贡献；释放临时资源不撤销已发生的消息提交或流程效果，dispose 不是业务回滚。经 Cordis 接入时，Cordis 只回收作用域里的副作用，不兑现业务事务、租户授权、撤除次序与失败处理。

## 原则与约束

- 命令只是入口：结果落在消息或流程拥有者的路径上，本组不另建队列、日志或流程状态。
- 不替别人放权：绑定 Skill 不放宽 Skill 的读取或脚本执行资格；客户端的预检与展示不构成授权。
- 一份识别定义，所有交付面与受理侧共用。
- 结果不知道就是不知道：按原请求认回，不重新展开，不重复投递，不重做流程。
- 内容只在采用点采用；撤权立刻生效。
- 不为未定的成员归属开空包，不复制同一份公开形状。
