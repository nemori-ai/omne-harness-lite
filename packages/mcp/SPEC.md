# MCP

## 总体架构

MCP 包组回答一个问题：系统之外的一个 MCP 服务，经它的接入点怎样被可靠地连上、读出它此刻提供的动作、向它发一次动作调用，并如实交回发生了什么。它用 MCP 自己的词对外提供接口与数据，不认识调用它的是谁。

| 成员                  | 回答的问题                                                                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mcp-contract`        | 接入点正文、键、动作清单、结局、拒绝与失败长什么样；需求端口与传输端口的协议；传输对每一类线上应答得出什么结论。纯数据与纯函数，带端口与传输的符合性套件，不依赖 Cordis 与 SDK |
| `mcp`                 | 连接表、在途调用表与任务表怎样一起运转：建连、清单的刷新与发布、调用与任务操作、状态视图、关闭与关停。不依赖 Cordis，不含传输                                                  |
| `mcp-cordis-contract` | MCP 在这套系统里以哪些服务出现：应用服务与需求端口的服务定义与键                                                                                                               |
| `mcp-host-local`      | 到接入点地址的真实传输（Streamable HTTP，含对旧 HTTP+SSE 对端的回退）与授权发现的取回；`./cordis` 入口的插件把通用实现装进服务                                                 |
| `mcp-bridge`          | 动作怎样到工具入口、技能怎样到 `Skills` 入口：本组唯一认识工具契约与技能契约的成员，交出工具条目来源与执行体、技能条目来源，并持有「等对端的任务」这一种等待契约                                                                                         |
| `mcp-protocol`        | 一个登录的人查看与刷新 MCP 接入点时，有哪些操作与观察：协议契约 `mcp/v1`，纯数据                                                                                                |
| `mcp-access`          | `mcp/v1` 的接入插件                                                                                                                                                             |
| `mcp-ui`              | 桌面客户端里资产页上「MCP」这一页怎样画：经资产治理口读写 MCP 这一类的设置，调用权限自己画，别的设置项用默认部件；经 `mcp/v1` 读接入点的状态与动作清单。只依赖前端这一组与 `mcp-protocol` |
| `mcp-authorization`   | 一个接入点的 OAuth 授权怎样取得、续上与失效：发现、登记、授权码与续期的规则，待完成的 OAuth 授权与它的状态。它为核心实现凭据的需求端口；凭据本体仍在秘密保管里。不依赖 Cordis，出站请求、时钟、保管与存储都是端口 |
| `mcp-storage-sql`     | 本组要跨重启留下的事实存在哪：对端目录、任务、接续记录、事件订阅与收到的事件、OAuth 授权的非秘密事实。一个 SQL 参与者，按租户的事务域 |

依赖只朝契约：`mcp-host-local` → {`mcp`、`mcp-cordis-contract`} → `mcp-contract`；`mcp-bridge` 依赖 `mcp-contract` 与 `tool-contract`，本组只有它认识 Tool，Tool 不认识本组；`mcp-protocol` 不依赖本组的别的成员；`mcp-access` 依赖 `mcp-protocol`、`mcp-contract` 与 `mcp-cordis-contract`，按 `packages/access/SPEC.md` 的规则装配；`mcp-ui` 在客户端一侧，本组里只依赖 `mcp-protocol`，也不被本组的别的成员依赖。工作时，调用方经读口 `refresh` 让通用实现建立一条 MCP 连接、取完整的动作清单并按修订条件整份发布；之后经调用口按动作名发一次调用，结局如实分类后交回。传输只讲协议：线路报告线上事实，契约的决策层给出结论，传输照办。采用、资格与凭据由组外经需求端口交来结论；动作清单经本组声明的存储端口保存。动作经工具入口到 agent 手上：MCP 向工具入口登记一个工具条目来源，调一个动作就是一次工具调用，MCP 是背后真正发请求的一方。

## 领域边界

MCP 拥有：接入点正文的判定与类别声明（设置项与接入点的调用权限项）；MCP 连接的建立、换代、降级、丢失与关闭；动作清单的取得、采用与发布；每次协议请求的发出与结局分类；一个接入点的 OAuth 授权的取得、续上与失效（`mcp-authorization`）；在途调用表、任务表与任务的看守；对端声明的事件类型、omne 向对端的事件订阅与收到的位置；对端带的技能清单的取得与每个文件的核对；按当下事实交出工具条目与技能条目的两个条目来源。

MCP 不拥有：接入点是否已采用、采用怎样求值（资产与装配）；主体能不能用这个接入点、许不许调用（身份与授权、资产的权限）；凭据本体的保管（秘密保管）；一个事件进来之后给谁、多急（事件的消费者）；一个技能怎样被搜到与披露（Skill）；一次工具调用的准入、结果保管、取消与等人决定（Tool）；原调用的保存、等待与恢复（调用方）；对端服务本身的运行，包括本机上长驻的 MCP 服务。

本组只认通用角色：主体与租户（经访问身份 `Access<P>`）、接入点持有、调用方给出的关联键与中止信号。

本组声明、由别人实现的端口：

| 端口             | 对方                                             | 本组需要它做什么                                                               |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------------------------ |

| `UseEligibility` | 身份与授权                                       | 每次使用现场答这个主体能不能用这个接入点：准许、拒绝带原因、或未知             |

## 心智模型

一个 MCP 接入点是「外面的一个服务，加上怎样连到它」。服务由别人运行；本组只按地址与它通信，不替人起服务。连接是长寿的、按租户、持有、采用修订与对端账号分开的通道，不属于任何会话：会话结束不关连接，连接断了不结束会话。动作是对端说它此刻有的，随对端变：接入点是资产，动作不是；本组不登记动作，只把一次合法、完整的取得整份采用成清单。工具条目是按当下事实现算的视图，清单一变，下一次搜索就不同，不经装配。

把对端当作远程服务来想。一个请求发出去之后，结果可能是对端的答复、读不懂的答复，或者什么也没等到；什么也没等到就是效果未知，按原来那次调用认回，不重发，不写成失败。取消、实际停止与效果撤回是三件事：取消只是告诉对端，关闭只是放下本端的资源，每一步只报告实际确认的范围。

最容易想错的几处：「连得上」不是「许用」，每次使用都先核采用、再现场核资格，许不许调由权限回答；「未取得」不是零个动作；迟到的结果属于产出它的那一代连接，不能覆盖较新的采用；`closeAll` 之后本实例不再问任何端口、不再建连；凭据只在凭据保管方与出站请求头里出现，本组的数据、日志与错误里没有它。

## 应然设计

### 接入点正文与类别声明

- 正文只描述接入点：名字、怎样认证（`none`、`static`、`oauth`）。地址、凭据与连接超时是连接目标设置，不写进正文。判定不抛出，不修补；同一正文总得到同一个拒绝原因：先报结构，再报名字，最后报组合。存在而非法的正文不当作空来源。
- 只按地址接入。系统不替用户把一个命令起成 MCP 服务，也不为命令型接入留设施。
- 设置声明项是连接目标、凭据（只在认证方式不是 `none` 时）、连接超时与「程序调用」。前三项没有缺省值。「程序调用」是一个布尔偏好，说明这个接入点的动作许不许被 agent 写的程序调用，缺省不许；它按租户层设置的规则由人或 agent 读写，是接入点持有者替远端作者作出的声明。
- 每个接入点有一项权限「调用这个接入点的动作」，取值禁止、询问、自动，缺省询问。权限按接入点一项，不按动作一项：动作不是资产，随对端变。MCP 只声明权限项，不判定权限。
- 类别给一份关口模板，只有一道关口「调用这个接入点的动作」。接入点的设置定义与权限声明里的设置定义由同一个纯函数产出，两者逐字节相同。
- 连接目标只做句法检查：小写 `https`，或回环主机上的小写 `http`；主机按 WHATWG URL 解析后与回环集合比较；没有 fragment、userinfo、空白、控制字符或反斜杠。句法检查不判定对端可信。

### 键与对端账号

- 对端账号只由认证方式与凭据配值经纯函数得出：认证方式为 `none` 时是 `anonymous`；否则凭据配值缺失就是缺失，不退回组织、官方或其他租户的凭据。凭据端口不答对端账号。
- 连接键是租户、持有、采用修订与对端账号；清单键是租户、对端账号与持有，不含采用修订与协议版本。采用修订一变就换新连接。一个租户看不到按另一个账号发现的动作清单。

### 访问核对

- 除取消与关停之外，每个操作先经 `AdoptionView` 核采用，再经 `UseEligibility` 现场核资格；两个结论不合并。未采用、主体无资格与接入点不存在对任何主体答同一个「无权」，不可区分；被设置挡下的原因只答给有资格的主体；端口不可读答未知，不答拒绝或空。
- 资格不缓存，撤权在下一次使用时生效，不等清单刷新。撤采用与被设置挡下是接入点的事实：下一次使用边界之前关闭该接入点的连接。主体无资格只是主体的事实，不关闭连接；结论未知时也不关闭。
- 建连之前再读一次采用，不信任令牌里的采用修订；修订不同或不可读答未知，不建连。同一租户同一持有上，重读采用、关闭其他修订的连接与建立连接条目在一个临界区内完成。
- 配值按连接目标、凭据、连接超时的次序检查，只报第一项；缺失与不合法分别报告，带配置项。连接超时缺值时可用请求带来的上界，配值不合法时不改用它。
- 取消在途调用不核采用与资格，只按租户、主体与关联键定位：取消只减少效果，主体失去资格之后仍能取消自己发出的调用，别人取消不了。

### 连接

- 一个连接键同时只有一条连接；并发的建连共享同一次建立，各自只等到自己的时限。连接时限与调用截止分开：连接时限是本组的设置，覆盖取凭据、打开传输、协商与失败后的收场；调用的截止只由调用方的中止信号给出。端口不尊重信号时，本组自己停止等待，并收口迟到交来的结果：句柄释放、传输关闭。
- 连接状态是准备中、就绪、降级、丢失、关闭。代际在每次协商成功时加一。同一个连接键上代际不重复使用：连接被遗忘之后，这个键上新建的连接接着往下数。迟到的结果按产出它的代际识别，不改变新连接，不发布新清单。
- 就绪连接上非调用的协议请求暂时失败进入降级，下一次成功回到就绪。只有传输标出「不再可用」或对端要求授权时，就绪连接才转为丢失；一个请求自己失败而传输仍可用时，连接不转丢失。重建不重发任何调用。
- 拆除的次序是拒新请求、关闭传输、释放凭据句柄。关闭在它开始的那一步就拒新请求，在等任何在途工作之前；一个持有的每条连接同时开始关闭。每一步都执行，前一步失败不跳过后一步；一条连接同时只有一次拆除，失去连接、准备失败、重建与关闭共用它。
- 条目只在已关闭、没有在途建连、且不再持有任何资源时离开表。
- 每条连接按凭据配值取得一次句柄，随连接关闭释放，准备失败时立即释放。一个句柄至多释放一次。
- `closeAll` 是本实例的关停：之后不再建连，要连接的操作先判关停、不问任何端口，先于采用核对。关停落在操作途中时，已开始的一步照常走完，之后不开始新的一步；已发出的结局与已发布的清单不改。

### 清单的取得与发布

- 首次发现由调用方经 `refresh` 触发；建立连接只做协商，不取清单，就绪不等清单。首次 `refresh` 之前读面报告「未取得」，不报告零个动作。
- 一次取得只有在全部分页取完、页数与动作数不超过上界、每一项合法、动作名不重复时才完整；任一页失败，前面已取的页也不采用。完整清单带上取得之前从存储读到的修订。从未合法发现的动作不造定义。
- 采用只按清单修订做条件判断：修订不同不产出记录；清单只能来自同一进程内由完整性检查构造出的值。条件成立时产出整份新记录，修订加一。对端不再提供的动作从清单里消失。
- 不可用在接入点这一级说明：断线、撤权、禁用或依据缺席时，接入点连同原因仍然看得到，它的动作不再作为条目出现，撤权之后不能继续读取新定义。
- 发布边界紧挨存储写入：资格仍准许，清单所在连接的采用修订仍是当前，产出清单的代际仍是当前，本次刷新没有被调用方中止。后两项与写入在同一段同步执行里核对。写入答修订冲突时保留较新的采用；存储不可读或不可写时答未知，不报告新修订。
- 动作定义原样保存，不改写；annotations 另存为不可信值。定义摘要按含 annotations 的规范化文本计算：成员次序不改变摘要，任何内容或数字词形的变化都改变摘要。调用方可以用动作身份与定义摘要作稳定键。
- 对端给出的 `ttlMs` 只更新新鲜度，不改变采用。清单的变化由长请求告知，见「长请求与清单变化」。

### 动作到 agent 手上

- MCP 经 `mcp-bridge` 向工具入口登记一个工具条目来源。一个接入点是一个工具条目：一个多命令工具，接入点的每个动作是这个工具的一个命令。工具名带来源的名字前缀与接入点的名字。条目是视图，不是登记进工具登记表的工具；没有同步工具表这一步。
- 命令的摘要取动作说明的第一句，说明的全文在看这个命令的用法时给。对端给的文字都带外部内容的标记。
- 接纳不了的动作不进命令表。工具的说明列出这些动作的名字与原因。
- 条目按这个主体此刻的事实现算。没持有、没资格与不存在答得一样：不交出这个接入点的条目。清单从未取到的接入点拿不出定义，来源把它连同原因单独交出。接入点用不了而取得过清单时，条目是已知不可用，带原因。
- 发出之前按动作复核：把当前清单里的这个动作重新转换成命令声明，与受理时固定的那一条比形状：命令名与参数契约，不比对端写的说明与摘要。形状不同就不发，答定义已变；只改了说明照常发出。别的动作变了，不挡这一次调用。
- 结局映射：没发出是没有开始；完成与动作自己报错是发生了；协议错误与效果未知是不知道，不猜成功。
- 动作一般不常驻。标了常驻的接入点在采用点成为一条常驻工具，命令是它此刻的动作，进工具声明；常驻标记标在接入点的引用上。采用时来源按名字交出这一个接入点的条目，有界地等一次清单，不刷新别的接入点；交不出就不常驻。
- 执行时这个提问者还没列出过被调的名字（例如服务刚重启），先有界地列出这一个接入点，再发。
- 协议里的提示词（prompts）不开放；资源（resources）只开到读技能的文件，不作为给 agent 的能力。问到没开放的，明确答不支持，不当作空集合。
- 调一个动作是一次工具调用：许不许归 Agent 发起时的放行判断，受理、结果保管、取消归 Tool。对端要求补充输入时，问的是人：MCP 把输入请求交给调用方，由 Tool 内「等人决定」的原语去问，MCP 不代答。

- 接入点那个工具条目的 `programmable` 取自「程序调用」这项设置，设置读不到时按不许。动作对程序的返回值：声明了输出 schema 并且输出校验符合时是结构化内容；没有声明输出 schema 的动作，是按次序的内容项列表，文字项带文字，别的项带类型与内容引用。输出校验不符时程序收到失败，不收到未经核对的结构。

### 调用

- 调用的次序：值树与参数形状的前提核对（违反是调用方缺陷，以 `TypeError` 拒绝，不占位）→ 在途表占位（查重与占位是一步）→ 关停 → 关口 → 配值 → 已知动作与定义摘要 → 建连 → 发出。从占位起，一次调用只有一个拥有者，占位只收口一次。
- 发出之前，每次等待都在这次调用的停止信号下（调用方的中止与 `cancel` 合成一个）；最后一次核对停止信号与连接，与发出在同一段同步执行里。停止信号在发出之前触发，调用答「未发出：已取消」，不论那一步本来会以什么原因拒绝；关停在发出之前开始，答「未发出：连接不可用」。
- 复核定义与发出是一步：调用方预期的定义摘要与当前不同，答「未发出：定义已变」；动作不在清单里，答「未发出：动作不可用」。「未发出」没有对端效果，原因是封闭集合。
- 续调用只凭挂起时交出的那份值接续（见「挂起与接续」），不要求原调用还在本次运行的在途表里；接续之前照常核采用、资格、对端账号与定义摘要，对不上答「未发出」。
- 发出之后停止信号触发：告知对端一次，不等它答复，结局是效果未知、子因本地放弃。连接不再接受请求之后不再告知对端。
- 结局只描述已发出的调用，封闭为六种：完成、动作自己的错误、需要输入、任务、协议错误、效果未知。是否建任务由对端对每个请求决定。没有 `resultType` 的旧结果按完成处理；未知的 `resultType` 与读不懂的应答都是协议错误，不猜测成功；协议错误不证明没有效果。效果未知带子因：断流、本地放弃。
- 声明了输出 schema 时，完成的结局带输出校验结论：符合、不符、没有声明。没有结构化内容或校验函数抛出时结论是不符，不当作符合。校验函数由装配方注入，没有缺省。
- 对端内容按次序逐项转成带类型的内容块，一项对一项，不丢弃任何一项；公共内容块表达不了的协议内容带协议类型原样交出；不合法的一项转成带原因的 `invalid` 项。结构化内容原样另交，不并入内容块，不压成文字。
- 进度与日志通知是不可信的过程信息，经调用方的观察函数交出，不代替结局；观察函数抛出不影响结局；本组不把通知写进自己的日志。

### 任务操作

- 任务表是耐久的，按租户、主体、持有与任务号登记，记下对端账号、发起的调用、状态、下次去看的时刻与过期时刻。非发起者、另一租户与表里没有的任务一律答未知，不问端口，不随任务是否存在而变。同一键在两个对端账号上出现时，该键一直有歧义，两个引用都答未知。任务号在答复交给调用方之前已经落盘。
- 复用现有连接（同租户、同持有、同对端账号）不核采用与资格，不等待；要新建连接时必须核采用并得到准许，否则不建连，答效果未知（没有连接）。
- 任务请求在连接时限下等待；没有应答答效果未知；对端错误与读不懂的应答原样交出。任务过期报已过期，不当作失败或完成。取消任务只等对端确认收到取消请求，终态经查询得知。

### 挂起与接续

- 工具条目来源是检查点来源：一次动作调用可以停泊在一个检查点上等待，答复到了从同一个检查点接续。停泊、答复、接续与失效走 Tool 的检查点作者那一条路径，本组不另做一套。
- 对端答「还需要输入」时，桥接挂起，等待用人工介入的等人契约。检查点里有接续要的全部：接入点的引用、对端账号、动作名、定义摘要、原参数、对端给的状态值、每个输入请求的键与形状、这是第几轮。对端给的状态值原样带回，本组不看、不改。
- 表单变成卡片：字符串与数字各一题，只给自由文本与跳过，数字读不成数时按没答；布尔一题两个选项；枚举一题，每个取值一个选项。必填的没答，整份按拒绝交回。字段多于 64 个或表单读不懂，不问人，按取消交回。卡片上对端写的字都带外部内容的标记，并写明是哪个接入点问的。
- 人的答复对应：作答是接受，拒绝是拒绝，不答是取消。答复只交回提问的那一次调用。等待没有超时，不默认答复。轮数有上限，到了上限答协议错误，不再问人。
- 对端只会收到本组声明支持的那种输入请求。收到别的是对端违约，答协议错误。
- 接续是写类请求。恢复段在发出之前先把「这个检查点已经发出过接续」记进耐久存储；同一个检查点再跑恢复段时看到这条记录，不再发，答效果未知。读任务的结果是读类请求，可以重复。
- 对端答「任务」时，桥接挂起，等待用本组的契约「等对端的任务」，它声明后台可等。检查点里是任务的引用。
- 任务的看守只凭耐久的任务表工作：照对端给的间隔去查，有下限与退避；任务到了终态、过期或查不到，把「到了」交给 Tool；任务要输入，把「要输入」交给 Tool，恢复段换成等人的等待，人答了之后经 `tasks/update` 交回，再挂回等任务。交出与任务表的转移是同一次提交。等待已经关了的，任务转已放下。
- 任务的结局只由对端的终态或明确的未知给出：过期报已过期，查不到报未知，都不写成失败或完成。取消一次调用时，它名下还在跟的任务请对端取消一次。

### 长请求与清单变化

- 长请求是传输的另一类请求：订清单的变化（`subscriptions/listen`）与收事件的长连接（`events/stream`）。它不参与普通请求的结算规则：应答流断了不结算成失败，报「断了」，由开它的一方决定重开；普通请求的超时不适用；调用方中止与 `close()` 关流并结束；对端要授权时结束，原因是要授权。
- 一条连接上长请求的条数有上限。重开有退避与随机的等待。重开不重发任何写类请求。
- 就绪的连接上开一条订清单变化的长请求，只点动作清单这一项；对端声明了事件或技能的清单变化时一并点上。对端在确认里没答应的项不靠它，照 `ttlMs` 与显式刷新。
- 收到变化，做一次与 `refresh` 相同的取得与发布。协议不接续这条流：断了重开之后先做一次取得，再听。
- 事件类型与技能的清单，取得与采用的规则与动作清单相同：取全了才采用，整份发布，按修订判，迟到的不覆盖，未取得不是零项。

### OAuth 授权

- 认证方式是 `oauth` 的接入点，凭据是一份 OAuth 授权：一份持有上、一个对端账号[经 OAuth 取得的那一份 MCP 凭据](../../.meta_harness/design/ubiquitous_language/terms/capabilities-and-composition.md#ul-mcp-credential--mcp-凭据--mcp-credential)，连同它的非秘密事实。它的非秘密事实（签发方、资源地址、范围、到期时刻、登记的方式与客户端标识、状态）在本组的存储里；访问令牌与续期材料各是秘密保管里的一条绑定，按用途分开，由 `mcp-authorization` 写。
- 连接只由登录的人经 `mcp/v1` 发起。给 agent 的工具里没有发起连接的命令。
- 开始连接：按挑战或 well-known 地址取受保护资源元数据，再取授权服务器元数据（OAuth 与 OIDC 两种发现都支持）；选定登记；建一条待完成的 OAuth 授权，里面有状态值、PKCE 的校验值、所选授权服务器的签发方、要的范围、回跳地址与过期时刻；答出授权地址。授权请求与令牌请求都带资源参数，值是接入点的规范地址。
- 登记的次序：这个接入点的设置里填了客户端标识，用它；否则授权服务器支持客户端标识元数据文档而操作者配置里有文档地址，用那个地址；否则授权服务器有注册地址，动态注册，带 `application_type: native`；都没有，连接不成，原因写明要先在对方那里登记一个应用。事先登记的与动态注册得到的客户端凭据按签发方保存，签发方变了不复用。
- 范围的选择：先用挑战里的；没有就用受保护资源元数据里列的全部；再没有就不带。加权时取以前请求过的与这次挑战的并集。
- 回跳由回跳接收端口交来。只有状态值对得上一条仍然有效的待完成的 OAuth 授权、并且按协议核过签发方之后，才换令牌；出错的回跳同样先核，核不过的不采用也不显示里面的文字。一条待完成的 OAuth 授权至多换一次令牌，换过、作废或过期之后不再接受回跳。再开始一次连接，旧的那条待完成的 OAuth 授权作废。回跳的页面只说连上了或没连上。
- 用：令牌没到期，把它交给这次请求；快到期或已到期，先续。同一份 OAuth 授权同一时刻至多一次续期在途，别的使用者等它的结果，各自只等到自己的时限。续期成功，先写续期材料，再写访问令牌，最后写非秘密的事实。续期被授权服务器拒绝，这份 OAuth 授权转「要重新连接」。续期没有应答或写入结果不知道，这一次使用答未知，已有的值不动。
- 「要重新连接」只在授权服务器明确拒绝之后出现。它不删任何东西；人再连一次，或断开。断开删掉这份 OAuth 授权的两条秘密与事实。持有被移除时一并删。
- 续期只维持同一个对端账号。令牌只发给它的授权服务器所对应的那个接入点，不发给别的地址。令牌、续期材料、授权码、校验值不出现在任何答复、失败、状态、日志或错误里。
- 认证方式是 `static` 的接入点照旧：凭据是人配的一条秘密，本组只取用。

### 事件

- 对端声明了事件扩展时，本组取它的 [MCP 事件类型](../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-mcp-event-type--mcp-事件类型--mcp-event-type)：名字、说明、订阅参数的形状、内容的形状、支持的送法。说明是对端的字，是不可信值。
- [MCP 事件订阅](../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-mcp-event-subscription--mcp-事件订阅--mcp-event-subscription)是 omne 向一个接入点要一类事件，身份是租户、持有、对端账号、事件类型名与规范化后的参数。它是正本，耐久：带送法、收到的位置、状态、最近一次的事由与一组订阅者的引用。本组不认识订阅者是谁。
- 有了第一个订阅者才向对端订；最后一个订阅者走了就关流并删掉订阅。没有订阅者的事件类型，本组不向对端要。
- 送法从对端列的与本组会的（拉、长连接推）里选：都有时用长连接推，只有拉就拉，只有回调的订不了并写明原因。本组不做回调那种送法。
- 收到的事件先落盘再交给消费者。同一条订阅里一个事件标识至多落盘一次。落盘与位置前进是同一次提交；位置只往前走。
- 对端说中间漏了，本组记一条缺口并报给消费者，位置跳到对端给的新位置，不装作连续。每条订阅留的事件有条数与时长的上限，超了丢最旧的并记一条缺口。
- 流断了或拉没有应答，退避后带着位置重开，状态不变。连接丢了，订阅等连接回来。对端以「被拒」终止订阅是裁决：订阅转已终止并报出去，本组不自己再订。对端说类型没了或形状变了，重新取事件类型，还在就重订。接入点被撤采用或被挡下，订阅转已终止。
- 交给消费者时带着订阅的引用与每条事件的标识；重启后把还没确认收下的再交一遍，重交的是同一条。消费者暂时不在，事件留着。
- 事件的内容是不可信的数据。收到事件不带来任何使用权。本组不规定事件怎样到模型。

### 技能

- 对端同时声明了资源能力与技能扩展时，本组取它的技能清单，里面每一项是一个 [MCP 技能](../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-mcp-skill--mcp-技能--mcp-skill)：每个技能的地址、frontmatter 与文件清单，清单里每个文件有地址、摘要与字节数。清单写成「动态」的技能不收；超过每个技能 512 个文件或 16 MiB 的不收；一个接入点上两个技能同名，两个都不收。不收的写明原因。
- [技能条目来源](../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-skill-entry-source--技能条目来源--skill-entry-source)按这个主体此刻的事实交出条目，名字是来源前缀、接入点的名字与技能的名字。没持有、没资格与不存在答得一样。
- 读正文与文件只读清单里列着的地址，用到才取，不在连接、列出时提前取。取到之后核字节数与摘要，`SKILL.md` 再核 frontmatter 与条目逐字段相同；核不过不用，答来源的内容变了，并重新取这一条。读过的内容按摘要留在内存里，有字节上限。
- 条目没有本机目录。交出的正文与文件带外部内容的标记与来源接入点。frontmatter 里的工具许可只是元数据。

### 耐久存储

- `mcp-storage-sql` 是存储契约下的一个参与者，按租户的事务域。它存：对端目录（动作、事件类型、技能）；任务；接续记录；事件订阅、订阅者、收到的事件与缺口；OAuth 授权的非秘密事实；待完成的 OAuth 授权；客户端登记。
- 每次读都带租户。读不到答不可读，不答成没有。提交答不知道就是不知道，按原来那次操作认回。每个脚本对同样的事实幂等。
- 落盘的目录不构成使用资格：重启之后每次使用照常先核采用、再现场核资格。
- 持有被移除时，它名下的行与 OAuth 授权由一次清理删掉。

### 传输

- 传输的结论只由两步决定：线上事件归入一个应答类别，决策表给出这一类的结论；真实传输与脚本化传输共用契约根导出的同一份规则，表外不另立结局规则。线路只报告事实，不看消息内容、不判状态码含义。
- 失败按对端效果分四种：未发出、已交出而没有应答、对端答 JSON-RPC 错误、应答读不懂。未发出没有对端效果；没有应答是效果未知。
- 传输不再可用时，它交出的未发出与没有应答的答复带上第一次不可用的原因（流断开、会话结束），之后不变；本端 `close()` 之后的答复不带。连接是否转丢失只读这个标记。
- 只有读类请求（`server/discover`、`tools/list`、`tasks/get`、`events/list`、`events/poll`、`skills/list`、`skills/get`、`resources/read`）在应答流断开或没有应答时以新请求号再发一次；`tools/call`、`tasks/update`、`tasks/cancel` 不重发。这是对协议「流断开须重发」的有意偏离：写类请求可能已产生效果。读类请求的重发只发生在 Streamable HTTP 的非 SSE 模式；旧 HTTP+SSE 模式下不重发任何请求。
- 每个请求与通知的 `_meta` 带协议版本、客户端能力与客户端信息；现代修订声明任务、事件、技能三个扩展与 elicitation 的 form 形式，不声明 sampling、roots 与 elicitation 的 url 形式；旧修订声明空能力。每个请求与通知带 MCP 请求头。调用方写的值按原词形写出。
- 对端时代按决策表判定：先发现代探测，必要时回退到 `initialize` 并按协商出的旧修订继续；对只会旧 HTTP+SSE 的对端在同一传输内回退一次，回退不重连。协议修订名是 ISO 日期，修订的先后与是不是现代修订都按修订名的文本次序判。传输不跟随重定向，不设自己的超时。
- 请求在途分三相：授权中、已交给线路、授权发现中。调用方的中止与 `close()` 按相当场结算：授权中答未发出，已交给线路答没有应答（本地放弃），授权发现中答需要授权并交出已取到的部分。线路断开只结算依赖线路的两相。一个请求只结算一次，先到者定。
- `close()` 只等线路的本地关闭，不等凭据句柄、元数据取回或对端。本组不发旧会话的 `DELETE`。
- 只有 2xx 正文越界（16 MiB）是流断开；SSE 事件的字节在解码之前计数。
- 对端答 401、或带 `insufficient_scope` 的 403 时，结论按「这次请求出示过凭据没有、认证方式是哪种」分开：没出示过凭据的，请求未发出，答需要授权并带授权发现；出示了静态凭据的，是凭据被拒，连接不可用，原因 `credential-rejected`，并向句柄回报一次拒绝；出示了 OAuth 令牌的 401，向句柄回报一次拒绝，由 `mcp-authorization` 续一次，续不上是「要重新连接」；出示了 OAuth 令牌的 `insufficient_scope`，是「要重新连接」并带上要的范围。其他 403 是连接不可用。授权发现按挑战里的 `resource_metadata` 或 well-known 地址依次取元数据，取回不经凭据句柄、不带凭据头。
- 对端发来的请求只答 `ping`，其余答方法不存在。

### Cordis 装配

- 服务键只由各抽象类的静态 `provide` 给出；方法签名从契约的操作类型推出。根入口不导入 Cordis。
- 插件在一条 fiber 上提供应用服务，它们共用一次装配的连接表、在途表与任务表。需求端口是可选依赖：每次调用现取，不缓存；缺席时答该端口的未知，用到它的那一步不放行。换代不重建连接表，已建连接沿用旧提供者交出的句柄直到关闭。
- 配置只查形状：未知字段、缺字段或类型不对使加载失败；取值范围由实现的构造检查，同样使加载失败，不回退缺省。
- 撤除只有一步：`closeAll`。撤除不撤回已发出的调用。

### 对客户端开放

- 本组对客户端开放一份协议 `mcp/v1`：契约在 `mcp-protocol`，接入插件是 `mcp-access`。起初有四样：列出这个租户的接入点，每个带连接状态、凭据有没有、能不能用与原因；读一个接入点，答上面那些，加清单的取得状态与每个动作的名字和摘要；刷新一个接入点；一条观察，帧只说「可能变了」，客户端收到就重读。
- 每一样都要登录身份，后加的连接、断开与事件的几样也是，见下一节。读到的不含秘密值：凭据只说有没有与状态。另一个租户的接入点读不到，答复与不存在的接入点相同。
- 命令行有对应的命令：`omne mcp list`、`show`、`refresh`；`omne mcp connect` 打印授权地址并等连上，`omne mcp disconnect`；`omne mcp events` 列事件类型，`omne mcp subscribe`、`unsubscribe`，`omne mcp tail` 看一条订阅收到的事件。
- 配地址、配密钥、改权限不在这份协议里，走资产的协议。

### 协议 mcp/v1

- `mcp-protocol` 是纯数据，只依赖公开契约的共同部分。三个操作都要登录身份，正文带目标租户，计一次业务访问，体上限小：`list-endpoints`（读）答接入点列表；`read-endpoint`（读，另带名字）答这个接入点与它的动作清单，清单没取得时为空；`refresh-endpoint`（提交，另带名字）答这次刷新的结局。观察 `observe-endpoints` 要登录身份，开时带目标租户；帧只说这个租户的接入点「可能变了」，客户端收到就重读。
- 一个接入点的各栏：名字；连接（状态 `none`、`preparing`、`ready`、`degraded`、`lost`，加一句原因或空）；凭据（`present`、`absent`、`invalid`、`not-required`）；能不能用（可用，或被挡下加原因）；清单（已取得加动作数，或未取得加原因或空）。一个动作：名字、摘要、能不能调、不能调时的原因。原因与摘要可能带对端的文字，写成不限非空的文本。
- 修订 2 加：观察 `observe-endpoints`，帧说这个租户的接入点可能变了、或某个接入点的事件可能变了；一个接入点多一栏可选的凭据的状态，在已有的四种之外另有「被拒」与「要重新连接」。
- 修订 3 加：操作 `begin-connect`（提交，带名字，答授权地址与这条待完成的 OAuth 授权的过期时刻，或不能连的原因）与 `disconnect`（提交，带名字）；一个接入点多两栏可选的：能不能点连接、现在是不是连接中。结果不知道时都用 `read-endpoint` 认回。
- 修订 4 加：`list-event-types`（读）答一个接入点的事件类型；`subscribe-events` 与 `unsubscribe-events`（提交），订阅者是这个登录的人；`read-events`（读，分页）答一条订阅最近收到的事件与缺口。
- 修订 5 加：一个接入点多一栏可选的技能数与取得状态。
- 后加的都标 `since`，字段都可选。给 agent 的工具里没有这些操作。
- 刷新的结局四种：已发布、被后一次取代、已取消、失败，失败带原因。结果不知道时答 `unknown`，客户端用 `read-endpoint` 认回，没有另设 `query-` 操作。没有这个接入点与它对你不可用，答同一个 `not-visible`。

### 接入插件 mcp-access

- `mcp-access` 的处理函数照接入的固定次序：核登录可以为目标租户行事（端口，应用的行用 `createMemberActing` 适配）；取主体；按调用现取 `mcpAdoptionView`、`mcpEndpointStatus`、`mcpActionDiscovery`，取不到答依据不可用，协议不撤下；调领域，映射结果。读领域抛出答依据不可用，刷新自己抛出答 `unknown`。
- 接入点按名字在采用视图的范围里找，找不到或状态读答「对你不可用」都是 `not-visible`，列表里不出现。状态的连接、凭据与能不能用原样映射；清单读失败时这一栏是未取得，原因写桥接的 `failureText`，与 agent 搜工具时 `withheld` 里写的一字不差；动作的摘要取桥接对这个动作的命令摘要，同一条规则。连接的原因只在失联与清单取不全时有：失联写桥接 `unavailableText` 的那一句（要授权、凭据被拒与连不上分开），取不全写一句清单没列全，不另写一套文字。凭据的状态：凭据已配而连接因凭据被拒失联时是「被拒」，连接再连上就回到「已配」；其余与凭据一栏相同。
- 刷新带行配置的连接等待上限 `refresh.connectBoundMs`；领域答失败时结局是失败加 `failureText`，「清单不完整」没有桥接的文字，由插件写一句并带缺陷名。刷新答「对你不可用」也是 `not-visible`。

### 界面模块

- `mcp-ui` 是 MCP 在桌面客户端里的界面模块：资产页栏里「MCP」那一项的窗格。它是资产页这个拓展点的贡献方，不是宿主：它只依赖前端这一组（外壳契约、共用界面件）、React、本组的 `mcp-protocol`、SDK 的客户端核心与公开契约（协议客户端的类型；把外壳给的租户文本读成租户），不导入资产的任何成员，资产的成员也不导入它。界面模块读两处：资产治理口给设置与权限，`mcp/v1` 给状态与清单。协议是可选的需要：没挂着时，状态与清单两块显示读不出，别的照常。每个接入点读一次 `read-endpoint`；页开着时开一条 `observe-endpoints`，帧说接入点可能变了就每个接入点再读一次，观察断了过一会儿重开，被拒、不许或页关了就不再开；「刷新」发一次 `refresh-endpoint`，不论它答什么都再读一次这个接入点，结果不知道也这样认回；刷新在途时不再给「刷新」。
- `./cordis` 入口的工厂 `createMcpUiModule({ page, governance })` 收两样，都由应用的装配给：放页面的拓展点（`page`，资产页的类别页面那一个）与资产治理口的键（`governance`）。界面模块注入这个键：口不在时它不加载，口撤下时它随之卸载，它放的页面随作用域撤掉，资产页这一类回到通用的窗格。
- 它要的口的形状自己写（`McpGovernance`）：按租户文本与类别打开一个视图；视图有订阅、快照、重读、改一项、清除一项、认回、关闭与默认部件 `Row`；快照里一行只写它读的字段。装配把资产的键交给它，资产给的形状赋不过去时装配处编译不过。
- 页面标识是类别 `mcp`，栏里的字是「MCP」，由它自己带。没有租户时不画、不打开口。打开的是这个租户的 `mcp` 这一类，读到的接入点每个一段，段的小标题是接入点的名字。读中、读不出、一个接入点都没有、列表不全各说什么，见下面的样子；列表不全时说出来，不说没有接入点。
- 每个接入点的调用权限「调用这个接入点的动作」由它自己画：点一档就经口改这一项，本层有挑选时可以清除。写入在途或结果不知道时不能再改；结果不知道时写原因并给「再确认一次」，认回进行中不给；被拒或没认回时写原因，控件重新可改。这一层不能改时说出来。这一项重读失败时交给默认部件画，由它给「重试」。一次只发一个写入、结果不知道按原操作认回，由治理口守，页面不另守。
- 别的设置项（连接目标、凭据、连接超时）都用口给的默认部件 `Row` 画，它就是资产的[设置行](../assets/SPEC.md#资产页与设置页的样子)。

**MCP 窗格的样子**（资产页栏里的「MCP」）。族的画法、状态、反馈与语气的规则在[视觉规范](../../.meta_harness/agents/skills/visual-standard/canonical/SKILL.md)与它的[规则与 token 的索引](../../.meta_harness/agents/skills/visual-standard/canonical/references/rules-index.md)，这里不重写。

- 族与多重：栏加窗格里的一个窗格，是一个类别自己带来的页面，栏里与通用的窗格没有区别。窗格标题「MCP」用引导字号；没有「新建」。接入点一个一段：上面一条细线，接入点的名字作小标题，等宽。段里先是调用权限，再是别的设置行。内容是正文的轻重，不是卡片。
- 状态：每个接入点的段里，名字下面一行是状态：连上没有；不能用时写原因。
- 动作清单：设置行之后列这个接入点的动作，每个动作一行，写动作名与摘要。清单还没取得时照实写，并给「刷新」。
- 调用权限是一行设置的样子：左边是名称「调用这个接入点的动作」；右边是一个分段控件，每一档一格，字取声明给的名字（禁止、询问、自动），生效的那一档就是控件上选中的那一格。本层有挑选时，控件下面一行弱墨写「这一层设的」；没有时写「这一层没有挑选」。被外层主动禁止时，控件换成只读的值「被禁止」；界内没有可选的一档时，换成只读的值「没有可选的一档」。这一层不能改时，控件画成只读的生效值，加一个锁的字形与一句「这一层不能改这一项。」，不画灰掉的控件。「清除这一层的挑选」在这一行的 `⋯` 里，本层有挑选、这一层能改时才有；清除能撤销，不问。
- 加载：读中写「正在读取 MCP 的接入点……」；一项重读时控件上显示等待。
- 空：一个接入点都没有时写「接进来的 MCP 接入点会列在这里。」。
- 部分：列表不全时，在接入点上方说一次「接入点不全：有的来源暂时读不出，这里没有列全。」。
- 读不出：照实写原因，带「重试」。
- 内容过长：接入点的名字换行，不截断。
- 反馈：分段控件自己就是回执：点一格就写，控件立刻显示新的一档，只在这个控件上显示等待；被拒就退回读到的值，在这一行下面写一句通知。清除之后这一行落定成新的生效值。结果不知道时控件停在发出的那一档上，这一行下面一句通知，带「再确认一次」。
- 用的件：`Section`（接入点的段）；`Segmented`；`RecordMenu`（`⋯`）；资产治理口给的默认部件 `Row`；`LoadingState`、`EmptyState`、`InlineNotice`。

通知与语气（规则见索引的 C3、C4 与 L7、L8）。通知的句子与种类由治理口给，种类与资产页的相同，语气也照[资产页的定法](../assets/SPEC.md#资产页与设置页的样子)：

| 句子 | 什么时候 | 语气 |
| --- | --- | --- |
| 口给的读不出的那一句，种类是 `unavailable` | 接入点读不出 | 琥珀，带「重试」 |
| 口给的读不出的那一句，种类是 `refused` | 接入点读答了拒绝 | 失败，带「重试」 |
| 「接入点不全：有的来源暂时读不出，这里没有列全。」 | 列表不全 | 琥珀 |
| 口给的没有成立的那一句 | 改或清除调用权限没有成立 | 失败 |
| 口给的结果未知、结果仍未知、没有认回的那一句 | 结果不知道 | 中性 |
| 「这一层不能改这一项。」 | 这一层不能改 | 中性，是锁旁边的说明 |

## 原则与约束

- 一个事实一个拥有者：MCP 不求值、不保存采用、不判资格与权限、不保管凭据本体、不保存原调用、不判调用终局、不决定事件给谁、不决定技能怎样披露，别人的结论只经端口读。
- 只用自己的词：契约里没有调用方体系的名字、条目形状与准入规则；工具入口与 Tool 不为 MCP 开专门的分支，MCP 作为一份贡献登记进去。
- 结局如实分类：未发出、已知结局与效果未知分开；效果未知不重发，不压成失败；拒绝不披露另一租户或接入点是否存在。
- 只报告实际确认的范围：关闭与释放都不声称比确认的更多。
- 秘密不进清单、日志、错误文本、模型的上下文与交出的数据；对端自报的身份、说明与 annotations 都是不可信值，不作身份或授权依据。
- 上界都是必填的正整数配置，没有缺省；资源与等待都有界，挂起的端口不让调用方无界地等，拆除的端口挂起除外，期限由宿主承担。
- 协议层优先复用官方 SDK；会违反结局如实分类或不代调用方重发的部分不复用，同一条规则只在契约根实现一次。产品源码不导入 SDK。
- 端口应以 `Outcome` 答复；同步抛出与 reject 是端口违约，读成该端口的违约答复，不成为本组的错误；本组自己的编程错误不吞掉。
- 自定义的并发、换代、收口、接续、订阅与 OAuth 授权协议要有形式模型与关键性质检查，模型在 `mcp` 与 `mcp-host-local` 的 `verification/` 目录；有限检查的通过不等于实现符合。
