# MCP

## 总体架构

MCP 包组回答一个问题：系统之外的一个 MCP 服务，经它的接入点怎样被可靠地连上、读出它此刻提供的动作、向它发一次动作调用，并如实交回发生了什么。它用 MCP 自己的词对外提供接口与数据，不认识调用它的是谁。

| 成员                  | 回答的问题                                                                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mcp-contract`        | 接入点正文、键、动作清单、结局、拒绝与失败长什么样；需求端口与传输端口的协议；传输对每一类线上应答得出什么结论。纯数据与纯函数，带端口与传输的符合性套件，不依赖 Cordis 与 SDK |
| `mcp`                 | 连接表、在途调用表与任务表怎样一起运转：建连、清单的刷新与发布、调用与任务操作、状态视图、关闭与关停。不依赖 Cordis，不含传输                                                  |
| `mcp-cordis-contract` | MCP 在这套系统里以哪些服务出现：应用服务与需求端口的服务定义与键                                                                                                               |
| `mcp-host-local`      | 到接入点地址的真实传输（Streamable HTTP，含对旧 HTTP+SSE 对端的回退）与授权发现的取回；`./cordis` 入口的插件把通用实现装进服务                                                 |

依赖只朝契约：`mcp-host-local` → {`mcp`、`mcp-cordis-contract`} → `mcp-contract`。工作时，调用方经读口 `refresh` 让通用实现建立一条 MCP 连接、取完整的动作清单并按修订条件整份发布；之后经调用口按动作名发一次调用，结局如实分类后交回。传输只讲协议：线路报告线上事实，契约的决策层给出结论，传输照办。采用、资格与凭据由组外经需求端口交来结论；动作清单经本组声明的存储端口保存。动作经工具入口到 agent 手上：MCP 向工具入口登记一个工具条目来源，调一个动作就是一次工具调用，MCP 是背后真正发请求的一方。

## 领域边界

MCP 拥有：接入点正文的判定与类别声明（设置项与接入点的调用权限项）；MCP 连接的建立、换代、降级、丢失与关闭；动作清单的取得、采用与发布；每次协议请求的发出与结局分类；授权发现（对端要求授权时读出受保护资源元数据）；本次运行内的在途调用表与任务表；按当下事实交出工具条目的条目来源。

MCP 不拥有：接入点是否已采用、采用怎样求值（资产与装配）；主体能不能用这个接入点、许不许调用（身份与授权、资产的权限）；凭据的保管、认证流程与续期（凭据保管方，由人在接入点上完成）；一次工具调用的准入、结果保管、取消与等人决定（Tool）；原调用的保存、等待与恢复（调用方）；对端服务本身的运行，包括本机上长驻的 MCP 服务。

本组只认通用角色：主体与租户（经访问身份 `Access<P>`）、接入点持有、调用方给出的关联键与中止信号。

本组声明、由别人实现的端口：

| 端口             | 对方                                             | 本组需要它做什么                                                               |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------------------------ |
| `AdoptionView`   | 资产求值与装配                                   | 答哪些接入点已采用，每项的采用修订、正文与配值；配值如实交出缺失、不合法或有值 |
| `UseEligibility` | 身份与授权                                       | 每次使用现场答这个主体能不能用这个接入点：准许、拒绝带原因、或未知             |
| `CredentialUse`  | 凭据保管方（`packages/assets` 的设置与秘密保管） | 为一份持有与一个连接目标取得一次凭据的受限使用：为出站 HTTP 请求授权的句柄     |
| `CatalogStore`   | 本组 `mcp` 的内存实现；耐久实现接存储契约        | 按键读一份动作清单；按期望修订整份写入                                         |

本组为别人实现的端口：

| 端口                                                                 | 对方                       | 本组提供什么                                                     |
| -------------------------------------------------------------------- | -------------------------- | ---------------------------------------------------------------- |
| 类别端口 `BodyContract`（类别 `mcp`）                                | 资产（`packages/assets`）  | 接入点正文的判定、设置声明项、接入点的调用权限项                 |
| 工具条目来源                                                         | Tool 的工具入口            | 按这个主体此刻的事实交出合法可用的动作，每个动作一个工具条目     |
| 读口 `ActionDiscovery`                                               | 调用方                     | 动作清单视图、刷新、对端视图                                     |
| 调用口与任务操作 `ActionInvoker`                                     | 调用方（Tool 的实际调用）  | 发出调用、带回输入答复、取消；任务的查询、取结果、交回输入、取消 |
| 状态口 `EndpointStatus` 与 `Connections`                             | 调用方与持有本组实例的装配 | 接入点状态的查询与列举；释放连接；关停                           |
| 服务键 `mcpActionDiscovery`、`mcpActionInvoker`、`mcpEndpointStatus` | Cordis 装配                | 应用服务；需求端口的键由端口实现方在其上提供                     |

## 心智模型

一个 MCP 接入点是「外面的一个服务，加上怎样连到它」。服务由别人运行；本组只按地址与它通信，不替人起服务。连接是长寿的、按租户、持有、采用修订与对端账号分开的通道，不属于任何会话：会话结束不关连接，连接断了不结束会话。动作是对端说它此刻有的，随对端变：接入点是资产，动作不是；本组不登记动作，只把一次合法、完整的取得整份采用成清单。工具条目是按当下事实现算的视图，清单一变，下一次搜索就不同，不经装配。

把对端当作远程服务来想。一个请求发出去之后，结果可能是对端的答复、读不懂的答复，或者什么也没等到；什么也没等到就是效果未知，按原来那次调用认回，不重发，不写成失败。取消、实际停止与效果撤回是三件事：取消只是告诉对端，关闭只是放下本端的资源，每一步只报告实际确认的范围。

最容易想错的几处：「连得上」不是「许用」，每次使用都先核采用、再现场核资格，许不许调由权限回答；「未取得」不是零个动作；迟到的结果属于产出它的那一代连接，不能覆盖较新的采用；`closeAll` 之后本实例不再问任何端口、不再建连；凭据只在凭据保管方与出站请求头里出现，本组的数据、日志与错误里没有它。

## 应然设计

### 接入点正文与类别声明

- 正文只描述接入点：名字、怎样认证（`none`、`static`、`oauth`）。地址、凭据与连接超时是连接目标设置，不写进正文。判定不抛出，不修补；同一正文总得到同一个拒绝原因：先报结构，再报名字，最后报组合。存在而非法的正文不当作空来源。
- 只按地址接入。系统不替用户把一个命令起成 MCP 服务，也不为命令型接入留设施。
- 设置声明项是连接目标、凭据（只在认证方式不是 `none` 时）、连接超时。设置项都没有缺省值。
- 每个接入点有一项权限「调用这个接入点的动作」，取值禁止、询问、自动，缺省询问。权限按接入点一项，不按动作一项：动作不是资产，随对端变。MCP 只声明权限项，不判定权限。
- 连接目标只做句法检查：小写 `https`，或回环主机上的小写 `http`；主机按 WHATWG URL 解析后与回环集合比较；没有 fragment、userinfo、空白、控制字符或反斜杠。句法检查不判定对端可信。

### 键与对端账号

- 对端账号只由认证方式与凭据配值经纯函数得出：认证方式为 `none` 时是 `anonymous`；否则凭据配值缺失就是缺失，不退回组织、官方或其他租户的凭据。凭据端口不答对端账号。
- 连接键是租户、持有、采用修订与对端账号；清单键是租户、对端账号与持有，不含采用修订与协议版本。采用修订一变就换新连接。一个租户看不到按另一个账号发现的动作清单。

### 访问核对

- 除取消与关停之外，每个操作先经 `AdoptionView` 核采用，再经 `UseEligibility` 现场核资格；两个结论不合并。未采用、主体无资格与接入点不存在对任何主体答同一个「无权」，不可区分；被设置挡下的原因只答给有资格的主体；端口不可读答未知，不答拒绝或空。
- 资格不缓存，撤权在下一次使用时生效，不等清单刷新。撤采用与被设置挡下是接入点的事实：下一次使用边界之前关闭该接入点的连接。主体无资格只是主体的事实，不关闭连接；结论未知时也不关闭。
- 建连之前再读一次采用，不信任令牌里的采用修订；修订不同或不可读答未知，不建连。同一租户同一持有上，重读采用、关闭其他修订的连接与建立连接条目在一个临界区内完成。
- 配值按连接目标、凭据、连接超时的次序检查，只报第一项；缺失与不合法分别报告，带配置项。连接超时缺值时可用请求带来的上界，配值不合法时不改用它。
- 取消在途调用不核采用与资格，只按租户、主体与关联键定位：取消只减少效果，主体失去资格之后仍能取消自己发出的调用，别人取消不了。

### 连接

- 一个连接键同时只有一条连接；并发的建连共享同一次建立，各自只等到自己的时限。连接时限与调用截止分开：连接时限是本组的设置，覆盖取凭据、打开传输、协商与失败后的收场；调用的截止只由调用方的中止信号给出。端口不尊重信号时，本组自己停止等待，并收口迟到交来的结果：句柄释放、传输关闭。
- 连接状态是准备中、就绪、降级、丢失、关闭。代际在每次协商成功时加一。同一个连接键上代际不重复使用：连接被遗忘之后，这个键上新建的连接接着往下数。迟到的结果按产出它的代际识别，不改变新连接，不发布新清单。
- 就绪连接上非调用的协议请求暂时失败进入降级，下一次成功回到就绪。只有传输标出「不再可用」或对端要求授权时，就绪连接才转为丢失；一个请求自己失败而传输仍可用时，连接不转丢失。重建不重发任何调用。
- 拆除的次序是拒新请求、关闭传输、释放凭据句柄。关闭在它开始的那一步就拒新请求，在等任何在途工作之前；一个持有的每条连接同时开始关闭。每一步都执行，前一步失败不跳过后一步；一条连接同时只有一次拆除，失去连接、准备失败、重建与关闭共用它。
- 条目只在已关闭、没有在途建连、且不再持有任何资源时离开表。
- 每条连接按凭据配值取得一次句柄，随连接关闭释放，准备失败时立即释放。一个句柄至多释放一次。
- `closeAll` 是本实例的关停：之后不再建连，要连接的操作先判关停、不问任何端口，先于采用核对。关停落在操作途中时，已开始的一步照常走完，之后不开始新的一步；已发出的结局与已发布的清单不改。

### 清单的取得与发布

- 首次发现由调用方经 `refresh` 触发；建立连接只做协商，不取清单，就绪不等清单。首次 `refresh` 之前读面报告「未取得」，不报告零个动作。
- 一次取得只有在全部分页取完、页数与动作数不超过上界、每一项合法、动作名不重复时才完整；任一页失败，前面已取的页也不采用。完整清单带上取得之前从存储读到的修订。从未合法发现的动作不造定义。
- 采用只按清单修订做条件判断：修订不同不产出记录；清单只能来自同一进程内由完整性检查构造出的值。条件成立时产出整份新记录，修订加一。对端不再提供的动作从清单里消失。
- 不可用在接入点这一级说明：断线、撤权、禁用或依据缺席时，接入点连同原因仍然看得到，它的动作不再作为条目出现，撤权之后不能继续读取新定义。
- 发布边界紧挨存储写入：资格仍准许，清单所在连接的采用修订仍是当前，产出清单的代际仍是当前，本次刷新没有被调用方中止。后两项与写入在同一段同步执行里核对。写入答修订冲突时保留较新的采用；存储不可读或不可写时答未知，不报告新修订。
- 动作定义原样保存，不改写；annotations 另存为不可信值。定义摘要按含 annotations 的规范化文本计算：成员次序不改变摘要，任何内容或数字词形的变化都改变摘要。调用方可以用动作身份与定义摘要作稳定键。
- 对端给出的 `ttlMs` 只更新新鲜度，不改变采用；本组不订阅清单变化通知。

### 动作到 agent 手上

- MCP 向工具入口登记一个工具条目来源。来源按调用交出这个主体此刻合法可用的动作，每个动作一个条目，保留原接入点与动作的关联。条目是视图，不是登记进工具登记表的工具；没有同步工具表这一步。
- 动作一般不常驻。标了常驻的接入点，它的动作在采用点成为常驻工具，进工具声明；常驻标记标在接入点的引用上。
- 协议里的非动作能力（resources、prompts）不随连接自动开放；问到时明确答不支持，不当作空集合。
- 调一个动作是一次工具调用：准入、结果保管、取消归 Tool。对端要求补充输入时，问的是人：MCP 把输入请求交给调用方，由 Tool 内「等人决定」的原语去问，MCP 不代答。

### 调用

- 调用的次序：值树与参数形状的前提核对（违反是调用方缺陷，以 `TypeError` 拒绝，不占位）→ 在途表占位（查重与占位是一步）→ 关停 → 关口 → 配值 → 已知动作与定义摘要 → 续调用核代际 → 建连 → 发出。从占位起，一次调用只有一个拥有者，占位只收口一次。
- 发出之前，每次等待都在这次调用的停止信号下（调用方的中止与 `cancel` 合成一个）；最后一次核对停止信号与连接，与发出在同一段同步执行里。停止信号在发出之前触发，调用答「未发出：已取消」，不论那一步本来会以什么原因拒绝；关停在发出之前开始，答「未发出：连接不可用」。
- 复核定义与发出是一步：调用方预期的定义摘要与当前不同，答「未发出：定义已变」；动作不在清单里，答「未发出：动作不可用」。「未发出」没有对端效果，原因是封闭集合。
- 续调用在连接换代之后无法证明旧代际上的在途状态时，答「未发出：未知」，不在新代际上重发。
- 发出之后停止信号触发：告知对端一次，不等它答复，结局是效果未知、子因本地放弃。连接不再接受请求之后不再告知对端。
- 结局只描述已发出的调用，封闭为六种：完成、动作自己的错误、需要输入、任务、协议错误、效果未知。是否建任务由对端对每个请求决定。没有 `resultType` 的旧结果按完成处理；未知的 `resultType` 与读不懂的应答都是协议错误，不猜测成功；协议错误不证明没有效果。效果未知带子因：断流、本地放弃。
- 声明了输出 schema 时，完成的结局带输出校验结论：符合、不符、没有声明。没有结构化内容或校验函数抛出时结论是不符，不当作符合。校验函数由装配方注入，没有缺省。
- 对端内容按次序逐项转成带类型的内容块，一项对一项，不丢弃任何一项；公共内容块表达不了的协议内容带协议类型原样交出；不合法的一项转成带原因的 `invalid` 项。结构化内容原样另交，不并入内容块，不压成文字。
- 进度与日志通知是不可信的过程信息，经调用方的观察函数交出，不代替结局；观察函数抛出不影响结局；本组不把通知写进自己的日志。

### 任务操作

- 任务表在本次运行内按租户、主体、持有与任务号登记，记下发起代际与对端账号。非发起者、另一租户、表里没有与重启之后的任务一律答未知，不问端口，不随任务是否存在而变。同一键在两个对端账号上出现时，该键一直有歧义，两个引用都答未知。
- 复用现有连接（同租户、同持有、同对端账号）不核采用与资格，不等待；要新建连接时必须核采用并得到准许，否则不建连，答效果未知（没有连接）。
- 任务请求在连接时限下等待；没有应答答效果未知；对端错误与读不懂的应答原样交出。任务过期报已过期，不当作失败或完成。取消任务只等对端确认收到取消请求，终态经查询得知。

### 传输

- 传输的结论只由两步决定：线上事件归入一个应答类别，决策表给出这一类的结论；真实传输与脚本化传输共用契约根导出的同一份规则，表外不另立结局规则。线路只报告事实，不看消息内容、不判状态码含义。
- 失败按对端效果分四种：未发出、已交出而没有应答、对端答 JSON-RPC 错误、应答读不懂。未发出没有对端效果；没有应答是效果未知。
- 传输不再可用时，它交出的未发出与没有应答的答复带上第一次不可用的原因（流断开、会话结束），之后不变；本端 `close()` 之后的答复不带。连接是否转丢失只读这个标记。
- 只有读类请求（`server/discover`、`tools/list`、`tasks/get`）在应答流断开或没有应答时以新请求号再发一次；`tools/call`、`tasks/update`、`tasks/cancel` 不重发。这是对协议「流断开须重发」的有意偏离：写类请求可能已产生效果。读类请求的重发只发生在 Streamable HTTP 的非 SSE 模式；旧 HTTP+SSE 模式下不重发任何请求。
- 每个请求与通知的 `_meta` 带协议版本、客户端能力与客户端信息；现代修订只声明任务扩展与 elicitation 的 form 形式，不声明 sampling、roots 与 elicitation 的 url 形式；旧修订声明空能力。每个请求与通知带 MCP 请求头。调用方写的值按原词形写出。
- 对端时代按决策表判定：先发现代探测，必要时回退到 `initialize` 并按协商出的旧修订继续；对只会旧 HTTP+SSE 的对端在同一传输内回退一次，回退不重连。协议修订名是 ISO 日期，修订的先后与是不是现代修订都按修订名的文本次序判。传输不跟随重定向，不设自己的超时。
- 请求在途分三相：授权中、已交给线路、授权发现中。调用方的中止与 `close()` 按相当场结算：授权中答未发出，已交给线路答没有应答（本地放弃），授权发现中答需要授权并交出已取到的部分。线路断开只结算依赖线路的两相。一个请求只结算一次，先到者定。
- `close()` 只等线路的本地关闭，不等凭据句柄、元数据取回或对端。本组不发旧会话的 `DELETE`。
- 只有 2xx 正文越界（16 MiB）是流断开；SSE 事件的字节在解码之前计数。
- 对端答 401、或带 `insufficient_scope` 的 403 时，请求未发出，答需要授权并带授权发现；曾用凭据句柄授权的请求先回报一次拒绝。其他 403 是连接不可用。授权发现按挑战里的 `resource_metadata` 或 well-known 地址依次取元数据，取回不经凭据句柄、不带凭据头。本组只做授权发现，不做认证流程。
- 对端发来的请求只答 `ping`，其余答方法不存在。

### Cordis 装配

- 服务键只由各抽象类的静态 `provide` 给出；方法签名从契约的操作类型推出。根入口不导入 Cordis。
- 插件在一条 fiber 上提供应用服务，它们共用一次装配的连接表、在途表与任务表。需求端口是可选依赖：每次调用现取，不缓存；缺席时答该端口的未知，用到它的那一步不放行。换代不重建连接表，已建连接沿用旧提供者交出的句柄直到关闭。
- 配置只查形状：未知字段、缺字段或类型不对使加载失败；取值范围由实现的构造检查，同样使加载失败，不回退缺省。
- 撤除只有一步：`closeAll`。撤除不撤回已发出的调用。

## 原则与约束

- 一个事实一个拥有者：MCP 不求值、不保存采用、不判资格与权限、不保管凭据、不保存原调用、不判调用终局，别人的结论只经端口读。
- 只用自己的词：契约里没有调用方体系的名字、条目形状与准入规则；工具入口与 Tool 不为 MCP 开专门的分支，MCP 作为一份贡献登记进去。
- 结局如实分类：未发出、已知结局与效果未知分开；效果未知不重发，不压成失败；拒绝不披露另一租户或接入点是否存在。
- 只报告实际确认的范围：关闭与释放都不声称比确认的更多。
- 秘密不进清单、日志、错误文本、模型的上下文与交出的数据；对端自报的身份、说明与 annotations 都是不可信值，不作身份或授权依据。
- 上界都是必填的正整数配置，没有缺省；资源与等待都有界，挂起的端口不让调用方无界地等，拆除的端口挂起除外，期限由宿主承担。
- 协议层优先复用官方 SDK；会违反结局如实分类或不代调用方重发的部分不复用，同一条规则只在契约根实现一次。产品源码不导入 SDK。
- 端口应以 `Outcome` 答复；同步抛出与 reject 是端口违约，读成该端口的违约答复，不成为本组的错误；本组自己的编程错误不吞掉。
- 自定义的并发、换代与收口协议要有形式模型与关键性质检查，模型在 `mcp` 与 `mcp-host-local` 的 `verification/` 目录；有限检查的通过不等于实现符合。
