# Media

## 总体架构

Media 回答三个问题：一份非文字内容的字节在不在、是谁的、对不对；它有哪些别的表示、各是谁做的；按一个型号的限额，同一份内容的合规版本是什么。它保管图片、语音与文件的原件，保管由原件做出来的表示，并把做表示的转换件开放成可登记、可替换的机制。包组的成员：

| 成员 | 回答的问题 |
| --- | --- |
| `media-contract` | 媒体对象、表示、上传、引擎声明有哪些值；状态与操作怎样判；存放、元数据、转换件定义、图像这几个端口长什么样。纯数据与纯函数，另带存放提供者与转换引擎的符合性套件、受控替身 |
| `media-cordis-contract` | 在这套系统里它以哪些服务出现；转换引擎的登记表怎样登记与撤除 |
| `media` | 上传、保管、表示、请求版本、分页读各怎样做。不依赖 Cordis、存储与图像库；`./cordis` 入口是提供者 |
| `media-storage-local` | 字节存放端口在本机文件系统上的实现 |
| `media-storage-sql` | 元数据端口在 SQL 契约上的实现 |
| `media-image` | 图像端口的实现：探测、缩放、质量阶梯 |
| `media-adapters` | Session 的受理前处理件、Model 的读媒体端口、Tool 的存产出端口，各怎样接到本组；怎样向资产登记「转换件」类别并用资产的求值回答转换件定义。每个适配是一个 Cordis 插件 |
| `media-protocol` | 对客户端开放哪些操作与观察 |
| `media-access` | 接入插件：核身份，调媒体的面，把结果映射成协议的结果 |
| `media-ui` | 界面模块：输入框的附件区、消息里一块非文字内容的画法 |
| 每个转换引擎一个成员 | 一份声明加一个转换函数。只依赖 `media-contract` |

源码依赖只朝内。`media-contract` 不导入任何实现。`media` 只依赖 `media-contract`：它不导入存放提供者、SQL 提供者、图像成员与任何引擎。只有 `media-adapters` 认识邻域，而且只认识它们的公开契约。Session、Agent、Request Context、Model、Tool、执行环境的成员不导入本组的任何成员。

## 领域边界

Media 拥有：媒体对象的身份、状态与持有；上传的会话；表示与它的出处；请求版本；转换引擎的登记；「转换件」这个资产类别的正文契约；字节存放与元数据两个端口的契约。

Media 不拥有：

| 事实 | 归谁 |
| --- | --- |
| 会话历史里哪条消息引用了哪份媒体 | Session。会话日志里只有内容引用与文字 |
| 一个型号原生收下哪些模态与文件类型、各自的限额 | Model |
| 一次请求里每一块用原件、别的表示还是文字兜底 | Request Context |
| 引用变成请求报文里的字节 | Model 的发出 |
| 一次工具执行产出了什么 | Tool |
| 屏幕上此刻是什么、文件在哪 | 执行环境 |
| 哪一份转换件定义对这个租户生效 | 资产的求值。本组只登记类别并读求值的结果 |
| 谁能为哪个租户行事 | 身份与授权 |

本组提供、别人消费的面：

| 面 | 消费方 | 说明 |
| --- | --- | --- |
| 受理前处理件 | Session | 核对输入里的内容引用，持有，补上表示快照与媒体事实，或拦下 |
| 读媒体 | Model | 按引用与型号的限额交回字节 |
| 存产出 | Tool | 收下一串字节，交回内容引用 |
| 转换引擎的登记面 `media.engines` | 带引擎来的插件 | 按引擎的名字登记 |
| 协议 `media/v1` | 客户端 | 上传、认回、分页读、描述、触发预处理、观察 |

前三个面的接口归消费方：它们各自声明端口，本组的适配成员来接。本组消费的面：资产的类别登记与求值、SQL 契约、执行环境的图像成员、接入的登记表。

内容引用是共同契约的值（存储、键、媒体类型、字节数、摘要）。它不是下载地址，不是读取资格。本组在引用块上另认两个可选的属性：媒体事实（图片的宽高；语音的时长、采样率、声道）与表示快照。它们的形状归共同契约。

## 心智模型

把它想成一个寄存处。东西交进来，寄存处验过、放稳，才给一张存根。存根上写着东西的类型、大小与指纹，凭它取到的永远是当初那一件。

- **存根不是东西。** 会话日志、工具结果、模型请求的记录里放的都是存根。东西只在寄存处。
- **原件不动，加工件挂在原件上。** 一段语音的转写、一份 PDF 提出来的字，是原件的表示。原件永远在，表示只增不改。
- **寄存处不认识型号。** 哪个型号读原件、哪个读文字，是 Request Context 按型号能力选的。寄存处只管把每一份备好。
- **没人认领的东西到期清掉；有人认领的留着。** 引用方把存根写进自己的事实之前，先来说一声「这件我要」。
- **加工的人可以换。** 用哪家加工是一份资产，官方、组织、租户各能持有；加工的手艺是登记进来的引擎。
- **柜子可以换。** 字节放在本机磁盘还是对象存储，是存放提供者的事，寄存处的规矩不变。

拿它量一个设计：

- 会话日志或模型请求的记录里出现了媒体的字节：错了。只放引用。
- 引用先交出去、字节后落盘：错了。
- 清扫先读出「到期且没人持有」再去删：错了。两步之间可能有人来持有。条件要写在删除的那一次写里。
- 引用方先写自己的日志、后来持有：错了。中间被清掉就成了悬空引用。
- 两个租户传了同一份字节，于是共用一个对象：错了。一方凭此能探出另一方有这份内容。
- Request Context 每次请求来问「这份有没有转写」：错了。受理时已经把快照写在消息上，请求只读日志。
- 转换件定义生效而引擎不在，于是当成「不需要转换」放行：错了。答不可用。
- 核心领域的成员导入了本组的成员：错了。它声明端口，本组来接。
- `media` 导入了 `node:fs`、SQL 提供者或图像库：错了。经端口。

## 应然设计

### 媒体对象

一个媒体对象是一份不可变的字节，属于一个租户。它有不透明的键、媒体类型、字节数、摘要、媒体事实。键由本组生成，与内容无关；摘要只用来核对与并入。

状态有四种：上传中、暂存、持有、删除中。对外，删除中与不存在相同。每个操作在每种状态下的答复：

| 状态 \ 操作 | 开始上传（同一上传标识） | 追加分片 | 提交 | 放弃 | 持有 | 读字节 | 备好表示 | 到期清扫 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 不存在 | 写下元数据行，进上传中 | 拒绝 | 拒绝 | 幂等返回 | 拒绝 | 材料不可用 | 拒绝 | 不可达 |
| 上传中 | 认回原上传 | 写入；同序号同内容认回，不同答冲突；超出声明大小拒绝 | 字节耐久且摘要对上：进暂存并交引用；同租户已有同摘要的活对象：交那一份的引用，本对象进删除中；摘要对不上：拒绝，本对象进删除中 | 进删除中 | 拒绝 | 材料不可用 | 拒绝 | 上传期满：进删除中 |
| 暂存 | 认回，答已提交的引用 | 拒绝 | 认回原引用 | 拒绝 | 核租户，进持有，记下持有方 | 交字节，核摘要 | 允许 | 已到期：进删除中 |
| 持有 | 认回，答已提交的引用 | 拒绝 | 认回原引用 | 拒绝 | 同一持有方认回；新的持有方加记 | 交字节，核摘要 | 允许 | 不动 |
| 删除中 | 当作不存在 | 拒绝 | 拒绝 | 幂等返回 | 拒绝 | 材料不可用 | 拒绝 | 接着删 |

别的租户对任何状态做任何操作，答复与「不存在」相同。

次序是保管的全部：

- 元数据行先于第一个字节写下，晚于最后一个字节删除。字节从不没有行。
- 引用只在字节耐久之后、在一次元数据事务里交出。
- 同租户同摘要至多一个活对象，由元数据里带租户的唯一约束守。并入不跨租户。
- 到期清扫是一次带条件的元数据写：仍是暂存，仍已到期。持有也是一次带条件的写：核租户，核状态是暂存或持有。
- 删除先标记，再删字节，最后删行。进程在中间死掉，行停在删除中，启动后接着删。
- 引用方先持有，再把引用写进自己的事实。

持有是一条记录：哪个对象，被哪个引用方持有。引用方用共同契约的消费者引用表示。持有之后的对象不到期。

引用方有两种存入的办法。客户端经上传：提交之后是暂存，受理输入时由处理件持有。服务端里的引用方（工具的产出）直接存入并持有，一步完成，没有暂存这一段。

探测以字节为准：声明的媒体类型与探测出的不符时拒绝。每种媒体的大小上限是配置；超过时拒绝并带上限。

### 上传

上传是分片的，可以续传，按上传标识与序号幂等。每段的大小不超过入口给这个操作的消息体上限，由开始上传的答复告诉调用方。提交时调用方带上自己算的摘要，与本组算的不同就拒绝。任何一步的结果不知道时，调用方用同一个上传标识问状态或再提交，认回原来的那一次，不产生第二份。

### 表示

一个表示由（原件、转换件定义的版本）确定。它的结局只有两种，都是事实：转出来了（文字兜底，零个或多个别的模态的表示），或这份媒体本身转不出（例如没有文字层的扫描件）。两种都带出处：定义的名字与版本，引擎的名字与修订。

进行中与失败都不是事实。进行中是活体；进程没了它就没了，再要一次即可。失败只报告给这一次的等待方，不落盘，下一次再要会重做。

「备好表示」是幂等的操作：

1. 向转换件定义的端口求值：对这个租户，这种媒体此刻生效的是哪份定义。没有：答不需要。读不到：答依据不可用。
2. 这份定义的这个版本已经有结局：认回。
3. 已经有一次在做：加入等同一个结局。
4. 否则按定义里引擎的名字从登记表借出引擎。取不到：答引擎不可用，不当成不需要。
5. 把这一份媒体的读句柄与定义里的参数交给引擎，带时限与取消。
6. 校验引擎交回的东西，把别的表示的字节存成媒体对象，记下结局。

转换失败的原因是封闭的：依据不可用、引擎不可用、引擎出错、超时、结果不合契约、结果未知、取消。转换没有外部效果，重做是安全的；结果未知按失败报，本组不自己重试。

别的表示自己也是媒体对象，状态跟随原件。文字兜底不大时随表示记录保存；超过配置的界线时存成一个媒体对象，表示里放它的引用。

预处理什么时候做，由引用方定，机制只有上面这一个：

| 时机 | 谁发起 | 用在哪 |
| --- | --- | --- |
| 存入时 | 客户端在上传提交之后 | 人发的媒体 |
| 需要时 | 采用工具结果的一方，在当前型号原生收不下而这种媒体有生效的定义时 | 工具产出的媒体 |

### 转换件：定义与引擎

转换件定义是资产，类别 `converter`，正文是数据：媒体种类、引擎的名字、给引擎的参数、数据去向。资产的名字就是媒体种类：一个模态的名字，或一个具体的媒体类型写成资产名字的形式。所以「一种媒体只有一份定义生效」就是资产的同名求值。求值时具体媒体类型的名字先于模态的名字。类别的判定核名字与正文里的媒体种类对得上、引擎的名字是规范形式；引擎此刻在不在不属于判定。

转换引擎是登记进来的插件。它交两样：

- 声明：名字与修订；收哪些媒体类型；收多大；数据去向（进程内、本机、远端并写明去处）；同时能跑几个；它认的参数的结构。
- 转换函数：拿到这一份媒体的读句柄、参数、访问身份与取消信号；交回「转出来了」「这份媒体转不出」「失败」之一。

引擎拿不到存放、元数据与别的媒体。它交回的是文字与「媒体类型加字节」，内容引用与内容块由本组造。它要的密钥是它自己声明的秘密设置项。

登记面 `media.engines` 是一个拓展点：在服务端；按引擎的名字放，每个名字至多一项；宿主交给贡献方的只有登记的回执；每次转换现取；取不到答引擎不可用；撤下时不再借出，在途的转换答不可用，借出的都还回之后才算撤完；加可选的声明项是相容的，改形状换主版本。

本组在借出时给每个引擎包上三层，引擎不用自己写：时限；并发上限与排队上限，满了答背压；同一份的合并。

### 请求版本

请求版本是同一种模态下为一个目标做的适配版：给出允许的媒体类型、字节上限、宽高上限，交回不超过它们的一份。只有图片有请求版本：先缩到宽高上限以内，再沿质量阶梯编码到字节上限以内；有透明通道的不丢透明。做不出时答超限。显示用的缩略图是同一个操作的另一个目标。

请求版本不是事实。它由（对象、目标、变换的版本）确定，存在一个有容量上限的缓存里，丢了重做。

### 字节存放与元数据

字节存放是一个端口，按对象存储的语义定：开一次分段写入、追加分段、封口、按键与范围读、删除、放弃写入。封口的答复之后，整份字节耐久、按键可读、不再变。端口不假设目录、改名与落盘调用。每个提供者有一个名字，写进内容引用的存储一项；一次部署可以装几个提供者，新对象写到装配选定的那个，旧引用按名字找回自己的那个。

元数据是另一个端口。它的每个操作是一次事务，条件写在操作里：写下上传中的行、暂存或并入、仍然活着才持有、到期才标记删除、删行、读出停在删除中的行、记下表示。

每个提供者过本组的符合性套件，才算换得掉。

### 协议与接入

协议 `media/v1` 有七个操作与一个观察：开始上传、追加分片、提交上传、认回上传、分页读字节（可带显示用的目标）、描述一份媒体（状态、媒体事实、预处理的现状）、触发预处理；观察一份媒体的预处理状态，帧只说「变了」，客户端收到就重读。

接入插件的处理函数照固定的次序：核这次登录可以为目标租户行事；取主体；取媒体的面，取不到答依据不可用；调媒体的操作；映射结果。读操作里领域抛出答依据不可用，提交操作里答结果未知。

### 界面

界面模块往会话界面的两个拓展点放东西：输入框的附件区（贴图、拖入、选文件、录音，上传的进度，预处理的结果与失败原因）；消息里一块非文字内容的画法（缩略图与看原图，回放，文件的名字与大小，模型这一次读的是哪一份）。它依赖媒体的协议客户端；协议没挂着时它不加载。

### 资源寿命与装配

每个提供者、每个适配、每个引擎是应用装配里的一行。媒体的服务不在时，三个适配行随之卸下，它们放在邻域登记面上的贡献随之撤回：Session 对带媒体的输入答依据不可用，Model 对选中原件的请求如实失败，产媒体的工具命令不可用。纯文字的会话不受影响。

卸下是一个过程：先不接新的上传与转换，在途的各有结局，然后才算卸完。

清扫由维护方按节拍调，每次有上限；启动后先接着删停在删除中的对象。

## 原则与约束

- 原件永不改，表示只增不改。契约里没有改写字节的操作。
- 字节只在本组。交给别人的只有内容引用；交回字节只经读媒体的端口与协议的分页读。
- 读出的字节与摘要对不上，答材料不可用，不交。
- 无权、不存在、别的租户、删除中，对外是同一个答复。
- 结果不知道就是不知道：上传按原上传标识认回；转换按失败报，由人重做。
- 本组不决定型号读哪一份，不判断型号收不收得下。限额由调用方当参数给。
- 大小、时长、到期时限、缓存容量、文字兜底的行内界线都是配置，本组不写死数值。
- 被持有的对象不回收。

## 不变式

| 编号 | 性质 | 违反时的后果 | 由什么守 |
| --- | --- | --- | --- |
| ME-1 | 引用交出之前字节已经耐久；读出的字节与摘要对不上就不交 | 历史指向不存在或被换过的内容 | 模型 [MediaCustody](../../docs/architecture/verification/media-custody/MediaCustody.tla) 的 `LiveIsDurable`；存放提供者的符合性套件 |
| ME-2 | 字节从不没有元数据行 | 崩溃后留下没人知道的字节 | 模型的 `BytesHaveRow`；核心的崩溃注入用例 |
| ME-3 | 被持有的对象不会被清扫删掉 | 历史里的媒体丢失 | 模型的 `HeldStays`、`ClaimsOnHeld`；清扫与持有并发的用例 |
| ME-4 | 引用方的事实里引用的对象一定被持有、字节耐久、属于同一租户 | 悬空引用；跨租户引用 | 模型的 `LogRefsResolve`；处理件的契约测试 |
| ME-5 | 一个租户拿不到、探不出另一个租户的对象；并入不跨租户 | 跨租户泄漏 | 模型的 `HandedOwn`；每个入口的跨租户用例 |
