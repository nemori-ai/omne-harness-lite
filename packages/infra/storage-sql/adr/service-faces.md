# 同一 SQL 实例的独立与 Service 访问面

采用依据：[共享集成决定](../../../../.meta_harness/design/record/decisions/shared-storage-clock-integration/decision.md)。行为归 [SPEC](../SPEC.md)。

Cordis 4.0.4 为不同调用方返回不同代理。原对象严格比较会拒绝同一 SqlStorage 的合法代理。
真实模型装配还会从 raw.atomic 发起事务，再让注入消费者参与，因此只包装 Service.atomic 的 unit 不完整。

采用提供者私有的局部 Symbol，将正式绑定关联到确切 raw 对象。属性不可写、不可重配，不从公共入口导出。
unit 保留帧、忙和既有污染的原次序；随后接受 raw 严格相同或正确关联的面。不能读身份时按原不同实例分支污染。
同文件、服务键或配置相同不构成同实例。投影只处理受信任进程内的提供者面，不承担租户授权、任意 JavaScript 沙箱或跨进程身份。

方法绑定原引擎，避免代理接收者破坏其私有字段；没有新提交点、async 包装或复制的 maintenance 控制器。
Service 构造只发布借用资源。拥有插件与外部装配分别保留自己原有的关闭责任。

代价是一处内部身份核验和薄方法委托。它们承担实例识别与可替换集成，没有另设事务协调器。
当 Cordis 代理语义变化、同提交跨进程、借用所有权改变或需要不受信任插件沙箱时，必须重新核对本选择。
复验至少覆盖双向参与、两个代理、异实例、换代、标记读取失败污染、原检查次序及撤除时在途。
