# Environment provider retirement

The registry retains each original provider until its retire operation reports drained.
A pending report does not confirm that the provider stopped. A failed registry close preserves the original retirement obligation for explicit retry.

The managedEnvironmentRegistry binding registers safe work before setup and retains its original close control in the row port.
It uses startRetainedAssemblyWork from assembly-lifecycle. A failed or pending original close keeps the managed row pending.
The ordinary lifetime cannot close preceding dependencies until the same registry close succeeds.
The assembly owner can obtain the retained control from closeControl for that row and explicitly retry it.
Service withdrawal does not transfer that responsibility or create a replacement registry.

The standalone registry keeps its direct close result. Its caller must retain the original instance and dependencies after failure.
The adapter does not authorize recovery or determine physical quiescence. Those decisions remain with the actual environment provider.

## Placement and lease adoption

The registry admits one trusted placement source per owner. Its caller fiber owns the contribution. Withdrawal immediately rejects new reads and new effects. The source disposer waits for callbacks already admitted to that exact contribution; replacement does not adopt those callbacks.

An acquisition owns its input data and original resource callbacks before the first authority wait. Discovery uses a snapshot of the registered providers, or only the original owner named by an explicit reference. The strategy receives the complete matching set from that snapshot. Candidate selection checks binding ownership and all requested facilities before consulting the source strategy. It must not choose by provider registration order. Duplicate references from one provider reject its discovery result. Withdrawal during selection rejects acquisition of that original entry. A replacement with the same name cannot inherit the pending selection.

Provider success is provisional. Before delivery, the registry checks current access, the original source, and the selected description. Failure attempts release of that exact lease. Pending or failed release retains the lease with the original provider registration. Contribution disposal closes the original provider permission writer before waiting for admitted callbacks. It retains unfinished callbacks and provisional leases for the same owner. Explicit retry completes their release and original provider retirement. Unconfirmed release rejects close and preserves that responsibility. The registry does not acquire a replacement instance. Each new command or file operation checks current authority for the original adopted instance. Existing process observation and stop controls remain with the original provider after access withdrawal.

## Native actions and durable host ownership

HOST-1 Native actions require no Runtime, Session, tenant, or Storage dependency. The durable provider consumes these actions through original scope, resource callbacks, and Storage. Cordis supplies integration and retained lifetime. User commands receive explicit cwd and env. Native standalone callers retain their original controls or manifests; these values alone do not establish cross-crash recovery.

HOST-2 The durable provider confirms original boot/unit/generation recovery coordinates before native preparation. The gate checks its actual cgroup before ready. Ready does not permit user execution. GO requires confirmed original permission and an open call, and occurs at most once. Stop closes the original GO writer first. An absent scope confirms stop only after original launch isolation or drain. Creator PID identity is an observation, never kill authority. Manager failure or uncertain late launch retains pending responsibility.

HOST-3 Persistent Bash holds actual cwd, variables, functions, and options. Each leg uses separate output pipes, sinks, and control identity. Completion requires a valid marker, both output EOFs, exited original sinks, and no remaining descendants. The provider confirms native leg completion and the original call stop receipt before admitting another leg. Unknown completion does not admit a successor. Completed old legs do not stop later legs. Birth adoption survives creator-call release; each later leg obtains its own permission.

HOST-4 File paths are explicit absolute host paths. They do not define a sandbox. Content methods reject target and parent symlinks and special objects; stat can report a symlink. Reads use bounded byte ranges and check the original handle and path metadata before delivery. Metadata versions do not establish external CAS. Search uses literal UTF-8 pattern bytes, including in malformed source text. Traversal and pages have finite configured budgets. Directory order and pages describe that scan, not a snapshot across external changes.

HOST-5 Mutations from one provider are serialized. Unsettled old-generation mutations block new-generation publication. Batch preflight checks every target before staging or publication. Stages use the target filesystem, exclusive creation, fsync, and directory sync. Copy completes staging before publication; cross-filesystem move is unsupported. Each publication and final completion has an original receipt. Lost receipts return unknown and stop subsequent publication. Recognition is read-only and does not infer receipts from current matching bytes.

HOST-6 Physical stop, disposal, and business completion are separate obligations. The original index persists the manifest before staging. Stage ownership records dev/inode/birthtime before data writes. Disposal checks that original physical identity; matching bytes alone do not authorize disposal. Missing ownership with an existing stage remains pending. Observed replacement stages remain pending and are preserved. Stage disposal requires no external rebinding of the private stage entry or its resolving parent paths between the final identity check and unlink. Reserved stage names are not OS isolation. The identity checks do not establish atomic conditional deletion. Read-only recovery preserves external target changes. Cleanup completion does not delete an unknown manifest or turn it into business success. A raw copy unknown result carries original manifest, stages, and publication receipts for its caller.

HOST-7 Native waits have explicit policy bounds. Expiration does not cancel an in-flight IO or discard its cleanup responsibility. Before the first wait, acquisition owns its input data and original resource callbacks. The provider retains each original acquisition and facility operation. After readiness verification, acquisition checks that the original provider and call remain open before it creates a lease. Retirement closes permission writers before waiting for admitted operations. Pending plan, permission, adoption-index, and settlement work prevents a drained report. Creator release returns pending and retains the original lease while adoption or its host index update is unfinished. The same release operation must be retried after that work settles. The provider retains original promises, controls, index, and dependencies until confirmed stop and disposal. Pending close rejects managed retirement and can retry the same owner. Linux user systemd scopes, a working user manager, actual Bash, and the configured filesystem are platform prerequisites. The provider reports unavailable or pending when they cannot supply the required evidence; it does not replace them with PID guessing or a fake backend.
