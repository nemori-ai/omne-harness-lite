# 租约策略与私有持久操作分离

2026-10-05，主会话在 panqiwei 的 R1-T5 自驱实施授权内采用内部职责分离。
采用范围只有本提供者；没有新增公共能力或服务，也未表示领域验收完成。
输入规格 SHA256：7da7b62641c1721066341ebeeba5c0a8f616364468bca709cca3ed6d48e82e04。
选择、表达和施工分别独立审阅；具体行为承诺由 [SPEC](../SPEC.md) 和其未迁依据拥有。

原 clock 实现将时间/租约判断与三个 SQL 操作放在同一类，策略直接消费 Kysely 事务。
依据 [D-115](../../../../.meta_harness/design/record/decisions/actual-architecture-and-thin-spec/decision.md)，
采用私有三操作端口，使策略只依赖事实和具名持久操作。SQL 后端继续借用原 Storage，
公开 LeaseClock 构造门选择该后端；私有基类承载同一份状态，不增加方法转发层。

不采用“整文件属于 adapter”的标签，因为业务判断仍须有独立责任。
不提升为新公共 capability，因为这三个操作没有实际跨提供者消费者。
不修改共享 Storage，因为本切片不改变事务抽象，原比较写和持久身份足以保持行为。

同时修复原关闭准入窗口：现行 SPEC 继续采用的旧节点要求等待定时在途前停止准入，
但 BASE282 实现在等待后才闩住。独立真实 SQLite 观察得到正常和存储缺陷两个反例。
独立停止位保留已开始续约的完成，并保留缺陷分支不额外回收的责任；不是取消已提交效应。
本次没有扩大手动续约或并发 start/close 保证。

复核条件：新增持久操作或真实跨提供者消费者；共享 Storage/事务保证变化；
时间/租约政策变化；私有继承造成额外状态或公开声明不能从真实制品消费。
应实际检查封装成本、所有消费者及四层入口，不凭分离宣称总复杂度下降。
