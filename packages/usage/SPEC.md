# Usage

## 总体架构

Usage 回答一个问题：一个租户或一个会话在一段时间里用了多少、花了多少，怎样合起来给人看。它不拥有任何一笔用量或费用，只把各个产生方的事实读出来，折叠，合并，开放。包组有七个成员：

| 成员 | 回答的问题 |
| --- | --- |
| `usage-contract` | 用量事实、查询、度量与覆盖说明有哪些值；折叠、切分、比率与分位怎样算；来源、会话范围这两个端口长什么样。纯数据与纯函数，另带来源的符合性套件 |
| `usage-cordis-contract` | 在这套系统里它以哪些服务出现；来源登记表怎样登记与撤除 |
| `usage` | 一次查询怎样问范围、读来源、折叠、合并。不依赖 Cordis；`./cordis` 入口是提供者 |
| `usage-adapters` | 模型调用的发出事实、工具执行的账、会话的执行，各怎样接成本组的端口。每个适配是一个 Cordis 插件 |
| `usage-protocol` | 对客户端开放哪些操作 |
| `usage-access` | 接入插件：核身份，调查询服务，把结果映射成协议的结果 |
| `usage-ui` | 界面模块：「用量」页、会话里的两处、卡片与呈现两个拓展点、布局与它的编辑 |

客户端经协议发来一次查询。接入插件核这次登录可以为目标租户行事。查询服务在范围是会话时先问会话范围端口，得到这个会话的几个消费者范围；再向登记着的每个来源分页读这个范围与时间段里的用量事实；用同一套纯函数折叠成各桶各组的度量，带上覆盖说明返回。

源码依赖只朝内。`usage-contract` 不导入任何实现。只有 `usage-adapters` 认识邻域，而且只认识它们的公开契约。Model、Tool、Session、Agent、Context 的成员不导入本组的任何成员。

## 领域边界

Usage 拥有：用量事实与用量查询的共同形状；度量与导出指标的定义；覆盖说明；来源的登记与合并；对客户端的协议；面板、卡片、呈现与布局。

Usage 不拥有：任何一笔用量、费用或时刻（归产生方：模型调用的归 Model，工具执行的归 Tool）；调用账目的修订、小计与单位规则（归共同包组的调用账目）；一个会话有哪些执行（归 Session）；谁有资格读（归身份与授权，以及每个来源自己的资格）；上下文怎样组装、装不装得下（归 Request Context）。Usage 不估算费用，不换算单位，不保存事实，不知道一个来源是模型还是工具。

Usage 是接在核心上的可装卸部分。卸掉它，核心的流程不变，任何事实都不丢；装回它，此前的用量立刻读得到，不需要回填。

Usage 声明、由本组的适配成员实现的端口：

| 端口 | 适配的是谁 | 一句话 |
| --- | --- | --- |
| 用量来源 `UsageSource` | Model 的发出事实读口；Tool 的按范围列账读口 | 我需要按租户、时间段与消费者范围分页读逐笔的用量事实，并知道有几笔没有时刻 |
| 会话范围 `UsageSessionScope` | Session 的历史读口（读者身份） | 我需要把一个会话换成几个消费者范围：它的全部执行，以及它的压缩任务 |

Usage 为别人提供的：

| 提供 | 对方 | 一句话 |
| --- | --- | --- |
| 协议 `usage` | 客户端、命令行、仓库外的程序 | 我提供统计、逐笔记录与上下文占比的读取 |
| 拓展点 `usage.widget`、`usage.presentation` | 别的界面模块 | 你可以往面板里带来卡片与图表类型 |

## 心智模型

把 Usage 想成一个纯算的工位，前面接着几根管子。每根管子是一个来源，流出的是逐笔的事实：一次模型发出，一次工具执行。工位不存水，只在有人来问的时候读一段、算一遍。所以它没有自己的一致性问题：一笔事实算不算、算几次、重启后在不在，都由产生方自己的那次提交决定。

最容易想错的地方：

- 合计不是完整的数。它是已知的和，旁边一定带着有几笔未知。
- 比率不能平均。各桶的缓存命中率平均起来不是总的命中率，要用合计重新算。
- 会话不是事实上的一个字段。产生方不认识会话；会话的范围是 Session 给出的一组执行，产生方的事实只带着受理时冻结的消费者引用。
- 没装的来源不算缺。查询只对登记着的来源负责，并说出这次答了的是哪些。
- 上下文占比不是用量。它是一个读数，不能相加，也不求实时。

## 应然设计

### 用量事实与来源

- 一笔用量事实对应产生方的一个最小单位：模型调用的一次真实发出，工具执行的一次调用。它带来源名、主体、时刻、消费者引用、标签（模型、供应商、档案、工具）、结局与成因、用量项、该付的费用、各段时长、连接重试次数、当时的窗口。它不带请求、回复、参数或任何正文。
- 用量项与该付的费用取自调用账目，修订、未知、暂估、单位与「该付多少」的规则归[调用账目](../common/SPEC.md#调用账目)，本组不另定。该付的费用未知时没有单位；一笔没有费用项时它不适用，不算未知。一笔里没有某一项用量，这一项对它不适用，不算未知。
- 来源按租户、时间段、消费者范围、次序分页交出事实，并报出范围内没有时刻的笔数。没有时刻的事实不落在任何时间段里。
- 消费者范围是一个拥有者名加一组工作标识。一笔事实在范围内，当且仅当它的消费者引用的拥有者相同，且工作标识等于其中一个，或以其中一个加斜杠开头。
- 一个会话的范围是几个消费者范围：Agent 拥有者下它的执行，与压缩提供者拥有者下它的压缩任务。压缩提供者以独立消费者的身份发出摘要调用，它的工作标识是压缩任务的引用，不以执行标识开头。两个拥有者名由应用装配给。
- 来源是一份份登记上去的贡献，撤回只撤自己那一份。来源名在登记表里唯一，重名的登记失败。

### 查询

- 一次查询给出范围、时间段、时区、时间桶与至多两个切分维度。范围是一个租户或一个会话。时区是必填的 IANA 时区名；时间桶的边界按这个时区算，夏令时切换那两天的桶照实际长度。
- 次序固定：先核资格；范围是会话时解析会话范围；再读每个登记着的来源；最后折叠与合并。会话不存在与会话不属于这个租户，答复相同。
- 任何一个登记着的来源答不了，整次查询答依据不可用并指明是哪个来源，不拿其余来源凑一个偏小的合计。没有登记的来源时答空结果并说明没有来源。
- 结果带覆盖说明：答了的来源、没有时刻的笔数、费用未知的笔数、比率里排除的笔数、事实最早从哪一刻开始有。
- 时间段与时间桶的组合有上限，超过的请求在读任何来源之前被拒绝。
- 逐笔记录的读取按同样的范围与时间段分页，一页的大小有上限。
- 组织这一种范围留在类型里，当前答不支持。

### 度量与指标

- 求和类的度量（各类 token、费用、时长）分三部分给出：已知的和、未知的笔数、暂估的笔数。未知与暂估不进求和。费用按单位分开，单位不同不相加、不换算；费用未知的笔数单独给出，不归到任何单位。
- 计数类的度量：调用数、单位数、重试的调用数、中断数、按成因的失败数。一个调用的几笔里，时刻最早的一笔算调用，其余算重试，由折叠判，来源不必知道。
- 比率由合计算，分母为零或没有可用的笔时是未知。缓存命中率是缓存读除以未缓存的输入、缓存读、缓存写之和；一笔里三项有任何一项未知，这一笔不进这个比率，排除的笔数写进覆盖说明。
- 分布类的度量（首字延迟、整次耗时）从逐笔的值算中位数与九成位数，不跨桶合并已算好的分位。
- 一段时长只由两个都记下的时刻算出；缺任何一个，或后一个早于前一个，这段时长是未知。
- 任何切分下，各部分的已知和、未知笔数、计数分别相加，等于不切分的结果。

### 上下文占比

- 取这个会话范围里用途是主循环、最近一笔用量已知的模型发出，把未缓存的输入、缓存读、缓存写相加，除以这笔事实上的窗口。
- 答复带着这一笔的时刻与模型，并带自动压缩的百分比。它不求实时：压缩或换模型之后、下一次请求之前，它仍是上一次的数。
- 还没有可用的发出时答「还没有」。用量或窗口缺失时答未知并给出原因，不给出一个猜的数。
- 上下文占比不进模型的请求，也不经过 Request Context 与 Runtime Context。

### 协议与接入

- 协议 `usage` 有三个读操作：统计、逐笔记录、上下文占比。都要登录身份；处理函数核这次登录可以为目标租户行事，每个来源再核自己的读取资格。
- 协议不设观察。客户端在打开时、手动刷新时与可见期间按间隔读取。
- 协议的结果里只有数与标识。

### 面板、卡片、呈现与布局

- 界面模块往外壳的页面位置放「用量」页（标识 `usage`，次序 30，`utility` 段），往会话的右侧边栏拓展点 `sessionSide` 放这个会话的用量（页签「用量」，次序 20），往会话的状态栏拓展点 `sessionStatus` 放上下文占比（次序 0）。会话的拓展点由应用装配交给它，它不导入会话的界面模块。
- 面板由三样互不决定的东西组成。卡片回答看什么数据：拓展点 `usage.widget`，按位置分键，一项是一张自己取数据的卡片。呈现回答这份数据怎样画：拓展点 `usage.presentation`，按数据的形状分键，一项是一种图表类型。布局回答摆在哪：一份有序的卡片清单，每张带宽度与所选的呈现。
- 原生的卡片与呈现也是这两个拓展点上的项。面板上出现什么只由布局决定。
- 布局有三层来处，后面的盖前面的：界面模块带的缺省；应用装配给的缺省；用户改过的。用户的改动经装配注入的偏好存取保存。
- 布局里的卡片不在了，那个位置显示不可用并允许去掉；所选的呈现不在了，用这张卡片的缺省呈现并标明。一张卡片渲染失败不影响别的卡片。
- 图表只用界面工具包的图表控件；本组的界面模块不直接导入图表库。
- 观感照[视觉规范](../../.meta_harness/agents/skills/visual-standard/canonical/SKILL.md)；图的墨、动与文本替代的规则见技能与[前端规格的图表一节](../frontend/SPEC.md#图表)，颜色与语气的规则见[规则与 token 的索引](../../.meta_harness/agents/skills/visual-standard/canonical/references/rules-index.md)的 C3、C4。下面每一句通知都写明语气：失败是 `InlineNotice` 的 `danger`；注意是 `caution`，琥珀；中性是 `neutral`。正常的状态不画字、不画点。
- 「用量」页是单列页：`PageColumn` 加 `PageHeader`，标题「用量」，页不自己写标题。页头右边是分段控件「时间段」（今天、7 天、30 天、90 天，缺省 7 天）与一个 `⋯`（`DropdownMenu`），里面是「编辑面板」与「刷新」；编辑时那一项写「完成」。会话侧边区里的面板没有页头，同样的分段控件与 `⋯` 在面板的顶上；状态栏里没有这一行。
- 卡不画成卡片：一张图是一段，上面一条细线，说明字号的强标题，下面是图；没有底色、阴影与圆角框。用量页上是三列的栅格，段与段靠间距与细线分开；会话侧边区里是一列。
- 概览是一行五个数字块（`StatBlock`）：费用、Token（输入与输出）、模型请求、缓存命中率、首字延迟（中位）。数字用表格数字，标签是弱墨的说明字。未知写「—」，不写 0；不同单位的钱不相加，用「 + 」并列；有费用未知的笔时写「n 笔未知」。
- 图里的系列只用图表色，按固定次序取。数据到了，整张图到达一次；之后数变了只落定，不逐柱长出来。悬停的提示是平样式的提示。空、只有一个点、全是未知各有确定的样子，不画成零。
- 刷新是安静的：到点重读或人按「刷新」时，卡片留着上一次的数，只把变了的落定一次，不退回「正在读取……」。
- 一张卡片的各个状态：
  - 第一次读：标题下是 `LoadingState`「正在读取……」。
  - 读不到：标题下一行 `InlineNotice` 写原因。`denied`、`not-found`、`unsupported` 与结果不知道（`uncertain`）是中性；`basis-unavailable` 与连不上（`unavailable`）是注意，带「重试」，按下等于刷新；`limited` 是注意；`invalid` 与外壳给的租户读不懂是失败；协议之外的结果写「读取没有成功。」（失败），结果的原名收在「详情」里。
  - 卡片不在了：那一张的位置上一行「这张卡片不可用：带来它的模块不在了。」（注意），带「去掉」。
  - 所选的画法不在了：用这张卡片的缺省画法画，图的上面一行「所选的画法不在了，用的是这张卡片的缺省画法。」（注意），带「去掉」。
  - 没有能画它的画法：一行「这张卡片现在画不出来：没有能画它的画法。」（注意），带「去掉」。
  - 渲染出错：一行「这张卡片出错了，别的卡片不受影响。」（失败）。
- 编辑面板：进入后每张图的标题旁出现一个 `⋯`，里面是上移、下移、宽度（窄、中、宽）、画法（缺省加这个形状登记的画法）、去掉；面板底部是「加一张」的下拉与「恢复缺省」。都用共用件的下拉，不用原生的 `select`。每一次改动立刻生效，自己就是回执，不另写「已保存」。
- 上下文占比在会话的状态栏里，是状态栏里唯一的东西，不抢输入框：一条细的读数条（`ReadingMeter`），旁边是说明字号的百分比与「截至上一次请求（时刻 · 模型）」。读数条平时是中性墨；越过压缩线或超过 100% 时变琥珀（注意）。还没有可用的请求、用量未知、窗口未知时，读数条的位置写「—」与原因：「还没有收场的请求」「这一次请求的用量未知」「这个型号的窗口未知」（中性）。
- 用到的共用件：`PageColumn`、`PageHeader`、`Segmented`、`DropdownMenu`、`Button`、`StatBlock`、`StackedBarChart`、`LineChart`、`AreaChart`、`ShareBar`、`ReadingMeter`、`InlineNotice`、`LoadingState`、`useSettleCue`、`useArrival`。

### 资源寿命与装配

- 查询服务、三个适配、接入插件各自可以单独装上与卸下。卸下时先不接新查询，在途的查询得到确定的答复，再撤协议与来源登记。
- 一页读多少、一次查询最多读多少页、时间段与时间桶的上限、界面的读取间隔，都由装配显式给出。

## 原则与约束

- 事实只有一个源头：产生方。本组不保存、不缓存任何一笔事实的权威副本。
- 规则只写一处：折叠、切分、比率、分位、时长与覆盖说明都只有一份纯函数实现，查询服务、适配的符合性套件与界面共用它的结果。
- 未知如实是未知。不把未知写成零，不把不完整的合计说成完整的，不把一个猜的占比显示成读数。
- 核心不认识本组。本组需要的东西声明成端口，由本组自己的适配成员去接邻域的公开读口。
- 看得到用量不等于看得到内容。

## 不变式

| 编号 | 永远成立的性质 | 违反的后果 | 由什么守 |
| --- | --- | --- | --- |
| US-1 | 一笔事实在一次统计里恰好算一次；账目的后一修订替换前一修订，不叠加 | 花费翻倍或漏算 | `usage-contract` 的折叠性质测试；来源的符合性套件 |
| US-2 | 合计只含已知的金额与数量；未知与暂估的笔数单独给出；单位不同不相加 | 人把不完整的数当成完整的 | 度量的类型（已知的和与未知的笔数分开）；折叠性质测试 |
| US-3 | 任何切分下各部分之和等于不切分的结果 | 两张图对不上 | 折叠性质测试，含夏令时切换日的时间桶 |
| US-4 | 比率由合计算；分母为零或有未知时是未知 | 给出一个没有意义的百分比 | 比率的类型与用例 |
| US-5 | 一次查询只读目标租户的事实；会话不存在与不属于这个租户答复相同 | 跨租户泄漏用量或会话是否存在 | 接入插件与查询服务的用例；发行层的两个租户用例 |
| US-6 | 协议与用量事实的形状里没有请求、回复、参数或秘密 | 账目读口泄漏内容 | 协议契约的形状；契约的往返用例 |
| US-7 | 任何登记着的来源答不了时不给出合计 | 少算一个来源而人不知道 | 查询服务的用例 |
| US-8 | 上下文占比的答复带着它是哪一刻、哪个模型的；缺用量或窗口时是未知 | 人照着过期或编出来的占比做判断 | 占比的类型与用例 |
| US-9 | 核心的成员不导入本组的任何成员；卸掉本组后核心的用例照过 | 插件变成了核心的依赖 | 方向检查；发行树上停用本组各行的用例 |
| US-10 | 面板上出现的卡片与呈现只由布局决定；同一个键上标识相同的两项是装配错误 | 界面出现两份互相矛盾的图，或一张被悄悄盖掉 | 布局求值的用例；外壳契约的存放规则 |
