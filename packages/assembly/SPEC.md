# Assembly

## 总体架构

Assembly 包组回答装配与交接领域里两个与 Cordis 贴得最近的问题：一次求值怎样从合法的来源、定义、实现与运行条件得到一份可采用的执行配置，换代时新旧推进者怎样交接；一个资源拥有者计划退出时，它手里的一组租约怎样有确定结局地关掉。另外，它为全系统提供少数几个 Cordis 集成辅助。

| 成员           | 回答的问题                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `assembly`     | 一组租约的关闭协议（准入、排空、按序执行退出步骤、给出报告）；以及采用与重装的行为规则的位置                                                                  |
| `kernel-basis` | Cordis 集成辅助：带配置校验的插件定义 `definePlugin`、可选依赖读取 `resolveOptional`、调用方 fiber 登记 `registerInCallerFiber`、测试装配 `startTestAssembly` |

关闭协议是一个纯进程内的对象：资源拥有者为自己的一代资源建一个实例，接纳租约，退出时停准入、等租约释放、按自己给的步骤列表关后端，拿到 `closed`、`failed` 或 `timed-out`。采用协调者在新 Run 开始或租户显式要求重新加载时求值，把整份结果写成本次执行的采用依据；换代时它编排「停新准入、交接在途、撤依赖、关后端」的次序，每一步由各资源拥有者对自己的关闭协议实例完成。`kernel-basis` 不声明服务键，只把各领域都要写的几段 Cordis 胶水写一次。采用协调的公开操作、失败分类与耐久性质归装配与交接领域的采用协调设计（`adoption-contract`）。

## 领域边界

本组拥有：一组租约的关闭协议与它的报告；求值、采用依据、发布与重装入口的行为规则；Cordis 插件定义、可选依赖读取、调用方 fiber 登记与测试装配这几个辅助的形状与失败边界。

本组不拥有：来源与业务规则（治理，见 `packages/governance`）；推进资格（原工作，Session 与 Agent）；调用事实与结果（实际执行者与消费者）；各能力的 Service 定义与服务键（各能力的契约成员）；发行与运维装配（应用）；fiber 状态与依赖注入（Cordis）；被关闭的资源本身（资源拥有者）；结果（操作结果归 `packages/common` 的 `operation-result`）。

本组声明、由别人实现的端口：

| 端口                         | 对方                                         | 本组需要它做什么                                               |
| ---------------------------- | -------------------------------------------- | -------------------------------------------------------------- |
| 退出步骤列表、排空超时与时钟 | 资源拥有者                                   | 给出关哪些后端、按什么次序、等多久、用哪个时钟                 |
| 类别提供者的候选列举         | 各能力类别（Tool、Skill、MCP、Agent 定义等） | 在一次求值作用域里列出候选项；本组只校验公共字段，不解释正文   |
| 迟到结果的常驻接收方         | Agent（宿主里的结果接收方）                  | 承接旧推进者在途调用的迟到结果；装配不接收、不保存、不重放结果 |

本组为别人实现的端口：

| 端口                                               | 对方                                   | 本组提供什么                                                  |
| -------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------- |
| 关闭协议                                           | 各资源拥有者与采用协调者               | 一组租约的准入、排空、退出步骤与报告                          |
| `definePlugin`、`resolveOptional`（`./cordis`）    | 全部 Cordis 插件作者                   | 强制配置 schema 的插件定义；缺席答 `undefined` 的可选依赖读取 |
| `registerInCallerFiber`、`Admission`（`./cordis`） | 目录型服务：Model 的实例目录与转换目录 | 在调用方 fiber 的 effect 里登记一份贡献，撤除时撤回它         |
| `startTestAssembly`（`./testing`）                 | 各成员的测试                           | 把测试插件装进新 Context，失败与撤除时收集全部错误            |

## 心智模型

关闭协议像一扇只关一次的门。门开着时，按名字发租约；关门那一刻先上锁（之后谁来都答「已停止准入」），再等屋里的人都出来，等不到就如实报「超时」并留下名单，等到了就按清单逐项关灯，哪盏灯坏了记下来。门只管这一代：换代就是另开一扇门，旧门关不着新门里的人。门不知道远端是否可达，远端暂时不通不是关门的理由。

采用是一次拍照，不是一根活线。求值把当时合法的胜出者连同版本、清单与请求输入一起写进采用依据，这次执行从依据里读，不再回头问提供方；只在新 Run 开始或租户明确要求重新加载时重新拍照。拍到一半来源变了，就重拍一次；还变，就不发布，旧照片留着。

最容易想错的地方：fiber 处于 `ACTIVE` 不等于存储可写、远端可达或工作已恢复；`dispose()` 完成、卸载完成或改写当前指针都不是关闭，也不表示业务收场、结果交接或外部效果撤回；同级 Cordis effect 的完成顺序不是产品的关闭顺序。

## 应然设计

### 关闭协议：一组租约

- 一个实例关闭一个进程里的一组租约；资源拥有者换代时另建一个实例。协议不打开代际，不把租约迁到另一个提供者，不选择关哪个后端；调用方给出步骤列表、排空超时与时钟。排空超时小于零时构造失败，此时还没有租约。
- 远端不可用不是停止准入；本地代理仍在时，调用方不调用 `close`，也不把准入设为停止。撤除本地提供者才是对该实例调用 `close`。
- 进程在 `close` 完成之前死亡，这次调用没有报告，不算成功；崩溃后的恢复归进程外监督。步骤失败或超时不回滚已经发生的外部效果。

### 关闭协议：准入与释放

- `admit` 必须带租约名字，没有默认调用方、租户或账号。准入开放时：空名字抛错，不新增持有；未持有的名字得到新 id；已持有的名字返回同一个 id；当前 id 被释放后再借同名得到新 id。准入停止后，`admit`（包括空名字）一律抛 `admission stopped`，不新增持有。
- `release` 在任何状态下都可以调用。只有传入的 id 仍是该名字当前持有的租约时才移除；旧 id 不能拆掉同名的新租约；重复释放什么也不做。释放不让 `close` 的 promise 确定，报告确定之后也不改写报告。
- `held` 按进入持有集合的次序返回当前持有的名字。`held` 与 `detachObserver` 都不释放租约、不停止准入、不让 `close` 确定；观察者离开不取消已持有的租约。
- 这些操作都不发出事件。

### 关闭协议：关闭与报告

- 第一次 `close` 建立唯一的关闭 promise；之后的调用（包括另一个 `caller`、从步骤或时钟里同步再调）都返回同一个 promise。被排除的调用方由第一次调用固定：它当时已被持有，排空就不等它。
- `close` 在返回 promise 之前就把准入设为停止，先于排空与任何步骤。
- 排空等到每个被等待的租约都释放，或注入的时钟走完排空超时。开始时等待集合非空而超时为零，直接报超时，不调用时钟。时钟走完时集合仍非空，报 `timed-out` 并按准入次序列出仍在等待的名字，步骤不执行；之后的释放不改写这份报告。时钟拒绝时，关闭 promise 以该错误拒绝，准入保持停止。
- 步骤按列表次序执行，每步是 `always` 或 `if-no-failure`。前面有步骤抛错之后，`always` 仍执行，`if-no-failure` 跳过并记入 `skipped`。抛错记为步骤名与消息（`Error` 取其消息，否则取字符串形式）。有失败或有跳过报 `failed`，列出已完成的步骤、每一项失败与跳过的步骤；否则报 `closed`，只列已完成的步骤。
- 关闭不取消租约；超时时仍被持有的租约一直持有到释放。promise 只在本进程内有效，不是跨进程的决定。
- 旧实例的 `close` 只等自己持有的租约，不释放新实例的租约，也不停止新实例的准入；旧报告确定之后新实例仍可接纳。
- 资源拥有者把在途结果的交接放在关闭后端之前；交接失败后，`always` 的后端步骤仍执行，`if-no-failure` 的跳过。

### 采用记录与失败

- 一次求值被采用时，持久记录是本次执行的采用依据：资产与定义版本、装配清单、固定的请求输入、适用执行条件。装配清单保存这次求值的来源、锁定的依赖身份与版本、扩展顺序；它不是活体句柄。
- 求值输入里的能力身份是类别加名字，不带版本；带版本的输入在求值之前被拒绝（`malformed`）。版本由来源层的层值决定：资产的「持有固定版本」与「跟随当前版」是层值。新的求值采用当时的合法胜出者；固定版本不豁免合法性、资格、锁定或撤权。Agent 定义总是解析为该身份最新的合法发布版本。
- 同一次执行从采用依据读取已记下的正文，不改写它。还没发出的 Tool 或 MCP 调用仍可按合法刷新看到新的定义与可用性；已记录的 Skill 正文不变，还没取用的 Skill 正文在取用时读当时的合法版本。
- 候选失败不发布新的采用依据，调用方得到失败记录，旧的合法采用保持。失败记录有四项：种类、身份、原因、旧采用是否保持。种类只有五种，没有成功种类：

| 种类         | 结果                                                                                     | 旧采用                             |
| ------------ | ---------------------------------------------------------------------------------------- | ---------------------------------- |
| 缺合法定义   | 装配失败，不是已采用。必需能力从未取得合法定义，或运行时自身必要依赖无法建立，都归这一种 | 保持；从未有过合法采用时写不适用   |
| 实现暂不可用 | 合法定义与必要绑定已具备时形成采用依据，并在依据里标明该能力暂不可用；不是装配失败       | 已有旧采用时保持；首次装配写不适用 |
| 候选被拒绝   | 返回原因，不是已采用                                                                     | 保持；从未有过合法采用时写不适用   |
| 来源未知     | 不用猜测补齐定义，不是已采用                                                             | 保持；从未有过合法采用时写不适用   |
| 无类别拥有者 | 不解释、不采用；未知类别归这一种                                                         | 保持；从未有过合法采用时写不适用   |

- 资产发布、装配成功、运行使用、旧实例退出是四件分开的事。

### 发布

- 注册表在一次求值作用域内合并候选项，只校验公共字段，不解释正文。同一能力身份只留一个胜出者；不同类别下的相同名字是两个身份。只有一份注册表，不按类别再拆。
- 一次收集有一个修订号；收集中来源变了一次就重试一次，再变则这次结果不完整，不缓存，也不替换上一份完整目录。能力、设置、权限分路求值；一次请求不混合旧模型档案、新工具 schema 与旧实现；任一路不完整，整份不发布。
- 发布是整份替换或完全不发布。发布前核对胜出者身份与所选候选一致，不一致则这次目录失效。取消优先于迟到候选；较新的完整快照胜过较早的；不完整的快照不胜出。原子性不靠某种数据库事务或 Cordis 布局成立，那会把布局变成产品要求。

### 重装入口与换代

- 只有两个入口：新 Run 开始时比较当前采用依据与这次求值，变了才重装；Run 执行中租户经系统斜杠命令显式要求重新加载。文件变化或 Git 同步本身不触发重装。不走这两个入口时，新选择可以保存，但不是采用依据，正在运行的组合不变，并告诉调用方新选择要到下一个入口才生效。
- 候选通过校验之前不取得业务推进资格；新旧并存期间两者的服务可见范围分开。重装失败保持旧的合法采用并返回原因，不调用旧实例的 `close`。
- 有效切换撤销旧推进权并保存接续依据，原执行不因此销毁；新推进者取得原 Run、新的 attempt 与候选装配。新候选兑现必要条件之前不切换新准入，旧租约与必需依赖留在原提供者。有效切换也不调用旧实例的 `close`。
- 旧实例退出是另一步：先停相应的新准入，再交接或终结在途责任，再撤除依赖分支，最后关闭共享后端；各资源拥有者关闭自己那一代的协议实例，装配不因此拥有这些资源。
- 原调用归旧的执行拥有者，直到收场或可靠交接；迟到结果须已有仍有效的接收方或可靠记录；旧推进者不推进新工作。
- 运行时启动前取得已校验的装配依据；同一位置的扩展按装配声明的顺序执行。

### Cordis 集成辅助

- 根入口为空，不导入 Cordis；`./cordis` 放插件辅助与调用方 fiber 登记，`./testing` 放测试装配。产品源码不导入 `./testing`。本组不声明服务键。
- `definePlugin` 的输入与返回是同一组字段，必须带一个 Standard Schema 形式的配置 schema，`apply` 的配置参数就是该 schema 的输出；返回值不带 `provide` 或 `intercept`。函数插件走这个辅助。配置在插件体运行之前由 Cordis 校验，失败则 fiber 失败、插件体不运行。
- 必需依赖写进 `inject`；可选依赖不写进 `inject`，在调用时用 `resolveOptional` 读，缺席答 `undefined`，插件保持装载。类型参数是调用方的断言。
- `registerInCallerFiber` 在调用方的 Context（服务方法里的 `this.ctx`）上建一个 effect，在其中同步执行准入恰一次（Cordis 拒绝建 effect 时零次）。准入答三态之一：新建（交回新回执，保留 effect，撤除时恰调用一次撤回）、认回（交回原回执）、拒绝（交回原失败）；后两者只移除本次新建的 effect，不调用撤回。准入里提前请求撤除时，在拿到移除函数后、返回前执行；重复与重入的撤除只撤一次；提前撤除与调用方卸载同时发生时，只请求本次移除，已开始的卸载持有撤回。准入与撤回都必须同步。函数不做领域资格决定，不重试，不把异常翻译成拒绝或成功，不提供事务回滚；返回「新建」不保证登记仍存活。
- `startTestAssembly` 先把全部插件提交给新 Context，再检查每个插件体是否都已运行；后面的提供者满足前面的依赖时，前面的插件体必须在返回前运行。全部提交后仍有插件体没运行，视为启动失败。启动失败时先按启动的相反次序撤除已启动的 fiber：撤除全部成功抛原错误，否则抛同时带原错误与全部撤除错误的失败。`dispose` 按相反次序撤除全部，第一次拒绝不停下，最后汇总全部拒绝。测试装配不关闭调用方传入的资源，不规定业务关闭次序。

## 原则与约束

- 关闭有确定结局：`closed`、`failed`、`timed-out` 三种之一，或者进程死亡而没有报告；超时不是成功收场。
- 只关自己那一代。换代另建实例，旧实例看不见新租约。
- 采用是整份的。整份替换或完全不发布；失败保留旧的合法采用。
- 采用依据是本次执行唯一的定义来源；运行中不回头问提供方，不半路换组合。
- Cordis 给机制不给语义：fiber 状态不是业务就绪，effect 的完成顺序不是关闭顺序，`dispose()` 不是关闭。关闭报告由调用方的步骤列表产生，不靠同级 effect 或一次 `emit` 收集。
- 辅助只写一次各领域都要的胶水，不收回别的能力的 Service 定义，不做领域决定。
