# 定义求值与装配交接内部设计

本页说明一组租约的关闭协议为什么分成现在这个形状。结果以[行为规格](../SPEC.md)中已接受的关闭句子为准。本页不改那些结果。关闭协议只有一个模块，`src/close-protocol.ts`。

`close` 在调用步骤或 `clock.delay` 之前，已经把唯一 promise 保存下来。步骤和时钟可以同步再次调用 `close`。那次调用返回同一个 promise，不另起一次关闭。

## 一个实例只关一组租约

换代不在关闭对象里再记一个代际字段。资源拥有者再建一个实例。旧实例只看见自己的租约。这样读者要回答「这次关闭在等谁」时，只看这一个实例的持有集合。

## 时钟和步骤由调用方提供

协议不选择计时器，也不选择关闭哪个后端。调用方传入时钟和步骤列表。超时因此不绑死某一种计时实现。后端关闭的次序就是该列表的次序。

## release 对照当前 id

同一个名字可以在释放之后再次借用，并得到新的 id。`release` 只在传入的 id 仍是该名字当前持有的租约时移除它。旧 id 不能拆掉后来的租约。

## 为什么不用 Cordis effect 当关闭报告

这些读数来自 Cordis 4.0.4 的 basis 条目。它们说明内核已经做什么。它们不是本协议的报告结果。

`effect-disposal-concurrent-not-ordered` 说明同级 effect 的释放并发执行，失败只写日志。同一个 effect 内部才逆序执行，前一个拒绝后后面的不再执行。所以交接和关闭后端不能做成两个同级 effect。

`service-method-ctx-is-caller` 说明带 tracker 的服务方法里，`this.ctx` 是调用方。观察者在调用方上下文登记的资源会随观察者撤除。已接纳的租约不能登记在那里。

`plugin-body-reruns-on-provider-change` 说明必需提供者换代会卸载并重跑插件体。这不保留旧租约，也不产生超时报告。

`emit-listener-throw-propagates` 说明 `emit` 不接住监听者抛出的错误，后面的监听者不再被调用。关闭失败不能靠一次 `emit` 收集。

因此关闭报告由调用方提供的一个步骤列表产生。SPEC 写那个报告的结果。本页只写这个理由。
