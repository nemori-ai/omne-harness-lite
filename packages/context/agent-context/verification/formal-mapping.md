# 暂存表的键：性质、模型与实现的对应

[StagingKey.tla](models/staging-key/StagingKey.tla) 定义暂存表的状态与动作，[expect.txt](models/staging-key/expect.txt) 列出每个配置的预期结论。规则归[包组规格](../../SPEC.md#适配)的暂存表一条。模型成立不等于实现符合；实现由 `tests/requests.spec.ts` 的暂存表用例核对。

## 环境前提

下面两条不变式归外域拥有者。模型把它们写成动作的使能条件，不证明它们。

| 前提                                       | 拥有者                   | 在模型里                                                         |
| ------------------------------------------ | ------------------------ | ---------------------------------------------------------------- |
| 同一会话至多一个未终结 Run                 | Session                  | `StartRun` 只在会话没有活跃 Run 时成立                           |
| 同一执行挂接同一时刻至多一个在途准备       | Agent 的请求接缝         | `Prepare` 只在本 Run 是会话的活跃 Run、且本执行没有在途准备时成立 |

租户只作隔离，不作排他。拟定请求身份取步号，消费位置取执行与步号。每个调用有两个副本：副本 1 守上述前提，副本 2 是同一调用仍在途时的重复到达。

## 性质

| 性质                                  | 含义                                                       | 规格不变式 |
| ------------------------------------- | ---------------------------------------------------------- | ---------- |
| `OneEffectivePerSession`              | 环境自检：一个会话同一时刻至多一次有效准备在途             | —          |
| `ExclusionWithinAuthorizedDomain`     | 两次调用同键，则它们属于同一执行                           | CX-43      |
| `NoBusyForInvariantRespectingCaller`  | 守前提的调用方永不被暂存表拒绝                             | CX-43      |
| `DuplicateRefused`                    | 同一调用在途时的重复到达答暂时不可用，旧准备结束即解除     | CX-43      |
| `ReadsOwnInput`                       | 组读口取回的是本次暂存的值                                 | CX-43      |
| `NoCrossTenantKey`                    | 不同租户永不同键                                           | CX-44      |
| `KeyIsCallIdentity`                   | 键恰好区分不同的调用                                       | CX-43      |

## 配置的用途

| 配置                      | 键                             | 用途                                                          |
| ------------------------- | ------------------------------ | ------------------------------------------------------------- |
| `positive-sessions.cfg`   | 调用身份；一个租户、两个会话   | 正控                                                          |
| `positive-tenants.cfg`    | 调用身份；两个租户             | 正控                                                          |
| `bad-tenant-key-busy.cfg` | 租户加拟定请求身份             | 反面对照：两个会话各发一次准备，第二个被拒                     |

## 范围

模型只覆盖暂存表的键，以及「暂存、读、删除」三步。令牌、登记代次与 Request Context 的内部步骤不在模型里。每个配置只有一个步号与一种用途。
