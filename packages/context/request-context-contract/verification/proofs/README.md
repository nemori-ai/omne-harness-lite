## FR-1 不需要证明

FR-1（固定请求可重放）不成立，反例就是结论，见 [formal-mapping.md](../formal-mapping.md#结论固定请求不可重放恢复靠摘要比较与作废换身份r2-d306)。它成立的全部前提是 `replay-ideal` 的五个环境开关全关：第六层没有逐请求块，适配器的完整读取能跨崩溃保留，第四至第七组的修订不动，没有新输入。生产环境不满足这些前提。

## FR-2 恢复协议的推广

**命题。** 在 FR-2 的恢复协议下，对任意崩溃次数和 attempt 数：

1. 每个身份（attempt）至多对应一份被 Model 受理的内容，并且它等于这个身份的固定记录。
2. 崩溃次数有限为 C 时，用到的 attempt 数不超过 C+1，并且在公平调度下这一步最终受理一份请求。

**前提。**

1. 内容摘要无碰撞。`coverage.budget.inputDigest` 覆盖被计量的完整输入（守卫 G2、G3）。
2. 固定记录在受理之前耐久写入（M0 先于 admit）。
3. Model 同身份同输入幂等，同身份异输入答 conflict；inspect 的 not-accepted 是权威答复。
4. 被作废的 attempt 不再被受理，也不出现在已采用视图里。

**推导。** 第 1 条对受理次数归纳。一次受理发生在两种情况之一：首次受理，内容就是刚固定的内容；或恢复时重新受理，此时协议要求重新准备的摘要等于固定记录的摘要，由前提 1 内容相等。unknown 时协议不重发，所以不会在原请求已受理时送出另一份内容。作废之后换新身份，新身份的固定记录先写（前提 2），所以受理的内容仍等于自己的固定记录。

第 2 条：每次换 attempt 都由一次 not-accepted 引起，而 not-accepted 只在一次崩溃使原请求没有送达之后出现。所以换 attempt 的次数不超过崩溃次数，attempt 数不超过 C+1。崩溃停止之后，公平调度使 Prepare、Fix、Admit 依次发生，这一步受理。

**范围外。** 前提 3 与 4 由 Model 与 session 承担，本成员不能保证。有限机检见 `design` 与 `design-wide`。

## CF-3 压缩后视图有界

**命题。** 一次压缩把条目 1..k 覆盖进一条记录，保留名单为 Ret，摘要权重为 s。压缩后的视图权重 V 满足 V ≤ R + S + Σ_{i>k} w(i)，其中 R 是保留预算，S 是摘要权重的上界。右边不含被覆盖前缀，所以与会话已有长度无关。

**前提。** 保留名单的权重不超过 R（`acceptDraft` 拒绝超预算的草稿）。摘要权重不超过 S（摘要步的输出上限）。视图从最后一条压缩记录起算：保留条目、摘要、覆盖范围之后的条目。

**推导。** V = Σ_{i∈Ret} w(i) + s + Σ_{i>k} w(i) ≤ R + S + Σ_{i>k} w(i)。再次压缩时，上一条记录和它的保留条目都在新的覆盖范围内，新视图仍只由新的保留名单、新摘要和新范围之后的条目组成，所以界不叠加。

## CF-4 一次准备的工作有界

**命题。** 一次准备至多进入一次压缩计划，至多 B 个摘要步。Model 调用次数不超过 2+B：一次组装判断、B 个摘要步、一次 resume 后的判断。

**前提。** 已进入过压缩时，`assemblyOutcome` 把 `needs-compaction` 转成 `cannot-fit`（守卫 G5）。每个摘要步的进度恰加一，否决不重开同一步。

**推导。** 第一次判断不通过才进入计划，计划次数加一。resume 后再判断：通过就结束；不通过时已有转换，结局是 `cannot-fit`，不再计划。摘要步的计数单调加一，到 B 结束。所以总步数不超过 2+B。`bad-retry-veto` 给出否决重开同一步时的热环反例。
