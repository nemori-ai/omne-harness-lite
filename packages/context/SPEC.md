# Context

## 总体架构

Context 包组回答两个问题。Runtime Context：一个领域要「知道」一个不归它管的事实时，数据怎样从拥有者送到它手上，而两边互不认识。Request Context：一次模型请求的输入怎样从别人拥有的事实算出来，能不能装进窗口，装不下时怎样压缩。

| 成员                              | 回答的问题                                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `runtime-context-contract`        | Runtime Context 的协议：块声明、注册、读取资格、读取结果、步提交与恢复材料长什么样，边界上怎样判。纯数据与纯函数 |
| `runtime-context`                 | 供给机制：作用域、注册、生产者、资格、当前投影与观察链怎样一起运转。不依赖 Cordis                                |
| `runtime-context-cordis-contract` | Runtime Context 在这套系统里以什么服务、事件和装配声明出现                                                       |
| `runtime-context-cordis`          | 把机制装进服务：isolate 绑定、按作用域过滤的唤醒、卸载时的收场                                                   |
| `request-context-contract`        | 一次请求的派生协议：七组输入、四种结局、装入裁定、压缩计划、六层布局、账目与窗口占用。无状态的操作组             |
| `request-context`                 | 有状态的部分：来源登记表、账目投影、拟定请求缓存、默认的压缩与表示策略。不依赖 Cordis                            |
| `request-context-cordis-contract` | Request Context 在这套系统里以什么服务出现：提示词贡献的登记面、来源集合的登记、持有者部件的租借                 |
| `request-context-cordis`          | 把机制装进服务：贡献登记表、策略选择、两块的生产者、卸载时的收场                                                 |
| `agent-context`                   | 把 Agent 声明的请求准备、可读上下文与账目出站三个端口译成对 Request Context 与 Runtime Context 的调用            |

两块各四段：纯契约、Cordis 服务定义、机制实现、服务实现。依赖只朝契约：`request-context-contract` 只用 `runtime-context-contract` 的读取结果类型与块声明，两块的契约都不认识 Session、Agent 或执行环境。工作时，拥有事实的领域把块声明与供值登记到 Runtime Context；作用域持有者为一个作用域注册块、签发读取资格；读者按资格取完整快照与之后的变化。协调者要发一次模型请求时，经 `agent-context` 调 Request Context 的操作组；操作组从按目标登记的来源集合稳定地读出七组材料，算出拟定请求、装入裁定与需要时的压缩计划。一次请求的账目由结果接收方交回 Request Context 的账目投影，再作为窗口占用块经 Runtime Context 供给下一次请求。

## 领域边界

Runtime Context 拥有：块声明目录（全系统一个块键一份声明），以及注册、读取资格、当前投影、观察链在本实例上的投影。这些都是投影，不是事实：注册修订的权威是作用域持有者的耐久提交，块的值归生产者。Runtime Context 不拥有任何块的内容，不签发身份，不判断动作能不能做，不组装请求，不保存历史，不持有耐久状态。

Request Context 拥有：从材料到请求的派生规则、装入裁定与压缩计划、六层布局、固定请求记录的格式，以及账目投影这份可重建的派生状态。它不拥有历史与压缩记录的提交（历史持有者），不发请求、不固定采用、不保存计划进度（协调者），不拥有计量与转换件（Model），不拥有压缩记录的形状与模型视图规则（`packages/common`）。

`agent-context` 只做翻译。它不选模型，不决定是否压缩，不改装入裁定，不提交压缩转换，不发模型调用。

两块都只认通用角色：作用域持有者、生产者、消费者类、集成方、协调者、历史持有者、结果接收方。不认识调用它们的是谁。

## 心智模型

Runtime Context 是一块公告板，不是一个仓库。拥有事实的一方把值贴上去，要用的一方按自己的资格看。公告板不判断值对不对，也不替谁做决定：数据走它，「许不许」「提交」「取消」这些决定走各自直连的窄端口。板上的一切都可以丢：进程重建之后，持有者从自己的日志把注册与检查点值交回，生产者重新贴值，读者重新绑定。所以板上不能有别处没有的事实。最容易想错的三处：读不到不是空，缺项、未知和拒绝各是一个要如实处理的结果；一份资格只决定能读哪些块，不决定能做什么；唤醒只是「去看看」，不是变化本身，丢了也不影响正确性。

Request Context 是一个纯算的工位，加一份可以重建的账本。它每次从别人那里稳定地读出七组材料，算出一份拟定请求和一个结论：装得下、要压缩、装不下或限额未知。同样的材料得到同样的内容，但计量每次重做，结论以本次为准。它不发请求，不记住哪次请求被固定了；固定的事实写在协调者的调用记录上，下一次经「已采用」传回。最容易想错的两处：压缩只追加一条压缩记录，原历史一字不改；一次准备至多进入一次压缩计划，计划用完仍装不下就是装不下，不再换个条件重来。

请求的开头越稳定越好。六层自上而下从最稳定排到最易变，变化只追加在尾部。能在输入变化时算好的派生物不留到请求到来时再算，请求到来时只做比对与拼装。

## 应然设计

### 访问核对

- 每个带目标的入口按固定次序核对：先权威端口（调用方访问身份的租户等于动作里的租户），再可信绑定来源（作用域绑定在同一租户），最后作用域的状态、注册、生产者代际与恢复围栏。前一项不成立，后面的不执行。
- 未绑定、绑定租户不同、权威端口拒绝，对外一律是无权，不先披露真实租户、登记数量或另一租户的存在。作用域未注册、已结束、恢复未完成只在授权通过之后披露。
- 端口答不可用或未知时，结果是不可用或未知并带原因，不安装投影，已关闭的恢复围栏保持关闭。权威端口只在两个恢复动作上、目标授权确认之后可以答无效；对普通动作答无效是协议违约，读作未知。
- 已授权判定里的 `current()` 是同步前提。每次 `await` 之后、调用来源之前、最终提交或披露之前同步调用它；检查与受保护的动作之间没有 `await`。答假即无权，不用旧答复继续。判定只在本次动作内有效，不保存成许可。
- 每个公开入口在第一次外部调用之前捕获本操作的输入快照，之后只用这份快照。授权一份输入之后不从可变输入里再读出另一份。
- 一个作用域第一次被确认时记下它的租户，记下的租户不改。可信绑定已匹配而记下的租户与之冲突，是内部一致性异常（`tenant-mismatch`）。
- 父作用域的每一跳独立核租户与授权，跨租户的父级值不被继承。子作用域的同键值遮蔽父级。

### 块、注册与资格

- 块声明归这个值的语义拥有者，不归存放它的一方。两类块：供给块由一个租户的一个生产者供当前值；状态块由声明的写者类提出更新、作用域持有者在步边界提交。同一块键带来摘要不同的声明，登记或注册被拒绝。
- 注册是持有者为一个作用域固定的清单：有哪些块、每块对到哪些需要、带什么参数。必需项在作用域创建时固定，之后不能移除，也不能改成可选。注册决定与块内容是两笔提交，不并成跨拥有者的一次提交。
- 读取资格只来自持有者签发，不从调用方在装配树里的位置推断。资格有两个集合：块键集合授权按块的原形状读；需要绑定集合授权读翻译后的值，被翻译的块不因此可按原形状读。重签取代旧资格，读者沿新资格继续、游标作废；撤销后下一次读取即无权。本实例重建之后不恢复任何资格，持有者重新签发。
- 需要用消费者自己的形状声明，不点名块键；集成方注册时用需要绑定把它对到一块，形状不同时附带纯函数翻译。块声明与需要都不认识对方。

### 提交链与恢复会话

- 本实例的注册表是按持有者提交顺序应用的投影。每笔普通提交带 `after`，即同一作用域上一条上下文记录的提交身份。只在 `after` 等于链头时应用；不等答「顺序不符」，持有者用恢复会话补齐后再送。注册修订的比较保留为一致性核对，不决定顺序。
- 同一提交身份、相同完整输入的重试返回原结果；输入不同（含改变结束标记）是提交冲突。失败的提交不进成功去重表。成功去重表每个作用域只留链头那一笔，应用下一笔或恢复安装时释放其余。
- 作用域结束依赖持有者已确认的提交。已结束永不回到开放；结束之后未见过的推进答 `scope-ended`。带结束标记的提交整笔核对后原子应用。
- 首次观察到一个作用域、以及进程重建之后，恢复围栏关闭：不签发资格、不建立读者、不披露投影。持有者开始恢复会话时，旧资格、读者、游标与在途供值一起失效；完成时交回完整恢复材料（注册链、`checkpointed` 状态块的最近值、结束），本实例核对后原子安装，不调用生产者，不执行 reducer。恢复材料与暂存的容量上限必须显式配置，不能无界；容量不足答不可用，不截断事实。空作用域也先经一次空材料的恢复。
- 恢复安装开放投影时，为供给块记待刷新标记。恢复后第一次合法的普通读取遇到标记时，在全部读取核对之后发起一次有界的供值；失败保留标记，之后的读取可以再试。标记不是取值许可，不启动后台工作。

### 读取结果、变化与状态块

- 一次读取的结果只落在四类之一：成功、拒绝、缺项、未知。成功的完整快照与变化都带 `missing` 清单；`read(needs)` 全有或全缺。可选块的合法无值与生产者缺席读作「无值」；来源不可用、未知、拒绝与内容无法解释不因块可选而消失。
- 来源明确答不可用是缺项；来源答未知、抛出、超时或回执不合法是未知；任一来源对本次供值答拒绝，整次读取拒绝。
- 游标在授权范围变化、生产者换代、进程重建、持有者重签资格、落后于观察链保留下界、恢复会话开始时作废，读者重取完整快照，不得到残缺的增量。
- 变化材料由持有者拉取：用游标取变化，再用纯函数算出哪一块从哪个修订变到哪个修订，以及按资格过滤的前值。前值来自持有者保留的上一份快照，本实例不保存旧值。唤醒丢失时，下一次拉取补齐。
- 一次执行开始或挂接建立时，调用方主动取当前完整快照，不以「没收到变化通知」省略。
- `per-request` 块不存值，不进快照，不进观察链，不产生变化提醒；每次读取向生产者现取，按读者资格过滤。
- 状态块的更新是提案。指向供给块或提出者不在写者类之内的更新在提交前剔除并带原因退回；`singleWriterPerStep` 时同一步第二个写者被拒。含被拒更新的步提交整笔无效。失败的步里已成功动作的更新保留为待处理，不丢，也不并进失败的一步。`untracked` 状态块在持有者带「执行结束」标记提交时失效，恢复时不读回。

### 生产者与供值

- 生产者槽是租户加块键。同一槽另一身份的登记被拒；同一身份再登记取单调递增的新代际并替换旧一代；旧一代的撤除不改动新一代。
- 发布带作用域、租户与值。任一核对不成立即不写值、不推进修订、不唤醒。值不合声明形状被拒，当前值不变。一个作用域的发布不改别的作用域。
- 作用域无关的块由本实例在四个时点调用生产者的供值回调：持有者注册该块时、生产者晚于注册登记时、生产者使当前值失效时、恢复后第一次合法读取遇到待刷新标记时。回调前后各核一次权限，最终同步段核代际、注册、结束、恢复代次与供给序号；任一不成立，结果被丢弃。
- 使当前值失效把值变为缺项并前进视图修订。按租户的失效只选本租户的目标，任一目标核不过整批不变，目标集合变了不提交过时的半批。
- 发布与失效没有操作身份，响应丢失后不承诺恰好一次；生产者查自己的权威值后重发。
- 撤销登记立即拒绝本代新操作，在上界内结算本代在途读取，之后依赖它的读取读到缺项，不读到旧值。
- 读取缓存只是性能手段：键含租户、作用域、当前资格、注册修订与投影版本；任何可能改变过滤后读取输出的写入都推进投影版本，或使读取绕过缓存。命中仍完成全部资格核对与 `current()`。

### 请求的计算边界与结局

- Request Context 的操作分两类。派生计算是纯函数：同一组稳定材料得同一内容，同一计划、进度与步结果得同一推导。效果操作读来源、取还 Model 租约、维护账目投影，按各自协议执行。
- 结局封闭：可扩展的拟定请求、可固定的拟定请求、需要压缩、装不下。失败封闭：无权、无效、不可用，另有未知。没有开放的「其他」分支。装不下是结局，不是失败；限额未知不是失败，拟定请求照常成立并在覆盖证据里标明。
- 本组成功只表示计算完成，不表示请求已发出、结果已承接或动作已获准。固定采用写在协调者的调用记录上，不另建上下文事实；本组不保存它，只经「已采用」读回。
- 访问身份必须显式带上，缺了是无效；访问身份的租户与目标不符是无权，且先于任何来源事实被判定。系统恢复只经恢复口，用另一种系统作用域的访问身份，普通端口不接受它，恢复授权也不能塞进普通访问身份。
- 覆盖证据逐项记下这次用了哪些输入、各自的修订、锚点与前缀变化原因，回答：模型看到了什么，和上次比什么变了，开头为什么变了。
- 发出未知或提交未知回协调者与模型调用身份对账；本组不自动重发，不新建相同调用，不因恢复重记原费用。取消只结束本次计算的等待，不证明已发出的调用已停止。

### 七组稳定读取与来源登记

- 组一是调用身份与用途，由调用方给出；其余六组（历史与新输入、runtime context 读取结果、系统提示词、模型侧、工具侧、当前条件与本次经过）各有一个组读口。调用身份是用途、消费位置、拟定请求身份与主体；需要区分在途调用的一方只能从它取键。
- 一组的读取是：读前计数、读组值、读后计数。前后不等丢弃整组再读一次，第二次仍变返回不可用（`unstable-input`），不交半组。令牌由来源拥有者给出并绑定来源实例的代际，来源重启、换登记、计数回绕都必须换代，不复用旧令牌。令牌不是内容散列，计量结论不进令牌。
- 七组之间没有整体快照时刻；本组另核跨组关系（收件模型与读取资格一致、各组目标一致、输入批落在历史依据之内），不成立是无效。收件模型变化后，旧的 runtime context 材料不被静默消费。
- 新输入与相关历史先可靠保存，再组装；只在内存队列里到达不算。
- 同一次组装的全部历史页用同一历史依据；读到「epoch 已变」用新依据重取重算，不拼接两个 epoch 的页。历史序号是十进制文本，按任意精度整数比较。
- 来源集合按目标（租户与作用域）登记，一个键同时只有一个有效集合；同键第二次登记是冲突，替换以旧引用做条件更新。登记授权由构造时注入的授权判定者核验，集合里的资格桥不能自授登记权。
- 每次操作借用一个集合代际。发布前在一次同步本地动作里核代际仍有效；先撤除，旧操作不能成功；先发布，撤除不撤回已交出的值。撤除不关闭外部来源，`settled` 等全部在途操作与租约交还之后才兑现，来源持有者在它之后才关读口。

### 计量与装入

- 预算计入请求的全部内容：系统提示词、适用历史、提醒、工具声明与最终选择的实际模态内容。不能只计最新文本或忽略工具 schema。
- 每份拟定请求按顺序：以本次访问身份取得 Model 准备租约；对每个供应商计划表示并完整计量；按各自的限制检查；交还租约，再交出结果。取得之后任何路径都交还租约；主操作成功而交还失败，结果是不可用，不交出可固定的成功；主失败不被交还失败覆盖。
- 计量结论不缓存也不复用。保留集合的探测、摘要请求、摘要之后的检查、最终请求是四份独立计量的输入；不用单条计量相加代替整体。一次压缩规划内可以按完整档案与来源声明精确匹配复用准备租约，但每份探测仍逐次计划与计量，不缓存权限或预算。复用的租约数与在途探测数有上界，超出时立即不可用，不排队。
- 「装得下」只有一个口径：整请求的每项计量都不超过硬限额，且输入 token 不超过触发界线。组装与摘要之后的检查用同一判定。

### 压缩

- 压缩只追加一条压缩记录：摘要、覆盖范围与保留名单一起提交，不改原块、原标注或原历史，不分两半提交。
- 覆盖范围从历史起点开始，到压缩点之前某处结束，包含上一条压缩记录。工具调用与它的结果不分在范围两侧，除非调用进了保留名单；两者都在范围内时一起保留或一起摘要。
- 未读的新输入、未答的等待与未结的后台占位不压：它们进保留名单或留在范围之后。什么算未结由历史持有者与原执行拥有者判断，作为下界交来；下界本身超出保留预算即装不下，不缩短范围，不突破预算。
- 计划归本组，调用归协调者。步只有摘要步一种；修剪在第一个摘要步之前做一次，只缩短交给摘要的材料，不算一步进度，不改模型视图与装入裁定。步结果带序号，必须等于已完成步数；进度每步恰加一，同一结果重试得同一推导。计划记录策略身份与参数摘要，换了即无效。
- 计划冻结一份压缩依据：目标、历史依据、判断窗口、投影消息、模型选择、请求框架与保留预算。之后的步骤只消费它，不补读当前历史；当前模型选择或表示策略与依据不同即无效。
- 判断窗口是增量的：上一条压缩记录、它的保留项、它之后的条目。判定的规模不随已被摘要的前缀增长。
- 摘要之后整请求装得下才给出压缩转换。转换是待提交的结果，由历史持有者与协调者在一次权威提交中完成；只有带已提交证据的转换进入续接。压缩提交之后，持有者先为模型类读者重签资格，调用方再以完整快照续接；续接拿到转换依据而读取结果不是完整快照即无效。
- 压缩策略、表示策略与修剪器可以替换。触发界线、保留预算、保留偏好、步数上界、修剪阈值都是配置项，默认值只是初值；策略给出不合法的草案是策略违约（不可用），不是调用方输入无效。

### 六层布局与前缀

- 请求自上而下分六层：① 系统提示词；② 工具声明；③ 历史头；④ 上下文快照提醒；⑤ 历史体；⑥ 尾部易变提醒。改层次是契约变更。
- 系统提示词只放慢变内容，每次求值、单独计量、不进历史。提示词贡献只有有序段与变量两类；带逐请求变化变量的段在登记时被拒。日期、当前目录、模型名、窗口占用这类会变的运行事实只走 runtime context 块。
- 工具声明按会话常驻工具的完整合法集合投影，不按步裁剪可用性；每个工具一条声明，多命令工具不按命令展开。非常驻工具只经 Tools 元工具可访问。
- 快照提醒锚定在本次完整读取发生时的模型可见历史尾部；下一次完整读取之前，每次请求都放在同一锚点。增量读取时调用方交入最近一次完整读取的块材料，本组不保存它。
- 块变化、工具转后台、后台结果到达、外部捎话一律以提醒追加进历史，不改快照，不改早先消息。逐请求变化的块只进第六层。
- 系统提示词或工具集合需要变化时立即变化，不为保住缓存的开头而推迟；覆盖证据记前缀变化原因。
- 模型侧只取明确标为模型可读且当前有资格的块；缺失或不明确的标注不进请求；保留名单不绕过块标注。工具内部消息始终排除。人侧投影与模型侧投影共用同一套块标注规则，模型预算不删人侧原件。
- 推理续接状态与其他块一样按模型可读标记进入投影，本组不按目标模型挑选或删改；去块后修正回放位置索引，使交给 Model 的消息仍然合法。整体关闭回放是调用方的参数，原样带进请求并记入覆盖证据。
- 前缀判断用历史行的链式前缀摘要在每层锚点比较一次，是常数时间，不逐条比对。

### 账目与窗口占用

- 账目的耐久事实只在协调者一侧的日志里。账目投影是可重建的派生状态：结果接收方在原账目提交之后经自己的出站端口交来，恢复时从日志授权重放，幂等。
- 收账的核对有固定次序：形状、租户、来源核验、账目合法性、目标状态与代际、幂等比对、容量、写入。来源核验必须证明这是一条已提交的日志事实，只核形状不算。幂等键是租户、调用、发出与账目修订；来源与交接关联不进键，不同交付路径转交同一原账目仍是认回。同键同值认回，同键异值冲突，较低修订乱序到达不倒退。`received` 不是清理原日志的依据。
- 每个目标在未初始化、重建中、就绪之间变化。新目标先完成授权重建，再接纳普通投递；首个普通投递不能把它悄悄变成就绪。重建在暂存索引上进行，失败不发布半份投影。容量上限构造时必填，没有缺省值；目标数满时只淘汰就绪、空闲、最久未用的整个目标，淘汰不确认任何事实。
- 窗口占用的值是四种之一：没有固定请求、固定请求暂无用量、实际、估算。它只按当前已采用的固定请求取值，不取旧调用的迟到账目；多次发出不相加；非数值分支不进比例、阈值或预算，不转成零。投影未就绪、来源故障或权限失败返回原失败，不转成这四种值。
- 两块（压缩设置、窗口占用）的生产者是 Request Context 的服务实现。Runtime Context 对它是可选依赖：不在场时两块读到缺项，到场后登记。

### 适配

- 每个操作先比对本组铸造的证据里的租户与访问身份的租户，不符答无权，不调用任何下游。
- 失败只用端口已有的类别，不新增，不把一类改成另一类。缺必要输入、缺依赖、缺材料答不可用并带诊断，不造默认值，不用旧值冒充当前值。
- 本组铸造的证据带自描述的记录键，任何实例都能读出它属于哪个租户、执行与挂接；指向的材料只在铸造它的实例里，丢失后答不可用并改做完整读取。只有本组解引用这些证据，Agent 与 Session 只原样保存与传回。
- 可读上下文读取在同一挂接、同一收件模型、已采用覆盖与当前固定事实一致、没有压缩转换时才做增量读取，否则做完整读取。
- 暂存表的键就是调用身份。同一调用重复到达时答暂时不可用，旧准备结束即解除；守住「一个会话至多一个未终结 Run」「一个挂接至多一个在途准备」的调用方不会被它拒绝。
- 账目出站不缓存回执、不吞账目、不重试；重试归接收方。收件口抛出答未知。账目目标由解析端口按调用给出，不从调用或执行的文本猜作用域。

### Cordis 装配

- 每个服务键只由对应抽象类的静态 `provide` 给出，提供者不另写键。服务方法的签名从契约根入口的操作类型推出，同一组签名不写两份。纯契约与机制实现不导入 Cordis；`-cordis` 成员的根入口不导出任何东西。
- 生产者登记、贡献登记、来源集合登记与部件租借都是登记即效应：效应落在调用方 fiber 上，调用方卸载即撤，撤除只撤自己那一代。
- 块是数据不是服务，没有一方 `inject` 一个块；必需块缺席是读取时的缺项，不让消费者停在 PENDING。作用域与租户是操作参数，不是 Context 或 isolate。一个 isolate 标签下一个提供者。
- intercept 配置里声明的消费者类与作用域是装配事实，不授予资格。`bind` 在全部访问核对之后把声明的消费者类与资格比对，这是一致性检查，不是访问控制。
- 事件只是唤醒或失效提示：载荷只带作用域引用与修订，不带块键与值，丢失不影响正确性。按作用域过滤不是安全隔离，事件只供受信装配。
- 两个权威端口与信任对象由装配入口在受信子树提供，不进插件树与插件配置；取不到时对应操作不可用，不放行。
- 配置经 schema 校验，未知字段、非法上限或指向不存在的策略使插件加载失败，不静默回退初值。账目收件口与 Request Context 服务由同一个插件 fiber 提供，窗口占用与收账读同一份状态。
- 卸载在一个函数里依次：拒绝新请求、结束读者、取消在途等待、在上界内等全部在途操作结算、释放表。关闭之后在途操作的最终同步段答关闭，不答成功。卸载不撤回已交出的变化材料、拟定请求、计划或转换，也不撤回外部效果。持有者部件只在全部租借结束、全部结算完成之后才关闭读口。

## 原则与约束

- 读不到就是读不到。缺项、未知、拒绝分别如实交出，不变成空值、默认值或旧值。
- 值归生产者，事实归日志。本组的一切状态都是投影或派生，进程重建后从持有者的日志与生产者的重新登记回来。
- 「知道」走 Runtime Context，「决定」走直连的窄端口。不经 Runtime Context 传控制信号。
- 访问身份每次调用显式带上；跨租户默认拒绝；拒绝不披露另一租户的任何事实。
- 本组不发请求、不固定采用、不提交历史；派生完成不等于发出成功，结果不知道就按原身份对账。
- 策略与数值不写死：压缩、表示、修剪、缓存与各类上限都是可替换实现或配置项，默认值只是初值。
- 请求到了不算，算在请求之前：派生物在输入变化时维护，请求到来时只比对与拼装；缓存失效看输入携带的修订或计数，不看时间、文件时间或内容重哈希；有缓存与无缓存同输入结果相同。
- 自定义的提交、恢复、缓存与并发协议要有形式模型与关键性质检查；模型与证明在各成员的 `verification/` 目录，有限检查的通过不等于实现符合。
