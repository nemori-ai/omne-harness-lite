# @omne-harness/runtime-context-contract 行为规格

状态：契约成员，`draft`。注册与更新、当前读取、作用域与租户资格、并发认回及未知结果处置这几部分由[技术接受](https://github.com/nemori-ai/omne-harness-lite/issues/262#issuecomment-6186972289)采用，本页在 RC-01 至 RC-04 和 RC-07 保留它们的原意。两类块、块声明归语义拥有者、需要与绑定、读取资格与绑定读者、状态块的步提交，依据产品正文 [运行感知与一次模型请求](../../../.meta_harness/design/product/runtime-context/design.md) 第 4 版 §2 至 §5 写入，修订处注明依据。本页只拥有公开类型以外的必要行为。公开形状归 `src/`，导出导航归 [docs/public-api.md](docs/public-api.md)，对象的身份与生灭归 [docs/object-model.md](docs/object-model.md)。

本成员没有运行实现。字节编码、存储、提供者选择和数值都不在这里定。设计接受不表示生产实现或运行验证已完成。

## 范围与依据

本成员拥有 Runtime Context 的协议：块声明、上下文需要、需要绑定、注册、读取资格、绑定读者、快照与变化、上下文更新、步提交、变化材料的类型，以及对它们的纯核对函数。它不拥有任何一块的内容，不判断动作能不能做，不选择执行落点，不组装模型请求，不保存历史。

本页只用通用角色：作用域持有者、生产者、消费者类（`model`、`tool`、`extension`、`coordinator`）、集成方、协调者、调用方、维护者。本成员不认识上层工作流的具体类型。外部业务事实由外部按本成员返回的身份关联。

## 结果与不变量

### RC-01 消费者、身份与范围

本能力向模型、工具、扩展和协调者四类消费者提供分块当前值及其变化。消费者类不是许可。每次读取都识别调用方、消费者类、作用域、主体与租户，并核对消费资格。托管租户数据和跨作用域操作显式携带租户身份。跨租户访问默认拒绝。

作用域由不透明的 `ScopeRef` 表示，可以带父引用。本成员不解释它指的是租户、会话还是一次执行。本阶段只有一种作用域持有者，所以只有单层作用域。父级查找与遮蔽规则（见 [RC-03](#rc-03-当前读取资格与缺项)）对以后的多层持有者同样成立。

块的内容归它的生产者或语义拥有者。本成员不因持有注册、快照或句柄而取得修改任何块内容的资格。多个合法消费者可以读同一块，各自独立满足资格。

公开能力可以独立使用。调用方提供作用域、生产者、资格材料和资源。本成员不强制创建任何上层对象，也不要求装配 Cordis。只处理调用方给出的数据时，缺上层对象不算拒绝。访问系统托管数据时仍适用原访问契约。根入口提供作用域引用与块键的解码函数，独立调用者从字符串得到品牌类型，不用类型断言。独立入口的字节编码未定。

### RC-02 块声明、注册与参数

每种块有一份块声明。块声明由这个值的语义拥有者发布，也就是决定这份值是什么意思的一方。它不归存放这份值的一方，也不一定归生产者。全系统一个块键只有一份声明。本成员不声明任何具体块键。语义拥有者在自己的包里导出声明，并用 `declare module` 增补 `ContextBlocks`。依据：产品 [§2.2](../../../.meta_harness/design/product/runtime-context/design.md#22-块声明归语义拥有者)。

块声明分两类。

| 类 | 谁改值 | 恢复 | 声明的附加字段 |
| --- | --- | --- | --- |
| 供给块 `supplied` | 一个生产者供当前值，读者只读 | `persisted`、`reread`、`recompute` 三选一 | 无 |
| 状态块 `stateful` | 声明的写者类提出更新，作用域持有者在步边界提交 | `checkpointed` 按最近一次步提交恢复；`untracked` 只在一次执行内有效，不恢复 | `writers`、`reduce`、`persistence`、`singleWriterPerStep` |

两类共用的字段：块键、值的形状、允许的消费者类、是否必需、披露方式（`plain` 或 `eligibility-checked`）、能否带前值、变化频率（`stable`、`per-step`、`per-request`）、可选的作用域级参数形状。`per-request` 块只进请求最末的尾部易变提醒，不进快照，不产生变化提醒。依据：产品 [§2.1](../../../.meta_harness/design/product/runtime-context/design.md#21-两类块供给块与状态块)、[§5.1](../../../.meta_harness/design/product/runtime-context/design.md#51-首次注入锚定快照与追加提醒)。

块声明不安装块，也不授权读它。谁供值由生产者登记决定（见 [RC-07](#rc-07-生产者句柄并发撤除与恢复)）。

注册是作用域持有者为一个作用域固定下来的清单：有哪些块、每块对到哪些需要、带什么参数。注册说的是「这里有这一块」，不是这一块当前的值。注册的身份是作用域加块键。必需项在作用域创建时固定，之后不能移除。可选项可以增删。移除一个可选项只停止本作用域后续使用该注册，共享来源和其他作用域不受影响。必需项不能用可选移除绕过。固定身份不能用内容更新改写。注册带注册修订，读取资格引用它。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

作用域级参数的形状由块的声明者定，值由持有者在注册时给出。本成员只校验值是否合乎形状。持有者不能给声明里没有的参数。这一条取代已接受条款里「注册保存来源与配置」的写法。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

注册决定是持有者的一笔提交。块内容是生产者的另一笔提交。两笔不并成一次跨拥有者的提交。进入持有者历史的依据是注册集合变更，以及不能重算的作用域自有输入。当前快照、预算过程和空闲推送不进历史。跨存储的同一次提交见 [STORAGE-T01](../../../docs/architecture/data-and-state.md#storage-t01)。

注册变更的最小对接如下。增加、更新和移除都走这张表。更新保持块的固定身份，只改绑定或参数。更新不是先移除再新增。

| 项 | 规则 |
| --- | --- |
| 关联身份 | 这次变更的提交身份，加作用域和块键 |
| 必要参数 | 作用域、块键、需要绑定、参数值、是否必需，以及增加、更新或移除。租户只在访问托管数据时必需 |
| 成功 | 注册决定已提交，注册修订前进。块内容由生产者另行提交 |
| 拒绝 | 无资格、移除必需项、更新改了固定身份、参数不合声明形状、绑定不合核对（见 [RC-06](#rc-06-需要绑定与读者形状)），或同一提交身份配上不同变更 |
| 未知 | 按原提交身份查询。不重建另一条注册 |
| 同身份重试 | 相同提交身份和相同变更返回原结果 |
| 参数冲突 | 相同提交身份配不同变更则拒绝。另一提交身份要改同一块时，先核它依据的注册修订是否仍是当前修订。已经变了就拒绝，调用方按当前注册重新提交。不用后写覆盖先写 |

注册或更新未提交，不报告为已生效。提交未知时保留原操作身份，按原拥有者查询和对账，不直接重建另一注册，也不用旧快照覆盖合法变化。

纯函数 `judgeRegistration` 核对一条注册材料：块声明存在、参数合乎形状、必需项未被移除、每条绑定通过 `judgeBinding`。核对失败是定义层的拒绝，带逐项原因。

### RC-03 当前读取、资格与缺项

读取资格由作用域持有者签发给一次绑定。它写明作用域、消费者类、主体与租户、允许读的块键集合，以及签发时的注册修订。读取资格只来自持有者签发，不能凭调用方所在的位置或装配树推断（[IC-18](../../../docs/architecture/cordis-integration-conventions.md#ic-18)）。持有者可以撤销它。读取资格只决定能读哪些块，不决定能做什么动作。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

绑定读者按一份读取资格建立。它的消费者类在建立时固定，使用者不能改成别的类。绑定读者每次读取都重新核对资格。撤权在下一次读取生效。旧读者不能继续读到新内容。

读取只纳入当前有效注册、生产者允许提供且消费者当前有权读取的块。历史提醒、旧快照和旧允许缓存不作为当前资格依据。资格或来源无法取得时保持未知，阻止依赖该允许结论的新读取或动作。不能返回空集合冒充完整成功。

无权、无有效注册、来源不可用、内容无法解释和结果未知分别处理，同时遵循对象存在性披露规则。错误不返回未授权正文、凭据或来源内部细节。必需块的生产者不在场时，注册照常成立，读取返回明确的缺项。缺项由依赖它的动作按各自契约处置。本成员不伪造占位值，不隐式移除必需项，也不让消费者因缺项而失效。依据：产品 [§2.3](../../../.meta_harness/design/product/runtime-context/design.md#23-需要绑定与集成原则)。

子作用域读一个块键时先查自己，再查父级。同一个块键在子作用域里的值遮蔽父级的值。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

一次读取能够解释采用来源、覆盖范围和修订。多个块需要同一合法读取范围时，由消费与最终发起的协调者保护一致性。本成员不宣称任意独立来源自动全局同提交。

读取的最小对接如下。读取不建立可认回的写操作。

| 项 | 规则 |
| --- | --- |
| 关联身份 | 绑定读者、作用域和这次读取的范围。托管读取再带租户 |
| 必要参数 | 读取资格，以及要读的需要集合或当前快照范围 |
| 成功 | 返回当时有权读取的当前值，按需要绑定翻译成消费者的形状，带来源证据和修订 |
| 拒绝 | 无权，或不存在且披露规则允许说明。不返回未授权正文 |
| 缺项 | 必需块无当前值。返回缺项与缺的是哪一块，不返回空值或旧值 |
| 未知 | 资格或来源未知时返回未知，不返回空集合 |
| 同身份重试 | 再读一次，取得读取当时的当前值 |
| 参数冲突 | 读取不修改注册 |

读到当前值不改变已经固定的请求。新的合法值作用于之后的读取。撤权停止新内容供给，不取消独立执行，也不撤回已发生的效果。

### RC-04 读取时点、观察与变化材料

绑定读者给出两种结果：当前的完整快照，或自上次读取以来的变化。快照带视图修订和游标。游标属于一个绑定读者。授权范围变化、生产者换代或进程重建之后，游标作废，读者必须重新取完整快照。作用域持有者也可以主动使一个读者的游标作废，做法是为该读者重签读取资格；压缩提交之后它对模型类读者这样做，本成员自己不认识压缩。实现可以因观察链的保留上限使早于下界的旧游标作废；结果同样是完整快照，不是残缺的增量。是否需要完整快照由本成员按游标状态判断，不由发起请求的一方猜测。依据：产品 [§5.1](../../../.meta_harness/design/product/runtime-context/design.md#51-首次注入锚定快照与追加提醒)。

一次执行开始，或为执行建立挂接（接续或换代之后）时，调用方主动取得当前合法完整快照。只有推送不能覆盖空闲期间的变化。调用方不能以「没有收到变化通知」省略这次读取。

块的值变化后，本成员算出变化材料：哪一块、从哪个修订变到哪个修订，以及按读者资格过滤过的前值。变化材料交给作用域持有者，由持有者写成变化提醒追加进历史。变化材料不是提醒消息本身。曾经可读、现在无权读的前值不披露。块是否允许带前值由块声明说明。纯函数 `diffForReminder` 从两份快照算出变化材料。

模型可读块的变化经持有者形成追加提醒。仅工具或扩展可读的块只向获准消费者供给，不通知模型。注册的增加或移除同样让后续适用消费者感知变化，不改写已经发出的输入。

完整快照只进请求，不进历史。变化提醒进历史。`per-request` 块不进快照，也不产生变化提醒。依据：产品 [§5.1](../../../.meta_harness/design/product/runtime-context/design.md#51-首次注入锚定快照与追加提醒)。

空闲状态推送可以丢弃。下一次执行开始或挂接建立时的读取承接变化，不补世界上所有中间值。普通输入、控制、结果和已承担交付责任的数据不得归到这条可丢路径。唤醒只提示检查权威状态，不单独授予推进资格。重复唤醒不得重复逻辑承接。丢失唤醒后仍有权威事实可补查。本成员不能用唤醒到达或订阅成功代替提醒已持久成立。

模型首次读取与合法压缩后，提供当前有权读的完整快照。私有块不因全量路径进入模型。历史提醒被摘要后，不能用摘要替代这次完整读取。

### RC-05 状态块、上下文更新与步提交

参与者对状态块提出的是上下文更新。上下文更新是提案，不是事实。一条更新只能指向状态块，提出它的一方必须在该块声明的写者类之内。不满足这两条的更新不会成为事实。更新带着提出它的原动作身份。依据：产品 [§2.5](../../../.meta_harness/design/product/runtime-context/design.md#25-状态块的更新与步提交)。

作用域持有者在步边界收齐这一步的全部更新，按各块的合并规则合成一份步提交。步提交写成之后，这些更新才成为块的值。一步只有一份步提交。块声明 `singleWriterPerStep` 为真时，同一步里第二个写者的更新被拒绝。提交本身不在本成员，归持有者。纯函数 `reduceStep` 把一组更新按声明的 `reduce` 合并成提交材料，不触碰任何存储。

失败的步里，已经成功的动作提出的更新保留为待处理，不进这一步的提交，由持有者决定怎样处置。本成员不丢弃它们，也不把它们并进失败的一步。

提交之后，模型可读的状态块按 [RC-04](#rc-04-读取时点观察与变化材料) 产生变化材料。`persistence: 'untracked'` 的状态块随该次执行结束而失效，恢复时不读回。

### RC-06 需要、绑定与读者形状

消费者在自己的定义里用自己的形状声明上下文需要：要一个什么样的值、用来做什么、是必需还是可选。需要不点名任何块键。依据：产品 [§2.3](../../../.meta_harness/design/product/runtime-context/design.md#23-需要绑定与集成原则)。

集成方在注册时为每条需要写下一条需要绑定，把它对到一块。形状不同时，绑定附带翻译。翻译是纯函数，归集成方，不进生产者或消费者任何一方的约定。本成员在读取时先核块资格，再按绑定翻译，交给读者的始终是消费者自己声明的形状，并带来源块的证据。

集成原则：集成方知道被集成方；被集成方只对外声明自己供什么、要什么，用自己的词，不知道被谁集成。本成员是集成方选用的中介，不是让被集成方互相认识的通道。由此，块声明与需要都不点名对方，块键只是集成方在注册时对上两边的手段。

必需的需要缺项时，依赖它的动作不可用，系统说明缺的是什么，不用空值、猜值或旧值代替。必需块的生产者暂时不在场时，注册照常成立。作用域的创建不因某个生产者暂时不在场而失败。

纯函数 `judgeNeed` 核对一条需要本身的合法性。纯函数 `judgeBinding` 核对一条绑定：块声明存在、需要的消费者类在块允许的消费者类之内、必需的需要没有绑到可选移除的块、没有翻译时两边形状相同。核对失败是定义层的拒绝，带原因。

## 所有权、失败与生命周期

### RC-07 生产者句柄、并发、撤除与恢复

生产者为一块登记供值后得到一个生产者句柄，用它发布新值、使当前值失效或撤销登记。为没有块声明的块键登记被拒绝。发布的值不合块声明的形状时，发布被拒绝，当前值与修订不变，不存成「内容无法解释」。生产者句柄有代际。生产者换代后，旧一代迟到的发布不被采用，不能覆盖新一代的值。使当前值失效只唤醒读者。读者读到什么以读取时的值为准，不按唤醒推断变化内容。撤销登记前，本代在途的读取先结算。依据：产品 [§2.2](../../../.meta_harness/design/product/runtime-context/design.md#22-块声明归语义拥有者)。登记寿命怎样落在 Cordis 归 [runtime-context-cordis-contract](../runtime-context-cordis-contract/SPEC.md)。

注册修改、生产者更新、撤权、读取和请求固定可能并发。每次读取和最终发起都能解释其合法采用范围，不拼接从未合法成立的状态。正在组装的新值不能覆盖已固定的请求。当前来源变更也不能无声改回旧快照。

取消一次读取或结束一个绑定读者，对应等待与资源结束。它不证明来源变更未提交，不取消原工具或模型执行，也不删除既有历史。释放资源或运行 disposer 不撤回外部输出。取消时提交未知，原责任方继续对账。

生产者或提供者撤除后，合法重读与依赖失败由本契约承接：读取返回缺项或未知，不返回旧值。已保管的不可重算事实不随实例或进程生灭消失。结构性绑定换代沿装配交接，新读当前数据不被误当作结构性换绑。

恢复需要保留本作用域的注册、参数、移除意图、自有不可重算值，以及足以解释旧执行的采用依据。只保存最后数据或只保存历史都不够。供给块按声明的恢复方式回来：`persisted` 读回原值，`reread` 向权威来源重取并按当前资格取得，`recompute` 从当前事实重算。状态块 `checkpointed` 按最近一次步提交恢复。恢复核对原身份与当前资格：主动移除不装回，必需信息不绕过，旧备份不复活撤销的资格。共享来源不可用时保持缺项，不用历史允许或缓存掩盖。依据：产品 [§2.1](../../../.meta_harness/design/product/runtime-context/design.md#21-两类块供给块与状态块)、[§8](../../../.meta_harness/design/product/runtime-context/design.md#8-故障恢复和数据保护)。

已发请求采用的值与本次应读的当前值分别恢复。执行换代不重发已经存在的模型或工具调用。原执行、结果、费用和原消费位置继续由原调用和消费拥有者负责。本成员只供给合法条件。

作用域结束使等待解除，不以所有独立执行物理停止为完成前提。迟到结果不复活推进。真实结果和账目按原拥有者保留。任何确认消息都不授予本成员删除共享来源、自有值或历史的权力。

后续成员和真实组合至少持续验证以下行为。这是义务，不是本次已执行的测试。

| 场景 | 必须检查的结果 | 条款 |
| --- | --- | --- |
| 同块不同消费者类 | 工具或扩展私有块不通过快照、变化、缓存或错误进入模型 | RC-03 |
| 必需块生产者缺席 | 注册成立，读取返回缺项，不返回空值，消费者不失效 | RC-03、RC-06 |
| 可选移除后故障恢复 | 原移除仍有效，共享来源和别的作用域不受删改 | RC-02、RC-07 |
| 必需块移除或身份改写 | 操作不生效，不以必需来源不可用偷换成可选 | RC-02 |
| 读取与撤权、注册变化竞争 | 最终合法范围可追溯，旧缓存不提供新允许，撤权在下一次读取生效 | RC-03、RC-07 |
| 游标作废的三种情形 | 授权范围变化、生产者换代、进程重建后 `changes` 要求重取完整快照 | RC-04 |
| 旧一代生产者迟到发布 | 不被采用，新一代的值不被覆盖 | RC-07 |
| 状态块越权更新 | 非写者类的更新、指向供给块的更新不成为事实 | RC-05 |
| 失败步的成功更新 | 保留为待处理，不进本步提交，不丢弃 | RC-05 |
| `singleWriterPerStep` 冲突 | 同一步第二个写者被拒绝 | RC-05 |
| 带翻译的绑定 | 读者拿到自己的形状与来源证据；翻译失败按读取失败报告 | RC-06 |
| 子作用域遮蔽 | 同键子级值遮蔽父级；父级缺失时沿链读到 | RC-03 |
| `per-request` 块 | 不进快照，不产生变化材料 | RC-02、RC-04 |

### 明确缺项

- 注册、当前读取和恢复的一致协议的精确形状，归产品 [CONTEXT-M01](../../../.meta_harness/design/product/runtime-context/design.md#context-m01)。
- 需要怎样声明、更新怎样随结果携带，归产品 [CONTEXT-M04](../../../.meta_harness/design/product/runtime-context/design.md#context-m04) 与各消费者契约的拥有者。
- 工作区指导的首次访问判据，归产品 [CONTEXT-E02](../../../.meta_harness/design/product/runtime-context/design.md#context-e02)。本成员只供给当前值，不拥有加载规则。
- 本成员的 `src/` 现在只有共享类型。需要、绑定、注册、资格、读者、更新、步提交、变化材料的类型，五种读取结果的类型名，五个纯函数与两个解码函数随实现切片进入，形状以本页和 [docs/object-model.md](docs/object-model.md) 为准。
- 三条 Cordis 机制读数仍是假设，列在 [runtime-context-cordis-contract/docs/cordis.md](../runtime-context-cordis-contract/docs/cordis.md)。

这些缺项不允许降低已定的访问、历史和恢复责任。当前没有运行实现，不宣称接口、租户隔离、并发、断电耐久或性能通过。作者自检和结构检查不授予接受。
