## 范围与依据

本成员拥有 Runtime Context 的协议：块声明、上下文需要、需要绑定、注册、读取资格、绑定读者、快照与变化、上下文更新、步提交、变化材料、作用域结束与恢复材料的类型，访问核验所需的两个端口的类型，以及对它们的纯核对函数。它不拥有任何一块的内容，不签发身份，不判断动作能不能做，不选择执行落点，不组装模型请求，不保存历史。

本页只用通用角色：作用域持有者、生产者、消费者类（`model`、`tool`、`extension`、`coordinator`）、集成方、协调者、调用方、维护者。本成员不认识上层工作流的具体类型。外部业务事实由外部按本成员返回的身份关联。

## 结果与不变量

### RC-01 消费者、身份与范围

本能力向模型、工具、扩展和协调者四类消费者提供分块当前值及其变化。消费者类不是许可。每次读取都识别调用方、消费者类、作用域、主体与租户，并核对消费资格。托管租户数据和跨作用域操作显式携带租户身份。跨租户访问默认拒绝。这一条取代已接受条款里读取还要识别「用途」的写法：读取资格只按消费者类与块键集合核对。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

作用域由不透明的 `ScopeRef` 表示，可以带父引用。本成员不解释它指的是租户、会话还是一次执行。本阶段只有一种作用域持有者，所以只有单层作用域。父级查找与遮蔽规则（见 [RC-03](#rc-03-当前读取资格与缺项)）对以后的多层持有者同样成立。

块的内容归它的生产者或语义拥有者。本成员不因持有注册、快照或句柄而取得修改任何块内容的资格。多个合法消费者可以读同一块，各自独立满足资格。

#### 作用域引用的铸造

作用域持有者铸造 `ScopeRef`。引用的文本由三项材料构成：租户、持有者侧的标识、作用域代次。这三项使引用在租户之间唯一，也在撤销与归档之后唯一。`ScopeRef` 的形状不变，本成员不解析它的文本。

引用里的租户只是唯一性与核对材料。任何一方都不从引用文本解析租户。租户的权威是可信绑定来源给出的租户（见[通用权威端口](#通用权威端口)）与调用方访问身份里的租户，两者必须一致。

新的业务代次使用新的 `ScopeRef`。旧引用永远不重新绑定到另一个租户，也不在结束之后重新打开。依据：J18。

#### 三面操作

本成员的操作分三面，共八个。操作类型在根入口定义，签名只写一次；[runtime-context-cordis-contract](../runtime-context-cordis-contract/SPEC.md) 的服务实现同一组类型。除 `bind` 以外，每个操作的第一个参数是调用方的可信主体。本成员把主体交给权威端口核对，不比较也不解释主体。

| 面 | 操作 | 做什么 | 条款 |
| --- | --- | --- | --- |
| 生产者面 | `registerProducer` | 为一个租户的一块登记供值，返回生产者句柄。输入带租户、生产者身份与供给块的块声明。作用域无关的块在这里给出按作用域供值的回调 | [RC-07](#rc-07-生产者句柄并发撤除与恢复) |
| 持有者面 | `prepareRegistration` | 用 `judgeRegistration` 核对注册材料，不写表 | [RC-02](#rc-02-块声明注册与参数) |
| 持有者面 | `issueEligibility` | 签发一份读取资格，返回资格身份。签发时核对读者的消费者类（见 [RC-06](#rc-06-需要绑定与读者形状)）。带「取代的资格身份」时是重签：旧资格转为被取代，按旧资格建立的读者沿新资格继续，游标作废，读取不被拒绝。收窄授权范围也经重签，不必先撤销 | [RC-03](#rc-03-当前读取资格与缺项)、[RC-04](#rc-04-读取时点观察与变化材料) |
| 持有者面 | `revokeEligibility` | 撤销一份读取资格。撤销后，该资格的读取按拒绝（无权） | [RC-03](#rc-03-当前读取资格与缺项) |
| 持有者面 | `applyCommit` | 持有者提交注册决定、步提交或作用域结束之后，把提交结果交给本成员应用。输入带提交身份；注册决定另带依据的注册修订。本成员按作用域加提交身份的完整输入去重，顺序不符时返回无效，见 RC-02 的[注册修订与提交顺序](#注册修订与提交顺序)。步提交只含 `reduceStep` 接受的更新。收到含被拒更新的步提交时整笔拒绝（无效），不写投影。带「执行结束」标记时，`untracked` 状态块失效。带作用域结束标记时，作用域转为已结束 | [RC-02](#rc-02-块声明注册与参数)、[RC-05](#rc-05-状态块上下文更新与步提交)、[RC-09](#rc-09-作用域结束恢复会话与恢复后供值) |
| 持有者面 | `beginReplay` | 开始一个作用域在本实例上的恢复会话，关闭披露围栏，返回恢复引用 | [RC-09](#rc-09-作用域结束恢复会话与恢复后供值) |
| 持有者面 | `finishReplay` | 用一份完整恢复材料原子安装作用域投影，结束恢复会话 | [RC-09](#rc-09-作用域结束恢复会话与恢复后供值) |
| 读者面 | `bind` | 按资格身份建立绑定读者。资格被重签取代后，读者沿新资格读取。读者使用资格里的主体 | [RC-03](#rc-03-当前读取资格与缺项)、[RC-04](#rc-04-读取时点观察与变化材料) |

这一条取代已接受条款里持有者操作不带主体、生产者按块键唯一的写法。依据：J41 与[本域目标协议](https://github.com/nemori-ai/omne-harness-lite/issues/678#issuecomment-6371505744)。

公开能力可以独立使用。调用方提供作用域、生产者、资格材料、资源与两个权威端口的适配器。本成员不强制创建任何上层对象，也不要求装配 Cordis。只处理调用方给出的数据时，缺上层对象不算拒绝。访问系统托管数据的适配器必须接到该数据的真实权威来源。本成员没有调用方可以选择的免核验模式。根入口提供作用域引用与块键的解码函数，独立调用者从字符串得到品牌类型，不用类型断言。独立入口的字节编码未定。

#### 通用权威端口

本成员不签发身份，也不保存许可。它经两个由调用方提供的端口核对访问：

- 可信绑定来源 `ScopeBindingSource`：对一个作用域回答四种之一：已绑定（带租户）、未绑定、不可用、未知。同一作用域的绑定不改租户。来源重建之后也必须认同原绑定。来源无法确认当前权威状态时答不可用或未知，不用缓存补出新的许可。
- 权威端口 `RuntimeContextAuthority<P>`：按动作回答授权判定。它有三个面：持有者动作（准备、提交、签发、撤销、开始恢复、完成恢复）、生产者动作（登记、发布、失效、供值、按租户失效）和读者动作（按资格读取）。动作是封闭的判别联合。授权判定是四种之一：已授权（带代租户主体与 `current()`）、拒绝、不可用、未知。完成恢复与开始恢复的判定另可答无效（检查点冲突或恢复材料不全），只在目标授权已经确认之后答复。

每个带目标的入口按下列顺序核对。前一项不成立，后面的不再执行：

1. 调用方有权访问该输入目标（权威端口）。
2. 可信绑定来源确认该作用域已绑定，且租户等于输入里的租户。
3. 作用域的状态、注册、生产者代际与恢复围栏。

未绑定、绑定租户与输入租户不同，以及权威端口答拒绝，对外一律是无权。本成员不先返回真实租户、登记数量或另一个租户的存在性。完全不认识的资格身份对 `bind` 是无权；对已经具备持有者资格的撤销才可以是「资格未知」。父级查找的每一跳独立核对租户与授权，跨租户的父级值不被继承。结构性的调用方声明和消费者声明不授予权限。

权威端口不可用映射为「不可用」，未知映射为「未知」，原因分别标 `authority`、`scope-binding` 或 `replay`。这两种结果表示本次核对不能给出成功。它们不安装新投影，已经关闭的恢复围栏保持关闭。没有成功的空值能代替它们。

#### 当前授权前提

已授权判定里的 `current()` 是必需的同步前提。权威适配器必须让撤权、原工作失效、恢复检查点失效与本成员的最终同步提交或披露共用同一个串行边界。本成员在每次 `await` 之后、调用来源之前以及最终提交或披露之前同步调用它。检查与受保护的动作之间没有 `await`。它答假时，结果是拒绝（无权），本成员不用旧答复继续。

判定只在这一次动作内有效，不保存为长期许可。动作完成、换代、取消或端口撤除之后，判定不再可用。一个保存了真值的闭包、一次异步核验成功或一个类型品牌都不满足这个前提。跨进程不能传送内存中的 `current` 闭包作为证明，需要另一个已接受且已验证的同步协议。这个前提由权威适配器与真实组合兑现，本成员不提供它（见[明确缺项](#明确缺项)）。

#### 输入快照

每个公开入口在第一次外部调用或第一次 `await` 之前，捕获本操作拥有的数据字段。之后的授权动作、可信绑定、规范化、校验、提交与披露只使用这份快照。本成员不会在授权一份输入之后从可变输入里重新读出另一份。快照包括数组与集合、嵌套的父级链、注册参数、提交数据、恢复材料，以及权威端口与绑定来源答复里的数据字段。

快照按字段的契约复制数据。schema、reducer、翻译、回调与端口保留真实对象身份。可信主体与 `TenantId` 也保留真实身份，不做 JSON 克隆，不被强制转换成替身。本成员不冻结调用方的对象。供给值与提交值按声明的数据形状复制为自有值，不执行不受信的克隆协议。无法合法捕获的数据走原形状失败通道。来源回执不合法时，本成员记未知并留下诊断。

快照只绑定同一次操作的输入。`current()` 只保护权威是否仍然新鲜。两者都必须成立，任何一个都不代替另一个。

### RC-02 块声明、注册与参数

每种块有一份块声明。块声明由这个值的语义拥有者发布，也就是决定这份值是什么意思的一方。它不归存放这份值的一方，也不一定归生产者。全系统一个块键只有一份声明。本成员不声明任何具体块键。语义拥有者在自己的包里导出声明，并用 `declare module` 增补 `ContextBlocks`。依据：产品 [§2.2](../../../.meta_harness/design/product/runtime-context/design.md#22-块声明归语义拥有者)。

块声明分两类。

| 类 | 谁改值 | 恢复 | 声明的附加字段 |
| --- | --- | --- | --- |
| 供给块 `supplied` | 一个租户的一个生产者供当前值，读者只读 | `persisted`、`reread`、`recompute` 三选一 | 无 |
| 状态块 `stateful` | 声明的写者类提出更新，作用域持有者在步边界提交 | `checkpointed` 按最近一次步提交恢复；`untracked` 只在一次执行内有效，不恢复 | `writers`、`reduce`、`persistence`、`singleWriterPerStep` |

两类共用的字段：块键、值的形状、允许的消费者类、是否必需、披露方式（`plain` 或 `eligibility-checked`）、能否带前值、变化频率（`stable`、`per-step`、`per-request`）、可选的作用域级参数形状。`per-request` 块只进请求最末的尾部易变提醒，不进快照，不产生变化提醒，读取路径见 [RC-04](#rc-04-读取时点观察与变化材料)。依据：产品 [§2.1](../../../.meta_harness/design/product/runtime-context/design.md#21-两类块供给块与状态块)、[§5.1](../../../.meta_harness/design/product/runtime-context/design.md#51-首次注入锚定快照与追加提醒)。

声明的 `required`、注册的 `required` 与需要的必需性各自生效。声明改为可选以后，合法的无值与生产者缺席可以缺席。来源不可用、来源未知、来源拒绝与内容无法解释不因块是可选而消失，按[读取结果](#读取结果)表落位。

消息的可见性标注不是块声明字段，归[内容块成员](../../common/content-block/README.md)。`consumers` 只决定哪类读者有资格读这一块。

块声明不安装块，也不授权读它。谁供值由生产者登记决定（见 [RC-07](#rc-07-生产者句柄并发撤除与恢复)）。

运行时的块声明目录归本成员的实现。声明经两条路径进入目录：生产者登记时带供给块的声明；作用域持有者注册状态块时带状态块的声明。注册供给块只引用块键。同一块键已有一份声明而新带来的声明摘要不同时，带来它的登记或注册被拒绝（无效）。不同租户的生产者登记同一块键时，各自带来的声明摘要也必须与目录相同。

持有者可以先于生产者注册一个供给块。这时目录里还没有它的声明，注册只核与声明无关的部分：块键的形状、作用域所属租户、绑定的结构。生产者带声明登记时，本成员按声明核对该块键已有的注册。某个作用域的注册与声明不相容时，本成员记录诊断，该块在这个作用域读到缺项，直到持有者重新注册。

注册是作用域持有者为一个作用域固定下来的清单：有哪些块、每块对到哪些需要、带什么参数。注册说的是「这里有这一块」，不是这一块当前的值。注册的身份是作用域加块键。必需项在作用域创建时固定，之后不能移除。可选项可以增删。移除一个可选项只停止本作用域后续使用该注册，共享来源和其他作用域不受影响。必需项不能用可选移除绕过。固定身份不能用内容更新改写。注册带注册修订，读取资格引用它。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

作用域级参数的形状由块的声明者定，值由持有者在注册时给出。本成员只校验值是否合乎形状。持有者不能给声明里没有的参数。这一条取代已接受条款里「注册保存来源与配置」的写法。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

注册决定是持有者的一笔提交。块内容是生产者的另一笔提交。两笔不并成一次跨拥有者的提交。进入持有者历史的依据是注册集合变更，以及不能重算的作用域自有输入。当前快照、预算过程和空闲推送不进历史。跨存储的同一次提交见 [STORAGE-T01](../../../docs/architecture/data-and-state.md#storage-t01)。

注册变更的最小对接如下。增加、更新和移除都走这张表。更新保持块的固定身份，只改绑定或参数。更新不是先移除再新增。

| 项 | 规则 |
| --- | --- |
| 关联身份 | 这次变更的提交身份，加作用域和块键 |
| 必要参数 | 调用方主体、作用域、作用域所属租户、块键、需要绑定、参数值、是否必需、依据的注册修订，以及增加、更新或移除。每次注册都带作用域所属租户，不只在访问托管数据时带 |
| 成功 | 注册决定已提交，注册修订前进。块内容由生产者另行提交 |
| 拒绝 | 无权（含可信绑定未绑定或租户不同）、作用域已结束、恢复未完成、移除必需项、更新把必需改为可选、作用域创建后增加必需项、更新改了固定身份、参数不合声明形状、绑定不合核对（见 [RC-06](#rc-06-需要绑定与读者形状)）、同一提交身份配上不同输入（无效） |
| 不可用与未知 | 权威端口或可信绑定来源不能给出结论。按原提交身份查询。不重建另一条注册 |
| 同身份重试 | 相同提交身份和相同完整输入，在当前授权通过后返回原结果 |
| 参数冲突 | 相同提交身份配不同输入则拒绝。另一提交身份要改同一块时，先核它依据的注册修订是否仍是当前修订。已经变了就拒绝，调用方按当前注册重新提交。不用后写覆盖先写 |

注册或更新未提交，不报告为已生效。提交未知时保留原操作身份，按原拥有者查询和对账，不直接重建另一注册，也不用旧快照覆盖合法变化。

作用域所属租户由可信绑定来源确认，持有者的注册材料必须给出同一个租户。绑定来源答未绑定，或答出的租户与材料不同，注册对外按无权拒绝。本成员在一个作用域第一次被确认时记下它的租户，记下的租户不改。可信绑定已经匹配、而本实例记下的租户与可信事实冲突，是内部一致性异常，结果是无效（`tenant-mismatch`），不返回另一个租户的材料。这一条取代已接受条款里「首次注册记下的租户即作用域租户」的写法。依据：J18、J41。

#### 注册修订与提交顺序

注册修订的唯一权威是作用域持有者的耐久提交。本成员的注册表是按提交顺序应用的投影。上表「参数冲突」一行的修订比较发生在持有者提交之前，由持有者完成。

`applyCommit` 的输入是三种之一：

| 输入 | 作用域与租户取自 | 说明 |
| --- | --- | --- |
| 注册决定 | 变更里的作用域与租户 | 可带作用域结束标记 |
| 步提交 | 步提交里的作用域与输入里显式给出的租户 | 可带执行结束标记与作用域结束标记 |
| 只结束作用域 | 输入里的作用域与租户 | 只表达作用域结束，不制造空注册，也不制造虚假的步 |

持有者提交之后调用 `applyCommit`。本成员按作用域加提交身份记录已应用的普通提交的完整输入与结果。这份记录只在进程内保存：

1. 同一提交身份、相同完整输入的重试，在当前授权通过后返回原结果，不降修订。认回不把旧修订说成当前修订。
2. 同一提交身份配不同完整输入，包括改变或省略作用域结束标记，返回无效，原因是「提交冲突」。
3. 注册决定依据的注册修订等于本成员的当前注册修订时，应用这笔提交，注册修订前进。
4. 注册决定依据的注册修订不等于当前注册修订，而且本成员没有见过这个提交身份时，返回无效，原因是「顺序不符」。持有者用恢复会话补齐（见 [RC-09](#rc-09-作用域结束恢复会话与恢复后供值)），再用原输入重试。持有者不改写原请求来伪装重试。

顺序不符、无效、拒绝、不可用与未知不进入成功去重表。补齐前序之后可以重试。

步提交也带提交身份。本成员按提交身份幂等应用步提交，不把它与注册修订比较。

作用域尚未完成恢复，或正在恢复时，新的注册决定与步提交返回「恢复未完成」。已经应用的普通提交可以认回，但不披露投影。

纯函数 `judgeRegistration` 核对一条注册材料：块声明存在、参数合乎形状、必需项未被移除、每条绑定通过 `judgeBinding`。目录里还没有声明的供给块，只核上一段列出的与声明无关的部分，其余在生产者带声明登记时核对。核对失败是定义层的拒绝，带逐项原因。

注册修订为非负安全整数计数。注册的 `required` 只规定作用域创建时固定的必需项；读取缺项按块声明的 `required` 判定。

### RC-03 当前读取、资格与缺项

读取资格由作用域持有者签发给一次绑定。它有资格身份，并写明作用域、消费者类、主体与租户、允许读的块键集合、允许的需要绑定集合，以及签发时的注册修订。读取资格只来自持有者签发，不能凭调用方所在的位置或装配树推断（[IC-18](../../../docs/architecture/cordis-integration-conventions.md#ic-18)）。这一条取代已接受条款里读取资格归生产者的写法：读取资格改由作用域持有者签发。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

两个集合各授权一种读取：

- 块键集合授权读者按块自己的形状读这些块。
- 需要绑定集合授权读者读带翻译的需要。读者按集合里的绑定读到翻译后的值。被翻译的块不因此进入块键集合，读者按块的原形状读它时被拒绝（无权）。

持有者经 `revokeEligibility` 撤销资格，撤销后该资格的读取按拒绝（无权）。重签是 `issueEligibility` 带「取代的资格身份」签发一份新资格。旧资格转为被取代，按旧资格建立的读者沿新资格继续，游标作废，读取不被拒绝。收窄授权范围也经重签，持有者不必先撤销。只有撤销与恢复会话的开始拒绝读取。读取资格只决定能读哪些块，不决定能做什么动作。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

读取资格有三个状态：有效、被取代（记下取代它的资格身份）、已撤销。资格由本成员保管，直到持有者撤销它、重签取代它、恢复会话使它失效，或本成员关闭。本成员重建之后不恢复任何资格，持有者重新签发。

绑定读者按资格身份建立。它的消费者类与主体取自资格，在建立时固定，使用者不能改。绑定读者每次读取都按下列顺序重新核对：

1. 资格的状态。被取代的资格沿取代者身份找到当前资格再核。已撤销即拒绝（无权）。
2. 权威端口的读者面对资格主体与这份资格给出已授权判定。拒绝即拒绝（无权）；不可用或未知即未知（`eligibility-unknown`）。
3. 可信绑定来源确认资格的作用域已绑定，且租户等于资格的租户。未绑定或租户不同即拒绝（无权）；不可用或未知即未知（`scope-binding-unknown`）。
4. 作用域的状态：已结束即拒绝（`scope-ended`）；恢复围栏关闭即拒绝（`replay-incomplete`）。
5. 资格的作用域，以及要读的块键或需要绑定在资格的两个集合里。
6. 读者的消费者类按当前注册仍合乎块允许的消费者类（见 [RC-06](#rc-06-需要绑定与读者形状)）。

撤权在下一次读取生效。旧读者不能继续读到新内容。

读取只纳入当前有效注册、生产者允许提供且消费者当前有权读取的块。历史提醒、旧快照和旧允许缓存不作为当前资格依据。资格无法取得，或来源查询失败、超时，读取结果都是未知。未知阻止依赖该允许结论的新读取或动作。不能返回空集合冒充完整成功。

无权、无有效注册、来源不可用、内容无法解释和结果未知分别处理，各自落位见下面的[读取结果](#读取结果)表，同时遵循对象存在性披露规则。作用域未注册与作用域已结束只在授权通过之后披露。错误不返回未授权正文、凭据或来源内部细节。必需块的生产者不在场时，注册照常成立，读取返回明确的缺项。本页的「不在场」只表示生产者不在场，不表示块没有值。缺项由依赖它的动作按各自契约处置。本成员不伪造占位值，不隐式移除必需项，也不让消费者因缺项而失效。依据：产品 [§2.3](../../../.meta_harness/design/product/runtime-context/design.md#23-需要绑定与集成原则)。

子作用域读一个块键时先查自己，再查父级。同一个块键在子作用域里的值遮蔽父级的值。父级的每一跳独立核对租户与授权，跨租户的父级值不被继承。依据：产品 [§2.4](../../../.meta_harness/design/product/runtime-context/design.md#24-注册读取资格与绑定读者)。

一次读取能够解释采用来源、覆盖范围和修订。多个块需要同一合法读取范围时，由消费与最终发起的协调者保护一致性。本成员不宣称任意独立来源自动全局同提交。

读取的最小对接如下。读取不建立可认回的写操作。

| 项 | 规则 |
| --- | --- |
| 关联身份 | 绑定读者、作用域和这次读取的范围。托管读取再带租户 |
| 必要参数 | 读取资格，以及要读的需要集合或当前快照范围 |
| 结果 | 四种之一，见[读取结果](#读取结果) |
| 同身份重试 | 再读一次，取得读取当时的当前值 |
| 参数冲突 | 读取不修改注册 |

#### 读取结果

一次读取的结果只落在下表的一行。表是封闭的，没有其他结果。

| 结果 | 落入的情形 | 返回什么 |
| --- | --- | --- |
| 成功 | 每项需要都有结果 | 每项需要的值，按需要绑定翻译成消费者的形状，带来源证据和修订。可选需要没有当前值时，该项标「无值」。「无值」不是失败。资格签发时的注册修订落后于当前注册修订时，结果同时带这两个修订，供持有者判断是否重签。绑定读者的完整快照与变化另带逐请求块的当前值，见 [RC-04](#rc-04-读取时点观察与变化材料) |
| 拒绝 | 无权（含资格已被撤销；可信绑定未绑定或租户不同；权威端口拒绝；任一来源对本次供值答拒绝；按原形状读不在块键集合里的块，包括只经翻译授权的块；读不在需要绑定集合里的带翻译需要）；无有效注册；作用域已结束；恢复未完成；服务已关闭 | 拒绝的原因。无有效注册只在披露规则允许时说明。不返回未授权正文 |
| 缺项 | 必需块无当前值；来源不可用（权威来源明确答复不可用）；生产者撤除后；翻译失败；内容无法解释 | 缺项与缺的是哪一块，带来源块的修订。不用空值或旧值冒充当前值 |
| 未知 | 来源读取未知（来源答未知、抛出、超时或回执不合法）；资格无法取得（权威端口不可用或未知）；可信绑定不能确认；恢复覆盖不能确认；依据的提交未知 | 未知及原因。不返回空集合 |

未知的原因是封闭集合：`source-unknown`、`eligibility-unknown`、`commit-unknown`、`scope-binding-unknown`、`replay-unknown`。读取的授权不可用与未知都映射 `eligibility-unknown`；可信绑定不可用与未知都映射 `scope-binding-unknown`。读取没有第五种结果。来源明确答复不可用仍是缺项（`source-unavailable`），不与授权不可用混同。

`changes` 另有游标作废，见 [RC-04](#rc-04-读取时点观察与变化材料)。游标作废不是读取失败，读者据此重取完整快照。

读到当前值不改变已经固定的请求。新的合法值作用于之后的读取。撤权停止新内容供给，不取消独立执行，也不撤回已发生的效果。

`snapshot()` 与 `changes()` 的成功结果带 `missing` 清单；`read(needs)` 全有或全缺。逐请求块每项分别表达值、无值、缺项或未知。

### RC-04 读取时点、观察与变化材料

绑定读者给出两种结果：当前的完整快照，或自上次读取以来的变化。快照带视图修订和游标。游标属于一个绑定读者。是否需要完整快照由本成员按游标状态判断，不由发起请求的一方猜测。依据：产品 [§5.1](../../../.meta_harness/design/product/runtime-context/design.md#51-首次注入锚定快照与追加提醒)。

游标在五种情形下作废：授权范围变化、生产者换代、进程重建、持有者重签该读者的资格、游标早于观察链的保留下界。作废之后，读者必须重新取完整快照。观察链的保留上限由实现决定。早于下界的旧游标作废后，结果同样是完整快照，不是残缺的增量。恢复会话的开始使该作用域的读者与游标失效（见 [RC-09](#rc-09-作用域结束恢复会话与恢复后供值)）。

作用域持有者主动使一个读者的游标作废时，用 `issueEligibility` 带该读者当前资格的身份重签。重签不拒绝读取，拒绝读取用 `revokeEligibility`。压缩提交之后，持有者对模型类读者这样做。本成员自己不认识压缩。持有者在提交压缩之后、重签之前崩溃时，恢复时先重签模型类读者的资格，再接续。

绑定读者的每次读取，不论结果是完整快照还是变化，都另带一部分：逐请求块的当前值。这一部分按读者资格过滤。本成员在读取时向生产者取值：`recompute` 的块调用生产者的取值回调，`reread` 的块向来源重读。这一部分不进快照，不进观察链，也不产生变化提醒。某块取不到值时按[读取结果](#读取结果)表落位：必需块无当前值或来源不可用记缺项，来源读取未知记未知，可选块无当前值标「无值」，来源答拒绝使整次读取拒绝（无权）。

一次执行开始，或为执行建立挂接（接续或换代之后）时，调用方主动取得当前合法完整快照。只有推送不能覆盖空闲期间的变化。调用方不能以「没有收到变化通知」省略这次读取。

块的值变化后，变化材料由持有者拉取：持有者用该读者的游标调 `changes`，再调纯函数 `diffForReminder` 算出变化材料：哪一块、从哪个修订变到哪个修订，以及按该读者资格过滤过的前值。本成员不推送变化材料，唤醒只提示持有者去拉。唤醒丢失时，持有者下一次拉取补齐。持有者把变化材料写成变化提醒追加进历史。变化材料不是提醒消息本身。曾经可读、现在无权读的前值不披露。块是否允许带前值由块声明说明。纯函数 `diffForReminder` 从两份快照算出变化材料。

前值来自作用域持有者保留的上一份快照。这份快照是持有者上一次为该读者取得的、已按资格过滤的结果。本成员不保存旧值。持有者重启之后，或该读者的游标作废之后，持有者没有可比的上一份快照，第一份变化材料不带前值。

模型可读块的变化经持有者形成追加提醒。仅工具或扩展可读的块只向获准消费者供给，不通知模型。注册的增加或移除同样让后续适用消费者感知变化，不改写已经发出的输入。

完整快照只进请求，不进历史。变化提醒进历史。`per-request` 块不进快照，也不产生变化提醒。依据：产品 [§5.1](../../../.meta_harness/design/product/runtime-context/design.md#51-首次注入锚定快照与追加提醒)。

空闲状态推送可以丢弃。下一次执行开始或挂接建立时的读取承接变化，不补世界上所有中间值。普通输入、控制、结果和已承担交付责任的数据不得归到这条可丢路径。唤醒只提示检查权威状态，不单独授予推进资格。重复唤醒不得重复逻辑承接。丢失唤醒后仍有权威事实可补查。本成员不能用唤醒到达或订阅成功代替提醒已持久成立。

模型首次读取与合法压缩后，提供当前有权读的完整快照。私有块不因全量路径进入模型。历史提醒被摘要后，不能用摘要替代这次完整读取。

### RC-05 状态块、上下文更新与步提交

参与者对状态块提出的是上下文更新。上下文更新是提案，不是事实。一条更新只能指向状态块，提出它的一方必须在该块声明的写者类之内。不满足这两条的更新不会成为事实。更新带着提出它的原动作身份。依据：产品 [§2.5](../../../.meta_harness/design/product/runtime-context/design.md#25-状态块的更新与步提交)。

作用域持有者在步边界收齐这一步的全部更新，按各块的合并规则合成一份步提交。步提交写成之后，这些更新才成为块的值。一步只有一份步提交。块声明 `singleWriterPerStep` 为真时，同一步里第二个写者的更新被拒绝。谁是第二个写者，按更新到达持有者的顺序判定。被拒的更新退回提出者，并带原因。提交本身不在本成员，归持有者。

越权的更新在提交前剔除。纯函数 `reduceStep` 对每条更新给出接受或拒绝。拒绝的原因是无权（指向供给块，或提出者不在声明的写者类之内）或不合形状。`reduceStep` 把接受的更新按声明的 `reduce` 合并成提交材料，不触碰任何存储。持有者只把接受的更新写进步提交，并按 `reduceStep` 的逐项原因把被拒的更新退回提出者。`applyCommit` 收到含被拒更新的步提交时整笔拒绝（无效），不写投影。

状态块可带 `updateSchema`，合并前校验更新，合并后校验值。异步校验不进入纯函数，返回定义层拒绝 `schema-not-synchronous`，带对应参数路径。单写者冲突归 `unauthorized`，原因 `single-writer`，保留第一个原动作身份。

失败的步里，已经成功的动作提出的更新保留为待处理，不进这一步的提交，由持有者决定怎样处置。本成员不丢弃它们，也不把它们并进失败的一步。

提交之后，模型可读的状态块按 [RC-04](#rc-04-读取时点观察与变化材料) 产生变化材料。`persistence: 'untracked'` 的状态块在持有者调用 `applyCommit` 并带「执行结束」标记时失效，恢复时不读回。本成员不自己判断执行何时结束。

### RC-06 需要、绑定与读者形状

消费者在自己的定义里用自己的形状声明上下文需要：要一个什么样的值、用来做什么、是必需还是可选。需要不点名任何块键。依据：产品 [§2.3](../../../.meta_harness/design/product/runtime-context/design.md#23-需要绑定与集成原则)。

集成方在注册时为每条需要写下一条需要绑定，把它对到一块。形状不同时，绑定附带翻译。翻译是纯函数，归集成方，不进生产者或消费者任何一方的约定。本成员在读取时先核块资格，再按绑定翻译，交给读者的始终是消费者自己声明的形状，并带来源块的证据。没有翻译的绑定按读者的消费者类核块资格，读者读它要求块键在资格的块键集合里。带翻译的绑定按集成方的消费者类核来源块的资格，读者读它要求这条绑定在资格的需要绑定集合里（见 [RC-03](#rc-03-当前读取资格与缺项)）。读者不因此取得按块原形状读取的资格，资格的块键集合不含被翻译的块。依据：产品 [§2.3](../../../.meta_harness/design/product/runtime-context/design.md#23-需要绑定与集成原则)。

集成原则：集成方知道被集成方；被集成方只对外声明自己供什么、要什么，用自己的词，不知道被谁集成。本成员是集成方选用的中介，不是让被集成方互相认识的通道。由此，块声明与需要都不点名对方，块键只是集成方在注册时对上两边的手段。

必需的需要缺项时，依赖它的动作不可用，系统说明缺的是什么，不用空值、猜值或旧值代替。必需块的生产者暂时不在场时，注册照常成立。作用域的创建不因某个生产者暂时不在场而失败。

需要的 `name` 是消费者定义内的身份。无翻译的绑定以 Standard Schema 对象引用相等作为形状相同的判据。

纯函数 `judgeNeed` 核对一条需要本身的合法性。纯函数 `judgeBinding` 在注册时核对一条绑定。注册时还没有读者，所以它只核注册时可知的部分：

- 块声明存在。
- 必需的需要没有绑到可选移除的块。
- 没有翻译时两边形状相同；带翻译时翻译已给出。
- 带翻译时，集成方的消费者类在块允许的消费者类之内。

核对失败是定义层的拒绝，带原因。

读者的消费者类在注册时不可知，所以在资格签发与读取两处核对：

- 签发：资格块键集合里的每一块都允许资格的消费者类；需要绑定集合里的每条绑定都带翻译，它的需要声明的消费者类等于资格的消费者类。不满足即拒绝签发（无权）。被翻译的块不因带翻译的绑定进入块键集合。
- 读取：按 [RC-03](#rc-03-当前读取资格与缺项) 的核对顺序再核一次，因为注册可能在签发之后变化。

## 所有权、失败与生命周期

### RC-07 生产者句柄、并发、撤除与恢复

生产者为一个租户的一块登记供值后得到一个生产者句柄，用它发布新值、使当前值失效或撤销登记。登记带调用方主体、租户、生产者身份与该供给块的块声明，声明进入运行时的块声明目录（见 [RC-02](#rc-02-块声明注册与参数)）。没有带块声明的登记被拒绝。权威端口先核生产者面的登记动作，拒绝即无权。

生产者槽的身份是租户加块键。生产者身份是登记时给出的名字，独立于代际。代际由本成员在每次登记时新取，单调递增。同一租户、同一块键已有另一身份的登记时，登记被拒绝。同一身份再次登记时取得新代际，新一代替换旧一代。另一租户的同一块键独立登记，但声明摘要仍须与目录相同。撤销登记只移除本代的登记；这一代已被新一代替换时，撤销不改动任何登记。租户的增删、装配重跑与退出分别登记或撤除对应的句柄，本成员没有跨租户的全局生产者入口。这一条取代已接受条款里「一个块键只有一个生产者身份」的写法。依据：J41 与[本域目标协议](https://github.com/nemori-ai/omne-harness-lite/issues/678#issuecomment-6371505744)。

句柄带只读的租户。句柄捕获登记时的主体，但每次操作都重新经权威端口核对，不保存许可。

每次发布都带作用域引用、租户与值。发布必须同时满足：句柄的租户等于输入的租户，可信绑定确认作用域属于这个租户，权威端口对这次发布给出已授权判定，句柄是当前代际，作用域有这块的有效注册，作用域没有结束，作用域的恢复围栏已经打开。任一项不满足，发布不写值，不推进修订，不唤醒。作用域未注册与作用域已结束只在授权通过之后披露。值按作用域加块键保存，一个作用域的发布不改别的作用域的值。本成员不按块键只存一个值。

使当前值失效有两种目标：指定一个作用域，或指定句柄租户的全部作用域。指定作用域的失效与发布做同样的核对。按租户的失效先核权威端口的按租户失效动作，只选本租户、这一块键已注册且未结束的目标，再逐个目标核权。最后在一个没有 `await` 的提交段里核对全部 `current()`、目标集合版本、代际与结束状态。目标集合变了就重新求目标，或答未知，不提交过时的半批。任一目标核验失败，整批不变。成功只列本批的合法目标；确实没有目标时成功返回空表。正在恢复的作用域不参加按租户的失效，恢复完成时由待刷新标记覆盖（见 [RC-09](#rc-09-作用域结束恢复会话与恢复后供值)）。失效不给生产者别的租户的作用域。依据：J41。

作用域无关的供给块（例如宿主事实、租户元信息、当前档案）由本成员驱动供值。生产者在登记时给出一个供值回调。回调收到作用域、租户与本次供值的代租户主体。本成员在四种时点调用这个回调：

- 持有者注册该块时，对这个作用域调用。
- 生产者在持有者注册之后才登记时，对本租户每个已注册该块的作用域调用。
- 生产者调用「使当前值失效」时，对每个失效目标调用。
- 恢复会话完成之后，第一次合法的普通读取遇到待刷新标记时调用（见 [RC-09](#rc-09-作用域结束恢复会话与恢复后供值)）。

回调开始之前，本成员核对生产者面的供值动作，取得代租户主体。回调完成之后，本成员重新取得并检查当前权限，再在最终的同步段里核对作用域绑定、注册、生产者代际、作用域结束、恢复代次与取值序号。旧代、旧序号、已结束、注册已撤销或读者已结束时，回调的结果不覆盖、不披露，也不唤醒。下游来源在自己的使用点核权，本成员的检查不授权来源的远端副作用。生产者不需要知道作用域列表。

回调的答复是五种之一：

| 答复 | 本成员怎样处理 |
| --- | --- |
| 值 | 按该作用域的发布处理。值不合块声明的形状时，记缺项（`uninterpretable`）并留下安全的形状诊断，不改成未知或无值 |
| 无值 | 当前值为无值。必需块读到缺项（`no-value`），可选块标「无值」 |
| 不可用 | 缺项（`source-unavailable`） |
| 拒绝 | 整次读取拒绝（无权）。拒绝不藏在成功快照里 |
| 未知 | 未知（`source-unknown`） |

回调抛出、超时，或回执不能识别为上表的一种，本成员记未知（`source-unknown`）。

发布的值不合块声明的形状时，发布被拒绝，当前值与修订不变，不存成「内容无法解释」。生产者换代后，旧一代迟到的发布不被采用，不能覆盖新一代的值。使当前值失效把该作用域的当前值变为缺项（可选块标「无值」）。这是值的变化，视图修订前进，读者经唤醒得知。作用域无关的块另外按第三种时点重调回调，回调取回值时修订再前进一次。失效成功只确认失效，不确认之后的来源读取成功。读者读到什么以读取时的值为准，不按唤醒推断变化内容。依据：产品 [§2.2](../../../.meta_harness/design/product/runtime-context/design.md#22-块声明归语义拥有者)。登记寿命怎样落在 Cordis 归 [runtime-context-cordis-contract](../runtime-context-cordis-contract/SPEC.md)。

发布与失效没有操作身份，本成员不承诺响应丢失之后恰好一次的认回。重发是新的合法易失投影操作，可以再次推进修订、唤醒或重读来源。响应丢失时，生产者先查自己的权威值，再按当前代际重新发布或失效；读者重新取快照或变化。一次未知不说明旧值没有写入。远端适配需要写操作认回时，须另定它的操作身份与结果查询。

撤销登记立即拒绝本代的新操作，再在可配置的上界内等待本代已经开始的读取结算为明确结果或未知，然后完成本地撤除。不能取消的来源仍由来源拥有者负责，迟到的值被丢弃。旧代的撤销不移除新代。

注册修改、生产者更新、撤权、读取和请求固定可能并发。每次读取和最终发起都能解释其合法采用范围，不拼接从未合法成立的状态。正在组装的新值不能覆盖已固定的请求。当前来源变更也不能无声改回旧快照。

取消一次读取或结束一个绑定读者，对应等待与资源结束。它不证明来源变更未提交，不取消原工具或模型执行，也不删除既有历史。释放资源或运行 disposer 不撤回外部输出。取消时提交未知，原责任方继续对账。

生产者或提供者撤除后，合法重读与依赖失败由本契约承接：读取按缺项返回（[读取结果](#读取结果)），不返回旧值。已保管的不可重算事实不随实例或进程生灭消失。结构性绑定换代沿装配交接，新读当前数据不被误当作结构性换绑。

恢复需要保留本作用域的注册、参数、移除意图、自有不可重算值、作用域结束，以及足以解释旧执行的采用依据。只保存最后数据或只保存历史都不够。依据：产品 [§2.1](../../../.meta_harness/design/product/runtime-context/design.md#21-两类块供给块与状态块)、[§8](../../../.meta_harness/design/product/runtime-context/design.md#8-故障恢复和数据保护)。

持久保存的分工如下。作用域持有者保存注册、自有值、步提交与作用域结束。生产者负责 `persisted` 供给块的持久保存，并在重启后重新发布。本成员不持有耐久状态。耐久边界按产品 [§8](../../../.meta_harness/design/product/runtime-context/design.md#8-故障恢复和数据保护)：已经确认持久保存的事实在普通进程崩溃、操作系统崩溃或断电后仍可读取和解释。

供给块按声明的恢复方式回来：`persisted` 由生产者重新发布原值，`reread` 向权威来源重取并按当前资格取得，`recompute` 从当前事实重算。状态块 `checkpointed` 按最近一次步提交恢复。本成员重建之后，作用域持有者用恢复会话恢复它的作用域，再重新签发读取资格，见 [RC-09](#rc-09-作用域结束恢复会话与恢复后供值)。这一条取代已接受条款里「经 `applyCommit` 逐条重放注册与交回检查点」的恢复顺序。

恢复核对原身份与当前资格：主动移除不装回，必需信息不绕过，旧备份不复活撤销的资格。共享来源不可用时保持缺项，不用历史允许或缓存掩盖。

已发请求采用的值与本次应读的当前值分别恢复。执行换代不重发已经存在的模型或工具调用。原执行、结果、费用和原消费位置继续由原调用和消费拥有者负责。本成员只供给合法条件。

作用域结束使等待解除，不以所有独立执行物理停止为完成前提。这一条取代已接受条款里「作用域结束使业务取消生效」的写法：业务取消归协调者，本成员只解除等待并认回迟到结果。迟到结果不复活推进。真实结果和账目按原拥有者保留。任何确认消息都不授予本成员删除共享来源、自有值或历史的权力。

### RC-09 作用域结束、恢复会话与恢复后供值

#### 作用域结束

作用域的寿命状态是开放或已结束。已结束永远不回到开放。作用域结束依赖作用域持有者已经确认的提交事实。本成员不另建耐久的结束日志。依据：J18。

| 情形 | 结果 |
| --- | --- |
| 只结束作用域，首次 | 可以在任何围栏状态下应用。不制造注册，注册修订不变，视图修订前进一次。解除该作用域的等待，封住推进 |
| 已结束的作用域上另一笔已确认的只结束作用域 | 记下它的成功结果，不再推进修订 |
| 注册决定或步提交带作用域结束标记 | 整笔完整核对之后原子应用。核对失败时整笔不改，不只应用结束 |
| 已结束的作用域上未见过的注册决定或步提交 | 拒绝（`scope-ended`） |
| 已结束之后的签发、绑定、读取与发布 | 拒绝（`scope-ended`），只在授权通过之后披露 |

只结束作用域与恢复完成共用最终提交边界。新的结束不能被较旧的恢复材料覆盖。

#### 恢复会话

一个作用域在本实例上有一个恢复披露围栏，状态是关闭或打开。首次观察到一个作用域时，以及进程重建之后，围栏默认关闭。围栏关闭时，本成员不签发资格、不建立读者、不披露投影，新的注册决定与步提交返回「恢复未完成」。首次正常创建也先经恢复会话：空作用域用空的恢复材料完成，之后才接受普通的业务推进。

恢复分两步，由持有者调用：

1. `beginReplay`：输入作用域、租户、持有者的耐久检查点（空作用域为空）与被取代的恢复引用。本成员在授权通过之后，于一个没有 `await` 的同步段里核对 `current()`、作用域绑定、被取代的引用与当前恢复代次，然后关闭围栏，生成恢复引用。同一同步段使该作用域的旧资格、读者、游标与未完成的供值失效，并解除等待。旧资格此后答无权，完成恢复也不使它重新有效。恢复不改变别的作用域。
2. `finishReplay`：输入恢复引用与一份完整恢复材料。本成员捕获材料，构建一份不披露的暂存投影：按注册序列恢复最终注册，装入应保留的检查点值，应用结束。它不调用生产者，不执行 reducer 的更新，不签发资格，也不触发原业务副作用。

恢复引用是本实例产生的不透明引用，绑定作用域、租户与恢复代次。它不是凭据，不能跨实例使用，也不能用来访问别的作用域。进程关闭之后它失效，重建从空开始，持有者重新核对全部耐久事实。陌生或无权的引用先按无权处理，只有已经通过目标核验的本作用域旧引用可以答「恢复冲突」。

恢复材料有三部分：

- 注册：检查点以内本作用域全部注册提交的耐久顺序，含移除意图。每项是原提交身份加注册变更。
- 检查点值：最终注册中应恢复的每个 `checkpointed` 状态块恰好一次，带它最近一次原步提交的全值，更新清单为空。同一提交、同一步的块合为一组。同一提交身份不能出现不同的步或冲突的块。不同块的最近一步可以不同。`untracked` 状态块与供给块不放入。
- 结束：截至检查点已经确认的作用域结束；没有结束为空。结束的提交身份可以与注册或检查点的原提交身份相同，它是该提交的事实投影，不是另一笔业务操作。

材料不复制持有者的日志类型。持有者从自己的完整耐久事实构造材料，并经权威端口证明原身份、每块的最新值、全部注册与移除，以及结束的覆盖。本成员核对形状、注册链、最终块声明与恢复值，但不从一个空数组猜测覆盖是否完整。恢复材料不是普通请求：缺少原更新、未恢复的 `untracked` 状态块与未应用的待处理更新都不产生「提交冲突」。

本成员向权威端口的持有者面提交开始与完成两种动作。动作带本成员填入的上一个检查点、当前修订、已知的结束，以及本实例普通操作已经应用的提交身份与完整输入摘要的序列。持有者在开始时核对检查点不回退、取代关系成立；在完成时核对材料覆盖检查点的全部所需事实，也覆盖本成员已知的成功提交与结束。本成员不从身份文本比较日志顺序。具体的日志编码不进入本成员。

开始恢复的结果：

| 输入与当前状态 | 结果与后果 |
| --- | --- |
| 本实例没有恢复会话，被取代的引用为空 | 持有者确认检查点，生成恢复引用，围栏关闭 |
| 同一完整输入重试，原会话仍是最新 | 再核权限，返回原恢复引用。已完成的会话也认回，不另关围栏，也不换代次 |
| 当前已有会话，请求显式取代它 | 持有者核对新检查点等于或晚于旧检查点，且覆盖本实例已知的提交。生成新引用，旧引用失效。围栏保持关闭或重新关闭 |
| 同一检查点的新尝试 | 必须取代当前引用，允许更换恢复材料，仍核完整覆盖 |
| 省略或写错被取代的引用；旧引用的开始重试而已有后继 | 恢复冲突（`replay-conflict`），不撤销后继 |
| 检查点回退，或持有者确认与已知提交冲突 | 检查点冲突（`checkpoint-conflict`），不开始新会话 |
| 权威端口或可信绑定不可用或未知 | 不可用或未知，不开始新会话。已经关闭的围栏不变为打开 |

本成员不提供「取消后恢复旧的就绪状态」。调用方中止、超时或失联时，最新的未完成会话保持关闭。调用方继续同一引用，或明确取代它开始新的尝试。

完成恢复的结果：

| 交错 | 必须行为 |
| --- | --- |
| 最新的活动会话，材料完整且作用域开放 | 安装之后打开围栏，返回就绪（开放）。持有者再签新资格 |
| 最新的活动会话，已知结束或材料确认结束 | 安装已结束的投影，返回就绪（已结束），围栏不打开，新资格被拒绝 |
| 本实例已结束，材料的结束为空 | 检查点冲突，不以恢复重开作用域 |
| 同一引用、相同完整材料，重试已经成功的完成 | 再核权限与最新会话身份，返回保存的就绪回执，不把原回执当当前可读的保证 |
| 同一引用、不同材料，重试已经成功的完成 | 恢复冲突，不改变已安装的结果 |
| 同一引用，重试未成功的完成 | 重新核对材料与覆盖。失败不预占成功材料的指纹，调用方可以修正材料重试 |
| 已有取代它的会话，或实例不同 | 恢复冲突或无权，不安装旧材料 |
| 核验之后出现新的结束或普通成功事实 | 最终版本核对失败，返回检查点冲突，围栏保持关闭。持有者改用覆盖新事实的会话 |
| 材料超过配置的容量，或暂存能力不足 | 不可用（原因 `replay`），诊断 `replay-capacity`，围栏保持关闭，不截断事实 |

最后，本成员在一个没有 `await` 的同步段里重新核对 `current()`、绑定、最新恢复引用与代次、已知结束与成功提交表的版本。核对通过才原子替换投影，为开放的投影建立待刷新标记，记下这次恢复的材料指纹与就绪结果。这一段不调用来源。注册修订来自完整注册链，不低于本实例已知已应用的注册修订。视图修订不回退：安装使可观察的投影改变时前进一次，否则保持。已完成会话的重试不再安装，也不推进修订。旧读者已经失效，本成员不把从零构造的计数当作旧读者可以继续使用的修订。

最新活动会话的构建、核对或安装失败时，旧的完整投影只作内部事实，围栏保持关闭，不披露旧值。对已完成会话的重试，以及对旧引用或无权引用的拒绝，不重新关闭当前已经就绪的围栏，不撤销之后签发的资格，也不改变后继会话；它们只返回对应的结果。只有成功的新开始或正常的作用域结束能在这些路径上改变当前的开放状态。

本成员的提供者必须有明确且可配置的恢复材料与暂存容量上限，构造时拒绝非法上限。输入快照的计量与复制也受这个上限保护，提供者不先无限复制再检查。容量不足时，持有者或宿主提供足够容量后重试，或在新实例上完整恢复。持有者不省略注册、移除、结束或旧的成功事实，不用分页截断冒充完整材料。具体默认值归提供者。开始恢复的小型元数据容量不足也答不可用（原因 `replay`），不产生成功的恢复引用。

正常的普通提交成功之后不另调用完成恢复。持有者在一次就绪之后遇到「顺序不符」时，以新的检查点开始取代旧会话的恢复会话，完整恢复到新检查点，再用原提交的完整输入重试。原提交此前已经应用则认回；此前只有「顺序不符」则重新核对。恢复材料中的检查点值更新清单为空，原步提交带有更新，两者分别按恢复材料与普通请求判等，因此不冲突。恢复已经覆盖、而本实例没有普通成功记录的旧请求，持有者的提交授权只允许仍应增量应用的事实，不重新施加旧增量。已覆盖注册的依据修订失配继续是「顺序不符」，调用方把恢复完成视为投影已追平。

系统维护者可以在持有者权威明确许可后恢复原持有者的事实，即使原用户已经撤权。这项权限只恢复投影。它不恢复普通资格，不签代租户凭据，也不启动来源读取。签发、绑定、读取与供值仍逐次核对普通使用权限。

#### 恢复后的普通供值

完成恢复安装开放投影时，本成员为其中的供给块登记待刷新标记。标记的身份包含作用域、块键、当前生产者代际与恢复代次。声明或生产者还没有到场的登记也保留待刷新意图，到场时按真实声明处理。标记只说明供给值尚未恢复，不是取值许可，不启动后台工作，也不是新的供给事实。恢复中被跳过的登记与按租户失效都由这次标记覆盖，本成员不逐条重演历史的来源调用。已结束的投影不建立待刷新意图。

恢复之后第一次合法的普通快照、读取或变化，对这次读取涉及的 `stable` 与 `per-step` 供给块发现标记时，本成员在完成读者与逐块的权限核对之后发起供值。只有系统恢复授权的调用不进入这条路径。调用来源之前，本成员取得该租户生产者的本次供值授权与真实主体，核对 `current()`、读者资格、作用域开放、注册、代际与恢复代次；响应之后按回调协议再次核权与核对序号，再更新值与本次读取。普通授权核对失败时不调用来源。`per-request` 块仍按每次读取供值，不变成缓存的稳定块。

每次普通读取对每个涉及的作用域与块键最多发起一次有界的刷新尝试。并发读取各自持有授权与取值序号。提供者只有在保留各自当前资格与披露核对时，才可以合并来源读取，不能借用别人的成功授权。正常的发布、失效、注册改变与刷新共同推进该作用域与块键的供给序号。成功的发布清除本代的标记，早先的回调不能再覆盖它。超时或取消不允许迟到的值绕过代次或序号。本成员的未知只结算本次等待，不声称物理来源读取已经取消。

有效的值或合法的无值完成这一轮刷新并清除标记；值仍须通过 schema。来源不可用、未知、拒绝或值无法解释，分别返回缺项、未知、拒绝与缺项（`uninterpretable`），并保留待刷新意图。之后独立的普通读取、有效的生产者后登记或普通失效可以再次触发。提供者用可配置的等待上界、并发与重试间隔策略限制代价，等待策略不把失败转成成功。

`scoped: true` 且没有回调的登记，本成员不制造回调或默认值，继续按缺项报告。生产者仍按原持久或重算责任用合法的发布交回值，成功发布清除本代的标记。换代、注销、结束或新的恢复代次使旧的在途任务不能完成新的标记。

## 组合与验证

### RC-08 缓存、观测与遥测

缓存只是性能手段，不代替资格核对。命中缓存的读取仍按当前读取资格核对，缓存不提供超过当前资格的数据。观测与遥测不泄露 `eligibility-checked` 块的值；诊断只带块键、修订、来源与结果种类。来源协议失约的诊断由适配或宿主的拥有者接收，不在无权读者的结果中带出原值、账目或别的租户的材料。注册与当前值读取、变化通知与模型投影的读数由集成方采集与拥有，本成员不规定数值。依据：产品 [§8](../../../.meta_harness/design/product/runtime-context/design.md#8-故障恢复和数据保护)、系统页 [观测与性能责任](../../../docs/architecture/runtime/runtime-context.md#观测与性能责任)。

| 取消与迟到 | 取消读取只结束等待与资源，不证明来源变更未提交；作用域结束后迟到结果不复活推进 | RC-07 |
| 执行换代 | 不重发已经存在的模型或工具调用，不重记原费用 | RC-07 |
| 状态块越权更新 | `reduceStep` 对非写者类的更新、指向供给块的更新给出拒绝（无权），持有者不写进步提交并退回提出者；`applyCommit` 收到含被拒更新的步提交时整笔拒绝（无效），投影不变 | RC-05 |
| 失败步的成功更新 | 保留为待处理，不进本步提交，不丢弃 | RC-05 |
| `singleWriterPerStep` 冲突 | 按到达持有者的顺序判定第二个写者并拒绝；被拒的更新带原因退回提出者 | RC-05 |
| `untracked` 状态块 | `applyCommit` 带「执行结束」标记后失效，恢复时不读回 | RC-05 |
| 变化材料拉取 | 持有者用游标拉取再调 `diffForReminder`；前值来自持有者保留的上一份按资格过滤的快照；持有者重启或游标作废后的第一份变化材料不带前值；唤醒丢失后下一次拉取补齐 | RC-04 |
| 必需项的绕过 | 更新把必需改为可选、作用域创建后增加必需项都被拒绝 | RC-02 |
| 缓存、观测与遥测 | 缓存命中仍核当前资格；诊断与遥测不带 `eligibility-checked` 块的值 | RC-08 |
| 带翻译的绑定 | 读者拿到自己的形状与来源证据；按集成方的消费者类核来源块，读者不能按原形状读该块；翻译失败按缺项 | RC-03、RC-06 |
| 未获准的读者读带翻译的需要 | 这条绑定不在读者资格的需要绑定集合里时，读取拒绝（无权），读不到翻译后的值 | RC-03、RC-06 |
| 读者消费者类的核对 | 块键集合里有不允许该消费者类的块时拒绝签发；`judgeBinding` 不核读者的消费者类；注册在签发后变化时，读取按当前注册再核 | RC-03、RC-06 |
| 子作用域遮蔽 | 同键子级值遮蔽父级；父级缺失时沿链读到；跨租户的父级值不被继承 | RC-03 |
| `per-request` 块 | 不进快照，不产生变化材料；完整快照与变化的每次读取都另带按读者资格过滤的当前值，取不到值时按读取结果表落位 | RC-02、RC-04 |
| 初次与压缩后读取 | 完整快照在场，私有块仍排除 | RC-04 |
| 作用域结束 | 没有注册的只结束作用域推进视图修订一次而注册修订不变；另一笔结束不再推进修订；带结束的注册或步提交整笔原子应用；结束之后未见过的推进为 `scope-ended`；已结束永不回到开放 | RC-09 |
| 恢复会话 | 首次恢复与同一实例的补齐；开始与完成的重试和中断；取代与恢复冲突；检查点冲突；容量不足不截断事实；开始使旧资格与读者失效；已完成会话的冲突不关闭现行围栏；系统恢复不恢复用户权限 | RC-09 |
| 恢复后供值 | 完成恢复只建立待刷新标记，不调用来源；之后的普通读取取回稳定块的值，没有新的失效也能取回；失败保留意图，之后的读取可以重试；并发刷新的序号不让迟到值覆盖新值 | RC-09 |
| 持久确认后普通故障 | 进程崩溃、操作系统崩溃和断电三种故障下，`persisted`、`reread`、`recompute` 三种恢复方式与 `checkpointed` 状态块分别有相称证据，不只用重启测试 | RC-07 |
| 重建后的恢复顺序 | 持有者开始恢复会话，交回完整恢复材料，再重新签发资格；本成员不恢复资格 | RC-03、RC-07、RC-09 |

### 明确缺项

- 注册、当前读取和恢复的一致协议的精确形状，归产品 [CONTEXT-M01](../../../.meta_harness/design/product/runtime-context/design.md#context-m01)。
- 需要怎样声明、更新怎样随结果携带，归产品 [CONTEXT-M04](../../../.meta_harness/design/product/runtime-context/design.md#context-m04) 与各消费者契约的拥有者。
- 工作区指导的首次访问判据，归产品 [CONTEXT-E02](../../../.meta_harness/design/product/runtime-context/design.md#context-e02)。本成员只供给当前值，不拥有加载规则。
- `current()` 同步前提的真实兑现：撤权、原工作失效与本成员最终提交共用串行边界的权威适配器，以及 Request Context 与 Runtime Context 之间的当前状态同步桥，都不由本成员提供。身份拥有者的首批能力不提供这座桥。它由实际资格与组合拥有者兑现，具名剩余责任交 [#677](https://github.com/nemori-ai/omne-harness-lite/issues/677) 登记。在桥兑现之前，依赖它的真实组合路径不开通。
- 两个权威端口的真实适配器归应用装配。本成员只定义端口与判定形状，`./testing` 的替身不证明真实授权。
- 窗口用量块的真实供值适配不在本成员。适配器从回调的合法主体取得普通 `Access`，把快照中的租户与作用域作为目标调用 Request Context 的用量查询，按 Request Context 的结果映射到回调的五种答复。值域、解码与比例归 [request-context-contract](../request-context-contract/SPEC.md)。
- 本成员已实现值类型、读取结果、游标作废、核心纯操作、声明摘要和两个解码函数。精确形状归 [src/index.ts](src/index.ts)，套件与非耐久替身归 `./testing`。这些资源不替代真实机制的并发与恢复验证。
- 三条 Cordis 机制读数已在采用的 Cordis 4.0.4 上由定义成员本地测试固定；尚未登记共同 basis，不能据此扩大共同采用。证据与剩余责任列在 [runtime-context-cordis-contract/docs/cordis.md](../runtime-context-cordis-contract/docs/cordis.md)。
- 唤醒载荷是否受对象存在性披露规则约束，待本契约拥有者确认。现在的写法是载荷只带作用域引用与视图修订，不带块键与值（[runtime-context-cordis-contract](../runtime-context-cordis-contract/SPEC.md)），据此认为它不披露块的存在；监听者能否从修订前进推断某块存在，尚未裁定。
- 唤醒丢失后，持有者最迟何时补拉变化没有上界。[RC-04](#rc-04-读取时点观察与变化材料) 只要求下一次拉取补齐。这个上界与持有者的恢复、保留上一份快照两项义务一起，归作用域持有者的契约（[#580](https://github.com/nemori-ai/omne-harness-lite/issues/580)）。
- 自定义的恢复、代际替换与并发协议需要行为模型与关键性质检查（[验证说明](../../../docs/verification.md)）。正式模型尚未进入本成员的 `verification/models/`，相应机制路径保持未验证。

这些缺项不允许降低已定的访问、历史和恢复责任。纯函数和非耐久替身的测试不证明真实机制的并发、断电耐久或性能。作者自检和结构检查不授予接受。

声明比较使用 `declarationDigest`：结构元数据按键排序后生成规范 JSON，再计算 SHA-256。schema 与 reducer 函数体不入摘要；可选 schema 的有无属于结构元数据。持有者显式给出注册变更的 `creating`，同次创建可以包含多笔提交，不从当前表是否已有注册推断创建状态。
