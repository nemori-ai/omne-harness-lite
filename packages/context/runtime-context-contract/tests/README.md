# Runtime Context 测试

本目录验证根入口、纯函数、导出清单，以及 `./testing` 契约套件。

## 运行

在仓库根通过测试名额运行：

```sh
./scripts/with-test-slot.sh pnpm turbo run build typecheck test --filter=@omne-harness/runtime-context-contract
```

先构建，再核对 `tests/fixtures/exports.json` 与公开接口页。导出核对调用共享的 `tools/dev-flow` CLI，产品源码不依赖工具成员。

## 覆盖与限制

套件返回用例列表，不绑定 Vitest。调用方提供新鲜实例的构造函数 `subject(ports)`、两个合法租户和主体；套件用自己的权威端口与可信绑定替身构造实例，从而控制每次核对的答复。关闭控制和观察链保留数可选，对应场景缺少控制时报告 NotApplicable。非耐久替身明确 `durability: 'none'`。

覆盖作用域、租户、资格撤销和重签、注册提交身份与顺序、生产者代际、发布形状、缺项、变化游标、逐请求块、翻译与状态块提交。权威组覆盖核对顺序、未绑定与错租户同为无权、`current()` 答假、不可用与未知的原因、输入租户与主体租户不同、按租户的生产者槽与按租户失效。恢复组覆盖围栏、开始与完成恢复的认回、取代与冲突、作用域结束、容量不足与恢复后的待刷新供值。纯函数测试另核对解码、绑定形状、更新授权与合并、异步 schema 拒绝和前值披露。

替身不证明真实来源、持久保存、断电恢复、来源超时、取消竞争或在途读取结算。真实实现及组合仍须兑现 SPEC 的相应义务。

公共套件另保护：旧读者沿资格重签链仍固定消费者类，当前注册已移除时按披露规则拒绝而不是以缺项冒充成功。专门坏实现分别模拟跨类读取和 success-plus-missing，公共用例必须拒绝它们。跨 realm Promise 使用 Node 的成熟 Promise 判定，异步 schema 仍是带路径的定义拒绝，同步未知异常保留原对象上抛。

风险补测通过公开操作验证：无声明时拒绝坏 need、跨块 key 和非法 integrator；子级可继承同租户父值与来源证据，无可用祖先登记时保留缺值，跨租户值不进入读出；资格撤销后旧游标也不能读取变化。过期游标继续由公共保留期用例覆盖。unknown 作用域入口另验证完整父链、未知键与循环拒绝的定位。

来源生命周期测试使用真实非耐久替身，检查稳定来源失败后的未知与恢复、明确不可用和无值的区别、被替换代际的晚到成功与失败，以及逐请求来源的未知、缺项、无值、形状错误和撤除。它们不证明真实来源超时、持久性或取消结算。
