# @omne-harness/runtime-context 行为规格

状态：机制实现成员，`draft`，已有运行实现。本成员实现 Runtime Context 的供给机制：作用域表、注册表、生产者表、资格表、当前投影、观察链、恢复会话与读取缓存。公开行为归 [runtime-context-contract SPEC](../runtime-context-contract/SPEC.md)。本页只写实现真实承担的本地行为，不重复契约条款。实现以契约 `./testing` 替身的分解为起点移植，再补上替身没有的生产责任（设计依据：#502 的 P4 GATE-RC 候选与其[决策记录](https://github.com/nemori-ai/omne-harness-lite/issues/502#issuecomment-6561318057)）。整套 `runtimeContextConformance` 对本成员的机制实例通过。

## 范围与依据

本成员与 Cordis 无关（[IC-4](../../../docs/architecture/cordis-integration-conventions.md#ic-4)）。根入口导出一个工厂 `createRuntimeContext`，它是 Runtime Context 唯一的机制工厂。[runtime-context-cordis](../runtime-context-cordis/SPEC.md) 的根入口不导出任何东西。不装配 Cordis 的独立调用方直接从本成员取工厂。Cordis 绑定、isolate、intercept 配置和唤醒事件归 [runtime-context-cordis](../runtime-context-cordis/SPEC.md)。

工厂的输入如下：

| 输入 | 内容 |
| --- | --- |
| `trust` | 契约的 `RuntimeContextTrust`：权威端口 `authority` 与可信绑定来源 `bindings`。必需。本成员没有免核验模式（[通用权威端口](../runtime-context-contract/SPEC.md#通用权威端口)） |
| `config` | 七个上限，全部可省略，省略即取初值。初值只是配置初值，见下表 |
| `onChange` | 可选。变化出口，见[变化出口](#变化出口) |
| `diagnose` | 可选。诊断出口，见[诊断](#诊断) |

| 配置字段 | 含义 | 初值 | 合法值 |
| --- | --- | --- | --- |
| `retention` | 游标最多落后多少个视图修订，超过即作废 | 64 | 非负安全整数 |
| `replayCapacity` | 一份恢复材料的条目上限：注册、检查点块与结束 | 10000 | 非负安全整数 |
| `supplyBoundMs` | 一次来源调用或供值回调的等待上界，超过按未知结算 | 30000 | 0 至 2147483647 |
| `settleBoundMs` | 撤销登记与关闭等待在途操作结算的上界 | 1000 | 0 至 2147483647 |
| `readCacheEntries` | 读取缓存的条目上限，0 表示不缓存 | 256 | 非负安全整数 |
| `refreshConcurrency` | 恢复后供值同时在途的来源调用上限，跨作用域计数 | 16 | 至少 1 的安全整数 |
| `refreshRetryMs` | 恢复后供值失败之后，多久内的读取不再调用来源 | 0 | 0 至 2147483647 |

构造时校验全部上限。非法值使工厂抛出 `RangeError`，消息点名字段。上限的唯一判定在 `resolveRuntimeContextConfig`，runtime-context-cordis 的配置 Schema 调用它，不另写一份。

输出是实现契约三面八操作的机制实例，另有 `close()`。实例不标 `durability`：本成员不持有任何耐久状态。注册修订的唯一权威是作用域持有者的耐久提交，本成员的表是按提交顺序应用的投影（[注册修订与提交顺序](../runtime-context-contract/SPEC.md#注册修订与提交顺序)）。进程重建之后，持有者用恢复会话恢复每个作用域，生产者重新登记（[IC-19](../../../docs/architecture/cordis-integration-conventions.md#ic-19)）。

## 结果与不变量

### 表与投影

| 表 | 键 | 内容 | 谁改 |
| --- | --- | --- | --- |
| 作用域表 | 作用域引用文本 | 可信绑定确认后记下的租户；寿命（开放或已结束）；恢复围栏（打开或关闭）与恢复代次；当前注册修订；视图修订；投影版本；游标代次；待刷新标记与上次刷新失败的时刻；按块键的供给序号；已应用普通提交的版本计数 | 持有者面、恢复会话、生产者面 |
| 注册表 | 作用域加块键 | 需要绑定、参数值、是否必需、注册修订 | `applyCommit` 与恢复安装 |
| 已应用提交表 | 作用域加提交身份 | 普通提交的完整输入、摘要与结果 | `applyCommit` |
| 块声明目录 | 块键 | 全系统一份声明。经生产者登记、持有者注册状态块或恢复材料进入 | 生产者面、持有者面、恢复会话 |
| 生产者表 | 租户加块键 | 生产者身份、代际、声明、作用域无关块的供值回调、本代在途调用 | 生产者面 |
| 当前投影 | 作用域加块键 | 当前值或替代它的失败、块修订、来源代际 | 发布、回调、步提交、恢复安装 |
| 资格表 | 资格身份 | 资格内容；有效、被取代（记取代者）或已撤销 | 持有者面、恢复会话 |
| 恢复会话 | 恢复引用 | 作用域、恢复代次、检查点、被取代的引用、已完成时的材料指纹与就绪回执 | 恢复会话 |
| 读取缓存 | 见[读取缓存](#读取缓存) | 一次快照里按资格过滤后的稳定条目 | 读者面 |

当前投影按作用域链查找：先本作用域，再父作用域，同键子级遮蔽父级。父级的每一跳独立核对可信绑定与租户（[RC-03](../runtime-context-contract/SPEC.md#rc-03-当前读取资格与缺项)）。查找一个块键的成本与链长成正比，不随历史长度增长。

`per-request` 块不存值。它在当前投影与观察链里都没有条目，每次读取向生产者取值。

### 本地行为

访问核对：

- 每个带目标的入口按契约的顺序核对：先权威端口，再可信绑定来源，最后作用域的状态、注册、代际与恢复围栏。拒绝、未绑定与租户不同对外一律是无权，不披露真实租户。
- 每次对外部端口或来源的等待之后，本成员先查实例是否已关闭。之后到最终同步段之间没有 `await`。最终提交或披露之前同步调用 `current()`，答假即无权。
- 每个公开入口在第一次外部调用之前捕获本操作的输入快照。之后只使用这份快照。
- 一个作用域第一次被确认时，本成员记下可信绑定确认的租户。可信绑定已匹配、而记下的租户与可信事实冲突时，`applyCommit` 答无效（`tenant-mismatch`），`issueEligibility` 答无权，读取答无权。

注册与提交：

- `applyCommit` 按作用域加提交身份去重。同一身份、相同完整输入的重试返回原结果；不同输入答无效（`commit-conflict`）。注册决定依据的修订等于当前修订时应用并前进；依据不等且身份未见过时答无效（`out-of-order`）。步提交按提交身份幂等，不与注册修订比较。
- 恢复围栏关闭时，新的注册决定与步提交答拒绝（`replay-incomplete`）。已结束的作用域上未见过的推进答拒绝（`scope-ended`）。
- 同一块键带来摘要不同的声明，登记或注册答无效。

生产者与供值：

- 生产者槽是租户加块键。同一槽另一身份的登记被拒绝（`other-producer`）。同一身份再登记取新代际，替换旧一代：本租户每个注册了该块的作用域删掉旧值、前进供给序号、使游标作废，作用域无关的块重新供值。另一租户的同一块键独立登记。
- 声明进入目录或替换目录里同键的声明对象时，本成员按新声明核对全部租户里该块键已有的注册。不相容的注册记诊断，该块在那个作用域读到缺项，直到持有者重新注册。
- 发布按契约的八步核对。旧代的发布答拒收（`stale-generation`）并记诊断。值不合声明形状时答拒收（`shape`），当前值与修订不变。
- 供值回调在开始之前核生产者面的供值动作，结束之后重新核权，再在最终同步段核对作用域绑定、注册、代际、结束、恢复代次与供给序号。任一项不成立时结果被丢弃并记诊断（迟到供值）。回调抛出、超时或回执不合法记未知。
- 使当前值失效把值变为缺项并前进视图修订。作用域无关的块再调用一次回调，取回值时修订再前进一次。按租户的失效在一个没有 `await` 的提交段里核对全部目标，目标集合变化时重求一次，再变则答未知。

读取：

- 每次读取按契约 [RC-03](../runtime-context-contract/SPEC.md#rc-03-当前读取资格与缺项) 的六步核对：资格状态、权威端口读者面、可信绑定、作用域状态、两个集合、读者的消费者类。另比较本实例记下的作用域租户与资格租户。
- 快照按资格的块键集合逐块给出值、「无值」或缺项，另带逐请求块的当前值。`read(needs)` 全有或全缺。带翻译的绑定在读取时翻译，翻译抛出或不合需要形状即缺项，不返回部分结果。
- `changes` 在游标代次变化、资格被重签、游标落后超过 `retention` 时答游标作废，读者重取完整快照。
- `bind` 接受一个可选的第二参数：Cordis 调用方在 intercept 配置里声明的消费者类。给了这个参数时，声明的类与资格的类不同，或调用方没有声明，`bind` 答拒绝（`callerMismatch`）。这项比较放在全部访问核对之后、建立读者之前，所以它不向无权的调用方披露任何东西。它是一致性检查，不是访问控制。不给这个参数时不比较。

### 读取缓存

读取缓存只是性能手段，不代替资格核对（[RC-08](../runtime-context-contract/SPEC.md#rc-08-缓存观测与遥测)）。

| 项 | 规则 |
| --- | --- |
| 位置 | 机制的读取路径里，位于六步核对之后。缓存不保存许可，也不缓存权威端口或可信绑定的答复 |
| 缓存什么 | 一次快照里每个非 `per-request` 块的条目：值（带来源证据）、「无值」或缺项。拒绝、未知、游标与逐请求块都不进缓存 |
| 键 | 可信绑定确认的租户、作用域引用文本、当前资格身份（被取代时沿取代者解析）、当前注册修订、作用域的投影版本。命中要求五项完全相同 |
| 投影版本 | 按作用域保存的单调计数。不变量：任何可能改变该作用域任一过滤后读取输出的变更，都推进该作用域的投影版本，或使读取绕过缓存。推进点是：每次视图修订前进（值、注册、结束、失效、撤销登记、步提交）；声明进入目录或替换同键声明对象时，全部租户里注册了该块键的作用域；生产者换代删掉旧值的作用域；恢复会话开始与恢复安装 |
| 绕过 | 作用域带父引用的读取；资格块键里有带待刷新标记的块；配置为 0 |
| 命中路径 | 完成六步核对，按键查缓存，命中则取出稳定条目，另向生产者取逐请求块，披露之前同步调用 `current()` 并核对资格与作用域状态 |
| 容量 | `readCacheEntries` 条，按最近使用淘汰 |
| 显式释放 | 撤销资格、重签取代、恢复会话开始、作用域结束与实例关闭时删除相关条目。这只为释放内存，正确性不依赖它 |
| `read(needs)` | 键相同的条目存在时，按块键取用其中的条目，翻译照常执行。它不写入缓存 |

声明在进入目录之前，读取资格里含该块键的读取一律答无权，所以不会有条目在声明到场之前进入缓存。

### 恢复会话

恢复会话按契约 [RC-09](../runtime-context-contract/SPEC.md#rc-09-作用域结束恢复会话与恢复后供值) 实现：`beginReplay` 关闭围栏、换恢复代次、撤销本作用域的全部资格；`finishReplay` 构建不披露的暂存投影，在最终同步段核对之后原子安装。

恢复材料的检查点值只放已有步提交的 `checkpointed` 状态块。已注册、还没有步提交的 `checkpointed` 块可以缺席。本成员核对形状、注册链、最终声明与恢复值，不要求每个已注册的 `checkpointed` 块都有检查点值，也不从空数组推断覆盖是否完整。覆盖由持有者的权威在完成恢复时核对（契约 RC-09「恢复材料」与「开始与完成两种动作」两段）。这样的块恢复之后没有值：必需块读到缺项（`no-value`），可选块标「无值」，与重启之前、第一次步提交之前的读取结果相同。之后的步提交照常写入值。

### 恢复后的普通供值

恢复安装开放投影时，本成员为其中的供给块建立待刷新标记。恢复之后第一次合法的普通读取遇到标记时，在全部读取核对之后发起一次有界的供值。本成员承担契约要求的代价限制：

- 同一作用域同一块键的标记同时只有一次来源调用。并发读取加入这一次调用，各自仍做自己的资格核对与披露核对。
- 跨作用域同时在途的刷新调用不超过 `refreshConcurrency`。超过时这次读取不调用来源，该块答未知（`source-unknown`），标记保留。
- 一次刷新失败之后，`refreshRetryMs` 之内的读取不再调用来源，按已存的失败落位（缺项、未知或拒绝），标记保留。初值 0 表示每次读取都可以重试。
- 有效的值或合法的无值清除标记。来源不可用、未知、拒绝或值无法解释保留标记。

### 变化出口

工厂接收可选回调 `onChange(scope, revision)`。某个作用域的视图修订每前进一次，本成员在写入完成之后同步调用它一次，传入作用域引用与新的视图修订。回调抛错时本成员记诊断（`change-outlet-failed`），不回滚已经完成的写入。实例关闭之后不再调用它。[runtime-context-cordis](../runtime-context-cordis/docs/cordis.md#按作用域过滤的唤醒) 用它派发唤醒事件。独立调用方自己决定怎样接这个回调。

### 诊断

诊断事件是封闭集合：旧代发布、迟到供值、供值超时、供值值无法解释、不相容注册、变化出口抛错、恢复容量不足、读取缓存的命中、未命中与淘汰、恢复后供值被推迟（并发上限或重试间隔）。事件只带块键、修订、代际与结果种类，不带块值、作用域引用、租户或主体（[RC-08](../runtime-context-contract/SPEC.md#rc-08-缓存观测与遥测)）。诊断出口抛错时本成员忽略它，结果不变。

## 所有权、失败与生命周期

| 事物 | 拥有者 | 失败时 | 结束 |
| --- | --- | --- | --- |
| 机制实例与全部表 | 调用工厂的一方 | 进程失败即丢失，由持有者的恢复会话与重新签发、生产者重新登记重建 | `close()` |
| 生产者句柄 | 生产者 | 旧代发布被拒收 | `dispose`：立即拒绝本代新操作，在 `settleBoundMs` 内等本代在途的供值调用结算，然后只撤除本代登记。本代已被替换时不改动登记。撤除之后依赖该块的读取读到缺项（`producer-withdrawn`），不读到旧值。实例已关闭时立即返回 |
| 绑定读者 | 建立它的集成方 | 资格撤销后读取答无权 | 读者结束或实例关闭 |
| 读取资格 | 持有者签发，本成员保管 | 撤销在下一次读取生效 | 撤销、重签取代、恢复会话开始或实例关闭 |

实例关闭（`close()`）按下列顺序进行，重复调用返回同一次关闭：

1. 拒绝新请求：此后每个入口答关闭（`closed`；生产者面为拒收 `closed`）。
2. 使全部绑定读者结束。
3. 取消在途的等待：正在等权威端口、可信绑定来源或供值回调的操作立即结束等待。等待端口的操作答关闭，等待来源的供值按丢弃处理。本成员不声称物理来源调用已经停止。
4. 在 `settleBoundMs` 内等全部在途操作结算，包括持有者面、生产者面与读者面的操作，不只等读取。
5. 释放全部表与读取缓存。

关闭第 1 步之后，任何在途操作的最终同步段都答关闭，不答成功。例如正在等权威端口的 `finishReplay` 不安装投影，`applyCommit` 不应用提交，`issueEligibility` 不签发资格。在途读取结算为关闭、未知或缺项，不结算为成功。关闭不撤回已经交给持有者的变化材料，也不撤回任何外部效果。

进程崩溃后，本成员没有东西可恢复。重建顺序如下：

1. 持有者对每个作用域开始恢复会话，交回完整恢复材料（注册链、已有步提交的 `checkpointed` 块的检查点值、结束），完成恢复。
2. 持有者重新签发资格。本成员不从任何地方恢复资格。
3. 生产者重新登记。`persisted` 块由生产者重新发布。作用域无关的 `reread` 与 `recompute` 块由第一次普通读取经待刷新标记供值。
4. 读者重新 `bind` 并取完整快照。

| 恢复方式 | 谁触发 | 恢复之前读到什么 |
| --- | --- | --- |
| `persisted` | 生产者重新登记后重新发布 | 必需块记缺项，可选块标「无值」。本成员不用旧值填充 |
| `reread`、`recompute`（作用域无关） | 恢复后第一次普通读取遇到待刷新标记 | 刷新失败按读取结果表落位，标记保留 |
| `scoped: true` 且没有回调 | 生产者按原责任重新发布 | 缺项。本成员不制造回调或默认值（契约 RC-09「恢复后的普通供值」） |
| `checkpointed` 状态块 | 恢复材料的检查点值 | 没有步提交的块按[恢复会话](#恢复会话)的读法缺席 |

## 组合与验证

| 承诺 | 位置 |
| --- | --- |
| 三面操作、读取结果种类、缺项语义、注册修订与提交顺序、恢复会话 | [runtime-context-contract SPEC](../runtime-context-contract/SPEC.md) RC-01 至 RC-09 |

| 持有者的耐久保存、步提交与恢复材料的覆盖核对 | 持有者的契约，不在本组 |

本成员不覆盖：持久化、跨进程一致性、断电耐久，以及与真实持有者、生产者的端到端组合。这些归持有者与装配的真实组合验证。

### 明确缺项

- 替身与本成员是两份近似代码，各自演进。整套 conformance 仍是唯一的可执行判据。是否收敛由契约拥有者在 0.1.0 重新评估时决定。
- `current()` 同步前提的真实来源不由本成员提供，缺口保留在 [#677](https://github.com/nemori-ai/omne-harness-lite/issues/677)（契约[明确缺项](../runtime-context-contract/SPEC.md#明确缺项)）。
- 自定义的恢复、代际替换与并发协议没有正式模型，相应机制路径保持未验证（[验证说明](../../../docs/verification.md)）。
- 一次恢复后供值被并发上限推迟时，读取答未知而不排队等待。M2 单机下同时恢复的作用域与块数有限，初值 16 足以覆盖首条路径；需要排队时再定等待策略。
