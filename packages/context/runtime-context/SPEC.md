# runtime-context 长期行为候选

状态：候选、待用户确认。目标成员为 `context/runtime-context`，不是已建立的实际包。本规格给出注册和读取的最小对接。字节编码、存储、Provider 和数值仍不在这里定。

产品输入归[运行感知与一次请求](../../../.meta_harness/design/product/runtime-context/design.md)，组合责任归[领域架构](../../../docs/domains/runtime-context/architecture.md)。源码及旧实现不构成本候选依据。

## RC-01 消费者、身份与范围

本能力向模型、工具、扩展和相应协调调用方提供分块当前数据及变化。消费者类别不是许可。每次实际读取须识别调用方、用途、数据所属范围和消费资格。托管租户数据及跨边界操作显式保留租户身份，跨租户访问默认拒绝。

Session 路径的注册及自有值属于原会话。生产者仍拥有原内容、共享当前值及读取资格。本能力不因持有注册、快照或句柄而取得修改源数据的资格。多个合法消费者可以读取同一块，各自独立满足资格。

公开能力可以独立使用。调用方提供与该操作有关的作用域、数据生产者、访问责任及资源，不强制创建隐式 Session 或启动 Cordis。纯计算可只处理调用方给出的数据。访问系统托管数据时仍适用原访问契约。注册和读取的最小对接见 [RC-02](#rc-02-原块与注册的必要条件) 和 [RC-03](#rc-03-当前读取与失败区分)。独立入口的字节编码仍未定。

## RC-02 原块与注册的必要条件

每个有效注册能够说明块身份、原生产者或来源、配置、允许消费者、是否必需及恢复依据。公开形状由后续实际类型拥有者定义，不能用一个无来源通用 Context 对象替代这些条件。

Session 决定本会话注册与本地选择，注册供给在其授权提交契约内承接变更。源内容更新由原生产者决定，注册存在不授予原内容修改权。共享当前数据、会话自有不可重算数据及派生计算有明确分类，不一律复制到日志，也不一律套资产设置继承。

进入会话日志的依据是注册集合变更，以及不能重算的会话自有输入。运行中模型可读块的状态变化以提醒进入历史，并写允许披露的前后值。当前快照、系统提示词、预算过程和空闲推送不进日志。注册决定是会话的一笔提交。块内容是生产者的另一笔提交。两笔不并成一次跨拥有者的提交。跨存储的同一次提交见 [STORAGE-T01](../../../docs/architecture/data-and-state.md#storage-t01)。记入标准见[必须进入日志的事实](../../../docs/architecture/runtime/session-and-run.md#必须进入日志的事实)。

添加注册前满足当前资格、来源规则及适用必需要求。移除可选注册只改变本会话后续供给，不删除共享源、不更改其他会话。必需注册不得通过可选移除绕过，内容更新不得改固定身份。当前注册与变更恢复事实共同保持一致。

注册或更新未提交，不报告为已生效。提交未知时保留原操作身份，按原拥有者查询和对账，不能直接重建另一注册或用旧快照覆盖合法变化。

注册变更的最小对接如下。增加、更新和移除都走这张表。块的内容形状不在本表。样例见 [RC-F02](docs/key-flows.md#rc-f02)。

会话路径携带会话。独立使用携带调用方给出的作用域，不制造会话。托管数据把租户当作参数。缺租户或跨租户默认拒绝。只处理调用方给出的数据时，不把缺会话当成拒绝。

更新保持块的固定身份，改来源、配置或消费者。更新不是先移除再新增。

| 项 | 规则 |
| --- | --- |
| 关联身份 | 这次变更的提交身份，加上作用域和块身份。会话路径上的作用域是会话。 |
| 必要参数 | 租户仅在访问托管数据时必需。还有作用域、块身份、来源、消费者、是否必需，以及增加、更新或移除。 |
| 成功 | 注册决定已提交。块内容由生产者另行提交。 |
| 拒绝 | 无资格、移除必需注册、更新改了固定身份，或同一提交身份配上不同变更。 |
| 未知 | 按原提交身份查询。不重建另一条注册。 |
| 同身份重试 | 相同提交身份和相同变更返回原结果。认回规则同[会话日志提交](../../session/session/SPEC.md#日志提交与查询结果)。 |
| 参数冲突 | 相同提交身份配上不同变更则拒绝。另一提交身份要改同一块时，先看它依据的注册状态是否仍是当前状态。已经变了就拒绝，调用方按当前注册重新提交。不用后写覆盖先写。 |

## RC-03 当前读取与失败区分

读取只纳入当前有效注册、生产者允许提供且消费者当前有权读取的块。历史提醒、旧快照及旧允许缓存不作为当前资格依据。授权或其他必要依据无法取得时保持未知，阻止依赖该允许结论的新读取或动作，不能报告空集合来冒充完整成功。

无权、无有效注册、来源不可用、内容无法解释和求值结果未知分别处理，同时遵循该对象存在性披露规则。错误不能返回未授权正文、凭据或源内部细节。必需注册存在但来源不可用时，报告必要内容缺项，由原消费契约处置，不伪造占位值或隐式移除必需项。

一次读取能够解释采用来源、覆盖范围及更新依据。多个块需要同一合法读取范围时，由消费与最终发起协调者保护一致性。本能力不能宣称任意独立源自动全局同提交。已发出请求的快照键见[装配与变化](../../../docs/architecture/runtime/assembly-and-change.md#细化与验证责任)。字节级的版本复核仍未定。

读取的最小对接如下。读取不建立一条可认回的写操作。

会话路径携带会话。独立读取携带调用方给出的作用域，不制造会话。托管数据把租户当作参数。缺租户或跨租户默认拒绝。只处理调用方给出的数据时，不把缺会话或租户当成拒绝。

| 项 | 规则 |
| --- | --- |
| 关联身份 | 读取方、作用域和这次读取范围。托管读取再带租户。 |
| 必要参数 | 消费者资格，以及要读的块或当前快照范围。 |
| 成功 | 返回当时有权读取的当前块。 |
| 拒绝 | 无权，或不存在且披露规则允许说明。不返回未授权正文。 |
| 未知 | 资格或来源未知时，不返回空集合冒充成功。 |
| 同身份重试 | 再读一次，取得读取当时的当前值。 |
| 参数冲突 | 读取不修改注册。 |

读取到当前值不改变原历史，也不更改已经固定的请求。新的合法值作用于之后的读取或组装。撤权停止新内容供给，不自动取消独立执行或撤回已发生效果。

## RC-04 attempt、变化与提醒

每次 attempt 开始主动取得当前合法完整快照。只有推送不能覆盖空闲期间变化，因此不能以“没有收到变化通知”省略这次读取。

存在未闭合运行时，模型可读块的有效变化交原变化消费路径形成追加提醒。仅工具或扩展可读的块只向获准消费者供给，不通知模型。注册添加或移除同样使后续适用消费者感知变化，不改写已经发出的输入。

快照前值、状态变化提醒和事件提醒的规则见产品[当前值与变化感知](../../../.meta_harness/design/product/runtime-context/design.md#5-当前值与变化感知)。前值受读取资格约束。曾经合法的历史不向现在无权的模型重新披露前值。

空闲状态推送可以丢弃；下一次 attempt 的当前读取承接变化，不补世界上所有中间值。原业务输入、控制、结果或已承担交付责任的数据不得归到这条可丢路径。通知只提醒检查权威状态，不单独授予推进资格。

消息式提醒的可靠保存与消费位置归 Session 原协调者。重复通知不得重复逻辑承接；丢失通知后仍有权威事实可补查。具体身份、补查、前值关联及提交协议未采用。本能力不能用通知到达或订阅成功代替提醒已持久成立。

模型首次读取与合法压缩后提供当前有权读的完整 Context。平常变化提醒参与适用历史投影。私有块不因全量路径进入模型；历史提醒被摘要后也不能用摘要替代这次完整读取。

## RC-05 会话值、模式与工作区指导

会话自有选择及不可重算值按原拥有者规则保存。三模式维度的有效值、初值和用户后果完整见[产品模式规则](../../../.meta_harness/design/product/runtime-context/design.md#4-三个模式维度独立)。Session 提供模式事实，本能力供给当前值。无显式初值时读取适用租户默认，然后保持本会话值；恢复、撤销归档、重新装配和租户以后修改默认都不重套初值。

逐工具执行环境值与缺省声明属于本会话当前策略，实际执行每次求值，不建立永恒固定执行位置。新增工具缺少适用值时说明缺项，不静默套租户后来默认。其他设置沿自身继承和覆盖规则，固定身份及组织上界始终保持。

模式修改的资格见[产品模式规则](../../../.meta_harness/design/product/sessions-and-work/design.md#按协作需要调整三个独立模式)。本能力只供给当前合法值及变化，不能通过 Context 注册或更新旁路修改 Session 模式。目标完成检查的装卸与在途处理归Agent扩展和装配拥有者；Context不因模式变化撤销原调用。

工作区 AGENTS.md 在实际首次访问尚未进入的目录时加载适用指导，未访问时不因普通资产发现预加载。来源、适用目录、读取资格及采用内容可追溯。它不属于普通 `.omne` 资产 reload，远端变化不自动同步。规范版本、精确首次访问判据及合并协议须后续核实，不能凭社区惯例声称已采用。

必需块的生产者、内容与消费者沿[产品必需感知](../../../.meta_harness/design/product/runtime-context/design.md#3-必需感知按内容及消费者供给)，含原 PF 标为推导的候选项，限定状态见成员内部设计的采用范围。ModelProfile 不夹带秘密；授权两级结构只给扩展；语义授权不是最终准入缓存；后台、子会话和待办只供实际已知状态。

## RC-06 持久状态与恢复

恢复需要保留本会话注册、来源配置、移除意图、自有不可重算值及足以解释旧执行的采用依据。仅保存最后数据或仅保存 Session log 都不够。实时值重算，共享当前值从有效权威重取，不把来源副本转成共享权威。

确认持久保存所需事实之后，普通进程崩溃、OS 崩溃及断电仍保留其内容、归属和解释依据。引用实际内容时，引用及其所需期限内可恢复内容共同满足保证；临时文件或即将失效地址不能假称可靠引用。具体提供者刷新、介质和部署条件需具名证据。

恢复核对原身份及当前资格，主动移除不装回，必需信息不绕过，旧备份不复活撤销资格。共享源不可用时保持缺项，不能用历史允许或缓存掩盖。普通恢复不统一增加人工审批；介质损毁后的开放范围与资格仍沿原恢复未决，不在此补默认。

已发请求采用值与本次应读当前值分别恢复。Agent 换代不会重发已经存在的模型或工具调用。原执行、结果、费用及原消费位置继续由原调用和消费拥有者负责，Context 仅供给合法条件。

## RC-07 并发、撤除与取消

注册修改、生产者更新、撤权、读取及请求固定可能并发。每次读取与最终发起须能解释其合法采用范围，不拼接从未合法成立的状态。正在组装的新值不能覆盖已固定请求，当前源变更也不能无声改回旧快照。

取消一次读取或订阅结束对应等待与资源，不证明源变更未提交，不取消原工具或模型执行，也不删除既有历史。释放 Cordis 资源或 disposer 不撤回外部输出。若取消时提交未知，原责任方继续对账。

生产者或提供者撤除后，合法重读与依赖失败由公开契约承接。已保管的不可重算事实不随实例或进程生灭消失。结构性绑定换代沿装配交接，新读当前数据不被误当作结构性换绑。

会话归档使业务取消生效并解除等待，不以所有独立执行物理停止为完成前提。迟到结果不复活推进，撤销归档也不重启旧调用；真实结果和账目按原拥有者保留。Model ACK 不授予本能力删除共享源、自有值或历史的权力。

## RC-08 缓存、资源与观测

当前指定值及注册读取不应因历史增长每次重扫全量日志。列表、全文和完整快照的物化成本仍按实际输出量计算，不能扩大成任意查询常数成本。生产者读取、变化适配、派生计算及跨边界交付分别计量。

每份缓存说明权威来源、输入范围、覆盖进度、容量、失效及重建条件。权限失效、来源或注册变化后不以过期允许供新数据；必要正确性判断回权威核对。重建期间的缺口和不可用可辨，不把不完整结果报告为完整成功。

观测保留原身份、来源、阶段、读取失败与变化缺口，正文和秘密按用途、资格及实际接收方筛选。可读不等于可发送，遥测不默认附完整块。未知资源尺度、延迟和容量不编统一数值。

## RC-09 持续验证与明确缺项

后续成员及真实组合至少持续验证以下行为。

| 场景 | 必须检查的结果 |
| --- | --- |
| 同块不同消费者 | 工具或扩展私有块不通过全量、提醒、缓存或错误进入模型 |
| 空闲期间多次更新 | attempt 读当前值，不补全部空闲推送；可靠普通输入不丢 |
| 可选移除后故障恢复 | 原移除仍有效，共享源和别会话不受删改 |
| 必需块移除或身份改写 | 操作不生效，不以必需来源不可用偷换成可选 |
| 读取与撤权、注册变化竞争 | 最终合法范围可追溯，旧缓存不提供新允许 |
| 初次与压缩后读取 | 完整合法 Context 在场，私有块仍排除 |
| 嵌套目录首次访问 | 指导在实际访问时加载，不由资产 reload 预装 |
| 持久确认后普通故障 | 进程、OS 崩溃和断电条件分别有相称证据，不能只用重启测试 |
| Agent 换代与迟到结果 | 当前数据重取，旧采用不改，原调用不重复执行 |
| 超长历史及缓存重建 | 当前点查询不重扫全量，实际输出与冷加载成本分别报告 |

MODEL-E01 的最终工具结果语法及嵌套投影、已展示在途内容保留兑现仍未闭合。公开 API、注册原子边界、前值关联、通知补查、AGENTS 规范、缓存一致性及资源指标尚待成员与协调者设计。

这些缺项不允许降低已定访问、历史和恢复责任。当前未运行实现，不宣称接口、租户隔离、并发、断电耐久或性能通过；作者自检和结构检查不授予接受。


### 旅程对应与持续验证场景

本成员承接 CAP-RC01 至 CAP-RC05 及 CAP-RC10 的供给侧责任。以下是持续验证义务，不是本次已执行的测试；真实组合须由 Session、原生产者、授权与原消费者共同取证。

<a id="rc-vj01"></a>
#### RC-VJ01 当前条件与模式变化

对应 [RC-J01](../../../.meta_harness/design/product/runtime-context/design.md#rc-j01)及 [RC-F01](docs/key-flows.md#rc-f01)。设置同一块对模型可读、仅扩展可读及必需来源不可用三种条件，检查全量和变化都不越消费者边界。空闲时连续改变当前值并同时接纳普通输入，下次 attempt 读当前值，可靠输入仍存在。另触发模型首次读取及压缩后读取，检查完整模型可读 Context，不把 attempt 拉取冒充这两个触发。完整快照分别提供有前值和无前值样本，均按该块的产品要求判断。变化提醒保留获准披露的前后值。用户修改一项模式不改其他维度。Agent 要改模式，必须走 HITL，由人显式授权。更改租户默认后，恢复原会话仍使用会话值。

<a id="rc-vj02"></a>
#### RC-VJ02 注册失效与提交未知

对应 [RC-J02](../../../.meta_harness/design/product/runtime-context/design.md#rc-j02)及 [RC-F02](docs/key-flows.md#rc-f02)。可选移除后模拟普通故障，检查移除保留、共享源与他会话不受影响。分别拒绝必需移除、固定身份改写及无权修改。交错撤权、读取、缓存命中和请求固定，检查新读取合法，旧请求仍可解释。丢失变更确认后取消等待，再按原操作查回；不能复制注册或判定未提交。精确调度和提交协议待 CONTEXT-M01 设计后落实。

<a id="rc-vj03"></a>
#### RC-VJ03 目录首次指导读取

对应 [RC-J03](../../../.meta_harness/design/product/runtime-context/design.md#rc-j03)及 [RC-F03](docs/key-flows.md#rc-f03)。对比普通资产发现、资产 reload、首次实际访问和再次访问，核对只有适用访问路径加载指导。记录路径、来源、资格及采用内容；无权与来源失败分别报告。恢复后首次访问认定及合并的精确预言须以 CONTEXT-E02 已采用协议补齐，当前不能自行选规则令测试通过。

#### RC-VJ08 已确认事实恢复

对应 [RC-J08](../../../.meta_harness/design/product/runtime-context/design.md#rc-j08)及 [RC-F08](../docs/key-flows.md#rc-f08)。对注册、自有不可重算值、移除和历史采用确认保存后，分别取进程崩溃、OS 崩溃及断电证据。恢复重取当前来源和资格，不能复活移除、重套模式默认或以旧权限供给。查询不可用保留未知，Agent 换代不重发原执行。归档及撤销沿 Session 唯一状态机核对，迟到结果不能恢复推进。

#### RC-VJ09 长历史、缓存缺口与受限诊断

对应 [RC-J09](../../../.meta_harness/design/product/runtime-context/design.md#rc-j09)及 [RC-F09](../docs/key-flows.md#rc-f09)。分别测量当前点查询、完整快照、缓存冷建及变化供给，检查成本与实际输出范围，不能用单一总耗时宣称每项满足。撤权及缓存失效时不扩大读取，覆盖不足明确报告缺口。诊断接收方变化重新检查外传资格，错误、摘要与引用不泄露正文或秘密。数值阈值待原拥有者采用后补入，当前不编通过门槛。
