# Runtime Context 供给机制的流程

本页给出本成员的五条机制级流程。每条有一张时序图和一张「失败与责任交接」表。行为以 [SPEC](../SPEC.md) 为准，图只投影条款。

协议级流程归 [runtime-context-contract 的协议流程](../../runtime-context-contract/docs/flows.md)，本页的流程是它们在机制内部的展开。Cordis 装载、登记寿命与唤醒派发归 [runtime-context-cordis 的流程](../../runtime-context-cordis/docs/flows.md)。图中的「机制实例」是工厂的输出，内部的表见[内部架构](architecture.md#模块与依赖)。

## 流程

### F-RCI01 注册变更与步提交的核对和写入

协议流程：契约的 F-RC02 与 F-RC07。条款：[RC-02](../../runtime-context-contract/SPEC.md#rc-02-块声明注册与参数)、[RC-05](../../runtime-context-contract/SPEC.md#rc-05-状态块上下文更新与步提交)。

```mermaid
sequenceDiagram
  participant H as 作用域持有者
  participant M as 机制实例
  participant Reg as 注册表
  participant Proj as 当前投影
  participant Obs as 观察链
  participant O as 变化出口
  H->>M: prepareRegistration(注册材料)
  M-->>H: 核对结果，不写表
  H->>H: 在本成员之外提交注册决定或步提交
  H->>M: applyCommit(提交身份，已提交的结果，依据的注册修订)
  M->>Reg: 查提交身份
  alt 提交身份已应用
    M-->>H: 原结果
  else 步提交
    M->>Proj: 写入步提交的值（含被拒更新时整笔拒绝，原因无效）
    M->>Obs: 追加视图修订
    M->>O: onChange(作用域, 视图修订)
  else 注册决定，依据的修订等于当前修订
    M->>Reg: 应用注册，前进注册修订，记下提交身份与结果
    M->>Obs: 追加视图修订
    M->>O: onChange(作用域, 视图修订)
  else 注册决定，依据不等且提交身份未见过
    M-->>H: 无效（顺序不符），带当前注册修订
    H->>M: 以新检查点开始恢复会话，补齐后原输入重试
  end
```

| 环节 | 结果 | 失败与责任交接 |
| --- | --- | --- |
| 核对 | 只给核对结果，表不变 | 核对失败带逐项原因，持有者修正材料后重新提交 |
| 持有者提交 | 提交在本成员之外完成 | 提交未知时由持有者按原提交身份查询，本成员不重建另一条注册 |
| 按提交身份应用 | 同一身份重试返回原结果；依据的修订等于当前修订时应用并前进 | 依据不等且身份未见过时返回无效（顺序不符），持有者用恢复会话补齐后原输入重试。注册修订的唯一权威是持有者的耐久提交 |
| 作用域所属租户 | 作用域第一次被可信绑定确认时记下 | 记下的租户与可信事实冲突时答无效（`tenant-mismatch`） |
| 声明 | 注册状态块时带来的声明进入目录 | 与同键已有声明的摘要不同时拒绝（无效） |
| 写入步提交 | `reduceStep` 对每条更新给出接受或拒绝；接受的合并结果在 `applyCommit` 时写入投影。步提交按提交身份幂等，不与注册修订比较 | 被拒的更新由持有者按逐项原因退回提出者。含被拒更新的步提交整笔拒绝（无效），投影不变。提交前不改投影。失败步里成功动作的更新由持有者处置，本成员不写入 |
| 变化出口 | 视图修订前进后同步调用 `onChange` | 回调抛错只记诊断，写入不回滚 |

### F-RCI02 发布与代际

协议流程：契约的 F-RC01 与 F-RC08。条款：[RC-07](../../runtime-context-contract/SPEC.md#rc-07-生产者句柄并发撤除与恢复)。

```mermaid
sequenceDiagram
  participant P as 生产者
  participant M as 机制实例
  participant PT as 生产者表
  participant Proj as 当前投影
  participant Obs as 观察链
  P->>M: registerProducer(主体, 租户, 块键, 生产者身份, 块声明)
  M->>M: 权威端口核登记动作
  M->>PT: 按租户加块键核身份与声明摘要，新取代际
  M-->>P: 生产者句柄（带代际）
  P->>M: 发布(作用域, 值, 代际)
  M->>PT: 比较代际，取写入序号
  alt 代际不小于当前代际，序号不小于已写入的序号
    M->>M: 按块声明的 schema 校验
    M->>Proj: 写入值，前进修订
    M->>Obs: 追加视图修订
  else 旧代际或旧序号
    M->>M: 丢弃并记录诊断
  end
  P->>M: 使当前值失效
  M->>Proj: 当前值变为缺项，前进修订
  M->>Obs: 追加视图修订，调用 onChange
  opt 作用域无关的块
    M->>P: 对每个已注册该块的作用域调用回调，各取写入序号，带超时
    M->>Proj: 回调的值按序号比较后写入，前进修订
  end
```

| 环节 | 结果 | 失败与责任交接 |
| --- | --- | --- |
| 登记 | 生产者表按租户加块键记录生产者身份与本成员新取的代际 | 权威端口拒绝即无权。没有带块声明，或声明与同键已有声明的摘要不同，登记被拒绝。同一槽另一身份登记被拒绝。同一身份再登记取新代际，替换旧一代，本租户各作用域的旧值删掉 |
| 旧代发布 | 拒收（`stale-generation`），投影与修订不变，有诊断 | 旧代不能覆盖新代的值 |
| 值不合 schema | 发布被拒绝，当前值与修订不变 | 不存成「内容无法解释」 |
| 使失效 | 当前值变为缺项，视图修订前进，变化出口被调用 | 读者读到什么以读取时的值为准。回调取回值时修订再前进 |
| 作用域无关块的回调 | 持有者注册该块时对该作用域调用；生产者后登记或使当前值失效时对每个已注册作用域调用 | 回调的值按写入序号比较后写入，晚到的旧结果不写入。持有者注册时的回调不阻塞 `applyCommit`，结果到达前该块读到缺项。回调失败或超时记诊断，该块保持缺项。生产者不需要知道作用域列表 |
| `dispose` | 立即拒绝本代新操作，在 `settleBoundMs` 内等本代在途的供值调用结算，然后只撤除本代登记 | 这一代已被替换时不改动登记。撤除后依赖该块的读取读到缺项（`producer-withdrawn`）。实例已关闭时立即返回 |

### F-RCI03 读取：核资格、读取缓存、翻译、缺项

协议流程：契约的 F-RC03 与 F-RC05。条款：[RC-03](../../runtime-context-contract/SPEC.md#rc-03-当前读取资格与缺项)、[RC-06](../../runtime-context-contract/SPEC.md#rc-06-需要绑定与读者形状)、[RC-08](../../runtime-context-contract/SPEC.md#rc-08-缓存观测与遥测)。

```mermaid
sequenceDiagram
  participant R as 绑定读者
  participant M as 机制实例
  participant A as 权威端口
  participant B as 可信绑定来源
  participant C as 读取缓存
  participant Proj as 当前投影
  R->>M: snapshot() 或 read(需要)
  M->>M: 资格状态（被取代时沿取代者）
  M->>A: 读者面判定（资格里的主体）
  M->>B: 作用域的绑定租户等于资格租户
  M->>M: 作用域开放且围栏打开，记下的租户相符，块键与消费者类合乎资格
  alt 键相同的缓存条目存在
    C-->>M: 稳定条目
  else 未命中或绕过
    M->>Proj: 本作用域查找，没有再查父作用域（逐跳核对）
    opt 有待刷新标记
      M->>M: 恢复后供值（合并、并发上限、重试间隔）
    end
    M->>C: 条目都可缓存且投影版本未变时写入
  end
  M->>M: 逐请求块向生产者取值；按绑定翻译
  M->>M: 披露前同步调用 current()，再核资格与作用域
  M-->>R: 值、「无值」、缺项、拒绝或未知
```

| 环节 | 结果 | 失败与责任交接 |
| --- | --- | --- |
| 核资格 | 六步都成立时继续。按原形状读要求块键在块键集合里；读带翻译的需要要求绑定在需要绑定集合里 | 撤销、权威端口拒绝、可信绑定未绑定或租户不同、记下的租户不符时答无权，生产者与回调零调用，不查缓存。端口不可用或未知答未知（`eligibility-unknown`、`scope-binding-unknown`） |
| 读取缓存 | 命中省掉过滤与查找 | 键含租户、作用域、资格、注册修订与投影版本，命中从不提供旧值。带父引用的作用域与带待刷新标记的块绕过缓存 |
| 来源调用 | 逐请求块与恢复后供值有 `supplyBoundMs` 上界 | 超时按未知结算 |
| 注册修订落后 | 按当前注册读取，结果带签发时与当前的两个修订 | 持有者判断是否重新签发资格 |
| 翻译 | 读者拿到自己的形状 | 翻译抛出或不合需要形状时返回缺项，带来源修订，没有部分结果 |
| 披露 | `current()` 为真且资格与作用域仍成立时返回 | `current()` 答假即无权。实例已关闭答关闭 |

### F-RCI04 `changes` 与游标作废

协议流程：契约的 F-RC04。条款：[RC-04](../../runtime-context-contract/SPEC.md#rc-04-读取时点观察与变化材料)。

```mermaid
sequenceDiagram
  participant R as 绑定读者
  participant M as 机制实例
  participant Obs as 观察链
  R->>M: changes(游标)
  M->>M: 核资格
  M->>Obs: 定位游标
  alt 游标有效且在保留范围内
    Obs-->>R: 游标之后的变化与新游标
  else 游标早于保留下界、授权范围变化、生产者换代、资格被重签或进程重建
    M-->>R: 游标作废，需要重取
    R->>M: snapshot()
    M-->>R: 完整快照、视图修订与新游标
  end
```

| 环节 | 结果 | 失败与责任交接 |
| --- | --- | --- |
| 游标有效 | 只返回读者资格允许的变化 | `per-request` 块不在观察链里，所以不在变化里 |
| 超过保留上限 | 最老的变化被丢弃 | 持有旧游标的读者得到游标作废，不得到残缺的增量 |
| 游标作废 | 读者重取完整快照 | 调用方不需要自己判断是哪种情形 |
| 变化材料 | 只为模型可读块生成，前值来自持有者保留的上一份按资格过滤的快照 | 本成员不保存变化材料，也不保存旧值。写成提醒归持有者 |

### F-RCI05 关闭与恢复会话

条款：[SPEC 所有权、失败与生命周期](../SPEC.md#所有权失败与生命周期)、[RC-09](../../runtime-context-contract/SPEC.md#rc-09-作用域结束恢复会话与恢复后供值)、[IC-19](../../../../docs/architecture/cordis-integration-conventions.md#ic-19)。

```mermaid
sequenceDiagram
  participant C as 关闭方
  participant M as 机制实例
  participant H as 作用域持有者
  participant P as 生产者
  participant R as 读者
  C->>M: close()
  M->>M: 1 拒绝新请求
  M->>M: 2 使全部绑定读者结束
  M->>M: 3 取消在途等待（端口与来源）
  M->>M: 4 在 settleBoundMs 内等全部在途操作结算
  M->>M: 5 释放全部表与读取缓存
  Note over M: 进程崩溃时没有这些步骤，表随进程丢失
  H->>M: 新实例：beginReplay(作用域, 租户, 检查点)
  M-->>H: 恢复引用，围栏关闭
  H->>M: finishReplay(恢复引用, 完整恢复材料)
  M->>M: 暂存，最终同步段核对后原子安装，建立待刷新标记
  M-->>H: 就绪（开放或已结束）
  H->>M: 重新签发资格
  P->>M: 重新登记；persisted 块重新发布
  R->>M: 重新 bind，取完整快照；第一次读取为待刷新的块供值
```

| 环节 | 结果 | 失败与责任交接 |
| --- | --- | --- |
| 关闭后的新请求 | 答关闭 | 调用方改用新实例 |
| 关闭时在途操作 | 最终同步段答关闭，不答成功：`finishReplay` 不安装，`applyCommit` 不应用，`issueEligibility` 不签发。在途读取结算为关闭、未知或缺项 | 端口不应答时关闭仍在上界内完成。本成员不声称物理来源调用已经停止 |
| 已交出的变化材料与外部效果 | 不撤回 | 外部效果的拥有者 |
| 恢复材料 | 注册链、已有步提交的 `checkpointed` 块的检查点值、结束 | 没有步提交的块可以缺席，恢复之后读法与重启前相同。材料覆盖由持有者的权威核对。超过 `replayCapacity` 答不可用（`replay`），围栏保持关闭，不截断 |
| 恢复后供值 | 第一次普通读取遇到待刷新标记时供值 | 失败按读取结果表落位并保留标记。同一标记的并发读取合并为一次调用 |

## 失败与生命周期

| 情形 | 结果 | 责任方 | 依据 |
| --- | --- | --- | --- |
| 提交顺序不符 | 返回无效，当前注册不变 | 持有者用恢复会话补齐后原输入重试 | [注册修订与提交顺序](../../runtime-context-contract/SPEC.md#注册修订与提交顺序) |
| 旧代发布 | 拒收，有诊断 | 生产者 | [RC-07](../../runtime-context-contract/SPEC.md#rc-07-生产者句柄并发撤除与恢复) |
| 撤权后的读取 | 拒绝（无权），已返回的值不收回 | 持有者 | [RC-03](../../runtime-context-contract/SPEC.md#rc-03-当前读取资格与缺项) |
| 翻译抛出 | 缺项，带来源修订 | 集成方修正翻译 | [RC-06](../../runtime-context-contract/SPEC.md#rc-06-需要绑定与读者形状) |
| 游标落后或作废 | 要求重取完整快照 | 读者的调用方 | [RC-04](../../runtime-context-contract/SPEC.md#rc-04-读取时点观察与变化材料) |
| 进程失败 | 全部表丢失 | 持有者开始恢复会话并重新签发，生产者重新登记 | [SPEC 所有权、失败与生命周期](../SPEC.md#所有权失败与生命周期) |

各内部对象的创建与结束见[对象模型](object-model.md#生命周期)。
