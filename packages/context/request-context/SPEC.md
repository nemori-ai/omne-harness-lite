# @omne-harness/request-context 行为规格

状态：机制实现成员，`draft`。本成员实现来源登记表 `createContextSourceRegistry` 与账目投影 `createContextAccounting`，有进程内的运行实现与契约测试。候选缓存、预计算派生物与默认策略已有本页的设计，尚未实现。公开行为归 [request-context-contract SPEC](../request-context-contract/SPEC.md)。本页只写实现真实承担的本地行为：登记代际与借用、账目索引与恢复状态、缓存键、按组失效、失效来源、预计算派生物、默认策略数值与修剪器行为。不重复契约条款。

## 范围与依据

本成员与 Cordis 无关（[IC-4](../../../docs/architecture/cordis-integration-conventions.md#ic-4)）。[request-context-cordis](../request-context-cordis/SPEC.md) 的根入口不导出任何东西；不装配 Cordis 又要托管登记的调用方直接从本成员取工厂，只要独立操作组的调用方用契约根入口的 `createAssemblyOperations`。贡献登记面与 isolate 绑定归 [request-context-cordis](../request-context-cordis/SPEC.md)。

本成员导出两个工厂：

| 工厂 | 输入 | 交出 |
| --- | --- | --- |
| `createContextSourceRegistry(options)` | 主体绑定、登记授权判定者、两个策略实现（压缩策略、表示策略）。经 Cordis 时策略由 request-context-cordis 按配置选定 | 来源登记表 `ContextSourceRegistry`：`register`、`replace`、`assembly(target)` 与 `close()`（[RQ-12](../request-context-contract/SPEC.md#rq-12-来源集合与登记面)） |
| `createContextAccounting(options)` | 来源核验、读取资格桥、窄采用来源、恢复授权与容量上限 | 收件口 `ContextAccountingInbox` 与恢复口 `ContextRecovery`（[RQ-14](../request-context-contract/SPEC.md#rq-14-窗口占用与账目收到)） |

历史源读口、Model 准备资源、转换件结果读口与读取资格随来源集合登记，不在构造时给出，也不逐次交入。请求字节取自 Model 的 `rules.plan` 返回的物化表示，本成员没有序列化端口。

原则：请求到了不算，算在请求之前。能在输入变化时维护的派生物不在组装时重算；组装时只做比对与拼装。输入快照的定义消费[比对代替求值](../../../docs/architecture/runtime/assembly-and-change.md#比对代替求值)。

本成员不持有任何耐久状态。登记表、账目索引与缓存都是进程内状态；账目索引从结果接收方的日志重放重建，缓存缺失时从输入重算，结果相同。

## 结果与不变量

### 来源登记表

| 项 | 本地行为 |
| --- | --- |
| 登记项 | 每个 `(tenant, scope)` 一项，记当前 `RegistrationRef`、`SourceGeneration`、来源集合与在途借用数 |
| 代际 | 每次 `register` 或成功 `replace` 新取一个代际，进程内单调，旧代际不复用 |
| 借用 | 每次操作开始时取当前代际并加一借用；结束时减一。代际被撤除或替换后，新借用直接返回不可用（来源登记） |
| 发布 | 操作组的结果交回之前，在同一个同步动作里核借用的代际仍是该键的当前代际；不是时丢弃结果，返回不可用 |
| 撤除 | `withdraw()` 标记该代际撤除并同步返回同一个结果对象；`settled` 在该代际的借用归零时兑现。挂起的操作使它一直待定 |
| 关闭 | `close()` 拒绝新登记与新借用，等待全部代际结算 |

### 账目投影

| 项 | 本地行为 |
| --- | --- |
| 目标状态 | 每个 `(tenant, scope)` 一份状态：`uninitialized`、`rebuilding` 或 `ready`，带当前 `AccountingGeneration` |
| 索引 | 按 `(call, dispatch)` 保存各修订的规范内容指纹与当前最高修订的账目；指纹在本代际内保留 |
| 代际 | 每次重建成功新取一个代际。`receive` 在异步核验之后、写索引之前再核代际与状态 |
| 暂存 | 重建在单目标的暂存索引上进行，成功后整体替换当前索引；失败丢弃暂存，保留旧索引，目标保持未就绪 |
| 容量 | `limits` 构造时必填，没有默认值；缺项或不是正安全整数时构造抛出 `TypeError`。达到上限时拒收，不淘汰旧事实 |

### 候选缓存

| 项 | 内容 |
| --- | --- |
| 存什么 | 候选内容与各层的渲染结果。不存组装结局：结局每次按本次输入（含「上一次准备」）计算。⑥ 尾部易变提醒与装入裁定每次重算，不进缓存 |
| 键 | 与 `PreparedInputKey`（[RQ-13](../request-context-contract/SPEC.md#rq-13-七组的稳定读取)）相同：主体键与七组各自的修订令牌，令牌覆盖七组的全部成员：调用身份与用途（访问身份、用途、消费位置、候选身份）；历史与新输入（历史依据的 epoch、上界与作用域引用，新输入批证据）；runtime context 读取结果（作用域引用、资格身份、游标与代次、快照修订与锚点、已采用与转换依据）；系统提示词（本作用域适用的段列表的摘要，即全局层加本作用域层；登记面实例的代次；组装上下文的各不透明键）；模型侧（选定模型的档案与参数摘要）；工具侧（工具采用集合摘要）；当前条件与本次经过（条件修订、扩展改写依据、调模型之前位置的经过）。「上一次准备」不进键，它只影响结局，结局不进缓存（[RQ-02](../request-context-contract/SPEC.md#rq-02-组装的前置输入)） |
| 命中 | 全部相等即复用已有的候选内容与各层渲染结果，不重算这些层。⑥、装入裁定与结局仍按本次输入计算 |
| 按组失效 | 见下表 |
| 失效来源 | 输入携带的修订或计数，而不是时间：每次调用时按组比较。缓存项记录它看到的值。不用文件时间，不用内容重哈希 |
| 通知入口 | 缓存由 `createContextSourceRegistry` 返回的登记表实例托管；缓存实现时，该实例增加 `notify(change)`，种类只有 `contributions`：贡献登记面的变化，带变化所在的作用域引用（全局层为 `null`）与该层的修订。实例收到后自己从登记面读口读段并渲染（见[预计算的派生物](#预计算的派生物)）。别的组不经通知，靠每次调用时的输入比较 |
| 容量 | 每个消费位置保留最近一个已固定候选加一个在算候选。候选是否已固定只由第三组的「已采用」得知：已采用且七组令牌逐组相同时返回原采用。本成员不另外记录固定状态。容量是配置初值 |

按组失效：每组变化时重算哪些层，前缀变化原因记什么。⑥ 与装入裁定不在表里，它们每次都重算。

| 组 | 变化 | 重算的层 | 前缀变化原因 |
| --- | --- | --- | --- |
| 一 调用身份与用途 | 访问身份、用途或消费位置变化 | 全部重算，不跨这三项复用任何层 | 按重算后实际变化的层记 |
| 一 调用身份与用途 | 只有候选身份变化 | 不重算层；开始新的准备，计划次数重置 | 无变化 |
| 二 历史与新输入 | 只有新输入或历史上界变化 | ⑤ 历史体尾部 | 无变化 |
| 二 历史与新输入 | 历史 epoch 变化 | ③ 历史头（含压缩记录）、④ 快照提醒、⑤ 历史体 | 发生了压缩 |
| 三 runtime context 读取结果 | 读取结果为完整 | ③ 历史头到新锚点的部分、④ 快照提醒、⑤ 历史体 | 新的完整读取换了快照 |
| 三 runtime context 读取结果 | 读取结果为增量 | 不重算 ①至⑤。④ 用调用方交入的最近一次完整读取的块材料，命中时复用 | 无变化 |
| 三 runtime context 读取结果 | 带压缩转换依据（`resume`） | ③、④、⑤ | 发生了压缩 |
| 四 系统提示词 | 本作用域适用的段列表摘要、登记面实例代次或组装上下文变化 | ① 系统提示词 | 系统提示词变了 |
| 五 模型侧 | 选定模型变化 | 全部 | 换了模型 |
| 五 模型侧 | 只有参数变化 | 不重算层 | 无变化 |
| 六 工具侧 | 工具采用集合变化 | ② 工具声明 | 工具集合变了 |
| 七 当前条件与本次经过 | 条件证据变化 | 不重算层，只更新覆盖证据里的条件部分 | 无变化 |
| 七 当前条件与本次经过 | 扩展改写依据变化 | 改写触及的层 | 触及①至④时记「扩展改写了已有内容」，只追加到⑤尾部时无变化 |
| 七 当前条件与本次经过 | 调模型之前位置的经过变化 | 不重算层 | 无变化 |

别的作用域的贡献变化不改变本作用域的段列表摘要，所以不使本作用域的 ① 失效，也不记前缀变化原因。

有缓存与无缓存的同输入结果相同。缓存项记录的修订落后于输入携带的修订时，缓存项作废，不返回旧内容。

### 预计算的派生物

| 派生物 | 谁维护 | 何时 | 组装时做什么 |
| --- | --- | --- | --- |
| epoch 视图与前缀摘要 | 历史持有者 | 消息提交、压缩提交 | 只读页、比摘要 |
| 系统提示词各有序段的渲染结果 | 登记表实例（`createContextSourceRegistry`），唯一拥有者 | 收到 `notify('contributions', …)` 后，从登记面读口读出该层的段并渲染；独立路径上第一次见到某段时渲染，按段摘要复用 | 按变量求值拼接；段文本不重渲染 |
| 工具声明投影 | 本成员 | 工具采用集合变化时，由第六组输入比较得知，不经通知 | 直接取 |
| 快照提醒文本 | 本成员 | 调用方交入的块材料第一次以某个身份出现时 | 按身份复用，直到下一次完整读取。身份是作用域引用、资格身份、快照修订与锚点。缓存缺失时从调用方交入的块材料重算，结果相同 |
| 表示决定（派生表示、transcript） | 内容拥有者 | 消息接纳前 | 取引用，不转换 |
| 计量结论 | Model 的计量端口 | 每个候选对每个供应商各计量一次：以本次访问身份取得 Model 准备租约，按该供应商 `rules.plan` 给出的物化表示计量改写后的完整输入，在全部路径上归还租约 | 不缓存，不复用。同一候选两次计量的结论可以不同 |

### 默认策略与修剪器

压缩策略默认实现的配置初值如下。三个数值现在都标「待重核」：它们来自同类系统的取证，按本项目的计量口径重核后才作为初值生效。

| 配置项 | 默认 | 状态 |
| --- | --- | --- |
| 触发界线 | 窗口的 80% 与「窗口减输出预留减余量」两者的较小值 | 待重核 |
| 保留预算 | 窗口减输出预留的 16%，作用于保留名单 | 待重核 |
| 保留偏好 | 较新优先 | 不涉及数值 |
| 修剪优先 | 是 | 不涉及数值 |
| 步数上界 | 3 | 待重核 |

这些项都是配置字段，默认值只是初值（[IC-14](../../../docs/architecture/cordis-integration-conventions.md#ic-14)）。

修剪器默认实现：只缩短交给摘要步的材料中超过阈值的工具结果与媒体占位，保留原消息身份与占位的引用，不改原记录，不改模型视图。阈值是配置初值。修剪只缩短交给摘要步的材料，不改变装入裁定。修剪在给出第一个摘要步之前完成一次，不算一步进度（[RQ-06](../request-context-contract/SPEC.md#rq-06-压缩共同结果与保护边界)）。

表示策略默认实现：同一块有多种表示可用时按模态的偏好顺序选，原件优先于派生表示，派生表示优先于 transcript；工具内容引用标待加载。偏好顺序是配置初值。

### 本地行为

- 同一候选身份内再次 `assemble`，先比缓存键；键相同时复用已有的候选内容与层渲染结果，不重算这些层，⑥、装入裁定与结局按本次输入计算（[RQ-01](../request-context-contract/SPEC.md#rq-01-调用方与计算边界)）。
- 读口返回「epoch 已变」时，本次组装丢弃已读页，用返回的当前依据重取并重算，不拼接（[H2](../request-context-contract/SPEC.md#历史源读口与-epoch-视图)）。
- 前缀摘要比较在每层锚点处各做一次，不逐条比对（[H3](../request-context-contract/SPEC.md#历史源读口与-epoch-视图)）。
- 任一依赖端口缺席或返回不可用时，相关操作返回不可用，带诊断，不伪装成功。
- 计划进度不在本成员保存。`deriveStep` 只接受调用方传回的进度，核计划身份、步序号（`StepInput.index` 等于已完成步数）与压缩依据（`basis` 的摘要与当前输入）后给出下一步；核不过返回无效（[计划操作的结果](../request-context-contract/SPEC.md#计划操作的结果)）。
- `planCompaction` 在计划里记下当前压缩策略的身份与参数摘要。`deriveStep` 时与实例当前的策略比较，不符即返回无效（[RQ-06](../request-context-contract/SPEC.md#rq-06-压缩共同结果与保护边界)）。
- `context.window-usage` 的值由账目投影的 `usage({ access, target })` 给出，四种状态之一（[RQ-02](../request-context-contract/SPEC.md#rq-02-组装的前置输入)、[RQ-14](../request-context-contract/SPEC.md#rq-14-窗口占用与账目收到)）。进程重启后，目标在授权重建完成之前返回不可用，重建后按当前固定请求给值，不在重启后读到缺项。

## 所有权、失败与生命周期

| 事物 | 拥有者 | 失败时 | 结束 |
| --- | --- | --- | --- |
| 候选缓存与派生物 | 本成员实例 | 进程失败即丢失，从输入重建 | 实例关闭 |
| 段渲染结果 | 本成员实例，唯一拥有者 | 段从登记面撤除后，下一次收到通知时丢弃 | 实例关闭。提供者撤除只释放实例，不另持有渲染结果 |
| 计划进度、压缩转换、最终请求记录 | 协调者与历史持有者 | 不在本成员 | — |
| 来源登记项与借用 | 登记表实例 | 进程失败即丢失，来源适配者重新登记 | 撤除并结算，或登记表关闭 |
| 账目索引与目标状态 | 账目投影实例 | 进程失败即丢失，从日志授权重建 | 实例丢弃；不清理原日志 |
| ④ 的块材料 | 调用方 | 不在本成员 | — |

登记表关闭：`close()` 拒绝新登记与新借用，撤除全部当前代际，等待每个代际的借用归零后兑现；有未归还的准备租约时结果为不可用，列出来源集合的拥有者。关闭后新的组装返回不可用（来源登记）。关闭不取消在途操作，也不撤回已交出的候选、计划或转换。缓存实现后，关闭同时释放缓存。

## 组合与验证

| 承诺 | 位置 |
| --- | --- |
| 操作组、来源集合、账目协议、四种结果、三类失败、六层布局、锚点、读口规则 | [request-context-contract SPEC](../request-context-contract/SPEC.md) |
| 贡献登记面与变化事件 | [request-context-cordis-contract SPEC](../request-context-cordis-contract/SPEC.md) |
| 输入快照与比对代替求值 | [装配与变化](../../../docs/architecture/runtime/assembly-and-change.md#比对代替求值) |
| 来源拥有者维护变更计数的义务 | 各来源拥有者的页面，不在本组 |

持续验证义务，随实现进入 `tests/`：

| 场景 | 必须检查的结果 |
| --- | --- |
| 七组逐项相同 | 复用层内容，不重算；⑥、装入裁定与结局按本次输入计算 |
| 「上一次准备」不同而七组相同 | 候选内容相同；结局按「上一次准备」分别得出，有缓存与无缓存一致 |
| 只有新输入 | 前四层字节不变，只重算尾部 |
| 七组各自变化 | 按「按组失效」表只重算对应层，前缀变化原因正确 |
| 逐请求值变化而修订不变 | ⑥ 按本次的逐请求值重算，不取旧缓存 |
| 别的作用域的贡献变化 | 本作用域的 ① 不失效，不记前缀变化原因 |
| 增量读取 | ④ 由调用方交入的最近一次完整读取的块材料生成；清空缓存后结果逐字相同 |
| 两个作用域的快照修订与锚点相同 | 快照提醒文本不串用，身份含作用域引用与资格身份 |
| 缓存项修订落后 | 作废，不返回旧内容 |
| 有缓存与无缓存 | 同输入结果逐字相同 |
| 读口 epoch 已变 | 丢弃已读页并重算，不拼接 |
| 修剪器 | 不改原记录，不改模型视图；只缩短交给摘要步的材料，在第一个摘要步之前完成，不记进度 |
| 计划与策略 | 换策略或改参数之后 `deriveStep` 返回无效 |
| 依赖缺席 | 返回不可用带诊断 |
| 默认策略数值 | 与配置初值一致，可被配置覆盖 |
| 窗口占用块 | 值是四种状态之一；重建前不可用，就绪且无固定请求为 `not-fixed` |
| 登记表 | 同键第二次登记为冲突；替换后旧借用不发布；旧句柄撤除不删后继；`settled` 等待借用归零 |
| 账目投影 | 新目标先重建再收账；同键同值认回、异值冲突、低修订不倒退；重建中不可用；重建失败保留旧索引；容量上限拒收不淘汰 |
| 复杂度 | 命中为七组比对；只有新输入时与新增消息数成正比；贡献变化只重算系统提示词；全重算只在访问身份、用途、消费位置或选定模型变化时发生 |

本成员不覆盖：持久化、共同提交、模型发送、真实协调者与持有者的端到端组合。
