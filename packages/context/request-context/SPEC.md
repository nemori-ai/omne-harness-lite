# @omne-harness/request-context 行为规格

状态：机制实现成员，`draft`，没有运行实现。本成员实现 Request Context 的纯操作、缓存、预计算派生物与默认策略。公开行为归 [request-context-contract SPEC](../request-context-contract/SPEC.md)。本页只写实现真实承担的本地行为：缓存键、按组失效、失效来源、预计算派生物、默认策略数值与修剪器行为。不重复契约条款。

## 范围与依据

本成员与 Cordis 无关（[IC-4](../../../docs/architecture/cordis-integration-conventions.md#ic-4)）。它导出一个工厂，输入是构造依赖（历史源读口、计量端口、转换件结果端口、两个策略实现）与配置，输出是实现契约纯操作的对象。贡献登记面与 isolate 绑定归 [request-context-cordis](../request-context-cordis/SPEC.md)。

原则：请求到了不算，算在请求之前。能在输入变化时维护的派生物不在组装时重算；组装时只做比对与拼装。输入快照的定义消费[比对代替求值](../../../docs/architecture/runtime/assembly-and-change.md#比对代替求值)。

本成员不持有任何耐久状态。缓存是进程内副本，失效后从输入重建，不改变任何结果。

## 结果与不变量

### 候选缓存

| 项 | 内容 |
| --- | --- |
| 键 | 七组输入各自的修订摘要的组合，覆盖七组的全部成员：调用身份与用途（访问身份、用途、消费位置、候选身份）；历史与新输入（历史依据的 epoch、上界与作用域引用，新输入批证据）；runtime context 读取结果（游标与代次、已采用与转换依据）；系统提示词（提示词贡献的登记修订、组装上下文的各不透明键。登记修订是整张登记表的修订，全局层或任一作用域层变化都使它前进）；模型侧（选定模型的档案与参数摘要）；工具侧（工具采用集合摘要）；当前条件与本次经过（条件修订、扩展改写依据、调模型之前位置的经过）。只排除「上一次准备」，它不改变候选应有的内容（[RQ-02](../request-context-contract/SPEC.md#rq-02-组装的前置输入)） |
| 命中 | 全部相等即返回已有候选，不重算 |
| 按组失效 | 只有新输入或历史上界变化：只重算历史体尾部与尾部易变提醒，前四层复用。提示词贡献变化：重算系统提示词，前缀变化原因记「系统提示词变了」。工具采用集合变化：重算工具声明，记「工具集合变了」。选定模型变化：全部重算，记「换了模型」。历史 epoch 变化：重算历史头（含压缩记录）与快照提醒，记「发生了压缩」。读取结果为完整：重算历史头到新锚点的部分与快照提醒，记「新的完整读取」 |
| 失效来源 | 变化通知而不是时间：历史持有者的提交通知、runtime context 的唤醒、贡献登记的变化事件、模型选择变更。每个来源携带修订或计数，缓存项记录它看到的值。不用文件时间，不用内容重哈希 |
| 通知入口 | 工厂返回的实例有 `notify(change)`。`change` 带来源修订或计数，种类是四个枚举值之一：`history`（历史持有者的提交）、`runtime-context`（runtime context 的唤醒）、`contributions`（贡献登记的变化）、`model-selection`（模型选择变更）。独立路径上由调用方把收到的通知转交这个入口；Cordis 路径上由 [request-context-cordis](../request-context-cordis/SPEC.md#结果与不变量) 订阅四种变化后调用它。本成员按种类使对应的组失效并预算派生物 |
| 容量 | 每个消费位置保留最近一个已固定候选加一个在算候选。候选是否已固定只由输入「已采用」得知：输入带已采用且七组逐项相同时返回原采用。本成员不另外记录固定状态。容量是配置初值 |

有缓存与无缓存的同输入结果相同。缓存项记录的修订落后于来源当前修订时，缓存项作废，不返回旧候选。

### 预计算的派生物

| 派生物 | 谁维护 | 何时 | 组装时做什么 |
| --- | --- | --- | --- |
| epoch 视图与前缀摘要 | 历史持有者 | 消息提交、压缩提交 | 只读页、比摘要 |
| 系统提示词各有序段的渲染结果 | 本成员，由贡献登记面驱动 | 贡献登记或撤销时 | 按变量求值拼接；段文本不重渲染 |
| 工具声明投影 | 本成员 | 工具采用集合变化时 | 直接取 |
| 快照提醒文本 | 本成员 | 完整读取时 | 锚定复用，直到下一次完整读取 |
| 表示决定（派生表示、transcript） | 内容拥有者 | 消息接纳前 | 取引用，不转换 |
| 计量结论 | Model 的计量端口 | 组装时对改写后的完整输入一次 | 复用同输入摘要与同计量组合的结论 |

### 默认策略与修剪器

压缩策略默认实现的配置初值如下。三个数值现在都标「待重核」：它们来自同类系统的取证，按本项目的计量口径重核后才作为初值生效。

| 配置项 | 默认 | 状态 |
| --- | --- | --- |
| 触发界线 | 窗口的 80% 与「窗口减输出预留减余量」两者的较小值 | 待重核 |
| 保留预算 | 窗口减输出预留的 16%，作用于保留名单 | 待重核 |
| 保留偏好 | 较新优先 | 不涉及数值 |
| 修剪优先 | 是 | 不涉及数值 |
| 步数上界 | 3 | 待重核 |

这些项都是配置字段，默认值只是初值（[IC-14](../../../docs/architecture/cordis-integration-conventions.md#ic-14)）。

修剪器默认实现：只缩短交给摘要步的材料中超过阈值的工具结果与媒体占位，保留原消息身份与占位的引用，不改原记录，不改模型视图。阈值是配置初值。修剪只缩短交给摘要步的材料，不改变装入裁定；修剪步之后必有摘要步。

表示策略默认实现：同一块有多种表示可用时按模态的偏好顺序选，原件优先于派生表示，派生表示优先于 transcript；工具内容引用标待加载。偏好顺序是配置初值。

### 本地行为

- 同一候选身份内再次 `assemble`，先比缓存键；键相同返回已有候选，不重算（[RQ-01](../request-context-contract/SPEC.md#rq-01-调用方与计算边界)）。
- 读口返回「epoch 已变」时，本次组装丢弃已读页，用返回的当前依据重取并重算，不拼接（[H2](../request-context-contract/SPEC.md#历史源读口与-epoch-视图)）。
- 前缀摘要比较在每层锚点处各做一次，不逐条比对（[H3](../request-context-contract/SPEC.md#历史源读口与-epoch-视图)）。
- 任一构造依赖缺席或返回不可用时，相关操作返回不可用，带诊断，不伪装成功。
- 计划进度不在本成员保存。`deriveStep` 只接受调用方传回的进度，核计划身份与已完成步数后给出下一步；核不过返回无效（[计划操作的结果](../request-context-contract/SPEC.md#计划操作的结果)）。

## 所有权、失败与生命周期

| 事物 | 拥有者 | 失败时 | 结束 |
| --- | --- | --- | --- |
| 候选缓存与派生物 | 本成员实例 | 进程失败即丢失，从输入重建 | 实例关闭 |
| 渲染结果 | 本成员，随贡献登记 | 贡献撤销即丢弃 | 贡献退出 |
| 计划进度、压缩转换、最终请求记录 | 协调者与历史持有者 | 不在本成员 | — |

实例关闭：新的组装返回不可用（实例已关闭），等在途组装结算，释放缓存。关闭不撤回已交出的候选、计划或转换。

| 来源拥有者维护变更计数的义务 | 各来源拥有者的页面，不在本组 |

持续验证义务，随实现进入 `tests/`：

| 场景 | 必须检查的结果 |
| --- | --- |
| 七组逐项相同 | 命中，不重算 |
| 只有新输入 | 前四层字节不变，只重算尾部 |
| 贡献变化、工具集合变化、模型变化、epoch 变化、完整读取 | 各自只重算对应层，前缀变化原因正确 |
| 缓存项修订落后 | 作废，不返回旧候选 |
| 有缓存与无缓存 | 同输入结果逐字相同 |
| 读口 epoch 已变 | 丢弃已读页并重算，不拼接 |
| 修剪器 | 不改原记录，不改模型视图；只缩短交给摘要步的材料，修剪步之后必有摘要步 |
| 依赖缺席 | 返回不可用带诊断 |
| 默认策略数值 | 与配置初值一致，可被配置覆盖 |
| 复杂度 | 命中为七组比对；只有新输入时与新增消息数成正比；贡献变化只重算系统提示词；全重算只在模型切换时发生 |

本成员不覆盖：持久化、共同提交、模型发送、真实协调者与持有者的端到端组合。
