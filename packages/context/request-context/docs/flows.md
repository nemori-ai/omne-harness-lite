# Request Context 派生计算的流程

本页给出本成员的三条机制级流程。每条有一张时序图和一张「失败与责任交接」表。行为以 [SPEC](../SPEC.md) 为准，图只投影条款，不表示运行实现已经存在。

协议级流程归 [request-context-contract 的协议流程](../../request-context-contract/docs/flows.md)，本页的流程是它们在实现内部的展开。贡献登记、变化事件与 Cordis 装卸归 [request-context-cordis-contract 的流程](../../request-context-cordis-contract/docs/flows.md)与 [request-context-cordis 的流程](../../request-context-cordis/docs/flows.md)。图中的「实例」是工厂的输出，内部模块见[内部架构](architecture.md#模块与依赖)。

## 流程

### F-RQI01 缓存命中与按组失效

协议流程：契约的 F-RQ01、F-RQ02 与 F-RQ05。条款：[候选缓存](../SPEC.md#候选缓存)、[本地行为](../SPEC.md#本地行为)、[RQ-01](../../request-context-contract/SPEC.md#rq-01-调用方与计算边界)、[H2、H3](../../request-context-contract/SPEC.md#历史源读口与-epoch-视图)。

前提：调用方给出七组输入，其中带上一次已采用的覆盖证据。实例在同一消费位置上可能已有缓存项。

```mermaid
sequenceDiagram
  participant C as 调用方
  participant I as 实例 assemble
  participant K as 候选缓存
  participant H as 历史源读口
  participant M as 计量端口
  C->>I: 七组输入
  I->>K: 按消费位置取缓存项，逐组比较修订摘要
  alt 七组全部相等，且来源修订没有超过缓存项记录的值
    K-->>I: 已有候选
    I-->>C: 已有候选，不重算
  else 某几组变化，或缓存项的修订落后
    I->>H: 按锚点读页
    H-->>I: 一页，或 epoch 已变
    alt epoch 已变
      I->>I: 丢弃已读页，用返回的当前依据重取
    end
    I->>I: 在各层锚点处比较前缀摘要
    I->>I: 只重算变化的组所在的层，其余层复用
    I->>M: 计量改写后的完整输入
    M-->>I: 预算报告
    I->>K: 写入新的在算候选与它看到的修订
    I-->>C: 新候选，覆盖证据记前缀变化原因
  end
```

| 环节 | 结果 | 失败与责任交接 |
| --- | --- | --- |
| 比较缓存键 | 七组逐项比较修订摘要，覆盖七组的全部成员。只有上一次准备不参与比较 | 命中只说明计算可以省略，不说明候选已经固定 |
| 修订落后 | 缓存项作废，不返回旧候选 | 来源拥有者要在变化时前进修订。来源不给修订时不能命中 |
| 按组重算 | 只有新输入时，前四层逐字不变，只重算尾部 | 各组对应哪一层见[内部架构的按组失效](architecture.md#按组失效只重算受影响的层) |
| epoch 已变 | 本次组装丢弃已读页并重算 | 不拼接两个 epoch 的页 |
| 前缀比较 | 每层锚点处比较一次摘要 | 不逐条比对。摘要不等的唯一原因是 epoch 变化 |
| 依赖缺席 | 读口、计量端口或转换件结果端口缺席或不可用时，返回不可用，带诊断 | 不伪装成功，不用旧页或其他租户的内容代替 |
| 有缓存与无缓存 | 同一组输入的结果逐字相同 | 不同即是缺陷，归本成员 |

### F-RQI02 预计算派生物在贡献变化时重算

条款：[预计算的派生物](../SPEC.md#预计算的派生物)、[候选缓存](../SPEC.md#候选缓存)、[RQ-02](../../request-context-contract/SPEC.md#rq-02-组装的前置输入)。

前提：一个贡献者在登记面登记或撤销了一条贡献，登记修订前进。登记面归 [request-context-cordis-contract](../../request-context-cordis-contract/docs/cordis.md#登记与撤除协议)。实例怎样得知这次变化还没有定义，见[公开接口页](public-api.md#随实现进入的导出)。

```mermaid
sequenceDiagram
  participant R as 贡献登记面
  participant I as 实例
  participant D as 派生物
  participant K as 候选缓存
  participant C as 调用方
  R->>R: 登记或撤销，登记修订前进
  R-->>I: 变化，带作用域引用与新的登记修订
  alt 登记
    I->>D: 渲染新段的文本，记下来源与修订
  else 撤销
    I->>D: 丢弃这条贡献的渲染结果
  end
  Note over K: 缓存项记录的登记修订落后，下一次比较时作废
  C->>I: assemble，第四组带新的贡献集合
  I->>D: 取段的渲染结果
  I->>I: 按变量求值拼接，段文本不重渲染
  I-->>C: 新候选，前缀变化原因记「系统提示词变了」
```

| 环节 | 结果 | 失败与责任交接 |
| --- | --- | --- |
| 预计算 | 段文本在贡献变化时渲染一次 | 组装时不重渲染段文本，只按变量求值拼接 |
| 撤销 | 渲染结果随撤销丢弃 | 撤销之后的组装不含这条贡献。已经交出的候选不撤回 |
| 缓存失效 | 记录旧登记修订的缓存项作废 | 只重算系统提示词。工具声明、历史与快照提醒复用 |
| 逐请求变量 | 带逐请求变化变量的段在登记时已被拒绝 | 拒绝归登记面。组装时遇到这样的段，按无效返回（[RQ-05](../../request-context-contract/SPEC.md#rq-05-完整预算与候选完成)） |
| 其他派生物 | 工具声明投影在工具采用集合变化时重算，快照提醒文本在完整读取时重算 | 快照提醒在下一次完整读取之前锚定复用 |

### F-RQI03 压缩策略选择与修剪

协议流程：契约的 F-RQ03。条款：[默认策略与修剪器](../SPEC.md#默认策略与修剪器)、[本地行为](../SPEC.md#本地行为)、[RQ-06](../../request-context-contract/SPEC.md#rq-06-压缩共同结果与保护边界)。

前提：工厂调用方在构造时传入了压缩策略实现，可以是本成员的默认实现。这次请求准备尚未进入压缩计划。

```mermaid
sequenceDiagram
  participant F as 工厂调用方
  participant I as 实例
  participant S as 压缩策略
  participant T as 修剪器
  participant C as 协调者
  F->>I: 工厂(构造依赖, 配置)，选定压缩策略
  C->>I: assemble
  I->>S: 按触发界线判断
  S-->>I: 需要压缩
  I-->>C: 需要压缩
  C->>I: planCompaction
  I->>S: 定覆盖范围，在保留预算内按保留偏好选保留名单，定步数上界
  I-->>C: 计划身份、步数上界、第一步，进度为零
  C->>I: deriveStep(计划, 进度, 上一步结果)
  I->>I: 核计划身份与已完成步数
  I->>T: 修剪步：缩短交给摘要步的材料
  T-->>I: 修剪后的材料，原记录与模型视图不变
  I-->>C: 修剪后的材料、下一步（摘要步）与新进度
  C->>C: 保存进度，发起摘要步
  C->>I: deriveStep(计划, 进度, 摘要结果)
  I-->>C: 压缩转换，或装不下
```

| 环节 | 结果 | 失败与责任交接 |
| --- | --- | --- |
| 选择策略 | 工厂调用方传入压缩策略。经 Cordis 时由 [request-context-cordis](../../request-context-cordis/docs/cordis.md#配置与策略选择) 按配置选择 | 实例构造后不换策略。换策略就是新建实例 |
| 触发界线 | 默认实现取窗口的 80% 与「窗口减输出预留减余量」两者的较小值 | 数值是配置初值，重核之前不作为初值生效 |
| 保留名单 | 默认保留预算为窗口减输出预留的 16%，作用于保留名单。默认较新优先 | 未结工作的条目集合由历史持有者给出。它是保留名单的下界，不是策略的选择（[RQ-06](../../request-context-contract/SPEC.md#rq-06-压缩共同结果与保护边界)） |
| 步数上界 | 默认 3，修剪优先 | 上界在计划给出时定下，之后不变 |
| 核进度 | 计划身份或已完成步数对不上时返回无效 | 进度只由调用方保存，本成员不保存 |
| 修剪步 | 只缩短超过阈值的工具结果与媒体占位，保留原消息身份与占位的引用 | 不改原记录，不改模型视图。修剪步不调用模型，仍记一步进度 |
| 进入摘要步 | 修剪步之后必有摘要步。修剪只缩短交给摘要步的材料，不改变装入裁定 | 主请求的模型视图在修剪后不变，所以计划必须经摘要步得到压缩记录（[RQ-06](../../request-context-contract/SPEC.md#rq-06-压缩共同结果与保护边界)） |
| 用完或被否决 | 按压缩后仍装不下处理 | 不在相同条件下重开计划 |

## 失败与生命周期

| 情形 | 结果 | 责任方 | 依据 |
| --- | --- | --- | --- |
| 构造依赖缺席或不可用 | 相关操作返回不可用，带诊断 | 工厂调用方补齐依赖 | [本地行为](../SPEC.md#本地行为) |
| 缓存项修订落后 | 作废，重算 | 本成员 | [候选缓存](../SPEC.md#候选缓存) |
| 读口返回 epoch 已变 | 丢弃已读页，重取重算 | 本成员 | [H2](../../request-context-contract/SPEC.md#历史源读口与-epoch-视图) |
| 计划身份或进度对不上 | 返回无效 | 调用方按保存的进度重新调用 | [本地行为](../SPEC.md#本地行为) |
| 实例关闭 | 新的组装返回不可用（实例已关闭），等在途组装结算，释放缓存 | 关闭方 | [SPEC 所有权、失败与生命周期](../SPEC.md#所有权失败与生命周期) |
| 关闭之后 | 不撤回已交出的候选、计划或转换 | 协调者与历史持有者 | 同上 |
| 进程失败 | 缓存与派生物丢失，从输入重建 | 本成员，结果不变 | 同上 |

各内部对象的创建与结束见[对象模型](object-model.md#生命周期)。
