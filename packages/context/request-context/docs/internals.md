## 4. 一次请求的完成与失败交接

一次请求的完整时序见 [RC-F06](key-flows.md#rc-f06)，压缩与预算失败见 [RC-F07](key-flows.md#rc-f07)。这些流程同时适用于主流程、压缩、扩展及独立调用，由各自原发起者承接。

发起成功与派生计算成功分别记录。发出结果未知时，按原调用身份对账，不把一次传输错误当成整项调用结束，也不由 Request Context 新建调用重发。

压缩内部模型调用有原身份、费用和消费位置。其结果先可靠承接，回压缩处理，不直接当主流程回复。压缩完成只追加摘要与排除名单，未读输入和未结占位保持，补全合法 Context 后复核整个请求。

固定部分超限与压缩后仍超限交原消费协调者。该协调者使消费契约指定的仍有效未终态 Run 失败，不能修改旧终态或借新的组装复活原 Run。独立计算或调用返回失败，不造 Session。

## 5. Tool 结果准入与旁路边界

[RC-F05](key-flows.md#rc-f05)按输入、模型回复和 Tool 结果区分否决后果。转换件技术约束由 [Model 共同契约](../../../model/model/docs/profile-and-modality.md#转换件的共同契约)维护，Request Context 消费接纳后固定的表示，不能在组装时重写历史。

Tool 拥有原结果与真实收场，并在可靠交接前持续保管原结果。消费者可先可靠保存所需内容或有效引用及原消费位置，再进行消息准入或转换；也可在 Tool 仍可靠保管时先完成处理，保存必要完成事实后再按原协议解除交付关系。开始处理或展示不等于完成处理，处理失败不能解除原责任。两条路径详见[Tool 可靠交接](../../../tool/tool-contract/SPEC.md#先可靠承接再处理结果)。否决不删除原结果，也不重跑外部工具来换结果。

否决使消费契约指定的仍有效未终态 Run 失败。后台、Run 外及旧 Run 已终态的结果，保留原归属和责任；不得默认挂后继、造 Run、恢复取消后的入队资格或反转旧终态。尚未定的旁路处置交原消费拥有者，只有依赖部分待设计。

MODEL-E01 仍缺最终允许块全集和嵌套投影依据。当前图与实际模型可读检查保留，但不按帧协议定义最终结果语法，也不另造递归机制。
