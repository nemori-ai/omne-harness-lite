# tests

本目录承载本包适用的持续测试。测试种类的责任与边界见仓库[包级测试责任与边界](../../../../docs/verification.md#包级测试责任与边界)。

## 允许的内容

`*.spec.ts` 运行测试、`*.spec-d.ts` 类型测试、测试辅助代码，以及 `fixtures/` 下的固定输入。

## 边界

本成员与 Cordis 无关，测试直接调用工厂，不装载 Cordis。来源集合、准备资源、采用来源与读取资格用契约 `./testing` 入口的内存替身，它们能前进计数、返回「epoch 已变」、拒绝与不可用，才能覆盖失效与失败的场景。持久化、共同提交、模型发送与真实协调者、持有者的端到端组合不在本目录。测试通过不代替规格或验收。

## 维护

公开行为或 SPEC 条款变化时，同步对应测试与本目录 `index.md`。工厂进入根入口时，同一次修改要更新导出测试。默认值改变时，同步核对默认数值的测试。

## 本包事实

- [public-entry.spec.ts](public-entry.spec.ts)：根入口的导出名单，以及每个导出的类型。
- [default-policies.spec.ts](default-policies.spec.ts)：默认压缩策略的配置初值与校验、保留名单（预算、按窗口取比例、调用与结果不拆开、窗口之后的结果迫使调用保留、保留名单超预算、未知计量、两种保留偏好）、修剪器（只缩短工具结果文本、取较小阈值、不改原记录、不切断字符）、摘要指令，以及默认表示策略（偏好顺序、派生表示的模态检查、不伪造转换）；两个策略各跑一遍契约的策略一致性套件。
- [default-assembly.spec.ts](default-assembly.spec.ts)：默认策略放进真实操作组：固定历史组装出的请求被 Model 请求准备替身接受、同输入同请求、计划的保留名单配对且不超预算、第 2 轮带 continuation 事实时准备租约收到 `lineage.continues`。
- [conversion-results.spec.ts](conversion-results.spec.ts)：缺席的转换件结果读口答没有条目的索引、跨租户答无权、纯文本历史照常组装。
- [registry.spec.ts](registry.spec.ts)：同键冲突、授权结论、代际不复用、旧句柄撤除不删后继、`settled` 等待在途借用、替换后旧借用不发布、关闭与未归还租约的拥有者，按代际记录的租约交还（主失败与交还失败都保留、关闭前已结算的泄漏仍报告、同一拥有者只列一次）、外部租户得到与未登记相同的答复、授权等待期间的并发与关闭，以及 `assembly(target)` 跑契约操作组的全部一致性用例。
- [accounting.spec.ts](accounting.spec.ts)：`limits` 必填、未初始化不可用、同值认回与异值冲突、低修订不倒退、核验顺序、核验结论保留类别、事实容量拒收不淘汰事实、系统恢复访问、重建失败与异常、重建中不可用、窗口占用四种状态、旧调度的账目不顶替、采用来源持续变化为不可用、跨租户拒绝；另有收件口的形状与核验顺序、每次发出的修订上限、核验等待中开始重建、已知用量的口径（暂定、缺项、非 token、重复项）、采用事实的边界解码、各次读取失败的类别、发布前计数变化与资格撤回、发布前投影换代，以及重建的访问、容量名额、失败与异常收尾；另有「目标淘汰（CX-11）」一组：最久未用先走、使用与收账都算用、在途的 `usage` 或 `receive` 不被淘汰、全部在途时预检拒绝且不拉取重放、发布时候选变忙则拒绝、重建失败不淘汰、重建中的目标不是候选、被淘汰目标的 `usage` 与 `receive` 同未初始化（E10）、淘汰后重放得到同样的投影、满目标仍拒收事实。
- [trust-conformance.spec.ts](trust-conformance.spec.ts)：用 request-context-cordis-contract 的 `./testing` 信任套件，对真实来源登记表逐用例运行。

没有 `*.spec-d.ts` 类型测试。

运行方式：在仓库根执行 `pnpm turbo run test --filter=@omne-harness/request-context`，或在本包目录执行 `pnpm test` 与 `pnpm typecheck`。

当前缺口：SPEC [组合与验证](../SPEC.md#组合与验证)中缓存、派生物与复杂度的场景随实现进入。复杂度场景需要测量，不只是断言。具名维护者由负责人指定。
