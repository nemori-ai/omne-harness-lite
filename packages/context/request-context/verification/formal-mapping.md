# 拟定请求缓存的代际发布、撤代与借用：性质、模型与实现的对应

[CandidateCache.tla](cache/CandidateCache.tla) 检查拟定请求缓存在代际发布、撤代、借用、历史追加、压缩、资格变化与重叠调用之间的交错。规则归[包组规格](../../SPEC.md#七组稳定读取与来源登记)。模型检查只说明给定抽象和有限范围内的性质，不证明实现符合模型，也不证明真实来源的页协议满足模型的假设。

## 状态与动作

每个配置有一个目标（一个租户、一个作用域）、两个本租户主体、一个外租户主体与两次或三次一次性的调用。历史存储是一个 epoch 加行数。一行的内容由代际、epoch 与序位标识：同一序位在不同代际或不同 epoch 下是不同内容。缓存是每主体一个槽位，槽位有修订号。

| 状态变量           | 含义                                                                                   |
| ------------------ | -------------------------------------------------------------------------------------- |
| `gen`、`withdrawn` | 登记表当前代际与撤除标记。`Replace` 换代，`Withdraw` 撤除，二者都是撤代                |
| `epoch`、`len`     | 历史存储的 epoch 与行数。`Append` 加一行，`Compact` 换 epoch 并可缩短                  |
| `allowed`          | 读取资格权威对每个本租户主体的当前判断。可随时撤销与重授                               |
| `cache`、`rev`     | 槽位内容与槽位修订                                                                     |
| `req[r]`           | 每次调用的阶段、主体、借用代际、准入与复核时的真实资格、载入材料、交出的行与源读行数等 |
| `regressed`        | 观察用：提交是否用更旧的计算覆盖了同代际更长或更新的槽位                               |

| 动作                    | 状态变化与抽象边界                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------ |
| `Begin(r, p)`           | 核访问租户、登记表是否撤除、读取资格。外租户直接无权                                                   |
| `Load(r)`               | 事务读自己的槽位与修订。借用代际撤代之后，调用看到清空的存储，不看到后继代际的提交                     |
| `Read(r)`               | 历史组的一次读取，抽象为一个原子步骤。有同 epoch 的材料时复用其行，只读其后的尾部，否则全读            |
| `Recheck(r)`            | 结果离开操作组之前的最后一次资格观察                                                                   |
| `Publish(r)`            | 登记表的同步发布段。借用代际不是当前代际时结果为不可用且不提交；否则槽位修订未变时暂存材料成为槽位内容 |
| `Append`、`Compact`     | 历史持有者的追加与压缩                                                                                 |
| `Replace`、`Withdraw`   | 登记拥有者的换代与撤除，二者都清空缓存                                                                 |
| `Revoke(p)`、`Grant(p)` | 资格权威撤销与重授一个本租户主体                                                                       |

## 性质表

| 编号 | 性质                                                               | 规格不变式 | 模型里的性质                                               |
| ---- | ------------------------------------------------------------------ | ---------- | ---------------------------------------------------------- |
| S1   | 撤代之后旧代际的派生物不再发布、不再被使用                         | CX-39      | `NoStalePublication`、`CacheIsCurrent`、`Equivalence`      |
| S2   | 每次请求重新核授权，命中不绕过；发布前复核真实执行；外主体不能命中 | CX-40      | `Authorized`、`RecheckedEligible`、`HitBelongsToPrincipal` |
| S3   | 稳定层加连续新增尾等于全量重算；跨 epoch 不拼接                    | CX-40      | `Equivalence`、`CacheContiguous`                           |
| C1   | 可复用的前缀还在槽位里时，一次请求的源读行数只与新增数有关         | —          | `TailReadBound`                                            |
| C2   | 较晚返回的旧计算不覆盖较新缓存                                     | CX-40      | `NoRegression`                                             |

`Authorized` 看准入那一刻的资格，`RecheckedEligible` 看复核那一刻的资格。两次观察之间资格可以被撤销，所以两条各自成立，不互相蕴含。

## 模型与源码

| 模型边界                         | 实现入口                                                                                                                                      |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `Begin` 的租户、撤除与资格检查   | `src/registry.ts` 的 `borrowed()`；`request-context-contract` `src/operations.ts` 的 `begin`                                                  |
| `Load` 在准入之后、不核授权      | `operations.ts` 的 `run` 在 `begin` 通过后才载入；`src/cache.ts` 的 `load`；取用前 `reuse.ts` 的 `materialBelongs` 另核主体、代际、用途与目标 |
| 存储属于借用的代际               | `registry.ts` 每个代际建一个 `GenerationCache`，撤代时清空                                                                                    |
| `Read` 的同 epoch 续读与首行连续 | `request-context-contract` `src/history-read.ts` 的 `readHistory`、`start`、`validPage`、`takePage`                                           |
| `Recheck`                        | `operations.ts` 的 `publish` 再次核资格                                                                                                       |
| `Publish` 的代际核对与提交       | `registry.ts` 的 `borrowed()`：异步工作结束后同步核代际，再提交事务，其间没有 `await`                                                         |
| 槽位修订与重叠提交               | `cache.ts` 的 `commit`：清空之后开始的事务整体放弃，逐槽比较载入时的修订                                                                      |

实现必须满足的动作守卫，与负控一一对应：

1. 发布段在同一同步步骤里核借用代际仍是当前代际，之后才交出结果与提交暂存（`bad-publish-check`）。
2. 撤除与替换使该代际的缓存不再被任何新借用读到（`bad-retire-clear`）。
3. 热路径不省略准入时的资格检查，也不省略发布前的资格复核（`bad-auth-hit`、`bad-skip-recheck`）。
4. 槽位键至少包含主体键；目标与代际由存储归属保证（`bad-shared-key`）。
5. 续读的第一行必须紧接前缀末序位，页内连续，否则按原无效结果返回，不拼接（`bad-gap`）。
6. 前缀的 epoch 与本次依据不同时不续读（`bad-epoch`）。
7. 提交时比较载入时的槽位修订，修订已变时丢弃本次暂存，结果仍可交出（`bad-overwrite`）。

## 配置的预期

正控的预期是没有反例；负控只声明一条性质，预期是它被违反。

| 配置                | 预期                    | 反例的含义                                   |
| ------------------- | ----------------------- | -------------------------------------------- |
| `valid-pairs`       | 无反例                  | 两次调用，不用对称缩减                       |
| `valid-cache`       | 无反例                  | 三次调用，对调用与本租户主体使用对称缩减     |
| `bad-publish-check` | `NoStalePublication`    | 借用中换代后照常发布                         |
| `bad-retire-clear`  | `Equivalence`           | 新代际复用旧代际前缀，交出的行混有旧代际内容 |
| `bad-auth-hit`      | `Authorized`            | 撤权后的主体靠热缓存取得结果                 |
| `bad-gap`           | `Equivalence`           | 续读接受晚一行开始的页，交出的行缺一行       |
| `bad-shared-key`    | `HitBelongsToPrincipal` | 同租户另一主体载入他人材料                   |
| `bad-epoch`         | `Equivalence`           | 压缩后旧 epoch 前缀拼上新 epoch 尾部         |
| `bad-overwrite`     | `NoRegression`          | 先读短、后发布的调用覆盖更长的前缀           |
| `bad-skip-recheck`  | `RecheckedEligible`     | 准入后撤权，发布前不复核，调用仍交出结果     |

## 假设与范围

- 历史在同一 epoch 内只追加，长度不回退。来源的页故障只建模了「第一页晚一行开始」一种。
- 一个目标、一个用途、一个消费位置；三次调用、三行历史、两个 epoch、两个代际。
- 没有容量淘汰。淘汰的结果等同于槽位缺失：下一次调用按全量读取，内容不变。淘汰与重叠调用的交错没有展开。
- 没有建模准备租约、结算、关闭、独立操作组、计划的判断窗口与各层的按组失效。`Equivalence` 不说明投影、可见性、回放或压缩保留语义，这些由契约成员的用例承担。
