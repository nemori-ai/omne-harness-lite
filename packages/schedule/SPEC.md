# 日程

## 总体架构

日程包组回答一个问题：一份「什么时候做什么」的安排怎样被完整地保存、按明确的时间与日历依据预测，到期时怎样在一个一致的边界里被接受成一份固定的 Job，并把这份 Job 的执行、通知与结果如实结算，而不重做、不漏记、不越权。

| 成员                       | 回答的问题                                                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `schedule-contract`        | 安排定义、规则、工作意图、候选、操作回执、读值与服务端口长什么样；共同编码与指纹算法。纯数据与 schema，不依赖 Cordis 与存储 |
| `schedule`                 | 规则计算与预测、安排的管理决定、只读查询、接受与 Job 的规则。不依赖 Cordis，不选存储后端，不认识 Session 与 Agent           |
| `schedule-cordis-contract` | 日程在这套系统里以哪些服务出现：命令、查询等服务的定义与键                                                                  |
| `schedule-local`           | 本机的 SQL 管理后端与原操作恢复、计算工作线程、本地应用组合、日历环境投影，以及 Cordis 提供者                               |
| `schedule-tools`           | 给 agent 的日程工具：九个动作的参数与结果、可信上下文与原操作键的取得、固定结果详情的读取                                   |

依赖只朝契约：`schedule-local` → {`schedule`、`schedule-cordis-contract`、`schedule-contract`、`sql-contract`、`calendar` 的公开契约与服务定义}；`schedule-tools` → {`schedule-cordis-contract`、`schedule-contract`、Tool 的公开作者协议}；`schedule` → {`schedule-contract`、`calendar-contract`}。管理命令先由纯函数在当前事实上做决定，再由存储参加者在一次提交里写入定义、修订、额度效果、outbox 与回执。预测在固定依据上只读地展开候选；接受在一致的保护边界里重新核对依据、资格、控制、次数与重叠，形成固定的 Job，交给自有的执行端口 `JobExecutor`，由外部适配器去跑程序或交给 Session。

## 领域边界

日程拥有：安排（Schedule）的身份、完整定义、修订、管理状态与谱系；规则计算与预测；候选（按规则算出、还没有被接受的一次触发，契约里的 `ScheduleCandidate`）、来源去重与两种次数；接受与 Job 的固定要求；后续控制、补跑与重叠；单次取消的判序；本组声明的通知义务与整份结算；系统订阅与作者同意的记录；历史与读面。Routine 只是安排内容的一部分，没有独立身份。

日程不拥有：日期知识与版本（日历）；用户的时区与日历选择（设置）；主体、授权、同意与额度的权威（身份与授权、资源治理）；会话、Run、消息种类与推进（Session），Agent 的定义与发布（资产）；通知的受理与送达（通知）；成果的发布与归档（结果与归档的提供者）；会话内的自我唤醒（Session）。日程不导入 Session 与 Agent 的类型或服务，不读别的领域的私有表。

本组只认通用角色：可信上下文里的主体与租户、系统归属、调用方给出的原操作键、外部引用（定义、会话、回传目标）都是不透明引用。

本组需要、由别人提供的：

| 需要                                            | 对方                                                      | 本组需要它做什么                                                 |
| ----------------------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------- |
| 日历查询与版本依据                              | 日历（`packages/calendar`）                               | 按明确身份与 `latest` 或 `pinned` 计算日别与工作日，带回实际版本 |
| 环境读取（同一修订的时区与日历）                | 设置，经日历的环境读取端口                                | 一次读到同一修订的时区与日历；缺值与不可用分开                   |
| 当前资格、同意与额度的守卫                      | 身份与授权、资源治理（`QuotaParticipant`）                | 在接受与管理的同一提交里给出可栅栏的决定，带决定时刻             |
| 具名命令与事务参加者                            | 存储（`sql-contract`）                                    | 一次提交写入定义、修订、额度、outbox 与回执；原操作查询          |
| `JobExecutor`（检查前提、开始、查询、请求停止） | 程序执行与 Agent 执行的外部适配器（经 Session 的 intake） | 按冻结的意图开始原 Job，报告真实的开始、停止与终态               |

| 工具作者协议与结果保管                          | Tool                                                      | 登记工具贡献，保管完整结果并按当前资格读回                       |

本组为别人提供的：

| 提供                                             | 对方                      | 本组提供什么                               |
| ------------------------------------------------ | ------------------------- | ------------------------------------------ |
| 命令服务（创建、修改、控制、原操作查询）         | 人、agent、系统功能、应用 | 完整保存、草稿转正、替换、暂停、恢复、结束 |
| 查询服务（列表、详情、修订、执行、日程表、预览） | 应用、`schedule-tools`    | 只读呈现原采用、结果、新鲜度与未完责任     |
| 服务定义与键                                     | Cordis 装配               | 唯一的服务定义；提供者继承它               |
| 工具（九个动作）                                 | Tool 与 agent             | 管理与查询安排                             |

## 心智模型

把一份安排想成「一条规则加一份固定的工作意图」，它自己不做任何事。时间一到，候选只是可以重算的建议；只有在接受那一刻，按当下的依据、资格、控制、次数与重叠全部重核通过，才铸成一份 Job，而 Job 一旦铸成就固定了：之后改安排、日历出新版、用户换时区，都不回头改它。安排管「以后还接不接」，Job 管「这一份做到哪了」，两件事分开控制。

日程与执行之间是远程调用。Job 交给 `JobExecutor` 之后，开始、停止、终态都由执行方报告；不知道就是不知道，按原 Job 与原操作查回，不新建会话、不重发指令、不重做工作。成功也分开记：执行达成、通知送达、成果发布、归档各有各的依据，一项成功不替另一项作证。

最容易想错的几处：预览不是批准，读得到不授写权；定时器只是唤醒提示，醒了不等于到了；暂停未来与取消这一份工作是两件事；接受了的通知不等于送达；`existing` 会话失效不能退回新建会话；Run 结束、普通回复或上报成功都不是目标达成；停止请求被受理不是前序已经停下。

## 应然设计

### 身份、来源与归属

- 安排、Job、操作发起者、出厂来源与通知目标分别可辨。租户身份是组织与账号的共同身份；系统自用有明确的系统归属，不伪造特殊租户。会话归档或运行实例退出不改变安排与 Job 的身份。
- Routine 是安排的内容：采用预置之后内容归安排持有，之后改预置不回写，改安排也不反改预置；没有独立的 Routine 增删改。
- Job 保存独立的创建来源：人直接创建没有来源会话；agent 直接创建必须有可信来源会话；调度器创建必须关联有效的安排与本次时隙。定时 Job 另存安排作者及其来源会话，调度器不是作者；所有者不由触发者反推。来源会话、执行会话与回传目标分别校验，不相互缺省。
- 人与 agent 直接创建 Job 时不创建安排、不伪造时隙；核验同意、授权、资源与所需能力后原子保存 Job、来源、回执与初始交接责任；同一批准请求重试只认回原 Job；缺同意拒绝，不生成待确认 Job。公开入口不接受调用方伪造的调度器来源。

### 资格与披露

- 创建、修改、控制、预览与查询、接受与开始、取消、资源动作与通知披露分别核当前资格。持有服务、工具可发现、同账号或系统调度不代替授权；未授权的跨租户默认拒绝，不改投另一身份，组织管理员不借此取得成员的私有安排。
- 保存过的授权不是未来动作的永久许可；单次或本会话授权不复制给新的作业会话。后台、缓存、索引、读面与诊断保留同一归属与字段披露。撤权与接受、开始、披露的竞争受实际保护边界约束，已发生的效果如实记录。

### 保存、草稿与替换

- 创建与更新使完整的工作内容、时间、适用声明与管理事实一起成立，失败不留半份生效。日期处理、补跑与重叠明确选择；组合通知明确非空的事件、内容与目标；参数与工作类型匹配。
- 创建必须明确是生效还是草稿。草稿不参与扫描、预算、准备、接受或发送，可完整修订，丢弃是终态。转正以当前主体、修订条件、同意与依赖重新核验，从严格未来的第一个有效时刻开始，记录转正者与时刻，重试认回原结果。
- 非重要的文本（标签、agent 指令、提醒内容）原地更新，保持管理状态；目的、时间结构、程序与输入、会话模式或目标、绑定的变化必须原子替换：同一提交停止旧安排的后续、建立新安排与双向的前后继、转移额度；失败没有半个后继；旧 Job 与历史保留；新后继从严格未来起算。终态不能被更新、转正或重授复活。
- 并发的修改或控制前提变化时重核或冲突，不覆盖后来确认的事实。

### 时间规则

- 一次性保存明确的本地日期时刻，相对表达在保存时固定；创建时已经过去或落在夏令时缺口里的拒绝。
- 常规的日、周、月、自然季度、年重复有正整数间隔、起算与明确的日期、星期、时刻，周从周一开始；同一规则里可以列多个月份、星期或时刻，不以多份安排代替。位置型只有「所选月、季度或年内第 N 个或最后一个指定星期几或工作日」，N 为正整数。
- cron 是标准五字段、分钟精度，拒绝秒字段、宏、随机散列与专有语法；日与星期同时受限时取并。rrule 正文只放规则属性，起算、次数与截止只在独立字段里；源可表达的规则全部属于接受范围，库能解析不等于新增承诺。
- 计算时区、包含的开始、可选的截止（包含且晚于开始）、两种次数上限与排除日期明确；排除日期按规则时区排除当日全部候选。不存在的月日或位置直接跳过，不改成月末，不扣次数。事件条件、任意脚本与无限嵌套不因某个库支持而准入。

### 计算顺序与有界性

- 唯一的计算顺序：在本地民用时间上枚举基础候选并保留来源；对原日期应用边界、首次启用与排除；按明确的日历条件做处理（保持原日、跳过、前移或后移到最近工作日），保留本地时刻；对结果日期再次应用边界与排除，被排除就丢弃，不再找下一日；按时区物化，缺口跳过、重复取第一次；同一安排的不同来源落在同一时刻时合并并保留全部来源。
- 跳过、前移、后移与工作日位置规则需要明确的日历；保持原日也不免除工作日位置规则的日历依赖。路径上任何日期缺覆盖答覆盖不足，不猜普通工作日；实际调休不用星期模板代替。
- 纯计算不读当前时间、不读数据库、不取用户设置、不访问网络；调用方传入时间、不可变依据、版本与边界。
- 每次求解的扫描有上限，先到者答搜索上限并带已观察到的位置；交互预览不自动循环到成功。多层预测共享一份预算，不每层重置。合法范围里没有结果是完整的空；遇到预算不能说「没有下一次」。只有不会再被后来来源改变的候选才能输出；预算用尽不暴露未封闭的碰撞，只保留已封闭的前缀。

### 预览

- 相同的完整定义、计算时区与日历身份和版本，引用与展开的预览得到一致的候选与理由；结果能辨原来源、平移、排除、边界与次数限制。
- 预览只读，返回有界的下一次或有限未来：不保存、不启用、不接受 Job、不扣次数、不发通知，不预测实际重叠与时长，不授写权。非法、无权、缺依据、查询故障、未知与合法空分开；两次查询依据变化如实说明。

### 环境绑定与依赖状态

- 跟随用户环境的安排保存相对意图、最近确认的环境修订与解释锚，时区与日历来自同一环境修订，不拼新时区配旧日历；显式安排保存明确的时区与日历引用。日历身份与版本政策是两条轴：显式安排可以 `latest` 也可以 `pinned`；用户切换偏好不改显式安排的日历身份；`pinned` 缺失时失败，不回退当前版。没有用户环境的系统安排不能跟随。用户安排缺省跟随，固定业务与系统安排用显式。
- 每次到期扫描先对账环境再算候选；对账没完成或权威不能证明新鲜时，最终准入失败关闭。跟随只重算还没接受的未来；已准备而未接受的旧证明判为依据过时，再准备新的；已接受的 Job 与历史不改。
- 环境不相容时停泊；恢复后从当前时刻重算，不补停泊期间的提醒与执行。
- 依赖以外域的公开引用与权威版本记录：暂时离线或不可用是可恢复的受阻，同一权威关系恢复后按补跑处理；日历暂不可取停泊，恢复后重算，执行按有界补跑，提醒不补；永久失效（设备退役、租户关闭、回传目标永久失效、定义身份永久失效、成员移除）终局失效，不用同名的新对象复活；权威读取失败或含混的不存在答未知或受阻，不推断终局删除。每个依赖只应用更高的版本，终局不被旧的恢复覆盖；没有可比较版本的提供者不能声称能可靠处理迟到的恢复。Agent 定义的旧发布停用不等于定义身份失效。

### 准备与接受

- 平时只预算下一个候选，不预建未来的 Job。准备固定定义与状态修订、来源、计算时区、实际日历版本与环境修订、夏令时处置、目的、内容、准入截止与政策摘要；准备是耐久的计算证明，不消费次数，不代表接受或发送。同一准备键重复返回旧证明；不同指纹不能覆写；新定义或环境生成新证明，旧证明明确判为过时，来源去重跨证明成立。
- 接受之前按有效的完整定义、当前控制与资格、最新必要的日期依据、次数与实际重叠重新校验；校验到接受之间前提变化必须重核或冲突。Job 的固定要求、来源、日期依据、接受、次数、相关处置与初始责任在对外确认时一致可恢复，并达到声明的耐久边界；不先报成功再补账。跨拥有者的保证（日历发布、权限）需要实际的守卫或协调：顺序调用、同进程或缓存读后写都不是同事务。权威在远端而不能提供可栅栏的资格协议时，依赖这一保证的后台接受受阻。
- `pinned` 只校验不可变版本与访问资格；`latest` 才校验发布代际；跟随另校验环境修订。计算与网络 I/O 在事务之外，事务内只核快照版本并提交决定，失配就退出重算。

### 来源、碰撞与次数

- 同一安排还没接受的候选落到同一有效时刻时合并为一份工作并保留各来源；新候选碰到同一安排已有的 Job 时记为因已有工作跳过，不建第二份，不向旧 Job 回填来源；已接受或已处理的来源因重算换了日期也不重复造工作。来源去重按租户与逻辑工作定界。
- 合格次数（`eligibleLimit`）计经过完整日期处理、夏令时与同刻合并之后的合格时隙；Job 次数（`jobLimit`）计实际接受的 Job。两轴独立，同时满足才接纳；rrule 的 COUNT 不是其中任何一个。过滤、排除、缺口、越界不耗合格次数；合格之后被重叠跳过不产生 Job，也不回填更早的时隙。纯通知 Job 计 Job 次数、不耗执行预算；等待、失败、取消不退次数，也不重新列入补跑。来源、碰撞与次数与接受一起可恢复，重复唤醒与回执丢失不多计、不漏记。

### 固定要求

- 接受固定本次的工作类型与描述、声明、目标、来源、原定时刻与日历版本和解释；实际受理与开始时间另记。之后改安排、日历、出厂内容或消费者的日历选择不回写旧 Job；等待中的 Job 不再变回候选，也不随新版挪动或取消。执行输入保有本次合法的 Agent 定义身份与版本采用依据，不另冻结整套资产副本。

### 后续控制、补跑与重叠

- 暂停阻止新的到期与补跑接受；恢复只解除暂停，并沿声明的补跑；结束永久停止新接受（含此前未接受的积压），不能恢复复活。控制先成立则没有后续的新 Job；接受先成立则旧 Job 保留，不自动取消。一次性工作已产生或没有候选时结束后续接受，但不表示原 Job 已执行完成。截止约束原定时刻，不拒绝截止内合法的迟到受理。重复控制返回实际状态。
- 周期执行的补跑只有「不补」与「最近 N 次」，N 为正整数；设备恢复、日历恢复与积压扫描用同一选择算法。一轮固定恢复时刻 T 与待处理区间：只选首次启用之后、原定截止之内、还没接受也没明确处理的漏过时刻；超过 N 的更早部分记为不补，后续扫描不得把同一区间分页补光。T 当刻的正常候选不占 N，与选中的补跑按原定时刻从早到晚逐项接受并应用重叠，每项重核资格与剩余次数；被跳过的项不从更早的区间补位。等待中的 Job 是原工作继续，不占 N，不重计次数。计算预算用尽时明确记为降级与跳过的区间，按不补重锚。
- 一次性执行必须明确「过期作废」或「等待恢复」；普通扫描迟到不自动作废，只有规定的可恢复受阻或跨期的暂停才触发；等待恢复保留原时刻直到同一依赖恢复；一次性至多接受一次。
- 重叠作用于同一安排的全部实际前序：含执行的 Job 看执行部分，纯通知看本次发送的主动作是否有真实的结束结果，未知不算结束；组合通知的尾部不挡下一次执行。跳过不建 Job、不补；并行建独立的执行关联；等待先接受并固定 Job，再按原定顺序等实际前序；替换先接受新 Job，向需要停止的全部前序发出明确的控制，原执行方报告所需的真实停止之后才开始新工作。停止失败、未知或未确认就受阻，不偷偷并行；配置时已知不支持就拒绝。归档、Run 终态或停止请求被受理都不是停止的证据。

### 执行意图与承接

- 工作意图在接受时冻结。`program` 保存注册程序的引用与经 schema 校验的 JSON 输入，不含指令与会话，不接受自由脚本；没有 Session 与 Agent 也能创建、查询、接受与执行。`agent` 必须有非空的指令与会话分支：`new` 保存稳定的 Agent 定义身份，每个 Job 幂等地只建一个新执行会话，恢复不再建；`existing` 保存明确的会话引用，只投递到那个会话，目标不存在、终局、跨租户或无准入资格时拒绝或受阻，绝不退回 `new`。
- 三条路径由外部适配器实现本组自有的 `JobExecutor`；核心不解析 Session 与 Agent 的内部对象。Session 的 intake 决定指令成为哪种消息、是否形成一轮、排队或推进；入队只表示承接中，实际执行、目标证据与原关联终态成立才结算。`existing` 不是会话的自我唤醒，也不续旧 Run。`new` 的上下文、资料与工作区显式引用且当前有权，不复制创建者的全部历史或授权。`new` 冻结的是定义身份，到实际启动时采用该定义最新的合法发布并记录；同一 Run 的普通恢复保留原采用；定义失效不改投同名对象。
- 开始未知时先查原执行，重试不再建会话或再投指令。实际执行承接与目标检查成立才记为开始。
- 当前 Job 的上报绑定本次实际执行关联的 Job，模型不能传另一个 Job 改变目标；绑定缺失或不一致时拒绝。进度、问题与最终成果分别可查，不自行改主动作的结局、不重试、不隐式发送。目标达成要有最终成果与可说明的依据，按本次固定的目标与交付要求检查；普通回复、上报成功、工具返回或 Run 完成都不够。检查不授无限续跑、不抵消停止、不拉起新的执行。
- 机械（`program`）Job 只执行具名功能与部署允许的动作，没有 agent 会话与模型的目标判断；真实功能成功才完成，触发或请求成功不够。有意停止的服务不被备份安排自行启动。普通租户改所有者不转成系统功能权。不可用的工具调用沿原位置收场为不可用，不当真实成功，也不制造物理资源或费用。Agent 产出的资产按实际的工作区与租户提交，不直接提交组织资产。

### 通知与整份结算

- 纯通知到期交付给定的内容，不启动 agent；纯执行没有配置的通知。组合仍是同一个 Job，声明非空的开始、成功、失败、取消事件及各自的内容与目标。开始是实际执行（等待或只建了会话不算）；成功要目标或机械的实际依据；失败要已确认的结局，未知不冒充失败。每个 Job 每个选中的实际事件一次逻辑通知；没选或没发生的不适用。
- 纯执行成功要执行目标达成；纯通知成功要目标租户可持久取回；组合成功要执行成功且全部实际触发的通知送达。没命中的事件不制造通知；执行失败或取消不因通知送达变成功；执行成功而应送的未送达不能整体成功。受理、尝试、在线、显示或已读、agent 自己的发送都不够。通知重试与换代继续原逻辑通知，不重做执行或内容生成；投递失败不倒写执行结局，也不递归生成执行失败通知。整体结算由本组做，不交给通知层推断。
- 提醒与执行互斥：提醒用纯通知 Job 承载，没有执行会话、不执行能力或模型、不占执行预算，计一次 Job 次数。首次通知接受的窗口是 `[W, deadline)`，`deadline` 取 W 加五分钟与下一个有效时隙的较小者，随准备冻结；T 等于 `deadline` 即错过，错过的不补发；窗口内已耐久接受的，传输晚于窗口也不算错过。长停机用有界的区间保存已判错过的部分。接受把时隙回执、通知 Job 与通知意图的交接放进同一保护边界或耐久的 outbox；发送失败与重试不重新接受时隙。
- 成果的执行、回传、发布与归档四项分别成立，各有状态、操作引用、成果引用或真实失败；执行成功不把其余三项标为成功。所选成果能力与发布、归档资格在接受前核验，不支持就拒绝，不在接受后再找缺省的去处；准备成功不等于用户可见；正式成果保留原报告引用并通过当前披露校验，原始报告不冒充交付物。每项外部请求有稳定的操作键，超时先查；提供者不能查询时记为未知并给人工处置入口，不盲目重发有副作用的操作。发布成功而归档失败只续归档。

### 取消、判序与恢复

- 取消资格独立于读权；普通租户不能取消系统的机械 Job。已接受未开始的 Job 可以在没有会话时取消，成立即不启动。已开始的记录停止意图，沿原执行的优雅或显式强制控制；业务取消、实际停止与资源、外部效果分别呈现，不以请求成功报已停止。纯通知发送前取消获胜则阻止发送、不另发取消通知；已发送或效果未知的不承诺撤回、不改写成取消、不重发。主动作已终结的保留原结局与未完的通知。
- 开始前取消先成立就不得启动；工作先开始就走原停止路径；主动作先终结就保留结局。各竞争跨普通重启可认回；重复取消不重复动作与通知；依赖恢复、前序结束、调度重建或完成检查不复活已取消的执行。取消不改安排、其他 Job 与固定输入，不退次数，不删历史，不重入补跑。替换的新 Job 被取消，不撤销它已经发出的旧工作停止。
- 组合执行取消成立（含执行前取消）只按声明选中的取消事件产生原逻辑通知，不伪造开始或成功；此前已触发的交付责任继续保管。迟到的成果、回执、费用与外部效果沿原 Job 保存，不把已取消的工作改成正常成功。
- 恢复先核对原 Job、执行关联、取消、主动作终态、原调用、未消费的结果与通知、区间处置。原调用还在执行就接续它的句柄与保管责任；已收场就取原结果；查询失败不推断不存在；重建不自动新建 Job、会话或调用。逻辑消息、执行账、费用与上下文组装沿原拥有者，不把通知或日志条目当新输入重放。会话归档解除业务等待、传播取消，但不等物理停止。

### 系统安排与订阅

- 系统安排是出厂的产品功能定义；可控的功能由所有者显式启用成订阅，订阅有自己的身份、定义版本、参数、管理状态与接受历史。未覆盖的参数用缺省；改参数只改本订阅还没接受的未来。不可控的功能以明确的权威分配为展开依据，不伪装成用户同意的订阅。
- 每个订阅者的时隙唯一键包含订阅身份，不用共享的安排加时刻吞掉别人的工作；没有授权或订阅时不接受，安装应用不等于订阅。错峰偏移用固定算法从功能、订阅与政策版本得出并保存实际值，重启不重新随机；原定时间与实际到期都保留。
- 取消订阅阻止新接受，已接受的工作沿 Job 控制处理。升级系统定义不改已接受的 Job；新版本按功能声明显式迁移或确认，不凭 `latest` 偷换。平台的机械维护走系统归属，不伪造用户订阅或同意。

### 作者同意与额度

- 读取与预览不要求写入同意。逐条同意模式下，agent 创建直接落为草稿，零未来接受，可以自主修订与丢弃自己的草稿；所有者转正就是逐条确认。没有适用的长期同意时，对已生效安排的修改、取消与替换逐命令确认，确认覆盖规范内容摘要、动作、所有者、目标、目的与来源上下文，批准不能挪用到另一份内容。
- 授权有两条轴：粒度（逐条、整体）与范围（本会话、长期）。整体长期授权跨会话与重启有效，没有隐含过期。安排保存授权引用与代际。撤销整体授权只阻塞依赖它的安排；重授不自动恢复，所有者逐条重新确认，原子更新采用、解除阻塞并审计；它不改变暂停，也不复活终态。
- 长期额度归资源治理，经额度参加者计量：每个所有者与作者的非终态未来意图各占一份（草稿、生效、暂停、受阻都占），不按时隙或 Job 重复计。创建原子保留一份，转正不另收，替换在同一事务转移一份，丢弃、结束、耗尽、失效释放。并发创建的保留与安排命令同提交，超额答容量超出且零部分写入。额度数值来自拥有者，本组不编造。
- 同意检查属于应用服务与它的权威端口；工具不能自己记「用户同意过」而跳过服务检查，也不能把整个多命令工具当成一个不可区分的权限。

### 历史与读面

- 安排、Job、交付、来源、日期依据、漏过与跳过、控制的历史按业务承诺保留，不因结束安排、会话归档、失权或实例退出自动清除；没有存活期限或删除能力；物理归档与索引优化不缩短可查范围。
- 查询受当前资格与字段披露限制，只读呈现原采用、成果、事件、交付、未知与新鲜度；当前安排不覆盖历史 Job；读面落后或查询故障不当作没发生；查询不补跑、不重做执行、不重发通知、不修复权威状态。
- 列表与日程表都有上限，达到上限显式标为不完整；游标绑定查询、权限、观察修订与稳定排序键，变化时答已变化，不拼混版本。日程表的请求时区只改变显示与范围边界，不重解释规则；历史取原采用依据，未来取当前预测依据并标为预测。摘要控制体积，完整详情经引用读取，截断后不声称完整。

### 时钟与定时器

- 民用时刻只用于规则、夏令时、到期与补跑截止；同一运行代际的单调时间只用于本次耗时与等待上限，不跨重启比较，不持久化为业务截止；运行代际识别本地时间轴，不冒充持久的执行栅栏。
- 一次本地操作的完成资格是全函数：代际变了答失效，操作已关闭答关闭，单调读数到了截止答受限，其余答合格。同一代际内过期后不因民用时间回拨恢复；重启不拿旧截止比新的单调读数。「关闭」指这一个操作的完成资格，不是服务的准入开关；已准入的操作排空完成不构成违反。
- 定时器只是唤醒提示，可以早到、迟到、重复、乱序或丢失；回调要重新取得观察并检查业务守卫。漏醒、重启与时钟跳变靠持久扫描接续。一轮补跑固定 T、候选集与政策，相同输入得到相同集合。

### 存储与原操作

- 后端只服务构造时固定的存储范围：租户所有者必须匹配范围的租户，系统所有者只能用系统范围；调用字段不能改变落点。本地存储不是对模型开放的授权入口。
- 外部守卫完整绑定原操作、主体、当前同意、采用依据与额度，返回事务里的决定时刻；本组参加者在锁内读当前状态并以这个时刻重新执行纯决定。记录、不可变定义、修订、替换的双向谱系、额度效果、outbox、操作索引与结果同提交成立；后续失败回滚守卫的临时额度。无变化只留回执与索引，不增修订与 outbox。outbox 只保存事件，不负责发送。
- 同一业务地址先查原回执；新的请求号、时间或候选号不制造第二次业务操作；同键异内容答键冲突。回执损坏、缺失或无法确认时保留未知。只有存储给出完整的否定证据才答没有提交，索引缺失不是否定证据；去重事实没有缺省的过期删除。存储的结果（已提交、已回滚、未知、身份冲突、接受前拒绝）原样解释，未知不改成普通失败。
- 本地参加者是提供者的装配协议，不进入日程的公开协议；远程提供者用自己的机制兑现同一承诺。

### 生命周期与装配

- 提供者停止先关新准入，再排空、停止或可靠交接原 Job、区间、控制、执行、通知与未知；承接之前原方持责，不出现无人负责的窗口。事实与责任独立于单一 fiber；依赖换代、旧引用与晚到结果归原身份。每个实例只撤自己的登记、监听、计时器、句柄与共享使用权，部分初始化失败也收口；旧清理不删新实例或其他租户；外部输出不靠 disposer 声称可逆，实际残留如实报告。
- 本地应用的关闭先同步拒绝新调用，再等已接受的调用真实结束与工作线程退出；旧引用答依赖受阻；重复关闭返回同一结果；未结束的调用让关闭保持等待，不据卸载推断写入没发生。计算工作线程的并发与排队容量显式配置，截止包含排队与运行，到期或取消中止实际任务；答不可用不等于线程已退出；销毁计算资源不改变已保存的安排。
- 服务定义在 `./cordis`，键与服务定义同源；提供者继承定义；工具只依赖定义与键，不自己构造服务。缺依赖、无效配置或不能满足停止与送达判据时拒绝或受阻，不静默选参数、目标或通道。Cordis 不提供业务授权、耐久或原子受理。监听或呈现失败不倒写已提交的事实。

### 工具

- 九个动作：创建、执行管理命令、查原操作、列表、详情、修订、执行记录、日程表、预览。参数不接受主体、所有者、会话身份或原操作键；写操作的键由宿主的耐久恢复记录派生，固定于适配采用身份、租户、调用、原准入与业务动作；恢复失败不写入，重启不另造操作身份。
- 结果保留已提交、无变化、拒绝与未知，写入结果总带原操作的定位；未知不自动重发。工具取消或卸载不代表安排已停止，也不撤销已发生的写入。
- 参数、完整结果与摘要都有上限，超限明确失败，不再次执行业务来生成摘要；摘要保留身份、原操作、控制状态、依据、总数、完整性与续页。详情只读已产生的那次调用的精确结果版本，每次读取先核当前披露资格，不回退最新，不因本次无权而返回旧缓存；通用的结果与内容读取也必须经过同一守卫。续页绑定固定版本、披露观察、已读页与累计预算，用宿主注入的密钥校验。

## 原则与约束

- 一个事实一个拥有者：日期知识、环境、资格、同意与额度、会话推进、通知送达、成果发布都经端口读结论，日程不存第二份，不读别人的私有表。
- 领域不认识调用它的是谁：Job 核心只认自有的 `JobExecutor`，执行细节由外部适配器解释。
- 候选是建议，接受才是事实；接受之后要求固定，事实只追加。
- 结果不知道就是不知道：按原 Job 与原操作查回，不新建、不重发、不写成成功或失败；只声称实际确认的停止、送达与撤回。
- 产品政策由本组实现，库只提供算法步骤；不引入通用的作业平台，进程内的定时器不能成为持久调度的权威。
- 策略数值（扫描上限、读面上限、额度、错峰窗口）是治理的配置，变更显式进行，不静默多算或截断后报完整。
- 改变接受、恢复或时钟语义之前，先补该部分的状态模型、正负控与实现映射；有限模型检查通过不等于源码精化或任意规模的证明。

## 不变式
