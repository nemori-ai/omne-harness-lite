# Canvas

## 总体架构

Canvas 包组回答一个问题：一个租户的[画布](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-canvas--画布--canvas)上摆着哪些对象引用，各在哪、多大、在哪[一叠](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-canvas-pile--一叠--canvas-pile)里、锁没锁、是谁摆的。人和 agent 共用这张画布，用同一组操作。画布只记引用与摆法，不存被摆上的东西：摆上去的是对别处事实的引用；拿走只去掉[摆法](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-canvas-arrangement--摆法--canvas-arrangement)，那样东西照旧在它的拥有者那里。

它是接在核心系统上的一个服务端领域。核心域（Session、Agent、Model、Tool、Runtime Context、Request Context）的成员都不依赖它；去掉它，核心原有的流程不变。

画布上的事由四样互不决定的东西合成，各有各的拥有者：

| 哪一样 | 回答的问题 | 拥有者 | 怎样进来 |
| --- | --- | --- | --- |
| 引用 | 这是什么东西的哪一个 | 拥有那样东西的领域 | 一对不透明的文本：种类、标识。画布不解释 |
| [可画布渲染](../../.meta_harness/design/ubiquitous_language/terms/reach-and-availability.md#ul-canvas-renderable--可画布渲染--canvas-renderable)的种类 | 哪些种类能摆上画布；摆上之前要不要先问拥有者；给人看叫什么 | 拥有那一类东西的领域声明；点归画布 | 服务端的点 `canvas.kinds` |
| 摆法 | 哪些引用在纸上，各在哪、多大、在哪一叠、锁没锁、谁摆的 | 画布 | 服务端的事实，画布是唯一的写入者 |
| 画法 | 一类东西在纸上长什么样 | 拥有那一类东西的领域的界面模块 | 客户端的点 `canvas.element`，键取自 `canvas.kinds` |

另有两样与领域无关。纸面的平移、缩放、拖动、改大小与磁吸的取整归共用界面件。此刻看着哪一块、多远、磁吸开没开，是这台设备的偏好，不是画布的事实。

人经协议 `canvas/v1` 调，agent 经工具 `Canvas` 调，两边落到同一个函数上。纸上画出来的样子只取决于四样：登记表上现在声明着哪些种类与画法；服务端这张画布现在的摆法；这台设备的视口与磁吸开关；当前租户与字号档。它与模块加载的先后、谁先连上都无关。

## 领域边界

本组拥有：一个租户的画布的纸（大小、网格）；画布上的每一个[画布项](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-canvas-item--画布项--canvas-item)与每一叠；每次改动摆法的是谁；可画布渲染的种类的登记面；[画布小应用](../../.meta_harness/design/ubiquitous_language/terms/capabilities-and-composition.md#ul-canvas-app--画布小应用--canvas-app)的点。

本组不拥有：

| 事实 | 归谁 |
| --- | --- |
| 被引用的那样东西在不在、内容是什么、谁能看 | 拥有那一类东西的领域 |
| 一类东西在纸上怎样画、怎样从查找里挑、拖进来的文件怎样变成引用 | 那个领域的界面模块 |
| 一个画布小应用画什么 | 带来它的 Plugin |
| agent 的一次调用许不许 | 放行判断，由 Agent 的准入在发起点问 |
| 一个主体能不能为一个租户行事 | 身份与授权 |
| 应用有[几面](../../.meta_harness/design/ubiquitous_language/terms/interaction-and-dispatch.md#ul-application-face--应用的面--application-face)、怎样翻面、停在哪一面 | 外壳契约与桌面应用 |
| 视口、远近、磁吸开没开 | 这台设备的偏好 |

和邻域的接缝：

| 邻域 | 接缝 |
| --- | --- |
| 媒体 | 应用装配里媒体的一行在 `canvas.kinds` 上声明种类 `media.object`，带 `admit`。`admit` 里媒体持有这个对象，持有方是画布的这条记录。画布不知道 `admit` 里做了什么。拿走不解除持有 |
| 会话 | 应用装配里会话的一行声明种类 `session.session`，不带 `admit`。会话的界面模块放这一类的画法与挑法；纸上点开一个会话，经外壳的切页去那个会话。agent 的调用来历里带它所在会话的标识，画布把它当不透明的文本记下 |
| Plugin | 画布小应用是一份 plugin 的一个客户端代码成员，放在点 `canvas.app-render` 上，键是小应用的名字。Plugin 的装载器照常放，不为画布改。纸上的那一项是种类 `canvas.app` 的引用，标识是小应用的名字 |
| 外壳 | 外壳契约的位置 `shell.back` 是应用的反面，规则归外壳契约。画布的界面模块往它上面放一项。两面、翻面、停在哪一面都不归画布 |
| 工具运行时 | 工具 `Canvas` 登记到工具的绑定上。许不许由放行判断在发起点判一次，工具到了就执行 |

本组声明、由别人实现的端口：

| 端口 | 对方 | 本组需要它做什么 |
| --- | --- | --- |
| 权威 | 身份与授权，经应用装配 | 答一个主体此刻能不能为这个租户读或改画布 |
| 是谁做的 | 应用装配 | 从调用的上下文得出是谁：人，或哪个会话里的 agent。得不出时答取不到 |
| 存储 | 存储的租户提交 | 一个写操作一次提交 |

成员与职责：

| 成员 | 回答的问题 |
| --- | --- |
| `canvas-contract` | 值、操作、结果与端口；全化表的纯决定。纯数据与纯函数，只依赖共同契约 |
| `canvas` | 领域实现：每个操作的事务脚本、找空处的几何、存储的端口。不依赖 Cordis；`./testing` 给内存存储与存储的一致性用例 |
| `canvas-local` | SQL 存储与 Cordis 上的提供者 |
| `canvas-cordis-contract` | 服务定义；服务端的点 `canvas.kinds` 的规矩与往上放一份声明的放法 |
| `canvas-protocol` | 协议 `canvas/v1`。纯数据 |
| `canvas-access` | 协议的接入插件 |
| `canvas-tools` | 给 agent 的多命令工具 `Canvas` |
| `canvas-ui` | 界面模块：反面上的纸，与四个客户端的点 |

本组每个成员都不依赖媒体、会话、Plugin 的任何成员。两个种类的服务端声明各是应用装配里的一行。界面模块之间不互相导入：`canvas-ui` 声明的点由应用的装配交给媒体、会话的界面模块。

## 心智模型

把画布想成桌上的一张纸，纸上摆着一张张卡片。每张卡片写着「某处的某一样」，东西本身留在原来的地方。谁都能挪卡片、叠成一叠、收进抽屉、再拿出来；每张卡片背面写着最后是谁动的。钉住的卡片谁也挪不动。

最容易想错的五处：

- **拿走不是删除。** 拿走的记录还在，能放回。被引用的东西不因画布的任何操作而消失。
- **画布不认识任何一类东西。** 一类东西能不能上、上之前怎样核、怎样画，都由它的拥有者带来。
- **人和 agent 是同一组操作。** 区别只在各自的发起点怎样判许不许。锁对谁都一样。
- **服务端是事实。** 拖动只是预览；不知道结果时，以重读到的为准。
- **画不出来不是空。** 没有声明、读不到、不在了、无权看，各有各的样子。

拿它量一个设计：

- 画布的代码里出现某一类东西的字段：错了。
- 拿走一样东西导致它的事实被删：错了。
- agent 与人走两套规则，或操作按调用者是谁分支：错了。
- 客户端先改了摆法，再告诉服务端：错了。
- 画布的服务端替谁去读被引用的东西：错了。
- 加一类东西要改画布：错了。
- 一类东西没有声明或读不到，画成空，或拿别的顶上：错了。

## 应然设计

### 纸、画布项与一叠

- 每个租户一张画布，标识是 `main`。每个操作带画布的标识。
- 纸有边：宽、高、网格的步长。服务端在读画布时给出它们，值是配置。读画布时一并给出项大小的下限与上限，以及没给大小的项的缺省占地；客户端用它们收住手势、画没给大小的项，不自己存一份。坐标以纸的左上角为原点，是非负整数；单位是中楷、远近为一时的一个像素。Agent 形的座位在纸的正中。
- 一个画布项是一条记录：引用；摆着还是拿走了；位置；大小（可以不给，不给就照画法自己的大小）；叠放次序（大的在上）；在哪一叠；锁没锁；最近一次改它摆法的是谁，与什么时候。
- 拿走了的记录留着拿走前的位置，不在任何一叠里，不锁。
- 一个引用在一张画布上至多一条记录。
- 一叠是一样有标识的东西：有名字（可以没有）与位置，能整个挪、改名。最后一项离开，这一叠就没了。
- 纸上的东西允许重叠。
- 摆着的项有上限。拿走了的记录也有上限，超过时丢最老的那一条。两个上限都是配置。上限被改小之后，已经摆着的一项也不拿走；摆着的降到上限以下之前摆不上新的。
- 刚摆上的与放回的排在最上。
- 纸被改小之后落在新边外的项，摆法不变；画的时候收进纸内；下一次挪它要落在纸内。

### 拓展点

画布开五个拓展点。服务端一个，客户端四个；共同规则见[拓展点的共同契约](../../docs/architecture/cross-cutting-concepts.md#拓展点的共同契约)。

| 问题 | `canvas.kinds` | `canvas.element` | `canvas.picker` | `canvas.intake` | `canvas.app-render` |
| --- | --- | --- | --- | --- | --- |
| 回答什么 | 哪些种类声明了可画布渲染；摆上之前要不要先问拥有者 | 一类东西在纸上怎样画 | 人怎样从这一类里挑一个摆上来 | 拖进来的东西怎样变成一个引用 | 这个名字的小应用怎样画 |
| 哪一棵树 | 服务端 | 客户端 | 客户端 | 客户端 | 客户端 |
| 放几项 | 按键放，每键至多一项 | 按键选画法，每键一项 | 同左 | 同左 | 同左 |
| 键从哪来 | 声明自带的种类名，`<领域>.<名字>`；键公开 | 种类名，取自 `canvas.kinds` 公开的键 | 同左 | 递进来的是什么，现有 `files` 一种 | 小应用的名字，任意 |
| 宿主给什么 | 调 `admit` 时：行事的租户与主体、引用的标识、由租户、画布与引用定出来的持有方引用 | 引用，与它画在哪一种框里：纸上、一叠里露出的一页、查找里的一行 | 查找的文本，与口 `pick(引用, { size? })` | 递进来的文件，与口 `place(引用, { size? })`、`done()` | 小应用的名字 |
| 这一项交什么 | 这一类的声明本身。数据：叫法、一句话说这一类是什么、一句话说这一类的标识怎样写；加一个可选的带副作用的函数 `admit` | 渲染函数 | 渲染函数 | 渲染函数 | 渲染函数 |
| 什么时候读，变化怎样传 | 每次 `place` 与 `kinds` 从登记表现取。键的变化经协议可用性的快照到客户端，客户端见键变了就重读 `kinds` | 画的时候现取；登记表或租户一变就重画 | 同左 | 同左 | 同左 |
| 出错时 | `admit` 抛出或过了时限，`place` 答依据不可用；`admit` 答不知道，`place` 答不知道。都不摆上去 | 没人放或抛出：画通用的一页，写种类的叫法与标识。只有这一样落回 | 不画：这一类不能从查找里挑 | 一句「这类东西现在放不上来」 | 一页，写「这个小应用现在不在」；这个名字有两份时写明是哪两份冲突 |
| 撤下 | 每一批离开时都排空：先不接新的 `place`，在途的 `place` 各有结局（`admit` 过了时限也是结局），然后才取走。之后 `place` 这一类答种类没有声明。已经摆着的记录不动 | 下一次画就是通用的 | 同左 | 同左 | 同左 |
| 形状怎样变 | 主版本 1；只做可加的改动，每次修订号加一 | 规矩带主版本 1；给画法的对象只加不改 | 同左 | 同左 | 同左 |
| 冲突时 | 同名两份：登记表答冲突并带出处。`place` 这一类答依据不可用：领域的答复写明是哪两家；经协议时这个结果没有正文，哪两家从 `kinds` 读；工具的失败文字里写明两家。`kinds` 列出它并标成冲突；撤掉一份，另一份立刻生效 | 同一层两份：画通用的，两项标着冲突；撤掉一份，另一份立刻生效 | 同左 | 同左 | 同左 |

`canvas.kinds` 的规则：

- 一类的声明只有一份，就是登记表上 `canvas.kinds` 的那一项。画布不另存一份：`place` 与 `kinds` 每次从登记表读，冲突与出处由登记表答。放这一项是调用者作用域上的效应；键公开，一项的内容不出服务端的树。
- 每一项的那一批离开时都排空，不论带不带 `admit`：`place` 的提交要在这一类还声明着的时候落下。排空等的是还没有结局的 `place`：一次 `place` 从取到这一类起算在途，到它有结局为止，`admit` 过了时限也是结局。过了时限的那次 `admit` 不再等，所以拥有者永远不答也卸得掉；它之后迟到的答复不改画布。离开之后不再有 `admit` 交给拥有者。数在途的 `place`、报排空完由 `canvas-cordis-contract` 给的放法做，贡献方只写声明。
- `admit` 的次序是先问拥有者，后提交记录。它答接受，才提交。它的另三种答复都不留记录：拒绝、依据不可用、不知道。抛出与过了时限算依据不可用；时限是画布的配置。
- 交给 `admit` 的持有方引用由租户、画布与引用定出来，提交之前就有，不用记录的标识。同一个持有方为同一个引用再问一次 `admit`，不产生第二份效果，所以重发一次摆放是安全的。
- 画布自己的种类 `canvas.app` 也经这个点声明，不带 `admit`，和别人的种类走同一个契约。

客户端的四个点由 `canvas-ui` 照[按键选画法的点](../frontend/SPEC.md#按键选画法的点)声明，所以 plugin 的装载器不改就放得上代码成员。`canvas-ui` 自己往 `canvas.element` 上放种类 `canvas.app` 的画法：它按引用的标识去 `canvas.app-render` 上取那个小应用。点叫 `canvas.app-render`，种类叫 `canvas.app`：一个是登记表上的点，一个是 `canvas.kinds` 上的键。`pick` 与 `place` 两个口都经协议的 `place` 把引用摆上来，答复照协议；第二个参数可以带一个大小，`canvas-ui` 把它取整到网格、收进项大小的上下限，再带进协议的 `place`；`pick` 摆在打开查找处的附近，`place` 摆在落点的附近；`done()` 说这一次递交收完了。挑中的引用已经摆着时协议答没有变化并交回那一项，`canvas-ui` 把那一项指给人看。

### 操作

| 操作 | 读写 | 作用 |
| --- | --- | --- |
| `look` | 读 | 纸（连同项大小的上下限与缺省占地）、摆着的每一项、每一叠与修订号 |
| `look-away` | 读 | 拿走了的记录，新的在前，分页 |
| `kinds` | 读 | 现在声明着的种类：名字、叫法、两句说明；同名声明了两份的也列出，标成冲突 |
| `place` | 写 | 摆上一个引用。给了位置就摆在那；只给了附近，服务端找最近的空处；都没给，从形的座位旁边找 |
| `arrange` | 写 | 一批改动一次提交：挪、改大小、进出一叠、提到最上；也挪一叠、给一叠改名 |
| `take` | 写 | 拿走若干项 |
| `pile` | 写 | 把若干项叠进一叠。叠的标识由调用方给：这一叠不在就建，在就叠进去。新一叠的位置：给了用给的，没给取列出的第一项的位置 |
| `scatter` | 写 | 把一叠散开，各项落在旁边的空处。这一叠已经不在时答没有变化 |
| `lock` | 写 | 把若干项锁上，或把若干项解开；一次只做一个方向 |
| `observe-changes` | 观察 | 帧只说「可能变了」，客户端重读 |

修订号随每次改了摆法的提交增长。读的依据取不到时答依据不可用，不答成一张空画布。

### 全化表

一个引用对一张画布有四种状态，每一格是确定的答复。下表「摆着，散的」指没锁的。

| 操作 ＼ 状态 | 没有记录 | 摆着，散的 | 摆着，在一叠里 | 拿走了 |
| --- | --- | --- | --- | --- |
| `place` | 查种类、查上限、`admit`、建记录：摆上了 | 没有变化，交回这一项，不挪 | 没有变化 | 查种类、查上限、`admit`、改回摆着：摆上了。没给位置用拿走前的位置，被占了找最近的空处 |
| `arrange` 挪、改大小、提到最上 | 找不到 | 照改；数值都相同答没有变化 | 改大小、提到最上照改；给了位置而没写离开这一叠：现状不允许 | 现状不允许 |
| `arrange` 进某一叠 | 找不到 | 进去 | 已在这一叠里答没有变化；在别的一叠里就换过去，原来那一叠空了就没了 | 现状不允许 |
| `arrange` 离开一叠 | 找不到 | 没有变化 | 出来；没给位置落在这一叠旁边的空处 | 现状不允许 |
| `take` | 找不到 | 拿走 | 拿走；那一叠空了就没了 | 没有变化 |
| `pile` | 找不到 | 进这一叠 | 已在这一叠里答没有变化；在别的一叠里就换过来 | 现状不允许 |
| `lock` 锁上 | 找不到 | 锁上 | 现状不允许：先从一叠里拿出来 | 现状不允许 |
| `lock` 解开 | 找不到 | 没有变化 | 没有变化 | 没有变化 |

锁着的一项一定摆着、散着。对它：`place` 同一个引用答没有变化；`arrange` 的任何改动、`take`、`pile` 都答现状不允许，原因是「锁着」；`lock` 锁上答没有变化，解开就解开。这些答复不看调用的是人还是 agent。

对一叠：

| 操作 ＼ 状态 | 这一叠在 | 这一叠不在 |
| --- | --- | --- |
| `arrange` 挪、改名 | 照改；相同答没有变化 | 找不到 |
| `arrange` 把一项放进它 | 进去 | 找不到 |
| `pile` | 叠进去 | 用给的标识建这一叠 |
| `scatter` | 各项散开，这一叠没了 | 没有变化 |

### 答复的次序

每个写操作按固定的次序答，前一项成立就不往下。第 1 到 3 步在查状态之前；全化表里的「找不到」「现状不允许」「没有变化」在第 3 步之后、提交之前答：

| 次序 | 情形 | 答复 |
| --- | --- | --- |
| 1 | 请求读不懂、位置出了纸、大小出了上下限 | 不合规则，写明是哪一处 |
| 2 | 主体无权为这个租户行事 | 拒绝 |
| 3 | 权威、是谁做的、存储，任一个依据取不到 | 依据不可用 |
| 4 | `place`：种类没有声明 | 现状不允许，原因「种类没有声明」；同名两份时答依据不可用 |
| 5 | `place`：摆着的已经到了上限 | 现状不允许，原因「摆满了」 |
| 6 | `place`：`admit` 不接受 | 答拒绝时现状不允许，原因「拥有者没有接受这个引用」；抛出、过了时限或答依据不可用时依据不可用；答不知道时不知道 |
| 7 | 提交的结果不知道 | 不知道 |

次序 4 到 6 只在 `place` 会把引用摆上纸时问，就是没有记录与拿走了两种状态。引用已经摆着时直接答没有变化，不问拥有者。上限排在 `admit` 之前：摆不上的时候不让拥有者白做一次带效果的事。

`admit` 是提交之前的一次外部调用，所以 `place` 的提交是带条件的写。提交的那一刻再核三样：这个引用仍然没摆着；摆着的仍然没到上限；这一类仍然声明着。不成立时按提交那一刻的状态答：已经摆着答没有变化并交回那一项，到了上限答摆满了，种类没了答种类没有声明。这几步的先后与交错有一个有限模型守着，见 [CanvasPlace](../../docs/architecture/verification/canvas-place/formal-mapping.md)。

### 一批与提交

- 一个写操作是一次提交。
- 一批是原子的：`arrange`、`take`、`pile`、`lock` 里有一项找不到或现状不允许，整批不做，答复写明是哪一项与原因。
- 一批里一个画布项、一叠各至多出现一次；出现两次答不合规则。
- 整批每一项都没有变化时，答没有变化，不提交。

### 失败、不知道与并发

- 写操作都是「把它摆成这样」的绝对命令，不是「挪多少」的相对命令。每个写操作按它留下的状态幂等：同一条命令在它做成之后原样重发，答没有变化，不产生第二份效果。`place` 靠一个引用至多一条记录；`pile` 靠调用方给的叠标识；`scatter` 靠这一叠已经不在；其余靠命令里写的是终态。照[以同一身份再做一次](../../docs/architecture/cross-cutting-concepts.md#同身份再做一次)的分法，它们属于「再做一次本身就是认回」的那一种。
- 结果不知道就是不知道，不写成成功或失败。调用方重读画布，或原样重发。所以协议不另设认回的操作。
- 人和 agent 同时改同一项，后提交的生效。命令不带预期版本。
- 客户端拖动时，那一页跟着指针走。这是手势的预览，不是事实。松手才发出命令；答复回来之前画成「还没定」；失败或不知道时重读画布，照读到的画。

### 是谁做的，许不许

- 每次改动记下是谁做的：人，或哪个会话里的 agent。它由「是谁做的」端口从调用的上下文得出，agent 自己填不了。它是来历，不是权限。
- 每次调用都经权威端口，按行事的租户判，人的与 agent 的一样。
- agent 的调用：许不许在发起点判一次，由 Agent 的准入问放行判断；工具到了就执行。本组不读放行，不另设同意的开关。
- 锁是摆法里的一个事实，锁着的东西对谁都不许改。agent 解不开人锁上的东西，是因为工具的 `lock` 关口缺省禁止，不是因为领域按是谁分支。人要挪锁着的东西，先解开它。

### 租户隔离

- 操作里没有指向别的租户的写法：画布由行事的租户定。一个租户读不到、改不了另一个租户的画布。
- 主体无权为这个租户行事，答拒绝；它和别的拒绝逐字节相同，正文是空的。
- 画布项与一叠的标识只在行事租户的画布里找。别的租户的标识和从没有过的标识答同一个「找不到」，所以「找不到」不披露别的租户有什么。
- 答复与协议结果名的对应：做成了 `succeeded`；没有变化 `no-change`；不合规则 `invalid`；拒绝 `denied`；找不到 `not-found`；现状不允许 `conflict`，带原因；依据不可用 `basis-unavailable`；不知道 `unknown`。
- 观察的帧只属于一个租户。

### 画不出来的四种情形

四种情形各有各的样子，不互相顶替，不画成空：

| 情形 | 谁发现 | 画成 |
| --- | --- | --- |
| 种类没有声明 | `canvas-ui`：`kinds` 读到了，里面没有这一类 | 通用的一页，加一句「这一类现在没有声明」 |
| 依据取不到 | `canvas-ui`：`kinds` 读不到，或它把这一类标成冲突 | 通用的一页，加一句「现在读不到」 |
| 那样东西不在了 | 这一类的画法，经它自己领域的协议读 | 由这一类的画法说 |
| 这个人无权看 | 同上 | 同上；和「不在了」是不是同一句话，由那个领域定 |

画布的服务端不替任何人读被引用的东西。后两种只有拥有者答得出，也只有它该答。

### 找空处与手势

- 找空处的几何只在服务端。`place` 不给位置、`scatter`、离开一叠不给位置、放回时原处被占，都用它。它给出的位置在网格上。占地连同名字那一行算；大小没给的项按配置的缺省占地算。纸上没有空处时，落在要的那一点上（没给就是形的座位旁边），压着别的，排在最上。
- 网格的步长只有服务端给的那一份；客户端按它取整手势的落点。
- 客户端只做手势的事：跟着指针、取整到网格、不出纸边。两边不各写一份同样的规则。
- 磁吸只改这一次手势落点与大小的取整，不改已有的摆法；关着时坐标原样。

### 对客户端开放

- 协议 `canvas/v1` 有九个操作与一条观察，见上面「操作」的表。人以行事租户的身份调它；agent 不经它。
- 接入插件的处理函数照固定的次序：核这次登录能不能为目标租户行事；取主体；取画布的服务，取不到答依据不可用；调画布；映射结果。读操作里画布抛出答依据不可用，写操作里答不知道。
- 观察的帧只说画布可能变了，不带内容。客户端收到就重读。

### 界面模块

- `canvas-ui` 要协议 `canvas/v1`，往 `shell.back` 放一项，声明四个客户端的点。协议缺着时外壳不放反面，应用只有一面（规则归[外壳契约](../frontend/SPEC.md#界面模块)）。
- 它读 `look`，订阅 `observe-changes`，变了就重读。它读 `kinds` 知道哪些种类声明着；服务端公开的键一变就重读。
- 人能做的：拖动、改大小、选中几样叠成一叠、拖到一叠上放进去、从一叠里拖出来、散开、给一叠改名、拿走、锁上与解开、查找（挑一个摆上来，或把拿走了的放回）、拖文件进来。每一样都能只用键盘做到。
- 把一样拖到另一样上面只是压着，不成一叠。一叠只由「叠成一叠」产生。
- 锁着的一页上有一个锁的记号，没有拖动与改大小的把手；点记号解开。
- 每样东西上看得到是谁摆的：平时是一个记号，分得出人与 agent；看着这一样时写全是人还是 agent、什么时候。
- 纸的正中有 Agent 形的一个座位，名字 `canvas`，优先级 1。它不叫家：家是正面侧栏里的那个座位。它是一个可按的控件：按它等于去正面次序最前的一页，待答数大于零时去待答的那一页；对它按右键是翻面，归外壳。
- 反面的一角有翻面的记号，由这一项用外壳给的 `turn()` 画；键盘走得到，可访问名称写明翻到正面。
- 看着哪一块、多远、磁吸开没开，是这台设备的偏好。存取的口由应用的装配注入。磁吸缺省开着。
- 去别的页经外壳的切页。从反面切页时先翻回正面，规则归外壳契约。

### 给 agent 的工具

- 工具 `Canvas` 是这组操作的投影，和协议落到同一个函数上。命令：`help`、`look`、`away`、`kinds`、`place`、`arrange`、`take`、`pile`、`scatter`、`lock`、`unlock`。
- 三道关口。`read`「看」：`help`、`look`、`away`、`kinds`，缺省自动。`arrange`「摆」：`place`、`arrange`、`take`、`pile`、`scatter`，缺省自动。`lock`「锁」：`lock`、`unlock`，缺省禁止。租户可以改这些取值。
- 来历由这次调用的绑定给，参数里没有是谁做的、租户与会话。
- 碰到锁着的东西，答复写明它锁着、要人来解开。
- `kinds` 给出每一类的标识怎样写。`help` 写画布小应用的三步做法：写文件；用 `OmneExtensions` 发布成 plugin 的一个代码成员；用 `Canvas` 把它摆上纸。
- 本组的拒绝、依据不可用与不知道，在工具里都是失败的结果，写明原因与该怎么办，不写成成功的文本。

### 存储与提供者

- 摆法只有画布一个写入者。SQL 存储里每个写操作是一个同步的事务脚本，一次提交。
- 一张画布上一个引用至多一条记录，由存储的唯一约束与领域一起守。
- 内存存储与 SQL 存储跑同一套一致性用例。
- 纸的大小、网格、各个上限、缺省的占地与 `admit` 的时限都是配置。缺失或无效时提供者拒绝加载，不静默取值。

### 不能声称的

- 人与 agent 同时改同一项时，先提交的那一次会被盖掉，没有提示。
- 画布不保证被引用的东西还在。在不在，由那一类的画法说。
- 媒体的持有没有解除的操作。被画布引用过的媒体会一直留着，直到媒体的保留规则另行规定。`admit` 接受了而提交没有成（条件不成立、失败或结果不知道），或 `admit` 过了时限之后拥有者才做完，都会留下一份画布没有记录的持有；它同样由媒体的保留规则承担。
- 锁保的是这一项的位置、大小、在不在纸上、在不在一叠里，不保它不被别的东西压住。
- 「agent 动不了人锁上的东西」靠 `lock` 关口的缺省值。租户把这个关口放开之后，agent 能解开再动。
- 「是谁做的」与「先问拥有者，后提交」的次序靠同一个进程里的调用得出，是应用的装配给的。画布与种类的拥有者分到两个进程之后，这两样要由那时的提供者重新兑现。租户隔离、同一个拒绝、观察只属于一个租户是协议给的，不随部署变。
- 画布小应用只能画，不能自己取数。

## 原则与约束

- 画布只拥有摆法。被引用东西的事实归它的拥有者，拿走不删除它们。
- 画布不认识任何一类东西。种类只经 `canvas.kinds` 进来，画法只经客户端的点进来。
- 人与 agent 用同一个函数，操作不按调用者是谁分支。
- 许不许在发起点判。是谁做的只是来历。
- 服务端是事实的权威。客户端只有投影与手势的预览。
- 读不到不是空；结果不知道就是不知道。
- 跨协议只传引用。画布的服务端不替任何人读被引用的东西。
- 尺寸、网格与上限是配置，配置不能减弱上面任何一条。

## 不变式

磁吸、纸面的手势、两面与翻面的不变式归[共用界面规格](../frontend/SPEC.md#不变式)，本表不重复。

| 编号 | 永远成立的性质 | 违反的后果 | 由什么守 |
| --- | --- | --- | --- |
| CV-01 | 画布不持有被引用东西的事实；拿走只去掉摆法，那样东西照旧存在 | 人以为只是收起来，东西却没了 | 契约里没有删除被引用东西的操作；拿走的用例 |
| CV-02 | 每个操作对人与 agent 是同一个函数，结果只由操作、参数、行事的租户与当前摆法决定，不看调用者是哪一种 | 两边看到两套规则 | 协议与工具对同一组输入的结果逐格相同的用例 |
| CV-03 | 摆法只有一个写入者；每次变更是一次提交，带是谁做的 | 两处各写一份，对不上 | 提供者的集成用例；存储的一致性用例 |
| CV-04 | 一个租户读不到、改不了另一个租户的画布；拒绝的答复不披露对方有没有 | 租户之间泄漏 | 跨租户的用例；拒绝逐字节相同的用例 |

| CV-10 | 人在画布上能做的每一件事都能只用键盘做到 | 键盘用户进不了画布 | `canvas-ui/tests/keyboard.spec.tsx`；纸面那一组控件自己的键盘规则归[共用界面规格](../frontend/SPEC.md#纸的面) |

| CV-12 | 一叠至少有一项摆着的；拿走了的项不在任何一叠里 | 纸上留着空的一叠；放回的东西带着旧的一叠 | 领域在同一次提交里守；性质用例 |
| CV-13 | 一条摆着的记录，它的种类在提交的那一刻声明着；带 `admit` 的，提交之前答了接受 | 画布引用了拥有者没接受的东西，媒体到期被清掉 | 模型 [CanvasPlace](../../docs/architecture/verification/canvas-place/formal-mapping.md) 的 `RecordIsHeld` 与 `CommitWhileDeclared`；`admit` 答拒绝、答依据不可用、抛出、过了时限、答不知道都没有记录的用例；`admit` 途中种类撤下的用例 |
| CV-14 | 锁着的一项，位置、大小、叠放的归属、在不在纸上都不变，直到被解开；这条不看调用者是谁 | 人锁住的东西被挪走 | 全化表里锁着那几格的用例；性质用例 |
