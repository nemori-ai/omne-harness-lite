# Agent Loop 的公开推进保证

状态为候选设计，未经技术接受。本页只写调用方、外部协调者与读取方可以观察到的推进保证。每条保证引用 [Loop 完整算法](../../../agent/docs/architecture/loop-algorithm.md)的节点 ID，节点的次序、读写与等待归该页。行为归[成员 SPEC](../../SPEC.md)，扩展作者可见的输入与输出归[扩展作者协议](../public-api/extensions.md)。本页不维护转移表或第二套状态机，也不拥有调用的物理寿命。

## 求值依据

Loop 使用原工作事实、已采用规则和当前运行条件求出下一步。完整输入包括本域推进事实、待处理及已承接输入、原调用与消费位置、扩展结论和卡片、当前推进要求以及请求准备结果。同一完整输入和同一规则得到同一下一步。历史记录不能独自还原当前资格或执行状态。当前授权变化不是同输入求值失败。

纯派生求值可以重算。实际模型或工具调用不能因重算再次发出。会改变后续推进的非确定判断、采用数据、等待及外部效果都可恢复，不只存在旧实例的内存中。

## 外部可观察的保证

| 保证 | 内容 | 节点 |
| --- | --- | --- |
| 接续优先 | 新的推进者先对账原提交、原调用、原结果、原等待与原卡片，再决定是否发起新工作。原调用在途则等待，已收场则读取，暂时查不到保持未知 | E1、E2、E4、R0 |
| 输入在合法边界可见 | 普通输入只在合法的输入边界被承接。承接时取当时全部合格普通输入，保留原顺序，分块读取不改变批次。新输入不改写已记录的请求 | I0、I2 |
| 执行开始只经过一次 | 执行开始之后位置只在新逻辑执行开启时经过一次。初始 checkpoint 的位置就是它，所以该位置的扩展调用提交之前崩溃时，恢复者接续同一次经过。resume、重挂接与换代不再经过 | E3、E4 |
| 请求装不下有真实原因 | Context 交不出装得下的请求时，失败候选保留固定内容超限或压缩后仍超限两类原因之一。Agent 不换模型、不删历史、不分叉、不无限压缩 | I1、P1、C0 至 C4、F1 |
| 等待 | 等待保存在原位置，不创建新执行或新挂接。等待可以挂起或交还资源。人的等待没有默认期限。超时不是取消或未执行的证明 | W0、M1、T0、A1、T3、X4 |
| 回复先准入后解析 | 模型完整回复先经消息准入，准入成功才解析动作。拒收保留原结果与费用，退避后以新 step 发新调用。连续拒收不设次数上限，否决历史跨恢复保留 | I3、Q1、Q2、Q4、Q5、I8 |
| 动作屏障 | 同批每条链到达最终结论或合法等待后才呈现本轮卡片。全部必要结论与卡片处理完成前，任何获准动作都不发起。后继出卡仍属原批 | A0、A1、X4、A2 |
| 发起前再核 | 屏障打开后，Tool 按原准入证据与当前权限再核。撤权在实际发起处生效，不以旧允许发出 | A2 |
| 全拒不伪造完成 | 本批全部动作被拒绝时，Agent 不等待从未发起的工具，为每个动作保存拒绝原因与拒绝消息，沿已有事实重新求值 | A3、T2、T3、T5、I8 |
| 结果逐槽保管 | 每个工具结果按原动作身份保管后才解除生产责任。后台占位保持同一次 Tool 执行，只释放占位这一版本的前台交付。迟到结果不改原槽位，不重开批次 | T0、T1、I8 |
| 没有动作不等于完成 | 无动作、空队列、流结束都不直接终结。Agent 仍核未完等待、协作模式、守卫阶梯与落终态之前位置 | I4、I8、F2 |
| 终态唯一出口 | 完成、失败与取消都经同一出口，由 `tryFinish` 与输入、控制、挂接共同排序后成立。先受理的输入使旧完成候选不成立。终态后只观察、保管与对账，不复活业务 | F1、F2、F3、F4、O0 |
| 控制范围 | 中断只作用于具名调用。取消只作用于一个执行。暂停只撤销当前挂接并保存接续。停用只作用于一个 runtime。任何一种都不隐含另一种 | M1、T0、E1、F0、E9、E0 |
| 守卫处置阶梯 | 守卫按原始工作事实形成 L0 至 L4 的处置，由调模型之后完整回复分支上的循环判断计算。L0 至 L3 记为 Agent 自持的守卫事实，L4 不记为守卫事实，它是循环判断以 ask 给出的请求人处理。L0 观测不可关闭。L1 与 L2 的干预消息由循环判断给出，经消息准入进入历史一次，之后推进继续。L3 形成打转失败候选。L4 请求人处理并等待答复。压缩、崩溃与换挂接不清零守卫事实。循环判断不可用时沿用上一次守卫事实，不伪造判断 | M4（守卫事实），M4、X5、Q1、Q2、Q4（L1、L2），I8、F1（L3），M4、X4、W0（L4） |
| 换挂接不丢原语义 | 原调用、扩展结论、卡片与已得判断在换 runtime 或换代后保持原语义。已有最终结论的扩展调用不再调用 | E2、X1、R0 |

本页的 L0 至 L4 专指守卫处置阶梯，规则见产品页 [J-AG08](../../../../../.meta_harness/design/product/agent-progression/design.md#j-ag08) 与系统页[循环守卫与终态扩展](../../../../../docs/architecture/runtime/loop-extensions.md#循环守卫与终态扩展)。它们不是算法节点。

## 请求与模型收场

Context 拥有可发送投影、预算与压缩。本成员提交本步用途与合法历史读取范围，取得装得下或不能装下的结论（I1、C0 至 C4）。未读输入、未完成等待的占位和原事实不被压缩清除。

调模型之前位置之后固定实际模型、参数、提示词、工具声明和模态表示（P0、P1、M0）。扩展改写候选请求时重新组装并复核，同一次经过不再次经过该位置。主请求、压缩步骤和扩展内部调用具有独立的调用身份和不同的消费位置（M5 的返回去处）。

首内容前一次真实发出发生可重试失败时，调模型之后失败分支的重试结论交回原 Model 调用，由 Model 决定继续发出或真实收场（M1、M2）。主 Loop 保持对原调用的等待，不提前形成最终结果、确认或新的逻辑调用。原调用真实收场后才经过调模型之后的最终位置和消息准入（M3、M4、I3）。用户单独中断模型后，该响应中尚未发出的建议不执行，已交付内容和费用保留。

## 消息准入

消息准入是 Agent 自己的规则，不经过扩展（U0、Q1、Q2、Q4、Q5）。各来源的调用时点与拒收后果归 SPEC 的[消息准入](../../SPEC.md#消息准入)，本页不重述。模型回复的原文不能由后置处理改写，派生表示不改原块、原顺序或原文字。

## 动作判断与结果承接

每个动作保留独立身份、原参数、生效参数、采用定义与实现及准入依据（I4）。同动作同位置的扩展按声明顺序求值，不同动作并行判断（A0）。准入检查、人看到的卡片与实际发起使用同一份生效参数（A0、X4、A2）。参数、绑定或授权依据改变后旧批准失效，无关的配置变化不重问。

前台工具交回本步所需结果（T0、T1）。符合声明的后台占位使当前步骤继续，后台不是第二次执行。不可用的替换件返回逻辑不可用结果，不假报物理启动。模型请求中的旧工具声明与当前调用约定不兼容时，Agent 返回具体原因供新的决定使用，不暗换参数或实现。

## 终态前后与控制

完成候选经落终态之前位置可以继续、等待或被否决（F1、F2）。失败与取消也经同一出口收束（F3）。扩展不能否决已生效的取消。终态成立后不再为该执行发新效果或重新花钱，迟到的结果与费用仍可保存（F4、O0）。

取消先保存意图，撤销新推进资格，再通知具名调用（E1、F0）。无法立即停止的真实执行仍可能产生效果。停止来源、请求生效、实际停止和未知效果分别记录。仅释放句柄、睡眠或换实例不传播业务取消。runtime 在原执行可靠终结后回 idle 并保持登记。新请求属于新执行，旧结果和句柄不转给新执行。

## 故障接续

新推进者先认回原调用，再按原节点接续（E2、E4、R0）。只有执行自身确认失去连续性才适用它的恢复结论。模型首内容前后的处置归 Model，Tool 失联不自动重放。用量与费用沿原实际调用，换推进者不重复记账，未知金额保持未知。恢复入口与回归点见算法页的[恢复入口与回归点](../../../agent/docs/architecture/loop-algorithm.md#恢复入口与回归点)，恢复切点表归[内部机制](../../../agent/docs/architecture/mechanisms.md)。
