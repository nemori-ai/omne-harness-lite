# Agent 定义与工作推进的内部设计

本页在正式维护位置保存待审技术设计。领域分解已评审不等于成员技术接受、阶段选择或实现支持。具名目录只有文档，公开形状和实际验证仍待设计及补证。

领域角色读[责任交接](../../../../docs/domains/agent-progression/architecture.md)，工程邻接读[组设计](../../docs/architecture.md)。本页与[SPEC](../SPEC.md)及原具名行为专题分别维护机制与行为，不据当前实现降低承诺。

## 从定义到有效构成

AgentDefinition 的能力身份、定义类型和专有继承声明由 Agent 能力解释。assembly 消费这些声明与会话执行类型要求，再使用共同资产规则确定合法身份和实现。不得把声明开放范围当作实现覆盖范围，也不得逐字段合并被替换定义的继承声明。

Session 固定定义身份；新 Run 可采用同身份最新合法版本，同一 Run 普通恢复用原已采用版本。定义、Loop 或已捕获扩展发生结构换代时，通过装配交接替换推进实例。Skill 正文、工具 schema、MCP 动作清单、模式取值或 Context 内容在稳定入口内合法更新，不据此推断必须重建 Loop。

旧清单和实际调用输入继续可追溯。候选校验失败不能发布半份新构成。实际必需入口已失效时不能靠保存旧数据假报可运行；合法定义存在但执行实现暂不可用时可保留能力位置并返回不可用原因。

## 推进次序与事实固定

Loop 的完整输入包括会话历史与有效推进投影、原调用和消费位置、当前条件以及所采用规则。相同完整输入与相同规则得到相同下一步；相同日志而当前授权或执行状态不同，不是假装同输入。

正常、全拒与等待分支见 [F-AG02](key-flows.md#f-ag02)，人工答复和后继出卡见 [F-AG03](key-flows.md#f-ag03)。

流程只表达职责和次序。控制可优先打断相应路径，不等待普通队列清空。T1 只在原步骤允许承接后消费当时全部普通输入，分块读取不改变产品批次。

模型完整回复先由 Agent 进行消息准入，再形成动作。不同动作可并行判断，同动作同位置按声明顺序处理。整批尚有未完判断、未交回答复或未处理完的卡片时，不发出已获准部分。发起前仍检查当前推进权、工作状态、授权依据和实际绑定；不能沿旧 PF 的“参数与绑定没变就永远按旧允许执行”绕过已生效撤权。

## 扩展协议的边界

十一处位置沿全系统扩展架构，不另开“组装前后”或“attempt 前”位置。调模型之后按完整回复或失败筛选；执行动作之后按单个结果或整批齐备筛选。这两个维度不增加位置。模型后失败分支包括首内容前单次真实发出结束后的重试决策，触发不以整项调用终局为前提。有效策略结论回原 Model 调用，由 Model 继续发出或真实收场，不使主 Loop 提前消费结果或 ACK。策略执行不依赖原 Agent 实例持续存活，独立调用沿同一策略边界。具体调度和恢复协议另待，不新增扩展位置。

扩展产生的改写、否决、卡片、判断结果和实际处置都可恢复。扩展只能追加事实或改变未提交候选，不能修改历史、暗中跳转或隐藏自己产生的调用。模型前扩展改变输入后重新组装并核预算，同一经过不重新触发自己。

共同动作准入是安全权威，扩展只可增加限制。工作区扩展的干预力上限为只观察。实际位置与求值后的权限进一步收窄声明能力。系统扩展有指定保守兜底，非系统扩展不可用和执行报错分别按明确策略处理。

扩展在 Run 内产生的模型或工具调用独立于扩展执行段的物理寿命。它们回原扩展位置；不能把扩展内部模型回复直接当主流程回复。已完成判断不重跑，原调用仍在途则接续，查询失败保持未知。

## 等待、消费与退出

等待是可恢复的业务位置。它可以由仍有效实例挂起，也可以交还执行资源。仅暂停不新增 attempt；原实例退出后由 Session 确立新 attempt，恢复原 Run。人的等待没有超时答案，也不靠持续轮询消耗计算。

可靠承接可以先完成处理并可靠保存完成依据，也可以先保存内容或可恢复引用、原调用归属、消费位置与后续责任。两条路径均须满足原消费契约，才能解除生产侧对应交付责任。模型 ACK 还要求真实收场和当前合法消费者；在重试中的单次发出失败不满足整项调用 ACK。工具全文不套用模型清理规则。

Agent 失去资格后不能提交新推进。原执行仍可以记录真实结果和费用，新的合法推进者可在原 Run 尚有效时继续消费。Run 终态或 Session 归档后，只进行允许的事实保管、费用结算及交付，不恢复已终结工作。

## 控制与故障交接

| 事件 | Agent 的责任 | 相邻责任的边界 |
| --- | --- | --- |
| 仅 Agent 实例退出 | 保存或依已有事实恢复原位置，释放使用关系 | 不取消 Model、Tool 或扩展已发调用 |
| Run 取消 | 停止新推进，响应具名控制，交出未收尾信息 | Session 保存意图和终态，控制原模型及前台工具；后台和无关调用不自动跟随 |
| Session 归档 | 解除原工作等待，不再发新动作 | 会话业务取消不等待全部物理执行停止；后到事实不复活工作 |
| 模型或工具查询不可用 | 保持原关联和未知状态，不发第二个原调用 | 执行拥有者确认自身失联及适用恢复结论 |
| 扩展依赖暂不可用 | 区分不可用与报错，记录按何策略处置 | 系统准入全拒；普通可选故障不扩大为全系统停机 |
| 关键保存失败或结果未知 | 阻止依赖可靠保存的新效果，按原身份对账 | 存储与事实拥有者分别承担写入及解释责任 |
| 撤除有卡片或原判断的扩展 | 保留采用依据、结果和原等待，报告未完成接续 | 不默认取消所有卡片，不把新版不同判断当旧判断已经完成 |

## 长期读取、观测与验证

推进投影和循环计数可以持久缓存，但必须标出事实进度并可从原事实重建。守卫读原始工作事实，不读压缩后的模型投影；attempt 更换和压缩不重置阶梯。实现须证明优化读取没有遗漏新输入、原等待或取消意图。

费用由原执行拥有者记账，Agent 维护原 Run 和原用途关联，不因换消费实例重复记账。诊断关联实际采用版本、扩展位置、调用、发起与消费尝试，数据外传继续遵守隐私规则。

验证覆盖正常推进、整批屏障、授权变化、卡片答复竞争、实例退出后原位置接续、终态前后扩展、迟到效果、结构交接和长期读取。旅程映射及持续验证入口见[目标成员规格](../SPEC.md#旅程验证入口)，具体操作与测试资源继续由成员细化，不据图宣称行为验证已通过。

## 待细化范围

公开操作与类型、step 切分、连续入口否决计数、扩展稳定调用和非确定输入协议、撤除后的接续、原子推进与提交未知仍需具体机制设计。扩展报错可以有类别细则，但不能扩大干预力或弱化共同兜底。

本批没有选择线程、调度器、数据库、provider 或 Cordis plugin 切分。持续利益对齐与流式在途耐久的既有待细化范围保持；不为完整候选消除未知。
