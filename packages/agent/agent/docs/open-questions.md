# Agent 定义与工作推进的待细化事项

本页维护技术义务和来源缺证，不授予新产品政策或默认机制。原问题ID保持；建议未获采用，既定边界继续有效。完整行为仍读成员SPEC及具名专题。

<a id="agent-m01"></a>
## AGENT-M01 step 切分与连续回复否决计数

模型完整回复被消息入口否决后创建新调用，期间可能换 attempt 或经过 Context 压缩。需要辨认同一推进单元。连续否决不设次数上限。

后续机制设计明确 step 边界与提交次序。

已定边界如下。

- 入口否决不是模型发出失败，后续调用具有新身份
- 否决历史跨恢复保留，不能借更换 attempt 洗掉历史
- step 不替代调用或动作身份，循环守卫读取原始事实

建议尚未采用。以原调用与位置关联设计和验证，不在本批补公开字段或统一重试算法。

影响范围。只限制精确协议及实施接受，不作为当前产品访谈。

<a id="agent-m02"></a>
## AGENT-M02 扩展稳定调用、非确定输入与撤除后接续

扩展已调用模型或出卡，当前推进实例被替换，原依赖撤除或新版判断语义不同。

后续成员设计明确稳定调用和非确定输入协议、采用版本约束、等待交接及撤除后的暂停、恢复或重建。

已定边界如下。

- 原调用与答复回原判断位置
- 已完成判断及效果不重跑，不产生第二张原卡或重复模型费用
- 原逻辑执行确定终局才作废卡片
- 不同语义的新判断不能无条件复用旧结果
- 用户等待没有超时和默认答案

建议尚未采用。保留上述行为约束，按实际依赖比较协议；不一律作废卡片或等待所有物理调用结束。

影响范围。未完成扩展换代分支的精确实现仍未定，其他已知边界可继续确认。

<a id="agent-m03"></a>
## AGENT-M03 原子推进、可靠交接与长期读取机制

多个触发竞争推进，提交确认丢失，结果交接后模型已 ACK，长期历史不断增长。

后续协调者明确资格和提交的共同边界、重放与对账接口、投影更新及负载尺度。

已定边界如下。

- 只有当前有效资格可推进，旧执行真实结果仍可写回
- 写入未知按原身份核对，不直接重复副作用
- 解除交付责任前有可靠内容或引用和原消费位置
- 缓存可重建且明确事实覆盖进度
- 原始守卫事实不因压缩或实例更换丢失

建议尚未采用。按现行承诺选择相称故障及并发验证，不选数据库、锁、线程或统一数值。

影响范围。机制与性能接受待实际设计，结构候选不声称已兑现。
