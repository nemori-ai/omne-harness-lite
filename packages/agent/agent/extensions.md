# Loop extensions 的位置与接续规格

状态为候选，待用户确认。本页与[成员 SPEC](SPEC.md)、[Loop 规格](loop.md)共同约束扩展提供者与调用协调者。它不授予新资产类别、通用角色或任意 Node API 使用权。

## 定义、采用与生效

Loop extension 声明身份、位置、适用情形、干预力及不可用处置。位置不是能力身份，同位置不同扩展可以并存；同一扩展的不同合法来源沿共同资产求值。扩展不作为 Agent 自主选择调用的工具条目呈现。

Agent 能力维护专有位置与行为含义，资产治理维护持有和合法发布，assembly 提供实际采用实现与顺序。生效扩展顺序随采用构成固定，不能在同一执行链半路暗换已捕获实现。动态数据和可用性由对应入口更新，不据此递归冻结所有下游。

声明干预力是能力上限。共同权限、位置及输入来源可以进一步收窄，不能通过运行时返回值升级。工作区扩展一律只观察。不可用处置属于该定义的声明，不是可由各层逐项配置的设置或权限。

## 十一处位置

| 位置 | 触发与输入 | 行为边界 |
| --- | --- | --- |
| 尝试开始之后 | 原工作对账后完整依据与当下条件 | 不能替代对账或给旧尝试续资格 |
| 消息落盘之前 | 尚未提交的候选输入、模型回复或工具结果 | 不能登记等人等待；按来源区分否决后果 |
| 消息落盘之后 | 已成立消息事实 | 不撤销该消息，可追加允许的新事实 |
| 压缩之前 | 将交给压缩的历史与模型档案 | 不自行认定内部待压范围；否决时不压，仍超限则失败 |
| 压缩之后 | 实际产生的 CompactionMessage | 未压缩不触发，后置不撤销历史 |
| 调模型之前 | 已组装但未发出的候选请求 | 可以阻止该请求或改候选，改动后重新预算 |
| 调模型之后 | 完整回复或失败的适用依据，区分单次发出与整调用 | 首内容前可重试失败在整调用未终局时触发策略，决定回原 Model；最终消费处理等整调用收场，不提前 ACK 或推进主 Loop |
| 执行动作之前 | 单动作、生效参数及准入依据 | 有序判断和人工等待，同批未齐不执行部分 |
| 执行动作之后 | 单结果或整批齐备 | 无否决能力，不撤销实际效果 |
| 落终态之前 | 候选终态及完整依据 | 可阻止不成立候选，继续、等待或按既有路径收束 |
| 落终态之后 | 已成立终态 | 不登记等人等待，不恢复工作或撤销终态 |

调模型之后的完整回复与失败、执行动作之后的单个结果与整批齐备分别是筛选维度，不新增位置。重试失败分支固定原调用与本次发出、失败成因、状态码、档案声明及已尝试范围，策略决定再试或不再试并回到原 Model 调用。真实单次失败不是整调用终局；只有策略不再继续或其他已定终局条件成立时才最终交接。首内容后的故障、用户中断、明确不可重试输入和已终局调用不经该分支重发。最终失败观察不重新取得重试资格；只观察扩展不改决策，系统策略不可用时按既定不再重试收束。策略与消费扩展须区分阶段和原位置，不要求另造公开枚举或 Loop 位置。

纯派生组装没有前后扩展点；attempt 尚未建立时没有尝试开始之前。

后置扩展不能否决已经发生的状态。具有可否决上限的后置扩展，只能在位置允许时提出新的等待或治理事实；动作之后仍不给否决能力，终态之后也没有可唤醒的 Run。声明与返回值必须符合位置，不能把错误返回默认为授予更强能力。

## 组合、参数和可恢复结果

同位置的扩展按采用顺序执行。后一件读取前一件处理后的候选和新增事实，不并行读原输入再按优先级拼一个结论。有效否决结束该次链；跳过不可用项后继续后继。

不同动作可并行经过各自的扩展链。每个动作先取得最终结论或到达合法等待，再呈现本轮卡片批次。整批判断未结束、所需有效答复未交回或整批卡片未按原规则处理完成时，不发出已通过的动作。完成该轮处理后回出卡位置，后继扩展可出新一轮卡片，原批次继续保持屏障。

扩展改动作参数时，执行前保留生效参数，模型原参数不改。准入、人批准与执行面对同一参数及实现。后续参数或绑定改变时不能复用旧批准；当前授权依据失效时同样不能沿旧允许发起。

模型前扩展追加了影响请求的事实后，重新组装和预算，不重新进入同一经过的模型前扩展。更换候选模型时同时重新满足窗口、模态和数据外传条件，不能先量旧输入再发送新输入。

只观察不改候选、不影响是否推进。可改写或可否决扩展保留其实际结论与必要输入，包含扩展身份、采用依据、位置、动作、原因和结果。不可用、报错、跳过与按默认策略处理分别可查；缺少记录不能伪装扩展通过。

扩展不能直接调用继续函数反复产生不留痕效果。实际模型、工具、外部读和副作用均通过可恢复的调用关联表达。非确定输入与等待前计算所需依据不能只放内存；已经保存的结论和效果复用，不再获取第二个答案覆盖原判断。

## 授权和额外检查

系统动作准入先计算结构化共同权限。明确禁止立即拒绝，不能由会话模式、自然语言授权或人的临时答复覆盖。规则允许自动执行的分支可通过；其余消费有效授权表达和会话授权模式，由共同准入产生拒绝、询问或允许。

扩展可以增加约束，不能把共同准入需要询问改成放行。其他 harness 的 allow 导入为无意见，导入方须明示转换含义。可否决不代表可替代授权或控制任意其他工作。

准入扩展不可替换、不可禁用且不可收窄。额外法务或业务检查作为独立扩展与它组合，不能借同名替换改变授权拥有者。全局授权写合法租户权限设置，单次授权只覆盖明确批准动作或整批，会话表达沿原所有者；本页不新增扩展私有授权存储。

获准后仍满足当前执行条件和合法环境。HITL 不能用普通批准解除沙箱要求，扩展也不能因已被持有而读取其他租户或发送受限内容。插件代码的能力限制继续消费安全架构，位置协议不自动提供恶意代码隔离。

## 人工等待的可靠接续

可否决能力在允许位置可以创建卡片并暂停原判断。记录须能还原扩展身份、采用依据、位置、动作、生效参数、卡片及原消费位置。普通聊天消息不能代替原卡片答复。

人工介入拥有卡片资格与唯一答复，本成员拥有答复如何回原扩展。会话与决策池展示共享同一个有效答复。等待人没有超时和默认允许或拒绝；明确“不回答”使该卡片及批次按答复规则推进，返回“没有答案”，不授予动作，不以缺批准为由重出原问题。

恢复到原等待时按以下状态处理。

| 已保存的事实 | 接续 |
| --- | --- |
| 卡片尚未答完且逻辑等待有效 | 保持原等待，不轮询模型、不出新卡 |
| 当前批次有效答复已交回，整批已按原规则处理完成 | 回出卡的扩展位置继续后继链；后继出卡继续保持屏障 |
| 同位置前件已取得结论 | 复用结论，不再次执行判断或效果 |
| 内部模型或工具仍在途 | 接续原调用，在原判断位置消费 |
| 原结果已由消费侧可靠保管 | 使用该内容或可靠引用，不重领已 ACK 完整副本 |
| 原逻辑工作已经终局 | 卡片失效，不伪造人的答案，不恢复工作 |
| 只丢失物理实例、句柄或查询暂不可用 | 不据此判卡片终局，不重发原调用 |

等待前后的回放不能多调一次已完成模型、重做效果或付第二遍判断费用。回放过程中遇到已存等待，交回日志保存的结果；不是从入口无条件重跑任意代码。

工具内部 Ask 的等待属于 Tool Execution，扩展卡片属于原 Run 判断位置。两种等待可以共享人工入口，但不能互换身份和终结依据。人无答复不消耗持续推进计算，合法答复后的继续执行仍须有效资格。

## 不可用与报错

不可用是扩展未能提供能力，报错是执行已经开始后失败，等人是正常等待。三者不能混用同一超时处置。

| 情形 | 处置 |
| --- | --- |
| 非系统扩展不可用，无额外声明 | 跳过该项，记录实际缺失与处置 |
| 非系统扩展声明缺失即否决 | 仅当前实际干预力仍为可否决且位于前置位置时生效，否则按位置及收窄结果跳过 |
| 非系统扩展要求指定替代件 | 不授予该声明；指定兜底仅由系统预先声明 |
| 只观察扩展报错，无具体类别策略 | 不改变推进，记录失败 |
| 可改写扩展报错，无具体类别策略 | 不应用本次改写，记录失败 |
| 可否决扩展报错，无具体类别策略 | 按所在位置合法的否决处置并记录；不能取得后置撤销能力 |
| 已有类别具体报错策略 | 采用该策略，仍受位置、权限与共同安全边界约束 |

声明缺失即否决不是各层可配的策略值。更具体层若要改变该声明，须走合法定义替换而不是给同一资产私配值；上级可锁定替换。依赖恢复后该扩展可重新可用，但不能因此重跑已经完成的原判断。

系统扩展的指定兜底不依赖失效原件的资源，实际采用仍可见。

| 系统扩展不可用 | 指定处置 |
| --- | --- |
| 动作准入 | 全拒，不放行、不出卡代办授权 |
| 模态转换 | 登记过转换件但不可用时按转换失败，不伪造可读表示；从未登记转换件按模型能力契约分别处理 |
| 重试策略 | 不再重试，保留真实失败与原费用 |
| 循环判断 | 记录不可用，不伪造检测结论 |
| 单结果卸载 | 记录不可用，不伪造已卸载 |

模态转换本阶段不是组织或租户可替换资产。其他系统策略的合法替换沿其具体契约，不从共用扩展点推出统一替换权。Loop 守卫 L0 的观测责任保持，不以组件缺失隐藏该状态。

## 否决、停止和终态

前置否决阻止对应候选状态。消息入口按来源分别拒收、另起模型调用或提出 Run 失败；压缩之前否决只是不压，无法装入仍失败；模型之前不发请求；动作之前不做该动作；终态之前否决不成立的完成候选后继续求值。

完成、失败和取消沿各自有效治理路径；扩展不能否决已生效取消来恢复新工作。后置扩展不改已成立终态。具体终态提交由 Session 完成，扩展没有独立落账通道。

动作之后或其他位置提出停止时，先记录以该扩展为真实发起来源的取消请求，随后走适用的治理与终态路径。不伪造人工拒绝，也不把停止称为已经撤回外部效果。取消权限与目标范围仍须明确，位置自身不授予通用停止权。

## 结构换代与未完成判断

assembly 撤除或替换已捕获扩展时，本成员交出原判断、采用版本、已发调用、卡片和消费位置。实例释放不自动取消这些独立执行；新版语义不同的判断不能直接使用旧结果当作自己已完成。

旧判断仍合法可接续时回原位置继续。依赖真实失效时沿该判断协议暂停、恢复或重建并说明原因，不能默认所有卡片作废，也不默认等待全部模型或工具物理结束才交接。精确撤除协议尚需设计，不由作者补默认。

## 验证与作者义务

扩展作者给出完整前提、依赖、可用性、报错策略、真实效果和可恢复输入。等待前留在本地内存的变量不能成为恢复后的唯一依据。声明可插拔不证明在撤除、恢复和并发下仍满足协议。

持续验证覆盖十一处位置的合法能力、后置不得撤销、工作区只观察、有序组合、改参批准一致、整批屏障、重复答复、明确不回答、实例替换不重问、不重复模型费用、系统全拒兜底、普通扩展跳过、授权收窄、撤除未完判断及终态后结果。测试须能指出违背某条约束的反例，不只照抄扩展注册表。

稳定调用身份、可恢复非确定输入、编码结构、类别报错细则、提交未知和撤除后的接续协议仍需细化。本页给出不可降低的行为边界，不声称这些机制已经具备。


## 旅程与持续验证

本页承接 [J-AG03](../../../.meta_harness/design/product/agent-progression/design.md#j-ag03)、[J-AG06](../../../.meta_harness/design/product/agent-progression/design.md#j-ag06)、[J-AG07](../../../.meta_harness/design/product/agent-progression/design.md#j-ag07) 及 CAP-AG05、CAP-AG06、CAP-AG09。整批正常与后继出卡流程见 [F-AG03](docs/key-flows.md#f-ag03)，恢复与换代见 [F-AG06](docs/key-flows.md#f-ag06)、[F-AG07](docs/key-flows.md#f-ag07)。

出卡、HITL 有效答复交回和原扩展接续分别具有可恢复责任。第一段成立不要求已经有人答复，第二段成立不要求原位置已完成处理。只有本批所需卡片按原规则全部处理完成，才能继续原经过并核对整批判断是否齐备。卡片身份和唯一有效决定归 HITL，授权类含义归 authorization；Agent 保存经过、位置、动作与参数绑定，不用聊天消息替代决定。

| 场景 | 可观察判据 |
| --- | --- |
| 三动作中一件已通过、一件等人、一件判断在途 | 已通过动作未发出；各动作先到结论或合法等待，再呈现本轮批次 |
| 出卡后退出、答复交回后退出、原位置处理中退出 | 三个时点均认回原经过和责任，不重出原卡、不重跑已存判断或内部模型 |
| 全部卡片有答复但一项原规则处理未完成 | 不放行整批，答复到达不冒称处理完成 |
| 第一轮处理后后继扩展再次出卡 | 新卡片有新等待，原动作批次继续屏障；不得从 T5 直接跳 Tool |
| 明确不回答或会话与决策池同时答复 | 唯一有效决定；不回答不批准，不重问同卡；竞争按 HITL 原契约处理 |
| 等待时参数、绑定、授权依据变更，或仅无关配置变化 | 前三项变化不复用失效批准；无关变化不机械重问；准入、人所见和执行参数一致 |
| 系统准入不可用与普通扩展不可用或执行报错 | 系统全拒且不出卡；普通扩展按声明、实际干预力及位置处理，处置可查 |
| 原逻辑工作终局，与只有 Agent 物理退出相比较 | 前者卡片失效且不伪造人决定；后者保持原等待，独立 Tool Ask 不受扩展退出代办 |
| 扩展撤除或换语义版本时仍有原判断和卡片 | 保存原采用语义与责任；缺精确接续协议则报告未完成，不默认重判或全部作废 |

稳定经过、非确定输入、撤除与跨域有效边界仍由 AGENT-M02、AGENT-M03 细化；上述判据不宣布已完成行为验证。
