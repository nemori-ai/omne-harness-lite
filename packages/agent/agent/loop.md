# Agent Loop 与原工作接续规格

状态为候选，待用户确认。共同输入和责任见[成员 SPEC](SPEC.md)，扩展行为见[扩展规格](extensions.md)。本页约束下一步求值与执行协调，不拥有 Session、Run 或调用的物理寿命。

## 求值依据

Loop 使用原工作事实、已采用规则和当前运行条件求出下一步。完整输入包括有效推进状态、待处理及已承接输入、原调用与原消费位置、扩展判断和卡片、当前权限与模式、模型与窗口、Context、环境和资源条件。

同一完整输入和同一规则应得到同一下一步。历史日志不能独自还原当前注册或执行状态；当前授权变化不是同输入求值失败。所有会改变后续推进的非确定判断、采用数据、等待及外部效果须可恢复，不能只存在旧实例内存。

纯派生求值可以重算，实际模型或工具调用不能因重算再次发出。Loop 不接管所有系统 event loop，不限制其他 Session 同时推进。

## 启动与接续次序

开始 attempt 时按以下次序处理。

1. 取得 Session 的原 Run 和当前有效资格。Run 已终态或有效取消已生效时，不开始新业务推进。
2. 核对原模型、工具、压缩、扩展及人工等待；先接续原工作，不跳回新模型请求入口。
3. 读取当前合法装配与能力可用性，拉取当前获准 Runtime Context。空闲期变化按当前快照与会话上次感知值形成适用提醒，不补造空闲期间每一步变化。
4. 保留 Session 的非消息 attempt 开始事实，包含 Run、序号、时间和真实原因。此事实不自动变成模型消息或恢复提示。
5. 当前条件及原等待责任齐备后，求值下一步。

attempt 结束记录可以帮助追溯，但崩溃时没有结束记录不构成恢复失败。挂起后继续同一有效实例仍是同一 attempt；替换或失去连续性后由治理建立新 attempt。内部模型重试不自动创建 Agent attempt。

## 正常转移与恢复位置

以下是行为判定，不固定公开枚举或数据库状态。

| 当前事实与条件 | 应做的事 | 不能做的事 |
| --- | --- | --- |
| 已有终态或有效取消 | 停止新推进，按原控制和保管责任收束 | 看最新结果就复活 Run |
| 原主流程模型尚未真实收场 | 继续等待原调用，可挂起或交还资源 | 新消息到达或实例替换后重发原请求 |
| 原扩展、压缩或工具调用未完 | 回原判断、压缩或动作位置接续 | 把内部回复当主流程模型消息 |
| 原结果已交接但尚未处理完 | 从消费侧保存的数据接续 | ACK 后要求生产侧重领或重发 |
| 步骤允许取输入且有普通队列 | 持久承接当时全部输入并保留顺序 | 分块搬运变成额外可见批次 |
| 合法输入无法形成装得下的请求 | 沿实际原因上交并提出失败 | 无限压缩或全部归因固定部分 |
| 适用卡片批次未答完 | 保留原等待，不发同批获准部分 | 把未答当拒绝、允许或故障 |
| 原卡片批次答复交回且已按原规则全部处理 | 回出卡扩展继续有序判断，后继可再出卡 | 再出原卡或重新付费取得已存判断 |
| 整批动作判断齐备 | 复核实际发起条件，执行获准动作，记录拒绝原因 | 用旧批准绕过已失效授权 |
| 整批动作均被拒绝 | 保留原因和原回复，沿当前事实重新求值 | 等待从未发起的工具，或直接判定完成 |
| 前台结果未齐 | 等原执行或合法后台占位 | 因等待者退出认为工具已失败 |
| 本步所需结果齐备 | 先可靠承接，再经执行后扩展，重新求值 | 将过程帧当最终结果 |
| 没有动作、没有待处理输入 | 核未完成等待、模式和终态前扩展，形成完成候选 | 仅由队列空直接写完成 |

普通输入只在合法承接边界可见。卡片答复、控制和系统业务输入按自己的去处处理，记录进日志不自动授予普通队列资格。Trigger 只要求检查条件，等待尚未满足时不得创建空转 attempt。

### T1 至 T8 的文档定位

这些定位号连接既有转移、产品旅程和 Session 交接，不是新增公开枚举或第二份工作状态机。表中每行引用本页行为，终态归 Session。

| 定位 | Agent 的判断与责任 | 相关流程 |
| --- | --- | --- |
| T1 | 原位置允许且没有须先接续的本步骤调用时，承接当时全部合格普通输入，交 Context 处理 | F-AG02、F-AG04 |
| T1′ | Context 交不出合法且装得下的请求时，保留实际原因并提出失败，进入统一终态出口 | F-AG04、F-AG05 |
| T2 | 输入可发送且没有原待接续模型时，模型前扩展、再预算、固定输入并登记原调用 | F-AG02 |
| T2w | 等主流程原模型真实收场；内部压缩和扩展调用回各自原位置 | F-AG02、F-AG06 |
| T2′ | 完整回复没有动作且无应承接输入时提出完成候选，仍检查等待、模式与终态前扩展 | F-AG05 |
| T3 | 对完整回复中的各动作运行有序扩展链，整批判断屏障保持 | F-AG03 |
| T4 | 保存原卡片批次和等待位置，等有效答复及原规则处理，不轮询模型 | F-AG03 |
| T5 | 所需答复交回且整批处理完成后回原出卡扩展继续；后继出卡再等，全判断齐备才核当前执行条件 | F-AG03 |
| T6 | 获准动作已发出，本步所需前台结果或合法后台占位未齐时，等原 Tool | F-AG02、F-AG06 |
| T7 | 所需结果齐备后可靠承接，执行后扩展，再求值下一步 | F-AG02 |
| T8 | 全批动作均被否决时保存原因，重新求值，不等未发工具或直接完成 | F-AG02 |

原工作接续、取消和既有终态优先，不能把 T1 当作所有恢复的固定入口。T4 可来自其他允许等待的扩展位置，不局限于执行动作之前。T1′、T2′ 的出口都遵守本页终态前后规则。精确 step 切分仍见 AGENT-M01。

## 请求组装与模型收场

请求上下文成员拥有可发送投影、预算和压缩行为。本成员提交本步目的及合法历史读取范围，取得装得下或不能装下的明确结论。未读输入、未完成等待占位和原事实不被压缩清除。

模型前扩展之后固定实际模型、参数、提示词、工具声明和模态表示。扩展改变日志或候选请求时重新组装和校验预算，同一次经过不再次跑模型前扩展。固定部分自身超限与历史加上固定部分仍超限分别说明。

主流程模型、压缩模型和扩展模型具有独立调用和不同消费位置。模型 runtime 自己的合法重试保留真实发出、失败及费用；一次发出失败不等于整项调用已经结束，本成员不提前消费完整结果或 ACK。

首内容前一次真实发出发生可重试失败时，可在整项调用尚未终局时触发模型后失败分支的有效重试策略。策略结论回原 Model 调用，Model 决定继续发出或真实收场；主 Loop 保持对原调用的等待，不提前形成最终结果、ACK、Run 终态或新的逻辑调用。该策略不依赖原 Agent 实例一直运行；换代沿原调用及决定接续，独立消费同样适用。具体策略调度与持久协议另待。

原调用真实收场后才执行适用的最终模型后处理和消息入口扩展。终局失败不再送回策略恢复原调用；回复被消息入口否决后的新调用与内部重试分开。工具参数尚未完整到达不得解析发起。模型 runtime 只提供候选回复，不替 Agent 发出建议动作。

用户单独中断模型后，不执行该响应中尚未发出的建议；保留已交付内容和费用，模型中断不暗中取消无关工具或整个 Run。

## 消息入口的失败链

| 候选被否决的来源 | 本成员必须处理 | 保留的责任 |
| --- | --- | --- |
| 外部输入 | 向受理方交回拒收原因，不承接为本轮消息 | 输入受理方记录拒绝结果；不能静默成功 |
| 模型完整回复 | 原调用仍是其真实收场；记录被哪个扩展否决，退避后可以创建新调用 | 原结果和费用不改写成调模型失败；连续否决上限仍可跨恢复识别 |
| 归属仍有效、尚未终结 Run 的工具结果 | 提出该消费契约指定的 Run 失败及具体扩展原因，不重跑原工具或制造替身结果 | 原结果、效果、费用与保管责任仍归原执行 |

后台、Run 外或原 Run 已终结的结果被拒收，按原消费契约处理，原终态不改，不默认挂到后继 Run。没有有效 Run 不造一个，已取消业务不得取得新入队资格；尚未明确的旁路后果留给原消费拥有者，不由本条代选。

模型回复后置处理不能改写已展示原文。转换件可以按契约附加派生表示，不改原块、原顺序或原文字。入口否决后的新调用是新调用，不是原调用内部重试。

连续否决上限是一项适用运行策略。step 精确切分、计数归属、退避和设定形状尚需细化；机制未明不允许在每次 attempt 或新调用时洗掉同一连续否决历史。

## 动作判断与结果承接

每个动作保留独立身份、原参数、实际生效参数、采用定义与实现及准入依据。同动作同位置扩展有序求值，不同动作允许并行判断。整批判断未齐备、尚有人答复未交回或本批卡片尚未按原规则处理完成时，不发获准部分。

实际发起前，当前推进资格、Run 状态、授权依据、能力绑定、参数和环境必须仍适用。参数和绑定相同不足以证明旧授权有效。条件仍适用时，不因为无关配置变化或 reload 机械重跑全部判断和出卡；失效条件不能由缓存的旧允许掩盖。

模型请求中的旧工具声明与当前调用约定不兼容时，不把旧参数交给新版或暗中改参。给 Agent 具体原因，由后续新的决定提出合法动作。原模型结果和费用照常保存。

前台工具需交回本步所需结果，符合声明的转后台占位可使当前步骤继续。后台不是第二次执行，不更改原 Session 与 Run。卸载占位包含必要结果与全文引用，原全文由工具保存；后续取回追加新调用和结果，不替换历史占位。

dummy execution 沿同一逻辑动作和原消费位置取得不可用结果，无需启动原物理工具。保留真实处理，不虚构效果或用量，不让恢复因没有物理工具实例而再调同一次逻辑动作。

## 终态前后与控制

无动作和队列空不跳过未完成等待、协作模式或终态前扩展。完成候选经适用扩展可继续、等待或被否决。有效终态由 Session 记录，终态后扩展处理已成立事实，不能恢复工作。

失败、取消与异常上交分别表达。上交可能在 Run 失败后继续有处理责任，不新增“已上交”终态。终态成立后不为该 Run 新建 attempt、发效果或重新花钱；原执行迟到的结果和费用仍可保存。

取消先保存意图，撤销新推进，再通知具名执行。没有 Agent runtime 时也由治理沿持久调用关联处理。Run 取消覆盖其模型和前台工具；后台工具、子 Session 和无关调用按各自规则。Session 归档按业务取消结束原等待，不以物理全部停止为前置。

仅释放句柄、睡眠或换实例不传播业务取消。无法立即停止的真实执行仍可能产生效果，不能用逻辑取消伪造物理中断。停止来源、请求生效、实际停止和未知效果分别记录。

## 循环守卫与历史读取

守卫读取原始工作事实，阶梯由对应历史派生。L0 观测不可关闭；L1 和 L2 追加干预消息；L3 提出打转失败；L4 请求人处理。同一完整依据上的已存判断复用，不以压缩摘要、新 attempt 或实例崩溃重置。

检测窗口和阶梯可持久缓存，缓存不是第二份权威。缓存须对应明确事实进度，可重建，并能识别滞后。普通技术恢复不能通过伪造新工作消息洗掉循环历史。

预算、时限和轮数采用明确策略，不在本规格设置统一数值。持续产生新工作而不打转的 Loop 不自动因“运行很久”终结。追加预算守卫不能据此新增本候选未采用的额度或配额业务。

长期查询取必要区间及可靠投影，不要求每次扫描全部会话。性能优化不得漏掉取消、原等待、未读输入或已知调用；未对齐流式耐久不声称已展示内容跨生产 runtime 失联均已证实可恢复。

## 故障接续与持续验证

新推进者先认回原调用。仍在途则等待，已收场则读取，暂时查不到保持未知。只有执行自身确认失去连续性才返回其恢复结论；模型首内容前后由 Model 处理，Tool 失联不自动重放。

用量及费用沿原实际调用。尝试一发起、尝试二消费同一成功结果，不能重复收费，也不能把它自动记成崩溃浪费。未知金额保持未知，不伪装零费用。

实现须保留以下可复跑场景。

| 场景 | 证据要说明 |
| --- | --- |
| 取输入前后崩溃 | 一次承接、顺序不变，原 Run 接续 |
| 主流程或内部模型在途时换实例 | 不重发，结果回原消费位置 |
| 已可靠交接、ACK 生效后换实例 | 从消费侧继续，不重新领取完整结果 |
| 三个动作其中一个等人 | 所有判断先到结论或等待，获准部分未提前执行 |
| 同批等待中撤权 | 旧允许不突破当前准入，无影响变化不机械重问 |
| 仍有效 Run 的工具结果入口被否决 | 不重做原工具，该消费 Run 失败，原效果仍可查 |
| 模型完整回复连续被否决 | 新调用与原内部重试分开计，恢复不清零限制 |
| 取消与完成候选竞争 | 一个有效终态，不用迟到结果恢复旧 Run |
| 仅 Model 查询暂不可用 | 保留未知，不制造重复原调用 |
| 长历史经过压缩与新 attempt | 读取范围可说明，守卫依据及阶梯不洗掉 |

step、计数与提交边界仍需机制设计。上表是验证义务，不是本批运行过这些行为的报告。

| 场景 | 可观察判据 |
| --- | --- |
| 完整模型回复含两个动作，第二个参数块尚未完整 | 完整回复与完整参数以前没有 Tool 发起；流 finish 不代替 Run 终态 |
| 整批动作全部被拒绝 | 保存逐动作原因并重新求值，不等待工具，不直接写完成 |
| Context 固定部分超限，或允许压缩后仍超限 | 原因可区分，该 Run 失败，历史和 Session 保留；无自动分叉、删历史、换模型或无限压缩 |
| 主模型、压缩模型与扩展内部模型分别在途后换实例 | 各自接续原调用与原消费位置；内部结果不作为主模型回复，无重复发出和费用 |
| 后台、Run 外、原 Run 已终结三类 Tool 结果被入口拒收 | 原事实仍可查，不造 Run、不改旧终态、不默认入后继 Run；有效未终态 Run 按消费契约失败 |
| 只有模型被中断，其他 Tool 仍在途 | 该响应未发建议不执行，Run 不自动取消，已有 Tool 独立收场 |
| 完成候选、失败与有效取消竞争 | 统一出口记录唯一终态；取消先有效后无新推进，后置扩展不反转终态 |
| 归档后迟到结果，随后撤销归档 | 事实和费用可保管；回休眠，不重启旧 Run、调用、卡片或业务输入 |
| 保存确认丢失或模型查询暂不可用 | 原身份对账，未知仍可见，不重复发效果或伪装零费用 |
| 长历史、压缩、新 attempt 与守卫 L3/L4 | 原始阶梯不清零；L3 走统一失败出口，L4 回原人工等待；读取和诊断权限可核对 |

测试须检查实际发起次数、原身份、消费位置、终态和责任记录。阈值、性能尺度及精确并发边界仍由 AGENT-M01、AGENT-M03 对齐，不能由本表反推公开 API 或部署数值。
