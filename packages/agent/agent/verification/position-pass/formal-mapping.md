# 一次经过：租户随时装卸之下的扩展链

`PositionPass.tla` 检查 Agent Loop 走过一个扩展位置的一次经过。租户在任意时刻装上或卸下拓展件，协调者进程可以崩溃并被接管，视图可以读不到，调用的结果可以丢失，Run 可以被取消。

本页写明模型检查了什么、上限是多少、每个动作对应哪条规则，以及它不检查什么。

## 结论的边界

TLC 在下面的上限内穷举了全部可达状态。结论只对这个模型和这些上限成立，不是对实现的证明。实现与模型一致，由契约测试守，清单见本页末尾。

## 模型对应的正文规则

| 规则 | 出处 |
| --- | --- |
| 走到位置时读一次租户启用的链并记下，这一次经过里链不变 | `docs/architecture/runtime/loop-extensions.md`「一次经过与扩展链的来源」 |
| 扩展调用先提交为已请求，提交确认之后才调用 | `packages/agent/SPEC.md`「扩展与卡片」 |
| 已有最终结论的扩展调用不再调（I6） | `packages/agent/SPEC.md`「不变式」 |
| 结果未知时以重放模式按原精确采用重新调用，不以全新方式重开 | `packages/agent/SPEC.md`「扩展与卡片」 |
| 不可用只在证实调用没有开始时成立；判不明开始或收场是未知（I4） | `docs/architecture/runtime/loop-extensions.md`「不可用、报错与系统扩展」 |
| 取消生效之后不新增业务效果（I13） | `packages/agent/SPEC.md`「不变式」 |
| 读不到不变成空 | 根 `AGENTS.md`「心智模型要点」 |


## 状态与动作

| 模型里的名字 | 含义 | 类别 |
| --- | --- | --- |
| `view`、`viewUp` | 租户此刻启用的集合；视图读不读得到 | 环境 |
| `opened`、`snap`、`st`、`concl`、`left`、`cancelled` | 经过已开；记下的链；每件的调用状态与结论；已离开位置；取消已生效 | 耐久（执行记录） |
| `online`、`mine`、`tried`、`known`、`inflight`、`decidedEmpty` | 协调者进程在不在；本进程提交了这件的已请求；本进程调过它；本进程手里的结果；在途的调用；本进程读到空链 | 易失，崩溃清空 |
| `snap0`、`runs`、`freshStarts`、`runsAfterConcl`、`startsAfterCancel`、`leftUnread` 与四个计数 | 只用于陈述性质与限定状态空间 | 幽灵变量 |

| 动作 | 对应的实现步骤 |
| --- | --- |
| `OpenPass` | 读视图；一次提交写入链快照与第一件的已请求 |
| `SeeEmpty`、`LeaveEmpty` | 读到空链，不开经过；所在节点自己的提交离开位置 |
| `Launch` | 取实现并调用。实现此刻不在：全新调用证实没有开始，得到不可用；重放保持原状态等待 |
| `Return` | 调用返回合法输出，或结果丢失 |
| `Conclude` | 一次提交写入这件的结论与下一件的已请求。否决不开下一件 |
| `Apply` | 链走完或被否决截断，采纳效果并离开位置 |
| `Crash`、`Takeover` | 进程崩溃，易失状态清空；新实例接管，沿耐久记录继续 |
| `Flip`、`ViewDown`、`ViewUp`、`Cancel` | 租户装或卸一件；视图读不到与恢复；取消生效 |

链的顺序用编号的大小表示。

## 性质

| 性质 | 说的是什么 |
| --- | --- |
| `SnapStable` | 经过开着时，记下的链等于开的那一刻的链 |
| `OnlySnapRuns` | 只有记下的链上的成员在这次经过里运行 |
| `NoRecall` | 已有结论的成员不再被调用 |
| `FreshOnce` | 每个成员至多一次全新调用，其余都是重放 |
| `UnavailableNeverRan` | 结论是不可用的成员，一次也没有运行过 |
| `NoStartAfterCancel` | 取消生效之后没有新的调用开始 |
| `NeverLeftUnread` | 视图读不到时，不按空链离开位置 |
| `InOrder` | 成员按链序运行；否决之后没有成员开始 |

## 配置与结果

`run-tlc.sh` 逐份运行 `expect.txt` 里的配置，并核对结果。两份正例应当通过。六份反例各打开一个故意的错误，应当报出指定的那一条性质。四份可达性配置把「这种情形不会发生」写成不变式，应当被违反，用来证明模型走得到这些情形。

| 配置 | 打开的错误，或要到达的情形 | 应当的结果 |
| --- | --- | --- |
| `valid-empty-start` | 无。起点没装 | 通过 |
| `valid-installed-start` | 无。起点装了两件 | 通过 |
| `bad-resnap` | 接管后重新读链 | 违反 `SnapStable` |
| `bad-recall` | 接管后把已有结论的成员重新置为已请求 | 违反 `NoRecall` |
| `bad-fresh` | 崩溃后把未知的调用当作全新调用 | 违反 `FreshOnce` |
| `bad-unknown` | 把丢失的结果写成不可用 | 违反 `UnavailableNeverRan` |
| `bad-cancel` | 取消生效后仍开始调用 | 违反 `NoStartAfterCancel` |
| `bad-unreadable` | 把读不到当作空链 | 违反 `NeverLeftUnread` |
| `reach-applied` | 链运行后被采纳 | 到达 |
| `reach-hot-install` | Run 开始时没装、之后装上的成员进入了链 | 到达 |
| `reach-replay` | 同一个成员物理运行了两次 | 到达 |
| `reach-revoked` | 记下之后被卸掉的成员以不可用结束 | 到达 |

## 被假定的环境行为

- 一次提交是原子的。
- 被取代的旧挂接不能提交。这条由执行记录的围栏守，见不变式 I2，本模型不重复检查。
- 实现此刻在不在，由它是否在租户当前启用的集合里表示。实现的登记被撤回与持有被禁用，在模型里是同一个事件。
- 崩溃不撤销已经开始的物理运行。

## 模型边界

本模型不检查下面这些：

- 出卡、答复与整批判断屏障。它们由 `packages/agent/agent-contract/verification/models/CardRounds.tla` 检查。
- 停止与重试的归约次序。它是对已形成的结论前缀的纯函数，由成员用例守。
- 同一批里多个动作的多条链。每条链是本模型的一个实例，它们共用一次读链，这一点由成员用例守。
- 活性。模型只检查安全性，并关闭了死锁检查，因为经过以终止状态结束。
- 命令型实现的启动与收场的细分步骤。模型把它们合成「调用开始」与「结果返回或丢失」两步。启动意图已登记而结局未保存的窗口，在模型里就是 `Launch` 之后的崩溃。

## 转契约测试的清单

每条性质一个测试。测试断言模型给出的结论，并写明去掉哪个检查它会变红。

| 性质 | 测试断言 | 去掉什么会变红 |
| --- | --- | --- |
| `SnapStable` | 经过开着时改变视图，接管后链不变 | 接管时不读记下的链快照 |
| `OnlySnapRuns` | 经过当中新装的成员在这次经过里不运行 | 每件调用前重读视图 |
| `NoRecall` | 结论提交后崩溃，接管后实现的调用次数不增加 | 恢复路由不看结论 |
| `FreshOnce` | 调用在途时崩溃，接管后的调用模式是重放 | 恢复时以全新模式调用 |
| `UnavailableNeverRan` | 结果丢失后不形成不可用的结论 | 把传输失败映射成不可用 |
| `NoStartAfterCancel` | 取消生效后走到位置，没有调用开始 | 取链前不查取消 |
| `NeverLeftUnread` | 视图答读不到时，前置位置等待，不离开 | 把读不到映射成空链 |
| `InOrder` | 否决之后的成员没有已请求的记录 | 结论提交时无条件开下一件 |
