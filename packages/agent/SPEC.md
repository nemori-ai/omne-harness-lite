# Agent

## 总体架构

Agent 管一轮 Run 怎样往前推。包组有四个成员：

| 成员                    | 回答的问题                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------ |
| `agent-contract`        | 一轮里有哪些声明、检查点长什么样、边界上怎样判。纯数据与纯函数，不依赖 Cordis 和存储 |
| `agent`                 | 一轮怎样一步步推进。不依赖 Cordis，离开这套系统也能单独用、单独测                    |
| `agent-cordis-contract` | 在这套系统里它以什么服务出现                                                         |
| `agent-host-local`      | 在本机上把实现、配置与邻域的端口接起来                                               |

推进是一张节点与边的表，加一个按表走的协调者。每到一个节点做一件事，按结果选一条边。走到哪、手里有什么，记在检查点里；检查点随执行记录进会话日志。

源码依赖只朝内：消费者依赖契约成员；通用实现只依赖契约与通用能力；Cordis 定义只依赖契约；宿主依赖 Cordis 定义与通用实现，再由应用装配。契约与通用实现的根入口都不导入 Cordis，也不导入任何外部协调者的类型；Cordis 绑定只从 `./cordis` 入口导出，测试替身只从 `./testing` 入口导出。

通用实现分三层。纯求值只读决策事实，返回下一步，不调执行记录，也不读时钟。效果协调层调执行记录，驱动 Model、Tool 与各个窄端口。宿主集成层把持久提供者与 Cordis 适配成纯端口。可复用的 runtime、可恢复的 execution、物理的执行挂接、纯求值是四件分开的东西：runtime 可以顺序承接多个 execution，同一时刻至多一个；执行结束后它回到空闲，不撤登记。

执行记录（Journal）的提供者有两种。独立提供者只保护 execution 自己的输入受理与结束。带提交参加者的提供者在同一次提交里同时保护外部协调者的事实。一个绑定固定一种协调模式，没有隐式默认。

Model 与 Tool 的结果由接收方保存。接收方是宿主装配并常驻的角色，在 Agent 实例之外，实例重建不丢它的状态。

## 领域边界

Agent 拥有一轮之内的次序：什么时候承接输入，什么时候要一次模型，什么时候交出工具调用，什么时候收尾。它还拥有执行记录的格式、检查点、消息准入的规则、扩展的作者协议与位置输出表、动作批的判断屏障，以及定义的声明与精确解析。

Agent 不拥有会话日志。它的执行记录交给日志的写入者去写。Agent 不拥有模型调用与工具执行：对它来说 Model 和 Tool 是被远程调用的服务，两端各管各的生命周期。

Agent 不认识调用它的是谁。它需要的东西声明成端口，由外层来适配。外部协调者的业务关联、输入受理、业务终态都留在协调者一侧；Agent 不接收也不返回协调者的业务身份，只返回 execution、执行挂接、操作与事件的身份。独立调用者没有这些对象，也不必模拟它们。

Agent 也不拥有下面这些，只消费它们给出的结论：

- 一次模型请求里历史与块的投影、预算、是否压缩、压缩的范围与算法，归 Context；档案解析、请求准备、发出与真实收场，归 Model。Agent 只拥有用途、调用次序、扩展调用、结果去处与失败候选。
- 谁能调用 Agent 的某个公开操作（主体资格），与某个 Model 或 Tool 动作能不能发起（动作准入），是两件事，都归授权，经两个端口问。Agent 不解释组织、角色、权限模式与协作设置。
- 卡片的唯一有效答复、拒答与故障的区分归人工介入。Tool 内部等人的等待归 Tool；Agent 只把它投影成在等人，不为它出卡。
- 外部输入的展开、脱敏与否决发生在输入受理方，在交给 Agent 之前。Agent 只看到受理后的完整内容。
- 跨执行的发现、什么时候恢复哪个 execution、失败之后的退避，归外部协调者或装配宿主。

| ---------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------- |

| 主体资格核验                 | `packages/identity`，经应用装配适配                   | 某个主体能不能调用某个公开操作，答允许、拒绝或不可用                                               |

| 测量事件                              | `packages/telemetry`               | 一次受理、一次驱动的起止                                    |

## 心智模型

一轮 Run 是一串步。一步是：承接输入，要一次模型，处理模型的结果，求值。求值只有三种结论：再走一步，等一件事，收尾。一次主模型请求开一步；模型内部的重试、压缩的模型调用、扩展内部的调用都不开新的一步。

协调者是活体，不存别处没有的事实。它丢了，新的协调者从检查点接着走。拿这一条量一个设计：一个只存在协调者内存里的计数或标记，重建之后就没了，所以它不能决定任何结局。恢复的接续点只能是能只凭日志重建全部所需状态的节点；做不到的节点不能当回归点。

几组容易混的事要分开想：登记不等于已发出；准入通过不等于执行成功；模型建议不等于工具发起；空队列、流结束、没有动作都不等于工作做完；接到控制不等于对方已经停下；读到 Runtime Context 不等于采用了它，选到一个模型也不等于有发送资格。未定也有两种：查询没有可信结论，保持未知；执行已可靠收场而标明外部效果未知，是一份可以消费的真实结果。人的拒绝、合法等待、模型被打断、工具转后台、实例更换都不是故障。

## 应然设计

### 一次主模型调用怎样收场

结果是一个封闭的集合，只有三类：

| 类       | 是什么                                                                         | 这一步怎么办                               |
| -------- | ------------------------------------------------------------------------------ | ------------------------------------------ |
| 完整回复 | 调用完成，内容完整                                                             | 照常处理。一串失败到此结束，重试的记录清空 |
| 被打断   | 人的控制让调用停下                                                             | 按控制的结果收。这不是失败                 |
| 不可用   | 其余全部：调用失败，不管出没出过内容；调用完成但内容被截断；调用完成但没有内容 | 见下表。绝不记成完成                       |

不可用再分暂时性与永久性。暂时性只有三个成因：上游不可用，流丢失，运行时丢失。哪个成因是暂时性的由模型契约判，Agent 不自己列。

| 不可用的情形       | 处置                                           |
| ------------------ | ---------------------------------------------- |
| 暂时性，预算没用完 | 记一次失败，等到策略给的间隔之后重新要一次模型 |
| 暂时性，预算用完   | 这一轮失败，带着成因                           |
| 永久性             | 这一轮失败，带着成因                           |

已经出的半截内容不进历史，不成为助手消息。

### 重试

重试的状态记在检查点里：这一串失败了几次，从什么时候起，下一次不早于什么时候。它和「这次调用已经有了结果」记在同一个检查点里，一次提交写下：不会出现结果收下了而次数没记，也不会出现次数记了而调用还算在途。

重试只重新要模型。上一步已经有结果的工具调用不重新交出。

预算由一个重试策略给：次数上限、总时长上限、间隔表、抖动。策略的数值从运维层来，成员里没有缺省数值。

### 等着的时候

一轮在等一件事时，叫醒它的是事件：结果、交接、取消一到，立刻醒。另有一个兜底的检查，防事件丢失，也防被调用方单独没了。兜底的间隔取自配置的序列 `reconciliationDelaysMs`：连续第 n 次被定时器叫醒、执行的修订号又没变，就等序列里的第 n 个数，用尽后一直用最后一个；修订号一变，或者上一次等待是事件叫醒的，回到第一个。这个计数只在内存里，重建后从头数；它只定下一次检查的早晚，不定任何结局。

等的是一次模型调用或工具调用的结果时，兜底到点问被调用方一句：你现在的活体还在推进它吗。回答「还拿着」就接着等，不读存储，不重新推进整轮。别的回答回到这个调用所在的那一步，照「接手」的表处置。到点的这一问不挡事件：问的时候结果到了，照样立刻醒。

### 接手

一轮被打断之后只有一种方式继续：会话给它开一次新的执行尝试，新的协调者从检查点接着走。进程重启、协调者的活体没了、会话提供者重装，走的是同一条路。

交出也可能被打断：Agent 写下了受理，会话还没读到回答。会话按原操作再交出一次，Agent 按操作身份认回原来的受理，答原回执与原挂接。运行实例的标识不算「同一份输入」的一部分，换了进程再交出不是冲突。认回不带来推进：原挂接属于另一个运行实例时，这个实例不在它下面接着走，执行只在新的挂接下继续。

检查点里每个发出了、结果还没进日志的模型调用与工具调用，接手之后第一次走到它时，先问被调用方同一句话。结果已经进日志的不问。本进程里刚被受理的调用不问。

| 回答                 | 主模型调用                                                                   | 工具调用                                                                               |
| -------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 还拿着；有结果了     | 等                                                                           | 等                                                                                     |
| 不在我手里了，带证据 | 记一次暂时性失败，成因是运行时丢失，照「重试」处置。另要的一次用新的调用身份 | 没有这个回答。开始过的工具调用由工具自己收场，结果「异常中断，效果未知」照常交回       |
| 没受理过             | 这次发出的意图作废，这一步重新发                                             | 这个动作回到工具从没见过它的状态，照发出动作的规则重新交出；被拒收就成为这个动作的拒绝 |
| 答不了               | 等，按兜底的间隔再问                                                         | 等，按兜底的间隔再问                                                                   |

被调用方权威地答了「这次意图不会有算数的结果」，这次意图就作废，日志里留下一条作废记录，写明是模型的还是工具的意图、成因与依据。作废有三种：

- 主模型调用被答「没受理过」：成因是没受理过，依据是那次回答。
- 主模型调用失联：成因是失联，依据是被调用方给的证据。它和重试的计数在同一次提交里写下。
- 工具确定拒收一个动作（不是暂不可用）：成因是没受理过，依据是拒收的证据。它和这个动作的拒绝在同一次提交里写下。接手之后重新交出时被拒收，与第一次发出就被拒收，都走这一条。

作废之后，那次调用就不在途了：一轮终结时不再等它。模型调用的结果迟到进了日志也不算数，那次请求也不算被采用过。一步的主模型调用是第几次，只数这一步里模型意图的作废记录。

人工介入的卡片与传播中的控制不走这一问：卡片按原操作身份认回，认不回才重新呈现；控制重新传播。

等待是可恢复的业务位置，保存在原位置，不建新的 execution，也不建新的挂接。人的等待没有默认期限；超时不是取消，也不证明什么没有执行。每次进入等待至多完整读一次日志：从上一次读取与此后自己的提交得到确切的游标，从游标起观察。

日志、Model、Tool 答「不可用」表示依赖暂时不在，不是节点故障：按依赖等待，到检查时刻以同一个操作再试。写提交答不可用时这次写没有生效，同一操作再写是安全的，不当作结果未知。写提交答确定失败时不等待，按节点故障收尾。

### 身份、租户与资格

- execution 身份由调用方在受理前分配，在租户内唯一；记录以租户加 execution 为键。每个模型、工具、扩展调用都有可恢复的身份与原用途，能区分同一步里的多个动作；一步不能代替调用身份。换挂接或换 runtime 不为同一个逻辑调用新建身份，也不重记费用。
- 操作身份由租户、execution、原持久前驱修订、转移种类与原帧里的稳定槽位确定地派生，不取随机值、时钟或当前进程。崩溃前后对同一帧的同一转移派生出同一身份。
- runtime 创建时绑定实例、租户、安全作用域与精确定义采用；改任一项都要新建实例。可序列化的配置里没有业务身份、权限、秘密或运行对象，配置不能覆盖绑定。
- 每次操作显式带租户。缺租户答输入无效；跨租户一律答拒绝，不区分对象不存在与无权访问，不返回内容或状态。只持有一个 execution 的标识文本不是资格。
- 每个公开操作在实际执行处核一次主体资格，位于租户核对之后、任何持久写入或外部发出之前。拒绝与不可用都不写任何状态。Agent 不缓存允许，所以撤权在下一次实际执行处生效；已合法受理的操作不回滚，已合法发出的调用沿原身份收场。
- 事件、失败诊断与遥测只写身份与状态，不嵌入消息正文、秘密、附件地址，不带私有权限块。私有权限块只经工具与扩展各自的注入能力读取，每次核当前资格，不进模型请求。

### 提交、认回与未知

- 同一 execution 同一时刻至多一个有效执行挂接。接管在同一次条件提交里让旧挂接被取代、新挂接生效，不要求旧 runtime 配合；旧 runtime 之后的推进写入得到「推进已被取代」，这是它得知被取代的唯一途径。被取代的挂接不能发新工作，但原生产者仍可保存真实的迟到结果。
- 一次条件提交原子地覆盖检查点、执行状态、效果意图、已分配序号的事件与操作结果；一次提交恰好分配一个后继修订，修订严格递增、不复用。期望修订过期时答「已变化」，本次什么都没写，调用方重读再求值。
- 效果意图先可靠保存，再发出：Model 用原受理身份，Tool 用完整原请求。写入结果未知时按原操作身份查询，不重发可能有效果的调用，不换新身份重试。
- 同一操作配同一语义输入，认回原结果，不再写事实，也不因修订已前进就改成新提交；配不同输入答冲突。认回不恢复旧的推进权。
- 查询只有四种结论：已提交、被拒绝、已排除、未知。查不到不等于已排除；被拒绝只来自控制的矛盾证据。消费者对四种结论逐一分支，不把任何一种落进默认分支。只有完整可信的永久排除，才允许后继操作。
- 写操作按固定次序判：请求形状；租户与当前资格；原操作的认回或冲突；挂接是否被取代；是否已终结；期望修订。前面的判定不披露后面的事实。
- 共同提交只发生在一个权威提交序列里：参加者与 Agent 的事实由同一个提供者在同一次提交里保存，成功才返回可继续的回执。两次独立写、事件队列、回调、进程内锁与通知都不能代替它。参加者只有参加、失败、冲突、不支持四种响应。
- 装配时拒绝不合格的组合：创建 runtime 之前核对配置与绑定的协调模式相等，并把配置要用的每一种共同提交与绑定声明的参加者比对；缺一种就答不支持，不创建、不保存任何状态。
- 快照只含开放项与头位置；已关闭的项离开快照，事实仍在日志里经分页读到。读方不把快照里缺席的项当作从未发生。不能一致地读出同一修订时答不可用，不用不完整的数组冒充完整快照。

### 受理、恢复与接管

- 每个 runtime 只有一个执行槽。先预约槽，再由日志幂等受理。受理结果未知时保持预约并查原操作，明确没提交才释放。并发的新受理答忙，不进隐藏队列；排队归调用方。runtime 在停用中或已销毁时，新的受理与恢复答不可用。
- 追加输入不需要活体：沿原 execution 的耐久视图受理，不要求推进资格、挂接或执行槽，也不自动恢复执行。活体只在提交后收到唤醒提示，提示丢了不撤销受理。
- 输入的完整内容由日志在受理时保存，带输入身份、来源依据与优先级。同一输入身份配不同内容答冲突。输入水位线是已可靠分配给该 execution 的输入边界，不能用内存队列的长度代替。外部来源的输入由外部协调者先在自己的可靠边界保存，再以同一内容交给 Agent。
- 恢复只认回原 execution 与原精确采用。接管与恢复由提供者按当前状态选，调用方不选。失联判断只答在跑、已失联（带证据）或未知；证据来自装配（单机的状态锁、多宿主的租约），不从超时、目录为空或任何缺席推断。判错不影响安全，因为原 runtime 的提交仍会被围栏挡下。
- 新挂接之后先对账再回原节点：对原提交、调用、结果、等待、卡片做只读查询；已提交就采用原结果，未定就等待，查询暂时不可用就保持未知。恢复不回到输入承接，不重做原效果。
- 每个业务节点在提交与外部发起之前重核当前资格与控制。非常态的优先级是：有效取消，已终结，挂接被取代，暂停或实例停用，资格未知。
- 交接（detach）同时保存原位置与责任并撤销该挂接，交接成功后 runtime 才回空闲。停用（quiesce）先让 runtime 进入停用中，再逐个交接在途 execution，全部交清才撤销本实例登记并答已排空；任一交接未知就答未解决，报出剩下的 execution，不宣称已排空。停用不取消 Model 与 Tool 的独立执行。
- 显式换代先准备并验证新实例，再撤旧授新。正在跑的不半路换：已开始的扩展调用保留原精确采用，新采用只影响还没开始的。依赖不在 runtime 底下热替换。

### 终结

- 终态只能由条件终结创建。它与受理输入、控制、挂接在同一个权威排序里，在最终提交点核资格、终态候选（`FinishCandidate`：完成候选、失败候选或取消候选）、期望修订、输入边界、责任闭包与终态前的判断，并在同一次提交里创建终态、最后的事件、终态后的观察责任与原操作结果。别的写都不能创建终态。
- 次序固定：先固定候选，走完终态之前位置的经过，再发行终结责任清单，再读最新修订，最后条件终结。有效取消优先于普通完成或失败。先受理的输入让旧的完成不成立。
- 条件终结的失败各有含义：前提变了或输入边界变了答已变化，重读再求值；有必要的责任没交清答被阻塞，并指出是哪一项；原操作未知或责任闭包不可确定答不可用，不当作被阻塞或已清；已终结之后的新请求答已终结。
- 终结责任清单不在检查点里：日志在接受每个会产生后续责任的事实时，同一次提交维护责任闭包，包括输入、调用、经过与卡片、材料、结果、控制、输出、观察、准入交接。检查点被替换不能删掉未清的责任。清单每项的处置只有已结清、具名保留、待恢复、未知四种。
- 以失败终结时，失败原因随终态写下，宿主据此记一条日志；失败不能只留在 Model 的账目里，让会话历史看不到原因。失败与被节点故障收尾时，已受理而没取入的输入保持原归属，记为保留，不投给后继 execution。
- 节点故障是已受理执行里的本地异常、不变量违规、不支持的路径、没有专门出口的确定拒绝。Agent 自己的拒绝、挂接被取代、忙、依赖不可用、原操作未知都不是节点故障。协调者固定第一个故障的节点、类别、步与来源，不保存错误正文、堆栈与请求；之后只收尾，不回到输入承接、请求准备或新的调用。来源分类在故障产生的边界确定，不解析诊断文本。
- 驱动在确定不能继续的节点停下而 execution 没有终结时，执行槽记为失败：观察仍显示占用，新受理答忙，同一操作的重试仍取回原句柄；运行时向工厂的接收者报告一次。只有拿到日志的终结才释放执行槽。
- 已终结之后只保管原事实：迟到的结果、观察、保管登记各自分配新修订，终态、检查点、最后事件与清单原版不变；迟到的控制只补记生产者确认、物理停止、责任释放三种真实事实，不追加事件。终态后观察只做纯观察，观察故障保留待办，不撤终态。
- 存在未确认的事件、未交清的结果责任、待观察的终态后观察或未释放的材料保管时，日志不删除对应记录。保留多久是提供者的政策，Agent 只定这个下限。

### 步数与守卫

- 步数上限是兜底：一步做完之后、下一次模型请求之前检查，不截断一步。到上限就以守卫类的失败收尾，依据写明上限与已走的步数。被拒收之后的新一步同样计数，所以连续拒收也有上界。
- 循环守卫的唯一计算者是调模型之后位置上的循环判断，它是受信的系统扩展，不由作者声明；阈值与检测算法是策略配置，Agent 不写死。它只读本执行已可靠保存的原始工作事实，不读压缩后的视图。守卫事实随检查点持久，压缩、崩溃、换挂接、runtime 换代与新的一步都不清零它。

### 请求准备与压缩

- 次序是：先取当前条件，再选模型，再读上下文，最后准备请求。读取需要实际收件模型，所以先选；选的输入含当前条件，所以先取条件。
- 模型选择按用途做；选择失败不改用其他路由。选择变化只影响下一次请求：记录最终请求之前每次准备都重选一次，收件模型不同就重读重备；记录之后不改写，也不中断在途调用。
- Runtime Context 在新 execution 开始、每次建立挂接、每次主请求准备、模型选择变化之后与压缩提交之后拉取。读到的内容在最终请求记录时才算采用，之前被取代就丢弃。全量还是增量由 Context 定，Agent 原样记录；读不到不变成空。
- 请求准备只计算，不改历史，不发压缩的模型调用。最终请求记录之前的准备只在内存里；崩溃后从检查点里固定的输入批重新准备。检查点不存工具请求、原调用部件与消息草稿的正文，只存引用与摘要；重算出的内容与摘要不符时答无效，不拿重算的结果继续准入。
- 压缩是有上界的多步计划：同一次准备至多进入一个计划；进入计划之后再要压缩就以「压缩后仍装不下」失败。压缩步骤的请求不经请求准备，也不触发压缩，不递归。每步是一次独立的模型调用，有自己的身份、消费位置与费用。
- 压缩的转换先固定来源，经消息准入，再与 Context 的转换在同一次提交里保存。之后的位置只面对已提交的事实，所以没有任何扩展位置能改写压缩的结果。
- 装不下的原因只有两类：固定内容超限，压缩后仍超限；限额未知不是失败。Agent 沿真实原因失败，不换模型、不删历史、不分叉、不无限压缩。

### 模型调用

- 首次受理之前，先保存 Model 调用的原引用与固定输入。受理结果未知时按原引用查询，原身份保持未知直到 Model 回答；查询不可用、超时、路由缺席都不证明没受理。只有 Model 权威地答没受理，才作废原意图，以新的尝试序号派生新身份重新准备。
- Model 对受理答不可用时按依赖等待，到时以原身份再受理。确定拒绝以模型拒绝失败收尾。
- Model 的重试由 Model 的重试策略形成唯一的决定；Agent 只把首内容之前的失败交给它，在原位置等同一个调用，不提前消费结果，不替 Model 确认，不自己发第二个调用。
- 回复先准入后解析。回复准入只接纳完整的结果；结构非法的回复（任一工具调用部件缺名、名为空或参数不是合法的值树）整条拒收，不剔除非法部件接纳其余，其中合法的工具调用也不成为动作。被拒收的回复，原结果与费用照样保留，退避后以新的一步发新的调用，不冒充内部重试。
- 拒收让连续数与累计数各加一，接纳让连续数归零、累计数保留。同一调用与结果版本的准入重试认回原结论，不增加计数。

### 动作与工具

- 同一动作的前置扩展链按声明顺序串行，不同动作的链并行，互不读对方的结论。官方动作准入是每条链末尾的受信系统扩展，不可替换、不可禁用、不可收窄；作者的扩展只能增加限制。
- 判断屏障在三件事都成立时打开：每条链都有最终结论；每张卡片都已处理；至少一个动作被允许。打开之前不发起任何已获准的动作；一个动作已被允许不能越过其他动作。全部拒绝时不等从未发起的工具，为每个动作保存拒绝原因与拒绝消息。
- 准入不可用让本批全部动作被拒绝，不放行任何动作，也不出卡；已开出但没呈现的卡片不再呈现，已呈现而没答复的作废。官方准入的必需输入读不到，等同准入不可用。
- 准入检查、人看到的卡片与实际发起用同一份生效参数。参数只在两处改：同链在官方准入之前的扩展改写，或人选了卡片草稿绑定的那个选项。动作、生效参数、工具定义或授权依据一变，旧的批准失效，官方准入以新值重判；无关的配置变化不重问。
- 判断允许的动作时先保存完整原请求，再提交判断，之后才保存工具意图并发起。工具调用的登记分两态：只有意图，没有调用引用；已关联调用身份，这仍不证明已受理。调用身份由 Tool 分配或认回，Agent 不预分配。发起结果未知时，以完整原请求重入，或保存引用后查询。
- Agent 按原动作顺序发起获准的动作，不等名额，也不计数在途调用。并发上限是配置项，作为范围预算随请求交给 Tool；由 Tool 限制同时执行的数目。
- 每个动作一个结果槽位。真实结果，或 Tool 确认转后台并给出耐久占位，按原动作身份保管进槽位，保管之后才解除生产责任。缺槽位（没发起或历史调用未定）不能当作拒绝。
- 转后台保持原 Tool 执行身份、原调用登记与原消费关系；Agent 不接管 Tool 的协程，不启动第二次工具。后台占位与最终结果是同一消费下的两个结果版本，分开保管、分开解除。最终结果在合法的后继位置消费，不改写占位，不重开已结束的批次。
- 工具结果被接收方答已保存之后，Agent 不再以同一消费位置发起这次调用。Agent 保存的原消费位置与原请求的消费者逐项相等，每个逻辑动作一个稳定位置，恢复或换挂接不重建。
- 普通的工具失败是可消费的结果，Agent 可以改参数或换方法，不把它当节点故障。失败之后要再做什么，以新的业务意图、新身份与当前准入推进，并关联原失败与已发生的效果。

### 结果接收

- 接收方一次提交接收条目、完整的冻结材料与已保存的依据，由同一个提供者在一个发布点共同建立。不允许先存材料再记条目；任何公开的已提交状态都不能只含其中一半。
- 结果按原消费位置交到受理时冻结的消费者；接收方按冻结的消费者与原调用引用查原绑定，不重新选去处，不从当前挂接或消费者文本猜实例。
- 每次推送（含已保存交付的重投）先核接收资格，再读原调用或写入；核验结果只对这一次有效。同键同内容认回原条目与原已保存，同键不同内容答冲突；已有的排除不会被复活。
- 已保存之后，Model 沿原证据自己取得确认，Agent 不执行 Model 的确认；Tool 按自己的协议解除交付。原操作引用丢了而没有证明释放时保持未知。生产者的交付责任只经两条路解除：先保管后处理，或先处理后保存完成依据。任一时刻恰有一个耐久保管者。
- 保管与推进分开检查：合法的保管方核原结果版本与交付责任，不要求旧挂接有效，不能改检查点、受理输入或发新效果；终结之后仍可保管。已被拒收的回复或工具结果仍是真实执行记录，数据、费用与效果不丢。
- 接收方在条目提交之后把 Model 的账目经 Agent 自己的出站端口交给 Context 一侧；未知与不可用以同一交接重试，拒绝、冲突、无效不重试。

### 消息准入

- 消息准入是 Agent 自己的规则，不经过扩展。准入的结论（提供者固定）、真实历史的应用（日志固定）、公开受理的成功（原操作结果）是三个事实，各有唯一拥有者；已固定的结论不被改写成另一种成功。
- 准入提供者对 Agent 自己产生的消息只因校验失败或保存失败拒收，不作业务否决。首次调用在耐久记录里一次保存输入键、完整请求、来源、原主体、资格依据、精确实现采用与全部原材料；保存确认之前不做转换或其他效果。
- 一次准入先记准备，把待办纳入终结责任闭包，再做任何转换；一次准入至多一次历史应用。同一来源位置在旧准入未定时不能另开新的准入。查看原准入结果只读，结论只有已记录、已排除、未知三种；未知之后仍沿同一次准入，不另开一次绕过。
- 排除不授权重发：仍可推进时，下一步确认排除后按新的持久前提重新求值；不可推进或已终结时只保存原排除与责任处置。
- 应用时同时核主体与推进资格、完整的期望、原准入的真实结论、来源位置与历史拥有者的前提。参加者或历史写入失败时，Agent、来源与历史一起回滚。已提交的历史处置不被保管记录改回未处理。

### 扩展与卡片

- 扩展有九处位置、三档干预力：只观察、改写、否决。实际能力是声明上限、位置输出表与来源收窄三者的交集；来源为工作区的扩展上限是只观察。作者的返回按位置输出表判，不合法的按报错处理。停止是一条需另行核权的控制请求，不是已取消的回执。改写只能动可改写的字段。
- 扩展调用先经日志提交为已请求，提交确认之后才调用。已有最终结论的扩展调用永不再调，换挂接、换 runtime、换代都不变。结果未知时以重放模式按原精确采用重新调用，不以全新方式重开。
- 注入给扩展的能力，每次使用先记为已请求再发出，结果先保存再交回；重放时按同一序号比对种类与输入依据，相同就认回原操作，不发第二次。
- 扩展不能直接发起工具调用。工具效果只经主循环的判断屏障与官方准入发起。
- 一条链上：否决结束链，问人暂停链，停止与重试不结束链。有效取消优先于任何输出。多个停止各自保留原来源，按声明顺序处置，不互相覆盖。
- 卡片每轮有稳定的轮次身份；卡片需求与原扩展调用先保存再呈现，同一请求去重。呈现结果未知时按原输入完整查询，不当作没呈现；一轮里部分已创建时保持未知，不重问已创建的卡。人的拒答与附言都是答复，不授予动作，不默认批准，没有超时。附言的含义按卡片来源交原扩展或授权领域解释，Agent 不自己读成批准。
- 定义不带版本。每个新 execution 采用同一身份当时的合法胜出版本；恢复与接管沿原采用，不升级。定义携带的提示词是系统提示词的唯一源，改一个字，采用摘要就变。权限上界只收紧，不授权；定义不可用不能按省略处理。

### 控制与取消

- 四种控制互不隐含。中断作用于一个具名调用，不改变执行状态，之后按原调用的真实收场继续；取消作用于一个 execution，不停已转后台的工具，不影响别的 execution；暂停保存接续并撤销挂接，不经终结，不请求生产者停下；停用作用于一个 runtime 实例，不取消 Model 与 Tool 的独立执行。
- 插队不是第五种控制。它是一条紧急输入沿原 execution 受理之后，对前台调用用中断类的控制：前台模型调用可中断就请求中断，已到达的内容保存，没发出的工具建议不执行；前台工具调用可转后台就请求转后台，否则请求允许的中断。
- 一次控制的进展是六个独立的事实：受理、意图成立、推进资格撤销、生产者确认、物理停止、责任释放。各自只在真的成立时记录；缺席表示没成立，未知单独标记。生产者在中断到达前已真实收场时，以真实收场为准。
- 控制的受理事实、每个新成立的阶段事实与对应事件，在同一个原子边界里与可查询的原操作结果一起保存；终态不能越过还没成立的对应事件。新挂接按原控制记录认回已成立的阶段，不重发控制命令。
- 有效取消之后，旧的推进不再准许 Model 或 Tool 受理、消息接纳、卡片呈现或作者的后续效果，每个实际拥有者在自己的发起处检查围栏。围栏之前已合法开始的外部动作仍可能完成，效果与费用沿原身份保留；不报告已撤回外部行动。
- 取消候选不经作者扩展链，由治理安装的受信取消判断核对：它只读各拥有者已核验的事实，答允许、阻塞或未知，并耐久记录；它不发模型调用、不注入、不出卡、不问人，作者的否决不是阻塞理由。判断记录不授予永久许可：相关事实一变就生成新记录并指向前一条，旧记录不改。
- 被取消的 execution 只能以取消的授权条件终结，不能以完成终结，也不恢复旧挂接的推进权。对已暂停的 execution 取消时，收束由下一次合法挂接执行。外部协调者一方的终态先成立时，Agent 认回原取消，取消路线一步不省。
- 取消后没处理的输入保留原归属与处置依据，不静默转入后继 execution；卡片与在途调用保留真实的收束责任，不伪造人的答复。

### 事件与读取

- 事件由日志在条件提交里分配，身份是 execution 加序号；序号从 1 起连续，没有空洞；同一身份的内容不变。读取的缺口必须显式返回。
- 订阅是按需拉取的页序列：读方慢只增加落后量，不阻塞推进，不丢事件。活体订阅的内存缓冲有字节上界，超出就以不可用结束这个订阅，读方用原游标重连。
- 确认单调：只确认已发出事件的连续前缀，重复的认回，较小的不回退。确认只表示读方已保存事实与游标，不证明终态、业务成功或生产者的确认，也不结清保管责任。
- Agent 的事件流只发自身事件，不透传生产者的内容。生产者的过程流由观察者按稳定调用引用直接向生产者取。
- 每次读取、续页、旧操作认回与缓存采用都核当前读取资格；读资格与推进资格分别核。撤权之后第二页按当前资格拒绝，已披露的事实不撤回。

### 宿主

- 宿主按实例槽（租户、安全作用域、精确定义采用）给出实例；一个槽在一个宿主进程里至多一个已发布、没进入回收的实例，并发请求共用一次建立。预约只预约实例身份，不授予推进资格。旧登记身份的撤除不撤除后继的登记。
- 空闲回收只认空闲：计时到期时先读最近一次报告，不是空闲就放弃。停用答未解决时实例保持发布，下一次到期再试。只有已排空才卸载实例的贡献作用域。
- 计划卸载先完成业务交接，再释放资源。依赖突然消失时宿主停止计时、不建新实例，挂接与在途责任留在日志里，不声称外部效果已撤回。宿主插件的静态依赖非计划换代，等于本宿主全部实例的在途 execution 同时失联，由恢复者接手。
- Tool 的启动围栏由宿主在使用点以局部依赖取得 Tool 的窄服务，只能使自己负责、还没受理的启动失效；Agent 不再声明这个键，也不取得更宽的启动权威。

## 原则与约束

- 失败如实是失败。一次失败不能因为出过一些内容，或者后面没有别的事可做，就变成完成。读不到不变成没有，查不到不等于排除，未知不填零，依据缺失答不可用，缺页不用空数组代替。
- 结果不知道就是不知道。不重新发一次去试，不写成成功或失败。
- 人的控制带来的停止不是失败，不进重试。
- 重试、间隔、时限这类策略不写死在代码里。全仓共用一个重试策略对象与一个判定函数。成员里不写数值默认，默认值是装配给的配置初值。
- 通知只唤醒，不是事实。事件队列、回调、进程内锁、Cordis 的撤除与取消调用的成功，都不能代替共同提交、围栏与持久排序；顺序保护必须是跨进程的权威比较。
- 判断函数是纯函数：不读时钟，不产生随机值，不做 I/O，不执行输入里的函数或访问器；成功值逐层冻结，不与输入共享对象；任何输入都不让它抛出异常，失败带具名原因返回。
- 采用组合与状态联合，不建 runtime 的业务父类；纯求值留在内部，不对外提供让每个消费者自己反复求下一步、发效果、存位置的调度协议。
- 测试替身只供测试，声明自己不耐久，不装进生产。内存替身与耐久实现对同一份可观察事实给出相同结果，同一套一致性用例适用于两者。
- Agent 只写自己需要的外部保证，不替拥有者写内部实现；拥有者兑现不了时，对应的组合就不具备这项保证，Agent 拒绝装配做不到共同提交的组合。
