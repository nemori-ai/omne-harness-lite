# Identity

## 总体架构

Identity 包组回答两个问题。身份：谁在行事，他现在是不是某个组织的成员、持有哪些资格，这一次请求用的是哪一份登录、代哪个租户行事。授权：一个具体动作现在能不能做，依据是什么，许可用过没有。

| 成员                | 回答的问题                                                                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `identity`          | 身份契约：两种主体的签发与核验、具名资格与角色映射、当前资格读口、注册与登录三项操作、治理端口、成员资格预留与治理恢复。附带参考替身与契约套件 |
| `identity-sql`      | 身份契约的持久提供者：账号、组织、租户、成员、登录、邀请与预留落在 SQL 存储的系统作用域里                                                      |
| `scrypt`            | 有界的口令派生与校验：身份只保存它给出的不透明材料                                                                                             |
| `authorization`     | 动作准入：租户动作的准入裁定、许可与消费事实、系统动作授权、询问处理                                                                           |
| `identity-protocol` | 公开协议 `identity/v1` 的协议契约：有哪些操作，各要什么身份、是读是写、能答哪些结果。纯数据                                                    |
| `identity-access`   | 接入层的身份端口实现与 `identity/v1` 的接入插件：把协议操作交给身份的公开入口，把结果映射回协议                                                |

`identity` 是纯契约，不依赖 Cordis 与存储（Cordis 服务定义在独立的 `./cordis` 入口）；`identity-sql` 用 `scrypt` 与存储契约实现它；`authorization` 只消费 `identity` 的核验器与资格读口，不认识提供者。工作时，入口经 `identity-access` 识别登录证明，为这一次请求签发代租户行事的主体；操作拥有者带着这个主体、操作、目标与生效参数向 `authorization` 要准入裁定，裁定每次重读主体核验、当前成员事实与许可状态；治理操作经治理端口直接在 `identity-sql` 的一次提交里核对并写入。成员变更与外域写入之间的竞争由成员资格预留协调。

## 领域边界

身份拥有：账号、组织、租户、成员资格与角色、凭据、登录及其当前租户选择、邀请与创建回执、成员资格预留与成员变更意图；主体的签发与核验；治理模型给出的资格解释。授权拥有：准入裁定的规则与证据格式、许可与消费事实、系统动作的用途矩阵、询问处理的判定。

本组不拥有：合法身份与时间点的纯值形状（`packages/common` 的 legal-identity、utc-instant）；资源、动作与生效参数的业务含义（各操作拥有者）；权限配值与求值（资产与规则）；人工交互与答复（HITL）；原工作的推进资格（原工作拥有者）；SQL 提交、查询与持久性（存储）；会话、Run 与任何业务生命周期；实际执行是否停止、外部效果能否撤回。

## 心智模型

身份是一本户籍簿，授权是每扇门上的门卫。户籍簿记着谁是谁、属于哪个组织、担什么角色、手里有哪些有效登录；它只回答「现在是什么事实」。门卫每次有人要过门都重新查一遍户籍簿和许可，再说放不放；它不记住上次放过谁。所以撤权不需要通知谁：下一次查就拒绝。最容易想错的地方：主体对象不随撤权失效，失效的是它背后的成员事实；一次 `allowed` 不是许可，换一个动作或晚一点再做都要重新问；门卫说「放」不等于动作已经做成，也不等于外部效果能撤回。

租户不是账号，也不是组织，是「这个账号在这个组织里」这件事的稳定名字。角色、登录、当前选择都挂在别处，所以退出再加入还是同一个租户，改角色不换租户。登录是一次成功认证签发的独立凭据，每份各有冻结的期限和自己的当前选择；同一账号的两份登录互不影响。

每个答复都要分清四种情况：确定的是、确定的否、依据现在拿不到、结果不知道。拿不到不是否，否也不能伪装成拿不到；提交之后回执丢了就是不知道，按原操作认回，不重做，也不写成失败。对外披露的口径比内部诊断窄：不存在、属于别人与无权看见说成同一句话，账号不存在、未激活与凭据错误也说成同一句话。

## 应然设计

### 主体、组织与租户

- 账号、组织与租户的标识各自稳定。租户由组织与账号共同确定；成员退出后重新加入沿用原租户。角色、当前选择与运行实例的变化不重命名已有归属。
- 账号是部署内的使用身份，不是实名证明。登录标识在注册时固定，部署内唯一，之后不可改；凭据更新或认证接入不重命名它。显示名称不参与身份相等，同名组织可以共存。
- 账号、组织、租户、成员资格与登录分别记录。成员资格无效不等于租户或历史事实不存在。资源所有者、作者与执行者不能被界面选择或连接覆盖。
- 本组的标识文本由创建对象的一方按 legal-identity 的词法产生，再经它的解析函数得到值。解析成功不是存在，存在不是成员有效，成员有效不是动作获准。
- 时间点不可用时答无法判定，不改用墙钟补一个时间。
- 停用、恢复与终结主体的资格和状态转换由产品政策定；没有定义的操作不按创建、读取、更新、删除的形式补出默认行为。

### 注册与激活

- 一次注册激活成功时，账号、唯一个人组织、个人租户与本人的超级管理员成员资格在同一次提交里共同成立，账号可以登录。任一项确定不能成立，答 `not-loginable`，不留下可登录的半个开通。
- `not-loginable` 不带详情：调用方不能从它知道标识是否被占用，也不能知道哪一条开通条件失败。提供者不能确定自己的提交是否成立时拒绝 Promise，不答 `not-loginable`。
- 登录标识与凭据须是非空文本；提供者可以采用更严格的规则（例如字节上界），须说明，并对不合规输入答 `not-loginable`，不改写输入。唯一性按原文比较，不去空白、不折叠大小写、不做 Unicode 规范化。
- 同一标识的并发注册至多一个成功。标识已属于已激活账号时，无论凭据同不同都答 `not-loginable`，原账号、原凭据与原登录不变。被拒绝的注册不占用标识。
- 成功不表示已经登录，结果不含登录凭证。结果未知时，调用方用同一标识与凭据签发一次登录来认回；重复注册失败不证明此前没有激活。
- 有单独激活步骤的方案还要守未激活留存：留存期内同标识同凭据接续原注册，不同凭据不能认领它；已判定到期的记录不复活；到期释放标识，不删除已激活账号。

### 登录：签发、识别与期限

- 签发按固定次序判断，前一步给出结果时不进入后一步：先读时钟与期限配置（不可得、倒退或任一时长不大于零答 `basis-unavailable`）；再查输入形状；再确认账号记录可读、登录记录可写；然后比较凭据；最后签发。依据不可得在比较凭据之前判定，所以 `basis-unavailable` 不说明凭据对不对，它的出现条件也不取决于账号是否存在。
- 账号不存在、未激活与凭据错误对外是同一个 `uniform-auth-failure`。账号不存在时也对一份假材料做一次同样的口令校验，使两种账号经过同一个派生名额与队列。
- 比较凭据之后登录记录写入失败或不能确定是否写入时，拒绝 Promise，不答 `basis-unavailable`：此时答复会泄露凭据正确。签发结果未知时再调用一次是新的签发，可能多产生一份登录。
- 每次成功签发一份新的独立登录，带新的登录标识与只出现在这一次答复里的不透明登录凭证。登录标识的文本不能当凭证用。初始当前选择是个人租户。
- 两个时长在签发时按当时读到的配置冻结并随登录保存：最长截止时刻是签发时刻加最长有效时长，空闲截止时刻是签发时刻加空闲时长。配置变化只作用于之后签发的登录；立即收回访问用撤销，不靠改期限。
- 识别的次序：凭证不是非空文本答 `invalid`；登录记录不作答答 `basis-unavailable`；没有这份凭证答 `invalid`；已撤销答 `invalid`，不读时钟；时钟不可得或读数早于下界答 `basis-unavailable`；读数不早于任一截止时刻答 `invalid`（等于即到达）；否则 `recognized`，带账号、登录与当前选择。识别不写任何东西，不刷新空闲计时。
- 采用的时钟读数不倒退。一个提供者实例记住采用过的最晚读数；对一份具体登录，下界还取它的签发时刻。失效的登录不复活，停机时间计入期限。
- 只有调用方报告的这一份登录的成功业务访问刷新它的空闲计时：新的空闲截止时刻是本次读数加签发时冻结的空闲时长，新值早于原值时保留原值，最长截止时刻不变。失败请求、健康检查、治理操作、仅完成认证与同账号其他登录的访问都不刷新。报告可以按短于空闲时长的粒度合并，登录因此最多提前一个粒度失效。报告失败不改变调用方已经给出的结果。
- `recognized` 只说明这份登录现在有效及其当前选择，不说明账号仍是成员，也不说明动作获准。

### 退出、撤销与更换凭据

- 退出与逐份撤销由本人当前有效登录发起，目标须属于同一账号。目标不存在与属于其他账号得到相同的 `not-visible`。目标已撤销或已到期答 `no-change`，不重复写。撤销自己的发起登录就是退出。
- 撤销持久保留，重启后不复活。撤销之后识别答 `invalid`。退出不注销账号、不解除成员、不终结组织或租户。
- 本人可以查询本账号全部当前有效登录及签发时刻，名单不含可冒用的材料；不承诺历史登录列表。
- 更换凭据须本人有效登录并通过当前凭据核验；组织管理员、主机运维或只持有登录都不能代替当前凭据。成功时新凭据成立与本账号全部旧登录失效（含发起的那一份）在一次提交里共同成立，不隐式签发新登录。凭据不以可读形式保存或返回。

### 组织、成员与邀请

- 治理模型定义成员准入、角色与操作资格。角色名只在它的模型内有意义；资格由模型映射成具名资格，消费方按资格名判断，不按角色名判断。另一个模型的同名角色答 `model-mismatch`，映射没列出的角色答 `unknown-role`，不猜。无效或不可用的模型不静默退回默认方案取得允许。
- 默认方案：每个账号开通唯一个人组织与个人租户，个人组织只有本人一个成员兼超级管理员，不接受邀请、退出与隶属。团队组织由已激活账号创建，名称不能空白；组织、创建者租户与首位超级管理员在一次提交里共同成立。每个有效成员恰有超级管理员或普通成员中的一个角色。
- 成员变更始终保留至少一位有效超级管理员；检查与提交共同守住这一条，两位管理员并发移除或降级对方至多一方成功。目标角色与当前角色相同答成功且事实不变；带上的预期角色与提交时不同答 `conflict`。
- 创建组织按「账号 + 创建调用身份」保存回执，绑定名称与模型；同一调用身份与相同输入交回已保存的结果，输入不同答 `conflict`。认回只读回执；没有回执或读不出答 `unknown`，`unknown` 不说明创建是否发生。
- 成员邀请指向明确账号，只由当前有效超级管理员从团队组织发出，邀请不带角色。资格核对在查找被邀请标识之前完成。截止时刻在发出时固定为本次读数加请求的时长（省略时用默认时长；不大于零或超过最长时长答 `denied`），之后的配置变化不改变它。
- 每份邀约只形成接受、拒绝、撤回、过期之一的一个终结，形成后不被覆盖。接受与拒绝只由被邀请账号本人做，撤回只由发出组织的当前有效超级管理员做。处置的次序：看不见答 `not-visible`；不是该做的一方答 `denied`；已终结或已过期答 `no-change` 并带那个终结；第一次判定过期时写下过期终结，之后时钟倒退或重启也不使它重新开放。邀请所属组织不存在时邀请过期。
- 接受时：首次加入与重新加入都得到普通成员并沿用原租户，不恢复旧角色；已是有效成员时答 `no-change`，邀请形成接受终结，角色与租户不变。无变更不掩盖其他失败条件。
- 退出组织由本人做，不能让组织没有有效超级管理员。成员变化只改变资格事实，不改写已有对象的归属，不删除会话等资源，不证明实际工作已经停止。
- 读面：有效成员读本组织有效成员与角色；超级管理员另读已解除成员、本组织发出的邀请；被邀请账号读本人收到的邀请。管理角色不开放成员的私有内容。

### 组织隶属

- 隶属须上下级双方分别确认，同一人管理双方也分别确认；每个组织至多一个上级，不自隶属，不成环。提交建立时重新核验双方资格与关系条件，并发接受不能形成环或两个上级。
- 已生效的隶属只由上级组织有当前处置资格的人解除，下级不能解除；不同模型可以定义上级的处置资格，不能把解除权转给下级。
- 隶属请求在接收方处理之前发起组织已不存在时失效；目标组织不存在时过期。失效与过期都是唯一终结。
- 建立隶属不创建成员或租户，不授予权限、资产或设置的继承。

### 当前租户与入口核验

- 每份交互登录独立维护当前选择。切换只改这一份登录，目标须是本账号有效成员资格的租户，否则 `denied` 且原选择不变；目标等于当前选择答 `no-change`；只有成功的答复带租户。从未切换时当前选择是个人租户。成员被移除后选择保持不变，之后的准入读到非成员。
- 经登录进入治理服务时，请求显式的行事租户须等于该登录当前的选择，不等即 `denied`，答复不披露实际选择。目标组织与行事租户是两个字段，目标不同不算冲突。
- 入口核验认可的身份材料、可信来源与业务范围。登录匹配与成员有效都不代替动作授权。裸 ID、地址、连接或 Cordis Context 不是资格。

### 治理端口的公共规则

- 每项治理输入带发起登录。提供者在提交时再核对这份登录：记录不可读答 `basis-unavailable`；登录不存在、已撤销、已到期答 `denied`；本次读数早于这份登录的签发时刻答 `basis-unavailable`，不判定它。行事操作还核对行事租户等于当前选择。成功业务访问报告不走这一核对，按上文自己的规则。
- 每项写操作的登录核对、资格核对、预期状态核对与写入在同一次提交里完成。两次并发调用不能都通过同一项核对再各自写入。拒绝不写任何东西；接受或过期的判定要在答 `no-change` 的同时写下终结。
- 可见性：组织对持有或曾经持有其成员资格的账号可见，从未是成员的得到 `not-visible`，已解除的成员得到 `denied`；被处置的成员须是有效成员；邀请对被邀请账号与发出组织的当前有效超级管理员可见；登录只对同一账号可见。`not-visible` 不区分不存在、属于别人与无权看见。
- 按标识查找的对象找不到答 `not-visible`，其他畸形输入答 `denied`，都不抛出、没有业务效果。
- 名单要么完整，要么答 `basis-unavailable` 且不带数组；任一项判不出、读失败或超过名单上限时都如此，不返回部分名单、截断名单或空名单。合法使用会超过的上限须有分页这样的去处。
- 提交结果不知道时，提供者按同一身份查询认回，有上界；仍不知道时拒绝 Promise，错误带原逻辑操作引用。调用方不自动重做。
- `diagnostic` 是内部诊断，不含凭据、登录凭证、登录标识或登录的标识文本；入口对外披露时不转发它。
- 持有治理端口的组件可以用任何已识别的登录行事，所以装配只把它交给受信持有者，与签发者同等对待。

### 主体的签发与核验

- 两种主体。系统主体只带部件名，不代表任何租户，用于扫描、卸载、目录枚举、中继、协调者读取。代租户主体带签发它的系统主体、显式租户与原工作关联；原主体是租户里的账号，消费方再核时读该账号在该组织的当前成员事实，不读系统主体的事实。没有不带租户的代租户主体。
- 签发归身份：只有本权威签发的主体能通过核验。装配把核验器交给消费方，把签发者只交给声明过的受信持有者。部件名只用于诊断，不是凭据。
- 持有者签发代租户主体之前，须向原工作拥有者核对原主体、目标租户与原工作的关系；核对失败、不可得或能力没有安装时不签发。合法的租户、非空的工作文本或签发登记都不证明这层关系。登录作为原工作时，关系核对就是同一次请求里登录识别成功且目标租户的账号等于识别出的账号；租户的人工介入入口主体用固定的工作文本，核对相同。两者都不证明当前成员资格或动作获准。
- 签发失败返回失败值，不抛出，畸形输入同样如此。核验是判定，不是解码：`verified` 交回的就是传入的那个对象；同形状的手写副本答 `rejected`；不能回答时答 `unavailable`，不答 `verified`。核验只证明来源。
- 进程内权威只在同一进程、同一份已加载模块内成立；主体经过序列化、结构化克隆或另一个进程后不再带有签发，跨进程的来源验证要另一个提供者。
- 接入成员为一次请求签发代租户主体时，只在目标租户的账号等于识别出的账号时签发，原工作是这份登录。请求队列排空时，它按队列保存的租户文本与登录文本重新签发同一形状的主体：登录证明在入队之前已经识别过，重新签发不再识别证明，也不再核账号；准入在会话受理时核对，治理端口在提交时再核发起登录。

### 资格与当前资格读口

- 具名资格是消费方判断的单位。组织成本账目读取资格允许读本组织全部租户的成本账目（含已退出成员的租户，不含下级组织），不开放请求正文、回复或秘密。组织设置管理资格只针对当前组织的设置目标，Settings 仍核主体所属组织、真实管理关系、合法定义与允许操作；两项资格不互借。默认团队方案里超级管理员持有这两项，普通成员都不持有。
- 当前资格读口答 `member`（带角色、经映射解析的资格与证据）、`not-member` 或 `unavailable`。未知租户、未知组织或账号、非成员、已解除、输入不能编码都答 `not-member`，证据只由输入算出，不读任何行；读口在这几种情况下的答复完全相同。读不到、读出畸形或映射答不认识的角色时答 `unavailable`，不答 `member` 也不答 `not-member`。
- 每次读取回答当下的事实；一次读数不是许可，不缓存为允许。成员记录的修订不是整张资格映射的版本。资格映射由发行代码采用，不在运行中动态替换。
- 这个异步读口不与资源提交处于同一围栏。需要「最终权威重读与提交之间没有 `await`」的消费方（如 Model 的最终发送），须由提供者协调资格写者与发送入口，在同一围栏内完成；旧读数、旧 `allowed` 或内存缓存都不能替代。

### 成员资格预留与治理恢复

- 预留让外域的一次写入在执行期间挡住会改变它所依赖的成员事实的成员变更。预留核验主体确由注入权威签发，绑定里的租户与主体引用与它一致，再在同一身份事务里核验成员事实与所需资格；空资格集合表示只要成员关系。绑定包含操作拥有者、原操作标识、主体、目的地、租户、目标与输入摘要，不含业务值或目的地的命令。同一原操作换绑定或资格集合答 `operation-conflict`。
- `held` 没有到期时刻，不存在按等待时间强制释放的路径。成员写者与预留互斥：成员变更意图先阻止该成员的新预留，再排空已有预留；变更真正提交后才报告成功。排空之后重新核对原登录、当前选择、原治理资格、预期角色与最后管理员规则；最终拒绝也结束自己的意图。同一成员的意图按持久顺序推进，只有队首可以提交。注册与创建组织只创建新成员，也经过同一道门。
- 结算不接收调用方断言的终态：身份只问受信装配注入的目的地，目的地在自己的事务里建立不可逆的 aborted，或答已有的 committed。目的地不可用、未找到、取消、超时与实例停止都不代替这项证明。核对完整预留绑定之后才结束预留。
- 结算以完整原请求进行，可以结束已建立的预留，也可以封闭还没到达源端的原请求。源端初读缺行不是释放证据：先取得目的地对该完整请求的终态，再在最终源端事务重读；仍缺行时只有 aborted 可以写下已结算围栏，committed 保留不可得并由调用方用原请求重试，不补造曾经获得的资格。围栏与预留共用原操作的唯一约束，之后迟到的预留返回原终态，不新建 `held`；已发出的旧 `held` 回包不得覆盖已结算状态。
- 围栏在系统仍允许原请求重试或迟到期间保存，不按时间删除；容量政策不缩短这一承诺。调用者持久保存还没发出的请求并驱动结算，身份不承担发现外域未送达的请求。
- 成员变更结果未知时，错误暴露原逻辑操作引用，恢复只沿这个引用进行，不新建同义操作。恢复读取要原发起账号的当前有效登录，并重新核当前选择与治理资格；最终变更始终核持久保存的原发起登录，新登录不能续接已过期或撤销的原授权。受信装配的批量恢复同样以原登录核验，不换成系统授权。每次处理有界的分页与次数，失败保留持久记录，后续调用或重启继续。
- 每次 SQL 尝试有自己固定的封套：已知未提交或回滚之后，新的准备事务才能退役旧尝试；旧尝试先完成则返回原终态，退役先完成则晚到的旧封套不能写成员。新尝试用新的身份与新的时刻，不把新时刻填进旧身份。
- 已完成结果的保存不授予新的披露资格：本人退出成功之后，新登录不能再选择那个租户，恢复读口可以答 `not-visible`，持久终态不变。

### 动作准入

- 准入输入显式带可信主体与租户、操作、目标、生效参数摘要、要求的具名资格与出示的许可（可以没有）。操作与目标由资源拥有者命名并拥有含义，本组只记录与比较。生效参数对本组不透明：资源拥有者或它的适配器对实际执行采用的固定表示算摘要，签发许可与裁定用同一表示；没有参数的操作出示固定的无参数摘要。
- 裁定按固定次序，第一个不满足的步骤决定结果：主体核验（核验得到的须是输入里的同一个对象）；作用域（系统主体不能出现在带租户的访问里，代租户主体的租户须等于访问的租户）；当前成员事实；要求的资格；出示的许可（租户、操作、目标、参数摘要逐项相符，未消费）。读不到的事实在它那一步答 `unavailable`。未授予的跨租户访问在作用域或成员事实一步拒绝，另一组织的租户与本组织的非成员同表现。
- 结论只有 `allowed`、`denied`、`unavailable`。`unavailable` 不是拒绝也不是允许：消费方阻止依赖允许的动作，不改写成已知无权，不用旧允许代替。`allowed` 与 `denied` 带依据与证据；证据摘要覆盖结论、原因与依据，参数摘要在依据里，读者可以重算。证据只能被同一次执行路径消费。
- 裁定是事实的纯函数，同一输入与同一事实给出同一结论。参考检查不保存结论，每次调用重读核验、成员事实与许可状态；依赖抛出一律是 `unavailable`，诊断不带异常文本。消费方在实际执行处每次调用裁定，不把一次 `allowed` 沿用到下一个动作。撤权之后的下一次裁定拒绝，主体对象不变也如此。
- 裁定与参考检查在保存边界复制并冻结值字段，调用方之后修改输入或返回值不能改写依据与可重算的摘要；主体与已铸造的租户保留原对象，保住来源核验需要的对象身份。
- 裁定不核对原工作的推进资格：消费方在操作点还须向原工作拥有者核对。缺少这项守卫的适配器不得推进业务。
- 消费端口经适配器接入：`allowed` 映射为端口的允许并带证据，`denied` 为拒绝，`unavailable` 为不可用；适配器不产生端口有而裁定没有的结论。适配器归应用装配或消费方，不在本组。
- 明确禁止不能被下层配置、授权表达、人工批准或运行模式突破；依据缺失不解释成允许；工作区不是提权来源。可见、持有、装配、调用、修改、分享与外传是不同动作，分别判定。管理角色不自动开放成员私有内容。

### 许可与消费

- 一个许可绑定一个操作、一个目标与一个参数摘要，三者在授予时记录；授予由产生它的表达或决定的拥有者做，参数摘要是人看到并批准的那一份。台账按（租户，许可文本）保存，另一租户的同名许可与从未授予的许可同答 `unknown`。
- 带许可的 `allowed` 不足以执行：同一开放许可上两次裁定都可能允许，只有一次消费成功。消费方以消费成功为执行依据，在自己的线性化点消费；再次消费答 `already-consumed` 并带原消费事实，不产生第二份消费，消费方比较事实里的消费位置认回自己的那一次。已消费的许可不复活。
- 参数改写之后出示同一许可得到 `permit-mismatch`：人看到、重新判断与实际执行采用同一份参数。单次批准只覆盖本人明确批准的那个动作；只有明确批准整批才覆盖该批的明确动作，每个动作仍各自满足当前准入；批次批准不扩到后来产生的新批次。
- 消费与实际资源提交的一致性归原操作的契约，本组不定义同提交。撤回产生新的撤回事实并保留原表达。

### 人工决定与询问处理

- 询问处理在结构化裁定之后应用：`prohibited` 始终拒绝，`unavailable` 保持不可用，不需要询问时保留自动路径；需要询问时才消费策略，缺策略是不可用，策略分别给出拒绝、问人与跳过询问。「继续」只表示询问这一步可以过去，不是准入许可。
- 人的拒绝、明确不回答、还没作答与失效各保留真实含义，都不是批准。依赖超时、连接断开或实例丢失不产生人的答复。答复之后按当前资格重新判断，不直接越过准入启动执行。
- 准入卡上的附言（人说了话但没给准驳）是自然语言的授权表达。解释器没有、不可用或读不出准驳时，附言不形成批准：适配器在裁定为 `allowed` 之后改答拒绝，原因 `human-guidance`；跨租户等更早的拒绝先给出。原话交回原工作拥有者作指导，不进证据。授权不把没有答案改写成执行失败，也不自动重问。

### 系统动作授权

- 系统部件做扫描、目录读取与已成立义务的收尾时，用独立的系统动作授权，不借租户准入。请求是系统主体、系统作用域、操作、目标（系统分支或租户分支）与参数摘要；租户分支里的租户是被维护对象所在的分区，不使系统主体代租户行事。
- 判定次序：主体核验（须是请求里的同一个系统主体）；用途矩阵（操作不在矩阵里答 `operation-forbidden`，这一步先于读取授予记录；作用域、目标分支或资源与该行不符答 `binding-mismatch`）；授予记录（没有或不含本行用途答 `grant-missing`，已撤销答 `grant-revoked`，有截止时间且已到答 `grant-expired`）；参数（固定参数的行须是无参数摘要）。答复种类不在约定之内（空答复、未知种类、形状不对）是读不到可信事实，答 `unavailable`，不是拒绝，更不是允许。没有安装授予来源时矩阵内的每个动作都是 `unavailable`。
- 只允许矩阵列出的动作；授予用用途点名行，用途只按相等比较，`*` 不是通配，持有一行用途的主体对其他行得到 `grant-missing`。需要矩阵之外的系统动作时，先给出该动作的既有职责与原义务绑定，再加行。
- 授予读口是读取授予记录的唯一入口，本组没有写入侧，安装事件不是授予。撤销或到期在下一次核验生效；一次 `allowed` 之后、动作完成之前的撤销不阻止这一次动作。用户退出不撤销具名维护授权。

### 持久提供者

- 身份记录落在系统作用域、系统保留前缀的事务域里；租户事务域的推导不得产出这个前缀。组合版本随参加者执行的全部代码（它按相对路径导入的模块闭包）变化，改了就登记新版本，旧登记留在域里。迁移发布后字节不变，表结构的变化写成新迁移。
- 一切不确定的计算（输入校验、口令派生、随机标识、摘要、时刻、排序键）在提交之前于主线程完成；写事务里的参加者只执行 SQL 与必须和写入同处一个事务的记录核对，不用随机数与时间函数。事务里比较时刻用排序键，排序键的文本次序与 utc-instant 的时刻比较同序。
- 凭据只保存口令派生材料，登录凭证只保存摘要；原文不进事实、表、读输出、诊断与错误文本。账号不存在时用插件启动时对随机秘密派生的假材料校验一次。
- 存储的写在事务域内串行，所以治理核对与写入的并发保证来自同一次提交。已提交的事实按存储的持久保证落盘，重启之后的识别与治理判断与重启前相同。
- 登录与邀请的时长、访问刷新粒度都来自配置，全部必填；缺一项或非法时插件失败，不提供任何服务，不填默认值。默认初值只供部署显式取用。
- 停止只设停止标志：之后的新调用答不说明凭据、登录或成员关系真假的结果（注册 `not-loginable`，签发、识别与治理 `basis-unavailable`，资格读口 `unavailable`；空凭证的识别仍答 `invalid`）；停止之前受理的调用跑完。停止不释放预留，不删除意图，不撤销已提交的事实。

### 口令派生

- 派生参数是部署配置，在打开时复制；缺字段、零或非有限正数时不创建模块。N 须是大于 1 的 2 的幂，不用 32 位位运算判断；r 或 p 为零的配置拒绝。参数只能放宽，不能低于已发布材料的值。
- 同时计算与排队的数目有上界，超出在计算前答 `queue_full` 或 `memory_limit`，等候不占派生内存。单个秘密的字节数超过上界时在政策与入队之前答 `unavailable`；超长材料在解码前拒绝。
- 不认识的方案与口令错误是 `mismatch`；材料损坏、参数超过当前配置或计算失败是 `unavailable`。口令政策由调用方传入，缺政策、政策抛错或返回值不合约定都不当成通过。比较用常数时间的比较。
- 关闭拒绝新的派生与校验，让还没开始的等候离开，等已经开始的计算结束；停止等待不归还已开始计算的名额。

### 协议与接入

- `identity/v1` 列出客户端可以调用的全部身份操作，契约是完整的；部署不提供的操作由处理函数答 `stage-not-provided`，每个操作都可以这样答。不需要登录、需要登录、需要登录且代租户行事三种身份要求，查询类与准入判断是读，其余是写。固定结果的响应体为空。
- 只有签发登录的成功体带登录凭证，通用通道不转发它；其他任何结果体都不带。签发登录的成功体总带登录的标识。身份操作不算业务访问，业务访问由会话的操作报告。
- 接入插件的处理函数调身份的公开入口，结果按治理端口的结果映射，不改写身份的 `denied` 与 `basis-unavailable`；领域服务每次调用现取，取不到答 `basis-unavailable`，协议不撤；抛出交给管道按效果规则答。入口身份端口里识别失败答 `denied`，依据不可得或抛出答 `basis-unavailable`。
- 协议契约是纯数据，只依赖公开契约成员，能在浏览器里用；领域核心不依赖接入成员。

### Cordis 装配

- 每个服务键由 `identity/cordis` 里对应抽象类的静态 `provide` 给出；提供者继承抽象类实现原接口，不另写键。纯契约的根入口不加载 Cordis。
- 持久提供者的插件注入存储与时钟两项，缺时钟时停在 PENDING；它在同一插件体里为同一个提供者实例提供全部身份服务，所以经治理端口的撤销与切换对识别立即生效。目的地封口与主体核验器是可选的受信依赖，每次预留或结算时现取，缺席时相应操作不可用，不释放持久预留。
- 撤除用一个受管效用：先停止提供者，再等口令模块关闭；撤除不撤销已提交的事实，不关闭存储。依赖换代时插件体重跑，组合登记幂等认回。
- 签发者与治理端口只装进受信子树；服务键存在不授予权限。生产根不自动安装完整签发者。

## 原则与约束

- 拿不到就是拿不到。确定的否、依据不可得与结果不知道分别如实交出，不互相改写，不用旧值、默认值或更宽的默认方案补。
- 资格每次现读，不缓存允许。主体只证明来源，成员事实决定资格，裁定只对这一次动作有效。
- 身份每次调用显式带上；跨租户默认拒绝；拒绝与不可见不披露另一租户或对象是否存在。
- 签发归身份，装配只安装；签发者与治理端口只交给声明过的受信持有者。
- 核对与写入同处一次提交；需要与外域写入同序的，走成员资格预留，不靠通知。
- 结果不知道按原逻辑身份认回，不新建同义操作，不重复签发当作认回。
- 期限、粒度、名单上限与派生参数都是配置或可替换策略，代码里不写死数值；合法使用会碰到的上限要有去处，不判失败。
- 撤权、撤除与停止只改资格与准入，不证明实际执行已停，不撤回外部效果。
