# authorization：长期行为规格

状态：[具名采用](https://github.com/nemori-ai/omne-harness-lite/issues/266#issuecomment-6190010029)覆盖 AU-01 至 AU-07、披露与后续治理操作的业务规则。AU-08、AU-10 是后续验证义务。AU-09 继续登记阶段与公开形状的承接责任。AU-11 定义首批公开形状，类型在本成员 `src/index.ts`。表达解释、人工决定、持久台账与跨进程依据的提供者机制尚需设计，本文不作为那些部分已实现或已验证的证明。

产品规则归[身份与授权产品](../../../.meta_harness/design/product/identity-and-authorization/design.md)，协作与依赖归[领域架构](../../../docs/domains/identity-and-authorization/architecture.md)。本文拥有授权建模、表达解释、范围、决定绑定、当前准入、撤回与消费。资源业务、权限配值、人工交互和运行控制由各自拥有者负责。

## AU-01 输入、建模与责任边界

消费者可以定义自己的资源、动作和资格条件，通过共同契约提交授权判断。输入须明确可信主体、行事范围、资源对象、实际动作、生效参数及判断所需的合法依据。不同事实不能压成一个没有作用范围的“当前用户”。

资源类别的含义和操作后果由资源拥有者定义，authorization 不要求资源必须属于工具、资产或某个运行时。纯计算可以只处理调用方提供的数据；访问托管资源须兑现相应访问契约。独立调用不需要伪造 Session、模式或运行状态。

[identity](../identity/SPEC.md)提供可信主体和当前资格，合法权限的来源及求值归相应拥有者。范围拥有者提供已认可的范围、原操作关联及生效条件。人工交互需要时消费 HITL 的有效答复，不直接读取这些成员的私有实现。

裸账号或租户 ID、连接、路径、历史允许及 Cordis Context 不能自行成为资格。高权限服务须核验原调用主体，不能用服务自身权限替调用者越权放行。资格判断的依据来源和实际采用范围须可追溯。

## AU-02 不可突破约束与合法权限

租户隔离、明确禁止、可信主体及实际作用范围是共同约束。锁定的允许集合形成上界，未锁定值按资产与规则的合法选择结果使用，不能将全部普通配值机械取交集，也不能在本成员另建配值引擎。

明确禁止不能被下层配置、授权表达、人工批准或运行模式突破。没有授予跨租户资格时默认拒绝，依据缺失不能解释成允许。工作区不是提高权限的来源。

不同动作的资格分别判定。可见、持有、装配、调用、修改、分享或外传不能互相推导。具体动作集合由所属业务定义，本成员不声明所有资源都必然具有相同操作。

准入允许不保证执行环境可用或动作成功。实际拥有者继续检查环境、凭据、资源和提交条件，人工批准不能解除结构化禁止或环境隔离要求。

## AU-03 授权表达与适用范围

### 表达与解释

结构化操作或自然语言可表达批准、拒绝及撤回。系统保留原表达和确认后的含义，说明表达者、动作、范围及必要依据。无法确定含义时保留未确定，不扩大范围，也不把模型解释的猜测当成用户决定。

表达者须有对应操作及范围的当前资格。授权成员提供共同解释能力，具体自然语言解释器、可信记录与关联接口仍需细化。扩展未提供、不可用或无法解释时不能假报已经得到允许。

### 单次与明确批次

单次批准只覆盖本人看到并明确批准的动作，单张动作卡不能扩展到同批其他动作。只有明确批准整批才覆盖该批的明确动作，每个动作仍须满足自身的当前准入条件。

许可与原动作、对象及生效参数关联，消费后不能复用。重复提交或重放同一动作不能增加许可，批次批准不扩展到后来产生的新批次或持续范围。

原操作拥有者定义动作和批次身份、终点及必要失效条件，authorization 维护对应授权的解释与消费。不能由本成员自行定义 Run 或其他业务生命周期，也不能把工作恢复当成新批准。

### 持续范围及持久规则

其他业务可接入自己的持续或全局范围，须明确拥有者、生效条件、记录位置及失效条件。本成员引用这些可信事实，不因范围名称为“全局”而授予跨组织或系统权限。

会话授权的业务范围、流水保管及业务终点由会话拥有者维护，授权成员提供表达、撤回及消费含义。系统装配沿[准入与 HITL](../../../docs/architecture/runtime/loop-extensions.md#准入与-hitl)接入，不在本成员复制一套会话生命周期。

持久权限写入须满足对应配置的管理资格及组织上界，由资产与规则的正式写入能力承接。仅追加表达不表示设置已更新，写入失败或结果未知不能报告持久规则已经生效，也不能静默改成另一作用范围。

撤回产生新的撤回事实，原表达保留用于可追溯解释。历史批准不证明仍有资格，具体资源访问仍按当前操作判断。

## AU-04 当前准入与结果

准入核验可信身份、作用范围、结构化约束及合法权限，随后按需要解释有效授权。已经明确禁止的动作不通过人工请求绕过禁止。符合自动准入规则的动作不为形式统一强制询问。

已有适用表达须同时满足当前资格、动作和参数匹配、有效范围及未消费或未撤回条件。无法满足时不能沿用历史允许。消费者提供适用运行策略时，策略只在共同边界内参与判断，不能扩大权限。

需要人工决定时给出原授权问题及必要关联，由人工交互能力交付。系统内的权限模式与具体判断顺序由已接受运行架构拥有，authorization 的独立调用不以存在这些模式为前提。

结果至少区分允许、拒绝、需要决定及必要依据无法取得，精确类型归公开形状设计。拒绝原因、含义未定和依赖不可用不能被一个成功布尔值覆盖。已知明确禁止可直接拒绝，其他必要依据不可得时阻止依赖允许结论的动作，不伪造正常拒绝原因。

准入服务不可用不能通过临时审批绕开，也不能由消费者复用无条件旧允许。允许结果保留实际主体、对象、动作、参数及必要依据，缓存或跨边界使用须有明确的可信来源和有效条件。

## AU-05 人工决定、参数改写与重新核验

决定绑定原请求、实际动作、作用对象和生效参数。答复者须有当前决定资格，重复或并发答复不能变成额外许可。HITL 维护请求、交付和唯一有效答复，授权成员校验答复的适用性，不建设第二份人工工作流。

参数改写后，人看到、系统重新判断和实际执行采用的内容须一致。动作、实现、参数或影响授权的依据改变时，旧批准不能自动适用。有效答复后按当前资格重新判断，不直接绕过准入启动执行。

拒绝、明确不回答、尚未作答和失效分别保留真实含义，均不能成为批准。原工作拥有者决定收到这些结果后怎样继续或收口，授权成员不将没有答案改写成执行失败，也不因没有批准就自动重问同一问题。

依赖超时、连接断开或运行实例丢失不产生人的答复，也不能单独证明原操作终局。等待的保存、取消和终结归原操作及 HITL 契约，授权的适用与消费沿原范围判断。

## AU-06 撤权、持久记录与恢复

成员资格、角色、权限及表达变化须可供后续准入识别。消费者拥有检查时机及所要求的判断与提交一致性，authorization 提供当前可核验依据，不能用普通通知冒充共同提交。

已确认的授权表达、撤回、消费及必要决定事实按系统耐久保证保留。恢复后不能复活已消费、已撤回或失效授权。原操作终局及范围失效事实由各自拥有者提供，不因授权实例重建而消失。

撤权不代表实际执行已经停止，也不回滚外部效果。停止结果交付、资源访问和消费确认须各自满足对应资格，结果保管及实际控制由业务拥有者负责。

事实读取失败不制造撤回或终局，事实缺失也不能补造允许。恢复先认回原操作、范围、决定及消费依据，再判断可否继续。介质或整机损毁后，0.0.0 到 0.1.0 不提供重新打开。不能用旧备份恢复的角色批准访问。

## AU-07 跨范围集成、装配与可追溯性

身份、资源及作用范围在 SDK、后台、系统任务和独立调用中均显式提供。跨进程或节点的依据须核验来源、适用对象及有效条件，不以任意可修改的租户字段作为证明。

子 Agent 权限组合、日程资格、资产创作与提升、成本账目读面分别由对应领域定义。authorization 消费其明确动作和约束，不用一般管理角色推导全部资源可读，也不将某项业务的准入模型推广到所有消费者。

组织管理员的管理资格不自动开放成员私有内容，读取诊断和对外发送分别授权。判断与治理结果记录必要的主体、范围、规则、决定和消费关联，读取及导出仍受内容和租户权限约束。

公开授权能力独立于 Cordis，系统提供者负责绑定、资源管理、替换及退出交接。提供者撤除不证明原判断或提交未发生，原调用与结果未知须有收口责任。Cordis 生命周期不替代授权记录的持久性、同提交或跨租户访问控制。

## AU-08 持久验证义务

这些是将来实现及集成须兑现的验证义务，不是已通过的证据。

| 反例 | 应检验的行为 |
| --- | --- |
| Session 外自定义资源请求授权 | 沿显式身份、动作与范围判断，不强制构造会话或工具对象 |
| 配置、批准或运行模式放宽明确禁止 | 不通过，不生成绕过请求 |
| 工作区或裸租户字段声明更高权限 | 不产生可信资格或提权 |
| 管理角色或查看资格被用于其他动作 | 仍核验该动作的实际资格 |
| 自然语言含义、动作或范围不确定 | 保留未确定，不扩成持续或系统许可 |
| 解释器或准入依据不可用 | 不假报已有允许，不用审批绕过服务 |
| 单张批准消费同批其他动作或后来批次 | 不匹配，明确整批时也只覆盖原明确动作 |
| 授权消费后重放或实例恢复 | 不增加许可次数，不复活已消费或撤回事实 |
| 表达被记录但持久设置写入失败或未知 | 不报告已形成全局效果，不静默改范围 |
| 等待期间资格、实现或参数发生变化 | 按当前资格和实际参数重判，旧批准不直接执行 |
| 同一决定从不同入口重复作答 | 一个有效决定，不增加授权 |
| 明确不回答、尚未作答或服务超时 | 保留真实区别，不产生默认批准或伪造终局 |
| 查询失败、连接断开或 disposer 被当成实际停止 | 不伪造终局、未发生或无副作用 |
| 身份判断与资源提交分离期间撤权 | 兑现原操作所要求的一致性，不用通知替代 |
| 管理员用某业务资格读取私有记录或诊断 | 该资格不自动开放其他读面 |
| 提供者替换后原提交回执丢失 | 结果保持可认回，不重建批准或盲目执行 |

纯求值、表达解释、人工交接、资源提交、跨进程来源和耐久恢复分别覆盖其保证。类型、mock、图和有限通过不能证明全部副作用可撤回、恶意代码隔离或灾后开放安全。性能尺度与真实装配验收归 T06。

## AU-09 阶段范围、公开形状与维护

0.0.0 -> 0.1.0 完整承接产品 CAP-ID09 至 CAP-ID12 的授权部分，并消费 CAP-ID01 至 CAP-ID08 的身份与治理依据。完整支持以产品能力定义为准，不由本规格中的摘要缩减。

公开形状仍须定义资源及动作接入、授权表达和解释结果、范围与操作关联、决定绑定、撤回与消费事实及可信提交查询接口。解释器、存储、并发消费、缓存、跨节点协议和共同完成机制归对应提供者及协调责任设计。

技术设计不得用接口便利补充委托、灾后恢复资格或业务生命周期。产品缺口及邻域事项见[问题登记](../../../.meta_harness/design/product/identity-and-authorization/design.md#未决问题与待定事项)，能力落点见[架构映射](../docs/architecture.md#阶段覆盖与后续细化)。改变有效行为须同步依据、公开类型、消费者和验证，技术候选、实现、验证及交付接受分别记录。

## AU-10 旅程定位与持续验证场景

本节连接 [J-ID06](../../../.meta_harness/design/product/identity-and-authorization/design.md#j-id06)、[J-ID07](../../../.meta_harness/design/product/identity-and-authorization/design.md#j-id07)、[J-ID08](../../../.meta_harness/design/product/identity-and-authorization/design.md#j-id08) 与 [F-ID06](../docs/key-flows.md#f-id06)、[F-ID07](docs/internals.md#f-id07)、[F-ID08](../../../docs/domains/identity-and-authorization/key-flows.md#f-id08)。CAP-ID09 至 CAP-ID12 的完整行为仍沿 AU-01 至 AU-09，身份事实沿 identity，不改阶段或原 AU-08 的验证义务。以下是持续验证场景，尚无本次运行证据。

<a id="v-au-j06"></a>

### V-AU-J06 显式身份及独立动作准入

交互、独立、后台和恢复入口对同类实际动作分别提供其认可的可信身份和范围，符合规则时取得准入结果。不能因没有 Session 强制伪造会话，也不能因管理员身份、对象可见或裸租户字段直接通过其他动作。请求明确禁止或未经授予跨租户访问时拒绝，必要依据不可得时阻止依赖允许的新动作。身份选择成功与动作获准分别可定位，恢复路径重新核当前资格，取消等待不报告实际访问未发生。

<a id="v-au-j07"></a>

### V-AU-J07 原决定等待、范围与消费

对可自动动作验证不强制出卡，对明确禁止验证不生成绕过审批，对需要决定的动作保留原操作、对象、生效参数及等待位置。HITL 出卡、唯一答复及原业务处理异步分段，答复回到原扩展或消费位置。分别验证批准、拒绝、明确不回答、尚未作答和失效；等待没有默认超时批准或拒绝，明确不回答交回无答案且不自动重问，连接断开或查询失败不制造答复或卡片失效。

等待期间收窄资格、改写参数或替换实现后，旧批准不能直接执行，重新判断与实际调用采用同一人可见参数。单张批准不覆盖同批其他动作，明确整批只覆盖原明确动作，各自当前准入齐备才按原流程执行获准动作。消费重放不增加次数，动作提交回执丢失先认回许可和原效果，不盲目重新执行；消费与资源提交的一致性按 T03 具体协议验收。

会话范围由会话保管，归档不自动撤回，Run 终局的单次清理不扩大许可。原等待取消及原操作确定终局时沿原控制契约处理，authorization 不另建终态。租户全局表达经写设置资格及上界核验后交资产与规则正式写入；写失败或未知不报告持久生效，也不静默改成临时授权。普通恢复认回原答复、范围、消费及写入结果，已消费许可不复活。相关记录和结果 ACK 按各自原拥有者分别取证，保留先可靠保管及先完成处理两条合法确认路径，不以答复到达或许可消费证明业务完成。

<a id="v-au-j08"></a>

### V-AU-J08 撤回、结果资格与事实恢复

对有当前资格的撤回新增撤回事实并保留原表达，后续准入按变更事实判断。无资格撤回拒绝，提交结果未知保持原身份；读取故障不伪造撤回、终局或允许。排队、人工等待及恢复路径不能无限沿用旧允许，判断与提交分离期间撤权按原操作一致性承诺验收。

分别核验撤权后的结果读取、交付和消费确认资格，停止交付不能消除生产者或合法承接者的保管责任。控制请求和物理执行结果独立记录，撤权、归档和 disposer 不证明实际执行已停止，也不回滚已发生输出。普通崩溃、重启及断电恢复后认回原操作、范围、决定和消费，已撤回或已消费事实不复活。查询与审计只读取原事实、不重做动作，私有内容和凭据不因管理角色或诊断需要泄露。介质或整机损毁后不提供重新打开，不能借旧快照直接允许。

公开形状、语义识别、参数记录、提交认回、跨边界来源及真实验证资源继续归 T01 至 T06。图和场景完整不表示这些机制已交付或业务已通过。

## AU-11 首批公开形状：准入裁定、许可引用与消费事实

本节的类型在 `src/index.ts` 定义。本节只写类型表达不了的条款。表达解释、人工决定、结构化约束与持久台账不在本节。

消费适配的有限范围按 [#659 的有限采用决定](https://github.com/nemori-ai/omne-harness-lite/issues/659#issuecomment-6370208573)采用。它不表示四个消费端口已全部实现。

### 裁定输入

`AdmissionInput` 是 `{ access, operation, target, arguments, requires, permit }`。`access` 是 `Access<Principal>`：identity 签发的主体与显式租户。`operation` 是 `{ owner, name }`，`target` 是 `{ owner, kind, key }`。两者对本成员不透明：资源拥有者命名它们并拥有含义，本成员只记录它们并与许可比较。

`arguments` 是生效参数的摘要 `{ digest }`。参数本身对本成员不透明：资源拥有者或它的适配器用 `effectiveArgumentsOf` 对实际执行所采用的固定表示算摘要，签发许可与裁定时用同一表示。没有参数的操作出示 `noArguments()`。

`requires` 是资源拥有者为这次操作要求的具名资格；为空表示成员资格足够。`permit` 是调用方出示的许可引用。首批是一个缺口：由资源拥有者决定这次操作是否需要许可并在输入里出示，与 `requires` 同样；本成员是否维护操作与适用表达的对应，随 AU-03 的表达解释形成形状时定。未出示许可时 `permit` 为 null。

### 裁定结论

`AdmissionDecision` 是 `allowed`、`denied` 或 `unavailable`。`allowed` 与 `denied` 带依据 `basis` 与证据 `evidence`。`denied` 另带 `reason`。`unavailable` 带诊断文本；它不是拒绝，也不是允许。消费方收到 `unavailable` 时阻止依赖允许结论的动作，不把它改写成已知无权，也不用旧允许代替。

### 裁定步骤

`decideAdmission(input, facts)` 按固定顺序判断。第一个不满足的步骤决定结果。

1. 主体核验。核验器答 `rejected`，拒绝，原因 `untrusted-principal`。核验器答 `verified` 但核验得到的主体不是输入 `access.principal` 的同一个对象，同样拒绝，原因 `untrusted-principal`：事实必须是对这次输入里那个主体的核验。答 `unavailable`，结论 `unavailable`。
2. 作用域。系统主体出现在带租户的访问里，拒绝，原因 `scope-mismatch`：系统主体没有租户资格，代租户行事必须签发代租户行事主体。代租户行事主体的租户与访问的租户不相等，拒绝，原因 `tenant-mismatch`。手写的租户同样得到 `tenant-mismatch`。
3. 当前成员事实。identity 读口答 `not-member`，拒绝，原因 `not-member`。答 `unavailable` 或没有读到，结论 `unavailable`。
4. 资格。`requires` 中任一资格不在读到的资格里，拒绝，原因 `qualification-missing`。
5. 许可。只在出示了许可时判断。许可引用的租户与访问的租户不相等，拒绝，原因 `permit-mismatch`。台账答 `unknown`，拒绝，原因 `permit-unknown`。许可的文本、操作（`owner` 与 `name`）、目标（`owner`、`kind` 与 `key`）或参数摘要与输入不符，拒绝，原因 `permit-mismatch`。参数改写后出示同一许可，得到的就是这个结果。许可已消费，拒绝，原因 `permit-consumed`。台账不能读，结论 `unavailable`。

未授予的跨租户访问在第 2 步或第 3 步拒绝。另一个组织的租户从未是成员，答 `not-member`，与本组织的非成员同表现。

这些步骤不核对原工作的当前推进资格。消费者在实际操作点还须向原工作拥有者核对该资格。成员仍有效不表示工作仍有效。缺少必要工作资格守卫的适配器不得推进业务，不能用本裁定的 `allowed` 补足缺失能力。

### 依据与证据

`basis` 记录裁定所依：操作、目标、租户、参数摘要、已核验的主体、读到的成员事实、要求的资格、出示的许可。未出示许可时 `basis.permit` 为 null，读者据此知道这次允许不依赖任何许可。参数摘要进入 `basis`，所以证据摘要随参数变化。证据是 `{ owner: 'authorization', record, revision, digest }`。`record` 是 `admission/<operation.owner>/<operation.name>`。`revision` 是裁定所依身份事实的修订；没有读到事实时是 `0`。`digest` 是 `{ kind, reason?, basis }` 规范 JSON 文本的 SHA-256。读者用 `digestOf` 重算并比较。证据类型是 `DurableEvidence & { owner: 'authorization' }`。`DurableEvidence` 的唯一定义在 exchange-refs，消费方契约再导出同一类型。摘要算法仍归本成员。

裁定保存值数据的自有不可变快照，包括操作、目标、参数摘要、要求的资格、许可引用包装，以及成员事实中的角色、模型、资格与证据。调用方后续修改这些输入，不能改变已返回的依据或其可重算摘要。快照不冻结调用方对象。已核验主体与已铸造租户按原对象保留，不通过 JSON 复制或重新铸造改变其身份。

### 不缓存允许

`decideAdmission` 是纯函数：同一输入与同一事实给出同一结论；事实变了，结论随之变。`referenceAdmissionCheck` 不保存任何结论，每次调用重新读主体核验、成员事实与许可状态。消费方在实际执行处每次调用裁定，不把一次 `allowed` 沿用到下一次动作。

`referenceAdmissionCheck` 在首次调用依赖前复制并冻结本次输入的值字段，只保留主体和已铸造租户的原对象。后续读取与裁定只使用这份快照。核验回答、成员事实与完整许可答复在读取完成时复制并冻结自有值包装，返回下一异步段前完成快照。许可快照包含授予绑定、授予证据、消费状态与消费事实；已铸造租户保留原对象。后续裁定不回读原答复，调用方及提供者的原对象不被冻结。这些快照绑定本次输入与已读事实，不提供跨数据源的同一时刻快照或操作点一致性。

撤权后再核拒绝：成员关系撤销后，identity 读口答 `not-member`，下一次裁定答 `denied`。原主体对象不变也如此。

每次重读不等于与最终执行共同排序。异步 `referenceAdmissionCheck` 和纯函数 `decideAdmission` 都不提供 [Model 最终发送的 R/S 围栏](../../model/model-contract/SPEC.md)。Model 提供者须协调身份权威资格写者与发送入口，在同一围栏内重读最终权威事实、核对凭据并同步 `start`，中间不得 `await`。纯裁定可以消费围栏内取得的一致事实，但它不建立该围栏。装配必须取得真实的共同排序协议，不能先异步 `check` 再凭旧 `allowed` 发送，也不能用缓存充当最终资格。这个提供者组合尚未交付。

### 许可引用与消费事实

`PermitRef` 是 `{ tenant, permit }`。一个许可绑定一个操作、一个目标与一个参数摘要，三者在授予时记录。台账按（租户，许可文本）保存许可，另一个租户的同名许可答 `unknown`，与从未授予的许可同表现。手写的租户同样答 `unknown`。

带许可的 `allowed` 本身不足以执行。消费方以 `consume` 答 `consumed` 为执行依据：同一开放许可上两次裁定都可能答 `allowed`，只有一次 `consume` 成功。

`PermitLedger.consume({ permit, consumer })` 把开放的许可变为已消费，返回 `ConsumptionFact`：许可、消费位置与证据。同一许可再次消费答 `already-consumed` 并带原事实，不产生第二份消费，无论消费位置是否相同；消费方比较事实里的消费位置来认回自己的消费。消费后的裁定答 `permit-consumed`。已消费的许可不复活。

消费点在消费方的线性化点：Tool 在 P04 的 consume 处消费许可，受理记录带 `PermitRef`。本成员不定义消费与实际发起的同提交；一致性归消费方的原操作契约。

台账在授予时复制并冻结操作、目标、参数摘要与 `granted` 证据，在消费时复制并冻结消费位置。许可引用保留已铸造租户的原对象。修改输入或返回值不能改写已保存的许可和消费事实，调用方的原对象仍可修改。

`PermitGrantor.grant` 由产生许可的表达或决定的拥有者调用，`granted` 是那份表达或决定的证据，`arguments` 是人看到并批准的那份参数的摘要。本节不定义表达的解释、撤回操作和人工决定的绑定；它们沿 AU-03、AU-05 另行形成形状。

### 消费端口的适配

消费端口经适配器接入授权。适配器把消费端口的输入映射为 `AdmissionInput`，把结论映射回该端口的结论。各消费端口与本节的逐项映射写在接入它的适配器成员里。`allowed` 映射为端口的允许并带证据，`denied` 映射为端口的拒绝，`unavailable` 映射为端口的不可用。适配器不产生端口有而本节没有的结论，例如 `need-decision`。实际适配器归应用装配或消费方的适配器成员，不在本成员。

首批 `ActionAdmission` 示例仅在 `permissions` 与 `decision` 都为 null 时使用上述映射。非 null 而必要解释端口未安装时返回 `unavailable`，不得忽略输入后允许。该示例不实现结构化权限、人工答复解释或完整 `invalid` 分类。正式适配器须接续 Agent 契约要求的错动作、错卡片答复校验，并满足实际工作资格守卫等消费前提。

测试内的 `SessionAccessCheck` 仅为本卡首批适配模型，不是 Session 已落地的正式接口。真实 Session 公共接口的兼容重验尚未完成，由 B1/S-2 后续协同补齐。这个未完成子范围不能据本地模型测试声明通过。

### 首批不覆盖的部分

结构化约束（permissions 的锁定允许集合与明确禁止）不进入首批裁定；它们由权限求值的写入者生产，接入形状待定。需要人工决定的结论、表达解释、撤回操作与持久台账待后续形状。系统作用域下的准入（系统主体在系统作用域的动作）不经本节的输入；它的形状随消费端口加入系统作用域变体时定义。

### 参考件

`referenceAdmissionCheck` 与 `inMemoryPermitLedger` 是进程内参考件。它们不持久：进程退出丢失全部许可。依赖抛出异常时结论是 `unavailable`，诊断不带异常文本。它们用于骨架装配，由耐久提供者替换。

### 验证

`tests/decide.spec.ts` 覆盖每个步骤、每个拒绝原因、两种不可用、证据的重算、参数摘要进入依据与证据、许可对操作的 owner 与 name、目标的三个成员和参数摘要逐项比较、核验得到另一个主体时拒绝。`tests/evidence.spec.ts` 覆盖规范 JSON 的成员顺序无关、undefined 成员去掉、数组保序。`tests/reference-check.spec.ts` 覆盖撤权后再核拒绝、每次重新读取、依赖抛出不放行、许可消费后不再放行。`tests/reference-snapshots.spec.ts` 覆盖异步读取期间的输入绑定、跨租户资格拼接拒绝，以及已读核验回答与成员事实不被后续修改改写。`tests/permit-reading-snapshots.spec.ts` 覆盖许可读回后微任务改写状态、绑定、答复种类或诊断不能改变裁定，原包装仍可修改，真实台账历史与可重算证据保持。`tests/permit.spec.ts` 覆盖台账的授予、查找、跨租户、手写租户与重复消费。`tests/snapshots.spec.ts` 覆盖调用方修改与返回值写入不能改写已存许可、消费事实或裁定依据，证据仍可重算。`tests/port-adapters.spec.ts` 覆盖 Agent、Tool 的有限映射及未支持权限、错动作或错卡片答复输入不放行，并验证本地 Session 适配模型。它不证明真实 Session 公共接口兼容。这些测试不覆盖持久台账、表达解释、人工决定与跨进程依据。

## 披露与后续治理操作

本节与所引用业务条款已经采用，范围见页首。操作清单不替代精确公开类型。

没有授予跨租户资格时，结果是拒绝。持有标识、句柄或历史允许不是资格。依据不可得时，阻止依赖允许结论的动作，并且不把该结果说成已知无权。认证失败的对外表现不区分账号不存在、未激活和凭据错误。那条对外表现归 identity。本成员不另造第二种认证失败。

| 结果 | 对外可以说的 | 内部诊断可以保留的 |
| --- | --- | --- |
| 允许 | 本次动作准入通过 | 主体、操作、资源、参数和依据 |
| 拒绝 | 本次不获准 | 明确禁止、已知无权或跨租户未授予 |
| 需要决定 | 等待原决定请求的一次答复 | 绑定的动作和生效参数 |
| 依据不可得 | 现在不能得出允许 | 哪一项依据缺失。不伪造成已知无权 |
| 对象按公开契约不可见 | 与不存在使用同一表现 | 对象是否存在。仅在该契约要求隐藏时 |

下表给出每一项操作的成功结果，以及失败或结束。公开类型仍归 T01。本表不创建接口。

| 操作 | 成功结果 | 失败或结束 |
| --- | --- | --- |
| 注册并激活 | 账号、唯一个人组织和个人租户共同成立 | 条件不足或依据不可得时不报告可登录。回执丢失则结果未知 |
| 登录 | 签发一份独立登录 | 不存在、未激活、凭据错误对外同一表现。时间或期限依据不可得时不签发 |
| 退出或撤销一份登录 | 指定登录失效，其他登录保持 | 发起登录无效，或目标不可见 |
| 更换凭据 | 新凭据成立，本账号全部旧登录失效 | 不隐式签发新登录 |
| 创建组织 | 组织、创建者租户和所采用的初始治理共同成立 | 已知失败不报告可用 |
| 发出并接受成员邀请 | 默认团队中，首次加入和重新加入取得普通成员，并沿用稳定租户。见 identity ID-06 | 已是有效成员则无成员变更。过期、拒绝、撤回只形成一个终结。其他治理模型的角色沿 identity ID-12 |
| 查询本人有效登录 | 返回本账号当前有效登录及签发时间，不含可冒用材料。见 identity ID-03 | 发起登录无效则不返回 |
| 退出组织、移除成员、调整角色 | 默认团队沿 identity ID-05 与 ID-06。最后一位有效超级管理员不能被同一次移除或降级去掉 | 无资格则拒绝。重复邀请不改变角色 |
| 切换当前租户 | 只改变该交互登录之后的请求。见 identity ID-08 | 无资格或依据不可得时原选择保持。显式行事租户与当前选择冲突则拒绝 |
| 解除已生效隶属 | 仅上级有当前处置资格的人解除。见 identity ID-07 | 下级身份解除被拒绝 |
| 授权表达、撤回与消费 | 单次批准只覆盖明确动作。撤回留下新事实并保留原表达。见 authorization AU-03、AU-05、AU-06 | 含义不明不扩大范围。已消费的许可不能复用 |
| 处理隶属请求 | 双方确认后建立隶属 | 发起组织不存在则请求失效。目标组织不存在则过期 |
| 判断动作准入 | 允许、拒绝、需要决定，或依据不可得 | 未授予的跨租户访问拒绝。明确禁止不被批准覆盖 |
| 停用、恢复、终结主体 | 本阶段不提供 | 不按创建或删除补出结果 |
| 介质或整机损毁后重新打开 | 本阶段不提供 | 不从旧备份角色授予访问 |
