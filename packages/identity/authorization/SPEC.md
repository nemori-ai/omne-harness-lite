# authorization：长期行为规格

状态：依据身份产品及 0.0.0 -> 0.1.0 承诺更新的长期规格候选，待项目负责人确认。目标拥有者为 `packages/identity/authorization`，没有创建实际包。精确公开形状、提供者机制及行为证据尚需设计和验证。

产品规则归[身份与授权产品](../../../.meta_harness/design/product/identity-and-authorization/design.md)，协作与依赖归[领域架构](../../../docs/domains/identity-and-authorization/architecture.md)。本文拥有授权建模、表达解释、范围、决定绑定、当前准入、撤回与消费。资源业务、权限配值、人工交互和运行控制由各自拥有者负责。

## AU-01 输入、建模与责任边界

消费者可以定义自己的资源、动作和资格条件，通过共同契约提交授权判断。输入须明确可信主体、行事范围、资源对象、实际动作、生效参数及判断所需的合法依据。不同事实不能压成一个没有作用范围的“当前用户”。

资源类别的含义和操作后果由资源拥有者定义，authorization 不要求资源必须属于工具、资产或某个运行时。纯计算可以只处理调用方提供的数据；访问托管资源须兑现相应访问契约。独立调用不需要伪造 Session、模式或运行状态。

[identity](../identity/SPEC.md)提供可信主体和当前资格，合法权限的来源及求值归相应拥有者。范围拥有者提供已认可的范围、原操作关联及生效条件。人工交互需要时消费 HITL 的有效答复，不直接读取这些成员的私有实现。

裸账号或租户 ID、连接、路径、历史允许及 Cordis Context 不能自行成为资格。高权限服务须核验原调用主体，不能用服务自身权限替调用者越权放行。资格判断的依据来源和实际采用范围须可追溯。

## AU-02 不可突破约束与合法权限

租户隔离、明确禁止、可信主体及实际作用范围是共同约束。锁定的允许集合形成上界，未锁定值按资产与规则的合法选择结果使用，不能将全部普通配值机械取交集，也不能在本成员另建配值引擎。

明确禁止不能被下层配置、授权表达、人工批准或运行模式突破。没有授予跨租户资格时默认拒绝，依据缺失不能解释成允许。工作区不是提高权限的来源。

不同动作的资格分别判定。可见、持有、装配、调用、修改、分享或外传不能互相推导。具体动作集合由所属业务定义，本成员不声明所有资源都必然具有相同操作。

准入允许不保证执行环境可用或动作成功。实际拥有者继续检查环境、凭据、资源和提交条件，人工批准不能解除结构化禁止或环境隔离要求。

## AU-03 授权表达与适用范围

### 表达与解释

结构化操作或自然语言可表达批准、拒绝及撤回。系统保留原表达和确认后的含义，说明表达者、动作、范围及必要依据。无法确定含义时保留未确定，不扩大范围，也不把模型解释的猜测当成用户决定。

表达者须有对应操作及范围的当前资格。授权成员提供共同解释能力，具体自然语言解释器、可信记录与关联接口仍需细化。扩展未提供、不可用或无法解释时不能假报已经得到允许。

### 单次与明确批次

单次批准只覆盖本人看到并明确批准的动作，单张动作卡不能扩展到同批其他动作。只有明确批准整批才覆盖该批的明确动作，每个动作仍须满足自身的当前准入条件。

许可与原动作、对象及生效参数关联，消费后不能复用。重复提交或重放同一动作不能增加许可，批次批准不扩展到后来产生的新批次或持续范围。

原操作拥有者定义动作和批次身份、终点及必要失效条件，authorization 维护对应授权的解释与消费。不能由本成员自行定义 Run 或其他业务生命周期，也不能把工作恢复当成新批准。

### 持续范围及持久规则

其他业务可接入自己的持续或全局范围，须明确拥有者、生效条件、记录位置及失效条件。本成员引用这些可信事实，不因范围名称为“全局”而授予跨组织或系统权限。

会话授权的业务范围、流水保管及业务终点由会话拥有者维护，授权成员提供表达、撤回及消费含义。系统装配沿[准入与 HITL](../../../docs/architecture/runtime/loop-extensions.md#准入与-hitl)接入，不在本成员复制一套会话生命周期。

持久权限写入须满足对应配置的管理资格及组织上界，由资产与规则的正式写入能力承接。仅追加表达不表示设置已更新，写入失败或结果未知不能报告持久规则已经生效，也不能静默改成另一作用范围。

撤回产生新的撤回事实，原表达保留用于可追溯解释。历史批准不证明仍有资格，具体资源访问仍按当前操作判断。

## AU-04 当前准入与结果

准入核验可信身份、作用范围、结构化约束及合法权限，随后按需要解释有效授权。已经明确禁止的动作不通过人工请求绕过禁止。符合自动准入规则的动作不为形式统一强制询问。

已有适用表达须同时满足当前资格、动作和参数匹配、有效范围及未消费或未撤回条件。无法满足时不能沿用历史允许。消费者提供适用运行策略时，策略只在共同边界内参与判断，不能扩大权限。

需要人工决定时给出原授权问题及必要关联，由人工交互能力交付。系统内的权限模式与具体判断顺序由已接受运行架构拥有，authorization 的独立调用不以存在这些模式为前提。

结果至少区分允许、拒绝、需要决定及必要依据无法取得，精确类型归公开形状设计。拒绝原因、含义未定和依赖不可用不能被一个成功布尔值覆盖。已知明确禁止可直接拒绝，其他必要依据不可得时阻止依赖允许结论的动作，不伪造正常拒绝原因。

准入服务不可用不能通过临时审批绕开，也不能由消费者复用无条件旧允许。允许结果保留实际主体、对象、动作、参数及必要依据，缓存或跨边界使用须有明确的可信来源和有效条件。

## AU-05 人工决定、参数改写与重新核验

决定绑定原请求、实际动作、作用对象和生效参数。答复者须有当前决定资格，重复或并发答复不能变成额外许可。HITL 维护请求、交付和唯一有效答复，授权成员校验答复的适用性，不建设第二份人工工作流。

参数改写后，人看到、系统重新判断和实际执行采用的内容须一致。动作、实现、参数或影响授权的依据改变时，旧批准不能自动适用。有效答复后按当前资格重新判断，不直接绕过准入启动执行。

拒绝、明确不回答、尚未作答和失效分别保留真实含义，均不能成为批准。原工作拥有者决定收到这些结果后怎样继续或收口，授权成员不将没有答案改写成执行失败，也不因没有批准就自动重问同一问题。

依赖超时、连接断开或运行实例丢失不产生人的答复，也不能单独证明原操作终局。等待的保存、取消和终结归原操作及 HITL 契约，授权的适用与消费沿原范围判断。

## AU-06 撤权、持久记录与恢复

成员资格、角色、权限及表达变化须可供后续准入识别。消费者拥有检查时机及所要求的判断与提交一致性，authorization 提供当前可核验依据，不能用普通通知冒充共同提交。

已确认的授权表达、撤回、消费及必要决定事实按系统耐久保证保留。恢复后不能复活已消费、已撤回或失效授权。原操作终局及范围失效事实由各自拥有者提供，不因授权实例重建而消失。

撤权不代表实际执行已经停止，也不回滚外部效果。停止结果交付、资源访问和消费确认须各自满足对应资格，结果保管及实际控制由业务拥有者负责。

事实读取失败不制造撤回或终局，事实缺失也不能补造允许。恢复先认回原操作、范围、决定及消费依据，再判断可否继续。介质或整机损毁后的开放资格归 U01，不能仅用旧备份恢复的角色批准访问。

## AU-07 跨范围集成、装配与可追溯性

身份、资源及作用范围在 SDK、后台、系统任务和独立调用中均显式提供。跨进程或节点的依据须核验来源、适用对象及有效条件，不以任意可修改的租户字段作为证明。

子 Agent 权限组合、日程资格、资产创作与提升、成本账目读面分别由对应领域定义。authorization 消费其明确动作和约束，不用一般管理角色推导全部资源可读，也不将某项业务的准入模型推广到所有消费者。

组织管理员的管理资格不自动开放成员私有内容，读取诊断和对外发送分别授权。判断与治理结果记录必要的主体、范围、规则、决定和消费关联，读取及导出仍受内容和租户权限约束。

公开授权能力独立于 Cordis，系统提供者负责绑定、资源管理、替换及退出交接。提供者撤除不证明原判断或提交未发生，原调用与结果未知须有收口责任。Cordis 生命周期不替代授权记录的持久性、同提交或跨租户访问控制。

## AU-08 持久验证义务

这些是将来实现及集成须兑现的验证义务，不是已通过的证据。

| 反例 | 应检验的行为 |
| --- | --- |
| Session 外自定义资源请求授权 | 沿显式身份、动作与范围判断，不强制构造会话或工具对象 |
| 配置、批准或运行模式放宽明确禁止 | 不通过，不生成绕过请求 |
| 工作区或裸租户字段声明更高权限 | 不产生可信资格或提权 |
| 管理角色或查看资格被用于其他动作 | 仍核验该动作的实际资格 |
| 自然语言含义、动作或范围不确定 | 保留未确定，不扩成持续或系统许可 |
| 解释器或准入依据不可用 | 不假报已有允许，不用审批绕过服务 |
| 单张批准消费同批其他动作或后来批次 | 不匹配，明确整批时也只覆盖原明确动作 |
| 授权消费后重放或实例恢复 | 不增加许可次数，不复活已消费或撤回事实 |
| 表达被记录但持久设置写入失败或未知 | 不报告已形成全局效果，不静默改范围 |
| 等待期间资格、实现或参数发生变化 | 按当前资格和实际参数重判，旧批准不直接执行 |
| 同一决定从不同入口重复作答 | 一个有效决定，不增加授权 |
| 明确不回答、尚未作答或服务超时 | 保留真实区别，不产生默认批准或伪造终局 |
| 查询失败、连接断开或 disposer 被当成实际停止 | 不伪造终局、未发生或无副作用 |
| 身份判断与资源提交分离期间撤权 | 兑现原操作所要求的一致性，不用通知替代 |
| 管理员用某业务资格读取私有记录或诊断 | 该资格不自动开放其他读面 |
| 提供者替换后原提交回执丢失 | 结果保持可认回，不重建批准或盲目执行 |

纯求值、表达解释、人工交接、资源提交、跨进程来源和耐久恢复分别覆盖其保证。类型、mock、图和有限通过不能证明全部副作用可撤回、恶意代码隔离或灾后开放安全。性能尺度与真实装配验收归 T06。

## AU-09 阶段范围、公开形状与维护

0.0.0 -> 0.1.0 完整承接产品 CAP-ID09 至 CAP-ID12 的授权部分，并消费 CAP-ID01 至 CAP-ID08 的身份与治理依据。完整支持以产品能力定义为准，不由本规格中的摘要缩减。

公开形状仍须定义资源及动作接入、授权表达和解释结果、范围与操作关联、决定绑定、撤回与消费事实及可信提交查询接口。解释器、存储、并发消费、缓存、跨节点协议和共同完成机制归对应提供者及协调责任设计。

技术设计不得用接口便利补充委托、灾后恢复资格或业务生命周期。产品缺口及邻域事项见[问题登记](../../../.meta_harness/design/product/identity-and-authorization/design.md#未决问题与待定事项)，能力落点见[架构映射](../docs/architecture.md#阶段覆盖与后续细化)。改变有效行为须同步依据、公开类型、消费者和验证，技术候选、实现、验证及交付接受分别记录。

## AU-10 旅程定位与持续验证场景

本节连接 [J-ID06](../../../.meta_harness/design/product/identity-and-authorization/design.md#j-id06)、[J-ID07](../../../.meta_harness/design/product/identity-and-authorization/design.md#j-id07)、[J-ID08](../../../.meta_harness/design/product/identity-and-authorization/design.md#j-id08) 与 [F-ID06](../docs/key-flows.md#f-id06)、[F-ID07](docs/internals.md#f-id07)、[F-ID08](../../../docs/domains/identity-and-authorization/key-flows.md#f-id08)。CAP-ID09 至 CAP-ID12 的完整行为仍沿 AU-01 至 AU-09，身份事实沿 identity，不改阶段或原 AU-08 的验证义务。以下是持续验证场景，尚无本次运行证据。

<a id="v-au-j06"></a>

### V-AU-J06 显式身份及独立动作准入

交互、独立、后台和恢复入口对同类实际动作分别提供其认可的可信身份和范围，符合规则时取得准入结果。不能因没有 Session 强制伪造会话，也不能因管理员身份、对象可见或裸租户字段直接通过其他动作。请求明确禁止或未经授予跨租户访问时拒绝，必要依据不可得时阻止依赖允许的新动作。身份选择成功与动作获准分别可定位，恢复路径重新核当前资格，取消等待不报告实际访问未发生。

<a id="v-au-j07"></a>

### V-AU-J07 原决定等待、范围与消费

对可自动动作验证不强制出卡，对明确禁止验证不生成绕过审批，对需要决定的动作保留原操作、对象、生效参数及等待位置。HITL 出卡、唯一答复及原业务处理异步分段，答复回到原扩展或消费位置。分别验证批准、拒绝、明确不回答、尚未作答和失效；等待没有默认超时批准或拒绝，明确不回答交回无答案且不自动重问，连接断开或查询失败不制造答复或卡片失效。

等待期间收窄资格、改写参数或替换实现后，旧批准不能直接执行，重新判断与实际调用采用同一人可见参数。单张批准不覆盖同批其他动作，明确整批只覆盖原明确动作，各自当前准入齐备才按原流程执行获准动作。消费重放不增加次数，动作提交回执丢失先认回许可和原效果，不盲目重新执行；消费与资源提交的一致性按 T03 具体协议验收。

会话范围由会话保管，归档不自动撤回，Run 终局的单次清理不扩大许可。原等待取消及原操作确定终局时沿原控制契约处理，authorization 不另建终态。租户全局表达经写设置资格及上界核验后交资产与规则正式写入；写失败或未知不报告持久生效，也不静默改成临时授权。普通恢复认回原答复、范围、消费及写入结果，已消费许可不复活。相关记录和结果 ACK 按各自原拥有者分别取证，保留先可靠保管及先完成处理两条合法确认路径，不以答复到达或许可消费证明业务完成。

<a id="v-au-j08"></a>

### V-AU-J08 撤回、结果资格与事实恢复

对有当前资格的撤回新增撤回事实并保留原表达，后续准入按变更事实判断。无资格撤回拒绝，提交结果未知保持原身份；读取故障不伪造撤回、终局或允许。排队、人工等待及恢复路径不能无限沿用旧允许，判断与提交分离期间撤权按原操作一致性承诺验收。

分别核验撤权后的结果读取、交付和消费确认资格，停止交付不能消除生产者或合法承接者的保管责任。控制请求和物理执行结果独立记录，撤权、归档和 disposer 不证明实际执行已停止，也不回滚已发生输出。普通崩溃、重启及断电恢复后认回原操作、范围、决定和消费，已撤回或已消费事实不复活。查询与审计只读取原事实、不重做动作，私有内容和凭据不因管理角色或诊断需要泄露。介质损毁恢复开放仍依赖 U01，不能借旧快照直接允许。

公开形状、语义识别、参数记录、提交认回、跨边界来源及真实验证资源继续归 T01 至 T06。图和场景完整不表示这些机制已交付或业务已通过。
