# Dynamis

## 总体架构

Dynamis 包组回答一个问题：一个领域让别的领域拓展自己时，「现在放着什么、该用哪一份、放的东西生没生效、卸下时在途的怎样收」怎样算，才能让结果只由现在的事实决定，和装卸的先后无关。名字取自希腊语 δύναμις（潜能）：一个[拓展点](../../.meta_harness/design/ubiquitous_language/terms/architecture-core-and-extension.md#ul-extension-point--拓展点--extension-point)是一份能被贡献兑现的潜能。

本组有两个成员。`dynamis` 全部是不可变的值与值到值的函数，不依赖 Cordis、存储、时钟与随机数。`dynamis-cordis` 把它接到 Cordis 上：根入口仍是纯的，`./cordis` 入口是一个服务。

| 成员      | 回答的问题                                                                                 |
| --------- | ------------------------------------------------------------------------------------------ |
| `dynamis` | 登记表、答案、目录与规矩、引用与采用、给 agent 看的树、一次变更的影响，以及撤下、换代、底三个状态机怎样算 |
| `dynamis-cordis` | 一棵 Cordis 树上活的登记表：谁放的东西什么时候出现、什么时候消失；放一项怎样成为调用方作用域上的效应 |

`dynamis` 里一个部件一个源文件，都经根入口导出：

| 部件 | 给出什么                                                       | 依赖哪些部件     |
| ---- | -------------------------------------------------------------- | ---------------- |
| 登记表 | 带实例标签的条目的值；装上、撤下、取走                         | 无               |
| 答案 | 同键多项时怎样答的三条规则                                     | 登记表           |
| 目录 | 一个点的规矩写成数据；读一个点；一个实例放的东西生没生效       | 登记表、答案     |
| 引用 | 点名要的键怎样解析；一份定义怎样采用；采用之后怎样按钉住的取   | 目录             |
| 树   | 全部的点、键、条目排成一棵树                                   | 目录             |
| 影响 | 一次变更让哪些条目的回执变了                                   | 目录             |
| 撤下 | 一次调用钉在哪个实例上、是什么结局；排空到哪一步               | 登记表           |
| 换代 | 代数怎样发；新旧两代怎样并存                                   | 登记表           |
| 底   | 进程起来先装什么；连着倒下之后停在哪                           | 无               |

第一个消费者是客户端的[外壳契约](../frontend/SPEC.md#外壳契约)：外壳的三个位置与各界面模块的拓展点都是登记表上的点。别的领域的拓展点仍然各用各的登记表；哪个点什么时候迁上来，由那个点的拥有者另行决定。

## 领域边界

本组拥有：登记表的值与它的正规次序；同键多项的答法；一个点的规矩的形状与核法；引用的解析与采用；树的形状；一次变更的影响怎样算；撤下、换代、底三个状态机的每一格。

本组不拥有：

- 任何一个具体的拓展点。点由它的宿主声明，规矩的内容归宿主。
- 许不许用。本组只答「在不在、是哪一份」；给谁看、许不许，由宿主在用到时按资格现问。
- 宿主怎样用登记表。一个点叫什么、条目的内容与摘要怎样取、读出来怎样画，归宿主。`dynamis-cordis` 只管「一个 fiber 放的条目什么时候在登记表上」，写法照 [IC-13](../../docs/architecture/cordis-integration-conventions.md#ic-13)。
- 耐久。登记表、账、底、代数都是调用方手里的值，存不存、怎样存由调用方定。`dynamis-cordis` 的服务不存：代数只在这个进程里不重复。
- 一项内容更细的校验。本组只核字段的种类；业务上的合法性由宿主在用到这一项时自己判。
- 租户。作用域是一条不透明的路径，本组不认识它的每一段是什么。

本组不声明端口，也不实现别人的端口。

## 心智模型

把登记表想成一张摊在桌上的清单：每一行写着「谁放的、放在哪个点的哪个键下、放的是什么」。装上一个实例是把它的几行摆上去，卸下是把写着它名字的几行收走。任何问题的答案都只看桌上现在有哪些行。

最容易想错的地方：

- **撞键不是登记失败。** 同一个键下来了两份，两份都在清单上，这个键的答案是「冲突」。其中一份走了，另一份立刻生效。
- **核规矩不是进门时的一道检查。** 贡献可以先于它的宿主装上。所以合不合规矩在读的时候算：不合的那一行留在清单上，只是不生效，并带着原因。
- **引用不是每次调用现找。** 一份定义点名它要的键，采用的那一刻解析成一个实例并钉住；之后每次调用按钉住的取，那个实例不在了就答不在，不换成别的。
- **读不出不是没有。** 一个点有读不出的来源时，这个点答依据不可用。
- **本组的函数不做事。** 它们只算出下一个值。真的装载一个 fiber、真的等一次调用收场，是调用方的事。

拿它量一个设计：答案里出现了「先来的」「后来的」，错了；一个键下多于一份时某一份悄悄胜出而没有写在条目自己身上的依据，错了；点名的没有时拿别的顶上，错了；把结果未知的调用再执行一次，错了。

## 应然设计

### 登记表

- 条目由贡献方写：落在哪个点、哪个键、键内的标识、属于哪个作用域、一列里的次序、内容摘要、内容。实例标签由登记表在装上时打上。
- 实例是一个 fiber 的某一代。同一个 fiber 卸下再装上是另一个实例。一个 fiber 同时至多一代在服务。
- 一个实例有三种状态：不在、在服务、正在撤下。装上是把这个实例的条目整份定为给出的那一组，所以装同一组两次结果相同。正在撤下的实例条目仍在，答案不再看它，按钉住的取仍找得到它。取走只按实例标签。
- 登记表的值按一个只由条目自己的字段决定的次序排好。所以装着同样的实例、各放着同样条目的两张登记表，值相等。
- 输入不合法时拒绝并指出第一处：fiber 为空，代数不是正整数，点名不是「宿主.名字」，作用域里有空段，次序不是有限数，摘要为空，同一个实例里同一处放了两次。

### 答案

- 发问者带着自己的作用域，每次读都显式给出，没有缺省值：漏掉它会让一个租户范围的发问者静默地看不到自己那一层。整个部署的作用域是一个导出的常量。
- 发问者看得见的条目，是作用域为它自己的作用域前缀的那些。
- 同键、同标识、同作用域、同摘要的几份算同一项，记下全部持有者。
- 答案四种：没有；一项；冲突（列出各项）；依据不可用（带原因）。出局的条目带着原因列在答案里。
- 本组带三条规则。恰好一项：并完剩一项才答一项，多于一项答冲突。最具体的胜出：取作用域最深的，较浅的出局并写明被谁盖过；最深的那一层多于一项仍是冲突。一列：按标识分组，一组剩一项的进列，多于一项的这个标识是冲突；列按次序、标识、键排。
- 宿主的规则更细时，取出看得见的、合规矩的条目，交给自己的纯函数。本组保证交出去的次序不带到达的先后。

### 目录与规矩

- 目录是一个点，名字 `dynamis.points`，按点的名字放。一项的内容是一个点的规矩。声明一个点，就是往目录里放一项。目录自己的规矩是内建的，它的键保留。
- 规矩是数据：名字、在哪棵树上、能放几项（一项、一列、每键一项、每键一列）、键取自哪个点、键是什么、宿主给这一项什么、这一项交什么（数据、纯函数、带副作用的函数）与必有的字段及种类、同键多项怎样答、这组贡献什么时候能变（构建时或运行中）、出错时宿主怎样答、主版本、修订号、键公不公开、符合性用例在哪、一句话说明。主版本换了是另一份规矩；修订号只数同一个主版本里可加的改动，从 1 起。两者都要是正整数。修订号进声明的摘要，所以两份只差修订号的声明是内容不同的两份。树上，规矩不在 1.1 的点写明 `v<主版本>.<修订号>`。「键公开」说的是这个点现在有哪些键可以告诉另一棵树；它只关乎键，一项的内容仍不出这棵树，也不是许可：给谁看、许不许用照旧由宿主在用到时现问。必须写明是公开还是不公开，没写的声明不算数。树上，键公开的点标 `public keys`。带副作用的项撤下要排空，这一条由种类推出，不另写。
- 写「构建时」的点，贡献在应用构建时就定了。登记表不拒绝运行中放上去的条目：它不知道一个条目是什么时候放的。这件事在影响里标出来，由管理入口决定装不装。
- 一个点的状态四种：声明了；没声明；被声明了两次且内容不同；目录有读不出的来源。内容相同的两份声明算一份。不合法的声明不算数。
- 读一个点时依次判：目录读不出、没声明或声明了两次，答依据不可用；这个点有对发问者可见的读不出的来源，答依据不可用；否则逐条核规矩，不合的出局并写明缺什么。
- 一个实例放的每一项都能问到回执：生效；点不在；点被声明了两次；读不出；不合规矩；撞键；正在撤下。回执按这一项自己的作用域问。一项被更具体的作用域盖过，取决于谁在问，所以它不在回执里，在那个发问者的答案的出局者里。

### 引用

- 引用写明要哪个点上的哪几个键，先具体后一般。只有「没有」才试下一个键；冲突与依据不可用就答它。
- 采用是把一份定义的每条引用各解析成恰好一项并钉住：点、键、标识、作用域、摘要、实例。有一条解析不成，整份不可用，并列出每一条缺的是什么。写了可选的引用，没有时记空。
- 采用之后按钉住的取：六样全对得上才答在，并写明那个实例在服务还是正在撤下；否则答不在。同内容有几个持有者时，钉在正规次序里最前的那个实例上。
- 给出一份采用与一个实例，能答这份采用的哪些槽位钉在它上面。

### 树

- 树上的节点交替是点、键、条目。一个条目的父是它所在的点下的键。一个点的父，在它的键取自另一个点时是那个点的键，否则是它的宿主。宿主按它所在的树分在服务端与客户端两边。
- 每个节点有一条唯一的路径。
- 键的来历成环、或取自一个没声明的点的，不上树，列在问题里。放了东西而点没声明的、被声明了两次的点，也列在问题里。
- 读不出的点在树上，写明读不出，不列它自己的条目；键取自它的点照常挂在它的键下。
- 条目节点上写着它的回执。贡献只在构建时定的点，节点上写明。正在撤下的实例放的不上树。树按发问者的作用域算。

### 影响

- 影响比较两张登记表：变更之前的，和变更之后的。它给出回执变了的每一个条目：新出现的、没了的、状态或原因变了的，各带前后的状态。它不改任何一张。
- 装上、卸下、撤下、换代的预演是同一种做法：先用登记表的纯操作算出之后的那一张，再问影响。
- 新出现在「构建时」的点上的条目，在影响里标成来晚了。
- 保护在位的一份靠它：装上一份撞键的东西，会让在位的那一份从生效变成撞键，这一条在影响里看得见。装不装由管理入口定；登记表的答法不因此看先后。

### 给 agent 读登记表的工具

agent 经只读工具 `OmneExtensionPoints` 看登记表。它在 plugin 包组的成员 `plugin-tools` 里，规则归 [plugin 的规格](../plugin/SPEC.md#给-agent-的工具看拓展树)。依赖只朝本组：工具导入本组的树、回执、可见性与影响，本组不认识它，也不为它加部件。

- 它读三样：服务端那棵树此刻的登记表；这个租户连着的客户端各自报上来的点与部位；登记表的修订。一个点的规矩与条目的回执按本组的答法算，两张登记表之间变了什么按本组的影响算。
- 它只读：不放、不撤、不改任何一项。
- 发问者的作用域由工具的绑定按行事的租户给出，模型给不了。它列出的条目与变化只是这个作用域看得见的。

### 撤下

- 受理一次调用时把它钉在一个在服务的实例上。正在撤下的不接新的，不在的答不在。同一个调用标识再来：钉的是同一个实例就认回，否则拒绝。
- 一次调用的结局只有三种：在跑、完成、未知。完成之后不再改。实例突然没了，它名下在跑的变未知。未知的只凭「效果已经耐久记下」认回成完成；没有记下的保持未知，不重做。
- 撤完一个实例的条件：它正在撤下，而且名下没有在跑的。
- 账上完成的调用可以清掉；在跑的与未知的留着。

### 换代

- 代数由调用方手里的一个值发出，每个 fiber 从 1 起只增不减。这个值要耐久：代数重用会让一条旧的绑定认到新装上的实例上。
- 换代是一步：旧的一代变正在撤下，新的一代装上。两代的 fiber 相同、新的代更大、旧的在服务，才成立。新一代的条目不合法时整步不成立，旧的仍在服务。

### 底

- 底的值记四样：进程在不在，要装的，装上的，上一次稳定之后连着倒了几次。
- 起来只起底，装上的为空。补装把装上的变成要装的；连倒的次数到了上限就不再补装，等人或 agent 处理之后放开。倒下清空装上的，次数加一。稳定之后次数清零。
- 改要装的只在进程起着的时候做：加一份，它同时算装上；去掉一份，它同时卸下。
- 管理入口属于底，不在「要装的」里。这一条由调用方守，依据见形式化件。

### 接到 Cordis 上（`dynamis-cordis`）

| 入口 | 内容 | 依赖 |
| --- | --- | --- |
| `.` | 座位的状态机：`noSeats`、`put`、`drop`、`ready`、`gone`、`drained`、`instanceFor`、`leaving` | 只有 `dynamis` |
| `./cordis` | 服务 `DynamisService`（键 `dynamis`）、拒绝的错误 `DynamisRefused`、键常量 `dynamisKey` | Cordis、`dynamis` |

- 一个 fiber 的一次激活是一个实例。依赖没了又回来，同一个 fiber 重跑一遍 `apply`，是新的一代。
- 一个活的 fiber 在服务里有一个活的座位。活的座位有两种状态：备着（fiber 还没就绪）、在位（fiber 就绪）。登记表上在服务的只有在位的座位放的条目。
- 放一批时可以写明「这一批离开时要排空」：它交的是带副作用的函数，离开不能立刻取走。带这种批的在位座位，fiber 离开时变成第三种状态：撤下中。它的实例在登记表上正在撤下（`retire`），条目还在，答案不再看它；它要排空的批都报了排空完，实例才取走。只交数据与纯函数的批不写这一句，离开时立刻取走，和以前一样。
- 撤下中的座位不再属于哪个活的 fiber：前四个操作都按 fiber 找活的座位，只有「排空完」按批找到它。所以同一个 fiber 在旧的一代撤下中时再放一批，开的是一个新的活座位。

  | 操作 \ 状态 | 没有活的座位 | 备着 | 在位 | 撤下中（按批找到的） |
  | --- | --- | --- | --- | --- |
  | 放一批，合法 | 占一个名字，发新的一代，备着 | 加进备着的 | 加进去，整份重装 | 不归它：这一批进这个 fiber 的活座位，没有就新开 |
  | 放一批，不合法，或这个实例已经占着其中一处 | 拒绝，什么都不变 | 拒绝 | 拒绝 | 拒绝 |
  | 撤一批 | 什么都不做 | 去掉这一批；一批都不剩就没有座位 | 去掉这一批，剩下的重装；一批都不剩就取走实例。这一批名下在途的由宿主自己等 | 什么都不做：这一批留到排空完 |
  | 就绪 | 什么都不做 | 整份装上，在位 | 什么都不做 | 什么都不做 |
  | 离开 | 什么都不做 | 丢掉备着的：它没有服务过，不用排空 | 有要排空的批：实例正在撤下，座位撤下中。没有：取走实例 | 什么都不做 |
  | 一批排空完 | 什么都不做 | 什么都不做 | 什么都不做：它还在服务 | 记下这一批排空了；要排空的批都排空了，取走实例，没有座位 |

- 合不合法取登记表 `install` 的判法，不另写一套。拒绝带原因：`invalid`（这一批自己不合法），或 `held`（这个实例已经占着其中一处）。
- 名字取调用方的插件名。两个活着的 fiber 同名时，后占的加后缀（`session-ui~2`）；先占的走了，名字空出来。撤下中的座位不占名字：同名的新一代可以在旧一代排空的时候装上，登记表只拒绝「另一代在服务」，不拒绝「另一代正在撤下」。后缀看谁先占，答案的内容不看名字。代数按名字只增。
- 服务的 `put(条目)` 先用状态机算出结果，被拒绝就抛 `DynamisRefused`，不留效应；合法才登记成调用方 fiber 上的效应，返回撤这一批的函数。调用方已经就绪时，这一批直接在位。条目可以写成实例的函数：放之前就问得出自己是谁的哪一代（`instanceFor`）。`put(条目, { drain })` 写明这一批要排空：`drain(实例)` 在这个实例开始撤下之后被调一次，返回的 Promise 完成就是这一批排空完。效应的撤除函数返回这个 Promise，所以调用方 fiber 的卸载等它。`drain` 失败时实例照样取走，失败交给等卸载的一方：登记表不留一个永远撤不完的实例。`drain` 没有返回 Promise 而是当场抛出，算同一种失败。
- 服务监听 Cordis 的 `internal/status`：fiber 到 `ACTIVE` 时就绪，到 `UNLOADING` 时离开。效应的撤除是兜底。所以 `apply` 里放的几批在 fiber 就绪时一起出现，`apply` 抛错的 fiber 放的从不出现，卸载时一起不再被答案看到。
- 登记表的值变了，服务发事件 `dynamis-cordis/changed`（`parallel`，载荷是变化之后的登记表）。备着的座位怎样变都不发。用 `parallel` 不用 `emit`：`emit` 遇到一个监听者抛错就不再调后面的，一个坏监听者会让别人收不到这次变化；`parallel` 在调用的那一刻同步、按次序调每一个，各自的错互不相挡。监听者抛错只记一条诊断，登记表已经更新。
- 它站在 Cordis 文档没写的三条行为上：`apply` 里登记的效应先于就绪的状态事件；开始卸载的状态事件先于效应被撤，`apply` 抛错时也是；依赖丢了再回来是同一个 fiber 对象重跑。三条各有一份探针用例在 `packages/assembly/kernel-basis/tests`，Cordis 升版时由它们守。`parallel` 同步调每个监听者这一条也有一份探针。

## 原则与约束

- `dynamis` 与 `dynamis-cordis` 的根入口：每个导出是值，或值到值的函数。不读时钟，不取随机数，不保存模块级的可变状态。
- 这两个入口里拒绝是返回值，不抛出。每个操作在每个状态下都有确定的答复。`dynamis-cordis` 的服务是唯一持有可变状态的地方：一个座位的值。它的 `put` 被拒绝时抛 `DynamisRefused`，因为调用方在自己的 `apply` 里，抛出才能让这个模块的加载失败。
- 次序只认条目自己带的：次序号、标识、键、作用域、摘要、实例标签。
- `dynamis` 的包清单没有运行时依赖。`dynamis-cordis` 只依赖 `dynamis` 与 Cordis。本组的成员都不依赖任何领域，也不导入 Node 内建模块，由依赖规则 `mechanism-knows-no-domain` 守：服务端入口、外壳契约、客户端装配可以依赖本组，靠的就是这一条。
- 要给本组加一个部件，先说明它回答哪个独立的问题，再改这份规格。
- 和通则的关系：[拓展点的共同契约](../../docs/architecture/cross-cutting-concepts.md#拓展点的共同契约)的第一条通则就是本组的答法：两份都在，这个键答冲突，不看先后。「后来的不弄坏在位的」由安装这个操作来守：装之前先算影响。还没迁上来的点在共同契约的表里记成偏离。
