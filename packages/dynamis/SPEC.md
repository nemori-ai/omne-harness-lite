# Dynamis

## 总体架构

Dynamis 包组回答一个问题：一个领域让别的领域拓展自己时，「现在放着什么、该用哪一份、放的东西生没生效、卸下时在途的怎样收」怎样算，才能让结果只由现在的事实决定，和装卸的先后无关。名字取自希腊语 δύναμις（潜能）：一个[拓展点](../../.meta_harness/design/ubiquitous_language/terms/architecture-core-and-extension.md#ul-extension-point--拓展点--extension-point)是一份能被贡献兑现的潜能。

本组只有一个成员，全部是不可变的值与值到值的函数。它不依赖 Cordis、存储、时钟与随机数。

| 成员      | 回答的问题                                                                                 |
| --------- | ------------------------------------------------------------------------------------------ |
| `dynamis` | 登记表、答案、目录与规矩、引用与采用、给 agent 看的树，以及撤下、换代、底三个状态机怎样算 |

成员里一个部件一个源文件，都经根入口导出：

| 部件 | 给出什么                                                       | 依赖哪些部件     |
| ---- | -------------------------------------------------------------- | ---------------- |
| 登记表 | 带实例标签的条目的值；装上、撤下、取走                         | 无               |
| 答案 | 同键多项时怎样答的三条规则                                     | 登记表           |
| 目录 | 一个点的规矩写成数据；读一个点；一个实例放的东西生没生效       | 登记表、答案     |
| 引用 | 点名要的键怎样解析；一份定义怎样采用；采用之后怎样按钉住的取   | 目录             |
| 树   | 全部的点、键、条目排成一棵树                                   | 目录             |
| 撤下 | 一次调用钉在哪个实例上、是什么结局；排空到哪一步               | 登记表           |
| 换代 | 代数怎样发；新旧两代怎样并存                                   | 登记表           |
| 底   | 进程起来先装什么；连着倒下之后停在哪                           | 无               |

本组现在没有消费者。现有各领域的拓展点仍然各用各的登记表；哪个点什么时候迁上来，由那个点的拥有者另行决定。

## 领域边界

本组拥有：登记表的值与它的正规次序；同键多项的答法；一个点的规矩的形状与核法；引用的解析与采用；树的形状；撤下、换代、底三个状态机的每一格。

本组不拥有：

- 任何一个具体的拓展点。点由它的宿主声明，规矩的内容归宿主。
- 许不许用。本组只答「在不在、是哪一份」；给谁看、许不许，由宿主在用到时按资格现问。
- Cordis 上的登记。把一次放入登记成调用者作用域上的效应归宿主与 [IC-13](../../docs/architecture/cordis-integration-conventions.md#ic-13)。
- 耐久。登记表、账、底、代数都是调用方手里的值，存不存、怎样存由调用方定。
- 一项内容更细的校验。本组只核字段的种类；业务上的合法性由宿主在用到这一项时自己判。
- 租户。作用域是一条不透明的路径，本组不认识它的每一段是什么。

本组不声明端口，也不实现别人的端口。

## 心智模型

把登记表想成一张摊在桌上的清单：每一行写着「谁放的、放在哪个点的哪个键下、放的是什么」。装上一个实例是把它的几行摆上去，卸下是把写着它名字的几行收走。任何问题的答案都只看桌上现在有哪些行。

最容易想错的地方：

- **撞键不是登记失败。** 同一个键下来了两份，两份都在清单上，这个键的答案是「冲突」。其中一份走了，另一份立刻生效。
- **核规矩不是进门时的一道检查。** 贡献可以先于它的宿主装上。所以合不合规矩在读的时候算：不合的那一行留在清单上，只是不生效，并带着原因。
- **引用不是每次调用现找。** 一份定义点名它要的键，采用的那一刻解析成一个实例并钉住；之后每次调用按钉住的取，那个实例不在了就答不在，不换成别的。
- **读不出不是没有。** 一个点有读不出的来源时，这个点答依据不可用。
- **本组的函数不做事。** 它们只算出下一个值。真的装载一个 fiber、真的等一次调用收场，是调用方的事。

拿它量一个设计：答案里出现了「先来的」「后来的」，错了；一个键下多于一份时某一份悄悄胜出而没有写在条目自己身上的依据，错了；点名的没有时拿别的顶上，错了；把结果未知的调用再执行一次，错了。

## 应然设计

### 登记表

- 条目由贡献方写：落在哪个点、哪个键、键内的标识、属于哪个作用域、一列里的次序、内容摘要、内容。实例标签由登记表在装上时打上。
- 实例是一个 fiber 的某一代。同一个 fiber 卸下再装上是另一个实例。一个 fiber 同时至多一代在服务。
- 一个实例有三种状态：不在、在服务、正在撤下。装上是把这个实例的条目整份定为给出的那一组，所以装同一组两次结果相同。正在撤下的实例条目仍在，答案不再看它，按钉住的取仍找得到它。取走只按实例标签。
- 登记表的值按一个只由条目自己的字段决定的次序排好。所以装着同样的实例、各放着同样条目的两张登记表，值相等。
- 输入不合法时拒绝并指出第一处：fiber 为空，代数不是正整数，点名不是「宿主.名字」，作用域里有空段，次序不是有限数，摘要为空，同一个实例里同一处放了两次。

### 答案

- 发问者带着自己的作用域。它看得见的条目，是作用域为它自己的作用域前缀的那些。
- 同键、同标识、同作用域、同摘要的几份算同一项，记下全部持有者。
- 答案四种：没有；一项；冲突（列出各项）；依据不可用（带原因）。出局的条目带着原因列在答案里。
- 本组带三条规则。恰好一项：并完剩一项才答一项，多于一项答冲突。最具体的胜出：取作用域最深的，较浅的出局并写明被谁盖过；最深的那一层多于一项仍是冲突。一列：按标识分组，一组剩一项的进列，多于一项的这个标识是冲突；列按次序、标识、键排。
- 宿主的规则更细时，取出看得见的、合规矩的条目，交给自己的纯函数。本组保证交出去的次序不带到达的先后。

### 目录与规矩

- 目录是一个点，名字 `dynamis.points`，按点的名字放。一项的内容是一个点的规矩。声明一个点，就是往目录里放一项。目录自己的规矩是内建的，它的键保留。
- 规矩是数据：名字、在哪棵树上、能放几项（一项、一列、每键一项、每键一列）、键取自哪个点、键是什么、宿主给这一项什么、这一项交什么（数据、纯函数、带副作用的函数）与必有的字段及种类、同键多项怎样答、出错时宿主怎样答、主版本、符合性用例在哪、一句话说明。带副作用的项撤下要排空，这一条由种类推出，不另写。
- 一个点的状态四种：声明了；没声明；被声明了两次且内容不同；目录有读不出的来源。内容相同的两份声明算一份。不合法的声明不算数。
- 读一个点时依次判：目录读不出、没声明或声明了两次，答依据不可用；这个点有对发问者可见的读不出的来源，答依据不可用；否则逐条核规矩，不合的出局并写明缺什么。
- 一个实例放的每一项都能问到回执：生效；点不在；点被声明了两次；读不出；不合规矩；撞键；正在撤下。回执按这一项自己的作用域问。一项被更具体的作用域盖过，取决于谁在问，所以它不在回执里，在那个发问者的答案的出局者里。

### 引用

- 引用写明要哪个点上的哪几个键，先具体后一般。只有「没有」才试下一个键；冲突与依据不可用就答它。
- 采用是把一份定义的每条引用各解析成恰好一项并钉住：点、键、标识、摘要、实例。有一条解析不成，整份不可用，并列出每一条缺的是什么。写了可选的引用，没有时记空。
- 采用之后按钉住的取：五样全对得上才答在，并写明那个实例在服务还是正在撤下；否则答不在。
- 给出一份采用与一个实例，能答这份采用的哪些槽位钉在它上面。

### 树

- 树上的节点交替是点、键、条目。一个条目的父是它所在的点下的键。一个点的父，在它的键取自另一个点时是那个点的键，否则是它的宿主。宿主按它所在的树分在服务端与客户端两边。
- 每个节点有一条唯一的路径。
- 键的来历成环、或取自一个没声明的点的，不上树，列在问题里。放了东西而点没声明的，也列在问题里。

### 撤下

- 受理一次调用时把它钉在一个在服务的实例上。正在撤下的不接新的，不在的答不在。同一个调用标识再来：钉的是同一个实例就认回，否则拒绝。
- 一次调用的结局只有三种：在跑、完成、未知。完成之后不再改。实例突然没了，它名下在跑的变未知。未知的只凭「效果已经耐久记下」认回成完成；没有记下的保持未知，不重做。
- 撤完一个实例的条件：它正在撤下，而且名下没有在跑的。

### 换代

- 代数由调用方手里的一个值发出，每个 fiber 从 1 起只增不减。这个值要耐久：代数重用会让一条旧的绑定认到新装上的实例上。
- 换代是一步：旧的一代变正在撤下，新的一代装上。两代的 fiber 相同、新的代更大、旧的在服务，才成立。

### 底

- 底的值记四样：进程在不在，要装的，装上的，上一次稳定之后连着倒了几次。
- 起来只起底，装上的为空。补装把装上的变成要装的；连倒的次数到了上限就不再补装，等人或 agent 处理之后放开。倒下清空装上的，次数加一。稳定之后次数清零。
- 改要装的只在进程起着的时候做。
- 管理入口属于底，不在「要装的」里。这一条由调用方守，依据见形式化件。

## 原则与约束

- 每个导出是值，或值到值的函数。不读时钟，不取随机数，不保存模块级的可变状态。
- 拒绝是返回值，不抛出。每个操作在每个状态下都有确定的答复。
- 次序只认条目自己带的：次序号、标识、键、作用域、摘要、实例标签。
- 包清单没有运行时依赖。
- 要给本组加一个部件，先说明它回答哪个独立的问题，再改这份规格。
- 和现行通则的关系：[拓展点的共同契约](../../docs/architecture/cross-cutting-concepts.md#拓展点的共同契约)写「冲突不静默：登记失败并报出来，不覆盖已有的一项」。本组的答法是两份都在、这个键答冲突。两者都不静默，都不覆盖；差别在后到的一份是登记失败还是留在清单上。现有的拓展点都没有用本组，所以现在没有冲突。一个点迁上来之前，由共同契约的拥有者裁定它用哪一种。

## 不变式

| 编号  | 永远成立的性质                                                                                 | 违反的后果                               | 由什么守                                                     |
| ----- | ---------------------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------ |
| DY-1  | 登记表的值只由现在装着哪些实例、各放了什么决定，与装卸的先后无关                               | 同一组东西装出两个不同的系统             | `order.spec.ts`；模型 Points 的 `Functional`、`Canonical`    |
| DY-2  | 取走一个实例只动带它标签的条目                                                                 | 误删别人的，或自己新一代的贡献           | `registry.spec.ts`；模型 Points 的 `Exact`                   |
| DY-3  | 一个 fiber 同时至多一代在服务                                                                  | 新旧两代在同一个键上互相撞               | `registry.spec.ts`、`rollout.spec.ts`；模型 Points 的 `OneInstance` |
| DY-4  | 同键多项的答案是确定的：同内容并成一项，再按规则答一项或冲突；没有哪一份因为先到而胜出         | 后到的起不来，先到的走了也回不来         | `answer.spec.ts`、`order.spec.ts`                            |
| DY-5  | 读不出、没声明、声明了两次，都答依据不可用，不答成没有                                         | 把依据不可用当成空，能力悄悄少了         | `catalog.spec.ts`                                            |
| DY-6  | 不合规矩的条目不生效，这个结果与装的先后无关                                                   | 贡献先装宿主后装时，不合规矩的留下并生效 | `catalog.spec.ts`、`order.spec.ts`                           |
| DY-7  | 采用只绑到点名过的键上的恰好一项；点名的没有时整份不可用，不找替代                             | 一份定义用上它没点名的实现               | `reference.spec.ts`；模型 Adopt 的 `OnlyNamed`               |
| DY-8  | 采用之后按钉住的取；钉住的实例不在了答不在                                                     | 一轮跑到一半换了实现或换了代             | `reference.spec.ts`、`adopt-walk.spec.ts`；模型 Adopt 的 `Pinned` |
| DY-9  | 一次调用只钉在一个实例上；正在撤下的不接新的；名下还有在跑的不算撤完                           | 孤儿调用，或一次调用在两个实例上执行     | `withdraw.spec.ts`、`withdraw-walk.spec.ts`；模型 Withdraw 的 `Pinned`、`NoOrphan`、`NoLateAdmit` |
| DY-10 | 完成的结局不改写；未知的只凭已耐久的记录认回，否则保持未知                                     | 把未知写成成功，或把一件事做两遍         | `withdraw.spec.ts`、`withdraw-walk.spec.ts`；模型 Withdraw 的每步断言 |
| DY-11 | 进程倒着的时候没有装上的；起来之后装上的为空；连倒的次数到上限就不再补装                       | 一份坏的贡献让进程永远起不来             | `floor.spec.ts`、`floor-walk.spec.ts`；模型 SelfHost 的 `DownIsEmpty`、`FloorHolds` |
| DY-12 | 发出的代数每个 fiber 只增不减，从不重复                                                        | 旧的绑定认到新的实例上                   | `rollout.spec.ts`                                            |
| DY-13 | 树上每个点恰有一个父，每个节点的路径唯一；键的来历成环的点不上树并被列出                       | 给 agent 看的不是一棵树                  | `tree.spec.ts`                                               |
| DY-14 | 源码只导入本成员自己的文件，不读时钟与随机数；根入口的导出名固定                               | 不能离开这套系统单独用、单独测           | `purity.spec.ts`、`public-entry.spec.ts`；包清单没有依赖     |

形式化件在 `dynamis/verification`：四个模型与它们各自的正控、负控，性质与实现、用例的对应见那里的 [formal-mapping.md](dynamis/verification/formal-mapping.md)。模型是有限的小世界，不是源码符合性的证明。
