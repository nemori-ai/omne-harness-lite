# model/model 长期行为规格

状态：原调用身份与受理、执行与观察边界、取消及恢复、结果保管和双路径 ACK已由[技术接受](https://github.com/nemori-ai/omne-harness-lite/issues/262#issuecomment-6186972289)采用，是本卡范围的现行协作契约。本页及所引专题中上述范围的采用状态以此处和接受记录为准。其余专有候选及明确未定的机制保留原状态；设计接受不表示生产实现或运行验证已完成。

本页和所引专题共同承载必要的非类型行为，不授予公开 API、实现或验证接受。

## 能力与契约拥有者

本成员提供模型档案和模态能力依据、完整请求执行、原结果查询与保管、控制、ACK、清理和实际费用事实。共同契约供全部模型提供者及消费者使用。独立消费以显式依赖满足存储、秘密取得及授权前提，无须启动 Cordis、Session 或 Agent Loop。

本页维护调用执行。档案与转换行为在[档案与模态专题](docs/profile-and-modality.md)，ACK、清理及成本行为在[结果承接专题](docs/consumption-and-cost.md)。这些专题是本规格的组成部分，不能只读本页就声称完成符合性。

Session 拥有工作身份、有效推进和选择事实，request-context 拥有派生输入及预算，Agent 拥有 Loop 和扩展位置，tool 拥有真正工具执行。模型只返回工具建议，不执行。类型、配置键、服务定义及注册 API 由后续公开设计拥有，本规格不重复猜字段。

## 请求资格、身份与固定输入

1. 发起者提供合法主体与租户范围、稳定调用身份、用途、当前消费者和原消费位置。会话路径在存在时关联 Session、Run 和发起 attempt；Run 外及独立路径不造 Run 或 attempt。
2. 实际采用档案、参数、系统提示词、组装内容、工具声明和访问依据须可解释或准确还原。临时句柄不能替代调用身份，当前档案不能覆盖原采用值。
3. 发出前固定合法最终输入，校验适用限额、模态、凭据、操作资格、接收方和数据传送目的。最终校验不能省掉模型前扩展改写后的复核，也不能再次执行同次扩展。
4. 参数由统一含义交适配器处理。上游不支持某项时明确留下不支持及实际采用情况，不能静默丢弃、假称已应用或私自改到另一档案。精确参数集合和不支持时的接口结果须由参数拥有者设计。
5. 首内容前重试仍须满足本次真实接收方和当前授权条件。原请求快照不是后续供应商外传的永久许可；资格失效时不能以恢复为由取得旧权力。
6. 缺必要来源、限额、计量或凭据时，说明具体失败且不发。读取暂时不可用与不存在分开。提交结果未知保留原身份核实，不能换新调用掩盖不确定。

不得借档案不是资产而取消主体、秘密、外传和读取检查，也不得另造按账号、Run 或单次调用颁发的模型执行许可。共同设置规则仍由 assets 维护。

## 调用和各次真实发出

逻辑调用有稳定身份及最终完成、失败或被中断的结局。每次真实发出单独辨认，以档案允许的单个供应商处理。供应商变更或同家重发都是新发出，不是修改旧记录。未发出失败与已经发出的拒绝分别保存。

进入会话日志的跨边界事实是未发出就失败、真实收场、停止尚未回报，以及消费侧已保存结果。每次重试、首内容边界、容量预留、在途块和费用金额留在本成员。记入标准见[必须进入日志的事实](../../../docs/architecture/runtime/session-and-run.md#必须进入日志的事实)。

受理的最小对接是现行规则。租户身份是参数。缺租户或跨租户默认拒绝。结果确认的前提见[ACK](docs/consumption-and-cost.md#ack-的前提与效果)。样例见 [F-SW03](../../session/session/docs/key-flows.md#f-sw03) 和[双路径 ACK](docs/key-flows.md#flow-md05)。

| 项 | 规则 |
| --- | --- |
| 关联身份 | 登记时生成的调用身份。 |
| 必要参数 | 租户、调用身份、这次固定采用、结果容量上界。 |
| 成功 | 受理和结果容量预留在同一事务里成立。此后才算已经发出。 |
| 拒绝 | 资格、限额或容量不成立。不算已经发出。 |
| 未知 | 按原调用身份对账。不换身份再发。 |
| 同身份重试 | 同一调用身份和同一固定采用返回原受理。 |
| 参数冲突 | 同一调用身份配上不同的固定采用则拒绝。 |

每次发出的实际供应商、原参数采用、时刻、首内容观察、原状态码、结束原因及费用依据须可追溯。失败记录不被成功覆盖，未知费用不填零。重试和多观察者不得重复登记同一笔真实用量；两次真实发出可能各有费用。

调用终局不反转；终局后可以补账及必要事实，不恢复原执行。后续消费否决、上层失败或 Run 结束不改实际模型结局。完整回复没成为消息时，记录原回复和否决责任；Loop 再试须另立新调用身份。

## 流式和首内容

开块、填充、封块、截断提醒、实际用量登记和流收场表达到达及事实，不成为 Run 状态；本规格不据此定义 open、fill、close、trim、account、finish 的接口词表。

块打开时固定追加片段或整体替换模式，不在同块途中换方式。整体替换仅更新该块，不覆盖其他块及历史。封块交完整内容，分次到达与一次取得的有效结果一致。

可增长的文字、思考、工具参数及语音，以首片实际内容作为首 token。图片和文件等整交块以完整交付作为首 token。响应头、心跳、空开块及单纯状态通知都不算。不能只识别文本，从而重发已交语音或工具参数的回复。无权取得或上游未提供的思考内容不补造。

新观察者先取当前在途快照，再取后续增量。快照不是完整增量史，不表示已收场或已消费。未收齐工具参数不得作为执行指令。模型完成后，工具建议仍须经过实际动作准入及工具契约。

输出限额正常截断按真实完成和相应提醒处理。上游故障、中断或自身失联按真实原因收场。已交部分按其有效保留规则处理，不能伪造完整消息；工具执行及用户消息格式归原拥有者。

已展示在途内容可追溯义务有效，但确切分段保存、故障可恢复表示和展示前后的确认协议尚待对齐。当前不得宣布此范围允许丢失，也不得声称最终 ACK 足以证明逐片耐久。

## 重试与策略

| 条件 | 必须行为 |
| --- | --- |
| 本地请求、授权或凭据明确无效 | 不反复发同样无效请求，给原消费者具体原因。 |
| 上游明确拒凭据、无效请求或不接受内容 | 留实际发出事实及状态，不让策略推翻禁止同输入重试的边界。 |
| 首内容前可重试上游失败或空回复 | 由有效策略按档案声明及实际失败决定继续或收场。 |
| 首内容后故障 | 不重新发同一逻辑回复，记录故障与实际已交内容。 |
| 明确用户中断 | 走控制结局，不作为策略故障重新尝试。 |
| 输入限额或适用表示不满足 | 交发起与组装协调者，不私删内容或换路由。 |

默认策略始终有明确采用来源。允许回退时按供应商声明次序逐家至多一次；不允许回退时原供应商退避后至多再试一次。策略替换不得突破允许供应商、回退声明、首内容后不重发及真实成本保留。具体退避数值及状态码映射不在本规格补定。

策略读取原状态码、失败成因、档案声明和已尝试情况，决定再试或不再试并留下可接续依据。一次发出失败而整调用仍等待策略时，不能向外报整调用终局或允许最终 ACK。首内容前可重试发出结束后，由原调用沿既有模型后失败分支取得策略，触发不等待整项调用终局。策略结论回原 Model，继续发出或形成真实终局；主 Loop 仍等待该调用，不提前消费结果或 ACK，也不另造 Run、Agent attempt 或逻辑调用。最终失败处理不再次送回策略复活终局，策略执行不依赖原 Agent 实例持续存活。精确调度、适配和持久决定协议另待，不新增 Loop 位置；只观察扩展不能改重试决定，系统策略不可用时不再重试并记录不可用。

独立调用消费同样有效策略，不创建隐式 Session 或要求原 Agent 一直活着。独立策略适配、决策持久化与通知方式留给技术设计，不能借此退回全部不重试或发出多份逻辑回复。

内部失败的尝试属于诊断和费用事实，不直接作为模型可读消息或改变 Agent 下一步。只有真实收场后的适用交接影响原消费者。按失败成因和原状态码分别表示，不用原状态码替代业务成因，也不把本地保存失败伪报供应商不可达。

## 故障交接

首内容前整调用结束失败时，会话主路径交 Run 的运行处置位置；首内容后部分结果和相应提醒交 Agent 的原步骤，提醒即该次中断交接，不重复另立同义事实。压缩、扩展、Run 外及独立用途回各自原位置。

明确区分已下架、被范围配置排除、模态不兼容、凭据不可用、上游不接受此次内容、暂时给不出回复、首内容后断流和确实未认出的原因。未知原因带可追查依据，不用兜底掩盖可识别原因。故障形态不作封闭穷举，精确映射及错误类型随提供者与公共契约确定。

被用户中断不带上游故障成因。输出限额完成不记同一层故障。原调用正常收场但消息前被否决时，消费方自行记录谁否决及后果，模型不篡改为调用失败，也不把新调用算作自己的供应商重试。

## 控制、取消与晚到事实

控制以原调用身份定位，记录到达、受理、传播及实际结果。取消关系不能只靠临时连接。取消等待不证明上游已停止或提交已回滚，适用流取消也不要求关闭全部共享连接。

单独模型中断不自动取消 Tool 或整个 Run；不执行被中断响应里尚未发出的工具建议。Run 取消只控制其关联调用，不涉及无关 Run 外调用；Session 归档按逻辑治理取消该 Session 全部未完成模型调用，不等待物理全停。

目标调用的中断或业务取消生效后，不为这个已取消调用追加真实发出；原 Run 是否继续由治理和原消费者决定。独立执行仍可能迟到完成，模型保存真实结果和费用，当前业务消费者不得借迟到事实恢复已取消的工作或自动创建后继 Run。撤销归档不使旧调用恢复资格。能否用原材料发起新的明确工作归其产品准入，不由 Model 偷选。

归档业务取消与上游真实停止分别记录。上游实际完成不能被改报未发出或物理中断，业务不再采用也不能当作没有成本。清理仍须满足结果责任交接及实际读取条件。

## 换代、恢复和耐久

Agent 或最后一个句柄消失时，模型继续原执行、输出、收场和记账。合法接手者核对当前访问、原身份、用途和消费状态，不修改原输入。仍运行就等原调用，完成且未 ACK 就承接原结果，已 ACK 就查询确认及清理并从消费方位置继续。

状态查询暂时不可用保持未知，不能推断自身失联、报告已结束或重新发出。只有可信地确认 Model runtime 自身失去连续性，才应用首内容前后规则。首内容前可按原消费位置恢复重发，保留原调用与新真实发出；首内容后记录运行时失联，不重发。失联判据尚待技术设计。

恢复时不从当前档案或最新配置重写原采用。原工作资格失效、取消或归档时，不恢复原业务推进。原调用未知提交先核实，而不是从缺消息反推出未发出。

公开持久确认须晚于所需调用、结果、承接、授权及账目事实达到耐久边界。进程崩溃、操作系统崩溃及断电后仍可读取解释。引用的模态内容及其必要保留时间满足同一承诺，临时文件地址不能当可靠唯一副本。介质损毁及灾后资格另行设计，不自动引入恢复管理员或全量人工审批。

## 观测、资源与验证

观测关联原租户、调用、各次真实发出、适用消费者与存在时的业务工作。模型 TTFT 与入口到首输出分开，真实发出、排队、组装、转换、重试和清理分别定位。不伪造上游用量、不把诊断采样当完整账目。

连接、读写、在途快照、等待、保管和清理都有资源边界，不能因无人读结果或某个清理故障拖垮其他调用。具体限额与调度尚待设计；不得丢掉未承接责任来达成低占用。故障降级仍按原规则报告未知或失败，不换接收方、不改权限、不产生无法说明的额外请求。

持续验证至少覆盖下列反例。相应流程入口见[能力旅程对应表](#能力旅程与持续验证入口)。

| 场景 | 需观察的保证 |
| --- | --- |
| 同名最具体档案缺凭据或模态不符 | 不暗退外层；列表与失败原因一致。 |
| 输入缺上限、计量依据或扩展后超限 | 无真实发出；保持历史、选择及原件。 |
| 只有响应头或图片开块后故障 | 未越首内容界，按策略决定。 |
| 首片工具参数、语音或整图到达后故障 | 不再发同一逻辑回复，不执行半截参数。 |
| 两次失败后成功 | 每次发出和费用真实，失败不被覆盖。 |
| Agent 退出但原 Model 仍运行 | 接续原身份，不重发或自动中断。 |
| 状态查询断开 | 未知保持未知，不按失联重试。 |
| 自身失联发生在首内容前后 | 分别允许恢复重发或收失联，不暗混。 |
| 正常回复被消息前扩展否决 | 原调用终局不改，新调用有新身份。 |
| 归档、撤销归档后迟到响应 | 原事实保留，旧工作不复活、不自动派后继 Run。 |
| 独立调用遇重试、取消和 ACK | 无隐式 Session、Run 或 attempt。 |
| 普通崩溃及断电发生在已确认保存后 | 原身份及事实耐久，确认丢失可核实。 |

档案、转换和输入边界的验证义务继续见[档案专题](docs/profile-and-modality.md)，交接、清理、账目和外传见[结果专题](docs/consumption-and-cost.md)。验证声明须绑定具体提供者、存储条件、事实范围及故障前提；mock、静态类型和文档检查不证明这些行为。

## 当前缺项

受理和结果确认的最小对接是现行规则，见上文和 [ACK](docs/consumption-and-cost.md#ack-的前提与效果)。参数词表、配置键、适配器映射、失联确认、跨进程稳定引用、策略接续、存储参与和流中耐久协议仍未设计。限额数值、计量算法及时间策略需按采用模型验证。本规格保留这些义务和承担者，不补机制或性能数值。工具最终结果块集合和嵌套投影先由工具及消息拥有者闭合来源，不能把过程帧许可等同全部结果许可。
