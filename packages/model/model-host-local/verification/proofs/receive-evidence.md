# 接收证明只在没有内容被交出时成立

本论证覆盖本机宿主的接收记录，消费包组规格「[首内容、接收窗口与流](../../../SPEC.md#首内容接收窗口与流)」的接收证明与「[不变式](../../../SPEC.md#不变式)」MD-10 在已发出的请求上的前提。它不证明传输的解码正确，也不覆盖进程重启。

## 状态与输入

一条已启动的流有一份接收记录。记 T 为传输已交出、还没被任何一次成立的证明盖住的事实序列，B 为传输是否开始读过响应正文，E 为传输是否交出过结束事实，L 为上一次成立的证明的窗口与那一批，V 为记录是否已作废。初始 T 为空，B、E、V 为假，L 为空。

输入有三种：

1. 交出：传输交出一条事实 f。V 为假时把 f 接在 T 的末尾；f 是结束事实时 E 置真。V 为真时不记。
2. 读正文：传输开始读响应正文。B 置真。
3. 要证明：命令层带着窗口 w 与一批事实 F 来要证明。

## 要证明的全化

| 前提                                         | 答复   | 之后                  |
| -------------------------------------------- | ------ | --------------------- |
| 没有这条记录，或执行资格不成立               | 不可用 | 不变                  |
| V 为真                                       | 不可用 | 不变                  |
| L 的窗口是 w，L 的那一批等于 F               | 成立   | 不变                  |
| L 的窗口是 w，L 的那一批不等于 F             | 不可用 | V 置真，T 清空        |
| L 的窗口不是 w，B 为真而 E 为假              | 不可用 | V 置真，T 清空        |
| L 的窗口不是 w，F 不等于 T                   | 不可用 | V 置真，T 清空        |
| L 的窗口不是 w，F 等于 T，且 B 为假或 E 为真 | 成立   | L 记为 w 与 F，T 清空 |

「等于」是逐条按规范编码比较，条数与次序都相同。此表覆盖全部组合。

## 性质

P：设第 1 到第 n 次成立的证明（不计同一窗口的重放）所带的批次依次为 F1 到 Fn。那么 F1 到 Fn 首尾相接，等于传输从启动到第 n 次成立那一刻交出的全部事实。

P 的论证，对 n 归纳：

1. 记录未作废时，T 恰好是上一次成立之后传输交出的全部事实：交出只在末尾追加，只有成立与作废清空 T，作废之后不再有成立。
2. 第 n 次成立要求 Fn 等于 T。由第 1 步，Fn 等于第 n-1 次成立之后交出的全部事实。接上归纳假设即得 P。
3. 重放不改变 T 与 L，所以不影响第 1 步。

Q：一次证明成立时，传输此刻没有读到任何还没交出的内容。

Q 的论证：成立要求 B 为假或 E 为真。

1. B 为假：传输没有读过响应正文。内容事实只来自解码响应正文，所以不存在读到而未交出的内容。
2. E 为真：结束事实是传输交出的最后一条事实（规格 MD-22），传输在物理停止之后才交出它，解码器在它之前交出全部已解码的事实。结束之后传输不再读。

## 结论

命令层只在一个窗口的证明成立、这次发出没有观察到内容、且本调用的其他窗口都已闭合时，才把首内容记为「已证明没有」。由 P，这次发出各窗口保存的批次合起来就是传输交出的全部事实；命令层对保存的每一批判过有没有内容。由 Q，没有读到而未交出的内容。所以首内容被记为「已证明没有」时，传输从没交出过内容事实，也没有持有内容。

## 前提与不覆盖的

- 传输的事实流是拉取式的：接收方不取下一条，传输不往下读。接收方保存一批时没有并发的交出。
- 传输在开始读响应正文之前同步报告「读正文」。漏报会让 Q 的第 1 步不成立，由传输的用例守。
- 读到而没有解码成事实的字节不算内容：没有人看得到它，也没有可执行的工具参数。
- 接收方自己补的结束事实不是传输交出的，得不到证明。
- 进程重启之后记录不在，答不可用。
- B 为真而 E 为假时一律不给证明。这比必要的更保守：这段时间里即使没有内容，首内容也保持不确定。
