# 模型调用组的工程关系

本页在正式维护位置保存待审技术设计。领域分解已评审不等于成员技术接受、阶段选择或实现支持。具名目录只有文档，公开形状和实际验证仍待设计及补证。

## 依赖方向

```mermaid
flowchart TD
  F[Agent、压缩、扩展或独立发起者] --> C[请求上下文公开契约]
  F --> M[model/model 公开契约]
  C --> P[模型档案能力依据]
  M --> A[显式提供者与存储依赖]
  M --> I[身份、秘密与外传资格契约]
  M --> R[原结果及费用事实]
  R --> F
  Assembly[产品装配] --> A
  Assembly --> M
```

箭头表示公开消费关系，不要求循环代码导入。发起者读取模型定义与调用接口；模型通过显式依赖返回结果，不反向导入 Agent 或 Session 实现。提供者适配共同契约，不重定义成功、首内容、费用或 ACK。

领域能力独立于 Cordis 使用，须声明自身显式依赖。Cordis 集成按现行 IC 约定拥有装配、绑定、替换和撤除；不能让 Cordis 作用域决定租户身份或调用寿命。客户端接入消费系统公开投影，SDK 不导入模型服务端、存储或 runtime 实例。具体导出及服务类型尚待实际设计。


## 成员分解与邻接协作

档案、执行、转换、保管和费用在目标 model/model 内组织。request-context 负责实际表示、预算和压缩；Session 保存选择；发起和消费方负责原用途，Model 不反向导入其私有实现。

本组不维护第二份状态机、错误集合或精确承接协议。完整机制见[成员内部设计](../model/docs/internals.md)，责任与事实归属见[领域角色](../../../docs/domains/model-invocation/architecture.md)。
