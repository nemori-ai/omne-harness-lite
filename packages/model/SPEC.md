# Model

## 总体架构

Model 回答一个问题：一次模型调用怎样被可靠地执行、保管并交还给它的消费者。它拥有模型档案、调用的受理与各次真实发出、原输出、结局、结果保管与费用事实。包组有九个成员：

| 成员                    | 回答的问题                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `model-contract`        | 调用、档案、转换、保管、计量与凭据有哪些值、操作与提供者端口，边界上怎样判。纯数据与纯函数，另带受控替身与提供者符合性套件 |
| `model-cordis-contract` | 在这套系统里它以哪些服务出现，定义自有的登记表怎样登记与撤除                                                               |
| `model`                 | 一次调用怎样受理、发出、保存、收场、读取与确认。不依赖 Cordis，离开这套系统也能单独用、单独测                              |
| `model-storage-sql`     | 调用事实怎样耐久地保存在 SQL 存储契约上                                                                                    |
| `model-host-local`      | 在本机上把实现、凭据、发送资源、宿主调度、结果推送与官方档案接起来                                                         |
| `pi-ai-transport`       | 一次真实发出怎样经 HTTP 与 SSE 到达网关并解释回来；家族怎样登记；网关协议怎样编码与解码                                    |
| `pi-ai-openai`          | OpenAI 家族的型号记录、规则、计量与官方档案                                                                                |
| `pi-ai-anthropic`       | Anthropic 家族的型号记录、规则、计量、词表资源与官方档案                                                                   |
| `tokenizer-tiktoken`    | 固定词表上的文本怎样在有界线程池里计数                                                                                     |

调用方经普通调用面受理一次调用，拿到可保存的调用引用。宿主为每次驱动取得执行代次，经发送边界做真实发出：传输准备、物化、在发送围栏里同步启动。传输交回的事实先经 `ModelCommands` 保存，再发布给观察者。调用收场后，结果被读取并确认，或被推送给受理时冻结的消费者 owner 保存之后由 Model 自己取得确认，然后清理。家族给传输提供每个型号的精确绑定，tokenizer 给家族计量器计数。

源码依赖只朝内：纯契约不导入任何实现，生产安装闭包里没有 Cordis、运行提供者、pi、tokenizer 词表或存储引擎；`model` 经端口注入取得传输、计量、媒体与持久化；Cordis 定义只从 `model-cordis-contract` 的 `./cordis` 发布；宿主依赖 Cordis 定义与 `model`；家族依赖传输与契约，传输不反向导入家族。纯契约分两个入口：根入口给调用方与消费者，`./provider` 给提供者作者；一个名字只从一个入口导出。

## 领域边界

Model 拥有：模型档案的身份、修订、撤回与同名求值；调用的受理、执行代次、每次真实发出、首内容判断、原输出、结局与控制结果；结果保管、确认与清理；每次发出的实际用量与费用事实；受理时选定的凭据层；每次发出带哪些推理状态；它自己的活体此刻在不在推进一次调用。

Model 不拥有：工作的发起、推进与业务采用（归消费者，会话路径上是 Agent）；请求输入的表示选择、组装、预算与压缩（归 Request Context）；工具的定义、准入与执行（归 Tool）；秘密的保管（归设置域）；主体与资格（归身份与授权）；账目的组织级投影与查询（归身份与接入的范围查询）。Model 只返回工具建议，不执行；不决定原工作的终态；不保管秘密。Model 不依赖 Tool：调用建议与工具结果经共享消息交接。

Model 不认识调用它的是谁。它需要的东西声明成端口，由外层装配来适配。

Model 为别人实现的端口：

| 端口                                                                               | 对方                                          | 一句话                                                                                     |

## 心智模型

把一次模型调用想成一次远程服务调用。调用方受理之后拿到的是一个可保存的引用，不是一个活着的连接。执行者可以换代，观察者可以来去，调用方可以离开；调用本身继续执行、保存、收场、记账。凡是只存在活体内存里的东西都可以丢，所以任何结局都只能由 `ModelCommands` 里的耐久事实决定。调用方不替 Model 收场，Model 也不等调用方。调用方想知道一次调用还有没有人管，就问一句「你的活体还在推进它吗」；Model 只按此刻的内存与自己的记录回答，答不了就说答不了。

一次调用有几条互相独立的事实轴：调用的结局、每次真实发出的发送状态与首内容、控制意图、结果保管、费用。它们不压成一个状态。控制意图成立不等于上游已停；结局是完成不等于结果已被消费；确认成立不等于正文已清理；费用未知不等于零；受理过不等于此刻有人在推进。

最容易想错的地方：

- 发出是不可撤回的。发送点之后的请求只能用控制放弃，不能宣称没有发出。可能已发出的调用永远不写成「未发出」。
- 首内容是重试的分界线。首内容之前可以按策略再发；之后同一逻辑回复绝不重新生成。判断不了首内容是否发生时，按已发生处理。
- 结果不知道就是不知道。提交未知按原操作认回，查询失败保持未知，不换身份重发，不写成成功或失败。
- 计量不是发出条件。输入大不大由请求组装方在请求前判断；Model 的准备与发送路径不计量，上游拒绝时以 `input-over-limit` 收场。
- 「不在我手里了」要有证据。活体里没有它，只说明本进程不在推进它；只有装配给出的证据说明别处也没有人在推进它，才答失联。

## 应然设计

### 受理与调用身份

- 调用方在首次受理之前固定调用身份与受理 operation，并可预先编码保存调用引用。受理成功表示原调用与它在租户份额里的一个名额在同一次提交里成立，不表示已发出。
- 同一调用、同一受理 operation、同一固定输入的重入返回原受理；同一调用换 operation，或同身份异输入，返回 conflict。
- `not-accepted` 只在原受理 operation 的排队、旧写者与存储恢复都被排除后返回。超时、路由缺席或查询失败都不证明未受理。
- 份额按个数计，不按字节计：每个已受理而结果还没被确认并释放的调用占一个名额。份额满时受理答 `unavailable` 且不排队、不占名额；所以没有「永远放不下」的拒绝。
- 一切受保护操作先验证主体与显式租户，默认拒绝跨租户。另一租户的调用与不存在的调用回答逐字节相同。调用引用的文本不含租户，租户取自调用方的访问依据。
- 受理入口在查账、占份额、调度或发送之前，用同一个封闭输入判断复制并核验输入。结构通过不证明资格、采用或份额。
- 受理成立时完整的固定请求已经保存。调用记录只带请求头（正文之外的字段与消息身份），正文另存一份，只在发送时读；所以调用记录的每次读写与请求大小无关，存储不因请求的字节数拒绝受理。
- 受理把消费者 owner 的装配声明冻结进受理事实。之后的发送点、策略点与确认读冻结值，不读当前装配。未声明的 owner 拒绝受理。
- 停止受理之后，同一 operation 的原受理仍可认回，新的受理答 `unavailable`；已受理的工作照常调度、驱动、读取与确认。

### 真实发出与发送围栏

- 一次真实发出分三段：`prepare` 不发送；`materialize` 读取并校验所选内容、编码最终请求体、预约容量，不发送也不计量；`start` 在调用时立即同步发起，不返回惰性对象，不在内部等待队列。同一 prepared 只物化一次，同一 materialized 只启动一次。
- 物化回执（供应商、表示采用、请求体摘要）与这次发出的首个接收窗口在同一次提交里持久，提交未确认前不得启动。
- 撤权、原工作失格、控制、换代与发送点进入同一个提供者协调的围栏。围栏内重读权威状态、核对已物化的内容、接收方、用途、工作资格与凭据，然后同步调用 `start`；中间不 await，不调用不受信回调，不排队。
- 撤权先于发送点则不发；发送点先于撤权则请求已在途，撤权触发控制，不能宣称未发出。发送点附近崩溃保留发送未知，既不称未发，也不据存储里没有 `started` 重发。
- 一次 `start` 对应原接收方的一次物理发出。传输禁用隐式 HTTP 重试与自动重定向。只有确定没有请求字节离开本机的连接失败，才可以在同一次发出里有界重试。
- 由唯一协调进程持有围栏。替换协调进程之前必须确认旧发送进程已终止或已失去全部发送能力；存储代次与租约超时只阻止旧写，不阻止旧发送。
- 发送边界在确定拒绝（凭据缺失、读不出、传输准备明确拒绝）时先记下未发出，再在原接收窗口里写一条失败终止，由驱动沿它收场；终止写未确认时按原 operation 认回，不生成第二个终止。

### 首内容、接收窗口与流

- 可增长的文字、思考、工具参数与语音以首片实际内容作为首内容；图片、文件与推理续接状态部件以完整交付作为首内容。响应头、心跳、空开块与纯状态不算。
- 任何可能观察内容的接收动作之前先打开接收窗口，把首内容状态记为不确定。崩溃留下的打开窗口不能靠存储里没有内容来关闭成「无内容」。已确认的未发出、没有块、单条失败事实、其他窗口全部闭合，才是 Model 自己的零内容依据。
- 观察内容先保存可恢复表示与首内容标记，再发布游标。未确认的批次不交给观察者。观察者先取完整快照，再取后续已确认更新；落后的观察者被结束并可以快照重连。
- 块打开时固定追加或整体替换模式，途中不换。增长中的工具参数不是可执行的调用；被截断过的工具参数块永远不能封为可执行调用。
- 以完成收场的回复至少有一个合法封口的块，以工具建议完成的至少有一个工具调用；否则以 `upstream-protocol` 失败，不交出空的完成。
- 传输事实以恰好一个结束事实收尾。没有合法终局就耗尽的流是失联，不是完成。协议的结束标记与传输的 EOF 分开判断。
- 结束块之后至多再收 `usageTail.maxFrames` 帧：每帧可以带用量，可以重复同一个结束块而增量为空；带内容或带另一个结束块的帧是协议错误。

### 重试

- 重试只在首内容之前，由有效策略按档案声明与实际失败决定。允许回退时按供应商声明次序各至多一次；不允许时原供应商退避后至多再试一次。
- 本地请求、授权或凭据明确无效，以及上游明确拒绝内容，不反复发送同样的请求。
- 上游报告输入超出其限制时以 `input-over-limit` 收场，策略必须停止：不重发同一输入，也不回退到同档案的其他供应商。调用方压缩后以新调用身份重新发起。
- 上游拒绝带回的推理状态时以 `replay-rejected` 收场这次发出。策略可以对同一供应商略去被拒发出中带上的全部推理状态再发；这次再发不占回退或退避名额，次数单独配置，缺省至多一次。
- 策略决定持久之后才准备下一次发出。策略不可用时不再试，以 `policy-unavailable` 收场。重试与退避的数值来自配置，不写死。
- 独立执行函数只执行一次真实请求，不重试、不保管、不确认。

### 控制、取消与晚到事实

- 控制以原调用身份定位。取消持久记录意图、传播并保管迟到的结果与费用；不自动确认，不伪装上游故障。取消输入不带原因，原因归调用方。
- 控制意图与上游真实停止分别记录。终局由传输在物理停止之后交出；已自然完成的流仍以完成收场。
- 一次控制只作用于目标调用，不按原工作扇出，不取消工具或其他调用。控制生效后不再为该调用追加真实发出。
- 消费者工作守卫对某一调用一旦答不合格就恒答不合格。发送点或策略点首次读到不合格时，Model 在同一提交里为该调用记录一次控制，其 operation 由调用身份按固定规则派生。守卫或证据适配器不可用时不当作不合格，也不记录控制。
- 迟到的账目与真实终结事实只经补录入口进入，核验可信来源后补到原发出上。补录不改变逻辑结局、结果版本、确认或清理。

### 执行写入的答复

执行方自己的写入失败时，结局按答复的含义决定，四种含义互斥且覆盖全部失败种类：

| 答复                                          | 含义                   | 结局                                                         |
| --------------------------------------------- | ---------------------- | ------------------------------------------------------------ |
| `invalid`、`unsupported`、`not-settled`       | 这次写入永远不会被接受 | 以成因 `persistence` 的失败收场                              |
| `commit-unknown`、`unavailable`               | 不知道写入是否成立     | 不收场；保留原写入，宿主在间隔之后再唤醒，先查询原操作再重放 |
| `conflict`                                    | 另有写入推进了调用     | 不收场；宿主再唤醒，执行方按当前修订重新决定                 |
| `stale-instance`、`handoff-invalid`、`denied` | 执行已不属于这个执行方 | 不写终局，不再唤醒                                           |

成因 `persistence` 的收场在任何未收场状态下合法，不经过重试判定；同一次提交把仍开着的接收窗口关闭。选定的凭据层缺失、不完整、撤销或读不出不会自己恢复，所以发送边界把它们记为未发出并以 `credential` 失败收场，不让调用方等待。

### 活体、失联与那一问

- 发起者离开或最后一个句柄释放时，执行、保存、收场与记账照常继续。
- 每次驱动由宿主取得执行代次，带宿主权威给出的可信主体与连续性证据。重复取得以同一 operation 认回原代次；旧代次不能再写。查询超时、目录为空、心跳迟到或租约到期都不是连续性证据。
- 调用方以调用引用经 `contact` 问「你的活体还在推进这次调用吗」，回答只有五种：`holding`（还拿着：我的活体正在推进它）、`settled`（有结果了：已收场，结果正在或将要按正常的路交回）、`lost`（不在我手里了：活体没有推进它，而且能证明没有任何人在推进它，带证据）、`not-accepted`（没受理过）、`unknown`（此刻答不了）。
- 回答之前先过访问核对。资格在实际执行处核，没有查看资格的主体得到拒绝，不论调用在不在活体里。回答要读一次这次调用的记录。
- 「活体里有」指此刻真的有东西在推进它：本进程的宿主对它有在跑的驱动、排着或欠着的下一次唤醒，或排着的结果交回。受理过而驱动已经停下、又没有任何东西会再叫醒它的调用，不算在活体里，所以同一进程里卡死的调用也问得出来。
- 「结果交回还排着」指推送在跑或排着，或有未确认的结果而此刻还没有登记的接收方。接收方登记着而推送已经放弃（结果未知或回执不符）的不算；认不出消费方、又不在跑也不排着的不算。

| 调用记录               | 活体里有  | 活体里没有                               |
| ---------------------- | --------- | ---------------------------------------- |
| 没有这次调用           | 不可达    | `not-accepted`                           |
| 已受理、在跑、在定重试 | `holding` | 判断来源给出证据：`lost`；否则 `unknown` |
| 已收场，结果还没被确认 | `settled` | 判断来源给出证据：`lost`；否则 `unknown` |
| 已收场，结果已确认     | `settled` | `settled`                                |

- 失联的证据只来自装配给的判断来源。单机上一个状态目录同一时刻只有一个服务进程持有独占锁，持锁进程的活体没有在推进一个调用，就等于没有任何人在推进它。没有判断来源，或它给不出证据时，不答 `lost`。
- 回答只看内存与自己的记录。这一问不加任何新的落盘状态，也不加扫描。
- Model 不跨进程接管旧调用，也不清理停在「在跑」的旧记录。调用方收到 `lost` 后以新的调用身份另要一次；原调用与它没送到的结果作废。
- 首内容之后或首内容无法排除时，同一逻辑回复不重新生成。只有接收窗口已可靠闭合且确认无内容时，同一调用才可以按原策略再做一次真实发出。
- 再驱动一个调用时不从当前档案或最新配置重写原采用：受理时固定的供应商、凭据层、参数、转换与适配器采用以及回放声明都保留。
- 物化资源丢失后，旧回执不授权新资源发送。重新物化得到相同请求体摘要才认回原回执；不同时建立新的发出并记录旧发出未发出。

### 结果读取、确认与清理

- 结果按原发出顺序与块序号组页，每位置至多一项；完整块与未封的部分值分开交付。页按完整结果项组装，超过组页目标的单项独占一页，不分割、不截断。
- `beginRead` 是第一份内容读取与读取登记的同一操作，与确认在同一调用修订上串行裁定。确认之后用原读取 operation 重复 `beginRead` 先认回原读取，再谈已确认。每一页重新核验当前读取资格。
- 确认同时要求整调用已真实收场，以及确认者在原租户内承担当前结果承接责任，并给出该 owner 的证据适配器认可的耐久证据。仍在输出、等待重试决定或回执未知时不能确认。
- 证据适配器的答复可以在写栅栏外读取，写入只在同一适配器、同一调用、consumer、结果版本、证据与执行代次下采用这份答复；其间任何一项变了，写入答 `unavailable`，不写。
- 确认与清理任务在同一裁定里成立。确认不回滚；清理失败不撤回确认，也不要求消费者重确认。
- 清理只移除本调用无用的输入、输出与引用；确认之前已开始的真实读取不被截断，在途写与未知写先核实；保留准确结算所需的最小事实。没有确认后默认永久保存完整副本的模式。

### 结果推送与保存

- Model 把完整、冻结的结果推给受理时冻结的 consumer owner 的接收方；重投与恢复不重新选择 owner。交付键是调用引用加结果版本（账目交付另加发出与账目修订），不用随机身份。
- 接收方只有同时证实四件事才返回 saved：完整冻结载荷已独立可靠保存；原消费关联与责任已成立；键、consumer 与载荷一致且去重已成立；保留条件与删除保护有效。saved 只认原键与原 owner 的证据。
- 接收结果未知时用原键与原载荷重投；同键同内容认回原回执，同键异内容是 conflict。未知只能被 saved 取代，saved 是终态。
- 账目交付只在结果 saved 之后推送。结果冻结之后到达的账目修订各成一个独立交付，不改原结果。
- Model 在 saved 之后以自己的确认 operation 与回执证据完成交接。生产者直到确认成立都保留原键与完整冻结载荷。
- 一次唤醒对一个交付至多推送 `1 + maxRedeliveries` 次；`unavailable`、`backpressured`、`cancelled-before-accept` 与没有接收方都只等下一次唤醒。接纳晚到账目之前先占名额，名额满时拒绝新报告，提交者继续保管来源。

### 公共观察与当前目标

- 每条内容流绑定原调用、发出、发布代次与投影版本。新发出或新发布代次使用新的流身份；旧引用永不指向后继。
- `current` 在同一确认边界上同时给出调用的权威状态与当前观察目标。目标为空只说明此刻没有可公布的目标，不表示调用不存在或已终局。
- 差分与应用是纯函数：修订与输出游标不倒退；已封块不改；追加块的新值以旧值为前缀；块不删除、不移位。失败不改任何输入，不交部分快照。
- 取得已确认快照与登记订阅在同一个不让出的同步段里完成。每次交付内容或终止帧之前重核观察资格；观察者的队列、帧与驻留时间都有显式上限，超界结束本观察，不驱逐别的观察者。

### 凭据

- 一份凭据由供应商、层与用途确定，租户取自调用方的访问依据。层是本租户、官方或无。准备时选定一层并随固定请求保存；发送时在围栏内只读这一层。
- 选层整层进行：本租户层持有任一项就选它，层内失败直接返回，不回退官方层；本租户层一项都没有、档案是官方档案且发行持有该供应商时才读官方层。两层的项不混用。
- 秘密不进入请求、调用记录、诊断、日志、错误消息与遥测。秘密只在一次 `start` 的同步调用内存在于本次发送资源的私有槽里。
- 每次读取都重读保管，不缓存；轮换、撤销与清除在下一次读取时可见。
- 凭据服务只交给受信的准备与发送边界；服务把端口放在方法闭包里，不放在服务实例上。

### 档案、选择与参数

- 档案身份是所在范围加不可变路由名。同一范围只能有一行同名档案，撤回也占身份；恢复撤回的名字恢复原行。
- 同名求值先去掉已撤回与被配置排除的同名行，再按租户、组织、官方取最具体者。胜出之后才判模态与锁定；缺凭据或模态不符不改换外层同名行。同名全部撤回是已下架，仍有在册而全部被排除是配置排除，来源读不到是不可用，三者不混。
- 来源给出的快照里有层序之外的候选，或同一身份有两个候选，说明来源没有给出当前组合：求值答不可用，不在这份快照上选胜者。
- 档案变更时检查：窗口、输入与输出上限是正整数，输入与输出上限不大于窗口，每项不大于对应供应商已知的有限上游值；压缩触发百分比是 1 到 100 的整数；输入模态含文本；支持图片的档案有单图字节上限。违反时返回 `invalid` 并列出字段，档案不变。`updatedAt` 不倒退。
- 参数按统一含义声明。供应商不能准确表达的显式参数在发出前返回 `unsupported`，不静默丢弃；省略的参数把固定供应商的默认值解析并保存进受理采用。`max-output-tokens` 不大于档案的输出上限。
- 修订与撤回不改在途调用的采用记录。
- 官方档案由各家族包提供；读取官方档案不创建 tokenizer、网络连接或模型实例。

### 模态、转换与工具声明

- 模态由内容的媒体类型判定，词表与判定归共享的模态成员。Model 支持文字、图片与语音；视频是合法模态，但没有档案能声明它。
- 历史模态投影由调用方随运行时上下文提供，Model 只按胜出档案的输入模态与它比对。投影缺失或不可读不能当作空历史放行。
- 转换件按具体媒体类型优先、模态次之选取，同键只一件生效；命中而不可用时返回失败，不回退为未登记或另一件。转换在本地完成，不调用模型；结果至少含一个不同模态的派生块与文本转写。
- 转换件登记与查找的键都必须已是规范形式：按相等匹配，不做归一化；模态键取自共享的模态词表。查找时给的媒体类型不是规范形式，就不到达任何转换件。
- 工具结果中的模型可见引用只在真实发送的物化阶段才读取字节；附件地址文本不进入媒体读取。读取前核固定请求确实含该来源与引用，以及当前读取与外传资格。
- 请求的工具声明只含名称、说明与参数 schema。名称在请求内唯一。无法无歧义映射供应商名称时返回 `unsupported`，不截断、不改名避让。

### 推理回放

- 档案的每个允许供应商有一份回放声明：产出的回放范围、能消费的范围集合、外来可见推理的处理。声明在准备时按供应商次序写进固定请求，受理后不随档案修订改变。
- 每次发出按这次的供应商对每条助手消息判断一次是否可续接：带回放标记、范围在该供应商可接受的集合里、适配器认识其格式、且不是被拒后再发中略去的消息。可续接就带上它的推理状态；不可续接就略去并交出一条不含载荷的诊断。投影只决定这次发出的请求体，不改历史。
- 回复含推理续接状态部件而物化回执没有回放格式时，保存这次收场的写入整批拒绝，不丢弃部件，也不按没有回放收场。
- 计量器与编码器对同一供应商使用同一投影。推理状态不按密文长度分词，也不为满足上限而去掉。
- 推理状态载荷是租户数据，不进入错误、诊断、遥测或普通展示。

### 计量

- 计量能力由请求组装方在请求前调用。Model 的准备与发送路径不调用它，也不以它的结论作为发出条件。计量不按字节数拒绝输入。
- 计数与计量都返回 Promise，调用者等待完整结果。首个异步计数之前复制本次消费的输入，之后的计数、摘要与限额检查都用同一份快照。
- 普通文本即使形似控制 token 也按普通文本计；特殊 token 只能来自固定配置的声明表。相邻普通文本先合并再计数，分段计数不相加。
- 计数依据把供应商、适配、算法、tokenizer、模板、投影、媒体变换与回放依据作为一个不可变组合；换其中任一项，依据它的旧结论失效。本地分词准确不等于上游计量准确：任一组成是估算，结果就是估算并带明确余量。缺依据时返回具名不可用，未知不按零计。
- 延续计量：请求组装方声明延续调用 X 时为「只追加、消息不变、投影确定、提示词与工具不变、回放设置不变」作保；锚点命中时结果是 X 的真实输入合计（不加余量）加新增部分的估算（余量只按它算）。任一核对条件不成立就不命中，退回完整计量并写明原因。来源调用读不到时按无此事实处理，另一租户与不存在的结果相同。校准状态按租户分区。
- 租约释放后不交出迟到的计量成功，交出的每个计量器都答不可用。
- tokenizer 初始化时核对实现版本、词表摘要与配置摘要，任一不符返回不可用，不换编码、不用字符倍率。计数不读文件、不联网。不同租约不共享明文缓存。

### 费用与账目

- 每次真实发出的用量、费用或未知值关联原调用、实际凭据绑定与原 consumer。未知费用保持未知，不写零，不用估算替代。上游用量自相矛盾时相应项记为未知并交出诊断。
- 同一账目事件经流内与补录两条路径到达只登记一次；合法重试可能产生多笔真实费用，不能按「一调用一费」去掉。账目修订使用新修订号与原事件关系。
- 传输交出的账目报告不含调用身份与迟到标记，由保存方补上。
- 账目可见不授予正文、附件、凭据或秘密的访问。组织范围的账目读取先取身份领域的裁定再按组织过滤；裁定拒绝或不可用时不先过滤。

### 诊断与数据保护

- 发出前按主体、目的、内容与真实接收方检查外传资格；换供应商重新满足接收方条件。
- 原状态码存在时保留，但状态码只是证据，不单独决定失败成因。外部失败的诊断是安全的短文本，不含秘密、URL、响应头、错误体或请求正文。
- 诊断查询每次核调用级诊断读取资格；普通读取、成本账目资格或管理员身份不自动授予它。游标不携带权限。诊断保留期限由部署采用；没有采用时查询不可用，不默认永久保留。

### 资源寿命与装配

- 定义、装配与活体分开。服务定义只从 `model-cordis-contract` 发布，提供者继承唯一定义，不复制键或类。目录命中、服务注入与解析成功都不授予保存、观察、交接或发送资格。
- 登记落在调用方的作用域上；撤除只撤自己的贡献，晚到的旧撤除不删除后继。撤除停止新的取得，不撤回已发出的请求，不宣称业务交接完成。
- 结果接收方按 owner 登记，一个 owner 同时只有一份存活登记：旧登记属于正在撤除的作用域时被新登记替换，属于仍存活的作用域时新登记失败。
- 驱动交回「答复未知、依赖暂时不可用、期望修订过期」时，宿主在配置的间隔之后再唤醒这个调用；其余失败不再唤醒。同一调用同一时刻至多一次驱动。
- 计划停止先停新受理，再等在途的驱动与推送交还，最后撤服务。停止信号只请求本地停止。
- 一次取得固定一份适配采用；版本更新只影响后续取得，不在发送或读取途中替换编码器、tokenizer 或解码器。共享资源由装配拥有者在所有使用者退出后关闭，单次请求不销毁借来的实例。
- 所有限额与期限由装配显式给出，成员不设未经测量的生产默认值；缺配置是加载失败，不是隐式无界。

### 传输与家族

- 所有型号只经网关的固定路由发出。网关引擎只有一份，源码里不出现厂商或型号家族名；厂商差异只能是记录的线数据或带修订名的规则。
- 家族记录是纯数据，采用摘要覆盖整条记录。行为或数据变化时新增修订并冻结旧记录，不原地修改。家族表按采用的全部四项精确查找，不按名字前缀匹配，不取最新修订，不把供应商转给别的家族。
- 取得一个精确绑定时一次核齐全部采用与资源；任一不匹配整体失败并释放已取得项，不用同名最新件补齐。
- 本项目的引擎与记录不关闭推理：推理强度 `none` 映射为不支持。
- 流停顿上界是两次收到响应字节的最长间隔，可选。到期在响应头之前以上游不可用失败，之后以流失联失败；到期不撤回已发出的请求。
- 代理编码与旧词表只给出估算，不声称 tokenizer 身份。
- 连接容量按个数授予预约，先到先得。预约不过期，到释放为止有效。消费预约的那次交换占着席位，到它物理结束之后才归还，别人不能替它提前归还；预约被消费之后再 `release` 不动槽位。被取消的等待者不占槽。容量已关闭或等待中被中止时，不给预约。

## 原则与约束

- 失败如实是失败，未知如实是未知。不把未知写成成功或失败，不把本地保存失败报成供应商不可达。
- 可能已发出的请求不能被说成没有发出；disposer、关闭与取消都不使外部输出可逆。
- 耐久事实是唯一权威。目录、缓存、镜像与进程内账本只是可丢的活体，不能决定任何结局。存储层的内存镜像只持有存储已经确认的写入，不先于存储持有未确认的写入。
- 规则只写一处：选层、判读、封闭输入判断、答复分类与命令核心都只有一份实现，内存与耐久实现、提供者、替身与符合性套件共用它。
- 共同契约不能被提供者降低。替身与脚本结果不证明生产提供者。
- 有界是预算，不是答案。合法使用会碰到的上限要有去处：份额满时等待再受理，名额满时背压，单项超过组页目标时独页。
- 策略类的数值（重试、退避、上限、期限、余量）都是配置，代码里不写死默认值。
