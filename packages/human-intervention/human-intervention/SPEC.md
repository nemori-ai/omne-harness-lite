# human-intervention/human-intervention 长期行为候选

本文件维护具名文档目标的完整必要行为。文档目录不成立真实 workspace 成员、公开形状、发布版本或运行能力。整体产品及技术采用尚未接受；阶段清单未选，实现与行为验证未核实。产品范围见[产品正文](../../../.meta_harness/design/product/human-intervention/design.md)，精确协作、机制与技术缺项见[内部设计](docs/internals.md)。本文件不重复未来公开类型，也不以机制未定取消已明确的行为。

## 责任与消费者

HITL 负责关联原请求、获准呈现、一次有效处理及答复交接。原 Tool 或 Run/拓展协调者拥有等待、有效答复含义、消费及后续推进；授权拥有者拥有决定或权限效果；实际执行者拥有外部效果和物理生命周期。决策池是查询/呈现视图，不是新主体或第二决定权威。

创建请求须提供可信原主体/租户、问题、来源、原工作与消费位置、适用参数和依据。读取和提交须提供可核验资格、指定卡片和原提交关联；确认必须说明实际成立阶段。恢复、查询、控制和退出按原身份及代际进行，不从最新版定义重新创造原请求。具体公开入口和数据形状由 Q-HI02 采用。

## 业务不变式

### INV-HI01 原请求身份与含义保持可恢复

确认可处理请求前，原请求及保管拥有者固定可信租户、来源、原会话/Run/Tool、卡片、问题与原等待/消费位置。授权动作固定原参数、生效参数、实现和采用依据；拓展请求固定原拓展身份、位置及版本或等价依据。恢复和界面换代不暗换这些关联，不以可运行闭包充当稳定数据。验证义务 V-HI01。

### INV-HI02 有效待答请求完整可发现且自包含

所有仍需人输入的有效卡片进入所属租户与位置的池视图；具备读取资格者可从池或原会话发现，不因会话数量、未打开原会话、runtime 退出或关屏遗漏。卡片说明来源、问题、动作/参数、合法选项、可选后果、原会话及解除对象，能回查原依据；多个等待解除对象不同仍可辨。不隐含新跨节点聚合、跨租户读取或带外渠道。验证义务 V-HI02。

### INV-HI03 问询、请示、消息与配值分别解释

Ask 问询的每个问题必须有描述、文本候选项及系统保证的自由作答；图解可选且不能替代文本，人可以不选任何候选而独立提交文字。请示提供批准、拒绝及独立自由作答，说明动作对象、理由、影响、可逆性和替代办法，本次请示不先执行拟请求动作。请示原话由原请求拥有者解释，能明确读成准驳时沿原规则处理；读不出时保留原话并标明“人有话说但未给准驳”，不合成批准、拒绝或明确拒答。原 agent 取得指导后调整并再请示，不能据此执行拟动作。

系统放行卡同样保证不选任何授权档位而独立提交自由文字，不要求先作准驳或授权范围选择。原话须保留并交原准入及授权拥有者按现行规则解释；有效授权及其范围仍沿原规则，文字提交本身不自动批准动作或写入权限设置。当前资格、允许值、明确禁止及原动作的适用范围继续按 INV-HI04、INV-HI05 核验。

拓展卡片同样保证不选选项而独立自由作答，原话回原拓展件解释，不增系统授权权威。信息或选择答复不自动成为权限。普通消息及提示词/Skill 命令沿原消息受理，流程命令沿原业务受理；卡片答案只交指定原请求。MCP 静态/OAuth 凭据取得由租户持有的配值资格承接，不因 Ask、Run 或答卡代办。验证义务 V-HI03。

### INV-HI04 授权决定仅在允许范围与真实资格内生效

系统准入先计算现行结构化权限、授权表达和会话模式；明确禁止立即拒绝，不出请求放宽的卡片。系统卡只提供当前有权且写入值可生效的选项；能访问会话不推导修改租户设置资格。仅本次及会话范围沿原授权规则；租户持久选择写入租户权限设置，受真实写设置资格及组织上界约束。确认设置生效须有设置拥有者实际证据，不创造跨 Run 的永久批准权威。准入组件不可用沿正式全拒承接，不借 HITL 补许可。

系统确定需问但生成有效卡片确定失败时，相关动作被拒、不执行，原协调者将准入故障造成的拒绝及真实原因交原 agent，并以合法可见方式告知人。不得伪造人的拒答或建立等待不存在卡片的有效人工等待。拓展出卡执行报错沿正式扩展错误策略及有效声明处置，保留真实失败和后续责任，不将报错变成人的答复或不存在卡片的等待。保存确认未知不属于确定生成失败，沿 INV-HI14 保管并查询。验证义务 V-HI04。

### INV-HI05 原批准不转移到不同动作或绕过环境

有效决定只适用于原动作、生效参数及匹配实现/依据。参数、实现或授权依据改变时不能自动复用旧批准；原继续执行者重新核验其是否仍适用，明确拒绝、重新判断或受阻。准入、人的批准和实际环境/隔离条件分别成立，普通批准不解除禁止或降低设施。保持调用约定、绑定及参数时，仅 runtime 换代不自动把原判断变成新动作；实际边界仍按现行规则核验。验证义务 V-HI05。

### INV-HI06 一张卡片只有一个有效人的处理

会话卡和决策池共享同一权威决定。答复、拒答与失效竞争由原等待协调者裁定，不允许两入口或两并发提交确认两份有效处理。原工作已确定终局后不再接收新有效答复；已经生效的历史答复保留，不因后续终局改写。重复技术提交查同次身份，返回实际结果，不重复权限效果或推进；人的再次提交不仅因文本相同任意合并。验证义务 V-HI06。

### INV-HI07 答复和原等待可恢复一致且交接无空档

协调者对外确认有效答复前，可靠保存人的处理及原等待关联更新，作为共同业务单元成立，不能只保存卡片答案而丢失原位置责任。只有该业务单元确认成立，才交回可消费的有效处理；保存失败不确认生效，保存未知须沿原身份查询确认后才能消费，竞争入口也按实际结果返回失败、未知、已处理或冲突。需授权/设置效果时保留对应确认与未完成责任，答复接收不冒充权限已生效。共同数据库不等于共同提交；跨后端无法同提交须按采用协议保留已确认阶段、未知及下一保管者。前方在后方可靠接手前保管，后方确认后从保存位置继续，通知失败不抹去提交。验证义务 V-HI07。

### INV-HI08 读取、作答和披露分别核验当前资格

呈现、答复、查询、恢复读取和通知内容均携带可信主体、租户、目标及用途，核验当前对应读取/决定/配值资格，跨租户私有访问默认拒绝。共用账号、工作区、实例、缓存、名字或旧批准不授新权。条件失效或不可确认时拒绝依赖操作，保留必要合法事实及未完成责任，不向无权方泄露问题、秘密或原内容。验证义务 V-HI08。

### INV-HI09 人工等待不被时间或系统替代回答

有效人工等待没有超时默认答案或“不回就当同意/拒绝”；界面、脚本和拓展件均不得替人给已出卡片答案。等待可长期存在，时间流逝、无人查看及重启不改变答复事实。额外拓展只能按其权限收紧或另问；导入 hook 的允许或代填输出只按无意见解释并向采用者明示，不放宽系统询问。原业务的合法终局/控制失效由其他不变式处理，不以此伪造人的答案。验证义务 V-HI09。

### INV-HI10 批次只阻塞其原等待范围

同次 Ask 的全部问题处理后解除该 Ask；Ask 等待以前台阻塞原调用，不因普通工具支持后台而转后台。其他工具内部人工等待按其声明的原 Tool 范围和生命周期，后台等待不自动阻塞 Run。Run 拓展的同轮卡片全处理、该批所有动作判断齐备前不执行任何获准动作；后继拓展可再出下一轮。池子不能把独立工具卡片并为全局屏障，也不允许一轮答一半就提前发已通过动作。验证义务 V-HI10。

### INV-HI11 合法拒答、拒绝与故障不混同

人明确“不回答”是有效处理并计入该张所在批次已处理，原问询取得没有答案的含义；“人有话说但未给准驳”另保留原话和未裁决事实，不合成人的不同意或明确拒答，也不据此批准动作。拒绝动作有人的不同意或准入否决原因，不冒充执行失败；确定出卡生成失败的拒绝标明系统准入故障及原因。插队是具名人的控制事件，按原 Run/Tool 规则解除其受影响等待，保留占位、消息及原因；卡片拒答只跳这一张，插队不取消整个 Run。取消等待不批准动作。系统保存/执行故障和因原执行终局而卡片失效不伪造拒答。验证义务 V-HI11。

### INV-HI12 等待期间继续受理合法输入且不偷作答

普通输入、后台结果和控制按原受理/工作责任处理；HITL 等待不新增拒收合法输入的门槛，也不把普通聊天猜成答案。普通消息到原队列等待其合法消费，卡片答复回卡片，控制按原目标处置；提示说明正在等待及排队，必要控制入口可用。受理成功、实际控制生效和等待解除分别确认，未知不假称已解除。验证义务 V-HI12。

### INV-HI13 扩展接续复用已发生判断而不重跑效果

原扩展在等待前后保留必要非确定输入、已发生模型/工具调用、结论和效果，接续按稳定原身份/位置取得记录。已有结论不重判，已有答复不再出同一卡，未完调用按原身份认回。不能仅调用同一个函数就声称回放安全；不得重复费用或效果。版本/依赖变化无法兼容时保管原进度并报告受阻，按原采用的恢复协议接续、重判或关闭，不替人给新答案。验证义务 V-HI13。

### INV-HI14 未知保持原身份并只接续未完成责任

响应丢失、超时、查询失败、断连及界面滞后不证明答复未保存、原工作未执行或终局已成立。保存已知范围、未知及下一查询/对账责任，先查原卡片/提交/等待/调用，不能另出同一张卡、另建授权或盲目重发原动作。未知答复提交须查询确认共同业务单元成立后才交原位置消费；查询确认失败返回真实失败，仍未知或查询不可用不确认生效或已处理。已确认部分保留，恢复再失败仍不丢进度。具名拥有者在必要介质、资格、服务及调度前提可用时继续未完成责任或报告明确受阻/失败；不承诺网络隔绝下原工作必然完成。验证义务 V-HI14。

### INV-HI15 原业务终局使等待失效而不复活

原 Tool/Run 已确定终局、合法控制解除等待或会话业务归档生效后，停止关联卡片的新有效答复，保存失效依据和历史。仅 Agent runtime 退出、交付面关闭或不可观察不作终局证据。会话归档依 Q04 在业务上取消并解除等待/推进依赖，传播适用取消，不等待全部独立执行物理停止；后到答复/结果不重开原工作，撤销归档不自动恢复旧调用。原工具连续性确认丢失沿工具真实收场，卡片不把新执行当原执行。验证义务 V-HI15。

### INV-HI16 资格失效不删除身份或冻结全部业务

成员资格失效限制后续访问/答复/新准入，不直接销毁租户、删除会话或等同归档。原事实与未完成责任按其业务继续保管；重新加入同组织恢复同一租户资格，不复活旧终局。自动归档由会话拥有者按启用配置、会话未标记常驻及真实连续空闲条件判断，资格失效本身不重置/暂停计时，隐藏卡片不证明空闲，无法确认原工作状态时保持未知。验证义务 V-HI16。

### INV-HI17 独立执行和物理效果有人继续负责

卡片处理或失效、Run 终局、取消信号、执行域终止及 dispose 不证明模型/工具/宿主调用实际停止、资源回收或效果撤回。原执行与桥接承接真实结果、费用、已知效果和迟到，现无披露资格仍按原业务保管，不能只向已消失执行者返回结果。独立执行可能继续计算计费，不把等待 Agent runtime 不占计算写成整个会话零成本。验证义务 V-HI17。

### INV-HI18 必要事实在确认前达到耐久边界

卡片、答复、原位置、采用依据、有效/失效确认及未完处置责任，在所声明介质/部署前提下覆盖普通进程、操作系统崩溃及断电后的可读取解释。进程缓冲、发送成功、收到唤醒或一次重启不证明耐久。清除唯一保管副本前已有可靠承接/保留依据；必要存储不可用时不确认依赖操作，恢复后核验当前条件，不丢失未消费答复或历史原因。验证义务 V-HI18。

### INV-HI19 runtime 和提供者换代只撤自身贡献

Agent runtime 实例换代不改变同一 Session 的 AgentDefinition ID、原 Run/Tool 或卡片身份；有效原执行者仍按单执行者规则推进。HITL 提供者配对自己的登记、订阅、临时使用权及句柄，部分失败/依赖退出先保管或交接未完责任；只撤自身贡献，旧代际清理不删除新实例或其他租户数据。共享资源退出不等全部释放，失败残留及下一处置可定位。独立接口与 Cordis 集成分别守合同，内核不能补业务授权、耐久或恢复保证。验证义务 V-HI19。

### INV-HI20 等待提示、送达和人的答复分开

卡片产生后在合法池范围可发现。需要通知时由来源业务提供获准目标/内容，正式通知能力承接自己的受理、保管和送达；发送、送达、已读、卡片有效答复和原工作完成分别确认。提示失败不删除卡片、不代答或重做产生卡片的原工作；未知交原通知身份查询。通知内容按当前披露资格裁剪，通知不能成为第二决定权威。验证义务 V-HI20。
