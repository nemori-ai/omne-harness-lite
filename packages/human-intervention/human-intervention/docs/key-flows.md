## F-HI03 两个入口竞争同一决定

对应 J-HI05。显示是合法投影，双方提交指向同一卡片与原等待，唯一协调者确认一个有效处理。技术重传查同次提交，另一新处理看到实际结果/冲突；不产生第二份批准或继续。投影落后时查权威并纠正，不靠缓存保护唯一性。

```mermaid
sequenceDiagram
  participant UI1 as 会话卡片入口
  participant UI2 as 租户池入口
  participant H as 呈现与答复接口
  participant W as 原等待协调者
  participant S as 可靠保管
  participant O as 原消费位置
  UI1->>H: 原卡片与提交身份、人的答复
  UI2->>H: 同一卡片的另一处理
  H->>W: 当前资格及合法内容
  W->>S: 裁定唯一有效答复和等待更新
  S-->>W: 真实保存结果
  alt 共同业务单元已确认成立
    W-->>H: 有效处理及竞争裁定
    H-->>UI1: 本次提交的实际处理结果
    H-->>UI2: 实际已处理或冲突说明
  else 明确保存失败
    W-->>H: 未确认有效处理、失败原因及各提交实际状态
    H-->>UI1: 真实失败及原提交关联
    H-->>UI2: 本次处理的真实状态
  else 保存结果未知
    W-->>H: 原提交未确认有效、须按原身份查询
    H-->>UI1: 未知及原提交关联
    H-->>UI2: 实际已知状态与未确认范围
    W->>S: 按原卡片与提交身份查询共同业务单元
    S-->>W: 原提交的查询结果
    alt 查询确认共同业务单元成立
      W-->>H: 已确认的有效处理及竞争裁定
      H-->>UI1: 已核实的处理结果
      H-->>UI2: 已核实的已处理或冲突说明
    else 查询确认共同业务单元未成立
      W-->>H: 原提交未生效、真实失败原因及各提交实际状态
      H-->>UI1: 已核实的失败结果
      H-->>UI2: 本次处理的真实状态
    else 仍未知或查询不可用
      W-->>H: 原提交仍未确认、原关联及下一查询责任
      H-->>UI1: 仍未知及查询受阻原因
      H-->>UI2: 本次处理的真实状态及未确认范围
    end
  end
  opt 共同业务单元已由保存或原身份查询确认成立
    W->>O: 交回可消费处理与未完成消费责任
    O->>S: 保存实际消费与继续结果
  end
  Note over H,O: 显示、答复生效、消费及动作发起分别成立
```

只有共同业务单元确认成立后才交回可消费答复。保存明确失败返回真实失败，结果未知沿原卡片与提交身份查询；查询确认成立才进入消费，仍未知或查询不可用则保管原关联及下一查询责任。竞争入口的已处理或冲突回执同样以权威实际结果为依据，不能在前一提交未知时先确认已处理。答复与终局竞争仍由原协调者裁定，无权入口不能因知道卡片 ID 而查询正文。INV-HI06–HI08、INV-HI11、INV-HI14、INV-HI18。
