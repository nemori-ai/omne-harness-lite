# 独立 HITL 交互验证台

本页供开发者手动检查独立等待的请求、答复和接手流程。它调用本包公开应用服务，使用真实 IdentitySql 和 SQLite。它复用包内测试装配，使用临时租户及系统代租户主体，不提供产品登录、动作授权或 Agent/Tool 接入。

## 启动

在仓库根目录完成开发环境构建后运行：

```sh
node --experimental-strip-types packages/human-intervention/human-intervention-local/verification/workbench/server.mjs
```

打开终端打印的 `url`。服务仅监听 `127.0.0.1`，端口由系统分配。每次启动创建新的临时数据库；路径与进程号一同打印。数据库位于仓库 `tmp/hitl-r1-c2/databases/`，不会操作正式租户数据。用 Ctrl-C 关闭服务和存储。

网页请求必须携带本次启动的本地控制令牌，且 Host 和 Origin 必须匹配服务地址。此控制令牌限制验证入口的访问，不能作为产品身份认证方案。不要把服务通过反向代理暴露给其他机器。

## 手动检查

1. 创建一张卡片，选择方案或填写原话。卡片应变为“已答复 · 待接手”。
2. 点击“接收答复”，再查看等待状态。卡片应变为“已接手”，等待应显示可以继续。
3. 创建两张卡片的请求，只答复并接手第一张。原等待仍需另一张卡片，不能显示整批完成。
4. 在第二张卡片尚未答复时重装应用服务。未答事项应保留；答复并接手第二张后，原等待才显示整批完成。
5. 创建请求后点击“原操作重试”。请求池不应新增重复卡片。点击“查询原结果”可读取原命令的完整结果。
6. 对未答请求点击“结束此请求”。请求中的未答卡片应变为“已取消”。
7. 在原话中输入 HTML 字符。页面应显示文字，不能执行其中内容。

“已加载”数量和状态筛选仅统计当前已加载页。使用“加载更多”继续读取。并发修改使快照失效时，页面要求刷新。`unknown` 表示结果未确认，应查询原结果或重试原操作，不应创建新的操作身份。

## 证据边界

“重装应用服务”只关闭并重新创建应用服务，保留进程、数据库和游标签名密钥。它不验证进程重启或物理断电恢复。此页面也不验证多租户隔离的全部场景、授权范围、执行槽或正式通知。

创建动作中的准备步骤由验证装配扮演原工作拥有者，冻结请求及其可读、可答复主体。答复、取消、接手、确认交付和结果查询均调用实际应用服务。页面不自行计算请求状态或伪造消费回执。

自动化事务、撤权和恢复检查见[持续验证](../README.md)。浏览器运行记录和截图放任务 tmp；作者运行不能替代独立验收。
