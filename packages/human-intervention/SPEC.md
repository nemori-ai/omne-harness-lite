# Human Intervention

## 总体架构

Human Intervention（人工介入，HITL）包组回答一个问题：一件工作走到需要人决定的地方时，怎样把这个请求和原来的工作关联起来，交给有资格的人看见，确认一个有效的人的处理，再可靠地交回原来等着的位置，而人工介入自己既不成为决定的权威，也不替原工作继续执行。

| 成员                       | 回答的问题                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `human-intervention`       | 公共协议 `hitl/1`：请求、卡片、答复、操作身份与原等待引用的值；命令、查询、恢复与提交协调的接口；边界解码；卡片的纯决策函数。不依赖 SQL、Node 或 Cordis |
| `human-intervention-local` | 单机 SQL 提供者：原操作终态与封口、请求与卡片的共同提交、独立原等待（WaitOwner）、Identity 资格协调、按资格的查询与池、恢复与交接的应用入口             |

原工作（Tool 的调用、Agent 的放行或扩展轮次、独立工作）先固定问题、动作与原等待位置，再以一次原操作登记请求；请求、卡片与原等待的有效关联在一次提交里同时成立。人从会话入口或待办池读到卡片，提交答复；协调者裁定唯一的有效处理，把决定与原等待的收件箱在同一次提交里写下。原等待当前代次的接收者从收件箱读决定、接手并记下消费回执；之后原拥有者自己判断能不能继续。提示的送达交给 Notification，与答复无关。

## 领域边界

本组拥有：请求与卡片；人的有效处理（决定）及其提交依据；请求的读者与答复者受众；待办池投影；决定交到原等待的交接状态。单机提供者另外拥有独立原等待的保管：准备记录、接收代次、终局、收件箱、消费回执与待接手集合。

本组不拥有：原等待的含义、批次屏障、继续位置与业务终局（原 Tool 或 Agent 的协调者；会话的业务控制归 Session）；批准的含义、许可与消费（Authorization）；租户持久权限设置（Settings 与权限规则的拥有者）；主体发行与成员资格（Identity）；提示的受理与送达（Notification）；会话入列与推进（Session、Agent）；实际执行与外部效果。卡片是查询与呈现的视图，不是新的主体，也不是第二个决定权威。

## 心智模型

把人工介入想成一个挂号窗口加一个寄存柜。原工作拿着自己的等待号来挂号：问题、动作、参数和「答复送回哪里」都在挂号时定死。人在窗口前只能交一次有效的答复；答复和「送回哪里」一起锁进原等待的寄存柜，之后谁来取、什么时候继续，是原工作自己的事。窗口不解释答复的意思：同意不同意、算不算授权，由接手的原拥有者按它自己的规则读。

等待是一件可以无限期存在的耐久事实，不是一个挂着的 Promise。进程退出、界面关闭、没人看都不改变它；运行时换了实例，等待号不变，只是领取人的代次变了，旧代次不能再领。等人的时候不占执行名额、写事务或跨调用的锁，别的工具调用与别的会话照常前进。

最容易想错的地方：保存了答复不等于原等待已经接手，接手不等于动作已经执行，执行也不等于授权已经生效，这几件事分别确认；结果不知道就按原操作身份查，查无记录不是未提交；没有人回答就没有答案，时间、通知或系统都不能替人回答；原工作终局之后卡片失效，但已经成立的历史决定保留。

## 应然设计

### 请求的身份与登记

- 一次请求固定可信租户、来源（独立工作、Tool 调用、Agent 放行轮次、Agent 扩展轮次）、原工作与原等待（`WaitRef`：拥有者、等待身份、继续实现的代次、目的地）、消费位置与采用依据。动作类请求另固定原动作、生效参数摘要、实现与授权依据。恢复与界面换代不暗换这些关联；运行时对象与闭包不进入数据。
- 请求、卡片与原等待的有效关联在一次提交里共同成立；任一参加者失败全部回滚。准备材料只固定原登记调用、受众与相容实现，不是有效人工等待。对同一等待换操作身份重新登记被拒绝。
- 来源的组合是封闭的：独立来源不带会话；Tool 来源必带调用引用；放行来源可带调用引用；扩展来源不带；带运行引用必带会话引用。
- 系统确定需要问人、却确定生成不出有效卡片时，相关动作被拒绝且不执行，原协调者把准入故障与真实原因交给原 agent，并以合法可见的方式告诉人；不伪造人的拒答，不建立等待一张不存在的卡的人工等待。保存结果未知不是生成失败，按原操作身份查询。

### 卡片与答复

- 每张卡都允许不选任何选项而独立提交原话，也允许跳过（decline）；界面总是给出这两项。问询的每个问题有描述与至少一个文本候选，图解可选且不替代文本。请示与系统放行卡不要求先选准驳或授权档位。每张卡必须写明跳过的后果，由出卡的原拥有者填写。
- 答复只有三种：选择一个选项、一段原话、跳过；没有超时或自动答复分支。拒绝动作是一个明确的选项，与跳过不同。
- 本组只保存原话与选择，不解释准驳。接手者用自己的结果词汇解释：问询的跳过是这一题「没有答案」；请示的原话读不出准驳时标为「人有话说但未给准驳」，动作不执行；放行卡的原话交原准入与授权拥有者解释，提交本身不批准动作，也不写持久授权；扩展卡的原话交原扩展件解释，扩展件只能收紧，不能放宽。
- 卡片状态只有待答、已决定、已失效。已决定的卡另有交接投影：待接手、已接手、已被取代。部分完成、提交未知与查询不可用另保留已知范围，不强行映射为待答或已关闭。

### 唯一的有效处理与共同提交

- 一张卡至多一个有效决定。两个入口、多个客户端、答复与失效的竞争由原等待协调者在同一排序边界裁定，不因两次独立的资格检查都通过而确认两份决定。
- 共同业务单元包括：卡片的有效决定、原等待收到它的耐久收件箱项、原操作终态与待交接责任。只有这个单元确认成立，原消费位置才拿到可消费的决定。保存明确失败答真实失败；保存未知沿原卡片与原提交身份查询，确认成立才进入消费，仍未知或查询不可用则保留原关联与下一次查询的责任。竞争入口的「已处理」或「冲突」同样以权威结果为准，前一提交未知时不先答已处理。
- 技术重传复用操作身份；人的新提交用新身份，即使文本相同。同一卡的另一提交答 `already-decided`，只有当前有读取资格的人能看到已有决定的投影。先核资格，再查去重回执，旧成功回执不泄露内容。
- 写操作的结果是封闭集合：成功、已决定、已失效、冲突、拒绝、非法输入、预算不足、不可用、未知。未知只表示提交可能成立，不返回新的操作身份。

### 原等待、终局与交接

- 原等待的有效状态与业务终局由原拥有者决定。原工作已终局、合法控制解除等待或会话归档生效之后，未答的卡失效并记下依据与原因，不再接收新的有效答复；已成立的决定保留，交接时结算为已被取代，不复活工作。运行时退出、交付面关闭或不可观察都不是终局依据。
- 带会话的来源，登记与答复必须在同一次提交里经 Session 的守卫核对原工作仍在进行；装配没有给出会话守卫时答不可用，空守卫清单不表示不适用。失效与交接确认不经守卫：失效正是原工作结束后要做的事。
- 守卫拒绝一次答复时，原工作已不在进行：卡片已有终态的，答复的人得到卡片的终态（已失效及原因，或已有的决定）；卡片仍待答的，答冲突（守卫拒绝）。守卫拒绝使整笔提交回滚；同一操作身份之后被封口，重试答「已封口」。
- 恢复按稳定目的地与等待身份进行。仍在等待的等待由原拥有者绑定新的接收者代次：比较预期代次，原子分配严格递增的新代次；客户端自报的代次不取得所有权。读收件箱与接手都要求当前代次，旧代次答 `stale-generation`。读取不确认接手，也不删除决定。
- 接手在一次提交里记下消费回执、增加回执计数、推进检查点并移出待接手集合；同一决定再次接手认回原回执。仍在等待的等待只在整批卡片都有耐久消费回执后才成为可继续。已终局且从未绑定接收者的等待，可由原拥有者按当前代次直接结算为已被取代，不建立接收者，不进入可继续。
- 交接确认（`acknowledgeDelivery`）只接受原拥有者保管的完整消费回执，不凭界面已读或新代次伪造。

### 资格、受众与披露

- 呈现、答复、查询、恢复读取与通知内容各自携带可信主体、租户、目标与用途，核对当前对应的资格；跨租户默认拒绝。共用账号、工作区、实例、缓存、名字或旧批准都不授新权。条件失效或不能确认时，依赖它的操作被拒，合法事实与未完成责任仍保管，不向无权方泄露内容。
- 受众在登记时由原工作拥有者固定。来源为 Tool 或 Agent 的卡：读者是出卡方自己与该租户入口主体，答复者只有该租户入口主体。于是这个租户的人用任何一次登录都能读卡与答卡，别的租户读不到也答不了，出卡方能读不能代答。当前成员资格在每次读取与答复时重核。
- 会话入口与待办池读同一张卡、走同一个提交，一卡一决、资格与守卫都相同；入口不改变机制，也不写进会话历史。会话历史只经原拥有者已有的路径写入一次。
- 每次写入与原操作查询先核验已签发主体、当前成员资格、所需资格与租户；原操作的 actor 必须等于该主体的稳定引用。写入只在提交期间短暂保留资格，等人期间不持有保留；已提交结果的重放也重核当前资格。目标端先封口时，迟到的原提交不能成立；提交先成立时，撤权保留历史结果，之后的披露仍重查资格。

### 查询与池

- 池列出有资格读者的待答卡，默认只列待人处理的；显式可查已答未接手与历史。池不另存决定权威。
- 一页在一个快照里读修订、目录键与卡片正文，按请求登记序号与请求内卡片顺序排列；游标签名绑定 actor、租户、位置、规范过滤条件与快照修订，修订变了答冲突，不把新旧内容混在一页。游标不是读取资格。
- 输出预算先耗尽答 `partial` 与有效续页；单项放不下答 `limited`，不截断原话；存储失败答不可用，不跳过故障宣称完整。
- 过滤带会话引用时是会话入口，只列来源带这个会话的卡；过滤来源种类只选该种类。待交接列表只向原消费者披露还没被它接手的决定。

### 等待与执行名额

- 一次 Ask 等人只挂起这一个调用；同会话其他已准入、无显式依赖的调用照常可运行；一个会话的 Agent 循环等人不阻塞别的会话。已有显式依赖、同一次 Ask 的全部问题、同轮扩展判断的屏障保持，作用域被记下，不扩成全局屏障。
- 等待时可靠保存继续状态，释放执行名额、共享写事务与跨调用锁；唤醒只是让人去重读。同一次 Ask 的全部问题都处理（跳过也算已处理）才解除这次 Ask；同轮扩展的全部判断齐备之前，任何获准动作都不执行。
- 整批答复被可靠接手之后，原调用进入可继续，保留原答复与继续位置，按原调度拥有者的公平策略重新取得名额才继续；取得名额与实际继续之前重核原终局、接收代次、当前权限与批次屏障。答复接手之前就没释放名额的调用保留原名额直接继续。人不需要重答。
- 等待期间普通输入、后台结果与控制照常受理；普通消息进原队列，不被猜成卡片答复。受理成功、控制生效与等待解除分别确认。
- 斜杠命令的提示词与 Skill 分支是普通消息，系统流程命令交实际拥有者；都不因为某张卡存在而成为它的答案。MCP 的静态凭据与 OAuth 凭据沿资产持有与配值资格取得，不经 Ask 或 Run 扩展代办。
- 成员资格失效限制之后的读取、答复与新准入，不销毁租户、不删会话、不等同归档；重新加入同一组织恢复同一租户的资格，不复活旧终局，不重建旧卡。自动归档由会话拥有者按配置与真实的连续空闲判断，隐藏卡片不证明空闲。

### 授权与提示的组合

- 系统准入先算结构化权限、授权表达与会话模式；明确禁止直接拒绝，不出请求放宽的卡。系统卡只给当前有权且写入后能生效的选项；能访问会话不推导出修改租户设置的资格。仅本次与本会话的范围沿原授权规则；租户持久选择写入租户权限设置，受真实写设置资格与组织上界约束，设置是否生效以设置拥有者的实际回执为准。
- 有效决定只适用于原动作、生效参数与匹配的实现和依据。参数、实现或授权依据变了，不自动复用旧批准，由原继续执行者重新核对。人的批准、准入与实际环境隔离条件分别成立。
- 每个阶段只登记它需要的保护：保存人的答复只需当前身份与读答资格、卡片状态、原等待未终局与这些资格依赖的外域事实，不要求原运行时在线；把答复解释成许可或写持久规则另需当前批准资格与提交参加者；恢复继续或执行动作另需原动作绑定、执行采用围栏、许可消费与执行容量。
- 提示在请求确认之后才产生，由来源业务给出获准目标与内容，交 Notification 承接；发送、送达、已读、有效答复与原工作完成分别确认。提示失败不删除卡、不代答、不重做产生卡的工作；通知内容按当前披露资格裁剪。

### 恢复、换代与撤除

- 已有结论不重判，已有答复不重出同一张卡，未完成的调用按原身份认回；版本或依赖不兼容时保管原进度并报告受阻，不替人给新答案，不把「扩展不在」当作人拒绝，更不默认批准。
- 运行时实例换代不改变同一会话的 Agent 定义身份、原 Run、原调用或卡片身份。提供者只撤自己的登记、订阅与临时使用权；旧代次的清理不删新实例或别的租户的数据。有序停服不是打断：等待与卡片原样保留，重启后由原拥有者接回。
- 应用服务关闭时先拒绝新调用，再排空已受理的读写，最后关闭内部适配器；关闭后的调用答不可用，不冒充可能已提交的未知。关闭不删请求、不终结业务等待、不关闭共享存储。
- 关系守护发现投影缺行、多行、错关联或计数不一致时，相应实例的查询结果不能再解释为「没有工作」：停止路由、关闭并排空，维护期间答不可用；恢复只消费原拥有者的可信事实，不重新执行登记、答复、消费或外部动作，重开前核对全部关系守护与原结果认回。

### 存储与表示

- 每张表只有一个写参加者；本组不读原等待、资格、配值或授权的私表，它们以事务事实进入。终态 `committed` 不是业务成功，完整业务结果从原 SQL 操作日志读回；日志暂不能确认答未知，结果损坏答不可用。封口只在认回耐久的中止之后才答 `not-committed`。
- 原操作身份是租户、actor 与 `operationId`；方法与规范命令进入输入摘要，摘要不同即冲突。恢复命令与普通命令各自认回自己一族的原操作，问错一族答冲突。
- 文本与标识是合法的 Unicode：孤立代理项在边界答非法输入；合法代理对、NUL、控制字符、空格与换行按原值保留。预算按原 UTF-8 计量，存储表示必须往返单射，不截断原话，不合并不同标识。修订与接收代次是任意精度的十进制文本，序号以十进制字符串传递。
- 一次答复只读这一题和这张卡；中间回执只保留原绑定与计划摘要，不复制整批历史答复，合法批次的累积不触发回执上限。

## 原则与约束

- 卡片不是决定权威。人的答复由原拥有者解释，许可由 Authorization 发，设置由 Settings 写，执行由原执行者做。
- 没有人回答就没有答案。时间、通知、界面、脚本与扩展件都不能替人作答；导入钩子的「允许」只按无意见解释。
- 几件事分别确认：答复保存、原等待接手、继续执行、授权生效、提示送达。一件成立不推出另一件。
- 结果不知道就是不知道。按原操作身份查询与封口，不换身份重发，不写成成功或失败；查无记录不是未提交。
- 等待是耐久事实，不是占着的资源。等人不持执行名额、写事务或锁，不阻塞独立的工作。
- 只撤自己的那一份。换代、关闭、撤除只影响本代次、本提供者的贡献，不删历史，不复活终局。
- 交接与提交的协议有形式模型与关键性质检查，模型在 `human-intervention/verification/`，对照见同目录的 `formal-mapping.md`；有限检查通过不等于实现符合。
