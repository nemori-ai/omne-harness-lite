# 工作区成员内部设计

状态：具名目标的技术设计草案。只有文档，尚无运行成员、公开类型或支持证据。公开必要行为归[完整 SPEC](../SPEC.md)，本页拥有数据身份、算法、并发、失败及恢复的机制说明。

## 状态与处理算法

以下状态描述可观察事实，不指定字段枚举或存储实现。逻辑工作区的存在与实例可用性分开；关系可有效或已解除；地址可可用、不可达、无资格或未核实。暂时不可达不进入“逻辑已销毁”，未知查询不返回“不存在”。托管销毁过程还须区分未获准、待确认效果、已确认销毁但关系未收敛、已经收敛；记录足以恢复原动作的依据。

显式接入先核验主体、目标、身份匹配依据和资源条件，再建立或采用关系及实例关联。Session 将明确选择交装配作为候选；有效参与条件、适用组织政策、实例条件及当前来源读取资格成立后，可以读取并校验该候选。来源校验通过且采用与交接条件成立后，Session 才确认当前选择已正式采用并报告附着成功。已有内容保持原样；关系同步与文件同步分开。若登记及关联已确认但来源或装配失败，分别报告已登记和未采用，不撤销已经确认的业务事实；首次没有原采用时工作区层仍为空，已有原采用时保留原采用记录，后续资格仍各自核验。

治理配置列出授撤、移除与销毁资格及合法修改者，不能由工作区文件定义授权。旧 PF 的创建者/不可转授超管方案只作为具名策略候选，不排除获明确授权的组织治理模型。是否已有同一逻辑资源不能只凭相同字符串判断，身份匹配协议见技术义务。

来源读取按以下顺序推进：

1. 确认 Session 的明确候选选择、有效租户关系及实例条件，取得此次实际装配适用的参与政策依据，并核验当前来源读取资格。这些条件成立后可以读取候选，无须等候装配完成；校验及采用与交接条件未成立前，候选来源不生效。
2. 读取两根配置；缺失按声明默认发现范围处理，已存在但无效则阻止候选，保留旧合法采用状态。
3. 发现约定原生位置及明确扩展范围，排除软链接和经过软链接的路径；读取配置不执行代码。兼容来源仅在有效准入允许、格式受支持时加入。
4. 保留每个候选的身份、实现和来源；将禁用、资格、锁定及受限配置过滤交资产拥有者，不在工作区层另造权限合成算法。
5. 同层可用原生候选按类别＋name 取并集，local 优先；本地被过滤不遮蔽共享。兼容候选低于合法原生，第三方不同内容冲突显式选择，去重避免重复执行。
6. 设置按声明项合成，local 显式值优先，完整实现及其配值边界保留；把可解释材料与一致读取依据交装配。AGENTS.md 等规范文本独立交 Context，不加入这套合并。

来源快照不是全局资源事务。读取提供者须证明本次组合对应可成立的读取版本；文件变化导致无法取得一致依据时重新读取或明确失败，不能声称混拼内容已校验。外部资源同步沿管理类型语义，不宣称全部实例原子更新。

## 并发提交与版本采用

确认业务事实要满足[数据与状态](../../../../docs/architecture/data-and-state.md)的保存边界。身份、关系和其授权变化不能发布相互矛盾的成功结果；跨存储或外部效果无法同事务时，用明确过程与恢复状态保持业务可判定性。技术方案须说明谁提交、何时对外确认、如何识别原动作以及恢复查询依据，不能以“将用事务”替代契约。

来源读取完成与候选采用分别确认，读取成功不改变 Session 的当前正式采用。Session 拥有当前选择，装配协调候选版本、当前选择和推进权之间的竞争处理；新选择和取消优先于迟到候选。工作区提供可复核的关联和版本依据，不向迟到候选继续声称关联有效。已经发出的调用保留原工作区、环境和输入；关联变化不改写历史效果。

`.omne` 每次变更属于该工作区所采用的共享同步范围，面向获准租户共享，不能任意永久排除。具体资源提供者沿管理类型的原生机制和策略处理同步，仍可异步、按需，原生冲突可以保留，但操作结果须精确到实际目标和原工作。Git worktree 是资源管理构造，显式关联才是 Omne 实例事实。共享文件冲突、关系变更和装配竞争各归其拥有者，不能用一个“最后写入胜出”覆盖全部问题。

组织参与政策按实际装配判断；关系有效性、普通资源授权及单次使用准入仍按各自契约。候选失败保持原采用记录，仍不延续其已经撤销的资格。后续准入、读取、结果交付及消费确认按当前授权核验，条件不可取得则阻止依赖允许结论的新动作。授权失效不能被旧来源快照洗成成功，工作区也不自行增加组织政策每次写入的热同步。

## 失败、取消、销毁与恢复

网络超时分不清“未执行”和“执行后未收到答复”。提供者返回已知效果和未知部分，消费者围绕原操作查询或等待；有确证的未执行或安全重试条件才发起后续动作。查询接口不可用也不能降成空结果。冲突、超限和格式错误保留原件与诊断，不静默替代工作区或忽略来源。

托管资源确认销毁后，逻辑使用及所有关系不得再表现有效。工作区治理负责让关系收敛，资源提供者负责效果证据；收敛未完成可见并可恢复。确认销毁后的恢复只推进未完成清理，结果未知先核对原效果；不重复删除外部资源。外部参与退出只操作自身关系，不走托管销毁分支。

取消是控制请求。取消登记、同步或销毁后仍保留已经确认的效果及必要查询状态，不能把取消当资源恢复。来源读取临时句柄由读取者释放，实际环境、持久实例和托管资源分别沿其生命周期管理。结束 Session、dispose 装配或退出关系不清除本地目录，也不证明真实执行已经停止。

成员退出期间的租户私有材料归身份及资产保留规则，不由工作区关系删除改写。执行环境报告实际落点变化和痕迹保留，Context 供给 agent，工作区只报告自己的关联变化。


## 技术后续设计与来源缺项

以下事项由技术或来源拥有者补足，不转成产品默认值投票。公开形状、机制与证据未定不删除既定必要行为。

### Q-WS04 身份解析、公开形状与关联有效条件

维护责任：workspace/workspace 的身份与关联设计拥有者。

场景：已有路径和 remote 无法单凭字符串证明逻辑身份；消费者需要可靠选择与恢复原关联。

待明确：成员技术设计如何表达身份、匹配证据、实例/地址有效条件、原工作引用及单次资格核验？

既定约束：

- 地址不是身份或凭据，同地址不自动合并，实例不固定租户。
- 不得从目录或尚未建立叶包反推公开 API。
- 身份、实例与版本分为三轴，见 [#679 的裁定](https://github.com/nemori-ai/omne-harness-lite/issues/679#issuecomment-6443061282)：身份的文本形式是 legal-identity 第六族 `WorkspaceId`。实例标识与装载依据组成的工作区附着暂由 [session-contract](../../../session/session-contract/SPEC.md#消费者资格与输入) 持有，迁回本域见 [#837](https://github.com/nemori-ai/omne-harness-lite/issues/837)。

处理方向及后果：

- 比较有明确来源的显式身份声明与匹配验证方案，并保留冲突结果。
- 对不能证实的身份关联拒绝采用或报告未知，等待来源补证。

不代负责人选择；本候选隔离未选范围。

影响：技术拥有者补公开类型及协议；身份和资格行为已有完整候选，不作为用户默认值问题。

### Q-WS05 一致来源读取、配置及兼容判定协议

维护责任：来源读取提供者、资产与装配拥有者。

场景：读取期间发生文件变化，扩展路径和重复兼容来源尚无精确协议。

待明确：来源提供者如何固定读取依据、定义路径基准/glob/去重、Schema 和兼容转换，并保证真实组合仍可解释？

既定约束：

- 不得混拼校验状态；错误 local 不回退；软链接不跟随；来源读取不执行。
- 类别格式及 hook/MCP 专有运行规则归对应能力，工作区不重写。

处理方向及后果：

- 设计版本化配置与可核验快照/一致读取协议，失败保持采用记录且继续当前授权检查。
- 无法取得一致来源或可靠转换时明确失败，隔离相关能力至协议补足。

不代负责人选择；本候选隔离未选范围。

影响：来源提供者、资产、装配与兼容成员须技术接受后方可实现。

### Q-WS06 确认边界、效果查询与跨拥有者恢复

维护责任：工作区治理、存储与资源提供者。

场景：登记或销毁提交后确认丢失，或资源已销毁而关系清理未完成。

待明确：工作区、存储与资源提供者如何识别原操作、提交一致事实、查询效果并收敛关系；所选提供者和部署能证明什么？

既定约束：

- 未知不等于未执行；取消不证明物理停止。
- 销毁确认后关系不能继续有效，本地文件不清理；原动作不可盲目重做。
- 确认业务事实须达到已声明耐久边界，外部效果独立核验。

处理方向及后果：

- 比较具备原操作查询和可恢复收敛状态的协议，固定参与拥有者与确认点。
- 提供者不能查询或证实安全重试时保留未知并隔离依赖推进，不伪装恢复成功。

不代负责人选择；本候选隔离未选范围。

影响：选择技术协议、存储前提、Git托管及必要故障验证；不承诺全局恰好一次或任意副作用回滚。

### Q-WS07 兼容格式及目录指导的精确外部依据

维护责任：兼容能力与 Runtime Context 来源维护者。

场景：旧 PF 规定兼容范围和目录指导责任，但未给可采用的精确版本矩阵及全部社区规范依据。

待明确：对应拥有者在哪个版本固定官方格式/规范依据及源码或验证补证，并声明未支持范围？

既定约束：

- 本轮不开展新外部研究、不臆造第三方保证。
- 目录指导归 Runtime Context，兼容贡献归具名能力；两者不互相代证。

处理方向及后果：

- 由对应拥有者补精确来源、版本及验证范围后采用。
- 缺依据时隔离相应兼容/目录指导细节，保留既定责任与拒绝规则。

不代负责人选择；本候选隔离未选范围。

影响：阻止对第三方未证行为作支持声明；不把来源缺证包装成产品选择。
