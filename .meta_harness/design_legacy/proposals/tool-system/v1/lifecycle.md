# 以依赖、效用与撤回组织能力

本页是[候选草案](README.md)的建模起点。语言无关规则在前，Cordis 承载方式
见[装配章节](assembly.md)；上游语义及局限见[来源核对](../../../research/cordis-lifecycle-and-tool-composition.md)。

## 定义、激活、效用与调用

一份工具或 skill 的定义可以长期保存。将它用于某个运行范围，则形成有所有者
和依赖条件的激活：它向环境贡献可用能力，退出时撤回自己产生的贡献。实际
调用借助这些能力产生业务结果，其寿命和结果不能被直接等同为激活的寿命。

| 概念 | 对工具/skill 的含义 |
|---|---|
| 定义 | 精确版本的契约、代码/资源与组合声明；卸载不删除已保存定义 |
| 激活 | 某所有者在明确范围内对选定贡献的使用；依赖满足时建立效用，失效时撤回 |
| 所需条件 | 必需的服务、内容条目、环境、版本和使用资格；运行期间持续求值 |
| 效用 | 对当前环境的受管贡献，例如工具入口、命令路由、指引、变量、挂载、监听和策略 |
| 逆效用 | 按贡献身份撤掉该项效用，释放其拥有的资源或使用关系；不覆盖别人的后续变化 |
| 调用/尝试 | 已获准的实际工作与效果，引用当时绑定；接续、停止及业务撤销另有契约 |

这不是要求实现六个通用类，也不要求每份静态文件有独立 Fiber。需要独立的
激活/撤回边界时才设相应运行所有者；多个一起生效的注册可以由同一组合插件
拥有。贡献与依赖是架构核心，持久记录负责保存事实，而非代替真实生命周期。

## 依赖关系与所有权关系分别表达

“Tool T 必需 Skill S”表示 T 的相关使用效用以 S 在该范围有效为条件；不表示
T 拥有 S 的全部生命，也不表示 S 卸载就要删除 T 的定义。多个工具或用户显式
加载都可使用 S，各自拥有使用关系。释放其中一个关系只能释放自己的份额。

初版依赖边至少说明：目标能力/条目及精确解析规则、作用范围、必需或可选、
条件的有效期、失效时应停止哪些贡献，以及对已接纳使用的政策。关系是动态
定义的组成部分；修改关系也要经过与定义更新相同的版本和发布边界。

所有权边说明谁创建、谁能撤除和谁等待释放。依赖失效引发消费者撤回的范围
由依赖边决定，清理资源由所有权边执行。不能把一棵插件父子树同时当作租户
关系、授权继承、全部依赖和业务工作树。

## 一次工具组合的具体生命周期

假设一个多命令 `workspace` 工具含 `status` 和 `save`，只有 `save` 必需
Skill S，同时需要存储服务 F：

1. 插件贡献精确定义、实现与 Skill S 条目。目录能提供获准摘要；这不立即使
   Agent 获得业务命令，目录贡献和使用贡献有各自的所有者。
2. Agent 按需使用该工具。组合激活解析 S 与 F，并在该使用范围建立 S 的内容
   使用关系、资源定位及 `save` 的绑定。必需条件尚未满足时保留等待原因，
   不发布半套可调用组合；`status` 可以独立就绪。
3. 激活产生一组关联效用：同一个工具槽位下的有效命令集、相应帮助、Skill S
   的指引贡献及所需资源访问、命令分派绑定和必要的变化订阅。下一请求将这些
   贡献一致投影；本次请求的正文完整性仍按[定义章节](definitions.md)验证。
4. S 在该范围停用或失效时，`save` 的使用激活失活：撤回其可调用绑定、命令
   帮助中的可用性、关联指引和仅由该激活拥有的资源/订阅。`status` 和其它
   独立消费者不受无关撤除影响。原定义与有权读取的发现摘要可以继续存在。
5. 条件恢复且期望使用关系仍有效时，重新解析并激活，产生新的贡献代次。
   显式取消的使用关系不自动恢复；激活恢复也不重执行原业务调用。

一个多命令工具的部分命令不可用时，模型槽位仍最多一个；每个业务调用必须
落在该请求和当前激活都有效的命令集合内。所有业务命令失效时只保留可披露
的发现/帮助入口，不能把一个仍存在的顶层名字伪装成完整可用工具集。

## 效用、逆效用与残留事实

| 正向效用 | 所有者与逆效用 | 撤回之后仍保留的事实 |
|---|---|---|
| 发布工具/命令可调用绑定 | 使用激活撤掉自己的绑定及分派资格，使新准入失效 | 已发模型请求、已接纳调用及定义版本 |
| 提供 skill 指引、帮助和动态变量 | 组合激活撤回对应来源的提示词/变量贡献，更新后续请求投影 | 历史内容证据；不能让模型“忘记”已发送内容 |
| 取得 skill 资源挂载或只读资源访问 | 持有者释放自己的挂载/访问关系，最后一个使用结束才释放共享资源 | 原始内容资产；获准持久保存的业务制品另行管理 |
| 事件监听、watcher、计时器 | 创建它的激活取消监听、关闭 watcher/计时器并等待受管回调 | 已产生的事件与真实外部效果 |
| 作用域限制、提示词覆盖或呈现选择 | 按贡献 token 移除自身一层，重新求值剩余贡献 | 其它所有者的限制、覆盖和权威授权 |
| 启动工作并附着前台观察 | 执行所有者拥有工作；会话只释放观察/等待，是否停止由控制契约决定 | 后台工作、过程、结果与费用 |
| 执行保存、发布、通知等业务动作 | 按领域契约停止、撤销或补偿，不能用插件卸载替代 | 已发生的持久/外部效果及不确定性 |

“逆”针对自身贡献的身份执行，不能简单恢复加载前整个 Map、提示词或配置
快照。例如 A 与 B 各增加限制，撤掉 A 后保留 B；局部覆盖退出后显露的基础
定义必须重新经过当前资格检查，不能因栈回退绕过权限。涉及必需安全策略的
贡献失效时，依赖该策略的新准入必须关闭，不能以“恢复默认值”为由放宽。

Tool 卸载释放其独占 skill 使用；S 仍被另一个工具或显式 skill 使用关系持有
时，不撤掉那些消费者的内容。反过来，“停用 S”是改变提供资格并使相关依赖
失效，不等于只释放一个消费者。全局停用、租户范围停用与会话取消使用的
影响范围必须由操作目标表达，不能混用一个无范围的 unload。

## 撤回是协议，不是一个布尔值

对受控的停用/更新，建议按以下语义顺序处理：关闭受影响的新准入，标记贡献
代次失效；撤回当前可用集合及后续上下文贡献；处理已接纳工作；释放独占资源
与共享使用关系，最后报告撤回/清理结果。独立步骤可以并行，有依赖的释放必须
等待前置结束。可调用性撤回与物理资源最终释放分别可观察。

各组效用在对消费者可见之前先纳入拥有者管理，避免初始化中途卸载漏掉资源。
多项贡献以同一激活代次供请求组装读取，组装提交前复核代次；有变化则重组。
不允许形成“Schema 是新版本、skill 是旧版本、路由已卸载”的成功请求快照。
已发请求无法撤回，返回的调用仍需核对当前准入条件。

建立失败撤回已建立的受管贡献，撤回失败记录残留与影响范围，关闭受影响入口。
共享存储里不能仅记 inactive 就假定监听、进程和路径已消失。初始化晚到回调
不能在失效代次重新发布贡献；资源必须归属有效所有者，否则立即进入清理。

若依赖意外消失，激活立即失去对新消费者的有效性；不要求等待昂贵清理完成
才阻止新调用。后台工作能否继续，取决于它实际持有的独立资源是否仍有效。
恢复只为当前有效期望重新建立贡献，不把旧缓存或未完成调用当作自动挂载许可。

## 在途工作对 Cordis 所有权的要求

为了让转后台后的工作跨会话实例继续，从启动起把实际执行及必要服务代次放在
独立执行所有者下；会话激活只拥有调用入口和观察效用。其逆效用是撤回这些
入口与观察，不是暗中取消独立工作。用户的普通 Run 中断仍显式控制自有后台
调用，两条生命周期不能混为一谈。

若需保留旧调用排空，旧实现及它的依赖必须在真实资源所有权上仍然存活，例如
在独立实现代次范围内运行，发布入口可以先撤除。不能先对唯一提供者执行 HMR，
再假定引用计数能阻止 Cordis 卸掉其消费者。不能共存的提供者采用显式停止/
占用冲突政策；意外丢失时不承诺旧工作继续。

后续实现不必另造 Cordis 生命周期引擎。服务依赖和受管效果直接复用 Cordis；
工具/skill 条目级的依赖激活由相应注册与装配能力管理，并将取得的使用关系、
订阅及派生贡献纳入 Cordis 所有者。需要补足的是产品层条目的含义、使用边界
和撤回结果，不是再建立一套与内核相互竞争的通用插件框架。
