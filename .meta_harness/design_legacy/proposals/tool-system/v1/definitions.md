# 定义、模型呈现与 tool–skill 依赖

本页是[候选草案](README.md)的一部分；所有字段名和示例为讨论记法。
定义的激活、依赖失效及逆效用沿[生命周期模型](lifecycle.md)，不能把以下
使用条件仅实现为静态字段和调用时布尔检查。

## 工具与操作

工具定义是可保存、可比较版本的语言无关数据。其来源是某插件版本的工具贡献，
可有稳定成员身份，但不要求每个工具、命令、服务都成为独立顶层资产。
定义版本与实现代码版本分别标识，并通过装配绑定；修改命令含义不能只改代码
而继续声称契约未变。

| 内容 | 候选语义 |
|---|---|
| 身份 | 所属资产/插件的精确版本、成员标识、定义契约版本；租户选用关系另行引用 |
| 模型表面 | 普通或多命令、名称建议、用途摘要、命令目录和帮助资源 |
| 操作集合 | 普通工具的一项操作，或多命令工具的命令集合；每项有独立稳定操作标识 |
| 数据契约 | 每项操作的输入/输出 Schema、错误含义、媒体与制品引用；不存在的字段不静默忽略 |
| 使用条件 | 模型与环境要求、必需 skill、可披露范围；定义声明与可信策略共同求值 |
| 执行能力 | 是否支持后台、停止、过程订阅、恢复检查点或外部工作重连；声明需执行器兑现 |
| 过程声明 | 操作可产生的帧类型/版本、载荷 Schema、记录等级、媒体及合并条件；见[过程帧](frames.md) |
| 动作解释 | 实际目标与副作用分类的可信求值接口，供授权、HITL 和预算使用 |

函数、Cordis Context、服务实例、进程对象和临时文件路径不属于持久定义。
作者可使用 TypeScript DSL 同时编写元数据和实现，但发布时必须区分可验证数据
与执行代码；运行时不能通过反序列化定义获得任意执行权限。

模型别名只在一次请求的工具清单内有意义。服务端保存该请求的别名到精确工具、
可见命令、实现绑定和技能内容的映射；实际调用根据该映射解析。不能把返回的
字符串工具名直接交给“当前注册表”而无声换成另一个版本。

## 多命令工具：一个槽位，多项完整操作

建议默认以紧凑入口呈现，例如一个 `workspace` 工具接受：

```json
{"command":"save","params":{"working_copy":"wc-7","message":"完成草稿"}}
```

顶层 Schema 声明 `command` 为字符串、`params` 为对象；每条命令的完整 Schema
由内部操作定义拥有。运行时在任何副作用前按具体命令校验参数。模型适配器应
验证目标模型经 OpenRouter 对该形状的支持；无法表达时显式选择受支持投影，
不绕过统一模型出口。

同一入口提供 `help` 元操作：无目标时读取可披露命令摘要，指定目标时取得该
命令用法、参数及依赖条件。`help` 保留为协议命令，不被业务操作覆盖。读取帮助
只要求相应内容披露资格，不因为写入命令需授权就禁止理解其申请条件；不可
披露命令不泄漏名称和参数。帮助不会自动执行资源中的脚本。

对于小型闭集工具，可以显式选择完整类型联合，仍保持一个顶层工具条目；它
消耗更多 token。`help` 和业务操作的呈现均从同一操作定义派生，不维护两份
易漂移的 Schema。Unix CLI 类比不自动引入 shell 词法、任意管道、重定向或
批处理。DSH PTC 的程序化嵌套调用是另一个范式，不代替本项要求。

例如 `workspace status` 与 `workspace publish` 虽共用入口，后者仍需按实际
目标与外部效果授权；调用、过程、费用和审计必须能定位具体命令。模型自报
“已读帮助”“已获批准”不提供授权事实。暂不引入来源系统的 HOLD/ack 协议。

## 依赖声明与使用条件

用户确认的 [PF-014.C6](../../../requirements/product/agent/PF-014-runtime-tool-and-skill-discovery-and-loading.md)
意味着必需技能参与工具使用激活及撤回。本稿建议同时支持工具级和操作级的
必需 skill 声明；前者由全部业务操作继承，后者只约束指定命令。
下面区分依赖目标的具体满足条件，两者都需要持续响应变化及清理其派生贡献。

| 依赖 | 例子 | 满足的含义与所有者 |
|---|---|---|
| 实现依赖 | 文件服务、Shell 执行器、凭据代理 | 对应范围的服务存在、实际就绪、版本/环境匹配；由装配与提供者检查 |
| 使用内容依赖 | `publish` 必须配套发布流程 skill | 获准读取的兼容精确内容及必需资源可达，核心指引进入产生该调用的模型请求；由内容与上下文装配检查 |

Skill 的持久内容不必拥有常驻运行进程，但将其用于某个范围所产生的指引、
资源访问、绑定和订阅必须有激活所有者。可由插件注册内容贡献及其取得/释放
接口，再由使用组合拥有具体效用。不能仅创建一个占位服务并以服务存在证明
模型获得了内容。[动态装配](assembly.md)说明这与 Cordis 生命周期如何衔接。

依赖声明至少定位 skill 身份及兼容约束、适用操作、解析范围、必需核心内容、
资源需求及有效期/失效响应，贡献撤回遵循生命周期页的共有规则。
兼容约束用于解析，发布的绑定记录解析后的精确版本与内容摘要；不能把 `latest`
留到执行时解析。资产版本选择、读取权益与当前权限仍归各自权威能力，声明
不能借依赖自动安装或授权。首版支持工具/操作直接要求多个 skill，不预设通用
依赖图引擎；嵌套资源引用按内容包解析，存在未解析依赖或循环时明确拒绝就绪。

## 装配到请求，而不是只登记“曾经读过”

建议使用以下流程：

1. 发现返回摘要、需要的 skill 和可用/可请求/不可用原因。只见到目录不获得
   执行资格；常驻发现/装载入口负责引导取得缺失内容，避免只能先调用受限工具
   才能读取其依赖的死循环。
2. 解析所选工具的操作、精确 skill 内容、实现和环境。缺少必需 skill 时可以
   显示帮助或待装载状态，但不将受影响业务操作标记为可调用。
3. 为下一次模型请求一致投影有效激活贡献中的工具清单及必需核心指引；相同
   skill 精确版本去重但保留各自使用关系。
   同一使用范围内若要求不兼容版本，先拆分可暴露操作集合或报告冲突，不将
   相互冲突的指引静默拼在一起。引用附件定位实际宿主/沙盒资源。
4. 上下文组装器产生可信的请求记录，关联工具投影、精确依赖与已纳入内容摘要。
   不接受模型参数充当这个记录。发送之后记录不可修改。
5. 调用准入同时核对请求记录、实际操作所需依赖和当前可用资格。内容撤回或
   绑定失效可使旧请求返回的调用无法接纳；返回明确原因并允许下一请求重新装配。

这提供“必要指引确实提供给此次模型请求”的可检查条件，不能证明模型理解或
遵守指引。机器可执行的约束必须进入运行时策略或操作契约；skill 中的文本
提醒不承担权限、安全隔离和副作用控制。

压缩、截断、模型切换和会话恢复都要重新计算上述条件。初版建议保留必需核心
正文，不把任意摘要或历史读过标志等价为完整依赖满足；超出窗口时缩小工具/
命令集合或报告预算不足。只占一个工具槽位并不免除 skill 与帮助的 token 成本。
允许精简正文时，应发布有明确兼容性的内容投影，而非即时无依据删节。

模型调用前读取附件不必把全部文件装入上下文；声明为必需核心的内容必须在
请求中，附件只要求获准且路径可达。运行期间脚本、文件、网络操作仍通过各自
执行权限。正文里的指令不因来自 skill 而提升优先级或获得任意代码能力。

## 生命周期与非模型消费者

Skill 更新或撤回触发相关使用激活失效，撤回派生入口、指引及独占资源，并使
后续装配重新求值；已发送请求保持历史原样，未接纳调用按当前状态检查，
已接纳调用保留原绑定及证据。运行中的工具实现不会因
说明文本更新而换成新代码。紧急撤回是否需要停止在途工作由显式控制决定，
不把内容卸载隐式解释为业务撤销。

后台重连延续已接纳的调用，不要求不存在的模型请求重新“阅读 skill”；接续
需要新的模型决策时，则在该次请求重新满足依赖。受控程序化消费者使用操作
契约，需声明其消费方式和调用来源，不能伪造模型上下文记录。若依赖确实要求
人类或模型参与某步骤，程序路径不能用读取文件绕过它。具体消费者类型进入
后续契约，本稿不承诺任意直接调用实现的入口。
