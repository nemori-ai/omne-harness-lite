# 候选与取舍

## 选择对象与必要约束

保持租户隔离、旧代际安全、状态权威分离、动态撤除和失败可见；不以源码复用降低这些性质。

| 候选 | 必要性质如何兑现 | 总负担与关键反例 | 结论 |
|---|---|---|---|
| A：受管 attachment + 一次短共同撤销屏障 | 门外准备、门内复核并发布；精确注册身份控制释放 | 提供者须加入同一协调协议并报告 unknown | 旧 D-007 已接受 legacy 范围；新谱系推荐等价承接，待 I 接受 |
| B：准备前分别检查权限/Session，完成后直接发布 | 接口简单、提供者独立 | 准备期间撤权/归档/卸载可穿过检查，产生陈旧发布 | 被并发反例排除 |
| C：把 Session 可变对象和所有资源纳入 Agent Registry | 单对象锁可暂时避免部分竞态 | 混合长期事实与临时实例，实例退出会威胁历史/独立工作，动态替换边界消失 | 被状态权威与恢复要求排除 |

## 推荐与仍待区分的事项

推荐 A，因为它保留已验证有价值的机制并把产品语义留给自有契约。新 baseline 的接受、provider 实现与真实组合证据仍待完成；源码或 Cordis 版本变化时重新核对。
