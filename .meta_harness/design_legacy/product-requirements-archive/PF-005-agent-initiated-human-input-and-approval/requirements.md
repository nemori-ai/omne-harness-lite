# PF-005：智能体主动提问、请求授权与答复接续

[智能体维度](../by-agent.md) · HITL 来源核对（迁移坐标：`.meta_harness/design/research/agent-initiated-hitl-sources/research.md`）

主维度：智能体。副维度：用户，关联用户接收问题、作出决定和管理待答事项。
HITL 在本项指智能体主动邀请用户提供信息或参与决策的流程。

## 已确认要求

2026-09-12 用户明确：“智能体应当具备主动向用户发起问题、请求用户授权的能力”，
并指定 `omne-next/omne_harness` 中 agent 发起 HITL 的要求作为对应来源。

主动提问和请求授权由用户直接确认。以下将它们与
[SYS-CONTINUITY](../../system/omne-next-continuity/requirements.md) 授权继承范围内的有效来源
要求映射为 C1–C10；来源正文、接受范围及后续修订见来源清单（迁移坐标：`.meta_harness/design/research/agent-initiated-hitl-sources/research.md#来源与确认范围`）。
原系统已接受的要求与已承诺的未来要求分别记录，均不等于已经实现或验证。

- **PF-005.C1：主动提问。** 具备相应能力的智能体能主动向会话 owner 请求
  信息，说明问题、为什么问以及答复将如何影响后续工作。可以提供建议回复，
  用户仍可输入建议之外的合法自由文本。
- **PF-005.C2：请求一次性批准。** 智能体能够主动就拟执行的动作请求用户
  决定；结果至少区分批准、拒绝与仅评论。含糊的自由文本不能被猜成批准或拒绝，
  一次性批准只适用于该请求描述的动作。请求呈现动作与对象、理由、影响范围
  与可撤销性、被拒后的去向及一次性提醒。C1/C2 的内容由发起方提供，缺少的
  元素如实显示，系统不从正文猜造；建议回复不约束用户的合法回答。
- **PF-005.C3：能力授权进入专用流程。** 当需要能力使用权限时，智能体能
  发起相应的专用授权申请，明确能力、动作、目标、必要参数摘要、影响及所请求
  的作用域；可选范围以该能力实际支持且用户有权授予的范围为准。通用问题的
  肯定回复或 C2 的批准不自动建立会话权限、设备持续授权或切换权限模式。
  专用流程由相应权限 owner 裁决；例如设备能力由经身份核验的设备 owner 授予，
  不能仅凭会话 owner 身份代授设备权限。授予、撤销与执行时的实时授权检查
  保持各自边界，智能体不能通过重复申请或改写参数绕过拒绝。
- **PF-005.C4：请求先耐久成立，再向用户呈现。** 问题、来源智能体、会话、
  发起工作、父子关系和当前状态可持续定位。用户能从任何入口作答前，对应等待
  必须已经可靠登记；消息、卡片、通知或链接都指向同一请求，不能出现能答却
  找不到等待的状态。请求标识用于定位，不能充当越过认证与授权的凭据。
- **PF-005.C5：长期等待与运行时资源解耦，答复后可恢复接续。** 等待用户
  不自动超时，也没有默认答案；只因首个有效答复、获授权取消/强停、会话终态
  清理或显式取代而结束。等待期间释放对应执行资源和租约，允许有界的热驻留
  宽限；宽限到期只回收实例，不替用户定夺。等人的墙钟时间不消耗活跃执行预算。
  运行时丢失或重建后，请求及等待仍可恢复；有热检查点时可从停驻处接续，没有时
  凭耐久问题、答复和历史从最近语义边界继续，不能捏造答复或工具返回。
- **PF-005.C6：多个请求各自独立。** 同一 logical Run 可有多个待答请求并存，
  继承来源不为这类人类请求设置数量上限。每条请求按自己的耐久身份定位、作答
  和了结；回答一条不能顺带关闭、覆盖或取代其它条目，也不能要求其余全部答完
  才接续该条答复对应的工作。不同 sub-agent 的请求同样保留各自因果关系。
- **PF-005.C7：只有合法答复产生一次接续。** Agent 主动问题和通用批准请求
  只能由会话 owner 回答；租户管理员可以在其治理权限内关闭工作，不能代答。
  同一请求及其有效代次由首个有效答复胜出，恰好触发一次因果接续；跨设备或
  跨入口重复提交返回已成立的真实结果。普通聊天只有在明确的回复上下文中、
  且目标唯一可判定时才能作为答复，不能事后猜测绑定。已采纳答复保留为不可变
  历史；已关闭请求的迟到答复明确拒绝，不复活等待或触发新接续。
- **PF-005.C8：请求进入统一决策池。** 通用的跨会话呈现、自包含条目、池内
  直接作答及通知边界迁由 [PF-008](../PF-008-unified-decision-pool/requirements.md)
  维护。此身份保留关联：本项请求携带 C1/C2 的内容进入池，池内答复遵循 C7
  的权限及单次接续规则；此次归属调整不撤回原要求。
- **PF-005.C9：条目状态与当前可答性分别可见。** 共同正文迁由
  [PF-008.C6](../PF-008-unified-decision-pool/requirements.md#已确认要求) 维护，本项
  请求同样遵循；当前不可答不关闭等待，可答性投影不替代提交时的真实准入结果。
- **PF-005.C10：批准与实际动作可追溯，越界重新请求。** 部分继承原系统已
  承诺的未来要求：一次性批准的请求与答复作为耐久历史保留，用户可在执行历史
  中按顺序核对请求、答复、随后的动作及其授权门记录，不能只采信智能体自报。
  超出批准所述动作和对象范围时，智能体必须发起新请求；受控动作照常由授权门
  裁决，不因旧批准放行。一次性批准不构成持续权限，可撤销性陈述不自动构成
  撤销保证。来源中“由系统权威记录对精确请求及批准结果的引用”与“没有引用时
  显示缺失、不能事后推断”两句自 2026-09-15 起不纳入本项，未来需要时作为新的
  能力另行登记（见[变更记录](#变更记录)）。

## 可观察场景

以下解释产品要求，尚不是已经执行的验收或已选定的协议。

| 场景 | 应有表现 |
|---|---|
| 智能体缺少完成任务的必要信息 | 主动说明问题与缘由；用户可自由回答，而非只能选预设选项 |
| 智能体拟执行一项需用户决定的动作 | 用户看到动作、对象、影响和被拒去向；评论或沉默不被当成批准 |
| 用户数天未答，原运行时已被回收 | 请求仍在，等待不消耗活跃执行预算；后来作答能恢复对应工作 |
| 同一轮有两条问题，用户从待办池只答其中一条 | 该条形成一次接续，其余条目保持原状态并可独立作答 |
| 用户从会话和另一台设备同时回答同一请求 | 首个有效答复生效一次，另一入口显示已答，不重复执行后续工作 |
| 执行设备暂离，用户仍能看到待办 | 显示当前不可答原因，保留问题，不假装已撤回或已处理 |
| 用户批准某项动作，后续动作扩大了对象范围 | 智能体对超出范围的动作重新请求，受控动作照常过授权门；历史按顺序可核对请求、答复与随后动作，系统不为动作标注批准引用 |

## 适用边界与待设计事项

本项拥有 agent 主动发起的问题、一次性批准及它们的等待与答复接续。能力授权
申请与专用权限流程相连，[PF-006](../PF-006-user-settings-and-agent-definition-authorization/requirements.md)
拥有用户设置与定义级授权；具体能力仍定义自己支持的权限模式和作用域。
[PF-007](../PF-007-system-initiated-hitl/requirements.md) 拥有系统授权拦截与合格动作的
暂行定夺，[PF-008](../PF-008-unified-decision-pool/requirements.md) 拥有统一池；这些
关联不把所有批准请求变成“先执行、后批准”。来源区分见
来源边界（迁移坐标：`.meta_harness/design/research/agent-initiated-hitl-sources/research.md#相邻范围与解释边界`）。

请求和答复的身份表示、运行/等待/接续状态模型、装配与存储方式、热宽限数值、
授权 scope 映射、展示与传输方式留待设计；系统不比对批准范围与实际动作。
“恰好一次”约束答复消费和逻辑接续，不自动证明外部副作用恰好发生一次；通知
送达也不证明用户已经看到或同意。

## 关联要求与当前覆盖

本项受 [SYS-TENANT](../../system/constraints/requirements.md#sys-tenant) 与
[PF-001](../PF-001-tenant-organization-context/requirements.md) 的租户、组织和权限约束，
具体化 [SYS-RUNTIME-CONTINUITY](../../system/runtime-state-and-continuity/requirements.md)
在长期等人场景中的要求。[PF-003](../PF-003-tool-execution-observation-and-control/requirements.md)
拥有工具调用的观察和生命周期控制；取消请求、停止工具和终结会话的传播边界
须分别建模。[PF-004.C11](../PF-004-subagent-delegation-and-supervision/requirements.md#相邻要求对-sub-agent-的约束)
引用本项用于 child 的人类请求；本项不扩大用户对 child 注入任意消息的控制权。

目前的设计（[本包覆盖状态](README.md#设计覆盖状态)）尚未
覆盖完整的主动 HITL、耐久待答、唯一答复及恢复接续。现有候选的普通输入处理
不能代替本项请求定位规则。本次登记不接受新架构或规格，也不反向改写旧基线；
当前没有已接受的业务决定或规格需要因此取代。
