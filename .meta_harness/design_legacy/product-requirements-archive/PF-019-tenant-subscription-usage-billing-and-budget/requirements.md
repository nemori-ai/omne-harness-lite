# PF-019：租户订阅、额度、用量、账单与预算管理

[用户维度](../by-user.md) · [租户管理](../PF-010-organization-personal-assets-and-permissions/requirements.md) · [来源核对](../../../research/legacy_backup/requirements-gap-resolution-sources/research.md)

2026-09-12 用户接受并重定义 GAP-4：在租户管理下增加订阅额度/用量、账单与
预算管理，且每一步 Agent Step 的金额开销都能够精细统计。本项作为租户管理
下的独立专题维护；主维度为用户，副维度为智能体。

## 已确认要求

- **PF-019.C1：个人与组织租户能管理财务和用量范围。** 个人用户及组织中
  具有相应管理资格的主体，能查看和管理该租户的订阅、已授予额度、已用/剩余
  用量、账单及预算。主体与范围沿 PF-010 区分，组织账目不混入成员私人账目；
  财务汇总的可见性不自动授予读取成员私人会话正文的权限。
- **PF-019.C2：每个 Agent Step 的金额可精细归因。** 能从具体 Step 查询
  其产生的费用及构成，并汇总到 Run、Session、Agent、派发关系和所属租户。
  模型调用、计费工具/服务及其尝试次数可追溯；不能只有模型 token 总量、每轮
  总价或租户总账而无法解释某一步花了多少钱。

以下 C3–C7 结合来源的资源计量要求细化；订阅和账单以及逐 Step 金额的明确
要求来自本轮用户，不声称来源 Harness 已承诺完整账单产品。

- **PF-019.C3：订阅、额度、使用权和预算分别管理。** 能辨认订阅对象、
  有效周期/状态、额度单位及重置规则，查看获准可作的变更及生效时间。账单能
  对应账期、项目、金额及供应方给出的结算状态；预算是本租户设定的消耗政策。
  有权管理预算不能改写供应方实际计费或伪造新增额度；取消/变更订阅对既有
  消耗和后续使用的影响应可解释。
- **PF-019.C4：金额及计量质量可核对。** 区分已确认实际值、估算、预留
  与未知，携带币种、计量单位、适用价格/依据和结算时点。迟到费用与估算调整
  可追溯，未计价或缺失不能显示成已确认零成本；存在无法归因的共享/延迟费用
  时明确列出待归因差额，不虚构精确分摊。汇总与明细能核对，跨币种不能直接相加。
- **PF-019.C5：预算模式与触顶效果可管理。** 支持仅观察、阈值告警/软预算
  和阻止新计费准入的硬预算；用户能查看适用范围、额度、周期与生效结果。
  首次启用计费来源时明确预算立场，不靠隐藏默认值开启无限支出。权限、物理
  容量与财务预算分别成立，任一项不能替代另外两项；主动对话也不隐含绕过硬预算。
- **PF-019.C6：预算约束覆盖延迟计量和在途调用。** 硬预算在下一次计费
  准入前检查或预留；普通预算下调或迟到费用不自动强杀已开始调用，其结果及
  费用继续结算。对于事后计费，说明已知暴露；无法确定的未来收费上界明确为
  未知，不宣称严格封顶，也不要求单请求最高收费保证。停止执行仍使用相应生命周期控制。
- **PF-019.C7：重试、恢复与派发不逃逸账目。** 同一事实的重复投递或读回
  不重复记账，供应方实际发生的多次计费则逐笔保留。运行时重建不重置额度或
  预算；Sub-agent 的消耗可沿因果派发树归集，不能因新会话/子 Agent 身份而
  获得未授予的新预算。后台工具晚于原 Run 完成时仍能归回发起 Step 及账期依据。

## 可观察场景与待设计事项

| 场景 | 应有表现 |
|---|---|
| 一步模型调用重试两次且供应方均收费 | 明细保留各次真实费用，Step 汇总可核对；回执重放不再记一笔 |
| 子 Agent 与父 Agent 同时消耗预算 | 各自 Step 可查询，派发树与租户汇总不遗漏或重复统计 |
| 某工具结果已返回，供应方次日才给出费用 | 原先显示估算/未知，后续补入实际值并保留调整关联 |
| 组织管理员下调预算 | 说明何时限制新消耗、哪些调用已在途；不改变供应方已确认账单 |

待设计：Agent Step 的精确行为边界、共享费用归因、价格版本和金额精度、账期
及多币种规则、预算并发准入与供应方对账协议。存储账本、支付渠道、税务发票、
代扣与支付执行流程未在本轮选定；“账单管理”不能由一张费用估算表冒充。
工程关联和诊断另见 [SYS-OBSERVABILITY](../../system/observability-and-logging/requirements.md)。
