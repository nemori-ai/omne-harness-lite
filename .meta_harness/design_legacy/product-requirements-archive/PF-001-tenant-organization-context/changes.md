## 2026-09-16 组织上下文效用范围的收窄

| 项 | 内容 |
|---|---|
| 来源 | 产品用户在 2026-09-16 会话中的直接裁决：「租户本质上限定的只有：设置、权限、可用的技能或工具（本身就是动态组装的），设置和权限不是叉乘而是根据优先级别来覆盖同字段」 |
| 触发 | 按 Cordis 投影分析该条时，原表的四个方面推出「为每个（组织 × agent）组合保留独立服务实例」的结构；代价被标价后，用户判定原表述过度 |
| 变化 | 效用范围由四方面（数据 / 权限 / 行动空间 / 流程规范）收窄为三项（设置 / 权限 / 可用技能或工具），并新增**求值方式**为确认范围：同字段优先级覆盖、工具集动态组装，不要求按组合预留独立集合 |
| 数据一项的去向 | 不再单列；数据范围与隔离边界的义务本就由 [SYS-TENANT](../../system/constraints/requirements.md#sys-tenant) 全局拥有，收窄不削弱该义务 |
| 流程规范一项的去向 | **未确认**。正文「待澄清与设计输入」记录其处置条件：设计不得自行归并或补第四方面，须回到需求方 |
| 受影响消费者 | 租户治理相关契约与提供者设计；引用本条的 [PF-010](../PF-010-organization-personal-assets-and-permissions/requirements.md)、[PF-026](../PF-026-account-journey-and-isolation/requirements.md) 按各自 owner 复核是否受影响；条款级 coverage 需重算 |
| 与迁移状态的关系 | frontmatter 的 `migration_status: equivalent-current-requirement` 描述的是**迁入时**相对源基线等价；本次裁决之后，正文已不再等同于源基线表述，不得据该字段推断二者一致 |

本节记录的是需求方的直接裁决，不是设计评审结论；设计材料不能反向扩大或收窄此范围。
