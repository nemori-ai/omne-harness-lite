# PF-011：面向未来的复杂日程规划、日历与通知提醒

[智能体维度](../by-agent.md) · [日程与通知来源核对](../../../research/legacy_backup/future-planning-calendar-and-notification-sources/research.md)

主维度：智能体。副维度：环境、用户，关联环境信号对规划的影响，以及用户的
时间意图、日历设置、日程管理和通知触达。

## 已确认要求

2026-09-12 用户明确：智能体能根据用户需求、自我演进需要、外部环境/信源/
数据源/连接器等信号，按需规划未来的线性（周期性）或非线性日程；系统提供
多国家或地区日历及节假日信息；日程效用包括触发/调度 Agent 执行，**和/或**
向用户通知；系统提供完整的定时闹钟及消息推送/通知机制。

C1–C4 展开直接要求。C5–C11 按本轮方向与
[SYS-CONTINUITY](../../system/omne-next-continuity/requirements.md) 补充原系统有效产品条款；
来源中当前承诺、已承诺未来范围及被后续修订的说法见来源核对。本项的“非线性
规划”不限于旧日历重复规则文档的狭义算术范围。

- **PF-011.C1：Agent 能主动规划和调整未来工作。** 规划依据可来自用户
  明确提出的任务，也可来自自我维护/演进需要，以及外部环境、信息源、数据源
  或连接器的信号。Agent 能结合进展和新信息建立、查看、调整或取消未来安排，
  说明安排的目的、依据、目标和预期效用；不能要求每项未来工作都由用户手工
  写出时间规则。信号或演进需要提供规划依据，不额外产生授权。
- **PF-011.C2：表达一次性、周期性与非线性时间意图。** 支持未来特定时刻、
  固定周期，以及按日期和日历关系形成的复杂序列，如每月第一个周一、季度
  最后一个工作日、指定次数或截止时间、排除/补充日期。基于新结果决定下一步
  时机、分阶段继续及重新规划同样属于本轮目标，不能以旧 recurrence 文档只
  覆盖确定性算术为由排除。规则有可解释的下一次及代表性未来预览，不能把
  无效、相互矛盾或无法在支持范围内求解的规则伪报为有效计划。
- **PF-011.C3：日历是可供规划查询的系统能力。** 系统提供多国家/地区的
  日历及节假日信息；Agent 能查询可用日历、区域、版本、覆盖范围和来源，判断
  工作日/节假日/非工作日，进行上下 N 个工作日、区间计数等算术，并预览复杂
  日程。调休补班、替代假日等逐日例外不能被“周一至周五”近似取代。同一版本
  和条件下，规划查询、预览与到期判定须给出一致答案，不能让 Agent 靠记忆猜。
- **PF-011.C4：到期效用支持执行、通知及两者组合。** 一个规划安排可以
  导向触发/调度一次 Agent 执行、仅向用户发出通知，或两者都做，用户和 Agent
  能辨认所安排的效用。纯提醒按耐久安排到点形成通知，无需启动 Agent、创建
  执行会话或消耗模型执行预算；组合安排保留各自结果，不能把通知失败或执行
  失败包装成全部成功。本轮“和/或”不沿用旧来源提醒型/执行型互斥的产品限制，
  具体如何组合及依赖先后留给后续设计。
- **PF-011.C5：未来执行不依赖发起时的运行实例存活。** 未来工作与提醒
  先成为可恢复的耐久安排，再向发起者确认。到点时原 Agent 未运行或运行时
  已重建，系统仍能定位该工作并按当前有效条件触发。
  [PF-004.C7/C8](../PF-004-subagent-delegation-and-supervision/requirements.md#定时派发与授权)
  拥有新会话定时派发及结果回流；当前会话也能安排未来继续同一件工作，等待
  期间释放执行资源、允许与耐久等待一致的有界热宽限，不消耗活跃执行时间。
  合法到期只产生一次逻辑接续；用户已取消或强停的工作不能届时复活。继续同一
  工作不额外要求逐次用户确认，也不豁免已有权限、人类控制和无进展约束。
- **PF-011.C6：多地日历持续供给，数据边界诚实。** 来源首批已承诺中国
  法定节假日及调休、日本国民假日及替代规则、美国联邦假日；它们作为已授权
  继承的初始范围，美国联邦假日不能被显示为所有地区统一放假。系统可继续
  扩展其它国家/地区及不同业务日历，按各自发布节奏更新并保留可追溯版本。
  发布物携带可用日历数据，覆盖至少完整发版自然年及当时已确认的更远日期，
  初始化后可在该覆盖内离线使用并尝试更新。覆盖不足、数据失效或来源不可用
  须显示真实状态，不能默认“没有节假日”或伪造未来日期的答案。
- **PF-011.C7：时间、日历与变更语义可解释。** 用户能辨认计划采用的时区、
  日历、版本、开始/截止条件和例外政策；支持按工作日过滤、跳过、前移/后移
  到工作日。沿用最新来源的生效环境跟随：适用计划按用户当前生效时区与日历
  计算，设置变化后在可观察的有界范围内重算尚未受理的未来；显式固定语义与
  跟随语义分别表达。日历版本切换、夏令时缺失/重复时刻、平移碰撞都有明确
  可追溯结果，不产生重复发生项，不越过截止条件，也不倒改已受理或历史事实。
- **PF-011.C8：日程可管理、可撤销、可重新安排。** 用户及获准 Agent 能
  查看安排、下一次时间、当前状态与创建依据，进行适用的修订、暂停、恢复、
  终止及改期。草稿可持久保存但不触发，需确认时经合法确认才生效；替换应形成
  连贯、可追溯结果，不短暂出现两份生效计划或丢失原计划，失败保留原有效安排。
  一次性工作须能与周期计划区分，执行状态和最终结果如实可见，结束后无需用户
  再停用。具体未来派发的分级授权继续引用 PF-004.C8；需用户裁决的事项进入
  [PF-008](../PF-008-unified-decision-pool/requirements.md)。
- **PF-011.C9：到期、受阻、错过和恢复有真实记录。** 同一计划发生项不会
  因重复扫描、重启或接管重复被受理，也不能误吞另一个真实发生项。到期重新
  核对当前权限、依赖和资源；暂时受阻与用户暂停、永久失效分别可见，恢复不能
  擅自换目标、移除用户暂停或复活已终止计划。错过按适用的有界政策处理，不能
  伪造当时已执行/已通知或积累无界补发。纯提醒继承错过不批量补发的范围；
  一次性执行默认到期条件不满足即终止，可显式选择等待恢复；周期工作保留
  意图并按其规则处理后续窗口。去重承诺不自动等于外部副作用恰好发生一次。
- **PF-011.C10：通知有耐久落点和实际推送能力。** Agent 能安排未来特定
  时刻的通知或提醒，系统提供可恢复的站内通知落点，以及用户可配置、已注册
  且获授权的消息推送/外部送达路径；来源个人版已承诺至少一条机外送达路径。
  在线实时呈现只是加速，外部失败不能使通知消失。用户设置、紧急度、免打扰、
  限流和合并去重实际影响送达；同一通知多路到达仍可识别为同一件事。排队、
  已投递、失败、结果未知须分别显示，不能把通道受理当成人已读。接收者、租户
  和通道权限受控，敏感内容的外部预览按权限裁剪；通知关联 HITL 时仍是同一
  请求的提醒，不另造待答事项或代替用户决定。
- **PF-011.C11：用户和 Agent 能回看安排及结果。** 提供具体日、周或时间
  窗口的日程视图、计划详情、定义变更史及逐发生项记录，可关联实际执行或
  通知结果。未来预览区分将发生、被日历过滤、受阻和暂停等情况，过去视图反映
  实际结果；缺席的结果不能被推断成成功。进入受阻、恢复和永久失效时主动通知
  用户，说明原因及可做什么；同计划同成因的持续问题合并呈现。日程价值和
  是否值得继续由 Agent/用户依据事实判断，读面不能把臆测当作运行事实。

## 可观察场景

| 场景 | 应有表现 |
|---|---|
| 用户要求每月最后一个工作日整理资料并通知自己 | 可用当地日历预览，正确处理节假日与调休，到期执行和通知各有真实结果 |
| 连接器报告一项外部事务尚未完成，Agent 判断稍后再查 | 可安排未来继续或后续工作，依据新结果调整节奏，等待不要求原实例持续占用资源 |
| Agent 为自我演进安排周期复盘 | 持久保存目的和范围，到期仍受授权、预算及相应演进要求约束 |
| 用户说“明天下午三点提醒我交材料” | 系统到点直接形成并尝试送达提醒，不为机械通知启动 Agent |
| 用户更换生效时区或日历 | 跟随型计划重算未来并可解释变化，固定型按其明确语义保持，历史不改写 |
| 日历尚未覆盖所问年份，或执行设备暂时离线 | 说明数据缺口或受阻原因，保留真实安排，不猜日期、不伪报执行 |
| 用户修改后续安排或终止等待中的工作 | 变更线索可追踪，不出现新旧计划双发；已终止工作不会在旧时刻复活 |
| 外部推送超时，用户随后打开系统 | 仍可看到同一耐久通知和真实投递状态，不能被标成已读或已答复 |

## 归属与待设计事项

2026-09-12 用户对 GAP-3 再次明确，日程管理要面向用户开放。本项 C1/C8/C11 的
创建、调整、暂停/恢复、终止、查看安排和结果，不仅供 Agent 使用；它们与
[PF-013.C11](../PF-013-session-run-lifecycle-and-pending-input-control/requirements.md#状态权限与跨端一致性)
的会话过滤及生命周期管理组合，支持用户找到 Agent 发起的工作并管理其未来
安排。日程暂停、单个发生项停止与已有 Run 中断继续保持各自效果。

[PF-002](../PF-002-external-change-response/requirements.md) 拥有环境感知与响应，
本项拥有这些信号引出的未来规划；PF-004 继续拥有 sub-agent 派发和监督，
本项不复制那套权限与回流正文。
[PF-006](../PF-006-user-settings-and-agent-definition-authorization/requirements.md) 拥有
用户设置，[PF-010](../PF-010-organization-personal-assets-and-permissions/requirements.md)
及 [SYS-TENANT](../../system/constraints/requirements.md#sys-tenant) 约束所有计划、日历读取与
通知的范围。本项记录通用通知能力及其日程应用，PF-005/PF-008 保留请求和决策池
的权威含义。

待设计：复杂规划与重规划的表示、各类计划身份与效用组合、组合的先后及部分
失败处置、长期日历更新与版本采用、组织/个人的时间设置关系、执行和闹钟的时间
精度、离线/休眠与错过处置、闹钟声音/贪睡等客户端交互、具体推送通道和投递
策略。完整目标已确认，这些精确承诺不能仅凭“采用 cron/RRULE”或“有通知表”
宣称完成，也不从来源阶段交付范围推定本项目一期已实现全部目标。

目前的设计（[本包覆盖状态](README.md#设计覆盖状态)）尚未覆盖
上述规划、日历、耐久到期和通知全流程。本次不采用旧系统单例 ticker、数据库、
调度库或部署方式；来源要求中的旧时区与互斥效用限制按[核对记录](../../../research/legacy_backup/future-planning-calendar-and-notification-sources/research.md#来源差异与当前处理)处理。
