## 选择与范围

1. 使用 packages/能力族/职责包；能力族负责导航，叶子包拥有源码、依赖、公开入口、测试与来源记录。
2. 按能力定义、具体提供者和消费扩展的真实责任与变化边界分包；应用装配选择提供者。
3. 共享数据和运行身份只有一个语义拥有者，经公开入口复用；不为每个插件、角色或未来设想预建空包。

适用范围：产品 monorepo 的能力族、职责包、公开入口、测试和 fork 来源布局。

## 理由与保留前提

单一临时 baseline 包只能方便搬运，不能隔离长期变化；能力族加职责叶子让来源、依赖和维护责任落到真实边界。

Meta Harness 的 providers 按实际产品包保存能力到实现映射；该设计不反推源码已实现或符合。

## 取代与影响

取代旧 fork 计划中先放单一 dsh-baseline、以后拆分的组织选择；不改变 D-005 至 D-008 产品契约。

原决定、旧评审和旧实现证据只证明其记录的对象与时点。当前规格采用、提供者符合性、应用装配与发布仍须分别引用实际
catalog、review、formal execution、provider conformance 和 release evidence；本包不会把这些状态合并为“已交付”。
