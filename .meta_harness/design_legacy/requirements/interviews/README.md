# 用户访谈记录

这里保存具有持续回顾价值的需求访谈语境：人和 AI 怎样形成、质疑和修正需求，
以及当时公开表达的理由与选择背景。记录是可选的上游来源，不是正式需求、提案、决定或规格。

## 何时建立或接续

- 交互明确是一场需求访谈，或连续交流正在形成/修正问题、结果、约束、优先级和取舍。
- 单条输入包含未来解释某项接受、否决或修正所需的重要前提或理由。
- 来源可恢复且内容值得跨任务回顾；同一主题优先接续现有包，不按消息拆包。

普通执行命令、状态询问、没有长期语义的局部修正，以及已有权威正文足以承载的简单确认，
不需要访谈包。短暂或低价值输入留在当前任务上下文或 `tmp/`。

新主题从[访谈模板包](../.templates/interview/README.md)复制为 `<topic>/`。开始记录后简短告知用户路径并允许纠正；
已授权仓库中的可逆笔记无需为开始动作中断访谈索要许可。没有稳定会话 URI 时，记录仓库任务、日期、参与角色和恢复说明，不伪造链接。

## 状态与升级边界

访谈包使用 `active` / `closed` 表示记录是否继续；`closed` 不等于 accepted。
只有正式 owner 将信息显式吸纳进需求 `requirements.md` / `changes.md`、proposal 或 decision，
相应内容才取得该 owner 声明的状态。访谈不创建 PF 编号、不进入 spec catalog，也不从“新能力”措辞直接推导插件。

记录遵循最小必要原则：不保存凭据、秘密或无关个人信息；只记录实际表达、公开理由与明确标注的解释摘要，
不推测模型隐藏思维链。参与者更正内容时保留可理解的更正关系。
