# PF-023：会话级合法模型切换与下一轮接续

[用户维度](../by-user.md) · [来源及后续修订核对](../../../../research/legacy_backup/requirements-gap-resolution-sources/research.md)

2026-09-12 用户明确新增：一个 Agent Session 能切换到另一个合法模型，继续
新一轮工作，并授权从 omne_harness 补充完整含义。主维度为用户，副维度为智能体。

## 已确认要求

- **PF-023.C1：在同一 Session 换模型继续下一轮。** 有权用户能为会话
  选择另一合法模型，保留同一会话身份、已持久历史和工作关联，以新模型开展
  下一轮 Run/Turn；不能用另建空白会话来替代切换。

以下 C2–C7 综合来源正文及 2026-09-09、09-10 修订。后者已补充候选集、
未知能力处置和窗口压缩，不能仅引用早期正文中“上下文长度尚未裁定”的状态。

- **PF-023.C2：选择仅作用于该会话及明确运行边界。** 模型按会话选择、
  用户默认偏好、Agent 定义默认模型的顺序解析；缺席层回落与显式非法选择
  分别处理。会话选择持久化但不修改用户偏好、Agent 定义或其他会话。当前 Run
  尚在执行时，切换请求应明确等待、拒绝或登记下一轮生效，不能无提示替换该
  Run 的模型；下一轮准入时确认实际生效模型与当前条件。
- **PF-023.C3：可选候选及理由可读，执行时仍检查当前事实。** 用户在切换
  前可取得获准可见模型的当前候选结果，包括可换、不可换及具体原因，不把
  不兼容模型从获准目录悄悄抹去。候选读面与切换使用相同事实含义和判据；若
  权限、模型供给或会话状态期间变化，切换重新检查并说明差异，不把旧列表
  当作永久授权。模型供应、访问资格及预算沿相应规则判断。
- **PF-023.C4：模态兼容取自耐久会话事实。** 按会话已有模态与目标模型
  实际接收能力判断，不凭模型等级升降。确认不支持与能力尚未确知分别具名
  拒绝；可丢弃缓存缺失或落后不能让历史模态消失。派生会话按派生点事实判断，
  不混入之后母会话新增内容；事实暂时不可信时明确保守处理。不得为放行切换
  静默丢弃原内容、转写模态或自动换成其他模型。
- **PF-023.C5：窗口不足时先作一次非破坏压缩。** 切换动作生效前，按
  目标模型上下文窗口的可配置比例检查当前有效上下文，为后续输出留空间。
  超限时作一次压缩，将摘要作为新事实保存、原始历史保留，后续使用摘要视图；
  压缩后仍超限或压缩失败则具名拒绝，模型选择保持原值，已成功的压缩保留。
  同一切换不无限重试压缩；该压缩不绕过 C4 的模态门。窗口未知本身不按已知
  超限拒绝，但对工程诊断可见；已知上限、比例与估算值可核对。
- **PF-023.C6：模型变化后的能力重新按实际条件生效。** 模型等级、模态、
  工具支持与有效装配共同影响下一轮能力；切换不能沿用旧模型的能力集合或
  越过 PF-012 的四项共同作用条件。已有后台工具仍按 PF-003 保持关联和自身
  生命周期，不能因换模型被冒充新调用或无依据地终止。
- **PF-023.C7：回复保留实际生成模型。** 每条模型生成的回复记录实际
  模型标识，历史读回和运行时重建后不改成当前选择。切换成功、未生效及拒绝
  原因可辨；模型选择的成功不代表下一轮执行或回复已经成功。

## 可观察场景与待设计事项

| 场景 | 应有表现 |
|---|---|
| 纯文本会话切到等级较低但仍合法的模型 | 允许下一轮使用；不因“降档”一概拒绝 |
| 会话已有图片，目标模型对图片支持未知 | 以能力未知明确拒绝，不把它描述成已确认不支持或静默删图 |
| 目标窗口更小 | 超过配置比例时先保留原历史地压缩一次，复核后切换或明确拒绝 |
| 旧模型生成回复后用户切换并重建运行时 | 旧回复仍标原模型，下一轮使用当前合法选择，后台工作保持真实关联 |
