# PF-002：外部环境感知与响应

[环境维度](../by-environment.md) · [Connector 来源核对](../../../../research/legacy_backup/connector-environment-source-sources/research.md)

主维度：环境。副维度：用户、智能体。2026-09-12 用户逐项介绍中的第二项。

## 已确认要求

**PF-002.C1（用户直接确认）：** 系统能够感知外部环境的变化，并具备对这些变化产生响应、
作出相应行为的能力。

同日用户明确拓展 PF-002，纳入原系统 Connector 相关机制。实际来源入口为
`omne_harness/libs/omne_harness_connector_sdk`，其产品要求还分布于信源安装、
授权与供给，以及下游感知/响应条目。C2 记录该直接要求，C3–C9 按本轮方向及
[SYS-CONTINUITY](../../system/omne-next-continuity/requirements.md) 映射来源已承诺的未来行为；
它们不表示已实现，源具体 SDK 或子系统结构也未因此被采用。

### Connector 接入与供给

- **PF-002.C2：通过 Connector 接入外部环境与信源。** 系统为外部环境、
  数据源及外部账号提供受治理的接入机制，外部实现能声明所供给的内容及兼容
  条件，通过安装/握手形成有效接入，再向获准的信息通道（来源称 Channel）
  供给内容并查询自身接入状态。接入面保持与供给职责相称的权限，不因连接
  Harness 就取得会话数据读取、系统管理或任意 Agent 控制能力。
- **PF-002.C3：一次安装是一份独立的用户连接与授权。** 同一 Connector
  实现可供同一用户连接多个外部账号或用途，各有独立安装身份、范围和生命周期，
  不能把工作账号与私人账号合并。安装归属明确的租户/用户，不能靠传入另一个
  Agent 或会话标识改写归属。用户自行安装、卸载和扩大范围须有明确同意，Agent
  可以建议或请求，不能代造同意事实。系统内获准供给的通道、账号、数据类别和
  速率，与访问外部系统所需凭据分别有效；任一成立不能替代另一项。安装记录
  使用凭据引用，不把令牌、密码等原文放入普通安装事实和审计。
- **PF-002.C4：Push 与 Pull 均可供给，内容保持数据身份。** 系统支持来源
  主动推送，也支持按安装配置拉取；二者接受同等的安装、授权、租户/用户、
  数据格式、容量和重复供给检查，Pull 不产生更宽松通路。内容保留来源、版本、
  新鲜度和必要时间信息，可按最新值或有界缓存供后续使用。供给方不决定 Agent、
  会话、任务提示或唤醒路由，外部内容不因进入系统就成为指令或权限。供给已
  成立与下游感知、响应或行动成功分别表达；下游失败不能倒改已受理内容。
- **PF-002.C5：暂停、故障、撤权、卸载和重装语义明确。** 用户可暂停及
  恢复自己的自助安装，技术恢复不能解除用户暂停、组织阻断或安全撤销。卸载
  终结原安装，旧内容退出默认 Agent 内容面；重装形成新身份和新一代内容，旧
  凭据、迟到请求或重放不能写入或复活新安装。默认不可见不等于物理删除，
  历史和审计处置另有边界。实现版本、通道或授权范围改变可追踪，扩大权限或
  破坏性升级需重新授权；兼容且不扩权的更新可按适用规则采用。被安全撤销的
  版本不能为了连续性继续供给。
- **PF-002.C6：用户能看清连接与供给状态。** 可辨认连接的外部账号、安装
  版本、授权范围、Push/Pull 方式、最近成功与错误、新鲜/陈旧及需采取的操作。
  没有新数据、数据源故障、凭据过期、用户暂停、组织阻断、安全撤销与已卸载
  不能压成一个含糊状态。恢复按已声明的有界策略取得内容，缺口或跳过如实可见，
  不能承诺有界信息通道逐条完整重放无限历史。
- **PF-002.C7：接入受个人和组织治理。** 个人与组织范围使用明确的信源
  准入政策；组织可限制允许安装的来源，或要求成员安装某类来源。组织要求
  为每个成员形成独立的用户安装及内容范围，不自动合并私人账号内容，也不能
  代替个人外部账号的 OAuth 等同意。被要求的安装与用户自助安装不互相冒充；
  组织撤回要求不能把原组织依据改写为用户永久同意，用户自行卸载的权限也须
  与安装来源相符。策略收紧阻断后续供给及默认投递，不能伪装成用户主动卸载。

### 从供给到感知与响应

- **PF-002.C8：运行中的 Agent 可被动感知获准信息。** Agent 定义可以
  声明希望感知的信息通道、适用时机和内容兼容范围；系统给出可解释的有效
  订阅，订阅本身不授予读取权或安装信源。已经运行的会话在适用边界接收获准
  新信息，各会话的呈现进度独立；被动订阅更新不自行启动或恢复休眠工作。
  内容已可见、已交给模型与模型理解/行动是不同事实，不能以前者宣称后者。
- **PF-002.C9：变化可按受治理条件主动触发响应。** 系统可以持久观察一个
  或多个通道，按 ANY/ALL、组合、计数、时间窗、去抖或合并等明确、有界条件
  发起 Agent 工作；条件判定不要求 LLM 持续空转，目标不必已经运行或直接
  订阅该来源。任务意图、目标、会话选择、忙碌处理和多目标策略由系统内获准
  配置决定，不由供给内容自报。重复变化、重启及重试须收敛到同一次逻辑触发，
  不丢失已成立但尚需交付的响应，也不重放已成功的其它目标；每次仍检查当前
  权限与执行资格。响应能关联到引起它的变化，并记录实际工作、失败和结果。

感知、决定响应和实际行动仍分别表达，不要求每次变化都采取动作。Connector
供给、被动感知与主动反应各有结果，不能用“Connector 已连接”表示完整响应
链路已经成功，也不把 Connector 本身变成通用远程 Agent 控制接口。

## 可观察场景

| 场景 | 应有表现 |
|---|---|
| 同一用户通过同一个 Connector 连接工作与私人日历 | 两个独立连接与授权；暂停或撤销其一不影响另一份同意 |
| 信源已无新内容，另一个信源却因令牌过期无法读取 | 用户能分辨“无新增”与“获取失败”，知道哪一项需要重新授权 |
| 用户暂停安装后，外部服务恢复 | 仍保持用户暂停，不因技术恢复继续供给 |
| 用户卸载后重装，旧推送迟到 | 旧请求不能污染新安装或使旧内容重新进入默认 Agent 输入 |
| Agent 正在协作时关注的通道更新 | 在适用边界感知获准信息；供给成功不被冒充为模型已经理解 |
| 两个来源在一个时间窗内都更新，满足已配置响应条件 | 系统可唤醒此前未运行的 Agent，去重并保留各来源时间与触发依据 |
| 组织要求成员连接工作来源，其中一人尚未同意个人 OAuth | 该成员显示待设置，不伪造同意，也不借用另一成员的私人内容 |

## 待设计与当前覆盖

具体 Connector 与账号目录、协议和内容模型、凭据托管、接入配置和界面、容量/
速率/新鲜度、订阅时机、响应条件与目标策略、失联恢复及数据处置仍需精确建模。
本轮不选择旧 SDK 的三方法 API、State/Inbound 分工、数据库或消息机制；开发者
发布 Connector、市场分发，以及更强的逐事件可靠队列各有独立范围，不从安装
和有界供给能力推导。

目前的设计（[本包覆盖状态](README.md#设计覆盖状态)）尚未完整
覆盖 Connector 安装与供给、感知及主动响应。来源的已承诺未来状态不等于本项目
交付完成；本次无已接受业务设计或规格需取代，旧需求基线保持历史范围。
