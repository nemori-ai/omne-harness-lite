# PF-016：Agent 开发 Cordis 插件并在线部署装载

[智能体维度](../by-agent.md) · 机制研究（迁移坐标：`.meta_harness/design/research/agent-developed-cordis-plugin-sources/research.md`）

主维度：智能体。副维度：用户、环境。2026-09-12 用户明确这是本项目新增要求：
在权限策略允许的前提下，Agent 能在系统不停机时开发、部署和装载 Cordis
plugin，包括 tool、skill、service 等。用户同时授权核对 Cordis、DSH 和 Raven，
细化要求及最小必要技术条件。本项不以 omne-next 已有功能作为确认依据。

## 已确认要求

- **PF-016.C1：Agent 能开发新插件。** Agent 可根据工作或演进需要，查阅
  获准的能力契约、依赖和运行诊断，编写或修改 Cordis 插件，形成可验证和部署
  的候选。范围包括提供工具、技能、服务及相关组合；不能仅提供从已有目录安装
  插件的入口来代替开发能力。主要实现语言为 TypeScript/JavaScript，行为及
  数据契约仍按 SYS-SPEC 保持语言无关。
- **PF-016.C2：获准插件能够在线部署并装载。** Agent 能把候选交付到目标
  装配可取得的位置，在系统持续运行期间启用，使其贡献在目标作用域实际可用。
  开发、验证、部署、装载及就绪分别可辨，保存了代码或登记了插件名称不等于
  已启用。不能以全系统停止或重启作为每次合法插件变更的必经步骤。
- **PF-016.C3：开发和生效均受权限策略治理。** 可编写的范围、可安装的
  依赖、部署目标、可提供/消费的服务、注册与替换的能力、可影响的租户/会话，
  都受当前有效策略约束。Agent 不因能写插件就获得修改授权判定、自授权限或
  影响其他租户的资格。已有效授予的权限可以支持自主完成；只有策略要求时才
  发起 HITL，不新增所有插件逐次人工批准的统一限制。

以下 C4–C7 是结合当前系统要求和机制研究对本轮方向的细化，不代表已经选定
热替换协议、沙盒实现、编译器或部署服务。

- **PF-016.C4：插件可观察、可更新、可停用。** Agent 和有权用户能辨认
  插件及其确切版本、来源、部署范围、依赖、实际运行状态及失败原因；能够在
  获准范围更新、停用和移除运行实例。卸载运行实例与删除定义/持久数据分别
  表达，撤权对新操作和在途工作的效果不能混成“已全部停止”。
- **PF-016.C5：不停机保留真实的影响边界。** 在线变更应让系统整体持续
  服务，并说明受影响的能力、消费者及在途工作如何处置。对共享服务的替换不能
  静默终止关联工作或混用不兼容版本；无关工作不因局部插件变更被一并重启。
  不适合当前在线切换的候选应明确受阻及原因。支持不停机不自动承诺任意插件、
  任意状态迁移均零间隙，也不承诺外部副作用可回滚。
- **PF-016.C6：已保存版本及部署意图可接续。** 需要保留的源码、资源、
  构建产物、验证依据和版本关系按 PF-015 持久管理，不能只存在于某一进程的
  动态注册表。期望装配与实际实例分别记录；运行时重建后，系统能够依当前权限
  和环境恢复获准装配，或明确报告无法恢复。曾经运行过不等于永久自动激活授权，
  临时试验也不自动成为持久部署。
- **PF-016.C7：失败可诊断，修订有依据。** 语法/构建、契约或依赖不兼容、
  权限拒绝、装载失败、运行异常和清理未完成有可辨认结果；Agent 能据此修订
  同一插件并重新验证。恢复前一版本、停止故障版本、恢复业务状态及补偿外部
  效果分别表达，不把切回旧代码一律报告为完整恢复。声称改进时应有与目标相关
  的比较依据，编译成功或插件已运行不等于工作效果已经改善。

## 最小必要技术要求

以下是从 C1–C7 和既有不变量推导的设计义务；规定需要保证什么，不预选内部
服务划分或统一状态机。

| 要求 | 必须能回答的问题 |
|---|---|
| **PF-016.T1：确切身份和可复现内容** | 正在验证和部署的是哪个插件、哪份代码/资源与依赖版本、哪份契约和配置；并发修订不能悄悄改变已核验候选 |
| **PF-016.T2：受控验证与实际兼容性** | 代码能否被目标执行器接受，声明、依赖和配置是否匹配，注册及实际调用能否成立；必要的装载/卸载和失败检查能否通过。候选测试的权限和效果也受治理，不能借“验证”先产生未经批准的生产效果 |
| **PF-016.T3：生命周期和释放责任** | 注册、监听器、计时器、子插件、连接与任务由谁拥有和清理；依赖消失如何响应；等待清理结束是否真的成功。外部独立工作必须有明确接续或终止归属 |
| **PF-016.T4：变更与在途绑定** | 新消费者何时见到新版本，旧调用如何完成或按授权停止，受影响依赖如何重建，失败后实际剩下什么；不混用不同版本的定义与实现，不伪报清理或恢复成功 |
| **PF-016.T5：权限具备实际执行边界** | 加载授权之外，插件执行能否绕开所声明的文件、网络、进程、服务及租户范围；部署应选择与被授予信任相符的执行边界。Cordis Context、依赖隔离和 Node VM 不能单独充当恶意代码安全隔离证明 |
| **PF-016.T6：持久恢复与环境适配** | 重建时从哪里取得同一已保存版本，如何重建受控装配、检查当前授权和环境能力；TypeScript 的转换和依赖解析必须适配所选执行器，不能假定所有动态加载入口天然执行 TS/import |

具体能力可采用拒绝繁忙变更、等待旧使用结束、显式终止或有条件迁移等不同政策；
需按真实契约选择，不能从 Cordis 热重载能力直接推导其中任意一种已经成立。
不在本轮固定同进程执行、子进程/沙盒、包管理器、存储后端或编译器，也不因
安全边界待设计而撤回用户明确的自定义可执行插件能力。

## 场景与关联

| 场景 | 应有表现 |
|---|---|
| Agent 发现现有工具不能满足工作 | 在获准范围开发、验证、部署新工具插件，系统持续运行，后续工作可发现和使用它 |
| Agent 新增技能资源或专用服务 | 以相应贡献形式装配，资源与依赖实际可达，权限和作用域不扩大 |
| 共享服务的旧版本仍被某次调用使用 | 变更说明并遵循该能力的在途政策，不用删除服务注册伪装旧调用已安全结束 |
| 候选可编译但缺依赖，或清理器报错 | 显示待依赖/失败/清理问题，不把发布成功或 dispose 返回当成完整可用/停止 |
| 系统运行时重建 | 依持久版本与当前部署意图恢复获准插件，保持来源、权限及未决结果可追踪 |
