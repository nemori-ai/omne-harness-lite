# composition.agent-session-binding v1

## 范围与依赖

本组合规定活体运行时、Session 附着、当前访问验证、Factory/驱动和资源提供者
如何共同完成激活与释放。规范依赖
[data.agent-runtime-identity v1](../../../data/agent-runtime-identity/v1/contract.md)
和 [capability.live-agent v1](../../../capabilities/live-agent/v1/contract.md)。
后者继续拥有 AgentRef、Registry 占位、工作许可和退出阶段；本组合细化端口，
不重定义它们。行为模型见 [Binding.tla](formal/Binding.tla)，符合性要求见[场景](scenarios.md)。

首版适用一个逻辑协调权威和受信提供者。运行时句柄、验证许可和资源使用对象
均为受约束能力，不是可反序列化获得权限的数据。未来跨进程提供者必须兑现相同
的身份、线性化、撤销、结果未知与释放保证，不能直接序列化 Cordis 对象代替协议。

## 提供者表面

操作名表示语言无关能力，不强制同名类、服务键、网络协议或包装层。

| 提供者 | 操作与承诺 |
|---|---|
| 访问验证 | `guardAccess(subject, tenant, target, operation, commit)`：验证当前实际操作并保护该次短提交；`deny`、`unavailable` 与已提交后通知失败分别表达 |
| Session 附着 | `attach(SessionRef, activationPermit, selection)`：在已预留尝试下取得精确附着；`guardActivation(attachment, commit)`：复核当前资格并保护发布；`release(attachment)`：精确解除此次运行附着 |
| Factory/驱动 | `prepare(activationPermit, owner)`：私有准备并返回实际装配和受管驱动；`requestRetire(reason)`：关闭新驱动工作；`awaitQuiescent()`：等待真实收口；`releaseResources()`：报告剩余资源与清理结果 |
| 资源/贡献提供者 | `acquireUse(binding, consumer)`：登记确切使用；`retire(binding)`：按绑定类型关闭新使用并协作撤除；`releaseUse(use)`：实际使用结束后解除精确关系 |

`activationPermit` 只允许对已预留 AgentRef 准备和清理，不授予一般业务执行权。
它绑定 SessionRef、FactoryBinding 与稳定 owner，受 Registry 当前尝试验证；
仅传入这些 ID 不能伪造许可。Session 的定义关联由其权威提供，selection 只提出
选择，不允许工厂替换原会话或定义身份。

## 当前权限与共同提交

**CB-01**：相关读、查找、附着、发布和工作准入按实际主体、租户、目标与操作
检查当前权限。允许创建/激活不自动允许读取全部历史、调用任意工具或控制别的
Run。拒绝对外不泄漏无权对象是否存在；内部有权诊断可区分权限拒绝、对象不适用
与权威不可用。清理能力只兑现原实例清理，不因普通权限撤销而失去收口资格。

**CB-02**：访问验证的允许结果只覆盖本次明确提交。准备前的允许、旧版本号、
缓存命中或远端迟到响应均不能直接供后续发布/准入使用。提供者必须将权限变化
与该次检查/使用接入同一撤销屏障，或提供被权限权威保证等价的短时排他有效区间；
区间内撤销的生效点须与提交有可解释先后，不能在已经生效的撤权之后放行。
无法确认有效性、租约/连接失效或响应含义不明时，拒绝新的准入。

**CB-03**：联合发布同时验证 Registry 的精确 preparing 尝试、稳定 owner、
Factory/实例必要绑定、当前权限与 Session 附着资格。上述条件到设置 ready
之间不存在允许撤销穿过的空隙。单机实现采用一份明确门顺序/协调协议；提交体
仅含受信的短状态操作，不等待 I/O、不调用用户插件回调、不在锁内开始释放。
需要异步工作的提供者先准备，再进入短提交；不能以多个独立 `isValid()` 调用
声称有共同屏障。各提供者必须给出其状态变化如何参与该边界的符合性映射。

检查/提交失败不产生 activated；发布已成立后的通知异常不撤销它。重入关闭仍
针对同一个 AgentRef；返回时可能已在退出阶段，消费方须按当前状态使用。

## 运行附着

**CB-04**：Registry 按 live-agent v1 先独占预留并登记准备及清理责任，Factory
随后取得附着和其它资源。`attach` 只附着已经存在、同租户且符合原定义关联的
Session，不创建长期会话。Session 提供者把附着的所有权登记到这次 AgentRef/
准备尝试；异步分配前已具备回收责任和可核实的尝试关联。超时或响应丢失不能
推定没有分配，必须能沿同一次尝试核实/清理；没有结论时保持待收口责任和占位。

**CB-05**：附着包含精确 SessionRef、原定义关联、此次注册身份、所属提供者绑定
及激活资格的修订依据，并提供受限的验证/释放操作。资格修订覆盖影响激活的事实，
不要求每次历史追加或标题更新都作废附着。提供者自行裁决会话和定义资格，调用者
提供的 DTO、可读日志或与 sessionId 相同的字符串不能替代其当前判定。

**CB-06**：准备期间资格变化或附着被撤销后，旧附着不得发布；资格后来恢复也不
使旧注册能力复活；原尝试进入收口，释放完成后以新 AgentRef 重新激活。已经发布后，资格失效立即封闭
受影响的新工作准入，并按 live-agent v1 收口；之前已经准入工作的后果由其所属
能力规则和合法清理决定，不将资格变化隐式解释为用户 cancel。

Session 的归档/删除等业务操作必须与上述门协调，活动 Run 是否允许该操作由
Run/Session 权威共同裁决，不能用 live-agent 是否 ready 代替。阻止准入、会话
状态耐久提交和物理停止是不同事实；本组合不规定 Session 存储事务或完整生命周期。

**CB-07**：运行附着的生命周期为 held → revoked/releasing → released，允许
未撤销时直接在合法释放阶段进入 releasing；只有真实解除后报告 released。
释放失败或结果未知保留原附着与清理责任；可安全重试时认回同一个注册身份。
旧释放操作、重复调用或迟到响应只能作用于该附着，不能撤掉同 Session 的后来
实例或提供者的新绑定。释放不会归档、删除或清空 Session，也不隐式结束独立工作。

## 构造、驱动和收口

**CB-08**：Factory 私有准备不得发起需要业务工作许可的 Run、模型请求或工具
动作。每份资源在对外起效前登记给稳定 owner；准备的异步结果与关闭竞争时，
晚到资源仍由原尝试接收并清理。prepare 失败不能把资源、附着或未知分配遗留在
没有账目的 Promise 中。调用方取消等待不撤销已经登记的清理责任。

**CB-09**：驱动只在 ready 以后、精确工作许可和业务准入同时成立时执行工作。
许可对应驱动声明的真实业务边界，不能用每个底层函数调用把一个 Run 拆开吸收
新代际配置。Session 激活不创建 Run，也不证明原 Run 可恢复；恢复须取得业务
权威的合法位置、输入/控制事实与实际资源证据。

**CB-10**：`requestRetire` 只确认收到退役意图；`awaitQuiescent` 成功必须表示
在途准备已交还，实例拥有的工作及未移交后代已结算，驱动不会再发起独立业务
操作。关闭中的受限收口和后续资源清理可以继续。自关闭不能等待包含自身的
完整排空；等待取消/超时返回未完成，不释放占位。

**CB-11**：独立工具/HITL 等工作的事实权威、必要记录者及控制关联不能依赖临时
Agent 实例存续。原实例的工作只有在目标权威已确认接管、当前观察/控制关联可
追溯、且不再依赖旧实例所需资源后，才可解除原账目；提交接管请求或失去回执
不构成移交成功。实现使用所属能力的具体可核实协议，本组合不提供通用移交 API。
外部工作从启动起已归独立 owner 时，释放观察订阅只解除观察使用，不重判工作。

**CB-12**：静止成立后封闭运行提交，再按实际使用关系释放：A 使用 B 时先释放
A，A 未确认释放前保留 B。Session 附着在其消费者退出后释放；所有必要清理
完成，Registry 才撤销占位。失败后可继续不受影响的清理，但保留失败项、它仍需
使用的提供者，以及必须等待它清理完成的资源。外部效果未知可由已确认
接管的独立权威持有，不能为了退出把未知改写为成功、取消或已撤销外部效果。

## 动态贡献与异常丢失

**CB-13**：新使用的登记与提供者关闭新使用的动作共享撤销屏障。Factory 与
实例必要绑定的计划撤除沿 live-agent v1 关准入并协调使用者退出；在途准备也是
使用者。可选贡献被工作实际绑定后，消费能力登记精确使用、贡献 owner 兑现
撤除政策；没有已定义在途政策时，繁忙撤除原子拒绝，不能检查空闲后让新使用
穿入再卸载。发布新同名贡献不使旧引用自动转向它。

**CB-14**：可计划撤除必须先完成上述协作，再调用 Cordis 卸载；直接销毁服务
之后才从 dispose 回调开始协调，不满足需要保留提供者资源的保证。意外失联或
依赖丢失封闭受影响的新操作，向原工作报告失败/未知及清理残留；依赖重现不
复活已关闭的实例/附着，也不证明旧外部工作停止。可独立使用的历史读面与其它
绑定保持自己的可用性，不能把模型网络不可达扩大为所有会话不可读。

## 验证边界

模型抽象提交屏障、精确登记、准备/释放及移交确认；小状态空间中的原子动作是
提供者须实现的线性化义务，不是对多个实际服务已能原子协作的证明。具体 IAM、
Session 持久性、Run/control、模型/工具协议、媒体、跨进程故障接管仍须独立规格
与真实提供者验证。此组合没有新增跨语言持久数据结构；身份继续用既有 Schema。
