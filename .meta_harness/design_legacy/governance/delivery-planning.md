## 计划消费什么

计划说明从当前状态到本次目标需要建立哪些事实，由谁建立，什么结果允许继续
或判定完成。它引用需求、决定、精确契约及必要的提供者/装配快照，不长期拥有
另一份接口或业务政策；任务可以引用既有材料，不要求重写固定模板。

一次任务的排期与状态按[持久化准入](organization.md#提案的持久化准入)留在临时
任务材料；需要长期解释的实施路线选择、迁移约束或验证结论回到其拥有者。

设计尚在探索时，可规划研究、证明、候选规格、原型与未决选项；明确哪些后续
工作依赖选择或证据，不能把这种计划称为全部实现均已就绪。正式实施只消费本
任务已有充分依据的范围。完整目标、验收、实施规格与施工计划的开发者输入
继续按[共同契约](../../.meta_harness/agents/roles/developer-contract.md)提供，证明或研究任务
则按其对象给出命题、假设、问题和输出，不强求预先存在产品实现。

## 按产物与证据安排工作

| 要点 | 本次计划应能定位的内容 |
|---|---|
| 目标与边界 | 需求/验收引用、交付范围、当前基线及仍未覆盖部分 |
| 输入与产物 | 采用的契约/设计/接口版本、预期输出及下一位消费者 |
| 性质与证据义务 | 从目标/需求导出的不变量及安全/进展约束，本工作需要建立或消费的性质、前提及负责者，引用现有记录和实际状态 |
| 完成判据 | 可观察结果、所需证明/模型/测试/实机证据、执行环境和结果归属 |
| 前置依赖 | 哪项可识别产物或证据必须先成立，什么条件释放依赖工作 |
| 写入与组合责任 | 明确负责人、可写范围、公共边界负责人及真实组合交付负责人 |
| 失败与接续 | 什么观察使路径失效、谁处理、哪些工作暂停或可继续、下一项可核对的输出 |

围绕可验收行为交付小增量；共享基础工作应指明消费者及接入验证时点。性能
优化有可复现负载和比较依据，正确性机制有契约及相关证据。任务数量、文件
数量、编译成功或完成百分比不能替代产品结果。

关键证明和可行性探针是实际工作，不能只在末尾写“补测试”。安排命题/模型
拥有者、证明或工具执行者、独立审阅、实际环境和消费者需要的闭合时点。先验证
一旦失败会使大量后续工作作废的假设；已有适用证据足够时引用，不机械重跑。

所需证明工具尚未支持时，明确选型/适配任务、输出和受阻消费；不得将普通脚本
退出成功或 TLC/Alloy 有限检查报告为已完成的机器检查演绎证明。选择和扩展工具链本身
按实际任务评估，不因本规范出现“机器检查”就默认某工具已获采用。

验收从契约导出可观察结果和重要反例。按实际风险覆盖失败、并发、恢复、撤除
及外部效果；替身仅支持规定范围，明确换成真实提供者后的验证责任。场景预期
不从被测代码自身的成功文字推导，也不能在 fixture 中补造缺失的产品行为。

## 依赖与并行

按产物的真实依赖组织，不强制研究、设计、spec、实现、验证固定串行。共享
接口、Schema、锁文件和装配资产指定单一写入归属；接口及前提足够稳定后，
消费者、提供者和验证设施可分别推进。不同契约的独立工作无需等待全部设计。

必要证明未完成时，暂停依赖该性质的机制接受与实施；获准的探索、反例搜索
及不依赖该前提的工作可继续。探索输出明确候选身份，不被其他任务默认为正式
接口或已兑现保证。关键前提已被反例推翻时通知受影响工作，按拥有者修正，
不能把实施者之间的互相承诺当作证据。

共同使用高风险机制的任务在复制该模式前取得相称的代表性组合证据。各组件
分别通过不构成组合通过；计划指定实际参与版本、组合场景、集成负责人和执行
时点。工作树隔离不能代替语义收敛，串行排期也不能弥补没有负责者的交接。

## 调整与完成

证据、假设、契约、接口或环境变化时，识别受影响的产物、消费者、测试和完成
结论。保留仍适用的成果；实现不符优先在契约内修复，前提失效或语义变化回到
设计/决定和[变更传播](spec-maintenance.md#变更沿依赖传播)。不得为了保住进度
降低有效要求、补造保证或把未完成义务删出范围。

远期未知保留方向、责任和闭合条件，近期任务才细化到足以实施。接续记录引用
输入版本、已确认事实、未验证假设、结果和下一项动作；不建立第二套长期规格。
从计划能找到未完成义务，并能辨认它们对本次交付和后续消费的影响。

计划形成可识别稿后，按[评审分工](../../.meta_harness/agents/roles/README.md#按判断对象选择-reviewer)
交 plan-reviewer 检查兑现路径、依赖和验收责任；规格表达与架构判断仍由各自
角色承担。普通局部修改不因引用本页而需要三轮审计。

完成结论说明实际交付、执行证据、局限及剩余义务，分别对应验收。计划就绪、
设计接受、实现完成与验证通过是不同事实；提交、合并、发布及外部操作按任务
授权执行，计划与评审本身不增加批准权。
