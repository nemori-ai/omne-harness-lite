# 开发者派发说明

向选定开发者提供以下内容；可以引用已有材料，不必新建文档。派发者先按
[共同契约](developer-contract.md)核对输入是否完整。

| 项目 | 本次需要填写的内容 |
|---|---|
| 身份与位置 | 任务 ID、角色、能力纵线与本次交付物、设计工作区与执行仓库/worktree 绝对路径、分支、基线提交 |
| 模型与推理强度 | 按角色配置选择目标模型；按实际任务规模和复杂度选 medium/high/xhigh，未调整时使用角色默认；通过宿主设置应用并核对实际结果 |
| 目标边界 | 要交付什么、不在范围内什么；允许读取以及创建/修改/删除的具体路径，含临时与生成输出 |
| 验收清单 | 每项标准的 ID 或稳定引用、可观察结果、通过条件、证据要求 |
| 实施规格 | 路径/正文、精确契约与所需提供者/装配快照、采用依据、依赖接口版本、不可破坏的条款及关键交接责任 |
| 性质及证据义务 | 目标/需求导出的不变量及安全/进展约束、保护位置、前提责任与证据引用；本次要生产或消费哪些结果，尚未闭合的必要义务阻止什么 |
| 施工计划 | 给定的实施顺序、前置依赖、交付节点、验证安排、本角色与其他任务的分界；延期映射的负责产物、受影响消费者及闭合时点 |
| 自主范围与动作授权 | 可自行选择什么；依赖安装、锁文件、本地提交、真实外部操作的已有授权 |
| 并行协调 | 具体写入负责人、共享接口负责人、消费/交付的接口版本与结果、真正阻塞的前置条件、计划允许的替身、发生冲突时的联系人；涉及组合时明确组合交付负责人及真实组合验证的范围与时点 |
| 方法与知识入口 | handbook 实际入口、相关 family/topic 包及本次采用规则；工作区与执行仓库各自的事实/操作来源，不默认继承父仓库 |
| 当前认知 | 已确认事实、已接受决定、假设、未知、尚未答复的问题 |
| 返回与恢复 | 派发者/接收者、澄清通道、成果和证据位置、交接状态位置、实际时限（如有） |

角色名表示适合的研发方向，不授予整个目录所有权，也不自动提供输入材料。
按架构责任选择角色，按能力纵线与交付物划定任务；同一角色可以派出多个实例。
跨能力切片可交给职责匹配且范围明确的角色；并行切片先确定互不争用的写范围和接口。
共享 Schema、公开入口、锁文件、应用装配等文件指定一名写入负责人，其他任务提交
修改需求。能力状态转换和跨能力产品规则交给对应能力/组合任务；应用装配与验证
不能补造未实现的规则。角色不规定五阶段流水线，也不要求每条纵线使用所有角色；
契约确定后，消费方、后端和交互可依计划分别实施，兄弟任务未全部完成不等于被阻塞。

派发者指定组合交付负责人并安排实际集成；负责人核对参与版本及交接结果，完成
其授权范围内的组合验证。该责任不扩大写权限，也不授予继续委派、Git 合并或最终
接受权。不能把各分支分别通过或替身通过当成真实组合通过。

首次消息应先要求进入指定 worktree 并核对分支。材料缺项时开发者先查给定来源，
仍缺失则向派发者返回最小澄清；派发者补齐后再启动依赖实施。用户无需替每个 worker
回答同一个问题，派发者负责归并和仲裁升级。
