# 研发品味

本章是全部设计与研发角色共享的研发品味：几种做法都能成立时，按它选方向。
它只在你所担任角色的职责、判断对象、写权限与任务授权之内生效，不扩大其中任何一项；
与角色正文的边界不一致时，以角色边界为准。

- 起草者与实施者在授权内用它做选择。
- 评审者与验收者不把它当作独立的发现来源或验收判据：只有某条品味在本次判断对象上
  对应一个说得出的后果时，才按本角色的发现标准报告；否则至多单列为不影响结论的观察。
- 语言无关的规格与领域读数只写性质，不据本章引入机制、技术栈或语言结构。复用、新增依赖、
  fork 与具体技术的选定仍按角色边界和任务授权处理；「优先复用」不是自行引入依赖的授权。
- 设计中需要展开时，读 harness-design-handbook skill 的 Taste 一节与
  references/architecture/assurance/judgment.md；实现中需要展开时，读执行仓库明确采用的防御指导。

## 通用判断

- 当前尚未正式发布第一版，研发演进要求直接按新规格做破坏性重构，同步迁移当前消费者并删除被替代的实现；不得为旧接口、旧格式或旧实现建立兼容入口、双轨执行、降级、回填或过渡层。历史设计与证据的保留不构成运行旧实现的要求。现行契约仍明确依赖的组件按其精确版本消费，不借本条扩大无关重构。第一版正式发布时必须重新制定兼容、弃用和数据迁移政策，届时调整本条。
- 先保护不变量，再选择抽象；抽象必须隔离真实变化或承载明确契约。
- 先做最小的正确模型，再按真实需求扩展；不为想象中的未来预埋框架。
- 复杂度必须有收益证据；没有可重复的瓶颈测量，不引入优化性复杂度。
- 先借力，再补差异。协议、算法或通用机制出现缺口时，先利用已有研究，核对官方实现和成熟开源方案；在满足规格、项目复用边界、许可和可验证性的前提下，优先直接复用、组合或窄适配。自行实现须有具体理由：现成方案哪里不满足要求，为什么必要差异不能由复用承接；未查证不是从零构建的理由。
- 研究要落实为工程选择，不能止于列资料，也不能查过一次后仍默认靠局部补丁推进。采用有依据的成熟路径，把自有实现集中在本项目真实的契约差异；同类能力共用机制，差异留在窄适配中。沿既有规格的局部修复保持轻量，已有适用研究和未受影响的验证证据直接复用，只补新的事实与受影响部分，不把借力变成重复调研或全量重验。
- 同一概念只有一个权威定义，跨能力、服务和实现语言复用；仅在语义确实不同或属于边界投影时采用不同表示，并明确映射。
- 优先组合和直接表达，删除没有独立行为、契约或边界价值的包装层。
- 让状态、所有权、生命周期、失败和副作用显式可见；不依赖隐藏的全局状态或隐式顺序。
- 外部输出不因被运行时调用就变得可逆；恢复、补偿、幂等和撤销必须区分。
- 让错误尽早暴露；禁止静默吞错、假成功和无法解释的默认行为。
- 策略类的东西不写死：重试、退避、超时、限流、节流、熔断、轮询间隔这类横切策略一律做成可配置的策略对象加可替换实现，默认值只是配置的初值；调度与时序优先复用生态里成熟的策略库（TS 里对应 python tenacity 的那一类），不自写计时与退避。写下一个数之前先问「将来会不会有人想改它」，会就不写死。
- 按开源框架的角度设计：调用模型、执行工具这类核心能力是可公开的、独立的函数闭包，不依赖运行时、会话、租户或存储即可单独使用；本项目的 runtime 只是它们的一种消费者，别人可以在外面用别的方式包装同一批组件。每个能力分清「公开函数面」与「Cordis 服务面」，前者不得被后者吞没；只在运行时层成立的不变量由运行时层承担，函数层不作此承诺。组件的内部构件（解析、装配、判定、投影、传输适配、执行者、转换件、重试件）同样可替换、可单独取用。
- 可观测性是运行行为的一部分：在真实边界让状态转换、失败与因果链可解释，生产、研发与 debug 共用结构化 log 和 trace 语义并通过配置调节细节。观测责任、关联、内容裁剪和耐久记录边界见设计工作区的全局要求 design/foundation/observability-and-logging/requirements.md；精确的观测契约要等规格设计做到那里。

## 工具使用

在任务授权内，优先使用当前 harness（Claude Code、Codex）实际提供的、职责与操作匹配的
专用工具，例如读取、检索和编辑文件优先使用对应的专用工具。任务本身就是运行程序、检查器、
测试或外部进程时，shell 就是对口工具；其余情形只有专用工具不可用或无法满足需要时，才用
shell 等通用工具兜底。通用性不代表效率更高，不因命令行习惯绕过合适的专用工具。
工具选择始终受角色与任务的行动边界约束。

## TS/JS 代码

编写、修改或评审 TS/JS 源码及其代码级设计时适用；不做这类工作时，本节不产生要求。

- 使用目标运行时支持的惯用写法，以清楚的命名、直接的控制流和适度的抽象表达意图。
  纯计算优先函数与普通数据，类承载实际状态、不变量或生命周期；优先组合，泛型和
  类型运算只服务真实契约，简洁以理解成本衡量。
- 保持严格类型检查，局部优先推导，公开边界明确输入与结果；用可辨识联合表达互斥
  状态。外部未知值先校验再收窄，不用 any、类型断言或非空断言掩盖未解决的契约缺口。
  共享数据沿权威规格实现；类型断言不做运行时校验，readonly 不保证运行时深度不可变。
- 每项异步工作都有所有者、错误去向与清理路径；等待、返回或显式托管 Promise，
  void 不能代替拒绝处理。取消请求与实际停止分开核实，计时器、监听与资源随拥有者
  收口；并发和缓冲须有边界，持续服务路径避免阻塞事件循环。
- 遵循 workspace 的模块与公开入口约定，区分类型依赖和运行时依赖；编译选项按实际
  Node/Cordis 依赖验证，源码、生成声明与独立包消费者共同核对，不能用断言或别名掩盖边界问题。
- 语法与风格遵循共享工具配置，未配置处沿所属包现有约定；机械规则交给统一格式化与静态
  检查，避免各包自立流派。注释解释约束与取舍，代码本身清楚表达行为。
