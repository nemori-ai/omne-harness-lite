# design-reviewer 判「表达」

量的是：给 [design-reviewer](../../../roles/design-reviewer/role.md) 一份候选规格和派发者附上的设计评审报告、
让它判「表达」这一种，它能不能把规格里的已知缺陷报出来，同时保持只读、只做这一种判断。
判据页是手册的 `references/review/expression.md`。被测的是**一整套**：角色正文、判据页与工具输出；分不出各自的贡献。

状态：**用例已签字（2026-10-01，第 1 版）。判定方法当天签的是以无界面宿主进程调用的判官；那种调用方式同日停用，
判官改由主会话派 subagent（规则另加了一句），已重新校准，等负责人重新签字。还没有基线。**

模型：Claude Opus 5.5、xhigh。角色文件钉的是 Fable 5.1，判「表达」时派发可换 Opus 5.5
（[角色说明](../../../roles/README.md#按判断对象选择-reviewer)）；这里沿用 2026-10-01 对照时的做法，在 Opus 5.5 上量。

## 判官校准

[calibration/cases.json](calibration/cases.json) 是 8 份报告的人工判定：对照里新旧两个角色各两份真实报告，
加 4 份反例（删掉两条发现、把两条发现挪进「未覆盖」、结论是没有问题的报告、另一份材料的报告）。
旧角色的第二份报告本身就带一处自然的反例：它引了 S-39 的坐标作别的发现的依据，却没有报那处裸引用。

现行判官是派成 subagent 的 Claude Sonnet 5.5（宿主记录的档位是 medium，派发者定不了档位）。2026-10-01 校准：
72 处判定与人工全部一致（49 处报出、23 处没报出），阻断条数等 11 项运行级计数也都一致；8 次派发，没有答复被驳回。
[比对记录](calibration/results/judge-subagent-claude-sonnet-5-5-rules-70fdea287e52.md)。

同一天早些时候的两次校准，逐处判定也都是 72 处全部一致，记录留着是因为它们各暴露过一件事：
以无界面宿主进程调用的那一次（[记录](calibration/results/judge-claude-sonnet-5-5@high-rules-62bf4cac80e1.md)，
负责人当时签的就是它），判官照抄原句时多写了一个字（「本本契约」），被程序驳回、重答通过；
改成 subagent 后、补那一句规则之前的一次（[记录](calibration/results/judge-subagent-claude-sonnet-5-5-rules-a676226b68b6.md)），
判官把一句原句里的全角逗号抄成了半角，同样被驳回、重答通过。
逐字核对不放宽：驳回的代价是多派一次，放宽的代价是判官可以靠一句报告里没有的话判「报出了」。

校准报告都是关于 `raf-contract` 的。三份真实材料还没有任何报告：它们的问题清单更长、每条的说明也更长，
判官在它们上面判得怎样没有校准过，要等有了运行再抽查。

## 真实案例的真值是怎么来的

三次真实评审的**报告原文都没有留存**。留下的是修订提交的说明、契约验证入口里「本轮修订了什么」的记录，以及修订前后的差异。
真值清单由这三样反推：一处改动同时满足「修订前的文本里确有可指出的缺陷」与「修订记录点名了它」，才列为应当被报出的问题；
只见于差异、记录没有点名的，以及后几轮才修掉的，都归进「已知的原有问题」——评审者报出它们不算抓到，也不算新的阻断。
所以这三份材料上的抓到率是**下界口径**：当时的评审者也许还报过别的、被驳回的发现，现在看不到。

传输绑定那一例的记录写的是「2 阻断、8 应修、12 建议」，但没有逐条标严重度，13 处里只有 1 处对得上（建议）；
另两例没有严重度记录。因此这三份材料不按严重度分开计分。

## 量不出什么

- 种入的 9 处是主会话写的，比真实待审稿里的问题更显眼，写的人与被测模型同源。
- 同一份材料里的几处问题由同一份报告判，不独立；三份真实材料都出自治理中心那一程、同一天的评审。
- 真实案例当时是由上一代评审角色（spec-reviewer，同一种模型家族）找出来的：它们量的是「现在的角色能不能找回当时找到过的问题」，
  量不出当时也漏掉的问题。
- 判据页的「跨契约批次核对」（同一批多份契约放在一起才看得见的不一致）没有材料覆盖。
