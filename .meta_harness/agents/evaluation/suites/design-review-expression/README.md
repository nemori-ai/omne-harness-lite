# design-reviewer 判「表达」

量的是：给 [design-reviewer](../../../roles/design-reviewer/role.md) 一份候选规格和派发者附上的设计评审报告、
让它判「表达」这一种，它能不能把规格里的已知缺陷报出来，同时保持只读、只做这一种判断。
判据页是手册的 `references/review/expression.md`。被测的是**一整套**：角色正文、判据页与工具输出；分不出各自的贡献。

状态：**用例待签字，判定方法待签字，还没有基线。**

模型：Claude Opus 5.5、xhigh。角色文件钉的是 Fable 5.1，判「表达」时派发可换 Opus 5.5
（[角色说明](../../../roles/README.md#按判断对象选择-reviewer)）；这里沿用 2026-10-01 对照时的做法，在 Opus 5.5 上量。

## 材料

| 材料 | 是什么 | 应当被报出 | 来源 |
|---|---|---|---|
| `raf-contract` | `capability.run-attempt-facts` v2，改成 candidate 后种入 | 9 处（E1～E9）：3 处工具核得出，6 处靠判断 | 主会话为 [2026-10-01 的对照](../../design-reviewer-merge-2026-10-01/README.md)写的，原样迁入 |
| `raf-contract-clean` | 同一份契约，只改成 candidate、不种入 | 无（对照） | —— |

迁入时改了一处标注：E3（失败集合开放式收尾）原先标成「工具核得出」，但这份契约没有九件事定义表，工具判不了它
（[对照记录](../../design-reviewer-merge-2026-10-01/README.md#对照里看到的与判定无关的事)），这里改标为「靠判断」。种入的文字没有动。

[calibration/](calibration/) 里是对照中新角色两次运行的人工逐条判定。

## 量不出什么

- 种入的 9 处是主会话写的，比真实待审稿里的问题更显眼，写的人与被测模型同源。
- 种入材料只有一份契约，9 处缺陷由同一份报告判，不独立。
- 判据页的「跨契约批次核对」（同一批多份契约放在一起才看得见的不一致）没有材料覆盖。
