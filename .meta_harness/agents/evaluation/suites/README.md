# 常设用例集

每个子目录是一个**流**——一个角色做一种事——的用例与判定依据，按现行角色名寻址，改角色正文、换模型钉值、
升宿主版本之后拿来重跑。它们与同级的各次实验记录不同：实验记录写的是某一天为某个决定跑了什么、得到什么，写完不再改；
这里的用例会随着发现的问题增补，每次增补升一个版本。跑它们的那一套在[运行器](../harness/README.md)。

| 流 | 角色与判断 | 现状 |
|---|---|---|
| [design-review-expression](design-review-expression/README.md) | design-reviewer 判「表达」 | 用例待签字 |
| [design-review-choice](design-review-choice/README.md) | design-reviewer 判「选择」 | 用例待签字 |
| [design-review-plan](design-review-plan/README.md) | design-reviewer 判「计划」 | 用例待签字 |

其余角色的流还没有迁入或建立，各自的一次性评估见[评估索引](../README.md)。

## 一个用例集里有什么

```text
flow.json        流的定义：角色、判断种类、宿主设置、指标、材料清单与每份材料里应当被报出的问题
briefs/          每份材料的派发简报，{WORKDIR} 在运行时换成副本路径
materials/       整份放进副本的待审材料（如为评估写的施工计划）
calibration/     人工判定过的报告标注，校准判官用
README.md        这个流量什么、量不出什么、基线数字与噪声范围
```

评审类的流里，一份**材料**是一次派发的待审对象，分三种：

- **种入的**：在一份真实材料上改几处，每处是一条已知的缺陷。种入的文字写在 `flow.json` 里，
  必须在钉住的那个提交的原文里恰好出现一次，`make test` 里有一条测试守着。
- **真实的**：一份待审稿在某次真实评审之前的快照（材料钉在那个历史提交上），应当被报出的是当时评审提出、作者接受并处置的发现。
  当时的评审除设计树之外还对着读的目录（例如研究），在那份材料的 `material_paths` 里另列，一并取自同一个提交。
- **对照**：不种入的材料。它上面没有「应当被报出的问题」，量的是评审者在没有种入时报多少阻断。

真实材料不是没有毛病的。每份材料另有一张**已知的原有问题**表：评审者报出它们不算抓到，也不算新的阻断；
表外的阻断发现单独计数，交人看过之后归进这张表（成立、不成立或属于另一种判断），用例集升版本。

## 规矩

- **两次签字之后才跑付费的评估。**用例由负责人看过并认可，判定方法由负责人看过并认可；签字记在 `flow.json` 的 `signoffs` 里，
  带用例集的版本号。版本一变签字失效，运行器拒绝开跑。整轮的花费按试跑实测报给负责人，同意之后才跑。
- **真值不进被测角色看得到的地方。**运行用的工作副本不含本目录。
- **改用例升版本，不原地改。**不同版本的结果不放在一起比。
- **材料钉在主线上够得着的提交。**本仓库按 squash 合并，分支上的提交合并后会够不着；`make test` 里那条测试在够不着时会失败，届时改钉。

## 什么时候跑

改了某个角色的正文、它内联的共享正文、它读的判据页或它依赖的工具输出；换了它的模型或档位；宿主升了版本。
跑之前先 `make role-eval ARGS="verify <用例集目录>"`（不花钱），再按运行器说明跑一个新的变体，与基线逐用例比。
比出来的差小于该流说明里写的噪声范围时，结论是「看不出变化」，不是「没有变化」。
