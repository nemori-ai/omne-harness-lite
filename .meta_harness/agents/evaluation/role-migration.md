# 角色迁移与新范式对齐

## 范围与来源

迁入八个角色的正文、两端配置、公共实施契约、派发模板、模型适配与历史证据。
[来源清单](role-migration.json)记录全部 56 个原文件的修订、哈希和新位置；迁入阶段保留了原根入口。
历史验证移到 [legacy-roles](legacy-roles/README.md)，原始证据文件保留字节，不把旧结论套给新提示。

模型、effort、权限与继续委派配置原样保留；本节所述迁入验证没有核验新的宿主支持、调用外部模型或切换根入口。
之后按新授权完成的根入口切换见[退役记录](host-entry-retirement/README.md)，下述试用证据仍只支持原范围。
角色正文从本次明确工作区与执行仓库取得事实，移除对原产品名称、OpenRouter 政策及旧 docs/spec/skills 的隐式依赖。

## 提示词变化

| 角色 | 对齐的指导 |
|---|---|
| architecture-reviewer | 现有能力与组合覆盖、剩余责任和演化依据；新独立维度的独立插件边界；区分资料、实现、语义缺口；按范围核对动作链与性质 |
| spec-reviewer | 忠实表达已给设计；data/capability/composition 归属；topic 信息包与按需形式化；模型映射、冻结版本和实际证据分开 |
| plan-reviewer | 消费既定能力演化；按四层就绪安排任务；证据先于消费、单一写入归属、替身到真实组合的责任；不重选业务政策 |
| 五个开发者 | 明确设计/执行上下文，按 handbook 就绪与语义拥有者处理缺口；保持四项开工输入、自主实施、写入权限、冲突停止及验收边界 |

详细方法由 handbook 拥有，角色按评审对象导航。模板可裁剪、工具按需，不会撤销实际触发的证明义务；
原有只读、不可自行修复/接受、不能猜测必需输入和不继续委派的边界保留。

## 验证

编译、链接及迁入渲染器共 67 项测试通过，其中新增测试把工具和内部 renderer 移到无旧根 skill 的目录，
实际生成两端角色并只读核对。pytest 退出时清理系统既有临时目录遇到权限警告，不影响这 67 项用例结果；
没有为此删除其他任务目录。技能结构、自包含引用、双端资源、角色配置与原始证据检查见[检查记录](role-migration-checks.json)。

三个独立普通 agent 先读完整生成提示，再收到[原始任务](role-migration-cases.json)，未提供预期答案。
观察摘要、输入与提示哈希见[试用记录](role-migration-probes.json)：

- 架构角色指出批准重复消费的具体反例，区分已定义能力与未实现提供者，没有替候选接受或写文件。
- 规格角色没有因纯函数 topic 缺 TLC/Alloy 判错；指出冻结版追加模型、取消语义漂移与无依据的总体证明声明。
- 计划角色指出证明提前消费、共享 schema 写权冲突及缺真实组合责任，同时保留已具备接口的并行安排。

试用基于重写工作区 AGENTS.md 和新增候选数量要求前的提示快照；后续[入口重写](meta-agents-rewrite.md)
及准入导航另行检查，不回写这组输入。
返回结果由主 agent 核对；只读动作依据试用者报告，未独立采集完整工具轨迹。未验证原生发现/加载、
沙箱强制、Claude 运行、精确模型遥测、真实压缩恢复、成本或长程行为；这些公开案例不是留出集或采用授权。
