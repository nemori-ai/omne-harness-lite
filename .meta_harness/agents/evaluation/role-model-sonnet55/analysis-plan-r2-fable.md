# 分析计划修订 2：实现类任务上 Fable 5.1 对 Opus 5.5

固定于 2026-09-29，早于本修订的任何运行。它回答一个新问题，不改[原计划](analysis-plan.md)，也不改原计划下
任何一次运行的判定。

## 问什么

订阅里 Fable 的用量单独计量，现有角色只有三个评审在用，派发量低，这部分额度大多闲置。
把一部分 Opus 角色改到 Fable 上，能否在**效果不变差**的前提下把闲置额度用起来。

本修订只检验开发者一类：在实现类任务上，`claude-fable-5-1` 与 `claude-opus-5-5` 同档位相比如何。
目标不是证明 Fable 更好，而是它不比 Opus 差到不可接受。

## 与原计划相同的部分

宿主、工具、权限、设置来源、检出、环境重置、辅助保持原样、关键约束及其观察方式、每次运行的上限、
重试与停止规则，全部沿用[原计划](analysis-plan.md)。协议适配的说明同样适用：只跑 `retain`，
不满足 `evidence-ready`，不支持精简或移除任何辅助。

## 不同的部分

| 项 | 取值 |
|---|---|
| 基线 | `claude-opus-5-5`，档位 high |
| 候选 | `claude-fable-5-1`，档位 high |
| 任务 | 留出集里的六个实现类任务：AD-1、AD-2、AD-3、TD-1、TD-2、TD-3 |
| 提示 | 各任务原来的角色定义（AD 用 application-developer，TD 用 tui-developer），只改 `model` 与 `effort` |
| 重复 | 每任务每组 2 次 |

档位取 high，是因为要替换的候选角色 capability-developer 与 infrastructure-developer 默认就是 high。

基线的来源：

- TD 三项：原计划下 Opus 的运行本来就是 high，直接沿用那 6 次，不重跑。
- AD 三项：原计划下 Opus 跑的是 medium，档位不对等，本修订补跑 Opus high 共 6 次。

候选共 12 次，加基线补跑 6 次，本修订新增 18 次运行。

## 已知的局限

- **角色不对应**：任务用的是 application-developer 与 tui-developer 的提示，要判断的却是
  capability-developer、infrastructure-developer 与 kernel-developer。本修订检验的是「同类实现任务上的
  模型能力」，不是那几个角色提示在 Fable 上的表现。
- **留出集已被用过一次**：这六个任务在原计划下已经跑过 Opus 与 Sonnet。期间没有据结果调整过任何提示、
  辅助、档位或判据，Fable 也没有在其上运行过；但它们对实验者不再是未见材料。
- **spec-drafter 不在本修订覆盖内**：任务包里没有起草契约一类的任务。把它改回 Fable 的依据只有
  2026-09-23 之前它一直运行在 Fable 上的历史，见[上一次复评](../role-model-reeval/README.md)。
- 任务取材自 TUI 与 CLI 的输入输出模块，不含存储、取消传播、恢复语义这类 capability 与 infrastructure
  角色的典型难点。

## 可接受的退化

候选记为「本次证据支持替换」须同时满足：

1. 候选没有任何一次违反关键约束；基线在同一任务上也违反同一约束的，单列说明。
2. 候选的任务成功次数不少于基线减一（12 次里至多少一次）。
3. 候选的目标测试通过比例均值不低于基线 5 个百分点以上。

成本照常记录，但**不作为判据**：Fable 的标价高于 Opus，本修订的出发点是闲置额度而不是单价。
两组在同一任务上全部失败且失败在同一批测试上时，该任务按「判据或规格缺口」单列，不计入比较。

## 采用

本修订只产出证据与结论。Fable 额度的实际水位不在本实验的观察范围内；改动之后是否挤占前台使用，
需要另行观察。
