# 文档写作的采用范围

**后续新建或修订文档时，必须加载 `asd-ste100` skill。遵循其适用规范。**
这项要求覆盖开发文档、产品与设计正文、规格、研究、skills、角色说明、计划与证据报告。
它约束本次撰写或修订的内容，不要求顺带重写未改动的历史材料。

## 按语言和文种采用

英文按文种选择模式：程序步骤、工具描述和操作指令采用 Strict；说明文与技术博客采用 STE-flavored。
中文至少符合可跨语言采用的清晰性原则：明确行动者，一句表达一个指令，术语一致，
条件与结果明确，必要步骤用列表表达。英文词数、词形和受控词典规则不机械套用到中文。
这项中文采用要求不表示检查器支持中文，也不构成正式 STE 合规声明。

## 保护含义

**语义准确优先于压缩和文风。**保留事实、数字、条件、例外、范围及要求强度。
不得把「可能」改成确定结论，或把「应当」与「必须」互换。
代码标识、契约字段、路径和错误原文保持准确；正式术语沿其权威定义使用。
如果改短会损失精度，保留必要表达并说明原因。

## 与其他写作方法组合

`asd-ste100` 约束表达，原任务与所属方法继续决定职责、内容、结构、格式和交付要求。
与其他 skill 组合写作时，保留原任务要求的模板、字段、来源记录和交付报告。
本 skill 的「默认只返回改写文本」适用于独立改写请求，不取消组合任务的其他产出。
技术博客保留有依据的作者立场与口吻，同时清楚表达技术主张和因果。

写作规范不改变材料的权威归属、接受状态或修订流程。
对已接受或冻结正文的语义变更仍须通过其原有接受入口。
检查器结果仅说明已配置的结构检测结果；交付前仍须对照原文复核语义。
