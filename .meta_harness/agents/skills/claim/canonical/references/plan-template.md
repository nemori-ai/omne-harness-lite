# 本卡交付计划模板（plan.md）

方法用 Matt `to-tickets`：切成端到端的薄切片，每片能单独验证、能在一个新上下文里完成，前置的预重构先做，每片写明被谁阻塞。本模板在它的骨架上加入本项目的角色与模型分配、七步待办、检查节奏与交回清单。节奏规则归 `claim` 技能的卡推进循环，档位与模型钉值归 `.meta_harness/agents/roles/README.md`「模型配置与本次派发」与 `dispatch-policy.json`。

使用规则：

- 放在 `tmp/issue-<号>/plan.md`，与同目录 `spec.md` 配套。切片在卡内顺序做，不另建 GitHub 子卡。
- 和 Matt 原版不同，本计划写成员、文件与验收命令，因为写者在当前仓库执行。
- 每条卡判据都要落到某个切片和一条验收命令。
- 首版前沿演进政策：消费者同波迁移，不做 expand–contract 兼容过渡；不能独立验证的切片合成一个可验证单元（`docs/engineering/skills.md`「项目差异与负责边界」）。
- 进度总览是固定格式，按下面「进度更新」及时改，不攒到交回。

## 进度更新

进度总览由四部分组成，格式固定：

1. **进度条一行。** `进度：[■■■■□□□□□□] 2/5 切片已完成 · 更新 <UTC 时间> · head <短 sha>`。进度条固定 10 格，已完成切片数 ÷ 切片总数，向下取整。跳过的切片不计入总数。
2. **当前一行。** `当前：切片 <号> 第 <n> 步（<步名>）`。受阻时写 `当前：受阻于切片 <号>：<一句原因>`。
3. **切片表。** 状态只用五个值：`待做`、`进行中（第 n 步）`、`已完成 <提交号>`、`受阻（<原因>）`、`跳过（<理由>）`。
4. **闭包表。** `| 闭包 | 写者模型@档位 | 清晰度 | 工作树 | 分支 | 状态 | 轮次 | 追加 | 验收报告 |`。状态只用 `待派`、`进行中`、`待验收`、`已合回 <提交>`、`已丢弃`、`停下（<原因>）`。派发、交回、验收、合回、停下时改。没有派子代理的切片不写。

什么时候改：

- 七步待办每完成一步，立刻勾选该步，并改「当前」行。
- 写者交回（第 3 步）、提交推送（第 7 步）、出现阻断或受阻时，改切片表与进度条。
- 闭包表在上述时点改：派发、交回、验收、合回、停下。压缩后先读它。
- 交回本卡前改成最终状态，并把进度总览原样贴进交接报告「做了什么」一节。
- 进度条、切片表与提交历史不一致时，以提交历史为准，先改计划再继续。

## 集中检查

- 结构读数：切片 <N> 之后集中跑一次（命令见 `spec.md`「Testing Decisions」）。差分变异按 `review-code` 技能「差分变异」一段，在最终 head 上跑热点。工具不覆盖的写「未测量」，不写零。
- 常规评审：全部切片完成后一次，按 `quality.md` 风险级别裁剪（L0、L1 不派实现评审；纯文档仍跑 `review-docs` 与 `review-delivery`；L3 逐行读热点）。
- 准入：线内的卡不跑卡级准入，合入父分支的条件归 `integration.md`「线父分支」，本线本波只在父分支头跑一次准入。不在线内的卡在最终 head 跑一次。同机串行；期间不提交、不做占 CPU 的事。整波验证归 Reduce。
