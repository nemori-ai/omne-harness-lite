# 自包含检查

派发者在派发前对每一条交付线做一次本检查。交付线开工后与任何会话都不通信，所以它需要的信息必须全部在上下文地图与任务信息包里。

## 怎样检查

找一个没有任何本次上下文的会话。只给它这两个文件，问三个问题：

1. 从哪个提交开工？
2. 能改哪些文件，不能改哪些文件？
3. 做到什么算完成？

三个问题都答得出，并且答案与派发者的意图一致，包才合格。任何一个答不出，补包，再检查一次。

## 逐项核对

- [ ] 地图第 1 节的冻结提交等于任务信息包的 taskBase，也等于卡上 binding 的 taskBase。
- [ ] 任务信息包的绑定字段与卡上 binding 逐字一致：卡、revision、attempt、分支、route、completionTarget。
- [ ] 写范围已用 `scope-cli.ts` 与同一波其他卡核对，没有交集。
- [ ] 禁写清单列出了冻结的共享、其他线的写范围与集成侧保留的文件。
- [ ] 每条验收判据都能用命令或文件核对，没有「看起来合理」一类的判据。
- [ ] 地图第 3 节的每一项都写到了文件与行，并写明读到哪里停。第一项是 `docs/orientation.md`。
- [ ] 相邻线只给了接口，没有给实现细节，也没有要求本线读相邻线的进度。
- [ ] 包中引用的每个文件都在冻结提交上存在，或者明确写了「待相邻线交付，本线只用其冻结形状」。
- [ ] 包不依赖派发会话的记忆：没有「如前所述」「按我们讨论的」一类指代。
- [ ] 停止条件与交回格式按模板写全。
