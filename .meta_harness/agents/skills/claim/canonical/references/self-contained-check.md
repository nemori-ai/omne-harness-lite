# 自包含检查

调度者在派发前对每张并行的卡做一次本检查。线的执行者开工后与任何会话都不通信，所以它需要的信息必须全部在上下文地图与任务信息包里。

## 怎样检查

找一个没有任何本次上下文的会话。只给它这两个文件，问四个问题：

1. 从哪个提交开工？
2. 能改哪些文件，不能改哪些文件？
3. 做到什么算完成？
4. 每条关键事实的出处与有效修订在哪里？

四个问题都答得出，并且答案与调度者的意图一致，包才合格。任何一个答不出，补包，再检查一次。

## 逐项核对

- [ ] 任务信息包的 taskBase 等于卡上 binding 的 taskBase。线内的卡还要核对它是本波批次分支上的提交。
- [ ] 任务信息包的绑定字段与卡上 binding 逐字一致：卡、revision、attempt、分支、route、completionTarget。
- [ ] 已用 `tools/dev-flow/src/delivery/scope-cli.ts` 核对：本卡与本波其他线的卡的写范围两两不相交。
- [ ] 禁写清单列出了冻结的共享、其他线的写范围与集成节点保留的文件。
- [ ] 每条验收判据都能用命令或文件核对，没有「看起来合理」一类的判据。
- [ ] 地图主体「先读什么」的每一项都写到了文件与行，并写明读到哪里停。第一项是 `docs/orientation.md`。
- [ ] 相邻线只给了接口，没有给实现细节，也没有要求本线读相邻线的进度。
- [ ] 包中引用的每个文件都在 taskBase 上存在，或者明确写了「待相邻线交付，本线只用其冻结形状」。
- [ ] 包不依赖调度会话的记忆：没有「如前所述」「按我们讨论的」一类指代。
- [ ] 停止条件按模板写全。交回格式要求把交接报告五节全文发在卡的交回评论里，不只给 tmp 路径。

- [ ] Line 包有两个协调边界和本域裁量，波中不依赖人/普通评论答复，也不消费新变化。
- [ ] 必要缺口可以结束执行并交 blocked/failed，已有差异与零差异均有合法出口，停写与处置等待完整。
- [ ] 同波重派要求旧执行终止、写权交接、新 attempt 及完整新输入；普通评论不能重开。
- [ ] 当前正式波、真实 R、idle 原因、逐收口重挂及明确 terminal 可区分，未知 nextHint 不被写成结束。
- [ ] 首次派发五事实分别记录，两宿主配置与本次实际宿主观测分开，缺环境明确未验证。
