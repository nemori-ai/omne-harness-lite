# 卡的推进循环

一张卡从第一个切片到候选固定的全过程。规则归 `docs/engineering/quality.md`（风险级别、升级阶梯）、`docs/engineering/integration.md`（准入、双基线）、`docs/development.md`「按改动选择检查」（门禁命令）、`CONTRIBUTING.md`（署名、PR）。本页只给顺序、产物与门槛。反复出现的失误与防范归 `.meta_harness/human/delivery-pitfalls.md`，下面用 P 编号引用。

## 阶段与门槛

| 阶段 | 产物 | 出口门槛 | 适用规则 |
| --- | --- | --- | --- |
| 实施 | 写者交回的改动、命令、退出码与未覆盖项 | 改动在写范围内 | P1、P8、P14、P18 |
| 验证 | 你在候选 head 上复跑功能门禁的日志 | 日志晚于最后一次改动，退出码 0，未覆盖范围已写明 | P1、P2、P13 |
| 评审 | 按风险选择的评审报告，存证据目录 | 每条阻断发现都有处置 | P4、P12、P16、P17 |
| 修复 | 集中修复的提交与复评结果 | 被点名的阻断已闭合，或已按阶梯升级 | P3 |
| 准入 | 最终 head 上的准入日志 | 退出 0，日志里的 head 等于最终 head；增量准入时按「准入」第 4 步 | P11、P12、P13 |
| gate | 不在线内的卡：调度者的 gate 运行记录 | 运行结论、目标分支和记录标签读回成功 | P5、P9、P10 |

## 角色与模型

本节的四档划分与分工是调度者约定，不是拥有者正文。具体模型名与档位钉值归 `.meta_harness/agents/roles/README.md`「模型配置与本次派发」。两者冲突时，以角色源包为准。派发时显式传模型，需要时传推理档位。顶档模型（Claude Fable 5.1、Codex GPT-6 Astra）默认用 medium、最高用 high，只有 hardest 任务用 xhigh；派发七个具名角色时，档位取 `render_pair.py --resolve` 的结果，规则见该 README。

| 承担 | 做什么 | 为什么 |
| --- | --- | --- |
| 调度者（你） | 编排、写规格与计划、写简报、裁定、维护卡与看板、机械子检查点 | 这些工作需要全局上下文和授权。调度者不当常规写者 |
| 便宜档 | 搜集与提炼上下文、链接与锚点核对、看板与标签读回、消费者盘点 | 读多写少，按清单执行 |
| 经济档 | 机械写作：文档单点同步、测试补断言、索引、探针脚本、规格完整的单模块切片 | 规格完整时，质量与中档相当，成本更低 |
| 中档 | 能力与组合行为、具体提供者、契约成员与消费者迁移。代码评审、交付边界核对、文档评审 | 项目默认档 |
| 顶档 | 内核原语与生命周期、并发与失败语义、安全敏感改动、跨多个包的改动。机制不明时的根因定位、第 3 轮修复、结构诊断 | 这些工作出错代价最高，或需要不同于前两轮的判断 |

- 独立验收 `qa` 默认用经济档。结论直接卡住发布，或要驱动真实终端矩阵、多个服务时，用顶档。
- 档位拿不准时上调一档。
- 一个切片里核心语义与机械部分分开派，各取各的档位，不让贵档做机械活。
- 每次派发用新的子代理。把原简报、后续指示和上一轮报告合并进新简报。只读评审在同一轮内的追问可以复用原子代理。
- 子代理的结论是证据，不是接受。你读 diff，写自己的总结。
- 子代理中途停下、没有交回时（例如宿主返回 429 限流），工作树里通常留着它未提交的改动和日志。先看 `git status`、`git diff --stat` 和它的日志，判断它做到哪一步。然后写接续简报：原简报、已有改动清单、剩下的失败与你的推断，派一个新的子代理接着做。不假设它什么都没做，也不丢掉它的改动。再次限流时，可以在角色源包允许的范围内换模型，并把这次偏离记进进度（P18）。

## 切片的七步

`plan.md` 里每个切片按这七步走，每步写承担者：

1. 便宜档子代理补本切片的上下文，只补差额。
2. 写简报：卡与修订、分支、写范围、必要输入、适用的品味与防御条目、完成条件、停止条件。简报里的命令都要能在当前仓库运行（P8）。要求写者在最后一次改动后重跑全部写者门禁，并报告每份日志的时间与提交号（P1）。简报还写明下面三项：
   - 命名账本：本切片涉及的全部成员名、交换表示、对外字段与事件名。写不出的由你先定，不留给写者「报回」。否则写者每轮都正确地停在同一类缺口上，返工的是简报。
   - 写者门禁：简报写明哪些检查算写者门禁，通常是写者自己新增或改动的用例、所属包全量一次、类型检查与 `check:docs` 各一次。demo 全量、冷启动这类对负载敏感的用例由你在验证时跑，写者不循环重跑来追绿。
   - 产物位置：日志与临时文件写进任务过程目录（例如 `tmp/issue-<号>/logs/`），不写在工作树根或其他被跟踪的目录。工作树中 Git 不忽略的未跟踪文件都会被 change-scope 计入改动，超出写范围就被拒绝。
   - 长命令与名额：长命令用宿主的后台运行，等完成通知再读结果。禁止 `until grep …; sleep` 这类轮询日志的循环。日志里出现 `with-test-slot: 排队中` 时，写者读名额的锁文件，报告占用者，然后交回，不干等（P29）。
   - 待定项分类：简报可能让写者交回待定项时，要求写者逐项分类：「能自己定，依据是……」，或「只有负责人能定，因为三问去不掉它：……」。三问指 `docs/engineering/map-reduce-states.md`「提问前三问」。简报里不设「交给负责人」一栏。写者交回的清单，你先过三问，再给负责人看。
3. 写者实施，交回改动、命令、退出码与未覆盖项。证据脚本每一步都核对成功（P14）。
4. 你复跑功能门禁，核对写范围。见[验证](#验证)。
5. 只有切片风险高时在这里评审。常规评审集中到实施完成后。见[评审](#评审)。
6. 有阻断时按[升级阶梯](#评审与修复的升级阶梯)修复。
7. 提交并推送，按[交付计划模板](plan-template.md)「进度更新」改 `plan.md` 的进度总览：勾选、当前一行、切片表与进度条。线内的卡同时改 `tmp/line-<线>/state.md` 的「本波进度」，格式归 `line` 技能范式「进度记录：两层，固定格式」。署名与 trailer 按贡献指南（P5）。

切片之间：

- 不在线内的卡，目标分支前进时先 `git merge` 合入，再运行 `task-sync`，taskBase 不变。线内的卡在波内不合并联调轨道。
- 发现范围、依据或规格冲突时，只暂停依赖它的切片，回到卡级准备裁定。
- 结构度量与品味核对，在若干切片完成后集中跑一次，不在每个切片跑。工具不覆盖的范围写「未测量」，不写零。
- 差分变异的时机、范围、名额与进程数按 `review-code` 技能「差分变异」一段，不在切片之间对整卡的改动全量跑。
- 计划因全局路径（例如 `pnpm-lock.yaml`，清单是 `tools/test-runner/test-runs.config.json` 的 `affected.globalPaths`）的改动判为全量时，中间轮跑不带 `--coverage` 的 `pnpm run metrics`。它只给圈复杂度，不算计划，不占名额。`--coverage` 只在最终 head 上跑。
- 把两个切片判为串行、或报 ETA 之前，点名每段等待争用的文件、类型或资源。点不出来就并行。点得出来时，先做不争用的部分；写范围交叉时，在正确基线上的未绑定草稿树里做，阻塞方落地后再把提交搬过去。一个切片的核心语义部分和机械部分分开，按各自的档位派给不同写者并行。方法见 `dispatch` 技能的 `references/wave-planning.md`（P27）。
- 卡上只在关键进展、阻塞与出现可审阅候选时更新事实，不逐次贴日志。

## 验证

在候选 head 上自己复跑功能门禁，至少类型检查与 lint。写者报告通过时也要复跑。

1. 按 `docs/development.md`「按改动选择检查」选命令。
2. 每份日志记录命令、HEAD 提交号、起止时间与退出码（P13）。
3. 后台运行时把真实退出码传出来：`<命令> > "$log" 2>&1; rc=$?; echo "exit=$rc" >> "$log"; exit "$rc"`（P1）。写者的测试步骤十分钟没有动静时，读名额的锁文件（`slot-*.lock`，目录见 `scripts/README.md`「运行名额」）查占用者，不干等（P29）。
4. 读工具输出的实际范围。工具没覆盖本次改动时写「未覆盖」与替代证据（P2）。

## 评审

实现评审与独立验收按风险级别派发，级别定义归 `quality.md`「按风险选择接受实现的看法」：

| 级 | 实现评审者（`review-code`） | `qa` |
| --- | --- | --- |
| L0、L1 | 不派。例外：机器读数有实施者没交代的红项时，只看那几处 | 不派 |
| L2 | 有未交代的红项，或读完摘要仍说不清某处时派 | 有可运行交付面、验收标准写得成「触发 → 可观察结果」时派 |
| L3 | 派，它逐行读热点。你仍逐行读热点 | 派 |

文档评审与交付边界核对不受级别约束：候选含正式文档变更时开 PR 后跑 `review-docs`。任何候选开 PR 后、接受前跑 `review-delivery`。

力度：契约成员或跨成员的改动分面派发。中等的工具修复合成一次评审。给评审与顾问的简报按 P4 写，发出前按它的「怎样核对」逐项检查。只读评审只在本工作树内搜索，手工变异在副本上改（P12）。评审之间可以并行，不与准入同时跑。子代理写不了报告文件时内联交回，缺字段不判 Pass（P16）。要加约束写进简报，不改带宿主资格摘要的角色提示（P17）。

## 修复

1. 全部阻断合成一轮集中修复，不逐条派发。
2. 修复后复跑受影响的功能门禁。
3. 只复评被点名的项。
4. 记录本轮的修订、阻断、类别、处置与验证。轮次连同接手前的一起数（P3）。

## 评审与修复的升级阶梯

轮次算法与升级顺序归 `quality.md`「三轮未收敛时升级结构诊断」。操作顺序：

| 轮 | 修复方 | 前置动作 |
| --- | --- | --- |
| 第 1、2 轮 | 实施时的档位。实施用经济档时升到中档。第 1 轮续用实施子代理，第 2 轮换新的 | 无 |
| 第 3 轮 | 顶档，或自己修 | 先逐条质疑评审判定：判得对吗，合理吗，本阶段必须闭合吗。站不住的记下理由，不计入未收敛 |
| 仍不收敛 | 停止局部修补 | 冻结当前修订与三轮记录，做结构诊断。可以请只读的顶档顾问给出根因、影响范围、应保留内容和修复路径 |

- 线内的卡两轮未闭合即停止依赖部分。没有其他工作可继续时，按 `line` 交回 blocked 或 failed，然后等待下一条 delta。Reduce 发 redo delta 或接管；是否移入下一波由 reduce 决定，线会话不自行顺延。不在线内的卡按上表升级。
- 第 2 轮修完、复评仍有阻断时，不论阻断是否同类，都按上表升级。
- 阻断与上一轮同类时，第 3 轮整类处理（P3）。
- 缩小承诺是结构诊断的常见结论之一。缩小承诺要经接受者批准。
- 换评审者、分支或拆补丁都不重置轮次。

## 准入

1. 固定候选：记录 head、taskBase 和 targetBase。之后目标分支前进时，先合入并运行 `task-sync`，再按影响重验。线内的卡在波内不合并联调轨道，这一条不适用。
2. 运行 `pnpm run admission`（等于 `OMNE_ADMISSION=1 pnpm run check`）。卡要求时加 `FULL=1`。它按准入锁排队，并把命令、head、逐步结果与退出码写进 `tmp/admission/` 下的准入日志（P13 由入口完成）。
3. 准入期间不提交（P11）、不做占 CPU 的事（P12）。可以写交接报告与下一张卡的简报。
4. 准入失败先定向复现（`npx turbo run test:<层> --filter=<成员> --only --env-mode=strict -- <测试文件> -t <用例>`），不反复全量重跑。`check --keep-going` 一次报出全部失败。修复后，在最终 head 上按 `docs/engineering/integration.md`「增量准入」（在「检查责任」之下）补跑，基线是失败的那个 head。前提、要跑的步骤、全局路径例外、证据写法与命令都以那一节为准。

## 准入与评审的节奏

```mermaid
flowchart LR
  A["切片实施"] --> V["复跑功能门禁"]
  V --> R["按风险评审（只读，可并行）"]
  R --> F["集中修复一轮"]
  F --> V2["复跑受影响的门禁"]
  V2 --> AD["最终 head 上准入一次"]
  AD --> PR["开 PR，交接报告"]
```

- 先复跑门禁再派评审，便宜的问题不等到准入才暴露。
- 评审不与准入同时跑。
- 没有评审发现时，直接在被评审的 head 上准入。

## gate

线内的卡不经 gate，合入批次分支归 line 技能。不在线内的卡交回后，由调度者按 `branch-integration` 技能送进轨道。工具改动要发行时，版本号随工具改动一起入轨（P9）。新版本的行为取决于仓库状态时，改变仓库状态的 PR 通过准入之前，不把发行算作完成（P10）。

## 子检查点的效率规则

范围小的子检查点不走完整阶段（P15）：

- 沿用线级与父项的上下文，只补差额。
- 发行、改钉子这类机械子检查点自己做，不派子代理、不做多面评审。
- 同一份证据只在最终 head 上跑一次。
