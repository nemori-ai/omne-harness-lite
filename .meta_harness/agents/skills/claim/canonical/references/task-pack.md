# 任务信息包模板

每张并行的卡一个任务信息包，放在该卡任务工作树的 `tmp/issue-<编号>/task-pack.md`，与上下文地图放在同一目录。调度者在派发前写全部各节。认领会话只读它，不改它。

各节的字段固定。没有内容的节写「无」，不删节。

```markdown
# 任务信息包：<交付线>（#<卡号>）

## 1. 绑定

与卡上的 binding 一致：

- 卡：<Issue URL>，revision <N>，attempt `<attempt>`
- 派发评论：<URL>
- taskBase：`<完整提交号>`（登记时的批次分支头）
- 分支：`<分支>`
- route：<route>；completionTarget：<目标>
- 工作树：<路径，或「认领时创建」>

## 2. 写范围（独占）

- <路径>
- ...

- [ ] 已用 `tools/dev-flow/src/delivery/scope-cli.ts` 核对：与本波其他线的卡的写范围两两不相交。

## 3. 禁写

- 冻结的共享：<路径>
- 其他线的写范围：<路径>
- 集成节点保留的文件：<路径>

## 4. 交付边界与验收

| 判据 | 成功条件 | 证据 |
| --- | --- | --- |
| <ID> | <可核对的结果> | <命令输出或文件> |

## 5. 替身与命令

- 允许使用的替身：<成员的测试入口>
- 本线自测命令：<命令>
- 准入命令：<线内每张卡自准入的命令，默认 `OMNE_ADMISSION=1 pnpm run check`>
- 准入锁路径：<同一台机器上排队跑准入用的锁文件绝对路径；锁文件存在表示有准入在跑，跑准入或测试前核对>
- 联调命令：<收口点的联调入口，供集成节点使用；没有时写「无」>

## 6. 停止条件

遇到下列情形，停下，把缺口写进交接报告并交回，不绕过：

- 要改冻结的共享。
- 要改写范围外的文件。
- 设计与不变量冲突。
- 验收标准互相矛盾，或与拥有者正文矛盾。
- 需要相邻线的实现细节才能继续。

## 7. 交回格式

1. 候选 PR：base <目标分支>，标题 <标题>，正文含「所含的卡」与「契约变化」两节。
2. 交接报告固定四节：做了什么（逐条对照验收，写达到或未达到，并给出证据）、没做什么及原因、发现的冲突（带文件与行）、给集成节点的提示（合并顺序、依赖、已知的脆弱点）。
3. 交接报告的四节全文发在卡的交回评论里，评论同时写 PR 链接与 head 提交号。工作树 tmp 中的副本可选。只给 tmp 路径不能完成交接。

交接报告只陈述事实。线的执行者不给自己的成果打「通过」，接受归有资格的负责人。
```
