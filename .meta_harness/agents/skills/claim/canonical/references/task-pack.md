# 任务信息包模板

每张并行的卡一个任务信息包，放在该卡任务工作树的 `tmp/issue-<编号>/task-pack.md`，与上下文地图放在同一目录。调度者在派发前写全部各节。认领会话只读它，不改它。

各节的字段固定。没有内容的节写「无」，不删节。

```markdown
# 任务信息包：<交付线>（#<卡号>）

## 1. 绑定

与卡上的 binding 一致：

- 卡：<Issue URL>，revision <N>，attempt `<attempt>`
- 派发评论：<URL>
- taskBase：`<完整提交号>`（登记时的批次分支头）
- 分支：`<分支>`
- route：<route>
- completionTarget：<目标>
- 工作树：<路径，或「认领时创建」>

## 2. 写范围（独占）

- <路径>
- ...

- [ ] 已用 `tools/dev-flow/src/delivery/scope-cli.ts` 核对：与本波其他线的卡的写范围两两不相交。

## 3. 禁写

- 冻结的共享：<路径>
- 其他线的写范围：<路径>
- 集成节点保留的文件：<路径>

## 4. 交付边界与验收

| 判据 | 成功条件 | 证据 |
| --- | --- | --- |
| <ID> | <可核对的结果> | <命令输出或文件> |

## 5. 替身与命令

- 允许使用的替身：<成员的测试入口>
- 本线自测命令：<命令>
- 准入命令：<线内的卡写「整次准入留给集成节点」；不在线内的卡写自准入的命令，默认 `pnpm run admission`（等于 `OMNE_ADMISSION=1 pnpm run check`，另写准入日志）>
- 准入锁路径：<同一台机器上排队跑准入用的锁文件绝对路径。锁文件存在表示有准入在跑，跑准入或测试前核对>
- 联调命令：<收口点的联调入口，供集成节点使用。没有时写「无」>

## 6. 停止条件

遇到下列情形，停止依赖项并继续无依赖工作。线会话无工作可继续时，按 `line` 技能交回 blocked 或 failed 并停写，不在普通评论求方案：

- 要改冻结的共享。
- 要改写范围外的文件。
- 设计与不变量冲突。
- 验收标准互相矛盾，或与拥有者正文矛盾。
- 需要相邻线的实现细节才能继续。

## 7. 交回格式

1. 候选 PR：base <目标分支>，标题 <标题>，正文含「所含的卡」与「契约变化」两节。
2. 交接报告固定五节，格式归 `docs/engineering/integration.md`「线会话记录」。
3. 交接报告的五节全文发在卡的交回评论里，评论同时写 PR 链接与 head 提交号。「做了什么」一节原样贴 `plan.md` 进度总览的最终状态。工作树 tmp 中的副本可选。只给 tmp 路径不能完成交接。
4. 线内的卡：本线本波的卡全部交完后，线会话开批次 PR，并在线父卡发 `<!-- line-handoff -->` 交回记录，规则按 `line` 技能「交回」阶段。

交接报告只陈述事实。线的执行者不给自己的成果打「通过」，接受归有资格的负责人。
```
