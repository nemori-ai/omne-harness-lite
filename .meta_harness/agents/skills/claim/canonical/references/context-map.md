# 上下文地图模板

一条交付线一份地图，放在任务工作树的 `tmp/issue-<编号>/context-map.md`。派发者在派发前填第 1 到第 5 节。认领会话保留这五节，只补第 6、第 7 节。没有派发者地图时，认领会话按本模板写全部七节，写不出的项写「未知」，不猜。

地图是纯文本，不依赖派发会话的记忆或某一种 agent 宿主的私有机制。

```markdown
# 上下文地图：<线名>（#<卡号>）

## 1. 绑定与冻结

- 冻结提交：`<完整提交号>`。本线从它开工，等于 binding 的 taskBase。
- 卡：<Issue URL>，revision <N>，attempt `<attempt>`
- 分支：`<分支>`，route <route>，completionTarget <目标>
- 写范围：<binding 的 writeScope，逐项列出>
- context 读回：<`status` 输出的 issue、revision、attempt、taskBase、targetBase；派发者填写时写「待认领后读回」>

## 2. 不变量

<本线必须保持的不变量原文，每条写机读标识与来源文件。没有时写「无」。>

## 3. 先读什么，读到哪停

1. `docs/orientation.md`：仓库定向页，读到能找到本线的拥有者为止。
2. <文件>:<起始行>-<结束行>：<为什么读，读到哪里停>
3. ...

不要读：<与本线无关、读了会扩大范围的路径>

## 4. 本线最容易踩的耦合

- <哪条轴不能决定哪条轴，哪个外域概念不能进本域契约>

## 5. 相邻线的接口

| 相邻线 | 它提供什么 | 它需要本线提供什么 |
| --- | --- | --- |
| <线名> | <接口或冻结形状> | <接口或无> |

只写接口，不写相邻线的实现细节。

## 6. 本次加载

- 读者角色：<id>；执行角色：<角色>，`implementation_kind`：<product|terminal|verification>
- 实际读过的 pstack 技能：<名称列表>

## 7. 仍未知

- <还没有确定的点，以及确定它需要谁的输入>
```

第 3 节的第一项固定为 `docs/orientation.md`。路径已冻结，派发者不删这一项。
