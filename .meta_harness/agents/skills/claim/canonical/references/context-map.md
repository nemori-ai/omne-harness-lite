# 上下文地图模板

同一波并行的各张卡共用一份地图主体，每张卡再加一节本线附录。调度者在派发前写主体与本线附录，放在该卡任务工作树的 `tmp/issue-<编号>/context-map.md`。认领会话保留调度者写的内容，只补「认领时补写」一节。没有调度者地图时，认领会话按本模板写全部各节。写不出的项写「未知」，不猜。

地图是纯文本，不依赖调度会话的记忆或某一种 agent 宿主的私有机制。

```markdown
# 上下文地图：<交付线>（#<卡号>）

## 主体（同一波各卡相同）

### 冻结头

- 冻结头：`<完整提交号>`。同一波的每张卡从它开工，等于各卡 binding 的 taskBase。

### 不变量

<本波必须保持的不变量原文，每条写机读标识与来源文件。没有时写「无」。>

### 系统地图

- `docs/orientation.md`：仓库定向页，含领域地图、协作图与顶层架构图。本项固定，不删。

## 本线附录

### 绑定

- 卡：<Issue URL>，revision <N>，attempt `<attempt>`
- 分支：`<分支>`，route <route>，completionTarget <目标>
- 写范围：<binding 的 writeScope，逐项列出>
- context 读回：<`status` 输出的 issue、revision、attempt、taskBase、targetBase；调度者写地图时写「待认领后读回」>

### 先读什么，读到哪停

1. `docs/orientation.md`：读到能找到本线的拥有者为止。本项固定，不删。
2. <文件>:<起始行>-<结束行>：<为什么读，读到哪里停>
3. ...

不要读：<与本线无关、读了会扩大范围的路径>

### 本线最容易踩的耦合

- <哪条轴不能决定哪条轴，哪个外域概念不能进本域契约>

### 相邻线的接口

| 相邻线 | 它提供什么 | 它需要本线提供什么 |
| --- | --- | --- |
| <交付线> | <接口或冻结形状> | <接口或无> |

只写接口，不写相邻线的实现细节。

## 认领时补写

### 本次加载

- 读者角色：<id>；执行角色：<角色>，`implementation_kind`：<product|terminal|verification>
- 实际读过的 pstack 技能：<名称列表>

### 仍未知

- <还没有确定的点，以及确定它需要谁的输入>
```
