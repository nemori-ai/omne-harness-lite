# 上下文地图模板

地图分两部分：

- 主体是线级的，放 `tmp/line-<线>/context-map.md`。一条线的各张卡跨波共用一份主体。线会话在线级准备时写它。调度者已给主体时，线会话只核对，不重写。
- 本卡附录是卡级的，放该卡任务工作树的 `tmp/issue-<号>/context-map.md`。它只写本卡的绑定、依据、缺口与受影响成员，主体用链接引用。本波的卡由线会话写附录，放 `tmp/line-<线>/w<波>/`。线外的卡由调度者在派发前写，认领会话保留调度者写的内容，只补「认领时补写」一节。

没有线（单独派给一张卡）时，主体与本卡附录写在同一个文件 `tmp/issue-<号>/context-map.md` 里。写不出的项写「未知」，不猜。

地图是纯文本，不依赖调度会话的记忆或某一种 agent 宿主的私有机制。收口点与线轨道同步点每波都变，不写进地图，以线包、`line-delta` 与本卡 binding 为准。

## 主体

```markdown
# 线级上下文地图：<线>（线父卡 #<号>）

## 不变量

<本线必须保持的不变量原文，每条写机读标识与来源文件。没有时写「无」。>

## 系统地图

- `docs/orientation.md`：仓库定向页，含领域地图、协作图与顶层架构图。本项固定，不删。

## 先读什么，读到哪停

1. `docs/orientation.md`：读到能找到本线的拥有者为止。本项固定，不删。
2. <文件>:<起始行>-<结束行>：<为什么读，读到哪里停>
3. ...

不要读：<与本线无关、读了会扩大范围的路径>

## 本线最容易踩的耦合

- <哪条轴不能决定哪条轴，哪个外域概念不能进本域契约>

## 相邻线的接口

| 相邻线 | 它提供什么 | 它需要本线提供什么 |
| --- | --- | --- |
| <线> | <接口或冻结形状> | <接口或无> |

只写接口，不写相邻线的实现细节。

## 本线加载

- 读者角色：<id>。查询命令与输出位置：<路径>
- 执行角色：<角色>，`implementation_kind`：<product|terminal|verification>
- 本线共用的三层技能（流程、写法、品味，见 `docs/engineering/skills.md`「三层分工」）：<名称列表>
```

## 本卡附录

```markdown
# 上下文地图本卡附录：#<卡号>

主体：<`tmp/line-<线>/context-map.md` 的路径或链接>

## 绑定

- 卡：<Issue URL>，revision <N>，attempt `<attempt>`
- 分支：`<分支>`，route <route>，completionTarget <目标>
- 写范围：<binding 的 writeScope，逐项列出>
- context 读回：<`status` 输出的 issue、revision、attempt、taskBase、targetBase。调度者写地图时写「待认领后读回」>

## 本卡依据

- <本卡特有的依据，每条带链接与精确修订。主体已列的不重复>

## 缺口

- <要补的实现、验证、文档、发行与登记，每项写来源>

## 受影响成员

- <受影响的成员与现有消费者>

## 认领时补写

- 读者角色：见主体「本线加载」。
- 执行角色与本卡额外加载的技能：<与主体相同时写「同主体」>
- 仍未知：<还没有确定的点，以及确定它需要谁的输入>
```
