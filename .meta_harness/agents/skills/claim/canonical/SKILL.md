# 认领

Issue 编号来自本次输入。没有编号时问一次，然后停下。

1. 按 `docs/engineering/agent-delivery.md` 认领。认卡评论写明负责人、宿主、会话、当前修订、授权依据和已有执行核对。已有派发就引用该决定。评论本身不授予执行权。
2. 按 `docs/engineering/integration.md` 和该卡的 route 确定指定基线。先把该基线同步到远端最新，再从这枚提交创建工作分支和工作树。分支名遵守仓库的署名约定。
3. 按 `docs/engineering/workflow.md` 把工作放进独立工作树。当前会话的工作根必须变成这棵工作树。宿主切换要求远端已有该分支、而分支尚未推送时，报告这一点并停下。不要为了切换而推送。
4. 读取并遵循 `pstack:bro`。用白话介绍这个任务要完整交付的成果。依据是该 Issue 的现行正文和验收条件。不把实现计划说成已经交付。
5. 报告 Issue、基线提交、分支、工作树路径、会话是否已切过去。然后停下，等下一条指令。不开始实现，不提交，不开 PR。
