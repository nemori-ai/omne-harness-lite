# 视觉规范

本技能写桌面应用与共用界面件看起来、动起来应当是什么样，以及为什么。规则只在这里写一次：规格写承诺并指到这里，代码照这里做。契约、不变式与产品的取舍不在这里，在下面「规则在哪里」列的拥有者那里。

来历：规则取自 super-assistant `83c1616f` 的设计文档与它的 `ink-motion` 技能。本仓库改了前缀（`--omne-`、`omne-`）、名词（统一语言的词）与范围（产品正文的「非目标」不收）。

## 一句话的标准

明亮的书桌与一盏暖灯：白天是羊皮纸与象牙白，夜里是暖炭色。层次靠阅读字体、间距与细线，不靠卡片与阴影。墨蓝只标动作、链接与焦点。琥珀是唯一「等你回答」的颜色，此外只作已知事实的「注意」语气。红只用在失败的事实与不可撤销的最后一步上。屏幕上有一个用毛笔写成的 Agent 形（简称形），它是 agent 本身；凡是它展开给人看的东西，都画在同一种墨框里。别的地方安静：正常的状态不画字、不画点、不画线。

## 六个问题排在好看之前

每一屏、每个组件先答六个问题：

1. 这是什么？
2. 是谁的？
3. 处在什么状态？
4. 谁改的？
5. 人能做什么？
6. 做了会怎样？

一个好看但在归属、状态或后果上误导人的界面是错的。这是观感验收的第一条。

## 四条最常用的否定

- 卡片里不再套卡片。
- 面上不写工具动作的字：常用的是图标钮，偶尔的进 `⋯`，字只留给落定、对话里的选项与一页唯一的主动作（[索引](references/rules-index.md)的 A 节）。
- 四个及以上平铺的动作是缺陷：把它们收进一个 `⋯`。
- 不模拟进度：没有假的百分比、计时与打字。

## 数在哪里

- 界面的数只在 `packages/frontend/ui-kit/src/styles/tokens.css`：颜色、字号、行高、间距、圆角、控件高度、图标大小、动效的时长与曲线。组件读语义层的 token，不写死数。本技能与 token 不一致时，以 token 为准，并回来改本技能。
- 形与墨框的数在 `packages/frontend/ui-kit/src/ink/` 的具名常量里，翻面的数在 `packages/frontend/ui-kit/src/paper/flip.ts` 的具名常量里。共用件的代码不写注释，所以每个常量的出处与它守住什么写在本技能的表里：笔法、时长、状态、移动与座位、墨框、翻面各有一张。
- 规则与 token 的对照在[规则与 token 的索引](references/rules-index.md)。

## 规则在哪里

| 问题 | 拥有者 |
| --- | --- |
| 产品要什么：形、形座位、状态表、待答数、告知笺、主题与字号档、非目标 | 产品正文 `.meta_harness/design/product/desktop-application/design.md` 的 `#agent-在屏幕上的形`、`#观感`、`#非目标` |
| 共用件给什么：块、外壳契约、形口、瞬时提示、不变式 | `packages/frontend/SPEC.md` 的 `#心智模型`、`#墨迹`、`#字号档`、`#外壳契约`、`#不变式` |
| 外壳怎样画：版式、家、外观、告知笺、窗口、键盘 | `apps/desktop/SPEC.md` 的 `#页面`、`#窗口` |
| 每一屏的版式、状态与用了哪些件 | 所在包组 `SPEC.md` 的界面一节 |
| 词 | 统一语言 `.meta_harness/design/ubiquitous_language/` |
| 看起来、动起来的规则，为什么，怎样验 | 本技能 |

几处说法不一致时：数以 token 为准，承诺以规格为准，产品的取舍以产品正文为准，看起来与动起来的规则以本技能为准。不一致本身是一个缺陷：报给拥有者，改到一致。不要在新代码里挑一边将就。
