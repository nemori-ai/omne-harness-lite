# 加一页的步骤与清单

> 什么时候读：要给应用加一页，或给已有的页加一块看得见的东西之前。
> 按下面的顺序做，每一步都有对应的规则与检查。道理在[设计语言](design-language.md)，规则在[规则与 token 的索引](rules-index.md)。页由某个领域的界面模块放进外壳；接入的做法归技能 `domain-access-plugin`，契约归 `packages/frontend/SPEC.md#外壳契约`。

## 1. 先写下六个问题的答案

动手之前，为新页或新的一块写下六个答案，放进卡或 PR 的描述：

1. 这是什么？
2. 是谁的？人的、agent 的，还是外部来的？
3. 它可能处于哪些状态？只用共用件状态词表里的词。
4. 谁会改它？人、agent，还是外部？改了以后人怎样看出来？
5. 人在这里能做什么？
6. 每个动作做了会怎样？能不能撤销？会不会影响别的会话或外部？

答不出第 6 个问题时，先不要画按钮。

## 2. 选一个页面家族

| 新东西是 | 用这个家族 | 从这里开始 |
| --- | --- | --- |
| 一个去处，内容是一列东西或一组设置 | 单列页 | `PageColumn` 加 `PageHeader` |
| 一类东西，要能浏览、阅读、新建、编辑 | 列表加阅读 | 共用件的列表加阅读（目录栏、阅读工具条、阅读面、`RecordMenu`）；选中记录时列表不重新挂载 |
| 一组类别，每类一个窗格 | 栏加窗格 | 共用件的栏加窗格 |
| 和 agent 来回说话的地方 | 对话 | 会话的界面模块；规则见[对话流](conversation-stream.md) |
| 临时的选择、命令或预览 | 浮层 | 共用件的菜单、弹出框、抽屉 |
| 形展开给人看的东西 | 墨框 | 共用件墨迹块的墨框；规则见[墨框与告知笺](ink-bubble.md) |

新东西是一个去处时，它的界面模块往外壳的 `pages` 位置放一项：`id`、`title`、`order`、`icon`，次要的去处给 `group: 'utility'`。导航的一行与页标题是同一个词（W2）。`icon` 取自图标集；图标集没有的意思先画字形（I1、I11）。

几个家族都不合适时，停下来。先在本技能里写清新家族的结构、状态与进出方式，评审通过再写代码。

这一页的版式、状态与用了哪些件，写进所在包组 `SPEC.md` 的界面一节。规则不抄进规格，规格指到本技能。

## 3. 为每个动作选反馈

为第 1 步列出的每个动作，按下表选出它的反馈。对应的件已经自己处理的，不再写任何动效代码。

| 动作之后发生了什么 | 选这个 | 用什么实现 |
| --- | --- | --- |
| 一个新结果出现了：提示、错误、回执、新行、加载完的内容 | 到达 | `InlineNotice`、`EmptyState`、`SaveReceipt` 与回执的件自己到达；别的东西用 `useArrival` 或 `Arrive` |
| 人点开流内的内容：详情、内嵌表单、编辑器的一节 | 展开 | `Disclosure` 或 `DisclosureTrigger` |
| 屏上已有的东西在原地变了：已保存、已提交、已回答 | 落定 | `useSettleCue` |
| 流内的东西离开 | 直接消失 | 不写任何东西 |
| 换了页或换了会话 | 页面到达 | 外壳已经处理，不要再加 |
| 在列表加阅读里换了记录 | 阅读面到达 | 阅读面已经处理，列表不能重新挂载 |
| 打开菜单、弹出框、抽屉 | 从锚点或边缘进出 | 共用件的浮层已经处理 |
| 开关、单选、分段、下拉 | 控件本身就是回执 | 立即生效，等待只显示在这个控件上，失败时恢复并在这一行给提示 |

不要做的事：

- 不写新的时长或曲线。只用 `--omne-motion-*`，动效门拒绝别的值。
- 不给首屏元素做错开入场。
- 不做离开动画，浮层除外。
- 不用 width、height、top、left 做动画。展开用网格行。

## 4. 有后果的动作要确认

按后果大小选容器（D1）：

- 动作可以撤销，后果只在这里：不需要确认，给一个回执就够了。
- 动作在这里不可撤销，但只影响这里：用原地确认（`InlineConfirm`）。红只给不可撤销的最后一步。图标按钮变成待确认时要带提示文字。
- 动作会影响别的会话、别的人或外部结果：用影响面板（`ImpactPanel`），列出谁受影响、什么保留、什么没做完。

不要用 `window.confirm`、底部抽屉或侧边抽屉来确认。

## 5. 尺寸只从档位里选

- 控件高度：默认的那一档。只有在芯片、行、表格和展开触发器里面才用紧凑的。用按钮的 `size`，不在样式里写高度（S3）。
- 图标：挨着文字、只有图标、紧凑控件与芯片里，三档（I5）。
- 字号、行高、圆角、间距：用 token。成员的样式里不写 px 与 rem 的数，1px 的细线除外（Z4）。
- 断点只有 768、1100、1160（S4）。
- 需要一个档位里没有的尺寸时，先确认这是一个新角色，再加 token、写进索引（S14）。

## 6. 只用已有的件

要做的事用哪个件，查[一件事一个件](rules-index.md#一件事一个件)。

自己写的可点元素必须带 `data-control` 的族标记，或者干脆用共用件。没有族标记的元素没有悬停和按下的反馈（K4）。

确实需要一个新的共用件时，把它放进 `packages/frontend/ui-kit/`，在「一件事一个件」里写下它的用途和什么时候不该用，再加进相应的检查。成员里不放共用的件。

## 7. 每个状态都要画出来

逐条确认新页有下面这些状态，并且每个都用了对应的件：

- 加载中、空、出错（带恢复动作）
- 等待中：只禁用正在等待的那个控件
- 结果未知：中性的词，加一个再确认的动作
- 禁用：说明为什么，或者干脆不显示
- 很长的内容：换行而不是缩小字号；被截断的地方留下看得见的痕迹（`+N` 或渐隐）

键盘也要能走通：Tab 能到每个控件，Escape 关闭浮层并把焦点还给触发它的控件，F6 能在区域之间走（K9）。

## 8. 文案

- 文案只有中文。共用件的文案由调用者传入，缺省是中文；共用件不挑错误码的措辞。
- 名词用统一语言的词。状态词只用状态词表。
- 日常界面不出现标识、协议名和原始报错。原始值放进详情（W5、L7）。
- 空状态写「这里会出现什么」，人能创建时加上创建它的动作（L5）。

## 9. 验证

1. 跑检查：

   ```sh
   pnpm run typecheck
   pnpm run lint:rules
   pnpm run lint:oxlint
   pnpm run lint:deps
   ```

   再在每个改动成员的目录里跑 `pnpm exec vitest run --mode fast` 与 `--mode slow`。

2. 走真的页面：`node apps/desktop/demo/page-walk.mjs --shots <目录>` 起真的服务端、独立转发进程与无界面的 Chromium，走完已有的步骤并截图。新页要在走查里加上自己的步骤。
3. 观感走查：按[观感验收的方法](visual-acceptance.md)截图，两套主题，三个窗口（1440×900、1100×760、720×480）。逐张看溢出、截断、对齐和对比度。窗口与标题栏只有真的 Electron 里看得到：在 `apps/desktop` 下 `pnpm run window`。
4. 为每个新动作加一条动效探针：做一个真的指针或键盘动作，写明期望的反馈（到达、展开、落定或浮层）、必须动的是哪个元素、哪些元素必须不动。
5. 打开系统的「减弱动态效果」，再走一遍新动作：移动都变成淡入淡出，状态词还在。

## 10. PR 自查清单

- [ ] 六个问题的答案写在卡或 PR 的描述里
- [ ] 属于一个页面家族；导航的一行与页标题是同一个词
- [ ] 每个动作都按第 3 节选了反馈，探针通过
- [ ] 有后果的动作按第 4 节选了确认容器
- [ ] 没有写死的尺寸、颜色、时长
- [ ] 只用了已有的件；新的共用件写进了「一件事一个件」
- [ ] 加载、空、出错、等待、结果未知都画了
- [ ] 两套主题、三个窗口截图看过
- [ ] 减弱动效下走过一遍
- [ ] 所在包组 `SPEC.md` 的界面一节写了这一页
