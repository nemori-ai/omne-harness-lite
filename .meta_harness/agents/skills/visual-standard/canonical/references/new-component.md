# 推一个新组件的七步

> 什么时候读：要做一个来源里没有、照抄得不到的组件之前，例如放行卡、后台调用、设置的层与锁、用量图表、供应健康。
> 每一步的出处是[规则与 token 的索引](rules-index.md)里的编号。

本仓库有许多 super-assistant 没有的组件。它们不是照抄能得到的，按下面七步推出来，每一步都有规则里的出处。以后新加组件也照此做。

| 步 | 问什么 | 出处 |
| --- | --- | --- |
| 1 | 它属于哪一族：单列页（`PageColumn`）、列表加阅读、栏加窗格、对话流里的一行、浮层，还是形展开的东西 | S6；[墨框与告知笺](ink-bubble.md)「算哪些」 |
| 2 | 它有多重。只有四档：要人决定的事最重（决定宽度、浮层底、细线抬起）；正文与气泡；过程行（一行：图标、名字、状态词，原地展开）；回执最轻（说明字号、弱墨、无边框、至多一个对勾） | N3；[对话流](conversation-stream.md)原则 5 |
| 3 | 它的每个状态怎样说真话：加载、空、错、等待、未知、部分、禁用、内容过长，各画一种；未知是中性的，不是失败也不是零；被裁掉的留 `+N` 或渐隐 | L1 至 L9 |
| 4 | 它的反馈归哪一种：自己就是回执的控件（开关、单选、分段、下拉）立刻显示新状态；结果看不见的动作（保存、提交、移除）落一个回执或一次落定；失败写在出事的那一行 | N1、L8 |
| 5 | 它怎样出现与离开：不是人亲手打开的结果「到达」；人亲手打开的「展开」；原地变了事实的「落定」；离开的直接切掉。一次操作一个主动作 | M3、M7 |
| 6 | 它用哪些现成的件。先在共用件里找；找不到时问它是不是一个新角色，是才加 token 与共用件，不在成员里私造 | S14；[一件事一个件](rules-index.md#一件事一个件) |
| 7 | 它的字：一个概念一个词，用统一语言里的词；状态词取自共用的状态词表；人话在前，机器的原文收进「详情」；界面不替系统说废话 | W1 至 W11 |

三条最常用的否定：卡片里不再套卡片；四个及以上平铺的动作是缺陷，收进一个 `⋯`；不模拟进度（没有假的百分比、计时、打字）。

## 推完之后

- 这个组件的版式、状态与用了哪些件，写进它所在包组 `SPEC.md` 的界面一节。七步的答案是那一节的依据，不另存一份。
- 第 6 步加了新的共用件时，在[一件事一个件](rules-index.md#一件事一个件)的表里加一行，写它的用途与什么时候不该用。
- 第 6 步加了新的 token 时，在[规则与 token 的索引](rules-index.md)里写下它的角色与用法。
- 一个例子：图表是规则里没有的东西，按七步推出来是「数是内容，内容是平的」：一张图是一段（上面一条细线、说明字号的强标题、下面是图），没有底色、阴影与圆角框；颜色只取图表色的 token；数据到了整张图到达一次，之后数变了只落定。
