# 设计语言：为什么这样设计

> 什么时候读：要知道一条规则为什么是这样，评审时要引道理，或想破一条规则之前。
> 这一份只讲道理，不给数。逐条规则在[规则与 token 的索引](rules-index.md)，数在 `packages/frontend/ui-kit/src/styles/tokens.css`。

## 1. 每一层只回答一个问题

设计语言散在一份文档里时，规则和数会各自漂移：来源在一次审查里发现同一组数有五个副本，代码里几十处规范引用已经失效。所以这里按问题分层，每层只有一个权威：

| 层 | 回答什么 | 位置 | 怎么守住 |
| --- | --- | --- | --- |
| 产品正文 | 产品要什么，不要什么 | `.meta_harness/design/product/desktop-application/design.md` | 产品负责人接受 |
| 设计语言 | 为什么 | 本技能的这一份 | 人读，评审时引用 |
| 规则 | 是什么：每条规则、每个件的用途 | 本技能的其余各份 | 引用检查：代码与规格引用的标题必须存在 |
| token | 数的唯一来源 | `packages/frontend/ui-kit/src/styles/tokens.css` | 令牌门、刻度门、动效门 |
| 组件 | 规则的唯一实现 | `packages/frontend/ui-kit/src/` | 一事一件门、没人用的件门 |
| 检查 | 把规则变成会失败的测试 | `ui-kit/tests/`、各成员的测试、`tools/product-checks` | `pnpm run lint:rules` 与成员的测试 |
| 走查 | 在运行中的应用上看与量 | `apps/desktop/demo/` 下的走查脚本 | 截图、量数、动效探针 |

几层之间说法不一致时，数以 token 为准，规则以本技能为准，承诺以规格为准。发现不一致就是发现了一个缺陷：改到一致为止，不要在新代码里选一边将就。

## 2. 立场与六个问题

立场归产品正文：形是 agent 本身，人在应用里随时要知道 agent 有没有在做事、有没有事在等自己回答（「Agent 在屏幕上的形」）；整个应用用一套设计语言（「观感」）。下面的道理都从这个立场推出来。

每个画面都要一眼回答六个问题：这是什么，是谁的，处于什么状态，谁改的，人能做什么，做了会怎样。一个好看但在归属、状态或后果上误导人的画面是错的。这是验收的第一条，排在好不好看之前。

## 3. 七条原则

每条原则后面写它防住的错误。

### 3.1 状态说真话

已受理、进行中、已完成、结果未知、失败是五个不同的事实，长得也不一样。只有真实在进行的事会动。结果未知是中性的，不画成成功，也不画成失败。不做假进度条、假打字效果，也不重播历史回执。

反过来，诚实不等于沉默：真实的过程、失败和未知都要有一行看得见的字。

防住的错误：一个在别处已经回答过的请求，仍然显示可以批准和拒绝的按钮。人以为还要决定，其实事情已经过去了。

### 3.2 东西有身份

同一个东西在每个地方都长一样：名字和状态词不变，变的只是露出多少。东西的名字本身就是打开它的入口，不要在名字旁边再放一个「打开」。

防住的错误：同一个去处在侧栏、页标题与文档里各叫一个名字。人会以为这是三个地方。

### 3.3 动作立刻发生，动效解释结果

动作本身不等动画。动画只回答一个问题：刚才发生的事，东西从哪里来、到哪里去、为什么变了。没有装饰性的动效。

防住的错误：在两页之间切换、在列表里换一条记录时，画面直接跳变。人看不出内容是换了，还是同一页刷新了一下。

### 3.4 一族控件一种手感

同一类控件在侧栏、页面、浮层里给出相同的悬停、按下、选中和焦点反馈。可以点的东西都有反馈。不能点的东西不显示手形指针，也不变色。

焦点环与控件画在自己外面的任何记号，永远完整地画出来。留出余地的是容器，不是控件：焦点环到处一个样子，只有容器知道自己为什么裁切（规则 K1）。

防住的错误：一行引用了不存在的颜色 token，悬停反馈悄悄消失，没有任何检查报错。折叠区的 `overflow: hidden` 切掉了刚聚焦的输入框的焦点环两边。

### 3.5 一个概念一个词

一个概念只有一个词，取自统一语言。导航的一行和它打开的页标题说同一个词。状态词只取自共用件的状态词表。

防住的错误：页标题是一个词，页内文案一直说另一个词。人分不清这是不是同一样东西。

### 3.6 人话在前，精确值在详情里

日常画面不出现内部代码、标识和协议名。先说人话，提供方的原始值放在小号等宽字里，或者收进「详情」。人需要原文的地方要能找到原文。

防住的错误：轮询失败时，设置页把服务商返回的原始报错直接当作这一行的说明，而失败状态下只给了一个破坏性的动作。

### 3.7 规则写成检查

只写在文字里的规则会漂移，因为它要求每个人都记得。能写成检查的规则就写成检查。检查从本技能与 `tokens.css` 读数，不在测试里抄一份。

防住的错误：没有检查盯着行高、图标尺寸和字号时，来源的样式表里出现了 99 处写死的行高、92 处不在刻度上的图标尺寸。

## 4. 空间：东西从哪里来，回哪里去

界面有六个层，每层只有一种进出方式。层让人知道一个东西是内容，还是临时浮起来的：

| 层 | 放什么 | 怎么进出 |
| --- | --- | --- |
| L0 纸 | 工作区底色 | 不动 |
| L1 侧栏 | 页面的导航、侧栏区、底部的次要入口 | 折成窄条 |
| L2 内容 | 气泡、行、表单、段 | 新到的内容上浮 4px 淡入；历史不动 |
| L3 贴边面板 | 宽窗口里停靠的侧边内容 | 从贴着的那条边滑入 12px |
| L4 锚定浮层 | 菜单、弹出框、下拉、提示 | 从锚点长出 4px |
| L5 模态 | 有后果的确认、影响面板、抽屉 | 遮罩淡入，内容从触发它的方向进来 |

**起点规则**是这一节的核心：浮起来的东西总是显示它从哪里来。菜单从按钮长出来，确认从触发它的方向进来。内容不戴浮层的阴影，浮层也不装成内容。

抽屉是一个例外的组合：它盖住内容，所以有遮罩和浮层的外观（L5）。它的起点是屏幕边缘，所以从那条边整幅滑进来，而不是只移动 12px。贴在版面里的面板才滑 12px。

所有导航类浮层在换页时关闭，在窗口跨过产生它的断点时也关闭。否则窄窗口下打开的导航抽屉会在窗口变宽后一直盖在页面上。

墨框不在这六层里：它是形展开的东西，画在形的那一层。它与应用自己的浮层不能混，见[墨框与告知笺](ink-bubble.md)。

## 5. 出现与消失：四种动作

以前每个页面自己决定一个东西出现时动不动，多数页面什么都没做，于是错误提示、回执、新加的行都是硬切出来的。现在按发生了什么来选动作，不按个人口味：

| 发生了什么 | 动作 |
| --- | --- |
| 一个结果出现了，不是人亲手打开的 | **到达**：上浮 4px 淡入 |
| 人亲手打开流内的内容 | **展开**：网格行从 0fr 到 1fr；有箭头就转 |
| 屏上已有的东西在原地换了事实 | **落定**：透明度从 .6 到 1 一次 |
| 流内的东西离开 | **离开**：直接消失 |

浮层不在这张表里，它们按第 4 节从锚点进出。每种动作用哪个时长与曲线，见规则 M3 与[时长](timing.md)。

### 5.1 页面带着同时出现的东西

在页面自己到达（换页、换记录、启动）之后一个 `enter` 时长以内挂上的东西，跟着页面一起出现，不再单独动。晚于这个窗口挂上的东西，自己到达。

这条规则解决了三个问题。第一，首屏不会出现一堆元素各自淡入的编排。第二，从缓存直接画出来的内容跟着页面走，网络晚到的内容自己到达，人看得出「这是刚来的」。第三，规则由组件自己执行：提示、空状态、回执、确认在挂上时自己判断时间，调用方不用记得包一层。没有人能忘掉它。

历史消息、「更早的」和分页是例外。它们挂得晚，但不是新的，所以不动。

### 5.2 为什么离开不做动画

有三个原因。动作要立刻发生，离开的动画会让人等一个已经不存在的东西。离开的动画要求节点在状态改变后继续挂着，容易留下过期的内容和可以点的按钮。离开时下面的内容会补位，补位本身就是一次移动，再加一个淡出就成了两次。

浮层是例外：它浮在上面，退出不推动版面，退出的方向本身说明它回到哪里去。

### 5.3 一个动作，一次主要的移动

一个人的动作只产生一次主要的移动，加上它的直接结果。没有页面加载的编排，没有错开入场，不在人阅读时改变版面。移动只用 transform 和 opacity。展开用的网格行和两个网格轨道（侧栏、停靠的侧边内容）是仅有的版面动画。全局主题色不做动画。

### 5.4 一只钟

所有时长和曲线只来自动效 token。循环动画只在真实进行时运行，匀速，离开视口和窗口隐藏时暂停。活动标记用图标的同一支笔写：斜着落下的三个墨点，按顺序写上去、再干回淡痕。它只以笔法动，不转、不缩放、不弹，所以不是转圈的 spinner。它也不画圆，因为开口的圆只属于形。

### 5.5 减弱动效

系统设置为减弱动效时，到达和面板移动只保留透明度变化，时长降到 `feedback`。落定的透明度提示保留，因为它本来就不移动。展开和滑动的高亮直接切换。循环停下，但状态词留着。形不写、不飞，每个状态留一个静的记号（[状态](states.md)）。

## 6. 尺度：少数几个数，到处一样

界面看起来不统一，多半不是某个数选错了，而是每个地方都自己选了一个数。所以每类尺寸只留几档，每档对应一个角色，按角色选，不凭眼睛选：

| 尺寸 | 档位的角色 |
| --- | --- |
| 控件高度 | 紧凑（芯片、行、表格、展开触发器里面）、默认、强调、触控 |
| 图标 | 紧凑控件和芯片里、挨着文字、整个按钮只有图标 |
| 字号 | 展示、页面标题、内容标题、阅读、界面、元信息 |
| 行高 | 阅读、标题、单行界面文字、会换行的界面文字 |
| 圆角 | 芯片、控件、卡片、窗口 |
| 间距 | 行内控件之间、相关的块之间、分开的段之间、页面级 |
| 断点 | 侧栏变抽屉、列表加阅读变一栏、对话区放得下停靠的侧边内容 |

确实需要一个新尺寸时，先问它对应的是不是一个新角色。是新角色，就在 `tokens.css` 里加 token，在本技能的索引里写下角色和用法，再用它。不是新角色，就用已有的档。

字号档是整个界面一起变大变小的唯一旋钮：token 里的长度都乘 `--omne-size`，成员只读 token，所以换一档时版式不变（规则 Z1 至 Z5）。

### 6.1 图标：一支笔，几笔写意

整个产品的样子是纸与墨，图标也该是纸上的东西，而不是从工程图标库里借来的细线。所以产品自己画图标，用一支毛笔的笔意，抽象、留白。规则在 I1 至 I12，这里说为什么：

- **几笔就够。** 一个图标只写它那件东西的姿态，最多三笔，里面不画细节。要三笔以上才认得出来，说明比喻选复杂了。笔画少了，纸就露出来了，侧栏不再显得挤。
- **一只手。** 每一笔都从一条中线生成，所有图标共用一条压力曲线，没有哪个图标有「自己的手」。闭合的形状留一个口，像一笔画成的圆。曲线的不匀写在中线里，不靠噪点、滤镜或贴图，所以 16px 下仍然清楚，颜色也跟着 `currentColor` 走。
- **一个意思一个图标。** 图标按意思命名，一个图标也不表示两个意思。整个界面只画图标集里的图标：细线图标库和毛笔图标放在一起，就是两只手。
- **动一下就好，要柔。** 只有拿着图标的那个控件被悬停或聚焦时，图标的一个部分才动，控件本身不动。图标先等一个 `feedback`，所以指针从侧栏上一路划过去，图标都不动；停住了，图标才用匀称的减速曲线滑进姿态。起步很陡的曲线会让一笔在前 40ms 就写完，看起来不丝滑。

## 7. 颜色：颜色表达事实

颜色只用语义角色：面、交互的底、强调、墨、线、事实色。名字说明它画在哪里，一个角色只有一个名字。不为某个页面单独加调色板。

颜色只在这几处有含义，各有原因：

- 墨蓝只标出动作、链接和键盘焦点。到处都是蓝色时，人就找不到下一步该点哪里。
- 琥珀是唯一「等你回答」的颜色：待答数、等人回答的决策卡片、列表里等人的那一行，都是琥珀；别的颜色从不表示在等人。人看到琥珀就去找等着自己的那件事。
- 绿、琥珀、红是说已知事实的三种语气：成功、注意、失败。它们说事实，不作装饰。除了等人回答的东西，琥珀只以「注意」这种语气出现（行内通知、状态词），说一件已知的、要留意的事。
- 红只用在失败的事实与不可撤销的最后一步上。一轮失败是已知的失败，用失败的语气，不用「注意」。可以撤销的确认用默认的墨色。

结果未知用中性色，不借注意色或失败色。来源：super-assistant `83c1616f` 的 `desktop/DESIGN.md`「Secondary」一节。

## 8. 页面家族：学会一次，到处能用

人只要学会几种页面，就能用好整个应用。新页面必须属于其中一种：

- **单列页**：一个最宽 1200px 的居中列，第一个标题落在同一条竖线上。页头只有标题、可选的一行说明和右侧的主动作，下面的细线由页头自己画。
- **列表加阅读**：左边一个固定的目录栏，右边一个有自己阅读宽度的阅读面。选中一条记录不是换页：列表、它的滚动位置、搜索词和筛选都不动，只有阅读面到达一次。
- **栏加窗格**：左边一条栏，右边一个窗格；窄了栏变成横条。
- **对话**：气泡、输入框、停靠的侧边内容、决策卡片。切换会话是换页，整个对话页到达一次。
- **浮层**：菜单、弹出框、抽屉、确认。从锚点或边缘进出，按 Escape 关闭，焦点回到触发它的控件。
- **形展开的东西**：墨框。只有形展开的东西才是墨框。

哪种都不合适时，这是一个设计决定：先写进本技能，再写代码。

**主要动作规则**：每个界面先说清它的主要场景，只把一两个最常用的动作做成看得见的控件，最常用的那个最显眼。其余的，包括很少用的编辑，都放进一个 `⋯`。很少用的动作永远不做成实心的主按钮。在别处已经有自然路径的事，不再加看得见的控件。界面上最需要的事实摆在明处，标识和修订收进详情。四个或更多动作平铺成一排是缺陷。

## 9. 确认与反馈：后果多大，容器多大

有后果的动作只在两种容器里确认：

- 局部、轻量、能撤销的后果，用**原地确认**：控件在原地变成待确认的样子，失去焦点或按 Escape 就恢复，没有计时器。
- 会影响到别的会话、别的人或外部结果的动作，用**影响面板**：列出谁受影响、什么保留在哪里、什么没做完。

浏览器的 `window.confirm`、底部抽屉和侧边抽屉都不是确认容器。

动作的结果按「屏上能不能看到」来给反馈：

- 开关、单选、分段控件和下拉本身就显示了新状态，所以它们就是自己的回执。它们立即生效，等待只显示在这一个控件上，不禁用整个区域。失败时恢复原状，在这一行下面给一条提示。
- 保存、提交、移除这些动作的结果在别处看不出来，所以要有回执，或者在原地落定一次。
- 错误放在它描述的那一行上，原始报错收进「详情」。每个失败状态都给一个恢复动作（重试、再确认一次），不能只给一个破坏性的动作。

## 10. 用词

- **名词**：用统一语言的词。界面称行动者为「agent」；它自己说的话里才用第一人称。
- **版本**：日常界面只说「版本」。「修订」只出现在详情里。
- **状态词**：只从状态词表取，一到两个词，细节放进详情。
- **空状态**：一句话说明这里会出现什么；人能创建时，再给一个创建它的动作。不单独写「这里还什么都没有」。样子要留白：这件东西的图标直接立在纸上，用 `ink-muted`，不套方框；那句话用正文墨色、常规字重（小号楷体加粗会发闷）；靠左放，不居中。
- **产品名**：窗口里不写产品名。侧栏左上角只有家与折叠钮；产品名是家的可访问名称与提示。
