# 检出、投影与宿主的坑

什么时候读：检查或准入报了看不懂的环境错；新建了工作树或换了机器；合并了目标分支之后要跑准入；要停后台的长命令；在 Windows 宿主或 WSL 上干活。

每条写的是实测到的现象与修法。

## 检出与依赖

- 新工作树没有 agent 投影时，`pnpm run check` 报缺少生成目录。先 `git submodule update --init`，再生成投影。
- umask 让投影文件带组写权限时，`check:agents` 报权限不符。对报错的文件 `chmod g-w`。
- 合并目标分支或换到新树之后，锁文件可能带来新依赖。不重装就跑准入，构建报模块无法解析。合并之后、准入之前，在这棵树运行 `pnpm install --offline --frozen-lockfile`，再 `git update-index --refresh`，然后确认 `git status --short` 为空。先装依赖再合并时，合并之后还要再装一次。
- 合并基线之后先跑 `pnpm run preflight`：它一次列出轻步骤的全部失败与修法。
- git 版本太旧时（实测 2.25），turbo 的 `ls --affected` 报 `Unable to query SCM`。把新版 git 放到 PATH 前面。

## 构建产物

- 有成员的验收夹具从 `dist` 导入时，准入的依赖检查报模块无法解析。准入前先构建这个成员及其依赖。
- 手动构建之后又改了源码，成员下的旧 `dist` 会被 `check:declarations` 读到，结果反映的是旧产物。准入前删掉手动构建残留的 `dist`，需要时重新构建。
- 用例经 `dist` 导入被测成员时，改了源码要先重新构建这个成员再跑用例，否则测的是旧产物。
- 借用别的工作树里的工具运行时，那棵树若正被写者改动，工具读到的是半改的状态。借用前确认那棵树没有写者在改。

## 宿主

- Claude Code 会话的钩子命令来自会话启动时所在检出的生成物，并在会话期间缓存。主检出落后时，所有工作树的钩子都可能报错。修法：快进主检出，重装依赖，重新生成投影，再重启会话。
- 上下文压缩之后只剩摘要，技能正文会淡出。宿主重新注入的是第一次加载时的技能文本，它可能来自已删除的工作树，也可能是旧版本。执行技能里的命令之前、报技能缺陷之前，核对加载的副本所在目录是当前检出的投影；压缩之后，或轨道上的技能源变了之后，在当前检出重新加载这次要用的技能。报技能缺陷之前，先在轨道上运行 `git log -1 -- <技能的 canonical 路径>`，核对缺陷是不是已经修过。
- Claude Code 会话会把 shell 的工作目录重置回会话的主工作目录。在某棵工作树里启动的会话，`cd` 到别的工作树不会保持。要在几棵树之间切换，从主检出根启动会话，或者每条命令都写绝对路径或 `git -C <树>`。
- Bash 工具的命令行里含有搜索模式，所以 `pgrep -f` 会把调用它的 shell 报成存活进程，`pkill -f` 杀过调用它的 shell（退出码 144）。列进程用 `ps -eo pid,etime,pcpu,args | grep '[p]attern'`：方括号让模式不匹配 grep 与调用它的 shell 自己的命令行。停宿主跟踪的后台任务用宿主的停止工具。

## gate

- gate 确认说明的上限按 UTF-8 编码算是 1024 字节，不是 1024 个字符。两次实测：750 个字符、1220 字节的中文说明被拒，604 字节的被接受。超限之后同一次运行仍在等待确认，缩短说明后可以对同一次运行再确认。

## Windows 与 WSL

- Windows 上已跟踪文件的工作副本可能是 CRLF，而索引是 LF，`format:check` 因此失败。用 `git ls-files --eol | grep 'i/lf.*w/crlf'` 找出这些文件。只是工作副本的换行不同时，删掉工作副本再 `git checkout -- <文件>`。改动本身带 CRLF 时，改成 LF 再提交。
- 对经运行名额的后台长链（`bash → node → turbo → pnpm.cmd`）或它的兄弟任务用宿主的停止工具，会关掉这一批进程共用的控制台。之后同一棵进程树里新起的 `cmd.exe`、`pnpm.cmd` 立即以 `-1073741502`（`0xC0000142`）失败，看起来像全部成员 0 秒失败。这时不改 turbo 或测试。要停这类长链，用 `taskkill //PID <pid> //T //F` 结束整棵进程树，再读名额目录，确认被结束的进程已经不占名额。
- Git Bash 的 `/tmp` 与 Windows 版 Python、Node 看到的不是同一个目录。给这些程序传临时文件路径时先用 `cygpath -w` 转换，否则报找不到文件。
- WSL 的 `/tmp` 在 WSL 重启之后清空。要留作证据的复现材料放在主检出的 `tmp/` 下。
