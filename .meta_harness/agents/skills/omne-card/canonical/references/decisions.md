# 提交成果与决定记录

什么时候读：要把成果交给接受者；负责人说「接受」「取消」「重开」；要代笔一条决定评论；要关卡或重开卡。

## 提交成果供接受

- 判据要求的证据贴在卡评论里，和交付声明一起交给接受者：命令输出尾部、测量摘要、验收结论、准入日志摘要。任务 tmp 只在本工作树可读，换会话、换机器或回收工作树之后接受者读不到它；只放在任务 tmp 的证据，接受者不据它判断。原件太大时贴摘要与关键行，写明原件位置与哈希。
- 说明实际输入、结果、限制和没覆盖到的。需要人决定时给足对象、范围与缺口，不把全部原始日志交给人逐条看。
- 同一段对话里有几个对象时，说清这次等的是哪一个：方案采用、某个子任务、整张卡，还是合并。
- agent 可以代笔人的明确决定，但要能核对授权人、身份、对象、修订和范围。不因为自己的测试结论给自己授接受。人已经明确决定而且有权限时，直接去记录，不再反复请示。
- 语境分不清「接受方案」还是「接受成果」时，不关卡。

方案、产品正文、架构与规格的采用不写成卡的决定，也不关闭关联的卡。卡与子任务的结果才进下面的决定记录。合并与发布各有自己的授权与入口。

## 决定评论的字段

记录种类、卡的交付修订、范围、决定者与权限依据、日期、所核的长期源、实际成果与证据、不含的与剩余责任。字段在、评论写成功，都不授予决定权。

```text
- 操作标识：{{本次决定唯一标识，超时用于读回对账，不声称平台exactly-once}}
- 决定：{{accept／cancel／revoke；部分认可用partial，不能让卡进入Accepted}}
- 对象与交付修订：{{IssueURL及revision}}
- 决定者、身份及权限依据：{{该交付结果的有权接受者；涉及产品／架构／契约变义列相应已有决定；代笔附有权者明确输入}}
- 日期：{{实际日期}}
- 范围：{{精确接受、取消或撤销结果；完整接受不能遗漏本次承诺}}
- 所核依据：{{适用产品场景、技术／工程规范、问题或调查授权及其修订、Git输入}}
- 成果与证据：{{实际远端提交／PR、方法、条件及结果范围；未执行不冒通过}}
- 不含与剩余责任：{{具名缺口及下一责任}}
- 前项关系：{{此前决定URL、取代／撤销精确范围，或无}}
```

交付决定以外的评论（范围裁定、接管说明）不写「决定」这个字段，免得读的人把它当成交付决定。要用字段时换一个名字，例如 `- 裁定：`。

## 谁能接受

- 决定来自有权者，或来自带着可核对授权输入的代笔。机器人留言、任意评论、有写权限、测试全绿，都不授予接受。
- 产品结果由产品负责人接受。技术结果由有权的技术或工程接受者判断，任务标签不赋予权限。
- 跨产品与技术时，各受影响语义的拥有者先接受自己的变化；主接受者不替别的拥有者批准变义。
- 接受的内容有歧义，或归属核对不了：保持 unknown，不关卡。

## 先记录、读回，再关卡

1. 写决定评论。
2. 读回，确认它在、内容对。
3. 再关卡。

这两步没有跨对象的事务。关卡失败不撤销已有的接受，也不补造第二次决定：读回之后修复。没有取得有效决定却已经关了卡：重新打开，留下误操作的说明。

平台写不进去时，分清「负责人已经在对话里作了决定」与「远端还没有记录」。停下依赖这条记录的状态切换，不说 Issue 已接受。恢复之后取回有权者可核对的输入，不凭模糊的回忆补造决定。

## 部分认可、取消、撤销与重开

- 部分认可只记认可的范围。卡不进入 Accepted，不作为完成关闭；剩下的结果继续活动，或由拥有者明确拆卡、缩小范围并接受新的交付修订。不用「记成 accepted 但少几项」的办法关卡。
- 只接受子任务或部分结果时，父卡继续活动。
- 取消由有权的卡负责人明确作出，记下对后继的影响。取消不满足别的卡的结果条件。
- 接受之后不改写旧决定。发现原范围其实没兑现，或接受的依据被撤销：由有权者记下精确的撤销范围与新的交付修订，再重开同一张 Issue。新需求或回归通常另开 Issue，引用原结果。
- 只有有权者的新记录能撤销原接受。普通的重开只触发冲突复核，不自动改变全部历史。
- 新决定指明此前决定的链接与取代或撤销的范围。当前有效的事实从相关决定与撤销链读出，链不完整就是 unknown。
- 交付修订在语义变了时由卡的拥有者递增；样式与无关的评论不升。

卡的历史只说明过去的交付与决定。当前的产品规则、规格与持续验收仍然直接读它们自己；过去的卡不能替代当前的能力证据。GitHub 评论可以编辑，这套记录防不了管理员篡改，不声称是不可篡改的审计。

## 对人的回执

每做完一件有意义的操作，简短说明：真实的卡号，做了什么，哪些事实已经记录、哪些还缺，下一步。受阻时指明条件、责任与需要人给的具体决定。

分清这几种说法，不只答「已完成」：草稿已写、卡已创建、已开工、候选已验证、决定已记录、卡已关闭。

工具超时或部分失败时，照实说成功了哪一部分和读回的结果。不向人重复字段清单、技能正文和全部检查过程。
