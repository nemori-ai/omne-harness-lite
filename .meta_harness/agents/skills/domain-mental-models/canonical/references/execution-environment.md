# 执行环境：动作在哪里跑

## 它是什么

执行环境回答四个问题：一个动作实际落在哪里，那里能用什么，留下的东西能活多久，它现在还在不在。动作总要落在某处，不存在「没有执行环境」这个状态。

把它想成一个出租柜台。集成方带着在别处求好的允许清单来，柜台按清单找第一个合格的提供者，这是落点；再凭获取键租一次，这是获取；交出一份只开放所需设施的租约。每次用设施都要过柜台的门。

- **环境要求只有三样。** 有序的允许绑定层清单、设施键集合、隔离断言集合。策略词不进本域。
- **落点是选中的那一个绑定层与提供者。** 按清单顺序取第一个合格的层。落点不授设施，也不授资源。解析落点与获取不是一个原子动作，获取时重新核对，核对失败即拒绝，不换落点。
- **设施是一个执行环境提供的做事手段。** 设施是按名登记的开放协议：`files`、`command`、`terminal`、`screen`、`program`。声明只提供词汇，不安装设施，也不授权。
- **提供者给出实际环境。** 提供者的身份是名、代与版本。它声明自己提供哪一层、哪些设施、能确认哪些隔离断言。提供者不能自签采用记录：执行环境核验回执之后才签发采用记录并交付租约。
- **Tool 向它要落点、获取、采用记录、租约与释放结果。** 适配在工具宿主一侧：先保存原获取描述，再按同一获取键获取与认回。工具执行者只拿设施，不拿租约。
- **每次设施操作都经同一道门。** 门核对请求形状、租约、账本、声明、租户、原调用与绑定层，须授权的操作再问设施守卫。结果只有四态：完成、未解析、拒绝、未知。
- **隔离靠隔离断言，确认不了就拒绝。** 环境要求点名要确认哪些断言；提供者确认不了的，这次获取拒绝，不写成已隔离。所需隔离不存在、建立失败或无法确认时，不静默退回宿主机或更宽松环境。
- **受限执行域是主进程里承载不可信代码的运行边界。** 代码只能读取显式提供的输入和获准接口返回的数据；宿主能力由受控接口显式授予；消耗有界，终止不依赖代码自愿配合。普通模块、Cordis 作用域或 `node:vm` 都不算受限执行域。
- **登记表不存别处没有的事实。** 耐久事实在集成方的账本里，原获取记录在提供者的配额域里。登记表丢了，从账本、提供者的原记录与恢复枚举接着来。

## 它不是什么

- 它不判许不许。一个动作允不允许做归授权；柜台只核对身份、作用域、账本与守卫给出的答复。环境可用不代表动作获准。
- 它不认识工具的含义。工具做了什么归工具；执行适配把合法原调用交设施，不重定义工具业务。
- 它不选层。该落哪一层是策略，归集成方；它只接收清单并在清单内匹配。
- 它不知道作用域什么时候结束。那归作用域持有者；它不从任何上层逻辑状态推断。
- 它不是工作区。工作区目录是地址，不是许可。
- 宿主机不是隔离。宿主提供者不确认任何隔离断言，工作目录只确定文件操作的起点。

## 拿它量一个设计

- 执行环境里出现了策略词、会话类型或授权判断：错了。它只认通用角色。
- 所需的隔离断言确认不了，就改落到宿主机上执行：错了。拒绝这次获取。
- 取消、释放或作用域结束之后，断言进程已经停了：错了。逻辑收口不是物理停止，只认域外监督者的读数。
- 拿空的资源列表证明没有未了的责任：错了。读不全的列表也不是空列表。
- 获取答复丢了，换一个获取键重发：错了。用原获取描述查询。
- 只在登记表内存里的一个标记决定了某个结局：错了。它重启之后就没了。
- 把一个提供者做不到的设施或隔离用统一形状声明出来：错了。证明不了就不声明。
- 为某个提供者或某种上层工作流在本域加特例：错了。新设施只改设施拥有者的包，新沙箱是新的提供者成员。

## 现状

包组里有两个提供者。宿主提供者只提供 `host_machine` 一层，提供 `files`、`command`、`terminal` 与 `screen`，不确认任何隔离断言，不承诺同一用户的恶意程序之间的隔离。受限执行域提供者只提供 `stateless_sandbox` 一层，确认 `restricted-js` 与 `network-none`，只提供 `program`。执行隔离正文不声明 Windows、macOS 或任意容器环境已经支持。做到哪一步，以源码为准。
