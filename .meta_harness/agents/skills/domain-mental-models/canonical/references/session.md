# Session 与会话日志

## 会话日志

**它是什么。** 一个会话的唯一事实源。它只增不改。这个会话里发生过什么，以它为准。

- 别的东西都是它的投影或缓存：列表里的标题、当前这一轮、界面上的对话。投影丢了，能从日志重算。
- Agent 的执行记录也在这同一份日志里，不是另一份。Agent 定义自己需要一份什么样的执行记录，Session 来提供。
- 所以任何一个运行着的对象没了都不要紧：Session 的实例、Agent 的实例、一次观察。重新起一个，从日志接着来。

**它不是什么。** 不是消息列表，也不是调试日志。它记的是事实：受理了什么输入，开了哪一轮，登记了哪次调用，哪次调用给了什么结果，这一轮怎样结束。

## Session

**它是什么。** 管一个会话的业务流程的领域。它回答的是「这份工作现在该怎样」：

- 这条输入收不收，排在哪。
- 开不开一轮，这一轮的推进资格交给谁。
- 取消、冻结、归档，会话处在生命周期的哪一段。
- 这一轮算不算结束了，结局是完成、失败还是被取消。

它拥有会话日志，是每一条业务事实的提交者。

**它不是什么。**

- 不是干活的。它不执行循环，不发模型请求，不运行工具。它不是第四个 runtime。
- 不直接控制 Model 或 Tool 的调用。会话路径上，调用、重试、中断由 Agent 发起；Session 的控制经 Agent 的控制入口送达原执行。
- 不是物理收场的判断者。取消、归档、换代只改变资格与责任。模型发没发出、工具停没停、环境关没关，由各自的拥有者报告，Session 只对账。

**它和邻域怎样认识。** Session 是最外层。它认识全部邻域：Agent、Model、Tool、Runtime Context、Request Context、执行环境。邻域都不认识它。

- 邻域的契约只用通用角色：消费者、持有者、协调者。Session 是这些角色在会话路径上的具名实现者。
- 认识只发生在 Session 的适配成员里。名称与形状的翻译都在那里。Session 的契约成员不导入 Model、Tool 的契约。
- 适配成员读邻域的公开事实，用来对账和承接结果。Model 和 Tool 的结果与账目，Session 从同一份会话日志里读。

## 拿它量一个设计

- 要给会话加一个新的事实：它先是日志里的一种条目，然后才是别的。没进日志的，不算发生过。
- 要加一个「当前怎样」的字段：它是日志的投影。写清它从哪些条目算出来，丢了怎样重算。
- 一个运行对象里存了日志里没有的事实：错了，它丢了就算不回来。
- Session 的代码要知道模型回了什么、工具做了什么：从日志读。
- Session 的契约成员里出现了 Model 或 Tool 的类型：错了，那属于适配成员。
- 邻域的契约里点名了 Session：错了，它应当写通用角色。
- Session 发出取消之后等着模型或工具真的停下才算取消：错了。取消生效就记终态，实际停没停由对方报告，Session 对账。
- 一轮当中的事要 Session 逐步决定：越界了，Run 之内归 Agent。见 [cross-domain.md](cross-domain.md)「Run 是边界」。
- 提交之后的通知只是叫醒。丢了、重复了、合并了都不改变事实；要靠它保证正确的设计是错的。
