# Request Context：一次请求的输入怎样算出来

## 它是什么

Request Context 回答一个问题：一次模型请求的输入怎样从别人拥有的事实算出来，能不能装进窗口。它是一个纯算的工位，加一份可以重建的账本。

- **它每次从别人那里稳定地读出六组材料。** 组一是调用身份与用途，由调用方给出。其余五组是历史与新输入、系统提示词、模型侧、工具侧、当前条件与本次经过，各有一个组读口。前后计数不等就整组重读，第二次仍变答不可用，不交半组。
- **每一块输入都有外面的拥有者。** 历史归历史持有者，会话路径上是 Session。定义的指令段经定义读口读出。档案、限制与计量资源来自 Model。工具定义与可用性经 `ToolLookup` 来自 Tool。Request Context 自己拥有的只是派生规则、装入裁定、三层布局与固定请求记录的格式。
- **它算出一份请求候选和一个结论。** 结局封闭：可扩展的请求候选、可固定的请求候选、需要压缩、装不下。装不下是结局，不是失败；限额未知不是失败，候选照常成立并在覆盖证据里标明。
- **请求自上而下分三层。** 系统提示词、工具声明、历史。历史里的每条消息都来自会话日志，请求时不放入日志之外的消息。日志只追加，所以对同一个接收方，下一次请求以上一次请求为开头。
- **采用点上定下的，请求组装只读记录。** 常驻的能力是采用点上定下的记录，随 Session 的采用材料保存：常驻 Skill 的简介是系统提示词里持有者记下的一段，常驻工具按会话常驻工具的完整合法集合投影成工具声明。请求组装不再问能力的拥有者。
- **每次请求现算的是派生与计量。** 系统提示词每次求值、单独计量。计量结论不缓存也不复用。同样的材料得到同样的内容，但结论以本次为准。
- **它和 Runtime Context 是两件事。** Runtime Context 供给运行数据；Request Context 算一次请求的输入。运行时上下文只经会话日志里的提醒到达模型，提醒由作用域持有者写；请求组装不读 Runtime Context。
- **它给出要压缩的裁定，压缩的执行不归它。** 它交出需要压缩的裁定与完整预算依据。压缩消费协议、一次准备的任务额度与结果交接归 Agent；保留算法、修剪和内部摘要次数由默认提供者定义；原子采用归 Session；压缩记录的形状归 `packages/common`。
- **`agent-context` 只做翻译。** 它把 Agent 声明的请求准备端口译成对 Request Context 的调用。

## 它不是什么

- 它不发请求，不固定采用。固定采用写在协调者的调用记录上；本组不保存它，只经「已采用」读回。
- 它不提交历史与压缩记录。压缩只追加一条压缩记录，原历史一字不改。
- 它不拥有计量。计量能力归 Model，经准备租约借来；输入大不大、要不要压缩由 Request Context 判断。
- 它不拥有媒体的保管、表示与转换件。带内容引用的块，它只读消息上的表示快照，不读字节。
- 它不选模型。协调者选模型并登记准备资源。
- 本组成功只表示计算完成，不表示请求已发出、结果已承接或动作已获准。

## 拿它量一个设计

- 请求里出现了会话日志之外的一条消息：错了。要让模型知道的运行事实，经提醒追加进历史。
- 日期、当前目录这类会变的值做成提示词变量：错了。它们只走 Runtime Context 块。
- 为保住缓存的开头，推迟系统提示词或工具集合的变化：错了。立即变化，覆盖证据记前缀变化原因。
- 按步裁剪工具声明，或给工具声明附上别的工具的函数签名：错了。
- 装不下时截短请求交出去：错了。装不下是一个如实交回的结局。
- 读不到历史就当成空历史继续组装：错了。缺项、未知、拒绝分别如实交出。
- 拿单条计量相加代替整请求计量：错了。
- 压缩之后改写早先的消息：错了。
- 请求到来时才算本可以在输入变化时算好的派生物：错了。请求到来时只做比对与拼装。
