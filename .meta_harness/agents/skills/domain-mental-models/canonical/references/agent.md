# Agent

## 它是什么

管一轮 Run 实际怎样往前推的领域。它回答的是「下一步做什么」：

- 准备一次模型请求，发出去。
- 读模型的回复，决定是结束，还是发起工具调用。
- 发起工具调用，接结果，再决定下一步。
- 在循环的每个拓展点上，让挂在那里的扩展运行。

它是 Model 和 Tool 的调用方，是它们的结果的接收方。对它来说，Model 和 Tool 是被远程调用的服务，见 [cross-domain.md](cross-domain.md)「调用是远程调用」。

## 它不是什么

- 不是会话的主人。它不决定收不收输入，不决定会话的生命周期，不拥有会话的业务状态。它对会话的了解，只有交到它手里的工作和推进资格。
- 不是事实的存放处。它的执行记录写进会话日志。Agent 的实例没了，换一个从日志接着推。
- 不认识 Context 的内部。它声明自己需要什么（准备一次模型请求、读模型可读的运行数据、把账目交出去），由适配成员翻译成对 Context 的调用。

## 扩展的装配归谁

| 事 | 归谁 |
| --- | --- |
| 循环上有哪些拓展点，扩展在拓展点上怎样被调用 | Agent |
| 这一轮用哪一份组合：哪些工具、哪些扩展、哪个模型 | 装配与采用。在采用点上求值，结果是一份采用依据 |
| 采用点在哪 | 只有两个：新的一轮开始时；一轮当中租户明确要求重新加载时 |

拓展点是 Agent 的。往拓展点上挂什么，是装配在采用点上定的。Agent 在一轮里用的是那一刻定下来的组合，中途不暗换。

## 拿它量一个设计

- Agent 发起一次调用之后等着对方的对象活着：不对。它保存调用的引用，结果交到登记的消费者引用上。
- Agent 的实例换了，就重新发一次调用：不对。先凭引用认回原来那次。
- Agent 在一轮当中发现有新的工具或扩展，就立刻用上：不对。等到采用点。
- Agent 需要知道一个治理领域的事实，于是导入那个领域的类型：不对。那是 Runtime Context 的一块，经适配读。
- 一条规则只在某个扩展装着的时候才成立：把它写成那个扩展的规则，不写成循环的规则。
