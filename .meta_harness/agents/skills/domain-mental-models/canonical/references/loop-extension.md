# 拓展件

## 它是什么

拓展件这一类资产的专有知识。它回答三个问题：

- **一件拓展件是什么。** 一个目录，里面是一份声明，加上实现要用的文件。声明写明挂在哪个位置、多大的干预力、实现是哪一种。
- **这个租户此刻启用了哪些。** 一份按当下事实现算的视图。一件拓展件进视图，要它被持有且没被禁用、求值胜出、它的「运行」设置是开。
- **这一件的实现怎样取得、运行、收场。** 内建的是随发行登记的函数。命令型的是包里的脚本，由子进程运行。

它和 Skill、MCP 是同一种东西：一个专有类别，向资产登记自己，资产不为它改规则。

## 它不是什么

- 不是拓展点的主人。位置、每处允许什么输出、几件之间怎样排、怎样归约，都归 Agent。它依赖 Agent 的契约，Agent 不认识它。
- 不是事实的存放处。视图丢了可以重算；内建实现的登记丢了可以重新登记。事实在资产里，一次经过的记录在会话日志里。
- 不决定输出算不算数。它把一次调用做完，如实交回输出、报错、不可用、未知之一。裁定归 Agent。
- 不自己起子进程。命令型的进程经执行环境启动。
- 不给 agent 用。agent 不知道拓展件存在，它不进提示词，不进工具声明。

## 热装卸是怎样做到的

三件事合起来：

| 事 | 谁给 |
| --- | --- |
| 发布和感知解耦：拓展件领域只管算出视图并发布，Agent 只管读，两头互不认识 | Runtime Context |
| Agent 不存这份值：每次走到拓展点现读，读到的只用于这一次经过 | Agent |
| 调用按身份现取：Agent 手里只有名字和精确版本，每次调用现取实现 | Agent 声明的端口，拓展件领域实现 |

前提是拓展件不进模型的上下文，所以它的增减不是重装配。

## 拿它量一个设计

- 资产的成员里出现了「如果是拓展件就……」：错了。差别由类别契约表达。
- 视图读不到某一层，就交出剩下的部分：错了。整份答读不到。
- 取实现时按「现在胜出的版本」：错了。按这一次经过记下的版本。
- 命令型的进程没起来和起来之后失联，都答不可用：错了。失联是未知。
- 为了让新装的拓展件生效去重建 Agent 或重开会话：错了。下一次走到拓展点就读得到。
- 拓展件的包里声明要调一个工具：错了。它不组合任何资产，要一个动作发生只能靠提醒或改写，仍然过官方准入。
- 筛选与排序的规则写在适配成员或提供者里：错了。它们只有一处，在领域实现的纯函数里。
