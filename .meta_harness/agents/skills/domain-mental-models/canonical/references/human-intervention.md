# 人工介入

## 它是什么

人工介入把「要人决定」的那一件事交给人，再把人的答复交回去。

- **卡片有三种：问询、系统放行卡、拓展件的卡。** 问询由 agent 经 `Ask` 发起，问的是信息或选择；放行卡由 Agent 的准入在放行判断答「问人」时发起，问的是许不许；拓展件的卡由出卡的拓展件写选项。
- **卡上的字各有作者。** 放行卡的壳由系统固定；「这一次会做什么」由工具作者的描述函数从这次调用的参数算出，界面按种类画，画不了就画条目。
- **答复交回原来等着的地方。** 问询的答复交回原工具调用，agent 接着想；放行卡的答复交回 Agent 的准入，由准入与授权的拥有者解释；拓展件的卡的原话交回原拓展件，它只能收紧。本组只保存原话与选择，不解释准驳。
- **一张卡片只产生一次有效决定。** 答复者要有当前资格。普通消息不自动回答卡片。
- **等待是耐久事实，不是挂着的 Promise。** 进程退出、界面关闭、没人看都不改变它。等人时不占执行名额、写事务或跨调用的锁，别的调用与别的会话照常前进。
- **没有人回答就没有答案。** 时间、通知、界面、脚本与拓展件都不能替人作答；超时不默认批准。

## 它不是什么

- 它不判许不许，那是放行判断。
- 它不保存授权。授权表达在会话日志里，持续的授权在租户设置里。提交答复本身不批准动作，也不写持久授权。
- 它不是工具自己出确认卡的地方。工具不出确认卡；要人确认内容，就是对带着完整内容的动作的放行。
- `Ask` 不是要授权的口。agent 不拿问询向人要许可，人在问询里答的话不产生许可。
- 它不送提示。提示的送达交给通知，与答复无关。

## 拿它量一个设计

- 一个工具或一个领域自己出确认卡、自己问人：错了。走放行卡，由准入发起。
- 把问询的答复当成许可：错了。
- 人工介入替原工作解释答复、写授权表达或设置：错了。它只把决定交回原等待，由原拥有者按当前事实重新判断。
- 同一张卡产生两次有效决定，或答复者没有当前资格也算数：错了。
- 卡上「会做什么」由准入或界面自己拼：错了。它由工具作者给，系统只画壳。
- 把「答复存下了」当成「原等待接手了」「动作执行了」或「授权生效了」：错了。这几件分别确认。
- 原工作终局之后，未答的卡还能答出有效决定：错了。卡失效；已成立的决定保留，不复活工作。
- 出卡方替这个租户的人答自己的卡：错了。出卡方能读不能代答。
