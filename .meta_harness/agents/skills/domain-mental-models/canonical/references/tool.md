# Tool：被调用的执行

## 它是什么

对 Agent 与程序，Tool 是被远程调用的执行服务。

- **受理一次调用。** 核请求的形状与参数、目标此刻可用、调用方主体的资格与推进资格、执行环境能否满足，写下受理记录，排进发起。这一步叫调用受理。
- **执行、保管、报告。** 按定义发起真实执行，保管结果与账目，报告结局；结果不知道就是不知道。
- **控制送到它。** 取消、转后台、读输出，按调用引用送到 Tool。
- **工具的本体是函数。** 模型消息里的调用与结果是它的投影；模型调用与程序调用走同一个函数。
- **定义由作者声明。** 命令、参数、后台许可、可编程调用许可、每个命令归哪道关口、算放行详情的只读函数，都是作者对外的声明。关口的声明给治理读，Tool 自己不拿它判任何事。

## 它不是什么

- 它不判许不许。调用到了就是已经放行；许不许在调用方交出之前由放行判断判过。
- 它不存放行、不读授权引用，也不为别的领域保存授权或同意。
- 它不认识调用它的是谁。它只认请求里的主体、租户与消费位置，不知道那是一个会话、一轮 Run 还是一段程序。
- 它不等调用方收场，也不替调用方取消；调用方换代不丢它的工作。

## 拿它量一个设计

- Tool 的契约、实现或存储里出现放行判断、权限求值、会话授权断言、授权引用：错了。
- 撤权之后想停住 Tool 已收下的调用，在 Tool 里再判一次授权：错了。用取消。
- 一次调用把共用的定义按值带着、每次调用存一份：错了。定义按采用引用存一份。
- 官方工具的定义换代之后，旧定义在治理里的租约留着不撤：错了。贡献的寿命跟着发行。
- Tool 为某个调用方类型写特例：错了。按请求里的事实办。
