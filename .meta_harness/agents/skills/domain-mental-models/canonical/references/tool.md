# Tool：被调用的执行

## 它是什么

对 Agent 与程序，Tool 是被远程调用的执行服务。

- **受理一次调用。** 核请求的形状与参数、目标此刻可用、调用方主体的资格与推进资格、执行环境能否满足，写下受理记录，排进发起。这一步叫调用受理。
- **执行、保管、报告。** 按定义发起真实执行，保管结果与账目，报告结局；结果不知道就是不知道。
- **控制送到它。** 取消、转后台、读输出，按调用引用送到 Tool。
- **工具的本体是函数。** 模型消息里的调用与结果是它的投影；模型调用与程序调用走同一个函数。
- **定义在装载时派生。** 形状、说明、返回声明与后台许可来自实现；名字、必需能力与可编程调用许可来自资产的治理声明。每个命令归哪道关口、调用条件、算放行详情的只读函数，也是作者对外的声明。关口的声明给治理读，Tool 自己不拿它判任何事。
- **多命令工具对模型是一个工具，只占一个声明。** 调用在参数里点名命令；声明里的命令清单与 guide 由定义机械派生，作者不拼出错文本。
- **工具目录的视图有两种来源。** 一种是绑定登记表里已装载实现的贡献，登记键是（来源层、能力身份、资产版本）；另一种是别的领域登记的工具条目来源，例如 MCP 的接入点。来源独占一个名字前缀，工具入口不认识具体的领域。来源的一次调用就是一次工具调用：受理、保管、取消归 Tool，执行体取自来源。 来源的一次调用也可以暂停等待：它交检查点的声明与接续，走检查点作者的同一条路径，没有为来源另开的分支。
- **程序调用走同一个函数。** 程序执行方（发行里是 `Code`）在自己那次调用之下按位置发起子调用，同一位置认回原调用，不产生第二次执行。目标要许可程序调用；许不许经嵌套动作准入的端口问，Tool 不判。父调用只在每个位置都收场之后才完成。
- **常驻工具的名字与参数形状在会话内不变。** 采用点是会话初始化、新 Run 开始和显式 reload，由纯函数判前进、保持、同形替换件或冻结。冻结的原因只有 `tool-shape-lost`；暂时缺席、未知与撤权一律给同形替换件。常驻的来源条目带着采用时的整条定义，没有登记键，不冻结。

## 它不是什么

- 它不判许不许。调用到了就是已经放行；许不许在调用方交出之前由放行判断判过。
- 它不存放行、不读授权引用，也不为别的领域保存授权或同意。
- 它不认识调用它的是谁。它只认请求里的主体、租户与消费位置，不知道那是一个会话、一轮 Run 还是一段程序。
- 它不等调用方收场，也不替调用方取消；调用方换代不丢它的工作。
- 它不给调用方排先后。名额与范围预算只管容量：同时有多少执行在跑。同一批动作谁先谁后，调用方在交出之前自己排好。命令的 `readOnly` 声明只随描述交给调用方，Tool 不凭它放行、排队或限流。

## 拿它量一个设计

- Tool 的契约、实现或存储里出现放行判断、权限求值、会话授权断言、授权引用：错了。
- 撤权之后想停住 Tool 已收下的调用，在 Tool 里再判一次授权：错了。用取消。
- 一次调用把共用的定义按值带着、每次调用存一份：错了。定义按采用引用存一份。
- Tool 为某个调用方类型写特例：错了。按请求里的事实办。
- 指望把并发预算设成 1 来保证两个动作的先后：错了。先后归调用方；预算是容量。
- 一条规则只在模型调用路径上生效，程序调用绕得过去：错了。规则落在函数这一面。
- 工具入口为 MCP 这类具体的领域开专门的分支，或装配与准入按工具名判一个命令此刻能不能用：错了。前者靠条目来源，后者靠命令声明的调用条件。
- 常驻工具暂时缺席或被撤权，就判会话冻结：错了。给同形替换件。
- 原地替换一个已登记的实现，或突然失依赖时换最新实现接着跑原调用：错了。替换就是装新版本，旧版本在引用归零后收走；在途调用保持未知。
- `Tools` 的搜索结果按采用点记下的集合或按 Agent 定义收窄：错了。要限制一个 agent 用什么，靠授权规则。
