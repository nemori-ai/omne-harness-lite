# 身份与授权：动作许不许

## 它是什么

这个领域回答两个问题：这个主体此刻能不能替这个租户做事（资格）；一个动作许不许做（放行判断）。两个问题分开答。

- **放行判断是一个纯函数。** 输入三样：权限设置（租户层与会话层合成的结果）、会话授权上下文、会话运行模式。按四步固定次序给出四种答复之一：放行（带授权引用）、问人、拒绝、依据不可用。
- **权限按动作所属的关口分项，不按工具整个算。** 一个能力可以有几道关口，一个动作恰好归其中一道，或不设关口。一个命令归哪道关口写在工具的定义里，不随这一次的参数变。持续的授权管的是一道关口。不设关口的动作不进放行判断。
- **许不许在动作的发起点判一次。** 模型发起的动作，发起点是 Agent 的官方准入。程序发起的嵌套动作，按目标自己的关口判；放行运行这段程序的那个动作，不放行它的任何嵌套动作。被调用的一方不再判。
- **判的是模型实际要执行的动作。** 经 `Tools` 取用一个工具时，判被取用的工具与它的参数，不判 `Tools` 这次调用。同一个动作不因取用方式不同而多问或少问一次。
- **结论只记一处。** 放行的结论、授权引用、这次用掉的本次放行，在准入的那一次提交里经会话的写入者记进会话日志。崩溃之后从那里认回，不重新问人。
- **授权的数据各有拥有者。** 权限设置归资产与规则；人在会话里表达的授权（给出与撤回）由 Session 保存成只追加的流水，由本领域解释。授权引用只点名其中一份，不复制它。
- **本次放行绑定一个动作。** 绑定的是这个动作、它真正执行的目标与生效参数的摘要，三项都相等才认。同工具、同参数的下一个动作对不上，还要再问。
- **本会话授权只在它给出时的权限依据下有效。** 设置变了，它不再被采用，重新要人决定。
- **撤回只影响之后的放行判断。** 已经放行、交出的调用照常执行；要停它用取消。
- **资格每次调用都核。** 主体能不能替这个租户做事，Agent 准入时核，Tool 受理时也核；这不是许不许，换主体或撤销成员资格立刻生效。

## 它不是什么

- 它不是 Tool 的事。Tool 对 Agent 是一次远程调用，调用到了就是已经放行；Tool 不判、不存、不读授权。
- 它不是人工介入。人工介入出卡、收答复；判许不许在这里。
- 它不是 Ask。人在问询里答的话不产生任何许可。
- 它不是条目的同意。日程、订阅这类由动作创建的条目只记创建者，不记授权引用，也不记放行的种类。
- 它不预先告诉 agent 哪些动作要问。agent 照常调用，系统在准入时判；不放行时，系统写一句结局作为这个动作的结果。
- 工作区不是授权来源。工作区不参与授权与权限设置，不论放宽还是收紧。

## 拿它量一个设计

- 被调用的一方（Tool、日程、通知）里出现放行、权限求值、会话授权或授权引用：错了。
- 同一个动作在两处各判一遍，或在启动时「再核一次授权」：错了。
- 授权引用被复制进另一个领域的记录，或随调用交给 Tool：错了。它只记在那次放行判断的记录里。
- 为了让撤权也能停住排队中的调用，在 Tool 里加授权判断：错了。用取消。
- 放行判断读不到依据时放行，或让动作挂着等：错了。拒绝这个动作，给 agent 一句结局。
- 本次放行没有绑定动作、目标与参数摘要，或被另一个动作用上：错了。
- 为「用掉本次放行」在另一个存储里写一笔并断言它还在：错了。它与放行的结论在同一次提交里记，由同一个写入者写。
- 一个多命令工具只有一项权限，读的命令和写的命令一起问或一起放：要问它的命令各归哪道关口。
- 经 `Tools` 调一个工具时判的是 `Tools` 本身，或放行一段程序就放行了它发起的动作：错了。
