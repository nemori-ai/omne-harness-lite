# MCP

## 它是什么

一个 MCP 接入点是「一个在外面的服务，加上怎样连到它」。服务在这套系统之外，由别人运行。系统只按地址和它通信。

- **MCP 领域拥有三样：** 接入点的定义（名字、地址、怎样认证）；连接（建立、保持、重连、可用性）；对端此刻提供的动作清单，以及向对端发一次动作调用。
- **接入点是资产，动作不是。** 租户登记的是接入点。动作是对端说它有的，随对端变；系统不登记它，只按次读清单。
- **动作经工具入口到 agent 手上。** MCP 向工具入口登记一个条目来源。agent 用 `Tools` 搜到一个动作，看用法，调用它。调一个动作就是一次工具调用：准入、结果保管、取消都归 Tool。MCP 是这次调用背后真正发请求的一方。
- **条目是视图。** 一个动作能不能被搜到、被调用，按这个主体此刻的事实现算：接入点合法可用，连接上有这份清单。清单变了，下一次搜索就不同，不经装配。
- **连接是长寿的，按租户、接入点、凭据账号分开。** 它不属于任何一个会话。
- **认证是接入点上的一件事。** 人在登记或点「连接」的时候完成它。凭据交给秘密保管，只给连接用。
- **对端要补充输入时，问的是人。** 复用工具内「等人决定」的那一个原语，不另做一套。

## 它不是什么

- 它不是工具运行时。它不做准入，不保管结果，不替 Tool 决定一次调用的结局怎样记。
- 它不运行 MCP 服务。本机上长驻的 MCP 服务也是系统之外的服务。系统只看它的地址通不通。
- 它不把动作登记成工具。没有「同步工具表」这一步，所以也没有两边对不上的时候。
- 连接不归会话。会话结束不关连接；连接断了不结束会话。
- 它不认识 agent、会话、Run。它只认主体和登记的消费者。
- 凭据不是设置项。它不进日志，不进模型的上下文，不给 agent 读。
- 「连得上」不是「许用」。可用性对谁都一样；许不许调一个动作，每次调用时由授权回答。

## 拿它量一个设计

- 为了加一个动作要重建 Agent、改系统提示词：错了。动作是数据，入口不变。标了常驻的接入点例外，它的动作在采用点进工具声明。
- 工具入口为 MCP 开了一个专门的分支：错了。工具入口不认识具体的领域，MCP 作为一份贡献登记进来。
- 连接断了，把原来那次调用再发一遍：错了。发出去之后结果不知道就是不知道，按原来的那次调用认回。一次调用至多发出一次。
- 受理之后、发出之前，清单里这个动作的定义变了，照旧发出：错了。复核定义和发出是一步，变了就答「定义已变」，不发。
- 两个租户用同一个接入点，共用了一条连接：错了。
- 对端一直不答，调用一直挂着：错了。每次调用有时限，到了就以「结果未知」收场。
- 发出之后被取消，记成「没有执行」：错了。取消、实际停止、效果撤回是三件事。
- 把对端给的结构化结果压成一段文字再交回：错了。结构化内容是函数的返回值，文字是给模型看的投影，两样都留。
- 系统替用户把一个命令起成 MCP 服务：现在不做。只按地址接入。
