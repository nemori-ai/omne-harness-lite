# MCP

## 它是什么

一个 MCP 接入点是「一个在外面的服务，加上怎样连到它」。服务在这套系统之外，由别人运行。系统只按地址和它通信。

- **MCP 领域拥有的：** 接入点的定义（正文只有名字与怎样认证；地址、凭据与连接超时是它的设置项，不写进正文）；连接（建立、保持、重连、可用性）；对端此刻提供的动作清单，以及向对端发一次动作调用；经 OAuth 取得与续上凭据的流程；对端声明的事件类型与本系统向对端的事件订阅；对端带来的技能的清单。这些里要跨重启留下的，存在它自己的耐久存储里，按租户分开。
- **接入点是资产，动作不是。** 租户登记的是接入点。动作是对端说它有的，随对端变；系统不登记它，只按次读清单。
- **动作经工具入口到 agent 手上。** MCP 向工具入口登记一个条目来源。一个接入点是一个工具条目：一个多命令工具，它的每个动作是一个命令。agent 用 `Tools` 搜到这个接入点，看到它的动作各一行，看要用的那个动作的用法，调用它。调一个动作就是一次工具调用：许不许归 Agent 发起时的放行判断，受理、结果保管、取消都归 Tool。MCP 是这次调用背后真正发请求的一方。
- **条目是视图。** 一个接入点能不能被搜到、被调用，按这个主体此刻的事实现算：接入点合法可用，连接上有这份清单。清单变了，下一次搜索就不同，不经装配。接入点用不了时连同原因仍看得到，它的动作不再作为条目出现。
- **连接是长寿的，按租户、持有、采用修订与对端账号分开。** 它不属于任何一个会话。采用修订一变就换新连接。
- **认证是接入点上的一件事。** 人在登记或点「连接」的时候完成它。凭据的本体交给秘密保管，只给连接用。经 OAuth 取得时，流程归 MCP：发现、登记、换取、续期。回跳由服务端这一侧接。出示了凭据还被拒，是「凭据被拒」或「要重新连接」，不是「要授权」。
- **对端的长任务仍是同一次工具调用。** 调用停泊在 Tool 的等待上。MCP 的看守凭耐久的任务记录问对端，到了终态把答复交给 Tool。重启之后接着问，不重新发起动作。
- **事件经 MCP 进来，到消费者为止。** 订阅的正本在本系统，带着收到的位置。事件先落盘、去重，位置同一次提交前进，再交给消费者。给谁、多急归通知。
- **对端带的技能经 `Skills` 入口到 agent 手上。** MCP 向 `Skills` 入口登记一个技能条目来源。MCP 技能不是资产，名字带接入点的前缀，内容是外部内容。交出一个文件之前核它的大小与摘要。
- **对端要补充输入时，问的是人。** 复用工具内「等人决定」的那一个原语，不另做一套。

## 它不是什么

- 它不是工具运行时。它不受理调用，不判许不许，不保管结果，不替 Tool 决定一次调用的结局怎样记。
- 它不运行 MCP 服务。本机上长驻的 MCP 服务也是系统之外的服务。系统只看它的地址通不通。
- 它不把动作登记成工具。没有「同步工具表」这一步，所以也没有两边对不上的时候。
- 连接不归会话。会话结束不关连接；连接断了不结束会话。
- 它不认识 agent、会话、Run。它只认通用角色：主体与租户、接入点持有、调用方给出的关联键与中止信号。
- 凭据不是设置项。它不进日志，不进模型的上下文，不给 agent 读。
- 「连得上」不是「许用」。可用性对谁都一样；许不许调一个动作，每次调用时由授权回答。资格不缓存，撤权在下一次使用时生效，不等清单刷新。
- 「未取得」不是零个动作。首次刷新之前，读面报告未取得。存储读不到也不是「未取得」，答不可用。
- 落盘的清单不是资格。重启后清单还在，每次使用照常核采用与资格。
- 它不决定一个事件给谁、多急，不决定一个技能怎样被搜到与披露。前者归通知，后者归 Skill。
- 它不保管令牌的本体。令牌与续期材料是秘密保管里的绑定，MCP 只留非秘密的事实。

## 拿它量一个设计

- 为了加一个动作要重建 Agent、改系统提示词：错了。动作是数据，入口不变。标了常驻的接入点例外：它在采用点成为一条常驻工具，进工具声明；之后对端加的动作，这个会话里没有。
- 工具入口为 MCP 开了一个专门的分支：错了。工具入口不认识具体的领域，MCP 作为一份贡献登记进来。
- 连接断了，把原来那次调用再发一遍：错了。发出去之后结果不知道就是不知道，按原来的那次调用认回。一次调用至多发出一次。
- 受理之后、发出之前，清单里这个动作的定义变了，照旧发出：错了。复核定义和发出是一步，变了就答「定义已变」，不发。
- 两个租户用同一个接入点，共用了一条连接：错了。
- 对端一直不答，调用一直挂着：错了。调用的截止由调用方的中止信号给出；信号在发出之后到了，告知对端一次，不等它答复，以效果未知收场。
- 发出之后被取消，记成「没有执行」：错了。取消、实际停止、效果撤回是三件事。
- 把对端给的结构化结果压成一段文字再交回：错了。结构化内容是函数的返回值，文字是给模型看的投影，两样都留。
- 对端要人补话，人答了之后恢复段跑了两次，把带答复的请求发了两遍：错了。接续之前先留一条接续记录；再跑时看到记录，答效果未知，不重发。
- 长任务查不到了，记成完成或失败：错了。结论是过期或未知。
- 续期没有应答，就把已有的令牌删掉，或要人重新连接：错了。结果不知道时什么都不删；「要重新连接」只在授权服务器明确拒绝之后出现。
- 给 agent 一个发起连接的工具：错了。连接是人把自己的对端账号交出去，只由登录的人发起。
- 先前进位置，再存事件：错了。两样是同一次提交，不然重启会丢事件。
- 对端终止了订阅，系统自己重订：错了。被拒是裁决，由订它的一方决定。
- 随连接来的技能顶掉了同名的官方 Skill，或它声明的工具许可生效了：错了。
- 系统替用户把一个命令起成 MCP 服务：现在不做。只按地址接入。

## 现状

发行的 `mcp` 行装 MCP 这一类（连同关口模板）、核、动作桥接与任务看守；`mcp-storage-sql` 行存动作清单、接续记录与任务行。进程重启后清单照样列出，还在跟的任务接着查。对端说清单变了，本进程经连接上的长请求自己跟上。对端要人补话时出人工介入的卡，人答了从同一个检查点接续；长任务等到终态再收场。OAuth 授权、事件与对端的技能还没有实现。组织层与别的进程写的设置不移动采用的戳，要等资产变化或本进程的写入才重读。做到哪一步，以源码为准。
