# 资产与规则

## 它是什么

资产回答三个问题：这份能力是谁的，现在用哪一版，对这个主体许不许用。

- **它只认能力标识。** 能力标识是「类别加名字」，例如类别 Skill、名字 `pdf-tools`。类别里面是什么，它不看。
- **类别是登记进来的。** 每个类别由它的拥有者向资产登记：正文契约、名字与一句说明、这一类的定义放在哪个点上。正文是目录的类别另交命名空间、目录的校验与大小上限、从目录到类别声明的投影。加一个类别，资产不改；资产的成员不认识任何具体类别。
- **持有分层。** 官方、组织、租户、工作区，每一层可以持有同名的一份。对一个主体，求值给出胜出的那一份和每个出局者的原因。求值的规则对每个类别是同一套。
- **界面上也按类别分，类别自己画。** 桌面客户端的资产页把类别排成一条栏，每类一个窗格；设置页只放不属于任何资产的设置。资产的界面模块提供治理口：类别的界面模块按租户与类别打开它，拿到这一类的持有与设置项、改与清除、结果不知道时的认回，加一个画一行的默认部件；它把自己的页面经拓展点放到资产页上。没带页面的类别用通用的窗格，和类别自己的页面用同一个口。
- **治理的事实和内容分开放，靠摘要对上。** 谁持有、哪一版、禁没禁用，是记录。包的内容是另一处的字节。一个版本的记录里记着内容的摘要；读内容的人拿到的内容和摘要对不上，就答「材料不可用」。
- **内容怎样存放，资产定一套，别的领域复用。** 单机装配下，存储后端是宿主机的文件系统：每一层一个根，根下每个类别一个命名空间，命名空间下每个名字一个目录。类别领域不自己找地方放。
- **读内容经读口。** 类别领域按能力标识向资产要一个包的读口，按包内的路径读。它拿不到宿主机上的路径。目录加载到本机之后在哪是另一件事：单机装配下它是一个事实，`Skills` 把它告诉 agent，供 Shell 使用。
- **发布是一个操作。** 校验、暂存、记版本、换入。读的人只会看到整份旧的或整份新的。
- **资产管定义，登记表管此刻放着的贡献，两者经类别的点接上。** 资产管一份能力是谁的、哪一版、哪一层持有、许不许用。持有、版本与设置值是持久的记录：类别的贡献撤走，它们不被改写，也不被删除。
- **一个类别对应一个拓展点，各层在持的每一份是点上的一项。** 点由类别领域声明，条目由资产与带来定义的那一方放。一项带着启没启用，被禁用的持有仍在点上。各层的候选从点上读，求值仍是资产自己的规则。工作区不经点，它是并在后面的另一个来源。

## 它不是什么

- 它不认识类别的内容。Skill 的三层、MCP 的地址，它都不懂，也不该懂。
- 它不是工作区。工作区是求值里的一层、并在后面的一个来源；它可以贡献资产，不能授予更高权限。
- 它不是装配。求值回答「此刻合法可用的是哪一份」。这个会话带哪些、哪些常驻，在采用点另外定。
- 它不是授权的全部。它给出资格这一个事实；一次具体的动作许不许，由授权每次回答。
- 宿主机上的目录布局不是契约。契约是能力标识和读口。换一种存储后端，类别领域不改。
- 租户不是一条和类别、层并列的业务轴。它是每条轴上都带着的隔离键：没有一条规则因为「是哪个租户」而不同。

## 拿它量一个设计

- 资产的成员里出现了「如果是 Skill 就……」：错了。类别的差别由类别登记的校验和投影表达。界面也一样：资产的界面模块里没有任何类别的名字。
- 一个类别的界面模块导入资产的成员去读设置项：错了。经治理口，口的形状它自己写，由应用的装配把键交给它。
- 一个类别领域自己拼出宿主机上的路径去读内容：错了。向资产要读口。
- 记录是新版本，目录里还是旧内容，读的人读到了旧内容并当成新版本：错了。对不上就答材料不可用。
- 某一层的来源读不到，求值当成「这一层没有」：错了。读不到是依据不可用，不是空。
- 被禁用的那一份遮住了别的层的合法候选：错了。出局者不遮人。
- 为了让一个会话用上新装的能力去改求值的规则：错了。那是采用或发现的事，见跨领域那一份。
- 一个类别领域自己去读持有的存储、自己拼各层的来源：错了。候选从它那个点上读。
- 拿登记表的「最具体的胜出」代替求值：错了。没有资格的那一份不能遮住别的层，这条只有求值答得出。
- 与更宽的层上不可替换的条目同名的一份发布成功了，只是不生效：错了。发布这一个点就拒绝，什么都不留下；那里的状态读不出时不当作没有。
- 发布了一半，另一个读的人读到了半份目录：错了。

## 现状

上面是目标。类别的登记与各层在持的定义都在登记表上，技能、转换件、Agent 定义的目录与资产的管理服务都经 `layerSources` 从点上读官方与租户两层的候选；工作区层的来源覆盖技能、工具与 Agent 定义。还没有到的：组织层没有来源；租户这一层的候选上，不可替换与替换锁总是否，所以截不住更具体的层；模型供应商不做跨层求值，租户持有的这一类定义不会被用上。求值与持有的记录、类别登记、内容的目录布局、读口、发布操作与开机时的恢复都在 `packages/assets`。新租户的第一次写入先登记它的库。已发布的版本文件不回收：移除与换版都留着旧版本的目录。治理的设置捕获排除正文契约不带设置钩子的类别，Skill 的持有不算进去。agent 经 `OmneExtensions` 列出、查看、问影响、取到工作区、发布、启禁、移除与认回，并读写普通设置项；客户端经 `assets/v1` 上传与发布。做到哪一步，以源码为准。
