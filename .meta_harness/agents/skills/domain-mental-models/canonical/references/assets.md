# 资产与规则

## 它是什么

资产回答三个问题：这份能力是谁的，现在用哪一版，对这个主体许不许用。

- **它只认能力标识。** 能力标识是「类别加名字」，例如类别 Skill、名字 `pdf-tools`。类别里面是什么，它不看。
- **类别是登记进来的。** 工具、Skill、MCP 各自向资产登记自己这个类别：名字的命名空间、包的格式校验、从包里取声明的办法。加一个类别，资产不改。
- **持有分层。** 官方、组织、租户，以后还有工作区，每一层可以持有同名的一份。对一个主体，求值给出胜出的那一份和每个出局者的原因。求值的规则对每个类别是同一套。
- **治理的事实和内容分开放，靠摘要对上。** 谁持有、哪一版、禁没禁用，是记录。包的内容是另一处的字节。一个版本的记录里记着内容的摘要；读内容的人拿到的内容和摘要对不上，就答「材料不可用」。
- **内容怎样存放，资产定一套，别的领域复用。** 单机装配下，存储后端是宿主机的文件系统：每一层一个根，根下每个类别一个命名空间，命名空间下每个名字一个目录。类别领域不自己找地方放。
- **读内容经读口。** 类别领域按能力标识向资产要一个包的读口，按包内的路径读。它拿不到宿主机上的路径。目录加载到本机之后在哪是另一件事：单机装配下它是一个事实，`Skills` 把它告诉 agent，供 Shell 使用。
- **发布是一个操作。** 校验、暂存、记版本、换入。读的人只会看到整份旧的或整份新的。

## 它不是什么

- 它不认识类别的内容。Skill 的三层、MCP 的地址，它都不懂，也不该懂。
- 它不是工作区。工作区是一个来源，加求值里的一层；它以后接进来，资产的规则不变。
- 它不是装配。求值回答「此刻合法可用的是哪一份」。这个会话带哪些、哪些常驻，在采用点另外定。
- 它不是授权的全部。它给出资格这一个事实；一次具体的动作许不许，由授权每次回答。
- 宿主机上的目录布局不是契约。契约是能力标识和读口。换一种存储后端，类别领域不改。
- 租户不是一条和类别、层并列的业务轴。它是每条轴上都带着的隔离键：没有一条规则因为「是哪个租户」而不同。

## 拿它量一个设计

- 资产的成员里出现了「如果是 Skill 就……」：错了。类别的差别由类别登记的校验和投影表达。
- 一个类别领域自己拼出宿主机上的路径去读内容：错了。向资产要读口。
- 记录是新版本，目录里还是旧内容，读的人读到了旧内容并当成新版本：错了。对不上就答材料不可用。
- 某一层的来源读不到，求值当成「这一层没有」：错了。读不到是依据不可用，不是空。
- 被禁用的那一份遮住了别的层的合法候选：错了。出局者不遮人。
- 为了让一个会话用上新装的能力去改求值的规则：错了。那是采用或发现的事，见跨领域那一份。
- 发布了一半，另一个读的人读到了半份目录：错了。
