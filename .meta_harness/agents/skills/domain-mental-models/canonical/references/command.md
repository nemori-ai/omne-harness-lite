# 命令

人用一个名字点名一件事，这个名字就是一条命令。敲 `/名字`、按一个键、在命令面板里选、点一个按钮，是同一条命令的四种触发。

## 它是什么

命令有五种。种类决定它点了之后落在谁的路径上：

| 种类 | 谁提供 | 点了之后 | 落在谁的路径上 |
| --- | --- | --- | --- |
| 引用型（Skill） | Skill 领域，自动 | 这句话原样是人的消息，另带这份 Skill 的正文一块 | 消息的受理 |
| 提示词命令 | 资产的一个类别 | 人敲的那一行原样是人的消息，提示词加参数另成一块跟在后面 | 消息的受理 |
| 系统命令 | 各操作的拥有者，自己登记 | 来源把参数解析成那个操作的字段；会话经入口的进程内调用，用发话人的登录去做，不产生给模型的消息 | 那个操作 |
| 控制 | 会话的界面模块 | 对在跑的一轮做一件事：停止、插队、停一个调用、转后台、重试 | 会话协议里已有的控制操作 |
| 界面动作 | 各界面模块 | 切页、聚焦、开面板 | 只在客户端 |

- **命令领域拥有的是四件事。** 一段输入里哪里是命令、哪里是引用、哪里只是文字；这个会话此刻有哪些入口项；点中之后交出什么；人打字时怎样帮他打对：名字的任意一截都找得到，参数有位置提示与参数候选。别的都落在别人的路径上。
- **命令由拥有那件事的领域带来。** 一条系统命令叫什么、参数是什么、能选哪些值、做的是哪个协议的哪个操作，都由那个操作的拥有者登记的来源说。命令领域只有登记点，它的源码里没有任何一条命令的名字。
- **清单是视图，不是登记簿。** 每一项的事实归它的来源：Skill 的归 Skill 领域，提示词命令的归资产，系统命令的归操作的拥有者。命令领域每次被问，现去问各个入口来源，自己不存。
- **人的菜单和 agent 的 `Skills` 入口，是同一份目录的两个读者。** agent 搜得到的 Skill，人就点得到；人点不到的，agent 也搜不到。两边都是按这个主体当下的事实现算的。
- **触发只是触发。** 用什么触发，不决定它做什么，也不决定它排在谁前面。「现在能不能用」只在命令上算一处，四种触发得到同一个答案和同一个原因。
- **客户端带上它看到的，服务端按当下的事实再判，对不上就拒绝。** 敲出来的带发送方所见：开头是哪条命令，引用了哪几份。按出来的带目标：哪一轮，哪一次调用。两者是同一个结构。
- **位置由种类定。** Skill 可以在一句话的任何位置被引用。提示词命令和系统命令只认开头。
- **名字有两种写法。** 全名带空间，永不相撞。短名按位置解析：开头先找命令再找 Skill，句中只有 Skill。
- **受理时由解析器认。** 会话的受理流水线有一步「解析这段话」，命令领域接在那里，答三种之一：输入（带展开之后的内容），操作请求，拒收。被点名的来源连参数一起收到，参数不对由它说。展开排在受理前处理之前。
- **键位是另一张表。** 它只存「在哪一层、哪个键、哪个外壳动作的名字」，跟账号走，客户端只缓存。按键的捕获全在客户端。

## 它不是什么

- 它不是第二条受理路径。它没有队列，没有日志，不决定开不开一轮。
- 它不是 Skill 的名单。装上或卸下一个 Skill，命令领域什么都不用做。
- 它不是授权。菜单里看得见、参数候选里有、输入框没拦，都不等于许用；受理时每次再问，系统命令由那个操作自己判。点名一个 Skill 不放宽这个 Skill 自己的读取资格。
- 它不是给模型用的。模型取用能力走 `Tools` 和 `Skills`。
- 引用不是启用。引用一份 Skill 是给这一条消息多带一块内容，系统不记「这个会话用了它」。
- 命令不认识键。一条命令不知道自己绑在哪个键上。
- 服务端不认识按键。到服务端的只有归约之后的东西：一条消息，一次控制，或一个操作请求。

## 拿它量一个设计

- 装一个 Skill，要另发一条命令，或要在命令领域登记一下：错了。
- 新装的 Skill，agent 搜得到，人的 `/` 菜单里要重新加载才有：错了。
- 命令领域存了一份 Skill 的名单，或缓存了清单再靠通知去失效：错了。通知只说「可能变了」，丢了也不出错。
- 命令领域的成员里出现 Skill、MCP、某条命令或某个操作的名字：错了。它只认「入口来源」这个口。
- 系统命令执行时把「已经放行」塞给操作，代替那个操作自己的访问裁定：错了。它经入口的进程内调用，用发这句话的那个登录去做。
- 只认名字的开头，敲中间一截找不到：错了。
- 参数候选取不到，输入框就不让发：错了。取不到不拦，交给受理判。
- 外壳或输入框的代码里出现某一条命令的名字：错了。它们只认动作表和输入框助手这两个口。
- 一个按键直接调了某个页面里的函数，没有经过动作表：错了。按钮灰着而快捷键还能触发，就是这样来的。
- 按键到了服务端：错了。
- 一个控制动作没有点名目标：错了。旧窗口里按一下，会停掉后来才开始的一轮。
- 客户端显示「引用了某份 Skill」，服务端按另一个意思受理了，没有拒绝：错了。
- 开头敲错的命令被当成普通话发给了模型：错了。
- 句子中间一个不认识的 `/名字` 被拒收：错了。那是路径，是文字。
- 清单取不到，菜单显示成空：错了。取不到是「无法判断」。
- 引用把 Skill 的正文拼进了人说的话里：错了。正文单独成块，来路是块的属性。
- 定时任务或连接件送来的文字里有 `/名字`，被当成了命令：错了。只有成员本人经交付面发的输入才解析。
- Esc 停掉了一轮：错了。Esc 只管最里面的一层。
- 输入法组字时触发了命令：错了。
