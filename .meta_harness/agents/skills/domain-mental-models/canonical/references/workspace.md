# 工作区

## 它是什么

工作区回答三个问题：这份资源是谁在治理，哪些租户可以在里面干活，它此刻在这台机器的哪里、处在什么版本。

- **工作区是一个逻辑身份，不是一个目录。** 路径、remote、分支都只是定位值。同一个工作区可以有几个实例，一个实例是这份资源的一次物化，例如同一个 Git 仓库的两个工作副本。
- **模型分两层。** 逻辑治理层管身份、关系、授权、实例关联与原操作，所有管理类型共用一套规则。物理资源层由管理类型回答：这是不是我认识的资源，另一处物化是不是同一份，它此刻还在不在、处在什么版本。
- **管理类型是登记进来的。** 文件系统型认一个目录。Git 型继承它，多认一样：这是哪个仓库的工作副本、当前在哪个提交。加一种类型，治理层不改。
- **登记是显式的，登记不动目录。** 租户把已有的目录登记成工作区，得到工作区、自己的所有者关系和一个实例。目录里的内容原样。销毁与解除只结束治理事实，物理资源不删。
- **关系有四种：没有、参与者、超管、所有者。** 谁能授予、撤回、移除、销毁，是一张表。没有关系的租户看不到这个工作区，答复和它不存在相同。
- **一次核验回答「这个租户此刻能不能把这个实例用到自己的工作上」。** 它不写任何事实。次序固定：成员资格与准入，关系，实例仍关联，实例此刻可用。合法的答复带根目录、装载依据和确认依据。
- **可用性是现看的。** 目录被移走、被另一个同名目录替换、仓库换了，都是「实例不可用」，不跟过去，也不改成别的目录。
- **会话拥有「选了哪个」，工作区拥有「合不合法」。** 会话把选择写进自己的日志。每一步开始之前，会话的适配按选择向工作区核验，把结果发布成「会话工作目录」这个块。工具调用受理时把块里的目录钉进固定请求，执行时只认钉住的那一个。
- **agent 可以自己换。** 它用一个工具提交和人一样的会话声明，带的是这个会话自己的主体。目标是当前仓库的另一个工作副本时，工具先把它关联成实例。更换从下一步起生效。

## 它不是什么

- 它不是文件系统的隔离。一次调用能碰哪些路径由执行环境的围栏管；工作区只说实例的范围在哪、许不许。它声明一项设置说 agent 可否读、写范围之外的文件；把范围与这项设置算成一次调用的文件范围是集成的事，这项设置经 Runtime Context 的一块供给。没有选工作区的会话不划范围，读写都不限。
- 它不碰物理资源。不建目录，不克隆，不拉取，不合并。读 Git 的事实只读文件，不启动任何程序：看起来只读的 Git 命令也会运行仓库配置的程序。
- 它不认识会话、Run、工具。谁来核验、什么时候核验，归调用方。它只认主体和租户。
- 核验通过不是许可。每个用到实例的动作各自再核验；关系解除之后的第一次核验就不通过，不等任何通知。
- 治理层不认识任何一种具体类型。规则里没有「如果是 Git」。对文件系统型成立的每一条规则，对 Git 型同样成立。
- 参与者的关系不是租户之间的信任。一个租户的 agent 在共用的工作区里干活，只带这个租户自己的资格。
- 两个独立的克隆不是同一个工作区。同一个仓库的工作副本才是同一份资源的另一次物化。
- 它不是资产。工作区目录里的 `.omne` 作为一个来源接进资产的求值，那是资产的一层；工作区给出一次一致的来源读取，不认识读到的是哪一类。

## 拿它量一个设计

- `workspace-contract` 或 `workspace` 里出现了一种类型的名字：错了。类型的差别由类型自己的四个方法表达。
- 为了知道仓库在哪个提交去运行 `git`：错了。读文件；格式不认识就明确答不支持，不猜，也不退成普通目录。
- 目录不在了，把会话悄悄放回默认目录接着干：错了。答「选了但用不了」，调用不执行，模型被告知原因。
- 更换工作区的提交直接改了这一步的工作目录：错了。块只在一步开始之前换值，已经受理的调用留在它钉住的目录。
- 服务端重启之后，拿日志里最新的选择当成模型已经知道的目录：错了。块是状态块，重启之后装回最近一次步边界提交的值，新受理的调用照它钉住。
- 调用受理之后租户被移除，调用照常执行：错了。取落点之前再核验一次，核不过的调用什么都碰不到。
- 没有关系的租户问一个工作区，得到「未获准」而不存在的得到「找不到」：错了。两种答复相同。
- 一个地址已经属于别的工作区的实例，拒绝的原因里带出了占用者：错了。
- 关联成了而更换没成，工具答「失败」或答「成功」：错了。两步分别如实说，再调一次由按地址找实例接上，不重复关联。
- 销毁工作区时顺手删了目录：错了。
- 工作区的成员里出现了一个类别的名字，或者为一个新类别去改来源读取：错了。类别与它的目录名从登记来。
- 一轮进行中，拿磁盘上现在的内容当这一轮的来源：错了。一轮用的是它开始时采用的那一份；内容对不上时答材料变了。
- 没选工作区的会话把文件工具关在默认目录里：错了。选工作区才是划边界；没选时读写都不限，默认目录只是工具默认在哪里干活。
- 入口为了知道「工作区之外的文件」是哪一档去直连治理的设置服务：错了。那是知道一个值，读 Runtime Context 里的那一块。
- 把「工作区之外的文件」这项设置说成隔离：错了。文件工具由围栏执行；命令只在启动之前核它明着写出的路径。

## 现状

登记、列出、查看、授予与撤回、移除、退出、销毁、实例的关联与解除、附着核验、文件系统型与 Git 型、会话的选择与更换、agent 用的更换工具，都在 `packages/workspace` 与它在 `apps/harness-server` 的装配里。Git 型只认文件格式的引用，reftable 的仓库答不支持。工作区目录里的资产来源只有 Skill 一类走通到会话；「工作区之外的文件」这项设置、每次调用钉住的文件范围与 Shell 的预检、桌面端的工作区页与会话里的选择，也都在。组织的参与政策还没有做。做到哪一步，以源码为准。
