# 进程这一层的装配

## 它是什么

进程里装着哪些插件、谁能换它们、怎样在服务不停时换、坏了怎样办、进程启动哪一版：这一层的规则归 `packages/assembly`。纯的部分在 `assembly`，接到 Cordis 上的部分在 `assembly-cordis`。应用只留发行里有哪些行、进程的入口与退出码、把监督者接到进程上。

- **两层，区别只有两样。** 官方层是发行自带的行与界面模块，加运维者在自己的部署里装的行；租户层是租户的 Plugin 带来的 fiber。一样是谁有权装、换、撤：官方层归发行方与这份部署的运维者，租户层归持有它的租户。另一样是交到手里的是什么：官方层拿到整棵树，租户层只拿到口。装入、备着、换代、排空、起不来时退回，两层用同一套。
- **一行是门牌加背后的一代又一代。** 依赖方认的是入口，进程活着它就不换。换实现是在入口背后换一代：新的一代备着，启动成了一步换上；旧的一代从此不接新的调用，名下在途的做完才算撤完。新的一代起不来，旧的照常服务。
- **三种换法。** 换实现不动依赖方。重跑照 Cordis 的规矩，连着注入它的子树一起卸了再装。换进程是进程有计划地退出，由监督者拉起。一行不声明就是换进程。
- **换之前先算影响。** 一次变更是哪一档、会重跑哪些行，在换之前由纯函数算出；真的换了之后再比一次，不等就走换进程。
- **官方要保护的条目带锁。** 锁只对更深的作用域起作用，租户的条目永远打不成整个部署那一层，所以伪造不了。不带锁的照旧可以被租户盖过。
- **不会挂着不动。** 每个阶段有期限，期限从时间源读。一行坏了，要么在期限内自恢复，要么进程带着原因退出并被拉起，从日志接着来。连着起不来到上限，按版本指针退回上一份起稳过的。监督者按退出码决定拉不拉、算不算一次倒下；人要停服务，就停监督者本身。
- **停机分三步。** 先停准入，再让声明了排空的行在调用方还活着时把在途的做完，然后其余的行按依赖图倒着停。
- **服务端与客户端用同一套版本指针。** 一版一个只读的目录，指针原子地切换；状态目录的戳挡住不认得它的格式的版本。

## 它不是什么

- 它不是采用这一层。采用换的是一次执行的组合与推进者，只在新 Run 开始或租户要求重新加载时发生；行的换代换的是一行背后的实现。两件事都叫换代，规则各在一节。
- 它不是 Dynamis。登记表、答案、锁的答法、座位的换代操作归 Dynamis；这里只决定官方的哪些条目带锁、什么时候让座位换代。
- 它不是 Plugin 的装载回路。Plugin 的状态表、底与客人的写法归 Plugin；装入一份带版本的实现这一段，两层共用这里的装载。
- 它不是隔离。两层之间的墙只对老实的代码成立；存心越界的客人代码归隔离。
- 它不是 Cordis。Cordis 给依赖齐了才启动、依赖没了就卸载；在途的工作怎样处置、期限、退回上一版，由这里给。`ACTIVE` 不等于站稳，也不等于起稳。
- 换的入口不是协议，也不是工具。它是本机的命令，谁能写状态目录与安装目录谁就是运维者。

## 拿它量一个设计

- 租户或 agent 经任何入口能改官方层装着什么：错了。
- 一行没声明能换实现或能重跑，却被热换或悄悄重跑：错了。缺省是换进程。
- 换代中间有一刻新旧都不服务，或新的起不来时旧的已经撤了：错了。
- 正在撤下的一代接了新调用，或名下还有在途的就算撤完：错了。
- 说好只动一行，实际重跑的行和预演的不一样：错了。
- 某个阶段等一件永远等不到的事、没有期限：错了。
- 停机直接按依赖图倒着停，不先停准入、不给排空的一步：错了。
- 一行在它依赖的行回来之前先回来：错了。回来的次序跟着依赖走。
- 指针指到一份没装完的版本，或一版坏了就永远起不来：错了。
- 换实现时新旧契约不同形，仍只换这一行：错了。
- 拿关闭协议之外的另一套做法关一代：错了。进程里的关闭只留这一套。
- 版本目录里另带一份 Cordis 或 Dynamis：错了，同一个服务键会变成两个。
