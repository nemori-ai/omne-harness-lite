## 调用是远程调用

对 Session 和 Agent 这两个领域，调一次模型、调一次工具，本质上是发一次远程请求，像 HTTP 请求那样两端分离。

- 发起的一方只管自己这边发起的调用的生命周期。
- 被调用的一方管它自己的生命周期。
- 发起的一方中断了，至多通知对方一句「这个请求我不再持有」。对方继续做完还是就此停止，是对方的事。发起的一方不管，也不在乎。

它不是函数调用。「我调了它，它就在我的寿命里」「我没了，它就该停」「它的结果只能在我还活着的时候交给我」，这三句都不成立。

它在设计里的样子：

- 一次调用有一个可以保存的稳定引用。发起的一方换了一个实例，甚至崩溃重启，凭引用仍能认回那次调用。
- 结果交给受理时登记的消费者引用，不交给「发起调用的那个对象」。所以 Model 和 Tool 不认识 Agent，也不认识 Session。
- 回执没等到时，结论是「不知道」，不是「失败」。按原来的那次操作去认回，不重新发一次新的。
- 取消、实际停止、效果撤回，是三件事。

拿它量一个设计。设计里出现下面任何一句，多半是把两端缠在了一起：

- 这一方等那一方结束才能收场。
- 这一方替那一方取消。
- 这一方的寿命决定那一方的寿命。
- 这一方要求那一方为它多保留一会儿。

这个模型不只管 Agent 调 Model。第三方来看一次调用也一样：它凭调用的引用向被调用的一方要，不向发起调用的那个对象要。

## Run 是边界

- Run 之外归 Session：这一轮开不开，交给谁，怎样算结束。
- Run 之内归 Agent：这一轮里每一步怎样走。
- 两者之间只有两样东西来往：Session 把工作和推进资格交给 Agent；Agent 把执行记录写进会话日志。

拿它量一个设计：

- Session 的代码里出现了「下一步该调哪个工具」：越界了，那是 Agent 的事。
- Agent 的代码里出现了「这条输入收不收」「会话该不该归档」：越界了，那是 Session 的事。
- Session 想直接控制一次模型调用或工具调用：不对。控制经 Agent 的控制入口送达。
- Session 想知道模型回了什么、工具做了什么：结果在同一份会话日志里，从那里读。Session 一侧的适配成员可以读邻域的公开事实来对账，不发业务调用。

## 知道与决定

一个领域需要另一个领域的东西，分两种，走两条路：

| 需要的是 | 走哪条路 | 例子 |
| --- | --- | --- |
| 知道一个事实 | Runtime Context。拥有事实的一方发布，要用的一方读或订阅，两边互不认识 | 现在是哪个租户，什么权限模式，选的哪个工作区 |
| 要一个决定 | 直连的窄端口。要决定的一方声明一个端口，能做决定的一方来实现 | 这个动作许不许；这次提交成不成立 |

Runtime Context 只供数据，从不发指令。想经它传一个「去做某事」的信号，是走错了路。

## 谁认识谁

- **源码依赖只朝内。** 外层认识内层公开的契约，内层不认识外层。Session 是最外层，经自己的适配成员认识全部邻域；Agent 认识 Model 和 Tool；反过来都不行。
- **内层的契约只用通用角色。** 消费者、持有者、协调者，不点名外层是谁。外层是这些角色的具名实现者。
- **结果在运行时朝外流。** 靠的是登记的消费者引用，不靠内层认识外层。
- **领域不认识调用它的是谁。** 它只按需求的本质提供服务。它的契约里不出现 Session、Run、Agent 这些词，除非它自己就是那个领域。
- **端口归提出需要的一方。** 一个领域需要别人做一件事，它自己声明这个端口，对方来实现。
- **两边都不该认识对方时，中间放一个适配成员。** 例子：`agent-context` 把 Agent 声明的三个需要（准备一次模型请求、读模型可读的运行数据、把账目交出去）翻译成对 Context 的调用。Agent 不认识 Context 的内部，Context 不认识 Agent 的内部。
- **跨几个领域才成立的保证，有一个具名的组合承担者。** 几个局部各自成功，不等于整体成立。

## 一个完整的领域提供什么

判据只有一条：每一样回答一个独立的问题。有这个问题才要这一样。

必须有的：

| 一样 | 它回答的问题 | 形状 |
| --- | --- | --- |
| 领域正文与词条 | 这个领域拥有哪些事实，不拥有哪些；每个词精确指什么 | 领域页；统一语言的词条；有身份的东西另有对象条目 |
| 纯契约 | 别人怎样用它：公开的值、操作、每种失败的含义 | 一个不依赖 Cordis、不依赖存储的成员 |
| 领域实现 | 规则本身 | 一个不依赖 Cordis 的成员。离开这套系统也能单独用、单独测 |
| 失败、未知、取消、恢复的语义 | 出了事怎样答；结果不知道时怎样认回 | 写在契约里。碰到状态与操作的，有全化表 |
| 规格与验证 | 怎样知道它是对的 | 成员规格；测试；命中触发条件的要有形式化模型 |

要在这套系统里运行，还必须有：

| 一样 | 它回答的问题 | 形状 |
| --- | --- | --- |
| Cordis 服务定义 | 它在装配树上叫什么名字，别人怎样声明依赖它 | 一个只放服务定义的成员 |
| 提供者 | 这个部署里它实际由什么实现：哪种存储，哪种外部资源 | 一个把实现和后端组合起来、绑到 Cordis 上的成员 |

有这个需要才提供的：

| 一样 | 什么时候要 | 形状 |
| --- | --- | --- |
| Runtime Context 的块 | 别的领域要「知道」它的某个事实 | 它作为生产者登记一块数据 |
| 给 agent 用的工具 | 要让 agent 能操作这个领域 | 一个独立的工具贡献成员。工具调领域的公开操作，不碰私有的表 |
| 设置项与权限项的声明 | 它有可以配置的行为，或有要管控的操作 | 在它的资产里声明。配值、求值、锁定归设置与权限，它不自己做 |
| 对客户端开放的三样 | 要让人或外部程序用它 | 协议契约、接入插件、协议客户端与界面模块。见 [access.md](access.md) |
| 给别的领域用的端口适配 | 别的领域声明了一个需要，它来满足 | 一个薄适配成员。接口归提出需要的一方 |

三条容易错的：

- **有贡献不等于开放。** 领域带了接入插件来，开不开放由服务端应用的装配决定。
- **对客户端开放的三样、工具、Runtime Context 的块，都是领域带来的，不是谁替它写的。** 入口、界面外壳、Runtime Context、工具运行时都不认识具体的领域。
- **不先开空包。** 先有责任和事实，再有成员。一个新名字、一段共同流程或几个相似的字段，都不单独证明需要一个新领域。

## 动态性与 Cordis

动态的意思是：系统在运行当中，能力可以装上、卸下、替换，而系统不停，在途的工作有确定的结局。

它不是由一个机制提供的，是八条性质合起来的结果。

| 性质 | 它让什么变得可以 | 一句话 |
| --- | --- | --- |
| 定义、装配、活体三分 | 换实现而不动数据 | 定义是数据，只引用能力的名字。装配是某一刻把名字绑到当时可用的实现上。活体是装配出来的运行对象，可以回收，可以重建 |
| 只在采用点采用 | 变化有确定的生效时刻 | 新的组合只在两个时刻被采用：新的一轮开始；租户明确要求重新加载。正在跑的不半路换 |
| 入口稳定，实现靠登记 | 加一个实现不惊动消费者 | 一项能力的入口不换代。实现作为一份份贡献登记到入口上，撤回只撤自己那一份。工具运行时是这样，接入层的登记表也是这样 |
| 每次调用现取 | 提供者暂时不在不等于崩溃 | 用到的时候才去取提供者。取不到就明确答「依据不可用」，不是空，不是异常 |
| 装上有效用，卸下有逆效用 | 卸载是干净的 | 装上一样东西要说清它产生了什么。卸下时要说清撤回什么，在途的怎样处置。卸下是一个过程：先不接新的，在途的各有结局，然后才算卸完 |
| 调用是远程调用，寿命分开 | 调用方换代不丢工作 | 见[调用是远程调用](#调用是远程调用) |
| 事实在日志里，活体不存事实 | 任何活体都可以丢 | 会话日志是唯一事实源。运行对象没了，从日志接着来 |
| 变化可以订阅 | 别人能跟上 | 「现在挂着哪些协议」是一个可以订阅的观察，客户端跟着长出来、收回去。Runtime Context 给出变化的材料 |

### Cordis 提供机制

Cordis 回答怎样接线，何时生，何时灭。

- **一棵插件树。** 每个插件声明自己依赖哪些服务、提供哪些服务。
- **依赖驱动生灭。** 依赖齐了，插件才启动。依赖没了或换了，插件卸载；依赖回来，它重新启动。
- **副作用绑在作用域上。** 一个插件登记的东西、订阅的事件、占的资源，记在它的作用域上。作用域卸载，这些自动收回。
- 服务端和客户端用的是同一个 Cordis。

### Cordis 不提供语义

下面这些它不管，由领域和装配自己组织：

| 它不管的 | 谁管 |
| --- | --- |
| 一个领域的业务含义 | 领域。领域独立于 Cordis 建模，离开它也成立 |
| 在途的工作怎样处置 | 拥有那份工作的领域。框架把插件卸了重跑，不等于业务交接完了 |
| 有先后次序的撤除 | 应用的关闭流程。不能靠卸载的次序 |
| 撤除失败了要让人知道 | 做撤除的一方自己报告 |
| 隔离与权限 | 身份与授权。服务在哪个作用域里看得见，不是权限 |
| 业务身份 | 领域。租户、会话、调用的身份和装配的作用域分别表达 |

Cordis 回答「接什么线、线什么时候在」。「线上跑的是什么、线断的时候业务怎么办」是领域和装配回答的。

拿它量一个设计：

- 一条业务规则只有在某个插件布局下才成立：领域含义依赖了 Cordis，错了。
- 「卸载的时候它自然就停了」：停的是线，不是业务。在途的那份工作的结局要另外说清。
- 一个定义里存了具体实现的引用：定义和装配混了，以后换不了实现。
- 一个运行对象里存了别处没有的事实：它丢了就丢了，不能重建。
