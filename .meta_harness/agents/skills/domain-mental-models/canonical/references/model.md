# Model：被调用的模型调用

## 它是什么

Model 回答一个问题：一次模型调用怎样被可靠地执行、保管并交还给它的消费者。对 Agent 与独立程序，它是被远程调用的服务。

- **受理之后调用方拿到一个可保存的引用。** 引用不是一个活着的连接。执行者可以换代，观察者可以来去，调用方可以离开；调用本身继续执行、保存、收场、记账。
- **受理核身份、输入与份额。** 调用方在首次受理之前固定调用身份与受理 operation。受理先验证主体与显式租户，默认拒绝跨租户；再用同一个封闭输入判断核验输入。受理成功表示原调用与租户份额里的一个名额同时成立，不表示已发出。
- **结局只由耐久事实决定。** 只存在活体内存里的东西都可以丢。调用的结局、每次发出的发送状态与首内容、控制意图、结果保管、费用是几条独立的轴，不压成一个状态。
- **发出不可撤回，首内容是重试的分界线。** 可能已发出的调用永远不写成「未发出」。首内容之前可以按策略再发；之后同一逻辑回复绝不重新生成。判断不了首内容是否发生时，按已发生处理。
- **结果不知道就是不知道。** 提交未知按原操作认回，查询失败保持未知，不换身份重发。`not-accepted` 只在原受理的排队、旧写者与存储恢复都被排除后返回。
- **调用方可以问一句「你的活体还在推进它吗」。** `contact` 只答五种：`holding`、`settled`、`lost`、`not-accepted`、`unknown`。`lost` 要装配给的判断来源出证据；调用方收到 `lost` 后以新的调用身份另要一次。
- **结果交给受理时冻结的消费者。** 调用收场后，结果被读取并确认，或被推送给消费者 owner 保存之后由 Model 自己取得确认，然后清理。
- **档案是关于一个可被调用的模型的全部事实。** 档案身份是所在范围、模型类型加不可变路由名。同名档案按租户、组织、官方取最具体者，只在同一种模型类型里比。
- **模型类型说怎样调用，模态说进出什么，两条轴互不决定。** 模型类型取 `llm`、`decisions`、`live`，由型号记录走的接口决定。三类共用供应商、凭据、目录与启用、同名求值、受理、发出的保存、保管与账目；一个功能要哪一类就按哪一类问，答复是就绪、卡在哪一级或不知道。一个输出图片的聊天型号仍是 `llm`。
- **live 调用是一条开着的线，不是一份应答。** 它没有输出块。进行中的事件只在活体里，推给消费者、消费者存下之后就放掉；事件的唯一存处是消费者的记录。活体丢了，这通调用以失败收场，不重连。收场时 Model 记下事件编到了第几号，消费者据此知道自己漏没漏。
- **模型供应商是请求真实到达的那一家上游服务。** 它是资产类别 `model-provider` 的一份资产，声明它要哪些凭据项；凭据项的值是一项秘密设置。
- **引擎按接口分，型号记录是纯数据。** 每个型号经它那条记录的供应商发出；一条记录是「这家经这种接口提供这个型号」，它固定走一份引擎。引擎与传输的源码里不出现供应商、厂商或型号家族名，厂商差异只能是记录的线数据或带修订名的规则。家族记录变化时新增修订并冻结旧记录，不原地修改。
- **型号记录里的每条适配事实来自经这条记录的供应商发出的真实请求。** 文档只提示该测什么，不单独支撑一条事实。

## 它不是什么

- 它不决定用哪个模型。选中哪一个模型是会话的当前值，归 Session 的选模型操作。
- 它不组装请求，不计量输入。请求输入的表示选择、组装、预算与压缩归 Request Context；上游拒绝时以 `input-over-limit` 收场。
- 它不存会话的事实。它不写消费者私有状态；会话路径上，结果与账目由 Agent 宿主的结果接收方写进会话日志。
- 它不执行工具。它只返回工具建议；工具的定义、准入与执行归 Tool。Model 不依赖 Tool。
- 它不保管秘密。秘密值在 Settings 的秘密保管里；Model 受理时选定一层，发送时只读这一层。
- 它不决定原工作的终态，也不替调用方收场；调用方不替 Model 收场，Model 也不等调用方。
- 它不认识调用它的是谁。它需要的东西声明成端口，由外层装配来适配。

## 拿它量一个设计

- 调用方超时后换一个调用身份重发：错了。按原调用与受理 operation 认回。
- 把「存储里没有 `started`」当成没发出而重发：错了。发送点附近崩溃保留发送未知。
- 首内容之后因为失败再生成同一逻辑回复：错了。
- 取消之后断言上游已经停了：错了。控制意图与上游真实停止分别记录。
- 活体里没有这个调用就答 `lost`：错了。没有判断来源的证据只能答 `unknown`。
- 再驱动一个调用时按当前档案或最新配置重写供应商、凭据层或参数：错了。受理时固定的采用都保留。
- 凭据在租户层读不出时退回官方层：错了。选层整层进行，层内失败直接返回。
- 在引擎里按厂商名写分支，或按名字前缀找家族记录：错了。差异写进记录或带修订名的规则；家族表按采用的四项精确查找。
- 照着文档给型号记录写一条适配事实：错了。它要来自经那家供应商发出的真实请求；同一个型号经两家提供是两条记录，各测各的。
- 给某一类型号单写一套「可不可用」的检查：错了。三类都是档案，都走同一套求值与供给判定。
- 把 live 调用的事件存进 Model，等消费者来读：错了。事件推给消费者，Model 只保管到它存下为止。
- 把费用未知记成零：错了。
