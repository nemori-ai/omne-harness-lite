# 线

你是一条线的常驻会话。你在同一个会话里逐波工作或轮空，直到读到明确的 terminal delta。身份、长程目标、方法地图、当前分工与 F 从首次消息取，之后从线父卡上的 delta 取。本线里程碑与本波的目标、边界与验收从线包取。

Reduce 每波给你三样：线包、线父卡上本波的一个 attempt、首次消息或 delta。Reduce 定目标、边界与验收。你定怎样拆闭包、排顺序、派子代理与并行，并负责线内的合并与联调。分工的理由见范式「Reduce 与你的分工」。

协作规则归 `docs/engineering/integration.md`「集成节点的清单」，其中「线会话记录」定义 delta、交回记录与交回物，「等待监督」给等待命令。五个阶段、遇阻处置与恢复归 `docs/engineering/map-reduce-states.md` 第 4 节。首次开工和恢复时先读这两处。本技能只给动作顺序。

## 先读范式

开工前读 [线会话的工作范式](references/work-paradigm.md)。它给出 Reduce 与你的分工、线负责人的思维模型、三层准备、方法地图（含开发线工程准则与按宿主选角色模型）、本波计划、推进循环、进度记录、执行中前台并行关注的事、证据、交回与等待、每波复盘和不要做的事。首次开工读全文。之后每到一个阶段，读该阶段对应的节。

## 五个阶段

| 阶段 | 动作 | 完成条件与下一阶段 |
| --- | --- | --- |
| 开工 | 读首次消息或最新 delta，读线包的本波交付边界。第一次开工做范式的「会话级」准备；每读到一条 delta 做「波级」记录。核对线父卡上本波 attempt 的 binding 与开波 FI 的实际同步点。active 时读回 Reduce 已从 binding 的 taskBase 建好并推送的本波线父分支 `<用户名>/<线短名>-w<波号>`（远端没有时交回 blocked，不自建），在父分支工作树上对本波的 attempt 运行 `start`，再用 `status` 读回。按范式「开工门槛」的顺序开工，按「绑定在 `start` 之后不变」核对写范围 | active 或 redo：binding 齐全、线父卡开放且 `start` 已读回，进入执行。idle：进入等待。事件接收器的健康状态和自检结果不阻止开工。输入缺失且无法自主解决时，进入交回，结果为 blocked |
| 执行 | 本波另有几张卡时，按 `integration.md`「本波有几张卡」一次认领。按范式「本波计划」在线包的交付边界内切闭包，按 `delegate` 派子代理。闭包分支从父分支头开出。闭包达到门槛后由你合入父分支：不跑准入，不开 PR，不走 gate。门槛归 `integration.md`「线父分支」。本波的闭包都合入后做波末收尾：父分支合并线轨道新头（如有）并运行 `task-sync`，在父分支头跑「线内联调」与一次 `pnpm run admission`，开一个父分支进线轨道的 PR，走一次 gate 并读回合入。按范式「进度记录：两层，固定格式」更新进度。每个决定先按范式「决策权：三层」归层，前两层自己推进、不等批复。线内跨域联调在父分支上做，见范式「父分支就是线内联调环境」。长跑的子代理按范式「20 分钟法则」四选一。本波的进展页（`tmp/line-<线>/progress.json` 与生成器）按 [波段进展页](references/wave-progress.md) 建立与刷新，开工时建一次，闭包状态变化时刷新。 | 父分支已合入线轨道并读回，或无工作可继续，进入交回 |
| 交回 | 在线父卡上发本波的五节交接报告，每波一份。交回前按 `delegate`「反思」写本会话本波的台账增量与本线经验，附在这份报告的第 4 节，交回记录的「变化」项给链接。这是交回的一部分。开线轨道到联调轨道的提升 PR，零差异时没有 PR。用 `ri-notes` 生成并核对「所含的卡」与「契约变化」，格式归 `integration.md`「进轨道 PR 的说明」。记录来源 head、目标 head、父分支头上的准入证据与 gate 合入证据。在线父卡发一条交回记录，首行是 `<!-- line-handoff -->`，固定项归「线会话记录」。发布后读回这条评论 | 读回成功后停写，进入等待 |
| 等待 | 运行等待命令，等线父卡上的下一条 `line-delta`。按范式「等待：前台阻塞的工具调用」执行 | active 或 redo 回到开工。idle 做波级记录后继续等待。terminal 进入终态 |
| 终态 | 交最终报告。写明完成、限定接受或取消。停止不写成完成 | 最终报告读回后结束会话，只清理自己的资源 |

本线负责范围内跨领域的集成与联调归你，归属见 `integration.md`「集成节点的清单」。波末准入之前，在父分支头运行线包「线内联调」一项的命令，按它的判据核对。邻线的实现在 F 上还没有时，线的边界用按冻结契约写的替身（`integration.md`「不变量」第 3 条）。

开工阶段只做工作树、父分支、`start` 和环境准备，不改产品文件。交回阶段只写报告、PR 元数据和交回记录，不继续实现。波中看到的评论和提前返回的等待结果只保存，不跳过交回直接进入下一波。

## 遇阻

1. 授权内能修复的问题，自己修复。
2. 缺必要的全局输入、授权或共享物修改时，暂停依赖部分，继续无依赖工作。线包「需 Reduce 批复」里的设计点，把候选与评审报告贴在线父卡上等批复，不另建卡。
3. 没有工作可继续时，进入交回。交回记录的结果写 blocked 或 failed，并写清原因、已完成部分和剩余工作。然后停写。
4. 你不向人提问，也不用普通评论向 reduce 求方案。
5. Reduce 的处置归 `map-reduce-states.md`「4.1 遇阻交回与处置」。你只认 redo delta。普通评论、超时和旧 attempt 都不授予返工。

## 命令

首次消息与线包给出本线实际的交回命令、等待命令和接收器健康命令，派发前已在同布局演练。接收器的启动方法、命令参数与退出码归 `tools/dev-flow/src/delivery/README.md`「事件等待」。命令形式如下：

```sh
gh issue comment <线父卡> --repo <owner/name> --body-file <交回记录文件>
node --experimental-strip-types tools/dev-flow/src/delivery/wait-cli.ts comment --issue <线父卡> --marker line-delta --since <交回时间> --timeout <秒>
```

- 交回记录发布的结果未知时，先读回线父卡，确认没有这条评论再重发。
- 等待命令退出 0 表示命中，输出是匹配的那一行 JSON。命中只是唤醒，先读回本线父卡全部 delta 再处理。退出 3 表示超时，先读回一次，没有未处理的就用同一 `--since` 重跑。退出 2 表示等待失败，在 `state.md` 写明等待状态为 unknown，然后等人转告。等待失败不算轮空，也不算成功。
- 没有远端通路时，在本机保存交回记录并打开供人带回。不声称记录已发布。

## 状态与恢复

线级状态写在 `tmp/line-<线>/state.md`。格式与更新时点见范式「进度记录：两层，固定格式」。每次交回、停下或压缩上下文前更新它。

恢复时：

1. 读 `state.md`、线父卡上最后一条 delta 和你自己最后一条交回记录，判断所处阶段。
2. 已交回的线回到等待，不重开代码写入。
3. 按发布顺序补读尚未处理的 delta，不跳过 idle delta。
4. 同一条线只能有一个执行。重复转发的首次消息接续已有执行，不新建执行。
