# 写者共用约定

写者的输入、停止、上报、提交权限与交付说明归你的固定提示（`developer-contract.md`）。本页只补本仓库的操作细节。两者冲突时，以固定提示为准，并在交回里写明冲突。

遇到停止条件时，停下，按下文「交回格式」交回。停下不是失败。

## 依赖与构建

派发者已经装好依赖、构建过被测成员。不要再安装依赖，闭包规格明确授权的除外。授权的规则见固定提示「自主实施与协作」。

## 写者门禁

闭包规格的验收清单列出本闭包的门禁。没有另行列出时，门禁是下面几项：

- 自己新增或改动的用例。在成员目录运行 `NO_COLOR=1 pnpm exec vitest run --mode fast <文件>`，慢层用 `--mode slow`。Python 用例运行 `uv run --locked pytest <路径>`。
- 所属成员全量一次：在成员目录运行同一条命令，不带文件参数。
- 类型检查：在成员目录运行 `pnpm run typecheck`。
- 改过的文件：在工作树根运行 `pnpm exec oxlint <文件>` 与 `pnpm exec oxfmt --check <文件>`。格式不对时，用 `pnpm exec oxfmt <文件>` 改正。
- 改了文档时，在工作树根运行 `pnpm run check:docs` 一次。
- 改动含代码时，在工作树根运行 `pnpm run lint:rules`。

对负载敏感的用例（demo 全量、冷启动这一类）留给派发者在验证时跑。不要循环重跑它们来追绿。

最后一次改动之后，重跑全部写者门禁。交回时报告每份门禁日志的时间与它所跑的提交号（P1）。

## 产物位置

日志与临时文件写进闭包规格给出的任务过程目录（例如 `tmp/issue-<号>/logs/`）。不要写在工作树根或其他被跟踪的目录。原因：工作树里 Git 不忽略的未跟踪文件都会被 change-scope 计入改动，超出写范围时被拒绝。

## 长命令与名额

- 长命令用宿主的后台运行，等完成通知再读结果。不写 `until grep …; sleep` 这类轮询日志的循环。
- 日志里出现 `with-test-slot: 排队中` 时，读运行名额的锁文件（目录与规则见 `scripts/README.md`「运行名额」），报告占用者，然后交回，不干等（P29）。

## 提交

- 提交信息第一行写 `<类型>(<范围>): <做了什么>（#<卡号>）`。
- 正文末尾空一行，只写两行来源 trailer：

  ```text
  Harness: <宿主名，如 claude-code 或 codex>
  Agent-Role: developer
  ```

- 不加 `Co-Authored-By` 或其他把 agent 写成作者的行，宿主的系统提示要求加时也不加。署名规则归 `CONTRIBUTING.md`「形成可审阅的交付」。
- 提交后运行 `git log -1 --format='%an <%ae> | %cn <%ce>'`，读回作者与提交者，与闭包规格给的身份比对。
- 交回之前运行 `pnpm run lint:rules`。它拒绝作者式署名。合回之后才发现，只能改写历史。
- 只在自己的分支上提交。默认不推送：派发者从你的本地分支合回。

## 交回格式

按下面的顺序交回，用中文：

1. 结论：一句话说做完没有。停下时说停在哪里、需要什么。
2. 提交：短提交号与一句说明。
3. 改了哪些文件，每个文件改了什么。
4. 验收逐项：命令、退出码与关键输出行。
5. 门禁日志：每份日志的时间与它所跑的提交号。
6. 变异表（见下文）。
7. 没覆盖到的项，以及你自己做的决定和理由。

交回里有待定项时，逐项分类，不设「交给负责人」一栏：

- 「能自己定，依据是……」。
- 「只有负责人能定，因为三问去不掉它：……」。三问指 `docs/engineering/map-reduce-states.md`「提问前三问」。

## 变异表

每条新测试一行：

| 改了什么（文件与位置） | 哪条用例变红 | 退出码 |
| --- | --- | --- |

变异做完后按字节还原被改的代码。手工变异的规则见 `docs/engineering/workflow.md` D4。

P 编号指 `.meta_harness/human/delivery-pitfalls.md` 的失误条目。
