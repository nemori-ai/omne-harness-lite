# 波段编排的判断方法

Reduce 在 PREPARE 分解当前波、在 RELEASE_WAVE 调整后一波预案时读本页。本页只给判断方法。波内独立性、共享物单写、读写交叉与收口守卫归 `docs/engineering/integration.md`「集成节点的清单」与 `docs/engineering/map-reduce-states.md`，本页不改变这些规则。

采用目标倒排（Backward Planning）与验收驱动规划：先明确里程碑最终要交付的行为、接受条件和必交证据，从最终集成态倒推必要能力、依赖和各波成果，再正向核对资源、权限与工期可行性。拆分与切波须保留每项必需成果的归属和验证，不把日期倒排当作工期可行性的证明。

Reduce 以里程碑的可验证进展、端到端完成时间和反馈时延为目标，不追求各线持续忙碌、卡数均等或最大并发。每波形成有意义的可验收增量，轮空是合法安排。到件即处理使开发与集成重叠，工期判断须同时考虑依赖链、集成队列和最终收口。

- 用 DAG、关键路径法（CPM）与资源约束项目调度（RCPSP）判断前置、余量和实际可并行度，优先解除制约里程碑的依赖；不为均衡工时打乱领域所有权。
- 用约束理论（TOC）、排队论与 WIP 控制考虑 Reduce、评审、测试、宿主额度和人工决定的容量。并发以端到端可消化负荷为准，合法写权和公平处置优先。
- 用滚动式规划（Rolling-wave Planning）与滚动时域（Receding Horizon）保持当前波清楚、下一波可调、远期方向可见。根据交付事实重排，波中新影响由 Reduce 承担，不改 Line 的冻结输入。
- 用小批量反馈、信息价值（Value of Information）与风险驱动开发前置关键未知，权衡早反馈与额外验证、迁移、收口成本。不机械切碎长任务，也不把必要探索推到末波。
- 用关键链项目管理（CCPM）、缓冲管理（Buffer Management）与进度风险分析（SRA）预留显式时间和容量余量，保护关键汇入、最终集成与验收。缓冲按风险和历史校准，由 Reduce 统筹其消耗与剩余风险；不固定套用比例，不逐卡重复叠加，也不把已知必做验证藏进缓冲。
- 用三点估算、历史分布和必要的情景分析考虑长尾、共同原因风险与返工。缺数据时保留假设和区间，不给伪精确承诺；超时后调整分解与资源，不削弱契约、验证或接受条件。
- 按功能纵切成波：一波把一个用户旅程环节从接入打通到存储，不按分层横切（先做全部契约，再做全部提供者，再做全部装配）。纵切使每波的增量都能端到端验收，分层横切要到最后一层才第一次暴露集成缺陷。
- 向负责人提议线的划分时，首先让线与线之间的接缝最少：协作紧密的几个领域可以由同一个线会话负责。划分与归属由负责人决定（`integration.md`「线与归属」）。线内跨领域的集成与联调归该线；邻线的实现在 F 上还没有时，线的边界用按冻结契约写的替身。跨线联调归 Reduce：编排时让本波的纵切判据能由收口时的里程碑联调命令，在邻线的真实实现上端到端检查。
- 说某段工作只能串行之前，先找出阻塞来自哪几个文件或类型。不碰这些文件的部分，现在就在正确基线上的草稿树里做，只留一小段切换，等阻塞方落地后补。草稿树不绑定、不建分支、不推送；阻塞方落地后，再把提交搬到正式分支。
- 决定并行时就核对读写交叉：一个单元改的文档，常常是另一个单元读的规格。不要等登记 binding 时才由写范围检查报出来。
- 一个切片可以拆成核心语义与机械两部分，按各自的档位派给不同的写者并行。
- 按 `docs/engineering/integration.md`「卡进入哪条轨道」与「线父分支」，线卡先合入本线本波的父分支，波末父分支经一次准入与 gate 进线轨道。所以每波的集成准入数等于活跃的线数，另加整波验证。Reduce 是几张连续 `integration` 卡的唯一写者时，可以使用该节已采用的个人批次例外，一次准入和 gate 入联调轨道，每卡证据与接受分别保留。工具链线的小批次提前提升由计划或 delta 明确，不改变其他线的冻结输入。
- 里程碑第一次把热路径（会话日志读写、投影、上下文组装这类每轮都走的路径）换成真件时，验收要有一条规模检查：比较第 k 轮与第 k+n 轮的代价。只跑几轮的端到端判据发现不了线性变慢。替身加符合性套件只证明形状，不证明代价。

这些方法用于取舍，不构成固定评分公式或逐步排程规程。波内独立性、共享物单写、具名跨线责任和接受守卫始终优先。不得靠波中问答、隐式换输入或提前放行换取速度；有权范围调整仍须保留未交付责任。
