## 核对方法与证据等级

1. 读取目标宿主实际版本。查其官方支持页与最小版本要求；配置接受一个任意字符串
   不算支持证据。读取精确模型、提供方和组织限制，不输出凭证、完整配置或私密地址。
2. Codex 可用 [App Server `model/list`](https://learn.chatgpt.com/docs/app-server#list-models-modellist)
   查询可见模型和 effort，并处理分页。不能运行实时查询时，可用当前版本的本地目录
   缓存作有时间边界的证据，明确它不是本次实时运行结果。隐藏/内部模型不能自动纳入。
3. Claude Code 对照官方支持与当前版本；当前账户可见项需用该会话模型选择器或
   受支持的只读枚举核对。查询不能暗中改变默认模型或触发一次收费生成。
4. 记录：宿主已支持、当前账户/提供方可用、当前会话可派发、模型实际运行成功。
   不将它们合并成一个 `supported: true`。
5. 确认宿主支持后，才收录这个模型的提示指导/引用；指南未找到则保留缺口，不从
   模型名字、参数规模、其他代际或另一个提供方推导专属提示。

本次未调用目标模型做付费探测。目录可见不保证未来可调用，官方支持也不保证账户
权益。`inherit`/未指定 model 的模板可以保持中性，不能带未经确认的模型专属段。

## 长期维护

新增模型、修改目标宿主版本、切换提供方、目录变化或支持失败时重新核对；模型
材料的维护先更新支持证据，再更新指导。旧模型不再受目标宿主支持时移出当前适配
范围，不为凑齐历史代际保留一套不可用模板。

支持记录是有日期的事实快照，不是运行时路由或永久模型白名单。生成器以它进行
保守准入，新增精确目标需先核对并更新证据，不绕过检查。若离线材料过旧
而无法确认目标支持，明确暂停该模型的专属适配，不用“应该支持”填补证据。
