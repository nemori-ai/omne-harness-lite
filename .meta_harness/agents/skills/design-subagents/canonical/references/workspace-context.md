# 角色资产的工作区与采用上下文

**何时读：**需要定位角色源、生成位置、评估协议或迁移后的维护入口。
**读后确定：**本次明确的工作区、源包、目标宿主与验证/采用边界；缺失项不从父仓库推断。

## 方法与实际输入

本 skill 的 references、模板、示例、支持快照和渲染器在包内自包含。
任务指定设计工作区与执行仓库；两者可分离，当前 shell/Git 根不自动成为它们的权威。
角色目标、写范围、采用模型、宿主版本、账户可用性及正式发布位置由明确输入确定。
支持记录是带日期的证据快照，迁移文件不等于重新核对宿主或调用模型。

采用 `.meta_harness` 布局时，先读其 `agents/README.md`：

| 内容 | 相对明确工作区根的位置 |
|---|---|
| 角色共享源、配置与内联公共正文 | `agents/roles/`，仅消费实际存在的源 |
| skill 的唯一维护源及宿主策略 | `agents/skills/<name>/canonical/` 与 `adapters/` |
| 集中编译及项目链接工具 | `tooling/README.md`，以实际支持范围为准 |
| 研发 agent 的评估协议与采用证据 | `agents/evaluation/README.md` 及其实际引用 |
| 原生生成物 | 工作区内 `.codex/agents/`、`.claude/agents/` |

其他工作区可以显式提供不同位置。角色目录为空时保留缺口，不假定同名旧角色已迁入。
生成方法见[打包](packaging.md)，正文中不永久写入临时 worktree 路径。

## 评估与采用

本包[验证方法](validation.md)指导角色与适配的评估，公开场景只用于开发调优。
若任务包括切换开发主力模型或移除防御辅助，还需消费该工作区实际采用的评估协议、基线、
判据、留出材料与接受权限；不能把脚本通过或一个公开案例成功当作采用依据。
协议尚未提供时可以继续编写候选、核对支持和设计实验，依赖它的采用或退出结论保持未决。
已有任务授权继续有效；本 skill 不另设较弱门槛，也不自动继承承载仓库的评估制度。
