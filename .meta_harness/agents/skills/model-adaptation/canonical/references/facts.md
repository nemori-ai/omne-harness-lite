# 每个型号要测的事实

每项在这个型号要走的那一种接口上测，上游固定。`probe-model.mjs` 覆盖的项标「脚本」，其余单独写请求补测。

| 类 | 要测到什么 | 怎样测 |
| --- | --- | --- |
| 推理的缺省 | 不带推理设置时推不推理、哪一档 | 脚本：`default`，看响应里有没有推理块、用量里的推理 token |
| 推理的档位 | `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 各是接受、换档还是拒绝 | 脚本：`effort-*`。拒绝时记原话 |
| 关闭推理 | 关掉是接受、忽略还是拒绝 | 脚本：`reasoning-off`。有的型号要求必须推理，会答 400 |
| 采样参数 | `temperature`、`top_p`、`top_k`、`seed` 接受、忽略还是拒绝 | 脚本：`sampling-*`。「接受」不等于「生效」，要生效的证据另测 |
| 工具选择 | 自动、不用、强制、指定一个工具 | 脚本：`tool-*`，看有没有工具调用 |
| 消息形状 | 末条是助手消息（预填）、连续两条同角色、空内容 | 脚本：`ends-with-assistant`；其余补测 |
| 推理块的形状 | 类型、格式名、有没有签名或密文；固定上游后格式名是否稳定 | 脚本：`replay-1` 的块类型；格式名看响应体 |
| 推理块的带回 | 原样带回是否计入；前面的内容改动后是否被丢；改坏后返回什么 | 脚本：`replay-2` 看输入 token 与 `input_transformations`；改动与改坏补测 |
| 换模型 | 换到别家再换回推理是否保留；别家的推理块带过来会怎样 | 补测，或看真实模型矩阵的交替格 |
| 缓存 | 会话那样只追加时命中多少；命中与写入记在用量的哪个字段 | 脚本：`cache-1` 到 `cache-3`，同一前缀只追加三次 |
| 用量与费用 | 输入里含不含缓存读与写；费用字段 | 脚本：`default` 的用量；对照缓存三次的数字 |
| 流式 | 首内容、推理、工具参数、收场、用量各在哪个事件 | 补测：同一请求带 `stream: true`，把事件类型按顺序记下 |
| 失败 | 内容被拒、输出上限被推理用完时返回什么 | 补测：小的输出上限加高推理档位 |

测不起的项（例如输入超过上下文窗口，一次要几美元）不测，记录里写「未测」与原因。

## 怎样留证据

- 每次请求的请求体与响应体写进过程目录，文件名带型号与项名。
- 事实表写日期、接口、上游。
- 记录的依据指到证据：录制件的路径，或「哪天、发了什么、看到什么」的一句话。
