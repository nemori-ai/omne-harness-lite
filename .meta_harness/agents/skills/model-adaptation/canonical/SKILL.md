# 型号适配

一条型号记录说的是「这个型号在网关上今天怎样表现」。它的每条事实都要有一次真实请求作出处。文档、迁移指南、厂商博客只告诉你该测什么、可能是什么值，不能当事实写进记录。

## 先知道三件事

- **事实以经这条记录的供应商发出的真实请求为准。** 同一个型号经两家提供是两条记录，各测各的。 文档与实测对不上时记实测，在记录的依据里写一句文档另有说法。结论标明是量到的、读到的还是推的。
- **真实请求花钱。** 每次发之前先记账（本次要发什么、预计多少），发完记实际花费。密钥只进认证头，不打印、不写进文件。
- **记录变了，修订号就升。** 记录的任何字节变了（包括依据的文字），采用指纹就变；同一修订号下的录制件、采用指纹、期望都要跟着换。

## 流程

1. **定范围。** 从 OpenRouter 的模型清单（`/api/v1/models`）与端点清单（`/api/v1/models/<型号>/endpoints`）取上下文窗口、输出上限、价格、支持的参数、服务它的上游。决定这个型号走哪个上游，并在请求里固定它（`provider.order` 加 `allow_fallbacks: false`）。上游不同，推理块的格式名就可能不同。
2. **列线索。** 读 OpenRouter 的通用文档与迁移指南、厂商的发布说明，列出这个型号可能与同家族其他型号不同的地方。每条线索都是要测的一项，不是事实。
3. **实测。** 照 [references/facts.md](references/facts.md) 的清单逐项测。先跑 [scripts/probe-model.mjs](scripts/probe-model.mjs) 出一张事实表，再对表里看不清的项单独写请求补测。探针缺省把型号前缀当作上游固定下来；端点清单里上游的标识与前缀不同时（例如 `qwen/` 的上游是 `alibaba`），用 `--provider` 给出第 1 步定下的上游。每次请求的请求体与响应体留在过程目录。
4. **选引擎。** 通用的 Chat 引擎能做到的先用它。走专用引擎（Claude 的 Messages、OpenAI 的 Responses）要有测到的能力差别，例如只有专用接口能报告推理块被上游丢掉，或只有专用接口能带回推理状态。理由写进记录的依据。
5. **写记录。** 记录在家族成员的 `src/records.ts`：引擎、线上写法（系统提示词怎样放、缓存怎样写、图片、推理摘要、工具名规则）、参数表、用量规则、修订号与每条事实的依据。依据写测量日期、请求的形状与结果，不写「据文档」。
6. **定发行缺省开不开。** 型号记录在官方档案里有了，供应商正文的目录就自动多一项（目录由官方档案投影，不手写），资产页的「模型」块随之多一行。要定的只有它在新租户里缺省开不开：开着的列在发行应用的 `src/assets/release-models.ts`，其余一律缺省关。缺省开着的范围由负责人定；没有新的说法时，新一代替换旧一代照旧例走，拿不准就缺省关，交付声明里写明。发行配置里 Agent 定义的初始模型必须在缺省开着的里面，`tests/assets/release-catalog.spec.ts` 守着这一条与条数，改了集合就改它。
7. **录制与回放。** 每条现行记录在 `tests/fixtures/records/<路由名>/<修订号>/` 有一份真实录制件：`request.json`、`stream.sse`、`facts.json`。用家族成员的 `tests/live/capture-records.ts` 经本机转发器录（转发器加认证头，脚本自己不读密钥）；只改了解码或编码时用它的 `--replay` 从已录的流重写，不发请求。采用指纹在 `tests/fixtures/adoptions.json`，检查是双向的：旧修订的行要删掉。快层的用例照录制件守引擎不退化。
8. **跑真实模型矩阵。** 在 `apps/harness-server` 下 `pnpm run live-matrix --budget-usd <美元> --changed <起点>`：改了记录只跑受影响的格子，改了引擎跑全部。格子都绿再加 `--record` 写进 `tests/live-matrix/baseline.json`。快层有一条不花钱的检查核期望与记录的修订号对得上：改了记录没重跑矩阵，它就红。
9. **同步消费者。** 记录的修订号出现在家族成员的记录用例、采用指纹、发行应用的矩阵期望里；本机发送的用例按录制件里的花费断言。改了就一起改。

## 判据

- 每条事实能指到一次真实请求的请求体与响应体。
- 记录里没有只来自文档的值；测不起的项写「未测」与原因。
- 录制件、采用指纹、记录用例、矩阵期望都在新修订号上，相关成员的快慢两层都过。
- 矩阵里这个型号的格子绿：热身之后的缓存命中不低于下限，带回的推理状态没有被丢。
- 发行缺省开不开定了：开着的在 `release-models.ts` 里，发行目录的用例与条数跟着改。

## 踩过的坑

上游常常与文档不同。测之前读一遍 [references/pitfalls.md](references/pitfalls.md)，那里是测到过的、文档没写或写错的事。
