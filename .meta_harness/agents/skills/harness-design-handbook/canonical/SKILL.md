# 项目设计判断

先确认本次执行仓库、有效要求、所核修订、采用范围及承诺拥有者。本技能提供判断方法，不定义系统、领域或成员承诺，也不授予实施、接受或发布权限。

项目输入从执行仓库读取。新责任从 `docs/requirements.md`、`docs/architecture/README.md`、`docs/domains/README.md` 定位本次拥有者。已有接口从实际包或应用的公开定义及必要行为读取。通用方法按执行仓库 `docs/engineering/skills.md` 加载。信息足够就停，不递归通读整个文档树。

技能资源从宿主给出的本 SKILL.md 实际位置读取。不要从安装目录向上猜项目 docs，也不要假定维护源码和当前工作仓库相邻。

## 选页之前：命名轴与拥有者

先做下面三步，再找现有正文或方法页。方法归执行仓库采用的研发品味页（本仓库为 `.meta_harness/agents/roles/engineering-taste.md#维度分解与正交`；其他执行仓库由派发者给出对应规则）。

1. 列出本次问题触碰的事实与决定。列事实，不列模块或机制名。
2. 为每条事实命名轴，从 `docs/domains/README.md` 与 `docs/architecture/README.md` 找到该轴的拥有者，再读拥有者的现行正文。
3. 拥有者已经回答的事实，按其正文执行。剩余事实分两类：没有拥有者的轴，进入下表的覆盖判断；同一条轴上两个自洽的答案，交有权者裁决。

产出是一份「事实、轴、拥有者、处置」清单，放在任务 tmp。第 3 步之后没有剩余事实时，本次没有设计缺口，直接消费拥有者的正文。

## 按本次缺口选页

| 缺口 | 只加载对应方法 |
| --- | --- |
| 新结果由哪些现有能力覆盖，是否真有剩余责任 | `references/coverage.md` |
| 性质由谁保护，前提、动作链或组合证据是否闭合 | `references/properties.md` |
| 既定语义如何由 Cordis 提供者和装配兑现，精确来源是否足够 | `references/cordis.md` |
| 独立评审对象已明确 | 派发指定的 choice、expression 或 plan 判据页，一次只判一种。派发只做一种评审时，对每一种被排除的评审写明实际派出的是哪一份；没有派的，在报告里写「未覆盖」 |

默认选一个方法页。发现跨页缺口时先点明问题，再按需展开。reviewer 已有明确判据页时直接读取它，不先加载本入口或其他判据。

## 带回什么，何时停止

返回本次判断、准确依据、被复用或改变的责任、尚缺决定或证据、受影响消费者及闭合条件。性质已有权威时引用，不另写同义规则。

关键语义或采用依据缺失时，只停依赖部分。提出有范围的候选，不用当前实现、结构通过或评审意见补造接受。达到任务约定终点即停止，剩余责任可定位、可接续。

本项目的唯一源和保存规则归 `docs/engineering/documentation.md`，验证义务归 `docs/verification.md`，风险和评审条件归 `docs/engineering/quality.md`。普通交付直接消费这些拥有者，不以加载本技能作为默认前提。
