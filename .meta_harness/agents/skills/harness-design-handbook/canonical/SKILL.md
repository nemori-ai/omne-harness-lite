# Harness 设计手册

## 从当前任务进入

先从[工作区上下文](references/workspace-context.md)定位有效需求、采用范围与承诺拥有者。
新或已迁单元采用公开类型、模块旁薄规格与必要理由。未迁单元继续读精确旧契约和相关验证义务。
同一承诺只有一个现行源。文件存在、接口齐全、图或绿测不能替代接受与兑现。
写文档前加载 `asd-ste100`，保留正式术语、条件、例外和要求强度。

## 默认维护流程

按当前缺口推进，信息足够即停止扩展阅读。普通修复无需重走完整设计。

1. **确认需求与责任。**说明可观察结果、有效依据、采用范围及谁拥有承诺。
   新需求先看既有能力能否覆盖；缺资料、缺实现和缺语义分别处理。
   不能把当前实现便利写成业务规则，也不能从目录推断领域边界。
2. **看实际架构与影响面。**读取实现派生的关系、当前消费者和明确架构预期。
   区分静态事实、候选提供者、unknown 与运行观察；标出目标/实现差距。
   对重要变化列明受影响的公开接口、装配、数据、验证和未迁消费者。
3. **明确类型之外的承诺。**公开类型和必要运行时校验表达形状。
   同一拥有者旁的薄规格表达不变量、失败、副作用、并发、取消、恢复和进展前提。
   多提供者共享的承诺由定义拥有者维护；整体性质由协调责任拥有者维护。
   薄规格按有效需求与已接受架构方向表达，当前实现不反向决定承诺。
4. **重要取舍留理由。**仅记录影响后续判断的选择、代价和复核条件。
   优先复用成熟实现；新增抽象须有独立责任、变化、生命周期或部署边界价值。
   Cordis 约束集成方式，领域语义独立于内核；装配不符时修订提供者设计。
5. **实现与验证。**从明确、已接受的承诺实施，冻结写范围和验收。
   隔离、同提交、取消、恢复和进展性质保留相称的模型、探针或故障/并发测试。
   未执行、受阻、有限前提与失败如实记录，不以 mock、类型或图替代行为证据。
6. **更新视图及接受。**从最终源码重新生成实际关系，对照预期解释偏差。
   按风险选择独立评审与验收；其意见是证据，不能自行提升接受状态。
   记录精确修订、检查范围、结果、保留缺口与下一消费者。

未知保持未知，尚未兑现的有效承诺保留责任及验证义务。不能放宽预期或伪造映射来消除偏差。

## 迁移保持什么

先盘点有效承诺、公开类型、Schema、例子、模型、测试、发布与直接/间接消费者。
行为修订与物理移动分别接受；接口变化须同步消费者，公共 Schema 身份不因搬动自动改变。
精确取代范围的消费和证据切换、删除验证通过、有接受依据后，才退役旧现行源。
未迁部分继续约束原消费者。历史接受、原输入与运行结果保留原坐标，不改写成新链已通过。
不为新或已迁单元预建 realization 四件套，也不为尚无实现的有效承诺造空包。

## 阻断与收敛

关键语义、必须的输入或接受依据缺失时，只暂停依赖它的工作；继续独立部分。
不补默认政策，也不把作者推荐、评审通过或文件存在当作接受。
实质评审最多三轮仍未收敛时按[交接的升级规则](references/handoff.md#三轮未收敛时升级结构诊断)检查整体责任和依赖。

## Cordis 最小内核模型

新任务按具体集成问题读取已采用上游事实与项目集成约定。
旧引用所需的内核说明在[A～G 参考页](references/legacy-workflow.md#cordis-最小内核模型)；它不成为领域建模前置。

## Taste

优先保护不变量，保持最小正确模型。复用、抽象价值和复杂度判断见[判断页](references/architecture/assurance/judgment.md)。
执行仓库采用的研发品味由其唯一拥有者维护；本手册不复制第二套规则。
