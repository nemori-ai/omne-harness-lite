# Harness 设计手册

## 从当前任务进入

先从[工作区上下文](references/workspace-context.md)定位有效需求、采用范围与承诺拥有者。
模块采用公开类型、模块旁行为契约与必要理由。行为契约避免重复形状，完整保留必要条件，不限制成员说明、内部设计和维护文档。尚无实现的有效要求由产品或系统设计拥有者维护。
同一承诺只有一个现行源。文件存在、接口齐全、图或绿测不能替代接受与兑现。
写文档前加载 `asd-ste100`，保留正式术语、条件、例外和要求强度。

## 承诺与方法边界

通用定位、实施、规划和验证方法按执行仓库的工程技能入口加载 pstack；
Matt 的 to-spec 与 to-tickets 只整理已确定输入和可验证切片，不代替正式承诺或接受。
本手册保留能力判断、承诺治理、性质归属与 Cordis 符合性。按当前缺口读取，普通修复无需重走完整设计。

- 新需求先核对既有能力覆盖。缺资料、缺实现和缺语义分别处理，不从目录推断领域边界。
- 公开类型与必要校验表达形状。接口拥有者的行为契约完整表达类型之外的不变量、失败、
  副作用、并发、取消、恢复和进展前提。多提供者共享承诺归定义拥有者，整体性质归协调责任拥有者。
- 行为承诺依据有效需求和已接受架构方向，当前实现不能反向决定承诺。
  保留采用范围、重要取舍的理由和复核条件，区分静态事实、候选、unknown 与运行观察。
- Cordis 约束集成方式，领域语义独立于内核。装配不符时修订提供者设计。
  隔离、同提交、取消、恢复和进展性质保留相称模型、探针或故障及并发测试。
- mock、类型、图和局部通过不能替代行为或真实组合证据。
  评审意见不授予接受，结论须绑定精确修订、适用范围、保留缺口和下一消费者。

## 当前终态与过程

按执行仓库的文档治理区分规定记录与临时过程。本项目正式RFC及Issue最小决定和恢复定位适用`docs/engineering/documentation.md`的保存例外；未进入正式RFC的候选、逐轮讨论和评审、原始验证输出仍在执行工作树`tmp/`保存。长期保留当前承诺、必要理由、采用范围和可复跑验证资源，由实际拥有者维护；实现侧内容随包/应用，不把开发日志搬进设计、研究或 ADR。验证文档写义务/方法/局限，单次结果留任务区。

## 迁移保持什么

先按用户当前要求及已接受上层设计判断旧内容是否仍有效，再盘点可承接的细化、公开类型、Schema、例子、模型、测试、发布与消费者。旧接受记录不能推翻现行上层设计；冲突旧设计不迁入规范，实际实现限制作为偏离记录，未判定内容不借迁移取得采用。
行为修订与物理移动分别接受；接口变化须同步消费者，公共 Schema 身份不因搬动自动改变。
精确取代范围的消费和证据切换、删除验证通过、有接受依据后，才退役旧现行源。
只有仍符合现行上层设计的有效细化继续约束消费者。保留旧文件不保证其中全部设计有效，也不要求保全被取代的条款。本次核对输入和结果留任务 tmp，不要求永久保留形成史；物理迁移不升级接受、实现或验证状态。
使用实际执行仓库的版本化包模板，不另建中央模块规格或节点四件套；不为尚无实现的有效承诺造空包。

## 阻断与收敛

关键语义、必须的输入或接受依据缺失时，只暂停依赖它的工作；继续独立部分。
不补默认政策，也不把作者推荐、评审通过或文件存在当作接受。
实质评审最多三轮仍未收敛时按[交接的升级规则](references/handoff.md#三轮未收敛时升级结构诊断)检查整体责任和依赖。
