# 信息包准入与停止条件

**何时读：**准备落盘、迁入旧材料，或不确定该进哪个 design family。
**读后留下：**持续消费者、唯一语义拥有者、准入结果和受阻时的临时落点。
**返回：**[工作区上下文](workspace-context.md)选择实际模板，或[交付](handoff.md)记录缺口。

## 先过统一准入测试

只有任务结束后仍有人需要材料作判断、兑现契约或复核证据，才进入长期设计链。
指出唯一语义拥有者，并确保来源、范围、状态、未知与下一步消费足以接续；否则留在本次 `tmp/`。
观察、候选、评审、接受、发布、实现和验证不能因换目录而升级。

| family           | 最低可消费信息                                           | 不满足时停止                                           |
| ---------------- | -------------------------------------------------------- | ------------------------------------------------------ |
| requirements     | 观察者、触发、所需/禁止结果、来源与确认范围              | 留在 intake；不补造确认或机制                          |
| research         | 持续问题、精确对象/版本、取得方式、观察与局限            | 一次检索留 `tmp/`；不可核实则只留待验证命题            |
| proposals        | 同一选择对象、能力覆盖、剩余责任、至少三个实质候选及证据 | 不足三项留 research/任务探索；已有决定的普通施工不建包 |
| decisions        | 有权者、接受记录、精确修订、范围、前提与取代关系         | 未接受就留 proposal；reviewer 意见不能升级             |
| architecture     | 需求/决定/catalog 快照支撑的当前能力基、组合与覆盖范围   | 采用不明就标候选/缺口，不建第二份契约                  |
| spec/data        | 多方共享且必须一致的数据含义、身份、版本和消费者         | 单方内部表示回能力/提供者；归属不明先停止              |
| spec/capability  | 可独立解释和演化的能力责任、操作/状态/失败及精确依赖     | 现有能力仍能拥有时不新增；语义未定保持候选             |
| spec/composition | 不能归于单项能力的整体性质、参与版本、保护者与失败交接   | 只汇总依赖不准入；关键责任未定不发布                   |
| providers        | 精确能力契约到插件/服务、源码修订、资源/装卸与符合性映射 | 只有机制设想回 proposal；无实现只记缺口                |
| assemblies       | 实际应用、提供者选择/版本、配置、动作链与集成证据        | 选择未发生保持候选；局部通过不等于整体完成             |
| migrations       | 长期前后身份/采用关系、过渡、消费者切换与退出证据        | 计划、派发、清单和进度留 `tmp/`                        |

## 模板与形式工件

topic 是入口加按需正文、证据和评审的信息包，不是单份固定表。先读实际 family README，
从相邻 `.templates/` 复制整包，再删除不适用文件并同步入口；模板占位不能进入 catalog 或状态清单。

规格中的 Schema、TLA+、Alloy、场景或证明按性质需要选择。optional 表示不为每个 topic 预造空工件；
契约或设计已经触发的行为、结构或证明义务必须完成或显式阻断相应发布与消费。

**停止判据：**正文只有一个拥有者，消费者能按入口找到必要信息；临时施工材料没有混入长期 family，
未满足的准入项保留在可恢复任务输入并指出闭合条件。
