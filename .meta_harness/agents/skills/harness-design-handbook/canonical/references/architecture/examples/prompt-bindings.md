# 示例：动态提示词变量

**何时读：**需要一个动态定义与调用绑定的具体演示。
**读后决定：**辨认声明、发布、绑定和历史，不照搬候选政策。
**返回：**[阶段页](../../project.md) · [专题地图](../../topics.md)。

## 假设与职责

假设提示词可独立管理与发布，包含固定文本和引用受限变量的动态模板；某个模板引用名为 `workspace_summary` 的变量。本例仅说明组合语义，不规定正式字段或模板语法。

内容管理能力保存定义和发布状态；变量提供者声明可提供的事实及读取范围；渲染能力按授权作用域组装结果；运行驱动决定何时渲染。存储保存记录，不自行决定发布或授权是否合法。

变量名的拼写可以检查，但合法性还要求存在有效声明，并且当前消费者有权使用。模板作者写入新名字，不能自行扩展系统允许的变量集合。详见[动态合法集合](../runtime/evolution.md)。

## 一次使用

发布时可以验证模板引用与声明契约；每次渲染还需要确认当前提供者及取值可用。本例选择“一个渲染操作使用确定的内容版本和有效绑定”作为说明政策，具体项目何时取得绑定仍需设计。

固定文本在相同内容版本下保持相同；动态取值依赖规定的状态来源和观察边界。如果一次渲染要求多个值来自一致快照，需要由该状态能力提供相应保证；仅在开始时记录时间，不会自动得到跨服务快照。

渲染所用的版本和必要来源应有足够证据解释最终输出。需要保留已进入会话的文本时，保存的是该次使用的结果或可可靠重建它的事实，不能依靠以后再次调用提供者获得相同内容。

## 提供者变化

替换期间，已经接纳的渲染可以固定旧绑定完成；也可以明确失效后重新准备。两者都需要避免一次输出混用未经允许的新旧语义。新渲染何时看到新提供者，应由切换边界决定。

撤除仍被引用的变量时，可以拒绝撤除、等待旧使用结束，或使相关渲染进入不可用状态。这些是待选择的政策，不能靠返回空字符串隐含选择“成功”。过去已形成的会话文本也不会因变量卸载而消失。

注册表仍存在，不代表这个变量仍可用。具体条目的依赖与撤除要有[明确绑定](../modeling/capabilities.md)。

## 需要验证的关系

- 未声明或无权读取的变量不能进入成功输出。
- 同一次使用符合约定的内容版本、绑定与状态观察边界。
- 提供者撤除后，新使用与旧使用分别遵守所选政策。
- 已承诺保留的历史文本不依赖提供者持续存活。

入口约束负责拒绝非法使用；若保留了独立来源，可核对组装结果与所用绑定。检查器本身的装载范围和历史基线按[不变量指南](../assurance/invariants.md)说明。
