# 从消费者视角核对契约

**何时读：**已有候选，需要发现漏掉的语义与交接，或确认另一位 agent 能否据此实施。
**读后留下：**具体缺口、所属责任和受影响消费；不适用的检查项无需造工件。
**返回：**[定义](../../define.md)或[交付](../../handoff.md)。

## 按行为选择核对要点

纯计算可能只需输入输出、失败与共享类型；长生命周期任务还需要所有权、取消和恢复。
下表是审阅视角，完整动作链的方法只由 [S5](../../define.md#s5从入口走到稳定点)维护。
这些关注点检查能力承诺是否充分，不能直接当作现有能力维度或固定的模块清单。

| 消费者需要知道 | 核对问题 | 缺口展开到 |
|---|---|---|
| 对谁承诺什么 | 责任与不承担的范围是否清楚？ | [能力边界](../modeling/capabilities.md) |
| 如何辨认和访问 | 身份、权威类型、发现/读写/撤除权限是否分清？ | [身份与作用域](../modeling/identity-and-scope.md) |
| 谁能观察哪些事实 | 披露范围、内容裁剪、顺序和新鲜度是否满足要求？ | [身份与作用域](../modeling/identity-and-scope.md)、[状态与存储](../modeling/state-and-storage.md) |
| 何时可以使用 | 依赖、条目、绑定和失效后响应是什么？ | [依赖与解析](../modeling/capabilities.md#依赖与解析) |
| 何时算发生或结束 | 接纳、提交、结果未知、取消、通知失败各指什么？ | [交互协议](../runtime/interaction.md) |
| 谁保留和释放 | 实例、任务、句柄、事实各由谁拥有？ | [生命周期](../runtime/lifecycle.md)、[状态与存储](../modeling/state-and-storage.md) |
| 什么必须保持或最终发生 | 性质来源、观察点、保护操作和进展前提在哪里？ | [不变量](../assurance/invariants.md) |
| 改变后怎样继续 | 生效点、旧绑定、在途工作与恢复有无归属？ | [动态演化](../runtime/evolution.md) |
| 额度与时间怎样约束行为 | 消耗由谁计量，限额/超时改变准入还是结果，已发生效果如何表达？ | [交互协议](../runtime/interaction.md)、[不变量](../assurance/invariants.md) |
| 跨边界是否仍成立 | 当前所需部署范围内，身份、失败与协调怎样保持？ | [部署边界](../runtime/distribution.md) |
| 凭什么依赖保证 | 精确版本、证据范围、前提责任和未验证义务是什么？ | [规格与证据](../assurance/specification.md)、[组合性质](../assurance/composability.md) |

## 沿完整动作链核对组合

选一条真实触发走到约定结果，再选最可能丢失责任的拒绝或失败分支。
例如执行者已交出工作资格，下一方授权直接拒绝；只有“允许”和“待批准”路径时，谁来结算或接续原工作？
每个局部状态都合法，不能说明整条操作有合法终点。

把缺口写成“在何种输入/交错下，哪个消费者无法依赖哪项承诺，由谁补齐”。
交接落在所属能力或组合契约，再对应提供者/装配；不能通过完善 Schema 或列齐接口遮蔽最后一段行为。

## 结束核对

引用精确权威和版本，不重新解释所有基础概念。
检查结论限定语义、提供者、装配与证据各自的范围，按[四层就绪](../../handoff.md#区分四层就绪状态)汇总。
足以回答本次消费者的问题即可收口；候选未决项明确保留，不以增加表格证明完整。
