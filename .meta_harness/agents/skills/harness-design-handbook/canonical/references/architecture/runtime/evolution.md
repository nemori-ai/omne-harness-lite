# 动态定义、装配与演化

**何时读：**定义、配置、依赖或提供者在运行中变化。
**读后决定：**生效/绑定边界、在途工作、旧引用及恢复政策。
**返回：**[阶段页](../../project.md) · [专题地图](../../topics.md)。

## 区分定义与运行

已保存的定义、已发布版本、当前激活实例、期望装配和实际运行态是不同内容。保存成功不意味着发布合法，发布成功不意味着当前依赖就绪，配置已提交也不意味着所有实例已活跃。

定义由哪项能力管理，如何授权修改、发布和激活，应有明确归属。支持独立发布的内容，不应随着某个消费者退出而丢失；动态代码定义跨重启是否保留、是否自动激活，也必须分别约定。

关于定义、绑定和版本的基础含义，见[概念定义](../foundations/concepts.md)。本页不规定所有能力具有统一发布状态机。

## 合法集合与使用绑定

动态 key 的合法性可以由有效声明、作用域和授权共同决定。填入一个语法合法的名称，不意味着它已经声明或允许访问；某时刻集合有限，也不要求把所有未来名字固化为永久枚举。

发布时验证引用，与使用时确认提供者可用，是不同检查。消费者只依赖大注册表时，还需要明确对具体条目的使用绑定及失效响应，详见[能力依赖](../modeling/capabilities.md)。

为一次操作选择稳定的使用边界：固定一个版本或代际完成，变化后重新准备，或明确失败。不可混用的字段应在同一绑定下解析。对在途操作采取何种政策取决于契约，不预设全系统冻结或统一停机。

## 变更及失败恢复

变更描述需要说明候选内容如何验证、何时对新消费者可见、旧消费者何时停止，以及何时可以释放旧资源。影响多个条目时，必须说明成功与失败覆盖的集合和观察范围。

| 可选政策 | 需要兑现的承诺 |
|---|---|
| 仍有使用时拒绝撤除 | 能识别有效使用关系，并报告拒绝原因 |
| 停止新接纳后排空旧使用 | 旧绑定保留到规定终态，再撤除提供者 |
| 显式终止受影响工作 | 终止结果和已发生外部效果可追踪 |
| 有条件迁移活跃使用 | 状态解释、所有权移交和失败恢复有独立契约 |

不同政策可以用于不同能力。不得把“插件可以重载”直接解释成“所有业务可以无缝迁移”。

失败恢复应明确恢复的是装配、配置、业务状态还是访问路径。恢复上一份配置不等于恢复旧实例的全部内存，也不撤销已提交的外部效果。如果恢复本身失败，应暴露当前状态与不可用范围，不能声称仍完整保留旧系统。

## 版本与规则演进

契约版本标识语义，内容版本标识发布内容，运行代际标识实例，数据格式版本标识保存的表示。几个编号可以相关，但不能用一个递增数字隐含替代所有兼容关系。

已发布内容需要可重复引用时，应能标识确切版本；可变的“当前版本”指针是另一项状态。
规范工件的冻结、升版与消费者传播见[规格演进](../../spec-evolution.md)，不与运行时代际混为同一个编号。

兼容承诺由实际需求和采用关系决定，不能凭手册假定待设计系统尚未上线或必须兼容旧版。
允许移除旧接口时，仍须明确处置在途工作、已承诺保留的数据与外部效果。

不变量或权限规则变化也属于演化。应说明新规则适用哪些对象和操作，旧检查何时退出，切换期间如何保持必需约束，详见[不变量](../assurance/invariants.md)。
