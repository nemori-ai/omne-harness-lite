# 未迁承诺的当前拥有者

本页只定位仍有效的承诺，不恢复开发形成史。用户新要求优先于旧工作流。
模块已迁移后，公开形状、薄规格、必要理由和可复跑资源随接口拥有者维护。

## 通用 family 名落在本工作区的哪里

| 内容 | 当前拥有者 |
|---|---|
| 系统目标与约束 | `design/foundation/` |
| 产品含义、规则、未决与验收 | `design/product/<topic>/` 的现行正文 |
| 统一语言、领域对象 | `design/ubiquitous_language/`、`design/domain_objects/` |
| 可重复消费的上游事实与机制探针 | `research/`、`design/basis/` |
| 未迁数据、能力与组合契约 | `design/spec/{data,capabilities,compositions}/<topic>/v<N>/` |
| 未迁提供者与装配当前映射 | `design/realization/packages/<group>/<node>/`、`design/realization/apps/<node>/` |
| 精确坐标、接受范围、冻结、关系与形式义务 | `design/registry/` |
| 系统级架构预期 | `design/architecture/` |
| 派生视图 | `design/views/`，不作为第二份权威 |
| 比较候选、提案、接受过程、评审、计划与实际运行结果 | 各自工作树 `tmp/<task>/`，不进入长期 family |

## 取得可实施输入

先核对当前需求范围、公开承诺及精确采用关系。接受、可实施、实现与验证分别表达。
部分采用必须定位所采用的条款，不能把整篇候选提升为接受或实现完成。
缺失能力、提供者、可信恢复输入与证明前提保持显式缺口，禁止创建空包冒充落实。

catalog 的 `acceptance` 表达当前 `scope_path` 与 `scope_clauses`，不依赖过去的决策事件。
技术选择与必要理由归当前拥有者正文。未接受选择保留为该正文的明确候选或未决项。
比较过程和接受事件留任务 tmp。终态不能指认 tmp、历史 Git URL 或快照目录为现行承诺来源。

## 未迁规格与映射

规格当前仍采用精确 `v<N>` 坐标。消费者和验证义务迁移前，旧坐标不能直接删除。
同一承诺只保留一个现行拥有者；已迁模块不预建 realization 四件套。
根入口、Cordis 绑定、服务定义与插件生命周期按现行集成约定核对。

冻结正文的语义变更须有明确接受。导航、状态和过程文字整理须核对规范条件，
不能靠统一刷新哈希绕过冻结。身份、Schema URI、租户和事务语义、形式性质继续约束消费者。

## 验证与交付

形式模型、配置、测试和必要最小夹具是可复跑资源，归实际承诺/消费者拥有者。
verification 正文只写义务、方法、前提和限制。原始输入、输出与本次结果在任务 tmp。
检查器只核已配置的结构或实际执行范围，不证明正文无歧义或完整系统已兑现。
设计评审前由派发者运行机械报告，评审者只判断指定对象，评审不自动产生接受。
