# 在设计工作区内取得上下文

需要确认有效需求、采用范围或承诺拥有者时读本页。信息足够即回当前任务，不展开全链。
实际工作区由任务明确提供；通过 skill 入口定位时先解析软链接。不从 shell 的父目录猜设计事实。

## 现行源

| 问题 | 拥有者 |
|---|---|
| 系统目标及跨系统约束 | design/foundation/ |
| 产品规则、接受状态与未决事项 | design/product/ 对应 topic |
| 正式词汇及有身份的对象 | design/ubiquitous_language/、design/domain_objects/ |
| 全系统预期、跨模块约束与模块规格归属 | design/architecture/README.md 及其现行正文 |
| 新/已迁模块形状与剩余行为 | 执行仓库里接口拥有者的公开类型、薄 SPEC、必要 ADR 与验证资源 |
| 实际关系、来源、变化与未知 | 对具体源码修订生成的架构数据，不是手写语义权威 |
| 未迁协议与实现投影 | design/registry/ 的精确采用项及相应 spec/realization 剩余范围 |
| 上游事实及采用版本 | research/、design/basis/ 的具名来源和可失败探针 |
| 接受、提案与实际验证 | 执行工作树 tmp；长期只保存实际拥有者的当前承诺、必要理由和验证义务 |
| agent 方法与职责 | agents/skills/、agents/roles/ canonical 源及宿主适配 |

工作区规则及本次用户要求确定采用范围。模块的当前实现不能反向定义承诺。
同一承诺一份现行源，接受、实现和实际验证分别记录。
产品规则仍归设计工作区，模块就近规格不复制产品正文。

## 读旧源的条件

具名未迁任务按其精确旧源与证据义务接续，必要时读[旧上下文](legacy-workspace-context.md)。
先核对迁移取代范围，不能仅凭目录存在就采用旧投影，也不能凭新入口就删除尚有责任的旧源。
有效未来义务有拥有者，不为它建空包；不要求保存决策/证据形成史。

## 派发与停止

任务简报给出实际输入、精确修订、范围、可写路径、验收和停止条件。
重要判断及接受归负责者；独立评审按判断对象派发，实际验证按风险采用。
关键输入或接受依据缺失时暂停依赖部分，继续独立工作。
临时施工计划、盘点和运行日志留任务 tmp；持续消费的结果回相应拥有者。
