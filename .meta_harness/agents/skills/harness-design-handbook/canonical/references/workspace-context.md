# 在设计工作区内取得上下文

需要确认有效需求、采用范围或承诺拥有者时读本页。信息足够即回当前任务，不展开全链。
实际工作区由任务明确提供；通过 skill 入口定位时先解析软链接。不从 shell 的父目录猜设计事实。

## 现行源

| 问题 | 拥有者 |
|---|---|
| 本项目要求及跨系统约束 | 执行仓库 docs/requirements.md；已采用条款不再由 design/foundation/ 的位置推定 |
| 产品规则、接受状态与未决事项 | design/product/ 对应 topic |
| 正式词汇及有身份的对象 | design/ubiquitous_language/、design/domain_objects/ |
| 已采用系统应然与领域责任 | 执行仓库 docs/architecture/、docs/domains/ |
| 未迁精确技术承诺 | design/architecture/README.md 定位尚未承接专题、完整Session候选及PF详细技术；IC与采用映射归执行仓库docs/architecture，成员精确承诺归实际拥有者 |
| 包群与成员文档 | 执行仓库 docs/member-documentation.md；包群拥有组内工程关系，成员拥有使用、行为、内部设计与维护 |
| 新/已迁模块形状与行为 | 实际接口拥有者的公开类型、完整行为契约、必要 ADR 与验证资源，SPEC 避免重复形状但不删必要条件 |
| 实际关系、来源、变化与未知 | 对具体源码修订生成的架构数据，不是手写语义权威 |
| 上游事实及采用版本 | research/、design/basis/ 的具名来源和可失败探针 |
| 接受、提案与实际验证 | 执行仓库docs/engineering/documentation.md规定RFC／Issue最小保存例外；其余过程及单次结果留tmp，当前规范与验证义务仍归实际拥有者 |
| 通用工程方法及项目差异 | 执行仓库 docs/engineering/skills.md 选择已采用 pstack 与 Matt，workflow、publication、quality 各自拥有项目约定 |
| 独有 agent 能力与职责 | agents/skills/、agents/roles/ canonical 源及宿主适配 |

本表的执行仓库路径描述本项目已经采用的位置。单独迁出手册时由任务明确提供对应拥有者，不猜测外部仓库。
工作区规则及本次用户要求确定采用范围。模块的当前实现不能反向定义承诺。
同一承诺一份现行源，接受、实现和实际验证分别记录。
产品规则仍归设计工作区，模块就近规格不复制产品正文。

## 迁移与尚未实现

迁移先辨认当前有效要求、唯一拥有者、实际消费者和相称验证资源。物理位置变更不改语义或数据身份。
尚无实现的有效要求留真正产品或系统拥有者，写明未实现与必要前提，不建空包。
正式RFC与Issue规定记录按上表判断，其余候选、逐轮评审、采用形成过程及单次验证结果留任务tmp。

## 派发与停止

任务简报给出实际输入、精确修订、范围、可写路径、验收和停止条件。
重要判断及接受归负责者；独立评审按判断对象派发，实际验证按风险采用。
关键输入或接受依据缺失时暂停依赖部分，继续独立工作。
临时施工计划、盘点和运行日志留任务 tmp；持续消费的结果回相应拥有者。
