# 核对 Cordis 承载和采用来源

本页在能力责任及必要语义明确后使用。领域不由 Cordis 建模，Cordis 提供装配、组合、依赖注入和生命周期。

## 从精确语义提出机制问题

说明所核承诺修订、消费者、要求的保证及候选提供者。每个机制问题对应一项会改变选择的性质，优先核失败、并发、取消、恢复及收尾。研究来源中的包、fork 或 API 不因此成为项目已采用方案。

只有需要具体 Cordis 行为时查来源。先核执行仓库的采用版本及范围，复用该版本的 basis 和 probe。未覆盖主张再查固定版本官方文档及源码，并用最小探针补足。分别记录实际采用版本、此次查阅版本、官方发布包及自有 fork 与上游基线的对应关系。记录 API 或生命周期主张、出处、适用前提及未知。文档与源码冲突时先核修订和发行物，仍冲突则保留双方证据并暂停依赖的选择。当前版本事实不在技能内另维护一份摘要。

## 投影到真实提供者和装配

既有语义及组合足够时复用其提供者，补实际消费和装配。实现不足时补齐或更换提供者。扩展责任时核真实消费者。独立维度的插件只承担该维度，不以转发包装证明其独立性。

核对提供者和装配怎样兑现身份、所有权、依赖、作用域、装卸、资源取得、失败、在途工作和结果交接。共同集成保证引用执行仓库 IC 约定及 constraints，成员公开承诺仍归成员。

每项绑定说明稳定语义条目及一个在该语义消失时会失败的验证。源码行号或同名 API 不能证明机制和契约语义重合。静态 assembly 结构不能替代同提交、租户授权或释放完成的运行证据。

替代实现、不同作用域实例及内部函数不自动成为新能力维度。机制不能兑现正当承诺时，先换提供者设计，不为装配方便修改领域边界或降低契约。替代仍无法成立时，按能力页的代价回询说明用户后果，由有权者裁决。

## 反向核对与停止

逐条返回有效要求、精确承诺、真实提供者或装配责任、证据范围及剩余缺口。反问新增插件为何不可由既有能力承担，反查声称已有的组合是否实际具备全部前提。

提供者机制未定、版本证据不足或运行资源不可用时保留具体缺口。可研究的独立部分继续，不能把来源核对、装配明确和真实通过合成一个支持结论。

来源入口为官方 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)。本项目从目标检出的 `.meta_harness/design/basis/README.md` 及其指向的 adopted basis/probe 读取采用事实。旧 4.0.2 摘要不再是现行依据。只读所核主张需要的资料，不展开整个 DSH 应用。
