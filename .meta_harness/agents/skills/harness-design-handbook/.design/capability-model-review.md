# 能力维度心智模型修订

日期：2026-09-15。范围：handbook 顶层指导及受影响 references，待用户审阅。
本轮不建立模板、不迁移产品设计、不改生成工具或切换根入口。

## 最新语义依据

用户明确：产品需求先分解到现有系统能力的一个或几个维度，检查组合能否承载；
没有合理承载方式的剩余独立责任形成新能力维度，再投影为独立的 Cordis 插件。
此要求优先于原稿固定八根变化轴的叙述，以及前轮将“关注点”与“能力责任”分为两个空间的整理。

本轮将能力基视为可维护、可增长的语义体系；既有能力是否存在由契约与采用上下文确定，
不从空骨架、接口清单或实现完成度推断。新增是有依据的设计选择，不是要求名字到插件名字的转换。

## 已失效的表述与调整

| 原表述/组织 | 问题 | 本轮处理 |
|---|---|---|
| 要求先投到固定的八根变化轴，再投到能力责任 | 把通用检查关注点放在能力维度的位置 | SKILL / decompose 改为要求到既有能力的覆盖、剩余责任与演化 |
| 只列七类关系，缺少覆盖推理 | 不能解释为何新增、为何不扩展，也容易将实现缺失当新能力 | 关系表变为分析结果；增加承载依据、组合反例、缺口分类与新增理由 |
| “能力不与插件一一对应”等笼统提醒居于主线 | 弱化了用户要求的独立维度到独立插件的设计目标 | 明确新增独立维度必须给出独立插件实现边界，再区分替代提供者、实例和内部部件 |
| 正交仅靠分别陈述/不借词判断 | 共享词汇不等于职责耦合，依赖存在不等于维度不独立 | capabilities 提供责任、变化隔离、显式交互和独立演化判据 |
| 队列例子先枚举受影响轴 | 示范了旧主线；只给 Q 时对已有呈现责任的判断也不充分 | 明确教学输入 Q/V 两项契约，按要求检查组合覆盖，消费配置不新增维度 |
| 例子主要说明无需新插件或动态提供者变化 | 尚未展示正向的新维度生成 | 新增 delivery-growth，从发送/存储的承载缺口推导可靠投递插件 |
| “投影”混指三个关系 | 容易把事实读面、能力承载和 Cordis 实现视为同一步 | 概念与 decompose 区分对象；关系表明确“读面投影” |

## 关联页处置

- SKILL：重写心智与路由，保留渐进披露、任务终点和简短 taste。
- decompose：S2 为现有能力覆盖，S3 为剩余责任与演化；从零与上下文缺失分别处理。
- concepts / paradigm / capabilities：定义能力维度、能力基及覆盖，明确正交性与插件映射。
- project：增加按演化结果确定插件变化的表，新增维度落实独立插件边界；纯计算能力不强造耐久状态。
- intake / define：不从需求名称预设新增，沿覆盖记录展开性质并允许反例反馈。
- handoff / workspace-context：反查新增理由，接受后更新能力地图与精确采用关系，候选/实现/证据分开。
- design-decisions：能力边界选择引用未覆盖责任与扩展不合适的依据。
- topics / contract-description / lifecycle：路由及“维度”措辞调整，身份、权限、披露、预算等留为按需检查项。
- queue-view：改为两个已知能力的组合示例；原主体/授权观察范围仍保留。
- delivery-growth：新增正向演化示例，边界推理与协议/证据未完成范围分别陈述。

其余运行时、状态、身份、规格、来源核对和证明专题仍适用，不因主线改变重写有效保证。
特别保留组合前提、完整动作链、强制证明门槛、语义/实现/资料缺口的区别及规格冻结规则。

## 方法解释与理论关系

前序讨论查阅过 Parnas 的模块分解论文与 Batory 的 FOSD 介绍：
前者将模块看作责任分配，以信息隐藏隔离设计变化；后者把功能增量及其组合作为设计对象。
本轮的覆盖分析、剩余责任判断与插件投影是结合用户目标所作的方法设计，
没有将“能力基”声称为线性空间，也没有声称存在自动求出唯一最小能力集合的算法。

参考来源：

- [Parnas，On the Criteria To Be Used in Decomposing Systems into Modules](https://www.cs.lafayette.edu/~gexia/cs301/resources/parnas.html)
- [Batory，FOSD / AHEAD 介绍](https://www.cs.utexas.edu/~schwartz/Started.html)
- [Cordis Primer，c291e7961a515f6d7af9304e7fd1d257929aef26](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/docs/cordis-primer.md)

这些来源支持理解责任分解、组合与运行时机制；当前方法中的正交性判断及维度到插件边界的要求来自本次设计目标。
不从 Cordis 的机制存在推断任意组合正确、可交换或外部效果可逆。

## 核对范围

独立评审应检查：现有能力优先、组合覆盖推理、合理扩展与新增的分界、独立插件映射、
资料/实现/语义缺口及未修改保证之间是否一致。行为试用采用独立原始案例检查这些选择，
不将本记录的预期答案交给试用者；实际结果记入[验证记录](validation.md)。

原来源与历史记录保留用于追溯，前轮完整性结论不能证明本次新心智已经被验证。
