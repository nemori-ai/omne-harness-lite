# 提案候选准入的增量

用户明确要求正式 proposal topic 至少包含三个 candidates。本轮将其落实到
[设计选择](../canonical/references/design-decisions.md#用能改变选择的依据比较)、
[proposals 家族](../../../../design/record/proposals/README.md#主题准入与候选比较)及本地模板包，
并修正投影页和工作区 README 中“不要求候选数量”的旧表述。

候选应回答同一选择对象，具有实质不同的责任或机制、兑现依据、代价与未知；不以改名、
参数微调或占位符凑数。可保留有事实依据的被排除路径；不足三个时仍可研究或分析单个候选，
尚不能作为满足准入的正式 topic。已有有效路径的普通局部工作无需另造提案。

这是用户采用的工作区方法要求，不宣称来自 DSH 或其他项目的官方制度。
外部 harness 调研是维护本 skill 的证据，保存在 [.design/research](research/harness-design-decisions/README.md)；
它不进入运行时 canonical，也不能自行建立产品规则。

入口重写同时发现 decisions family 的“已接受选择”归属与“未接受草稿直接建 topic”冲突，
已先修 family 和模板：文案草稿留在来源提案，实际接受后才形成 decisions 主题。
本次没有新建实际提案/决定或接受任何产品方案。
