# 家族本地的 topic 模板信息包

状态：草稿，2026-09-15。范围：知识家族模板、目录入口与 handbook 的落盘导航。

## 用户要求与设计依据

用户在模板起草中明确：模板应位于 `design/{family}/.templates/`，agent 进入家族即可发现；
每个 family 的 topic 是一个子目录信息包，不是一份通用 Markdown 文件。
本轮据此替换先前未交付的集中模板草稿，不迁移原产品内容或切换根宿主入口。

## 形状与知识归属

- family README 导航实际主题与模板；topic README 是局部上下文地图，正文按需展开。
- requirements 分条款与来源/确认变化；research 分推断与实际证据；proposals 分设计、取舍与评审。
- decisions 保存实际接受范围；architecture 分能力与组合视图，投影精确契约及接受依据。
- spec 有 data/capability/composition 三种包，分可变入口、待命名版本规范与版本外验证记录。
- providers/assemblies 分长期设计与真实证据；migrations 分过渡设计与执行记录。
- 任务级交付计划继续归 tmp/，方法仍由 handbook 的 delivery-planning 提供，不新建长期知识家族。

这些包不是固定文件数或强制全链流水线；可裁剪，入口必须同步，影响结论的未知保留。
模板占位不计作实际能力/规格；不建立机器登记格式、空 catalog、形式任务或伪接受状态。

## 与当前能力心智的对应

提案正文拥有现有能力及组合的覆盖分析、语义/实现/资料缺口、剩余责任与演化理由。
新增维度说明合理组合/扩展为何不足，并投影独立插件；规格与提供者分别拥有承诺与兑现。
架构包在实际接受后更新能力及组合视图，使后续需求可以从新能力基继续推理。
不因新增一个插件便认为整体保证已闭合，证据前提与受阻消费在相关拥有者显式保留。

## 分发与迁移边界

模板唯一源在工作区 design 各家族内，原集中单文件草稿不再作为入口。
handbook 内新增导航保留方法自包含：单独分发 skill 没有模板时仍能按产出要求设计，
不得自动借用承载仓库的模板或规则。编译产物仍只包含 canonical，不复制各 family 模板。

包内职责与渐进导航成立，能力覆盖/剩余责任/演化/独立插件主线完整，模板和候选不冒充已接受保证，
规格可变信息与冻结规范分开，没有强制全链或额外审批。

本轮是模板组织与导航检查，没有重新执行行为试用、产品实现、形式验证或真实宿主加载。
前轮行为证据保留其原输入与范围，不据此声称这些模板在所有设计任务上已经验证。
交付正文直接位于各 family 的 .templates/；本轮开始时的输入/生成物快照及已取代的集中草稿仅用于历史追溯。

### 后续：规格包的可选形式化工件

这是工件选择与填写引导，未创建没有产品语义的可运行模型或运行结果。
