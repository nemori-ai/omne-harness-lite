# 工具执行阶段一验收场景

本页登记 Tool 阶段一的有限持续验证场景。产品规则及当前状态归[产品入口](README.md)；本页不改变产品采用状态，也不以已登记场景声称新增行为已实现。

| S4   | 会话里的模型对一条长命令要求发起即后台，工具作者许可这次调用的后台。 | 前台位置当场得到说明原因的占位，这一轮不等它就结束。命令只启动一次，账目不因转后台多出一份。命令结束后，结局作为一条来源为后台工具执行、带命令输出的提醒回到会话，并开始新的一轮。 | [TL-J03](design.md#tl-j03)的发起即后台，[一次工作可以等待、恢复和并行调用](../sessions-and-work/design.md#一次工作可以等待恢复和并行调用)的后台结果投递。技术保证归[Tool SPEC](../../../../packages/tool/SPEC.md#前后台计时与控制)与[会话 SPEC](../../../../packages/session/SPEC.md)。 |
| S5   | 同一会话里有两条后台命令，用户按项停止其中一条并写明原因。 | 停止的回执先是受理，不写成已停；之后读到停止已证实、结局为被中断。会话里有一条提醒说明用户停了哪一项及原因，被停的那条结束后结局也回到会话并写明被用户停过；这两条都没有单独开始新的一轮。另一条照常完成、回到会话并开始新的一轮。 | [TL-J07](design.md#tl-j07)的单次控制，区分请求、受理与真实停止；[控制、取消、恢复与外部效果](design.md#控制取消恢复与外部效果)的停止回到会话。 |
| S6   | 一条前台长命令正在运行，用户把它转到后台。 | 前台位置当场得到说明原因的占位，这一轮可以结束。命令没有重启。它出现在本会话的后台调用里，带短号、意图与动作。 | [TL-J03](design.md#tl-j03)的用户操作转后台。 |
| S7   | 一条许可后台的长命令没有要求后台，运行超过转后台的阈值。 | 到点自动转后台，占位写明原因是阈值。命令只启动一次。结局之后照常回到会话。 | [TL-J03](design.md#tl-j03)的阈值转后台；阈值取自设置。 |
| S8   | 一条不许可后台的调用运行到前台上限。 | 前台得到被中断的结果，原因是前台超时。执行真实结束后，真实结果另存，不改写前台已得到的结果。 | [前台和后台是等待与交付方式](design.md#前台和后台是等待与交付方式)的前台上限。 |
| S9   | Agent 在等一条许可后台的前台命令，用户插队一条消息。 | 命令转到后台并继续运行，占位写明因插队转后台。插队的消息由原来这一轮承接，这一轮没有被取消。 | [插队、取消工作和归档有不同影响范围](../sessions-and-work/design.md#插队取消工作和归档有不同影响范围)；[TL-J03](design.md#tl-j03)。 |
| S10   | Agent 在等一条不许可后台的前台调用，用户插队一条消息。 | 这次调用被请求中断，前台得到说明原因的结果。插队的消息由原来这一轮承接。 | [插队、取消工作和归档有不同影响范围](../sessions-and-work/design.md#插队取消工作和归档有不同影响范围)。 |
| S11   | Agent 在等模型回复，用户插队一条消息。 | 模型的这次回复被中断，已到达的内容保留，其中没有执行的动作不再执行。插队的消息由原来这一轮承接。 | [插队、取消工作和归档有不同影响范围](../sessions-and-work/design.md#插队取消工作和归档有不同影响范围)。 |
| S12   | 一条前台命令正在运行，用户取消这一轮。 | 这一轮当场记为被取消。前台命令被请求停止；取消的生效不等它真的停下。它真实结束后的结果照存，不复活这一轮。 | [TL-J07](design.md#tl-j07)的 Run 取消。 |
| S13   | 会话里有一条后台命令，用户取消正在进行的一轮。 | 后台命令不受影响，继续运行。它结束后结局照常回到会话，并开始新的一轮。 | [TL-J07](design.md#tl-j07)：后台不跟随 Run 取消。 |
| S14   | 会话里有一条后台命令，用户归档这个会话。 | 归档的反馈写明收起了这条后台命令，不写成已停。后台命令被请求撤回。它的结局照存、查得到，不回到会话，不开始新的一轮。会话出现在已归档的列表里，不出现在平常的列表里。 | [TL-J07](design.md#tl-j07)的归档；[插队、取消工作和归档有不同影响范围](../sessions-and-work/design.md#插队取消工作和归档有不同影响范围)。 |
| S15   | 会话里有两条后台命令，Agent 列出它们并中断其中一条。 | 列出的两项各有短号、意图、动作与状态。中断的答复是已请求，不是已停止。被中断的那条结束后，结局写明是 Agent 停的。会话里没有另外的停止提醒。 | [BkgToolCalls](../meta-capabilities/design.md#meta-background)；[TL-J07](design.md#tl-j07)。 |
| S16   | 一条后台命令在持续输出，Agent 读它的输出两次。 | 第一次读到已有输出的一段与续读的位置。第二次带上这个位置，只读到之后新增的内容。命令的最终结果、终局与账目不因读取改变。 | [BkgToolCalls](../meta-capabilities/design.md#meta-background)；[返回、过程与账目](design.md#返回过程与账目)的输出正文。 |

## 执行与范围

运行方式、具体装配与可执行场景见[Tool验收入口](../../../../packages/tool/tool/acceptance/README.md)。S4 到 S16 在发行装配上跑，见[发行验收](../../../../apps/harness-server/SPEC.md#发行验收)。执行文件使用 `// covers: PD-tool-execution S<N>` 引用本表。编号只定位场景，不创建新业务对象或公开接口。

验收使用构建后的公开入口、真实运行时和账本逻辑，以及单进程非耐久提供者。外部身份、资格、环境与宿主条件由受控装配提供。场景不证明生产授权、真实Agent或Session、持久化、跨进程或断电恢复。两个失败场景不会经历成功路径的全部步骤，不制造不存在的执行事实。

分页与Tools结果取回的教学核验同时遵循[公开接口](../../../../packages/tool/SPEC.md#总体架构)及现行Tools行为规格。模型消费方仅取得ToolResult和真实帮助，按其中的合法引用请求后续页。它不重做原工具，也不把测试消费者称为生产模型集成。本页不声明覆盖TL-J06的全部卸载、耐久保管和费用规则。

场景登记、作者自测、最终独立验收和交付接受分别记录。单次通过不表示Tool全部产品能力已实现。
