# 工具执行

状态：本页已定义的全部能力已纳入 `0.0.0 → 0.1.0` 交付承诺。技术接受、实现支持与交付验证分别核对。

## 产品需求描述

### 场景与范围

用户让 Agent 读取资料、运行命令或使用外部服务时，需要知道这项能力现在是否可用、实际做了什么、为何等待，以及能否叫停。工具作者需要说明调用条件和结果，让调用方不必猜测。程序也可以独立调用工具，不必创建 Session 或运行 Agent Loop。

本域负责工具定义的执行含义、一次调用的结果、真实执行与外部效果，以及这些事实的保管。资产拥有、设置求值、授权、环境供应和被调用领域的业务结果分别由其拥有者负责。工具入口能访问这些能力，但不能替它们宣布业务完成。

### 定义、已知能力与一次执行

Tool Definition 是工具在数据与治理层面的定义，可以与实现一起提供。已知能力表示调用方已经合法取得的工具身份和用法。Tool Execution 是一次逻辑工具调用，其真实执行有独立运行时；不可用替换件也属于同类别的 dummy tool execution。

知道工具存在、工具当前可用、这次动作获得授权，是不同判断。常驻工具直接呈现在模型面前，非常驻工具经发现、查看用法和调用入口取得。常驻与否不改变动作空间，也不放宽执行许可。常驻标记归装配引用，Agent Definition 的明确标记优先于 Plugin 标记。元能力的必需入口沿其自身规则保留。

当前来源被撤权、卸载或失去依赖时，先按共同规则求值同标识的合法候选；仍有可用实现就更新选择。只有求值后没有可用实现，已知工具才保留最近合法取得的身份与参数形状，并说明不可用原因。调用替换件无论收到何种参数，都得到带原因的正常不可用结果，原工具不会物理执行。系统不能为从未合法取得的工具编造定义，也不能借记忆读取撤权后的新说明或内容。

不可用结果仍有原调用、原用途和结果消费位置。恢复后可以分辨它的结果是否已经取得和处理，不能因重建 Agent 再次调用。记账只能记录实际发生的处理，不能虚构原工具启动、耗时、效果或用量。

### 工具作者必须说明什么

工具采用单函数或多命令形态。单函数只接受参数；多命令先选择本工具的一项命令，再交该命令的参数。一份完整定义必须说明工具做什么、每个参数是什么。多命令形态还必须给每项命令一行说明。

多命令工具在模型面前使用紧凑命令清单。作者可以提供全部命令的完整参数，也可以只提供清单。完整参数供系统校验和详细用法查询，不展开到常驻呈现中。没有参数声明时，工具自身仍须判断交来的参数。可选的 help 必须与统一用法查询一致。Agent 对不熟的命令须先取得用法。

工具可以声明以下执行条件和许可。

| 声明 | 未声明的含义 |
| --- | --- |
| 必需的外部服务 | 不以该服务为必需前提。 |
| 附件存储 | 不产出需要该存储承接的附件。 |
| 目标环境及设施 | 没有特殊环境要求，实际直接依赖仍须如实声明。 |
| 调用参数需要的模态 | 只需要文本。 |
| 结果包含的模态 | 只有文本。 |
| 是否允许可编程调用 `programmable` | 不支持 Agent 通过脚本组合或编排该工具的调用。 |
| 是否允许后台，以及自动转后台阈值 | 未许可后台时，不能采用后台方式。阈值不能产生许可。 |

必需依赖按抽象能力名声明，全部成立才可用。可选资源在实际使用时探测，不因为可能用到就列为必需。声明必须与真实使用一致。附件存储存在之外，实际消费者还须有取回能力和读取资格。

模型路径发起前，参数所需模态由当前有效模型的输出能力满足；结果所含模态由模型输入能力或合法转换满足。任一端不能满足时，工具原位呈现不可用，不先执行再等待已知不能采用的结果。模型、转换能力或工具声明改变时重新求值，有合法转换不能仅因模型不直接接受原模态而禁用工具。实际返回仍须检查真实可读内容，独立调用按自身消费者判断，不强制绑定模型。

目标环境和转后台阈值由定义声明设置的形状与默认值。目标环境属于落点与身份，工作区不能配值。配值资格、组织上界和锁定沿共同设置规则成立，不得靠改值绕过后台许可、授权或隔离。

工具定义须明确声明装载或装配时允许从配置赋值的参数，未声明项不能由配置注入。作者构造配置与本次调用参数、服务依赖分开，配置不能提升后台或可编程调用许可。合法值的来源、覆盖和治理上界沿共同设置规则，秘密不进入公开定义或模型描述。

转后台阈值、前台上限和工具并发上限属于偏好，沿共同设置规则求值。后台许可是作者的许可，用户配值不能把未许可工具变成可后台工具。发起前求得本次合法值，发起后固定采用值，后续更新只影响后续调用。无效或无法核实的配置不授权降级执行，不能据此猜出新的默认值。

### 可编程调用许可

执行编排程序的入口见 [Code() 产品设计](../meta-capabilities/design.md#meta-code)。本节拥有目标工具的调用方式许可；Code 的产品行为、交付阶段与实现状态由元能力正文分别维护。

Agent 可以编写脚本，按顺序、条件或并行组合工具调用。工具作者通过 `programmable` 声明是否允许自己的工具参与这种编排。只有显式 `true` 表示允许，省略或 `false` 都表示不支持。该声明作用于整个工具，多命令工具的所有命令共同受它约束。

这是作者对调用方式的许可。常驻呈现、后台许可、工具已经装载、人工批准或用户设置，都不能把未许可工具变成可编程工具。允许可编程调用也不授予动作权限，每个实际调用仍须满足当前授权、参数、依赖、环境及适用的人工判断。

脚本的可调用工具集合只包含明确许可且当前合法可用的工具。发现和用法说明须让调用方知道该限制；即使脚本已记住名称，或通过通用工具入口间接调用，系统仍须在发起前检查目标工具。拒绝时说明不支持这种调用方式，不执行目标工具。MCP 来源和元能力入口不自动取得可编程调用许可。

直接模型工具调用以及独立程序通过 SDK 消费工具，不因本项未声明而被禁止。Agent 脚本经 SDK 调用仍属于脚本编排，不能借入口名称避开限制。本项约束 Harness 提供的工具调用通路；脚本运行环境对原生命令、文件及网络的限制仍归执行环境与授权。

声明更新影响后续调用。排队中尚未启动的脚本调用须复核当前许可，不能借旧清单继续启动。已经启动的执行保持原采用，停止仍走原控制规则。脚本可编排工具不代表支持脚本自动重试、失败回滚或新的等待与恢复保证。

### 发起前与发起后

装配、每次 attempt 开始以及必需提供者变化时，重新判断可用性。一次具体发起仍须满足当前主体资格、授权、工作状态、工具定义、实现、参数与环境条件。排队或已经通过人工判断，都不等于永久许可。

人工批准只覆盖人所看到的明确动作，或其明确批准的整批动作。单卡不能扩成整个 Run 的任意动作许可。全局授权沿租户权限设置，在当前组织上界和设置资格内生效。工作区不能提权。无关 reload 不要求重复批准，实际影响操作、参数、实现或授权依据的变化须重新核对，不能盲用旧批准。

尚未发起的模型建议遇到定义调用约定或实现绑定变化时，不能暗改参数后执行，须说明原因并交回合法调用方判断。单纯说明文字变化不自动表示调用约定变化，但系统也不保证任意 schema 更新兼容旧建议。

发起后固定本次匹配的定义、实现、参数、设置、允许读取的 Context、准入依据、工作区、环境及资源入口。后续更新作用于后续调用，不能给已发调用换函数、改参数、搬环境或重发。准入通过但环境无法满足时，不执行且说明原因，不能退回更宽松环境或宿主机。

### 前台和后台是等待与交付方式

前台表示当前步骤须等这次调用的结果才能继续。后台表示当前步骤可以继续，原执行随后交付最终结果。转后台只改变这一等待关系，仍是同一次 Tool Execution；调用身份、执行事实、外部效果、全文和费用责任保持。

工具自身没有两种前后台物理寿命。Agent 退出、被替换或释放最后一个句柄，均不取消工具。后台也不要求新建线程或进程。工具作者声明是否支持后台这种使用方式，缺省不支持。

允许后台的工具可以由适用阈值、用户操作或插队转后台。调用入口明确支持发起时就后台的，前台位置当场得到说明原因的转后台占位。未许可后台的工具不能通过这些路径绕过声明。一次执行已经转后台后，不会再转一次。

前台上限只计算在前台实际运行的时间，不计算内部等待时间，转后台后不继续计算。达到上限时，允许后台则转后台，否则中断，原因是前台超时。没有定义或合法配值时，没有该项限制。转后台阈值与前台上限分别表达，前者不能改变未许可工具。

同一 Session 内同一工具的并发上限合计前台和后台执行。超出的调用按发起先后排队，不能冒充执行失败。转后台不释放其并发执行名额。独立调用的并发范围由实际调用契约明确，不为套用会话限额虚构 Session。

### 工具内部等待与人的答复

内部等待表示工具暂停执行，等待明确形状的外部输入。输入可以来自人、系统或其他 Agent。它与调用方的前后台关系是不同维度，本设计的需答复等待边界仅允许执行在前台等待。工具内部等待也不同于 Run 的扩展等待，二者不能互相替代。

Ask 等人的等待没有超时或默认答案，本设计不开放其转后台。系统不能因前台时限、物理资源退出或查询暂时不可用而替人作答，或作废仍有效的原等待。当前会话继续可靠受理普通输入，其他会话可以运行，普通消息不自动回答原卡片。

人的答复回原等待，答复者须有当前资格，同一卡片只产生一次有效决定。卡片和有效决定归 HITL，Tool 拥有原等待及接续后果；涉及动作授权的解释归身份与授权。“不回答”是合法答复，表示没有答案，不是批准。合法控制可以解除等待；原等待执行确定终局后，卡片作废，不补答案。

确实占用资源的其他等待可以由其专有契约设置时限，到期按等不到应答处理。这个规则不能用于给 Ask 增加超时。具体资源等待时限仍待相应拥有者设计。

### 返回、过程与账目

调用方须能区分完成、失败、不可用、转后台、被中断、等不到应答。它们以带原因的正常工具返回表达。转后台表示前台等待结束，不是执行终局，原执行还须有一次最终收场。本设计的后台不等待答复，最终收场为完成、失败或被中断。

完整工具参数已经收齐但解析不了时，原工具不执行，返回具体失败。参数还在流中增长时不解析、不执行。明确叫停或前台上限导致的中断不同于失败，系统不能自动重试中断动作。

工具作者可以普通函数返回，其整个返回值作为文本；也可以返回 ToolResult，分别提供面向消费者的内容、可选卸载原文和附件地址。普通返回统一转换为 ToolResult。只有结构化返回支持卸载原文和附件，精确字段由后续公开契约拥有。

工具可以在执行中发过程帧，给人观察，不进入模型上下文。过程帧不是最终结果，也不能证明动作成功。工具不必预先声明是否发帧，未发帧是正常情况。发不出去不单独使工具失败。各块打开时固定追加片段或整体替换方式，封块交付完整内容，重连先读当前快照再接增量。节流可以合并相邻增量，裁剪须说明多少、为何裁剪。

每次调用保存实际时长、资源用量及适用费用，执行账不直接放入模型上下文。原调用费用不因重通知、换 attempt 或结果消费而重计；真正的新调用可以产生新费用。未知费用不是零，取消和归档不抹去真实费用。租户可查自身账目，组织管理员可查本组织所有租户明细，这不授予调用正文、附件、凭据或其他秘密的读取资格。

### 结果保管、卸载与模型采用

Tool 先可靠保管实际结果，再交回原用途和消费位置。消费者可先可靠接下所需内容及原位置，再进行执行后扩展、卸载及消息准入；也可在 Tool 继续保管时先完成处理，可靠保存必要完成事实后解除对应待交付关系。通知到达、页面展示或开始处理，都不解除结果交付责任。交接前后均须有人承担原结果和接续责任，工具全文保留义务不随交付关系解除而结束。

工具自己要求卸载时，用作者构建的摘要。系统发现单条工具消息超过适用限额时，兜底保留首尾作机械截断，不编造语义摘要。占位须包含够用内容、原文大小和取回方式，让调用方分清“已卸载”和“没有结果”。原文仍保存，原附件地址保留。

会话历史一开始追加的就是占位，后续分页取回是新调用和新返回，不回写旧占位，不重复原工具效果。工具全文没有已采用的到期删除规则，不能因消费、模型 ACK、归档、Run 结束或压缩删除全文，使历史引用失效。读取仍核对当前资格。

工具作者决定多模态内容如何交给 agent。放在 ToolResult 附件区的内容，转成模型消息时只以文本告知附件地址，不自动解析成二进制或多模态块；agent 自行决定是否另行合法读取。需要模型在采用结果时直接感知的内容，由作者直接放进 ToolResult 消息内容区，以多模态内容块的 ref 返回，不必同时登记附件。模型治理领域只在真正请求模型时加载这些内容 ref 的二进制。两种方式都保管原件，转换不覆盖原结果；只给人看的块不缩小模型候选，已有 transcript 沿原表示规则处理。独立调用按自身消费者处理，不强制有模型。

模型相容性按实际要直接感知的内容判断，附件的媒体类型不增加当前模型的输入模态要求。附件存储、消费者的合法取回能力和地址披露资格仍分别检查，知道地址不等于获得读取授权。

工具结果被消息准入或模态转换否决时，保留真实原结果，不重跑工具制造另一份结果。消费契约明确指定结果回到仍有效、未终结 Run 时，否决使该 Run 失败。后台、Run 外或原 Run 已终态的结果不改原终态、不自动归入后继 Run，也不创建 Run；业务已取消的结果不重新取得入队资格。尚未规定的旁路消费后果归实际消费拥有者，不以工具执行成功替代消息采用成功。

### 控制、取消、恢复与外部效果

用户可以单独中断一次工具，不要求模型或整个 Run 一起停止。Agent 仅按既有后台控制范围控制自己发起的后台执行。控制须说明目标、发起者与原因，分别显示已请求、已受理和实际结果。请求停止不表示物理执行已经停止，工具不能通用回滚外部效果。

Run 取消保存意图、撤销新推进资格，并请求停止其前台关联工具。后台和无关调用不自动取消。Session 归档在业务上取消该会话全部原未完成调用并解除等待，不等待物理全停；控制继续向前台和后台传播。迟到真实结果、效果和成本沿原调用保存，不复活工作。撤销归档不自动重启旧调用。

只失去 Agent 或句柄时，合法接手者认回原执行，继续等待或从已保存结果接续。查询暂时不可用时保留未知，不认定工具丢失，不重发。工具自身确认失去连续性时，以失败和异常中断原因收束，系统不自动重放。外部效果是否发生另行判断，未知不能写成没有发生。合法调用方可以核查、补偿或发起新动作，但不能把恢复解释为已保证效果可逆。

已确认保存的原调用、结果、答复、交接和账目，须经受普通进程崩溃、操作系统崩溃和断电。存储介质可读取和所声明部署条件是前提，临时地址不足以保管已确认的图片或文件。物理损毁后的可恢复范围与安全开放政策另待明确，不能发明灾后管理员或用旧备份复活撤销资格。

### 非目标与具体未覆盖

本域不选择执行引擎、存储、线程、数据库、公开类型或统一性能数值，也不创建独立调用所不需要的 Session、Run 或 attempt。已有关联的调用保留原关联。Skill 方法读取和脚本执行、MCP 认证刷新与动作调用，分别沿其拥有者的契约组合。凭据和获准 Context 只给实际获准消费者，可读不自动可向外部工具或 MCP 发送。

本域提供工具定义及操作的注册和合法装载机制。创作产物也沿同一机制进入可用候选，资产的创作、持有、发布及候选选择仍归其拥有者。Agent 创建工具仍须授权。产出按提交位置归工作区或租户，Agent 不直接产出组织资产，也不代用户提升。显式合法增量装载后才可能当场使用，单纯写文件不代表装载。同标识创作入口的冲突结果留未来创作设计，不默认覆盖。

引用式结果的共享契约迁移、已展示在途内容的故障保留衔接，以及精确控制、发起、持久交接和资源政策，见[问题登记](design.md#未决问题与待定事项)。这些缺项只限制相关设计和验证，不降低已确定的结果保留、授权、耐久与独立寿命保证。

### 关键用户旅程

下列 TL-J01 至 TL-J07 仅为文档定位号，不是新业务对象或公开接口。原精确规则由前述需求小节拥有；旅程说明这些规则怎样共同满足用户目标。工具成功、消息采用、业务完成和真实效果分别判断。

<a id="tl-j01"></a>
#### TL-J01 让调用方取得一项可理解的合法工具能力

工具作者要提供可用的动作，Agent 或程序消费者要先理解工具和命令。前提是定义、来源与装载资格合法。作者提供单函数说明，或提供紧凑多命令清单及相应参数说明，并声明真实依赖、环境、模态、后台许可及可编程调用许可。脚本可调用集合按[可编程调用许可](#可编程调用许可)筛选，直接调用入口不因这项许可缺省而删除工具。模型看到的工具描述由定义中的描述和可编程调用许可共同表达，未来可补其他字段。供应商请求格式不得改变工具说明及可编程调用许可的含义。装配按常驻引用呈现工具，调用方通过发现和详细用法入口了解非常驻或不熟命令。两种呈现方式均不扩大动作权限。

来源撤权、卸载或依赖变化时，先求值同标识合法候选。没有可用候选时，已知工具保留最近合法身份与形状，用户能看见具体不可用原因。未曾合法取得的工具不出现猜造定义，撤权后也不读取新的未授权说明。恢复提供者后仍须重新求值治理与依赖，不能无条件恢复可用。Agent 创作仍经授权，提交归工作区或租户，用户提升与显式合法装载另由各拥有者负责；文件写入不表示能当场调用，创作冲突不默认覆盖。

本路径不执行原工具，因此停止执行和执行失败归 TL-J02、TL-J07；合法卸载与撤权影响后续选择，已发调用保持原采用。能力：CAP-TL01、CAP-TL02、CAP-TL03。协作与异常：[定义及动态可用性](../../../../packages/tool/tool-contract/docs/flows.md#tl-f01)。

<a id="tl-j02"></a>
#### TL-J02 发起一个真实动作，或取得已知不可用的逻辑结果

Agent 或独立程序希望读资料、执行命令或调用外部服务。调用方取得合法定义后交完整参数、原用途、消费与控制责任；纯函数的独立使用不需要 Session，访问托管资源时由实际集成方兑现身份、授权、环境和保管责任。Skill 方法读取不授权脚本，MCP 连接或认证刷新不代替动作准入。Agent 脚本的每个目标调用还须通过可编程调用许可检查，不能将批准脚本本身扩成对其全部子调用的许可。

已知不可用的替换件对任何参数正常返回原因，形成原逻辑调用的不可用结果，不启动原工具、不虚构原工具资源和效果。可用工具只有在参数收齐并解析成功、当前准入成立、合法环境准备完毕和排队后复核通过时才实际发起。整批动作的判断尚未齐备，已获批准的一部分也不先执行；人工决定绑定原操作和生效参数，解释与复核由身份和发起协调者负责。

完整参数错误返回失败，半截参数不解析。明确禁止、旧批准失配或推进资格撤销阻止发起；环境无法满足时说明原因，不退到宿主机。排队表示尚未启动，不是假失败，队列取消沿成员操作协议处理。发起后的定义、实现、参数、设置、Context、环境、资源入口和身份固定，reload 不换执行或重发。恢复按原调用核实已启动、已得结果或待交付状态，不因 Agent 重建重复动作；停止与提交未知见 TL-J07。

能力：CAP-TL02、CAP-TL03、CAP-TL04、CAP-TL07、CAP-TL11。协作与异常：[发起与逻辑结果](../../../../packages/tool/tool-contract/docs/flows.md#tl-f02)。

<a id="tl-j03"></a>
#### TL-J03 等待同一工具，或在许可内先继续当前步骤

用户或调用方已经有一次合法工具执行，希望决定当前步骤是否继续等待。前台依赖原结果，后台解除这项等待，原执行以后交最终结果。工具作者须明确许可后台，阈值、用户操作和插队均不能创造许可。支持发起时后台的入口也核对许可，并在原前台位置交说明原因的占位。

转后台仅单向改变等待及交付关系，同一执行不重建、不换环境或身份，已经在后台不能再次转换。前台上限只累计前台实际运行时间，内部等待不计。达到上限后，有后台许可则转后台，没有许可则请求中断并说明前台超时；请求不证明物理已停，中断不自动重试。阈值、上限和并发按合法设置采用，无默认与合法值时不添加限制。

会话中同工具的前后台与内部等待共同占用尚在执行的名额，超额按发起顺序排队。转后台不释放仍运行的名额。独立消费者使用自身明确范围，不造 Session。后台最终交完成、失败或被中断，保留原执行与工作关联，不复活原 Run。Tool 只交回原消费方，不自行创建 Run；会话未归档且结果仍有合法后续投递资格时，Session 可按准入和工作规则交当前未终结 Run 或形成后继 Run，见[会话工作治理](../sessions-and-work/design.md#一次工作可以等待恢复和并行调用)。归档或撤销投递资格后，迟到结果与账目仍真实保存，但不能重新取得任务资格；通知到达本身不授予后继工作。断线或 Agent 换代认回原关系，不重发原工具。

能力：CAP-TL04、CAP-TL05、CAP-TL10、CAP-TL11。协作与异常：[等待关系转换](../../../../packages/tool/tool-contract/docs/flows.md#tl-f03)。

<a id="tl-j04"></a>
#### TL-J04 在原工具内部等待点取得一次有效答复

工具执行需要明确形状的外部输入，答复者希望让原执行继续。前提是原等待仍有效，答复者有当前资格。本设计仅允许需答复执行在前台等待，内部等待不等于调用方的前台等待，也不等于 Run 扩展等待。工具把人答复需求交给 HITL，卡片出卡、答复成立和原等待处理分别发生；通知或展示不表示工具已经继续。

有效答复回原等待，同一卡片只产生一次有效决定。人选择“不回答”时，工具取得没有答案的合法答复，不把它解释为批准。普通消息仍可靠受理，但不自动回答卡片；其他会话可以运行。Ask 无超时、默认答案或转后台，前台上限和物理等待资源退出不能替人答复。

失权、重复或失效卡片的答复不能建立新的有效决定或重复后续效果。合法控制、业务取消或原执行确定终局按其原规则使等待和卡片失效，不补答案；仅查询失败或 Agent 退出不作废有效等待。恢复者认回原等待、已成立决定和处理位置，不重新出一份独立决定。其他确实占资源的等待只按专有契约处理等不到应答，不能给 Ask 套统一期限。

能力：CAP-TL06、CAP-TL10、CAP-TL11。协作与异常：[内部等待与 HITL](../../../../packages/tool/tool-contract/docs/flows.md#tl-f04)。

<a id="tl-j05"></a>
#### TL-J05 观察执行过程并在原位置采用真实结果

用户观察进行中的工具，原消费者要取得最后结果。工具可选发送过程帧，仅给人观察。开块固定追加或整体替换方式，重连先取当前快照再接增量，封块交完整内容；节流合并和裁剪需可解释。没有帧正常，观察发送失败不单独令工具失败，过程消息、最终收场和执行账各有含义。

工具普通返回统一成为 ToolResult，结构化返回可以带卸载原文和附件。消费者先可靠保管原结果及接续依据，再进行执行后扩展和消息准入；也可先完成处理并可靠保存必要完成事实，随后按工具协议解除对应待交付关系。读到、展示或通知均不足以解除责任，保存失败和提交未知保留原责任并对账。

会话模型路径核对真实可读内容与模型或合法转换，转换追加派生表示，原结果不改。消息否决或转换失败不重跑工具、不丢真实结果；只有消费契约指定回到仍有效且未终结 Run 时才使该 Run 失败，其他旁路后果归原消费者，不能改旧终态或默认创建后继 Run。中断和故障保留已交付过程与真实收场，已展示在途内容的保存协议及故障验证责任沿 TOOL-M04；内容 ref 与附件地址按上述规则分流，MODEL-E01 跟踪技术迁移及验证。换消费者回原消费位置接续，不以重连或换 attempt 重做效果。

能力：CAP-TL07、CAP-TL08、CAP-TL09、CAP-TL11。协作与异常：[观察、收场与采用](../../../../packages/tool/tool-contract/docs/flows.md#tl-f05)。

<a id="tl-j06"></a>
#### TL-J06 卸载大结果，后来取回全文并核对真实成本

原消费者需要在消息限额内保留可用内容，用户后来仍要取回完整结果和查询费用。前提是内容或可恢复引用、原关联及附件达到耐久和保留条件。作者提供卸载原文时采用作者摘要，单条超限的兜底只保首尾并说明机械截断。占位说明够用内容、原大小和取回方式，历史首次追加即为占位。

取回按当前资格发起新查询或分页调用，产生新的返回，不改旧占位、不重做原效果。存储失败不能留下声称可取回的空占位；地址失效、读取暂时不可用和对象不存在分别报告。读取被撤权可以拒绝读者，不能解除内容保管责任。消费、Model ACK、Run 结束、归档和压缩都不授权删除工具全文，原附件地址保留；恢复后原关联仍能定位内容。

执行账记录实际时长、用量和费用，未知费用保持未知，真实新取回调用可以有新成本，原调用不因通知、换 attempt 或读取重计。取消后真实费用继续归原调用。租户可查自己、组织管理员可查本组织租户账目，但账目资格不授正文、附件或秘密读取。无 Session 调用沿真实归属记账，不创建 Run；费率提供者采用及分页、保管协议的接受与验证沿 TOOL-M03。

能力：CAP-TL07、CAP-TL09、CAP-TL11、CAP-TL12。协作与异常：[卸载、取回与账目](../../../../packages/tool/tool-contract/docs/flows.md#tl-f06)。

<a id="tl-j07"></a>
#### TL-J07 控制一次调用，并在取消或故障后核实原执行

用户希望单独停止工具，或者工作治理已取消 Run、归档 Session，合法接手者要辨认哪些事实仍待处理。控制明确原目标、主体与原因，分别显示请求、受理和实际结果。单次停止不要求模型或整个 Run 一起结束；Agent 只沿既有范围控制自己发起的后台执行，不从句柄扩大权限。

Run 取消撤销新推进资格并请求停止前台关联工具，后台和无关调用不自动跟随。Session 归档在业务上取消全部原未完成调用并解除等待，控制传播到前后台，不等待物理全停。真实结果、效果和成本可能后来到达，沿原调用追加保存，不复活 Run、旧等待或入队资格。撤销归档不重启旧调用，资源释放不证明外部效果可逆。

接手者查询原调用：仍运行则认回句柄，已收场则取原结果，已交接则从消费者保存位置继续。查询暂时不可用保持未知、不重发。只有工具自身可靠确认连续性丢失，才以失败和异常中断收束，不自动重放。外部效果为已发生、已知未发生或未知，失败不证明没有效果；核查、补偿和新动作由当前合法调用方另行判断和记录。

原调用、答复、控制、结果、交接和账目已确认的保存须承受进程崩溃、OS 崩溃和断电，临时附件地址不足以兑现。存储不可用限制依赖保存的新动作，但原执行保管及对账责任继续。介质损毁的恢复资格另待明确，不造灾后管理员。控制、连续性、围栏与交接的技术候选及提供者验证沿 TOOL-M02、TOOL-M03。

能力：CAP-TL03、CAP-TL06、CAP-TL09、CAP-TL10、CAP-TL11、CAP-TL12。协作与异常：[控制与恢复](../../../../packages/tool/tool-contract/docs/flows.md#tl-f07)。

## 未决问题与待定事项

本域全部已定义能力的阶段范围已明确，不再保留阶段选择缺项。以下技术设计与来源缺证由具名拥有者承接，须在相关能力交付前补齐；它们不降低阶段承诺，也不作为产品投票。

<a id="tool-e01"></a>
### TOOL-E01 引用式结果与附件地址的技术兑现

本项为技术义务。消息内容中的多模态引用供本次模型直接感知；附件只提供文本地址，让 agent 决定是否另行读取。共享值、消息校验、保管和模型发送须共同兑现此边界，不自动开放任意嵌套块。

责任由 Tool、共享内容与消息、Model 及 Context 拥有者承担。实际实现与验证尚未完成，不能声称已可用。持续义务见[技术原文](../../../../packages/model/model/docs/open-questions.md#model-e01)。

<a id="tool-m01"></a>
### TOOL-M01 公开形状与独立函数消费

本项为技术义务。两种定义形态和两种返回写法已定，但参数校验、名称规则、文本转换及公开接口已设计，运行实现尚未完成。

精确公开形状、对象模型和协议已接受，尚须实施，不改变现已确定的行为。责任由Tool定义与公开接口拥有者承担；具体义务、既定边界和实施条件见[技术原文](../../../../packages/tool/tool-contract/docs/architecture.md#tool-m01)。

<a id="tool-m02"></a>
### TOOL-M02 发起、队列、等待与控制的兑现协议

本项为技术义务。动作在排队或等批次卡片期间撤权，工具完成与停止竞争，原等待跨 Agent 退出仍须接续。

机制尚未兑现，已有准入、等待和控制责任完整保留。责任由Tool发起、队列、等待、控制协调者及HITL与提供者承担；具体义务、既定边界和实施条件见[技术原文](../../../../packages/tool/tool-contract/docs/architecture.md#tool-m02)。

<a id="tool-m03"></a>
### TOOL-M03 原结果可靠承接、全文与账目的精确协议

本项为技术义务。结果保存提交未知、消费者替换、卸载存储失败、历史原文取回和迟到账目同时存在。

未运行存储和消费组合；具体旁路后果仍归其拥有者，不填默认政策。责任由Tool、存储与原消费协调者承担；具体义务、既定边界和实施条件见[技术原文](../../../../packages/tool/tool-contract/docs/architecture.md#tool-m03)。

<a id="tool-m04"></a>
### TOOL-M04 已展示过程内容的故障保留衔接

本项为技术义务。已展示过程在工具自身连续性丢失后仍须可追溯；技术设计采用保存先于展示和独立持久读取，实际故障证据仍须补齐。

该故障边界尚不能声明已证明无丢失，其他结果耐久与控制规则继续。责任由流式、Tool、存储与交付面承担；具体义务、既定边界和实施条件见[技术原文](../../../../packages/tool/tool-contract/docs/architecture.md#tool-m04)。

<a id="tool-n01"></a>
### TOOL-N01 非目标与外域责任

本项是明确非目标或既有另域责任，不是待裁决产品选择。本域不增加后台人工等待、统一线程、同标识工具覆盖、Agent 组织资产提交或灾后恢复主体。

以下非目标与外域责任保持各自边界。

- 当前需答复执行仅前台，Ask 无超时。
- Agent 不能直接提交组织资产或代提升。
- 同标识创作入口另归未来创作设计。
- Q06/Q07 建议未采用，不能造灾后管理员。
- 不选引擎、后端、线程、数据库、统一数值或额度预算。

不作为本域未决阻断，也不授予相关能力。
