# 桌面应用

## 产品需求描述

一个人要用这套系统，需要一个能打开、能登录、能和 agent 对话的地方。桌面应用是给人用的第一个图形界面。它是一种[交付面](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-delivery-surface--交付面--delivery-surface)：把会话日志投影给人看，把人做的事送进受理。它自己不持有任何领域事实，屏幕上的每一条都来自服务端，人做的每一件事都是别处已经定义过的动作。

桌面应用有六部分：登录、会话管理、对话、资产、设置、用量。六部分之外的东西不在这个题目里。[开发模式](#开发模式)不是第七部分：它是一个开关，打开之后在这六部分的界面上起作用。用量那一部分的规则归[用量与花费](../usage-and-cost/design.md)，部署不开放它时应用里没有这一部分。

### 应用拥有什么，不拥有什么

应用拥有的事实只有五样：

- 窗口里有哪几部分，它们怎样排布。
- 登录证明放在哪。它只放在应用里人看不到、页面的代码也读不到的那一半。
- 连不上服务端时怎样告诉人。
- 界面长什么样：一套设计语言，六部分共用。agent 在屏幕上的形也属于这一样，见「Agent 在屏幕上的形」。
- 人对观感的选择：明暗主题与[字号档](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-size-tier--字号档--size-tier)。它们是[观感偏好](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-look-and-feel-preference--观感偏好--look-and-feel-preference)，只影响好不好看，存在本机。<!-- OD-2 -->

下面这些规则各有自己的拥有者，应用只把它们呈现出来，不重新定义，也不替服务端判断：

| 事实 | 拥有它的正文 |
| --- | --- |
| 怎样注册、登录、退出，登录什么时候失效 | [身份与授权](../identity-and-authorization/design.md#j-id01) |
| 会话怎样建立，输入怎样被接下，一轮怎样结束 | [会话与工作](../sessions-and-work/design.md#j-sw01) |
| 设置项有哪些值，谁能改，改了什么时候生效 | [资产与规则](../assets-and-rules/design.md#settings-and-permissions) |
| agent 的问题卡是什么，谁能答 | [人在回路](../human-intervention/design.md) |
| 模型的输出与工具的结果是什么 | [模型调用](../model-invocation/design.md)、[工具执行](../tool-execution/design.md) |

服务端是事实的权威。按钮能不能按、列表里有什么，都以服务端的答复为准。应用可以缓存显示用的内容，但不把缓存当成结果。

一个部署开放了哪个领域，应用里才出现它的那一部分。部署没有开放设置，应用里就没有设置这一部分，其余部分照常用。应用的代码里没有「如果有某个领域就怎样」的判断。

### 登录

没有登录时，应用只显示登录门。人第一次使用时注册并登录，之后直接登录。注册与登录成不成，按[身份与授权](../identity-and-authorization/design.md#j-id01)的规则，应用显示服务端答复的结果。

密码交出之后，表单立刻清空，应用不保留密码，也不把它写进任何日志。

登录成功后，应用显示人现在以哪个租户的身份在用。每一部分的每一次读与写都带着这个租户。

人可以随时退出，回复还在出的时候也可以。退出之后本机立刻回到登录门。服务端有没有注销这次登录，没有得到确认时，应用如实告诉人：本机已经退出，服务端那边不知道。

登录在使用当中失效时，例如被吊销，应用回到登录门，并说明是登录失效了，不是网络断了。

### 会话管理

登录之后，应用列出这个人在当前租户下的会话，新的在前。每个会话占一行：第一条输入的开头作标题，下面写最近一次活动离现在多久，例如「3 分钟前」；精确的时刻在提示里。<!-- OD-10 -->

人选一个会话进入，看到它的历史，接着聊。人也可以新建一个会话。建立的结果不知道时，应用如实显示，并能认回那一次建立，不重新建一个。

列表每次取自服务端。应用不另存一份会话清单。

### 对话

人在输入框里写一条消息发出去。消息有没有被接下，按[会话与工作](../sessions-and-work/design.md#j-sw02)的规则，应用显示它现在的状态：发送中、已经被接下、没有发出、不知道。不知道的那一条可以认回。

回复一边生成一边出现。除了文字，会话里别的内容各按自己的种类显示：模型的推理、工具的调用与它的结果、agent 提的问题卡、一轮的结束。应用不认识的种类显示成一个看得见的占位，不悄悄丢掉。读到哪些内容由服务端按每一块自己的标注给，显示成什么样是应用的事。

回复还在出的时候，人可以接着打字、接着发送，也可以取消这一轮。取消的结果以服务端的答复为准；取消中与取消了没有得到确认，应用分开显示。

一轮失败之后，会话停下来等人。这时应用要让人看到三样：

- 这一轮为什么失败，用一句人读得懂的话。
- 还有几条消息没有被处理。它们没有丢，下一轮会按先后一起带上。
- 接下来能做什么。两条路：再发一条新消息；或者按「重试」，让它带着没处理的消息接着做。

重试只在还有消息没处理时成立。没有的时候，应用提示人发一条新消息。

agent 用提问工具提出的问题，人在对话页里直接作答。

这个会话此刻所有在等人回答的问题，在输入框正上方摆成一列卡，左右切换，一次看一张。不论这些问题是 agent 一次问的几个，还是同时发了几次提问，人看到的样子都一样：上方一排题号，看得出一共几题、哪几题答了；每张卡上是问题、选项、一个随时能写字的文本框，和「不回答这一题」。人可以只写自己的话，不选任何选项。

每一题都选了、写了，或明确不回答，才能提交。提交只有一个按钮，一次交全部的题，每一题各自记下。有一题没记上（例如它刚在别处答了，或那次提问已经关掉），别的题照常记下，那一题写明原因，人填的东西还在。某一题结果不知道时照实说，可以认回，不重新提交。

等人回答的时候，输入框照样能发消息，但应用要说清楚：发的是一条排队的消息，不算回答。取消这一轮会把还没答的问题一起关掉，取消的按钮上要说出这个后果。

不论问题来自哪一个工具，卡的样子都一样：出卡的工具只交出问题与选项，卡怎样画归应用。卡头写清是谁在问，问题来自工具时写出是哪一个工具。

转写区里，提问和别的工具调用一样留一行记录：显示它问了什么，等的时候标明还在等，答完显示它拿到的答复。记录不能作答，也不长得像能作答的卡。

同一个问题也出现在「待你决定」页，样子相同。这一页按会话分开，列出这个租户所有在等人回答的问题，人不用进到每个会话里去答；在这里答了，那个会话自己接着往下走。在任一处答了，另一处跟着收起。

工具调用的参数显示成人读的样子：参数名与值，不是内部的数据结构。

### 资产

资产这一部分是人管理自己租户里各类资产的地方。它按类别分开：每一类资产有自己的一页，人在左边的一条栏里切换；窗口窄时这条栏变成一行横条。<!-- OD-11 -->

每一类的页面由那一类资产自己设计。不同的资产内容不一样，能配的东西不一样，要看的状态也不一样，所以应用不替它们规定页面长什么样。一类资产没有带来自己的页面时，用通用的页面。应用只保证三件事：

- 一类资产的页面出了错，只有这一页显示读不出，别的类别照常。
- 一类资产自己的页面没有装上时，这一类用通用的页面，它的资产与设置项照样看得到、改得了。
- 一份资产的设置只在一个地方改。

通用的页面列出这个租户这一类正持有的资产。每一份显示它的名字、[资产简介](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-asset-summary--资产简介--asset-summary)里的标题与一句说明、现在用的是哪一版、启用还是禁用、是不是部署自带的。没有设置项的资产也在列表里。人点开一份，看到它的几条要紧的事实、它的内容（内容是一段数据的显示这段数据，内容是一个目录的显示里面有哪些文件与各自的大小）、它现在能不能用与不能用的原因，以及这一份资产的设置项。设置项怎样显示、怎样改，和「设置」一节相同。

人可以新建一份资产，怎样新建由类别定。内容是一段数据的类别，页面照这一类要的字段给出表单。内容是一个目录的类别，人选一个本机目录，应用把里面的文件传给服务端；传完并被服务端接受之前，任何人都看不到这份资产，也看不到它的一部分（见[资产上传](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-asset-upload--资产上传--asset-upload)）。同名的资产已经在持有时，新建得到的是它的新版本，页面在提交之前说明这一点。有的类别不能在这里新建，例如随部署来的工具，这一类的页面上就没有新建的入口。服务端拒绝时，页面显示它给的原因：内容不合这一类的规则，或超过了这一类的哪一个上限。

人可以禁用、启用、移除一份资产。禁用保留它的设置，以后可以再启用。移除不可逆，它的设置随之退出，页面在提交之前说明这一点；移除之后可以再新建同名的资产，得到的是一份新的持有，不带回以前的设置。部署自带的资产不能禁用，也不能移除，页面上不给这两个动作。这些规则归[资产与规则](../assets-and-rules/design.md#cap-ar04-资产持有禁用与移除)。

别处改了这个租户的资产时，例如另一个窗口、命令行或 agent，开着的页面自己重读，回到服务端现在的事实。新建、禁用、启用、移除的结果不知道时，页面显示不知道，并按原来的那一次认回，不重新做一遍。

页面上不论怎样画，规则不变：被上层锁定的项改不了，秘密项只显示设没设，人没有资格做的事做不了。这些由服务端判，不由页面判。

### 设置

设置这一部分列出不属于任何一份资产的设置项。一份资产自己的设置项在「资产」里它那一份的详情里。每一项显示它的说明、现在生效的值、这个值来自哪一层、人自己在这一层设了什么、它有没有被上层锁定、人能不能改。

人可以改一项，也可以清除自己设的值。改完之后应用显示服务端答复的结果。被拒绝时显示原因：被锁定、超出上层给的范围、上层禁止、别人刚改过。被拒绝之后屏幕上的值不变。

秘密项只显示设没设，不显示值。

权限项的每一档会带来什么效果，应用按服务端的答复显示，不自己解释。

设置的规则归[资产与规则](../assets-and-rules/design.md#ar-j05)。

### 连接断开与恢复

连不上服务端时，应用显示已经断开，并且一直试着重新连上。断开期间发出的操作，没有发出的显示没有发出，可能发出的显示不知道，都不显示成成功或失败。

连上之后，应用重新开始观察正在看的会话。断开期间它可能漏了内容，所以按需要重新读历史，屏幕上的内容回到和服务端一致。

连接正常时，应用不显示任何连接状态。只有断开与正在重连时才出现一句话。

### Agent 在屏幕上的形

人在应用里随时要知道两件事：agent 有没有在做事，有没有事在等自己回答。应用用一个[形](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-agent-figure--agent-形--agent-figure)来回答这两件事，不用文字、圆点或转圈。

形是 agent 在这个窗口里的样子：一支毛笔写出的墨圆，留一个口。它不是图标、头像或产品标志。同一时刻屏幕上只有一个形。人看着某个会话时，形代表这个会话的 agent。人没在看任何会话时，形代表这个租户的全部会话。

形只坐在[形座位](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-figure-seat--形座位--figure-seat)上。座位有三个：

| 座位 | 在哪 | 什么时候形坐在这里 |
| --- | --- | --- |
| 门 | 登录门的上方 | 没有登录时 |
| 家 | 侧栏的左上角 | 登录之后，人不在对话页时 |
| 对话头 | 对话页的头部，会话标题的旁边 | 人在对话页时 |

人打开对话页，形从家走到对话头。人离开对话页，形回家。形离开的座位上什么都不留。

家同时是对话这一部分的入口：对话在导航里没有自己的一行。人点家里的形，去对话页。有事等人回答时，人点形，去「待你决定」页。<!-- OD-6 -->

形用自己的笔画说出它代表的会话此刻在做什么：

| 会话里的事实 | 人看到的形 |
| --- | --- |
| 输入被接下，一轮开始 | 墨圆沿旧迹重写一遍 |
| 在等模型的第一段回复，或推理在出 | 墨圆一遍遍重写，间歇长短不一 |
| 工具调用在跑 | 墨圆里有一点，在几处之间挪动 |
| 回复的正文在写出 | 形旁有两到四道竖笔，自上而下 |
| 只剩后台的调用在跑 | 墨圆重写，间歇比在想时长得多 |
| 一轮正常结束 | 口合上一拍，墨再干掉 |
| 一轮失败或被取消 | 一道枯笔从口里飞出，再干掉 |

回复在写出的时候，消息上方与转写末尾都没有「正在生成」一类的字，会话列表里也没有「在回复」的标记。用读屏的人听到一句状态。列表、上传、读设置与重连这类加载不是 agent 在做事，照旧显示活动标记加一个词。

形的口外用琥珀色写出[待答数](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-awaiting-answer-count--待答数--awaiting-answer-count)：这个租户此刻有几个[人在回路](../human-intervention/design.md)的请求停下来等人回答，即待答的问询与放行。导航里「待你决定」后面是同一个数、同一种颜色。没了结的通知不算进去，导航里通知的条数用中性的样子显示。琥珀是「等你回答」的颜色，规则见[观感](#观感)。

凡是形展开给人看的内容，都画在[墨框](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-ink-bubble--墨框--ink-bubble)里。墨框的边从形的口写出，边合上之后内容才出现。收起时内容先走，墨沿来路卷回口里。墨框用在三处：

- 一条强通知到了：形在家旁边写出[告知笺](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-told-note--告知笺--told-note)。<!-- OD-4 -->
- 窗口不够宽时，人点对话头的形，展开对话页的侧边内容，例如用量与后台调用。
- 登录门上的一句话：登录失效了，或者退出时服务端是否注销没有得到确认。

应用自己的菜单、下拉、提示与确认不用墨框。常驻在版面里的东西也不用墨框，例如宽窗口里停靠的侧边内容与「待你决定」页。两种样子混在一起，人就读不出「这是 agent 在给我看」。

告知笺的规则：

- 形坐在家、侧栏展开时才写。侧栏折着或形不在家时不写，这一条也不算进待答数。人在通知页里照样看得到那条通知。
- 同时只写最新的一条，最多三行。第四行能写完全文时写第四行。
- 人点告知笺，去它指的那条通知。人去了那条通知或点掉告知笺，墨卷回口里。告知笺不按时间自己消失。
- 写过一条告知笺不改变服务端的任何事实，也不表示人看到了那条通知。

形对人的动作有回应：指针停在形上时，墨圆里出现一点；按下时有一圈墨。形从不让人等：墨框正在写时，在框里按一个键或按一下，墨立刻写完；一程走到半路要去别处，笔从它所在的地方接着走。说状态的笔不因按下而干掉，它说的是 agent 此刻在做的事。<!-- OD-13 -->

形在每个座位上大小相同，大小只随字号档变。系统打开减弱动效时，形不写、不飞，直接以新的样子出现在新的座位上。每个状态仍然有一个看得见的标记。

### 随身入口

人不在对话页时，也常常想对 agent 说一句话。应用在整个窗口之上放一个随身入口：登录之后它就在，在哪一页都看得到。人按它，展开一个小框，写一句话，选说给一个新会话还是某个已有的会话，发出去。这句话和在对话页的输入框里发的是同一件事：那个会话成为打开着的会话，话出现在对话页。发出去之后小框如实说结局：受理了、确定没有发出（带原因）、不知道；不知道时请人到对话页看。

人可以按住它，把它拖到窗口里的任何地方。它留在人放下的地方，下次打开应用还在；窗口变小时它仍然整个在窗口里。位置是[观感偏好](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-look-and-feel-preference--观感偏好--look-and-feel-preference)，存在本机。

它默认的样子是墨点：同一支毛笔点出来的几粒墨，落在一个不画出来的圆上，圆的口和形的口开在同一处。人看得出一个圆，纸上没有圆。它用的是形的笔墨，但它不是形：形是 agent 本身，屏幕上仍然只有一个；墨点没有那一笔圆，不坐座位，不写待答数，不走一程。它只说两件事：这里可以对 agent 说话；打开着的会话在做事时，墨点一粒粒重点。小框画在[墨框](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-ink-bubble--墨框--ink-bubble)里，边从墨点那里写出来。被拖起来时只留一粒，放下时其余的依次点出来。

人可以把它换成自己喜欢的样子：一份 [plugin](../../ubiquitous_language/terms/capabilities-and-composition.md) 可以只换形象，可以只换小框里面的内容，也可以整个换掉。只换形象的那一份拿不到说话的能力。

这一节依据产品负责人 2026-11-23 的决定：提供一个能发消息、能指定新建会话或复用某个会话的随身入口；人可以自定义形象，可以拖到界面的任意位置；默认的形象接着原生界面的设计语言，尤其是形，用水墨与「点」的意象来做（点线面、大象无形、撒豆成兵）；默认形象做进应用。要不要给一个关掉它的设置还没有定，见 [Q-DA07](#q-da07)。

### 开发模式

人想让 agent 改界面上的某个东西时，常常叫不出它的名字。[开发模式](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-ui-developer-mode--界面开发模式--ui-developer-mode)让人直接指着它说。它是应用里的一个开关，缺省关着。关着时，应用和没有这个功能时一样。

界面上能被指的是[界面部位](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-ui-part--界面部位--ui-part)：一种有名字的东西，例如发送按钮、工具调用行。同一种部位可以在屏幕上画好几处，人指的是其中一处。

打开开发模式之后，输入区多一个「选取」的入口。进入选取，人这样选：

1. 指针移到哪里，哪里的部位显示一个框与它的叫法。此时点击不触发界面原本的动作，人可以放心地点「删除」这样的按钮。
2. 点一下，选中这一处。按住修饰键再点，多选一处；已经选中的再点一下就去掉。
3. 拖一个框，选中框里完整的部位。框里的部位有里外层时，只取最外面的。看不见的不会被选中。框里没有一个完整的部位时，选中装得下这个框的最小的部位。
4. 人可以把悬停的部位换成它外一层或里一层的，也可以把选中的一个容器拆成它里面的几个。
5. 人点的东西没有自己的名字时，选中的是包着它的最小的部位，应用照实写明。

每个选中的有一个序号，写在屏幕的框上，也写在输入区里。人可以在话里用序号指它们，例如「把 #1 和 #2 都换成胶囊形」。去掉一个之后，别的序号不变。一次能选的个数有上限，到了上限应用告诉人。

选中的东西是一份[界面选择](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-ui-selection--界面选择--ui-selection)。它在这个应用里只有一份，换页面不丢：人可以在资产页选一个按钮，再回到对话页写字。它随人发出的下一条消息走，发出之后清空。它和人写的字是分开的：会话的标题、搜索和历史里的文字不含它。以后回看这一轮，看得见当时选了什么。

agent 收到这条输入时，已经知道每个被选中的是哪个部位、是屏幕上的哪一处、这一处画的是什么，例如一条工具调用行是哪个工具的。部位的名字就是 agent 的工具用的名字，所以它不用再找。

选中的东西由服务端核对。应用已经不在连接中、部位不存在、个数或大小超出上限时，这条消息不发出去，应用说明原因，人写的字和选中的东西都留着。核对不了的时候同样不发出去，不当作没有选中。

人也可以不选，只说位置，例如「对话页输入框右边那个按钮」。agent 自己在界面的结构里找。符合的不止一个时，agent 在人的屏幕上把候选标上序号，再问人是哪一个。

agent 可以看界面此刻的样子：现在连着哪些应用、各开着哪一页，一个应用此刻画着哪些部位，一个部位现在长什么样（一张图）。它也可以在人的屏幕上把几处标出来几秒。它只能看、只能标它在为之工作的那个租户的应用。许不许照[动作放行](../meta-capabilities/design.md#动作放行与环境准入)：看、截图、标出来各是一项权限，缺省自动，租户或组织可以收紧。理由是这些都不留下东西，看到的也只是这个租户自己的应用窗口。

选取的手势随应用形态不同：桌面应用是点与框。别的图形交付面有各自的手势，其余的规则相同。

### 观感

六部分用同一套设计语言：明亮的书桌与一盏暖灯。白天是羊皮纸与象牙白，夜里是暖炭色。层次靠阅读字体、间距与细线，不靠卡片与阴影。颜色只在下面这几处有含义：

- 墨蓝标出动作、链接与焦点。
- 琥珀标出等人回答的东西：待答数、等人回答的决策卡片、列表里等人的那一行。别的颜色不用来表示在等人。<!-- OD-12 -->
- 绿、琥珀、红是说一件已知事实的三种语气：成功、注意、失败。它们只说事实，不作装饰。除了等人回答的东西，琥珀只以「注意」这种语气出现，例如行内通知与状态词。结果不知道时用中性，不用琥珀，也不用红。
- 红只用在失败的事实与不可撤销的最后一步上。一轮失败是已知的失败，用失败的语气。

人可以选三种主题：浅色、深色、跟随系统。

人可以选四个字号档：小楷、中楷、大楷、老花，缺省是中楷。换一档，整个界面的字与尺寸一起变，形也跟着变，版式不变，没有东西被裁掉或缩小来将就。人可以一档一档地放大、缩小，也可以回到中楷。

主题与字号档在侧栏底部的「外观」里选。「设置」那一部分不放它们。

中文正文用随应用带的霞鹜文楷，各系统上一样。<!-- OD-1 -->

正常的状态是安静的：连接正常时不显示连接状态；一轮正常开始与正常结束时，转写里不加字。不正常时才出现一句话，写在出事的地方。<!-- OD-5 -->

窗口里不写产品名。侧栏左上角只有家与折叠侧栏的按钮。<!-- OD-3 -->

### 皮肤

人可以把整个界面换成另一套样子。一套样子是一套[皮肤](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-skin--皮肤--skin)：它一起给出颜色、形状、图标、消息与输入区的样子、背景，以及随身入口的形象。换皮肤是整套一起换：界面各处同一刻换成那一套，不出现一部分是旧的、一部分是新的。

皮肤是这个租户持有的一类资产，在「资产」那一部分有自己的一页。这一页列出持有的皮肤，也是换皮肤的地方：人点一套就穿上它，点「自带的样子」就回到应用原来的样子。同一时刻只穿一套。

启用几套和穿哪一套是两件事。启用是说这一套装着、可以穿，它和别的资产一样归[资产与规则](../assets-and-rules/design.md#cap-ar04-资产持有禁用与移除)。穿哪一套是人在这台设备上的[观感偏好](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-look-and-feel-preference--观感偏好--look-and-feel-preference)，按租户记。所以人可以同时启用几套，再在它们之间换，换的时候不用等。

应用照下面的规则定此刻穿哪一套：

- 人选了「自带的样子」：不穿。
- 人选过一套，它装上了：穿它。
- 人选过一套，它启用着但还没有装上，或者装不上：不穿，这一页写明它的状态与原因。应用不替人换成别的一套。
- 人选过的那一套被禁用或移除了：当作没有选过。
- 人没有选过，只启用着一套，它装上了：穿它，并把它记成人选过的。这样以后再多出一套时，穿着的这一套不变。
- 人没有选过，启用着两套以上：不穿，这一页请人选一套。

agent 可以替人换皮肤：它发布并启用一套新的，再禁用原来那一套。只剩一套启用着，界面就换成它。发布、启用与禁用和别的资产是同一组动作。

皮肤只改看得见的样子，不带任何能力：它不给 agent 加工具，不在服务端运行代码。一份带了这些东西的包，发布成皮肤时被拒绝，并说明原因。一份包是不是皮肤由它自己写明；写明是皮肤的不能发布到别的类别里。

穿着一套皮肤时，同一个地方另一份 plugin 放的样子不算数，以皮肤的为准。脱下皮肤之后，那一份照常算数。

皮肤换不了三样：侧栏与导航的结构，登录的那一页，窗口的标题。没有登录时界面总是自带的样子。

一套皮肤装不上，或者画某一处时出了错，应用照常打开，那一处回到自带的样子。「资产」里这一套写明哪里没有生效与原因。

这一节依据产品负责人 2026-11-24 的决定：界面里有专门的地方让人自己换皮肤；皮肤在资产里是单独的一类，它的内容是一份更窄的 plugin；一套皮肤联动界面上所有能改的地方一并改。

### 关键用户旅程

<a id="j-da01"></a>

#### J-DA01 第一次使用

人打开应用，看到登录门，注册并登录。登录之后看到空的会话列表，新建一个会话，发出第一条消息，看到回复一边生成一边出现。

<a id="j-da02"></a>

#### J-DA02 回来接着聊

人登录之后在列表里看到之前的会话，选一个进入，看到历史，接着发消息。回复还在出的时候他又发了一条，两条都有确定的状态。

<a id="j-da03"></a>

#### J-DA03 一轮失败之后接着做

人发出一条消息，这一轮失败了。他看到失败的原因、还有一条消息没处理、一个「重试」的按钮。他按重试，下一轮带着那条消息接着做，他不用重新输入。

<a id="j-da04"></a>

#### J-DA04 改一项设置

人打开资产，选一类资产，点开其中一份，看到它的一项设置现在的值与它来自哪一层。他改了它，看到服务端答复已经生效。他又清除了自己设的值，生效的值回到上层给的那一个。另一项被上层锁定，他看得到锁定，改不了。

<a id="j-da05"></a>

#### J-DA05 断开与恢复

回复正在出的时候连接断了。人看到已经断开的提示。连接恢复之后，屏幕上的内容补齐到和服务端一致，没有重复，也没有缺。

<a id="j-da06"></a>

#### J-DA06 退出与登录失效

人按退出，立刻回到登录门。另一次，他的登录在别处被吊销，应用回到登录门并告诉他登录失效了。

<a id="j-da07"></a>

#### J-DA07 装上一份资产，用完再卸掉

人打开资产，选「技能」这一类，按新建，选了本机的一个目录。页面显示有几个文件、一共多大，他确认之后文件传给服务端。传完，列表里出现这一份，带着它的标题与一句说明。他点开它，看到里面有哪些文件。后来他暂时不想用，把它禁用；再后来把它移除，页面先告诉他移除不可逆、它的设置会退出。之后他又装了同名的一份，是一份新的，没有带回以前的设置。

<a id="j-da08"></a>

#### J-DA08 指着界面说

人打开开发模式，进入选取，框住输入区里的两个按钮，再按住修饰键点了对话头上的一个控件。三处各有一个序号。他写「把 #1 和 #2 都换成胶囊形，#3 不动，只要告诉我它是什么」，发出去。agent 没有再找，直接改了前两个，并说出 #3 是模型选择。他回看这一轮，消息上看得见当时选的三处。

<a id="j-da09"></a>

#### J-DA09 只说位置

人没有选，写「对话页输入框右边那个按钮换个颜色」。agent 在界面的结构里找到两个符合的，在他的屏幕上标出 #1 与 #2，问他是哪一个。他答 #2。agent 改完，截了一张那个按钮的图，确认颜色变了。

### 可观察场景

下列场景是产品判据，正文描述的是期望结果。

1. 全新的部署上打开应用。只看到登录门。注册并登录后看到空的会话列表与当前租户。
2. 新建会话并发一条消息。消息先显示发送中，再显示已经被接下；回复逐段出现，这期间对话头的形在写，转写里没有「正在生成」一类的字；一轮正常结束时转写里不加字，形合上口回到静止。<!-- OD-5 -->
3. 回复还在出的时候按停止。按钮变成正在停止，随后这一轮显示已取消；输入框一直可用。
4. 让模型的调用失败。对话里出现失败的原因、没处理的消息的条数与「重试」。按重试后，下一轮开始，没处理的消息不用重新输入。
5. 让 agent 用工具，并在一次提问里问两个问题，同时另发一次只有一个问题的提问。工具卡显示参数名与值、结果。输入框上方出现三张卡，左右切换；三题都答了才能提交，按一次提交之后三题都记下，这一轮接着走；转写区里每次提问各留一行记录。再让它问一个问题，这一次在「待你决定」页里答，不进会话；回到会话，这一轮已经接着走完。
6. 在资产里点开一份资产，改它的一项普通项、清除它；试着改一项被锁定的项。前两步显示服务端答复的新值，第三步显示被锁定且值不变。设置这一部分不列这些项。
7. 停掉服务端再起来。应用先显示已断开，恢复后内容与服务端一致。
8. 退出。回到登录门。再登录后会话都在。
9. 在页面的运行环境里找登录证明。找不到。
10. 在资产里选一个本机目录新建一份技能。传完之前，列表里与另一个窗口里都没有它；传完之后两处都出现它，带标题与说明。禁用它，列表显示已禁用，它的设置还在；启用它；移除它，列表里没有它了；再用同一个名字新建，成功，新的一份上没有以前设过的值。部署自带的一份工具上没有禁用与移除。
11. 登录之后打开对话页，再离开。形从家走到对话头，再走回家。任何时刻屏幕上只有一个形，形离开的座位上什么都没有。
12. 让 agent 一次问三个问题。形的口外写出琥珀色的 3，导航里「待你决定」后面也是 3。三题答完并提交，两处一起归零。
13. 让一个来源发一条强通知，人在家、侧栏展开。形旁写出告知笺；人点它，去了那条通知，墨卷回口里。再发一条，这次侧栏折着：什么都不写，待答数不变。
14. 在「外观」里换主题、换字号档。四档下版式都成立，没有东西溢出或缩小来将就，形跟着字号变大小。
15. 打开系统的减弱动效，重做场景 2、11、13。形不写、不飞，直接出现在新的样子与新的座位上；每个状态仍有看得见的标记。
16. 打开开发模式，输入框里写着字，进入选取，点发送按钮。消息没有发出去，字还在，发送按钮被选中并得到序号 #1。退出选取，再点输入框，可以接着写。
17. 选中两处，发出一条用序号指它们的消息。会话的标题是人写的话，不含选中的东西。agent 的第一步不是找。历史里这条消息显示选中的两处。
18. 选中一处之后断开这个应用与服务端的连接，再发。消息没有发出去，应用说明原因，字与选中的东西都还在。
19. 关掉开发模式。「选取」的入口没有了，界面的每个动作和打开之前一样。

### 非目标

- 终端界面。
- 离线使用。没有连上服务端时，应用不提供任何写的操作。
- 应用自己判断权限或业务有没有完成。
- 拖动形、让形指着界面里的东西、让形离开应用窗口。<!-- OD-7 -->
- 形换成别的形状、给形起名字、形在没事时的小动作。<!-- OD-7 -->
- 开发模式里只用键盘走遍所有部位。
- 选中界面上没有名字的东西本身。选中的是包着它的最小的部位。
- 开发模式里改外壳的结构、加一级页面。这要重新构建应用，不在开发模式里。

<a id="q-da02"></a>

### Q-DA02 租户与组织的界面

身份的规则里有切换当前租户、建立组织、邀请成员。应用里做不做、做到哪，决定登录这一部分有多大。

<a id="q-da03"></a>

### Q-DA03 登录在应用重启后是否保留

保留，人少输一次密码，登录证明要落在本机的加密保存里。不保留，本机不留任何证明，每次打开都要登录。

<a id="q-da05"></a>

### Q-DA05 多语言

只有中文，文案直接写在界面里。要多语言，文案要抽出来，并定缺省语言与怎样选。

<a id="q-da06"></a>

### Q-DA06 别的图形交付面

桌面应用的页面按拿出来就能当网页跑来写。要不要把网页作为一种正式的交付面提供，决定浏览器直接连服务端这条路要不要支持。

<a id="q-da07"></a>

### Q-DA07 随身入口能不能关掉

随身入口默认对每个登录的人都在。有人会觉得它碍事。要给一个关掉它的设置，就要定这个设置是观感偏好（存在本机）还是租户的设置（跟着人走）。
