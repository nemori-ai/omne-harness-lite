# PF-002 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

| 场景 | 应当看到什么 |
|---|---|
| 给组织加入一个 tool | 设置页上**自动多出**这个 tool 的配置表单，无需任何人去配置设置页 |
| 加入一个 plugin | 它内含的 skill、tool、slash command **一并进来**，各自的表单也一并出现 |
| 移除那个 plugin | 内含的东西**一并退场**，表单一并消失 |
| 试图单独卸载 plugin 里的某个 skill | **被拒绝**。内含成员不取得独立生命周期 |
| 组织给某 tool 的执行权限配「问一下」，不加锁 | 成员可以在自己租户里改成「自动」 |
| 组织给某 tool 的执行权限配「问一下」并**加锁** | 成员改不了，且被告知**这是组织锁定的** |
| 组织放入一个自定义 skill，能力标识与某 official 相同 | 该组织下所有引用这个能力标识的地方**都用上了新的**，包括**别人打的 plugin 里面那个** |
| 组织把自己的自定义安全组件标为 immutable | 成员无法把它换回 official，也无法换成自己的 |
| 成员在个人组织里替换 official | **允许**——official 永远可被替代 |
| 某个 official 能力标识被所有层都移掉 | **失败**，并指出这是缺陷。official 是最小必需 |
| 组织**移除**某工具后，成员问 agent 能不能做那件事 | agent 说做不到，**说不出为什么**——它不知道有这回事。设置页上那块表单**没有了** |
| 组织**禁用**某工具后，同样的提问 | **agent 的回答一模一样**——它同样不知道有这回事。但设置页上那块表单**还在、标着已禁用、配的值一个没丢**，成员据此知道可以去申请 |
| 上一条之后，租户在自己这一层把它**启用** | **仍然不可见**。下面一层开不回上面一层禁掉的东西 |
| 会话挂上的**工作区**把**它自己提供的**某个资产配成禁用 | 这个会话里**不可见**——工作区照样配得了这一项，它是设置不是权限 |
| 同一个工作区把**组织提供的**某个资产配成禁用 | **禁不掉**，那个资产照常可见——[工作区配的禁用值只对它自己提供的那批生效](design.md#禁用是逐层配的布尔设置任一层为真即不可见) |
| 组织放入一个**与某 official 同类同名**的 tool，参数形状和说明都跟 official 那份不一样 | 它**替代**了那个 official，不是多出一份并存的资产。**args schema 与说明不参与判定** |
| 组织把它**启用**回来 | 组装时又可见了，**而且用的还是禁用之前配好的那些值** |
| agent definition A 引用 B 作 sub-agent，B 又引用 A | **拒绝**，并指出环在哪 |
| agent definition 引用的能力标识无人提供 | **明确失败**，指出缺哪个；不悄悄少装一个零件继续跑 |
| 成员在组织范围发布一个 skill，随后换了岗位 | 署名**照旧**——角色不进租户身份 |
| 该成员随后退出组织 | skill **留在组织**，署名**仍然照旧**；它记的是当时是谁做的 |
| agent 在某租户下产出一个 skill | 作者是**那个租户**，且记录标明**由 agent 产出** |
| 查看一个 official 资产的作者 | 是**平台**，不是某个租户 |
| 一个已发布的版本 | **不可变**。有新版本时**不静默替换**已选用的那个 |
| 资产在 agent 运行中被移除 | **已经开始的调用不受影响**；下一次准入才按新结果判 |
| 组织为它**并不持有**的资产配权限 | **被拒绝**。配置权不能凭空出现 |
| 组织装上一个**拓展件**，并把干预力配成「只观察」 | 它**照样每次都被调到**，只是改不动东西——这是成立的配法，不是没装好 |
| 组织把某拓展件的干预力**锁**在「只观察」 | 成员在自己租户里**放不宽**，且被告知这是组织锁定的 |
| **同一个位置**装了两个不同的拓展件 | **两个都跑**，各干各的。位置不是能力标识，它们不互相覆盖 |
| 组织和租户各装了**同一个**拓展件的不同版本 | 走[同标识覆盖](../PF-001-identity-scope-and-agent-constraints/design.md#62-三种合成语义)，**只有一个生效** |
| 装上一个拓展件之后，看 agent 面前的工具条目 | **一条没多**。拓展件由系统在固定位置调，不进[动作空间](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-action-space--动作空间--action-space) |
| 一个 plugin 里带了拓展件，停用这个 plugin | 拓展件**一并退场**，那个位置上不再有它 |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 存在一份**独立于资产维护**的设置字段表 | 它会与资产各自演化，最终对不上。设置页必须是持有关系的函数 |
| 成员绕过组织的 immutable，改掉被锁死的值 | 强制形同虚设。**安全事故** |
| 组织换上的安全组件**没进**某个 plugin，而 plugin 里还是旧的 | 漏洞正好留在 plugin 里。这是"引用指向能力标识"要防的正是这件事。**安全事故** |
| 同一类里两份**同名**的资产在求值结果里**并存**，各算各的 | 身份被当成了 name 之外的东西（参数形状、说明、实现包）。**替代因此失效**——组织换上的那份没顶掉 official |
| 某个 official 能力标识在求值结果里**空着** | agent 组装不出来，或以残缺形态跑起来 |
| **工作区配的禁用值，关掉了组织或租户提供的资产** | 一个目录从旁边绕开了组织的管理决定——**而那条决定本来是「下面开不回来」的**。[§5.7 要防的正是这件事](design.md#57-工作区那一级不参与权限计算) |
| 改一项设置，结果**换掉了一个资产** | 两轮合成被混为一谈 |
| 组装时悄悄跳过一个**找不到提供者**的引用 | agent 少了零件却照跑，没人知道 |
| 成员退出组织后，他创作的资产**跟着走了** | 组织范围的产出不该变成个人资产 |
| 成员退出组织后，他的**署名被抹掉** | 作者记录是历史事实，不是当前成员名册 |
| 超级管理员能读到成员**租户级**的私有配置 | 管理权越界。作用域是组织，不是成员的私有部分 |
| 一个层能为**它不持有**的资产配值 | 为不存在的东西设边界，既无意义又无法解释 |
| 租户把组织给的拓展件干预力**从「只观察」改成「可否决」** | 干预力被当成了设置走覆盖。**它是权限，只能收窄**——组织的边界当场失效，**安全事故** |
| 同一个位置装了两个拓展件，结果**只跑了一个** | 把「位置」误当成了能力标识，**第二个被静默丢掉** |
| 装了拓展件之后，agent 面前**多出一条工具** | 拓展件组合了 Tool。agent 拿到了一件没被授予的动作 |
| 已发布的版本被**就地改写** | 消费方脚下的地基变了而不自知 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 设置页是长出来的 | 加一个资产、不碰任何配置代码，表单自己出现；移除后自己消失 | 需要有人去某处登记这个资产有哪些字段 |
| 两轮合成分开 | 改一项设置，检查生效的资产**还是原来那一个** | 改设置导致资产被换 |
| 引用指向能力标识 | 组织替换某 skill 后，**随便挑一个含它的 plugin**，跑起来用的是新的 | plugin 里还是旧的 |
| immutable 真的锁得住 | 在租户层尝试覆盖被锁的值，**每一条路径**都被拒 | 有某条路径能绕过去 |
| 移除与禁用可分辨 | 分别做一次，**看设置页**：一次表单消失、值也没了，一次表单还在并标着已禁用、值原样留着且能启用回来。**agent 那一侧两次表现相同** | 两个动作在设置页上也看不出差别；或者禁用之后 agent 还装得上它 |
| official 不可清空 | 尝试在各层移掉某个 official 能力标识，求值结果**仍有东西** | 求出空集而系统没报错 |
| 工作区只禁得掉自己那批 | 让工作区分别对**自己提供的**和**组织提供的**两个资产配上禁用：**前一个不可见，后一个照常可见** | 后一个也被关掉了 |
| 组合图无环 | 构造一个环，**在定义时就被拒**，而不是组装时挂起 | 组装超时或栈溢出 |
| 干预力走收窄 | 组织锁一档、租户尝试放宽，**每一条路径**都被拒 | 有某条路径能放宽 |
| 位置不是能力标识 | 同一位置装两个不同拓展件，**两个都被调到** | 只跑了一个 |
| 作者记录稳定 | 换岗、退出各做一次，署名不变 | 署名随成员关系变化 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| 资产怎样被发现、装载、卸载 | 运行时装载另有归属，本 topic 只定它由什么构成 |
| 谁能创作、怎么发版、怎么上架 | 开发与发布流程另有归属 |
| 某个具体 tool 到底有哪几项配置 | 本 topic 定「设置是资产的属性」这个结构，具体字段属那个 tool 自己的定义 |
| 资产怎样在组织之间流动 | 归 [PF-003](../PF-003-asset-transfer-and-sharing/README.md)，它定义资产复制与分享两个动作 |
| Skill 套 Skill、Plugin 套 Plugin、Plugin 装 Agent Definition | 本版**刻意不做**，见 design.md §4。真有需要再加 |
| 会话与 agent runtime 的生命周期 | 本 topic 定 Agent Definition 是静态定义，跑起来之后的事归 [PF-004](../PF-004-agent-definition-and-assembly/README.md) 与 [PF-012](../PF-012-agent-loop-and-run/README.md) |
| **一共有哪些拓展点位置**、每个位置看得见什么改得动什么、同位置多个挂件按什么次序跑 | 归 [PF-012 §5.8](../PF-012-agent-loop-and-run/design.md#58-loop-拓展点)。本 topic 只定**拓展件是一类资产**及它的形状与组合 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
