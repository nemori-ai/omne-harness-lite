# PF-002 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

| 场景 | 应当看到什么 |
|---|---|
| 给组织加入一个 tool | 设置页上**自动多出**这个 tool 的配置表单，无需任何人去配置设置页 |
| 加入一个 plugin | 它内含的 skill、tool、slash command **一并进来**，各自的表单也一并出现 |
| 移除那个 plugin | 内含的东西**一并退场**，表单一并消失 |
| 试图单独卸载 plugin 里的某个 skill | **被拒绝**。内含成员不取得独立生命周期 |
| 组织给某 tool 的执行权限配「问一下」，不加锁 | 成员可以在自己租户里改成「自动」 |
| 组织给某 tool 的执行权限配「问一下」并**加锁** | 成员改不了，且被告知**这是组织锁定的** |
| 组织放入一个自定义 skill，能力标识与某 official 相同 | 该组织下所有引用这个能力标识的地方**都用上了新的**，包括**别人打的 plugin 里面那个** |
| 上一条之后，看设置页与 agent 查到的那个条目 | 两处都看得到**这一份来自组织、替换了官方那一份**——[替换必须可见](design.md#55-资产替换的层级) |
| 挂上的工作区带来一个与租户那份同名的 skill | 生效的是工作区那份，**设置页上标着它来自工作区、替换了租户那一份** |
| 组织把某工具的执行权限**锁**在「问一下」，租户换上一份**同名的自己的工具**，再配「自动」 | **仍然每次都问**——组织锁下的界[跟着身份走](design.md#替换是一条路径不是一扇后门)，换一份实现绕不过去 |
| 租户给某个 MCP 接入点取了凭据，挂上的工作区带来一份**同名的接入点** | 工作区那份**拿不到租户那一份凭据**——设置的值[跟着资产走](design.md#替换是一条路径不是一扇后门)；工作区那一级自己又取不了，**它连不上**，直到被收进租户层再取 |
| 组织给官方某 MCP 接入点配了连接目标，租户换上一份**同名的自己的接入点** | 租户那份**不用组织配的连接目标**，只用它自己这一层配的与它自己声明的默认值 |
| 组织把某工具的执行权限**锁**成「问一下」「禁止」两档，工具作者声明的默认是「问一下」，成员配「自动」 | **「自动」不作数**——它在组织锁下的界外；往外找第一个落在界内的挑选，是作者的默认「问一下」，**生效的就是它** |
| 同上，但作者声明的默认是「自动」，也没有哪一层在界内挑过 | 界内谁都没挑到，**取界内离「自动」最近的「问一下」**，不是「禁止」——组织说的是「不许自动」，不是「关掉它」 |
| 组织给某工具的执行权限配「禁止」、**没锁**，成员配「自动」 | **仍然禁止**——配成「禁止」的锁不锁都是界；每次调用都被拒，不出卡片 |
| 组织把自己的自定义安全组件标为 immutable | 成员无法把它换回 official，也无法换成自己的 |
| 成员在个人组织里替换 official | **允许**——official 永远可被替代 |
| 某个 official 能力标识被所有层都移掉 | **失败**，并指出这是缺陷。official 是最小必需 |
| 组织**移除**某工具后，成员问 agent 能不能做那件事 | agent 说做不到，**说不出为什么**——它不知道有这回事。设置页上那块表单**没有了** |
| 组织**禁用**某工具后，同样的提问 | **agent 的回答一模一样**——它同样不知道有这回事。但设置页上那块表单**还在、标着已禁用、配的值一个没丢**，成员据此知道可以去申请 |
| 上一条之后，租户在自己这一层把它**启用** | **仍然不可见**。下面一层开不回上面一层禁掉的东西 |
| 会话挂上的**工作区**把**它自己提供的**某个资产配成禁用 | 这个会话里**不可见**——工作区照样配得了这一项，它是设置不是权限 |
| 同一个工作区把**组织提供的**某个资产配成禁用 | **禁不掉**，那个资产照常可见——[工作区配的禁用值只对它自己提供的那批生效](design.md#禁用是逐层配的布尔设置任一层为真即不可见) |
| 同一个账号在同一台机器上、挂着同一个目录，**从一个租户身份切换到另一个** | 看得见的**工作区是另一份**：上一个身份在那个目录里持有的资产与配的值，**这一个身份一样都看不到** |
| 租户为某项设置配了值，**工作区**也配了一个，两边都没加锁 | 生效的是**工作区那个**——[工作区压过租户](design.md#58-三条层序各答一个问题) |
| 组织把某项设置配了值并**加锁**，工作区再配一个 | **锁得住**，生效的还是组织那个。[工作区压不动锁住的项](design.md#58-三条层序各答一个问题) |
| 会话创建时**没有指定**工作区 | 这一级是**空的**：资产归属没有第三级持有，设置那一格没有值——[什么都没加载](design.md#它是会话选用的不指定就是空)，哪怕 agent 正在某个目录里跑 |
| 会话创建时指定了一个工作区，承载目录里放着**特定命名的配置文件** | 装配时**自动**读进来，里面的资产与设置值出现在求值结果里，**没有人手动导入过** |
| 同一个租户、同一台机器，agent 在宿主机上读**工作区目录外**的文件 | **读得到**——只要执行环境权限与命令权限没禁止。[目录不是围栏](design.md#工作区不是目录) |
| 工作区里配了一项**权限**（比如把某工具的执行权限写成「自动」） | **一概不作数**——[加载时就被滤掉](design.md#57-工作区那一级不参与权限计算)，无论它是放宽还是收紧 |
| 组织放入一个**与某 official 同类同名**的 tool，参数形状和说明都跟 official 那份不一样 | 它**替代**了那个 official，不是多出一份并存的资产。**args schema 与说明不参与判定** |
| 组织把它**启用**回来 | 组装时又可见了，**而且用的还是禁用之前配好的那些值** |
| agent definition A 引用 B 作 sub-agent，B 又引用 A | **拒绝**，并指出环在哪 |
| agent definition 引用的能力标识无人提供 | **明确失败**，指出缺哪个；不悄悄少装一个零件继续跑 |
| 成员在组织范围发布一个 skill，随后换了岗位 | 署名**照旧**——角色不进租户身份 |
| 该成员随后退出组织 | skill **留在组织**，署名**仍然照旧**；它记的是当时是谁做的 |
| agent 在某租户下产出一个 skill | 作者是**那个租户**，且记录标明**由 agent 产出** |
| 查看一个 official 资产的作者 | 是**平台**，不是某个租户 |
| 一个已发布的版本 | **不可变**。有新版本时**不静默替换**已选用的那个 |
| 资产在 agent 运行中被移除 | **已经开始的调用不受影响**；下一次准入才按新结果判 |
| 组织为它**并不持有**的资产配权限 | **被拒绝**。配置权不能凭空出现 |
| 组织装上一个**拓展件**，并把干预力配成「只观察」 | 它**照样每次都被调到**，只是改不动东西——这是成立的配法，不是没装好 |
| 组织把某拓展件的干预力**锁**在「只观察」 | 成员在自己租户里**放不宽**，且被告知这是组织锁定的 |
| **同一个位置**装了两个不同的拓展件 | **两个都跑**，各干各的。位置不是能力标识，它们不互相覆盖 |
| 上一条的两件，在装配清单里一前一后 | **按清单里的先后依次过**，后一件看得到前一件的结论；把两件在清单里对调，先后跟着对调 |
| 定义一个 skill 声明要用某个 tool，那个 tool 又声明要配这个 skill | **接受**，两边各装一份；这不是要拒绝的那种环 |
| 仓库带来一个以本地命令方式接入的 MCP 接入点，挂上工作区、开一个会话 | 它**没有启用**，没有任何命令在本机被跑起来；持有这份工作区的租户在自己的设置里打开它之后才会用上，打开之后它的每一个动作仍要人点头 |
| 仓库目录里的文件把上一条那个接入点写成「启用」 | **打不开**——开关不在仓库里 |
| 组织和租户各装了**同一个**拓展件的不同版本 | 走[同标识覆盖](../PF-001-identity-scope-and-agent-constraints/design.md#62-三种合成语义)，**只有一个生效** |
| 装上一个拓展件之后，看 agent 面前的工具条目 | **一条没多**。拓展件由系统在固定位置调，不进[动作空间](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-action-space--动作空间--action-space) |
| 一个 plugin 里带了拓展件，停用这个 plugin | 拓展件**一并退场**，那个位置上不再有它 |
| 工作区带来一个 MCP 接入点，它自己声明执行权限「自动」 | 它的每一个动作**照样要人点头**（问一下）；把它收进租户层之后，才能在租户层配成「自动」 |
| 工作区带来一个 skill、一条斜杠命令与一个 MCP 接入点，同一租户的另一个人没挂这份工作区 | 挂上它的那个人**当场就用得上**这三样（MCP 的动作每次仍要问人）；**别人一样都碰不到** |
| 工作区带来一个声明了「可否决」的挂件 | 它照样每次被调到，但**只观察**，拦不住任何东西 |
| 装上一个 MCP 接入点，对端提供五个动作 | agent 面前**多出五个工具条目**，每个各有自己的执行权限 |
| 一次执行尝试进行到一半，MCP 对端新增了一个动作 | 这次尝试里 agent 面前的条目**不变**；下一次尝试开始时才出现 |
| 从 Claude Code 导入一个会产出 `allow` 的 hook | 导入时**明示**这一项被译成「无意见」；装上之后它放不行任何动作 |
| 发布一个 ① 或 ② 型的斜杠命令，名字带 `omne-official` 前缀 | **被拒**，并说明这个前缀留给系统 |
| 系统新添一条 ③ 型流程 | 它的名字在 `omne-official` 前缀下，**不可能与任何已发布的 ① ② 型同名** |
| 人敲一个 ② 型命令，后面带了几句话 | skill 正文**一字不差**地成为一个内容块，他带的那几句**另成一个内容块** |
| 某条命令声明了参数，人给的参数对不上 | **当场明说哪里不对，什么都没发出去**；① ② ③ 型一样 |
| 某条命令没声明参数，人在命令名后写了一段话 | 那一整段作**一个自由参数**，照常发出 |
| 人敲一条他**没有权限用**的命令 | 与敲一个**不存在**的名字**完全一样**：当场明说「没有这个命令」、不发送；**不会说「你不能用」，也不会当一句话送进会话** |
| 会话开着，组织**禁用**（或移除）了一条 ① 型命令 | 这个会话里**照样敲得出**，展开的还是原来那段；人发一条 **reload** 之后，敲它得到「没有这个命令」 |
| 会话开着，组织**新加入**一条 ② 型命令 | 这个会话里**还没有**；发 reload 之后才有 |
| 会话开着，那个人对某条命令的**权限被收回** | **不等 reload**，此刻起敲它就是「没有这个命令」 |
| 会话开着，某条 ③ 型命令背后的服务不在了，人敲它 | **明说执行失败**，日志里那条记它发生过的条目记着失败；**随后它自动从这个会话的命令里消失**，没有人发 reload |
| 运行正在跑，人发 reload | 正在跑的那次运行**不被打断**，照它已经捕获的构成跑完；reload **只重填它对应的那一张注册表**，别的注册表不动 |
| 会话已经开着，有人往它挂的工作区的配置文件里新添了一条斜杠命令 | 发 reload 之前**没有**；发了之后挂上它的那个人就能用 |
| 同一个人在两个租户下各配一个接同一服务的连接件 | 两边的鉴权绑定**各配各的**，可以接对面两个不同的账号 |
| 连接件把对面账号 X 发来的一条消息投进成员甲的会话 | 这条消息**按甲那个会话创建时的租户身份处理**——放行、成本都算甲那个租户身份的；**X 只作来源留在消息上**。设置页上**找不到**「送进来的消息按什么身份处理」这一项 |
| 组织配连接件的「能不能安装」 | 取值是**一组租户角色，外加「自己」**——与其余「谁可以……」同一种 |
| 连接件送来一条事件，它的类型不在这份连接件的事件目录里 | **受理时被拒**，拒绝看得见、说得出原因；**不落进任何会话**，也不被悄悄丢掉 |
| 连接件送来一条目录里有、但这份持有**没订阅**的类型 | **同样受理时被拒**，看得见 |
| 打开一份连接件的设置 | 看得到**事件订阅**：勾的是目录里的哪几种；组织层与租户层各配各的 |
| 看一个组合了这份连接件的 agent 上下文里关于它的说明 | **只有被订阅的那几种**的说明；没订阅的那几种一条都不在 |
| agent 在运行中想多订阅一种事件 | **没有这个动作**——订阅只由持有它的那几层配 |
| 已有的会话甲开口接收连接件 X 的投递，X 送来一条订阅了的事件 | 这条事件**落进会话甲**，按甲创建时的租户身份处理——**① 那一路，主体是会话** |
| 连接件 Y 配了触发会话的默认运行模式 `never`，它送来一条订阅了的、走开新会话那一路的事件 | **受理为它开一个新会话**，事件落进去，触发这个会话的第一次运行；**新会话的运行模式是 `never`**——**② 那一路，主体是连接件** |
| 连接件 Z 哪一层都**没给**触发会话的默认运行模式（作者声明了一个默认也一样），它送来一条走开新会话那一路的事件 | **开不出新会话**，受理时明说缺的是这一项；**系统不替它挑一个值** |
| 上一条的 Z，同时给一个已有的会话开口接收投递 | ① 那一路**照常**——已有的会话用它自己的运行模式 |
| 租户把 Y 的触发会话的默认运行模式从 `never` 调成 `auto_permission` | **此后**开出来的新会话按 `auto_permission` 起步；**已经开出来的那些不变** |
| 组织把 Y 的触发会话的默认运行模式锁在 `never` | 租户**调不动**，且被告知这是组织锁定的 |
| 仓库目录里的文件把某个连接件的触发会话的默认运行模式写成 `bypass-permissions` | **不作数**——治理类，[加载时就滤掉](design.md#57-工作区那一级不参与权限计算) |
| 一条外部事件在内容里写明要进哪个会话、以谁的身份处理、按 `bypass-permissions` 跑 | **一样都不起作用**：进哪个会话、开不开新会话、身份、运行模式都只来自持有上的配置或会话自己；外部内容只决定它是目录里的哪一种 |
| 一件拓展件注册时声明「不在时否决」，组织或租户想在自己那层把它改成「跳过」 | **没有这个配置项**——不可用处置是[这一件自己的声明](design.md#不可用处置是这一件自己的声明)，各层配不了；要不同的处置，就换一件 |
| 成员乙写了一个 tool，组织持有了它，哪一层都没另配「谁可以使用它」 | 乙的会话里**装得上**；同组织的成员丙的会话里**装不上**，丙的 agent 面前没有这一条——与斜杠命令「没有权限就等于没有」同一种样子 |
| 同上，但乙那个 tool 与一个 official 工具同名，组织持有它就是替换了 official 那一份 | 丙的会话里装的是 **official 那一份**——组织换上一份只给自己人用的实现，拿不走别的成员手里的 official |
| 一次运行正在跑，组织收回了丙对某个 tool 的「谁可以使用它」 | 这次运行**照样用得上**它；**下一次运行起**它不再装进丙的会话 |
| 打开一份 skill 的设置 | **没有「正文变体」「资源的取用方式」这两项**；看得到的只有作者自己声明的那些 |
| 组织超管想给组织接入的某个 MCP 接入点配一份凭据 | **没有这个操作**——组织那一层不持有 MCP 凭据；接入点照样接得进来、连接目标照样配得了，**每个成员在自己的租户层取自己那一份** |
| 组织超管想在组织层给一个连接件配鉴权绑定 | **同样没有这个操作**；每个人在自己的租户层配 |
| 组织接入了一个要 OAuth 的接入点，成员甲取了、成员乙还没取 | 甲的会话里它的动作**用得上**，对端认的是甲的账号；乙的会话里它的动作**不可用**，查得到原因——**甲取的那一份到不了乙那里** |
| 同一个人在两个租户身份下，各自经 OAuth 连同一个 MCP 接入点 | **对端看到两个账号**；一个租户身份下的会话，用不到另一个租户身份取的那一份 |
| 一个接入点要 OAuth、还没人取过，用户开始一次 run | **会话里没有任何一张卡片问他**；它的动作不可用，查得到原因 |
| 仓库带来的接入点要 OAuth | 挂上工作区之后**连不上**；把它收进租户层、在那里取了之后才用得上 |
| 对端撤了这一份，而一次执行尝试正在进行 | **这次尝试手上的动作清单不变**；下一次尝试开始前它的动作变成不可用 |
| 经 OAuth 取得的那一份到期续上了 | **没有人被打扰**，也看不到一次「设置被改」 |
| 任何屏、机读输出、调试输出 | **搜不到 MCP 凭据的值**；只看得到有没有、哪一层的、什么时候取的 |
| 打开设置页 | **分成两块**：一块是跟着人走的界面偏好（语言、时区），一块是这个组织 / 租户持有的资产各自的设置与权限；换一个组织，前一块不变、后一块跟着变 |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 存在一份**独立于资产维护**的设置字段表 | 它会与资产各自演化，最终对不上。设置页必须是持有关系的函数 |
| 成员绕过组织的 immutable，改掉被锁死的值 | 强制形同虚设。**安全事故** |
| 组织换上的安全组件**没进**某个 plugin，而 plugin 里还是旧的 | 漏洞正好留在 plugin 里。这是"引用指向能力标识"要防的正是这件事。**安全事故** |
| 同一类里两份**同名**的资产在求值结果里**并存**，各算各的 | 身份被当成了 name 之外的东西（参数形状、说明、实现包）。**替代因此失效**——组织换上的那份没顶掉 official |
| 某个 official 能力标识在求值结果里**空着** | agent 组装不出来，或以残缺形态跑起来 |
| **工作区配的禁用值，关掉了组织或租户提供的资产** | 一个目录从旁边绕开了组织的管理决定——**而那条决定本来是「下面开不回来」的**。[§5.7 要防的正是这件事](design.md#57-工作区那一级不参与权限计算) |
| **同一个目录换一个租户身份挂上去，看到的还是上一个租户那批资产与配值** | 工作区没有挂在租户下，**这是一条跨租户泄漏路径**。**安全事故** |
| **工作区配的设置值，压过了上层已经加锁的那一项** | 一个目录把 immutable 绕过去了。**安全事故** |
| **会话没指定工作区，却有某个目录里的配置被加载了进来** | 隐式吃了一份跟别人代码一起来的配置——[工作区是 opt-in 的](design.md#它是会话选用的不指定就是空)，[§5.7](design.md#57-工作区那一级不参与权限计算) 防的正是这条路。**安全事故** |
| **工作区里写的一项权限真的生效了**，不管是放宽还是收紧 | 那条路本来就不该走——**一个仓库不能给自己提权**，也不该握着把工具全收成不可用的开关。**安全事故** |
| 改一项设置，结果**换掉了一个资产** | 两轮合成被混为一谈 |
| 组装时悄悄跳过一个**找不到提供者**的引用 | agent 少了零件却照跑，没人知道 |
| 成员退出组织后，他创作的资产**跟着走了** | 组织范围的产出不该变成个人资产 |
| 成员退出组织后，他的**署名被抹掉** | 作者记录是历史事实，不是当前成员名册 |
| 超级管理员能读到成员**租户级**的私有配置 | 管理权越界。作用域是组织，不是成员的私有部分 |
| 一个层能为**它不持有**的资产配值 | 为不存在的东西设边界，既无意义又无法解释 |
| 租户把组织给的拓展件干预力**从「只观察」改成「可否决」** | 干预力被当成了设置走覆盖。**它是权限，只能收窄**——组织的边界当场失效，**安全事故** |
| 同一个位置装了两个拓展件，结果**只跑了一个** | 把「位置」误当成了能力标识，**第二个被静默丢掉** |
| 装了拓展件之后，agent 面前**多出一条工具** | 拓展件组合了 Tool。agent 拿到了一件没被授予的动作 |
| 已发布的版本被**就地改写** | 消费方脚下的地基变了而不自知 |
| **工作区带来的资产，权限取了它自己声明的值** | 仓库替自己定了权限——声明「自动」的 MCP 克隆下来就能静默外发。**安全事故** |
| 一次执行尝试的中途，agent 面前的 MCP 工具条目**变了** | 对端的变化没有等到下一次尝试，agent 在一次尝试里看到两个不同的动作空间 |
| **同标识替换之后，外层锁下的权限管不住替换它的那一份** | 替换成了绕开锁的后门——换一份同名的实现就把组织的边界甩掉了。**安全事故** |
| **外层给原来那一份配的凭据，落到了替换它的那一份上** | 一把凭据交给了另一份实现，**对端以租户的账号认一份租户没选过的东西**——比如仓库带来的那一份。**安全事故** |
| **组织那一层的一份 MCP 凭据或鉴权绑定，被带到了成员的机器上** | 人离职时收不回——[正是被排除的那条路](design.md#mcp-凭据一份持有一份静态的或经-oauth-取得的) |
| **仓库带来的本地命令型 MCP 接入点或命令型 hook，挂上工作区就跑了起来** | 一个仓库在没有任何人点头的情况下在宿主机上跑了自己写的命令。**安全事故** |
| 连接件送进来的 `/xxx` **触发了一条系统业务流程** | 外部来源替人触发了只该由人发起的事——**斜杠命令只由交付面识别** |
| 人敲一个 ② 型命令，展开了一个他**无权使用**的 skill | 命令成了绕开 skill 权限的后门 |
| **连接件送进来的消息，以对面那个账号的身份被处理了** | 外部来源借连接件，以一个本系统不认识的名义让 agent 做事——放行、成本、隔离都挂不上。**安全事故** |
| **一个人判下来不能用的资产，装进了他的会话，用的时候才被拒** | 多出第二种失败：「有、但我不能用」；「各类共用同一项」只剩一个名字 |
| **组织换上一份只给自己人用的实现，别的成员因此连 official 那一份也没有了** | 组织行使了一项 [PF-001 说谁都没有](../PF-001-identity-scope-and-agent-constraints/design.md#来源official-与-customized)的权力：不许成员用 official |
| 人敲一条他**没有权限用**的命令，得到一句与「没有这个命令」**不同**的回答，或它被当成一句话送进了会话 | 「无权限就是不存在」破了：多出第二种失败，或一条他不能用的命令变成了内容 |
| **权限收回之后**，那个人在同一个会话里还敲得出那条命令 | 收回的权限等 reload 才生效——**成了空话** |
| 组织改了一条 ① ② 型命令，**没人发 reload**，开着的会话里那条命令就变了 | 命令集在人不知情时自己变了，同一个名字两次展开的不是同一段话 |
| 一条 ① ② 型命令的名字带着 `omne-official` 前缀发布成功 | 保留名的前缀被占，**一个名字从此可能有两种解释** |
| **外部内容选中了它的事件类型之外的任何东西**——进哪个会话、开不开新会话、以谁的身份、按什么运行模式 | 一个外部来源替人决定了去处、身份或放行。**安全事故** |
| **一份没给触发会话的默认运行模式的连接件，开出了一个新会话**（系统替它挑了一档，或拿了作者的默认） | 一个无人值守的会话在没人想过「本该问人时怎么办」的情况下跑起来了 |
| **目录外或未订阅的类型被悄悄丢掉**，或者被收进了会话 | 前者：来源以为送到了、谁也不知道没送到；后者：agent 收到了它事先不知道会来的东西，说明也对不上 |
| **agent 上下文里出现了没订阅的事件类型的说明** | agent 等一种永远不会来的消息，或把收进来的认错 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 设置页是长出来的 | 加一个资产、不碰任何配置代码，表单自己出现；移除后自己消失 | 需要有人去某处登记这个资产有哪些字段 |
| 两轮合成分开 | 改一项设置，检查生效的资产**还是原来那一个** | 改设置导致资产被换 |
| 引用指向能力标识 | 组织替换某 skill 后，**随便挑一个含它的 plugin**，跑起来用的是新的 | plugin 里还是旧的 |
| immutable 真的锁得住 | 在租户层尝试覆盖被锁的值，**每一条路径**都被拒 | 有某条路径能绕过去 |
| 移除与禁用可分辨 | 分别做一次，**看设置页**：一次表单消失、值也没了，一次表单还在并标着已禁用、值原样留着且能启用回来。**agent 那一侧两次表现相同** | 两个动作在设置页上也看不出差别；或者禁用之后 agent 还装得上它 |
| official 不可清空 | 尝试在各层移掉某个 official 能力标识，求值结果**仍有东西** | 求出空集而系统没报错 |
| 工作区只禁得掉自己那批 | 让工作区分别对**自己提供的**和**组织提供的**两个资产配上禁用：**前一个不可见，后一个照常可见** | 后一个也被关掉了 |
| 工作区的设置压过租户，但压不动锁住的 | 同一项设置，租户配一个、工作区配一个：**工作区那个赢**；随后让组织把它锁死，**每一条路径**工作区都改不动 | 工作区改不动没锁的，或改得动锁了的 |
| 工作区按租户隔离 | 同一个目录用两个租户身份各挂一次，两边的资产与配值**互不可见** | 一边读得到另一边的 |
| 工作区是 opt-in 的 | 同一个目录里起两个会话，一个创建时指定了它、一个没指定：**前者那一级有内容，后者那一级为空** | 没指定的那个也加载了 |
| 工作区的内容自动进来 | 承载目录里放好特定命名的配置文件，建会话时指定它，**不做任何导入动作**，装配结果里就有那些资产与设置值 | 还要人手动导一次 |
| 权限一概不从工作区来 | 在工作区里写一项放宽的、再写一项收紧的，**两项都不作数** | 有一项生效了 |
| 组合图无环 | 构造一个环，**在定义时就被拒**，而不是组装时挂起；Skill 与 Tool 互相声明**不被拒** | 组装超时或栈溢出；或把 Skill⇄Tool 当成环拒掉 |
| 替换是一条路径 | 对每一个锁了权限的能力标识，分别让租户、工作区各换上一份同名的，**每一条路径**上锁都照样管着 | 有某一层的同名实现逃出了锁 |
| 不锁的是挑选 | 组织给某项权限配「问一下」不锁，成员配「自动」：**生效「自动」**；组织改成锁住，同一操作**生效「问一下」**；组织改配「禁止」、不锁，同一操作**生效「禁止」** | 不锁时求出空集或仍是「问一下」；锁了之后成员的值生效；不锁的「禁止」被成员挑掉 |
| 干预力走收窄 | 组织锁一档、租户尝试放宽，**每一条路径**都被拒 | 有某条路径能放宽 |
| 位置不是能力标识 | 同一位置装两个不同拓展件，**两个都被调到** | 只跑了一个 |
| 作者记录稳定 | 换岗、退出各做一次，署名不变 | 署名随成员关系变化 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| 资产怎样被发现、装载、卸载 | 运行时装载另有归属，本 topic 只定它由什么构成 |
| 谁能创作、怎么发版、怎么上架 | 开发与发布流程另有归属 |
| 某个具体 tool 到底有哪几项配置 | 本 topic 定「设置是资产的属性」这个结构，具体字段属那个 tool 自己的定义 |
| 资产怎样在组织之间流动 | 归 [PF-003](../PF-003-asset-transfer-and-sharing/README.md)，它定义资产复制与分享两个动作 |
| Skill 套 Skill、Plugin 套 Plugin、Plugin 装 Agent Definition | 本版**刻意不做**，见 design.md §4。真有需要再加 |
| **共享的、人人可见的工作区** | 本版每一份[工作区](design.md#工作区)都属于某一个租户，[公共工作区刻意不做](design.md#非目标) |
| **目录之外的工作区承载形态**、**承载目录里哪些文件会被解析** | [本版不定义](design.md#非目标)。验收只看「有这样一类文件，挂上就自动加载」 |
| **斜杠命令能触发的系统业务流程，除 reload 之外还有哪几条**、任一条（含 reload）怎么实现 | [本版不枚举](design.md#非目标)。验收只看「③ 是一种绑定目标、敲下去不进队列」，以及 reload [只重填它对应的那一张注册表、不是完整的重新装配、不打断正在跑的运行](design.md#会话认得哪些命令什么时候变) |
| **组织或租户自己创作 ③ 型命令** | [本版不开放](design.md#非目标)，将来的拓展点 |
| 会话与 agent runtime 的生命周期 | 本 topic 定 Agent Definition 是静态定义，跑起来之后的事归 [PF-004](../PF-004-agent-definition-and-assembly/README.md) 与 [PF-012](../PF-012-agent-loop-and-run/README.md) |
| **一共有哪些拓展点位置**、每个位置看得见什么改得动什么、同位置多个挂件怎么依次过 | 归 [PF-012 §5.8](../PF-012-agent-loop-and-run/design.md#58-loop-拓展点)。本 topic 只定**拓展件是一类资产**、它的形状与组合，以及[同位置几件的先后取装配清单里的顺序](design.md#loop-extension) |
| **只送一个标识、回头去拉内容的投递（薄信封）** | [本版不支持](design.md#非目标)，只支持消息包整份随信封进来 |
| **会话怎么开口接收连接件的投递、连接件开出来的新会话以哪个 agent definition 与哪个租户身份建** | 归会话那一块（[PF-015](../PF-015-session-lifecycle-and-ownership/README.md)）；本 topic 只验收两种投递方式各自的主体与本 topic 这一侧的配置 |
| **被订阅的事件类型的说明怎么带进上下文** | 归 [PF-010](../PF-010-context-management-and-assembly/README.md)。本 topic 只验收「带的只有订阅了的那几种」 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
