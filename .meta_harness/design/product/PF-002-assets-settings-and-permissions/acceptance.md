# PF-002 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

| 场景 | 应当看到什么 |
|---|---|
| 给组织加入一个 tool | 设置页上**自动多出**这个 tool 的配置表单，无需任何人去配置设置页 |
| 加入一个 plugin | 它内含的 skill、tool、slash command **一并进来**，各自的表单也一并出现 |
| 移除那个 plugin | 内含的东西**一并退场**，表单一并消失 |
| 试图单独卸载 plugin 里的某个 skill | **被拒绝**。内含成员不取得独立生命周期 |
| 组织给某 tool 的执行权限配「问一下」，不加锁 | 成员可以在自己租户里改成「自动」 |
| 组织给某 tool 的执行权限配「问一下」并**加锁** | 成员改不了，且被告知**这是组织锁定的** |
| 组织放入一个自定义 skill，能力标识与某 official 相同 | 该组织下所有引用这个能力标识的地方**都用上了新的**，包括**别人打的 plugin 里面那个** |
| 组织把自己的自定义安全组件标为 immutable | 成员无法把它换回 official，也无法换成自己的 |
| 成员在个人组织里替换 official | **允许**——official 永远可被替代 |
| 某个 official 能力标识被所有层都移掉 | **失败**，并指出这是缺陷。official 是最小必需 |
| 组织**移除**某工具后，成员问 agent 能不能做那件事 | agent 说做不到，**说不出为什么**——它不知道有这回事 |
| 组织**禁用**某工具后，同样的提问 | agent 说明**这项被组织关掉了**，成员知道可以去申请 |
| agent definition A 引用 B 作 sub-agent，B 又引用 A | **拒绝**，并指出环在哪 |
| agent definition 引用的能力标识无人提供 | **明确失败**，指出缺哪个；不悄悄少装一个零件继续跑 |
| 成员在组织范围发布一个 skill，随后换了岗位 | 署名**照旧**——角色不进租户身份 |
| 该成员随后退出组织 | skill **留在组织**，署名**仍然照旧**；它记的是当时是谁做的 |
| agent 在某租户下产出一个 skill | 作者是**那个租户**，且记录标明**由 agent 产出** |
| 查看一个 official 资产的作者 | 是**平台**，不是某个租户 |
| 一个已发布的版本 | **不可变**。有新版本时**不静默替换**已选用的那个 |
| 资产在 agent 运行中被移除 | **已经开始的调用不受影响**；下一次准入才按新结果判 |
| 组织为它**并不持有**的资产配权限 | **被拒绝**。配置权不能凭空出现 |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 存在一份**独立于资产维护**的设置字段表 | 它会与资产各自演化，最终对不上。设置页必须是持有关系的函数 |
| 成员绕过组织的 immutable，改掉被锁死的值 | 强制形同虚设。**安全事故** |
| 组织换上的安全组件**没进**某个 plugin，而 plugin 里还是旧的 | 漏洞正好留在 plugin 里。这是"引用指向能力标识"要防的正是这件事。**安全事故** |
| 某个 official 能力标识在求值结果里**空着** | agent 组装不出来，或以残缺形态跑起来 |
| 改一项设置，结果**换掉了一个资产** | 两轮合成被混为一谈 |
| 组装时悄悄跳过一个**找不到提供者**的引用 | agent 少了零件却照跑，没人知道 |
| 成员退出组织后，他创作的资产**跟着走了** | 组织范围的产出不该变成个人资产 |
| 成员退出组织后，他的**署名被抹掉** | 作者记录是历史事实，不是当前成员名册 |
| 超级管理员能读到成员**租户级**的私有配置 | 管理权越界。作用域是组织，不是成员的私有部分 |
| 一个层能为**它不持有**的资产配值 | 为不存在的东西设边界，既无意义又无法解释 |
| 已发布的版本被**就地改写** | 消费方脚下的地基变了而不自知 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 设置页是长出来的 | 加一个资产、不碰任何配置代码，表单自己出现；移除后自己消失 | 需要有人去某处登记这个资产有哪些字段 |
| 两轮合成分开 | 改一项设置，检查生效的资产**还是原来那一个** | 改设置导致资产被换 |
| 引用指向能力标识 | 组织替换某 skill 后，**随便挑一个含它的 plugin**，跑起来用的是新的 | plugin 里还是旧的 |
| immutable 真的锁得住 | 在租户层尝试覆盖被锁的值，**每一条路径**都被拒 | 有某条路径能绕过去 |
| 移除与禁用可分辨 | 分别做一次，观察 agent 的回答：一次说不出原因，一次能说明被关掉 | 两个动作产生同样的结果 |
| official 不可清空 | 尝试在各层移掉某个 official 能力标识，求值结果**仍有东西** | 求出空集而系统没报错 |
| 组合图无环 | 构造一个环，**在定义时就被拒**，而不是组装时挂起 | 组装超时或栈溢出 |
| 作者记录稳定 | 换岗、退出各做一次，署名不变 | 署名随成员关系变化 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| 资产怎样被发现、装载、卸载 | 运行时装载另有归属，本 topic 只定它由什么构成 |
| 谁能创作、怎么发版、怎么上架 | 开发与发布流程另有归属 |
| 某个具体 tool 到底有哪几项配置 | 本 topic 定「设置是资产的属性」这个结构，具体字段属那个 tool 自己的定义 |
| 个人与组织之间的资产共享、携入、转让 | 归下一个 topic |
| Skill 套 Skill、Plugin 套 Plugin、Plugin 装 Agent Definition | 本版**刻意不做**，见 design.md §4。真有需要再加 |
| 会话与运行实例的生命周期 | 本 topic 定 Agent Definition 是静态定义，跑起来之后的事另有归属 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
