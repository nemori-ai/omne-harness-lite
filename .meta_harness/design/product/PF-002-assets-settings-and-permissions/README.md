# PF-002：设置、权限与资产的展开

**[PF-001](../PF-001-identity-scope-and-agent-constraints/README.md) 把设置、权限、资产
三者定为「范围化对象」，说清了它们对外的样子——挂在哪一层、多层同时有值时怎么合成。
本 topic 把这三者展开：它们各自是什么，彼此之间是什么关系。**

一句话概括本 topic 的结论：**三者都是组合关系上的东西。**
资产之间组合，资产组装成 agent 也是组合；而设置与权限**附着在具体资产上**，
与资产之间同样是组合关系。

| `extends` | 无 |

**与 PF-001 的分界**：同一个字段在多层都有值时听谁的，归 PF-001；
有哪几类资产、一个 plugin 里装了什么、一个 tool 的执行权限长什么样，归这里。
判据是**改动它的原因**——PF-001 因身份模型变，本 topic 因对象的种类或组合形状变。

## 状态

- 产品设计：**rev 17**。rev 16 已定稿；**rev 17 待产品负责人确认**（各 rev 改了什么见[变更历史](changelog.md)）。现行要点：每一类资产的[身份是「类别 ＋ name」](design.md#身份是类别--name其余归实现)，
  其余归实现，**一层对一个身份至多持有一份**；配值的最小单位是[属性配值](design.md#组织的设置是视图不是对象)，**挂在资产持有上**；
  权限[**锁下的是界、各层取交集，不锁的只是在界里挑**](design.md#53-两个例子两种合成)；[同标识替换之后，**权限的界跟着身份走、设置的值跟着资产走**](design.md#替换是一条路径不是一扇后门)；
  [「谁可以使用它」是各类资产共用的一项权限](design.md#谁可以使用它是各类资产共用的一项权限)，**权限项只有各类别列出的那些**；
  [三条层序各答一个问题](design.md#58-三条层序各答一个问题)——**设置是覆盖、同身份的资产是替换、权限是忽略，除非上面锁了**；
  [工作区](design.md#工作区)是**租户持有的一级归属、由目录承载而不是目录本身**，**会话创建时显式指定、不指定就空**，
  挂上就在装配时[自动加载承载目录里的特定文件](design.md#挂上之后它的内容在装配时自动进来)，**只禁得掉它自己提供的那批资产**；
  [禁用](design.md#禁用是逐层配的布尔设置任一层为真即不可见)是逐层配的布尔设置，**任一层为真即不可见**，
  [不可用](../PF-006-tools-and-skills/design.md#63-不可用时装的是同名替换件不是不装)则是**可见但用了一定失败**；
  [设置项分四类](design.md#设置项分四类资产声明每一项时必须标类别)——**落点与身份类和 `immutable` 与权限一样不从工作区来**；
  [official 可被替代，除 meta 与上层锁了的](design.md#55-资产替换的层级)，**同标识替换必须可见**；
  求值[先禁用滤、再同标识取最具体](design.md#56-四步资产求值--组装--投影--层级计算)，**被禁的退出替换、标识退回下一层**；
  [工作区提供的资产，权限项取最严值](design.md#57-工作区那一级不参与权限计算)——执行权限「问一下」、干预力「只观察」、各项「谁可以……」= 挂上它的那个租户本人；
  **仓库带来的本地命令型 MCP 接入点与命令型 hook 默认不启用**，由持有这份工作区的租户逐件打开；
  [同一位置上几件拓展件的先后 = 装配清单里的顺序](design.md#loop-extension)；[Plugin 的「启用哪些成员」是唯一改组合的设置](design.md#56-四步资产求值--组装--投影--层级计算)，组装展开到它时就地求值；
  [斜杠命令](design.md#slash-command)的绑定目标恰有三种——**自定义提示词、一个 skill、一条系统业务流程**，绑定目标与参数声明**是命令本身、不是设置**，**只由交付面识别、只对人**，保留名**一律在 `omne-official` 前缀下**，带声明的参数**解析不通过就当场明说、不发送**；
  [一个会话认得哪些命令](design.md#会话认得哪些命令什么时候变)在装配时定下，**没有权限就等于不存在**，① ② 型的增删禁用**等人发 reload 才进来**，③ 型本版只由系统提供；
  [MCP](design.md#mcp) 的每个动作是一个工具条目，**每一次执行尝试开始前重算、一次尝试之内不变**；[MCP 凭据](design.md#mcp-凭据一份持有一份静态的或经-oauth-取得的)**静态的或经 OAuth 取得的是同一项设置**，一份持有一份、由有配值资格的人在配值处取，**不出卡片、不由 agent 或 run 发起**，没取到或失效就是连不上；[连接件](design.md#connector)带身份鉴权，接对面哪个账号是持有上的落点与身份类设置，**投递目标本版只能是一个已有的会话**
- 未决项：**四项**（[§九](design.md#九未决项)）——组织那一层能不能持有 MCP 凭据（连接件的鉴权绑定同一道题，不挡 OAuth 开工）；「谁可以使用它」在组织、租户持有的资产上怎么判；Skill 的「正文变体」与「资源的取用方式」是什么；Connector 的两项权限取什么值
- 待裁决：**四项**（D-1～D-4，同上），见 [decisions §三](decisions.md#三待裁决)
- 技术投影：**尚未开始**
