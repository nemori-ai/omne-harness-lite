# PF-002 流程与状态

**连接件范围搁置**：本页中连接件专属的流程与验收仅保留为条件性材料，不构成当前交付要求；是否保留该资产待重新确定。
`design.md` 说这块产品**是什么**，本页说它**怎么动**。
查「这步失败了怎么办」来这里，查「这个概念是什么」去 design.md。

## 一、主要旅程

### 1.1 给组织加一个资产

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 该组织的超级管理员 | 选定一个资产（可能是 plugin，里面带着一批东西） | — |
| 2 | 系统 | 该范围**持有**这个资产 | 资产进入这个组织的可用集合 |
| 3 | 系统 | 该资产自带的设置项与权限项，**自动在设置页长出对应表单** | 管理员能看见并配置它 |

**第 3 步不需要任何人去"配置设置页"。**表单是资产带来的，
见 [design.md §6.1](design.md#61-设置页是长出来的不是画出来的)。

进入组织可用集合不等于进入每个 agent 的构成。Skill、Tool、MCP 是否被选入，继续经
[PF-004 的绑定规则](../PF-004-agent-definition-and-assembly/design.md#skilltoolmcp-的绑定规则)判断；
关闭自动继承的定义不会仅因组织增加资产就自动增加能力，类型要求与定义显式依赖仍须满足。

加进来的若是 **plugin**，它[内含的成员](design.md#plugin)**一并进来**，
各自的表单也一并出现。它们**不取得独立的生命周期**——不能单独卸载其中一个。

### 1.2 配置一个资产的设置或权限

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 持有该资产的归属层（组织、租户或[工作区](design.md#工作区)） | 给某一项配一个值 | 这一级的那份持有上记下了一个[属性配值](design.md#组织的设置是视图不是对象) |
| 2 | 配置者 | 可选：把它标为 **immutable** | 更具体的那些级不能再覆盖它 |

**配值的资格来自持有。**不持有这个资产的层，配不了它的项——
组织没有这个工具，就配不了这个工具的执行权限。

**不标 immutable = 默认**（可被更具体的一级改）；**标了 = 强制**（改不了）。
**权限项上，标了的是一道界**——可以锁成一个值，也可以锁成几档里的一部分；
**没标的只是在界里挑一个**，更具体的一级挑的更算数（[design.md §5.3](design.md#53-两个例子两种合成)）。

**工作区那一级的值来自实例中的 `.omne` 与 `.omne.local`，共用实例的各会话按各自租户身份求值，[会话装配时自动解析](design.md#挂上之后它的内容在装配时自动进来)**——
用户通过相应目录内容表达共享或本地定制，不因此在租户治理入口之外再取得一份权限配值资格；[会话没挂工作区，这一级就没有值](design.md#它是会话选用的不指定就是空)。
两目录候选先经禁用与使用资格过滤，可用内容取并集，同能力资产 local 优先；上层锁定与工作区权限过滤照常成立。
挂上了，按[同一条覆盖次序](design.md#58-三条层序各答一个问题)压过租户；
**唯独权限项不从它这里来**（[design.md §5.7](design.md#57-工作区那一级不参与权限计算)）。

### 1.3 用自定义资产替换 official

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 组织或租户 | 放入一个自定义资产，其**能力标识**与某个 official 相同 | — |
| 2 | 系统 | 在这一层及以下，该能力标识生效的是这个自定义资产 | 求值结果指向新的那个 |
| 3 | 系统 | **所有引用该能力标识的 plugin 与 agent definition 自动用上新的** | — |

第 3 步是[引用指向能力标识](design.md#63-组合的引用指向能力标识)的直接后果。

**换上之后，外层管这个身份的界照样管着新的这一份**：组织把这项执行权限锁在「问一下」，
租户换上一份同名的、再配「自动」，仍然每次都问。**外层给原来那一份配的设置值不跟过来**——
新的这一份用它自己这一层配的值与它自己声明的默认值（[design.md §5.5](design.md#替换是一条路径不是一扇后门)）。

**此流程只适用于允许替换且未锁定的资产**：meta、official Agent Definition 及上级锁定的持有不得被越级替换，见 [§5.5](design.md#55-资产替换的层级)。替换之后该能力标识下仍然有东西，不得清空。

### 1.4 组织锁死一个自定义资产

场景：公司换上自己的审计组件，不许任何成员换掉。

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 组织超级管理员 | 放入自定义资产 | 组织层生效 |
| 2 | 组织超级管理员 | 标记为 **immutable** | 租户层的替换被拒绝 |

**锁的是组织自己那一层的持有，持有 official 也可以锁**，租户和工作区均不得替换；租户同样可锁定自身持有，阻止工作区替换。meta 与 official Agent Definition 本身的不可替换不依赖这些层另行加锁。

### 1.5 不让成员用某个工具

两个动作，**选哪个取决于是收回持有还是暂时关掉**（[design.md §6.4](design.md#64-移除与禁用是两个动作)）：

| 动作 | 步骤 | 结果 |
|---|---|---|
| **移除** | 该范围不再持有它 | 组装时装不上；设置页里那块表单**消失**，配的值随之没了 |
| **禁用** | 保留持有，本层把[「禁用」这项设置](design.md#禁用是逐层配的布尔设置任一层为真即不可见)配成真 | 组装时被滤掉，同样装不上；设置页那块表单**还在**、标明已禁用，**配的值原样留着**，可以再启用回来 |

对从未合法纳入的能力，两者都阻止新增；对会话已知能力，两者生效后保留不可用替换件，不删除身份。
**成员要知道自己少了什么、能不能去申请，看的是设置页。**

### 1.6 组装一个 agent

四步，**顺序不能换**（[design.md §5.6](design.md#56-四步资产求值--组装--投影--层级计算)）：

| 步 | 发生什么 | 失败时 |
|---|---|---|
| 1 | 按[资产归属那条层序](design.md#58-三条层序各答一个问题)求出这个租户**有哪些资产可用** | 目标范围不可用时**明确失败**，不静默回退 |
| 2 | 从 agent definition 沿组合图展开，得到**实际装上的资产** | 引用的能力标识无人提供 → 见下方异常表 |
| 3 | 这些资产各自的属性项，**构成这次的项集合** | — |
| 4 | 逐项按层级求值，得到**这次实际用的值** | — |

### 1.7 创作一个资产

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 获授权的成员，或在该范围下运行的 agent | 在某个范围里创作 | 产生草稿 |
| 2 | 创作者 | 修订草稿 | 草稿可反复改 |
| 3 | 创作者 | 发布 | **该版本自此不可变**；再改形成新版本 |

**所有者与作者分别记录**：在组织范围创作的，所有者是组织，
[作者是那个租户](../PF-001-identity-scope-and-agent-constraints/design.md#67-创作与归属)。
agent 产出的要标明是 agent 产出。

## 二、分支与异常

| 情形 | 系统怎么做 | 为什么 |
|---|---|---|
| 组合图成环：沿引用展开会回到自己（Agent Definition A 把 B 当 sub-agent，B 又把 A 当 sub-agent） | **拒绝**，指出环在哪 | 否则组装永远算不完。[Skill 与 Tool 互相引用不在此列](design.md#谁能组合谁)——两边各装一份就完，展开得完 |
| agent definition 引用的能力标识**无人提供** | **明确失败**，指出缺哪个 | 悄悄少装一个零件，agent 会以一个残缺的形态跑起来，而没人知道 |
| 租户想替换一个被组织标为 immutable 的资产 | **拒绝**，说明是组织锁定的 | 让成员知道这不是系统故障，也不是他权限不够可以去申请 |
| 一个层想为**它不持有**的资产配值 | **拒绝** | 配置权不能凭空出现 |
| 某个 official 能力标识在求值后**没有任何东西** | **失败**，这是缺陷不是配置结果 | official 是最小必需，任何层不得把它清空 |
| 移除一个还被其他资产引用的东西 | **先告知受影响的引用**，不默认级联删除 | 见 PF-001 §6.8 |
| plugin 的内含成员被单独卸载 | **拒绝** | 内含成员随 plugin 治理，不取得独立生命周期 |
| 资产在运行中被替换或移除 | **不影响已经开始的调用** | 撤销影响的是下一道尚未通过的准入，见 PF-001 §6.6 |
| 一个 MCP 接入点的 [MCP 凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-mcp-credential--mcp-凭据--mcp-credential)**还没取、或已经失效**（对端撤了、续不上） | **下一次执行尝试开始前连不上，它的动作一律不可用**；不在会话里弹卡问人。有资格给那份持有配值的人去重新取一次，下一次尝试就好 | 取值就是配值，不归 run；[连不上就是不可用](../PF-006-tools-and-skills/design.md#接入点连不上它的动作就是不可用)，不另立规则 |
| 组织那一层想给一个 MCP 接入点配 MCP 凭据，或给一个连接件配鉴权绑定 | **拒绝**，说明这两项只在租户那一层配、每个成员自己取 | [组织那一层不持有它们](design.md#mcp-凭据一份持有一份静态的或经-oauth-取得的)：发到每台机器上的那一份，人离职时收不回 |
| 挂上的工作区里带着一个**以本地命令方式接入的 MCP 接入点**，或一件**导入成拓展件的命令型 hook** | **不启用**，装配时和禁用的一样不可见；本次会话所属且获准使用该工作区的租户在自己的设置里打开它，之后[照资产增减生效的时点](../PF-004-agent-definition-and-assembly/design.md#63-三类变化三种传播)进来 | 挂上就跑，等于在宿主机上跑仓库写好的命令，[权力不从项目里来](design.md#57-工作区那一级不参与权限计算) |

## 三、状态流转

### 3.1 一个资产在某个范围里

```text
（未持有）──加入──→ 持有·启用 ──禁用──→ 持有·禁用
                       │   ↑                  │
                       │   └──────启用────────┘
                       └──移除──→（未持有）
```

| 从 | 到 | 触发 | 前置条件 | 设置页上的表现 | 组装时 |
|---|---|---|---|---|---|
| 未持有 | 持有·启用 | 加入 | 该范围的管理者——组织层是[超级管理员](../PF-001-identity-scope-and-agent-constraints/design.md#角色)，租户层是本人；若来自 plugin 则随 plugin 一并 | 表单**出现** | 可见 |
| 持有·启用 | 持有·禁用 | 禁用 | 该范围的管理者（同上） | 表单**仍在**，标明已禁用，**配的值原样保留** | 候选被滤掉；已知能力保留不可用条目 |
| 持有·禁用 | 持有·启用 | 启用 | 同上；**只去得掉本层自己配的那个真** | 表单恢复可用，**值还是原来那些** | 可见 |
| 持有（任一） | 未持有 | 移除 | 同上；先告知受影响的引用 | 表单**消失**，配的值随之没了 | 不新增；已知能力保留不可用条目 |

**这份持有上还挂着它的[属性配值](design.md#组织的设置是视图不是对象)**——这一级为它配的每一项值。
**配值跟着持有走**：移除，持有没了，配值随之消失；禁用，持有还在，**配值一个不丢**。

**第六列的不可见指当前资产候选被过滤。**已知 Tool／Skill／MCP 保留不可用条目；两种操作在管理侧仍不同，
差的是**配置还在不在、还能不能开回来**——那是成员在设置页上看得见的事。

**[「禁用」是每一层各配各的](design.md#禁用是逐层配的布尔设置任一层为真即不可见)**，
所以这张图是**某一层自己**的状态。上面一层配了真，下面一层就算自己这格是「持有·启用」，
**组装时照样不可见**——[任一层为真即为真](design.md#禁用是逐层配的布尔设置任一层为真即不可见)。

### 3.2 一份持有上、一个属性项的[属性配值](design.md#组织的设置是视图不是对象)

```text
（未配）──配值──→ 已配·可覆盖 ──加锁──→ 已配·immutable
                     │   ↑                    │
                     │   └──────解锁─────────┘
                     └──清除──→（未配）
```

| 状态 | 含义 | 更具体的那些级能做什么 |
|---|---|---|
| 未配 | 这一级没意见 | 沿用外面一级的结果 |
| 已配·可覆盖 | 「**默认**这样」 | 可以改 |
| 已配·immutable | 「**必须**这样」 | 改不了。**[工作区](design.md#工作区)那一级同样改不了** |

**这张图是某一级自己的状态**，[三条层序上的位置见 design.md §5.8](design.md#58-三条层序各答一个问题)。
**这份持有被移除，图上所有状态一起消失**——配值不脱离持有存在。

**解锁是允许的**，但它不回溯：解锁只影响此后的求值，
不改变解锁之前已经发生的事。

### 3.3 一个资产定义的版本

```text
草稿 ──反复修订──→ 草稿 ──发布──→ 已发布（不可变）
                                      │
                                      └──再改──→ 新的草稿 ──→ 新版本
```

**已发布版本不可变。**发现有新版本**不静默替换**已选用的版本——
选用哪个版本是消费方的决定。

**[版本选用](../../ubiquitous_language/terms/circulation-and-entitlement.md#ul-version-selection--版本选用--version-selection)记在持有上，有两种：钉在某一版，或追随当前版。**
不另说时是追随当前版；**追随是持有上写明、在设置页上看得见的一个选择**——
选了它，新版一发布，下一次求值就用上，这是持有者选的，不是静默替换。钉住的，持有者不改选就不换。

## 四、角色与操作

| 操作 \ 角色 | 组织超级管理员 | 组织普通成员 | 非成员 |
|---|---|---|---|
| 给组织加入 / 移除资产 | 可 | 不可 | 不可 |
| 配置**组织级**的设置与权限 | 可——**MCP 凭据与连接件的鉴权绑定除外**：[组织那一级不持有](design.md#mcp-凭据一份持有一份静态的或经-oauth-取得的)，他在自己租户级配 | 不可 | 不可 |
| 把组织级的值标为 immutable | 可 | 不可 | 不可 |
| 配置**自己租户级**的设置与权限 | 可 | 可 | — |
| 覆盖组织级的值 | 可 | **看组织有没有加锁** | — |
| 在组织范围创作、发布资产 | 可 | 有条件：按被授予的权限 | 不可 |
| 在自己个人组织里做上述一切 | 可 | 可 | — |

**超级管理员在自己那一栏里能做的事，作用域仅限该组织**——
他管得到组织级，管不到成员租户级的私有部分。

实现时遇到本表覆盖不到的组合，**回到产品设计确认，不要自行补一条**。
