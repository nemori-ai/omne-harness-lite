# PF-002 流程与状态

`design.md` 说这块产品**是什么**，本页说它**怎么动**。
查「这步失败了怎么办」来这里，查「这个概念是什么」去 design.md。

## 一、主要旅程

### 1.1 给组织加一个资产

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 有管理资格的成员 | 选定一个资产（可能是 plugin，里面带着一批东西） | — |
| 2 | 系统 | 该范围**持有**这个资产 | 资产进入这个组织的可用集合 |
| 3 | 系统 | 该资产自带的设置项与权限项，**自动在设置页长出对应表单** | 管理员能看见并配置它 |

**第 3 步不需要任何人去"配置设置页"。**表单是资产带来的，
见 [design.md §6.1](design.md#61-设置页是长出来的不是画出来的)。

加进来的若是 **plugin**，它[内含的成员](design.md#plugin)**一并进来**，
各自的表单也一并出现。它们**不取得独立的生命周期**——不能单独卸载其中一个。

### 1.2 配置一个资产的设置或权限

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 持有该资产的层（组织或租户） | 给某一项配一个值 | 这一层记下了这个值 |
| 2 | 配置者 | 可选：把它标为 **immutable** | 下层不能再覆盖它 |

**配值的资格来自持有。**不持有这个资产的层，配不了它的项——
组织没有这个工具，就配不了这个工具的执行权限。

**不标 immutable = 默认**（下层可改）；**标了 = 强制**（下层改不了）。

### 1.3 用自定义资产替换 official

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 组织或租户 | 放入一个自定义资产，其**能力标识**与某个 official 相同 | — |
| 2 | 系统 | 在这一层及以下，该能力标识生效的是这个自定义资产 | 求值结果指向新的那个 |
| 3 | 系统 | **所有引用该能力标识的 plugin 与 agent definition 自动用上新的** | — |

第 3 步是[引用指向能力标识](design.md#63-组合的引用指向能力标识)的直接后果。

**official 永远可被替代，但不可被清空**——替换之后该能力标识下仍然有东西。

### 1.4 组织锁死一个自定义资产

场景：公司换上自己的审计组件，不许任何成员换掉。

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 组织超级管理员 | 放入自定义资产 | 组织层生效 |
| 2 | 组织超级管理员 | 标记为 **immutable** | 租户层的替换被拒绝 |

**锁的是组织自己那一层。**official 处在最底层，本来就是被替换的对象，
不存在"把 official 锁住"这回事。

### 1.5 不让成员用某个工具

两个动作，**选哪个取决于是收回持有还是暂时关掉**（[design.md §6.4](design.md#64-移除与禁用是两个动作)）：

| 动作 | 步骤 | 结果 |
|---|---|---|
| **移除** | 该范围不再持有它 | 组装时装不上；设置页里那块表单**消失**，配的值随之没了 |
| **禁用** | 保留持有，本层把[「禁用」这项设置](design.md#禁用是逐层配的布尔设置任一层为真即不可见)配成真 | 组装时被滤掉，同样装不上；设置页那块表单**还在**、标明已禁用，**配的值原样留着**，可以再启用回来 |

**两者对 agent 是同一个结果：都不可见**——它装不上，也无从知道有过这回事。
**成员要知道自己少了什么、能不能去申请，看的是设置页。**

### 1.6 组装一个 agent

四步，**顺序不能换**（[design.md §5.6](design.md#56-四步资产求值--组装--投影--层级计算)）：

| 步 | 发生什么 | 失败时 |
|---|---|---|
| 1 | 按四层作用域求出这个租户**有哪些资产可用** | 目标范围不可用时**明确失败**，不静默回退 |
| 2 | 从 agent definition 沿组合图展开，得到**实际装上的资产** | 引用的能力标识无人提供 → 见下方异常表 |
| 3 | 这些资产各自的属性项，**构成这次的项集合** | — |
| 4 | 逐项按层级求值，得到**这次实际用的值** | — |

### 1.7 创作一个资产

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 获授权的成员，或在该范围下运行的 agent | 在某个范围里创作 | 产生草稿 |
| 2 | 创作者 | 修订草稿 | 草稿可反复改 |
| 3 | 创作者 | 发布 | **该版本自此不可变**；再改形成新版本 |

**所有者与作者分别记录**：在组织范围创作的，所有者是组织，
[作者是那个租户](../PF-001-identity-scope-and-agent-constraints/design.md#67-创作与归属)。
agent 产出的要标明是 agent 产出。

## 二、分支与异常

| 情形 | 系统怎么做 | 为什么 |
|---|---|---|
| 组合图成环（A 引用 B，B 又引用 A） | **拒绝**，指出环在哪 | 否则组装永远算不完 |
| agent definition 引用的能力标识**无人提供** | **明确失败**，指出缺哪个 | 悄悄少装一个零件，agent 会以一个残缺的形态跑起来，而没人知道 |
| 租户想替换一个被组织标为 immutable 的资产 | **拒绝**，说明是组织锁定的 | 让成员知道这不是系统故障，也不是他权限不够可以去申请 |
| 一个层想为**它不持有**的资产配值 | **拒绝** | 配置权不能凭空出现 |
| 某个 official 能力标识在求值后**没有任何东西** | **失败**，这是缺陷不是配置结果 | official 是最小必需，任何层不得把它清空 |
| 移除一个还被其他资产引用的东西 | **先告知受影响的引用**，不默认级联删除 | 见 PF-001 §6.8 |
| plugin 的内含成员被单独卸载 | **拒绝** | 内含成员随 plugin 治理，不取得独立生命周期 |
| 资产在运行中被替换或移除 | **不影响已经开始的调用** | 撤销影响的是下一道尚未通过的准入，见 PF-001 §6.6 |

## 三、状态流转

### 3.1 一个资产在某个范围里

```text
（未持有）──加入──→ 持有·启用 ──禁用──→ 持有·禁用
                       │   ↑                  │
                       │   └──────启用────────┘
                       └──移除──→（未持有）
```

| 从 | 到 | 触发 | 前置条件 | 设置页上的表现 | 组装时 |
|---|---|---|---|---|---|
| 未持有 | 持有·启用 | 加入 | 有管理资格；若来自 plugin 则随 plugin 一并 | 表单**出现** | 可见 |
| 持有·启用 | 持有·禁用 | 禁用 | 有管理资格 | 表单**仍在**，标明已禁用，**配的值原样保留** | **被滤掉，不可见** |
| 持有·禁用 | 持有·启用 | 启用 | 同上；**只去得掉本层自己配的那个真** | 表单恢复可用，**值还是原来那些** | 可见 |
| 持有（任一） | 未持有 | 移除 | 同上；先告知受影响的引用 | 表单**消失**，配的值随之没了 | 不可见 |

**「禁用」与「移除」的差别在第五列，不在第六列**：两者在组装时都不可见，
差的是**配置还在不在、还能不能开回来**——那是成员在设置页上看得见的事。

**[「禁用」是每一层各配各的](design.md#禁用是逐层配的布尔设置任一层为真即不可见)**，
所以这张图是**某一层自己**的状态。上面一层配了真，下面一层就算自己这格是「持有·启用」，
**组装时照样不可见**——[任一层为真即为真](design.md#禁用是逐层配的布尔设置任一层为真即不可见)。

### 3.2 一个属性项的值

```text
（未配）──配值──→ 已配·可覆盖 ──加锁──→ 已配·immutable
                     │   ↑                    │
                     │   └──────解锁─────────┘
                     └──清除──→（未配）
```

| 状态 | 含义 | 下层能做什么 |
|---|---|---|
| 未配 | 这一层没意见 | 沿用下面一层的结果 |
| 已配·可覆盖 | 「**默认**这样」 | 可以改 |
| 已配·immutable | 「**必须**这样」 | 改不了 |

**解锁是允许的**，但它不回溯：解锁只影响此后的求值，
不改变解锁之前已经发生的事。

### 3.3 一个资产定义的版本

```text
草稿 ──反复修订──→ 草稿 ──发布──→ 已发布（不可变）
                                      │
                                      └──再改──→ 新的草稿 ──→ 新版本
```

**已发布版本不可变。**发现有新版本**不静默替换**已选用的版本——
选用哪个版本是消费方的决定。

## 四、角色与操作

| 操作 \ 角色 | 组织超级管理员 | 组织普通成员 | 非成员 |
|---|---|---|---|
| 给组织加入 / 移除资产 | 可 | 不可 | 不可 |
| 配置**组织级**的设置与权限 | 可 | 不可 | 不可 |
| 把组织级的值标为 immutable | 可 | 不可 | 不可 |
| 配置**自己租户级**的设置与权限 | 可 | 可 | — |
| 覆盖组织级的值 | 可 | **看组织有没有加锁** | — |
| 在组织范围创作、发布资产 | 可 | 有条件：按被授予的权限 | 不可 |
| 在自己个人组织里做上述一切 | 可 | 可 | — |

**超级管理员在自己那一栏里能做的事，作用域仅限该组织**——
他管得到组织级，管不到成员租户级的私有部分。

实现时遇到本表覆盖不到的组合，**回到产品设计确认，不要自行补一条**。
