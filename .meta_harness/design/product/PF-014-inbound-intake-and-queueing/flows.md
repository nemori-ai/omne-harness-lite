# PF-014 流程与状态

`design.md` 说这块产品**是什么**，本页说它**怎么动**：
一条东西从外面送到，到它被处理完，中间经过哪些步骤；插队在几种停法下各走哪条路；
哪一步失败了用户看到什么。

**概念一律引用 [design.md](design.md)，本页不重新定义。**

---

## 一、主要旅程

### 旅程一：一条东西从外面送到，到被处理完

```text
   外面送到
      │
      ▼
  ① 能不能进这个会话？ ──否──→ 【具名拒绝】发的人知道，日志留一笔
      │是
      ▼
  ② 这条是不是已经来过？ ──是──→ 【去重】返回已经受理的那一条，不新增
      │否
      ▼
  ③ ◆「消息落盘之前」拓展点 ──否决──→ 【不受理】内容不进日志正文，
      │        （模态转换件转不成         但「有一条被拦下」留一笔
      │          也是否决）
      │通过（可能已被改写：脱敏；或挂上了派生表示：模态转换）
      ▼
  ④ 完整持久提交【入站事实 + 对应去处的责任】          ← 这里是提交点，也是唯一的提交点
      │
      ├──【进队列】──→ 队列非空 → loop 不退出，或在满足当前准入条件时开下一个运行（旅程二）
      ├──【落到卡片上】→ 让那个停住的位置继续 → 一次尝试的「停住等」结束
      └──【就地处置】→ 按已保存目标处置，实际生效另行确认（旅程三）
```

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| ① | 系统 | 判断目标会话存不存在、送的人够不够格 | 通过，或一条**说得出原因**的拒绝 |
| ② | 系统 | 按来源自己给出的「同一件事」判断是否重复 | 新的一条，或指回已受理的那一条 |
| ③ | [拓展件](../PF-002-assets-settings-and-permissions/design.md#loop-extension) | 只观察 / 改内容 / 否决 | [三档干预力各自的结论都留下了](design.md#56-消息落盘之前那一刻看得到什么) |
| ④ | 系统 | 成为一条[入站到达](design.md#入站到达)，**落进[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)**，同时[去处](design.md#三个去处)就定了 | **日志事实与对应去处的责任完整持久成立** |

**这条旅程只有一个提交点，就是第 ④ 步。**

> **④ 之前被拒（①）或被拦（③），这件事就没进来**——发的人要知道，因为他可能要改了再发。
> **④ 尚未提交成功就停机，没有已受理事实**——发送方保留原输入及同次提交标识，恢复后查询／自动重试。**④ 的回执未收到，结果只是未知**——查明提交事实，不能按未受理另发一条。责任边界沿 [§6.8](design.md#68-停机不会让一条入站到达永远悬着)，不要求人手重新输入。
> **④ 之后，它就不会凭空消失了**：要么被消费，要么被明确关掉，**两种都留痕**。

#### 落盘之后没有第二步「定落点」

**很容易在落盘之后再加一步「定一个落点并记下来」**，
而那一步要看**此刻这个会话有没有运行在跑**。**这一步不存在**：

> **[去处由它是什么决定，不由此刻处境决定](design.md#三个去处)**——
> 落盘那一刻就知道它是进队列、落到卡片上，还是就地处置。

**省掉它的收益很具体**：有了那一步，就有一个**会跨越停机存在的中间态**
（「已受理，落点未定」），系统回来时**得主动扫一遍、逐条补定**。
**没有那个中间态**——[落盘是不可分割的一步](design.md#68-停机不会让一条入站到达永远悬着)。

### 旅程二：一条排着的消息，什么时候被取走

```text
  已持久入队，仍有待处理资格
                │
                ▼
  当前存在未终结 Run？
       │是                      │否
       ▼                        ▼
  交给原 Run 的下一合法 T1     系统创建后继 Run
  原 Run 等待时不另起 Run     不依赖用户查看
       │                        │
       └─────────┬──────────────┘
                 ▼
       T1 持久承接此刻队列的全部
                 │
                 ▼
       退出待处理投影，原 Run 继续处理
```

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| 1 | 系统 | 按持久事实判断是否存在未终结 Run，不以队列原本空不空代替 | 同一会话至多一个未终结 Run |
| 2 | 系统 | 已有 Run 时交给它；没有时在满足当前准入条件后自动创建后继 Run，恢复后仍承担推进责任 | 没有因等待或停机重复开 Run，也没有输入永久悬空 |
| 3 | Loop | 到下一合法 T1，一次持久承接全部待处理消息 | 承接事实与退出待处理资格一致，原消息及承接历史保留 |

**队列非空不证明此刻已有 Run 或 Agent runtime。**停机后可以暂时没有执行实例；系统仍须自动恢复。已有 Run 在等待模型或工具时，队列也可以曾为空；新输入不因此另起 Run。完整边界沿 [PF-012 Run](../PF-012-agent-loop-and-run/design.md#run)。

**这一步不按来源挑**（不是「队首连续的用户消息取一批，斜杠命令与其他来源一项一个运行」）——
[理由见 §5.9](design.md#59-一个运行内部会多次取队列)。

### 旅程三：用户插队

```text
  用户发出【插队】
      │
      ▼
  ── 同一次提交里，三件事一起成立 ─────────────────────────────┐
  │                                                              │
  │  ① 按 loop 停在哪处置（下表）                                │
  │  ② 那句话放到待处理消息队列的队首                            │
  │  ③ 落下占位与提醒，写明原因                                  │
  └──────────────────────────────────────────────────────────────┘
      │
      ▼
  loop 走到 T1 ──→ 取走那句话（它在队首）──→ agent 带着它接着想
      │
      └── 运行【不落终态】，它一直活着
```

**① 那一步的几种停法：**

| loop 停在哪 | 动作 | 落下什么 | 之后回到 [PF-012 的哪一步](../PF-012-agent-loop-and-run/design.md#56-状态转移表) |
|---|---|---|---|
| **等模型回复** | 中断这次模型调用，**保留已到达的部分** | [一条标明被中断的消息 + 一条中断提醒](../PF-009-context-message-types/design.md#56-流断在半路) | 这一步的回复算完了，**被中断的回复不交出动作**（[参数已收齐的工具调用也不执行](design.md#54-插队停在哪就怎么办)）→ 那句话在队首 → T1 |
| **工具执行中，允许转后台** | **转后台** | 占位，原因「**因插队转后台**」 | [转后台的以占位算齐](../PF-012-agent-loop-and-run/design.md#56-状态转移表) → T7 → T1 |
| **工具执行中，不允许转后台** | **中断执行** | 占位，原因「**因插队被中断**」 | 结果齐了 → T7 → T1 |
| **`Ask()` 停着等人** | **中断这次执行** | 占位，原因「**人拒绝回复**」 | 同上 |
| **[运行等待态](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-run-wait-state--运行等待态--run-wait-state)上悬着卡片** | **取消等待，卡片移出[决策池](../PF-008-human-in-the-loop/design.md#决策池)** | 每张卡片记「**人明确拒绝回复**」 | 卡片全答完 → T5 → T8 → T1 |
| **正在取队列 / 组装 / 正要调模型** | **什么都不中断** | 只有 ② 与 ③ | **马上就是 T1**，它在队首 |

> **六条路，同一个终点：[T1，取一批消息的那一点](../PF-012-agent-loop-and-run/design.md#56-状态转移表)。
> 零个新的状态转移。**

**最后一行说明插队在任何时刻都合法**——**没有一个「现在不能插」的窗口**。
否则用户按下去没反应，而他不知道为什么。

**插队之后 agent 看到什么**：它读到自己上一句话被标着「中断」、
或者一条说明原因的占位，**外加用户那句新话**。
被中断的那句话里若有它想调、还没执行的工具，**它读完用户的新话再决定要不要重新发起**。
[原因一定要写明](design.md#541-占位消息一律要说清原因)——否则它会把占位读成「工具执行失败了」，
然后去重试一件用户刚刚叫停的事。

### 旅程四：一个后台结果在运行结束之后才回来

```text
  用户：「跑那个两小时的构建，好了告诉我」
      │
      ▼
  运行 A：调用工具 → 转后台 → 以占位算齐 → 继续 → 模型没动作 → 队列空 → 【完成】
      │
      │   （两小时过去）
      ▼
  结果回来 ──→ 受理成一条入站到达 ──→ 落进会话日志 ──→ 进队列
                                                          │
                                                          ▼
                                             检查持久事实：无未终结 Run，有待处理输入
                                                          │
                                                          ▼
                                        运行 B 起来 → T1 取到它 → agent 回话给用户
```

**这条旅程没有分支。**它不分「有活跃运行就只记一笔、没有就入队」两路，
**只有一条路**：进队列，**剩下的由队列空不空自己决定**。

> **它同时是 [PF-012 §6.12 那条规则的两半](../PF-012-agent-loop-and-run/design.md#612-终态之后再回来的东西不让-run-复活)的演示**：
> **运行 A 不复活**（它的终态是终态），**而运行 B 会起来**。
> **少读哪一半都会做错**：少前一半，一个已经结算完的运行被重新拉起；
> 少后一半，**用户要等到自己下次说话才发现构建两小时前就跑完了**。

## 二、分支与异常

| 在哪一步 | 什么情况 | 用户看到 | 系统停在 | 能否重试 |
|---|---|---|---|---|
| **旅程一 ①** | 目标会话不存在，或送的人够不上资格 | **发的人**收到一条说得出原因的拒绝 | 什么都没发生 | **可以**——条件变了再送 |
| **旅程一 ①** | 队列已经排得很长 | —— | **照常受理。**[本版队列不设容量上限](design.md#66-队列不设容量上限) | 不适用 |
| **旅程一 ②** | 同一件事第二次送到 | **发的人**拿到与第一次相同的结果 | 只有一条入站到达 | 不适用 |
| **旅程一 ②** | 用户自己把同一句话发了两遍 | **两条都在。**[我们不替他猜](design.md#63-去重只认来源说得出的那个同一件事) | 两条入站到达 | 不适用 |
| **旅程一 ③** | 拓展件把**用户自己那条**否决了 | **必须让他看得出来**，否则他的话凭空消失，[而他会再发一遍](design.md#否决了也不许静默) | 内容不进日志正文；「被拦下」留一笔 | **可以**——改了内容再发 |
| **旅程一 ③** | 拓展件把**外部来源**那条否决了 | **日志里一定留一笔**；要不要回告发送方，[是那件拓展件的事](design.md#否决了也不许静默) | 同上 | 视那件拓展件 |
| **旅程一 ③** | 一件「可否决」的拓展件自己挂了 | —— | **当作否决**（fail-closed），[且这件事本身要可见](../PF-012-agent-loop-and-run/design.md#干预力三档直接用-pf-000-的) | 不适用 |
| **旅程一 ③** | 一件**模态转换**拓展件没能转成那个块（它挂了、此刻不可用，或交不出合乎契约的东西） | **发的人被告知**这一条没发进去；会话、可选模型都没变 | **转换失败就是落盘前的否决**：这条到达**不被受理**，不进日志正文、**进不了队列**（[PF-013 转换件](../PF-013-model-profiles-and-invocation/design.md#转换件)） | **可以**——换一份内容再发 |
| **旅程一 ③** | 那个块的模态或媒体类型上**根本没有登记转换件** | —— | **照原样落盘**，没有 transcript；[收不下它的模型从此不在可选之列](../PF-013-model-profiles-and-invocation/design.md#511-有-transcript-的块不再把任何模型挡在外面)。**这不是失败**，契约归 PF-013 | 不适用 |
| **旅程一 ④ 提交未生效** | 停机 | 明确未受理或暂时无法查明 | 无受理事实、无待处理资格 | 发送方保留输入并沿同次提交标识查询／自动重试，不要求人重新输入 |
| **旅程一 ④ 已提交，回执未到** | 断线或停机 | 结果未知，查询后可见原受理状态 | 已受理，系统承担恢复 | 查询／重试返回原事实及当前状态，不新增消息或 Run |
| **旅程二 3** | 停机，队列里还排着东西 | —— | **一条都没少。**[队列是日志算出来的](../PF-012-agent-loop-and-run/design.md#待处理消息队列)，重算一遍就有了 | 不适用 |
| **旅程二** | 队列非空，而这个会话没有活跃运行（比如刚崩过） | 他那句话**还排着，且看得出还排着** | 满足当前准入条件时**这个状态不许长期存在**；不能确认登录有效时保留消息并明确阻挡——[必须有东西把会话拉起来](design.md#68-停机不会让一条入站到达永远悬着) | 不适用 |
| **旅程三** | 连续插两次 | 第二次**只是进队首**，不再中断一次 | loop 已经在走向 T1 | 不适用。[再中断一次违反「最大程度保留」](design.md#65-插队是原子的) |
| **旅程三** | 插队时 loop 停在**工具执行中**，而那个工具在外面的东西停不掉 | agent 拿到占位，**原因写着中断** | [产品要求的是「不再产生新的外部效果」；停不停得掉是工具那一侧的能力](../PF-012-agent-loop-and-run/design.md#被取消不在这张表里因为它不是一行) | 不适用 |
| **旅程四** | 结果回来的那一刻，运行**恰好正在结束** | —— | **这不是一个危险时刻**：[两种处境走的是同一条路](design.md#52-三个去处为什么是穷尽的)，差别只在队列空不空，**而那是 loop 自己看的** | 不适用 |

## 三、状态流转

### 一条入站到达

```text
                    （未受理，不是状态）
                     被拒：够不上资格 · 会话不存在
                     被拦：拓展件否决（含模态转换件转不成）
                            │
                            ✕
   外面送到 ──受理并落盘──→ 【已受理】
                                │
          ┌─────────────────────┼─────────────────────┐
          ▼                     ▼                     ▼
      进了队列              落到卡片上              就地处置（生效另判）
    （接下面那张图）      （PF-008 接手）         （到此了结）
```

| 从 | 到 | 触发 | 前置条件 | 不可逆？ |
|---|---|---|---|---|
| —— | **已受理** | **受理并落盘，一步** | 目标会话在、资格够、没被去重掉、没被否决 | **是**——[落进了只增不改的日志](../PF-012-agent-loop-and-run/design.md#会话日志) |

> **这里没有「已受理但还没定落点」这个中间态。**
> 有了它，它就**会跨越停机存在**，于是必须被写下来、被主动扫描补齐。
> **[去处在落盘那一刻就定了](design.md#52-三个去处为什么是穷尽的)，所以它不存在。**

### 一条排队的消息

```text
   持久入队 ──→ 【待处理】──持久承接──→ 【已承接】（不再排队）
                                             │
                                      原 Run 继续处理，历史保留
```

| 从 | 到 | 触发 | 前置条件 | 不可逆？ |
|---|---|---|---|---|
| 待处理 | **已承接** | [T1 取一批](design.md#69-取批一次取走此刻队列里的全部) | 它在队列里 | **是** |

**这张图只画承接路径，不穷举待处理资格的全部解除原因。**归档取消待处理资格是另一条路径，沿 [design §9.2](design.md#92-会话被归档那一刻队列怎么办) 与 PF-015 的归档规则，不记成消费成功。待处理／已承接由事实派生，不另立状态权威：
[「取到哪了」从日志派生，不另立权威](../PF-012-agent-loop-and-run/design.md#67-检测状态从日志派生不另存)。
**所以这张图与其说是状态机，不如说是一条投影的读法。**

> **没有因恢复把已承接消息重新排队的转移。**只读取而未持久承接时仍待处理；承接之后停机，沿原 Run 恢复，不能另作一次承接。因归档取消待处理资格沿 PF-015，取消与承接不同，历史均保留。

**本 topic 没有用户撤回排队项的操作。**
操作边界见[为什么没有撤回一个排队项](design.md#为什么没有撤回一个排队项)。

**没有在本 topic 或其引用规则中定义的转移不得自行添加。**承接与取消都保留原输入和相应历史事实。

## 四、角色与操作

**资格不另开一套面**：

> **谁能对一个会话发控制指令、谁的消息能进它的队列，
> 与「他能不能访问这个会话」是同一个判断。**

这照搬 [PF-008 §6.7 立下的规矩](../PF-008-human-in-the-loop/design.md#67-租户隔离在池子上成立)——
在这里另立一套资格，**两套规则迟早会在某个边角上给出不同答案**。
[跨租户默认拒绝](../PF-001-identity-scope-and-agent-constraints/design.md#租户)在受理这一步同样成立。

| 操作 \ 谁 | **会话里的用户** | **外部来源**（经[连接件](../PF-002-assets-settings-and-permissions/design.md#connector)） | **agent 自己** |
|---|---|---|---|
| **发一条会进队列的消息** | 可 | **可**——[送进来的就要被处理](design.md#62-送进来的就要被处理要不要送进来归连接件)；**该不该送进来，是连接件那一侧的判断** | **不可**——它的产出走[工具](../PF-006-tools-and-skills/README.md)与[消息](../PF-009-context-message-types/README.md)那两条路，不从受理面进来 |
| **[插队](design.md#插队)** | 可 | **不可** | 不可 |
| **取消 / 强制停止** | 可 | 不可 | 不可 |
| **把一次工具执行切到后台** | **有条件**：[那个工具声明了允许](../PF-006-tools-and-skills/design.md#66-前台后台-与-等待态是两个维度)。**人可以决定「现在切」，不能决定「它能不能切」** | 不可 | **可**——[它在发起时就能决定这次不占前台](../PF-007-meta-capabilities/design.md#61-tools通向任意非常驻工具)，那是另一条路，不是控制指令 |
| **中断一次工具执行** | 可 | 不可 | 不可 |
| **中断一次模型调用** | 可 | 不可 | 不可 |
| **答一张卡片**（含[「我不答这个」](../PF-008-human-in-the-loop/design.md#65-不回答是合法答复)） | **有条件**：[与他能不能访问那个会话是同一个判断](../PF-008-human-in-the-loop/design.md#67-租户隔离在池子上成立)；[「本租户所有会话」那一档还要有改设置的权](../PF-008-human-in-the-loop/design.md#52-那个判断函数) | 不可 | 不可 |

> **「外部来源不能插队」这一行值得多看一眼。**
> 一个外部来源能把正在干活的 agent 打断，**意味着外面的人可以随时抢走这个会话的注意力**。
> **它能做的到此为止：把一条消息放进队尾。**
> 那条消息照样会被看到——[队列非空「完成」就不成立](../PF-012-agent-loop-and-run/design.md#56-状态转移表)——
> **只是它等 loop 自己走到 T1，不把 loop 从半路拽过来。**

## 通知与受理完成

持久受理成功后已承担保管责任，不等待 Trigger 通知送达才算成功。通知丢失或停机恢复仍沿持久输入及未完成责任推进。原 Run 有有效 Agent runtime 时通知它；普通追加留到下一合法 T1，不替换 attempt 或打断在途调用。原执行者不在时，满足合法推进条件才在原 Run 创建新 attempt；无未终结 Run 且有待处理输入时才创建新 Run。重复信号不等于新的提交，控制指令仍按原目标处置。精确条件沿 [PF-012](../PF-012-agent-loop-and-run/design.md#边界什么让它开始什么让它结束)。
