# PF-006 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

### 工具定义的两种范式

| 场景 | 应当看到什么 |
|---|---|
| 写一个只干一件事的工具 | **不必套命令分派**——直接就是一组参数 |
| 写一个承载一族动作的工具 | **多命令范式**：先选命令，再给那个命令的参数 |
| 一个有十个命令的多命令工具标了常驻 | **只占一个槽位**，不是十个 |
| 看一个有十个命令的多命令工具在模型面前的样子 | **只有两格**：从十个命令里选一个（每个一行说明）、交给它的参数；**十个命令各自的参数一个都没摊出来** |
| 工具作者在定义里放了全部命令的完整参数 | 模型面前**照样只是那份命令清单**；agent 对不熟的命令**动手前先问一次详细用法**，`Tools().inspect` 答得出每个参数；**交上来的参数不对，系统当场认得出** |
| 工具作者只在定义里放命令清单，不带参数 | 模型面前**与上一行一模一样**；`Tools().inspect` 答得出的只有那份清单，交上来的参数对不对由工具自己判 |
| 一份工具定义缺了工具说明，或某个参数没有说明 | **不是一份完整的工具定义**——缺哪一处说得出来 |
| 一个多命令工具，某个命令没有那一行说明 | **同上不完整**——那一行就是模型面前「选哪个命令」的说明 |
| 把任何一份完整的工具定义交给任何一家模型供应商 | **拼得出那一家要的工具描述**：工具说明、每个参数的说明都在 |
| 想查一个工具怎么用 | 走 [`Tools().inspect`](../PF-007-meta-capabilities/design.md#61-tools通向任意非常驻工具)，**对两种范式都管用** |
| 一个多命令工具带了 `help`，另一个没带 | **两个都成立**——`help` 是可选的命令空间 |
| 对比一个工具的 `help` 与 `inspect` 的说法 | **说得一致** |
| 翻遍工具定义找「这个工具会不会进等待态」 | **找不到这一格**——等待态是函数逻辑里的原语，不是定义时的声明 |
| 一个工具这次进了等待态、下次没进 | **正常**——等不等是这一次跑出来的事 |

### 六项可选声明

| 场景 | 应当看到什么 |
|---|---|
| 一个工具什么都不声明 | **照样成立**——六项全是可选的 |
| 一个工具**没声明**能不能后台 | **不能后台**：它不会自动转后台，用户也**手动切不了** |
| 用户想把一个没声明允许后台的执行切到后台 | **切不了**——人可以决定「现在切」，不能决定「它能不能切」 |
| 声明了依赖某个存储，而那个存储没配好 | **这个工具整个不可用**，装[替换件](../PF-006-tools-and-skills/design.md#替换件) |
| 声明了「只要 A」，实际却去用了 B | **这是缺陷**：可用性算出来是对的、跑起来是错的 |
| 没声明产出附件，却产出了附件 | 同上——**声明与实际必须对得上** |
| 租户在自己那一层改了一个工具的转后台阈值 | 按改后的值自动转后台——**它是偏好类设置**，定义里只是默认值 |
| 工作区想改一个工具的目标环境 | **改不了**——目标环境是落点与身份类 |
| 任何一层想把一个没声明允许后台的工具配成「能后台」 | **配不了**——能不能后台是作者的许可，不是设置 |

### 返回值：两种写法，一种模型

| 场景 | 应当看到什么 |
|---|---|
| 工具按普通函数那样返回 | **整个返回值当字符串用**，进消息 |
| 工具返回一个 `ToolResult` | 按字段分别处理：进消息的内容 / 要卸载的原始结果 / 附件地址 |
| [agent-loop](../PF-012-agent-loop-and-run/README.md) 拿到一次执行的结果 | **只有一种形状**——普通返回已在上报时转成 `ToolResult` |
| 按普通函数返回的工具想带附件 | **带不了**——那是 `ToolResult` 才有的能力，两种写法能力不对等是有意的 |
| 一次工具执行完成 | 连同结果上报的还有**这次的账**：跑了多久、耗了多少计算这类事实 |
| 去 ToolMessage 里找 cpu 时间 | **找不到**——账不进 agent 的上下文 |

### 三层各自成立

| 场景 | 应当看到什么 |
|---|---|
| 装了五十个工具，只有三个标了常驻| 系统提示词里**只有那三个 + 两个取用入口**；**动作空间仍然是五十个** |
| 问「这个 agent 能不能做 X」 | 答案来自**动作空间**，与 X 占不占槽位无关 |
| 把一个条目的常驻标记去掉 | **动作空间不变**，agent 照样调得到它，只是不再直接列出来 |
| 一个条目的依赖断了 | **动作空间不变，槽位不变**，只有可用性变 |
| 问「agent 为什么不用这个工具」 | 能分别查到三个答案：**在不在动作空间**、**占不占槽位**、**当下可不可用** |

### 常驻标记

| 场景 | 应当看到什么 |
|---|---|
| 同一个工具，A 的清单标了常驻，B 的没标 | **两边表现不同**，各按各的来；工具本身没有变 |
| plugin 把某成员标为常驻，装它的 agent definition 标为非常驻 | **以 agent definition 为准** |
| 查两个取用入口 | **它们恒定占槽位**，不能被配成非常驻 |
| 持有某份 agent definition 的租户，在自己那一层把其中一条引用的常驻改掉 | **按改后的值呈现**——常驻是那条引用上的偏好类设置 |
| 一份技能标了常驻 | 系统提示词里有它的 **name 与说明**，**没有正文** |
| 一个工具标了常驻，先后换两家模型 | **两次都直接可见**；具体呈现成什么样，随那家模型的适配 |
| 一个 MCP 接入点带来的动作 | **每个动作一个工具条目**，**不常驻**，经 `Tools()` 找得到、调得通 |
| 一次执行尝试进行到一半，MCP 对端加了一个动作 | **这次尝试里看不到它**；下一次尝试开始时出现 |
| 一次尝试开始前 MCP 接入点连不上 | 上一次拿到的每个动作都在原位，**都是不可用替换件**，调用得到「不可用：接入点连不上」 |

### 可用性与替换件

| 场景 | 应当看到什么 |
|---|---|
| 一个工具依赖的外部服务断了 | 下一次 run 开始时，它变成**替换件**；条目还在原位 |
| agent 调用那个替换件 | 拿到一条**正常返回**，说明**现在用不了以及缺什么**；**不是报错** |
| 外部服务恢复了 | 下一次 run 开始时**自动换回真身**，不需要任何人做动作 |
| 同一 session 连续三次 run，中途依赖断了又恢复 | 可用性跟着变，而**动作空间三次完全一样** |
| 技能声明依赖某个能力标识，那个标识下**换了一个提供者** | **仍然可用**——声明指的是名字，不是那一份具体资产 |
| 技能用得上、但**没写进声明**的东西不在 | **可用**；那个东西用的时候现探 |
| 技能声明里的某一项**一个提供者都没有** | **不可用**，替换件说明缺哪一个 |
| 一个工具声明「调它要模型给得出图」，这次的有效模型吐不出图 | **不可用**——这一项**只有模型自己满足得了** |
| 一个工具声明「结果里有图」，这次的有效模型收不下图，但**转换件转得出文本** | **可用**，结果以文本到达。这不是另一条规则，是**这一项被转换件满足了** |
| 同上，而**转换件也转不出来** | **不可用** |
| 用户换到一个吐不出图的模型 | 要图当参数的工具**变成替换件**，**动作空间一个不少**；调用它们得到「不可用」与原因 |
| 问「这一项为什么不可用」 | **答得出具体缺什么**，不是一句「不可用」 |

### 工具执行的归属与跨轮

| 场景 | 应当看到什么 |
|---|---|
| 一次执行还没完，这一轮结束了 | **执行继续**；位置上有占位返回说明它转了后台 |
| 又过了几轮，执行完成 | **结果回到那个 session**；agent 在下一次 run 以提醒得知 |
| 执行**已转后台**，发起它的 agent runtime 中途退役重建 | **执行照跑，结果照样送达**——宿主与收件人都是会话，不是那个 runtime |
| 执行**还在前台**，agent runtime 被回收 | **执行照跑、照等**；协程重建后接着等它，结果照常回到这一步 |
| 前台停在 `Ask()` 上等人时 agent runtime 被回收 | **卡片照样挂着**；人回了话，工具拿到应答接着跑 |
| 工具自己的 runtime 所在的进程没了 | **停机，落失败，不重来**——哪怕它看上去还没来得及做任何事 |
| 据点整体停机时一次执行在前台；恢复之后 | 那次调用的位置上有一条追补的**占位返回消息，原因写「工具执行异常中断」**，收场是失败；**系统不替它重调**，agent 自己决定 |
| 据点整体停机时一次执行已转后台、还没跑完；恢复之后 | agent 收到一条追补的**提醒，说清「后台工具执行异常中断」**，收场是失败 |
| 恢复时，一次调用还没有返回消息，但它在工具执行运行时里**还在跑** | **不追补任何东西**，照常接着等它 |
| 用户取消一次运行，有一次执行在前台、一次在后台 | 前台那次**落被中断**，占位原因「**运行被取消**」（不是「用户手动中断」），后台那次**照跑** |
| 查一次执行的来历 | **说得出是哪一次 run、哪个 agent runtime 发起的**（记录得下来） |
| [会话被归档](../PF-015-session-lifecycle-and-ownership/design.md#63-归档先停活儿再落状态)时还有执行没完，前台或后台 | **收场是被中断**，不是失败；不留下没有结局的执行 |
| 一次执行转了后台，后来跑完 | **两个收场**：前台那一次调用是「转后台」，后台那段执行另有自己的一个（完成、失败、被中断、等不到应答之一），以提醒到达 |

### 六种收场分得清

| 场景 | 应当看到什么 |
|---|---|
| 执行成功 | 结果 |
| 执行真的出错 | **失败** |
| 调用一个不可用的东西 | **「用不了 + 原因」**，agent 据此**绕路而不是重试** |
| 执行转后台 | **占位返回说明已转后台**，agent 去干别的 |
| 用户叫停 | **「被用户手动中断」**，agent **不自动重试** |
| 等待态到头没人回 | **「等不到应答」**，既不是失败也不是被拒 |
| agent 用 `BkgJobs()` 掐掉自己发起的一个后台执行 | 收场**被中断**，那段执行的收场提醒里写「**被 agent 停掉**」——**与用户叫停分得出** |
| agent 发起时就让一个允许后台的工具在后台跑 | 位置上当场一条占位，原因「**发起时就在后台**」 |
| 模型给了一个参数说完了、却解析不了的调用 | **不执行**；agent 收到一条正常返回，收场**失败**、原因写参数解析不了；调用块照原文留在回复里 |
| 把这六种摆在一起看 | **六条消息的语义互不相同**，都能让 agent 判断出下一步 |

### 前后台与等待态正交

| 场景 | 应当看到什么 |
|---|---|
| 前台执行中途进入等待 | **停着等应答**，这一轮等着它；它仍在前台 |
| 找一次「在后台等应答」的执行 | **本版找不到**——要等应答的执行只在前台等（[design §6.6](design.md#66-前台后台-与-等待态是两个维度)） |
| 一个允许后台的工具跑太久 | 按它的转后台时长**自动转后台**；没设转后台时长、到了前台上限，同样转后台 |
| 一个**不允许**后台的工具跑到了前台上限 | **被中断**，占位原因「**前台超时**」；agent 不自动重试 |
| 一次执行停在等待态上很久 | **前台上限不数这段时间**——`Ask()` 等人不会被超时掐掉 |
| 同一个会话里同一个工具同时要跑的次数超过了并发上限 | 超出的**排队**，按发起的先后轮到；**没有一个被拒** |
| 用户手动把一个允许后台的执行切到后台 | **切得过去**，agent 收到占位返回 |
| 用户想把一个**不允许**后台的执行切到后台 | **切不过去** |
| 问「这次执行在等什么」 | **答得出它等的是什么形状的应答** |

### 工具跟外面通信的两个原语

| 场景 | 应当看到什么 |
|---|---|
| 问「一个工具能主动往外说话吗」 | **能，两种**：等待态（要东西进来）、发帧（给东西出去） |
| 查工具定义里有没有「我发不发帧」这一格 | **没有**——系统按**实际收到什么**来解析 |
| 一个工具这次发了帧，下次一帧不发 | **两次都正常**，系统不核对任何声明 |
| 一个工具先往外吐日志，最后发一块汇总面板 | **成立**——同一次执行里换着发是允许的 |
| 帧发不出去（比如接收端不在） | **这次执行照常跑完**，收场不受影响 |
| 绝大多数工具 | **一帧都不发**，这是正常形态 |
| 问「帧算第七种收场吗」 | **不算**——它不改变这次调用办成什么样 |

### 工具的产出：三部分

| 场景 | 应当看到什么 |
|---|---|
| 问「一次执行交出来几部分」 | **三部分**：进消息的、附件、**过程中的帧**。前两部分在跑完时，第三部分在跑的过程中 |
| 问「agent 看得到帧吗」 | **看不到**——帧的读者是人 |
| 一个工具发了一路帧，但结果只给了一句「见上」 | **不成立**——agent 一帧都看不见，等于什么都没给它 |
| 一个工具产出一张图 | 图**作为附件**存起来；**消息里给出地址** |
| agent 想看那张图 | **自己去取**——用能读那个存储的工具 |
| 一个工具声明自己产出附件 | 它**声明了放进哪个存储** |
| 那个存储**没有任何工具读得出来** | 这个工具**当下不可用**——附件写得进去、取不出来，等于不存在 |
| 结果太大装不进消息 | **卸载**：消息里是**占位**（够用的那部分 + 多大 + 怎么取全文），**原始结果存着没丢** |
| **工具自己声明要卸载** | 占位里是**工具开发者构建的摘要** |
| **系统兜底卸载**（单条消息超限额） | 占位里是**首尾保留的机械截断**——**系统不替工具开发者写摘要** |
| 多数这类结果 | **agent 看占位就够了**，不必去取全文 |
| agent 确实要看全的 | **分页取回**（`Tools().read_result`） |
| 分辨「结果被卸载了」与「工具没返回什么」 | **分得出**——否则它会重来一次，而重来得到的还是一条占位 |
| 一个**后台**执行的结果很大 | **照样能卸载**——两个维度不相干 |
| 一个进过**等待态**的执行的结果很大 | **照样能卸载** |
| 一个结果很大的执行 | **不会因此被转到后台**——结果多大与该不该占着 run 无关 |

### agent 造工具与技能（本版三条）

| 场景 | 应当看到什么 |
|---|---|
| 未获授权的 agent 试图创建 | **不发生** |
| 获授权的 agent 创建了一个工具 | 它是一份**资产**，**归属算得出来**（来自运行时注入的租户上下文） |
| 创建并完成显式增量装载 | **当场能用**；agent runtime**没有被重建** |
| 系统受理了 agent definition 的变更（不是只改工作区文件） | **下一次 run 时重建 agent runtime** |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 依赖不满足就**不装**，让条目消失 | 动作空间随环境波动变形，[I-4](../PF-004-agent-definition-and-assembly/design.md#61-不变式) 作废；用户查不出东西为什么没了 |
| 取用技能或调用非常驻工具**改变了 system prompt** | 成分变成运行期可变的，[PF-004](../PF-004-agent-definition-and-assembly/design.md#54-为什么系统提示词必须落在第三列) 那一条当场作废 |
| 常驻标记被做成工具自身的属性 | 上下文预算的决定权跑到了工具作者手上，而他根本不知道装配方装了多少东西 |
| **一个多命令工具在模型面前摊开了每个命令的完整参数** | 一个槽位还在，**紧凑没了**——命令越多吃得越多，而这一轮用不到的占了大头 |
| **一份缺了工具说明或参数说明的定义被当成完整的** | 拼不出供应商要的工具描述；模型对着一个名字和一串参数名去猜 |
| **工具定义里出现了「会不会进等待态」这一格** | 把一件**每次跑起来才知道**的事做成了静态声明 |
| **工具定义里出现了「发不发帧、发哪一种帧」这一格** | 多了一个**从头到尾不会被读一次**的字段，还得配一整套「声明与实际不符怎么办」的规矩 |
| **系统先查工具定义，再决定要不要解析帧** | 解析策略不统一了——**同样一份数据，换个工具发出来就被当成别的东西** |
| **一次执行因为「帧没发出去」而失败** | 一个纯粹的旁白决定了正剧的结局。**播报是附加的，不是执行的一部分** |
| **工具靠发帧代替给结果** | agent 什么也没拿到——**它看不见帧** |
| **没声明能不能后台的工具，被自动或手动转到了后台** | 默认倒向了宽松那一边——**一个从没准备好异步的工具被丢进了它没准备好的时序**，而且这种错**不报错，只偶尔显形** |
| **一个多命令工具的每个命令各占一个槽位** | 多命令范式存在的理由当场作废——**它本来就是为了把一族动作压进一个槽位** |
| **多命令工具带的 `help` 与 `Tools().inspect` 说得不一样** | 同一个工具的用法有两处说法，**而 agent 分不出该信哪个** |
| **换了模型之后，动作空间里少了条目** | 可用性变了却改了动作空间——[三层正交](design.md#51-三层正交)被打破，agent 不知道自己少了什么 |
| **任何一次工具执行因为 agent runtime 被回收而停了** | 它从不由 agent runtime 承载；**协程每回收一次就断一批活**，而回收是计划内天天发生的事 |
| **MCP 接入点连不上，它的动作从动作空间里消失** | 不可用被做成了「不装」——agent 不知道自己少了什么 |
| **一次停了的执行被系统判定「从没开始」而自动重来** | 系统替 agent 断定了一件这一层看不全的事；**真做过的话就是做第二遍** |
| **一次执行尝试进行中，MCP 动作清单变了形** | agent 手上的那份清单半路变形，它规划到一半的动作可能没了 |
| **一次运行被取消，前台那次执行的占位写成「用户手动中断」** | 取消的可能不是用户，停的也是这一步而不是这一次执行——**排查的人与 agent 都读错了是谁、停了什么** |
| **一个参数解析不了的调用，没有任何东西回给 agent** | 它以为调用发出去了，**等一个永远不会来的结果** |
| **agent-loop 里到处判断「这次返回的是哪一种写法」** | 统一转换没做——**工具作者的方便传染给了系统** |
| **执行的账被塞进 ToolMessage** | 白占 agent 的预算——**它拿 cpu 时间做不出任何判断** |
| **某次工具执行完成了却没留下账** | 查不出是谁在拖后腿，而**这件事只有执行完那一刻记得下来** |
| plugin 的常驻声明压过 agent definition | 同上 |
| 取用入口可以被配成非常驻 | agent 无从发现任何东西，**整套机制转不起来** |
| 可用性只在装配时算一次 | 拿着过期的判断去调用；外部服务恢复了也换不回来 |
| 把**中断**当成失败递给 agent | 它会重试——而用户刚刚明确表示不想让它跑。**agent 越勤快后果越糟** |
| 把据点停机时没了的执行以**被中断**递给 agent | 反过来的错：它以为是有人叫停，**该自己判断要不要再调的时候不敢动** |
| 把**不可用**当成失败递给 agent | 它会重试一个注定失败的东西，而正确做法是绕路 |
| **产出了附件，却没有工具能把它读回来** | 那个附件**等于不存在**，而 agent 会拿着地址反复尝试 |
| **卸载被做成了截断** | **原始结果丢了**，而占位提示看上去像是「还能取回来」 |
| **占位里只有地址、没有内容** | 每一次大结果都变成**一次额外往返**，卸载从省事变成添乱 |
| **系统替工具开发者臆造了一份摘要** | 比机械截断更危险——**它看上去是有意义的**，agent 会当成完整转述用下去 |
| **占位提示让 agent 以为工具没返回什么** | 它会重来一次，**而重来得到的还是一条占位** |
| **因为结果大就把执行转到后台** | 两件事被耦合了——**结果多大与该不该占着 run 毫无关系** |
| 把**等不到应答**当成失败 | 同上，重试一个没人回应的东西 |
| 六种收场里有任何一种以**报错**形式抛给 agent | 报错不带语义，它只能猜 |
| 工具要的执行环境给不了时，**降级给一个不满足要求的** | **绕过了工具作者的安全判断**。与 [PF-005 沙箱创建失败退回宿主机](../PF-005-execution-environments-and-sandboxes/design.md#62-宿主机不提供租户隔离因此必须被显式允许)同性质 |
| 工具执行的生命周期被绑在一次 run 上 | 长任务一到轮次边界就死；跨轮的结果永远送不回来 |
| 结果送给发起它的 agent runtime 而不是 session | 那个 runtime 退役之后结果就丢了 |
| 有人能"手动把一项设为可用" | 声明与实际脱节，算出来是对的、跑起来是错的 |
| agent 未获授权也能造工具 | §6.9 第一条被绕过 |
| agent 造出来的东西**算不出归属** | 它落在哪个租户里说不清，租户隔离在这里破掉 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 三层正交 | 分别改三层各一次，**另两层纹丝不动** | 改常驻标记后动作空间跟着变，或者依赖一断条目就没了 |
| 动作空间不受呈现影响 | 把所有常驻标记去掉，**agent 能做的事一件不少** | 去掉标记之后它真的做不了了 |
| 形状恒定 | 反复制造依赖故障与恢复，**条目数与顺序始终不变** | 条目数跟着环境波动 |
| 系统提示词成分恒定 | 一次 run 里取五份技能、调十个非常驻工具，**system prompt 逐字不变** | 取用之后提示词变长了 |
| 可用性确实每轮重算 | 断掉依赖 → 下一轮不可用；恢复 → 再下一轮可用，**全程无人干预** | 要重起一个 agent runtime 才能恢复 |
| 替换件会解释自己 | 调用它，**答得出缺什么**，而不是一句「不可用」 | 只有一个报错码 |
| 六种收场分得清 | 造出六种情形，**agent 每次的下一步动作都不同且正确** | 中断后它重试了，或不可用时它死磕 |
| 依赖只有必需项，指的是名字 | 换掉某个能力标识下的提供者判可用；缺掉声明里任意一项判不可用；**没有第三种结果** | 出现「部分可用」，或者换个提供者就判死 |
| 执行绑 session 不绑 run | 发起后转后台、立刻结束这一轮，**结果仍然回得来** | 轮次一结束执行就没了 |
| 回收与取消分开 | 回收 agent runtime：**前后台的执行都照跑**；取消运行：**前台那次落被中断，后台那次照跑** | 回收时有执行停了，或取消时后台的也停了 |
| 前后台与等待态解耦 | 本版开着的三种组合**都造得出来**；「后台 × 在等待」本版关着，而结果怎么到达**只看有没有占位**，不看工具是哪一个 | 一进等待就被迫转后台，或反过来；或者结果落成哪种消息要查一张按工具分的表 |
| 发帧不影响执行 | 把接收端断掉，**六种收场一个不变** | 帧发不出去，这次执行也跟着失败 |
| 帧的解析是统一的 | **同一份帧数据，换哪个工具发出来处理结果都一样** | 要先查工具定义才知道该怎么处理它 |
| 造出来的东西归属算得出 | 让 agent 造一个，**查得到它属于哪个租户**，且无人配置过 | 要额外配一次归属 |
| 多命令工具的模型面前只有一种样子 | 同一个多命令工具，带与不带各命令的完整参数各装一次，**模型面前逐字相同** | 带了完整参数的那一次，模型面前多出了参数 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| 两个取用入口各有哪些命令、怎么用 | 归 **PF-007** |
| agent 怎么创建、编辑、动态装载 | 归后续 topic，本版只验那三条最小必要 |
| 造出来的工具与已有的重名怎么办 | 同上 |
| 依赖声明写成什么样（名字怎么拼、清单怎么排） | 产品只定它是[一串必需项的抽象名字](design.md#依赖) |
| 等待态的上限具体是多久 | **资源政策**，本版不定 |
| 帧落成哪一种消息、给谁看、怎么增量更新 | 归 [PF-009](../PF-009-context-message-types/README.md)。本 topic 只验**工具这一头** |
| 那份帧协议具体有哪几种帧、各带什么字段 | 产品只定「**由协议约定而不由定义声明**」这条选择，协议的具体形状是技术设计 |
| 设施一共有哪几种 | [PF-005](../PF-005-execution-environments-and-sandboxes/design.md#设施) 已明确不定这份清单 |
| 提醒怎么送达 agent | 归 **run** 那一块 |
| 尚未持有的资产怎么获取 | 归 PF-002 / PF-003 |
| 解析依赖的性能 | 没有可重复的瓶颈测量之前，不定性能指标 |
| 工具与技能的 name 怎么写、定义里带不带返回形状的描述 | 归规格；产品只要求 name 同一类别内唯一 |
| 各家模型供应商的工具描述具体长什么样、怎么从定义拼出来；模型面前「交给这个命令的参数」那一格的说明写成什么 | 归规格与各家的适配；产品只要求**拼得出来**，以及说明必填 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。

工作区文件单独变化不满足上述装载条件：未显式 reload 且未发生实际装配时，不因此刷新资产或定义；校验失败须报错并保留原内存数据。
