# PF-006 流程与状态

`design.md` 说这块产品**是什么**，这里说它**怎么动**。
查「这个概念是什么」去那边，查「这一步失败了怎么办」看这里。

## 一、主要旅程

### 1.1 装配一个 agent：从清单到三层

| 步骤 | 发生什么 | 产出 |
|---|---|---|
| 1 | 读 agent definition 与它引用的 plugin，得到要装的全部条目；MCP 接入点展开成对端的[一个个动作](design.md#613-mcp-接入点带来的动作) | 一份**引用清单**，每条带着自己的常驻标记（一项求值后的设置） |
| 2 | 读每个条目的[依赖声明](design.md#依赖)，逐项找**在场且可用的提供者** | 每一项一个**满足 / 不满足** |
| 3 | 每项都满足的判可用，缺一项的判不可用 | 每条目一个**可用性取值** |
| 4 | 不可用的，就地换成[同名替换件](design.md#替换件) | **装配清单**（形状与步骤 1 一致） |
| 5 | 按常驻标记决定谁占槽位；可见时呈现成什么按装配策略（技能是 name 与说明，工具按模型的适配） | **系统提示词的成分** |

**步骤 4 之后条目数不变**——这是形状恒定的由来。
不可用的那些没有消失，只是换成了会解释自己的东西。

**两处 agent definition 压 plugin**：同一条目两边都标了常驻，以 definition 为准。

### 1.2 每次 run 开始前：重算可用性

| 步骤 | 发生什么 |
|---|---|
| 1 | 对装配清单里的每一项，**重新解析一遍依赖**；MCP 接入点的动作集随之重取，**这一次 run 之内不再变** |
| 2 | 可用性变了的，换上或换下[替换件](design.md#替换件) |
| 3 | 变化以**提醒**的形式让 agent 知道（送达机制归 run 那一块） |

**动作空间不变，槽位不变，只有可用性变。**

> 上一次 run 能用的，这一次可能就不能用了。**这不是故障**，是 §6.2 写明的性质。

### 1.3 agent 调用一个不占槽位的工具

它不需要先把工具"装进"什么地方——**经取用入口直接调用**。

| 步骤 | 发生什么 |
|---|---|
| 1 | agent 通过取用入口找到它要的那个工具 |
| 2 | **知道它收什么参数**——非常驻工具的参数格式同样不在系统提示词里 |
| 3 | 发起调用 |

**全程 system prompt 不变。**这一条是硬的：系统提示词的成分在装配时定死，
运行中没有任何动作能改它（[PF-004 §5.4](../PF-004-agent-definition-and-assembly/design.md#54-为什么系统提示词必须落在第三列)）。

### 1.4 agent 取用一份技能

| 步骤 | 发生什么 |
|---|---|
| 1 | agent 通过取用入口搜索或按名找到那份技能 |
| 2 | 取回它的正文，需要时连同资源（[`Skills().read`](../PF-007-meta-capabilities/design.md#62-skills通向任意技能)） |
| 3 | 正文作为**这一次的返回内容**进入对话，随上下文自然存续 |

**同样不改变 system prompt**，也**不产生"已激活"这类需要维护的状态**。
上下文裁剪掉了就没了，还要用再取一次。

### 1.5 一次工具执行的生命周期

```text
                         发起
                          │
                     ┌────┴────┐
                     ↓         ↓
                  前台跑     后台跑
                     │  ⇄ 转后台  │      （转后台的三个触发源见 design.md §6.6）
                     │           │
              ┌──────┼───────────┼──────┐
              ↓      ↓           ↓      ↓
           进等待  完成        完成   进等待
              │      │           │      │
        拿到应答 / 等不到          拿到应答 / 等不到
              └──────┬───────────┴──────┘
                     ↓
              六种收场之一（design.md §5.5）
                     ↓
              结果回到 **session**
```

**前台/后台**与**是否在等待**是两个独立的维度，图中两侧各自成立。

**「⇄ 转后台」这一步本身就是前台那一次调用的收场**——位置上落一条「已转后台」的返回，这一轮接着走；
右边那一支跑到头，**另有自己的收场**（完成、失败、被中断、等不到应答之一），以提醒到达。
**执行挂在哪，这一步没有变**：左右两边都是它自己的 runtime、绑在会话上；
变的只是 agent runtime 从阻塞在它上面，变成不再等它（[design.md §5.2](design.md#前台后台说的是-agent-runtime-在不在等它)）。

**转后台有三个触发源**（[design.md §6.6](design.md#66-前台后台-与-等待态是两个维度)）：
**前台跑超过声明的时长**（系统按工具自己的声明）、**用户手动切**，
以及**用户[插队](../PF-014-inbound-intake-and-queueing/design.md#插队)时系统顺带触发**。
**三者都不绕开声明**——工具没声明允许后台，插队时它是**被中断**，不是转后台。

**图上还少了一条旁路：发帧。**它不在这张图里，是因为**它不改变这次执行走到哪**——

```text
   执行跑着（前台或后台，等着或没等着）
        │
        ├──→ 发一帧 ──→ 出了工具这道门就归 PF-009 了
        ├──→ 发一帧 ──→ ……
        │
        ↓
   照常走向六种收场之一
```

**帧发得出去发不出去，这次执行都照原样走。**
所以它没有分支，也不构成第七种收场。

### 1.6 一次执行跨越了多轮

| 时刻 | 发生什么 |
|---|---|
| 第 N 轮 | agent 发起一个长任务；它转后台，位置上留下一条**占位返回**说明已转后台 |
| 第 N 轮结束 | 这一轮结束了，**执行还在跑** |
| 第 N+1、N+2 轮 | agent 干别的。agent runtime 甚至可能已经退役重建——**执行的宿主是会话，不受牵连** |
| 某一刻 | 执行完成，**结果回到那个 session** |
| 下一次 run | agent 以**提醒**的形式得知结果 |

**收件人是 session，不是发起它的那个 agent runtime。**
那个 runtime 退役不影响送达——这正是[它绑在会话上](design.md#52-工具这个词指三样东西寿命各不相同)的原因。
**还在前台的执行也一样不受影响**：agent runtime 被回收，执行照样跑、照样等；
协程重建后读 Run 里记的「在等这一次」接着等（[design.md §6.12](design.md#它的宿主是谁决定了什么会带走它)）。

### 1.7 用户中断一次执行

| 步骤 | 发生什么 |
|---|---|
| 1 | 用户叫停 |
| 2 | 执行停下 |
| 3 | 位置上放一条**正常的返回消息**，语义是「**被用户手动中断**」 |
| 4 | agent 读到的是「这事不做了」，**不是「这事没成」** |

**绝不能**把它变成一个报错或失败递过去：agent 会重试，
而用户刚刚明确表示不想让它跑。

## 二、异常分支

| 分支 | 怎么处理 | 为什么 |
|---|---|---|
| **技能依赖的工具一个都没装** | 技能不可用，换[替换件](design.md#替换件)，说明缺什么 | 让 agent 读到一份自己执行不了的指引，比告诉它用不了更糟 |
| **技能依赖的某个[能力标识](../PF-002-assets-settings-and-permissions/design.md#63-组合的引用指向能力标识)有不止一个候选提供者，只有一个在** | **可用** | 声明指的是名字，**谁生效在那个名字上谁就满足它**——这件事在声明那一侧根本看不见 |
| **技能用得上、但没写进声明的东西不在** | **可用**；那个东西**用的时候现探** | [声明里只有必需项](design.md#只有且只有必需)。可有可无的写进去，反倒把本来能用的判死 |
| **声明里的一项，提供者换了一个** | **重算这一项**；算完还满足就照旧可用 | 提供者换了或没了都要重算，这正是每次 run 前重算的由来 |
| **工具依赖的外部服务连不上** | 工具不可用，换替换件 | 对端不归本系统掌握，断了不是本系统的故障 |
| **工具要的执行环境给不了** | 工具不可用，换替换件 | **绝不能降级给一个不满足要求的环境**——要求里写着要隔离，是因为给出它的人判断这东西不安全 |
| **换到一个满足不了某一端模态的模型** | 那几个工具变成**不可用**，原位装替换件；**动作空间不变** | [可用性重算的自然结果](design.md#它同时决定了换模型之后哪些工具还在)，不是失败 |
| **多命令工具带的 `help` 与 `Tools().inspect` 说得不一样** | **缺陷** | agent 分不出该信哪个 |
| **agent 调用了替换件** | 返回「现在用不了 + 原因」，**正常返回** | 它要回答的是「为什么」，报错带不了这个信息 |
| **agent 反复调用同一个替换件** | 照常返回同样的说明 | 不做惩罚也不做静默。**它读得懂就会绕路**，读不懂是另一个问题 |
| **一个工具声明只要 A，实际去用了 B** | 这是**声明与实际不符**，属缺陷 | 可用性算出来是对的、跑起来是错的，排查时所有人都会先怀疑别处 |
| **不允许后台的工具跑太久** | 不自动转后台，也不允许手动转 | 声明就是声明。要能转后台，去改工具定义 |
| **等待态等不到应答**（**占着资源的那种**） | 到上限后按第六种收场，**不是失败也不是被拒** | 混进失败，agent 会重试一个没人回应的东西 |
| **等待态等不到应答**（**什么都不占的那种**） | **就一直等着，没有上限** | 不花钱的等待没有理由到点；设了上限就得规定「到点算什么」，**那是系统替人签字**。[`Ask()` 属于这一类](../PF-007-meta-capabilities/design.md#611-ask通向人) |
| **[会话被归档](../PF-015-session-lifecycle-and-ownership/design.md#63-归档先停活儿再落状态)时还有执行没完** | 前台后台都停，收场是**被中断** | 归档是有意的停止，不是执行没做成；收件人都没了，跑完也没处送 |
| **agent runtime 被回收时有执行还在前台**（包括停在 `Ask()` 上等人的） | **照跑、照等**；协程重建后接着等它 | 工具执行从不由 agent runtime 承载；它的等待态是它自己的，卡片照样挂着 |
| **agent runtime 被回收时有执行已转后台** | **照跑** | 同上 |
| **工具自己的 runtime 所在的进程没了** | 停机，落**失败**，不重来；恢复时 agent 收到追补的一条消息，原因写「**异常中断**」——前台的是占位的返回消息，已转后台的是一条提醒；**要不要再调由 agent 定** | [停了不重来，没有「从没开始」的例外](design.md#停机之后它不重来)；「异常中断」是原因，**不是被中断**：没有人叫停它 |
| **用户取消一次运行时有执行在前台** | 跟着停，落**被中断**；后台的不停 | 那一步不要了，而前台那次正是那一步在等的；[取消不等于回收](design.md#它的宿主是谁决定了什么会带走它) |
| **MCP 接入点在 run 开始前连不上** | 它的每个动作装成**不可用替换件**（照最近一次拿到的清单），说明「接入点连不上」 | [连不上就是不可用](design.md#接入点连不上它的动作就是不可用)，与别的工具同一条规则 |
| **agent 无授权就想造工具** | 不发生 | §6.9 第一条 |
| **agent 造的工具与已有的重名** | 归后续 topic | 本 topic 只固定三条最小必要，不替它定冲突规则 |

**产出与卸载相关的分支：**

| 分支 | 怎么处理 | 为什么 |
|---|---|---|
| **一个工具产出附件，但没有工具读得出那个存储** | 这个工具**当下不可用** | 写得进去取不出来，等于没产出。**而 agent 会拿着地址反复尝试** |
| **结果太大装不进消息** | **卸载**：消息里换成占位提示，原始结果存着 | 硬塞进去，一条消息就把上下文吃光了 |
| **agent 要看被卸载的原始结果** | **分页取回**（[`Tools().read_result`](../PF-007-meta-capabilities/design.md#61-tools通向任意非常驻工具)） | 不分页就等于把刚卸下去的原样搬回来 |
| **占位提示写得像「没有结果」** | **缺陷** | agent 会重来一次，**而重来得到的还是一条占位** |
| **一个后台执行的结果被卸载** | **正常**，两件事不相干 | 前后台、等待态、卸载是三个正交维度 |

## 三、状态流转

### 3.1 一个条目的可用性

```text
        每次 run 开始前重算
                │
        ┌───────┴────────┐
        ↓                ↓
      可用            不可用
   （真身在位）   （替换件在位，带原因）
        └───────┬────────┘
             来回切换
        动作空间、槽位  全程不变
```

**没有第三态。**「部分可用」不存在——[声明里的每一项都是必需的](design.md#只有且只有必需)，
**全都有提供者就可用，缺一项就不可用**。
没写进声明的东西不满足，是**那一次执行**的事，不改变这里的取值。

### 3.2 一次工具执行

| 状态 | 能转到哪 |
|---|---|
| **前台执行中** | 后台执行中 / 前台等待 / 完成 / 失败 / 被中断 |
| **后台执行中** | 后台等待 / 完成 / 失败 / 被中断 |
| **前台等待** | 前台执行中（拿到应答）/ 后台等待 / 等不到 / 被中断 |
| **后台等待** | 后台执行中（拿到应答）/ 等不到 / 被中断 |
| **完成 / 失败 / 被中断 / 等不到** | 终态 |

**前台 → 后台是单向的。**回不去：转后台之后这一轮已经继续往下走了，
再把它拉回前台等于要求时间倒流。

**「前台执行中 → 后台执行中」这一步，对前台那一次调用是一个收场（转后台）**，
对这次执行只是 agent runtime 不再等它；表里的终态说的是**执行**跑到头时的那一个。

## 四、谁决定什么

| 事情 | 谁决定 | 谁不能决定 |
|---|---|---|
| 一个条目是不是常驻 | **装配方**：写引用的人给默认值，持有那份 agent definition / plugin 的各层配值（偏好类）；两处都有，agent definition 优先 | 工具或技能的作者——他不知道装配方的预算 |
| 一个工具需要什么样的执行环境 | **工具作者**给形状与默认值；持有它的组织、租户可以配值（落点与身份类） | 工作区配不了；装配方不能放宽它；系统不能降级满足 |
| 一个工具能不能后台执行 | **工具作者** | 用户不能强行把不允许后台的切到后台 |
| 一次执行**要不要**转后台 | **用户**、工具声明的自动超时，或[插队](../PF-014-inbound-intake-and-queueing/design.md#插队)时系统顺带触发 | agent 不替用户做这个决定 |
| 一次执行**要不要**中断 | **用户**，或[插队](../PF-014-inbound-intake-and-queueing/design.md#插队)时系统顺带触发（这个工具不允许转后台）；运行被中断时还在前台的、会话被归档时还没完的，随之被中断 | agent 不中断自己的执行 |
| 一项当下可不可用 | **依赖解析的结果** | 没有人能"手动设为可用"——那会让声明与实际脱节 |
| 取不取用一份技能、调不调一个非常驻工具 | **agent 自己** | 系统不替它判断"你现在该看哪份指引" |
| agent 能不能造工具 | **授权** | agent 自己 |
| 造出来的东西归谁 | **运行时注入的租户上下文** | 谁都改不了——它是算出来的，不是配出来的 |
