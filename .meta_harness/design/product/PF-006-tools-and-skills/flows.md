# PF-006 流程与状态

`design.md` 说这块产品**是什么**，这里说它**怎么动**。
查「这个概念是什么」去那边，查「这一步失败了怎么办」看这里。

## 一、主要旅程

### 1.1 装配一个 agent：从清单到三层

| 步骤 | 发生什么 | 产出 |
|---|---|---|
| 1 | 读 agent definition 与它引用的 plugin，得到要装的全部条目 | 一份**引用清单**，每条带着自己的 meta 标签 |
| 2 | 按[依赖关系](design.md#依赖)解析：每一项要成立还需要什么 | 一棵**依赖解析树** |
| 3 | 算每一项当下可不可用 | 每条目一个**可用性取值** |
| 4 | 不可用的，就地换成[同名替换件](design.md#替换件) | **装配清单**（形状与步骤 1 一致） |
| 5 | 按 meta 标签决定谁占槽位 | **系统提示词的成分** |

**步骤 4 之后条目数不变**——这是形状恒定的由来。
不可用的那些没有消失，只是换成了会解释自己的东西。

**两处 agent definition 压 plugin**：同一条目两边都标了 meta，以 definition 为准。

### 1.2 每次 run 开始前：重算可用性

| 步骤 | 发生什么 |
|---|---|
| 1 | 对装配清单里的每一项，**重新解析一遍依赖** |
| 2 | 可用性变了的，换上或换下[替换件](design.md#替换件) |
| 3 | 变化以**提醒**的形式让 agent 知道（送达机制归 run 那一块） |

**动作空间不变，槽位不变，只有可用性变。**

> 上一次 run 能用的，这一次可能就不能用了。**这不是故障**，是 §6.2 写明的性质。

### 1.3 agent 调用一个不占槽位的工具

它不需要先把工具"装进"什么地方——**经取用入口直接调用**。

| 步骤 | 发生什么 |
|---|---|
| 1 | agent 通过取用入口找到它要的那个工具 |
| 2 | **知道它收什么参数**——非 meta 工具的参数格式同样不在系统提示词里 |
| 3 | 发起调用 |

**全程 system prompt 不变。**这一条是硬的：系统提示词的成分在装配时定死，
运行中没有任何动作能改它（[PF-004 §5.4](../PF-004-agent-runtime-assembly-and-liveness/design.md#54-为什么系统提示词必须落在第三列)）。

### 1.4 agent 取用一份技能

| 步骤 | 发生什么 |
|---|---|
| 1 | agent 通过取用入口搜索或按名找到那份技能 |
| 2 | 取回它的正文 |
| 3 | 正文作为**这一次的返回内容**进入对话，随上下文自然存续 |

**同样不改变 system prompt**，也**不产生"已激活"这类需要维护的状态**。
上下文裁剪掉了就没了，还要用再取一次。

### 1.5 一次工具执行的生命周期

```text
                         发起
                          │
                     ┌────┴────┐
                     ↓         ↓
                  前台跑     后台跑
                     │  ⇄ 转后台  │      （转后台：自动超时，或用户手动）
                     │           │
              ┌──────┼───────────┼──────┐
              ↓      ↓           ↓      ↓
           进等待  完成        完成   进等待
              │      │           │      │
        拿到应答 / 等不到          拿到应答 / 等不到
              └──────┬───────────┴──────┘
                     ↓
              六种收场之一（design.md §5.3）
                     ↓
              结果回到 **session**
```

**前台/后台**与**是否在等待**是两个独立的维度，图中两侧各自成立。

### 1.6 一次执行跨越了多轮

| 时刻 | 发生什么 |
|---|---|
| 第 N 轮 | agent 发起一个长任务；它转后台，位置上留下一条**占位返回**说明已转后台 |
| 第 N 轮结束 | 这一轮结束了，**执行还在跑** |
| 第 N+1、N+2 轮 | agent 干别的。运行实例甚至可能已经退役重建 |
| 某一刻 | 执行完成，**结果回到那个 session** |
| 下一次 run | agent 以**提醒**的形式得知结果 |

**收件人是 session，不是发起它的那个运行实例。**
实例退役不影响送达——这正是[绑定关系](design.md#tool-execution)那样定的原因。

### 1.7 用户中断一次执行

| 步骤 | 发生什么 |
|---|---|
| 1 | 用户叫停 |
| 2 | 执行停下 |
| 3 | 位置上放一条**正常的返回消息**，语义是「**被用户手动中断**」 |
| 4 | agent 读到的是「这事不做了」，**不是「这事没成」** |

**绝不能**把它变成一个异常或失败递过去：agent 会重试，
而用户刚刚明确表示不想让它跑。

## 二、异常分支

| 分支 | 怎么处理 | 为什么 |
|---|---|---|
| **技能依赖的工具一个都没装** | 技能不可用，换[替换件](design.md#替换件)，说明缺什么 | 让 agent 读到一份自己执行不了的指引，比告诉它用不了更糟 |
| **技能依赖「A 或 B」，只有 A 在** | **可用** | 这正是要能表达「或」的原因 |
| **技能的可选依赖不满足** | **可用** | 可选就是可选，按最严的算会误杀一批好用的东西 |
| **工具依赖的外部服务连不上** | 工具不可用，换替换件 | 对端不归本系统掌握，断了不是本系统的故障 |
| **工具要的执行环境给不了** | 工具不可用，换替换件 | **绝不能降级给一个不满足要求的环境**——工具作者要隔离是因为他判断这东西不安全 |
| **agent 调用了替换件** | 返回「现在用不了 + 原因」，**正常返回** | 它要回答的是「为什么」，异常带不了这个信息 |
| **agent 反复调用同一个替换件** | 照常返回同样的说明 | 不做惩罚也不做静默。**它读得懂就会绕路**，读不懂是另一个问题 |
| **一个工具声明只要 A，实际去用了 B** | 这是**声明与实际不符**，属缺陷 | 可用性算出来是对的、跑起来是错的，排查时所有人都会先怀疑别处 |
| **不允许后台的工具跑太久** | 不自动转后台，也不允许手动转 | 声明就是声明。要能转后台，去改工具定义 |
| **等待态等不到应答** | 到上限后按第六种收场，**不是失败也不是被拒** | 混进失败，agent 会重试一个没人回应的东西 |
| **session 结束时还有执行没完** | 随之收场 | 收件人都没了，跑完也没处送 |
| **agent 无授权就想造工具** | 不发生 | §6.9 第一条 |
| **agent 造的工具与已有的重名** | 归后续 topic | 本 topic 只固定三条最小必要，不替它定冲突规则 |

## 三、状态流转

### 3.1 一个条目的可用性

```text
        每次 run 开始前重算
                │
        ┌───────┴────────┐
        ↓                ↓
      可用            不可用
   （真身在位）   （替换件在位，带原因）
        └───────┬────────┘
             来回切换
        动作空间、槽位  全程不变
```

**没有第三态。**「部分可用」不存在——可选依赖不满足的仍然算可用，
必需依赖不满足的就是不可用。

### 3.2 一次工具执行

| 状态 | 能转到哪 |
|---|---|
| **前台执行中** | 后台执行中 / 前台等待 / 完成 / 失败 / 被中断 |
| **后台执行中** | 后台等待 / 完成 / 失败 / 被中断 |
| **前台等待** | 前台执行中（拿到应答）/ 后台等待 / 等不到 / 被中断 |
| **后台等待** | 后台执行中（拿到应答）/ 等不到 / 被中断 |
| **完成 / 失败 / 被中断 / 等不到** | 终态 |

**前台 → 后台是单向的。**回不去：转后台之后这一轮已经继续往下走了，
再把它拉回前台等于要求时间倒流。

## 四、谁决定什么

| 事情 | 谁决定 | 谁不能决定 |
|---|---|---|
| 一个条目是不是 meta | **装配方**（agent definition 优先，其次 plugin） | 工具或技能的作者——他不知道装配方的预算 |
| 一个工具需要什么样的执行环境 | **工具作者** | 装配方不能放宽它；系统不能降级满足 |
| 一个工具能不能后台执行 | **工具作者** | 用户不能强行把不允许后台的切到后台 |
| 一次执行**要不要**转后台 | **用户**，或工具声明的自动超时 | agent 不替用户做这个决定 |
| 一次执行**要不要**中断 | **用户** | agent 不中断自己的执行 |
| 一项当下可不可用 | **依赖解析的结果** | 没有人能"手动设为可用"——那会让声明与实际脱节 |
| 取不取用一份技能、调不调一个非 meta 工具 | **agent 自己** | 系统不替它判断"你现在该看哪份指引" |
| agent 能不能造工具 | **授权** | agent 自己 |
| 造出来的东西归谁 | **运行时注入的租户上下文** | 谁都改不了——它是算出来的，不是配出来的 |
