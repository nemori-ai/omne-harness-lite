# PF-002：资产的种类与组合

- 修订：**rev 0（draft）**，2026-09-17
- 状态：**设计进行中，不可作为实施依据**

## 一、背景与问题

[PF-001](../PF-001-identity-scope-and-agent-constraints/design.md) 说清了资产
**对外**的样子：它挂在哪一层身份上、多层同时有值时怎么合成、official 是不可去除的底座。
但它把资产**内部**当成了一个黑箱——只列了一张"种类表"，没有说这些种类之间是什么关系。

黑箱留着，三件事就说不清：

- **一个 plugin 里装了一个 skill，这个 skill 是不是也是资产？**
  如果是，它能不能被单独引用、单独覆盖？如果不是，那它是什么？
- **一个 agent 由什么组装而成**，这件事和"一个 plugin 由什么组成"是不是同一回事？
- 组织在自己这层放了一个 customized skill，它**是否自动进入**所有引用了
  同能力标识的 plugin 和 agent definition？

这三个问题现在每次讨论都要重新发明一遍答案。

## 二、目标与非目标

### 目标

1. 把「资产」下面的**四类具体抽象**一一定义清楚。
2. 定义资产之间的**组合关系**：谁能组合谁，组合出来的东西怎么确定。
3. 说明**组装成 agent** 与资产之间的组合是同一种关系，还是两种。

### 非目标

> 待补。模型稳定之后再画边界——现在画会把没想清楚的东西当成边界排除掉。

## 四、概念定义

### 资产

> **沿用 [PF-001 §4](../PF-001-identity-scope-and-agent-constraints/design.md#四概念定义)**：
> 资产是范围化对象的一种，**约束 agent 由什么组装而成**。
> 它有能力标识、所属层、合成语义三个要素。

本 topic 在此基础上回答：资产具体有哪几类，它们之间怎么组合。

### 四类资产

**「资产」这个抽象下只有这四类。**

| 类 | 是什么 |
|---|---|
| **Skill** | {{待定义}} |
| **Tool** | {{待定义}} |
| **Plugin** | **分发与组合单元**。注意：**不是 Cordis 的 plugin**，是 `omne-next/omne_harness` 意义上的 **agent plugin**——它把若干资产打包在一起分发与启用 |
| **Agent Definition** | 一个 agent 的**静态定义**：它由什么组装而成、以什么面貌工作。不是会话，也不是运行实例 |

**Plugin 这个词有歧义风险。**本项目内核用 Cordis，Cordis 也有 plugin 的概念，
指的是运行时可装卸的代码单元。两者**完全不是一回事**：

| | Cordis plugin | 本 topic 的 Plugin |
|---|---|---|
| 是什么 | 运行时的代码装载单元 | 产品意义上的资产分发与组合单元 |
| 谁关心 | 实现与运行时 | 产品的使用者与管理者 |
| 归哪 | 技术设计 | 产品设计 |

正文出现「Plugin」一律指后者。指前者时必须写全「Cordis plugin」。

## 五、模型

### 组合是一种关系，不是四种

> **这一节是 PM 推导，待产品负责人确认。**推理链见 [decisions.md](decisions.md)。

产品负责人给出的两个判断：

1. 资产之间是**组合关系**；
2. 资产组装成 agent，**本质上也是组合关系**。

把两者合起来，得到一个统一的形状：**四类资产都是同一张组合图上的节点。**

```text
Agent Definition ──组合──→ Plugin ──组合──→ Skill
       │                     │
       │                     └──组合──→ Tool
       ├──组合──→ Skill
       ├──组合──→ Tool
       └──组合──→ Agent Definition   （sub-agent）
```

- **Skill 与 Tool** 通常是叶子。
- **Plugin** 组合出来的**还是资产**，可以继续被组合。
- **Agent Definition** 是特殊的组合节点：它被**实例化**时产生一个运行中的 agent；
  被**引用**时充当 sub-agent。

由此，「组装」不是第二种机制——**组装就是组合关系在一个 Agent Definition 上求值的结果**。

### 求值与组装是两步

这一点容易混，分开说：

| 步骤 | 输入 | 输出 | 归谁 |
|---|---|---|---|
| **求值** | (组织, 账号) + 五层作用域 | 这个租户**有哪些资产可用** | [PF-001 §6.2](../PF-001-identity-scope-and-agent-constraints/design.md#62-三种合成语义) |
| **组装** | 一个 Agent Definition + 上一步的可用集合 | 一个具体的 agent | 本 topic |

求值决定**候选集**，组装决定**实际构成**。
两步都做完，才能回答 agent 每次运行时问的那句"我现在由什么组装而成"。
