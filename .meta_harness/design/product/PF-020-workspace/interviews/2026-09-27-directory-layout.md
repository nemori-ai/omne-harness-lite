## 建议的共同目录结构

以下结构对两个根分别适用；子目录按需存在，不要求创建空目录。

```text
<工作区实例目录>/
├── .omne/
│   ├── workspace.json
│   ├── skills/
│   │   └── <技能包>/
│   │       ├── SKILL.md
│   │       ├── .omne/skill.json  # 可选的技能定义记录
│   │       ├── scripts/         # 按需携带的资源
│   │       ├── references/
│   │       └── assets/
│   ├── tools/
│   ├── mcps/
│   ├── connectors/
│   ├── loop-extensions/
│   ├── commands/
│   ├── plugins/
│   └── agents/
└── .omne.local/
    └── 与 .omne 相同的结构，按需存放本地定制
```

- 八个资产目录对应 Skill、Tool、MCP、Connector、Loop Extension、Slash Command、Plugin、Agent Definition；目录拼写是本轮建议，尚未定稿。
- 目录负责便于阅读和携带，能力身份仍按类别与 name；不得用目录重命名暗中改变资产身份。
- 技能包内部文件沿已有格式；其余类别先确定承载位置，逐类接续包格式，不假定它们都可用一个 Markdown 文件完整表达。
- 技能包内部的 `.omne/skill.json` 属于技能包，不因此被递归发现成另一个工作区。`scripts/` 的出现也不等于自动执行许可。
- `workspace.json` 建议继续集中登记资产、允许的设置配值和禁用，不同时另设一份表达相同事实的 `settings.json`。

## 自动发现的两种产品体验

**建议延续显式登记**：系统自动发现两个根的清单，按清单加载资产。放进目录但尚未登记的文件不自动成为会话能力；通过产品安装或创建资产的入口可以同时维护文件和登记，后者是本轮体验建议。优点是能明确看见将加载什么，也避免递归扫描插件包和技能附带文件造成重复加载；手工复制资产则多一步登记。

**另一种是约定目录直接发现**：把合法资产放进对应目录即加入装配候选，清单只承担设置或例外。手工使用更直接，但会改变 S-24 的显式列举政策，并需明确重复发现、插件成员与独立资产、未知文件的处置。这是需要产品负责人选择的体验，不由目录树替代裁决。

无论采用哪种，发现都不表示已获使用资格，更不表示启动 MCP、执行脚本或安装 loop extension。后续仍经过 PF-002 的过滤与装配。

## 设置、权限与规范的边界

1. **设置**：资产声明有哪些设置与默认值，清单为相应资产配值。两来源同能力资产按已定规则替换，不由此推出包内逐文件拼接、设置字段递归合并。
2. **只改共享资产的本地设置**：例如共享技能已存在，用户只想本地调整一个选项。当前 S-24 会丢弃指向本清单未列资产的配值，不能声称只写 local `assignments` 已支持此用法。建议将“允许独立本地配值、不复制资产”列为下一项产品讨论，明确其目标资产与冲突规则后再演进规格。
3. **权限**：不建议增加工作区 `permissions.json`。两个根都不能授予权限、解除组织锁定或绕过组织参与限制；鉴权绑定与凭据沿已有租户侧入口，不因 local 私有就改存于此。
4. **规范**：PF-002 的 Plugin 可包含 Rules 等声明式成员，但这不等于已经定义了一种独立的工作区规范资产。暂不赋予顶层 `rules/` “全部文件自动注入每个会话”的含义。需继续决定规范的归属、适用 agent／路径、加载时机及共享与本地冲突，再给出承载位置。
5. **运行数据**：建议会话记录、缓存及临时产物沿自身生命周期存放；不因 `.omne.local` 私有便把所有运行状态放进资产目录。

### 向产品负责人提出的配置建议

建议在两个根的 `workspace.json` 中增加同构的兼容来源配置；以下只是字段草案，省略现有清单的必填成员，不是可以直接交给现行 Schema 的完整文件：

```json
{
  "compatibility": {
    "codex": { "enabled": true },
    "claude-code": { "enabled": false }
  }
}
```

- 一个开关控制对应 harness 的三类受支持资产的发现，无须用户再把每份第三方资产复制或逐项登记到 `.omne`。这对原来“所有资产显式登记”的建议增加了受开关控制的第三方发现入口；Omne 原生资产是否自动扫描仍未决。
- 建议同一个开关由 local 显式值覆盖共享值，local 缺省继承；例如共享启用 Claude Code，本地可显式关闭。布尔设置不能按资产并集简单合并。用户尚未裁定这个覆盖规则及最终缺省值。
- 这个配置选择装载来源；不能把它直接塞进现行只为已列资产配值的 `assignments`，其设置归属与表示需在后续设计中明确。
- 直接复用意味着源文件仍留在第三方位置，兼容读取不自动改写它们。使用资格、命令型 MCP／hook 的默认禁用、hooks 干预力与 `allow` 映射继续沿 PF-002，开关不授予执行权。
- 仅取本轮三类相关声明，不引入外部 harness 的整体设置、权限政策、Agent Definition 或指令文件。用户家目录不在“同工作区”范围内；子目录发现深度及外部符号链接边界仍需后续明确。
