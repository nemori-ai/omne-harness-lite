# PF-020：验收标准

## 一、应当成立的场景

| 场景 | 应观察到的结果 |
|---|---|
| 用户自行 clone 项目，租户尚无对应工作区关系，并在新会话中发起首次登记与附着 | 可接入现有目录，建立工作区关系与实例关联；不要求先到治理中心单独建记录或重新 clone |
| 中心已登记工作区及当前租户关系，本地尚无实例 | 可从相应托管来源装载本地实例后附着，不因本地实例化创建另一份逻辑工作区 |
| 用户进入未登记的目录，只普通启动新会话 | 不自动建立关系，不因 .omne 或 .omne.local 存在而加载工作区来源 |
| 用户显式选择将已有本地目录作为工作区使用 | 发起关系登记并附着；向治理中心同步关系及必要关联标识，不自动上传目录文件 |
| 本地目录对应一个已存在的 Omne Host 工作区 | 关联该工作区并登记当前租户关系，不为此重复创建或上传中心工作区 |
| 已解除关系的目录被再次显式登记 | 按登记与授权规则重新建立关系，成功后可再次参与工作区装配；不由普通启动自动恢复 |
| 本地目录首次登记并附着成功 | 治理中心可列出该工作区，目录下的工作区来源按既有规则进入装配 |
| 首次登记失败 | 不报告已附着工作区，不提前加载目录中的工作区装配来源，不替换已有文件 |
| 登记一个外部 Git 仓库目录 | 不自动上传到 Omne Host，也不因此获得外部项目所有权或远端写权限 |
| 同一租户在两个连续会话中选择同一工作区 | 第二个会话能看到前一会话持久化的资源与成果 |
| 同一工作区在两台部署节点上被装载 | 两边识别为同一逻辑工作区，各自有工作区实例；不会各自生成两个工作区身份 |
| 租户 B 被授权维护租户 A 拥有的工作区，且 B 所属组织允许参与 | B 的实例写入同一个工作区状态，并记录 B 的租户、账号、实例和会话归因；不会生成 B 的副本工作区 |
| 租户 C 只有读取关系 | C 可以装载和读取工作区，但维护操作被拒绝 |
| 租户治理中心列出当前工作区 | 列表来自有效的租户—工作区关系；没有实例的工作区也能被列出 |
| 同一工作区通过本地路径与 GitHub/云端地址访问 | 地址不同但逻辑工作区身份仍可保持一致；地址不是身份 |
| 工作区同时有 Omne Host、GitHub、Obsidian 或 Office 365 地址 | 工作区仍是一个逻辑对象；每个地址显示自己的提供者类型，不自动生成多个工作区 |
| 公开 GitHub 地址被租户发现但尚未建立关系 | 可以显示为发现候选，但不能因此直接维护或写入工作区 |
| 不同 agent 类型先后处理同一工作区 | agent 类型变化不导致工作区资源聚合丢失或换主 |
| 工作区没有预先定义目标 | 会话仍可选择并装载它；目标可以在会话中指定或由 agent 从内容理解 |
| 工作区携带自定义 skill/tool 等资产 | 资产进入 PF-002 工作区层，并按其设置覆盖与权限过滤规则生效 |
| 工作区地址字符串被另一租户知道 | 另一租户不能仅凭地址访问或装载该工作区 |
| 当前目录对应工作区地址但会话未选择 | 工作区层保持为空，不发生隐式附着 |
| 普通参与租户删除自己的参与关系 | 允许退出，条目删除，本地内容保留 |
| 工作区超管删除自己的参与关系 | 允许退出，同时失去该工作区的超管授权 |
| 创建者或工作区超管移除参与租户 | 可以删除该参与关系，不清理对方本地目录 |
| 普通参与租户请求删除他人的关系 | 拒绝，目标关系不改变 |
| 请求单独删除仍存在工作区的唯一治理所有者关系 | 拒绝；只能沿已定义流程销毁工作区，本版不提供所有权移交 |
| 获准租户解除与工作区的关系 | 关系条目被删除，该关系不再出现在治理中心的有效关系投影中；本地文件保留 |
| 关系删除后，该租户的后续会话使用原目录，两个 Omne 目录仍存在 | 仅按普通本地目录处理；其中资产、设置、规范不进入工作区装配层 |
| 已解除关系的目录中，兼容开关仍开启且存在第三方资产 | 不再通过该工作区的兼容发现路径加载这些资产，不自动恢复关系 |
| A 删除自身参与关系，B 的关系仍有效 | A 使用原目录时没有工作区装配来源；B 的关系不受该删除影响 |
| 地址不可达或装载失败 | 用户看到明确失败；系统不静默创建空工作区或切换到另一工作区 |
| 本地实例目录外存在宿主机资源 | 是否可访问由 PF-005 和命令权限决定，不能把工作区目录当作安全围栏 |
| 组织启用参与限制，某租户或工作区不在允许范围内 | 不提供逐租户、逐工作区的例外豁免；仍按所选整体策略判定，工作区授权不替代组织许可 |
| 组织未配置工作区参与限制 | 默认不启用，不因工作区属于外组织而额外拒绝；仍须满足工作区及资源授权 |
| 组织从不启用改选参与范围 | 支持仅本组织、仅同一组织树；下一次实际会话装配时按当时策略判断 |
| 会话已装配，随后组织收紧策略或组织树发生变化 | 不运行中热同步重判，不逐次写入重新判断本项限制，也不强制触发重装配或结束会话 |
| 策略或组织树变化后会话再次发生装配 | 按当时最新策略和组织关系判定，不能沿用上次装配结论 |
| 组织已限制外组织工作区参与，租户把开源项目按普通目录使用 | 当前参与限制不拦截这条路径；仅沿既有环境和工具权限访问，工作区配置不进入装配。该场景记录已知缺口，不算已具备防绕过保障 |
| 组织限制为只准参与本组织，目标工作区属于同树的另一个组织 | 即使工作区授予维护资格，也不得开发、维护或写入；原有读取资格不受本项限制影响 |
| 组织限制为只准参与同树，目标属于同树另一组织且已授权维护 | 组织侧允许参与；仍须通过工作区具体写入授权 |
| 组织限制为只准参与同树，目标属于另一棵组织树 | 不得参与开发、维护或写入；已获准的读取仍可进行 |
| 有 Omne Host 治理所有者的工作区同时具有 GitHub 地址，另一托管工作区属于外组织 | 按治理所有者租户的组织判断，不按地址提供者判断；外部仓库登记不因 GitHub 地址被赋予治理所有者或组织归属 |
| 租户无某私有工作区的读取资格 | 不因组织限制“不拦读取”而获得读取资格 |
| 实例下两个目录分别提供不同能力资产 | 自动发现后可用资产取并集，不因存在 local 而丢掉其他共享资产 |
| 两目录都有相同类别与 name 的可用资产 | local 覆盖共享候选，来源可见；共享原件不被覆盖写入 |
| 同名资产类别不同 | 两份都可参与，不被误认为同能力冲突 |
| local 同能力资产被禁用或无使用资格，共享候选仍可用 | local 不遮蔽共享候选；继续按 PF-002 的既有次序求值 |
| 组织锁定某能力的替换，而目录中有同名资产 | 两个目录都不能绕过组织锁定 |
| A、B 的会话共用同一物理实例 | 可以读取同一份 .omne.local 来源，按各自租户身份与治理配置分别求值；不要求实例固定归某一租户，也不保证该目录内容跨租户私有 |
| `.omne` 内容发生变更 | 变更属于共享同步内容；同步完成时间与冲突处理按后续策略验收 |
| `.omne.local` 内容发生变更 | 不进入共享上传或向其他租户同步，不上传合并后的有效内容来代替源内容 |
| 两目录写入权限放宽配置，或带来本地命令型 MCP/hook | 权限配值按 PF-002 过滤；命令型组件不因自动发现就启动 |

## 二、设置与第三方来源的补充场景

| 场景 | 应观察到的结果 |
|---|---|
| 同一布尔项共享为 `true`、local 为 `false` | 有效值为 `false`，不能取 OR 得到 `true` |
| 同一布尔项共享为 `false`、local 为 `true` | 有效值为 `true` |
| local 未配置某项，共享有显式值 | 采用共享值，不把未配置当成 `false` |
| 两目录各配置不同的设置项 | 均保留；同项非布尔设置也以 local 显式值优先 |
| Codex 开启、Claude Code 关闭 | 按 Codex 约定识别 `.agents`、`.codex` 中受支持资产，不因 Claude Code 目录存在而加载它 |
| Claude Code 开启，MCP 配置在工作区根 `.mcp.json` | 按该 harness 约定发现，不因文件位于 `.claude` 外而遗漏 |
| 两根均未配置 Codex 或 Claude Code 兼容开关，但第三方目录存在 | 对应来源默认关闭，不发现其中资产 |
| 第三方来源启用并含受支持的 Skill、MCP、hook | 无须复制到 `.omne` 或逐项登记；仍按 PF-002 过滤与装配，不自动授权运行 |
| Omne 原生与兼容来源有同能力可用资产 | 原生优先，来源与替换原因可见 |
| Codex 与 Claude Code 有同能力、不同内容的候选且未获选择 | 显示冲突，不静默选择一家；同一来源多路径发现不重复执行 hook |
| 第三方配置还含权限政策、Agent Definition 或指令文件 | 本项兼容开关不将它们一并导入 |

## 三、目录布局的补充场景

| 场景 | 应观察到的结果 |
|---|---|
| 用户在共享或本地根放置八类资产 | 两处均使用 `skills/`、`tools/`、`mcps/`、`connectors/`、`loop-extensions/`、`commands/`、`plugins/`、`agents/` 对应同一组类别 |
| 工作区只使用 Skill | 不要求补齐其他七类空目录，根命名空间约定位置下符合包格式的 Skill 自动发现，无须逐项登记 |
| 嵌套子项目包含资产命名空间，但根配置未登记相关路径 | 不递归发现其中资产 |
| 根配置登记了嵌套目录的相对路径或通配符 | 在登记范围按资产格式发现，匹配语法以后续规格为准 |
| 默认、登记或通配符匹配遇到软链接，或路径需穿过软链接 | 不发现、不跟随，不以解析后的目标路径绕过限制 |
| 命名空间目录缺失，或有资产但 workspace.json 缺失 | 缺失目录为空来源；缺失配置仍发现默认范围，未配值按各自既定默认规则 |
| 任一根的 workspace.json 无法解析或不符合配置格式 | 指明文件与错误并阻止本次装配，不静默忽略或回退到另一根 |
| 用户配置资产、设置、禁用或兼容来源开关 | 各根通过自己的 `workspace.json` 集中表达，不要求另写同义 `settings.json` |
| 技能包含 `.omne/skill.json` 与资源子目录 | 定义记录属于技能包，不递归产生另一个工作区；资源不会因目录位置自动执行 |
| local 只有针对共享资产的设置覆盖，没有同名资产包 | 继续使用共享资产，按允许的设置和既定优先级应用覆盖，无须复制资产 |
| 可用的同名 local 资产与针对共享资产的 local 设置覆盖同时存在 | 使用完整 local 实现，不叠加这份共享实现覆盖；即使某设置不冲突也不混入 |
| local 替换共享技能，但缺少共享技能里的某个脚本 | 使用完整的 local 包，不从共享包补文件形成混合资产 |

## Omne Host 首版类型的补充场景

| 场景 | 应观察到的结果 |
|---|---|
| 租户创建 Omne Host 工作区 | 可以选择管理类型；首版仅提供 Git |
| 创建后在获准部署节点装载实例 | 中心资源按 Git 管理，实例为相应工作副本；仍指向同一逻辑工作区 |
| 查看工作区的分类 | Omne 原生类别、omne-host 中心地址提供者、Git 管理类型分别表达 |
| Git 工作区包含文档、PPT 或表格 | 不因不是代码而被排除；文件及仓库容量限制按所选 Git 托管服务与部署配置验收 |
| Git 工作区实例卸载 | 不因此删除中心托管资源或工作区身份 |

### 装配与显式资产重载

| 场景 | 应观察到的结果 |
|---|---|
| 会话运行中新增、替换资产或修改工作区配置 | 不自动静默刷新已有装配；agent 直接读到新文件不等于装配已更新 |
| Git 同步带来资产或兼容开关变化 | 不自动触发重载；下一次实际装配时读取最新来源 |
| 已有会话需要应用资产更新 | 提供显式资产热重载命令，执行后先校验数据，通过后才替换 agent runtime 内存中的相应数据 |
| 重载前校验发现配置错误 | 明确报告错误；原有内存数据尚未替换，不报告更新成功或留下部分替换结果 |

## 四、生命周期与自主同步的补充场景

| 场景 | 应观察到的结果 |
|---|---|
| 部署节点已有实例，尚无会话 | 实例可以独立存在，后续会话可选择并附着 |
| 创建会话请求指定目标工作区及本地装载路径 | 先完成装载，再创建会话并附着；装载失败不报告该路径已创建成功 |
| 使用实例的会话结束 | 不自动卸载或删除实例，工作区仍持续存在 |
| 用户修改本地文件，agent 仍在处理另一部分工作 | 不要求立即刷新上下文；用户告知或 agent 后续读取时感知变化 |
| 用户在 remote 上传文件 | 不要求会话即时同步；agent 可按用户指示或工作需要检查、获取和整合 |
| 本地变更尚未 push，或另一个实例尚未取得 remote 变更 | 允许暂时不同步，不能报告各处已一致 |
| agent 检查后发现 Git 冲突且具备处理所需信息与授权 | 可自主处理，不强制每次转交用户决定 |
| agent 为并行任务建立分支或 Git worktree | 仅产生 Git 工作目录，不自动登记 Omne 实例或新的逻辑工作区 |
| 会话显式选择 worktree 作为工作区使用 | 识别并关联实例，继续指向原逻辑工作区 |
| 一个会话让多个 subagent 并行处理同一项目 | 可以分别使用多个 worktree 的工作目录，不要求都挤在同一目录 |
| 用户接入已经有文件的本地目录 | 直接使用原内容，不重新 clone 或替换文件 |
| 从中心实例化到的路径与已有内容冲突 | 沿 Git 原生结果报错，不自动删除、覆盖或合并；用户或 agent 决定复用或换路径 |
| 同步操作失败 | 失败与当前状态可见；不因异步处理而伪报完成 |
| 用户不再使用某个本地实例 | 后续会话不再附着即可；无需先完成治理中心的卸载或清理流程 |
| 中心存储中的工作区确认销毁，本地实例仍在 | 删除指向该工作区的全部租户关系，包括治理所有者；本地内容保留，后续会话按普通目录使用且不加载工作区来源 |
| 创建者租户请求销毁工作区，既有治理与资源授权允许 | 具有销毁资格；确认销毁后执行全部关系删除 |
| 创建者授予或撤回某租户的工作区超管权限 | 允许；撤回保留参与关系，其他权限仍按已有授权 |
| 工作区超管尝试向另一个租户授予超管权限 | 不允许转授；不能以已有超管身份取得此权限 |
| 创建者明确授予工作区超管权限的租户请求销毁 | 具有该工作区的销毁资格，不要求转移工作区治理归属 |
| 普通参与者、一般管理员或仅有组织超管身份的租户请求销毁 | 未具备创建者身份或获授该工作区超管权限时拒绝，不改变资源或关系 |
| 中心暂不可达或销毁结果尚未确认 | 不认定已销毁，不以此触发全部租户关系删除 |

### 原生能力与产品接口

| 场景 | 应观察到的结果 |
|---|---|
| agent 在 Git 工作区中提交、合并或同步 | 可通过已有通用工具使用 Git 原生能力，不要求先转换成 Omne 专用命令 |
| 人通过产品界面管理 Git 工作区 | 操作及结果由产品契约表达，版本、合并与同步沿用 Git 语义；失败不得显示为成功 |
| agent 直接使用 Git 后，界面按需读取状态 | 应反映实际资源状态，不以“未经过 Omne 专用工具”为由维持另一套相矛盾的版本记录；不要求即时推送 |
| 后续设计其他管理类型 | 保持 Workspace 的共同治理与实例语义，具体能力复用相应资源系统，不强求其具备 Git 分支或 worktree |

## 五、绝不能发生

- 同一个逻辑工作区因为换了机器、agent 类型或地址，就被当成互不相干的多个工作区。
- 被授权维护的租户修改共享资源时被静默写入自己的私有副本。
- 仅因为地址公开或提供者是 GitHub，就自动获得工作区写权限。
- 工作区资源把组织或租户锁定的权限、凭据、落点或身份设置放宽。
- 未经租户授权，仅凭地址或当前目录装载工作区。
- 把单次会话目标写回成工作区的固定目标。
- 装载失败时静默新建一个工作区并报告成功。
- 用工作区邀请、实例已装载或 `.omne.local` 的配置绕过组织的参与限制。
- 因组织禁止参与外部工作而一并拒绝原本有资格的只读访问。
- 将实例 `.omne.local` 内容作为工作区共享同步内容上传，或把它当成共用物理实例时的租户隐私保证。
- 把工作区所有者的组织设置、凭据或私有资产自动用于参与者会话。
- 将工作区或实例的存活强制绑定到某个会话，或会话结束即自动清理实例。
- 将资源同步可异步解释成授权检查可以省略，或将发起同步解释成已经完成同步。

## 六、本版不验收

AGENTS.md 的社区规范兼容、嵌套目录首次访问加载与上下文处理交给 runtime context 设计和相应验收，不在这里定义专属工作区说明文件或将其按资产重载规则验收。


具体 Git 托管与同步实现、并发完整性、地址发现及交付面交互，须在对应产品选择和规格完成后验收。上述 agent 自主运用 Git、冲突不强制转交用户及操作结果真实的产品场景已经明确；待裁范围见 [design §九](design.md#九未决项)。

## 资源操作与首版范围

| 场景 | 预期 |
|---|---|
| 用户在工作区完成文档或代码成果 | 无须先经过额外的工作区发布或交付流程；版本与里程碑沿 Git 及具体任务管理 |
| 上传或同步触及文件大小或仓库容量限制 | 明确报告失败，本地原件保留；不静默截断、遗漏或显示成功 |
| 工作区配置多个 Git remote，向其中一个推送 | 按所选目标及 Git 原生结果呈现，不显示为所有地址和实例均已同步 |
| 上传或同步仅排队或开始执行 | 不显示为目标资源已完成更新 |

## 外部仓库登记的参与者边界

| 场景 | 必须可观察的结果 |
|---|---|
| 首次登记尚无 Omne 工作区记录的外部仓库 | 只建立该租户的参与关系，不创建 Omne 治理所有者关系；外部项目所有权和资源写权限不因此改变 |
| 第二个租户登记同一外部工作区 | 同为参与者，首登租户不因登记先后获得治理特权 |
| 外部工作区的参与者退出 | 删除自身关系，不删除其他租户关系、不销毁外部仓库或清理本地文件 |
| 首登租户仅凭首次登记请求移除他人或授予工作区超管 | 首次登记不提供这些治理资格，不把它当 Omne Host 工作区创建 |
| 组织已启用参与范围限制，请求把无 Omne 治理所有者的外部仓库作为工作区附着 | 不认定工作区身份、不加载 `.omne`、`.omne.local` 或兼容来源；不能把首登或参与租户的组织补成归属，也不报告已成功附着 |
| 受限组织的租户按普通目录访问同一外部仓库 | 沿 Files／Shell 与底层资源原权限访问，不加载工作区来源；不能声称已阻止文件系统层面的使用 |
| 组织限制从关闭改为启用，会话已装配外部工作区 | 不热重判当前运行、不自动删除关系或本地文件；下一次实际装配时不给工作区身份及装配来源 |
