## 二、PM 推导

1. 将装载后的具体工作入口命名为**工作区实例**，以便把逻辑工作区与本地/远端承载分开。
   实例的精确身份和状态机仍未定；与会话解耦及资源异步同步原则已由后续用户输入确定。
2. 将本地路径、GitHub URL、云端存储等统一称为**工作区地址**，作为属性/访问关系，不作为
   工作区身份。一个工作区可以有多个地址。
3. PF-002 继续拥有“工作区资产层”的求值规则；PF-020 拥有工作区本体、实例和地址的更广义边界。
4. PF-002 原先用“承载目录”描述的内容，应理解为一个工作区地址或实例的本地实现，而不再是
   工作区身份本身。
5. **组织归属按治理所有者租户所在组织判断**：工作区已有治理所有者，租户身份已有组织这一分量，因此沿已有关系即可判定；GitHub 等提供者不是组织归属，不另引入一项独立的工作区组织所有者。本版不提供治理所有权移交，后续用户已明确确认。
6. **组织许可与工作区授权同时成立**：组织限制防止自身资源外用，工作区授权保护资源，两者回答不同问题。只读豁免只针对本项组织限制，不推出对私有资源的读取权，也不让工作区所有者的组织配置自动进入参与者会话。
7. **两个目录是同一工作区层的两种来源**：目录约定没有增加身份层；“同能力”沿 PF-002 的类别 ＋ name。local 优先不覆盖禁用、使用资格与上层锁定，先过滤再在可用候选中替换；因此被过滤的 local 候选不会遮蔽仍可用的共享候选。
8. **本地定制不等于租户治理配值**：用户指定的是工作区实例内的目录，而非租户层的治理入口。两目录继续受 PF-002 的工作区权限过滤约束；放宽工作区资产权限仍走收进租户层后配值的既有路径。
9. **不把有效合并结果写回共享目录**：用户分别规定共享内容与单租户本地内容；若同步合并结果，local 定制就会被传播给其他租户，与用户要求矛盾。共享同步须保留这一区别，具体实现后续决定。

10. **将 Git 选型称为工作区管理类型**：用户明确同一 Omne Host 未来可提供多种类型；既有工作区类别回答治理归属、地址提供者回答地址来自谁，两者都不能表达这个选择。因此单独以管理类型属性表达；Git 工作区沿用工作区身份与生命周期，作为变体，不另造身份对象。

11. **生命周期解耦不以会话终结隐式清理实例**：用户明确节点可以先有实例、会话随后附着，因此不能把实例存活绑定在单次会话上。
12. **异步的是资源同步，不是授权豁免**：用户限定在本地与 remote 文件变更、会话感知语境；不据此修改组织参与限制或租户访问资格。
13. **自主工作需要真实操作结果**：agent 被赋予同步与冲突判断责任，就必须能取得差异、冲突及失败状态；发起异步同步不能被表述为 remote 已更新。

14. **同一概念保留词条身份**：`GitBasedWorkspace` 明确此前 Git 工作区的类型记法，身份与生灭未改变，继续使用 `UL-git-workspace`，不另立一个对象。
15. **共同契约不强制 Git 特有能力**：既然未来类型复用各自原生资源系统，共同工作区约定就不能以具有 Git 分支或 worktree 为准入条件；能力差异应如实表达，精确协议待后续设计。
16. **统一反映实际资源状态**：agent 可直接操作 Git，人也可通过界面操作，因此界面按需读取的结果须来自同一实际资源状态，不维护只认专用接口的第二套版本事实；不因此增加实时刷新义务。

17. **第三方发现随工作区来源一同退出装配**：其开关属于双目录工作区配置，用户明确这些目录不再影响装配，故不能继续由残留开关引入兼容资产；不据此重定义其他独立的资产来源。
18. **删除单条关系不删除其他租户关系**：用户明确删除的是关系条目，同一工作区允许多个租户参与，因此只取消该条关系的标识，不把工作区全局身份或他人关系一并删除；中心销毁的级联另行裁定。

19. **接入本地目录不要求重新下载或迁移**：用户给出的场景是已有 clone 直接开始会话，因此登记接入已有资源；不能将“记录为可用工作区”扩大为上传到 Omne Host 或取得外部项目所有权。

20. **创建先后以当前租户的登记为参照**：用户明确本地先有时可指向已经存在的 Omne Host 工作区，因此“本地先有”不意味着中心资源尚不存在；矩阵将租户登记先后与资源提供者分轴，避免把登记当作托管迁移。

21. **销毁资格与治理归属分开表达**：用户将销毁授权语境中的所有者明确为创建者或其授予超管权限的租户；既有组织归属依赖唯一治理所有者。此次是授权扩展，没有要求转移治理归属，因此工作区超管作为租户在该工作区上的权限角色表达，不新增身份对象或多个组织归属。
22. **工作区超管不等于组织超管或一般管理能力**：用户限定授权来源为工作区创建者，不能仅凭组织角色或原有 `administer` 能力推定销毁权。其余管理能力、撤回和再授权不由本次销毁裁决补全。

23. **实例本地不是租户级私有**：用户明确允许实例跨租户共用且按会话装配求值；同一物理目录中的 `.omne.local` 不会凭读取者身份自然变成不同文件。因此收窄为不进入中心共享同步的实例本地来源，不再保证共用实例的租户彼此不可读。租户层私有配置与凭据仍不共享，实例共用不扩大其授权。

24. **未来扩展不构成首版未决**：首版仅 Git、原生能力复用及保持简单已有裁决，因此不为其他类型转换、提供者自助注册预设产品政策；待引入相应能力时再裁定。具体 UI、协议与 Git 服务选型移交已有责任方，不为清空清单而补默认值。

- **会话与交付面产品投影已对齐**：PF-015 rev 13、PF-016 rev 10 已按有效参与关系、显式首次登记与实例解耦修订；原“仅租户持有”“仅本机清单”表述不再成立。具体接口、命令拼法和交付布局仍由后续规格承接，详见本次跨 PF 回顾。

- PF-004 §6.3 已区分可选能力增量装载与必需构成变化；本轮资产热重载命令提供显式触发入口，需在该约束下设计，不能由命令名称推断任何资产都可原地替换。PF-016 及后续交付面应承接入口，当前尚未命名或实现该命令。
