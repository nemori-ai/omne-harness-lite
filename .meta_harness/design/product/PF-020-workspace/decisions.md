# PF-020 决策与来源

本页区分用户已经明确的方向、PM 为使模型可用而作的推导，以及仍需继续讨论的事项。

## 一、用户已明确

| 日期 | 方向 | 落点 |
|---|---|---|
| 2026-09-24 | 工作区归属于一个租户 | design §四·1 |
| 2026-09-24 | 工作区是跨会话持续、可由不同 agent 类型访问的治理和逻辑概念 | design §三、§四·2 |
| 2026-09-24 | 工作区通常有物理边界，但可以是代码仓库、PPT、Excel、知识库或整台宿主机等完整资源聚合 | design §三·工作区 |
| 2026-09-24 | 工作区不绑定一个固定目标；目标可以由内容感知或在单次会话中指定 | design §二、§四·3 |

| 2026-09-24 | 同一租户可在多个物理机部署，资源装载后 agent 才能持续迭代 | design §三·工作区实例、§四·4–5 |
| 2026-09-24 | 工作区允许带有自定义资产 | design §四·7 |

## 二、PM 推导

1. 将装载后的具体工作入口命名为**工作区实例**，以便把逻辑工作区与本地/远端承载分开。
   这是当前产品模型的建议名；实例的精确身份、生命周期和同步语义仍未定。
2. 将本地路径、GitHub URL、云端存储等统一称为**工作区地址**，作为属性/访问关系，不作为
   工作区身份。一个工作区可以有多个地址。
3. PF-002 继续拥有“工作区资产层”的求值规则；PF-020 拥有工作区本体、实例和地址的更广义边界。
4. PF-002 原先用“承载目录”描述的内容，应理解为一个工作区地址或实例的本地实现，而不再是
   工作区身份本身。

## 三、待继续讨论

- 工作区的具体身份格式、命名、删除、归档和恢复。
- 实例的身份、状态、装载/卸载、失效和恢复。
- 中心存储与多地址之间谁是权威，是否允许多个可写副本。
- 多实例并发写入、一致性、冲突解决和断线恢复。
- 地址的发现、校验、凭据引用与权限授予。
- 会话选择逻辑工作区后解析实例，还是直接选择实例。

## 四、来源问题

- PF-005 中“共享的工作空间”可能指执行环境中的共享空间；在它的产品语境确认前，不能直接
  把该说法与 PF-020 的逻辑工作区视为同一对象。
- PF-001、PF-015、PF-016 仍有部分旧文案把工作区写成本地目录；它们需要随本 topic 的接受版本
  做一次词义对账，本版先保留其既有核心隔离与显式选择规则。
