# PF-020：工作区

工作区是一个跨会话持续存在、带有自身身份和治理归属的完整资源聚合包。它有一个治理所有者租户，
也可以授权其他租户参与同一个工作区；不同类型的 agent 可以在不同会话和不同部署节点上继续工作；它不绑定一个固定目标，
也不等同于某台机器上的目录。

本 topic 先把工作区本体、租户—工作区关系、工作区实例和工作区地址分开，并把工作区类别与地址提供者类型分轴。资产层的设置、替换和权限过滤
仍由 [PF-002](../PF-002-assets-settings-and-permissions/README.md) 负责；本版不提前决定
Git 托管产品、实例标识或操作接口的具体协议；Git 资源管理复用原生机制，由 agent 自主运用。

组织参与限制默认不启用，可选仅本组织或同一组织隶属树；首版不提供逐租户、逐工作区例外豁免，两种限制均不拦原有资格下的只读访问。
组织参与限制只在会话装配阶段判定，运行中不热同步重判。当前仍无法阻止将开源项目当作普通本地目录访问和使用，见[已知覆盖缺口](design.md#已知覆盖缺口普通目录使用)；不将其表述为完整的防“公器私用”保障。
实例目录下的 `.omne` 与 `.omne.local` 结构相同，用于自动发现资产、配置与规范；可用内容取并集，
同能力资产由 local 覆盖共享来源，同项设置（含布尔值）亦以 local 显式值优先。`.omne` 的变更进入共享同步，`.omne.local` 留在实例本地、不进入共享同步；实例可以跨租户共用，各会话分别求值，不以目录名承诺租户间私有。

Codex 与 Claude Code 分别开关、默认关闭且须显式开启，仅复用同工作区的 Skill、MCP、hook；原生同能力资产优先，第三方之间的不同内容冲突显式选择。

local 可以只为共享资产提供设置覆盖；选用同名 local 资产时，以完整实现为准，不叠加针对共享资产的设置覆盖。资产配置在装配时读取，运行中通过显式资产热重载命令更新，不自动静默重载；校验通过后才替换内存数据，校验失败原数据不变。AGENTS.md 的支持交由 runtime context 设计承接。

两个根都采用可选的 `workspace.json` 集中配置，资产按八类约定目录自动发现；嵌套目录须登记相对路径，可用通配符，软链接始终排除。配置缺失正常，解析或格式错误阻止装配；见[目录内部结构](design.md#目录内部结构)。

统一抽象为 `Workspace`，Git 特化为 `GitBasedWorkspace`，复用 Git 原生能力；契约与接口主要服务前端和人的使用，不另要求 agent 使用定制 Git 工具。

Omne Host 首版仅提供 Git 工作区，中心托管 Git 仓库，部署节点装载工作副本；租户创建时选择管理类型，未来可增加其他类型。管理类型与工作区类别、地址提供者分别表达。

工作区及实例与会话生命周期解耦：既可先有实例再附着，也可在创建会话时指定本地路径，先装载再创建。会话视实例为本地、中心为 remote，资源同步允许异步；agent 按需感知变更，自主同步、解决 Git 冲突，并以分支和 worktree 组织协作。

## 状态

- 产品设计：**rev 21，已正式接受（active）**，接受依据见 [D-074](../../record/decisions/session-workspace-product-acceptance/decision.md)。核心模型、Git 原生能力复用、目录装配与实例解耦已明确。支持中心先登记后实例化、本地先有后显式登记附着；关系登记不上传资源。解除即删除关系条目，未重新显式登记前按普通目录使用。中心销毁仅限创建者或其授予的工作区超管，销毁后删除全部关联关系、本地内容保留。参与租户可退出，创建者及工作区超管可移除参与租户；唯一治理所有者不能单独退出，本版不提供所有权移交。
- 未决项：首版没有需继续新增的产品裁决；保留未来扩展、跨 PF 与交付面交接，以及后续规格与实现细化（见 [design.md 第九节](design.md#九未决项)）。
- 待讨论策略见 [decisions.md](decisions.md#三待继续讨论)；用户已明确的方向与 PM 推导分列，不为未决项填写默认值。
- 技术投影：尚未开始。
