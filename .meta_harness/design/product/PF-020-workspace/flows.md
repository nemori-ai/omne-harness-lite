# PF-020：流程与状态

本页描述产品可观察的流转；两个目录的名称、合并与共享边界按产品规则，文件格式、同步协议和具体装载实现尚未定义。

## 一、选择与装载

1. 会话创建或恢复时，交付面提出一个工作区选择：逻辑工作区、一个地址，或一个可用的工作区实例。
2. 系统核对会话租户的资源访问资格；若要参与开发、维护和写入，还须检查所属组织的工作区参与限制。只读不受这两种组织限制阻拦，但不会因此获得原本没有的资源访问权。
3. 解析地址并装载或复用可访问实例；会话显式附着后，实例成为 agent 的工作入口，并记录本会话代表的租户关系。
4. 未选择工作区时，核心不因当前目录自动附着；工作区层为空。交付面给出的默认值必须经过显式确认或提交。
5. 授权失败、地址不可达或装载失败都要显式报告，不能静默换成另一工作区。

### 附着后的发现与装配

1. 从实例目录下的 `.omne` 与对应租户的 `.omne.local` 自动发现资产、配置和规范，使用相同结构与解析规则；不要求再手工导入每份工作区资产。
2. 保留每项的来源与归属。读取目录不启动其中的命令，不把另一租户的 local 内容或凭据纳入候选。
3. 按 PF-002 过滤禁用、无使用资格的资产以及工作区不能提供的配值。两个目录的可用内容取并集，同能力资产 local 优先；local 被过滤时，共享候选仍可参与。
4. 按会话租户所在组织、租户自身与工作区候选求值，再按所选 Agent Definition 组装、投影属性、计算有效值。工作区所有者的组织与私有配置不因所有权自动成为参与者的输入。
5. 按 PF-004 形成装配清单并进入所需初始化；必需资源缺失时明确失败，不报告残缺装配成功。本地命令型 MCP 与命令型 hook 的默认禁用、逐件启用规则继续成立。

运行中配置发现与重新加载的具体触发由后续策略确定；资源同步不是改写在途装配的隐式指令。

## 二、跨会话与跨节点继续

- 下一次会话可以选择同一个逻辑工作区，并复用已有实例或在另一节点建立新实例。
- 被授权参与的其他租户也可以选择同一个逻辑工作区；这不会创建一个新的工作区身份。
- agent 类型可以变化；只要实例与资源可用，工作区身份和资源聚合继续保持。
- 一个实例卸载不删除工作区；实例是否可以继续被复用、何时失效，待后续生命周期决定。

## 三、地址变化与多实例

- 地址可以被替换、增加或暂时不可达；地址变化本身不创建新工作区。
- 同一租户可在多个部署节点上装载同一工作区；并发写入与冲突处理尚未定义。
- 不同地址提供者可以指向同一工作区，但只有明确标为权威或被后续同步策略接受的写入才改变共享状态。
- 不同租户即使提供相同字符串地址，也不能仅凭地址获得授权；获得授权后可以访问同一工作区共享资源，本地定制仍分别隔离。

### 共享与本地变更

- `.omne` 中的每次变更应同步到云端，并向其他获准租户共享；何时上传、何时算完成、离线和冲突如何处理，留给 Omne Host 及相应提供者设计。
- `.omne.local` 中的变更只改变对应租户本地的定制；不得把两目录合并后的有效结果整体作为共享内容上传。
- 修改共享目录仍是工作区写入，必须通过所属组织参与限制与工作区授权；只读资格不因自动加载而升级为维护资格。

## 四、异常与禁止的隐式行为

| 触发 | 产品行为 |
|---|---|
| 地址存在但租户无权访问 | 拒绝访问并说明原因，不建立实例 |
| 地址不可达 | 报告装载失败；不新建空工作区冒充成功 |
| 租户没有有效的租户—工作区关系 | 拒绝访问或维护，不因公开地址自动建立写权限 |
| 工作区实例被卸载 | 当前需要它的操作显式失败或进入待恢复状态，具体恢复策略待定 |
| 当前目录恰好对应某地址但会话未选择 | 不自动附着工作区 |
| 工作区资源带来权限放宽配置 | 按 PF-002 过滤，不改变租户或组织边界 |
| 工作区授权维护，但所属组织禁止在该组织范围参与 | 不允许开发、维护和写入；保留原有只读访问资格 |
| `.omne.local` 与 `.omne` 提供同能力资产 | 可用候选中 local 优先，只影响本租户；不改写共享原件 |
| 工作区上传或同步包含本地定制 | 不得将 `.omne.local` 作为共享内容传播；具体失败与重试流程待同步设计 |
