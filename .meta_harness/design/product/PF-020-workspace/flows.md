# PF-020：流程与状态

本页只描述产品可观察的流转；地址解析、文件格式、同步协议和 Cordis 生命周期留给后续规格。

## 一、选择与装载

1. 会话创建或恢复时，交付面提出一个工作区选择：逻辑工作区、一个地址，或一个可用的工作区实例。
2. 系统先核对会话租户是否拥有有效的租户—工作区关系，以及该关系是否允许当前动作，再解析地址并装载或复用工作区实例。
3. 装载成功后，实例成为本次会话中 agent 的工作入口；工作区资源和 PF-002 允许的自定义资产进入求值，并记录实例代表的租户关系。
4. 未选择工作区时，核心不因当前目录自动附着；工作区层为空。交付面给出的默认值必须经过显式确认或提交。
5. 授权失败、地址不可达或装载失败都要显式报告，不能静默换成另一工作区。

## 二、跨会话与跨节点继续

- 下一次会话可以选择同一个逻辑工作区，并复用已有实例或在另一节点建立新实例。
- 被授权参与的其他租户也可以选择同一个逻辑工作区；这不会创建一个新的工作区身份。
- agent 类型可以变化；只要实例与资源可用，工作区身份和资源聚合继续保持。
- 一个实例卸载不删除工作区；实例是否可以继续被复用、何时失效，待后续生命周期决定。

## 三、地址变化与多实例

- 地址可以被替换、增加或暂时不可达；地址变化本身不创建新工作区。
- 同一租户可在多个部署节点上装载同一工作区；并发写入与冲突处理尚未定义。
- 不同地址提供者可以指向同一工作区，但只有明确标为权威或被后续同步策略接受的写入才改变共享状态。
- 不同租户即使提供相同字符串地址，也不能因此看到同一工作区资源。

## 四、异常与禁止的隐式行为

| 触发 | 产品行为 |
|---|---|
| 地址存在但租户无权访问 | 拒绝访问并说明原因，不建立实例 |
| 地址不可达 | 报告装载失败；不新建空工作区冒充成功 |
| 租户没有有效的租户—工作区关系 | 拒绝访问或维护，不因公开地址自动建立写权限 |
| 工作区实例被卸载 | 当前需要它的操作显式失败或进入待恢复状态，具体恢复策略待定 |
| 当前目录恰好对应某地址但会话未选择 | 不自动附着工作区 |
| 工作区资源带来权限放宽配置 | 按 PF-002 过滤，不改变租户或组织边界 |
