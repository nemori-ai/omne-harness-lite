# PF-020：流程与状态

本页描述产品可观察的流转；两个目录的名称、内部布局、合并与共享边界按产品规则，配置字段、各类包的精确格式、同步协议和具体装载实现沿后续设计与规格展开。

## 创建 Omne Host 工作区

1. 租户创建时选择工作区管理类型；首版仅提供 Git，不提供未支持的类型选项。
2. 创建中心托管的 Git 工作区，沿已有租户关系与组织政策管理访问；具体托管服务与仓库初始化步骤由后续设计明确。
3. 获准的部署节点可装载相应 Git 工作副本为实例，随后按下述流程供会话选择与附着；创建工作区与装载实例是不同动作。

## 组织参与策略

组织未配置时不启用参与限制，也可选择仅允许本组织或同一组织树的工作区。首版不提供逐租户、逐工作区的例外名单；会话装配时按组织整体所选范围和当时的组织树判断参与资格，运行中不热同步或逐次操作重判，下一次实际装配再判断；不启用不等于自动授权，两种限制均不拦原有资格下的只读访问。

组织策略或组织树变化不自动触发会话重装配、结束会话或删除关系；本规则不重定义其他权限和资产配置的生效机制。

以下治理检查针对工作区使用路径。将开源项目当作普通目录使用仍不在参与限制覆盖范围内，见[已知缺口](design.md#已知覆盖缺口普通目录使用)；不能把工作区路径上的拒绝解读成普通目录也已被阻止。

## 一、选择与装载

1. 工作区实例可以在部署节点上独立存在，不要求同时存在会话。
2. 用户可以选择已有实例供会话显式附着；也可以在创建会话请求中指定目标工作区与本地装载路径，先完成装载，再创建会话并附着。后一条路径装载失败时，不把依赖该实例的会话创建报告为成功。
3. 以工作区身份装载或附着时，系统按拟创建或现有会话的租户身份核对资源访问资格；若要参与开发、维护和写入，还须检查所属组织的工作区参与限制。检查通过后才使用已有实例或展开装载。只读不受这两种组织限制阻拦，但不会因此获得原本没有的资源访问权。附着后记录本会话代表的租户关系。
4. 未选择工作区时，核心不因当前目录自动附着；工作区层为空。交付面给出的默认值必须经过显式确认或提交。
5. 该租户的关系条目已删除且未重新显式登记时，后续会话使用原本地路径按普通目录处理，工作区装配层为空；不因 `.omne`、`.omne.local` 或兼容目录存在而恢复关系或加载其中的工作区资产。
6. 必须访问中心资源的授权失败、地址不可达或装载失败都要显式报告，不能静默换成另一工作区，也不能把普通本地目录使用报告为中心工作区附着成功。

两条路径及托管来源的对应见[创建与接入矩阵](design.md#工作区创建与接入矩阵)。

### 从已有本地目录首次登记

1. 用户已在本地拥有目录，例如自行 clone 的 Git 仓库，但当前租户尚无对应工作区关系。
2. 用户显式选择“作为工作区使用”后，在首次会话使用中发起登记与附着；仅进入目录或普通启动会话不登记、不加载工作区来源。
3. 沿工作区身份、关系和授权规则接入已有内容，将本地目录关联为实例，并向治理中心同步关系登记。只同步关系及必要关联标识，不上传工作区文件；无须重新 clone，不将外部仓库迁移到 Omne Host，不重复创建已存在的 Omne Host 工作区。
4. 登记并附着成功后，治理中心可以列出该关系，会话才从本地实例发现并装配工作区来源。失败时如实报告，不伪报附着成功，不提前加载这些来源。

### 附着后的发现与装配

以下发现与装配只适用于会话以有效租户关系附着工作区；普通本地目录不执行此流程。

1. 在实例根部 `.omne` 与该实例的 `.omne.local`，按相同约定目录和包格式发现原生资产，不逐项登记；嵌套目录不自动搜索，仅通过两根各自的 `workspace.json` 登记相对路径扩展发现范围，支持通配符。所有发现路径均排除软链接且不跟随，登记也不例外。目录缺失视为空来源；配置文件缺失仍正常发现默认范围；文件存在但解析或格式错误时明确报告并阻止装配，不能跳过错误的 local。AGENTS.md 的首次目录访问加载归 runtime context，不混入这项资产发现流程。
2. 保留每项的来源与归属。读取目录不启动其中的命令；共用实例的租户可以从同一本地来源取得候选，再各自求值，不能因此载入其他租户的租户级私有资源或凭据。
   同项设置取 local 显式值，local 未配置则取共享值；布尔项不取 OR。Codex、Claude Code 的兼容开关默认关闭，先合并两根显式配置，再发现已开启来源中的 Skill、MCP、hook；不要求复制或逐项登记第三方资产。
3. 按 PF-002 过滤禁用、无使用资格的资产以及工作区不能提供的配值。两个目录的可用内容取并集，同能力资产 local 优先；local 被过滤时，共享候选仍可参与。
   对仍使用的共享资产，允许仅由 local 配置提供设置覆盖；如果选用了同名 local 资产，则完整使用 local 实现，不叠加针对共享实现的覆盖。Omne 原生可用资产优先于兼容来源；两个第三方来源的同能力不同内容冲突应显示并由用户选择，不能静默选一家或重复触发同一 hook。
4. 按会话租户所在组织、租户自身与工作区候选求值，再按所选 Agent Definition 组装、投影属性、计算有效值。工作区所有者的组织与私有配置不因所有权自动成为参与者的输入。
5. 按 PF-004 形成装配清单并进入所需初始化；必需资源缺失时明确失败，不报告残缺装配成功。本地命令型 MCP 与命令型 hook 的默认禁用、逐件启用规则继续成立。

运行中文件和配置变化不自动刷新装配，资源同步也不隐式重载。下一次实际装配时重新发现并求值；会话装配设计提供显式资产热重载命令，执行命令后才发起运行中的重新加载。重载先校验待加载数据；校验成功后才替换 agent runtime 内存中的相应数据，校验失败明确报错而原数据不变。具体运行中切换与外部组件生命周期按 PF-004 及后续规格接续。

### 复用实例、worktree 与已有路径

- 多个租户的会话可以附着同一实例，各自按装配时的租户身份求值，不给实例固定一个租户身份。
- 创建 Git worktree 不自动登记实例。显式选择其目录作为工作区使用后，再关联实例与原工作区；一个会话可以将多个 worktree 分配给不同 subagent 并行工作。
- 接入已有目录保留原内容，不重新 clone；从中心实例化时目标路径冲突按 Git 原生结果报告，由用户或 agent 决定下一步，不自动覆盖、删除或合并已有目录。

## 二、跨会话与跨节点继续

- 下一次会话可以选择同一个逻辑工作区，并复用已有实例或在另一节点建立新实例。
- 被授权参与的其他租户也可以选择同一个逻辑工作区；这不会创建一个新的工作区身份。
- agent 类型可以变化；只要实例与资源可用，工作区身份和资源聚合继续保持。
- 会话结束不自动卸载或删除实例；后续会话可以再附着可用实例。实例卸载不删除工作区，不再使用本地实例时不再附着即可，不要求另设治理中心清理流程。

## 三、地址变化与多实例

- 地址可以被替换、增加或暂时不可达；地址变化本身不创建新工作区。
- 同一租户可在多个部署节点上装载同一工作区；agent 可用分支与 Git worktree 组织工作，自主发现和处理 Git 冲突，底层完整性与失败保证沿后续规格展开。
- 不同地址提供者可以指向同一工作区；读写目标沿 Git remote、分支及显式操作表达。写入一个目标不自动传播到其他地址，不另设统一 Workspace 权威地址或跨地址同步规则。
- 不同租户即使提供相同字符串地址，也不能仅凭地址获得授权；获得授权后可以访问同一工作区共享资源，实例本地来源可相同，但按各会话租户分别求值，不据此共享租户级私有资源。

### 共享与本地变更

- `.omne` 中的每次变更属于应同步到中心、向获准租户共享的内容；允许异步，由 agent 根据用户指示或工作需要运用 Git 同步，不要求变更后立即 push 或立即更新其他实例。
- `.omne.local` 中的变更改变实例本地来源，共用该实例的会话在装配或显式重载时分别求值；不得把两目录合并后的有效结果整体作为共享内容上传。
- 以工作区身份修改共享目录遵循装配时判定的组织参与范围及既有工作区授权；不在每次写入时热同步重判这项组织限制。只读资格不因自动加载而升级为维护资格。

### Git 资源的按需感知与同步

1. 用户可以在本地实例或 remote 上传、修改文件；变更先作用在相应位置，不要求会话即时感知。
2. 用户告知有新内容，或 agent 工作中自行发现需要检查时，agent 读取本地状态或获取 remote 变化，判断下一步。
3. agent 通过已有通用工具直接运用 Git，无须专门的 Omne Git 命令体系；在授权范围内自行决定同步、提交与推送，必要时使用分支、worktree 和冲突处理能力协调工作；不把 Git 冲突固定转交给用户。确需业务取舍、信息或额外授权时再协作。
4. 工具如实返回变更、差异、冲突及同步成功或失败；未同步的本地内容不能显示为已到 remote。完成同步不自动重装会话中的资产或改写既有上下文。

### 工作区超管权限的授予与撤回

仅创建者可以授予或撤回某租户的工作区超管权限，超管不能转授。撤回权限保留参与关系与其他已有授权；删除参与关系则一并解除依附该关系的授权。

### 治理关系解除与中心销毁

解除关系时，普通参与租户和工作区超管可以退出自身参与关系；创建者或工作区超管可以移除参与租户。普通参与租户不能删除他人关系；工作区仍存在时不得单独删除唯一治理所有者关系，本版不提供所有权移交。满足条件后删除指定的租户—工作区关系条目；工作区超管退出时一并失去该工作区的授权。该租户后续使用原本地目录时不再获得工作区装配身份；`.omne`、`.omne.local` 及经其开关发现的第三方资产不进入会话装配。文件仍保留，其他租户的关系不随这条记录的删除而删除。

中心销毁按以下结果推进：

1. 核对发起租户是工作区创建者，或持有创建者明确授予的工作区超管权限；不满足则拒绝，不改动资源或关系。资源授权继续适用，组织参与限制沿装配阶段的判定规则，不增加销毁时的组织策略热同步。
2. 销毁中心托管工作区。确认销毁后，删除指向它的所有租户关系，包括治理所有者及参与租户；不能将提交请求、暂时不可达或失败不明当作已确认销毁。
3. 各部署节点的本地文件保持原样；后续会话使用这些目录时不加载工作区来源。不得在中心已销毁后继续把关联关系展示为有效。

关系解除和销毁权限按[产品规则](design.md#治理关系解除与中心销毁)执行。关系删除不推定已运行会话会立即重装配；销毁与关系清理的具体失败恢复协议由后续规格表达。

## 四、异常与禁止的隐式行为

| 触发 | 产品行为 |
|---|---|
| 地址存在但租户无权访问 | 拒绝访问并说明原因，不建立实例 |
| 本次操作必须访问的地址不可达 | 如实报告该装载或同步操作失败，不新建空工作区冒充成功；不能把 remote 暂不可达等同于本地实例已消失 |
| 该租户的关系已删除，后续会话使用原本地目录 | 作为普通目录使用，工作区装配层为空；不从目录残留内容恢复关系或中心授权 |
| 租户没有有效关系，却请求通过该关系访问中心工作区资源 | 拒绝，不因本地文件或公开地址存在而建立授权 |
| 当前操作需要的本地资源已不存在 | 如实报告该操作无法完成；不推定中心工作区或租户关系随之消失 |
| 当前目录恰好对应某地址但会话未选择 | 不自动附着工作区 |
| 工作区资源带来权限放宽配置 | 按 PF-002 过滤，不改变租户或组织边界 |
| 工作区授权维护，但所属组织禁止在该组织范围参与 | 不允许开发、维护和写入；保留原有只读访问资格 |
| `.omne.local` 与 `.omne` 提供同能力资产 | 可用候选中 local 优先，各会话按其租户分别求值；不改写共享原件 |
| 共享配置启用某兼容来源，local 显式关闭 | 有效开关为关闭，不发现该来源资产；变更在下一次实际装配或显式重载时读取 |
| 工作区上传或同步包含本地定制 | 不得将 `.omne.local` 作为共享内容传播；具体失败与重试流程待同步设计 |
| 用户在 remote 上传内容，而会话正在进行另一项工作 | 不要求即时拉取、打断或刷新；由用户告知或 agent 按需检查后处理 |
| Git 同步遇到内容冲突 | 保留可供判断的状态与失败结果，由 agent 按授权自行处理，必要时再向用户询问 |

## 六、资源操作与成果

人或 agent 选择实际操作的本地实例或远端目标，沿 Git 能力读取、写入或同步资源；交付面如实显示操作结果。超出托管或部署容量限制时报告失败，本地原件保留，不静默截断或遗漏内容。资源成果不需要经过额外的工作区发布流程；已写入目标不代表其他地址或实例已同步。
