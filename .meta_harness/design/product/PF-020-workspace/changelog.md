# PF-020 变更历史

## rev 3 — 2026-09-27 — 组织参与限制与共享／本地目录

依据 [本轮交流](interviews/2026-09-27-assets-settings-and-attachment.md) 明确：组织可禁止本组织租户参与本组织外，或同一组织隶属树外的工作区开发、维护与写入；两种限制都不拦只读，且不替代资源自身授权。

工作区实例下约定 `.omne` 和 `.omne.local` 两个结构完全相同的目录，用于自动发现资产、配置与规范；可用内容取并集，同能力资产 local 优先。前者变更属于云端及其他获准租户的共享同步内容，后者属于单租户本地定制，不进入共享同步。

同步修正 PF-001 的工作区授权表述与 PF-002 的单租户假设，目录来源内部的优先级接续既有资产过滤、替换和锁定规则。词条与对象依据复核；不改变冻结契约的采用状态。上传、下载、同步冲突及在途更新细节继续开放，下一轮讨论 Omne Host。

## rev 2 — 2026-09-24 — 补充租户关系与地址提供者分类

本轮把“租户能在治理中心感知哪些工作区”落为持久的租户—工作区关系，区分治理所有者与参与租户，
并允许被授权租户对同一个工作区的共享资源进行维护。新增工作区类别与地址提供者类型的分轴：
Omne Host、GitHub、Obsidian、Office 365 等是地址提供者示例，不直接决定工作区身份；工作区可以
拥有多个不同提供者的地址。治理中心展示有效关系的投影，公开地址本身不自动生成写权限。

## rev 1 — 2026-09-24 — 初步开题

根据本会话产品讨论建立 PF-020。首次明确区分：

- 工作区：租户拥有、带身份、跨会话持续的完整资源聚合包；
- 工作区实例：在某个部署节点上装载后供 agent 使用的具体工作入口；
- 工作区地址：本地路径、GitHub、云端等可变化的访问地址，不是身份。

同时把“无固定目标”“可携带自定义资产”“多部署节点”作为当前产品方向落盘，
将存储权威、同步、并发和生命周期列为后续未决。PF-002 升为 rev 21，继续负责工作区资产层的
设置、替换和权限过滤。
