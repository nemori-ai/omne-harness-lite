# PF-013 流程与状态

> **这一页说这块怎么动。**[design.md](design.md) 说它是什么。
>
> 两条纪律：**每条旅程都要走到收场**；**没画出来的转移，研发会自己发明一个**。

---

## 一、主要旅程

### 1.1 用户在会话里换一个模型

```text
 用户在[展示列表](design.md#510-合法目标集合与展示列表是两件事)里挑了一个
        │
        ├─ 它不在[合法目标集合](design.md#510-合法目标集合与展示列表是两件事)里 ──→ **根本选不了**（不是「被拒绝」，是压根没得选）
        │     └─ 已下架 · 这个范围不允许（锁死或配成不允许） ·
        │        **[收不下会话里已有的模态](design.md#511-有-transcript-的块不再把任何模型挡在外面)**
        │
        ▼ 它是合法目标
 ① 切换发生。不拒绝，没有第二种结果
        │
        ▼
 ② 落成一条要被记录的事实 ──→ [会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)
        │
        │   ⟨正在进行的那一次模型调用：照常跑完，不打断⟩
        ▼
 ③ 下一次模型请求之前：【想】那一圈照常走
        │   组装 → 量 → 超了就压缩 → 再组装 → 再量
        │   **唯一的差别：这次读到的是新档案**
        ▼
 ④ 调模型，用新的那条
```

| 步骤 | 触发者 | 发生什么 | 完成的标志 |
|---|---|---|---|
| **1** | **用户** | 在列表里选了一个合法目标 | —— |
| **2** | 系统 | 把「换成了它」写成一条记录条目 | **条目落盘**。此后任何人问「这一轮为什么换了口气」，都答得出来 |
| **3** | [agent loop](../PF-012-agent-loop-and-run/design.md#agent-loop) | **走的是[已有的组装与压缩判断](../PF-012-agent-loop-and-run/design.md#55-想这一步交进闭包拿回装得下的一份)**，没有新分支 | 量下来在预算内 |
| **4** | agent loop | 这一次请求用新档案 | 一条回复，**并记下实际生成它的那条档案**（[PF-004 §6.6](../PF-004-agent-definition-and-assembly/design.md#66-模型在每次请求时确定)） |

**这条旅程的提交点在第 2 步。**条目一落盘，切换就已经发生了——
**后面走不走得通，是下一次请求的事，不回头推翻这次切换**。

> **用户会有的困惑，写在明面上**：切换之后**界面上不会立刻有任何变化**。
> [不新增分支](design.md#68-不为切换新增分支)的代价就在这里。

### 1.2 一次模型调用的完整旅程

```text
 请求攒好了
    │
    ▼
 ① 还没出门：有效模型算得出来吗？它[还是合法目标吗](design.md#69-合法目标算不出来时不替用户改选)？凭据取得到吗？
    ├─ 算不出来 / 已下架 / 不再允许 /
    │  [和会话里的模态对不上](design.md#610-模态兼容挡在算合法目标那一刻不挡在出门那一刻) /
    │  没凭据 ──────────────→【发不出去】不重试，立即上交
    ▼
 ② 出门，等首 token
    ├─ 连不上 / 超时 / 5xx / 被限流 ──→【其余全部】**[状态码原样带着](design.md#57-上交带什么原样带着状态码不翻译它)**；
    │                            要不要再试、换一家还是退避之后再来，由
    │                            [那件拓展件](design.md#512-重试站在一个已经存在的位置上)说了算
    │                              └─ 它说不再试 → [试尽](design.md#什么时候算试尽) → 上交
    ├─ 凭据被拒 / 请求不合法 / 内容被拦 ──→【重试没用】立即上交，**拓展件改不了**
    ▼
 ③ 首 token 出来了，流进行中
    ├─ 断了 / 不动了 / 中途报错 ──→【已经开口说话了】**一律不重试**，立即上交
    │
    ├─ **用户插队，中断这次回复** ──→【被中断】**不是故障，不带成因**，见 1.6
    ▼
 ④ 完整的一份回复
    ├─ 空的 ──→ 按【其余全部】处置（首 token 从没出来过）
    ├─ 撞上输出上限 ──→ **不是非常态**，收场归 [PF-009](../PF-009-context-message-types/design.md#56-流断在半路)
    └─ 正常 ──→ 主路径走完
```

**每一次失败的尝试都[留痕](design.md#试过又失败的那几次留痕不进方程)**——
不进[方程的定义域](../PF-012-agent-loop-and-run/design.md#方程从日志里读什么)，也不进模型的上下文。

### 1.3 走一遍：换到一个窗口更小的模型

| 步骤 | 在哪一层 | 发生什么 |
|---|---|---|
| 1 | —— | 用户换成一个窗口小得多的模型。**切换成功**——窗口大小不构成拒绝理由 |
| 2 | **运行** | 下一次请求前【想】那一圈：组装 → 量一量，**超了** |
| 3 | **运行** | [压缩](../PF-010-context-management-and-assembly/design.md#57-压缩能做的只有两件事) → 再组装 → 再量 |
| 4a | —— | **在预算内 → 照常调模型。到此为止，什么特别的事都没发生** |
| 4b | **运行** | 还超 → [T1c](../PF-012-agent-loop-and-run/design.md#56-状态转移表)：**上交给会话**，同时这个 Run 落终态失败 |

**第 4b 一个字都不归本 topic**——它是 [PF-012 已有的一行](../PF-012-agent-loop-and-run/design.md#压完还超这一层腾不出空间了)。

> **这条旅程是[「不新增分支」](design.md#68-不为切换新增分支)的全部证据**：
> 从第 2 步起，**没有一步是因为「刚才换过模型」才走的**。

### 1.4 走一遍：选中的模型被下架了

| 步骤 | 发生什么 |
|---|---|
| 1 | 某条档案被撤回。**行保留**（[§6.4](design.md#64-撤回不删行会话指向被撤回的档案时说已下架)） |
| 2 | 会话仍然指着它。**列表里它还在**，标着「已下架」，**但它不是合法目标** |
| 3 | 下一次请求：有效模型算不出来 → **不替用户改选**（[§6.9](design.md#69-合法目标算不出来时不替用户改选)） |
| 4 | 这次调用落在【发不出去】那一类，成因具名为**已下架**，**立即上交** |
| 5 | 接手方是**运行**——[一个字都没出来，agent 的那一步此刻不存在](design.md#55-上交交给谁看模型说没说出话) |
| 6 | 用户换一个在册的 → 回到 [1.1](#11-用户在会话里换一个模型) |

**第 3 步是这条旅程的要害。**自动顶一个上去看起来更体贴，
**但那是静默地换掉用户的选择**——[取舍里记着为什么不这么做](design.md#七取舍)。

### 1.5 走一遍：说到一半断了

| 步骤 | 发生什么 |
|---|---|
| 1 | 首 token 已经出来，用户屏幕上有半句话。**连接断了** |
| 2 | **不重试。**哪怕状态码看起来是「再试一次就好」的那种——[「已经开口说话了」优先](design.md#已经开口说话了优先于其余各类) |
| 3 | [PF-009 的收场](../PF-009-context-message-types/design.md#56-流断在半路)：已交付的那部分**记在这次尝试的账里**——用户看见过的都在日志里，**但它不成为一条消息，不给模型看** |
| 4 | [补一条中断提醒](../PF-009-context-message-types/design.md#613-只要发生了中断就补一条提醒) |
| 5 | **那条提醒就充当这一跳的上交条目，不另立一条**（[§5.5](design.md#55-上交交给谁看模型说没说出话)） |
| 6 | 接手方是 **agent 的一步**——它读到那条提醒，自己决定要不要重说 |

**第 5 步是最容易做错的一步。**另立一条上交条目，
**同一次断流就在记录里登记了两处，而两份登记必然分叉**。

### 1.6 走一遍：用户插队，中断这次回复

**形态上它和 [1.5](#15-走一遍说到一半断了) 几乎一样，性质完全不同。**

| 步骤 | 发生什么 |
|---|---|
| 1 | 用户对正在进行的这次回复发一个插队指令。**指令怎么被受理，归 PF-014，不在这里** |
| 2 | 这一次模型调用**被中断**。**不是故障**——不走[那张分类表](design.md#54-三类事实归本层定死其余照状态码) |
| 3 | 已经吐出来的那部分**照样落盘**——[规矩归 PF-009](../PF-009-context-message-types/design.md#56-流断在半路)，本 topic 只引用 |
| 4 | 交回给 agent 的一步，语义是「**这次被用户中断了**」，**不带任何故障成因** |
| 5 | loop 尽快走到下一次消费输入的那个点，**去看用户刚插进来的那句话** |

**第 2 步和第 4 步是这条旅程存在的全部理由。**
不分开，**用户每插一次队，记录里就多一条「模型调用失败」**——
而[失败是「这事没成」，中断是「这事不做了」](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)。

### 1.7 走一遍：会话里发过一张图

**这条旅程说明[模态投影](design.md#模态投影)怎么改变用户眼前的东西。**

| 步骤 | 发生什么 |
|---|---|
| 1 | 会话刚建，[模态投影](design.md#模态投影)里只有「文本」。**所有在册且这个范围允许的模型都是合法目标** |
| 2 | 用户发了一张图。**那条消息落盘之前先过[转换件](design.md#转换件)那一道**——「图」这个键上登记了转换件，就给这张图[配上派生表示与 transcript](design.md#转换件) |
| 3a | **转出来了**：那个块有了 transcript，**不进投影**。[任何模型都读得了那一份](design.md#511-有-transcript-的块不再把任何模型挡在外面)，合法目标一个都没少 |
| 3b | **没人转**（「图」这个键上没有登记转换件）：图照原样落盘，没有 transcript——**投影里多了「图」，而且再也减不回去** |
| 3c | **转失败了**（转换件挂了，或交不出 transcript）：**这条消息不落盘**，用户被告知[没发进去](design.md#转换件)。**会话、投影、合法目标都没变**，他可以换一张再发。**模型回复与工具结果转失败另走两路**：前者退避重试、试尽 Run 失败，后者 Run 失败（[转换件](design.md#转换件)） |
| 4 | 走到 3b 的情况下，用户打开模型列表：**看不了图的那些现在不可选**，并说得出为什么 |
| 5 | 这个判断[必须是常数代价的](design.md#618-模态投影要答得快而且是增量维护出来的)——**不许为此去扫一遍会话历史** |

**如果用户选的就是一个纯文本模型，而那张图又没人转呢？**

| 步骤 | 发生什么 |
|---|---|
| 2′ | 那张图照样[落进记录](../PF-009-context-message-types/design.md#612-日志完整删减只发生在组装那一步)——**记的是发生了什么，不是模型该看什么** |
| 3′ | **选中模型就此不再是合法目标**（它收不下「图」，而这个块没有 transcript） |
| 4′ | 下一次请求：[不替用户改选](design.md#69-合法目标算不出来时不替用户改选)，**发不出去并上交**，成因具名为**和会话里的模态对不上** |
| 5′ | 用户换一个读得了图的（它现在才是合法目标），或者开一个新会话 |

> **第 4′ 步的成因必须具名。**并进「这个范围不再允许」，用户会去找管理员——
> **而管理员帮不上忙**。

## 二、分支与异常

| 在哪一步 | 什么情况 | 用户看到 | 系统停在 | 能否重试 |
|---|---|---|---|---|
| **选模型** | 目标不在合法目标集合里 | **它根本不可选**；已下架的那条标着「已下架」 | 选中模型不变 | —— |
| **选模型** | 目标[收不下会话里已有的模态](design.md#511-有-transcript-的块不再把任何模型挡在外面) | **它不可选，并说得出「它读不了这个会话里的图」** | 选中模型不变 | —— |
| **选模型** | 范围没配凭据 | **它可选，但标明「现在用不了 + 缺什么」**（[§5.10](design.md#510-合法目标集合与展示列表是两件事)） | 选中模型不变 | —— |
| **切换** | 用户选了合法目标 | **切换成功** | 新的选中模型已落盘 | —— |
| **还没出门** | 有效模型算不出来（已下架 / 不再允许） | 这一轮没有回复，**说得出是哪一条、为什么** | **上交给运行** | **不能**——这一层变不出一个模型，**拓展件也变不出** |
| **还没出门** | 范围没配凭据、或凭据被上游拒 | 同上，成因是**凭据不可用** | **上交给运行** | **不能**——凭据在范围那一层手上 |
| **还没出门** | 选中的模型[和会话里已有的模态对不上](design.md#610-模态兼容挡在算合法目标那一刻不挡在出门那一刻) | 这一轮没有回复，**说得出是它读不了会话里的图** | **上交给运行** | **不能**——用户换一个能读的，或开新会话 |
| **首 token 之前** | 连不上 / 超时 / 上游 5xx | 慢一点，**看不出别的** | 本层了结中 | **看[那件拓展件](design.md#512-重试站在一个已经存在的位置上)怎么说** |
| **首 token 之前** | 被限流 | 慢一点 | 本层了结中 | 同上，退避之后再来 |
| **首 token 之前** | 上面两种[试尽](design.md#什么时候算试尽)了 | 这一轮没有回复 | **上交给运行** | **不能**——策略已经说不再试了 |
| **首 token 之前** | 请求被判不合法 / 内容被上游策略拦下 | 这一轮没有回复，**说得出是被上游拒了** | **上交给运行** | **不能**——重试一百次也一样 |
| **首 token 之后** | 断了 / 不动了 / 中途报错 | **屏幕上那半句话还在**，外加一条「刚才断了」 | **上交给 agent 的一步** | **不能**——重试会造出第二份回复 |
| **拿到完整一份** | 回复是空的 | 慢一点 | 本层了结中 | **能**——首 token 从没出来过 |
| **拿到完整一份** | 撞上输出上限 | 一条完整的消息 + 一条提醒 | **主路径走完，不是非常态** | —— |
| **任何一步** | 这一层**认不出**这是什么 | 这一轮没有回复 | **上交，成因是「没认出来」** | **不能** |

**「报错」不是任何一格的答案。**每一格都要么说得出成因，要么说得出下一步。

> **这张表里没有「用户中断」，而那不是漏了。**
> 这一整节说的是**故障**；[被中断是一个控制动作，不是异常分支](design.md#还有一种没走完它不在这张表里)，
> 它的旅程在 [1.6](#16-走一遍用户插队中断这次回复)。

## 三、状态流转

### 3.1 一条模型档案

```text
   ┌────────┐   撤回    ┌────────┐
   │  在册   ├────────→ │ 已撤回  │  ← 终态
   └────────┘          └────────┘
       ↑
    建档（组织超管 / 租户，在自己那一层）
```

| 从 | 到 | 触发 | 前置条件 | 不可逆？ |
|---|---|---|---|---|
| ——  | 在册 | 建档 | 建档者持有该范围的配置资格 | —— |
| 在册 | 已撤回 | 撤回 | —— | **是** |

**终态：已撤回。**

**「已撤回」是终态，而行永远保留**——
删了行，会话指着它时就只说得出「未知模型」（[§6.4](design.md#64-撤回不删行会话指向被撤回的档案时说已下架)）。

> **「这个范围不再允许它」不是这张图上的转移。**那是[作用域求值](../../ubiquitous_language/terms/scope-and-resolution.md#ul-scope-evaluation--作用域求值--scope-evaluation)的结果变了，
> **档案自己一个字没动**——[两者用户要做的事不同](design.md#在册--已撤回)。

### 3.2 一次模型调用

```text
  ┌──────────┐
  │  待发出   │
  └────┬─────┘
       │ 过了出门前那两道（选中的还是合法目标吗 · 凭据取得到吗）
       │                          └─ 过不了 ──→【上交】
       ▼
  ┌──────────┐   换一家 / 退避（本层了结）
  │  在途     │ ←──────────────┐
  └────┬─────┘                │
       ├─ 出事，[拓展件](design.md#512-重试站在一个已经存在的位置上)说再试 ─┘
       ├─ 出事，[试尽](design.md#什么时候算试尽)了 ──→【上交】
       │
       │ 首 token 出来了
       ▼
  ┌──────────┐
  │ 说话中    │ ── 出事 ──→【上交】**不回「在途」**
  └────┬─────┘
       │ 收齐
       ▼
  ┌──────────┐
  │ 完整一份  │  ← 终态
  └──────────┘

  任何一个非终态 ── 用户插队 ──→【被中断】← 终态，**不是故障**
```

| 从 | 到 | 触发 | 前置条件 | 不可逆？ |
|---|---|---|---|---|
| 待发出 | 在途 | 出门前两道都过了 | **选中的仍是[合法目标](design.md#510-合法目标集合与展示列表是两件事)** · 取得到凭据 | 否 |
| 待发出 | **上交** | 两道里任何一道没过 | —— | **是** |
| 在途 | 在途 | **换一家 / 退避**（本层了结） | 落在[「其余全部」那一类](design.md#54-三类事实归本层定死其余照状态码)，**且[那件拓展件](design.md#512-重试站在一个已经存在的位置上)说再试** | 否 |
| 在途 | **上交** | [试尽](design.md#什么时候算试尽)了，**或**落在「发不出去 / 重试没用」——**那两类拓展件改不了** | —— | **是** |
| 在途 | 说话中 | **首 token 到了** | —— | **是**——见下 |
| 说话中 | **上交** | 任何**故障** | —— | **是** |
| 说话中 | 完整一份 | 流正常收尾（**含撞上输出上限**） | —— | **是** |
| **待发出 / 在途 / 说话中** | **被中断** | **用户插队** | —— | **是**。**它不经过「上交」，也不带成因**（[§5.4](design.md#还有一种没走完它不在这张表里)） |
| 在途 | 完整一份 | —— | **不会发生**：完整一份必定先经过「说话中」 | —— |

**三个终态：完整一份、上交、被中断。没有第四个。**

**「被中断」单独是一个终态，不并进「上交」**——
并进去，**用户的一次正常操作就会被登记成一次失败**。

**「说话中 → 在途」这条转移不存在，而它正是本 topic 最硬的一条规则。**
一旦开口，**这次调用只有两个下场：说完，或者上交**。

> **上交之后接手方是谁，看[说没说出话](design.md#55-上交交给谁看模型说没说出话)**：
> 一个字都没出来 → **运行**（越过 agent 的一步）；已经有内容 → **agent 的一步**。

### 3.3 一个会话的选中模型

```text
  ┌──────────────┐   一条「换成了 X」的事实落盘   ┌──────────────┐
  │ 选中模型 = A  ├──────────────────────────→ │ 选中模型 = X  │
  └──────────────┘                            └──────────────┘
         │                                            │
         └───── 正在进行的那次调用：照常跑完，仍然用 A ──┘
                下一次请求：用 X
```

| 从 | 到 | 触发 | 前置条件 | 不可逆？ |
|---|---|---|---|---|
| 选中 A | 选中 X | 一条切换事实落盘 | **X 是合法目标** | 否——可以再换回来 |
| 选中 A | 选中 A | 用户选了个非合法目标 | —— | **这条转移不存在**：他根本选不到 |

**没有「自动从 A 变成别的」这条转移。**
选中的那条不可用了，[系统不替用户改选](design.md#69-合法目标算不出来时不替用户改选)——
**它停在 A，并且每次请求都诚实地失败**。

> **选中模型变了，不等于[有效模型](design.md#选中模型-与-有效模型)变了**：
> 组织那一层[锁死](../../ubiquitous_language/terms/scope-and-resolution.md#ul-immutable-marker--不可覆盖标记--immutable-marker)过，
> 求值出来的可能还是别的。

### 3.4 一个会话的模态投影

```text
  { 文本 }  ──发了一张没人转的图──→  { 文本, 图 }  ──同样的语音──→  { 文本, 图, 语音 }
       ↑
       ├─ 图配上了 transcript ──→ { 文本 }，一个模态都没多
       └─ 图转失败了 ──→ 那条消息没落盘，{ 文本 } 不变

      合法目标集合 ──────────────── 只会越收越紧 ────────────────→
```

| 从 | 到 | 触发 | 前置条件 | 不可逆？ |
|---|---|---|---|---|
| 少一种 | 多一种 | 一个该模态的[块](../PF-009-context-message-types/design.md#消息的内容是一串块不是一段文本)进了会话历史 | **它没有 transcript**——那个键上没有登记[转换件](design.md#转换件)。配上了就不进投影；转失败了那条消息根本不落盘 | **是** |
| 多一种 | 少一种 | —— | **这条转移不存在** | —— |

**没有终态，但它单调。**[记录一条都不能擦除](../PF-010-context-management-and-assembly/design.md#612-记录里的消息一条都不能擦除)，
**压缩也只翻标注、不搬走东西**——所以进去的模态再也出不来。
**而[一个块有没有 transcript 是落盘那一刻就定死的事实](design.md#转换件)**，之后不再变，所以投影仍然是单调的。

> **直接后果，要对用户说清楚**：**一个长会话里只要出过一个没有 transcript 的块，它的可选模型就永久变少**。
> 想回到全集，**只能开一个新会话**。
> **装齐了转换件，这条基本不会被触发；一件都没装，它就退回最严的形态**——
> 出过一个图块，纯文本模型就永久出局。

**文件块看它的媒体类型**：一段视频、一张图，就按那种模态进这张图；**媒体类型不属于四种模态的，不参与**——它装的只是[一个附件的引用](design.md#模态)。

## 四、角色与操作

| 操作 \ 角色 | **组织超级管理员** | **租户** | **会话里的用户** | **agent** |
|---|---|---|---|---|
| **建一条自建档案** | 可（建在组织层） | 可（建在自己那层） | 不可 | **不可** |
| **撤回一条自建档案** | 可（自己那层建的） | 可（自己那层建的） | 不可 | 不可 |
| **撤回官方档案** | **不可** | **不可** | 不可 | 不可 |
| **配这个范围的凭据** | 可（组织那把） | 可（自己那把） | 不可 | 不可 |
| **看见凭据的值** | **有条件**：只有配的那一方；**任何对外可见的面上都不出现它**（[§6.16](design.md#616-错误信息外泄之前要脱敏)） | 同左 | **不可** | **不可** |
| **锁死某条档案，不许下层换** | 可（[不可覆盖标记](../../ubiquitous_language/terms/scope-and-resolution.md#ul-immutable-marker--不可覆盖标记--immutable-marker)） | 可（对更下层） | 不可 | 不可 |
| **中断正在进行的这次回复** | —— | —— | **可。**它是控制动作，**不产生故障成因**；[怎么受理归 PF-014](design.md#八边界与依赖) | **不可** |
| **切换会话的模型** | —— | —— | **可，且合法目标不得拒绝** | **有条件**：只在它代表用户执行一条明确的切换指令时；**它不能为了绕开一次失败而自己换模型**（[换模型不是这一层的手段](design.md#什么时候算试尽)） |
| **改一次请求实际用哪条档案** | **有条件**：挂一件在[「调模型之前」](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)的拓展件，**且它必须[留下结论](../PF-012-agent-loop-and-run/design.md#610-能干预的拓展件必须留下结论)** | 同左 | 不可 | 不可 |
| **决定一次失败之后还试不试** | **有条件**：挂一件在[「调模型之后 · 失败」](design.md#512-重试站在一个已经存在的位置上)的拓展件，**干预力至少要「可改写」**；**改不了[那三类事实](design.md#612-事实判断归本-topic策略归拓展件)** | 同左 | 不可 | **不可**——它连自己换个模型都做不到 |
| **看见一次调用试过哪几家** | 可（留痕） | 可（自己范围内的） | —— | **不可**——[它拿这个做不出任何判断](design.md#试过又失败的那几次留痕不进方程) |

**「有条件」都写出了条件。**留空或写「视情况」等于把判断推给实现者。
