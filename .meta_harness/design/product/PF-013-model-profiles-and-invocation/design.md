## 一、背景与问题

**「我们能调哪些模型」这件事，今天没有一个对象承载。**

[PF-004 定了模型在每次请求时才确定](../PF-004-agent-definition-and-assembly/design.md#66-模型在每次请求时确定)，
[PF-002 定了「用哪个模型」是一项设置](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性)，
[PF-001 判定模型档案是数据不是资产](../PF-001-identity-scope-and-agent-constraints/design.md#资产的种类)。
**三处都在用它，而它是什么、记哪些事实，没有一处说过。**

于是四个问题悬着：

- **这项设置的取值到底是什么？**如果是一个名字，那么「这个模型看不看得了图」「它一次能吃多少」
  **就没有地方可问**——每个要用到这些事实的地方都得自己去猜，或者各自硬编一份。
- **组织想接一个我们没提供的模型，怎么接？**它的凭据放哪、放几把、轮换时改几处。
- **一次模型调用失败了，这一层能做什么、什么时候该放弃？**
  [PF-011 把这一层整格排了出来，一段一段点明各归谁](../PF-011-off-nominal-handling/design.md#模型调用那一层整格是这么分的)——
  **而「发出去 · 失败了能做什么 · 什么时候算试尽」那一段是[六层里唯一空着的一格](../PF-011-off-nominal-handling/design.md#54-各层的四要素)**。不填，结果是可以预见的：每个撞上失败的地方各自发明一套重试。
- **用户在会话中途换一个模型，会发生什么？**立刻打断正在进行的那一次？
  历史装不下新模型的窗口怎么办？**会话里已经有过一张图，而新模型读不了图呢？**
  在此之前每次讨论都要重新发明一遍答案——**而最后那一问，同类产品普遍答错了**（[§5.11](#511-有-transcript-的块不再把任何模型挡在外面)）。

**本 topic 把这四件事一起回答。**它们共享同一批事实——
**能调哪些、发得出去吗、发不出去怎么办、用户换成了哪个**，拆开会让一条规则跨三个包。

**超长期运行还要求一次调用有清楚的交接终点。**消费方处理完结果后，模型侧若继续保存每次调用的创建输入与结果副本，占用就会随调用次数累积；仅因调用已结束就删除，又会丢掉尚未处理的结果。消费方必须能明确确认自己已经接好这份结果，由此触发模型侧不再需要的副本清理。

## 二、目标与非目标

### 目标

1. **定义模型档案**：它记哪些事实、谁能建、凭据挂在哪。
2. **填上 [PF-011 那一格](../PF-011-off-nominal-handling/design.md#54-各层的四要素)**——
   一次模型调用这一层**本层了结得了什么**、**什么时候算试尽**、**上交时带什么成因**。
3. **定义选中模型与有效模型**，以及两者为什么必须是两个词。
4. **定义换模型这件事怎么发生**：它先是一条要被记录的事实，生效点在哪，以及
   **为什么它不给 agent loop 添一个分支**。
5. **定义合法目标集合怎么算**，包括**会话的[模态投影](#模态投影)**这一项输入——
   **把「切到看不了图的模型之后会话像是卡死」那类事故从源头堵死**。
6. **把「再试一次值不值」这个策略从产品正文里拿出去**，交给
   **[一件挂在 PF-012 已有位置上的可替换拓展件](#512-重试站在一个已经存在的位置上)**，
   同时**把那几类不是策略、而是事实的情形留在这里**。
7. **让消费方确认该次调用结果已经处理或由自己保管后，模型侧清理不再需要的副本**，同时保持真实收场、费用及后续记账责任。

### 非目标

| 不做什么 | 为什么 |
|---|---|
| **通用回收、资产删除、会话删除或正式 Session／Run 的完整交付** | 结果确认只处理本次模型调用的创建输入与结果副本、模型侧引用及后续消费资格；消费方可以自行处理或保管结果，不以其他产品完整实现为前置 |
| **模型怎么被选、谁能配、多层怎么覆盖、能不能锁死** | 归 [PF-001](../PF-001-identity-scope-and-agent-constraints/README.md) 与 [PF-002](../PF-002-assets-settings-and-permissions/README.md)。本 topic **用**它们的层级求值，不另造一套配置机制 |
| **模型在哪一刻被解析、换模型要不要重建实例、实际用了哪个要留痕** | 归 [PF-004 §6.6](../PF-004-agent-definition-and-assembly/design.md#66-模型在每次请求时确定)。本 topic 一个字不改 |
| **请求体的内容怎么攒出来、装不下时怎么压** | 归 [PF-010](../PF-010-context-management-and-assembly/README.md)。**换模型之后的生效走的就是这条既有流程** |
| **流式怎么回来、怎么拼成完整一份、断在半路记录里留什么** | 归 [PF-009](../PF-009-context-message-types/design.md#56-流断在半路)。本 topic 只定**断了之后这一层还做不做**得了什么 |
| **分层处置模型本身**：阶梯、上交的形状、终局、「本层了结得了吗」的总判据 | 归 [PF-011](../PF-011-off-nominal-handling/README.md)。**本 topic 是它的一个填格人，不是第二份权威** |
| **模型请求从哪条路出去** | [SYS-LLM](../../../../docs/requirements.md#模型接入sys-llm)不限定统一请求通道；具体通道由模型接入契约及提供者维护，本 topic 不将当前通道扩张为系统要求 |
| **重试几次、按什么次序换、退避多久、超时几秒** | **策略，不是产品设计**（[PF-011 已定](../PF-011-off-nominal-handling/design.md#八边界与依赖)）。试几次、换哪家、退避多久归[一件挂在已有位置上的可替换拓展件](#512-重试站在一个已经存在的位置上)；超时算多久是[运行时的设置项](#617-本-topic-不出现任何时限数值)；**本 topic 定重试挂件看得到什么、能做什么，不定它怎么决定，也不出现任何时限数值** |
| **会话怎么建、怎么收束、日志的家** | 归 [PF-015](../PF-015-session-lifecycle-and-ownership/README.md)。本 topic 只定会话上的两项事实：**选中模型**与**[模态投影](#模态投影)** |
| **模型产出的工具调用参数解析不了怎么办** | 那是**拿到回复之后**的事，归 [PF-009](../PF-009-context-message-types/design.md#610-没收齐的工具调用参数不解析不执行) 与 [PF-006](../PF-006-tools-and-skills/README.md)。本 topic 到「拿回完整的一份」为止 |
| **九点能力评分**（coding / web_search / browser_use ……） | **产品负责人裁决不留**，理由见 [§7](#七取舍) |
| **按能力自动挑模型、自动降级到另一个模型** | **本版明确不做**，理由见 [§7](#七取舍)。换模型是用户的命令 |
| **让上游在一次请求里自己换供应商** | **不用。**每一次发出去只走一家，换一家就是再发一次，由[重试挂件](#512-重试站在一个已经存在的位置上)决定、每一次都留痕——**上游在一次请求里悄悄换过，「试过哪几家」就无从得知**（[§5.12](#512-重试站在一个已经存在的位置上)） |
| **转换件升为资产** | **本版不做，将来考虑。**转换件[可以按键替换](#转换件)，像资产那样；但它**不走资产的持有、分享与求值**。升不升是产品负责人留到以后的一个决定 |
| **组织持有一把凭据、供成员共用** | **本版不做，另立 topic。**[组织那一层不持有模型凭据](#56-凭据挂在范围上不挂在档案上)，每个人在自己的租户层带自己那一把。组织持有的那一把要发到每个成员的机器上，**人离职时收不回**；需要续期的凭据还得在许多台机器上各自续期。要不要有「组织统一供给凭据」这件事，等它自己的 topic 再议 |

## 三、用户与场景

| 使用者 | 什么时候接触这块 | 他关心什么 |
|---|---|---|
| **会话里的用户** | 觉得当前模型不合适，想换一个 | **我说换就换**；换完之前说过的话还在不在 |
| **组织超级管理员** | 想让成员用上一个我们没提供的模型 | 档案建在组织层，成员就都看得见；**凭据不由组织配**——成员各用自己那一把；能不能只许成员用某几个 |
| **租户** | 自己想多用一个模型；调模型用的是自己那一把凭据 | 我建的那条跟官方那些是不是在同一份列表里、同名的分不分得出；我那把凭据换了，哪些跟着换 |
| **agent 自己** | 每一步 | **这次调用是怎么了**——再来一次有用吗，还是根本白费 |
| **写重试策略的人** | 想换掉默认的重试行为 | 我挂在哪、看得到什么、我说了能不能算数 |
| **写转换件的人** | 想让某种模态或某类文件被读懂 | 我登记在哪个键上、交出什么、**转失败了会怎样** |
| **排查问题的人** | 事后 | 当时答话的到底是哪一条档案？试过哪几家供应商？为什么都不行 |
| **对成本负责的人** | 看账单 | 这个租户的量记在哪把凭据上 |

**第四行是直接消费者。**它分不清「换一家就好」和「重试一百次也一样」，
**下一步必然是错的**——该绕路时死磕，该等一下时直接放弃。

### 模型档案

**关于一个可被调用的模型的全部事实**：上游认哪个名字、能走哪几家供应商、
收得下和给得出哪几种[模态](#模态)、一次能吃多少和吐多少、送进去之前还有什么限制。

**它是数据，不是[资产](../PF-001-identity-scope-and-agent-constraints/design.md#资产的种类)**——
[PF-001 那一格的判定不动](../PF-001-identity-scope-and-agent-constraints/design.md#资产的种类)：
「用哪个模型」是某个 Agent Definition 的一项**设置**，档案不是组装出 agent 的零件。

**但它是一个对象，不是一个名字。**这是本 topic 最基础的一步：

> **那项设置的取值，是对一条档案的引用；档案自己是一个独立存在、可以被读出来的东西。**

做成裸字符串，「这个模型看不看得了图」就没有地方可问——
**每一处要用到这个事实的代码只能自己猜**，而它们会猜出不同的答案。

| 属性 | 业务含义 | 取值与约束 | 何时确定 |
|---|---|---|---|
| **路由名** | 上游认的那个名字 | **同一范围内唯一**——[档案的身份是所在范围加路由名](#档案的身份所在范围加路由名)；**一旦定下不可改**——改了就是另一条档案 | 建档时 |
| **来源** | [官方档案还是自建档案](#官方档案--自建档案) | 二选一 | 产生时，**不可改** |
| **允许的供应商** | 这条档案允许走哪几家、**按什么次序** | **有序列表，非空**；**顺序即[重试挂件](#512-重试站在一个已经存在的位置上)逐家去试的顺序**——每一次发出只走其中一家 | 建档时，可改 |
| **允不允许回退** | 第一家不行时，允不允许往后走 | 是 / 否 | 建档时，可改 |
| **收得下的模态** | 它能读哪几种内容 | **非空**，取自[模态](#模态)那几种 | 建档时，随上游变化更新 |
| **给得出的模态** | 它能产出哪几种内容 | **非空**，同上 | 同上 |
| **一次最多吃多少** | 这条档案实际提供的输入窗口有多大 | **明确、有限且至少一，不超过已知的上游输入窗口** | 建档时，可改，随上游限制复核 |
| **一次最多吐多少** | 输出上限有多大 | **至少一** | 同上 |
| **送进去之前的限制** | 内容必须满足的上游要求，以及本档案实际提供的输入上限；两者分别声明 | 上游要求可明确为未知；本档案的上限必须明确、有限。首版具体约束为**一张图最大多少字节**：提供图片输入的档案必须给出正的有限上限；不提供图片输入时不适用 | 建档时确定，可改；上游事实按证据更新，本档案上限随之复核 |
| **在册状态** | [在册还是已撤回](#在册--已撤回) | 二选一 | 见 [§6.4](#64-撤回不删行会话指向被撤回的档案时说已下架) |
| **请求参数** | 发请求时随档案带上的那些常用参数：推理强度、temperature、seed 这一类 | **一组统一命名的参数与各自的默认值**，词表由系统定一份、**各家 adapter 自己解析处理**；上游不认的项**不静默丢，留痕** | 建档时给，可改 |

**请求参数为什么在档案上而不在别处**：这些值说的是「这条档案怎么被调」，跟哪个 agent、哪个会话无关；
放在会话或 agent 定义上，同一条档案在两处就会被两套参数调，**而排查的人查不出这一次到底带了什么**。
一次请求实际带了什么，[留痕](../PF-004-agent-definition-and-assembly/design.md#66-模型在每次请求时确定)在那次请求的可追溯组成里；
「调模型之前」的拓展件可以只为这一次改掉它们，改了同样留痕。**词表里有哪些参数、每项什么取值，归规格。**

**凭据不在这张表里**：[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)
是**范围身上的一项属性**，不是档案的，理由见 [§5.6](#56-凭据挂在范围上不挂在档案上)。

> **属性表只写业务约束。**精确的数据结构、字段名与格式归 `spec/` 的 Schema，
> 在这里再写一份完整字段规格，两边必然对不上。

**差一点就是它、但不是它的三样：**

| 那是什么 | 为什么不是档案 |
|---|---|
| **上游那个模型本身** | 我们改不了它。**档案是我们对它的记载**，记载可能过期，而模型不会因为我们改了档案就变 |
| **一次模型调用** | 那是[计算资源](../../ubiquitous_language/terms/execution-and-outcome.md#ul-model-call--一次模型调用--model-call)，有头有尾；档案是长期的数据 |
| **「这次实际用了哪条」那条留痕** | 那是[一次请求的可追溯组成](../PF-004-agent-definition-and-assembly/design.md#66-模型在每次请求时确定)，是历史，不是档案 |

#### 上游限制与档案提供的上限

**上游允许多大，与我们通过这条档案提供多大，是两件必须分清的事。**
前者是需要证据的上游事实；后者是本项目要配置、兑现和验证的输入范围。
读档案的人必须分得清哪一项来自上游，哪一项是本档案提供的上限，不能把后者说成模型本身的能力。

- **上游限制查不明，明确记为未知。**未知不等于没有限制，也不能用零或空值冒充。
  只有证据明确说明某项没有限制，才能这样记；整次请求的总量限制不能当成已经查明的单图上限。
- **官方与自建档案都必须给出明确、有限的输入范围。**输入窗口必须明确；提供图片输入时，
  **一张图最大多少字节**也必须是正的有限值，即使上游对应限制未知或已明确不设这一项限制。
  尚未配齐适用上限的档案不能用于发出请求，不能默认为无限，也不能靠只发文本绕过缺项。
- **已知上游限制仍然有效。**本档案的提供范围不能超过已知的上游范围；
  单图大小、图数、整次请求总量等要求各按自己的适用范围同时满足，不能拿一种替代另一种。
  没有提供某种模态，就不能因为配了一个大小上限而宣称支持它；上游某项大小限制未知，也不取消已经确认的模态。
- **组装后的输入必须通过本档案的限额检查，才能发出。**字节与图片数量按实际值精确检查；输入 token 按下述计量规则检查。原件超限时，
  按已有的[组装与转换规则](#八边界与依赖)处理；没有合规表示就明确拒绝这份请求，不能先发给上游试运气。
  这不改写已落盘的原件，也不把大小问题改报成不支持该模态。
- **符合本档案的上限，不保证上游一定接受。**未知限制、其他已知要求或上游变化仍可能使请求失败；
  上游实际拒绝时，按[既有调用规则](#57-上交带什么原样带着状态码不翻译它)如实记录。
  一次成功只说明那一次被接受，不能据此把未知改成没有限制。

**输入 token 允许有依据的估算与可配置余量。**能取得适用的准确计数或可靠上界时使用它；否则可以使用适配该模型的分词计量与完整请求表示进行估算，并按明确配置的余量检查档案上限。消息历史、提醒、工具定义及实际发送模态都要纳入，不能只数用户新发的一句话。没有适用计量依据或必要配置时仍拒绝请求，不把任意字符倍率当成模型计量。

估算通过表示这份请求通过了所声明的估算与余量检查，**不保证上游实际 token 数完全相同或必然不超限**。估算连同余量超过上限时拒绝，并说明这是估算限额检查的结果，不能称为已经测得实际超限。字节与图片数量不采用这种估算例外。发送前的估算、余量和计量依据应可追查；响应中的实际用量与费用仍按上游事实记录，不用估算填账或覆盖实际值，也不因估算偏差抹掉已经发生的请求。

具体上限数值、计量算法与余量配置及验证办法随模型供给配置与规格确定，本 topic 不给全体模型写死一个值。
分清这两类信息，用户才知道自己能发多大的内容，也不会把本项目的可用范围误当成上游完整能力。

#### 档案的身份：所在范围加路由名

**一条档案是哪一条，看两样：它所在的范围，和它的路由名。**范围指出厂默认、某一个组织或某一个租户。

- **同一个范围里，一个路由名只对应一条档案**——在册的、已撤回的都算。
  要在同一个范围里再用一个已撤回档案的路由名，就是把那一条[恢复在册](#64-撤回不删行会话指向被撤回的档案时说已下架)，不是另建一条。
- **不同范围里，同一个路由名可以各有一条**：官方（出厂默认）、组织层、租户层各有一条同名的，都建得成、都在，互不相撞。

**路由名就是能力：同名的几条，运行时从下往上覆盖。**「用哪个模型」那项设置记的是**路由名**；
一个会话用到这个名字时，在它所在的那条范围链上取**最具体一格**的那一条——**租户 > 组织 > 官方**，
与[资产按层求值](../PF-002-assets-settings-and-permissions/design.md#56-四步资产求值--组装--投影--层级计算)同一条规矩。
**同名的几条里用哪一条，由层序定，不由引用它的人挑**；这个名字在一条链上恰好落到一条档案，它的事实都在那一条上。

> **所以「用哪个模型」这项设置的值是一个路由名，不是某一层的某一行。**
> 切换改的是这个名字；组织锁死的是这个名字；会话那一格、组织那一格记下的，也都只是这个名字。
> **它落到哪一行，每次用到时按层序现算**——同一个名字，在两个成员的会话里可以落到不同层的两行。

**取最具体一格之前，先滤掉两种；另两种不滤：**

| 这一条 | 取胜者之前 | 为什么 |
|---|---|---|
| **[已撤回](#在册--已撤回)** | **滤掉**——最具体那一格的撤回了，这个名字就落到下一格在册的那一条 | 与资产[先滤禁用、再取最具体](../PF-002-assets-settings-and-permissions/design.md#56-四步资产求值--组装--投影--层级计算)同形：撤回的那一条已经不在册，让它挡着外层在册的那条，这个名字就平白用不了 |
| **[这个范围不允许](#在册--已撤回)的** | **滤掉**，同上 | 范围允不允许是[设置与权限那一套](#在册--已撤回)对这一条下的判断；判了不允许，它在这个范围里就与撤回的一样不在候选里 |
| **读不了这个会话里的内容的**（[模态](#模态)对不上） | **不滤**——胜出的是它，这个名字在这个会话里就[不是合法目标](#510-合法目标集合与展示列表是两件事) | 在册、范围允许，它就是这个名字在这条链上的那一条；**同一个名字不因为会话里发过一张图，就换成另一层的供应商与参数** |
| **调它时没有凭据可用的** | **不滤**——胜出的还是它，[列表上标明缺什么](#510-合法目标集合与展示列表是两件事) | 缺凭据是调它的人[去配自己那一把](#56-凭据挂在范围上不挂在档案上)就能了结的事，不是这一条不在；滤掉它，名字就会随「配没配凭据」在两层之间来回换 |

**「已下架」只在链上同名的每一条都撤回了时才说。**会话用的这个名字，最具体那一条撤回了、链上另有同名在册的一条，
**调用照发，用那一条**；列表上撤回的那一条标「已下架」，外加「被某层同名档案覆盖」，看得出这个名字此刻用的是哪一层的（[§6.4](#64-撤回不删行会话指向被撤回的档案时说已下架)）。

**组织的锁锁的是路由名。**组织把「用哪个模型」[锁死](#选中模型-与-有效模型)在一个名字上，成员换不了名字；
**这个名字落到哪一条，照样按上面的层序**——供应商、请求参数、凭据都取胜出的那一条的。

**为什么不能只拿路由名当一条档案的身份**：路由名是上游认的那个名字，**谁也改不了它**。
同一个上游模型，平台随系统发布一条，某个组织按自己的需要（换一组供应商次序、换一组请求参数）再建一条，是常事；
只认路由名，两条里总有一条建不进来——**而被挡的那一方连换个名字都做不到**。

**为什么同名的几条按层覆盖、不由人挑**：组织或租户为同一个上游模型再建一条，是要换一种调法去调它——
**这就是在替换外层那一条的实现**，与资产的[同标识替换](../PF-002-assets-settings-and-permissions/design.md#55-资产替换的层级)是同一件事。
让人在同名的几条里挑，每个会话就得自己决定用谁的配置，列表上同一个名字排着几行、长得一样，挑中了哪一条他自己都说不清。

**代价要写明：**

- **组织建了一条与官方同名的自建档案，成员就用不到官方那一条。**[自建档案调用时用的是调它的那个成员自己那把凭据](#56-凭据挂在范围上不挂在档案上)，
  没配自己那把的成员，这个名字就用不了——列表上标明缺什么。这是按层覆盖的直接后果。
- **组织锁得住名字，锁不住这个名字落到哪一条**：成员在自己那层建一条同名的，供应商与参数就是他的了。
- 同一个路由名在列表上仍可能不止一行：胜出的那一条之外，被盖住的照列、带来源、标「被某层同名档案覆盖」，**选不了**（[§6.3](#63-官方与自建在同一份列表里)）。

### 模态

**一类内容的形态**：文本 · 图 · 语音 · 视频。

**它有两处落点，而且必须对得上：**

| 落在哪 | 它在说什么 |
|---|---|
| **档案上** | 这个模型**收得下**哪几种、**给得出**哪几种 |
| **[内容块](../PF-009-context-message-types/design.md#消息的内容是一串块不是一段文本)上** | 这一块**是**哪一种——**由块的媒体类型决定** |

**两处对不上，就不该走到发请求那一步**——挡在[算合法目标](#510-合法目标集合与展示列表是两件事)那一刻，
而不是挡在出门那一刻（[§5.11](#511-有-transcript-的块不再把任何模型挡在外面)）。

**差一点就是它、但不是它**：**块的类型**。
[PF-009 的块有七类](../PF-009-context-message-types/design.md#消息的内容是一串块不是一段文本)，
而模态只有四种——**两者不是一回事：模态是内容的形态，块的类型是装它的载体。**

- **思考**与**工具调用**是文本的**用途**，不是形态；
- **视频没有自己的块类型，它装在文件块里**——文件块的模态**看它的媒体类型**：
  媒体类型是一段视频，这个块就是「视频」；是一张图，就是「图」；
- **媒体类型不属于四种模态中任何一种的文件块**（一份文档、一个压缩包），
  装的就只是[一个附件的引用](../PF-009-context-message-types/design.md#消息的内容是一串块不是一段文本)——
  引用是一段文本，**任何模型都读得了**。

> **所以「文件」不是一种模态**：文件块是载体，**它装的东西有没有模态、是哪一种，看媒体类型**。
> 媒体类型落在四种之外的文件块不进模态投影，也不影响一个模型是不是合法目标。

### 模态投影

**这个会话的历史里，出现过哪几种[模态](#模态)是「只有原件、没有 transcript」的。**

它是一份**投影**，从[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)得来——
**不是第二份权威**：从日志重算一遍，一定得到同一个答案。

> **⚠️ 它不是「历史里出现过哪几种模态」，中间隔着[转换件](#转换件)那一道。**
> 一张图若在落盘之前被转换件配上了 transcript，**它就不再进这份投影**——
> 因为[任何模型都读得了那一份](#511-有-transcript-的块不再把任何模型挡在外面)。

**它只算标着[给模型看](../PF-009-context-message-types/design.md#每个块带两个标注给人看吗给模型看吗)的块。**
只给人看的块永远不会递到模型面前，它是什么模态，与挑哪个模型无关——
算进去，一块只给人看的图就能把一批模型挤出合法目标，而那些模型根本不会碰到它。
**转换件因此也不转它**：没有哪个模型要读它的 transcript。

三条性质：

- **它只增不减。**一个**没有 transcript** 的块进了历史，这个会话就**永远**含有那一种——
  [记录里的消息一条都不能擦除](../PF-010-context-management-and-assembly/design.md#612-记录里的消息一条都不能擦除)，
  所以那个块不会消失。**压缩也不会让它消失**：压缩只翻「给模型看」那一位，不搬走东西。
  **而 transcript 是[在落盘之前写好的](#转换件)，之后不再变**——
  所以「有没有 transcript」这件事本身也只增不减，**投影因此仍然是单调的**。
- **它必须答得出「有没有」，而且要快**（[§6.18](#618-模态投影要答得快而且是增量维护出来的)）。
  用户每打开一次模型列表就要用到它一次。
- **它是[合法目标集合](#510-合法目标集合与展示列表是两件事)的一个输入**，不是模型档案的属性。

**差一点就是它、但不是它：**

| 那是什么 | 为什么不是模态投影 |
|---|---|
| **这一次请求里带了哪些模态** | 那是**这一份组装**的事实，会随压缩与筛选变；投影说的是**整个会话曾经有过什么** |
| **当前模型收得下哪些模态** | 那是[档案](#模型档案)的属性，说的是**能力**；投影说的是**历史** |
| **历史里出现过哪几种模态** | **那是它的上界。**投影只收其中**没有 transcript** 的那些——两者的差，正是转换件干的活 |

> **会话本身归 [PF-015](../PF-015-session-lifecycle-and-ownership/README.md)，本 topic 只定这一项投影，
> 因为它只为一件事服务：算合法目标。**

### 转换件

**一件挂在 [PF-012「消息落盘之前」](../PF-012-agent-loop-and-run/design.md#消息落盘之前每条消息都经过它不只是输入)那个位置上的
[拓展件](../PF-012-agent-loop-and-run/design.md#拓展件)：拿一个块，交出它在别的模态下的样子，外加一段纯文本的 transcript。**

> **位置归 [PF-012](../PF-012-agent-loop-and-run/design.md#模态转换为什么必须落在这里)（rev 11），契约归这里**——
> 因为「有哪些[模态](#模态)、哪个模型收得下哪些」是大语言模型域定的。

**它的契约：**

| | |
|---|---|
| **按键登记，同键可替换** | 键是**一种[模态](#模态)，或一种文件的媒体类型**。**同一个键上只有一件生效**，换一件就是把原来那件替换掉。**一个位置上照样挂多件**——[同一个位置挂多个是常态](../PF-012-agent-loop-and-run/design.md#按位置命名不按功能命名)，各管各的键。**一个文件块同时命中「模态」键与「媒体类型」键时，媒体类型那个键上的那一件来转**，只出一份派生表示——更具体的那个键压过更一般的，一个块不会有两份各说各话的 transcript |
| **输入：一个块** | **一个非文本模态的[内容块](../PF-009-context-message-types/design.md#消息的内容是一串块不是一段文本)，或者一个文件块。**模态或媒体类型就在块上，不必另传 |
| **输出：别的模态的块，外加 transcript** | **一个或多个别的模态的内容块——不能是文件块——外加一段纯文本的 transcript。**transcript 是最后的兜底，**每一次都必须有**；**只交 transcript、一个派生块都不交，同样不合契约** |
| **本版不调模型** | 转换是本地的事：**transcript 只来自本地的识别**，转换件自己不发起模型调用。**代价**：「让一个看得懂图的模型替纯文本模型描述这张图」这条路本版没有 |
| **原块不动** | 交出来的那几个块**不进消息的块序列，也不另立对象**：它们挂在原块上，作为原块的**派生表示**；transcript 也挂在原块上。**原件一步没动** |
| **落盘之前写好，之后不再变** | 所以**一个块有没有 transcript，是落盘那一刻就定死的事实**——[模态投影因此还是单调的](#模态投影) |

**组装时怎么用它**：按[有效模型](#选中模型-与-有效模型)收得下的模态，取原件或对应的派生表示；
**都取不到，就用 transcript**。所以**有 transcript 的块，任何模型都读得了**（[§5.11](#511-有-transcript-的块不再把任何模型挡在外面)）。
几份都收得下时挑哪几份，是 [PF-010 组装](../PF-010-context-management-and-assembly/README.md)的事。

**转换失败，那条消息就不落盘——不管它是谁产生的。**失败指它自己挂了，或者交不出合乎上面契约的东西——
没有 transcript、一个派生块都不交、交出了文件块。这是「消息落盘之前」这个位置上的[否决](../PF-012-agent-loop-and-run/design.md#干预力三档直接用-pf-000-的)
（[PF-012](../PF-012-agent-loop-and-run/README.md) rev 11），**落不了盘之后怎么办，按消息是谁产生的分三路**：

| 那条消息是 | 转换失败之后 | 用户看到的 |
|---|---|---|
| **输入消息**（用户说的、外面捎来的） | **拒绝这次请求，发送方被告知** | 这张图没发进去，**会话、投影、可选模型都没变**，他可以换一张再发 |
| **模型的回复** | **这次模型调用照常结束，那一份记下被谁否决**——它不是故障，不带成因，也不交给重试挂件；loop **退避之后另起一次新的模型调用**。同一步里一次次被否决到上限，**这个 Run 失败**（上限归 [PF-012](../PF-012-agent-loop-and-run/design.md#消息落盘之前的否决按消息是谁产生的分三路)） | 慢一点；到了上限，这次任务失败，**原因指向转换件与那个块** |
| **工具交回的结果** | **这个 Run 失败**，原因指向转换件与那个块 | 这次任务失败，说得出是哪一个块没转成 |

**没有第四路，尤其没有「照原样落盘、只是没有 transcript」这条路。**
我们**没有补偿机制**：落了盘的东西收不回，而一个转坏了的块一旦进了日志，
就会**永久**缩小这个会话的可选模型（[模态投影只增不减](#模态投影)）。**宁可这次请求失败、这个 Run 失败，也不留一个说不清的块。**

> **「消息落盘之前」仍是 [PF-012 的 Loop 位置](../PF-012-agent-loop-and-run/design.md#消息落盘之前每条消息都经过它不只是输入)，
> 但它的失败语义与[业务流程拓展点](../PF-015-session-lifecycle-and-ownership/README.md)同性质：拒绝或失败，不补偿。**
> 它的干预力因此是「可改写 · 可否决」：写派生表示与 transcript 是改写；
> 它失败了，照[「可否决那一档挂了当否决」](../PF-012-agent-loop-and-run/design.md#干预力三档直接用-pf-000-的)办。

**没有登记转换件，不是失败。**那个键上没人登记，块就照原样落盘、**没有 transcript**——
[它于是进模态投影，把收不下它的模型挡在外面](#511-有-transcript-的块不再把任何模型挡在外面)。
**这是有意的兜底方向**：没人读得懂时宁可挡住，也不能让模型读到一个空块。
**登记了、此刻却用不了，不是这一条**——那是它挂了，[当转换失败](../PF-012-agent-loop-and-run/design.md#系统自带的几件不可用时各有定法)。

**三件事它不做，也不是：**

- **不判断「这次要不要转」。**它不知道这个会话现在用哪个模型，**也不该知道**——
  [落盘之前那一刻看不到此刻有没有运行在跑](../PF-014-inbound-intake-and-queueing/design.md#56-消息落盘之前那一刻看得到什么)。
  **能转就转，转好了挂在那儿**；用不用得上，是组装那一步按模型挑的事。
- **不承诺无损。**一张图转成的那段文字**一定比原图少**。
  产品要为此负一条责任：**用户要看得出这次模型读到的是哪一份**——
  它落在[交付面](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-delivery-surface--交付面--delivery-surface)对那条消息的呈现上：
  模型这一次读的是转换出来的那一份，那条消息就标明「本次模型读到的是转换后的文本」（[PF-016 §6.21](../PF-016-cli-tui-delivery-surface/design.md#621-被转换过的消息呈现上说得出模型读的是哪一份)）。
- **不是资产。**它能按键替换，像资产那样；**但本版不升为资产**——
  不走资产的持有、分享与求值（[非目标](#非目标)）。**所以替换只发生在系统装配那一层**：
  组织与租户本版换不了哪个键上的转换件——**能按范围各换各的，就是资产那一套，只是换了个名字**。

**差一点就是它、但不是它**：**[结果卸载](../../ubiquitous_language/terms/execution-and-outcome.md#ul-result-offloading--结果卸载--result-offloading)**。
那是把**太大**的工具结果换成带摘要的占位，**原件离开了消息**；
转换件处理的是**读不懂**，而且**原件一步都没动**。

### 选中模型 与 有效模型

**这一对必须同时定义，因为混起来的代价极高——而它是个只靠命名就能防住的错。**

| | **选中模型** | **有效模型** |
|---|---|---|
| 是什么 | **会话当前指向的那条档案** | **这一次请求实际用的那条档案** |
| 本质 | 一个**取值**，是一条被记下来的事实 | 一次**求值的结果**，每次请求现算 |
| 什么时候变 | 只因一次[切换](#59-换模型一条事实一个生效点零个新分支)而变 | **每一次请求都可能不同** |
| 算不出来会怎样 | 不会——它就摆在那儿 | **算不出来是一件非常态**（[§6.9](#69-合法目标算不出来时不替用户改选)） |

**两者都落在「用哪个模型」这一项[设置](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性)上，不另起一套机制：**

| | 在那项设置上是什么 |
|---|---|
| **选中模型** | 这项设置在**会话那一格**的值。[切换](#59-换模型一条事实一个生效点零个新分支)就是改这一格；会话从没切换过时这一格没有值，选中模型取这项设置沿层级求值出来的那一条 |
| **上层锁死** | 组织或租户把这项设置配成[不可覆盖](../../ubiquitous_language/terms/scope-and-resolution.md#ul-immutable-marker--不可覆盖标记--immutable-marker)——会话那一格的值于是压不过它 |
| **有效模型** | 这项设置[四步求值](../PF-002-assets-settings-and-permissions/design.md#56-四步资产求值--组装--投影--层级计算)的结果，外加「调模型之前」的拓展件只为这一次做的改写 |

**所以有效模型由两件事决定：**

1. **选中模型经[层级求值](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性)**——
   组织在自己那层[锁死](../../ubiquitous_language/terms/scope-and-resolution.md#ul-immutable-marker--不可覆盖标记--immutable-marker)了，算出来的就是锁定的那条，不是会话选的那个，**请求照常用锁定的那条发出**；
2. **一件挂在[「调模型之前」](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)的拓展件可以改掉它**——
   那是 PF-012 已经开放的位置，**而它[必须留下结论](../PF-012-agent-loop-and-run/design.md#610-能干预的拓展件必须留下结论)，所以改掉不是静默的**。

**差一点就是它、但不是它**：**「上一条回复是哪个模型生成的」**。
那是[留痕](../PF-004-agent-definition-and-assembly/design.md#66-模型在每次请求时确定)，
是上一次求值的历史答案——**事后回看不改成当前选的那个**。

> **为什么非要两个词**：混成一个，用户界面上那句「你正在用 X」就会被读成
> 「刚才那句话是 X 说的」。**这两件事完全可以不是同一个答案**，而混起来之后
> **没有任何地方查得出差在哪**——[§7](#七取舍) 里记着一个真实发生过的反面案例。

### 在册 / 已撤回

| | **在册** | **已撤回** |
|---|---|---|
| 能不能被新选中 | 能 | **不能** |
| 还读不读得出来 | 读得出来 | **读得出来**——[行还在](#64-撤回不删行会话指向被撤回的档案时说已下架) |
| 会话已经指着它 | 照常 | 说得出「**已下架**」，而不是「未知模型」——**链上同名的每一条都撤回了时**；链上另有同名在册的，这个名字[落到那一条](#档案的身份所在范围加路由名)，调用照发 |
| 能不能换到另一边 | 能被撤回 | **能恢复在册**——恢复的还是原来那一条，[指着它的会话不用换就接得上](#64-撤回不删行会话指向被撤回的档案时说已下架) |

**差一点就是它、但不是它**：**「这个范围不允许它」**。
那条档案照样**在册**，只是在这个范围[求值](../../ubiquitous_language/terms/scope-and-resolution.md#ul-scope-evaluation--作用域求值--scope-evaluation)算不出来——
被锁死了，或者某一层把它配成了不允许。**「范围允许」就是这次求值的结果**——档案不是资产，
没有[使用权](../../ubiquitous_language/terms/circulation-and-entitlement.md#ul-usage-right--使用权--usage-right)这一层，
组织不想让某个范围用某条档案，用的就是设置与权限那一套。

> **两者用户要做的事不同**：已下架要换一个，不被允许要去找管理员。
> **所以它们不能共用一个说法。**

### 官方档案 / 自建档案

| | **官方档案** | **自建档案** |
|---|---|---|
| 谁产生 | 随系统发布 | **组织超级管理员或租户**，在自己那一层建 |
| 位于哪一层 | **出厂默认层** | 组织层或租户层 |
| 凭据 | **不含**——出厂默认那一格的那一把由部署装配时配好（[§5.6](#56-凭据挂在范围上不挂在档案上)） | **不含**，调用时取[发起调用的那个租户的那一把](#56-凭据挂在范围上不挂在档案上)——建在组织层的也一样 |
| 在哪展示 | **同一份列表**——不是两份（[§6.3](#63-官方与自建在同一份列表里)） | 同左 |
| 列表上标着什么 | **来源：官方** | **来源：自建，外加建在哪一层**（组织层 / 租户层） |
| 能不能与对方同路由名 | **能**——[身份是所在范围加路由名](#档案的身份所在范围加路由名)，两者在不同的范围里；**同名时自建的[按层覆盖](#档案的身份所在范围加路由名)官方的** | 同左；组织层与租户层同名时，租户层的覆盖组织层的 |

**注意：这两个词与[官方件 / 自定义件](../../ubiquitous_language/terms/circulation-and-entitlement.md#ul-official-asset--官方件--official-asset)不是同一个东西。**
那一对说的是**资产**的来源，而[档案不是资产](../PF-001-identity-scope-and-agent-constraints/design.md#资产的种类)。
**两套词各有各的对象，不能互相套用**——所以这里用「档案」而不是「件」。

### 什么时候算试尽

**这一层不再有可试的手段。**到了这一刻，这件非常态就[上交](#55-上交交给谁看模型说没说出话)。

**这是一个判断，而不是一个公式**——**做这个判断的是[挂在「调模型之后 · 失败」那个位置上的拓展件](#512-重试站在一个已经存在的位置上)**，
而它是可替换的。

三条性质：

- **「试几次、按什么次序、等多久值不值」是策略**，因此不写死在这里。
- **但有一批情形根本轮不到策略**：[「重试没用」那几类与「已经开口说话了」](#54-三类事实归本层定死其余照状态码)
  是**事实判断**——重试在物理上没有意义，**任何策略都改不了**（[§6.12](#612-事实判断归本-topic策略归拓展件)）。
- **「换一个模型」不是这一层的手段**，所以「所有模型都试过了」不是试尽——
  换模型是用户的命令（[§6.5](#65-切换是用户的直接命令合法目标不得拒绝)）。

**差一点就是它、但不是它**：**「这一次失败了」**。
一次失败之后若还有手段可试，**这一层就还没了结不了**。

> **档案上那两项——「允许的供应商及次序」「允不允许回退」——是这个判断的[输入](#512-重试站在一个已经存在的位置上)，
> 不是它的定义。**写成定义，策略就被钉死在一种形态上了。

## 五、模型

### 5.1 一条档案，三种身份的人碰得到它

```text
          出厂默认层：官方档案（随系统发布，不含凭据）
                 │
      组织层：组织超管建的自建档案 ───┐
                 │                  ├─→ 这个范围看得见的档案 ──→ 聚合成一份列表，每条标着来源
      租户层：租户自己建的自建档案 ───┘        （作用域求值，PF-001/002）
                 │
                 ↓
   「用哪个模型」这项设置的取值 ──引用──→ 一条档案
                 │
                 ↓  层级求值（PF-002 第四步）
          【有效模型】这一次请求实际用的那条
```

**三件事值得单独说：**

- **档案与凭据是两样东西，挂的地方也不一样**：档案可以在出厂默认层、组织层或租户层；
  凭据只在租户层，外加出厂默认那一格由部署配的一把（[§5.6](#56-凭据挂在范围上不挂在档案上)）。
- **「这个范围有哪些档案」不是一个新机制**——就是[作用域求值](../../ubiquitous_language/terms/scope-and-resolution.md#ul-scope-evaluation--作用域求值--scope-evaluation)。
  组织把某条锁死、某条配成不允许，用的都是已有的那一套。
- **官方与自建在这张图上位置不同，在用户眼里却是同一份列表。**
  位置差别是求值的输入，**不是展示的结构**；它在列表上只留下一样东西：每一条的[来源标注](#63-官方与自建在同一份列表里)。

### 5.2 这一层的四要素——填 PF-011 那一格

**[PF-011 §5.4 那张六层表里，一次模型调用那一行写着「未定——这一层尚无 owner」](../PF-011-off-nominal-handling/design.md#54-各层的四要素)。
本节填的就是那一格。**

| 要素 | 这一层的答案 |
|---|---|
| **主路径** | **发出请求 → 流式回来 → 完整的一份回复**（[PF-011 已定，本 topic 不改](../PF-011-off-nominal-handling/design.md#54-各层的四要素)） |
| **本层了结得了的** | **① 换一家供应商再来一次**；**② 退避之后再来一次**。**没有第三样**——而**试几次、换哪一家、等多久，由[一件可替换的拓展件](#512-重试站在一个已经存在的位置上)定，不写死在这里** |
| **交给谁** | **agent 的一步**；**但模型一个字都没出来时，那一层此刻不存在，按[已有的例外](../PF-011-off-nominal-handling/design.md#61-起点可以是任何一层往上不许跳)越过它交给运行**（[§5.5](#55-上交交给谁看模型说没说出话)） |
| **终局** | **——**。它不是根，[只有租户那一层落得了终局](../PF-011-off-nominal-handling/design.md#68-阶梯到租户为止) |

**「本层了结得了的」只有两样，这一条比看上去要紧。**
它意味着**这一层变不出**下面这些东西，因而它们一律是上交，不是重试：

| 缺的是 | 谁手上有 |
|---|---|
| 一条能用的凭据 | **租户自己**——去配他那一把 |
| 一个在册且这个范围允许的模型 | **用户或管理员** |
| 一个读得了这个会话里那些内容的模型 | **用户**——[换一个，或开新会话](#511-有-transcript-的块不再把任何模型挡在外面) |
| 更小的一份请求 | **运行那一层**——[压缩就在那里](../PF-010-context-management-and-assembly/design.md#57-压缩能做的只有两件事) |
| 一份上游肯接受的内容 | **agent 的一步**——它自己改写 |

> **这正是 [PF-011 那条总判据](../PF-011-off-nominal-handling/design.md#56-了结得了吗看缺的那样东西在谁手上)在这一层的展开，
> 不是另一条判据。**

### 5.3 一次模型调用会在哪些位置偏离——这是举例，不是清单

**沿主路径那三步走一遍，已知会出事的位置有四处：**

| 位置 | 已知会出什么事 |
|---|---|
| **还没出门** | 选中的模型已下架 · 这个范围不再允许它 · **它和会话里已有的[模态](#模态投影)对不上了** · 没有可用的凭据 |
| **出门了，首 token 之前** | 连不上 · 超时 · 凭据被拒 · 被限流 · 请求被判不合法 · 内容被上游策略拦下 · 上游 5xx |
| **首 token 之后，流进行中** | 连接断在半路 · 吐了一半不动了 · 上游中途报错 |
| **拿到完整一份之后** | 回复是空的 · 撞上输出上限被截断 |

> **这张表里没有「用户中断了这次回复」，因为[那根本不是偏离](#还有一种没走完它不在这张表里)。**

> **这张表是开放的，而且一定会过期。**
> 它只用来说明「偏离会长在哪几个位置」，**不是这一层非常态的定义**。
> 依据是 [PF-011 §5.7「这不是一张清单，是一个判断」](../PF-011-off-nominal-handling/design.md#57-这不是一张清单是一个判断)：
> **穷举表永远列不全，而且列出来的第二天就过期。**

**真正起作用的是下一节那个判据。**新情形出现时按它归类，
**上游改了状态码、加了一种新错误，这套分类一个字都不用动。**

### 5.4 三类事实归本层定死，其余照状态码

**产品负责人 2026-09-20 裁决：**

> **llm request 各种情况都是有状态码的，面向状态码设计就行了，策略模型应当足够干净了。**

**所以本 topic 只认三件「重试在物理上没有意义」的事实，其余原样交给状态码：**

| 类 | 判据 | 本层做什么 | 这是什么性质的判断 |
|---|---|---|---|
| **发不出去** | 请求**根本没到**上游 | **不重试，立即上交** | **事实**——[本 topic 定死](#612-事实判断归本-topic策略归拓展件) |
| **重试没用** | 上游答的是「**这次请求本身不行**」：凭据不对 · 请求不合法 · 内容被策略拦下 | **不重试，立即上交** | **事实**——同上 |
| **已经开口说话了** | **首 token 之后**的任何**故障** | **一律不重试，立即上交** | **事实**——同上，且[优先于其余各类](#已经开口说话了优先于其余各类) |
| **其余全部** | **上游那边的事** | **把[状态码原样带着](#57-上交带什么原样带着状态码不翻译它)**，[试不试、怎么试由策略定](#512-重试站在一个已经存在的位置上) | **策略** |

**前三行与最后一行，性质完全不同，这条界线要看清楚：**

> **前三类说的是「重试在物理上没有意义」——那是事实，任何策略都改不了。
> 最后一类说的是「再试一次值不值得」——那是判断，而判断可以换一个人来做。**

> **「已经开口说话了」那一行说的是「故障」，这两个字是限定词。
> [用户主动中断不走这张表](#还有一种没走完它不在这张表里)。**

#### 最后一行不再往下细分

**「换一家可能就好」与「等一下可能就好」不分成两类**，理由是产品负责人那句话：

> **那正是 5xx 与 429 的分别，状态码已经说得清清楚楚。**
> 把它翻译成两个自造的词，**只是在上游与策略之间多垫一层**——
> 而**垫的那一层还会过期**：上游加一种新状态码，这两个词就得重新分配一次。

**前三类为什么不能同样交给状态码，也要说清**，否则这条会被读成「全部照状态码就行」：

| 这一类 | 状态码为什么答不了 |
|---|---|
| **发不出去** | **根本没有状态码**——档案已下架、范围不再允许、模态对不上、没配凭据，**都发生在出门之前** |
| **已经开口说话了** | 那是**本层自己**观察到的事实（首 token 出来了），**与上游最后返回什么无关** |
| **重试没用** | 它**确实是照状态码认的**，但认出来之后的处置是[一条事实，不是一次判断](#612-事实判断归本-topic策略归拓展件)——**不能交给策略去「权衡」** |

#### 「已经开口说话了」优先于其余各类

**标题里那句话的准确说法是：**

> **只要首 token 已经出来，无论上游最后返回什么，都归它。**

**首 token 指这次回复交出的第一样内容，不论模态。**
[PF-009 把内容块按到达方式分成两种](../PF-009-context-message-types/design.md#能一点点长出来的与要么没有要么整个有的)，
首 token 在两种里各落在一个明确的时刻，**哪一块先到这个时刻都算**：

| 这一块怎么到 | 模型的回复里有哪些 | 什么时候算开口 |
|---|---|---|
| **能一点点长** | 文本 · 思考 · 工具调用的参数 · 语音 | **第一片到了** |
| **开个口，然后整个交出来** | 图 · 文件（视频装在文件块里） | **整块交出来了**——光开了个口不算 |

**响应头到了不算，整交的块开了口还没交出来也不算**：那时还没有任何内容，
用户屏幕上什么都没有，记录里也没东西——**判据是「交出了内容」，不是「流有了动静」**。
**这条判据挂在到达方式上，不挂在模态清单上**：将来多出一种内容块，它归哪种到达方式，首 token 就落在哪个时刻，这里一个字不用改。

| 把「开口」定在…… | 会错成什么样 |
|---|---|
| **响应头** | 一个字都还没出来就被当成「已经开口」，**本来可以重发的那一段窗口被关掉** |
| **整交的块开了口** | 图还没交出来就断了，被当成「已经开口」——**与响应头是同一个错**，窗口被白白关掉 |
| **只算文本与思考** | 吐了半截工具调用就断的回复被当成「一个字都没出来」而重发——**记录里那半截调用与新的一份并存** |
| **只算文字类的那几样** | 先吐了一段语音、或先交出一张图就断的回复被重发——**记录里那段语音、那张图与新的一份并存** |

**这个优先关系必须写明**，否则几条规则并列，实现者会读成
「是 5xx 就重试」——**而那时已经有半句话在用户屏幕上了**。
**更要紧的是：它优先于策略那一行**，所以**挂在那个位置上的拓展件也推翻不了它**。

**为什么不许重试，依据全在已接受的内容里：**

| 依据 | 说的是什么 |
|---|---|
| [用户看见了的，会话日志里必须有](../PF-009-context-message-types/design.md#69-用户看见了的会话日志里必须有) | 已交付的那半句**一定在记录里** |
| [流断在半路已经有收场](../PF-009-context-message-types/design.md#56-流断在半路) | 故障断的：已交付的那部分**记在那次调用的账里**，**外加一条提醒** |
| [只要发生了中断就补一条提醒](../PF-009-context-message-types/design.md#613-只要发生了中断就补一条提醒) | agent 会知道刚才断了 |

**这三条合起来，「再发一次」就没有落脚的地方**：记录里会躺着两份回复，
**而用户只看见过一份半**。**一个逻辑回复只发一次**——重试要让位给它。

**有一种情形看着像例外，其实不是：回复完整回来了，却在落盘之前被否决**——
例如[转换件](#转换件)转不成。那一份**没有成为消息**，用户已经看见的部分记在那次调用的账里，与故障断流一样，
所以记录里不会躺着两份回复。**这次调用照常结束**，记下那一份被谁否决；**它不是故障**，不走上面那张表、不带成因，
也不交给重试挂件。**产品负责人裁决这时退避重试**，兑现的方式是 loop **退避之后另起一次新的模型调用**——
「一个逻辑回复只发一次」照旧成立，因为被否决的那一份从来没成为一份回复。
**「试尽」只管故障这一维**；同一步里一次次被否决到上限、这个 Run 失败，那道上限归 [PF-012](../PF-012-agent-loop-and-run/design.md#消息落盘之前的否决按消息是谁产生的分三路)。
**代价写在明面上**：用户看着一份回复出来，随后又看到另一份（[§7](#七取舍)）。

#### 判据怎么用：三个例子

**这三条是判据的应用，不是模型的一部分**——重判它们不动摇上面那张表。

| 情形 | 归哪一类 | 为什么 |
|---|---|---|
| **回复是空的** | **其余全部**（策略那一类） | 首 token **从没出来过**，所以不归「已经开口说话了」；空回复是上游侧的临时形态，**试不试由策略照状态码定** |
| **撞上输出上限被截断** | **不是非常态** | 主路径走完了——[PF-009 已把它收成一条正常的消息 + 一条提醒](../PF-009-context-message-types/design.md#56-流断在半路)。**上层要知道这件事，而那已经由那条提醒兑现** |
| **没有可用的凭据** | **发不出去** | 请求根本没到上游。缺的是一条凭据，**而那在租户自己手上** |

#### 还有一种「没走完」，它不在这张表里

**用户可以对正在进行的一次回复发一个插队指令，效果是中断这一次模型调用**，
让 loop 尽快走到下一次消费输入的那个点。

> **那是一个控制动作，不是一次故障。**

**必须写明，因为它和「连接断在半路」形态几乎一样**——
都发生在首 token 之后，都留下半句话。**不分开，用户每插一次队，
记录里就多一条「模型调用失败」，而那是错的。**

| | **故障** | **被中断** |
|---|---|---|
| 是什么 | 这一层[偏离了主路径](../PF-011-off-nominal-handling/design.md#非常态) | **一个正常的控制动作** |
| 算[非常态](../PF-011-off-nominal-handling/design.md#非常态)吗 | **算** | **不算** |
| 走上面那张分类表吗 | **走** | **不走** |
| 主路径 | 没走完 | **同样没走完** |
| 回到 agent 那一步时 | 那是一次[上交](../PF-011-off-nominal-handling/design.md#上交)，**带一个[成因](#57-上交带什么原样带着状态码不翻译它)** | **不是上交**——它不是非常态。语义是「**这次被用户中断了**」，**不带任何故障成因** |

**这与 [PF-006「用户可以中断，而中断不是失败」](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)是同一条，
换了一层。**那边的理由在这里一个字不改：

> **失败是「这事没成」，中断是「这事不做了」。**
> 把中断当成失败递给 agent，**它会重试——而用户刚刚明确表示不想让它跑下去。**

**本 topic 到此为止**：这个指令怎么被受理、谁有权发、正在跑的工具要不要一起停，
**都不在这里**（[§8](#八边界与依赖)）。**读者只需要知道这一层有两种「没走完」，
一种归本 topic，一种不归。**

### 5.5 上交：交给谁，看模型说没说出话

**这一层的上交分两种，而[接手方不同](../PF-011-off-nominal-handling/design.md#61-起点可以是任何一层往上不许跳)**——
**本节说的全是[故障](#还有一种没走完它不在这张表里)，[被中断不走上交这条路](#还有一种没走完它不在这张表里)：**

| 情形 | 接手方 | 交的是什么 |
|---|---|---|
| **一个字都没出来** | **运行**——越过 agent 的一步 | **一条上交条目**，带[成因](#57-上交带什么原样带着状态码不翻译它) |
| **已经有内容进了记录**（首 token 之后断的） | **agent 的一步** | **[PF-009 那条中断提醒本身](../PF-009-context-message-types/design.md#613-只要发生了中断就补一条提醒)就充当这一跳的上交条目，不另立一条** |

**第一行是 [PF-011 已经写死的](../PF-011-off-nominal-handling/design.md#56-了结得了吗看缺的那样东西在谁手上)**：
agent 就是模型，模型没给出回复，**那个会思考的主体此刻不在那里**。

**第二行是本 topic 补的另一半，而它照搬了 PF-011 已有的一条判断。**
[PF-011 §5.8「接收方就是模型的那一跳」](../PF-011-off-nominal-handling/design.md#接收方就是模型的那一跳)
为工具执行交给 agent 那一跳定过：**那条 agent 必须读懂的消息就是上交条目，不另立一条**。
**三条理由在这里一条不少地成立：**

| 理由 | 在这里怎么成立 |
|---|---|
| **另立的那条，读者答不出来** | agent 读不到它（[默认不进模型上下文](../PF-011-off-nominal-handling/design.md#58-上交交的是什么)），剩下只有排查的人看——那是留痕，**PF-000 已经给它安了家** |
| **同一件事会有两处登记** | [PF-009 §6.13 已经要求补一条提醒](../PF-009-context-message-types/design.md#613-只要发生了中断就补一条提醒)。再加一条上交条目，**同一次断流就有两处登记，而双份登记必然分叉** |
| **PF-000 限定了什么时候才产出多条** | [只有两个原因](../PF-000-occurrences-and-record-entries/design.md#54-一件事什么时候产出不止一条条目)：干预点先于结果、增量先于成品。**这一跳两个都不沾** |

> **上交条目长什么样，归 [PF-011 §5.8](../PF-011-off-nominal-handling/design.md#58-上交交的是什么)——六条要求一条不改。
> 本 topic 只定「交给谁」与「带什么成因」。**

#### 试过又失败的那几次，留痕，不进方程

**换了三家供应商、失败了两次，那两次照样是[发生的事](../PF-000-occurrences-and-record-entries/design.md#发生的事)。**

**每一次发出去只走一家**——换一家就是再发一次，由[重试挂件](#512-重试站在一个已经存在的位置上)决定。
所以**试过的每一家都是一条单独的留痕**：哪一家、什么时候、上游回了什么状态码，都查得到。
让上游在一次请求里自己按次序换家，这几条就全没了——**在我们这边它只是一次请求**（[非目标](#非目标)）。

[PF-011 §5.1 那张表里正好有这一格](../PF-011-off-nominal-handling/design.md#51-非常态与发生的事是同一件事的两个面)：
**「留痕 × 偏离主路径」＝「调用没成、准备重来」**。

由此两条直接后果：

- **它们不进[方程的定义域](../PF-012-agent-loop-and-run/design.md#方程从日志里读什么)**——
  [只有效力为「依据」的条目才进](../PF-000-occurrences-and-record-entries/design.md#52-那个判断两条独立充分条件)。
  **所以本层重试不改变下一步，`f` 照旧是纯的。**
- **它们也不进模型的上下文**（[默认拒绝](../PF-010-context-management-and-assembly/design.md#62-没有明确标了给模型读的不进模型那一份)）。
  **agent 不需要知道我们换过几家供应商**——它拿这个做不出任何判断。

### 5.6 凭据挂在范围上，不挂在档案上

**一把 OpenRouter 凭据配在[租户](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-tenant--租户--tenant)那一层；
这个租户发起的模型调用都从它出去——调的是官方档案、组织层建的自建档案，还是他自己建的，都一样。
[组织](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-organization--组织--organization)那一层不持有凭据。**

```text
   组织层 ── 若干条自建档案（不带凭据）
                                               调用时，不管档案建在哪一层，
   租户层 ─┬─ 一把 OpenRouter 凭据   ←─────────  都取发起调用的那个租户这一把
           └─ 若干条自建档案（不带凭据）
```

**它是[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)：
一个租户身上的一项属性，一个租户一把。**

**不是[设置](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性)**——
设置总是**某份资产**的属性，而[档案不是资产](#模型档案)，凭据也不是。
**它挂在租户自己身上**，所以：**身份即范围**（这一把是谁的，看它配在哪个租户上），
**轮换就是改这一项的值**（不是换一个对象），**用量归到这个租户头上**。

**四条性质：**

- **自建档案自身不存凭据。**调用时取**发起调用的那个租户**的那一把——**不是档案所在那一层的**：
  组织层建的档案，成员调它，用的是成员自己那一把。
- **官方档案自身也不含凭据**；**出厂默认那一格可以有一把**——由部署装配时配好，**产品里没有任何操作能配、换或解绑它**；
  它和官方档案一样随部署而来，不是哪个组织或租户的东西。
- 本节当前描述的是一把 OpenRouter 凭据。[SYS-LLM](../../../../docs/requirements.md#模型接入sys-llm)不限定系统请求通道，不能由本节推导出全系统只允许这一类凭据。其他接入方式的凭据设计仍由相应契约拥有者细化。
- **租户可以自带凭据。**租户配上自己的那一把，他的模型调用就从它出去，
  **用量也跟着记在他头上**——**这是产品要支持的用法，不是绕开产品的走法**。

#### 组织那一层为什么不持有

**模型调用发生在每个人自己的机器上**（[PF-016 §6.20](../PF-016-cli-tui-delivery-surface/design.md#620-每台机器上只有自己那一把凭据)）。
组织持有一把，就得把它发到每个成员的机器上：

- **人离职时收不回**——那一把已经在他的机器上了；
- **需要续期的凭据，还得在许多台机器上各自续期**。

所以每个人在自己的租户层带自己那一把。**[MCP 凭据](../PF-002-assets-settings-and-permissions/design.md#mcp-凭据一份持有一份静态的或经-oauth-取得的)走的是同一条路**——两种凭据一并这么定。

**代价**：每个成员都得自己配一把，组织给不出一个大家共用的账号；
**组织层建的自建档案，成员配上自己那一把之前用不上**——[列表上标明缺的是什么](#510-合法目标集合与展示列表是两件事)。
组织统一供给凭据这件事，[本版不做](#非目标)。

> **代价写在明面上**：**做不到「这个模型走另一个账号」**。[§7](#七取舍) 里说清楚了。

### 5.7 上交带什么：原样带着状态码，不翻译它

**成因这个东西，只为一件事服务：**

> **让接手的那一层知道——[谁能让它不再发生](../PF-011-off-nominal-handling/design.md#56-了结得了吗看缺的那样东西在谁手上)。**

**所以取值只按这一个维度分，[下一步不同才是两个取值](#612-事实判断归本-topic策略归拓展件)。**

| 成因 | 什么时候用它 | 谁能让它不再发生 |
|---|---|---|
| **已下架** | 选中的档案已被撤回 | **用户**换一个 |
| **这个范围不再允许** | 求值之后它不在合法目标里（锁死 / 撤权 / 移除） | **管理员** |
| **和会话里的模态对不上** | 会话里[来了一个没有 transcript、而它又收不下的块](#511-有-transcript-的块不再把任何模型挡在外面)，或有效模型被换成了收不下的那个 | **用户**换一个能读的，或开新会话 |
| **凭据不可用** | 没有可用的那一把，**或**有而上游拒绝它 | **用户**去配或换他租户的那一把 |
| **这次请求本身上游不接受** | 上游明确拒绝了**这一次请求的内容**（不合法 · 被策略拦下） | **agent 自己**——改写内容再来 |
| **上游这会儿给不出回复** | 连不上 · 超时 · 5xx · 限流，**且[试尽了](#什么时候算试尽)** | **没人**——等 |
| **说到一半断了** | 首 token 之后的任何**故障** | **没人**——**但已经有内容到了记录里** |
| **没认出来**（兜底） | **这次确实没认出来** | 去看留痕 |

**每一条上交，都还要原样带着上游返回的状态码（有的话）。**

> **成因回答「谁能了结」，状态码回答「上游到底怎么了」。**
> **两者不是一回事，也不互相替代**——
> 成因是给[分层处置](../PF-011-off-nominal-handling/README.md)用的，状态码是给排查的人和[重试策略](#512-重试站在一个已经存在的位置上)用的。

> **这张表里没有「被用户中断」，而那不是漏了。**
> [被中断不是非常态](#还有一种没走完它不在这张表里)，它根本不产出故障成因。
> **加进来，用户的一次正常操作就会被登记成一次失败。**

#### 为什么是八个取值，不是更多

**两条判据把取值数压住了：**

| 判据 | 它挡住了什么 |
|---|---|
| **「谁能让它不再发生」答案相同的，并成一个** | 「连不上」「超时」「5xx」「被限流」都并进**上游这会儿给不出回复**——答案一律是「没人，等」。[取值本来就该按这条判](#612-事实判断归本-topic策略归拓展件)；差在哪，**状态码说得比自造的词准** |
| **不为已经有状态码的事再造一套词** | 产品负责人的原话。多垫一层自造词，**上游加一种新状态码它就得重新分配一次** |

**「凭据没配」与「凭据被拒」合成一条，是有意的**：两者**用户要做的事完全一样**——
去配一把能用的。分成两条只多一个取值，**换不来任何不同的下一步**。

**反过来，「和会话里的模态对不上」必须单独具名，而不是并进「这个范围不再允许」**：
后者要去找管理员，前者**管理员帮不上忙**——用户只能换一个能读图的，或者开一个新会话。
**下一步不同，就是两个取值。**

#### 兜底值不许用来偷懒

> **「没认出来」的意思是「这次确实没认出来」，不是「懒得分类」。**

两条约束：

- **它出现时，同样要留下可追溯的痕迹**——不然排查的人手上什么都没有。
- **它反复出现，是设计要回来修的信号**：说明有一类情形还没被具名，
  而具名它**不需要改模型**（[§5.4](#54-三类事实归本层定死其余照状态码) 那张表照旧）。

#### 「已下架」为什么要单独具名

**因为不具名，用户看到的是「未知模型」。**

会话指着一条已被撤回的档案，这件事**我们完全知道是怎么回事**——
说成「未知」等于把一个已知的事实丢掉，而用户会以为是系统坏了。

### 5.8 把前身的三档放进这个模型

**前身把模型调用失败分成三档：`surface_to_agent` / `retry_then_abort` / `abort`。
我们有意不照搬**——因为[在 PF-011 的分层模型里，它们根本不在同一个层面上](../PF-011-off-nominal-handling/design.md#52-一层要声明四样)：

| 前身的档 | 在这个模型里是什么 | 归谁 |
|---|---|---|
| **`retry_then_abort`** | **本层了结**（换一家 / 退避）**＋ 试尽之后上交** | **本 topic**（[§5.2](#52-这一层的四要素填-pf-011-那一格)、[§5.4](#54-三类事实归本层定死其余照状态码)） |
| **`surface_to_agent`** | **上交给 agent 那一步** | [PF-011 已定](../PF-011-off-nominal-handling/design.md#上交) |
| **`abort`** | **同样是上交**，只是接手方越过了 agent 那一层 | [PF-011 已定](../PF-011-off-nominal-handling/design.md#61-起点可以是任何一层往上不许跳) |

> **写明这张对照，是因为不写的读者会以为我们漏了两档。**
> 没漏——**那两档被 PF-011 收编成了同一个动作「上交」，差别只在接手方是谁**，
> 而那正是 [§5.5](#55-上交交给谁看模型说没说出话) 定的事。

**这也是为什么成因分类要在这个边界上做**（[§6.11](#611-成因在这个边界上分类不丢进外层按异常形态分)）：
前身把分档放在外层的失败兜底里，按异常形态分，**结果是本地数据库故障被报成了 provider 不可达**。

### 5.9 换模型：一条事实，一个生效点，零个新分支

```text
 用户说「换成 X」
       │
       ▼
 ① 这是一条要被记录的事实 ──→ 落进[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)
       │
       │   正在进行的那一次模型调用：照常跑完，不打断
       ▼
 ② 下一次模型请求之前：【想】那一圈照常走
       │
       │   组装 → 量 → 超了就压缩 → 再组装 → 再量
       │   ↑
       │   **唯一的差别：这次判断读到的是 X 的档案**
       ▼
 ③ 调模型，用 X
```

**这一节最要紧的一句：**

> **换模型没有给 [agent loop 的状态方程](../PF-012-agent-loop-and-run/design.md#agent-loop)添任何分支。**

换一种写法——「切换时若目标窗口更小则压缩上下文」——会在 loop 里多出一个
**只有切换才会走到的分支**，**那个分支此后要单独维护，而它平时根本不跑**。

**而[下一次请求前本来就要量一量装不装得下](../PF-012-agent-loop-and-run/design.md#55-想这一步交进闭包拿回装得下的一份)。**
切换只是让那次判断读到了另一份档案。

| 换到什么样的模型 | 谁处理 | 走的是哪条既有的路 |
|---|---|---|
| **窗口更小** | [PF-010 / PF-012](../PF-012-agent-loop-and-run/design.md#55-想这一步交进闭包拿回装得下的一份) | 量出来超了 → 压缩 → 再量 → 还超就 [T1c 上交给会话](../PF-012-agent-loop-and-run/design.md#56-状态转移表) |
| **收不下会话里已有的模态** | 本 topic | **换不过去**——它[根本不在合法目标集合里](#511-有-transcript-的块不再把任何模型挡在外面)。**这一行不是「换过去之后怎么办」，是「压根换不过去」** |
| **已下架 / 不再允许** | 本 topic | [§6.9](#69-合法目标算不出来时不替用户改选)：不替用户改选，这次调用发不出去并上交 |

> **第二行与第一行的差别，正是这套设计的分界**：
> **窗口装不装得下要到量完才知道，所以不挡在切换那一刻；
> 模态兼容不兼容当场就算得出来，所以挡在那一刻**（[§5.11](#511-有-transcript-的块不再把任何模型挡在外面)）。

> **「模型是[当下条件](../PF-012-agent-loop-and-run/design.md#当下条件)的一部分」这条 PF-012 已经写了**，
> 本 topic 不重定；这里只说明**切换这件事怎么变成那份当下条件的改变**。

### 5.10 合法目标集合与展示列表，是两件事

**它们大部分重合，而不重合的那一小块正是要紧的地方。**

**两者的单位都是路由名**：「用哪个模型」这项设置的值是一个路由名，[不是某一层的某一行](#档案的身份所在范围加路由名)，
所以用户在这里挑的、切换改的，都是名字；每个名字此刻落到哪一行，按层序现算，那一行的事实（模态、窗口、凭据）决定这个名字在这个会话里能不能用。

| | **合法目标集合** | **展示列表** |
|---|---|---|
| 用来做什么 | [切换不得被拒](#65-切换是用户的直接命令合法目标不得拒绝)的那个前提 | 用户看见的那一份 |
| 怎么算出来 | 每个路由名**在这条范围链上胜出的那一条**（[已滤掉已撤回与这个范围不允许的](#档案的身份所在范围加路由名)），**兼容这个会话的[模态投影](#模态投影)** | **合法目标 ∪ 当前选中的那一条**，外加**被它们盖住的同名条目**（只作标注） |

**为什么展示列表要多出那一条：**

> **当前选中的模型可能已经下架。它必须仍然显示，否则用户看不到自己选的是谁。**

**而它不是合法目标**——选不了、切不过去。**两者若是同一个集合，这两条必有一条落空。**

**列表里的每一条，用户还要看得出它此刻能不能真的用上。**展示列表就是上面那个并集，外加被盖住的同名条目，此外一条不多：

| 这一条 | 在不在列表里 | 用户看到 |
|---|---|---|
| **合法目标，调它时有凭据可用** | 在 | 可选 |
| **合法目标，调它时没有凭据可用**（比如一条自建档案，而这个租户还没配自己那一把） | 在 | **可选，并标明现在用不了、缺什么** |
| **当前选中的那条，已下架**（链上同名的都撤回了） | 在——**只因为它是选中的** | **标着「已下架」** |
| **当前选中的那条，这个范围不再允许，或读不了这个会话里的内容** | 在——同上 | **标明是哪一种**，用户知道自己此刻停在一条用不上的档案上 |
| **列表里某个名字胜出的那一条之外、被它盖住的同名条目**（含最具体那一格撤回了的那条） | 在——**跟着那个名字** | **标「被某层同名档案覆盖」**，撤回了的再标「已下架」；**选不了**——选这个名字，用的就是胜出的那一条 |
| **其余不是合法目标的** | **不在** | —— |

**缺凭据那一行为什么要标出来**：它**在用户挑模型的那一刻我们就已经知道**了，
不像窗口要到具体一次请求量完才算得出来。**知道却不说，用户要白白试一次才明白。**

**选中那条为什么非在不可**：它是用户此刻停着的地方。拿掉它，用户看不到自己选的是谁，
也就不知道这个会话为什么发不出去——**而[不替他改选](#69-合法目标算不出来时不替用户改选)，他就只能靠这一行知道该换了**。

**不是合法目标、也不是选中的那些，列表里没有它们**——被盖住的同名条目是唯一的例外，只作标注（见下）：列表回答的是「我现在能换到哪些」和「我此刻在哪一条上」两件事，
选不到的东西当候选摆进来，不回答其中任何一件。[「不得拒绝」的前提是合法目标](#65-切换是用户的直接命令合法目标不得拒绝)，
**它们从来不在候选里，所以也谈不上被拒绝**。

**上表每一行都还标着来源**——官方的，还是自建的、建在哪一层（[§6.3](#63-官方与自建在同一份列表里)）。
**一个路由名能选的只有一行：它在这条链上[胜出的那一条](#档案的身份所在范围加路由名)**，来源告诉用户这个名字此刻用的是谁建的那一条；
被它盖住的同名条目照列，**让用户看得出这个名字换了实现**——与资产那边[同标识替换必须可见](../PF-002-assets-settings-and-permissions/design.md#55-资产替换的层级)同一个道理。

**被盖住的为什么照列**：列表回答「我能换到哪些」与「我此刻在哪一条上」，被盖住的哪一件都不回答；
但少了它们，用户只看见一个熟悉的名字，**以为用的是官方那一条**，而供应商、窗口、请求参数可能全是组织或他自己另配的。
**所以它们在列表上只作标注，不作候选。**

### 5.11 有 transcript 的块，不再把任何模型挡在外面

**这是本 topic 里把一类已知事故从源头堵死的一条。**

> **一个会话的历史里出现过一个图块，而它没有 [transcript](#转换件)，
> 那么从此以后，看不了图的模型就不在这个会话的合法目标里。**

**「没有 transcript」这个限定是整条规则的关键**：

| 如果判据是…… | 带过图的会话能不能切到纯文本模型 | [转换件](#转换件)什么时候被用到 |
|---|---|---|
| 历史里**出现过**图 | **永远不能** | **几乎用不到**——不兼容的模型从来进不了候选 |
| 历史里出现过**一个没有 transcript 的**图块（**实际是这一种**） | **能**——只要那些图都配上了 transcript | **每一次**——它正是「能不能切过去」的决定者 |

**一个块没有 transcript，只剩一种来路：它那种模态或媒体类型上没有登记转换件。**
转换件在、却转失败了，[那条消息根本不落盘](#转换件)——**所以它不会在会话里留下一个没有 transcript 的块**。

> **第一种写法会让转换件自相矛盾。**
> 产品负责人裁决「**落盘之前把收不下的模态处理成文本，
> 这样后面用的时候就变得很干净了（根据模型判就可以）**」——
> **「根据模型判」的前提，就是存在一个收不下原件的模型在用它。**
> 把那种模型全挡在候选之外，**转换件于是永远没有用武之地**。

**放宽之后，这条规则要付的代价也要写出来：**

> **纯文本模型读到的是那段文字，不是那张图。**[转换件不承诺无损](#转换件)。
> 所以[产品必须让用户看得出这次模型读到的是哪一份](#转换件)，落在交付面对那条消息的呈现上（[PF-016 §6.21](../PF-016-cli-tui-delivery-surface/design.md#621-被转换过的消息呈现上说得出模型读的是哪一份)）——
> **不说出来，用户会以为它看过原图，然后照着一个它根本没看见的细节去问。**

**它不是「切过去之后会失败」，是「压根切不过去」**——
因此[「合法目标不得拒绝」那条一个字不动](#65-切换是用户的直接命令合法目标不得拒绝)：
**它的前提就是「合法目标」，而不兼容的从来没进过那个集合。**

**这与[组织锁死](../../ubiquitous_language/terms/scope-and-resolution.md#ul-immutable-marker--不可覆盖标记--immutable-marker)是同一个形状**：
被锁掉的也不进合法目标，**所以也谈不上被拒绝**。

#### 挡在这一刻，而不是出门那一刻

**同一件事有两个可以挡的位置，而选哪个决定了产品是什么样：**

| 挡在哪 | 用户经历的 |
|---|---|
| **算合法目标时**（**选这个**） | 那个模型**不在可选之列**；当前选中的若正是它，列表上**标明它读不了这个会话里的内容** |
| 请求出门时 | 切换看起来成功了，**然后这个会话就再也发不出一次请求**，直到他自己想明白换回去 |

**第二行不是假想。**产品调研里，这是同类产品上**反复出现**的同一种投诉——
带过图的会话切到纯文本模型之后，**会话像是卡死了**：
每一条新消息都失败，而失败信息里通常只说「模型不支持图片输入」，
**不说该怎么办**（open-webui、cline、opencode、以及前身的 harness 都出现过；
**这是调研观察到的事实，不是拍板依据**，来源随本次起草交付）。

> **我们从源头不让它进候选，所以这类投诉在我们这里不会发生。**

#### 由此掉出的三条

- **模态投影只增不减**（[§4](#模态投影)），所以**合法目标集合只会越收越紧**。
  这是实情，要说出来：**一个长会话里只要出过一个没有 transcript 的块，它的可选模型就永久变少了**。
  想回到全集，**只能开一个新会话**。
  > **转换件把这件事的发生率压了下去，但没有消掉它。**
  > 装齐了转换件，这条基本不会被触发；**一件都没装，它就退回最严的形态**——
  > 出过一个图块，纯文本模型就永久出局。
- **当前选中的模型也可能因此出局**——用户往一个纯文本模型的会话里发了一张**没有转换件可转**的图。
  那时[选中模型不再是合法目标](#69-合法目标算不出来时不替用户改选)，
  按 [§6.9](#69-合法目标算不出来时不替用户改选) 处置：**不替他改选**，下一次请求发不出去并上交，
  成因具名为**和会话里的模态对不上**。
- **它必须算得快**——见 [§6.18](#618-模态投影要答得快而且是增量维护出来的)。

### 5.12 重试站在一个已经存在的位置上

**「再试一次值不值得」是策略，而策略要能被换掉。**

> **重试是一件[拓展件](../PF-012-agent-loop-and-run/design.md#拓展件)，
> 挂在 [PF-012 已有的那个位置](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)上：
> 「调模型之后」，[收场维度](../PF-012-agent-loop-and-run/design.md#两个位置带维度)取「失败」。**

**那个位置上原本写的典型用途就是「失败分档」——本 topic 不新增任何位置，
[PF-012 一个字都不用改](../PF-012-agent-loop-and-run/design.md#58-loop-拓展点)。**

**这一条要单独说，因为它省掉了一次[架构内核](../architecture-core.md)改动**：
位置是[从状态点推出来的](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)，
凭空多一个就等于改了那套推导本身。

#### 系统自带一件默认的，所以开箱就有重试

**这个位置上不会空着：系统自带一件默认的重试拓展件。**

它照[档案上那两项声明](#模型档案)办——按「允许的供应商及次序」**一家一家地发，每一次只走一家**：

| 档案说 | 它怎么试 |
|---|---|
| **允许回退** | 顺着次序换下一家，**每家至多试一次**；次序走完就是试尽 |
| **不许回退** | **同一家退避之后至多再试一次**；再不行就是试尽 |

**两行都有尽头**，所以默认这一件一定会停。**不许回退的档案也照样有一次重试**——
不许的是换家，不是再试；否则一条不许回退的档案开箱就没有重试，一次网络抖动照样打断一轮对话。

它是[系统自带的挂件](../PF-012-agent-loop-and-run/design.md#系统自带的几件各站在哪)之一，
**与[转换件](#转换件)一样走同一套位置、同一套干预力，不享受特权**；
租户要换成自己的策略，**把它替换掉就是了**。

> **为什么非要自带一件**：没有它，**开箱状态下一次网络抖动就打断一轮对话**——
> 开箱即用的稳定性**不该取决于有没有人去挂一件**；
> 而[档案上那两项声明](#模型档案)也会**一个消费者都没有**。
> **代价**：多一件要解释的东西——**用户想换掉这套策略之前，得先知道有它在**。

#### 它看得到什么

**看得到什么是产品设计；怎么拿到是技术设计。至少这四样：**

| 看得到 | 为什么它非要不可 |
|---|---|
| **上游返回的状态码** | **这是产品负责人裁决的那条**：「llm request 各种情况都是有状态码的，**面向状态码设计就行了**」。给了它，**策略自己就能分清 429 与 503，不必本层先翻译一遍** |
| **这次失败的[成因](#57-上交带什么原样带着状态码不翻译它)** | 状态码答不了[本层那三类事实](#54-三类事实归本层定死其余照状态码)里的两类——**请求出没出门、首 token 开没开口**。不给，它只能自己去解析上游的原文，**而那正是 [§6.11](#611-成因在这个边界上分类不丢进外层按异常形态分) 要挡的事** |
| **档案声明了什么**：允许的供应商及次序、允不允许回退 | 这是它做判断的**素材**。不给，它就只能凭空定一个次数 |
| **这次调用已经试过哪些** | [失败的尝试是留痕](#试过又失败的那几次留痕不进方程)，**每一次只走一家，所以一家一条，读得到**。不给，它没法知道自己已经走到第几家 |

> **前两样一起给，才是「策略模型够干净」的意思**：
> **本层只交出它独有的那两件事实，剩下的原样交出去，不越俎代庖地分类。**

#### 它能做出什么决定，以及那个决定怎么生效

**两个决定，没有第三个：**

| 决定 | 后果 |
|---|---|
| **再试一次**，并说清换哪一家 / 退避之后再来 | 这次调用回到[「在途」](flows.md#32-一次模型调用)，主路径继续 |
| **不再试** | [试尽](#什么时候算试尽)，**上交** |

**生效方式不另造机制**：
[PF-012 已经定死「拓展件只能靠改日志起作用」](../PF-012-agent-loop-and-run/design.md#69-拓展件只能靠改日志起作用)，
它[追加一条结论条目](../PF-012-agent-loop-and-run/design.md#610-能干预的拓展件必须留下结论)，loop 读日志算下一步。

**干预力走 [PF-012 已有的三档](../PF-012-agent-loop-and-run/design.md#干预力三档直接用-pf-000-的)，本 topic 不新定一档**：
做重试决定的那一件至少要**可改写**；**只观察**的那一件只能记一笔，**改变不了试不试**。

> **它自己挂了怎么办，PF-012 也已经定了**：可改写那一档挂了不影响正在发生的事，
> **但要留一笔「它没跑成」**——否则排查的人分不出「策略说别试了」和「策略根本没跑」。

#### 有三件事它改不动

**这是[事实与策略那条界线](#612-事实判断归本-topic策略归拓展件)在这里的落点：**

- **「发不出去」「重试没用」「已经开口说话了」三类，它推翻不了**——
  那三类说的是重试在物理上没有意义，**不是「不值得」**。
- **「一个逻辑回复只发一次」它推翻不了**——
  [首 token 之后的优先关系](#已经开口说话了优先于其余各类)高于任何策略。
  **首 token 之后没有任何情形交到它手上**：回复在落盘之前被否决，是那次调用照常结束、loop 另起新调用，[不是一次失败](#已经开口说话了优先于其余各类)。
- **换一个模型它做不到**——那是[用户的命令](#65-切换是用户的直接命令合法目标不得拒绝)，不是这一层的手段。

### 5.13 模型请求的运行时可以被单独控制，而它停了看首 token

**[一次模型调用与一次工具执行是兄弟](../../ubiquitous_language/terms/execution-and-outcome.md#ul-model-call--一次模型调用--model-call)**，
所以这一节与 [PF-006 §6.12](../PF-006-tools-and-skills/design.md#612-工具执行的运行时可以被单独控制而它停了就不重来) 同形，
**但两处的答案不一样**——差别正说明了为什么它们是两层。

#### 单独控制：中断这一次调用，不动别的

| 单独动它的手段 | 谁能发 | 结果 |
|---|---|---|
| **中断这一次调用** | 用户，**或[插队](../PF-014-inbound-intake-and-queueing/design.md#插队)顺带触发** | [**被中断**，不是故障](#还有一种没走完它不在这张表里)，**不带任何成因** |

> **「单独」这两个字是硬的**：中断这一次模型调用，
> **不动正在跑的那几个工具执行，也不动这个 run**。
> [产品负责人的原话就是两件事要分开做](../PF-014-inbound-intake-and-queueing/design.md#53-插队的核心原则)：
> 「系统应该要支持能够**单独地**：1）中断一次 tool execution；2）中断一次 llm response」。

**而[该落盘持久化的依然要落盘](../PF-009-context-message-types/design.md#56-流断在半路)**——
已经吐出来的那半句话**用户可能已经看见了**，
[抹掉它不叫干净，叫记录与事实对不上](../PF-012-agent-loop-and-run/design.md#52-会话日志是唯一的真相来源)。

#### 停机之后：能不能重来，只看首 token

此处先确认模型 runtime 自身已经失去连续性。只失去原 Agent runtime 或其句柄时，先查询原调用：仍运行就接续，已完成就取结果，不能套本节重发。

| | [run / agent-loop](../PF-012-agent-loop-and-run/design.md#57-一次尝试三条路通向重新算一遍) | [一次工具执行](../PF-006-tools-and-skills/design.md#612-工具执行的运行时可以被单独控制而它停了就不重来) | **一次模型调用** |
|---|---|---|---|
| 停机之后 | **重新算一遍** | **不重来**，落失败 | **看首 token 出没出来** |
| 为什么 | 它是纯函数的求值 | 它可能已经在外面做了事 | **首 token 之前它还没交出任何内容，重发不会造出第二份回复**；**之后不行——那半句话已经在记录里、用户可能已经看见** |

**所以这一层的停机恢复，与[「已经开口说话了」那一类](#已经开口说话了优先于其余各类)是同一条规则，不是两条：**

| 停在哪 | 恢复时算什么 |
|---|---|
| **首 token 之前** | **已确认原模型执行失联，这次调用没交出过回复。**在原调用的消费位置按恢复规则重新求值并可重发；主流程、拓展件、压缩与会话旁路分别接续自己的工作，不统一跳回 T1 |
| **首 token 之后** | **算[「说到一半断了」](#57-上交带什么原样带着状态码不翻译它)**：这次调用就此收场，**记下的原因是运行时失联**——不是用户叫停，也不是上游出错。与连接断在半路一样**一律不重发**——[一个逻辑回复只发一次](#已经开口说话了优先于其余各类) |

> **不统一这两处会怎样**：实现者为「崩溃恢复」单开一条路，
> 在那条路上**允许重发已经吐了半句的回复**——
> 于是记录里躺着两份回复，**而用户只看见过一份半**。

**「首 token 之前重发」保证的是回复只有一份，不是钱只花一次。**
请求到了上游、首 token 还没出来，**上游可能已经开始计费**；重发一次，**这笔钱可能记两次**。
两笔都是真花掉的，**照实记成成本**——[按尝试记明细、按 Run 汇总](../PF-012-agent-loop-and-run/design.md#成本两层缺哪一层都会算错)（[PF-012](../PF-012-agent-loop-and-run/README.md) rev 9）。
**这与[「账只记一次」](../PF-009-context-message-types/design.md#到达的过程有它自己的语法)不冲突**：那说的是一条流里记一次，这里是两次发出、两条流。
**一次调用的实际费用拿不到时**（失败了、被中断了、上游没给），明细里记「未知」——**不是零**，拿到了再补一条；
那一条即使在 Run 终结之后才到，也照样归那个 Run（[PF-012 §6.17](../PF-012-agent-loop-and-run/design.md#617-run-这一层的七条不变式)）。
**这条规则归本 topic**；成本明细本身按什么维度记、给谁看，归 [PF-001 §6.4](../PF-001-identity-scope-and-agent-constraints/design.md#64-隔离)。

**「停机」在这里同样不只是机器断电。**
**判据与[工具那一层一模一样](../PF-006-tools-and-skills/design.md#612-工具执行的运行时可以被单独控制而它停了就不重来)：
这个运行时与它所服务的那个会话失去了连续性。**

#### 它只有一个宿主，所以只有一种结局

**一次模型调用的生命周期归属只有会话，它最终记录一个真实收场；Agent runtime 不拥有它的生命周期。**Run 是调用工作的逻辑治理归属，发起尝试只是来源。主流程调用、拓展件调用、压缩摘要调用都按此处理；不属于任何 Run 的旁路调用直接归会话，成本也归会话。

Agent runtime 只持有该调用的[运行时句柄](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-runtime-handle--运行时句柄--runtime-handle)。发起者被回收、销毁或替换时句柄释放，模型请求本身继续运行；即使没有句柄持有者，也继续记录流式输出、结果、费用与失败。模型连接与在途输出不依赖原 Agent runtime 存活。

| 事件 | 模型调用的结果 |
|---|---|
| 仅释放／销毁 Agent runtime 或最后一个句柄 | 不取消、不重发；执行及输出连续性保持 |
| 新 Agent runtime 接手，原调用仍在运行 | 按原调用身份重新取得句柄，继续等待 |
| 新 Agent runtime 接手，原调用已经完成且结果尚未确认 | 读取原结果并承接，不重新请求模型 |
| 原调用结果已确认 | 查明确认及副本清理状态；后续使用由已承接结果的消费方负责，不再从模型侧重新领取完整结果 |
| 显式取消本次调用或其所属 Run | 中断目标调用；不影响其他 Run 或无 Run 归属的会话级调用 |
| 会话归档 | 中断该会话全部在途模型调用 |
| 模型 runtime 自身确实失去连续性 | 才适用本节首 token 前／后的恢复规则 |

主流程必须等待模型结果，但等待不要求持有句柄的 Agent runtime 一直活着，也不等于增加工具那种“转后台”收场。调用终止或失联之后的首 token 规则保持；单独释放 Agent runtime 不是模型 runtime 停机，不能据此收场、补中断提醒或重发。

本次实际采用的模型、请求输入及原调用归属不随接手者改写。模型切换或定义热重载只影响允许采用新输入的后续调用，不把已经在途的请求变成新请求；发起者已被取代不妨碍原调用结果写入。Run 仍等待该调用时由当前尝试消费；Run 已终结时留痕与记账，不使其复活。取消范围与结果接续归 [PF-012 §6.13](../PF-012-agent-loop-and-run/design.md#613-取消跟着宿主走)。

这些规则适用于每一次模型调用，不只主流程“想”的那一次。转换件不发起模型调用，仍沿其既定边界。

#### 这一层的非常态边界，也是两分的

**[与工具那一层同一条分法](../PF-006-tools-and-skills/design.md#这张表同时划出了这一层的非常态边界)：**

| | 什么 | 怎么走 |
|---|---|---|
| **本层了结得了的** | **[「其余全部」那一类里，策略说还值得再试的](#54-三类事实归本层定死其余照状态码)**——换一家、退避之后再来 | **本层自己消化**，[失败的尝试留痕、不进方程](#试过又失败的那几次留痕不进方程)，**不上交** |
| **本层了结不了的** | [三类事实](#54-三类事实归本层定死其余照状态码)，外加**试尽了**的那些 | **[上交](#55-上交交给谁看模型说没说出话)**，带[八个成因之一与状态码](#57-上交带什么原样带着状态码不翻译它)。**情形不必穷举，成因必须封闭** |

> **注意这一层的两分与工具那一层不是同一刀。**
> **工具那一层是「有没有一个说得清的收场」，这一层是「再试一次还救不救得回来」。**
> 两层的「了结得了」各有各的意思——**这正是[它们是两层而不是一层](../PF-011-off-nominal-handling/design.md#52-一层要声明四样)的原因**。

## 六、产品规则

### 6.1 档案是一个对象，那项设置的取值是对它的引用

**设置记的是路由名，但这个名字背后必须是一条档案**，不是一个无所指的字符串：
它在一条范围链上[恰好落到一条](#档案的身份所在范围加路由名)，「它看不看得了图」「它一次吃得下多少」都问那一条。
名字背后没有对象，这些问题**就没有地方可问**，而每一处要用它的地方都会自己猜一个答案。

**路由名一旦定下不可改**——改了就是另一条档案。
**不这么定**，历史里那条「当时用的是谁」的留痕会指向一个已经变了意思的名字。

**一条档案是哪一条，看所在范围加路由名**（[§4](#档案的身份所在范围加路由名)）：
同一个范围里一个路由名只有一条，不同范围里可以各有一条同名的。
**官方档案与自建档案同路由名，两条都建得成、都在，谁也不挡谁**——它们在不同的范围里。

### 6.2 凭据挂在范围上，档案自己不存

- **[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)是[租户](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-tenant--租户--tenant)身上的一项属性**，
  **一个租户一把**；这个租户发起的调用都用它，不管档案建在哪一层。
- **[组织](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-organization--组织--organization)那一层不持有凭据**：每个人在自己的租户层自取（[§5.6](#组织那一层为什么不持有)）。
- **它不是某份资产的[设置](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性)**——
  档案与凭据都不是资产。**身份即范围，轮换是改值，用量归这个租户。**
- **租户可以自带凭据**：配上自己的那一把，他的调用就从它出去。
- **自建档案自身不存凭据**，建在组织层的也一样。
- **官方档案不含凭据**；出厂默认那一格的那一把由部署装配时配好，产品里改不了它。
- **租户那一把可以换，也可以解绑**：解绑就是把这一项清空，此后这个租户的调用照「没配」处理。

**没有可用的凭据不阻止任何事的发生**，它表现为一次调用在[「还没出门」](#53-一次模型调用会在哪些位置偏离这是举例不是清单)
这个位置的非常态，成因是**凭据不可用**。

### 6.3 官方与自建在同一份列表里

**不是两份清单，也不是一份主列表加一个「自定义」抽屉。**

用户要的是「我现在能用哪些」，**而那个问题的答案只有一个**。
分成两份，他就得自己合并——**而他合并出来的那一份，与系统求值出来的可能不一样**。

**同一份列表里，每一条都标着来源**：

| 来源 | 列表上标什么 |
|---|---|
| 官方档案 | **官方** |
| 自建档案 | **自建**，外加**建在哪一层**——组织层还是租户层 |

**为什么非标不可**：[官方、组织层、租户层可以各有一条同路由名的档案，运行时按层覆盖](#档案的身份所在范围加路由名)。
不标，用户只看见一个熟悉的名字，**以为用的是官方那一条**——而这个名字此刻落到的那一条，走的供应商、窗口、请求参数可能都是组织或他自己另配的。

**被盖住的同名条目照列、带来源，并标「被某层同名档案覆盖」**；它们只作标注、选不了（[§5.10](#510-合法目标集合与展示列表是两件事)）。
**怎么呈现——排在胜出那一条下面、折起来还是别的——归交付面**（[PF-016](../PF-016-cli-tui-delivery-surface/README.md)）。

**来源是每一条上的一个标注，不是把列表分成几块的依据**——分块就回到了上面否掉的那两种做法。

### 6.4 撤回不删行；会话指向被撤回的档案时，说「已下架」

- **撤回是一个动作，不是删除。**档案的行**保留**。
- **已撤回的档案不能被新选中**，但**读得出来**。
- **已撤回的档案可以恢复在册。**恢复的还是原来那一条——同一个范围、同一个路由名；
  谁撤得了它，谁就恢复得了它。
- **「已下架」说的是一个名字，不是一行。**会话用的那个名字，在链上[同名的每一条都撤回了](#档案的身份所在范围加路由名)，才说「已下架」；
  最具体那一条撤回了、链上另有同名在册的一条，**调用照发，用那一条**，列表上撤回的那一条标「已下架」，外加「被某层同名档案覆盖」。
  **这不是替用户改选**：他选的是这个名字，名字没变；变的是这个名字落到哪一条，而那本来就按[层序](#档案的身份所在范围加路由名)定。
  撤回的那一条恢复在册，它又是最具体的那一条，这个名字落回它。

**行保留的理由有两条，都落在「那一条还是那一条」上**：

- 会话指着它的时候，**用户看到的是具名的「已下架」，而不是「未知模型」**；
- **上游把同一个模型重新上架，只能用同一个名字**——路由名是上游的，谁也改不了。
  撤回若是终态，这个名字在这个范围里就永久占住了，想再用它只能另起一条，**而另起一条根本起不出来**。
  恢复原来那一条，**还指着它的会话不用换就接得上**：它重新在册，只要这个范围允许、模态兼容，它就又是合法目标，下一次请求照常发出。

删行的代价是静默的：那条会话此后每次都在引用一个不存在的东西，
**而系统说不出它曾经是什么，也再恢复不了它**。

### 6.5 切换是用户的直接命令，合法目标不得拒绝

**用户选了一个[合法目标](#510-合法目标集合与展示列表是两件事)，切换就发生，没有第二种结果。**

**以下都不构成拒绝理由：**

| 不构成拒绝 | 为什么 |
|---|---|
| **目标窗口更小，历史可能装不下** | 那要到[下一次请求前量一量](#59-换模型一条事实一个生效点零个新分支)才知道，**而到那时走的是[已有的压缩判断](../PF-012-agent-loop-and-run/design.md#55-想这一步交进闭包拿回装得下的一份)** |
| **目标比当前这个「差」** | **那是用户的判断，不是系统的** |

**有两样东西看起来像拒绝，其实不是**——**它们根本不进合法目标集合**，
所以用户选不到，**也就谈不上拒绝**：

| | 依据 |
|---|---|
| **组织[锁死](../../ubiquitous_language/terms/scope-and-resolution.md#ul-immutable-marker--不可覆盖标记--immutable-marker)的那些** | [PF-001 / PF-002 的层级求值](../PF-002-assets-settings-and-permissions/design.md#54-默认与强制一个机制三处适用) |
| **[收不下会话里已有模态](#511-有-transcript-的块不再把任何模型挡在外面)的那些** | [§5.11](#511-有-transcript-的块不再把任何模型挡在外面)、[§6.18](#618-模态投影要答得快而且是增量维护出来的) |

> **「不得拒绝」与「它不在候选里」不矛盾，因为这条规则的前提就是「合法目标」。**

### 6.6 切换先是一条要被记录的事实

**不是一个当场改掉的开关。**

它落进[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)，
和别的[记录条目](../PF-000-occurrences-and-record-entries/design.md#记录条目)一视同仁：不可变、追加、查得到。

**不这么做，「这一轮为什么换了个口气」事后无从回答**——
而[会话日志是唯一的真相来源](../PF-012-agent-loop-and-run/design.md#52-会话日志是唯一的真相来源)。

### 6.7 生效点：收到那条事实之后、下一次模型请求之前

- **不打断正在进行的那一次调用。**它照常跑完。
- **下一次请求用新的。**

**打断的代价**：那一次已经花掉的钱白花，而且[已经交付出去的那部分还得收场](../PF-009-context-message-types/design.md#56-流断在半路)——
**用一次中断去换几秒钟的提前生效，不划算**。

### 6.8 不为切换新增分支

**[状态方程不变](../PF-012-agent-loop-and-run/design.md#agent-loop)。**
切换后的第一次请求**自然地走[已有的组装与压缩判断](../PF-012-agent-loop-and-run/design.md#55-想这一步交进闭包拿回装得下的一份)**，
**只是那次判断的输入换成了新模型的档案**。

> **没有新分支，也就没有新的失效点。**

### 6.9 合法目标算不出来时，不替用户改选

**出门之前核的是[有效模型](#选中模型-与-有效模型)。**它算得出来、又是[合法目标](#510-合法目标集合与展示列表是两件事)，请求就照常发出——
**上层锁死了另一条，有效模型就是锁定的那条，照常用它发出，不算失败**。

**只有有效模型算不出来、或算出来的那条不是合法目标时**——被撤回了、这个范围不再允许它、
或者[会话里新来了一种它收不下的模态](#511-有-transcript-的块不再把任何模型挡在外面)——
**系统不自动换一个顶上。**

这次请求就是一次非常态：成因是**已下架** / **这个范围不再允许** / **和会话里的模态对不上**，
**发不出去，立即上交**。

**依据**：[撤权管的是下一道准入](../../ubiquitous_language/terms/circulation-and-entitlement.md#ul-revocation-is-not-stop--撤销不等于强制停止--revocation-is-not-a-stop)，
而下一次请求就是下一道准入。

**自动顶替的代价**：用户以为自己在用 A，实际答话的是 B，
**而他没有任何办法发现**——[§7](#七取舍) 记着一个真实案例。

### 6.10 模态兼容挡在算合法目标那一刻，不挡在出门那一刻

**一个模型收得下的模态，必须覆盖这个会话[模态投影](#模态投影)里的全部模态，
它才是这个会话的[合法目标](#510-合法目标集合与展示列表是两件事)。**

- **判断落在[块](../PF-009-context-message-types/design.md#消息的内容是一串块不是一段文本)的形态上**，不落在消息上——
  同一条消息里各个块的形态可以不同。
- **文件块看它的媒体类型**：是一段视频、一张图，就按那种模态算；
  **媒体类型不属于四种模态的，不算**——它装的只是一个附件的**引用**，**任何模型都读得了**（[§4 模态](#模态)）。

**由此，「带着收不下的模态出门」这件事在正常路径上根本不会发生**（[§5.11](#511-有-transcript-的块不再把任何模型挡在外面)）。

**只剩两条路还能走到那儿，两条都有人负责：**

| 还能怎么走到 | 怎么办 |
|---|---|
| **会话里新来了一种当前模型收不下的模态** | 选中模型就此不再是合法目标，按 [§6.9](#69-合法目标算不出来时不替用户改选) 处置：**不替用户改选**，这次请求发不出去并上交，成因是**和会话里的模态对不上** |
| **一件挂在[「调模型之前」](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)的拓展件把有效模型换成了收不下的那个** | 同上处置。**而它[必须留下结论](../PF-012-agent-loop-and-run/design.md#610-能干预的拓展件必须留下结论)，所以查得出是谁干的** |

> **两条路的处置是同一条，这不是巧合**：两者都是「**选中/有效的那个此刻不合法**」，
> 而那件事 [§6.9](#69-合法目标算不出来时不替用户改选) 已经定完了。**不需要第二条规则。**

**「一张图超过档案声明的大小上限」不归这一条**——
那不是模态问题（同一个模型照样收图，只是这张太大），**模态投影答不了它**。
它是[组装读到那份档案之后自己处理的事](#八边界与依赖)。**本 topic 要求档案给出有限上限，且超限输入不得发出**；
具体怎么得到符合上限的表示，仍归组装与技术设计。

### 6.11 成因在这个边界上分类，不丢进外层按异常形态分

**一次模型调用的失败，由这一层自己认出来、自己归类。**

**不许**把它原样抛给外面，让外层按异常形态去猜——
前身踩过这个坑：**本地数据库故障被报成了 provider 不可达**，
而排查的人照着这个说法去查上游，**查了很久**。

这是 [PF-011「上层只认跨层通用的说法」](../PF-011-off-nominal-handling/design.md#65-上层只认跨层通用的说法)的另一面：
**上层不读下层的编码，前提是下层把自己的事认清楚了。**

### 6.12 事实判断归本 topic，策略归拓展件

**[四类](#54-三类事实归本层定死其余照状态码)各有各的下一步**，不得合并成「失败了就重试」。
**而它们分属两种性质，这条界线是本节的全部内容：**

| 性质 | 哪几类 | 归谁 | 为什么 |
|---|---|---|---|
| **事实** | 发不出去 · 重试没用 · **已经开口说话了** | **本 topic 定死** | 重试在**物理上没有意义**——请求没到上游、这次请求本身不行、话已经说出去了。**换一套策略也改不了这件事** |
| **策略** | **其余全部**（上游那边的事） | **[挂在「调模型之后 · 失败」的拓展件](#512-重试站在一个已经存在的位置上)**，**[照状态码判](#54-三类事实归本层定死其余照状态码)** | 「再试一次值不值」是一次**价值判断**，而它随部署、成本、上游状况而变 |

**「已经开口说话了」优先于其余各类，而且拓展件推翻不了它**——
[一个逻辑回复只发一次](#已经开口说话了优先于其余各类)是事实那一侧的。

**这四类管的全是[故障](#还有一种没走完它不在这张表里)。
用户主动中断一次回复，不是故障，不进这四类，也不带成因**——
与 [PF-006 那条](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)同构。

> **不写明这条界线，读者会以为整个失败处置都外包给拓展件了**——
> 于是一件写得不好的拓展件，可以让系统在已经吐了半句话之后再发一遍。

### 6.13 「试尽」由拓展件判定，档案的两项声明是它的输入

**本 topic 不写死重试次数，不承诺任何秒数，也不规定走哪一家。**

[试尽](#什么时候算试尽)是「这一层不再有可试的手段」这个**判断**，
而做这个判断的是[那件可替换的拓展件](#512-重试站在一个已经存在的位置上)。

**档案上那两项——「允许的供应商及次序」「允不允许回退」——是它的素材，不是它的公式。**

**这个位置上不会空着：[系统自带一件默认的](#系统自带一件默认的所以开箱就有重试)，租户可以把它换掉。**

### 6.14 上交带的成因是封闭枚举，外加一个诚实的兜底；状态码另外原样带着

**[八个取值](#57-上交带什么原样带着状态码不翻译它)**，其中一个是「没认出来」。

**兜底不许用来偷懒**：它的意思是「这次确实没认出来」，
**而且它出现时同样要留下可追溯的痕迹**。

**成因封闭，不等于信息被压扁**：
[上游返回的状态码原样带着](#57-上交带什么原样带着状态码不翻译它)，**本 topic 不把它翻译成第二套词**。
**成因回答「谁能了结」，状态码回答「上游到底怎么了」。**

### 6.15 上交条目的形状不在这里定

**[归 PF-011 §5.8](../PF-011-off-nominal-handling/design.md#58-上交交的是什么)，六条要求一条不改。**

本 topic 只定**交给谁**（[§5.5](#55-上交交给谁看模型说没说出话)）与**带什么成因**（[§5.7](#57-上交带什么原样带着状态码不翻译它)）。

**首 token 之后断的那一种不另立上交条目**——
[PF-009 那条中断提醒本身就是它](#55-上交交给谁看模型说没说出话)。

### 6.16 错误信息外泄之前要脱敏

**上游返回的原文里可能带着凭据**——鉴权头的片段、密钥的前几位、内部标识。

[PF-011 已经要求「写入那一刻完成脱敏」](../PF-011-off-nominal-handling/design.md#58-上交交的是什么)，
**而这一层是最容易违反它的地方**：上游的错误信息看起来只是一段文本，
**顺手原样带上去是最省事的写法**。

**条目不可变、[记录一条都不能擦除](../PF-010-context-management-and-assembly/design.md#612-记录里的消息一条都不能擦除)——
写错了就是永久的。**

**任何对外可见的面上都不得出现凭据**，也不得出现只有我们内部才有意义的标识。

### 6.17 本 topic 不出现任何时限数值

**「超时算多久」「退避等多久」是[策略](../PF-011-off-nominal-handling/design.md#八边界与依赖)，不是产品设计。**两样各有各的家：

| 时限 | 它是谁的设置 | 为什么在那儿 |
|---|---|---|
| **退避等多久** | **[那件重试拓展件](#512-重试站在一个已经存在的位置上)的配置**——[拓展件是第八类资产](../PF-002-assets-settings-and-permissions/design.md#loop-extension) | 等多久再试，是「再试值不值」这个判断的一部分，换一套策略就该跟着换 |
| **超时算多久**：发出之后多久等不到首 token、开口之后多久没有新内容就算停滞 | **运行时的设置项**，挂在 [Agent 定义](../PF-002-assets-settings-and-permissions/design.md#agent-definition)上 | 它决定的是「这一次算不算出事了」，出事之后才轮到重试挂件判断试不试；放进重试挂件，换掉挂件就连「什么算出事」一起换掉了 |

**两样都走[资产已有的那一套](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性)：各层配值、沿层级求值。
本 topic 不另造一处，也不定数值。**

### 6.18 模态投影要答得快，而且是增量维护出来的

**用户每打开一次模型列表，就要用它算一遍合法目标。**
一个跑了三个月的会话可能有几万条消息——**每次去扫一遍，列表就打不开了**。

**所以这条是产品规则，不是实现建议：**

> **「这个会话有没有出现过某种模态」必须是一个常数代价的问题**，
> **因而[模态投影](#模态投影)是被增量维护的一项事实，而不是一次算出来的查询。**

**但它仍然是投影，不是第二份权威**——
**从[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)重算一遍，必须得到同一个答案**。
做不到，它就成了一份会和日志对不上的状态，
**而[对不上的时候没人说得清哪份是真的](../PF-012-agent-loop-and-run/design.md#67-检测状态从日志派生不另存)**。

### 6.19 消费方确认结果后，清理模型侧不再需要的副本

**“确认该次模型调用结果已处理”（简称 ACK）是消费方的明确动作，不是新的产品对象。**它表示：消费方已经处理完这次调用的结果，或已经自行保存了后续使用所需的内容，模型侧不必继续为它保管可供重新消费的完整副本。ACK 不宣称结果已经成为会话消息，也不替消费方作出使用、持久化或否决结果的决定。

这件事与调用收场、费用结清、释放运行时句柄分别判断：**完整拿到回复只是有了可处理的结果；释放句柄只是持有者离开；ACK 才结束模型侧为后续消费保管副本的责任。**没有 ACK 时，完成、失败、零句柄、发起者退出或 Run 结束，都不能代替消费方确认。

#### 何时可以确认，谁可以确认

| 调用与消费的情况 | ACK 的结果 |
|---|---|
| 调用已真实收场；有权承接它的消费方已处理结果，或已自行保存后续使用所需内容 | 接受确认，开始清理不再需要的模型侧副本；不要求先写入正式 Session，也不要求所属 Run 结束 |
| 回复完整到达，但消费方既未处理、也未自行保存，仍在决定如何使用或持久化 | 不具备确认条件；模型侧继续保管，不能自动确认或替它丢弃 |
| 调用仍在执行、重试或接续原调用，结果尚未确定 | 明确拒绝提前确认；执行继续。需要停止执行时使用取消，之后仍按实际收场处理结果 |
| 调用已经以上交失败或被中断真实收场，消费方已处理相应结果 | 可以确认。将来允许另起调用，不是保留本次大副本的理由；ACK 不把失败改成成功，也不重新发送请求 |
| 一次发出失败，但本次调用仍在等待或执行重试决定 | 不能把某一次发出的失败当作整次调用结果确认；先按既有调用规则作出真实收场或继续执行 |

**确认资格来自这次调用的归属和承接责任。**只有在该调用所属租户内、具备该调用访问资格且当前负责承接其结果的消费方，可以代这次调用作出确认。只读观察者、拿到一个引用的人、已被替换而不再承担承接责任的旧消费方，都不能替当前消费方确认；跨租户确认不得生效。取得句柄不另授确认权限。

消费方需要向多个地方交付时，由它自己完成处理或保管后确认；**模型侧不收集所有曾经看过结果的人逐一同意**。当前真实读取另按下述清理条件保护，不把历史消费者名单变成无限等待条件。

#### 确认生效与清理完成分别可见

确认生效后，不再向新的消费者提供该调用完整结果的重新领取，也不再允许借原引用恢复执行或重新发送请求。确认之前已经开始的真实读取，不能因清理而只读到一半；读取完成或按既有访问规则明确结束后，不再阻止清理。仅持有一个闲置句柄不算仍在读取。

**模型侧必须清理已无用途的创建输入与结果副本，以及只为这些副本保留的引用。**不提供“已经 ACK，但默认永久保留完整副本”的模式。消费方自行持有的内容、已形成的不可变记录和其他调用的内容不属于这次清理范围；多个调用仍需要的内容不能因其中一次 ACK 而消失。

| 可观察结果 | 它说明什么 |
|---|---|
| 尚未确认 | 消费责任尚未交接；不能报告已清理 |
| 已确认，仍待清理 | 后续消费已经交给消费方，但仍有真实读取、在途写入、尚未确认的写入结果，或清理故障需要处理；应说明原因及谁负责继续处理 |
| 已确认，模型侧副本已释放 | 本次应清理的模型副本已经清理；不表示调用历史、消费方自己的内容或费用事实被删除 |
| 确认结果暂时无法判明 | 调用方可以按原调用查询或重复确认；不能把不确定报告成确认失败、清理成功或重新发起模型请求 |

确认一旦生效不因清理失败退回未确认。模型侧承担后续清理责任，故障解除或真实在途工作收口后继续完成，不要求原消费方始终在线或再次确认。等待必须指向仍实际需要保护的工作；仅凭曾经有读者、句柄没有逐个释放、所属 Run 尚未结束，不能阻止清理。不能证明已结束的在途工作必须如实保留责任，也不能把已经失去访问能力的旧持有者写成必须回来同意的人。

#### 真实结果与账不随副本消失

ACK 和清理都不得修改成功、失败、中断、已发送或未发送的事实，不得抹掉已形成的记录，不得把结果确认解释成“已成为会话消息”。结果由消费方自行保存时，后续是否成为消息及如何处理，仍由原有规则和真实处置决定。

**未知费用仍是未知，不是零；迟到的真实费用仍归原调用及原来的 Run 或会话。**模型侧必须保留完成这一责任所必需的信息；重复确认、重试清理、恢复清理和迟到回执都不能造成重复计费。若费用责任已能独立延续，不得仅以费用尚未知为由扣住无关的完整输入与结果副本；若某份内容仍是正确记账所必需的，就明确保留那部分责任，不能先声称全部释放。

同一次调用的确认可重复：得到原确认及当前清理状态，不重新消费、不重新执行、不再收费，也不复活已释放的副本。对仍有权查询的旧引用，系统必须明确表示“已确认”或“模型侧副本已释放”；**不能把真实存在过的调用伪装成从未找到**，也不承诺确认后还能从模型侧取回完整输入或结果。原来的租户与访问边界仍适用。

## 七、取舍

| 面临的选择 | 选了 | 为什么 / 代价 |
|---|---|---|
| 档案做成**一个对象** ／ 一个名字 | **对象** | 名字做不到：模态、窗口、路由**没有地方挂**，每一处要用的地方都自己猜一个。**代价**：多一个要维护的对象，官方档案要随上游变化更新 |
| **留九点能力评分** ／ 不留 | **不留** | 前身自陈它**零消费者，只记录与发布**。留着的代价不是存储，是**每加一个模型就有人去填九个没人读的格子**——而填错了没人发现，因为没人读。**代价**：将来真要按能力挑模型，得重新设计一套；**而那时它会有消费者** |
| 凭据挂在**范围**上 ／ 挂在每条档案上 | **范围** | 每个租户填一次、轮换只改一处、脱敏面只有一处。**代价**：**做不到「这个模型走另一个账号」**；一个租户调的所有档案的用量都记在同一把凭据上，**上游账单分不到单条档案** |
| 凭据**每人在租户层自取** ／ **组织持有一把、供成员共用** | **每人自取** | 组织那一把得发到每个成员的机器上，**人离职时收不回**；需要续期的凭据还要在许多台机器上各自续期。**代价**：每个成员都得自己配一把，组织给不出一个大家共用的账号；**组织层建的自建档案，成员配上自己那一把之前用不上** |
| 档案的身份是**所在范围加路由名** ／ 只按路由名 | **所在范围加路由名** | 路由名是上游的名字，谁都改不了；只按路由名，官方档案与自建档案、组织与租户的同名档案必有一方建不进来，**被挡的那一方连换个名字都做不到**。**代价**：同一个路由名在列表上可能不止一行，所以每一条都要标来源 |
| 同路由名的几条档案：**运行时按层覆盖** ／ **由用户在其中挑** | **按层覆盖**（租户 > 组织 > 官方，先滤已撤回与范围不允许的） | 为同一个上游模型另建一条，就是在替换外层那一条的调法，与资产的同标识替换是一回事；由人挑，每个会话都得自己决定用谁的配置，同一个名字排几行、长得一样。**代价**：组织建了与官方同名的一条，成员就用不到官方那一条，没配自己凭据的成员这个名字用不了；**组织锁得住名字，锁不住它落到哪一条**——成员自建一条同名的就换了实现；列表上被盖住的也得照列、标出来 |
| 已撤回的档案**可以恢复在册** ／ 撤回是终态、再上架另起一条 | **可以恢复** | 上游把同一个模型重新上架，只能是同一个名字——撤回若是终态，这个名字在这个范围里就永久占住了。恢复原来那一条，**指着它的会话不用换就接得上**。**代价**：「已下架」不等于永远用不了——一个停在已下架档案上的会话，哪天它又回来了 |
| **重试是一件可替换的拓展件** ／ 把重试规则写死在产品正文里 | **拓展件** | 写死就是把一次**价值判断**（再试值不值）当成产品承诺；而它随部署、成本、上游状况而变。**而且位置是现成的**——[PF-012「调模型之后 · 失败」那一格原本就写着「失败分档」](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)，**这次省掉了一次[架构内核](../architecture-core.md)改动**。**代价**：**开箱行为取决于挂了什么**，所以[系统自带一件默认的](#系统自带一件默认的所以开箱就有重试)——多一件要维护、要解释的东西，**用户想换掉它之前得先知道有它在**；读者还要分得清哪几类是事实、哪几类是策略 |
| **事实判断留在本 topic** ／ 连同一起交给拓展件 | **留下** | 全交出去，一件写得不好的拓展件就能让系统在已经吐了半句话之后再发一遍。**代价**：那条界线要讲清楚，读者多一层要理解的东西 |
| **首 token 之后一律不重试** ／ 尽量救回来 | **不重试** | 救回来的代价是记录里躺着两份回复，**而用户只看见过一份半**。**代价**：一次本来可能自动恢复的断流，变成一次上交；用户得自己再说一遍 |
| **按「重试有没有用」分类** ／ 按上游返回什么分类 | **按处置差异** | 上游改状态码、加新错误是常态，**而这套分类一个字不用动**。**代价**：归类要多想一步，不能照着错误码查表 |
| **成因封闭枚举 + 兜底** ／ 开放字符串 | **封闭 + 兜底** | 开放字符串让接手的那一层没法穷举处理，只能去猜。**代价**：兜底会**吸收掉本该具名的新情形**，要靠痕迹去发现它变多了 |
| **合法目标不得拒绝** ／ 切换时逐条校验再决定放不放行 | **不得拒绝** | 「校验之后拒绝」等于系统替用户否决他的选择；而**窗口装不装得下要到下一次请求量完才知道**，在切换那一刻判它，与[生效点](#67-生效点收到那条事实之后下一次模型请求之前)矛盾。**代价**：用户可以切到一个装不下历史的模型，**而代价要到下一次请求才显形**（走[已有的压缩判断](../PF-012-agent-loop-and-run/design.md#55-想这一步交进闭包拿回装得下的一份)） |
| **模态不兼容的不进候选** ／ 让它可选、到请求时再失败 | **不进候选** | 让它可选，就复现了调研里那类投诉：**带过图的会话切过去之后像是卡死了**，每条新消息都失败而用户不知道该怎么办。挡在候选那一刻，**用户当场就看得见为什么**。**代价**：**模态投影只增不减，所以一个长会话发过一次图之后，可选模型永久变少**——想回到全集只能开新会话；而且这个判断[必须是常数代价的](#618-模态投影要答得快而且是增量维护出来的)，**投影因此得被增量维护，而不是随手算一遍** |
| **不替用户自动改选** ／ 选中的不可用时自动顶一个 | **不改选** | 自动顶替是**静默地换掉用户的选择**。**代价**：选中的模型一旦不可用，**每一次请求都失败，直到用户自己换** |
| **撤回保留行** ／ 删掉 | **保留** | 会话指着它时说得出「**已下架**」而不是「未知模型」；**行还在，撤回才恢复得了**。**代价**：档案表只增不减 |
| **不为切换新增分支** ／ 切换时专门处理一次 | **不新增** | 专门分支**只有切换才跑得到**，此后单独维护，而它平时根本不跑。**代价**：切换的后果**要到下一次请求才看得见**，用户可能觉得「我切了但好像没变」 |
| **转换件的产出挂在原块上** ／ 就地改写块上的文本 ／ 新增一批块 | **挂在原块上：一组派生表示 + 一段 transcript** | 就地改写只容得下文本一种产出，**一段视频转出的几张关键帧就没处放**；新增块会让同一份内容在消息里出现两次，**组装时得先猜哪几块是同一个东西**。挂在原块上，原件不动、换个收得下的模型照样用原件。**代价**：一个块上多了两样东西要解释，**组装要多一步挑选** |
| **转换失败，这条消息不落盘；输入被拒、模型回复那次调用结束并由 loop 另起新调用、工具结果让 Run 失败** ／ 落盘、只是没有 transcript | **不落盘，也不补偿** | 落盘的话，一次偶发的转换故障就会**永久**缩小这个会话的可选模型——[模态投影只增不减](#模态投影)。不落盘，用户当场知道、当场重发。**代价**：**转换件坏了，用户连发给一个本来读得了原图的模型都发不出去**——它不知道当前用哪个模型，[也不该知道](#转换件)；**工具交回的结果转不成，那次已经做完的执行的结果就丢了，Run 失败**——我们没有补偿机制，不做复杂 |
| **每一次发出只走一家，换家由重试挂件做** ／ 让上游在一次请求里按次序自己换 | **只走一家** | 上游替我们换，换过几家、每家回了什么，**在我们这边都只是一次请求**——[留痕](#试过又失败的那几次留痕不进方程)与[「已经试过哪些」](#它看得到什么)都拿不到。**代价**：每换一家多一个来回，**慢一点** |
| **模型回复在落盘前被否决时退避重试** ／ 照「已经开口说话了」一律不重试、直接失败 | **那次调用照常结束，loop 退避之后另起新调用；同一步连续被否决到上限 Run 失败** | 产品负责人的裁决：模型回复这边值得再试一次，而那一份没成为消息，记录里不会有两份回复。**另起一次新调用**，而不是让同一次调用回到在途：这样「开口之后不回在途」照旧没有例外，重试挂件也只管故障这一维。**代价**：**用户看着一份回复吐完，随后又看到另一份**；工具结果没有这条路——**再跑一次工具，外面的事可能又做一遍** |
| **转换件本版不升为资产** ／ 现在就做成资产 | **不升** | 产品负责人的裁决：可替换这件事先有，资产身份（持有、分享、按层求值）**将来再考虑**。**代价**：它能换，但**只在系统装配那一层换**——组织与租户本版换不了；要按范围换，就是升资产（[转换件](#转换件)） |
| **选中模型与有效模型分成两个词** ／ 一个「当前模型」 | **两个词** | 见下 |

**最后一条有一个真实的反面案例，而它不是孤例。**

2025–2026 年间，多家面向终端用户的模型产品出现过同一种投诉：
**界面上显示的模型，与实际答话的模型不是同一个，而用户没有任何办法知道**。
用户反对的不是「系统会改路由」这件事本身，**而是不被告知、也无法留在自己选的那个上**。

> **这是产品调研观察到的事实，不是拍板依据**——来源随本次起草一并交付，
> **不进 [decisions.md](design.md) 的拍板记录**。

> **前身靠命名防住了这个错**：那个字段叫「**是不是被选中的那个**」，
> 而不是「**是不是当前的那个**」——**因为后者会被读成「此刻实际生效的那个」，
> 而那是[四层求值的答案](#选中模型-与-有效模型)。**

**代价**：多一个概念要解释，界面上也得说清楚「你选的」和「这次用的」可能不一样。
**但那个不一样本来就存在**——不说，它只是看不见。

## 九、未决项

**这一章只放真的还没想清楚的事。**结论已经有了、只是在别处的，一律归 [§八](#八边界与依赖)。

> **不是所有「没有答案」的地方都是产品未决项。**判据是[该区红线那一条](../AGENTS.md#红线)：
> **这条内容产品负责人能看懂并判断对错吗？**能，才是产品的事；
> 不能，它归技术设计，**这里指路就够了**（[§8](#八边界与依赖)）。
> 挂一个未决上去，会让后来者以为产品欠了一个决定——**而那个决定根本不在产品这一层**。

### 9.1 一处需要上游回补：工具能产出哪些块

**这不是本 topic 的缺口，是它依赖的那一侧还没说出口的话。本 topic 只标，不去改它。**

[PF-009 定了工具结果块「自己又是一串块」](../PF-009-context-message-types/design.md#消息的内容是一串块不是一段文本)，
所以**一次工具执行可以产出图**。

| 问题 | 归谁 | 为什么它对本 topic 要紧 |
|---|---|---|
| **工具能产出哪些块** | [PF-006](../PF-006-tools-and-skills/README.md) | 不知道能产出什么，就不知道[模态投影](#模态投影)会被推到哪一步 |
| **工具产出的图，算不算进这个会话的模态投影** | [PF-006](../PF-006-tools-and-skills/README.md) / [PF-009](../PF-009-context-message-types/README.md) | **算，那么一次工具执行就可能让一批模型当场不再是[合法目标](#510-合法目标集合与展示列表是两件事)**——而用户没做任何事 |
