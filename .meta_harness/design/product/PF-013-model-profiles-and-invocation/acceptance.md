# PF-013 验收标准

> **产品视角的验收**：用户看到什么、能做什么、做错时发生什么。
> 判断一条写得好不好——**把它交给一个不懂实现的人，他能照着判断产品对不对吗？**

---

## 一、可观察的场景

### 档案与凭据

| # | 场景 | 通过的样子 |
|---|---|---|
| **S1** | 组织超管建了一条自建档案，租户也建了一条 | **用户看到的是一份列表**，官方的和这两条在一起，**没有「自定义」抽屉**；**每一条标着来源**——官方，或自建（组织层 / 租户层） |
| **S2** | 租户换了自己那把 OpenRouter 凭据 | **只改一处**，他调的每一条档案——官方的、组织层建的、他自己建的——都跟着换。**没有一条档案里存着旧的那把** |
| **S2b** | 组织超管想在组织层配一把凭据给全员用 | **没有这个操作**——组织那一层不持有凭据；组织层建的自建档案，成员调它用的是各自租户那一把 |
| **S2c** | 组织层建了一条自建档案，某个成员还没配自己那把凭据 | 那条档案**在他的列表里可选**，但**标明「现在用不了 · 缺的是你自己的凭据」**；真去用，这一轮的成因是**凭据不可用**。另一个配了自己那把的成员，照常用得上 |
| **S3** | 一个租户没配自己的凭据，而他看得见自建档案（自己建的或组织层建的） | 那些档案**在列表里可选**，但**标明「现在用不了 + 缺什么」**；真去用，这一轮的成因是**凭据不可用** |
| **S4** | 问「这个模型看不看得了图」 | **答得出来**——它是档案上的一项事实，不是某处代码里的猜测 |
| **S5** | 官方档案 | **它里面没有凭据**。翻遍产品对象也找不到一把属于它的 |
| **S5b** | 调一条官方档案，而调用方的租户没有自己的凭据 | 出门用的是**出厂默认那一格的那一把**——部署装配时配好的；**产品里找不到任何一处能改它、换它、解绑它** |
| **S5c** | 租户解绑了自己那把凭据 | 这一项清空；此后这个租户的调用照「没配」处理，成因是**凭据不可用** |
| **S5d** | 组织超管修订一条自建档案的窗口 | **改得了**；想改它的路由名——**改不了**，只能另建一条、撤回旧的 |
| **S5e** | 配凭据的人回头去看他配的那一把 | 看得到**有没有、是哪个范围的、什么时候配的**；**看不到值本身**，哪一面都没有 |
| **S5f** | 某组织在组织层建了一条自建档案，路由名与一条官方档案相同 | **建得成**，两条都在；列表里**并排出现、各标来源**——一条「官方」、一条「自建 · 组织层」；选哪条，用的就是哪条 |
| **S5g** | 同一个组织在组织层、某个成员在租户层，各建一条同路由名的 | **两条都建得成**，列表里各标「自建 · 组织层」「自建 · 租户层」 |
| **S5h** | 在一个范围里再建一条档案，路由名与这个范围里一条**已撤回**的相同 | **不另起一条**——那就是原来那一条；把它**恢复在册**，需要的话再修订它 |
| **S5i** | 在一个范围里再建一条档案，路由名与这个范围里一条**在册**的相同 | **建不成**——同一个范围里一个路由名只有一条 |

### 切换

| # | 场景 | 通过的样子 |
|---|---|---|
| **S6** | 用户选了一个合法目标，哪怕它更弱、窗口更小 | **切换成功。**没有任何一条路径能让系统说「不行」 |
| **S7** | 切换之后，正在进行的那次调用 | **照常跑完**，用的还是旧档案；**下一次**请求才用新的 |
| **S8** | 切换到一个窗口小得多的模型 | 下一次请求**走的是[已有的组装与压缩判断](../PF-012-agent-loop-and-run/design.md#55-想这一步交进闭包拿回装得下的一份)**——**找不到一段只有切换才会走到的逻辑** |
| **S9** | 组织把某条档案锁死了 | 被锁掉的**根本不在可选项里**。用户选不到它，**也就没有「被拒绝」这回事** |
| **S10** | 用户当前选中的模型被下架了 | **它仍然显示在列表里，标着「已下架」**；下一次请求诚实地失败，**系统没有偷偷换一个顶上** |
| **S10b** | 另一条档案也下架了，但用户没选它 | **它不在列表里**——展示列表只是合法目标加上当前选中的那一条 |
| **S10c** | 用户选中了 B，之后组织把「用哪个模型」锁死成 A | 下一次请求**照常发出，用的是 A**——不算失败；列表上看得出**选的是 B、这次用的是 A** |
| **S10d** | 用户选中的那条档案被撤回，他没换；之后那条档案**恢复在册** | 列表上「已下架」的标注**消失**；下一次请求**照常用它发出**（这个范围允许、模态兼容的话）——**用户什么都不用做** |
| **S11** | 事后问「刚才那句话是哪个模型说的」 | **答得出来**，而且**不是「你现在选的那个」**——它是当时那次请求的留痕 |

### 模态

| # | 场景 | 通过的样子 |
|---|---|---|
| **S26** | 会话里发过一张图，**而「图」这个键上没有登记转换件**，用户打开模型列表 | **看不了图的那些不在可选之列**；当前选中的若正是其中一条，它留在列表上并**说得出「它读不了这个会话里的图」** |
| **S26b** | 同上，但那张图**被[转换件](design.md#转换件)配上了 transcript** | **一个模型都没被挤出去**——[有 transcript 的块不挡任何模型](design.md#511-有-transcript-的块不再把任何模型挡在外面)；而用户**看得出这次模型读到的是转出来的那一份，不是原图**——那条消息的呈现上标着「本次模型读到的是转换后的文本」（[PF-016 §6.21](../PF-016-cli-tui-delivery-surface/design.md#621-被转换过的消息呈现上说得出模型读的是哪一份)） |
| **S26c** | 同上，但那件转换件**转失败了** | **那条消息没进会话**，用户当场被告知没发进去；**模态投影与可选模型一个都没变** |
| **S26f** | 模型回了一张图，而「图」上的转换件**转失败了** | 那份回复**没成为消息**；**那次调用照常结束**，记下被转换件否决——**记录里没有一条「模型调用失败」**；loop **退避之后另起一次新的调用**；同一步里一次次被否决到上限，**这个 Run 失败**，原因指向转换件与那个块 |
| **S26h** | 一块只给人看、不给模型看的图，所在键上没有转换件 | **一个模型都没被挤出去**——模态投影只算给模型看的块；转换件也不转它 |
| **S26i** | 一个装着图片的文件块，「图」这个键与这个媒体类型的键上都登记了转换件 | **只有媒体类型那一件来转**，这个块只挂一份派生表示与一段 transcript |
| **S26g** | 一个工具交回一张图，而转换件**转失败了** | **这个 Run 失败**，原因指向转换件与那个块；**会话里没有一个没 transcript 的图块** |
| **S26d** | 把「图」这个键上的转换件换成另一件 | **换得掉，而且那个键上只有新的那一件在跑**；已经落盘的块上的派生表示与 transcript **一个字不变** |
| **S26e** | 事后翻记录，看那张转换过的图 | **原图原样在**；转出来的几份与 transcript **挂在同一个块上**，没有多出一个块 |
| **S27** | 同上，会话里有三万条消息 | **列表照样立刻打得开**——这个判断[不许去扫一遍会话历史](design.md#618-模态投影要答得快而且是增量维护出来的) |
| **S28** | 用户正用一个纯文本模型，然后发了一张**没有转换件可转**的图 | 那张图**照样落进记录**；**选中模型就此不再是合法目标**；下一次请求失败，成因具名为**和会话里的模态对不上** |
| **S29** | 同上，用户去问该怎么办 | 他被告知**换一个读得了图的，或者开新会话**——**不是「去找管理员」** |
| **S30** | 把会话日志重放一遍，重算模态投影 | **得到与增量维护出来的那份完全相同的结果** |
| **S31** | 会话里只有文本和一个[文件块](design.md#模态)，**它的媒体类型是一份文档** | **纯文本模型照样可选**——文件不是一种模态，这个文件块只是一个引用 |
| **S31b** | 会话里来了一段视频，**它装在文件块里**，而「视频」这个键上没有登记转换件 | **收不下视频的模型不可选**——[文件块的模态看它的媒体类型](design.md#模态)；**块清单里找不到一个「视频块」** |

### 一次调用出事

| # | 场景 | 通过的样子 |
|---|---|---|
| **S12** | 挂着一件重试拓展件，档案声明了三家、允许回退，第一家连不上 | **按那件拓展件说的办**；用户只觉得慢了一点，agent **不知道**换过 |
| **S13** | 那件拓展件说「不再试了」 | **上交**，成因是**上游这会儿给不出回复**，**外加上游那个状态码原样带着**；**不再有下一次尝试** |
| **S13b** | 租户一件重试拓展件都没挂 | **照样有重试**——[系统自带的那一件在跑](design.md#系统自带一件默认的所以开箱就有重试)，按档案声明的供应商次序办，**只在那条档案允许回退时才换一家**，每家至多试一次 |
| **S13c** | 同上，而那条档案不许回退，第一家连不上 | **同一家退避之后再试一次**；还不行就试尽、上交——**不会换家，也不会一直试下去** |
| **S14** | 把那件重试拓展件整个换成另一种策略 | **换得掉**——它挂在 [PF-012 已有的那个位置](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)上，**而本 topic 没有为重试新增任何位置** |
| **S15** | 凭据被上游拒了，而挂着的拓展件说「再试一次」 | **不试。**[那是事实判断，拓展件改不了](design.md#612-事实判断归本-topic策略归拓展件)，立即上交，成因是**凭据不可用** |
| **S16** | 模型已经吐了半句话，然后连接断了 | **那半句还在用户屏幕上，也在记录里**；**没有第二份回复被生成出来** |
| **S17** | 同上，而成因看起来像「换一家就好」的那种，且挂着的拓展件想重试 | **照样不重试**——[「已经开口说话了」优先，且拓展件推翻不了它](design.md#已经开口说话了优先于其余各类) |
| **S17b** | 模型只吐了半截工具调用的参数，一个字的文本都没有，然后断了 | **算已经开口说话了，不重发**——[首 token 是交出的第一样内容，不论模态](design.md#已经开口说话了优先于其余各类) |
| **S17c** | 响应头到了，一样内容都还没交出来，然后断了 | **还没开口**，照「其余全部」由策略定试不试 |
| **S17e** | 模型先吐了一小段语音，一个字的文本都没有，然后断了 | **算已经开口说话了，不重发**——语音能一点点长，第一片到了就算 |
| **S17f** | 模型先整张交出了一张图，然后断了 | **算已经开口说话了，不重发** |
| **S17g** | 模型开了一个图块的口，图还没交出来，然后断了 | **还没开口**，照「其余全部」由策略定试不试——整交的块交出来才算 |
| **S17d** | 首 token 之前停了机，恢复后重发了一次 | **回复只有一份**；**两次发出的费用都在成本明细里**，拿不到实际费用的那一次记「未知」 |
| **S18** | 模型一个字都没出来就彻底失败了 | 上交**直接到运行那一层**，**没有卡在一个此刻没有人的位置上** |
| **S19** | 上游返回了一种我们从没见过的错误 | **试不试照「其余全部」由重试挂件定**；试尽了上交，**成因是「没认出来」**，状态码原样带着，并留下可追溯的痕迹；**分类表一个字都不用改** |
| **S19b** | 首 token 已经出来，然后据点停机了 | 恢复之后**不重发**；这次调用算**说到一半断了**，原因记为**运行时失联**——不是用户中断，也不是上游出错 |
| **S19c** | 压缩闭包里生成摘要的那次模型调用，首 token 之后断了 | **与主流程那次一样不重发**——本 topic 的调用规则对每一次模型调用都成立 |
| **S20** | 换了三家、失败两次之后成功了 | 那两次**留痕，一家一条**——[每一次发出只走一家](design.md#试过又失败的那几次留痕不进方程)；**它们不进模型的上下文，也不改变下一步** |
| **S20b** | 事后问「这次调用试过哪几家」 | **答得出每一家**，以及各自回了什么状态码——**没有哪一次是在一个请求里悄悄换过的** |
| **S21** | 模型撞上输出上限被截断 | **不算这一层的非常态**——一条完整的消息 + 一条提醒（[PF-009](../PF-009-context-message-types/design.md#56-流断在半路)） |
| **S22** | 上游的错误信息里带着凭据片段 | **任何对外可见的面上都搜不到它**——见 [§三](#三判据) 的哨兵办法 |

### 中断

| # | 场景 | 通过的样子 |
|---|---|---|
| **S23** | 用户对正在进行的回复插一句话 | 这次调用**被中断**，loop 尽快走到下一次消费输入的那个点 |
| **S24** | 同上，事后翻记录 | **看不到任何一条「模型调用失败」**——[被中断不是故障](design.md#还有一种没走完它不在这张表里)，不带成因 |
| **S25** | 同上，已经吐出来的那部分 | **照样在记录里**（规矩归 [PF-009](../PF-009-context-message-types/design.md#56-流断在半路)） |

## 二、绝不能发生的事

| 绝不能 | 如果发生了意味着什么 |
|---|---|
| **界面上显示的模型，与实际答话的模型不是同一个，而没有任何地方查得出来** | 用户为一个他没选的模型的输出买单，**而他连发现都发现不了**。这是[本 topic 最贵的那个错](design.md#七取舍) |
| **选中的模型不可用时，系统自动换一个顶上** | 同上，只是换了个触发方式——**静默地推翻了用户的选择** |
| **拒绝一次合法目标的切换** | 系统替用户否决了他的判断。「这个模型更差」**不是系统的判断** |
| **首 token 之后还重试** | 记录里躺着两份回复，**而用户只看见过一份半**。这个错查起来极贵——**两份都是「合法」的** |
| **把响应头或整交块的开口当成首 token，或者只认某几种模态** | 前者关掉了本来能重发的窗口；后者让先吐了半截工具调用、一段语音或一张图的回复被重发 |
| **转换件转失败了，那条消息照样落盘**（不管是输入、模型回复还是工具结果） | 一次偶发的转换故障就**永久**缩小了这个会话的可选模型，**而用户根本不知道发生过什么** |
| **转换件把原块改了，或者把产出另作一批块塞进消息** | 原件没了，换个收得下的模型也读不回原图；或者同一份内容在消息里出现两次 |
| **拿不到实际费用时把那一次记成零** | 「没花钱」与「不知道花了多少」从此分不开，**账对不上也查不出** |
| **把用户的一次中断登记成一次模型调用失败** | 用户每插一次队，账上就多一条故障。**失败率从此不可信**，而真正的故障淹没在里面 |
| **算一次合法目标要去扫一遍会话历史** | 一个跑了三个月的会话，**模型列表就打不开了**；而用户每次挑模型都要用它一次 |
| **模态投影和会话日志对不上** | 它就成了第二份权威，**而[对不上的时候没人说得清哪份是真的](../PF-012-agent-loop-and-run/design.md#67-检测状态从日志派生不另存)** |
| **让一个读不了会话里已有模态的模型出现在可选项里** | 用户切过去，**然后这个会话每条新消息都失败**——他不知道为什么，也不知道该怎么办。**这是同类产品上真实发生过的事** |
| **一件重试拓展件能让系统在已经吐了半句话之后再发一遍** | [事实与策略的界线破了](design.md#612-事实判断归本-topic策略归拓展件)，**记录里会躺着两份回复** |
| **为重试新增一个拓展点** | [位置由状态点推出](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)，凭空多一个就等于改了 PF-012 的模型——**而现成的位置本来就在那儿** |
| **一条自建档案里存着凭据** | 轮换时要逐条改，漏一条就是一条静默失效的档案；**脱敏面从一处变成 N 处** |
| **组织那一层有一把凭据，被成员的调用用上了** | 那一把得发到每个成员的机器上，**人离职时收不回**——[正是被排除的做法](design.md#组织那一层为什么不持有) |
| **同路由名的几条档案在列表上长得一样，看不出各自的来源** | 用户挑中了哪一条自己都说不清，**而它们走的供应商、窗口、请求参数都可能不同** |
| **一个自建档案因为与官方档案同路由名而建不进来** | 路由名是上游的，被挡的一方连换个名字都做不到——[身份是所在范围加路由名](design.md#档案的身份所在范围加路由名)，两者本来不相撞 |
| **凭据、内部标识出现在任何对外可见的面上** | 条目不可变、[记录一条都不能擦除](../PF-010-context-management-and-assembly/design.md#612-记录里的消息一条都不能擦除)——**写错了就是永久的** |
| **撤回一条档案时把行删掉** | 会话指着它的用户看到「未知模型」，**而我们明明知道那是什么**；这条档案也**再恢复不了** |
| **本 topic 里出现一张「这一层的非常态有哪些种」的封闭清单** | 那是退回穷举，而[穷举表列出来的第二天就过期](../PF-011-off-nominal-handling/design.md#57-这不是一张清单是一个判断) |
| **成因按上游返回什么码来分** | 上游改一个码，我们的处置当场错位；**而错位是静默的** |
| **把本地的故障报成「上游这会儿给不出回复」** | 排查的人照着这个说法去查上游，**查很久**。前身真的踩过 |
| **在 agent loop 里长出一段只有切换才会走到的逻辑** | 那段逻辑平时不跑，**出错也没人发现**；[状态方程不变](design.md#68-不为切换新增分支)这条当场作废 |
| **为切换新增一个状态点或一个拓展点** | [位置由状态点推出](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)，凭空多一个就等于改了 PF-012 的模型 |
| **重试的留痕进了模型的上下文** | agent 拿「我们换过三家供应商」做不出任何判断，**白占预算** |
| **本 topic 里出现第二份上交条目的形状定义** | [那归 PF-011 §5.8](../PF-011-off-nominal-handling/design.md#58-上交交的是什么)。**两份定义必然分叉** |
| **本 topic 里出现任何秒数** | [时限是策略](design.md#617-本-topic-不出现任何时限数值)。写进产品设计，它就会被当成承诺 |
| **首 token 之后断了，还另立一条上交条目** | 同一次断流在记录里登记两处，**而[两份登记必然分叉](design.md#55-上交交给谁看模型说没说出话)** |

## 三、判据

**怎么算这块设计站得住：**

1. **把上游的错误码词表整个换掉，这一层的[四类处置](design.md#54-三类事实归本层定死其余照状态码)输出不变。**
   变了，说明分类是照着上游的码做的，**而那份码会变**。
   （这是 [PF-011 §6.5 那条验收办法](../PF-011-off-nominal-handling/design.md#65-上层只认跨层通用的说法)在这一层的落点。）
2. **随便拿一种新出现的失败情形，两个互不通气的人归出同一类。**
   归不一致的那一种，说明**判据还有洞**，不是那两个人的问题。
3. **拿一把带哨兵串的凭据跑一遍**——把整个流程跑到失败，
   **任何用户看得到、记录里留得下、对外发得出去的面上，都搜不到那个哨兵串**。
   搜得到，就是 [§6.16](design.md#616-错误信息外泄之前要脱敏) 没做到。
4. **把那件重试拓展件整个换掉，本 topic 的产品规则一条都不用改。**
   要改，说明[策略和事实混在一起了](design.md#612-事实判断归本-topic策略归拓展件)。
   **反过来也要成立**：拓展件怎么写，都动不了「首 token 之后不重试」和那三类事实。
5. **「这个会话有没有出现过图」这个问题，代价与会话有多长无关。**
   随会话长度变化的，说明[投影没有被增量维护](design.md#618-模态投影要答得快而且是增量维护出来的)。
6. **把会话日志重放一遍，重算出来的模态投影与维护出来的那份逐项相同。**
   不同，它就是第二份权威，不是投影。
7. **[PF-011 那张六层表](../PF-011-off-nominal-handling/design.md#54-各层的四要素)里，模型调用那一行的四格全填满了。**
   这是本 topic 存在的直接理由——**填不满就是没做完**。
8. **把「切换模型」这件事从产品里整个拿掉，agent loop 一行都不用改；
   把重试那件拓展件拿掉，[PF-012 的十一个位置](../PF-012-agent-loop-and-run/design.md#十一个位置是推出来的不是挑出来的)一个都不少、一个都不多。**
   任何一条不成立，说明本 topic 偷偷改了别人的模型。
9. **「选中模型」与「有效模型」在任何一处正文里都不能互换。**
   换了一处仍然读得通，说明那两个词在那里被用成了同一个意思——**而那正是要防的错**。
10. **每一条「绝不能」都举得出一个真实会违反它的做法。**举不出来的那条是想象出来的，删掉。
