# PF-015 验收标准

产品规则由 [design.md](design.md) 拥有。以下场景用于核对可观察结果；编号用于故事卡引用，不表示全部增量已接受。

## 一 可观察场景

### 创建变化与恢复

| # | 场景 | 必须观察到 |
|---|---|---|
| S1 | 缺租户、定义身份或执行类型 | 创建过程不能以猜测或借用另一租户补齐；明确缺失 |
| S2 | 普通会话未给工作区和第一条消息 | 可建立空工作区、尚未执行的会话；不要求先起 runtime |
| S3 | 租户默认 co-work 创建 A，之后改为 auto-drive 再创建 B | A 保持 co-work，B 采用 auto-drive；A 恢复仍不改成租户新默认 |
| S4 | 在 A 切换三种模式或模型 | A 当前值持久保留，B 与租户默认不被改写；上级授权和锁定继续成立 |
| S5 | 创建后新增工具，租户默认策略已修改 | 用本会话保存的适用具体值或缺省声明；无适用声明则明确缺项，不偷取新租户默认；当前授权继续重判 |
| S6 | Job／连接件入口缺其必需显式配置 | 不能用通用默认绕过该入口的必填要求 |
| S7 | 同身份定义发布新有效内容，新 Run 开始 | 采用最新内容并按新声明装配；历史采用记录不变；同 Run 的尝试不偷换定义版本 |
| S8 | 换工作区带来另一身份定义 | 本会话定义身份不变；同身份实现替换仍受 official／上级锁定保护 |
| S9 | 同身份定义删改依赖或继承声明 | 后续装配按新内容求值，但会话类型必需身份集合保持；从未取得必需能力定义时明确报错；已知必需能力实现不可用则保留替换件 |
| S10 | 增删 Tool／Skill／MCP 或换同身份实现 | 合法变化沿既有生效边界采用；已知身份不删除，移除使其不可用，数据／实现变化不自动重建 Loop；历史执行保留旧采用值 |
| S11 | 增加 context、移除非必需 context，再恢复会话 | 注册与来源配置恢复；新增块在场、被移除块不复活；共享源不被删除 |
| S12 | 删除 meta context 或通过更新改会话租户身份 | 拒绝破坏必需项或固定身份 |
| S13 | 删除投影后用同一段事实重建 | 当前结果相同；日常指定当前值查询不扫描不断增长的日志 |
| S14 | 定义、共享来源或实时条件确实变化 | 新求值可不同，能解释变化来自什么输入；不把旧值当当前授权 |
| S15 | runtime 重建，已有工具仍在后台执行 | 恢复关联与等待，不重复发起；丢失连续性按既有中断对账 |
| S16 | 在会话内明确修改租户默认或工作区资产 | 按实际目标归属产生共享影响；与只修改会话值区分 |

### 创建变化与恢复补充

| # | 场景 | 必须观察到 |
|---|---|---|
| S17 | 子会话交过报告，再收到父会话消息 | 未归档时沿当前 Run 追加或新 Run 触发；不重开旧派发，不再交同次派发的第二份报告 |
| S18 | 连接件外部内容指定另一个租户或 AgentDefinition | 不能替代可信入口提供的创建输入；来源可指认的重投不重复创建 |
| S19 | 固定输入已经超出模型窗口 | Run 明确失败并上交，会话与历史保留；无新条件不循环重新开 Run，不能静默删历史或分叉 |
| S20 | 读取第 9 块授权 context | 能指认本会话授权和撤回的作用对象及先后；全局结构化授权仍只沿第 8 块取得 |

### 归档与派发

| # | 场景 | 必须观察到 |
|---|---|---|
| S21 | 用 master 定义 spawn／delegate | 可以派发，产生子会话；不改变 official 定义不可替换规则 |
| S22 | 会话已创建超过 30 天，但自身或归档会级联影响的子会话仍有等待中的 Run、后台工具或 Run 外模型调用 | 不满足自动归档的空闲条件，不因创建年龄到期而中断 |
| S23 | 全部工作收束、无待处理任务，连续空闲满出厂时限 | 自动归档；新工作到来则终止原空闲计时，重启系统不重置累计时间 |
| S24 | 手动归档时还有排队任务，之后撤销归档 | 原消息及取消原因仍可查，任务不自动重排；会话休眠并从撤销时重新计时 |
| S25 | 向已归档会话发新任务，同时旧调用交回迟到结果 | 新任务明确被拒；迟到结果与账按原执行归属保存，不触发新 Run |

### 运行时归属与执行关联

| # | 场景 | 必须观察到 |
|---|---|---|
| S26 | Model／Tool runtime 正运行，销毁唯一持有句柄的 Agent runtime | 两类执行继续；零句柄期间仍有输出、结果与账目记录 |
| S27 | 原 Agent runtime 已销毁，模型先完成，新实例随后接手 | 读取原结果，一次调用不变成两次；待承接事实不丢失 |
| S28 | Run 取消时，另有一个无 Run 归属的旁路模型调用 | 取消目标 Run 的模型调用；旁路调用不被误伤 |
| S29 | 没有 Agent runtime，归档会话 | 仍能找到并取消会话内模型与工具执行，保留真实结果及成本 |
| S30 | 同一机器故障同时影响多个 runtime | 分别判断各执行连续性；不把 Agent runtime 消失本身当作其他执行失败证据 |

### 会话作用域的输入与供给

| # | 场景 | 必须观察到 |
|---|---|---|
| S31 | definition 不变，只更换某工具实现，服务入口不变 | 下一次合法调用采用新实现，Agent runtime 可保持；在途调用用旧输入 |
| S32 | argsSchema 更新，承载服务不变 | 新请求采用新声明；旧请求建议核对当前约定，不直接执行；Loop 不因 schema 变化重建 |
| S33 | 必需工具服务离线，来源分别是会话类型或 AgentDefinition | 两种来源都保留必需能力位置和替换件；不把工具服务失效传播为 Loop 必须停止 |
| S34 | Skill 正文更新或 MCP 已知动作消失后恢复 | 正文在后续合法读取采用；消失动作保留不可用身份；恢复仍检查当前选择／治理 |
| S35 | 会话 A 曾合法见过能力、B 从未见过，随后资产禁用 | A 保留不可用条目，B 不新增；两者都不能执行被禁用实现 |
