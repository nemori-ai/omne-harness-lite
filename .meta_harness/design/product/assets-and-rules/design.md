# 资产与规则

状态：产品修订候选，正文待负责人确认。负责人已确定 0.0.0 -> 0.1.0 完整支持 CAP-AR01、02、03、04、05、07、08、09、10，范围见第三块。阶段承诺、实现、验证和交付接受分别记录。

## 产品需求描述

### 让共同能力可治理，也让具体资产独立发展

组织希望成员使用共同方法，同时保留不可突破的约束；租户希望选择适合自己工作的合法能力；参与项目的人希望把项目方法放在工作区，不靠复制每个人的私有设置来协作。用户需要知道一份能力归谁、为什么可以使用、采用了哪份内容，以及改动会影响什么。

Harness 提供资产身份、版本、持有、来源、流转、设置与权限的共同治理契约。共同契约让不同类别的资产可以进入同一套治理，并不代替各类别的专门业务。Tool、Skill、MCP、Slash Command、Plugin、Loop Extension 和 AgentDefinition 的定义及使用规则仍由对应领域维护，类别接入不等于具体类别的全部能力已经支持。连接件是否保留为资产及其接入设计另行确定。

资产治理取得身份与授权的可信主体和资格，向装配与实际业务提供合法候选和配值依据。持有资产、选入组合、装配成功和动作获准是不同事实，本领域不接管模型、工具或 Agent 的运行生命周期。组织的具体管理资格沿所采用的治理模型及对应操作规则核验，默认个人与团队方案沿[身份产品](../identity-and-authorization/design.md)，不把某种组织角色枚举作为所有资产消费者的前提。

### 创作一份资产，再让它成为可使用的版本

<a id="ownership-and-versions"></a>

用户把方法、工具定义或其他能力内容保存为资产时，需要能够辨认自己的这份定义，并知道哪些内容仍在编辑，哪些版本已供他人采用。能力标识由资产类别与 name 表达同一种能力，它不是具体资产或版本，也不代表所有权和执行资格。一个能力标识下可以有不同具体资产，每份资产分别保有草稿、版本线和来源；同名不授予对另一份资产的处置权。

定义所有权说明定义归谁，使用权说明能否按已成立关系使用它。使用权不自动包含编辑、复制、提升或再分享，也不开放其他租户内容。持有表示某范围加入了这份资产，并可在本层选用和配值；它不保证某个 Agent 已经选入或执行。一个层可以保存多份同能力标识资产，但对同一能力标识至多持有一份。新增资产不能替用户决定改换持有。

所有者、作者、持有者和使用者分别记录。人类在组织范围合法创作的资产归组织，在自己的租户范围创作的归租户；个人组织的人类创作沿其个人组织归属。作者保留创作时租户身份，角色变化或退出组织不改历史署名。官方资产的作者和所有者为平台，不虚构租户。

用户让 Agent 产出资产时，归属取决于实际提交位置：提交到特定工作区的是工作区资产，提交到租户的是租户资产，提交须有对应访问资格，并保留 Agent 产出来源。工作区产出不能默认为发起会话的租户资产。Agent 不能直接产出组织资产；用户希望组织拥有时，须另行人工提升，创作意图或一般批准不能代替提升。

草稿可以修订，发布版本不可变，修改已发布内容形成新版本。采用者可以固定已发布版本，或跟随当前发布版本；不另指定时跟随当前版，选择在设置页可见。固定者不因发现新版暗换，跟随者在后续求值采用新版，不改写已经发出的调用输入。分享只能跟随，不能固定版本；重复复制采用目标新版本的后果在流转路径中单独说明。

完整创作、上架与发布路径，以及普通成员创作组织资产的具体委托仍需细化。已有身份、版本及归属保证继续成立，不能由技术入口存在推导这些用户路径已经齐备。

### 把资产加入使用范围，并看清为什么采用这份实现

<a id="resolution"></a>

用户选择一份资产后，需要知道实际生效的是哪层的哪份实现，自己的选择为什么被允许或限制。例如，组织加入审计 Skill 并锁定替换后，成员须能看到组织来源和锁定原因，不能用租户或工作区的同名内容绕过。修改生效资产的某项设置与替换整份实现是不同动作。

能力实现按适用的官方、组织、租户、工作区层序选择。先过滤禁用候选，再过滤使用者无资格的候选，最后选择合法的最具体实现；被过滤的实现不能遮蔽同标识其他合法实现，上层锁定仍有效。官方能力构成最小下界，不能被清空或禁用。允许替换的官方能力可以由同标识自定义件替换，meta 能力、official AgentDefinition 及上级锁定持有的不可替换约束仍各自成立。

资产可以在自身定义中声明 `immutable`，表示这份资产不能被下级同能力标识的其他资产替换。声明随该资产定义提供，不要求持有者另行设置替换锁；下级也不能用自己的声明或配值解除它。例如，组织层合法采用的审计 Skill 自身声明 `immutable` 时，租户或工作区的同标识 Skill 不能替换它。相同资产在下级继续持有不属于替换。

这项声明只约束从合法采用该资产的层到更具体层的替换，不反向限制上级，也不绕过禁用、使用资格或既有上级约束。被过滤的候选不能凭声明锁住其他合法候选。它与持有层主动锁定替换分别成立，任一适用的不可替换约束都须遵守。

定义中的 `immutable` 不表示草稿或全部内容永远不能修改，也不自动锁定资产的设置、权限或引用能力。发布版本不可变、合法发布新版本、禁用与移除仍分别沿自己的规则；不可替换不授予使用或执行资格。

用户能查到生效实现的来源层、被替换内容和候选未生效原因。同标识替换不转移原设置或凭据，原能力身份的权限锁定继续限制替换件；替换件少声明被锁权限项不能借此逃出约束。

使用资产组合时，组合引用能力标识，不直接固定某份实现，也不转移被引用内容的所有权。Plugin 内含成员随 Plugin 版本和使用权治理，没有独立顶层生命周期；外部引用不因打包就归 Plugin 作者所有。复制或分享 Plugin 的发起阶段须核对目标方能否提供外部引用，源方有、目标方没有时提前告知；告知本身不自动拒绝流转。无法完成展开的递归组合须拒绝，Skill 与 Tool 声明相互配套不等于这种环。新增组合种类须明确采用范围，不从共同契约推导任意组合已被支持。

### 在项目工作区协作，保留每个租户的私有边界

<a id="workspace"></a>

用户参与一个工作区，希望使用项目共享的方法，同时保留自己合法的实例本地定制。使用工作区来源须提供明确选择，未选择时该来源为空；会话何时选择由会话业务维护。相同目录或地址不能证明工作区身份、参与资格或宿主权限。多个获准租户共用实例时，工作区来源可以共用，租户私有资产、配值和凭据仍分别隔离。

`.omne` 和 `.omne.local` 属于同一工作区层，local 不是租户私有来源。共享及 local 候选分别过滤后取合法内容并集，同能力标识的合法 local 优先；被过滤的 local 不遮蔽合法共享候选。同层设置逐项取 local 显式值，缺省时才沿用共享值，显式 false 不是缺省，也不与共享值取布尔或。

用户可以只覆盖允许的 local 设置项，不必另建完整资产。选择完整 local 替换资产时，不混入共享实现的配值。工作区只禁用自己提供的资产，不能禁用官方、组织或租户实现。

工作区可以贡献能力、偏好和合法绑定，不能贡献授权或权限配值。加载时过滤对其他资产的落点与身份设置，以及除自身禁用外的治理设置。工作区资产可携带自己的落点声明，实际使用仍受权限和执行环境约束。工作区资产的动作每次须经人工许可，Loop Extension 只观察；使用资格限于在自己会话中获准选择该工作区的租户。声明更宽的出厂权限不生效。需要放宽时，先按合法方式收进租户层再配值，仓库文件不能代替批准。

可能在本机启动命令的工作区 MCP 接入点及导入的命令型 hook 默认不启用，由获准租户在自己的设置里逐件打开。仓库不能替人打开，启用也不解除保守权限和宿主执行边界。

为采用而读取并校验来源，只在实际装配或显式 reload 时发生；系统可以更早预先求值，但预先求值不构成采用。文件编辑、Git 同步和下一次 Run 不构成隐式刷新。新候选校验失败时说明原因，保留此前合法采用状态，不能发布半份新组合；装配与工作推进怎样接续由相应领域维护。

### 配置资产的行为，同时守住权限上界

<a id="settings-and-permissions"></a>

用户进入组织或租户设置时，需要看到自己持有资产的设置和权限，而不是一套与资产脱离的字段目录。资产声明设置项的含义、合法值和类别，资产类别声明权限项及实际执行关口。作者可以声明设置，不能自拟一项无人执行检查的权限。属性配值是某份持有上某项设置或权限的值，不能脱离持有单独取得配置权；账号语言、时区等个人偏好也不是资产设置。

普通设置沿默认、组织、租户、工作区、会话的适用次序求值，取最具体合法值，上层锁定阻止下层改变。禁用有专门布尔规则，不能把全部设置统一取布尔或。偏好、绑定、落点与身份、治理各有允许来源，工作区限制不能因更具体而失效。

权限先求锁定允许集合的交集，再从最具体来源向外取第一个落在共同允许范围内的挑选。未锁值是默认选择，不是强制边界。全部挑选都在界外时，有序分档权限取界内距最具体挑选最近的一档，等距取较严档；未定义顺序的类别不能猜距离。共同允许范围为空时拒绝使用。

组织、租户或会话主动将某项权限配为“不允许执行该权限所控制的操作”时，该权限值无论是否加锁，都不可被更具体层覆盖为允许。这是对具体操作的权限限制，不表示禁用整份资产。作者的出厂默认权限值即使不允许该操作，也只作为最外层挑选，不构成上述不可覆盖的权限约束。使用资格、执行权限、持有、装配和编辑分别判断，获准做其中一个动作不授予其他动作。

各类别共用“谁可以使用它”，作者未另声明时只限作者自己。工作区来源中的“自己”是本次获准使用该工作区的租户。使用者无资格的自定义件不参与候选选择，官方实现不因此被隐藏。

用户表达“本租户以后这类调用都允许”时，经写租户权限资格及组织上界校验后，才写入租户权限值。单次或会话授权表达仍归身份与授权，人工批准也不能覆盖明确禁止或工作区过滤。每个可配置事项须说明配置主体、允许范围、生效点、对既存事实的影响及无效配置的后果；具体部署时长不进入产品约束。

用户暂时不想用资产时，禁用保留持有及配值，可按资格再启用；下层改为启用不能取消上层禁用。移除则收回持有，配值随之退出。清除一项覆盖只表示本层不再提供该值，重新沿当前来源求值，不等于关闭、设成 false 或恢复某个旧默认。

### 与他人协作时，选择复制、分享或人工提升

<a id="circulation"></a>

用户希望团队拿到一份可以独立修改的内容时，使用资产复制；只希望他人持续使用自己维护的内容时，使用分享。复制产生目标方独立的所有权和版本线，后续修改不自动传播，源资产保留。分享不转移所有权，接收方取得使用权并跟随分享方当前发布版本，不能改内容或固定版本。关系结束后，已经独立拥有的副本保留，分享使用权结束且不会因关系恢复自动复活。确认前须能区分这些后果。

#### 先确认允许的来源与目标

已定义的个人及团队方案限制流动方向。团队组织中的组织级和租户级资产不能进入任何个人组织，也不能流出隶属树；导出、模板和下载受同一边界约束。多个获准租户装配同一工作区来源不是私有资产间的复制或分享，不提供绕过外流限制的路径。其他治理模型未定义的方向不自动许可。

本人型流转限本人在两个组织中的合法身份。个人组织资产可以进入本人所属团队的租户级；本人也是目标团队管理员时，复制可选择组织级，个人组织向团队组织级没有分享。团队租户资产可进入同树另一团队中本人的租户级，不能进入他人的跨组织私域。

组织型流转限同树两个团队的组织级，由源管理员发起、目标管理员确认。发起者不必成为目标成员，也不能因此写入目标某个成员的租户级。同组织租户所有者可以向另一成员分享并由对方确认，不能以复制替代；两个个人组织可以分享并由接收本人确认，不能按本人型复制到另一人的个人组织。未定义方向不能默认为允许。

#### 复制形成一份独立资产，重复复制须知道会覆盖什么

复制只处理源方拥有的已发布内容，不复制草稿或被分享来的内容。用户发起时确定源版本和合法目标层，系统按目标层的同源复制血缘判断首次或重复，不能因能力标识撞名就覆盖。

首次复制产生目标独立资产，能力标识不变，版本从 v1 开始，不携带源配值。目标没有同标识持有时，一并持有副本；已有持有时，副本并存，不暗换原持有。本人型作者记目标租户，组织型作者记实际确认的目标管理员租户，源作者不变。目标可看到交付者、时间及版本，复制血缘不开放源私有内容。

重复复制全量形成并采用目标新版本，目标本地内容改动不进入新版本，旧发布版本仍可查询和回退。目标配值不被覆盖，删除的项退出求值，新增项取默认，未改变项保留原配值及锁定。血缘只匹配目标层，不改其他层副本；没有同源血缘的同名资产新增并存，不自动改换持有。

#### 等待对方确认，再维护分享关系

跨主体复制或分享等待目标层管理者确认，本人型两边均为本人，发起即成立。组织型重复复制也须重新取得目标确认，首次同意不能成为静默覆盖的许可。

待确认通知和邀请分别有部署默认时长，发起者可以指定本份时长，具体数值由配置说明。撤回、到期或源资产消失后不能确认，也未曾建立目标资产或使用权；重新发起是新邀约，确认时仍核当前资格及关系。

已确认分享没有自动到期或暂停。所有者可以撤销，接收者可以移除。相关隶属、分享方成员关系或接收方成员关系解除时，分享结束，重入和重新隶属不复活。接收方可以配置自己的设置及权限，不能编辑、再分享、复制或提升这份分享资产；分享没有集团强制管辖含义，接收方可以合法替换或移除。

#### 把资产所有权交给组织，须由人完成交付

租户资产提升到组织是不可逆的所有权交付。原持有和配值保留，组织不自动新增持有；提升后适用组织级分享设置，仍可分享则既有分享保留，否则撤回，不要求再次确认。

共享工作区和外部仓库的资产也可以直接人工提升，不要求先进入租户层。托管工作区由治理所有者或其明确授权的人发起；外部仓库由具资产处置权或明确授权的人发起，并提供可核实的权利或授权依据。目标组织管理员确认后才完成接收，发起本身不完成提升。

访问、参与、仓库写入或 Agent 创作事实都不自动授予来源处置资格。Agent 不能代用户发起提升或确认组织接收，直接提升也不放宽原工作区运行权限。资格依据不可核实时，不完成依赖它的提升；来源资格核实、组织接收及恢复协议仍需细化。

### 变更后，能够辨认生效范围和真实结果

<a id="changes-and-failures"></a>

改版、移除或退役前，用户需要知道受影响引用及后续采用后果，不能默认级联删除、替换其他对象或停止独立工作。并发草稿编辑不能用过期内容覆盖他人已确认的修改，实际管理动作仍检查当前资格与目标条件，旧菜单不代表永久许可。

变化只在规定采用或准入边界作用于后续工作，不改写历史和已捕获输入。移除、禁用或撤权不证明模型或工具已经停止，也不回滚外部效果。会话已合法见过的 Tool、Skill、MCP 在该会话内保留已知身份及不可用原因，该会话从未取得的能力不因撤权新增；人的 Slash Command 沿其类别入口的可见性规则。共同治理提供来源和不可用依据，具体展示及运行后果归类别和消费者。

凡改变某个作用域合法候选集合或生效选择的治理事实，资产治理都把该作用域的采用变更计数加一，并通知后续使用方。这类事实包括发布、改变选版、加入或结束持有、禁用与再启用、锁定与解除锁定、替换、改变「谁可以使用它」、分享的确认与撤销、复制形成新持有。设置值或设置锁定变化时，设置的维护方同样把该作用域设置来源的采用变更计数加一。计数只增不减。使用方比对计数就知道来源有没有变，不必在每次工作开始时重读全部来源。计数变化本身不改变已经采用的结果，采用仍只在规定边界发生。

报告治理事实已持久保存前，须达到项目要求 SYS-DURABILITY 的确认边界。确认后的事实须能在进程崩溃、操作系统崩溃和断电后读取，不据此承诺介质或整机物理损毁后的同等恢复。确认响应丢失时查询原操作结果，不能把未知当失败重复创建副本或改版。部分成功须分别说明已完成及待处理步骤，来源故障、权限不足、引用阻断和真正空清单分别可辨，不能用空结果或假成功掩盖故障。

秘密配值不以原文进入审计、来源说明或遥测。遥测保留规则采用及真实结果，候选求值、确认邀请和装配成功都不是工具已经执行的证明。权限分档距离的精确表示、来源版本、并发协议及公开类型归技术拥有者细化，不能借技术待定改变产品规则。

### 关键用户旅程

<a id="key-journeys"></a>

以下 AR-J 编号只提供文档定位。旅程解释第一块既有规则的用户后果，不新增公开对象、交互界面或业务默认。能力及支持程度沿第二、三块；每条旅程的架构流程只承接本领域贡献，实际装配、人工决定和执行收场仍由各自领域维护。正常路径及受阻后果均适用当前资格、租户私有边界和真实结果要求。

#### AR-J01 创作、发布并选择可用版本

<a id="ar-j01"></a>

人类作者希望把自己的方法变成可供采用的资产，前提是对提交范围有合法创作资格。作者先确定资产类别和归属范围，维护草稿，再通过共同与类别校验发布不可变版本。持有管理者选择固定发布版或跟随当前版，未另指定时采用可见的跟随选择。固定者保持原版，跟随者在后续求值取得合法新版，已发调用仍用原内容。

同名新资产各有身份，保存内容不授予处置另一份资产的权利。Agent 代主体产出时只提交到获准租户或工作区，按实际位置归属并保留来源；Agent 不能直接产出组织资产，用户希望交组织时另走人工提升。人类组织创作仍须当前资格，未细化的普通成员委托不能由归属规则代定。

过期编辑返回冲突，校验拒绝或来源不可用时不发布，也不假称空定义合法。取消和失联可能跨过已成立保存或发布，恢复后查询原操作结果，不能再发布一版来掩盖未知。组织创作委托和类别上架制度仍待原拥有者细化，不缩减公共草稿与发布承诺。能力涉及 CAP-AR01、02、03、16，流程见 [AR-F01](../../../../packages/assets/assets/docs/internals.md#ar-f01)。前三项纳入 0.0.0 -> 0.1.0 完整支持，CAP-AR16 的独立能力未纳入，适用耐久与真实性仍须成立。

#### AR-J02 加入资产、暂时禁用或结束持有

<a id="ar-j02"></a>

组织持有管理者或租户本人希望让某份合法资产进入自己的范围，前提是拥有定义或取得有效使用权，并有该层管理资格。管理者明确要加入的具体资产和版本选择，每层同能力标识至多持有一份。已有同标识持有时，保存另一份资产只形成并存记录，改换须是合法的明确操作。加入后可为本层持有配置允许的项，实际选入、装配和执行分别判断。

临时不用时，禁用保留持有、选版和配值；再启用只解除本层禁用，不能打开上层禁用。决定结束持有时，移除使本层配值退出，先说明受影响引用，不能暗中级联删除其他资产或停掉独立工作。无权管理、无合法权利依据或唯一持有冲突时拒绝，依赖不可用时说明无法判定。取消与移除、配值写入竞争后核实原结果；恢复不得留下脱离持有的生效配值。能力涉及 CAP-AR04、09、16，流程见 [AR-F02](../../../../packages/assets/assets/docs/internals.md#ar-f02)。CAP-AR04、09 属于阶段内完整支持，CAP-AR16 不另承诺为独立交付。

#### AR-J03 选择实际采用的同标识实现

<a id="ar-j03"></a>

租户或装配消费者希望采用最适合自己的合法实现，前提是提供明确组织、租户及可选工作区和可信资格。系统先过滤禁用，再过滤无使用资格的候选，最后沿适用层序求合法实现，不能让失效的更具体候选遮蔽可用回退。生效结果能定位具体资产、版本、来源及未生效依据，查看解释仍受披露资格约束。

合法上层定义声明 immutable 或持有管理者锁定替换时，更具体层同标识其他资产不能取代它；无需同时设置两种锁。同一具体资产继续被下层持有不算替换。用户仍可合法改设置或发布新版本，不能把不可替换当作全部内容被冻结。允许替换时，旧设置及凭据不搬到新实现，原能力身份的权限界及主动不允许操作值继续成立，替换件删项不能绕过。

没有必需合法定义时，装配指出缺失；已有定义但执行暂不可用时由类别说明不可用。来源或资格未知不伪造空清单，候选校验失败不发布半份组合，原合法采用按原条件保留。取消、reload 或恢复不能重写已发调用，也不能用旧允许一直放行新动作。能力涉及 CAP-AR05、10、11、16，流程见 [AR-F03](../../../../packages/assets/assets/docs/internals.md#ar-f03)。CAP-AR05、10 完整纳入 0.0.0 -> 0.1.0，完整解释及独立治理观测未纳阶段。

#### AR-J04 使用工作区方法和合法本地定制

<a id="ar-j04"></a>

获准租户希望采用项目共享方法，前提是明确选择工作区并通过其身份及参与检查。未选择时工作区来源为空。实际装配或显式 reload 读取共享及 local 材料，分别过滤后合法 local 同标识实现优先。用户仅覆盖设置时，同项 local 显式值优先，缺省沿共享，false 不等于缺省；选整份 local 实现时不混原共享实现配值。共用实例中的 local 仍是工作区层，其他租户私有资产和凭据不会因此可读。

受限权限、授权、给其他资产配落点与身份、除自身禁用外的治理配值在加载时过滤。资产自身合法声明与这些配值分别处理。可能启动本机命令的工作区 MCP 和导入命令型 hook 默认关闭，获准租户在自己的设置逐件启用；仓库不能替人打开。启用后，动作仍按人工许可、Loop Extension 只观察及宿主限制执行，需要放宽先按合法方式收进租户层。

身份、资格或来源不可核实时不能从路径猜许可；无效候选不替换合法旧采用。文件编辑、Git 同步及下一 Run 不自动刷新。取消或恢复的交接由装配和会话业务处理，不用重新读取旧仓库文件来声称原调用输入已经改变。能力涉及 CAP-AR07、08、09、15，流程见 [AR-F04](../../../../packages/assets/docs/key-flows.md#ar-f04)。前三项完整纳阶段，独立来源刷新 CAP-AR15 未纳阶段。

#### AR-J05 配置行为并取得具体动作的合法准入

<a id="ar-j05"></a>

有配值资格的用户希望调整自己持有资产的行为，前提是该项存在、取值合法且来源允许。设置视图从持有及声明产生，用户写值、清除或按资格锁定，普通设置取最具体合法值并守上层锁。清除只是撤回本层覆盖，沿当前来源再求值，不是设 false 或固定旧默认；移除持有后的配值不能继续生效。

用户选择权限值时，先遵守共同上界，再取最具体来源向外首个界内挑选。所有挑选均在界外才按已定有序分档取最近档，等距取较严；比较关系未定不能猜。组织、租户、会话主动不允许某项具体操作时，下层、模式和人工批准都不能改为允许，即使未锁；作者出厂默认不允许只作挑选。这种权限限制与禁用资产分别显示后果，工作区也不能贡献权限配值。

实际动作按生效参数由身份与授权判断，规则允许询问时交 HITL 的原决定请求，答复仍须当前有效，执行环境再守自己的限制。用户明确要求租户全局允许，只有表达范围、写入资格和当前上界均成立才写租户权限；单次或会话批准不能扩成持久全局许可。无资格、越界或主动不允许时拒绝对应写入或操作，依赖未知不默认放行。取消、人工等待、撤权和恢复不回滚已确认配值，也不证明工具停止，原结果按原操作核实。能力涉及 CAP-AR04、08、09、10、16，流程见 [AR-F05](../../../../packages/assets/permissions/docs/internals.md#ar-f05)。前四项完整纳阶段，必要的安全与耐久继续成立。

#### AR-J06 使用组合并核对流转的外部依赖

<a id="ar-j06"></a>

组合使用者希望让引用能力协同工作，前提是组合种类有采用依据且所需定义合法。组合引用能力标识，具体实现沿完整合法作用域解析；Plugin 内含成员随 Plugin 版本和权利，外部引用保有自己的归属。组合只采用符合当前启用规则及治理边界的成员，不能因组合使用而绕过成员约束。

无终点递归展开须拒绝，Skill 与 Tool 配套互引不因相互引用就被视为该环。无合法必需定义或类别校验失败时指出具体问题，不发布半份组合。复制或分享 Plugin 发起时核对目标能否提供外部引用，源有目标没有的情况提前告知，告知不新增拒绝政策。取消或失联后查询已成立流转及采用事实，不把外部引用补成目标资产或自动重做。能力涉及 CAP-AR01、06、09，流程见 [AR-F06](../../../../packages/assets/docs/key-flows.md#ar-f06)。CAP-AR06 的完整组合及流转核对未纳 0.0.0 -> 0.1.0，不据通用接入宣称任意组合已支持。

#### AR-J07 交付独立副本或更新同源副本

<a id="ar-j07"></a>

源所有者希望目标方独立拥有并修改内容，先确定自己的已发布源版本及合法目标层。本人型合法发起即成立，组织型等跨主体复制等待具资格目标确认，重复组织复制也须重新确认。方向、资格、时限和源存在按当前事实核验，草稿、分享来件、团队资产进个人组织、跨树及未定义方向都不能据持有或打包放行。

首次形成目标独立资产及 v1，不携带源配值；无同标识持有时同时加入，有则并存。重复只按目标层同源血缘全量形成并采用新版，目标本地内容不混入，配值不被全量覆盖，删项退出、新项默认、未变项保持。无同源血缘的撞名不变成覆盖，其他层副本不被更新；目标旧版本仍可查询和回退。

等待时没有目标资产或新版，撤回、到期或源消失后不可确认。并发、取消、依赖失败或失联后，明确未成立与结果未知，恢复查询原操作，不重复多生副本或版本。交付结果不开放源私有内容，实际装配及执行仍另判断。能力涉及 CAP-AR02、03、04、06、12、16，流程见 [AR-F07](../../../../packages/assets/assets/docs/internals.md#ar-f07)。这条复制路径长期保留，CAP-AR12 未纳 0.0.0 -> 0.1.0，其使用阶段内公共版本能力不改变流转的阶段边界。

#### AR-J08 分享持续维护的内容并结束使用关系

<a id="ar-j08"></a>

源所有者希望对方跟随自己维护的内容，先核合法方向和分享资格。跨主体等待目标层确认，组织由当前目标管理员、租户由本人处理；本人型合法发起即成立。邀请尚未确认时没有使用权，撤回、到期或源消失后不能确认，重新发起是新邀约，具体时长沿部署配置及本次选择，不钉死数值。

确认后，接收方取得跟随发布版的使用权，可合法配本层值、替换或移除，不能固定版本、编辑、复制、提升或再分享。成立分享没有自动到期或暂停。源方撤销、接收方移除或相关隶属、分享方成员或接收方成员关系解除时分享结束，重入和重新隶属不复活。

确认与撤回、到期和关系解除竞争不能同时产生结束和可用权利。允许依据未知时不建立使用权，确认失联或取消后查询原事实，通知不代表完成。结束关系不停止已经开始的独立调用，恢复不得从备份或旧通知复活分享。能力涉及 CAP-AR03、04、06、13、16，流程见 [AR-F08](../../../../packages/assets/assets/docs/internals.md#ar-f08)。CAP-AR13 长期维护但未纳阶段，成立关系的方向仍以本页原规则为准。

#### AR-J09 由人把资产交付组织所有

<a id="ar-j09"></a>

有来源处置资格的人希望组织拥有资产，先核目标组织及当前来源依据。租户资产按其合法提升规则交付所有权，原持有和配值保留，组织不自动持有，历史作者不改。共享工作区或外部仓库可以直接人工提升，无须先转租户；托管工作区由治理所有者或明确授权者发起，外部仓库由具可核实资产处置权或明确授权者发起。后两种路径须目标当前组织管理员确认后才完成接收。

访问、参与、仓库写入、Agent 创作和一般批准不构成来源处置资格，Agent 没有代人发起或确认入口。必要资格或来源无法核实时不完成提升，目标未确认不显示已接收。提升后原分享按组织级分享设置判断，仍可分享则保留，否则撤回，不要求重新确认，也不能一律保留或结束。

提升不可逆，取消或响应丢失不能声称所有权已自动回滚。恢复按原操作核实归属及适用分享处置，不能显示相互冲突的结果。直接来源的持有与源侧处置细节不能从租户路径照搬，核实和接收协议仍由技术拥有者细化，工作区运行权限不因提升入口放宽。能力涉及 CAP-AR02、04、13、14、16，流程见 [AR-F09](../../../../packages/assets/assets/docs/internals.md#ar-f09)。CAP-AR14 及该流转路径未纳 0.0.0 -> 0.1.0。

#### AR-J10 在治理变化或故障后核实采用与真实结果

<a id="ar-j10"></a>

合法管理者或消费者希望知道变更是否完成、后续采用什么，前提是有查询相应事实和解释的资格。治理成员区分成功、冲突、来源故障、权限不足、引用阻断及真正空结果，assembly 只采用完整合法候选。改版、移除、撤权或显式 reload 作用于规定后续边界，已发调用和历史不会被重写；会话已知 Tool、Skill、MCP 保留身份及不可用原因，未知能力不因失败被新增。

取消、失联、进程崩溃、操作系统崩溃或断电后，消费者查询同一原操作，读回已耐久确认事实，分别呈现成立和仍待处理的步骤；无法核实就保持结果未知，不假成功，也不按失败重复副作用。介质或整机物理损毁不在同等恢复保证内。候选失败保留原合法采用不等于旧允许永久有效，恢复须核当前条件，不复活已撤销权利。

撤权、禁用、移除和运行实例回收不证明工具或模型已经物理停止，真实效果及账目由独立执行方保管。解释、审计和遥测不泄露秘密配值及其他租户私有内容，准入或装配成功不冒充执行成功。能力涉及 CAP-AR03、04、05、09、10、11、15、16，流程见 [AR-F10](../../../../docs/domains/assets-and-rules/key-flows.md#ar-f10)。CAP-AR11、15、16 的独立能力未纳阶段，已选五项的必要安全、失败及耐久保证不能因此关闭。
