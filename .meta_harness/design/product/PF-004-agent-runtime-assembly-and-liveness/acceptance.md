# PF-004 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

### 装配

| 场景 | 应当看到什么 |
|---|---|
| 一份定义在某个作用域下装配 | 产生一个运行实例和一份**装配清单**，清单上能查到装了哪些工具、哪些技能、落在什么执行环境 |
| 定义引用的某个能力标识无人提供 | **明确失败并指出缺哪个**；不产生运行实例，更不产生一个少装了零件却照跑的实例 |
| 同一个会话已有就绪的运行实例，又要跑一轮 | **直接复用，不重新装配**；装配清单不变 |
| 试图为同一个会话装配第二个运行实例 | **拒绝** |
| 同一份定义在两个不同作用域装配 | 两份清单**不同**（各自作用域求值出的实现、设置、权限不同），而**定义本身一个字没变** |

### 三个时刻

| 场景 | 应当看到什么 |
|---|---|
| 装配完成那一刻 | 系统提示词的**成分**已确定；**成品尚未存在** |
| 同一个运行实例，用模型 A 请求一次，再用模型 B 请求一次 | 两次的系统提示词**可以不同**（同一批成分、不同组装方式），而**运行实例没有重建** |
| 改一项权限 | 运行实例**不重建**；下一次运行里多出一条提醒 |
| 换掉执行环境 | 运行实例**不重建**；agent 执行同一条命令，只是落在别处 |
| 换模型 | 运行实例**不重建**，动作空间**不变** |
| 组织移除了实例正在用的一个必需组件 | 该实例**退役**；下一次装配不再包含它 |
| 组织移除了一个可选工具 | 正在跑的实例**照常活着**；下一次装配不再有它 |

### 动作空间与权限

| 场景 | 应当看到什么 |
|---|---|
| 把某工具的执行权限从「自动」改成「问一下」 | agent **照样能发起**那个调用，只是这次要问；**动作空间没变** |
| 把某工具**禁用** | agent 发起调用时被拒，**它知道这件事存在、能说明被关掉了** |
| 把某工具**移除** | 下一次装配后它不在动作空间里，agent **说不出为什么**——它不知道有这回事 |
| 收紧整个会话的安全权限 | agent **照常工作**，动作空间不变；受影响的是调用的结果 |

### 上下文

| 场景 | 应当看到什么 |
|---|---|
| 外部环境在一轮运行进行中发生变化 | **当前这一轮不被打断**；变化在**下一轮**以一条提醒出现 |
| agent 收到那条提醒 | 它**读到**变化并自行调整后续动作；不是系统在背后改写了它的能力 |
| 上下文暂时取不到 | 明确反馈；**不拿旧值冒充当前事实** |

### 生灭与成本

| 场景 | 应当看到什么 |
|---|---|
| 一段连续多轮的协作，中间实例被回收重建过 | **用户完全无感**：接着上次说，它还记得，还是那个它 |
| 实例重建前后 | 依据的**定义版本不变** |
| agent 问了个问题，人两天后才回 | 这两天**不消耗计算资源**，账单上没有这两天的运行费；人回话后接上 |
| 实例空闲被回收 | 走**显式退役**：先不接新活，等手上的事停当，再释放 |
| 退役时仍有未结算的工作 | **不算退役完成**，如实报告被占住的是什么 |
| 退役时某项资源释放失败 | 如实报告**保留**状态与原因 |
| 强制停止之后 | **逻辑停止、实际停止、外部效果未知，分别报告** |
| 实例已经消失，事后追查「当时装的什么」 | **装配清单还在**，答得出来 |
| 看一个租户的成本 | 运行实例消耗的部分**归到启动它的那个租户** |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 同一个会话同时存在两个运行实例 | 两副身子以同一身份说话，历史没有单一真相 |
| 用户看到「agent 重启了」而他什么也没做 | 资源治理泄漏成了协作事件 |
| 实例重建之后，依据的定义版本变了 | 同一段协作里 agent 中途变脸 |
| 改一项权限导致 agent **不知道某件事存在** | 权限跑进了构成里。收紧权限从此既无法解释、也无法申诉 |
| 换模型导致运行实例被重建 | 系统提示词的成品被提前定死了 |
| 换执行环境导致运行实例被重建 | 执行环境跑进了构成里 |
| 构成性变化**悄悄改写**了一个正在跑的实例 | 一个进行中的任务莫名其妙地换了能力 |
| 上下文变化**打断**了正在进行的一轮 | 不紧急的事被当成紧急的处理 |
| 装配缺了必需的东西，仍产生一个能跑的实例 | 缺零件的 agent 跑起来，问题会在很远的地方以莫名其妙的形式出现 |
| 实例被回收，某件未完成的事**既没持久、也没接续、也没报失败** | 回收变成了一种静默的数据丢失 |
| 等人回话的时间被计入成本 | 一个等两天的确认变成两天的运行费 |
| 实例消失之后，「当时装的是什么」查不到 | 排障与审计失去唯一的答案来源 |
| 把「已经停止」说成「外部效果已经撤销」 | 外部输出不因被运行时调用就变得可逆 |
| 超级管理员能看到成员运行实例里**跑的内容** | 管理权越界。资源是组织的，内容是成员的 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 定义是数据 | 同一份定义在两个作用域装配，**定义本身逐字节不变**，两份清单不同 | 装配过程回头改了定义 |
| 成分与成品分开 | 同一实例换模型再请求一次，提示词**可以不同**而实例**没重建** | 换模型触发重建，或两次提示词被迫相同 |
| 动作空间只由构成决定 | 把权限从宽改到严再改回来，**动作空间三次都一样** | 动作空间跟着权限变 |
| 注入不触及实例 | 权限、执行环境、上下文各改一次，**实例的身份与清单都没变** | 任一项改动导致重建 |
| 构成性变化不改写活体 | 移除一个正在用的可选工具，**正在跑的那个照常用完它手上的活** | 它中途失去能力 |
| 变化以内容到达 | agent 能在回答里**说出**它知道了什么变化 | 它的能力被改了但它说不出所以然 |
| 一个会话至多一个实例 | 并发触发两次装配，**只有一个成功** | 出现两个 |
| 实例对用户不可见 | 人为回收重建若干次，用户侧**看不出任何痕迹** | 会话中断、上下文丢失或提示"重启" |
| 等人不烧钱 | 制造一次长等待，核对成本**没有随墙钟时间增长** | 等待期间持续计费 |
| 退役是显式的 | 退役过程中每一项资源与工作**都有结局** | 某项悄悄消失，或宣称清理干净而实际保留 |
| 清单可追溯 | 实例消失后仍能查到它当时的构成 | 查不到 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| 会话怎么建、怎么命名归档、历史怎么存 | **本 topic 不拥有会话**，只用到「实例附着在一个会话上」 |
| 输入怎么受理、排队、调序、什么时候取一批 | 不拥有 |
| 谁决定现在该跑一轮、怎么推进、怎么收束、怎么中断 | 不拥有驱动 |
| 单次工具调用的观察、中断与后台接续 | 它有自己的生命周期，能跨实例存活 |
| 子 agent 的委派、监督与关系 | 另一件事 |
| 待决项的统一呈现与作答 | 那是跨会话的事 |
| 模型怎么供给、怎么路由、模型选择存在哪 | 归 SYS-LLM 与会话那一侧。本 topic 只定**模型在哪一刻被确定** |
| 崩溃后恢复到哪个合法位置 | 归 SYS-RUNTIME-CONTINUITY。本 topic 定的是正常生灭 |
| 具体有哪些上下文项、哪些执行环境 | 本 topic 定它们**以什么方式**进入，不枚举内容 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
