# 元能力入口

状态：本页产品设计已接受，规定元工具的入口、用户旅程和能力边界。交付版本按阶段表维护，实现和验证分别核对。Code() 是独立程序编排入口；Engram() 与 Stop() 保留占位，Stop() 不在 0.1.0 引入。

## 产品需求描述

### 使用者与范围

Agent 需要发现和调用工具、读取技能、操作执行环境、与人和其他 Agent 协作，并查看自己发起的工作。装配者需要知道系统提供哪些共同入口，安全管理者需要知道这些入口怎样受权限与环境约束。元能力为一类操作提供稳定入口，具体词义由 [Meta Capability](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-meta-capability--meta-能力--meta-capability) 拥有。

本文定义入口的用途、命令含义、可观察结果及边界。各命令的精确参数、公开类型、运行协议和实现选型由技术设计承担。入口不取得被调用领域的业务所有权，也不以一次工具成功宣布业务完成。

### 必需入口、常驻与命令可用性

采用并提供的元工具是 Agent 的必需入口，不能由装配者禁用、移除，或用 customized 实现覆盖。元工具必定常驻，普通工具也可以常驻，但不会因此成为元能力。每个多命令入口占一个槽位，入口后的工具或动作数量增加，不使其槽位数量增加。额外常驻的普通工具单独占位。

这里的必需绑定约束作用于实际采用的入口集合。尚未实现的定义和纯占位不因此进入模型工具清单，也不计入已经交付的槽位预算。不能由本文列出的名称总数推导当前部署具有同样数量的入口。

每个已定义的多命令入口提供 `help`，可查询命令清单或指定命令的详细用法。常驻定义只展开一行一命令的紧凑清单，完整参数和用法按需经 `Tools().inspect` 或该入口的 `help` 取得，两处说明保持一致。尚未定义的占位不据此获得命令。

命令权限与入口绑定分别判断。权限可以使一条命令不可用，不能移除整个元工具。调用方仍能看见合法已知的命令、不可用状态和具体原因。依赖或设施缺失也必须明确呈现，不能隐式换用另一入口或更宽松环境。共同的动态可用性、替换件和发起前复核归[工具执行](../tool-execution/design.md)。

### 入口清单与分工

| 入口 | 用途 | 已定义命令或状态 | 执行条件 |
| --- | --- | --- | --- |
| [Tools()](#meta-tools) | 发现、查询和调用工具，取回原结果 | search、inspect、execute、read_result | 执行沿目标工具；结果读取按当前资格 |
| [Skills()](#meta-skills) | 发现技能、读取方法及资源、运行随附脚本 | search、read、exec_script | 读取与执行分别准入，脚本需相应环境与设施 |
| [Files()](#meta-files) | 结构化文件操作 | read、open、write、edit、patch、list、find、info、move、copy、delete、mkdir | 采用本次合法执行落点 |
| [Shell()](#meta-shell) | 命令行与终端会话 | create_session、execute、close_session、info | 采用本次合法执行落点 |
| [Web()](#meta-web) | 搜索和取得网络内容 | search、fetch | 网络设施 |
| [Browser()](#meta-browser) | 按页面结构操作浏览器 | open、act、read、shot、tabs | 浏览器设施 |
| [Computer()](#meta-computer) | 按像素操作图形界面 | 基础、精细、窗口和应用动作，及 help | 图形界面设施 |
| [Agents()](#meta-agents) | 派发工作及与其他 Agent 通信 | spawn、delegate、handoff、message、withdraw、status、list_targets、list_dispatched | 目标可用、派发或通信资格成立 |
| [TodoItems()](#meta-todo) | 维护本会话的待办条目 | add、remove、mark_complete、list | 本会话范围 |
| [BkgJobs()](#meta-background) | 观察和控制本会话的后台执行 | list、output、terminate | 原执行及控制资格 |
| [Ask()](#meta-ask) | 向人提问或请示 | ask、request_approval | 会话协作模式、命令可用性与答复资格 |
| [Cordis()](#meta-cordis) | 只读检视自身装配与公开契约 | list、query；产品定义保留，未承诺实现 | 获准检视范围与实际检视提供者 |

| [Code()](#meta-code) | 运行 Agent 编写的工具编排程序 | help、execute | 受限前台编排；目标工具显式许可 programmable 并逐次准入 |

### 会话授权上下文

[会话授权上下文](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-session-authorization-context--会话授权上下文--session-authorization-context)保留用户在会话中表达的授权及撤回，按先后只追加，不覆盖先前记录。它记录用户表达，不保存一份脱离当前条件的“已获准动作清单”。归档不删除该数据，撤销归档也不恢复已取消的工作。

一笔授权表达有来源、方向及作用域。来源可以是结构化操作或自然语言，方向可以是给出或撤回。人通过卡片自由作答或主动发消息表达的意思同样需要识别，不能只认系统主动询问后的按钮。

| 作用域 | 覆盖范围 | 承载与生效条件 |
| --- | --- | --- |
| 这一次 | 明确批准的下一批工具动作 | 留在本会话授权上下文，批次完成后不扩大到后续动作 |
| 本会话 | 该会话中明确授权的后续动作 | 留在本会话授权上下文，撤回后后续求值不再沿用 |
| 全局 | 该租户后续会话中明确授权的动作 | 由具备资格的主体落成租户层权限设置值，不以当前会话记录替代跨会话设置 |

具体作用域由人表达，系统不得替人扩大。授权意图明确而作用域含糊时取最窄范围；连是否批准都不明确时，不生成批准。能表达全局意图不表示有权修改租户设置，生效资格、设置合成和撤回规则由[身份与授权](../identity-and-authorization/design.md)及[资产与规则](../assets-and-rules/design.md)拥有。工作区不参与授权与权限设置，无论试图放宽还是收紧。

会话授权上下文应能被获准的 Agent 感知，避免依赖模型记忆或重复请示。提供给模型的内容仍受秘密与可见性规则约束，存放和生命周期归 Session。

### 动作放行与环境准入

动作放行组合权限设置、会话授权上下文及会话运行模式，依次作如下判断。权限设置自身的锁定上界、具体值及合成算法沿[现行授权架构](../../../../docs/architecture/security/identity-and-authorization.md)，不在这里另定固定层级交集算法。

1. 求得当前合法执行权限。有效结果为禁止时拒绝，不出卡片，授权表达及运行模式不能翻转禁止。
2. 有效结果为自动时，权限判断可放行，不要求额外授权表达或运行模式确认。目标资格、参数、环境等其他准入仍须满足。
3. 有效结果为问一下时，结合当前授权表达判断这次动作是否已获准。每次重新求值，撤回对后续调用生效，不能用缓存批准替代当前资格。
4. 仍需决定时使用会话运行模式：`never` 拒绝，`auto_permission` 请求人工判断，`bypass-permissions` 跳过本次询问。任何模式都不能越过有效禁止。

放行判断本身不可用时，系统按现行 Agent 与 HITL 的默认拒绝规则处理需要该判断的动作，不因自动权限或 bypass 模式放行，也不假装已经取得人工决定。动作获准后仍须通过执行环境准入；设施不足或落点不可用时明确拒绝，不退到宿主机或其他宽松落点。

子 Agent 的权限不得宽于派发者的合法权限，也不得超过子请求的范围。父处于 `never` 时，子不能借自己的 `request_approval` 取得更宽权限。具体继承与持续复核沿身份、Agent 和 Session 的拥有者规则。

<a id="meta-tools"></a>
### Tools() 工具发现、用法与结果

| 命令 | 产品含义 |
| --- | --- |
| search | 按目的发现本会话合法纳入的已知工具 |
| inspect | 取得工具及命令的完整参数说明和用法 |
| execute | 用给定参数发起目标工具调用 |
| read_result | 按原调用取回被卸载的原结果，必须支持分页 |

搜索包含常驻和非常驻工具。常驻工具须标明可以直接调用，非常驻工具须能继续取得用法。已知不可用工具仍返回其合法保留的身份、形状及原因；从未合法纳入的资产不显示，历史身份也不授权读取撤权后的新内容。

execute 本身不装载新能力、不扩大动作空间，也不因取用而改写系统提示词。没有另行发生定义或能力数据更新时，取用前后的提示词保持。底层工具、Skill 或 MCP 的数据及实现更新不要求替换访问入口或重建 Agent runtime。

read_result 查询的是一次调用的产物，不要求调用方知道内部文件路径。取回分页形成新返回，不重做原效果、不覆盖旧占位；结果保管、全文保留和当前读取资格归 Tool。目标工具的[可编程调用许可](../tool-execution/design.md#可编程调用许可)须在发现和用法中可辨认，经 execute 间接调用也不能避开。

<a id="meta-skills"></a>
### Skills() 方法、资源与随附脚本

| 命令 | 产品含义 |
| --- | --- |
| search | 按任务发现合法已知的技能，说明实际来源及不可用原因 |
| read | 按需读取技能正文或指定资源文件 |
| exec_script | 显式执行当前合法技能实现随附的指定脚本 |

read 是读取，不是激活。正文成为本次返回，不建立“已启用”状态，不因读取改写系统提示词，不运行脚本，也不自动装载全部附件。上下文不再保留正文时可重新 read，无须恢复激活状态。

exec_script 只能运行该技能实际携带的脚本，不能运行任意路径或其他技能的脚本。使用权按技能判断，并继续满足具体动作、资源与环境准入。允许审核过的技能脚本而禁止任意 Shell 执行，是可表达且须生效的策略。路径变化不能把技能入口变成通用命令入口。

读取和脚本执行分别核对资格与当前实现。实际执行固定本次输入、实现及合法环境，按所需设施求得落点，不因为技能脚本而豁免隔离。依赖不足时 search 仍说明缺项；仅脚本设施或执行依赖不足时 read 应返回正文还是替换件，沿 [Q-SK08](../skills/design.md#q-sk08-只有依赖或脚本设施不足时正文是否仍可读取)保留未决，不从搜索结果或历史可见性推导读取许可。

技能设置按类别提供：偏好和绑定值给获准的正文消费者及脚本；落点与身份值只给对应获准脚本，不进入 Agent 上下文。读取正文不授予秘密读取或向模型发送秘密的能力。精确规则由[Skill 产品](../skills/design.md)拥有。

工作区技能包可以处于 Agent 能访问的目录。Files 或 Shell 按自身资格读写这些文件，不表示已装配版本自动更新，也不借用技能权限取得额外通用执行权。作者创建、编辑和装载技能不属于这三个取用命令。

<a id="meta-files"></a>
### Files() 文件操作

| 命令 | 产品含义 |
| --- | --- |
| read | 读取文件内容 |
| open | 打开支持的图片并返回附件和图片内容 |
| write | 整份写入或覆盖 |
| edit | 精确修改一处，匹配不准确时明确失败 |
| patch | 一次修改多处或多个文件，全部预检通过后才提交 |
| list | 列目录 |
| find | 分别支持按文件名和按内容查找 |
| info | 查询大小、修改时间及是否为二进制等文件信息 |
| move、copy、delete、mkdir | 移动、复制、删除和建目录 |

write、edit、patch 分开表达整份覆盖、单处修改和批量修改，不能以“尽力匹配”修改不确定的位置。多次 edit 中途失败，不撤销此前已经成功的修改。delete、覆盖写入及其他已发生外部效果不因工具内置或资源释放而可逆。

#### patch 的预检、提交和恢复

| 情况 | 文件结果及必须交回的信息 |
| --- | --- |
| 任一预检失败，例如第三处原文不匹配 | 所有目标保持未改，说明失败位置与原因 |
| 整批提交成功 | 明确成功及实际修改范围 |
| 写入故障、进程崩溃或回执不能确认 | 明确未知与已确认范围，保留原批次的恢复责任，不宣称全成功或完全没改 |

全部校验完成前不能开始修改。预检的全有或全无不等于多文件提交对外同时可见，外部进程可能看见中间状态。恢复认回原批次，不能把未知当普通失败自动重发。恢复遇到外部后续写入时明确报告冲突，不覆盖新内容，不隐瞒未解决的部分修改。

#### 文本、差异与图片

文本结果采用 Unix CLI 风格，清楚区分成功、拒绝和未知，保留路径、版本、分页及截断信息，不用 JSON 对象正文代替可读文本。edit、patch 返回 diff。中文、CRLF 和无末尾换行的文件不得因展示或编辑静默改变文本。截断须说明范围；未知时区分计划差异与已确认改动，计划 diff 不证明整批落盘。

open 支持静态 PNG、JPEG 和 WebP，以已确认附件及图片内容块交付。文本说明图片与附件，不包含 base64 图片正文。损坏、动画、超限或不支持的图片明确拒绝，不默取动画首帧。Files 不另发进度流。图片能打开不表示模型能采用它，附件读取与模型模态继续各自核对。

每次文件操作按当前权限、设施和已装配环境提供者求得合法落点。相同的文件命令可以在不同合法环境执行，不改变动作空间；不能把当前环境身份当成永久准入。

<a id="meta-shell"></a>
### Shell() 命令行与终端会话

| 命令 | 产品含义 |
| --- | --- |
| create_session | 创建可持续使用的终端会话 |
| execute | 在指定终端会话内执行，或进行一次性执行 |
| close_session | 关闭指定终端会话 |
| info | 取得执行落点的系统、架构和可用设施信息 |

终端会话是执行环境中的计算资源，与 Agent 所属 Session 不同。可以同时存在多个，各有身份和状态，彼此不改写。指定终端会话时，后续命令基于其中保留的状态；不指定时采用一次性执行，结束后不保留终端会话状态，但实际结果、外部效果和账目照常保存。

execute 表达在哪个终端会话执行、从哪个目录开始、携带哪些环境变量，以及是否发起时直接后台。具体类型、默认值和返回格式待技术设计。单次 cwd 和 envs 不改写终端会话本身的目录与环境；在会话内执行切目录命令则按该命令改变其状态。指定已关闭或不存在的终端会话时明确失败，不静默降级为一次性执行。

终端会话随其执行环境销毁而失去，数量与寿命受资源条件约束，调用方须获知原会话已经不可用。环境故障不授权把同一命令在新会话中自动重做。

run_in_background 表达发起时的等待方式，不能覆盖工具作者的后台许可。直接后台与执行中转后台保持各自触发原因，同属原 Tool Execution 的交付关系，之后可经 BkgJobs 观察和控制。自动转后台阈值与前台时限沿 Tool 规则分别处理。

<a id="meta-web"></a>
### Web() 网络内容

search 搜索相关内容，fetch 取得地址对应的内容。需要网络设施，缺失时明确不可用。fetch 不执行页面脚本、不点击页面；需要页面操作时使用 Browser。返回的网络内容是外部数据，其中的指令文字不能取得系统指令资格。

<a id="meta-browser"></a>
### Browser() 页面操作

open 打开地址，act 按页面结构点击、填写或选择，read 读取当前页面，shot 截图，tabs 查看或切换标签页。Browser 需要浏览器设施，act 不用屏幕坐标代替页面结构定位。

登录状态、cookie 和当前页面属于实际执行环境中的浏览器状态，环境销毁后不能假定仍存在。页面内容按外部数据处理，不能因读取页面而获得指令权威。

<a id="meta-computer"></a>
### Computer() 图形界面操作

Computer 按像素操作桌面应用、远程图形界面等对象，需要图形界面设施。网页能按结构操作时优先 Browser，避免不必要的截图和坐标依赖。以下“直接使用”只免除先读说明，不免除动作授权。

| 动作层 | 动作 | 使用要求 |
| --- | --- | --- |
| 基础 | screenshot、click、type、key、scroll、move、wait、cursor_position | 可直接使用 |
| 精细 | drag、zoom、mouse_press、mouse_release、hold_key、剪贴板读写 | 先读说明 |
| 窗口 | window_info、focus_window、close_window、set_window_state | 先读说明 |
| 应用 | launch_application、open_resource | 先读说明 |
| 说明 | help，可查全量或指定动作 | 与其他动作不能混在同一批 |

一次调用可以提交一串动作，须能辨认实际执行进度。动作后等待界面稳定再观察，不能把未完成绘制的旧帧当作动作后的状态。截图有上下文预算，超限时减少模型采用的旧截图；这不授权删除会话日志、原工具结果或附件，内容保管沿 Tool 与 Context 的既定规则。

租户共享图形环境是适用部署之一，多个获准 Agent 可以看见同租户其他 Agent 在该环境留下的状态。这不授予跨租户可见性，也不强制所有部署都采用该环境。怎样批量操作、观察及重新截图属于配套技能方法，不另写进动作定义。

<a id="meta-agents"></a>
### Agents() 派发与通信

| 命令 | 产品含义 |
| --- | --- |
| spawn | 以派发时模型上下文的副本创建子会话并派发工作 |
| delegate | 以明确 instruction 创建子会话并派发工作 |
| handoff | 以交接说明创建独立主会话 |
| message | 向符合通信规则的 Agent 发送普通消息 |
| withdraw | 显式撤回 spawn 或 delegate 派发的工作 |
| status | 查询直属 spawn/delegate 派发的状态及已有报告；handoff 创建后的查询对象与范围待 META-P03 |
| list_targets | 列出当前可以派发的定义或外部目标 |
| list_dispatched | 列出本会话的派发历史 |

#### 三种派发模式

| 维度 | spawn | delegate | handoff |
| --- | --- | --- | --- |
| 会话关系 | 当前 Session 的子会话 | 当前 Session 的子会话 | 独立主会话 |
| 初始输入 | 派发时组装给模型的上下文副本 | instruction | handoff 说明 |
| 派发者控制 | 可显式撤回派发工作 | 可显式撤回派发工作 | 不能凭派发关系撤回 |
| 派发调用返回 | 等待一次报告或失败，控制另按 Tool 处理 | 同 spawn | 确认新会话创建成功或失败后返回，不等工作完成 |
| 通信 | 派发者与被派发者双向 | 同 spawn | 派发关系双向，另适用主会话之间通信 |

spawn 和 delegate 可选 master 或 non-master 定义，产生的仍是子会话。handoff 选择符合准入的 master 定义，产生独立主会话，用户可以直接与之交互。定义类型、可见性和派发权限沿 Agent 与身份拥有者规则，不因入口存在而获得派发权。

子 Agent 是独立的 Agent runtime，有自己的装配和动作空间。spawn 的副本成为子会话日志的起始输入，不复制或共享父会话日志节点，也不指向父日志。父在派发后产生的内容对子不可见，需要继续发送消息。delegate 与 handoff 只以明确交给它们的说明开始，不能借派发关系读取父的未提供上下文。

spawn 和 delegate 的报告等待由原 Tool Execution 承担，不新建另一套工具收场。现行 Tool 规则只允许需答复执行在前台等待，不能从派发可能很久推导允许转后台。派发等待如何精确接入该规则，见 [META-T02](#meta-t02)，不得沿用与其冲突的后台等待承诺。

#### 双向通信与消息失败

通信有两条独立路径：派发者与其直接派发的 Agent 可以双向通信；同租户、具有独立主会话身份且未归档的 Agent 可以相互通信，不要求派发关系。共同的租户隔离、当前资格及归档准入仍须满足。

兄弟子 Agent 和隔代子 Agent 不因同祖先取得彼此通信资格，也不具备独立主会话路径。不同租户不通。接收方已归档时拒绝新的任务消息并明确告知，不暗中排队或自动唤醒。拒绝须区分关系不成立、身份不符、归档或租户边界等原因，同时不泄露未授权对象内容。

#### 一次报告与后续消息

报告终结一次 spawn 或 delegate 派发，结束对应等待并交回工具结果；普通消息可以往返多次，不终结派发，不替代报告。每次派发最多一份报告。发起方可附报告形状的期望，系统交给被派发者并随报告回显供比对，但不把期望变成强制格式校验。

交回报告不归档子会话，不表示子 Run 必然终态，也不强制销毁子 Agent runtime。报告后仍可沿合法通信路径发消息。未归档的接收会话已有未结束 Run 时按输入规则追加，否则可触发新的 Run；不补交第二份报告、不复活旧派发，也不为后续消息发明同会话并行派发机制。

#### 派发控制与会话归属

withdraw 控制被派发的工作，不把子会话或其 runtime 寄宿于父 Agent runtime。父 Run 取消或父 Agent runtime 释放，不隐含取消子会话及其执行。父 Session 归档沿子会话关系递归归档，handoff 的独立主会话不在此范围。

归档取消已受理但未处理的新任务，保留历史；撤销归档不自动恢复旧任务。已发执行的迟到结果、外部效果和账目按原归属保存。请求撤回、实际停止和外部效果分别报告，不假报停止成功。成本归最初发起方的租户，不随继续派发的层级漂移。

list_dispatched 是派发历史，不能替代 Session 对子会话关系及主 Agent 管理全部子会话的能力。Session 没有因报告或一次 Run 结束而删除、回收或终态的规则。

#### 外部 harness 派发

系统保留向外部 harness 派发任务的产品能力，接入采用已要求的 ACP 范式，具体协议与装配仍须技术设计。外部目标不成为本系统的子会话，其身份和权限不能假装继承本系统的一套权限。

能否派给该外部目标须显式获准，任务说明离开系统属于对外输出，不能因称为派发而声称可撤回。message、withdraw 等控制取决于对方真实支持，缺失或确认未知须如实报告。外部报告按外部数据处理，不获得指令权威。租户、输出与成本责任仍由本系统实际拥有者承担。

<a id="meta-todo"></a>
### TodoItems() 本会话待办

add 新建一条，remove 移除一条，mark_complete 将一条标为完成，list 查看全部条目。每条待办有自己的身份与状态，写操作逐条生效，不以整份覆盖改写其他条目。标为完成后仍能看到完成项，移除与完成分别表达。

待办是 Agent 用于组织工作的清单，不是系统自动执行的任务。加入条目不触发执行。待办归当前 Session，不跨会话继承；Run 结束或 Agent 替换不能凭空更换会话范围。跨会话工作对象不由此入口补造，其来源待办继续登记在[领域对象待裁](../../domain_objects/pending.md)。

<a id="meta-background"></a>
### BkgJobs() 后台执行

list 列出本 Session 的后台执行，output 读取原执行的可见状态及合法结果内容，terminate 请求中断自己有权控制的执行。人用过程帧只供人观察，不因通过 output 就进入模型上下文；模型可读的中间输出范围及读取协议仍须明确，不在此扩展。后台跨轮存在仍可观察，不能因 Agent runtime 换代就失去原身份。该入口不显示其他 Session 的执行，也不以查不到暂时状态认定执行已经丢失。

Agent 主动中断与用户叫停均须保留发起者及原因。中断不记成普通失败，也不授权自动重试；实际停止是否成立与外部效果分别核实。Session 归档沿 Tool 的业务取消和控制传播规则处理，历史、真实结果和账目不因入口停止接受新动作而删除。

<a id="meta-ask"></a>
### Ask() 提问与请示

ask 获取只有人能给的输入；request_approval 请求对明确动作的准驳。两者都发生在所问动作实施之前，不能先实施再请示。系统应一次收齐当前需要的问题，避免多轮逐个打断。

#### 问题与请示的内容

ask 可以一次包含多个问题。每个问题必须有清楚的问题描述、文本设计项，以及系统保证的自由作答途径。图解可辅助比较，不能代替选项文本，也不为简单选择添加无用展示。人可以不选任何候选项，直接表达自己的答案。

request_approval 固定提供同意、不同意，并保留自由作答。请示必须说明具体动作及对象、原因、影响范围、可撤回程度，以及拒绝后的备选或停止后果。人给出的原话若不能明确判为准或驳，就交回原话并标明尚无裁决，不猜一个答案。Agent 可据此调整动作后重新请示。

批准只覆盖人看见并批准的明确动作或整批动作，计划、参数、实现或授权依据出现实质变化时重新核对。系统不因普通重载重复请示，也不把单次批准扩大为整个 Run 的所有动作。有效批准或撤回沿本页的[会话授权上下文](#会话授权上下文)及当前授权规则处理。

#### 协作模式与命令限制

Ask 人交互能力由 Session 协作模式独立控制：co-work 开启，auto-drive 关闭。关闭不移除、禁用或替换元工具的必需绑定，也不自动授权原本需要判断的动作。切回 co-work 后仍按当前权限模式核对命令。

never 使 request_approval 不可用，单独并不禁止 ask；ask 是否能发起交互还取决于协作模式。父的权限与模式限制不能由子会话绕过。在途交互怎样衔接沿 HITL 与 Session 契约，模式切换不能伪造人类答复。

#### 等待、答复与恢复

Ask 使用 Tool 内部等待与 HITL 的卡片、答复能力。它在前台等待，不转后台，没有超时和默认答案。前台上限不计算内部等待时间。上述规则不以“零资源消耗”为前提，真实并发名额及资源仍按 Tool 处理。

普通输入继续可靠受理，但不自动回答卡片，其他会话可以工作。人的有效答复必须回到仍有效的原等待，答复者有当前资格，同一卡片最多一次有效决定。自由作答与明确不回答都由系统支持，不依赖 Agent 记得添加出口。

| 情况 | 可观察后果 |
| --- | --- |
| 人有效回答或明确批准、拒绝 | 原等待取得一次有效应答，工具按其结果继续 |
| 人在卡片上明确不回答 | 返回“没有答案”，不是失败或批准；多问题批次按其原规则收齐 |
| 人明确插队并解除原等待 | 按当前输入与 HITL 规则处理“拒绝回复”，原 Ask 被中断，不伪造准驳 |
| 人叫停或原 Run 被合法取消 | 原工具按中断和等待解除规则处理，卡片不补答案 |
| Session 归档 | 业务取消原未完成调用，解除等待，保留已有事实 |
| 仅 Agent 退出、查询不可用或服务重启 | 不据此认定原执行丢失，不作废有效卡片，恢复时认回原等待及已得决定 |
| Tool 可靠确认自身连续性丢失并终局失败 | 保存失败及异常中断原因，原卡失效且无伪造答案，是否新问由合法调用方另定 |

Ask 不产生“等到期限算同意或拒绝”的结果，也不以转后台占位解除原回答义务。具体卡片、输入插队、资格和恢复沿[人在回路](../human-intervention/design.md)、[会话与工作](../sessions-and-work/design.md)及[工具执行](../tool-execution/design.md)的当前规则。

#### 减少无效打断

Agent 不应询问自己能查到的事实，不作无信息量的开工礼貌确认，不为权限已经明确禁止的动作另问一次，也不对仍在有效授权范围内的同一动作反复请示。动作改变时须重新说明。不能为了减少打断扩大授权，不能为了推进任务把没有回答变成默认答案。

<a id="meta-cordis"></a>
### Cordis() 只读检视装配

Cordis 的产品定义保留，尚未承诺实现。list 给出可检视的类别和问题范围；query 对一个获准的检视面提出精确问题，取得该处完整的公开契约。概览与细查分开，不能把全系统完整契约一次塞进上下文。

可贡献的检视内容包括服务公开方法及签名、活跃插件及父子关系、注册工具的参数形状、本 Session 动态装入与初始装配的区别、事件名称与形状，以及界面侧可贡献 UI 的位置。签名不是服务实现，也不授予调用或读取秘密的资格。

检视内容由提供能力的插件贡献，list 随实际注册变化。没有贡献检视面的插件不会被虚构为可查询内容；不需要维护一张独立静态总表。

查询区分宿主侧与界面侧。只部署宿主侧的装配只报告该侧，不能从单机部署推导一定存在或不存在界面侧。界面侧需要实际连接的页面，未连接时如实不可用，不降级或猜测状态。

必须守住以下边界：不能调用所见服务的方法，不能修改配置，不能执行所生成的代码，只能看到当前主体获准的自身装配范围，不能看到整个部署的其他租户。编写插件前了解可用契约与了解自身装配可使用同一入口。修改装配、安装、移除和持久配置更新属于其他获准能力，不能从只读 query 扩展出来。

<a id="meta-engram"></a>
### Engram() 知识结构占位

Engram 仅保留知识结构元能力的定位：对象是知识能有哪些类型、如何连接及哪些组织方式合法，不等同于记录一条记忆。它属于 Agent 自身结构的能力方向。

本页不定义其命令、数据结构、演化协议或实现，也不要求实现交付。它与 Session log、记忆内容及卸载附件的边界须在后续实际设计时明确。外部参考系统的特性不构成本项目已采用设计。

<a id="meta-code"></a>
### Code() 程序化工具编排

Code() 是已选定名称的独立 meta tool，负责执行 Agent 编写的工具编排程序。Agent 可以按顺序、条件或并行组合工具调用，对结果筛选、计算，再把所需输出交回模型。一次程序执行及每次子调用均沿 Tool Execution 承接，不新增第四类领域运行时。

Code 拥有程序推进与组合输出，Tool 拥有每次调用的准入、执行和结果，执行环境拥有代码限制与资源控制。Tools 继续承担发现、用法、单次调用及结果取回。Shell 执行环境命令，Skills 执行指定技能随附脚本；它们不会仅因可以运行代码而取得 Code 的编排通路。

#### 从用法到一次执行

| 命令 | 产品含义 |
| --- | --- |
| help | 取得程序写法、受控工具调用与输出方式、限制，以及指定命令的用法 |
| execute | 提交一段程序及明确输入，执行获准的工具编排，交回程序结果和真实执行状态 |

Agent 先通过 Tools 发现目标并取得完整用法，再提交程序。Code 的用法必须给出实际支持的语言及版本、可用标准能力、工具调用方式、结果表示和错误处理方法。不能让模型猜测语言或依赖上游项目的私有约定。语言、精确参数和执行引擎由技术设计固定，不在产品页指定实现。

程序及显式输入是本次调用的内容。可信租户、原 Session 和 Run 关联、动作授权、实际工具绑定、结果保管及资源限制由宿主提供，不能由程序自报。程序不能选择另一租户、替换发起者、伪造批准或取消关联。一次调用采用的程序与输入在发起后固定，修改程序形成新调用。

Code 的程序内存只服务本次调用，不提供跨调用的隐式变量、终端会话或可恢复程序栈。显式输入和返回值跨界时必须可校验；无法表达的值明确报错，不能静默丢字段或改变值。准确的数据形状归公开契约。

#### 取得可调用工具并逐次准入

程序取得的是受控调用能力，不是工具实现函数或运行时句柄。可调用集合只包含已合法纳入、当前可用且显式声明 `programmable: true` 的工具。调用方可以进一步缩小范围，不能扩大范围。既有发现入口可以解释合法已知工具不可用的原因，但不得因此授予程序执行资格。

每次实际发起前，包括排队后启动前，重新核对当前许可、身份、参数、定义与实现匹配、授权、环境及人工判断。旧清单和已创建代理不是长期许可证。调用约定或绑定变化不能静默修改原请求，须返回具体原因，由合法调用方重新判断。

经 Tools.execute、SDK、Skill 或其他包装入口转发时，真实目标仍沿可信编排来源核验。程序不能把来源改成直接调用。MCP 工具和其他元工具没有例外；未许可的目标不执行，原调用位置收到可辨认的拒绝或不可用结果。

Code 自身不开放可编程调用。直接或间接递归调用 Code 均不支持，避免把程序组合变成无界调用链及同工具名额相互等待。普通工具代理也不能向程序暴露私有 executor 来绕过这项限制。

#### 顺序、条件、并行与子调用结果

顺序路径等待所依赖的真实结果后才继续。条件路径只发起实际选中的分支。并行路径允许多个相互独立的调用在途，但每个子调用仍计入同一 Session 下目标工具的并发名额，超额调用按目标队列等待。Code 的一次外层调用不能代替全部子调用计数，也不能把它们伪装成独立消费者绕过限额。

每个已受理子调用须关联原 Code 调用及可稳定辨认的程序调用位置。并行返回按该位置交回，不能依返回先后错配。相同参数的两次显式调用仍是两次动作，系统不能擅自合并；重传、查询或恢复原身份也不能变成新动作。

程序读取子调用的正式结果，能够分辨完成、失败、不可用、被中断和其他适用状态。程序可以显式处理可处理的失败，选择后续分支；未处理的程序异常使 Code 失败。拒绝、未知及失败不能转换成空值或成功。程序处理了某项失败，也不能改写该子调用原来失败的事实。

Code 不提供让子调用脱离程序、无人接手结果的发起方式。程序正常结束前，所有已受理子调用须有已知终局，其结果须有明确承接者。程序正文先返回但子调用仍在途时，Code 仍未完成。程序异常或被中断时可先报告其自身终局，但必须显示仍未收场的关联调用及后续责任，不能报告整批动作已经停止。

#### 前台、外部答复与控制

Code.execute 采用前台编排，不声明后台许可。它本身不能通过阈值、用户操作或插队转后台。目标工具的后台许可不改变 Code 的等待关系；子调用若按自己的规则转后台，Code 仍等待其最终结果，不能把后台占位当作数据结果或据此宣告编排完成。Code 不开放显式脱离等待的子后台作业模式。

程序等待子结果、子工具等待外部答复、当前模型步骤等待 Code，是不同关系。普通程序等待不能自动冒充 Tool 的资源应答等待。某个子调用需要人或其他主体答复时，仍由原工具和 HITL 维护原等待、原卡及有效决定。Code 须让等待原因和对应子调用可观察，不复制卡片或代人回答。

Ask 仍只能在前台等待，无超时、无默认答案。关联 Code 等待须保留该语义，不能把程序的计算限额或父调用计时变成 Ask 的隐式答复期限；等待与计时的精确交接由技术契约落实。普通输入不自动回答原卡。并行的其他合法分支可以继续，各自仍受准入与资源限制。工具已经转后台后，不得再开启需答复等待。

用户停止 Code 时，先阻止程序继续发起子调用。控制结果须列明本次关联的未完成子调用，并按当前控制资格向这些调用请求停止，包括已经转后台但仍由 Code 等待的调用。每项分别报告受理、拒绝、未知和实际收场；不能因为程序已停就报告全部子调用已停。控制不影响无关工具或会话。Run 取消、Session 归档的通用传播范围保持原规则，不能由本条扩成取消所有后台工作。

程序未处理异常、资源耗尽或确认失去连续性时，停止新推进。宿主须向当前有控制资格的全部关联未完成子调用逐项请求停止，包括已转后台的子调用；无权控制、停止被拒或结果未知的调用继续保管和跟踪，不能静默遗弃或假报已停。必要的停止或保管失败保持可查询。销毁执行域不能解除子调用的结果、费用及控制责任。

Run 取消触发的 Code 中断须保留原取消原因，只沿 Run 原有传播范围控制子调用，不能改记为程序异常以扩大到全部后台调用。Session 归档仍沿其自身对全部原未完成调用的规则传播。其余未收场调用由宿主沿原身份承接，不能再交给已停止的程序。

#### 受限执行与输出

程序仅取得明确输入、语言计算能力和受控工具通路。它不能直接取得 Cordis Context、全局服务容器、宿主对象、凭据、任意模块加载或宿主文件、网络、进程能力。需要文件或网络动作时，经已许可的工具发起，工具仍在自己的合法环境执行。Code 的执行环境不替全部子工具统一选择落点。

执行环境须兑现时间、内存、并发、输出及宿主调用的限制，并能终止不合作程序。无法建立限制时拒绝执行，不降级到宿主或更弱环境。部署按合法资源策略提供限额，程序只能请求更小范围，不能提高上界。限额须可查询，超限须说明具体原因；等待、停止和结果保管所需资源不能靠丢弃原责任回收。实际引擎、数值及隔离证据沿执行环境技术设计。

子调用的完整结果保留在原 Tool 调用下。程序消费其中当前有资格读取且可表达的内容，图片、附件、卸载结果不能被隐式丢弃或转换成猜测的文本。需要读取原文或附件时，仍经具名受控读取通路核验资格。精确模态、附件与分页表示由 Tool 结果契约承接。

程序显式选择的输出组成 Code 的最终结果，模型不自动收到每次子调用全文。空输出须与程序失败区分。超限输出沿 Tool 的卸载和取回规则保管并给出明确占位；输出转换或保管失败不能伪报成功，也不能重跑程序补结果。中间工具过程帧仍给人观察，不因为程序需要数据就变为模型可读输入。若要消费中间结果，须由目标工具另有明确的可消费结果契约。

外层结果附有可核验的子调用关联及未完成责任，程序自己的摘要不能遮掉真实失败或停止未知。各子调用结果、实际成本及原执行事实分别保留，Code 只记录自身实际计算及资源成本，汇总不重复记费。程序读到返回值或输出汇总，不单独构成原结果已经可靠交接。

#### 故障与接续

仅 Agent 被替换或失去观察连接时，按原身份认回仍存活的 Code 和子调用。查询暂时不可用保持未知，不宣告丢失，不重发程序。程序连续性已经确认丢失时，Code 按异常中断失败收束，保留已发生、未发生及未知的子调用事实；不从头重跑，也不默认从某一行接续。

原结果、已有效的答复、尚未收场子调用及迟到效果仍由宿主和原 Tool 拥有者保管、查询与对账。结果不能只投给已经销毁的程序。需要补偿或再次执行时，由合法调用方核查后发起新动作，明确它可能产生新的效果和费用。释放 Cordis 资源不撤销外部写入。

#### Code 的可观察判据

以下是产品验收标准，不表示已经运行测试。采用 Code 的交付必须同时覆盖正常组合与相关失败路径。

| 标识 | 场景 | 必须可观察的结果 |
| --- | --- | --- |
| CODE-A01 | 顺序读取、条件分支与并行汇总 | 仅选中分支执行，依赖正确结果；并行乱序回包不串位置，最终输出可供模型使用 |
| CODE-A02 | 省略或关闭 programmable，经包装入口重试 | 目标不执行，拒绝原因可辨；直接模型调用的原资格不受误伤 |
| CODE-A03 | 发现后撤权，排队后变更许可或绑定 | 启动前复核，失效调用不启动，不能沿旧代理或暗改参数执行 |
| CODE-A04 | 并发达到目标工具限额 | 每次子调用按真实 Session 计数并排队，后台及内部等待不偷放名额 |
| CODE-A05 | 子工具需人工答复，另有并行分支 | 原卡只产生一次有效决定，等待不造超时默认答案，其他合法分支可推进 |
| CODE-A06 | 子工具转后台或程序提前返回 | 后台占位不当最终结果，Code 不提前报告完成，无未登记的遗留执行 |
| CODE-A07 | 部分子动作成功后程序抛错 | Code 失败，向有权控制的关联未完成调用逐项请求停止；原成功、失败及在途动作分别可查，无回滚或自动重试声明 |
| CODE-A08 | 用户停止 Code，或 Run 取消时部分子调用仍在执行 | 新调用被阻止，按真实原因选择控制范围，Run 取消不被改写成全树停止；逐项报告真实结果，迟到输出和费用仍有拥有者 |
| CODE-A09 | Agent 换代、查询失联、程序连续性确认丢失 | 先认回原身份；未知不重发，确认丢失不重跑，原结果和有效答复不丢 |
| CODE-A10 | 读取秘密、直接访问宿主或递归 Code | 无获准通路则拒绝，不取得宿主对象，不通过转发洗去编排来源 |
| CODE-A11 | 死循环、内存或输出超限 | 能实际限制或终止代码，准确报告超限，已发工具继续由宿主承接 |
| CODE-A12 | 大结果、附件、空输出、子结果交接确认未知 | 原结果可依法取回，空输出不冒充失败，确认未知保留交付责任，汇总不重计子费用 |

<a id="meta-t02"></a>
### 派发等待与既有边界

spawn/delegate 必须等待报告或失败，且报告、普通消息与子会话存续分别判断。Tool 产品仅允许需答复执行在前台等待。派发的接续、取消、查询未知及报告交接须按该边界补齐精确契约，不授予后台等答复能力。未补齐前不能声明技术设计完整；报告与通信规则仍须遵守。

<a id="meta-p03"></a>
### handoff 后的 status 范围

spawn/delegate 的直属派发可查询状态及已有报告。handoff 创建确认之后，原派发调用已经返回，目标是独立主会话。尚缺一致依据来决定 status 此时查询创建结果、继续读取目标工作进展，还是不支持该模式的查询。产品负责人须先明确查询对象及模式范围，技术设计不能自行选择。

该分歧只限制 handoff 的 status 范围，不改变既定双向通信、派发历史、创建确认返回及不可撤回规则。它不授权读取目标会话全部内容或绕过当前资格。

### 由其他拥有者维护的缺项

- [Q-SK08](../skills/design.md#q-sk08-只有依赖或脚本设施不足时正文是否仍可读取)拥有技能仅依赖或脚本设施不足时 read 返回正文还是替换件的来源分歧，本页不选答案。
- [领域对象待裁](../../domain_objects/pending.md)继续维护跨会话工作对象、一次派发、Agent 间消息与外部目标的建模缺项；不能由命令名补造身份、存储或生命周期。
- [领域对象清单](../../domain_objects/objects.md)保留 meta 与工具关系及 handoff 是否有报告的未裁内容。handoff 的工具返回仍只确认创建，不等报告。
- Code 的精确协议与验证义务由 [TOOL-M05](../../../../packages/tool/tool-contract/docs/architecture.md#tool-m05)统一定位，Tool、执行环境、Agent、Context 与装配拥有者承接。产品细化不表示语言、公开签名、隔离提供者或恢复协议已获技术接受。

Engram 和 Stop 的占位不是待实施任务，也不是其他元工具设计或交付的前置条件。Stop 不展开功能定义。
