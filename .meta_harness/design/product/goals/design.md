# 目标

## 产品需求描述

用户把一件事交给一个会话里的 agent 时，想说清的不只是「做什么」，还有「做到什么算完」和「做不到时怎么办」。没有这两样，agent 要么做一点就停下来等人，要么一直做下去不知道停。目标就是这份说清了的委托。

目标属于一个[会话](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-session--会话--session)，是一次有限的委托。它不是待办清单，不是定时任务，也不给 agent 任何权限：能做什么仍由权限决定，什么时候再触发一次工作由日程决定。

### 目标的正文

一份[会话目标](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-session-goal--会话目标--session-goal)的正文有七节。

| 节 | 写什么 |
| --- | --- |
| 目的 | 要什么，为什么 |
| 达成 | 每一条[目标判据](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-goal-criterion--目标判据--goal-criterion)：成立是什么样子，证据从哪来，证据要显示出什么才算数 |
| 指标 | 量的是什么，怎样量，方向，目标，可以有底线与基线 |
| 守则 | 从头到尾要守的：不许做的，和必须这样做的 |
| 退出 | 每一条[目标退出路径](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-goal-exit-path--目标退出路径--goal-exit-path)：什么情形该停，停了交什么，算成功还是失败 |
| 依据 | 权威的材料在哪，什么时候读 |
| 做法 | 从哪开始，用什么方法 |

正文对干活的 agent 同时是三样东西：一份约定，一个随时能读数的目标函数，一张上下文丢了能据以找回来的地图。它不是计划，也不是进度。

正文有长度上限，按字符数算。它只当索引：少数几条看得见的判据，材料放在外面由依据指过去。

### 设目标与改目标

用户不需要知道正文的格式。用户用自己的话说想要什么，会话里的 agent 先和用户对齐，缺什么问什么，再起草整份正文，交给用户确认。用户看到的是一张确认卡片，上面是完整的正文。用户可以确认，可以写一句要怎样改，也可以不设。**用户确认之前，目标不生效。**

之后用户查看目标，看到的是这份正式的正文，并能看到它的来历：自己当时的原话，谁起草的，自己什么时候确认的。

用户随时可以改：再说一次自己想要什么，agent 停下手里的活，重新对齐、起草、请用户确认；用户也可以不经过 agent，自己直接改，例如把预算加几轮。标准与预算归用户，用户说改了就是改了。

无人值守的会话里没有人可以对齐。它的目标由建这个会话的一方在建的时候交来，之后不能改。

### 谁说了算

一份目标有一个主人。有人值守的会话里，主人是会话里的那个人；无人值守的会话里，主人是建这个会话的一方。

- 设与改，要主人确认。agent 只能起草。
- 暂停、恢复与取消，只有人能做。agent 不能。
- [目标判定](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-goal-judgment--目标判定--goal-judgment)发现得停下来时，有人值守的会话里目标暂停、交给人；无人值守的会话里目标直接收场。

agent 可以随时看目标与自己离做完还差多少，可以维护一份[目标进展清单](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-goal-progress-list--目标进展清单--goal-progress-list)。清单是 agent 的说法，不是证据：算不算成立，看的是它指到的那些真实的工具结果。

### 推进与收场

目标进行中时，agent 每次想结束这一轮，系统按正文判一次。只有三种出路：

- 做完了，或正文里写的某条退出成立：目标收场。
- 还没做完：这一轮不结束，agent 被告知还差哪几条，接着做。
- 判定发现得停下来，而会话里有人：目标暂停，用户被告知为什么停下、还差什么。之后由用户决定恢复、改目标、取消，或照那条退出收场。

判定不要求目标必须达成。做不到时，它要认出来，照设好的路如实收场，不把没做到说成做到了。[目标结局](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-goal-outcome--目标结局--goal-outcome)写明做到了哪几条、指标最后的值、为什么收场。达成与按退出路径收场，在任何界面上都分开写。

暂停目标不停当前这一轮，取消目标也不停。停一轮是另一个动作。

### 关键用户旅程

**设一个目标。** 用户在会话里说「把首页加载降下来」。agent 问清怎样算降下来、有没有要守住的，起草正文并出确认卡片。用户确认。agent 开始做，用户在目标面板上看到每条判据做到哪了。

**做完。** agent 认为做完了。系统按正文核对：每条判据都有证据并且成立。目标收场为达成，用户看到结局。

**做不完。** 预算用尽时指标到了底线但没到目标。正文里写了「够用」的退出，目标照它收场，结局写明离目标差多少。

**卡住。** agent 连续几次都没有进展。目标暂停，用户被告知。用户给了一条线索后恢复，agent 接着做。

**改主意。** 做到一半，用户说标准放宽一些。agent 起草一份只改那一条的修订，用户确认，agent 照新的标准接着做。

**无人值守。** 一份到点执行的作业带着一份目标新开一个会话。agent 做到达成，或照某条退出收场；判定发现达不成时目标直接收场，作业的结局照目标的结局。

## 能力定义

| 能力标识 | 定义与范围 | 需求位置 |
| --- | --- | --- |
| CAP-GL01 用自己的话设目标 | 用户说想要什么；agent 对齐后起草；用户在确认卡片上确认后生效 | [设目标与改目标](#设目标与改目标) |
| CAP-GL02 正文与来历 | 目标以七节正文存在；用户看到正式的正文与每次修订的来历 | [目标的正文](#目标的正文) |
| CAP-GL03 改目标 | 用户用话说或直接改；每次修订经用户的动作生效 | [设目标与改目标](#设目标与改目标) |
| CAP-GL04 暂停、恢复与取消 | 只有人能做；不经过 agent | [谁说了算](#谁说了算) |
| CAP-GL05 按目标判定 | agent 每次想结束一轮时判一次；出路是收场、接着做，或暂停交给人 | [推进与收场](#推进与收场) |
| CAP-GL06 如实收场 | 做不到时照退出路径收场；结局写明做到了什么 | [推进与收场](#推进与收场) |
| CAP-GL07 看得见差多少 | agent 与用户随时看到每条判据的读数与还差多少 | [谁说了算](#谁说了算) |
| CAP-GL08 无人值守的目标 | 建会话的一方交来正文；不能改、不能暂停；判定发现达不成就收场 | [设目标与改目标](#设目标与改目标) |
