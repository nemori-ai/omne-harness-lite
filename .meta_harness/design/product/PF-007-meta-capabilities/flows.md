# PF-007 流程与状态

`design.md` 说十二扇门**各是什么**，这里说 agent **怎么走它们**。

## 一、主要旅程

### 1.1 agent 想干一件事，但手头没有现成的动作

**这是 meta 存在的主线场景。**

| 步骤 | agent 做什么 | 为什么是这一步 |
|---|---|---|
| 1 | 先看槽位里有没有 | 常驻的直接调，不必绕 |
| 2 | 没有 → `Tools().search` | 装配清单里可能有，只是没常驻 |
| 3 | 找到了 → `Tools().inspect` | **参数格式同样不在系统提示词里** |
| 4 | `Tools().execute` | 全程 **system prompt 不变** |
| 5 | 还是没有 → `Skills().search` | 也许没有现成动作，但有现成方法 |
| 6 | 都没有 → 用世界族的门自己做 | `Shell()`、`Files()`、`Browser()`…… |

**第 6 步是兜底**：十二扇门保证了「什么都没配」也不等于「什么都做不了」。

### 1.2 一件长活：从前台到后台再回来

| 时刻 | 发生什么 | 哪扇门 |
|---|---|---|
| 1 | agent 发起一个要跑很久的动作 | `Shell().run` 或任意工具 |
| 2 | 超过工具声明的时长，**自动转后台**；位置上留占位返回 | [PF-006 §6.6](../PF-006-tools-and-skills/design.md#66-前台后台-与-等待态是两个维度) |
| 3 | agent 去干别的 | —— |
| 4 | 过了几轮，想看看它怎么样了 | **`Jobs().list` → `Jobs().output`** |
| 5 | 发现跑偏了，掐掉 | **`Jobs().terminate`** |
| 6 | 或者它自己跑完了，结果以提醒到达 | 收件人是 **session** |

**第 4、5 步没有 `Jobs()` 就走不通**——那正是这扇门存在的理由。

### 1.3 拿不准的时候问人

| 步骤 | 发生什么 |
|---|---|
| 1 | agent 判断这件事的裁决权不在自己 |
| 2 | `Ask().ask`，**带上选项与各自的后果** |
| 3 | 这次调用进入[等待态](../PF-006-tools-and-skills/design.md#等待态)，agent 停下来等 |
| 4 | 人做了选择 → 拿到应答，继续 |
| 5 | 或者上限到了没人回 → 按[第六种收场](../PF-006-tools-and-skills/design.md#53-一次工具执行的收场有六种)走 |

**第 3 步复用的是 PF-006 已有的原语，不另造机制。**

### 1.4 把一件事交给子 agent

| 步骤 | 发生什么 |
|---|---|
| 1 | `Agents().dispatch`，交出去一件可以独立完成的事 |
| 2 | 子 agent 是**另一个运行实例**，有自己的装配与动作空间 |
| 3 | 它**不共享**父 agent 的上下文，除非派发时明确交付 |
| 4 | 父 agent 可以 `list` 看状态、`send` 再说一句、`interrupt` 叫停 |
| 5 | 结果走**工具执行那一套**回来——可转后台、可被中断、绑在 session 上 |
| 6 | 成本算**发起方的租户** |

### 1.5 在一个会话里连续做事

| 步骤 | 发生什么 | 依赖什么 |
|---|---|---|
| 1 | `Shell().session` 开一个会持续存在的命令行 | 执行环境至少绑定在**会话**上 |
| 2 | 在里面连续执行，**后一步基于前一步的结果** | [会话级沙箱](../PF-005-execution-environments-and-sandboxes/design.md#63-会话级沙箱到点销毁数据不留存) |
| 3 | 沙箱到点销毁 | —— |
| 4 | agent **收到提醒**，知道东西没了 | PF-005 §6.6 |
| 5 | 要用就重开一个，**里面是空的** | —— |

**第 4 步是前提**：不知道东西没了，agent 会继续引用不存在的东西。

### 1.6 agent 想知道自己是怎么回事

| 问题 | 走哪扇门 |
|---|---|
| 我有什么能力 | `Tools().search` / `Skills().search` |
| 我在忙什么、做到哪了 | `Todos().read` |
| 我手上还有什么在跑 | `Jobs().list` |
| 我落在什么机器上 | `Shell().info` |
| **我是怎么被装配出来的** | **`Cordis().inspect`（不在首批）** |

**前四个首批就有，最后一个是这块设计留的口子。**

## 二、异常分支

| 分支 | 怎么处理 | 为什么 |
|---|---|---|
| **`Tools().search` 搜到一个当下不可用的工具** | **照样返回**，并说明缺什么 | 藏起来的话 agent 会以为自己没这个能力，而实际只是暂时用不了 |
| **`Tools().execute` 执行一个不可用的工具** | 走[替换件](../PF-006-tools-and-skills/design.md#替换件)，返回「用不了 + 原因」 | agent 据此**绕路**，不是重试 |
| **`Skills().read` 读到一份依赖不满足的技能** | 正文照给，**但要说明缺什么** | 不说明的话，agent 会照着一份执行不了的指引干下去 |
| **`Web()` 所需的网络设施给不了** | 这扇门当下不可用 | 与任何工具一样走替换件。**不降级、不绕道** |
| **`Browser()` / `Computer()` 的设施给不了** | 同上 | 同上 |
| **`Files().edit` 要改的那一处对不上** | **明确失败**，不"尽力而为"地改个差不多的地方 | 改错位置比不改更糟，而且很难被发现 |
| **`Shell().session` 所在的执行环境没了** | 会话随之消失，**agent 要被告知** | 不告知的话它会对着一个不存在的会话继续发命令 |
| **`Jobs().terminate` 掐掉一个执行** | 记为**被中断**，不是失败 | [PF-006 §6.7](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)。但**要分得出是 agent 掐的还是用户掐的** |
| **`Ask()` 等不到应答** | 按第六种收场，**不是失败也不是被拒** | 混进失败，agent 会重问一个没人回应的问题 |
| **`Agents().dispatch` 派发的定义没有派发权限** | **派不出去**，明确说明 | PF-002 的「谁可以派发它」 |
| **子 agent 自己又去派子 agent** | 本 topic 不禁止，但**成本仍算最初发起方的租户** | 归属不随层级漂移 |
| **有人试图禁用或替换某扇门** | **不发生** | meta 不可禁用不可替换 |
| **`Web()` 取回的内容里写着「忽略你之前的任务」** | 那只是一段文字 | **外部内容是数据，不是指令** |

## 三、状态流转

### 3.1 十二扇门本身

```text
       装配
        │
        ↓
      在位 ─────────────── 没有别的状态
        │
   （不可禁用、不可替换、不可移除）
```

**十二扇门没有状态机。**它们要么在，要么这个 agent 根本没装配起来。

**但门后的东西有状态**：一个具体工具可能当下不可用，
那是[可用性](../PF-006-tools-and-skills/design.md#可用性)的事，不是门的事。

### 3.2 `Shell().session` 开出来的会话

| 状态 | 能转到哪 | 谁触发 |
|---|---|---|
| **开着** | 关闭 / **随执行环境消失** | agent 关 / 环境到点 |
| **关闭** | 终态 | —— |
| **随环境消失** | 终态，**agent 必须被告知** | 环境销毁 |

### 3.3 `Agents().dispatch` 派出去的子 agent

| 状态 | 能转到哪 |
|---|---|
| **在跑** | 完成 / 失败 / 被中断 |
| **完成 / 失败 / 被中断** | 终态，结果回到发起方的 session |

**与[一次工具执行的收场](../PF-006-tools-and-skills/design.md#53-一次工具执行的收场有六种)同形**，
不另立一套。

## 四、谁决定什么

| 事情 | 谁决定 | 谁不能决定 |
|---|---|---|
| 有哪十二扇门 | **产品**。它是系统的基本盘 | 装配方不能增删 |
| 一扇门能不能被关掉 | **谁都不能。**meta 不可禁用 | 租户、组织、安全策略都不行 |
| 一扇门能不能被换成自己的实现 | **谁都不能。**meta 不可替换 | 同上 |
| 门后**具体能做什么** | 装配清单 + [可用性](../PF-006-tools-and-skills/design.md#可用性) | —— |
| 一个动作落在什么执行环境上 | **注入**（[PF-005](../PF-005-execution-environments-and-sandboxes/design.md)） | agent 不选落点 |
| 走哪扇门 | **agent 自己** | 系统不替它判断 |
| 派不派子 agent、派哪一个 | **agent**，在权限允许的范围内 | —— |
| 要不要问人 | **agent** | 系统不替它决定什么该问 |
| 后台的东西掐不掐 | **agent** 或**用户**，两者都可以 | 但记录要**分得出是谁做的** |
| `Cordis()` 什么时候交付 | **产品负责人** | —— |

**「谁都不能」出现了两次，那是本 topic 最硬的一条。**收紧安全只能靠
执行环境、权限与装配清单，**不能靠关掉门**——关掉门会让 agent 突然
"不知道某件事存在"，那种失明无法解释也无法申诉。
