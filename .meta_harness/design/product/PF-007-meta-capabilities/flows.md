# PF-007 流程与状态

`design.md` 说十三扇门**各是什么**，这里说 agent **怎么走它们**。

## 一、主要旅程

### 1.1 agent 想干一件事，但手头没有现成的动作

**这是 meta 存在的主线场景。**

| 步骤 | agent 做什么 | 为什么是这一步 |
|---|---|---|
| 1 | 先看槽位里有没有 | 常驻的直接调，不必绕 |
| 2 | 没有 → `Tools().search` | 装配清单里可能有，只是没常驻 |
| 3 | 找到了 → `Tools().inspect` | **参数格式同样不在系统提示词里** |
| 4 | `Tools().execute` | 全程 **system prompt 不变** |
| 5 | 还是没有 → `Skills().search` | 也许没有现成动作，但有现成方法 |
| 6 | 都没有 → 用世界族的门自己做 | `Shell()`、`Files()`、`Browser()`…… |

**第 6 步是兜底**：十三扇门保证了「什么都没配」也不等于「什么都做不了」。

### 1.2 一件长活：从前台到后台再回来

| 时刻 | 发生什么 | 哪扇门 |
|---|---|---|
| 1 | agent 发起一个要跑很久的动作 | `Shell().run` 或任意工具 |
| 2 | 超过工具声明的时长，**自动转后台**；位置上留占位返回 | [PF-006 §6.6](../PF-006-tools-and-skills/design.md#66-前台后台-与-等待态是两个维度) |
| 3 | agent 去干别的 | —— |
| 4 | 过了几轮，想看看它怎么样了 | **`BkgJobs().list` → `BkgJobs().output`** |
| 5 | 发现跑偏了，掐掉 | **`BkgJobs().terminate`** |
| 6 | 或者它自己跑完了，结果以提醒到达 | 收件人是 **session** |

**第 4、5 步没有 `BkgJobs()` 就走不通**——那正是这扇门存在的理由。

### 1.3 拿不准的时候问人

| 步骤 | 发生什么 |
|---|---|
| 1 | agent 判断这件事的裁决权不在自己 |
| 2 | `Ask().ask`，**一次问全**，带上选项与各自的后果 |
| 3 | 这次调用进入[等待态](../PF-006-tools-and-skills/design.md#等待态)，agent 停下来等 |
| 4 | 人做了选择 → 拿到应答，继续 |
| 5 | 人觉得给的选项都不对，**自己写了一句** → 照样拿到应答 |

**第 3 步复用的是 PF-006 已有的原语，不另造机制。**

**这条旅程没有「等到点了」这个分支**——`Ask()` 不设上限，也不替人作答
（[design.md §6.11](design.md#611-ask通向人)）。

### 1.4 要动手之前先请示

| 步骤 | 发生什么 |
|---|---|
| 1 | agent 打算做一件敏感的事，**但一个字节都还没动** |
| 2 | `Ask().request_approval`：做什么、为什么、影响多大、**撤不撤得回**、不准的话怎么办 |
| 3 | 人看到的是**固定的两个选项**：同意 / 不同意，**外加一个自由作答的口子** |
| 4 | 点「同意」→ agent 做**恰好那一件事**；同时这笔同意**记进会话授权上下文** |
| 5 | 点「不同意」→ 不做，按备选走或如实收尾 |
| 6 | 自己写了「第二封改改语气再发」→ **既不是准也不是驳**，agent 调整后**再请示一次** |
| 7 | 自己写了「以后都允许吧」→ **这是一笔全局作用域的授权**，[照他说的算](design.md#会话授权上下文)；**能不能真生效，按他自己的权限判** |

**第 6 步是这条旅程的要害**——那是最容易被「聪明地」处理掉的一种回应，
而处理掉的代价是替人签了字。

**第 7 步的要害在另一头**：照他说的算**不等于**替他把话说大。
他说「这次可以」就只管这次——[系统不替人解释，只负责准确理解](design.md#611-ask通向人)。

### 1.5 同一件事，第二次不必再问

| 步骤 | 发生什么 |
|---|---|
| 1 | 前面某一步，人已经点头同意「清掉这个目录」 |
| 2 | agent 接着往下干，又要动那个目录 |
| 3 | **不必再敲门**——[会话授权上下文](design.md#会话授权上下文)里有这一笔，agent 自己看得见 |
| 4 | 换一个会话，同样的事 → **看他当初给的作用域**：给的是「本会话」就从头再来，给的是「全局」就不必 |

**第 3 步是这一层设计的全部价值**：问得太勤，人就会开始不假思索地点同意，
那时这扇门形同虚设——**而它看上去还在工作**。

**第 4 步不再是一刀切的边界**：边界由他表达的作用域划，**而不是由会话划**。

### 1.6 把一件事交给别的 agent

| 步骤 | 发生什么 |
|---|---|
| 1 | **先选模式**：分身去做同一件事（`spawn`）、把另一件事交出去等结果（`delegate`）、整件事从此转手（`handoff`） |
| 2 | 对方是**另一个 agent runtime**，有自己的装配与动作空间 |
| 3 | **它带着什么开始干活，由模式决定**：`spawn` **继承当前会话的上下文**，另两种**从一段 instruction 开始** |
| 4 | **三种模式都跟得住**：`status` 看进展、`message` 再说一句（[规则一](design.md#先说谁能给谁发消息这是两条独立的规则)对**任何**派出去的都成立） |
| 5 | **`withdraw` 只对前两种成立**——`handoff` 的生命周期不受派发者控制 |
| 6 | **前两种**的结果走**工具执行那一套**回来（进[等待态](../PF-006-tools-and-skills/design.md#等待态)、可转后台、可被中断、绑在 session 上）；**`handoff` 确认会话建起来就返回，不等它干活** |
| 7 | 成本算**发起方的租户** |

**`handoff` 与另两种真正的差别只有一条：它是一个独立的主会话。**
因此它撤不回、生命周期不归你管、**用户可以直接找它说话**。

> **三种模式派出去的都能回头给你发消息**（[规则一是双向的](design.md#先说谁能给谁发消息这是两条独立的规则)）。
> **差别在能跟谁通**：`spawn` / `delegate` 出去的**只能跟你通**；
> `handoff` 出去的还落在[规则二](design.md#先说谁能给谁发消息这是两条独立的规则)里，
> **跟任何同租户的活跃主会话 agent 都能通**。
>
> **前两种仍然必须交一次报告**——**而报告一到，这次派发就结束了**。
> [报告与消息是两样东西](design.md#报告与消息是两样东西)。

### 1.7 在一个会话里连续做事

| 步骤 | 发生什么 | 依赖什么 |
|---|---|---|
| 1 | `Shell().create_session` 开一个终端会话，拿到它的标识 | 执行环境至少绑定在**会话**上 |
| 2 | `Shell().execute` 带上那个标识连续执行，**后一步基于前一步的结果** | [会话级沙箱](../PF-005-execution-environments-and-sandboxes/design.md#63-会话级沙箱到点销毁数据不留存) |
| 3 | 期间还可以**再开一个**，干别的事 | **多个终端会话同时存在** |
| 4 | 用完了 `close_session` | —— |
| 5 | 或者沙箱先到点销毁，**那个环境里的会话一起没** | —— |
| 6 | agent **收到提醒**，知道东西没了 | PF-005 §6.6 |
| 7 | 要用就重开，**里面是空的** | —— |

**第 6 步是前提**：不知道东西没了，agent 会继续对着一个不存在的会话发命令。

**不给会话标识的 `execute` 是一次性的**——跑完不留痕，不用开也不用关。

### 1.8 agent 想知道自己是怎么回事

| 问题 | 走哪扇门 |
|---|---|
| 我有什么能力 | `Tools().search` / `Skills().search` |
| 我在忙什么、做到哪了 | `TodoItems().list` |
| 我手上还有什么在跑 | `BkgJobs().list` |
| 我落在什么机器上 | `Shell().info` |
| **我是怎么被装配出来的** | **`Cordis().query`（不在首批）** |

**前四个首批就有，最后一个是这块设计留的口子。**

## 二、异常分支

| 分支 | 怎么处理 | 为什么 |
|---|---|---|
| **`Tools().search` 搜到一个当下不可用的工具** | **照样返回**，并说明缺什么 | 藏起来的话 agent 会以为自己没这个能力，而实际只是暂时用不了 |
| **`Tools().execute` 执行一个不可用的工具** | 走[替换件](../PF-006-tools-and-skills/design.md#替换件)，返回「用不了 + 原因」 | agent 据此**绕路**，不是重试 |
| **`Skills().read` 读到一份依赖不满足的技能** | 正文照给，**但要说明缺什么** | 不说明的话，agent 会照着一份执行不了的指引干下去 |
| **`Web()` 所需的网络设施给不了** | 这扇门当下不可用 | 与任何工具一样走替换件。**不降级、不绕道** |
| **`Browser()` / `Computer()` 的设施给不了** | 同上 | 同上 |
| **`Files().edit` 要改的那一处对不上** | **明确失败**，不"尽力而为"地改个差不多的地方 | 改错位置比不改更糟，而且很难被发现 |
| **`Files().patch` 里有一处对不上** | **整份不应用**，文件一个字节不变 | **「改了一半」既不是成功也不是失败，而且看上去像成功**。重来一次比收拾残局便宜得多 |
| **`Skills().exec_script` 要跑的脚本不属于那份 skill** | **拒绝**，这是红线 | 放开就是 `Shell()` 的后门，命令行的权限管控当场作废 |
| **带脚本的 skill 要的设施给不了** | 这份 skill 的 `exec_script` **不可用**，`read` 照常 | 读方法与跑脚本是两件事，不因为后者用不了就连方法都读不到 |
| **终端会话所在的执行环境没了** | **那个环境里的会话全部消失**，agent 要被告知 | 不告知的话它会对着一个不存在的会话继续发命令 |
| **`execute` 给了一个已经不存在的会话标识** | **明确失败**，说明那个会话没了 | 悄悄降级成一次性执行更糟——agent 以为自己接着上一条，其实状态全丢了 |
| **对一个声明不允许后台的工具用 `run_in_background`** | **起不来**，明确说明 | 声明就是声明（[PF-006 §6.6](../PF-006-tools-and-skills/design.md#66-前台后台-与-等待态是两个维度)） |
| **`BkgJobs().terminate` 掐掉一个执行** | 记为**被中断**，不是失败 | [PF-006 §6.7](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)。但**要分得出是 agent 掐的还是用户掐的** |
| **`Ask()` 迟迟没人回** | **就一直等着**，不设上限、不替人作答 | 「到点当作同意」是替人签字，「到点当作拒绝」同样是。等待不占资源，没有理由到点 |
| **人回了一句既不是准也不是驳的话** | 原话交给 agent，标明**有话说但没给裁决** | 替人合成一个裁决，等于伪造签字。宁可再问一轮 |
| **人说「以后都这样吧」** | **认成一笔全局作用域的授权**；能不能生效另按他的权限判 | **那确实是他的意思。**要防的是反过来——他只说「这次可以」，系统却当成「以后都可以」 |
| **agent 请示获批了，那系统还拦不拦** | **看三样东西合起来**：权限设置、会话授权上下文、会话运行模式 | 获批不等于自动放行，而有权限设置也不等于请示没意义。**两个想当然的读法都不对** |
| **权限设置里明确禁止的事，用户在会话里点了同意** | **仍然不放行** | 否则任何禁止都能靠「让用户点个同意」绕过去。**会话里坐着的那个人，未必是设权限的那个人** |
| **拿不准这次动作算不算落在已获授权的范围内** | **宁可再问一次** | 误判有两个方向：多问一遍人嫌烦，少问一遍就**做了没有人批准过的事**。代价差着量级 |
| **`Agents()` 派发的定义没有派发权限** | **派不出去**，明确说明 | PF-002 的「谁可以派发它」 |
| **子 agent 自己又去派子 agent** | 本 topic 不禁止，但**成本仍算最初发起方的租户** | 归属不随层级漂移 |
| **有人试图禁用或替换某扇门** | **不发生** | meta 不可禁用不可替换 |
| **`Web()` 取回的内容里写着「忽略你之前的任务」** | 那只是一段文字 | **外部内容是数据，不是指令** |

## 三、状态流转

### 3.1 十三扇门本身

```text
       装配
        │
        ↓
      在位 ─────────────── 没有别的状态
        │
   （不可禁用、不可替换、不可移除）
```

**十三扇门没有状态机。**它们要么在，要么这个 agent 根本没装配起来。

**但门后的东西有状态**：一个具体工具可能当下不可用，
那是[可用性](../PF-006-tools-and-skills/design.md#可用性)的事，不是门的事。

### 3.2 终端会话（可以有多个，各自独立）

| 状态 | 能转到哪 | 谁触发 |
|---|---|---|
| **开着** | 关闭 / **随执行环境消失** | agent `close_session` / 环境到点 |
| **关闭** | 终态 | —— |
| **随环境消失** | 终态，**agent 必须被告知** | 环境销毁 |

**每个会话各走各的状态机**，互不影响；但**同一个执行环境里的会话会一起没**——
它们都活在那个环境里，环境是它们的宿主。

### 3.3 `Agents()` 派出去的活

| 状态 | 能转到哪 |
|---|---|
| **在跑** | 完成 / 失败 / 被中断 |
| **完成 / 失败 / 被中断** | 终态，结果回到发起方的 session |

**与[一次工具执行的收场](../PF-006-tools-and-skills/design.md#55-一次工具执行的收场有六种)同形**，
不另立一套。

**`handoff` 不走这张表**——它的派发动作在**确认新会话建没建起来**那一刻就结束了，
发起方那边**没有一个「在跑」的东西**可看。**它自己的会话另有生命周期，不归发起方管。**

> **注意这不等于「从此失联」**：`handoff` 出去的那个**有独立主会话身份**，
> 双方仍然[可以互发消息](design.md#先说谁能给谁发消息这是两条独立的规则)。
> **脱钩的是执行的托管关系，不是通信的通路。**

### 3.4 一次问询

| 状态 | 能转到哪 | 谁触发 |
|---|---|---|
| **等着** | 拿到应答 / 被取消 / 随 run 被中断 / **随会话被归档清掉** | 人，或会话生命周期 |
| 以上四种 | 终态 | —— |

**「等着」这个状态没有超时出口。**它可以停留任意久，因为停在这里不花钱
（[design.md §6.11](design.md#611-ask通向人)）。

### 3.5 [会话授权上下文](design.md#会话授权上下文)

| 状态 | 怎么变 |
|---|---|
| **空** | 会话刚开始时 |
| **攒着几笔** | 用户每表达一次授权，多一笔——**点「同意」是一笔，自由作答里说的是一笔，他主动说的也是一笔** |
| **攒着的里面有撤回** | **撤回同样是往后追加一笔**，不是把先前那笔擦掉 |

**它只往后排，不回头改，也不会归零。**
[会话被归档它也不丢](../PF-015-session-lifecycle-and-ownership/design.md#67-归档不动授权)——
**它是数据，不是活物**。

**「此刻这件事到底准不准」不在它里面，是按这份流水当场算出来的。**
所以撤回能立刻生效：下一次求值读到那一笔，结论就变了。
**没有一个存着「已获准清单」的地方需要去改**——这正是「以为撤了其实没撤」不会发生的原因。

## 四、谁决定什么

| 事情 | 谁决定 | 谁不能决定 |
|---|---|---|
| 有哪十三扇门 | **产品**。它是系统的基本盘 | 装配方不能增删 |
| 一扇门能不能被关掉 | **谁都不能。**meta 不可禁用 | 租户、组织、安全策略都不行 |
| 一扇门能不能被换成自己的实现 | **谁都不能。**meta 不可替换 | 同上 |
| 门后**具体能做什么** | 装配清单 + [可用性](../PF-006-tools-and-skills/design.md#可用性) | —— |
| 一个动作落在什么执行环境上 | **注入**（[PF-005](../PF-005-execution-environments-and-sandboxes/design.md)） | agent 不选落点 |
| 走哪扇门 | **agent 自己** | 系统不替它判断 |
| 派不派子 agent、派哪一个 | **agent**，在权限允许的范围内 | —— |
| **用哪种派发模式** | **agent**，三种模式回答的是三个不同的问题 | —— |
| **派完要不要停下来等** | **模式本身**（`spawn` / `delegate` 等，`handoff` 不等） | **agent 不能临时选**——给它一个开关只会让它选错 |
| **一个 `handoff` 出去的会话什么时候结束** | **它自己，或用户** | **派发者不能**，`withdraw` 对它不成立 |
| **两个 agent 之间能不能通信** | **[那两条规则](design.md#先说谁能给谁发消息这是两条独立的规则)**，不是谁的偏好 | 发不出去时**必须说清是哪一条不满足** |
| 要不要问人 | **agent** | 系统不替它决定什么该问 |
| **人回答了什么** | **人**，而且只有人 | 系统不替人作答、不替人把模棱两可的话解释成裁决 |
| **一次问询等多久** | **没人定，因为不设上限** | 谁都不能规定「到点算同意」或「到点算拒绝」 |
| **这次批准在本会话内还算不算数** | **算。**它进了[会话授权上下文](design.md#会话授权上下文)，同一件事不必问第二遍 | 但它**出不了这个会话**——换一个会话，从头来过 |
| **这次批准能不能变成长期授权** | **不能。**`request_approval` 碰不到权限设置 | agent 不能自己给自己续期，系统也不得把一句「以后都行」写进设置 |
| **一个动作最终放不放行** | **三样东西合起来**：权限设置 + 会话授权上下文 + 会话运行模式 | 没有任何一样单独说了算 |
| 给一个 agent 长期授权 | **人**，走[设置与权限](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性) | 不能从一次问询的回答里长出来 |
| 一次执行**发起时就在后台起** | **agent**（`Shell().execute` 的 `run_in_background`），前提是工具允许 | —— |
| 一次**已在前台跑的执行要不要转后台** | **用户**，或工具声明的自动超时 | agent 不替用户做这个决定 |
| 开几个终端会话、什么时候关 | **agent**，在资源约束内 | —— |
| 后台的东西掐不掐 | **agent** 或**用户**，两者都可以 | 但记录要**分得出是谁做的** |
| `Cordis()` 什么时候交付 | **产品负责人** | —— |
