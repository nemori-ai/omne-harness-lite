### ST-007-01 · 一次问清多个问题并保留自由作答

- **子期**：2A · 可控的人机协作
- **价值**：用户可以一次回答多个问题，也可以用自己的话答复。
- **覆盖场景**：[S60](acceptance.md#状态族与他者族)、[S61](acceptance.md#状态族与他者族)、[S62](acceptance.md#状态族与他者族)、[S65](acceptance.md#状态族与他者族)、[S66](acceptance.md#状态族与他者族)、[S67](acceptance.md#状态族与他者族)
- **演示**：
  1. 让 agent 一次提出三个带文字选项的问题 → 人同时看到三个问题，每个都能自由输入，agent 停在工具等待。
  2. 不答其中一个问题并等待超过通常工具执行时长，再填写自己的文字 → 卡不因到时自动作答或失败，原文字交回工具。
  3. 另起 Ask 等待，确认原工具执行因据点停机丢失，恢复后查看 → 原执行落失败“异常中断”、卡作废、不伪造答案；是否再问由 agent 重新判断。
- **不含**：Ask.request_approval 的自由修改计划、图片选项、后台等待和系统卡回放。
- **前置**：ST-015-01、ST-006-08、ST-006-15
- **就绪**：是

### ST-007-02 · spawn 带上下文副本等回报告

- **子期**：2C · 扩大委托与自主执行
- **价值**：用户能让另一位 agent 使用当前背景处理一件事，并取回该次报告。
- **覆盖场景**：[S81](acceptance.md#状态族与他者族)、[S82](acceptance.md#状态族与他者族)、[S85](acceptance.md#状态族与他者族)
- **演示**：
  1. 从已有会话按合法权限 spawn 一件前台工作 → 子会话不是独立主会话，另有 Agent Runtime 和自己的装配；派发时上下文副本为其日志第一条。
  2. 派发后父会话再增加记录，查看子会话输入 → 子会话不自动看到父方后来内容；派发工具前台等待，直到子方交报告或失败。
- **不含**：转后台等待、报告自动等同 Run 终态及 handoff 生命周期。
- **前置**：ST-012-01、ST-007-01
- **就绪**：是

### ST-007-03 · delegate 只交指令而不交父方上下文

- **子期**：2C · 扩大委托与自主执行
- **价值**：用户可以委托一件窄任务而不把整段会话背景带过去。
- **覆盖场景**：[S83](acceptance.md#状态族与他者族)
- **演示**：
  1. 在含有敏感背景的父会话，合法 delegate 一段明确 instruction → 子会话不是独立主会话，起始任务只含该指令，不能读到父方上下文。
  2. 让子方完成该次派发并返回报告 → 原前台派发取得对应报告，父方上下文没有自动共享。
- **不含**：完整跨会话授权入口、后台等待及上下文共享策略。
- **前置**：ST-007-02
- **就绪**：是

### ST-007-04 · handoff 创建可直接对话的独立会话

- **子期**：2C · 扩大委托与自主执行
- **价值**：用户能将工作交给独立会话，之后直接参与那边的对话。
- **覆盖场景**：[S84](acceptance.md#状态族与他者族)、[S86](acceptance.md#状态族与他者族)
- **演示**：
  1. 合法 handoff 一件工作 → 确认独立主会话创建成功后，原工具即返回，不等待新会话干完任务。
  2. 用户直接进入新会话说话，再覆盖创建失败情况 → 成功会话可以直接对话；失败有明确结果，原工具也收场。
- **不含**：withdraw 和父归档级联、自主报告及新授权政策。
- **前置**：ST-015-01、ST-012-01
- **就绪**：是

### ST-007-05 · 协作消息与一次派发报告分开处理

- **子期**：2C · 扩大委托与自主执行
- **价值**：用户能中途澄清、报告后继续协作，同时辨认该次派发是否已经结束。
- **覆盖场景**：[S87](acceptance.md#状态族与他者族)、[S88](acceptance.md#状态族与他者族)、[S89](acceptance.md#状态族与他者族)、[S90](acceptance.md#状态族与他者族)、[S92](acceptance.md#状态族与他者族)、[S93](acceptance.md#状态族与他者族)、[S94](acceptance.md#状态族与他者族)、[S17](../PF-015-session-lifecycle-and-ownership/acceptance.md#创建变化与恢复补充)
- **演示**：
  1. 在 spawn、delegate 和 handoff 关系中用合法双方互发澄清消息 → 消息可达；spawn/delegate 的派发仍等待，普通消息不替代报告。
  2. 让子会话交过一次报告，再由父发消息，分别覆盖子方有和没有未结束 Run → 前者追加、后者开新 Run；不重开原派发或提交第二份同次报告。
  3. 分别尝试兄弟或隔代子会话直接互发、向已归档目标发新任务、跨租户发消息 → 均拒绝，归档情形说明归档原因，不把内部关系当越权入口。
- **不含**：无派发关系的主会话消息、完整投递重试及目标不存在协议，均沿来源 O1 待细化范围。
- **前置**：ST-007-02、ST-007-03、ST-007-04、ST-014-01
- **就绪**：是

### ST-007-06 · 撤回子工作不控制独立 handoff

- **子期**：2C · 扩大委托与自主执行
- **价值**：用户能收回受自己治理的派发，不会误停独立会话。
- **覆盖场景**：[S95](acceptance.md#状态族与他者族)、[S96](acceptance.md#状态族与他者族)
- **演示**：
  1. 分别 withdraw 已 spawn 和 delegate 的工作 → 原派发可以收回，返回可辨认的处置结果。
  2. 尝试 withdraw handoff → 明确拒绝并说明其独立生命周期，不停止那个独立主会话。
- **不含**：撤销已发生效果、父 Run 取消和父 Session 归档。
- **前置**：ST-007-02、ST-007-03、ST-007-04
- **就绪**：是

### ST-007-07 · 按调用分页读回大结果

- **期次**：第三期 · 性能与体验
- **价值**：agent 需要占位提示之外的信息时，可以读取那次调用的原始结果，无需猜存放路径。
- **覆盖场景**：[S17](acceptance.md#tools-与-skills)、[S18](acceptance.md#tools-与-skills)、[S19](acceptance.md#tools-与-skills)、[S106](../PF-006-tools-and-skills/acceptance.md#工具的产出三部分)
- **演示**：
  1. 让一次工具调用产出足以卸载的结果 → 会话里保留占位提示，原始结果已经保存。
  2. 经 Tools().read_result 按该次调用取回第一页，再取后续页 → 每次只收到一段；按页可读回原始内容，没有一次把全文搬进上下文。
  3. 查看这次公开取用过程 → 使用的是调用结果入口；说明能区分“那次调用返回了什么”与“某个路径上有什么”。
- **不含**：卸载判定或摘要生成、文件系统读取、原始结果保留期限及分页参数的技术形状。
- **前置**：ST-006-21
- **就绪**：是

### ST-007-08 · 查看并停止本会话的后台工作

- **期次**：第三期 · 性能与体验
- **价值**：agent 能找到自己仍在后台执行的工作，读取进展，并明确结束不再需要的那一项。
- **覆盖场景**：[S51](acceptance.md#状态族与他者族)、[S52](acceptance.md#状态族与他者族)、[S53](acceptance.md#状态族与他者族)、[S54](acceptance.md#状态族与他者族)、[S75](../PF-006-tools-and-skills/acceptance.md#六种收场分得清)
- **演示**：
  1. 在当前会话发起一个允许后台的长工具，再过几轮调用 BkgJobs().list 与 output → 原执行仍列在本会话视野内，能读到它的进展和输出。
  2. 由 agent 经 BkgJobs().terminate 停掉该项 → 收场是被中断；原执行收场提醒写明“被 agent 停掉”。
  3. 另由用户手动停止另一项，再查记录 → 两次都为中断，但能区分 agent 停止与用户停止。
  4. 按既有规则归档该会话，核对 BkgJobs() 的视野 → 视野随会话归档结束；仅完成一个 Run 不会结束本会话的后台视野，不把它当作跨会话任务管理入口。
- **不含**：后台转入许可、用户过程帧的呈现、Run 取消、会话归档的停止机制和跨会话后台任务管理。
- **前置**：ST-006-10、ST-006-12、ST-012-08、ST-015-07
- **就绪**：是

### ST-007-09 · 逐条维护本会话的待办

- **期次**：第三期 · 性能与体验
- **价值**：agent 可以记住本会话尚要做的事，分清完成与放弃，不因改一条而丢掉其余条目。
- **覆盖场景**：[S55](acceptance.md#状态族与他者族)、[S56](acceptance.md#状态族与他者族)、[S57](acceptance.md#状态族与他者族)、[S58](acceptance.md#状态族与他者族)、[S59](acceptance.md#状态族与他者族)
- **演示**：
  1. 经 TodoItems().add 加三条，再 list → 三条均在，各自有身份。
  2. mark_complete 其中一条，再 list → 那条显示完成并仍可见，另外两条原样保留。
  3. remove 另一条，再 list → 只少被移除的条目；完成与移除分得清。
  4. 换到另一个会话读取待办 → 原会话待办不跟过去。
- **不含**：系统自动执行待办、整份计划覆盖、跨会话计划对象和指定待办界面布局。
- **前置**：ST-015-01
- **就绪**：是

### ST-007-10 · 查到已知能力当前用不了的原因

- **期次**：第三期 · 性能与体验
- **价值**：使用者能分辨“没有这项能力”和“这项能力当前用不了”，找到具体限制而不靠反复调用猜原因。
- **覆盖场景**：[S7](acceptance.md#meta-不可禁用不可替换)、[S16](acceptance.md#tools-与-skills)、[S22](acceptance.md#tools-与-skills)、[S34](../PF-006-tools-and-skills/acceptance.md#三层各自成立)
- **演示**：
  1. 在一个已合法纳入工具与技能的会话中，收紧一条元能力命令的执行权限 → 该命令仍看得见，并说明用不了及原因；不把整扇门藏掉。
  2. 使一个已知工具的依赖缺席，经 Tools().search 查找 → 仍返回该工具，明确缺什么。
  3. 使一个已知技能的声明依赖不满足，经 Skills().search 查找 → 仍返回该技能，明确缺什么；不据历史可见性读取被撤权的新内容。
  4. 查同一个工具的状态说明 → 能分别读出是否在动作空间、是否占槽位以及当前是否可用。
- **不含**：未合法纳入资产的发现、新权限政策、已发旧调用的绑定变更、reload 失败说明和强制模型采用某种绕路策略。
- **前置**：ST-006-03、ST-015-06、ST-015-08
- **就绪**：是
