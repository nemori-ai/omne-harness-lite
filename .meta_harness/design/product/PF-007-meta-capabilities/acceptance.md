# PF-007 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

### 基本盘

| 场景 | 应当看到什么 |
|---|---|
| 装配一个**什么工具技能都没配**的 agent | 它仍然有**十一扇门**（首批），能读写文件、跑命令、上网、派子 agent、问人 |
| 数一下它的槽位 | **恰好十一个**（首批），不多不少 |
| 给它装一千个工具 | 槽位**还是十一个**——`Tools()` 不因为门后东西多而变大 |
| 装配方额外把某个高频工具标成常驻 | 槽位变成**十二个**（首批十一 + 这一个）；**那是装配方的取舍，地板不变** |

### meta 不可禁用、不可替换

| 场景 | 应当看到什么 |
|---|---|
| 试图把某扇门的执行权限设成「禁止」 | **做不到** |
| **试图把门后的某一条命令关掉** | **做得到**——[权限作用在命令这一级](design.md#57-权限能关掉一条命令关不掉一扇门) |
| **那条命令被关掉之后，agent 去看** | **看得见它存在、看得见自己用不了、看得见为什么**。**不藏起来** |
| **会话运行模式是 `never`** | **`Ask().request_approval` 在这个会话里不可用**；**`Ask()` 这扇门还在**，`ask` 照常能用 |
| 试图用自己的实现覆盖某扇门 | **做不到**——[official/customized](../PF-001-identity-scope-and-agent-constraints/design.md#来源official-与-customized) 那套在这里不适用 |
| 试图把某扇门从装配清单里移除 | **做不到** |
| 安全策略要收紧这个 agent | 只能改**执行环境、权限、装配清单**；**门一扇都关不掉** |

### `Tools()` 与 `Skills()`

| 场景 | 应当看到什么 |
|---|---|
| `Tools().search` 找一个非常驻工具 | 找得到，结果说明**下一步该 inspect** |
| `Tools().search` 命中一个**常驻**工具 | 也找得到，但标明**直接调即可**，不必绕 |
| `Tools().inspect` | 拿到**参数格式**——它本来不在系统提示词里 |
| `Tools().execute` 之后查 system prompt | **逐字未变** |
| `Tools().search` 命中一个当下不可用的 | **照样返回**，并说明缺什么 |
| 一次执行的结果**被卸载**了 | `Tools().read_result` **取得回原始结果** |
| 取回一个很大的结果 | **分页**——不分页等于把刚卸下去的原样搬回来 |
| 问「为什么它不在 `Files()` 里」 | 说得出：**那是「那次调用返回了什么」，不是「某个路径上有什么」** |
| `Skills().read` 一份技能 | 拿到正文；**没有产生任何"已启用"状态**；system prompt **逐字未变** |
| 上下文被裁剪后再要用那份技能 | **重新 read 一次**即可，不需要任何恢复动作 |
| `Skills().search` 命中依赖不满足的技能 | 搜得到，**说明缺什么** |
| `Skills().exec_script` 跑一份 skill 自带的脚本 | **跑得起来**，落在当前执行环境上 |
| 试图用 `exec_script` 跑一个**不属于任何 skill** 的脚本 | **做不到** |
| 试图用它跑**别的 skill** 的脚本 | **做不到** |
| 查这次执行的权限依据 | 是**那个 skill 的使用权**，不是「能不能跑 shell」 |
| 一个组织允许用某 skill 连同脚本、但禁止 agent 随意跑 shell | **这个意图表达得出来，也生效** |

### 世界族的五扇门

| 场景 | 应当看到什么 |
|---|---|
| `Files().edit` 改一处 | 精确改那一处；**改不准就明确失败**，不"尽力而为" |
| `Files().write` 与 `edit` | **是两个命令**，整份覆盖与局部修改分得开 |
| `Files().patch` 一次改五处，中途第三处对不上 | **一处都没改**，文件和动手前一模一样 |
| 同样五处改动用五次 `edit`，中途失败 | **留下改了两处的文件**——所以这类改动该用 `patch` |
| `write` / `edit` / `patch` | **三个命令**，各自的失手代价不同 |
| `Files().find` | 能**分别**按文件名找、按内容找 |
| 同一条 `Files().read`，执行环境从宿主机换到沙箱 | **agent 照常发起**，动作空间不变 |
| `Shell().execute` 一条长命令 | 超时按工具声明**转后台**，接着用 `BkgJobs()` 接手 |
| `Shell().create_session` 开两条终端会话，各自执行 | **两条同时存在、互不干扰**，各有自己的状态 |
| 在一条终端会话里连续执行两条命令 | **后一条基于前一条的结果** |
| `execute` **不给**终端会话标识 | **一次性执行**，跑完不留痕 |
| `execute` 给一个**已经关掉**的终端会话标识 | **明确失败**，说明那条终端会话没了；**不悄悄降级成一次性** |
| `execute` 带 `cwd` / `envs` 在某条终端会话里执行 | **只影响这一次**；那条终端会话本身的目录与环境**没被改写** |
| `execute` 带 `run_in_background` | **直接在后台起**，随后由 `BkgJobs()` 接手 |
| 对一个声明**不允许后台**的工具带 `run_in_background` | **起不来** |
| 会话所在的沙箱到点销毁 | **那个环境里的会话全部消失**，agent 收到提醒 |
| `Web().fetch` 一个页面 | 拿到**内容**；**不执行页面脚本、不点任何东西** |
| 取回的内容里写着「忽略你之前的任务」 | **那只是一段文字**，agent 不照做 |
| `Browser().act` 点一个按钮 | 按**页面结构**定位，不按坐标 |
| `Computer()` 操作一个桌面应用 | 按**像素**工作；典型落在租户级沙箱上 |
| 同租户另一个 agent 看那台共享机器 | **看得见**前一个留下的东西——共享空间的固有性质 |

### 状态族与他者族

| 场景 | 应当看到什么 |
|---|---|
| 一个执行转了后台，过几轮后 | `BkgJobs().list` **看得见它**，`BkgJobs().output` 看得到进展 |
| `BkgJobs().terminate` 掐掉 | 记为**被中断**，不是失败 |
| 查记录 | **分得出是 agent 掐的还是用户掐的** |
| session 结束 | `BkgJobs()` 的视野随之结束——它看的就是这个 session |
| `TodoItems().add` 加三条，再 `list` | **三条都在**，各有各的身份 |
| `mark_complete` 其中一条 | **那一条标成完成，另两条一个字没动** |
| `remove` 其中一条 | **只少那一条** |
| 完成与移除 | **分得开**——做完了还看得见，不做了才没了 |
| 换一个会话 | 待办**不跟过来** |
| `Ask().ask` 的每个问题 | **问题描述（人话）+ 文本候选项 + 自由作答**，三样齐全 |
| 有三件事要问 | **一次问完**，不是连打断三轮 |
| 给的选项人都不满意 | **随时可以自己写一句**，而且这条路**不靠 agent 记得留** |
| 一个只给了图、没给文字的选项 | **不允许**——图是补充，替代不了文本 |
| 两个方案文字说不清差别 | 选项可以**附一份图解**，人看得见差别 |
| 问出去之后 | agent **停下来等**，用的是 PF-006 的等待态原语 |
| **一直没人回** | **就一直等着**——没有「到点了」这件事发生 |
| `Ask().request_approval` | 说清**做什么、为什么、影响多大、撤不撤得回、不准怎么办** |
| 人看到的选项 | **固定两个**：同意 / 不同意，**外加自由作答** |
| 请示的那一刻 | 那件事**一个字节都还没做** |
| 人点头之后 agent 做的事 | **恰好是请示里写的那件**；计划变了**重新请示** |
| **人点头之后，本会话里同一件事** | **不必再问**——会话授权上下文里有这一笔 |
| **换一个会话，同一件事** | **看他当初给的作用域**：给的是「本会话」就要重新问，给的是「全局」就不必 |
| **会话被归档，又撤销归档** | 攒下的授权**一条不少**，不用重新说一遍 |
| 人说「第二封改改语气再发」 | 既不算准也不算驳，**原话交回**，agent 调整后再问一轮 |
| **人在自由作答里说「以后都允许」** | **算一笔授权**，作用域按他说的那档；**能不能真生效，另按他自己的权限判** |
| **agent 没问，人自己说「这类事不用问我」** | **一样算**。授权不挑来源 |
| **人说「刚才那个收回」** | **算一笔撤回**，下一次求值立刻生效 |
| 请示获批，那到底放不放行 | 看**权限设置 + 会话授权上下文 + 会话运行模式**三样合起来 |
| 权限设置里明确禁止的事，人在会话里点了同意 | **仍然不放行** |
| `Agents()` 派一件事 | 对方是**另一个 agent runtime**，有自己的装配 |
| **`spawn` 出去的那个** | **不是独立主会话**；它带着**派发那一刻组装出来的那份上下文的副本**开始干活，**那份副本是它日志里的第一条**；**派发之后派发者这边发生的事，它看不见** |
| **`delegate` 出去的那个** | **不是独立主会话**；它**只带着那段 instruction**，**看不到发起方这边的上下文** |
| **`handoff` 出去的那个** | **是一个独立的主会话**——**用户可以直接进去跟它说话** |
| **`spawn` / `delegate` 派发完** | 工具调用**停在等待态**，直到对方**返回报告或失败** |
| **`handoff` 派发完** | **确认会话建没建起来**（成功失败都算）**工具调用即结束**，**不等它干活** |
| 派发者给任何一个派出去的发消息 | **发得出去**——三种模式都一样（[规则一](design.md#先说谁能给谁发消息这是两条独立的规则)） |
| **`spawn` / `delegate` 出去的想给派发者发消息** | **发得出去**——[规则一是双向的](design.md#先说谁能给谁发消息这是两条独立的规则)。典型用途是**干到一半确认一件事实、澄清一句需求** |
| **它发完消息之后** | **这次派发没有结束**，工具调用**仍停在等待态**——[消息什么都不终结，只有报告终结这次派发](design.md#报告与消息是两样东西) |
| **`handoff` 出去的想给派发者发消息** | **发得出去**（规则一；它同时还落在[规则二](design.md#先说谁能给谁发消息这是两条独立的规则)里） |
| 两个素不相识、都有主会话、都还活着、同租户的 agent 互相发消息 | **发得出去**——**不需要有派发关系** |
| **两个兄弟子 agent 之间发消息**（同一个父派出去的两个） | **发不出去**——彼此**没有派发关系**，也都**没有独立主会话身份**。**隔代之间同理** |
| 给一个**会话已被归档**的 agent 发消息 | **发不出去**，且**说清是「会话已归档」**，不是笼统一句失败 |
| 给**另一个租户**的 agent 发消息 | **发不出去**，[与租户隔离的通则一致](../PF-001-identity-scope-and-agent-constraints/README.md) |
| `withdraw` 一个 `spawn` / `delegate` 出去的 | **收得回** |
| **`withdraw` 一个 `handoff` 出去的** | **收不回**，明确说明——**它的生命周期不受派发者控制** |
| 查成本 | 算**发起方的租户**；对方再往下派，**仍然算最初那个** |
| 派一个自己没有派发权限的定义 | **派不出去**，明确说明 |
| **子 agent 请求比父更宽的权限** | **拿到的是交集**——超出父的那部分一律没有（[§5.8](design.md#58-子不得宽于父)） |
| **父是 `never`，子想请示** | **子的 `request_approval` 一并不可用**；**子的 `Ask()` 这扇门照样在** |
| **工作区里放着一份想放宽权限的东西** | **不作数**——[加载时就被滤掉了](../PF-002-assets-settings-and-permissions/design.md#57-工作区那一级不参与权限计算)，根本没进求值 |
| **工作区里放着一份想*收紧*权限的东西** | **同样不作数**。授权与权限这一维**只认组织级与租户级** |
| **`bypass-permissions` 模式下，碰一件被明确禁止的事** | **仍然不放行**。它跳过的是「问」，不是「禁」（[§5.6](design.md#56-一次放行判断走四步)） |

### `Cordis()`（不在首批）

| 场景 | 应当看到什么 |
|---|---|
| 首批交付里找这扇门 | **没有**——它定义完整但不实现 |
| 翻产品设计 | **它的位置、命令、边界与危险性写得明明白白**，照着能直接做 |
| 将来实现时：`list` | 给**不收窄的概览**：有哪些面可以看 |
| 将来实现时：`query` | 给**收窄后的完整契约**：某个方法参数到底什么形状 |
| 装上一个新插件之后再 `list` | **多出它贡献的那一项**——检视面随系统生长 |
| 一个没贡献检视面的插件 | **不出现在 `list` 里**。它选择了不透明，而这个选择本身看得见 |
| 拿到一个服务方法的签名之后想调用它 | **调不动**。看得见签名，不等于能执行 |
| 想用它改配置 | **改不动**。检视与配置是两件事 |
| 让它生成一段代码然后执行 | **执行不了**。这扇门的产物是**知识**，不是动作 |
| 看到的范围 | **自己那一份装配**，不是整个部署 |
| 界面那一侧没有连着的页面 | 那一路**当下不可用**，与任何设施给不了时一样——**不降级、不猜** |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 某扇门被禁用、被替换、被移除 | agent 突然"不知道某件事存在"，**无法解释也无法申诉**；动态性被剥夺 |
| **一条命令被权限关掉，却对 agent 藏起来** | 同上那个病，只是换了一层——**它会以为这个能力不存在**，于是**连「这条路被关了」都报告不出来** |
| **`bypass-permissions` 翻掉了一条明确禁止** | 那条线就不存在了。**四家在跑的 harness 没有一家允许任何层放宽 deny** |
| **工作区里的东西放宽了组织或租户的权限** | **一个仓库给自己提权了。**它是跟着 `git clone` 来的，**不该由它决定这个 agent 能干什么** |
| **子 agent 拿到了比父更宽的权限** | 派发成了提权路径——**父自己没有的东西，派一个子出去就有了** |
| 安全策略通过关掉门来收紧 | 同上。收紧只能靠执行环境、权限、装配清单 |
| 十三扇门逐个动作占槽位（而不是一门一位） | 常驻预算当场爆掉，**meta 这件事在预算上不成立** |
| **有人开始实现 `Engram()`** | **它现在没有可实施的定义**——[本版只占位](design.md#613-engram通向自己的知识结构占位声明不作实现交付要求)，连命令集都不定。**动手前必须先回来把那一节做完** |
| **`Engram()` 被当成「记忆功能」做出来** | 记忆是它**能承载的一类内容**，**不是它本身**——它动的是**知识的结构**，不是「记住一件事」 |
| `Tools().execute` 或 `Skills().read` **改变了 system prompt** | [PF-006 那条](../PF-006-tools-and-skills/design.md#51-三层正交)当场作废 |
| `Skills().read` 产生了一个需要维护的"已启用"状态 | 同上 |
| 搜索把当下不可用的东西**藏起来** | agent 会以为自己没这个能力，而实际只是暂时用不了 |
| `Files().edit` 改不准时"尽力而为"地改个差不多的地方 | **改错位置比不改更糟**，而且很难被发现 |
| `Files().patch` **部分应用**，留下改了一半的文件 | **最糟的状态**：既不是成功也不是失败，而且**看上去像成功** |
| `Skills().exec_script` 能跑任意路径的脚本 | 它成了 `Shell()` 的后门，**对命令行的权限管控当场作废** |
| skill 脚本的执行权按「能不能跑 shell」判断 | 粒度错位。审核过的 skill 与随意跑命令被当成了同一件事 |
| `Files()` 与 `Shell()` 合并 | 编辑不可靠、权限管不住、结果没有形状 |
| `Browser()` 与 `Computer()` 合并 | 网页操作退化成截图点坐标；或者浏览器之外的界面全碰不了 |
| 设施给不了时**降级**到别的门顶替 | 与 [PF-005 沙箱创建失败退回宿主机](../PF-005-execution-environments-and-sandboxes/design.md#62-宿主机不提供租户隔离因此必须被显式允许)同性质 |
| 外部取回的内容被当成指令执行 | **提示注入**。网上的文字、页面上的文字，都只是数据 |
| `BkgJobs().terminate` 被记成失败 | agent 会重试一件它自己刚决定不做的事 |
| 分不出后台执行是 agent 掐的还是用户掐的 | 两者的后续处理不同，混在一起无从判断 |
| `BkgJobs()` 能看见别的 session 的执行 | 视野越界 |
| `execute` 对着一个不存在的会话**悄悄降级**成一次性执行 | agent 以为自己接着上一条，**其实状态全丢了**，而它不知道 |
| `cwd` / `envs` 改写了会话本身的状态 | 「这个会话现在在哪」不再有唯一答案 |
| **一次问询到点了，系统替人给了个答案** | **替人签字。**无论到点算同意还是算拒绝，都是同一种越权 |
| **人说的话被翻译成了一个它并不是的裁决** | 同上。**人有话说**与**人作了决定**是两回事 |
| **人只说了「这次可以」，系统当成「这类事以后都可以」** | **那是替他作主，不是理解他。**当事人根本不知道自己批准了什么 |
| **话说得含糊，系统往宽里算** | **授权的原则是只保守**——[说不清就按「仅下一次动作允许」算](design.md#611-ask通向人)。少给了他再说一句就补上，**多给了事已经做完了** |
| **一个问题没给自由作答的口子** | 人被困在几个都不对的答案里，只能挑一个最不错的 |
| **自由作答这条路靠 agent 记得留** | 总有忘的时候，而那一次就退化成上一条 |
| **候选项只有图、没有文字** | 引用不了、复述不了，**读屏的人直接被挡在门外** |
| **先把事做了，再请示** | 那不叫请示，叫通知。人拒绝的时候已经晚了 |
| **有人在会话里说一句，就改掉了整个租户的授权面** | **越权。**作用域是他表达的意图，**能不能生效仍按他自己的身份与权限判** |
| **权限设置里明确禁止的事，靠会话里点个同意就做成了** | 任何禁止都能这么绕过去。**会话里坐着的那个人，未必是设权限的那个人** |
| **会话被归档，攒下的授权跟着没了** | 授权是数据，**[归档不动它](../PF-015-session-lifecycle-and-ownership/design.md#67-归档不动授权)**。「工作被取消」推不出「授权也没了」 |
| **撤回了一笔授权，却还得去某个清单里把它划掉** | 说明存了一份「已获准清单」。**那正是「以为撤了其实没撤」的来源**——结论必须现算 |
| **本会话里同一件事反复来敲门** | 人很快就会闭着眼点同意，**那时这扇门形同虚设而看上去还在工作** |
| **agent 拿到批准后做的事比请示的多** | 人签的是那段文字。多做的部分没有任何人批准过 |
| `Cordis()` 做成可写的 | 「看得见」与「改得动」之间那道墙没了，agent 能改自己的骨架 |
| `Cordis()` 能看见整个部署 | 租户隔离在这扇门上破掉 |
| 子 agent 的成本算到子 agent 自己头上 | 归属随层级漂移，账算不清 |
| **`spawn` 被做成一个独立的主会话** | **那个形状叫 `handoff`。**两种模式被合成一个，[五个维度](design.md#派发有三种模式)里有四个跟着错 |
| **`spawn` 出去的那个与派发者读同一本会话日志**，或它的日志指向父的日志 | **那是 `fork`，不是 `spawn`。**[两个会话在存储上不共享节点](../../ubiquitous_language/decisions.md#ul-d-4--主会话与子会话--2026-09-21)；而且**子会看见派发之后才发生的事**，[规则一那条通路随之变得可有可无](design.md#先说谁能给谁发消息这是两条独立的规则) |
| **`handoff` 之后双方断了联系** | **协作最需要的那条线被剪掉了。**它有主会话身份，[规则二](design.md#先说谁能给谁发消息这是两条独立的规则)本来就适用 |
| **只有 `delegate` 能被跟进，另两种不能** | [规则一](design.md#先说谁能给谁发消息这是两条独立的规则)对**任何**派出去的都成立。这样做**无端削掉另外两种的可观测性** |
| **`withdraw` 能把 `handoff` 收回来** | **那它就不是 `handoff` 了，是 `delegate`。**「不受派发者控制」是它的定义 |
| **`spawn` / `delegate` 出去的，除了那一次报告就再也说不上话** | [规则一是双向的](design.md#先说谁能给谁发消息这是两条独立的规则)。**报告终结的是这次派发，不是那条通路**——[干到一半确认一件事实、澄清一句需求，全靠它](design.md#报告与消息是两样东西) |
| **消息发不出去时只回一句「发不出去」** | agent 无从判断该换个人、该等一等，还是**这条路压根不存在**——[四种原因的处理方式完全不同](design.md#命令) |
| **跨租户的两个 agent 通上了** | 租户隔离在这条通路上破掉 |
| **`handoff` 的派发动作停下来等它干完** | 那是 `delegate` 的行为。`handoff` **确认会话建起来就返回** |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 基本盘成立 | 造一个零配置 agent，**十一件事都能做** | 它什么都干不了 |
| 多命令范式省得下预算 | 门后从 10 个动作加到 1000 个，**槽位数不变** | 槽位跟着长 |
| 不可禁用 | 把所有能想到的收紧手段都试一遍，**门一扇都关不掉** | 有一条路能关掉 |
| 不可替换 | 试图用自定义实现覆盖，**顶不掉** | 顶掉了 |
| 三对不重叠 | 分别说得出：为什么 `Files()` 不能用 `Shell()` 做、`Web()` 不能用 `Browser()` 做、`Browser()` 不能用 `Computer()` 做 | 说不出，那就该合并 |
| `patch` 真的原子 | 造一个中途必然失败的多处改动，**文件一个字节都没变** | 留下了改了一半的文件 |
| 脚本执行不越界 | 穷举各种路径写法，**一个不属于该 skill 的脚本都跑不到** | 有一条路能跑到别处 |
| system prompt 恒定 | 一次 run 里走遍十一扇门，**system prompt 逐字不变** | 走完变长了 |
| 后台够得着 | 发起一个长任务，几轮之后**看得见、停得掉** | 扔进后台就再也够不着 |
| 等待态复用 | `Ask()` 用的就是 PF-006 的原语，**不另造机制** | 它有一套自己的状态 |
| 问询不替人作答 | **翻遍设计找不到任何「多久之后算什么」** | 有一个默认答案藏在某处 |
| 批准不会扩散到设置 | 人说一百次「以后都行」，**权限设置仍然一个字没变**——那一笔落在[会话授权上下文](design.md#会话授权上下文)里 | 有一条路让一次批准改动了权限设置 |
| 批准也不会白批 | 本会话里同一件事**不再问第二遍** | 每一步都来敲门 |
| 授权照他说的作用域走 | 他说「这次可以」，换一个会话**同样的事要重新问**；他说「以后所有会话都这样」，**换一个会话不再问**；**他没说清就按最窄的算** | 作用域被系统替他放大，或者不论他说什么都只管这一个会话 |
| 禁止是硬的 | 权限设置里禁掉的事，**会话里点同意也做不成** | 禁止能被绕过，那它就是摆设 |
| 外部内容是数据 | 在页面里埋一句指令，agent **不照做** | 它照做了 |
| `Cordis()` 定义完整 | 虽然不实现，**照着产品设计能直接做**：命令、看得见什么、四条红线、两侧，一样不缺 | 只有一个名字 |
| 检视面会生长 | 装一个新插件，`list` **多出它贡献的那一项**，没有人改过任何总表 | 得有人去维护一张清单 |
| **三种派发模式分得开** | 拿[五个维度](design.md#派发有三种模式)逐一核对，**三种模式的取值组合各不相同**，且**每一格都说得出为什么** | 有两种模式在所有维度上都一样——那它们本该是一个 |
| **两处分水岭各自只有一条** | 说得出：`spawn` 与 `delegate` 只差「**带着什么开始干活**」；`spawn`/`delegate` 与 `handoff` 只差「**是不是独立主会话**」，**另外三个维度全是它的后果** | 说出了第二条分界——那多半是编的 |
| **报告与消息分得开** | `spawn` / `delegate` 出去的**交一次报告这次派发就结束**；而消息**来回多少次都不终结任何东西** | 两者被做成了同一条通路 |
| **通信判定按规则走** | 造出[四种发不出去的原因](design.md#命令)，**每一种回的话都不同** | 四种都回同一句 |
