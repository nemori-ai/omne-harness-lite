### ST-016-02 · 创建的组织名称可被有权客户端共同读取

- **价值**：用户在不同客户端看见同一个组织名称，能分清同名但身份不同的组织
- **覆盖场景**：[S1](../PF-001-identity-scope-and-agent-constraints/acceptance.md#组织名称)、[S2](../PF-001-identity-scope-and-agent-constraints/acceptance.md#组织名称)、[S3](../PF-001-identity-scope-and-agent-constraints/acceptance.md#组织名称)、[S4](../PF-001-identity-scope-and-agent-constraints/acceptance.md#组织名称)
- **演示**：
  1. 注册并读取个人组织 → 初始名称为“个人组织”
  2. 提供名称创建团队组织，用另一有权客户端读取 → 两处名称相同，创建者为首位超级管理员
  3. 再创建同名组织 → 名称相同但组织与租户身份不同
  4. 不提供有效名称创建 → 明确失败，没有部分组织或成员关系
- **不含**：组织改名、本机组织别名
- **前置**：无
- **就绪**：是

### ST-016-03 · 登录到期时原 Run 继续，新 Run 等待有效登录

- **价值**：用户的在途工作不会因登录到期被截断，下一轮也不会沿失效登录开始
- **覆盖场景**：[S8](acceptance.md#新-run-的登录确认)、[S9](acceptance.md#新-run-的登录确认)、[S10](acceptance.md#新-run-的登录确认)、[S11](acceptance.md#新-run-的登录确认)
- **演示**：
  1. 场景一：启动一个 Run，在它执行中让登录到期 → 原 Run 的合法下一 Attempt 继续产生响应，已放行动作继续收场
  2. 场景二：会话没有未终结 Run；登录有效时持久受理消息，在新 Run 开始前让登录到期，再确认登录状态 → 新 Run 未开始，原消息保留，提示重新登录
  3. 场景三：另以有效登录持久受理消息，在新 Run 开始前使中心不可达，再尝试开始 Run → 明说无法确认登录，不以副本放行
  4. 在场景二或三恢复中心连接、重新有效登录并满足当前准入条件 → 原会话归属与历史保持，原待处理消息无重复地继续处理
- **不含**：自动续期、自动重放治理写、免除其他动作准入
- **前置**：无
- **就绪**：是
