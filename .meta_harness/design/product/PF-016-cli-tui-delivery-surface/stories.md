### ST-016-01 · 在没有屏的地方用了人读入口，当场被告知并指到机读入口

- **价值**：在脚本、管道或没有终端的环境里用 `omne` 的人，敲了一条给人看的命令时，不必去翻帮助就知道该换哪一条；他也不会拿到一套悄悄换了形式的输出
- **覆盖场景**：[S5](acceptance.md#给脚本用)
- **演示**：
  1. 把一条给人看的治理命令的输出接进管道：`omne tenant current --state-dir <一个还不存在的目录> | cat` → 标准输出什么都没有；错误输出第一行是 `omne: tty-required`，接着一行说明这条命令要在真正的终端里用，并给出同一件事的机读写法 `omne machine tenant current`；命令以「用法不对」收场；那个目录没有被创建
  2. 照提示改用机读入口：`omne machine tenant current --state-dir <同一个目录> | cat` → 标准输出是一份完整的 JSON 文档，说明此刻办不了这件事的原因（这台机器还没有配置过）
  3. 在没有终端的地方起全屏界面：`omne tui --terminal-profile xterm-379 --state-dir <同一个目录> </dev/null | cat` → 同样是两行：`omne: tty-required`，接着指到机读入口 `omne machine`；界面没有起来
  4. 用一个它不认识的终端类型起全屏界面：`omne tui --terminal-profile no-such --state-dir <同一个目录>` → 第一行是 `omne: tty-unsupported`，接着同样指到机读入口
  5. `omne --help` → 与做这张卡之前一字不差
- **不含**：把给人看的命令自动改成机读方式接着执行（那正是不许的静默降级）；机读入口自身的输出格式；终端太小、输入被别的程序占用等情形下除「指到机读入口」之外的引导；**有屏、但命令缺了凭据文件**的那种拒绝（那不是没有屏，机读入口同样要凭据文件，指过去是错的——它照旧只报原来那一行）
- **前置**：无
- **就绪**：是
