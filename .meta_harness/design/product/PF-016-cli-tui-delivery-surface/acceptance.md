# PF-016 验收标准

这是**产品视角**的验收：人看到什么、能做什么、做错时发生什么。
**每一条都应当能交给一个不懂实现的人，让他照着判断产品对不对。**

**本页不重复别的 topic 的验收。**
[一条入站到达不许被静默丢弃](../PF-014-inbound-intake-and-queueing/acceptance.md)、
[一次运行怎样才算落了终态](../PF-012-agent-loop-and-run/acceptance.md)——那些在各自那里验。
**这里只验这块交付面自己的承诺。**

## 一、可观察场景

### 装起来、进组织

| 场景 | 应有表现 |
|---|---|
| 一位同事在一台干净的机器上装好之后，第一次运行 | **不能直接开会话。**它明说[还差「准备好」那两样里的哪一样](design.md#62-没准备好就开不了会话)——连哪个[治理中心](design.md#治理中心)、有没有一个有效的登录状态——并指出下一步做什么 |
| 他刚登录完，**还没配模型凭据** | **开得了会话**（凭据[不在「准备好」那两样里](design.md#62-没准备好就开不了会话)）；**但屏上要提前说出来**：模型这一层还没配。**第一次真要调模型时失败，并指得出是这个原因** |
| 他注册、登录之后 | 当前身份摆在他看得见的地方：**哪个账号、[当前租户身份](../PF-001-identity-scope-and-agent-constraints/design.md#当前租户身份)是哪一个** |
| 超级管理员建了团队组织并向他发了邀请 | 他**进来就看得见**这份邀约，**连同它什么时候到期**——不需要任何人另外通知他 |
| 他接受邀请、切到那个租户身份，然后开会话 | 这个会话**属于新的那个租户**；他[先前在个人组织下建的会话一个都没变](../PF-001-identity-scope-and-agent-constraints/flows.md#18-切换当前组织) |
| 两个账号在同一台机器上各自登录、各自开会话 | 彼此**列不出、看不见、进不去**对方的会话与卡片 |
| 超级管理员向一个**还没注册**的标识发邀请 | **如实说这个标识还没注册**，请对方先注册；邀请没有发出去（[flows 1.2](flows.md#12-超级管理员把同事请进来)） |
| 他在另一台机器上登录同一个账号 | [观感偏好](design.md#观感偏好)**还是那一套**——它跟着账号走；但**那台机器上没有这台机器上的会话** |

### 在会话里

| 场景 | 应有表现 |
|---|---|
| 他进来时没有指名任何会话 | **开的是一个新会话**；最近的几个会话摆在他看得见的地方，要接上次的得指名。**他在说第一句话之前知道这句话会落进哪个会话**（[§6.18](design.md#618-进来没指定会话就是新的当前目录是本租户的工作区就默认挂上)） |
| 他在一个**本租户记下的[工作区](../../ubiquitous_language/terms/scope-and-resolution.md#ul-workspace--工作区--workspace)目录**（或它的子目录）下开会话 | 那份工作区**默认挂上**，并在他开口之前显示出来；他可以换一份或不挂 |
| 他在一个**无关目录**下开会话，或那个目录只被**别的租户身份**记成了工作区 | **那一级为空**，不提示别的租户有；要挂得指名 |
| 人打完一句话按下提交 | 屏上出现的是**落盘之后的那一条**。落盘没成功时，**屏上什么都不留** |
| 一次运行在跑 | 屏上的条目**顺序与[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)一致**；每一条都指得回日志里的一条 |
| 系统停下来等人 | 一张[卡片](../PF-008-human-in-the-loop/design.md#决策卡片)摆到眼前，**没有倒计时、没有默认选项、没有「不回就当同意」** |
| 人在卡片上作答，或表示「这个我不答」 | 两种都算[人处理了它](../PF-008-human-in-the-loop/design.md#61-永远等着系统不替人作答)；**一张卡片只能答一次**，在哪儿答的都算数 |
| 人要归档一个还在跑的会话 | **先逐条说清连带的三件不可逆的事**，再让他确认（[§6.13 第一档](design.md#第一档连累别的对象的逐条说清再让人确认)） |
| 人要发「停」，而他其实只想[插一句话](../PF-014-inbound-intake-and-queueing/design.md#插队) | **在按下去之前就分得出这两件事**——一个[让运行落终态、回不去](../PF-012-agent-loop-and-run/design.md#66-终态不可逆且只有一个出口)，一个不终止运行（[§6.13 第二档](design.md#第二档只作用于这一次运行的把差别摆在按下去之前)）；**这一档不加确认**，[理由在那里](design.md#613-回不去的后果人动手之前就得知道) |
| 人要发「[强制停止](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-forced-stop--强制停止--forced-stop)」 | 他分得出它与「停」的差别：**连执行资格一起撤，且外部效果收不回来** |
| agent 要动一个作用会落到这台机器上的工具，而[没有被显式允许](../PF-005-execution-environments-and-sandboxes/design.md#62-宿主机不提供租户隔离因此必须被显式允许) | 明说**这个动作不能直接落在这台机器上**，并给出下一步（允许它，或换落点）。**不静默换个地方跑掉** |

### 关掉、回来、离开

| 场景 | 应有表现 |
|---|---|
| 人关掉屏、断线、重启机器 | 会话、日志、等着的卡片、已经表达过的授权**一样都不少**；**这个会话不会因此落入[归档](../PF-015-session-lifecycle-and-ownership/design.md#会话归档)、子会话不会被级联归档、等着的卡片不会从[池子](../PF-008-human-in-the-loop/design.md#决策池)里消失**（[§6.8 那三件](design.md#68-关掉屏不会让任何东西丢掉)）。**断线与重启造成的停机，在途活儿的收场照 [PF-012 的停机口径](../PF-012-agent-loop-and-run/design.md#三个运行时停机之后各算什么)，不在这条里验** |
| 他关掉屏，而一条**定时到点的入站到达**在这期间到了；或队列里还有没跑完的 | **照常被受理、照常跑**（[§6.16](design.md#616-没人开着屏这一处照常发生事)）；他回来时看到它已进队列或已跑完，日志里有那几条 |
| 他关掉屏，一个会话在这期间**到了自动归档的期限** | **照常被收**，不等他下次打开 |
| 他过两天回到同一个会话 | 看到的历史与[会话日志投影](../../ubiquitous_language/terms/record-and-context.md#ul-session-log-projection--会话日志投影--session-log-projection)**逐条一致**，包括他不在时跑出来的那几条；该等的还在等 |
| [治理中心](design.md#治理中心)连不上，他想开一个新会话 | **明说是「问不到你的成员资格」**，不是「你没有权限」，更不是拿旧副本放行 |
| [治理中心](design.md#治理中心)连不上，他在一个**已经开着的会话**里接着干活 | **说话、跑运行、调工具、答卡片照常**（[§6.17](design.md#617-治理中心不可达已经开着的会话照常干活)）；屏上标明此刻连不上中心、用的是上次读到的配置；**没有任何离线时长上限** |
| 他离线期间在别处被移出了组织，之后这台机器**重新连上**中心 | 那个租户下的会话**收起来**：不再呈现、不再受理新的东西；**正在跑的那一次不被强制停下**，跑完即止（[§6.10](design.md#610-成员资格无效期间本机那些会话不呈现也不删)） |
| 他被移出了组织（[治理中心](design.md#治理中心)可达，成员资格读得到） | 那个租户下的会话**进不去、也不再呈现**；**但它们没有被删掉**，重新加入之后原样可用 |
| 他在离线时想看自己属于哪些组织 | **看得见**（那是副本，只用来显示）；**但一次放行也做不了** |
| 他在两台机器上各开了会话，各自攒了卡片 | 每台机器上的[池子](../PF-008-human-in-the-loop/design.md#决策池)**只有这一台上的那些**，并标明它是这一处的（[§6.19](design.md#619-这里看到的池子是这一处的)）；两边加起来才是他全部等着的 |
| 他还没配自己那把[凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)，而组织在组织层配了一把 | **他这台机器上调不了模型**——组织那把不下发（[§6.20](design.md#620-每台机器上只有自己那一把凭据)）；失败指得出是「没配自己那一把」 |

### 给脚本用

| 场景 | 应有表现 |
|---|---|
| 一段脚本把整条链跑完 | 落下的记录条目序列**与人走一遍时相同** |
| 脚本读回的事实 | **只有事实**，没有进度、提示、诊断混在里面；每一条都说得出**它以谁的身份产生** |
| 脚本遇到一张没人答的卡片 | 它停在**「等人」**，并且这个收场**与「这次运行失败了」分得开** |
| 脚本想做人能做的某件事 | 做得了；**做不了的必须在正文里被具名列出**（[§6.5](design.md#65-人能做的脚本能做脚本能做的人能做)） |
| 在没有屏的环境里去用人读那一份 | **明说用不了并指出机读那一份**，不静默换一种方式接着跑 |
| 同一个场景开着调试跑一遍、关着再跑一遍 | 两次的记录条目序列**逐条相同** |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| **屏上显示了一条日志里没有的东西** | 这块屏不能再被当作判断系统对错的依据——**而研发者正是在用它验尸** |
| **一个账号的交付面列出、显示或进入了另一个账号的会话或卡片** | [隔离](../PF-001-identity-scope-and-agent-constraints/design.md#64-隔离)在人唯一看得见的地方破了 |
| **超级管理员看到了本组织成员的会话内容** | 把治理权限读成了数据访问权限；[PF-001 明写超管不取得成员个人范围的访问权](../PF-001-identity-scope-and-agent-constraints/design.md#角色) |
| **[治理中心](design.md#治理中心)不可达时，靠本地副本放行了一次准入** | [撤销向后生效](../PF-001-identity-scope-and-agent-constraints/design.md#66-撤销不等于强制停止)被悄悄改成了「离线多久之后才生效」 |
| **交付面替人答了一张卡片**（超时、默认值、脚本里的「自动同意」） | [PF-008 §6.1](../PF-008-human-in-the-loop/design.md#61-永远等着系统不替人作答) 破了，**而它破在没人看着的那一次上** |
| **关掉屏让会话落入了[归档](../PF-015-session-lifecycle-and-ownership/design.md#会话归档)**、级联归档了子会话、或让等着的卡片从池子里消失 | **一个日常动作造成了[只有归档才该造成的不可逆后果](../PF-015-session-lifecycle-and-ownership/design.md#63-归档先停活儿再落状态)** |
| **一个人被移出组织之后，他机器上那些会话被自动清掉了** | 那就是删除会话，[而系统不提供删除会话的能力，任何角色都不提供](../PF-015-session-lifecycle-and-ownership/design.md#61-会话不会消失) |
| **[凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)的值出现在屏上、机读输出里或调试输出里** | 它会跟着屏幕的回滚记录、日志文件与粘贴出去的那段输出一起走 |
| **留下一个看起来还在跑、实际没人在跑的运行** | 人会一直等一件不会发生的事；[而该不该起一副 runtime 只看日志](../PF-012-agent-loop-and-run/design.md#agent-runtime) |
| **同一个场景，两种[呈现形式](design.md#呈现形式)跑出了不同的记录** | [§5.5](design.md#55-两种呈现形式同一份事实) 破了——**脚本验出来的「成功」与人看到的「失败」会同时成立** |
| **存在一件只有脚本能做、屏上没有的动作** | 那是一条没人复核的后门 |
| **没人开着屏的那段时间里，一条到了的入站到达被丢了、或到期的会话没被收** | [据点没有照常运转](design.md#616-没人开着屏这一处照常发生事)，[PF-014 §6.8](../PF-014-inbound-intake-and-queueing/design.md#68-停机不会让一条入站到达永远悬着) 在本形态下破了 |
| **把别的租户身份记下的工作区默认挂到了这个会话上** | [跨租户默认拒绝](../PF-001-identity-scope-and-agent-constraints/design.md#64-隔离)在会话创建这一步破了 |
| **组织层的那把凭据出现在了同事的机器上** | [离职时收不回](design.md#620-每台机器上只有自己那一把凭据)——那正是被排除的做法 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| [交付面不持有领域事实](design.md#61-交付面不持有任何领域事实) | 拿屏上（或机读那一份里）任意一条，**指得回[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)里的一条** | 有一条指不回去——那就是交付面自己编的 |
| [两种呈现形式同源](design.md#55-两种呈现形式同一份事实) | 同一场景两种形式各跑一遍，**记录条目序列逐条相同** | 两边条数或顺序不同 |
| [人做的事走的都是已有的路](design.md#54-人做的每一件事走的都是已有的路) | 把屏上所有能做的事列一遍，**每一件要么是入站到达（落在三个去处之一），要么是[正文具名列出的那几条会话事实](design.md#第二类具名的那几条会话动作它们不经入站到达)，要么根本不进任何会话** | 出现一件**三者都不是**的；或者具名清单之外又冒出一条「也是会话事实」 |
| [没准备好就开不了会话](design.md#62-没准备好就开不了会话) | 在一台没登录的机器上试着开会话，**开不了，且说得出差哪一样** | 会话建起来了，事后才发现归属不对——**而归属改不回来** |
| [当前身份一直在场](design.md#63-当前身份必须一直在场) | 屏上任意时刻都看得到账号与当前租户身份；机读的每一条都说得出以谁的身份产生 | 人做完一个动作之后才发现自己站错了地方 |
| [现读的范围是具名三类](design.md#69-需要现读成员资格的那几件事不拿副本放行) | 断开中心：**那三类每一个都明确失败**；**读类照常显示且标明「这是上次读到的」**；会话里的事[照常](design.md#617-治理中心不可达已经开着的会话照常干活) | 断网之后还能建会话；或者反过来，断网之后连自己属于哪些组织都不给看、连手上的会话都干不了 |
| [没人开着屏，这一处照常发生事](design.md#616-没人开着屏这一处照常发生事) | 关掉屏，安排一条定时到达、让一个会话到期：**回来时到达已被受理、会话已被收** | 回来才开始处理——那就是「下次打开才收」 |
| [进来没指定会话就是新的；当前目录是本租户的工作区就默认挂上](design.md#618-进来没指定会话就是新的当前目录是本租户的工作区就默认挂上) | 不指名进来得到的是新会话；在工作区目录下开的会话挂着那份、在无关目录下开的那一级为空；**两种情况下他开口前都看得见挂了什么** | 进来接上了昨天的会话而他不知道；或目录没被记成工作区却被挂上了 |
| [保留但不可达](design.md#610-成员资格无效期间本机那些会话不呈现也不删) | 把一个人移出组织，他那些会话**进不去**；把他重新邀请回来，**原样可用** | 数据没了，或者移出之后还进得去 |
| [观感偏好不改变领域行为](design.md#612-观感偏好不改变任何领域行为) | 换配色、换键位、开调试各跑一遍，**日志逐条对得上** | 开了调试之后行为变了——**那这块面就不能用来观察** |
| [回不去的后果，人动手之前就得知道](design.md#613-回不去的后果人动手之前就得知道) | **第一档**：归档一个在跑的会话之前，**那三件事逐条出现在他眼前**。**第二档**：屏上分得出「停」与「[插队](../PF-014-inbound-intake-and-queueing/design.md#插队)」、「停」与「强制停止」——**但不为它们加确认** | 他确认之后才知道子会话也被收了；或者他想插一句话却把跑了两小时的任务停了 |
| [进来就看得见等着的事](design.md#614-没有带外通知所以进来就要看得见等着的事) | 一进来就看得到等着答的卡片与等着点头的邀约，**连同到期时间** | 有邀约白白过期，而他从头到尾不知道有这回事 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| **自己起一个治理中心的那条路** | [它不是产品形态](design.md#二目标与非目标)，研发夹具不验产品承诺 |
| **机器关机期间到期归档的时钟怎么算** | [§9 未决](design.md#九未决项)，归 PF-015 的 owner |
| **据点那个一直运转的东西占多少资源、怎么起怎么停、机器休眠算什么** | 归技术设计；产品只验[「机器开着时它照常发生事」](design.md#616-没人开着屏这一处照常发生事) |
| **中文输入、宽字符、屏幕闪烁这一类** | **产品侧给不出可判断的标准**——它们的表现取决于具体的终端程序。归技术设计，在那里说清测到什么程度 |
| **断线、重启造成停机时，在途的工具执行与模型调用怎么收场** | 停机之后各算什么[已经由 PF-012 定死](../PF-012-agent-loop-and-run/design.md#三个运行时停机之后各算什么)，在那边验。**本 rev 只验[§6.8 那三件可判定的](design.md#68-关掉屏不会让任何东西丢掉)与[关屏不是停机](design.md#616-没人开着屏这一处照常发生事)** |
