## 一、背景与问题

**这套系统的产品设计已经把会话、运行、卡片、受理定得很细，却没有一处回答「人从哪里进来」。**

[卡片摆在人眼前等他答](../PF-008-human-in-the-loop/design.md#决策池)、
[外面进来的事走同一个受理面](../PF-014-inbound-intake-and-queueing/design.md#入站到达)、
[会话睡醒还是原来那个](../PF-015-session-lifecycle-and-ownership/design.md#611-会话睡醒之后还是原来那个)——
**每一条都写着「人」或「用户」，而那个人站在哪里、用什么东西看、用什么东西答，从来没有被定义过。**

这造成三个具体的空洞：

**第一，没有任何人能用它。**一位同事想在自己的电脑上跟 agent 干活，
他得先拿到一个可安装的东西、注册一个账号、登录、进他公司的组织——
**这四步一步都没有落点**。

**第二，组织那条线走不完。**[PF-001 定了注册、登录、建组织、发邀请、接受、切换当前租户身份](../PF-001-identity-scope-and-agent-constraints/flows.md#一主要旅程)，
每一个动作都写清了谁能做、做完什么算数。
**但这些动作此刻没有任何发起处**，而本版**没有网页，也没有邮件这类带外通道**——
连「乙怎么知道甲邀请了他」都没有答案。

**第三，整条链无法被端到端验证。**「输入 → 受理 → Run → 模型与工具 → 等人 → 终态 → 记录」
是十几份设计咬合出来的一条链，**它至今没有在一套真实装配上从头跑到尾过**。
没有载体，每一份设计都只能各自看起来对。

**不做会怎样**：这些设计一份也交付不出去——
**它们描述的那个系统，没有任何一个人能够碰到它**。
同时，账号、组织、邀请、隶属这条线**连一次真实的走通都没有**，
而它是租户隔离这条硬约束落地与否的唯一检验方式。

## 二、目标与非目标

### 目标

- **给这个系统第一个[交付面](#交付面)**：一个装在用户自己机器上的命令行应用，
  同事各自安装、注册、登录、进组织，在自己的机器上开会话、跟 agent 协作、答卡片、翻历史。
- **把「人做的事」全部接到已有的入口上**，一条新的领域通路都不开
  （[§6.1](#61-交付面不持有任何领域事实)）。
- **定清三处地方各自拥有什么**：人面前那块屏、[会话据点](#会话据点)、[治理中心](#治理中心)。
- **让脚本和人用同一份事实、同一条受理**（[§5.5](#55-两种呈现形式同一份事实)），
  从而整条链可以被脚本驱动着跑完并留下可核对的记录。
- **把这条形态带来的新后果说清楚**——会话落在个人机器上之后，
  哪些事情跟着变了（[§5.6](#56-哪些东西在中心一侧哪些在据点一侧)、[§6.10](#610-成员资格无效期间本机那些会话不呈现也不删)）。

### 交付分批

交付顺序是治理与独立模型调用作为基础，再交付独立工具执行，随后交付 Agent 工作会话；每一批各自验收。

| 批次 | 交付什么 | 人从哪里看到它 |
|---|---|---|
| **基础（首批治理）** | 10 人以内组织的内网治理 CLI/TUI 闭环，支持 Linux 与 macOS 客户端（下表）；模型调用作为可独立使用的基础能力 | 治理经本交付面；独立模型调用经开发期的模型调用示例 |
| **第二批** | 可独立运行的工具执行能力，在模型调用示例里接上工具执行并把结果返回给模型 | 开发者直接使用工具能力，也能经模型调用示例看到完整调用结果；无需先创建会话 |
| **第三批** | Agent 工作会话：开会话、对话、运行、卡片、持久会话与据点运行 | 本交付面；模型与工具在会话里出现 |

**首批交付 10 人以内组织的内网治理 CLI/TUI 闭环，支持 Linux 与 macOS 客户端。**
同事各自在本机安装客户端，连组织统一部署的治理中心。人数是首批使用规模，
不自动变成账号数上限，也没有给出硬件或并发峰值承诺；Windows 不在首批交付范围内。

| 首批必须走通 | 用户得到什么 |
|---|---|
| 安装、配置中心、注册、登录与退出 | 能从自己的电脑使用同一个中心，始终分得清所连中心和所用账号 |
| 创建组织、查看成员、调整角色、退出或移除成员 | 超管与普通成员按 PF-001 的边界行事；操作结果与当前身份可核对 |
| 邀请与隶属请求的发起、查看、接受、拒绝、撤回，以及解除隶属 | 人能找到待处理事项，并看清完成、拒绝或到期结果；不靠邮件或网页补流程 |
| 切换当前租户身份 | 当前账号不变，当前组织与角色清楚，操作不能串到其他组织 |
| 查看和逐个撤销自己的登录、主动更换凭据、到期重新登录 | 消费 PF-001 的身份规则，人用 CLI、TUI 与脚本得到同样结果 |
| 升级、备份与恢复的交付说明与验证 | 按 [PF-017](../PF-017-governance-center-as-deployable-application/design.md#618-备份与恢复的交付目标) 完成单机运维、每日备份与恢复工具；整机/磁盘损毁的灾备指标后续验收；客户端辨认版本、中心可用性与是否需重新登录，运维者不因此取得账号治理权 |

**人用 CLI 与 TUI 都覆盖上述治理操作，脚本也能完成同样的治理旅程。**
呈现不同不增加或减少治理权限；中心侧升级与恢复遵守 PF-017 的运维边界，不能借客户端治理入口开一条代办通道。

**Agent 工作会话在第三批交付。**本 topic 对会话、对话、工具执行、卡片、持久会话与据点运行的设计继续有效，
但这些场景不纳入首批实现和验收；完成治理闭环不能被称为 PF-016 全部兑现。
治理动作不必先创建会话、启动 Agent、配置模型或调用模型。
资产复制分享、模型配置与其他会话支撑能力不因列在本 topic 的完整动作表里就自动纳入首批治理交付清单。

各批内先做哪一块，见各 topic 的 `stories.md`：卡在文件里的先后就是建议的交付顺序。

### 非目标

| 不做什么 | 为什么 |
|---|---|
| **网页界面、桌面应用** | 本版只有这一个交付面。**桌面应用将来另立 PF**，那时它是[交付面](#交付面)的第二种，不改这里的概念 |
| **让别的客户端接进来**（编辑器协议、第三方前端） | 没有具名消费者。真出现时，它要的是一份协议，而协议归技术设计 |
| **远程操作别人的机器** | [会话据点](#会话据点)只服务坐在这台机器前的那个人。跨机器的只有据点与[治理中心](#治理中心)之间那一条 |
| **治理中心自身的产品设计** | 账号、组织、邀请、隶属、角色的规则**全归 [PF-001](../PF-001-identity-scope-and-agent-constraints/design.md)**；它怎么部署、怎么运维归部署那一侧 |
| **个人自托管一个[治理中心](#治理中心)** | 本版承诺的部署形态只有一种：**一个组织统一部署一个中心，同事的机器都连它**。一个人在自己电脑上起一个中心来用，**不是产品形态**——研发者为端到端验证起的那个中心是研发夹具，产品对它不作任何承诺（[裁定](design.md)）。**代价写在明面上**：[没有中心，一个会话也开不了](#62-没准备好就开不了会话)，包括只想在自己电脑上试一试的人 |
| **组织托管[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)、下发到据点** | [组织那一层不持有模型凭据](../PF-013-model-profiles-and-invocation/design.md#非目标)，每个人在自己的租户层带自己那一把，本版每台机器上只有那一把（[§6.20](#620-每台机器上只有自己那一把凭据)）。组织统一持有一把、发到每个人机器上，**离职时收不回**。要不要有「组织统一供给凭据」这件事，归 [PF-013 非目标](../PF-013-model-profiles-and-invocation/design.md#非目标)那一条，另立 topic 再议 |
| **用量与成本的呈现** | [计量这块还没有 topic 认领](../../domain_objects/pending.md)。本交付面不发明一套 |
| **图片、公式这类富呈现** | 模态归 [PF-013](../PF-013-model-profiles-and-invocation/design.md#模态)。屏上只给文本与[附件](../../ubiquitous_language/terms/execution-and-outcome.md#ul-attachment--附件--attachment)的引用 |
| **自动更新、灰度、使用数据上报** | 与本版要解决的问题无关，且都会引入新的产品承诺 |
| **[斜杠命令](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-slash-command--斜杠命令--slash-command)这类资产本身** | 那是资产，归 [PF-002](../PF-002-assets-settings-and-permissions/design.md) 与 [PF-006](../PF-006-tools-and-skills/design.md)。本交付面只提供**发起它的地方**，并且[要让人分得出它与交付面自己的动作](#57-人要做的事分三族) |

## 三、用户与场景

| 使用者 | 什么情况下接触这块 | 他关心什么 |
|---|---|---|
| **同事**（组织的普通成员） | 在自己的电脑上装一个东西，注册、登录、接受邀请，然后干活 | 装完之后还要做几件事才能开始说第一句话；东西会不会丢；过两天回来还在不在 |
| **超级管理员** | 建团队组织、邀请同事、看谁在里面、把人移出去 | 没有网页的情况下这些事怎么做；对方怎么知道；做错了能不能收回 |
| **研发者 / 脚本** | 用一段脚本把一整条链跑完，核对留下的记录 | 人能做的它能不能做；拿到的事实是不是和屏上那一份同源；失败时分得清是哪一类失败 |
| **agent** | 它的工具作用落在**同事自己的电脑上** | 落点准不准得上（[PF-005 要求被显式允许](../PF-005-execution-environments-and-sandboxes/design.md#62-宿主机不提供租户隔离因此必须被显式允许)）；停下来问人的时候，有没有人看得见 |

> **agent 在这一节里不是修辞。**本形态下
> [宿主机](../../ubiquitous_language/terms/grounding-and-isolation.md#ul-host-machine--宿主机--host-machine)
> **就是同事自己的那台电脑**——「工具的作用落到宿主机上」在这里的含义是
> **落到一个人的私人机器上**，而不是落到一台服务器上。

### 交付面

**系统把[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)投影给人看、
并把人做的事送进[受理](../PF-014-inbound-intake-and-queueing/design.md#入站到达)的那一面。**

**它有两个定义性质，缺一条就不是它：**

| | |
|---|---|
| **它不持有任何领域事实** | 屏上的每一条都能指回日志里的一条；它提交的每一件事都成为一条[入站到达](../PF-014-inbound-intake-and-queueing/design.md#入站到达)、一条卡片答复或一条[控制指令](../PF-014-inbound-intake-and-queueing/design.md#控制指令)。**它自己什么都不留** |
| **它没有自己的领域语义** | 它不新开任何通路。**凡是在它上面能做的事，都是别的 topic 已经定义过的动作** |

**本版只有一种交付面：一个装在用户自己机器上的命令行应用。**
它是**分发出去的一份东西**——同事各自安装、各自登录，装的是同一份。

> **为什么把它立成一个概念，而不只是「这个命令行应用」**：
> **会有第二个**——[桌面应用本版明确不做，而它一旦要做，是另立一个 PF](#二目标与非目标)。
> 上面那两条性质**对它同样成立**：它们不是这个命令行应用的实现约束，
> 是「什么东西有资格算作交付面」的判据。

**「一次使用」不是一个有身份的东西。**
同一台机器上可以同时开着好几处在用它，各自有各自的滚动位置、各自打了一半的草稿——
**这些东西退出即消失，产品不给它们任何身份**。
产品要说的一切，**都挂在[登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)与[会话据点](#会话据点)上**。

### 会话据点

**一个[账号](../PF-001-identity-scope-and-agent-constraints/design.md#账号)的[会话](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-session--会话--session)、
[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)、等着他答的[卡片](../PF-008-human-in-the-loop/design.md#决策卡片)，
以及跑他那些[运行](../PF-012-agent-loop-and-run/design.md#run)的[agent runtime](../PF-012-agent-loop-and-run/design.md#agent-runtime)，
实际所在的那一处。**

**本交付形态下，它就是这个人自己的那台机器**——
[会话、运行、工具执行都在用户本机](design.md)是产品负责人的裁定。

| 性质 | 说明 |
|---|---|
| **身份** | **（哪一处 · 哪个[治理中心](#治理中心) · 哪个账号）** 这一组合（[§5.2](#52-一个账号在一处怎么被装起来)） |
| **「一处」怎么算** | **「一处」是一个位置概念：这些会话的事实存在那里，也只从那里够得着。本交付形态把它落成一台机器**——**同一台机器上，同一个账号看到的永远是同一批会话**，不论他从这台机器的哪个入口进来；**换一台机器一定是另一处** |
| **产生** | 这个账号**在这一处第一次登录到某个[治理中心](#治理中心)成功**的那一刻，据点随之立起来。**它不是一个要人另外去做的动作** |
| **消失** | **这一处属于它的那份数据被清除**时。**本交付面不提供清除它的动作**（[flows §三](flows.md#三状态流转)） |
| **它不随任何一次使用生灭** | 关掉屏、登出、换一个人用这台机器，**据点都还在** |
| **没人开着屏的时候它照常发生事** | 后台触发照常受理、空闲的会话照常被拉起来跑、卡片照常攒着、到期的会话照常被收——**开着屏只是有人在看，不是这一处才开始运转**（[§6.16](#616-没人开着屏这一处照常发生事)） |
| **它装着什么** | 这个账号名下、**在这一处开的**全部会话及其日志；这些会话里等着人的卡片；正在跑的运行 |
| **它不装什么** | **治理事实**（账号、组织、成员资格、角色、邀约），以及[挂在组织层与租户层的那些设置、权限、资产与模型档案](#56-哪些东西在中心一侧哪些在据点一侧)——**一律在[治理中心](#治理中心)**。据点上可以留一份用于呈现的副本，**但那份副本不作[现读判定](#69-需要现读成员资格的那几件事不拿副本放行)的依据** |

> **「一处 = 一台机器」是本交付形态的落法，不是据点这个概念的语义。**
> 据点的语义只有那一句：**这些会话的事实存在那里，也只从那里够得着**——
> 它在单机与分布式下含义相同，将来「一处」可以是一台远端节点，
> [「别把单机焊进语义」](../PF-015-session-lifecycle-and-ownership/design.md#58-存储要守住的两件事)这条不被它违反。
> 东西实际落在哪个目录下、怎么分账号，归技术设计；
> **产品这边要守的是那句可被反例否定的话**：同一台机器上，同一个账号列出来的会话是同一批。
> **不这么要求，人会在同一台电脑上看不见自己昨天开的会话，而他无从知道为什么。**

> **它不是一个进程。**
> **「此刻有没有一个进程在服务它」与「它在不在」是两件事**——
> 正如[会话本来就不是活物](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-session--会话--session)、
> [「未终结」不等于有协程活着](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-run--运行--run)。
> **「没人开着屏时它照常发生事」说的是这一处的运转，不是某个进程**：
> 靠什么让它运转起来、那个东西什么时候起什么时候停，归技术设计；
> **产品只要求[§6.16](#616-没人开着屏这一处照常发生事)那句话在这台机器开着的任何时刻都成立。**

> **别和[宿主机](../../ubiquitous_language/terms/grounding-and-isolation.md#ul-host-machine--宿主机--host-machine)混。**
> 本形态下两者恰好是同一台机器，但**它们回答的问题不同**：
> 宿主机回答「一次工具执行的作用**落在哪**」，据点回答「这些会话的事实**存在哪**」。
> **落点每次执行现算，据点不是。**

### 治理中心

**[账号](../PF-001-identity-scope-and-agent-constraints/design.md#账号)、[组织](../PF-001-identity-scope-and-agent-constraints/design.md#组织)、
成员资格、[角色](../PF-001-identity-scope-and-agent-constraints/design.md#角色)、[邀约](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-offer--邀约--offer)，
以及[挂在组织层与租户层的那些范围化对象](#56-哪些东西在中心一侧哪些在据点一侧)、租户—工作区关系等治理事实所在的那一处，
独立于任何人的机器。**

| 性质 | 说明 |
|---|---|
| **身份** | **一次部署就是一个治理中心**。**它的身份不是它的地址**——地址是够到它的方式，**可以变**：同一个中心换了地址，人们的账号、组织与成员资格**一条不变** |
| **地址变了怎么办** | 这台机器上记着的是地址，所以**换地址在产品上是一件要被告知的事**：人必须分得清「中心搬家了」与「连到了另一个中心」。按 [PF-017 的中心标识](../PF-017-governance-center-as-deployable-application/design.md#612-同一个中心换了地址还是它另一个中心必须被认出来) 区分；标识不同明说是另一个中心，不把旧登录与身份接过去。可信性另须按 PF-017 确认，确认不了不交出登录状态、不接受答复 |
| **它是「部署」这个词在本形态下的所指** | [PF-001 说登录标识「部署内唯一」](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-login-identifier--登录标识--login-identifier)——**那个「部署」就是它**。两个治理中心上的同名标识**是两个账号**，互不相通 |
| **它不知道任何会话** | 会话、日志、卡片一概不在这里。**它连「这个租户开过几个会话」都答不出** |
| **它是那些事实的唯一权威** | 「这个租户此刻算不算数」「这一层配的是什么值」只有它答得准。别处的副本**只能用来显示，不作[那三类现读判定](#69-需要现读成员资格的那几件事不拿副本放行)的依据** |

> **为什么必须把它立出来**：**它不是实现细节，是用户看得见的产品事实。**
> 一个人注册在哪个治理中心上，决定了他的登录标识是谁的、他能被谁邀请、
> 他那台机器上的会话属于哪一套身份。**换一个治理中心，他就是另一个人。**

> **本版不要求一台机器同时连着两个治理中心。**
> 不要求，是因为[多组织的端到端验证在一个中心上就做得完](flows.md#14-一段脚本把整条链跑完)——
> 多组织靠的是多个账号与多个组织，不是多个中心。
> **而这件事不必另行设计**：一个[登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)
> 属于哪个治理中心，本来就是它身份的一部分。

### 呈现形式

**交付面把同一份事实交给读者的形式，恰有两种：**

| 取值 | 读者 | 它长什么样 |
|---|---|---|
| **人读** | 坐在屏前的人 | 排版、着色、可以原地更新的那一份 |
| **机读** | 脚本、CI、另一个程序 | 逐条、可被解析的那一份 |

**两种形式消费的是同一份[会话日志投影](../../ubiquitous_language/terms/record-and-context.md#ul-session-log-projection--会话日志投影--session-log-projection)、
走的是同一条受理。差别只在怎么交出去**（[§5.5](#55-两种呈现形式同一份事实)）。

> **它不是「两个功能」，是同一个东西的两种读法。**
> 做成两个，两边迟早对不上——而对不上的那一天，
> **脚本跑出来的「成功」与人看到的「失败」会同时成立**。

> **别和[会话运行模式](../PF-015-session-lifecycle-and-ownership/design.md#会话运行模式)混。**
> 那是「本该问人的那一刻改怎么办」，是会话的事；
> 这里是「这份事实交给谁读」，是交付面的事。**前者改变领域行为，后者一个字都不改。**

### 观感偏好

**这块交付面上那些只影响「看起来怎么样、用起来顺不顺手」的选择**——
具体的色板与样式、键位、一屏保留几轮、要不要去掉装饰只给线性文本。

**判据只有一条，与 [PF-015 判 runtime context 用的是同一条](../PF-015-session-lifecycle-and-ownership/design.md#55-哪些算-meta-runtime-context)：**

> **在 agent loop 内，模型、工具、拓展点**这三个角色**没有一个消费它**。

**所以它与[租户的界面偏好](../PF-015-session-lifecycle-and-ownership/design.md#56-十四项-meta-runtime-context)不是一回事**：
语言、时区、地区、**明暗风格**那几样**是要被 agent 感知的**，
[已经是每个会话必带的那十四项之一](../PF-015-session-lifecycle-and-ownership/design.md#56-十四项-meta-runtime-context)，
**不在这里，也不由这里定**。

**「明暗」与「配色」因此要分开读**：

| 这一样 | 归谁 | 为什么 |
|---|---|---|
| **明暗风格** | [PF-015 那一项](../PF-015-session-lifecycle-and-ownership/design.md#56-十四项-meta-runtime-context)。**本 topic 只消费** | agent 要感知它——它得知道自己写出来的东西会被摆在深色还是浅色上 |
| **具体色板与样式**（哪一档灰、粗细、留白） | **观感偏好** | 三个角色一个都不消费 |

> **两者必须一致**：屏上用着暗色、而告诉 agent 的是亮色，**那是自相矛盾**。
> **一致的办法是屏跟着 PF-015 那一项走**，不是在这里另配一个明暗开关。

**它跟人走：它是[个人 context](../../ubiquitous_language/terms/scope-and-resolution.md#ul-personal-context--个人-context--personal-context) 的一部分，由账号承载**（[裁定](design.md)）。
[PF-001 只定了个人 context 存在、由账号承载、与协作范围 context 正交，有哪些项不由它定](../PF-001-identity-scope-and-agent-constraints/design.md#contextagent-运行时可感知的上下文信息)——
**观感偏好是本 topic 往里放的一项**。后果有两条，都是用户看得见的：
**换一台机器登录同一个账号，还是熟悉的那一套**；它因此[在中心一侧](#56-哪些东西在中心一侧哪些在据点一侧)，
**中心不可达时用据点上那份副本，改了的值等再连上时送过去**。
**不论存在哪儿，[它不改变任何领域行为](#612-观感偏好不改变任何领域行为)。**

## 五、模型

### 5.1 三处地方，各自拥有什么

```text
   ┌────────────────────────────────────────────────────┐
   │                     治理中心                        │  一次部署一个，
   │  账号 · 组织 · 成员资格 · 角色 · 邀约                │  独立于任何人的机器
   │  组织层与租户层的：设置 · 权限 · 资产 · 模型档案      │  ← 对同组织的人一致的那些
   │  各人的个人 context（观感偏好在内）· 各人自带的凭据   │  ← 跟着账号或租户走的那些
   └──────────────────────────┬─────────────────────────┘
                              │  现读成员资格 / 发起治理动作
                              │（副本只用于显示，不作准入依据）
   ┌──────────────────────────┴─────────────────────────┐
   │            会话据点（这个人的那台机器）              │  （一处 · 中心 · 账号）
   │  会话 · 会话日志 · 等着的卡片 · 运行                  │  ← 只属于他这段协作的那些
   └──────────────────────────┬─────────────────────────┘
                              │  投影出去 / 把人做的事送进受理
   ┌──────────────────────────┴─────────────────────────┐
   │                      交付面                         │  同一台机器上可以
   │      人读的那一份          机读的那一份              │  同时有好几处在用
   └────────────────────────────────────────────────────┘  ← 什么都不持有
```

工作区的治理关系在中心；Omne Host 首版中心托管 Git 仓库，外部工作区资源不因此迁入中心。部署节点上的实例独立于会话，可由不同租户的会话共用；会话私有的是自己的选择与上下文，实例目录不属于某次协作的私有状态。

**这张图要读出三件事：**

- **箭头都是单向的。**据点向中心**问**、**发起**动作，
  **中心从不往据点里写会话**；交付面向据点**要**投影、**送**提交，**它自己不留底**。
- **中心与据点按治理事实、跨机器身份配置与会话事实分工；工作区另按资源所在提供者与实例装载节点区分**（[§5.6](#56-哪些东西在中心一侧哪些在据点一侧)）。
- **会话这类事实只在中间那一层，而那一层在用户自己的机器上**（最下面那一层也在他机器上，但它什么都不持有）。
  因此「我的会话在哪」这个问题的答案是
  **「在我自己的电脑上」**，而不是「在服务器上」——[这是裁定](design.md)，
  它的全部后果在 [§5.6](#56-哪些东西在中心一侧哪些在据点一侧) 与 [§6.10](#610-成员资格无效期间本机那些会话不呈现也不删)。

### 5.2 一个账号在一处怎么被装起来

**[会话据点](#会话据点)的身份是三样东西的组合：**

```text
   哪一处（这台机器）  ×  哪个治理中心  ×  哪个账号
```

**三样各有各的理由：**

| 为什么带这一样 | 理由 |
|---|---|
| **哪一处** | 会话的事实真的落在那台机器上。**换一台机器就是另一份**——这正是这条裁定最直接的后果。**[本形态下一台机器算一处](#会话据点)**，「一处」本身只是个位置概念 |
| **哪个治理中心** | [登录标识只在一个部署内唯一](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-login-identifier--登录标识--login-identifier)。**不带它，两个中心上的同名标识会被当成同一个人** |
| **哪个账号** | 归属的根。同一台机器上的两个账号**是两个据点**，[互不可见](#64-一台机器上账号之间互不可见但宿主机那一层不隔离) |

**这里有意不带的两样：**

| 不带 | 为什么 |
|---|---|
| **[登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)** | 同一个账号在这台机器上登录两次，**看到的是同一批会话**。登录状态回答的是「这次站在哪」，不是「东西在哪」 |
| **[租户](../PF-001-identity-scope-and-agent-constraints/design.md#租户)** | 一个账号的多个租户身份**共用这一份据点**；[租户之间的隔离照 PF-001 在里面成立](../PF-001-identity-scope-and-agent-constraints/design.md#64-隔离)，**不靠把据点拆成两份来实现**。拆了反而会出第二套隔离规则 |

**据点在[第一次登录成功](#会话据点)那一刻立起来，不必人另外做一个动作。**
**而「这台机器准备好了没有」是另一个问题**，它只有两样，[写在 §6.2](#62-没准备好就开不了会话)——
**本 topic 里「准备好」只在那一处定义，别处一律引用它。**

### 5.3 屏上的每一条，都指得回日志里的一条

**[会话日志是唯一的真相来源](../PF-012-agent-loop-and-run/design.md#52-会话日志是唯一的真相来源)，
交付面对它只有读这一件事可做。**

```text
   会话日志（只增不改）
        │
        │  按会话日志投影这套协议算出来
        ▼
   人读的那一份 ／ 机读的那一份      ← 同一份投影，两种交法
```

**三条推论，每一条都能被反例否定：**

| 推论 | 反例长什么样 |
|---|---|
| **屏上不会出现日志里没有的东西** | 人说了一句话，屏上立刻显示出来了，**但它其实还没被受理**——后来受理失败，那句话就凭空消失了。[PF-014 §6.1 先落账再谈别的](../PF-014-inbound-intake-and-queueing/design.md#61-先落账再谈别的) |
| **屏上的顺序就是日志的顺序** | 工具的结果先于发起它的那次调用显示出来 |
| **重新进来看到的和刚才一样** | 同一个会话，第二次进来少了几条——[投影重算必得同一个答案](../PF-015-session-lifecycle-and-ownership/design.md#58-存储要守住的两件事) |

> **「本地先显示，稍后再对齐」这条路本设计不走。**
> 它换来的是打字后立刻看到回显，**付出的是屏幕可能在撒谎**——
> 而这块交付面**同时是研发者判断系统对不对的那副眼睛**。
> **眼睛会自己补全，就没法用来验尸。**

### 5.4 人做的每一件事，走的都是已有的路

**人在一个会话上做的事分两类，没有第三类：**

#### 第一类：成为一条入站到达

**[PF-014 定死了受理面只有一个、去处只有三个](../PF-014-inbound-intake-and-queueing/design.md#51-一条入站到达从哪里来到哪里去)。
三样都是[入站到达](../PF-014-inbound-intake-and-queueing/design.md#入站到达)，
[落进会话日志是它们共同的动作、不是去处](../PF-014-inbound-intake-and-queueing/design.md#三个去处)，
差别在受理之后谁来看它：**

| 人在屏上做什么 | 去处 | 谁来看它 |
|---|---|---|
| 说一句话、发一条绑定提示词或 skill 的[斜杠命令](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-slash-command--斜杠命令--slash-command) | **进[待处理消息队列](../PF-012-agent-loop-and-run/design.md#待处理消息队列)** | loop |
| 在一张[卡片](../PF-008-human-in-the-loop/design.md#决策卡片)上作答，或表示「这个我不答」 | **落到那张卡片上** | 那张卡片背后等着的东西 |
| 停、强制停、[插队](../PF-014-inbound-intake-and-queueing/design.md#插队)、把一次工具执行切后台、中断一次工具执行 | **就地处置**（一条[控制指令](../PF-014-inbound-intake-and-queueing/design.md#控制指令)） | **没有人「看」它**，它改的是执行权或队列本身 |
| 发一条绑定系统业务流程的斜杠命令 | **就地处置**（[不是控制指令](../PF-014-inbound-intake-and-queueing/design.md#510-斜杠命令在受理时分两路走)） | **agent 看不到它**，那条流程自己去办；会话日志里留一条记它发生过的条目 |

#### 第二类：具名的那几条会话动作，它们不经入站到达

**这一类是具名的、可以数得过来的，不是一个开口：**

| 人在屏上做什么 | 它是什么 | 依据 |
|---|---|---|
| **给这个会话换一个模型** | **一条会话事实**，落进会话日志，**[下一次请求时生效](../PF-013-model-profiles-and-invocation/design.md#67-生效点收到那条事实之后下一次模型请求之前)** | [PF-014 §5.5 明说它不是控制指令](../PF-014-inbound-intake-and-queueing/design.md#看着像控制指令其实不是)、[§5.7 明说它不进队列](../PF-014-inbound-intake-and-queueing/design.md#同样要写什么不会)；[PF-013 §6.6 说它落进会话日志](../PF-013-model-profiles-and-invocation/design.md#66-切换先是一条要被记录的事实) |
| **[归档](../PF-015-session-lifecycle-and-ownership/design.md#会话归档) / 撤销归档** | 改的是**会话本身的状态**，不是送进会话的内容 | [PF-015 §6.2](../PF-015-session-lifecycle-and-ownership/design.md#62-归档有两条来路人手动或到期自动)、[§6.4](../PF-015-session-lifecycle-and-ownership/design.md#64-撤销归档只还给你状态) |

> **这几条是对会话本身做的操作，各归定义它的那个 topic 拥有**：
> 换模型归 [PF-013](../PF-013-model-profiles-and-invocation/design.md#66-切换先是一条要被记录的事实)，
> 归档与撤销归档归 [PF-015](../PF-015-session-lifecycle-and-ownership/design.md#62-归档有两条来路人手动或到期自动)；
> [PF-014 把换模型明确列为「一条会话事实」而不是入站到达](../PF-014-inbound-intake-and-queueing/design.md#看着像控制指令其实不是)，
> 就是在承认这一类的存在。**产品上它们的长相已经定完**：即时生效、不排队、留在会话日志里。
> **它们经哪条通路被受理、怎么落盘，是规格设计的事**（推理链在 [decisions §二](design.md)）；
> **产品这边只钉死一句**：不论走哪条路，[交付面自己都不写日志](#61-交付面不持有任何领域事实)。

**绑定系统业务流程的斜杠命令不在这一类里。**它是人从交付面用 `/` 触发一条系统业务流程的入口，
[走受理面、成为一条入站到达](../PF-014-inbound-intake-and-queueing/design.md#510-斜杠命令在受理时分两路走)，属于第一类；
能触发的流程本版只点名一族——[reload](../PF-002-assets-settings-and-permissions/design.md#会话认得哪些命令什么时候变)，每一条只重填这个会话对应的那一张注册表，不是一次完整的重新装配。这一类的几条具名动作则**不经入站到达**，所以它们**不是斜杠命令**——
换模型、归档在交付面上怎么拼、拼不拼成 `/` 开头，[归技术设计](#57-人要做的事分三族)；**拼成 `/` 开头的，那个名字是[系统保留名](../PF-002-assets-settings-and-permissions/design.md#slash-command)、在 `omne-official` 前缀下，它仍是这一类的具名动作**。

#### 两类之外的，根本不进任何会话

列会话、切当前租户身份、建组织、发邀请、看设置从哪一层来、改[观感偏好](#观感偏好)……
**它们是对[据点](#会话据点)或[治理中心](#治理中心)做的事，agent 不会看到它们。**

> **这条界线人要看得见**（[§5.7](#57-人要做的事分三族)）。
> 看不见的后果很具体：用户以为自己刚才那句话 agent 听见了，
> **而那其实是一条只在本机发生的动作**；或者反过来，
> 他以为改个设置不打扰 agent，**而那其实进了队列**。

### 5.5 两种呈现形式，同一份事实

**同一个场景，用[两种呈现形式](#呈现形式)各跑一遍，
[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)上留下的记录条目序列必须一样。**

**这是本交付面最要紧的一条性质，因为整条链的可验证性建立在它上面：**

```text
   同一个场景
      ├── 人在屏前走一遍  ──┐
      │                     ├──→  同一串记录条目
      └── 脚本驱动走一遍  ──┘
```

**它兑现三件事：**

- **研发者拿脚本验出来的，就是同事真的会遇到的。**两份不同源，验证就只是在验证脚本自己。
- **出了问题可以换一种形式再看一遍。**屏上看不明白的，用机读那一份逐条对。
- **不必为脚本另建一套入口**，因此也不会有「脚本能做而人做不了」的隐藏动作
  （[§6.5](#65-人能做的脚本能做脚本能做的人能做)）。

### 5.6 哪些东西在中心一侧，哪些在据点一侧

**分界不是「治理 vs 会话」那么粗，判据是一句话：**

> 治理事实与跨机器延续的身份配置在[中心](#治理中心)一侧，会话事实在本机[据点](#会话据点)一侧。工作区另按逻辑资源与实例区分：资源可以中心托管或位于外部提供者，实例在装载节点，能够独立于会话并跨租户共用。

| 这一样 | 在哪一侧 | 为什么 |
|---|---|---|
| 账号、组织、成员资格、角色、[邀约](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-offer--邀约--offer) | **中心** | 治理事实，[PF-001 的全部动作都改它们](../PF-001-identity-scope-and-agent-constraints/flows.md#一主要旅程) |
| **挂在组织层与租户层的[范围化对象](../PF-001-identity-scope-and-agent-constraints/design.md#范围化对象)**：设置、权限、资产，以及[挂在范围上的模型档案与凭据](../PF-013-model-profiles-and-invocation/design.md#56-凭据挂在范围上不挂在档案上) | **中心** | **推出来的，见下** |
| **各人的[个人 context](../../ubiquitous_language/terms/scope-and-resolution.md#ul-personal-context--个人-context--personal-context)**，[观感偏好](#观感偏好)在内 | **中心** | 它跟着账号走、换台机器还在（[裁定](design.md)）；据点上留一份副本供离线时用 |
| **各人自带的那把[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)** | **中心**（配在租户层） | [PF-013 定了它是范围的属性](../PF-013-model-profiles-and-invocation/design.md#56-凭据挂在范围上不挂在档案上)；据点调用时取所在范围那一把，[值本身永不呈现](#611-秘密不进任何一份呈现)（[§6.20](#620-每台机器上只有自己那一把凭据)） |
| 会话、[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)、等着的卡片、正在跑的运行 | **据点** | [裁定](design.md)：会话、运行、工具执行在用户本机 |
| 租户—工作区关系 | **中心** | 治理中心按有效关系列出可用工作区；本机候选缓存不能替代授权 |
| 工作区资源及本地实例 | **资源所在提供者与装载节点** | Omne Host 首版中心托管 Git；外部资源不自动上传。实例可跨租户共用、独立于会话；`.omne.local` 留在实例本地 |
| 会话层的值与本会话的工作区选择 | **据点** | 归会话，不将被选实例变成会话私有资源 |

**为什么组织层与租户层那些东西只能在中心一侧**——只有这一个答案自洽：

| 若把它们放在各自的机器上 | 当场坏在哪 |
|---|---|
| 甲在组织层配了一个值 | **乙看不到**，而[组织层的值本来就该对这个组织的每个成员成立](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性) |
| 甲把一份资产[分享](../PF-003-asset-transfer-and-sharing/design.md#分享)给乙 | **没有一个双方都够得着的地方**，分享这件事无从发生 |
| 甲的租户级配置 | 他换一台机器就全没了，**而[租户是归属与隔离的单位](../PF-001-identity-scope-and-agent-constraints/design.md#租户)，不是机器** |

> **注意这与「会话在本机」不冲突。**
> 两者分的是不同的东西：**这个人此刻能用什么**（按范围求值，对同组织的人一致）
> 与**这段协作发生了什么**（只属于他和这台机器）。

#### 哪几件事必须现读

**「现读」的范围是具名的三类，[逐条写在 §6.9](#69-需要现读成员资格的那几件事不拿副本放行)**：
建新会话 · 改变中心那一侧事实的治理动作 · 切换当前租户身份。
**其余一概不现读**——读类用副本显示（并标明是副本），会话里的一切不问中心。

| 这件事 | 怎么答 |
|---|---|
| 那具名的三类 | **现读中心**。[撤销向后生效](../PF-001-identity-scope-and-agent-constraints/design.md#66-撤销不等于强制停止)——**拿旧副本放行，撤销就不是向后生效了** |
| 我在哪些组织里、这一层配的是什么值 | **拿副本显示，并标明它是副本** |
| 我有哪些会话、说过什么、哪些卡片等着我 | **据点自己就答得出**，中心根本不知道有这些东西 |

**「问不到」不等于「无效」，也不等于「有效」。**
中心不可达时，那三类**明确失败并说清是因为问不到**（[§6.9](#69-需要现读成员资格的那几件事不拿副本放行)）；
**而已经开着的会话照常继续跟本机的 agent 干活**（[§6.17](#617-治理中心不可达已经开着的会话照常干活)）——
它用的是据点上那份副本，**副本可能已经旧了，这是被明知并接受的代价**。

### 5.7 人要做的事分三族

**按「这件事是对谁做的」分，恰好三族。这不是命令表，是边界表**——
**具体的命令拼写归技术设计**，但**哪件事属于哪一族是产品判断**：

| 族 | 对谁做的 | 包含哪些事 | 做完之后 |
|---|---|---|---|
| **会话族** | 对一个**会话** | 开一个新的 · 列出我的 · 进去接着聊 · 说话 · 答卡片 · 发控制指令 · 翻日志 · [归档 / 撤销归档](../PF-015-session-lifecycle-and-ownership/design.md#会话归档) · 看当前[运行模式](../PF-015-session-lifecycle-and-ownership/design.md#会话运行模式) · **[给这个会话换一个模型](../PF-013-model-profiles-and-invocation/design.md#66-切换先是一条要被记录的事实)** | **可能进入某个会话的日志**（[§5.4](#54-人做的每一件事走的都是已有的路)） |
| **治理族** | 对[中心那一侧](#56-哪些东西在中心一侧哪些在据点一侧)的事实 | 注册 · 登录 / 退出 / 列出与撤销自己的登录状态 / 主动更换凭据 · 建组织 · 发邀请 / 撤回 / 接受 · 隶属请求的发起与接受 · 看成员与角色 · 退出组织 / 移除成员 · 切换当前租户身份 · [资产的复制与分享](../PF-003-asset-transfer-and-sharing/design.md)的发起与确认 · 看与配组织层、租户层的设置、权限与[模型档案](../PF-013-model-profiles-and-invocation/design.md#模型档案) | **不进任何会话。**它改的是中心那一侧的事实，**因而对同组织的别人也成立** |
| **本机族** | 对这一处的**据点**与交付面自己 | 看这台机器连的是哪个中心、装的是什么版本 · 看一项设置此刻的值[最终来自哪一层](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性) · 改[观感偏好](#观感偏好) · 体检（能不能连上中心、这台机器准备好了没有） | **不进任何会话**，也**不改任何对别人成立的事实** |

> **[斜杠命令](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-slash-command--斜杠命令--slash-command)属于会话族，不属于本机族。**
> 它是[一条进到这个会话里的入站到达](../PF-014-inbound-intake-and-queueing/design.md#510-斜杠命令在受理时分两路走)。
> **绑定提示词或 skill 的，长得像一条命令，但它是内容**——agent 看到的是展开后的那条消息。
> **绑定系统业务流程的，仍属会话族，但它不是内容**——它触发一条系统流程，会话日志里留一条记它发生过的条目，agent 看不到。
> 交付面自己的动作则一条都到不了 agent 眼前。

**斜杠命令在交付面上怎么敲，产品只定这几条，记法归技术设计：**

| | |
|---|---|
| **只认输入开头的一条** | 一条输入至多一条命令；中间出现的 `/xxx` 是正文 |
| **两种呈现形式一样识别** | 脚本驱动交付面，[做得了人能做的一切](#65-人能做的脚本能做脚本能做的人能做)，[留下的记录条目也必须一样](#55-两种呈现形式同一份事实)——所以机读那一侧同样认得出斜杠命令 |
| **敲了一个这个会话没有的命令名** | **当场明说「没有这个命令」，不发送**——人当场改，脚本拿到一个明确的失败；不会被当成一句话送给 agent，也不会进队列。「没有」按这个会话的[会话斜杠命令集](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-session-slash-command-set--会话斜杠命令集--session-slash-command-set)算：**他没有权限用的，与根本不存在的，回答一模一样**，交付面上**没有「你不能用」这一种提示**（[PF-002](../PF-002-assets-settings-and-permissions/design.md#会话认得哪些命令什么时候变)） |
| **参数与声明对不上** | 命令声明了参数的，交付面**像命令行程序那样按声明解析**；**解析不通过，当场明说哪里不对，不发送**——与敲了一个没有的名字同一种后果。三种绑定目标一条规则 |
| **想发一句以 `/` 开头的普通话** | **必须有一种办法原样发出去**，不被认成命令。具体怎么记，归技术设计 |
| **命令声明了参数** | 按声明提示人该给什么；[没声明的，命令名之后的整段文字作一个自由参数](../PF-002-assets-settings-and-permissions/design.md#slash-command) |
| **名字撞了** | 交付面自己的动作名与绑定系统业务流程的命令名是[系统保留名](../PF-002-assets-settings-and-permissions/design.md#slash-command)，**一律在 `omne-official` 前缀下**；别的斜杠命令不得使用这个前缀——**人敲下一个名字，只可能有一种解释** |
| **会话里的命令变了** | 组织或租户增删、禁用了提示词或 skill 型的命令，**开着的会话照旧**；人发一条 **reload** 才换成新的一批（[PF-002](../PF-002-assets-settings-and-permissions/design.md#会话认得哪些命令什么时候变)）。reload 是一条绑定系统业务流程的命令，照本节的规矩敲 |

**三族之外没有第四族**：找不到「对谁做的」的动作，本交付面就不提供它。

## 六、产品规则

### 6.1 交付面不持有任何领域事实

**屏上的每一条，都指得回[会话日志](../PF-012-agent-loop-and-run/design.md#会话日志)里的一条；
它提交的每一件事，都走[§5.4 那两类已有的路](#54-人做的每一件事走的都是已有的路)。**

**交付面自己从不写日志，它只把东西交出去。**
这一句对两类都成立：入站到达交给[受理](../PF-014-inbound-intake-and-queueing/design.md#入站到达)，
[那几条具名的会话事实](#第二类具名的那几条会话动作它们不经入站到达)交给它们各自的拥有者——
**交付面在两条路上都只是发起方，不是落账方。**

它也不持有第二份会话列表、第二份卡片池、第二份权限判断——
**凡是它显示的，都是别处算出来的。**

> **这一条挡的是一种很自然的演化**：先在界面里缓存一点状态让它快一些，
> 再加一点本地判断让它聪明一些，**然后某一天界面上的状态与日志对不上了**。
> 而[会话日志是唯一的真相来源](../PF-012-agent-loop-and-run/design.md#52-会话日志是唯一的真相来源)
> 这条一旦在交付面上破掉，**破的位置恰好是人唯一看得见的地方**。

### 6.2 没准备好就开不了会话

**一个账号在这一处准备好之前，交付面不让他开会话，也不让他进任何会话。**

> **「准备好」在本 topic 里只在这里定义，恰有两样：**
>
> 1. **这台机器知道连哪个[治理中心](#治理中心)**；
> 2. **有一个有效的[登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)。**

**差哪一样，就明说差哪一样，并指出下一步做什么。**
**[会话据点](#会话据点)不在这张清单上**——第 2 样成立的那一刻它就立起来了，
**它是登录成功的连带结果，不是人要另外做的第三件事**。

**模型调不调得动也不在这张清单上。**
配没配好一把能用的[凭据](../PF-013-model-profiles-and-invocation/design.md#56-凭据挂在范围上不挂在档案上)，
**不决定他开不开得了会话**——它决定的是**第一次真要调模型时那次运行成不成**
（推理链在 [decisions](design.md)）。
**但交付面要提前把这件事说出来**：准备好了、可以开会话了，**而模型这一层还没配**。

> **为什么要拦而不是「先用着，回头再补」**：
> [一个会话在创建那一刻捕获租户身份](../PF-015-session-lifecycle-and-ownership/design.md#612-会话持有创建那一刻的租户身份)，
> 此后归属、成本、求值全照它算，**而且改不回来**。
> **身份没齐就建起来的会话，没有任何办法事后纠正它归谁。**
>
> **而凭据不一样**：它配错了、过期了、还没配，**代价只是这一次调用失败，下次配好就好了**。
> **把可恢复的东西写进不可恢复那道门的前置条件，挡掉的是人，救不回任何东西。**

#### 治理操作遇到登录失效

登录是否有效、有限寿命与主动更换规则只由 [PF-001](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态) 定义，
客户端不能根据「窗口还开着」「网络又连上了」或本地记录把失效的登录当成有效。
体检不维持登录，客户端不保存账号凭据替人自动续期。

| 中心给出的结果 | CLI/TUI 与脚本的表现 |
|---|---|
| 登录已失效，含到期、撤销与更换凭据后的失效 | 明说需要重新登录，旧登录不能继续发起治理操作；机读结果同样可辨。不能把普通的业务失败显示成登录失效 |
| 中心答不出，或连不上 | 明说暂时不可用；不把它显示成「你没有权限」或要求无效的重新登录来修复故障 |
| 主动更换凭据成立 | 动手前说明全部旧登录会失效；成功后引导用新凭据重新登录，不暗中沿用当前登录 |
| 更换凭据回执丢失 | 明说结果未知，按 PF-001 的流程核实；不暗中重试更换或声称旧凭据一定仍可用 |

重新登录是一次新的登录，按 PF-001 从个人组织开始选择当前租户身份；
此前未完成的治理操作不能因重新登录而自动发出，人须核实账号、组织与操作结果后再继续。
**登录失效不等于停止已有 Agent 运行**，这条边界归 PF-001 §6.6；首批不借此实现 Agent 会话控制。

### 6.3 当前身份必须一直在场

**人在屏前的任何时候，都看得见自己此刻是哪个账号、
[当前租户身份](../PF-001-identity-scope-and-agent-constraints/design.md#当前租户身份)是哪一个。
机读那一份里，每一条事实都说得出它是以谁的身份产生的。**

**并且：一次使用自始至终只以一个登录状态行事。**
换账号**不是屏上的一个切换动作，是重新进来一次**；
而[切换当前租户身份](../PF-001-identity-scope-and-agent-constraints/design.md#当前租户身份)**是**——
那是同一个账号内的一项选择，[只影响此后新建的东西](../PF-001-identity-scope-and-agent-constraints/flows.md#18-切换当前组织)。

> **这条不是为了好看。**归属在创建那一刻钉死且不可回退，
> **而「忘了自己站在哪」是这类工具上最常见、代价最高的一种错**：
> 用错身份建的会话，**成本算在另一个租户头上，历史挂在另一个组织名下**，
> 发现的时候已经改不动了。

### 6.4 一台机器上，账号之间互不可见；但宿主机那一层不隔离

**同一台机器上的两个账号是[两个据点](#52-一个账号在一处怎么被装起来)**：
甲的交付面列不出乙的会话、看不见乙的卡片、进不去乙的任何会话。
**同一个账号的不同租户身份之间，照 [PF-001 的隔离](../PF-001-identity-scope-and-agent-constraints/design.md#64-隔离)办**，
[卡片也分属各自的池子](../PF-008-human-in-the-loop/design.md#67-租户隔离在池子上成立)。

**但有一条必须一起说，否则这条规则会被读成一个它给不出的承诺：**

> **[宿主机不提供租户隔离](../PF-005-execution-environments-and-sandboxes/design.md#62-宿主机不提供租户隔离因此必须被显式允许)。**
> 一旦某个工具的作用**落到了宿主机上**，那就是这台机器本身——
> **甲的 agent 在上面写下的东西，乙的 agent 看得见。**

**两条合起来才是真话**：**会话与治理这一层互不可见；落到机器上的那一层，PF-005 早就写明了不隔离，
而它给的答案是「必须被显式允许」，不是「装作隔离了」。**

### 6.5 人能做的脚本能做，脚本能做的人能做

**同一件事，两种[呈现形式](#呈现形式)下都做得了；
做不了的那些必须被具名列出，并说明为什么。**

**当前唯一被具名排除的是「当场打字」那一类交互本身**——
脚本不敲键盘，它把要说的话一次给全。
**但它要做的那件事一件不少**：说话、答卡片、发控制指令、做治理动作，都在。

> **反过来的方向更要守**：**不许有「脚本才能做」的动作。**
> 那种动作会变成一条没人看得见的后门——
> **它不出现在任何一块屏上，因此也不会有任何人复核它。**

### 6.6 机读那一份只承载事实

**机读的那一份里只有事实；过程、提示、诊断、进度一概不混在里面。**

**判据是一句可核对的话**：把机读那一份整个喂给一个解析器，**不该出现读不懂的行**。

> **这一条的价值不在整洁，在于它是[上一条](#65-人能做的脚本能做脚本能做的人能做)的兑现方式。**
> 脚本要能从输出里判断「这件事成了没有、成了什么样」，
> **混进一行人话，判断就得靠猜**；而猜出来的验证结论**比没有验证更糟**。

### 6.7 交付面永不替人作答

**没有超时、没有默认答案、没有「不回就当同意」，
两种[呈现形式](#呈现形式)下都没有。**

这条直接继承
[PF-008 §6.1](../PF-008-human-in-the-loop/design.md#61-永远等着系统不替人作答)，
**在这里只多说一句它在无人看管时的样子**：

> **脚本跑着跑着遇到一张没人答的卡片，它停在「等人」，而不是替人选一个然后继续。**
> **「等人」是一种正常的收场，不是失败**——
> 它与「这次运行失败了」必须分得开，否则自动化跑出来的结论全不可信。

**[「这个我不答」是合法答复](../PF-008-human-in-the-loop/design.md#65-不回答是合法答复)，
它由人给出，不由交付面代劳。**

### 6.8 关掉屏不会让任何东西丢掉

**关掉屏、断开连接、机器重启——
会话、日志、等着的卡片、[已经表达过的授权](../PF-015-session-lifecycle-and-ownership/design.md#54-会话内的授权与生命周期的交界)
一样都不少。**

> **这条规则说的是「不丢」，不是「什么都没发生」。**
> 关屏之后日志上**可能多出几条**（在途的活儿有它的收场，见下）；
> **多出来的是记录，不是丢失**——[日志本来就只增不改](../PF-012-agent-loop-and-run/design.md#会话日志)。

**理由是它们本来就不在屏上**：屏上什么都不持有（[§6.1](#61-交付面不持有任何领域事实)），
[会话睡醒还是原来那个](../PF-015-session-lifecycle-and-ownership/design.md#611-会话睡醒之后还是原来那个)。
**重新进来看到的，与日志一致。**

**这一条禁掉的，是三件可以当场判定的事：**

> **关屏不是[归档](../PF-015-session-lifecycle-and-ownership/design.md#会话归档)。**因此关屏**不得**：
> **① 让这个会话落入归档状态；② 级联归档它的子会话；③ 让等着的卡片从[决策池](../PF-008-human-in-the-loop/design.md#决策池)里消失。**

**在途的那些活儿是另一回事，本 topic 不另立规矩。**
**关屏不是停机**——[没人开着屏，这一处照常发生事](#616-没人开着屏这一处照常发生事)，在途的运行接着跑，跑完的收场照常落账。
**断线与机器重启才可能是一次[停机](../PF-012-agent-loop-and-run/design.md#停机不是机器断电是失去连续性)**：
[PF-012 已经把「失去连续性」定成停机，并逐样写明了停机之后各算什么](../PF-012-agent-loop-and-run/design.md#三个运行时停机之后各算什么)——
**agent runtime 重算、一次工具执行不重来且落失败**。
**确实造成了一次停机的，就照那份口径落账，不套用归档那套「中断不是失败」。**

> **这两者必须分开说，否则会写出一句做不到的承诺。**
> 「重启机器也不中断任何在途的活儿」听着很好，**但机器重启就是一次停机**——
> 那时在途的工具执行**必然**按 PF-012 落失败。
> **所以产品能禁的只有上面那三件**（它们与停机无关，是交付面自己的动作），
> **在途活儿的收场跟着 PF-012 走。**

**有一条要一直守住**：不许留下一个**看起来还在跑、实际没人在跑**的运行——
[该不该起一副 runtime 只看日志](../PF-012-agent-loop-and-run/design.md#agent-runtime)，
**而日志得按 PF-012 的口径如实落账。**

### 6.9 需要现读成员资格的那几件事，不拿副本放行

**「现读」管的范围是具名的，不是「一切判断」。恰有三类：**

| 必须现读[治理中心](#治理中心)的 | 为什么是它 |
|---|---|
| **建一个新会话** | 它[在那一刻捕获租户身份](../PF-015-session-lifecycle-and-ownership/design.md#612-会话持有创建那一刻的租户身份)且改不回来 |
| **任何改变中心那一侧事实的治理动作**（建组织、发／撤回／接受邀约、改角色、移除成员、隶属请求、资产的复制与分享） | 它改的就是中心上的事实，**本来就得到那儿去做** |
| **把[当前租户身份](../PF-001-identity-scope-and-agent-constraints/design.md#当前租户身份)切到某个组织** | [PF-001 已定：在目标组织没有成员资格就切不过去](../PF-001-identity-scope-and-agent-constraints/flows.md#二分支与异常) |

**这三类在中心不可达时明确失败，并说清失败是因为问不到**——
**不静默放行，也不静默降级成「用上次看到的」。**

**其余一概不现读**，尤其这两样：

| 不现读的 | 怎么办 |
|---|---|
| **读类**：列我在哪些组织里、看成员与角色、看一项设置的值来自哪一层 | **用据点上那份副本照常显示**，**但必须让人看出这是副本**——「这是上次读到的，此刻连不上中心」 |
| **会话里的一切**：说话、答卡片、发控制指令，以及工具与执行环境的[权限求值](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性) | **不问中心**（[§6.17](#617-治理中心不可达已经开着的会话照常干活)）。权限求值读的是[各层配的值](#56-哪些东西在中心一侧哪些在据点一侧)，那是另一回事——**它离线时用的也是副本，而那份副本可能已经旧了** |

> **为什么把范围写死**：不写死，「不拿副本放行」会被读成「离线时一切授权判定都不许通过」——
> 那与[「已经开着的会话照常干活」](#617-治理中心不可达已经开着的会话照常干活)正面冲突。
> **反过来若不设范围，[撤销向后生效](../PF-001-identity-scope-and-agent-constraints/design.md#66-撤销不等于强制停止)
> 就被偷偷改成「在这台机器离线多久之后才生效」**——而那个时长没有任何人定义过，也没有任何人看得见。
> **具名三类，是这两头之间唯一站得住的位置**：中心说了算的那几件事一律现读，其余的不因为断了网就停。

### 6.10 成员资格无效期间，本机那些会话不呈现，也不删

**在能读到成员资格的前提下**，一个人被移出组织之后，
**他机器上那些属于该租户的会话不呈现、进不去、发起不了任何新的动作；
但它们不被清除**——成员资格恢复之后原样可用。

**「在能读到成员资格的前提下」这个前提不能省。**
[列会话与进入既有会话不在现读那三类里](#69-需要现读成员资格的那几件事不拿副本放行)——
要求它们现读，等于「网一断，连自己昨天写的东西都看不了」。
**所以离线时按据点上那份副本呈现，而副本可能已经旧了**：

| 离线期间发生的 | 这台机器上看到的 |
|---|---|
| 他在别处被移出了组织 | **那些会话照旧列得出、进得去**，因为这台机器还不知道 |
| 他在里面想接着干活 | **干得了**（[§6.17](#617-治理中心不可达已经开着的会话照常干活)）——这台机器还不知道他已经被移出 |
| 这台机器再连上中心 | **按新读到的成员资格重新算**，该收起来的收起来。**收起来不是归档**：那些会话不再呈现、不再受理新的东西；正在跑的那一次运行不被强制停下（[撤销不等于强制停止](../PF-001-identity-scope-and-agent-constraints/design.md#66-撤销不等于强制停止)），跑完即止，日志照常落账 |

> **这不是一个缺口被遮起来，是把它摆到该摆的地方。**
> 一台离线的机器**不可能知道**别处刚发生的事；产品能定的是
> **它再连上时必须照新的算**，以及**它离线时允许做到哪一步**——后者定在 [§6.17](#617-治理中心不可达已经开着的会话照常干活)：
> 除了[那三类](#69-需要现读成员资格的那几件事不拿副本放行)，都允许。

**两条依据，方向一致：**

| 依据 | 它说了什么 |
|---|---|
| [PF-001：退出之后再加入，回来的是同一个租户](../PF-001-identity-scope-and-agent-constraints/design.md#退出之后再加入回来的是同一个租户) | 租户级的私有部分**不可达但不销毁**，重新加入原样可用。本机这一份是同一个口径 |
| [PF-015 §6.1：会话不会消失](../PF-015-session-lifecycle-and-ownership/design.md#61-会话不会消失) | **系统不提供删除会话的能力，任何角色都不提供。**「本机自动清理」就是删除会话，**它与这条正面冲突** |

> **这条承诺的边界要说实话。**产品能承诺的是**这块交付面不再呈现、不再放行**；
> **它不承诺那台机器的磁盘上不再有这些字节**——那是一台私人电脑。
> **合规意义上的数据清除是另一件事**：它有自己的触发条件、审批与留痕，
> [PF-015 已经把它划出去了](../PF-015-session-lifecycle-and-ownership/design.md#为什么没有删除)，
> **至今没有 topic 认领**（[§9](#九未决项)）。

### 6.11 秘密不进任何一份呈现

**[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)、
登录用的凭据、登录状态本身这类东西，不出现在屏上、不出现在机读那一份里、
不出现在任何调试输出里。**

**能被呈现的只有「有没有、是哪个范围的、什么时候配的」，不含值本身。**

> **这块交付面是本系统唯一一处人与秘密会面的地方**——
> 他在这里配上它、在这里看到用它跑出来的结果。
> **一旦它被打印到某一行上，那一行就会留在屏幕的回滚记录里、进入日志文件、进入他粘给同事的那段输出。**

### 6.12 观感偏好不改变任何领域行为

**改[观感偏好](#观感偏好)、开调试输出、换一种呈现形式——
同一个场景跑出来的记录条目序列必须一模一样。**

**判据是可观察的**：开着调试跑一遍、关着再跑一遍，**日志逐条对得上。**

> **这一条是这块交付面能被当作观测工具用的前提。**
> 观察行为会改变被观察的行为，**那就不是观察，是干预**——
> 而研发者恰恰是在用它判断系统本身对不对。

### 6.13 回不去的后果，人动手之前就得知道

**回不去的后果，人必须在动手之前就知道。怎么让他知道分两档，按「它连累了谁」分：**

#### 第一档：连累别的对象的，逐条说清再让人确认

| 动作 | 要说清什么 |
|---|---|
| **[归档一个会话](../PF-015-session-lifecycle-and-ownership/design.md#63-归档先停活儿再落状态)** | 子会话级联被归档、未完成的工具执行被中断、正在进行的模型响应被中断——**三件都不可逆，撤销归档也不回来** |
| **[撤销归档](../PF-015-session-lifecycle-and-ownership/design.md#64-撤销归档只还给你状态)** | 回来的**只有状态**：被中断的活儿不续，被级联归档的子会话不跟着回来 |

**脚本那一侧同理**：**不许用「反正是脚本」把确认省掉**，
它得以别的方式明确表示「我知道会连带发生什么」。

#### 第二档：只作用于这一次运行的，把差别摆在按下去之前

**[取消与强制停止让这次运行落终态，而终态不可逆](../PF-012-agent-loop-and-run/design.md#66-终态不可逆且只有一个出口)**——
它同样回不去，**但它不连累别的对象**。

| 这里要的不是确认，是**分得清** | 为什么 |
|---|---|
| **停**与**[插队](../PF-014-inbound-intake-and-queueing/design.md#插队)**的差别，必须在按下去之前就看得出来 | [PF-014 已经把这条写到没有解释余地](../PF-014-inbound-intake-and-queueing/design.md#插队与取消差别必须写死)：**一个让跑了两小时的任务落终态，一个不终止运行**，而它们在屏上可能只差一个键 |
| **[强制停止](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-forced-stop--强制停止--forced-stop)**与「停」的差别 | 前者**连执行资格一起撤**，且**外部效果收不回来** |

> **为什么这一档不加一道确认**：用户按「停」的本意**就是现在就停**。
> 在它前面插一句「你确定吗」，**等于把这条指令的语义打了折**——
> 而这条路[必须始终开着，否则用户就被自己的 agent 锁死了](../PF-008-human-in-the-loop/design.md#62-等待期间照常收排队等着解除时一起看到)。
> **所以这一档花力气的地方是「让他按之前就分得清」，不是「按完再问一遍」。**

### 6.14 没有带外通知，所以进来就要看得见等着的事

**本版没有邮件、没有短信、没有任何带外通道。
因此：人一进来，就看得见两类等着他的东西——**

| 等着的 | 出处 |
|---|---|
| **等他答的[卡片](../PF-008-human-in-the-loop/design.md#决策卡片)** | 属于他当前租户身份的那些，[分属各自的池子](../PF-008-human-in-the-loop/design.md#67-租户隔离在池子上成立) |
| **等他点头的[邀约](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-offer--邀约--offer)** | **当前四样**：[加入组织的邀请与隶属请求](../PF-001-identity-scope-and-agent-constraints/flows.md#15-邀请与加入)、[分享邀请与待确认的复制通知](../PF-003-asset-transfer-and-sharing/design.md#614-待确认的复制通知与分享邀请会过期)。**[四样都会过期](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-offer--邀约--offer)，所以「什么时候到期」要一起看得见** |

> **这条不是「做一个收件箱」那么简单，它是这条形态下的必需品。**
> [PF-008 要求「人得知道有东西在等他」，并把通知怎么送达判给技术设计](../PF-008-human-in-the-loop/design.md#七取舍)、
> [PF-014 要求「排着的东西必须看得见」](../PF-014-inbound-intake-and-queueing/design.md#64-排着的东西必须看得见)——
> **没有带外通道时，这两条唯一的兑现方式就是「他自己来看的时候一定看得到」。**
> **而没人来看的那段时间里，等着的东西照常攒着**（[§6.16](#616-没人开着屏这一处照常发生事)）——
> 它不会因为没人看而消失，也不会因为没人看而被替人处理掉。

日程与主动通知来源的扩展见 [PF-021 通知交付](../PF-021-schedule-and-calendar/design.md#65-通知发送与租户送达)；
该 topic 拥有通知在目标租户可持久取回的送达判据，以及日程管理和[单次 Job 取消](../PF-021-schedule-and-calendar/design.md#614-取消单次-job)的产品动作。
这些入口沿本 topic 的人读／机读等价与租户隔离，不把通知等同于卡片或邀约，也不增加带外渠道。

### 6.15 环境不支持的时候明说，不静默降级

**人读那一份需要一块真正的屏。拿不到的时候（被重定向、跑在没有屏的环境里），
交付面明确说不行，并指出机读那一份怎么用——不悄悄换一种方式接着跑。**

> **静默降级的代价是延迟发现**：脚本以为自己在驱动人读那一份，
> **实际上拿到的是另一套输出**，而它可能一直「成功」到某个断言终于失败为止。

### 6.16 没人开着屏，这一处照常发生事

**只要这台机器开着，[会话据点](#会话据点)就在运转：没人开着屏的时候，
定时到点的[入站到达](../PF-014-inbound-intake-and-queueing/design.md#入站到达)照常被受理、
队列非空的会话照常起一次[运行](../PF-012-agent-loop-and-run/design.md#run)、
等人的[卡片](../PF-008-human-in-the-loop/design.md#决策卡片)照常攒着、
[到期的会话照常被收](../PF-015-session-lifecycle-and-ownership/design.md#62-归档有两条来路人手动或到期自动)。**
**开着屏只是有人在看**（[裁定](design.md)）。

**它让四条已接受的规则在本形态下成立，而不是失效：**

| 规则 | 没有这条时会怎样 |
|---|---|
| [PF-014 §6.8「队列非空且没有活跃运行，这个状态不许长期存在」](../PF-014-inbound-intake-and-queueing/design.md#68-停机不会让一条入站到达永远悬着) | 没人开屏的那几个小时里，它就是长期存在的 |
| [PF-008「人得知道有东西在等他」](../PF-008-human-in-the-loop/design.md#七取舍) | 只能推迟到他下次进来 |
| [PF-015 到期自动归档](../PF-015-session-lifecycle-and-ownership/design.md#62-归档有两条来路人手动或到期自动) | 退化成「下次有人打开才收」 |
| [PF-012 停机口径](../PF-012-agent-loop-and-run/design.md#三个运行时停机之后各算什么) | 关一次屏就是一次停机，在途的工具执行每次都落失败 |

**代价写在明面上**：每台同事的机器上**始终有东西在运转**，
它占多少资源、怎么起怎么停、机器休眠时算什么，**归技术设计**；
**机器关机的那段时间不在这条承诺里**——关机就是[停机](../PF-012-agent-loop-and-run/design.md#停机不是机器断电是失去连续性)，
到期归档的时钟在关机期间怎么算[还未定](#九未决项)。

> **为什么不选「开着屏才有」**：那样最安静、概念也最简单，
> **但上面四条里有两条是已接受规则的直接失效**，而失效的位置恰好是没人看着的时候——
> 人回来只会发现「昨天定的那件事没跑」，而无从知道为什么。

### 6.17 治理中心不可达，已经开着的会话照常干活

**[治理中心](#治理中心)问不到的时候，已经开着的会话里的一切照常：
说话、跑运行、调工具、答卡片、发控制指令。不设离线时长的上限**（[裁定](design.md)）。
**它用的是据点上那份副本**——[组织层与租户层配的那些值](#56-哪些东西在中心一侧哪些在据点一侧)、
[个人 context](#观感偏好)、[自己那把凭据](#620-每台机器上只有自己那一把凭据)——
**副本可能已经旧了**，而这台机器无从知道。

**两条代价，都被明知并接受：**

| 代价 | 具体是什么 |
|---|---|
| **撤销的实际生效点被拖长** | 一个人在别处被移出组织，他离线的这台机器**直到再连上中心才知道**。[撤销向后生效](../PF-001-identity-scope-and-agent-constraints/design.md#66-撤销不等于强制停止)在中心上照常成立，**在这台机器上生效的时刻是它再连上的那一刻** |
| **他离线期间仍能在那个租户下干活** | 会话在他自己的机器上，工具也在；**产品选择不让网线决定他能不能干手上的活** |

**边界照旧**：[必须现读的那三类](#69-需要现读成员资格的那几件事不拿副本放行)在离线时明确失败——
**开不了新会话、做不了治理动作、切不了租户身份**；
再连上之后[按新读到的成员资格重新算](#610-成员资格无效期间本机那些会话不呈现也不删)。

> **为什么不选「断了就停」**：那样撤销立刻咬合，**但网线一断就干不了活，而会话与工具明明都在本机**。
> 治理中心是治理事实的权威，[不是会话的权威](#治理中心)；**让它的可达性决定一个本机会话能不能继续，等于把它做成了每一句话的必经之路**。

### 6.18 进来没指定会话就是新的；当前目录可作为本租户工作区地址的默认候选

**人进来时没有指定会话，交付面开一个新的，不接上次那个**（[裁定](design.md)）。
**要接着上次的，他得指名**——进来时最近的几个会话要摆在他看得见的地方，接上去是一次显式选择。
**不论哪种，有一条不变：[他在说第一句话之前必须知道这句话会落进哪个会话](#62-没准备好就开不了会话)。**

**开新会话时，交付面可以按运行命令时的当前目录寻找本租户工作区地址或实例；
找到后只把对应工作区作为[创建时显式指定的那一项](../PF-015-session-lifecycle-and-ownership/design.md#613-工作区在创建时显式指定不指定就是空)的默认候选。用户仍可更换或不选择。**

**这条与[「系统不替会话猜一份工作区」](../PF-015-session-lifecycle-and-ownership/design.md#613-工作区在创建时显式指定不指定就是空)相容，界线有三道：**

| 界线 | 具体是什么 |
|---|---|
| **候选与关系分开** | 本机可用地址或实例清单用于提出候选，治理中心的有效租户—工作区关系决定工作区身份与资格。目录尚未登记时可显式选“作为工作区使用”，完成登记后附着；普通启动仍按普通目录使用 |
| **按当前会话租户授权** | 创建者与合法参与者均可使用；不能借其他租户的关系取得资格，也不能仅因实例正被其他租户使用就排除它 |
| **候选须显式提交** | 在会话创建前显示所选工作区及实例，用户可更换或不选择；未确认或未提交选择，不因当前目录或命名空间文件存在自动附着 |

**当前目录若落在某个本地工作区地址的子目录里，可以作为该地址的默认候选；嵌套时取最近的一层**
；这只是已知实例入口的候选定位，不递归发现资产，也不自动登记嵌套工作区。

> **为什么默认是新的**：接着上次那个打开就能继续，
> **但人很容易把一件新事说进一个旧会话**，而[会话类型对不上只提醒、不拦](../PF-015-session-lifecycle-and-ownership/design.md#66-跑题只提醒不阻拦)。
> 总是新的，代价是**会话数量涨得快**，而[会话不能删](../PF-015-session-lifecycle-and-ownership/design.md#61-会话不会消失)，只能等[自动归档](../PF-015-session-lifecycle-and-ownership/design.md#62-归档有两条来路人手动或到期自动)慢慢收——**这个代价产品付得起，上一个付不起**。

#### 工作区操作的呈现

交付面支持两条已有产品路径：选择可访问工作区并指定本地路径装载，或选择已有目录显式登记并附着。后者向中心同步关系，不默认上传资源。加载或登记失败应明确呈现，不静默退成普通目录并显示附着成功。

同一会话可以呈现同一工作区的多个 worktree 及 subagent 分工；关闭会话不删除实例。解除关系是治理动作，本地目录保留且后续按普通目录使用；销毁工作区与删除关系的资格、级联结果沿 PF-020，不因本机目录仍在而显示关系有效。

人的上传、下载、查看和 Git 操作应标明目标实例或 remote，以及实际完成或失败；不显示为全部地址和实例已同步，不另加成果发布状态。资源同步允许异步，不强迫运行中的 agent 即时感知。文件大小、容量限制按所选托管与部署配置呈现，失败保留本地原件。

通过 PF-002 的显式资产 reload 命令呈现工作区资产更新：先校验，失败显示错误且原内存数据不变，通过后才按 PF-004 生命周期更新。具体命令拼法与界面布局由后续规格细化。

### 6.19 这里看到的池子，是这一处的

**一个人在这台机器上看到的[决策池](../PF-008-human-in-the-loop/design.md#决策池)，
是[这一处据点](#会话据点)内、他[当前租户身份](../PF-001-identity-scope-and-agent-constraints/design.md#当前租户身份)下所有等着他的卡片。
他在另一台机器上开的会话攒下的卡片，在那一台上。**
**交付面要让他知道这一点**——池子标明它是这一处的。

**这不改 PF-008 的定义。**[PF-008 说的「一个租户范围内所有等着人输入的卡片」](../PF-008-human-in-the-loop/design.md#决策池)，
「所有」本来就相对于会话所在之处——**等的永远是某个会话**，而会话在据点上。
[PF-008 §6.6「答了它会解除什么」](../PF-008-human-in-the-loop/design.md#66-卡片要让人看出答了它会解除什么)在每一处内照常成立。

> **为什么不让中心把几台机器的池子合成一份**：那要中心知道每台机器上有哪些卡片，
> **而[中心不知道任何会话](#治理中心)、[交付面不持有任何领域事实](#61-交付面不持有任何领域事实)**——
> 两条都是本 topic 的根。合成一份的代价是一整套跨机器的同步，**换来的只是「一个人同时用两台机器」这件目前没有人要求的事**。

### 6.20 每台机器上只有自己那一把凭据

**本形态下，一个人的机器上只有他自己带的那把[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)**（[裁定](design.md)）。
它照 [PF-013 §5.6](../PF-013-model-profiles-and-invocation/design.md#56-凭据挂在范围上不挂在档案上) 配在**租户层**——
「范围可以自带凭据」那条**就是本形态下每个人配凭据的路**；中心不签发、不轮换，产品不为此多做任何事。

| 这一样 | 在哪 |
|---|---|
| 凭据的值 | 配在[中心](#治理中心)一侧的租户层；据点调用时取所在范围那一把，[离线时用手上那份副本](#617-治理中心不可达已经开着的会话照常干活) |
| 换一把、撤掉 | 改租户层那一项的值（[轮换就是改这一项的值](../PF-013-model-profiles-and-invocation/design.md#56-凭据挂在范围上不挂在档案上)）；这台机器再连上中心时取到新值 |
| 值本身 | [永不呈现](#611-秘密不进任何一份呈现) |

**组织那一层不持有模型凭据**（[PF-013](../PF-013-model-profiles-and-invocation/design.md#56-凭据挂在范围上不挂在档案上)），所以没有「组织那一把」可以下发；
组织托管凭据、下发到据点，[本版不做](#二目标与非目标)——发出去的那一份，人离职时收不回。
**后果**：一个人没配自己那一把，[开得了会话，第一次真要调模型时那次运行失败并指得出原因](#62-没准备好就开不了会话)——
**组织那一层给不了他一把兜底的**。

### 6.21 被转换过的消息，呈现上说得出模型读的是哪一份

**一条消息里的块被[转换件](../PF-013-model-profiles-and-invocation/design.md#转换件)转过，而模型这一次读的是转换出来的那一份（它收不下原件），
那条消息呈现时就标明：「本次模型读到的是转换后的文本」。**人读、机读[两种呈现形式](#55-两种呈现形式同一份事实)都带这一标注。

**为什么非有不可**：[转换不承诺无损](../PF-013-model-profiles-and-invocation/design.md#511-有-transcript-的块不再把任何模型挡在外面)，一张图转成的那段文字一定比原图少。
人发出去的、屏上引用着的是原件，**不说出来，他会以为模型也看过原件**，然后照着一个它根本没看见的细节去问。

**它指得回日志里的东西**（[§5.3](#53-屏上的每一条都指得回日志里的一条)）：块上挂着的派生表示与 transcript 是落盘时写下的，
这一次用的是哪个模型也在日志里——**标注是这两样算出来的，不是屏自己的判断**。
模型收得下原件、读的就是原件时，不标。

## 七、取舍

| 面临的选择 | 选了 | 为什么 |
|---|---|---|
| 会话放在**中心**（换台机器也看得见） vs 放在**用户自己的机器上** | **用户自己的机器**（[裁定](design.md)） | 代价是诚实的：**换台机器看不到那些会话**，[一个租户的池子也因此按据点各一份](#619-这里看到的池子是这一处的)。换来的是工具执行与会话贴着人走，且中心的职责窄到只有治理 |
| 治理事实也放本机（全离线可用） vs 只放中心 | **只放中心** | [撤销向后生效](../PF-001-identity-scope-and-agent-constraints/design.md#66-撤销不等于强制停止)要求有一个此刻说了算的地方。放在本机，「此刻」就变成了「这台机器上次同步的时候」 |
| 人读与机读**各做一套** vs **同一份事实两种交法** | **同一份两种交法** | 各做一套之后，研发者验的是脚本那一套，同事用的是屏那一套，**两者的差异恰好藏在没人验的地方** |
| 屏上**本地先显示后对齐**（手感好） vs **落账之后才显示**（诚实） | **落账之后才显示** | 这块屏同时是研发者的眼睛。[先显示的那一版在失败路径上会撒谎](#53-屏上的每一条都指得回日志里的一条)，而那正是最需要它说真话的时候 |
| 换账号做成**屏上一个切换动作** vs **重新进来一次** | **重新进来一次** | 「当前是谁」必须任何时刻都成立（[§6.3](#63-当前身份必须一直在场)）。同类工具上最常见的事故就是拿错身份做了不可回退的动作，**而切换越顺手，错得越无声** |
| 被移出组织后**本机自动清理** vs **保留但不可达** | **保留但不可达** | 自动清理等于删除会话，[而那是明文禁止的](../PF-015-session-lifecycle-and-ownership/design.md#61-会话不会消失)；且[PF-001 对租户级私有部分的口径就是不可达但不销毁](../PF-001-identity-scope-and-agent-constraints/design.md#退出之后再加入回来的是同一个租户)。**合规清除是另一件事，不靠这里顺手做掉** |
| 交付面自己的动作与[斜杠命令](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-slash-command--斜杠命令--slash-command)**混成一类**（人不必区分） vs **分成两类并让人看得出** | **分成两类** | 混起来对新手友好一天，之后每天都要付利息：**用户无法预判自己这一下会不会被 agent 看到**，而两者的后果完全不同——一个进日志、一个不进 |
| 没人开着屏时**这一处照常发生事** vs **开着屏才有** | **照常发生事**（[裁定](design.md)） | 「开着屏才有」最安静，但[四条已接受规则里有两条直接失效](#616-没人开着屏这一处照常发生事)，且失效在没人看着的时候。代价是每台机器上始终有东西在运转，那是可以在技术设计里定义清楚的运维事实 |
| 中心不可达时已开着的会话**照常干活** vs **明确停下** | **照常干活，不设时限**（[裁定](design.md)） | 会话与工具都在本机，[让网线决定他能不能干手上的活，等于把中心做成每一句话的必经之路](#617-治理中心不可达已经开着的会话照常干活)。代价是撤销在这台机器上的生效点被拖到它再连上那一刻——被明知并接受 |
| 每台机器上**只有自己那一把凭据** vs **模型请求经中心出去** vs **组织托管一把、复制到每台机器** | **只有自己那一把**（[裁定](design.md)） | 经中心出去把「模型调用在本机」重新划了；组织托管一把、复制出去，离职时收不回——[组织那一层也就不持有模型凭据](../PF-013-model-profiles-and-invocation/design.md#非目标)。**而 [PF-013 已经允许范围自带凭据](../PF-013-model-profiles-and-invocation/design.md#56-凭据挂在范围上不挂在档案上)，不必为此再造任何东西** |
| 自托管一个治理中心**算正式部署形态** vs **只是研发夹具** | **研发夹具**（[裁定](design.md)） | 算正式形态，「我的账号在哪个中心」就成了每个用户都得理解的概念，备份升级运维也归了用户。代价是没有中心一个会话也开不了——**v1 只承诺组织统一部署，个人自托管等有真实需求再升级** |
| 进来没指定会话**接着上次** vs **总是新的** | **总是新的**，接上次要指名（[裁定](design.md)） | 接着上次容易把新事说进旧会话，[而会话类型对不上只提醒不拦](../PF-015-session-lifecycle-and-ownership/design.md#66-跑题只提醒不阻拦)。总是新的会让会话数量涨得快，只能等自动归档慢慢收——**这个代价付得起** |
| 观感偏好**跟人走** vs **跟机器走** vs **分开** | **跟人走**，是个人 context 的一部分（[裁定](design.md)） | 跟机器走每换一台就重配；分开要维护一份「哪些跟人走」的名单，每加一个选项吵一次。跟人走的代价是中心多承载一类东西——[PF-001 本来就把个人 context 挂在账号上](../PF-001-identity-scope-and-agent-constraints/design.md#contextagent-运行时可感知的上下文信息)，这不是新的一类 |
| 一个租户的池子**按据点各一份** vs **中心合成一份** | **按据点各一份** | 合成一份要中心知道每台机器上的卡片，[与中心不知道任何会话正面冲突](#619-这里看到的池子是这一处的)，换来的只是目前没人要求的「一人同时用两台机器」 |

## 八、边界与依赖

**本 topic 不立任何别人必须遵守的协议，只用已有的规矩**，因此[在架构内核之外](../architecture-core.md#内核之外的-pf)。
它划的[那条中心与据点的界](#56-哪些东西在中心一侧哪些在据点一侧)**不是一条新规矩**，
