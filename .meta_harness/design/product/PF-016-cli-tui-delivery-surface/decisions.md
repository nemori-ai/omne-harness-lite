# PF-016 决策与来源

产品设计允许 product manager 做判断，但**不允许发明没人拍过板的东西**。
本页把两者分开：哪些是产品负责人裁决的，哪些是 PM 自己推导的，各自依据在哪。

## 一、拍板记录

### 2026-09-22 · 这个交付面是什么，以及它的五条边界

**原话五条，由派发者当日转录**（**是转录，不是二手转述**；
本 topic 尚无 `interviews/`，这五条是目前唯一的原始输入）。

> 「我们的这个 CLI TUI 是要**真正能够被面向生产进行产品分发**的，也就是比如**一个组织下的多名同事
> 各自在自己的机器上安装 cli，然后注册、登录，一个超级管理员创建了团队组织，然后邀请大家加入，
> 这个流程是要有的**。」

> 「**会话、run、工具执行在用户的本机。**」

> 「**中心治理节点……本质上是一个独立的 app。**」

> 「主要面向『**可用于研发时进行端到端验证 且 轻量化的 local harness 生产版本**』性质的 CLI-TUI。」

> 「**多组织的情况实质上我们应该是已经设计了**（就意味着是要实现交付的），我们的 CLI TUI 的设计和实现
> **要能够满足这块也能被端到端地验证**……**没有 web 能力**。」

### 2026-09-22 · 正式接受

**原话**：「PF-016 正式接受。」——在 rev 3 落盘、C-26 闭合、PF-015 第 3 项改为「账号级」之后。
[README front-matter](README.md) 的 `status` 由 `draft` 改为 `active`，正文一个字未动；

> **D3 的读法要说一句。**裁决选的是「中心为每个租户签发一把可撤销的凭据」那个选项的**结果**——

> [PM 推导为本版不做](#二pm-推导)，可被推翻。

### 2026-09-23 · 斜杠命令的第三种绑定目标不是内容

**产品负责人原话（一）**，块 B-1 的开头（全文与其余六条在 [PF-002 decisions](../PF-002-assets-settings-and-permissions/decisions.md#2026-09-23--斜杠命令三种绑定目标mcp-的动作即工具条目连接件带身份鉴权工作区资产的权限取最严值)）：

> 拍要我定的六项之前，我先强调一下：斜杆命令在我们的系统中有两种性质，一种是当作提示词的名称（也就是你说的斜杠命令是内容那一半），另一种是当作触发一条系统的业务流程的命令名（比如执行会话上下文压缩、列出后台执行的任务、展示会话的 todoItems 等等），这个在这一次的设计中就需要把两种都设计覆盖（但同样只是把契约、协议和规格形状设计好，不做具体的特定一种命令的实现的设计）。

**原话（二）**：

> slash command 在我们的系统里面就是对应三种：1）自定义的 prompt；2）装配的一个 skill，直接加载它的 SKILL.md 内容当作消息的一个块；3）系统内的一条业务流程，比如一个命令服务的某一个动作的执行、一个查询服务的一个动作的执行。我们之所以把它定做一种专门的资产类型是为未来提供一种可编程性留的口子。

| 裁决 | 落在正文哪里 |
|---|---|
| **绑定系统业务流程的斜杠命令不是内容**；另两种仍是 | [§5.4 第一类](design.md#第一类成为一条入站到达)新增一行；[§5.7](design.md#57-人要做的事分三族) 那段引文 |
| **本程只定形状，不枚举任何一条系统业务流程** | [§5.4 第二类](design.md#第二类具名的那几条会话动作它们不经入站到达)末段 |

交付面一侧的其余几条（未知命令名、字面发送、参数提示、两种呈现形式一样识别、撞名）是 PM 推出的，
推理链在[第二节「rev 4 新推的」](#rev-4-新推的)；撞名的规则本身归 [PF-002](../PF-002-assets-settings-and-permissions/design.md#slash-command)，§9 那一项随之关闭。

### 2026-09-23 · 参数按声明解析、无权限即不存在、保留名带前缀

**背景**：斜杠命令解析的复用提案展开的产品问题交产品负责人作答，随后补裁两处；
全文与其余几条的落点在 [PF-002 decisions](../PF-002-assets-settings-and-permissions/decisions.md#2026-09-23--斜杠命令参数无权限即不存在会话认得哪些命令③-型不开放保留名前缀)。

**产品负责人原话（一）**：

> 问题一：另成一个内容块；问题二：命令型的 slash command 类似 CLI command 那样按照命令声明的参数来解析，解析没通过直接当场明说，不发送；问题三：有点过度设计了其实，就是没有权限在装配时候（会话创建装载可用的所有 slash commands）本身就不应该可见，不装配，那其实就是当普通消息文本传送；未决一：prompt 型和 skill 型的不存在这个问题，因为如果要失效，需要显式地先用 reload 类的斜杆命令来触发会话的可变装备组建部分的重装配，命令型的本质上就是服务，执行时候服务报错即可，然后下一轮的时候自动触发重装配来保证命令不再可见；未决二：本版不开，不做复杂，未来是要开发这块的可拓展性，诚实记录好即可；未决三：约定所有的保留名都带 omne-official 前缀

**原话（二）**，补裁——第 1 条答「当普通消息文本传送」与本 topic [§5.7](design.md#57-人要做的事分三族)「不存在的命令名当场明说、不发送」相抵时按哪边，第 2 条答「① 型带参数声明时是否同一规则」：

> 1. 无权限 = 不存在 = 当场明说不发送; 2. 『当场明说不发送』

| 裁决 | 落在正文哪里 |
|---|---|
| **声明了参数的命令，像命令行程序那样按声明解析；解析不通过当场明说、不发送；三种绑定目标一条规则** | [§5.7](design.md#57-人要做的事分三族) 那张表新增「参数与声明对不上」一行 |
| **没有权限用的命令，与不存在的名字同一种后果：当场明说、不发送**；不当普通文本送出 | [§5.7](design.md#57-人要做的事分三族)「敲了一个这个会话没有的命令名」 |
| **保留名一律带 `omne-official` 前缀** | [§5.7](design.md#57-人要做的事分三族)「名字撞了」；[§5.4 第二类](design.md#第二类具名的那几条会话动作它们不经入站到达)末段 |
| **① ② 型的变化等人发 reload 类命令才进开着的会话** | [§5.7](design.md#57-人要做的事分三族)「会话里的命令变了」；[§5.4 第二类](design.md#第二类具名的那几条会话动作它们不经入站到达)末段点名 reload |

**每条都附推理链，可以被逐条核对与推翻。**

| 结论 | 从哪几条推出 | 推理 |

| [会话据点](design.md#会话据点)的身份是**（一处 · 治理中心 · 账号）** | 裁决 2、3；[PF-001 登录标识「部署内唯一」](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-login-identifier--登录标识--login-identifier)；[PF-001 §6.4 隔离](../PF-001-identity-scope-and-agent-constraints/design.md#64-隔离) | 会话的事实真在那台机器上 → 带「一处」；账号的唯一性只在一个部署内成立，而本形态下「部署」就是治理中心 → 带「中心」；归属的根是账号 → 带「账号」。**不带登录状态**，因为同一账号登录两次看到的是同一批会话；**不带租户**，因为租户隔离[已经有一套规则](../PF-001-identity-scope-and-agent-constraints/design.md#64-隔离)，再按租户拆一次就会有第二套 |

## 六、调研参照

**这一节里的东西全部是参照与反例，不是依据。**
被采纳的做法已经写进[§二 PM 推导](#二pm-推导)并说清了它为什么适用于本产品；
**没有任何一条因为「某个知名产品这么做」而进入正文。**
下表区分**观察到的事实**与**我对其理由的推测**。

| 看的是什么 | 观察到的事实（来源） | 我的推测（**标明是推测**） | 对本设计的用处 |
|---|---|---|---|
| **团队治理能不能在命令行里做完** | Vercel CLI 有 `teams add` / `teams invite` / `switch`，并规定**非交互时必须显式传参**；同一页又写着「You can manage Teams with further options and greater control from the Vercel Dashboard」（[docs](https://vercel.com/docs/cli/teams)）。GitHub CLI 只有 `gh org list`，**建组织要去网页**（[manual](https://cli.github.com/manual/gh_org)） | 推测：命令行一侧通常只承担**治理动作的子集**，复杂的留给网页 | **反面参照**：我们**没有网页**，所以[治理族必须自足](design.md#57-人要做的事分三族)——这是本形态的额外负担，不是抄来的功能清单 |
| **一台机器上多身份** | GitHub CLI 的活动账号是**全局一个**、按 host 分，切换靠 `gh auth switch`，官方文档承认上下文无关的命令「won't know which account you want」（[docs](https://docs.github.com/en/github-cli/github-cli/using-multiple-accounts)）；社区的常见抱怨是**用错账号推了代码** | 推测：全局活动账号之所以留着，是因为按目录绑定要再引入一层配置 | **采纳的是那个失败模式，不是那个做法**：[一次使用只以一个登录状态行事、当前身份一直在场](design.md#63-当前身份必须一直在场)。适用理由在本产品里更硬——[归属在创建那一刻钉死且改不回来](../PF-015-session-lifecycle-and-ownership/design.md#612-会话持有创建那一刻的租户身份) |
| **人读与机读怎么分** | `clig.dev` 写死两条：「Human-readable output is paramount」与「Anything that is machine readable should also go to stdout … Log messages, errors, and so on should all be sent to stderr」 | —— | 支持[§5.5 同源两交法](design.md#55-两种呈现形式同一份事实)与[§6.6 机读只承载事实](design.md#66-机读那一份只承载事实)。**适用理由是裁决 4**：这块面同时是验证载体 |
| **偏好跟人走还是跟机器走** | VS Code Settings Sync **默认不同步 machine 作用域的设置**，理由写在文档里：「their values are specific to a given machine」（[docs](https://code.visualstudio.com/docs/configure/settings-sync)） | 推测：他们之所以要专门分出这一档，是因为「全同步」会把只在某台机器上成立的值带到别处 | 它是[观感偏好「分开」那个选项](design.md#七取舍)的原型，**产品负责人没有选它**：本产品里它的成本更明确——会多出一份要维护的名单 |
| **离开组织之后本机残留** | 1Password：删除成员后，**要等那台设备联网并解锁时，数据才从设备上移除**；离线则在下次联网解锁前仍可访问（[support](https://support.1password.com/offboarding/)）。Claude Code：会话记录**明文存在本机**，默认保留 30 天，可用 `cleanupPeriodDays` 调（[docs](https://code.claude.com/docs/en/data-usage)） | 推测：两家都把「本机上那份」当成尽力而为的事，因为产品无法控制一台私人机器 | **印证了[§6.10 的边界要说实话](design.md#610-成员资格无效期间本机那些会话不呈现也不删)**：能承诺的是不呈现、不放行，**不是磁盘上没有字节**。但**保留而非清理**这条是从 [PF-015 §6.1](../PF-015-session-lifecycle-and-ownership/design.md#61-会话不会消失) 推出来的，不是抄来的 |
| **长活儿要不要跟着终端一起死** | Cursor 把长活儿整个搬到云端 VM（「you can close your laptop and check the result later」），并把「compute 留在你机器上」的那一种**另起了一个名字**（[docs](https://cursor.com/docs/cloud-agent)） | 推测：他们没有在用户机器上做常驻守护，而是换了一台机器来放那件活儿 | **只用来说明「没人开着屏时怎么办」是一个真问题**：别人绕开它的办法（搬到云端）**与裁决 2「会话、run、工具执行在用户本机」直接冲突**，所以对我们不可用——[本产品的答案是这一处自己照常运转](design.md#616-没人开着屏这一处照常发生事) |
| **等人的时候怎么叫人** | Claude Code 的通知渠道是一项可配的偏好（终端响铃 / 各家终端的桌面通知 / 自定义 hook），**默认只在少数终端里发桌面通知**（[docs](https://code.claude.com/docs/en/terminal-config)） | 推测：渠道做成可配，是因为终端之间能力差异大到无法给一个统一承诺 | **支持把「用什么叫人」判给技术设计**（[§二](#二pm-推导)）。「没人开着屏的时候怎么办」[已答](design.md#616-没人开着屏这一处照常发生事)：等着的东西照常攒着 |
