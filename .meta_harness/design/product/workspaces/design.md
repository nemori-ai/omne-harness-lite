# 工作区产品设计

状态：产品设计草案，revision 2。尚无整体接受证据。设计落位不授予实现支持、阶段能力或技术采用。技术承接从[领域入口](../../../../docs/domains/workspaces/README.md)与[能力组入口](../../../../packages/workspace/README.md)展开。

## 产品需求描述

工作区让人和 agent 围绕同一份资源跨会话、跨节点持续工作。它是有独立身份的资源聚合，可以包含代码、文档、数据、知识和自定义资产，不要求预先绑定固定目标。一次会话可以有临时目标，agent 也可以从资源中理解任务；任务完成或 agent 类型改变不改工作区身份。

工作区、实例和地址回答三个问题：维护的是哪份资源聚合，使用的是哪次具体物化，通过什么入口访问。实例可以先于会话存在，同一工作区可以有多个实例，同一实例可以由获准的多个租户使用。路径、remote、分支和提交用于定位或版本管理，均不能替代工作区身份或授权。换地址、换机器、结束会话、卸载实例，不自动删除逻辑工作区。

Omne Host 托管工作区有唯一治理所有者租户。外部仓库登记不设 Omne 治理所有者，首次登记者与后来接入者均是参与者；登记不转移外部资源所有权，不增加外部写权限。参与关系、具体资源访问资格与组织参与政策分别成立，知道地址、获邀或实例已存在都不能替代这些条件。共享资源保持同一工作区归属；多实例内容可以处于不同版本，不承诺即时一致或写入所有地址。

框架承载可配置的组织参与规则及其依据、适用范围和拒绝原因，不钉死部署默认值、固定政策档位或例外名单。按正式装配约定，这项政策在实际装配时判断，政策变化本身不热重判当前会话或删除关系；普通动作仍须满足自己的有效授权。若采用按治理归属限定组织范围的政策，无治理所有者的外部工作区不能把首登者或参与者组织冒充归属。工作区使用路径的拒绝不等于阻止普通目录访问：原本合法的文件访问沿环境、工具与提供者权限继续，不加载工作区来源，也不能把这种覆盖描述成操作系统隔离。

工作区来源只提供允许的资产和设置材料。资产类别的求值、执行许可与生命周期分别归其拥有者；AGENTS.md 等目录指导归 Runtime Context。共享实例不分享租户私有资产、配值或凭据，工作区所有者的私人材料也不成为参与者会话的输入。

### J-WS01 显式接入已有目录或装载已登记资源

用户希望把已有项目作为工作区继续使用，或从已登记资源在指定节点取得实例。前提是用户明确选择工作区及目标，当前租户具备有效参与条件和本次所需的资源资格。交付面可以建议当前目录或最近记录，但提交仍是明确选择；进入目录或普通新建会话不登记、不附着。

中心先登记与本地先有内容都可接入。本地已有目录无需重新 clone；显式登记只同步租户关系及必要关联标识，不上传文件、不迁移外部资源、不重复创建已有托管资源。身份匹配需要明确依据，同一地址字符串不能自动合并不同工作区。创建托管工作区时选择已支持的管理类型，创建资源与本地装载是分别可观察的动作。

登记与实例关联成立后，Session 将明确选择交装配作为候选。有效参与条件、适用组织政策、实例条件及当前来源读取资格成立时，可以读取和校验该候选的工作区来源，无须等候装配完成。来源校验通过且采用与交接条件成立后，Session 才确认当前工作区选择已正式采用并报告附着成功。

授权失败、目标路径冲突、登记失败或必须访问的地址不可达，均给出真实原因，不覆盖已有目录、不新建空工作区、不报告已附着。依赖装载的新会话不能把装载失败显示为创建成功。关系和实例关联已经确认但来源或装配校验失败时，分别显示已登记、未采用及具体原因。首次接入没有原采用时，工作区层仍为空；已有原采用时保留原采用记录，后续授权仍须分别核验。用户可以修正资格或目标、查询已经完成的登记，再继续接入；取消或超时后先核对实际关系与资源结果，不能凭未收到答复重复创建。用户也可继续按普通目录使用，界面需表达其工作区层为空。

### J-WS02 由不同租户和节点持续维护同一工作区

获准参与者希望在自己的会话或另一节点继续工作。每次实际装配按该会话租户核验参与条件、组织政策和来源；实例不固定持有某租户身份。同一工作区的共享资源保持身份与操作归属，各会话的有效资产和设置可以不同。

实例可以独立存在，结束、归档会话或改变 agent 类型不卸载实例、不销毁资源。Git 管理类型允许 agent 运用分支与 worktree 组织并行工作；新建 worktree 不自动登记 Omne 实例，显式作为工作区使用后才关联原工作区。多个目录或 worktree 不构成安全沙箱。

实例失效或地址变化只改变相关入口的可用性，不证明中心资源已丢失。恢复时查询原工作区、原实例及所需资源，保留原租户、会话和操作归因；不能借共享实例读取别人的私有配置，不能把故障当成理由静默写入新身份的私有副本。用户可选择其他获准入口，原动作的结果仍归原动作。

### J-WS03 在获准目标上读写、同步与处理冲突

人或 agent 希望维护工作成果，先选择实际本地实例或远端目标，并满足读写资格和该管理类型的能力条件。共同契约描述身份、目标、状态和结果；具体类型复用原生资源管理，不强迫非 Git 类型虚构分支或提交。

Git 类型复用 commit、diff、branch、worktree、merge、fetch 与 push。agent 可以用已有通用工具自主检查变化、同步并处理冲突，无须先学习 Omne 专属 Git 工具。发生冲突不固定转交用户；只有需要业务取舍、信息或额外授权时才请求协作。远端或本地变化由用户告知或 agent 按需检查，不要求即时推送、即时拉取或中断当前任务。

结果说明作用目标及实际状态。排队、开始传输、写入本地与远端确认完成分别表达；写入一个 remote 不表示全部地址或实例已同步。资源成果不额外经过统一工作区“发布”状态。容量和文件大小限制由已采用提供者及部署配置表达，超限明确失败并保留本地原件，不截断、遗漏或显示成功；Git 不承诺合并任意二进制文件。

冲突、断网或结果未知保留可判断的状态。取消请求不保证已执行写入撤销或物理执行停止。恢复先查询原操作与原生资源状态，确认需要后续动作再执行；不得盲目重推、重写或重放原工具。

### J-WS04 从共享与实例本地来源取得可解释的材料

用户希望工作区携带的资产和设置可用，同时保留本地定制。已有明确候选选择，且本会话租户的有效参与条件、适用组织政策、实例条件和当前来源读取资格成立时，系统可以为该候选读取来源，无须先完成装配。读取成功不等于正式采用；来源校验及采用与交接条件成立前，候选材料不生效。

实例根 `.omne` 是共享来源，`.omne.local` 是实例本地来源；两者结构相同，后者不进入工作区共享上传与同步。`.omne` 中的每次变更须纳入该工作区所采用的共享同步范围，面向获准访问该工作区的租户共享。同步仍可异步、按需，完成时机、冲突和失败处理沿所采用管理类型的机制与策略，不要求变更后立即 push 或立即更新其他实例。

共用物理实例时，local 可能被多个会话读取，其名称不保证租户间私密。租户私有材料仍须走租户来源与授权边界。

两根各自用 `workspace.json` 表达扩展发现、允许的设置、禁用与兼容配置，不另设同事实的 `settings.json`，也不设置仓库授权用的 `permissions.json`。原生资产在约定位置按类别格式自动发现，无需逐件登记，也无需创建空目录。类别位置为 `skills/`、`tools/`、`mcps/`、`connectors/`、`loop-extensions/`、`commands/`、`plugins/`、`agents/`；包内格式和运行规则由对应类别拥有。Skill 的 SKILL.md 与可选 `.omne/skill.json` 不把技能内部命名空间变成另一工作区；脚本存在不授予执行权，顶层 rules 目录也不自动注入全部文本。

默认发现限定实例根的约定位置。额外嵌套范围须由根配置明确登记相对路径，可使用受支持通配符；不任意递归扫描。软链接及需要穿过软链接的路径始终排除，显式登记也不能绕过。来源缺失是空来源，配置缺失仍发现默认范围；已存在配置解析或格式错误阻止此次装配，标明文件与原因，不忽略 local 或退回共享值。

可用资产先经过禁用、资格和锁定筛选，再按类别＋name 取并集，同身份的可用 local 资产优先于共享；被过滤的 local 不遮蔽合法共享候选。选中的实现是完整包，不逐文件拼接。设置按声明项处理，同项 local 显式值优先，未配则取共享；显式 false 不等于未配，也不按 OR 合并。结构值不自动递归合并。用户可只用 local 配置覆盖共享实现的允许设置；若选中同身份 local 实现，针对共享实现的覆盖、凭据和包文件不迁移过去。

求值应说明来源、选中与过滤原因。工作区文件不能放宽权限、落点、身份设置或治理锁定。错误修正后重新求值；来源读取期间不执行其中程序，也不上传两根求值后的有效结果作为共享资源。

### J-WS05 明确复用同工作区的第三方资产

用户希望复用 Codex 或 Claude Code 的已有 Skill、MCP 与 hook，前提是所采用兼容能力及格式版本受支持，并且有效配置明确允许该来源。不同 harness 使用独立开关，Codex 开关覆盖其 `.agents` 与 `.codex` 工作区约定。两根开关按同项显式值优先规则求值，不凭目录存在启用；具体部署缺省值与支持版本不在本候选补定。

读取原位置的受支持内容，无需复制或逐件登记。范围限同工作区，包含对应约定中的根配置入口，如 Claude Code 的 `.mcp.json`；不读取用户家目录，不导入第三方整体权限政策、Agent Definition 或指令文本。hook 转为 Loop Extension 的规则归对应能力。原文件保留，不自动改写，不将第三方本地内容转成共享同步资源。

转换后仍须资格、禁用、锁定和运行准入检查。可用 Omne 原生同能力资产优先，原生内部 local 优先于共享。两个第三方来源提供同能力不同内容时展示冲突并由用户明确选择，不静默指定一家优先；无冲突能力可取并集，多路径不得重复装载同一来源或重复触发 hook。未知格式、未支持字段或不能可靠识别重复时明确报告，不能伪装成功。用户可关闭来源、解决冲突或选用支持格式后再装配；兼容开启不等于命令型 MCP 或 hook 获准执行，其逐件准入归相应能力与租户治理。

### J-WS06 更换选择或显式采用新的来源

用户希望为同一会话附着、更换、解除工作区，或采用更新后的资产与配置。Session 保存当前选择和变更事实，工作区给出合法关联，装配重新求值受影响输入。文件修改、Git 同步、兼容开关变化不静默改变已采用装配；新的实际装配或显式 reload 才读取并校验。工作区按作用域为来源维护只增不减的采用变更计数。可读材料变化（包括本地文件修改与来源同步），或参与关系变化使当前主体可读的范围改变时，计数加一，并通知使用方。会话选了哪个工作区是 Session 的事实，新 Run 开始时直接比对，不靠这个计数。计数变化只说明来源变了，不构成采用；新 Run 开始时所选工作区与计数都相同，就不必重读来源。不经系统的本地修改由工作区察觉后计入；工作区还没察觉完时，新 Run 直接重读来源，所以新 Run 总能读到开始时已有的本地修改。显式 reload 总是重新读取并校验，不靠比对跳过。

候选验证通过并符合交接条件后才采用，失败说明原因并保持原采用记录，不发布半新半旧组合。保留原采用不延续已经撤销的授权：后续准入、读取和结果交付各按当前资格核验；旧条件失效或授权无法取得时阻止依赖允许结论的新动作。更换工作区不改变会话租户，已发模型或工具调用保留原输入、实现、环境及工作区引用，未消费结果仍可归回原工作。较新的选择和取消优先于迟到候选，旧建议在执行前按当前约定核验。

实际执行落点、重建及原痕迹是否保留由执行环境报告，Runtime Context 将事实供给 agent；不能用“选择成功”证明执行环境已切换，不能用“新环境可用”证明原工具已迁移。用户可修正候选后再次发起，恢复围绕原工作查询或等待，不重发已经执行的动作。显式 reload 的命令形状与交接机制由装配及交付面接续，不扩大为外部副作用可回滚。

### J-WS07 分别管理参与关系与工作区超管授权

用户希望退出、移除参与者，或调整托管工作区的治理授权。合法治理配置必须明确哪些主体具备授撤、移除他人、销毁及转授资格，谁能修改配置，以及授权的作用域和上界；仓库内容不能自行授予这些权利。仅有参与或一般管理名号不产生额外资格。参与者可以退出自身关系，移除别人须有本资源的明确治理资格。工作区仍存在且未完成合法归属变更时，不能单独解除唯一治理所有者关系。

PF-020 提供了一个具体治理方案：仅创建者授撤工作区超管，超管不能转授，创建者或该超管可移除参与者或销毁托管资源。它是可供负责人选择的具名策略候选，不能据此排除经合法授权的组织治理模型，也不是本轮默认值或已选支持清单。无论选择何种合法方案，授权都不自动移交治理归属，不绕过资源授权、组织政策或租户私有数据边界。

撤回一项工作区治理授权只撤回该授权，保留参与关系及其他合法权利；删除关系则解除依附该关系的授权，不删除别人的关系或本地文件。外部工作区的首登者没有因登记取得上述托管治理特权，只可沿参与资格退出自身关系，不能因首登销毁外部资源或授予超管。

关系解除后，该租户后续会话将原目录当作普通目录，`.omne`、`.omne.local` 和经开关发现的兼容来源均不进入工作区装配；残留配置不能恢复关系。需要再次使用时须显式登记并重新核验，不从本地内容恢复已解除的中心权利。已运行会话的合法采用与实际授权按相应规则处理，不推定关系删除立即重装全部 runtime。组织成员退出与工作区关系解除是不同动作；成员解除期间租户私有资产和配值的保留、不可访问及同租户重入恢复归身份与资产，工作区不得顺带共享或销毁这些材料。失败或取消后查询具体关系及授权结果，不展示未经确认的退出成功。

### J-WS08 确认销毁托管资源并收敛关系

具有所采用治理策略明确销毁资格的主体希望结束 Omne Host 托管工作区，须同时满足本次资源授权。PF-020 的具名策略限定创建者或其明确授权的工作区超管；本候选不把该策略钉死为唯一组织治理模型。一般维护权限、组织超管名号或公开地址本身都不自动授予销毁资格；组织治理主体如需承担此动作，须有合法、明确且受上界约束的授权。外部工作区登记不提供销毁外部资源的入口。

托管资源确认销毁后，所有指向该工作区的租户关系失效并完成清理，包括治理所有者与参与者。远端请求已提交、超时、暂时不可达与明确未销毁分别表达；不能把未知当销毁，也不能在确认销毁后继续展示旧关系有效。本地实例文件保持原样，后续使用为普通目录，不自动登记成替代工作区。

销毁和关系清理跨责任发生，过程须保留可恢复状态。资源已销毁但关系清理未完成时，继续收敛关系而不重新销毁；结果未知时先查原操作和资源，不能因取消或重启猜测资源未动。界面呈现已确认效果、尚未完成部分与可用恢复入口。销毁确认不证明任何本地数据已清除，也不撤销原动作真实结果。

## 阶段与版本支持承诺

0.0.0 → 0.1.0 的工作区能力清单等待负责人选择。CAP-WS01 至 CAP-WS14 是选择对象，不是已承诺全支持的清单。本页不提出推荐基线，旧 PF 的“首版仅 Git”、具体默认值、其他领域阶段承诺均不能替代选择。选择须注明完整能力范围、必要依赖、部署与提供者版本、已验证条件和未覆盖行为；不能以只完成界面或目录扫描声称整个能力成立。

长期框架候选保留身份、参与、实例、来源及真实结果的责任边界，并允许管理类型、地址提供者与合法治理配置扩展。已知 Git 路线不是 Omne Host 的永久唯一类型，未来类型不必伪造 Git 语义。组合工作区、创建后类型转换、所有权移交、local 跨设备备份或迁移、通用跨地址同步、大文件产品及额外交付流程没有因本稿成为支持承诺。

版本支持矩阵须由具体能力拥有者明示，包括资源管理类型、提供者、配置格式、资产格式及第三方兼容版本。未知或不支持的版本明确报告，不按相似字段猜测兼容。阶段选择、产品扩展选择、技术义务和来源缺口分别见[问题记录](design.md#未决问题与待定事项)；未决仅隔离其依赖能力，不降低本页已写明的身份、授权及结果规则。

## 未决问题与待定事项

本章是当前产品问题入口。阶段与政策选择、技术义务、来源缺证及明确非目标分别维护；既定约束不重新请求选择。技术问题只限制依赖部分，不能减损已有不变量。

### Q-WS01 0.0.0 → 0.1.0 能力与版本清单

决定责任：阶段负责人。

场景：需要把工作区候选转为有范围的阶段承诺。

待明确：负责人选择哪些完整能力、部署范围、管理类型/提供者及兼容版本，并明确验证前提？

既定约束：

- CAP-WS01 至 CAP-WS14 未核实实现；旧首版范围与其他域承诺不能代选。
- 身份、授权、结果真实性与原工作保留不因选择较小范围削弱。

处理方向及后果：

- 按逐项能力及必要依赖形成具名支持清单。
- 暂不授予工作区阶段支持，保留设计候选直至依赖证据齐备。

不代负责人选择；本候选隔离未选范围。

影响：决定阶段承诺与后续实施准入；本稿无推荐基线。

### Q-WS02 合法治理策略的支持与采用范围

决定责任：产品负责人及合法治理配置拥有者。

场景：组织希望通过自己的治理角色管理托管工作区，历史 PF 只给出创建者/工作区超管方案。

待明确：工作区治理配置支持哪些授撤、移除、销毁与转授规则；谁可以合法发布这些配置？

既定约束：

- 框架的合法治理配置边界已按本轮要求写明；本卡只待选择具体策略支持及采用，不重问框架可配置性。
- 明确授权、作用域、上界、配置修改资格及拒绝原因必须可核验。
- 工作区文件不授予权限，管理员名号不自动授权，租户私有边界不因治理角色放宽。
- 托管工作区唯一治理归属与外部参与身份分别成立。

处理方向及后果：

- 支持 PF-020 有来源的创建者/不可转授超管方案，并明确采用范围。
- 支持具名组织治理角色方案，明确授权来源、转授边界、撤销及验证；可与前一方案按部署分别采用。

不代负责人选择；本候选隔离未选范围。

影响：依赖具体治理操作的支持矩阵保持未选；框架候选不把历史角色表钉死为永久唯一模型。
