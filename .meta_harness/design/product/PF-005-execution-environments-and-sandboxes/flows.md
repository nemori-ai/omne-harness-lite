# PF-005 流程与状态

`design.md` 说这块产品**是什么**，本页说它**怎么动**。
查「这步失败了怎么办」来这里，查「这个概念是什么」去 design.md。

## 一、主要旅程

### 1.1 一次工具执行落到某处

| 步骤 | 发生什么 | 完成的标志 |
|---|---|---|
| 1 | agent 发起一个动作——「执行一条命令」，**不说在哪执行** | — |
| 2 | 按当前生效的执行安全策略，确定这次落在**哪一个**执行环境 | 取值确定 |
| 3 | 动作在那里执行，产生效用 | 拿到结果 |

**第 2 步永远有结果**：不存在「没有执行环境」这个状态（[design.md §4](design.md#执行环境)）。
若策略允许宿主机，取值就是宿主机；不允许，就是某个沙箱。

### 1.2 安全策略收紧，执行环境热替换

| 步骤 | 发生什么 | 运行实例 |
|---|---|---|
| 1 | 策略改为「不允许直接使用宿主机的命令行」 | **不变** |
| 2 | 注入的执行环境取值换成一个沙箱 | **不变** |
| 3 | 变化在下一轮以一条提醒到达 agent | 不变 |
| 4 | agent 执行**同一条命令**，落在沙箱里 | **动作空间不变** |

**这是换一个值，不是开关一套机制。**能这么做的前提是宿主机本身也是一个取值
（[design.md §6.1](design.md#61-宿主机是一个取值不是默认状态)）。

### 1.3 会话级沙箱：创建与连续使用

| 步骤 | 发生什么 | 完成的标志 |
|---|---|---|
| 1 | 这个会话第一次需要一个有状态的隔离环境 | — |
| 2 | 创建一个会话级沙箱，**开始计算它的最大连续存活时间** | 沙箱可用 |
| 3 | 连续执行，**后一步可以基于前一步的结果** | — |

第 3 步就是它存在的全部理由。**这一段窗口期内它有状态**，如此而已。

### 1.4 会话级沙箱到点销毁

| 步骤 | 发生什么 | 里面的数据 |
|---|---|---|
| 1 | 达到最大连续存活时间 | — |
| 2 | **直接销毁** | **不留存** |
| 3 | 这个会话下次还要用 | — |
| 4 | **重建一个新的**，重新计时 | 空的 |
| 5 | 变化以一条提醒到达 agent；它**自行决定要不要重算** | — |

**本版不对会话级沙箱的数据作持久要求**，这是刻意不做（[design.md §6.3](design.md#63-会话级沙箱到点销毁数据不留存)）。
第 5 步是这条能成立的前提：agent 得知道东西没了，才谈得上重算。

### 1.5 租户级沙箱：共享使用

| 步骤 | 发生什么 |
|---|---|
| 1 | 该租户的某个 agent 在上面装了个东西、留下些文件 |
| 2 | **同租户的另一个会话、另一个 agent 实例**在同一个空间里看见它 |
| 3 | 双方都可以接着用，也可能互相覆盖 |

**第 2、3 步是特性不是缺陷。**共享工作空间的价值正在于互相看得见，
就像几个人共用一台电脑。

### 1.6 租户级沙箱停机或换节点

| 步骤 | 发生什么 | 数据 |
|---|---|---|
| 1 | 那台机器要停机维护，或要换一个物理节点 | — |
| 2 | **允许停**——沙箱是计算资源 | **必须能备份** |
| 3 | 在新的地方重新起来 | **必须能迁回来** |
| 4 | 该租户的 agent 接着用 | 攒下来的东西还在 |

**需要和租户生命周期一样长的是数据，不是那台机器**（[design.md §5.2](design.md#52-租户级沙箱本体的存活与数据的存活是两件事)）。

### 1.7 agent 感知自己落在哪

| 情形 | agent 应当知道 |
|---|---|
| 当前动作落在哪一类执行环境 | 知道 |
| 这个环境**是否保留上一次的痕迹** | 知道 |
| 环境刚被换掉 / 沙箱刚被重建 | **下一轮以一条提醒到达** |

变化**不打断当前正在进行的运行**，与
[PF-004 §6.4](../PF-004-agent-runtime-assembly-and-liveness/design.md#64-上下文变化怎样到达-agent) 一致。

## 二、分支与异常

| 情形 | 怎么做 | 为什么 |
|---|---|---|
| 这次动作要求的环境**当前不可用** | **明确失败**，说明缺的是什么 | 悄悄换到另一类环境，效用的存活期就和 agent 的预期对不上 |
| 策略**不允许宿主机**，而这个动作只能落在宿主机 | **拒绝**，并说明是策略所致 | 让人知道这不是故障，是可以去申请的 |
| 沙箱**创建失败** | **明确失败**；不退回宿主机顶替 | 退回宿主机等于绕过了安全策略 |
| 会话级沙箱到点销毁时**仍有动作在执行** | 按[退役](../PF-004-agent-runtime-assembly-and-liveness/design.md#67-运行实例的生与灭)的方式收口：先不接新的，等手上的停当 | 直接掐断会留下没有结局的动作 |
| 租户级沙箱两个 agent **同时改同一个东西** | **不阻止**，结果按实际发生的算 | 这是共享空间的固有性质；阻止它就得加隔离，那它就不是共享空间了 |
| 租户级沙箱的数据**迁移失败** | **不算迁移完成**，如实报告；不在新节点上以空数据起来冒充成功 | 用空的顶上，用户会以为东西丢了而实际只是没迁过来 |
| 宿主机可用但**该租户未被授予使用资格** | **拒绝** | 宿主机不提供租户隔离，必须显式允许 |

## 三、状态流转

### 3.1 无状态沙箱

```text
（无）──一次调用开始──→ 存在 ──调用结束──→（无）
```

它的一生就是一次工具调用。**没有"闲置"这个状态**，因此也没有回收的问题。

### 3.2 会话级沙箱

```text
（无）──首次需要──→ 存在（计时中）──到最大连续存活时间──→ 销毁 ──→（无）
   ↑                                                                    │
   └──────────────── 下次还要用就重建一个新的，重新计时 ───────────────┘
```

| 从 | 到 | 触发 | 数据 |
|---|---|---|---|
| 无 | 存在 | 这个会话首次需要 | 空 |
| 存在 | 销毁 | **到达最大连续存活时间** | **不留存** |
| 无 | 存在 | 下次还要用 | **空的，重新算** |

**「最大连续存活时间」是每个沙箱各自的上限**，不是这个会话一辈子只能有一个。

### 3.3 租户级沙箱

```text
（无）──首次需要──→ 运行中 ──停机 / 换节点──→ 在别处重新起来 ──→ 运行中
                       │                              ↑
                       └────── 数据备份 ──────────────┘
                              （必须能迁）
```

| 状态 | 沙箱本体 | 数据 |
|---|---|---|
| 运行中 | 占资源 | 在 |
| 停机 / 迁移中 | **允许不存在** | **必须仍可取回** |
| 在别处运行 | 占资源（另一处） | **接回来** |

**这一格就是「沙箱是计算资源、数据是数据」的全部含义**：
本体可以没，数据不能丢。

## 四、谁能决定什么

| 操作 \ 角色 | 使用者 | 组织超级管理员 | agent |
|---|---|---|---|
| 决定这次动作落在哪 | 不直接决定 | **通过执行安全策略决定** | **不决定**，它只发起动作 |
| 授予 / 收回「可以使用宿主机」 | 不可 | **可** | 不可 |
| 知道当前落在哪、痕迹在不在 | 可 | 可 | **可**（§1.7） |
| 在租户级沙箱里做事 | 可 | 可 | 可 |
| 让租户级沙箱停机 / 换节点 | 不可 | 可 | 不可 |
| 延长会话级沙箱的存活时间 | **不可** | **本版不提供**——上限是资源政策，见 design.md §2 非目标 | 不可 |

**「agent 不决定落在哪」这一行是本 topic 的核心**：它只发起动作，
落点由注入决定。这正是「策略改了而 agent 无感」的来源。

实现时遇到本表覆盖不到的组合，**回到产品设计确认，不要自行补一条**。
