# PF-005 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

### 落点是每次执行算出来的

| # | 场景 | 应当看到什么 |
|---|---|---|
| S1 | 任何一次工具执行 | **要么说得出它落在哪一个执行环境，要么明确被拒**；不存在「没有执行环境」这个答案 |
| S2 | **一个什么沙箱实现都没装的部署** | **照样能跑**——宿主机始终在场，[只要执行环境权限允许就可用](design.md#61-宿主机始终在场沙箱实现装配时可选装配)；**不存在「宿主机不可用」** |
| S3 | **同一时刻，三扇门的执行环境权限分别是 `always-allow` / `auto_place` / `never-allow`** | **三扇门各算各的落点**，同时成立；**没有一个全局取值把它们统一掉** |
| S4 | 某个工具的执行环境权限改成 `never-allow` | **下一次执行**的落点变成一个沙箱；**agent runtime 不重建，动作空间不变** |
| S5 | 改前改后，agent 发起同一条命令 | **两次都执行成功**，只是落点不同；agent 不需要改变它发起动作的方式 |
| S6 | 权限刚改完，当前正有一轮在跑 | **当前这一轮不被打断**；变化在**下一轮**以提醒到达 |
| S7 | **装进来一个新的[沙箱实现](design.md#沙箱实现)** | 它**说得出自己提供哪几种设施、能绑在哪几个层级**，**用的是与别的实现同一套声明方式** |
| S8 | 会话挂着一个由目录承载的工作区，`Files()` 的执行环境权限允许落宿主机，agent 读**工作区目录之外**的一个文件 | **读得到**——与读目录内的文件走同一条放行判断；[目录不是边界](design.md#工作区的承载目录不是宿主机上的边界) |
| S9 | 同上，但这扇门的执行环境权限是 `never-allow` | 落到沙箱里去，**目录内外一视同仁**——不存在「目录内落宿主机、目录外落沙箱」 |

### hooks 与子进程环境

| # | 场景 | 应当看到什么 |
|---|---|---|
| S10 | 已启用的 hooks 兼容件具备执行所需输入，部署只有宿主机落点 | 可以在宿主机起子进程；不因没有沙箱而一律拒绝 |
| S11 | 据点进程持有未列入名单的秘密变量，启动工具、MCP stdio 或 hooks 子进程 | 子进程环境中没有该变量；列入名单且实际存在的普通变量可以取得 |
| S12 | 工作区 hook 尚未由租户启用 | 宿主机允许不代替启用，不运行它 |

### 四类环境各自的存活

| # | 场景 | 应当看到什么 |
|---|---|---|
| S13 | 一次 browser use 结束 | 那个无状态沙箱**随即结束**；没有闲置状态，也没有回收问题 |
| S14 | 会话级沙箱里连续执行两条命令 | **后一条能基于前一条的结果** |
| S15 | 会话级沙箱达到最大连续存活时间 | **直接销毁**；里面的数据**不留存** |
| S16 | 同一会话随后又要用 | **重建一个新的，重新计时**；里面是**空的** |
| S17 | 重建之后 agent 再来取上次的东西 | **取不到**，而且它**知道取不到**（收到过提醒），自行决定重算 |
| S18 | 租户级沙箱里某个 agent 装了个东西 | **同租户的另一个会话、另一个 agent runtime 看得见** |
| S19 | 租户级沙箱停机后在另一个物理节点起来 | **数据跟着过去**，攒下的东西还在 |
| S20 | 租户级沙箱的数据迁移失败 | **不算迁移完成**，如实报告；**不在新节点上以空数据冒充成功** |

### 隔离与授权

| # | 场景 | 应当看到什么 |
|---|---|---|
| S21 | 两个租户的 agent 都在宿主机上写东西 | **互相看得见**——宿主机不提供租户隔离 |
| S22 | 某个工具的执行环境权限是 `never-allow` | 它的作用**落不到宿主机上**；要么落进沙箱，要么明确拒绝 |
| S23 | 两个租户各自有租户级沙箱 | **互相看不见**；不存在跨租户共享的沙箱 |
| S24 | 试图创建一个「组织级沙箱」供多个租户共用 | **不存在这个东西** |
| S25 | 沙箱创建失败 | **明确失败**；**不退回宿主机顶替** |

### 执行环境权限

| # | 场景 | 应当看到什么 |
|---|---|---|
| S26 | **同一个租户下，`Shell()` 配 `auto_place`、`Computer()` 配 `never-allow`、`Browser()` 配 `always-allow`** | **三个各按各的算**，互不牵连 |
| S27 | **`auto_place` 算出该进隔离容器，而容器起不来** | **这次执行被拒**，**不回退宿主机**，失败原因说得出来 |
| S28 | **算出来该落隔离环境，而没有一个已装配的沙箱实现在设施或层级上匹配得上** | **这次执行被拒**，**说得出差的是哪一样**；**不回退宿主机** |
| S29 | **`never-allow` 的工具，隔离环境也去不了** | **拒绝**。没有第三条路 |
| S30 | **给 `Shell()` 配 `never-allow`** | **那扇门还在**，`Shell()` 照常能调；**变的只是作用落在哪** |
| S31 | **工作区里放着一份想改执行环境权限的配置** | **不作数**——[加载时就被滤掉了](../PF-002-assets-settings-and-permissions/design.md#57-工作区那一级不参与权限计算)，放宽收紧都一样 |
| S32 | **一个没声明要用执行环境的工具** | **这一维对它不适用**；**不去给它算一个落点，也不记一条配置** |

### 设施

| # | 场景 | 应当看到什么 |
|---|---|---|
| S33 | 问任意一个执行环境「你提供哪几种设施」 | **答得出来**——它是声明出来的，不是靠猜或靠名字推断 |
| S34 | 问**宿主机**同一个问题 | **一样答得出来**，用**同一种方式**声明；宿主机在这件事上不是例外 |
| S35 | 两个同为会话级的沙箱 | **提供的设施可以完全不同**；同层级不等于可互换 |
| S36 | 同一种设施（比如命令行） | **可以由不同绑定层级的执行环境提供** |

### 共存与感知

| # | 场景 | 应当看到什么 |
|---|---|---|
| S37 | 一个 agent 同时用着命令行沙箱和租户级共享机器 | **两者并存**，各自按自己的层级存活；**并存的理由是设施不同** |
| S38 | 问 agent「你现在在哪儿干活」 | 它答得出当前的执行环境，以及**这里保不保留上次的痕迹** |
| S39 | 沙箱被换掉或重建 | agent 在**下一轮**收到提醒，**自行**调整；不是系统在背后替它处理 |
| S40 | 会话级沙箱到点时仍有动作在执行 | 先不接新的、等手上的停当再销毁；**不留下没有结局的动作** |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 存在「没有执行环境」的动作 | 动作落在了一个说不清的地方，安全性无从判断 |
| **把「当前生效的执行环境」做成一次装配定死的一个全局取值** | 三扇门同时要不同落点就落不下去，**而粒度本来就是每个工具各配各的** |
| **出现「宿主机不可用」这个状态** | agent runtime 本身就跑在它上面；**它不在，整个系统就不在** |
| **某个沙箱实现自带一套别人没有的接口或声明方式** | 宿主机与沙箱不再以同一种方式被比较，**换落点又变回换机制** |
| 换执行环境导致 agent runtime 被重建 | 执行环境跑进了构成里，违反 [PF-004](../PF-004-agent-definition-and-assembly/design.md) |
| 换执行环境导致动作空间变化 | 同上。agent 应当照常能发起同一个动作 |
| 沙箱创建失败后**悄悄退回宿主机** | **绕过了[执行环境权限](design.md#执行环境权限)**。安全事故 |
| **落点算出来不可用，却换一个更宽松的顶上** | 同上——**把刚算完的那套判断作废了**，而宿主机是唯一不提供租户隔离的那个 |
| **一个工具的执行环境权限被另一个工具带着变** | 三态是 per-tool 的；**牵连意味着配置说的不算数** |
| **靠执行环境权限去关掉一扇 meta 的门** | 这一维只管作用落在哪，**关门是它做不到也不该做的事** |
| **执行环境权限是 `never-allow` 的工具，作用却落到了宿主机上** | 同上 |
| 出现跨租户共享的沙箱 | 直接破坏租户隔离。安全事故 |
| 租户级沙箱换节点后**数据丢了** | 「需要和租户生命周期一样长的是数据」这条落空 |
| 迁移没完成却在新节点上以空数据起来 | 用户会以为东西丢了，而实际只是没迁过来——**真假丢失无法分辨** |
| 会话级沙箱销毁时，agent **不知道**东西没了 | §6.3「重算」的前提落空，它会继续引用不存在的东西 |
| 沙箱被当成一类资产，走持有 / 复制 / 分享 | 它是动作落地的地方，不参与组装；那套语义对它毫无意义 |
| **只有沙箱声明设施，宿主机不必声明** | 宿主机当场变回特例，**热替换的前提破了**——换过去之后没人说得出还能干什么 |
| 把设施并进那张四格表，让表变宽 | 寿命与本事被搅成一件事；设施是开放的，表会跟着一起长 |
| 环境变化**打断**了正在进行的一轮 | 不紧急的事被当成紧急的处理 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 宿主机与沙箱同等对待 | 查任意一次执行的落点，**宿主机与沙箱以同一种方式被记录**；不是一个布尔开关 | 记录里只有「是否沙箱」 |
| 落点按门算 | **同时问三扇门「你这次落在哪」，三个答案可以不同** | 只答得出一个全局的落点 |
| 热替换成立 | 改一次执行环境权限，**agent runtime 的身份与装配清单都没变**，而下一次的落点变了 | 权限一改就重起一个 agent runtime |
| 动作空间不受影响 | 权限在宽严之间来回改，**动作空间三次都一样** | 动作空间跟着权限变 |
| 两维分类成立 | 能分别指出：**哪个不绑定是因为用完就扔**（无状态沙箱），**哪个不绑定是因为大家共用**（宿主机） | 两者被并成同一类 |
| 设施是声明出来的 | 拿任意两个执行环境（**含宿主机**）来问，都能列出自己提供哪几种设施，格式一致 | 得靠环境的名字或类型去猜里面有什么 |
| 设施与层级正交 | 造两个同层级但设施不同的沙箱，**系统认得出它们不可互换**；再造两个不同层级但同设施的，**系统认得出设施相同** | 层级一样就当成可互换 |
| 会话级确实有状态 | 窗口期内，后一步能基于前一步的结果 | 每次调用都是干净的 |
| 会话级确实不留存 | 到点销毁后重建，里面**是空的** | 数据被悄悄保留了（那是另一种设计，不是本版） |
| 租户级确实共享 | A 会话装的东西，**B 会话看得见** | 各会话各一份 |
| 数据与本体分开（**仅租户级**） | **停掉那台机器再换个地方起来**，数据还在 | 要么不许停机，要么一停数据就没 |
| 持久要求只在租户级 | 会话级到点销毁后重建**是空的**；无状态用完即无——**两者都不做备份** | 给会话级悄悄加了持久化 |
| 租户隔离不被削弱 | 两个租户各做一遍，**互相看不见对方沙箱里的任何东西** | 有一条路径能看见 |
| agent 能感知 | 让它回答「你在哪儿、上次的东西还在吗」，**答得对** | 它答不出，或答错而不自知 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| 用什么技术实现隔离 | 容器、虚拟机、云主机都是技术选择 |
| 工具怎么声明它需要哪些设施、匹配不上怎么办 | **供给侧归这里，需求侧与匹配归工具与技能**那一块 |
| 设施一共有哪几种、名字怎么定 | 本 topic 只定**要声明**，不定这个清单；它随工具生态长 |
| [执行环境权限](design.md#执行环境权限)怎么配置、谁能改 | 归 PF-002 的设置与权限 |
| 具体怎么实现一个沙箱、那套契约与协议长什么样 | **技术设计。**本 topic 只定**所有沙箱实现遵循同一套，并各自声明设施与可绑定层级** |
| 会话级沙箱的存活上限具体是多久、能不能调 | **资源政策**，本版不定 |
| 重要产出该存到哪里 | 本 topic 只负责说明**沙箱不是存它的地方** |
| 沙箱内数据备份与迁移的具体机制 | 本 topic 只定**哪一类必须能备份能迁移** |
| 会话级沙箱的数据持久化 | **本版刻意不做**，见 design.md §6.3 |
| 租户级沙箱内多个 agent 的协调与互斥 | 互相影响是共享空间的固有性质，本版不引入协调机制 |
| 宿主机本身怎么部署、怎么运维 | 归部署那一侧 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。

## 工作区实例与隔离

同一工作区的多个实例或 worktree 可供不同租户、不同 subagent 使用；目录分工不是执行环境沙箱。目录是实例地址而非逻辑身份，执行位置与文件访问仍按本 topic 的环境及命令权限判定。

## 会话执行环境策略

| # | 场景 | 应当看到什么 |
|---|---|---|
| S41 | 未明确初值创建会话 | 从租户设置取得初始策略，实际落点仍逐工具逐次求值 |
| S42 | 会话内修改策略、恢复会话 | 本会话当前值恢复，租户默认和其他会话不变；当前授权与设施约束继续成立 |

## 独立工具的环境输入

| # | 场景 | 应当看到什么 |
|---|---|---|
| S43 | 当前只有宿主机实现；同一工具先合法采用明确允许宿主机的环境输入，后在下一次执行前合法采用禁止宿主机的新输入 | 前次执行在宿主机成功，后次明确拒绝并指出缺少所需的隔离环境；调用者使用同一工具名与调用方式，已发出的旧调用不因新输入被改写 |
