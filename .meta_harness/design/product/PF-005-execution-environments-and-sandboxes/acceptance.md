# PF-005 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

### 执行环境是一个取值

| 场景 | 应当看到什么 |
|---|---|
| 任何一次工具执行 | **总能说出它落在哪一个执行环境**；不存在「没有执行环境」这个答案 |
| 策略允许宿主机时装配 | 注入的取值就是**宿主机**——它是一个具体取值，不是「没套沙箱」 |
| 策略改为不允许宿主机 | 注入的取值换成一个沙箱；**运行实例不重建，动作空间不变** |
| 策略改前改后，agent 发起同一条命令 | **两次都执行成功**，只是落点不同；agent 不需要改变它发起动作的方式 |
| 策略刚改完，当前正有一轮在跑 | **当前这一轮不被打断**；变化在**下一轮**以提醒到达 |

### 四类环境各自的存活

| 场景 | 应当看到什么 |
|---|---|
| 一次 browser use 结束 | 那个无状态沙箱**随即结束**；没有闲置状态，也没有回收问题 |
| 会话级沙箱里连续执行两条命令 | **后一条能基于前一条的结果** |
| 会话级沙箱达到最大连续存活时间 | **直接销毁**；里面的数据**不留存** |
| 同一会话随后又要用 | **重建一个新的，重新计时**；里面是**空的** |
| 重建之后 agent 再来取上次的东西 | **取不到**，而且它**知道取不到**（收到过提醒），自行决定重算 |
| 租户级沙箱里某个 agent 装了个东西 | **同租户的另一个会话、另一个 agent 实例看得见** |
| 租户级沙箱停机后在另一个物理节点起来 | **数据跟着过去**，攒下的东西还在 |
| 租户级沙箱的数据迁移失败 | **不算迁移完成**，如实报告；**不在新节点上以空数据冒充成功** |

### 隔离与授权

| 场景 | 应当看到什么 |
|---|---|
| 两个租户的 agent 都在宿主机上写东西 | **互相看得见**——宿主机不提供租户隔离 |
| 某租户未被授予「可以使用宿主机」 | 动作**落不到宿主机上**；要么落进沙箱，要么明确拒绝 |
| 两个租户各自有租户级沙箱 | **互相看不见**；不存在跨租户共享的沙箱 |
| 试图创建一个「组织级沙箱」供多个租户共用 | **不存在这个东西** |
| 沙箱创建失败 | **明确失败**；**不退回宿主机顶替** |

### 共存与感知

| 场景 | 应当看到什么 |
|---|---|
| 一个 agent 同时用着命令行沙箱和租户级共享机器 | **两者并存**，各自按自己的层级存活 |
| 问 agent「你现在在哪儿干活」 | 它答得出当前的执行环境，以及**这里保不保留上次的痕迹** |
| 沙箱被换掉或重建 | agent 在**下一轮**收到提醒，**自行**调整；不是系统在背后替它处理 |
| 会话级沙箱到点时仍有动作在执行 | 先不接新的、等手上的停当再销毁；**不留下没有结局的动作** |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 存在「没有执行环境」的动作 | 动作落在了一个说不清的地方，安全性无从判断 |
| 把宿主机实现成「没套沙箱」的默认态 | 切换退化成开关一套机制，**运行时热替换做不到**，agent 也感知得到 |
| 换执行环境导致运行实例被重建 | 执行环境跑进了构成里，违反 [PF-004](../PF-004-agent-runtime-assembly-and-liveness/design.md) |
| 换执行环境导致动作空间变化 | 同上。agent 应当照常能发起同一个动作 |
| 沙箱创建失败后**悄悄退回宿主机** | **绕过了安全策略**。安全事故 |
| 未被授权的租户的动作落到了宿主机上 | 同上 |
| 出现跨租户共享的沙箱 | 直接破坏租户隔离。安全事故 |
| 租户级沙箱换节点后**数据丢了** | 「需要和租户生命周期一样长的是数据」这条落空 |
| 迁移没完成却在新节点上以空数据起来 | 用户会以为东西丢了，而实际只是没迁过来——**真假丢失无法分辨** |
| 会话级沙箱销毁时，agent **不知道**东西没了 | §6.3「重算」的前提落空，它会继续引用不存在的东西 |
| 沙箱被当成一类资产，走持有 / 转移 / 分享 | 它是动作落地的地方，不参与组装；那套语义对它毫无意义 |
| 环境变化**打断**了正在进行的一轮 | 不紧急的事被当成紧急的处理 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 宿主机是一个取值 | 查任意一次执行的落点，**宿主机与沙箱以同一种方式被记录**；不是一个布尔开关 | 记录里只有「是否沙箱」 |
| 热替换成立 | 改一次策略，**运行实例的身份与装配清单都没变**，而落点变了 | 策略一改就重建实例 |
| 动作空间不受影响 | 策略在宽严之间来回改，**动作空间三次都一样** | 动作空间跟着策略变 |
| 两维分类成立 | 能分别指出：**哪个不绑定是因为用完就扔**（无状态沙箱），**哪个不绑定是因为大家共用**（宿主机） | 两者被并成同一类 |
| 会话级确实有状态 | 窗口期内，后一步能基于前一步的结果 | 每次调用都是干净的 |
| 会话级确实不留存 | 到点销毁后重建，里面**是空的** | 数据被悄悄保留了（那是另一种设计，不是本版） |
| 租户级确实共享 | A 会话装的东西，**B 会话看得见** | 各会话各一份 |
| 数据与本体分开（**仅租户级**） | **停掉那台机器再换个地方起来**，数据还在 | 要么不许停机，要么一停数据就没 |
| 持久要求只在租户级 | 会话级到点销毁后重建**是空的**；无状态用完即无——**两者都不做备份** | 给会话级悄悄加了持久化 |
| 租户隔离不被削弱 | 两个租户各做一遍，**互相看不见对方沙箱里的任何东西** | 有一条路径能看见 |
| agent 能感知 | 让它回答「你在哪儿、上次的东西还在吗」，**答得对** | 它答不出，或答错而不自知 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| 用什么技术实现隔离 | 容器、虚拟机、云主机都是技术选择 |
| 工具怎么声明它需要什么样的环境 | 归**工具与技能**那一块 |
| 执行安全策略怎么配置、谁能改 | 归 PF-002 的设置与权限 |
| 会话级沙箱的存活上限具体是多久、能不能调 | **资源政策**，本版不定 |
| 重要产出该存到哪里 | 本 topic 只负责说明**沙箱不是存它的地方** |
| 沙箱内数据备份与迁移的具体机制 | 本 topic 只定**哪一类必须能备份能迁移** |
| 会话级沙箱的数据持久化 | **本版刻意不做**，见 design.md §6.3 |
| 租户级沙箱内多个 agent 的协调与互斥 | 互相影响是共享空间的固有性质，本版不引入协调机制 |
| 宿主机本身怎么部署、怎么运维 | 归部署那一侧 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
