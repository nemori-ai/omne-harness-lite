# PF-005 故事卡

**已发到**：ST-005-05

顺序已由产品负责人确认，见[拍板记录](decisions.md#2026-10-03--故事卡验收补充与交付顺序确认)。先在明确获准的宿主机执行，再核对设施供给、拒绝结果，以及逐次、逐工具采用输入的边界；与工具卡的穿插先后按同次记录执行。

演示使用执行仓库的模型调用示例（`examples/model-invocation-minimal-demo`）集成独立工具运行时后的程序化入口。产品负责人观察公开调用结果、当次采用的合法环境输入和工具实际作用的文件。当前环境实现只有宿主机，隔离后端留后续；不以完整会话界面或具体元工具实现为前置。

卡片只规定操作与可见结果，不指定环境协议的技术形状、输入刷新方式或装载机制。宿主机与隔离环境仍属同一执行环境抽象；本批拒绝分支不冒充跨隔离环境的成功切换。

### ST-005-01 · 没装沙箱也能在明确获准的宿主机上执行工具

- **价值**：部署使用者可以先在自己的机器上使用工具，不必为了第一次执行安装沙箱。
- **覆盖场景**：[S2](acceptance.md#落点是每次执行算出来的)
- **演示**：
  1. 启动未装任何沙箱实现的程序化演示，给本次命令工具明确允许宿主机的执行环境权限 → 演示列出的执行环境只有宿主机。
  2. 通过公开能力读取宿主机提供的设施 → 返回它声明的设施清单，其中包含本次工具需要的命令行设施。
  3. 通过独立工具能力在指定的演示目录写入一份带约定文字的文件 → 调用成功，产品负责人打开该文件能看到约定文字；本次执行落点为宿主机。
- **不含**：沙箱实现、会话执行环境策略、工作区目录访问与 hooks 子进程。
- **前置**：无
- **就绪**：是

### ST-005-05 · 查得到当前宿主机声明的设施

- **价值**：装配工具的人能查清当前环境能提供什么，不必靠环境名称猜测。
- **覆盖场景**：[S33](acceptance.md#设施)
- **演示**：
  1. 启动只有宿主机环境实现的程序化演示 → 公开输出列出当前可用的执行环境为宿主机。
  2. 通过公开能力询问宿主机提供的设施 → 返回它声明的设施清单，负责人能逐项读出。
  3. 对照本次演示工具声明的命令行设施要求与该清单 → 能从声明中确认宿主机提供这项设施，不需要依据名字推断。
- **不含**：隔离实现、固定设施总表，以及宿主机与另一实现的统一声明方式比较。
- **前置**：无
- **就绪**：是

### ST-005-02 · 必须隔离的工具在没有合适环境时明确拒绝执行

- **价值**：调用者知道这次操作为什么没有执行，不会在要求隔离时意外改动自己的机器。
- **覆盖场景**：[S22](acceptance.md#隔离与授权)、[S28](acceptance.md#执行环境权限)、[S29](acceptance.md#执行环境权限)
- **演示**：
  1. 在未装任何沙箱实现的程序化演示中，准备一个需要命令行设施的写文件工具，并明确设置禁止宿主机的执行环境权限 → 演示显示该工具需要命令行设施、禁止在宿主机执行，当前没有提供命令行设施的隔离环境。
  2. 通过独立工具能力请求它在指定的演示目录创建文件 → 调用被拒，结果明确说明缺少提供命令行设施的隔离环境。
  3. 检查指定目录和本次公开调用结果 → 文件没有产生，调用未转到宿主机执行，也未报告成功。
- **不含**：已匹配沙箱创建失败、沙箱中的成功执行、自动选择策略的其他分支。
- **前置**：无
- **就绪**：是

### ST-005-03 · 环境输入变更只影响同一工具之后的调用

- **价值**：调用者能收紧后续执行的落点要求，同时清楚已经发出的工作仍沿原输入完成。
- **覆盖场景**：[S43](acceptance.md#独立工具的环境输入)
- **演示**：
  1. 在只有宿主机实现的演示中，为需要命令行设施的写文件工具合法采用明确允许宿主机的输入，发起一项尚未完成的调用 → 公开进展显示原调用已在宿主机开始，采用依据是这份输入。
  2. 在下一次调用前，合法采用禁止宿主机的新输入；仍用同一工具名和调用方式请求写另一份文件 → 新调用明确拒绝，指出缺少提供命令行设施的隔离环境，新文件没有产生。
  3. 让先前已经发出的调用完成 → 它仍在宿主机按原输入成功，原目标文件内容正确；没有因新输入改写或重发这项工作。
- **不含**：隔离环境中的成功执行、自动刷新时机、完整会话策略恢复，以及用两个宿主机目录冒充两个执行环境。
- **前置**：ST-005-01、ST-005-02
- **就绪**：是

### ST-005-04 · 三个工具同时按各自的环境权限执行

- **价值**：调用者能对不同工具采取不同落点要求，一个工具的权限不会把其他工具一起改变。
- **覆盖场景**：[S3](acceptance.md#落点是每次执行算出来的)
- **演示**：
  1. 在只有宿主机实现的演示中，准备三个需要命令行设施的普通工具，分别合法采用 always-allow、auto_place、never-allow；本次自动决策采用已明确允许宿主机的合法输入 → 负责人能同时读到三个各自的权限与采用依据。
  2. 分别调用三个工具 → 前两个各自在宿主机成功，第三个因没有匹配隔离环境明确拒绝；公开结果各自对应本工具的输入。
  3. 只把第一个工具的下一次合法输入改成 never-allow，再调用三个工具 → 第一个改为拒绝，第二个仍按自己的输入在宿主机成功，第三个仍拒绝；不存在统一覆盖三者的全局取值。
- **不含**：Shell、Computer、Browser 的具体实现，自动决策的默认政策、隔离实现和三种不同隔离落点。
- **前置**：ST-005-01、ST-005-02
- **就绪**：是
