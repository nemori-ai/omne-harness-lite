# MCP产品设计

状态：产品设计草案，revision 8。尚无整体接受证据。落位不授予运行支持。技术承接从[包组规格](../../../../packages/mcp/SPEC.md)展开。

## 产品需求描述

MCP 让获准使用一个外部接入点的人和 agent 发现并使用对端动作。[MCP 接入点](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-mcp--mcp--mcp)是一个在本系统之外运行的 MCP 服务，加上怎样连到它。接入点的 name 是资产身份，连接参数、凭据和动作清单不是身份。一个接入点在工具入口里是一个[工具条目](../../ubiquitous_language/terms/reach-and-availability.md#ul-tool-entry--工具条目--tool-entry)：一个多命令工具，对端的每个动作是它的一个命令，随接入点持有、配置及授权。动作没有自己的资产持有，MCP 本身也不是一个可调用动作。接入不改变组织锁定、租户边界或工具的实际执行责任。

MCP 只按地址接入。系统按登记的地址与对端通信，只看这个地址通不通、对端可不可用，不替用户把一个命令起成 MCP 服务。本机上长驻的 MCP 服务同样是系统之外的服务，由用户在系统之外运行，再登记它的地址。以后要支持命令型，从 Cordis 动态装配的角度另行设计，不经执行环境。

使用者应能分清“我合法知道这个动作”“对端现在提供它”“此刻准许调用它”以及“原调用实际产生什么效果”。对端增删动作是正常变化。已知身份保留，新动作由当前合法发现取得，离线不能凭猜测生成 schema。

动作经工具入口到 agent 手上。MCP 向工具入口登记一个[工具条目来源](../../ubiquitous_language/terms/reach-and-availability.md#ul-tool-entry-source--工具条目来源--tool-entry-source)，按这个主体此刻的事实交出条目。条目能不能被搜到、被调用，取决于接入点此刻合法可用、连接上有当前清单。条目是视图，不是登记进工具入口的工具。清单变了，下一次搜索就不同，不经装配。调一个动作就是一次工具调用，受理、结果保管、等待与取消归 [Tool](../tool-execution/design.md)，许不许由 agent 发起时的[放行判断](../meta-capabilities/design.md#动作放行与环境准入)判，MCP 是这次调用背后向对端发请求的一方。对端给的结构化结果是这次调用的返回值，内容块是给模型看的投影，两样都保留。

动作一般不常驻，agent 经 `Tools` 搜索、查看用法和调用。例外是标了常驻的接入点。常驻标记标在引用这个接入点的那一条上，不按动作逐个标。这样的接入点在采用点成为一条常驻工具，命令是它此刻的动作，进入工具声明，适用[常驻工具的规则](../tool-execution/design.md#resident-tools)。会话里这条声明不再变：对端之后加的动作，这个会话里调不到；撤了或改了参数的动作，调用时说明不可用，同一接入点的其余动作照常。采用时接入点此刻用不了，会话照开，这个会话里它不常驻，经 `Tools` 照常可用。Skill 需要对端在场时声明外部服务，不按资产能力标识组合或依赖某个 MCP 动作。

接入点持有及配值沿资产规则。身份和落点设置不从工作区取得，同名实现替换不继承原实现的连接目标或凭据，身份上的权限界仍约束替换件。工作区能提供接入点材料和允许的偏好，不自授权限，工作区来源的动作按既有最严规则逐次询问。兼容来源只在获准开启和支持范围内读取，源文件保留，不导入第三方整体权限或家目录配置。这些是候选能力的业务条件，版本范围的选择不能将它们删掉。

每个接入点有一项权限，「调用这个接入点的动作」，取值禁止、询问、自动，缺省询问。这项权限由 MCP 类别在资产里声明。权限按接入点一项，不按动作一项，因为动作不是资产，随对端变化。授权的动作规则可以按来源匹配，来源是接入点的能力标识（类别加名字），一条这样的规则管这个接入点的全部条目。新登记的接入点保持缺省值时，它的每个动作在调用时都按询问处理，直到有资格的人把这一项设为自动。

认证是接入点上的事。需要鉴权的接入点使用该租户持有的 MCP 凭据。合资格的人在登记接入点或对它点「连接」时完成认证，方式是提供静态值或完成 OAuth。OAuth 是取得同一项凭据的方式。agent 不在会话里向用户发起认证，Run 或工具等待也不自动发起取值，不以决策卡代替配值资格。凭据交给秘密保管，只给连接使用。同一个人在两个租户下分别取得凭据；组织接入点不下发一个跨租户共用账号，工作区也不取得该值。续期只维持同一对端账号，换账号属于配值变更。禁用持有不删除凭据，移除持有按秘密拥有者的生灭契约处理。凭据值不进入模型、普通 Context、人机呈现、日志或诊断，获准连接适配只取得本次用途必要的秘密使用能力。

凭据出了问题时，人要看得出该做什么。对端拒绝了出示的凭据时，接入点的状态写明「凭据被拒」，它与「还没有提供凭据」和「对端要求认证」是三种不同的状态。经 OAuth 取得的凭据到期时由系统续上。对端明确拒绝续期，或要求更大的范围时，状态写明「要重新连接」，由人再点一次「连接」。续期的结果不知道时，系统不删已有的凭据，也不要求人重新连接。

连接建立、合法清单采用、放行判断、真实发起及结果消费分别确认。连接超时与调用超时独立，连接可恢复不表示原调用没有发生。动作走 Tool 的受理、等待、前后台、停止与结果契约。MCP 不经执行环境启动本机进程，对端服务的运行与回收不归本系统。远端资源的实际能力按提供者声明，不假装由本机环境迁移或回收。

协议里除了动作还有别的能力。本项目采用其中两样：对端声明的事件（J-MC09）与对端带来的技能（J-MC10）。别的非动作能力没有采用：把对端的资源与提示词交给 agent、界面扩展、文件扩展、由对端回调本系统的事件投递。它们不宣布开放，也不永久排除。MCP 协议 SDK 不等于完整 Harness SDK，不携带服务端秘密、共享连接或执行闭包。

### J-MC01 采用接入点并取得合法连接条件

目标是让操作者接上一个明确来源的接入点。前提是接入点候选读取、持有、配值和使用资格分别成立。操作者登记接入点的地址，取得完整且匹配的定义、实现与设置，按用途配置凭据，需要认证时在登记或点「连接」时完成。连接提供者核验对端身份后发布可解释的连接状态。初次没有合法清单时只说明尚未发现，不编造动作。

来源格式错误、权限拒绝、凭据缺失或失效、地址不可达都明确报告。存在但非法的来源不当作空来源。部分建立的连接由取得者收口。取消准备与是否已建立连接分开，确认丢失时查原准备，不能为制造成功而重复建立连接。能力为 CAP-MC01、CAP-MC02、CAP-MC03。

### J-MC02 发现合法动作并理解不可用

目标是让 agent 从合法清单发现一个有来源的动作。前提是当前接入点采用、主体资格及发现条件可验证。合法发现返回动作身份、定义版本、接入点关联和可用性依据。一个接入点是工具入口里的一个工具条目，它的动作是这个工具的命令。agent 用 `Tools` 搜到的是接入点，看到它有哪些动作，每个动作一行；要用哪个动作，才取那一个动作的完整用法，再调用它。权限仍是每个接入点一项。条目按这个主体此刻的事实现算，对端新动作经合法发现取得后，已有会话的下一次搜索就能看到，不经装配。

断线、撤权、禁用或必需依赖缺席时，不可用在接入点这一级说明：接入点连同原因仍然看得到，它的动作不再作为条目出现，也不能继续读取撤权后的新定义。对端不再提供某个动作时，这个动作从清单里消失。`0.0.0 → 0.1.0` 阶段不为每个不常驻的动作保留最近合法形状与替换件，依据是产品负责人 PanQiWei 2026-11-12 的裁定。常驻接入点的动作是常驻工具，仍按[常驻工具的规则](../tool-execution/design.md#resident-tools)以同形替换件保留。从未合法取得的动作不呈现。模型调用一个此刻不在清单里的动作，或调用常驻动作的替换件，属于 dummy tool execution，真实原工具没有物理执行；返回不可用结果而非伪造成功，替换件自身真实开销按事实记录。发现与刷新失败不伪装空清单。能力为 CAP-MC04、CAP-MC10。

接入点的动作缺省不能被 agent 写的程序调用。接入点的持有者可以在这个接入点的设置里许可它，人和 agent 都按设置的规则管理这一项；许可只决定调用方式，程序里对动作的每次调用仍各自过放行判断。规则见[可编程调用许可](../tool-execution/design.md#可编程调用许可)。

### J-MC03 刷新后续采用且保护原调用

目标是使用对端新清单或合法更新的接入点设置。装配、每次搜索、每次执行尝试开始及必需提供者变化时重新求值，显式合法刷新也能更新后续采用，不必为注册表内部数据变化重建 Agent runtime。来源及权限变化分别处理；撤权在下一次使用边界生效，不等清单刷新。

候选校验及完整采用成立后，后续调用使用新定义；已发调用固定原输入、凭据账号关联、实现、工作及消费位置。旧的未发建议遇到调用约定或绑定变化，回给 agent 重新判断，不能暗改参数发出。失败保持原采用事实，不延续撤权，也不发布半新半旧材料。迟到刷新不能覆盖较新选择或重新开启已撤接入点。真正捕获的入口或结构变化由装配拥有者安全交接，原调用和迟到结果留在原工作。

对端声明它会通知清单变化时，系统在连接上订这项通知。收到通知，系统做一次与显式刷新相同的取得与采用，人不必点刷新。对端不声明时，清单照旧按时限与显式刷新更新。服务重启之后，最近一次合法取得的清单还在，带着它取得时的新鲜度。留着的清单不构成使用资格：每次使用照常核采用与资格。能力为 CAP-MC05。

### J-MC04 发起一个 MCP 动作

目标是获得一次明确动作的工具结果。调一个动作就是一次工具调用。会话或独立调用者提供原主体、租户、目标、参数及结果/控制责任，这个接入点的调用权限在 agent 发起时由放行判断判，放行后 Tool 受理并采用匹配定义与实现；实际发起前核当前工作资格与资源条件，不再判许不许。需要人的准入不越过明确禁止，也不假造超时默认答复。

对端在调用中途要求补充输入时，问的是人。原工具调用在工具内等人决定，复用[工具内部等待](../tool-execution/design.md#工具内部等待与人的答复)的原语与人工介入的卡片，不另做一套。这个等待没有超时，也不默认答复。人答了，答复交回对端，原调用继续。人拒绝或明确不回答时，把相应的答复告诉对端。卡片上对端写的字标明是外部内容，并写明是哪个接入点在问。人的答复只交回提问的那一次调用。

对端把一次动作做成长任务时，这仍是同一次工具调用。调用等到对端任务的终态，终态的结果就是这次调用的结果。agent 可以按 Tool 的规则把这次等待转到后台。服务重启之后，系统凭对端给的任务标识接着等，不重新发起动作。任务过期或对端查不到它时，结论是过期或未知，不写成完成或失败。任务中途要人补充输入时，照上一段问人。

调用取得原调用身份与原消费位置后，由实际提供者执行。参数不合法不执行原动作；无法满足必需环境不静默换落点。成功、失败、不可用、中断或效果未知各给出真实含义；协议错误保留原因及已知效果。转后台只改变等待关系，仍是同一次执行。结果附件及全文沿 Tool 和 Context 的读取、保留与模态契约，不把清单、过程帧或执行账当最终结果。能力为 CAP-MC06、CAP-MC07。

### J-MC05 控制原调用并完成会话归档

目标是停止等待或请求停止一个原调用，知道控制实际做到哪里。前提是原调用可定位且本次控制具有资格。控制沿 Tool 传播至相应请求、流、订阅或进程，说明未发起可阻止、已发起合作停止、实际完成、失败或未知的范围；协议不支持某种停止时明确限制。

会话归档在业务上取消未完成调用并解除推进等待，不等待所有远端物理停止。迟到结果不能恢复该 Session 的推进，撤销归档也不自动恢复旧调用。执行拥有者仍承接原效果、费用、必要历史和实际资源收场；当前无权披露时保存事实并限制交付。关闭客户端、Agent runtime 实例换代（同一 Session 的 Agent Definition 标识不变）或最后句柄释放不自动取消，控制请求不证明物理停止，取消不回滚外部效果，也不必关闭整个共享连接。能力为 CAP-MC07、CAP-MC08。

### J-MC06 断线后恢复连接和原工作

目标是在失联后继续可确认的责任。连接提供者按合法当前条件恢复连接并重新发现；新连接及新清单服务后续合法调用，不能借重连重发原动作。原调用协调者按原身份查询、等待或对账，区分查询暂不可用、真实执行连续性丢失、已取得结果及消费尚未完成。

只丢失 Agent runtime 时认回原执行；确认执行连续性丢失沿 Tool 失败规则收束。超时、断线、答复丢失不证明未执行；证据不足保留未知及下一责任。只有原协议有已采用且可验证的安全接续依据，才接续未完成步骤，不普设自动重试。成员资格失效不销毁租户或调用事实、不冻结业务状态；未来读取、调用和披露仍核验当前资格。能力为 CAP-MC08。

### J-MC07 独立程序消费 MCP 接入能力

目标是让合法程序使用选定的接入点、连接、发现或动作能力，无须构造 Agent Loop 或完整会话界面。程序显式给出身份、用途、控制与结果消费者，操作只要求其实际依赖；实际动作仍经 Tool 责任，不借协议 SDK 获得服务端凭据。

缺必需客户端能力或授权时明确拒绝相关操作，可选协议能力不受支持时如实说明，不使整个动作域失效。程序退出前保留或可靠交接已接纳工作及未消费结果，退出不证明原动作未发生。未来公开类型和成员边界由技术拥有者设计，本文不造包名。能力为 CAP-MC09。

### J-MC08 查询状态而不泄露秘密

目标是让有资格的人或程序解释接入点、当前清单与原调用状态。读面分别给出来源、新鲜度、连接状态、最近合法清单、不可用原因、实际控制/效果和下一责任；“查询不可用”与“确实不存在”分开。人机呈现保持同一业务含义，不能以采样诊断代替必要调用事实。

查询核验当前披露资格，历史保存不授予永久读取权。凭据只能显示有无、合法归属和必要取得元信息，不能从错误、URL、参数、协议自报、附件或原命令标注旁路泄露。读面不重做连接创建或动作，不以旧投影重判授权。能力为 CAP-MC10。

### J-MC09 订阅并接收对端的事件

目标是让对端发生的事进到本系统里，断了接得上，不重复。前提是接入点合法可用，对端声明了它会发生哪几类事。[MCP 事件类型](../../ubiquitous_language/terms/reach-and-availability.md#ul-mcp-event-type--mcp-事件类型--mcp-event-type)是对端声明的一类事件：类型名、说明、订阅参数的形状与内容的形状。有资格使用这个接入点的人读得到它的事件类型。

系统向对端要一类事件时，建立一条 [MCP 事件订阅](../../ubiquitous_language/terms/reach-and-availability.md#ul-mcp-event-subscription--mcp-事件订阅--mcp-event-subscription)。订阅的正本在本系统。重启或断线之后，系统带着已经收到的位置接着收。同一条事件在一条订阅里只留一次，交给消费者时带着它的标识。对端说中间漏了，或终止了订阅，系统记下并报出来，不装作连续。对端因为拒绝而终止的订阅，系统不自己重订，由订它的一方决定要不要再订。没有订阅者的事件类型，系统不向对端订。对端只肯用回调投递的事件类型订不了，原因写明。

谁要这类事件、给谁、多急、要不要叫醒一个会话，是[通知](../notifications/design.md)的订阅与投递，人和 agent 都经它表达，不归本领域。本领域做到把事件连同标识交给消费者为止。有资格使用这个接入点的人还可以直接查看一类事件，用来核对对端确实在发。事件的内容是外部数据。收到事件不带来任何权限，也不直接让 agent 做事。能力为 CAP-MC11。

### J-MC10 发现并读取随连接来的技能

目标是让 agent 用上对端自己带的工作方法。前提是接入点合法可用，对端声明了它带技能。[MCP 技能](../../ubiquitous_language/terms/reach-and-availability.md#ul-mcp-skill--mcp-技能--mcp-skill)是对端经连接提供的一个技能：名称、说明、`SKILL.md` 正文和一份文件清单。它不是 Skill 资产。它没有自己的持有、版本与发布，随接入点的持有、配置与授权一起来去。

MCP 向 `Skills` 入口登记一个[技能条目来源](../../ubiquitous_language/terms/reach-and-availability.md#ul-skill-entry-source--技能条目来源--skill-entry-source)。agent 在 `Skills` 里搜得到、读得到 MCP 技能，三层披露照旧。每一条写明来自哪个接入点。它的名字带接入点的前缀，所以它不会顶替同名的官方、租户或工作区 Skill。接入点不可用时，它的技能连同原因一起不可用。MCP 技能不是资产，Agent 定义引用不到它，所以它不常驻。

MCP 技能的内容是外部内容，交给模型时标明，并写明来源。它声明的工具许可不生效。它里面的指令不授予身份、权限或系统决策权。它没有本机目录，文件只按清单里列的路径经 `Skills` 读。系统在交出一个文件之前核对它的大小与摘要，对不上就不交出，并说明来源的内容变了。能力为 CAP-MC12。

## 能力定义

| 稳定能力 | 完整能力与适用条件 | 正文位置 |
| --- | --- | --- |
| CAP-MC01 接入点定义与采用 | 按资产身份、完整来源和当前资格读取并采用；只按地址接入，不替用户起命令型服务；工作区/兼容来源不自授权，不跨实现继承专有设置 | J-MC01、J-MC03 |
| CAP-MC02 租户凭据供给 | 获准配值人在登记接入点或点「连接」时提供静态或 OAuth 凭据，agent 不在会话里发起认证；按持有隔离、生灭及同账号续期；凭据被拒与要重新连接各有可辨的状态，续期结果不知道时不删凭据；秘密不呈现 | 产品需求描述、J-MC01 |
| CAP-MC03 合法连接及资源收场 | 核验对端地址与资格；连接时限独立于调用，准备失败/未知及退出有归属 | J-MC01、J-MC06 |
| CAP-MC04 合法发现与不可用条目 | 经工具条目来源把一个接入点交成一个工具条目，它的动作是这个工具的命令：agent 搜到接入点，看到动作各一行，用哪个动作才取那一个的完整用法；条目按当下事实现算；动作一般不常驻，标了常驻的接入点在采用点成为一条常驻工具，命令是它此刻的动作；不可用在接入点这一级说明，不常驻的动作不逐个保留替换件，常驻的接入点按常驻工具的规则保留；从未合法发现不造定义 | J-MC02 |
| CAP-MC05 清单与采用更新 | 搜索、开始尝试/提供者变化重算，合法显式刷新只改后续采用；对端通知清单变化时系统自己取得并采用；重启后最近合法清单还在，但不构成使用资格；撤权即时、迟到不覆盖、原输入不变 | J-MC03 |
| CAP-MC06 经 Tool 发起动作 | 调一个动作是一次工具调用；接入点一项调用权限（缺省询问）由放行判断在发起时判，Tool 受理后匹配定义/实现/参数/资源；对端要求补充输入时经工具内等待问人；对端的长任务是同一次调用，等到终态，重启后凭任务标识接着等；会话与独立调用均保留原身份 | J-MC04 |
| CAP-MC07 原结果、控制和可靠承接 | 结果/效果/执行账/消费分责，控制不冒充物理停止，确认前可靠保存不可重建事实 | J-MC04、J-MC05 |
| CAP-MC08 失联、归档及恢复 | 原身份查询和接续；未知不当未发生、不盲目重发，归档后仍保管效果和费用 | J-MC05、J-MC06 |
| CAP-MC09 独立程序消费 | 无完整会话/Loop 仍可消费已选择能力，显式身份/消费者/控制责任；SDK 不携带服务端秘密 | J-MC07 |
| CAP-MC10 有资格的解释与观察 | 查询各自权威及新鲜度，区分未知与不存在，人机说明一致且不传播秘密 | J-MC02、J-MC08 |
| CAP-MC11 事件类型与事件订阅 | 读得到对端声明的事件类型；订阅的正本在本系统，带着位置接续，同一事件只留一次；漏了与被终止照实报；没有订阅者不订；事件内容是外部数据，给谁与多急归通知 | J-MC09 |
| CAP-MC12 随连接来的技能 | 经技能条目来源进 `Skills` 入口，带来源与前缀，不顶替同名 Skill，不常驻；内容是外部内容，工具许可不生效，没有本机目录；交出文件前核大小与摘要 | J-MC10 |

## 未决问题与待定事项

本章拥有产品与阶段未决；技术与来源事项导航到实际技术责任。成员尚未具名，完整行为候选仍留原任务 contracts，由组维护承接缺项，不创建成员或组根统一 SPEC。既定用户决定不复活为问题。

### Q-MC02 成员与公开身份/操作形状的技术归属

分类：技术义务。两个接入点可能提供同名动作，连接与调用有不同代际，未来消费者需要可靠引用和操作入口。

产品影响：影响接口消费和实现切片；不阻塞负责人选择 CAP。

维护责任：MCP 公开定义与工程成员技术拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#总体架构)。

### Q-MC03 客户端、认证、清单一致采用及配置机制

分类：技术义务。OAuth 续期、连接准备及 A/B 刷新同时发生，过期响应可能覆盖新采用或把账号关联混给另一租户。

产品影响：连接与刷新实施前须完成技术采用和符合性证据。

维护责任：客户端、秘密、认证与清单采用协调拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#应然设计)。

### Q-MC04 原调用、dummy、可靠结果和恢复的组合协议

分类：技术义务。远端已生效但本地登记或答复丢失；归档后迟到结果必须有归属，恢复不得重发。

产品影响：涉及 CAP-MC06–08 的技术兑现，不将机制缺项降为整域产品待定。

维护责任：原 Tool 调用、原工作及结果消费者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#调用)。

### Q-MC05 非动作桥接的客户端采用范围

分类：技术义务。事件与技能已经采用（J-MC09、J-MC10）。把对端的资源与提示词交给 agent、界面扩展、文件扩展与由对端回调的事件投递没有采用。直接宣称支持全部 MCP 协议会误导消费者。

产品影响：只影响没有采用的那几样，不暂停已定的动作、事件与技能。

维护责任：具体客户端及非动作桥接拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#动作到-agent-手上)。

### Q-MC06 持续验证与真实部署前提

分类：技术义务。图和结构能通过，但连接混租户、清理误关他方或断电丢失原调用关联仍可能发生。

产品影响：技术采用和实现接受的义务，不把本次文档检查写成行为接受。

维护责任：各实际提供者、组合验证与部署拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#不变式)。

本域没有新增的产品政策待裁。技术义务不转为产品投票；其他拥有者的政策沿唯一产品位置接续。
