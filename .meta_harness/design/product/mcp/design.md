# MCP产品设计

状态：产品设计草案，revision 3。尚无整体接受证据。能力状态、阶段与明确决定各保留自身依据，落位不授予运行支持。技术承接从[包组规格](../../../../packages/mcp/SPEC.md)展开。

## 产品需求描述

MCP 让获准使用一个外部接入点的人和 agent 发现并使用对端动作。[MCP 接入点](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-mcp--mcp--mcp)是一个在本系统之外运行的 MCP 服务，加上怎样连到它。接入点的 name 是资产身份，连接参数、凭据和动作清单不是身份。对端的每个动作在工具入口里是一个[工具条目](../../ubiquitous_language/terms/reach-and-availability.md#ul-tool-entry--工具条目--tool-entry)，随接入点持有、配置及授权。动作没有自己的资产持有，MCP 本身也不是一个可调用动作。接入不改变组织锁定、租户边界或工具的实际执行责任。

MCP 只按地址接入。系统按登记的地址与对端通信，只看这个地址通不通、对端可不可用，不替用户把一个命令起成 MCP 服务。本机上长驻的 MCP 服务同样是系统之外的服务，由用户在系统之外运行，再登记它的地址。命令型（stdio）接入不在 `0.0.0 → 0.1.0` 阶段，这一阶段不为它写接入说明，也不为它留设施，依据是产品负责人 PanQiWei 2026-11-12 的裁定。以后要支持命令型，从 Cordis 动态装配的角度另行设计，不经执行环境。

使用者应能分清“我合法知道这个动作”“对端现在提供它”“此刻准许调用它”以及“原调用实际产生什么效果”。对端增删动作是正常变化。已知身份保留，新动作由当前合法发现取得，离线不能凭猜测生成 schema。

动作经工具入口到 agent 手上。MCP 向工具入口登记一个[工具条目来源](../../ubiquitous_language/terms/reach-and-availability.md#ul-tool-entry-source--工具条目来源--tool-entry-source)，按这个主体此刻的事实交出条目。条目能不能被搜到、被调用，取决于接入点此刻合法可用、连接上有当前清单。条目是视图，不是登记进工具入口的工具。清单变了，下一次搜索就不同，不经装配。调一个动作就是一次工具调用，准入、结果保管、等待与取消归 [Tool](../tool-execution/design.md)，MCP 是这次调用背后向对端发请求的一方。对端给的结构化结果是这次调用的返回值，内容块是给模型看的投影，两样都保留。

动作一般不常驻，agent 经 `Tools` 搜索、查看用法和调用。例外是标了常驻的接入点。常驻标记标在引用这个接入点的那一条上，不按动作逐个标。这样的接入点，它的动作在采用点成为常驻工具，进入工具声明，适用[常驻工具的规则](../tool-execution/design.md#resident-tools)。Skill 需要对端在场时声明外部服务，不按资产能力标识组合或依赖某个 MCP 动作。

接入点持有及配值沿资产规则。身份和落点设置不从工作区取得，同名实现替换不继承原实现的连接目标或凭据，身份上的权限界仍约束替换件。工作区能提供接入点材料和允许的偏好，不自授权限，工作区来源的动作按既有最严规则逐次询问。兼容来源只在获准开启和支持范围内读取，源文件保留，不导入第三方整体权限或家目录配置。这些是候选能力的业务条件，阶段选择不能将它们删掉。

每个接入点有一项权限，「调用这个接入点的动作」，取值禁止、询问、自动，缺省询问。这项权限由 MCP 类别在资产里声明。权限按接入点一项，不按动作一项，因为动作不是资产，随对端变化。授权的动作规则可以按来源匹配，来源是接入点的能力标识（类别加名字），一条这样的规则管这个接入点的全部条目。新登记的接入点保持缺省值时，它的每个动作在调用时都按询问处理，直到有资格的人把这一项设为自动。

认证是接入点上的事。需要鉴权的接入点使用该租户持有的 MCP 凭据。合资格的人在登记接入点或对它点「连接」时完成认证，方式是提供静态值或完成 OAuth。OAuth 是取得同一项凭据的方式。agent 不在会话里向用户发起认证，Run 或工具等待也不自动发起取值，不以决策卡代替配值资格。凭据交给秘密保管，只给连接使用。同一个人在两个租户下分别取得凭据；组织接入点不下发一个跨租户共用账号，工作区也不取得该值。续期只维持同一对端账号，换账号属于配值变更。禁用持有不删除凭据，移除持有按秘密拥有者的生灭契约处理。凭据值不进入模型、普通 Context、人机呈现、日志或诊断，获准连接适配只取得本次用途必要的秘密使用能力。

连接建立、合法清单采用、动作准入、真实发起及结果消费分别确认。连接超时与调用超时独立，连接可恢复不表示原调用没有发生。动作走 Tool 的当前准入、等待、前后台、停止与结果契约。MCP 不经执行环境启动本机进程，对端服务的运行与回收不归本系统。远端资源的实际能力按提供者声明，不假装由本机环境迁移或回收。

协议存在非动作能力。本项目具体桥接随获准采用客户端及其明确支持范围；该范围尚未闭合。本文完整定义动作接入的旅程，非动作桥接保留相应技术缺项，不宣布全部开放，也不将其永久排除。MCP 协议 SDK 不等于完整 Harness SDK，不携带服务端秘密、共享连接或执行闭包。

### J-MC01 采用接入点并取得合法连接条件

目标是让操作者接上一个明确来源的接入点。前提是接入点候选读取、持有、配值和使用资格分别成立。操作者登记接入点的地址，取得完整且匹配的定义、实现与设置，按用途配置凭据，需要认证时在登记或点「连接」时完成。连接提供者核验对端身份后发布可解释的连接状态。初次没有合法清单时只说明尚未发现，不编造动作。

来源格式错误、权限拒绝、凭据缺失或失效、地址不可达都明确报告。存在但非法的来源不当作空来源。部分建立的连接由取得者收口。取消准备与是否已建立连接分开，确认丢失时查原准备，不能为制造成功而重复建立连接。能力为 CAP-MC01、CAP-MC02、CAP-MC03。

### J-MC02 发现合法动作并理解不可用

目标是让 agent 从合法清单发现一个有来源的动作。前提是当前接入点采用、主体资格及发现条件可验证。合法发现返回动作身份、定义版本、接入点关联和可用性依据。每个动作是工具入口里的一个工具条目，经 `Tools` 搜索、查看用法与调用。条目按这个主体此刻的事实现算，对端新动作经合法发现取得后，已有会话的下一次搜索就能看到，不经装配。

断线、撤权、禁用或必需依赖缺席时，不可用在接入点这一级说明：接入点连同原因仍然看得到，它的动作不再作为条目出现，也不能继续读取撤权后的新定义。对端不再提供某个动作时，这个动作从清单里消失。`0.0.0 → 0.1.0` 阶段不为每个不常驻的动作保留最近合法形状与替换件，依据是产品负责人 PanQiWei 2026-11-12 的裁定。常驻接入点的动作是常驻工具，仍按[常驻工具的规则](../tool-execution/design.md#resident-tools)以同形替换件保留。从未合法取得的动作不呈现。模型调用一个此刻不在清单里的动作，或调用常驻动作的替换件，属于 dummy tool execution，真实原工具没有物理执行；返回不可用结果而非伪造成功，替换件自身真实开销按事实记录。发现与刷新失败不伪装空清单。能力为 CAP-MC04、CAP-MC10。

### J-MC03 刷新后续采用且保护原调用

目标是使用对端新清单或合法更新的接入点设置。装配、每次搜索、每次执行尝试开始及必需提供者变化时重新求值，显式合法刷新也能更新后续采用，不必为注册表内部数据变化重建 Agent runtime。来源及权限变化分别处理；撤权在下一次使用边界生效，不等清单刷新。

候选校验及完整采用成立后，后续调用使用新定义；已发调用固定原输入、凭据账号关联、实现、工作及消费位置。旧的未发建议遇到调用约定或绑定变化，回给 agent 重新判断，不能暗改参数发出。失败保持原采用事实，不延续撤权，也不发布半新半旧材料。迟到刷新不能覆盖较新选择或重新开启已撤接入点。真正捕获的入口或结构变化由装配拥有者安全交接，原调用和迟到结果留在原工作。能力为 CAP-MC05。

### J-MC04 发起一个 MCP 动作

目标是获得一次明确动作的工具结果。调一个动作就是一次工具调用。会话或独立调用者提供原主体、租户、目标、参数及结果/控制责任，经这个接入点的调用权限与本次调用的准入后采用匹配定义与实现；实际发起前复核当前工作、授权和资源条件，排队前批准不是永久许可。需要人的准入不越过明确禁止，也不假造超时默认答复。

对端在调用中途要求补充输入时，问的是人。原工具调用在工具内等人决定，复用[工具内部等待](../tool-execution/design.md#工具内部等待与人的答复)的原语与人工介入的卡片，不另做一套。这个等待没有超时，也不默认答复。人答了，答复交回对端，原调用继续。人拒绝或明确不回答时，把相应的答复告诉对端。

调用取得原调用身份与原消费位置后，由实际提供者执行。参数不合法不执行原动作；无法满足必需环境不静默换落点。成功、失败、不可用、中断或效果未知各给出真实含义；协议错误保留原因及已知效果。转后台只改变等待关系，仍是同一次执行。结果附件及全文沿 Tool 和 Context 的读取、保留与模态契约，不把清单、过程帧或执行账当最终结果。能力为 CAP-MC06、CAP-MC07。

### J-MC05 控制原调用并完成会话归档

目标是停止等待或请求停止一个原调用，知道控制实际做到哪里。前提是原调用可定位且本次控制具有资格。控制沿 Tool 传播至相应请求、流、订阅或进程，说明未发起可阻止、已发起合作停止、实际完成、失败或未知的范围；协议不支持某种停止时明确限制。

会话归档在业务上取消未完成调用并解除推进等待，不等待所有远端物理停止。迟到结果不能恢复该 Session 的推进，撤销归档也不自动恢复旧调用。执行拥有者仍承接原效果、费用、必要历史和实际资源收场；当前无权披露时保存事实并限制交付。关闭客户端、Agent runtime 实例换代（同一 Session 的 Agent Definition 标识不变）或最后句柄释放不自动取消，控制请求不证明物理停止，取消不回滚外部效果，也不必关闭整个共享连接。能力为 CAP-MC07、CAP-MC08。

### J-MC06 断线后恢复连接和原工作

目标是在失联后继续可确认的责任。连接提供者按合法当前条件恢复连接并重新发现；新连接及新清单服务后续合法调用，不能借重连重发原动作。原调用协调者按原身份查询、等待或对账，区分查询暂不可用、真实执行连续性丢失、已取得结果及消费尚未完成。

只丢失 Agent runtime 时认回原执行；确认执行连续性丢失沿 Tool 失败规则收束。超时、断线、答复丢失不证明未执行；证据不足保留未知及下一责任。只有原协议有已采用且可验证的安全接续依据，才接续未完成步骤，不普设自动重试。成员资格失效不销毁租户或调用事实、不冻结业务状态；未来读取、调用和披露仍核验当前资格。能力为 CAP-MC08。

### J-MC07 独立程序消费 MCP 接入能力

目标是让合法程序使用选定的接入点、连接、发现或动作能力，无须构造 Agent Loop 或完整会话界面。程序显式给出身份、用途、控制与结果消费者，操作只要求其实际依赖；实际动作仍经 Tool 责任，不借协议 SDK 获得服务端凭据。

缺必需客户端能力或授权时明确拒绝相关操作，可选协议能力不受支持时如实说明，不使整个动作域失效。程序退出前保留或可靠交接已接纳工作及未消费结果，退出不证明原动作未发生。未来公开类型和成员边界由技术拥有者设计，本文不造包名。能力为 CAP-MC09。

### J-MC08 查询状态而不泄露秘密

目标是让有资格的人或程序解释接入点、当前清单与原调用状态。读面分别给出来源、新鲜度、连接状态、最近合法清单、不可用原因、实际控制/效果和下一责任；“查询不可用”与“确实不存在”分开。人机呈现保持同一业务含义，不能以采样诊断代替必要调用事实。

查询核验当前披露资格，历史保存不授予永久读取权。凭据只能显示有无、合法归属和必要取得元信息，不能从错误、URL、参数、协议自报、附件或原命令标注旁路泄露。读面不重做连接创建或动作，不以旧投影重判授权。能力为 CAP-MC10。

## 阶段与版本支持承诺

产品负责人 PanQiWei 于 2026-11-11 确定：`0.0.0 → 0.1.0` 阶段纳入 CAP-MC01 至 CAP-MC10 全部十项能力。纳入范围以各项能力定义及其引用的需求为准，包含其中的条件、例外与失败后果。负责人保留按实际情况把个别能力移出本阶段的决定，移出时在本节写明。

产品负责人 PanQiWei 于 2026-11-12 确定了以下五条，十项能力的范围按本文现行规则理解。

1. MCP 只按地址接入。命令型（stdio）接入不在 `0.0.0 → 0.1.0` 阶段，以后从 Cordis 动态装配的角度另行设计，不经执行环境。
2. MCP 动作经工具入口到 agent 手上。除标了常驻的接入点之外，动作不常驻。
3. 对端要求补充输入时问人，复用工具内等人决定的原语与卡片。
4. 认证在接入点上，由人在登记或点「连接」时完成。OAuth 排在 4 号线的最后一程。
5. 失去资格后的呈现先只做到接入点这一级：说明这个接入点不可用及原因，不为每个不常驻的动作保留替换件。

工具条目来源的形状与接入点的一项调用权限，是设计会话据这些裁定定下的。

| 阶段或版本 | 能力 | 支持程度及范围 |
| --- | --- | --- |
| 0.0.0 → 0.1.0 | CAP-MC01 至 CAP-MC10，全部十项 | 按本文完整行为交付，覆盖按地址接入、发现、真实调用与独立程序消费；命令型接入不在本阶段 |

阶段承诺是交付目标，不表示实现、验证或交付已经完成。实现状态仍按第二块的证据记录。能力之间的依赖继续成立：CAP-MC03 依赖 CAP-MC01，需要鉴权时还依赖 CAP-MC02；CAP-MC04 依赖合法接入点与发现条件；CAP-MC05 依赖接入点采用及清单；CAP-MC06 消费 CAP-MC04 及 Tool 准入；CAP-MC07、CAP-MC08 承接原调用；CAP-MC09 消费对应操作；CAP-MC10 观察这些事实。真实调用须保留原身份、授权、可靠结果、控制及未知效果约束。

具体协议、SDK/provider、公开接口、精确版本、参数值及验证方案交技术采用。重连退避、连接/调用时限、并发、清单缓存、OAuth 续期和保留参数由合法配置表达；未知参数不授权削弱已有业务不变式。非动作桥接仅在相应明确契约及采用范围内支持，未闭合部分沿 Q-MC05 隔离。公开版本支持与实现观察仍须绑定真实证据。

## 未决问题与待定事项

本章拥有产品与阶段未决；技术与来源事项导航到实际技术责任。成员尚未具名，完整行为候选仍留原任务 contracts，由组维护承接缺项，不创建成员或组根统一 SPEC。既定用户决定不复活为问题。

### Q-MC02 成员与公开身份/操作形状的技术归属

分类：技术义务。两个接入点可能提供同名动作，连接与调用有不同代际，未来消费者需要可靠引用和操作入口。

产品影响：影响接口消费和实现切片；不阻塞负责人选择 CAP。

维护责任：MCP 公开定义与工程成员技术拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#总体架构)。

### Q-MC03 客户端、认证、清单一致采用及配置机制

分类：技术义务。OAuth 续期、连接准备及 A/B 刷新同时发生，过期响应可能覆盖新采用或把账号关联混给另一租户。

产品影响：连接与刷新实施前须完成技术采用和符合性证据。

维护责任：客户端、秘密、认证与清单采用协调拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#应然设计)。

### Q-MC04 原调用、dummy、可靠结果和恢复的组合协议

分类：技术义务。远端已生效但本地登记或答复丢失；归档后迟到结果必须有归属，恢复不得重发。

产品影响：涉及 CAP-MC06–08 的技术兑现，不将机制缺项降为整域产品待定。

维护责任：原 Tool 调用、原工作及结果消费者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#调用)。

### Q-MC05 非动作桥接的客户端采用范围

分类：技术义务。一个客户端只支持动作，另一个还支持非动作能力；直接宣称全 MCP 协议支持会误导消费者。

产品影响：仅影响对应非动作接入，不暂停已定动作链。

维护责任：具体客户端及非动作桥接拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#动作到-agent-手上)。

### Q-MC06 持续验证与真实部署前提

分类：技术义务。图和结构能通过，但连接混租户、清理误关他方或断电丢失原调用关联仍可能发生。

产品影响：技术采用和实现接受的义务，不把本次文档检查写成行为接受。

维护责任：各实际提供者、组合验证与部署拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/mcp/SPEC.md#不变式)。

本域没有新增的产品政策待裁。技术义务不转为产品投票；其他拥有者的政策沿唯一产品位置接续。
