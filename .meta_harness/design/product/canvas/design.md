# 画布产品设计

采用范围见[topic 入口](README.md)。项目要求取[项目要求](../../../../docs/requirements.md)。本文维护已确认的产品规则。拓展点、协议与存储等机制由技术拥有者说明。

## 产品需求描述

没有[画布](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-canvas--画布--canvas)时，人和 agent 只在对话里协作。双方关心的东西散在各处：一个会话在会话列表里，一张截图在某段历史里，agent 做出来的东西留在一段转写里，往后一翻就看不见了。人没有一个地方把自己在意的几样东西摆在眼前。agent 也没有一个地方把做好的、整理好的东西摆给人看。

画布解决这件事。它是人和 agent 共用的一张纸。双方都能把系统里已有的东西摆上去，挪动、改大小、叠成[一叠](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-canvas-pile--一叠--canvas-pile)、拿走、放回，用的是同一组操作。agent 还能做一个[画布小应用](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-canvas-app--画布小应用--canvas-app)摆上去。画布只记哪些东西摆在哪里，不保存那些东西本身。拿走一样东西，只是画布上不再摆它，那样东西照旧在原来的地方。

画布是接在核心上的一块。部署没有开放它时，应用只有[一面](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-application-face--应用的面--application-face)，其余各部分照常工作。

### 画布、画布项与一叠

每个[租户](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-tenant--租户--tenant)有一张画布，只有一张。画布有边，一开始是空的。画布的大小与网格的疏密由部署配置。

画布上的每一样是一个[画布项](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-canvas-item--画布项--canvas-item)。画布项指着别处的一个对象，例如一个[媒体对象](../../ubiquitous_language/terms/record-and-context.md#ul-media-object--媒体对象--media-object)或一个[会话](../../ubiquitous_language/terms/agent-runtime-loop.md#ul-session--会话--session)，并带着它的[摆法](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-canvas-arrangement--摆法--canvas-arrangement)：在哪里、多大、压在谁上面、在不在一叠里、锁没锁、最近是谁摆的。被指着的对象归拥有它的领域。画布不复制它的内容，也不判断它在不在、谁能看。

同一个对象在一张画布上至多有一个画布项。再摆一次已经摆着的对象，画布不变，也不挪它。再摆一次拿走过的对象，就是把它放回。

一叠是叠在一起的几个画布项。它有自己的位置，可以有名字，里面至少有一项。最后一项离开时，这一叠就没有了。画布项可以互相压着。压着不等于在一叠里：一叠只由「叠成一叠」这个操作产生。

摆法记在服务端。换一台设备、另开一个窗口，看到的是同一张画布，每一项都在原处。人拖动一个画布项时，跟着指针走的那一下只是预览。松手之后，屏幕上是服务端答复的样子。结果不知道时，那一项先显示「还没定」，随后按服务端现在的样子画出来，不写成成功，也不写成失败。

一个租户的画布，只有这个租户的人和在这个租户的会话里工作的 agent 能看、能改。别的租户读不到它，也改不了它。被拒绝时，对方得不到这张画布上有什么的任何线索。

### 应用的两面

画布是应用的反面。正面是[桌面应用](../desktop-application/design.md)的登录、会话、对话、资产、设置与用量所在的那一面。这台设备上第一次登录之后，露出的是正面。

人用下面几个入口翻面：

- 在哪一面都可以按 ⌘⇧O。
- 正面侧栏底部有一个墨记号，点它翻到反面。
- 反面角上有一个记号，点它翻回正面。
- 在反面右键点[形](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-agent-figure--agent-形--agent-figure)，也翻回正面。

在反面左键点形，应用翻回正面，到在正面点形时去的那一页：平时是最前面的那一页，有事等人回答时是「待你决定」。

导航里没有画布这一页，应用菜单里也没有翻面。

翻面时，形拿着纸边把这一面翻过去。翻面不让人等：翻到一半时点任何地方或再按一次，立刻停在要去的那一面。系统打开减弱动效时，直接换过去。

两面一直都在，翻面只换露在外面的那一面。翻过去再翻回来，各面停在原来的样子：正面还在原来那一页，输入框里没发出的字还在；画布还停在原来看着的那一块。收起的那一面不接指针，也不接键盘。

应用记住人最后翻到哪一面，下次登录之后露出的还是那一面。停在哪一面是这台设备上的[观感偏好](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-look-and-feel-preference--观感偏好--look-and-feel-preference)。

屏幕上仍然只有一个形。翻到反面，形去画布中间它的座位上。翻回正面，形回到[正面它该在的座位](../desktop-application/design.md#agent-在屏幕上的形)上。

人在反面要去正面的某一页时，例如点开画布上的一个会话，应用先翻回正面，再到那一页。

部署没有开放画布时，应用只有正面。侧栏底部没有那个墨记号，按 ⌘⇧O 不翻面。

### 人和 agent 用同一组操作

画布给人和 agent 同一组操作：

| 操作 | 做什么 |
| --- | --- |
| 看 | 读画布现在的样子：摆着哪些画布项，各在哪、多大，每一叠里有哪些 |
| 看拿走过的 | 列出拿走过的画布项，最近拿走的在前 |
| 看能摆哪几类 | 列出现在[可画布渲染](../../ubiquitous_language/terms/reach-and-availability.md#ul-canvas-renderable--可画布渲染--canvas-renderable)的种类：每一类的叫法、一句说明，以及怎样指明这一类里的一个对象 |
| 摆上 | 把一个对象摆到画布上。摆上拿走过的对象，就是放回 |
| 整理 | 挪、改大小、放到最上面、放进一叠、从一叠里拿出来、挪一叠、给一叠改名 |
| 叠成一叠 | 把几个画布项叠成新的一叠，或叠进已有的一叠 |
| 散开 | 把一叠散开 |
| 拿走 | 把一个或几个画布项从画布上拿走 |
| 锁上、解开 | 锁住一个画布项，或解开它 |

一次操作的结果只取决于三样：是什么操作、带了什么、画布现在是什么样。做的是人还是 agent，不改变结果。

每一次改动都记下是谁做的：人，或者某个会话里的 agent。每个画布项上看得到最近是谁摆的，也就是最近一次动它摆法的是谁。是 agent 时，写明是哪个会话。这是来历，不是权限。人摆的画布项 agent 照样能挪，agent 摆的人也照样能挪。人要让一个画布项不被 agent 动，就[锁住](#锁定)它。

许不许按系统已有的规则判，人和 agent 各在一处：

- 人的操作按人登录的租户判。人对自己租户的画布可以做全部操作。
- agent 的操作在它发起时由[动作放行](../meta-capabilities/design.md#动作放行与环境准入)判一次。画布的操作归三项权限。「看」包括看、看拿走过的、看能摆哪几类，缺省自动。「摆」包括摆上、整理、叠成一叠、散开、拿走，缺省自动。「锁」包括锁上与解开，缺省禁止。租户可以改这三项。

人和 agent 同时改同一个画布项时，后到的那一次生效。先到的那一次被盖掉，界面不另外提示。人和 agent 看到的始终是服务端现在的样子。

一次整理、拿走或叠成一叠可以同时涉及几个画布项。这几项要么全部照做，要么一项都不做。有一项找不到或现状不允许时，整次不做，答复写明是哪一项、为什么。

操作没有照做时，答复分成下面几种，彼此不混：

- 请求不合规则，例如位置出了画布、大小超出上下限：写明是哪一处。
- 无权对这个租户的画布操作：拒绝。
- 判定要用的东西此刻读不到：这一次没有做，可以再来。
- 现状不允许：写明原因，例如画布项锁着、画布摆满了、这一类没有声明、拥有者没有接受这个对象。
- 结果不知道：照实说不知道。再看一次画布，就知道它做成了没有。同一个操作再做一次也安全，结果相同。

### 摆上去，落在哪

摆上时可以给一个位置，可以只说放在哪附近，也可以都不给：

- 给了位置，就摆在那里。
- 只说了附近，就摆在离那里最近的空处。
- 都没给，就摆在画布中间形的座位旁边的空处。

人的放法对应前两种。人把文件拖进来时，松手处就是位置。一次拖进几样，它们在松手处略微散开。人从[查找](#查找)里挑一个对象时，它摆在打开查找的地方附近的空处。

找空处时，按画布项摆上以后占的地方算，连同写在它下面的字。附近没有空处时，画布项落在要的那一点上，压着别的画布项。压着是允许的，后来的在上面。

刚摆上的画布项大小由它那一类的画法定，像一张明信片那么大。人或 agent 改过大小之后，用改过的大小。

一张画布上摆着的画布项有上限，由部署配置。拿走过的不算在内。到了上限再摆，答复说「摆满了」，画布不变。部署把上限改小时，已经摆着的画布项一项也不被拿走。摆着的降到新的上限以下之前，摆不上新的。

摆上之前，画布先确认这一类此刻可画布渲染。这一类的拥有者还可以要求先核一下这个对象，并为画布留住它。拥有者不接受时，这一次不摆。答复只说拥有者没有接受，不说是不存在、不归这个租户，还是不许看。

### 挪、改大小与磁吸

人拖动一个画布项，它跟着指针走，松手处就是它的新位置。拖它的四个角改大小。画布项拖不出画布的边，大小有上下限。人也可以把一个画布项放到最上面。在一叠里的画布项不单独挪：要挪它，先把它从一叠里拿出来。

磁吸是这台设备上的一个开关，缺省开着。磁吸开着时，人拖动或改大小之后松手，位置与大小落到画布的网格上。磁吸关着时，松手在哪就是哪。磁吸只影响人这一次手势的结果：打开或关掉它，画布上已有的画布项一项都不动。agent 摆的位置和系统找的空处，也都不受它影响。它的用处是让人手摆的画布项对得齐，画布不乱。

磁吸开没开是这台设备上的观感偏好，每台设备各是各的。

### 一叠

人选中几个画布项，把它们叠成新的一叠。把一个画布项拖到一叠上，它进这一叠。把一个画布项拖到另一个画布项上面，它只是压着那一项，不成一叠。agent 用「叠成一叠」做同样的事。一个画布项至多在一叠里：叠进另一叠，它就离开原来那一叠。

一叠平时只露出最上面几页的边，写着名字和里面有几项。人点开一叠，里面的画布项摊开，可以在里面找。人从里面拖出一项，它离开这一叠，停在松手的地方。没有给位置时，例如 agent 只说拿出来，它落在这一叠旁边的空处。

一叠可以整个挪，可以改名。散开一叠时，里面的画布项各自落到这一叠旁边的空处，这一叠没有了。拿走一叠里的一项，它也离开这一叠。最后一项离开时，这一叠没有了，画布上不会留下一个空的一叠。

拿走过的画布项不在任何一叠里。锁着的画布项不能叠进一叠，见[锁定](#锁定)。

### 拿走与放回

拿走一个画布项，它立刻从画布上消失，不问确认。拿走只去掉它的摆法，被它指着的对象照旧在原来的地方：那张截图还在会话的历史里，那个会话还在会话列表里。画布上没有删除。要删掉一个对象，到拥有它的地方去删。

拿走过的画布项列在「拿走过的」里，最近拿走的在前。这份清单有上限，由部署配置。超出时，最早拿走的那一项从清单里消失。被它指着的对象不受影响，仍然能被重新摆上来。

放回就是再摆上一个拿走过的对象。没给位置时，它回到拿走之前的位置。那里已经被占了，它就落在离那里最近的空处。放回的画布项在最上面。放回同样要过摆上之前的确认：这一类此刻没有声明，或拥有者不再接受这个对象时，放不回来，答复说明原因。

### 查找

人在画布上打开查找，做两件事：挑一个已有的对象摆上来，或者把拿走过的放回。没有输入时，先列最近拿走的。输入时，在拿走过的画布项和能从查找里挑的种类里一起找。

一类对象能不能从查找里挑，由拥有它的领域决定：它提供了挑法，这一类才出现在查找里。挑中的对象已经摆在画布上时，画布不多摆一份，而是把那一项指给人看。

### 锁定

人可以锁住一个画布项。锁着的画布项，谁也挪不动、改不了大小、拿不走、叠不进一叠，也放不到最上面。这条对人和 agent 一样。只有摆在画布上、不在一叠里的画布项锁得上：要锁一叠里的一项，先把它拿出来。

锁着的画布项上有一个锁的记号，没有拖动与改大小的把手。人点那个记号就解开它。人要挪一个锁着的画布项，先解开它。

「不让 agent 动人锁住的东西」由两条规则合起来做到：

1. 锁着的画布项对谁都不许改。
2. 锁上与解开归「锁」这一项权限，缺省不许 agent 做。会话处在跳过询问的运行模式时也一样，跳过询问越不过禁止。

所以人锁上的画布项，agent 挪不动，也解不开。agent 碰到锁着的画布项时，答复写明它锁着、要人来解，agent 照此告诉人。租户把「锁」这一项改成允许之后，agent 就能先解开再动它。

锁的规则不看是谁摆的。人可以锁住 agent 摆的画布项，锁住之后它同样不动。

### 能摆什么

系统里任何一类对象，只要拥有它的领域声明它可画布渲染，就能摆上画布。声明写明这一类叫什么、一句话说明它是什么、怎样指明这一类里的一个对象，并带来这一类在画布上的画法。拥有者还可以要求摆上之前先核对象，见[摆上去，落在哪](#摆上去落在哪)。

画布不认识任何一类对象。多一类，是拥有它的领域多一份声明，画布不用改。一个领域没有开放时，只有它那一类受影响，见[画不出来的时候](#画不出来的时候)。

画布上没有新建内容的入口。画布上的每一项，要么指着系统里已有的对象，要么指着 agent 做的画布小应用。文字、链接、便笺这类内容，要先有一个领域拥有它们，并声明它们可画布渲染，才摆得上画布。

产品要求下面三类可画布渲染。

#### 媒体对象

媒体对象由媒体声明。人从桌面或文件管理器把文件拖到画布上，文件先上传、备好，再摆在松手的地方。上传失败或媒体此刻没有开放时，画布上不多出东西，并说明原因。agent 用一个媒体对象的引用把它摆上来，例如它截下的一张屏幕。

画布上的媒体对象和它在历史里的样子相同：图片是缩略图，点开看原图。语音与文件照[在历史里看](../media/design.md#在历史里看)的规则显示。

没有被引用的媒体对象到期会被清掉。媒体对象摆上画布时，媒体为画布留住它，所以画布上的文件不会过一阵自己消失。拿走之后它也照样留着。它什么时候可以清，见 [Q-CV01](#q-cv01)。

#### 会话

会话由会话这一领域声明。人在查找里挑一个会话摆上来，agent 用会话的标识把它摆上来。画布上的会话写着标题、最近一次活动和它现在的状态。人点开它，应用翻回正面，对话页打开这个会话。

#### 画布小应用

画布小应用是 agent 做的一段只管画的界面。agent 先把它做成一份 [plugin](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-plugin--插件--plugin) 发布出来，再把它摆上画布。画布小应用这一类由画布自己声明。画布项按名字指着这个画布小应用。

画布小应用只能画。它能用的只是 plugin 交给界面代码的那些能力，其中没有自己去取数据的办法。它要显示的内容，在 agent 做它的时候写进去。plugin 交给界面代码的能力变多，画布小应用能做的也随之变多。

agent 改了画布小应用再发布，画布上那一项换成新的样子，位置不变。发布它的 plugin 被禁用或移除时，那一项写着「这个小应用现在不在」，画布项留着。plugin 回来，它又画出来。两份 plugin 带了同名的画布小应用时，这个名字画不出来，画布上写明是哪两份冲突。撤掉其中一份，另一份立刻生效。

人不直接做画布小应用。人要一个，就对 agent 说。拿走过的画布小应用，人可以放回。

### 画不出来的时候

一个画布项画不出来，有四种情形。画布不把它们画成空白，也不拿一种情形的说法顶替另一种。

| 情形 | 谁来说 | 人看到的 |
| --- | --- | --- |
| 这一类没有声明，例如拥有它的领域没有开放 | 画布 | 一页，写着这一类的名字、对象的标识，和「这一类现在没有声明」 |
| 画布此刻读不到哪些种类声明着 | 画布 | 同样的一页，写着「现在读不到」 |
| 被指着的对象不在了 | 拥有这一类的领域 | 这一类的画法自己说 |
| 这个人无权看被指着的对象 | 拥有这一类的领域 | 这一类的画法自己说 |

后两种只有拥有对象的领域答得出，画布不替它去查。拥有者可以对这两种说同一句话，免得把一个人无权看的对象存不存在告诉他。

四种情形下，画布项都留着，摆法不变。人和 agent 照样能挪它、拿走它。情形消失之后，它照常画出来。

一个画布项的画法出了错，只有这一项画成通用的一页，写着这一类的叫法与对象的标识。别的画布项照常。

### 远近、键盘与字号

人可以平移画布，平移到画布的边为止。人可以围着指针缩放，缩放有上下限。看着哪一块、放多大，是这台设备上的观感偏好，不影响别的设备，也不影响 agent。

缩放画布时，形的大小不变。换[字号档](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-size-tier--字号档--size-tier)时，画布整张一起变大变小，画布项之间的相对位置不变。

画布上的每一个动作都能只用键盘做到：翻面、平移、缩放、选中一个或几个画布项、挪、改大小、叠成一叠、从一叠里拿出来、散开、拿走、查找与放回、锁上与解开。

### 在画布上对 agent 说话

画布上不另设对话面板。人在画布上对 agent 说话，用[随身入口](../desktop-application/design.md#随身入口)。随身入口在反面也在，用法和在正面相同。人在随身入口里去对话页时，应用翻回正面，打开对话页。

### 非目标

- 画布不保存、不复制被指着的对象的内容。画布上没有删除，删除一个对象归拥有它的领域。
- 画布不判断一个对象在不在、谁能看，这些由拥有者答。
- 画布不规定任何一类对象的样子，画法归拥有那一类的领域。
- 画布不按是人还是 agent 定两套规矩。「人摆的东西 agent 不许挪」这类约束，用锁定与权限表达。
- 画布不是导航里的一页。画布上不另设对话面板。

### 关键用户旅程

<a id="j-cv01"></a>

#### J-CV01 第一次翻到画布

人登录之后在正面，侧栏底部有一个墨记号。他点它，形拿着纸边把应用翻过去。反面是一张有边的空画布，形坐在画布中间。他按 ⌘⇧O 翻回正面，原来那一页和输入框里没发出的字都在。他再翻到反面，关掉应用。下次打开，应用停在反面。对应 CAP-CV01、CAP-CV02。

<a id="j-cv02"></a>

#### J-CV02 把几份文件摆在眼前

人从文件管理器里拖了两张截图和一份 PDF 到画布上的一块空处。三样在松手处略微散开，上传、备好之后出现，每一项下面写着是人摆的。他点开一张截图看原图。他在另一台电脑上登录同一个租户，翻到反面，画布上是同样的三项，在同样的位置。对应 CAP-CV02、CAP-CV03、CAP-CV04、CAP-CV13。

<a id="j-cv03"></a>

#### J-CV03 把一个会话放在手边

人在画布上打开查找，输入几个字，挑出一个正在进行的会话。它摆在打开查找的地方附近的空处，写着标题、最近一次活动和状态。过了一阵，他点开它。应用翻回正面，对话页打开的就是这个会话。对应 CAP-CV01、CAP-CV08、CAP-CV14。

<a id="j-cv04"></a>

#### J-CV04 让 agent 做一个画布小应用

人在画布上用随身入口对 agent 说：「做一个到月底的倒计时，放在画布上。」agent 做好一份 plugin 发布出来，再把它摆上画布。人没有刷新，画布上就出现了这一项，下面写着是这个会话里的 agent 摆的。人把它拖到右上角，下面改成人摆的。他又说「改成只显示天数」。agent 改好再发布，画布上那一项换成新的样子，仍在右上角。对应 CAP-CV03、CAP-CV10、CAP-CV15、CAP-CV17。

<a id="j-cv05"></a>

#### J-CV05 画布乱了，整理一下

画布上摆了二十来项。人选中三张截图，把它们叠成一叠，起名「参考图」。他对 agent 说「把会话都叠到一起」。agent 看了画布，要把六个会话叠成一叠，整次被拒，答复指出其中一个锁着。agent 把其余五个叠成一叠，并告诉人那一个锁着，要人来解。人点开「参考图」，拖出一张放到旁边。后来他把「参考图」散开，剩下的两张落到旁边的空处，这一叠没有了。对应 CAP-CV06、CAP-CV09、CAP-CV10。

<a id="j-cv06"></a>

#### J-CV06 拿走，再放回

人把一张不再需要的截图拿走，它立刻消失，没有确认。那张截图仍在原来那段会话的历史里。第二天他又想要它，在画布上打开查找，不输入，最近拿走的排在最前。他选它。原来的位置空着，它就回到那里。那里已经摆了别的，它落在离那里最近的空处。对应 CAP-CV07、CAP-CV08。

<a id="j-cv07"></a>

#### J-CV07 锁住一项，不让 agent 动

人把一个摆得正好的会话锁上，它上面出现锁的记号，拖动与改大小的把手不见了。他让 agent 整理画布。agent 动不了这一项，告诉人它锁着。人让 agent 把它解开，agent 被拒绝，告诉人这件事要人来做。人点锁的记号解开它，拖到新位置，再锁上。对应 CAP-CV09、CAP-CV10。

<a id="j-cv08"></a>

#### J-CV08 一项画不出来

部署撤下了媒体。画布上的截图都变成一页，写着「这一类现在没有声明」和对象的标识，别的画布项照常。人照样能挪它们、拿走它们。媒体回来之后，它们照常画出来。另一次，人在资产里移除了一份 plugin，它带的画布小应用在画布上写着「这个小应用现在不在」。人把这一项拿走。对应 CAP-CV11、CAP-CV12、CAP-CV15。

### 可观察场景

下列场景是产品判据，正文描述的是期望结果。演示通过不替代产品负责人接受。

- **S-CV01 翻面与停在哪一面。** 在开放了画布的部署上第一次登录。应看到正面，侧栏底部有一个墨记号；导航里没有画布，应用菜单里没有翻面。点墨记号：形拿着纸边把应用翻过去，反面是一张有边的空画布，形坐在画布中间。再翻一次，翻到一半时点一下窗口：立刻停在要去的那一面。在正面写一句话不发出，按 ⌘⇧O 到反面，再按回来：原来那一页与那句话都在。停在反面时关掉应用再打开：打开的是反面。
- **S-CV02 部署没有开放画布。** 应用只有正面：侧栏底部没有墨记号，按 ⌘⇧O 不翻面，其余各部分照常。
- **S-CV03 拖文件进来。** 往画布上一块空处同时拖进两张图片与一份 PDF。三样在松手处略微散开，各自出现，下面写着是人摆的，过程中没有弹出任何询问。点一张图片：看到原图。另开一个窗口登录同一个租户：画布上是同样的三项，位置相同。拖进一个超过媒体大小上限的文件：画布上不多出东西，并说明原因。
- **S-CV04 摆一个会话并点开。** 打开查找，输入一个会话标题里的字，挑中它：它摆在打开查找处附近的空处，写着标题、最近一次活动与状态。再挑一次同一个会话：画布上没有多出一份，画布把原来那一项指给人看。点开它：应用翻回正面，对话页打开这个会话。
- **S-CV05 agent 做画布小应用。** 在反面用随身入口请 agent 做一个倒计时摆到画布上。人不用刷新，画布上出现这一项，下面写着是哪个会话里的 agent 摆的。人把它拖到别处：下面改成人摆的。请 agent 改它的样子：agent 再发布之后，那一项换成新的样子，位置不变。在资产里禁用那份 plugin：那一项写着「这个小应用现在不在」，别的画布项照常。重新启用：它又画出来。
- **S-CV06 一叠。** 把一项拖到另一项上面：它压着那一项，没有成一叠。选中这两项叠成一叠，起个名字：画布上露出最上面几页的边、名字与数目 2。把第三项拖到它上面：数目变成 3。点开这一叠，从里面拖出一项放到别处：数目变成 2。让 agent 再从这一叠里拿出一项，不给位置：它落在这一叠旁边的空处。散开：最后一项落到旁边的空处，这一叠没有了，画布上没有留下空的一叠。
- **S-CV07 拿走与放回。** 拿走一张图片：它立刻消失，没有确认。在原来那段会话的历史里，那张图照常看得到。打开查找、不输入：它排在最前。放回：它回到原来的位置。再拿走它，在它原来的位置摆上别的，然后放回：它落在离原位置最近的空处。
- **S-CV08 锁定。** 锁上一个会话：它上面有锁的记号，没有拖动与改大小的把手；拖不动它，也拖不进一叠。请 agent 挪它：画布不变，agent 告诉人它锁着、要人来解。请 agent 解开它：画布不变，agent 告诉人这件事它不许做。把会话切到跳过询问的运行模式，再请一次：结果相同。点锁的记号解开：能拖动了。再请 agent 挪它：挪动成功。
- **S-CV09 磁吸。** 磁吸开着，拖一个画布项松手：它落在网格上。关掉磁吸：画布上的画布项一项都没动。再拖它：松手在哪就停在哪。在另一台设备上看磁吸的开关：和这台各是各的。请 agent 把一项摆到一个不在网格上的位置：它照那个位置摆。
- **S-CV10 整批与拒绝。** 请 agent 一次把五项挪成一列，其中一项锁着：五项都不动，答复指出是哪一项、因为锁着。请 agent 把一项摆到画布边外：没有摆，答复写明位置出了画布。部署把摆着的上限设成 3，摆满之后再摆一项：答复说摆满了，画布不变。拿走一项再摆：摆上了。
- **S-CV11 同时改。** 人正拖着一个画布项时，让 agent 把同一项挪到别处，然后人松手。画布上那一项只有一份，停在后到的那一次的位置。两台设备上看到的相同。
- **S-CV12 画不出来。** 部署撤下媒体：画布上的图片与文件都变成一页，写着这一类的名字、对象的标识与「这一类现在没有声明」。别的画布项照常，这一页能挪、能拿走。媒体回来：它们照常画出来。让画布一时读不到哪些种类声明着：画布项写着「现在读不到」，不变成空白。让一个画布项的画法出错：只有这一项变成通用的一页。
- **S-CV13 键盘、减弱动效与字号档。** 不用指针，只用键盘：翻到反面，平移、缩放，选中一项，挪、改大小、叠进一叠、拿出来、散开、拿走、从查找里放回、锁上、解开，再翻回正面。每一步都做得到。打开系统的减弱动效：翻面直接换。四个字号档下各看一次：画布整张一起变大变小，画布项之间的相对位置不变。缩放画布：形的大小不变。
- **S-CV14 租户之间。** 用另一个租户登录：它的画布是空的，看不到前一个租户的任何一项。在后一个租户的会话里，让 agent 用前一个租户的一个会话标识摆上来：画布上那一项由会话的画法说它不在或无权看，看不到前一个租户的任何内容。
- **S-CV15 在画布上说话。** 在反面打开随身入口，对一个新会话说一句话：小框如实说出结局。在随身入口里去对话页：应用翻回正面，对话页打开那个会话。

## 能力定义

| 能力标识 | 定义与范围 | 需求位置 |
| --- | --- | --- |
| CAP-CV01 应用的两面与翻面 | 应用有正面与反面，画布是反面，这台设备上第一次登录之后是正面；⌘⇧O、正面侧栏底部的墨记号、反面角上的记号、在反面右键点形四个入口，导航与应用菜单里没有；两面一直都在，翻面只换露在外面的一面，各面停在原来的样子；翻面能被一下打断，减弱动效时直接换；停在哪一面按设备记；从反面去正面的某一页先翻回正面；部署没有开放画布时只有正面，没有翻面的入口 | 「应用的两面」；J-CV01、J-CV03；S-CV01、S-CV02 |
| CAP-CV02 一个租户一张画布 | 每个租户一张有边的画布，一开始是空的；大小与网格的疏密由部署配置；摆法记在服务端，各设备、各窗口看到同一张；只有这个租户的人与在它的会话里工作的 agent 能看、能改，被拒的一方得不到画布上有什么的线索 | 「画布、画布项与一叠」；J-CV01、J-CV02；S-CV03、S-CV14 |
| CAP-CV03 看画布与来历 | 人看到画布现在的样子，别处的改动随即出现；agent 用「看」读画布、拿走过的与能摆的种类；每次改动记下是谁做的，每个画布项上看得到最近是谁摆的，是 agent 时写明会话；来历不是权限 | 「人和 agent 用同一组操作」；J-CV02、J-CV04；S-CV05 |
| CAP-CV04 摆上与找空处 | 给位置、只给附近、都不给，分别摆在那里、附近最近的空处、画布中间形的座位旁的空处；找空处连同画布项下面的字算；没有空处时落在要的那一点上，允许压着，后来的在上面；同一个对象在一张画布上至多一个画布项；摆着的有上限，改小上限不拿走已有的；摆上之前确认这一类可画布渲染，拥有者可再核对象，不接受时不说是哪一种原因 | 「摆上去，落在哪」；J-CV02、J-CV03；S-CV04、S-CV10 |
| CAP-CV05 挪、改大小与磁吸 | 挪、拖四角改大小、放到最上面，拖不出边，大小有上下限；在一叠里的不单独挪；磁吸是设备上的开关，缺省开着，开着时人的手势松手落到网格；开关不改已有摆法，不影响 agent 的摆法与系统找的空处 | 「挪、改大小与磁吸」；J-CV04；S-CV09 |
| CAP-CV06 一叠 | 叠成新的一叠或叠进已有的一叠，一个画布项至多在一叠里；平时露出最上面几页的边与名字、数目；点开摊开并可在里面找，可拖出；整个挪、改名；散开时各项落到旁边的空处；最后一项离开时一叠没有；压着不等于在一叠里；拿走过的不在一叠里 | 「一叠」；J-CV05；S-CV06 |
| CAP-CV07 拿走与放回 | 拿走立刻生效、不确认，只去掉摆法，被指着的对象不受影响；画布上没有删除；拿走过的清单最近的在前，有上限；放回回到原位置，被占时落在最近的空处，在最上面；放回同样要过摆上之前的确认 | 「拿走与放回」；J-CV06；S-CV07 |
| CAP-CV08 查找 | 人在画布上打开查找，挑一个已有对象摆上来或放回拿走过的；不输入时先列最近拿走的；只有提供了挑法的种类出现在查找里；挑中已摆着的对象时不多摆，把那一项指给人看 | 「查找」；J-CV03、J-CV06；S-CV04、S-CV07 |
| CAP-CV09 锁定 | 人可以锁住一个摆着、不在一叠里的画布项；锁着时谁也挪不动、改不了大小、拿不走、叠不进一叠、放不到最上面；有锁的记号，没有把手，点记号解开；锁上与解开归「锁」这一项权限，缺省不许 agent 做，跳过询问的运行模式越不过，租户可以改；agent 碰到锁着的得到写明锁着、要人来解的答复 | 「锁定」；J-CV05、J-CV07；S-CV08 |
| CAP-CV10 人与 agent 同一组操作 | 同一组操作、同一套规则，结果只取决于操作、所带的内容与画布现状；人的操作按租户判，agent 的在发起时由放行判断判，「看」「摆」缺省自动，「锁」缺省禁止；同时改同一项时后到的生效；一次涉及几项时全做或全不做，并指出是哪一项；各种没照做的答复分开，结果不知道照实说，重做一次安全 | 「人和 agent 用同一组操作」；J-CV04、J-CV05、J-CV07；S-CV10、S-CV11 |
| CAP-CV11 可画布渲染的声明 | 一类对象由拥有它的领域声明可画布渲染才能摆上；声明带叫法、一句说明、怎样指明一个对象与画法，可要求摆上之前先核；画布不认识任何一类，多一类或少一类只影响那一类；画布上没有新建内容的入口；产品要求媒体对象、会话、画布小应用三类 | 「能摆什么」；J-CV08 |
| CAP-CV12 画不出来的四种情形 | 没有声明、读不到由画布说，不在了、无权看由拥有者说，拥有者可以对后两种说同一句话；不画成空白，不互相顶替；画布项与摆法留着，照样能挪、能拿走，情形消失后照常画；一项的画法出错只有这一项落回通用的一页 | 「画不出来的时候」；J-CV08；S-CV12 |
| CAP-CV13 媒体对象上画布 | 人把文件拖到画布上，上传、备好后摆在松手处，几样略微散开；失败或媒体没有开放时不多出东西并说明原因；agent 用引用摆；样子与历史里相同；摆上时媒体为画布留住它，拿走后照样留着 | 「媒体对象」；J-CV02；S-CV03 |
| CAP-CV14 会话上画布 | 人在查找里挑会话，agent 用标识摆；画布上写标题、最近一次活动与状态；点开时翻回正面，对话页打开这个会话 | 「会话」；J-CV03；S-CV04 |
| CAP-CV15 画布小应用 | agent 把它做成 plugin 发布再摆上；只能画，能做什么随 plugin 交给界面代码的能力；再发布后换成新的样子，位置不变；plugin 不在时写「这个小应用现在不在」，画布项留着；同名冲突时写明是哪两份；人不直接做，能放回 | 「画布小应用」；J-CV04、J-CV08；S-CV05 |
| CAP-CV16 远近、键盘与字号 | 平移到边为止，围着指针缩放，有上下限；看着哪一块、放多大与磁吸开关是设备上的观感偏好；形不随缩放变大小；换字号档时整张一起缩放，相对位置不变；画布上每个动作都能只用键盘做到 | 「远近、键盘与字号」；S-CV13 |
| CAP-CV17 在画布上对 agent 说话 | 随身入口在反面照常可用；在它里面去对话页时翻回正面并打开对话页；画布上不另设对话面板 | 「在画布上对 agent 说话」；J-CV04；S-CV15 |

### Q-CV01 摆上过画布的媒体对象什么时候能清

媒体对象一摆上画布，媒体就为画布留住它。拿走不解除，画布也没有别的解除办法。所以在画布上摆过的文件会一直留着，一直占着存放的地方。

它们什么时候能清，取决于媒体那条没有裁定的保留规则，见[媒体：回收](../media/design.md#回收)。那条定下之后，画布这一侧还要定：拿走、拿走过的清单丢掉最早的一项，各算不算画布不再需要这个媒体对象。

<a id="q-cv02"></a>

### Q-CV02 部署把画布改小时，边外的画布项怎样

画布的大小由部署配置。部署把它改小时，已有的画布项可能落在新的边外。有两种做法：

- 摆法不变。边外的画布项照原位置记着，画的时候收进画布里。人或 agent 挪它时，它才落到边内。画布只因人或 agent 的操作而变。
- 系统把边外的画布项挪进新的边界，来历写成系统。画布总是在边内，但人会看到一次既不是自己、也不是 agent 做的改动。

定下之前按第一种做：它不引入一种既不是人、也不是 agent 做的改动。
