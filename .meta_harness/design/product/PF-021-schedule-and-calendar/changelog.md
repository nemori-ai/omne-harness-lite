### rev 7 · 2026-09-28

| 项 | 内容 |
|---|---|
| 变更 | 五项选择闭合：既有 Job 事实不变，未形成工作采用最新日历校验；沿用特殊日期基线；补跑、重叠及通知成为每份 Schedule 的可变配置 |
| 策略 | 不补／补最近 N 次；跳过／停止先前后执行／独立并行／等待；通知按开始、成功、失败、取消事件组合声明。创建、读取、更新均覆盖类型与参数 |
| 依据 | INT-027 五项裁决、INT-028 明确策略类型与配置入口；配套推导见 decisions §七 |
| 取代 | rev 6 的 U3/U6/U7 不再待裁；不采用统一漏跑跳过、统一重叠跳过、统一结局通知。rev 6 排除无依据策略体系的范围不覆盖本次明确要求的三类策略配置 |
| 事实边界 | 候选预算不是 Job，最新校验后接受本次工作才成为事实；已创建的等待 Job 不因日历或策略变更被回写。停止与成果可继续作为新事实 |
| 技术交接 | 记录用户指定的日常 t+1 预算与调派前重算方向，交接提前唤醒、校验／接受一致、来源去重、有界补跑和替换停止确认的验证责任 |
| 对账 | 新增三条策略属性词条，精化 Schedule／Job 定义，同步四条对象依据；对象数不变，地图重生成。工具仍为五组 23 命令 |
| 状态 | 产品本轮无剩余待裁，整包仍为草稿；技术契约、实现与运行验证尚未交付 |

### rev 5 · 2026-09-28

| 项 | 内容 |
|---|---|
| 变更 | Routine 从独立对象改为 Schedule 内的工作描述；一份 Schedule 持有一份 Routine，各次 Job 共用其定义但不共享执行状态。创建和修改统一在日程入口完成 |
| 工具 | 建立五组多命令工具的产品定义：Calendars、Schedules、ScheduledJobs、CurrentJob、Notifications；移除 Routines 管理槽，预置发现与读取归 Schedules，明确两类 agent 的行动范围 |
| 依据 | [INT-019～023](interviews/2026-09-28-product-discussion.md#int-019两类-agent-的原子行动与工具命名讨论)，尤其 INT-022 包含关系与 INT-023 完整更新指令；命令设计判断见 decisions |
| 取代 | 不再采用独立 Routine 身份、生灭、多个 Schedule 共享可变内容、关联 Routine ID 或共享内容派生更新方案；历史提议留访谈，不再作为现行模型 |
| 对账 | UL-routine 形态改为属性，移除其对象条目；Schedule 身份与内容关系同步。出厂 Routine 是供采用的预置数据，不另建运行期模板对象。通知查询所指记录的未定义边界登记待裁 |
| 范围 | 同步模型、流程、工具命令、验收与来源。Routine 简化及工具设计不替未决的启用政策、已产生未开始 Job 采用边界、送达判据和恢复政策填默认；未修改相邻 PF 或冻结规格 |

| 推导边界 | 系统自用内容及其单次工作不借用租户归属；机械执行不用 agent 会话、成果工具或 Loop 检查。该范围不扩展为任意无租户 agent 执行 |
