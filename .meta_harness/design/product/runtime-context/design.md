# 运行感知与一次模型请求

状态：候选、待用户确认。本文定义用户可判断的产品规则。它不选择公开接口、存储、通信协议、转换算法或压缩策略。

## 产品需求描述

### 1. 用户需要持续感知当前工作条件

用户让 Agent 长期工作时，需要它知道自己属于哪个会话和租户、当前有哪些工作、使用什么模型、允许做什么。工具与扩展也可能需要读取相应数据。Runtime Context 按块提供这些消息之外的数据，每块有自己的来源和允许消费者。

用户重新进入老会话时，先看到最近一段获准历史，往前翻时继续取得更早内容，新记录在取得当前段后继续到达。人侧读取不以模型窗口裁剪历史。加载到哪属于读者状态，不改写会话事实。具体分页与交付入口由会话和交付面继续设计。

模型每次请求需要完整的适用输入。当前感知、历史提醒和这次实际交给模型的内容各有用途，用户应能追查一次请求采用了什么。保存历史不意味着模型、工具或扩展都能读到全部内容。

### 2. 来源、会话选择和历史分别生效

生产者拥有原内容和读取资格。Session 维护本会话注册了哪些块，以及会话自己选择或维护的值。注册声明保存来源、配置、消费者、是否必需及恢复依据。注册不会把共享数据变成本会话的资产。

移除一个可选块，只停止本会话后续使用该注册。共享来源及其他会话仍保留。恢复不能把用户主动移除的可选块装回。必需块不能用可选移除绕过，固定的会话与租户身份不能用内容更新改写。

已经发出的请求保留当时实际采用的内容。后来更新、撤权或移除不改写这次输入，也不撤回已经发生的工具效果。后续读取和动作须重新满足有效资格。历史快照、提醒和一次请求中的允许结论都不成为未来许可。

### 3. 必需感知按内容及消费者供给

以下表格承接本候选必需感知候选范围。允许某类消费者读取，仍须满足具体内容的资格。它不授予读取秘密、私有全文或外传的权限。

| 块 | 来源及至少表达的内容 | 消费者 |
| --- | --- | --- |
| 会话元信息 | 会话身份、创建时间、类型、日志版本、权限模式和协作模式 | 模型、工具、扩展 |
| 租户与组织元信息 | 身份、名称、组织内角色及创建时间，由身份拥有者供给 | 模型、工具、扩展 |
| 账号偏好 | 通过租户关联取得可读的语言、时区、地区、明暗风格等已有偏好；不要求每项都有值 | 模型、工具、扩展 |
| Agent 元信息 | Agent 身份与本次采用的定义版本；会话路径中 Agent 身份对应会话身份，不随实例换代改变 | 模型、工具、扩展 |
| 环境元信息 | 实际操作系统类型、版本及当前日期，不要求精确到时分 | 模型、工具、扩展 |
| 当前 ModelProfile | 会话当前使用的合法档案内容，不包括不得披露的调用凭据 | 模型、工具、扩展 |
| 当前压缩设置 | 当前 ContextCompactionSettings 内容 | 模型 |
| 组织与租户结构化授权 | 两级分开供给的完整获准结构化授权，不由 Context 解析合并成许可 | 扩展 |
| 本会话语义授权 | 租户在本会话表达的授权或撤回、动作范围、单次或会话作用域、先后关系与来源；全局值沿租户权限取得 | 模型、扩展 |
| 工作区选择 | 逻辑工作区及实际地址或实例入口，可以为空，可表达多个 worktree 分工 | 模型、工具、扩展 |
| 未结束后台工具 | 原执行身份、所做事项、实际已知状态及查询或控制入口，适用时说明等待内容 | 模型、工具、扩展 |
| 未归档子会话 | 原关系、受派任务与已知状态；报告已交和仍可交互分别表达 | 模型、工具、扩展 |
| 未完成待办 | 身份、事项及当前未完成状态；不添未承诺期限、优先级或跨会话目标 | 模型、工具、扩展 |
| 窗口占用比例 | 当前实际上下文长度占有效模型窗口的比例，实时派生 | 模型 |

后台执行、子会话和待办只提供实际已知信息。查不到当前状态不能虚构进度、完成时刻或成功。窗口占用与压缩设置共同帮助模型判断主动压缩的代价，预算仍由完整请求校验。

会话模式或装配不能取消必需感知。必需注册在场不代表来源永远可用。身份、授权或其他必要内容不可取得时，系统明确说明缺项或未知，不能用空白、猜值或旧许可伪装可继续。

### 4. 三个模式维度独立

模式事实由 Session 提供，Context 只供给当前值及变化。三个维度都可以在运行期变化，改变一维不自动改变其余维度。模式不能越过明确禁止或工作区的权限边界。

| 维度 | 有效值 | 用户可见结果 |
| --- | --- | --- |
| 权限处理 | `never` | 本应询问的动作按拒绝处理，不出授权询问。`Ask().request_approval` 不可用，其不可用原因可感知。 |
| 权限处理 | `auto_permission` | 按有效授权表达判断；没有结论时交获准的人决定，不由模型代批。 |
| 权限处理 | `bypass-permissions` | 放行本应询问的动作；明确禁止仍不可突破。 |
| 执行环境 | `always-allow` | 允许该工具的作用直接落宿主机，仍须满足动作授权与实际执行条件。 |
| 执行环境 | `auto_place` | 系统按实际条件求合适的执行环境，每次执行重新求值。 |
| 执行环境 | `never-allow` | 该工具绝不直接落宿主机，所需隔离环境到不了位时拒绝，不回退到更宽松落点。 |
| 协作 | `co-work` | 开启 Ask，具体命令仍受权限限制；不增加该模式的目标完成检查。 |
| 协作 | `auto-drive` | 关闭 Ask，增加目标完成检查，目标未完成不能正常收束；用户停止、取消、失败及授权约束仍成立。 |

切协作模式不创建新会话、不改变用途或定义身份，也不增加能力。切回 `co-work` 只移除协作模式附加的完成检查，作业会话自身强制检查仍在。

执行环境维度逐工具独立，适用于工具声明需要执行环境的情况。动作准不准仍由权限维度判断，获准落宿主或隔离不表示该动作已获准或一定成功。

没有显式模式初值时，采用适用租户默认，随后成为本会话的值。租户以后改变默认，不重写已有会话。重启、恢复、撤销归档和重新装配都不重新套默认。其他设置沿各自覆盖或继承规则，不能把这一条扩成所有值都只在创建时读取。

这个会话的租户可以改权限处理、执行环境和协作三个模式。Agent 不能直接写模式。Agent 要改模式，必须走 HITL，由人显式授权。Context 提供当前合法值及变化，不授予修改资格。自动归档默认关闭，允许显式开启；启用及时限由租户配置，常驻标记由具会话管理资格的用户维护自己的会话；开启或解除常驻沿已有连续空闲。常驻仅适用于主会话，不存在常驻子会话。具体时限及配置契约由设置与Session拥有者提供，本域不另定规则。

### 5. 当前值与变化感知

每次执行开始或挂接建立时，主动取得当时有权读取的完整当前快照。运行期间，模型可读块发生变化时追加变化提醒。工具或扩展私有块的变化只向获准消费者供给，不发给模型。

会话空闲时可以丢弃当前状态推送，下次执行开始或挂接建立时读取当前值。不必补世界上每一次中间状态，但不能丢弃已经受理的普通输入、控制或原结果。变化链记录本会话实际感知的变化。

状态变化提醒说明从什么变成什么，事件提醒说明发生了什么。提醒都追加，后一次提醒不覆盖前一次。完整状态快照允许可选携带前值，是否携带由该块的数据性质和产品要求决定，不统一要求或禁止。

模型首次读取及压缩之后，提供当前允许模型读取的完整 Context。平时通过变化链保持理解，不能只取最新提醒。历史提醒可能过时，结构化授权仍从当前权威来源判断。

工作区 AGENTS.md 在实际首次进入相应子目录时加载适用指导，不因普通资产发现提前加载，也不靠资产 reload 代替。远端文件更新不承诺立即同步全部 Context。

### 6. 一次模型请求采用合法完整输入

系统提示词每次请求求值，本候选只含文本，不存成会话消息。普通新输入及其他需要本次承接的历史消息先可靠保存，再组装。实际使用的工具声明必须与合法绑定一致，不能给模型旧说明而执行新实现。直接调用与脚本编排的声明消费沿[工具可编程调用许可](../tool-execution/design.md#可编程调用许可)，本域不另定许可。

人侧和模型侧可见性逐块独立，四种组合都成立。消息类型提供常态去向，块标注决定实际选取。ToolInternalMessage 始终不进模型，缺少明确模型可读标注的块不进入请求。未完整工具调用可以保留原内容备查，但不执行，也不作为模型请求中的完整调用。

Tool 结果采用独立分流。附件区只成为地址文本，不进入媒体读取或模态约束；消息内容中的模型可见 ref 保留原引用，在 Model 真正请求时才加载二进制及完成必要转换。消息准入、历史投影和请求组装不得为了产生 transcript 提前读取这些字节。其他消息来源继续使用下述接纳前转换规则。

文字、图片、语音可以作为原生内容参与请求。按实际模型能力选择原件、适用派生表示或 transcript，多种可用表示的选择归明确策略。带模型读取标注的非文本块和文件进入转换规则，包括同时供人和模型读取的内容。纯文本及仅供人读取而没有模型读取标注的块，不被无关转换件否决。转换在消息接纳前完成，不因当前模型能读原件而跳过。消息接纳后，派生表示及 transcript 固定，后来更换转换件不能回填或改写既有历史。转换不覆盖原件，也不改原可见性。缺少转换能力与转换执行失败分别可查，不以空白或捏造文本冒充成功。

转换件共同技术契约由 [Model](../../../../packages/model/model-contract/SPEC.md#转换件的共同契约)拥有，以下仅说明本域接纳和表示采用的产品后果。本候选采用的转换件由系统装配，使用本地识别，不另调模型；组织或租户不按范围选择转换件。每次适用转换，转换件须交出至少一份合乎契约的其他模态表示及纯文本 transcript，派生表示不能是文件块。未登记对应转换件时，原块可按原规则保存但没有 transcript，实际可读性及合法模型约束继续判断；已经登记却不可用或转不成时按转换失败，不能借未登记分支落下无解释内容。用户能看出本次模型实际读到原件还是转换表示。

输入转换或消息准入被否决时，发送方得到拒绝原因，该输入不成为会话消息。模型回复被否决时，原调用真实收场与被否决事实保留，不冒充模型服务故障。原有效工作沿消息否决路径继续。连续否决不设次数上限，不因此使 Run 失败。独立或旁路回复沿原消费契约收场，不暗造 Run，也不改旧终态或恢复取消后的工作资格。工具结果的后果限于[压缩与未完工作](#7-压缩保留历史与未完工作)中的原消费契约。

完整预算同时计算全部系统提示词、历史、提醒、工具定义和实际发送的模态内容。精确字节、图片数等限制实际检查，token 可以采用适用估计与明确余量。未知限制保持未知，不编一个窗口或通用时限。

模型调用前扩展改变参数或内容时，重新组装或复核最终输入，包括资格、实际接收方和预算。同一次经过不重复触发该扩展位置。固定发出内容后，后来的设置、Context 或档案变化不改写原请求。

### 7. 压缩保留历史与未完工作

压缩只处理允许的会话内容。在满足目标模型限制的硬条件内，兼顾前缀一致、信息保留和长度。一次压缩确定压缩覆盖范围：从会话历史的起点开始，到压缩点（这条 CompactionMessage 追加的位置）之前的某一处结束，并包含上一条 CompactionMessage。它为这段范围生成摘要，并点名范围内仍要原样交给模型的消息。这份点名就是保留名单。摘要、覆盖范围和保留名单共同形成追加的 CompactionMessage。

压缩之后，模型看到的历史依次是保留名单里的消息（按原顺序）、这条 CompactionMessage，以及排在覆盖范围之后的全部模型可读消息。覆盖范围可以在压缩点之前结束，范围之后、压缩点之前的消息照常出现。范围内没有保留的消息只以摘要形式出现。保留名单在压缩时固定，之后不变，所以后续请求的开头保持稳定。再次压缩时，新的覆盖范围包含上一条 CompactionMessage 和它的保留项；新压缩可以把它们再次列入保留名单，没有列入的进入新摘要。

压缩不删除原历史，不改原块内容或原可见性。用户仍能沿原资格查看原内容，也能知道压缩发生。

上次模型请求之后尚未让模型读取的新输入不能先压成摘要。未答等待和未结后台执行的占位不能压掉。这些未结工作要么进保留名单，要么留在覆盖范围之后。工具调用和它的结果在模型视图里同时出现或同时不出现：覆盖范围的终点不能把一次调用和它的结果分在两侧，除非调用一侧进了保留名单；两者都在范围内时，一起保留或一起摘要。压缩后重新供给完整合法 Context。原调用、未消费结果及账目不会因请求投影省略而消失。

固定部分本身超限，或合法压缩后仍装不下时，明确说明原因并保留会话和历史。会话路径使原消费契约指定的仍有效未终态 Run 失败；独立调用返回失败，不创建 Session 或 Run。不默认换模型、分叉、删除历史，也不在相同条件下无限重做。

Tool 结果消息准入或模态转换被否决时，原结果先可靠保管，使明确消费契约指定的仍有效未终态 Run 失败。后台、Run 外或原 Run 已终态时，不改旧终态、不默认挂后继、不造 Run，也不恢复取消后的入队资格。具体旁路后果由原消费拥有者设计，不能靠重跑外部效果取得另一份结果。

### 8. 故障、恢复和数据保护

已经确认持久保存的注册、自有不可重算值、历史、采用与交接事实，在普通进程崩溃、操作系统崩溃或断电后仍可读取和解释。可从外部权威重取的当前值与可重建缓存分别处理，不承诺永久保存任意缓存。物理介质损毁后的恢复范围和开放资格不在这里代定。

恢复保留本会话值、注册及实际采用依据，再按现行规则取得共享与实时数据。撤权后不能从旧历史恢复访问。查询不可用保持未知，不能伪装成不存在或无工作；消费者更换不重发已经存在的调用。

可读不自动可发送。实际模型、工具、MCP 或遥测接收方改变时重新核对目的和内容。秘密不能因放入 Context、摘要、提醒、附件引用或错误详情而外泄，账目查看资格也不授予正文资格。

已经展示的在途内容有故障后可追查要求，兑现机制尚未闭合。不能默认允许丢失，也不能声称每片同步落盘。Model ACK 不是 Context、Tool 或历史的通用清理许可。

### 9. 本域保留的边界

Tool 内容 ref 与附件地址分流已有明确产品规则，MODEL-E01 跟踪共享块、消息校验和发送的技术兑现。本域只投影模型可见内容块及地址文本，不读取二进制，也不发明递归语法。

本候选不设计实时双工语音层的第三份投影，不恢复已经搁置的连接件入口，不定压缩算法、存储、Provider、公开签名、统一规模或时限。Cordis 负责装配集成，不证明恶意代码隔离。候选说明目标行为及缺项，不证明实际实现已满足。

当前语音沿普通完整输入及流式输出处理，不按播放进度改写历史或块标注。停止语音播放本身不等于取消原业务工作。

### 关键用户旅程

以下 RC-J 编号只定位本文旅程，不定义产品对象或公开操作。每条旅程解释前述规则的用户后果；跨域过程由相应拥有者推进，Context 只承担供给与派生。能力与旅程多对多，对应协作从[关键流程](../../../../packages/context/docs/key-flows.md)展开。

<a id="rc-j01"></a>
#### RC-J01 开始或接续工作，先理解当前条件

用户在已有合法会话中开始或接续工作，希望 Agent、工具与扩展按当前工作条件行动。Session 提供该会话身份、注册和会话值，Agent 在每次执行开始或挂接建立时主动取得当前有权读取的完整快照。各消费者分别取得[必需感知](#3-必需感知按内容及消费者供给)，未完成待办、子会话和后台工具只呈现实际已知状态。来源不可用会表现为缺项或未知，不能伪装成没有工作。

这个会话的租户可以改变三个独立模式。没有显式初值的模式仅在创建时捕获适用租户默认。重新进入、恢复或重新装配沿用本会话值。Agent 要改模式，必须走 HITL，由人显式授权。Context 供给模式事实，授权、落点和完成检查分别由其业务拥有者执行。拒绝或必要条件缺失阻止依赖动作，不把模式快照当未来许可。取消此次读取仅结束该读取，不能撤回原调用效果。

执行开始或挂接建立时读取当前快照，与模型首次读取及压缩后取得完整模型可读 Context，是两个触发。运行中的合法变化继续形成追加提醒；空闲状态推送可以丢弃，下一次执行开始或挂接建立时读当前值。已经受理的输入、控制和结果仍可靠保留。完整快照的前值可选，状态变化提醒则表达获准披露的实际前后关系。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC03](#cap-rc03)、[CAP-RC04](#cap-rc04)。协作见 [RC-F01](../../../../packages/context/runtime-context/docs/key-flows.md#rc-f01)，成员与验证见 [RC-04](../../../../packages/context/runtime-context/SPEC.md#rc-04-读取时点变化与提醒)、[RC-05](../../../../packages/context/runtime-context/SPEC.md#rc-05-会话值模式与工作区指导)及 [RC-VJ01](../../../../packages/context/runtime-context/SPEC.md#rc-vj01)。

<a id="rc-j02"></a>
#### RC-J02 调整本会话感知，撤除后不再继续供给

有相应资格的会话使用者调整本会话注册或自有值，希望后续工作采用新选择。Session 维护注册业务，原生产者继续拥有内容和资格。有效变更说明来源、配置、消费者、必需性与恢复依据，再影响后续供给。可选移除只影响当前会话，共享源及其他会话保持各自事实。

必需块移除、固定身份改写或无权变更被拒绝。读取期间撤权时，旧缓存不能继续供应新内容；必要依据查不到时暂停依赖读取并保留未知。提交响应丢失不能解释为未保存，原拥有者按原操作查询和对账。用户取消等待不证明变更未提交。恢复保留主动移除及会话自有值，已发请求仍保留原采用依据，不把注册失效解释为撤回外部效果。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC02](#cap-rc02)、[CAP-RC04](#cap-rc04)、[CAP-RC10](#cap-rc10)。协作见 [RC-F02](../../../../packages/context/runtime-context/docs/key-flows.md#rc-f02)，成员与验证见 [RC-02](../../../../packages/context/runtime-context/SPEC.md#rc-02-原块与注册的必要条件)、[RC-07](../../../../packages/context/runtime-context/SPEC.md#rc-07-并发撤除与取消)及 [RC-VJ02](../../../../packages/context/runtime-context/SPEC.md#rc-vj02)。

<a id="rc-j03"></a>
#### RC-J03 进入工作目录时取得适用指导

用户让 Agent 在选定工作区处理任务，希望访问子目录时遵守该处指导。实际首次访问尚未进入的目录，Context 协作取得有权读取的适用 AGENTS.md，保留来源、适用目录与采用依据。普通资产发现不会提前加载未访问目录，资产 reload 也不能替代首次访问加载。

无权或来源不可用时，系统不能声称已取得指导；依赖该指导的处理须按原消费契约报告缺项。取消本次读取不撤销已发生操作。恢复后仍须区分历史采用与当前资格，首次访问判据、合并和恢复协议尚待 CONTEXT-E02 明确，不能据此声称远端变化已即时同步。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC05](#cap-rc05)、[CAP-RC10](#cap-rc10)。协作见 [RC-F03](../../../../packages/context/runtime-context/docs/key-flows.md#rc-f03)，成员与验证见 [RC-05](../../../../packages/context/runtime-context/SPEC.md#rc-05-会话值模式与工作区指导)及 [RC-VJ03](../../../../packages/context/runtime-context/SPEC.md#rc-vj03)。

<a id="rc-j04"></a>
#### RC-J04 回看历史，并理解中断后留下了什么

有历史读取资格的用户重新进入会话，先取得最近一段获准历史，再向前读取更早内容，并接收之后的新记录。会话与交付面拥有这条读取路径，Context 提供同源块标注下的投影规则。读者加载进度不改变历史，模型窗口和压缩也不删人侧原件。人侧与模型侧各自按块资格筛选，读取账目不因此取得正文资格。

用户叫停或流中断时，已经交付的内容按原消息规则保留并能解释中断；无内容不造空回复。残缺工具调用可以留作备查，不能执行或作为完整模型调用输入。ToolInternalMessage 始终不进入模型。普通语音仍沿完整输入和流式输出处理，停止播放不等于取消业务。用户取消翻阅只结束对应读取；撤权后不从旧缓存取得新内容。已展示在途内容的故障保留尚缺兑现机制，不能默认允许丢失，也不能把重新打开历史声称为已验证恢复。

关联能力为 [CAP-RC06](#cap-rc06)、[CAP-RC10](#cap-rc10)。协作见 [RC-F04](../../../../packages/context/request-context/docs/key-flows.md#rc-f04)，成员与验证见 [RQ-03](../../../../packages/context/request-context/SPEC.md#rq-03-历史与块投影)及 [RQ-VJ04](../../../../packages/context/request-context/SPEC.md#rq-vj04)。

<a id="rc-j05"></a>
#### RC-J05 提交图片或语音，并知道模型实际读取什么

发送方提交合法内容，或原消费方承接模型、工具结果，希望内容以模型可理解的表示参与后续工作。Tool 结果按内容 ref 与附件地址分流，实际请求才加载内容 ref；以下接纳前转换适用于其他消息来源。带模型读取标注的非文本块或文件，包括同时供人和模型读取的内容，进入[转换规则](#6-一次模型请求采用合法完整输入)。适用转换在消息接纳前完成，即使当前模型能读原件也不跳过；接纳后派生表示与 transcript 固定，原件和原标注保留。请求时再按实际模型能力选用原件、派生表示或 transcript，用户可以追查实际选用结果。

没有登记对应转换件，与已登记却不可用或执行失败，具有不同结果。前者允许按原保存规则保留没有 transcript 的原块，实际模型约束继续检查；后者不能伪装成前者或空白成功。纯文本、只给人看的块不受无关转换件否决。Tool ref 迁移和真实发送验证沿 MODEL-E01，未知嵌套分支不能宣称相容。

外部输入被否决，发送方得到原因，该输入不成为会话消息。模型回复被否决，保留真实收场并回原 Agent 的否决路径。连续否决不设次数上限，不因此使 Run 失败。Tool 结果先可靠保管；否决按原消费契约处置有效未终态工作。后台、Run 外或旧 Run 已终态时不挂无关后继，不改旧终态，不恢复取消资格。取消或故障后需要接续的是原结果及原消费位置，不能重跑外部 Tool 换一份结果。

关联能力为 [CAP-RC06](#cap-rc06)、[CAP-RC07](#cap-rc07)、[CAP-RC10](#cap-rc10)。协作见 [RC-F05](../../../../packages/context/request-context/docs/key-flows.md#rc-f05)，成员与验证见 [RQ-04](../../../../packages/context/request-context/SPEC.md#rq-04-模态与可追溯表示)、[RQ-08](../../../../packages/context/request-context/SPEC.md#rq-08-失败否决与消费位置)及 [RQ-VJ05](../../../../packages/context/request-context/SPEC.md#rq-vj05)。

<a id="rc-j06"></a>
#### RC-J06 发起一次能解释实际采用内容的模型请求

Agent、扩展或独立能力消费者需要发起模型请求。会话路径先可靠保存本次新输入，再取得合法历史、逐请求求值的文本系统提示词、匹配实际绑定的工具声明、模型可读 Context、有效档案与参数。Request Context 按实际发送表示计算完整预算。独立消费者可以提供合法输入使用计算能力，不必创建 Session 或 Run；读取托管数据及外发仍由集成方承担资格责任。

模型前扩展修改内容或参数后，重新组装或复核最终输入及实际接收方，同一次经过不重复触发该扩展位置。必要资格、绑定或来源缺失时不能发出伪装完整的请求。最终发起协调者固定采用依据后交 Model 执行，后续设置和 Context 变化不改原请求。可读不自动可发送，换接收方须重判。

取消组装只终止相应计算与等待。发出结果未知时按原调用身份对账，不能新建调用重发。恢复区分固定采用与当前条件，结果、费用及消费责任仍归原调用。预算超限的具体后果见下一旅程。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC06](#cap-rc06)、[CAP-RC07](#cap-rc07)、[CAP-RC08](#cap-rc08)、[CAP-RC10](#cap-rc10)。协作见 [RC-F06](../../../../packages/context/request-context/docs/key-flows.md#rc-f06)，成员与验证见 [RQ-02](../../../../packages/context/request-context/SPEC.md#rq-02-组装的前置输入)、[RQ-07](../../../../packages/context/request-context/SPEC.md#rq-07-扩展修改发起与固定采用)及 [RQ-VJ06](../../../../packages/context/request-context/SPEC.md#rq-vj06)。

<a id="rc-j07"></a>
#### RC-J07 长期工作接近窗口限制，保留未完事项再继续

用户希望长期会话继续工作，并保留仍要处理的信息。Request Context 检查完整输入预算；有适用的合法压缩路径时，只压缩允许的会话内容。摘要、压缩覆盖范围与保留名单共同形成追加 CompactionMessage，原历史和原标注不变。上次模型请求后尚未读取的新输入、未答等待及未结后台占位受保护，必须进保留名单或留在覆盖范围之后。范围内仍要原样给模型看的消息靠保留名单留下，不会被摘要截断。

压缩完成后重新取得完整模型可读 Context，再检查全部输入。固定部分本身超限、压缩后仍超限、必要限制未知分别说明。前两种失败使原消费契约指定的仍有效未终态 Run 失败，保留 Session、历史及已有结果；独立调用向调用方返回失败。系统不默认换模型、分叉、删历史或在相同条件下无限重做。

压缩若使用内部模型调用，其结果先按原调用及消费位置承接，再回压缩处理，不当作主流程回复。取消组装不证明该模型已物理停止，也不撤销已提交的压缩记录。中断恢复沿原内部调用接续，整条压缩记录（摘要、覆盖范围与保留名单）不能只恢复一部分，Model ACK 也不能提前清掉接续所需内容。

关联能力为 [CAP-RC04](#cap-rc04)、[CAP-RC08](#cap-rc08)、[CAP-RC09](#cap-rc09)、[CAP-RC10](#cap-rc10)。协作见 [RC-F07](../../../../packages/context/request-context/docs/key-flows.md#rc-f07)，成员与验证见 [RQ-05](../../../../packages/context/request-context/SPEC.md#rq-05-完整预算与候选完成)、[RQ-06](../../../../packages/context/request-context/SPEC.md#rq-06-压缩共同结果与保护边界)及 [RQ-VJ07](../../../../packages/context/request-context/SPEC.md#rq-vj07)。

<a id="rc-j08"></a>
#### RC-J08 故障或归档之后，认回原事实与当前资格

维护者恢复会话，用户希望已确认保存的注册、会话值、历史及采用依据仍能读取和解释。恢复方区分不可重算事实、外部当前值和可重建缓存，按原身份认回事实，再依当前资格取得共享与实时值。主动移除不装回，模式不重套租户默认，旧授权和历史不恢复已撤回的访问。

查询不可用保持未知，不能当作对象不存在或原执行未开始。Agent 换代不重发已存在的模型或工具调用；原结果、未结费用和消费位置继续保留。归档触发 Session 的业务取消并解除等待，不以所有独立执行物理停止为前提。迟到结果仍归原调用，不恢复推进；撤销归档回到 Session 定义的可接新工作状态，不复活旧工作。

确认后普通故障保证覆盖进程、操作系统崩溃和断电，不能用只做过重启检查声称全部满足。物理损毁恢复范围和开放资格仍由原拥有者决定。已展示在途内容的故障保留机制继续作为具名缺项，不降低保留目标。

关联能力为 [CAP-RC02](#cap-rc02)、[CAP-RC03](#cap-rc03)、[CAP-RC10](#cap-rc10)。协作见 [RC-F08](../../../../packages/context/docs/key-flows.md#rc-f08)，成员与验证见 [RC-06](../../../../packages/context/runtime-context/SPEC.md#rc-06-持久状态与恢复)、[RQ-09](../../../../packages/context/request-context/SPEC.md#rq-09-取消恢复与迟到)、[RC-VJ08](../../../../packages/context/runtime-context/SPEC.md#rc-vj08)及 [RQ-VJ08](../../../../packages/context/request-context/SPEC.md#rq-vj08)。

<a id="rc-j09"></a>
#### RC-J09 检查长会话为何等待或失败

有相应诊断资格的维护者，需要从一次读取或请求追查实际来源、采用范围、表示选择、预算与失败位置。Context 的供给与派生记录区分原事实和缓存，并分别计量当前读取、变化、历史扫描、模态读取、转换、物化与发送。当前点查询不能因历史增长每次重扫全量，但完整输出成本仍随读取量增长。

缓存缺口或重建未完成时不能报告完整成功，来源未知也不冒充不存在。诊断和遥测只按用途与实际接收方提供获准信息；错误详情、摘要、提醒、链接不能泄漏正文或秘密。取消诊断读取不清理原数据。故障后从持久依据解释旧请求，再重建可重算缓存，不用最新值冒充原采用。具体规模、计量方法与性能数值尚未采用，当前只有验证义务，未有实现通过结论。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC08](#cap-rc08)、[CAP-RC10](#cap-rc10)。协作见 [RC-F09](../../../../packages/context/docs/key-flows.md#rc-f09)，成员与验证见 [RC-08](../../../../packages/context/runtime-context/SPEC.md#rc-08-缓存资源与观测)、[RQ-10](../../../../packages/context/request-context/SPEC.md#rq-10-性能缓存与观测)、[RC-VJ09](../../../../packages/context/runtime-context/SPEC.md#rc-vj09)及 [RQ-VJ09](../../../../packages/context/request-context/SPEC.md#rq-vj09)。
