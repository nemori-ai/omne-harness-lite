# 运行感知与一次模型请求

状态：候选、待用户确认。本文定义用户可判断的产品规则。它不选择公开接口、存储、通信协议、转换算法或压缩策略。

## 产品需求描述

### 1. 用户需要持续感知当前工作条件

用户让 Agent 长期工作时，需要它知道自己属于哪个会话和租户、当前有哪些工作、使用什么模型、允许做什么。工具与扩展也可能需要读取相应数据。Runtime Context 按块提供这些消息之外的数据，每块有自己的来源和允许消费者。

用户重新进入老会话时，先看到最近一段获准历史，往前翻时继续取得更早内容，新记录在取得当前段后继续到达。人侧读取不以模型窗口裁剪历史。加载到哪属于读者状态，不改写会话事实。具体分页与交付入口由会话和交付面继续设计。

模型每次请求需要完整的适用输入。当前感知、历史提醒和这次实际交给模型的内容各有用途，用户应能追查一次请求采用了什么。保存历史不意味着模型、工具或扩展都能读到全部内容。Runtime Context 回答「现在是什么」。Request Context 回答「这一次交给模型什么、装不装得下」，见 [6.1](#61-request-context-的派生计算)。

### 2. 来源、会话选择和历史分别生效

Runtime Context 是作用域内共享数据的供给中介。它按块供给当前值，核对读取资格，把变化转交出去。它不拥有任何块的内容，不判断动作能不能做，也不组装模型请求。它只认识作用域持有者、生产者、消费者类和集成方这几种通用角色，不认识上层工作流的具体类型。

作用域持有者为一个作用域维护注册、签发读取资格，并在步边界提交状态块的更新。`0.0.0 -> 0.1.0` 阶段只有一个作用域持有者，就是会话（Session），一个作用域就是一个会话。

块的内容归它的来源。作用域持有者维护本作用域注册了哪些块、各块对到哪些需要、带什么参数，以及作用域自己选择或维护的值。注册不会把共享数据变成本作用域的资产。

移除一个可选块，只停止本作用域后续使用该注册。共享来源及其他作用域仍保留。恢复不能把用户主动移除的可选块装回。必需块不能用可选移除绕过，固定的会话与租户身份不能用内容更新改写。

已经发出的请求保留当时实际采用的内容。后来更新、撤权或移除不改写这次输入，也不撤回已经发生的工具效果。后续读取和动作须重新满足有效资格。历史快照、提醒和一次请求中的允许结论都不成为未来许可。

#### 2.1 两类块：供给块与状态块

runtime context 块是一个作用域里按块键识别的一份当前值。它回答「现在是什么」，值就地更新，不是一条事实流。发生过什么由会话历史回答，块不重复保存历史。块分两类，差别只在谁能改它的值。

- 供给块由一个生产者供当前值，读者只读。会话元信息、当前 ModelProfile、未结束后台工具都是供给块。这类事实只有一个权威来源，读者只需要它最近一次发布的值。
- 状态块由多个参与者提出局部更新，按块声明里的合并规则合并，由作用域持有者在步边界提交。同一份值要由几方在工作中共同积累时用它。例如人对授权询问的答复逐笔加进本会话语义授权，工具与扩展逐条增改未完成待办。

除供给块的生产者外，没有参与者能直接改写块的值。状态块的更新先是提案，持有者在一步结束时一并提交（见 [2.5](#25-状态块的更新与步提交)）。这样，同一步里几方的更新同时生效，读者不会看到只做了一半的一步。

块在故障或重启之后怎样回来，由块声明说明，分三种。

| 恢复方式 | 含义 | 例子 |
| --- | --- | --- |
| 持久保存 | 值本身可靠保存，恢复时按原值读回 | 会话模式、工作区选择、本会话语义授权 |
| 重读来源 | 不另存副本，恢复时向权威来源重新读取，并按当前资格取得 | 租户与组织元信息、账号偏好、当前 ModelProfile |
| 重算 | 从当前事实重新算出 | 环境元信息、未结束后台工具、窗口占用比例 |

持久保存的状态块按最近一次步提交的结果恢复。状态块也可以声明只在一次执行内有效、不持久。这样的块随该次执行结束而失效，恢复时不读回。

第一批状态块是本会话语义授权与未完成待办。其余必需感知都是供给块，见 [2.2](#22-块声明归语义拥有者)。

#### 2.2 块声明归语义拥有者

每种块有一份块声明。块声明由这个值的语义拥有者发布，也就是决定这份值是什么意思的一方。它不归存放这份值的一方，也不一定归生产者。本会话语义授权由会话保存，但人的答复要经授权一方解释才成为一笔授权表达，所以它的声明归授权。三个模式由会话供值，含义也由会话决定，所以声明归会话。

块声明说明以下内容。

- 块键。命名按语义拥有者划分。
- 值的形状。
- 允许哪几类消费者读：模型、工具、扩展、协调者。协调者是替作用域发起模型请求与工具调用的一方。允许某类消费者读，仍须满足具体内容的读取资格，不授予读取秘密、私有全文或外传的权限。
- 是否必需。必需块的范围见 [§3](#3-必需感知按内容及消费者供给)。
- 披露方式：按消费者类即可读，还是还要逐项核对内容资格。
- 快照和变化提醒能否带前值。
- 变化频率：稳定，或逐请求变化。逐请求变化的块只进请求最末的尾部易变提醒（见 [5.1](#51-首次注入锚定快照与追加提醒)）。
- 恢复方式（见 [2.1](#21-两类块供给块与状态块)）。状态块另外说明哪几类参与者能提更新、合并规则，以及是否持久。

全系统一个块键只有一份声明。两份声明会让同一个名字在不同参与者手里有不同含义，而这种错误不会报错。Runtime Context 本身不声明任何具体块，只按声明核对注册、读取和更新。

块声明不安装块，也不授权读它。谁供值，由生产者登记决定。生产者为一块登记供值后得到一个生产者句柄，用它发布新值、使当前值失效或撤销登记。生产者句柄有代际。生产者换代后，旧一代迟到的发布不被采用，不能覆盖新一代的值。使当前值失效只唤醒读者，读者读到什么以读取时的值为准，不按唤醒推断变化内容。

必需感知各块的声明落位如下。键名由各语义拥有者定稿，表中键为建议。

| 必需感知 | 键 | 类与恢复 | 语义拥有者 | 允许消费者类 | 变化频率 |
| --- | --- | --- | --- | --- | --- |
| 会话元信息：身份、创建时间、类型、日志版本 | `session.meta` | 供给块，持久保存 | 会话 | 模型、工具、扩展、协调者 | 稳定 |
| 会话元信息：权限处理、执行环境缺省与协作三个模式 | `session.modes` | 供给块，持久保存 | 会话 | 模型、协调者 | 稳定 |
| 会话元信息：逐工具执行环境策略 | `session.tool-environment-policy` | 供给块，持久保存 | 会话 | 模型、协调者 | 稳定 |
| 租户与组织元信息 | `identity.tenant` | 供给块，重读来源 | 身份 | 模型、工具、扩展 | 稳定 |

#### 2.3 需要、绑定与集成原则

消费者在自己的定义里用自己的形状声明上下文需要（下文简称需要）：要一个什么样的值、用来做什么、是必需还是可选。需要不点名任何块键。例如 Ask 元能力只需要知道「现在能不能与人交互」这一个是或否。授权一方只需要知道「动作仍需决定时怎么处理」：拒绝、问人，或跳过询问。它们都不认识会话的模式词。

集成方是知道各参与者、负责把它们接在一起的一方。作用域持有者在注册时是集成方，装配时负责接线的一方也是。集成方在注册时为每条需要写下一条需要绑定，把它对到一块。形状不同时，需要绑定附带翻译。

| 需要（消费者的形状） | 绑到的块 | 翻译 |
| --- | --- | --- |
| Ask：能否与人交互 | 三个模式中的协作模式 | `co-work` 为能，`auto-drive` 为不能 |
| 授权：动作仍需决定时怎么处理 | 三个模式中的权限处理 | `never` 为拒绝，`auto_permission` 为问人，`bypass-permissions` 为跳过询问 |

协调者为一次工具调用求设置时也是集成方。它读逐工具执行环境策略，求出这次调用的目标环境设置，随调用一并固定交给工具执行。工具执行与执行环境都不认识会话的模式词。

消费者经 Runtime Context 读到的，始终是它自己声明的形状，并带着来源块的证据。

块声明里的允许消费者类限制的是按块自己的形状直接读取。没有翻译的需要绑定按读者的消费者类核对来源块。带翻译的需要绑定由集成方写下并担保：Runtime Context 按集成方的消费者类核对来源块的资格，再把翻译后的值交给读者。读者不因此取得按块自己的形状读该块的资格。所以工具与扩展读不到三个模式本身，但能经集成方的翻译读到自己需要的那个值。

这套安排遵循一条集成原则：集成方知道被集成方，被集成方只对外声明自己供什么、要什么，用自己的词，不知道被谁集成。Runtime Context 是集成方选用的中介，不是让被集成方互相认识的通道。由此得出三条规则。

- 块声明归语义拥有者。「我供这个」与「我要这个」都是对外声明，都不点名对方。
- 需要以消费者自己的形状为准。块键只是集成方在注册时对上两边的手段。
- 翻译归集成方，不进生产者或消费者任何一方的约定。

后果是，同一个工具或同一套授权规则放进另一种产品组合时，自己的声明不用改，只换绑定。会话的模式词改变时，只改翻译，Ask 与授权不用跟着改。

必需的需要缺项时，依赖它的动作不可用。系统说明缺的是什么，不用空值、猜值或旧值代替。必需块的生产者暂时不在场时，注册照常成立，读者读到明确的缺项。作用域的创建不因某个生产者暂时不在场而失败，缺席在读取时如实可见。

#### 2.4 注册、读取资格与绑定读者

注册是作用域持有者为一个作用域固定下来的清单：这个作用域有哪些块、每块对到哪些需要、带什么参数。注册说的是「这里有这一块」，不是这一块当前的值。必需项在作用域创建时固定，之后不能移除。可选项可以增删，移除的后果见 [§2](#2-来源会话选择和历史分别生效) 开头。

有的块需要作用域级的参数。参数的形状由块的声明者定，值由持有者在注册时给出，Runtime Context 只校验值是否合乎形状。这样生产者不必猜每个作用域要什么，持有者也只能给声明里有的参数。

读取资格由作用域持有者签发给一次绑定。它写明作用域、消费者类、主体与租户、允许读的块键、允许的需要绑定，以及签发时的注册修订。允许读的块键授权读者按块自己的形状读这些块。允许的需要绑定授权读者读带翻译的需要，被翻译的块不因此进入允许读的块键（见 [2.3](#23-需要绑定与集成原则)）。读取资格只来自持有者签发，不能凭调用方所在的位置推断。读取资格只决定能读哪些块，不决定能做什么动作。

持有者可以撤销读取资格，撤销之后按它读取被拒绝。持有者也可以签发一份新资格取代旧资格，这叫重签。重签之后旧资格失效，按旧资格建立的读者沿新资格继续读取，读取不被拒绝。收窄授权范围也用重签，不必先撤销。

绑定读者按一份读取资格读取。它的消费者类在建立时固定，使用者不能改成别的类。例如工具不能把自己当成扩展，去读只给扩展的结构化授权。绑定读者每次读取都重新核对资格，所以撤权在下一次读取就生效，旧读者不能继续读到新内容。

绑定读者给出两种结果：当前的完整快照，或自上次读取以来的变化。授权范围变化、生产者换代或进程重建之后，上次读取的位置作废，读者要重新取完整快照。作用域持有者也可以主动使一个读者的位置作废，做法是重签该读者的资格。压缩提交之后，它对模型类读者这样做。

作用域引用是不透明的。Runtime Context 不解释它指的是租户、会话还是一次执行。作用域可以有父作用域。子作用域读一个块键时先查自己，再查父级。同一个块键在子作用域里的值遮蔽父级的值。`0.0.0 -> 0.1.0` 阶段只有会话一个作用域持有者，所以只有单层作用域。父级查找与遮蔽规则对以后出现的多层持有者同样成立。

#### 2.5 状态块的更新与步提交

步由作用域持有者划定。会话路径上，一步是协调者推进的一轮：从一次模型请求固定发出，到这一轮的动作结果全部回到持有者为止。持有者没有完整收到这一轮的结果，或结果被否决，这一步就是失败的步。

参与者对状态块提出的是上下文更新。上下文更新是提案，不是事实。一条更新只能指向状态块，提出它的一方必须在该块声明的写者之内。不满足这两条的更新不会成为事实。

作用域持有者在步边界收齐这一步的全部更新，按各块的合并规则合成一份步提交。步提交写成之后，这些更新才成为块的值。一步只有一份步提交。块可以声明每步只许一个写者。提交之后，模型可读的状态块按 [5.1](#51-首次注入锚定快照与追加提醒) 产生变化提醒。

失败的步里，已经成功的动作提出的更新保留为待处理，不进这一步的提交，由持有者决定怎样处置。这些动作的效果已经发生，例如人已经答复了授权询问，直接丢掉更新会让块的值与已发生的事对不上。把它们并进失败的一步，又会让一步失败看起来部分成功。

工具调用结果与 Agent 各阶段的结果都可以携带上下文更新。怎样携带，由工具执行与 Agent 定义与工作推进各自决定（见 [CONTEXT-M04](#context-m04)）。

第一批两个状态块按以下方式工作。

- 本会话语义授权：人对授权询问答复「本会话允许」，授权一方把答复解释成一笔授权表达，随这次动作的结果作为更新交回。这笔更新的提出者按承载动作结果的协调者计，所以它在这一块的写者之内。持有者在步边界提交，按先后追加，不覆盖先前的表达。模型可读这一块，所以每笔新表达产生一条变化提醒。
- 未完成待办：工具或扩展逐条增加、完成或移除待办，各自提出更新。持有者按条目合并后提交，一条的改动不覆盖其他条目。

### 3. 必需感知按内容及消费者供给

以下表格承接本候选必需感知候选范围。允许某类消费者读取，仍须满足具体内容的资格。它不授予读取秘密、私有全文或外传的权限。

| 块 | 来源及至少表达的内容 | 消费者 |
| --- | --- | --- |
| 会话元信息 | 会话身份、创建时间、类型、日志版本 | 模型、工具、扩展、协调者 |
| 会话模式 | 权限处理、执行环境与协作三个模式；执行环境模式可以逐工具设定 | 模型、协调者。工具与扩展经集成方翻译取得自己需要的值 |
| 租户与组织元信息 | 身份、名称、组织内角色及创建时间，由身份拥有者供给 | 模型、工具、扩展 |
| 账号偏好 | 通过租户关联取得可读的语言、时区、地区、明暗风格等已有偏好；不要求每项都有值 | 模型、工具、扩展 |
| Agent 元信息 | Agent 身份与本次采用的定义版本；会话路径中 Agent 身份对应会话身份，不随实例换代改变 | 模型、工具、扩展 |
| 环境元信息 | 宿主事实：平台（操作系统类型与版本）、当前日期（不要求精确到时分）、宿主能提供的设施、能确认的隔离与运行前提是否满足，由执行环境拥有者供给 | 模型、工具、扩展 |
| 当前落点 | 工具作用当前实际落在哪个执行环境，以及先前环境留下的痕迹是否仍在，由执行环境拥有者供给；尚未使用执行环境时如实表达为没有落点 | 模型、工具、扩展 |
| 当前 ModelProfile | 会话当前使用的合法档案内容，不包括不得披露的调用凭据 | 模型、工具、扩展 |
| 当前压缩设置 | Request Context 压缩策略当前生效的设置，包括触发界线与保留比例 | 模型 |
| 组织与租户结构化授权 | 两级分开供给的完整获准结构化授权，不由 Runtime Context 解析合并成许可 | 扩展 |
| 本会话语义授权 | 租户在本会话表达的授权或撤回、动作范围、单次或会话作用域、先后关系与来源；全局值沿租户权限取得 | 模型、扩展 |
| 工作区选择 | 逻辑工作区及实际地址或实例入口，可以为空，可表达多个 worktree 分工 | 模型、工具、扩展 |
| 未结束后台工具 | 原执行身份、所做事项、实际已知状态及查询或控制入口，适用时说明等待内容 | 模型、工具、扩展 |
| 未归档子会话 | 原关系、受派任务与已知状态；报告已交和仍可交互分别表达 | 模型、工具、扩展 |
| 未完成待办 | 身份、事项及当前未完成状态；不添未承诺期限、优先级或跨会话目标 | 模型、工具、扩展 |
| 窗口占用比例 | 当前实际上下文长度占有效模型窗口的比例，实时派生 | 模型 |

后台执行、子会话和待办只提供实际已知信息。查不到当前状态不能虚构进度、完成时刻或成功。窗口占用与压缩设置共同帮助模型判断主动压缩的代价，预算仍由完整请求校验。

当前落点承接[执行环境](../execution-environments/design.md#j-ee02-在有明确寿命的环境里持续工作)的要求：agent 必须能感知当前落点及上次痕迹是否仍在。表中的消费者列与 [2.2](#22-块声明归语义拥有者) 的允许消费者类同义。会话模式怎样到达工具与扩展，以及各块的语义拥有者、类与恢复方式，也见 2.2。

会话模式或装配不能取消必需感知。必需注册在场不代表来源永远可用。身份、授权或其他必要内容不可取得时，系统明确说明缺项或未知，不能用空白、猜值或旧许可伪装可继续。

### 4. 三个模式维度独立

模式事实由会话提供，Runtime Context 只供给当前值及变化。三个维度都可以在运行期变化，改变一维不自动改变其余维度。模式不能越过明确禁止或工作区的权限边界。

| 维度 | 有效值 | 用户可见结果 |
| --- | --- | --- |
| 权限处理 | `never` | 本应询问的动作按拒绝处理，不出授权询问。`Ask().request_approval` 不可用，其不可用原因可感知。 |
| 权限处理 | `auto_permission` | 按有效授权表达判断；没有结论时交获准的人决定，不由模型代批。 |
| 权限处理 | `bypass-permissions` | 放行本应询问的动作；明确禁止仍不可突破。 |
| 执行环境 | `always-allow` | 允许该工具的作用直接落宿主机，仍须满足动作授权与实际执行条件。 |
| 执行环境 | `auto_place` | 系统按实际条件求合适的执行环境，每次执行重新求值。 |
| 执行环境 | `never-allow` | 该工具绝不直接落宿主机，所需隔离环境到不了位时拒绝，不回退到更宽松落点。 |
| 协作 | `co-work` | 开启 Ask，具体命令仍受权限限制；不增加该模式的目标完成检查。 |
| 协作 | `auto-drive` | 关闭 Ask，增加目标完成检查，目标未完成不能正常收束；用户停止、取消、失败及授权约束仍成立。 |

切协作模式不创建新会话、不改变用途或定义身份，也不增加能力。切回 `co-work` 只移除协作模式附加的完成检查，作业会话自身强制检查仍在。

执行环境维度逐工具独立，适用于工具声明需要执行环境的情况。动作准不准仍由权限维度判断，获准落宿主或隔离不表示该动作已获准或一定成功。

没有显式模式初值时，采用适用租户默认，随后成为本会话的值。租户以后改变默认，不重写已有会话。重启、恢复、撤销归档和重新装配都不重新套默认。其他设置沿各自覆盖或继承规则，不能把这一条扩成所有值都只在创建时读取。

这个会话的租户可以改权限处理、执行环境和协作三个模式。Agent 不能直接写模式。Agent 要改模式，必须走 HITL，由人显式授权。Runtime Context 提供当前合法值及变化，不授予修改资格。自动归档默认关闭，允许显式开启；启用及时限由租户配置，常驻标记由具会话管理资格的用户维护自己的会话；开启或解除常驻沿已有连续空闲。常驻仅适用于主会话，不存在常驻子会话。具体时限及配置契约由设置与Session拥有者提供，本域不另定规则。

### 5. 当前值与变化感知

每次执行开始或挂接建立时，主动取得当时有权读取的完整当前快照。运行期间，模型可读块发生变化时追加变化提醒。工具或扩展私有块的变化只向获准消费者供给，不发给模型。

会话空闲时可以丢弃当前状态推送，下次执行开始或挂接建立时读取当前值。不必补世界上每一次中间状态，但不能丢弃已经受理的普通输入、控制或原结果。变化链记录本会话实际感知的变化。

状态变化提醒说明从什么变成什么，事件提醒说明发生了什么。提醒都追加，后一次提醒不覆盖前一次。完整状态快照允许可选携带前值，是否携带由该块的声明说明，不统一要求或禁止。

模型首次读取及压缩之后，提供当前允许模型读取的完整 runtime context，形式与位置见 [5.1](#51-首次注入锚定快照与追加提醒)。平时通过变化链保持理解，不能只取最新提醒。历史提醒可能过时，结构化授权仍从当前权威来源判断。

工作区 AGENTS.md 在实际首次进入相应子目录时加载适用指导，不因普通资产发现提前加载，也不靠资产 reload 代替。远端文件更新不承诺立即同步到 Runtime Context。

#### 5.1 首次注入、锚定快照与追加提醒

模型通过三种提醒看到 runtime context 块，每种有固定的位置。

| 提醒 | 放什么 | 位置 | 是否进会话历史 |
| --- | --- | --- | --- |
| 上下文快照提醒 | 当前允许模型读的全部稳定块的完整值 | 快照锚点 | 不进，只进请求 |
| 变化提醒 | 一个稳定块从什么变成什么 | 按发生顺序追加在历史中 | 进 |
| 尾部易变提醒 | 逐请求变化的块的当前值 | 请求最末 | 不进，只进请求 |

完整快照在以下情况重给：一次执行的第一次请求、新挂接建立之后、压缩之后，以及上次读取已经作废时（授权范围变化、生产者换代、进程重建）。其他时候不重给快照，变化靠历史中已有的变化提醒传达。是否需要完整快照，由 Runtime Context 按这个读者上次读到哪里、那次读取是否仍然有效来判断，不由发起请求的一方猜测。压缩之后的重给靠作用域持有者在压缩提交后使模型类读者的位置作废（见 [2.4](#24-注册读取资格与绑定读者)），Runtime Context 自己不认识压缩。

上下文快照提醒锚定在本次完整读取发生时的模型可见历史尾部。这个尾部不含本次请求承接的新输入。新输入排在锚点之后。在下一次完整读取之前，每次请求都把它放在同一个快照锚点。压缩之后重给的快照同样锚在当时的历史尾部。覆盖范围一直延伸到压缩点时，这个位置就在压缩记录之后。

快照不进会话历史，但它的位置必须稳定。位置一变，请求从那里起的内容就和上一次不同，前缀一致无法维持。锚点取当时的历史尾部而不取历史开头，这样新的一次执行开始时，旧历史仍排在前面、逐字不变。锚点取尾部也保证快照之后的历史都比快照新，模型不会在快照之后读到更早的变化提醒。

模型可读的块的值变化后，Runtime Context 算出变化材料：哪一块、从哪个修订变到哪个修订，以及按读者资格过滤过的前值。变化材料交给作用域持有者，持有者把它写成一条变化提醒追加进历史。曾经可读、现在无权读的前值不披露。块是否允许带前值，由块声明说明。快照本身不因变化而改动，模型依据快照加上其后的变化提醒链理解当前状态。

声明为逐请求变化的块，例如窗口占用比例，只进请求最末的尾部易变提醒。它每次请求重算，不进快照，也不产生变化提醒。这类值每次请求都不同。放进快照会让快照每次都变，生成变化提醒又会让历史每次请求多一条。

后台工具完成、外部捎话等事件不是块的变化，由各自的来源产生事件提醒。上下文快照提醒、变化提醒和尾部易变提醒都带来源标记。来源标记的取值由消息的拥有者统一维护，Runtime Context 与作用域持有者只使用这些取值。

### 6. 一次模型请求采用合法完整输入

系统提示词每次请求求值，本候选只含文本，不存成会话消息。普通新输入及其他需要本次承接的历史消息先可靠保存，再组装。实际使用的工具声明必须与合法绑定一致，不能给模型旧说明而执行新实现。直接调用与脚本编排的声明消费沿[工具可编程调用许可](../tool-execution/design.md#可编程调用许可)，本域不另定许可。

人侧和模型侧可见性逐块独立，四种组合都成立。消息类型提供常态去向，块标注决定实际选取。ToolInternalMessage 始终不进模型，缺少明确模型可读标注的块不进入请求。未完整工具调用可以保留原内容备查，但不执行，也不作为模型请求中的完整调用。

Tool 结果采用独立分流。附件区只成为地址文本，不进入媒体读取或模态约束；消息内容中的模型可见 ref 保留原引用，在 Model 真正请求时才加载二进制及完成必要转换。消息准入、历史投影和请求组装不得为了产生 transcript 提前读取这些字节。其他消息来源继续使用下述接纳前转换规则。

文字、图片、语音可以作为原生内容参与请求。按实际模型能力选择原件、适用派生表示或 transcript，多种可用表示的选择归明确策略。带模型读取标注的非文本块和文件进入转换规则，包括同时供人和模型读取的内容。纯文本及仅供人读取而没有模型读取标注的块，不被无关转换件否决。转换在消息接纳前完成，不因当前模型能读原件而跳过。消息接纳后，派生表示及 transcript 固定，后来更换转换件不能回填或改写既有历史。转换不覆盖原件，也不改原可见性。缺少转换能力与转换执行失败分别可查，不以空白或捏造文本冒充成功。

转换件共同技术契约由 [Model](../../../../packages/model/model-contract/SPEC.md#转换件的共同契约)拥有，以下仅说明本域接纳和表示采用的产品后果。本候选采用的转换件由系统装配，使用本地识别，不另调模型；组织或租户不按范围选择转换件。每次适用转换，转换件须交出至少一份合乎契约的其他模态表示及纯文本 transcript，派生表示不能是文件块。未登记对应转换件时，原块可按原规则保存但没有 transcript，实际可读性及合法模型约束继续判断；已经登记却不可用或转不成时按转换失败，不能借未登记分支落下无解释内容。用户能看出本次模型实际读到原件还是转换表示。

输入转换或消息准入被否决时，发送方得到拒绝原因，该输入不成为会话消息。模型回复被否决时，原调用真实收场与被否决事实保留，不冒充模型服务故障。原有效工作沿消息否决路径继续。连续否决不设次数上限，不因此使 Run 失败。独立或旁路回复沿原消费契约收场，不暗造 Run，也不改旧终态或恢复取消后的工作资格。工具结果的后果限于[压缩与未完工作](#7-压缩保留历史与未完工作)中的原消费契约。

完整预算同时计算全部系统提示词、历史、提醒、工具定义和实际发送的模态内容。精确字节、图片数等限制实际检查，token 可以采用适用估计与明确余量。未知限制保持未知，不编一个窗口或通用时限。

模型调用前扩展改变参数或内容时，重新组装或复核最终输入，包括资格、实际接收方和预算。同一次经过不重复触发该扩展位置。固定发出内容后，后来的设置、Runtime Context 或档案变化不改写原请求。

#### 6.1 Request Context 的派生计算

Request Context 是一次模型请求输入的派生计算与装入保证，与 Runtime Context 同在本 topic。它读取的全是别人拥有的事实：历史、runtime context 的读取结果、工具定义与绑定、模型档案与限制、提示词贡献和当前条件。它不拥有事实，不发请求，不固定采用，不写历史。

Request Context 对一组输入给出以下结果。

- 请求候选：系统提示词、工具声明、历史、提醒和表示决定都已就位的一份模型输入。同一组输入再算一次，得到同一份请求候选。
- 覆盖证据：逐项记录这次用了哪些输入及其修订。它包括历史范围、有效压缩记录、快照修订与快照锚点、提示词各段来源、档案与参数、工具声明、表示决定和预算，以及和上一次相比请求开头为什么变化。
- 装入裁定：装得下、固定部分超限、需要压缩、限额未知四者之一。限额未知不是失败。请求候选照常成立，真正发送时再按模型实际能力判断。
- 表示决定：每个内容块用原件、派生表示、transcript，还是留到发送时再加载。

一次组装只得到以下四种结局之一，没有第五种。

- 请求候选成立，还要经过模型调用前扩展。
- 请求候选成立，可以固定发出。
- 需要压缩。
- 装不下。

装入裁定与结局的对应：装得下与限额未知给出请求候选；需要压缩给出压缩计划，计划用完仍没有合法摘要时按 [7.1](#71-压缩计划与步骤) 归入装不下；固定部分超限直接装不下。

覆盖证据让「历史投影」与「模型实际看到的」可以对账。会话历史不含系统提示词和上下文快照提醒，所以两者并不相同。系统不把这两样也写进会话历史，而是让每次固定下来的请求带上覆盖证据。这样会话历史只保存对话本身，每次请求仍能凭固定请求记录与覆盖证据完整解释。

覆盖证据回答三个问题：模型这次看到了什么，和上一次相比什么变了，请求开头为什么变了。开头变化的原因记为以下之一：新的完整读取换了快照、系统提示词变了、工具集合变了、发生了压缩、扩展改写了已有内容、换了模型。

提示词贡献只有两类：有序段和变量。贡献者包括 Agent 定义、工作区指导、技能与元能力用法。贡献随贡献者存在，贡献者退出后，后续请求不再包含它的内容。日期、当前目录、模型名、窗口占用这类会变的运行事实不走提示词贡献，只走 runtime context 块。系统提示词拒绝逐请求变化的变量。系统提示词排在请求最前面，其中任何一处逐请求变化，都会让整份请求的开头每次不同。

一次请求的内容自上而下依次排列。越稳定的内容越靠前，变化只发生在尾部。

1. 系统提示词。
2. 工具声明。
3. 快照锚点之前的模型可见历史。有压缩时，它按 [§7](#7-压缩保留历史与未完工作) 的顺序开始：保留名单里的消息、压缩记录、覆盖范围之后到锚点之间的消息。没有压缩时，它是锚点之前的全部模型可读消息。
4. 上下文快照提醒，位于快照锚点。
5. 历史体：锚点之后的全部模型可读消息，按原顺序排列，包括变化提醒、事件提醒和本次新输入。
6. 尾部易变提醒。

前缀一致是优化目标，不是保证。系统提示词或工具集合需要变化时立即变化，不为保住已缓存的开头而推迟，覆盖证据记下原因。

### 7. 压缩保留历史与未完工作

压缩只处理允许的会话内容。在满足目标模型限制的硬条件内，兼顾前缀一致、信息保留和长度。一次压缩确定压缩覆盖范围：从会话历史的起点开始，到压缩点（这条 CompactionMessage 追加的位置）之前的某一处结束，并包含上一条 CompactionMessage。它为这段范围生成摘要，并点名范围内仍要原样交给模型的消息。这份点名就是保留名单。摘要、覆盖范围和保留名单共同形成追加的 CompactionMessage。

压缩之后，模型看到的历史依次是保留名单里的消息（按原顺序）、这条 CompactionMessage，以及排在覆盖范围之后的全部模型可读消息。覆盖范围可以在压缩点之前结束，范围之后、压缩点之前的消息照常出现。范围内没有保留的消息只以摘要形式出现。保留名单在压缩时固定，之后不变，所以后续请求的开头保持稳定。再次压缩时，新的覆盖范围包含上一条 CompactionMessage 和它的保留项；新压缩可以把它们再次列入保留名单，没有列入的进入新摘要。

压缩不删除原历史，不改原块内容或原可见性。用户仍能沿原资格查看原内容，也能知道压缩发生。

上次模型请求之后尚未让模型读取的新输入不能先压成摘要。未答等待和未结后台执行的占位不能压掉。这些未结工作要么进保留名单，要么留在覆盖范围之后。工具调用和它的结果在模型视图里同时出现或同时不出现：覆盖范围的终点不能把一次调用和它的结果分在两侧，除非调用一侧进了保留名单；两者都在范围内时，一起保留或一起摘要。压缩后重新供给完整合法 Context。原调用、未消费结果及账目不会因请求投影省略而消失。

固定部分本身超限，或合法压缩后仍装不下时，明确说明原因并保留会话和历史。会话路径使原消费契约指定的仍有效未终态 Run 失败；独立调用返回失败，不创建 Session 或 Run。不默认换模型、分叉、删除历史，也不在相同条件下无限重做。

Tool 结果消息准入或模态转换被否决时，原结果先可靠保管，使明确消费契约指定的仍有效未终态 Run 失败。后台、Run 外或原 Run 已终态时，不改旧终态、不默认挂后继、不造 Run，也不恢复取消后的入队资格。具体旁路后果由原消费拥有者设计，不能靠重跑外部效果取得另一份结果。

#### 7.1 压缩计划与步骤

装入裁定为需要压缩时，Request Context 为这份请求候选给出一份压缩计划。计划一并定下覆盖范围与保留名单，规则见 [§7](#7-压缩保留历史与未完工作)。计划里需要调用模型的步，由协调者发起调用，结果交回 Request Context 推导下一步。计划归 Request Context，调用归协调者，所以这次调用的费用、取消与恢复由发起它的一方记录，与 [RC-J07](#rc-j07) 中「先按原调用及消费位置承接」一致。

压缩计划由两种步组成，修剪步排在摘要步之前。

- 修剪步不调用模型。它只缩短交给摘要步的材料中过大的工具结果与媒体占位，不改原记录。
- 摘要步是一次内部模型调用，为压缩覆盖范围生成摘要。

修剪不单独改变模型之后看到的历史。模型看到什么，仍只由 §7 的压缩记录决定。修剪优先，是因为它不花模型调用，又能让摘要步的输入装得下、费用更低。

计划在给出时定下步数上界，之后不变。每完成一步，压缩计划进度恰好加一，由发起调用的协调者可靠保存，中断后从已完成的步接续。同一次请求准备至多进入一次压缩计划。步数用完仍没有合法摘要，或某一步被否决，按压缩后仍装不下处理（见 §7），不在相同条件下重开计划。

默认压缩策略可以替换。它的触发界线与保留比例是可配置的初值，具体数值归 Request Context 的实现说明，不是产品要求。当前压缩设置是这份策略生效中的一组配置值，不是另一个有身份的对象。它经必需感知块「当前压缩设置」供给模型，与窗口占用比例一起帮助模型判断主动压缩的代价。压缩设置由装配配置给出。设置改变只影响之后的装入裁定与压缩，不改已提交的压缩记录，并和其他稳定块一样产生变化提醒。组织、租户或会话能否调整压缩设置，见 [U04](#u04)。

### 8. 故障、恢复和数据保护

已经确认持久保存的注册、自有不可重算值、历史、采用与交接事实，在普通进程崩溃、操作系统崩溃或断电后仍可读取和解释。可从外部权威重取的当前值与可重建缓存分别处理，不承诺永久保存任意缓存。物理介质损毁后的恢复范围和开放资格不在这里代定。

恢复保留本会话值、注册及实际采用依据，再按现行规则取得共享与实时数据。失败步里保留为待处理的上下文更新随持有者的步记录一起保存，重启后仍可处置。撤权后不能从旧历史恢复访问。查询不可用保持未知，不能伪装成不存在或无工作；消费者更换不重发已经存在的调用。

可读不自动可发送。实际模型、工具、MCP 或遥测接收方改变时重新核对目的和内容。秘密不能因放入 runtime context 块、摘要、提醒、附件引用或错误详情而外泄，账目查看资格也不授予正文资格。

已经展示的在途内容有故障后可追查要求，兑现机制尚未闭合。不能默认允许丢失，也不能声称每片同步落盘。Model ACK 不是 Runtime Context、Tool 或历史的通用清理许可。

### 9. 本域保留的边界

Tool 内容 ref 与附件地址分流已有明确产品规则，MODEL-E01 跟踪共享块、消息校验和发送的技术兑现。本域只投影模型可见内容块及地址文本，不读取二进制，也不发明递归语法。

本候选不设计实时双工语音层的第三份投影，不恢复已经搁置的连接件入口，不定压缩算法、存储、Provider、公开签名、统一规模或时限。Cordis 负责装配集成，不证明恶意代码隔离。候选说明目标行为及缺项，不证明实际实现已满足。

当前语音沿普通完整输入及流式输出处理，不按播放进度改写历史或块标注。停止语音播放本身不等于取消原业务工作。

### 关键用户旅程

以下 RC-J 编号只定位本文旅程，不定义产品对象或公开操作。每条旅程解释前述规则的用户后果；跨域过程由相应拥有者推进，Runtime Context 只承担供给，Request Context 只承担派生。能力与旅程多对多，对应协作从[关键流程](../../../../packages/context/docs/key-flows.md)展开。

<a id="rc-j01"></a>
#### RC-J01 开始或接续工作，先理解当前条件

用户在已有合法会话中开始或接续工作，希望 Agent、工具与扩展按当前工作条件行动。会话作为作用域持有者维护注册和会话值，并供给会话身份。Agent 在每次执行开始或挂接建立时主动取得当前有权读取的完整快照。各消费者分别取得[必需感知](#3-必需感知按内容及消费者供给)，未完成待办、子会话和后台工具只呈现实际已知状态。来源不可用会表现为缺项或未知，不能伪装成没有工作。

这个会话的租户可以改变三个独立模式。没有显式初值的模式仅在创建时捕获适用租户默认。重新进入、恢复或重新装配沿用本会话值。Agent 要改模式，必须走 HITL，由人显式授权。Runtime Context 供给模式事实，授权、落点和完成检查分别由其业务拥有者执行。拒绝或必要条件缺失阻止依赖动作，不把模式快照当未来许可。取消此次读取仅结束该读取，不能撤回原调用效果。

执行开始或挂接建立时读取当前快照，与模型首次读取及压缩后取得完整模型可读 runtime context，是两个触发。运行中的合法变化继续形成追加提醒；空闲状态推送可以丢弃，下一次执行开始或挂接建立时读当前值。已经受理的输入、控制和结果仍可靠保留。完整快照的前值可选，状态变化提醒则表达获准披露的实际前后关系。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC03](#cap-rc03)、[CAP-RC04](#cap-rc04)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RC-04](../../../../packages/context/runtime-context-contract/SPEC.md#rc-04-读取时点观察与变化材料)、[RC-05](../../../../packages/context/runtime-context-contract/SPEC.md#rc-05-状态块上下文更新与步提交)及 [RC 持续验证义务](../../../../packages/context/runtime-context-contract/SPEC.md#持续验证义务)。

<a id="rc-j02"></a>
#### RC-J02 调整本会话感知，撤除后不再继续供给

有相应资格的会话使用者调整本会话注册或自有值，希望后续工作采用新选择。会话作为作用域持有者维护注册，块的内容仍归原来源。有效变更说明要增删哪一块、对到哪些需要、带什么参数，再影响后续供给。块的消费者、必需性与恢复方式沿块声明。可选移除只影响当前会话，共享源及其他会话保持各自事实。

必需块移除、固定身份改写或无权变更被拒绝。读取期间撤权时，旧缓存不能继续供应新内容；必要依据查不到时暂停依赖读取并保留未知。提交响应丢失不能解释为未保存，原拥有者按原操作查询和对账。用户取消等待不证明变更未提交。恢复保留主动移除及会话自有值，已发请求仍保留原采用依据，不把注册失效解释为撤回外部效果。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC02](#cap-rc02)、[CAP-RC04](#cap-rc04)、[CAP-RC10](#cap-rc10)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RC-02](../../../../packages/context/runtime-context-contract/SPEC.md#rc-02-块声明注册与参数)、[RC-07](../../../../packages/context/runtime-context-contract/SPEC.md#rc-07-生产者句柄并发撤除与恢复)及 [RC 持续验证义务](../../../../packages/context/runtime-context-contract/SPEC.md#持续验证义务)。

<a id="rc-j03"></a>
#### RC-J03 进入工作目录时取得适用指导

用户让 Agent 在选定工作区处理任务，希望访问子目录时遵守该处指导。实际首次访问尚未进入的目录，Runtime Context 协作取得有权读取的适用 AGENTS.md，保留来源、适用目录与采用依据。普通资产发现不会提前加载未访问目录，资产 reload 也不能替代首次访问加载。

无权或来源不可用时，系统不能声称已取得指导；依赖该指导的处理须按原消费契约报告缺项。取消本次读取不撤销已发生操作。恢复后仍须区分历史采用与当前资格，首次访问判据、合并和恢复协议尚待 CONTEXT-E02 明确，不能据此声称远端变化已即时同步。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC05](#cap-rc05)、[CAP-RC10](#cap-rc10)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RC-05](../../../../packages/context/runtime-context-contract/SPEC.md#rc-05-状态块上下文更新与步提交)及 [RC 持续验证义务](../../../../packages/context/runtime-context-contract/SPEC.md#持续验证义务)。

<a id="rc-j04"></a>
#### RC-J04 回看历史，并理解中断后留下了什么

有历史读取资格的用户重新进入会话，先取得最近一段获准历史，再向前读取更早内容，并接收之后的新记录。会话与交付面拥有这条读取路径，Request Context 提供同源块标注下的投影规则。读者加载进度不改变历史，模型窗口和压缩也不删人侧原件。人侧与模型侧各自按块资格筛选，读取账目不因此取得正文资格。

用户叫停或流中断时，已经交付的内容按原消息规则保留并能解释中断；无内容不造空回复。残缺工具调用可以留作备查，不能执行或作为完整模型调用输入。ToolInternalMessage 始终不进入模型。普通语音仍沿完整输入和流式输出处理，停止播放不等于取消业务。用户取消翻阅只结束对应读取；撤权后不从旧缓存取得新内容。已展示在途内容的故障保留尚缺兑现机制，不能默认允许丢失，也不能把重新打开历史声称为已验证恢复。

关联能力为 [CAP-RC06](#cap-rc06)、[CAP-RC10](#cap-rc10)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RQ-03](../../../../packages/context/request-context-contract/SPEC.md#rq-03-历史与块投影)及 [RQ 组合与验证](../../../../packages/context/request-context-contract/SPEC.md#组合与验证)。

<a id="rc-j05"></a>
#### RC-J05 提交图片或语音，并知道模型实际读取什么

发送方提交合法内容，或原消费方承接模型、工具结果，希望内容以模型可理解的表示参与后续工作。Tool 结果按内容 ref 与附件地址分流，实际请求才加载内容 ref；以下接纳前转换适用于其他消息来源。带模型读取标注的非文本块或文件，包括同时供人和模型读取的内容，进入[转换规则](#6-一次模型请求采用合法完整输入)。适用转换在消息接纳前完成，即使当前模型能读原件也不跳过；接纳后派生表示与 transcript 固定，原件和原标注保留。请求时再按实际模型能力选用原件、派生表示或 transcript，用户可以追查实际选用结果。

没有登记对应转换件，与已登记却不可用或执行失败，具有不同结果。前者允许按原保存规则保留没有 transcript 的原块，实际模型约束继续检查；后者不能伪装成前者或空白成功。纯文本、只给人看的块不受无关转换件否决。Tool ref 迁移和真实发送验证沿 MODEL-E01，未知嵌套分支不能宣称相容。

外部输入被否决，发送方得到原因，该输入不成为会话消息。模型回复被否决，保留真实收场并回原 Agent 的否决路径。连续否决不设次数上限，不因此使 Run 失败。Tool 结果先可靠保管；否决按原消费契约处置有效未终态工作。后台、Run 外或旧 Run 已终态时不挂无关后继，不改旧终态，不恢复取消资格。取消或故障后需要接续的是原结果及原消费位置，不能重跑外部 Tool 换一份结果。

关联能力为 [CAP-RC06](#cap-rc06)、[CAP-RC07](#cap-rc07)、[CAP-RC10](#cap-rc10)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RQ-04](../../../../packages/context/request-context-contract/SPEC.md#rq-04-模态与可追溯表示)、[RQ-08](../../../../packages/context/request-context-contract/SPEC.md#rq-08-失败否决与消费位置)及 [RQ 组合与验证](../../../../packages/context/request-context-contract/SPEC.md#组合与验证)。

<a id="rc-j06"></a>
#### RC-J06 发起一次能解释实际采用内容的模型请求

Agent、扩展或独立能力消费者需要发起模型请求。会话路径先可靠保存本次新输入，再取得合法历史、逐请求求值的文本系统提示词、匹配实际绑定的工具声明、模型可读 runtime context、有效档案与参数。Request Context 按实际发送表示计算完整预算。独立消费者可以提供合法输入使用计算能力，不必创建 Session 或 Run；读取托管数据及外发仍由集成方承担资格责任。

模型前扩展修改内容或参数后，重新组装或复核最终输入及实际接收方，同一次经过不重复触发该扩展位置。必要资格、绑定或来源缺失时不能发出伪装完整的请求。最终发起协调者固定采用依据后交 Model 执行，后续设置和 runtime context 变化不改原请求。可读不自动可发送，换接收方须重判。

取消组装只终止相应计算与等待。发出结果未知时按原调用身份对账，不能新建调用重发。恢复区分固定采用与当前条件，结果、费用及消费责任仍归原调用。预算超限的具体后果见下一旅程。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC06](#cap-rc06)、[CAP-RC07](#cap-rc07)、[CAP-RC08](#cap-rc08)、[CAP-RC10](#cap-rc10)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RQ-02](../../../../packages/context/request-context-contract/SPEC.md#rq-02-组装的前置输入)、[RQ-07](../../../../packages/context/request-context-contract/SPEC.md#rq-07-扩展修改发起与固定采用)及 [RQ 组合与验证](../../../../packages/context/request-context-contract/SPEC.md#组合与验证)。

<a id="rc-j07"></a>
#### RC-J07 长期工作接近窗口限制，保留未完事项再继续

用户希望长期会话继续工作，并保留仍要处理的信息。Request Context 检查完整输入预算；有适用的合法压缩路径时，只压缩允许的会话内容。摘要、压缩覆盖范围与保留名单共同形成追加 CompactionMessage，原历史和原标注不变。上次模型请求后尚未读取的新输入、未答等待及未结后台占位受保护，必须进保留名单或留在覆盖范围之后。范围内仍要原样给模型看的消息靠保留名单留下，不会被摘要截断。

压缩完成后重新取得完整模型可读 Context，再检查全部输入。固定部分本身超限、压缩后仍超限、必要限制未知分别说明。前两种失败使原消费契约指定的仍有效未终态 Run 失败，保留 Session、历史及已有结果；独立调用向调用方返回失败。系统不默认换模型、分叉、删历史或在相同条件下无限重做。

压缩若使用内部模型调用，其结果先按原调用及消费位置承接，再回压缩处理，不当作主流程回复。取消组装不证明该模型已物理停止，也不撤销已提交的压缩记录。中断恢复沿原内部调用接续，整条压缩记录（摘要、覆盖范围与保留名单）不能只恢复一部分，Model ACK 也不能提前清掉接续所需内容。

关联能力为 [CAP-RC04](#cap-rc04)、[CAP-RC08](#cap-rc08)、[CAP-RC09](#cap-rc09)、[CAP-RC10](#cap-rc10)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RQ-05](../../../../packages/context/request-context-contract/SPEC.md#rq-05-完整预算与候选完成)、[RQ-06](../../../../packages/context/request-context-contract/SPEC.md#rq-06-压缩共同结果与保护边界)及 [RQ 组合与验证](../../../../packages/context/request-context-contract/SPEC.md#组合与验证)。

<a id="rc-j08"></a>
#### RC-J08 故障或归档之后，认回原事实与当前资格

维护者恢复会话，用户希望已确认保存的注册、会话值、历史及采用依据仍能读取和解释。恢复方区分不可重算事实、外部当前值和可重建缓存，按原身份认回事实，再依当前资格取得共享与实时值。主动移除不装回，模式不重套租户默认，旧授权和历史不恢复已撤回的访问。

查询不可用保持未知，不能当作对象不存在或原执行未开始。Agent 换代不重发已存在的模型或工具调用；原结果、未结费用和消费位置继续保留。归档触发 Session 的业务取消并解除等待，不以所有独立执行物理停止为前提。迟到结果仍归原调用，不恢复推进；撤销归档回到 Session 定义的可接新工作状态，不复活旧工作。

确认后普通故障保证覆盖进程、操作系统崩溃和断电，不能用只做过重启检查声称全部满足。物理损毁恢复范围和开放资格仍由原拥有者决定。已展示在途内容的故障保留机制继续作为具名缺项，不降低保留目标。

关联能力为 [CAP-RC02](#cap-rc02)、[CAP-RC03](#cap-rc03)、[CAP-RC10](#cap-rc10)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RC-06](../../../../packages/context/runtime-context-contract/SPEC.md#rc-06-需要绑定与读者形状)、[RQ-09](../../../../packages/context/request-context-contract/SPEC.md#rq-09-取消恢复与迟到)、[RC 持续验证义务](../../../../packages/context/runtime-context-contract/SPEC.md#持续验证义务)及 [RQ 组合与验证](../../../../packages/context/request-context-contract/SPEC.md#组合与验证)。

<a id="rc-j09"></a>
#### RC-J09 检查长会话为何等待或失败

有相应诊断资格的维护者，需要从一次读取或请求追查实际来源、采用范围、表示选择、预算与失败位置。Runtime Context 的供给记录与 Request Context 的派生记录区分原事实和缓存，并分别计量当前读取、变化、历史扫描、模态读取、转换、物化与发送。当前点查询不能因历史增长每次重扫全量，但完整输出成本仍随读取量增长。

缓存缺口或重建未完成时不能报告完整成功，来源未知也不冒充不存在。诊断和遥测只按用途与实际接收方提供获准信息；错误详情、摘要、提醒、链接不能泄漏正文或秘密。取消诊断读取不清理原数据。故障后从持久依据解释旧请求，再重建可重算缓存，不用最新值冒充原采用。具体规模、计量方法与性能数值尚未采用，当前只有验证义务，未有实现通过结论。

关联能力为 [CAP-RC01](#cap-rc01)、[CAP-RC08](#cap-rc08)、[CAP-RC10](#cap-rc10)。协作见[组内流程](../../../../packages/context/docs/key-flows.md)，成员与验证见 [RC-08](../../../../packages/context/runtime-context-contract/SPEC.md#rc-08-缓存观测与遥测)、[RQ-10](../../../../packages/context/request-context-contract/SPEC.md#rq-10-性能缓存与观测)、[RC 持续验证义务](../../../../packages/context/runtime-context-contract/SPEC.md#持续验证义务)及 [RQ 组合与验证](../../../../packages/context/request-context-contract/SPEC.md#组合与验证)。

### U03 个人 Context 的组织影响范围

已有账号偏好按[必需感知](#3-必需感知按内容及消费者供给)供给可读的语言、时区、地区、明暗风格等，不要求每项都有值。这部分不是待重新选择的偏好清单。

组织可以影响哪些个人 Context 内容及其适用范围，仍缺产品说明，由 Runtime Context 产品拥有者承接。缺项使用户尚不能据此判断组织能影响自己哪些偏好，不授予组织修改个人偏好的能力，也不由本域补定偏好或组织政策。个人 Context 与治理配值分别成立；已有租户隔离、来源读取资格及消费者边界保持，阶段与版本支持范围不变。

### U04 压缩设置的调整范围

当前压缩设置由装配配置给出，见 [7.1](#71-压缩计划与步骤)。组织、租户或会话能否在各自范围内调整触发界线与保留比例，产品尚未决定。只允许装配配置时，同一部署内行为一致，租户与用户不能按自己的工作调整。允许租户或会话调整时，还要定下谁有资格调整、允许的范围，以及与装配值的先后关系。

缺项不影响默认策略的使用，也不授予任何一方调整资格。由 Runtime Context 产品拥有者会同设置拥有者决定。

<a id="u06"></a>
### U06 由技术设计推导、待确认的三处写法

下面三处由 Context 成员的技术设计推导，已写进本页或成员契约，产品负责人尚未确认。确认之前它们按候选执行。改变任一处时，同步修订 [runtime-context-contract](../../../../packages/context/runtime-context-contract/SPEC.md) 与 [request-context-contract](../../../../packages/context/request-context-contract/SPEC.md) 的对应条款。

- **变化频率多一个值。**[§2.1](#21-两类块供给块与状态块) 只列稳定与逐请求两种。契约 [RC-02](../../../../packages/context/runtime-context-contract/SPEC.md#rc-02-块声明注册与参数) 多一个 `per-step`：状态块在步提交后变化，只产生变化提醒，不进尾部易变提醒。产品若只保留两种，契约删去这个值，状态块按稳定处理。
- **读取资格带允许的需要绑定。**[§2.4](#24-注册读取资格与绑定读者) 写明读取资格含允许的需要绑定。这一项为带翻译的需要而推导：没有它，读者要么读不到翻译后的值，要么得到按块原形状读取的资格。
- **窗口占用比例的时点。**[§3](#3-必需感知按内容及消费者供给) 写这个比例实时派生。契约取该作用域最近一次固定请求的占用比例（[RQ-02](../../../../packages/context/request-context-contract/SPEC.md#rq-02-组装的前置输入)）：读取先于组装，读取时本次请求的占用还不存在，所以模型看到的值落后于本次请求。产品若要求本次请求的占用，需要改变读取与组装的先后。

由 Runtime Context 产品拥有者确认。缺项不改变已有的租户隔离、读取资格与消费者边界。

### CONTEXT-E01 工具引用式结果的技术兑现

工具消息内容中的多模态 ref 供模型直接感知，附件区只产生文本地址，由 agent 决定另行读取。Request Context 不在消息组装阶段读取二进制，实际请求阶段由 Model 加载所选内容 ref。该产品规则已明确，任意嵌套语法没有因此获准。

共享内容、消息、Tool、Model 与 Request Context 须共同实施并验证，不能把设计存在当支持声明。技术义务见[MODEL-E01](../../../../packages/model/model/docs/architecture.md#model-e01)。
