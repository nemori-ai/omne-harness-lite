# PF-012：Agent Loop 与 Run

**一次运行到底怎么走完，停机之后又怎么接着走——本 topic 回答。**

前面几个 topic 各自定了 agent 能做什么（[PF-006](../PF-006-tools-and-skills/README.md)、
[PF-007](../PF-007-meta-capabilities/README.md)）、什么时候停下来等人（[PF-008](../PF-008-human-in-the-loop/README.md)）、
它由什么装配而成（[PF-004](../PF-004-agent-definition-and-assembly/README.md)）、
留下什么（[PF-000](../PF-000-occurrences-and-record-entries/README.md)）、
怎么组装给模型看（[PF-010](../PF-010-context-management-and-assembly/README.md)）、
跑偏了谁接手（[PF-011](../PF-011-off-nominal-handling/README.md)）。
**没有人回答的是：这些东西串起来，一次运行是怎么往前走的。**

一句话概括本 topic 的结论：

> **Run 是数据，Agent Loop 是方程。**
> 状态存在[会话日志](design.md#会话日志)里，下一步由方程算出来——**所以停机不可怕，重算一遍就是了。**

## Run 与 Agent Loop

| | **[Run](design.md#run)** | **[Agent Loop](design.md#agent-loop)** |
|---|---|---|
| 是什么 | **数据 / 治理**的概念 | **执行逻辑**的描述 |
| 回答什么 | 这次运行是什么、归谁、**现在到哪一步了** | **从这一步怎么走到下一步** |
| 形态 | 可记录、可查、可审计的状态 | **状态转移方程** |
| 缺了它会怎样 | 停机之后**不知道当时在哪** | 知道在哪也**算不出下一步** |

**两个都要，缺一个恢复就不成立。**

**而 Run 的边界，两句话说得完：**

> **有还没被[承接](design.md#边界什么让它开始什么让它结束)的输入、而且没有未终结的 Run，就开始一个；
> 落一个[终态](design.md#运行终态)，才结束。**
> **[队列不是真相，是日志的投影](design.md#待处理消息队列)**——已记录的输入减去已被承接的。

**「触发」与「收束」因此不是两个独立概念，是这条规则的两端**——
触发就是**让队列从空变非空的那件事**，收束就是**再没有可承接的输入、这个 Run 落终态**。
[什么东西会进队列、插队怎么被受理](../PF-014-inbound-intake-and-queueing/README.md)归 PF-014。

**Run 存在的全部理由，是让下面这个判断只读日志就答得出来：**

> **把系统关机、抹掉全部内存、只留[会话日志](design.md#会话日志)，重新开机后必须答得出
> 「现在该不该起一副 agent runtime、它接手什么」，且答案唯一。**

**所以「[Run 未终结](design.md#run-未终结不等于有一副-agent-runtime-活着)」不等于「有一副协程活着」**——
一个等人三天的 Run，三天里一副协程都没有，[而它好端端悬在日志上](design.md#只看日志该不该起一个-agent-runtime)。

## 方程

```text
下一步  =  f ( 会话日志 , 当下条件 )
```

**`f` 是纯的。**同一份日志配同一份[当下条件](design.md#当下条件)，算出来的下一步唯一。

> **恢复不是「接着上次的进程」，是「重新算一遍 `f`」。**
> 而且[**它不是异常路径**](design.md#57-一次尝试三条路通向重新算一遍)——
> 系统崩了、等人回来、 agent runtime 换了一副，**三条路在方程眼里是同一件事**。

## Run 是三样东西的归属单位

**成本 · 失败 · 收束。**三样回答的是同一个问题——**这一次要做的事，怎么样了**。

分给不同的单位，这个问题就要跨三个对象拼，而它们的边界不一样。
**检验它的是这句话：「这次失败的任务，一共花了多少钱？」**

> **一次 Run 可能有好几次[执行尝试](design.md#执行尝试)**，而**账单上还是一笔**——
> [明细按尝试记，汇总按 Run 算](design.md#成本两层缺哪一层都会算错)。
> Run 是逻辑的，尝试是物理的；**尝试的身份是 (哪个 Run, 第几次)，从日志派生，不另存。**

## Loop 拓展点

**位置不是挑出来的，是推出来的：**

> **每个[状态点](design.md#53-改日志的动作与纯派生的动作)有紧前与紧后两条边，每条边就是一个位置。**
> 六个状态点十二条边，**只有「尝试开始之前」不归本 topic**，[其余十一条全部开放](design.md#十一个位置是推出来的不是挑出来的)。

**尝试开始之后 · 消息落盘之前 · 消息落盘之后 · 压缩之前 · 压缩之后 · 调模型之前 ·
调模型之后 · 执行动作之前 · 执行动作之后 · 落终态之前 · 落终态之后**

**位置没有编号，就叫它站的那个名字。**

> **「消息落盘之前」不属于某一步，每有一条消息要落盘就经过一次**——
> 不论它是用户说的、模型吐的还是工具交回来的。四件最要紧的事都发生在那一刻：
> **脱敏 · 敏感信息识别 · 提示词注入与攻击检测 · 把收不下的模态转成收得下的**。
> [日志只增不改](design.md#会话日志)，**落盘之后再想脱敏，原文已经永久留在那儿了**。
> **对模型的回复只能整份否决、不能改写**——用户多半已经在流式里看完了原文。
> 见 [§5.8](design.md#消息落盘之前每条消息都经过它不只是输入)。

**位置按它站在哪命名，不按挂在那儿的功能命名**，所以——

| | |
|---|---|
| **同一个位置可以挂多个[拓展件](design.md#拓展件)** | **落终态之前**同时站着「打转保护」和「没达成目标就别停」，**各干各的** |
| **位置的数目不随功能增长** | 功能没有上限，位置**十一个** |
| **拓展件是[第八类资产](../PF-002-assets-settings-and-permissions/design.md#loop-extension)** | 组织超管配一份、租户覆盖或收窄，**走资产已有的那一套**。**例外：模态转换件本版不是资产**，[只随系统装配](../PF-013-model-profiles-and-invocation/design.md#转换件)，组织与租户换不了 |

**系统自带的几件，各站在一个位置上**，它们不享受特权——只有三处往严里走：
[不可用时由系统预先声明的指定挂件顶上](design.md#系统自带的几件不可用时各有定法)（放行判断那一格是全拒件），**放行判断那一件不能被替换、禁用或收窄**，
**模态转换那一件本版组织与租户换不了**（[它本版不是资产](../PF-013-model-profiles-and-invocation/design.md#转换件)；重试那一件租户可以换成自己的）：

| 挂件 | 站在 | 谁拥有 |
|---|---|---|
| **循环探测** | **调模型之后**（收场＝完整回复） | 本 topic |
| **放行判断** | **执行动作之前** | [PF-008](../PF-008-human-in-the-loop/README.md) |
| **卸载判定** | **执行动作之后**（范围＝这一个） | [PF-006](../PF-006-tools-and-skills/README.md) |
| **模态转换** | **消息落盘之前** | [PF-013](../PF-013-model-profiles-and-invocation/README.md) |
| **重试** | **调模型之后**（收场＝失败） | [PF-013](../PF-013-model-profiles-and-invocation/README.md) |

**标题不写数目**——**数目会变**，写进标题就等于每加一件都要改一次标题。

> **[循环探测与卸载判定不在转移表里](design.md#循环探测的四种结局全落在已有的行上)。**
> 它们站在位置上，**跑完它们 `f` 的取值不变**；
> 而循环探测的四种结局——无事、写一条干预消息、判定转不动了、判定要问人——
> **全都落在表里已经有的那个尾巴形状上，一行转移都不用补**。

**不管挂什么，都只有一条通路：**

> **只能靠改[会话日志](design.md#会话日志)起作用 · 不改方程本身。**

**这一条护着 `f` 的纯性**：能不留痕地改变下一步，重算就得到不同结果，
**整套恢复机制塌掉**。[LangChain 那种「挂件自己循环调下一层」的写法因此装不进来](design.md#三种形态两种装得进一种拆两半)。

> **可否决那一档还能让 Run 停下来等人**：落一张卡片，用的是 loop 主流程等模型、等工具、等人的
> [同一个原语](design.md#等人是-loop-的原语)——**放行判断就是这样问人的**，租户的拓展件也一样。
> 等待靠日志撑着，协程没了照样接着等。**但没有[「放宽」这一档](design.md#没有放宽这一档)**：拓展件拦得住，放不宽。
>
> **拓展件是装了才有的可插拔服务**：[不可用按它的拓展件不可用处置办——租户挂上的默认跳过、注册时可声明为否决；可用却报错按它那一类的策略办](design.md#拓展件是可插拔的服务不可用即卸载报错按策略)；
> 系统自带的几件不可用时[由系统预先声明的指定挂件顶上](design.md#系统自带的几件不可用时各有定法)，
> **放行判断那一格是全拒件：安全组件不在时停工，不裸奔**。
