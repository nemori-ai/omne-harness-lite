# 2026-10-06：日志事实与模型消息投影

来源：本工作树同会话用户输入。以下逐字摘录只记录本次要求，不提升其他修订的接受状态。

> 对于 packages/session 相关的，你必须要明确（除了 runtime context 那块的）现有实现都不是正式的哈，所以该重构的要重构。

> session log 原则上我们要求应该是 event、message 都是 log 的一种子类型或者应该是 log 的一个字段，但是现在似乎 event （比如 attempt event）也被包装成了 SystemReminderMessage 发给了模型，这是不行的

> 会话调用一次模型的时候，应该是从 session log 来算出请求模型的消息列表投影，而且我们要求它应当至多是 O(n) 复杂度的，不然性能会有问题，而且最好是 O(1) 或者 O(logn) 的复杂度，最好还有某种缓存能够前缀复用以及在前缀发生改变时候重算并再次缓存

限定采用：尝试开始是非消息日志事实；不自动作为模型消息。派生视图允许缓存，输入变化须失效重算。复杂度的计量单位、完整输入、输出成本和缓存机制由技术设计明确，不从本次要求推出任何性能时限或数值预算。业务提醒和真实调用中断原因保持各自规则。
