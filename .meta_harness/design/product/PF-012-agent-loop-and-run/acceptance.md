# PF-012 验收标准

---

## 一、可观察的场景

| # | 场景 | 通过的样子 |
|---|---|---|
| **S1** | 一次运行正常跑完 | 日志里**只有那几个改日志的动作留下了痕迹**；组装跑了两次也一条都没多 |
| **S2** | 崩在「工具调用发出去了，结果没落盘」，那次执行随据点一起没了 | **追补一条占位的 `ToolMessage`，原因写「工具执行异常中断」**，照常走 T7——**系统不重发那个动作**，agent 读到之后自己决定要不要再调；它读到的收场是失败，**不是「被中断」** |
| **S3** | 崩在「模型已给完整回复，终态没落」 | **幂等收尾，一次模型都不再调** |
| **S4** | 等人时 agent runtime 被回收，人回话之后接着跑 | **还是原来那个 Run**；**对账什么都不用补**（上一次是正常停住的）；用户看到的是他的问题被接上了 |
| **S5** | 同一次 Run 换过两个 agent runtime | **账单上还是一笔**（明细分两次尝试记），失败也只有一笔——**不会变成两个 Run** |
| **S6** | 靠反复崩溃想洗白打转记录 | **阶梯不重置**，崩多少次都一样——因为它是从日志里数出来的 |
| **S7** | 把某件拓展件上次的判断留在日志里，保持完整输入和求值规则不变，重算一遍 `f` | **算出来的下一步与当时完全相同**，且**有结论的那件一次都没被重跑**（还在等人的那件见 S53） |
| **S8** | 「只观察」那一档的拓展件报错，它那一类没另定策略 | **正在发生的事照常**，一步都不受影响 |
| **S9** | 「可否决」那一档的拓展件报错，它那一类没另定策略 | **当作否决**，**且这件事本身可见**——不是悄悄放过去 |
| **S10** | 「可改写」那一档的拓展件报错，它那一类没另定策略 | 事情照常，**但日志里留得下「它没跑成」**——排查的人分得出这与「它说不用改」的区别 |
| **S11** | 压缩闭包交不出装得下的东西 | **两件事同时发生且各留一条**：上交给会话、Run 落终态失败（按实际来源区分固定部分超限与压缩后的会话上下文仍超限） |
| **S12** | 一件非常态被上交到会话层之后 | **Run 已经是终态了，而那件事还在往外交**——租户那一层照样会接到它 |
| **S13** | 循环守卫 L3 结束了一个 Run | **落终态失败，不往上交**——它不是非常态 |
| **S14** | agent 打转打到触发了压缩 | **阶梯照数不误**——窗口取自会话日志，而[日志里一条都没被擦除、也没被改过](../PF-010-context-management-and-assembly/design.md#612-记录里的消息一条都不能擦除) |
| **S15** | 一批动作全被人否了 | **照样回 T1 走一遍模型**——否则它下一轮还会再发一次 |
| **S16** | 有东西转到后台还没回来 | 那个占位**不会被压缩点名**——agent 始终知道自己还有东西在外面跑 |
| **S17** | 外面来的事在 Run 等人的时候到达 | **照常收进日志**，解除阻塞之后**一起**看到 |
| **S18** | 同一份日志配同一份当下条件，算两次 | **下一步相同**。换一份当下条件（比如某个能力没了）**允许不同** |
| **S19** | 在**落终态之前**挂一件「没达成目标就别停」的拓展件，它判定没达成 | **这次不收束，接着转**——它否决的是**停下来** |
| **S20** | 同一件报了错，按默认策略 | **仍是否决停下**，接着转；**这件事本身可见** |
| **S21** | **同一个位置挂两件**（比如落终态之前同时有打转保护和目标判定） | **两件都跑**，[依次过](design.md#三种形态两种装得进一种拆两半)，**各留各的条目** |
| **S22** | 在**调模型之前**挂一件会改日志的拓展件 | **重新组装一次再发**，且**不再回到这个位置**——[同一位置同一次经过只跑一轮](design.md#改了日志就重新组装同一位置同一次经过只跑一轮) |
| **S23** | 问 loop「这一轮上下文超了没有」 | **它答不上来，也不需要答**——它只收到[压缩闭包](design.md#55-想这一步交进闭包拿回装得下的一份)交回的「装得下 / 装不下」 |
| **S24** | 换掉整套压缩策略（判定时机、压哪一段、摘要怎么写全变了） | **[状态转移表](design.md#56-状态转移表)一个字不用改** |
| **S25** | 换掉循环探测的实现（阈值、算法、判定口径全变了） | **转移表一个字不用改**——[四种结局仍落在已有的行上](design.md#循环探测的四种结局全落在已有的行上) |
| **S26** | 把循环探测整件拿掉 | **loop 照转**，只是没人管原地打转了 |
| **S27** | 一件拓展件自己调了一次模型做判断 | 那笔钱**算进它插手的那个 Run** |
| **S28** | 一次**不属于任何 Run** 的模型调用（旁路提问那种） | 它的花费**不被硬塞进任何 Run**，归会话那一级 |
| **S29** | Run 停在「等人」上，**观察它占用的计算资源** | **一份都不占**。停住是[这次尝试的出口](design.md#这个循环从哪里出去)，不是在原地反复问 |
| **S30** | 在**消息落盘之前**挂一件脱敏拓展件，送进一条带敏感信息的输入 | **日志里从头到尾没有原文**——不是「先落盘再改掉」 |
| **S31** | 在同一位置挂一件注入检测拓展件，它判定这条输入是攻击 | **那条输入不进日志**，也因此不进[方程的定义域](design.md#方程从日志里读什么) |
| **S32** | 会话未归档，Run 已落终态，一个后台结果**在那之后**才回来 | 结果**照样落进日志**、**那个 Run 的终态不变**；同时它**进了[队列](design.md#待处理消息队列)**，于是**开出下一个 Run 来看它**——**不复活这一个，不等于没人管** |
| **S33** | 用户说「**跑那个构建，好了告诉我**」，构建两小时后才完，那次 Run 早已收束 | 结果回来时**自动开出一个新 Run**，用户被告知——**不需要他先说话才发现** |
| **S34** | Run 正跑着，用户又说一句（**不插队**） | **同一个 Run 接着消费它**，不另起一个；**日志里多一条承接记录** |
| **S35** | 模型这一步**没给动作**，但队列里还有东西 | **Run 不结束**，回去取下一批 |
| **S36** | 模型这一步没给动作，**队列也空了** | Run 落「**完成**」 |
| **S37** | 同一件脱敏拓展件挂着，这次是**模型吐出**一段含敏感信息的回复 | **日志里同样没有原文**——**这个位置不只管输入**，模型吐的、工具交的一视同仁 |
| **S38** | 挂一件把图转文本的拓展件，送进一张图 | 日志里**那个内容块原样还在**，**转换出来的那几份（至少一段纯文本兜底）在落盘那一刻就一起在了**；随后换一个收得下图的模型，**用的仍是原图** |
| **S39** | 用户在 Run **等工具结果**时取消 | 终态落**被取消**；那个在途执行按 [PF-006](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)落一条「**被中断**」的占位，**不是失败** |
| **S40** | 一个 agent **不打转、一直在干新活**，没人挂预算守卫 | **系统不会自己停它**——这是[已知且有意的边界](design.md#方程不保证这个循环会停)，不是缺陷 |
| **S41** | Run 正跑着，用户发了一条**带插队命令**的消息 | 那条消息**排到队首**、loop 里**各种等待态一并解除**；**这个 Run 不落终态**——它只是被推到了下一次取消息那一点 |
| **S42** | 停机，重启，观察队列 | **一条都没少**——队列是[日志算出来的](design.md#待处理消息队列)，不是另一份权威；可以持久化派生投影 |
| **S43** | **把系统关机、抹掉全部内存，只留会话日志，再开机** | **只读日志就答得出「现在该不该起一副 agent runtime、它接手哪个 Run」，而且答案唯一**（[那张表](design.md#只看日志该不该起一个-agent-runtime)）。答不出或有两个答案，就是**还缺条目** |
| **S44** | Run 正跑着，队列里又落进两条；随后停机，重来 | **新的一次尝试取用的顺序与上次相同**——因为每一次承接都落了一条记录，[并入点是日志事实](design.md#run-跑着的时候又进来一条东西) |
| **S45** | 同一个 Run 崩了三次，问「这次任务花了多少」 | 账单按 Run 汇总，明细保留调用与原发起尝试，接续不重复计费；只按真实重发／损失依据识别额外开销，不用“总成本减最后尝试成本”算浪费 |
| **S46** | 某个外部效果在第 2 次尝试发出，第 3 次尝试重来到同一步 | **两次算出来的幂等键完全相同**（对方不会做第二遍）；**两条记录的尝试序号不同**（查得出各是哪一次）。[两个字段，方向相反](design.md#幂等键与追溯标识必须是两个字段) |
| **S47** | 崩在「效果已经发出去、结果还没写回日志」 | 那条记录的结果是「**不知道**」；恢复时**不当作没发生**——[要不要重做看幂等键，不看有没有结果](design.md#不知道这个值不能省) |
| **S48** | 用户**强制停止**一个正在跑的 Run | 先落取消请求，再撤销尝试推进资格并按关联通知模型／前台工具；无 Agent runtime 也照做；终结条目由**会话这一侧**写，终态＝被取消，**并标注「可能存在未收尾的外部效果」**（[三步闭环](design.md#强制停止的三步闭环)） |
| **S49** | Run 在**等人**，此刻一副协程都没有，用户说「别弄了」 | **取消照样成立**——[作用对象是 Run，不是协程](design.md#615-取消先落日志再发信号) |
| **S50** | 一副被判定已死的协程又活了过来，试图往日志里写 | **推进运行的记录写不进去**——[只有序号最大的那次尝试能继续推进运行](design.md#同一个-run-同一时刻只有一副协程在推它) |
| **S50a** | 旧尝试被取代后，它已经发出的调用才交回响应体或账 | 结算仍落下、仍归该 Run、标明迟到；不能借此继续推进旧尝试或复活运行 |
| **S51** | 日志里留着一条「有开始、没有配对结束」的尝试 | **恢复照常进行**，不报数据损坏——[来不及写结束条目是常态](design.md#617-run-这一层的七条不变式)（I-15） |
| **S52** | 一件租户挂的可否决拓展件在执行动作之前**出一张自己写选项的卡** | 卡片进池子，**Run 停在等人**，与放行判断出的卡**同样的待遇**；卡片记录里**标得出是哪一件出的** |
| **S53** | 接 S52：卡片悬着时系统崩了，之后人答了 | 新的一次尝试**回放**那件拓展件：**一张新卡都不出、它先前调过的模型一次都不再调**，走到出卡那一处拿到的就是那笔答复，接着下结论（[原语](design.md#等人是-loop-的原语)） |
| **S54** | 一次回复里三个动作，第二个要问人 | **三个都先判完**，卡片**成批**落；被放行的第一、三个**也等这一批答完才执行** |
| **S55** | 答完之后，瀑布里排在后面的一件又要问人 | **同一批动作出现第二轮卡片**，照样成批、照样全答完才往下走 |
| **S56** | 一件拓展件只有「只观察」或「可改写」 | **它出不了卡**——等人是[可否决那一档](design.md#干预力三档直接用-pf-000-的)的 |
| **S57** | 放行判断算出「问一下」，一件拓展件（或从别家搬来、带着 `allow` 的 hook）想把它改成放行 | **改不了**——卡片照出；那个 `allow` 在这里**只算「无意见」**，导入时已明示（[没有放宽这一档](design.md#没有放宽这一档)） |
| **S58** | 一件拓展件在执行动作之前把参数从 A 改成 B | 日志里**先有一条生效参数 B，再有执行**；模型那条回复里**仍是 A**；放行判断判的、实际跑的**都是 B** |
| **S59** | **压缩之前**挂的一件可否决拓展件否决了这一趟 | 这一趟**不压**；装得下照常往下走，**装不下就上交给会话、Run 落失败** |
| **S60** | **消息落盘之前**一件拓展件否决了用户发来的一条 | **那条不进日志**，**用户看得出它被拦下了**；「有一条被拦」这件事本身留了一笔 |
| **S61** | 转换件处理用户发来的一张图时报错 | **那条消息不落盘**，按 S60 的办法让发送方知道——**不会有一个说不清读不读得了的块混进日志** |
| **S62** | 一件拓展件在**执行动作之后**要求「停住」（比如搬来的 `PostToolBatch` 阻断或 `continue:false`） | **不是否决**——日志里**先一条取消请求（发起方是那一件），再一条终态「被取消」** |
| **S63** | 拓展件在等人时 agent runtime 被回收，Run 还在 | 卡片**还在池子里**，Run **还在等**；与「取消这个 Run」**分得清**——后者卡片作废 |
| **S64** | 一件**租户挂上的**拓展件依赖的服务用不了，它注册时没另声明不可用处置 | **跳过：视作这一件已卸载**，这一次这个位置没有它，瀑布跳过它；**日志里看得见「它此刻不在、按跳过处置」**——不是当成它判了否决，也不是悄悄没了 |
| **S64b** | 「图」这个键上登记的转换件**此刻不可用**，用户发来一张图 | **当转换失败**：那条消息不落盘、用户被告知——**不会照原样落一个没有 transcript 的图块** |
| **S64c** | 系统自带的重试件此刻不可用，一次模型调用失败了 | **不重试，直接上交** |
| **S64d** | 循环探测或卸载判定此刻不可用 | **不干预，日志里看得见「它此刻不在」** |
| **S64e** | 租户想把放行判断换成同名的另一件、禁用它，或把它配成只观察 | **做不到**；想多一道关，另挂一件可否决的拓展件与它并排 |
| **S64f** | 一件租户挂在**执行动作之前**、可否决的注入检测拓展件，注册时声明不可用处置为**否决**；它依赖的服务用不了 | **这一次那个动作不许做**，瀑布到此为止；**日志里看得见「它此刻不在、按否决处置」**，agent 分得出这不是一次执行失败 |
| **S64g** | 同 S64f，但组织把这件拓展件的干预力收窄到了**只观察** | **照跳过办**——它在的时候拦不住任何东西，不在的时候也拦不住 |
| **S64h** | **放行判断此刻不可用**，agent 这一步要执行三个动作，其中一个的执行权限是「自动」 | **三个都被拒**，**一张卡片都不出**；每一个的否决都写明「放行判断此刻不在」。放行判断回来之后，同样的动作照常判 |
| **S64i** | 租户想给自己挂的一件拓展件指定「不可用时由另一件顶上」，或想改系统自带那几件不可用时顶上的指定挂件 | **做不到**——指定挂件只给系统自带的用，且只由系统预先声明；租户要「不在就不许跑」，声明为否决 |
| **S65** | 某一类拓展件的协议另定了报错策略，它跑起来报错 | **照那条策略处置**，且**实际怎么处置的**留在日志里 |
| **S66** | **消息落盘之前**一件拓展件否决了**模型的回复** | 回复不落盘；**那次调用照常结束，记下被哪一件否决——日志里没有一条「调模型失败」**；loop 退避之后**另起一次新调用**；同一步连续被否决到上限，**Run 落失败**，原因指向那件拓展件 |
| **S66b** | **消息落盘之前**一件脱敏拓展件想把模型回复里的一段改掉再落盘 | **改不了**——对模型的回复它只能整份否决；日志里那份与用户在流式里看到的**始终是同一份** |
| **S66c** | 用户叫停了一次运行，系统随后补了一条中断提醒 | **不会因此开一个新 Run**；下一次用户说话时，新 Run 读得到那条提醒 |
| **S66d** | 一批动作里第一个已被放行、等第二个的卡片时，组织把那项权限收窄了 | 在原动作、绑定和参数保持时，第一个**照放行时的结论执行**，不重判；收窄管的是之后的准入；若 reload 已移除或改变绑定，则按 §6.18 不自动执行并交回 agent |
| **S66e** | 模型已经开口、没说完，据点停机；恢复之后 | **不再发这次调用**；追补一条中断提醒（原因：异常中断），agent 那一步自己决定要不要重说 |
| **S66f** | 模型请求发出去了、还没开口，据点停机；恢复之后 | 那次调用算没交出过回复；**新的一次尝试照常再发**，记录里只会有一份回复 |
| **S66g** | 一个 Run 落了终态之后，它发起过的一次模型调用的实际费用才到 | **照样落账、归这个 Run**，标明是迟到的；Run 的终态不变 |
| **S67** | **消息落盘之前**一件拓展件否决了**工具交回的结果**（或转换件转它时报错） | **Run 落失败**，原因指向那件拓展件；**不落任何替身**，也**不重跑那次工具** |
| **S68** | Run 停在等一次前台工具执行，agent runtime 被回收，之后重起一副 | **那次工具执行照跑、没被取消**；新协程读 Run 知道自己在等哪一次，结果到了接着走 |
| **S69** | 一次执行转了后台，还没跑完据点就整体停机；恢复之后 | **追补一条 `SystemReminderMessage`，说清「后台工具执行异常中断」**，agent 自己决定要不要再调；**已经有结束提醒的、或工具执行运行时里还找得到的，一条都不补** |
| **S70** | Run 停在等一次前台工具执行（协程已交还），这时据点整体停机；恢复之后 | **Run 不会永远停在那儿**：追补的占位 `ToolMessage` 落进日志，照常起一副协程往下走——**哪怕只看日志时这个 Run 属于「等的东西还没到、不起协程」那一行** |
| **S71** | 恢复时，日志里登记着一次调用、没有对应的 `ToolMessage`，但那次执行在工具执行运行时里**还在跑** | **一条都不追补**，接着等它——与 S68 是同一种处境 |

## 二、绝不能发生的事

| 绝不能 | 为什么 |
|---|---|
| **把任何状态只放在进程里** | 它在停机那一刻就没了，**而没人知道少了什么** |
| **把据点停机时没了的工具执行，以「被中断」递给 agent，或由系统替它重调** | 前者让 agent 以为是有人叫停、不敢重来；后者可能把外面已经做了一半的事再做一遍。**收场是失败、原因写「异常中断」，要不要再调由 agent 定** |
| **拓展件不留痕地改变下一步** | **`f` 当场不纯**，重算得到的结果与当时不同，**而没人看得出哪里不一样** |
| **新的一次尝试里重跑有结论的拓展件** | 它可能不纯。上次的判断已经在日志里，**重跑就是拿一个新答案覆盖一个旧事实** |
| **回放时再出一次卡、再调一次模型** | 人被问第二遍，钱花第二遍——**回放碰到的每一次等，日志里都已经有答案** |
| **一件拓展件把「问一下」改成放行** | 放行多出一条绕开权限治理、不落任何授权记录的通道——[没有放宽这一档](design.md#没有放宽这一档) |
| **放行判断此刻不在，却有动作被执行了** | 一道授权从没发生过就生效了，而且[收不回来](design.md#系统自带的几件不可用时各有定法)——**安全组件不在时停工，不裸奔** |
| **执行的参数与日志里记的不是同一份** | 重算读到的、审计查到的都是原参数，**而没有任何东西报错** |
| **放行之后参数又被改了** | 人签的是一份，跑的是另一份 |
| **一批动作里有的先执行了、有的还在等人** | agent 下一步看到一个做了一半的现场 |
| **一件拓展件自己循环调下一层**（[环绕式那一半](design.md#三种形态两种装得进一种拆两半)） | 中间那几次**不经过日志**，重算拿不回同一个下一步 |
| **在「停住等」上反复去问「好了没有」** | 一个在等人的 Run 一直占着一个协程，**直接违反[等人不消耗计算资源](../PF-012-agent-loop-and-run/design.md#agent-runtime-的四条不变式)** |
| **一条迟到的结果把已经终态的 Run 重新拉起来** | 账、终态、通知都已经发出去了，**而它又活了**。[终态是吸收态](design.md#612-终态之后再回来的东西不让-run-复活) |
| **把脱敏或注入检测挂在「消息落盘之后」** | [日志只增不改](design.md#会话日志)——**原文已经永久留在那儿了**，改不掉也删不得 |
| **只对用户输入做脱敏与注入检测** | 那个位置[不只管输入](design.md#消息落盘之前每条消息都经过它不只是输入)。**模型吐出来的内容照样会带敏感信息**，而按这种做法它没有任何位置可以被处理 |
| **模型没给动作就直接落「完成」** | 这期间[队列里可能已经有东西了](design.md#56-状态转移表)——**一次收束把它跨了过去**，而它明明已经在日志里 |
| **把[待处理消息队列](design.md#待处理消息队列)做成独立存储** | 它是日志的投影。另存一份，**组装一取就没了**（方程失效），**一次重启就丢消息**（停机是主路径） |
| **Run 收束之后回来的东西没人管** | [不复活这一个，不等于没有下一个](design.md#612-终态之后再回来的东西不让-run-复活)。做成「没人管」，用户要**等到自己下次主动说话才发现两小时前就跑完了** |
| **把插队实现成「取消当前 Run，再起一个」** | 插队[中断的是这次尝试，不是这个 Run](design.md#run)。落成「被取消」，用户会看到一次并不存在的终止，**账与通知也跟着错** |
| **在插队之外再造一级优先级** | [插队是唯一的加急通道](design.md#先到先处理只有一个例外)。每多一级就多一处要解释的语义，**而没有一个场景要得到它** |
| **把模态转换挂在组装里或调模型之前** | 组装里转，[一圈两次组装结果不同](design.md#模态转换为什么必须落在这里)；调模型之前转，**量的是原图、发的是文本**，压缩判断跟着错 |
| **转换之后把原始内容块丢掉** | 换一个收得下那个模态的模型时，**原图还要用**。[原样进日志，文本填在同一个块里](design.md#模态转换为什么必须落在这里) |
| **取消时把在途执行记成「失败」** | 失败是「这事没成」，[中断是「这事不做了」](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)。记成失败，下一个 Run 里 agent 会去重试**用户刚刚喊停的事** |
| **同一个位置只跑第一件，丢掉其余** | 把「位置」当成了能力标识。**第二件被静默丢掉**，而它可能正是组织的合规检查 |
| **在落终态之前把「可否决」做成「拦住往前走」** | 方向反了。**那儿的否决是「不许停」**，做反了会让「没干完就别停」变成「干完了也不许交」 |
| **让组装写日志**（哪怕只写「加载到哪了」） | 日志一旦被组装写脏，**`f` 就不纯了**，而这是整个恢复机制的地基 |
| **把拓展件挂在组装中间** | [组装是纯派生的](design.md#53-改日志的动作与纯派生的动作)，不是状态点——**它前后推不出位置**，不是「不给开」 |
| **恢复时往历史里多塞一句** | **改变了检测窗口**——多出来的那条可能被当成新的工作输入，**把阶梯洗白** |
| **为循环阶梯另存一个计数器** | 多一份状态就多一处会和日志对不上的地方，**而对不上的时候没人说得清哪份是真的** |
| **从「留痕」条目里取状态** | [只有「依据」进方程的定义域](../PF-000-occurrences-and-record-entries/design.md#52-那个判断两条独立充分条件)。混进来，日志的清理策略就会静默改变行为 |
| **Run 一落终态就把那条阶梯也停掉** | **会话层与租户层的处置从此永远不会发生**，而它们本来可能有办法 |
| **把「停着等」当成一种终态** | 等待没有上限；**当成终态，那个 Run 就再也接不回来了** |
| **新增第四个终态** | 三个终态所有消费方都要处理（读面、统计、告警、计费）。**为什么失败，本来就有地方写** |
| **把「人不同意」归进失败** | [人拒绝不是失败](../PF-011-off-nominal-handling/README.md#非常态不是报错)。归错了，用户会看到一次并不存在的故障 |
| **一次尝试铸一个新 Run** | **账和失败都算错**——一次网络抖动就能让一笔变成两笔 |
| **把成本的归属单位放在 agent runtime 上** | 实例一回收，那笔账就没了；**换过两个 agent runtime 的 Run，永远问不出它一共花了多少**。[明细按尝试记是另一回事](design.md#成本两层缺哪一层都会算错)——那是记在日志里的流水，归属单位仍是 Run |
| **成本只记 Run 一层，不分尝试** | 崩溃重来之后，**要么把已花的忘掉，要么把重算的再加一遍**——两者都是错账，**而且事后分不出是哪一种** |
| **把「Run 未终结」读成「有一副协程在跑」** | 一个[等人三天的 Run](design.md#run-未终结不等于有一副-agent-runtime-活着) 会被当成已经结束，或者有人去杀一副根本不存在的协程 |
| **承接不落记录**（把「取到哪了」记在内存里） | 停机就没了，[队列重建不出来](design.md#待处理消息队列)；而且新的一次尝试的取用点与上次不同，**`f` 的输入序列就变了** |
| **给[执行尝试](design.md#执行尝试)另建一套独立权威状态** | 它从日志派生；允许持久化投影，但不能产生与日志分叉的执行事实 |
| **把尝试序号写进[幂等键](design.md#幂等键与追溯标识必须是两个字段)** | 重来算出来的键与上次不同，**对方认不出这是同一件事**——同一封邮件发第二遍 |
| **外部效果的结果只有「成功」和「失败」两个值** | 「已经发出去、结果还没写回」那种记录**无处安放**，只能被当成没发生，**于是重做一遍** |
| **先发停止信号，再写取消请求** | 中间那一瞬停机，恢复逻辑看到「Run 未终结」，**起一副新的接着推进一件已经被叫停的工作** |
| **强杀之后指望被杀的那副协程写终结条目** | 它已经没了。那个 Run 永远挂在未终结上，[被反复复活](design.md#强制停止的三步闭环)——**强杀变成无限重启** |
| **强杀之后不标注「可能存在未收尾的外部效果」** | 强杀的定义就是不等收尾，**系统确实不知道最后那一下有没有落地**。不写，下游会当作什么都没发生 |
| **同一时刻让两个 Run 在一个会话里推进** | 它们交错着往同一本日志里写，**某一次求值看见多少，取决于另一个恰好写进去了几条**——[那是调度时序，不是日志事实](design.md#一个会话任一时刻至多一个未终结的-run) |
| **把[拓展点](design.md#loop-拓展点)和[拓展件](design.md#拓展件)混为一谈** | **拓展点是位置，拓展件是挂上去的东西**。位置十一个且可穷举，挂什么没有上限——混了就会得出「位置也没有上限」 |
| **为一个功能新开一个「拓展点」** | 位置[由状态点推出](design.md#十一个位置是推出来的不是挑出来的)，不由功能推出。新功能挂到已有位置上去，**十一个之外没有第十二个** |
| **从日志里擦掉一条消息** | [一条都不能擦除](../PF-010-context-management-and-assembly/design.md#612-记录里的消息一条都不能擦除)，**不管它还模型不模型可读** |

## 三、判据

**怎么算这块设计站得住：**

1. **同一份[会话日志](design.md#会话日志)配同一份[当下条件](design.md#当下条件)，
   两个互不通气的实现算出同一个下一步。**
   算不一致的那一次，说明**判据还有洞**，不是那两个实现的问题。

2. **跑完它 `f` 的取值会变，它才是状态点。**
   [「改不改日志」不够用](design.md#由此得到判据看跑完它-f-的取值变不变)——拓展件也改日志，但跑完它 `f` 还指着同一个段。
   多建一个状态点，恢复时就多一类状态要对；少建一个，**那一段就会被重做**。

   > **配套的一条**：段内任意位置断掉，重新算 `f` **必须还指向同一个段**。
   > 指向别处的那一次，说明**有东西没落进日志**。

3. **把[系统自带的那几件拓展件](design.md#系统自带的几件各站在哪)全部拿掉，loop 照转。**
   转不动的那一件说明它不是拓展件，**是方程自己的一步**。
   > **「照转」说的是机制，不是说该这么用。**拿掉放行判断，所有动作直接放行；
   > 拿掉模态转换，收不下那个模态的模型就**读不到那一块**——
   > **转得动，但那是另一个问题。**
   > 这也不是它们**此刻不可用**时的样子：那时顶上的是[系统预先声明的指定挂件](design.md#系统自带的几件不可用时各有定法)——放行判断那一格是全拒件（S64h）。

4. **任取一件拓展件，把它上次的判断留在日志里，保持完整输入与求值规则不变再重算，下一步相同**（S7）。
   在这些前提下仍不同，说明必要依据缺失或求值没有遵守同输入同结果；当前条件真实变化不作为该场景的失败。
   **还在等人的那一件，把答复落进日志再重算**（S53）：它**一张新卡都不出、一次模型都不再调**。
   出了，就说明它在等待前后靠内存传了东西，或它有一次等待没被记下。

5. **三个终态，每一个都举得出至少一条真实路径**——举不出来的那个是想象出来的。

6. **位置清单的完备性，能被独立复算。**数一遍[状态点](design.md#53-改日志的动作与纯派生的动作)，
   乘二，减去归 [PF-015 的那一条](design.md#十一个位置是推出来的不是挑出来的)，**得数必须是十一**。
   > **这一条是「推出来的」与「挑出来的」的分水岭。**挑出来的清单没法被复算，
   > 只能问「你觉得够不够」；推出来的清单，**漏没漏等价于问「状态点漏没漏」**。

7. **拿一个真实的产品功能，拆成机械动作，逐条落位。**
   落不进去的那几条，**要说得出它们归哪个 topic**——说不出来，才是缺口。
   > 已经这样验过两个：[`/goal` 全落在落终态前后与调模型之后；`/btw` 一条都用不上](interviews/2026-09-19-loop-extension-points.md#七用-btw-与-goal-回头检验)。
   > **后者不是缺口**——拓展点是「能改下一步」的位置，旁路提问按定义不改下一步。

8. **本 topic 里没有一张「非常态有哪些种」的清单，也没有一套失败分类。**
   出现了就是[把已经交割出去的地盘又拿回来](design.md#512-run-的终态与非常态的终局是两条线)。

9. **每一条「绝不能」都举得出一个真实会违反它的做法** —— 举不出来的那条是想象出来的，删掉。

10. **把系统关机、抹掉全部内存、只留会话日志，重新开机后答得出
    「现在该不该起一副 agent runtime、它接手哪个 Run」，且答案唯一**（S43）。
    > **这是[整个 Run 设计的充分性判据](design.md#它存在的理由让起不起协程只看日志就算得出来)**，
    > 也是本页其余各条的总闸：**答不出，或者两个人算出两个答案，就说明日志里还缺条目**——
    > 缺哪一条，照 [§6.16](design.md#616-日志里至少要有这几种-run-相关的条目) 一项项对。

11. **同一条外部效果记录上，幂等与追溯各自独立成立**：
    **拿它重算一遍幂等键，跨尝试必须相同**；**拿它问「是哪一次干的」，必须答得出**。
    > **两个问题要能分别回答**——只答得出一个，就说明[那两个字段被合成了一个](design.md#幂等键与追溯标识必须是两个字段)。

## 持久化投影与完整函数输入

| # | 场景 | 应当看到什么 |
|---|---|---|
| S72 | 同一日志前缀、同一当下条件、同一规则重新求值 | 下一步相同；持久化投影与从该日志重建的结果相同 |
| S73 | 当前授权或模型选择变化，日志未变化 | 使用完整新输入求值，可得不同结果；不声称只凭日志可还原全部输入 |
| S74 | 投影落后于日志 | 不以过期状态重复消费、重复发起执行或丢弃已发生事实 |
| S75 | 重建 agent runtime 时工具还在后台跑 | 恢复关联，不因函数输入相同而重复发起外部动作 |

## 运行时归属与句柄

| # | 场景 | 通过的样子 |
|---|---|---|
| S76 | 等模型首 token 前或之后，销毁唯一 Agent runtime | 模型执行继续，不取消、不重发；零句柄期间输出与费用可查 |
| S77 | 模型／工具在重建 Agent runtime 前完成 | 新尝试读取原结果，只承接一次，不再次执行；原调用和原发起尝试归属不变 |
| S78 | 新消息入队时原模型仍在途 | 重建不会制造重复请求；需要打断则按既有输入规则显式取消原调用 |
| S79 | 旧尝试已被替代，独立执行返回 | 保留结果与费用；当前尝试可承接仍在等待的结果；旧尝试无法推进，终结 Run 不复活 |
| S80 | 取消 Run，同时存在会话旁路提问和后台工具 | 取消本 Run 模型与前台工具；旁路提问不受影响，后台工具沿原规则继续 |
| S81 | 无 Agent runtime 时归档会话 | 仍能找到并取消会话名下模型和工具，收场如实记录 |
| S82 | 同一故障只损毁 Agent runtime，或同时损毁其他 runtime | 分别判断执行连续性；不能凭等待者消失就认定模型失联或工具失败 |

无 Agent runtime 时分别发起优雅／强制 Run 取消：两者都按持久关联通知模型与前台工具；优雅取消等收尾、强制停止保留未收尾提示；会话治理保证幂等终结。取消记录后进程中断，恢复继续完成取消与结算，不继续业务推进。

| # | 内部调用接续场景 | 通过的样子 |
|---|---|---|
| S83 | 拓展件判断模型／压缩摘要模型仍在途时销毁 Agent runtime | 新尝试接续原调用，在原拓展位置／压缩计算消费；不重发，不把内部回复送入主流程 T2′／T3 |
| S84 | 原模型调用等待期间有普通消息入队 | 消息保持未承接，原请求收场及原步骤允许后再消费；不会被错误视为已经给原请求看过 |
| S85 | 尝试 1 发起调用，尝试 2 消费其成功结果 | 费用只归原调用与原发起尝试，不自动算作崩溃浪费 |

## 重装配与独立执行交接

必须能够说明：何种变更要求重装配、请求与实际生效时间、旧／新清单及采用来源、会话固定身份、Run 与尝试关系、仍在途执行及原消费者、未完成判断、当前有效值、失败原因和是否已经切换。保存足以恢复这些结果的函数输入；对象布局由规格确定，不为“重装配任务”自动新增领域对象。

| # | 场景 | 验收要求 |
|---|---|---|
| S86 | 从等待或崩溃中仅重建 Agent runtime | 同一 Run、新尝试；不静默升级、不重复已发请求，不重置会话模式 |
| S87 | reload 候选缺必需工具／含无效配置／尝试绕过 immutable | 明确失败；旧有效数据不被部分替换 |
| S88 | 等模型生成时换 Agent runtime，原模型随后完成 | 流继续，费用一次计，原消费者一次承接 |
| S89 | 工具正修改旧工作区时切换新工作区 | 旧工具不被重定向到新目录；新调用使用实际生效的新入口 |
| S90 | 新旧实现交替，旧模型回复建议调用旧工具 | 按当前装配核对，已移除或绑定已变则交回 agent 重新判断；不得只按同名把旧参数送给新实现 |
| S91 | reload 要卸掉仍有未完成判断／卡片的 extension | 不能丢等待或复用不同语义判断；依赖未满足与恢复失败可见，不把卸载当成判断完成 |
| S92 | 模式切换需更换 extension | 用户读到的“已生效”与实际 Ask／完成检查行为一致；类型强制检查保留 |
| S93 | 无变化 reload、重复提交、候选晚到、切换途中崩溃 | 不重复外部执行，不让旧候选覆盖更新选择；恢复能解释实际生效结果 |
| S94 | 交接期间取消 Run／归档 Session | 不复活、不启动新推进；取消仍覆盖应停止的独立执行 |
| S95 | 零句柄期间原执行完成或失败 | 结果与费用保留，新实例可取得，不误判失联 |
| S96 | reload 后原动作已获批、同一绑定和参数均未改变 | 不因 reload 重复出卡；已有放行结论继续适用于原动作 |

## 无实例替换时的能力更新

| # | 场景 | 预期 |
|---|---|---|
| S97 | Agent runtime 未替换，但旧模型建议到达时工具 schema 或实现已变 | 不自动发起工具、不暗改参数；原因交回 agent；旧模型结果和费用照记 |
| S98 | 仅说明文字更新，同动作、同调用约定、同绑定、同参数已有放行 | 不因更新本身重复要求放行 |

## 派发与归档裁决验收

归档时取消尚未承接输入，队列投影排除它们但日志保留；重建投影或撤销归档不会启动这些任务，取消不得冒充已承接。
