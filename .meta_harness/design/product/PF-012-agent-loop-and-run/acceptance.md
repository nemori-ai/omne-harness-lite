# PF-012 验收标准

---

## 一、可观察的场景

| # | 场景 | 通过的样子 |
|---|---|---|
| **S1** | 一次运行正常跑完 | 日志里**只有那几个改日志的动作留下了痕迹**；组装跑了两次也一条都没多 |
| **S2** | 崩在「动作发出去了，结果没落盘」 | **合成一条「被中断」的结果**补上，照常走 T7——**不重发那个动作** |
| **S3** | 崩在「模型已给完整回复，终态没落」 | **幂等收尾，一次模型都不再调** |
| **S4** | 等人时 agent runtime 被取消，人回话之后接着跑 | **还是原来那个 Run**；**不必对账**（上一次是正常停住的）；用户看到的是他的问题被接上了 |
| **S5** | 同一次 Run 换过两个 agent runtime | **账还是一笔**，失败也只有一笔——**不会变成两个 Run** |
| **S6** | 靠反复崩溃想洗白打转记录 | **阶梯不重置**，崩多少次都一样——因为它是从日志里数出来的 |
| **S7** | 把某件拓展件上次的判断留在日志里，重算一遍 `f` | **算出来的下一步与当时完全相同**，且**那件拓展件一次都没被重跑** |
| **S8** | 「只观察」那一档的拓展件挂了 | **正在发生的事照常**，一步都不受影响 |
| **S9** | 「可否决」那一档的拓展件挂了 | **当作否决**，**且这件事本身可见**——不是悄悄放过去 |
| **S10** | 「可改写」那一档的拓展件挂了 | 事情照常，**但日志里留得下「它没跑成」**——排查的人分得出这与「它说不用改」的区别 |
| **S11** | 压缩闭包交不出装得下的东西 | **两件事同时发生且各留一条**：上交给会话、Run 落终态失败（原因写明是固定部分超限） |
| **S12** | 一件非常态被上交到会话层之后 | **Run 已经是终态了，而那件事还在往外交**——租户那一层照样会接到它 |
| **S13** | 循环守卫 L3 结束了一个 Run | **落终态失败，不往上交**——它不是非常态 |
| **S14** | agent 打转打到触发了压缩 | **阶梯照数不误**——窗口取自会话日志，而[日志里一条都没被擦除、也没被改过](../PF-010-context-management-and-assembly/design.md#612-记录里的消息一条都不能擦除) |
| **S15** | 一批动作全被人否了 | **照样回 T1 走一遍模型**——否则它下一轮还会再发一次 |
| **S16** | 有东西转到后台还没回来 | 那个占位**不会被压缩点名**——agent 始终知道自己还有东西在外面跑 |
| **S17** | 外面来的事在 Run 等人的时候到达 | **照常收进日志**，解除阻塞之后**一起**看到 |
| **S18** | 同一份日志配同一份当下条件，算两次 | **下一步相同**。换一份当下条件（比如某个能力没了）**允许不同** |
| **S19** | 在**落终态之前**挂一件「没达成目标就别停」的拓展件，它判定没达成 | **这次不收束，接着转**——它否决的是**停下来** |
| **S20** | 同一件挂了 | **按 fail-closed 仍是否决停下**，接着转；**这件事本身可见** |
| **S21** | **同一个位置挂两件**（比如落终态之前同时有打转保护和目标判定） | **两件都跑**，[依次过](design.md#三种形态两种装得进一种拆两半)，**各留各的条目** |
| **S22** | 在**调模型之前**挂一件会改日志的拓展件 | **重新组装一次再发**，且**不再回到这个位置**——[同一位置同一次经过只跑一轮](design.md#改了日志就重新组装同一位置同一次经过只跑一轮) |
| **S23** | 问 loop「这一轮上下文超了没有」 | **它答不上来，也不需要答**——它只收到[压缩闭包](design.md#55-想这一步交进闭包拿回装得下的一份)交回的「装得下 / 装不下」 |
| **S24** | 换掉整套压缩策略（判定时机、压哪一段、摘要怎么写全变了） | **[状态转移表](design.md#56-状态转移表)一个字不用改** |
| **S25** | 换掉循环探测的实现（阈值、算法、判定口径全变了） | **转移表一个字不用改**——[四种结局仍落在已有的行上](design.md#循环探测的四种结局全落在已有的行上) |
| **S26** | 把循环探测整件拿掉 | **loop 照转**，只是没人管原地打转了 |
| **S23** | 一件拓展件自己调了一次模型做判断 | 那笔钱**算进它插手的那个 Run** |
| **S24** | 一次**不属于任何 Run** 的模型调用（旁路提问那种） | 它的花费**不被硬塞进任何 Run**，归会话那一级 |
| **S25** | Run 停在「等人」上，**观察它占用的计算资源** | **一份都不占**。停住是[这次尝试的出口](design.md#这个循环从哪里出去)，不是在原地反复问 |
| **S26** | 在**消息落盘之前**挂一件脱敏拓展件，送进一条带敏感信息的输入 | **日志里从头到尾没有原文**——不是「先落盘再改掉」 |
| **S27** | 在同一位置挂一件注入检测拓展件，它判定这条输入是攻击 | **那条输入不进日志**，也因此不进[方程的定义域](design.md#方程从日志里读什么) |
| **S28** | Run 已落终态，一个后台结果**在那之后**才回来 | 结果**照样落进日志**、**那个 Run 的终态不变**；同时它**进了[队列](design.md#待处理消息队列)**，于是**开出下一个 Run 来看它**——**不复活这一个，不等于没人管** |
| **S29** | 用户说「**跑那个构建，好了告诉我**」，构建两小时后才完，那次 Run 早已收束 | 结果回来时**自动开出一个新 Run**，用户被告知——**不需要他先说话才发现** |
| **S30** | Run 正跑着，用户又说一句（**不插队**） | **同一个 Run 接着消费它**，不另起一个——队列没空，loop 就没退出 |
| **S31** | 模型这一步**没给动作**，但队列里还有东西 | **Run 不结束**，回去取下一批 |
| **S32** | 模型这一步没给动作，**队列也空了** | Run 落「**完成**」 |
| **S33** | 同一件脱敏拓展件挂着，这次是**模型吐出**一段含敏感信息的回复 | **日志里同样没有原文**——**这个位置不只管输入**，模型吐的、工具交的一视同仁 |
| **S34** | 挂一件把图转文本的拓展件，送进一张图 | 日志里**那个内容块原样还在**，**并且它记录文本的那个字段被填上了**；随后换一个收得下图的模型，**用的仍是原图** |
| **S35** | 用户在 Run **等工具结果**时取消 | 终态落**被取消**；那个在途执行按 [PF-006](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)落一条「**被中断**」的占位，**不是失败** |
| **S36** | 一个 agent **不打转、一直在干新活**，没人挂预算守卫 | **系统不会自己停它**——这是[已知且有意的边界](design.md#方程不保证这个循环会停)，不是缺陷 |
| **S37** | Run 正跑着，用户发了一条**带插队命令**的消息 | 那条消息**排到队首**、loop 里**各种等待态一并解除**；**这个 Run 不落终态**——它只是被推到了下一次取消息那一点 |
| **S38** | 停机，重启，观察队列 | **一条都没少**——队列是[日志算出来的](design.md#待处理消息队列)，不是另一份存储 |

## 二、绝不能发生的事

| 绝不能 | 为什么 |
|---|---|
| **把任何状态只放在进程里** | 它在停机那一刻就没了，**而没人知道少了什么** |
| **拓展件不留痕地改变下一步** | **`f` 当场不纯**，重算得到的结果与当时不同，**而没人看得出哪里不一样** |
| **新的一次尝试里重跑拓展件** | 它可能不纯。上次的判断已经在日志里，**重跑就是拿一个新答案覆盖一个旧事实** |
| **一件拓展件自己循环调下一层**（[环绕式那一半](design.md#三种形态两种装得进一种拆两半)） | 中间那几次**不经过日志**，重算拿不回同一个下一步 |
| **在「停住等」上反复去问「好了没有」** | 一个在等人的 Run 一直占着一个协程，**直接违反[等人不消耗计算资源](../PF-012-agent-loop-and-run/design.md#agent-runtime-的四条不变式)** |
| **一条迟到的结果把已经终态的 Run 重新拉起来** | 账、终态、通知都已经发出去了，**而它又活了**。[终态是吸收态](design.md#612-终态之后再回来的东西不让-run-复活) |
| **把脱敏或注入检测挂在「消息落盘之后」** | [日志只增不改](design.md#会话日志)——**原文已经永久留在那儿了**，改不掉也删不得 |
| **只对用户输入做脱敏与注入检测** | 那个位置[不只管输入](design.md#消息落盘之前每条消息都经过它不只是输入)。**模型吐出来的内容照样会带敏感信息**，而按这种做法它没有任何位置可以被处理 |
| **模型没给动作就直接落「完成」** | 这期间[队列里可能已经有东西了](design.md#56-状态转移表)——**一次收束把它跨了过去**，而它明明已经在日志里 |
| **把[待处理消息队列](design.md#待处理消息队列)做成独立存储** | 它是日志的投影。另存一份，**组装一取就没了**（方程失效），**一次重启就丢消息**（停机是主路径） |
| **Run 收束之后回来的东西没人管** | [不复活这一个，不等于没有下一个](design.md#612-终态之后再回来的东西不让-run-复活)。做成「没人管」，用户要**等到自己下次主动说话才发现两小时前就跑完了** |
| **把插队实现成「取消当前 Run，再起一个」** | 插队[中断的是这次尝试，不是这个 Run](design.md#run)。落成「被取消」，用户会看到一次并不存在的终止，**账与通知也跟着错** |
| **在插队之外再造一级优先级** | [插队是唯一的加急通道](design.md#先到先处理只有一个例外)。每多一级就多一处要解释的语义，**而没有一个场景要得到它** |
| **把模态转换挂在组装里或调模型之前** | 组装里转，[一圈两次组装结果不同](design.md#模态转换为什么必须落在这里)；调模型之前转，**量的是原图、发的是文本**，压缩判断跟着错 |
| **转换之后把原始内容块丢掉** | 换一个收得下那个模态的模型时，**原图还要用**。[原样进日志，文本填在同一个块里](design.md#模态转换为什么必须落在这里) |
| **取消时把在途执行记成「失败」** | 失败是「这事没成」，[中断是「这事不做了」](../PF-006-tools-and-skills/design.md#67-用户可以中断而中断不是失败)。记成失败，下一个 Run 里 agent 会去重试**用户刚刚喊停的事** |
| **同一个位置只跑第一件，丢掉其余** | 把「位置」当成了能力标识。**第二件被静默丢掉**，而它可能正是组织的合规检查 |
| **在落终态之前把「可否决」做成「拦住往前走」** | 方向反了。**那儿的否决是「不许停」**，做反了会让「没干完就别停」变成「干完了也不许交」 |
| **让组装写日志**（哪怕只写「加载到哪了」） | 日志一旦被组装写脏，**`f` 就不纯了**，而这是整个恢复机制的地基 |
| **把拓展件挂在组装中间** | [组装是纯派生的](design.md#53-改日志的动作与纯派生的动作)，不是状态点——**它前后推不出位置**，不是「不给开」 |
| **恢复时往历史里多塞一句** | **改变了检测窗口**——多出来的那条可能被当成新的工作输入，**把阶梯洗白** |
| **为循环阶梯另存一个计数器** | 多一份状态就多一处会和日志对不上的地方，**而对不上的时候没人说得清哪份是真的** |
| **从「留痕」条目里取状态** | [只有「依据」进方程的定义域](../PF-000-occurrences-and-record-entries/design.md#52-那个判断两条独立充分条件)。混进来，日志的清理策略就会静默改变行为 |
| **Run 一落终态就把那条阶梯也停掉** | **会话层与租户层的处置从此永远不会发生**，而它们本来可能有办法 |
| **把「停着等」当成一种终态** | 等待没有上限；**当成终态，那个 Run 就再也接不回来了** |
| **新增第四个终态** | 三个终态所有消费方都要处理（读面、统计、告警、计费）。**为什么失败，本来就有地方写** |
| **把「人不同意」归进失败** | [人拒绝不是失败](../PF-011-off-nominal-handling/README.md#非常态不是报错)。归错了，用户会看到一次并不存在的故障 |
| **一次尝试铸一个新 Run** | **账和失败都算错**——一次网络抖动就能让一笔变成两笔 |
| **把成本挂在 agent runtime 上** | 实例一回收，那笔账就没了；**换过两个 agent runtime 的 Run，永远问不出它一共花了多少** |
| **把[拓展点](design.md#loop-拓展点)和[拓展件](design.md#拓展件)混为一谈** | **拓展点是位置，拓展件是挂上去的东西**。位置十一个且可穷举，挂什么没有上限——混了就会得出「位置也没有上限」 |
| **为一个功能新开一个「拓展点」** | 位置[由状态点推出](design.md#十一个位置是推出来的不是挑出来的)，不由功能推出。新功能挂到已有位置上去，**十一个之外没有第十二个** |
| **从日志里擦掉一条消息** | [一条都不能擦除](../PF-010-context-management-and-assembly/design.md#612-记录里的消息一条都不能擦除)，**不管它还模型不模型可读** |

## 三、判据

**怎么算这块设计站得住：**

1. **同一份[会话日志](design.md#会话日志)配同一份[当下条件](design.md#当下条件)，
   两个互不通气的实现算出同一个下一步。**
   算不一致的那一次，说明**判据还有洞**，不是那两个实现的问题。

2. **跑完它 `f` 的取值会变，它才是状态点。**
   [「改不改日志」不够用](design.md#由此得到判据看跑完它-f-的取值变不变)——拓展件也改日志，但跑完它 `f` 还指着同一个段。
   多建一个状态点，恢复时就多一类状态要对；少建一个，**那一段就会被重做**。

   > **配套的一条**：段内任意位置断掉，重新算 `f` **必须还指向同一个段**。
   > 指向别处的那一次，说明**有东西没落进日志**。

3. **把[系统自带的那几件拓展件](design.md#系统自带的几件各站在哪)全部拿掉，loop 照转。**
   转不动的那一件说明它不是拓展件，**是方程自己的一步**。
   > **「照转」说的是机制，不是说该这么用。**拿掉放行判断，所有动作直接放行；
   > 拿掉模态转换，收不下那个模态的模型就**读不到那一块**——
   > **转得动，但那是另一个问题。**

4. **任取一件拓展件，把它上次的判断留在日志里重算，下一步相同**（S7）。
   不同，就说明**有东西没被记下来**。

5. **三个终态，每一个都举得出至少一条真实路径**——举不出来的那个是想象出来的。

6. **位置清单的完备性，能被独立复算。**数一遍[状态点](design.md#53-改日志的动作与纯派生的动作)，
   乘二，减去归 [PF-015 的那一条](design.md#十一个位置是推出来的不是挑出来的)，**得数必须是十一**。
   > **这一条是「推出来的」与「挑出来的」的分水岭。**挑出来的清单没法被复算，
   > 只能问「你觉得够不够」；推出来的清单，**漏没漏等价于问「状态点漏没漏」**。

7. **拿一个真实的产品功能，拆成机械动作，逐条落位。**
   落不进去的那几条，**要说得出它们归哪个 topic**——说不出来，才是缺口。
   > 已经这样验过两个：[`/goal` 全落在落终态前后与调模型之后；`/btw` 一条都用不上](interviews/2026-09-19-loop-extension-points.md#七用-btw-与-goal-回头检验)。
   > **后者不是缺口**——拓展点是「能改下一步」的位置，旁路提问按定义不改下一步。

8. **本 topic 里没有一张「非常态有哪些种」的清单，也没有一套失败分类。**
   出现了就是[把已经交割出去的地盘又拿回来](design.md#512-run-的终态与非常态的终局是两条线)。

9. **每一条「绝不能」都举得出一个真实会违反它的做法** —— 举不出来的那条是想象出来的，删掉。

## 四、不验收什么

| 不验 | 归哪 |
|---|---|
| 重试几次、等多久、退避多少、循环检测的阈值 | **策略** |
| 日志落在哪、存几份、留多久 | **技术设计**与 [PF-000](../PF-000-occurrences-and-record-entries/README.md) |
| 组装取多少、边界怎么算、压缩用什么算法 | [PF-010](../PF-010-context-management-and-assembly/README.md) |
| 一共有哪几种消息、块标注怎么标 | [PF-009](../PF-009-context-message-types/README.md) |
| 卡片怎么出、池子怎么组织 | [PF-008](../PF-008-human-in-the-loop/README.md) |
| 六种收场各自长什么样、卸载产物什么形状 | [PF-006](../PF-006-tools-and-skills/README.md) |
| 装配缺东西怎么失败、 agent runtime 怎么被取消 | [PF-004](../PF-004-agent-definition-and-assembly/README.md) |
| 一件非常态被交到外层之后怎么走 | [PF-011](../PF-011-off-nominal-handling/README.md) |
| 费率、账单、配额 | **计费那一侧**。本 topic 只定 Run 是成本的归属单位 |
