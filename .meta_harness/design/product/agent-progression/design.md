# Agent 定义与工作推进

状态：已由产品负责人采用，见[技术接受与产品采用决定](https://github.com/nemori-ai/omne-harness-lite/issues/384#issuecomment-6258475204)。本页说明产品中的 Agent 怎样依据定义工作、怎样等待外部结果和人的决定，以及中断后怎样接着原工作。它不声明功能已实现。

## 产品需求描述

### 使用场景

用户用一个 Agent 开始协作，之后继续补充输入。一次工作可能多次调用模型、同时使用多个工具、等待确认，或因故障换一个推进实例。用户关心工作、结果、费用和未完成责任，不需要按实例的生灭重建协作。

组织和租户可给 Agent 配置方法、能力与额外检查。检查必须有明确适用位置和权限边界。配置检查不能另开授权通道，也不能让一次组件故障悄悄跳过系统必需的动作准入。

Agent 负责判断下一步、协调调用和接续自己的执行。模型、工具、上下文和人工决定仍按各自规则提供能力；Agent 使用必要事实，不接管它们的内部治理。权限模式的解释归授权，压缩后哪些历史退出请求归 Context，工具内部等待的答复归 Tool。

本页会话场景中的 Session、Run 和 attempt 表达产品协作关系，不是使用 Agent 能力必须创建的对象。独立调用者可以提交输入、消费输出并取得本次执行的结束结果；会话集成另行兑现输入受理、Run 终态和归档规则。

### 定义与协作身份

AgentDefinition 声明 Agent 需要什么能力、是否接纳额外能力，以及采用什么工作方式。定义身份使用能力类别与 name；默认模型、人格、语气和组合内容不是身份。定义数据、一次装配的采用结果和实际推进实例分别存在。

定义类型有 master 与 non-master。master 具备产品规定的主协作机制，用户以 master 创建主会话。non-master 不因名字或能力强弱成为 master；其具体差异须有规则，不能推断它缺少任意能力。

master 仅由产品官方提供。组织、租户和工作区只能自定义 non-master。official 定义不可由同标识自定义定义替换；可替换的自定义定义仍受上级锁定约束。定义不可替换不禁止其允许配置的设置配值，也不自动锁定它引用的所有能力实现。

master 的出厂类目包括 general-purpose、coding、office、research 和 personal-life，只由产品出厂增补。类目到会话用途的映射归会话规则。派发时选 master 不把子会话变成独立主会话；spawn 与 delegate 可以选择两类定义，handoff 选择 master，资格仍按派发规则检查。

会话固定 AgentDefinition 身份。新 Run 采用该身份最新合法发布内容；同一 Run 的普通恢复保留已采用版本。显式 reload 可在安全交接后采用同身份新版本。定义变更、实例替换、新 Run 和重新执行已有调用是不同操作。

### 额外能力的选择

会话执行类型要求的 Skill、Tool 和 MCP，以及定义显式要求的这三类能力，均为必需项。自动继承的排除和会话对可选项的移除不能去掉必需项。

自动继承声明属于定义本身，默认关闭。开启后可以开放到组织、租户或工作区，包含从该层到组织的相应来源。声明开放到组织只自动选入组织提供的能力身份；已选身份的具体实现仍在完整合法作用域内解析，不因此排斥合法的同标识租户实现。

排除项只扣除自动继承部分，按能力类别与 name 区分。排除 MCP 接入点不改成逐个工具名称的排除规则。此机制不自动扩展到 Plugin、Slash Command、Loop Extension 或其他 AgentDefinition。

采用更具体层的同标识自定义定义时，使用新定义自己的整份继承声明，不合并被替换定义的旧字段。新定义未声明继承，仍按关闭处理。

初次装配、reload 或后续装配无法取得必需能力的合法定义，或 Loop 自身必需入口无法建立时，此次候选校验失败并说明缺失，不采用该候选。已有合法采用仅在其当前条件仍适用时保留，不能借旧采用假报新依赖已经成立。已有合法定义但实际实现暂不可用时，保留已知能力及不可用应答，不因暂不可用拒绝启动 Loop；必需身份不承诺每次执行成功。

会话曾合法纳入的 Tool、Skill 和 MCP 身份持续保留。禁用、卸载、定义排除或撤权可以使其不可用，但不抹掉已知身份。不可用应答保留原因，不能提供撤权后的新内容，也不能为从未取得的能力编造定义。重新可用仍须满足当前选择、治理和依赖条件。

### 一次工作怎样推进

在会话路径中，Session 组织逻辑工作，Run 标识一次工作，attempt 标识承担推进的一次尝试。Agent Loop 判断下一步，Agent runtime 执行决定。Loop 规则没有实例寿命，Agent runtime 不拥有模型与工具的执行寿命。

正常推进经过以下阶段。

1. 先处理取消和既有终态，接续原调用、原判断及原等待。
2. 在允许承接下一批时取得当时全部普通输入，保留顺序。卡片答复回原卡片，控制指令按控制路径处理。
3. 根据可用的历史和当前条件形成可发送的模型输入。固定内容已经超限，或允许的压缩后仍装不下时，本次 Run 失败并说明实际原因，Session 与历史保留。不默认分叉、删除历史、偷换模型或无限新建 Run，也不反复制造压缩循环。
4. 经过模型前检查，固定本次输入，发起模型调用。一次发出失败但原调用还在重试时，仍等待原调用。
5. 原调用真实收场后检查完整回复，形成候选动作。未收齐的工具参数不执行。
6. 逐动作经过有序检查。同批不同动作可以并行判断，整批判断结束且所需卡片均按原规则处理完成前，不执行已经获准的部分。
7. 需要人决定时等待原卡片。有效答复交回后，整批卡片须按原规则处理完成，再回到出卡的检查位置继续判断。后继检查仍可提出下一批卡片。
8. 获准动作满足当前执行资格、环境和资源条件后调用真实能力。取得前台结果或合法后台占位，先可靠承接，再经过执行后检查，继续判断下一步。整批动作全被拒绝时，没有工具执行可等，沿已有事实重新判断，不直接完成或空转等待。

新输入不因为已经到达就改写正在执行的模型请求。用户要求插队时走明确的控制路径，已有输出、实际费用和效果仍保留。

### 模型回复与工具结果

模型回复是候选内容，不是已经获准的动作。后续检查不改写用户已经看到的模型原文；模态转换按契约附加派生表示，保留原内容。

外部输入、模型完整回复和工具结果成为消息前，都先经过消息准入，下文也称消息入口。消息准入是 Agent 自己的规则，不依附任何扩展位置。三种来源的拒收后果不同。

消息入口拒绝外部输入时，发送方得到可理解的拒收结果。拒绝模型回复时，原模型调用已经结束，其结果和费用保留。退避后可以创建新的模型调用。连续否决不设次数上限，不因此使 Run 失败。新调用不冒充原调用内部重试。

工具结果被入口否决时，仅在原消费契约指明归属仍有效、尚未终结的 Run 时使该 Run 失败并说明检查来源。后台、Run 外及原 Run 已终结的结果按原消费入口处理，不改旧终态、不默认挂到后继 Run；没有有效 Run 不造一个，已取消业务不取得新入队资格。未定旁路后果继续由原消费拥有者明确。不能重跑工具来制造另一份结果，也不能以虚构结果替代原执行。真实结果仍由其拥有者保存，否决只改变它能否成为本次协作的消息和依据。

不可用替换件是一种逻辑工具执行。原工具未被物理执行时，仍记录此次动作与不可用结果，后续沿原消费位置处理。日志不能虚构真实工具启动、效果或用量。

### 扩展检查与权限

Loop extensions 在产品规定的位置观察、改写未提交候选或否决状态变化。同一位置有序执行，后一个读取前一个的候选与新事实。扩展不能改写既有事实，不能不留痕地改变下一步，也不能直接指定跳转。

允许位置共九处，限制如下；收场维度和结果范围只用于筛选，不增加位置。

| 位置 | 对产品行为的限制 |
| --- | --- |
| 执行开始之后 | 每个新的 Agent 逻辑执行经过一次。重挂接、实例换代或接续原执行时不再经过。不能给已失效的执行挂接重新授予推进资格 |
| 压缩之前 | 可以不压；因此仍装不下时本次 Run 失败。不允许改写 |
| 压缩之后 | 只有实际发生压缩才触发，不撤销已成立历史 |
| 调模型之前 | 可改未发请求或阻止发出；改后重新检查输入 |
| 调模型之后 | 完整回复与失败分别处理；首内容前一次发出失败可进入重试策略，原调用尚未终局。只有整项调用真正结束后才交最终结果，内部重试不另开 Run、attempt 或逻辑调用 |
| 执行动作之前 | 单动作有序判断，可在合法位置等待人；全批判断齐备再执行 |
| 执行动作之后 | 按单结果或整批齐备筛选，没有否决能力，不撤销效果。整批范围不允许改写。停止或请求人处理只影响后续推进，不撤销已发生动作 |
| 落终态之前 | 核对候选，可要求继续、等待或否决不成立候选 |
| 落终态之后 | 不等待人，不撤销终态或恢复原工作 |

后置位置是执行开始之后、压缩之后、调模型之后、执行动作之后和落终态之后。后置位置都没有否决能力。除落终态之后外，后置位置上的停止或请求人处理只影响后续推进，不撤销已发生的动作。落终态之后只能观察。

产品暂不在消息成立前后另设扩展位置。外部输入、模型完整回复和工具结果的消息准入因此不经过扩展。三种来源各有自己的拒收后果，见“模型回复与工具结果”。

干预力分为只观察、可改写和可否决，实际能力还受位置及共同权限收窄。工作区提供的扩展只观察。扩展可以增加限制，不能把系统的“需要询问”改成放行。导入其他 harness 的 allow 只表示无意见，导入时向使用者说明。

动作参数改变时，保留原参数和生效参数。准入检查、人看到的卡片及真实执行必须针对同一生效参数。参数、绑定或影响批准的授权依据改变后，不自动复用旧批准；无关更新和单纯 reload 不机械重复出卡。

动作准入不能被替换、禁用或收窄成只观察。准入不可用时全部拒绝，不放行动作，也不出卡让人替代失去的授权检查。

非系统扩展不可用时默认跳过，并使这次缺失可见。声明缺失即否决的扩展，只有当前仍具可否决能力且位于前置位置时才能按该声明拦截。不可用与已经执行后报错分开；报错沿已经明确的类别策略处理；没有类别特殊策略时，只观察报错不改变推进，可改写报错不应用本次改写并记录，可否决报错按所在位置合法的否决处理。报错不取得后置撤销能力，也不能伪造一件未运行扩展的判断。

### 人的决定与等待

等待人不是失败或工作终态。人可以长期不回复，系统没有默认超时答案，不持续运行模型或反复询问同一张卡片。

同一卡片只产生一次有效答复，会话和决策池展示共用决定。人明确选择“不回答”也是答复，向原等待返回“没有答案”；它不授予动作，也不因没有批准就重复原问题。原逻辑执行已确定终局时，卡片失效。Agent 实例退出、物理进程丢失或查询失败本身不证明这一终局。

扩展等待保存原检查、动作、采用依据与等待位置。换一个 Agent 实例后，已取得的判断、效果和答复继续使用，不再付一次判断费用或出第二张相同卡片。工具内部 Ask 的等待属于工具执行，不能用扩展等待替代。

### 完成、失败与取消

模型没有动作和普通队列为空只构成完成候选。系统还检查未完成等待、当前协作模式和终态前扩展。终态前检查可以要求继续、等待或否决不成立的候选；终态成立后不能由后置扩展撤销。

Agent 在必要检查成立后结束自己的执行，不要求输出观察者批准。会话路径中的普通完成必须同时核对 Session 已受理的输入，不能因通知尚未送达 Agent 就提前结束原工作。Run 终态为完成、失败或被取消，由 Session 治理记录。终态后不为原 Run 发起新工作。独立执行迟到的真实结果和费用继续归原工作；是否形成新的待处理输入由会话规则判断，不复活原 Run。

取消先可靠保存意图，再停止新推进并通知目标执行。Run 取消不自动停止已转后台工具、子会话或无关调用。Session 归档从业务上取消其未完成请求并解除等待，不要求所有物理执行先停止；归档后的结果不恢复原工作，撤销归档也不重启旧调用。

逻辑取消、实际停止和外部效果撤回分别说明。强制停止可能留下未收尾效果，不能报告它们全部已撤回。扩展提出停止时须留下真实发起来源，不能伪造人的决定。

### 恢复与长期运行

恢复依赖原工作事实、当前权限与模式、装配依据、Context 和执行状态。日志保存历史和逻辑治理事实，不单独提供所有当前输入。

原执行仍在途则等原调用，已经收场则取原结果，查询暂时不可用则保持未知。只有执行自身确认失联，才用它自己的恢复规则处理。工具不自动重放，未知副作用不写成未发生。模型首内容前后沿模型契约处理，不因等待者替换重发。

已确认保存的输入、进度、结果、判断、授权和账目须在进程崩溃、操作系统崩溃及断电后保留。介质或整机物理损毁的恢复政策另行设计，不在此引入恢复管理员。

Loop 读取决定下一步所需的事实范围，不要求每步扫描完整历史。循环守卫依据原始工作事实，压缩和新 attempt 不清零阶梯。L0 观测不可关闭，L1 与 L2 提醒，L3 以打转失败收束，L4 请人处理；检测算法、阈值及预算数值归策略。

真实调用、判断和效果保留因果关联。诊断不默认发送正文、附件或秘密。遥测采样不能代替完整费用账目。

### 非目标与局部待设计

本页不决定公开接口、存储机制、线程安排、Cordis 服务名、扩展编码协议或性能数值。持续利益对齐是长期承诺，本页不据此增加自动演进设计或实现。

step 的精确切分、连续回复拒绝计数、扩展非确定输入记录、撤除后的合法接续及停止信号重试仍须技术设计。流式已展示内容在生产 runtime 自身失联时的耐久衔接沿现有架构未决范围处理，本页不宣布允许丢失，也不代定逐片落盘。

<a id="j-ag01"></a>
#### J-AG01 选定 Agent 并取得合法能力

用户希望以一个适合目标的 Agent 开始协作，定义维护者希望限定该 Agent 必需和可选的能力。前提是调用方具有相应创建或派发资格，定义与能力来源合法。用户按会话用途选定义；定义维护者声明必需能力和是否继承额外能力。装配方先选身份再解析实现，Agent 解释定义类型与继承规则，把合法采用交给会话工作流程。

结果是可解释的定义版本、必需与可选来路，以及当前可用或不可用的能力。禁止替换 official、越过锁定或删除必需项的请求被拒绝。首次装配、reload 或后续装配缺少必需合法定义，或者 Loop 必需入口不能建立时，候选失败；合法定义存在而执行实现暂不可用时，可保留已知身份和不可用应答。装配中断不制造 Run 或执行，恢复先核对候选及当前资格。已有会话的取消与归档由 Session 治理处理；Agent 不借定义校验创建第二条控制路径。

关联 [CAP-AG01、CAP-AG02](#能力定义与实现状态记录表)，协作见 [F-AG01](../../../../packages/agent/agent-contract/docs/flows/scenarios.md#f-ag01)，规格及验证见[定义专题](../../../../packages/agent/agent-contract/docs/public-api/definition.md#旅程与持续验证)。

<a id="j-ag02"></a>
#### J-AG02 推进一项工作并取得工具结果

用户已经有合法 Session 和未终结 Run，希望一次输入经过模型与工具形成结果。Agent 先认回原工作，再在允许位置承接当时全部普通输入。它向 Context 请求可发送内容，经模型前扩展和预算复核后固定请求。Model 真实收场后，Agent 对完整回复准入并解析完整动作参数，然后等待全批判断齐备，再发获准动作。

用户可以继续补充输入，但新输入不改写已发请求。前台结果或合法后台占位返回原动作位置；后台保持同一次 Tool 执行。不可用替换件返回真实的逻辑不可用结果。全批动作被拒绝时，Agent 保存原因并重新求值，不等不存在的工具，也不自动完成。模型重试仍在原调用内时继续等待；故障、中断与实例替换分别沿原拥有者接续。用户取消 Run 后不再发新动作，已有结果、费用及未知效果仍可查。

关联 [CAP-AG03、CAP-AG04、CAP-AG05、CAP-AG09](#能力定义与实现状态记录表)，协作见 [F-AG02](../../../../packages/agent/agent-contract/docs/flows/scenarios.md#f-ag02)，规格及验证见 [Loop 旅程验证](../../../../packages/agent/agent-contract/docs/flows/loop.md#旅程与持续验证)。

<a id="j-ag03"></a>
#### J-AG03 审阅一批动作并继续原判断

具备答复资格的人希望知道哪些动作需要决定，并让决定只用于所见动作。前提是动作到达允许等待的扩展位置，系统准入仍可用。不同动作各自完成判断或到达合法等待后，HITL 呈现该轮卡片批次。人可逐卡回答，也可明确不回答；尚未回答没有默认含义。Agent 等全部所需有效答复交回并按原规则处理完成，回到出卡的原扩展位置，再处理后继扩展。后继扩展仍可出下一轮卡片，整个动作批次继续等待。

卡片与唯一有效答复归 HITL，授权类答复的授权含义归 authorization。Agent 保持原参数、生效参数、实现绑定和扩展经过。最终执行还核对当前资格。参数、绑定或相关授权依据改变后，旧批准不能自动使用；无关变更不机械重问。系统准入不可用时全拒且不出卡；其他扩展的缺失与报错沿既定干预力和位置规则处置。实例退出后复用原判断、答复与调用，不重出原卡。Run 取消或原逻辑执行确定终局后解除原等待，不伪造人的答案；工具内部 Ask 仍归 Tool。

关联 [CAP-AG05、CAP-AG06、CAP-AG09](#能力定义与实现状态记录表)，协作见 [F-AG03](../../../../packages/agent/agent-contract/docs/flows/scenarios.md#f-ag03)，规格及验证见[扩展旅程验证](../../../../packages/agent/agent-contract/docs/public-api/extensions.md#旅程与持续验证)。

<a id="j-ag04"></a>
#### J-AG04 面对输入装不下或消息拒收

用户希望受阻工作留下真实原因并保护已有历史。前提是 Agent 正在准备模型输入，或处理某个原消费入口的候选消息。Context 判断能否形成可发送请求；扩展可以在合法位置阻止压缩。固定部分超限，或允许处理后仍装不下时，Agent 提出该 Run 失败，保留 Session、历史和具体原因。用户不会因该失败被自动分叉会话、切换模型或进入无穷压缩。

外部输入拒收返回发送方。完整模型回复拒收后保留原结果和费用，退避后可创建新调用。连续否决不设次数上限。否决历史跨恢复保留，不因此失败。工具结果否决只影响原消费契约指定的有效未终结 Run；旁路、后台及已终态结果由原消费入口处理，不重做工具、不造新 Run、不把迟到结果挂到后继工作。必要保存失败或查询未知时先保留对账责任，不能将未知当成成功。取消优先阻止新的处理效果；中断后先认回原压缩、原调用或原结果，再恢复相应位置。

关联 [CAP-AG04、CAP-AG07、CAP-AG08、CAP-AG09](#能力定义与实现状态记录表)，协作见 [F-AG04](../../../../packages/agent/agent-contract/docs/flows/scenarios.md#f-ag04)，规格及验证见 [Loop 旅程验证](../../../../packages/agent/agent-contract/docs/flows/loop.md#旅程与持续验证)。

<a id="j-ag05"></a>
#### J-AG05 完成工作或停止指定目标

用户希望区分工作完成、单次调用被中断和整个 Run 被取消。前提是相应操作资格有效，控制目标可定位。Agent 无动作且普通队列为空时，只提出完成候选。未完成等待、当前模式与终态前扩展仍须核对；检查要求继续或等待时回对应位置。完成、失败和取消通过同一终态出口，由 Session 记录唯一终态。

用户只控制单个模型或工具时，其他调用与整个 Run 不因此取消。模型中断后已交付内容和费用保留，该响应中未发建议不执行。Run 取消先保存意图并撤新推进资格，再按具名范围通知执行；后台、子会话和无关调用不自动跟随。Session 归档按业务取消解除等待，不以全部物理执行停止为条件；撤销归档回休眠，不恢复旧 Run、卡片或调用。控制确认未知时保留未收尾责任，实例恢复后继续对账。终态后扩展不能反转终态，迟到真实效果和费用仍归原调用。

关联 [CAP-AG08、CAP-AG09](#能力定义与实现状态记录表)，协作见 [F-AG05](../../../../packages/agent/agent-contract/docs/flows/scenarios.md#f-ag05)，规格及验证见 [Loop 旅程验证](../../../../packages/agent/agent-contract/docs/flows/loop.md#旅程与持续验证)。

<a id="j-ag06"></a>
#### J-AG06 换一个推进实例继续原工作

用户希望等待模型、工具或人的决定时，即使推进进程退出也不用重新付费或重复行动。前提是原工作事实和必要接续依据已可靠保存，Session 仍允许该 Run 推进。新的合法推进者先对账原调用和原消费位置；在途则等待，已收场则读取，已 ACK 则从消费侧依据继续，查询暂不可用则保持未知。等待可挂起或交还资源，仅等待不新增 attempt。

Model 和 Tool 独立拥有原执行寿命。只有执行拥有者确认自身失联，才适用它的恢复结论；Tool 不自动重放，Agent 替换不重发原模型。可靠交付可以先完成处理，也可以先保存接续内容或可靠引用，再解除原生产责任；模型 ACK 另要求真实收场及合法消费者。若当前资格已撤或 Run 已终态，接手者只做获准的事实保管、结算和交付，不继续旧业务。未知不能写成失败、零费用或无副作用。普通崩溃与断电后的已确认事实必须保留；在途展示内容跨生产 runtime 失联的局部耐久机制仍待细化。

<a id="j-ag07"></a>
#### J-AG07 更新定义版本并保护在途工作

有相应资格的使用者希望更新 Agent 的工作方式，又不丢掉已发调用和人的决定。前提是会话固定的 AgentDefinition 标识不变。新 Run 取同标识合法发布版本，普通恢复保持原采用版本；显式 reload 经候选校验与安全交接后可以采用同标识新版本。模型选择和入口内数据变化按各自时点生效，不等于更换定义或 attempt。

候选无效时报告原因，不发布半份构成；原采用只在仍合法时继续。结构换代由装配方与 Session 交接推进资格，原调用、扩展经过、卡片和已得判断保持原语义。尚未发的动作核对当前参数、绑定、授权和调用约定；不兼容就交回原因，不暗换参数或实现。取消先成立时新候选不能恢复推进。换代中断后按原身份对账；撤除扩展后的精确接续协议仍由成员与装配拥有者细化，不能默认作废卡片或重跑已得结论。

<a id="j-ag08"></a>
#### J-AG08 长期推进时识别重复打转并解释费用

用户希望长期任务继续前进，诊断者希望解释停在哪里、为什么等待和费用来自哪里。前提是读取资格有效，原工作事实和调用关联可核实。Loop 按所需范围读取事实，缓存标明进度并可重建。守卫按原始事实形成 L0 至 L4 的适用处置；压缩、崩溃或新 attempt 不清零阶梯。持续产生新工作不因单纯运行时间长而被当作打转。

L1、L2 提醒后可以继续，L3 以打转失败进入统一终态出口，L4 等待人的处理。已存判断复用；必要依据缺失不编造守卫通过或费用。获准的诊断者看到原调用、真实发出、判断和消费关联，不能因接手者换了就重复记账，也不能靠遥测采样补成完整账单。停止和恢复沿原控制与工作位置，守卫不扩大取消范围。算法、阈值、配置资格、适用上界与生效时点由相应策略拥有者细化，本页不钉死部署值或新增配额业务。
