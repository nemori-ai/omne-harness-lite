# Slash Command产品设计

状态：产品设计草案，revision 1。尚无整体接受证据。能力状态、阶段与明确决定各保留自身依据，落位不授予运行支持。技术承接从[能力组工程入口](../../../../packages/slash-command/README.md)展开。

## 产品需求描述

用户需要用一个可辨认的名字主动发起内容输入或系统业务。Slash Command 让这层绑定可以独立持有、替换和治理。命令是入口，命令名是身份；提示词正文、绑定目标和参数声明是命令的定义，不是各层配值后可暗换的设置。命令共同持有、来源及同名替换沿资产规则，识别与展开的专有含义由命令领域维护。

绑定恰有三种：命令自带提示词、装配中可取用的 Skill、系统业务流程。前两种产生用户消息内容，后一种由实际系统能力执行，不产生普通消息或入队资格。键盘控制与 shell 命令分别沿交互和执行机制，模型取用方法或动作也不经 Slash Command。绑定 Skill 不转移其所有权，不放宽正文读取或脚本执行资格。

交付面的人读和机读呈现遵守相同识别含义。仅输入开头可出现一条命令，正文中间的斜线文本仍是内容；来自连接件、定时或其他非交付面来源的相同文本也仍是内容。产品需要一种明确的原样输入方式，使用户能输入以斜线开头的普通文本；精确拼法由技术契约确定。

交付面动作与系统流程命令使用保留的 `omne-official` 命名空间。提示词和 Skill 绑定即使由官方提供，也不得占用该命名空间；同名定制沿既有替换规则处理。前缀边界、分隔符和参数语法须有统一技术定义，不能让客户端各自解释。

### J-SC01 创作并采用一个有明确绑定的入口

**目标与前提。**有权创作命令的主体希望将提示词或 Skill 绑定为入口。命令有合法名字、唯一绑定含义及可选参数声明；参数声明为每项提供给人的提示。共同资产规则决定提交、持有、来源、替换及锁定资格。

**正常结果。**发布校验拒绝提示词或 Skill 绑定占用保留命名空间。声明参数的命令按声明解析，没有声明时将名字之后整段文本作为自由参数。绑定目标和参数改变以修订或同名替换表达，不借设置配值让同一份命令在不同层变成不同定义。合法工作区来源仅成为候选，校验及正式采用分别确认。

**拒绝与故障。**无创作或提交资格、名字非法、定义不完整、来源不可读或绑定无法校验时明确失败，不发布半份命令，不从其他同名来源拼补正文或参数。取得文件不证明入口已经进入会话命令集。

**控制与恢复。**取消来源读取或发布等待不删除已确认的资产提交事实。恢复查询原提交及采用状态；保留原采用记录不延续已经撤销的当前权限。具体创作界面、发布入口和系统流程作者扩展另由其拥有者设计，不因本能力成立而自动提供。

### J-SC02 在交付面发现并识别当前合法命令

**目标与前提。**用户或驱动交付面的程序希望知道在目标会话能使用哪些入口。会话使用创建时捕获的租户身份，并有可核验的当前命令集；展示只披露该主体有权使用的命令。

**正常结果。**交付面识别输入开头至多一条命令，并按同一份定义提示参数。没有权限的命令不可见，敲下它与敲不存在的名字同样回答“没有这个命令”，不发送，也不改作普通消息。参数不合法时说明哪里不对并留在交付面，不成为入站到达。原样输入方式及非交付面文本沿普通内容路径。

**拒绝与故障。**当前集合无法取得时说明无法判断，不把查询故障当成空集合。预检之后集合变化或权限撤回时，受理侧仍按当前条件复核；已不合法的名字同样回答“没有这个命令”，不入队、不触发流程、不回退为普通话。该请求已经到达受理面，由原受理拥有者保留具名拒绝事实。

**控制与恢复。**取消查找或编辑不改变命令集。断线重连重新取得合法当前读面，不使用旧客户端缓存恢复撤销资格。用户手动再次提交是一次新输入；技术重传须辨认原受理，不能借自动重试重复提交。

### J-SC03 用提示词命令送出实际内容

**目标与前提。**用户希望将命令自带提示词和合法参数送给 agent。受理侧已经核验当前名字、绑定、租户、会话及参数，并固定本次采用的定义。

**正常结果。**受理时展开实际提示词及参数，形成用户消息。消息落盘前扩展取得展开后的内容和原命令标注。成功受理保存原命令、实际展开内容及必要来源依据，再由原消息拥有者赋予待处理资格。读取或展开成功都不等于消息已受理，命令领域不创建第二份队列，也不决定新建 Run。

**拒绝与故障。**正文或参数无法取得、一致版本无法成立、资格失效或受理扩展否决时，不以空展开或部分正文表示成功。否决使原命令和展开结果一起不进入消息正文；具名拦截事实仍由受理拥有者记录，并让用户可见。合法脱敏作用于展开内容，持久事实反映实际获准保存的结果，不能把脱敏前全文重新塞进标注或诊断。

**控制与恢复。**取消展开或等待回执分别报告尚未受理、已受理或无法确认。消息已受理而回复丢失时查询原消息，不按更新后的定义重新展开、重复投递。后续命令更新不改历史正文、原输入或已发模型请求。

### J-SC04 用 Skill 命令保留正文与用户参数的边界

**目标与前提。**用户通过合法绑定请求方法内容。除入口资格外，还须核验所选 Skill 的当前合法采用、正文读取权和来源条件；命令不能用绑定关系替 Skill 放权。

**正常结果。**取得的 Skill 正文逐字形成用户消息的独立内容块，用户参数另成内容块。来源是块的属性，不在正文里冒充正文文字。命令与受理拥有者保留原输入、实际取得内容、所选版本、来源及范围，再沿消息路径承接。该路径与工具 read 返回分开；它不自动执行脚本，不生成 Skill 激活状态，也不改为工具执行日志。

**拒绝与故障。**未选入、禁用或卸载、读取撤权、来源故障及资源缺失分别按 Skill 和受理契约处理，不从旧缓存或别的同名 Skill 补齐。方法仍合法选入且未禁用、卸载，主体仍有读取权且正文来源正常，仅必需依赖或脚本设施不足时，读取返回正文加缺项说明还是不可用替换件，沿前序 [Q-SK08](../skills/design.md#q-sk08-只有依赖或脚本设施不足时正文是否仍可读取) 等负责人裁定。命令适配不选择另一默认，不把设施不足改称读取撤权，也不把替换件伪装成完整正文。

**控制与恢复。**读取、展开、消息受理与结果披露分别保留真实进度。已受理消息使用原实际内容接续；重新取内容须重新核验当前权利。用户 Q03 已定 dummy 属逻辑工具执行且真实原工具未物理执行，该决定不将命令用户内容统一改为工具返回，不授权重复调用脚本。

### J-SC05 将系统流程交给真正拥有者

**目标与前提。**用户通过系统提供的流程入口请求实际能力执行或查询。命令集包含该入口，参数合法，实际流程拥有者可核验目标、当前资格及操作前提。

**正常结果。**受理协调者将动作交给真实流程拥有者。命令受理不产生用户消息或待处理资格；会话仅留命令名、参数及结果摘要。流程是否改日志、控制运行、产生资源或外部效果，由该流程契约决定。reload 是已点名的流程族，其他具体流程不靠例子自动成为支持承诺。

**拒绝与故障。**实际服务缺席或拒绝时，显示这次真实失败并保存相应摘要，随后自动刷新会话命令注册表，使失效入口不再可见。刷新本身失败须可见，不能声称命令已消失或把失败执行报告为成功；再次使用仍按当前条件核验。流程执行成功而摘要或回告失败，不能反推业务未发生。

**控制与恢复。**命令取消等待不等于流程物理停止。原流程拥有者承接控制、未知结果、迟到回执和恢复；摘要不能替代其实际操作身份、提交或恢复位置。重新查询原流程，不凭摘要缺失再次执行具有副作用的动作。

### J-SC06 显式刷新内容并及时落实撤权

**目标与前提。**用户希望在自己选择的时刻更新会话采用。命令集在会话装配时形成；合法提示词或 Skill 入口的新增、移除、禁用及内容/绑定修订经对应范围 reload 或重新装配生效，不在用户不知情时暗换定义。

**正常结果。**reload 只读取其指定来源范围、校验候选，并更新该范围合法求值。新增资格等待对应刷新或装配进入集合，收回入口资格则从下一次使用即时落实，不等 reload。命令集合不沿用 Tool/Skill 已知身份的不可用占位政策来显示无权入口。系统流程失效后的自动刷新仍是独立触发。

**拒绝与故障。**候选不完整、来源故障或校验失败时保留原采用记录，明确本次未生效，不发布半新半旧集合；原记录不延续撤权。仅更新注册表数据不要求一律重建 Agent runtime。同一 Session 固定创建时的 Agent Definition 标识；候选采用同标识的新版本，或改变捕获的 Loop、extension 或直接必要入口时，装配拥有者校验完整构成并安全交接。命令刷新不允许更换 Agent Definition 身份，也不授权刷新命令请求范围外的来源。

**控制与恢复。**连续刷新、较新选择、撤权、取消与迟到候选竞争时，由采用/装配协调者保护当前合法状态。需要重建结构时按原规则保留当前 Run 并开始新 attempt，旧调用、清单与结果位置不原地改写。恢复读取真实采用状态，不仅看“reload 完成”摘要。

### J-SC07 在取消、断线和故障后解释原请求

**目标与前提。**用户需要知道刚才的命令究竟产生了什么。系统可辨认原租户、会话、命令请求、实际定义采用、消息或流程操作身份。

**正常结果。**结果明确区分交付面未发送、受理侧拒绝、已展开未提交、消息已受理、流程已交接、实际完成、部分完成及结果未知。可见确认对应拥有者已保存的事实；通知送达不代替受理或执行。历史内容按授权读取，秘密与其他租户私有材料不因调试或恢复泄露。

**拒绝与故障。**查询不可用不是“没有发生”。必要存储不可用时，依赖持久保证的新动作不得假报成功。写入结果未知先查询或对账原身份；用户消息不因内容相同而任意去重，技术重传也不因超时就被当成另一条用户输入。

**控制与恢复。**原消费者继续保管已取得内容和结果，可靠承接前不能留下责任空档。取消、关闭交付面、实例换代和 dispose 分别报告实际效果，不撤销已经发生的业务或外部效果。归档及 Run 终态不因迟到回执复活，允许的迟到事实仍关联原工作。

## 阶段与版本支持承诺

`0.0.0 → 0.1.0` 的 CAP-SC01 至 CAP-SC09 清单尚待负责人选择。负责人选择完整能力、产品适用条件与能力依赖，可明确尚不支持的绑定或交付范围；不得将未知机制、provider、精确版本或验证方案设为先选 CAP 的前置，也不把旧 PF 的“本版”直接继承为阶段承诺。

CAP-SC04 与 CAP-SC05 依赖相应受理、消息内容及持久承接；CAP-SC05 另依赖 Skill 合法读取且保留 Q-SK08 的局部未裁范围。CAP-SC06 依赖被实际选中的系统流程契约；CAP-SC07 与 CAP-SC08 分别依赖采用协调和必要装配交接；CAP-SC09 依赖原消息/流程可查询状态。选入能力须携带这些产品条件，不能只选成功演示而省掉拒绝、撤权、未知或恢复。

公开形状、成员归属、识别语法、提交和刷新协议由技术采用确定，见[问题与技术义务](design.md#未决问题与待定事项)。支持声明须另附实际采用及验证证据；本文不推荐默认能力子集，也不凭文件存在声称已实现。

### Q-SC01 0.0.0 → 0.1.0 的完整能力与适用范围

决定责任：阶段负责人。

分类：阶段选择。场景：负责人需要决定哪些完整命令能力进入目标阶段，以及支持哪些绑定和交付条件。

已知约束：CAP-SC01 至 CAP-SC09 是完整能力候选，实现状态未核实。选入内容能力须携带合法读取、实际内容保存及原受理承接；选入流程或 reload 须携带原能力执行和恢复。撤权、租户隔离、未知结果和不盲目重做等不变量不能因参数未定或只演示成功而省略。

待决定：哪些 CAP 及产品适用条件、能力依赖进入 `0.0.0 → 0.1.0` 支持清单？可以选择其中一组完整能力，也可以选择更广的完整组合并明确尚不支持的绑定/交付范围。两种结果都需同步对外支持清单和验收范围；作者不推荐默认子集。

具体机制、provider、精确版本和验证方案随后由技术拥有者采用，不作为负责人先选 CAP 的前置。Q-SK08 的局部读取结果沿原问题集中裁定，不能借阶段清单另选一个命令专有默认。

### Q-SC02 统一定义、参数语法与原样输入公开形状

分类：技术义务。人读、机读和受理再次解析同一输入。

产品影响：影响发布、识别、原样输入和一致错误表现。

维护责任：命令定义、识别与跨客户端技术拥有者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/slash-command/docs/architecture.md#q-sc02-统一定义参数语法与原样输入公开形状)。

### Q-SC03 原输入、实际内容及受理的可靠交接

分类：技术义务。正文已读取，消息提交确认丢失而客户端准备重传。

产品影响：影响受理确认、实际内容保存及故障后的重复输入风险。

维护责任：原受理、消息及内容消费者。完整技术约束、处理方向及承接缺项见[技术唯一位置](../../../../packages/slash-command/docs/architecture.md#q-sc03-原输入实际内容及受理的可靠交接)。

### Q-SC04 指定刷新与装配交接的采用协议
