# Slash Command产品设计

状态：产品设计草案，revision 4。落位不授予运行支持。技术承接从[包组规格](../../../../packages/slash-command/SPEC.md)展开。

## 产品需求描述

用户需要用一个名字点名一件事。想让 agent 按某份 Skill 的方法做，用户在话里写 `/review`，这一轮就带着那份方法的正文，用不用不再靠 agent 猜。想换模型、改权限模式、收起会话，用户在输入框开头敲 `/model`、`/permission`、`/archive`，不用去界面上找控件。用户自己写好的一段常用提示词，发布成提示词命令，以后敲 `/名字 参数` 就发出去。

### 入口项与它的位置

一个会话此刻能点名的东西是一张清单，清单里的每一项叫[入口项](../../ubiquitous_language/terms/reach-and-availability.md#ul-command-entry--入口项--command-entry)。入口项恰有三种，**能写在哪里由种类决定**，不由每一项自己声明：

| 种类 | 能写在哪里 | 发出去之后 | 从哪来 |
| --- | --- | --- | --- |
| 引用型 | 一句话的任何位置 | 用户的话原样是用户的消息；被引用的那份 Skill 的正文另成一块，随这一轮交给 agent | Skill 领域，自动 |
| 提示词命令 | 只在开头 | 用它自带的提示词加上参数，形成用户的消息 | 资产的一个类别，由有权的主体发布 |
| 系统命令 | 只在开头 | 交给这件事真正的拥有者去做，不产生给模型的消息 | 各流程的拥有者 |

开头是一条命令时，它后面的整段是这条命令的参数，参数里的斜杠不再认作引用。开头至多一条命令；引用不限条数，同一份被引用几次只带一次。

**Skill 不需要谁为它创作命令。**一个主体在这个会话里此刻能取用的 Skill，自动是清单里的引用型入口项：发布之后马上就在菜单里；禁用之后马上不能点名，菜单里灰着并写明原因；卸下之后就不在。这只是把 Skill 现有的目录换一个形状交给命令，Skill 的事实仍归 Skill 领域，读取正文仍过 Skill 自己的读取权。

键盘控制、命令面板与按钮是同一类事的另外几种触发，见[同一条命令的四种触发](#同一条命令的四种触发)。shell 命令与模型能调的工具不经斜杠命令。

### 名字

每个入口项有一个[全名与短名](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-command-name--全名与短名--command-name)。全名是 `<空间>:<名字>`，永不相撞：系统命令的空间是保留的 `omne-official`，Skill 的空间是 `skill`，提示词命令的空间是 `prompt`。名字的词法沿 Skill 的：小写字母与数字的段，用连字符连接，全名至多 64 个字符；大写照认，折成小写。

用户平时敲短名，也就是不带空间的那一段。短名按位置解析：**在开头，系统命令先于提示词命令先于 Skill；在句中，只认 Skill。**一份 Skill 的短名在开头被一条命令占了，菜单在开头给出它的全名。提示词命令与 Skill 即使由官方提供，也不能占用 `omne-official`；租户的东西进不了保留空间。

### 斜杠怎样被认出来

一句话里的斜杠多数不是命令：路径、网址、分数、代码。用户不应该为了发一句话去想斜杠会不会出事。规则是：

- 一处斜杠只有同时满足下面几条才是**候选**：它不在代码里；它在开头，或者左边是汉字、空白、括号或标点，不是字母、数字或 `_ / . : ~ < \ - = & ? # % @ + $ *` 之一；它后面紧跟一个合词法的名字；名字后面是结尾，或者不是 `/ _ \ = @ *`，也不是「点加字母或数字」。所以 `/etc/hosts`、`https://a.b/c`、`1/2` 都不是候选。
- 候选在开头而清单里没有它、这个人看不见它，或它此刻不能用：**这句话不发出去**，用户得到「没有这个命令」或「此刻不能用」及原因。无权与不存在是同一个回答。
- 候选在句中而清单里没有它，或它是命令型的，或它此刻不能用：它是普通文字。界面上看得出它「认得但这里不算」。
- 想让一个斜杠只是文字，在它前面写一个反斜杠：`\/tmp`。给模型的文字里去掉这个反斜杠。会被拒的开头，界面给一个「按原样发送」，它就是加上这个反斜杠。

同一段文字、同一张清单，人看到的、命令行看到的和服务端受理时认出的，是同一个结果：三处用的是同一个识别规则。只有成员本人经交付面发的输入才这样识别；连接件、日程、系统主体送来的文字里有 `/名字`，仍是普通内容。

### 看到的就是受理的

用户发出一句话时，交付面带上它此刻认出的结果：开头是哪条命令（或没有），引用了哪几份 Skill。这叫[发送方所见](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-sender-view--发送方所见--sender-view)。服务端受理时按当下的清单再认一遍：

- 一样：照常受理。
- 不一样，例如发出前那份 Skill 刚被禁用：**整条不受理**，写明哪一项变了，这句话留在输入框里，用户看清之后再决定。服务端不替用户猜他原本想要什么。
- 驱动交付面的程序没有带所见：照服务端认出的受理，回执里写明绑定了什么。

### 用户的话不被改写

引用一份 Skill 时，用户的话原样存成一块，那份 Skill 的正文另成一块，块上记着它来自哪一份、哪一版（这是块的[来路标记](../../ubiquitous_language/terms/record-and-context.md#ul-origin-tag--来路标记--origin-tag)，不写进正文冒充正文）。存着的正文逐字不变；agent 读到它时知道这是哪一份 Skill 的正文，不是用户说的话。引用不运行 Skill 的脚本，不让 Skill 变成「已激活」的状态，也不放宽它的读取权：用户点了名，读取权照样由 Skill 判。

原输入、展开之后实际交出的内容、绑定到的全名与版本，在同一次受理里保存。之后那份 Skill 改了、卸了，历史不变。

### 系统命令不是一句话

系统命令做的就是界面上对应的那个控件做的事：`/model` 做的就是换模型，`/archive` 做的就是归档，经过的是同一个访问裁定。它不产生给模型的消息，不进待处理，会话里只留命令名、参数与结果摘要。一轮在跑时，每条系统命令声明它是「立刻做」还是「拒绝并说明」，也声明它什么时候生效（立刻、下一次模型请求起、下一轮起），这两项给人看，真正的拒绝来自那个操作自己。

### 同一条命令的四种触发

一条命令是一个有名字的事。用户可以敲出来、按一个键、在命令面板里选、点一个按钮。**用什么触发，不决定它做什么，也不决定它排在谁前面。**一条命令此刻不能用，四种触发给出同一个原因。

除了清单里的三种，客户端还有两种命令只在客户端里：对在跑的一轮的控制（停止这一轮、插队发送、转后台、停一个调用、重试），和界面自己的动作（开命令面板、切会话、聚焦输入框）。控制点名它要控制的那一轮或那一次调用，界面落后时服务端拒绝，不会停掉新的一轮。这两种被敲成 `/stop` 这类写法时在客户端就地执行，不作为一句话提交。键只能绑到这两种上。

用户能在一处看到全部：设置里的「命令与快捷键」一页，按组列出全部不是 Skill 的命令，每一条写着做什么、斜杠写法、现在的键、此刻能不能用；在那里改键。改过的键跟着账号走，换一个客户端登录还是自己的键。Skill 列在资产页，不列在这一页。哪些键、哪一层先查、Esc 管什么，由[桌面应用](../../../../apps/desktop/SPEC.md)定。

### J-SC01 发布一条提示词命令

**目标与前提。**有权的主体想把一段常用提示词变成一个名字。提示词命令是资产的一个类别：名字、给人看的一句话、提示词、可选的参数提示。共同资产规则决定提交、持有、来源、替换及锁定资格。

**正常结果。**提示词里可以写定长的位置参数与「剩下的全部」两种占位；没写占位时参数空一行接在提示词后面。改提示词或参数提示是同名替换的一次修订，不借设置让同一条命令在不同层变成不同定义。合法工作区来源只成为候选，校验及正式采用分别确认。

**拒绝与故障。**定义不完整、名字不合词法、想占保留空间、来源不可读时发布被拒，写明第一处不合格，不发布半份。取得文件不证明它已经在某个会话的清单里。

**控制与恢复。**取消发布等待不删除已确认的资产提交。恢复查询原提交，不重新提交一份。

### J-SC02 在输入框里找到能点名的东西

**目标与前提。**用户想知道此刻能点名什么。清单按这个会话、这个人、此刻的事实现算，只列这个人有权用的项。

**正常结果。**光标前面是一个候选斜杠加正在敲的名字时出菜单：斜杠在开头，命令与 Skill 都列；在句中，只列 Skill；开头已经是一条命令时参数里不出菜单。敲字母时按名字匹配，也能按说明里的字找到。不能用的项列在菜单里，灰着，写着原因，不能采用。采用之后写进这个位置能直接用的最短写法。认出来的地方有标记：引用、开头的命令、会被拒的开头、认得但这里不算，四种各不相同。

**拒绝与故障。**清单取不到时菜单写明「现在取不到」，不显示成空，也不把取不到当成「没有这个命令」。一个来源取不到时只有它那一部分写明取不到，其余照常。

**控制与恢复。**清单可能变了时交付面收到一个只说「可能变了」的通知，就重读。断线重连之后重读，不用旧的缓存决定什么能用。用户输入法组字期间菜单不动，按键不被处理。

### J-SC03 用提示词命令发出一条消息

**目标与前提。**用户敲 `/名字 参数`。受理时按当下的清单认出这条命令，取这一版的提示词。

**正常结果。**提示词代入参数，形成用户的消息，原输入与展开之后的内容一起保存，再照普通消息往下走：受理前处理看到的是展开之后的内容，合法脱敏作用于它。命令领域不建第二份队列，也不决定开不开新的一轮。

**拒绝与故障。**提示词取不到时整条不受理，不以空提示词或半份展开当成功。受理前处理否决时，原命令与展开结果一起不进入消息，否决由受理的拥有者记录并让用户看见。

**控制与恢复。**消息已受理而回执丢了，按原请求认回，不按更新之后的定义重新展开、重复发出。

### J-SC04 在一句话里引用一份 Skill

**目标与前提。**用户在话的任何位置写 `/某个 Skill`。这份 Skill 此刻在清单里、能用，这个人有读取权。

**正常结果。**这一轮带着用户原样的话一块，与每份被引用的 Skill 的正文各一块，块上有来路标记。agent 读到正文时知道它是哪一份的，不是用户说的话。这条路与 agent 自己调读取工具分开，不运行脚本。

**拒绝与故障。**取清单与取正文之间那份 Skill 被移除、禁用或读取权被收回：整条不受理，不发出半份，不从旧缓存或别的同名 Skill 补。只缺必需依赖而 Skill 仍可读时，正文照常返回并写明缺项，这是 [Q-SK08](../skills/design.md#q-sk08-只有依赖或脚本设施不足时正文是否仍可读取) 的裁定结果（产品负责人 PanQiWei 2026-11-12 定），命令不另选政策。

**控制与恢复。**已受理的消息用当时实际交出的内容接续，重新取内容要重新核验当下的读取权。

### J-SC05 用系统命令做一件事

**目标与前提。**用户在开头敲一条系统命令。这件事真正的拥有者能核验目标、资格与前提。

**正常结果。**受理把它交给原操作去做，结果显示给用户。会话里留下命令名、参数与结果摘要；改不改日志、控不控制运行、有没有外部效果，由那个操作的契约决定。

**拒绝与故障。**原操作拒绝时，显示的是它自己的拒绝，例如一轮在跑时归档被拒。操作做成了而回执丢了，不能反推它没发生，也不再做一次。

**控制与恢复。**取消等待不等于操作停下。未知结果、迟到回执与恢复归原操作的拥有者，按原来的那次操作认回。

### J-SC06 清单跟着事实走，不等刷新

**目标与前提。**用户发布、禁用或卸下一份 Skill 或提示词命令，或某项资格被收回。

**正常结果。**清单不是一张存着的表，每次读都按当下的事实现算，所以变化之后的下一次读就是新的：新发布的马上能点名，收回的马上不能。不需要用户重新加载，也不重新装配 agent。引用在受理时取当下胜出的那一版正文。

**拒绝与故障。**某个来源此刻取不到，只有它那一部分写明无法判断，不当成空，也不发布半新半旧的结果。

**控制与恢复。**清单变化不改变已经受理的输入与正在跑的一轮已经定下的上下文。

### J-SC07 在取消、断线和故障后解释原请求

**目标与前提。**用户需要知道刚才那条命令究竟产生了什么。系统可辨认原租户、会话、请求身份与原操作身份。

**正常结果。**结果分得清：交付面没发出、受理侧拒绝、所见对不上被拒收、消息已受理、操作已交出、已完成、结果未知。可见的确认对应拥有者已经保存的事实。

**拒绝与故障。**查询不可用不是「没有发生」。写入结果未知时先按原身份查询或对账，不因为超时就当成另一条输入再发一次。

**控制与恢复。**取消、关闭交付面、实例换代分别报告实际效果，不撤销已经发生的业务或外部效果。

## 未决问题与待定事项

技术义务的已定约束在[包组规格](../../../../packages/slash-command/SPEC.md)，这里不重复。

### Q-SC06 要等到安全点的系统命令

分类：产品与技术。重新加载、压缩这类命令在一轮跑到一半时不能马上做，要等到一个安全的时刻；它与已经排着的话谁先谁后，后到的话能不能越过它，需要一组声明。

产品影响：决定 `/reload`、`/compact` 在一轮在跑时的行为，以及用户排着的话会不会被清掉或推迟。

维护责任：命令领域定声明的形状，各命令的拥有者实现。没有一条真的命令需要它之前不定。

### Q-SK08 关联的 Skill 正文读取待裁

本域只引用[Skill 未决块的唯一 Q-SK08](../skills/design.md#q-sk08-只有依赖或脚本设施不足时正文是否仍可读取)。它已于 2026-11-12 由产品负责人 PanQiWei 裁定：必需依赖缺席不挡读取，正文照常返回并写明缺项。命令按这个结果同步，不另设政策。本节标题保留原样，别处有链接指到它。
