# PF-008 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

### 两个维度的等待态

| 场景 | 应当看到什么 |
|---|---|
| agent 调 `Ask().ask`（前台） | 那次工具执行进等待态，**run 也停住** |
| 一个**转到后台**的工具执行进等待态 | 那次执行停住，**run 照跑不误** |
| 后台那次执行的卡片 | **照样进池子**——它同样在等人 |
| 那张卡片一直没人答，而 run 已经跑完了 | 它**还挂着**；结果最终回到 **session** |
| 系统判断要问人 | **run 停住**，而**这次响应里的工具一个都还没开始执行** |
| 问「是谁停了」 | 三种情形**分得清清楚楚**，不是一句「反正停了」 |

### 判断函数

| 场景 | 应当看到什么 |
|---|---|
| llm 响应里**有 tool calls** | 判断函数**跑** |
| llm 响应里**没有 tool calls**（纯文本） | 判断函数**不跑**，run 照常往下走 |
| 查它吃了什么 | 这次响应 + 租户权限清单 + 会话授权上下文 + 会话运行模式，**四样** |
| 查它吐了什么 | 要不要停 + **给人看的说明与选项**，**两样** |
| 同一个动作，在两个不同会话里 | **可以一个放行、一个要问人**——依据本来就不同 |
| 人点「同意」之后 | 动作执行，**这笔同意进[会话授权上下文](../PF-007-meta-capabilities/design.md#会话授权上下文)** |
| 本会话里再遇到同一件事 | **不再问第二遍** |
| 换一个会话遇到同一件事 | **重新问**。那笔授权没跟过来 |
| 权限设置里明确禁止的事 | **人在卡片上点同意也做不成** |

### 决策池与卡片

| 场景 | 应当看到什么 |
|---|---|
| 同时开着五个会话，其中三个在等人 | 打开池子，**三张（或更多）卡片都在**，不必逐个会话去找 |
| **整个租户只有一个会话在跑** | 它的卡片**照样进池子**——机制不看会话数 |
| **那个会话当时没人开着** | 卡片**照样进池子**——机制不看活不活跃 |
| 点进一张卡片 | **完整说明 + 选项**，不必回原会话翻上下文就能判断 |
| 看不懂那段说明 | **能溯源回原会话** |
| 分辨这张卡是 agent 问的还是系统拦的 | 界面上**不需要分**；**记录里分得出** |
| 查一张卡片会解除什么 | **看得出来**是解除一次前台执行、一次后台执行、还是一个 run |
| 在原会话里答一张卡 | 算数；**池子里那张随即消失** |
| 在池子里答一张卡 | 算数；**会话里那张随即消失** |
| 同一张卡片试图答第二次 | **答不了**，它已经了结 |
| 一个人属于两个租户 | 两边卡片**分属各自的池子，不混** |
| 想答一张自己访问不了那个会话的卡片 | **看不到它，也答不了** |
| 租户管理员看全局 | 看得到这个租户里**有哪些会话在等人** |

### 一批卡片与解除

| 场景 | 应当看到什么 |
|---|---|
| `ask` 一次问三个问题 | 池子里**三张卡片** |
| 一次响应里两个动作被判定要人点头 | 池子里**两张卡片** |
| 答了三张里的两张 | **什么都没发生**，run 还等着 |
| 答掉第三张 | 三个答案**一起**回到那个 run，它继续 |
| 其中一张点「不回答」 | 那张**解除**，且**计入答完** |
| 一批里全都点了「不回答」 | 照样解除阻塞；agent 拿到的是**「没有答案」，不是失败** |
| 人否掉一个动作 | agent 拿到**「人不同意」**，**不是执行失败** |

### 永远等待与会话可用性

| 场景 | 应当看到什么 |
|---|---|
| 卡片挂了很久 | **一直挂着**。翻遍设计**找不到任何「多久之后算什么」** |
| 等待期间人在会话里发新任务 | **明确挡下并说明原因**——不排队，也不被当成答复 |
| 等待期间人想中断 | **随时可以**，记为**被中断，不是失败** |
| 中断之后 | 那一批卡片**一并清掉**，池子里不留孤儿 |
| 会话走到终态 | 悬着的卡片**一并清掉** |
| 有东西在等人 | **人会知道**——通知必须存在 |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| **卡片到点了，系统替人给了个答案** | **替人签字。**无论到点算同意还是算拒绝，都是同一种越权 |
| **设计里藏着任何「多久之后算什么」** | 同上 |
| **后台工具进等待态，把 run 也停了** | 后台的意义当场作废——转后台就是为了不挡着 run |
| **后台工具的等待不进池子** | **没人知道它在等，它会永远等下去**，而且没有任何人会发现 |
| **一批卡片答到一半就放行** | agent **拿着残缺的前提做决定**，而做出来的东西看上去和正常的一模一样 |
| **同一张卡片在两处各有一套状态** | 「在会话里答了、池子里那张还在」——人从此不信任这个池子 |
| **同一张卡片被答两次** | 同上 |
| **卡片不能溯源回原会话** | 说明写偏的时候，人只能瞎点或者干脆不管 |
| **人拒绝被记成执行失败** | agent 会**重试一件人刚刚否掉的事**，而且觉得自己在尽职尽责 |
| **「不回答」被记成失败** | 同上。人不想答、答不上来、系统出错，是三件事 |
| **判断函数生成说明失败，于是放行** | **让最危险的那次调用绕过了这一关**。这一关的失败必须是「停下来」 |
| **纯文本响应也去跑判断函数** | 没有动作可拦，纯耗 |
| **池子跨租户混在一起** | 租户隔离在这里破掉 |
| **另开一套「答复资格」** | 两套规则迟早在某个边角给出不同答案 |
| **等待期间的新任务被悄悄排队** | 用户以为自己交代了事情，**其实什么都没发生** |
| **中断这条路被关掉** | 会话只收答复与中断 + 永远等待，**用户被锁死在一个他不想继续的任务里** |
| **池子长出自己的状态与流转**（变成「组织待办中心」） | 真正在等的那个 run 被隔在一层之外；而**「组织在等」本来就是个伪概念** |
| **按当前活跃会话数决定卡片发不发进池子** | 机制长出了一个不该有的分支，而且它在「只有一个会话」时**悄悄退化，没人会注意到** |
| **人在池子里看到自己无权访问的会话内容** | 卡片自包含**不是泄露上下文的借口** |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 两个维度真的分开 | 造一个后台工具的等待，**run 照跑**；造一次 `Ask()`，**run 停** | 两种情形表现一样 |
| run 级的等待成立 | 系统拦下一个动作时，**被拦的那个动作还没开始执行**，停住的是 run 不是某次工具执行；**哪怕此刻有后台执行在跑，它也不受影响** | 它被硬塞进某次工具执行里；或者「有没有工具在跑」被当成了判据 |
| 判断函数的触发条件 | 纯文本响应跑一百次，**判断函数一次都没跑** | 它每次都跑 |
| 不替人作答 | **翻遍设计找不到任何时间或默认答案的字段** | 有一个默认答案藏在某处 |
| 池子省得下事 | 五个会话在等，人**打开一处就看全**，且**点进去就能判断** | 他还得回每个会话去看 |
| 机制与会话数无关 | 把会话数从 1 调到 50，**卡片一律进池子**，行为没有分支 | 某个数量之下它不发了 |
| 卡片自包含 | 随机抽一张卡片给没看过那个会话的人，**他能做出判断** | 他必须先去读会话 |
| 溯源没被堵死 | 任何一张卡片**都点得回它所属的会话** | 有卡片是孤岛 |
| 两个入口一件事 | 在任一处答完，**另一处立刻消失** | 两处各自有状态 |
| 全答完才解除 | 答到一半，**被阻塞的东西一动不动** | 它提前走了 |
| 拒绝与失败分得开 | 人否掉一个动作，agent **不重试** | 它重试了 |
| 失败方向正确 | 让判断函数在生成说明时出错，**结果是停住，不是放行** | 它放行了 |
| 租户隔离 | 跨租户的卡片**一张都串不过去** | 串过去了 |
| 用户不会被锁死 | 等待期间**随时中断得掉** | 他只能答或者干等 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| Run 怎么被驱动、怎么收束 | 归后续 topic。本 topic 只用到「它有一个等待态」 |
| 会话怎么建、历史怎么存、输入平时怎么进来 | 同上 |
| 会话运行模式本身 | **另有归属**。本 topic 依赖它、不定义它 |
| 判断函数**怎么实现** | 产品只定它的职责与性质 |
| 通知用什么形式送达 | 技术设计。产品只要求**它必须存在** |
| 池子的界面、排序、分组 | 同上。产品只要求**人找得到该他答的那张** |
| 「不能访问会话但能审批」这类角色 | 本版答复资格跟会话访问权一致，**这个角色长不出来**。是有意的取舍 |
