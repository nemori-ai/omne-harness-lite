# PF-008 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

### 两个维度的等待态

| 场景 | 应当看到什么 |
|---|---|
| agent 调 `Ask().ask`（前台） | 那次工具执行进等待态，**run 也停住** |
| 一个**转到后台**的工具执行要进等待态 | **本版不发生**——[要等应答的执行只在前台等](../PF-006-tools-and-skills/design.md#66-前台后台-与-等待态是两个维度)。下面两行说的是将来打开这一格时的样子，本版不验收 |
| （将来）后台那次执行的卡片 | **照样进池子**——它同样在等人；**run 照跑不误** |
| （将来）那张卡片一直没人答，而 run 已经跑完了 | 它**还挂着**；结果最终回到 **session** |
| 系统判断要问人 | **run 停住**，而**这次响应里的工具一个都还没开始执行** |
| 问「是谁停了」 | 三种情形**分得清清楚楚**，不是一句「反正停了」 |

### 判断函数

| 场景 | 应当看到什么 |
|---|---|
| llm 响应里**有 tool calls** | 判断函数**跑** |
| llm 响应里**没有 tool calls**（纯文本） | 判断函数**不跑**，run 照常往下走 |
| 查它吃了什么 | 这次响应 + 租户权限清单 + 会话授权上下文 + 会话运行模式，**四样** |
| 查它吐了什么 | 要不要停 + **给人看的说明与选项**，**两样** |
| 同一个动作，在两个不同会话里 | **可以一个放行、一个要问人**——依据本来就不同 |
| 系统拦下来的那张卡片 | 选项是**固定的四档**：不允许 / 这次 / 本会话 / 本租户 |
| 点「这次允许」 | 动作执行，**不留下任何授权** |
| 点「本会话内这类都允许」 | 动作执行，这笔进**[会话授权上下文](../PF-007-meta-capabilities/design.md#会话授权上下文)** |
| 点「本租户所有会话都允许」 | 动作执行，**写进权限设置** |
| **没有改租户设置资格的人看这张卡片** | **第四档不出现** |
| **组织把这类动作的执行权限收窄到不含「自动」**，有资格的人看这张卡片 | **第四档同样不出现**——写下去也不生效 |
| 判断函数算出「要问」，卡片却写不出来 | **那些动作不执行**，agent 拿到「不许做」及原因；**人被明确告知这里出了问题**；没有一张空卡挂着等 |
| 放行判断那一件被想办法换成同名的另一件、配成只观察、或禁用 | **做不到**——它不能被替换、禁用或收窄 |
| **放行判断此刻不可用**，这一步有动作要执行 | **一律被拒，不出卡**——顶上的是全拒件；agent 拿到的拒绝写明「放行判断此刻不在」 |
| 一件从别家搬来的 hook 出了一张四档样子的卡，人选了「本会话都允许」或「本租户都允许」 | **只算对那一件的答复**：会话授权上下文与权限设置都**没有**多一笔；卡片样式与系统拦下来的那张**分得开** |
| **一个被明确禁止的动作** | **根本不产生卡片**——不存在「禁止但你可以选允许多久」 |
| 本会话里再遇到同一件事 | **不再问第二遍** |
| 换一个会话遇到同一件事 | **重新问**。那笔授权没跟过来 |
| 权限设置里明确禁止的事 | **人在卡片上点同意也做不成** |

### 决策池与卡片

| 场景 | 应当看到什么 |
|---|---|
| 同时开着五个会话，其中三个在等人 | 打开池子，**三张（或更多）卡片都在**，不必逐个会话去找 |
| **整个租户只有一个会话在跑** | 它的卡片**照样进池子**——机制不看会话数 |
| **那个会话当时没人开着** | 卡片**照样进池子**——机制不看活不活跃 |
| 点进一张卡片 | **完整说明 + 选项**，不必回原会话翻上下文就能判断 |
| 看不懂那段说明 | **能溯源回原会话** |
| 分辨这张卡是 agent 问的、系统拦的还是拓展件问的 | 界面上**不需要分**；**记录里分得出**，拓展件出的**还标得出是哪一件** |
| 一件拓展件出的卡 | **选项是它自己写的**，人照样**可以自由作答**；进同一个池子、守同样的规矩（只答一次、全答完才解除、不会自己消失） |
| 一件拓展件（或从别家搬来、带着 `allow` / 代答输出的 hook）想在人看到之前替人作答或放行 | **不生效**，卡片照出；那类输出**只算「无意见」**，导入时已明示 |
| 查一张卡片会解除什么 | **看得出来**是解除一次前台执行、一次后台执行、还是一个 run |
| 在原会话里答一张卡 | 算数；**池子里那张随即消失** |
| 在池子里答一张卡 | 算数；**会话里那张随即消失** |
| 同一张卡片试图答第二次 | **答不了**，它已经了结 |
| 一个人属于两个租户 | 两边卡片**分属各自的池子，不混** |
| 想答一张自己访问不了那个会话的卡片 | **看不到它，也答不了** |
| 租户管理员看全局 | 看得到这个租户里**有哪些会话在等人** |

### 一批卡片与解除

| 场景 | 应当看到什么 |
|---|---|
| `ask` 一次问三个问题 | 池子里**三张卡片** |
| 一次响应里两个动作被判定要人点头 | 池子里**两张卡片** |
| 同一次停下里，一个动作被放行判断拦、另一个被租户的拓展件拦 | **一批两张**，一起等、一起解除 |
| 一批答完之后，排在后面的一件拓展件又要问人 | **第二轮卡片**，照一样的规矩；卡片上**看得出答完之后未必马上接着跑** |
| 答了三张里的两张 | **什么都没发生**，run 还等着 |
| 答掉第三张 | 三个答案**一起**回到那个 run，它继续 |
| 其中一张点「不回答」 | 那张**解除**，且**计入答完** |
| 一批里全都点了「不回答」 | 照样解除阻塞；agent 拿到的是**「没有答案」，不是失败** |
| 人否掉一个动作 | agent 拿到**「人不同意」**，**不是执行失败** |

### 永远等待与会话可用性

| 场景 | 应当看到什么 |
|---|---|
| 卡片挂了很久 | **一直挂着**。翻遍设计**找不到任何「多久之后算什么」** |
| 等待期间人在会话里发新消息 | **照收，进队列**；同时给一个**弱提示**：还有几张在等你 |
| 等待期间后台执行完成的通知到了 | **照收，进队列**——那是这个 run 自己等的东西 |
| 阻塞解除后 agent 走下一步 | 队列里攒下的**一起看得到**，不分批 |
| 用户在会话里发的那条消息 | **不会被当成对某张卡片的答复**。答复只在卡片上做 |
| 等待期间人想中断 | **随时可以**，记为**被中断，不是失败** |
| 中断之后 | 那一批卡片**一并清掉**，池子里不留孤儿 |
| 会话被归档 | 悬着的卡片**一并清掉** |
| 据点停机时一次执行正停在 `Ask()` 上等人，恢复后这次执行落了失败（异常中断） | 它的卡片被**关成「已作废」**，标明「它等的那次执行已经没了」；**卡片上没有任何答案**，agent 拿到的是异常中断，不是「人同意」或「人拒绝」 |
| 一张卡片挂了三天，它等的那次执行还在 | **照挂**——关卡只看那次执行终没终局，不看挂了多久 |
| 有东西在等人 | **人会知道**——通知必须存在 |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| **卡片到点了，系统替人给了个答案** | **替人签字。**无论到点算同意还是算拒绝，都是同一种越权 |
| **一件拓展件在人看到之前替人答了卡、或把「问一下」改成了放行** | 同上——拓展件是系统里的一段判断，不是人；**而且放行多出一条绕开权限治理的路** |
| **拓展件出的卡在记录里分不出是哪一件出的** | 租户说不清自己哪条规矩在起作用，审计也查不到是谁拦的 |
| **设计里藏着任何「多久之后算什么」** | 同上 |
| **一张它等的执行已经没了的卡片还挂在池子里等人答** | 人替一件已经没了的事花判断，**答完才知道白答了**；池子里的卡不再都值得答 |
| **后台工具进等待态，把 run 也停了** | 后台的意义当场作废——转后台就是为了不挡着 run |
| **后台工具的等待不进池子** | **没人知道它在等，它会永远等下去**，而且没有任何人会发现 |
| **一批卡片答到一半就放行** | agent **拿着残缺的前提做决定**，而做出来的东西看上去和正常的一模一样 |
| **同一张卡片在两处各有一套状态** | 「在会话里答了、池子里那张还在」——人从此不信任这个池子 |
| **同一张卡片被答两次** | 同上 |
| **卡片不能溯源回原会话** | 说明写偏的时候，人只能瞎点或者干脆不管 |
| **人拒绝被记成执行失败** | agent 会**重试一件人刚刚否掉的事**，而且觉得自己在尽职尽责 |
| **「不回答」被记成失败** | 同上。人不想答、答不上来、系统出错，是三件事 |
| **判断函数生成说明失败，于是放行** | **让最危险的那次调用绕过了这一关**。这一关的失败必须是「不放过去」 |
| **判断函数写不出卡，run 却挂着等一张不存在的卡** | 永远等不到答复——**那不是停住，是卡死** |
| **搬来的 hook 出的卡上点一下，就写进了会话授权或租户权限** | 放行多出一条绕开放行判断的路，**而人以为自己只是答了一张普通的卡** |
| **组织不许「自动」的动作，卡片上仍摆着「本租户全允许」** | 人按下去以为给了长期授权，**下一次照样被问**，而他不知道为什么 |
| **纯文本响应也去跑判断函数** | 没有动作可拦，纯耗 |
| **池子跨租户混在一起** | 租户隔离在这里破掉 |
| **另开一套「答复资格」** | 两套规则迟早在某个边角给出不同答案 |
| **等待期间把用户的消息挡回去** | 等于告诉他「你现在不能说话」，而他多半只是**忘了还有卡片要答** |
| **等待期间把后台执行的完成通知拒收** | 那是**这个 run 自己发起的活**。拒收它，run **永远收不到自己等的东西** |
| **队列里的东西分批喂给 agent** | 它得靠多轮去拼一个本来就完整的现场 |
| **用户发的普通消息被当成对某张卡片的答复** | 系统替他答了一张他没打算答的卡片 |
| **人明确点了「本租户全允许」，系统却只当作这一次** | 把他明确要的东西打了折——**与静默升格同样是不听人说话，只是方向相反** |
| **没有资格的人也能点「本租户全允许」** | 正是 [PF-007 点出的那个洞](../PF-007-meta-capabilities/design.md#611-ask通向人)：**会话里坐着的人，未必是设权限的人** |
| **被明确禁止的动作也弹卡片问「允许多久」** | 禁止形同虚设。它应当在判断那一步就被否掉，根本不产生卡片 |
| **中断这条路被关掉** | 卡片不会自己消失 + 永远等待，**那个 run 会一直挂着，没有任何出路** |
| **池子长出自己的状态与流转**（变成「组织待办中心」） | 真正在等的那个 run 被隔在一层之外；而**「组织在等」本来就是个伪概念** |
| **按当前活跃会话数决定卡片发不发进池子** | 机制长出了一个不该有的分支，而且它在「只有一个会话」时**悄悄退化，没人会注意到** |
| **人在池子里看到自己无权访问的会话内容** | 卡片自包含**不是泄露上下文的借口** |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 两个维度真的分开 | 造一次 `Ask()`，**run 停**；系统拦下一个动作，**停的是 run 而不是某次工具执行**（后台工具的等待本版关着，将来打开时**run 照跑**） | 两种情形表现一样 |
| run 级的等待成立 | 系统拦下一个动作时，**被拦的那个动作还没开始执行**，停住的是 run 不是某次工具执行；**哪怕此刻有后台执行在跑，它也不受影响** | 它被硬塞进某次工具执行里；或者「有没有工具在跑」被当成了判据 |
| 判断函数的触发条件 | 纯文本响应跑一百次，**判断函数一次都没跑** | 它每次都跑 |
| 不替人作答 | **翻遍设计找不到任何时间或默认答案的字段**；**也找不到任何一条让拓展件替人作答或放宽的路** | 有一个默认答案藏在某处，或有一件拓展件能替人点头 |
| 池子省得下事 | 五个会话在等，人**打开一处就看全**，且**点进去就能判断** | 他还得回每个会话去看 |
| 机制与会话数无关 | 把会话数从 1 调到 50，**卡片一律进池子**，行为没有分支 | 某个数量之下它不发了 |
| 卡片自包含 | 随机抽一张卡片给没看过那个会话的人，**他能做出判断** | 他必须先去读会话 |
| 溯源没被堵死 | 任何一张卡片**都点得回它所属的会话** | 有卡片是孤岛 |
| 两个入口一件事 | 在任一处答完，**另一处立刻消失** | 两处各自有状态 |
| 全答完才解除 | 答到一半，**被阻塞的东西一动不动** | 它提前走了 |
| 拒绝与失败分得开 | 人否掉一个动作，agent **不重试** | 它重试了 |
| 失败方向正确 | 让判断函数在生成说明时出错，**结果是那些动作不执行、人被告知**，不是放行，也不是挂着等一张不存在的卡 | 它放行了，或 run 卡死 |
| 租户隔离 | 跨租户的卡片**一张都串不过去** | 串过去了 |
| 用户不会被锁死 | 等待期间**说得上话，也随时中断得掉** | 他只能答或者干等 |
| 队列真的在收 | 等待期间发三条消息 + 收一个后台完成通知，解除后 agent **四样都看得到** | 有东西被丢了或被挡了 |
| 授权档位由人明确选 | 四档**摆在卡片上**，选哪档就是哪档，**系统不替他选也不打折** | 有一档被系统代劳或忽略 |
| 第四档受资格约束 | 拿一个没有改设置资格的人来看，**那一档不出现** | 他也能点 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| Run 怎么被驱动、怎么收束 | 归 [PF-012](../PF-012-agent-loop-and-run/README.md)。本 topic 只用到「它有一个等待态」 |
| **拓展件出卡之后怎么停、协程没了怎么接着等、回来怎么回放** | 归 [PF-012](../PF-012-agent-loop-and-run/design.md#等人是-loop-的原语)。本 topic 只验卡片出来之后的那些 |
| 会话怎么建、历史怎么存 | 归 [PF-015](../PF-015-session-lifecycle-and-ownership/README.md)；**输入平时怎么进来**归 [PF-014](../PF-014-inbound-intake-and-queueing/README.md) |
| 会话运行模式本身 | 归 [PF-015](../PF-015-session-lifecycle-and-ownership/design.md#会话运行模式)。本 topic 依赖它、不定义它 |
| 判断函数**怎么实现** | 产品只定它的职责与性质 |
| 通知用什么形式送达 | 技术设计。产品只要求**它必须存在** |
| 池子的界面、排序、分组 | 同上。产品只要求**人找得到该他答的那张** |
| 「不能访问会话但能审批」这类角色 | 本版答复资格跟会话访问权一致，**这个角色长不出来**。是有意的取舍 |
