**已发到**：ST-008-06

第二期按用户确认的子期推进：2A 可控的人机协作（11张）、2B 稳定完成项目长任务（15张）、2C 扩大委托与自主执行（7张）。每张卡的“子期”标示所属批次，不表示交付状态；子期内卡序为 PM 建议。撰写授权与来源范围见 [decisions](design.md)。就绪只表示覆盖的产品场景写定，不表示整包接受、技术承诺接受或实现完成。

### ST-008-01 · 批准后只执行本次获准动作

- **子期**：2A · 可控的人机协作
- **价值**：用户能在执行发生前批准或拒绝一次动作。
- **覆盖场景**：[S7](acceptance.md#判断函数)、[S8](acceptance.md#判断函数)、[S12](acceptance.md#判断函数)、[S13](acceptance.md#判断函数)、[S49](acceptance.md#一批卡片与解除)
- **演示**：
  1. 发起需要批准的工具动作，再发起只有文本的回复 → 前者执行前出固定四答卡，后者不出执行批准卡。
  2. 选择“仅这一次允许” → 只执行本次动作，会话没有新增长期授权；再次发起同动作仍要求批准。
  3. 另起一次动作并选择拒绝 → 动作未执行，agent 取得“没批准”，不是工具执行失败。
- **不含**：Ask 自由请示、会话或租户长期授权写入、组合 hooks 卡片。
- **前置**：ST-012-01
- **就绪**：是

### ST-008-02 · 不能批准时明确阻止执行

- **子期**：2A · 可控的人机协作
- **价值**：用户知道动作为什么未执行，故障也不会导致先做后问。
- **覆盖场景**：[S16](acceptance.md#判断函数)、[S17](acceptance.md#判断函数)、[S18](acceptance.md#判断函数)、[S20](acceptance.md#判断函数)、[S22](acceptance.md#判断函数)
- **演示**：
  1. 分别用无租户设置权限的成员、组织禁止自动授权的条件发起动作 → 固定四答中的第四项隐藏，不能越权写入。
  2. 禁止该动作，再尝试让 agent 执行 → 当场拒绝，不出可绕过禁止的批准卡。
  3. 分别让出卡能力和放行判断不可用 → 动作都不执行；出卡失败向 agent 和人说明原因、不制造空等待，判断不可用由全拒件接替。
- **不含**：自动恢复服务、策略覆写和绕过判断。
- **前置**：ST-008-01
- **就绪**：是

### ST-008-03 · 在决策池找到有权处理的会话请示

- **子期**：2A · 可控的人机协作
- **价值**：用户不用逐个打开会话就能找到自己有权答复的请示。
- **覆盖场景**：[S26](acceptance.md#决策池与卡片)、[S28](acceptance.md#决策池与卡片)、[S29](acceptance.md#决策池与卡片)、[S30](acceptance.md#决策池与卡片)、[S37](acceptance.md#决策池与卡片)、[S38](acceptance.md#决策池与卡片)、[S39](acceptance.md#决策池与卡片)、[S40](acceptance.md#决策池与卡片)
- **演示**：
  1. 准备同租户五个会话，其中三个各有一张等待卡，包括未打开的会话 → 池里出现三张可独立读懂的卡，并能跳到来源会话。
  2. 分别从会话与池提交同卡答复，包括同时答复 → 只形成一笔有效答复；两个入口的待答状态同步消失。
  3. 用另租户、同租户但无该会话访问权的成员，以及只拥有租户管理员身份的成员查看 → 租户池相互分开；无会话权限不能看或答，管理员身份只让其知道哪里在等，不自动取得卡片正文。
- **不含**：通知渠道、池排序和目标会话不存在时的跨会话投递。
- **前置**：ST-008-01
- **就绪**：是

### ST-008-04 · 授权按明确作用域生效并可撤回

- **子期**：2A · 可控的人机协作
- **价值**：用户可以限制授权作用域，并让撤回影响下一次动作。
- **覆盖场景**：[S14](acceptance.md#判断函数)、[S15](acceptance.md#判断函数)、[S23](acceptance.md#判断函数)、[S24](acceptance.md#判断函数)、[S76](../PF-007-meta-capabilities/acceptance.md#状态族与他者族)、[S77](../PF-007-meta-capabilities/acceptance.md#状态族与他者族)、[S78](../PF-007-meta-capabilities/acceptance.md#状态族与他者族)、[S20](../PF-015-session-lifecycle-and-ownership/acceptance.md#创建变化与恢复补充)
- **演示**：
  1. 在 A 的批准卡选择本会话授权 → A 下次同动作不再问，B 仍问；第9块能指认该授权。
  2. 由有权限的成员选择租户级允许，再在自由答复或普通消息中给出明确作用域的授权表达 → 按表达与本人权限求值；租户结构化授权由第8块读取，不塞入第9块。
  3. 撤回本会话的一笔授权，再执行原动作 → 第9块保留授权及撤回先后，下一次判断不沿用已撤回授权。
- **不含**：不清楚作用域时创设默认权限、完整组织治理界面及历史授权批量迁移。
- **前置**：ST-008-01
- **就绪**：是

### ST-008-05 · 答完整批卡片才继续本轮判断

- **子期**：2A · 可控的人机协作
- **价值**：用户知道一批答复何时完整，系统不会收到部分答案就抢先执行。
- **覆盖场景**：[S41](acceptance.md#一批卡片与解除)、[S43](acceptance.md#一批卡片与解除)、[S44](acceptance.md#一批卡片与解除)、[S45](acceptance.md#一批卡片与解除)、[S46](acceptance.md#一批卡片与解除)、[S47](acceptance.md#一批卡片与解除)、[S48](acceptance.md#一批卡片与解除)
- **演示**：
  1. 一次提出三个问题，只答两个 → 三张卡同属一批，Run 仍停住；跳过第三题后整批解除，跳过被视为已答。
  2. 另起三个问题并全部跳过 → 交回“没给答复”，不是工具执行失败。
  3. 准备同动作批次里的系统判断和一个可出卡 hook → 各自的卡同批待答；全批答完才继续。若后续 hook 又需要答复，则第二轮再出卡，并提示可能还有后续。
- **不含**：自动替人选择、hook 自动答系统卡以及派发后台等待。
- **前置**：ST-007-01、ST-008-01
- **就绪**：是

### ST-008-06 · 停止等待会作废整批请示

- **子期**：2A · 可控的人机协作
- **价值**：用户能停止无人答复的等待，不必先唤醒执行者。
- **覆盖场景**：[S55](acceptance.md#永远等待与会话可用性)、[S56](acceptance.md#永远等待与会话可用性)、[S49](../PF-012-agent-loop-and-run/acceptance.md#一可观察的场景)
- **演示**：
  1. 让一批批准或提问卡停在等人，确认没有活跃 Agent Runtime，再停止 Run → 取消仍成立，等待按中断收场，不是执行失败。
  2. 从池与会话查看该批卡，再尝试答原卡 → 整批已不在待答集合，旧卡不能放行原动作。
- **不含**：会话归档、撤销外部效果和恢复已取消任务。
- **前置**：ST-012-07、ST-014-04
- **就绪**：是
