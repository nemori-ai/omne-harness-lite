# PF-008 决策与来源

产品设计允许 product manager 做判断，但**不允许发明没人拍过板的东西**。
本页把两者分开：哪些是产品负责人裁决的，哪些是 PM 自己推导的，各自依据在哪。

## 二、PM 推导

从已拍板内容推出的判断，附可核对的推理链。

| 结论 | 从哪几条推出 | 推理 |
|---|---|---|
| **后台工具的等待态照样进池子，但不阻塞 run** | 「两个维度解耦」+ [PF-006 的前台/后台](../PF-006-tools-and-skills/design.md#66-前台后台-与-等待态是两个维度) | 两个维度一分开，就掉出**三种情形**而不是两种。中间那种——后台工具进等待态——**也需要人输入，也该进池子，但 run 不必停**。不进池子的话，**没人知道它在等，它会永远等下去而且没人会发现** |
| **系统那条只能挂在 run 上** | 「执行点位在拿到 llm response 之后」 | 那一刻**这次响应里的工具一个都还没开始执行**，所以**没有对应的那次工具执行可以承载这个等待**。注意此刻**可能仍有后台执行在跑**——但**「有工具在执行」与「有那次工具执行」是两回事**，后台那些承载不了这个等待。这从另一面印证了两个维度必须分开 |
| **一个会话同一时刻最多一个 run 在等** | 「新消息进队列、由当前 run 在下一步消费」 | 新消息**不另起 run**，所以这条在改判之后**仍然成立**——但理由变了：先前是「不收所以不起」，现在是「**收了但不起**」。另外**同一会话可以同时有别的后台执行在等**，它们各等各的 |
| **卡片必须能溯源回原会话** | 「说明由那个函数生成」 | 函数可能写偏、写漏。**堵死溯源，人在看不懂的时候只有两条路：瞎点，或者干脆不管**——两条都是坏的。自包含的意思是「通常不必回去」，不是「不许回去」 |
| **卡片要让人看出「答了它会解除什么」** | 三种情形 + 一个会话可能有多张卡片 | 人在池子里看着五张，他想知道「我答了这张，那个任务是不是就接着跑了」。看不出来就只能一张张试，而**试错在这里是昂贵的**——每张卡片背后都可能是一个跑了很久的任务 |
| **两种来源的卡片形状一样，但记录里分得出** | 「无论 agent 发起还是系统计算发起，都在这个池子里以卡片形式陈列」 | 让人去理解「这张是 agent 问的、那张是系统拦的」，是**把系统内部的结构负担转嫁给他**。但审计需要分——**系统拦下一个动作是安全事件的线索，agent 主动问不是**。混在一起就看不出「这个 agent 频繁触碰危险动作」 |
| **人拒绝必须与执行失败分得开** | [PF-006 六种收场](../PF-006-tools-and-skills/design.md#55-一次工具执行的收场有六种)要「分得开」 | 混在一起，agent 会**重试一件人刚刚否掉的事**，而且它会觉得自己在尽职尽责 |
| **「不回答」也与失败分得开** | 上一条 + 「或者用户点击不回答」这条裁决 | **人不想答、人答不上来、系统出错了，是三件不同的事。**agent 拿到的是「没有答案」，据此改道或收尾 |
| **判断函数失败时的方向是「停住」，不是「放行」** | 「这一关是为了拦危险动作」 | 生成不出说明就放行，等于**让最危险的那次调用绕过了这一关**——而失败本来就更可能发生在复杂、少见、危险的输入上 |
| **答复资格跟会话访问权一致，不另开一套** | 「同一概念只定义一次」 | 另立一套「答复资格」，两套规则**迟早会在某个边角上给出不同答案**，而那时没人说得清哪套对。代价是「不能访问会话但能审批」这类角色本版长不出来，已写进取舍 |
| **跨租户的卡片分属各自的池子** | 「池子是租户的」+ [PF-001 跨租户默认拒绝](../PF-001-identity-scope-and-agent-constraints/design.md#租户) | 一个人属于多个租户是常态，混在一起就是在这扇门上破掉隔离 |
| **池子是陈列，不能长出自己的状态与流转** | 产品负责人的纠正：「不存在组织在等什么这个概念」 | 把池子当主体，就会做出一个「组织待办中心」——它开始有自己的状态、流转、归属，而**真正在等的那个 run 反倒被隔在一层之外**。**陈列不等于主体** |
| **通知必须存在** | 「永远等待」 | 不设上限是硬规则，但它把一个问题推给产品：**人怎么知道有东西在等他**。池子解决的是「找得到」，不是「知道」。**没有通知，「永远等着」就变成「永远没人管」** |
| **中断这条路必须始终开着** | 「永远等待」+「卡片不会自己消失」 | 人可能永远不去答，而卡片不会自己消失——没有中断，那个 run 就真的会挂到天荒地老。**改判之后这条依然成立，只是理由换了**：从「用户被锁死、连话都说不了」变成「**那个 run 没有别的出路**」 |
| **答复只在卡片上做，普通消息永远是消息** | 改判后「等待期间照收消息」 | 这条消解了改判带来的唯一真问题——**这条消息是答复还是新交代**。不必靠「当前有没有卡片挂着」去猜（legacy 正是这么判的），**因为答复根本不走消息这条路** |
| **队列里的东西要一起交付，不分批** | 「解除阻塞态，消息一起它都看得到」 | 分批喂的话，agent 得靠多轮去拼一个**本来就完整的现场** |
| **系统拦截的卡片还要有「不允许」这一档** | 产品负责人列的三档全是「允许多久」 | 只给三档允许，这一关就退化成「问你允许多长」而不是「问你允不允许」。**拒绝必须是一个选项**，否则这道门挡不住任何东西 |
| **第四档（本租户全允许）受资格约束** | 它写的是租户[权限设置](../PF-002-assets-settings-and-permissions/design.md#52-设置与权限是资产的两种属性) + [PF-007 的告诫](../PF-007-meta-capabilities/design.md#611-ask通向人) | **只有有权改那份设置的人才选得了**，没资格的人卡片上不出现这一档。否则就正是 PF-007 点出的那个洞——**会话里坐着的那个人，未必是设权限的那个人**，让普通成员点一下就给全租户开了长期授权 |
| **被明确禁止的动作不产生卡片** | 三样输入合起来判断 | 禁止的东西在判断那一步就该被否掉。**不存在「这件事禁止，但你可以选允许多久」这种问题**——弹出这张卡片本身就说明禁止没生效 |
| **四档摆出来不违反 PF-007「不得静默升格」** | [PF-007 性质五](../PF-007-meta-capabilities/design.md#611-ask通向人) | **分界是「明不明确」。**PF-007 禁的是把一句顺口的「以后都这样吧」**由系统解释成**长期授权；这里是**一个标着后果的选项，人看着它按下去**。禁的是系统替人解释，**不是禁止人给长期授权**——长期授权一直都可以给，只是必须由人明确地给 |
| **卡片「形状一样」指的是样子，不是选项集** | 三种卡片的选项本来就不同 | 要一致的是**卡片这个东西的样子**（带说明、带选项、可自由作答），这样人不必去理解它来自哪条路。但**人看到什么选项，取决于这张卡片在问什么**——那本来就该不一样，也不需要向人解释 |
| **一张卡片只能答一次，两处入口同一件事** | 「结果自动回传」+ 池子与会话都看得见 | 分成两件事，同一张卡片就有两套状态。**「在会话里答了，池子里那张还在」一旦发生，人就再也不信任这个池子了** |
| **判断函数的产品职责在本 topic 定最小必要** | 它是 PF-008 的组成部分，但也属于权限体系 | 本 topic 只定**何时跑、吃什么、吐什么、必须满足什么性质**，不碰实现。**它若将来长成独立 topic，本 topic 引用不改写** |
| **拓展件出卡借的是 run 那一列** | 等人是 loop 协程的原语（2026-09-23）+ 两个维度的判据（「有那次工具执行」才能挂在工具那一列） | 拓展件站在 loop 的一个位置上，**那一刻没有哪一次工具执行是它发起的**——与系统发起那条[只能挂在 run 上](#二pm-推导)是同一个理由 |
| **「系统不替人作答」包括拓展件替人作答** | [§6.1](design.md#61-永远等着系统不替人作答) + 2026-09-23 不设放宽 | §6.1 禁的是**没有人做的事却给了答案**。拓展件是系统里的一段判断，它在人看到之前填答案、点允许，**世界里并没有人做了什么**——与超时到点同一种越权。**不设放宽是同一条规矩在放行那一侧的样子**：答案只来自人，放行只来自权限与人给的授权。hooks 调研缺口 3（租户 hook 抢在人看到前代答）由此答为：**不允许，搬来的那类输出只算「无意见」** |
| **拓展件出的卡，记录里要标出是哪一件** | 裁决「记录标出哪一件拓展件」+ 原有「记录里必须分得出来源」 | 同是拓展件发起，**不同的那一件是租户不同的规矩**；只标「拓展件发起」，审计分得出来源、分不出是哪条规矩在拦，租户也没法判断哪一件该留 |
| **拓展件写的「允许」选项跨不过放行那一关** | 不设放宽 + [PF-012 放行之后参数不许再变](../PF-012-agent-loop-and-run/design.md#改参数先落一条生效参数) | 那一件据答复能做的是**不再拦**或**改参数再交下去**；把它当成放行，就是换了个入口的放宽 |
| **一批卡片答完之后可能还有下一轮** | 同一位置[依次过](../PF-012-agent-loop-and-run/design.md#三种形态两种装得进一种拆两半) + [一批先全部判完](../PF-012-agent-loop-and-run/design.md#一批动作先全部判完再执行任何一个) | 后一件要看前一件的结论才问得出，前一件等人时后一件无从问起。**这不改变「全答完才解除」**，只是解除之后可能又停一次——所以 §6.6 要求卡片不能让人以为「答了就一定跑起来」 |
| **拓展件出的卡同样永远等着，只有人处理或会话归档才消失** | §6.1 的穷举 + 三种来源形状一样 | 那条穷举本来就不看来源；给拓展件的卡另设出口，就是给它开了一个到点替人签字的口子 |
