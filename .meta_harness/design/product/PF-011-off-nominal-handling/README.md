# PF-011：非常态的分层处置

**事情没按正常走的时候，谁接手、接不住了往哪交——本 topic 回答。**

一句话概括本 topic 的结论：

> **非常态不是一类事，是一件事偏离了某一层的主路径这个状态。**
> **处置沿着作用域从里往外走，一层了结不了，带着交代上交给外面一层。**

## 「非常态」不是「报错」

**这是读本 topic 之前必须先摆正的一件事。**

系统里绝大多数「不那么正常」的情况**根本不报错**：

| 这是非常态 | 报错了吗 |
|---|---|
| 用户叫停 | **没有**——[明文「中断不是失败」](../PF-006-tools-and-skills/design.md#55-一次工具执行的收场有六种) |
| 一个能力此刻够不着 | **没有**——[明文「这不是故障」](../PF-006-tools-and-skills/design.md#62-可用性在每次-run-开始前重算) |
| 停下来等人回话 | **没有**——那是[有意设计的路](../PF-008-human-in-the-loop/README.md) |
| 一次执行转到后台 | **没有** |
| 上次能用的这次不能用 | **没有** |
| 工具真的挂了 | **报了** |

**只有最后一行是报错。**按「报错」去理解这个 topic，做出来的会是一套错误码与重试策略，
而 [PF-006 那一轮裁决](../PF-006-tools-and-skills/decisions.md)挡的正是这件事。

取「非常态」这个名字就是为了把这条写进词里：**它说的是「不在标称路径上」，不是「坏了」。**

## 六层，同一套模型

```text
租户                身份持续可用（稳态式）          ┐
 └─ 会话                建立 → 一次次运行 → 一直可用   │
     └─ 运行                触发 → 备身子 → 走 → 收束   │ 包含关系，
         └─ agent 的一步        想 → 动作 → 看结果        │ 所以处置从里往外
             ├─ 一次模型调用        发请求 → 回来 → 完整   │
             └─ 一次工具执行        调用 → 执行 → 交回     ┘
```

**但模型不认层数。**一层只需声明四样——主路径、本层了结得了什么、
了结不了交给谁、到头了怎么收场。

> **rev 2 加了三层，过程中逼出三处修订**——主路径有两种形态、
> **层结构是树不是链**、一层此刻可能根本不存在。
> **模型站住了，但代价不是「多填一行」那么轻。**经过记在 [changelog](changelog.md)。
