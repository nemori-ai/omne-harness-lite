# PF-011 流程与状态

> **这一页说这套模型怎么动。**[design.md](design.md) 说它是什么。
>
> 两条纪律：**每条旅程都要走到收场**——停在半路的旅程等于没定义；
> **状态流转要穷尽**——没画出来的转移，研发会自己发明一个。

---

## 一、主要旅程

### 1.1 一件非常态的完整旅程

```text
某一层偏离了它的主路径
        │
        ▼
  ① 这件事偏离的是哪一层？  ←── 判据：缺的那样东西在谁手上
        │                        （不看是谁撞见的）
        ▼
  ② 那一层了结得了吗？
        │
   ┌────┴────┐
   │         │
  能        不能（或手段已用尽）
   │         │
   ▼         ▼
 回到      ③ 留下一条上交条目
 主路径       │
   │         ▼
  完         ④ 本层就地停住，不再往前
             │
             ▼
        ⑤ 外面一层接手 ──→ 回到 ②
             │
             ▼
     外面没有层了 ──→ ⑥ 落终局
```

**任何一层在 ② 这一步，都可以横向选择「问人」**——问完若能回到主路径，
这一层就了结了它，不必上交。

### 1.2 走一遍：一个工具用不了（agent 的一步了结）

| 步骤 | 发生什么 | 产出 |
|---|---|---|
| 1 | agent 调一个工具，拿到「现在用不了 + 为什么」 | 一条正常的返回消息（[PF-006](../PF-006-tools-and-skills/design.md#替换件)） |
| 2 | **偏离在哪一层**：agent 缺的是「一条能走的路」，而动作空间里还有别的 | **起点 = agent 的一步** |
| 3 | **了结得了吗**：能。它换一条路 | —— |
| 4 | 主路径继续：想 → 动作 → 看结果 | —— |

**处置一步都没走出 agent 那一步，运行与会话完全不知情。**——这是最常见的情况，
也是这套模型最该保证的：**能自己解决的，谁也别惊动。**

> **为什么工具执行那一层不算偏离**：[替换件是正常返回](../PF-006-tools-and-skills/design.md#替换件)，
> 而且它[在 run 开始前就装好了](../PF-006-tools-and-skills/design.md#62-可用性在每次-run-开始前重算)——
> **一个先于这次执行就已经成立的偏离，起点不可能在这次执行上**。
> 见[收编表](design.md#六种收场在这个模型里各是什么)。

### 1.3 走一遍：额度用完（起点直接在租户层）

| 步骤 | 发生什么 |
|---|---|
| 1 | 一次模型调用撞上额度用完 |
| 2 | **偏离在哪一层**：缺的是配额，而[使用成本按租户归属](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-tenant--租户--tenant)——**一次模型调用、agent 的一步、运行、会话，没有一个变得出配额** → **起点 = 租户层** |
| 3 | **底下四层一个都不试**——跳过四次注定无用的处置 |
| 4 | 租户层了结得了吗？能补配额 / 能换配额 → 了结；**都不行 → 落终局**（外面没有层了） |

**这一条是 [§5.5](design.md#55-起点偏离在哪一层不看是谁撞见的) 存在的全部理由。**
按「谁撞见谁先处置」，这里要白白浪费**四层**的处置——
**层越多，这个错误越贵。**

### 1.4 走一遍：agent 绕不动了（一路上交到头）

| 步骤 | 在哪一层 | 发生什么 |
|---|---|---|
| 1 | **agent 的一步** | 它要的能力一个替代都没有，别的路都试过、都不行 → **手段用尽** |
| 2 | **agent 的一步** | 留下一条上交条目：这一层的收场与原因，**寿命宿主取运行那一档或更长** |
| 3 | **agent 的一步** | **就地停住**，不再往前走 |
| 4 | **运行** | 接手。能不能换一个 agent runtime 、换个装配把那个能力补回来？ |
| 5 | **运行** | 补不回来 → 留下自己的上交条目 → 停住 |
| 6 | **会话** | 接手。重算可用性、换个地方重建执行环境，能不能让下一次运行拿到它？ |
| 7 | **会话** | 还是不行 → 留下条目 → 停住 |
| 8 | **租户** | 接手。这个能力是不是被禁用了、配额是不是不够？能不能重新启用？ |
| 9 | **租户** | 还是不行 → **落终局**（外面没有层了） |

**三条上交条目在记录里并排存在**，后一条不覆盖前一条——
agent 交给运行、运行交给会话、会话交给租户；**租户那一层是落终局，不再往外交，所以不是四条**。

排查的人照着它们能看出：**这件事被四层各接过一次，各自做了什么，为什么都不行。**

### 1.5 走一遍：模型彻底不可用（越过一个此刻不存在的层）

| 步骤 | 在哪一层 | 发生什么 |
|---|---|---|
| 1 | **一次模型调用** | 重试、换路由，**所有路都失败** → 手段用尽 |
| 2 | **一次模型调用** | 留下上交条目 → 停住 |
| 3 | —— | **接手方本该是「agent 的那一步」，可它根本没有发生过**——agent 就是模型，模型没给出回复，**那个会思考的主体此刻不在那里** |
| 4 | **运行** | **直接由它接手**（[不算跳级](design.md#61-起点可以是任何一层往上不许跳)）。它能不能换个装配、换一套模型配置？ |
| 5 | **运行** | 不行 → 继续往外 |

**这条旅程靠的是[「一层此刻可能根本不存在」那条](design.md#61-起点可以是任何一层往上不许跳)**——
把「往上不许跳」读成死规矩，事情就卡死在第 3 步了。

## 二、状态流转

**一件非常态，从发生到收场，只有这几个状态：**

```text
   ┌──────────┐
   │  刚偏离   │
   └─────┬────┘
         │ 算出起点在哪一层
         ▼
   ┌──────────┐   了结了    ┌──────────┐
   │ 某层处置中 ├──────────→ │ 回到主路径 │  ← 终态
   └─────┬────┘             └──────────┘
         │ 了结不了 / 手段用尽
         ▼
   ┌──────────┐
   │  已上交   │ ──→ 外面一层接手，回到「某层处置中」
   └─────┬────┘
         │ 外面没有层了
         ▼
   ┌──────────┐
   │  终局     │  ← 终态
   └──────────┘
```

| 从 | 到 | 什么时候 |
|---|---|---|
| 刚偏离 | 某层处置中 | 算出起点之后，**立即**——不存在「先放着」这个状态 |
| 某层处置中 | 回到主路径 | 这一层不需要外面给任何东西就继续走下去了 |
| 某层处置中 | 已上交 | 缺的东西这一层拿不到，**或**手上的手段已用尽 |
| 已上交 | 某层处置中 | 外面那一层接手 |
| 已上交 | 终局 | **外面没有层了** |
| 某层处置中 | 某层处置中（同层） | 横向问了人，人答复了，这一层接着处置 |

**两个终态：回到主路径、终局。没有第三个。**

**没有「已上交 → 回到主路径」这条转移**——上交之后，回到主路径的是**接手的那一层**，
不是交出去的那一层。交出去的那一层已经停住了。

## 三、每一层能做什么

| 层 | 本层了结得了的 | 上交给 | 落终局 |
|---|---|---|---|
| **租户** | 补配额 · 在别处重建租户级沙箱 · 重新启用被禁的资产 | **不能**——[阶梯到这儿为止](design.md#68-阶梯到租户为止) | ✅ **只有它** |
| **会话** | 重算可用性 · 换地方重建执行环境 | → 租户 | ❌ |
| **运行** | 重建一个 agent runtime · 缺可选的照装并标明 · 腾空间 | → 会话 | ❌ |
| **agent 的一步** | 换路 · 换方法 · 先干别的 · 不做了换方向 · 分页取回 | → 运行 | ❌ |
| **一次模型调用** | **尚无 owner**（[§9.2](design.md#91-模型调用那一层还没有-owner)） | → agent 的一步 | ❌ |
| **一次工具执行** | 进等待态等一个应答 · 转后台（声明允许时） | → agent 的一步 | ❌ |

**每一层都能做的三件事**：判断偏离在不在自己这一层 · **横向问人** · 留下自己的条目。
**每一层都不能做的一件事**：改写别层已经写下的条目。

**「落终局」只有最外层能做**，这一条不是权限设计，是定义的推论：
终局的意思就是「一路往外交到头，**没有哪一层**还能让它回到主路径」，
**而只有走到根，才谈得上「外面没有层了」**。

> **模型调用与工具执行是兄弟**，各交各的父节点（agent 的那一步），**互不干涉**。

## 四、这条阶梯自己出问题时

**处置机制本身也会出问题，不能假装它不会。**

| 情况 | 怎么办 | 为什么 |
|---|---|---|
| **上交条目写不下去** | **停住，别放过去**，并让这件事本身可见 | 放过去就是[假成功](../../foundation/observability-and-logging/requirements.md)。这与[卡片生成失败时仍然停住](../PF-008-human-in-the-loop/README.md)同形 |
| **算不出偏离在哪一层** | **从撞见它的那一层起步** | **猜错起点比白试一层更贵**——猜错会直接跳过真正办得了事的那一层；**保守起步逐层往上，最坏也只是多过一道** |
| **接手的那一层此刻不存在** | **交给再外面一层**（[不算跳级](design.md#61-起点可以是任何一层往上不许跳)）；一直到某一层在，或者外面全没了才**落终局** | 一层此刻不存在，**它就不可能有办法**。不跳，事情会永远停在「已上交」。最清楚的例子：**模型调用彻底失败时，「agent 的那一步」根本没有发生过** |
| **同一件事在两层被同时处置** | **不发生。**上交即打断，交出去的那一层已经停住 | 这正是[§6.2](design.md#62-上交即打断)那条规则要挡的 |
| **上交之后外层迟迟不接** | 它停在「已上交」，**这是一个可观察的状态，不是卡死** | 卡在哪一层、停了多久，照着条目就查得出来 |
| **一层反复上交同一件事** | 上层照常接、照常处置；**不做惩罚也不做静默** | 与[反复调用同一个替换件的处置](../PF-006-tools-and-skills/flows.md)同形——**读得懂就会改，读不懂是另一个问题** |
