# PF-004 流程与状态

`design.md` 说这块产品**是什么**，本页说它**怎么动**。
查「这步失败了怎么办」来这里，查「这个概念是什么」去 design.md。

**本页只写装配这个动作、以及它产出的那份清单。**
谁决定现在该装配，是驱动那一侧的事（[design.md §2 非目标](design.md#非目标)）；
本页写的是**这个动作一旦发生，必须做什么、必须留下什么**。

> **本页不写「那个协程怎么起、怎么停」。**
> 空闲回收、等人期间被取消、强制停止之后怎么报告，
> 全归 [agent runtime](../PF-012-agent-loop-and-run/design.md#agent-runtime) 那一侧，
> 见 [PF-012](../PF-012-agent-loop-and-run/flows.md)。

## 一、主要旅程

本页的构成变更指系统已受理的变更；单纯修改工作区文件或同步 Git 不自动触发这些传播，工作区来源须经实际装配或显式资产 reload。reload 校验失败时原内存数据不变。

### 1.1 装配出一份清单

| 步骤 | 发生什么 | 完成的标志 |
|---|---|---|
| 1 | 取得会话类型能力要求、生效定义版本及其显式依赖与能力自动继承声明、作用域资产与配值输入；定义替换先守 official、类型与上级锁定边界；继承未声明按 false | 必需项与候选来源可辨；继承声明来自生效定义，不逐字段叠加被替换定义 |
| 2 | 按 [Skill、Tool、MCP 绑定规则](design.md#skilltoolmcp-的绑定规则)选入：先确保两类必须依赖，再按开放范围继承并扣除继承排除项；继续确定执行环境等其余构成 | 必需绑定均成立，动作空间确定 |
| 3 | 确定系统提示词组合规则与采用定义 | 能力描述与 schema 在每次请求取当前合法数据 |
| 4 | 产出**装配清单** | 可以照它起一个 agent runtime 了 |

**第 3 步不组装出提示词文本**——那要等到请求模型时才知道跟谁说话（[§5.4](design.md#54-为什么系统提示词必须落在第三列)）。

**缺必需的东西就明确失败**，不产生残缺的清单，见下方异常表。

**第 4 步到此为止。**照这份清单起协程是[另一个动作](../PF-012-agent-loop-and-run/flows.md)，
**可以起很多次，也可以一次都不起**。

### 1.2 复用已有的清单

新 Run 先按会话固定的定义身份核对最新有效内容。只有定义等输入未变化且清单仍有效，才走本节复用；同 Run 普通恢复保持当前已生效清单；显式 reload 已切换过的，恢复该次切换后的清单，不回到 Run 最初版本。

| 步骤 | 发生什么 |
|---|---|
| 1 | 会话已有一份仍然有效的装配清单 |
| 2 | **直接用，不重新求值** |

构成没变，就没有重新装配的理由。**这是常态，不是优化。**

**复用的是清单，不是协程。**下一次[执行尝试](../PF-012-agent-loop-and-run/design.md#执行尝试)
照样起一个新的 agent runtime，只是不必再跑一遍作用域求值。

### 1.3 运行中装上一个新能力

| 步骤 | 发生什么 | 完成的标志 |
|---|---|---|
| 1 | 运行中发现需要一个当前没装的**可选**能力 | — |
| 2 | 按当前作用域求值，确认它可用 | — |
| 3 | 装上它；**清单追加一条**，正在跑的协程**不必重起** | 动作空间变大 |

**这不是 [§6.3](design.md#63-三类变化三种传播) 的反例。**
新增或更新能力条目与替换 Loop 自身直接必要入口是两回事；能力声明为必需不改变这一边界。

### 1.4 权限被收紧

| 步骤 | 发生什么 | 这份构成 |
|---|---|---|
| 1 | 组织把某个工具的执行权限改严了 | **不变** |
| 2 | 变化作为上下文，在下一次运行里以一条提醒到达 | 不变 |
| 3 | agent 再调用那个工具 | **调用被拒，它知道为什么** |

**动作空间自始至终没变。**agent 照样发得出那个调用，只是这次不被允许——
它因此能解释，也能去申请。

### 1.5 这次执行的落点换了

| 步骤 | 发生什么 | 这份构成 |
|---|---|---|
| 1 | 动作落到的地方换了（比如那扇门的执行环境权限改严，下一次执行算出来是沙箱而不是宿主机） | **不变** |
| 2 | 同样以上下文的形式在下一轮到达 | 不变 |
| 3 | agent 执行同一条命令 | **照样执行**，只是落在了别处 |

工具定义说的是「执行一条命令」，从不说「在哪执行」。

### 1.6 组织移除了一个正在用的工具

| 情形 | 会话能力记录 | Agent runtime 与在途执行 |
|---|---|---|
| 可选工具失去合法提供者 | 已知身份保留，变更生效后使用替换件 | 不因此重建 Loop；已发执行按自己的资源条件继续 |
| 会话类型或 AgentDefinition 要求的工具失去服务 | 必需位置保留，真实实现不可用用替换件说明 | 两种要求都不等于 Loop 直接依赖工具服务 |
| Loop 自身的必需入口被撤除 | 保留事实，不能以失效入口推进 | 按实际依赖与所有权恢复／重建，不自动取消独立调用 |

历史清单不改写；当前会话采用记录独立更新。完整边界见 [§6.10–6.12](design.md#610-重装配触发与生效矩阵)。

### 1.7 换模型

| 步骤 | 发生什么 | 这份构成 |
|---|---|---|
| 1 | 下一次请求用另一个模型 | **不变** |
| 2 | 按新模型的方式，从**同一批成分**组装出这一次的系统提示词 | 不变 |
| 3 | 这一条产出记下**实际生成它的模型** | — |

**动作空间也不变。**换模型不触及构成，因此**既不重算清单，也不重起协程**。

## 二、分支与异常

| 情形 | 怎么做 | 为什么 |
|---|---|---|
| 装配时，从未取得必需能力的合法定义 | **明确失败**，指出缺哪个 | 残缺的 agent 跑起来，它自己不知道缺什么，用户也不知道 |
| 装配时，Loop 自身必要入口拿不到 | **明确失败**，说明缺什么 | 同上 |
| 装配时，作用域求值本身失败 | **明确失败**；**不产生半份清单** | 半份清单会被下一次当成「有效的」复用 |
| 已取得合法定义的能力实现不可用（含两种必需来源） | 保留身份与替换件，说明原因；不由该工具的服务失效使 Loop 装配失败 | 必需位置不等于 Loop 对工具服务的直接依赖 |
| Skill、Tool、MCP 重载候选缺少会话类型或定义显式要求能力的合法定义 | 校验失败并指出缺项，旧内存数据尚未替换 | reload 不取消必须依赖 |
| 新增资产在自动继承范围外，或命中继承排除项，且不是必须依赖 | 不自动纳入本次构成 | 来源提供了资产，不等于定义接纳它 |
| 注入进来的上下文**暂时取不到** | 明确反馈；不拿旧值冒充当前事实 | 过期的环境认知比没有认知更危险 |

> **「取消到一半」「资源释放失败」「强制停止之后怎么报告」这几类，
> 本页不再收**——它们说的是一个协程怎么停，归
> [PF-012 §6.14](../PF-012-agent-loop-and-run/design.md#614-停止有两级)。

## 三、状态流转

### 3.1 一份装配清单

```text
（没有）──装配（求值）──→ 有效 ──构成赖以成立的东西没了──→ 失效
                            │  ↑                              │
                            │  └──复用（不重新求值）          │
                            └──增量装载：追加一条，仍然有效   │
                                                              ↓
                                          下一次需要时重新求值出新的一份
```

| 状态 | 含义 | 能照它起协程吗 | 占资源吗 |
|---|---|---|---|
| 求值中 | 正在按作用域算 | 不能 | **不占**——这是一次计算，不是一个驻留物 |
| 有效 | 构成确定 | **能**，而且能起很多次 | **不占** |
| 失效 | 赖以成立的构成变了 | 不能 | **不占** |

> **这张表最要紧的是最后一列全是「不占」。**
> 写成「开始占 / 占 / 仍占直到释放完」就错了——
> **那是协程的状态，不是一份数据的状态**。

**清单不会「被回收」，它只会失效。**它是数据，留着不花钱；
[要不要留、留多久，是记录那一侧的事](../PF-000-occurrences-and-record-entries/README.md)。

### 3.2 清单与协程的关系

```text
一份清单 ──┬──→ 第 1 次尝试的 agent runtime（起，灭）
           ├──→ 第 2 次尝试的 agent runtime（起，灭）
           └──→ ……
```

**一对多，而且清单活得更久。**「当时那个 agent 是什么样」这个问题，
**恰恰在那些协程全都消失之后才最常被问到**。

### 3.3 三类变化对构成的影响

不是状态机，是一张必须记住的对照表：

| 变化的是 | 这份清单 | 正在跑的协程 | 下一次装配 |
|---|---|---|---|
| **Loop 自身捕获组成** | 采用变化时形成新清单 | 按实际依赖交接，不取消独立调用 | 生效 |
| **会话能力数据／实现／可用性** | 历史不改写，当前采用值更新 | 不因此重建；已知身份保留 | 按已有生效边界采用 |
| **注入**（执行权限这一类、上下文）**与随之现算的落点** | **不变** | **不变**，下一轮以提醒到达 | 生效 |
| **请求时才定的**（模型） | 不存在改写这回事 | 不变 | —— |

## 四、谁能影响这份构成

| 操作 \ 角色 | 协作中的用户 | 组织超级管理员 | 系统 |
|---|---|---|---|
| 看见装配清单 | 自己的会话：可 | 可（作为构成与成本的观察对象） | — |
| 看见它**在跑什么内容** | 自己的会话：可 | **不可**——那是成员的私有部分 | — |
| 改变它的构成（移除/替换资产） | 在自己有权维护的租户或工作区来源内可；工作区文件变化经显式 reload 或实际装配进入 | 在有权治理的组织来源内可，经 PF-002 持有规则处理 | — |
| 改变注入给它的权限 | 自己租户级的：可 | 组织级的：可 | — |
| 让它失效 | 已授权变更触及 Loop 自身捕获组成时，按生命周期处理 | 同左，不因组织角色取得其他工作区的维护资格 | 依赖没了时可 |

> **「谁能取消那个协程」不在这张表里**，归
> [PF-012](../PF-012-agent-loop-and-run/design.md#614-停止有两级)。

**「看见它在跑什么内容」这一行对超级管理员是「不可」**，与
[PF-001 的作用域约束](../PF-001-identity-scope-and-agent-constraints/flows.md#四角色与操作)一致：
**组织所治理资源的构成与成本可按已有资格观察，内容仍是成员私有部分；实例可跨租户共用不扩大组织对其他租户会话或私有资源的访问权。**

实现时遇到本表覆盖不到的组合，**回到产品设计确认，不要自行补一条**。

## 当前 Run 显式 reload

核对来源范围与候选 → 校验并按变化层次分流：仅能力数据／实现／可用性变化，更新会话采用值而不新建尝试；采用新 AgentDefinition 或替换 Loop 自身捕获组成，才按 [PF-012 安全交接](../PF-012-agent-loop-and-run/design.md#618-agent-runtime-的装配与重装配交接)采用新清单、开启新尝试。无变化不伪造切换；校验失败不部分替换旧数据。旧依赖自身已失效时不能假报继续可用。撤除和不可用的具体衔接不在本页统一规定。
