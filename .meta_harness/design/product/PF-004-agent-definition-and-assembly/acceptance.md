# PF-004 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

> **rev 5 把「一个协程怎么起、怎么停」整块移交给了
> [PF-012](../PF-012-agent-loop-and-run/acceptance.md)**——
> 空闲回收、退役未结算、强制停止之后怎么报告、等人不烧钱，
> 都不在本页验收，见
> [UL-D-3](../../ubiquitous_language/decisions.md#ul-d-3--runtime-与活体--2026-09-20)。
> **本页只验收：一份定义怎么被求值成一份构成，以及那份构成对变化怎么反应。**

## 一、可观察场景

### 装配

| 场景 | 应当看到什么 |
|---|---|
| 一份定义在某个作用域下装配 | 产生一份**装配清单**，上面能查到装了哪些工具、哪些技能、需要哪几类执行环境 |
| 定义引用的某个能力标识无人提供 | **明确失败并指出缺哪个**；**不产生半份清单**，更不产生一份少记了零件却被当成有效的 |
| 同一个会话已有一份有效的清单，又要跑一轮 | **直接复用，不重新求值**；清单一个字不变 |
| 同一份定义在两个不同作用域装配 | 两份清单**不同**（各自作用域求值出的实现、设置、权限不同），而**定义本身一个字没变** |
| 装配完成，但这次运行随即被取消 | **清单照样存在且有效**——它不因为没被用过就作废 |

### 三个时刻

| 场景 | 应当看到什么 |
|---|---|
| 装配完成那一刻 | 系统提示词的**成分**已确定；**成品尚未存在** |
| 照同一份清单，用模型 A 请求一次，再用模型 B 请求一次 | 两次的系统提示词**可以不同**（同一批成分、不同组装方式），而**清单没有重算** |
| 改一项权限 | 清单**不重算**；下一次运行里多出一条提醒 |
| 换掉执行环境 | 清单**不重算**；agent 执行同一条命令，只是落在别处 |
| 换模型 | 清单**不重算**，动作空间**不变** |
| 运行中热装上一个新工具 | 清单**追加**一条，**动作空间变大**，正在跑的那个协程**不必重起** |
| 那次装载触及了必需绑定、热装不了 | 退一步**重新装配**，新清单的动作空间同样包含它；不静默跳过 |
| 组织移除了清单里一个必需组件 | 该清单**失效**；下一次装配不再包含它 |
| 组织移除了一个可选工具 | 正在跑的那个协程**照常用完它手上的活**；下一次装配不再有它 |

### 动作空间与权限

| 场景 | 应当看到什么 |
|---|---|
| 把某工具的执行权限从「自动」改成「问一下」 | agent **照样能发起**那个调用，只是这次要问；**动作空间没变** |
| 把某工具**禁用** | agent 发起调用时被拒，**它知道这件事存在、能说明被关掉了** |
| 把某工具**移除** | 下一次装配后它不在动作空间里，agent **说不出为什么**——它不知道有这回事 |
| 收紧整个会话的安全权限 | agent **照常工作**，动作空间不变；受影响的是调用的结果 |

### 上下文

| 场景 | 应当看到什么 |
|---|---|
| 外部环境在一轮运行进行中发生变化 | **当前这一轮不被打断**；变化在**下一轮**以一条提醒出现 |
| agent 收到那条提醒 | 它**读到**变化并自行调整后续动作；不是系统在背后改写了它的能力 |
| 上下文暂时取不到 | 明确反馈；**不拿旧值冒充当前事实** |

### 清单的存续与成本

| 场景 | 应当看到什么 |
|---|---|
| 一段连续多轮的协作，中间换过好几个 agent runtime | **清单不必跟着换**：定义版本没变、作用域求值结果没变，就一直是那一份 |
| 跨多次尝试复用同一份清单 | 各次尝试**依据的定义版本相同**（I-3） |
| 那些协程全都消失之后，追查「当时装的什么」 | **装配清单还在**，答得出来 |
| 看一个租户的成本 | 照这份清单跑出来的部分**归到启动它的那个租户**（I-8） |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 改一项权限导致 agent **不知道某件事存在** | 权限跑进了构成里。收紧权限从此既无法解释、也无法申诉 |
| 换模型导致清单被重算 | 系统提示词的成品被提前定死了 |
| 换执行环境导致清单被重算 | 执行环境跑进了构成里 |
| 构成性变化**悄悄改写**了一份已经算出来的清单 | 一个进行中的任务莫名其妙地换了能力，且事后查不出当时是什么 |
| 上下文变化**打断**了正在进行的一轮 | 不紧急的事被当成紧急的处理 |
| 装配缺了必需的东西，仍产生一份被当作有效的清单 | 缺零件的 agent 跑起来，问题会在很远的地方以莫名其妙的形式出现 |
| 各次尝试复用清单时，依据的定义版本变了 | 同一段协作里 agent 中途变脸（I-3） |
| 那些协程消失之后，「当时装的是什么」查不到 | 排障与审计失去唯一的答案来源 |
| **给清单安排「回收」「释放资源」这类动作** | 把一份数据当成了活物——**那正是 rev 5 拆掉的那个矛盾** |
| 超级管理员能看到成员会话里**跑的内容** | 管理权越界。资源是组织的，内容是成员的 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 定义是数据 | 同一份定义在两个作用域装配，**定义本身逐字节不变**，两份清单不同 | 装配过程回头改了定义 |
| 清单是数据 | 一份清单被三次尝试先后复用，**它自己没有任何状态变化**（除追加） | 它带上了「在用 / 空闲」之类的运行态 |
| 成分与成品分开 | 照同一份清单换模型再请求一次，提示词**可以不同**而清单**没重算** | 换模型触发重算，或两次提示词被迫相同 |
| 动作空间只由构成决定 | 两头都要测：①把权限从宽改到严再改回来，**动作空间三次都一样**；②热装上一个工具，**动作空间立刻变大** | 动作空间跟着权限变；或构成变了而动作空间没跟上 |
| 注入不触及构成 | 权限、执行环境、上下文各改一次，**清单逐字节不变** | 任一项改动导致重算 |
| 构成性变化不改写已算出来的 | 移除一个正在用的可选工具，**正在跑的那个照常用完它手上的活** | 它中途失去能力 |
| 变化以内容到达 | agent 能在回答里**说出**它知道了什么变化 | 它的能力被改了但它说不出所以然 |
| 清单可追溯 | 那些协程全消失后仍能查到当时的构成 | 查不到 |
| 复用是常态 | 连续多轮协作里，作用域求值**只跑了该跑的那几次** | 每次尝试都重跑一遍求值 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| **agent runtime 怎么起、怎么被取消、取消怎么传播** | **rev 5 移交给 [PF-012](../PF-012-agent-loop-and-run/acceptance.md)**——含空闲回收、退役未结算、强制停止之后怎么报告、等人不烧钱、一个会话至多一个活跃协程 |
| 会话怎么建、怎么命名归档、历史怎么存 | **本 topic 不拥有会话**，只用到「一次装配为一个会话而做」 |
| 输入怎么受理、排队、调序、什么时候取一批 | 不拥有 |
| 谁决定现在该跑一轮、怎么推进、怎么收束、怎么中断 | 不拥有驱动 |
| 单次工具调用的观察、中断与后台接续 | 它有自己的生命周期，[绑在会话上](../PF-006-tools-and-skills/design.md) |
| 子 agent 的委派、监督与关系 | 另一件事 |
| 待决项的统一呈现与作答 | 那是跨会话的事 |
| 模型怎么供给、怎么路由、模型选择存在哪 | 归 SYS-LLM 与会话那一侧。本 topic 只定**模型在哪一刻被确定** |
| 崩溃后恢复到哪个合法位置 | 归 SYS-RUNTIME-CONTINUITY。本 topic 定的是**正常的装配与失效** |
| 一个运行中装上的能力明天还在不在 | **归那个能力自己作为资产的存续**，不归清单 |
| 具体有哪些上下文项、哪些执行环境 | 本 topic 定它们**以什么方式**被注入，不枚举内容 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
