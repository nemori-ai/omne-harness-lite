# PF-010 流程与状态

`design.md` 说这块产品**是什么**，本页说它**怎么动**。
同一个概念只在 `design.md` 定义一次，这里只引用。

## 一、主要旅程

### 1.1 用户切进一个跑了很久的会话

| 步骤 | 发生什么 |
|---|---|
| 1 | 用户打开会话 |
| 2 | **往回要一段最近的历史**——**不是全量** |
| 3 | 界面上有东西了；**同时开始一直收着新的** |
| 4 | 用户往上翻，翻到头 | 
| 5 | **从当前已加载的最早那条再往前要一段**，**接在前面** |
| 6 | 第 4、5 步可以反复，直到会话开头 |

**第 2 步与第 5 步不是同一个动作**：一个锚在**最近**，一个锚在**当前已加载的最早点位**。

**第 3 步那条通道一直开着**——**新的来了自己就到，不必反复去问**。

> **「加载到哪了」始终是看的人那一边的事。**
> 无论翻了多少次，**会话日志一个字都没被写过**。

### 1.2 给模型组装一份上下文

```text
     ┌─ build 系统提示词 ────────────┐
     │   （实例存续期内恒定，压不动）  │
     │                              ├──→ 一份完整的上下文
     │                              │
     └─ build 会话上下文 ────────────┘
         （每轮重算；只有这块压得动）
```

**四条要求各自在这一步的哪个位置起作用：**

| 要求 | 在哪一步 |
|---|---|
| **四：先落盘再组装** | **在最前面**——落盘没完成，这一步不许开始 |
| **二：成分必须明确标了给模型读** | **取每一个块的时候**——没明确标的，不取 |
| **三：边界由压缩记录定** | **取会话那一块的时候**——看**哪些块还模型可读** |
| **一：前缀一致** | **贯穿整个过程**，而且[压缩那边也要守](design.md#56-压缩这件事的调子三个联合目标) |

**量与压那一圈归 [PF-012 §5.5](../PF-012-agent-loop-and-run/design.md#55-想这一步先组装量完才知道要不要压)**，
本 topic 只说**组装这一步内部怎么做**。

### 1.3 一次压缩发生时，日志里到底动了什么

```text
压缩之前的日志：

  … [消息 A：块1 块2]  [消息 B：块1]  [消息 C：块1 块2 块3] …
       给模型 ✓ ✓        给模型 ✓        给模型 ✓ ✓ ✓

压缩之后的日志：

  … [消息 A：块1 块2]  [消息 B：块1]  [消息 C：块1 块2 块3] … + [CompactionMessage]
       给模型 ✗ ✓        给模型 ✗        给模型 ✓ ✗ ✗           ← 新加的一条摘要
       ↑                 ↑                    ↑
       └─────────── 只翻了标注，一个字没改，一条没删 ──────────┘
```

| 动作 | 日志里的结果 |
|---|---|
| **标记块不再模型可读** | **那一位翻了**；**内容一个字没变** |
| **生成摘要** | **往后追加一条 `CompactionMessage`** |

**三件没有发生的事：**

- **没有任何一条消息被擦除**——哪怕它整条都不再模型可读；
- **没有任何内容被改写**；
- **「给人看」那一位一个都没动**——**用户那一侧完全不受影响**。

**注意那些 ✗ 是散布的**，不是从某一点起整段变 ✗——
**这正是[组装边界不是一个起点](design.md#59-块级标记解释了组装边界为什么不是一条线)的原因**。

### 1.4 下一次组装，怎么看这份被压过的日志

| 步骤 | 发生什么 |
|---|---|
| 1 | **不是**「从最后一条 `CompactionMessage` 往后取」 |
| 2 | **按块看**：哪些块还标着「给模型读」 |
| 3 | 那些块**可能落在最后一条摘要之前**，**照取不误** |
| 4 | 摘要本身也是一条模型可读的消息，一并取 |

## 二、异常分支

| 分支 | 怎么处理 | 为什么 |
|---|---|---|
| **落盘还没完成，但这一轮要组装了** | **等**。落盘完成之前不开始 | 否则模型看过的东西日志里没有，**恢复后重算不出同一份** |
| **某个块的标注缺失或不明** | **不取**（默认拒绝） | **误给收不回来**；少给了还能再给一次 |
| **压完还是超预算** | **不是压缩能解决的**——按 [PF-012 §5.5](../PF-012-agent-loop-and-run/design.md#压完还超这一层腾不出空间了)走 | 系统提示词那块**压不动**；光固定部分就超了，那是装配的问题 |
| **上一次模型请求之后来了一大批新消息，正好撑爆** | **仍然不许压它们** | **模型一次都还没看过**；压了它永远看不到原文 |
| **用户往上翻，翻到会话开头** | **没有更早的了**，停住 | — |
| **一条已经不模型可读的消息，有人想删掉省空间** | **不许** | **「不给模型看」不等于「可以删」** |

## 三、谁决定什么

| 决定 | 谁定 | 依据 |
|---|---|---|
| 一次往回要多少条 | **实现** | 产品只定「先一段，不是全量」 |
| 边界具体怎么算 | **实现** | 产品只定「按哪些块还模型可读」 |
| 压缩在三个目标之间怎么取平衡 | **实现** | 产品只定「三个同时成立」 |
| 摘要里写什么、写多长 | **实现** | 产品只定「压缩可以生成摘要」 |
| **哪些块可以被翻成不可读** | **压缩** | 那是它两个动作之一 |
| **「给人看」那一位** | **谁都不在这一层动它** | 压缩只碰「给模型看」 |
| **一条消息能不能被删** | **不能，没有人有这个权限** | [日志 append only](../PF-012-agent-loop-and-run/design.md#会话日志) |
| 什么时候触发压缩 | **[PF-012](../PF-012-agent-loop-and-run/design.md#55-想这一步先组装量完才知道要不要压)** | 组装→量→超了才压 |
| 加载到哪了 | **看的人那一边** | **不写回日志** |
