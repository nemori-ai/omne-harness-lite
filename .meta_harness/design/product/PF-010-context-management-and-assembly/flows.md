# PF-010 流程与状态

`design.md` 说这块产品**是什么**，本页说它**怎么动**。
同一个概念只在 `design.md` 定义一次，这里只引用。

## 一、主要旅程

### 1.1 用户切进一个跑了很久的会话

| 步骤 | 发生什么 |
|---|---|
| 1 | 用户打开会话 |
| 2 | **往回要一段最近的历史**——**不是全量** |
| 3 | 界面上有东西了；**同时开始一直收着新的** |
| 4 | 用户往上翻，翻到头 | 
| 5 | **从当前已加载的最早那条再往前要一段**，**接在前面** |
| 6 | 第 4、5 步可以反复，直到会话开头 |

**第 2 步与第 5 步不是同一个动作**：一个锚在**最近**，一个锚在**当前已加载的最早点位**。

**第 3 步那条通道一直开着**——**新的来了自己就到，不必反复去问**。

> **「加载到哪了」始终是看的人那一边的事。**
> 无论翻了多少次，**会话日志一个字都没被写过**。

### 1.2 给模型组装一份上下文

```text
     ┌─ build 系统提示词 ────────────┐
     │  （按组合规则和当前数据生成，压不动）│
     │                              ├──→ 一份完整的上下文
     │                              │
     └─ build 会话上下文 ────────────┘
         （每轮重算；只有这块压得动）
```

**五条要求各自在这一步的哪个位置起作用：**

| 要求 | 在哪一步 |
|---|---|
| **四：先落盘再组装** | **在最前面**——落盘没完成，这一步不许开始 |
| **五：输入里有当下生效的那份模型档案** | **一进来就要有**——取多长、给原件还是派生表示还是 transcript，全看它 |
| **二：成分必须明确标了给模型读** | **取每一个块的时候**——没明确标的，不取 |
| **三：边界由压缩记录定** | **取会话那一块的时候**——看**哪些块还模型可读** |
| **一：前缀一致** | **贯穿整个过程**，而且[压缩那边也要守](design.md#56-压缩是一个闭包它的调子是三个联合目标) |

**组装不管「够不够长」这件事。**装不装得下[由压缩那个闭包负责](#13-一次压缩交进去一份日志拿回一份装得下的)。

### 1.3 一次压缩：交进去一份日志，拿回一份装得下的

```text
   Agent Loop                 │        压缩闭包（内部不对外可见）
  ─────────────────────────── │ ───────────────────────────────────
   把日志 + 模型档案交进去  ──┼──→  ① 量一量：按这份档案，装得下吗
                              │        └─ 装得下 ─────────────┐
        （在这里挂着等）       │      ② 挑一段历史来压         │
                              │      ③ 生成摘要 · 点名一批块   │
                              │      ④ 再量一遍 ──────────────┤
                              │           └─ 还是装不下 ──┐   │
   拿回一条 CompactionMessage ←┼─────────────────────────┼───┘
            或                 │                          │
   拿回一件 off-normal  ←──────┼──────────────────────────┘
```

| 这一步 | 谁的事 |
|---|---|
| **要不要压、压哪一段、摘要写多长** | **闭包内部**——[产品只定硬约束、三个目标和动作边界](design.md#56-压缩是一个闭包它的调子是三个联合目标) |
| **交回来的装不装得进目标模型的窗口** | **闭包必须保证**——这是它的后置条件 |
| **装不进怎么办** | **闭包自己失败**，交一件[非常态](../PF-011-off-nominal-handling/design.md)出来 |
| **Agent Loop 看见什么** | 只有两种回执：**一条 `CompactionMessage`**，或**一件非常态** |

> **它内部要调模型生成摘要，所以这一步是真的要等。**
> [Agent Loop 在这里挂起](../PF-012-agent-loop-and-run/design.md#agent-runtime)，压缩交回来才继续。

### 1.4 一次压缩落盘之后，日志里到底多了什么

```text
压缩之前：

  … [消息 A：块1 块2]  [消息 B：块1]  [消息 C：块1 块2 块3] …
       给模型 ✓ ✓        给模型 ✓        给模型 ✓ ✓ ✓

压缩之后：

  … [消息 A：块1 块2]  [消息 B：块1]  [消息 C：块1 块2 块3] … + [CompactionMessage]
       给模型 ✓ ✓        给模型 ✓        给模型 ✓ ✓ ✓         ├─ 摘要：…………
       ↑                 ↑                    ↑                └─ 点名：A.块1 · B.块1 · C.块2 · C.块3
       └────────── 前面这些一个字没改，一位没翻，一条没删 ──────────┘
```

| 动作 | 日志里的结果 |
|---|---|
| **生成摘要** | **往后追加一条 `CompactionMessage`**，摘要是它的内容 |
| **点名一批块** | **名单写在那条 `CompactionMessage` 上**；**被点名的块本身一个字没动** |

**四件没有发生的事：**

- **没有任何一条消息被擦除**——哪怕它整条都不再模型可读；
- **没有任何内容被改写**；
- **没有任何一个块上的标注被回头修改**；
- **「给人看」那一位一个都没动**——**用户那一侧完全不受影响**。

> **正因为前面一个字没动，这份日志才能重放**：
> **任何一个历史时刻给模型看的是哪些块，都还原得出来**——
> 拿那一刻之前的全部 `CompactionMessage` 算一遍就是了。

**注意那份名单点的是散布在各处的块**，不是从某一点起整段点掉——
**这正是[组装边界不是一个起点](design.md#59-块级标记解释了组装边界为什么不是一条线)的原因**。

### 1.5 下一次组装，怎么看这份被压过的日志

| 步骤 | 发生什么 |
|---|---|
| 1 | **不是**「从最后一条 `CompactionMessage` 往后取」 |
| 2 | **先算一份视图**：把排在前面的全部 `CompactionMessage` 的名单并起来 |
| 3 | **按块看**：块上那一位标着给模型读，**且不在那份名单里** |
| 4 | 合格的块**可能落在最后一条摘要之前**，**照取不误** |
| 5 | 摘要本身也是一条模型可读的消息，一并取 |

> **第 2 步没法省。**「哪些块还模型可读」**没有一个地方存着**，每次都得算。

## 二、异常分支

| 分支 | 怎么处理 | 为什么 |
|---|---|---|
| **落盘还没完成，但这一轮要组装了** | **等**。落盘完成之前不开始 | 否则模型看过的东西日志里没有，**恢复后重算不出同一份** |
| **某个块的标注缺失或不明** | **不取**（默认拒绝） | **误给收不回来**；少给了还能再给一次 |
| **压缩压完了还是装不下** | **闭包自己失败**，交一件[非常态](../PF-011-off-nominal-handling/design.md)出来 | **这不是方程的一条分支**——Agent Loop 只认「装得下 / 装不下」 |
| **系统提示词那一块自己就超了窗口** | 同上，**压缩也救不了** | 那一块**压不动**；光固定部分就超了，**那是装配的问题** |
| **上一次模型请求之后来了一大批新消息，正好撑爆** | **仍然不许压它们** | **模型一次都还没看过**；压了它永远看不到原文 |
| **要压的那一段里有[悬着的东西](../PF-012-agent-loop-and-run/design.md#611-悬着的东西不许被压掉)** | **绕开它们**，不许点名 | 点掉了，**agent 就不知道自己还有东西在外面跑** |
| **用户往上翻，翻到会话开头** | **没有更早的了**，停住 | — |
| **一条已经不模型可读的消息，有人想删掉省空间** | **不许** | **「不给模型看」不等于「可以删」** |

## 三、谁决定什么

| 决定 | 谁定 | 依据 |
|---|---|---|
| 一次往回要多少条 | **实现** | 产品只定「先一段，不是全量」 |
| 边界具体怎么算 | **实现** | 产品只定「按哪些块还模型可读」 |
| **这一次要不要压、压哪一段** | **压缩闭包内部** | 产品只定硬约束与三个目标；**方程不参与** |
| 压缩在三个目标之间怎么取平衡 | **实现** | 产品只定「三个同时成立」 |
| 摘要里写什么、写多长 | **实现** | 产品只定「压缩可以生成摘要」 |
| **哪些块被点名** | **做这一次压缩的人** | 那是它两个动作之一 |
| **交回来的装不装得下** | **压缩闭包必须保证** | 装不下就是它自己失败 |
| **「给人看」那一位** | **谁都不在这一层动它** | 压缩只管「给模型看」那一侧 |
| **块上已经落盘的标注** | **谁都不许回头改** | 改了日志就不能重放 |
| **一条消息能不能被删** | **不能，没有人有这个权限** | [日志 append only](../PF-012-agent-loop-and-run/design.md#会话日志) |
| 加载到哪了 | **看的人那一边** | **不写回日志** |
