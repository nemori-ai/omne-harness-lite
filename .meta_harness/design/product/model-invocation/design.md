# 模型调用的产品设计

状态：产品设计已正式接受。本文定义的全部能力承诺在 `0.0.0 → 0.1.0` 完整交付。产品接受与阶段承诺不表示实现、行为验证或交付接受已完成。

## 产品需求描述

### 用户要解决的问题

用户需要知道能调用哪些模型、这一次实际用了什么，以及一次失败后系统有没有继续尝试。会话运行很久时，用户可以换模型，维护者可以更新档案，而在途工作仍有明确结局。模型结果被处理后，系统释放不再需要的大副本，保留真实调用和成本事实。

模型调用既可以属于会话，也可以由独立程序发起。独立程序不必为了取得结果而创建一个隐式会话，它承担自己的结果处理责任。

### 档案、选择与实际调用

模型档案记载路由名、来源、允许供应商及次序、回退声明、输入输出模态、限额与统一请求参数。档案是长期配置数据，不是资产，也不是模型本身。档案可能过期，一次成功不能证明全部上游限制已查明。

一条档案由所在范围和路由名共同识别。范围是官方出厂默认、某组织或某租户。同一范围内，路由名唯一且不可修改；来源在产生时确定。改变路由名意味着另建档案。同名档案可以分布在不同层。

官方档案随发布提供。组织超级管理员及租户分别在有资格的自身层维护自建档案。修订参数、供应商、模态和限额不改变身份。撤回保留原行，不能再被新选中；有撤回资格者可以恢复同一档案。已撤回的同名身份不能用另一条新行取代。Agent 不自行建改、撤回或恢复档案，也不配置凭据；它可以代表用户执行明确的合法切换指令，不能以调用失败为由自己换名。

Session 拥有模型列表的用户选择和切换事实。本域提供求值所需的合法档案、能力与限制，不替 Session 保存选择。选中模型是会话记下的路由名。未作会话选择时，沿既有设置规则取得初值。有效模型是某次请求实际采用的档案，沿设置求值和允许的模型前扩展求得，可能与选中模型不同。上一条回复实际采用的模型是历史事实，不随后续选择改写。本次实际采用的参数及修改依据也须可追溯，档案随后修订不改原记录。上游不支持的参数须明确说明实际采用和不支持情况，不能静默丢弃或假称已应用；具体参数词表和接口结果由已接受的 Model 公开契约维护。

同名求值先排除已撤回和被当前范围配置排除的档案，再取租户、组织、官方中最具体的那一条。模态不兼容或缺凭据不使胜出档案落回另一层。组织锁定的是路由名，不能据此锁死这个名字解析到的物理档案行；合法同名覆盖仍按层序进行。

一个名字的最具体档案撤回后，若外层仍有同名在册且未被配置排除的档案，名字按规则落到它，选择没有变。链上同名档案都撤回时，说明已下架；被配置排除、无法查询或未找到分别说明，不混成已下架。有效模型无法取得或不合法时，不擅自换别的名字。

### 用户看到的列表与切换

列表同时呈现官方与自建，标明来源及所在层。可选对象是当前合法路由名；组织或租户的锁定及会话模态约束决定合法集合。当前选中值即使不合法也保留，标明原因。被合法目标或当前选择的胜出档案覆盖的同名条目只作来源说明，不能单独选择。其余非法目标不作为候选展示。

缺凭据的合法目标仍可选，但列表须说明目前用不了及缺什么。模型窗口较小不是拒绝合法切换的理由，模型相对较弱也不是。用户作出合法切换后，保存切换事实；确认保存后切换已发生，下一请求失败不能倒过来撤销它。提交暂时无法判明时，报告未知并核实原操作，不能报告成功后丢失选择。

切换不打断正在执行的调用。下一请求按新有效档案走通常的组装、计量和必要压缩。仍装不下时，会话路径明确结束原 Run 的失败并保留历史；独立调用向调用方返回输入约束失败。系统不默认分叉、删除历史或暗换模型。用户可以立即看到选择变化和受理反馈，上一回复的模型仍按原调用说明。

<a id="tool-consistency"></a>

部分模型供应商会校验请求中声明的工具名称和参数形状，是否与历史中的工具调用一致。同一会话的工具名称或参数形状改变后，含旧调用的历史可能被拒绝，会话无法继续。因此同一会话的各次请求使用一致的工具名称与参数形状，切换模型或修订档案都不改变它们。会话的常驻工具规则保证这项一致性，见[工具执行](../tool-execution/design.md#resident-tools)。某项工具对新模型不可用时，它以原名称与参数形状呈现不可用说明。

### 凭据的范围

档案自身不存凭据。模型调用以发起租户的合法绑定取得适用凭据，实际用量与费用仍归真实调用及其租户。租户可以自带、更换和解绑自己的凭据；解绑后按缺失处理，不翻改既有发出事实。

本域的凭据供给范围不包含组织持有凭据并供成员共用的产品操作。组织层自建档案由调用租户提供适用凭据。官方档案使用部署默认凭据的既有例外，仅在相应部署确实提供且原规则允许时适用；产品不能修改这个部署默认值。租户绑定存在但无法读取时，不能静默退回默认或其他租户凭据。

凭据的存在、归属及配置时间可以按资格展示，秘密值不能回显，也不能进入普通消息、错误或遥测。这里不规定全系统只有一种通道或每租户永远只有一个秘密值；新接入方式的数量、键与选择细则须有自己的有效契约。

### 多模态内容及转换

Tool 结果采用独立分流。附件区只成为地址文本，不进入媒体读取或模态约束；消息内容中的模型可见 ref 保留原引用，在 Model 真正请求时才加载二进制及完成必要转换。消息准入、历史投影和请求组装不得为了产生 transcript 提前读取这些字节。其他消息来源继续使用下述接纳前转换规则。

本域的原生支持目标为文字、图片和语音，不要求每个模型都具备全部能力。文件是载体，模态由媒体类型判断。不能因为称为文件就一概视为文本；媒体类型不属于模型模态的附件引用只表示引用，不宣称模型已理解附件正文。视频的既有文件表示不构成本域原生视频理解能力的交付承诺。

新会话的初始模态约束为文本，合法档案仍须实际支持文本并满足范围等条件，不能把所有在册模型都当可选。模型合法性使用会话模态投影。它累积原历史中标为模型可读、没有 transcript 的模态。只给人看的块不加入；有 transcript 的块不增加这项模态约束。投影可由历史重建，不是第二权威源。压缩的派生排除不改原块标记或 transcript，也不重写这项历史约束。

历史约束增长时，在其他候选条件不变的前提下，合法目标可能减少。档案能力和配置可以变化，新增或恢复兼容档案可以扩大合法集合，不能声称长会话的可选模型永远只减。当前选择也可能因新内容失去兼容性，下一请求如实失败，不自动改选。

除 Tool ref 路径外，模态转换在消息接纳前为模型可读的非文本块或文件形成派生表示及纯文本 transcript。原块保留，转换结果挂在原块上，不插成另一批消息块。一个转换件按模态或文件媒体类型登记；同键只有一件生效，文件同时命中时优先具体媒体类型键。转换件由系统装配选择，不作为组织和租户可替换资产，也不调用模型；transcript 来自本地识别。

转换结果须包含至少一个不同模态的非文件派生块及 transcript。转换件未登记时，允许原件按消息准入保留，不伪造 transcript。已登记却不可用、执行报错或结果不合契约属于转换失败。仅供人读的块不为模型转换。派生表示和 transcript 在消息接纳前形成，接纳后固定；转换件新增、更换或升级不回填、重算既有消息，也不改变已经成立的模态投影依据。

转换失败时，输入请求不被接纳，发送者获知原因；模型回复不成为会话消息，但原调用照常收场，保留被否决事实，Loop 退避后另起新调用。连续否决不设次数上限，不因此使 Run 失败。工具结果不能成为消息时，仅在原消费契约明确归属仍有效、尚未终结的 Run 时使该 Run 失败。后台、Run 外或原 Run 已终结的结果按原消费契约处置，不改原终态、不默认挂到后继 Run；没有有效 Run 不造一个，已取消业务不恢复推进或取得新入队资格。未定旁路后果由原消费拥有者明确。工具原结果及真实效果仍保留，不重做工具以取得可转换结果。

[请求上下文的 RQ-04](../../../../packages/context/request-context/SPEC.md#rq-04-模态与可追溯表示)负责实际表示选择与输入组装，按有效模型取适用原件或派生表示，都不可用时使用已有 transcript，并检查有效模型能接纳该文本表示；多份适用表示的选择归明确组装策略。转换可能损失信息，交付面须使用户知道本次模型实际读取了哪份表示，不能假装读过原图。Tool 内容 ref 和附件地址分流按本节规则处理，任意嵌套语法不自动获准。

### 档案提供范围与上游能力

上游输入限制与本档案提供的范围分别可读。上游事实可以明确未知，未知不等于无限、零或不适用。只有实际证据可以确认上游不设某项限制。

官方与自建档案都须有正的有限输入窗口。提供图片输入时，还须有正的有限单图字节上限。适用上限缺失、无效或超过已知上游限制时，档案不能用于发送请求；本次只有文本也不能绕过图片档案缺项。输出上限为正值，输入输出能力分别声明。

实际请求同时满足档案提供上限与每项适用的已知上游要求。单图大小、图数和整次总量分别检查，不能互代。恰好达到限额时不因这项限额拒绝。超限原件可以按已有规则选择合规表示；没有合规表示就明确失败，原件和历史保留。大小超限不能报成模态不支持。

预算计入系统提示词、历史、提醒、工具声明和全部实际模态内容。字节与图片数精确校验。token 优先采用适用准确计量或可靠上界，否则允许基于完整实际请求、适用计量方法和明确余量估算。缺计量依据或必要余量配置时不发出；不能只数一句话或编造字符倍率。

估算与余量通过不承诺上游计数完全一致或一定接受。估算超限只说明估算检查不通过，不称已测得真实超限。实际用量与费用不能由估算代填，一次上游成功也不能把未知限制改成无上限。模型前扩展改动输入后重新核对最终表示和限制，不重复执行同一次扩展位置。

### 每次真实发出和失败

一次逻辑调用可以包含多次真实发出。每次只交一个允许供应商，换家或退避后重试都单独留事实。供应商、时刻、失败、原状态码及实际费用不能被最终成功覆盖。策略不能暗换路由名，也不能让上游在单次请求里不透明地换家。

首 token 指第一次实际交出的内容。可逐片增长的块以第一片为准，图片和文件等整交块以完整块为准。响应头、心跳及空开块不算。开始交内容后的故障不重发同一逻辑回复，即使别的供应商可能成功，也不能推翻这一边界。

请求和凭据明确无效时，说明具体成因，不反复发送同样无效输入。缺本地凭据可以未发出；上游拒绝凭据通常已经发出，保留真实事实与可能费用。首内容前的可重试上游失败及空回复按适用策略处理，策略不再继续才结束调用。输出限额截断按正常结果加提醒表达，不混成故障或自动重发。

系统提供可替换的默认重试策略。允许回退时按档案供应商次序，每家至多一次；不允许回退时原供应商退避后至多再试一次。替换策略仍受档案及首内容边界约束。策略看得到原状态码、失败成因、档案声明和已尝试情况，并记录再试或不再试的决定。系统策略不可用时不再重试，不能编造一次正常决定。

会话路径中，失败由发生边界分类后交原处理位置。首内容前没有有效回复时由运行层处置；首内容后部分内容与中断提醒供 Agent 继续判断，不能另造第二份相同上交事实。扩展、压缩及独立调用分别回自己的消费者，不强行跳回主 Loop。上游原因未知时如实说明并留依据；本地存储故障不能冒充供应商故障。

### 控制、恢复与结果保管

单独中断本次模型调用不隐式结束 Run 或工具。中断是控制结果，不记为上游故障。取消请求、实际停止和资源清理各自可见。会话归档在业务上取消原未完成调用并解除等待，不等独立模型执行物理全停；迟到结果和费用按原调用保存，不能使工作复活，撤销归档也不能自动恢复原调用。

Agent 退出、换代或所有句柄释放不取消模型原执行。合法接手者按原身份查询，仍运行就等待，已收场就承接结果，已确认就转消费保存侧。查询暂时不可用不证明原执行丢失。只有确认 Model runtime 自身失去连续性时，首内容前才可按原消费位置恢复重发，首内容后记录失联、不重发。恢复重发可能真实多次收费，未知费用保持未知，不写零。

完整输出、业务采用、结果确认和成本结算分别判断。流式读到、页面展示和开始处理不算可靠消费。模型保管原结果，直到当前合法消费者已处理完成，或可靠保存后续所需内容、原身份和处理位置，才确认 ACK。消费方不必先完成 Run 或把扩展、压缩和独立结果写成聊天消息。

调用仍输出、重试或等待重试决定时不能 ACK。旧消费者、只读观察者、拿到引用者及其他租户不能代当前承接者确认。确认生效后，新消费者不能重新领取模型侧完整结果。此前开始的真实读取不能被清理截断；闲置句柄不永久阻止释放。确认、清理和费用结算分别可查。

清理失败继续由模型侧负责，不能回滚确认，也不要求原消费者在线或再次确认。清理只释放本次无用输入、结果副本及其专用引用，不删除消费方持有内容、真实历史或其他调用仍需内容。正确记账所需资料保留，但未知费用不能成为永久扣住无关全文的理由。重复确认、查询或重启不重发、不重复逻辑消费、不重复记同一费用，也不复活已释放副本；合法旧引用能查出曾存在及已释放，不能伪装未找到。

已确认持久保存的调用、承接及账目事实须经得起进程崩溃、操作系统崩溃和断电。确认丢失按原身份核实，不直接再发。物理介质损毁与普通耐久分别设计。已展示在途内容须满足可追溯承诺，逐片耐久的兑现机制仍待对齐，不能借收场 ACK 宣称已证明，也不能默认允许丢失。

### 成本、隐私与性能

租户可查看自己的成本账目，组织管理员可查看全组织的成本账目及明细。这个资格不授予他人私有请求、回复或秘密的读取权。迟到费用在 Run 已结束时仍归原工作，有 Run 或 attempt 时关联，没有时不造一个。

实际发送前核对主体、数据范围、目的和实际接收方。允许读取不等于允许发给模型或遥测；供应商改变时重新满足外传条件。原件、派生表示、引用、图片和语音同样受保护。错误对外呈现前去除秘密与无权披露的内部信息。

单个会话某种模态是否存在的点查询须为常数代价，由增量维护的投影回答并可从历史重建。长期会话不能每次重扫全历史。完整列表及输入物化按实际读取量评价，不假称全部常数成本。模型自身 TTFT 与入口到首输出的端到端耗时分别观察；排队、转换、组装、发送、重试及清理各有可定位记录。遥测不复制秘密或完整正文来换取方便。

### 边界及尚需细化

本域不决定通道、提供者或存储机制，不建立能力评分和自动选另一个模型的功能，不新增模型执行许可、灾后管理员或统一清理时限。具体计量、参数词表、错误映射、跨进程消费与清理协议随成员规格细化。工具 ref 的共享契约迁移与流中已展示内容的恢复仍需技术兑现；当前均不作为新增产品选择。

下列 J-MD 编号只用于本文定位，不是新业务对象或公开接口。旅程引用上文的规则拥有位置，并连接能力、架构与成员规格。跨域完整推进仍由原协调者负责。

#### J-MD01 维护档案并准备自身凭据

组织超级管理员或租户希望在有资格的自身范围供给模型。维护者先识别范围与不可变路由名，建立或修订档案的供应商次序、参数、模态和限额，再按需要撤回或恢复原档案。官方档案由发布提供，Agent 不能自行维护。身份、同名占用与权限不成立时拒绝操作；资料读取失败不解释为档案不存在，保存结果未知则核实原操作。撤回后禁止新选择，已采用的调用记录和费用保持原事实，恢复不复活旧调用。

调用租户另行绑定、更换或解绑自己的凭据，档案不存秘密。组织层档案仍使用调用租户适用凭据。部署默认只在既有例外真实存在时适用；绑定存在但不可读时不能退默认。解绑影响后续准入，不能抹除已经发出的事实。用户能按资格看到存在、归属和配置时间，不能看秘密值。配置主体退出不使在途调用自动中断；取消配置操作的提交未知须核实，不能声称已回滚。

此旅程使用 CAP-MD01、CAP-MD04、CAP-MD12。协作见[档案与选择流程](../../../../packages/model/model/docs/flows.md#flow-md01)，规则见[档案、选择与实际调用](#档案选择与实际调用)、[凭据的范围](#凭据的范围)及[档案专题](../../../../packages/model/model-contract/SPEC.md#身份修订及撤回)。

<a id="j-md02"></a>
#### J-MD02 在会话中选择下一请求的模型

用户希望换到合法路由名，Session 负责显示列表与保存切换。本域提供范围链中的档案、同名胜出依据、模态能力与凭据可用性，输入组装方提供从历史重建的模态投影。Session 保留当前非法选择及原因，覆盖条目只说明来源。缺凭据仍可合法选择，小窗口或相对较弱不能成为拒绝理由；锁定和实际模态不兼容则不能选择。

用户确认合法目标后，Session 保存选择事实，受理反馈与保存确认分别可辨。提交未知时核实原操作。当前模型调用继续使用原采用值，下一请求才使用新有效档案。下一请求仍装不下时会话原 Run 失败、历史保留，独立调用返回输入失败；不撤销已确认切换、不删历史、不换名。单独中断模型或消费者退出不撤销选择，撤销归档也不重启旧调用。

此旅程使用 CAP-MD02、CAP-MD03、CAP-MD05、CAP-MD06。协作见[档案与选择流程](../../../../packages/model/model/docs/flows.md#flow-md01)，Session 的选择责任继续见[会话产品](../sessions-and-work/design.md)，本域规则见[用户看到的列表与切换](#用户看到的列表与切换)。

<a id="j-md03"></a>
#### J-MD03 让混合内容成为可解释的合法输入

发送者希望原图、语音或文件保留，同时模型能取得适用表示。Tool 结果先按内容 ref 与附件地址分流，二进制延迟至实际请求；以下接纳前转换适用于其他消息来源。消息接纳协调者先按本域转换契约处理模型可读的非文本块，包括同时供人和模型读取的块；仅供人读取且没有模型读取标注的块不转换，未登记转换件与已登记不可用分别判断。成功派生及 transcript 挂在原块上，接纳后固定，不随转换升级回填。转换会损失信息，交付面说明实际读取哪份内容。

转换失败时，输入不接纳并通知发送者；模型回复不成为消息，但原调用保留结局与否决事实，Loop 另起新调用。连续否决不设次数上限。工具结果只能由仍有效未终结 Run 的原消费契约使该 Run 失败；后台或 Run 外结果回原消费方，原效果保留、不重做、不默认入后继 Run。取消业务不因转换结果而恢复推进。Tool 引用路径的实施和验证沿 MODEL-E01，不支持任意嵌套块。

随后请求上下文依据有效档案选原件、派生表示或已有 transcript，核对完整预算并按自己的规则压缩。必要计量、余量、有限上限或合规表示不足时不发出；恰到上限通过该项，估算通过不保证上游接受。模型前扩展修改后复核最终输入但不重跑同次扩展。组装失败保留原件与历史，恢复先核对原采用，不从新配置拼出另一份原请求。转换和压缩的中断结果由各自原消费者处理，不假称已接纳或已发出。

此旅程使用 CAP-MD05、CAP-MD06、CAP-MD12、CAP-MD13。协作见[转换与组装流程](../../../../packages/model/model/docs/flows.md#flow-md02)，本域转换规则唯一源为[多模态内容及转换](#多模态内容及转换)，Context 只消费该契约，完整输入算法仍归请求上下文。

<a id="j-md04"></a>
#### J-MD04 取得一次真实回复并解释重试

会话、扩展、压缩或独立程序希望取得一次逻辑回复。发起者固定完整输入、有效档案和原消费位置后，模型校验资格、凭据、接收方及限制，每次只向一个允许供应商真实发出。独立调用不造 Session、Run 或 attempt。缺本地凭据可未发出，上游拒凭据则保留真实发出及可能费用。

首内容前可重试故障或空回复由适用策略决定是否退避、换下一供应商或收场，每次费用和失败分别保留。响应头、心跳和空开块不算首内容；增长块首片、整交块完整交付才越界。等待策略时调用未收场，不提前上交最终失败或 ACK。首内容后故障不重发；部分内容和提醒回原消费位置，输出限额截断按正常结果加提醒。正常回复中的完整工具建议仍须动作准入，未收齐参数不能执行。用户中断模型后，原响应中尚未发出的工具建议不再执行，即使参数已经完整；中断内容按控制结果交回。模型回复被消息准入否决不能反转原调用终局，新请求使用新调用身份。

观察者首次或重连先取在途快照，再读增量。开块、填充、封块、截断提醒、计费和流收场分别表达到达及事实，不成为 Run 状态。展示不等可靠消费，已展示内容的故障可追溯兑现仍依 MODEL-M03。消费者退出不自动停止物理执行，恢复按下一旅程核对原调用。

此旅程使用 CAP-MD06、CAP-MD07、CAP-MD08、CAP-MD11、CAP-MD13。协作见[发出、重试与流收场流程](../../../../packages/model/model/docs/flows.md#flow-md03)，行为及验证见[执行规格](../../../../packages/model/model-contract/SPEC.md#流式和首内容)。

<a id="j-md05"></a>
#### J-MD05 中断本次调用并在换代后接回原工作

用户希望只中断本次模型调用，或合法接手者希望在 Agent 换代后继续消费。模型按原调用接收控制，记录请求、受理、传播及真实结果；单调用中断不取消 Tool 或整个 Run。Session 归档取消原业务依赖并解除等待，供应商物理停止仍可能未知。迟到结果与费用保留，不能推进取消业务，撤销归档不复活旧调用。

接手者核对原租户、当前资格、原调用和消费位置，仍运行则等待，已收场未 ACK 则承接原结果，已 ACK 则从消费保存侧继续。拒绝旧消费者或跨租户越权，读取暂不可用保持未知。只有可信确认 Model runtime 自身失去连续性，才在首内容前按原用途恢复重发；首内容后记失联并禁止重发。恢复重发可能多笔真实费用，未知费用不填零。控制结果未知须核实原身份，不把超时当作停止或未发出。

此旅程使用 CAP-MD09、CAP-MD10、CAP-MD11、CAP-MD12。协作见[控制和恢复流程](../../../../packages/model/model/docs/flows.md#flow-md04)，准确失联判据及控制传播仍依 MODEL-M02 设计，已展示在途保留仍依 MODEL-M03。

<a id="j-md06"></a>
#### J-MD06 承接结果、确认并释放模型副本

当前合法消费者希望可靠取得结果并释放无用大副本。整调用真实收场后，消费者可以完成原用途处理，保存其契约必要的处理结果与完成事实，再 ACK；也可以先可靠保存后续所需内容或可恢复引用、原身份、范围和原位置，再 ACK。两条路径都不要求 Run 已结束或结果成为聊天消息。读取、展示、获得引用和开始处理不足以 ACK，重试及等待策略期间不能确认。

保管失败或处理未完成时，模型继续承担原结果责任。旧消费者、观察者和其他租户不能代确认。ACK 回执未知按原调用查询或重复确认，不能直接重新消费或发请求。确认生效后禁止新完整结果领取；接手者转消费保存侧，已有真实读取及未知写入仍受保护。清理失败由模型续做，不回滚确认，不要求原消费者在线。闲置句柄不永久阻止释放，不能误删消费内容、历史、其他调用数据或必要账目。

已取消业务的结果仍由当前合法消费者交接，不因归档自动 ACK，不要求已撤权者回来确认，也不凭迟到结果恢复业务。已确认事实须耐进程、操作系统崩溃及断电；介质损毁另行设计。清理和费用结算各自可见，未知费用已能独立结算时不扣住无关全文。

此旅程使用 CAP-MD09、CAP-MD10、CAP-MD11、CAP-MD12。协作见[双路径 ACK 与清理流程](../../../../packages/model/model/docs/flows.md#flow-md05)，行为及验证见[结果承接专题](../../../../packages/model/model-contract/SPEC.md#ack-的前提与效果)。

<a id="j-md07"></a>
#### J-MD07 查询真实成本和诊断记录而不泄露内容

租户希望查询自身用量，组织管理员希望查询组织账目及明细，工程人员希望解释等待、首输出和清理开销。模型按原调用及每次真实发出保留实际费用或未知值，迟到账目仍补原工作，有 Run 或 attempt 才关联。重复回执和观察不重复记同一笔费用；真实重试可以有多笔。费用未知不写零，不用输入估算代填，也不靠查询重发。

查询、读取、ACK 与导出各自核对当前资格，账目可见不授予他人私有请求、回复或秘密读取权。更换供应商前重新核对真实接收方的外传条件。存储和秘密读取失败保持未知，外部错误去除秘密和无权披露的内部信息。取消或归档不抹成本，恢复按原身份补账和清理，不复活业务。

模态点查询由增量投影回答且可从原历史重建，单会话单模态点查询须常数代价；完整列表与内容物化仍按实际量评价。模型 TTFT 与入口端到端首输出分别观察，记录排队、转换、组装、重试及清理位置。遥测不复制秘密和全文，诊断取数中断或缺项不得伪装零成本或完整记录。

此旅程使用 CAP-MD04、CAP-MD11、CAP-MD12、CAP-MD13。协作见[费用与查询流程](../../../../packages/model/model/docs/flows.md#flow-md06)，行为及验证见[费用专题](../../../../packages/model/model-contract/SPEC.md#真实费用和账目边界)。

<a id="identity-neighbor-diagnostics"></a>
### 供应商尝试诊断的披露与保留

供应商尝试诊断的披露与保留由 Model、诊断接入与存储拥有者维护。供应商尝试诊断向哪些具资格主体披露什么内容，以及诊断资料的保留范围与条件，已有最小查询、授权与保留机制设计。具体权限映射、期限和容量仍须由相应拥有者确定，运行能力尚未实现，用户和维护者不能据此认定自己可查询完整诊断记录。

已有[成本、隐私与性能规则](#成本隐私与性能)继续有效，账目资格不授予私有请求、回复或秘密读取权，真实尝试及费用不被最终成功覆盖。具体资格、披露与保留契约由[成员技术义务](../../../../packages/model/model/docs/architecture.md#identity-neighbor-diagnostics)维护；若方案需要改变既定产品边界，由 Model 产品拥有者提出具体裁决。本项不补披露政策、保留时限或机制，不新增能力，也不改变阶段与版本支持范围。

<a id="model-e01"></a>
### MODEL-E01 工具引用式结果的技术兑现

工具消息内容中的多模态 ref 供模型直接感知，附件区只产生文本地址，由 agent 决定另行读取。模型侧不在消息组装阶段读取二进制，实际请求阶段由 Model 加载所选内容 ref。该产品规则已明确，任意嵌套语法没有因此获准。

共享内容、消息、Tool、Model 与 Context 须共同实施并验证，不能把设计存在当支持声明。技术义务见[MODEL-E01](../../../../packages/model/model/docs/architecture.md#model-e01)。

<a id="model-m01"></a>
### MODEL-M01 输入和适配器的精确契约

本项为具体适配与验证义务。参数、限额及预算的通用公开契约已接受；pi-ai 适配设计仍为候选，具体型号数值、提供者实现和符合性证据尚待落实。

实现及符合性仍缺精确输入；当前行为承诺完整保留。责任由Model成员与提供者承担；具体义务、既定边界和剩余缺项见[技术原文](../../../../packages/model/model/docs/architecture.md#model-m01)。

<a id="model-m02"></a>
### MODEL-M02 可靠承接、独立策略与清理接续协议

本项为实施与验证义务。原身份恢复、可靠承接、独立策略及清理接续协议已接受，消费者替换、ACK 与真实读写并发、费用迟到及重启仍须由实际提供者验证。

未运行跨进程或存储验证；不降低耐久、结果保管和首内容限制。责任由Model、存储与原消费协调者承担；具体义务、既定边界和剩余缺项见[技术原文](../../../../packages/model/model/docs/architecture.md#model-m02)。

<a id="model-m03"></a>
### MODEL-M03 已展示在途内容的恢复兑现

本项为实施与验证义务。保存后展示及首内容不确定窗口的设计已接受，实际提供者仍须证明已展示内容的故障可追溯性。

尚不能声称已验证该故障范围无丢失；不重问整套流式设计。责任由流式、Model、Tool、存储与交付面承担；具体义务、既定边界和剩余缺项见[技术原文](../../../../packages/model/model/docs/architecture.md#model-m03)。

### MODEL-M04 新接入方式的凭据具体形状

<a id="model-n01"></a>
### MODEL-N01 当前明确不采用的扩张

本项是明确非目标或既有另域责任，不是待裁决产品选择。自动选另一个模型、组织成员共用凭据、转换升资产及额外模型执行许可不在本域承诺范围。

这些边界已明确，不作为待裁决事项。

<a id="model-e02"></a>
### MODEL-E02 到达语法的跨产品来源承接

本项为来源承接待办。消息分次到达、两种填充模式、完整块和真实收场的产品来源尚未在 Model、Session、Tool、Context 与交付面之间完整对账。Model 产品维护者在本页登记来源核对，不能据此取得完整消息历史或全部共同流式协议的所有权。

各产品拥有者须确认当前正文分别承接哪些用户可见行为，并定位共同表示的技术拥有者及仍缺的来源。已接受的[到达语法与在途观察](../../../../docs/architecture/runtime/streaming-and-consumption.md#到达语法与在途观察)继续约束开块、填充、封块、真实收场及分次与完整结果一致性。本项限制完整来源闭合的声明，不重选流式设计，不扩大实时双工范围，也不将已展示内容的局部耐久问题计为整套协议未设计。

[封存来源](../../product.0.0.1.legacy/PF-009-context-message-types/design.md#到达的过程有它自己的语法)只用于核对引用范围与原始依据，不作为并列现行产品规则，也不表示完整旧 PF 已接受或已承接。
