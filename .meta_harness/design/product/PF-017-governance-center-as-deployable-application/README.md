# PF-017：治理中心作为一个可部署应用

**[治理中心](../PF-016-cli-tui-delivery-surface/design.md#治理中心)已经被立成一个概念，却还没有被立成一个应用。**
本 topic 回答它作为一个要被装到某台机器上、开着、有人管的东西是什么形状：
**谁把它立起来、立起来要准备什么、立起来那一刻里面有什么；客户端凭什么被它认出来、不信时人看到什么；
它停了、重启了、升级了、搬家了人会看到什么；那把密钥在产品上是什么；运维它的人是谁、能做什么、绝不能做什么。**

**边界只有一句话：它不拥有任何领域语义。**
账号、组织、成员资格、邀约、登录状态归 [PF-001](../PF-001-identity-scope-and-agent-constraints/README.md)；
据点一侧与两侧分界归 [PF-016](../PF-016-cli-tui-delivery-surface/README.md)；会话归 [PF-015](../PF-015-session-lifecycle-and-ownership/README.md)。
本 topic 立的[五个概念](design.md#四概念定义)全在**部署这一层**——[运维者](design.md#运维者)、[部署密钥](design.md#部署密钥)、[中心标识](design.md#中心标识)、[部署参数](design.md#部署参数)、[中心体检](design.md#中心体检)——
没有一个碰得到治理事实。

> **本 topic 不在治理中心身上用「[交付面](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-delivery-surface--交付面--delivery-surface)」这个词。**
> 治理中心[不知道任何会话](../PF-016-cli-tui-delivery-surface/design.md#治理中心)，不是那个意义上的交付面；
> 正文一律写「治理中心作为一个应用」。

## 本 rev 覆盖到哪

| 这一块 | 本 rev |
|---|---|
| **中心服务谁、接入前提、第一个人怎么来** | ✅ [生来是空的，第一位超管走正常路](design.md#61-中心生来是空的第一位超级管理员走的是正常路)——没有内置账号、没有「首个注册者自动成管理员」 |
| **客户端怎么被认出来、中心凭什么信、不信时人看到什么** | ✅ [只认登录状态](design.md#62-中心只认登录状态不认客户端) · [只信自己签发且此刻有效的，「上游验过了」不算数](design.md#63-只信自己签发的此刻仍有效的登录状态别人说验过了不算数) · [答复的先后：版本先于一切、答不出优先于无效](design.md#64-无效与答不出是两个不同的答复) · [四种不认的情形拒绝同形](design.md#65-拒绝的时候什么都不多说) |
| **部署前提** | ✅ [本版假定中心只对这个组织的成员够得着](design.md#部署前提)；它撑着哪三条规则，前提不成立时要重看什么 |
| **那把密钥** | ✅ [部署密钥](design.md#部署密钥)：运维者生成一次、自己保管、中心永不显示；[什么都不加密，丢了重生成、换了什么都不丢；备份外泄换的是模型凭据](design.md#611-部署密钥运维者生成一次自己保管中心永不显示它) |
| **部署参数** | ✅ [五项，各归定义它的 topic](design.md#部署参数)（PF-001 三项、PF-003 两项）；[每项必填、重启生效、按新值算、判过到期的不回头、邀约时效在发出那一刻定下](design.md#615-部署参数由运维者给值起动时读缺一不可) |
| **启动、停止、重启、升级人看到什么** | ✅ [不半开](design.md#66-要么整个起来要么不起来) · [重启不退出登录](design.md#67-重启不让任何人退出登录) · [停机已确认的都在](design.md#68-停机已确认的都在没确认的等于没发生) · [升级整体成或整体不成](design.md#69-升级同一个中心要么整体成要么整体不成) · [时间不倒退](design.md#610-时间不能倒着走)（崩掉之后很快重启等钟走过那一小段；钟先跳快再校正回来会停摆，本版无运维出口）。**机器断电与操作系统崩溃是这几条共同的例外**：最后一段已答复成功的事可能不在（[§6.7](design.md#67-重启不让任何人退出登录)、[§6.8](design.md#68-停机已确认的都在没确认的等于没发生)、[§6.10](design.md#610-时间不能倒着走)、[§6.12](design.md#612-同一个中心换了地址还是它另一个中心必须被认出来)）；中心自己崩掉不在例外里 |
| **运维者是谁、能做什么、绝不能做什么** | ✅ [运维者](design.md#运维者)不是账号、不是租户角色；[没有任何一扇门通向账号能做的事](design.md#613-运维者没有任何一扇门通向账号能做的事)、[产品不把任何秘密的值交给他](design.md#614-产品不把任何秘密的值交给运维者)；[与超管两条线不交叉](design.md#55-运维者与超级管理员两条线不交叉)，由此接受的后果（单超管出事无人能治理）写在同一节 |
| **地址与身份：搬家还是另一个中心** | ✅ [中心标识](design.md#中心标识)——[PF-016 §9 那一问在 §6.12 回答](design.md#612-同一个中心换了地址还是它另一个中心必须被认出来)；[中心不知道自己的地址](design.md#612-同一个中心换了地址还是它另一个中心必须被认出来) |
| **本版不做** | ✅ [非目标](design.md#非目标)：密钥轮换、多实例、跨进程协调、个人自托管、合规删除、平台管理员、注册开关、备份作为产品动作、跨版本兼容承诺——每条写了为什么 |
| **命令怎么拼、数据放哪、密钥长什么样、防冒充怎么做到、哪些版本算对得上** | ❌ **不在这里。**归技术设计，见 [design §8 交出去的](design.md#八边界与依赖)；**防冒充必须有、不交出能直接用的凭证**是那里写着的两条硬要求 |

**没覆盖的部分不要从本文推断。**未决项在 [§9](design.md#九未决项) 显式列着：六条归别的 topic，一条（钟先跳快再校正回来时要不要给运维出口）归本 topic 的后续版本；没有待裁决。
