# PF-017 验收标准

[design.md](design.md) 说这块产品是什么，本页说**做成什么样算做对了**。
这里的每一条都应当能交给不懂实现的人去判断。

**据点那一侧的验收在 [PF-016](../PF-016-cli-tui-delivery-surface/acceptance.md)，治理事实的验收在 [PF-001](../PF-001-identity-scope-and-agent-constraints/acceptance.md)**；
本页只验**中心作为一个应用**的那些承诺。

## 一、可观察场景

| 场景 | 应有表现 |
|---|---|
| **[运维者](design.md#运维者)第一次启动中心，密钥没给** | **起不来**，并明说差的是[部署密钥](design.md#部署密钥)；什么都没留下，补上再来即可 |
| 运维者第一次启动，某一项[部署参数](design.md#部署参数)没给 | 起不来，并**指出是哪一项**；不是笼统的「配置错误」 |
| 运维者第一次启动成功 | [体检](design.md#中心体检)答得出「在」、一个[中心标识](design.md#中心标识)、版本；**里面零账号、零组织**——没有任何内置账号可登录 |
| 中心刚立起来，第一个人来 | 他**注册、登录、建团队组织**，建起来他就是超管——[与 PF-001 定的一模一样](../PF-001-identity-scope-and-agent-constraints/flows.md#一主要旅程)，**没有多出任何「首次」步骤**；运维者不参与 |
| 第二个人来，也建了一个组织 | **照常**：他是他那个组织的超管。中心不限制组织数量，先来者没有任何特殊待遇 |
| 客户端带着一个中心签发且仍有效的登录状态来 | 中心按 PF-001 办事；**不问来者是哪台机器、什么程序** |
| 客户端带着一个**已撤销**的登录状态来 | 「这次登录已不再有效，请重新登录」。**他的账号、组织、成员资格原样都在**；重新登录得到的是一个新的登录状态 |
| 客户端带着一个**别的中心签发**的登录状态来 | 答复**与上一行逐字相同** |
| 客户端带着一个**从没存在过**的登录状态来 | 答复**与上两行逐字相同** |
| 客户端**什么都没带**就要建组织、发邀请 | 答复**与上三行逐字相同** |
| 客户端来问事时，中心的数据所在恰好够不着 | 「暂时答不出，稍后再试」——**不是「无效」**，人不该去重新登录；也**不是**一个空清单或旧答案 |
| 数据所在够不着时，一个**什么都没带**的客户端来建组织 | 「这次登录已不再有效，请重新登录」——不用查就判得了；他照着去登录，得到「暂时答不出」 |
| 数据所在够不着时，一个还没登录的人读体检 | **照样读得到**在不在、标识、版本三样——「在」只说中心在应答 |
| 客户端带着有效的登录状态来做一件事，但那件事的输入格式就不对 | 按 PF-001 的反馈答「输入不合格」——**不是「无效」，也不是「答不出」**；同样的输入配一个已撤销的登录状态来，得到的是「这次登录已不再有效」（先认人，后看输入） |
| 中心开着的时候，遇到自身的故障 | 答不了的一律「暂时答不出」；运维者在完整体检里看得见 |
| 一个人列出本账号的登录状态 | 看到每一个的签发时间，以及认得出是哪一个的条目；**列表里的任何一项都不能拿到别处当登录状态用** |
| 一个**版本对不上**的客户端，带着一个已撤销的登录状态来 | **只有「版本对不上」**——中心不去判那个登录状态，也不说它有效无效 |
| 同一个版本对不上的客户端读体检的公开部分 | **照常读得到**在不在、标识、版本三样——它正是靠这个看见对不上的是哪一版 |
| 中心重启 | 重启完成后，**此前有效的登录状态依然有效**：同事的机器仍然[准备好](../PF-016-cli-tui-delivery-surface/design.md#62-没准备好就开不了会话)，不需要重新登录；此前已失效的依然失效 |
| 中心升级成功 | [中心标识](design.md#中心标识)不变；账号、组织、成员资格、登录状态**一条不变**；客户端若版本对不上，**明说「版本对不上」** |
| 中心升级失败（新版本接不了这份数据） | 起不来，明说是版本；**数据还是升级前的样子**，换回旧版本照常能起 |
| 中心停机那一刻，有人的注册走到一半 | 那条记录停在[未激活](../PF-001-identity-scope-and-agent-constraints/flows.md#31-账号)；中心起来后他[用同一标识同一凭据接着走](../PF-001-identity-scope-and-agent-constraints/design.md#未激活的账号记录不会永久占着那个名字)即可 |
| 中心停机那一刻，一份邀请刚发出、回执没到 | 起来之后那份邀请**要么在、要么不在**，没有半份；不在就重新发 |
| 运维者把中心搬到另一台机器、换了地址 | 同事换掉地址后，客户端读到的**标识相同**→ 「中心搬家了」，账号、组织、成员资格、登录状态、据点一条不变 |
| 运维者**从零重立**一个中心，用同一个地址 | 客户端读到的**标识不同**→ 明说这是**另一个中心**，不把它当成原来那个接着用 |
| 运维者从备份恢复 | 恢复出来的**还是原来那个中心**（标识相同）；备份之后签发的登录状态**不被认**，那些人重新登录；备份之后的注册、邀请、加入**都不在了**；**备份之后被撤销的登录状态又有效了、被移出的成员又回来了**——持有者要重新撤销一次，超管要重新移一次。**这些后果在 [flows 1.6](flows.md#16-从备份恢复) 里逐行写着，运维者动手前就该知道** |
| 运维者丢了部署密钥 | 中心下次起不来（明说是密钥）；他**生成一套新的**，中心起来，**账号、组织、成员资格、登录状态一样没少**；已有的未激活记录照常可以接着走 |
| 中心开着时，机器上那份部署密钥被删了 | **什么都不变**：体检照旧说在、完整；下次启动才起不来并点名密钥 |
| 一份中心数据的备份外泄了 | 里面模型凭据的值跟着外泄；有权配模型凭据的人**各自改值**就是处置，中心自己不需要换任何东西（那份备份若连着部署密钥，再换一套密钥）。账号凭据从里面读不出来，登录状态也不能从里面拿去直接用 |
| 运维者把机器的钟往回拨了，再启动中心 | **起不来**，明说是时钟 |
| 中心开着时，机器的钟被往回拨了 | **中心不停**；凡要看时间的事都「暂时答不出」，直到钟追上中心用过的最晚时刻；不看时间的事照常；运维者在完整体检里看得见时钟不正常 |
| 运维者想替某个同事接受一份邀请、或把某人移出组织 | **没有这个入口**——不是「做了被拒绝」 |
| 运维者想撤销某个同事的登录状态 | **没有这个入口**。他能做的只有停掉中心，那对所有人一视同仁 |
| 运维者想看部署密钥的值 | **看不到**：生成时给过一次，此后体检里只有「在不在、完整不完整」 |
| 运维者看完整体检 | 看得到：在不在、标识、版本、这次什么时候起来的、此刻能不能答（数据所在够不够得着、时钟正不正常、有没有自身的故障）、密钥在不在完整不完整（启动时载入的结果）、每一项部署参数各自此刻的值。**看不到**：账号有几个、组织有哪些、谁登录着、谁邀请了谁 |
| 一个还没登录的人看体检 | 只有**在不在、标识、版本**三样 |
| 运维者改了一项部署参数 | 改了的值**下次启动才生效**，此后[按新值算，邀约例外](design.md#615-部署参数由运维者给值起动时读缺一不可) |
| 运维者把未激活记录的留存期限**调短**再重启 | 已经积下、还没被判为到期的记录**按新期限判**：该到期的，下一次被判时就是到期 |
| 运维者把未激活记录的留存期限**调长**再重启 | 已经被判为到期、清掉了的**不回来**；从没被判过的按新期限算——还在期限内的，原主人用同一标识同一凭据能接着走完注册 |
| 运维者把邀请的默认时长**调短**再重启 | **已经发出的邀请，到期时刻一个都不变**——不论发起时填没填时长；此后发出、没填时长的按新的默认值 |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 中心**半开**：能登录却答不出成员资格、能建组织却记不下邀请 | 每个答案都可能错得很像对的；[账号没有个人空间就被激活](../PF-001-identity-scope-and-agent-constraints/flows.md#11-注册)这类事会静默发生 |
| 中心认了一个**不是它签发的**登录状态 | 身份可以被任何能构造一个登录状态的人冒充 |
| 中心认了「客户端说它验过了」、「运维者说放行」、「刚才还有效」中的任何一个 | 有了一条不经登录状态的路——**而且不出现在任何屏上，没人复核** |
| 中心把「答不出」答成「无效」或「有效」 | 前者让人白白重新登录、以为自己被踢了；后者是拿旧答案放行，[撤销向后生效](../PF-001-identity-scope-and-agent-constraints/design.md#66-撤销不等于强制停止)被破 |
| 四种不认的情形（没带、从没签发、已撤销、别的中心的）**答复不同** | 能靠差异试探出某个登录状态曾经有没有过；[账号存在性不泄漏](../PF-001-identity-scope-and-agent-constraints/acceptance.md#二绝不能发生的事)在大门口被破 |
| 版本对不上时，中心**还去判了登录状态**（答的是「无效」或别的，而不是「版本对不上」） | 一个中心看不懂的请求被猜着判了；客户端也分不清是该升级还是该重新登录 |
| 重启或升级之后**有人被退出登录**，或重启前已撤销的**又能用了** | 前者让每次维护变成全公司重新登录；后者是 [PF-001 定的安全事故](../PF-001-identity-scope-and-agent-constraints/acceptance.md#二绝不能发生的事)。**从备份恢复不在这一行**：恢复会带回备份之后撤销的登录状态，那是[恢复的后果](flows.md#16-从备份恢复)，要在动手前让运维者知道 |
| 改一项部署参数，让一份**已经发出的邀约**到期时刻变了（过期的复活，或没过期的提前、推后）；或让一条**已被判为到期**的未激活记录回来 | 邀约的时效是发出那一刻定下的，被部署参数悄悄改了；[到期本身就是一个答复](../PF-001-identity-scope-and-agent-constraints/design.md#两种邀约都会过期)，被一次改参数悄悄收回了 |
| 中心开着时钟往回倒了，**某个判定用了比中心用过的最晚时刻更早的时刻** | 过期的邀约复活、该到期的记录被判成没到期，而中心照常运行、没人看到报错 |
| 从「列出本账号的登录状态」拿到的东西，能直接当一个登录状态用 | 一次列表就能拿到同一账号其他设备的登录；持有者逐个撤销追不上 |
| 客户端把一个**报出同一个中心标识的冒牌货**当成了中心，把登录状态交给它 | 标识被当成了防冒充（它不是秘密，谁都报得出）；同事的登录落进别人手里 |
| 中心的工程记录里出现对端地址，或账号、租户能被还原出来的标识 | 运维者读记录就能知道谁在什么时候从哪来——那是一扇通过记录开的门 |
| 升级之后中心**变成了另一个标识**，或有账号、组织、成员资格丢了 | 全组织每台机器上的据点一夜之间成了别人的 |
| 升级失败后数据**已经被改了一半**，旧版本起不来了 | 全组织身份事实的唯一一份坏在半路 |
| 中心在一口**倒退了的钟**上起来了 | 过期的邀约复活、到期的记录回到期限内，**每一步都显示成功** |
| 部署密钥的值出现在体检、答复、日志、任何输出里 | 拿到它的人能冒充中心，说出只有中心自己能说的话 |
| 丢了部署密钥导致**任何一条账号、组织或登录状态读不出来** | 密钥被做成了数据密钥——那正是[明文排除的](design.md#部署密钥) |
| 中心里存在一个**没人注册过的账号** | 那就是 PF-001 说没有的平台管理员 |
| 运维者有任何一条**不经登录状态**就能做治理动作的路 | 同上 |
| 运维者能从产品里看到**谁在里面、谁登录着** | 治理事实从部署那张面漏了出去 |
| 中心**记住并区别对待某个客户端**（这台机器可信、那个程序是官方的） | [人能做的脚本能做](../PF-016-cli-tui-delivery-surface/design.md#65-人能做的脚本能做脚本能做的人能做)在中心一侧破了 |
| 两个不同的中心（从零各立一次）**标识相同** | 分不出「搬家」与「另一个中心」，人会在另一套账号体系上重新注册而不自知 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| [生来是空的](design.md#61-中心生来是空的第一位超级管理员走的是正常路) | 第一次启动成功后，用任何标识与凭据登录都失败；第一个注册的人与第二个走的步骤逐步相同 | 有一个预置的名字能登录；或第一个人多走了一步「初始化」 |
| [只认登录状态，不认客户端](design.md#62-中心只认登录状态不认客户端) | 同一个有效登录状态，先后从两台不同机器、用两种不同程序（人用的那份与一段脚本）来做同一件事：**答复相同**；中心上找不到任何「可信机器」「可信程序」的登记 | 换一台机器或换一个程序，同一个登录状态得到不同的待遇 |
| [只认自己签发且此刻有效的](design.md#63-只信自己签发的此刻仍有效的登录状态别人说验过了不算数) | 撤销一个登录状态后**立刻**用它来问事，被拒；用另一个中心签发的来问事，被拒且答复与前者逐字相同 | 撤销后还能用一会儿；或两种拒绝的答复有差别 |
| [答复的先后](design.md#64-无效与答不出是两个不同的答复) | 版本对不上的客户端带着有效、已撤销、别的中心的、什么都没带四种来：**四次都只得到「版本对不上」**；同一客户端读体检公开部分**照常读得到**。版本对得上时让数据所在够不着，再带一个已撤销的来：得到「答不出」，**不是**「无效」；同时什么都不带来：得到「无效」。数据所在够得着时，带一个有效的登录状态、配一份格式不对的输入：得到「输入不合格」；换成已撤销的登录状态配同一份输入：得到「无效」 | 版本对不上时答了登录状态的事；判不了时把要查的说成了「无效」；或把输入不合格说成了「无效」「答不出」 |
| [三个出口不合并](design.md#53-认出一个来者只有一条路) | 让数据所在够不着，再用一个**有效**的登录状态来问事：得到「答不出」，**不是**「无效」；修好后同一个登录状态照常能用，不需要重新登录 | 数据一坏就把人踢下线 |
| [拒绝逐字相同](design.md#65-拒绝的时候什么都不多说) | 版本对得上、数据所在够得着时，分别用四种来者（没带、从没签发、已撤销、别的中心的）做同一件事：**四次答复逐字相同**；登录失败的三种情形答复也逐字相同 | 任意两次答复有差别 |
| [停机：已确认的都在，没确认的等于没发生](design.md#68-停机已确认的都在没确认的等于没发生) | 发出一份邀请、在回执到达之前停掉中心，再起来：那份邀请**要么完整在、要么完全不在**；注册走到一半时停掉，起来后用同一标识同一凭据能接着走完 | 出现半份邀请；或注册的人被告知「名字已被占用」而那条记录正是他自己的 |
| [不半开](design.md#66-要么整个起来要么不起来) | 逐一拿掉密钥、某项参数、数据所在，分别启动：**每次都起不来**，且每次说明的原因**各不相同**；全部齐了才起来 | 缺了某样还是起来了；或起不来但说不出为什么 |
| [重启不让任何人退出登录](design.md#67-重启不让任何人退出登录) | 三台机器登录，重启中心，三台上原来的登录状态**都还能用**；重启前撤销的那一个重启后**仍不能用** | 重启后要重新登录；或撤销的又活了 |
| [升级整体成或整体不成](design.md#69-升级同一个中心要么整体成要么整体不成) | 升级成功：标识、账号数、组织数、有效登录状态数与升级前**逐一相等**。升级失败：换回旧版本能起，且上面几样与升级前逐一相等 | 升级后少了什么；或失败后旧版本也起不来 |
| [时间不能倒着走](design.md#610-时间不能倒着走) | 把钟拨到中心用过的最晚时刻之前，启动：**起不来**，明说是时钟。中心开着时把钟往回拨一小时：**中心不停**；接受一份按原时间还剩半小时就过期的邀请，得到「答不出」而不是接受成功；不看时间的事（比如读自己的成员资格）照常答；钟走回原来的时刻之后，一切照常 | 启动时起来了；或开着时拿倒退的钟做了判定；或开着时整个停了 |
| [过期只量中心的钟](design.md#54-中心自己的时间) | 把一台客户端机器的钟拨快一个月，去接受一份按中心的钟还没过期的邀请：**照常接受**；拨慢一个月，去接受一份按中心的钟已过期的：**不可接受** | 过没过期随客户端机器的钟变 |
| [密钥不加密任何东西](design.md#611-部署密钥运维者生成一次自己保管中心永不显示它) | 换一套密钥再启动：标识、账号、组织、成员资格、有效登录状态**逐一不变**；一条未激活记录在换密钥后仍能接着走完注册 | 换了密钥有东西读不出来；或未激活记录卡住 |
| [同一个中心换地址还是它](design.md#612-同一个中心换了地址还是它另一个中心必须被认出来) | 同一份数据在两个地址上先后起来，两处读到的标识**相同**；从零立两个中心，标识**不同** | 搬家后标识变了；或两个新中心撞了标识 |
| [运维者没有门](design.md#613-运维者没有任何一扇门通向账号能做的事) | 在中心所在的机器上，找不到任何一条不带登录状态就能建组织、邀请、移除、改角色、撤销他人登录状态的操作——**不是「有但被拒」，是没有** | 有一条「管理员命令」能做这些 |
| [秘密不经产品的任何呈现与输出交出去](design.md#614-产品不把任何秘密的值交给运维者) | 生成密钥之后，体检、日志、任何答复里搜不到部署密钥的值；模型凭据的值、登录用的凭据、登录状态本身同样搜不到；账号凭据在数据里不以可读形式存在。**不验**模型凭据在数据与备份里读不读得出——本版读得出，产品不承诺 | 某处打印了其中任何一样；或账号凭据在数据里读得出 |
| [不交出能直接用的凭证](design.md#八边界与依赖) | 在一台机器上列出本账号的登录状态，把列表里的每一项拿到另一台机器上当登录状态用：**每一次都得到「这次登录已不再有效」**；从一份数据备份里取出的登录状态，同样用不了 | 列表或备份里的某一项能直接用 |
| [参数缺一不可、重启生效、按新值算、邀约例外](design.md#615-部署参数由运维者给值起动时读缺一不可) | 缺任一项启动失败并点名；改一项不重启，旧值继续生效。**邀约**：准备三份邀请——一份发起时填了时长、一份没填且还没过期、一份没填且已过期；把默认时长调短后重启，再调长后重启：**三份的到期时刻始终不变**，已过期的那份始终不可接受；此后新发、没填时长的一份用新默认。**留存期限**：一条按旧期限还没到期、按新期限已到期的未激活记录，调短后重启，下一次被判时**是到期**；一条已经被判为到期、清掉了的，调长后重启**不回来**；一条按旧期限早已过期却从没被判过的，调长后重启按新期限算，原主人能接着走完注册 | 缺了也起得来（用了个没人定的数）；或改了立刻生效；或已发出的邀约到期时刻跟着参数变了；或已判到期的记录回来了；或调短对已积下的那些不起作用 |
| [版本对不上就明说](design.md#616-版本对不上就明说) | 用一个版本对不上的客户端做任何需要登录状态的事：**只得到「版本对不上」**，中心上那件事没有发生 | 半通不通：有的动作做成了、有的报了看不懂的错 |
| [体检只说部署](design.md#617-体检只说部署不说里面有谁) | 未登录读体检：恰三样；让数据所在够不着再读：**三样照样都在**；运维者读完整体检：看得到「此刻答不了」，没有任何账号、组织、登录状态的内容 | 体检里能数出账号；或数据所在一坏，公开体检就读不到标识与版本 |

## 四、本版不验收的

| 不验收 | 原因 |
|---|---|
| **据点那一侧**：客户端读到另一个中心时怎么呈现、旧据点怎么办 | 归 [PF-016](../PF-016-cli-tui-delivery-surface/design.md#九未决项) |
| **治理事实本身**：成员资格、角色、邀约过期、隔离 | 归 [PF-001](../PF-001-identity-scope-and-agent-constraints/acceptance.md) |
| **防冒充怎么做到** | 归技术设计；产品要求它必须有（[design §8](design.md#八边界与依赖)），本页只验「冒牌货拿不到登录状态」（§二）。**确认失败时客户端怎么呈现**归 PF-016 |
| **公网可达下的抢注** | 本版假定中心只对组织成员够得着（[部署前提](design.md#部署前提)）；前提不成立时的抢注，本版不防 |
| **只有一位超管的组织，超管出事之后怎么恢复治理** | 本版接受这个后果（[design §5.5](design.md#55-运维者与超级管理员两条线不交叉)）；补救归 PF-001 的未来版本 |
| **模型凭据在数据与备份里读不读得出** | 本版读得出，产品只承诺不呈现（[design §6.14](design.md#614-产品不把任何秘密的值交给运维者)） |
| **请求里显式带的租户身份与登录状态上当前选中的不一致时怎么答** | 归 PF-001（[design §9](design.md#九未决项)） |
| **在线密钥轮换、多实例、跨进程协调** | [本版不做](design.md#非目标) |
| **个人自托管** | [不是产品形态](../PF-016-cli-tui-delivery-surface/design.md#二目标与非目标)，研发夹具不验产品承诺 |
| **备份怎么做、多久一次、恢复前要不要再确认一次** | 备份与恢复在产品之外做；本版只验[恢复出来的算什么](flows.md#16-从备份恢复) |
| **同一份数据同时起两处的检测** | 那是运维错误，产品[明说不检测](design.md#612-同一个中心换了地址还是它另一个中心必须被认出来)，不验收 |
| **哪些版本算对得上** | 归技术设计；本版只验**对不上时明说** |
| **运维动作的留痕** | 归[可观测性要求](../../foundation/observability-and-logging/requirements.md)；产品不给运维者身份，无从按人验收 |
| **钟往前跳的后果** | 产品[明说不可逆、不可检](design.md#610-时间不能倒着走)，不验收 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
