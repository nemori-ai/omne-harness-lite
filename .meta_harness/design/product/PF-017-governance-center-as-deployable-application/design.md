# PF-017：治理中心作为一个可部署应用

- 修订：rev 1，2026-09-23 · [变更历史](changelog.md)
- 状态：草稿——没有卡住模型形状的待裁决；几条 PM 建议待产品负责人确认（[decisions §三](decisions.md#三待裁决)）；仍开着的缺口在 [§9](#九未决项)

## 一、背景与问题

**[治理中心](../../ubiquitous_language/terms/grounding-and-isolation.md#ul-governance-center--治理中心--governance-center)已经被立成一个概念，却还没有被立成一个应用。**

[PF-016 把它定为一处](../PF-016-cli-tui-delivery-surface/design.md#治理中心)：账号、组织、成员资格、邀约与组织层／租户层的范围化对象所在的那一处，独立于任何人的机器，一次部署就是一个，身份不是地址。
[PF-001 定了里面每一样东西的规则](../PF-001-identity-scope-and-agent-constraints/design.md)。
**但从来没有一处回答：它作为一个要被装到某台机器上、开着、有人管的东西，是什么形状。**

这造成四个具体的空洞，每一个都有人正等在那儿：

**第一，没人知道怎么把它立起来。**一个组织决定用这套系统，
第一件事就是要有一个中心——[没有中心，一个会话也开不了](../PF-016-cli-tui-delivery-surface/design.md#62-没准备好就开不了会话)。
可是**由谁立、立起来要准备什么、立起来那一刻里面有没有人**，正文一个字没有。

**第二，中心凭什么认出来者。**同事的机器[以一个登录状态的身份向中心问事](../PF-016-cli-tui-delivery-surface/design.md#69-需要现读成员资格的那几件事不拿副本放行)，
**中心信不信、凭什么信、不信时人看到什么**，没有产品规则——
技术侧只能写下「入口层必须先核实调用者身份」，却说不出核实的产品含义。

**第三，它停了、重启了、升级了，人看到什么。**
[PF-016 定了据点那一侧的样子](../PF-016-cli-tui-delivery-surface/design.md#617-治理中心不可达已经开着的会话照常干活)：中心问不到时，已开着的会话照常干活、三类现读明确失败。
**中心这一侧承诺什么**——重启之后还算不算登录着、升级会不会把谁变成陌生人——没人写过。

**第四，管它的那个人是谁。**[PF-001 的角色只有两种](../PF-001-identity-scope-and-agent-constraints/design.md#角色)，都在**一个组织之内**；
[超级管理员明说不是平台管理员](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-super-administrator--超级管理员--super-administrator)。
那么把中心立起来、保持在线、升级它的那个人，**在产品里是谁、能做什么、绝不能做什么**，
是一个被明确留空的位置——留空不等于没有：**没写，做出来的就会是一个能替任何人做任何事的后门账号。**

**不做会怎样**：承载租户领域事实的那个应用没有准入依据（[「没有 PF 的应用不建节点」](../../realization/README.md#应用节点比提供者节点多什么)）；
入口层身份核实无规则可依；PF-016 那一侧的「对端」永远是一个没有形状的东西；
而**第一个组织第一次部署时，会遇到一整串没人回答过的问题**——从「谁先注册」到「密钥丢了怎么办」。

## 二、目标与非目标

### 目标

- **把治理中心作为一个应用的形状定下来**：谁把它立起来、立起来要准备什么、立起来那一刻里面有什么（[§6.1](#61-中心生来是空的第一位超级管理员走的是正常路)）。
- **定清中心怎么认出一个来者**：只认[登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)、只信自己签发且此刻仍有效的、别人说「验过了」不算数、不信时怎么答（[§6.2](#62-中心只认登录状态不认客户端)～[§6.5](#65-拒绝的时候什么都不多说)）。
- **定清启动、停止、重启、升级对所有人可观察的承诺**（[§6.6](#66-要么整个起来要么不起来)～[§6.10](#610-时间不能倒着走)）。
- **给那把密钥一个产品含义**：它是什么、谁生成谁保管、丢了换了会怎样（[§6.11](#611-部署密钥运维者生成一次自己保管中心永不显示它)）。
- **回答 PF-016 留下的那一问**：怎么确认两个地址后面是同一个中心（[§6.12](#612-同一个中心换了地址还是它另一个中心必须被认出来)）。
- **立出[运维者](#运维者)这个位置**，并把它与[超级管理员](../PF-001-identity-scope-and-agent-constraints/design.md#角色)那条线彻底分开：能做什么、绝不能做什么（[§6.13](#613-运维者没有任何一扇门通向账号能做的事)、[§6.14](#614-运维者读不到任何秘密的值)）。

### 非目标

| 不做什么 | 为什么 |
|---|---|
| **任何治理事实的语义**：账号、组织、成员资格、邀约、角色、登录状态、当前租户身份 | 全归 [PF-001](../PF-001-identity-scope-and-agent-constraints/design.md)。本 topic 只说它们**装在一个什么样的应用里**，一条规则都不改 |
| **据点一侧，以及中心与据点的分界** | 归 [PF-016](../PF-016-cli-tui-delivery-surface/design.md#56-哪些东西在中心一侧哪些在据点一侧)。中心问不到时据点怎么办，那边已经定完 |
| **会话** | [中心不知道任何会话](../PF-016-cli-tui-delivery-surface/design.md#治理中心)；会话归 [PF-015](../PF-015-session-lifecycle-and-ownership/README.md) |
| **密钥轮换**（中心开着的时候换密钥） | 本版[部署密钥](#部署密钥)只在中心**停着**时更换（[§6.11](#611-部署密钥运维者生成一次自己保管中心永不显示它)）。在线轮换要处理「新旧两把同时有效」那一段，而**没有任何本版场景需要中心在换密钥时保持在线**——它换来的只是少一次重启 |
| **多实例、高可用、跨进程协调** | [第一版是单机系统](../../foundation/cross-system-constraints/requirements.md#sys-deploy)。**代价写在明面上**：中心停着的那段时间，全组织的[三类现读](../PF-016-cli-tui-delivery-surface/design.md#69-需要现读成员资格的那几件事不拿副本放行)一律失败——开不了新会话、做不了治理动作、切不了租户身份；已开着的会话不受影响 |
| **个人自托管一个中心** | [PF-016 的裁定](../PF-016-cli-tui-delivery-surface/decisions.md#一拍板记录)：本版承诺的部署形态只有「一个组织统一部署一个中心」。研发夹具起的那个中心不在产品承诺里 |
| **合规意义上的数据清除** | [PF-015 划出去、PF-016 再次点名、至今没有 topic 认领](../PF-016-cli-tui-delivery-surface/design.md#九未决项)。本 topic 不顺手认领 |
| **平台管理员、全局角色、任何跨组织的治理权** | [PF-001 没有这样东西](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-super-administrator--超级管理员--super-administrator)。本 topic 立的[运维者](#运维者)**不是它**——运维者连一个账号都不是（[§5.5](#55-运维者与超级管理员两条线不交叉)） |
| **给运维者一个网页或图形界面** | [本版没有 web](../PF-016-cli-tui-delivery-surface/decisions.md#一拍板记录)。运维者在中心所在的那台机器上做事；具体的命令与界面归技术设计 |
| **关闭自助注册的开关、注册限流** | [PF-001 把限流与滥用处理判给部署运维关注点](../PF-001-identity-scope-and-agent-constraints/design.md#非目标)，本版**没有开关**：谁够得到中心谁就能注册，够不够得到由[运维者](#运维者)决定把中心放在哪（[§6.1](#61-中心生来是空的第一位超级管理员走的是正常路)）。可被推翻，见 [decisions §二](decisions.md#二pm-推导) |
| **备份与恢复作为产品动作** | 备份与恢复**在产品之外做**：中心的数据放在哪、怎么备份、怎么拿备份起一个中心，归运维者与技术设计。本 topic 只定**恢复出来的那个中心算什么、会带回来什么**（[§6.12](#612-同一个中心换了地址还是它另一个中心必须被认出来)、[flows 1.6](flows.md#16-从备份恢复)） |
| **跨版本并存的兼容承诺**（新中心配旧客户端，或反过来） | 没有具名消费者要求它。本版只要求[对不上时明说](#616-版本对不上就明说)；中心与客户端一起升级是运维者的事。将来要给兼容窗口是加法 |
| **运维者的身份与留痕** | 产品不给运维者身份（[§4 运维者](#运维者)），所以也无从把一次运维动作记在某个人名下；中心自己的运行留痕归[可观测性要求](../../foundation/observability-and-logging/requirements.md)，不在这里立规矩 |

## 三、用户与场景

| 使用者 | 什么情况下接触这块 | 他关心什么 |
|---|---|---|
| **[运维者](#运维者)**（组织里把中心立起来并保持在线的人） | 第一次部署；停机维护；升级；换机器、换地址；密钥丢了 | 要准备什么才起得来；起不来时能不能一眼看出缺什么；升级会不会弄丢谁的账号；我**能做什么、不能做什么**，出了事算不算我的 |
| **[超级管理员](../PF-001-identity-scope-and-agent-constraints/design.md#角色)** | 中心刚立起来，他要建团队组织、把同事请进来 | 我是不是第一个；有没有一个「管理员账号」要先拿到；运维者能不能替我做治理动作、能不能看我的东西 |
| **同事**（组织的普通成员） | 每次[三类现读](../PF-016-cli-tui-delivery-surface/design.md#69-需要现读成员资格的那几件事不拿副本放行)都要问它；中心搬家、重启、升级时 | 重启之后我还登录着吗；换了地址是不是还是我们的中心；我被踢出去了还是中心暂时答不出 |
| **客户端**（本版是 [PF-016 那份装在同事机器上的东西](../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-delivery-surface--交付面--delivery-surface)，带着一个[登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)来问；**脚本走的是同一条路**） | 每一次向中心问事或发起治理动作 | 中心认不认我；不认的时候是「重新登录」还是「等一会儿」；版本对不对得上 |

> **agent 不在这张表里，这不是漏写。**agent 跑在[据点](../PF-016-cli-tui-delivery-surface/design.md#会话据点)上，
> [中心不知道任何会话](../PF-016-cli-tui-delivery-surface/design.md#治理中心)；agent 需要的成员资格与各层配值**由据点向中心问**，
> 它自己从不与中心说话。

### 运维者

**持有一次[治理中心](../PF-016-cli-tui-delivery-surface/design.md#治理中心)部署的控制权的那个人（或那几个人）：
能把它立起来、停掉、重启、升级，能拿到它所在的机器与它的数据所在。**

| 性质 | 说明 |
|---|---|
| **它不是一个账号** | 中心立起来那一刻[里面一个账号也没有](#61-中心生来是空的第一位超级管理员走的是正常路)，而运维者已经在了——**他先于任何账号存在**，所以不可能靠账号来定义。**一个人可以同时是运维者、又持有一个账号；产品不知道也不关心这两件事落在同一个人身上** |
| **它不是一个[租户角色](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-tenant-role--租户角色--tenant-role)** | 角色是[租户在组织内的属性](../PF-001-identity-scope-and-agent-constraints/design.md#角色)，作用域是一个组织；运维者的作用域是**这一次部署**，与组织无关——一个中心上有几个组织，运维者都是同一拨人 |
| **产品不给它身份、不记录它是谁** | 「谁是运维者」由**谁握着那台机器与那份数据**决定，那是组织自己的事，中心既不登记、也无从核实。**后果写在明面上**：一次运维动作产品无法记到某个人名下；要按人追责，靠组织对那台机器的访问管理 |
| **它能做的事全在部署这一层** | 立中心、生成与保管[部署密钥](#部署密钥)、给[部署参数](#部署参数)、启停重启升级、看[中心体检](#中心体检)、换机器换地址；备份与恢复（**在产品之外做**；产品只定恢复出来的算什么，见 [flows 1.6](flows.md#16-从备份恢复)）。清单见 [§6.13](#613-运维者没有任何一扇门通向账号能做的事) |
| **它绝不能做的事全在账号那一层** | [没有任何一扇门通向账号能做的事](#613-运维者没有任何一扇门通向账号能做的事)，[读不到任何秘密的值](#614-运维者读不到任何秘密的值) |

> **为什么非立这个位置不可**：不立，「把中心立起来的那个人」就会被顺手做成一个**内置的管理员账号**——
> 一个没人注册过、凭据写在某处、能替任何人做任何事的账号。**那正是 PF-001 说没有的那个平台管理员。**
> 把运维者定义为「握着部署的人」而不是「一个特殊账号」，**是让「产品里没有平台管理员」这句话在部署那一侧也成立的唯一办法。**

> **别和[超级管理员](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-super-administrator--超级管理员--super-administrator)混。**
> 超管是**一个组织内**的最高治理角色，做的是治理动作，通过客户端以他自己的登录状态做；
> 运维者做的是**让中心在**这件事，从中心所在的机器上做，**手上没有任何登录状态可用**。
> [两条线不交叉](#55-运维者与超级管理员两条线不交叉)。

### 部署密钥

**只有这一次部署持有的一套秘密。它用来让「只有这个中心自己能说出的话」不可伪造——
任何够得到中心的东西都冒充不了中心说出这些话。具体是哪几句，归技术设计。**

| 性质 | 说明 |
|---|---|
| **谁生成** | [运维者](#运维者)，**立中心时生成一次**，用产品自带的生成办法；这个办法在交出它时提醒运维者：**这是唯一一份，丢了中心起不来** |
| **谁保管** | 运维者，**放在中心的数据之外**。中心从不把它显示出来——不在[体检](#中心体检)里、不在任何答复里、不在任何输出里 |
| **它不加密任何东西** | 账号、组织、成员资格、登录状态、[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)的值——**一样都不靠它保护** |
| **缺了、不完整** | [中心不起来](#66-要么整个起来要么不起来)，并说明缺的是它 |
| **丢了** | 运维者重新生成一套，中心用新的起来 |
| **换了** | **什么都不丢**——它不加密任何东西，里面没有一样东西要靠旧的那套才读得出（[§6.11](#611-部署密钥运维者生成一次自己保管中心永不显示它)） |
| **本版不轮换** | 只在中心**停着**时更换；换的效果等同于一次停机再启动 |

> **它的名字里有「密钥」，但它不是账号的凭据、不是模型凭据、也不是登录状态**——
> 那三样各归各的拥有者，[值都永不呈现](../PF-016-cli-tui-delivery-surface/design.md#611-秘密不进任何一份呈现)。
> 它是**部署级**的：整个中心只有一套，与任何人无关。

### 中心标识

**一个[治理中心](../PF-016-cli-tui-delivery-surface/design.md#治理中心)用来指认自己的那个名字：
立起来那一刻由中心自己定下、此后不变、跟着它的数据走、对任何够得到中心的人可读。**

| 性质 | 说明 |
|---|---|
| **它不是地址** | 地址是够到中心的方式，可以变；标识不变。[PF-016 定的「身份不是它的地址」](../PF-016-cli-tui-delivery-surface/design.md#治理中心)在这里有了可比较的东西 |
| **它不是秘密** | 中心[在任何人登录之前就答得出它](#617-体检只说部署不说里面有谁)。客户端靠它分辨[「搬家了」与「另一个中心」](#612-同一个中心换了地址还是它另一个中心必须被认出来)，人靠它核对「我们的中心是不是这个」 |
| **跟着数据走** | 中心换机器、换地址、[从备份恢复](flows.md#16-从备份恢复)，只要用的是同一份数据，标识就是同一个；**从零重立一个，就是一个新的标识、一个新的中心**——哪怕运维者是同一个人、地址是同一个地址 |
| **它不由运维者起名** | 由中心生成。让人起名，两个中心撞名的那一天，正是最需要分得清的那一天 |

> **为什么它与[部署密钥](#部署密钥)是两样东西**：密钥是秘密、可以换；标识是名字、不能换。
> 若把「我是哪个中心」押在密钥上，**丢一次密钥就等于换一个中心**——
> 全组织每台机器上的[据点](../PF-016-cli-tui-delivery-surface/design.md#会话据点)（身份里带着「哪个中心」）一夜之间全成了别人的。
> 为了防冒充而付这个代价不值得：**「连上的是不是它自称的那个中心」由传输那一层保证**，归技术设计（[§8](#八边界与依赖)）。

### 部署参数

**那些产品正文写着「按部署配置」、对整个中心上所有人一律生效、且不属于任何组织或租户的值的统称。**

| 性质 | 说明 |
|---|---|
| **每一项各归定义它的 topic** | 本版有五项：[未激活记录的留存期限](../PF-001-identity-scope-and-agent-constraints/design.md#未激活的账号记录不会永久占着那个名字)；[加入组织的邀请、隶属请求](../PF-001-identity-scope-and-agent-constraints/design.md#两种邀约都会过期)各自的默认时长（PF-001）；[待确认的复制通知、分享邀请](../PF-003-asset-transfer-and-sharing/design.md#614-待确认的复制通知与分享邀请会过期)各自的默认时长（PF-003）。**本 topic 不新增任何一项**，只说它们由谁给、什么时候生效、改了之后怎么算 |
| **不是[范围化对象](../PF-001-identity-scope-and-agent-constraints/design.md#范围化对象)** | 不挂在任何一层、不参与求值、没有组织或租户能覆盖它。**它是部署的事实，不是治理的事实** |
| **每一项各自由[运维者](#运维者)给值，中心起动时读** | [每一项都必须有自己的值，缺一不可](#615-部署参数由运维者给值起动时读缺一不可) |
| **改了只影响此后的判定** | 本 topic 的规则（[§6.15](#615-部署参数由运维者给值起动时读缺一不可)）：不追溯改写已做出的判定，也不为已存在的记录保留旧值 |

### 中心体检

**中心关于「我此刻在不在、能不能答」的自述——它只说部署，不说里面有谁。**

| 谁看 | 看到什么 |
|---|---|
| **任何够得到中心的人**，登录之前就能看 | 在不在 · [中心标识](#中心标识) · 版本 |
| **[运维者](#运维者)**，在中心所在的机器上看 | 上面三样，加上：这次是什么时候起来的 · 数据所在够不够得着 · [部署密钥](#部署密钥)在不在、完整不完整（**不含它的值**） · 时钟正不正常 · 每一项[部署参数](#部署参数)各自此刻的值 |

**它不含**：账号有几个、组织有哪些、谁登录着、谁被邀请了——**一个字都没有**。
那些是治理事实，[通过客户端以登录状态看](../PF-001-identity-scope-and-agent-constraints/flows.md#四角色与操作)，运维者没有这扇门（[§6.13](#613-运维者没有任何一扇门通向账号能做的事)）。

## 五、模型

### 5.1 中心有两张面，没有第三张

```text
                    ┌──────────────────────────────────────────┐
   同事的机器 ──────→│               治理中心                    │←────── 运维者
  （客户端，以一个     │                                          │  （在中心所在的机器上）
   登录状态的名义）    │   账号 · 组织 · 成员资格 · 邀约 · 登录状态   │
                    │   组织层与租户层的范围化对象               │   能做的：立 · 启停 · 升级 ·
   能做的：PF-001     │                                          │   密钥 · 参数 · 体检
   定义的全部动作，    │   ─────────────────────────────────────  │
   以及体检的公开部分  │   中心标识 · 部署密钥 · 部署参数 · 版本    │   不能做的：上面那一层的任何事
                    └──────────────────────────────────────────┘
```

**这张图要读出三件事：**

- **上面那一层是治理事实，只从左边那张面进出**，而且每一次都要带着一个登录状态（[§6.2](#62-中心只认登录状态不认客户端)）。
  运维者站在右边，**对那一层没有门**。
- **下面那一层是部署事实，只从右边那张面改**。同事从左边只读得到其中不是秘密的那几样（[体检的公开部分](#中心体检)）。
- **没有第三张面。**没有「内部接口」「管理接口」「脚本专用入口」——
  [脚本走左边、与人同一条路](../PF-016-cli-tui-delivery-surface/design.md#65-人能做的脚本能做脚本能做的人能做)。
  多一张面，就多一条没人复核的路。

**备份与恢复不在右边那张面上**：它们在产品之外做，产品只定[恢复出来的算什么](flows.md#16-从备份恢复)。

### 5.2 中心的一生

```text
   （没有）
      │  运维者准备好：数据所在 · 部署密钥 · 每一项部署参数
      │  第一次启动成功 ── 中心标识在这一刻定下，里面零账号、零组织
      ▼
   已立起来 · 运行中  ◄──────────────────────────┐
      │                                          │
      │  停止（运维者动手，或机器停了）             │  再次启动成功（同一份数据，同一个标识）
      ▼                                          │
   已立起来 · 停着  ──────────────────────────────┘
      │
      │  升级 = 停着的时候换一个版本再启动：起得来就是同一个中心，起不来数据原样不动
      │  换密钥 = 停着的时候换一套再启动：什么都不丢
      │  换机器、换地址 = 把数据（连同密钥）搬过去再启动：标识不变
      │
      ✕  本版没有「销毁」这一步
```

| 它的哪一样 | 什么时候定 | 会不会变 |
|---|---|---|
| **[中心标识](#中心标识)** | 第一次启动成功那一刻 | **不变**，跟着数据走 |
| **里面的治理事实** | 从零开始，此后只由 PF-001 的动作改 | 运维者的任何动作都不改它们 |
| **[部署密钥](#部署密钥)** | 立中心时生成 | 可以换，只在停着时换，换了什么都不丢 |
| **[部署参数](#部署参数)** | 立中心时给 | 可以改，停着时改，下次启动生效 |
| **版本** | 每次启动 | 升级就是换它 |
| **地址** | 运维者定 | 可以变；**中心自己不知道也不需要知道**（[§6.12](#612-同一个中心换了地址还是它另一个中心必须被认出来)） |

**把中心放在一台不属于任何同事的机器上，是部署的意图，不是起得来的条件。**
[中心独立于任何人的机器](../PF-016-cli-tui-delivery-surface/design.md#治理中心)说的是它的身份与归属不挂在任何人身上；
中心不检查、也无从检查自己跑在谁的机器上，这件事归运维者。

> **为什么没有「销毁」**：[已激活的账号本版没有任何消失路径](../PF-001-identity-scope-and-agent-constraints/design.md#非目标)，组织也不解散。
> 中心装着的正是这些东西——**它们没有终点，装着它们的那一处就没有终点**。
> 停掉不是销毁；把那份数据清掉也不是产品动作（与[据点那边的口径](../PF-016-cli-tui-delivery-surface/flows.md#三状态流转)一样）。

### 5.3 认出一个来者，只有一条路

```text
   来者 ──一次请求──→ 中心
                       │
                       ① 版本对得上吗？ ── 对不上 ──→「版本对不上」（不看登录状态，也不区分带没带）
                       │ 对得上
                       ▼
                       ② 认人：带了登录状态吗？是我签发的吗？此刻仍有效吗？
                       │
            ┌──────────┼──────────────────────┐
            ▼          ▼                      ▼
           是    没带／不是／已失效          答不出（此刻判不了）
            │          │                      │
            ▼      「重新登录」             「稍后再试」
       ③ 按 PF-001 办  （四种情形逐字相同）   （不是拒绝，也不是放行）

   ①②③ 任何一步判不了，都在那一步答「答不出」，不再往下，也绝不改说成「无效」
```

**先核版本，再认人，最后才按 PF-001 办事**（[§6.4](#64-无效与答不出是两个不同的答复)）。
**认人那一步有三个出口，一个都不能少，也一个都不能合并**（[§6.3](#63-只信自己签发的此刻仍有效的登录状态别人说验过了不算数)、[§6.4](#64-无效与答不出是两个不同的答复)、[§6.5](#65-拒绝的时候什么都不多说)）。
**没有第四个出口**——没有「客户端说它验过了」、没有「刚才还有效」、没有「运维者说放行」。

注册、登录与[体检的公开部分](#中心体检)不需要登录状态，走的是 ① 之后直接办；**体检的公开部分连 ① 也不挡**，见 [§6.4](#64-无效与答不出是两个不同的答复)。

### 5.4 中心自己的时间

**「现在几点」由中心说了算，而且只由它说。**
[邀约什么时候过期](../PF-001-identity-scope-and-agent-constraints/design.md#两种邀约都会过期)、[未激活记录什么时候到期](../PF-001-identity-scope-and-agent-constraints/design.md#未激活的账号记录不会永久占着那个名字)，
量的都是中心的钟；同事机器上的钟怎么走，与此无关。
**所以这口钟不能倒着走**（[§6.10](#610-时间不能倒着走)）——倒一次，过期的邀约会悄悄复活，到期的记录会悄悄回到期限内，而且没有任何人会看到报错。

### 5.5 运维者与超级管理员：两条线不交叉

| | [运维者](#运维者) | [超级管理员](../PF-001-identity-scope-and-agent-constraints/design.md#角色) |
|---|---|---|
| **是什么** | 握着这次部署的人 | 一个组织内的最高治理角色 |
| **靠什么行事** | 对中心所在机器与数据的控制 | 他自己的登录状态与角色 |
| **作用域** | 这一次部署 | 那一个组织 |
| **能做的** | 立 · 启停 · 升级 · 密钥 · 参数 · 体检；备份与恢复在产品之外做 | 建组织 · 邀请 · 改角色 · 移除 · 隶属 · 管组织的设置权限资产 |
| **做不了对方的事** | **没有门**：不能注册、登录、建组织、邀请、移除、改角色、撤谁的登录状态，不能读任何人的东西 | **没有门**：不能启停升级中心、看不到部署密钥、改不了部署参数 |
| **产品记不记得他是谁** | **不记**——他不是账号 | 记——他是一个租户 |

**两条线在一个人身上重合是常事**（IT 同事既部署中心又是公司组织的超管），**但产品把它当成两个人**：
他做治理动作时用的是登录状态，做运维动作时用的是机器；**前者留下的每一笔都记在他的租户名下，后者产品记不到任何人名下**。

> **为什么不让运维者「顺便」有一点治理权**（比如替忘了密码的同事重置、把最后一位超管请回来）：
> 一开这个口，运维者就成了一个**不需要登录就能做治理动作的身份**——
> 也就是 [PF-001 明说没有的那个平台管理员](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-super-administrator--超级管理员--super-administrator)。
> **本版那些「救急」的路一条都没有**：[凭据不能重置](../PF-001-identity-scope-and-agent-constraints/design.md#非目标)、[组织永远至少有一位超管](../PF-001-identity-scope-and-agent-constraints/design.md#角色)。
> 那是 PF-001 定的形状；要开口子得回那边开，**不在部署这一侧偷偷开**。

## 六、产品规则

### 6.1 中心生来是空的；第一位超级管理员走的是正常路

**中心第一次立起来那一刻，里面零账号、零组织、零登录状态。它不自带任何账号，[运维者](#运维者)也不为它造一个。**

第一个人怎么来，**一步都不新增**：

| 步 | 谁 | 做什么 | 依据 |
|---|---|---|---|
| 1 | 任何够得到中心的人 | 注册 | [PF-001 flows 1.1](../PF-001-identity-scope-and-agent-constraints/flows.md#11-注册)：「任何能访问该部署的人」 |
| 2 | 他 | 登录 | [PF-001 flows 1.2](../PF-001-identity-scope-and-agent-constraints/flows.md#12-登录) |
| 3 | 他 | 建一个团队组织，**建起来他就是它的超级管理员** | [PF-001 flows 1.4](../PF-001-identity-scope-and-agent-constraints/flows.md#14-创建组织) |
| 4 | 他 | 邀请同事 | [PF-016 flows 1.2](../PF-016-cli-tui-delivery-surface/flows.md#12-超级管理员把同事请进来) |

**三条后果：**

| 后果 | 说明 |
|---|---|
| **谁先来没有任何特殊待遇** | 第一个注册的人与第一百个一样，只是一个账号。他之所以成为超管，是因为**他建了一个组织**，不是因为他先来。第二个人也可以建自己的组织 |
| **谁够得到中心，谁就能注册** | 中心不设第二道门。够不够得到，由运维者把中心放在哪决定——[PF-001 把限流与滥用处理判给部署运维关注点](../PF-001-identity-scope-and-agent-constraints/design.md#非目标)，本版没有「关闭注册」的开关（[非目标](#非目标)） |
| **中心不限制组织的数量** | 「[一个组织统一部署一个中心](../PF-016-cli-tui-delivery-surface/decisions.md#一拍板记录)」是**部署的意图**——谁部署、谁负责、同事都连它——不是中心上只能有一个组织。[多组织的端到端验证本来就在一个中心上做](../PF-016-cli-tui-delivery-surface/flows.md#14-一段脚本把整条链跑完) |

> **为什么不做一个「内置管理员」或「首个注册者自动成为管理员」**：
> 前者是一个没人注册过、凭据得写在某处、能替任何人做事的账号；后者给了「先来」一个产品意义。
> **两者都要一个 PF-001 里不存在的平台级角色。**而本产品的治理权全在组织之内，
> [建组织的人就是它的超管](../PF-001-identity-scope-and-agent-constraints/design.md#组织)——**正常路已经把「第一个管理员从哪来」答完了。**

### 6.2 中心只认登录状态，不认客户端

**凡是读或改中心所拥有的事实，每一次都以恰好一个[登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)的名义进行。**
例外只有两处，且都是「还没有登录状态」的事：**注册与登录本身**，以及[体检的公开部分](#中心体检)。

**中心不知道、也不试图知道**：来者是哪台机器、哪个程序、是人在敲还是脚本在跑、装的是 PF-016 那份东西还是别的什么。
**它眼里只有登录状态。**

> **这条挡的是「可信客户端」。**一旦中心开始认「这台机器是我们的」「这个程序是官方的」，
> 就有了一条不经登录状态的路，而[人能做的脚本能做、脚本能做的人能做](../PF-016-cli-tui-delivery-surface/design.md#65-人能做的脚本能做脚本能做的人能做)那条规则
> 在中心这一侧就破了——**破在没人看得见的地方**。

### 6.3 只信自己签发的、此刻仍有效的登录状态；别人说「验过了」不算数

**中心信一个登录状态，当且仅当两件事同时成立：**

1. **是它自己签发的**（[PF-001 flows 1.2](../PF-001-identity-scope-and-agent-constraints/flows.md#12-登录)）；
2. **此刻仍有效**——没有被[退出或撤销](../PF-001-identity-scope-and-agent-constraints/flows.md#13-退出)。

**每一次来都重新看这两件事。**别的一概不算：

| 不算数的 | 为什么 |
|---|---|
| 「客户端已经验过了」 | 客户端不是签发方，它的话与任何人的话等重 |
| 「刚才还是有效的」 | [撤销向后生效](../PF-001-identity-scope-and-agent-constraints/design.md#66-撤销不等于强制停止)，「刚才」不是「此刻」 |
| 另一个中心签的 | [两个中心上的同名标识是两个账号](../PF-016-cli-tui-delivery-surface/design.md#治理中心)，登录状态更不相通 |
| 运维者说放行 | [运维者没有这扇门](#613-运维者没有任何一扇门通向账号能做的事) |

**「上游已经验过了不算数」在产品上的意思只有一句：没有任何东西能替一个人担保身份。**
唯一的凭证是中心自己发的那个登录状态，而且是此刻仍有效的那个。

**一个已被撤销的登录状态再来**：中心拒绝，答复是「这次登录已不再有效，请重新登录」。
**除此之外什么都没变**：他的账号、组织、成员资格原样都在；他重新登录得到的是[一个新的登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)，
[当前租户身份从个人组织重新起算](../../ubiquitous_language/terms/subjects-and-ownership.md#ul-current-tenant-identity--当前租户身份--current-tenant-identity)；
他机器上的会话[一样都不少](../PF-016-cli-tui-delivery-surface/design.md#会话据点)——只是在重新登录之前[进不去、也开不了新的](../PF-016-cli-tui-delivery-surface/design.md#62-没准备好就开不了会话)。

### 6.4 「无效」与「答不出」是两个不同的答复

**中心不能放行时，先说哪一句是写死的：**

| 先后 | 规则 |
|---|---|
| **① 版本核对先于一切** | 版本对不上时，**只答「版本对不上」**——不看登录状态，也不区分带没带。一个它看不懂的请求，它连「这是谁」都不去判（[§6.16](#616-版本对不上就明说)） |
| **② 「答不出」可以在任何一步出现，且优先于「无效」** | 哪一步判不了，就在那一步答「答不出」，不再往下。**判不了就不下结论**——**绝不把「判不了」说成「无效」**，也绝不说成放行 |
| **③ 版本对得上、也判得了，才轮到「无效」** | 带来的登录状态没过 [§6.3 那两件事](#63-只信自己签发的此刻仍有效的登录状态别人说验过了不算数)，或者根本没带（[§6.5](#65-拒绝的时候什么都不多说)） |

**体检的公开部分不受 ① 挡。**它正是让人在登录之前看见版本与[中心标识](#中心标识)的那一处——
挡住它，版本对不上的客户端就连「对不上的是哪一版」「连的还是不是原来那个中心」都看不到。

**认人那一步不能放行时，答复恰有两种，不得合并，也不得互相冒充：**

| 答复 | 它是什么 | 人该做什么 |
|---|---|---|
| **无效** | 一个**成立的结论**：这次来的身份此刻不作数 | 重新登录 |
| **答不出** | **没有结论**：中心此刻判不了（数据所在够不着、时钟读不到） | 稍后再试；**不要重新登录，那解决不了问题** |

**「答不出」既不是放行，也不是拒绝**——与 [PF-001 §6.4「不可用」与「失权」的分界](../PF-001-identity-scope-and-agent-constraints/design.md#64-隔离)同一条。
把「答不出」说成「无效」，人会白白重新登录一次、还以为自己被踢了；说成「有效」，就是拿旧答案放行。

### 6.5 拒绝的时候，什么都不多说

**下面四种情形，中心的答复逐字相同：**

1. **不带登录状态**，就做需要登录状态的事；
2. 带的登录状态**从没被这个中心签发过**；
3. 带的登录状态**已被退出或撤销**；
4. 带的登录状态是**别的中心签的**。

**登录失败的三种情形答复也逐字相同**（[PF-001 flows §2](../PF-001-identity-scope-and-agent-constraints/flows.md#二分支与异常)）。
**这两组都只在版本对得上、也判得了的时候才出现**（[§6.4 的先后](#64-无效与答不出是两个不同的答复)）：判不了的那一刻，四种情形里要查的那三种一律答「答不出」。

[账号存在性不从登录路径泄漏](../PF-001-identity-scope-and-agent-constraints/acceptance.md#三判据)这条，在中心的大门口同样成立：
**从中心的拒绝里，读不出任何一个名字存不存在、任何一个登录状态曾经有没有过。**

### 6.6 要么整个起来，要么不起来

**中心启动，要么全部就绪、开始答一切它拥有的事；要么不起来，并告诉[运维者](#运维者)差的是哪一样。没有中间态。**

启动要的东西：

| 要什么 | 缺了会怎样 |
|---|---|
| **数据所在**够得着 | 不起来，说明是它 |
| **[部署密钥](#部署密钥)**在、且完整 | 不起来，说明是它 |
| **每一项[部署参数](#部署参数)**都有值、都合法 | 不起来，说明缺哪一项、哪一项不合法 |
| **时钟没有倒退** | 不起来（[§6.10](#610-时间不能倒着走)） |
| **版本能接手这份数据** | 不起来，数据原样不动（[§6.9](#69-升级同一个中心要么整体成要么整体不成)） |

**「不半开」对每一类人各意味着什么：**

| 谁 | 他不会遇到的 |
|---|---|
| 运维者 | 「起来了但注册坏了」「起来了但邀约不会过期」这类**要靠试才发现**的状态。起不来就是起不来，而且说清为什么 |
| 同事 | 一个**能登录却答不出成员资格**、**能建组织却记不下邀请**的中心。中心要么答一切它拥有的事，要么整个问不到 |
| 客户端 | 需要自己判断「中心哪一部分能用」。它只需分得清[版本对不上与认人那一步的三个出口](#53-认出一个来者只有一条路) |

**中心开着的时候数据所在坏了**，属于「答不出」（[§6.4](#64-无效与答不出是两个不同的答复)）：它对答不了的事说答不了，**不拿旧答案顶、不编一个空清单**，并在[体检](#中心体检)里让运维者看见。

> **为什么不做「能起多少起多少」**：那样每一个部件都得定义「我不在时别人怎么办」，
> 而中心拥有的事实彼此咬合——[账号没有个人空间就不能激活](../PF-001-identity-scope-and-agent-constraints/flows.md#11-注册)、
> [邀请不会过期就等于永远有效](../PF-001-identity-scope-and-agent-constraints/design.md#两种邀约都会过期)。
> **半开的中心给出的每个答案都可能是错的，而错得很像对的。**

### 6.7 重启不让任何人退出登录

**中心停了再起来，此前有效的[登录状态](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)依然有效；此前已失效的依然失效。升级同样。**

[PF-001 flows §3.2 要求失效在重启之后依然成立](../PF-001-identity-scope-and-agent-constraints/flows.md#32-登录状态)——登录状态是一样**留得住**的东西，不是中心开着时才有的记忆。
留得住的东西，重启前后是同一批。

**这一条管的是重启与升级，不管[从备份恢复](flows.md#16-从备份恢复)。**恢复把中心带回备份那一刻，
备份之后被退出或撤销的登录状态会跟着回来——那是恢复的后果，由 [flows 1.6](flows.md#16-从备份恢复) 拥有，并要在恢复之前让运维者知道。

**后果**：中心重启，同事唯一注意到的是**那段问不到的时间**；
重启完成后他的机器[仍然「准备好」](../PF-016-cli-tui-delivery-surface/design.md#62-没准备好就开不了会话)，不需要重新登录，
[三类现读](../PF-016-cli-tui-delivery-surface/design.md#69-需要现读成员资格的那几件事不拿副本放行)重新能做。

> **为什么不选「重启即全员退出」**：那让每一次维护都变成全公司的重新登录，
> 而且[逐个撤销登录状态](../PF-001-identity-scope-and-agent-constraints/flows.md#13-退出)这个动作会变得毫无意义——反正重启就全没了。
> **登录状态的存亡只由它自己的退出与撤销决定**，不由中心的进程决定。

### 6.8 停机：已确认的都在，没确认的等于没发生

**中心停下来之前已经确认给人的每一件事，起来之后都在；停下来那一刻还没确认的，等于没发生。**
[PF-001 flows §2 写着「底层不可用 → 不产生部分结果」](../PF-001-identity-scope-and-agent-constraints/flows.md#二分支与异常)，停机是它的一个实例。

| 停机那一刻正在发生的 | 起来之后 |
|---|---|
| 一次注册走到一半 | 停在[未激活](../PF-001-identity-scope-and-agent-constraints/flows.md#31-账号)，[用同一标识同一凭据接着走](../PF-001-identity-scope-and-agent-constraints/design.md#未激活的账号记录不会永久占着那个名字) |
| 一份邀请刚发出、回执没到 | 要么在（可以看到它等着），要么不在（重新发）；**不会有半份** |
| 一次切换当前租户身份 | 同上：切成了就是切成了，没切成就还在原来的组织 |

**[运维者](#运维者)可以在任何时刻停它**，不必等谁。**停机对据点上的会话没有任何影响**（[PF-016 §6.17](../PF-016-cli-tui-delivery-surface/design.md#617-治理中心不可达已经开着的会话照常干活)）。

### 6.9 升级：同一个中心，要么整体成，要么整体不成

**升级就是停着的时候换一个版本再启动。起得来，它就是原来那个中心：[中心标识](#中心标识)不变，账号、组织、成员资格、登录状态一条不变。
起不来，数据必须还是升级前的样子，旧版本照常能起。**

**没有「升级到一半」的中心。**这一条是对技术设计的要求，不是描述：
**中心装着的是全组织身份事实的唯一一份**，一个升到一半的中心比一个停着的中心糟得多——它可能在错的数据上给出看起来对的答案。

**升级之后客户端对不对得上**，见 [§6.16](#616-版本对不上就明说)；中心与客户端一起升级是运维者的事（[非目标](#非目标)）。

### 6.10 时间不能倒着走

**中心的钟是整个部署唯一的一口钟**（[§5.4](#54-中心自己的时间)）。**它拒绝在一口比它上次记下的时刻还早的钟上启动**，并告诉运维者是这个原因。

| 钟怎么了 | 中心怎么办 | 为什么 |
|---|---|---|
| **倒退了**（比上次记下的时刻早） | **不起来** | 过期的[邀约](../PF-001-identity-scope-and-agent-constraints/design.md#两种邀约都会过期)会复活、到期的[未激活记录](../PF-001-identity-scope-and-agent-constraints/design.md#未激活的账号记录不会永久占着那个名字)会回到期限内，**而且每一步都显示成功** |
| **开着的时候读不到钟了** | 凡是要看时间才能答的事，答「答不出」（[§6.4](#64-无效与答不出是两个不同的答复)） | 猜一个时间等于替系统撒谎 |
| **往前跳了一大截** | **中心分不出这是跳了还是它真停了那么久**，照常起来 | 后果诚实地写在这里：邀约会提前过期、未激活记录会提前被清，**且不可逆**。这口钟归运维者看管 |

### 6.11 部署密钥：运维者生成一次、自己保管，中心永不显示它

**[部署密钥](#部署密钥)由[运维者](#运维者)在立中心时生成一次，放在中心的数据之外，由他保管。中心不在任何地方显示它。**

| 情形 | 会怎样 |
|---|---|
| **生成时** | 用产品自带的生成办法生成；这个办法在交出它时提醒运维者：**这是唯一一份，丢了中心起不来**。此后它不进[体检](#中心体检)、不进任何答复 |
| **缺了、不完整** | 中心不起来（[§6.6](#66-要么整个起来要么不起来)）。**里面的账号与组织一样都没少**——只是中心在拿到一套完整的密钥之前不开门 |
| **丢了** | 运维者**生成一套新的**，中心用新的起来。**什么都不丢**：密钥不加密任何东西（[§4](#部署密钥)），账号、组织、成员资格、登录状态与新密钥无关 |
| **换了** | 只在停着时换，效果等同于一次停机再启动：[停机那一刻没确认的等于没发生](#68-停机已确认的都在没确认的等于没发生)，已确认的都在 |
| **未激活的账号** | 换密钥**不影响它们**：在留存期限内照 PF-001 [接着走完注册](../PF-001-identity-scope-and-agent-constraints/design.md#未激活的账号记录不会永久占着那个名字)即可 |
| **泄漏了** | 拿到它的人能冒充中心，说出那些只有中心自己能说的话。**处置就是换一套**：停、换、起 |

> **为什么它必须什么都不加密**：同类产品最常见的一条运维事故，是「丢了那把密钥，所有加密过的东西再也读不出来」（[decisions §六](decisions.md#六调研参照)）。
> 本产品让这套密钥只做一件事——让中心自己说的话伪造不了——**就是为了让「丢了」的代价是「重新生成一套」，而不是「全组织的东西没了」**。

### 6.12 同一个中心换了地址还是它；另一个中心必须被认出来

**同一个[治理中心](../PF-016-cli-tui-delivery-surface/design.md#治理中心)换了地址，还是它：[中心标识](#中心标识)不变，账号、组织、成员资格、登录状态一条不变。**

**「怎么确认两个地址后面是同一个中心」——答案是比[中心标识](#中心标识)：**

| 客户端在新地址上读到的标识 | 它是什么 | 客户端该怎么办（PF-016 已定的要求：[人必须分得清](../PF-016-cli-tui-delivery-surface/design.md#治理中心)；本 topic 只给判定依据） |
|---|---|---|
| 与它记着的相同 | **中心搬家了** | 照常，一切接着用 |
| 与它记着的不同 | **另一个中心** | **明说这是另一个中心**，不得把它当成原来那个接着用——[那台机器上的据点、登录状态、副本都是原来那个中心的](../PF-016-cli-tui-delivery-surface/design.md#会话据点) |

**中心自己不知道、也不需要知道自己的地址。**
[本版没有网页、没有邮件、没有任何带外通道](../PF-016-cli-tui-delivery-surface/decisions.md#一拍板记录)——
中心不生成任何要人点开的链接，所以它不必知道人从哪儿够到它。
**搬家因此是运维者与客户端之间的事**：运维者把新地址告诉同事，同事在自己机器上换掉地址，客户端拿标识核对。中心一侧什么都不用做。

**[从零重立](#52-中心的一生)的那个，是另一个中心。**哪怕运维者是同一个人、地址是同一个地址、里面重新注册了同样的名字——
[两个中心上的同名标识是两个账号](../PF-016-cli-tui-delivery-surface/design.md#治理中心)。客户端会看到标识不同，并且必须说出来。
**[从备份恢复](flows.md#16-从备份恢复)的不是重立**：标识跟着数据走，恢复出来的还是原来那个。

**同一份数据被拷贝之后在两处同时起来，是运维错误，产品不检测。**
两处的[中心标识](#中心标识)相同，此后却各自演化——各自收注册、各自签登录状态、各自记邀约；
**客户端按标识分不出它们**，同事连到哪一处就改哪一处的事实。发现之后只能保留一份、丢掉另一份，
丢掉的那一份上发生过的事都不在了。**这件事归运维者看管**，与[钟往前跳](#610-时间不能倒着走)同一个口径：
产品分不出，所以把后果诚实地写在这里。

> **「连上的是不是它自称的那个中心」**——也就是防冒充——**不靠标识**，标识不是秘密。
> 那由传输那一层保证，归技术设计（[§8](#八边界与依赖)）。**产品要的是两件事分开**：标识负责「是不是同一个」，传输负责「是不是真的它」。

### 6.13 运维者没有任何一扇门通向账号能做的事

**[运维者](#运维者)能做的**：立中心 · 生成与更换[部署密钥](#部署密钥) · 给与改[部署参数](#部署参数) · 启动、停止、重启、升级 · 看[中心体检](#中心体检) · 换机器、换地址 · 备份与恢复（**在产品之外做**；产品只定恢复出来的算什么，见 [flows 1.6](flows.md#16-从备份恢复)）。**到此为止。**

**运维者绝不能做的**——**不是「不该做」，是「没有这扇门」**：

| 做不了的 | 为什么连门都没有 |
|---|---|
| 以任何账号的身份做任何事：注册、登录、建组织、邀请、接受、移除、改角色、隶属、切租户身份 | 这些[全都要一个登录状态](#62-中心只认登录状态不认客户端)，而运维者手上没有 |
| 替任何人做治理动作（「替他接受邀请」「把他移出去」） | 同上。**给运维者一个不需要登录状态的通路，就是造出那个平台管理员** |
| 撤销任何人的登录状态 | [撤销是账号持有者自己的动作](../PF-001-identity-scope-and-agent-constraints/flows.md#13-退出)。运维者手里唯一的钝器是**停掉中心**——那让全组织的三类现读失败，不针对任何一个人 |
| 直接造一个账号、删一个账号、删一个组织 | [账号只从注册产生，本版没有消失路径](../PF-001-identity-scope-and-agent-constraints/design.md#非目标)。运维者没有第二条产生账号的路 |
| 看谁在里面、谁登录着、谁邀请了谁 | 那是治理事实，[要以登录状态通过客户端看](../PF-001-identity-scope-and-agent-constraints/flows.md#四角色与操作)。体检里[一个字都没有](#中心体检) |
| 看任何人的会话 | [中心里根本没有会话](../PF-016-cli-tui-delivery-surface/design.md#治理中心) |

**这条承诺的边界要说实话**：运维者握着那台机器与那份数据，**产品挡不住一个直接翻数据的人**。
产品承诺的是**通过产品没有这样的门**，以及[秘密的值在数据里也读不出来](#614-运维者读不到任何秘密的值)。
要防的是「产品自己开了后门」，不是「握着磁盘的人」——后者靠组织对那台机器的访问管理。

### 6.14 运维者读不到任何秘密的值

**[部署密钥](#部署密钥)的值、账号的凭据、[模型凭据](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-model-credential--模型凭据--model-credential)的值、登录状态本身——运维者一样都读不到。**

| 秘密 | 中心怎么对它 |
|---|---|
| 部署密钥 | 生成时交给运维者一次，此后**不显示**（[§6.11](#611-部署密钥运维者生成一次自己保管中心永不显示它)） |
| 账号的凭据 | [不以可读形式保存](../PF-001-identity-scope-and-agent-constraints/design.md#账号)——**在数据里也读不出来** |
| 模型凭据的值 | [永不呈现](../PF-016-cli-tui-delivery-surface/design.md#611-秘密不进任何一份呈现)；体检不含它 |
| 登录状态 | 不出现在任何输出里；体检只说「在不在」的部署事实，不说谁登录着 |

**运维者看得到的只有「在不在、完整不完整、什么时候生成的」**，
与[客户端那一侧对秘密的口径](../PF-016-cli-tui-delivery-surface/design.md#611-秘密不进任何一份呈现)一致。

### 6.15 部署参数由运维者给值、起动时读、缺一不可

**每一项[部署参数](#部署参数)都必须由[运维者](#运维者)各自给一个值；缺任何一项，中心不起来并指出缺哪一项。产品不替它们出厂一个数。**

**改了要重启才生效**：参数在中心起动时读一次；改了的值在下一次启动生效。

**部署参数变更只影响此后的判定：不追溯改写已做出的判定，也不为已存在的记录保留旧值。**

| 新值生效那一刻（重启），一条记录**按旧值**处在哪 | 怎么算 |
|---|---|
| **已经到期**（按旧值算已到期，不论有没有人来问过） | **不动。**[到期本身就是一个答复](../PF-001-identity-scope-and-agent-constraints/design.md#两种邀约都会过期)，它算已经判完：调长期限不让过期的邀约复活，也不让过了留存期限的未激活记录回到期限内 |
| **还没到期**（按旧值算尚未到期） | **按新值判。**一条未激活记录、一份悬着的邀约（发起时没有指定时长的那种），此后被问到时量的是中心当下的钟、用的是当下的参数：调短可能让它当场到期，调长让它多等一会 |
| 新值生效之后才产生 | 按新值 |

> **为什么是「此后的判定」，不是「按记录产生时的参数」**：过期与到期本来就是[量中心当下的钟](#54-中心自己的时间)去判的，
> 参数跟着同一口径——**判的那一刻用的是那一刻的钟与那一刻的参数**。
> 按记录产生时的参数算，要给每一条记录记下一份当时的参数；**而运维者调短期限的那一天，往往正是想让已经积下的那些尽快到期**，
> 那样做却一条也够不着。

> **为什么不出厂一个默认值**：[PF-001 明说这些数值「不在产品这一层定」](../PF-001-identity-scope-and-agent-constraints/design.md#未激活的账号记录不会永久占着那个名字)——
> 留多久是这套部署愿意为一个半途而废的注册扣住多久名字，那是部署的事。**出厂一个数，就是产品替部署定了。**
> 代价是立中心时多填几项；换来的是**没有任何一个数是没人决定过的**。
>
> **为什么不做「改了立刻生效」**：那要为每一项定义「改的那一刻正在判的事按新的还是旧的」，而**没有任何本版场景要求中心在改参数时保持在线**。

### 6.16 版本对不上就明说

**中心与客户端版本对不上时，中心明说「版本对不上」，不半通不通。**
[PF-016 已定客户端那一侧的呈现](../PF-016-cli-tui-delivery-surface/flows.md#二分支与异常)；中心这一侧的承诺是：**它不会试着把一个它看不懂的请求猜着办了**。
**这一关先于一切**（[§6.4 ①](#64-无效与答不出是两个不同的答复)）：对不上时只答这一句，不看登录状态，也不区分带没带；只有[体检的公开部分](#中心体检)不受它挡。

中心的版本在[体检](#中心体检)里，登录之前就能读到；运维者升级中心时据此通知同事升级客户端。**哪些版本算对得上**归技术设计。

### 6.17 体检只说部署，不说里面有谁

**[中心体检](#中心体检)的公开部分（在不在、[中心标识](#中心标识)、版本）对任何够得到中心的人可读，登录之前就能读；
完整部分只有[运维者](#运维者)在中心所在的机器上看得到。两部分都不含任何治理事实，也不含任何秘密的值。**

> **为什么公开那三样**：客户端要靠标识分辨[搬家还是另一个中心](#612-同一个中心换了地址还是它另一个中心必须被认出来)、靠版本判断[对不对得上](#616-版本对不上就明说)——
> 而这两件事都发生在登录之前。**多一样都不公开**：账号有几个、组织有哪些，对一个还没登录的人是不该知道的事。

## 七、取舍

| 面临的选择 | 选了 | 为什么 |
|---|---|---|
| 中心**自带一个管理员账号** vs **生来是空的** | **生来是空的** | 自带的那个账号没人注册过、凭据得写在某处、能替任何人做事——**它就是 PF-001 说没有的平台管理员**。而[建组织的人就是它的超管](../PF-001-identity-scope-and-agent-constraints/design.md#组织)，正常路已经把「第一个管理员」答完了 |
| 运维者是**一个特殊账号** vs **握着部署的人** | **握着部署的人** | 特殊账号要在账号体系里开一个不受角色约束的口子；而运维者先于任何账号存在，本来就不能靠账号定义。代价是**运维动作记不到人名下**，靠组织管机器 |
| 运维者**有一点救急的治理权**（重置凭据、请回超管）vs **一点没有** | **一点没有** | 一开口就是不需要登录状态的治理通路。**本版那几条救急路 PF-001 都没开**（[凭据不重置](../PF-001-identity-scope-and-agent-constraints/design.md#非目标)、[组织永远至少一位超管](../PF-001-identity-scope-and-agent-constraints/design.md#角色)），要开得回那边开 |
| 中心的身份**押在密钥上**（不可伪造）vs **一个不是秘密的标识**（跟着数据走） | **不是秘密的标识** | 押在密钥上，丢一次密钥全组织的据点一夜之间成了别人的。**防冒充归传输层**，标识只管「是不是同一个」。代价：标识本身不能证明「真的是它」 |
| 部署密钥**顺便加密数据** vs **什么都不加密** | **什么都不加密**（可被推翻） | 加密了数据，「丢了密钥」就等于「全组织的东西没了」——同类产品最常见的事故。只让中心自己的话伪造不了，丢了就重新生成 |
| **在线轮换**密钥 vs **停着换** | **停着换** | 在线轮换要处理新旧两把同时有效的那一段，而没有任何本版场景要求换密钥时不停机 |
| **能起多少起多少** vs **要么整个起来要么不起** | **要么整个起来要么不起** | 中心拥有的事实彼此咬合，半开的中心给出的每个答案都可能错得很像对的 |
| 重启**全员退出** vs **登录状态照旧** | **照旧** | 全员退出让每次维护变成全公司重新登录，也让逐个撤销失去意义。登录状态的存亡只由它自己的退出与撤销决定 |
| 升级**尽力迁移** vs **要么整体成要么整体不成** | **整体成或整体不成** | 中心装着全组织身份事实的唯一一份；升到一半比停着糟 |
| 中心**知道自己的地址**（像有网页的产品那样）vs **不知道** | **不知道** | 没有网页没有带外通道，中心不生成任何链接。不知道地址，搬家就纯粹是运维者与客户端的事 |
| 部署参数**出厂默认** vs **每项必填** | **每项必填** | PF-001 明说数值不在产品层定。出厂一个数就是产品替部署定了 |
| 部署参数**热更新** vs **重启生效** | **重启生效** | 热更新要为每一项定义改的那一刻怎么判，而没人要求改参数时不停机 |
| 参数变更**按记录产生时的参数**算 vs **按判的那一刻的参数**算 | **按判的那一刻**（可被推翻） | 前者要给每条记录记一份参数，且运维者调短期限时一条已积下的都够不着；后者与过期、到期量中心当下的钟是同一个口径。**已经到期的不因调长而回来** |
| 有一个**关闭注册的开关** vs **没有** | **没有**（可被推翻） | 谁先来没有特殊待遇、账号不能删，一个开关挡不住什么、却给了运维者第一个伸进治理行为的杆子。够不够得到中心由它放在哪决定 |
| 中心**记住客户端**（机器、设备名）vs **只认登录状态** | **只认登录状态** | 记住客户端就有了不经登录状态的路；[登录状态列表本来就带签发时间](../PF-001-identity-scope-and-agent-constraints/design.md#登录状态)，够人分辨了 |

## 九、未决项

| 缺口 | 会改变什么 | 当前已知 | 谁能明确 |
