# PF-003 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

## 一、可观察场景

### 复制

| 场景 | 应当看到什么 |
|---|---|
| 普通成员把个人组织里的一个 skill 复制给自己所在的团队 | 落在**他自己的租户级**，出现一份他的；**不需要管理员批**，也没有待确认的通知；设置页长出对应表单 |
| 同上，但他是这个团队的超级管理员 | 他**可以选**落在组织级或自己的租户级；选组织级，团队组织级出现一份组织的 |
| 普通成员试图把它落在组织级 | **拒绝**，说明组织级由超级管理员管 |
| 复制之后修改个人组织里那份 | 团队那份**纹丝不动** |
| 复制之后团队修改他们那份 | 个人组织那份**纹丝不动** |
| 个人侧发布新版本后再复制一次 | 团队那份产生**新版本并立即生效**，内容整体等于个人侧这一版；本人型**不需要任何人确认** |
| 团队此前在他们那份上改过东西，然后被再复制一次 | 那些改动**不在新版本里**；旧版本仍然查得到、回退得回去 |
| 团队为那份资产配了执行权限，然后被再复制一次 | 配的值**照旧生效**，包括标了 `immutable` 的 |
| 查看团队那份的作者 | 是 **(团队组织, 他)**，不是他的个人租户；源侧那份的作者**没被改** |
| 团队那份的版本号 | **独立从 v1 开始**，与源侧的版本号无关 |
| 复制一个 plugin | 内含的 skill、tool、slash command **一并过去**，各自表单一并出现 |
| 复制的 plugin 引用了目标组织没有提供者的能力标识 | **发起时就被告知缺哪个**，不是等到组装才失败 |
| 落进的那一层里已有一个同能力标识、但**不是**从这个源复制来的资产 | 这次是**新增**，那一份**没被冲掉**；并告知同一能力标识下现在有两份 |
| 超级管理员先把个人组织里的 skill 复制到自己的租户级，之后再复制一次、选组织级 | 组织级**新增**一份组织的；他租户级那份**不动** |
| 之后他再复制一次、仍选组织级 | 更新的是**组织级那一份** |
| 普通成员租户级那份被提升到组织级之后，他再复制一次 | 他租户级**新增**一份；组织那份**不动** |
| 他在 A 公司的**租户级**资产，复制到有共同上级的 B 公司 | **成功**，落在**他在 B 的租户级**，不需要任何人确认 |
| 同上，但他在 B 公司没有成员身份 | **拒绝** |
| 同上，但两家公司没有共同上级 | **拒绝**，并说明它们不在同一条隶属链上 |
| 他试图把 A 公司租户级的资产直接落进 B 公司的**组织级** | **拒绝**——同树跨组织，组织级只能来自组织级 |
| A 公司的超级管理员把 A 组织级的模板复制给同一棵树上的 B 公司 | B 公司收到一份待确认的复制通知；B 的超级管理员确认后，B 的组织级出现一份 **B 自己的**，作者是 **(B, 确认的那位超级管理员)**；此后两边各改各的，互不影响 |
| 同上，B 的超级管理员还没确认 | B 那边**什么都没多出来**；A 可以撤回 |
| 同上，但发起的是 A 公司的**普通成员** | **拒绝** |
| 同上，但 A 与 B **不在同一棵树上** | **拒绝** |
| 任何跨组织的复制或分享，试图落在**别人的租户级** | **拒绝** |
| 试图复制一个草稿 | **拒绝** |
| 试图把任何团队组织的资产弄进个人组织 | **拒绝**，租户级的也一样 |
| 他退出团队组织之后 | 组织级那份留在组织、署名照旧；他租户级那份留在原处、谁也够不着，重新加入后原样可用；他**再也不能以那个租户的名义发起复制或分享** |

### 分享

| 场景 | 应当看到什么 |
|---|---|
| 集团把一个安全组件分享给有共同上级的子公司 | 子公司的超级管理员确认后**能用**，所有权仍是集团的 |
| 集团随后发布新版本 | 子公司用到的**自动就是新版本**，无需任何人操作 |
| 子公司试图修改被分享来的资产内容 | **拒绝** |
| 子公司为它配自己那一层的执行权限 | **允许**——那是他自己那一层的值 |
| 子公司用别的资产把它替换掉 | **允许**。本版的分享不带强制 |
| 子公司移除这个分享 | **允许** |
| 集团撤销这个分享 | 子公司失去获权；**已经开始的调用不受影响** |
| 子公司试图把它再分享给第三方，或复制出去 | **两个都拒绝** |
| 账号 A 把个人组织的 skill 分享给账号 B | **允许，无任何范围条件** |
| 把个人组织里的 skill 分享到**我在团队里的租户级** | **成功**，不需要任何人确认；团队里只有我用得到它 |
| 那一份我试图再分享给团队里的同事，或提升到组织级 | **拒绝**——被分享来的不能再分享、也不能提升；要给同事用，先复制到我的租户级，再分享 |
| 试图把个人组织里的资产**分享**到团队的**组织级** | **拒绝**——个人组织进团队组织级只有复制，且只有超级管理员 |
| 试图把团队组织的资产分享给任何个人组织 | **拒绝** |
| 把我租户级的工具分享给同组织的一位同事 | 他收到一份待确认的分享邀请；**他确认之后能用**，不能改；我发了新版本，他**自动用上** |
| 同事还没确认 | 他的可用集合里**没有它**；我可以撤回 |
| 同事试图把它再分享给第三个同事 | **拒绝** |
| 同事退出组织 | 这段分享**结束** |
| 同事后来重新加入 | **不复活**——他用不了，要我再分享一次、他再确认一次 |
| 我退出组织 | 我分享给同事的那段**结束** |
| 试图把组织内分享发给不在本组织的人 | **拒绝** |
| 超级管理员想让某份组织级资产给一部分人用 | 没有「分享」这个动作——配那份资产的「谁可以使用它」 |
| 一份待确认的分享邀请放到过期 | **确认不了了**，被分享方的可用集合里**从头到尾没有过它**；分享方可以重新发一份 |
| 一份待确认的复制通知放到过期 | 同上——目标组织里**什么都没多出来** |
| 邀约发出之后，源侧那份资产被移除 | 那份邀约**自动过期**，接收方看到的是「已失效」 |
| 已经确认过的分享 | **不过期**——过期只管确认之前那一段 |
| 被分享方查看它的版本 | 他选用的是「**分享方当前发布的那一版**」这个动态目标，不是某个固定版本号 |
| 被分享方想钉在某个版本上 | **没有这个选项** |
| 用被分享来的资产产生的成本 | 算在**使用方**的租户头上 |

### 关系变化

| 场景 | 应当看到什么 |
|---|---|
| 隶属关系解除，此前 A **分享**给 B 的东西 | **失效**，向后生效，不强停正在跑的工作 |
| 隶属关系解除，此前 A **复制**给 B 的东西 | **留着**。B 照常使用、照常修改 |
| 隶属关系解除之后，两家又重新建立隶属 | 此前的分享**不复活**；要用，A 再分享一次、B 再确认一次 |
| B 已有上级，试图接受第二个上级 | **拒绝**，提示需先解除 |
| 接受之后会形成环 | **拒绝**，说明两者已在同一条隶属链上 |
| 一方单方面把另一方设为自己的下级 | **不存在这个动作**。必须两边的超管各做一次 |
| 任一方单方面解除隶属 | **允许** |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 团队组织里的任何资产出现在任何个人组织中 | 那条不变量被绕过了。**资产流失** |
| 有某条路径（导出、另存模板、打包下载）能把团队资产弄到个人组织 | 同上。不变量是系统级的，不是某个动作的规则 |
| **任何路径把资产写进别人的租户级**——资产复制只落发起者自己的租户级或组织级，组织内分享要那个人自己点头才进来 | 一个人的私有部分被外人写了东西。跨组织时，那个组织也没点过头 |
| 一次复制把目标那边**配好的权限值**冲掉 | 覆盖越界了。**安全事故** |
| 一次复制把目标那边**自己做的同名组件**冲掉 | 判据用错了——血缘才是判据，不是能力标识。**安全事故** |
| 组织级的资产被**普通成员**复制或分享出去 | 组织的财产由一个没有治理权的人处置了 |
| 普通成员带进来的东西，不经超级管理员就出现在**组织级** | 组织级的门没人守 |
| 组织型复制或组织—组织分享，**没经目标组织的超级管理员确认**就落下了 | 一个组织单方面往另一个组织里塞了东西 |
| 复制之后源侧一改，目标侧跟着变 | 那不是复制，那是分享。两个动作被混成一个 |
| 被分享方能改分享来的资产内容 | 所有权失去意义 |
| 被分享方能把它再分享给第三方，或提升到组织级 | 一次转手就绕开了边界，流动路径再也追不清 |
| 隶属关系解除后，**复制**过去的被收回 | 能被收回的所有权不是所有权 |
| 隶属关系解除后，**分享**出去的还能继续用 | 范围条件已经不成立，边界形同虚设 |
| 一段已经结束的分享，在关系重新接上之后**自己恢复了** | 替双方重新点了头——而那个头可能早就不想点了 |
| 一个组织的管理员**单方面**就能建立隶属关系 | 他一个人推开了资产流动的边界。**那是后门，不是隶属关系** |
| 个人组织出现在某条隶属链上 | 一个人的私域被纳入了公司治理 |
| 同一份资产在源侧与目标侧共用一个实体 | 复制的 fork 语义没实现 |
| 复制或分享让 agent 的运行语义发生变化 | 这两个是治理层动作，agent 不该感知 |
| 一份过期的邀约还能被确认 | **过期就不是一个答复了**，而接收方点下去的那一刻，谁也说不清发起方现在还想不想给 |
| 一份指向已不存在的资产的邀约还挂在接收方那里 | 确认下去**当场失败**，而失败发生在他点头之后——他会以为是系统坏了 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 复制是 fork | 复制完之后改源侧，目标侧**逐字节不变**；反之亦然 | 任何一侧的改动影响了另一侧 |
| 重复复制是全量覆盖 | 目标侧先本地改一处，再复制一次，新版本里**那处改动没有了**，而旧版本里**还在** | 出现了合并结果，或旧版本被改写 |
| 覆盖不碰配置 | 目标侧配一项权限并加锁，再复制一次，**那一项照旧生效** | 配的值被冲掉或被重置 |
| 复制血缘是唯一判据 | 目标侧放一个同能力标识、无血缘的资产，复制一次，**它还在** | 它被冲掉了 |
| 血缘只在落进的那一层里找 | 同一个来源先落租户级、再落组织级，**两份并存**；再往任一层复制，**只动那一层那份** | 另一层那份被覆盖，或第二次落层被当成重复 |
| 确认由落进那一层的管理者做 | 本人型复制与分享**发起即成**；组织型与组织—组织分享**只有目标组织的超级管理员**点得了确认；组织内分享**只有接收的那个人**点得了 | 本人型还要别人批，或别人替接收方点了头 |
| 普通成员落不了组织级 | 普通成员从个人组织复制进团队，**只能选自己的租户级**；强行指定组织级被拒 | 普通成员带进来的东西出现在组织级 |
| 跨组织落不到别人的租户级 | 构造「T 里我的租户级 → T′ 里别人的租户级」的复制与分享，**都被拒** | 有一条通了 |
| 待确认的邀约会过期 | 发一份复制通知与一份分享邀请，**都放到过期**，各自**确认按钮按不下去**，且**什么都没建立**；发起方重发一份，新的那份照常能确认 | 邀约一直挂着，半年后照样能确认 |
| 资产没了就自动过期 | 发出邀约之后**把源侧那份资产移除**，那份邀约**随即失效**，接收方看到的是「已失效」而不是确认之后的一个失败 | 确认得下去，然后当场失败 |
| 分享是被动同步 | 分享方发新版本，被分享方**不做任何操作**就用上了新的 | 需要对方确认，或对方仍停在旧版本 |
| 分享不带强制 | 被分享方能收窄权限、能替换、能移除，**每条路径都通** | 有某条被系统拦住 |
| 分享不可传递 | 被分享方尝试再分享、复制、提升，**三条路都被拒**；组织内被分享来的也一样 | 有一条通了 |
| 结束的分享不复活 | 组织内分享之后让同事退出再加入、跨组织分享之后让两家解除再重新隶属，**两种情形他都用不了**，直到分享方再分享一次 | 关系接上，旧的分享自己回来了 |
| 边界是那棵树 | 构造「无共同上级的两个组织」，分享与复制**都被拒**；构造「有共同上级」，组织—组织的分享与复制通、我自己两个租户之间的复制与分享通 | 判据退化成"是不是团队组织" |
| 个人组织永远在树外 | 尝试给个人组织设上级、或让它当别人的上级，**都被拒** | 有一条能设上 |
| 隶属必须双方同意 | 只有一方动作时关系**不成立** | 单方面就建上了 |
| 解除的效果分得清 | 解除后检查：分享来的**用不了**，复制来的**照常用** | 两者结果相同 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| 上级组织强制下级必须用某个资产、不许替换 | 本版**刻意不做**。隶属是事实陈述，不附带管辖权，见 design.md §2 |
| 被分享方钉在某个版本上 | 本版**刻意不做**。钉住就是要一份 fork，那个动作叫复制 |
| 一个组织有两个上级组织 | PF-001 定的是「至多一个」。要表达合资，需要的是关系表而不是属性 |
| 冲突探测、三方合并、版本线分叉 | 复制语义是全量覆盖替换，没有"合"这个动作 |
| 租户级提升到组织级 | 归 [PF-001 §6.7](../PF-001-identity-scope-and-agent-constraints/design.md#67-创作与归属) |
| 组织级资产在本组织里给谁用 | 归 PF-002 的「谁可以使用它」 |
| 隶属关系本身怎么建立、怎么解除 | 归 [PF-001](../PF-001-identity-scope-and-agent-constraints/flows.md#17-建立与解除组织隶属)，那是组织属性的事 |
| 资产怎么创作、修订、发版、上架 | 归 PF-002 与开发发布流程 |
| 「源侧有更新」的提示 | 本版**刻意不做**，它会暴露源侧的活动 |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
