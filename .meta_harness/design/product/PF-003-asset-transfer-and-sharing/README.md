# PF-003：资产的复制与分享

**[PF-002](../PF-002-assets-settings-and-permissions/README.md) 说清了一个范围持有资产
之后会发生什么，但没说资产**怎么到一个范围里来**——从一个组织到另一个组织，从一个成员到另一个成员。本 topic 回答这个问题。**

一句话概括本 topic 的结论：**在主体之间流动有两种根本不同的需要，所以有两个动作。**

> **第一个动作的正式名是[资产复制](../../ubiquitous_language/terms/circulation-and-entitlement.md#ul-asset-copy--资产复制--asset-copy)**，
> **不叫「转移」**——**源侧不消失**，它的实质是 fork 一份。
> **目录名里的 `asset-transfer` 是旧拼写**，不改：改目录会牵动全仓的链接。

| | **资产复制** | **分享** |
|---|---|---|
| 是谁的动作 | **本人型**：同一自然人的两个租户身份之间；**组织型**：同一棵树上两个团队组织之间 | **所有者**的授权 |
| 对方可以是 | 我自己在另一个组织的租户；同树的另一个团队组织 | 另一个组织；或一个租户——**本组织的同事（组织内分享）**、我自己在另一个组织的租户 |
| 所有权 | 落下的那一份独立拥有，落在哪一层归谁 | 不动，仍属分享方 |
| 此后 | **断链**，各走各的 | **被动同步**，源方改了就跟着变 |
| 关系断了 | **留着** | **失效**；关系再接上也**不复活** |

最后一行是使用者最该记住的：
**你要不要让对方在关系结束之后还能用，决定了你该复制还是该分享。**

谁和谁之间能走哪个动作，是[一张逐格的方向表](design.md#62-谁能流向谁)。
**要点三条**：组织内，所有者可以把自己的资产开放给任何一个同事，对方自己决定用不用；
同一棵树上跨组织，只有组织—组织；自己的资产可以复制或分享到自己在另一个组织的租户下，只要不是团队到个人、不跨树。

**跨主体的都要对方确认**——由东西要落进的那一层的管理者点头；**本人型两侧都是自己，不需要第二个人**。
**确认之前那份邀约会过期**——**两类各有默认时长，发起时发起方可以指定这一份的**；
**被它指向的那份资产不在了，它随即自动过期**（[§6.14](design.md#614-待确认的复制通知与分享邀请会过期)）。

两者共同遵守一条系统级不变量：**团队组织里的资产不出那棵隶属树**，
一律不得进入任何个人组织。

**与 PF-001 的分界**：组织怎样隶属、关系怎么建立解除，归 PF-001——那是组织**属性**的事。
关系成立或断开之后**资产**怎么样，归这里。

**与 PF-002 的分界**：资产有哪几类、怎么组合、怎么配、怎么求值，组织级资产在本组织里谁能用，归 PF-002；
它**怎么在主体之间流动**，归这里。判据是**改动它的原因**——
PF-002 因对象的种类或组合形状变，本 topic 因流动的方向或语义变。
