# PF-001 验收标准

[design.md](design.md) 说这块产品是什么，本页说**做成什么样算做对了**。
这里的每一条都应当能交给不懂实现的人去判断。

## 一、可观察场景

| 场景 | 应有表现 |
|---|---|
| 新用户在已有部署上注册 | 取得独立账号，同时有了自己的个人组织，可立即开始使用 |
| 同一台部署上的第二个人注册 | 与第一个账号彼此独立，看不到对方任何个人数据 |
| 注册中途失败后用同一个名字重来 | 能接着完成，不会说"这个名字已经被占用了" |
| 注册中途失败，**在留存期限内**用同一标识、同一凭据重来 | **认回的是同一条未激活记录**，接着走完剩下的步骤即可激活；不是新建一个账号 |
| 注册中途失败，**过了留存期限**之后另一个人用那个标识注册 | **注册得成**——那条未激活记录已被清除，登录标识已经释放，**为它建的个人组织与第一个租户也一起没了** |
| 激活**已经提交**、成功回执却没送达，用户再发起一次注册 | 看到「这个名字已经有人用了」；**他的账号其实已经可用**，持凭据直接登录即可，不需要任何补救动作 |
| 用户在一台设备上登录之后，想知道自己账号上还有哪些登录有效 | **列得出全部有效的登录状态，每一个带签发时间**——持本账号任一有效登录状态就能列 |
| 用户在这张列表上撤销其中一个登录状态 | **只有被指定的那一个失效**，其余（包括他正在用的这一个）照常有效 |
| 同一现实人持有两个账号，其中一个加入组织 O | 另一个账号**不因此**取得 O 的任何资产、权限，其使用成本也不并入 O |
| 用户创建一个组织 | 立刻就是这个组织的超级管理员，不需要再找人授权 |
| 用户在自己的个人组织里想邀请别人 | **没有这个入口**，不是"点了之后被拒绝" |
| 一份加入组织的邀请放到过期 | **接受不了了**，成员关系与租户**从头到尾没产生过**；重新发一份即可 |
| 一份隶属请求放到过期 | 同上——**关系没建立**，重新发起一份。它是**另一种对象**，接受它也不会产生任何租户 |
| 发出邀请的那个组织不存在了 | 那份还没被接受的邀请**自动过期**，对方看到的是「已失效」，而不是接受之后的一个失败 |
| 发起者发出邀约时**指定了有效时长** | 这一份**按他指定的那个时长**过期；**同时发出的、没指定时长的那些，各按自己那一类的默认值**过期。两份邀约的到期时刻可以不同 |
| 组织有一项共享技能，两个成员角色不同 | 用的是同一份组织资产；能不能编辑、发布按各自权限判定 |
| 用户仅在个人范围获权使用某资产，随后进入组织协作 | 组织操作**不能借用**个人的使用权，需要该组织自己的依据 |
| 同一官方定义被个人与两个组织选用 | 官方所有者保持可辨；各范围的使用权、所选版本与权限**分别生效** |
| 成员在组织范围创作了一个 Plugin，之后离开组织 | 作者事实保留；**组织资产不跟人走**；后续操作按最新成员权限 |
| 成员退出组织之后，又被这个组织重新邀请回来 | 回来的是**同一个租户**：他先前在这里的**租户级自定义资产与各项配值原样可用**，不需要重建；离开期间那些东西**谁也访问不到**，但也**没有被删掉** |
| 组织设了某项权限的上限，成员在自己租户级想调高 | **调不上去**。权限取各层交集，组织的上限是不可突破的边界 |
| 组织超管调整组织配置与成员权限 | 在该组织范围生效且可审计；**看不到**成员的个人设置与私人会话 |
| 用户清除自己的某项设置覆盖 | 按该项规则重新求值并显示依据；清除不等于关闭，也不固定恢复旧出厂值 |
| 管理者移除被日程或 agent 引用的资产 | 说明依赖影响与处置；**不暗中删除日程、不替换定义、不强停正在运行的会话** |
| 两个管理入口同时修改同一草稿 | 后提交的旧修改**不覆盖**已确认的新内容，给出可理解的冲突与恢复结果 |
| 成员被移出组织，此时他有一个任务正在跑 | 任务不被强制中止；但他接下来发起的新操作会被拒绝 |
| 用户在两个组织之间切换 | 账号身份不变；两边的设置、权限、可用技能各是各的，互不沾染 |
| 用户在组织 O 下建了一个会话，随后把当前组织切到 P | 那个会话**仍然算在租户 (O, 该账号) 头上**：成本、归属与可用资产一概照 O 算。**切换只对此后新建的东西生效** |
| 两位超级管理员在不同地方**同时**移除或降级对方 | **先成的一方成功，后成的一方被拒**，且看到的提示与单次被拒时**完全相同**；组织始终有超管 |
| 一位**普通成员**打开自己所在组织的成员名单 | **看得到**：这个组织有哪些成员、各持什么角色。名单**只有这个组织这一层**——别人在别的组织里有什么，这里一个字也没有 |
| 同一位普通成员想看这个组织**发出的邀约**或**收到的隶属请求** | **看不到**。那两样只有超级管理员看得见；他**没有**任何可以对它们做的动作 |
| 一位成员被移出组织之后，另一位**普通成员**再打开同一份名单 | 名单里**没有这个人**：普通成员取到的名单只含有效成员，**看不出这个组织解除过谁**。同一时刻**超级管理员**能把已解除的那些一并看到——那是管理成员要用的一面 |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 未激活的账号能登录或做任何事 | 一个没有自己空间的账号进了系统，用户以为注册成功了却什么也做不了 |
| 账号上有一个有效的登录状态，持有者**在列表里看不到它** | 看不见就撤销不了。一个丢了回执留下的登录状态会一直有效下去 |
| 一条未激活的记录**永久占着那个登录标识** | 一次半途而废的注册把一个名字永远拿走了，发起者自己也什么都没得到 |
| 退出登录后，重启系统又能用旧登录态访问 | 用户以为自己退出了，实际没有。**安全事故** |
| 成员在自己的租户级设一条权限，突破了组织设的上限 | 成员给自己提权。**安全事故** |
| 超级管理员能读到成员个人范围的资产、设置或私人会话 | 管理权越界到私人空间 |
| 本组织的成员名单**只有超管看得到** | 普通成员不知道自己在跟谁共事，分享给谁、请谁接手都无从下手 |
| 从成员名单里能读出某个人**在别的组织里**的成员关系 | 一次组织内的读取跨过了租户隔离 |
| 普通成员从成员名单里读出**这个组织解除过谁** | 组织的人事变动被摊成了日常可见的东西。**已解除的那些只给超级管理员看** |
| 一个账号的数据、余额或权限，因为"背后是同一个人"而流入另一个账号 | 隔离模型失效 |
| 仅凭文件放在同一块磁盘、同一个目录或同一个系统用户，就能访问别人的东西 | 隔离靠的是身份判定，不是物理位置 |
| 组织失去最后一位有效的超级管理员 | 这个组织再也没人能管理，成了死组织。**两次同时发生的动作各自看都合法、合起来把超管清空，同样算发生** |
| 账号切换当前组织之后，先前建起来的东西跟着换了租户 | 归属漂移：同一个会话的成本、可见性与权限跟着账号当前站在哪里跑，**「归谁」不再是一个稳定的答案** |
| 成员退出组织时，他在这个组织里租户级的自定义资产与配值被清掉 | 一次成员关系的断续把归属蒸发掉了；他被请回来时，那些东西再也拿不回来 |
| 注册、登录失败却显示成功，或把数据接进了另一个账号 | 用户对自己是谁产生错误认知 |
| 从反馈差异能试探出某个标识是否已注册 | 账号存在性泄漏 |
| 超级管理员把某个 official 资产**禁掉**，使该能力标识下什么都不剩 | agent 组装不出来了。official 是最小必需，可被替代但不可被清空 |
| 一个 customized 资产因为被 agent 使用，就让作者或该 agent 多了行动权限 | 资产与权限串味。资产决定组装，权限决定行动 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 注册的提交点在激活 | 在第 1、2 步之间任意位置中断，检查结果：要么账号可用且有个人组织，要么没有可用账号。**不存在第三种** | 出现"有账号但没有个人空间"的用户 |
| 登录标识部署内唯一 | 两个人用同一个标识注册，第二个必然失败 | 两个账号同名，登录时无法确定是谁 |
| 账号存在性不泄漏 | 用不存在的标识、错误的凭据、未激活的账号分别尝试登录，三次反馈**完全一致** | 反馈有差异，可据此枚举账号 |
| 权限收窄 | 组织设上限 N，成员在租户级设 N+1，实际生效仍是 N | 生效成了 N+1 |
| 退出的持久性 | 退出后**重启系统**，再用旧登录态访问，被拒绝 | 重启后又能访问 |
| 退出的作用范围 | 在设备 A 退出，设备 B 上同一账号的登录**仍然有效** | 一处退出把别处也踢下线 |
| 有效登录状态列得全 | 同一账号在三台设备登录，在任一台上列出，**三个都在，各带签发时间**；撤销其中一个之后再列，**只剩两个** | 列不全、列出已失效的，或撤销一个把别的也带掉 |
| 「有共同上级」把自己算进来 | 团队 T 的上级是公司 C：判 **T 与 C 有共同上级**得到**真**；再取两棵不同隶属树上的组织，得到**假** | 团队与它自己的公司被判成"不同树"，同一棵树内本该允许的流转被挡掉 |
| 未激活记录到期释放标识 | 注册到第 1 步就停手，等过留存期限，再用那个标识注册：**成功**，且得到的是一个全新账号与**全新的个人组织**——**上一条记录为它建的个人空间也不留下** | 那个标识一直报"已被占用"；或标识放出来了，**上一条记录的个人组织与租户还挂在那儿**，新账号拿到的是别人用过的空间 |
| 成本按租户归属 | 同一账号在两个组织各发起一次调用，两笔成本分别算在两个租户上，明细可逐条列出 | 成本算到账号头上，分不出是哪个组织的 |
| 角色变更不动归属 | 成员创建若干资产后角色被调整，那些资产的归属不变 | 资产换了主人或成了无主 |
| 个人组织不可邀请 | 在个人组织中找不到邀请入口 | 有入口但点了报错——那说明它被实现成了权限判定 |
| 组织必有超管 | 尝试移除唯一的超级管理员，操作被拒绝且不产生部分效果。**并发地让两位超管同时移除或降级对方，只有先成的一方成立**，后成的一方被拒且提示与单次被拒相同 | 移除成功，组织无人可管；或两次动作各自看都合法、合起来把超管清空了 |
| 切换组织不串味 | 切换前后，各层的事实集合都不因切换本身增减；账号的身份事实不进入任何一层 | 某一层多出或少了东西 |
| 租户身份在创建那一刻捕获 | 在组织 O 下创建一个会话，切换到 P，再查那个会话的归属与成本：**仍然是 (O, 该账号)** | 归属随账号当前所在的租户漂移 |

## 四、本版不验收的

| 不验收 | 原因 |
|---|---|
| 账号注销与永久关闭 | 产品负责人明确本版不要求 |
| 组织解散 | 同上 |
| 账号恢复，以及**凭据的一切写路径**（重置与主动更换都算） | 产品负责人明确本版不做，见 [design §2 非目标](design.md#非目标)。**不是"未定"**——本版没有改凭据的动作，也不该为它预备入口 |
| **一次撤销全部登录状态** | 本版不做。逐个撤销已经够用，见 [design §4 登录状态](design.md#登录状态) |
| **未激活记录留存期限的具体数值** | 按部署配置，产品这一层不定数值。要验收的是**到期清除、标识释放、期限内认回同一条**这三件事 |
| 超管与普通成员之外的中间角色 | 精确角色矩阵未定 |
| 注册的限流与滥用防护 | 本版视为部署运维关注点 |
| 资产怎样在组织之间主动流动 | 本 topic 只确认"不自动流入"与组织的隶属属性；转移与分享归 [PF-003](../PF-003-asset-transfer-and-sharing/README.md) |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。
