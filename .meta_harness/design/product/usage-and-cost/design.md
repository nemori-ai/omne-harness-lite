# 用量与花费产品设计

采用范围见[topic 入口](README.md)。项目要求取 [requirements](../../../../docs/requirements.md)，责任边界取[用量与花费领域](../../../../docs/domains/usage-and-cost/README.md)。本文维护已确认的产品规则，工程机制由技术拥有者说明。

## 产品需求描述

一个人用了一段时间之后，会想知道三件事：这段时间用了多少，钱花在了哪里，眼前这个会话还能装多少。现在这些数只挂在每一次调用上，要一次一次去查。用量与花费把它们合起来给人看。

它只做统计和展示。每一笔用量与费用仍归产生它的一方：模型调用的归[模型调用](../model-invocation/design.md)，工具执行的归[工具执行](../tool-execution/design.md)。用量与花费不改这些事实，不估算，不替任何一方记账。

它是接在核心上的一块。一个部署没有开放它，会话、agent、模型与工具照常工作，只是没有这些面板。之后再开放，此前的用量照样看得到。

### 看哪个范围

范围有两个。一个会话：这个会话引起的全部模型调用与工具执行，包括为它做的上下文压缩。一个租户：这个租户的全部会话，加上不属于任何会话的调用。

租户看自己的。看得到用量与花费，不等于看得到请求、回复、附件或秘密。组织管理员查看全组织的账目是[模型调用](../model-invocation/design.md#成本隐私与性能)已定的资格，那一层的面板不在本题目的当前范围里。

子会话各算各的。归档、取消、清理都不减少已经记下的用量与花费。

### 看到哪些数

基础的数是每一笔事实上本来就有的：各类 token（输入、输出、缓存读、缓存写、推理）、费用、请求数与真实发出数、时长、工具执行的次数与时长。

导出的数由基础的数算出，定义写明分子分母：

- 缓存命中率：缓存读除以全部输入（未缓存的输入、缓存读、缓存写之和）。
- 推理占输出的比例。
- 重试率、失败率、中断率。
- 首字延迟与整次耗时的中位数和九成位数。
- 输出速度：输出的 token 除以从首个内容到收场的时间。

费用是供应商报回的实际数，不是按价目估算的。供应商没报的费用是未知。合计只加已知的，同时说明有几笔未知，不把未知当零，也不把合计说成完整的。单位不同的不相加，各自合计，单位名照供应商声明的显示。费用只到每次发出的总额，不拆到输入、输出或缓存上，因为供应商只报一笔。

### 怎样切开看

可以按时间段看，并把时间段切成小时、天、周或月。日期的边界按看的人自己的时区算。可以按模型、按供应商、按调用的用途（主循环、压缩、扩展、工具动作）、按来源（模型调用还是工具执行）切。任何切法，各部分加起来等于不切的合计。

### 这个会话还能装多少

会话里显示上下文占比：最近一次主循环请求送给模型的全部输入，占当时所用模型窗口的多少，并标出自动压缩的位置。它让人心里有数，不求实时与精确：它是截至上一次请求的数，压缩或换模型之后要等下一次请求才更新，界面照实写明。还没有请求时不显示数。

### 在哪里看

「用量」是应用里单独的一页，看整个租户。在一个会话里，右侧边栏有这个会话的用量，输入框下方的状态栏有上下文占比。会话里的这两处由用量放进会话留出的位置，会话自己不认识用量。

### 面板可以自己配

面板由卡片组成，原生的以图为主。人可以改四样：

- 组合：面板上放哪些卡片。
- 排列：卡片的次序与宽度。
- 图表类型：同一份数据换一种画法，例如把堆叠柱换成折线。
- 渲染方案：用别人带来的画法或卡片。

原生的卡片、画法和别人带来的是同一种东西，面板上出现什么只由这份配置决定，没有哪一张被悄悄盖掉。配置里的一张卡片不可用了（带来它的模块不在了），那个位置写明不可用，别的卡片不受影响。人随时可以恢复缺省。

别人带来的卡片按公开的协议自己取数据。当前只支持随应用一起装配的界面模块；在运行中装入第三方的界面模块不在本题目的当前范围里。人对面板的改动存在本机。

### 关键用户旅程

#### J-UC01 看这个会话花了多少

用户在一个会话里打开右侧边栏的用量。看到这个会话到现在的费用、各类 token、请求数与缓存命中率，以及按时间的走势。把走势切成按模型或按用途。有一笔费用还不知道时，合计旁边写明另有一笔未知。

此旅程使用 CAP-UC01、CAP-UC02、CAP-UC03、CAP-UC05。

#### J-UC02 看我这段时间用了多少

用户打开「用量」页，选最近 30 天，按天看。看到费用与 token 的合计、每天的走势、各模型的占比与逐模型的明细。换成按周，或换一个时间段。日期的边界按用户的时区。

此旅程使用 CAP-UC01、CAP-UC02、CAP-UC03、CAP-UC04、CAP-UC05。

#### J-UC03 心里有数：这个会话快满了没有

用户在输入框下方看到上下文占比和自动压缩的位置。发了一条消息、模型答完之后，占比更新。换了模型之后，占比仍是上一次请求的，界面写明「截至上一次请求」。

此旅程使用 CAP-UC06。

#### J-UC04 流断了的那一次，费用后来补上了

一次回复生成到一半，用户中断了它，或服务重启了。这一次的费用起初是未知。供应商事后报得出时，费用补到原来那一次上，面板上的未知少一笔，合计相应变多。供应商报不出时，它一直是未知，不变成零。

此旅程使用 CAP-UC02、CAP-UC03；费用怎样补归[模型调用](../model-invocation/design.md#每次真实发出和失败)。

#### J-UC05 把面板配成自己要的

用户进入编辑：去掉用不到的卡片，把费用的走势挪到最前，把它从堆叠柱换成折线。之后每次打开都是这个样子。开发者写一个界面模块，带来一种新的画法和一张新的卡片，用用量的公开协议取数据；装配进应用之后，用户可以在编辑里选它们，部署也可以把它们放进缺省的配置里换掉原生的。

此旅程使用 CAP-UC07、CAP-UC08。

#### J-UC06 部署不开放用量

运维停用用量。应用里没有「用量」页，会话里没有那两处。会话、模型与工具照常。之后再启用，此前的用量都在。

此旅程使用 CAP-UC09。

## 能力定义

| 能力标识 | 定义与范围 | 需求位置 |
| --- | --- | --- |
| CAP-UC01 范围 | 按一个会话或一个租户统计；会话的范围含为它做的压缩；子会话各算各的；租户只看自己的 | J-UC01、J-UC02 |
| CAP-UC02 基础的数 | 各类 token、费用、请求数与发出数、时长、工具执行的次数与时长；都取自产生方的事实，不估算 | J-UC01、J-UC02、J-UC04 |
| CAP-UC03 未知与单位 | 未知不当零；合计只加已知的并说明未知几笔；单位不同不相加、不换算；费用不拆到用量的种类上 | J-UC01、J-UC02、J-UC04 |
| CAP-UC04 时间段与时区 | 按时间段看，切成小时、天、周、月；边界按看的人的时区；不写时区的请求被拒绝 | J-UC02 |
| CAP-UC05 切分与导出的数 | 按模型、供应商、用途、来源切；各部分之和等于合计；导出的数定义写明，比率由合计算 | J-UC01、J-UC02 |
| CAP-UC06 上下文占比 | 最近一次主循环请求的全部输入占当时模型窗口的比例，带自动压缩的位置；写明截至哪一次；没有时不显示数 | J-UC03 |
| CAP-UC07 公开的数据 | 统计、逐笔的记录与上下文占比经公开协议读取；只有数与标识，没有正文；每次读取核当前资格 | J-UC05 |
| CAP-UC08 可配置的面板 | 卡片、画法、布局三样分开；人可以改组合、排列、图表类型与渲染方案；原生的与带来的同一机制；不可用的卡片照实标出；可恢复缺省 | J-UC05 |
| CAP-UC09 可装卸 | 不开放时核心照常；再开放时此前的用量都在；归档、取消、清理、重启都不减少已记下的用量 | J-UC06 |

## 未决问题与待定事项

### 组织范围的面板

组织管理员查看全组织账目的资格已由身份与模型调用的正文确定。数据的形状与查询为它留了位置。面板与资格的接线尚未定义，不能据此认定管理员已经可以查看。责任由用量与身份的拥有者承担。

### 运行中装入第三方界面模块

当前只支持随应用装配的界面模块替换图。运行中装入、隔离与安全边界是界面外壳的一项新能力，尚无产品规则。本项不是待裁决的产品选择，是明确的非目标。

### 预算与提醒

花费的上限、超额提醒与自动停止不在本题目里。项目当前不选额度与预算。
