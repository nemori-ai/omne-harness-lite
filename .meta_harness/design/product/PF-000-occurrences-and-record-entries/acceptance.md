# PF-000 验收标准

**本 topic 给的是一个判断和一组标记，所以验收不看流程，看两样：
拿真实的事走一遍能不能走通，以及那些不合法的组合有没有真的被挡住。**

---

## 一、可观察的场景

| # | 场景 | 通过的样子 |
|---|---|---|
| **S1** | 任取[校准表](design.md#56-校准表拿真实发生过的事走一遍)里的一行，交给两个互不通气的人 | **两人填出同一个答案**，包括「零条」那两行 |
| **S2** | 一次请示发出去、人答复了 | **两条条目**：请示那条是瞬态·可否决，答复那条是依据。**结论被记下来了**（[K1](design.md#61-k1能干预的必须留下结论)） |
| **S3** | 一次运行跑到一半，承载它的 agent runtime 被回收，之后恢复 | **决定下一步的依据全都还在**——没有一条把寿命挂在实例上（[K2](design.md#62-k2依据的寿命不得短于要靠它重建的那个对象)） |
| **S4** | 一名成员被移出租户，当时没有任何会话在跑 | **照样留下一条依据条目**，寿命宿主是租户。[没有会话的系统工作同样可观测](../../foundation/observability-and-logging/requirements.md) |
| **S5** | 一次工具执行发出去，之后进程崩了，回音永远没来 | **那条条目的「外部效果确定性」是「不可确定」**，不是「失败」，也不是没有终态 |
| **S6** | `Computer()` 的旧截图超出预算 | **一条新条目都不产生**——[翻块上那一位](../PF-010-context-management-and-assembly/design.md#57-压缩能做的只有两件事)，**记录里的块一条没少，人照样看得见** |
| **S7** | 有人要给寿命宿主新增一个取值 | **他答得出「它什么时候不在了」**；答不出就不是寿命宿主 |

## 二、绝不能发生的事

| 绝不能 | 为什么 |
|---|---|
| **一条能改写或否决的瞬态条目，没有任何条目记下它的结论** | 恢复之后重算会得到与当时不同的结果，**而且没人看得出来哪里不一样** |
| **决定某次运行下一步的依据，寿命挂在 agent runtime 上** | 实例可回收可重建。挂错了，**恢复时依据已随实例一起没了** |
| **某条恢复路径的唯一依据是一条瞬态条目** | 瞬态按定义可丢。**那条路径只在不崩的时候成立，而它存在的全部理由就是应对崩溃** |
| **把「持久」读成「模型看得见」** | **绝大多数留下来的东西模型根本不看。**混起来会在两个方向同时出错 |
| **为了让一条事实能实时送达，给它配一个实时孪生条目** | **一条持久条目本来就能实时送达。**两条迟早不一致，而且没人知道该信哪条 |
| **寿命宿主的取值里出现功能领域**（「工具」「文件系统」「审批」） | 它们答不出「什么时候不在了」。**填进来等于把被否决的那套分法换个名字请回来** |
| **靠名字前缀推断一条条目的效力或寿命** | 等于把分类藏进命名约定，**而命名约定没人校验**。一个字母之差、含义相反，读的人分不清 |
| **方程从「只为解释才留的」条目里取状态** | [PF-012「方程不去别处取状态」](../PF-012-agent-loop-and-run/design.md#52-会话日志是唯一的真相来源)当场破功 |
| **只记成功与失败，没有「不可确定」** | [不得以缺少终态记录冒充仍在运行](../../foundation/observability-and-logging/requirements.md) |
| **本 topic 里出现「存哪、存几份、留多久」** | 那是技术设计，且[已确认的系统约束明文不预选](../../foundation/observability-and-logging/requirements.md) |

## 三、判据

**怎么算这块设计站得住：**

1. **校准表里每一行，两个互不通气的人填出同一个答案。**
   填不一致的那一行，说明**判据还有洞**，不是那两个人的问题。
2. **任取一个已有 topic 里的十件事，全都放得进来**，且没有一件需要
   「既是这个又是那个」。
3. **三条禁格每一条都举得出一个真实会违反它的做法**——
   举不出来的禁格是想象出来的，应当删掉。
4. **「给谁看」一个字都没有在本 topic 里被重新定义。**
