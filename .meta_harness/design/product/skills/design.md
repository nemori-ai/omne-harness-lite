# Skill产品设计

状态：产品设计草案，revision 10。尚无整体接受证据。落位不授予运行支持。技术承接从[包组规格](../../../../packages/skills/SPEC.md)展开。

## 产品需求描述

Skill 是可复用的工作方法。它告诉 agent 遇到一类事情该怎样做。一个 Skill 是一个目录，入口文件 `SKILL.md` 给出名称、说明与正文，目录里还可以有参考资料、模板和脚本。名称辨认方法，说明回答何时使用，正文解释步骤与条件；三者不能用目录名或一句工具调用替代。

Skill 按三层披露，用到才读下一层。第一层是名称与说明，取自 `SKILL.md` 的头部，常驻时一直在模型面前，不常驻时出现在搜索结果里。第二层是 `SKILL.md` 的正文，模型决定用这个 Skill 时读。第三层是目录里别的文件，正文指到、模型需要时按目录里的路径读。Skill 可以组合 Tool，组合和依赖沿资产规则成立，不从文字中的每个名字递归扩张装配，也不把 MCP 对端动作造为独立资产或 Skill 组合成员。需要外部服务时沿既有依赖语义声明，不能凭这份声明取得服务操作权。

用户需要在上下文预算内找到方法，按需取得正文和资源，再由 agent 按指导工作。目录里的脚本是文件，用 `read_file` 读。要运行它，agent 用 Shell，那是一次普通的 Shell 工具调用，见 J-SK05。发现、读取和实际内容采用分别可辨认。常驻只把名称和说明交给模型，不自动加载正文；读正文是一次返回，不产生“已激活”状态，不改变系统提示词，也不自动读全部附件或运行脚本。指导文本和资源中的指令不授予身份、权限或系统决策权。

方法内容、持有与配值归各自资产拥有者；本领域维护方法的定义、发现、按需读取和来源，以及向消息、Context、工具与环境交接的专有规则。Skill 交出的材料里有依赖声明和 [Skill 包](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-skill-package--skill-包--skill-package)字节。Skill 只交依赖声明，依赖在不在场、方法此刻可不可用，由[集成方](../../ubiquitous_language/terms/scope-and-resolution.md#ul-integrator--集成方--integrator)求值（J-SK02）。已发布方法的内容由资产存放。Skill 按能力标识向资产要一个[包的读口](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-package-reader--包的读口--package-reader)，按[包的清单](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-package-manifest--包的清单--package-manifest)里的路径与摘要读文件，不认宿主机上的路径，存放办法见[资产与规则](../assets-and-rules/design.md#content-storage)。工具 read 返回与命令展开用户消息各自保存实际采用内容，不能统一改成一种日志。Skill 自身没有持续执行运行时，`Skills` 也没有执行命令。运行脚本是一次 Shell 工具调用，工作和结果归工具执行。后续内容更新不会重写已经读取或采用的旧内容。

### 元技能

[元技能](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-meta-skill--元技能--meta-skill)是官方层的一个普通 Skill，教 agent 怎样写 Skill。它常驻，名称与说明一直在模型面前，正文用到才读。它没有特殊机制，按普通 Skill 发现、读取与治理。它的资产定义声明不可替换（`immutable`），租户不能用同名的 Skill 盖住它：同名的发布被拒绝，什么都不发布，原因写明与它同名。

### J-SK01 将合法方法来源交给消费者

作者或装配者希望同一份方法能在不同 agent 中复用。前提是方法具有名称、使用说明、正文、资源范围及必要依赖，来源可读取，资产持有和使用资格成立。资产拥有者提供版本与合法选择，Skill 校验本类别的材料，并向装配或独立消费方提供可解释的定义和来源。来源、能力身份与具体实现版本分别显示；同名替换不能隐藏它来自哪一层或替换了什么。

工作区原生方法使用已有 `SKILL.md`、可选 `.omne/skill.json` 和按需资源的包形式。候选读取须有明确工作区选择、有效参与和实例条件及当前读取权；这些条件成立即可读取候选，校验与交接完成后才正式采用。目录存在、当前工作目录、兼容开关或发现成功均不授予执行许可。原生、local 和兼容来源的发现、过滤及冲突处理沿工作区与资产拥有者；完整替换不得混拼另一实现的正文、资源或凭据。

缺少必要定义、错误配置、来源不可读或一致版本无法成立时，报告具体失败，不能当作空方法或静默回退。取消候选读取只结束该读取责任，已经确认的关系及原采用记录继续保存；原采用仍受当前资格约束。恢复定位原来源和候选进度，不覆盖原文件、不重复安装。agent 与人提交新方法按 J-SK07 承接；市场与取得尚未持有资产的产品流程不在本稿定义。

### J-SK02 找到方法并理解当下能否使用

agent 希望判断一类工作有没有现成方法，以及为什么某份方法现在用不了。前提是主体此刻的使用资格和当前资产求值可取得。`Skills` 能搜到的是这个主体此刻合法可用的 Skill。它按当下事实现算，不是采用点上记下的集合，也不按 Agent 定义的引用收窄。租户新装一个不常驻的 Skill，已有会话的下一次搜索就能看到，这不是重新装配。要限制一个 agent 用哪些 Skill，靠授权规则。

常驻来自两处叠加：会话执行类型的必需身份集合，与 Agent 定义的引用。两处都可以标常驻，任一处标了就常驻。Agent Definition 与 Plugin 同时声明时，按既有装配规则由前者决定。常驻呈现名称和说明，在采用点定下，进入系统提示词。常驻是给模型省一步搜索，不是能用的前提。不常驻的方法通过 `Skills` 的搜索找到，常驻方法也在搜索范围内并标明已经直接可见。

在会话与 Agent 的动态重装配做成之前，已有会话里的常驻简介不随新装或更新而变，只对新会话生效。撤销资格不等装配，立刻生效。

搜索按使用说明找到合法可用的 Skill，并返回当前来源与可用性。每次搜索按当下事实求可用性。声明依赖是一串抽象的必需名字，全部满足才可用；可选条件在用时探测，不塞入必需声明。Skill 只交依赖声明，依赖在不在场、方法此刻可不可用由集成方求值。会话与 Agent 的集成方在装配、确认当前采用、为执行建立新挂接及必需提供者变化时，同样按当前事实重算可用性；合法显式刷新影响后续采用。独立读取方法时，每次核验当前访问资格，无须先有会话或执行尝试。依赖满足不是单次操作授权，也不保证实际资源已经就绪。

已知方法失去选入资格、被禁用或卸载时，发现仍保留最近合法身份，用替换件说明不可用原因。发现结果不授予读取撤权后的新内容。只缺必需依赖时，正文照常读得到，缺什么写在搜索结果与读取结果里，见 J-SK03；这个结果不从发现的不可用状态推出。调用不可用替换件沿 dummy tool execution 逻辑收场，保留原调用及结果消费位置；真实原工具未物理执行，不为凑齐抽象建立真实执行资源或虚构效果，替换件自身实际开销如实记录。主体此刻没有使用资格、也从未合法取得的方法，不因搜索或不可用说明新增身份。恢复必须同时满足当前定义、治理及依赖，不仅是提供者重连。搜索失败和无法核验当前条件明确可见，不能用空集合假报“没有方法”；取消搜索不改变能力集合。

### J-SK03 按需读取正文或指定资源

agent 已选到方法，希望只读取眼前需要的内容。前提是本次读取的主体、方法、当前合法采用值和读取权可核验。三层披露对应三种读法。读入口返回 `SKILL.md` 的正文。按目录里的路径读，返回那一个文件。列目录返回目录里有哪些文件。每次读取返回实际取得内容、来源、版本及范围。读取经资产按能力标识给出的包的读口，按清单里的摘要逐个文件核对，对不上答材料不可用，读不到清单之外的东西。附件、二进制资源或不能直接表示的内容按实际支持能力说明，不能把遗漏、截断或资源不可取伪装成完整方法。

工具 read 的内容作为原调用返回进入对话，随 Context 自己的组装、裁剪和重新读取规则存续。读取不修改系统提示词，不产生启用或卸载方法的状态。只读正文不自动取全包；读到脚本源码不运行脚本。上下文不再包含该内容时，可以再次合法读取，不能假定 Skill 内藏一份永久激活副本。

错误资源地址、包外目标、资源缺失、读取权失效或提供者故障分别报告。缺少请求的资源不能用别的同名包补齐。选入或读取权失效、方法禁用或卸载时拒绝读取原受限内容，对合法已知身份返回替换件及安全原因。读取与更新竞争时，返回必须对应一次可成立的版本和范围；不能将旧正文与新资源拼成成功。取消后已得到的内容及已经交接的事实按原消费者规则保管，未完成范围明确。恢复重新核验当前读取权，历史可见性不授予新的访问。

方法仍被合法选入且未禁用、卸载，主体仍有读取权，正文来源正常时，必需依赖缺席不挡读取。正文照常返回，缺什么写在搜索结果与这次读取的结果里。这是产品负责人 PanQiWei 2026-11-12 对 Q-SK08 的裁定。Skill 不管脚本的运行设施，所以没有「脚本设施不足」这一种情况。读取资格失效时不取原受限内容，这一条不变。其余读取、来源和内容采用责任继续成立。

### J-SK04 做法的差异写在方法里

用户希望 agent 在不同场合按不同的做法工作。Skill 是一份文档目录：agent 用了一个 Skill 之后怎样做事，步骤、语气、注意什么，都写在正文和目录里的文件中，agent 读了照着做。所以 Skill 不声明设置，不接受配值，也不向 agent 或 Shell 里的进程供给任何值。

要换一种做法有两条路。长期的差异发布成另一份 Skill：租户层的同名 Skill 盖过官方层的，也可以复制一份再改。一次性的要求在对话里直接告诉 agent。

方法文件里写了设置声明的包，检查按格式错拒绝，不当作空声明。脚本运行时需要的凭据与环境，由那一次 Shell 调用按执行环境自己的规则取得。读取正文不授予秘密读取权，名称相同也不授予；秘密值不进入模型、普通消息、诊断或日志。

### J-SK05 运行方法携带的脚本

用户或 agent 希望运行选中方法目录里的某个脚本。`Skills` 没有执行命令。脚本和参考资料、模板一样，是第三层的文件，用 `read_file` 读。读到脚本源码不运行它。

运行归 Shell。资产一定先加载到本地。单机装配下，一个 Skill 的目录就在本机的文件系统里，agent 用 Shell 直接运行里面的脚本。agent 从 `Skills` 的读取结果里知道这个目录在本机的位置。这个位置是单机装配下的一个事实，不是包的读口给的路径；Skill 读内容仍经包的读口。这是一次普通的 Shell 工具调用：许不许照[动作放行](../meta-capabilities/design.md#动作放行与环境准入)；受理、环境与落点、等待、前后台、取消、结果保管，全照[工具执行](../tool-execution/design.md)与[执行环境](../execution-environments/design.md)的规则。

Skill 不持有执行权。没有按某个 Skill 判的脚本执行许可，没有脚本桥接，也没有「只能运行包内脚本」这条规则。Shell 的许可不因为脚本来自某个 Skill 而放宽，也不因此收紧。能读一个 Skill，不等于能运行任何命令。

防护与隔离不在这一阶段。现在不为脚本的运行设计防护、隔离或沙箱，也不设计分布式部署下脚本怎样到执行落点。

依据：产品负责人 PanQiWei 2026-11-12 的裁定。

### J-SK06 在命令展开中保留真实方法内容

用户通过合法绑定命令使用一份方法，希望看到本次展开采用的内容。前提是命令拥有者已经确定命令匹配、有效绑定和本次输入，Skill 读取权及采用条件成立。Skill 返回实际正文、获准设置和来源，命令/入站消息消费者按其契约形成用户消息内容块并保留本次展开的依据。用户原输入、展开结果和消息受理事实由消息与命令拥有者关联，本领域不重做匹配、消息队列或 Run 创建。

命令展开需要读取正文时，同样受 J-SK03 的结果边界约束。只缺必需依赖时，正文照常返回并写明缺项。命令适配不能自行选定另一种 Skill 读取政策。

该路径与工具 read 返回分别保存。正文更新只作用于下一次合法展开，不能回写历史消息、把旧内容换成新版本或将用户展开改记为工具执行结果。方法取用失败时沿命令契约明确拒绝或失败，不能以空展开宣称命令完成。读取成功不证明消息已受理；消息已确认受理后答复丢失，恢复应查询原消息，不重展开并重复投递。取消按实际进度分别保留已读取、已展开和已受理事实。

### J-SK07 合法新增或更新方法而不改写原工作

Agent 可以用 Files 或 Shell 写一个 Skill 的目录，再用资产的工具 `OmneExtensions` 把它发布到当前租户名下。`Skills` 只读，没有发布命令。人从资产页发布，走的是同一个发布操作，两个入口用同一套校验与发布。发布之前，agent 可以先问这次发布的效果：一个新 Skill，已有同名 Skill 的新版本，或者会盖住同名的官方 Skill。发布先校验目录、核大小上限，校验不过或超出上限时直接拒绝，什么都不发布。与声明不可替换的官方 Skill 同名时同样拒绝，原因写明与哪一份同名，见 [Q-SK09](#q-sk09-与不可替换的官方-skill-同名时拒绝发布还是发布了不生效)。

Agent 发布一个 Skill 许不许，照[动作放行](../meta-capabilities/design.md#动作放行与环境准入)判断，和 agent 对资产的其他改动一样，归 `OmneExtensions` 产生效果的那一项权限。这一项缺省自动，所以 agent 发布 Skill 缺省不问人。发布出来的 Skill 是租户在持的资产，人随时能在资产页禁用或移除它，因此缺省不拦下来问。要每次问人的租户或组织，把这一项设成问一下。设成禁止时，agent 不能发布。这一项管 agent 对资产的全部改动，收紧它不只收紧 Skill。要问人时，人同意后才发布，人拒绝或不答时不发布。

产物是一份资产，按实际发布位置归属，agent 的发布落在行事的租户名下。Agent 不能直接发布组织资产，也不能代用户提升为组织资产。面向组织的创作意图仍由用户自己手动提升。发布须符合当前访问规则，不额外授予持有、装配或执行权。组织提升流程归相应拥有者。

新方法发布成功后，主体此刻合法可用的 Skill 随之变化。已有会话的下一次搜索就能看到不常驻的新方法，不需要装载动作，不改变 Agent Definition，也不重建 Agent runtime。只在执行落点写文件、没有发布，搜索看不到它。新方法被标了常驻时，简介只在采用点进入系统提示词，已有会话不更新，见 J-SK02。发布校验失败时保持原有版本，后续使用仍核验当前资格，不能延续已经撤销的权利。

作者更新正文、资源、说明或脚本后，消费者希望后续取得新合法内容，同时原工作仍可解释。前提是资产拥有者保存内容版本，装配和消费者明确本次采用依据。合法数据或实现更新可以作用于后续取用，不要求替换统一入口或重建 Agent runtime；真正的服务绑定变化沿装配责任处理，不冻结其内部数据。

工作区文件变化及同步不自动采用；新的实际装配或显式 reload 才读取并校验，校验失败保持原采用记录，不能发布半新半旧结果。更新、reload、新工作区选择、取消和撤权竞争时，迟到候选不得覆盖较新选择或在失效条件下采用。已读取内容和已展开消息保留原版本，未来请求按当前合法采用核验。运行脚本的 Shell 调用归工具执行，Skill 的更新不改写它。

不可用和恢复沿 J-SK02。撤除只撤本实例贡献，不能恢复整个旧表而抹掉其他方法。失败和无法确认的采用进度可查询；恢复围绕原读取、候选或调用接续，不用新成功掩盖旧未知。

### J-SK08 取消和故障后接续原执行与结果

这个旅程退出。依据是产品负责人 PanQiWei 2026-11-12 的裁定：`Skills` 没有执行命令，Skill 的脚本由 Shell 运行。运行脚本的那次 Shell 调用怎样停、换代后怎样取得结果、结果怎样保管，归[工具执行](../tool-execution/design.md)。Skill 不为它另设旅程或能力。

### Q-SK08 只有依赖或脚本设施不足时正文是否仍可读取

状态：已裁定。产品负责人 PanQiWei 于 2026-11-12 决定：依赖不齐时正文读得到。

场景：会话仍合法选入 Skill S，S 未禁用或卸载，主体仍有正文读取权，正文来源正常，但 S 的必需依赖缺席。agent 请求读取 S 的正文。

结果：必需依赖缺席不挡读取。正文照常返回，缺什么写在搜索结果与这次读取的结果里。读取资格失效时不取原受限内容，这一条不变。「脚本设施不足」这一支不再存在，因为 Skill 不管脚本的运行设施。

落点：J-SK02、J-SK03、J-SK06 与 CAP-SK04、CAP-SK05 已按这个结果写。读到正文不是运行任何命令的凭证；运行脚本是一次 Shell 工具调用，见 [J-SK05](#j-sk05-运行方法携带的脚本)。

### Q-SK09 与不可替换的官方 Skill 同名时，拒绝发布还是发布了不生效

状态：已裁定。产品负责人 PanQiWei 于 2026-11-23 决定：拒绝发布。

场景：官方层有一份声明了不可替换的 Skill，例如元技能。租户发布一份同名的 Skill。

结果：发布被拒绝，什么都不发布，原因写明与哪一份官方 Skill 同名、它不可替换。不采用「发布成功但不生效」：人以为发上去了，其实没有用，要再查一次才知道。

落点：[J-SK07](#j-sk07-合法新增或更新方法而不改写原工作) 已按这个结果写。同名的判断由资产的发布做，三条发布的路共用，见[资产的规格](../../../../packages/assets/SPEC.md#发布到租户这一层)。
