# Skill产品设计

状态：产品设计草案，revision 1。尚无整体接受证据。能力状态、阶段与明确决定各保留自身依据，落位不授予运行支持。技术承接从[能力组工程入口](../../../../packages/skills/README.md)展开。

## 产品需求描述

Skill 是可复用的工作方法。它告诉 agent 遇到一类事情该怎样做，主体是可读指引，可以携带资源文件和脚本。名称辨认方法，说明回答何时使用，正文解释步骤与条件；三者不能用目录名或一句工具调用替代。Skill 可以组合 Tool，组合和依赖沿资产规则成立，不从文字中的每个名字递归扩张装配，也不把 MCP 对端动作造为独立资产或 Skill 组合成员。需要外部服务时沿既有依赖语义声明，不能凭这份声明取得服务操作权。

用户需要在上下文预算内找到方法，按需取得正文和资源，再由 agent 使用指导或显式执行配套脚本。发现、读取、实际内容采用、脚本准入和执行结果分别可辨认。常驻只把名称和说明交给模型，不自动加载正文；读正文是一次返回，不产生“已激活”状态，不改变系统提示词，也不自动读全部附件或运行脚本。指导文本和资源中的指令不授予身份、权限或系统决策权。

方法内容、持有与配值归各自资产拥有者；本领域维护方法的定义、发现、按需读取和来源，以及向消息、Context、工具与环境交接的专有规则。工具 read 返回与命令展开用户消息各自保存实际采用内容，不能统一改成一种日志。Skill 自身没有持续执行运行时；执行脚本的工作和结果由原工具调用承接。后续内容更新不会重写已经读取或采用的旧内容。

### J-SK01 将合法方法来源交给消费者

作者或装配者希望同一份方法能在不同 agent 中复用。前提是方法具有名称、使用说明、正文、资源范围及必要依赖，来源可读取，资产持有和使用资格成立。资产拥有者提供版本与合法选择，Skill 校验本类别的材料，并向装配或独立消费方提供可解释的定义和来源。来源、能力身份与具体实现版本分别显示；同名替换不能隐藏它来自哪一层或替换了什么。

工作区原生方法使用已有 `SKILL.md`、可选 `.omne/skill.json` 和按需资源的包形式。候选读取须有明确工作区选择、有效参与和实例条件及当前读取资格；这些条件成立即可读取候选，校验与交接完成后才正式采用。目录存在、当前工作目录、兼容开关或发现成功均不授予执行许可。原生、local 和兼容来源的发现、过滤及冲突处理沿工作区与资产拥有者；完整替换不得混拼另一实现的正文、资源或凭据。

缺少必要定义、错误配置、来源不可读或一致版本无法成立时，报告具体失败，不能当作空方法或静默回退。取消候选读取只结束该读取责任，已经确认的关系及原采用记录继续保存；原采用仍受当前资格约束。恢复定位原来源和候选进度，不覆盖原文件、不重复安装。合法新增方法按 J-SK07 承接；具体创作入口、发布和取得尚未持有资产的产品流程不在本稿定义。

### J-SK02 找到方法并理解当下能否使用

agent 希望判断一类工作有没有现成方法，以及为什么某份方法现在用不了。前提是会话的合法已知能力和当前采用依据可取得。常驻标记来自装配引用，Agent Definition 与 Plugin 同时声明时按既有装配规则由前者决定。常驻呈现名称和说明；非常驻方法通过取用入口找到，常驻方法也在搜索范围内并标明已经直接可见。

搜索按使用说明找到合法已知身份，并返回当前来源与可用性。声明依赖是一串抽象的必需名字，全部满足才可用；可选条件在用时探测，不塞入必需声明。装配、每次执行尝试开始及必需提供者变化时重算，合法显式刷新影响后续采用。依赖满足不是单次操作授权，也不保证实际资源已经就绪。

已知方法失去选入资格、禁用、卸载或依赖时，发现仍保留最近合法身份，用替换件说明不可用原因。发现结果不授予读取撤权后的新内容；只有依赖或脚本设施不足时，正文读取结果单列在 J-SK03 和 Q-SK08，不从发现的不可用状态直接推出。调用不可用替换件沿 dummy tool execution 逻辑收场，保留原调用及结果消费位置；真实原工具未物理执行，不为凑齐抽象建立真实执行资源或虚构效果，替换件自身实际开销如实记录。从未合法纳入的方法不因搜索或不可用说明新增身份。恢复必须同时满足当前定义、治理及依赖，不仅是提供者重连。搜索失败和无法核验当前条件明确可见，不能用空集合假报“没有方法”；取消搜索不改变能力集合。

### J-SK03 按需读取正文或指定资源

agent 已选到方法，希望只读取眼前需要的内容。前提是本次读取的主体、方法、当前合法采用值和读取资格可核验。读取正文，或明确指定该方法的资源，返回实际取得内容、来源、版本及范围。附件、二进制资源或不能直接表示的内容按实际支持能力说明，不能把遗漏、截断或资源不可取伪装成完整方法。

工具 read 的内容作为原调用返回进入对话，随 Context 自己的组装、裁剪和重新读取规则存续。读取不修改系统提示词，不产生启用或卸载方法的状态。只读正文不自动取全包；读到脚本源码不运行脚本。上下文不再包含该内容时，可以再次合法读取，不能假定 Skill 内藏一份永久激活副本。

错误资源地址、包外目标、资源缺失、读取资格失效或提供者故障分别报告。缺少请求的资源不能用别的同名包补齐。选入或读取资格失效、方法禁用或卸载时拒绝读取原受限内容，对合法已知身份返回替换件及安全原因。读取与更新竞争时，返回必须对应一次可成立的版本和范围；不能将旧正文与新资源拼成成功。取消后已得到的内容及已经交接的事实按原消费者规则保管，未完成范围明确。恢复重新核验当前读取权，历史可见性不授予新的访问。

当方法仍被合法选入且未禁用、卸载，主体仍有读取权，正文来源正常，但方法必需依赖或脚本设施不足时，脚本不得在缺项条件下执行。正文是照常返回并说明缺项，还是只返回不可用替换件，尚待负责人裁定 Q-SK08。本稿只保留这条读取结果分歧，不把设施不足解释成材料读取资格失效，也不以默认结果补齐缺口。其余读取、来源和内容采用责任继续成立。

### J-SK04 让配置到达正确的消费者

方法作者希望通过声明的设置调整指导和配套脚本。前提是每项设置的类别、含义、取值条件及合法配值来源已经由资产规则确定。偏好和绑定类的求值结果随正文返回给 agent，也交给对应脚本；落点与身份类只交给有权使用它的脚本及受控执行适配，不进入模型、普通消息、诊断或日志。治理值由对应判断拥有者消费，不把它改成正文可以放宽的政策。

工作区可提供的配值沿既定类别和锁定过滤；它不能通过方法文件声明新的权限、凭据归属或执行落点许可。完整替换实现保留自己的声明和配值边界，不能将旧实现专有设置或凭据迁给新实现。脚本只得到本次用途所需且获准的值，名称相同不授予秘密读取权。

缺少必需设置、类别不合法或秘密无法取得时，拒绝依赖该条件的使用并说明安全原因，不输出秘密值。取消读取不会撤销已经合法确认的配值事实。设置更新影响后续合法取用；已发脚本保留原实际采用，恢复与重新取用仍核验当前授权，不能用旧秘密快照复活撤权。

### J-SK05 显式运行方法携带的脚本

用户或 agent 希望执行选中方法的某个配套脚本，同时不开放任意 Shell。前提是明确执行请求指向当前合法方法实现所携脚本，Skill 使用资格、原执行动作准入、依赖及本次设施条件成立。脚本执行权随该 Skill 的适用许可判断，不以通用 Shell 许可代替；相反，Skill 许可也不授予任意路径执行、其他工具动作或脚本内额外资源访问。

桥接确认脚本属于所选包及版本，把明确请求交工具运行时。实际发起固定匹配的脚本、参数、设置、实现、原主体和工作关联，并按当前环境权限、设施需求和已采用提供者取得真实落点。需要环境者不能在准备失败时静默降到宿主；未声明环境需求的入口须固定其明确直接依赖。文件或 Shell 路径可以按自己的权限访问工作区资源，不能借用 Skill 许可，也不使新文件自动进入装配。

包外脚本、替换后不匹配的旧建议、缺少依赖、资源不满足或撤权时不运行原脚本，并返回可解释原因。排队前的判断不是永久执行许可。脚本内容不可信时沿正式隔离边界约束资源和宿主接口；无法满足者不得承接该运行方式。结果、附件、等待和允许的前后台继续沿原工具契约，不由 Skill 新造一套收场。

### J-SK06 在命令展开中保留真实方法内容

用户通过合法绑定命令使用一份方法，希望看到本次展开采用的内容。前提是命令拥有者已经确定命令匹配、有效绑定和本次输入，Skill 读取资格及采用条件成立。Skill 返回实际正文、获准设置和来源，命令/入站消息消费者按其契约形成用户消息内容块并保留本次展开的依据。用户原输入、展开结果和消息受理事实由消息与命令拥有者关联，本领域不重做匹配、消息队列或 Run 创建。

命令展开需要读取正文时，同样受 J-SK03 的结果边界约束。只有依赖或脚本设施不足的分支等待 Q-SK08，不能由命令适配自行选定另一种 Skill 读取政策。

该路径与工具 read 返回分别保存。正文更新只作用于下一次合法展开，不能回写历史消息、把旧内容换成新版本或将用户展开改记为工具执行结果。方法取用失败时沿命令契约明确拒绝或失败，不能以空展开宣称命令完成。读取成功不证明消息已受理；消息已确认受理后答复丢失，恢复应查询原消息，不重展开并重复投递。取消按实际进度分别保留已读取、已展开和已受理事实。

### J-SK07 合法新增或更新方法而不改写原工作

Agent 创建或修改方法须有适用授权，未获授权时不发生。产物是一份资产，按实际提交位置成为工作区或租户资产。Agent 不能直接提交组织资产，也不能代用户提升为组织资产；面向组织的创作意图仍由用户自己手动提升。提交位置须符合当前访问规则，不额外授予持有、装配或执行权。具体创作入口、同名处理和组织提升流程归相应拥有者，Skill 只承接合法方法及装载结果。

新方法经资产拥有者合法登记和选择，再完成显式增量装载后，当场供当前消费者使用，不改变 Agent Definition，也不因增加该能力重建 Agent runtime。只在工作区写文件不算完成装载，不触发当场可用。装配校验失败时保持原采用记录，后续使用仍核验当前资格，不能延续已经撤销的权利。

作者更新正文、资源、说明或脚本后，消费者希望后续取得新合法内容，同时原工作仍可解释。前提是资产拥有者保存内容版本，装配和消费者明确本次采用依据。合法数据或实现更新可以作用于后续取用，不要求替换统一入口或重建 Agent runtime；真正的服务绑定变化沿装配责任处理，不冻结其内部数据。

工作区文件变化及同步不自动采用；新的实际装配或显式 reload 才读取并校验，校验失败保持原采用记录，不能发布半新半旧结果。更新、reload、新工作区选择、取消和撤权竞争时，迟到候选不得覆盖较新选择或在失效条件下采用。已读取内容、已展开消息和已发脚本保留原版本，未来请求按当前合法采用核验。尚未发起的旧脚本建议不暗换目标或参数，约定或绑定变化时交回消费者重新判断。

不可用和恢复沿 J-SK02，停止或卸载入口不丢原执行及结果。撤除只撤本实例贡献，不能恢复整个旧表而抹掉其他方法。失败和无法确认的采用进度可查询；恢复围绕原读取、候选或调用接续，不用新成功掩盖旧未知。

### J-SK08 取消和故障后接续原执行与结果

用户希望停止脚本，或在 agent、代码域、环境及服务换代后取得真实结果。前提是原工具调用、控制目标、主体、工作和消费责任可定位。取消受理、代码停止、宿主调用实际收场、资源释放和结果可靠交接分别呈现。Skill 入口退出、Agent runtime 销毁、Run 终态或 disposer 不证明执行已停止，也不撤销已发生的外部效果。

受限代码域被终止后，已准入宿主调用和迟到结果继续由桥接与原调用拥有者保管，不能只返回给已销毁代码域。消费者暂时失去披露资格时保管事实仍存在，按结果契约处理交付，不能泄露或直接丢弃。当前查询失败保持未知；确认工具丢失运行连续性时按工具失联规则收束，不自动重放原脚本。

恢复定位原调用、已知效果、结果和未完成交接，查询、等待或对账后只接续未完成责任。转后台改变等待关系，不产生第二次执行；后台和内部等待的支持条件沿原工具契约。结果和消费位置按原确认边界可靠保存，再释放相应责任；普通崩溃或断电后仍能解释已确认事实。没有本稿新增的 TTL、默认答复或盲目重发政策。

## 阶段与版本支持承诺

`0.0.0 → 0.1.0` 的能力清单等待负责人选择。CAP-SK01 至 CAP-SK12 均未被本文选为阶段基线，旧 PF 的“本版”与前序领域支持不构成本域支持。选择应说明完整能力、产品场景、来源类型、资源种类、命令/独立消费适用范围及必要产品依赖；不能只选“读技能”而省掉其资格、来源和历史采用规则。

负责人选择 CAP 和产品适用条件；具体 provider、API、机制版本、存储、格式矩阵及验证方案随后由技术拥有者固定，真实支持声明绑定精确采用与证据。技术机制和测试参数不是选择 CAP 的前置投票。某能力依赖环境、工具、消息或装配时，相应产品条件必须同时成立，其他域已选择也不能替代本域选择。

框架保留来源提供者、资源读取、发现排序、装配呈现和脚本执行适配的扩展边界。部署可按合法治理配置支持类型、额度和运行条件，不在本稿固定阈值、TTL、默认策略、设施清单或执行引擎。配置数值未定不削弱包外执行禁止、秘密隔离、历史不改写、原结果保管和真实控制确认等不变式。实施前须补足与所选范围相称的技术承诺和验证；正文、结构通过和独立审阅均不授予接受。

### Q-SK07 具体创作与安装入口、市场和自动发布另行设计

### Q-SK08 只有依赖或脚本设施不足时正文是否仍可读取

决定责任：产品负责人。

分类：产品选择。场景：会话仍合法选入 Skill S，S 未禁用或卸载，主体仍有正文读取权，正文来源正常，但 S 的必需工具依赖或脚本设施缺席。agent 请求读取 S 的正文，用于理解方法或寻找其他做法。

已知约束：缺项条件下不能发起依赖该项的原脚本执行。读取不激活、不执行脚本，发现仍保留已知身份并说明缺项。读取资格失效时不取原受限内容；本场景没有发生这种失效。Q03 只决定替换件的 dummy 逻辑性质，不决定何时返回正文。

来源分歧：PF-007 flows 144/151 要求正文照给并说明缺项；PF-007 design 456 和 PF-006 design 734–748 将已知不可用与替换件、必需合取关联。正式 Skill、资产、授权及环境分工没有具名消除这两种结果，因此不能从现行分工推出默认答案。

待裁决：在上述条件下，正文读取应返回正文和缺项说明，还是只返回不可用替换件及原因？

- 返回正文并说明缺项：agent 仍能了解方法；执行仍单独核验依赖、授权及设施，不能把已读正文当作可执行凭证。
- 只返回替换件及原因：agent 明确知道方法不可用，但缺项期间无法通过该读取取得正文，即使其读取权和正文来源仍正常。

处理建议：由产品负责人作具名决定，并同步 J-SK02/J-SK03/J-SK06、F-SK02/F-SK03/F-SK06、INV-SK03 至 INV-SK05 及 V-SK03 至 V-SK05。作者不代选默认，也不重开 Q03。

影响：只限制该正文读取结果及依赖它的消费分支定稿。无争议的发现、撤权、正常读取、资源边界、脚本准入、dummy 分类与实际内容交接继续有效；不暂停整个 Skill 领域。
