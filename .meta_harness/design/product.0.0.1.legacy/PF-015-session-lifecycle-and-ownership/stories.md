### ST-015-01 · 在新会话中收到第一条答复

- **价值**：用户能够从新建会话开始一次真实交流，不必通过 demo 专用运行对象发起任务。
- **覆盖场景**：[S2](acceptance.md#创建变化与恢复)、[S36](../PF-012-agent-loop-and-run/acceptance.md#一可观察的场景)
- **演示**：
  1. 以当前租户身份和合法 AgentDefinition 创建普通会话，显式给定本次采用的执行类型与模式，不指定工作区和第一条消息 → 会话建立，尚未启动任务；工作区为空，没有因创建而发出模型请求。
  2. 从普通消息入口发送一个无需工具的文本问题 → 本会话承接该问题，用户收到真实模型回复。
  3. 等到回复完成，查看本轮结果 → 无动作、队列为空，Run 为 completed；会话与记录仍在。
- **不含**：第二种入口、模式切换、工具调用、失败恢复和 Connector；已有适用的租户隔离及执行准入约束仍须成立。
- **前置**：无
- **就绪**：是

### ST-015-02 · 重新进入会话时看得到已经发生的事

- **价值**：用户离开后回来，仍能查看此前的交流和任务结果，不必重新提问。
- **覆盖场景**：[S1](../PF-010-context-management-and-assembly/acceptance.md#给用户那一侧)、[S2](../PF-010-context-management-and-assembly/acceptance.md#给用户那一侧)
- **演示**：
  1. 准备一个有多轮交流和工具结果的会话，并准备一个已有大量记录的会话 → 已知消息、结果与记录范围可核对。
  2. 离开后重新进入两个会话 → 已保存的近期交流和结果可读；大历史会话首载仅最近一段，没有全量加载。
  3. 对同一会话重复打开并查阅已加载内容 → 内容来自原记录，查阅前后日志条目没有增加或被改写。
- **不含**：往前分页、实时续收、搜索、大结果全文展开及会话重启恢复；这些不影响本卡保存和读取既有记录的责任。
- **前置**：ST-015-01、ST-012-01
- **就绪**：是

### ST-015-03 · 重启后原工作不会凭空消失或重新执行

- **价值**：用户在系统中断后仍能认回原会话与工作进度，已取得的回复不会再花一次钱生成。
- **覆盖场景**：[S13](acceptance.md#创建变化与恢复)、[S3](../PF-012-agent-loop-and-run/acceptance.md#一可观察的场景)、[S51](../PF-012-agent-loop-and-run/acceptance.md#一可观察的场景)、[S72](../PF-012-agent-loop-and-run/acceptance.md#持久化投影与完整函数输入)
- **演示**：
  1. 完成一次任务，重启系统后重新打开会话 → 原消息和任务结果仍可查，不因启动而重新执行已完成工作。
  2. 在另一轮中，让完整模型回复已保存但 Run 尚未终结时发生中断，恢复后查看同一轮 → 原回复仍在，系统只收尾一次，没有新增模型请求。
  3. 保留完整持久输入和当下条件，移除可重建的 Run 进度投影后恢复 → 重建的当前结果与同输入求值一致，能认回原 Run；不要求仅凭日志还原所有外部条件。
  4. 在缺少尝试结束条目的情况下再次恢复 → 不报数据损坏，沿已有事实继续对账；日常当前值查询不随日志长度重扫全部历史。
- **不含**：模型或工具自身失联、全部共享来源回到旧版本、模型可读块视图的缓存政策，以及具体存储或投影刷新机制。
- **前置**：ST-015-02
- **就绪**：是

### ST-015-09 · 归档普通会话后原工作停止且历史保留

- **期次**：第一期 · 普通会话手动归档
- **价值**：用户能收起普通会话并停止名下工作，撤销归档后仍能查看历史，但不会重做旧任务。
- **覆盖场景**：[S24](acceptance.md#归档与派发)、[S25](acceptance.md#归档与派发)、[S29](acceptance.md#运行时归属与执行关联)
- **演示**：
  1. 准备普通会话的排队消息及在途模型或前台工具，分别覆盖仍有和已无Agent Runtime的情况，再手动归档 → 不再承接原待处理任务或发起新调用，仍能定位并停止会话名下执行；原消息、取消原因、真实结果和成本保留。
  2. 向已归档会话提交新任务，并让原调用迟到返回 → 新任务明确拒绝，迟到结果与账按原执行规则保留，不创建或复活Run，不重复外部效果。
  3. 撤销归档后查看并重新发送一个问题 → 会话回到休眠可用状态，从撤销时重新计时；旧任务不自动重排，历史保留，新问题沿普通入口开展新工作。
- **不含**：待答卡和后台任务的组合旅程、自动30天空闲归档、父子级联全部组合、handoff和中心工作区删除；归档不是关闭客户端或撤销外部效果。
- **前置**：ST-014-04、ST-012-06、ST-015-02
- **就绪**：是

### ST-015-04 · 会话保留自己选择的模式和模型

- **子期**：2B · 稳定完成项目长任务
- **价值**：用户选定的工作方式不会因重启或租户默认变化而丢失。
- **覆盖场景**：[S3](acceptance.md#创建变化与恢复)、[S4](acceptance.md#创建变化与恢复)
- **演示**：
  1. 按租户 co-work 默认创建 A，再改默认为 auto-drive 创建 B，重建 A → A 仍为 co-work，B 按新默认创建。
  2. 在 A 合法切换权限三档（never／auto_permission／bypass-permissions）和模型 → A 当前选择可恢复，B 和租户默认不变；上级锁定和授权仍约束切换。
  3. 在合法会话中切换协作两档（co-work／auto-drive），观察 Ask 总开关，再恢复该会话 → Ask 总开关由协作模式决定，权限三档仍分别约束请示命令；两个维度的当前值和实际行为相符，恢复不重新套用租户默认。
- **不含**：新增模式政策、越权切换及定义版本更新；Job 类型强制完成检查由 ST-021-02 验证。
- **前置**：ST-015-01、ST-007-01
- **就绪**：是

### ST-015-05 · 恢复后保留自己注册的上下文

- **子期**：2B · 稳定完成项目长任务
- **价值**：用户调整的上下文能被恢复，必需上下文和租户身份受到保护。
- **覆盖场景**：[S11](acceptance.md#创建变化与恢复)、[S12](acceptance.md#创建变化与恢复)
- **演示**：
  1. 在会话添加一个合法 context，并移除一个非必需 context，再恢复会话 → 新块和来源配置还在，已移除块不复活，共享源没有被删除。
  2. 尝试移除 meta context 或借更新改变会话租户身份 → 明确拒绝，固定身份和必需块保留。
- **不含**：AGENTS.md 首次目录访问加载、模型可读视图缓存和工作区资产登记。
- **前置**：ST-015-01
- **就绪**：是

### ST-015-06 · 更新能力后仍认得原身份和原调用

- **子期**：2B · 稳定完成项目长任务
- **价值**：能力更新不会让旧调用变成另一件事，也不会丢掉已知工具位置。
- **覆盖场景**：[S10](acceptance.md#创建变化与恢复)、[S31](acceptance.md#会话作用域的输入与供给)、[S32](acceptance.md#会话作用域的输入与供给)、[S97](../PF-012-agent-loop-and-run/acceptance.md#无实例替换时的能力更新)、[S98](../PF-012-agent-loop-and-run/acceptance.md#无实例替换时的能力更新)
- **演示**：
  1. 工具调用仍在途时更新同身份实现，再发起下一次合法调用 → 旧调用用旧输入收场，新调用采用新实现，Agent Runtime 可以保持。
  2. 旧模型建议到达前更新 schema 或实现 → schema 或实现绑定的变化本身就要求交回 agent 重新判断；即使新实现仍接受旧参数，也不自动执行或暗改参数，旧模型结果和费用照记。
  3. 只更新说明文字，同动作、约定、绑定、参数均未变且已获准 → 不仅因更新再次请示。
  4. 分别合法增选、移除 Tool／Skill／MCP 或替换同身份实现 → 变化沿既有生效边界采用；已知身份保留，移除只使其不可用，数据或实现变化不自动重建 Loop，历史执行保留旧采用值。
- **不含**：Skill 正文读取更新、MCP 服务端动作消失及恢复、reload 更换执行者及定义版本升级；前两项由 ST-015-08 覆盖。
- **前置**：ST-012-01、ST-008-01、ST-006-05
- **就绪**：是

### ST-015-08 · 能力离线后能解释并恢复原位置

- **子期**：2B · 稳定完成项目长任务
- **价值**：用户能理解已有能力为什么暂时不可用，并在条件恢复后继续使用。
- **覆盖场景**：[S33](acceptance.md#会话作用域的输入与供给)、[S34](acceptance.md#会话作用域的输入与供给)、[S35](acceptance.md#会话作用域的输入与供给)
- **演示**：
  1. 分别让会话类型和 AgentDefinition 声明的必需工具服务离线 → 必需位置及替换件仍在，具体不可用原因可查，Loop 不因工具离线而必须停止。
  2. 更新 Skill 正文，再让已知 MCP 动作消失后恢复 → 后续合法读取采用新正文；动作保持已知身份，恢复按当前选择及治理判断，不越权取新内容。
  3. A 曾合法见过能力、B 从未见过，随后禁用该资产 → A 保留不可用条目，B 不新增；两者都不能执行禁用实现。
- **不含**：能力发现全集、新的不可用策略和实现更新。
- **前置**：ST-015-06、ST-006-03、ST-006-06
- **就绪**：是

### ST-015-10 · 归档时待答卡和后台工作一并收束

- **子期**：2B · 稳定完成项目长任务
- **价值**：用户收起会话时，悬着的请示与后台工作不会继续悬置或偷偷开展新工作。
- **覆盖场景**：[S81](../PF-012-agent-loop-and-run/acceptance.md#运行时归属与句柄)、[S57](../PF-008-human-in-the-loop/acceptance.md#永远等待与会话可用性)
- **演示**：
  1. 准备待答卡、后台工具及会话名下模型执行，回收Agent Runtime后手动归档 → 待答卡移出池，仍能找到并停止名下执行，真实结果与成本保留；不依赖Agent所持句柄。
  2. 让旧答复、后台结果和费用迟到，并向归档会话送新任务 → 旧答复不能批准或恢复已取消工作，结果按原归属收尾，新任务明确拒绝，不另起Run。
  3. 撤销归档 → 会话休眠，旧待答卡和后台任务不自动重排，已发生的外部效果不被撤销。
- **不含**：自动30天空闲归档、父子级联全部组合和中心工作区删除；handoff仍按独立生命周期治理。
- **前置**：ST-015-09、ST-008-06、ST-014-04、ST-012-08
- **就绪**：是
