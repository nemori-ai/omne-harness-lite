# PF-004 验收标准

做成什么样算做对了。**这里写的是可观察的结果，不是实现方式。**

> **「一个协程怎么起、怎么停」归
> [PF-012](../PF-012-agent-loop-and-run/acceptance.md)**——
> 空闲回收、退役未结算、强制停止之后怎么报告、等人不烧钱，都不在本页验收。
> **本页只验收：一份定义怎么被求值成一份构成，以及那份构成对变化怎么反应。**

## 一、可观察场景

### 装配

| 场景 | 应当看到什么 |
|---|---|
| 一份定义在某个作用域下装配 | 产生一份**装配清单**，上面能查到装了哪些工具、哪些技能、需要哪几类执行环境 |
| 从未取得定义所要求能力的合法定义 | 明确失败并指出缺项；已有合法定义仅实现不可用时则保留替换件，不据此拒绝 Loop 启动 |
| 同一个会话已有一份有效的清单，又要跑一轮 | 先核对同身份定义等输入；未变化且清单仍有效才直接复用，有新有效定义版本则重新装配 |
| 同一份定义在两个不同作用域装配 | 两份清单**不同**（各自作用域求值出的实现、设置、权限不同），而**定义本身一个字没变** |
| 装配完成，但这次运行随即被取消 | **清单照样存在且有效**——它不因为没被用过就作废 |

### 三个时刻

| 场景 | 应当看到什么 |
|---|---|
| 装配完成那一刻 | 提示词组合规则与采用定义已确定；能力描述／schema 逐请求取当前合法值，成品尚未存在 |
| 照同一份清单，用模型 A 请求一次，再用模型 B 请求一次 | 两次的系统提示词**可以不同**（同一批成分、不同组装方式），而**清单没有重算** |
| 改一项执行权限 | 清单**不重算**；下一次运行里多出一条提醒 |
| 那扇门的落点换了 | 清单**不重算**；agent 执行同一条命令，只是落在别处 |
| 换模型 | 清单**不重算**，动作空间**不变** |
| 运行中热装上一个新工具 | 清单**追加**一条，**动作空间变大**，正在跑的那个协程**不必重起** |
| 变化触及 Loop 自身捕获的必需入口 | 按实际依赖交接；不得把工具内部服务替换混同为 Loop 入口替换 |
| 已知必需工具的实际服务失效 | 保留必需能力位置及替换件；Loop 可继续判断其他动作，不要求工具服务作为 Loop 硬依赖 |
| 组织移除了一个可选工具 | 生效后已知身份保留，呈现不可用原因；已发调用保留原输入 |

### 动作空间与权限

| 场景 | 应当看到什么 |
|---|---|
| 把某工具的执行权限从「自动」改成「问一下」 | agent **照样能发起**那个调用，只是这次要问；**动作空间没变** |
| 把某工具的执行权限**收窄为空集** | agent **照样发起得出来**那个调用，每次都被拒，**它知道这件事存在、能说明被关掉了**；动作空间没变 |
| 把会话已知工具禁用 | 沿既有边界生效后呈现替换件；身份保留，不强制重建 Loop |
| 把某工具**移除** | 同上 |
| 一次运行正在跑，组织收回了丙对某个工具的「谁可以使用它」 | 默认下一 Run 采用，显式 reload 可提前采用；保留已知身份，不能执行被撤回的实现或获取未授权新内容 |
| 收紧整个会话的安全权限 | agent **照常工作**，动作空间不变；受影响的是调用的结果 |

### 上下文

| 场景 | 应当看到什么 |
|---|---|
| 外部环境在一轮运行进行中发生变化 | **当前这一轮不被打断**；变化在**下一轮**以一条提醒出现 |
| agent 收到那条提醒 | 它**读到**变化并自行调整后续动作；不是系统在背后改写了它的能力 |
| 上下文暂时取不到 | 明确反馈；**不拿旧值冒充当前事实** |

### 清单的存续与成本

| 场景 | 应当看到什么 |
|---|---|
| 一段连续多轮的协作，中间换过好几个 agent runtime | **清单不必跟着换**：定义版本没变、作用域求值结果没变，就一直是那一份 |
| 跨多次尝试复用同一份清单 | 各次尝试**依据的定义版本相同**（I-3） |
| 那些协程全都消失之后，追查「当时装的什么」 | **装配清单还在**，答得出来 |
| 看一个租户的成本 | 照这份清单跑出来的部分**归到启动它的那个租户**（I-8） |

## 二、绝不能发生的事

| 绝不能发生 | 如果发生了意味着什么 |
|---|---|
| 没有构成切换，仅改一项执行权限就导致 agent **不知道某件事存在**；或改一项**执行权限**，让它下一次运行里不见了 | 权限跑进了构成里。收紧权限从此既无法解释、也无法申诉 |
| 换模型导致清单被重算 | 系统提示词的成品被提前定死了 |
| 落点换了导致清单被重算 | **每次执行算出来的落点被当成了构成**。进构成的只有「需要哪几类环境」与「装进来哪些沙箱实现」 |
| 构成性变化**悄悄改写**了一份已经算出来的清单 | 一个进行中的任务莫名其妙地换了能力，且事后查不出当时是什么 |
| 上下文变化**打断**了正在进行的一轮 | 不紧急的事被当成紧急的处理 |
| 装配缺了必需的东西，仍产生一份被当作有效的清单 | 缺零件的 agent 跑起来，问题会在很远的地方以莫名其妙的形式出现 |
| 各次尝试复用清单时，依据的定义版本变了 | 同一段协作里 agent 中途变脸（I-3） |
| 那些协程消失之后，「当时装的是什么」查不到 | 排障与审计失去唯一的答案来源 |
| **给清单安排「回收」「释放资源」这类动作** | **把一份数据当成了活物**——清单不占资源，它只会失效 |
| 超级管理员能看到成员会话里**跑的内容** | 管理权越界。资源是组织的，内容是成员的 |

## 三、判据

| 设计点 | 做到了的判据 | 没做到时的表现 |
|---|---|---|
| 定义是数据 | 同一份定义在两个作用域装配，**定义本身逐字节不变**，两份清单不同 | 装配过程回头改了定义 |
| 清单是数据 | 一份清单被三次尝试先后复用，**它自己没有任何状态变化**（除追加） | 它带上了「在用 / 空闲」之类的运行态 |
| 成分与成品分开 | 照同一份清单换模型再请求一次，提示词**可以不同**而清单**没重算** | 换模型触发重算，或两次提示词被迫相同 |
| 已知能力身份单调 | 新增合法工具后可见；随后禁用、改定义排除或重建 Loop 仍有不可用条目 | 已知身份消失，或保留身份却绕过当前准入 |
| 权限变化不删除已知能力 | 按原边界生效后保留不可用条目，不把旧许可套给新绑定 | 将历史可见身份当成执行许可 |
| 注入不触及构成 | 执行权限、上下文各改一次（**落点随之按新值现算**），**清单逐字节不变** | 任一项改动导致重算 |
| 能力更新不取消已发调用 | 移除可选工具，已发调用不因更新本身取消；自身资源确实失效则沿执行失败规则，尚未发起动作核对当前状态 | 重发／暗换已发调用，或把未发动作交给失效／变更绑定 |
| 变化以内容到达 | agent 能在回答里**说出**它知道了什么变化 | 它的能力被改了但它说不出所以然 |
| 清单可追溯 | 那些协程全消失后仍能查到当时的构成 | 查不到 |
| 复用是常态 | 连续多轮协作里，作用域求值**只跑了该跑的那几次** | 每次尝试都重跑一遍求值 |

## 四、本版不验收的

| 不验收 | 为什么 |
|---|---|
| **agent runtime 怎么起、怎么被取消、取消怎么传播** | 归 [PF-012](../PF-012-agent-loop-and-run/acceptance.md)——含空闲回收、退役未结算、强制停止之后怎么报告、等人不烧钱、一个会话至多一个活跃协程 |
| 会话怎么建、怎么命名归档、历史怎么存 | **本 topic 不拥有会话**，只用到「一次装配为一个会话而做」 |
| 输入怎么受理、排队、调序、什么时候取一批 | 不拥有 |
| 谁决定现在该跑一轮、怎么推进、怎么收束、怎么中断 | 不拥有驱动 |
| 单次工具调用的观察、中断与后台接续 | 它有自己的生命周期，[绑在会话上](../PF-006-tools-and-skills/design.md) |
| 子 agent 的委派、监督与关系 | 另一件事 |
| 待决项的统一呈现与作答 | 那是跨会话的事 |
| 模型怎么供给、怎么路由、模型选择存在哪 | 归 SYS-LLM 与会话那一侧。本 topic 只定**模型在哪一刻被确定** |
| 崩溃后恢复到哪个合法位置 | 归 SYS-RUNTIME-CONTINUITY。本 topic 定的是**正常的装配与失效** |
| 资产目录里某能力明天是否仍被持有 | 归资产治理；会话已知身份仍须按本页保持 |
| 具体有哪些上下文项、哪些执行环境 | 本 topic 定它们**以什么方式进入**——上下文靠注入，执行环境靠装配留下的那两样——**不枚举内容** |

**这一节不是遗漏清单，是边界声明。**验收时发现上述内容缺失，不算缺陷。

## Skill、Tool、MCP 的统一绑定

下表的通用场景对 **Skill、Tool、MCP 三类分别执行**；meta tool、作业成果工具与 Skill 呈现场景按所列类别执行。MCP 一项指接入点资产，不把对端动作另建成资产。

| 场景 | 应当看到什么 |
|---|---|
| 定义关闭自动继承，作用域新增一个未被要求的资产 | 不自动进入构成；两类必须依赖照常绑定 |
| 类型要求与定义显式声明各要求一个能力，定义将二者都列入继承排除项 | 两者仍必须绑定，排除不能取消必需来路 |
| 相同能力同时来自类型要求、定义显式要求与自动继承 | 同能力标识不重复绑定，保持必需性质 |
| 开放到组织，各来源提供互不重名的额外能力 | 只自动继承组织范围的候选；不额外继承租户、工作区候选 |
| 只开放到组织，租户或工作区提供组织已有能力的同标识实现 | 该能力仍被继承，具体实现按完整作用域的既有替换规则选取；不因继承范围是组织就强制使用组织实现 |
| 同上，租户或工作区还提供一个组织没有的能力标识 | 额外标识不被自动继承；替换一个已有能力不扩大继承名单 |
| 某能力标识被排除继承，其他层提供同标识实现，且该标识没有必需来路 | 仍不继承；更换实现不能绕过排除 |
| 组织锁定某项持有为 `immutable`，租户或工作区提供同标识实现 | 仍绑定被锁定的实现；三类资产逐类验证，持有为 official 时同样成立 |
| 组织、租户或工作区尝试用同标识自定义实现替换 meta tool | 不允许替换；类型强制绑定和实现不可替换两项约束同时成立 |
| 开放到租户，各来源提供互不重名的额外能力 | 自动继承租户与组织候选，不额外继承工作区候选 |
| 开放到工作区，各来源提供互不重名的额外能力 | 工作区、租户、组织均参与自动继承；仍须通过既有资产资格与权限规则 |
| 开放到工作区但会话没有工作区 | 工作区来源为空，租户与组织仍参与；不自行附着目录 |
| 开启继承，排除一个非必需能力 | 不继承该能力；同名但不同类别的资产不受影响 |
| 类型要求或定义显式声明的必需能力缺合法定义 | 明确失败；两种来源已有合法定义但实现不可用时，都保留替换件 |
| 作业会话选择关闭自动继承的定义 | meta tools 与 PF-021 要求的成果工具仍在场 |
| 关闭自动继承后显式重载已选中的能力 | 可以更新该能力；关闭继承不等于禁止重载 |
| 显式 reload 发现额外能力 | 仍按相同范围和排除规则选择，不借 reload 扩大继承范围 |
| 显式 reload 发现试图覆盖 `immutable` 或 meta 的实现 | 既有替换限制继续生效，不借 reload 解除锁定或替换 meta |
| reload 候选缺少必需能力定义或 Loop 自身必要入口 | 校验失败，原数据不替换；工具实际实现不可用另按替换件处理 |
| 必需 Skill 被选入 | 满足绑定要求，但不据此强制全文进入提示词；呈现仍沿 PF-006 |
| Agent Definition 未声明自动继承 | 等同 false，额外能力不自动选入，两类必须依赖仍绑定 |
| 组织的自定义 non-master 未锁定，租户或工作区提供同标识 non-master 定义，继承声明不同 | 采用最终生效定义的整份声明，不合并旧定义的开关、范围或排除项 |
| 上级自定义定义开启继承，下级替换定义未声明继承 | 新定义按默认 false，不沿用上级 true |
| 组织、租户或工作区单独为继承声明配值，未替换 Agent Definition | 不产生独立字段覆盖，原定义的声明保持不变 |
| 组织、租户或工作区尝试替换 official Agent Definition | 替换不生效；对 official master、official non-master 都成立 |
| official 定义引用了允许替换且未锁定的工具能力，下级提供同标识工具实现 | 定义保持 official，工具实现仍按自身替换规则解析；不将定义锁误用为全部依赖实现锁 |
| 组织、租户或工作区尝试提供自定义 master | 不允许；三层可自定义的类型都只有 non-master |
| 上级自定义 non-master 的持有已标 immutable，下级提供同标识定义 | 替换不生效，上级定义及其继承声明保持有效 |

## 工作区来源的装配边界

| 场景 | 预期 |
|---|---|
| 只修改工作区 Agent Definition、资产或配置，未显式重载 | 不因文件变化或下一 run 自动更新已加载装配；下一次实际装配可读取新来源 |
| 有权维护工作区的用户修改 local 并执行 reload | 允许沿既有治理资格加载，不要求仅因资产来自工作区就具有组织超管身份 |
| reload 候选校验失败 | 明确报告错误，原内存数据尚未被替换；不先销毁旧构成再回滚 |
| Git remote 更新了文件 | 不强制即时通知或刷新 agent 上下文，agent 可按需读取和同步 |
| 组织工作区参与限制变化但未发生新装配 | 不在运行中热同步重判；其他权限规则不因此改动 |

## 定义身份与热重载

| 场景 | 应当看到什么 |
|---|---|
| 同一身份定义发布新有效内容 | 新 Run 取得新内容；同 Run 的普通恢复使用当前已生效版本；显式 reload 可安全交接到同身份新版并开启新尝试；历史采用依据不改写 |
| 更换工作区或请求更换另一身份定义 | 不改变本会话固定的定义身份 |
| 新定义减少依赖或改变继承声明 | 后续按新声明求值，类型必需身份集合不变 |
| 同身份工具实现热替换 | 按既有来源锁定与生效边界采用；旧工具执行仍可追溯实际使用的旧实现 |

| 本会话移除一个自动继承的可选工具，之后重新装配或恢复 | 移除声明继续参与求值，工具不被自动装回；撤销移除后仍须符合当前定义范围 |
| 新定义将此前本会话移除的可选能力改为显式必需 | 必需绑定优先并说明来源；会话移除不破坏强制依赖 |

## 装配矩阵与撤除原则

| 场景 | 验收要求 |
|---|---|
| 同 Run 显式 reload 同身份新定义 | Run 身份保持，新尝试采用完整有效清单，旧实例不再推进；历史版本可追溯 |
| 只换模型、权限／环境取值或动态 context 内容 | 不因这些值变化强制重装配；各自按下一次消费或准入点生效 |
| 允许范围内增装非常驻可选项 | 可追加；不能借增量绕过必需项、继承范围和覆盖锁 |
| Loop 自身必需入口撤除 | 不能以失效入口假推进；工具背后服务撤除只按其实际依赖传播，保留能力替换件 |
| 一次 MCP 请求失败 | 沿调用层既有失败规则；不能只因失败就循环重建整个 agent |
| 只替换 Agent runtime | 不连带终止模型／工具；若其自身资源真实失效，则显式按其失败规则处理 |
| reload 未变化或校验失败 | 可区分无变化、失败与实际生效，不部分替换；不承诺已失效旧依赖仍能运行 |

## 数据、实现与服务解耦

| 场景 | 验收要求 |
|---|---|
| Tool 实现更新而定义和入口不变 | 后续合法调用采用新实现；Loop 不重建，已有执行保持原输入 |
| argsSchema 更新而承载服务不变 | 后续请求取得新声明；旧模型建议按当前约定核对，不自动执行；Loop 不因此重建 |
| Skill 正文更新 | 下一次合法读取取得新内容，已读内容不回写；不重建 Loop |
| 已知能力卸载后换定义排除，随后提供者回来 | 仍不可用；恢复必须符合当前选择和治理 |
| 对 Loop 无直接依赖关系的工具服务换代 | 只影响实际消费者；不能无理由扩大为整个会话重建 |

## 派发与归档裁决验收

选择可用的 master 定义执行 spawn／delegate 时允许创建子会话；不会将它变成 handoff 的独立主会话，且不绕过派发权限或 official 不可替换规则。
