# D-069：拒绝无法判等的 Skill YAML 自定义标签键

- 当前状态：产品负责人已接受这一拒绝策略；新版本表达、发布、实现与验证分别待完成。
- 来源提案／研究：[Skill 规格形状](../../proposals/skill-spec-adoption/README.md)、[规则层与开放格式调查](../../../../research/skill-spec-sources/research.md)，沿用D-034；具体已观察缺口为 [Skill SP-3](../../../realization/packages/core/skill-package/design.md#实施缺口与消费者影响) 与 [此前实际217/221技术接受](../../evidence/2026-09-26-tests-core-final/README.md)。
- 实际接受依据：2026-09-26，产品负责人对问题「Skill 文本有一处未定规则：未知 YAML 自定义标签用于键、且其含义导致无法确定是否重复时，应该如何处理？现有规格既要求拒绝重复键，又要求忽略未知属性，没有定义“判等未知”的结果。」明确回复 **「补规格：拒绝这类无法判等的输入，普通未知属性仍忽略（推荐）」**。

## 已接受范围

当Skill文本frontmatter映射图中，未知／未支持自定义标量标签用于键或复杂键内部，且标签canonical知识缺失导致不能确定键唯一性时，整个文本读入拒绝。拒绝沿用 `malformed`，来由沿用M16；由该文本读入构成包的路径承接同一失败。普通未知属性仍按S-5忽略、留可见痕迹。不能仅因出现未知标签、解析器警告、普通未知键或被忽略属性的任意值而拒绝；仍先核完整映射图的解析有效性与键唯一性。

本决定只裁新输入域结果。不定义tag加载器、插件、外部解析服务或动态扩展YAML schema，不改变JSON规范化包形状、正文逐字、不展开／不执行、八拒绝值、既有确定拒绝次序。缺少键判等知识不再把成功与拒绝之外的“未判定”作为新版本结果。

## 精确版本与取代范围

冻结 `data.skill-package/2` 三资源及既有记录不原地改。发布 `data.skill-package/3`，仅补S-20／S-24 M16并使S-5／S-21的处置前提一致；Schema结构与依赖原图不改，只有自身坐标元信息（$id、顶层title及顶层description的本文件作用域）升3。其它契约继续精确钉其既有Skill2；新推荐不自动升级AM／Slash／AE／外部调用方。

本次用明确新策略取代SP-3在新3文本读入的“待裁”状态；旧2的语义空缺、此前部分结果和运行原件保留原适用范围。实现公开入口采用须先写清：新3文本读入／规范化值入口、完整原2Schema、既有AM3采用的2正文端口各自的坐标与映射，不能用新$id冒充旧2，也不为未要求的旧文本缺口新建行为兼容层。

技术规格由主调度按已授权的技术验收流程接受；人的总体门仍由产品负责人签。本决定不扩大Connector、运行时或阶段外实施范围。
