# D-081：采用日志追加时比较已读取尾的演进方向

2026-09-27，主线依据用户“Implement the plan”、继续按已接受 spec／realization 实施及“作为主调度者和验收者”授权，在技术选择范围内采用 [late-coordination.md](../../proposals/model-request-adaptation/late-coordination.md) 的**候选 B 方向**。精确来源 SHA256 `ba2e68bf7e404a9fdb1d6ef16f8e7bd9df86891eb6096b14dfc6eb8814538c05`；[独立架构评审及可恢复输入](../../proposals/model-request-adaptation/review.md#2026-09-27-late-提交协调方向独立架构评审) 无本次方向阻断。主线执行技术采用，责任归指导本程的实际负责人；这不是人的总体交付签收。

## 接受范围

演进已有 session-log 的追加承诺：调用者从一次合法完整权威读取得日志事实与尾，依据其中原发出 attempt／Run 状态构造响应；追加在同一提交点比较该尾是否仍成立，成立才原子提交完整响应／消息批，不成立则本次整批零写。所有响应结算写方采用同一保护；一般 Run 事实写方仍只向同一权威日志追加，不要求另写协调标记。

日志继续拥有不透明载荷、共同提交顺序、判重及恢复；runtime／回复生产者拥有 late 判定、原 ResponseId／MessageId 与批次认回。不新建协调服务，不把 Run 认法或业务授权交给日志，不增加第四操作；独立无 Run 的 invokeModel 不因此依赖日志。未知回执必须先按稳定身份认回原整批，不能把之后的条件冲突或 fence 失效解释成之前未写。

此决定只选方向，**不接受字段形状、失败枚举／优先级、新版契约、provider 或消费者投影**。精确规格、必要形式工件及日志/runtime/回复消费者需另行起草、独立表达和架构核对、明确采用，之后才能施工。当前 SL2 冻结资源不变，B1 withRun 的原阻断仍在。

## 理由、取代与保留前提

该方向将准确 late 与批次写入保护放在已有共同物理提交对象上，保持 MR4/CA2 持久表示；避免 A 的逐批额外协调记录及全相关事实写方协议，也避免 C 的响应表示及全历史读面迁移。它不是已测性能结论：全尾比较会受无关追加影响，必须用可配置争用重试／退避和实际提交机会说明有限进展，耗尽后恢复归属不丢。

D-076 既有准确 late、原归属、回复同批和恢复要求全部保留；只取代其运行时 L-4 中“预读事实后普通追加即可保护实际提交时 late”的充分性判断，不撤销其他采用。可恢复反例是预读之后新 attempt 或同 attempt 终结先落，旧响应随后写入不晚。归档有限实验能区分这类交错，不能代证真实日志、丢回执、权限、旧 writer 静止、Run 终结识别或无限竞争。

下一产物由日志契约 owner 明确条件、完整前缀、缺席及失败／恢复关系；runtime 与回复 owner 明确完整批次键、合法读取、原 attempt、认回及全部写方传播；provider 与装配 owner 明确共同文件对象、耐久／重启、旧 writer 停止和宿主排空。真实 Run owner 的生产终结表示尚未闭合，验收驱动仅能认证自己实际生产的记录。多值响应头 G2-6、opened 未知恢复、模态与完整 Agent Loop 缺口不因本决定关闭。

若合法完整前缀不可得、三操作恢复无法表达，或真实争用反例否定承诺的进展前提，应按原候选和强反对理由重比 A/C，不先降低准确 late、判重、原样载荷或恢复保证。
