### 资产的复制与分享（→ PF-003 rev 5）

| 项 | 原话 | 含义 |
|---|---|---|
| 隶属解除后再隶属 | 「不复活，应当重新分享，因为分享是双方确权的一个动作（同「邀请」），解除隶属关系可以认为是分享方取消对另一方的共享或者被分享方自己放弃了对共享来的资产的使用权」 | 分享结束是终态；重新分享是新的一段。落法不依赖解除事件：读时谓词加「隶属建立时刻 ≤ 分享确认时刻」 |
| 普通成员复制进团队 | 「普通成员可以将来自自己这个账号的个人组织的资产复制进组织，这个动作不需要超管确认；但是普通成员不能将不在同一个棵隶属树的非个人组织的资产复制到另一个非个人组织，当然也不能从任何非个人组织将资产复制到自己的个人组织」 | 本人型复制不需要第二人确认；跨树、团队→个人一律不可 |
| 落在哪一层 | 「普通成员复制进来的资产，是隶属租户下的，不需要超管确认；超管复制进来的资产可以选择是组织级别（所有有权限的租户可以使用）还是他自己这个租户自己用」 | 普通成员落自己租户级；超管可选组织级或自己租户级 |
| 三条规则 | 「1）同一项资产，在同一个组织内，资产的所有者可以选择向任何人开放（共享）这个资产的使用权（被共享者用不用他自己确认）；2）同树的资产只能组织 - 组织的复制或分享；3）自己的资产可以任意复制或分享到自己在其他组织的另一个租户下，只要不是团队组织到个人，或者跨树」 | 组织内分享是分享的一格（接收方为同组织租户）；同树跨组织只有组织—组织；本人的资产可到本人在别处的租户 |
| 矩阵与四处改动 | 「共享和复制这块的，确认了，就按照最新的这套规则矩阵来」 | 矩阵原样进 PF-003 §6.2；组织→组织复制允许（目标超管确认）；个人→我在团队的租户级可分享；跨组织不落别人租户级；原「组织级不能复制」「个人→团队不分享」作废 |

## 主线自定，待确认

下列由主线在裁决之后推出、已写进正文或契约，**不在本决定的接受范围**，产品负责人未反对即维持，反对则改：

- 「共享」不另立词，组织内那一格是接收方为租户的资产分享；组织型复制在目标侧的作者 =（目标组织, 确认的超管）；「待确认的复制通知与分享邀请」「一段分享关系」都是对象；再复制一次时血缘按落进的那一层找（PF-003 §9 裁 B）；退出组织再加入分享同样不复活。
- 拓展件不可用处置第一版只两种取值（跳过／否决）加自带件的替换件；系统自带放行判断的替换件是全拒件。
- MCP 对端动作缺说明时由桥做最小规范化补占位说明，不当它不可用；接入点 name 登记时收窄到可转写词法。
- `data.model-profile` S-3：组织层与租户层的自建档案可同路由名并存（与「自建名在隶属树内唯一」的旧读法相左，**已明确请产品负责人确认**）。

## 理由与保留前提

三份拆分各自的理由与代价在各提案 `alternatives.md`「推荐与改票条件」，三票的反证互不重复，记录在 `review.md`；接受的人须明知 assets B 下「血缘对应不出流转一方」只靠读面测试与评审守。
「两块运行时归 `apps/cli`」以 realization 准入「没有 PF 的应用不建节点」为据，且产品负责人认定它们本质上是 CLI 这个应用里的东西——「可独立运行」是验收要求，不是装配边界。
`tenancy-host` 不改名的代价是名不副实，由节点 README 的显式记录承担；改名牵全仓链接，等中心侧装配内容稳定后一次做。
「模型面只有 flat」以本项目自建参数校验层为前提，产品负责人明说 omne-next 的 typed-union 是 LangChain 严格类型校验所迫。
