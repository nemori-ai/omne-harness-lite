# CLI 关闭尝试与实际静止的限定修正

状态：设计已采用，产品实现及独立 L3 尚待。
负责人授权主会话继续整改。主会话于 2026-10-04T23:23:59.967328+00:00 在委托内采用本修正，不表示负责人逐条亲审。

依据为[原补充](../identity-t3-binding-coordinates/decision.md)、[原D0](../identity-integration-design/decision.md)
及 CQ1 S10、CQ2 S10/S11、CG2 S11 的有效业务承诺。精确修订见[inputs](inputs.json)。
原补充对CG关闭拒绝及表示恢复次序的投影不完整：一般 OwnedWork 拒绝已承诺静止，而原CG拒绝没有这个许可。
本次取代原补充的CLI收尾投影，并给 managed CG 增加具名关闭观察资源；工厂、Schema、业务结果与独立绑定不变。

采用[CLI生命周期](../../../architecture/identity-integration/cli-lifecycle.md)：

- 绑定在分配CG之前交付稳定原关闭尝试；公开close观察原结果，管理行只在成功后完成，拒绝时保有依赖。
- 应用保存CG行的实际登记回执，在既有停止屏障之后区分未登记、已登记未观察和已观察。不能等待不存在的行回执或以服务不可见判断无工作。
- 输入/输出真实结束和恢复完成后才许可CLS关闭。CG关闭拒绝仍报告70及原诊断，不恢复、不撤CLS、不伪报整体closed。
- 复用原lifetime及startAssemblyWork，不扩展公共OwnedWork，不增加第二协调器、超时放行或重试政策。

连续反例按手册先作结构诊断，根因为混同业务关闭、行排空和表示收场三个事实。责任表和三轮处置保留输入。
Choice和Expression对最后冻结快照无阻断；审阅意见不是接受。
真实既有Cordis/lifetime探针修正了首轮无登记覆盖不足，覆盖6个正分支及1个负控。合成工作行不代替正式产品验证。
原CQ两模型13配置（2正11负）符合预期，原有限/进展前提保持，模型不覆盖close异常。

T3-S1仅在独立M05基线冻结释放后实施。绑定/CLI还需QA按本修正冻结差量场景；整体T3和R1仍开放。
