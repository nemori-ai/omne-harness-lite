## 采用范围

- `assembly-lifecycle/src/retained-work.ts` 加入既有 assembly-lifetime-mechanism，层次为 assembly，domains 为空。
  它拥有原关闭尝试的保有与完成协调，不属于纯数据定义。
- content-blocks 仅 `src/index.ts` 与 `src/json.ts` 采用精确 contract/context 角色。
  依据是公开 JSON 表示、严格读取、复制和写入边界；其余内部文件保持原候选责任，不把 `src/**` 整体提升。
- 保有关闭采用 assembly-lifecycle 的公开类型和模块 SPEC。
  行端口必需的 `retainClose` 只交付原行控制，整体 `closeControl` 只归实际装配拥有者。
  方法返回 undefined 或尝试返回 retained 均不表示静止，也不许可释放依赖。
  显式重试不自动决定安全性，普通 startAssemblyWork 的关闭失败及错误记录不被取代。
- 插件树采用模块的六字段声明和静态／动态匹配规则。
  固定 host 拥有动态贡献；能力是否可用、换代、工作失败和收尾仍归原领域协议。
  固定行失效、静态服务丧失或同键新实例仍须结束整代。
  原八个 R1 管理绑定继续使用静态依赖及空动态集合，不通过改标 dynamic 绕过停止责任。
- JSON 薄规格接续 README 的既有严格无损边界。
  普通 getter/toJSON 不被求值，不承诺 Proxy traps 零执行；成功复制不授予领域读取或授权权限。
  调用拒绝表示及 Tool Runtime 的既有采用范围保持，不由本记录提升其实现状态。
