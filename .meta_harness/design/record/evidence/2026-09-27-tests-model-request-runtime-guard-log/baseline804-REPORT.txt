## 产品反例

[diagnostic-minimal-final.mjs](diagnostic-minimal-final.mjs) 是无测量 hook 的公开入口最小复现，精确 source 与实际 argv 在 `diagnostic-minimal-final-command.json`。先以 `{ dir, processOwnership }` 开启、追加 dedupe `stable`、close；然后以相同物理 current 重开，传 `diagnostic(event) { throw new Error('DIAGNOSTIC_SINK_SENTINEL') }`，调用 `readSince('s', 0)`。

预期原历史 tail 1 仍可读，实际抛出 sentinel。栈由 `dist/recovery.js:67 enterRecovery` 经 `dist/resident.js:50 initializeResident` 到 `dist/open.js:161`；完整栈保存在原始 JSON/stderr。失败读取时另一个公开 owner 无法取得 root，实际错误为经过清洗的 `session log IO failed at initialization`。最小复现随后 `second.close()` 成功，这是与早期“第一次 close 遇 throwing sink”不同的轨迹；早期轨迹 close 失败且终止前锁仍保留，原件亦保留。不能把两者混为同一清理结果。

主矩阵失败的 observer 对象在异常前仍持有 root FD/SQLite；这是异常前快照。实际 Node exit 1 已由父进程 wait，后续独立 root 锁复取证明 OS 资源释放。没有声称失败发生时已经排空。产品源码保持原字节，反例已交派发者修复。
