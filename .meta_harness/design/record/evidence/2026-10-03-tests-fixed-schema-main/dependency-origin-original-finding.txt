## 阻断

### DO-1：变量的初始化基点被当作调用时基点，重赋值后遗漏真实文件和外部边

检查表第 9、10、14 问；位置为冻结提交中的 `tools/core-verification/src/dependency-surface.ts:88–92`，后续使用点为第 141 行。

`requireOrigin` 取 `symbol.valueDeclaration.initializer`，接受任何 `VariableDeclaration`，既不限制不可重赋值的声明，也不核对可见赋值。后面的 `createRequire(...).resolve` 因此能得到一个真实存在但不是运行时实际读取的文件，整次扫描没有报错。

**已执行反例：**夹具 `src/index.mjs` 为：

```js
import { createRequire } from 'node:module'
let require = createRequire(new URL('../package.json', import.meta.url))
require = createRequire(import.meta.url)
export const value = require('./generated/start.cjs')
```

两个目标均存在。根 `generated/start.cjs` 只导出 `{ selected: 'package-base' }`；`src/generated/start.cjs` 导出 `selected: 'source-base'`，并读取 `require('node:fs').readFileSync`。所有模块名均为字面量，没有需要支持任意计算式模块名的要求。

实际输出保存在 `supplement-dependency-origin-r1-evidence/let-reassignment/result.json`：

```json
{
  "actual": { "selected": "source-base", "readFileSyncType": "function" },
  "scanned.external": ["node:module"],
  "omittedExternal": "node:fs",
  "omittedFile": "…/src/generated/start.cjs",
  "counterexampleReproduced": true
}
```

扫描清单反而包含根 `generated/start.cjs`。复现脚本对真实 Node 结果、错误文件清单和遗漏的 `node:fs` 均有断言；冻结 HEAD 与被调用扫描器的 SHA256 一并写入原件。扫描器 SHA256 为 `b665e2533547a0f7985996503f6f4064b165793686b8bdcefb68c590c2cf7e7b`。

**违反的约束：**`tools/core-verification/README_ZH.md:100` 要求识别受控文本中的 require 边，并且“不能把不可核对的动态路径当通过”；第 102–104 行将读取文件及 hash 作为受控入口图证据。本增量的 `requireOrigin` 注释和提交说明进一步承诺对未知来源拒绝。此反例在已识别的 require 调用中静默选择错误来源，产生成功但不完整的文件／依赖清单。它不是对通用 JS 解析器的额外要求：无法确定该绑定时拒绝，也能守住原边界。

**后果：**真实运行时外部边可以从库存中消失，依赖例外断言或归档的 source graph 因此可能被错误放行。对这个具体输入，原扫描器按源码目录解析恰好会读到 `src/generated/start.cjs`；本次采用初始化基点后将该真实边移出了清单。当前产品的固定 Schema loader 使用 const，原 ENOENT 已修复，但不能因此把新增来源判定的这条错误成功路径视为成立。

**实施者需要完成的事：**对调用时来源无法由受支持绑定确定的情况明确拒绝，或正确记录其真实依赖；增加会对上述漏边失败的回归。不得通过删掉库存断言、忽略错误文件或排除 require 边使检查变绿。本报告不修改产品，也不要求实现通用赋值流分析。

## 范围外待裁决

按 ROOT 补派要求，只读核对了原生 CommonJS 未声明 require 的可见重赋值。下面的 `.cjs` 内容可改变 Node wrapper 中的 require 参数：

```js
require = require('node:module').createRequire(
  require('node:path').join(__dirname, '../package.json'),
)
module.exports = require('./generated/start.cjs')
```

源码单文件 binder 看不到 Node wrapper 参数的声明。当前第 87 行在 symbol 缺失时无条件采用文件基点，仍会忽略这种可见写入。若根与源码目录各有不同图，同样可错误记录源码目录的图。**这段只读判断未执行重现，而且原扫描器已存在相同限制，不计作本增量第二项新缺陷。**只限制有声明变量为 const，不会约束这个分支；若新来源判定承诺覆盖 native require，就需要对这种可见写入拒绝或准确处理。此判断只涉及明确赋值，未扩展到 eval、跨模块全局变更或完整语言解析。
