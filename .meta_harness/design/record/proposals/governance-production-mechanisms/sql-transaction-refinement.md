# 生产登录与治理事务组合 · 候选 r2

输入：[登录 r3](login-finalization.md)、PF-001 rev17、PF-017 rev4；旧提供者、入口契约与 Storage 接口为已接受基线。本文不接受新服务面，也不要求修改已冻结契约。目标是给下一版 AI/OG/entry 的精确契约提供实际可落实的事务边界。

## 当前路径与需要改变的事实

- `LoginsImpl.exchange/verify/listEffective` 用 `storage.read`，`judgeLoginState` 只看账号激活和撤销。新增时限后它们将成为模型 Observe，不能绕过正在提交的活动更新。
- entry `authenticated` 先 exchange，再 `memberships.currentTenant`，再补授权，最后单次调用领域方法；每个服务自行提交。这个编排不能同时保证登录仍有效、当前租户与预期一致、业务与活动一起提交。
- OG `currentTenant/switchCurrentTenant` 在自己事务外调 AI verify；账号事实读取也有独立事务。若仅把整个 route 包进 storage.write，现行 P-1 的嵌套调用禁止会明确报错；不得静默放开嵌套。
- AI/OG 的通知在各自 storage.write 返回后派发。若改变提交边界却保留原派发点，就会在最终提交失败时发出不存在的业务通知。
- clock.now 的租约来自独立写服务；共同事务内只读当前已建立的可信时间，不能等待需要同一写锁的续约。不可用就整体回滚，释放锁后由既有续约流程推进。

## 三条实施路径

| 选项 | 可维护的责任与代价 |
|---|---|
| A：明确的事务作用域服务面 | entry 组合拥有一次请求的提交；账号/治理提供者各自导出只能在给定作用域内执行的同语义操作。原普通服务仍独立提交；两面共享内部业务函数。通知统一延后到真实提交后。改动较多，但边界和失败显式 |
| B：让 Storage 通过隐式上下文自动合并所有嵌套 read/write | 调用代码少改，但撤销现行嵌套即缺陷的规则，服务返回不再等于提交、通知也可能过早；异步游离工作可能逃逸作用域。不能仅改 ALS 就接受 |
| C：业务先提交，再单独 touch 登录 | 实现局部，但时钟/存储故障可留下业务成功却没有成功活动；不能兑现本次同提交要求，也不能解决预期租户与授权竞态 |

推荐 A。复用现有 SQLite/PG 事务能力，不造第二套事务日志、自动补偿或跨进程协调。此选择尚待评审；提供者节点在接受前不得据此改代码。

## A 的明确协议

entry 组合先完成不需要存储的版本/信封/路由识别及出示物缺席、重复、表示层检查；这些确定答案不因存储不可用变成 unavailable。只有需认人的合格输入才发起有边界的一次治理请求。免认证 register/login 继续专有动作链；改密的昂贵凭据比对/派生在写事务外完成，事务内重核快照和发起登录。

内部公共作用域仅由提交拥有者创建，包含当前 WriteTx、不可伪造的存储实例关联、仍开放标志、提交后通知队列；不能保存给下一次请求、交给后台工作或跨进程传递。每个 owner 用它创建**不同于普通服务的事务面**，不冒充普通 Storage 的独立提交语义。作用域关闭、实例关联不匹配、未许可重入或并发分支使用时立即报缺陷；事务面必须由其所属提供者核对关联，不能仅信传入的 tx。业务函数仅接受 owner 的执行上下文；普通服务通过独立事务运行同一函数，事务面直接使用已有 tx。

一次受认证业务执行顺序：

1. 在共同事务中由 AI 按出示物派生句柄并锁定所属账号、该登录，读可信时间，判有效；尚未核身份的恶意输入不能选中任意账号锁。行不存在仍按拒绝收场。
2. 载荷验证沿 entry 的既有次序；需要当前租户的操作由 OG 在同一事务读真实选择，并与请求的 expectedTenant 比较。不匹配不执行目标操作、不 touch。
3. 授权与组织变更沿 OG 的组织锁和末位超管不变量；读路由的补授权与读取也在这次事务内。业务成功的定义来自路由的领域结果集合，不靠 HTTP 200 或有没有异常推断。
4. 业务成功后 AI 再读当前可信时间，按 r3 检查未撤销/代际/两个截止后决定 touch。已过期的在途业务可以按准入成立的结果提交，但不复活登录。最终时钟不可用则整个事务抛出回滚信号，入口映射 unavailable。
5. 只有外层提交成功，才发布通知并输出成功答复。提交异常不得把回滚请求等同于确定未提交；客户端沿 unknown 收场，不自动重试非幂等动作。通知失败不得改说已提交业务失败。

已接纳操作与后来撤销的次序由锁序列决定：持锁操作先提交，则撤销随后成立；撤销先成立，则后来准入被拒。不得把先前独立 exchange 成功当作后续写的永久许可。

## 观察路径清单

| 路径 | 必须用的边界 | 是否成功活动 |
|---|---|---|
| entry 初步认人/业务准入 | 同一次请求事务的 AI 事务面；旧独立 exchange 不作为许可缓存 | 只有最终业务成功才算 |
| 单独 AI verify/exchange | 独立写事务取得同样账号/登录锁，读取可信时间；即使只读也不能走裸只读连接 | 否 |
| AI 有效登录列表 | 调用账号锁后读所属登录，统一时刻过滤；锁与该账号的签发/改密/撤销/touch 共用 | 作为 entry 成功业务时是；纯内部列表不自行伪造业务成功 |
| OG 当前选择查询/切换 | AI 同作用域校验，再查询/更新 OG 选择；独立调用则建立完整作用域 | 由 entry 成功结果负责 |
| OG 选择清扫 | 每个句柄的有效性观察与删除共同作用域，不用“先 verify 再独立 delete” | 否 |
| 注册组合 | 不依赖登录，但继续通过普通账号/治理服务；不能被隐式拉入 entry 新事务 | 否 |

## 本期数据库边界

本期新组合仅兑现 SQLite，所有涉及有效性或治理授权的调用共用 `BEGIN IMMEDIATE` 事务边界（包含不写事实的观察）。共享 storage-sql 的 PostgreSQL 方言保持原有独立协议；**不宣称新版组合可在 PG 运行**。新版生产中心的 PG 配置必须在启动/开闸前明确拒绝，不能退回旧的无限登录或不同事务边界。共享存储与其他消费者不受此项装配限制。

PG 后续精化尚需明确账号、登录、组织、邀约、AFFILIATION_SENTINEL 的完整顺序，并覆盖独立与参与面。当前组织邀请授权并不都锁组织行、隶属 sentinel 与组织可能逆序，因此本稿不作 PG 无循环锁/共同授权承诺。跨账号撤销仍应先读目标的不可变归属，不属于调用账号则同不存在拒绝，不能拿外账号登录锁再判归属。

## 唯一事务终结边界

现有 `entry.invoke` 的 catch 与 AI `storageUnavailable`、OG `withStorage` 的异常映射不能搬进外层事务。共享的内部业务函数不吞存储异常；事务面直接传播需要回滚的异常、最终时钟失败及缺陷。普通服务在自己的事务已结束后映射；组合在外层事务退出后映射。嵌套 Storage 仍报缺陷，不因这次组合静默合并。

事务中的结果必须先通过其规范结果集合、形状及出站 Schema 核验；集合外返回、成功体转换/编码失败抛缺陷，使整个事务回滚且不派发通知。预生成的成功字节只作为待提交结果留在内存；实际网络发送与日志中的成功结论都在提交之后。网络发送失败不倒退提交，不撤销活动。

具名拒绝不一律回滚。允许拒绝前提交的事实只能由对应 owner 明列：当前已知是 AI S-13/S-14/S-18 对未激活账号首次到期的单调落盘，须保持账号边界与既有通知规则；注册组合仍走其专有提交链。其他本次受认证路由若拒绝，不能留下团队创建键、组织、成员、邀请、选择或活动的部分变更。精确实现需逐操作核对列表；遇到新的“失败也写”路径，先由 owner 登记语义，包装层不能按字符串猜。最末时钟失败和异常回滚仍撤销本次事务中全部写入，下一次观察可重新建立到期事实。

通知仅为提交后尽力派发，不升级为可靠消息。真实提交拥有者在确认提交后释放一次队列；回滚丢弃，提交未知不假称已送达。数据库锁释放后派发，不等待监听者完成，监听者失败不把已提交业务改报失败。

## 精化验证义务与限制

- 模型 LoginCommit 的 Stage 映射为最终时间判定与活动暂存；只有成功提交的操作可回溯到这个线性化点。业务效果/临时活动/通知在提交前不对外可见。
- 在真实事务中故意暂停 touch 后、commit 前，另一连接 verify/list/current/query 均不能先宣布旧状态到期；去掉观察锁的负控必须能重现模型反例。
- 在业务已写、最终时钟不可用时，数据库业务行与活动都不变，通知为零；恢复时钟后正常请求可继续。
- 改密与凭据比对/签发交错：旧快照不能借新代际签出有效登录；改密成功后的所有旧登录拒绝，新增合法登录可用。正常重启保留代际及时间。
- 预期租户比较、成员授权/撤销和实际操作同提交；两客户端切换竞态不能让操作落进另一个租户。
- 首次升级到有界登录应使旧无限登录失效；后续重启/升级不能重写签发时刻。迁移失败沿 guard 撤回，不把迁移候选当已提交。

尚需新版 AI/OG/entry 的操作、失败集合及 wire Schema，作用域类型/节点绑定与通知收尾设计，Linux/macOS SQL 实验。它们未完成前本稿不是可消费实现规格，也不开放生产部署。

## r1 定向评审处置

独立评审指出提前把异常转换成 unavailable 可能提交半份创建键，以及 PG 锁序/授权共同保护没有闭合。r2 增加唯一终结边界、拒绝可留事实的 owner 清单、提交前 Schema 校验，并明确首版仅 SQLite；PG 的新组合实施延期。版本/信封/出示物的确定拒绝在开事务前完成，作用域绑定同一存储实例，通知仍为提交后尽力派发。待复审，不代接受。
