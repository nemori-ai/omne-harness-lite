# 可选路径与实际采用

双方在同一 baseline 下将不同的组织治理正文冻结为 v2。main 的生效时刻用于资产分享不复活；draft 的拒绝与共同参与用于已经交付的治理中心。双方同号决定分别记录了不同接受事件。

| 路径 | 后果 | 判断 |
| --- | --- | --- |
| 迁移 PR #9 的决定、产品修订和规格引用闭包 | draft 的 173 项冻结资源、协议与实现继续按原坐标消费；#9 的原字节保存在固定输入快照，34 份规格获得后移坐标 | 用户本会话明确选择「统一我们的编号整体往后挪」；采用 |
| 迁移 draft 的治理规格与消费者闭包 | 需要迁移至少 11 个契约版本、119 项资源及对应提供者/协议绑定；#9 的坐标保持 | 违背本次编号方向要求；不采用 |
| 合成一份同时提供两组承诺的新组织治理契约 | 必须重新设计 AI/OE 版本组合、条款编号、提供者与消费者，并验证拒绝/共同参与与时刻写入的组合 | 新业务规格及实现超出本次行政身份协调；不采用 |

采用路径的闭包同时计算 catalog 依赖、冻结正文、Schema 与模型中的精确引用。仅按 catalog 得到 OG 与 AT 两份，但正文和 Schema 反向引用继续传播到 #9 全部 34 份契约。因此迁移 146 项资源；不把 OG3 声称为 draft OG2 的功能超集。

原 main 和 draft 的完整设计输入、逐资源映射及实际检查由[本次证据](../../evidence/2026-09-26-checks-pr9-pr10-reconciliation/README.md)保存。
