# 多值响应头的表示与函数事实交接候选

2026-09-27，rev 1，candidate，未接受。接续 [RT4](../../../spec/capabilities/model-request-runtime/v4/contract.md) G-31 与 [MR5 candidate](../../../spec/data/model-response/v5/contract.md)。这是一项已有响应留存性质的承接，不新增领域对象、服务操作或平台。本轮已读机制，不声称双盲。

## 既有承诺、具体缺口与责任

MR4 S-20/S-21/S-22 要求采得的上游原始事实经写前脱敏后留存，保留原值、写后不变、凭据不进入响应任何成员；留存缺席不等于空对象，留存失败不另造一次模型失败。RT4 S-16 明确响应头不是首 token；S-54 是未结算函数结果，S-58/S-59 分别拥有真实发送／读过程，S-17/S-49/S-70/S-73 拥有响应和消息最终结算。

已观察的缺口有两层：TransportFailure 的头值有数组，而 MR4 只有 string-map；独立 invokeModel 的结果没有响应头事实交接，且错误读体取消会丢掉此前采得的头值。具体源码观察由本 topic 的消费审计及本次冻结输入支持，不把接口名字当真实 IO 证明。

头值含义归 data.model-response；运输面采集和写前凭据脱敏归 transport，单次调用结果归 runtime，持久响应／消息整批归既有结算者。Cordis 不提供原值留存、秘密保护或耐久同提交。这些责任不移入 kernel、事件广播或模型定义插件。

## 表示轴的三个实质候选

| 路径 | 优势与承接 | 成本、最强反方与改票条件 |
|---|---|---|
| A：原 map 的 string 或 ordered string[] 原形 | 直接承接当前实际采得且脱敏后的 JSON map；保留单值、次序、重复及空值，MR4原单值域保持同义 | 消费者必须处理两个值类型。若产品要求逐 HTTP 头原线序／重复名跨键顺序，本表示不足，须回 C 而不是假称 map 有这些事实 |
| B：所有值规范成 string[] | 消费者只有一种值类型，可统一遍历 | 把已采得 string 改成单元素数组，原样结构丢失；仅在产品明确改为规范化表示而非留存原形时改票 |
| C：ordered header-entry-list | 可直接表达逐头条目的重复名和次序 | 当前采集是 Node 解码后的 map，线序已不在这个值里；必须改采集边界、头名及脱敏碰撞策略、相关消费者，不可从 map 捏造线序。真实线序需求出现才采用 |

本候选建议 A；MR5 candidate 按此起草。允许空串、空数组及空 map，分别原值保留；缺席与这些值不同。拒绝非字符串数组成员、嵌套数组、null/对象/数字。无 join、取首、去重、排序、trim、stringify 或头名新归一化策略。采集边界仍是运输面已取得的 map，不声称 Node rawHeaders 或 HTTP 线序。

## 交接轴的三个实质候选

| 路径 | 优势与承接 | 成本、最强反方与改票条件 |
|---|---|---|
| A：S-58 结果交出同次已采得的头事实，S-54保留到最终结果 | 成功响应、HTTP错误、已取得头之后取消均有共同交接；泛型响应保持不透明；读流或门失败不会擦掉已交给调用者的事实 | 增一个明确可选结果成员及所有提供者接线。若真正存在 send 结果之后才采得的协议头，须扩展精确事实交接而非让本字段猜其值 |
| B：只在 S-59 最终 StreamEnd 给头，失败仍从失败对象取 | 最接近当前 reader 的实际执行方，不改 send 成功结果 | 取消、reader未进入、解析异常或没有最终yield时可丢已采得事实；两条权威路径还须定义冲突优先。只有能证明所有分支都完整交接且责任更清晰时改票 |
| C：独立 header callback／另读事实端口 | 能在头刚采得时独立交接，便于更早观察 | 新回调与取消、卸载、门和结果引入时序／所有权；头不能成为内容可见事件，秘密的额外传播面也须承接。若出现独立消费者或其他协议采集时点需求再考虑 |

本候选建议 A。候选函数结果属性名 `rawHeaders`，含义只引用 MR5 S-20；没有独立身份或线上 Schema。S-58 对应同次结果交接该事实；S-54 原四种结果在已经取得且保留头事实时携带它。发送前拒绝／零发出取消不伪造字段。S-59 不需要第二条头事实权威，不得因读体中断、门失败或取消抹掉 S-58 已交出的事实。新的交接采用一份头事实；不得从 failure 与不透明 response 各读一份然后猜优先级。

字段是本次已采得且按原凭据规则处理的自有不可变 map，不是 HTTP 线序、过滤后的展示摘要或核心事实认证。合法数组值必须原形保留。没有取得／没有留存时沿 MR5 缺席，不能补 `{}`；本候选不新增失败值、留存政策或默认脱敏规则。给出非法事实的提供者不符合该端口，不通过兼容猜测补救。

## 四表与反向核对

| 性质 | 承载与依据 | 前提／未关闭的门 |
|---|---|---|
| 原样值域与完整保留 | MR5 S-20及Schema；S-58→S-54明确事实交接 | 实际采集、脱敏及交接必须另验，不由Schema通过证明 |
| HTTP错误／取得头后取消仍保留 | 同次send结果持有既已取得的事实，invoke独立保留到终局 | 真正的socket/reader停止仍沿RT；结果字段不证明已停止 |
| 头不触发内容门、观察者或首token | 沿RT4 S-16/S-55/S-62/S-63，字段不进入arrival/snapshot/diagnostic | 不因增加结果字段扩展任何跨会话观察范围 |
| 秘密保护 | 原MR写前规则与runtime/transport责任 | G-6政策值及真实秘密哨兵仍待，不能假设新字段天然安全 |
| 响应和消息同提交、不重发 | 原RT4 S-17/S-70/S-73；新字段归完整响应原值 | MR5接收、codec精确采用、真实全部写方/来源仍待；G29不由此关闭 |
| 结果／重试／费用／缓存不变 | 除raw头值和精确依赖外保留原RT4/MR4条款 | 不补费用0、不从请求猜执行方、不新增重试或默认TTL |

已有 owner 可承接，没有新fiber、plugin、进程或数据库对象。单次调用新增的不可变事实仍由该调用持有，正常资源释放和取消实际等待不变。外部写入仍不可逆，结果中带头不使结算可回滚。分布式后真实采集／脱敏／交接归协议与装配，不能由Cordis身份或序列假定。

对旧消费者，MR5与RT5只为候选新链；推荐不自动升级旧MR4/RT4/runner等精确采用。公开 core 接收入口、runtime、transport和共同codec须各自投影并显式采用。wrapper/key格式、旧历史可认与混用边界须由 codec owner 核对，本页没有擅定新格式或兼容层。

## 可反驳的验收与未覆盖

1. 单值／数组／重复／空值正向原形一致，坏值负向与原拒绝优先相同；旧MR4仍拒数组，新MR5接受。
2. 真实本地TLS 2xx、HTTP错误、错误读体期间取消、首内容门失败及已取得头后读断裂，各核实际采集map→send→invoke；响应头不触发门/首token/observer。
3. 持久新响应经完整core接收、真实一次append与reopen原值一致，凭据哨兵不进入响应、诊断、观察者；JSON保真不独自证明脱敏或物理同批。
4. 至少丢数组形状、取得头后取消擦掉事实、把头当首token三个可编译行为负控；正常oracle0，mutant指定AssertionError非零。
5. 公开制品及双语literal示例实跑，真实任务／socket／reader收束，改动后的消费者精确采用可查；其他生产门分别报告。

目前只有 MR5 candidate 与其有限Schema检查、只读表达评审；本候选及RT5尚未接受，以上真实传输／持久链验收未运行。G28/G29/G30、TL-G1、完整十三操作与37生产认证仍各归原owner；不据本稿关闭。root技术采用前必须有冻结候选的独立架构与规格表达评审，并完成相应提供者投影。
