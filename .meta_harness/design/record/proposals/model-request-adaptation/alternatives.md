# 公共实现与模型适配的候选比较

已确定的必要结果是逐模型精调、公共函数可独立消费、路由差异明确、版本更新和在途绑定可验证。以下比较机制，用户确认的目标不参与删减。

| 候选 | 性质承载 | 负担与关键反例 |
|---|---|---|
| A：每模型一个继承 adapter 的插件/服务 | 每模型可独立维护和撤除，也可以共享公共传输/连接资源 | 多个独立实例仍要对齐共用协议与撤除交接；基类不能自动保护跨实例日志栅栏或租户隔离。资源重复不是排除本候选的必然理由 |
| B：公共传输、家族规则、模型窄定义；贡献注册于稳定提供者 | 公共函数可独立用；模型差异显式，版本引用与资源集中 | 引用取得与撤除需一个明确判定点；提供者整体替换仍中断依赖方，不能宣称全层无中断 |
| C：动态读 OpenRouter 能力表，按参数/供应商在线生成通用适配 | 少量公共代码可快速覆盖目录 | 目录能力不能证明 reminder/cache/replay 语义；目录变动会改变策略，无法兑现人工逐模型认证和固定版本 |

采用方向 B 与用户的「公共实现 + 模型窄适配」一致。A 在生命周期完全独立且没有共享协议时更直接；本批多数差异是数据和映射规则。C 可作为探针输入，不作为 official 自动上线机制。

若代表性真实验证证明稳定提供者内引用管理无法清楚收口，回到 B 的生命周期分解，不把问题隐藏在更多模型插件或共享基类中。
