## 选择对象、范围与现有覆盖

要选的是：**怎样让一个已发出模型动作的结算，按其真正写入日志时的运行/尝试事实确定 late，同时保留原样载荷、响应唯一和回复同批提交？**本轮不改变模型何时有权发起动作，不建立完整 Agent Loop，不扩展工具 SQL 账或全部费用补账协调。

MR4 S-35/CA2 S-39 已确定技术含义：锚定**发出所在的 attemptId**；响应写下时，该尝试已被较大序号取代或该 Run 已终结，标 `late: true`；缺席是确定的“不晚”。对账条目壳可归新尝试，却不能用该壳替换原发出 attempt。没有 Run 的调用没有 late。领域读数提出的“到达还是落账”疑问，在本纵线已有这份精确承诺，不需要再次询问用户。产品的“动作已发起”精确时点等其他未决不由它一并关闭。

| 已有责任 | 已接受覆盖 | 尚缺的承接 |
|---|---|---|
| 会话日志 | SL2 原样无损存取、全序、租户判定、判重与尝试栅栏在提交点、整批原子、未知回执恢复 | 不承诺调用者预读到的前缀在后来追加时仍未变化；不认识 Run 终结或响应载荷 |
| 两个运行事实的读取 | RAF2 在一次日志读取上答已被取代/已终结；真值单调，读不到或认不出不能答假 | 只读，不给写入许可；S-6/G-2 明示假值可能在调用方写入前过期 |
| 模型结算与回复提交 | RT3 S-17 按 ResponseId 先到者赢；回复与响应同批；迟到账 unfenced；未知 opened 隔离及真实恢复 | 所有结算入口都缺少 late 判定依据与响应实际提交之间的保护 |
| Run 边界 | 产品拥有尝试递增、终态吸收、取消代写等规则 | 生产终结表示/认法和全部边界写方的精确协议尚未闭合；本轮不得以验收驱动代替 |

两条必须同时消除的交错：结算写方先读到“attempt 1 当前、Run 未终结”，构造不带 late 的响应；另一写方先提交 **attempt 2**，或在 **attempt 仍为 1 时提交 Run 终结**；旧结算随后 unfenced 提交。SL2 的 ResponseId 无冲突、载荷原样，因此错误“不晚”可落下。改成 fenced 会拒收应保留的账，且仅比较序号不能解决同 attempt 终结；预先一律标晚、事后回写、进程 mutex 均不兑现现有含义。

本轮属于现有组合保证未闭合。候选 A 扩展跨写方组合规则；B 演进会话日志已有提交承诺，并更新结算消费；C 取代部分响应持久表示及读面。尚无依据新建独立能力或服务。

### 写方覆盖：不能只覆盖正常成功回复

下表是从既有职责人工列出的**目标态覆盖要求**，不是已审计全部源码的声明。主线尚未提供完整反查索引，本稿不据其触发“边界连锁”回询。

|---|---|---|
| 真实尝试启动方 | 新尝试开始；任何条目壳首次引入更大 attempt 都影响最大序号 | A 必须参加共同链；B/C 必须进入同一日志顺序且可由完整前缀识别，不能只盯某个方法名 |
| Run 正常终结出口 | 完成、失败、被取消的终结 | 三者都须用真实 owner 的认法；A 参加链，B/C 观察实际提交位置 |
| 强停后会话治理代写方 | 无活尝试后写取消终结，产品 PF-012 §6.15 | 同正常终结；不能漏成“runtime 之外的写入” |
| runtime 正常无回复、中断、release、宿主撤除 | 生成模型响应体及账 | A/B 均走统一受保护结算；C 采用新表示；任何旧直接响应写入路径均须退出 |

## 候选 A：opaque 共同前驱标记链

保护位置在**写方共享的不透明判重键与同批原子性**。每个会改变相关 Run 事实的批次、以及依据这些事实结算响应的批次，从一次完整权威读取得最后已提交标记和对应事实，为该前驱的同一后继判重键竞争。标记与业务条目同批；一路成功后，另一路撞键、重读新前驱和事实，再构造尚未提交的批。SL2 仍不解释 payload，也不新增操作。

“共同前驱标记链”（无词条）只是本候选的技术描述，不立新领域身份；它不能成为第二份 Run 状态。标记的合法壳、初始前驱、键空间、读取键和历史启用规则都待精确定义，本文不填值。首次尝试仍须有真实开始事实，不能以孤立标记伪造“尝试已存在”。

若 Run 边界先胜，结算旧前驱必冲突；若响应先胜，后来边界不重写其历史 late。该解释**依赖所有实际事实写方参加同一链**。任一终结代写或首次高序号写入绕开链，两个原反例原样恢复。

不能将专用前驱偷换成普通 tail 再只让相关写方参加：结算读尾 T，无关写入到 T+1，终结写方竞争 T+1 的键并成功，结算随后竞争 T 的键也成功，仍漏标。若改成所有追加都推进尾标记链，覆盖范围扩大为全体追加者，附加记录与迁移成本也必须按全体计算。

**状态与失败。**业务事实只在标记和业务同批成功后成立，不允许“先占位、后写业务”的悬挂窗口。`alreadyRecorded{keys}` 必须区分原 ResponseId/MessageId 与单纯前驱竞争：原响应存在就认回先到者；仅前驱失败才可重读重建。键冲突本身不证明本次模型响应已写下。未知回执后，先按稳定读取键认回原整批，不能因前驱已被占或较新 attempt 拒绝而另造结果。

**迁移与代价。**设参与提交数为 N、实际事实写方种类为 W、竞争失败次数为 K：至少新增 N 个耐久标记条目及索引项；至少 W 类写方加组合约束；每次竞争失败至少一次失败追加与一次重读。日志无标记历史须在旧写方真实静止且权威尾确定后建立一致起点；各写方不能独立猜“第一个标记”。后续降级到旧写方会破坏保证，须有显式装配拒绝/迁移边界。

**反查信号。**事实仍只在日志，但标记链的规则由多 owner 同步维护；新添一个边界写方就触发 W 的重审，跨 owner 同批职责突出。优点是复用 SL2 三操作、provider 不增领域知识；代价是每批多写与全写方协议约束。若该覆盖不可证，准确 late 失去保护点，本候选不可采用。

## 候选 B：显式日志前缀／尾条件追加

保护位置在**会话日志已有追加提交点**。写方取得覆盖到某一尾位置的完整权威前缀，按其中原发出 attempt/真实 Run 终结认法构造批次；演进后的追加仅在同一会话提交前尾仍等于所读尾时提交，否则该次尝试零写入。尾条件与既有租户、栅栏、判重及整批写入在同一不可插入的提交边界内判断。Run 边界无论由哪个真实写方写下，只要经过共同日志就会改变尾；包括同 attempt 终结。

“日志前缀／尾条件追加”（无词条）在此是候选性质描述。**保留 append、readByKey、readSince 三个操作，演进 append 的显式前置条件与失败关系；不暗加第四操作，不传业务回调，不让日志构造或修补 ModelResponse。**MR4/CA2 的 late 形状和含义保持，payload 仍是写方提交的原样 JSON 值。条件参数形状、缺席语义、失败优先级与精确发布版本都由后续规格起草/评审处理；不能给旧 SL2 偷添参数。

**完整前缀是必要前提。**结算不得把一次 RAF 的两个布尔值与另一时刻读出的 tail 拼起来，也不得只读响应读取键后把那次 tail 当作已经读过全部 Run 事实。可从头读，或从同一权威日志已经验证的连续水位追补到本次 tail；日志身份、租户/会话、无跳号、真尾、终结认法均需一致。断档、旧副本、未知字段无法判断终结、实际尝试不存在，都不等于“不晚”。仅有尾相等但缺少该尾之前的事实仍然不安全。

**原子关系。**尾比较通过后到整批提交之间没有别的追加；比较失败的这次操作不改变条目、判重占用或可见尾。回复消息与响应使用同一条件、同一批，不先落消息再重算 late。响应先提交，则后续终结不能把它重标；边界先提交，则旧尾必冲突，重读后按新事实构造准确 late。条件不是尝试栅栏，迟到结算继续 unfenced，也不授予旧尝试推进或新发出权。

**代价与公平。**设该会话日志已有 E 条、增量 Δ 条、冲突次数 K：初读最多消费 E 条，合法连续缓存可按 Δ 追补；每次冲突至少一次失败追加和一次重读/重建；额外协调记录数为 0。无关追加也令尾变动，可能反复使结算冲突，这是真实可观察代价。仅有公平调度不保证“读尾到提交”窗口总能遇到空档；进展须额外以前后写入有可获得的提交机会为前提。不得静默增加无限紧循环、固定退避或隐含饥饿豁免。重试/退避/预算由配置策略与可替换实现承担，耗尽或无法保证进展时由既有结算 owner 保留可恢复责任并如实失败；精确映射仍待规格表达。

**迁移与演进半径。**至少一处日志公开承诺、一处日志提供者投影、runtime 结算与回复提交方两类写方采用，以及 RAF 折叠/终结认法的来源对齐；不是“只改日志内部实现”。所有继续运行的追加者须走新权威提交域，全部旧无条件响应结算者须先停止或完成明确交接。普通无关追加可沿其原语义继续，只是会使条件冲突；不能由此推断旧响应写法也安全。无需每个 Run 事实写方另产标记，已有日志条目不因迁移而回写。若存在历史漏标，不能宣称新协议已修复它；历史处置另归数据 owner。

**反查信号与损失点。**跨 owner 同提交由共同日志的通用条件承接，Run 状态权威不搬到日志；没有重复维护 runEnded/currentAttempt。runtime、回复写方、日志需一次显式版本传播。若实现只比较内存尾、先比较后排队、允许旁路文件写、或响应写方仍绕过条件，准确 late 即失去保护点。若改成按“相关 Run 状态”而不是全 tail 判条件，则 provider 需认识业务或一个新条件表达协议，那是新的选择，不能伪装成本候选的优化。

## 候选 C：按响应的历史位置派生 late

保护位置移到**不可变历史与响应读取投影**。记录保留原发出 attempt、响应所在批次及位置；读取时，从响应那次提交**之前**的完整历史前缀判断尝试更替和 Run 终结。未来的新尝试或终结不能倒改既有响应的含义。对账时仍按发出 attempt 判，不按条目壳的新 attempt 判。

此方向不需要结算写方与 Run 边界预读竞争，也不增加共同标记；新的相关写方只要进入可识别的历史就自然影响结果。它仍依赖真实终结认法、完整日志及批次边界，不能靠“当前 runEnded 为真”直接推断历史 late。

**现版本不允许直接这样做。**MR4 S-35/CA2 S-39 把 late 放在持久值中，缺席明确是不晚；SL2 S-11 读回原样。先写缺席 late，再读时补 true 会改变原始值的解释；追加一条“补标”也不能自动推翻旧值。因此需新的响应/账表示与读面消费约定、精确版本及迁移，旧 MR4 不能暗改。原始导出、重放、账汇总、排查、跨系统复制及直接 Schema 解码方都须区分物理表示和领域读面；准确消费者数尚未盘点。

**状态、失败与代价。**原响应仍按 ResponseId 唯一、回复仍整批；unknown ack 仍按真实日志认回。派生计算不可用时必须如实不可判，不能返回无 late 的“成功”；若缓存派生结果，须带来源位置且可重建，不能成为第二份终态权威。设响应数量 R、全历史条目 E：朴素逐条读历史的上界可达 R×E 次条目处理，单次顺序折叠可降低重复计算，但缓存/导出一致性仍需专门证据；这里只列数量关系，不宣称测得瓶颈。至少 MR/CA 两处表示关系及一个读面变化，直接原始消费者 D 个都须迁移。

**反查信号。**避免写方之间的共同前置条件，却使写端、读端、账与导出反复同步改表示；若两处各自派生 late，就出现同一事实重复定义。若任何旧读取者把缺席解释为不晚，或历史截断丢了边界位置，准确 late 失去保护点。可取之处是避免全尾冲突；代价是本轮最广的已接受表示迁移。本稿不增加“Run 终结与相关响应同一批”这一新允许；其合法性和含义仍未决，不能以条目位置替产品裁定。

## 共用的失败、认回与装卸边界

1. **稳定的认回身份。**ResponseId、MessageId、原发出/会话/租户等沿原记录；竞争不重新 plan/send、不改绑模型、不重新铸号。写方共享的判重键必须同时有约定读取键，且编码跨 owner 一致；SL2 不自动把 dedupeKey 变 readKey。精确编码是后续缺口，本文不制定。
2. **区别当前失败与历史未知。**A 的前驱竞争、B 的尾条件冲突，仅证明这一次尝试没有提交；不能排除更早未知回执的那一批已提交。`alreadyRecorded` 的键、`attemptSuperseded`、普通旧尾空读也不能替代认回。原批所有关键读取键/完整身份及批次关系须一致；只找到消息或只找到响应不能当作正常成功。
3. **未知期间不改写故事。**先停止旧流、旧锚点追加及全部旧结算写者，必要时排空旧日志属主、真实重开并读取完整权威结果；withRun 具备有效新尝试栅栏，无 Run 具备唯一重新承载。认回原响应则接受先到者原值；确认原批未提交才允许按新依据重建尚未提交的批。不能在仍可能迟到提交时用同一身份换一份 late/处置竞争。
4. **未知 opened 的更强前提保持。**沿 D-076/RT3 S-17/33 的既有恢复时机，未确定 opened 有无时保持未结算与内容不可见，不提交普通响应、不交重试、不再发；即使本候选消除了 late 竞争也不能绕过。取消请求、函数 outcome、dispose 完成均不是实际停止证明。
5. **读权限不因协调扩大。**每个结算方须有对该会话必要权威事实的既有合法读取与写入资格；入口核租户/会话身份，不能暴露整本日志给原本仅获单条回复的调用者。若回复提交 owner 尚无合法前缀读面，装配/消费者投影必须先补明确承接，不能把无权读取答成“不晚”，也不能把日志 provider 升为业务裁判。
6. **失败仍有主人。**条件/链冲突不是上游失败、不触发模型重试，也不是响应已经完成。等待、重试与恢复任务归已有调用/回复 owner；不能留下无主后台 Promise。配置预算耗尽、停止或存储不可用时保留原耐久锚点和可认回身份，沿原恢复/返回边界报告；本文不新增一种调用领域状态。

### 装配草图与不另拆能力的理由

```text
真实尝试 / Run 终结及治理代写 ────────┐
runtime 正常 / 中断 / 撤除 / 对账 ─────┤
回复提交方（消息 + ModelResponse） ────┤
其他日志写方 ────────────────────────┤
                                     ▼
                      既有 sessionLog 权威提交域
                         同一 entries.jsonl
                          │              │
                          ▼              ▼
                   RAF 只读派生      按稳定读取键认回
```

A 在相关写方的完整批次里增加共同标记；B 在 sessionLog 既有提交点增加显式条件，响应写方消费；C 将 late 转到版本化的历史读面。箭头是业务责任，**不是新增 inject 图**。沿已有投影，runtime 与 RAF 对 sessionLog 的 required 依赖保持，公开 invokeModel/传输函数不引入日志依赖。

不拆出 late 服务：它没有新生命周期或独立消费者，返回结果仍必须回到同一 ResponseId 批次。不给每个 Run/attempt/call 建日志实例：这些是数据身份，共同顺序已属会话；拆实例只会重新制造排序问题。不合并 runtime、RAF、日志：同 fiber 不使跨 await 的预读和写入原子，且三者分别拥有结算、派生、持久提交。纯折叠/构造仍可独立取用，但不会因为可复用就获得持久提交权。

上游依据严格限于 Cordis 4.0.4 basis：[`plugin-body-reruns-on-provider-change`][BASIS-RELOAD] 说明 provider 换代使消费者卸载重跑；[`effect-disposal-concurrent-not-ordered`][BASIS-DISPOSE] 说明跨 effect 不能借完成顺序保证先结算后释放，异常可能只记日志；[`isolate-hides-instances-not-data`][BASIS-ISOLATE] 不提供数据权限。三个条目的 probe 均非 null，历史检查状态不是本次新运行。撤除顺序仍由已有 owner 明确组合：关准入、停止新工作、等待实际旧流/追加/结算收束、保留未决恢复责任、再释放资源与日志写资格。文件锁、耐久和实际 socket 停止不由这些 basis 证明。

## 推荐、可计数代价与改票条件

**作者推荐 B，前提是其新版本的完整前缀条件、失败/恢复和全部结算消费者能够经独立评审闭合。**它保留现有 MR4 的 durable late 与原样 payload；复用共同日志的物理排序，不要求每个 Run 事实 writer 额外产协调条目，也不把 Run 认法搬进不透明存储。此推荐不等于“B 已实现更快”，没有性能测量。

| 候选 | 可计数的主要新增负担 | 当前最强反对理由 | 重新改变推荐的证据 |
|---|---|---|---|
| A | N 个附加耐久条目；W 类事实写方迁移；K 次竞争追加和重读 | 漏一个边界写方就丢保护，长期同步维护半径大 | 能枚举并约束全部真实 writer，旧 writer 切换可验证，专用链与 unknown ack 形式/故障证据成立；若 B 的无关冲突在真实负载下持续妨碍结算且 A 总成本更低，A 重新优先 |
| B | 一个日志提交承诺演进；日志/runtime/回复投影传播；每次冲突一次追加及追补读取，0 个协调记录 | 全尾冲突可能因无关写导致饥饿；合法前缀读面必须真实存在 | 若无法在保留原样存取和三操作的前提下表达恢复，或所有结算方的合法读面无法建立，撤回推荐；如果实际争用反例否定所声明进展前提，重比 A/C，不先削保证 |
| C | MR/CA 两处表示关系及至少一个读面迁移；D 个直接原始消费者复核；历史折叠计算 | 改变已接受持久表示，旧读取者会误解缺席 late | 若有独立产品/技术演进明确要求统一历史派生读面，全部消费者/导出已完成精确迁移，且真实负载表明消除写端争用收益超过迁移成本，C 重新优先 |

N/W/K/E/Δ/R/D 是比较量，不是测量值；W/D 尚未完成真实源码清点。三个候选均不放宽准确 late、原归属、未知回执认回、回复同批或旧写方实际停止。当前未出现需要削弱产品要求才能比较的冲突，因此本稿不发起产品回询。

## 可反驳的证据义务

下列局部 O 编号只在本稿有效，**完整验收均未执行**。形式模型应表达真实竞争而非预先把“先读后写”合成一个原子动作；有限正确配置与至少一个相应错误变体均需得到能区分它们的结果。实际 I/O、文件属主切换和授权不能由有限模型代证。

| 动作与注入点 | 观察/拒绝的 oracle | 候选差异与消费边界 |
|---|---|---|
| O-01 结算已构造不晚，先提交新 attempt，再放结算 | 最终原 ResponseId 恰一条且 late=true；旧尝试零推进、零新 HTTP | A 旧前驱撞键；B 旧尾冲突；C 新读面按响应前缀判断 |
| O-02 同上，但只写同 attempt 的 Run 终结 | 同 O-01；不能只靠最大序号测试通过 | 三者都须真实终结 recognizer |
| O-03 响应先提交，然后才新 attempt/终结 | 该历史响应仍不晚，不回写、不按当前终态重标 | 防 A 一律标晚、防 B 比较/写入拆步、防 C 用当前事实派生 |
| O-04 在旧读尾与终结之间插入无关追加 | 原反例仍被挡住；重复多次无关追加时记录冲突数与是否获得提交机会 | 击穿 A 普通 tail 拼键的错误变体；量 B 争用；C 折叠无误 |

主线另提供一份已运行的有限设计实验；本稿起草者读取脚本和结果、核对输入 SHA，**未自行执行**。脚本 SHA-256 `1cf10e5d4b36bfcec2551391d500cdbecdea2fbaa1f21d7c5fc4211d670b36ef`，结果 SHA-256 `590acd8f7afb4f1423107110ced31248056e9fc3618a335b4650555394895fa6`。在 6 个动作、2 个结算写方竞争同一 ResponseId、1 次无关追加及 2 种边界形式的有限排列内，两种模式各 360 条历史；旧预读直接追加出现 96 条错误 late，尾条件模式错误为 0、记录 248 次条件冲突及 96 次写入静止后的重试。两种边界在实验中都折为同一个布尔事实，消息/响应同批作为一个模型动作，因此**不证明真实 Run 认法或物理整批原子**。实验也未覆盖 unknown ack、真实 I/O、旧 writer 停止、崩溃重开、授权、公平性、无限争用或 HTTP；它只支持“这组有限交错能区分有无尾条件”，不关闭上述验收。持久归档待主线保全，本文不虚构归档路径。
