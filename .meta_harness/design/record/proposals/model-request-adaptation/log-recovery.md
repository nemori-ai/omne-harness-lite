# 日志健康打开与不可信恢复的识别选择

2026-09-27，本纵线 SL3 JSONL 施工发现 SLJ3-RG1：合法派生索引不能区分健康关闭与不可信写入后异常退出；取锁成功也不能证明旧物理进程退出。本页组织这项必要依赖的技术选择，不扩展会话、进程平台或资产能力。

三个实质候选及其完整机制、代价和改票条件见 [恢复投影的候选比较](../../../realization/packages/session/session-log-jsonl/v3-recovery-design.md#施工反例与候选比较)：调用者显式选择模式；provider 每日志预写 active／健康关闭 clean 并消费可信退出事实；复用索引或锁作失效信号。推荐第二项，原因是写入前建立可靠信号，异常退出无需补写，同时保留健康索引路径。它仍承担每日志同步、健康索引信任和可信宿主输入的成本；标记及锁均不能代证物理退出。

rev 1 的 RG-V3 混淆消费者回执未知与 provider 不可信，RG-V7 未区分正确索引替换与删除两条安全路径；两项在 rev 2 只改验收文字后独立复核闭合。完整输入、初稿、差分和归因摘要见 [评审归档](reviews/session-log-jsonl-recovery-2026-09-27.tar.gz)及[评审记录](review.md#2026-09-27-sl3-恢复路径识别增补独立复审)。本页不重复机制正文，也不把评审通过当作实际恢复完成。

主线在受托实施范围内的技术采用见 [D-085](../../decisions/session-log-recovery-projection-adoption/decision.md)。旧 SL3 契约与 D084 投影保持；新装配依赖、真实 IO、所有调用者迁移及恢复开闸仍沿投影 RG-G1～4，由原 owner 交付。
