# 交付面上的一段输入，怎样被认成一条斜杠命令、解析并展开

## 需要作出的选择

人在[交付面](../../../ubiquitous_language/terms/interaction-and-dispatch.md#ul-delivery-surface--交付面--delivery-surface)上提交一段输入，
系统要依次回答四问：**这段输入是不是一条斜杠命令（识别）、是哪一条（解析名字）、参数是什么（解析参数）、
展开成什么或交给谁（展开与分派）**。本包要选的是：**这套逻辑以哪家为起点**，以及它与两处邻居的接缝——
② 型命令去读 skill 正文的那一处、③ 型命令把事交给一条系统业务流程的那一处。

它影响的可观察结果：同一串 `/xxx` 在人读、机读两种形式下后果是否相同；打错名字时是当场被拒还是变成一句话、
一次付费调用；会话日志里审计者能不能看出「人敲的是什么」；② 型命令会不会成为绕开 skill 权限的后门。

以下每条都来自当前产品正文或产品负责人原话，**本包不调整它们**；候选能不能兑现，逐条在 [alternatives.md](alternatives.md) 对照。

### 可以调整的

`/` 开头普通话的字面记法；命令名的字符集与大小写处理；参数声明的具体语法与占位符形状；
识别与解析落在客户端还是据点进程；外部格式的导入兼容到什么程度。**这些都是技术设计的自由度**，
本包给出推荐与区分条件，不替产品正文加规则。

## 契约、动作链与 Cordis 投影

以下是**推荐路径下**的动作链草图，供评审判断接缝是否画对；它没有走完 handbook 主线的 C／D 步骤，不是提供者设计。

1. **交付面 · 识别**（R1）。输入是人读形式下提交的整段文本，或机读形式下那一行里的文本字段；
   机读形式另有一个显式的「按字面发送」标记（兑现 N4 且与人读形式对称）。输出三选一，**不依赖任何目录**——
   文法本身就能判「不是命令」「字面发送」「一次命令尝试」。
2. **交付面 · 预判**（R2 的前一半）。拿有效命令集的快照查名字：
   **交付面动作** → 本地执行，不成为入站到达；**未知** → 当场明说、不发送，机读形式拿到带失败类别的结果；
   **① ② ③** → 作为一条入站到达提交，携带「一次命令尝试」的原文与快照版本。
3. **受理 · 以此刻为准再判**（R2 的后一半）。判得与交付面相同 → 往下走；不同 → **PF-014 §9.5 第二行的产品未决**，契约里留显式缺口。
4. **受理 · 分路**（R3–R5）。① ② → 按声明解析参数 → 展开（② 以敲命令者的身份过 skill 自己的权限）→
   一条 `UserMessage`（内容块 + 原命令标注：原文、命令名、绑定目标类别、所绑资产身份）→ 「消息落盘之前」→ 落账 → 进队列。
   ③ → 按声明解析参数 → 交给登记处 → 写一条留痕条目（命令名、参数、结果摘要），不进队列。

**Cordis 草图**：R1、R3 是纯计算，[不必制造 fiber](../../../../agents/skills/harness-design-handbook/canonical/SKILL.md#cordis-最小内核模型)；
有效命令集是读面投影，不是某个服务持有的状态；③ 的登记处由提供流程的插件往里登记，登记返回 disposer 并由 `ctx.effect` 纳管
（DSH `dsh-commands` 的 `register` 就是这个形状，[E-S11](../../../../research/connector-and-slash-command-sources/evidence.md#e-s11-组件目录生命周期与挂起类别两源)），
流程随插件卸载即从有效命令集里消失。**事件派发模式、inject 关系与撤除责任没有在本包里判定**，留给架构设计。

拟议的契约落点（名字都是拟议，未进 registry）：一份识别文法与解析结果的数据契约（R1、R3）；
受理契约里的「命令尝试受理」操作（R2 后一半、R4、R5）；斜杠命令资产的数据形状（参数声明、绑定目标）；
交付面呈现与受理契约里的预判与失败类别（R2 前一半，[cli 节点](../../../realization/apps/cli/README.md)已登记待立）。

## 交接缺口

- **产品未决，本包不代答**：受理时认不出了怎么办（PF-014 §9.5 第二行）；③ 运行中何时生效（同表第一行）；
  ③ 能否由组织或租户创作、保留名能否被 ③ 型自定义命令替换（[PF-002 §九](../../../product/PF-002-assets-settings-and-permissions/design.md#九未决项)）；
  保留名集合变大时已发布的同名 ① ② 型命令怎么办（[PF-002 decisions §四](../../../product/PF-002-assets-settings-and-permissions/decisions.md#四已知的来源问题)）。
- **正文没有说法、看起来是技术缺口的**（先由技术设计给候选，涉及产品长相的再交产品负责人）：
  ② 的 skill 处于不可用替换件时展开什么；人对一条命令没有入口权限时，报「没有这个命令」还是「你不能用」；
  一条命令能否同时绑两种目标（omne-next 的绑定表允许 skill 与提示词并存，[E-S4](../../../../research/connector-and-slash-command-sources/evidence.md#e-s4-绑定表与组件变体)）。
- **对 cli-tui 提案的影响**：D7「斜杠命令与子命令共享同一份命令定义」在本包推荐下只能覆盖**交付面动作与 ③ 流程**这两类系统提供、封闭的名字；
