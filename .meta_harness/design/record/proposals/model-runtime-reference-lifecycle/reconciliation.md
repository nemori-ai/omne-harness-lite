29 条性质是全链性质，不等于本次要实现九个领域对象。直接改动只有一次模型调用的定位、执行与消费资源关系及耐久可查事实。Session、Run、Agent runtime、Tool Execution、装配清单是环境输入或邻接消费者；不交付它们的完整系统。Model Profile、Model Response、Session Log 原有语义只在实际补缝处升级，不能借登记服务扩大重做范围。

“有前提地能”意味着模型提供者可兑现自己的责任，前提须进入精确契约；“不能，需求正当”是 Cordis 原语不提供，要由相应能力承担，不代表删除要求。右栏均是尚待执行的验收，现有绿色测试不能冒充本增量证据。

| INV-01 | 有前提地能：调用创建时固定 Session/tenant/原 Run，后继读取不得迁账；原关联来源由外部身份端口承担 | 同 Session 主调用与 noRun 旁路，换消费者后逐项相等 |
| INV-02 | 不能，需求正当：内存索引不能代替耐久身份。模型能力须承诺 ref 发布边界、原采用事实及缺席分类 | 返回 ref 后进程丢失，按原 key 得确定登记事实或明确不可判，禁止新 send |

## 表 B：从用户原始要求复核内核负面清单

原始要求是“Session/Run 持可序列化 ref，后继能查回真实执行或明确收场；Agent runtime 与执行解耦；独立 Cordis service + 简单 demo loop”。不是从上表删减后的性质再提问。

| 内核不提供 | 本要求是否命中、承担者 |
|---|---|
| 跨 fiber/边界事务 | 命中：ref 发布、原事实及 final response 必须有明确提交点。由模型与日志/存储契约承担；不得说两个 effect 就是同提交 |
| 可靠投递 | 命中：观察流仍是有界临时交付，重接以原记录/结果认回；不承诺所有实时帧无损重放，若产品需要该保证必须另精化流记录 |
| 外部效应回滚 | 命中：已发模型请求和费用不能回滚；取消、消费者释放、恢复分别表达 |
| 有序异步清理 | 命中：旧 owner 必须按自身一项组合 close 排空；消费者 effect 只清自己的等待/观察，不能依赖多个 effect 的完结顺序 |
| 权限边界/沙箱 | 命中：当前访问及取消授权须由显式端口核验，不以 Context/fiber/ref 代替 |
| 跨进程身份/可见性 | 命中：ref 是值，live Map 是本进程事实；跨进程重新读耐久记录可做，远程活实例附着不由 Cordis 自动提供 |
| 持久化/崩溃恢复 | 命中：open 发布和完整 pending 结果有实际缺口，不能用 register(effect) 宣称完成 |
| 背压/流控 | 命中：N 个观察者各自有界并可释放；慢观察者不能无限保留整个模型 owner |
| 时序保证 | 命中：prepare/publish、首内容锚、完成/处分、撤权与关闭竞争须在模型协议中明确；内核不代保 |

## 表 C：原对象承载复查

| 对象/原保证 | 复查结果与最小改动 |
|---|---|
| Model Call：一个 Session、稳定 callId、原 Run、固定采用输入 | 原保证可保留；加 ref 查询不造平行“执行资产”身份，不迁所有权 |
| Model Call：原 RT10 S5/S7/S36/S61 将宿主写为 Agent runtime | 与当前已确认需求不成立，需求正当。C1 重分为真实模型执行 owner 和消费者资源；不删领域性质、不要求重建全系统 |
| Model Response：final 不可改、一次发出一条、处分不可伪造 | 原保证保留。零消费者时的完整结果耐久不能伪造 consumed；后继表示/存储协议要明确未处分事实与 final 事实的区别 |
| Session Log：单会话顺序、原子批、unknown 认回 | 原保证保留。新增记录如采用须新 data.messages 坐标，不能绕日志 codec 塞私有类型 |
| Run：当前尝试推进、终态不回退，旧账可落 | 原保证保留；模型 opened 是已获准执行的事实，须与新工作 fence 分开核。原结算已 unfenced，不能错误地把其改为新 attempt |
| Model Profile / 输入校准 / runner | 原保证与版本保持；只传播新增参数/结果接口所需消费者变更。不得借 registry 改模型策略或重试政策 |

C1 重分解后只有执行 owner 与消费资源生命周期分开，并未增加独立领域对象。无需改 Session/Run/Agent 的责任边界，故不以昂贵全域重写回询用户。

## 表 D：结构代价与自证

替代分解见 [alternatives.md](alternatives.md)。既有 service 内部补查找/消费资源是最低新增边界路径；独立 registry 要新增一个与执行 owner 同步的服务边界；耐久动作协调器要替换发送调度主路径。三者都须解决持久事实，不能用“只 Map”作为廉价方案冒充完整满足。

| 信号 | 结果 |
|---|---|
| 半径异常 | 无：消费者资源是 effect，不为身份/权限新增 fiber 或 isolate |
| 组合爆炸 | 无：一个调用一个已存在执行容器，观察数 N；不建立 Session×Run×Model 的服务乘积 |
| 边界连锁 | 不使用：反查索引尚未建立，不能据对象数量触发此信号 |
| 动态性代价 | 可避免：固定的是一次已发调用的原 lease，未固定后继新调用；registry 更换不是隐式重发许可 |

本次没有可归因于产品过度要求的成本回询。需要技术接受的是有限公开面和耐久承诺的修订；如果规格草拟发现必须改变“否决前回复不成消息”等产品规则，只暂停该缺口并报告明确反例，不自行制造默认政策。

## 反向核对与后继门

- 消费者 dispose：撤其等待/观察，执行与原费用继续；真正执行 owner close：原取消/排空/unknown 留责，不因 fiber 消失假释放。
- 提供者依赖消失：模型服务原关闭协议生效，不能依赖消费者重载自动重发；ref 仍能解释原耐久事实。
- 事件边界：没有新增控制广播；附着不泄露别的 Session/tenant，不把通知当授权。
- 跨进程：值和耐久事实可恢复；活 owner 发现、唯一重承载、远程订阅/撤权是协议责任。首版只承诺实际单机装配与恢复端口，不声称分布式 exactly-once。
- 形式义务：consumer N→0 不 cancel/send，old/new generation 精确清理，resolve/finish/close 竞争，pending/final 原子认回及 first-token 不重发需独立有限模型及反例变异；具体 TLA 状态变量/边界归后继 spec。实际 HTTP、Cordis 卸载与持久 I/O 故障另验。

此对账不释放实现。必须先完成候选的独立架构审查、必要契约/Schema/形式义务及提供者设计，再由主线接受精确修订；未完成项显式保留，原 TODO 不因此冻结。
