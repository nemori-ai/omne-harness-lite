# 调用引用与生命周期的候选边界

## 需要选择什么

调用者保存一次模型调用的可序列化引用，后来者应能按当前权限认回原执行或结果；没有消费者期间，调用继续记录输出、收场与成本。引用不是授权凭据，重新等待不是再次发送。这里的“可序列化调用引用”“模型执行索引”均是机制描述（无独立词条），不另立领域对象或正式术语；原对象沿 [UL-model-call](../../../domain_objects/objects.md#ul-model-call--一次模型调用)，临时访问资源沿 [UL-runtime-handle](../../../ubiquitous_language/terms/agent-runtime-loop.md#ul-runtime-handle--运行时句柄--runtime-handle)。

需求来源：PF-013 rev16 [§5.13](../../../product/PF-013-model-profiles-and-invocation/design.md#513-模型请求的运行时可以被单独控制而它停了看首-token)，PF-012 rev21 [§6.13](../../../product/PF-012-agent-loop-and-run/design.md#613-取消跟着宿主走)，PF-015 rev20 [§6.19](../../../product/PF-015-session-lifecycle-and-ownership/design.md#619-从函数输入确定持久化范围)及 [§6.21](../../../product/PF-015-session-lifecycle-and-ownership/design.md#621-三类-runtime-的归属与执行关联)。本轮用户还明确允许后继 Run 按引用查询，并限定只交 model runtime；由派发者转交，作为本包范围输入，**不推导跨 Run 结果处分权自动转移**。

一次调用仍只有一份身份与原归属。Session 是生命周期归属，Run 是关联工作的治理／成本归属；外部输入缺席的行为须写清，但不在本包制造完整 Session/Run 系统。采用基线是 [D-107](../../decisions/model-input-usage-calibration-adoption/decision.md) 对 RT10/MR9 的接受；新产品改变的是宿主解释、接续与关联承诺，不抹掉输入校准、原批认回、脱敏、原费用、有限上限等既有保证。

## 现有能力如何承载

以下是已有条款与静态证据的覆盖解释，不是主线的性质承载四表。C 的源码观察及本次字节重绑见附录；条件轨迹未实测。

| 要求 | 现有承载与组合 | 仍缺什么 |
|---|---|---|
| 身份和原归属不变 | RT10 S5/S7；`CallKey={session,callId}`、日志原 Run/attempt；ModelCallHost 持实际执行 | 发前 `open` 尚无耐久事实，不能保证已发布 ref 在崩溃后可解释。不是必须另造执行 ID |
| 消费者释放不取消执行 | runtime v11 已分 host/observer；reservation、attempt 借用释放不调用执行 owner.close；demo 已按 Session 留存 host | RT10 S5/S7/S36 仍明写 Agent 宿主，与新产品冲突；owner 能复用，不能靠代码类型解释覆盖冻结规范 |
| 仍活时继续等待 | 原 CallContainerStore 保留实际 invocation 与 pending 责任 | `openCall` 只续同 host 的 resumable，不给在途等待；`readAttempts` 读历史不等于活执行附着 |
| 完成后重取 | RT10 S34 历史读取；MR9 原响应，结算 `unfenced+tailEquals` | 未处分回复停在 `reply_pending`，当前不能保证零消费者后新的合法消费者取得且正确处分；不得预填 consumed |
| 后继尝试出现，原执行首内容继续 | RT10 S8/S15 的 opened 先写后交内容 | 原 opened 用旧 attempt fence；新 attempt 已落日志时可能被 `attemptSuperseded` 拒绝。只是 opened 条件轨迹，**最终响应结算已经 unfenced** |
| 真失联才能恢复 | RT10 S17/S33 与 v12/v14 要旧网络及全部 writer 停止、原批认回、首内容后不重发 | 新消费者出现不证明失联；当前入口缺 live／完成／确失联／不可判的完整查找语义 |
| 显式控制与归账 | RT10 interrupt 等控制、v18 来源与 runner v8 原 Run 失败主体约束 | 新读者的查询、等待、处分、取消须分别授权；查到旧调用不授予新 Run 使用原失败主体推进的权限 |
| 指定当前状态查询 | 原调用事实和投影可复用；PF-015 §6.19 允许派生索引 | 尚未证明指定调用当前值查询不随日志长度全扫；索引不是第二份权威，须带来源进度 |

参照的精确节点：[runtime v19](../../../realization/packages/model/model-request-runtime/v19-output-history-design.md)、[runner v8](../../../realization/packages/agent-loop/loop-extension-runner/v8-failure-execution-design.md)。历史文字与正式接受层分别读，不把正文旧 candidate 标签当作无接受。

## 性质覆盖范围与演化责任

本包引用封存 B 的局部编号，29 条仍保留，不另编号取代它们。下列分组只供候选比较定位保护点，**不裁定“能／有前提地能”**。

| 组 | B 的性质 | 模型侧责任与外部边界 |
|---|---|---|
| 身份、输入和原账 | INV-01/02/03/06/07，SAF-08/14 | 模型保留 CallKey、原归属、采用依据及真实结算；当前授权由可信外部端口给，查询不改原账 |
| 执行与消费分离 | SAF-01/02，LIV-01/02 | 模型执行与等待资源分开；零消费者留存、活执行认回和未处分结果重取由模型承担 |
| 尝试、终态与用途 | INV-04/05/08，SAF-06/07/10/11，LIV-05/06 | 模型原事实继续写且不推进终结 Run；当前尝试与用途处分资格由外域给；不实现完整工具准入、入站与装配 |
| 明确控制和恢复 | SAF-03/04/05，LIV-03/04 | 模型只处理合法目标调用，实际停止/未知分别记；外域负责 Run/Session 取消目标发现和意图来源，模型不能用消费者释放替代它 |
| 既有准入与选择 | INV-09，SAF-09/13 | 当前模型选择、有限上限、真实计量/校准和适配依赖保留；此次 ref 不成为旁路发出的新入口 |
| 空闲与归档前提 | SAF-12 | 模型可提供活调用/未完成责任事实；空闲判定、计时和归档治理属 Session，未因提案而纳入交付 |

演化是：模型能力公开面的**扩展**；已冻结 Agent 宿主文字及新尝试即破坏式恢复含义的有限**取代**；当前状态的**读面投影**；真实 opened 写权和无消费者结果保留的跨边界协调。新 registry 是否独立能力由三候选比较决定，不能从 Map 或目录存在推出。

## 候选 A 的装配草图及为什么不继续拆

以下是 [候选 A](alternatives.md#候选-a现有模型服务扩展解析和消费面) 的候选草图，供主线裁定后引用；不是提供者设计或 API 定稿。

```text
外部 Session/Run 事实端口：身份、访问、原工作归属、取消/终态/处分资格
                   ↓ 显式输入与缺席结果
现 modelRuntime 公共函数组合 / Cordis 服务
  CallKey → 现调用容器与真正执行 owner → 原传输、内容门、结算
      ├→ 取得临时等待/观察资源 → 消费者 A/B 各自释放
      └→ 同一会话日志的原事实 + 派生查询索引 → 终态/结果读取

demo consumer plugin/fiber：发起→保存引用→等待/显示；退出只撤消费
后继 demo consumer：引用→当前授权→在途接续或原结果；不再次 dispatch
```

保留同一个模型能力是因为模型身份、首内容、取消、最终响应及真实费用的含义仍由同一责任解释。原容器已有执行资源，原日志已有耐久事实；新增独立定位 owner 会多一道发布／注销／结算协调边界。查询面有新行为，适合演进服务条款；没有证据要求每调用一个插件或 Session×Run×Call 标签组合。

此草图**不保证不加持久记录**。发前身份及未处分结果可能要求补同日志事实或记录能力；若保护点无法在现责任内闭合，推荐 A 必须改票，不能用“最小”拒绝必要持久化。

Cordis 依据只沿采用的 4.0.4：

- [plugin-body-reruns-on-provider-change](../../../basis/cordis/plugin-body-reruns-on-provider-change.md)：消费者重载可凭 ref 接续，插件体重跑不能隐式重新发送。生产者换代本身可能影响执行，需要明确原 owner 的收尾／认回责任，不能承诺调用自动存活于任何提供者撤除。
- [effect-disposal-concurrent-not-ordered](../../../basis/cordis/effect-disposal-concurrent-not-ordered.md)：消费资源释放与执行 owner 的停止协议分开；实际 close 的停止、认回、结算、释放不能靠多个 effect 的完成顺序保护。
- [isolate-hides-instances-not-data](../../../basis/cordis/isolate-hides-instances-not-data.md)：ref 访问仍验租户/Session，不为身份数据差异新建 isolate。

三条均有既存 probe，本次没有重跑。DSH 服务门面、live map、精确实例撤除等只是转交的参考模式，未独立核验；DSH Agent 所有权、会话键一对一和破坏性 handle.dispose 不可直接采用。本稿没有采用 DSH agent，也没有为未来 Tool/Agent 建通用基类。

公开函数层继续支持独立调用模型；模型运行时的引用、授权和耐久承诺只属于运行时层。新增解析/消费行为可为独立函数组合并由 Cordis 服务装配，不能强制纯 `invokeModel` 使用 Session/Run。公开操作数量不是约束：比较独立取得消费资源操作与历史读取的显式模式时，以副作用、失败集合和释放义务是否清晰为准；不预定第十四操作，也不为守十三强塞模式。

## 必须先澄清的精确缺口

这些是技术表达或跨 owner 协调缺口，不等于重新询问已明确的产品要求。已有产品已要求恢复身份、零消费者记录和原归属；实现不能选择丢掉它们。每项由主线裁定保护边界，再由 spec drafter 表达，不能在代码里填默认。

| 缺口 | 已明确与未明确 | 依赖的后继材料／最小区分证据 |
|---|---|---|
| 发前引用公布 | 已要求从发起起身份可恢复；RT10 open 尚无记录。尚未明确公布点、已分配未发出的恢复形态、失败与不存在的区分 | 主线决定同日志事实或其他权威依据、公开成功的提交点；在 open 成功/首次 dispatch 前崩溃，查回原身份且零自动发送。若复用外域记录须指出同提交对象，不能一句“Session 保存”交掉责任 |
| 无持有者与未处分回复 | 输出/结果/账不能依赖消费者常驻；既有 MR9 未处分值不能伪造 persisted/vetoed/consumed | 区分“执行收场事实已保留”和“消费者处分已完成”；明确原始回复的耐久保护、后继读取与唯一处分责任、未知回执；零持有者完成后重启，再取得原内容并否决，验证一次账且无虚构处分。是否改变 MR/MS/RT 必须据此判断 |
| 查无／不可判／确失联 | 本地 Map absent、查询失败和超时均不能证明失联；原日志有 in_flight 也不能证明存活 | 明确查询的信息源、新鲜度与 loss 证据；失联确认及所有旧 writer 收束之前不准 reconcile 重发。缺资格时不能通过 notFound 披露存在性，精确拒绝形状由契约定 |
| 后继 Run 访问与控制 | 用户要求跨 Run 可查；原工作/费用不迁移；查询不自动授予取消或消费旧失败主体 | 凭据来源、Session 绑定、读/等/处分/取消四种资格分别定；同 Session 新 Run 查询旧结果可成功，但原终结 Run 不复活，跨租户全部拒绝。完整授权治理不在本轮实现 |
| 旧 attempt 的 opened 写权 | 原合法调用可继续；已发生事实不能以新尝试推进权限简单抹掉；内容必须先有真实 opened | 固定 dispatch A→合法更高 attempt B→原首内容轨迹；决定哪一条共同日志条件允许原执行记录事实，又保持旧 Agent 新动作被 fence 拒绝。取消/归档与 opened 的竞争一起建模；不可直接全局改 unfenced |
| 直接查询与索引 | 当前值应有 O(1) 相对日志长度访问目标；旧投影不得冒充当前 | 指定调用状态查找与历史列表分开测，明确来源进度、追尾/重建及故障语义；未选持久结构前不承诺复杂度证明已成立 |

## 反例和验证交接

下表是未执行的义务，不是 evidence run。精确 TLA+/Alloy 及测试由后继规格定义，不在提案内写一份竞争规格。

| 验证主题 | 能改变选择或阻止接受的观察 | 所需产物 |
|---|---|---|
| 引用发布与崩溃 | 已交付 ref 在首次发送前丢失，不能区分未发与不存在 | ref/调用事实提交边界；状态模型 + 故障注入 |
| 多消费者与零消费者 | 最后一人 release 使原发送中断；两人取得结果造成二次处分或账 | acquire/release/finish/settle 并发模型；真实 Cordis consumer 重载与原 send 计数 |
| 附着与执行结束竞争 | lookup 看见 live，attach 时已结束却新建调用或永等 | 解析/取得消费资源完整操作语义；模型中的 close/replace/finish 交错 |
| pending 耐久与否决 | 零消费者结果仅内存、重启丢失；为了落盘先假造 consumed | 无处分事实/完整原批认回与唯一处分语义；真实日志重开负控 |
| opened 与尝试交接 | 旧实际执行 first-content 被合法新 attempt 拒；放宽后又让旧 Agent 推进 | 同日志写授权边界与组合证明；精确条件轨迹及取消竞争 |
| 查找与失联恢复 | 换查询实例后 Map 空就重发，或调用已完成仍走失联恢复 | 查询信息源与恢复前提；活/终/未知/真失联四路，首内容后零再次发送 |
| 跨 Run 权限及归账 | 新读者改原归属、消费旧失败主体推进新 Run，或 ref 越租户 | 身份/用途/资格接口与正反例；不要求实现完整 Run |
| 撤除与真实资源 | fiber dispose resolve 被当作网络/写者已停，未知写入无人认回 | owner 关闭协议与实际停止证据；保留既有 unknown 不提前释放 |
| 当前值查询 | 日志线性增长使指定调用状态每次全扫；旧索引冒充当前 | 读面新鲜度语义、读取工作量测量及可重建性验证 |

最小 demo 可用 noRun 合法路径完成发起、流式展示、保存 ref、消费者 A 撤除、B 在途重等、C 完成读取；Run 分支用受控但有来源的外部身份和授权输入验证。执行服务真正关闭另验实际停止和结算，不能用 consumer release 代替。它不实现正式 Agent Loop，也不以“demo 成功”代证完整跨 Run 治理。

## 报给主线

1. RT10 S5/S7/S36/S61 宿主解释、S33 恢复适用前提、S8/S15 opened 写权、S28/S34/S49 的接续与未处分消费，需在**后继版本**逐条核定；MR9/SL3 等是否改变依赖上述缺口，不能无依据扩大升版。
2. 词条方面，可序列化调用引用是现 Model Call 身份投影（无独立词条）；不得把 UL-runtime-handle 属性改成持久对象。若需要正式名称，由术语 owner 先处理。
3. 对象条目没有本轮拆合／改宿主建议。封存 B 指出的 UL-model-response 成功/失败留痕未裁残留和术语索引摘要滞后保留给维护者；不据它们删除既有 MR9 保证。
4. 完整 Session/Run 取消发现、归档、空闲与新输入治理仍在外域；模型提供可查身份、状态与合法控制端口。缺外域生产实现不等于该模型端口可以无授权默认运行。
5. 本包候选 A 的保护点须由主线四表与独立评审审视，不能将附录静态读数或作者推荐当作已经接受。所有行为、并发模型及复杂度验证本次未执行。
