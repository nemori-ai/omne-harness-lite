# 23条完整旅程、30项细化与跨模块验收

本章是预定验收与文档承载走查，**没有运行这些产品场景**。产品原文224个故事正文行全部保留在机器清单；feature映射不能替代下列整条旅程。所有数值与支持目录仍以已接受的产品范围为准。

## S01 注册之后，直接开始第一件事

来源：用户故事L17–L33。路径：EP-01 → EP-02 → EP-03 → EP-08 → EP-09。

**按原过程验收**：
- 1. 用户注册账号，下载受支持的客户端并登录，看到自己的助理与可开始工作的入口，不需要先选择个人或团队版本。
- 2. 用户选择平台提供的 AI 与算力服务；已有服务的用户也可以填写兼容的 API。两条路径分别说明可用能力、计费来源和限制。
- 3. 用户交入一份活动需求书：“先帮我理一下要准备什么。”不必先建项目、分类或填写个人画像。
- 4. 助理读取材料并整理目标、交付物与缺口。文件里已经写明的日期和用途不再追问；真正影响下一步的事实缺失时才询问。
- 5. 用户看到原件、整理结果与真实处理状态，能继续修改要求。原件不会被摘要覆盖。
- 6. 工作需要私人邮箱或本机文件时，产品提供连接或范围选择入口；基础服务不要求用户自己部署。
- 7. 用户关闭电脑，随后在手机登录，能够找到同一件事、材料和成果，继续交流。

**完成事实**：一个普通用户可以从注册走到第一次真实交付，没有自行部署基础服务的步骤。关联模块：M07、M14、M15、M16。

**必须注入的异常**：在供应身份后、材料提交前断线；恢复不得重复建账号，API无效不丢稿。

**功能回链**：M01.1, M06.6, M07.1, M07.6, M07.9, M08.2, M08.3, M11.7, M14.1, M15.1, M15.2, M15.3, M15.4, M16.1, M16.2, M16.3, M16.5, M16.8, M18.2。

## S02 相处两周之后，助理懂得我的取舍

来源：用户故事L35–L54。路径：EP-11 → EP-03。

**按原过程验收**：
- 1. 用户正常交流与工作，不必专门填写“记忆表”。助理逐渐形成对相关偏好和背景的理解。
- 2. 用户开启一段新的项目对话，助理结合之前的取舍组织方案，并说明哪些建议用了既往背景。
- 3. 用户问“你为什么觉得我不喜欢探索性的设计？”助理指出当时表达的范围与来源，而不是编造一段解释。
- 4. 用户纠正：“那次是因为客户赶时间，这次可以尝试。”助理区分那次项目的限制与长期偏好。
- 5. 后续建议随之调整，正在做的相关工作也重新考虑，重要变化对用户可见。
- 6. 用户可以打开对自己的理解，查找某个主题、展开依据，辨认哪些是自己说过的、哪些是助理推断的。

**完成事实**：用户感到“它记得我，也听得进我的纠正”，新的相处能改变助理之后的判断。关联模块：M01、M02、M17。

**必须注入的异常**：让纠正提交失败、索引更新延迟，并在下一Session命中旧摘要；成功只以权威提交为准，后续行动不得继续采用已失效理解。区分原话、外部转述与推断；对选定的组装/压缩保护策略做相同权限、不同要求来源的正反对照，不把更强产品判据当框架默认保证。

**功能回链**：M01.1, M01.2, M01.3, M01.4, M01.5, M01.6, M01.7, M01.8, M03.9。

## S03 它记得旧承诺，也理解我现在的时间

来源：用户故事L56–L75。路径：EP-11 → EP-04 → EP-12 → EP-06。

**按原过程验收**：
- 1. 助理通过获准查看的日历与往来，发现出差日期可能影响那个旧承诺。
- 2. 它先核实相关日期、时区、地点与行程限制，不因为记录久远就忽略，也不把旧日期当作未来安排。
- 3. 在已有授权内，它整理可以调整的行程、需要协调的人以及还不确定的条件。
- 4. 助理向用户说明冲突及实际可行的选择，并展示依据。它不需要等待用户先创建“检查冲突”任务。
- 5. 用户告诉助理此次取舍，助理据此完成获准的调整，并把需要外部确认的部分继续跟进。
- 6. 原承诺、新行程和最后的决定保持清楚关联，用户之后不用重新回忆为何改过安排。

**完成事实**：长期理解与当下现实共同影响行动，用户得到可采取的结果，而不是一条缺乏背景的冲突提醒。关联模块：M01、M02、M03、M10、M13。

**必须注入的异常**：仅提供部分日历/跨时区旧日期；不按亲属类别自作主张，不无声改已对外确认行程。

**功能回链**：M01.3, M01.4, M02.1, M02.2, M02.3, M02.7, M02.8, M03.1, M03.2, M03.3, M03.4, M06.1, M09.8, M09.9, M10.3, M10.8, M13.4, M13.7, M17.2, M17.3。

## S04 没有新指令，它主动改善反复发生的问题

来源：用户故事L77–L97。路径：EP-04 → EP-11 → EP-03。

**按原过程验收**：
- 1. 助理在参与这些工作时发现重复现象，形成一个初步判断：问题可能集中在需求与生产条件的衔接。
- 2. 它结合用户持续表达的目标，判断这件事值得调查，而不是仅把它记成一条观察。
- 3. 在已有资料权限和投入边界内，助理比较相关返工记录，区分已证实原因与仍待核实的解释。
- 4. 助理准备一份可修改的交付检查表，并用已有案例检查它是否能帮助减少遗漏。
- 5. 它在合适的时候向用户展示已经完成的调查和材料，说明为何开始、用了哪些依据、还不确定什么。
- 6. 用户指出一种特殊项目不适用，助理调整检查表及使用条件。
- 7. 下一次类似项目，助理主动采用适合的部分，并观察是否减少返工；无效时继续修正或停止沿用。

**完成事实**：没有新命令、也没有预先存在的待办，助理仍从连续目标中形成行动理由，做出可验证的改进。关联模块：M01、M02、M03、M08、M11。

**必须注入的异常**：在没有新命令、外部事件或待办时连续触发获准自省；既要交付有依据的实际成果，也要在无收益、依据失效或预算不足时收敛。记录用量与重复工作，不以调用数量、全拒绝或全部遗忘作为通过。

**功能回链**：M01.1, M01.2, M01.7, M01.8, M03.1, M03.2, M03.3, M03.4, M03.6, M03.7, M03.9, M11.1, M11.7, M11.8, M13.6。

## S05 它发现一个机会，并先替我做好准备

来源：用户故事L99–L114。路径：EP-04 → EP-09 → EP-06。

**按原过程验收**：
- 1. 助理把新信息与用户的方向、已有作品和时间余量联系起来，形成值得进一步调查的判断。
- 2. 它检查机会是否仍有效、要求是否匹配、信息是否可靠，并估计进一步投入是否值得。
- 3. 在预算与授权范围内，助理整理相关作品、准备初步材料，必要时委派其他能力做有限调查。
- 4. 如果用户已经授权某类明确范围内的接洽，助理可以按该范围开展；没有此授权时先完成能够独立推进的准备。
- 5. 它带着实际进展来找用户，说明适合之处、代价、截止窗口和需要用户决定的内容。
- 6. 用户表示近期改变了方向，助理更新理解并结束不再合适的后续投入；已获得材料仍可回看。

**完成事实**：助理能够主动发现、调查和准备，也能够有理由地不做或结束，让用户的注意力用在有价值的选择上。关联模块：M01、M02、M03、M11、M16。

**必须注入的异常**：模拟机会过期/预算不足/用户沉默；不将沉默当扩大投入同意。

**功能回链**：M01.1, M01.4, M02.2, M02.6, M03.1, M03.2, M03.3, M03.4, M03.6, M03.7, M06.8, M11.1, M11.2, M11.8, M13.7, M13.10, M16.6, M17.2, M17.3。

## S06 与助理一起完成一轮内容生产

来源：用户故事L118–L140。路径：EP-12 → EP-03 → EP-04 → EP-06。

**按原过程验收**：
- 1. 用户交入品牌邮件、需求书和参考图，说明目标、时间及预算，助理整理已确定条件与尚未确定部分。
- 2. 用户指定品牌联系人、一个设计助理和印刷商往来，或者让助理从已可用资源中找到合适对象。
- 3. 每个协同资源在这件事里有清楚用途：确认口径、产出稿件、确认生产规格。用户看到具体名称、内容与状态。
- 4. 助理向设计助理交付获准材料，同时向印刷商询问必要的规格与档期；各方只获得完成此次协作所需的内容。
- 5. 等设计结果时，助理继续整理物料清单。印刷商回复后，所需修改回到原事情，再进入相关设计工作。
- 6. 品牌方改变口径，助理识别受影响的稿件、成本和时间，完成可恢复调整，将重要的新承诺带给用户决定。
- 7. 用户随时问“现在等谁”，可以得到基于真实往来与结果的回答，不用分别打开每个工具重新拼装进度。
- 8. 稿件、物料表和交付记录汇总为可使用成果；“已完成”“已发出”和“对方已确认”分别表达。
- 9. 活动结束，相关资源完成使命，不再持续监听或催促。历史、成果与整个邮箱账户继续保留，其他项目不受影响。

**完成事实**：邮件、其他助理和物料通过统一协同心智进入同一件事，变化能推动工作，使命可以结束。关联模块：M03、M04、M06、M09、M11、M17。

**必须注入的异常**：一位设计参与者失败，供应商回复重复；其余成果保留，关闭此使命不影响同邮箱其他事情。

**功能回链**：M04.1, M04.2, M04.4, M04.5, M04.7, M04.9, M04.10, M04.11, M06.1, M06.3, M06.5, M07.1, M07.2, M07.5, M09.3, M09.5, M09.6, M09.7, M09.9, M11.3, M11.4, M11.5, M11.7, M11.8, M13.8, M17.3, M18.3。

## S07 我在团队里，助理仍然为我承接协作

来源：用户故事L142–L161。路径：EP-12 → EP-06。

**按原过程验收**：
- 1. 用户交入会议纪要，说明自己负责客户反馈，同事负责合同。助理理解职责与依赖。
- 2. 用户连接获准共享的材料与往来，同事或其助理也可以在需要时参与具体协作。
- 3. 外部顾问继续使用受支持的邮箱沟通，没有本产品账号仍能参与。
- 4. 助理在授权范围内准备材料、追踪反馈，发现客户与同事意见冲突后保留双方原意和来源。
- 5. 用户决定自己的处理方式，助理推进可以代表用户完成的动作；不能代其他人许下承诺。
- 6. 退出项目时，用户结束相关关注和权限，助理不继续追踪退出后的变化。

**完成事实**：团队与外部关系作为现实语境被理解，用户无需创建企业版账户结构才能让助理协同。关联模块：M04、M06、M09、M17。

**必须注入的异常**：仅授读取团队资料而未授对客户转发；系统必须拒绝外发私人注解或代表同事承诺。

**功能回链**：M04.1, M04.9, M06.1, M06.2, M09.1, M09.4, M09.7, M09.8, M09.9, M11.1, M15.1, M17.4, M17.7, M17.9。

## S08 一次研究，几个助理共同完成

来源：用户故事L163–L183。路径：EP-03 → EP-12 → EP-09。

**按原过程验收**：
- 1. 用户提出目标，交入文章链接、截图和一份现有方案，说明希望得到什么，以及可接受的投入。
- 2. 助理确认实际能读取哪些材料。原网页无法取得时，明确已看到的范围，再使用获准的其他信息渠道。
- 3. 助理判断是否需要其他助理参与，给不同参与者清楚的研究问题、材料范围和交付要求。
- 4. 用户能看见真实的协作进展；主助理在等待某项结果时，可以继续完成独立部分。
- 5. 参与者返回结果后，主助理比较依据与分歧，识别哪些只是推测、哪些有可核实支持。
- 6. 最终交付可阅读的结论、来源与可实际使用的试验材料。用户可以追问，也可以据此继续创作。
- 7. 委派结束后，相关资源完成使命，主界面和桌面助理都不再停在处理中。

**完成事实**：用户取得有依据的成果，并能辨认协作带来了什么，而不是只看到参与者数量增加。关联模块：M04、M07、M11、M16。

**必须注入的异常**：原网页不可取得、参与者结论分歧；分清所见范围与推断，不编造引用或统一意见。

**功能回链**：M03.4, M03.7, M04.9, M07.1, M07.2, M07.9, M08.3, M11.1, M11.2, M11.3, M11.4, M11.5, M11.6, M11.7, M11.8, M14.8, M16.6。

## S09 把一件跨月事务交给助理陪跑

来源：用户故事L185–L205。路径：EP-04 → EP-12 → EP-08。

**按原过程验收**：
- 1. 用户说明目标与已完成的部分，交入所需材料。助理区分已知日期、待核实条件和大致时间窗口。
- 2. 助理组织准备、提交、等待与领取等阶段，指出需要用户本人完成的动作。
- 3. 有确定时间的约定进入可见安排；不确定阶段由助理根据实际情况安排适度检查，用户不必指定每次查询间隔。
- 4. 用户提交后补充回执，助理把它纳入同一件事，继续关注获准查询的进展。
- 5. 有变化时，助理调整后续安排；需要本人到场时提前准备地点、时间与材料提醒，并注意实际开放时间。
- 6. 用户换设备或数天未打开应用，再问“办到哪了”，仍能得到上次查到什么、目前等什么和下一步的真实回答。
- 7. 事项完成后停止后续检查，保留全程记录和最终材料。

**完成事实**：事情跨越时间与会话仍连续，助理能跟随现实节奏推进，也能清楚结束。关联模块：M02、M03、M06、M10、M13。

**必须注入的异常**：不确定办理窗口、节假日闭馆、跨周重启；按实际窗口推进且无无限无效查询。

**功能回链**：M02.4, M03.6, M04.7, M04.9, M06.1, M06.2, M06.3, M06.4, M06.5, M06.6, M06.7, M06.8, M10.3, M10.4, M17.3。

## S10 还有两周和只剩两小时，助理采用不同做法

来源：用户故事L207–L227。路径：EP-04 → EP-09 → EP-06。

**按原过程验收**：
- 1. 助理理解目标与取舍，最初投入适度调查和多个方向的探索，用空闲算力完成可并行的准备。
- 2. 客户提前截止后，助理核实变化，识别剩余时间、已有成果、等待对象和必须完成的环节。
- 3. 即使算力仍然充足，它也意识到用户的审核时间和协作方档期变得稀缺。
- 4. 助理收敛方向，停止收益较低的扩展，把资源投入已有方案的检查、补缺和可交付准备。
- 5. 它向用户说明显著取舍：“现有方案可以按时交付，新增方向需要另一个窗口。”已经明确的目标内动作直接推进。
- 6. 用户决定保留哪部分探索，助理调整剩余工作，并妥善停止不再需要的委派与关注。
- 7. 交付后记录此次变化及结果，为之后理解类似情境提供依据。

**完成事实**：时间、注意力、材料与算力共同影响行动，用户能感受到助理理解当下的轻重。关联模块：M02、M03、M06、M11、M16。

**必须注入的异常**：期限从两周缩至两小时，资源不足；可调整工作但不暗降已承诺质量，保留已花费用。

**功能回链**：M02.5, M02.6, M02.7, M03.4, M03.5, M03.6, M03.8, M03.9, M04.9, M06.1, M06.3, M06.5, M10.8, M11.2, M16.5, M17.2, M17.6。

## S11 固定简报之外，它知道何时值得深入调查

来源：用户故事L229–L248。路径：EP-04 → EP-12 → EP-06。

**按原过程验收**：
- 1. 用户说明关注目的、来源与希望被打扰的方式，助理从已可用资源中组织相关关注。
- 2. 按约定时间形成简报，每项信息能回到实际来源和取得时间；无新增与来源失败分别说明。
- 3. 某次变化与用户正在考虑的方向紧密相关，助理判断值得进一步核实，而不只把它列为一条新闻。
- 4. 在已有自主工作范围内，助理调查相关资料、比较用户现有条件，形成可以采取的下一步和必要准备。
- 5. 用户在合适的入口收到带着进展的消息，可以阅读、纠正、继续或结束这项工作。
- 6. 用户要求“最近少打扰我”，助理调整通知方式；持续工作是否暂停由用户表达的实际意图决定。

**完成事实**：定期信息供给、变化后的继续工作和自主发现各自成立，并共同服务用户目标。关联模块：M02、M03、M04、M10、M13。

**必须注入的异常**：同一变化重复推送，用户只说少打扰；不制造重复待办，不擅自停后台工作。

- 6. 如果选择取消付费或关闭账户，产品说明后续用量、保存期限、分享成果和仍未完成的动作如何处理。
- 7. 删除等不可恢复后果在具体对象和范围明确后确认，实际完成情况可查。

**完成事实**：用户能开始使用，也能更换入口、收回设备和有序离开，重要内容与未完成责任有清楚去向。账号退出与商业服务细节为建议补充。关联模块：M05、M14、M15、M16、M17、M18。

**必须注入的异常**：删除/停止使用后恢复旧快照并尝试再次检索；先核对删除与撤权事实再开放相应范围。原件、摘要、索引、缓存、审计和第三方独立副本分别说明结果；未覆盖项不能显示全部已删。

## 连续工作验收的共同取证规则

一次通过不代表跨周工作成立。IWP-02及IV-CORE/AUTH/NODE/COOP/MEMORY按相应旅程固定初始状态、来源版本、政策、事件顺序、恢复点和实际提供者，组合纠正、撤权、委派、重启与未知结果窗口。记录真实原请求、授权依据、外部回执、事情进展和模型/工具用量；既核对禁止结果，也核对授权内的有效工作。

每条断言先注明所属层：框架按接受契约，产品按选定策略，适配器按实际提供者边界。已授框架token的有效性不被更强资源侧政策倒写；Plexus旧job终态不被当成跨Session路由保证；摘要来源归属的更强保护仅在明确承担它的策略下验收。断言从权威记录与实际效果核对，模型自报“没有越权”不能作为通过证据。以上均为预定验收，尚未执行。
