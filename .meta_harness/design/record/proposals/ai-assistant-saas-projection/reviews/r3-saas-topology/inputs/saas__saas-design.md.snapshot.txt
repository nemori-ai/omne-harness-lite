# AI 助理 SaaS 外围架构投影（待评审）

日期：2026-09-30。范围：外部真实 AI 助理产品的 SaaS 外围及与既有 harness 的装配边界。性质：候选投影，不是框架契约、实现声明或商业承诺。主线整合后接受状态仍须单列。本稿仅写于获准临时目录，不为仓库建立第二份长期设计权威。

## 1. 依据、假设与领域读数

依据为《AI 助理产品定义与功能需求》讨论稿 1.0 和《用户故事》讨论稿 1.0（2026-09-30），沿用其 M01–M18、S01–S23 编号。用户新增规划基线为 **10,000 注册用户的种子阶段**。DAU、在线连接、执行并发、持续关注量均未确定；地域、供应商、预算、支持平台、服务价格、保留期限和 SLO 数值也未确定。暂按国际云中立、单主地域规划，可用区冗余和异地备份以地域裁决后为准。不是先建企业组织、席位或企业专属部署产品。

本次采用目标态框架作为依赖，而非把工作区存在代码当成已经交付。框架精确覆盖取主线 [framework/baseline.md](../framework/baseline.md) 和 [framework-capabilities.json](../framework/framework-capabilities.json)，仓库观察基线 `2a04c2322a7b679133654acc3c4241effaade4be`；本稿定义外围需要接收/提供的接口性质，缺口不由外围私自填成框架承诺。部署、身份和数据责任分组是本产品的候选装配方式，不给 harness 新增正式语义或词条。

领域读数先记录如下，再展开机制。由于任务输入已经指定三类平面、cell 及身份链，**双盲未达成**；本表不声称独立防偏置。没有消费 Cordis 实现细节推导用户需求。

| 稳定编号 | 可观察结果与性质 | 类型、责任与验证 |
|---|---|---|
| P01 | 同一自然人在新设备找回原助理；个人无需建立组织 | 不变量；账号与供应；S01 中断注册续接、S23 新设备 |
| P02 | 任一资料、任务、通知、费用均不能因猜到标识或变更设备而跨用户泄漏 | 安全；身份、数据与执行共同兑现；越权矩阵与同名对象反例 |

| P09 | 分享只交付明确的内容与操作；成果可继续修改且不丢已记录交互 | 安全与不变量；成果托管；S18 |
| P10 | 重要决定和结果在可靠中心可回找，推送失败不吞事实 | 条件进展；通知；S19/S22 |

## 2. 种子阶段的装配建议

**候选建议：少量托管 VM 运行有状态 harness cells，外围业务先作为一个模块化应用部署，数据库、对象存储、密钥、备份等使用托管服务。** 外围无状态入口可有两个实例用于更新与故障恢复；这不意味着同一 harness 状态有两个活动写者。具体 VM 数与规格依真实 harness 内存和模型等待行为测量决定，不按注册人数预开一万个实例。此建议以小团队、无既有 Kubernetes 运维平台为假设；若团队已有成熟平台，候选 B 的代价会改变。三个实质方案见 alternatives.md。

用户最新约束已纳入：一万注册用户的主要并发压力来自大模型；常规 CRUD、同步和通知按普通小型 SaaS 设计即可。优先解决持久化与分布式一致性，不以通用吞吐为由建设复杂缓存、分片数据库或跨地域多活。cell 是故障、状态归属与升级批次，不是流量分片指标。

### 2.1 三类责任并不等于三套微服务

| 平面 | 权威责任与报告节点 | 首期形状 | 不属于它的权力 |
|---|---|---|---|
| Control | SP-01 身份供应、SP-02 授权、SP-05 cell 路由、SP-10 商业资格、SP-12 生命周期 | 模块化服务 + 控制数据库；管理接口独立权限 | 不直接改写 harness 内部任务状态，不代替具体外部动作确认 |
| Data | SP-03 API/同步、SP-04 内容、SP-08 通知、SP-09 成果、SP-07 外部回调 | 相同应用的逻辑模块 + 对象存储；按公开接口调用 | 不因持有文件或索引而拥有转发、模型读取或分享权限 |
| Execution | SP-05 单机 harness、SP-06 远端节点与沙箱、SP-07 外部效应、模型调用适配 | 每个 cell 一个活动 owner；短时工具执行与有状态 runtime 分开 | 不持有全平台管理员凭证；模型文字不能改变身份、预算或路由 |

SP-11 提供三个平面的运维能力；SP-13 提供桌面/移动壳。稳定组件清单在 component-index.json；这些都是责任节点，首期可同仓库同进程，秘密信任边界、非可信代码边界以及 cell 持久 owner 仍必须分开。

### 2.2 框架接口需求及外围接缝

本表是外围消费者要求，并非声称框架每一项已交付。框架基线由主线另列；已承诺但未完成的提供者按依赖排期，外围不得复制一套相冲突语义。

| 接缝 | 外围提供/消费 | 必须保留的事实 | 未覆盖时的处理 |
|---|---|---|---|
| 身份装配 | SP-01/02 提供已核实主体、自然人/成员/租户映射 | 原始执行主体、代表谁、当前成员资格、授权依据 | 发布前明确框架接收面；不只塞一个任意 tenant 字符串 |
| 请求接入 | SP-03 提交同一业务请求并查询回执 | 请求 ID、内容摘要、接受/未接受/未知、harness 工作引用 | 产品层持久 inbox 负责交接；不能靠模型再次读取聊天推断 |
| 外部执行 | SP-06/07 接收受限动作并返回真实证据 | 幂等键、动作参数、权限依据、来源节点、外部请求 ID | 产品集成适配可自建；框架当前连接件未有正式承接时不冒用旧契约 |
| 资源与费用 | SP-10 提供来源选择、可消费资格，消费真实计量 | 预留 ID、调用 ID、实际/估计/未知、第三方回执 | 不把 UI 预算当硬限制；调用前阻止新增消耗 |
| 撤回与停止 | SP-02/05/06 发布撤权/停止事实并核对实际执行 | 新动作许可、在途动作、取消能力、核对结论 | 不把进程退出或取消请求回执等同于外部效果撤销 |
| 运行恢复 | SP-05 管 cell 生命周期，消费耐久检查点与恢复能力 | 唯一写者、版本、持久日志边界、未结算外部动作 | 无恢复依据不得对外宣称恢复成功；保留阻塞与人工核对入口 |
| 读模型与通知 | SP-03/08 消费状态与结果 | 权威 owner、版本、时间、可见范围、重放游标 | 事件只做更新提示；按权威现读修正投影 |

框架状态交接的当前已知限制：accepted registry 坐标不等于提供者已经可运行；PF007 的 Engram 占位不等于长期记忆完整交付；当前 PF015 连接件存在性/接入设计已搁置，产品邮件和日历适配可作为外围工程规划，但不能引用旧 data.connector/v2 宣称当前承诺；多节点产品目标与单机首版实施边界分别记账。

### 2.3 与框架权威事实的单向接线

| 报告节点 | 框架既有权威 | 外围实际新增与限制 |
|---|---|---|
| SP-01 身份供应 | FC-02/03，PF-001 的账号、个人组织、成员与登录治理 | IdP 验证适配、外部 subject 到框架账号的绑定、注册引导；自然人/成员不得另立SaaS主库。文中“控制关系库”可承载框架提供者或引用映射，但只有框架治理owner修改其权威事实 |
| SP-02 授权桥 | FC-04/07/12 的资产权限、工具放行、显式决定 | 增加产品用途/出站/商业限制与用户入口；有效准入必须满足框架许可 **并且** 产品限制。SaaS allow 不能替代或覆盖框架 tool admission，框架拒绝始终拒绝 |
| SP-05 cell 装配 | FC-13/14/26/29 的会话、Run、据点与恢复事实 | 云部署与实例身份、operational route、版本与围栏；tenant/member身份不由路由器创造。若框架提供据点/归属定位，路由只存其引用与部署代际，不并行保存第二套领域归属 |
| SP-06 产品接入和编排适配 | FC-20/26，PF-020工作区实例/remote与节点领域规则 | 设备配对引导、网络穿透/中继、身份桥、支持目录与受控传输；工作身份、委派、工作区实例与执行结论复用框架owner。文中work/attempt/node回执是接缝需携带的信息，不定义与框架竞争的新工作域 |
| SP-07 外部适配 | FC-07/08 工具和MCP基础；FC-09当前搁置 | 自建首发邮箱/日历产品适配与凭据桥；不将产品渠道改名为已接受框架Connector |
| SP-08 通知投递 | FC-21/22的日程/通知权威事实 | APNs/FCM/邮件交付适配、通知中心读面；不能让投递器独立决定同一批准事项 |
| SP-04/09 内容/成果 | FC-20已有工作区/资源/成果关系 | 资料与托管服务作为产品消费者，不直接重写工作区权威；可公开页面的分享权限不等同于框架资产分享，两类范围相交时均须满足 |

精确适配接口尚未被框架规格承接之处，由主线交接明确；本任务不重新论证框架承诺，也不以尚未实现为由否定目标态产品。以下动作链中的权威存储均按本表归属解释。

## 3. 统一身份、授权与委派

### 3.1 一条关联链，七种不同事实

统一身份意味着系统可以核实整条行动因果链，并不意味着把全部系统登录成同一个超级账号。采用成熟 IdP 的 OIDC 登录作为候选，OIDC 的职责是核实终端用户身份；OAuth 安全建议来自 RFC 9700。业务授权仍归产品与框架各自的资源 owner。[OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html)；[OAuth Security BCP](https://www.rfc-editor.org/rfc/rfc9700.html)。

| 层次 | 认证与身份键 | 授权、委派与保存边界 |
|---|---|---|
| IdP | 核验签发者、受众、时效、登录回调关联；以 issuer + subject 绑定 | 邮箱地址只作资料，不据同邮箱静默合并账号。账号恢复与新增 IdP 绑定属于安全操作 |
| 全局自然人 | 框架稳定自然人身份；SaaS仅绑定经验证的IdP方法 | 不默认拥有所有租户对象；个人登录恢复不应重复建立助理 |
| 租户成员 | member 指向 person 与 tenant；个人注册自动供应内部个人 tenant | 对外无需组织选择。成员资格、资源范围和动作授权每次核对；tenant ID 由可信映射取得 |
| 设备/节点 | 登录 session 与设备凭证分开；私钥存 OS 安全区或节点密钥区 | 设备可收回；节点另外具有可执行资格和本地资料范围。登录客户端不会自动共享磁盘 |
| 工作负载 | 服务或进程以短期工作负载凭据认证，可用云身份或 SPIFFE 类实现 | 服务认证只证明“哪个服务”，不能冒充“用户同意了什么”；限制 audience 与调用面 |
| 代理动作 | 记录实际 actor、代表的 member、委派链、目的、资源、动作、范围和费用来源 | 子代理、插件、远端节点仅得完成指定工作的最小资格，不能用父服务权限超出委托 |
| 第三方 OAuth | 连接记录绑定租户、服务主体、外部账号、scope 和 token 引用 | 令牌只交付专用适配器；OAuth scope 是外部上限，仍须核对事情使命和本次操作范围 |

SPIFFE 提供工作负载身份与可验证身份文档的概念；其采用本身不会赋予业务权限。[SPIFFE Concepts](https://spiffe.io/docs/latest/spiffe-about/spiffe-concepts/)。RFC 8693 的 token exchange 区分 subject 与 actor，可作为委派交换的实现候选，但本产品仍需明确可委派动作与深度，不假定第三方都支持 token exchange。[RFC 8693](https://www.rfc-editor.org/rfc/rfc8693.html)。

第三方连接的OAuth回调必须绑定发起的member、tenant、设备登录上下文、预期provider及一次性流程状态；不能在回调时只看当前cookie就把另一个账号接到本用户。token刷新由连接保管owner协调，避免并发刷新把轮换后的凭据覆盖回旧值；刷新失败与用户撤权分别记录。连接令牌不交给模型、浏览器脚本或任意执行节点。

### 3.2 逐跳检查位置

1. **客户端 → API**：核实会话、设备、当前成员、资源 tenant；检查动作及内容长度/格式，绑定请求 ID 和实际提交账号。客户端自报的 tenant、role、node 不能直接成为授权证据。
2. **API → harness cell**：核对路由代际与成员权限，形成已接受工作的持久回执；cell 独立核对当前 tenant、工作身份与授权引用，不能仅信任“来自内部网络”。
3. **cell → 工具/子代理**：收窄资源、允许动作、外发对象、可用来源与预算；记录本次委派依据。引用材料不是自动授权传播整个会话。
4. **工具网关 → 节点/第三方**：在实际启动新读取、写入、收费调用或发送前核对现行资格与撤权代际。节点核对自身收件身份、工作 ID、许可范围和本地路径；外部适配器核对连接账号与真实目标地址。
5. **结果 → 存储/用户/分享**：核对返回的 tenant、work、node、版本和接收人；源材料的可读权不等于可外发权。结果可能包含受限原文，不能因为是摘要而跳过出站判断。

“每跳重查”不要求每个字段都同步调用同一个中心服务。身份签名验证可以本地完成；影响立即撤权的资格和外部副作用准入必须访问足够新鲜的权威事实。缓存有效期、离线许可长度及最大撤权传播时间是待接受参数；候选建议是在无法确定权限时，外围适配器停止新的高风险外部效果并保留现有工作。已有会话离线继续的框架规则仍成立；这里不要求治理中心不可达就强杀会话，也不回溯否定先前合法动作。不能承诺无法联网的恶意自带设备一定停止本地运行。

### 3.3 撤权、在途与退出

撤权的候选提交点是权威授权记录写入 revoked 与新代际，并在同一存储事务写出待通知事件。该点之后本产品可控制的新动作准入拒绝旧资格。已准入、已发送或第三方已受理的动作分别列入在途核对；若产品承诺“提交后任何已排队动作均不得发生”，执行准入与撤权必须共享序列化依据，且受控效应网关要能拒绝旧代际，仅凭异步通知不够。

用户操作应区分：退出当前客户端使其 session 失效；收回设备使其会话/执行资格失效；暂停主动活动禁止新的自主工作；结束事情/资源使命停止该目的的后续动作；撤回账户连接影响所有依赖；关闭账号进入总退出流程。**后台工作依赖持久、可撤回的工作授权，不能偷留客户端 refresh token 当作持续同意。** 用户退出当前客户端后，已有合法云端工作可继续；账号关闭或停止服务则按收尾政策禁止新增消耗。

这里的客户端 session 是登录凭据上下文，不等于框架持久工作会话。FC-26/PF-016 rev10 §5.6、§6.17明确中心现读的触发边界及已有会话离线继续，且没有离线时长上限。本方案不把每次工具调用改成治理中心现查，也不以租约到期结束框架会话。有限离线许可只可用于新增的SaaS外部资源/效应入口，在其政策经接受后限制该入口的动作资格；本地既有工作仍遵守框架权威规则。收回设备后的远程会话不应因UI失效被误报已停止。

对自带节点采取诚实的安全模型：平台能停止派发、停止提供秘密、拒收过时代际的变更、收回平台资源入口；节点所有者能控制本机，平台不能追回其已经持有的明文或保证断网中的第三方直连停止。需要强撤权的外部副作用经受控网关；必须本地直连的能力在支持目录明确在途限制，远端断连时不自动改派重做。

### 3.4 分享与客服

分享授予的是某份成果/版本及明确的阅读或交互权，不是加入整个个人 tenant。匿名链接、指定收件人、登录参与三种方式不能混为一项：首发支持哪些由产品决定。每种方式均有独立 grant、可见数据、到期/撤回状态；链接泄漏后的已下载副本不能被技术上收回。严格即时撤回内容需授权代理读取，不用长效公开对象 URL 绕过检查。

客服默认只见服务元数据与用户主动提交的诊断包。身份恢复、代用户访问内容、发起退款与读取日志是不同权力。提权必须有工单、目的、范围、时限和记录；高风险账户操作按既定人工核验政策执行，客服不能直接把自己加成用户成员，也不能借助理代发消息。紧急访问流程可以不依赖故障用户在线，但属于单独受控运营政策，需事后复核；未经接受不得预置“全局万能客服账号”。

## 4. 持久化、事件和一致性

### 4.1 一个事实一个写者

| 数据 | 写入 owner / 存储 | 一致性与重建 |
|---|---|---|
| 人、成员、设备、资格、路由 | SP-01/02/05；控制关系库，模块表权责清楚 | 资格/代际与其 outbox 同事务；恢复后先核对最新撤权事实 |
| 产品请求与内容元数据 | SP-03/04；数据关系库 | 提交内容摘要与幂等键；同键异内容拒绝，不误认成旧成功 |
| harness 工作与状态 | 框架 owner；每 cell 已选定的持久存储 | 外围只通过接受的接口查询/迁移；共享托管 DB 候选不能改成任意多活写 |
| 原件、版本、构建产物 | SP-04/09；对象存储 | 不可变版本 + 校验和 + tenant 范围；元数据先临时态，完成核验后发布为已保存 |
| 外部动作与远端派发 | SP-06/07；持久动作台账 | 记录意图、启动、外部 request ID、证据、未知与核对结果 |
| 用量、金额、预算预留 | SP-10；台账及供应商回执 | 追加调整条目而非覆盖历史；未知费用不填零 |
| 通知与已决定事实 | 决定归所属业务 owner；SP-08 inbox 投影 | 推送是交付尝试；inbox 和权威结果可重建，已读不是同意 |
| 检索/向量/预览索引 | SP-04 派生层 | 可重建；删除和权限变化传播可核对，检索结果读取前再授权 |
| 遥测/审计/备份 | SP-11；分开受控存储 | 审计不是采样日志；备份不是删数据的例外黑箱 |

首期可以用一个托管 PostgreSQL 集群承载外围控制与业务表，但模块不直接修改其他 owner 的事实。同一事务保护的承诺必须写出共同表/行：例如账号供应的唯一注册键、授权撤销代际行、预算余额/预留行、cell assignment 行。跨外围库与 harness 库默认是显式状态机和重试交接，不用“都在同一云”假装跨库原子提交。

### 4.2 两个最容易误报成功的窗口

**文件上传。** 客户端申请绑定 tenant/对象/大小/类型的短期上传许可，先传到隔离暂存区；SP-04 校验内容摘要、完整性与安全处理结果后，提交正式版本与可读取状态。上传成功只表示字节到达；格式提取、模型读取各有事实。临时对象清理依照 manifest，不删除正在提交或被版本引用的对象。批量上传逐项回执，单项失败不回滚成功原件。

**命令接受。** SP-03 持久记录请求及内容摘要后回 accepted；向 harness 提交失败时保持待交接，重试使用同一请求身份。harness 必须能关联原请求/查询接受情况，才允许对不明接入重放；没有该接缝时产品层只能报告待核对，不能再造工作。网络错误不能决定服务端是否提交。

### 4.3 可靠事件与重放

外围 owner 在更新业务事实的同一事务写 outbox，投递器再交付托管队列或最初的数据库投递作业；消费者用 `(consumer, event_id)` inbox 去重，业务写入与消费确认同事务。事件包括 tenant、owner、对象 ID、对象版本、发生时间、因果请求、schema 版本与必要授权引用，正文尽量用受控引用。仅对同一对象有必要的事件检查版本，不引入全局总序。[AWS outbox 指南](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)支持避免数据库与通知双写窗口，并明确消费者仍需处理重复。

投递保证不能扩展成外部效果恰好一次。邮件 API 或付款 API若没有可用幂等语义，遇到已发送但回执丢失先查外部事实，无法查明保留 unknown，交由用户或支持核对。死信要保留原因、租户、原请求与重放权限；运维重放仍受现行授权、预算和版本检查，不能把旧消息当成永久同意。

候选最简部署可用关系库 outbox worker 完成后台交接，是否另加托管队列取决于连接器和任务类型。此处采用队列是耐久交接与重试需要，不是吞吐承诺。Cordis 进程内事件不承担跨进程可靠投递。

## 5. 单机 cell、远端节点与安全调度

### 5.1 Cell 是单机框架的持久部署边界

每个 cell 有稳定部署身份、存储边界、当前进程代际、分配给它的 tenant 集合和版本清单。一个 tenant 的相关 harness 状态首期只归一个活动 cell owner，不把会话、工具、定时工作随机轮询到多个无关进程。不同 tenant 可以由同一 cell 承载，前提是框架隔离契约与内存成本验证成立；外围不能因注册一万人直接断言可共享到哪个密度。

外围路由注册表可写成 `tenant -> cell + generation + placement_state`。generation 是拒绝过时请求的候选围栏值，**它单独不能防止旧进程继续写自己的磁盘或直连外部服务**。真正迁移需要让原 owner 失去存储写权和敏感效应资格，或取得其已停止的可信证据；无法围栏时不启用新 owner，牺牲可用性保安全。若框架未提供租户级可迁移状态，就迁移整个 cell，不能靠复制部分表进行热迁移。

cell 迁移候选步骤：标记 draining 并停止新派发 → 保存已接受工作的引用与未结算动作 → 等待可收口部分，显式记录不可结束部分 → 原 owner 停止并围栏 → 导出/备份一致版本与 manifest → 在新环境恢复但禁用外发 → 校验数据、撤权、预算和外部未知动作 → CAS 切换 assignment 代际 → 开启新 owner → 保留旧代际墓碑。复制成功不是切换成功；只有路由事实提交后新请求才归新 owner。

Kubernetes StatefulSet 提供稳定 pod 身份和持久存储关联，但它不替本产品定义 cell 迁移、数据事务或外部副作用围栏。[StatefulSet 官方说明](https://kubernetes.io/docs/concepts/workloads/controllers/statefulset/)。VM 重启、容器重调度和多副本同样不能代替上述责任。

### 5.2 自带节点接入和派发

用户安装受支持执行端后，用短期一次性配对流程在可信客户端确认节点；设备注册保存公钥、所属 tenant、可用能力、资料范围及版本。节点从内向外建立认证连接，减少暴露家庭/公司设备入站端口；中继只路由显式协议，不允许任意内网隧道或控制面管理访问。配对码不可作为长期执行凭证。

节点能力声明包括软件/工具能力、可处理资料引用、位置约束、当前空闲与最后报告时间。能力声明不是资料授权；用户许可的目录变化或节点报告过期需要重验。执行选择顺序建议为：资格与地点硬限制 → 资料/工具可用性 → 来源与预算 → 当前负载、耗时和质量偏好。仅余量不足可以排队；权限不足不能当成负载失败转发另一台机器。

每个派发具有稳定 work ID、attempt ID、目标 node、assignment generation、输入版本、动作能力、可出站结果范围、来源与预留引用。节点先把“已接受”写入本地耐久回执，再启动工作；结果带原身份、内容摘要和真实执行证据返回。平台回执已接受、节点开始、外部效果已发生和结果持久保存分别记录。

节点断线后，平台不能凭心跳过期重做有外部副作用的工作。纯计算在授权允许、成本允许且结果可去重时可另起 attempt；可能发送或修改的操作先核对。重连先上传动作台账并对账，再接新任务。撤节点先禁新派发与秘密获取，在途分为未启动、可取消、已外发、结局未知；旧结果可保存为证据，但不能据过期权力继续后续动作。

### 5.3 沙箱和数据地点

生成代码、网页抓取、文件转换和用户依赖安装是非可信执行，不与身份服务、token vault 或 harness 状态库共用管理权限。采用 VM/microVM 或经过验证的沙箱运行时候选，限制 CPU、内存、磁盘、时长、进程数、出站和挂载；未开放默认禁止访问控制元数据与云实例凭证。普通容器共享宿主内核，namespace/网络策略只是隔离的一部分。[Kubernetes 多租户说明](https://kubernetes.io/docs/concepts/security/multi-tenancy/)。

“资料不能离开节点”至少分清：原件不得上传、摘要不得出站、只允许特定字段结果、模型请求是否可以含原文。检查范围包括检索摘要、工具stdout/stderr、错误栈、trace/log、临时缓存、崩溃诊断和最终成果；各类返回通道均需最小化与出站策略，不能只检查文件复制。若当前模型请求统一经 OpenRouter，且任务要求任何内容都不离机，则不能一边调用外部模型一边声称本地处理。可在节点执行不需模型的程序处理、只返回获准聚合结果，或等待支持范围裁决；不偷偷改成直接本地模型以绕过框架来源约束。

## 6. 云原生交付与日常运营

### 6.1 环境、网络与秘密

开发、预发布、生产使用独立凭据与数据边界；基础设施通过版本化 IaC 重建，生产手改进入变更记录。公开入口只承接客户端、OAuth 回调、受验证 webhook 和成果域；数据库、队列、cell 管理、secret vault 与遥测入口走私有网络或强工作负载认证。出站允许范围按执行种类管理，第三方 webhook 验签不能只靠源 IP。管理入口单独认证、多因素验证与最小权限。

秘密归专用托管密钥服务：平台 IdP client secret、OAuth refresh token、OpenRouter key、推送凭证、签名密钥各自限制读取方。采用信封加密候选，密文记录携带 key version，轮换期间明确读取旧版本与新写版本。日志、trace、错误、模型消息和导出默认排除秘密；用户在专门设置页添加 API key，助理只看到连接引用、能力及验证结果。

失窃处理要能冻结凭证、轮换服务身份、撤回受影响连接并清点在途操作；不得假设删掉数据库字段就使第三方已签发 token 失效。云 KMS 不等于业务租户授权，也不能凭“加密”宣称平台运营人员永远无法看到内容。

### 6.2 升级、迁移与兼容

每次发布记录客户端/API schema、harness 精确版本、存储 schema、插件集合、执行端协议和基础镜像摘要。先扩展兼容读写，再迁移数据，最后移除旧字段；若迁移不可逆，回滚方案必须是恢复备份或前滚修复，不能承诺旧二进制一定能读新库。协议支持窗口由产品确定，超出窗口的旧客户端保持本地草稿、清楚提示升级，不能静默丢掉输入。

cell 升级先停新增工作，核对在途，按第5节单写交接；外围无状态服务可分批更新。灰度按 cell 或内部测试租户，不把同一个 tenant 的状态写入随机分给新旧两个 owner。发布健康检查包含登录、资料读取、一个可撤销委托和状态重连；容器存活不等于功能可用。

### 6.3 备份、恢复与灾备

恢复对象至少包括：身份映射与控制数据库、cell 持久状态、原件与成果对象、授权/撤权事实、计量台账、密钥引用与可恢复密钥、部署配置和软件版本。关系库 PITR 只覆盖其数据库状态，不能让对象存储、第三方发送或另一 cell 同时倒带。PostgreSQL PITR 依赖基础备份及连续 WAL，且配置文件不自动由 WAL 恢复。[PostgreSQL 恢复文档](https://www.postgresql.org/docs/current/continuous-archiving.html)。

备份 manifest 记录一致性边界、生成时间、对象校验、版本与依赖。至少定期在隔离环境实际恢复，再查租户隔离、文件完整性、原请求关联和未知动作；只有备份任务成功不算恢复验证。跨地域副本在地域与数据驻留许可确定后配置；首期灾备是被动恢复，不能顺势变成跨地域多活。

灾难恢复先围栏旧环境、恢复为禁止外发的隔离状态、核对更晚的撤权/注销墓碑和付款/供应商事实、处理回放产生的重复事件，再开放读和新动作。原环境无法确知是否仍活跃时，不允许两个地区各自代用户发消息。RPO/RTO 按数据类别与恢复演练结果定稿；本文不给未经验证的小时/分钟承诺。

### 6.4 遥测、SLO 与审计

trace 关联客户端 request、租户匿名引用、cell/generation、work/attempt、model invocation、外部 provider request、artifact version 和费用预留。模型等待 span 与实际 CPU 执行分开，避免等待外部误报死循环。记录参数摘要和对象引用，默认不采集原始 prompt、邮件正文、文件内容、Authorization header 或 API key。OpenTelemetry 支持属性删除、过滤和裁剪，但采集方仍负责最小化，哈希标识也不自动匿名。[OTel 敏感数据指导](https://opentelemetry.io/docs/security/handling-sensitive-data/)。

遥测三层分开：开发诊断日志可采样；运营指标关注接受成功率、等待/失败归因、模型并发与费用；安全及商业审计必须耐久记录关键变更，不能因采样丢失撤权/分享/客服提权/计费调整。审计记录 actor、代表主体、目标、策略版本、前后状态摘要、决定、来源与时间，不记录秘密。审计传输缓冲失败需要明确告警；关键动作若要求审计同提交，应在业务事务写审计 outbox。

| 候选 SLI | 计量范围与排除说明 | 运营用途 |
|---|---|---|
| 请求可接受性 | 合法请求得到耐久接受/明确拒绝；网络未到达单列 | 区分平台故障与预算、权限拒绝 |
| 状态可核对性 | 已接受工作可查询到带版本与时点的真实状态 | 发现长期卡住与丢回执 |
| 模型等待与失败 | 排队、首响应、完成、限流、供应商故障分开 | 并发上限、公平性与成本调整 |
| 撤权执行差距 | 撤权提交至各受控准入面拒绝旧资格的观测 | 验证真实安全边界 |
| 成果可取回性 | 已声明交付的文件/页面在权限允许时可打开 | 不以模型“已生成”代替交付 |
| 恢复有效性 | 演练覆盖数据类、实际丢失窗口、恢复时长 | 形成可兑现 RPO/RTO |

SLO 数值、观测窗口、支持时段与对外补偿政策待定。种子期先有能解释上述事实的仪表与值班路径，不建设庞大指标平台。故障状态页不包含租户私密任务；按影响面公告，支持系统能关联脱敏事件编号。

### 6.5 软件供应链与支持

构建使用锁定依赖、受控 CI、可追踪镜像摘要、依赖清单/SBOM、签名或来源证明以及漏洞处置流程。生产部署核对允许的构建来源；不让生成代码向平台 CI 注入构建脚本或拿到签名凭据。SLSA 可用来描述来源与构建保证等级，但采用规范不等于已经通过某等级。[SLSA 1.2](https://slsa.dev/spec/v1.2/)。

首期支持工具至少提供：按用户可授权工单查请求回执、连接健康、cell 代际、交付文件状态、预算预留与费用对账、导出删除进度；动作有审计且默认只读。建立故障分级、升级联系人、值班覆盖、供应商故障处理、退款争议与数据恢复演练流程。支持响应时间仍由团队能力决定，不预设全天候人力。

## 7. 桌面、移动、推送和交互成果

SP-13 负责本地安全壳：系统浏览器登录，适合原生客户端的授权码与 PKCE，OS 凭据存储，账号隔离的本地草稿与缓存，文件选择权限，深链目标校验，签名更新和失败回退。桌宠与完整客户端共享相同请求/状态协议；剪贴板预览、暂放文件、未发送输入在用户提交前保持本地，异步读取回调要检查对象是否仍存在、账号是否仍相同。上传重连不得把先前账号的内容交给当前账号。

移动系统可能暂停后台进程；“客户端离线”是入口状态，“云端工作中/节点工作中”是执行状态。客户端持久本地提交键，断线后先查回执；实时流提供游标补读或完整快照，不把 websocket 当消息唯一权威。冲突编辑通过版本检查与保留草稿解决，不以最后一次网络到达静默覆盖。

SP-08 先保存可靠通知中心记录，再投递 APNs/FCM/邮件。推送 payload 用最少内容与受控深链，不携带全文或审批授权令牌；打开后重新认证并读现行决定。FCM 返回 message ID 表示接受投递，不能等同于设备送达或用户已读；过期、折叠与离线都会影响实际交付。[FCM 消息生命周期](https://firebase.google.com/docs/cloud-messaging/customize-messages/setting-message-lifespan)。苹果服务端接入需按实际平台验证，未据只含目录的页面推导可靠性保证。

SP-09 的成果发布区与主应用分离 origin、cookie、网络和执行身份。静态成果先支持不可变构建 + 版本指针；有交互数据的成果另有命名空间与 schema/version，更新 UI 不重建用户已填内容。生成页面不能读取主应用 cookie、token vault、任意文件或云元数据；若需要调用外部动作，通过受控产品 API并复查分享者/操作者权力。页面内的按钮不能取得作者的全部代理资格。

发布动作区分 preview、private published、shared、withdrawn、expired（本报告描述态，非框架新增枚举）。构建完成不等于部署成功；只有可读健康检查和权限检查通过、版本指针提交后才交付“可使用链接”。撤下停止新的访问与动作，保留/删除历史和交互数据按产品政策；已下载内容不可追回。任意动态应用托管的支持语言、计算时长、外部访问与保留价格都是首发支持目录事项，不能由“做一个页面”扩张为无限通用 PaaS。

## 8. 商业资格、计量、预算与来源

用户选择的模型来源、执行算力、存储/托管服务分别计量。服务资格（能否使用产品）与预算（本次可消费多少）是两套判断；支付完成也不自动增大某件事的自主工作范围。用户有权暂停、取消续费和停止具体持续消耗；这些动作的生效时点与剩余保存责任需展示。

候选预算过程：按事情/租户/来源检查可用余额 → 原子预留该次上界或明确的估算额 → 允许模型/执行动作 → 写实际用量与供应商凭据 → 结算差额并释放剩余。并发调用争用同一预算时，共享权威 reservation/余额行保护额度；不能先读余额再各自消费。调用失败但费用未知时保留未结算项，不立即全额释放后再次超支。

硬上限能做到什么取决于供应商：若单次请求可限制输出、时长和并发，可给出本产品新增准入上限；供应商迟报、价格变化或实际费用超过估值时，不能假称用户账单绝不会超出。预留安全余量、预算软/硬级别、超额由谁承担均待产品裁决。先停止新的可计费调用，已在途部分如实结算。模型提供商限流、预算不足与平台故障有不同错误码和用户解释。

计量事件以真实 invocation/attempt/provider receipt 去重；重放事件不重复扣款。支付 webhook 验签后先持久 inbox，异步更新商业状态；重复、乱序和主动对账是正常路径。Stripe 文档明确可能重复交付且不保证事件生成顺序，候选支付商即使不是 Stripe 也要逐家验证相同边界。[Stripe Webhooks](https://docs.stripe.com/webhooks)。

**来源限制是一个显式 gap。** 框架要求模型请求经 OpenRouter。可选路径是用户提供 OpenRouter 凭据，或平台通过 OpenRouter 已支持且可验证的 BYOK 能力接入外部提供商凭据；这不是任意 OpenAI-compatible 地址直连。OpenRouter 官方 BYOK 描述的是其支持的提供商密钥集成，是否允许 fallback 也需按用户选择和实际配置核验。[OpenRouter BYOK](https://openrouter.ai/docs/guides/overview/auth/byok)。首发支持目录要明确具体服务与能力，禁止失败后静默换用平台余额。若用户坚持任意直连端点，则与框架全路由约束冲突，主线须带回裁决而不是外围悄悄绕过。

OpenRouter文档当前明确默认可能fallback到共享容量并消费OpenRouter credits，因此接入时要检查实际provider/key级设置，使用用户允许的来源集合，不仅在产品UI勾选“禁止切换”。同一平台workspace汇集多个用户BYOK时，是否能逐调用确定选中且只使用指定租户的密钥必须验证；未经验证不得上线这种共享保管模式。可从用户自己的OpenRouter凭据隔离路径起步，平台服务走平台凭据，连接引用、预算和回执均绑定此次来源。平台路由设置变化后重新验证，不能仅在首次连接时检查。

## 9. 隐私、导出、删除与有序退出

维护资料清单时同时覆盖原件、历史版本、派生摘要、记忆来源、检索索引、缓存、交互成果数据、分享 grant、通知、遥测、备份和第三方持有的副本。能导出原件不等于导出全部助理状态；导出包以 manifest 列包含项、版本、无法导出项和原因，结构化数据与附件有稳定关联。

导出前重验主体与范围，持久记录导出 job；以明确快照边界构建清单，分批生成时保留版本/时间说明；下载短期授权、可撤销且不公开缓存。删除前具体说明对象、范围和不可恢复后果。删除提交先禁止新读取/派生和分享，再逐 owner 清理并登记完成事实；失败项重试，不能因为一个子项成功显示全部已删。

框架持久记录与不可擦除历史的规则仍由其owner维护，SaaS不得直接改写追加日志或删除来源记录来模拟“已遗忘”。生命周期适配使用框架允许的删除/归档/整个主体退役接口；若某类记录没有当前支持的清理面，就将其列为尚未覆盖项及待明确保留范围，不能对用户承诺完整删除后再保留秘密副本。长期记忆的纠正与删除属于产品PWP-01建设，也不自动等于擦除原始会话。

备份按保留周期淘汰及密钥策略处理；恢复必须先应用删除/关闭墓碑，防止已删除资料复活。第三方已持有的数据只能给出已请求删除/无法控制的事实，不宣称全世界同步抹除。计费、争议与安全审计可能有独立保留义务，具体地域法律与政策需另行核定；本文不代替法律判断也不自行指定保留年限。

账户关闭候选链：身份增强验证 → 展示正在进行、待核对、已分享和未结算责任 → 暂停新增工作/消耗 → 用户选择可用导出 → 撤回设备/连接/分享 → 按政策停止订阅 → 处理在途与费用 → 删除或保留有依据的数据 → 发完成与剩余限制报告。停续费不等于立即删除，退出客户端不等于账号关闭。相关条目在原需求中含“建议补充”，需产品接受后成为发布承诺。

## 11. 一万注册用户的模型并发与费用测算

本节按用户要求只做可复算模型；不把普通数据库压力视为主要工程问题，不规定大型压测、缓存分层或吞吐优化。所有使用率数值是算例而非预测、套餐或承诺。

| 参数 | 基准算例 | 含义 |
|---|---:|---|
| N | 10,000 | 用户指定注册数 |
| d | 20% | 每日活跃比例，假设；DAU = N × d = 2,000 |
| u | 8 | 每DAU每日交互轮次，假设 |
| k | 2 | 每轮平均模型调用数，含委派/整理，假设 |
| W | 5,000 | 全部用户合计持续关注使命数，独立于DAU，假设 |
| e | 2 | 每使命每日有效变化/检查数，假设 |
| q | 0.2 | 每变化需要模型的比例，假设；不得每次轮询都调用模型 |
| a | 2 | 每次需模型的后台活动平均调用数，假设 |
| L | 20秒 | 平均单次模型在途时间，假设，需实测 |
| p | 6 | 同一24小时平均到峰值因子，假设 |

每日模型调用 `R = N*d*u*k + W*e*q*a = 36,000`。平均在途约 `R*L/86,400 = 8.33`；使用该粗略峰值因子约 `50` 个在途请求。该式来自到达率乘平均在途时间的估算，峰值相关性、流式长尾与供应商限流会使实际数偏离；它不是并发保证。配置全平台/租户/来源的公平并发和预算上限，排队说明原因，不能通过无限并发耗尽余额。

保持 N=10,000 的敏感性：d 从20%变40%，其余不变，R=68,000、估算峰值约94.4；L从20秒变60秒，在基准使用率下估算峰值150；W从5,000变20,000，基准DAU下R=48,000、估算峰值66.7。优先校验真实模型等待、token长度、后台使命是否有有效变化；不另列注册人数三档。

在线连接不能与模型执行并发等同。可在上线观测中记录同时在线客户端数量和重连峰值，用普通托管入口/数据库完成初始部署；大多数已注册用户处于休眠，后台使命也不要求各自常驻一个忙循环。常规API、资料读写与通知以真实错误/延迟发现问题后再调整。

月模型费用候选公式：`30 * Σ(每日各模型输入token/1e6 * 输入单价 + 输出token/1e6 * 输出单价 + 已核实附加费用)`；不得把缓存命中、BYOK费用或供应商价格当作默认优惠。基础运行费用 `Σ VM小时×小时价 + DB实例/存储/备份 + 对象GB月/请求/出站 + 队列/密钥/日志 + IdP/推送/支付费 + 域名与支持运营`。执行算力费用另加 `Σ执行CPU秒/GiB秒/磁盘/出站×核实单价`。自带节点的用户自付成本与平台实际收费分别显示。

种子期基础配置原则：一个主地域、外围模块化应用少量实例、一个托管关系库、对象存储、密钥服务、备份和少量cell；模型等待不意味着VM持续满CPU。决定cell数量先测框架常驻内存、活跃工作状态与恢复成本，禁止由本算例推导“一万用户需要一万VM”。本次未核查地区SKU、供应商价格或SLA，不给确定月账单；成本表待填单价、税费、币种、最小计费与地域，并保留访问日期。

## 12. 实施顺序、阻塞与评审边界

工程包明细在 work-packages.json，首期建议按三条可交付主链推进：A「注册→持久接受→模型调用→真实文件结果→换端恢复」；B「明确连接→有限外部动作→回调→撤权→故障核对」；C「远端节点→受限材料→真实结果→离线恢复」。数据生命周期、费用、遥测和备份跟随各链交付，不能留到所谓上线收尾阶段。

| 待决定项 | 不影响现在做什么 | 阻止什么 |
|---|---|---|
| 国际主地域与数据驻留 | 云中立接口、数据清单、恢复动作链 | 供应商/地域定案、跨境路由、真实价格与部署 |
| 首发OS与渠道目录 | 通用登录/同步、一个明确试验渠道的原型规格 | 宣称所有桌面/手机/邮箱可用 |
| 模型来源支持目录 | OpenRouter路径、来源/预算分离 | 任意兼容端点直连与静默fallback |
| 自主/离线执行/撤权窗口 | 把现行权限和在途事实建模清楚 | 默认无限后台权限或零延迟断网撤权承诺 |
| 保留、导出、删除、收费与SLO政策 | 生命周期job、manifest、计量/恢复证据 | 对外签订数值承诺与商业发布 |
| 框架目标提供者的实际完成 | 围绕承诺接缝实现外围 | 将未交付能力报成可运行，或复制框架内部语义 |

本稿不接受上述政策，不修改框架规格，不指定新包布局，不声称测试已通过。验收材料应包含具体失败注入、租户越权反例、撤权与迁移竞态、账单重复事件、数据恢复演练和完整用户旅程结果。正式施工前由主线对照框架基线、需求映射及独立评审意见，明确哪些是已承诺依赖、外围建设、适配缺口或用户待裁决。
