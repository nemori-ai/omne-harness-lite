# AI 助理 SaaS 外围架构投影（待评审）

需求基线日期：2026-09-30；本轮精化：2026-10-01。范围：外部真实 AI 助理产品的 SaaS 外围及与既有 harness 的装配边界。性质：候选投影，不是框架契约、实现声明或商业承诺。主线整合后接受状态仍须单列。本章只拥有外部SaaS的候选接缝与装配选择，框架事实始终归所引来源。

## 1. 依据、假设与领域读数

依据为《AI 助理产品定义与功能需求》讨论稿 1.0 和《用户故事》讨论稿 1.0（2026-09-30），沿用其 M01–M18、S01–S23 编号。用户新增规划基线为 **10,000 注册用户的种子阶段**。DAU、在线连接、执行并发、持续关注量均未确定；地域、供应商、预算、支持平台、服务价格、保留期限和 SLO 数值也未确定。暂按国际云中立、单主地域规划，可用区冗余和异地备份以地域裁决后为准。不是先建企业组织、席位或企业专属部署产品。

本次采用目标态框架作为依赖，而非把工作区存在代码当成已经交付。框架精确覆盖取主线 [框架基线](../../../../research/ai-assistant-saas-projection/framework-baseline.md) 和 [框架坐标](../../../../research/ai-assistant-saas-projection/framework-capabilities.json)，仓库观察基线 `2a04c2322a7b679133654acc3c4241effaade4be`；本稿定义外围需要接收/提供的接口性质，缺口不由外围私自填成框架承诺。部署、身份和数据责任分组是本产品的候选装配方式，不给 harness 新增正式语义或词条。

领域读数先记录如下，再展开机制。由于任务输入已经指定三类平面、cell 及身份链，**双盲未达成**；本表不声称独立防偏置。没有消费 Cordis 实现细节推导用户需求。

| 稳定编号 | 可观察结果与性质 | 类型、责任与验证 |
|---|---|---|
| P01 | 同一自然人在新设备找回原助理；个人无需建立组织 | 不变量；账号与供应；S01 中断注册续接、S23 新设备 |

| P09 | 分享只交付明确的内容与操作；成果可继续修改且不丢已记录交互 | 安全与不变量；成果托管；S18 |
| P10 | 重要决定和结果在可靠中心可回找，推送失败不吞事实 | 条件进展；通知；S19/S22 |

## 2. 种子阶段的装配建议

**候选建议：少量托管 VM 运行有状态 harness cells，外围业务作为模块化应用部署，可搭配托管容器等无状态宿主，外围数据库、对象存储、密钥、备份等使用托管服务。** 外围无状态入口可有少量实例用于更新与故障恢复；这不意味着同一 harness 状态有两个活动写者。具体 VM 数与规格依真实 harness 内存和模型等待行为测量决定，不按注册人数预开一万个实例。此建议以小团队、无既有 Kubernetes 运维平台为假设；若团队已有成熟平台，候选 B 的代价会改变。三个实质方案见 alternatives.md。

用户最新约束已纳入：一万注册用户的主要并发压力来自大模型；常规 CRUD、同步和通知按普通小型 SaaS 设计即可。优先解决持久化与分布式一致性，不以通用吞吐为由建设复杂缓存、分片数据库或跨地域多活。cell 是故障、状态归属与升级批次，不是流量分片指标。

### 2.1 三类责任并不等于三套微服务

| 平面 | 权威责任与报告节点 | 首期形状 | 不属于它的权力 |
|---|---|---|---|
| Control | SP-01 身份供应、SP-02 授权桥、SP-05 cell 路由、SP-10 商业资格、SP-12 生命周期；账号/成员权威仍在FC-28治理中心 | 外围模块化服务 + 外围控制库；独立单实例治理中心 + SQLite；管理接口独立权限 | 不直接改写 harness 内部任务状态，不代替具体外部动作确认 |
| Data | SP-03 API/同步、SP-04 内容、SP-08 通知、SP-09 成果、SP-07 外部回调 | 相同应用的逻辑模块 + 对象存储；按公开接口调用 | 不因持有文件或索引而拥有转发、模型读取或分享权限 |
| Execution | SP-05 单机 harness、SP-06 远端节点与沙箱、SP-07 外部效应、模型调用适配 | 每个 cell 一个活动 owner；短时工具执行与有状态 runtime 分开 | 不持有全平台管理员凭证；模型文字不能改变身份、预算或路由 |

### 2.2 框架接口需求及外围接缝

本表是外围消费者要求，并非声称框架每一项已交付。框架基线由主线另列；已承诺但未完成的提供者按依赖排期，外围不得复制一套相冲突语义。

| 接缝 | 外围提供/消费 | 必须保留的事实 | 未覆盖时的处理 |
|---|---|---|---|
| 身份装配 / IF-01 | SP-01先持久供应意图，再调用框架注册并查回绑定 | 外部绑定引用、供应意图、框架幂等注册引用或可唯一查回的受理/账号回执 | IF-01须明确框架已有/待接线的查回面；不能查回时停待核对，禁止再次注册，不写跨库同事务 |
| 请求接入 | SP-03记录一次明确提交，并查询该请求是否已被框架受理 | SaaS请求ID与框架受理事实的可查关联；用户新的主动发送是新的输入 | 仅网络重发先查原受理事实；不假设框架对用户输入通用去重，查不清保持待核对 |
| 外部执行 | 框架向SP-06/07交付受限动作与自身幂等键，适配器回传证据 | PF-012 §5.14按(会话, Run, 第几步)确定的键、动作参数、来源、外部标识/不知道 | 此键透传及回传Run日志是必需接缝；新attempt不得铸新业务键，未交付按框架依赖接续 |
| 资源与费用 / IF-05、IF-02 | SaaS在可替换模型发出实现之前装配每次预算准入；未放行不创建/发出新计费调用 | 预留/消费/调用关联、来源、实际/估计/未知；调用前工作等待与已创建调用终态分开 | HWP-01/03 + SWP-10须明确装配接缝；现行model-request-runtime/v2凭据不可用仍released终态，不改成悬挂；交付前不声称硬预算已实现 |
| 撤回与停止 | SP-02/05/06 发布撤权/停止事实并核对实际执行 | 新动作许可、在途动作、取消能力、核对结论 | 不把进程退出或取消请求回执等同于外部效果撤销 |
| 运行恢复 | SP-05 管 cell 生命周期，消费耐久检查点与恢复能力 | 唯一写者、版本、持久日志边界、未结算外部动作 | 无恢复依据不得对外宣称恢复成功；保留阻塞与人工核对入口 |
| 读模型与通知 / IF-07 | SP-03/08转发并消费各类型owner回执 | PF-008卡片池权威结论；产品业务决定由自身owner提交；类型、版本、范围、重放游标 | SaaS收到回答不等于卡片池已提交；自然语言答卡片须明确reply-to-card，不伪装普通插队 |

框架状态交接的当前已知限制：accepted registry 坐标不等于提供者已经可运行；PF007 的 Engram 占位不等于长期记忆完整交付；当前 PF015 连接件存在性/接入设计已搁置，产品邮件和日历适配可作为外围工程规划，但不能引用旧 data.connector/v2 宣称当前承诺；多节点产品目标与单机首版实施边界分别记账。

### 2.3 与框架权威事实的单向接线

| 报告节点 | 框架既有权威 | 外围实际新增与限制 |
|---|---|---|
| SP-01 身份供应 | FC-02/03，PF-001 的账号、个人组织、成员与登录治理 | IdP 验证适配、外部 subject 到框架账号的绑定、注册引导；自然人/成员不得另立SaaS主库。外围控制关系库只保存引用映射；当前FC-28治理中心独立单实例使用SQLite及其自身备份，不由外围PostgreSQL替换 |
| SP-02 授权桥 | FC-04/07/12 的资产权限、工具放行、显式决定 | 增加产品用途/出站/商业限制与用户入口；有效准入必须满足框架许可 **并且** 产品限制。SaaS allow 不能替代或覆盖框架 tool admission，框架拒绝始终拒绝 |
| SP-05 cell 装配 | FC-13/14/26/28/29 的会话、Run、据点与恢复事实 | 云部署与实例身份、operational route、版本与围栏；tenant/member身份不由路由器创造。若框架提供据点/归属定位，路由只存其引用与部署代际，不并行保存第二套领域归属 |
| SP-06 产品接入和编排适配 | FC-20/26，PF-020工作区实例/remote与节点领域规则 | 设备配对引导、网络穿透/中继、身份桥、支持目录与受控传输；工作身份、委派、工作区实例与执行结论复用框架owner。文中work/attempt/node回执是接缝需携带的信息；框架发起外部效果的权威结局仅入PF-012 §5.14 Run日志，SP-06不另定义结局域 |
| SP-07 外部适配 | FC-07/08 工具和MCP基础；FC-09当前搁置 | 自建首发邮箱/日历适配；默认以FC-08 credential-custodian为同一连接凭据的唯一逻辑owner（HWP-04依赖），SaaS vault仅其保密存储实现或保存引用；不将产品渠道改名为已接受框架Connector |
| SP-08 通知投递 | FC-21/22的日程/通知权威事实 | APNs/FCM/邮件交付适配、通知中心读面；不能让投递器独立决定同一批准事项 |

精确适配接口尚未被框架规格承接之处，由主线交接明确；本任务不重新论证框架承诺，也不以尚未实现为由否定目标态产品。以下动作链中的权威存储均按本表归属解释。

## 3. 统一身份、授权与委派

### 3.1 一条关联链，七种不同事实

统一身份意味着系统可以核实整条行动因果链，并不意味着把全部系统登录成同一个超级账号。采用成熟 IdP 的 OIDC 登录作为候选，OIDC 的职责是核实终端用户身份；OAuth 安全建议来自 RFC 9700。业务授权仍归产品与框架各自的资源 owner。[OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html)；[OAuth Security BCP](https://www.rfc-editor.org/rfc/rfc9700.html)。

| 层次 | 认证与身份键 | 授权、委派与保存边界 |
|---|---|---|
| IdP | 核验签发者、受众、时效、登录回调关联；以 issuer + subject 绑定 | 邮箱地址只作资料，不据同邮箱静默合并账号。账号恢复与新增 IdP 绑定属于安全操作 |
| 全局自然人 | 框架稳定自然人身份；SaaS仅绑定经验证的IdP方法 | 不默认拥有所有租户对象；个人登录恢复不应重复建立助理 |
| 租户成员 | member 指向 person 与 tenant；个人注册自动供应内部个人 tenant | 对外无需组织选择。成员资格、资源范围和动作授权每次核对；tenant ID 由可信映射取得 |
| 设备/节点 | 登录 session 与设备凭证分开；私钥存 OS 安全区或节点密钥区 | 设备可收回；节点另外具有可执行资格和本地资料范围。登录客户端不会自动共享磁盘 |
| 工作负载 | 服务或进程以短期工作负载凭据认证，可用云身份或 SPIFFE 类实现 | 服务认证只证明“哪个服务”，不能冒充“用户同意了什么”；限制 audience 与调用面 |
| 代理动作 | 记录实际 actor、代表的 member、委派链、目的、资源、动作、范围和费用来源 | 子代理、插件、远端节点仅得完成指定工作的最小资格，不能用父服务权限超出委托 |
| 第三方 OAuth | 连接记录绑定租户、服务主体、外部账号、scope 和 token 引用 | 令牌只交付专用适配器；OAuth scope 是外部上限，仍须核对事情使命和本次操作范围 |

SPIFFE 提供工作负载身份与可验证身份文档的概念；其采用本身不会赋予业务权限。[SPIFFE Concepts](https://spiffe.io/docs/latest/spiffe-about/spiffe-concepts/)。RFC 8693 的 token exchange 区分 subject 与 actor，可作为委派交换的实现候选，但本产品仍需明确可委派动作与深度，不假定第三方都支持 token exchange。[RFC 8693](https://www.rfc-editor.org/rfc/rfc8693.html)。

第三方连接的OAuth回调必须绑定发起的member、tenant、设备登录上下文、预期provider及一次性流程状态；不能在回调时只看当前cookie就把另一个账号接到本用户。token刷新只由框架credential-custodian这一逻辑owner协调，避免并发刷新把轮换后的凭据覆盖回旧值；刷新失败与用户撤权分别记录。连接令牌不交给模型、浏览器脚本或任意执行节点。SP-07只经保管方取用，不能为同一连接再持另一份refresh token独立刷新。若某产品专用凭据类型确需不同owner，须明确其与框架类型不重叠；同一连接迁移时先停止原owner刷新/使用、核对在途及供应商令牌，再完成显式交接，不同时双持。保管方未交付是HWP-04依赖，不以自建第二owner绕过。首版产品邮箱/日历连接令牌只允许SP-07消费，MCP bridge不获该连接的直接取用面；全部该类产品动作经过SP-02用途grant准入，不能借共享custodian绕过产品撤权。

### 3.2 逐跳检查位置

1. **客户端 → API**：核实会话、设备、当前成员、资源 tenant；检查动作及内容长度/格式，绑定请求 ID 和实际提交账号。客户端自报的 tenant、role、node 不能直接成为授权证据。
2. **API → harness cell**：核对路由代际与成员权限，形成已接受工作的持久回执；cell 独立核对当前 tenant、工作身份与授权引用，不能仅信任“来自内部网络”。
3. **cell → 工具/子代理**：收窄资源、允许动作、外发对象、可用来源与预算；记录本次委派依据。引用材料不是自动授权传播整个会话。
4. **工具网关 → 节点/第三方**：在实际启动新读取、写入、收费调用或发送前核对现行资格与撤权代际。节点核对自身收件身份、工作 ID、许可范围和本地路径；外部适配器核对连接账号与真实目标地址。
5. **结果 → 存储/用户/分享**：核对返回的 tenant、work、node、版本和接收人；源材料的可读权不等于可外发权。结果可能包含受限原文，不能因为是摘要而跳过出站判断。

“每跳重查”不要求每个字段都同步调用同一个中心服务。身份签名验证可以本地完成；影响立即撤权的资格和外部副作用准入必须访问足够新鲜的权威事实。缓存有效期、离线许可长度及最大撤权传播时间是待接受参数；候选建议是在无法确定权限时，外围适配器停止新的高风险外部效果并保留现有工作。已有会话离线继续的框架规则仍成立；这里不要求治理中心不可达就强杀会话，也不回溯否定先前合法动作。不能承诺无法联网的恶意自带设备一定停止本地运行。

### 3.3 撤权、在途与退出

产品连接撤权的候选提交点明确为SP-02的用途grant写入revoked/新代际，及其outbox在**同一SP-02事务**提交。首版邮箱/日历只由SP-07消费令牌，SP-07在准入新操作时读取SP-02 grant，该点后拒绝旧资格；FC-08 custodian停止分发、供应商撤销token是后续各自回执，不能把它们写成跨owner同事务，也不能等待它们成功才承认SP-02本地禁新已生效。已准入、已发送或第三方已受理的动作分别核对；若承诺已排队但未准入动作也不得启动，准入与撤权须共同读取SP-02该grant的现行版本。令牌停发/撤销未完成明确展示，MCP bridge没有绕过SP-02直取本产品连接令牌的入口。

用户操作应区分：退出当前客户端使其 session 失效；收回设备使其会话/执行资格失效；暂停主动活动禁止新的自主工作；结束事情/资源使命停止该目的的后续动作；撤回账户连接影响所有依赖；关闭账号进入总退出流程。**后台工作依赖持久、可撤回的工作授权，不能偷留客户端 refresh token 当作持续同意。** 用户退出当前客户端后，已有合法云端工作可继续；账号关闭或停止服务则按收尾政策禁止新增消耗。

这里的客户端 session 是登录凭据上下文，不等于框架持久工作会话。FC-26/PF-016 rev10 §5.6、§6.17明确中心现读的触发边界及已有会话离线继续，且没有离线时长上限。本方案不把每次工具调用改成治理中心现查，也不以租约到期结束框架会话。有限离线许可只可用于新增的SaaS外部资源/效应入口，在其政策经接受后限制该入口的动作资格；本地既有工作仍遵守框架权威规则。收回设备后的远程会话不应因UI失效被误报已停止。该PF-016条款原理由针对用户自有据点；本候选只采用“治理中心不可达本身不结束已有会话”作为平台cell的运行前提，不将其扩张为平台付费资源在任意网络分区下仍无限可用。

**模型入口的独立依赖（IF-05/IF-02）。** 治理中心不可达与SP-10预算/凭据保管方不可达是不同事实。SaaS在可替换模型发出实现之前装配每次预算准入，包括Loop内部后续调用；未放行就不创建/发出新的平台计费请求。此时“等待”是**产品/调度在调用创建前的工作等待**，不是模型调用runtime的等待态。准入放行并创建调用后，原`model-request-runtime/v2` S-19/S-29⑧仍适用：凭据不可用写`released{cause: credential_unavailable}`终态，不能把已终结调用假装挂起或恢复成未完成；后续走既有失败处理与用户可见的工作接续。会话保留，已发调用继续记录结果并结算。IF-05/IF-02的装配点、返回值与消费身份尚待HWP-01/03 + SWP-10明确，交付验证前不声称硬预算已实现。平台托管cell按可信调用实现取用凭据，具体模式见§5.1/§8。

对自带节点采取诚实的安全模型：平台能停止派发、停止提供秘密、拒收过时代际的变更、收回平台资源入口；节点所有者能控制本机，平台不能追回其已经持有的明文或保证断网中的第三方直连停止。需要强撤权的外部副作用经受控网关；必须本地直连的能力在支持目录明确在途限制，远端断连时不自动改派重做。

### 3.3a 决定按类型保有唯一owner

PF-008的Ask/系统拦截卡片由**框架卡片池**权威提交；SP-03/08只转发回答并等待卡片池回执，SaaS转发接受不表示卡片已答。产品自己的业务决定（如事情范围或产品批阅对象）才由相应产品owner提交，类型及引用必须可辨，不能复制框架卡片为第二份产品决定。自然语言答卡片使用明确的`reply-to-card`关系及card ID/期望版本，由IF-07/IF-02接线；普通会话新输入保持原意，不伪装成插队去暗答卡片。重复、冲突、拒答与超时都以对应owner结论为准。

### 3.4 分享与客服

分享授予的是某份成果/版本及明确的阅读或交互权，不是加入整个个人 tenant。匿名链接、指定收件人、登录参与三种方式不能混为一项：首发支持哪些由产品决定。每种方式均有独立 grant、可见数据、到期/撤回状态；链接泄漏后的已下载副本不能被技术上收回。严格即时撤回内容需授权代理读取，不用长效公开对象 URL 绕过检查。

客服默认只见服务元数据与用户主动提交的诊断包。身份恢复、代用户访问内容、发起退款与读取日志是不同权力。提权必须有工单、目的、范围、时限和记录；高风险账户操作按既定人工核验政策执行，客服不能直接把自己加成用户成员，也不能借助理代发消息。紧急访问流程可以不依赖故障用户在线，但属于单独受控运营政策，需事后复核；未经接受不得预置“全局万能客服账号”。

## 4. 持久化、事件和一致性

### 4.1 一个事实一个写者

| 数据 | 写入 owner / 存储 | 一致性与重建 |
|---|---|---|
| 框架账号、成员、登录治理 | FC-02/03/28治理中心；独立单实例SQLite | 框架治理owner提交与自身备份恢复；外围只保存绑定引用 |
| 产品设备、外部资格、部署路由 | SP-01/02/05；外围控制关系库 | 同owner资格/代际与outbox同事务；恢复必须进入新restore epoch并按§6.3使旧资格默认不可用 |
| 产品请求与内容元数据 | SP-03/04；数据关系库 | 提交内容摘要与幂等键；同键异内容拒绝，不误认成旧成功 |
| harness 工作与状态 | 框架 owner；每 cell 已选定的持久存储 | 外围只通过接受的接口查询/迁移；共享托管 DB 候选不能改成任意多活写 |
| 原件、版本、构建产物 | SP-04/09；对象存储 | 不可变版本 + 校验和 + tenant 范围；元数据先临时态，完成核验后发布为已保存 |
| 框架发起的外部效果结局 | 框架Run日志，PF-012 §5.14；SP-06/07仅持适配证据/传输回执 | 幂等键仅由(会话, Run, 第几步)确定并透传；外部标识及不知道回写Run日志后才成为框架权威事实 |
| SaaS自有支付、导出等动作 | SP-10/12等相应产品owner的动作记录 | 独立产品动作使用自身稳定业务键；不得拿它代替或重铸框架step幂等键 |
| 用量、金额、预算预留 | SP-10；台账及供应商回执 | 追加调整条目而非覆盖历史；未知费用不填零 |
| 通知与已决定事实 | PF-008卡片池拥有框架卡片；产品业务决定归自身owner；SP-08仅inbox投影 | 转发接受与权威答复回执分开；自然语言答卡片明确reply-to-card；已读不是同意 |
| 检索/向量/预览索引 | SP-04 派生层 | 可重建；删除和权限变化传播可核对，检索结果读取前再授权 |
| 遥测/审计/备份 | SP-11；分开受控存储 | 审计不是采样日志；备份不是删数据的例外黑箱 |

首期可以用一个托管 PostgreSQL 集群承载**外围**控制与业务表，但模块不直接修改其他 owner 的事实。FC-28治理中心继续独立单实例SQLite与自身备份；它不是PostgreSQL中的一组表。本候选不以尚未存在的PostgreSQL治理提供者替换已交付范围。同一事务保护的承诺必须写出共同表/行：例如SaaS供应意图/外部绑定行、产品授权撤销代际行、预算余额/预留行、cell assignment行；这些事务不包含框架账号创建。跨外围库与 harness 库默认是显式状态机和重试交接，不用“都在同一云”假装跨库原子提交。

**资料与workspace的单写边界（IF-06）。** 对SP-04资料，workspace中的文件只是标记了SP-04基准版本的工作拷贝；编辑后发布必须带该基准版本对SP-04做CAS，冲突时保留工作拷贝并说明需核对，不能双向最后写入覆盖。对框架原生workspace资源，workspace owner仍是文件权威，SP-04只存带取得时间/版本的快照引用，不反向成为另一个文件master。成果和派生资料分别保留来源，快照与当前原件不可混称。

### 4.2 两个最容易误报成功的窗口

**文件上传。** 客户端申请绑定 tenant/对象/大小/类型的短期上传许可，先传到隔离暂存区；SP-04 校验内容摘要、完整性与安全处理结果后，提交正式版本与可读取状态。上传成功只表示字节到达；格式提取、模型读取各有事实。临时对象清理依照 manifest，不删除正在提交或被版本引用的对象。批量上传逐项回执，单项失败不回滚成功原件。

**命令接受。** SP-03先持久记录一次用户明确提交的请求及摘要，返回的回执只证明产品入口已接受。PF-014 §6.3对用户主动发送一律不去重：用户主动再发同一段文字仍是新的输入，不能用内容摘要吞掉它。客户端因断网重发同一次网络请求时，SaaS入口以原请求身份查询自己的交接记录，并通过必需的受理查回接缝核对框架是否已受理。只有可证明尚未交付/受理时才继续原交接；已经受理则复用查询结果；结果不明保持待核对。这里要求的是“可查询原受理事实”，**不假设框架已有通用request-id幂等受理**，也不把重复投递交给框架猜测。网络错误不能决定服务端是否提交。

**注册供应（IF-01）。** SP-01在任何框架注册调用前，先在外围库写供应意图、验证过的issuer/subject绑定候选和稳定外部引用；该事务不创建框架自然人或成员。随后调用框架注册组合，并保存框架回执/身份引用。框架提交而SaaS未记回执时，恢复须按IF-01约定的框架幂等注册引用或可唯一查回的外部绑定引用核对；已有主体就补齐绑定，确认未创建才继续。若现有框架接口没有该查回能力，本候选将IF-01登记为必需接缝，供应停在待核对并交由owner处理，**不得因SaaS绑定表为空再次注册**。

### 4.3 可靠事件与重放

外围 owner 在更新业务事实的同一事务写 outbox，投递器再交付托管队列或最初的数据库投递作业；消费者用 `(consumer, event_id)` inbox 去重，业务写入与消费确认同事务。事件包括 tenant、owner、对象 ID、对象版本、发生时间、因果请求、schema 版本与必要授权引用，正文尽量用受控引用。仅对同一对象有必要的事件检查版本，不引入全局总序。[AWS outbox 指南](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)支持避免数据库与通知双写窗口，并明确消费者仍需处理重复。

投递保证不能扩展成外部效果恰好一次。邮件 API 或付款 API若没有可用幂等语义，遇到已发送但回执丢失先查外部事实，无法查明保留 unknown，交由用户或支持核对。死信要保留原因、租户、原请求与重放权限；运维重放仍受现行授权、预算和版本检查，不能把旧消息当成永久同意。

候选最简部署可用关系库outbox worker完成后台交接，是否另加托管队列取决于产品渠道和任务类型。此处采用队列是耐久交接与重试需要，不是吞吐承诺。Cordis 进程内事件不承担跨进程可靠投递。

### 4.4 外部事件进入框架的合法接缝

框架入站source kind是闭合集，不能新增万能system、伪装用户/extension或复活已搁置Connector。首版路线由IF-08与IF-04接线：SP-07的事件接收、验真、限定范围外部轮询和去重都是**无模型的机械处理**，先持久保存待处理意图、真实来源/取得时点与权限引用。仅当确有待处理意图且产品策略判断值得唤醒时，PWP-10以真实租户归属和获准用户/agent身份，经IF-04创建真实的一次性Schedule；同一事情尚未到期的安排归并，创建/归并有稳定关联。补跑、重叠和通知行为逐项配置，无事件不创建空agent轮询会话。Job建立新作业会话后通过获准工具读取事件；Job首输入及`scheduled_trigger`的精确数据形状由IF-04定形，本候选不宣称已经冻结。日志记录真实日程触发，读取结果保留外部事件原来源，不能把两者混为一个来源。

另一条有限接缝是**原后台工具runtime仍存活**时沿真实callId回传。按PF-006 §6.12，停机/迁移使该runtime中断后，恢复追补异常中断并收场为失败；不得再向该callId补成功回传或让执行复活。此后到达的事件仍保存在产品待处理意图，转上面一次性Schedule路径，不能把跨周等待托付给会消失的后台执行。没有真实Job或存活callId时保持待处理意图，不伪造其中任何一个。

## 5. 单机 cell、远端节点与安全调度

### 5.1 Cell 是单机框架的持久部署边界

每个cell有稳定部署身份、存储边界、当前代际、分配给它的tenant集合和版本清单。一个tenant的相关harness状态首期只归一个活动cell owner，不随机轮询给多个进程。**多租户共享cell只是一项有前提的候选**：PF-005 §6.2的宿主执行对全部共享租户默认禁止（never-allow），非可信工具进入隔离执行；身份/policy、框架日志、凭据保管与其他租户数据不得挂载或暴露给工具。平台密钥只由可信模型请求实现按调用取用，不在共享宿主上放可被租户工具读取的凭据文件。PF-016 §6.20的自有据点凭据限制不被改写；若其提供者/装配方式不能满足上述隔离，就不采用该共享布局。密度待实测，不预设每租户一VM，也不由一万注册数推出一万实例。

**候选A的持久介质与围栏原语。** cell持久状态放在该cell专属、可detach的持久卷，不能只存VM易失本地盘。围栏云API由SP-11实际执行并取得原实例stop完成、持久卷detach完成、旧工作负载身份/受控效果资格revoke完成三类可信回执；SP-05消费并核验这些证据后才切换路由，不重复充当云取证owner；命令已提交、心跳超时、DNS切换或generation改变均不够。具体云/卷类型须验证这三类证据以及无隐藏写入者，不能detach或无法证明旧实例停止时保持停顿。已发出的模型/第三方请求另行核对，停止实例不会追回它们。

外围路由记录采用`tenant -> cell + restore_epoch + generation + placement_state`，generation只在同一epoch内递增。**任一影响平台准入的权威输入从备份/旧状态恢复，都必须由SP-11独立恢复控制点激活fresh restore epoch**，尤其包括外围控制库、治理中心SQLite、授权库、凭据保管库与预算/路由事实。该控制点的介质、条件激活、强一致现读和自身丢失处置见§6.3；不能只把外围PostgreSQL恢复算入触发。受控路由、数据/分享访问、效果网关、模型预算与凭据取用入口都现查该控制点，只接受与当前epoch相等的资格；不能确认当前值就拒绝新的受控访问/效果。不能从恢复出来的旧generation加一生成“新”资格，也不能仅凭随机epoch存在便自动开放。旧入口进程若无法接受新epoch规则须先隔离，非受控的BYOK直连限制另见§8。

cell迁移按以下顺序：SP-05 draining禁新派发 → 保存Run日志中未结算动作及适配证据 → 收口可完成工作 → SP-11执行云API取得stop/detach/revoke回执，SP-05核验 → 恢复一致版本但禁外发 → 核对权限、预算、删除与外部未知动作 → 在当前独立epoch内CAS切assignment generation → 开启新owner。任一权威输入恢复还必须通过§6.3的旧资格全部可疑门；路由提交不能替它放行。框架若无租户级迁移面就迁移整个cell，不复制私有表自造热迁移。

**凭据驻留。** 平台托管cell保存引用，可信模型请求实现取得本次有效预算许可后短期取用平台密钥；模型、任意工具和沙箱都拿不到该秘密。结束取用、销毁内存或断开vault只能说明不再主动提供，不能证明泄漏副本或已发请求被撤回。在平台托管cell执行的BYOK请求也由可信请求实现按该租户的连接引用取用，不交任意工具。若所选框架提供者或用户自有据点的既定离线方式需要本地BYOK副本，沿框架保管与隔离规则实施，并显式记录副本持有者；未验证引用适配时不能谎称不存在副本，也不能借此放宽共享cell前提。平台不承诺轮换用户密钥，迁移与未知费用按§8处理。

### 5.1a 装配内保证与跨进程兑现

| 保证 | cell内的权威/装配 | cell与外围/节点之间必须兑现 | 不满足时 |
|---|---|---|---|
| 会话租户身份不变 | PF-015会话创建身份由框架持有 | 每跳传原身份引用并验证，路由不能改写租户 | 拒绝错误归属的操作/结果 |
| 日志先于可见/上下文 | PF-012会话/Run日志拥有事实 | 适配证据回写日志后才宣称框架结局；受限结果进入日志前先出站判定 | 保留待核对；不把适配器回执当最终成功 |
| 取消跟宿主、停止不等于回滚 | 框架Session/Run与模型/工具执行控制规则 | 显式控制请求、原callId/执行身份和真实回执，断线不等于停止 | 未知/不可取消分别显示 |
| 同一步外部效果幂等身份 | 框架按(会话,Run,步)铸键 | SP-06/07和支持幂等的供应商透传同键，attempt不变业务键 | 不支持核对时保持不知道，不盲重发 |
| 生命周期与服务可见性 | Cordis进程内所有权/依赖装配 | 跨进程须独立身份、耐久交接、epoch现查与存储围栏 | 进程dispose不冒充撤销外部效果 |
| 治理中心失联时已有会话继续 | PF-016自有据点规则；本候选有限采用为cell前提 | IF-05/IF-02在调用创建前做平台预算准入；已创建runtime仍执行原凭据失败终态 | 工作可在调用创建前等待；已有调用失败如实接续，不使会话到期 |

Kubernetes StatefulSet 提供稳定 pod 身份和持久存储关联，但它不替本产品定义 cell 迁移、数据事务或外部副作用围栏。[StatefulSet 官方说明](https://kubernetes.io/docs/concepts/workloads/controllers/statefulset/)。VM 重启、容器重调度和多副本同样不能代替上述责任。

### 5.2 自带节点接入和派发

**M05默认候选形状（IF-03）。** 中心cell持久保存Session/Run，远端节点承接受限工具动作；远端只保管其接受回执、执行观察和出站证据，不另建与中心竞争的Run，也不把中心Run搬到节点。节点选择解决算力/资料地点，cell宿主迁移是另外的基础设施恢复动作，不能混成业务Run跨节点迁移。IF-03需精化派发、节点回执、失联核对与结果回传协议；尚未交付协议不能由SaaS自定框架工作域。

用户安装受支持执行端后，用短期一次性配对流程在可信客户端确认节点；设备注册保存公钥、所属 tenant、可用能力、资料范围及版本。节点从内向外建立认证连接，减少暴露家庭/公司设备入站端口；中继只路由显式协议，不允许任意内网隧道或控制面管理访问。配对码不可作为长期执行凭证。

节点能力声明包括软件/工具能力、可处理资料引用、位置约束、当前空闲与最后报告时间。能力声明不是资料授权；用户许可的目录变化或节点报告过期需要重验。执行选择顺序建议为：资格与地点硬限制 → 资料/工具可用性 → 来源与预算 → 当前负载、耗时和质量偏好。仅余量不足可以排队；权限不足不能当成负载失败转发另一台机器。

每个派发携框架work/Run/step身份、attempt ID、目标node、restore epoch与assignment generation、输入版本、动作能力、可出站范围、来源及预留引用；框架外部效果幂等键仅按(会话,Run,第几步)确定并透传，attempt只用于观察尝试，不参与重铸业务键。节点先把“已接受”写入本地耐久回执，再启动工作；结果带原身份、内容摘要和真实执行证据返回。节点接受/启动/适配证据分别保存；框架发起的外部效果结局由Run日志接收外部标识或不知道等事实，SP-06/07的独立台账只是证据和核对输入，不单独宣告最终成功。

节点断线后，平台不能凭心跳过期重做有外部副作用的工作。纯计算在授权允许、成本允许且结果可去重时可另起 attempt；可能发送或修改的操作先核对。重连先在节点完成出站检查，再传递允许返回的动作对账证据；框架日志核对完成后才接新任务。撤节点先禁新派发与秘密获取，在途分为未启动、可取消、已外发、结局未知；旧结果可保存为证据，但不能据过期权力继续后续动作。

### 5.3 沙箱和数据地点

生成代码、网页抓取、文件转换和用户依赖安装是非可信执行，不与身份服务、token vault 或 harness 状态库共用管理权限。采用 VM/microVM 或经过验证的沙箱运行时候选，限制 CPU、内存、磁盘、时长、进程数、出站和挂载；未开放默认禁止访问控制元数据与云实例凭证。普通容器共享宿主内核，namespace/网络策略只是隔离的一部分。[Kubernetes 多租户说明](https://kubernetes.io/docs/concepts/security/multi-tenancy/)。

“资料不能离开节点”至少分清：原件不得上传、摘要不得出站、只允许特定字段结果、模型请求是否可以含原文。检查范围包括检索摘要、工具stdout/stderr、错误栈、trace/log、临时缓存、崩溃诊断和最终成果；各类返回通道均需最小化与出站策略，不能只检查文件复制。若当前模型请求统一经 OpenRouter，且任务要求任何内容都不离机，则不能一边调用外部模型一边声称本地处理。可在节点执行不需模型的程序处理、只返回获准聚合结果，或等待支持范围裁决；不偷偷改成直接本地模型以绕过框架来源约束。

节点返回内容在进入云cell的agent上下文前按PF-012 §6.1先落会话日志，PF-010 §6.12限制擦除原始记录。因此出站范围判断必须在节点侧、发送到云日志之前完成，判断依据与允许的内容摘要留在节点证据中；用户须先知道获准结果仍可能含敏感内容，以及进入框架历史后的删除限制。不得先发原文到云端日志，再靠后置过滤或SaaS删除job声称收回。

## 6. 云原生交付与日常运营

### 6.1 环境、网络与秘密

开发、预发布、生产使用独立凭据与数据边界；基础设施通过版本化 IaC 重建，生产手改进入变更记录。公开入口只承接客户端、OAuth 回调、受验证 webhook 和成果域；数据库、队列、cell 管理、secret vault 与遥测入口走私有网络或强工作负载认证。出站允许范围按执行种类管理，第三方 webhook 验签不能只靠源 IP。管理入口单独认证、多因素验证与最小权限。

秘密的加密存储使用专用密钥/保密设施；逻辑拥有者与存储设施分开：第三方连接默认归框架credential-custodian单一owner，OAuth刷新由它协调；SaaS vault是其保密存储实现或只存引用。平台IdP client secret、OpenRouter平台key、推送凭证、签名密钥分别由对应服务owner控制读取。采用信封加密候选，密文记录携带 key version，轮换期间明确读取旧版本与新写版本。日志、trace、错误、模型消息和导出默认排除秘密；用户在专门设置页添加 API key，助理只看到连接引用、能力及验证结果。

失窃处理在可控制范围内冻结资格、轮换平台服务身份、向供应商申请撤回受影响连接并清点在途操作；这些动作须得到实际回执，平台不能承诺轮换用户自己的BYOK。不得假设删掉数据库字段就使第三方已签发 token 失效。云 KMS 不等于业务租户授权，也不能凭“加密”宣称平台运营人员永远无法看到内容。

### 6.2 升级、迁移与兼容

每次发布记录客户端/API schema、harness 精确版本、存储 schema、插件集合、执行端协议和基础镜像摘要。先扩展兼容读写，再迁移数据，最后移除旧字段；若迁移不可逆，回滚方案必须是恢复备份或前滚修复，不能承诺旧二进制一定能读新库。协议支持窗口由产品确定，超出窗口的旧客户端保持本地草稿、清楚提示升级，不能静默丢掉输入。

cell 升级先停新增工作，核对在途，按第5节单写交接；外围无状态服务可分批更新。灰度按 cell 或内部测试租户，不把同一个 tenant 的状态写入随机分给新旧两个 owner。发布健康检查包含登录、资料读取、一个可撤销委托和状态重连；容器存活不等于功能可用。

### 6.3 备份、恢复与灾备

恢复对象至少包括：外围身份映射与控制库、FC-28治理中心SQLite及自身备份、cell持久卷、原件与成果对象、产品授权/撤权事实、计量台账、密钥引用与可恢复密钥、部署配置和版本。治理中心独立单实例意味着其故障时新建会话/治理/切身份等现读操作受影响；已有离线会话按框架规则继续。采用其已交付SQLite备份/隔离恢复范围，不据此宣称整机灾备已验证；外围PostgreSQL的PITR不恢复治理中心。独立restore epoch控制点与外围控制/治理存储的物理恢复域分离，禁止把同一PostgreSQL集群另一个数据库当成独立控制点。关系库 PITR 只覆盖其数据库状态，不能让对象存储、第三方发送或另一 cell 同时倒带。PostgreSQL PITR 依赖基础备份及连续 WAL，且配置文件不自动由 WAL 恢复。[PostgreSQL 恢复文档](https://www.postgresql.org/docs/current/continuous-archiving.html)。

备份 manifest 记录一致性边界、生成时间、对象校验、版本与依赖。至少定期在隔离环境实际恢复，再查租户隔离、文件完整性、原请求关联和未知动作；只有备份任务成功不算恢复验证。跨地域副本在地域与数据驻留许可确定后配置；首期灾备是被动恢复，不能顺势变成跨地域多活。

**恢复控制点的具体介质。** 候选采用与控制/治理存储**物理恢复域分离的托管强一致对象存储**，存当前epoch指针与候选激活记录；地域内托管多可用区可用性是采用前提，不自建共识集群，也不承诺零宕机。SP-11先写不可变的候选激活记录，再对当前指针做条件写；成功将指针切到该记录是唯一激活提交，孤立候选记录不算激活。创建用“此前不存在”条件，后续切换比较已读取的当前对象版本；访问策略阻止无条件覆盖/删除，冲突时重新读取当前指针，不能盲重试覆盖。控制库、治理SQLite或授权库恢复不得回滚这组对象。

Amazon S3的[强一致性说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html)、[条件写](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)与[强制条件写的访问策略](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes-enforce.html)是可选原语的能力例证（观察2026-10-01，EXT-15/16/17）；尚未选定供应商，不把这些保证泛化到任意S3兼容服务，也不以文档代证完整epoch协议。具体多可用区/地区能力、条件操作及访问策略都要在选定服务验收。

每个受控效果/敏感数据入口在新动作准入时**强一致现读当前epoch**，不允许用陈旧缓存继续放行；读取不可达就拒绝该新增效果。它是同步可用性依赖并产生请求、延迟和存储费用，计入运行预算与故障面；一万用户的普通负载没有理由引入“可能陈旧但先放行”的优化。强一致读也不追回准入后已经外发的动作，它们继续按在途/未知事实核对。

**任一权威输入恢复的安全门。** 外围控制PITR、治理中心SQLite、授权/凭据保管库、预算/路由或其他影响身份权限判断的权威输入恢复，都先关闭平台受控入口，再由上述独立控制点条件激活fresh epoch并进入旧资格可疑门。治理库恢复可能带回已撤登录、旧成员或旧权限；PF-017 §6.18及其未决治理后果仍归PF-017/PF-001 owner，外围不裁决这些事实的新含义，只在门外拒绝新受控效果，直到具备可信的当前身份、权限与凭据依据。此限制只作用于SaaS受控入口，不改变自有据点已有离线会话承诺。

**控制点自身丢失。** 当前指针/激活记录丢失、遭篡改或不可核实时，全门保持关闭；不能从任一旧库推算当前epoch。由受保护的恢复管理身份人工恢复新的信任根与控制点，轮换/实际失效旧平台资格和相关访问身份；隔离仍指向旧根的入口，逐入口确认新根、现读和拒旧均有效后，才逐项重新开放。恢复一个旧指针备份本身不能授权开门；未知用户自持BYOK密钥不因更换信任根被追回。SP-11执行恢复/云取证，SP-05只消费证据协调实例和路由。

恢复后默认把**全部旧的平台授权、分享grant、访问票据、平台凭据资格与旧预算许可**列为可疑不可用。不能假定只影响备份点之后几条记录，因为任一已恢复权威库及其未投递outbox都可能同时失去撤权。按独立审计、供应商回执、各cell已观测事实核对；缺口不能补齐时，相关主体必须重新验证，资源/分享/消费范围必须重新授权后才可逐项发新epoch资格。日志存在、快照校验成功、用户仍能登录或旧token尚未过期，均不构成恢复许可。保管方停止分发/使用旧的平台调用凭据；重新启用前须核实持有者、用途和供应商侧状态，需要撤销/替换时取得真实回执。未能使旧实例或可能泄漏的秘密副本失去使用能力时，继续按在途/未知费用窗口处理，不宣称旧凭据已被全球撤回。由最新可信保留/删除政策无法确定的数据保持不可访问，交给对应owner处置，不能先开放旧内容再等用户投诉。

新的敏感数据/成果访问经能核对epoch与资格的入口；旧直连对象票据如能绕过该入口，必须先使对应原始入口/签名资格不可用，或取得票据实际失效的证据，才开放受影响服务。仅刷新产品分享表不能撤掉已发的供应商票据。已下载或外部持有的明文不能追回；非受控BYOK直连不纳入平台凭据已撤回的断言。

在这些门通过后，再逐类开放经过重新核实的读、分享和新动作，核对未知外部效果与未结费用后接续。数值RPO/RTO按数据类别和演练结果定稿；撤权/删除安全不是给数据库RPO填一个数字就获得，缺失事实以停用旧资格换取安全。该规则不改变harness自有据点已有离线会话寿命。

### 6.4 遥测、SLO 与审计

trace关联客户端request、租户匿名引用、cell/restore epoch/generation、框架Session/Run/step与work/attempt、model invocation、外部 provider request、artifact version 和费用预留。模型等待 span 与实际 CPU 执行分开，避免等待外部误报死循环。记录参数摘要和对象引用，默认不采集原始 prompt、邮件正文、文件内容、Authorization header 或 API key。OpenTelemetry 支持属性删除、过滤和裁剪，但采集方仍负责最小化，哈希标识也不自动匿名。[OTel 敏感数据指导](https://opentelemetry.io/docs/security/handling-sensitive-data/)。

遥测三层分开：开发诊断日志可采样；运营指标关注接受成功率、等待/失败归因、模型并发与费用；安全及商业审计必须耐久记录关键变更，不能因采样丢失撤权/分享/客服提权/计费调整。审计记录 actor、代表主体、目标、策略版本、前后状态摘要、决定、来源与时间，不记录秘密。审计传输缓冲失败需要明确告警；关键动作若要求审计同提交，应在业务事务写审计 outbox。

| 候选 SLI | 计量范围与排除说明 | 运营用途 |
|---|---|---|
| 请求可接受性 | 合法请求得到耐久接受/明确拒绝；网络未到达单列 | 区分平台故障与预算、权限拒绝 |
| 状态可核对性 | 已接受工作可查询到带版本与时点的真实状态 | 发现长期卡住与丢回执 |
| 模型等待与失败 | 排队、首响应、完成、限流、供应商故障分开 | 并发上限、公平性与成本调整 |
| 撤权执行差距 | 正常撤权传播及治理SQLite/控制/授权/凭据等任一权威恢复后：新epoch生效、旧资格默认停用、缺记录时重新授权的观测 | 验证恢复不会仅凭旧快照复活权限 |
| 成果可取回性 | 已声明交付的文件/页面在权限允许时可打开 | 不以模型“已生成”代替交付 |
| 恢复有效性 | 演练覆盖数据类、实际丢失窗口、恢复时长 | 形成可兑现 RPO/RTO |

SLO 数值、观测窗口、支持时段与对外补偿政策待定。种子期先有能解释上述事实的仪表与值班路径，不建设庞大指标平台。故障状态页不包含租户私密任务；按影响面公告，支持系统能关联脱敏事件编号。

### 6.5 软件供应链与支持

构建使用锁定依赖、受控 CI、可追踪镜像摘要、依赖清单/SBOM、签名或来源证明以及漏洞处置流程。生产部署核对允许的构建来源；不让生成代码向平台 CI 注入构建脚本或拿到签名凭据。SLSA 可用来描述来源与构建保证等级，但采用规范不等于已经通过某等级。[SLSA 1.2](https://slsa.dev/spec/v1.2/)。

首期支持工具至少提供：按用户可授权工单查请求回执、连接健康、cell 代际、交付文件状态、预算预留与费用对账、导出删除进度；动作有审计且默认只读。建立故障分级、升级联系人、值班覆盖、供应商故障处理、退款争议与数据恢复演练流程。支持响应时间仍由团队能力决定，不预设全天候人力。

## 7. 桌面、移动、推送和交互成果

SP-13 负责本地安全壳：系统浏览器登录，适合原生客户端的授权码与 PKCE，OS 凭据存储，账号隔离的本地草稿与缓存，文件选择权限，深链目标校验，签名更新和失败回退。桌宠与完整客户端共享相同请求/状态协议；剪贴板预览、暂放文件、未发送输入在用户提交前保持本地，异步读取回调要检查对象是否仍存在、账号是否仍相同。上传重连不得把先前账号的内容交给当前账号。

移动系统可能暂停后台进程；“客户端离线”是入口状态，“云端工作中/节点工作中”是执行状态。客户端持久本地提交键，断线后先查回执；实时流提供游标补读或完整快照，不把 websocket 当消息唯一权威。冲突编辑通过版本检查与保留草稿解决，不以最后一次网络到达静默覆盖。

SP-08 先保存可靠通知中心记录，再投递 APNs/FCM/邮件。推送 payload 用最少内容与受控深链，不携带全文或审批授权令牌；打开后重新认证并读现行决定。FCM 返回 message ID 表示接受投递，不能等同于设备送达或用户已读；过期、折叠与离线都会影响实际交付。[FCM 消息生命周期](https://firebase.google.com/docs/cloud-messaging/customize-messages/setting-message-lifespan)。苹果服务端接入需按实际平台验证，未据只含目录的页面推导可靠性保证。

SP-09 的成果发布区与主应用分离 origin、cookie、网络和执行身份。静态成果先支持不可变构建 + 版本指针；有交互数据的成果另有命名空间与 schema/version，更新 UI 不重建用户已填内容。生成页面不能读取主应用 cookie、token vault、任意文件或云元数据；若需要调用外部动作，通过受控产品 API并复查分享者/操作者权力。页面内的按钮不能取得作者的全部代理资格。

发布动作区分 preview、private published、shared、withdrawn、expired（本报告描述态，非框架新增枚举）。构建完成不等于部署成功；只有可读健康检查和权限检查通过、版本指针提交后才交付“可使用链接”。撤下停止新的访问与动作，保留/删除历史和交互数据按产品政策；已下载内容不可追回。任意动态应用托管的支持语言、计算时长、外部访问与保留价格都是首发支持目录事项，不能由“做一个页面”扩张为无限通用 PaaS。

## 8. 商业资格、计量、预算与来源

用户选择的模型来源、执行算力、存储/托管服务分别计量。服务资格（能否使用产品）与预算（本次可消费多少）是两套判断；支付完成也不自动增大某件事的自主工作范围。用户有权暂停、取消续费和停止具体持续消耗；这些动作的生效时点与剩余保存责任需展示。

候选预算过程：按事情/租户/来源检查可用余额 → 原子预留该次上界或明确的估算额 → 允许模型/执行动作 → 写实际用量与供应商计量回执 → 结算差额并释放剩余。并发调用争用同一预算时，共享权威 reservation/余额行保护额度；不能先读余额再各自消费。调用失败但费用未知时保留未结算项，不立即全额释放后再次超支。

此预留检查经**IF-05/IF-02装配在每次可替换模型发出实现之前**，不能只在任务进入cell前检查一次。预算未放行时产品/调度保持工作等待，不创建新的计费调用；已有runtime不能被借凭据取值点伪装为等待：若凭据取不到，`model-request-runtime/v2`仍写`released{cause: credential_unavailable}`终态，由既有失败处理和用户可见接续处理后续工作。已发调用继续收结果并结算，会话仍存在。装配接缝由HWP-01/03和SWP-10明确并验证前，不宣称硬预算已实现。凭据仅可信请求实现短期取用，任意工具拿不到；内存销毁/断开vault/回收引用不等于追回泄漏副本或已发请求。

用户自有据点的BYOK如按既有框架方式保有副本，平台只掌握引用与可得用量，不能远程保证副本失效或代用户轮换。旧owner失联且无法可信围栏时，可能继续产生**未知花费窗口**；向用户如实说明，禁止在新owner迁移接续同一工作形成双重支出。须取得stop/凭据实际失效等可信证据，或由用户在供应商侧处理并核对后，才能决定接续；不能将“提醒了用户”当作围栏成功。独立的新用户意图另行受理，但不自动继承未知工作。

**平台费用滥用控制。** SP-01对批量注册/重复领取平台资格保留审计；SP-10/11监测异常费用增长、来源key异常使用及自主循环消耗，支持按主体/来源和必要时平台范围暂停新增收费调用的可恢复熔断。阈值、处置与解封政策待定，保留原因和回执，由有权运营者或明确策略恢复；已发调用仍结算，资料读取等无关功能不跟随熔断消失。这是账单安全与恢复边界，不是通用吞吐平台。

硬上限能做到什么取决于供应商：若单次请求可限制输出、时长和并发，可给出本产品新增准入上限；供应商迟报、价格变化或实际费用超过估值时，不能假称用户账单绝不会超出。预留安全余量、预算软/硬级别、超额由谁承担均待产品裁决。先停止新的可计费调用，已在途部分如实结算。模型提供商限流、预算不足与平台故障有不同错误码和用户解释。

计量事件以真实 invocation/attempt/provider receipt 去重；重放事件不重复扣款。支付 webhook 验签后先持久 inbox，异步更新商业状态；重复、乱序和主动对账是正常路径。Stripe 文档明确可能重复交付且不保证事件生成顺序，候选支付商即使不是 Stripe 也要逐家验证相同边界。[Stripe Webhooks](https://docs.stripe.com/webhooks)。

**来源限制是一个显式 gap。** 框架要求模型请求经 OpenRouter。可选路径是用户提供 OpenRouter 凭据，或平台通过 OpenRouter 已支持且可验证的 BYOK 能力接入外部提供商凭据；这不是任意 OpenAI-compatible 地址直连。OpenRouter 官方 BYOK 描述的是其支持的提供商密钥集成，是否允许 fallback 也需按用户选择和实际配置核验。[OpenRouter BYOK](https://openrouter.ai/docs/guides/overview/auth/byok)。首发支持目录要明确具体服务与能力，禁止失败后静默换用平台余额。若用户坚持任意直连端点，则与框架全路由约束冲突，主线须带回裁决而不是外围悄悄绕过。

OpenRouter文档当前明确默认可能fallback到共享容量并消费OpenRouter credits，因此接入时要检查实际provider/key级设置，使用用户允许的来源集合，不仅在产品UI勾选“禁止切换”。同一平台workspace汇集多个用户BYOK时，是否能逐调用确定选中且只使用指定租户的密钥必须验证；未经验证不得上线这种共享保管模式。可从用户自己的OpenRouter凭据隔离路径起步，平台服务走平台凭据，连接引用、预算和回执均绑定此次来源。平台路由设置变化后重新验证，不能仅在首次连接时检查。支持验证还必须包含OpenRouter及实际provider的数据留存/训练用途、适用地域和可用策略控制，并对照用户隐私/地点约束；未核实或不能满足就排除该路由，不以模型名称相同替代供应商数据策略。这里是待验证的路由准入要求，不宣称任何provider默认零留存或禁止训练。

## 9. 隐私、导出、删除与有序退出

维护资料清单时同时覆盖原件、历史版本、派生摘要、记忆来源、检索索引、缓存、交互成果数据、分享 grant、通知、遥测、备份和第三方持有的副本。能导出原件不等于导出全部助理状态；导出包以 manifest 列包含项、版本、无法导出项和原因，结构化数据与附件有稳定关联。

导出前重验主体与范围，持久记录导出 job；以明确快照边界构建清单，分批生成时保留版本/时间说明；下载短期授权、可撤销且不公开缓存。删除前具体说明对象、范围和不可恢复后果。删除提交先禁止新读取/派生和分享，再逐 owner 清理并登记完成事实；失败项重试，不能因为一个子项成功显示全部已删。

框架持久记录与不可擦除历史的规则仍由其owner维护，SaaS不得直接改写追加日志或删除来源记录来模拟“已遗忘”。生命周期适配使用框架允许的删除/归档/整个主体退役接口；若某类记录没有当前支持的清理面，就将其列为尚未覆盖项及待明确保留范围，不能对用户承诺完整删除后再保留秘密副本。长期记忆的纠正与删除属于产品PWP-01建设，也不自动等于擦除原始会话。

备份按保留周期淘汰及密钥策略处理；恢复必须先应用删除/关闭墓碑，防止已删除资料复活。第三方已持有的数据只能给出已请求删除/无法控制的事实，不宣称全世界同步抹除。计费、争议与安全审计可能有独立保留义务，具体地域法律与政策需另行核定；本文不代替法律判断也不自行指定保留年限。

账户关闭候选链：身份增强验证 → 展示正在进行、待核对、已分享和未结算责任 → 暂停新增工作/消耗 → 用户选择可用导出 → 撤回设备/连接/分享 → 按政策停止订阅 → 处理在途与费用 → 删除或保留有依据的数据 → 发完成与剩余限制报告。停续费不等于立即删除，退出客户端不等于账号关闭。相关条目在原需求中含“建议补充”，需产品接受后成为发布承诺。

## 11. 一万注册用户的模型并发与费用测算

本节按用户要求只做可复算模型；不把普通数据库压力视为主要工程问题，不规定大型压测、缓存分层或吞吐优化。所有使用率数值是算例而非预测、套餐或承诺。

| 参数 | 基准算例 | 含义 |
|---|---:|---|
| N | 10,000 | 用户指定注册数 |
| d | 20% | 每日活跃比例，假设；DAU = N × d = 2,000 |
| u | 8 | 每DAU每日交互轮次，假设 |
| k | 2 | 每轮平均模型调用数，含委派/整理，假设 |
| W | 5,000 | 全部用户合计持续关注使命数，独立于DAU，假设 |
| e | 2 | 每使命每日有效变化/检查数，假设 |
| q | 0.2 | 每变化需要模型的比例，假设；不得每次轮询都调用模型 |
| a | 2 | 每次需模型的后台活动平均调用数，假设 |
| L | 20秒 | 平均单次模型在途时间，假设，需实测 |
| p | 6 | 同一24小时平均到峰值因子，假设 |

每日模型调用 `R = N*d*u*k + W*e*q*a = 36,000`。平均在途约 `R*L/86,400 = 8.33`；使用该粗略峰值因子约 `50` 个在途请求。该式来自到达率乘平均在途时间的估算，峰值相关性、流式长尾与供应商限流会使实际数偏离；它不是并发保证。配置全平台/租户/来源的公平并发和预算上限，排队说明原因，不能通过无限并发耗尽余额。

保持 N=10,000 的敏感性：d 从20%变40%，其余不变，R=68,000、估算峰值约94.4；L从20秒变60秒，在基准使用率下估算峰值150；W从5,000变20,000，基准DAU下R=48,000、估算峰值66.7。优先校验真实模型等待、token长度、后台使命是否有有效变化；不另列注册人数三档。

在线连接不能与模型执行并发等同。可在上线观测中记录同时在线客户端数量和重连峰值，用普通托管入口/数据库完成初始部署；大多数已注册用户处于休眠，后台使命也不要求各自常驻一个忙循环。常规API、资料读写与通知以真实错误/延迟发现问题后再调整。

月模型费用候选公式：`30 * Σ(每日各模型输入token/1e6 * 输入单价 + 输出token/1e6 * 输出单价 + 已核实附加费用)`；不得把缓存命中、BYOK费用或供应商价格当作默认优惠。基础运行费用 `Σ VM小时×小时价 + DB实例/存储/备份 + 对象GB月/请求/出站 + 队列/密钥/日志 + IdP/推送/支付费 + 域名与支持运营`。执行算力费用另加 `Σ执行CPU秒/GiB秒/磁盘/出站×核实单价`。自带节点的用户自付成本与平台实际收费分别显示。

种子期基础配置原则：一个主地域、外围模块化应用少量实例、一个外围托管关系库、独立单实例SQLite治理中心、对象存储、保密设施、独立恢复控制点、各自备份与少量cell；模型等待不意味着VM持续满CPU。决定cell数量先测框架常驻内存、活跃工作状态与恢复成本，禁止由本算例推导“一万用户需要一万VM”。本次未核查地区SKU、供应商价格或SLA，不给确定月账单；成本表待填单价、税费、币种、最小计费与地域，并保留访问日期。

## 12. 实施顺序、阻塞与评审边界

工程包明细在[建设依赖与规模](delivery-plan.md)及data内机器材料，首期建议按三条可交付主链推进：A「注册→持久接受→模型调用→真实文件结果→换端恢复」；B「明确连接→有限外部动作→回调→撤权→故障核对」；C「远端节点→受限材料→真实结果→离线恢复」。数据生命周期、费用、遥测和备份跟随各链交付，不能留到所谓上线收尾阶段。

| 待决定项 | 不影响现在做什么 | 阻止什么 |
|---|---|---|
| 国际主地域与数据驻留 | 云中立接口、数据清单、恢复动作链 | 供应商/地域定案、跨境路由、真实价格与部署 |
| 首发OS与渠道目录 | 通用登录/同步、一个明确试验渠道的原型规格 | 宣称所有桌面/手机/邮箱可用 |
| 模型来源支持目录 | OpenRouter路径、来源/预算分离 | 任意兼容端点直连与静默fallback |
| 自主/离线执行/撤权窗口 | 把现行权限和在途事实建模清楚 | 默认无限后台权限或零延迟断网撤权承诺 |
| 保留、导出、删除、收费与SLO政策 | 生命周期job、manifest、计量/恢复证据 | 对外签订数值承诺与商业发布 |
| 框架目标提供者的实际完成 | 围绕承诺接缝实现外围 | 将未交付能力报成可运行，或复制框架内部语义 |

本稿不接受上述政策，不修改框架规格，不指定新包布局，不声称测试已通过。验收材料应包含具体失败注入、租户越权反例、撤权与迁移竞态、账单重复事件、数据恢复演练和完整用户旅程结果。正式施工前由主线对照框架基线、需求映射及独立评审意见，明确哪些是已承诺依赖、外围建设、适配缺口或用户待裁决。
