## 2. 最小结构与一次调用生命周期

接续同一 `apps/cli` 应用节点，候选可执行名以 `omne` 示意，未冻结。首次建包必须先完成相关客户端契约及节点可实施范围，不因这里列出命令就宣称可开工实现全部产品。

```text
应用入口（help / version / config / health / 治理命令 / TUI）
   ├─ CLI 参数或脚本输入 ─┐
   └─ TUI 输入与呈现 ────┴─ 同一具名用例面
                              ├─ 本地状态与秘密引用（CAS）
                              └─ 按精确协议版本选择的客户端
                                   ├─ D-029 信任核实
                                   ├─ HT1 请求/答复运输
                                   └─ 当前操作专属 Schema 与结果转换
```

逻辑模块先控制在应用入口、共享用例/协议适配、本地状态适配、渲染适配四处职责；不先建十个包装包。可复用客户端协议与运输有独立消费者时，沿既有 `packages/frontend`/租户客户端边界落包；具体成员名称须节点接受，不把旧候选 facade+socket 全套照搬到本期。公开共享代码依赖契约，不 import 中心提供者私有 src。

**单次命令**：解析本地参数→短锁读取配置修订/所选登录引用→释放锁→验证信任、读公开 health 并检查中心绑定→确认所需生产协议可用→必要时安全采集秘密→组装一个具名请求→握手核验后发送→完整读取/分类→按原修订 CAS 更新本地状态→输出一个最终结果→关闭连接、归还终端、退出。网络等待不持本地文件锁。

**TUI** 是一个前台客户端进程，共用这些用例；可连续发起多次单次调用，但每个 HTTP 连接仍只承载一次请求。每次操作捕获自己的配置修订、账号、登录引用及预期租户；不让后续界面切换改写已在途请求。调用尚未结束时防止同一按钮重复提交；其他并发命令仍由后端与本地 CAS 处理，不能只靠禁用按钮。

**没有空据点**：不拉起 Agent、daemon、模型、会话数据库、工具执行或本机 socket；没有登录就不能显示治理身份，但帮助/版本/配置/公开 health 可用。TUI 退出不自动退出账号，Ctrl-C 不意味着取消后端已开始的治理。下一期据点可以消费同一中心客户端，届时再接本机边协议，不把当前 local config 当会话据点。

## 4. 请求、结果、退出码与结果未知

### 4.1 输入与输出候选

人读 CLI 与 TUI 调同一 typed 用例；脚本入口候选 `omne json <use-case>`，每次读一个完整 JSON 输入/或明确参数，stdout 只写**一个最终 JSON 对象加 LF**，stderr 放不含秘密的诊断。它是旧提案逐行 JSON 的单次治理子集，不把任务进度伪装为领域事件；未来流式 Agent 面另立契约。帮助/版本属于本地明确结果，脚本有结构化等价形式。命令名、JSON 外壳、退出码均属新客户端契约，尚未冻结。

候选最终结果至少区分 `success / rejected / unavailable / unknown / local-conflict`，包含本地请求关联号、具名用例、中心标识及可信程度、请求捕获的非秘密身份、远端结果和本地保存结果。关联号只是本次调用标识，不是后端幂等键；不能擅自加到旧信封。未通过认证时账号/租户只可标“未核实”，不把用户输入当中心认人结果。

远端登录成功载荷包含 loginState 秘密，**运输层可接收，呈现层不得透传**；共享用例先写入受保护本地状态，再输出句柄/保存结果等非秘密信息。日志、调试、异常对象、HTTP body trace 均经过同一秘密约束。若本地保存没有取得持久确认，分别表达远端结果与本地确定未替换／替换未确认／已确认保存的实际知识；不能说登录在中心失败，也不能把本地报错等同于没有安装新记录。

显示快照若保留，只是 `centerId + account + tenant + fetchedAt + source/result` 的有限副本，标明上次读取/当前不可达；换中心/账号时不串读，不作为权限或默认请求身份。当前调用没有快照时明确不可得，不合成空清单。本期不为满足副本显示创建空据点；落盘哪些快照、上限与清理由客户端契约定，与登录秘密文件同等级保护。

### 4.2 已接受运输判定必须原样守

- TLS≥1.3；仅在握手并核实对端之后发送应用数据，不发 0-RTT；POST + 明确 Content-Length，不用 chunked，不等 100 Continue；每连接只发一个请求，不开 HTTP/2 或连接池复用去绕约束。
- 不使用 Authorization/Bearer 头、不在 URL/query/cookie 放秘密；完整信封在 body。时间不由客户端提供为准入依据。
- HT1 S-17 先按 HTTP 成帧读满，再以体**逐字节**识别 `"version-mismatch"`；这一步先于普通状态码拒绝。其余按 JSON 与**本次请求对应**的 Result/Failure/health 校验；不是接受“27种 result 随便一个”。200 不代表业务成功。
- 断连、超时、TLS异常、体不完整、不属于本次操作的形状 → 问不到并记录对端异常，不猜失败/空/无效。接收限额与总期限需客户端规格给出；超限也是问不到，不截断后继续用部分 JSON。
- 收到 3xx 不跟随，不把登录出示物重发到重定向地址；透明重试、代理认证和通用 HTTP 库的自动行为必须受控。库是否能保留上述字节/解析语义需隔离探针；不因 fetch 方便就假定兼容。
- accepted 成功/失败 Schema 可作为 codec 输入；不跨包引用后端私有 parser。如果抽出纯协议模块，权威仍是冻结 Schema，派生类型不能成为第二份手写路由真相。

### 4.3 结果未知是独立维度

本地能证明未发送任何业务字节（配置/信任/输入失败）时，`remoteEffect=not-attempted`；一旦有业务字节交给网络且不能取得有效最终结果，写操作记 `remoteEffect=unknown`。完整 `unavailable` 若该操作契约不能证明无业务效果，仍不得推断未提交。服务端答成功而本地保存失败则 `remoteEffect=confirmed-success`、`localEffect=not-installed/unconfirmed/conflict`。普通读未取得结果是 unavailable，不编一份空结果。

默认**不自动重发任何治理写**。创建组织如显式给出 creationKey，只能沿该契约相同 key 的语义查证/重试。本期最小候选要求脚本调用者显式给出并保有 key；交互用例若自动生成 key，必须先持久保存与中心、账号及操作关联，未取得保存确认前不发送创建请求。跨调用未知结果不自动生成新 key；登录会多出一个登录状态，邀请会多发，改密会使旧登录失效，均不能借网络重试自动再办一次。超时后取消本地等待不是取消远端。TUI 未知结果保持明确可见，后续查证是新的读操作，不自动补动作。

退出/撤销例子：远端确认撤销成功才把该次所选引用清掉；超时可以将本地引用标不可自动使用/待核实，**不能写“已退出所有设备”或“中心已撤销”**。登录结果未知且没有秘密可保存时，只能提示重新登录并查看多余登录清单；客户端不能凭用户名撤销猜测中的登录。

候选退出码（**新客户端规格待接受**，backend failure 原值仍保留）：

| 码 | 含义 | 不得误读 |
|---|---|---|
| 0 | 本次用例全部必要步骤确认成功 | 远端成功但本地保存失败不返回0 |
| 2 | 本地输入/配置不合要求，业务未发出 | 不是中心 invalid-input 的统一替身 |
| 3 | 证书信任失败/已绑定中心不同，业务未发出 | 不清除原中心登录、不自动接受新中心 |
| 4 | 已收到可识别的版本不匹配或本地无该生产适配器 | 不降回旧版生产 |
| 5 | 中心明确不认所用登录 | 不猜是到期、撤销还是伪造，反馈依契约 |
| 6 | 中心明确业务拒绝/输入拒绝 | 保留原具名失败，不翻成权限不足或空清单 |
| 7 | 访问不可得、没有业务结果；没有未知写效果 | 可能是读/health失败，不等于无效登录 |
| 8 | 写操作结果未知，需查证 | 不自动重发 |
| 9 | 远端结果已知，但本地保存/并发CAS未完成 | 输出必须区分远端成功与本地状态变更未获确认或发生冲突 |
| 130 | 用户中止本次前台等待 | 最终结构化结果可写时标明发送阶段与 unknown；脚本不能把130当作远端回滚证明 |

未预料缺陷以独立软件失败类别处理，不归入成功或上述领域拒绝；具体退出码在客户端契约收口，不用吞异常补一个“稍后再试”。

## 5. 信任、中心绑定与秘密发送顺序

### 5.1 CA 与 SPKI 的不同责任

CA 默认路径核链与配置 URL 主机名；私有 CA 是显式配置。不能以“内网”跳过 hostname，不能把服务端自报 centerId 当证书身份。SPKI 替代路径在**不带密码或登录出示物**的连接上计算 SHA-256，首次向人展示并等待其明确确认，再记住该指纹；脚本须预先配置经核实的指纹，不在非交互模式默认接受。后续指纹变更一律拒绝并提示显式重新配置，不沿用旧登录试一下。

D-029 的显式 insecure 开关只获准用于开发实验。生产客户端配置拒绝 insecure；若隔离符合性夹具需要跳过校验，单独的开发装配每次打印警告且不可默认为生产配置。产品新目标没有让“实验用开关”自动成为生产承诺。

信任配置中不允许 URL userinfo；候选只支持直接 HTTPS 指定端点，不把环境代理/重定向暗中接入秘密路径。路径只是投递地址，不作为权限；连接地址和 centerId 分开保存。

### 5.2 不发送秘密前的绑定检查

1. 每次 invocation 捕获已选 profile 的地址、信任模式、已读取并核验的材料字节快照及其摘要、revision；尚未绑定则只能配置/公开探测。
2. 不带任何业务秘密完成 D-029 的证书信任，再按 HT1 单次连接读取公开 health。收到的 centerId 与已绑定值不同就停止，不从旧 profile 取密码/登录出示物、不发业务请求。首次绑定在已建立证书信任后显式确认中心和地址，再 CAS 保存。
3. 业务另开连接（HT1 一连接一请求）；该连接仍完整执行同一信任策略，并使用同一份已捕获 CA 字节或 pin；不得按同一路径再次加载可能已替换的内容。每次请求采用捕获的配置，不在重连时偷偷切到并发修改后的地址、CA 或指纹。信任/中心绑定变更会使后续新调用采用新 revision，当前在途调用照其捕获值结算并在保存时检测冲突。
4. 在核验完成后才向网络发送密码或登录出示物。TUI 可以提前有隐藏输入，但传输不可提前写 body。日志不记录 secret，TLS调试输出也不放开 body。
5. 同一中心换地址：必须在新地址经信任核实且 health centerId 相同后显式更新绑定；另一个中心采用独立 profile/重新登录，不“收养”旧登录或旧账号。CA路径的合法证书更新不自动变成 SPKI pin，SPKI路径的变更按其拒绝规则处理。

**可证明范围必须说明**：公开 health 与后续业务是两次连接，EC1/HT1 没有在一次受保护请求中证明“此刻数据对应的 centerId 与前次 health 相同”的字段/承诺。相同证书私钥下后台恰在两次连接间换成另一个中心，这个竞态不是多做一次 health 就能完全消除。现有 D-029 保障的是证书对端认证；客户端可以先发现已存在的中心变更并阻止发秘密，但不能宣称跨两请求原子绑定。需要 entry/部署 owner 明确端点在一次调用期间的中心身份稳定前提，或未来协议提供足够的绑定。**不能擅自往 EC1 信封加 expectedCenter，也不能谎称那样可收回已发出的秘密**。该缺口不阻止实现无秘密的 health/配置与 accepted TLS codec；阻止相应更强保证的声明。

## 6. 安全输入、本地文件与并发 CAS

### 6.1 秘密入口

- 人读从可恢复的 TTY 无回显输入读取；不要让密码成为命令行位置参数/flag 值，不在历史、报错、复制提示中显示。取消、异常、终端 resize/退出都恢复回显和终端模式。登录标识不是秘密，但也不拼进意外泄露原始输入的诊断。
- 脚本使用明确的受保护文件描述符或秘密输入文件；默认 JSON stdin 不承担同时可被转录的明文秘密。参数只包含 fd 数字/文件路径，不包含值；TUI 与脚本都不接受“缺了用空字符串/环境里随便找”的猜测。秘密文件只读一次，不删除用户提供的源文件。
- 账号密码只用于这次请求，不持久保存；本地保存的是登录出示物和对应非秘密句柄。读取到的新密码应尽快释放引用，不宣称 JS 字符串已可靠擦除内存；无 core dump/内存攻击保证不冒充已有产品承诺。
- 无 TTY 时人读需要隐式秘密输入则明确失败，指引脚本的显式安全入口；不退成明文 echo。

### 6.2 最小本地状态

候选使用一个受保护状态目录，目录权限 0700，状态/秘密文件 0600，归当前 OS 用户；Linux/macOS 文件行为需实际验证。简单起点是**每个 profile 一个完整小状态记录**，包含 revision、地址/信任引用、绑定 centerId、选中的登录句柄与秘密、非秘密显示身份及其来源。密码不写。每次替换整个记录，避免“令牌已换而账号/centerId没换”的跨文件半成功。若改用系统密钥环，需另证明密钥环项与元数据的共同更新/恢复规则，不能自动假定其更安全即免CAS。

状态只能由客户端自己的受控目录定位；拒绝符号链接、异常所有者、目录可被其他用户写、宽权限秘密文件。通过已打开的文件描述符核验文件类型与权限，不能只 `stat(path)` 后再普通 open 留出替换窗口。创建使用私有权限、独占临时名，写完同步文件→同目录替换→同步目录；新文件权限不得从被替换的宽权限对象继承。磁盘满/同步失败要保留可辨结果，不说保存成功。密钥材料路径的内容不自动复制进可展示的配置导出。

这些是**客户端状态契约候选**，不是既有 EC1 能保证的事实。选用的跨平台锁/安全文件 API 必须先做最小探针；不在未验证的 shell 拼接中处理秘密。

### 6.3 多进程并发的比较与替换

使用 OS 管理、进程退出可释放的跨进程排他锁或经过验证的等效机制；锁文件/目录自身只表示定位，不用 PID 文件+超时推断可安全抢占。锁有有界等待，失败明确 local-busy；拿不到不绕开。锁身份必须独立于被替换的状态记录，不能锁即将 rename 的文件后误认为新 inode 仍受同一把锁保护；替换前后进程竞争必须取证。具体适配库尚未选，不把候选 API 当现成能力。

1. 在短锁中读完整状态，核权限，得到 `revision=r` 与所选登录/中心绑定；释放锁。
2. 进行网络用例；网络期间不持锁，允许另一个进程读配置/执行其他用例。
3. 有结果要保存时重新短锁，**同时比较 revision、中心绑定与原登录引用**；仍匹配才写 revision=r+1 的新完整记录。版本号只是本地序列，与登录寿命或后端修订无关。
4. 不匹配时不覆盖：返回远端结果+本地冲突。再读到的状态可以展示，但不能把旧网络请求重解释成用新身份发出的。

必须覆盖的并发：

| 交错 | 正确本地收场 |
|---|---|
| 两次登录同时发出，第二次先落本地 | 后到的旧 revision 结果不覆盖新选中登录。远端可能多出一次有效登录；只输出其非秘密句柄与“未选为本机登录”，后续正常清单可查，不静默自动撤销或输出秘密 |
| 退出旧登录期间，另一进程登录新账号/新登录 | 远端退出旧句柄成功，不删新记录；报告远端成功、本地已改变 |
| 改密期间，另一进程正在登录 | 客户端CAS只保护本地选择；全部旧登录是否失效归后端新版，不能声称CAS已解决改密竞争 |
| 租户切换成功回执后，本地配置被另进程修改 | 不写回旧profile；中心实际当前租户只能重新读取，不能让本地显示指针成为权限源 |
| 中心地址/信任配置变化与旧请求返回交错 | 旧结果不得写进新中心 profile；原结果按旧中心身份显示，秘密不挪用 |
| 远端登录成功后本地写盘失败 | 远端登录已创建；区分确定尚未替换与替换/耐久未确认，持锁重读最新记录后报告当前选择，不自动重登、撤销或删除别人的新引用 |
| 本地退出标记/删除与在途旧请求交错 | 本地状态变化不能撤回已发送请求；旧响应不复活被清掉的引用 |

CAS 比较必须在持锁的**同一次**读取与替换中，不能先读revision、释放锁、再rename。原子rename只防半文件，不防丢更新。客户端锁不跨中心网络，不代替后端预期租户共同提交。

### 6.4 本地替换没有确认时的收场

本地适配器结果至少区分 `not-installed`（能证明未替换）、`installed`（替换及所需同步均已确认）、`unconfirmed`（替换或耐久无法确认）、`conflict`（CAS 不匹配，未替换）。rename 成功后目录同步失败、提交返回前进程中断均不能归入 not-installed。所有 login/logout、配置、信任和身份缓存变更共用这个结果集合。

每次拟替换记录带不可重复的本地 operationId、新 revision 和预期旧绑定。发生 unconfirmed 后只做一次持锁重读：若最新记录包含本 operationId，可以报告“当前可见为本次记录”，但没有补足同步证据前不能追认原操作已耐久；若已经是后来的记录，报告当前选择和原结果未确认，不推断原写从未发生。读也失败则保持本地未知。禁止凭旧 revision 无条件删文件或撤销新登录作补偿。进程崩溃后新 invocation 首先核验并读取持久记录，不能依赖已消失的内存结论。

### 6.5 本地存储实现的三个真实候选

- **A：完整 JSON 记录 + 稳定 OS 锁 + 同目录耐久替换**。文件易读、可移植，但 Node 的跨平台 OS 锁需要验证过的适配；需自行承担文件发布、锁身份、半完成与 CAS。
- **B：单个受保护 SQLite 状态库，复用 Node24 内置 SQLite 的事务与进程锁**。元数据、登录秘密、revision、operationId 在一个事务中 CAS；不造应用 daemon。减少手写替换/锁协议，但新添本地数据库格式、WAL/SHM权限和迁移责任；SQLite 错误仍可能结果未知，不能省掉 §6.4。安全目录与同用户恶意篡改边界须明确，不能假定 SQLite open 自带路径防替换保证。
- **C：系统密钥环 + 元数据文件**。可使用 OS 秘密服务，但 Linux headless 可用性和 macOS 授权提示不同；两处写入、删密钥与元数据 CAS 的共同恢复仍需设计。当前没有证据表明其总负担更小。

三者尚未接受。B 可用隔离多进程探针先验证竞争、崩溃释放、回滚、WAL权限与提交错误的真实边界；该证据不等于客户端完整契约已接受。

## 7. TUI：共享操作与最小 pi-tui 探针

TUI 只给具名用例提供表单/列表/结果，不重新实现后端规则。始终显示：真实绑定中心、当前账号、当前租户/角色及是否旧副本。提交前冻结该次输入，结果返回时标注发起身份，不借屏幕已切换覆盖语境。权限变化由服务器结果反馈；隐藏按钮是呈现，不是授权。拒绝路由未有契约时不可把本地“从列表藏起来”当拒绝成功。

本期界面只需：连接/登录准备；组织与身份选择；成员表；收/发邀请和隶属请求；登录列表/改密；明确的成功/拒绝/未知结果区。所有表单与机读输入共享一个用例定义。超时/网络失败不触发自动补交；本地输入草稿可保留但不得持久保存密码。人读确认只说明后果，不增加第二套超管授权。

pi-tui 保留原提案 A：钉版直接采用、自有薄适配、不打渲染核心 patch；**没有精确版本和通过证据前不得写已采用/已验证**。E1/E3 可在隔离实验区先做，不需要真实账号、治理写路由或恢复设施：

| 探针 | 最小夹具/输入 | 必须记录与停止条件 |
|---|---|---|
| E1a 输入/焦点 | Node24+选定精确pi-tui版本；组织/邀请表单的一条普通编辑器和一条无回显秘密输入适配；切焦点、取消、resize | 在终端复用器（扩展按键开启）、VS Code终端、一个现代终端三类宿主；中文拼音逐字200字，粘贴5000字中英混合，硬件光标开/关。记录宿主/OS/版本、候选窗位置、冻结、粘贴到首帧时间、输出字节 |
| E1b 秘密与收尾 | 虚构秘密含控制字符/多行粘贴，正常提交、Ctrl-C、异常、EOF；不连中心 | 屏幕/scrollback/stdout/stderr不得出现原值；退出恢复echo/光标/键盘模式；不能把控制字符粘贴变为自动执行或输出转义注入。禁止使用真实密码取证 |
| E1c 短列表治理反馈 | 假数据成员/邀约表，操作在途后变更显示身份，再交成功/拒绝/unknown | 响应对应原请求身份，未知不被新列表刷新掩盖；仅测呈现，不冒充后端权限测试 |
| E3 离线可得 | 精确版本+锁文件+完整所需包/构建资源落本地，在清空项目产物并禁止网络的环境从零构建运行E1夹具 | 不借全局已装包、温缓存、隐式下载补依赖；记资源清单/摘要/平台。失败先指出缺项，不说钉版即安全 |

原 E1 改票阈值保留：候选窗错位或冻结>2s且只能改渲染核心才转绿，直接采用路线不成立，回候选比较；不因本期表单简单取消中文输入义务。E3 失败按原提案重评可获得性/替代路线；不能私打 patch 后称原样采用。Linux/macOS 都需平台证据，单平台真实终端结果不能冒充双平台完成。自动PTY断言不能独自证明真实IME候选窗表现，无法观测的项目明确未核。

不做本期无关的20,000条Agent日志/E2/12小时流式/E4/单文件分发E5，除非本期治理列表实测暴露同类问题；本轮不重开整套渲染选型。

### §10 定向复查补充 · 2026-09-25

本补充优先于§2“每次操作捕获登录引用”的歧义：一次CLI命令是一次使用；一次TUI打开至退出是一整次使用，由**组合**持有固定中心/账号/登录捕获。每条请求可取得新的远端当前租户读数，但不从其他进程刚写入的本地记录静默切换登录。发现本地所选登录或绑定被别的进程改变，停新准入、按原身份结算已发请求，要求明确结束这次使用后重新进入；旧响应不改挂到新身份下。失效后的显式重新登录也必须先结束旧使用，不自动续期或重发旧写。

副本范围由组合承担，覆盖**本期所有适用的治理读面**，不是任选几个屏幕；原§4.1的“若保留”不构成删减PF016 §6.9的许可。只需保存实际成功取得的读数；网络不可达且存在匹配中心/账号/查询的适用副本时可呈现并明确时点/副本来源，没有副本明确不可得。写入/切换必须现读，拒绝/失权不能用副本覆盖；登录秘密不进入副本。存储不足或CAS失败必须独立报告，不能让应用宣称副本已保存。记录中“少量”只描述首批规模，不是截掉读面或任意丢弃已存在适用副本的政策。

落选方最强理由：A也能通过内部适配及完整用例收尾管理存储换代，不必必然重跑；B同样需要关闭旧组合准入。C也可做一个共享应用协调器保证多呈现一致。推荐B的正面理由仅为记录/CAS/恢复的可独立核验与替换责任；C若仍在apps内暗含这些跨边界规则则违反应用装配边界，不能把它描述为无协调器的必然坏方案。这些代价比较不取消A/C可行性。

## 14. 2026-09-25治理TUI终端责任重新分解（候选）

依据PF016 rev7本期范围、CG2/D049，治理对象与固定登录/Preview/秘密不呈现/收件箱规则不变；完整Agent长编辑器下一期。领域读数先封存，再比较本段机制；没有接受新终端提供者。旧TTY秘密候选的2004模式查询与尾帧信任问题不通过局部解析补丁消除。

A：既有pi-tui路线，只直接采用有独立价值的渲染/非秘密编辑组件，应用适配器独占终端；秘密仍经受保护文件。需另说明并验证受支持模拟器/输入来源、模式保存恢复与终端生命周期。优势是已有编辑/渲染经验与未来Agent形态衔接；代价是本次治理仍承担raw、2004及模拟器模式长尾。不能声称“秘密走文件”自动解决所有模式责任。

B：治理阶段采用Node内置canonical行输入的交互菜单，界面不变更raw/2004/光标可见性/备用屏模式，秘密只读文件；完整表单按步骤输入非秘密字段，组织/账号/来源每屏可辨，同一CG2 use贯穿。操作系统承担已有行编辑，应用只处理完成的非秘密行。优势是无需新秘密终端协议或第三方渲染器、资源边界较小；代价是输入体验为逐行菜单，尚须证明当前身份持续在场、长列表分页、窗口缩放时的输入/呈现与正常退出；不能拿普通问答脚本冒充PF016所有呈现承诺。未来Agent编辑器仍独立需要A或其他已评估框架。

C：完整采用终端拥有者与预先明确的支持配置（独立启动/结束的终端会话），TUI进程不向另一交互消费者归还中途输入；在该边界内接成熟编辑器。可使模式与残余输入生命周期由外层统一结束，但引入启动器/平台依赖与运维使用变化；不能私自要求员工另装桌面或把它转为WebUI。需可执行的Linux/macOS终端宿主证据，当前不足。

三者都不能把2004 end marker当加密边界，也不承诺从任意恶意终端/输入注入者恢复可信控制状态。要判断本期哪条够用，先核“输入尾段中含秘密”究竟是哪种提供者才承担的性质，以及不改变终端模式能否直接复用原会话状态；产品不变，支持前提必须可说明、可失败，不靠隐藏假设。B只是较小范围候选，不因更快就采用；若身份常驻/resize无法兑现，须回到A/C比较，不偷偷降级产品。

### A的输入历史容量选择（候选，2026-09-25）

实源码显示pi-tui0.86.1的UndoStack无条数上界，Input公共setValue不清历史；仅限制当前字段文本不能限制长期编辑保留的快照。KillRing同样无上界；本期无需kill/yank，通过受支持按键白名单不进入该路径，清空字段可新建Input实例。

| 路径 | 得失 |
|---|---|
| 保持发行物原样，限制同一个Input的编辑次数，超出后结束该输入 | 没有源码差异，但用户有效编辑也会被中止，字段长度很小仍可能触发；直接采用不等于没有产品代价 |
| pnpm对精确0.86.1施加项目维护的UndoStack单点补丁，最多256个快照 | 公共Input接口与成熟Unicode/编辑/水平布局保持；配合字段UTF-8上界64KiB、只保留当前一个Input，历史有可计量上界。代价是一个具名上游差异，锁与制品必须带补丁，不再称完全未经修改的直接采用 |
| 应用自建完整单行编辑状态，只用宽度工具 | 可以直接掌握历史/内存，但重写光标/字素/删除/单词行为，引入此前研究已经指出的编辑长尾 |

倾向第二条：补丁归apps/cli的第三方输入维护材料，通过pnpm patchedDependencies绑定精确版本与内容；不是renderer fork，不使用private字段窥探或运行时猴子补丁。独立review、补丁失败负控和真实制品仍在采用前；当前未修改产品依赖或第三方源码。Ctrl-U的整字段清空可重建唯一Input，Undo只承诺保留最近256次快照；kill/yank与鼠标不作为本期表单支持键。普通按键仍严格增量UTF-8解码后给组件，输出沿D049安全投影在宽度布局前处理，stripTerminalSequences不替代安全投影。
