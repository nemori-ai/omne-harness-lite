# R2：两个实现接缝的闭合候选

## 前身与性质

基准是 D-062 接受的目标态映射，源码尚不存在。不是新能力或产品取舍。既有契约已规定：S-21 的附件长度是无上界非负整数，S-24 数值无损，S-26 拒绝次序固定，S-27 不修补；S-3/S-14 的标识按 identity-values S-31 接收，在消息／会话范围判唯一。对象与所有权仍沿既有内容块、附件引用、模型调用和会话日志；没有新对象。

本次已经看过机制与独立 spec-reviewer 的反例，**没有达成新的双盲领域读数**。这里只继承上述已接受性质，不以 Ajv 的限制反向删减它们。装配对象反查索引尚未建立，消费者清单为人工核对。

| 性质 | 可观察反例 | 保护者 |
|---|---|---|
| 形状接收与数值精确 | 合法附件长度 `9007199254740993` 经严格读入后不能因是 `LosslessNumber` 而被拒，也不能被改成另一个整数 | content-blocks 的读写与 judge |
| 固定失败次序、不修补 | 同时有可见半截调用与坏长度时不能提前报 malformed；成功不得交出为了校验而替换过数字的块 | content-blocks judge；消息级重复仍归 messages |
| 标识词法与生成分开 | `b0`、`call_` 加 32 字符是合法接收值；不能把随机生成器的 26 字符形式当接收条件 | 数据接收边界 |
| 同一生产者可重放，登记唯一 | 同一模型调用、发出轮次、块索引重放得到同一 CallId；不同三元组不能因未分隔拼接而必然相同；哈希碰撞仍由登记方检出 | pi 传输、模型运行时、会话日志 |

最后一行的确定性是既有 pi **提供者选择**，不是新加的全系统领域保证。前三行安全／不变量沿已冻结契约。本包不增进展性承诺；纯校验在有限输入与可用计算资源下返回，外层输入资源预算不在这里重新定义。

## 数值到原 Schema 的桥接

直接把 `LosslessNumber` 对象喂 Ajv 的 integer 类型判定会拒绝合法值；先转 Number 会丢精度。候选 N-A 保留一份原 Schema，编译时不修改；只在 `judgeContentBlock` 的末位 malformed 判定中，构造一次私有校验视图。

1. 原值仍是既有 JSON 值代数：null、布尔、字符串、有限 number、数组、对象，以及本模块实际铸出的 `LosslessNumber`。伪造形似对象不是数值。循环引用、undefined、bigint、函数等不属于该代数，作为 malformed 的依据；不抢先于 S-26 具名拒绝。
2. 视图保持所有成员、缺席与 null、数组次序和非数值叶子；只把真正的 `LosslessNumber` 叶子按精确十进制数值分类替换：非负整数 → 0，负整数 → -1，正的非整数 → 0.5，负的非整数 → -0.5。零含带负号的零归第一类。普通有限 number 不改。
3. 精确分类从已由引擎确认合法的数字原文提取符号、系数、小数位数、十进制指数；去掉系数末尾的零后比较指数与小数位数，判断是否整数。指数与位数比较不能经有损 Number 转换，不能展开 `1e1000000` 成一百万位数字；不把 `Number.isInteger(Number(raw))` 当判据。
4. Ajv 8.20.0 编译精确 `$defs/ContentBlock`，不是约束为空的 Schema 根。只把视图送入该校验器；具名语义谓词仍按原对象的 **JSON 语义类型** 判：genuine LosslessNumber 是数值，不是可查成员的对象，不能用裸 typeof object 代替此判别。例：其余合法的 text 块中 visibility 为 9007199254740993 或 1e400，应为 malformed，不能因数字的运行时外壳误报 visibility_missing。任何成功结果／冻结值、序列化和下游调用只取原无损值，视图既不导出也不返回，不写存储、不进入事件。
5. 此投影只适用于当前 `content-blocks/v2` Schema：唯一数值谓词为 `AttachmentRef.bytes` 的 integer 和 minimum 0；自由 `opaque`、`arguments` 无额外数值谓词。字符串／布尔常量、结构、required、组合、additional/unevaluatedProperties 不因这些替换改变真值。所有真数值仍投为数值，因而不会把一个 LosslessNumber 假当满足 object 形状的对象。
6. 包内副本继续逐字节对齐冻结 Schema；针对数值谓词集合有独立检查。新增数值 enum/const、上限、multipleOf、uniqueItems 或对数字值作相等比较的任何约束，都必须先重新审视此证明范围，不能沿用这份视图。测试明确枚举允许的数值相关约束，而不是只记当前文件 hash 为测试 oracle。

这是当前 CB Schema 的等价判定映射，不是通用 JSON Schema 数值引擎。`arrival-events`、`messages` 会在包含 CB 的更大 Schema 上校验，当前私有视图不导出，不能替它们解决嵌套大数；`model-profile`、`call-accounts`、工具作者 Schema 的 numeric 约束也不同，**不能复用此视图**。它们尚未实现的 judge 各自仍欠无损值到所选引擎的映射，交给相应节点在开包前闭合；CB 的 codec 可独立供其消费，不要求它们先建成。

## 铸号责任协调

候选 I-B 明确取代 D-060 M44／CB 节点中“所有铸号方都用同一随机生成器”的普遍范围，保持交换词法和唯一性职责不变：

- 普通新消息标识、工具侧新块和新增派生块继续使用 `identity-values.generateOpaqueIdentifier()`；不在 CB 新增生成器或 Cordis 服务。
- pi 一次流的块标识仍为 `b` 加规范十进制索引。从 0 开始并连续递增是 pi 现有提供者选择；AE S-7 只要求非负、严格递增，未要求起点或连续；这不是从会话日志位置生成 MessageId。
- pi CallId 继续采用 `call_` 加 SHA-256 的 base64url 前 32 字符。为消除原三元组拼接的歧义，哈希输入固定为 `UTF8(JSON.stringify([ModelCallId, dispatchKey, indexKey]))`；这里的 JSON.stringify 精确指 ECMAScript 的该内建算法，不带 replacer 或 space，三个元素均为字符串，不调用用户 toJSON。其 QuoteJSONString 对斜杠、非 ASCII、控制字符和孤立代理项的规定一并采用，不能换成另一个同样合法但转义不同的 JSON 写法；[官方算法](https://tc39.es/ecma262/multipage/structured-data.html#sec-json.stringify)于 2026-09-27 核对。数字串由下节的精确规范函数生成。
- 相同输入三元组确定性相同；不同三元组的输入编码单射，但截断哈希**不提供无条件唯一**。已接受契约要求登记方保证唯一，但 **当前具体判重键与恢复映射尚未闭合**，session-log 的不透明 dedupeKey 不自动保证载荷 CallId 唯一。这是模型运行时／写入方的实施门，本次不宣称提供了碰撞保护；重放既有事实与重新登记的区分同样需要在那里闭合。附件追加、派生块与原流组合后的消息级查重仍要执行，不因 `b` 前缀而省略。
- 上游调用 id 仍只作传输事实，不升格为会话身份；是否改写出站调用与结果 id 仍由 pi 的既有请求内映射负责。本包不声称两条文本探针验证了工具往返。

这次不替 pi 的 `target` 定新域值或解决运行时登记、会话恢复设计缺口。精确三元组序列化与冲突测试成为 pi 本地 T-13 的前置；完整运行时恢复仍待后续。

### pi 数字表示与保留的入口实施门

成功域按 AE v2 S-5/S-7：dispatch 是 ≥1 的整数，index 是 ≥0 的整数，均不增加上界。输入采用 CB 已有 `JsonNumber = number | LosslessNumber`；前者必须有限且整数，其十进制解释沿 CB 无损 codec 的 number 写出规则，后者取模块保留的原始 JSON 数字字面量，绝不经 Number 转换。内部连续索引可用 BigInt 计数，但公开值必须转回上述 JsonNumber；BigInt 不成为线格式。

规范函数把合法非负整数写为 `系数e指数`：系数无前导零且无末尾零，指数是无正号、无前导零的非负十进制整数；零固定为 `0e0`。例：1、1.0、1e0 均为 `1e0`；10 和 1e1 均为 `1e1`；9007199254740993 保留 `9007199254740993e0`；1e400 保留 `1e400`，不展开 400 个零。依据合法 JSON 数字系数、小数位数及指数作精确位数运算，数字指数比较不经 Number；非整数或负值不在输入域中，不能四舍五入、取绝对值或截断。

这闭合了哈希成功路径的表示与字节编码；**pi 的 planRequest 在非法 target 上怎样收口仍留作显式入口实施门**。本次不擅自在既有三种规划拒绝中加第四种、不抛假上游错误；在主线与模型运行时明确该调用边界前，不派完整 pi 入口实现。CB 独立形状／codec 包不消费此输入，因而不受该门阻断。同样，CallId 登记／恢复和 D-019 比较门仍未闭合。

## 四表与反向核对

| 对账 | 本候选承载／限制 |
|---|---|
| A 性质承载 | 数值保持在原对象与 codec；Schema 判定视图只保护当前有限约束集。接收词法不变，生成责任由生产者承担，组合唯一仍有独立接收检查。 |
| B 内核负面清单 | Cordis 不提供数字无损、Schema 语义或跨调用唯一性。CB 纯模块无 fiber、事件、提交、存储；pi 的在途连接/卸载仍归既有节点，不移入 CB。 |
| C 原性质复查 | S-21/S-24/S-26/S-27 不变；D-060 通用随机生成器范围需新决定明确收窄。原接受／冻结文件不覆盖。 |
| D 代价 | 一次 O(输入规模) 私有校验视图及少量十进制分类代码，替代整个通用验证器；不引入插件／服务／持久分配器。数值约束演进必须重新比较，不能伪装免费扩展。 |

dispose 时 CB 无资源或在途工作；pi 已发出的外部请求仍由原 owner 结算，本设计不使其可回滚。纯值 import 没有 inject 重启传播。视图不进入任何事件，不能跨租户泄露。跨进程必须使用严格无损 codec，不能传运行时 class；每跳落实仍是 CB-2，各消费者不得把模块单测算作端到端证据。
