# PR11 整合候选 · 2026-09-27

尚未接受。本支 `7b755ac6` 与上游 `d4eaf767` 在同一路径独立实现了 content-blocks；上游同时交付其真实 core 消费者与新版规格。当前问题是实现与接受身份的协调，不重新设计数据契约。主线已读两侧机制，没有新的双盲声明。

## 既有承诺与事实

上游 [core 规格修订决定](../../decisions/core-implementation-spec-reconciliation/decision.md)已接受 CB/Messages/MR/Loop/TD/AM/SA/AE 的 v3，Skill3 另有独立接受；原319冻结资源保持。主线对合并工作内容逐件核到354冻结资源与上游相同、319旧资源哈希不变。版本推荐不自动升级24个外部消费者；MRR2、TER2等仍按其精确采用。

上游 CB 默认3并保留 `schema/v2`，公开 `LosslessNumber`、`OpaqueJson`、表示恢复及 `schema-runtime`；后者已被 messages、arrival-events、asset-model、tool-definition 使用。其数值表示、公开类型与本支 CB2 不同，不能挑几个同名文件混用。上游也有 descriptor 检查、稀疏/非枚举/getter拒绝、共享对象逐位置遍历及深冻结拷贝；没有根据旧195项结果宣布上游缺陷。

本支[原接缝设计](design.md)的 N-A 私有数值视图是 CB2 提供者的技术选择；I-B 普通随机生成与 pi 确定性例外、精确三元组编码是另一项选择。上游没有处理后一项，仍同时保留“几处同生成器”与 pi 的确定性生成说明。I-B 有独立消费价值，不能因源码替换静默删除。

## 三个实现整合候选

| 候选 | 最强理由 | 代价与判断 |
| --- | --- | --- |
| A 保留本支 CB2，给上游消费者补新公开面并升级到3 | 已有独立QA与本支反例覆盖，原数值桥简单 | 须重新实施 OpaqueJson、精确Schema桥与多包接口，重复上游已完成的工作；不是单次冲突解决，须另行设计和验证 |
| B 整体采用上游 CB 与其消费者，保留本支事实和 I-B | 一份数值代数、一套公开面，与当前已接受3及真实消费者一致 | 原195项只保留旧输入身份；本支非JSON优先级测试不能直接套新入口，整合后必须按新公开面重验。主线推荐 |
| C 同时保留两套包，以两条调用路径维持各自输入 | 可分别保留两边局部结果，减少短期源码搬迁 | 增加两套数字品牌/Schema引擎及转换边界，当前没有独立领域责任；违反一份权威及不加未经要求兼容层的约定 |

## B 的精确边界

1. `packages/core/content-blocks` 及其依赖消费者以 `d4eaf767` 为基线；本支旧实现和独立QA保存在原提交与原证据归档，绝不改标为新包/v3验收。旧 N-A 不再约束这个当前提供者，不把其四象限实现嫁接到上游通用桥。
2. 继承 I-B 的生成分工、编码与未闭合的登记/恢复责任。CB3 的改动不改变接收的 BlockId/CallId 词法；pi 的输入非法 target 收场仍未定。这里只协调原采用范围，不释放完整 pi 或模型运行时实施门。
3. 上游已有的通用数值桥与消费者不再被本支旧“尚未闭合”文字阻挡；模块外的每跳读写、会话唯一和恢复仍不提升。对混入 undefined/getter/cycle 的 JS 非JSON值，上游先 malformed，本支旧入口曾先命名拒绝；该差异记录为入口输入域复核项，不据此修改已发布语义或先判上游违约。
4. 上游 D-067/D-068/D-069 名称与发布原文原样保持。本支原 Docker D-067、CB接缝 D-068 及其快照也保持原字节，以“合并前本支编号”标识历史引用。拟由新的唯一 D-070 协调记录承接：Docker R4 技术采用整体保留；I-B生成选择继续有效；N-A旧提供者退为历史。现行导航改指 D-070 的具体范围，旧投影与原始证据不改写、不重标。此处不提前编号下一份停止协议决定。
5. 合并 lockfile 的重复 CB importer 已被发现，原失败日志保留；本支相对基点仅加旧 CB importer，故取上游完整锁文件并冻结安装。新增 Node 依赖只补下载该锁固定版本，不自行更新版本。整合测试与独立审阅完成前不接受交付。

## 反向核对与验证

没有新增内核原语、插件状态、外部副作用或数据身份；替换纯模块不改变治理中心既有源码。上游新公开函数面不是跨进程契约，也不代替各 owner 的持久性保证。主线负责检查冻结原件、当前包/锁、受影响节点和编号消歧，独立架构/规格核对整合边界，实际运行验证公开消费者、类型、构建与治理回归。Fable 的里程碑整体评审仍保留。

本候选若采用，只接受上游整合基线与本支技术选择的继续/退役范围；不接受未实现 Agent 全链、不把 Docker I1 探针升级为当前最终制品、不替上游人的总体门签字。
