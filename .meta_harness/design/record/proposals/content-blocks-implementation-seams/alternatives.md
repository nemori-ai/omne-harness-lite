# R2 候选与取舍

约束与具体反例见 [design](design.md)。两个选择对象分别比较，推荐组合为 N-A＋I-B；都尚未接受。

## 无损数值怎样进入块形状校验

| 候选 | 承载方式 | 优势与代价／失效条件 |
|---|---|---|
| N-A：当前 CB Schema 的私有数值视图 | 原 Schema 交 Ajv；按当前数值谓词等价类替换视图中的无损数值；原值只读且原样交出 | 最小局部桥接，复用成熟结构校验；一份全树视图占用额外内存。正确性限当前 CB 数值谓词集合，Schema 变化要重新审视。 |
| N-B：派生 Schema 的精确数字 keyword | 冻结副本只作源；生成内部 Schema，把 numeric type/bounds 改为接受 LosslessNumber 的自定义谓词，递归保持 $ref/组合语义 | 能保留原对象、以后扩展数值边界；要保证派生覆盖所有 numeric 语义且不误认 object，解释器定制与 Ajv 升级耦合更深。对当前一个 bytes 谓词成本偏大。 |
| N-C：完整手写块校验 | 七类块及所有结构/数值约束都写成精确谓词，Schema 只供测试对照 | 无中间视图，失败次序直观；重写 required/oneOf/unevaluatedProperties/嵌套等已存在能力，形成第二套结构表达，漂移面最大。若未来 Schema 引擎不能承载更多性质，可能重选。 |

直接 Number 转换不满足无损要求，不是可行候选。N-B 最强理由是避免分配全树副本且可推广；当前没有重复消费者或测得的开销证据支持先建通用桥。N-C 最强理由是完全可控；代价是每份契约的每次结构变化都要双份维护。推荐 N-A 的前提是保持窄范围，并在数值谓词改变时强制复查。

## 铸号规则怎样协调

| 候选 | 承载方式 | 优势与代价／失效条件 |
|---|---|---|
| I-A：所有生产者统一随机生成 | pi 删除 b+索引和确定性 CallId，同普通生产者调用既有 CSPRNG | 符合 CB 当前概括、实现简单；丢掉 pi 已接受的同输入可重放选择。如要保留，另需保存每流编号表，新增状态与恢复责任。 |
| I-B：按生产者限定策略 | 普通生产者随机；pi 保留本地索引／确定性哈希，明确通用要求只约束词法与唯一性，输入编码定一处 | 保留两端已有实质选择，不新增运行时 owner；需要修正旧 CB 普遍陈述并记录取代范围。组合查重不能省，哈希不是形式唯一性证明。 |
| I-C：运行时统一发号端口 | 模型/工具/派生块都从同一个消息／会话作用域 allocator 取号，由 owner 保留重放映射 | 协调唯一与恢复更集中；需要新端口、状态生灭、持久映射或反查协议。现有契约与 owner 没要求这一协调机制，不能只为消除文字冲突新开服务。 |

I-A 的强项是沿既有生成器零新算法；但实际要放弃的是 pi 的确定性选择，必须证明其没有消费者收益，当前尚无这种证据。I-C 的强项是明确全局责任；代价不是多一层函数，而是跨消息来源的状态与失败恢复。推荐 I-B，范围限两份映射的接缝；运行时真正的登记冲突处理仍由原契约承担。
