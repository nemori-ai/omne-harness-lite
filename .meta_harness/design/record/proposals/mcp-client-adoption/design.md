# MCP 客户端这一层用什么实现、本版桥到哪一步

## 需要作出的选择

两问，一次答：

1. **实现路径**：MCP 协议客户端（连接、握手、列举、调用、通知、重连）由谁提供——DSH `mcp-client` 原样、它的 fork、
   官方 SDK，还是本项目自写。
2. **桥接范围**：对端除「动作」（tools）之外还能提供 resources、prompts，还能反向请求 sampling、elicitation、roots，
   并发送进度、日志、清单变化等通知。产品把「本版桥到哪一步」交给采用的客户端
   （[PF-002 §4 MCP](../../../product/PF-002-assets-settings-and-permissions/design.md#mcp)、[§2 非目标](../../../product/PF-002-assets-settings-and-permissions/design.md#非目标)，rev 13），
   依据是产品负责人 2026-09-23 的裁决「看直接复用的方案支持到哪种程度」。

**这个选择改变的可观察结果**：agent 面前 MCP 条目的形状与稳定性；接入点断了时 agent 读到的是替换件还是条目消失；
一次 MCP 调用落在六种收场中的哪一种；两个租户身份配了不同凭据时是否串号；
对端在调用中途要人输入时，人能否看到并作答。

## 现有能力如何承载

本设计链**还没有**工具协议、工具运行时或 MCP 的契约与节点，没有可以组合的现成承载者。
下表只把性质对到**候选的来源形状**上，读数取自 [mcp-client-reuse 研究](../../../../research/mcp-client-reuse/research.md)（首轮，2026-09-23）。

| 要求 | DSH `mcp-client` `c291e796` 现状 | Codex rmcp-client `5c5308fc`（只能借形状） | 未覆盖或需改 |
|---|---|---|---|
| N-1 逐动作条目 | 每动作一个 `ToolDefinition`，公开名 `mcp__<server>__<raw>`，产物是 DSH 工具契约（E-4、E-8） | 每动作一个 `ToolSpec`（E-13） | 两源形状同向；条目的数据形状要换成本项目的工具定义 |
| N-2 run 前重算、run 内不变 | 连接成功与 `tools/list_changed` 推送时重列，**没有 run 时点**，run 中可被异步换代（E-3） | 每一步前按本地脏标记重投影，不跟对端推送（E-12，部分推断） | 两源都要改；run 时点只能在客户端之外取得 |
| N-3 替换件与持久清单 | 断连期间留上一代、调用失败；预算耗尽**撤销登记**＝「不装」；首连失败一个都不登记（E-3） | 调用时拿不到绑定返回「not available」普通结果（E-14） | **两源都没有持久清单**；DSH 默认终局正是 §6.3 排除的做法 |
| N-4 收场 | `isError` 与断连都抛错成「失败」（E-4） | 鉴权失效折成 `isError`（E-9） | 「不可用」两源都给不出；按 N-4 它本就不该出自客户端，而出自 run 前判定 |
| N-5 按持有分连接与凭据 | 一个插件实例一条连接、静态配置；全局装载时所有 agent 共用一份凭据（E-2、E-7） | 凭据归本机用户，键为服务名 + URL（E-10） | **两源都没有租户维度** |
| N-6 两项超时 | 调用超时可配；连接与发现超时继承 SDK 60 s 不可配（E-6） | 启动 10 s、调用 60 s 分开（E-16） | DSH 需改 |
| N-7 逐动作身份 | 公开名稳定，权限规则可写到单个动作（E-6） | 有逐动作审批覆盖（E-14） | 身份形状可用；审批不归客户端 |
| N-8 宿主与重连 | 连接挂 Cordis 插件作用域；ACP 路径下挂会话新建的 Agent，**执行比连接活得长**；只对 stdio 自动重连（E-3、E-7） | 会话持有；只对 HTTP 会话过期重建（E-9、E-12） | 两源各覆盖一半的重连 |
| N-9 人作答 | 客户端能力声明为空，不收 elicitation（E-3） | 收 elicitation，转审批/提问界面（E-15） | 映射到本项目等待态要自己做 |
| N-10 不带入 DSH 工具契约 | 六个 DSH 包 peer 依赖 + 未声明的 `dsh-util-values`；`tools.ts` 全部建在 `dsh-tools` 上（E-1、E-4） | Rust，十余个 codex 内部 crate | 见 alternatives A、B |
| N-11 拉起位置 | stdio 由 SDK 在宿主机直接拉起（E-5） | 可交远端执行器，实验性（E-11） | 需要能替换 stdio 传输的拉起方式 |

## 剩余责任与能力演化

不论选哪条路，下列责任**都落在本项目**——没有一个现成客户端替我们承担。候选之间的差别只在「协议层从哪来」与「搬进来多少要改掉的东西」。

| 剩余问题 | 关系 | 归属理由与消费者影响 |
|---|---|---|
| 按「持有 × 求值后的连接目标与凭据」管理连接（N-5） | 新增（提供者内部） | 持有与设置求值是本项目的概念，任何上游都没有；键的精确构成归提供者设计 |
| run 开始前列举并投影成条目、run 内冻结（N-1、N-2） | 新增，与可用性计算组合 | 时点归 run 前的可用性重算（PF-006 §6.2），客户端只供「这次能否拿到清单」 |
| 上一次清单的持久副本（N-3） | 新增存储需求 | 替换件要同形只能靠它；按 D-026 落持久存储 |
| 收场映射（N-4） | 新增，工具协议的一部分 | 不可用在 run 前判定、run 内一律按失败/被中断/等待态走 |
| elicitation → 工具等待态（N-9） | 组合：桥到将来的等待态契约 | 等待态契约尚未起草；卡片形状与 PF-008 的交点要一起定 |
| stdio 拉起位置接口（N-11） | 组合：接执行环境 | 候选假设，确认后才是义务 |
| 协议层本身（握手、JSON-RPC、传输、分页、取消） | **四条候选分歧所在** | 见 [alternatives.md](alternatives.md) |

**不提出新的能力维度。**MCP 客户端是工具运行时的一个提供者，不是一项独立能力；能力边界怎么画归将来的架构设计。

## 契约、动作链与 Cordis 投影

**本包不写契约，也不写提供者设计。**下面只是在 C 路径下写出一个投影轮廓，让「剩余责任」有落点可查；定稿归规格与 realization。

- **run 开始前**（每个装进来的 MCP 持有各走一遍）：求值连接目标、凭据、两项超时 → 取或建连接（受连接超时约束）→ 分页列完 `tools/list`
  → **完整拿到**：刷新持久清单，投影成条目；**拿不到**（连不上、超时、分页中断）：读持久清单，逐动作装替换件，说明「接入点连不上」；
  **一份清单都没有**：交接缺口，不填默认。
- **一次调用**：条目 → 当前连接 → `tools/call`（带单次调用超时与取消信号）。对端 `isError`、断连、超时 → 失败；
  本系统中断 → 发 MCP 取消通知，收场被中断；对端要输入 → 本次执行进入等待态；不重放。
- **Cordis 形状（轮廓）**：一个提供连接服务的插件，连接作为它纳管的 effect；**不做「一个服务端一个插件实例」**。
  理由是手册六问第三问：按租户、按持有区分的是**数据**（设置值），不是实现，定制数据不开隔离维度；
  DSH 那种「服务端配置＝插件配置」在这里会让实例数等于持有数 × 求值组合，触发表 D 的组合爆炸信号。
  工具执行是否 `inject` 这个服务要按「消费者能否承受被卸载重跑」再判——长时执行承受不了，归提供者设计。
- **跨进程之后**（SYS-DEPLOY）：连接池与持久清单的一致性在单机由同一存储给出，分布式后要由协议重新兑现；本包只标出，不设计。
