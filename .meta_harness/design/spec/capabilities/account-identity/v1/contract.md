- 契约坐标：`omne-harness-lite-design-2026-09-15` · `capability.account-identity` · `v1`

- 系统约束：[SYS-TENANT](../../../../foundation/cross-system-constraints/requirements.md#sys-tenant)
- 精确依赖：无。本契约不消费其他能力；个人租户的产生由

- 状态：candidate

## 目的、消费者与责任

本能力拥有**自然人产品身份**的产生、验证与登录态管理。

消费者是一切需要「这次交互是谁」的能力。本能力对它们承诺一件事：
**给出的账号身份唯一、已通过验证，且可追到一次仍然有效的登录。**

本能力**不拥有**：租户与成员关系（归[租户治理](../../tenant-governance/v1/contract.md)）、
设置取值、资产与权限的具体内容、额度与账目——它们各有 owner，本能力只提供「这次交互是谁」。
它也不判断两个账号背后是否同一现实人——见 INV-5，这是一条**禁止拥有**的条款。

## 概念、身份与必要状态

| 概念 | 含义 | 权威与保留范围 |
|---|---|---|
| 账号身份 | 一个自然人的产品身份 | 本能力拥有；持久，本版不承诺终止语义 |
| 登录标识 | 用于定位账号的对外标识 | 本能力拥有；**部署内唯一**，见 S-3 |
| 凭据 | 证明持有该账号的东西 | 本能力拥有验证责任；不承诺具体形式 |
| 激活状态 | 账号是否可用 | 本能力拥有；**未激活的账号不是可用账号**，见 S-4 |
| 登录会话 | 一次可撤销的已登录状态 | 本能力拥有；**持久事实**，见 S-7 |

**账号身份不隶属于任何租户。**它先于任何租户存在，也不因所属租户变化而变化。
这是 SYS-TENANT 双层结构中「自然人全局身份」的一半。

## 性质与前提

| 性质 | 要求来源与观察范围 | 保护边界 | 依赖保证或环境前提 |
|---|---|---|---|
| **S-1**（安全）未通过验证的身份绝不被当作成功账号使用或呈现 | PF-001 §4「个人组织」与 §6.8；对所有消费者成立 | 本能力的全部对外操作 | 无 |
| **S-2**（安全）不因两个账号背后是同一现实人，而使一方的任何事实对另一方可用 | PF-001 §4「账号」 | 授权判定依据的构成 | 各维度 owner 不得自行引入该路径 |
| **S-3**（不变量）登录标识在**部署范围内**唯一 | PF-001 登录旅程 的必要条件 | 账号产生操作 | 存储提供者保证唯一性约束 |
| **S-4**（不变量）未激活的账号不可用于任何交互 | PF-001 §4「个人组织」与 §6.8 | 身份验证与登录 | 无 |
| **S-5**（不变量）系统中不存在把两个账号关联为同一现实人的事实 | PF-001 §4「账号」 及其约束段 | 数据形状本身 | **结构性条款**：数据契约中不含跨账号关联字段 |
| **S-6**（不变量）任一次交互所用的账号身份唯一且已验证 | PF-001 登录旅程与 §6.4 | 所有消费者的操作入口 | **前提**：消费者的操作签名含身份参数且该参数**无默认值**；前提失效时责任在该消费能力 |
| **S-7**（安全）登录态被撤销后，绝不存在凭它成功访问该账号数据的后续交互 | PF-001 登录旅程 | 登录态验证 | **前提**：撤销记录持久，不随本能力装卸消失 |
| **S-8**（安全）物理位置事实绝不构成访问资格 | PF-001 兼容边界 | 资格判定依据的构成 | **结构性条款**：判定依据中不出现路径、工作目录、操作系统用户、存储位置 |
| **S-9**（安全）失败或中断的注册、登录、注销绝不呈现为成功，也绝不把数据接入错误账号 | PF-001 §6.8 | 全部旅程操作 | 结果集合见 S-15 |

| **S-11**（进展）**前提**：存在有效登录态且调用方发起撤销 ⇒ 该登录态最终失效 | PF-001 登录旅程 | — | 范围只及该登录态，见下 |

## 操作与可观察事实

### 产生账号（未激活）

- **输入与授权**：登录标识、凭据。**本操作不要求调用方已认证**——这是自助注册（PF-001 §4「个人组织」）。
  谁有资格发起本操作属于部署准入策略，见 G-2。
- **状态变化与提交**：写入一条未激活的账号记录。提交点在本次写入。
  **本操作不使账号可用**（S-4）。
- **返回与失败**：成功返回账号身份；失败集合 = { 标识已被占用, 凭据不满足已声明规则, 存储不可用 }。
- **重试与幂等**：以登录标识为幂等边界。重复提交同一标识：若既有记录未激活且由同一次注册产生，
  返回同一账号身份；否则返回「标识已被占用」。
- **事件**：不发布。未激活账号不是可观察事实。

### 激活账号

- **输入与授权**：账号身份 + 激活依据。**激活依据由**[注册组合](../../../compositions/account-registration/v1/contract.md)**提供**，
  本能力不自行判断个人租户是否存在。
- **状态变化与提交**：账号转为可用。**这是账号可用性的唯一提交点。**
- **返回与失败**：失败集合 = { 账号不存在, 已激活, 激活依据无效, 存储不可用 }。
  已激活时返回成功且不产生第二次效果（幂等）。
- **事件**：发布「账号已激活」通知。**通知性质**：消费者不得据其返回值改变本操作结果。

### 验证凭据并建立登录态

- **输入与授权**：登录标识、凭据。
- **前置**：账号存在**且已激活**（S-4）。未激活账号的验证结果与不存在账号**不可区分**——
  否则未激活账号的存在性会泄漏。
- **状态变化与提交**：写入一条登录态记录。**登录态是持久事实**，不是内存生命周期（S-7 的前提）。
- **返回与失败**：失败集合 = { 标识或凭据不匹配, 存储不可用 }。
  **「标识不存在」与「凭据错误」必须返回同一失败**，不得区分。

### 撤销登录态

- **输入与授权**：该登录态本身，或持有该账号的其他有效登录态。
- **状态变化与提交**：撤销记录写入后提交。**撤销必须持久**——若仅在内存中失效，
  重启后 S-7 失守。
- **返回与失败**：失败集合 = { 登录态不存在, 存储不可用 }。已撤销时返回成功（幂等）。
- **作用范围**：只有**被撤销的那一个登录态**失效。同一账号在其他设备上的登录态**不受影响**——
  这是已确定的产品行为，不是未定范围，消费者不得实现成全设备失效。

### 验证登录态

- **输入**：登录态标识。
- **返回**：已验证的账号身份，或拒绝。
- **缺席时的默认答案**：**存储不可用或查询失败时拒绝。**
  查不到撤销记录不等于未撤销；把「查不到」当作「有效」会使 S-7 在故障期间失守。

## 交接、缺席与恢复

**本能力不可用时**，消费者不得沿用上一次的身份判定结果继续放行。
已建立的登录态记录是持久事实，在本能力恢复后仍然有效；但在不可用期间，
任何需要验明身份的操作**必须失败而非放行**。

**撤除不等于外部效应回滚**：已发出的注册成功回执不因本能力撤除而收回。

**在途操作**：本能力的每个操作都在单次提交内完成，不存在跨操作的在途状态。
注册旅程的在途状态归[注册组合](../../../compositions/account-registration/v1/contract.md)。

## 装配给的保证与协议给的保证

本节回答步骤 F 第四问，按 [SYS-DEPLOY](../../../../foundation/cross-system-constraints/requirements.md#sys-deploy)
要求写入契约：第一版单机，但领域语义在未来分布式下必须不变。

| 保证 | 当前由谁兑现 | 分布式后 |
|---|---|---|
| S-3 标识唯一 | 单机存储的唯一性约束 | **须由协议重新兑现**：跨节点的标识分配需要一致性保证 |
| S-4 未激活不可用 | 同进程内的读取即时可见 | **须由协议重新兑现**：激活状态的传播延迟期间，副本可能读到旧值 |
| S-7 撤销后不可访问 | 撤销记录写入即对后续读可见 | **须由协议重新兑现**：撤销的传播窗口内旧节点可能仍放行；须定义最大传播时延并纳入契约 |
| S-6 身份参数无默认值 | 类型与接口约定 | 不变，与部署形态无关 |
| S-2/S-5/S-8 结构性禁止 | 数据形状与判定依据的构成 | 不变 |

**前三条是装配给的保证**，跨进程后失效，必须由协议重新兑现。
这一行是本契约对未来演化的显式承诺边界，不是设计笔记。

## 规范表达与验证义务

| 性质 | 表达形式 | 证据义务 |
|---|---|---|
| S-3、S-4、S-5 | JSON Schema + 存储约束 | 结构检查 |
| S-2、S-8 | 结构性审查 | 判定依据的静态检查：不出现禁止路径 |
| S-1、S-7、S-9 | 规范场景 | 对抗性旅程演练：每个中断点尝试越权，任一成功即失败 |
| S-10、S-11 | 行为模型 | 见[注册组合](../../../compositions/account-registration/v1/contract.md)的形式任务；本能力单独的进展性质随其一并检查 |

**有限检查不表述为无条件证明。**每项证据须记录其输入范围与关闭的故障路径。

| 编号 | 缺口 | 谁能闭合 | 在闭合前 |
|---|---|---|---|

| **G-4** | 账号终止语义未确认（PF-001 §2 非目标明确不要求永久关闭账号） | 需求方 | 本版不承诺；S-3 的唯一性因此在账号存续期内恒成立 |

**需求正文中的 pending 表述未被本契约采用。**核实结果：该表述在需求 topic 的 changes.md 中
无任何用户确认条目，唯一可追依据是一份已接受的设计决定。按「未确认的要求不驱动落地」，
本契约以 S-1、S-4 的「未通过验证」与「未激活」表述同等保护，不引入未经确认的 pending 概念。
