# 工程证据、查询与缺口 v1

本契约坐标为 `(omne-harness-lite-design-2026-09-15, capability.engineering-observation, 1)`。正文从同名
legacy v1 重基，保留 OB-01～OB-03；D-008 只作 provenance，不自动接受本坐标。

本能力拥有结构化 log/trace/diagnostic 的采集、关联、缺口、查询与退出语义。观测事件
不是授权、控制或业务状态权威；普通诊断失败不得静默改变已成立的业务提交。

## 工程观测

**OB-01**：每项业务能力在本身的操作/提交边界生成受理、拒绝、开始、等待、
答复、控制、终态、失败、unknown 与动态变更依据，带 CD-02/CC-07 的关联。
工具过程披露与这些工程事实不同；未形成调用即被拒绝的入口也必须有
可定位 operation/主体/阶段及被裁剪目标，不能只统计成功调用。

观测采集与读面拥有采集 cursor、处理版本、来源水位、保留策略、索引、
导出任务和 gaps；关键业务记录仍由原权威拥有。工程事件非授权或执行
命令，不允许观测 listener 改变已经成立的结果。度量至少覆盖队列/等待/
执行延迟、请求/错误/拒绝计数、资源使用、依赖就绪、写入/交付水位和费用
质量；它们不是供应方账单。

**OB-02**：关键生命周期/审计随所属耐久提交或可核实 outbox 保存，不受
普通诊断采样丢弃。非关键诊断允许有界缓冲/采样/保留期，但记录缺口类型、
来源范围、水位和丢弃计数。采集/传输/存储/索引故障和积压对读面可见，
无需伪造覆盖全链路。关键记录不能保存时拒绝依赖它的新效果；入口拒绝
自身也无法耐久记录时返回 audit_unavailable 并保留可用的最小诊断，不能
声称审计完整。诊断故障不通过递归记录制造无限任务。

**OB-03**：query/export 使用当前身份、tenant、内容分类和对象权限；原
记录内容按秘密引用、敏感参数与正文权限裁剪。关联 ID 不等于全文读取
能力。导出固定快照/水位，保留期结束或缺失显示 gap/gone；不从若干成功
span 推导整体已完成。观测插件卸载先排空必要记录，失败保留责任及
剩余 cursor；采集恢复认回原水位，不重放业务效果。
