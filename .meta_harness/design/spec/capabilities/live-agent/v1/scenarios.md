# capability.live-agent v1 的符合性场景

本表是规范场景，不是已执行实现测试。模型、数据与提供者测试的范围分别见
[验证说明](../verification.md)。

| 场景 | 初始条件、动作与可观察结果 | 规则 |
|---|---|---|
| S01 同会话并发激活 | 同租户同 Session 空闲；两个 activate 竞争；一个预留成功，另一个冲突；失败方无资源副作用 | AR-4 |
| S02 租户与权限 | 两租户都有相同 sessionId；可各激活；用 A 依据读/控制 B、同租户无对象权限、缺失依据均不可访问；无事件/列表泄漏 | AR-1/2 |
| S03 旧生命期 | a1 释放后 a2 同 Session 激活；a1 的句柄、工作提交与重复清理不能控制/删除 a2；resolve(a1) 不重定向 | AR-2/7/10 |
| S04 准备竞争 | setup 等待期间 owner 关闭或依赖撤除；晚到资源仍清理，不发 activated、不启动驱动；清理完成前新 activate 冲突 | AR-5/6/7 |
| S05 发布重入 | activated 监听器关闭实例，另一监听器抛错；发布仅一次，通知错误可见，退出继续，返回句柄如实为 closing | AR-6/17 |
| S06 私有失败 | Session attachment 不匹配、原定义不可用、setup/发布检查失败；无活体发布，已有会话历史保留，清理失败占位可见 | AR-5/7 |
| S07 并发关闭 | 两外部调用者关闭同一实例；共享退出过程；一个取消等待，另一个继续等待，不能恢复准入 | AR-11 |
| S08 真正排空 | ready 有受管工作；close 后新工作拒绝，既有工作及其未移交后代先结束，才清依赖和撤登记 | AR-8/10/12 |
| S09 自等待 | 某许可内部请求关闭；关闭已受理；等待完整退出明确 self-wait 拒绝；许可结束后外部等待者得到真实结果 | AR-14 |
| S10 清理失败 | releasing 某资源失败；独立清理继续、依赖它的资源保留；blocked 原因/残留可查，无 disposed，无新实例；仅安全重试原清理 | AR-13 |
| S11 提供者演化 | f1 撤除时仍有 preparing/ready 使用者；先关闭它们的准入并排空，再撤 f1；同名 f2 此前冲突，之后可绑定 | AR-15/16 |
| S12 意外依赖丢失 | 实例必需服务消失使实例关闭；仅模型网络不可达则相应新请求拒绝，独立本地查询继续；原工作报真实失败/未知，不伪造排空 | AR-16 |
| S13 调用者与业务父 | master 运行时重建；独立 session 宿主持有的 child/background 工作不被当作 master 的局部 effect 销毁 | AR-3/12 |
| S14 移交边界 | 本实例工作请求移交但接管结果未知；不能减少原账目；接管明确成立后方可释放局部资源，独立效果仍有权威归属 | AR-10/12/13 |
| S15 装配一致性 | 工作 A 已使用装配 r1；配置切至 r2；A 不混读 r2，后续合格工作按所属能力边界采用 r2；换驱动则新实例 | AR-9 |
| S16 恢复与真实事实 | 同 Session 重新 activate；新 incarnationId，原持久历史/定义关联未改；没有驱动恢复证据时只能报告激活，不能报告 Run 已续接 | AR-4/5 |
| S17 授权撤销 | 持有旧 Handle 但权限已撤销；下一操作被拒；宿主仍可用精确清理能力收口，清理能力不能发起新工作 | AR-1/8/11 |
| S18 外部晚到 | a1 已释放，原工具效果后来确认；不能回写 a2 的运行态，原工作权威仍接收真实事实，不自动重复执行 | AR-10 |
| S19 Session 失效竞争 | Session attachment 检查后、发布前撤销；同一屏障裁决，不能带失效绑定发布；发布后业务状态变化，Run 准入重查 | AR-6 |
| S20 同名旧撤除 | f1 完成撤除，f2 注册同名；f1 的晚到撤除无额外作用，不撤 f2；独立解析键提供者不受影响 | AR-15 |
| S21 进程重启 | 同 Session 在新进程重新激活；AgentRef 不与旧进程相同；跨部署协调/执行权尚未实现时拒绝声称安全自动接管 | AR-4/10；ARI-3 |
| S22 可选贡献在途撤除 | 实例上的可选工具贡献正被工作 A 使用，B 独立；贡献 owner 关闭新使用，消费能力依契约结算 A 后才释放；缺少撤除策略则明确受阻，B 不被关闭 | AR-9/16 |
| S23 同租户多会话 | A 的两个不同 Session 各激活；只关闭一个，另一个仍可准入；任何目录/占位键不能只用 tenantId | AR-4 |
| S24 有限信任插件 | 插件仅获部分宿主权限但尝试作为同进程无限能力 Factory 装载；执行边界映射未建立则拒绝，不能靠 Context 隔离宣称安全 | 执行信任前提；AR-1 |
