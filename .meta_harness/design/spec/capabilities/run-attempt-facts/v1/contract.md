## 一、含义与使用范围

### S-1 本契约拥有什么

**一个读：给 (会话, 运行, 尝试)，答两件事实——这次尝试是否已被取代、这个运行是否已终结；两件事实都按会话日志定义，只从假变真。**

| # | 拥有的事实与判定 | 正文 |
|---|---|---|
| 1 | 两件事实的**定义**：以会话日志里已提交的条目为准 | [S-5](#s-5-两件事实) |
| 2 | 单调：一件事实一旦答真，此后永远是真 | [S-6](#s-6-只从假变真) |
| 3 | 一次读的两件事实出自同一刻，且看得见调用开始之前已提交的一切 | [S-7](#s-7-读的是哪一刻) |
| 4 | 「日志里没有这次尝试」与「读不到」是两个值；**答不出就失败，不答「未取代、未终结」** | [S-8](#s-8-缺席时的默认答案与失败值) |

### S-2 本契约不拥有什么

| 不拥有 | 归谁 |
|---|---|
| **写下这两件事实**：尝试开始记录、运行终结记录——它们是会话日志里的条目，由 loop 写 | **本版不收**：loop 与会话那一程（PF-012 §6.16；[G-1](#十已知缺口)） |
| **运行终结记录的形状**：从日志里怎样认出「这个运行终结了」 | **本版不收**：loop 那一程（[G-3](#十已知缺口)）；`capability.session-log` v1 同样不收（那份契约的 S-2） |
| **`late` 怎样算**：锚定哪次尝试、是否标 `late` | 写下那笔账的一方（`data.call-accounts/v1#S-39`「由写下它的那一方判」）。本契约只给事实 |
| **尝试栅栏**：带栅栏的写入被拒 | `capability.session-log/v1#S-10`。本契约的「已被取代」与那道栅栏**同一个条件**，但本契约不拒任何写 |
| **运行的其余事实**：终态是哪一种、原因、是否留有未收尾的外部效果 | loop 那一程；本版只答「终结了没有」 |

### S-3 本契约明确不承诺什么

- **不与调用方的写同成同败**：本契约的读在调用方自己的提交之外；读到「仍是当前」之后、调用方提交之前，事实可能变真（[G-2](#十已知缺口)）。**本契约只保证：它答真的，那一刻确实已经为真**（[S-6](#s-6-只从假变真)、[S-7](#s-7-读的是哪一刻)）。
- **不另存一份尝试或运行的状态作为权威**：事实的权威是会话日志（[S-5](#s-5-两件事实)）。提供者怎样读出它归提供者节点（[十一](#十一提供者映射)）。
- **不附 Schema**。线上形状归把它送过进程边界的那份 composition（[规格容器的规矩](../../../README.md#准入门槛与停止条件)）。

## 二、概念、身份与必要状态

**会话的指认是 `SessionRef`（`data.messages/v1#S-24`），运行与尝试是 `data.call-accounts/v1#S-37` 的 `RunId` 与 `AttemptId`，不复制定义。**

### S-5 两件事实

对一个会话里的 (运行 `run`, 尝试 `attempt`)，在某一刻：

1. **已被取代**（`superseded`）为真，当且仅当**那一刻这个会话的会话日志里有一条条目，壳上是同一个 `run`、尝试序号大于 `attempt`**。
   - 这正是 `capability.session-log/v1#S-10` 拒收 `fenced{run, attempt}` 的条件：**「已被取代」为真的那一刻起，这次尝试带栅栏的写一条也写不进**。两者同一个条件，所以不会出现「栅栏已经关了、这里还说仍是当前」或反过来。
   - 与 PF-012 [「只有序号最大的那次尝试」](../../../../product/PF-012-agent-loop-and-run/design.md#同一个-run-同一时刻只有一副协程在推它)同义的前提与那份契约相同：每次尝试在日志里的第一条就是它的尝试开始记录（`data.messages/v1#S-20`），这是 loop 的义务。
2. **已终结**（`runEnded`）为真，当且仅当**那一刻这个会话的会话日志里已有这个运行的终结记录**（[PF-012 §6.16](../../../../product/PF-012-agent-loop-and-run/design.md#616-日志里至少要有这几种-run-相关的条目)「Run 终结」那一行：它落下，运行就有了[运行终态](../../../../ubiquitous_language/terms/agent-runtime-loop.md#ul-run-terminal-state--运行终态--run-terminal-state)）。终结记录怎样认，本版不收（[G-3](#十已知缺口)）。
3. **这次尝试在日志里**，当且仅当那一刻日志里至少有一条条目壳上是 (`run`, `attempt`)。不在，就没有「这次尝试」可答（[S-8](#s-8-缺席时的默认答案与失败值) 的 `attemptNotFound`）。
4. **权威是会话日志**：[PF-012 §5.2](../../../../product/PF-012-agent-loop-and-run/design.md#52-会话日志是唯一的真相来源)、执行尝试词条「身份从日志派生、不另存」。提供者手里若有别的存放，它的答案也必须等于按本条从日志算出的答案。

### S-6 只从假变真

1. **「已被取代」一旦为真，永远为真**：会话日志只增不改（`capability.session-log/v1#S-11`），更大序号的那条条目不会消失。
2. **「已终结」一旦为真，永远为真**：终态只落一次，不复活（运行词条「落终态才结束」；延续是另一个运行）。
3. **「这次尝试在日志里」一旦成立，永远成立**；「不在」可能稍后变成「在」（尝试开始记录在两次读之间落下）。
4. **后果**（M74、N-29 的读法）：调用方在自己的提交之前读到的「仍是当前」「尚未终结」，到它提交的那一刻可能已经不对；读到的「已被取代」「已终结」到它提交时仍然对。**所以依它写下的 `late` 只可能漏标、不会误标**（`data.call-accounts/v1#S-39`）；漏标的窗口本版不闭合（[G-2](#十已知缺口)）。

### S-7 读的是哪一刻

1. **一次读的两件事实出自同一刻**：不会「已被取代」按这一刻、「已终结」按另一刻。
2. **那一刻不早于调用开始**：调用开始之前已经成功返回的任何一次会话日志追加，这一次读都看得见（`capability.session-log/v1#S-13` 第 4 条）。
3. **不承诺那一刻之后**：读返回之后提交的条目，这一次读不反映。

## 三、贯穿全部操作的规矩

### S-8 缺席时的默认答案与失败值

**一律拒绝或明确失败，不填初值。**三类分开：

| 情形 | 结果 | 为什么不合并 |
|---|---|---|
| 判定得出「日志里没有这次尝试」 | **`attemptNotFound`** | 读得到、确实没有：一个结论。**不是「仍是当前、尚未终结」**——一次还没开始（或根本不属于这个会话）的尝试，谈不上当前 |
| 判定**做不出来**：会话日志此刻读不到；或提供者认不出终结记录（[G-3](#十已知缺口)） | **`unavailable`** | 没有结论（`data.identity-values/v1#S-19`） |
| 输入**根本不构成这个请求** | **`invalidInput`**，在判定之前 | 表示层校验不是判定（`data.identity-values/v1#S-33`） |

- **身份参数没有默认值**：会话、运行、尝试缺一即 `invalidInput`，**不从进程上下文或「当前那次尝试」补**（`data.identity-values/v1#S-17`、`#S-18`）。
- **两件事实要么一起答出，要么一起不答**：没有「已被取代答得出、已终结答不出」的半截答复——[M74](../../../../record/decisions/mainline-self-rulings-2026-09/decision.md#八实现映射起草反推出的契约修订m31m442026-09-25-追加)「不给过渡值」；**绝不以 `false` 顶替一件判不出的事实**。

**失败值总表**（本契约的全部失败值，含义以这里为准）：

| 值 | 含义 | 类 |
|---|---|---|
| `invalidInput` | 输入不构成这个请求（上表第三行）；[S-9](#s-9-attemptfacts读一次尝试的两件事实) ⑥ 列出具体情形 | 表示层 |
| `attemptNotFound` | 读得到这个会话的日志，里面没有这次尝试的任何条目（[S-5](#s-5-两件事实) 第 3 条）。运行本身不在日志里也是这个值 | 定位 |
| `unavailable` | 判不出来（上表第二行）。**与已接受的 `capability.organization-governance` v1 同名同义** | 失败 |

> **账本外的名字**：`attemptNotFound` 与两件事实的成员名 `superseded`、`runEnded` 是本契约起草时给的**候选名**（施工简报的账本没有它们），**主线已接受**（[D-040 §八 N-37](../../../../record/decisions/mainline-self-rulings-2026-09/decision.md#八实现映射起草反推出的契约修订m31m442026-09-25-追加) ①）。

**谁调用**（据点进程内的能力间面，**不直接暴露给人或 agent**）：工具执行运行时，每条收场路径在它的写事务之前（节点 T-4）。

## 四、操作

每个操作写全九件事：①输入 · ②前置与授权 · ③结构性禁止 · ④提交点与原子性 · ⑤成功返回 · ⑥失败集合（闭合枚举，按判定次序）· ⑦幂等与重复 · ⑧缺席时的默认答案 · ⑨事件。

### S-9 attemptFacts：读一次尝试的两件事实

`attemptFacts(session, run, attempt) → { superseded, runEnded }`

| # | 内容 |
|---|---|
| ① | `session`（`SessionRef`）、`run`（`RunId`）、`attempt`（`AttemptId`：尝试序号，≥ 1 的整数） |
| ② | 调用方是装配放进来的读方（[S-11](#s-11-装配给的保证-vs-协议须给的保证)） |
| ③ | 无 |
| ④ | 只读，无提交；两件事实出自同一刻（[S-7](#s-7-读的是哪一刻)） |
| ⑤ | `superseded`、`runEnded`：两个都给出的真值（[S-5](#s-5-两件事实)） |
| ⑥ | `invalidInput`（任一参数缺席或不合形状）→ `attemptNotFound`；读不到、认不出终结记录 ⇒ `unavailable` |
| ⑦ | 只读，天然可重复；两次读之间事实只可能从假变真（[S-6](#s-6-只从假变真)） |
| ⑧ | 判不出 ⇒ `unavailable`；**不答「未取代、未终结」** |
| ⑨ | 不发 |

## 七、装配给的保证 vs 协议须给的保证

### S-11 装配给的保证 vs 协议须给的保证

[SYS-DEPLOY](../../../../foundation/cross-system-constraints/requirements.md#sys-deploy)：**左列单机时由装配顺带给出，跨进程之后不会自动成立；右列是本契约已经记下的待兑现项（[G-4](#十已知缺口)）。**

| 保证 | 本版（单机）由谁给 | 跨进程之后谁重新兑现 | 做不到会怎样 |
|---|---|---|---|
| **读看得见调用开始之前已提交的日志**（[S-7](#s-7-读的是哪一刻) 第 2 条） | **装配给**：据点上一份会话日志、一份本能力，读的是同一份存储 | **协议给**：读写明它读到日志的哪个位置为止，不以落后的副本冒充；或读在日志的定序者上做 | 新尝试已经开始，这里仍答「仍是当前」——漏标扩大到任意长 |
| **答案等于从日志算出的答案**（[S-5](#s-5-两件事实) 第 4 条） | **装配给**：提供者从同一本日志读出，或它的存放与日志同一次提交写入（[十一](#十一提供者映射)） | **协议给**：存放是日志的派生视图，写明它追到哪个位置 | 两份状态对不上：栅栏已关、这里说仍是当前；或反过来**误标** `late` |
| **调用方身份已核实** | **装配给**：据点进程内的能力间面 | **协议给**：调用携带会话与调用方身份，接收边界重新验证（`data.identity-values/v1#S-30`） | 拿到一个会话指认就能探知别人的运行进度——**本契约的面不得直接暴露成终端 API** |

## 八、交接、缺席与恢复

### S-12 提供者撤除、换代与重启

- **本契约没有自己的事实**：两件事实都在会话日志里（[S-5](#s-5-两件事实) 第 4 条）。换一个提供者实例、重启，**任何一次读的答案只取决于那一刻的日志**。
- **撤除时在途的读**：调用方可能等不到回答，按 `unavailable` 处置。
- **提供者缺席**（装配里没有它）：消费者按它自己契约「读面缺席」那一行收场（工具执行运行时：`dependencyUnavailable{runAttemptFacts}`，它的 S-15），**不给过渡值**。

## 九、规范表达与验证义务

### S-13 本版选用哪些形式工件

**不建形式模型。**本版只有一次读，它的性质是「按日志定义」「只从假变真」「答不出不编」：前两条由会话日志的只增不改与尝试栅栏的同一条件继承而来（栅栏那一半写在 `capability.session-log` v1 的模型里，**该模型未运行**），第三条是单次调用上的比较。**真正的跨 owner 交错**——读、取代、调用方提交三者之间——本版明确不闭合（[G-2](#十已知缺口)），没有一条本契约承诺的性质可供模型去反证。证据是下面几条规范场景与故障注入；G-2 闭合时（落账与事实有了共同存储对象），那个协议才需要行为模型。

本版不附 JSON Schema。执行状态在[验证入口](../verification.md)，**不写进本版本目录**。

### 规范场景

**每一条都要真跑**。操作层面的实例在 [`examples.md`](examples.md)。

#### S-14 取代之后读得「已被取代」

运行 `R` 的尝试 1 写过条目；loop 以尝试 2 落下尝试开始。之后读 `(s1, R, 1)`。**必须观察到**：`superseded: true`、`runEnded: false`；同时 `capability.session-log` 拒收尝试 1 的带栅栏追加（两边同一个条件）。读 `(s1, R, 2)`：`superseded: false`。

#### S-15 终结之后读得「已终结」

运行 `R` 的终结记录落下之后读 `(s1, R, 2)`。**必须观察到**：`runEnded: true`。**受 [G-3](#十已知缺口) 阻**：在终结记录的形状定下之前，这一条只能在验收装配里由代 loop 写终结的那一方演练。

#### S-16 没有这次尝试不是「仍是当前」

读 `(s1, R, 7)`（日志里只有尝试 1、2）与 `(s1, Q, 1)`（运行 `Q` 从没出现）。**必须观察到**：两次都是 `attemptNotFound`，**没有一次交回两个 `false`**。

#### S-17 读不到就是读不到

让会话日志读不到（故障注入）。**必须观察到**：`unavailable`；**不交回任何真值**。

#### S-18 只从假变真

对同一个 `(s1, R, 1)` 反复读，其间落下尝试 2 的尝试开始、再落下运行终结。**必须观察到**：读到的序列里，任何一件事实一旦是 `true`，此后再也不是 `false`。

## 十、已知缺口

**缺口不填默认值。**

| # | 缺口 | owner | 闭合条件 |
|---|---|---|---|
| G-1 | **本版与真承接者那一程的关系**（据点装配缺口 C-16）：本版是窄口——只有一个读，给出工具执行运行时算 `late` 要的两件事实；**运行与尝试的完整读面与它的真提供者**（尝试开始、运行终结记录的写法，运行终态与原因的读，恢复时「该不该起协程」要的全部判定）归会话日志与 loop 那一程（C-1、C-8）。那一程起草时，本版的 S-5～S-9 要么原样收进（或以本契约的新版本发布），要么写明差异；**消费者不因此升级**，直到它们改钉新版 | 主线 → 会话日志与 loop 那一程（[D-040 §八](../../../../record/decisions/mainline-self-rulings-2026-09/decision.md#八实现映射起草反推出的契约修订m31m442026-09-25-追加) M74 的 C-16） | 那一程的契约发布，写明与本版的对应；`capability.tool-execution-runtime` 的 G-18 随之闭合；验收替身删除 |
| G-2 | **读与调用方的提交之间没有共同存储对象**（N-29）：调用方读到「仍是当前」之后、它自己提交之前，事实可能变真，那笔账就漏标 `late`。本版只保证不误标（[S-6](#s-6-只从假变真) 第 4 条） | 主线 ＋ 会话日志与 loop 那一程（与 `capability.tool-execution-runtime` G-18 同一闭合条件） | 落账与两件事实的写入有一个共同存储对象（例如账以带栅栏或带条件的追加进同一本日志），本契约出新版或被那份契约取代 |
| G-3 | **运行终结记录怎样认**：本版的「已终结」按终结记录定义，而那条记录的形状归 loop 那一程；`capability.session-log` v1 把它当不透明载荷。**在它定下之前，提供者从产品日志里认不出终结 ⇒ 按 [S-8](#s-8-缺席时的默认答案与失败值) 答 `unavailable`**，不答 `false` | loop 那一程（PF-012 §6.16 的条目形状） | 终结记录有形状（或一个约定的读取键），提供者据它判 |
| G-4 | **跨进程**：[S-11](#s-11-装配给的保证-vs-协议须给的保证) 右列 | 架构设计（本版单机不阻断） | 分布式演化启动时给出，**作为本契约的新版本发布** |

## 十一、提供者映射

**本版的最小提供者**（候选；节点由主线另立，本契约不设计它）：据点根作用域一份，服务键候选 `runAttemptFacts`；**不另存表**（主线裁定 [D-040 §八 N-37](../../../../record/decisions/mainline-self-rulings-2026-09/decision.md#八实现映射起草反推出的契约修订m31m442026-09-25-追加) ④，取代施工简报原写的「本机 JSON 文件或 sqlite 表」）。**本契约对它的要求只有一条是形态上的**：它的答案必须等于按 [S-5](#s-5-两件事实) 从会话日志算出的答案（第 4 条）。

- **「已被取代」与「这次尝试在日志里」直接从会话日志的条目壳算出**：`capability.session-log` v1 的条目壳带 `run` 与 `attempt`，从头读一遍即可。另存一张表，就要与日志同一次提交写入，否则它就是 PF-012 说的[「日志之外的第二份状态」](../../../../product/PF-012-agent-loop-and-run/design.md#同一个-run-同一时刻只有一副协程在推它)——所以不存。
- **「已终结」在 [G-3](#十已知缺口) 闭合之前从产品日志里算不出**：**产品装配里这一次读恒收 `unavailable`**（与今天读面缺席时消费者的收场相同，不更坏）；验收装配里由测试种子答（代 loop 写终结的那一方同时给出它）。

它**取代**验收装配里「尝试与运行的事实」那个替身（[据点装配验收替身表](../../../../realization/apps/cli/design.md#验收装配)）；**真提供者**归会话日志与 loop 那一程（[G-1](#十已知缺口)）。
