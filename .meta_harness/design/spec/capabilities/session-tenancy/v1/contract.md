## 一、含义与使用范围

### S-1 本契约拥有什么

**一个读：给一个会话，答它持有的那个租户身份；同一个会话永远答同一个。**

| # | 拥有的事实与判定 | 正文 |
|---|---|---|
| 1 | 会话 → 它持有的租户身份这一映射的**读** | [S-5](#s-5-会话持有的租户身份)、[S-8](#s-8-holdingtenant读会话持有的租户身份) |
| 2 | 答案不变：一个会话一旦答出某个租户身份，此后永远是它 | [S-6](#s-6-答案不变) |
| 3 | 「没有这个会话的记录」与「读不到」分成两个值 | [S-7](#s-7-缺席时的默认答案与失败值) |

### S-2 本契约不拥有什么

**窄口**：下表左列是真的会话契约要有、而**本版不收**的东西。

| 不拥有 | 归谁 |
|---|---|
| **写下这一映射**：会话创建时捕获当前租户身份、记给这个会话 | **本版不收**：会话那一程（PF-015；[G-1](#十已知缺口)、[G-2](#十已知缺口)） |
| **会话存不存在、是否归档、会话的其余事实**（工作区、运行模式、父会话……） | 会话那一程；注册表求值输入里「会话事实」之外的几片归据点读面（据点装配 C-3） |
| **「此刻以哪个租户身份行事」**：登录状态上的那项选择 | `capability.organization-governance` 的查询面（`data.identity-values/v1#S-28` 第一句）。本契约答的是**会话创建那一刻捕获下来的值**，不是此刻的选择 |
| **这个租户身份是否仍然有效**：成员资格、租户存续 | 租户领域的契约；本契约不核实，只如实交回记下的那一个 |
| **调用方有没有权知道这个会话归谁** | 装配（[S-10](#s-10-装配给的保证-vs-协议须给的保证)） |
| **执行环境**（派发器句柄解析的另一样） | `capability.execution-environments`（同批另一位起草）；本契约只答租户那一样 |

### S-3 本契约明确不承诺什么

- **不铸、不改任何身份值**：会话标识与租户身份都由别处给。
- **不回答「没有租户」**：一个会话要么答出它的租户身份，要么是一个具名失败；没有「这个会话不属于任何租户」这个答案（[S-7](#s-7-缺席时的默认答案与失败值)）。
- **不分辨「会话不存在」与「会话在、但它的租户没记在这里」**：两者同一个值 `sessionNotFound`（[S-7](#s-7-缺席时的默认答案与失败值)）。
- **不附 Schema**。操作的输入与返回用散文写含义；线上形状归把它送过进程边界的那份 composition（[规格容器的规矩](../../../README.md#准入门槛与停止条件)）。

| 坐标 | 被消费的条款 | 用在哪 |

| 同上 | [`#S-28`](../../../data/identity-values/v1/contract.md#s-28-当前租户身份在创建那一刻捕获) 当前租户身份在创建那一刻捕获 | [S-5](#s-5-会话持有的租户身份)、[S-6](#s-6-答案不变)：会话持有的就是这个捕获值，此后选择改了也不跟着变 |

## 二、概念、身份与必要状态

**身份值一律引用 `data.identity-values` v1，会话的指认是 `SessionRef`（`data.messages/v1#S-24`），不复制定义。**

### S-5 会话持有的租户身份

**每个会话恰持有一个租户身份：会话创建那一刻捕获的[当前租户身份](../../../../ubiquitous_language/terms/subjects-and-ownership.md#ul-current-tenant-identity--当前租户身份--current-tenant-identity)**（[PF-015 §6.12](../../../../product/PF-015-session-lifecycle-and-ownership/design.md#612-会话持有创建那一刻的租户身份)；`data.identity-values/v1#S-28`）。

1. **恰一个**：一个会话不会持有两个租户身份，也不会一个都不持有。
2. **创建时定下、此后不变**：创建之后登录状态上的选择改成别的，已经创建的会话一概不跟着变（`data.identity-values/v1#S-28` 第三句）；会话睡醒之后还是原来那个（[PF-015 §6.11](../../../../product/PF-015-session-lifecycle-and-ownership/design.md#611-会话睡醒之后还是原来那个)）。
3. **它是这个会话里一切租户归属的来源**：会话日志条目壳上的租户身份（`capability.session-log/v1#S-12`）、执行记录上的租户、凭据取哪一把、账算到谁头上、「谁可以用」按谁求值——**写入方与判定方都从这里取，不从调用方、进程上下文或「当前登录的那个人此刻选的」取**。
4. **本契约只答，不记**：这一映射由会话创建写下，那一写本版不收（[S-2](#s-2-本契约不拥有什么)）。

### S-6 答案不变

**对同一个会话，本契约答出的租户身份永远是同一个。**

1. 某一次读答出 `T`，此后任何一次对同一个会话的读，要么答 `T`，要么是 `unavailable`；**不会答出另一个租户身份，也不会改答 `sessionNotFound`**（本版没有删除会话这回事，[S-2](#s-2-本契约不拥有什么)）。
2. 一个会话此刻答 `sessionNotFound`，稍后可能答出它的租户身份——会话那一侧在两次读之间写下了它；**反过来不会**。
3. 因此**消费者可以把答出的值留着用**：同一个会话不必每次重读才正确。要不要重读是消费者自己的事（例如模型请求运行时每次发出现读，那是它的选择，不是本契约的要求）。

## 三、贯穿全部操作的规矩

### S-7 缺席时的默认答案与失败值

**一律拒绝或明确失败，不放行、不回退、不填初值。**三类分开：

| 情形 | 结果 | 为什么不合并 |
|---|---|---|
| 判定得出「这里没有这个会话的记录」 | **`sessionNotFound`** | 读得到、确实没有：一个结论。**不是「没有租户」**——消费者不得把它读成「不属于任何租户」而放行 |
| 判定**做不出来**：这一映射此刻读不到 | **`unavailable`** | 没有结论；按当时状态重试可能不同（`data.identity-values/v1#S-19`） |
| 输入**根本不构成这个请求** | **`invalidInput`**，在判定之前 | 表示层校验不是判定（`data.identity-values/v1#S-33`） |

- **会话没有默认值**：缺席即 `invalidInput`，**不从进程上下文、当前登录状态或「上一个会话」补**（`data.identity-values/v1#S-17`、`#S-18`）。
- **答不出时消费者不得自己补一个**：不以「没有租户」、调用方的租户、别的会话的租户顶上。消费者各自怎样收场在它们的契约里（执行运行时的 `dependencyUnavailable`、派发器的解析失败、模型请求运行时的 `unavailable`），**本契约只保证它们拿到的不是一个编出来的值**。

**失败值总表**（本契约的全部失败值，含义以这里为准）：

| 值 | 含义 | 类 |
|---|---|---|
| `invalidInput` | 输入不构成这个请求（上表第三行）；[S-8](#s-8-holdingtenant读会话持有的租户身份) ⑥ 列出具体情形 | 表示层 |
| `sessionNotFound` | 这一映射里没有这个会话：会话不存在，或它的租户身份没记在这里——**本契约分不出两者，同一个值**。与 `capability.asset-registry` v1 的同名值同为「定位」一类，各自说的是各自那份记录里没有这个会话 | 定位 |
| `unavailable` | 读不到（上表第二行）。**与已接受的 `capability.organization-governance` v1 同名同义** | 失败 |

**谁调用**（本契约的面是据点进程内的能力间面，**不直接暴露给人或 agent**）：

| 调用方 | 什么时候 |
|---|---|
| 工具执行运行时 | 每次 `submit` |
| 拓展点派发 | 拓展件解析执行环境句柄、要租户那一样时 |
| 据点读面（会话资产注册表的求值输入） | 收齐「会话事实」那一片时 |
| 模型请求运行时 | 每次要发起租户时（取凭据、记账） |
| 会话日志的写入方 | 给条目壳填租户身份时（`capability.session-log/v1#S-12` 第 3 条） |

## 四、操作

每个操作写全九件事：①输入 · ②前置与授权 · ③结构性禁止 · ④提交点与原子性 · ⑤成功返回 · ⑥失败集合（闭合枚举，按判定次序）· ⑦幂等与重复 · ⑧缺席时的默认答案 · ⑨事件。

### S-8 holdingTenant：读会话持有的租户身份

`holdingTenant(session) → { tenant }`

| # | 内容 |
|---|---|
| ① | `session`（`SessionRef`） |
| ② | 调用方是装配放进来的读方之一（[S-7](#s-7-缺席时的默认答案与失败值)「谁调用」），身份由装配核实（[S-10](#s-10-装配给的保证-vs-协议须给的保证)） |
| ③ | 无 |
| ④ | 只读，无提交 |
| ⑤ | `tenant`：这个会话持有的租户身份（`TenantId`，[S-5](#s-5-会话持有的租户身份)） |
| ⑥ | `invalidInput`（`session` 缺席或不合 `SessionRef`）→ `sessionNotFound`；读不到 ⇒ `unavailable` |
| ⑦ | 只读，天然可重复；同一个会话的答案不变（[S-6](#s-6-答案不变)） |
| ⑧ | 读不到 ⇒ `unavailable`；**不答「没有租户」，不交回任何默认租户** |
| ⑨ | 不发 |

## 七、装配给的保证 vs 协议须给的保证

### S-10 装配给的保证 vs 协议须给的保证

[SYS-DEPLOY](../../../../foundation/cross-system-constraints/requirements.md#sys-deploy)：**左列单机时由装配顺带给出，跨进程之后不会自动成立；右列是本契约已经记下的待兑现项（[G-4](#十已知缺口)）。**

| 保证 | 本版（单机）由谁给 | 跨进程之后谁重新兑现 | 做不到会怎样 |
|---|---|---|---|
| **调用方身份已核实**（全部操作） | **装配给**：本契约的面是据点进程内的能力间面；够得着它的只有装配放进来的读方 | **协议给**：调用携带调用方身份，在接收边界重新验证（`data.identity-values/v1#S-30`） | 拿到一个会话指认就能问出它归哪个租户——**本契约的面因此不得直接暴露成终端 API** |
| **答案不变**（[S-6](#s-6-答案不变)） | **装配给**：据点上一份提供者、一份存储 | **协议给**：副本上的读不得答出与主本不同的租户身份；读不到主本就 `unavailable`，不拿一份没同步到的副本答 `sessionNotFound` | 同一个会话在两个节点上被当成两个租户的：条目壳、凭据、账各挂一半 |
| **消费者拿到的租户身份就是这个会话的** | **装配给**：同一进程里按 `SessionRef` 一次读 | **协议给**：答复带着它答的是哪个会话，接收边界核对，不单独传一个租户身份再在对端配会话 | 一个会话的执行挂到另一个租户名下 |

## 八、交接、缺席与恢复

### S-11 提供者撤除、换代与重启

- **本契约的一切事实都在提供者的存储里**，提供者实例里没有「只有它知道」的东西；**换一个实例、重启，任何一次读的答案不变**（[S-6](#s-6-答案不变)）。
- **撤除时在途的读**：调用方可能等不到回答，按 `unavailable` 处置；本契约不交接任何活状态。
- **提供者缺席**（装配里没有它）：消费者按各自契约「读面缺席」那一行收场——那不是本契约的一个返回值，但口径与 `unavailable` 同：**不给默认**。

## 九、规范表达与验证义务

### S-12 本版选用哪些形式工件

**不建形式模型。**本版只有一个读，它的性质是「答不出不编」与「答案不变」：前者是单次调用上的一个比较，没有交错；后者的唯一威胁是那一次写（本版不收）与存储持久，没有两个写入者在本契约的面上相遇。**证据是下面三条规范场景与一次故障注入**；会话那一程把写收进来时，若出现并发创建或迁移，再按性质决定要不要行为模型。

本版不附 JSON Schema。执行状态在[验证入口](../verification.md)，**不写进本版本目录**。

### 规范场景

**每一条都要真跑**。操作层面的实例在 [`examples.md`](examples.md)。

#### S-13 答出的就是记下的那一个，而且不变

会话 `s1` 的映射记着 `T1`。连读两次；重启提供者再读一次。**必须观察到**：三次都是 `T1`。

#### S-14 没有记录不是没有租户

读一个从没记过的会话 `s9`。**必须观察到**：`sessionNotFound`；**没有一次交回任何租户身份**。随后会话那一侧（测试里由种子代它）记下 `s9 → T2`，再读：`T2`。

#### S-15 读不到就是读不到

让映射的存储读不到（故障注入），读 `s1` 与从没记过的 `s9`。**必须观察到**：两次都是 `unavailable`——提供者手里留着 `s1` 的答案时交回 `T1` 也合规（[S-6](#s-6-答案不变) 让它可以留）；**绝不是 `sessionNotFound`，也绝不是别的租户身份**。

## 十一、提供者映射

**本版的最小提供者**（候选；节点由主线另立，本契约不设计它）：**本机 JSON 文件或 sqlite 表（经 `core/storage`）**，一张（会话 → 租户身份）的映射，据点根作用域一份，服务键候选 `sessionTenancy`。它要兑现 S-5～S-8：答出之后不变、重启不丢、答不出不编、`sessionNotFound` 与 `unavailable` 分开。**表里的行由谁写不在本契约**（[G-2](#十已知缺口)）：验收装配由测试种子写；产品装配在会话那一程之前没有写入方。
它**取代**验收装配里「会话持有租户读面」那个替身（[据点装配验收替身表](../../../../realization/apps/cli/design.md#验收装配)）；**真提供者**归会话那一程（[G-1](#十已知缺口)）。
