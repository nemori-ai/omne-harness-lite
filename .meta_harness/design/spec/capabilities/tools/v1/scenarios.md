# 工具定义、调用、结果与控制场景

本表是规范场景，不是已执行的实现测试。每行给出触发与期望的事实序列（事实 kind 按
TL-15（legacy source: `contract.md`） 的转移表）、ToolCall.tla（legacy source: `ToolCall.tla`） 里对应的动作与性质，以及模型
不覆盖、须由提供者验收兑现的部分。编号 TS-xx，与 run-driver v3（legacy source: `../../run-driver/v3/contract.md`）
的 S-xx 场景互不重号。模型的抽象范围与刻意未覆盖项见验证范围（legacy source: `../verification.md`）。

| 编号 | 场景 | 路径与可观察结果 | 模型动作与性质 | 模型外验收 |
|---|---|---|---|---|
| TS-01 | 前台调用正常结算并接续 | `tools.call.proposed`（同批 `run.calls.proposed` 与等待登记）→ `tools.call.admitted`（授权 allow、预算预留、附着登记同批）→ `execution.attempt.accepted` → `execution.attempt.dispatch_intent` → `execution.attempt.terminal` + `tools.call.settled{succeeded}` + `inbound.arrival.accepted{call_settlement}` 同批 → Run waiting → `inbound.arrival.classified{continuation}` + 登记注销同批 → 下一 Step 的 tool_result | Propose / GateAllow(foreground) / Start / Dispatch / Terminal / Adjudicate / Consume；SettledDelivered、ConsumedOnce | 结果按输出 Schema 校验、content 引用已耐久（TL-19（legacy source: `contract.md`））；费用随 attempt 记 |
| TS-02 | 门 = ask，人批准后执行 | `tools.call.waiting` + `hd.request.created{system_approval}` 同批 → 批准 → `run.approval.consumed` + `tools.call.admitted` 同批 → 同 TS-01 | GateAsk / Approve；AnswerOnce | 决定只被这次准入消费，新 attempt 不能重用（TL-08（legacy source: `contract.md`）、HD-06（legacy source: `../../human-decisions/v2/contract.md`）） |

| TS-07 | 转后台失败保持前台 | `tools.relation.detach_requested` → owner 拒绝 → 关系回 foreground 并具名报告；owner 崩溃期间的请求同样回退 | DetachFail / OwnerRecover 的关系回退 | 单次失败原因具名；复合打断下失败改为停止（TL-11（legacy source: `contract.md`）、RN-04（legacy source: `../../run/v2/contract.md`）） |
