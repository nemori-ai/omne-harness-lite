# RT4 的精确消费者传播

本候选从 D-076 已接受 RT3/SL2 演进到 RT4/SL3；SL3 由 D-083 接受。此处说明采用者须做的变化，不将新规范、已采用投影与实现符合性合成一个状态。实际采用仍查各入口与 registry，推荐版本不自动升级消费者。

## 必须保持的停止与切换顺序

1. 先完成 RT4、提供者与全部实际写方的精确采用；检查共同业务键和读取键、消息/响应全批认回、显式 condition、owner 策略与失败传播。缺任何一项，不在同一日志根混用三参数和四参数消费面。
2. 关闭旧业务准入，实际停止旧网络读取、门回调、追加与潜在 unfenced 结算者；不能仅以取消、函数 outcome、运行时撤除或新 fence 认作停止。已有 durable 锚点/意图和未知责任保留；不补假响应。
3. 日志 owner 按被采用的生命周期协议关闭准入、排空旧任务、完成旧物理写者停止与资源/所有权交接，由新 owner 独占恢复真实日志。写入不可信时旧确认尾不能证明缺席；无法确认恢复条件保持 unavailable。
4. 在原 S-33 新尝试/重新承载时机权威读回；带 Run 时另确认共同日志新尝试的有效 fence。所有历史响应按稳定身份认回原批；未提交批才按新合法前缀重构 late。无 Run 保留独占重新承载与 late 缺席。
5. 所有应对账项收口后才按原守卫允许新的推进。接线变更不创造模型重发许可，不加载新模型版本重写旧绑定，也不把历史 JSON 记录升级成新业务值。

## 证据和停止边界

规范新有限模型只证明其精确输入及已执行范围内的性质；[验证入口](../verification.md#v4-结算与未知提交)拥有复跑方法、覆盖和限制，单次运行与修订过程放本工作树 `tmp/<task>/`；旧结果不自动覆盖新正文。真实文件比较/持久、合法授权、共同 codec、生产 Run 认法、实际停止、TransportFailure 头表示仍分别由 G-28～G-31 和既有 owner 承担。切换/放手/回复处置的回执未知不保证持久状态未变：消费者按 S-6/S-9/S-27/S-32/S-49 区分本实例待确认与权威记录；不把读取当前选中当作本次命令恰一次认回，不自动重放未知切换。收口/重新承载是入口，owner 保留也不保证之后获调度；只有 S-71 前提成立且结算/恢复被实际调用、执行到许可预算内的可得提交机会，才能依赖条件进展。模型 StopOld 只是明确的环境动作；无饥饿不在全尾争用承诺内。若合法前缀、共同日志或实际提交机会不能成立，沿 D-081 改票条件返回主线，不删除不变量以放行。
