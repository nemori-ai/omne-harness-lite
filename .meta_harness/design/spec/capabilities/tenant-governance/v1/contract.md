# 租户治理契约 v1

- 契约坐标：`omne-harness-lite-design-2026-09-15` · `capability.tenant-governance` · `v1`
- 需求及边界依据：[SYS-TENANT](../../../../requirements/system/constraints/requirements.md#sys-tenant)、
  [PF-001](../../../../requirements/product/PF-001-tenant-organization-context/requirements.md)、
  [PF-026.C1/C4](../../../../requirements/product/PF-026-account-journey-and-isolation/requirements.md)
- 精确依赖：无。成员关系只消费账号身份的**值**，不要求账号能力在线
- 状态：candidate

## 目的、消费者与责任

本能力拥有三件事：**租户身份**、**账号与租户的成员关系**、**成员资格判定**。

它同时拥有一件容易被误放的东西：**作用域层次的结构定义**（见 S-12）——
即系统中有哪些身份层、各层如何标识。设置、权限、工具组装三方都按这个层次求值，
若各自定义一套，同一字段在三处会得出不同结果而无人能解释。

本能力**不拥有**：账号身份（归[账号身份](../../account-identity/v1/contract.md)）、
角色矩阵与权限规则（PF-010）、设置字段目录与取值（PF-006）、额度与账目（PF-019）、
技能与工具的发现装载（PF-014）。

**本能力不是访问控制的执行点。**它回答「这个账号在这个租户有没有成员资格」，
由各对象 owner 在自己的访问点上调用并据此拒绝。见 S-6 的前提。

## 概念、身份与必要状态

| 概念 | 含义 | 权威与保留范围 |
|---|---|---|
| 租户 | 一个组织范围 | 本能力拥有；持久 |
| 个人租户 | 与恰好一个账号一一对应的租户 | 本能力拥有；由注册组合创建 |
| 组织租户 | 可容纳多个成员的租户 | 本能力拥有；产生方式见 G-1 |
| 成员关系 | （租户，账号）的归属事实 | 本能力拥有；独立于两端的生命周期 |
| 当前组织上下文 | 一次协作所处的租户 | **本能力只定义其取值域与切换的后果**，「如何确定与改变」见 G-3 |
| 作用域层次 | 系统中的身份层及其标识方式 | 本能力拥有结构；**层间次序见 G-2** |

## 性质与前提

| 性质 | 要求来源与观察范围 | 保护边界 | 依赖保证或环境前提 |
|---|---|---|---|
| **S-1**（不变量）每个已激活账号恰好归属一个个人租户，且该个人租户只属于这一个账号 | PF-026.C1 | 个人租户创建；成员关系变更 | 存储唯一性约束。**适用范围限于账号存续期**，终止语义见账号契约 G-4 |
| **S-2**（不变量）任一成员关系恒可分解为（一个已存在的租户，一个已存在的账号） | SYS-TENANT 双层结构 | 成员关系写入 | 存储引用完整性 |
| **S-3**（不变量）账号身份不隶属于任何单一租户；它先于租户存在且不因租户变化而变化 | SYS-TENANT「不被强行归为单一租户」 | 数据形状 | **结构性条款**：账号身份的表达不含租户字段 |
| **S-4**（不变量）任一受租户所有权约束的对象恰有一个归属租户 | SYS-TENANT | 各对象 owner 的写入路径 | 本能力提供归属语义定义；执行在各 owner |
| **S-5**（不变量）每个组织租户在任何时刻至少有一位有效的最高管理者 | PF-010 管理操作表退出边界 | 成员移除与降权的前置条件 | 角色定义归 PF-010（其正文自记待定义） |
| **S-6**（安全）在没有明确所有权或成员资格依据时，跨租户访问绝不成功 | SYS-TENANT「默认拒绝」 | 各对象 owner 的访问点 | **前提**：所有租户范围对象的访问经由带租户参数的接口，且该参数**无默认值**。前提失效时责任在该对象 owner |
| **S-7**（安全）切换当前组织上下文绝不改写已验证的账号身份 | PF-026.C4 | 切换操作 | 无 |
| **S-8**（安全）切换账号绝不沿用另一账号的成员资格 | PF-026.C4 | 成员资格判定 | 判定只以账号身份为输入，不含任何缓存键回退 |
| **S-9**（安全）账号级事实绝不因切换组织被复制成租户级事实，反之亦然 | PF-026.C4；PF-010.C9 | 各层事实的写入路径 | **前提**：各层事实沿**数据层次**求值，不沿装配链下发。见 S-12 的说明 |
| **S-10**（安全）两个不同账号的个人范围在数据、设置、权限、额度四维度上互不相交 | PF-026.C3 | 各维度 owner 的访问点 | 隔离判据由本能力给出，执行在各 owner |
| **S-11**（安全）组织上下文造成的可观察差异绝不超出「设置」「权限」「可用技能或工具」三项 | PF-001 收窄裁决 | 组织上下文的参与方式 | **前提**：组织上下文只以**显式参数**参与求值，不作为可见性维度。见下方说明 |
| **S-12**（不变量）作用域层次只有一个定义；同一字段在任一（账号，组织上下文）下的求值结果唯一 | PF-001 求值方式 | 层次结构的拥有权 | **层间次序未确认，见 G-2** |

### S-11 的前提为什么必须写进契约

若把租户做成服务可见性的维度（为每个租户提供一份独立的服务实例），
会立刻产生**第四类**随组织上下文而变的差异——实例本身不同——PF-001 的收窄裁决当场失守。

同时该做法也不提供隔离：可见性维度隔离的是实例，不是数据；
一个实例内部持有跨租户的数据句柄，隔离多少次都无效。

因此本契约把它写成前提：**租户身份是显式数据参数，不是作用域维度。**
这与 SYS-TENANT 的原文一致——「受租户所有权约束的关键对象和跨边界操作**显式携带**租户身份」。

同理，**事件的接收范围不得被当作租户隔离手段**。租户判定只有一个正当位置：
访问点上的显式成员资格校验。

## 操作与可观察事实

### 创建个人租户

- **输入与授权**：账号身份。**由**[注册组合](../../../compositions/account-registration/v1/contract.md)**调用**。
- **前置**：该账号尚无个人租户（S-1）。
- **状态变化与提交**：写入租户记录与成员关系，单次提交。
- **返回与失败**：失败集合 = { 该账号已有个人租户, 账号身份无效, 存储不可用 }。
- **幂等**：以账号身份为幂等边界；重复调用返回既有个人租户，不产生第二个。

### 创建组织租户

- **输入与授权**：发起者的账号身份、租户名。
- **前置**：**准入判定通过**。本契约把准入定义为一个**显式判定点**，
  其策略未经需求方确认（G-1）；在裁决前，判定点没有默认放行实现。
- **状态变化与提交**：写入租户记录，并将发起者写为首位最高管理者（S-5 要求组织不得无管理者）。
  两者在单次提交内完成。
- **返回与失败**：失败集合 = { 准入判定拒绝, 发起者身份无效, 存储不可用 }。

### 查询成员资格

- **输入**：账号身份、目标租户。
- **返回**：成员资格存在（含其角色标识）或不存在。
- **缺席时的默认答案**：**存储不可用或查询失败时返回「不存在」，调用方据此拒绝。**
  **不得返回空集合并让调用方自行解释**——空集合会被顺手读成「无限制」，
  使 S-6 在故障期间失守。这是本契约最容易被实现方写错的一条。

### 加入成员

- **输入与授权**：目标租户、被加入的账号、角色。发起者须在该租户有管理资格。
- **前置**：目标租户是组织租户（个人租户的成员规则见 G-4）；被加入账号已激活。
- **状态变化与提交**：写入成员关系，单次提交。
- **失败集合**：{ 发起者无管理资格, 目标不是组织租户, 账号不存在或未激活, 已是成员, 存储不可用 }。
- **准入策略**：谁可发起属于 G-1 的范围。
- **事件**：发布「成员关系已变更」通知。

### 移除成员 / 降低角色

- **前置**：发起者有管理资格；**且操作后该组织仍有至少一位有效最高管理者（S-5）**。
- **状态变化与提交**：删除或修改成员关系，单次提交。
- **失败集合**：{ 发起者无管理资格, **操作将使组织失去最后一位最高管理者**, 成员关系不存在, 存储不可用 }。
- **部分效果**：无。前置不满足时不产生任何变化。

### 切换当前组织上下文

- **输入与授权**：已验证的账号身份、目标租户。
- **前置**：该账号在目标租户有有效成员资格。
- **后置**：后续协作以目标租户为组织上下文。**账号身份不变（S-7）**；
  **不复制任何账号级事实到租户级，也不把租户级事实带出（S-9）**。
- **失败集合**：{ 无成员资格, 目标租户不存在 }。
- **本契约不定义切换由谁在什么时机发起**，见 G-3。

### 求取作用域层次

- **输入**：账号身份、当前组织上下文。
- **返回**：本次求值适用的层序列，每层带其标识。
- **本操作不求值任何字段**：它只给出层次，字段取值由设置 owner（PF-006）、
  权限 owner（PF-010）、工具组装（PF-014）各自按此层次求值。
- **层间次序**：见 G-2。**本版返回层的集合与标识，不规定账号层与租户层的相对次序。**

## 交接、缺席与恢复

**本能力不可用时，所有依赖成员资格的访问必须拒绝。**
这是 SYS-TENANT「默认拒绝」的直接推论，也是本契约与多数能力最重要的差别：
多数能力不可用时降级为不提供服务，本能力不可用时必须**主动拒绝**。

租户与成员关系是持久事实，不随本能力装卸消失；本能力恢复后无需重建。

**撤除不等于外部效应回滚**：已生效的成员变更通知不因本能力撤除而收回。

## 装配给的保证与协议给的保证

| 保证 | 当前由谁兑现 | 分布式后 |
|---|---|---|
| S-1 个人租户唯一 | 单机存储唯一性约束 | **须由协议重新兑现**：跨节点创建需一致性保证 |
| S-5 至少一位最高管理者 | 单次提交内的前置检查 | **须由协议重新兑现**：两个节点并发移除不同管理者可能同时通过各自前置检查 |
| S-6 默认拒绝 | 查询即时可见 | **须由协议重新兑现**：成员关系撤销的传播窗口内旧节点可能仍放行 |
| S-3、S-11 结构性 | 数据形状与参数约定 | 不变 |

**S-5 在分布式下的失效方式值得单独记住**：它是一条跨行的约束，
单机靠一次提交内的检查保证，跨节点则需要真正的协调。这条不能靠「以后加锁」含混带过。

## 规范表达与验证义务

| 性质 | 表达形式 | 证据义务 |
|---|---|---|
| S-1、S-2、S-4 | JSON Schema + 存储约束 | 结构检查 |
| S-3、S-11 | 结构性审查 | 静态检查：账号身份表达不含租户字段；租户身份不作为可见性维度出现 |
| S-5 | 行为模型 | 并发移除场景的模型检查 |
| S-6、S-9、S-10 | 规范场景 | 越界尝试演练：对每类受租户约束对象，任一次越界成功即失败 |
| S-8 | 规范场景 | 账号 A↔B、租户 O1↔O2 的四种切换交叉演练 |

## 已知缺口

| 编号 | 缺口 | 谁能闭合 | 在闭合前 |
|---|---|---|---|
| **G-1** | **组织租户的产生与成员加入的准入策略**：谁有资格创建组织租户、谁能加人。三个需求包都不拥有 | 需求方 | 契约保留显式判定点，**无默认放行实现**；不猜一个默认策略 |
| **G-2** | **账号层与租户层在作用域层次中的相对次序**：谁覆盖谁有相反的产品后果 | 需求方与 PF-006 owner | 本版给出层的集合与标识，**不规定次序**。次序确定后填入，不改契约形状 |
| **G-3** | 当前组织上下文**如何确定与改变**（由谁、在什么时机发起切换） | 需求方（PF-001 自记待澄清） | 本契约只定义切换的前置与后果 |
| **G-4** | 个人租户的成员关系规则：他人能否成为某账号个人租户的成员；账号能否退出自己的个人租户 | 需求方 | 加入成员操作限定为组织租户 |
| **G-5** | S-1 的适用范围是注册时刻还是账号存续期恒真 | 需求方 | 本版按存续期表述，但依赖账号终止语义未定（账号契约 G-4） |
