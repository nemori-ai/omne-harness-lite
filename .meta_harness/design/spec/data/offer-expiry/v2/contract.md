# data.offer-expiry v2

- 坐标：`(omne-harness-lite-design-2026-09-15, data.offer-expiry, 2)`；accepted，按 [D-040](../../../../record/decisions/governance-identity-offer-contracts/decision.md) 采用并冻结，v1 不改。
- 来源：[PF-001 rev18](../../../../product/PF-001-identity-scope-and-agent-constraints/design.md#接收方可以明确拒绝待处理邀约) 的邀请/隶属接收方拒绝，及既有两种邀约过期规则；与 [v1](../v1/contract.md) 的差异为拒绝终结值和相应判定，时限相等处的严格性不变。
- 精确依赖：data.identity-values v1 S-1/S-3，仅取 AccountId/OrganizationId，不复制身份定义。时间的线上形状由本 Schema 的 Instant 复用，不改变 v1 的表示。
- 本版不消费能力/组合契约；由治理下一版采用后兑现操作授权与共同提交。资产消费者不自动升级，未为复制/分享新增拒绝动作。

### S-1 本契约拥有什么

拥有邀约的不可接受条件：不可变发出/到期时间、持久终结记录和派生状态、同一时点的求值规则。不拥有谁能接受/拒绝/撤回、这些动作建立什么业务事实、邀约身份或路由。

### S-2 四类消费者

前版列出的四类为组织邀请、隶属请求、待确认复制通知、待确认分享邀请。当前只有前两类拟采用 v2；资产两类保持其原采用关系，不能从共享枚举多出 declined 推导产品已经允许其拒绝。实际 capability/Schema 必须钉精确版本，不随推荐自动升级。

### S-3 本契约明确不承诺什么

不铸邀约标识、不统一四类邀约身份；不拥有业务授权或可靠送达；不规定发起人/接收人角色；不提供恢复为 pending、续期或宽限期；不为已经成立的成员/隶属或资产授予增加期限。需要新邀约时由 owner 重新产生一份。

### S-4 OfferTiming

OfferTiming 恰由 issuedAt 与 expiresAt 两个同源时间点构成，expiresAt 必须严格晚于 issuedAt。它是结构相等的值，不是身份；具体对象/引用/终结事实由能力记录拥有。

### S-5 时刻在发出的同一提交内定死

两个时间点在发出邀约的同一次提交确定，之后不改。发起者指定时长或默认时长只用于这一次计算，不能留下可在后来改动并重算本份截止的来源。

### S-6 指向的对象

每份邀约显式携带恰一个用于过期判定的对象引用。组织邀请只判发起组织，被邀请账号不参与这个过期条件；隶属请求只判接收方组织，不把发起方加入。复制通知/分享邀请沿其原版只判所指资产。对象不存在引发过期的引用范围不能由数据消费者自行扩大。身份值不得回收后指向另一对象，使旧邀约复活。资产引用范围留给其原能力，不由本版补决定。

### S-7 派生状态

| 状态 | 含义 | 持久还是派生 |
|---|---|---|
| pending | 未终结且未过期 | 读时派生 |
| accepted | 已被接受 | 接受的共同提交写下 |
| withdrawn | 已被发起方撤回 | 撤回的共同提交写下 |
| declined | 已被接收方明确拒绝 | 拒绝的共同提交写下 |
| expired | 未终结且已过期 | 读时派生，不作为终结字段保存 |

一个对象至多一份终结记录；接受、撤回、拒绝的竞争只能有一个先成立的结果。重复同一动作是否返回幂等成功由能力定义，但不得新增效果或改写另一种终结。没有任何终结可回到 pending。

### S-8 判定式

先读终结记录，存在则返回其 accepted/withdrawn/declined，不再因时间或对象消失改成 expired。没有终结时，`now > expiresAt` 或 owner 指定的对象已不存在则 expired，否则 pending。沿 v1 的严格不等号：恰等于 expiresAt 仍未因时间过期；不要借登录期限的 `>=` 判据替代邀约规则。

必要时间或存在性事实读不到则 unavailable，不返回任何状态。已确定终结无需再读时钟。未终结时，时间源和指定对象存在性都是必要读数；任一不可用则 unavailable，即使另一项单独看来足以过期也不能短路成 expired。这保留 v1 的失败语义。

### S-9 读时派生，且派生状态不回退

所有返回状态的单个/列表读面都在有效一致边界求 S-8；pending/expired 不由后台任务维护。成立的 expired 不可后来变 pending；终结状态不互换。此性质依赖不可倒退时间、引用身份不复用，以及终结只能在同提交重判 pending 后写入。列表任一必要读数不可用不能被当少一项或空列表。

### S-10 接受操作在同一提交内重新求值

接受时必须在与业务效果和终结记录相同的原子边界重判 S-8；只有 pending 能成立。之前读取、界面按钮或旧缓存不是接受依据。接受失败不能留下半份成员/隶属或终结；提交结果未知由消费组合如实收场。

### S-11 到期之后不可接受

S-8 已为 expired 则不能写 accepted 或产生接受效果。先在 pending 时完成的接受不因随后到期撤销关系；关系解除归对应能力。

### S-12 过期与撤回收场相同

expired、withdrawn、declined 都不能再被接受且不产生接受效果；来路不同，读面保留真实原因。accepted 也不能再次产生接受效果。不得用接收方拒绝冒充发起方撤回，也不得把拒绝已接受邀约当成业务关系解除。

### S-13 接受路径上，四种来路给同一个拒绝值

接受操作对 expired/withdrawn/declined/accepted 统一给能力定义的同一个不可接受结果；数据契约不命名能力失败值。此处不要求已授权状态读面隐藏真实终结原因，也不省略能力先行授权。

### S-14 offer_ttl

各类独立配置正的默认时长，发出时可指定本份正时长；无指定取该类默认。发起者指定零、负或非法时长时，本次调用具名拒绝且不写，不改成默认；部署默认值配成非正或非法时，配置加载方必须使提供者启动失败、不进入可服务状态，不能留到每次调用再拒绝。必要默认在运行时取不到或时间计算溢出则不可用，不产生无期限邀约。时长折入 expiresAt，不能跨份借用设置。具体数值与表示由消费能力/装配给，不在数据契约补新默认。

### S-15 改参数不动已发出的

默认配置变更只影响之后发出的新份，不重算已有 expiresAt；发出时指定的时长也不可事后覆盖。重启/升级/恢复不为原份重新起算期限。

### S-16 同一时间源

issuedAt、expiresAt 与求值 now 在同一个不可倒退的时间轴上比较。必要时钟不可用，不取客户端或另一个墙钟猜测。接受、撤回、拒绝及返回派生状态的读面均受此约束；发出也须可靠时间，不产生不完整 timing。

### S-17 装配给的保证 vs 协议须给的保证

同一一致性域须给时间、对象存在性、终结和业务效果的必要同提交保证；跨进程后不能用无界传播窗口替代。消费者明确每条边如何兑现，保证缺席则不开放相关操作。记录终结后的故障耐久性由采用目标约束，不能从状态 Schema 推断数据库实现已经满足。

### S-18 后台清理不担正确性

停掉清理不改变任何状态或授权结果。清理只能移走允许清理的数据，不能是到期生效的唯一触发；未清理的 expired 也不可接受。数据契约不承诺清理频率或可靠通知。

### S-19 规则与读面归属

过期谓词在本契约只定义一次；对象存在性由对象 owner 提供，邀约 owner 依 S-6 的精确清单携带引用，并在必要的一致边界读取。不能根据缓存缺项或其他 owner 暂不可用自行认定对象已消失。

### S-20 不可用不等于不存在

存在性读不到不是不存在，不能因此永久结束邀约。必要依赖失败给不可用；具名拒绝与未知提交不能混作“确定什么也没发生”。终结写入的结果未确认时不得自动用另一终结动作覆盖，先按消费组合可用读面核实。

### S-21 本版的触发源

时间推进是两类治理邀约实际的过期触发；已终结无需触发。当前团队组织没有终结路径、个人组织不参与这两类邀约，因此“所指组织消失”的分支在当前装配没有合法产品动作触发，但规则保留；未来删除能力必须兑现同源读与身份不复用。资产触发不随本版改变。

### S-22 Schema 的范围

[Schema](offer-expiry.schema.json) 复用 Instant，定义 OfferTiming、五值 OfferState、三值 SettledState。终结只能保存 accepted/withdrawn/declined；pending/expired 不得作为终结存储。Schema 只核形状，不证明 expiresAt>issuedAt、同源时钟、授权、判定次序或同提交。

## 版本差异与消费者义务

v1 的时间表示、严格过期比较、默认时长与引用规则保留；S-7/8/9/12/13/16/22 扩展拒绝终结，其他文字压缩而不把资产消费者升级。独立规格评审与精确采用已完成；治理下一版与 entry 新版的采用及状态迁移仍待完成。实现与测试不因本版接受而自动升级；有限行为验证由治理终结竞争模型与真实提交测试承接。

### S-23 过期之后接受被拒

发出 expiresAt=t 的邀约，now>t 时接受须被拒且从未产生接受效果；now=t 的时刻不能仅因时间拒绝，其他条件仍需逐项核。必要存在性不可用时保持 unavailable，不因 t 已过而省掉该失败。

### S-24 终结之后接受被拒

同次演练比较四支：过期、撤回后、接收方拒绝后、已接受后再次接受；其接受失败值逐字相同，前三支没有接受效果，第四支没有第二份效果。读面仍能区分四种来路。重复拒绝不能覆盖 accepted/withdrawn/expired，也不能多发业务效果。

### S-25 时长三路及清理无关性

显式T、缺席按类默认、非法指定三路同跑：前两者截止按各自值确定；非法指定被拒且不写，不能偷偷使用默认。另以非法部署默认启动，须加载即失败、不开放服务。停掉清理后，未终结且now>issuedAt+T仍派生expired并拒绝接受；不能用后台任务落盘expired才生效。

### S-26 指向的对象消失即过期

保留前版对象存在性义务：原资产消费者在其原版验证所指资产消失使邀约过期；不为它们自动增加declined。当前治理没有合法组织终结触发，不能造产品没有的删除动作冒充端到端验证；结构/合成夹具仅验证判定式并明确范围。未来加入终结能力时补该真实旅程。
