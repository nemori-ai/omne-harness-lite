## 结果与反例

### 工具定义的校验方法与限制

定义除 Schema 外还检查官方元 schema、顶层 object 带 properties、每参数说明及十七关键字限制；命令 input 的根相对引用、$id 和名字转写长度亦检查。生成与模型投影按 S-7/S-6 重算并按 JSON 值比较，命令表字符串逐字符比较，不按对象键书写次序比较。完整拒绝值及 M 编号、返回值语义和调用场景分别验证；返回值形状与本地重算不替代真实实现。

人工对读只支持规范和实例的自洽。分别判读 Schema、具名拒绝、生成规则、调用行为与真实组合。第5节实现上限反例的 Schema 通过不能判第13行；非法 pattern 的 input_not_schema 反例亦须跑。

## 变化的影响

规范内容归 [v2 contract](v2/contract.md)，本页不维护修复轮次。content-blocks 的五项公共定义、ExecutionOutcome、call_in_result、媒体模态与 Offload.raw 的内联表示变化时同步定义引用及 V-1，裸字符串空串按 S-20 核实际空文本块。

- flat 生成须按命令名码点升序写 command enum、固定格式命令表说明；args 是无 properties 的 object，只要求 command，缺席 args 按 {} 判。模型面不是执行参数校验器，派发须按 commands[c].input 判。嵌套 additionalProperties 按 JSON Schema 原义，只有命令 input 顶层缺席该项按 false；作者显式 true/schema 仍有效。单函数模型面保持作者 schema，不自动补 false。
- 工具名字符集 [A-Za-z0-9_:-]，禁 __、_:、:_，转写后不超128。保留序列保证逆转写唯一，不只是外观规范；ModelToolEntry 三字段和三家包装须实际比对。
- 参数 schema 须先合法于 Draft2020-12，再核 object/properties、所有参数说明和十七关键字。布尔 schema 不能以 JsonSchema 的宽形状通过代替表示校验；非法 schema 的 input_not_schema 与合法却实现编不出的 schema_unsupported 分开，后者排在前十二步之后。
- format 只作注解。定义编译失败不得退成不判参数；一次调用超出判定时限仅令那项 failed{schema_unsupported}，带说明且不影响同批，定义照收，不能误记为定义表示拒绝。返回值与声明不合按执行运行时 S-41 的 result_rejected 验证。工作区定义解析位置归 asset-evaluation 的 G-6。
- stand_in 的形状归本契约 S-6；此刻是否替换件及原因归 asset-registry S-8/S-10，制造归执行运行时。MCP 的 schema_unsupported 原因由桥 S-17 传至注册表原样呈现，普通坏定义无此例外。
- 跨进程演化时，按第七节逐项核定义版本相同、help 读同一版本、每边界重新校验；单机装配不能代替协议符合性。G-5/G-9/G-11/G-16 等缺口按当前 owner 接续，不以旧运行日志或删除日志关闭。

发现语义冲突回当前拥有者及 PF-006/PF-002/PF-005，不在本页改契约；单次范围与反例保留工作树 tmp。
