# 注册组合验证与缺口

| 条款与性质 | 需取得的证据 | 当前结果与受阻消费 |
|---|---|---|
| ACR-01～03 身份/个人范围唯一 | 账号与 Tenant 权威的同键并发、唯一 claim、目标稳定性场景；后续 Tenant 入口规范 | 尚未执行；TG-01 增量未锁，不能实施完整 signup。 |
| ACR-04/05 成功及 unknown 屏障 | 跨 owner TLA+ 行为模型，覆盖 pending、durable、unknown、`committed_blocked`、回执丢失、重启与公平前提；真实存储故障注入 | 模型和提供者验证均未执行；CC-06 受信恢复映射仍待实施，不得宣布注册恢复就绪。 |
| ACR-06 原操作认回 | 双进程并发/崩溃重启的权威回执与稳定目标测试 | 未执行；CLI 唯一 writer 跨进程命令通道未设计。 |
| ACR-07 范围隔离 | 两账号、多组织、账号级与租户级设置/资产、额度及旧缓存的组合测试 | 未执行；PF-006 字段 owner/scope 和本地资源 locator 未定义。 |

规范场景见 [v1/scenarios.md](v1/scenarios.md)。行为模型应区分逻辑排位与耐久确认，检查“绝不双 active personal”“绝不提前 active/成功”，以及在权威最终可用、公平重试和未决操作可核实的前提下最终认回或明确失败。有限 TLC 只能覆盖其建模范围；真实数据库和认证 provider 仍须符合性测试。
