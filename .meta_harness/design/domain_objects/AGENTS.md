# 领域对象区的维护与导航

本文件说明**进到这个目录的人各自该走哪条路**，对所有人成立。
这一区拥有什么、不拥有什么归 [README](README.md)；一条条目长什么样、对账器守哪几条归 [conventions](conventions.md)。

**怎么立条目、怎么判宿主与并入、怎么把缺口登记成待裁、升了 rev 之后怎么逐条复核**——归 `domain-objects` skill。
那份会把你的位置摆成「收账的，不是设计的」，**只有真要在这里落字的人才加载**；
来取输入的人不加载，这里对你们是一份**指得回产品正文的索引**。

## 你来这里做什么

| 情形 | 怎么做 |
|---|---|
| 做架构、规格或实现，要知道「有哪些对象、各自依据在哪」 | 从[领域对象地图](../views/domain-object-map.md)找入口，读 [objects.md](objects.md) 里那一条，**再顺着「依据」去读产品正文**。不加载 skill。条目与正文不一致时信正文，并把不一致报出来 |
| 你要用的对象带着「未裁」，或者它还在 [pending.md](pending.md) | 那是下游开工前要先闭合的缺口。按它写的「谁来裁」去问；**只暂停依赖它的那部分工作，不要自己补一个答案接着往下做** |
| 立条目、改条目、登记或闭合一项待裁、处置对账器的报错 | **先加载 `domain-objects` skill**，再落字 |
| 刚改了某个产品 topic 并升了 rev | 对账器会点一串名。**复核是升 rev 那个人的事**：加载同一份 skill，按它的「逐条复核」做完再交付 |
| 觉得某个东西该算对象、或不该算 | 那不在这里判。对象性是词条的[形态](../ubiquitous_language/conventions.md#形态这个词指的是哪一类东西)，去[统一语言](../ubiquitous_language/AGENTS.md)那边改，这里跟着动 |
| 想把对象按能力、上下文或聚合分组 | 不在这里做，也不往条目里加分组字段——那是系统架构设计的产物，见 [README](README.md#这里不拥有什么) |
| 评审一份对 objects.md 或 pending.md 的改动 | 自己看也先加载同一份 skill——**评的判据要和写的判据是同一套** |

## 答案在哪一份

查**这个对象的骨架**（宿主、身份、生灭、依据、还悬着什么）→ [objects.md](objects.md)；
查**像对象、却还没人裁过的东西** → [pending.md](pending.md)；
查**谁寄宿在谁身上、哪些 topic 还在讲它、依据是不是落在一份还没被接受的草稿 topic 上** → [领域对象地图](../views/domain-object-map.md)，那是**派生物，不手改，也不得引为依据**；
查**某个字段是什么意思** → [conventions](conventions.md)；
查**它到底指什么、为什么是这个形状** → 词条与它「依据」指向的产品正文。**这里到「有这么一个对象」为止。**

## 红线

约束**任何在这里落字的人**。各条的道理与判法在 skill 里，这里只留结论。

- **键是词条 ID。**没有词条的东西不立条目；立不了词条的进 pending.md。
- **正文没说的写「正文未述」。**不补一个看起来合理的——下游会把它当已定事实实现出来。
- **不复核就改 rev，等于把对账关掉。**rev 是这里与产品正文对齐的唯一凭据。
- **两处正文说法相左，不在这里静默选一个。**登记成待裁，写清谁来裁、什么算闭合。
- **条目不自带任何划分。**
- **总表只由生成器产出。**
