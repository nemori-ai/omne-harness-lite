# 当前模型日志 codec 的精确载荷标记

2026-09-28，D-100 实施接续的技术精确化；状态由接受记录确定，未声明实现或验证完成。

沿 [当前实施映射](v7-current-design.md) 的唯一 root codec 和原 D-094 日志编码/认回责任，当前 `payload.format` 及本域去重、读取键的前缀统一为 **`mrr/3`**。其余键的身份分量、规范化、payload成员、entry类型、同批比较、条件提交与认回算法继续原已接受定义；值采用 MP5/MS6/MR7/LC6。本页只钉实现承载字节，不增加公共操作、产品政策、失败值或存储能力。

删除旧 root MR4 与 log-codec-v2 MR5 双轨及旧子路径导出，公共函数名迁到根；不保留 mrr/1 或 mrr/2 解码执行，也不把旧串转换成新串。`log-codec-key.ts` 与 root codec 持同一当前常量，不让payload与key各自判代际。

当前接收/完整历史读取必须识别本模型日志域：遇到旧 `mrr/1` key、旧 `mrr/1`/`mrr/2` payload 或本域其他不支持标记，明确拒绝或按读面返回 unavailable。识别只用于拒绝，不解析旧业务值，不查当前目录补旧快照；不能把这些条目当非模型数据跳过，进而报告空历史、absent或允许再次发送。键和值代际不匹配同样失败。无关日志域仍沿原规则解释，不能泛拒所有会话条目。

所有当前 runtime 写读、结算、历史、选择消费者与demo同批迁移到根。新建数据目录执行当前验收；旧目录字节保持原样，不就地升级/清空。当前代际未确认追加仍由原owner持有，前缀变化不是抛弃责任的依据。

必要验收：新root公开encode/decode和完整原批认回；payload/key均为mrr/3且业务身份不变；旧标记、错配和伪造键在接收/全前缀读上拒绝而非absent；未知opened/response原有责任与停止测试继续；真实新目录同批回复、关闭重开；旧数据字节不变；旧子路径不可导入。schema旧资源只为现行精确依赖保留，与本页旧执行面删除无冲突。双语README与真实例子同步更新。
