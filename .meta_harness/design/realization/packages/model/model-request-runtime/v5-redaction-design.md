# model-request-runtime：RT5 G-6 脱敏政策投影候选

2026-09-27，rev 2，**candidate，未接受；本增补未实现、修订待独立安全复评、新增 bindings 0**。本次针对 rev1 的 R5R-AR1，统一 JSON scalar 处理并补 raw.body 转义区间与写前稳定性核验；不改变三参数候选基线，不关闭 R5R-G4。本文只补既有节点的提供者政策；原四件套、v3/v4 冻结投影及已运行证据保持原范围。下文新增构件、配置和字段名均为**候选实现名**，不是已经存在的 API。

## 输入、承诺与范围

baseline `omne-harness-lite-design-2026-09-15` 的 [RT5](../../../../spec/capabilities/model-request-runtime/v5/contract.md) 与 [MR5](../../../../spec/data/model-response/v5/contract.md) 已由 D-090 接受，catalog 坐标一致。本文投影 RT5 S-20/S-46/S-54/S-58/S-60/S-63、G-6 和 MR5 S-20/S-21/S-22；其余十三操作、late、恢复、费用与模型适配不重定。产品依据沿 RT5 已采用的 PF-013 rev 13 §6.16、PF-011 的写前脱敏要求；不借当前产品新版扩大采用。

D-091 只采用不透明 R 和私有网络资源；[transport 头投影 rev2](../pi-ai-transport/v5-headers-design.md) 的 PH-G2 尚未关闭。本文给 G-6 **可供安全评审接受或拒绝的具体生产基线**，不是从产品中读出的数值，也不以候选存在、空配置或测试值宣布 G-6 完成。秘密政策接受、两 provider 接线、附件写方、真实验证分别过门。

领域性质沿既有契约，不重新做领域拆分：四个表面都不得泄漏本次已用凭据及规定片段；处理发生在公共返回或持久写入前；其余原文不改；已留存的头在取消、读失败后仍保留。此次是已有机制读数之后的窄投影，不声称重新取得双盲读数。政策是数据与纯计算；没有新 plugin、fiber、service、表或诊断原文流。

## 三参数的生产候选值

部署显式选择候选配置修订 `openrouter-redaction/1`；这是非秘密配置标签，不是新的领域身份。以下三项缺一不可，工厂不暗填。允许应用导入一份公开、不可变的候选基线配置再显式交入；配置常量不是藏在算法里的默认值。

| RT5 G-6 参数 | `openrouter-redaction/1` 的精确值 | 单位、合法范围与理由 |
| --- | --- | --- |
| `credential_fragment_min_length` | **8** | 按 Unicode scalar 数；当前 OpenRouter 凭据准入保持已有非空可打印 ASCII，所以等于 ASCII 字节数。全值无论长短都匹配。通用纯构件接收安全整数 1～64；本生产基线的受支持加强配置限 1～8，超过 8 须另一个被安全评审接受的配置修订。8 是“至少八字符片段也保护”的明确工程取舍，不能推出少于八字符片段安全或凭据具有某种熵；短片段和误遮罩风险由评审裁决 |
| `credential_header_names` | `authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `api-key`, `apikey`, `x-auth-token`, `x-access-token`, `x-openrouter-api-key`, `x-amz-security-token` | **整头剥除**。基线 11 项均须在生产有效配置中；可增加，不能从此配置修订中删除。名单项为非空小写 ASCII HTTP token，重复项拒绝；不含值、不从租户或模型档案读名单 |
| `credential_patterns` | 三个描述：`prefix-token("sk-", "key")`、`scheme-token("bearer", "auth")`、`scheme-token("basic", "auth")` | 不是开放正则。`key` 字符集恰为 `A-Z a-z 0-9 _ -`；`auth` 恰为 `A-Z a-z 0-9 . _ ~ + / - =`。三项均须在生产配置中；`sk-` 是刻意覆盖该前缀家族的保守识别，不声称外部厂商密钥格式永不改变。未知前缀/编码的覆盖靠已知值规则或后续被接受的新描述，不谎称“识别所有秘密” |

**名单匹配与保留**：只在比较头名时折叠 ASCII A～Z；不 trim、不用 locale、不折叠其他字符。匹配原始采得键名，不在脱敏重命名之后才判名单。`Authorization`、`AUTHORIZATION` 与 `authorization` 均整项移除；采得 map 中不同大小写的键各自判断，不合并。一个被剥头的 string[] 全部移除；未剥的数组维持数组、次序、重复及空元素。Node 如何从线上同名头形成 map 仍由 PH-V1 核实，不从本名单推出 HTTP 线序保证。

**描述语法和精确匹配**：

- `prefix-token(prefix, alphabet)`：在每个位置尝试按 ASCII 大小写敏感匹配 literal prefix，随后必须有至少一个 alphabet 字符，取其连续最大串；替换范围包括 prefix 和整个尾串。`sk-a` 即匹配；没有尾字符的 `sk-` 不因本描述匹配。无词边界、行首行尾锚点，嵌在其他文本内也匹配。
- `scheme-token(scheme, alphabet)`：literal scheme 按 ASCII 不区分大小写，其后恰为一个或多个 SP/HTAB，再接至少一个 alphabet 字符并取连续最大串；替换范围包含 scheme、间隔和整个尾串。无词边界和多行模式；换行不当间隔。`Bearer abc`、`bAsIc aA==` 匹配，`bearerish` 不匹配。
- 描述只能选择这两种 kind 和这两个具名字母表；prefix/scheme 为 1～64 个可打印 ASCII，scheme 只准 ASCII 字母。候选通用配置上限是 64 个互不完全重复描述、128 个头名、每个头名 1～128 ASCII 字符；基线明显低于这些上限。未知 kind/alphabet/额外字段、空串、重复、越界、非数据属性一律配置错误。没有 regex source、flags、回溯、lookaround、backreference、脚本、外部词典或每次请求动态求值。
- 实现采用 literal 搜索及确定的连续字符扫描，不能将描述转换成任意用户正则。先计算各具名字母表在输入各位置的连续串终点与 SP/HTAB 串终点；每个位置至多比较每个描述的 64 字符 literal，再按终点表确定区间，不在大量重叠前缀上重复扫描整个长尾。已知片段用固定 m 窗口集合加精确相等复核，输入只滑扫一次；不枚举所有长子串，不以 hash 相同代相等。编译/扫描的时间与内存界按凭据长度、输入长度、m 和描述数给出。配置只复制自有数据属性，拒绝访问器/循环结构；反射操作抛错统一以受控配置错误拒绝，不把 getter/proxy 错误原文交出。成功投影为普通数据的 proxy 不被宣称已识别或隔离；本纯构件不是同进程任意代码沙箱。公共构件的实际复杂度、长前缀重叠和极端输入由 R5R-V5 量测，不凭语法声明性能已过。上述数量界是本候选可审阅配置，改变须更新配置修订和相应资源验收。

这份基线只针对 OpenRouter 链上的模型凭据暴露；不加入厂商专线、TTL、缓存断点或模型家族默认值。组织/租户自建模型也不能削弱该部署秘密政策。凭据来源、权限与每次新取继续归目录和保管方。

## 共用构件、匹配顺序与所有权

候选 `createCredentialRedactionPolicy(config)` 放在本包纯公开入口；transport 已依赖本包的公开协议，可单向复用这一构件，不反向依赖 transport、Cordis、目录、会话或存储。RT5 S-60 的公开 `redact(value, knownCredential, params)` 使用同一个匹配内核。构造阶段深复制、校验、冻结配置并编译非秘密匹配数据；绑定本次凭据所得闭包只有处理操作，没有读出凭据、窗口表或原始输入的属性。配置、闭包和脱敏结果不能拿来证明真实凭据来源。

1. **先验证再触及网络**：构造工厂或启动插件时校验完整配置；每次发送在当前凭据准入后绑定同一快照。全值匹配加全部长度为 m 的滑动窗口，覆盖任何长度不少于 m 的连续子串；长度小于 m 的完整凭据仍匹配。匹配区间从**原输入**求并集，一次输出，不能依名单次序反复删改输入造成遮罩缺口。现有 `credentialRedactor` 的逐窗口替换须由这一内核取代，不能保留第二套政策。
2. **文字匹配**：全值和窗口按 scalar 精确相等，不做大小写、Unicode 正规化、空白、URL 或 base64 解码；三个形态扫描器也在原输入上匹配，区间取并集。一个最大连续被遮罩区间替换为一个 `█`（U+2588）；不使用空串，防止把两段保留文本拼成新凭据。该标记不属于当前 ASCII 凭据及两个 token 字母表，不能自己再匹配。不得额外“信任已有标记”而跳过其两侧输入。
3. **结构化上游错误**：递归处理所有对象键和 scalar，数组保序。字符串值、字符串 code/message/raw 使用文字区间规则；**非字符串 scalar 统一按其 JSON token 扫描**：数字使用精确原始十进制表示，布尔使用 `true`/`false`，null 使用 `null`。只要 token 任一部分命中全值、片段或形态，该 scalar 整体投影成字符串 `█`；未命中才逐值保留，包括其原类型和精确数值。不能无条件透传布尔/null，也不能将精确数字先转 IEEE-754 再判。这是凭据处理引起的 JsonValue 类型变化，不把未命中的类型改成字符串。例如分别用合法已知凭据 `true`、`false`、`null`，对应 raw 值必须变为 `"█"`，不能以全值短于 m 为由跳过；数组与嵌套对象同样适用。HTTP 状态分类仍从传输先采得的真实 HTTP 事实取得，不从已经遮罩的原文猜回。既有契约强制保持的领域身份、费用和状态事实不通过此函数任意重写；若秘密与这类受约束字段冲突，按下面 R5R-G4 暂停对应写入设计，不能借脱敏改业务语义。
4. **对象键碰撞**：先保留所有未改名键，再按原对象 own-entry 顺序给改变的键分配脱敏名；与已用键碰撞时追加 `█` 到唯一。用无原型自有 map/等效安全构造，`__proto__`/`constructor` 不改变原型、不吞项；不跨条目合并值。只给必须因秘密改变的键追加后缀，原非秘密键不动。header 名单剥除先于此步骤。
5. **幂等与不别名**：同政策、同已知凭据再次处理，文本、JSON 值和头在值意义上满足 `R(R(x)) = R(x)`；命中的非字符串 scalar 已变为不命中的标记字符串，二次处理仍保留它。标记和不拼接避免新文本命中，键碰撞二次不会再改已遮罩名。**字节留存是下述会明确失败的投影，不把文本/值层推导直接套到源字节。**每份输出及嵌套容器由处理者自有并深冻；调用者随后变更输入/config 不影响输出。实现必须用反例检查这些推导，readonly 类型不作证据。

**raw.body 的处理是同内核的字节投影，不能逐 chunk 分别替换。**附件写方在任何持久临时文件或对象存储写入之前拥有本次私有、受限的原始缓冲。候选内部一步投影记为 `J(bytes)`，下列命名只解释算法，不新增服务失败值或附件契约：

1. 核 UTF-8，并为当前 JSON/SSE 文本建立源 token 区间。SSE 以实际帧 data 载荷处理，跨网络 chunk 保留词法状态。匹配视图同时含原字节解码文本、JSON 字符串解码后的 scalar 序列、**每个非字符串 scalar 的精确源 token（数字/true/false/null）**。JSON 转义/`\uXXXX`/surrogate pair 保留 scalar 到源字节的对应表；先在所有视图取匹配，再统一投影源区间，不能漏掉原字节视图里的命中。
2. 字符串解码视图命中的 scalar 映射到其完整原编码 span；非字符串 scalar 的任一命中扩至该 token 全体，以 UTF-8 字节 `"█"` 替换；其余命中按区间并集换成 UTF-8 `█`。只改被匹配/按上述 scalar 规则确定的源 span，保留其余字节、空白和次序，不 parse→stringify。**原字节命中若只覆盖某个转义的后半部，不得为了修补语法而擅自扩张到未命中的反斜杠，或另外加转义字节。**重叠标记先由同一原输入区间归并，不能逐视图先后修改。
3. 在任何写入之前，先求 `J(x)=y`，再对自有候选 y 用**相同模式、policy 和已知凭据**重新求一次 J。只有两次均可完成映射，且第二次结果与 y **逐字节相同**，才交出可留存字节 y。第一次或第二次无法映射、超出资源界、第二次仍需改字节，均是本提供者的**留存未成**：不输出 x/y，不写临时持久副本，不伪造 AttachmentRef，仅给受控失败事实。最多这两遍，不循环到碰巧稳定，不信任“已经脱敏”标记跳过扫描。保真核验始终以原 x 和独立期望区间为准，不能拿第二次输入作原文消除第一次改写。

此处 `J` 的识别范围是本提供者完成投影的前提；**不是为 MR5 新增“附件必须是合法 JSON”的保证**，也不凭 JSON.parse 成功判秘密安全。源数据或候选无法用该范围完成写前复核时，只能报告本次留存未成，不将“修到能解析”当实现办法。非文本、无效 UTF-8、未闭合/损坏帧同样沿这个明确失败路径；其他表示将来若要支持，由对应保真投影另行采用。按 MR5 S-20，留存未成不阻止响应其余成员收场、不擦已安全 H。取消/中途断流仍对已取得且可辨认的完整留存单位执行同一流程；不能仅因 outcome 非成功放弃已安全留存内容，也不能删掉失败单位后谎称原完整体已保存。

**转义区间反例必须固定**：令 `V = nsecret1`、m=8，JSON 字符串源字节为 `22 5c 6e 73 65 63 72 65 74 31 22`，即双引号、反斜杠、`nsecret1`、双引号。JSON 解码值是换行接 `secret1`，并不含 V；原字节视图却在半开区间 `[2,10)` 含 V。一次最小替换得到 `22 5c e2 96 88 22`（双引号、反斜杠、█、双引号）。第二遍无法识别该转义，故**第一次调用就在写前报告留存未成**；不得漏掉原字节命中、输出这个未经复核的 y、删反斜杠或补语法。此失败不是改变模型 outcome，也不声称所有附件原本必须可解析。

对**成功返回**的字节投影 R，以上规则给出可实际验证的幂等：若 `R(x)=y`，已核 `J(y)=y`，故再次独立调用 R(y) 两遍仍返回同一 y；失败结果没有可再处理/可持久字节，不能把失败换成原 x 维持表面幂等。独立 oracle 必须同时核成功域、失败域、逐字节保真和二次处理，不能只断言一个类型标记或对象身份。

附件 IO 仍归原写方；本包纯构件不读附件、不创建临时文件、不隐藏设置。留存大小界、保留期及附件真提供者不由 G-6 三参数冒充，见 R5R-G3。已经存在的 `rawHeaders` 不因 body 留存未成而丢失。未解码的 base64/URL 自定义编码、未知凭据低于 m 的孤立片段、跨多个独立记录拆散的片段不由该算法声称覆盖；安全评审若认为这些是 S-20 必须承担的含义，就拒绝本稿并回 owner 明确编码/跨记录边界，不能把这个限制偷偷当产品豁免。

## 配置来源、装配与失败

可信部署配置是唯一来源。候选基线作为普通数据导出；[model-request-acceptance](../../../retired/model-request-acceptance/design.md) 以及实际产品装配 owner 在启动前显式选择修订与完整值，先用同一纯构造器生成政策，再交给 transport 工厂与 invoke/P-2。两端不各自读 env、不接受 model profile/请求/上游建议覆盖、不用 Cordis intercept 混出部分字段。将来改变参数以新完整配置构造新 provider；活动请求保留旧快照，新请求只使用新完整快照，不在 response 到达后查“最新政策”。本稿不定义配置发布 API 或租户授权面。

本候选通用构件能表达的值域不等于生产已批准配置：装配必须核已采用修订与完整值（或上表允许的只加强变体）。允许变体的增加名单/描述、降低 m 仍有资源/误遮罩验收；变体值自身全部保存在非秘密部署配置，不只保存一个碰撞可混淆的摘要。精确 baseline 的采用、实现与测试范围分别记录。

静态缺项/非法参数/编译失败统一 **工厂构造失败／插件启动失败，零网络、无半套服务**，不把它报成凭据不可用或上游故障。已知凭据输入非法沿现有 invalidInput，零 send；有效配置的处理代码在发出后异常，绝不能 fallback 原文。transport 在自己的边界保留原 stop/stopped 收束；能在 MR5 可选留存位置确认为留存失败时按既有分支缺席，并给受控故障事实。会影响必需响应事实的异常，不造新的业务码或第五 outcome；按 R5R-G4 报具体契约冲突，由原 owner 先定可兑现路径。新异常路径未经该门不能声称完整 S-20。

公开独立 invoke 的调用者与可替换 TransportAdapter 仍承担原 S-20 合规责任。生产装配使用同一个 policy 构造结果，所有本包提供的 send/read/redact 路径共享内核；任意第三方 adapter 不会因为类型相容自动通过认证。候选 `InvocationPolicy.redact` 单字符串回调应明确迁移为完整 policy 配置/处理构件，不保留“callback 缺失就直通”的兼容层。具体公共类型变更由 runtime/transport owners 联合落地和包外消费者验证，本稿不擅改已接受 S-58 发送参数或增加服务操作。

## Cordis、装卸与存储要求

沿 D-025 的 Cordis 4.0.4。政策不独立 inject；它随现有 P-2/transport 配置构造，改变提供者仍按 [plugin-body-reruns-on-provider-change](../../../../basis/cordis/plugin-body-reruns-on-provider-change.md) 处理，不能推成旧请求重发。配置失败依据 [plugin-throw-fails-fiber](../../../../basis/cordis/plugin-throw-fails-fiber.md)；关闭顺序不靠 [effect-disposal-concurrent-not-ordered](../../../../basis/cordis/effect-disposal-concurrent-not-ordered.md) 提供。三条均有 probe；本增补未运行它们。Node 字节分块、UTF-8/SSE 解码及资源停止是**待按实际采用版本取证的实现主张**，不是 Cordis 保证。

| 装载所得 | owner、可用点与部分失败 | 撤除/完成与仍然为真 |
| --- | --- | --- |
| 非秘密编译 policy/config | 工厂或原 provider；校验全部通过才发布；半途失败不建网络资源、不输出原配置 | 关闭原准入，旧调用仍持原快照；不用全局可变 policy 指针让旧调用换规则 |
| 本次已知值匹配闭包 | 发出 owner；只在发送前绑定，runtime/transport 内部按同一快照各持必要处理引用 | 实际请求/reader/回调及待处理持久责任收束才解除强引用；不提前释放导致错误/取消支漏扫，不承诺 JS 内存物理擦除 |
| 原始 body 私有缓冲 | 原附件留存 owner；未处理不交公开/持久端口；分配或验证失败归留存失败 | 取消仍收束自身工作；安全字节交存储后释放原缓冲；进程丢失不假装附件已存或重取旧凭据重做 |
| 已安全头/错误/字节 | 输出创建者独占复制，公共交接后由消费者持有 | 后续 policy 更新、R.stop、reader 失败不能擦掉已留存 H；历史记录不重新洗成新政策 |

新增直接存储要求为 **0**。脱敏不引入跨 owner 同提交；日志 msg/rsp/账仍须用原共同 `entries.jsonl` 批，附件写方仍须先确认安全字节持久后才给真实引用。此先后不是附件与日志原子提交，不能靠同一进程内锁、时钟或 policy 对象证明两种 IO 原子。原日志/附件不可用语义及责任保持。

## 方案比较与取舍

| 关键选择 | 可行落选方的最强论证 | 本候选的选择、弱点与置信度 |
| --- | --- | --- |
| 政策执行 | A：可信部署交 RE2 风格表达式，统一成熟无回溯引擎；表达力强、可维护大词典，但须采用依赖和确切语法/资源规则 | **B：两种有限描述＋literal 扫描**；只解决当前三形态及已知窗口，表达面小、无需新 native/WASM 依赖。弱点是新语法须升提供者，词法投影仍有实现成本；置信度中，资源实测未做。没有把通用 JS regex 作为安全替身 |
| 政策归属 | 独立 policy 服务可热换、不重建调用者；多个消费者可统一查询 | **纯构件＋原 provider 配置**；减少独立生命周期和配置竞态，支持框架消费者。弱点是装配必须保证两端同配置，不能靠全局 service 自动收敛；置信度高 |
| 已知片段阈值 | 1～4 更能遮掉短回显；较大阈值更少误伤原文 | **基线 8，可显式加强**；不把厂商格式或概率冒充依据。弱点是短于 8 的非全值回显可能保留，共用前缀也会误遮罩；置信度中，属于安全评审的真实否决点 |
| 原始 body | 在每个 transport chunk 上直接替换易实现、内存小；整包 parse/stringify 复用现成 JSON 解析；扩大命中 span 至完整转义可提高留存成功率 | **带源区间的词法投影/受限私有缓冲＋写前第二遍稳定性核验**；前两者分别漏跨块或改原字节，扩 span 会改未命中字节。弱点是额外一遍投影、如 nsecret1 反例的保守留存失败及词法成本，须归附件 owner 真测；置信度中，不把可留存范围提升为附件合法 JSON 契约 |

反向核对：配置换代不重发旧请求；关闭不会让旧错误绕过脱敏；policy/秘密不经事件广播；跨进程须重新传明确配置修订与安全值，不能把本机闭包/冻结当协议。已发生费用和已持久事实不回滚。不增加 LLM 抽象基类、通用秘密管理服务或厂商适配目录。

## 安全评审门与未完成责任

独立评审逐条给可反驳结论：① min=8 对已承诺的片段保护是否足够；② 11 项名单和三形态的漏扫/误遮罩是否可接受；③ ASCII、Unicode/转义、未知编码与跨记录边界是否符合 S-20；④ literal 扫描、区间并集、键碰撞、全部 scalar、字节成功/失败域与幂等能否成立；⑤ 缺配置/处理异常/取消时有没有原文旁路；⑥ raw.body 是否在任何持久临时写前完成两遍复核、其他字节保真且没有暗加附件 JSON 保证；⑦ 公开 JS 对象、异常、Promise、配置错误和诊断是否可达秘密；⑧ 审过的完整配置是否就是两端真正使用的同次快照。任一点无足够依据可拒绝该选择，不能用“候选默认”压过安全反例。R5R-AR1 的上述处置尚待同一独立 reviewer 复核，不自称阻断已关闭。

| 缺口 | 受阻消费者、owner 与闭合条件 |
| --- | --- |
| R5R-G1：RT5 G-6 政策尚未接受 | 主线安排独立安全/架构复核并作精确采用；在此之前 PH-G2 与生产 rawHeaders 出值仍不放行 |
| R5R-G2：RT5 S-20/S-54/S-58 的实际跨包路径未实现 | runtime/transport owners 更新公开 policy 类型、factory/plugin/direct 消费及同次 H 保留；联合真实 TLS、取消、异常、制品与双语例通过 R5R-V1/V2/V4～V7；纯 helper 通过不代验 |
| R5R-G3：MR5 S-20 raw.body 实际附件写方/资源配置未落地 | 原附件 owner 与 model-request-acceptance/产品装配 owner 指定真实附件提供者、留存大小/期限配置和字节投影，完成 R5R-V3。只关闭参数选择不等于 full S-20/原始体 IO 完成 |
| R5R-G4：必需事实与秘密处理失败的边界待安全评审明确 | RT5 S-18/S-20/S-46、MR5 S-21 同时约束真实状态/费用/身份与不得含凭据。现有 ASCII 凭据准入允许 `503`；若上游实际 HTTP 503，error 原文可以遮罩，但 `failure.statusCode` 按来源仍为 503。该碰撞是否属于“出现凭据”不能由本稿裁成豁免，也不能自行收紧凭据格式、改身份/金额或删必需字段。原契约 owner 必须对具体反例定界；未解决前，涉及此冲突的必需输出与 full S-20 验收受阻，三参数本身的评审可继续 |
