- **语义接受**：本后继尚无；契约坐标仍为 `data.model-profile/v4` 和 `capability.model-request-runtime/v6`，不改契约字段或输入限制政策。本工作树 catalog 仍显示 candidate，精确接受与同步由主线登记。

继承 v7 的六项 capabilities、core MP4 完整判定、家族公共 route 加模型窄声明、配置同源、精确全值等价、最终固定计划、计量与材料责任、装卸配对、无新增存储及 IL-G1～4。它们的兑现点仍由 v7 投影表定位；以下变更取代其中关于旧根继续执行、独立版本子入口、双版本回归及保留旧读取实现的句子。

## 当前消费者必须同时迁移

| owner / 当前消费面 | 交付动作与边界 |
| --- | --- |
| transport owner | 统一 definitions/configuration/plan/registry/factory/plugin 及 exports，删除本轮旧定义和过渡入口；root import 不自动建 Agent 或登记贡献。既有凭据、H、取消和资源归属沿 D-095，不借迁移削弱 |
| runtime 与数据/codec owner | 采用 MP4 完整快照和配套精确后继消费，调整拒绝传播与最终 plan 门；移除仅为本轮旧格式兼容留下的解释路径。旧用户数据仍原样保留，不修改既有提交、不猜当前 cap；拒绝读取或续接不等于已经结算，原未完成责任不能记作完成 |
| demo 与当前装配 owner | `examples/model-invocation-minimal-demo` 与全部当前调用者一起改到新根/新定义/完整输入，不保留旧 Pro 特例。有真实计量与材料时验收新路径；尚缺依据时明确发前拒绝，不能宣称 demo 的新版成功调用已经完成 |
| 文档与验证 owner | transport、runtime 和 demo 的 README/README_ZH、fixtures、独立打包消费者及实际示例同批迁移；说明当前完整声明范围、输入限制及仍缺的成功发送证据 |

“不兼容旧版”只针对本次被替代的公开面和消费路径；当前契约仍明确依赖的 content-blocks 等精确版本继续使用，不以名字含旧版本就无差别升级/删除。采用文件、历史规格、既有运行证据及用户数据也不属于清理目标。本节点不代其他 owner 决定 codec 格式名或删除其仍被现行契约消费的实现。

## 取舍、实施次序与验收

| 选择 | 落选方最强理由 | 本方代价 / 置信度 |
| --- | --- | --- |
| 统一新根并同步破坏性迁移 | 双版本过渡可暂时保持旧 demo 成功发送 | 当前调用者必须同批改动；缺计量时新版明确不可发。用户已选择此边界，技术投影置信度高，不将可用性代价藏在旧执行旁路 |

完整定义、纯读取/建档及其测试可以先实现并行交付，无需等待全部 meter；其余当前消费者同步迁移并保证拒绝路径正确。**完整声明通过不能升级为成功发送通过**，全拒绝也不能算最终调用交付完成。成功路径须补足 v7 已列的可靠计量、实际表示及原有缓存/模态义务后执行 IL-V4～8。

采用后的当前 IL-V9 由 [IL-V9-v8](verification.md#v8-统一公开面破坏性迁移验证) 取代过渡验收；其他 IL-V 继续适用。IL-G2 仍阻塞对应成功发送，IL-G3 仍阻塞未迁移的 runtime/codec/装配。源码、规格接受、实际验证分别报告，主线负责 D-100 精确取代与所需消费者同步。
