# CG1 提供者与 Cordis 投影

本节点实现CG1，不复制中心授权或CLS事务。选择沿D046 B边界与CLI-TUI§11：独立本地记录可替换，用例组合供CLI/TUI共同消费，应用只装配/输入/呈现；不再设另一数据库或后台进程。纯函数网络客户端D045不必为了形状进入ctx，直接经公开入口消费；本地记录依赖经注入，以支持实际资源换代。

## 服务与所有权

插件名`governance-client-operations`，必需inject `clientLocalState`，provide `governanceClientOperations`。公开`createGovernanceClient({state, timeoutMs?})`可用于一次性装配，返回同一服务和close，不自建root Context。生产网络调用仅来自D045公开readPublicHealth/exchangeGovernance；内部测试构造器可注入运输及观察时刻，公开配置不提供任意路由代理或凭据替身。

服务面：`runAction(input)`承接一条canonical Input，自行取得/关闭本次使用；`openUse()`让TUI持有一次S5使用，其`run(input)`只接invoke/logout，及`close()`。configure/register/login/health归进入前动作，不能塞进已登录use来换引用。未知输入正常映射invalid-input；闭合域误用沿CG1缺陷，不变成远端授权拒绝。两条路径共用动作分派/输出构造/校验。

根组合跟踪所有实际Action Promise，包括创建使用的本地读取、运输、CAS与查证；每个use跟踪自己的在途动作。关闭先关准入，再等完整集合，最后释放use引用；不关闭借来的CLS。TUI/CLI应用必须先调用组合close并等待，然后才移除插件/关CLS；动态更换CLS前同样静止组合，不能直接依赖Cordis并发effect顺序。插件effect负责自身close，作为受控卸载的最后防线；宿主任意跳过顺序强拆依赖不在“无损换代”承诺内。无需isolate、label、通知事件、轮询或后台worker。

网络异常是一次动作结果，不让fiber卸载；configured center/账号是数据，不按每租户起插件。新依赖到来启动新组合，旧调用只用捕获的原依赖及原中心/登录，不在等待后重新ctx.get。

## 数据流与保护点

| CG1 | 提供者承接 |
|---|---|
| S2固定使用 | 私有使用对象+所属组合WeakSet；捕获CLS storeId、完整中心绑定和登录引用。每次动作的准入先read CLS并逐值比较；变化停止新准入。纯副本/修订更新不换登录 |
| S3/S14公开安全结果 | 输入先按CG Schema、操作载荷沿EC2；捕获JSON快照后才await。输出只经公共投影器构造、再按CG Schema校验；登录成功逐字段保留句柄，绝不把原reply或CLS spread进公开DTO。defect不输出原异常/输入 |
| S4/S13中心 | 捕获记录/参数；无秘密health；标识精确比较，再允许目标请求。相同证书端点在两连接间换中心仍依赖既有部署稳定性前提，不说预查已提供密码学原子绑定 |
| S5/S6/S7用例 | 每个use busy拒绝并发，不排队；根服务可并行不同使用。登录/注册独立前置动作，返回后由应用显式重新进入。未知账号以OG36成功结果补足，账号不合已知引用则缺陷；不会把当前选择直接当成员有效 |
| S7预期租户 | 原载荷expectedTenant保留到发送；不现查后替用户换预期。EC2负责同提交读/写/权限，组合无第二套超管规则 |
| S8/S9/S10本地结算 | 每动作以准入快照汇总账号补足、读数更新与失效；一次CAS。remote/local结果分开。CAS unknown后一次read，storeId+operationId共同查证，不重交/回滚/撤销补偿 |
| S11生命周期 | 行为Promise结束才离开根/use集合；网络取消后仍等运输收场及CAS确认/查证。close不能抢先关借来的存储 |

唯一共同持久对象仍是CLS1的完整本地记录；中心业务事务在远端EC2，与本地没有共同提交对象，因此明确两阶段结果。UUID用于动作/本地operationId，假设密码学随机源碰撞可忽略；不存在无界历史去重表。记录值相等采用对象成员顺序无关、数组顺序有意义的规范JSON比较，不对ID作trim/大小写折叠；输入和配置也先深复制，返回不暴露可变内部引用。

## 副本实现与已知失权

按照CG1 S9的13路由、查询键及资格依赖表建立纯函数映射，不在组件各写名单。持久副本只从CLS完整记录读取；本use另持“已知不适用”规则，防止清理CAS失败或另进程旧副本写回后继续展示。该规则作用于同账号及受影响组织/查询，不成为远端授权拦截；fresh请求仍交EC2。新的线上结果本次可显示，但不能只按查询键解除旧盘副本禁用。仅在本动作将这份具体副本CAS installed后，登记“完整来源/查询/结果/取得时刻逐值相同”的副本例外；以后CLS返回同key旧值或别的条目仍禁用。CAS失败/unknown不登记例外。每次新失效观察同时移除受影响的旧例外，不能让较早成功再次穿过后来的失权。新的本账号成员资格读数只更新知识，不无条件恢复原持久条目；不把别人的缓存时间当解除失权的证明。

prefer-copy有适用副本就显示，缺席才线上；refresh线上失败仅在CG1允许的不可得类别回退。入口刷新待办归应用，组合无后台策略。缓存数据来自成功EC2 Exchange，动作结果unknown不改成成功历史副本。取得时刻只用于显示来源，由客户端观察时刻转OE Instant；它不是中心Clock，不参与登录或邀约有效性。无法取得合表示时刻时不保存副本，报告本地不可保存并仍保留远端事实。默认Node观察时刻仅用于此显示元数据，测试可注入；取时集中在`src/observation-time.ts`，no-wall-clock只对这个具名文件放行，其他frontend/领域文件仍禁止取墙钟；不给它设置租户事实的能力。

失效和新读数据一起形成CLS完整拟写；受影响缓存即使持久清理失败，也在use内停止适用。同一动作身份准备读数并入最终一次CAS，不能用两次保存绕过原快照。读取局部副本不会偷偷调用网络续期；网络访问由显式动作发起。

## 结构与依赖

源码按surface/validation/use/actions/cache/report/settlement/client分工，小文件按职责而不是每条路由建类。输入/输出Schema使用包内冻结CG1副本与EC2/IV/OE公开Schema，漂移测试对齐精确规范；跨包不引用src。Ajv沿现有工具链，TypeScript公开类型只投影Schema。超时沿D045配置，不引入重试库。主入口与`./schema`为公共出口，测试替身与私有构造不导出。

对照路线：把全部函数放apps会失去共享规则owner；把CLS也吞进此包会取消D046已选独立恢复边界；给每路由单建plugin没有独立生命周期收益。此节点的新增状态只为整次使用与收场，不是重新设计账号/租户。
