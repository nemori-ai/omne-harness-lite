# offer-expiry：RFC3339 原字符串精确时序增补候选

## 公开面、责任映射与 Cordis

候选根导出：`compareRfc3339Instants(left: unknown, right: unknown) → Parsed<-1 | 0 | 1>`；`Parsed` 沿已有 identity-values 根公开类型，结果仅为 `{ok: -1|0|1}` 或 `{invalidInput: string}`。**按本候选建议的 R1，其排序保证以前后两值确为合法 RFC3339 时间点为前提；unknown 参数要求静态检查，不承诺认证实际闰秒公告。**可静态判定非法则 invalidInput，说明固定且不回显输入；不抛输入值异常，不转成相等或默认当前时间。ok 只给该前提下的排序，不能被调用方解释成外部事实已核。合法 `:60` 保留、正确排序；不把事实未知伪称 invalidInput，也不加 unknown／unsupported 来假装本函数已有完整接收责任。两种公开责任的取舍与调用者门见 TL-G1。

## 接收域与标准边界

现有 OE1/OE2 Instant 同时有 pattern 与 `format: date-time`。当前 `validate('Instant', value)` 的公开实现关闭 format 断言，能否过它只说明 pattern 等形状，不证明日历合法；日期语义必须继续检查。原 `instantFromRfc3339` 能拒非法日历／偏移，但会量化小数并拒绝 `:60`，不能把它的成功集合当新完整接收域。

本页以 [RFC3339 §4.2／§4.3／§5.6／§5.7](https://www.rfc-editor.org/rfc/rfc3339.html#section-5.6) 为 OE1 S-22 已引语义的核对来源：偏移按本地时间减 UTC，`-00:00` 表示 UTC 已知而本地偏移未知；T/Z 可小写，小数不限固定小数位；日历和闰秒限制必须成立。**标准本身不是新采用决定**，下面普通域机制是对此与现有 OE 规则的技术投影；不采用 RFC9557、IANA 时区、闰秒查询服务或历法扩展。

| 输入边界 | 本候选的已明确处理／待核范围 |
| --- | --- |
| 文本与完整消耗 | 只接收原始 string；恰四位年、两位月日时分秒、T/t、可选点后至少一位十进制小数、Z/z 或带符号 HH:MM。拒绝日期单值、无偏移、空小数、空格替 T、首尾杂字符／换行；不 trim、不字符串强制转换。现有 `$` pattern 可作形状否定检查，不能替代完整输入消耗 |
| 本地日历 | 年 0000～9999；月 01～12，日按公历月份／闰年有效性；年可被4整除且不被100整除、或被400整除为闰年，包括0000。时 00～23、分 00～59；不借 Date 自动进位接受02月30日／24点 |
| 偏移 | Z/z、+00:00、-00:00 的时点偏移量均为0，原词法和含义不写回；±HH:MM 的小时≤23、分钟≤59。减偏移可跨日、跨本地四位年边界，不因此拒绝合法本地串；内部结果可位于公元0000之前或9999之后 |
| 小数 | 缺席等于数值0；保留全部位，尾零不影响时点。不能转浮点、整数毫秒／纳秒、按固定精度截断，也不人为限制位数 |
| 秒与闰秒 | 秒字段只容00～60；60还须经偏移折算处于 UTC 月末最后一分钟，否则可静态判为非法；不限定只能6月／12月。真正合法60需要该日确有正闰秒，负闰秒分钟的59则不存在。这两项外部事实不是月份／日历形状能认证的，沿 TL-G1。**合法时点如何排序**见下一节，不将60滚动或统一拒绝 |

`-00:00` 的未知是本地偏移信息，不是本函数所比较的 UTC 时点未知；不因此新造失败值。不同表示的时点相等不许可替换日志里的原 `timing`，MR4 与 opened 的原值关联仍按 D088 消费。

## 精确比较算法与资源边界

以下内核针对**已满足所需合法性前提**的两条原串；接收器不能用该前提掩盖 TL-G1。其返回次序不需要累计闰秒数，因为它不求两个时刻相距多少秒、也不转换为 TAI 或 epoch 毫秒。

1. 完整扫描词法，读取有限日历字段及小数在原串中的起止位置；确定日历与偏移字段是否合法。字段宽度固定，不用无界回溯或递归解析。小数只保留切片边界，不解析成 Number；原输入不改。
2. 得到本地日期的整数日序。候选实现采用公历计算：年 y 前的日数为 `365*y + floor((y+3)/4) - floor((y+99)/100) + floor((y+399)/400)`，再加当年月之前的天数、必要闰日与 `day-1`，以0000-01-01为日序0。月天数是历法常量，不是业务策略。也可复用等价且已证不滚动非法日期的有限字段构件；两者不可各自定义合法域。
3. `utcMinute = dayOrdinal*1440 + hour*60 + minute - signedOffsetMinutes`。正偏移减，负偏移加；Z/z/±00:00为0。本地四位年加最大偏移下，全部整数运算绝对值低于60亿，适合精确 Number 整数运算；不必为有限字段另建大数平台，也不能把无界小数混入这个界限。静态60检查用归一化后的 UTC 日和日内分钟；偏移最多跨相邻一天，有限日历进退须正确跨月／年，内部 UTC 年可为−1或10000，不能沿输入四位年边界截断。内部无需书写扩展年字符串。
4. 临时次序键为 `(utcMinute, second, fractionDigits)`。先比 utcMinute，再比 second，最后按小数位从左到右比较，短方超出位视为0，扫到较长者末尾；全相等返回0。虚拟补零不分配最长字符串，不删改原串。两条合法正闰秒在不同偏移下得到同一个 utcMinute/second=60；该分钟的59.x先于60.x，60.x先于下一分钟的00，不能把60进位成下一分钟00。负闰秒的不存在标签由接收合法性责任排除，不需要在排序键中补出一秒。
5. 比较全部结束后只返回 -1/0/1。该键是内部比较工具，不是新持久 Instant，也不作为时长相减的计量单位。反身、反对称、传递和时区等价均须测试；不能从这套排序算法推出实际观察发生过或时钟单调。

设两条输入长度为 n/m，词法接收与最坏小数比较时间 O(n+m)，额外状态为固定数量的索引和有限整数；若宿主字符串切片会复制，其额外空间最多 O(n+m)，不得建立跨调用缓存。没有分配与 `10^fractionLength` 成比例的数，没有固定精度上限。接收巨大有限输入会花与输入相称的时间；需要外层资源上限的 owner 仍自行处理其输入接收，不可在本函数偷偷把合法长小数四舍五入成相等。真实吞吐和内存测量列 TO-V9，不声称无限输入具有有限常数耗时。

## TL-G1：两种公开责任与真实调用前提

OE1 S-22／OE2 引用 RFC3339；其 §5.7 使 `:60` 是否存在依赖当月实际正闰秒，负闰秒还影响 `:59` 的合法性。当前 public validator 不断言 format，旧 millis 解析器一律拒 `:60`，两者都不是已接受完整闰秒事实的给出方。候选扫描器能判字段、日历、偏移及 UTC 分钟位置，**不能凭日期形状证实实际公告**。

| 公开责任候选 | 最强理由、实际输入和保证 | 代价、失效与建议 |
| --- | --- | --- |
| **R1：合法 RFC3339 时间点前提下的纯排序（本页建议）** | 比较器检查可静态判的表示、日历、偏移，然后精确排序；对所有合法普通／闰秒值都不丢精度。实际闰秒合法性由调用路径先行保证；无需累计表、公告 IO 或新服务 | ok 不构成完整合法性证书，调用者必须在真实边界兑现前提，不能只写一句注释。前提不成立的值不在排序保证内；未核的未来正／负闰秒不能由该返回值放行。足以提供 MR4 所缺比较原语，runtime 完整关联仍有 TL-G1；中高置信，待独立评审 |
| R2：unknown 的完整接收并排序 | 外部调用方得到完整是否合法／顺序的一个结果，不会误把条件排序当校验器；闰秒公告事实需要显式来源、覆盖范围和更新 owner | 缺事实必须可表达不可决定，不能归 invalidInput；当前 Parsed 不能表达，须重新给出精确公开结果及消费映射。无已采用事实输入时不能实现其全域承诺。本轮不为它新增表／时间服务；若无法让真实调用路径承担 R1 前提，需主线另行闭合此责任，不能悄改 R1 |

R1/R2 是技术公开责任的候选比较，不从 brief 的拟议 unknown→Parsed 签名反推产品政策。建议 R1 是因为 MR4 要求对已有合法时间点判顺序，OE 已有时间值语义，新增外部事实认证没有已定提供者；**建议不等于降低 runtime 全批合法性要求**。若主线采用 R1，core 可实现完整合法域的条件排序；runtime 在没有真实前提证据时仍不能宣布关联合法。R2 不能靠“暂不支持60”伪装完成。

本页**没有**增加闰秒表／网络查询／时间服务，没有把 RFC 附录历史表冒充永远完整，没有把所有60当合法或非法。合法性已由有效责任证实的闰秒值可以使用上述顺序内核；普通域精度不因此放宽。若需要改变已冻结接收承诺或新增规范失败语义，回规格演进；本页不自行裁定。

**runtime 的调用顺序与实际 owner**：先按 D088 捕获原值并执行完整 MR4 表示接收，再由原 runtime／回复生产者与实际宿主证明这些时间值来自其符合 MR4 S-17 的真实生产路径；读回时沿 G29-P 的已核合法历史／共同写方来源，不能用“Schema过了”或客户端 `trusted=true` 替代。真实时钟产出、字符串书写与进入 timing 的路径需要具名源码和独立制品／组合证据；只证明使用了旧 Clock 接口，不自动证明外部闰秒合法性。面对未核外部时间、未知历史或不具备必要闰秒前提，原关联认回按 RT4 S-70 的“原值不可确认”保持 unavailable，不将 helper 的 ok 当作合法批、不写响应或发出 retry。相应 owner 无法提供此前提时，TL-G1 仍阻断这段生产接线，主线须选择 R2 所需的明确责任或其他经接受的承接，而非默认不存在闰秒。前提成立后才消费本排序结果判断 MR4 大小关系；opened 原字符串关系、同源性和实际观察事实仍独立核验。
