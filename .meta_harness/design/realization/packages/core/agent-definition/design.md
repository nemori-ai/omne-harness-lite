# agent-definition 实现设计

本页是 2026-09-27 rev 1 候选；所有新增导出、技术类型及源码组织名均为**候选**。本文中的 S-n 指 [`data.agent-definition/v1`](../../../../spec/data/agent-definition/v1/contract.md)，其他坐标写全。源码尚未建立，表中均为拟兑现点。

## 实现路径与来源

按[读取链提案](../../../../record/proposals/model-request-adaptation/read-projection.md)建设一个 TypeScript 纯模块，复用 [content-blocks](../content-blocks/design.md) 的严格无损 JSON 与中性 Schema 技术入口、[asset-model](../asset-model/design.md) 的共有表示，以及 tool-definition/model-profile 的精确 Schema。只自建两个槽位的约束组合、跨项排重和提取；不另写 JSON 解析器、任意 Schema 等价判定器或时长数值系统。

Cordis 的已接受版本为 4.0.4（[D-025](../../../../record/decisions/cordis-adoption-version/decision.md)）。**本节点不依赖或调用 Cordis**，没有服务键、inject、fiber、effect、事件、身份或 LLM 基类；因此不以任何 basis 条目推导运行行为，也没有未核对的 Cordis API 主张。模型贡献的热更新由模型节点负责，本正文规则按消费者选定的代码版本调用。

## 公开面与校验路径

候选公开入口 `@omne-harness-lite/agent-definition` 暴露下列独立函数；调用不需要 runtime、会话、租户或存储。它们接受共享的无损 `JsonValue`，不把 TypeScript 类型当成接收边界已经严格解析的证据。

| 候选导出                                | 实现边界                                                                                                                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AgentDefinitionBody`、`AssetReference` | 对应本契约两份 Schema 定义；前者保留 body 的未知 JSON 成员，后者按 S-3 投影既有共享形状。`CapabilityId`、`AttributeDeclaration`、`JsonValue` 直接使用各自现有公共类型，不另立领域定义 |
| `judgeAgentDefinitionBody(body)`        | 结果为 `{ ok: true }` 或 `{ rejected: 'malformed' }`；完整判断两槽位，不返回局部成功，不查询目标资产                                                                                  |
| `extractAgentDefinitionInputs(body)`    | 使用同一判定逻辑；成功交 `{ ok: { references, attributes } }`，失败交同一局部拒绝。两集合从同一次 body 输入中取得，并以无损复制隔离调用方后续修改；不交求值结果、来源身份或默认补值   |
| `./schema`                              | 发布规范 agent-definition/v1 Schema 的原字节与原 `$id`；显式使用 `#/$defs/AgentDefinitionBody` 或 `#/$defs/AssetReference`，根 Schema 不是 body 校验器                                |

接收原始 JSON 的消费者先调用 content-blocks 已有 `readJsonStrict`；重复键被解析器拒绝后不得继续。已解析输入的消费者必须能证明其严格无损来源，不能经 `JSON.parse` 舍入后再用本包给它补发保证。持有完整正文的一方经现有无损写入器保留其余成员；本包不创建只剩两个槽位的新正文覆盖原件。

候选实现将固定 Schema 判定与跨项判定合成一条只读路径：Schema 守形状、声明种类、规范域和默认值；额外按精确 capability 排重及按 item 排重。对象成员顺序不影响规范域比较，`allOf` 数组顺序不能改；额外关键字和看似等价的 Schema 也拒绝。只使用预置的本地 `$id` 资源，不解析作者提供的远程 Schema。Duration 的合法表示复用 TD3，正值判定保留原字符串的精确意义，不转成 Number 毫秒；调度器能否承受其范围不在这里判。

输入不修改，成功复制保留引用数组和声明数组的原顺序及缺席成员；数组的保存顺序不变成装配执行次序。`resident` 缺席不补 false，合法时长不换单位，空数组不补声明。内存内编译只针对有限的固定规范资源，不按作者 body 建模块级缓存。

固定资源图按 `$ref` 精确版本封闭；同一图中的 v2 与 v3 使用各自原 `$id`，不可将旧 `$id` 指到新内容。当前 CB、AM、TD 已有公开 `./schema/v2`；其余传递资源若仍由规范引用，必须从所属包的公开精确版本入口取得。未导出的资源由资源 owner 补公开出口，再由制品消费测试核闭包；不穿透别包私有目录、不抓网络、不用空 Schema 占位、不把能力求值包拉回本 data 包。AD-G3 登记这项提供者交接，不能以源码仓库内可读代替打包后可用。

`AssetReference` 与 AE3 S-6/S-7 C14 的同形同步是定义对齐义务，测试可用两边公共入口；它不是本包对 capability.asset-evaluation 的规范或运行时依赖。根求值消费者未来单向采用本包。

## 根输入生产者的交接

根输入生产者必须在自己的授权/版本选择边界取得所选已发布 AssetVersion，完成 AM3 通用校验，再从这份版本的完整 body 调用本包。AM3 当前以 `OpaqueJson` 持有该正文；只有显式采用 AD1 的新消费者可经 CB3 公共 `readOpaqueJson` 取得无损值，不改变 AM 的通用不透明规则。

消费者把同一次成功提取的两集合、实际根 capability、记录号及版本交给 [`capability.asset-evaluation/v4`](../../../../spec/capabilities/asset-evaluation/v4/contract.md) 的 `root` 输入；`source` 由真实读取事实给出，本包不伪造证明或自行补上。失败不调用求值，不返回空集合掩盖读取失败。求值、registry 提交、manifest 现读以及 runtime 缺时限拒绝各由自己的契约拥有。本包只执行值检查，没有同一提交跨 owner 的要求，也没有供两个写入者共享的存储对象。

真实读取链的提供者与验收装配节点尚待主线指定（AD-G2）；既有 `core/asset-evaluation` 只是纯计算消费者，不是资产读取者。未经这项指派和组合测试不能把 fixture 当作真实版本来源。完整根资产初值的产品生产流程仍沿提案保留缺口，本包不从示例生成默认 Agent Definition。

## 状态、并发与失败映射

本节点没有领域状态、提交点、写权、后台任务或恢复动作；每次输入使用同一确定规则。返回集合独立于输入可变对象；共享的固定 Schema 编译对象不保留前次 body。未取得完整合法输入不产生局部集合，所有窄校验拒绝均为 `malformed`；授权失败、版本不存在、存储不可用由调用能力保留，不能折成 body malformed。

无用户配置、默认时限、密钥或启动参数。固定制品的资源不全、`$id` 错误或 Schema 编译失败是初始化缺陷：明确失败且不发布判定器，不伪造成输入 `malformed`；在插件消费者中沿本批启动失败政策收口。合法输入的错误返回和制品初始化错误保持区分。非法作者默认值则是 S-9 的表示拒绝，不能由启动默认纠正。

函数不自行写正文/诊断日志；在调用边界把拒绝类别交给消费者的观测链。观测方按 [SYS-OBSERVABILITY](../../../../foundation/observability-and-logging/requirements.md) 控制内容，不将 opaque 正文或作者 Schema 回写日志作为校验证据。

## 存储要求及成对装卸

**对存储提供者的要求：无。** S-2 的持久版本读取不由本包执行；S-9 无写入和提交。包不选数据库，不取得文件、时钟、网络、锁或环境授权。装配归属事项只有前节的真实输入来源和采用版本，见 AD-G2/AD-G3。

**装载贡献与资源：0 项；撤除动作：0 项。** 模块内固定资源为普通进程内值，无注册、监听、计时器和 disposer。消费者持有函数或结果至其自身生命期结束；插件卸载不改写已产生结果。本包无异步在途工作可被内核取消，没有需要人为建立的排空协议。

## 实施缺口与消费者影响

- **AD-G1（S-1～S-10）**：AD1 和所需 MP3 仍为 candidate；本节点仅供独立评审。owner 为主线/规格接受者；阻断本节点正式采用及任何据此声称的正文支持。
- **AD-G2（S-2、S-9）**：根输入生产者与真实资产读取、授权、固定版本交接未在本节点建立；owner 为主线指定的读取链 provider/assembly，受阻为 AE4、registry3、manifest3 至 runtime3 的真实链验收。点名消费者不代替点名写/读责任；需明确生产者节点后再核正文到 `root.source` 的实际来源。
- **AD-G3（S-5、S-6、S-10）**：MP3 的公共资源及整个固定 `$ref` 图的制品闭包尚未验证，owner 为依赖资源包与本节点实施者；受阻为新包编译和独立包消费。旧 pinned 资源不自动换版。
- **AD-G4（S-1～S-10）**：尚未建包，没有符合性或消费者运行证据；owner 为本节点实施者及独立验收者，闭合 [verification](verification.md) 的 AD-V1～AD-V7 后才能登记实际绑定。完整 Agent Definition 保持契约 G-1 的范围，不属于此 gap 的填补目标。
