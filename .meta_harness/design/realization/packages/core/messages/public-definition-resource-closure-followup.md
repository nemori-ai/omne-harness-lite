# MS7 / MR10 当前公开定义的精确资源闭包

2026-09-29，revision 2，candidate，未采用；新增 binding 0。本页接续 D110 已接受的 [MS7映射](v7-design.md)、[MR10映射](../model-response/v10-reference-result-design.md)，仅修正资源注册/编译根的过度扩大，不改冻结 Schema、公开类型、judge 或契约版本。相关选择与范围见[附页](../../../../record/proposals/model-runtime-reference-lifecycle/public-schema-closure-choice.md)。

## 已证差异与最小选择

旧映射把依赖资源文件内**所有** `$defs` 都视为当前公开执行入口的依赖，从 MS7 的 TD3.ModelToolEntry 扩到资产定义，再扩到旧 LC/MS；MR10 的 LC6.FailureCause 也被扩到 LC6.ModelRequest/Subject。实际根是各包公开 `SCHEMA_DEF_NAMES`：MS7 50 项、MR10 25 项，加上生产显式编译的私有成员视图。按完整规范URI+JSON Pointer只递归触达定义，不以注册一个资源文件推出它所有defs都是执行入口。

[T26原始证据](../../../../record/evidence/2026-09-29-model-public-schema-closure/README.md)在固定 `19a3b968` 上独立抽取根、沿定义引用求闭包，使用真实公共编译器：75公开defs及MR两个私有入口通过；18逐资源删除均以精确缺URI失败。静态审计96到该点core无diff。无需复写规范URI或增加 resolver；不是从静态数量猜运行通过。

| 当前执行根 | 必需原字节资源（含根，共9份） | 直接含义 |
| --- | --- | --- |
| MS7 全部50公开defs | MS7、CB3、CB2、OE1、CA3、IV1、MP5、MP6、TD3 | created精确MP6/TD3，dispatched精确MP5；TD3触达 ModelToolEntry/ModelToolName，不触达资产图 |
| MR10 全部25公开defs及既有2个私有成员入口 | MR10、CA3、IV1、MP5、CB2、OE1、LC6、CB3、MS7 | MS7仅被用到所需Assistant支路，不触达created的MP6/TD3；LC6仅FailureCause，不触达MS6/CA2 |

两个“9”表示规范资源数；MR既有按规范生成的私有成员视图资源另计，不当第十份规范，不改其已有生成规则。真实AJV可能预解析已注册资源并在第一次 ResponseId 编译时就发现任何缺项，故删除反控证明聚合根集合的最小资源图，不声称 ResponseId 值本身依赖全部九份。

冻结资源保持完整原文件和 `$id`，不裁掉unused defs，不拼接专用Schema、不把旧URI重指新字节、不远程补取。当前生产注册只保留各自九份；删除其它不触达资源的注册/import，以及仅为这些注册存在的源码/manifest依赖和无消费者出口。是否仍有别的合法消费者必须按真实根判断；本页不是删除整个仓库所有旧资源的授权。

## 对既有映射和验证的精确替代

采用本页后仅替代：MS7 v7“精确依赖、资源与绑定”的22资源全图必要性、把MR10随LC6带入MS6的判断；M7-V1/M7-G2的同类全图要求；MR10 v10“数据图”中要求其图注册CA2/MS6/MP6/TD3及旧资产链的推论；R10-V7中这些资源对MR公开根一律必要的断言；以及R10-V1关于MR所需MP6闭包的表述，其余值判断义务保持。原文冻结字节保留，当前采用以此精确范围为准。MS7 的50定义、MR10 的25定义及全部语义关系/负例不缩减。

| 义务 | 后继必验 | 已有与未覆盖 |
| --- | --- | --- |
| RC1／M7-V1、R10-V1/V7 | 生产根名单与规范/current源码一致；九资源原字节/$id；全部公开defs及实际私有编译入口完整编译；漏根/漏资源/错URI不可通过 | T26固定源候选图已证；变更后的真实schema.ts初始化仍待 |
| RC2／最小图因果反控 | 每包分别从九资源完整新图删除一项，共18例，必须缺被删的精确URI；不能以任意异常或root空Schema编译代替 | T26已有同源实际18例可按hash复用；图/编译器/根变化才针对复验 |
| RC3／删除无用依赖 | MS生产不再引LC/AM等无关Schema链，MR不再引MS6/CA2/MP6/TD3等无关注册；只为它们存在的依赖移除 | 不得仅改计数或测试而保留全部注册；有真实别用途的依赖不误删 |
| RC4／制品与冷构建 | 实际独立pack消费公开入口，当前类型/纯值关系正反例不减；通过正式冷构建检查MS/LC旧manifest环是否已消除，不能借预编译另一spoke的dist | T26原报告没有验证生产修改或当前冷构建；本页不宣称已过 |
| RC5／缺资源与版本语义 | MP5/MP6、CB2/CB3等真正可达多版本各用原资源；准确missing资源即失败，原URI不能由新版本替代 | 保留精确规范资源不等于提供旧执行路径；无价值过渡代码删除 |

不再要求为了本轮 MS/MR 验收，把每个依赖文件全部 `$defs` 也作为根全部编译。依赖包自己承诺的公开根仍由其 owner 完整验证；不因本页减少其责任。保持强校验与单轨执行，同时消除不产生保护价值的过度注册。

MR10 保留 LC6.FailureCause 原资源有真实当期引用；若下一轮连该旧LC文件也要删除，须单独迁MR后继引用。现MS7确实同时引用MP5/MP6，CB2也实际可达；用户破坏性重构要求删除无价值过渡，不允许用“只留最新”跳过精确规范变更。LC/AE后继迁移单列待主线另行采用，不是本页九资源删除的前置，也不要求完成资产、工具、Session/Run或拓展件全部执行。

没有新业务状态、持久提交、Cordis行为、第三方依赖或算法语义，无新增TLA/Alloy义务。触发复核的变化是公开根、Schema引用、私有投影、编译器解析语义或package exports；届时以实际定义闭包和因果编译反控重新核对，而不是固定“9”永久不变。
