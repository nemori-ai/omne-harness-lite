# 验证义务与方法

本页维护节点验证义务、责任与方法限制，不维护执行台账。规范与采用版本从契约及本节点 design 读取；实际实现从成员入口读取。结果、配置和反例留工作树 tmp。下列义务列出不表示实现、检查或接受完成，未决语义按原 owner 接续。

契约验证义务归 [account-identity verification](../../../../spec/capabilities/account-identity/verification.md)，版本间相同条款须逐条判断继承范围，不把本节点的一次结果自动外推到旧版本消费者。

## 覆盖缺口

- S-32 须在完整 OS 进程重启和读失败注入下同时核 verify 与 exchange；同进程 dispose/reload 不能替代。S-47 重启后同批出示物 exchange 须得同一 LoginStateId。
- S-35 的类型形状检查不能代替跨账号关联字段静态规则；S-36 九方法失败闭合和品牌参数分别核。熵下限归实现审阅，文本规则和场景不能证明熵。
- S-43/S-54 的并发须真实两个实例/连接；覆盖激活与清除、创建个人组织与清除两交错及组织引用约束阻断删除后重扫收敛。模型不证明实际存储兑现。
- S-30 的结构保证逐行对应具体装配事实，十四行协议保证跨进程须重验；线上身份只经 exchange，撤销目标的 unknown 不纳入发起方品牌限定。
- S-46 全部持久字符串/日志/事件载荷须含有效出示物正对照；恒拒无法证明秘密不泄漏。S-45 两个 Node 前提（randomBytes 失败抛出、base64url 无填充）以注入/输出形状核；签发只在提交成立后返回，碰撞不可覆盖/合并/泄露旧行。
