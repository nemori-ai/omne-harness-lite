- 源码位置：`packages/tenancy/organization-governance`——**已实现（HUB `c9b5850`）**：`src/plugin.ts`（`organizationGovernancePlugin`、`OrganizationGovernanceConfigSchema`）、`src/types.ts`（四个服务面 `OrganizationsService`／`OffersService`／`MembershipsService`／`OrganizationPurgeService` 与逐字对契约 ⑥ 的失败联合、服务名常量、本契约拥有的 `InvitationId`／`AffiliationRequestId`、读面形状、config 与事件类型）、`src/organizations.ts`／`src/memberships.ts`／`src/offers.ts`／`src/purge.ts`（四个服务面的实现）、`src/records.ts`（行解码与共用判定）、`src/runtime.ts`（共用依赖与失败映射）、`src/migrations.ts`（迁移片段 `organizationGovernanceMigrations`、`OG_TABLES`）。第二层 `tenancy` 是租户领域这个限界上下文的名字，产品负责人已拍板（[D-024](../../../../record/decisions/tenancy-domain-name/README.md)）；布局规则见[两层布局](../../../README.md#packages-的两层布局)
- 契约采用与边界依据：一个 Cordis 插件、一条 fiber，提供四个服务面（服务名 `organizations`、`memberships`、`offers`、`organization-purge`），兑现契约**全部 25 个操作**。内部三组（隶属、成员、邀约）本版不拆——「创建组织」一次提交同时产生组织行、成员记录与首位超管，接受邀请一次提交写成员记录与邀请终结记录，内核不提供跨 fiber 事务（理由在 [design.md](design.md#实现路径与来源)）。**第四个服务面是本节点新加的**：[S-53](../../../../spec/capabilities/organization-governance/v1/contract.md#s-53-清除未激活账号的个人组织) 没有授权前置，契约把「只由清除链调用」记为装配给（[S-42 第 4 行](../../../../spec/capabilities/organization-governance/v1/contract.md#s-42-装配给的保证-vs-协议须给的保证)）；把它放在一个**只有 [account-registration](../account-registration/README.md) inject 的服务名**上，是这条装配保证在 Cordis 上能落到的最具体形状，理由在 [design.md](design.md#s-53-单独一个服务名只给清除链)。**v2 不改插件边界**：同一插件、同一 fiber，多 provide 两个 v2 读面的服务名（候选 `organizations-v2`、`memberships-v2`），钉哪一版由消费者 inject 哪个名字表达、装配绑定；另导出一个事务内读入口（候选子路径 `./tx-reads`），只许 [asset-governance](../../assets/asset-governance/README.md) import
