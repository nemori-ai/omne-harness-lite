本次 PF 修订的影响与未兑现范围见 [README](README.md) 开头。下述既有形状不是新增生产语义的接受或实现声明。

本节点是 [PF-017 治理中心作为一个可部署应用](../../../product/PF-017-governance-center-as-deployable-application/README.md)（rev 7）的应用装配——
PF-017 有意不在治理中心身上用「交付面」这个词，本节标题只沿用节点模板——并承接

**本程追加（设计已接受，尚未实现）**：同一进程再装资产提供者与模型档案目录的中心插件 P-1（[当前选择](#技术栈采用)：承载已超出租户领域、现在不改名）；它们兑现的契约都是 `accepted`，本版**对外不可达**（入口契约 v1 路由表封闭），[design「本程追加」](design.md#本程追加资产治理与模型档案目录的中心侧候选尚未实现)。
**它是一个采用型装配**：不选产品政策，不拥有能力语义，每一处选择都指向决定、契约或某个 provider 节点。

## 拓扑与进程模型

**进程模型：一个 Node 进程，入口 `src/cli.ts`，两条子命令。**`tenancy-host serve` 从环境变量起治理中心（`boot()`），收到 `SIGTERM`／`SIGINT` 即逆序撤除（`TenancyHost.dispose()`）；
`tenancy-host keygen <dir>` 一次性写四份部署密钥。退出码：撤完 0，启动失败或撤除超过总时限 1，用法错 2（[design.md](design.md#成对的装载与撤除)）。
进程怎么被拉起（systemd／容器／手动）由 [PF-017 §8](../../../product/PF-017-governance-center-as-deployable-application/design.md#八边界与依赖) 交给技术设计，本版不定；各节点的测试进程也内嵌调用同一个 `boot()`。

| 进程                                                      | 生命周期与所有者                                                                                                                                                                                                                                                                                                                        | 承载什么                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | 崩溃或退出时谁收口                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **tenancy-host 进程**（治理中心作为应用运行时的那个进程） | 由[运维者](../../../product/PF-017-governance-center-as-deployable-application/design.md#运维者)起（`tenancy-host serve`）、运维者停（`SIGTERM`／`SIGINT`）。启动是一个整体：只读核对不过、任一 fiber 启动失败或清单错误（`PENDING`）⇒ 撤除已装的、升级快照未确认则恢复、说明原因、退出非零（[design.md](design.md#成对的装载与撤除)）；入口层开闸即「起来了」 | 一个 Cordis `Context`，按顺序装 `storage` → `clock` → `credentials` → `account-identity` → `organization-governance` → `account-registration` →（本程追加、候选：资产提供者 → 模型档案目录 P-1）→ 运维面 → 入口层；一个 sqlite 文件库（WAL），升级时旁边多一份未确认的快照；一个 TLS 监听（入口层）与一个本机套接字（运维面），**没有第三个监听**；四份密钥 PEM 只在两个持钥插件与一个核实插件的 config 里，TLS 私钥只在入口层的 config 里。**租户领域的全部事实与中心标识都在存储里**，进程不持有任何只活在内存里的领域事实（[AI S-28](../../../spec/capabilities/account-identity/v2/contract.md#s-28-依赖不可用撤除与重启时的在途归属)、[OG S-43](../../../spec/capabilities/organization-governance/v1/contract.md#s-43-依赖的提供者不可用)、[S-34](../../../spec/compositions/governance-center-entry/v1/contract.md#s-34-起来即整体停机时在途请求归谁)） | 在途调用按各自那一次存储提交收场（内核不取消在途调用）；sqlite 由 WAL 恢复到最后一个完整提交；`clock_lease` 未收回 ⇒ 下次启动至多等一个租约宽度（[clock 节点](../../packages/infra/clock/design.md#状态并发与失败映射)）；启动途中崩溃留下的未确认快照，下次启动先恢复——开闸在确认之后，被恢复掉的只有启动自身的写（[两步开闸](design.md#两步开闸就绪与开闸分开)）。**退出不是取消、不是失败** |

**没有子进程、没有工作线程。**`scrypt` 是 CPU 密集计算，credential-verification 节点把并发上限归装配的运维关注点；本版不做限流，记在[实施缺口](design.md#实施缺口与消费者影响)。

## 交互面

**本应用没有人直接操作的界面**：人与脚本经客户端（`apps/cli`）到达入口层，运维者经本机工具到达运维面。五份契约的服务面只在进程内被解析。本节登记三个入口与归属：

| 面                                           | 入口                                                                                                                                                                                                                                            | 语义归谁                                                                                                                                                                                                                                           | 精确形状归谁                                                                                                                                                                                   |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **客户端一面**（人或脚本经客户端到达本进程） | 入口层的 TLS 监听，地址来自 `OMNE_TENANCY_ENTRY_LISTEN`；27 条路由加公开体检，**封闭**                                                                                                                                                          | 各领域操作的产品含义归 [PF-001](../../../product/PF-001-identity-scope-and-agent-constraints/README.md) 与相关 PF；认人、答复先后、拒绝同形归 [PF-017](../../../product/PF-017-governance-center-as-deployable-application/README.md)              | `composition.governance-center-entry/v1`（信封、四种入口答复、路由表、Schema）；落到 HTTPS 上的字节归传输绑定 `composition.governance-center-entry-https-json` v1（`accepted`、已冻结，D-029） |

| 核心与共享      | `packages/core/identity-values`、`core/offer-expiry`、`core/storage`、`core/kernel-basis`                                                                                                                                          | 彼此之间按各节点依赖表                                                                                                                                                                                                                                                                              | `tenancy/*`、`infra/*`；`kernel-basis/testing` 不得被产品代码 import                    |
| 内核            | `@deepseek-ai/cordis` 4.0.4 官方包                                                                                                                                                                                                 | —                                                                                                                                                                                                                                                                                                   | —                                                                                       |

**三条依赖方向的规矩：**

1. **迁移片段在各 owner 包，合成在 `apps/tenancy-host`**——表是 owner 事实的存储形状，列跟着 owner 变，片段放在 owner 包里让「迁移随 owner 列变化同步修改」这条代价落在同一个包、同一次修改；跨 owner 那条外键与合成次序只有装配同时看得见两边（[core/storage 节点](../../packages/core/storage/design.md#表结构不在协议里由装配层迁移建立两节点同一约束域)、[design.md 迁移的所有权](design.md#迁移的所有权)）。代价不因此消失：被外键引用的列改名不在编译期暴露，靠本节点的外键存在性与约束名测试在 CI 里挡。
2. **密钥只出现在三个 config 对象里**：`account-registration` 的 config 持 `activation` 私钥，`organization-governance` 的持 `purge` 私钥，`account-identity` 的持两把公钥；TLS 私钥只在入口层的 config 里；**都不经任何服务**（但挂在各自 fiber 的 config 上，同进程可达，[design.md](design.md#私钥不经服务-store-可达)）。
3. **`tenancy/*` 与 `infra/*` 之间没有 import 边**，只有 Cordis 服务名（`storage`、`clock`）——换提供者只改本应用的装载清单。升级整体性要的两个 `infra/*` 导出（`createUpgradeGuard`、`clockPreflight`）由本应用 import、不由任何 `tenancy/*` 包 import；`governanceCenterPreflight` 由本应用从入口层包 import，那个包也不 import storage-sql（核对形状靠同形的普通数据对上）。

## 分发与升级

- **安装渠道与进程管理：未钉。**本版无分发承诺；当前的消费者是各节点的场景演练，它们在测试进程里起本装配。
- **平台**：随 `node:sqlite` 与 Node `>=24 <25`；WAL 要求同一主机、共享内存可用（[研究](../../../../research/agent-harness-persistence-and-identity-infra/research.md#sqlite-运行参数在三家-tsrust-实现里一致)）；运维面的 Unix 域套接字不承诺 Windows。
- **升级 = 停着的时候换一个版本再启动**（[PF-017 §6.9](../../../product/PF-017-governance-center-as-deployable-application/design.md#69-升级同一个中心要么整体成要么整体不成)）：Kysely `Migrator` 的登记表在库里，启动时在 `provide('storage')` 之前先做只读核对（数据格式版本能否接手、时钟未回拨），有待跑迁移就先建快照、再跑合成后的迁移；
  全部 fiber 起来之后确认快照，确认之后才放行入口层开闸，所以确认之前任何一步失败都恢复快照、没有对外提交随之消失，旧版本照常能起。**不用 `down` 回滚**；编号名只追加（M-9）。
  **pg 上这一条本程不兑现**：迁移单事务成立，迁移之后的失败撤不回（缺口 U-3，pg 首跑前定手段）。机制与其余缺口（同一份库的排他、确认之后的开闸失败支）在 [design.md](design.md#升级的整体性迁移前只读核对快照与确认)。磁盘要多容纳一份库的大小。
- **升级时的语义保证不归本页**：撤除次序与在途工作的收场在 [design.md](design.md#成对的装载与撤除)；跨协议版本不承诺兼容窗口，版本对不上客户端得 `version-mismatch`（[入口契约 S-8](../../../spec/compositions/governance-center-entry/v1/contract.md#s-8-协议版本与跨版本不变的两样)），中心与客户端一起升级是运维者的事。
- **密钥文件与库文件的备份、权限与迁移是运维约定**；本节点只规定文件权限的检查（[design.md](design.md#密钥装配两对-ed25519-密钥作为部署配置输入)）。
