## 工作区接入的适用范围

既有治理与 Docker 装配不承担工作区登记、关系解除、销毁级联或来源装载协议。PF-020 的工作区身份、实例、地址与参与关系不能从现有数据库或中心进程拓扑推定，Git 托管拓扑亦未因此确定。

实例本地来源与租户层私有内容分开。现有账号治理契约不以工作区实例单租户为前提。组织参与限制与共享/本地内容边界的新增配置和执行路径，仍由工作区协议及其后续条件阶段承接，不能仅凭产品引用宣布实现。

外部仓库不因首次登记产生 Omne 治理所有者。组织限制启用时，不因此授予工作区身份或加载其装配来源。普通目录访问沿原权限，不新增文件系统隔离或运行中会话立即终止保证。产品规则不自动成为已接受业务协议。

## 当前装配与责任

当前交付目标是一个进程中的 SQLite 治理组合，按应用的发行/运维插件树核验职责。稳定行、公开插件引用及配置投影归应用源码。运行资源、守卫、检查函数和完成回调由具名服务注入，不以历史清单或固定 fiber 数量判断资格。

本应用承担四组责任：

1. 存储与迁移：各 owner 导出片段，宿主合成次序、编号名及跨 owner 外键 `organization_owner_account_fk`。账号与个人组织保持同一保护域。迁移前只读核对数据格式、时钟和中心标识，SQLite 在迁移前建快照，未确认启动失败须恢复。守卫绑定真实实例，复制配置不能伪造确认。
2. 时钟：同一装配使用唯一时钟实例。启动期回拨、时钟不可读或判定写失败均阻止启动。租约记录与生产库不得由未受守卫的实例或手工写者改变。
3. 密钥：两对 Ed25519 激活/清除密钥由配置载入，私钥只到产出方、公钥只到核实方。数据接触之前核配对，缺失、二义、非法、权限过宽或不配对均使启动失败。当前不轮换密钥。
4. 网络与维护：运维面先于入口，两者位于业务提供者之后。宿主提供 TLS、监听地址、套接字目录、等钟上界、部署参数和日志，并保持维护资源直到真实关闭完成。客户端据点副本、代理和防冒充确认归客户端。

准备失败不得产生数据库、目录或监听器。装载须分别观察管理工作的 ready、fiber ACTIVE、声明服务可见与代际仍有效。全部就绪后确认升级，再兑现同代 EntryOpening，入口再核钟并观察 serving。不能半开服务。

停止先关闭准入，再等待已有业务、维护和 setup 前缀真实收场。依赖与资源按责任逆序释放，核对维护完成状态和升级守卫后再撤外部资源服务。诊断阈值只报告未完成项，不授权强制释放。初始错误与收场错误均须报告。

## 分层状态与明确缺口

已迁整体性质以应用 SPEC 为准，旧 [实现设计](design.md)只接续未迁责任、存储要求与未来增量。原 AI S-30、OG S-42、AR S-25、OE S-17、IV 第六节和入口 S-36 的“装配给”逐行归属仍从 [承接表](design.md#归装配的事项逐条承接)读取。提供者义务、客户端义务和协议给不能混算为宿主完成。

SQLite 使用 WAL + FULL，耐久前提限于操作系统、文件系统和设备正确兑现同步请求。该配置与进程崩溃验证不等于物理断电、磁盘毁损或整机恢复保证。

PostgreSQL 当前在宿主启动前拒绝。连接锁断开时的收场 U-2 与迁移提交后装配失败的整体恢复 U-3 尚未闭合，受阻消费者是 PG 部署，不能以迁移单事务或共享存储类型可用开放生产升级。

确认后到开闸之间的失败 U-4 沿限定收场：不丢已确认提交，不恢复已确认快照，旧版本不能据此再起，须核钟后用同一版本重启。等 serving 有界，失败不得报告启动成功。

租户残留选择清扫的触发/节奏归 OG G-13；未激活清除的候选记录枚举和清扫提供者归 AR G-6。公开链不自动产生后台扫除能力。网络边界仍承担限流和试探防护，内网可达不等于任意账号可信。

## 未实现的中心增量

资产治理、模型档案目录与 OG3 时刻的中心装配已接受设计，尚未实现，精确范围见 [追加设计](design.md#本程追加资产治理与模型档案目录的中心侧候选尚未实现)。节点名暂保留，承载内容稳定后再统一处理命名。

该增量须承接新增插件与撤除次序、三组迁移片段、官方件与档案清单发布、启动登记、两个保留期和出厂格凭据引用。P-1 在中心不提供取值面，版本绑定不能从现行服务键推定。官方清单登记或装入失败须阻止启动，`manifestNotNewer` 沿目录契约规定收场。

中心不能有 `asset.*` 订阅者，须保留静态负控与实际开闸前检查。AG S-50、AT S-34、OG3 S-42 与 MPD S-22 的跨 owner 责任按追加设计逐组承担，不能扩大精确同提交例外。

未闭合责任分别是中心各面对外可达的入口 U-6、严格递增时刻的时钟条件 U-7、跨发布清单序号单调 U-8、凭据取值保管方 U-9、官方清单内容 U-10。时钟现行能力从其拥有者核对，不能由接口迁移推断新增时刻义务完成。

## 分发、维护与验证边界

当前分发和命令归应用 README、[部署入口](../../../../../apps/tenancy-host/deploy/README.md)与 [Docker 部署入口](../../../../../apps/tenancy-host/deploy/docker/README.md)。节点理由从 [可搬运归档](packaging.md)、[维护绑定](maintenance-binding.md)与 [Docker 映射](docker.md)定位。健康探针同进程消费公开 main，不另建第二套治理装配。

[验证义务](verification.md)要求真实 SQLite 文件库、TLS、Unix、实际插件组合、双进程与子进程终止，以及失败恢复、确认前关闸、换代和晚完成。应用构建、类型检查和局部测试不能替代这些组合，跳过不计通过。[绑定表](bindings.yaml)只在各自条款与前提成立时适用，基础探针和入口模型不能证明宿主实现。

首次工作根创建须串行，原位源变动的精确 hash/fstat 分支须独立验证。恢复只保持隔离，不授予安全重新开放。TUI 限于采用的终端 profile，不能推出任意终端支持。Docker 有限验证不覆盖实际公司部署、原生 amd64、专门 TUI 到 Docker 操作或独立整机灾备。模拟 amd64、Mac 内的 Linux Engine 与同机备份均不能代替对应真实环境。Agent 工作会话、Web/desktop 不属于此治理部署范围。

当前契约由实际拥有者维护。候选比较、接受过程和每次执行结果留本工作树 `tmp/`，不在本页维护运行台账。
