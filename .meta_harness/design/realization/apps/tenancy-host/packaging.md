# 治理中心可搬运归档 · 候选

这是 PF017 rev4 单机交付的开发分发提供路径，接续单机候选分发A。尚未采用；只把现有 keygen/serve 应用与其生产依赖完整搬离仓库，不增加治理操作、不改 EC2/HT2、迁移或存储语义。每日备份、隔离恢复、服务管理器和安全再开放分别保留原缺口，不能靠归档宣称交付完成。

## 分发对象与所有权

节点消费目前已接受并实现的装配与公开入口 `apps/tenancy-host/dist/cli.js`，固定 Node24.21.0、pnpm10.28.1。主线原型已从仓库外生产闭包运行真实中心，并经 Docker Linux 与 macOS 客户端互联验证；原型不是最终打包器的证据。目标是同一类 `app/` 归档，附精确文件清单、BUILD_ID、运行说明。预装 Node 为显式前提，当前验证目标 Linux arm64/amd64 与 macOS arm64；没有验证的平台不写为已通过。

中心运行时仍只有已有清单和 Cordis 装配；归档工具是开发进程，不进 Context、不增加 fiber/service/inject/event。keygen 生成物、TLS 私钥、中心数据库、运维套接字、备份目录均不是构建输入，也不能进入制品。

## 与 CLI 分发的共同实现

不从另一应用导入私有工具，也不复制 D050 的归档发布算法。把现有 `apps/cli/tools/package.ts` 中只负责文件闭包/校验/发布的算法移到新的开发工具成员 `tools/artifact-builder`，经公开入口导出；两个应用的薄适配各自给明确成员名、README、清单格式、应用版本及构建入口。它是开发工具复用，不能进入任一应用生产依赖。源码/测试在该成员的 src/tests；两个应用可通过 devDependency 消费，根 workspace 显式登记该成员。

公共输入是确定的一份分发说明：workspace 成员选择器、清单格式与版本、README 文本、源根、指定新输出；不接受任意 shell 字符串。生产命令只由两个仓库脚本给出的固定说明产生。运行算法沿 D050：构建依赖先完成 → 临时 inject-workspace-packages=true 的 pnpm deploy --prod --offline --ignore-scripts → 普通文件/内部相对链接清单 → BUILD_ID → 关闭归档并算摘要 → 同文件系统 link 独占发布 → 只清理自有暂存。Node/pnpm检查、tar环境白名单、锁/工作区配置复核、发布后输出失败不删除有效产物全部保留。共享工具不负责运行安装包，也不接受部署密钥或用户数据参数。

CLI 现有 `scripts/package-cli.sh` 和 `packageCli` 测试接缝保留并委托公共工具；D050 可观察调用形状、清单格式和失败含义不变。宿主新增 `scripts/package-tenancy-host.sh <新绝对路径.tar.gz>`，委托本应用薄适配。开发工具公共运行入口直接导出可由固定Node24去类型执行的src，类型声明由其build生成；不在工具源码中使用需要额外转译的TS形态。这样全新检出安装冻结依赖后，脚本首次运行不依赖尚未存在的工具dist；整体类型检查仍沿workspace构建拓扑先生成声明。此选择只限不分发到产品的开发工具。包自带说明只教预装Node、校验、解压到新目录、已有keygen/serve配置入口，不下载依赖、注册服务或启动中心。两个构建都要保持源与dist稳定，不能同时构建共享依赖后冒称快照隔离。

## 构建身份与启动兼容

宿主清单使用自身格式 `omne-tenancy-host-build/1`，字段与语义沿共享文件清单；BUILD_ID是排序后文件清单的SHA256，不含清单本身或BUILD_ID。宿主增加纯 `--version`，读且验证包内BUILD_ID；开发检出缺失时显示development，非法时非零失败。不加载配置、不打开数据库/套接字、不生成密钥、不查询中心。现有keygen/serve及错误用法不扩成隐式启动。HOST_VERSION保留应用协议中的版本含义，不能把BUILD_ID塞成新的协议版本或修改EC体检输出。纯版本分支在进程入口动态加载其最小读文件模块，不先加载boot依赖；它等待真实stdout写回调，输出错误由该分支拥有并返回非零，不能把既有MainIo的void stdout调用当成已写出。标识读取错误使用稳定诊断，不把原始异常或任意文件内容输出。

## 失败、生命周期与验证

暂存目录在目标父目录内，由一次构建拥有；前提是该目录可信且没有恶意并发替换、源码/锁/dist不并发编辑。构建器不负责验证取得源代码的信任，也不承诺操作系统强杀后清理或归档文件掉电耐久。已存在目标（包括链接）不覆盖；暂存或归档发布失败只处理本次拥有物。归档成功不构成安装成功。

实施前由独立架构评审核对共同算法归属与D050消费者保持，再按既有授权记录采用。验证必须包括：共享算法原故障测试继续通过；两应用适配选择正确成员/清单/README；宿主纯version不需配置；最终制品逐文件与链接核清单/BUILD_ID；只挂制品的新Linux容器启动keygen/serve；macOS客户端真实TLS治理旅程和停止/重启；制品不含运行时数据。精确版本、Node镜像、原始命令与归档摘要须封存。上线服务管理、独立备份位置和真实内网配置尚未完成时，测试不能被表述为生产接受。
