# 候选与取舍

## 选择对象与必要约束

保持租户隔离、旧代际安全、状态权威分离、动态撤除和失败可见；不以源码复用降低这些性质。

| 候选 | 必要性质如何兑现 | 总负担与关键反例 | 结论 |
|---|---|---|---|
| A：定向维护 DSH agent/scope 原语，在其上实现项目 Registry/私有实例插件 | 保留成熟 scope/initiator 机制；项目契约拥有代际、授权门、账目与退出 | 需长期维护 fork 和补足产品行为；现有源码尚未兑现完整 AgentHost | 旧 D-005 已接受其 legacy 范围；新谱系推荐等价承接，待 I 接受 |
| B：直接采用上游 `dsh-agent` 产品行为 | 复用最多，按上游生命周期和事件工作 | 上游可否决 created、资源/Registry 删除顺序和产品边界不足以兑现 AR/CB，且会把上游策略当本项目契约 | 被旧反例排除；作为真实采用路径保留 |
| C：仅用官方 Cordis 从零重建所有 Agent 原语 | 可完全按 AR/CB 实现 | 重写 scope、initiator 和实例原语，当前没有收益证据；验证与维护负担最高 | 未选，除非 fork 无法演化或许可/依赖前提变化 |

## 推荐与仍待区分的事项

推荐 A，因为它保留已验证有价值的机制并把产品语义留给自有契约。新 baseline 的接受、provider 实现与真实组合证据仍待完成；源码或 Cordis 版本变化时重新核对。
