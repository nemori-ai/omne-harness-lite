# 设计知识的准入与归属

本文件帮助 agent 判断一份材料是否值得进入设计链，以及应由哪个目录持续维护；
产品心智与通用权威边界沿用父级约定。

## 先判断失效事件，再选目录

这里保存后续需求分析、设计和维护要继续消费的知识。准入依据是持续的消费对象，
不是任务名称、文件格式或评审状态。选目录只问一个问题：**什么事件会让这条事实失效**——
产品方向改变归 product，系统目标改变归 foundation，上游换版本归 basis，语义变更归 spec，
实现换方案归 realization，已经发生的事归 record。先读[准入与停止条件](README.md#准入与停止条件)，再进入相应目录。

一次交付的计划、派发、文件盘点与进度放本次明确工作区的 `tmp/`，不作为 design topic。
不要因任务名称里出现「迁移」「重构」就另建目录；迁移的长期产物是 registry 里的血缘关系
与 record 里的接受和证据，过程材料留任务区。

创建或迁入材料前执行四步：指出任务结束后的持续消费者；判断它何时失效从而定位唯一拥有者；
核对该目录 README 的最低信息与停止条件；再从本地 `.templates/` 建包并裁剪。
任一步无法回答就停止建包，把待核对输入留在任务区；不要先创建空 topic、`plan.md`
或第二份权威等待以后补齐。

产品交流若具有持续回顾价值但尚不是正式结论，进入该 topic 的 `interviews/`；笔记只保存来源语境，
升级为正文由该 topic 的 owner 显式完成。触发与记录边界见[需求归位](../agents/skills/harness-design-handbook/canonical/references/intake.md#何时自主启记访谈)。

## 两条容易走错的归属

**多对多关系不属于任一端。** 一条产品条款可覆盖多个契约，一个契约被多条条款覆盖。
把这层关系写进产品正文，契约重分解时要遍历全部 topic；写进契约正文，产品改一次要改 N 个文件。
它归 [registry/covers.json](registry/README.md#covers)。同理，旧新身份的对应关系归
`registry/lineage.json`，不写在任一端的正文里。

**聚合视图必须派生。** 「某个对象现在是什么样」的答案全部来自别处——条款在 product 与 foundation、
承诺在 spec、绑定在 realization、证据在 record。手写它就是造第二份权威，且每次重分解都要改。
这类页面归 [views/](views/README.md) 由生成器产出，任何人不手写、不手改，也不得引为依据。

## 状态和交接红线

- 观察、推断、候选、评审、接受、发布、实现与验证分别记录；文件存在或 reviewer 无意见不能提升状态。
- 产品条款先投影到现有能力及组合；只有合理组合或扩展仍不能拥有剩余独立责任时才提出新能力维度及独立插件边界。
- 新建正式 proposal 至少三个实质候选；不足时继续 research/任务探索，不用改名、参数变化或空选项凑数。
- spec 的形式工件按性质需要选用；optional 表示不是每个 topic 都预建，已经触发的证明义务必须闭合或明确阻断。
- basis 条目必须给出 symbols 与一个在该语义消失时会失败的 probe；给不出就记为待核对主张，不作为设计依据。
- 绑定的证据可以是测试或形式任务，但**必须写明成立前提**；两种形式都拿不出时，问题在性质表述本身，
  退回把性质改写成有界形式，不新设一个「无法验证」的状态把缺证据登记成已处理。

## 按当前缺口展开

- 新建或吸纳主题：读所属目录的 README 与本地 `.templates/`；按[信息包规则](README.md#主题是信息包)裁剪，模板本身不代表知识已准入。
- 比较方案、记录接受或表达精确承诺：分别定位 record/proposals、record/decisions、spec，不能通过换目录提升状态；具体入口见 [目录地图](README.md#组织原则)。
- 现有条款与实现或证据冲突：读[规格演进](../agents/skills/harness-design-handbook/canonical/references/spec-evolution.md)，定位拥有者和消费者，不能在施工计划里重写契约。
- 需要知道某个上游机制到底保证什么：读 [basis/](basis/README.md) 的条目，不在本次分析里重新推导一遍。

普通局部修订直接接续已有主题；当前准入、拥有者与缺口清楚后停止扩展阅读，不为一次任务补齐所有目录。
进入 `product/` 工作时先读它自己的 [AGENTS.md](product/AGENTS.md)——那里的身份视角与语言要求与本文件不同。
