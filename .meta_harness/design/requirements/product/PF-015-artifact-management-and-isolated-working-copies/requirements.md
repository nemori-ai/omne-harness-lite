# PF-015：制品管理与隔离工作副本

[智能体维度](../by-agent.md) · [来源核对](../../../research/dynamic-loading-and-artifact-sources/research.md)

主维度：智能体。副维度：用户、环境。2026-09-12 用户明确制品的存储和管理
与 Agent 运行时、其宿主机解耦，能够加载到一次工作使用的文件系统，并支持
多个会话同时处理同一制品。本轮制品包括需要持久化、跨会话使用的代码、文档、
数据、报告、多模态文件等工作材料，不限于已发布的软件发行物。

## 已确认要求

C1–C3 是本轮直接要求；C4–C6 结合来源细化保存、并发和生命周期的可观察含义。
Git worktree 是用户给出的隔离示例，不是本项目已选定的存储或并发协议。

- **PF-015.C1：持久制品独立于运行时及宿主机。** 系统提供制品存储与管理
  能力，已确认保存的内容可以跨会话保留、查找和使用，其持久身份及管理不依赖
  原 Agent 运行时或原宿主机仍存在。重建运行时、更换工作宿主、回收沙盒不能
  单独导致已保存制品丢失。仅把文件留在原宿主目录或运行时内存中不足以满足
  该要求；本项不强制第一版采用远端服务或独立物理机器。
- **PF-015.C2：能够加载进实际工作文件系统。** Agent 能选择获准制品及
  相应已保存版本，把内容加载到一次工作使用的宿主机或沙盒文件系统，并能够
  辨认制品来源、版本、目标环境和工作位置。存储中的内容与正在编辑的工作副本
  分别表达；加载不得暗中改指另一个宿主、扩大访问范围或覆盖无关工作。
- **PF-015.C3：同一制品可被多个会话同时处理。** 系统提供工作副本隔离或
  等效机制，使各会话在明确基线下独立工作，不因共享制品身份而相互覆盖文件、
  改变对方工作目录或混入未确认修改。可采用 Git worktree 等方式，但目录隔离
  本身不等于租户安全隔离，也不自动完成并发成果整合。
- **PF-015.C4：保存结果与恢复范围明确。** Agent 能把工作成果保存回制品
  存储，并区分本地已修改、本地已提交、持久保存已确认、保存中、失败及结果
  未知。系统可按已确认版本重新加载和接续；未成功保存的工作不能显示为已经
  持久化，也不承诺原工作环境丢失后必然恢复尚未保存的数据。清理前应能辨认
  未保存变化及处置影响，失败时保留仍可恢复的工作。
- **PF-015.C5：并发保存不静默丢弃工作。** 多会话从相同或不同基线处理
  制品后，保存应辨认版本变化，明确分别保留、整合或冲突的结果。需要整合时
  提供可理解的冲突及处理路径；不能以最后写入覆盖冒充成功合并，也不要求
  所有文件类型均可自动合并。重试和恢复应关联原操作，结果未知时避免盲目
  重复产生不可辨认的保存或发布效果。
- **PF-015.C6：管理、工作副本与对外发布分别受治理。** 制品具有明确身份、
  所属租户、来源/版本及访问资格；Agent 能在获准范围保存、查找、选择、加载
  和管理。删除工作副本、回收运行环境、删除持久内容及对外发布是不同动作。
  发布须明确来源版本、选中内容、目标和可见范围；普通保存或加载不能隐式
  发布整个工作目录、秘密或其他租户内容。制品中的文字和脚本不会自行成为
  授权或高优先级指令，加载不同时授予执行权限。

## 产品场景

| 场景 | 应有表现 |
|---|---|
| 会话 A 保存报告后原运行时及沙盒被回收 | 会话 B 可以从制品存储取得已确认内容，在新工作环境继续处理 |
| 同一材料分别交给宿主机和沙盒中的两个会话 | 各自加载获准版本到明确工作位置；副本隔离，修改归属可辨 |
| 两个会话修改同一制品，先后保存 | 后一次保存能发现基线变化，保留各自工作并明确整合结果或冲突 |
| 保存超时，随后工作环境需要回收 | 能区分已确认保存与未知结果，不用本地文件存在证明存储完成 |
| Agent 要把内部报告交付外部 | 选择具体已保存内容、目标及可见性，按相应授权完成发布并报告真实结果 |

## 来源边界与待设计

omne-next 的受管 Workspace 要求提供重建后取得已确认版本、并发冲突和受治理
发布的产品依据；其旧 Workspace ADR 中“宿主磁盘为主、远端为备份”的装配
假设不能缩小本轮的宿主机解耦要求。旧 Artifact = Tag + Release 是较窄的
发布模型，不能取代这里的持久工作材料含义。

DSH Workspace 记录既有目录及会话归属，不能据此声称它已提供本项的独立制品
存储；文件系统抽象也只提供不同执行环境的 I/O 边界。Git/Gitea/LFS、每会话
clone、自动 rebase、目录布局和来源发布接口均未作为本项目实现选择。

制品粒度与组合、版本/引用、跨范围共享、内容与元数据的一致性、冲突解决与
保存确认协议、离线策略、保留/删除及回收规则、存储故障保证仍需设计。已确认
宿主机解耦不等于数据能承受任意存储介质灾难；独立存储的耐久保证须另行给出。
