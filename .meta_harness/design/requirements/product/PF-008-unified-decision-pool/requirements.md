# PF-008：统一决策池与跨会话直接答复

[用户维度](../by-user.md) · [来源核对](../../../research/user-governance-and-decision-pool-sources/research.md)

主维度：用户。副维度：智能体，关联请求的持续可见与答复后的工作接续。
本页的“统一决策池”对应用户本轮所说的“决策通知池”，强调其中待决定、可答复
的事项；来源通常称“决策待办池”。

## 已确认要求

2026-09-12 用户明确：智能体和系统从不同会话发起的 HITL，应在同一个地方
集中向用户呈现；用户无需回到具体会话，可直接在池中答复。

C1–C3 展开本轮直接要求；C4–C7 承接原系统有效条款及已登记要求。
[PF-005.C8/C9](../PF-005-agent-initiated-human-input-and-approval/requirements.md#已确认要求)
中通用池呈现、池内作答与可答性的正文迁到本页，原身份保留引用，确认范围不撤回。

- **PF-008.C1：跨会话、跨发起来源统一呈现。** 用户能在一个地方集中处理
  等待其输入的决定项，覆盖 agent 主动问题、主动批准请求、系统授权确认，以及
  已登记的暂行定夺。不能要求用户先记住是哪种发起者或哪个会话，才能找到待办。
- **PF-008.C2：条目足以直接作答，并保留来源。** 每项能辨认发起 agent 或
  系统、所属会话与工作、提出时间、请求类型和真实状态，可进一步定位原始
  耐久请求与上下文。问题、动作和授权的必要信息自包含，用户无需打开来源
  会话才能理解并回复；各类请求的元素由对应发起方或系统事实提供，缺失内容
  如实显示，不由池猜造。
- **PF-008.C3：池内答复直接驱动对应后续。** 用户可在条目上提供自由文本、
  批准、拒绝或该类请求支持的决定；提交后由对应请求执行其声明的后果，例如
  解除等待并接续、授权放行/拒绝、暂行产物正式生效或撤销。答复不只是写一条
  消息或“已读”标记，也不要求用户另回会话重复操作。
- **PF-008.C4：一项决定在各入口保持同一身份和真实结果。** 池内和会话内
  操作同一请求、同一合法作答者范围和同一结算语义；首个有效答复胜出，后续
  重复或竞态提交返回真实结果，不重复形成决定或接续。每条请求独立定位，
  回答一条不能误关其它待办；批量操作若由某类请求支持，也须逐项结算。
- **PF-008.C5：请求寿命独立于会话界面和运行时实例。** 条目在呈现前有
  可靠的请求/等待或暂行产物依据；关闭页面、运行时回收和重建不使其消失。
  有效答复、取消/强停、工作终态清理、显式取代及失败恢复等出口须使池内状态
  与对应事实一致，不能留下一条实际上已关闭却仍诱导用户作答的悬空待办。
  等待期限或呈现窗口到期不能充当用户答案。
- **PF-008.C6：决定状态与当前可答性分别呈现。** 待答、已答、取消、被取代
  等状态可辨；同时显示现在可答、执行设备不可达、尚未落位、暂时无法判断等
  当前可达情况。不可答不等于请求已消失或已结算，可答性投影也不承诺之后
  提交一定成功；实际失败需明确说明。对用户隐藏无助于作决定的内部节点坐标。
- **PF-008.C7：统一入口保留权限、组织和后果边界。** 集中显示不合并不同
  请求的租户、owner 或授权范围；每次读取和答复都满足原请求的权限要求，不能
  用一个条目标识代替身份验证。通知可引导用户关注并进入该项决定；通知已读、
  送达失败或重复提醒都不产生批准，不另造一份请求事实。

## 可观察场景

| 场景 | 应有表现 |
|---|---|
| 会话 A 的 agent 在问问题，会话 B 的动作被系统拦截 | 用户在同一池中看到两个可区分的待办，直接分别答复 |
| 用户在池里答复后才打开原会话 | 原会话能呈现同一答复及后续结果，不要求再答一次 |
| 用户在两个设备同时决定同一事项 | 只采纳一个有效决定，各入口最终展示相同事实 |
| 发起会话所在运行时重建，或执行设备暂离 | 条目保留，真实显示能否此刻作答，恢复后继续关联原请求 |
| 用户在池内处理系统产生的暂行决定 | 按该动作声明使产物正式生效或撤销，并显示后果与回传状态 |

## 归属与待设计事项

[PF-005](../PF-005-agent-initiated-human-input-and-approval/requirements.md) 定义主动请求的
内容、一次性批准与答复接续；[PF-007](../PF-007-system-initiated-hitl/requirements.md) 定义系统
请求及暂行确认；本页拥有它们共用的池产品要求。统一呈现和作答不要求把所有
请求生命周期合成一个模型或一张表，也不复制第二份授权/答案事实。

[PF-011.C10](../PF-011-future-planning-calendars-and-reminders/requirements.md#已确认要求)
拥有通用通知耐久落点及推送要求；其中与 HITL 关联的通知引向本池的同一请求，
通知送达状态继续不能替代决定状态。

待设计：列表与详情的信息组织、筛选/排序/分页、批量支持范围、不同组织条目
是否同屏聚合及其明确上下文、答复回传、读写一致性与恢复机制。设备离线时
预先收下决定、上线后重放，来源尚未承诺，本轮“直接在池内答复”也没有单独
裁定离线受理保证；当前不可答必须如实呈现。

[SYS-TENANT](../../system/constraints/requirements.md#sys-tenant) 与
[PF-001](../PF-001-tenant-organization-context/requirements.md) 继续约束所有条目与操作。
当前候选（迁移坐标：`.meta_harness/design/proposals/agent-core/#当前需求对应与缺口`）尚未定义
完整池读写与跨请求后果关联。本次明确产品范围，未接受新架构、发布规格或声明
实现完成；已接受治理决定及旧需求基线保持原有作用域。
