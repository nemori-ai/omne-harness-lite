# 系统需求容器

这里维护待设计系统的产品结果、系统目标与全局约束；
系统身份和要求由实际导入的正文或本次明确输入确定，不由工作区所在位置推断。

实际主题从 `system/` 与 `product/` 的入口发现；条款身份、确认范围、来源和基线由各 topic 拥有。
跨能力纵线尚待闭合的需求覆盖由本目录 `coverage-obligations.md` 汇总导航：它只投影条款、消费者与闭合条件，
不重新定义需求或替代提案中的能力覆盖分析。文件尚未存在时这是明确的集成缺口，不能向工作区外回读替代。

## 准入门槛与停止条件

- 至少能定位观察者、触发情形、所需/禁止结果、来源和确认范围；未决解释必须能与已确认条款分开。
- 缺少确认时停在 intake 或任务输入，不补造需求；机制偏好和能力划分转 proposals，不写回结果条款。

## 新建需求主题

从本地 [topic 模板包](.templates/topic/README.md) 复制为 `system/<topic>/` 或 `product/<topic>/`。
入口说明本次范围与输入，`requirements.md` 拥有条款，`changes.md` 拥有来源、确认与前提变化；
下游能力覆盖与机制选择归提案，不把需求名称直接转成新插件。

已有主题沿其入口接续；本 README 维护 system/product 索引及覆盖义务入口，不将 `.templates/` 计作已确认要求。
信息包的裁剪与引用见 [系统设计链](../README.md#主题是信息包)。
