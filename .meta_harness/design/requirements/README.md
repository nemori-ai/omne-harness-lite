# 系统需求容器

这里维护待设计系统的产品结果、系统目标与全局约束；
系统身份和要求由实际导入的正文或本次明确输入确定，不由工作区所在位置推断。

目前尚无实质需求正文。使用手册时据此记录上下文缺口，不自动读取工作区外的文档补齐。
导入时保留条款身份、确认范围、来源和基线；空容器不成为第二份当前正文。

## 新建需求主题

从本地 [topic 模板包](.templates/topic/README.md) 复制为 `system/<topic>/` 或 `product/<topic>/`。
入口说明本次范围与输入，`requirements.md` 拥有条款，`changes.md` 拥有来源、确认与前提变化；
下游能力覆盖与机制选择归提案，不把需求名称直接转成新插件。

已有主题沿其入口接续；实际导入后在这里链接各主题，不将 `.templates/` 计作已确认要求。
信息包的裁剪与引用见 [系统设计链](../README.md#主题是信息包)。
