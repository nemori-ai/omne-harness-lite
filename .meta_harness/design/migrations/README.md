# 迁移设计

本家族拥有前后采用关系、过渡约束与实际切换结果。每个持续维护的主题是一个子目录信息包，先读其 README，再按当前问题展开。

## 主题准入

只有后续消费者仍需依赖的迁移知识才建立主题：明确的前后身份或采用关系、过渡约束、
消费者切换条件及可核对的收口结果。迁移设计可以先于执行存在，但要能辨认这个持续消费对象。

一次交付的实施计划、subagent 分工、扫描清单、重试日志与进度放本次工作区 `tmp/`。
任务叫“迁移”不使这些材料自动准入；`execution.md` 保存与长期边界有关的实际切换/退出证据，
不承担施工看板。尚未收敛的筹备材料继续留在任务中，必要结论形成后再按其拥有者整理。

## 新建或接续主题

- 新主题从本地 [topic 模板包](.templates/topic/README.md) 开始，复制为 `<topic>/`；包内为入口和 `design.md + execution.md`。
- 接续已有主题先读该主题入口，保留有效正文、精确来源和实际状态，只补本次缺口。
- 设计不自动启动迁移；冻结规范、在途责任及外部事实按实际范围保护。

命名、裁剪与跨家族引用遵循 [信息包约定](../README.md#主题是信息包)。
模板自身不是实际主题；不要将 `.templates/` 中的候选占位符计入能力、决定或证据清单。
