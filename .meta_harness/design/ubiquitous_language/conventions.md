# 词条的规矩

## 一个词条长什么样

````markdown
### UL-tenant · 租户 · Tenant

> **中**：资源、数据与成本的归属边界，也是隔离边界；系统里每一个受归属约束的
> 对象都恰好属于一个租户，跨租户访问默认拒绝。
>
> **EN**: The boundary of ownership, isolation and cost attribution. Every
> ownership-bearing object in the system belongs to exactly one tenant, and
> access across tenants is denied by default.

- **出处**：[PF-001 §4 租户](../product/PF-001-identity-scope-and-agent-constraints/design.md#租户)（rev 6）
- **别混**：与[组织](terms/subjects-and-ownership.md#ul-organization--组织--organization)不是一回事——组织是租户的**一半**，另一半是账号
- **弃用**：~~「空间」~~、~~「工作区」~~
````

> **示例里的相对路径按各卷的实际位置写**：词条在 `terms/` 下，
> 指向产品 topic 要多退一层（`../../product/…`）。

**标题三样一次看全**：稳定 ID · 中文名 · 英文名。

| 字段 | 必填 | 说明 |
|---|---|---|
| **ID** | ✅ | `UL-` + 英文名的 kebab-case。**改 ID 等于换概念**，不为措辞微调改它 |
| **中文名 / 英文名** | ✅ | 各一个，**不并列两个**。有别的叫法就进「弃用」 |
| **中 / EN 定义** | ✅ | 各自在本语言里**自然且精确**——**不是逐字互译** |
| **出处** | ✅ | 定义的**依据**在哪个 topic 的哪一节，带 rev |
| **别混** | 按需 | 最容易和它搞混的那一个，**以及差在哪** |
| **弃用** | 按需 | 曾经用过、今后不要再用的说法 |

### 名字必须够具体，不许占用通用词

**这是这里最容易犯、而且最贵的错。**

一个通用词被定义到一个很窄的概念上之后，**它在别处的正常用法就全成了冲突**——
而那些用法是躲不掉的，因为它们本来就是那个词的常见意思。

| 想叫 | 出事的地方 | 应当叫 |
|---|---|---|
| ~~`Role` 角色~~ | 消息也有 role（user / assistant / system） | **`Tenant Role` 租户角色** |
| ~~`Layer` 层~~ | 系统里到处是「层」 | **`Scope Layer` 作用域层** |
| ~~`Context` 上下文~~ | 给模型看的上下文、Cordis Context | **`Runtime Context` 运行时 context** |
| ~~`Injection` 注入~~ | 依赖注入 | **`Runtime Injection` 运行时注入** |
| ~~`Composition` 组合~~ | 作用域合成也叫 composition | **`Asset Composition` 资产组合** |
| ~~`Lineage` 血缘~~ | [registry 已有一份血缘](../registry/README.md)（身份谱系） | **`Transfer Lineage` 转移血缘** |

**判据一句话：**

> **这个词在别的上下文里，会不会也被用来指别的东西？**
> **会，就加限定词。**

加限定词**不会**让文档变啰嗦——**词条给的是正式名，正文在没有歧义的地方可以简称**。
在讲租户治理的一段里写「角色」没有问题；**跨 topic 引用、写规格、做翻译时用正式名**。

**反过来也别矫枉过正。**`Account` `Organization` `Tenant` `Sandbox` 这些
虽然常见，但**它们在本领域就是这个意思**，业界也这么用——**加限定反而不自然**。
要加限定的是**被收窄了的**通用词，不是**本来就是这个意思**的常用词。

### `runtime` 这个词，本系统写死了

> **凡以 `runtime` 为中心词的对象（`X Runtime` / 「X 运行时」），都是一个协程：**
> **有独立的执行上下文，能在 await 点挂起与恢复，能被独立取消，有自己的生命周期。**
>
> **其中兼任调度者的——持有待处理队列、循环取事件并分发——同时是 event loop。**
> 这是**附加身份，不是准入门槛**。

产品负责人 2026-09-20 直接裁决，依据与推理链在 [UL-D-3](decisions.md#ul-d-3--runtime-与活体--2026-09-20)。

**判断位置，不判断字面**——`runtime` 在哪一侧决定它受不受这条约束：

| 形态 | 它是什么 | 受约束吗 | 例 |
|---|---|---|---|
| **`X Runtime` / 「X 运行时」**（中心词） | 一个**东西** | **受。必须是协程** | [agent runtime](terms/agent-runtime-loop.md#ul-agent-runtime--agent-runtime--agent-runtime) · 模型请求运行时 · 工具执行运行时 |
| **`Runtime X` / 「运行时 X」**（定语） | 「在运行期发生的」 | **不受** | [`Runtime Context`](terms/scope-and-resolution.md#ul-runtime-context--运行时-context--runtime-context) · [`Runtime Injection`](terms/agent-runtime-loop.md#ul-runtime-injection--运行时注入--runtime-injection) |

中文语序刚好能分：**`runtime` 在后是名词，在前是形容词。**

**这条规矩是用来判的。**拿它量过之后被判出去的，[Run](terms/agent-runtime-loop.md#ul-run--运行--run) 是一个——
它是若干协程实例的**逻辑包络**，没有自己的执行上下文，**所以它不叫 runtime**。

### 出处为什么必填

**没有出处，词条就是第二份权威。**

**出处只有两种合法形式：**

| 形式 | 用在什么时候 | 长什么样 |
|---|---|---|
| **指向某个 topic 的某一节** | **绝大多数词条** | 链到 `PF-001 §4「租户」`，并注明 `（rev 6）` |
| **指向 [decisions.md](decisions.md) 的一条** | 这个概念**不归任何一个 topic**——跨全链的治理概念，被很多 topic 引用却没有哪一个拥有它 | 链到 `UL-D-1`，并注明是**谁、哪天**直接裁决的 |

**没有第三种。**指向 topic 的那种要带 rev——**topic 升 rev 时，
照着 rev 就能找出哪些词条要复核**。

> 一条查不到出处的词条，说明它是**在这里被发明出来的**。
> 那是[红线](../product/AGENTS.md#红线)：**不发明没人拍板的东西。**

**第二种形式不是后门。**它成立的条件很窄：**这个概念确实跨全链、确实没有归属，
且产品负责人确实直接裁决过**。三条缺一，就该回去找那个 topic，
或者把它提给产品负责人——判据见 `product-design` skill 的「什么时候问，什么时候自己定」。

## 中英文定义不是互译

**两条定义各自独立成立**，讲同一件事，但**各自用各自语言里自然的说法**。

| | ✗ | ✓ |
|---|---|---|
| **中** | 一个代表隔离边界的容器对象 | 资源、数据与成本的归属边界，也是隔离边界 |
| **EN** | A container object representing an isolation boundary | The boundary of ownership, isolation and cost attribution |

左边那种是**把另一边逐字搬过来**的结果：中文读着像译文，英文读着像中式英语，
**两边都不精确**。

**英文名用领域惯用词**，不自造。拿不准时看这个概念在
[spec/](../spec/README.md)、[basis/](../basis/README.md) 或上游文档里
已经叫什么——**已经有名字的，不另起一个**。

## 什么配有词条

**五条都过，才收。**

| 判据 | 问自己 |
|---|---|
| **跨 topic** | 它被**一个以上** topic 使用，或显然会被 |
| **误读有代价** | 读错它，会有人**把设计或实现做错**——而不只是读着别扭 |
| **写得出无歧义定义** | 写不出来，说明**它还没想清楚**；那就先别收，去把它想清楚 |
| **不是实例** | 它是**一类**东西，不是某一个。`Tools()` 是 **meta tool 的实例** |
| **不是修辞** | 「门」若只是比喻，不收；若它**承担了精确所指**（= meta tool 的那个入口），收，并写明它等于什么 |

**反过来，只要在两个以上 topic 出现、且含义必须一致的名词，一律要收。**
漏掉一个，那个词就会在第三个 topic 里被重新发明。

## 分卷按「它回答什么问题」

**卷不是抽屉，是语义维度。**选错维度，整套词表会在第一次重构时全部搬家。

**两个看着顺手、实则会塌的维度：**

| 别按 | 会怎样 |
|---|---|
| **按来源 topic 分**（PF-001 一卷、PF-002 一卷……） | 同一个概念被多个 topic 使用，**于是它有好几个家**——**那正是统一语言要消灭的东西**。而且 topic 一重排编号，卷就全错 |
| **按被描述的对象分**（会话一卷、工具一卷、消息一卷……） | **对象会被重新分解。**今天「工具」是一类，明天它拆成「调用定义」和「执行体」，这一卷就得拆 |

**按「它回答什么问题」分。**问题不会因为编号重排或对象重分解而改变：

> **谁 · 怎么算 · 由什么构成 · 怎么流动 · 怎么来怎么没 · 落在哪 · 怎么来往 · 留下了什么**

**检验一个分卷对不对，只有一个办法：**

> **看同一个来源 topic 的概念有没有被分到不同卷。**
> **全都落在同一卷，那这个卷就是那个 topic 的马甲。**

例：PF-001 的概念散在四卷——账号/组织/租户去了「主体与归属」，
层与合成语义去了「作用域与求值」，资产与设置权限去了「能力与构成」，
拥有/获权/选用去了「流转与授权」。**这才叫按语义分。**

**卷的数目要少。**放不进任何一卷就新开一卷，是最容易犯的懒——
**多半是那个概念自己还没想清楚**，而不是维度不够用。

## 无歧义怎么自检

**写完一条定义，跑这三个测试。过不了就重写，不要「差不多就行」。**

| 测试 | 怎么做 | 不过说明 |
|---|---|---|
| **替换** | 把正文里这个词**换成定义原文**，句子仍然成立、意思不变 | 定义**比这个词多说了或少说了**东西 |
| **边界** | 说得出一个「**差一点就是它、但不是它**」的东西，并说得出差在哪 | 定义**没划出边界**，只是在描述典型情况 |
| **独立** | 不看 topic 正文，**只读这一条**，能判断手上一个具体东西算不算它 | 定义**在偷偷依赖上下文** |

> **最常见的失败是「独立」测试。**写的人脑子里装着整个 topic，
> 于是写出一条**只有他自己读得懂**的定义。

## 加一个新词条

**顺序是硬的：先有词条，再在正文里用。**

| 步 | 做什么 |
|---|---|
| **1** | **查重**——从 [index.md](index.md) 搜，**连[弃用说法](#一个词条长什么样)一起搜**。已经有了就用现成的，**不要因为「我这个语境不太一样」另起一个** |
| **2** | **取名**，过一遍[「名字必须够具体」](#名字必须够具体不许占用通用词)那一关 |
| **3** | **[选卷](#分卷按它回答什么问题)**。放不进任何一卷，多半说明它还不是一个清楚的概念 |
| **4** | **写齐必填字段**，出处指向**已经拍板的东西** |
| **5** | **跑[三个自检](#无歧义怎么自检)**。过不了就回去把概念想清楚 |
| **6** | **在 [index.md](index.md) 加一行** |
| **7** | **然后**才在 topic 正文里使用它 |

**第 7 步之前不要动正文。**先写正文再补词条，补的时候人已经默认那个词
是对的了——**查重和自检会走过场**。

**第 6 步漏了，下一个人就查不到重。**索引是手写的，不是生成的——
**因为查重发生在加词条之前，靠生成器的索引永远慢一步**。

## 改一个词条

**改定义 = 改语言。**

| 改的是 | 怎么办 |
|---|---|
| **措辞更清楚，所指没变** | 直接改，更新出处 rev |
| **所指变了** | **这是 topic 的产品变更**，先在那个 topic 里记 changelog 并升 rev，**再**回来改词条 |
| **发现两处说法对不上** | 记进 [conflicts.md](conflicts.md)，**不要静默统一掉** |
| **一个词不再使用** | 不删条目，**移进「弃用」并说明现在叫什么**——删掉会让读到旧文档的人查无此词 |
