# 词条的格式契约

**一个词条长什么样、每个字段与每个取值是什么意思。**读词条的人靠它读懂，写词条的人靠它写对，对账器靠它解析——三方共用这一份。

**怎么取名、选卷、写定义、判形态、加一个词条、改一个词条**不在这里：那是落字的人才需要的判断，
归 `ubiquitous-language` skill，只此一份。谁该加载它、谁不必，见本区 [AGENTS.md](AGENTS.md)。

## 一个词条长什么样

````markdown
### UL-tenant · 租户 · Tenant

> **中**：资源、数据与成本的归属边界，也是隔离边界；系统里每一个受归属约束的
> 对象都恰好属于一个租户，跨租户访问默认拒绝。
>
> **EN**: The boundary of ownership, isolation and cost attribution. Every
> ownership-bearing object in the system belongs to exactly one tenant, and
> access across tenants is denied by default.

- **形态**：对象
- **出处**：[PF-001 §4 租户](../product.0.0.1.legacy/PF-001-identity-scope-and-agent-constraints/design.md#租户)（rev 19）
- **别混**：与[组织](terms/subjects-and-ownership.md#ul-organization--组织--organization)不是一回事——组织是租户的**一半**，另一半是账号
- **弃用**：~~「空间」~~、~~「工作区」~~
````

> **示例里的相对路径按各卷的实际位置写**：词条在 `terms/` 下，
> 指向产品 topic 要多退一层（`../../product/…`）。

**标题三样一次看全**：稳定 ID · 中文名 · 英文名。

| 字段 | 必填 | 它是什么 |
|---|---|---|
| **ID** | ✅ | `UL-` + 英文名的 kebab-case。**改 ID 等于换概念**；[领域对象条目](../domain_objects/README.md#键是统一语言的词条-id)也以它为键 |
| **中文名 / 英文名** | ✅ | 各一个，**不并列两个**。别的叫法在「弃用」里。**这就是正式名**：跨 topic 引用、写规格、做翻译用它，不另译 |
| **中 / EN 定义** | ✅ | 两条各自独立成立，讲同一件事，**不是逐字互译**。读哪一条都应当得到同一个所指 |
| **形态** | ✅ | 这个词指的是**哪一类东西**，[十个取值里选一个](#形态这个词指的是哪一类东西)。**排在出处前面** |
| **出处** | ✅ | 定义的**依据**在哪，[合法形式只有两种](#出处为什么必填) |
| **别混** | 按需 | 最容易和它搞混的那一个，**以及差在哪** |
| **注意 / 待裁决** | 按需 | 读这个词时最容易漏掉的后果；还悬着、会影响所指的问题（指向它在哪个 topic 待裁） |
| **弃用** | 按需 | 曾经用过、今后不要再用的说法。查重时要连这一栏一起搜 |

**词条只回答「这个词精确指什么」。**「为什么设计成这样、有什么后果」在出处指向的正文里，不在这里。

## 形态：这个词指的是哪一类东西

**定义里本来就在说这件事**——「一项属性，不是一层」「是视图不是对象」「它是一个状态，不是一类事」。
**形态字段把这句话从散文里拎出来，写成一个能被工具读到的值。**

它是词条**精确所指**的一部分，不是另一层建模：把一个视图读成对象，
照着它建出来的就是一份会和上游打架的存储。

| 取值 | 它意味着 | 例 |
|---|---|---|
| **对象** | **有独立身份**——系统里分得出「这一个」与「那一个」，能被标识、被引用；并且有**自己的生命周期**、**运行时实例**或**耐久记录**三者之一。**[领域对象](../domain_objects/objects.md)里必有它的一条** | 账号 · 运行 · 工具执行 · 消息 |
| **变体**（父：某词条） | 某个对象的**子种类**：身份机制与父类相同，**生灭也跟父类一个样**。哪一样有了自己的一套，它就是对象，不是变体——三类沙箱的身份机制相同，可一个活一次调用、一个活到会话、一个活到租户，**所以是三个对象** | 个人组织（父：组织） · 技能（父：资产） |
| **属性** | 挂在某个对象上的一项值、标记或关系，**或它在某段关系里扮演的角色** | 上级组织 · 不可覆盖标记 · 子 agent |
| **规则** | 讲「怎么算、怎么判、什么必须成立」 | 作用域合成语义 · 会话内单活跃 |
| **过程** | 讲「做一件事」。**它留下的有身份的东西另算**——一次派发交回来的派发报告是对象，派发不是 | 作用域求值 · 资产复制 |
| **视图** | 从别处算出来的，**丢了能从上游原样重算**。每次现算还是落盘增量维护，不改变它是什么 | 属性投影 · 待处理消息队列 · 会话日志投影 |
| **状态** | 某个对象状态机上的一个或一组状态，或某个分类的一个取值 | 运行终态 · 非常态 |
| **位置** | 系统结构上一个**固定的、可被指名的位点**：由设计穷举，不在运行期创建，没有自己的生灭；别的东西挂在它上面或落在它里面 | Loop 拓展点 · 业务流程拓展点 |
| **总称** | 只用来归类或指一块范围，**自身不会有实例** | 范围化对象 · 架构内核 |
| **未定** | 是不是对象**还没有人裁过**，或两处正文说法相左。**[conflicts.md](conflicts.md) 与[领域对象的待裁](../domain_objects/pending.md)里必各有一条**。读到它：那是一个显式缺口，别照着任何一种读法往下建 | —— |

**写法**（工具按这个形状读，别自由发挥）：

```markdown
- **形态**：对象
- **形态**：变体（父：[组织](terms/subjects-and-ownership.md#ul-organization--组织--organization)）
- **形态**：未定
```

「父」的链接按词条所在卷的实际位置写：同卷 `#锚点`，跨卷 `别的卷.md#锚点`。变体的父可以还是变体，
但顺着往上必须走得到一个形态为「对象」的词条。取值后面不加说明文字——理由属于定义，不属于这个字段。

**宿主、级别、一致性边界不是词条的字段。**「谁寄宿于谁」会随对象的重新分解而变，那不是「含义变了」；
它的家是[领域对象条目](../domain_objects/conventions.md#一条对象条目长什么样)的「宿主」。

> **形态变了算「含义变了」。**一个词从「视图」变成「对象」，或从「对象」降成「属性」，
> 所有照着旧形态做的设计都要复核。

## `runtime` 这个词，本系统写死了

> **凡以 `runtime` 为中心词的对象（`X Runtime` / 「X 运行时」），都是一个协程：**
> **有独立的执行上下文，能在 await 点挂起与恢复，能被独立取消，有自己的生命周期。**
>
> **其中兼任调度者的——持有待处理队列、循环取事件并分发——同时是 event loop。**
> 这是**附加身份，不是准入门槛**。

产品负责人 2026-09-20 直接裁决，依据与推理链在 [现行词义](index.md)。

**判断位置，不判断字面**——`runtime` 在哪一侧决定它受不受这条约束：

| 写法 | 它是什么 | 受约束吗 | 例 |
|---|---|---|---|
| **`X Runtime` / 「X 运行时」**（中心词） | 一个**东西** | **受。必须是协程** | [agent runtime](terms/agent-runtime-loop.md#ul-agent-runtime--agent-runtime--agent-runtime) · 模型请求运行时 · 工具执行运行时 |
| **`Runtime X` / 「运行时 X」**（定语） | 「在运行期发生的」 | **不受** | [`Runtime Context`](terms/scope-and-resolution.md#ul-runtime-context--运行时-context--runtime-context) · [`Runtime Injection`](terms/agent-runtime-loop.md#ul-runtime-injection--运行时注入--runtime-injection) |

中文语序刚好能分：**`runtime` 在后是名词，在前是形容词。**

**这条规矩是用来判的。**拿它量过之后被判出去的，[Run](terms/agent-runtime-loop.md#ul-run--运行--run) 是一个——
它是若干协程实例的**逻辑包络**，没有自己的执行上下文，**所以它不叫 runtime**。

## 出处为什么必填

**没有出处，词条就是第二份权威。**

**出处只有两种合法形式：**

| 形式 | 用在什么时候 | 长什么样 |
|---|---|---|
| **指向某个 topic 的某一节** | **绝大多数词条** | 链到 `PF-001 §4「租户」`，后面跟 `（rev 19）` |
| **指向 [现行词义](index.md) 的一条** | 这个概念**不归任何一个 topic**——跨全链的治理概念，被很多 topic 引用却没有哪一个拥有它 | 链到 `UL-D-1`，并注明是**谁、哪天**直接裁决的 |

**没有第三种。**一条查不到出处的词条，说明它是**在这里被发明出来的**——
那是[红线](../product.0.0.1.legacy/AGENTS.md#红线)：不发明没人拍板的东西。

### rev 怎么写，怎么读

**`（rev N）` 里的 N 是那个 topic 的 rev**（该 topic `README.md` front-matter 的 `revision`），意思是：
**有人拿这条定义对着那一版正文核过，成立。**topic 升了 rev 而词条还标着旧值，对账器会点它的名——
那不代表定义错了，只代表「那边改过，这条还没人回头看」。

```markdown
- **出处**：[PF-005 §5.2](../product.0.0.1.legacy/PF-005-execution-environments-and-sandboxes/design.md#52-租户级沙箱本体的存活与数据的存活是两件事) · [§6.4](../product.0.0.1.legacy/PF-005-execution-environments-and-sandboxes/design.md#64-租户级沙箱共享的工作空间)（rev 3）
- **出处**：[PF-004 §4 执行环境](../product.0.0.1.legacy/PF-004-agent-definition-and-assembly/design.md#执行环境)（rev 6） · [PF-005 §4](../product.0.0.1.legacy/PF-005-execution-environments-and-sandboxes/design.md#执行环境)（rev 3）
```

第一行是同一个 topic 的两节共用一个 rev，第二行是两个 topic 各带各的。

**指向产品正文的链接，后面要跟着它那个 topic 的 `（rev N）`。**同一个 topic 连着的几条链接可以共用后面那一个；
换了 topic 就各带各的。[对象条目的「依据」](../domain_objects/conventions.md#一条对象条目长什么样)是同一条规矩，由同一个对账器查。

## 常驻持有者的现行定义

PanQiWei 的 D-04 裁决（2026-10-24，由获授权的 reduce 会话记录，[裁决输入](https://github.com/nemori-ai/omne-harness-lite/issues/675#issuecomment-6392857690)）采用跨持有者的 Tool 常驻规则。常驻持有者是已有对象在保存常驻工具首次 shape、提供采用点输入及承担引用保留义务时扮演的角色。会话是其中一种。这个角色不引入新的身份、实例或生命周期。首次 shape 的持久事实及状态转换仍由具体持有者拥有，Tool 只拥有常驻规则、同形判据与纯判定。词条见[常驻持有者](terms/reach-and-availability.md#ul-residency-holder--常驻持有者--residency-holder)。

## 对账器替这里守着什么

形态必填且合法、变体的父走得到一个对象；[index.md](index.md) 每一行与分卷标题在 ID、中文名、英文名、锚点上一致；
当前PD出处的rev核README当前值，封存PF出处核封存README值并标为历史来源；封存可定位不证明词条已按当前产品复核或获得新采用。形态为「对象」「未定」的词条，领域对象那边有对应的条目或待裁。
完整的一张表与道理在[领域对象的 conventions](../domain_objects/conventions.md#对账)，命令在工作区的 `tooling/README.md`「领域对象对账」。
