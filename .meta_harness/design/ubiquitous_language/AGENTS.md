# 统一语言区的维护与导航

本文件说明**进到这个目录的人各自该走哪条路**，对所有人成立。
这一区拥有什么、不拥有什么、怎么分卷归 [README](README.md)；一个词条长什么样、每个字段什么意思归 [conventions](conventions.md)。

**怎么取名、选卷、写无歧义的中英文定义、判形态、查重、处置对不上的地方、升了 rev 之后怎么复核出处**——
归 `ubiquitous-language` skill。**只有要新增或修改词条的人才加载**；
来查一个词、或在正文里用一个已有的词，不需要它。

## 你来这里做什么

| 情形 | 怎么做 |
|---|---|
| 只是要某个词的准确含义，或它的正式英文名 | 从 [index.md](index.md) 找到词条，读那一条。不加载 skill。**英文名从词条取，不自己另译**——规格要能跨语言复现，译法分叉会直接传导到契约 |
| 写正文时要提到一个概念 | 先搜 [index.md](index.md)，**连「弃用说法」一栏一起搜**。有就用那个词；措辞可以变，词不能变。不加载 skill |
| 读词条时拿不准某个字段——「形态：变体」意味着什么、出处里的 rev 是谁的 | [conventions](conventions.md)。尤其是[形态](conventions.md#形态这个词指的是哪一类东西)：把一个视图读成对象，照着建出来的就是一份会和上游打架的存储 |
| 要引入新概念、改一条定义、改形态、把某个 topic 的概念提成词条 | **先加载 `ubiquitous-language` skill**。顺序是硬的：**先有词条，再在正文里用** |
| 发现两处说法对不上 | 记进 [conflicts.md](conflicts.md)，**不静默统一掉**。哪一类、怎么写、哪些自己就能定，在 skill 里 |
| 刚改了某个产品 topic 并升了 rev | 对账器会点名出处还标着旧 rev 的词条。**复核是升 rev 那个人的事**：加载 skill，逐条回读再改 rev |
| 给一个词条判了「对象」或「未定」 | 这里写完还没完：[领域对象](../domain_objects/AGENTS.md)那边要同时立条目或立待裁，加载 `domain-objects` skill |
| 想回改某个 topic 正文的用词来对齐词表 | 不在这里做。这里立规矩；回改由那个 topic 的 owner 自己做并维护现行正文 |

## 答案在哪一份

查**有没有这个词、它在哪一卷** → [index.md](index.md)，**它不是定义**；
查**这个词精确指什么、别和谁混、哪些说法不要再用** → `terms/` 下那一卷里的词条；
查**不归任何 topic 的概念凭什么这么定** → [现行词义](index.md)，产品负责人的直接裁决与推理链；
查**哪些地方对不上、裁了没有** → [conflicts.md](conflicts.md)；
查**为什么设计成这样、有什么后果** → 词条「出处」指向的产品正文。**「为什么」不在这一区。**

## 红线

约束**任何在这里落字的人**。各条的道理与判法在 skill 里，这里只留结论。

- **先词条，后正文。**反过来做，查重和自检都会走过场。
- **出处必填，合法形式只有两种**：某个 topic 的某一节（带 rev），或 [现行词义](index.md) 的一条。查不到出处的词条是在这里被发明出来的。
- **「为什么」一律不写进词表**，哪怕它很精彩——写进去就是第二份权威。
- **对不上的地方记下来，不顺手改。**
- **改 ID 等于换概念。**不再用的词不删，移进「弃用」并写明现在叫什么。
- **不复核就改 rev，等于把对账关掉。**
- **[index.md](index.md) 是手写的，加、改、废词条必同步改它**；它与分卷是否一致由对账器守着。
