## 选择与范围

1. 一个项目自有 diagnostics 提供者统一结构化日志、标准 trace context、内容裁剪、有界本地输出与生命周期；业务包消费受限记录面，应用持配置和关闭管理面。
2. 首批机制采用 Pino 10.3.1、SonicBoom 4.2.1、OTel API 1.9.1、Trace SDK 与 ALS 2.11.0；不自建遥测协议、通用队列或 exporter 框架。
3. 输出在业务短门外启动，within 保留调用者返回和错误，诊断关闭只证明自身收口。诊断故障不能覆盖业务结果。
4. 关键审计随所属耐久提交或可核实 outbox 保存；logger 和 span 不能替代业务事实。

适用范围：共享诊断公共面、依赖选择、生命周期以及 records 和 admission 等真实边界的观测注入。

## 理由与保留前提

生产、研发和 debug 需要共同语义；成熟库与最小适配减少自建机制，同时维持业务事实和诊断输出的失败隔离。

当前目标提供者见 observation-diagnostics，契约依据见工程观测。旧机制探针只证明当时设计输入，不是当前 provider conformance。

## 取代与影响

D-011 只取代目录创建、共同容量、排他和关闭未知的实现前提；本决定其余公共面、依赖与审计边界继续有效。

原决定、旧评审和旧实现证据只证明其记录的对象与时点。当前规格采用、提供者符合性、应用装配与发布仍须分别引用实际
catalog、review、formal execution、provider conformance 和 release evidence；本包不会把这些状态合并为“已交付”。
