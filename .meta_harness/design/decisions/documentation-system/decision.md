## 选择与范围

1. 精确契约按共享数据、单项能力和跨能力组合组织；目录不预设插件、服务或数据库边界。
2. 研究、提案、决定、架构、规格与维护知识各有唯一拥有者，跨包只作引用或有声明的投影。
3. 已发布版本不可原地覆盖；历史与未接受候选不得进入当前有效规格发现面。

适用范围：设计知识的语义归属、精确引用、规格分类和发布版本不可覆写。

## 理由与保留前提

按 DDD 战术分类或工具类别切分会分散动态能力语义；单义拥有者与精确引用使设计能够被检查和演进。

当前物理容器是本工作区的 design families，规格位于 design/spec。路径重组只投影原有原则；当前准入由系统设计链与各 family README 拥有。

## 取代与影响

没有产品语义取代。旧 docs/spec 物理路径由当前 Meta Harness 布局迁移，不再作为长期路径约束。

原决定、旧评审和旧实现证据只证明其记录的对象与时点。当前规格采用、提供者符合性、应用装配与发布仍须分别引用实际
catalog、review、formal execution、provider conformance 和 release evidence；本包不会把这些状态合并为“已交付”。
