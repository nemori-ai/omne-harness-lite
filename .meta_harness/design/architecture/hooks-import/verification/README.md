# 验证义务

行为见[设计](../design.md)，规范输入见[场景](scenarios.md)与[方言映射](dialects.md)。

| 必须覆盖的场景 | 规范输入与不能替代的部分 |
|---|---|
| 每个 handler 恰好一条报告，包括不导入的；坏 matcher 整份拒绝；`allow` 不是放行；启动之后的普通错误，与不可用、失联这两类分开，且都记日志；`ask` 不授权、`proposedRewrite`、回放不重跑脚本；同一路径的 name，以及插入 handler 的身份代价；Stop 的续跑标记从日志读，跨重启成立 | 工作区这一侧要验：只在本工作区原位读、明确打开才发现、关闭优先于打开、打开来源不授予执行权、原生与兼容的冲突、去重、下次装配才采用。场景页第 1 至 4 节的报告、PreToolUse 的各种收场与其他事件的映射，要保持方言之间的全部差异。执行环境的端口仍负责进程与日志的责任 |

授权、来源、并发提交与外部作用要用真实组合验证。结果未知不补成成功。范围与前提不能用 Schema、Mock 或局部模型替代。
