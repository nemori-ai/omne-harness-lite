# 连接件的接入约束

本页的值约束是连接件正文、来源、投递目标与入站信封的形状，全部写成文字，不依赖任何 Schema 文件。

## 值与身份

`ConnectorDefinition` 是闭合的 `{ source? }`。唯一的可选项是作者给的默认来源。正文跟随资产记录复制与分享。凭据引用与投递目标只在持有的配值里，不能进入正文。能力身份仍是类别加 name，不从来源或目标推导。

`SourceIdentity` 的闭合成员是 `channel` 与 `externalAccount`。两者都是外部的不透明字面值，非空，没有首尾空白，逐码点比较。不解析，不修补，不做 Unicode 规范化。`channel` 恰为空串时报 `channel_empty`，空白串、空的 `externalAccount` 等报 `malformed`。来源不证明账号与凭据匹配，也不允许据它反查租户、持有或资格。

`DeliveryTarget` 恰有一支 `{ kind: "session", session: SessionRef }`，`SessionRef` 引用消息那一侧唯一的定义。`kind` 出现但不是 `session`（包括不是字符串、大小写不同）报 `target_unknown`，缺 `kind` 报 `malformed`。目标会话不存在、已归档或不可访问是受理时的拒绝，不是 `target_unknown`。引用不授予资格，跨租户默认拒绝。
目标只引用已有的会话。连接件事件开新会话是另一条产品路径，不预留 `new_session` 这一支目标。按外部线程分会话不是目标。目标没有作者默认，每一层都缺值时不放行。

`InboundEnvelope` 的闭合形状是 `{ externalId, receivedAt, text?, attachments?, source }`，`externalId`、`receivedAt`、`source` 必需。`text` 与 `attachments` 至少出现一项。两项都缺报 `envelope_empty`，空串或空数组报 `malformed`。文本只含空白仍然合法，原样保留，不解析，不规范化。附件是非空、有序的 `AttachmentRef` 列表，原引用与顺序都保持。交接时字节已经在附件的存储里，引用不授予读取资格，读取由存储的拥有者按租户现判。

`(source, externalId)` 唯一表达「同一件外部事」：两个分量都逐码点相等才算相同。连接件重投时不能现铸新的 `externalId`，也不从这个值推导 `MessageId`、时间、次序或渠道。去重的范围、拒绝的痕迹与外部编辑后同 ID 异内容的处理归受理，最后一项见未决。
`receivedAt` 用 Instant 表示，只指连接件收下的时刻，不是外部产生的时刻，也不是本系统受理的时刻，不是身份或排序的依据。缺失时不能补成受理时刻，也不能假造一个值。`receivedAt` 相同或倒挂都合法，任何业务判定都不读它，不据它新增时效或可信时钟资格。会话内的次序由日志决定。

## 受理与信任

信封不含租户、持有、投递目标或处理身份，也不含命令、是否处理、插队、中断、取消这类标志。可信交接另外显式携带持有、租户身份、投递目标与处理身份，并认证实际的接入端。不能从 `source`、`externalId`、正文或附件的键补出归属。没有「当前租户」，也没有默认身份。缺少必需的上下文时判不出，不放行。外部文本不能改写这份上下文。

受理之后，信封落成恰好一条 UserMessage。文本原样成为一个文本块，不加 origin。附件不丢、不重排：媒体类型是 image 的取图块，audio 的取语音块，其余取文件块，沿[内容块](../../ubiquitous_language/terms/record-and-context.md#ul-content-block--内容块--content-block)的规则。`externalId`、`receivedAt`、`source` 留在入站来源事实里，不塞进闭合的 Message。被去重、拦下或拒绝的不落消息，痕迹由受理拥有。
以 `/` 开头的外部文本仍是内容，这条归 [Slash Command 产品正文](../../product/slash-commands/design.md#产品需求描述)第 11 行。连接件的接入面只负责把一条消息送进目标会话[请求队列](../../../../docs/architecture/runtime/session-and-run.md#受理之前请求队列)的末尾。它不能读日志、管理会话、覆盖、撤回、重排、插队、改变运行，也不能执行工具或模型。

送进来并被受理的消息必须被处理，没有「收下但不处理」。外部的筛选发生在交给连接件之前，它不替系统忽略已受理的输入。停用或移除连接件只影响之后的接入，不撤销已落日志的输入，也不撤销已产生的外部效果。

## 持有、声明与缺席

鉴权绑定 `credential` 是 `CredentialRef`，不是秘密本体，不用于呈现。一份持有一份值，不跨租户共享，同一个人在两个租户里各配各的。同一租户身份要接同一服务的两个账号，就用两份 name 不同的连接件。没有配值就是缺席，不造一个「未绑」值。缺失时沿外层求值，全部缺失就不能连接。非引用的凭据值沿资产写面的 `valueOutOfDomain` 拒绝。前提：组织层不允许配鉴权绑定。

可以确定的声明：

| item | 类别／域 | 默认 |
|---|---|---|
| source | setting／placement_identity，SourceIdentity | 仅取正文source，缺席时不带 |
| target | setting／placement_identity，DeliveryTarget | 不带 |
| credential | setting／placement_identity，CredentialRef | 不带 |
| triggeredSessionRunMode | setting／governance，never／auto_permission／bypass-permissions | 不带，作者默认无效 |

三种运行模式的权威是统一语言里的会话运行模式，不依赖工具准入的定义。这四项都不能从工作区配置。`placement_identity` 与 `governance` 的违例由求值沿原来的拒绝规则过滤。没有触发模式时，连接件事件不能开新会话，受理明确报缺项，不选一个默认模式。
声明是正文的确定函数，item 不重复，不自行产出保留项 `disabled` 或 `usableBy`。**上表不是完整的声明集合。** 安装权限与处理身份的表示见未决，不能补出取值域或默认，也不能把「推不出」当成「没有」。

## 表示校验

每个接收边界都重新校验，不信上游已经校验过。非法值在进入业务判断之前拒绝，不记成受理的业务结论。不能用丢掉多余或坏的成员、裁掉空白、大小写归一或只保留部分附件来修补。
这些值的拒绝集合是闭合的。多处违例时固定按 `target_unknown > channel_empty > envelope_empty > malformed` 取最高的一项，与遍历顺序无关。`malformed` 是其余一切形状失败，内嵌的 `SessionRef`、`AttachmentRef`、`Instant` 违例也落在这一项。嵌入资产形状时按资产的闭合集合带原名，不另造同义的错误。形状合法只证明形状，不证明可信、会话可访问或附件可读。
单个值形状合法也不证明交接已认证、实际账号一致、声明求值、去重或投递有进展。

连接件不承诺外部的可靠投递、崩溃后补发、内容真实、文本或附件的体积上限，也不承诺任何推进性质。受理之后的不漏不重归会话的受理。体积上限要是具名的政策参数。

## 未决

下列未决闭合之前，依赖它的那部分不按本设计实现。

| 未决 | 问题与读法 | 由谁定 |
|---|---|---|
| 连接件是不是一类资产 | [资产与规则的产品正文](../../product/assets-and-rules/design.md#让共同能力可治理也让具体资产独立发展)第 11 行写着连接件是否保留为资产、接入设计怎样，另行确定。资产规格的[类别正文端口](../../../../packages/assets/SPEC.md#类别提供方与正文)里没有连接件这一类。 | 产品负责人先定；定为资产之后，连接件的技术拥有者定公开形状、Schema 身份与验证入口 |
| 事件目录与订阅 | 事件目录、类型成员、厚信封、消息包形状、目录外与未订阅的拒绝、事件订阅这项设置，完整形状与声明没定。词义见统一语言的[连接件事件类型](../../ubiquitous_language/terms/capabilities-and-composition.md#ul-connector-event-type--连接件事件类型--connector-event-type)。不能把本页五个成员的信封当成定稿。 | 资产与规则的产品拥有者与连接件的技术拥有者 |
| 事件开新会话 | 事件开新会话的交接、Agent 定义与租户怎样选、运行模式缺项怎样拒绝，没定。不能当作投递目标的一个新分支来猜。 | 会话的受理与生命周期的拥有者 |
| 安装权限与处理身份 | 前提：连接件的权限只有安装一项，处理身份是固定规则，取目标会话创建时捕获的租户身份，外部账号只作来源。安装权限与 `usableBy` 的技术对接、处理身份的认证与当前性没定。不把 `install` 与 `processingIdentity` 做成两项权限，也不把它们重新列成待定的取值域与默认。 | 连接件的技术拥有者 |
| 认证交接与来源事实 | 认证的交接、必需的归属、入站来源事实、`externalAccount` 与实际凭据账号的一致性及其失败，端口、事实与当前授权的责任没定。不能让来源的断言冒充认证。 | 会话的受理拥有者 |
| 外部编辑后同 ID 异内容 | 外部改了内容又用同一个 `externalId` 送来时怎样去重。读法一：当作同一件事丢掉。读法二：当作新消息。两种都不能静默做。 | 产品负责人 |

## 验证义务

单值约束与两个分量相等不需要新增 TLA 或 Alloy 模型。验证分开报告 Schema、实际的拒绝值、受理与真实组合。
必须成对验证：空的 `channel` 与空白的 `channel`；两项内容都缺与空串或空数组；未知的 `kind` 与合法但不可达的会话；正文里带 `credential` 或 `target`；多处违例的取值次序。来源与 `externalId` 原样保留且重投不变、租户隔离与资格、以斜杠开头的文本原样落日志、附件的类型与顺序、没有读面与管理面、持有上的凭据只能经写面修改，这些都有消费者义务。
交接、处理身份、编辑后去重、事件目录这几条未决闭合之前，相应场景保持未完成，不用 Schema 通过代替。
