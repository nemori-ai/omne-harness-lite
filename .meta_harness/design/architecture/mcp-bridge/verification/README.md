# 验证义务

设计见[设计](../design.md)，输入与预期见[规范场景](scenarios.md)。

| 能力 | 必须覆盖的场景 |
| --- | --- |
| 条目投影 | 最小规范化三样各自的正例与反例。三种已知不可用的原因，以及几种原因同时成立时按判定次序报第一种。清单未取得与取得了空清单分得开。同一份输入与实现上限的输出逐字相同 |
| 调用结局 | 对端报出动作自己的错误时，内容照样进工具结果，调用以失败收场 |
| OAuth 取值 | 两段取值与凭据保管方的两步收存。同一份持有上至多一个 `pending`。过期的等号边界。未配上的凭据过了保留期被丢弃。改值、清值与移除持有使绑定转 `revoked`。续期不打扰人。授权服务器暂时够不着与明确拒绝分开。凭据出示的来处 |

授权、来处、并发提交与外部效果用真实组合验证。结果未知不补成成功。这一类场景不能用 Schema、替身或局部模型替代。
