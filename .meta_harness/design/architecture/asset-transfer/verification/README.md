# 验证义务

行为见[设计](../design.md)，规范输入见[场景](scenarios.md)，形式模型见[模型](../models/README.md)。

| 必须覆盖的场景 | 规范输入与不能替代的部分 |
|---|---|
| 复制与分享的三种终态、重复确认与时效边界；首次、重复、撞名、按层、尝试键重放与结果未知；覆盖内容不碰配置；每条路径的树边界与确认时重判；分享跟随、撤销与移除、认回；断开后重接不复活，并以关掉事件、断开期间不读、逆序读三种负控验证；来源移除后的 `expired` 与重新持有；plugin 的内含与外部引用；各读面结果未知时不写；组织内分享、成员退出再加入、超管不能私看；方向矩阵每一格的普通成员与超管；删除与提升同提交结束分享，以及失败回滚 | 场景页第 1 至 10 节覆盖对应的旅程与每个失败值的反例。重新持有后的待确认件时效、plugin 的内含与引用区分这两条未决闭合之前，相应场景不能算通过。提升时分享怎样结束以设计的未决为限。`removeShared` 与 `unhold` 的告知要有独立的验证义务。形式模型不覆盖 IO 失败、两次读的实际顺序与完整资格，只证明它写明的前提下的性质 |

授权、来源、并发提交与外部作用要用真实组合验证。结果未知不补成成功。范围与前提不能用 Schema、Mock 或局部模型替代。
