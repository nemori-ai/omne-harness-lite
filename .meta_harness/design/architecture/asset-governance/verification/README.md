# 验证义务

行为见[设计](../design.md)，规范输入见[场景](scenarios.md)。

| 必须覆盖的场景 | 规范输入与不能替代的部分 |
|---|---|
| 结构拒绝与资格拒绝的区分；锁与同记录、版本、权限界；禁用与移除对配置的不同后果；官方件不可改与 bootstrap 重放；先告知与新引用的并发；真实并发下的发布与 CAS 认回；不可逆的提升与来源结束同提交；引用方不可判定时不答拒绝、不答空表；不可见与不存在逐字相同；钉版，以及 shared 不可钉 | 场景页的五条旅程（持有、替换官方件、锁、禁用与移除、创作）、十九个失败值的反例与角色矩阵逐格对到操作。predicate 范围的并发不能用顺序执行替代。草稿与配值的过期编辑这两条未决闭合之前，相应场景不算完整 |

授权、来源、并发提交与外部作用要用真实组合验证。结果未知不补成成功。范围与前提不能用 Schema、Mock 或局部模型替代。
