# 会话推进的进展、成本与诊断：设计

## 范围

会话日志、Run 与 attempt、受理、恢复与模型请求组装的现行规则归 [Session、Run 与输入承接](../../../../docs/architecture/runtime/session-and-run.md)、[控制、取消与故障恢复](../../../../docs/architecture/runtime/control-and-recovery.md)与 [Request Context](../../../../docs/architecture/runtime/request-context.md)。本页只写三件现行正文没有定下的事：持续追加时的进展，模型请求输入的成本界，恢复与收场的诊断量。

## 持续追加时的进展

前提：同一 Session 至多一个未终结 Run，输入先被受理时，已定的收尾不能越过它（[Agent 包组规格](../../../../packages/agent/SPEC.md)的不变式 I7）。

- 协调者取得这个会话的写入资格之后，读当前相关的状态，重新求值，一次提交。
- 日志的整条尾部只用来定位历史快照。无关的追加不触发无界的重读与重算。
- 只有相关的变化使一次决定失效：Run、围栏、取消与输入资格。
- 批量输入按显式的有界策略处理。
- 代价高的模型消息投影固定在一个历史前缀上，之后的追加留给下一步。
- 事务调度公平且有界。会话持续有追加时，承接仍能轮到，不要求一段安静的窗口。

## 模型请求输入的成本界

记号：N 是输入条目、块、压缩引用与调用配对引用的边的合计。B 是被检查或输出的字节数。K 是输出项数。

| 情形 | 成本 |
| --- | --- |
| 冷建，或缓存全部失效后的重建 | O(N + B)。每一条、每一个引用只做常数次处理。载荷无界的条目不当作常数 |
| 只追加的热更新 | O(ΔN + 受影响的后缀 + B) |
| 定位会话当前的缓存 | 期望 O(1)，或用有序索引 O(log N) |
| 输出的物化 | O(K + B)，单独计 |

- 工具调用与结果的配对沿调用身份的索引取得，不为每条模型回复回扫整个前缀。
- 一次批量压缩的引用可以多到 N，所以增量更新不在所有情形下是 O(1)。
- 本地缓存的复用与供应方的前缀缓存和计费完全分开。后者不在这里的保证之内。

## 恢复与收场的诊断

- 每一个提交结果未知、恢复受阻、关闭未完成与投影过时的标记，都带操作、Session、Run、调用、来源版本与阶段。公开的诊断不含消息正文、密钥或凭据。
- 指标包括：未承接的工作数、最旧一项义务的年龄、恢复扫描的进度、重复受理数、围栏拒绝数、失联对账数、未完成的关闭数、缓存命中与失效的原因、线性工作量。
- 没有来源给出数值预算时，不为这些指标设服务等级目标。

## 验证义务

- 持续追加：在会话不停有新追加的负载下，验证已受理的输入最终被承接，以及无关追加不引起重算。
- 成本：用操作计数验证冷建、热更新与输出物化的工作量符合上表，包括一次压缩引用多到 N 的情形。
- 诊断：在提交结果未知、恢复受阻与关闭未完成三种故障下，验证标记带全身份与阶段，且不含正文与秘密。
