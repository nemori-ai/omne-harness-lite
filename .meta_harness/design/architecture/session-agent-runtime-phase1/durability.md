# 持久事实与动作链

本页拥有跨模块提交与交接要求；模块具体操作形状和失败联合归候选承诺，采用后移动到成员。

## 唯一事实与共同存储

第一版推荐一个部署提供的**同一AtomicStorage实例**。共同存储对象不是同库文件名、租户标签或相同配置；参加者必须在StorageUnit中核验实例。
Session状态提供者拥有Session归属、生命周期、已受理来源索引、待处理投影、Run当前选择、attempt栅栏、原消费位置和恢复义务索引。
日志SQL提供者拥有不可变journal条目及顺序／去重；两者以显式参加接口参与同一StorageUnit。
各拥有者维护自己的表／migration；Session协调定义跨owner事务，调用者不能用两次普通write拼接。
模型／工具拥有自己的执行结果与费用journal；它们和Session只在有共同实例及显式参加承诺时共提交，否则用下述可靠交接，绝不假设网络／外部效果能同事务。

| 数据 | 分类／保存 | 恢复责任 |
|---|---|---|
| 受理、承接、Run开始／終结、attempt开始、取消意图、调用准备与承接 | 不可变事实 | Session协调；已宣称本owner的非法事实导致不可用 |
| 原响应、真实收场、费用、未知外部效果依据 | 各执行者的不可变事实 | 原调用拥有者；可信结算不受新attempt推进栅栏阻断 |
| 待处理资格、当前Run／attempt、取消阶段与工作索引 | 必须持久的当前投影 | 和相应事实同提交，恢复校验；可由事实重建，不另立权威 |
| Run进度与模型消息缓存 | 派生投影，可丢失 | 按固定日志范围和完整外部输入重建，发布前核验来源 |
| Agentfiber、原调用句柄、计时器、监听、内存索引 | 瞬态资源 | 同步撤准入并清理；销毁不改变事实，也不表示原调用停止 |
| 当前权限／环境／上下文 | 当前来源观测；实际采用依据保存 | 通过来源代际读取，不把外部变化伪装原日志事实 |

### 创建

验证当前可信主体、租户、合法且可用AgentDefinition、显式执行类型／模式和允许的配置。未知／拒绝在发布前失败。
创建持久初始化记录和固定身份；在可恢复创建流程中完成合法装配／context初始化，最后同提交发布Session已建立和归属。
未完成初始化不作为普通可用Session返回；原创建请求身份可查询并接续，不另外创建第二个Session。对外unknown不报成功。
调用已有context初始化若不能共同参加事务，则保存创建阶段／所需初始化身份，恢复重试幂等初始化后发布；不声称跨两个普通append原子。
创建不接受第一条消息，不发模型请求，不制造工作区默认值。首个Run失败前也须先完成Session建立。

## 受理与消费

1. 发送方以稳定来源提交身份保存输入，携带当前租户／主体和明确Session。相同身份不同载荷拒绝，不能默认为覆盖。
2. 会话协调在当前权限和可接收生命周期下，开启StorageUnit，锁定已有Session行／必要sentinel，核验来源去重及预期条件。
3. 同提交追加受理事实／合法消息，写待处理资格及推进义务。成功返回的是已持久受理；提交未知返回unknown且可按来源查，不说未受理。
4. 提交后尽力发推进通知。发送方得到确认后才能移除自己的工作副本；确认丢失保留并按原身份重试。
5. 协调者从持久工作索引读取，不靠队列空转非空。无未终结Run且有合格输入时，同提交建立Run并记录承接，移除这些输入的待处理资格。
6. 已有Run按其段与优先规则承接新输入。承接事实、原Run／消费位置和资格退出同提交；随后崩溃继续原工作。普通read不消费，加载历史不写日志。

消费清除的是工作资格／可靠交接副本，不删除消息、结果、受理及承接历史。归档按产品规则取消未承接资格并留取消事实；撤销归档不恢复这些任务。
Signal通知可以合并、重复、丢失，只有持久事实能决定推进；未满足等待时通知不新建attempt。

## 收尾与新输入竞争

**正常完成、受理／承接及Run选择都锁定同一Session当前状态并核验同一日志头。**
若输入受理先提交，收尾重新读取资格，按原Run规则承接后继续，不能以旧空队列落completed。
若收尾先提交，后受理可建立新Run；原终态不改。输入和归档并发时由同一提交顺序决定接受或拒绝。
协调者在已取得Session写锁后读当前相关状态、重求值并一次提交。全tail只定位历史快照；无关append不触发无界读算重试。批量输入按显式有界策略处理；昂贵消息投影固定历史prefix，后追加留下一步。相关Run/fence/取消/资格变化才让决定失效；需要原模型完整批tailEquals时在同锁内取得当前tail。公平有界事务调度保证持续追加仍能轮到承接，不要求安静窗口。

## attempt与发起栅栏

Session协调取得当前Run、assembly采用版本、等待条件与执行者代际；只有原执行者已交还／失效且工作可推进时，追加新attempt开始事实并更新栅栏。
本机活跃拥有者登记属于瞬态排他执行资源；进程重启全部作废，跨Session独立；同进程注入重跑先同步撤旧准入并完成交还。仅凭超时不能判旧执行者已死。
attempt身份仍为(Run,序号)，日志是事实权威；持久投影只是快速栅栏。
旧attempt的推进、准备新动作、承接结果均拒绝。可信原调用结算可保存，但不因此获得推进权。

发起模型／工具分成**准备位置**与**提交执行准入**：

- prepare只保存原动作／消费位置、固定输入证据和稳定creationKey；模型openCall沿原creationKey认回其CallKey后关联原位置，工具callId沿原回复取用。这一步不表示已经对外发出。
- 实际调用拥有者通过协调的原子准入端口核验最新attempt、当前授权、Run未终结、未撤准入及原调用未发起；同提交原发出锚点及唯一执行拥有者claim与代际。模型对齐原已出门／ResponseId，工具对齐原queued执行意图；不提前签发第二个网络许可。
- 该提交是内部发起的线性化点，之后外部IO由独立执行者持有。网络IO不放入StorageUnit。之前取消阻止发起；之后取消处理已发起调用，即使首个网络字节尚未发送。
- 重复返回的原证明只供查询／接续，不授予启动。实际外部IO仅归原claim的唯一执行owner；交接须确认全部可能旧执行者／writer停止，再按原能力恢复协议决定，不凭proof重发。
- 已发起承诺不会因Agent换代被再准入。提供者必须区分尚未发送／发送未知／仍运行／有结果；能证明从未发出且产品允许的原调用恢复才能继续其自身协议，不能创建同义新call。
- 执行者代际改变时，已有准入义务明确转交或判失联；不把旧Agent拿着的裸callId当新权限。执行者只接受原准入证明及当前可执行阶段。

会话栅栏与真实执行准入必须共享该原子端口；不能“读栅栏→异步间隙→普通open”就声称无旧尝试新发起。取消后仍可能有已准入的外部效果，必须留风险和原归因。

## 原调用、结果与ACK

等待位置保存：原Session／Run、动作链／段、callId、原attempt归因、固定输入、结果来源和已承接标志。
Agent关闭只释放句柄，调用池保持执行；新attempt按原位置查实际执行：存活则重取句柄，有结果则读取原结果。
找不到时必须按执行者连续性／journal证据判断，不从Agent缺席或一次查询错误推导失联。unavailable保持恢复责任；真失联依现有模型首token／工具不重来规则落真实失败／中断依据。

结果拥有者先持久保存原结果和交接义务，再通知Session。Session先可靠保存完整原Pending及必要引用，在同提交记录保管承接；当前Run合法等待位置才更新可推进资格，终态迟到仅保存事实，不新建资格。随后提供custodyWitness，由原能力适配按其ACK接受条件确认；摘要不能替代原全文。
首次、重复认回和迟到保管成功都可提供原身份的可靠保管凭证，但这不是模型replyDisposition或最终费用结算。ACK丢失重复交回只认原承接，不再给资格；unknownCommit没有ACK，原执行方继续保管。原结果工作副本仅按该能力现行ACK／清理契约移除；模型response历史、费用和Session消息不被清理。
消息业务形态仍来自原能力：前台ToolMessage、后台业务结果提醒、实际模型中断原因。attempt开始事实独立，绝不作为这一跳消息。
外部效果未知保持unknown；不能用结果缺失证明未执行，不默认自动重试工具。模型首token前可否续发沿现行原调用协议和真实证据。

## 取消与恢复

治理入口先同提交取消意图／目标和关闭新工作准入。协调在无Agent实例时也读取持久调用／等待集合。
优雅取消请求每个明确目标停止，保持原拥有者负责真实收场／费用；只有相应产品收束条件确实满足才落取消终态。
强制取消先提升／撤销推进权，记录外部效果可能未收尾，治理者落终态；不等待被杀Agent写事实。已发起执行的原结算继续，禁止新消费位置和新调用。
归档、父子递归与派发撤回按产品不同目标执行；首卡不扩展第二期派发取消协议。

进程恢复先校验存储能力、migration与恢复索引；公平分页扫描初始化、待处理、未终结Run、取消和结果交接义务。
先对账原执行再求下一步；没有Agent要恢复的会话也做后台失联对账。存储不可用、当前授权未知或依赖缺失时记录blocked事实／诊断和继续责任，不假成功。
扫描间隔／批量／并发／退避是必须配置的可替换有界策略；持续失败必须可观测。无存储可用或公平调度前提时不声称最终完成。

## 关键断点

受理提交前由发送者负责；提交后由Session负责。结果保存前由原调用执行者负责；保存后直到持久承接ACK前仍由它负责重交；承接后Session负责下一步。
每跳都列清不可撤销边界、重复身份和恢复拥有者，跨节点时以相同语义的可靠交接替换共同事务；不承诺任意外部系统的exactly-once。
