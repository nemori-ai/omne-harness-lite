# 按会话装插件：设计试点

状态：候选设计，仅用于检验薄规格流程。未接受运行机制，未建立产品包或宣布 IC-17 已实现。
依据：[系统责任预期](../system-intent.md)、IC-17/18、PF-004 的装配清单、PF-012 的恢复与
PF-015 的会话生命周期。正式作用域名称、接口和存储表示仍未裁定，不为候选另立对象词条。

## 已确定的责任

Session 生命周期负责会话内 runtime 的装载/停止协调。Agent runtime 驱动 Loop，持有其发起工作的句柄，
模型/工具 runtime 各自负责实际执行、取消、收场和费用。Agent runtime 撤除不自动等于它们已经停止。
会话级动态插件不写入发行/运维插件树，资产装配清单也不等于 Cordis 插件树。
即使没有 Agent runtime 可恢复，会话侧仍须发现并对账失联工作，继续未完成取消，追补执行事实并推进最终收口。
具体触发机制、策略和进展前提由后续精确设计确定，不能用永久保留未完成替代这个责任。

跨边界请求显式携带租户和会话身份，Run/尝试关联按各业务接口传递。
不能从 Context、插件实例、isolate 标签或目录推导授权。数据共享不因实例可见性相同而合法。

## 需要约束的行为

| 边界 | 承诺与拥有者 | 验证反例 |
|---|---|---|
| 隔离 | Session 协调者限定事件/登记的会话归属；各数据能力仍校验租户/会话权利 | A 会话贡献在 B 可见或可调用，或标签代替数据授权 |
| 登记与撤除 | 贡献随贡献者撤除；会话整体撤除覆盖其所有动态插件，不删业务历史 | 卸载贡献者后登记仍被消费，或重装造成双登记 |
| 故障 | 一个会话的失败不使其他会话停机；共享提供者故障由自己的责任方处理 | A 故障清除 B 的 fiber 或把共享故障隐瞒为成功 |
| 在途 | 先停止准入，再按句柄取消/接续/收场；未实际停止的责任由原执行方保持 | 取消请求一发出即销毁责任，迟到结果/费用失去拥有者 |
| 恢复 | 按日志与原调用身份识别已执行/仍在途事实，不因重建 Agent 重发已发请求 | 恢复出现第二次同义外部请求，或没有 Agent runtime 时后台失联无人对账 |
| 进展 | 停止诊断与实际完成分别观察；无终结证据则保留未完成状态 | 等待阈值到期被解释为执行已释放，或未完成取消没有继续推进 |

会话归档按 PF-015 取消未承接任务并保留记录，拒绝新任务。
已发起执行的迟到结果仍归原历史/费用，不获得新的待处理资格。
撤销归档不恢复已取消任务，也不自动重启被中断执行。
这组产品要求不由运行时插件卸载替代。

## 候选机制与反向检查

| 候选 | 可承载部分 | 尚缺保护点/代价 |
|---|---|---|
| 每会话子 Context + Service 调用方 effect | 插件与贡献的共同撤除 | 子 Context 不自动隔离事件/数据，需证实例边界及显式事件过滤 |
| 每会话独立 Context，共享能力经显式接缝 | 可见性与故障域更易区分 | 跨 Context 贡献/事件、共享提供者与在途托管需要明确协议 |
| 进程内会话协调者显式持有插件/工作句柄 | 准入、关闭、恢复责任显式 | 手动账本易漏登记，需精确一次收场和多故障验证；不能替代 Service effect |

没有选择获机制接受。DSH 的 scope 原语不在当前复用授权内，不直接采用它的继承语义。
Cordis 的 isolate 只隔实例，不能作为以上行为的完整证据。

## 实施前必须补齐

公开形状至少区分创建/装载、停止准入、请求停止、观察完成和恢复输入。
同一会话/贡献/调用的身份、所有权、失败与重复执行行为由对应公开接口及薄规格拥有。
接口名、错误联合、跨进程责任移交及是否需要持久关闭记录仍待精确设计，不由本文填默认值。

两个租户/多个会话、贡献者单卸载、共享提供者替换、停止时任务竞争、取消后迟到完成、
崩溃恢复与双故障须有真实组合用例。并发关闭/恢复模型须覆盖提交前后与进展前提。
现有 kernel-basis 探针只支持单个机制事实，不能代替会话整体模型和行为验收。
该设计试点通过不释放上述缺项的产品实施。
