# Meta AI Muse：2026-09-16 的产品与系统观察

- 调查对象与日期：Meta Platforms, Inc. 的 Muse；以 2026-09-16 访问的官方 Meta 产品、公告、
  研究、安全、条款和隐私页面为基线。
- 消费者：个人长期运行智能体的产品比较与能力覆盖分析，特别是运行环境、授权、连接器、持久
  记忆和数据治理的设计问题。
- 当前结论：Muse 是 Meta 2026-09-08 发布、在美国向 iOS、Android 与 `muse.ai` 分阶段推出的
  个人 AI agent；官方同时承认产品仍处于早期、会犯错且不保证任务执行。它不是本文所指的通用
  Meta AI Assistant，也不是仅研究/演示项目。[E1](evidence.md#e1-产品页与-faq)、
  [E2](evidence.md#e2-发布状态与产品承诺)、[E6](evidence.md#e6-使用条款与可用性限制)

## 问题与区分条件

本调查回答：一个面向个人、可跨应用执行与后台持续工作的 agent，Meta 对其入口、身份、权限、
记忆、数据处理、技术隔离和剩余风险作了哪些**公开且具体**说明？下列事情会改变结论：产品条款、
隐私政策或安全设计的版本更新；扩大地区/平台的正式公告；或公开 API、连接器清单、配额、价格和
独立安全验证资料。营销宣称、设计意图、已上线行为与计划功能分开表述。

## 已观察到的产品与系统解剖

### 状态、入口与身份边界（事实）

- 发布公告称 Muse 是个人 AI agent，2026-09-08 “rolling out in the US” 于 iOS、Android 和
  `muse.ai`，AI 眼镜“coming soon”。因此截至基线它是受地区限制的公开推出产品；公告没有给出
  完整国家清单、准入队列规则或保证所有美国用户均可使用的证据。[E2](evidence.md#e2-发布状态与产品承诺)
- 官方产品页把对话入口表述为 Muse app 和 WhatsApp；安全说明还明确 iOS、Android 应用与 Web UI
  客户端通过安全传输层直连用户 VM。产品页称可经 Connectors 接电子邮件、日历、Instagram 等应用，
  但公开资料未给出完整连接器清单、每一区域可用性或 WhatsApp 的具体上线条件。
  [E1](evidence.md#e1-产品页与-faq)、[E3](evidence.md#e3-公开安全架构说明)
- 18 岁以下（或当地要求的更高年龄）不得使用；受适用法禁止接收服务或软件者也不得使用。用户可
  选择独立 Muse 账户，或将其放入与其他 Meta 产品相同的 Accounts Center；后者允许按 Meta 条款和
  隐私政策跨该中心资料与设备结合使用。若用未关联既有 Meta 账户的邮箱注册，可保持独立。
  [E5](evidence.md#e5-隐私政策)、[E6](evidence.md#e6-使用条款与可用性限制)

### 任务、交互循环与持久工作（事实）

- 用户以对话交代任务或目标；官方称 Muse 能回答问题、浏览网页、完成多步骤任务、购买、生成图片
  与文档、设提醒、跟踪目标及监控事项。它可据目标做行动计划、跟踪进度，并在应用关闭后在后台继续
  工作；遇到变化、需要批准或有“实质性新信息”时回到用户。此为 Meta 产品主张，不是本研究对完成率
  或自治可靠性的测试。[E1](evidence.md#e1-产品页与-faq)、[E2](evidence.md#e2-发布状态与产品承诺)、[E4](evidence.md#e4-产品交互设计说明)
- 交互并非只限一问一答：设计说明称主聊天可被中断或并行发送多个任务，另有 Side Chats；Goals
  页面呈现追踪目标和计划，活动/权限视图提供执行日志。官方还称可在日程和相关事件触发时继续工作。
  公开资料没有定义调度的持久性、失败重试、通知投递、任务取消语义或并发限额。
  [E4](evidence.md#e4-产品交互设计说明)
- 产品页说 Muse 可“work with your apps and build its own tools”；技术说明更具体地称它能为具 API 或
  CLI 的服务写自定义连接器，且 VM 可处理并发 sub-agents 与 crons。此支持“具工具创建和多 agent
  编排的产品宣称”，不支持外部开发者可取得工具 API、任意代码均会被执行、或用户可导出/安装自定义
  工具的说法。[E1](evidence.md#e1-产品页与-faq)、[E3](evidence.md#e3-公开安全架构说明)

### 模型、多模态与产物（事实及限度）

- 发布公告称 Muse 的行动由 Muse Spark 驱动；官方模型文章把 Muse Spark 定义为 Meta
  Superintelligence Labs 的 Muse 系列首个模型，称其原生多模态推理、支持工具使用、视觉 chain of
  thought 与多 agent orchestration。安全文章在浏览子 agent 和抗提示注入语境中提及 Muse Spark 1.3。
  因版本命名出现在不同资料/语境，不能据此断言全部 Muse 工作流在 2026-09-16 固定使用同一精确模型
  版本。[E2](evidence.md#e2-发布状态与产品承诺)、[E3](evidence.md#e3-公开安全架构说明)、[E7](evidence.md#e7-muse-spark-模型资料)
- 可以把“生成图像、文档，及产生文档/PDF/网页等 Artifacts”记为官方产品能力。隐私政策把文字、
  语音、照片和共同创建内容列为可能收集的交互资料；这不单独证明每种输入/输出模式均在所有地区、
  设备或套餐开放，也不提供产物格式/托管/版权保证。[E1](evidence.md#e1-产品页与-faq)、[E4](evidence.md#e4-产品交互设计说明)、[E5](evidence.md#e5-隐私政策)

### 工作环境、浏览与连接器（事实）

- Meta 的技术说明称每位用户有一台隔离的云端 Linux VM，含浏览器、存储、CPU、内存；客户机直接
  连到自己的 VM。它称此 VM 是用户放入 Muse 资料的 system of record，并称持久应用状态在与运行
  cell 和凭据库分离的 Postgres 中。该文明确为“系统在 launch 时”的自述，不能替代源码审计或服务
  SLO。[E3](evidence.md#e3-公开安全架构说明)
- 公开架构将核心 harness、工作区文件与它执行的二进制放入 `systemd-nspawn` runtime cell；敏感服务
  在 cell 外，包括安全模型/分类器、执行内置连接器的 `privsep`、凭据库/代理 `hatch-authd`、
  Sentinel、持久状态库和推理/遥测代理。文中称 Linux 与 IPC 限制让 cell 内 root 不是 host root，
  且运行 cell 与其他服务以 Unix socket 和 peer ACL 通信。此是罕见的有实现名称的第一方架构披露。
  [E3](evidence.md#e3-公开安全架构说明)
- 内置连接器由运行 cell 内 CLI 解析参数/转递，受 sandbox 的 worker 在外部执行具凭据能力的业务逻辑；
  `authd` 保管 OAuth token 并做 credential surrogation，主 agent 不见真实秘密。浏览器是受虚拟化的
  Chromium；浏览 sub-agent 见 accessibility-tree snapshot 而非 raw DOM，不能在页面上下文运行 JS；
  用户接管或填充安全凭据时 agent 暂停。官方并未公开连接器协议、可用应用全集或独立复现实验。
  [E3](evidence.md#e3-公开安全架构说明)

### 授权、治理与安全控制（事实）

- Sentinel 是连接器动作和一切网络出口的唯一许可权威：Muse 提议动作，Sentinel 对用户设定的连接器
  政策作 allow/deny/ask 决定。用户审批是经客户端直达 Sentinel 的待决项，不经由与 Muse 的对话；
  可是一时、会话/任务/时间限定或永久授权，且授权绑定 connector/destination/use case。低风险或
  已允许只读行动可免打断。审批类型与精确阈值由 Sentinel 决定，未公开为稳定 API/政策。
  [E3](evidence.md#e3-公开安全架构说明)
- UI 设计也将结构化接受/拒绝卡和凭据安全存储设为非对话式确定控制；默认网页浏览可继续，发送邮件、
  购买等难逆行动会停下审批，设置可调谨慎程度。用户可以管理连接器权限、限制为只读、变更设置或断开
  连接器，且有完整活动审计轨迹的产品主张。[E1](evidence.md#e1-产品页与-faq)、[E3](evidence.md#e3-公开安全架构说明)、[E4](evidence.md#e4-产品交互设计说明)、[E5](evidence.md#e5-隐私政策)
- Meta 说明的防御层包括：模型抗提示注入训练、把外来内容标为 untrusted、独立分类器/红队、运行
  cell、最小权限凭据路径、Sentinel 和人审。对浏览器另列外泄、DOM/图像/下载文件提示注入和高风险
  表单分类器；电子邮件连接器会过滤一次性密码、密码重置和 magic link。Meta 也明确 Muse 仍会犯错，
  提示注入仍是未解问题。这些是厂商安全声明和设计材料，并非第三方验证或“不会被攻破”的证明。
  [E3](evidence.md#e3-公开安全架构说明)
- 条款要求用户维持有意义的人类监督，特别是对发送、金融交易、删改数据和系统配置等状态改变行动作
  批准；同时保留 Meta 为安全、合规、运营等目的监控、记录、审查、暂停、阻止或修改 Muse 行动的权利。
  条款禁止绕过第三方安全措施、无有意义人审作就业/信贷/住房/保险/教育/医疗/法定权利决定、隐瞒
  自动化性质的跨系统自动化链等使用。[E6](evidence.md#e6-使用条款与可用性限制)

### 记忆、个性化、隐私与数据（事实）

- Meta 称 Muse 会跨对话保留记忆，用于目标、模式和既往对话基础上的主动建议；用户可读写 Memory
  files，查看 `MEMORY.md`，要求遗忘特定话题/人员，或删除消息、Side Chats、VM 文件；reset 会删除
  全部 Muse 数据。已删内容仍可能被记住，须另使用 Forget 才是重要的明确限制；断开连接器不保证
  其既用资料自动从记忆/历史消失。[E2](evidence.md#e2-发布状态与产品承诺)、[E4](evidence.md#e4-产品交互设计说明)、[E5](evidence.md#e5-隐私政策)
- 隐私政策称每人 VM 隔离、对话和 VM 数据不与 Meta 广告系统共享（即使同 Accounts Center）；若账户
  分离，Muse 互动和 VM 数据不与其他 Meta 产品共享。将 Muse 加入 Accounts Center 则在政策另有例外时
  可跨该中心 profile/device 结合信息；故“无广告系统共享”不能被概括为“任何 Meta 数据处理均不存在”。
  [E5](evidence.md#e5-隐私政策)
- 模型训练开关初用时为开，用户可在 Data controls 关闭，政策称变更也适用于既往互动；开启时 Meta
  称会移除某些 PII 类别并与账户脱钩。来自 Connectors 的任务信息亦受同一开关控制。安全文补充称
  trajectory（对话、工具调用和 subagent handoff）在用于训练前做 PII 清理；这不等于零识别风险或零
  服务端访问。现有 VM 设计会通过运营政策限制 Meta 人员访问，却“不阻止”Meta 为支持、安全或运营
  服务所必需的访问。[E3](evidence.md#e3-公开安全架构说明)、[E5](evidence.md#e5-隐私政策)
- Muse Confidential VM 是“later this year”的计划：Meta 说目标是以仅用户持有的密钥加密整个 VM，
  使 Meta 不能访问；安全文说已与小规模可信测试者使用并寻求外部审计。它不是本基线已向一般用户提供
  的机密模式。[E2](evidence.md#e2-发布状态与产品承诺)、[E3](evidence.md#e3-公开安全架构说明)

### 价格、区域与明示限制（事实）

- 产品页称免费但有 usage limit，超过后可等重置或付费订阅；发布公告称大部分需求免费、有订阅计划。
  条款保留改变/停止免费、提供订阅或额外付费 AI usage 的权利。上述页面没有公开本包可核实的价格、
  具体配额、重置周期、套餐功能或全球可用表，故不能填造这些数值。[E1](evidence.md#e1-产品页与-faq)、[E2](evidence.md#e2-发布状态与产品承诺)、[E6](evidence.md#e6-使用条款与可用性限制)
- 条款警告动作/输出可能不准确、不完整、有重大错误或不按预期执行；不保证及时、可逆、持续可用、
  无错误或与所有第三方/Meta 服务兼容。用户要独立核实结果，且对自己指示下的行动、产物和金融损失
  承担责任。产品比较时，不能把其“agent”称号或隔离宣称推成事务原子性、补偿、幂等或完成保证。
  [E6](evidence.md#e6-使用条款与可用性限制)

## 比较相关观察（推断，非本项目决策）

1. **持久 agent 不是无边界后台任务。** 由专属 VM、目标/计划、调度和活动审计可合理推断，Muse
   把长期工作建模为可持续的个人工作环境；由条款的无执行保证可知，它不承诺可靠完成。对比任何
   harness 时应分开问“持久状态/调度归谁”和“结果/补偿由谁保证”，不能只比较是否有后台运行。
   推断依据：[E2](evidence.md#e2-发布状态与产品承诺)、[E3](evidence.md#e3-公开安全架构说明)、[E4](evidence.md#e4-产品交互设计说明)、[E6](evidence.md#e6-使用条款与可用性限制)。
2. **审批的关键是独立执行权威。** Sentinel 的位置、独立客户端审批路径和受范围绑定的能力票据，
   支持把“对话中同意”与“可强制执行的授权”区分开。能否迁移为其他产品的适当设计，仍需各自威胁
   模型和需求，不由 Muse 资料决定。推断依据：[E3](evidence.md#e3-公开安全架构说明)、[E4](evidence.md#e4-产品交互设计说明)。
3. **个人化需要可检查、可撤销的数据面。** `MEMORY.md`、Forget、删除/reset、训练 opt-out、
   分离账户和连接器撤销构成了多条控制面；但删除不等于遗忘，且现有 VM 不阻止运营必需访问。这提示
   比较时将“记忆可见/可改/可忘”“训练使用”“广告系统”和“运营人员访问”分别核对。
   推断依据：[E3](evidence.md#e3-公开安全架构说明)、[E5](evidence.md#e5-隐私政策)。
4. **工具能力与连接器权限分属不同边界。** Muse 声称可自建工具/连接器，但内置连接器的真实凭据
   和业务逻辑在运行 cell 外，且 Sentinel 逐行动/出口裁决；因此“agent 可写代码”不等价于“该代码
   获得凭据或网络权限”。推断依据：[E1](evidence.md#e1-产品页与-faq)、[E3](evidence.md#e3-公开安全架构说明)。
