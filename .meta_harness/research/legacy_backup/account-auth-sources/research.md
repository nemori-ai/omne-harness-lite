# 成熟认证机制可承载什么

- 日期与范围：2026-09-16；[证据记录](evidence.md)中的官方产品文档、固定源码文档及标准。
- 消费者：[账号身份提案](../../../design_legacy/proposals/account-identity/README.md)。
- 结论：应优先通过适配成熟认证提供者实现凭据、注册和会话；产品账号、Tenant 个人范围与 CLI 多账号隔离仍需本项目明确定义。用户随后选择首版自助注册、账号密码和可撤销会话；仍未选定 Better Auth、Keycloak 或具体 provider 版本。

## 与本项目相同的问题

Claude Code 和 Codex 展示了 CLI 在浏览器或设备上完成登录、本地保存凭据、报告当前账号并退出的产品方式；它们登录既有的 Claude/ChatGPT 账号，不承担我们的新账号注册和个人租户创建。DSH 的本地 launch token 换浏览器 cookie 证明持有本机入口，不能用它区分多个产品账号；DSH 的模型供应商密钥也不是产品用户身份。[E1–E3](evidence.md)

Better Auth 官方文档提供邮箱密码注册、禁用自助注册配置、数据库会话及撤销、SQLite 适配和设备授权。其文档区分首方设备登录取得会话 token 与公共 CLI 调 API 取得限定受众/范围的 OAuth token；这两个出口不能混用。启用 cookie cache 时，官方说明已撤销 session 在别的设备上可能继续有效直到缓存过期；数据库撤销 API 的存在并不能推出即时拒绝。Keycloak 则提供注册、用户管理、会话和 OAuth/OIDC，代价是另一个可运行服务及其运维面。[E4–E7](evidence.md)

## 推断与设计影响

成熟组件可成为独立账号能力的**实现提供者**；它的数据表和用户 ID、session 不自动取得项目内 `UserRef`、Tenant 成员或额度归属的解释权。适配层须把同一注册操作绑定到稳定 `UserRef`，把经验证的主体传递给 Tenant，且在个人租户尚未 ready 时阻止个人业务准入。用户已选择首版自助注册；框架有开关不等于它已按本项目政策正确配置。

CLI 应展示当前账号和目标租户，分别切换；本机多个账号各有独立受保护凭据槽。PF-026.C2 已确认退出当前登录态后的新交互不能凭它访问账号数据，因此 `logout` 成功回执要以该会话对后续请求已失效为条件；若服务器撤销暂不可核实，只能给 pending/失败并封闭本机继续使用。已经接纳的工作与其他设备的独立会话范围须由正式契约限定，不从本次退出推断全局回滚。

## 待验证的区分证据

| 未知 | 最小实验 | 影响 |
|---|---|---|
| Better Auth 的具体稳定版本、许可、Node/SQLite 适配及迁移 | 锁版本，在本项目运行环境完成 schema、两账号注册、重启及并发进程实验 | 是否可作为第一版嵌入式 provider |
| CLI token 与撤销可见性 | 在一台机器存两账号凭据；退出成功回执后从另一进程以该会话旧 token、缓存 cookie 调受保护 API，必须拒绝。撤销不可核实时仅返回 pending/失败并封闭本机继续使用；含崩溃、重启与多进程 | PF-026.C2 的退出保证、缓存配置和凭据槽方案 |
| 认证 provider 身份映射 | 创建两个账号、改变登录名/凭据并重启，核对 provider subject 到不复用 `UserRef` 的稳定一对一映射 | 防止改名、重新登录或迁移导致数据串账号 |
| 注册身份与 Tenant 提交不共享原子事务时的恢复 | 在账号创建、Tenant claim、发布回执间逐点故障注入并重试相同操作 | 注册组合机制、待处理状态和可用性门 |
| 独立 IdP 的部署及离线需求 | 本地单机上安装/升级/备份、登录和注销端到端验证 | Keycloak 类路径是否值得增加服务 |

研究不证明这些候选已经通过本项目组合测试；具体提供者需以采用版本重新取证。
