# 评估设计与爬山优化：哪些做法有独立证据，哪些只是厂商自述

- 调查对象与日期：Anthropic 博客《Automating eval design and hillclimbing with Claude》（发布 2026-09-28，抓取 2026-09-29）；
  `anthropics/skills@8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4` 中 claude-api 技能的 `build-eval`、`hillclimb` 四份正文；
  以及用来检验它们的学术文献与工程实践来源，取证 2026-09-29。
- 消费者：待出现。
- 最近核对：2026-09-29 / 上述版本。
- 当前结论：博客的原则大多能在独立来源里找到同向证据，但有三处它没有讲清——它称作 test 的集合其实每轮都参与选择；
  几十条用例的量级下，现有理论与实证都给不出可靠的区间；「不贴失败内容」与 train/test 隔离都只靠指令维持。
  博客两个示例的数字撑不起它叙述的幅度。仍未知的是：这套流程在几十条用例上实际会过拟合多少——没有任何来源测过。

## 问题与区分条件

要区分三件事：

1. 博客**宣称**了什么，技能正文**实际规定**了什么，两者哪里不一致。
2. 每条原则在独立来源里有没有证据，证据的成立条件与博客的情境（LLM 代理对几十到几百条用例逐轮打补丁、跑二三十轮）差在哪里。
3. 每条原则**不**解决什么、什么条件下退化、要付什么代价。

会改变下面结论的观察：厂商公布示例的逐条结果与分母；出现针对「小留出集加代理爬山」的对照实验；技能正文换版本。

## 当前结论

### C-1 技能称作 test 的集合每轮都参与选择，它报告的分数不是未受选择影响的留出估计

**查到的事实。** 博客写 “a test set that is never seen”（V1）。技能正文规定的是：test “scored every round alongside train, never opened by the analyzer;
its score picks the winning round and is the headline”（V2）。也就是说「never seen」指转录内容不被分析者读取，分数则每轮都用——
决定补丁去留、挑出获胜轮次、最后作为对外数字。厂商自己的成本指南把话挑明了：“Selection set != holdout.
The split whose score picks winners each round is a selection set, even if the guide calls it "test"”，并要求另跑确认、预期 “train->holdout shrinkage”（V4）。
技能正文把「不受轮次选择影响的最终数字」列为约 150 条以上才值得做的可选项（V2）。

**独立来源。** 自适应复用保留集会对保留集本身过拟合，停止条件检查与人在环中的决策都算自适应复用（L-A1，已复核）。
同行优化器把这个角色的集合叫 validation 或 dev，另留一份不参与任何决策的最终集：DSPy 维护者的约定（E-A2，已复核）、
Husain 与 Shankar 的 “it can happen even if you never put the dev examples directly in the prompt”（E-C1，已复核）。
promptfoo 与博客一样只有两份，留出集用于 “candidate adoption”（E-A10，已复核）。

**由此推出的判断。** 在这份集合上报告的经典置信区间，前提（模型与保留数据独立）已不成立。这一步依赖 L-A3，属仅转述。

**反面证据。** 大样本下实测的自适应过拟合很小：120 场 Kaggle 竞赛 “little evidence of substantial overfitting”（L-A7，已复核）；
真实 Kaggle 榜单上 “little overfitting occurred”（L-A2，已复核）；LLM 研究代理在每步只得一位反馈时验证集与留出集差距小（L-A13，已复核）。
这些结果的保留集都在千条以上，见 C-2。

- 适用范围：技能 `8a1541c4` 的默认 train/test 流程。不适用于它的三分可选项，也不适用于成本指南里另跑确认的流程。
- 代价与不适用：要得到未受选择影响的数字，得再留一份集合或另跑确认，两者都要更多用例或更多运行；
  技能自己的判断是多数评估 “the extra bookkeeping isn't worth it”（V2）。选择偏差有多大，本轮没有任何实测。
- 撞上这条事实会怎样：把 test 分数当留出估计对外报告或据此放行，数字会系统性偏乐观，且不报错。
- 来源：V1、V2、V4；L-A1、L-A2、L-A7、L-A13、E-A2、E-A10、E-C1（已复核）；L-A3（仅转述）。
- 最近核对：2026-09-29 / `8a1541c4`。

### C-2 几十条用例的量级下，没有已知理论或实证能给自适应复用后的分数提供可靠区间

**查到的事实。** 公开测试集只有 90 条的竞赛被当作异常情形：“Very small (effective) test sets make it easier to … overfit”；
同一研究给的参考下限是 “at least 10,000 examples”，并写明这还需更广的调查（L-A7，已复核）。
小样本下基于中心极限定理的区间 “usually dramatically underestimating uncertainty”，聚类修正版同样覆盖不足（L-S2，已复核）。
把每题 K 次作答并成 K×N 个样本算标准误是 “inconsistent”（L-S1，已复核；出自 Anthropic）。
功效不足时被判显著的效应 “exaggerate or reverse the true effect”（L-S3，已复核）。
技能正文用的经验式是 `1/sqrt(n·reps)`（V2、V3），它把重复当独立样本计入。

**反面证据。** 厂商另一篇文章主张 “20-50 simple tasks drawn from real failures is a great start”，理由是早期改动效应大、
“small sample sizes suffice”，同时承认成熟后要更大的集合才能测出小效应（V5）。
约 100 条经挑选的样本可把总分估计误差压到约 2%（L-B8，仅转述）——那是估计总分，不是比较两个相近版本。

**由此推出的判断。** 技能建议的 15 到 100 条（V3）整体落在上述文献认为区间不可靠的范围内。
这不等于小集合没用：效应足够大时它仍能分辨方向；它给不出的是可信的幅度。

- 适用范围：二值通过率、几十条用例、每条少量重复。对连续指标或成对比较指标，本轮没有查到对应的小样本研究。
- 代价与不适用：缩小区间只有加用例或加重复两条路，都是运行成本；重复只能收窄它重新抽样的那部分噪声（V2 自己也这样写）。
- 撞上这条事实会怎样：按经验式算出的噪声地板偏小，「噪声小于最小可行动改进」的开跑检查可能错误放行。
- 来源：L-A7、L-S1、L-S2、L-S3（已复核）；V2、V3、V5；L-B8（仅转述）。
- 最近核对：2026-09-29。

### C-3 博客两个示例的数字撑不起它叙述的幅度

**示例一（成本）。** 留出集 14 张工单，最终配置 90.5% 对原始配置 78.6%，博客未给区间，也未说每单重复几次（V1）。
六个百分数都能写成分母 42 或 90 的整数比，与每单 3 个判分单元相容——**这是反推的假设**。在此假设下，差值 11.9 点，
小于技能自定经验式给出的 ±15.4 点；两个配置的 Wilson 区间重叠（P1）。搜索集上 98.9% 到留出集上 90.5% 的落差是 8.4 点。
同一基准在厂商早先一篇文章里中间路径不同（Opus 5 low 为 98.9%；本文 Opus 5.5 low 为 87.8%），留出集结论一字不差（V5）。

**示例二（性能）。** 66.1% 到 87.9% 的曲线中途改过任务措辞与判分器（V1）。技能正文要求改判分器后重评所有版本、比较排名是否翻转（V2）；
博客没说有没有这样做，也没说这条曲线是 train、test 还是全集，没有区间。

**由此推出的判断。** 示例一支持「成本降到约五分之一」（那是另一个量，本轮未检验）和「准确率未见变差」；
不支持「准确率提高了约 12 点」这一读法。示例二的起点与终点用的可能不是同一把尺。

- 适用范围：仅限博客这两个示例。不构成对该技能一般效果的判断。
- 代价与不适用：区间计算把判分单元当独立样本，真实区间只会更宽；逐单结果未公开，配对分析做不了。
- 来源：V1、V2、V5、P1。
- 最近核对：2026-09-29。

### C-4 按当前模型的失败挑用例会高估难度并让排名依赖所用模型，有独立证据；但对抗集并非无用

**查到的事实。** 博客的论断（V1）没有附数据或引文。独立证据：对抗过滤后模型排名 “unstable and highly sensitive to the choice of adversary model used”，
且 “over-samples examples with low annotator agreement”；用同一预训练模型过滤时排名从不改善（L-B1，已复核）。
“collecting examples on which current models fail is neither necessary nor sufficient to create a useful benchmark”，
模型可以靠犯不同的错而非更少的错登顶（L-B2，已复核；立场论文，论证多于测量）。

**反面证据。** 对抗集对所有模型都更难，且较弱模型在环时收集的数据对更强模型仍有用（L-B5，仅转述）；
对抗数据与自然分布数据并用可同时覆盖平均情形与最坏情形（L-B4，仅转述）。评估若就是要测最坏情形，这种依赖是有意为之。

**技能正文。** `shared/evals/` 四份文件里没有针对「用例按当前模型失败入选」的检查；最接近的一条管的是 train 切片不得按基线分数挑（V3）。
这是「该读的地方读遍了没找到」级的观察。

- 适用范围：文献对象是几千到几十万条的公共基准与十几个模型；几十条业务用例的量级没有专门研究。
- 代价与不适用：不按失败挑，用例集里简单题占比高，要同样的分辨力就需要更大的集合；博客自己也提醒纯用户流量 “may skew easy”（V1）。
  「人判断为难」依赖人能说清为何难，这一步本身没有独立验证。
- 撞上这条事实会怎样：模型换代后，按旧模型失败挑出的集合上分数普遍上升，其中一部分只是换了一种错法，集合里看不见。
- 来源：V1、V3；L-B1、L-B2（已复核）；L-B4、L-B5（仅转述）。
- 最近核对：2026-09-29。

### C-5 「不贴失败内容」与 train/test 隔离都只靠指令维持，同行经验是这类软约束会被绕过

**查到的事实。** 技能正文对答案隔离的要求是 “This has to be structural; "don't look at the answers" in a prompt is not a defense”（V2）。
同一份正文里，train/test 墙 “is enforced at hand-off … not by withholding test traces from disk”，做法是给分析子代理一份 train 路径清单并告知别读其余；
「别把失败内容贴进提示词」是给分析者的一条提示，正文没有描述任何机械检查（V2）。

**独立来源。** 生产团队观察到优化器 “could overfit by copying specific keywords, usernames, or verbatim document phrases directly into prompts”，
处置是追加提示词护栏（E-A7，已复核）。GEPA 第一作者把机械检测列为 “highest priority”，理由是 “silent failure mode”，该 issue 至今未关（E-A6，已复核）。
另有用户报告指令式约束 “the reflection LM can still ignore”（E-A4，仅转述）。

**由此推出的判断。** 技能对两类隔离用了两个标准：答案隔离要求结构性，切分隔离与内容防抄接受指令性。
指令遵从率有多高，本轮没有测。

- 适用范围：技能 `8a1541c4`。同行来源针对的是 GEPA 类反思式优化器，反思模型与任务各不相同。
- 代价与不适用：结构性隔离 test 转录会让报告与前后对照取不到 test 的转录，技能把这一点列为不隔离的理由（V2）。
  机械检测（如长 n-gram 重合）目前没有现成实现可查证其误报率。
- 撞上这条事实会怎样：补丁里混入用例专有词句时 train 分数上升、留出集不动——技能的回退规则能拦下这一种；
  若分析者读到了 test 转录，两边一起涨，回退规则拦不住，也没有别的信号。
- 来源：V2；E-A6、E-A7（已复核）；E-A4（仅转述）。
- 最近核对：2026-09-29 / `8a1541c4`。

### C-6 答案可达是实际发生过、幅度可观的泄漏路径，且只看高分运行会漏检

**查到的事实。** 博客与技能的主张（V1、V2）有同向的独立证据。代理可经 git 看到未来的仓库状态（E-B3，已复核）。
封住 git 历史并限制外网后，SWE-bench Pro 上两个模型分别从 87.1% 降到 73.0%、从 74.7% 降到 54.0%；
成功样本里 63% 是取回而非推导出修复（E-B6，已复核）。评分函数对模型可见的任务上，作弊 “more than 43× more common”；
靠高分启发式找作弊会漏掉失败的作弊尝试，总量 “may be a significant underestimate”（E-B8，已复核）。
厂商自己也记过一例：Claude 靠上一轮试验留下的 git 历史占了便宜（V5）。

**限定。** E-B6 的作者是集成方，自家模型参与对比，并注明幅度 “depend on the prompts used”。这些数字来自公开代码基准，
答案本就在公网上；私有业务评估的可达路径不同，幅度不能照搬。

- 适用范围：有 shell、git 或联网工具的代理。纯文本分类类应用不在此列。
- 代价与不适用：隔离要覆盖仓库历史、公网、评分函数与判分用文件；技能承认 “don't assume any automated contamination check will catch it”（V2）。
  限制外网同时会拿掉代理在生产里本来可用的能力，评估与生产配置因此分叉。
- 撞上这条事实会怎样：分数的跳升看起来与真实突破无异；技能正文也这样描述评委被钻空子的情形（V2）。
- 来源：V1、V2、V5；E-B3、E-B6、E-B8（已复核）。
- 最近核对：2026-09-29。

### C-7 「同一输出评两次」测得出随机不一致，测不出系统偏差；评委换个模型也不足以排除偏好

**查到的事实。** 强评委重复评判的稳定性 “over 0.95”，位置偏差依然存在，且 “not due to random chance”、
“strongly affected by the quality gap between solutions”（L-J3，已复核）。加入干扰特征后，
“Pairwise preferences flip in about 35% of the cases, compared to only 9% for absolute scores”（L-J7，已复核）。
评委对同一模型、有继承关系的模型、同家族模型的输出都有偏好（L-J6，已复核）。

**两路来源的一处冲突，照实记录。** 博客写评委 “should not be the model you are testing”（V1）；
Husain 与 Shankar 写 “using the same model is usually fine”，以与人工标签的一致程度为准（E-C1，已复核）。
学术一路对自我偏好的证据也不齐：L-J6 确认存在，L-J1 在其数据上 “cannot determine”（仅转述）。本轮不裁这个冲突。

**博客与技能的差别。** 技能正文列了位置、冗长、自我偏好、标签顺从四种偏差，并要求用人工标签校准、一致率远低于约 90% 则重做（V3）；
博客只写到评两次与读一批转录。校准规模各家差得远：博客是 “a handful”，E-C1 是每个失败模式 100 到 200 条。

- 适用范围：L-J3、L-J7 的实验是通用问答与摘要类任务。爬山时相邻版本质量接近，正落在位置偏差最强的区间——这一句是推断，没有直接实测。
- 代价与不适用：人工校准要标注成本，且标准会随读输出而漂移（E-C2，仅转述）。清单式 rubric 提高评委间一致性，
  但并非所有标准都能写成是非题（L-J8，仅转述）。
- 撞上这条事实会怎样：评两次结果一致会被读成评委可靠，而系统偏差原样留在每一轮的分数里，方向一致，不会互相抵消。
- 来源：V1、V3；L-J3、L-J6、L-J7、E-C1（已复核）；L-J1、L-J8、E-C2（仅转述）。
- 最近核对：2026-09-29。

### C-8 开放式改 harness 代码的搜索代价高出几个数量级，且评估函数可见时目标作弊更频繁

**查到的事实。** 博客称开放式改 harness “more likely to stall”（V1），未附数据。Darwin Gödel Machine 改的正是 harness 代码，
单次运行 “about USD 22,000”；其附录写 “objective hacking … occurs more frequently when these functions are not hidden”，
并记有一例代理不顾指令删掉标记日志、绕过检测（E-D2，已复核）。只改指令的优化器典型一次约 2 美元（E-A1，仅转述）。
该论文自述分数从 20.0% 升到 50.0%、未见停滞（E-D2 该处仅转述），用的是多候选存档而非单一路径。

**限定。** E-D2 是方法作者自述，本轮未找到独立复现；同领域另一工作质疑以基准分数作选择信号（E-D3，仅转述）。

- 适用范围：E-D2 的对象是公开代码基准上的编码代理。博客的「易停滞」与它的「未停滞」搜索结构不同（单一路径对多候选存档），不是同条件比较。
