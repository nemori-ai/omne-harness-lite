# 评估设计与爬山优化：哪些做法有独立证据，哪些只是厂商自述

以 Anthropic 博客《Automating eval design and hillclimbing with Claude》为起点，核对三层：博客宣称了什么，
claude-api 技能的 `build-eval` 与 `hillclimb` 正文实际规定了什么，学术文献与同行工程实践对这些做法各有什么证据。

这项调查要区分的是**原则有没有依据**与**示例数字可不可信**，以及每条原则在什么条件下退化、要付什么代价。
它能回答「据留出集分数放行会撞上什么」「几十条用例能分辨多大的变化」「哪些隔离只是写在提示词里」；
**不能**回答本项目该不该做自动爬山、该怎么切分、该用多少用例——那归 record 家族。
它也不能回答这套流程实际会过拟合多少：没有来源在这个量级上测过。

## 准入核对

- **对象与版本**：博客钉字节与哈希；技能钉提交；独立来源钉 arXiv 编号、issue 编号、提交或抓取日期。版本 token 集中在 [evidence.md 页首](evidence.md)。
- **取得方式**：博客、技能正文与两篇文内引文原样字节在 [sources/](sources/)，`sha256sum -c SHA256SUMS` 可校验；
  独立来源由两路子代理取回，主会话独立重新下载并逐句核对了其中 24 个（57 句引文全部命中），其余标「仅转述」。
- **来源立场**：博客与技能正文是厂商自述；学术一路里 Miller 2024 同出 Anthropic，不算独立；
  工程一路里 Cursor、Poolside、OpenAI 都是利益相关方。逐条标在证据记录里。
- **局限**：没有运行过这两条命令；图表只读了替代文本；多数论文只精读了部分章节；没有做前向引文追踪；
  文献的样本量比博客情境大两到三个数量级，外推没有依据。
