## 一个必须先讲清的结构事实

Pi 仓库里有**两套并存的「会话」模型**，不要混为一谈。

- **(A) 已发货的 CLI 会话**：`packages/coding-agent/src/core/session-manager.ts` 的 `SessionManager` + `~/.pi/agent/sessions/*.jsonl`。这是今天 `pi` 命令实际在用的。
- **(B) 新一代持久化运行时 `AgentHarness`**：`packages/agent/`（`@earendil-works/pi-agent-core`），规格文档 `packages/agent/docs/harness.md`（1468 行的 implementation specification）。它定义了 Session/Branch/AgentLane/Operation/三存储的完整模型。**CLI 主路径尚未使用它**——`grep` 显示 `AgentHarness` 在 coding-agent 里只出现在 `src/experimental/`（`experimental/session-worker.ts:14`、`experimental/mini/worker/run.ts:10`）。harness.md §0.9 自陈 WP00–WP07 已实现、WP08 进行中，并逐条列出未实现项。

## 0. 对象确认

**结论。** 承担「一段持续协作的身份与归属边界」的对象，在 (A) 里就叫 **session**，物理形态是一个 JSONL 文件；在 (B) 里 **Session** 被拆成三层：`Session`（全局元数据 + 不可变 entry 树 + 值/列表 + 用量账本）、`Branch`（一条有可移动 tip 的命名数据路径）、`AgentLane`（Branch + 完整模型配置 + 队列 + 至多一个 operation）。

**证据。**

- (A)：`docs/sessions.md:7` "Sessions auto-save to `~/.pi/agent/sessions/`, organized by working directory. Each session is a JSONL file with a tree structure."；`docs/session-format.md:8` 路径模板 `~/.pi/agent/sessions/--<path>--/<timestamp>_<session-id>.jsonl`。
- (B)：`packages/agent/docs/harness.md` §0.2 "A **session** has four parts: an immutable **entry tree** …; mutable **values and lists** at bound typed addresses …; **Branches and AgentLanes** (a Branch is one named data path with a movable tip; an AgentLane adds total model configuration, queues, and at most one operation; sessions may start with zero of either, and `main` is an ordinary explicit name); and an append-only **usage ledger**."
- (B) 还把「一次被接受的工作单元」独立成 **operation**，§0.2："An **operation** is one accepted unit of lane work … Acceptance and execution ownership are separate: an accepted operation may have no process-local driver."

**取舍分析。** (A) 的会话身份 = 文件路径 + header 里的 UUID，没有任何账号/租户维度；归属边界靠 **cwd** 承担（会话按工作目录分桶存放）。(B) 显式把「数据路径」（Branch）和「执行能力 + 配置」（AgentLane）拆开，使「同一段历史上并行跑多条 lane」成为一等能力（§0.4 Slack 例子：同一 channel 历史上两个 thread 各跑各的 lane，"with no coordination"）——这是 (A) 的单活跃 leaf 模型做不到的。

## 1. 数据存储

**结论。**

1. (A) 会话 = 每会话一个 JSONL 文件，按 cwd 分目录；**每行一条 entry**，entry 通过 `id`/`parentId` 组成**树**（不是线性日志）。
2. 落盘是**惰性的**：在本次会话产生第一条 assistant 消息之前，什么都不写磁盘；第一条 assistant 到达时把内存里积攒的全部 entry 一次性以 `wx`（独占创建）写出，之后才转为逐行 append。
3. **逻辑上 append-only**，但有两个非 append 的例外：版本迁移会整文件重写，`/clone`/分支抽取会新建文件并整写。entry 本身从不被原地修改或删除。
4. **没有「长期记忆」这套东西**——Pi 没有跨会话记忆系统。跨会话传递靠的是文件（`AGENTS.md`、skills、用户自己写的 md），不是一个记忆库。
5. 会话结束后**不做任何处理**：文件永久留在磁盘，无保留策略、无自动清理。删除 = 删文件，或 `/resume` 里 Ctrl+D（有 `trash` CLI 时走回收站）。

**证据。**

- 文件位置与命名：`docs/session-format.md:6-11`；`session-manager.ts:500-505`（`--<cwd 去掉前导分隔符、/\\: 替换为 ->--`）。
- 惰性落盘：`session-manager.ts:1071-1098` `_persist()`——`const hasAssistant = this.fileEntries.some(e => e.type === "message" && e.message.role === "assistant"); if (!hasAssistant) { … }`；有 assistant 后 `openSync(this.sessionFile, "wx")` 全量写出再置 `flushed = true`。`session-manager.ts:1573-1581` 的注释把这条规则写死为契约："Only write the file now if it contains an assistant message. Otherwise defer to `_persist()`, which creates the file on the first assistant response, matching the `newSession()` contract".
- append-only 的例外：`_rewriteFile()` 用 `openSync(path, "w")` 整写（`session-manager.ts:1035-1045`），触发点是版本迁移（`:1003-1005`）与分支抽取（`:1566`、`:1602`）。`fileEntries` 从无 `splice/pop/shift`。
- 容错：读取时逐行解析，**尾部残行被静默丢弃并补一个换行**（`session-manager.ts:566-579`）；首行不是合法 session header 则整个文件判为非 Pi 会话（`:572-576`，且 `_setSessionFile` 在非空却解析不出时直接抛错、不修改文件，`:947-951`）。
- 记录单位与结构：`docs/session-format.md:197-341` 列出全部 entry 类型：`session`(header)、`message`、`model_change`、`thinking_level_change`、`usage`、`compaction`、`branch_summary`、`custom`、`custom_message`、`label`、`session_info`。所有非 header entry 继承 `{ type, id, parentId, timestamp }`（`:201-208`），`id` 通常是 8 位 hex。
- 消息/工具调用表示：`AgentMessage` 联合体（`docs/session-format.md:186-195`）含 `SystemMessage / UserMessage / AssistantMessage / ToolResultMessage / BashExecutionMessage / CustomMessage / BranchSummaryMessage / CompactionSummaryMessage`。工具调用是 assistant 消息里的 `ToolCall` content block（`{type:"toolCall", id, name, arguments, namespace?}`，`:67-75`），工具结果是独立的 `toolResult` 消息，靠 `toolCallId` 回连（`:113-122`）。
- **系统提示与工具清单也是会话数据**：`docs/session-format.md:228` "System messages carry the prompt and tool loadout: the first request of a session persists one with every prompt section and tool declaration, and later changes persist as system messages that patch `sections` by name (`null` removes one) and list `toolsAdded`/`toolsRemoved`. Replaying them in order yields the current prompt and tools; there is no separate prompt state entry."
- 用户 `!` 命令也入会话：`BashExecutionMessage` 带 `excludeFromContext?: boolean  // true for !! prefix commands`（`:147-157`）——记录了但不进 LLM 上下文。
- 成本进会话：`Usage` 结构带 `cost` 明细（`:124-139`）；`UsageEntry` 记录「不属于对话、也不进上下文」的模型用量（如 cache warming），但计入会话 token/费用总计（`:259-267`）。
- 长期记忆：**无**。跨会话的东西是 `AGENTS.md`/`CLAUDE.md` 上下文文件（`packages/coding-agent/README.md:325-334`）、skills、prompt templates——都是普通文件，非记忆库。
- 删除：`docs/session-format.md:13-17` "Sessions can be removed by deleting their `.jsonl` files … When available, pi uses the `trash` CLI to avoid permanent deletion."；`docs/sessions.md:49-51`。
- 会话内容敏感度：`docs/sessions.md:157` 明确写 bug report 里的 `session.jsonl` "contains file contents and command output read during the session"。
- (B) 的存储模型（规格）：`harness.md` §0.3 "Three stores, one invariant"——`entries`（write-once, append-only）、`values/lists`、`usage ledger`（append-only）；"*Every payload is in an entry, a bound value/list, or the ledger; there is no third place.*" §1.7 三个后端 Memory / JSONL / SQLite 过同一套一致性测试；JSONL 那节写着 "The file is the **replay recipe** for the Memory maps, not the state"、"**A torn final line is discarded whole**"、"Durability is process-crash level: a resolved `commit()` survives process death; **no fsync promise**"。

**取舍分析。**

- **惰性落盘**换来的是「不留空会话文件」，代价是**用户输入过但模型还没回话时崩溃 = 这段输入不存在**。这是一个被写进注释、当作契约维护的取舍，不是 bug。
- **树而非线性**是整个设计的枢纽：分支、压缩、fork 全部落在同一个 `id/parentId` 结构上，`/tree` 因此能「不新建文件就切分支」。代价是消费者解析会话必须自己走树、自己处理 compaction 区间（`docs/session-format.md:358-379` 的 `buildContextEntries()` 三步规则）。
- **把 system prompt 与工具清单建模成会话内的增量 patch**（而非单独的状态条目），好处是「重放即得当前状态」、fork 天然带上正确配置；代价是任何读者要还原「当前有哪些工具」都必须重放整条路径。
- **压缩不是删除**：`README.md:284` "Compaction is lossy. The full history remains in the JSONL file; use `/tree` to revisit." (B) 把这点上升为不变量：§0.6 "**Deletion as a runtime feature** — entries and usage rows are never deleted: compaction changes provider context, not storage"，合规级擦除只能靠 §2.9 的 administrative "precise rewrite"，而那个**没有实现**。
- (B) 的 JSONL 后端有一个诚实标注的代价：§0.9 "**J1 — JSONL snapshot compaction (§1.7):** specified, not implemented; dead bytes are never reclaimed today."，§1.7 进一步量化「a 30-turn run leaves ~10 dead `pi.op.state` lines」、bash 工具「at 50 KiB per checkpoint, continuously changing output adds ~15 MiB per ten minutes」。逻辑删除立即、物理删除目前**永不发生**。

## 2. 权限治理

**结论。Pi 没有权限系统，也没有沙箱，这是明确的、写进 README/SECURITY 的产品决定。** 没有「运行模式」式的权限分层，没有会话内逐次批准，没有最终放行判定链——**工具调用默认全部直接执行**。它用三样东西替代：(a) 进程级操作系统边界（容器/VM，由用户自己上）；(b) **Project Trust**——一个只管「要不要加载项目本地配置与扩展」的**输入加载闸**；(c) 把逐次批准的能力**下放给扩展**（`tool_call` 事件可 block）。

**证据。**

- 顶层声明：`README.md:47-49` "Pi does not include a built-in permission system for restricting filesystem, process, network, or credential access. By default, it runs with the permissions of the user and process that launched it."
- `packages/coding-agent/docs/security.md:31-37`（标题就叫 **No Built-in Sandbox**）："Pi does not include a built-in sandbox. Built-in tools can read files, write files, edit files, and run shell commands with the permissions of the pi process. Extensions are TypeScript modules that run with the same permissions. … **This is intentional.** … A partial in-process sandbox would be easy to misunderstand as a security boundary while still depending on the host shell, filesystem, package managers, credentials, and extension code. Real isolation needs to come from the operating system or a virtualization/container boundary."
- Project Trust 的确切范围：`docs/security.md:7` "Project trust controls whether pi loads project-local settings, resources, packages, and extensions. **It is not a sandbox and it does not restrict what the model can ask tools to do** after you start working in a directory."；`:37` "Project trust is only an input-loading guard."
  - 触发条件（发现这些才问）：`.pi/settings.json`、`.pi/extensions|skills|prompts|themes`、`.pi/SYSTEM.md|APPEND_SYSTEM.md`、当前或祖先目录的 `.agents/skills`（`docs/security.md:9-16`）。
  - 决策存储：`~/.pi/agent/trust.json`，**按规范化目录**保存，"the closest saved decision on the current or parent path applies before the global default"（`docs/security.md:18`）。**注意：绑定的是目录，不是会话，也不是账号。**
  - 默认值 `defaultProjectTrust: "ask" | "always" | "never"`；非交互模式（`-p` / `--mode json` / `--mode rpc`）**不弹窗**，`ask` 与 `never` 都等于忽略这些资源，`always` 才信任；`--approve/-a`、`--no-approve/-na` 单次覆盖（`docs/security.md:29`）。
  - 未解析信任前只加载：context files、user/global 扩展、CLI `-e` 扩展（`docs/security.md:27`）。
  - 可被扩展接管：`project_trust` 事件，"the first extension that returns a yes/no decision owns the decision"（`docs/security.md:27`、`docs/extensions.md:353-368`）。
- 代码侧佐证：全仓 `grep -i "approv|permission"` 在 `packages/coding-agent/src` 里只命中 `--approve/-a`（`src/cli/args.ts:219-221`、`:316-317`）和包管理命令，**没有任何工具调用审批逻辑**。
- 替代品 = 扩展钩子：`docs/extensions.md:798-843` `tool_call` 事件 "**Can block.**"，返回 `{ block: true, reason?: string, terminate?: boolean }`；`event.input` 可变且 "Mutations to `event.input` affect the actual tool execution … **No re-validation is performed after your mutation**"。
- 工具面可控的只有**装载**，不是**放行**：`--tools`（allowlist）、`--exclude-tools`、`--no-builtin-tools`、`--no-tools`（`README.md:581-590`），运行中还有 `pi.setActiveTools(names)`（`docs/extensions.md:1716`）。
- 安全边界的官方口径：`SECURITY.md:48-68` **Out Of Scope** 明列 "Local code execution or sandboxing behavior (the Pi coding agent intentionally does not have a sandbox)"、"Prompt injection attacks"、"Risks from working in untrusted repositories"。`docs/security.md:37` "Prompt injection from repository files, comments, documentation, context files, or build output is expected local-agent risk and cannot be reliably prevented by pi."
- 作者本人的理由（一手博客，mariozechner.at/posts/2025-11-30-pi-coding-agent/）："As soon as your agent can write code and run code, it's pretty much game over."，唯一真实防护是「inside a container」。
- 官方推荐的替代边界：`docs/containerization.md`（`README.md:53-57` 概述三种模式）；`docs/security.md:44-53` 给出具体建议，包括 "avoid mounting host `~/.pi/agent` unless the container should access host sessions, settings, and credentials"。

**取舍分析。**

- Pi 把「权限」问题整体**搬出了产品边界**：它认为进程内的部分沙箱是「看起来像边界但不是边界」的净负债，宁可零机制 + 明确文档，也不做会被误读的半吊子。代价是：默认配置下没有任何护栏；任何「逐次确认」体验都得自己用扩展写，而扩展本身又与 pi 同权限——**没有一层是真正的信任边界**。
- Project Trust 是很清晰的一刀：它保护的不变量只有一个——「一个仓库不能在你点头前悄悄改掉 pi 的设置或扩展」。它**不**保护模型行为，文档反复强调这点。绑定粒度是**目录（含祖先继承）**而不是会话，且 `/trust` 写完 `trust.json` 后 "the current session is not reloaded, so restart pi for changes to take effect"（`README.md:310`）——即信任决定不参与会话状态机。

## 3. 上下文感知域

**结论。** 会话能看见的外部世界 = **启动它的那个用户能看见的一切**，没有边界检查。会话级绑定的只有 **cwd**（写进 header）；上下文文件、skills、扩展、工具装载在**启动时**发现，运行中可通过 `/reload` 或 `resources_discover` 事件**追加**。没有 MCP，没有内建知识库/外部数据连接器。

**证据。**

- **cwd 是会话级的**：写进 header（`docs/session-format.md:217`），会话目录由 cwd 派生（`session-manager.ts:500-505`）。
- **cwd 失效的边界检查**（唯一一处真正的「边界检查」）：`src/core/session-cwd.ts:14-32` `getMissingSessionCwdIssue()` → `MissingSessionCwdError`。
- **无路径围栏**：`read` 工具经 `resolveReadPathAsync(path, ctx?.cwd || cwd)`（`src/core/tools/read.ts:100`）→ `resolveToCwd()` 仅做 `resolvePath(filePath, cwd, …)`（`src/core/tools/path-utils.ts:48-50`），**没有任何 `startsWith(cwd)` 之类的包含性检查**——绝对路径直通。bash 只校验 cwd 存在（`src/core/tools/bash.ts:90-92`）。
- **上下文文件**：`README.md:325-334`——`~/.pi/agent/AGENTS.md`（全局）+ 从 cwd 向上走的父目录 + 当前目录；全部串联。**上下文文件不受 project trust 约束**（`docs/security.md:27`："Context files such as `AGENTS.override.md`, `AGENTS.md`, and `CLAUDE.md` are loaded regardless of project trust unless context loading is disabled."）。
- **进行中追加**：`resources_discover` 事件（`docs/extensions.md:370-387`）；`/reload`（`README.md:200`）；`ctx.reload()`（`docs/extensions.md:1333`）。工具集可运行时增删（`pi.setActiveTools`），且这些变化**作为 system message 写进会话**（`docs/session-format.md:228-232`）。
- **没有 MCP**：`docs/usage.md:310`、`README.md:501`。全仓 `grep -l mcp` 在 `packages/coding-agent/src` 与 `packages/agent/src` 里只命中一个 vendored 的 highlight.js。
- **联网**：无内建 web 工具；`--offline`/`PI_OFFLINE=1` 只关「启动期网络操作」，不影响模型请求与 bash（`README.md:320`）。

**取舍分析。**

- 感知域 = 操作系统权限域，与第 2 节是同一个决定的两面：不做围栏，所以也不需要「哪些目录允许」的配置面。唯一的 cwd 检查是**可用性**检查，不是**安全**检查。
- 「上下文文件不受信任门控」是个刻意的实用取舍：让 `AGENTS.md` 在信任决策之前就能生效，代价是**最典型的 prompt injection 载体恰恰不设防**——而文档直接承认这属于 expected risk。

## 4. 生命周期控制

**结论。** 会话**没有状态机，也没有终态**。它就是一个文件：进程起来时创建或续上，进程退出就没了前台，文件永远可以再被打开。「一段协作的边界」由**用户显式动作**划定（`/new`、`--name`、`/fork`、`/clone`），而不是由系统判定的终止。**没有父子会话运行时关系**（header 里的 `parentSession` 只是出处指针），**没有 sub-agent**。

**证据。**

- 创建：启动即创建（`session-manager.ts:968-994`）；`SessionManager.create / open / continueRecent / inMemory / forkFrom`（`docs/session-format.md:430-436`）。CLI：`pi -c`、`pi -r`、`pi --session <path|id>`、`pi --fork <path|id>`、`pi --no-session`、`pi --session-dir <dir>`（`README.md:569-580`）。
- **没有终态**：全仓没有 session 的 status/closed/archived 概念；`isPersisted()` 只区分是否落盘（`docs/session-format.md:480`）。会话「结束」的唯一形式是进程退出 → `session_shutdown` 事件（`docs/extensions.md:341-342`）。
- 会话替换流程（`docs/extensions.md:316-329`）：`/new` 或 `/resume` → `session_before_switch`（可取消）→ `session_shutdown` → `session_start{reason}` → `resources_discover`。替换语义的坑写进了文档：`docs/extensions.md:1290-1300` "Captured old `pi` / old command `ctx` session-bound objects are stale after replacement and **will throw if used**."
- 终止时在跑的东西：`src/core/agent-session.ts:917-925` `dispose()` → `abortRetry(); abortCompaction(); abortBranchSummary(); abortBash(); this.agent.abort();`，并注明 "Dispose must succeed even if an abort hook throws."
- 父子：header 的 `parentSession` 只在 `/fork`、`/clone` 时写入源文件路径（`docs/session-format.md:220-224`），**纯出处记录**，无运行时从属、无级联终止。
- **无 sub-agent**：`docs/usage.md:310`；`README.md:503` "**No sub-agents.** There's many ways to do this. Spawn pi instances via tmux, or build your own with extensions"。
- 恢复/分支（三件不同的事，`docs/sessions.md:119-128` 给了对照表）：`/tree`（同一会话文件、完整树、可选分支摘要）、`/fork`（新文件、用户消息选择器）、`/clone`（新文件、当前活动分支）。
- **分支摘要**：切走一条分支时，可让模型总结被放弃的那条路径并挂在新位置上（`docs/sessions.md:130-140`），落成 `branch_summary` entry，带 `fromId` 指向被放弃的 leaf（`docs/session-format.md:285-298`）。
- (B) 的生命周期（规格，更严格）：`harness.md` §4.6 **Abort**——"Invocation cancellation and durable cancellation are different: aborting one caller's `Context` stops only that caller's observation and never mutates operation state. Durable cancellation exists only through `requestAbort(operationId, context)`"，取消是一次**持久化提交**。§4.7 **Close — a controlled crash**："Close writes no cancellation or terminal state. … The Drive is not replaced and durable operation state is unchanged, so **reopening sees the same restart point as process loss**."

**取舍分析。**

- 「会话永不结束」在 Pi 里不是哲学主张，而是**把边界交给用户**的结果：没有超时、没有归档、没有 GC。好处是极简且永远可回溯；代价是磁盘上无限堆积、**没有任何「这段协作到此为止」的系统语义可供上层（计费、审计、清理）挂钩**。
- **同文件分支 vs 新文件 fork 的二分**是个漂亮的产品切分：前者答「我想比较几条路」，后者答「我想让这条路独立存在」。
- (B) 把 abort 建模成**持久事实**而不是进程内信号，是这套规格最值钱的一条：它使「取消」在崩溃后仍然成立、并有确定的收尾路径。但代价也被诚实写出：§4.6 "A process crash, transport loss, or lost response after the commit **permanently loses those payloads**: an explicit product tradeoff."

## 5. 会话层面的其他维度

**有**：成本归属、跨 provider 迁移、命名与书签、导出与分享、诊断与崩溃记录、可观测性契约、一条实验性的「多端附着到同一会话」路线。
**没有**：账号体系、云端同步、跨设备会话、团队共享、租户隔离。

- **成本归属**：每条 assistant 消息带 `usage` 含 `cost` 五项明细；`ToolResultMessage.usage` 记录「工具内部做的嵌套 LLM 工作」（`docs/session-format.md:113-139`）；`UsageEntry` 记录不属于对话的模型用量并计入总计（`:259-267`）。(B) 里这被提升为独立的 append-only **usage ledger**（§0.3），fork 时 "Destination usage starts at zero"（§2.7）。
- **跨 provider / 跨模型**：`model_change`、`thinking_level_change` 是一等 entry（`docs/session-format.md:243-257`）。
- **命名与书签**：`session_info` entry 存显示名（`:333-341`）；`label` entry 是用户书签（`:323-331`）。
- **导出与分享**：`/export` 导出 HTML；`/share` 上传为**私有 GitHub gist**（`docs/sessions.md:34-35`）。`README.md:21-35` 另有 OSS 会话数据公开倡议。
- **诊断**：`/bug` 打包 `report.json` + `diagnostics.json` + 可选 `session.jsonl`；明确 "API keys, header values, URL credentials, and the analytics tracking id are **never** included"（`docs/sessions.md:142-162`）。
- **遥测**：只有版本检查与安装匿名 ping（`README.md:314-320`），**没有会话内容上报**。
- **账号**：`/login radius` 只是某个模型网关的 OAuth；会话不与任何账号关联。
- **多端/并发（实验性）**：`packages/server/README.md:1-20` "**Experimental** local server … A Session may have **multiple presentation attachments**."；`harness.md` §0.6 把规则写成非目标："**Multiple writable owners** — exactly one host-assigned owner may hold a writable Session at a time … Storage backends do not enforce this host-lifecycle rule."
- **会话搜索**：`harness.md` §2.8 明确 "**S3 — design only, not implemented.**"

## 6. 它刻意不做什么（原文引用）

**CLI 产品层**（`packages/coding-agent/README.md:497-515`，标题 `## Philosophy`）：

> "Pi is aggressively extensible so it doesn't have to dictate your workflow."
> "**No MCP.** Build CLI tools with READMEs (see Skills), or build an extension that adds MCP support."
> "**No sub-agents.** There's many ways to do this. Spawn pi instances via tmux, or build your own with extensions, or install a package that does it your way."
> "**No permission popups.** Run in a container, or build your own confirmation flow with extensions inline with your environment and security requirements."
> "**No plan mode.** Write plans to files, or build it with extensions, or install a package."
> "**No built-in to-dos.** They confuse models. Use a TODO.md file, or build your own with extensions."
> "**No background bash.** Use tmux. Full observability, direct interaction."

**安全边界的不保证**（`SECURITY.md:48-68` Out Of Scope，节选）：

> "- Local code execution or sandboxing behavior (the Pi coding agent intentionally does not have a sandbox)
> - Behavior of pi extensions or skills installed by the user
> - Risks from working in untrusted repositories
> - Prompt injection attacks
> - Reports about malicious model output."

**持久化运行时层**（`packages/agent/docs/harness.md` §0.6 Non-goals，全文）：

> "- **Exactly-once external effects** — hooks with side effects must be idempotent, keyed by operation id.
> - **Provider stream resumption** — the harness never reattaches to a provider stream …
> - **Multiple writable owners** — exactly one host-assigned owner may hold a writable Session at a time …
> - **Work scheduling** — the harness never creates platform alarms, scans repositories for abandoned sessions, leases hosted submissions, or promises an HTTP receipt …
> - **Replication** — a session lives in one place.
> - **Durable write history** — values retain only current state, lists only until whole-list deletion …
> - **Deletion as a runtime feature** — entries and usage rows are never deleted: compaction changes provider context, not storage; … Compliance-grade erasure is the administrative precise rewrite (§2.9), the sole sanctioned exception."

**取舍分析。** 这套「不做」是一致的：**凡是需要产品替用户做判断的机制（审批、计划、待办、后台、子代理），Pi 一律外推**，换来核心可被完全理解、可被扩展替换。代价是：开箱即用的安全性为零、跨会话记忆为零、团队协作为零。harness.md §0.6 则是另一种诚实——把分布式/持久化领域里所有**没有**给出的保证一次性列清，配合 §0.9 的实现状态清单，使规格与现实之间不留模糊地带。
