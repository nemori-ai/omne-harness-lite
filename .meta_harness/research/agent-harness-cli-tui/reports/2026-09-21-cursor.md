## 1. 技术栈

**结论先行**：这是一个 **Node.js + React + 私有 Ink 分支**的 TUI，用 webpack 打成 70 个 chunk，**连同一个 123 MB 的完整 Node 24.5.0 二进制一起分发**，外加 4 个 Rust 原生可执行文件和 4 个 N-API 原生模块。单版本 247 MB。**没有 Windows 原生安装路径**（§4）。

### 1.1 运行时：外挂完整 Node，不是打包成单二进制

`cursor-agent` 本体是 **35 行 bash**（`versions/<v>/cursor-agent`）：

```bash
#!/usr/bin/env bash
set -euo pipefail
export CURSOR_INVOKED_AS="$(basename "$0")"
NODE_BIN="$SCRIPT_DIR/node"
if [ -z "${NODE_COMPILE_CACHE:-}" ]; then
  export NODE_COMPILE_CACHE="${XDG_CACHE_HOME:-$HOME/.cache}/cursor-compile-cache"   # darwin: ~/Library/Caches/cursor-compile-cache
fi
if ! should_skip_system_ca && "$NODE_BIN" --use-system-ca --version >/dev/null 2>&1; then
  exec -a "$0" "$NODE_BIN" --use-system-ca "$SCRIPT_DIR/index.js" "$@"
fi
exec -a "$0" "$NODE_BIN" "$SCRIPT_DIR/index.js" "$@"
```
【反向取证，逐字】。三条可读出的设计决定：
1. **自带 Node**，不用系统 Node、不用 Bun、不用 SEA/pkg 单二进制。`node --version` → `v24.5.0`（【实测】）。`process.versions` 是完整的原生 Node（openssl 3.5.1、icu 77.1、v8 13.6.233.10-node.21），没有魔改痕迹。
2. **启动时无条件开 `NODE_COMPILE_CACHE`**，注释写的是 "Enable Node.js compile cache for faster CLI startup (requires Node.js >= 22.1.0)"。这与【官方】changelog "Faster startup via compile caching and lazy initialization"（2026-01）对得上。
3. **`--use-system-ca` 有探测式降级**：先试跑一次 `node --use-system-ca --version`，失败就退回不带。`AGENT_CLI_CREDENTIAL_STORE=file` 时直接跳过（对应【官方】changelog 2026-06-29 "`AGENT_CLI_CREDENTIAL_STORE=file` for sandboxes without Keychain"）。

另外两个包装脚本：`cursor-agent-svc`（后台 helper，跑 `cursor-agent-svc.js`）、`cursor-askpass`（`SUDO_ASKPASS` helper）。

## 2. 交互范式与渲染

**结论先行**：主聊天界面是 **inline 滚动区**（Ink `<Static>` + 行 diff 局部擦除），**不进 alt-screen**；但两个重滚动的子界面（`Ctrl+R` 变更审阅、会话列表 pager）**完全跳出 Ink**，自己进 alt-screen 用绝对光标定位 + 同步输出直写 stdout。非交互 `--print` 走一条**完全不经过 React/Ink 的独立代码路径**。

### 2.2 log-update：两套实现，生产上只开了其中一套

fork 的 `../ink/build/log-update.js` 提供两条路径：

**(a) `incremental: true`（逐行 diff，未启用）**——对比 `c[e] !== n[e]`，相同行发 cursorDown（`r.Ku`）跳过，不同行才发 eraseLine+内容：
```js
for(let e=0;e<m;e++) c[e]!==n[e] ? p.push(r.fq+c[e]+"\n") : p.push(r.Ku);
```

**(b) 默认路径（首个差异行 + 高度熔断）**——找到第一个不同的行 `A`，只从那里往上擦；**但如果需要擦的高度超过 `process.stdout.rows`，就整屏清空重画**并触发 `onFullClear`：
```js
const h = d.length - A + a, g = c.slice(A);
let C="", y=false;
if (h > process.stdout.rows) { C += r.Ik; C += c.join("\n"); a=0; y=true; }   // r.Ik = clear screen
else { h>0 && (C += r._W(h)); C += g.join("\n"); ... }
e.write(C); i=u; if (y && n) try{ n() }catch{}                                // n = onFullClear
```

**`maxFps` 和 `incrementalRendering` 在全 bundle 里只出现在 `index.js`（即 Ink fork 自身的默认值定义处），一次都没有出现在 `1931.index.js`（应用层调用点）。** 应用层实际传的选项是（`./src/run-agent.tsx` 逐字）：

**含义（这是判断，不是事实）**：他们在 fork 里写了逐行增量渲染器，但在 2026.08.04 这个构建里**没有启用它**，仍然跑默认的「首差异行 + 超高整屏清」路径。整屏清就是用户看到的闪烁，所以才有下面的 flicker 遥测。

### 2.3 他们为「重绘」建了三套观测设施（全部【反向取证】）

**(1) flicker 遥测**（`./src/flicker-detection.ts` 逐字）：
```js

  a.length<=4 || e-c<6e4 || (function(e,t){ ...
    debugLog(`flicker reported to Datadog: clearScreen called ${e} times within ${u}ms`);
    const p=quality_metric_tags({is_compact:String(d)});
    c.increment(s,1,p); c.distribution(i,e,p); return !0 })(a.length,e) && (c=e) }
```
**5 秒内 `clearScreen` 超过 4 次就上报 Datadog**，60 秒节流一次，带 `is_compact` 标签。

**(2) render stall watchdog**（`./src/render-stall-watchdog.ts`）：每 2 秒轮询；若**活跃状态下 10 秒没有 render commit**，上报 `category:"render_stall", waitingFor:"render_commit"`，附带 `render_count`、`active_for_ms`、`raw_mode:process.stdin.isRaw`、以及最近 30 秒内的 React 错误（name/message/stack/componentStack，各截 4000 字符）。轮询间隔若超过 6 秒（休眠/挂起），重置计时不误报。

**(3) `agent repaint-debug` —— 一个隐藏的终端重绘剖析器**（`./src/commands/repaint-debug.ts`，命令描述逐字：*"Launch agent-cli in a PTY with a browser repaint visualizer"*）。实现：
- 用 `@lydell/node-pty` 把 agent-cli 拉起在一个 PTY 里
- 用 `node-ansiparser` 解析子进程输出流，自己维护一个**单元格级的终端模拟器**（实现了 CUU/CUD/CUF/CUB/CNL/CPL/CHA/CUP/ED/EL/DECSC/DECRC/IND/RI/NEL）
- 每次 PTY 写入都对比前后快照，产出：`bytes / totalBytes / totalWrites / printableChars / controlChars / escapeSequenceCount / changedCells / changedRows / touchedRows / operationRuns`
- 起一个 HTTP server：`GET /` 返回内嵌的 HTML 可视化页（暗色网格，改动行高亮 `.touched-row`），`GET /events` 是 SSE 帧流，`GET /snapshot` 拿最新帧，`POST /input` 注入按键（`enter`/`ctrlc`/`escape`）

**这套指标（escape 序列计数、changed cells、touched rows）就是"我的终端写入量过大"这个问题的专用量具。** 建这种工具的团队，是在跟重绘成本长期搏斗。【二手】论坛复现与之完全吻合（§5）。

### 2.4 `<Static>` 截断：只渲染最近 10 轮

`./src/utils/static-redraw.ts` 逐字：
```js
const o = require("../agent-ui-state/dist/index.js").tZ;      // tZ = 10
const r = "Rendering latest messages. Use /full-conversation to render everything";
function s({hasClearHandler:e,isProcessing:t}){
  return e ? (t ? {eventHandled:!1,shouldClear:!1,hint:"Ctrl+L can only clear the screen when the agent isn't doing work."}
                : {eventHandled:!0,shouldClear:!0,hint:null})
           : {eventHandled:!1,shouldClear:!1,hint:null} }
```
- 常量 `tZ = 10`（`agent-ui-state` 里 `const D=10`）——**重绘截断后只保留最近 10 轮**，其余折叠成 `conversation-truncated-notice`。
- 斜杠命令 `/full-conversation`（"Toggle full conversation rendering after redraw truncation"）可以关掉截断。还有一个 `/static-indicator` 调试开关。
- **`Ctrl+L` 在 agent 工作时被禁用**，提示语逐字如上。

这与【官方】changelog 2026-05-14 "Long conversations redraw instantly focusing only recent turns" 对得上——即这是论坛问题（§5，tmux 重绘全历史）的官方修复落地形态。

### 2.5 终端能力协商（这一路做得比我预期的多）

**颜色**（`detectColorSupport`）：`COLORTERM ∈ {truecolor,24bit}` → truecolor；`TERM` 含 `256color`/`256-color` → 256；`TERM ∈ {dumb,unknown}` 或非 TTY → none；否则 TTY → basic。

**背景色 / 亮暗主题**（`./src/utils/terminal-theme.ts`，逐字要点）：
- 写 `\x1b]11;?`（OSC 11 查询背景色），**临时切 raw mode**，用正则 `/\x1b\]11;(?:rgba?):([0-9a-fA-F]{1,4})\/([0-9a-fA-F]{1,4})\/([0-9a-fA-F]{1,4})(?:\/[0-9a-fA-F]{1,4})?(?:\x07|\x1b\\)/i` 解析回复，**超时 60 ms**
- 超时/无回复则退回 `COLORFGBG` 环境变量 + 一张硬编码的 16 色 ANSI 调色板
- 查询失败会设一个进程级闩锁 `s=true`，之后**永不再查**
- 计算相对亮度 `r/255*.2126 + g/255*.7152 + b/255*.0722` 判亮暗

**OSC 回复污染输入的代价**（`./src/utils/terminal-osc-input.ts`）：因为上面是「写查询 → 读 stdin」，回复可能迟到并被当成用户输入。他们写了一个**有状态的流式剥离器**，从 stdin 里剔除 OSC 10/11/12/4 的回复和焦点事件 `\x1b[I`/`\x1b[O`，并缓存跨 chunk 的半截序列（`p(t)` 判断"是某前缀的前缀"）。这个过滤器就挂在 Ink fork 新增的 `stdinInputFilter` 选项上。**这是"做终端能力查询"这条路的直接代价，而且它没有别的解法——终端协议本身没有带内/带外分离。**

**kitty keyboard protocol（CSI u）—— 启用了**：
- `./src/run-agent.tsx` 在 `process.stdin.isTTY` 时写 `\x1b[>1u`（push，flags=1 disambiguate），并在 `SIGINT`/`SIGTERM`/`exit` 写 `\x1b[<u`（pop）
- `./src/ui.tsx` 在 Ink 的 `suspend` 事件写 `\x1b[<u`、`resume` 事件写 `\x1b[>1u`
- fork 的 `../ink/build/parse-keypress.js` **新增了 CSI-u 解析**（`/^(?:\x1b)\[([0-9:;]+)u$/`，拆 keycode/modifier/eventType，eventType=3 即 key-release 直接丢弃），**上游 Ink 的 parse-keypress 没有这段**。同时新增 `[I`→`focus_in`、`[O`→`focus_out` 和 `option` 修饰键

**Shift+Enter 白名单**（`terminalSupportsShiftEnter`，逐字集合）：
```js
new Set(["ghostty","wezterm","kitty","iterm2","windows-terminal","warp","zed"])
```
不在表里的终端，`getNewlineKeyHint()` 返回 `"\\+Enter"`（反斜杠+回车）而不是 `"Shift+Enter"`。与【官方】docs `cursor.com/docs/cli/using` 的说法一致（iTerm2/Ghostty/Kitty/Warp/Zed），但 bundle 里多了 `wezterm` 和 `windows-terminal`——**文档与实现在这里有微小分叉，以实现为准**。

**Apple Terminal 特例**：`configureAppleTerminal()` 会 **shell out 到 `/usr/libexec/PlistBuddy`**，读默认 profile 名，再 `Set 'Window Settings':'<profile>':useOptionAsMetaKey true`（失败则 `Add ... bool true`），返回 `requiresRestart: true`。即 **CLI 会去改用户 Terminal.app 的偏好设置 plist**。另有一段逐字的手动指引：
```

  1. Open Terminal → Settings → Profiles → Keyboard
  2. Check 'Use Option as Meta Key'
  3. Use Option+Enter for newlines
Alternatively, use \+Enter or Ctrl+J (works without config)
```

**"半块" prompt bar 白名单**（`terminalSupportsPromptBarHalfPadding`，16 个终端）：`alacritty, ghostty, gnome-terminal, hyper, iterm2, kitty, konsole, mintty, rio, tabby, terminator, tilix, vscode, warp, wezterm, windows-terminal`。**不含 apple-terminal、tmux、screen、jetbrains、xterm**。可用 `AGENT_CLI_DISABLE_HALF_BLOCK_PROMPT_BAR` 关掉。

**终端识别**（`detectTerminalProgram`）：19 条环境变量规则（`GHOSTTY_RESOURCES_DIR`、`KITTY_WINDOW_ID`、`ALACRITTY_LOG`/`ALACRITTY_SOCKET`、`WARP_IS_LOCAL_SHELL_SESSION`、`ITERM_SESSION_ID`、`WT_SESSION`、`KONSOLE_VERSION`、`VTE_VERSION`、`TILIX_ID`、`TERMINATOR_UUID`、`XTERM_VERSION`…）+ `TERM_PROGRAM` / `LC_TERMINAL` / `TERMINAL_EMULATOR` 映射表。

**复用器**（`detectMultiplexer`）：`TMUX`→tmux、`STY`→screen、`ZELLIJ`→zellij、`HERDR_ENV|HERDR_PANE_ID`→herdr。tmux 还会 `execFileSync("tmux","-V")` 取版本。

**tmux/screen 透传**（`./src/notifications/multiplexer-wrap.ts` 全文）：
```js
function o(e,t){ return "tmux"===t ? `\x1bPtmux;${e.replaceAll("\x1b","\x1b\x1b")}\x1b\\`
                : "screen"===t ? `\x1bP${e}\x1b\\` : e }
```

**焦点上报**（`window-focus-tracker.ts`）：`?1004h`/`?1004l`，解析 `\x1b[I`/`\x1b[O`（含 8-bit `\x9bI`/`\x9bO`）。用途是"窗口失焦时才发桌面通知"。**在非 tmux 的复用器（zellij/screen/herdr）下直接不建 tracker**；tmux 下建但额外要求 `hasObservedFocusReport()` 才信任。

**同步输出（DECSET 2026）**：只在 `./src/components/file-change-review.tsx` 用（3 处），配 `stream.cork()`/`uncork()`。

**内联图片**（`./src/utils/terminal-images.ts`）：
- kitty graphics protocol（`_Ga=T,f=100,q=2,C=1[,c=,r=,i=];<base64>\x1b\`，超 4096 字节分片 `m=1`/`m=0`）给 `kitty/ghostty/wezterm/warp`

- **`detectMultiplexer()` 非空就直接返回 null——tmux/screen/zellij 下完全没有内联图片**

**终端标题**：`terminal-title.ts` + `terminal-title-status.ts`，带 emoji 状态映射（`transfer:📤 loading:📂 reconnecting:🔄 shell-running:⌨️ planning:🧭 generating:⏳ queued:📋 waiting-for-user:❓ waiting-for-confirmation:🔐 reviewing:📝 idle:✅`）和 200 ms 的 `Working ···/.··/..·/...` 动画。

**超链接**：`terminal-hyperlink.ts`；fork 的 `../ink/build/output.js` 在截断/换行时**专门处理 OSC 8**（`const E="\x1b]8;"`，闭合序列 `\x1b]8;;`）——上游 Ink 的 output.js 不认 OSC 8。

**可访问性**：`INK_SCREEN_READER=true` 或 `isScreenReaderEnabled` 时，`debug` 模式打开 → **渲染完全不节流**（`this.rootNode.onRender = t ? this.onRender : throttle(...)`）。

## 3. 工程实践与设计品味

**结论先行**：**明确做**的事密度极高（终端探测、可访问性、vim、图片、mermaid、语法高亮、重绘遥测）；**明确拒绝做**的事只能从代码里反推出三条；**作者自述理由：一条都没找到**——这是本路最大的空白，不是我没查。

### 3.1 明确做的（从实现推断）

- **把 Ink 抄进自家仓库再改**，而不是提 PR 给上游或用 patch-package。fork 里加了 `maxFps`、`incrementalRendering`、`stdinInputFilter`、`onReactError`、`onFullScreenClear`、`onImmediateRender`、CSI-u 解析、OSC 8 感知的截断、屏幕阅读器模式、背景色渲染——**这些都是上游 Ink 接不了的产品化需求**。
- **把渲染健康度当成生产信号**：flicker 计数进 Datadog、render stall 进 hang 上报、React 错误进 Sentry 并带 componentStack、`DID_FIRST_PAINT` 打 performance mark。
- **给终端重绘专门建量具**（`repaint-debug`）。
- **逐终端适配而不是取最小公分母**：三张白名单（Shift+Enter 7 个、半块 padding 16 个、内联图片 4 个）、Apple Terminal 自动改 plist、tmux/screen DCS 透传、tmux 版本探测。
- **认竞品的配置**：启动 mark 里有 `WILL_LOAD_CLAUDE_PERMISSIONS`/`DID_LOAD_CLAUDE_PERMISSIONS`（读 Claude Code 的 permissions）。【官方】changelog 佐证：rules 从 `.cursor/rules` + `AGENTS.md` + `CLAUDE.md` 加载；skills 从 `.claude/skills`、`.agents/skills`、`.codex/skills` 发现（2026-03）；"Hooks fire reliably with Claude Code format accepted"（2026-04）。
- **把交互界面拆得很细**：126 个 component，每个工具一个 `*-tool-ui.tsx`（read/edit/delete/glob/grep/ls/shell/mcp/task/goal/todos/ask-question/create-plan/generate-image/fetch-mcp-resource…），pager 抽成 `pager/` 6 个子件 + `unified-list-pager.tsx`。

### 3.2 明确拒绝做的（三条，均从实现反推）

1. **拒绝在复用器下做图形**：`terminal-images.ts` 第一行就是 `if (detectMultiplexer(e)) return null`。tmux/screen/zellij 用户永远拿不到内联图片——这是主动放弃，不是没实现。
2. **拒绝在 agent 工作时清屏**：`Ctrl+L` 被门控，提示语明写 "Ctrl+L can only clear the screen when the agent isn't doing work."
3. **拒绝做 Windows 原生安装**：`./src/commands/install-core-win32.ts` 在 bundle 里的**完整模块体**是：
   ```js
   "./src/commands/install-core-win32.ts"(e,t,n){n("node:child_process")}
   ```
   —— 一个只 require 了 `child_process`、**零导出**的空模块。而 posix 安装器的 `detectSystemInfo` 只接受 `linux|darwin` × `x64|arm64`，其余抛 `Unsupported operating system: <platform>`。这与【官方】GitHub Actions 文档里给出的 Windows 安装方式（`irm 'https://cursor.com/install?win32=true' | iex`，走 PowerShell 外部脚本）不矛盾——**Windows 的安装/自更新不在这个 Node 程序里做**。

### 4.3 磁盘：多版本并存的真实代价

【实测】

三个版本的 `node` 二进制**字节数完全相同**（129,074,464），但**各存一份**——单是重复的 Node 就占 387 MB（55%）。分发是 tar.gz 整包展开，没有任何跨版本去重或硬链接。

保留策略（`./src/commands/install-core-posix.ts`，`cleanupOldInstallVersions`）：
- 排除当前版本、`dev/`、点开头目录，以及 `~/.local/bin/{agent,cursor-agent}` realpath 指向的目录

### 4.5 原子写的残留证据（一条具体的实现代价）

`~/.cursor/` 里有三个孤儿临时文件：
```
-rw-rw-r-- 1363 Jul 13 08:45  cli-config.json.156188.0621eff4-4833-4d9e-8220-6723e63ae8fe.tmp
-rw-rw-r--    0 Aug  6 07:23  cli-config.json.215184.dd77611a-5731-4f7a-84a3-0b77cefab1ef.tmp
-rw-rw-r-- 3953 Jul 30 07:59  cli-config.json.33656.10384144-d49c-4b1d-bd4a-e1c3b8db4e19.tmp
```
命名格式 `<name>.<pid>.<uuid>.tmp` → 典型的 write-temp-then-rename 原子写。**三个都没被 rename、也没被清理**，其中一个 0 字节（写到一半死了）。这是原子写策略的固有代价：崩溃/被杀时留残骸，而这个实现**没有启动时扫残骸的清理逻辑**（负面结论强度：我在 `cursor-config` 与 `./src/utils/agent-cli-state.ts` 相关模块名里没找到，**未穷尽搜索**）。

### 4.6 安装锁

`.install.lock` 用 `openSync(path, "wx")` 独占创建；**超过 60 秒的锁按 inode 比对后强行删除**（`Date.now()-stat.mtimeMs > 6e4` → 再 `statSync` 比 ino 相同才 unlink）。失败时错误文案逐字：`Another CLI update is already in progress. Wait for it to finish or remove ~/.local/share/cursor-agent/.install.lock if no update is running.`

下载 = `curl -fSL <urlPrefix>/<os>/<arch>/agent-cli-package.tar.gz | tar --strip-components=1 -xzf - -C <versions>/.<version>`，成功后 `rm -rf <versions>/<version>` + `rename`。**管道式解压：curl 和 tar 任一端挂掉都要靠双向 SIGTERM 清理**，代码里确实写了双向 kill + 双端 close 汇合，但整包没有校验和/签名验证（负面结论强度：我在 `install-core-posix.ts` 全文里没看到任何 hash/signature 校验；**已读全文，可信度较高**）。

### 4.7 CLI 与 IDE 的关系

**【反向取证】证据链**（比官方说法更硬）：
- CLI 的 webpack 模块 ID 里，`../proto/`（522 次）、`../context/`、`../utils/`、`../git-core/`、`../merkle-tree/`、`../indexing-client/`、`../file-service/` 与 `../ink/` **是同级 workspace 包**——即 **CLI 和 IDE 共用一个 monorepo 里的这批包**。
- proto 里带着明显属于 GUI 的枚举：`CURSOR_TYPE_POINTER`、`CURSOR_TYPE_GRAB`、`CURSOR_TYPE_RESIZE_NWSE`、`CURSOR_TYPE_CROSSHAIR`…（鼠标指针形状）。一个 TUI 不需要这些——**这是 IDE 的 proto 被整份复用进 CLI 的痕迹**。
- `../ink/` 被放在这批共享包旁边，说明 **Ink 的 fork 是放进 Cursor 主 monorepo 的，不是 CLI 独有的小仓库**。

**`cursor` vs `cursor-agent` 两个命令**：`~/.local/bin/cursor` 是安装器写出的 **32 行 POSIX sh shim**（逐字见 §1.1 引用的 `updateCursorShim`）：遍历 `$PATH` 找一个**不是自己**的 `cursor` 可执行文件，找到就 `exec` 它（即真正的 IDE CLI）；找不到且第一个参数不是 `agent` 就报错 `Error: No Cursor IDE installation found. Use 'cursor agent' or 'agent' to run the agent.`；是 `agent` 就 `exec ~/.local/bin/agent`。**所以 `cursor` 是给 IDE 让路的垫片，`cursor-agent`/`agent` 才是本体。** 程序内部 `commandName()` 返回 `"cursor agent"`（当 `CURSOR_CLI` 置位）、`"agent-local"`（当 `CURSOR_AGENT_CLI_LOCAL_MODE=true`）、否则 `"agent"`——这就是 `--help` 里 usage 写 `agent` 而不是 `cursor-agent` 的原因。

**会话/认证共享**：**没有官方原文确认**。网络检索一路查遍 `cursor.com/docs/cli/reference/authentication` 等页面，未找到"CLI 与 IDE 共享会话/认证"的官方表述；流传的说法出自第三方聚合站点【二手】。唯一的一手实证是 Luca Becker 博客【二手，但是作者本人实测】："MCP servers configured for the desktop IDE automatically work in the CLI … Rules and other settings also synchronize between environments"。本机 `~/.cursor/cli-config.json` 里确实有 `authInfo`（含 email/displayName/userId/authId），且 `~/.cursor/mcp.json` 是官方文档点名的 CLI 与 IDE 共同配置位置【官方】。

### 7.3 关于"反向取证"本身的诚实边界

本报告 §1、§2、§3.1–3.2、§4 的绝大部分，来自我读 minify + webpack 打包后的 JS。这意味着：

1. **变量名全部被压缩**（`e,t,n,r,s,i,o,a,l,u,c,d`），我对控制流的理解靠的是保留下来的**字符串字面量、模块 ID、导出名映射（`n.d(t,{...})`）和已知第三方库的形状**。凡是纯靠控制流推断的结论，我都标了"推断/中等不确定度"。
2. **模块 ID 是构建产物，不是 Cursor 的公开承诺。**`./src/components/prompt-bar.tsx` 这样的路径说明源码树长这样，但不说明它们的职责边界就是我猜的那样。
3. **这是一个特定构建的特定版本。**所有结论都绑在 `2026.08.04-aaa8809` / linux-x64 上。同版本的 darwin 包我没有，无法比对。
4. **实现痕迹 ≠ 官方口径。**Cursor 从未公开承认用 Ink、从未公开 monorepo 结构、从未公开依赖清单。如果 Cursor 明天说"我们不用 Ink"，我的证据是 116 处 `../ink/build/` 模块 ID 和 43 个模块名；但我无法排除它是某个第三方 Ink-like 包被 vendor 进来后目录恰好叫 `ink` 的可能（**这个可能性很低但不为零**，因为模块名、API 形状、依赖集合与 Ink 完全吻合）。
