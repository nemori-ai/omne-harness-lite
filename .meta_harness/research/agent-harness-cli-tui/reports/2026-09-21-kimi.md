### 1.2 SEA 结构（一手，可复现）

ELF 里一个 30,732,096 B 的 NOTE 段，name `NODE_SEA_BLOB`，由 `postject` 注入。解析出：

```
magic   = 0x0143da20
flags   = 9  = kDisableExperimentalSeaWarning | kIncludeAssets
code_path = /home/runner/work/kimi-code/kimi-code/apps/kimi-code/dist-native/intermediates/main.cjs
code    = 18,879,289 B，以 "#!/usr/bin/env node" 开头，明文
assets  = 209 个，11,836,557 B
```

`flags` 里**没有** `kUseSnapshot`(2) 和 `kUseCodeCache`(4)——所以 JS 是明文存的。
这不是巧合，上游构建脚本写死了：

> `apps/kimi-code/scripts/native/02-sea-blob.mjs`：
> ```js
> const config = { main: nativeJsBundlePath(), output: nativeBlobPath(), assets: {...},
>   disableExperimentalSEAWarning: true, useCodeCache: false, useSnapshot: false };
> ```

**本机二进制解码出的 flags=9 与上游构建配置一字不差对上**，这是二进制实证与源码的交叉验证。

构建链（一手，上游源码）：`tsdown`（rolldown）→ 单个 CJS `main.cjs`（`codeSplitting: false`，
`target: 'node24'`，`alwaysBundle` 把除 `cpu-features` 外的一切强制内联）→
`node --experimental-sea-config` 生成 blob → 复制 CI 机器的 `process.execPath`（即 Node v24.15.0）→
`postject` 注入 → 签名（macOS `codesign`，Windows `signtool`）。

**ELF 里还有 `lpstub` 和 `malloc_hook` 段**，这是 Node 的 large-pages 构建特征——说明底座是官方
Node release 二进制，不是自己裁剪编译的。

## 2. 交互范式与渲染

> **版本边界（重要）**：本节 2.1–2.6 描述**本机 0.31.0** 的实测行为。
> 2.7 单独讲 0.31.0 之后的变化，两者不要混读。

### 2.1 内联滚动区，不占用备用屏（0.31.0：构造性否定）

`\x1b[?1049h`（备用屏）在 **main.cjs 里 0 次命中，整个二进制 `strings` 0 次命中**。
鼠标跟踪四个模式 `?1000` / `?1002` / `?1003` / `?1006` **全部 0 次**。
这是构造性否定，不是"没找到"。

社区独立复现同一结论（二手但方法可核）：issue #2721 评论里 zsj555 用 `script -qec kimi` 抓 pty 原始序列，
报告 0.34.0 上「No `\x1b[?1049h` / `\x1b[?1047h` — zero occurrences」，
启动时实际开的是 Kitty keyboard（`\x1b[>7u`）、focus tracking（`?1004h`）、
synchronized updates（`?2026h`）、bracketed paste（`?2004h`）——与我在 0.31.0 上的读数一致。

作者自述的渲染策略（一手，`packages/pi-tui/README.md`）：
> "The TUI uses three rendering strategies:
> 1. **First Render**: Output all lines without clearing scrollback
> 2. **Width Changed or Change Above Viewport**: Clear screen and full re-render
> 3. **Normal Update**: Move cursor to first changed line, clear to end, render changed lines
> All updates are wrapped in **synchronized output** (`\x1b[?2026h` ... `\x1b[?2026l`) for atomic, flicker-free rendering."

代码侧对应（一手，`pi-tui/src/tui.ts`）：`doRender()` 逐行比对 `previousLines` 与 `newLines`，
算出 `firstChanged`/`lastChanged`，用相对光标移动 `\x1b[NA` / `\x1b[NB` / `\x1b[NG` 定位，
`\x1B[2K` 清行。全量重绘路径才发 `\x1B[2J\x1B[H\x1B[3J`（清屏 + home + **清 scrollback**）。
最后一条是后面一串 bug 的根。

### 2.2 终端能力协商（一手，`pi-tui/src/terminal.ts`）

| 能力 | 序列 | 做法 |
|---|---|---|
| Kitty keyboard protocol | `\x1b[>7u\x1b[?u\x1b[c` | 一次性发「请求 flags 7 + 查询 + DA 哨兵」。flags 7 = disambiguate(1) + report event types(2) + report alternate keys(4)。**DA 查询当哨兵**：不懂 Kitty 协议的终端会先回 DA，于是无需启动超时就能落到 modifyOtherKeys |
| modifyOtherKeys 回退 | `\x1B[>4;2m` / 关 `\x1B[>4;0m` | Kitty 不可用时启用 |
| bracketed paste | `\x1B[?2004h` | 启动即开 |
| synchronized output | `\x1B[?2026h/l` | 每帧包裹 |
| color-scheme 通知 | `\x1B[?2031h/l` + DSR `\x1B[?996n`，回 `CSI ?997;1n`(dark)/`;2n`(light) | 主题自动跟随 |
| 背景色查询 | OSC 11 `\x1B]11;?\x07`，超时 250 ms，失败再看 `COLORFGBG`，再失败默认 dark | 主题探测 |
| focus 上报 | `\x1B[?1004h`，`[I`/`[O` | 通知只在失焦时发 |
| 终端进度 | OSC `\x1B]9;4;3\x07`（活跃）/ `\x1B]9;4;0;\x07`（清除），1 s keepalive | ConEmu/WezTerm 风格进度 |
| 桌面通知 | OSC 9；不支持则退化成裸 BEL `\x07`；tmux 内用 DCS passthrough 包一层并把内部 ESC 加倍 | — |
| 单元格像素尺寸 | `\x1B[16t` | 供内联图片算行数 |
| 内联图片 | Kitty graphics 协议（APC）| 按 `TERM_PROGRAM` 白名单：kitty / ghostty / wezterm / warp / iTerm2 开；**tmux 与 screen 一律关图片** |
| OSC 8 超链接 | 每行尾追加 `\x1B[0m\x1B]8;;\x07` 兜底关闭 | tmux 下先探 `client_termfeatures` 是否含 `hyperlinks`，不含就不发 |

**Windows 专门处理**（一手注释）：给 stdin console handle 加 `ENABLE_VIRTUAL_TERMINAL_INPUT (0x0200)`，
> "Without this, libuv's ReadConsoleInputW discards modifier state and Shift+Tab arrives as plain `\t`."

**macOS Apple Terminal 专门处理**：Apple Terminal 不发 Shift+Enter，于是调 darwin 原生模块
`darwin-modifiers.node` 直接查物理 Shift 键状态，把 `\r` 改写成 `\x1B[13;2u`。

**tmux 配置检查**（一手，`src/tui/utils/tmux-keyboard.ts`）：启动时 `tmux show -gv extended-keys`
和 `extended-keys-format`，不对就给出可执行的警告原文：
> "tmux extended-keys is off. Modified Enter keys may not work. Add `set -g extended-keys on` to ~/.tmux.conf and restart tmux."
> "tmux extended-keys-format is xterm. Kimi Code works best with csi-u. Add `set -g extended-keys-format csi-u` to ~/.tmux.conf and restart tmux."

### 2.3 输入模型

- **stdin 分片重组**（`stdin-buffer.ts`，**代码来自 OpenTUI**，MIT，注释里注明）：
  按 CSI/OSC/DCS/APC 各自的终止条件判断序列是否完整，10 ms 超时兜底。
  注释举的例子是鼠标 SGR 序列被拆成三个 data 事件的情况。
- **paste-burst 回退**（`paste-burst.ts`，**fork 的本地 patch**，上游没有）：
  终端不支持 bracketed paste 时，用时序启发式判断"这是粘贴不是敲键"：
  `PASTE_BURST_MIN_CHARS=8`、`PASTE_BURST_CHAR_INTERVAL_MS=8`、
  `PASTE_BURST_ACTIVE_IDLE_TIMEOUT_MS=30`、`PASTE_ENTER_SUPPRESS_WINDOW_MS=120`。
  命中窗口内 Enter 插换行而不是提交。可用 `tui.toml` 的 `disable_paste_burst = true` 关掉。
- **键位**：`keybindings.ts` 是一张可覆盖的 action→keys 表，默认值走 **Emacs/readline 传统**
  （`ctrl+a`/`ctrl+e` 行首行尾、`ctrl+b`/`ctrl+f` 左右、`alt+b`/`alt+f` 词移动），
  还有 kill-ring（`kill-ring.ts`）和 undo-stack。
- **IME**：**显式设计，不是顺带**。见 §2.5。

### 2.4 流式输出的两级节流（一手，两个常量）

| 层 | 常量 | 值 | 位置 |
|---|---|---|---|
| 应用层 delta 合并 | `scheduleFlush` 里的字面量 | **50 ms**（≈20 Hz）| `src/tui/controllers/streaming-ui.ts` |
| 渲染层帧率上限 | `TUI.MIN_RENDER_INTERVAL_MS` | **16 ms**（≈60 Hz）| `pi-tui/src/tui.ts` |

模型 delta 先攒进 `_assistantDraft` / `_thinkingDraft`，50 ms 一次 flush 成组件更新；
组件更新走 `requestRender()`，再被 16 ms 的 `scheduleRender` 节流。
工具调用的流式参数另有 `STREAMING_ARGS_FIELD_RE`（只从半截 JSON 里抠
`path|file_path|command|pattern|query|url|description|title|name` 这几个字段做预览）
和 `STREAMING_ARGS_PREVIEW_MAX_CHARS = 64*1024` 上限。

### 2.5 CJK / IME：显式投入的地方（一手，算法级）

**宽度模型**（`pi-tui/src/utils.ts`）：

```js
function graphemeWidth(segment) {
  if (segment === "\t") return 3;                       // tab 记 3 列
  if (zeroWidthRegex.test(segment)) return 0;           // \p{Default_Ignorable}|\p{Control}|\p{Mark}|\p{Surrogate}
  if (couldBeEmoji(segment) && rgiEmojiRegex.test(segment)) return 2;   // \p{RGI_Emoji}
  const cp = segment.replace(leadingNonPrintingRegex, "").codePointAt(0);
  if (cp >= 127462 && cp <= 127487) return 2;           // Regional Indicator（国旗）
  let width = eastAsianWidth(cp);                       // get-east-asian-width@1.6.0
  if (segment.length > 1) for (const char of segment.slice(1)) {
    const c = char.codePointAt(0);
    if (c >= 65280 && c <= 65519) width += eastAsianWidth(c);   // FF00–FF EF 全角块累加
    else if (c === 3635 || c === 3763) width += 1;              // 泰文/老挝 SARA AM
  }
  return width;
}
```

配套的：

- `Intl.Segmenter` 做 grapheme / word 切分（不是按 code unit）。
- `visibleWidth()` 有 **4096 条 LRU 缓存**（`WIDTH_CACHE_SIZE = 4096`），
  ASCII 快路径 `isPrintableAscii` 直接返回 `length`，另有 `asciiVisibleWidth()` 带提前退出。
- **CJK 断行**：`cjkBreakRegex = /[\p{Script_Extensions=Han}\p{Script_Extensions=Hiragana}\p{Script_Extensions=Katakana}\p{Script_Extensions=Hangul}\p{Script_Extensions=Bopomofo}]/u`
  ——命中的字每个自成一个 token，也就是**逐字可断**，不做西文式整词不拆。
- **泰文/老挝 SARA AM 归一化**：`normalizeTerminalOutput()` 把 `ำ`(U+0E33) 拆成 `ํา`、
  `ໍາ`(U+0EB3) 同理，每一帧的每一行都过一遍（有 `THAI_LAO_AM_REGEX` 前置快判）。
- ANSI 感知的截断与换行：`truncateFragmentToWidth` / `wrapTextWithAnsi` 用 `AnsiCodeTracker`
  跨行保持活跃样式码，并在行尾补 reset。

**IME 候选窗定位**（README 有专门一节 "Focusable Interface (IME Support)"，一手原文）：

组件渲染出一个零宽 APC 标记 `CURSOR_MARKER = "\x1B_pi:c\x07"`，TUI 在成帧后扫描该标记、
算出行列、把它从输出里剥掉，然后用 `\x1b[NB`/`\x1b[NA` + `\x1b[<col+1>G` 把**硬件光标**挪过去。
默认硬件光标是隐藏的（画面上画的是假光标），因为部分终端在隐藏光标时也能跟踪 IME 位置；
需要可见光标才定位的终端用 `PI_HARDWARE_CURSOR=1` / `setShowHardwareCursor(true)` 打开。

README 还明确写了一个容易踩的坑（一手原文）：
> "**Container components with embedded inputs:** When a container component (dialog, selector, etc.) contains an `Input` or `Editor` child, the container must implement `Focusable` and propagate the focus state to the child... Without this propagation, typing with an IME (Chinese, Japanese, Korean, etc.) will show the candidate window in the wrong position."

fork 的本地 patch 里还有一条 CJK 专项：**CJK-aware autolinks**（PR #2917，pi-tui 0.84.3）——
> "Stop GFM autolinks at CJK/full-width punctuation so a bare URL followed by CJK text no longer swallows the CJK characters into the link target."

### 2.6 非交互 / 多路输出（一手）

`kimi -p/--prompt <text>` 是唯一的非交互面，`--output-format` 只有 `text` 和 `stream-json` 两档。

- **流分离**：`PromptTranscriptWriter` 把 **assistant 正文写 stdout，thinking 写 stderr**
  （两个独立的 `PromptBlockWriter`）。`stream-json` 模式下 meta 信息（版本、resume 提示）
  变成 stdout 上的 JSON 行；`text` 模式下这些走 stderr。管道消费者拿到的 stdout 是干净的。
- **不调 `process.exit()`**：print 模式靠事件循环自然排空。为此专门写了
  `src/cli/headless-exit.ts`，注释是我在这份代码里读到的最讲究的一段：
  > "If a stray ref'd handle survives shutdown — a lingering socket (e.g. a connection blackholed by a restrictive firewall, or an HTTP/2 session kept alive by PING), an un-cleared timer, or a child whose pipes stay open — the loop never empties and the process hangs until an external timeout kills it. This arms an **unref'd** fallback timer: a healthy run drains and exits naturally before it fires... It only force-exits a run whose loop is already wedged."
  配套 `drainStdio()` 在强制退出前先等 stdout/stderr 缓冲刷完（有上限），
  免得慢速管道消费者导致输出被截断。
- **print 模式主动关掉自动更新交互**：`runUpdatePreflight(version, uiMode === "print" ? { isTTY: false } : {})`
  ——传死 `isTTY: false`，保证非交互运行不会弹升级提示。
- **TTY 检测的实际用处**：`detectTerminalTheme()` 非 TTY 直接返回 `dark` 并跳过 OSC 11 探测；
  `writeClipboardOSC52()` 非 TTY 直接返回 false（注释：*"the sequence would pollute piped output"*）；
  `NO_COLOR` / `FORCE_COLOR=0` / `CI` 非空都算 color opt-out。
- **交互模式本身没有 TTY 硬门槛**（代码级阅读，**未实测**——实测要启交互会话，BRIEF 禁止）：
  `ProcessTerminal.start()` 只做 `if (process.stdin.setRawMode) setRawMode(true)`，
  没有"不是 TTY 就拒绝启动"的分支。issue #1792（Windows TUI 打印原始 ANSI 而不渲染）
  是同一族的观测现象。

- **终端死亡处理**（`src/tui/utils/dead-terminal.ts`，一手注释）：
  `EIO`/`EPIPE`/`ENOTCONN` 被识别为"控制终端没了"（父 shell 崩了、tmux server 没了、
  SSH 断了但没送 SIGHUP）：
  > "Continuing to write to a dead terminal would re-fire the same error on every render tick and pin a CPU core."
- **崩溃时恢复终端**（`src/utils/terminal-restore.ts`）：
  `TERMINAL_RESTORE_SEQUENCE = "\x1B[?25h\x1B[?2004l\x1B[<u\x1B[>4;0m"`——
  显示光标、关 bracketed paste、pop Kitty keyboard、关 modifyOtherKeys，每步单独 try/catch。

## 3. 工程实践与设计品味（含作者自述）

### 3.1 他们明确做什么

**一手自述，`packages/pi-tui/README.md` 的 Features 段：**
> - "**Differential Rendering**: Three-strategy rendering system that only updates what changed"
> - "**Synchronized Output**: Uses CSI 2026 for atomic screen updates (no flicker)"
> - "**Bracketed Paste Mode**: Handles large pastes correctly with markers for >10 line pastes"
> - "**Component-based**: Simple Component interface with render() method"
> - "**Inline Images**: Renders images in terminals that support Kitty or iTerm2 graphics protocols"

**组件模型极简**：`Component` 只要一个 `render(width: number): string[]`，返回一组"每行不超过 width
可见宽度"的字符串。没有虚拟 DOM、没有协调器、没有 Flexbox。README 原文：
> "When creating custom components, **each line returned by `render()` must not exceed the `width` parameter**. The TUI will error if any line is wider than the terminal."

**缓存的责任在组件侧**，框架不替你做。README 给的是手写缓存模板（`cachedWidth`/`cachedLines`/`invalidate()`）。
框架侧对应的优化是 fork 的本地 patch：组件返回同一个字符串引用时，
`doRender()` 直接复用上一帧的处理结果，跳过归一化与宽度重算——
`pi-tui` 0.80.8 changelog 原话："Speed up the terminal renderer in long sessions by reusing processed lines across frames."

**tui.toml 与 config.toml 分家**（一手，`docs/en/configuration/config-files.md`）：
> "runtime settings live in `config.toml`, and terminal-UI preferences live in a companion `tui.toml`."

本机 0.31.0 的 `tui.toml` 只有 6 项，上游 HEAD 文档已有 11 项。**完整维度**（一手，文档表格）：
`theme` / `render_latex` / `disable_paste_burst` / `cache_expiry_hint` / `disable_feedback_survey` /
`[editor].command` / `[notifications].{enabled,notification_condition}` / `[upgrade].auto_install` /
`[status_line].{items,command}`。

注意这条分界暴露的取舍：**`tui.toml` 里放的全是"客户端偏好"，没有一条改变 agent 行为**。
主题、粘贴启发式、通知、外部编辑器、状态栏、自动升级、LaTeX 渲染——
换台机器丢了它不影响任何结果，只影响观感。而 `config.toml` 里是 model/provider/permission/hooks。
这条线划得很干净，代价是有些东西会两头找（如 mermaid 开关在 tui.toml，而图片压缩预算在 config.toml）。
还有 `/reload-tui`（只重载 tui.toml）与 `/reload`（两个都重载）两个命令，说明他们认为
"只改观感"值得一条更轻的重载路径。

**自定义状态栏是外部命令**：`[status_line].command` 的第一行 stdout 替换 footer，
JSON 快照从 stdin 传入，**300 ms 上限、每秒最多一次、失败回落内置布局**——
把用户脚本关进了明确的预算里。

**TUI 是 klient 契约的一个客户端**（一手，模块表）：`packages/klient` 定义了
agent/global/session 三层契约（`contract/session/{approval,events,interaction,lifecycle,question}` 等），
SEA bundle 里只打包了 `transports/memory/`。也就是说 **TUI 和 Web UI 面对同一套类型化契约，
TUI 走进程内内存传输，Web 走 kap-server 的 HTTP/WS**。
`src/tui/reverse-rpc/` 则是反向通道：内核要审批或提问时，通过 `modal-coordinator` 弹 TUI 模态框。

**四个前端面共用一个内核**：TUI（`runShell`）、headless（`runPrompt`）、
ACP server（`kimi acp`，`@agentclientprotocol/sdk@0.23.0`，`protocolVersion: 1`，`specTag: "v0.10.x"`，
带 `negotiateVersion()` 降级协商）、Web/Desktop（`kimi web` + `kimi vis`）。

**`--yolo` 与 `--auto` 的分档**（一手，`kimi --help`）：
> `-y, --yolo    Auto-approve regular tool calls; the agent may still ask questions.`
> `--auto        Start in auto permission mode: fully autonomous, the agent will not ask questions.`

"免批准"和"免提问"被拆成两档。config.toml 里对应 `default_permission_mode = manual|yolo|auto`。

### 3.3 可核实的设计取舍痕迹

- **0.80.6 的 revert**（一手 changelog）：
  > "Revert the fork's viewport and scrollback rendering patches, restoring the upstream differential-rendering behavior. The narrow-terminal fixes (width clamping, overwide-line truncation) are kept."

  这是一次明确的"我们自己改渲染改砸了，退回上游"。0.80.4 和 0.80.5 两版里那几条
  "pin the viewport anchor on partial shrinks"、"re-anchor the viewport with an in-place repaint"
  是被 revert 的对象。**fork 承担渲染核心的改动，代价被自己量化并承认了。**
- **transcript 窗口化**（一手，`src/tui/utils/transcript-window.ts`，全是 doc 注释）：
  因为每帧要把整棵组件树渲成字符串数组，历史必须裁。五个环境变量控制：
  `KIMI_CODE_TUI_MAX_TURNS=15`（保留最近 15 轮）、`..._EXPAND_TURNS=3`（只有最近 3 轮能 Ctrl+O 展开）、
  `..._HYSTERESIS=5`（超出 5 轮才裁，避免抖动）、`..._KEEP_RECENT_STEPS=30`、
  `..._KEEP_RECENT_ASSISTANT=20`、`..._KEEP_RECENT_ASSISTANT_COMPLETED=2`。
  作者自述取舍：
  > "Once a turn ends, fold all but its last few assistant messages into the step summary — intermediate chatter is rarely re-read, while the tail usually holds the conclusion."
- **"缩小时是否清空空行"是可配的**：`setClearOnShrink` / `PI_CLEAR_ON_SHRINK`，注释：
  > "When false, empty rows remain (reduces redraws on slower terminals)."
- **`fd` 按需下载**：`@` 文件补全依赖 `fd`。系统没有就从 `${KIMI_CODE_CDN_BASE}/fd` 下载
  指定版本（v10.4.2，darwin-x64 是 v10.3.0）并**校验硬编码的 SHA-256**，解压到 `~/.kimi-code/bin/`。
  Linux x64 拿的是 **musl 静态版**——尽管主程序自己不支持 musl。
- **渐进式发布**：`~/.kimi-code/updates/` 里 `latest.json` 带 rollout 计划
  （`[{percent:30,delaySeconds:0},{percent:30,delaySeconds:43200},{percent:40,delaySeconds:86400}]`），
  按 `device_id` 算 bucket。`rollout.log` 每次启动记一行决策
  （`phase`: startup-cache / background-refresh；`reason`: not-newer / eligible / **held** / no-manifest）。
  本机日志里能看到 bucket=32 的设备被 `held` 到 `eligibleAt` 才升级——**灰度是真跑的，不是摆设**。

## 4. 实施取舍与代价

### 4.1 Node SEA 的账

| 代价 | 具体数 / 事实 | 强度 |
|---|---|---|
| **体积** | 本机 linux-x64 **153.7 MB**（0.28.1 是 160.8 MB）。其中 Node 运行时约 123 MB，SEA 载荷 30.7 MB。npm 渠道 unpacked **53.3 MB** | 强（本机实测 + npm registry）|
| **未 strip** | 17.9 MB 符号表 + DWARF 随二进制走 | 强 |
| **每平台一份完整 Node** | 6 个目标（darwin/linux/win × x64/arm64），每份都是一整个 Node | 强（install.sh + install.ps1 分支）|
| **musl 生态被排除** | install.sh 直接拒装，引导去 npm | 强 |
| **升级 = 重下整个二进制** | `~/.kimi-code/updates/` + CDN + SHA-256 + 灰度 bucket；自建了一整套 rollout 机制 | 强 |
| **启动一度更慢** | 见 §6 | 中（二手，报告者自测）|
| **Windows 上 hooks 会闪控制台窗口** | #3297 open，标题直指 "(native single-binary CLI)" | 中 |
| **打包遗漏原生资产** | #3326 open："kimi web: terminal creation fails in the packaged binary (node-pty native assets not bundled; deeper hang after fixing)" | 中 |
| **两条分发渠道会打架** | #3789 open："npm install from an old native install (≤0.28) silently keeps the old binary: `~/.kimi-code/bin/kimi` shadows the new npm shim via PATH" | 中 |

**换来的**（一手，README）：
> "Install with one command: no Node.js setup, PATH gymnastics, or global module conflicts."

**一个意外的副作用**：`useSnapshot:false` + `useCodeCache:false` 让 18.9 MB 的 JS 以明文存在二进制里，
且 rolldown 输出未压缩、保留 `//#region <源文件路径>` 标记。
**后果是这个"闭源分发"的二进制实际上可以被完整反解成接近源码的形式**——
我这一路的一手证据大半来自这里。（考虑到仓库本身是 MIT 开源的，这不构成泄密；
但它确实意味着**选 SEA 而不开 snapshot/code-cache，等于放弃了产物的不透明性**。
这是事实陈述，不是价值判断。）

### 4.2 内联渲染（非备用屏）的账

**得到的**：输出留在 scrollback 里，`Ctrl+C` 之后历史还在，可以用终端原生选择复制，
SSH 断线后终端不会残留一屏烂摊子。

**付出的**（每一条都有 open issue 佐证，见 §5）：
- 任何"视口之上发生变化"都退化成 `\x1B[2J\x1B[H\x1B[3J` 全量重绘 —— **会清掉 scrollback**。
  resize 拖拽时每一步都触发（#2324）。
- 没有应用级滚动视口 → 滚动位置会被重绘打回顶部（#981、#2168、#2296、#3263）。
- 历史必须窗口化（默认 15 轮），**超出窗口的内容从组件树里被销毁**，
  折叠后的 assistant 消息无法再展开（#2904）。
- 应用与终端争鼠标语义：既没接管，"Copied" 提示又和真实剪贴板对不上（#2721、#3745）。

### 4.3 fork 一个高速演进的上游的账

上游 `earendil-works/pi` 有 107,890 stars 且改动频繁。Moonshot 的做法是**周期性 re-baseline**
（0.80.x → 0.84.1 → 0.84.2 → 0.84.5），每次在 changelog 里逐条重申保留的本地 patch。

- **好处**：0.84.2 白拿了 "~9-18x alternate-screen render-churn reduction" 和全屏搜索；
  0.84.5 白拿了组件级鼠标、原生剪贴板、大输出分块渲染。
- **代价一**：TUI 的核心能力节奏受上游支配。#1174 的保守鼠标策略提案等了两个半月没人回，
  最后是靠 re-baseline 把上游的鼠标实现搬过来——**社区提案的路径被 re-baseline 的路径挤掉了**。
- **代价二**：上游改约定要跟着改。0.84.5 changelog：
  "Upstream also removed the library's own `PI_*` environment/config reads; logging destinations are now constructor-provided only."
- **代价三**：上游的 bug 直接变成自家的。#2324 把根因追到 `earendil-works/pi#6050`（其状态见 §5.3），
  也就是说**这个 flicker 在 Moonshot 侧只能等上游或自己打 patch，而他们刚 revert 过一次自己打的渲染 patch（0.80.6）**。
- **品牌残留**：0.31.0 里调试日志仍往 `~/.pi/agent/pi-debug.log` 写，环境变量仍叫 `PI_*`。
  （上游 0.85.1 把 `PI_*` 读取删掉，等于顺手解决了这个尴尬。）

### 4.4 嵌入整个浏览器 UI 的账

TUI 用户为 10.4 MB 他们可能永远不打开的 Vue/mermaid/katex/字体资产付费。
反过来，`kimi web` / `kimi vis` 不需要联网拉前端、不需要额外安装，离线可用。
这是一个**明确的、可量化的取舍**：**每个 CLI 用户为 Web UI 承担约 6.8% 的二进制体积**。

（2.0.0 起 mermaid 也能在终端里画了，这部分能力在两个面上各实现了一遍。）

### 6.3 渲染性能（一手 changelog + 一手 bench 源码）

pi-tui 0.84.1/0.84.2 changelog 的数字：**"the ~9-18x alternate-screen render-churn reduction"**。

**测法**（一手，`packages/pi-tui/test/render-churn-bench.ts`，我读到了源码）：
- 布局：`VStack [ ScrollView(transcript), dock VStack [status, editor, footer] ]`
- 终端：100 列 × 30 行的 `NullTerminal`（丢弃输出，把 xterm 解析排除在测量外）
- 20 帧预热 + 300 帧测量
- 两个场景：`static`（帧间无变化，纯重合成 churn）、`editor`（每帧往编辑器追加一个字符）
- 指标：**V8 sampling heap profiler 的累计分配量**（采样间隔 4096），注释写明
  "it measures churn, not retention"；以及 wall time

**三条限定**（必须跟着数字一起报）：
1. 这是 **alt-screen** 路径的数字，**不适用于本机 0.31.0 的 inline 路径**。
2. 它测的是**分配量 churn**，不是帧率、不是延迟、不是内存占用峰值。

## 附：一句话可带走的结构事实

- 产品谱系：**kimi-cli（Python / prompt-toolkit + rich，前代，wind-down）→ kimi-code（TypeScript / pi-tui fork，现产品）**，官方单向迁移。
- 分发：**Node v24.15.0 SEA 单文件（linux-x64 153.7 MB）** + npm（53.3 MB unpacked）双渠道；musl 被明确排除。
- TUI：**pi-tui（`earendil-works/pi` 的 fork，本机 0.80.8 / 上游已到 0.84.5）**，周期性 re-baseline，
  本地 patch 逐条在 changelog 里公示。
- 渲染：**内联三段式差分 + CSI 2026 同步输出 + 16 ms 帧节流 + 50 ms delta 合批 + 默认 15 轮 transcript 窗口**。
- 备用屏与鼠标：0.36.0 起有，但**至今仍是 `KIMI_CODE_TUI_FULL_SCREEN=1` opt-in**，默认内联。
- CJK：宽度模型、Intl.Segmenter 分素、逐字断行、IME 硬件光标定位、CJK autolink patch 都做了；
  **ambiguous-width 无 locale 开关（#3301 open）、中英混合大粘贴会冻结（#2776 open）、IME 输入卡顿（#3753 open）**。
