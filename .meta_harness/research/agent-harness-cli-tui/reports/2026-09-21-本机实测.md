# 本机统一口径实测：四家 CLI 的启动、体量与可移植性下限

**这一份不是某一家的报告，是派发者在同一台机器、用同一把尺子量出来的横向数字。**
六路调研被明确禁止各自测一套——六组不可比的数字比没有数字更坏。

## 0. 结论先行

1. **非交互启动耗时跨越两个数量级**：codex 11 ms，claude 189 ms，cursor-agent 801 ms，kimi 1242 ms。
   这条梯度与各家的运行时选择完全对齐：原生 Rust → Bun 编译单文件 → 外挂 Node + webpack chunk → Node SEA。
2. **常驻内存同向拉开**：24.5 MiB / 142.4 MiB / 194.4 MiB / 387.7 MiB（`--help` 一次调用的峰值 RSS）。
3. **六家里五家自带 ripgrep**（codex / claude / cursor / kimi / DSH），**只有 Pi 没有**。
   两家自带更多：codex 连 `zsh` 与 `bwrap` 都随包分发，cursor 自带 `node` 与
   **一个 fork 过的 ripgrep**（`15.1.0-cursor5`）。这是本轮最明显的一条跨家共性。
   （初稿曾写"四家"，那是只覆盖了本机可执行的四家；补齐两份源码取证后更正为五家，并记下 Pi 是例外。）
4. **「静态链接主二进制」不等于「这一份分发可移植」**：codex 主二进制是 static-musl，
   在本机 glibc 2.31 上跑得动；但它**随包分发的 `zsh` 是动态链接且要求 GLIBC_2.38，实测直接无法执行**。
   分发的可移植性下限由**最弱的那个随包文件**决定，不由主二进制决定。
5. **分发体积普遍在 150–330 MB 量级**，四家没有一家把「装得小」当成目标。

## 1. 取得方式与环境

- 机器：Ubuntu 20.04.6 LTS，Linux 5.15.0-1084-aws，x86_64，8 核，30 GiB 内存，**glibc 2.31**。
- 时间：2026-09-21。
- 方法：`timeout 30 <bin> <arg> >/dev/null 2>&1 </dev/null`，**先 2 次预热**，再取 **n=10** 的
  min/中位/max，墙钟由 `date +%s%N` 前后取差。峰值 RSS 由 `/usr/bin/time -v` 单次 `--help` 取
  `Maximum resident set size`。脚本随包保存为 `measure.sh`，原始输出 `measure-raw.txt`、`measure-footprint.txt`。
- **stdout 被重定向，四家走的都是非 TTY 路径。**

## 2. 启动耗时（非交互，n=10，单位 ms）

| 对象 | 版本 | `--version` 中位 (min–max) | `--help` 中位 (min–max) | user/sys CPU (`--help`) | 自愿/非自愿上下文切换 |
|---|---|---|---|---|---|

| **claude** | `2.1.278` | **12** (12–14) | **189** (179–221) | 0.20 / 0.06 s | 73 / 22 |
| **cursor-agent** | `2026.08.04-aaa8809` | **881** (804–1025) | **801** (772–988) | 0.97 / 0.14 s | 732 / 118 |
| **kimi** | `0.31.0` | **1247** (1216–1509) | **1242** (1173–1403) | 1.50 / 0.20 s | 936 / 166 |

`--help` 才真正初始化运行时。**该推断未经源码或符号验证**，仅由两个数字的落差提出。
其余三家两个子命令耗时一致，没有这种分叉。

## 5. 可移植性下限（`ldd` + `objdump -T` 取最高 GLIBC 版本要求）

| 对象 | 链接方式 | GLIBC 版本要求 | 在本机（glibc 2.31）可执行 |
|---|---|---|---|
| `codex`（主二进制） | **statically linked** | 无 | ✅ 实测 `codex --version` 正常 |
| `codex-resources/bwrap` | 动态 | — | ✅ 实测输出 `bubblewrap built for Codex` |
| `codex-path/rg` | 动态 | — | ✅ 实测输出 `ripgrep 15.2.0 (rev e89fff89ac)` |
| **`codex-resources/zsh/bin/zsh`** | 动态 | **GLIBC_2.38** | ❌ **实测失败**：`version 'GLIBC_2.38' not found (required by ...)`，libm 与 libc 各报一次，另有 GLIBC_2.33 缺失 |
| `claude.exe` | 动态（librt/libc/libpthread/libdl/libm） | **GLIBC_2.26** | ✅ |
| `kimi` | 动态（+ libstdc++、libgcc_s） | **GLIBC_2.28** | ✅ |
| cursor 自带 `node` | 动态 | **GLIBC_2.28** | ✅ |

**第 4 行是本轮唯一一条「构造并验证过」强度的负面结论**（不是「读遍没找到」）：
codex 的 musl 静态主二进制把自己的 libc 依赖降到零，但同一份分发里的 `zsh` 要求比本机高 7 个小版本的 glibc，
落地即失效。**这条观察不支持推广为「codex 在旧发行版上不可用」**——主二进制与 `rg`、`bwrap` 都正常，
只有随包 `zsh` 这一个文件失效，其对 codex 功能的实际影响**本轮未测**（未查证它在什么场景下被调用、
是否有回退到宿主 shell 的路径）。

## 8. 这份实测不支持什么

- **不支持任何关于 TUI 首帧延迟、重绘帧率、大输出滚动性能的结论。**
  本轮**刻意没有测**：启动交互式 TUI 等于开一个真实会话，会触碰认证、写入用户状态、可能消耗额度。
  上表全部是**非交互子命令的进程启动成本**，与「用户按下回车到看见界面」不是同一件事。
- **不支持「启动快 = 交互流畅」**。两者由不同的路径决定，本轮无证据连接它们。
- **不支持对 DeepSeek Harness 与 Pi 的任何运行时数字**：两者本机均未安装，只做了源码取证。
  因此第 2–7 节的表格**只有四家**，缺的两家不是"没测出来"，是**不具备测的条件**。
- **单机单次采样**：n=10 只压住了同一台机器上的抖动，没有覆盖不同 CPU、文件系统、冷页缓存
  （无 root 权限，**无法清空 page cache，所有数字都是热缓存**）。冷启动会更慢，慢多少本轮未测。
- **版本绑死**：所有数字只对上表列出的那几个版本成立。

## 9. 终端控制序列的同口径探测（派发者统一施测）

**为什么由派发者做**：各路分头查 escape sequence，口径必然不一致（搜的扩展名不同、是否含 `node_modules` 不同），
得到的表不可横比。下表用同一组特征串、同一套范围规则跑出来。

**方法**：二进制用 `strings -n 3 | grep -cF '[<seq>'`；源码树用 `grep -rhoaF` 限定
`*.js *.ts *.tsx *.rs` 且不含 `node_modules`。计的是**出现次数**，不是去重后的实现点数。

| 对象 | `?1049`<br>alt-screen | `?2004`<br>括号粘贴 | `?2026`<br>同步输出 | `?25l`<br>隐藏光标 | `?1000/1002/1006`<br>鼠标 | `?1004`<br>焦点 | `?u`<br>kitty 键盘 |
|---|---|---|---|---|---|---|---|
| claude.exe `2.1.278` | 2 | **0** | **4** | 1 | 2/0/2 | 0 | 0 |
| kimi `0.31.0` | **0** | 3 | **6** | 2 | 0/0/0 | 2 | 1 |
| codex 二进制 `0.154.0` | 2 | 2 | **2** | 2 | 0/0/0 | 2 | 1 |
| cursor-agent bundle | 6 | 2 | **6** | 3 | 0/0/0 | 2 | 0 |
| codex 源码 `774d6425` | 10 | 0 | **2** | 2 | 8/8/7 | 0 | 3 |
| pi 源码 `890f9208` | 6 | 4 | **14** | 5 | 3/4/5 | 5 | 2 |
| **DSH 源码 `c291e796`** | **0** | **0** | **0** | **0** | 0/0/0 | **0** | **0** |

### 9.1 读得出的两条

**（a）同步输出（DECSET 2026）在除 DSH 外的每一家都出现。**
这个序列的唯一用途是把一帧的多次写入包起来、让终端一次性呈现，即消除撕裂与闪烁。
**六家里五家都用了它，意味着这已经是这一代终端 agent 的事实基线**，而不是某一家的巧思。

**（b）DSH 全表 0，且不是检索缺口——三条独立证据同向。**
1. 全仓库（不限扩展名、不排除任何目录）搜 `?1049` 与 `?2026`，**命中文件数为 0**；
2. 全仓库 `package.json` 里 TUI 相关依赖：`react` 50 处，`ink` / `ink-*` / `blessed` / `opentui` /
   `terminal-kit` / `yoga-layout` **各 0 处**；
3. `apps/cli/package.json` 的 `description` 自述为
   **"dsh CLI: profile boot, plugin management, and the browser UI alias"**，
   且 `apps/` 下并列着 `cli`、`desktop`、`desktop-host`、`web` 四个应用。

→ **DSH 的 CLI 是启动器与插件管理器，它的人机界面不在终端里。**
这不是「本轮没查到它的 TUI」，是「它这一版没有 TUI」。
最终形态以 DSH 那一路的源码通读为准，本节只提供同口径的交叉佐证。

### 9.2 这张表不支持什么

- **不支持「命中 0 = 没有这个能力」。** 动态拼接的序列（`\x1b[?${code}h`）、被 minify 拆散的字面量、
  由第三方库在 `node_modules` 内发出的序列，本方法一律看不见。
  除 DSH 外，每个 0 都只是**「在这个位置、用这个方法没找到」**。
  已额外检索过动态构造形态（`\x1b[?${`、`\u001b[?${`、`CSI ?`、`DECSET`）在 DSH 源码中同样 0 命中。
- **不支持按次数比较谁做得更完整。** 出现次数受打包方式影响极大：
  同一个实现点在 minify 后可能只剩一处，在源码里可能开关各一处。
- **claude 的 `?2004`=0 尤其不可当作「不支持括号粘贴」**——Bun 打包会内联并改写字面量，
  而其它三个序列却命中了，说明该方法对这个二进制只是部分有效。**这是本方法的已知盲区，不是产品事实。**

## 10. 非交互界面的同口径对照（派发者统一施测）

**方法与其盲区（先说盲区）**：对四家实测 `--help` 并保存原文于 `help/`。
**顶层 `--help` 的字面扫描会制造假阴性**——codex 把非交互能力放在 `exec` 子命令下，
顶层看不到 `--output-format`、`--json`。因此下表**只支持「顶层暴露了什么」，不支持「产品是否具备该能力」**。
为此补抓了 `codex exec --help`（112 行）。DSH 与 Pi 本机未安装，不在表内。

| | codex `0.154.0` | claude `2.1.278` | cursor-agent `2026.08.04` | kimi `0.31.0` |
|---|---|---|---|---|
| `--help` 行数 | 133（顶层）+ 112（`exec`） | **302** | 89 | 46 |
| 单次非交互 | `exec` / `e` 子命令 | `-p, --print` | `-p, --print` | `-p, --prompt` |
| 输出格式 | `exec --json`、`--output-schema`、`--output-last-message` | `--output-format` | `--output-format`：`text｜json｜stream-json` | `--output-format`：`text｜stream-json` |
| 增量流式 | — | — | `--stream-partial-output` | （`stream-json`） |
| 会话接续 | `resume` / `fork` / `queue` / `archive` / `unarchive` / `delete` 六个**一等子命令** | `--resume` / `--continue` | `--resume [chatId]` / `--continue` | `-S, --session [id]` / `-c, --continue` |
| 沙箱 | `-s, --sandbox` + `sandbox` 子命令 | （顶层未见） | `--sandbox` | （顶层未见） |
| 免批准 | `--approve-for-me`、`--dangerously-bypass-approvals-and-sandbox` | （顶层有 `--permission` 系） | `-f, --force` | **`--yolo` 与 `--auto` 两档**：前者仍可能提问，后者完全不问 |
| 浏览器界面 | — | — | — | `web`（本地 server + Web UI）、`vis`（会话可视化） |
| 编辑器协议 | `app-server`、`remote-control`（均标 experimental） | （顶层未见 MCP 之外的） | — | **`acp`**：作为 Agent Client Protocol server 走 stdio |

### 10.1 读得出的三条

**（a）`stream-json` 是非交互流式输出的事实标准。** claude、cursor、kimi 三家都提供，
且都与「单次非交互」开关绑定。codex 走的是另一条路（`--json` + `--output-schema` + `--output-last-message`），
**它是唯一一家提供输出 schema 约束的**。

**（b）会话管理在 codex 是一等 CLI 命令，在其余三家是标志位。**
codex 有 `resume`/`fork`/`queue`/`archive`/`unarchive`/`delete`/`migrate-rollouts` 七个子命令，
其余三家只有 resume/continue 两个开关。这与上一轮会话设计调研的结论方向一致
（见 [四个 agent harness 怎么设计「会话」](../../agent-harness-session-design/research.md)：会话树只有 Codex 做了）。

**（c）终端不是唯一界面，而且不止 DSH 一家这么想。**
kimi 有 `web` 与 `vis` 两个把界面搬进浏览器的子命令，DSH 的 CLI 干脆自述为
"the browser UI alias"（见第 9.1 节）。**六家里至少两家把浏览器界面当作并行的一等界面。**

### 10.2 这张表不支持什么

- **不支持任何「某家不支持某能力」的结论**——顶层 help 没列不等于没有，codex 就是现成的反例。
  每一个"—"都只意味着**「顶层 `--help` 文本里没有这个字面量」**。
- **不支持按 `--help` 行数比较复杂度**。302 行 vs 46 行的差别里，既有功能面的差别，
  也有「全塞顶层」与「分散进子命令」的组织差别，本方法区分不开这两者。

### 11.2 ACP 探测失败（**方法失效，不是观察结果**）

## 12. Pi 的一条独有事实（源码取证，顺带发现）

本节不是同口径对照，是做跨家探测时撞见的、值得单独记一笔的事实。

**Pi 自研并发布了一个 TUI 库**：`@earendil-works/pi-tui` **v0.86.1**，
`package.json` 的 `description` 自述为
"Terminal User Interface library with **differential rendering** for efficient text-based applications"。

- **发货路径确实在用它**：`packages/coding-agent/package.json` 依赖 `@earendil-works/pi-tui`
  （全仓库仅两处引用该包名：它自己与 coding-agent）。
- **运行时依赖只有两个**：`get-east-asian-width@1.6.0`（**东亚字符宽度**）与 `marked@18.0.11`（markdown）。
  没有 React、没有 Ink、没有 yoga。
- **为三个平台各写了原生模块**：`native/darwin/src/*.m`（Objective-C）、`native/linux/src/*.{c,h}`、
  `native/win32/src/*.c` + `build.mjs`，三边都带 `prebuilds/**/*.node`；
  头文件为 `native/napi.h` 与 **`native/clipboard.h`**，源码里另有 `native-modifiers.ts`
  → 原生代码是为**剪贴板**与**键盘修饰键**这两件终端里做不干净的事而写的。
- **用 `@xterm/headless` 作为 devDependency 测渲染**——即拿一个真实终端仿真器当断言靶子来验收 TUI 输出。
- 42 个源文件里有 `tui-alt-screen.ts`、`alt-screen-search.ts`、`terminal-image.ts`、`latex.ts`、
  `kill-ring.ts`（Emacs 式剪切环）、`fuzzy.ts`、`autocomplete.ts`、`stdin-buffer.ts`、`keybindings.ts`。

**这条事实的分量在于对照**：六家里体量最小的那个，是唯一从零造 TUI 库、
并为此维护三套平台原生代码的。**代价本节未测**（三平台原生构建与 prebuild 分发的维护成本、
`get-east-asian-width` 之外的宽字符边界、differential rendering 的实际效果），交 Pi 那一路。
