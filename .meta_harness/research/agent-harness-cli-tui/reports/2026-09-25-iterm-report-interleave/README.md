# iTerm 合法模式答复拆散粘贴尾的真实观察

2026-09-25，macOS iTerm3.7.1beta1、Node24.21.0，默认普通CmdV纯文本758个ASCII字符。自己的新窗口89025，用户剪贴板仅内存保存/未变更时恢复，结束关闭窗口；没有改全局偏好。

实际字节分三次到达：768字节（begin6+正文758+end前4字节ESC[20）；真实DECRQM答复11字节；末尾2字节1~。剔除真实答复可重建完整end，原字节串没有连续end。随D053制品附带的实际InputFramer消费后inPaste仍true。探针随后显式eof解除自己的测试分帧器，单独恢复2004与termios；JSON的events持数组引用，含清理时invalid/eof，不能把它们说成终端主动EOF。

这是实际模拟器输入顺序的反例，不是产品启动时机复现：探针故意在收到首块后发真实模式查询，测试其与普通粘贴块交错；没有伪造模式答复/粘贴字节。复现需要该D053固定制品路径或等价InputFramer构建、Swift/AppKit/AppleEvent和专用测试窗口；用新run路径运行Swift驱动，不能覆盖本包。

范围：证明该版本普通粘贴不把模式答复排到整帧之后、原分帧器无法在该交错结束粘贴。未证明所有机器每次调度都这样，也不是输入协议认证、修复验证或产品profile采用。与前一份iTerm正常粘贴/IME探针是不同场景，不推翻正常路径的有限观察。
