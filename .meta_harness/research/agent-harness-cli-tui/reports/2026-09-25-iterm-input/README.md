# iTerm 3.7.1beta1 普通输入的限定观察

2026-09-25，实际macOS iTerm 3.7.1beta1、Node24.21.0。官方精确tag提交85892eb49eef454ee8241f2003b8124cd5154fa8；取得方式为GitHub API树定位后Docker Node fetch raw源，原文件随包。来源路径为sources/Pasting/iTermPasteHelper.m、sources/PTYSession/PTYSession.m及PTYSession+ARC.m、sources/PTYSession/iTermNaggingController.m、sources/PTYTextView.m、sources/Settings/iTermAdvancedSettingsModel.m等，原路径见抓取日志。消费者为CLI第二终端提供路径核对；研究不采用该profile。

真实GUI普通CmdV：剪贴板含正文ESC伪结束/伪模式答复，收到一个真实2004 begin/end且正文ESC被终端删除。WeType Pinyin通过真实物理键nihao+Space提交“你好”；r1输入法在ASCII状态只得到nihao空格而失败，r2切中文后通过。记录mac-source-r2.json含真实字节和原2004 reset→set→reset；termios前后相同。这不是发送Unicode事件冒充IME。驱动只新建自己的iTerm窗口，完成后关闭；用户剪贴板所有类型只在内存暂存，changeCount仍为本次时恢复；原输入源恢复，无用户内容写入证据。没有改用户全局终端偏好。

源码事实：普通pasteEventWithString过滤不安全控制码，然后addPasteBracketing。PasteSpecial的regex替换在过滤后，能够重新引入ESC，不能推广普通粘贴结论。普通键在PTYTextView shouldHandleKeyDown发现isPasting且未passthrough时进入helper队列；完整framed buffer分块write，末块写后才清context并dequeueEvents。每次paste初始化关闭passthrough，但用户可在粘贴界面主动打开，届时不再有此顺序保证。PTYSession第一块先在bracketedPastePending下入dataQueue，安装expectation后按队列顺序flush，后续块仍经writeTask。不是所有自动化、广播、tmux、特殊键映射或异步IME路径都由这条普通键路径覆盖。

另一个真实限制：PTYSession+ARC的watchForPasteBracketingOopsieWithPrefix观察应用输出，若误判断残留00~前缀会调用maybeTurnOffPasteBracketing。NoSyncTurnOffBracketedPasteOnHostChange=true会自动关闭2004；键不存在则弹出提示，选择Yes/Always也会关闭，false则不关闭。该键由iTermNaggingController定义；本机只读defaults查询得到不存在，不等于false已经配置。探针没有触发该提示，也不能证明任意业务文本不会触发。

适用范围仅为这些实际路径/版本/设置；没有逐单元格字体截图验收，没有Apple Pinyin，没有产品TUI业务操作，没有慢速粘贴取消/IME异步交错穷举，也不证明终端偏好在运行中不会被人改变。输入法和普通粘贴分别完成，不宣称其并发交错安全。源文件是上游实现，不自动成为项目契约；是否限制支持前提及怎样选择另归设计。
