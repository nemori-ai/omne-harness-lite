# debugger 子代理：一方现状、社区做法、失败模式与取证手段

八家同代产品——**Claude Code、Codex、Cursor、GitHub Copilot、Gemini CLI、opencode、Kimi Code CLI、
DeepSeek Harness**——各自把「调试」这件事放进了子代理体系的哪个位置；社区把 `debugger` 这个角色
写成了什么样；这类角色被实证记录下来的失败模式有哪些；以及要让 agent「看见」终端与桌面应用里的问题，
现有手段各自能证明什么、在哪里失真。

这项调查要区分四件事：**一方产品实际内置了什么**（而不是文档里出现过哪个名字）；
**社区在权限这一维上是否存在可援引的共识**（分歧本身就是结论）；
**哪些失败模式有实证而不只是轶事**，以及它们的实证对象与本项目的对象差在哪；
**每一种取证手段的证明力边界**。

- **调查对象与基线**：八家的**官方文档站、官方仓库源码与官方博客，以 2026-09-22 当日线上版本与
  `main`/`master` 分支为准**；社区侧 22 条来源；方法学侧 21 条论文与工程规范。
  **三份稿都没有记录 commit SHA 或产品版本号**——精确坐标只到「当日 + 分支」这一层，
  两处例外与其出处见[证据记录](evidence.md)。
- **消费者**：`tmp/omne-harness-lite-tui-design/06-debugger-subagent.md`（前端调试子代理的角色设计，
  任务材料，未入库）；将来的 `.meta_harness/agents/roles/frontend-debugger/`。
- **最近核对**：2026-09-22（首轮）。

## 准入核对

三路的取证条件、每条来源的身份与一手/转述标注、合并后的未核验清单，全部在[证据记录](evidence.md)，
**取证条件与结论不写在同一页**。本轮有五处必须随结论一起传下去的限制：

- **主会话没有逐句复核任何一条 URL。**三份稿是 subagent 产出，**属模型输出而非证据**；
  本包做的是去重、查冲突、把每条负面结论与它的检索位置绑在一起，**不为任何一条来源背书**。
- **八家的「没有内置 debugger」全部是读数缺口，不是构造反例。**其中只有 Codex 一家的角色清单可穷举且已读遍；
  其余是「读遍指定的那几份材料未发现」。**每个「未发现」都必须连同检索位置一起读。**
- **本包里没有一条以 TUI 渲染缺陷为对象的量化数据。**失败率数字来自 SWE-bench / Defects4J 的代码修复任务，
  UI flaky 的 45.1% 来自 Web 与 Android——**搬到终端场景是外推，不是观察**。
- **Reddit 与 Discord 的一手内容本轮不可达**（WebSearch 对 `reddit.com` 返回 API 400，WebFetch 被拒）；
  社区失败经验因此只有 **7 条用户自述、零第三方复现**。
- **方法学那一路自列七个条目只到转述级**（Zeller 两篇、Wong 综述、Pearson、CDP Accessibility 页、
  `@xterm/headless` 的局限描述、AgentStepper 的技术细节）；**另有 ttyrec 与 Terminal-Bench 两条同样是转述，
  未进它自己的清单**。逐条标注在证据记录里。

本家族不拥有方案选择：结论只写到「这条事实让什么变得不可能、什么要额外付出代价」为止。
角色该怎么设计、权限怎么配、取证手段怎么选，归
record/proposals 与
record/decisions。
