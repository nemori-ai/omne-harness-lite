# 与 AI 助理共同生活和工作的用户故事

需求讨论稿 1.0 · 2026 年 9 月 30 日

## 阅读说明

这套故事描述一种持续的协作关系：助理逐步理解用户的目标与取舍，感知获准接触的现实，知道时间与资源的限制；既承接直接委托，也主动发现和推进值得做的事情。用户可以独立工作、处于团队之中，或与外部伙伴合作，始终通过自己的助理与世界协同。

故事按使用关系组织：先建立理解与主动协作，再一起推动外部事情，随后展开设备与资源调动、日常交付和用户控制。每条故事均包含起因、连续过程、异常与完成标准，不按单个按钮或技术组件拆散。

故事基于当前已有体验、此前讨论的目标，以及本轮确认的商业服务与协同方向补充。这里表达希望完整成立的用户旅程，不宣称每个环节已经上线。具体功能对应另一套《产品定义与功能需求》。场景中的人物、项目和供应商均为说明需求的假设情境。

产品名称未定。本文使用“助理”和“产品”称呼；“协同资源”指为一件事接入的往来、材料、其他助理或能力，用户无需先学习这个术语才能开始使用。

## 一 建立持续理解与主动协作

### S01 注册之后，直接开始第一件事

**起因与目标**。用户希望助理帮自己整理活动材料，但没有部署经验，也不想为了试用先研究服务器与连接配置。

**连续过程**。

1. 用户注册账号，下载受支持的客户端并登录，看到自己的助理与可开始工作的入口，不需要先选择个人或团队版本。
2. 用户选择平台提供的 AI 与算力服务；已有服务的用户也可以填写兼容的 API。两条路径分别说明可用能力、计费来源和限制。
3. 用户交入一份活动需求书：“先帮我理一下要准备什么。”不必先建项目、分类或填写个人画像。
4. 助理读取材料并整理目标、交付物与缺口。文件里已经写明的日期和用途不再追问；真正影响下一步的事实缺失时才询问。
5. 用户看到原件、整理结果与真实处理状态，能继续修改要求。原件不会被摘要覆盖。
6. 工作需要私人邮箱或本机文件时，产品提供连接或范围选择入口；基础服务不要求用户自己部署。
7. 用户关闭电脑，随后在手机登录，能够找到同一件事、材料和成果，继续交流。

**异常与控制**。API 无效或额度不足时保留草稿与材料，说明怎样继续；首次注册中断后不要求重复建立身份。新设备登录不默认授权读取其中所有文件。

**完成标准**。一个普通用户可以从注册走到第一次真实交付，没有自行部署基础服务的步骤。关联模块：M07、M14、M15、M16。

### S02 相处两周之后，助理懂得我的取舍

**起因与目标**。用户在几次项目中表达过自己更重视稳定交付、偏好简洁表达。下一次讨论时，他希望这些背景仍然有用，也希望能够纠正助理的误解。

![几次相处形成对用户的理解，具体来源能够展开；用户指出这次情境不同后，助理调整当前判断和后续工作，原始记录仍被保留。](../插图/05-长期理解与纠正.png)

*图解 · 旧经验提供背景，用户的新反馈可以改变当下判断；记忆、证据和当前取舍各自可辨。*

**连续过程**。

1. 用户正常交流与工作，不必专门填写“记忆表”。助理逐渐形成对相关偏好和背景的理解。
2. 用户开启一段新的项目对话，助理结合之前的取舍组织方案，并说明哪些建议用了既往背景。
3. 用户问“你为什么觉得我不喜欢探索性的设计？”助理指出当时表达的范围与来源，而不是编造一段解释。
4. 用户纠正：“那次是因为客户赶时间，这次可以尝试。”助理区分那次项目的限制与长期偏好。
5. 后续建议随之调整，正在做的相关工作也重新考虑，重要变化对用户可见。
6. 用户可以打开对自己的理解，查找某个主题、展开依据，辨认哪些是自己说过的、哪些是助理推断的。

**异常与控制**。证据不足或来源不可达时明示；修正未成功不能显示已生效。用户的工作偏好不能自动覆盖生活场景，外部资料中的观点也不能变成用户立场。

**完成标准**。用户感到“它记得我，也听得进我的纠正”，新的相处能改变助理之后的判断。关联模块：M01、M02、M17。

### S03 它记得旧承诺，也理解我现在的时间

**起因与目标**。用户七个月前答应参加家人的毕业活动。现在收到一项出差邀约，没有主动要求助理检查冲突。

![助理把七个月前的约定与今天收到的出差邀请放到同一个时间语境中，核实日期与现实条件，再准备可行选择。](../插图/06-共同时间与现实.png)

*图解 · 时间感让新变化与旧承诺能够相遇；感知范围、来源时点和仍待核实的条件也需要清楚。*

**连续过程**。

1. 助理通过获准查看的日历与往来，发现出差日期可能影响那个旧承诺。
2. 它先核实相关日期、时区、地点与行程限制，不因为记录久远就忽略，也不把旧日期当作未来安排。
3. 在已有授权内，它整理可以调整的行程、需要协调的人以及还不确定的条件。
4. 助理向用户说明冲突及实际可行的选择，并展示依据。它不需要等待用户先创建“检查冲突”任务。
5. 用户告诉助理此次取舍，助理据此完成获准的调整，并把需要外部确认的部分继续跟进。
6. 原承诺、新行程和最后的决定保持清楚关联，用户之后不用重新回忆为何改过安排。

**异常与控制**。不能仅因“亲属活动”这一类别替用户预先决定轻重；只看到部分日历时说明覆盖范围。行程已对外确认的内容不能无声改动。

**完成标准**。长期理解与当下现实共同影响行动，用户得到可采取的结果，而不是一条缺乏背景的冲突提醒。关联模块：M01、M02、M03、M10、M13。

### S04 没有新指令，它主动改善反复发生的问题

**起因与目标**。用户长期希望提高内容交付质量。几次项目里，品牌需求与印刷规格对不上，导致反复返工；用户尚未提出专门改进任务。

![主动协作场景设计稿：助理结合持续目标与现实条件，自主发现问题，准备改进材料，并根据用户反馈调整。](../插图/01-主动协作.png)

*场景图 · 没有新的委托，助理仍可以从已有目标与共同经历中形成有依据的行动理由。*

**连续过程**。

1. 助理在参与这些工作时发现重复现象，形成一个初步判断：问题可能集中在需求与生产条件的衔接。
2. 它结合用户持续表达的目标，判断这件事值得调查，而不是仅把它记成一条观察。
3. 在已有资料权限和投入边界内，助理比较相关返工记录，区分已证实原因与仍待核实的解释。
4. 助理准备一份可修改的交付检查表，并用已有案例检查它是否能帮助减少遗漏。
5. 它在合适的时候向用户展示已经完成的调查和材料，说明为何开始、用了哪些依据、还不确定什么。
6. 用户指出一种特殊项目不适用，助理调整检查表及使用条件。
7. 下一次类似项目，助理主动采用适合的部分，并观察是否减少返工；无效时继续修正或停止沿用。

**异常与控制**。不能为显得主动不断制造文档和通知；调查收益不足时应收敛。新增外部沟通或扩大资料范围仍须符合原授权。

**完成标准**。没有新命令、也没有预先存在的待办，助理仍从连续目标中形成行动理由，做出可验证的改进。关联模块：M01、M02、M03、M08、M11。

### S05 它发现一个机会，并先替我做好准备

**起因与目标**。用户想逐步拓展某类内容业务。助理了解其能力、近期安排和可投入预算，在获准关注的信息中发现一个可能适合的机会。

**连续过程**。

1. 助理把新信息与用户的方向、已有作品和时间余量联系起来，形成值得进一步调查的判断。
2. 它检查机会是否仍有效、要求是否匹配、信息是否可靠，并估计进一步投入是否值得。
3. 在预算与授权范围内，助理整理相关作品、准备初步材料，必要时委派其他能力做有限调查。
4. 如果用户已经授权某类明确范围内的接洽，助理可以按该范围开展；没有此授权时先完成能够独立推进的准备。
5. 它带着实际进展来找用户，说明适合之处、代价、截止窗口和需要用户决定的内容。
6. 用户表示近期改变了方向，助理更新理解并结束不再合适的后续投入；已获得材料仍可回看。

**异常与控制**。机会已过期、来源不足或预算不合适时，不包装成必须抓住的好消息；用户未回应不能视为同意扩大投入。

**完成标准**。助理能够主动发现、调查和准备，也能够有理由地不做或结束，让用户的注意力用在有价值的选择上。关联模块：M01、M02、M03、M11、M16。

## 二 围绕事情与外部持续协同

### S06 与助理一起完成一轮内容生产

**起因与目标**。用户承接品牌活动，上游是品牌方，下游有设计师、印刷商和现场执行人员。他希望把需求、设计、打样、修改与交付串起来，减少自己逐条转发和追问。

![内容生产场景设计稿：供应商邮件、设计助理与物料文件夹加入同一件事，反馈推动修改，使命完成后保留成果和历史。](../插图/02-协同资源.png)

*场景图 · 往来、其他助理和物料分别保留真实内容，通过共同的协同资源心智参与同一件事。*

**连续过程**。

1. 用户交入品牌邮件、需求书和参考图，说明目标、时间及预算，助理整理已确定条件与尚未确定部分。
2. 用户指定品牌联系人、一个设计助理和印刷商往来，或者让助理从已可用资源中找到合适对象。
3. 每个协同资源在这件事里有清楚用途：确认口径、产出稿件、确认生产规格。用户看到具体名称、内容与状态。
4. 助理向设计助理交付获准材料，同时向印刷商询问必要的规格与档期；各方只获得完成此次协作所需的内容。
5. 等设计结果时，助理继续整理物料清单。印刷商回复后，所需修改回到原事情，再进入相关设计工作。
6. 品牌方改变口径，助理识别受影响的稿件、成本和时间，完成可恢复调整，将重要的新承诺带给用户决定。
7. 用户随时问“现在等谁”，可以得到基于真实往来与结果的回答，不用分别打开每个工具重新拼装进度。
8. 稿件、物料表和交付记录汇总为可使用成果；“已完成”“已发出”和“对方已确认”分别表达。
9. 活动结束，相关资源完成使命，不再持续监听或催促。历史、成果与整个邮箱账户继续保留，其他项目不受影响。

**异常与控制**。供应商没有回复时明确等待与跟进安排；某个设计任务失败不吞掉其他成果；外发结果不明先核实，不能盲目重发。

**完成标准**。邮件、其他助理和物料通过统一协同心智进入同一件事，变化能推动工作，使命可以结束。关联模块：M03、M04、M06、M09、M11、M17。

### S07 我在团队里，助理仍然为我承接协作

**起因与目标**。用户负责一个跨部门项目，同时对接外部顾问与客户。他希望助理处理自己负责的工作，不要求其他人先迁移到新平台。

![用户与自己的助理共同处在协作中心，与客户、同事及伙伴分别交换获准材料和反馈；对方可以继续使用原有沟通方式，各方职责和资料范围保持清楚。](../插图/08-多方协同.png)

*图解 · 服务主体始终是你；协作范围可以跨团队与组织，参与某件事并不意味着获得所有人的资料或决策权。*

**连续过程**。

1. 用户交入会议纪要，说明自己负责客户反馈，同事负责合同。助理理解职责与依赖。
2. 用户连接获准共享的材料与往来，同事或其助理也可以在需要时参与具体协作。
3. 外部顾问继续使用受支持的邮箱沟通，没有本产品账号仍能参与。
4. 助理在授权范围内准备材料、追踪反馈，发现客户与同事意见冲突后保留双方原意和来源。
5. 用户决定自己的处理方式，助理推进可以代表用户完成的动作；不能代其他人许下承诺。
6. 退出项目时，用户结束相关关注和权限，助理不继续追踪退出后的变化。

**异常与控制**。能读团队资料不意味着能转发给客户；用户的私人注解不会自动成为共享内容；参与项目不等于获得其他成员所有数据。

**完成标准**。团队与外部关系作为现实语境被理解，用户无需创建企业版账户结构才能让助理协同。关联模块：M04、M06、M09、M17。

### S08 一次研究，几个助理共同完成

**起因与目标**。用户需要研究一种新的内容制作方法，希望查清依据并得到可尝试的方案。他既关心质量，也希望投入适度。

![围绕同一个问题，助理把有限的研究任务和材料交给不同参与者，比较证据与分歧，汇回真实文件、结论及未解决的问题。](../插图/09-协作研究与交付.png)

*图解 · 委派要带着清楚的目的和材料边界；最终价值体现在可使用的成果与可追问的依据。*

**连续过程**。

1. 用户提出目标，交入文章链接、截图和一份现有方案，说明希望得到什么，以及可接受的投入。
2. 助理确认实际能读取哪些材料。原网页无法取得时，明确已看到的范围，再使用获准的其他信息渠道。
3. 助理判断是否需要其他助理参与，给不同参与者清楚的研究问题、材料范围和交付要求。
4. 用户能看见真实的协作进展；主助理在等待某项结果时，可以继续完成独立部分。
5. 参与者返回结果后，主助理比较依据与分歧，识别哪些只是推测、哪些有可核实支持。
6. 最终交付可阅读的结论、来源与可实际使用的试验材料。用户可以追问，也可以据此继续创作。
7. 委派结束后，相关资源完成使命，主界面和桌面助理都不再停在处理中。

**异常与控制**。没有真实委派就不能声称调用了其他助理；一项失败要交代剩余覆盖范围。增加参与者不自动获得更多权限或突破预算。

**完成标准**。用户取得有依据的成果，并能辨认协作带来了什么，而不是只看到参与者数量增加。关联模块：M04、M07、M11、M16。

### S09 把一件跨月事务交给助理陪跑

**起因与目标**。用户准备办理证件，知道大致步骤，但后续何时受理、何时领取并不完全确定，希望助理共同管理这段过程。

![办理一件跨周事务，经历准备、提交、等待与领取；不确定窗口中依据实际进展调整跟进，用户需要出面时获得提醒，完成后停止继续检查。](../插图/07-跨周推进.png)

*图解 · 确定步骤与不确定窗口共同属于一件事；助理根据现实进展调整节奏，并在使命完成后收尾。*

**连续过程**。

1. 用户说明目标与已完成的部分，交入所需材料。助理区分已知日期、待核实条件和大致时间窗口。
2. 助理组织准备、提交、等待与领取等阶段，指出需要用户本人完成的动作。
3. 有确定时间的约定进入可见安排；不确定阶段由助理根据实际情况安排适度检查，用户不必指定每次查询间隔。
4. 用户提交后补充回执，助理把它纳入同一件事，继续关注获准查询的进展。
5. 有变化时，助理调整后续安排；需要本人到场时提前准备地点、时间与材料提醒，并注意实际开放时间。
6. 用户换设备或数天未打开应用，再问“办到哪了”，仍能得到上次查到什么、目前等什么和下一步的真实回答。
7. 事项完成后停止后续检查，保留全程记录和最终材料。

**异常与控制**。外部查不到状态不能说成“没有进展”；窗口已过仍无结果时主动告知并调整，不无限重复检查。付款、提交等具体后果遵循已有授权与确认范围。

**完成标准**。事情跨越时间与会话仍连续，助理能跟随现实节奏推进，也能清楚结束。关联模块：M02、M03、M06、M10、M13。

### S10 还有两周和只剩两小时，助理采用不同做法

**起因与目标**。用户希望完成一个高质量方案。开始时有两周时间和充足算力，后来客户将截止提前；用户本人也没有余力逐项审阅大量新方案。

![时间取舍场景设计稿：还有两周时比较多个方向，只剩两小时时检查选定方案并准备交付，避免继续消耗稀缺的审核时间。](../插图/04-时间与取舍.png)

*场景图 · 资源仍有余量，也可能需要停止扩展。助理要识别此刻真正稀缺的是哪一种条件。*

**连续过程**。

1. 助理理解目标与取舍，最初投入适度调查和多个方向的探索，用空闲算力完成可并行的准备。
2. 客户提前截止后，助理核实变化，识别剩余时间、已有成果、等待对象和必须完成的环节。
3. 即使算力仍然充足，它也意识到用户的审核时间和协作方档期变得稀缺。
4. 助理收敛方向，停止收益较低的扩展，把资源投入已有方案的检查、补缺和可交付准备。
5. 它向用户说明显著取舍：“现有方案可以按时交付，新增方向需要另一个窗口。”已经明确的目标内动作直接推进。
6. 用户决定保留哪部分探索，助理调整剩余工作，并妥善停止不再需要的委派与关注。
7. 交付后记录此次变化及结果，为之后理解类似情境提供依据。

**异常与控制**。不能为节省费用而悄悄降低已承诺质量，也不能因为资源还有余额就无意义地继续生成。已产生的费用和已发生动作如实保留。

**完成标准**。时间、注意力、材料与算力共同影响行动，用户能感受到助理理解当下的轻重。关联模块：M02、M03、M06、M11、M16。

### S11 固定简报之外，它知道何时值得深入调查

**起因与目标**。用户希望了解某些行业动态，每天看一份简报，同时让助理留意与自己长期方向有关的变化。

![用户的现实约定、助理的未来工作、来源简报与基于目标的主动调查有不同起因；新信息可以引出调查，但保存约定本身不等于已建立提醒或执行。](../插图/12-时间安排与持续关注.png)

*图解 · 时间相关能力服务于现实目标。固定安排、变化后的继续工作与自主发现相互衔接，同时保留各自的真实状态。*

**连续过程**。

1. 用户说明关注目的、来源与希望被打扰的方式，助理从已可用资源中组织相关关注。
2. 按约定时间形成简报，每项信息能回到实际来源和取得时间；无新增与来源失败分别说明。
3. 某次变化与用户正在考虑的方向紧密相关，助理判断值得进一步核实，而不只把它列为一条新闻。
4. 在已有自主工作范围内，助理调查相关资料、比较用户现有条件，形成可以采取的下一步和必要准备。
5. 用户在合适的入口收到带着进展的消息，可以阅读、纠正、继续或结束这项工作。
6. 用户要求“最近少打扰我”，助理调整通知方式；持续工作是否暂停由用户表达的实际意图决定。

**异常与控制**。没有新内容时不编造简报；资料不足的判断标明限制。一次通知投递失败不让结果消失，重复的同一变化不反复制造新的待办。

**完成标准**。定期信息供给、变化后的继续工作和自主发现各自成立，并共同服务用户目标。关联模块：M02、M03、M04、M10、M13。

## 三 在不同设备与资源条件下协同

### S12 从手机交代工作，让三台云服务器各展所长

**起因与目标**。用户在手机上与助理聊天，名下另有三台云服务器运行着同样的助理能力。甲的计算能力较强，乙保存着项目所需文档，丙当前较空闲。用户希望获得一份基于这些资料的分析结果。

![手机与三台远程节点的场景设计稿：甲适合计算，乙保存独有资料，丙目前空闲；助理根据需要选择执行地点，结果回到用户当前入口。](../插图/03-多节点协作.png)

*场景图 · 手机是交流入口，实际工作可以发生在更合适的远程节点。图中是两类选择理由，不表示资料会自动复制到每台机器。*

**连续过程**。

1. 用户通过产品引导将手机与三台服务器接入自己的账号，不需要自行建立注册中心或配置节点间连接。
2. 助理了解当前可用节点的实际状态、可提供能力和获准访问的材料范围，保留状态的取得时间。
3. 用户在手机提出目标。助理发现需要乙上的文档，选择在那里完成获准的读取与初步整理。
4. 若后续计算适合甲，且必要材料或中间结果允许传递，助理可以交给甲执行；也可能因为丙的可用程度和成本更合适而选择丙。
5. 用户能看到工作实际在哪里进行，并可以追问选择理由。结果尚未到达时，助理不把分派成功说成分析完成。
6. 用户锁屏离开，远程节点上能够继续的工作仍继续。需要本人判断时，问题与足够背景回到手机；否则结果完成后再通知。
7. 用户在手机查看成果，也可回到电脑继续修改，沿用同一件事与原始材料关系。

**异常与控制**。节点登记在账号下不等于全部资料已授权。甲算力强但拿不到必需材料时，不能仅因速度就绕过访问限制；节点状态不明时不得假装在线。

**完成标准**。跨端聊天之外，确实发生基于算力或资料所在位置的远程分派与执行，成果回到用户当前入口。关联模块：M02、M04、M05、M14、M16、M17。

### S13 资料不能搬走，就让工作到资料所在的地方

**起因与目标**。用户需要分析一份只能留在指定机器上的生产文档。另一台服务器算力更强，但用户明确要求原始文档不能离开指定机器。

**连续过程**。

1. 用户指定资料范围和限制，助理记录这次工作可以读取什么、在哪里处理、什么结果可以带回。
2. 助理检查指定节点是否具备完成任务的能力；如果可行，就把相应工作放在那里进行。
3. 如果还需要其他能力，先判断能否只传递获准的中间结果，而非默认复制全部文档。
4. 原始材料的限制持续适用，不因换模型、换节点或委派其他助理失效。
5. 助理带回获准返回的摘要、结论或成果，说明实际处理的材料范围和未覆盖内容。
6. 用户可以追问用了哪台机器、哪些资料以及返回内容的范围，并结束后续使用。

**异常与控制**。若现有条件无法完成，说明具体缺口并让用户决定下一步；不能假称本地处理。摘要也可能包含敏感内容，不能天然视为可以自由外传。

**完成标准**。资料所在位置和使用边界成为真实行动条件，用户无需自己搬运文件以配合助理。关联模块：M04、M05、M08、M17。

### S14 一台机器离线后，事情仍然有交代

**起因与目标**。助理正在多个节点上完成工作，其中一台保存独有材料的机器突然离线，用户希望知道哪些部分受影响、能否继续。

**连续过程**。

1. 产品标明节点的最后已知状态，指出哪些工作依赖它，而不把所有任务统一显示为失败。
2. 助理保留其他节点已经完成的成果，继续处理真正独立且有价值的部分。
3. 对受影响部分，助理判断是否存在拥有同样获准材料与能力的替代节点；没有时明确等待条件。
4. 如果替代需要改变资料范围或成本约束，助理先取得必要决定；已有规则允许的替代可以直接进行。
5. 原节点恢复后，先核对先前工作的实际结局，再继续。不能因为没有及时收到回执就重复发送外部消息或再做一遍修改。
6. 用户收回该节点时，产品停止新分派，并说明尚在进行的动作和可保留成果。

**异常与控制**。“手机断开”“执行节点离线”“远程任务已停止”是不同事实；不能相互替代。结果无法确认时，清楚标明并提供后续核对路径。

**完成标准**。用户始终理解事情处于何种状态，故障不会把协作变成无声停滞或重复行动。关联模块：M05、M06、M17、M18。

## 四 把日常输入变成可持续使用的成果

### S15 工作途中，把东西放到助理桌上

**起因与目标**。用户正在聊天软件、浏览器或文档工具里工作，希望顺手交付图片、PDF 或任务文字，不想为了每次交付切换到完整聊天窗口。

![同一张桌面场景中，用户可把材料直接交给助理，也可先暂放并补充用途；新复制的内容只是半透明候选，点击或拖动接受后才交付完整原件。](../插图/10-桌面交付.png)

*图解 · 直接交付、暂放补充说明与剪贴板候选有不同的动作含义；预览不会自行发送，文件类型也不替用户决定用途。*

**连续过程**。

1. 用户启用桌面助理，把猫咪放在右下方竖屏并锁定。重新打开后位置保留，换屏幕布局时仍然可见。
2. 用户拖入 PDF，靠近猫咪的位置提示可直接交付，较远的位置提示可以先放下并补充说明。
3. 用户暂放文件，写“翻译成中文并保留表格”后交付。助理收到原件、用途和实际拖放动作；暂放时不提前发送。
4. 另一回，用户交入已经写清任务的 `task.md`，直接开始。产品不强制复述，也不把文字默认解释成“记下来”。
5. 用户复制一张截图，桌边出现半透明虚线预览并显示真实缩略图。点击就交付；按住拖向说明区域，就先补充用途。
6. 预览约 30 秒无操作后消失；用户正在悬停、聚焦或拖动时，不突然把它收走。预览出现本身不触发上传或任务。
7. 完整原文或原件进入助理，缩略内容只用于预览。收到结果或追问时，用户可以打开同一段完整会话。
8. 助理真正完成后桌宠回到相应状态，交付的图片或文件可以实际保存。

**异常与控制**。未知来源不猜成某个应用；文件类型不支持时说明限制。有未发送草稿时不绕过说明直接发送。取消暂放、移除文件或关闭便签后，迟到的读取不能重新打开并偷偷交付。

**完成标准**。空间动作表达交付方式，原件、用途与行为语境完整保留，轻量入口不干扰用户工作。关联模块：M07、M08、M14、M17。

### S16 资料可以先收好，之后再与助理一起使用

**起因与目标**。用户陆续收到资料、截图和文件，有些暂时没有任务。他希望原件可靠保存，等需要时从不同事情和视角使用。

![同一份原始材料可以产生摘要、译文和后续版本，也可以被事情、联系人与日程引用；原件、加工结果及当前用途分别可追溯。](../插图/11-原件版本与语境.png)

*图解 · 资料可以先保存、之后再使用；摘要不覆盖原件，多个阅读视角仍指向同一份事实。*

**连续过程**。

1. 用户直接保存一段无标题原文或导入一批文件，不需要先开启对话或配置模型。
2. 产品逐项显示保存和可读取情况，图片有真实预览；不能提取的文件仍保留原件及清楚的限制。
3. 用户修改一份资料，能查看历史和改动来源；助理之后整理的摘要或译文保留与原件的关系。
4. 用户把资料关联到一次活动、一个联系人和一项日程，在不同视角看到的是同一份内容。
5. 用户从资料中唤起助理，看到这次实际附带的范围，询问“比较这两版的差异”。
6. 切换到另一份资料又返回时，原来的未发送文字和附件仍然属于原来的语境。
7. 资料被撤回读取或远程来源不可达后，旧引用仍说明取得时间与当前限制；助理不能宣称已经重新读到最新原文。

**异常与控制**。批量导入局部失败不吞掉成功项；同时编辑发生冲突时保留用户草稿。助理暂时不可用时，可用的资料管理仍能使用。

**完成标准**。原件、版本和关系可靠存在，资料收纳、助理读取与形成长期记忆是可区分的结果。关联模块：M01、M07、M08、M13、M18。

### S17 一封邮件带来的约定，自然进入日程

**起因与目标**。朋友发邮件约用户下午见面，用户希望助理查看安排、回复并建立相关日程，不想在多个工具之间重复录入。

**连续过程**。

1. 用户把邮件或准确的联系人引用交给助理，询问“看看我今天下午是否有空”。
2. 日历已经授权，助理直接查询；不再追问一次是否允许本次会话连接。
3. 邮件没有说明具体时刻，助理核实可得信息后，仅询问必要的开始时间或具体选择。
4. 用户明确所需回复及安排，助理在授权范围内执行，保留邮件往来、联系人、地点与时间之间的关系。
5. 用户要求提前提醒自己，再建立相应提醒；只建立日历约定时，产品不声称提醒已经生效。
6. 对方改期，助理通过相关协同资源收到变化，检查冲突并按已有授权处理，重要取舍再与用户协商。
7. 约定结束后，必要记录保留，该次往来的持续关注可以结束。

**异常与控制**。同名联系人不能选错；用户已明确确认的同一条回复不反复询问。发送和外部确认不同，时间缺失不能自行猜测成一个确定预约。

**完成标准**。外部往来能进入用户的现实安排，授权与信息不会在每一步被重复索取。关联模块：M04、M06、M09、M10、M17。

### S18 把结果做成真正能用的页面

**起因与目标**。用户准备一段短途行程，希望在手机上查看、打卡和随时调整；也可能希望给朋友一个能共同参与的小工具。

![用户表达用途后，助理交付可在手机打开和操作的行程页面；之后可继续修改、保留实际记录，并按清楚范围分享，成果重新参与后续协作。](../插图/13-交互式成果.png)

*图解 · 真实成果应能被打开、使用和继续调整；可用页面、源代码和临时预览不能混为一谈。*

**连续过程**。

1. 用户说明目的、时间和使用情境，交入已有材料。助理查明还缺哪些必要条件。
2. 用户说“做成手机上可用的打卡页面”，助理据此建立实际可打开的成果，而非只在聊天里贴代码。
3. 用户在手机打开页面，看到内容来源、当前版本和支持的操作，记录已完成的行程。
4. 用户继续说“把这一站移到明天”，助理修改对应成果，保留已有记录，不误建一个互不相关的新页面。
5. 页面成为这件事的协同资源，可以在原会话引用、查看和继续调整。
6. 用户选择分享时，清楚知道给谁、能看什么或操作什么；对方的参与只在支持的范围内成立。
7. 使用结束后，用户能够按产品支持的方式留存或导出成果，并了解停止分享或到期的影响。

**异常与控制**。页面中的外部数据不可用时标明；页面有外观不代表背后的动作已完成。临时预览与长期可用成果区别清楚，不暗示无限期运行。

**完成标准**。交付可以继续被使用和协同，而不止于一条回答；版本、数据、分享与结束均有清楚边界。关联模块：M04、M08、M11、M12、M17。

## 五 自主工作中的掌握、成本与可靠性

### S19 它先完成可恢复的工作，我在需要时参与

**起因与目标**。用户正在忙，助理还需要整理多份稿件与资料。用户希望工作继续，同时保留重要判断和纠正空间。

![助理直接推进已经授权且可恢复的整理工作，用户稍后集中查看和调整；确有必要信息或尚未确认的高风险后果时，带着对象、材料与后果向用户协商。](../插图/14-自主行动与用户掌握.png)

*图解 · 日常动作不反复询问，重要决定带着完整语境回到用户；关闭、超时或沉默都不构成新的同意。*

**连续过程**。

1. 助理在既有授权范围内完成读取、整理和可恢复修改，不为每一步都发送“是否继续”。
2. 确实需要事后审阅的结果以清楚的暂行状态呈现，助理继续独立的工作；普通已完成修改不被强行变成审批事项。
3. 用户没有及时查看时，待审内容进入集中入口，仍保留来源、改动和实际产物。
4. 用户集中接受部分结果、修改一项、撤回另一项；产品解释受影响的后续成果并反馈实际结局。
5. 一项工作要作出尚未确认的不可恢复承诺，助理单独提出具体问题，其他无依赖部分继续推进。
6. 用户从手机作答后，桌面入口反映同一个决定；关闭卡片或未回应不被解释成同意。

**异常与控制**。已发出的消息或不可恢复的外部动作，不能伪装成随时可撤回的草稿。撤回未成功或仍在处理时如实说明。

**完成标准**。用户不用持续盯着助理，也不会失去对关键后果的掌握；工作推进与用户参与相互协调。关联模块：M03、M07、M13、M17。

### S20 收回一项权限，助理清楚停止相应使用

**起因与目标**。用户不再希望助理读取某个邮箱、使用某个目录，或继续关注某位供应商的往来。

**连续过程**。

1. 用户在相关资源或权限入口查看当前授予的范围、用途和正在依赖它的事情。
2. 如果只想结束一次合作，可以结束那段协同资源；如果希望停止整个邮箱使用，则撤回账户范围的授权。
3. 产品明确两种选择的不同后果，用户完成实际需要的操作。
4. 助理不再开始未获准的新读取或动作，受影响的工作说明缺少什么；其他资源继续可用。
5. 正在进行的外部动作是否可以停止、已经读取或发出什么，按实际情况交代。
6. 用户之后重新授权时，需要重新确定当前用途；不能无声恢复所有过去的监听与待办。

**异常与控制**。撤权失败不能显示成功；旧引用不应变成伪造的可读结果。已经给外部参与者或模型的内容不能声称因此被追回。

**完成标准**。用户可以理解并控制协同的范围和生命周期，停止确实有作用，也不误伤其他事情。关联模块：M04、M05、M09、M17。

### S21 自带 API 与平台服务都能用，投入有数

**起因与目标**。用户最初使用平台服务，后来希望用自己的模型 API；执行工作仍可能使用平台算力或自己的远程节点。他希望费用与切换规则清楚。

![注册登录进入同一个助理后，用户可以使用平台服务，也可连接自己的兼容 API；模型用量、执行算力、预算和切换规则需要各自说明。](../插图/15-登录与双来源服务.png)

*图解 · 平台服务与自带 API 都应有清楚的能力和费用说明；自带模型 API 不表示整件事零成本，也不默认允许静默切换收费来源。*

**连续过程**。

1. 用户查看当前服务来源、可用能力、用量和预算，理解哪些费用由平台收取、哪些由自己的供应商收取。
2. 用户添加自己的 API，产品验证实际可用能力并提示必要修正；不要求把密钥发给聊天中的助理。
3. 用户选择相关任务使用自带模型服务，计算任务按允许的方式使用平台或已接入节点。
4. 助理考虑质量、耗时与资源余量，在预算和既有选择中安排工作；不需要每次调用都打断用户确认。
5. 接近预算限制时，助理收敛低价值探索并说明影响。需要扩大预算或切换未授权的付费来源时，由用户决定。
6. 用户按事情查看实际投入；外部供应商不能提供准确费用时，产品明确标为估计或未知。
7. 用户撤回某个 API 或停止持续工作后，不再产生未经允许的新消耗。

**异常与控制**。自带 API 失效不能静默改用平台余额；平台余额不足不能悄悄使用另一个密钥。“模型费用自付”不意味着存储或执行算力必然免费。

**完成标准**。两种服务来源均可用，用户知道付出了什么，助理的主动性始终考虑资源约束。关联模块：M03、M05、M15、M16。

### S22 断网、卡住与重启之后，工作可以核对和继续

**起因与目标**。用户交付材料后网络中断，不确定是否送达；另一次工作耗时很长，界面一直没有进展。他希望保留内容并知道发生了什么。

![工作中出现断线或节点离线时，保留原委托、草稿与已完成部分；恢复后先核对实际发生的动作和结果，再继续未完成部分，避免重复外部行为。](../插图/16-中断恢复与有序收尾.png)

*图解 · 失去连接不等于任务失败，也不等于工作从未发生。恢复应围绕原来的事情核对事实，并把真实结局带回所有入口。*

**连续过程**。

1. 产品区分尚未送达、已接受、正在执行、等待外部和结果不明，不用一个“连接中”覆盖所有情况。
2. 发送前失败保留草稿与附件；已接受后的断线保留原委托，等待后续核对。
3. 重新联网或登录后，产品恢复能确认的真实状态及结果，不把用户带回一个没有历史的新任务。
4. 助理说明已完成部分、受影响部分与可继续方式；用户不需要重新上传所有已经保留的材料。
5. 对可能产生外部效果的操作，先检查是否已经发生，再决定重试；不自动制造第二次发送或修改。
6. 长时间没有进展时给出可理解状态和适用的控制入口；不支持的取消不能假称已完成。
7. 故障解决后，主客户端、手机与桌面助理收敛到同一结局，结果文件仍可取得。

**异常与控制**。单个模型或来源失败不阻断仍可用的资料服务；过去错过的工作不得补造已执行记录。帮助与诊断入口不暴露密钥或无关私人内容。

**完成标准**。用户能够恢复工作和信任，失败不会吞掉输入，也不会无声重复产生后果。关联模块：M07、M08、M14、M18。

### S23 换设备、停止使用与带走自己的内容

**起因与目标**。用户换了电脑，或者准备暂停服务。他希望保留自己的材料、理解正在运行的工作，并能有序退出。

**连续过程**。

1. 用户在新设备登录后找到自己的事情与资料，可以检查旧设备的在线和授权状态。
2. 如果旧设备丢失或不再使用，用户从可信入口收回相应访问与新工作资格。
3. 用户暂停主动活动，查看尚在执行、等待外部或需要自己决定的事情，再逐项收尾。
4. 用户按产品支持范围导出资料与成果，知道哪些内容、历史或交互数据被包含，哪些没有。
5. 用户可以退出一个客户端而保留远程服务，也可以明确停止相关持续工作；两种后果分别说明。
6. 如果选择取消付费或关闭账户，产品说明后续用量、保存期限、分享成果和仍未完成的动作如何处理。
7. 删除等不可恢复后果在具体对象和范围明确后确认，实际完成情况可查。

**异常与控制**。重装客户端不等于删除账户资料；停止续费不应让尚未披露的持续费用继续产生。账号恢复、注销和数据保留细节属于正式服务前需要确定的产品承诺。

**完成标准**。用户能开始使用，也能更换入口、收回设备和有序离开，重要内容与未完成责任有清楚去向。账号退出与商业服务细节为建议补充。关联模块：M05、M14、M15、M16、M17、M18。
