# 实时语音通话：这条链路保证什么、代价在哪

- 调查对象与日期：OpenAI `gpt-live-1`（2026-09-10 API 发布）为主，兼及 Google Gemini 3.8 Live、
  托管平台（Vapi/Retell/Bland）、开源框架（Pipecat、LiveKit Agents）、学术评测与美欧中法规；取证 2026-09-19
- 消费者：待出现。2026-09-19 由设计者要求调查，面向未来可能的语音交互与电话通道设计
- 最近核对：2026-09-19 / `gpt-live-1`、Gemini 3.8 Live、FCC 24-17
- 当前结论：这块的**技术可行性已不是瓶颈，证据质量才是**——厂商自测数字普遍缺独立复现，
  学术基准彼此不可比且都没测到生产条件，行业流传的失败率数字有的引用链是断的。
  能确定的硬事实集中在能力边界、计费结构与法规义务三处。

## 问题与区分条件

要区分四件常被合并的事：**语音层能做什么**、**整条链路需要什么**、**厂商数字的证据强度**、
**法规现在要求什么**。会改变边界的观察：任何一次第三方在公开语料上的复现；
中文场景的实测数字；FCC 那份 NPRM 变成最终规则。

## 证据入口

分主题的证据见 [证据索引](evidence.md) 与 `notes/` 六份文件。
本轮完整论证与取证路径见 [2026-09-19 首轮调研](reports/2026-09-19-landscape-and-claim-audit.md)。

## 当前结论

### C1 「实时打电话」不是一个模型，是一条链路，买模型只解决中间一段

媒体传输（WebRTC/SIP/PSTN）→ 轮次控制 → 语音层 → 推理层 → 工具与业务系统。
`gpt-live-1` 把自己明确限定在"耳朵和嘴"：语音层"listens, speaks, and decides when to ask the backend
for help"，推理、工具、权限、确认、持久任务状态全部归应用与后端。$0.05/min 只买这一段。

- 适用范围：`gpt-live-1` 的官方架构描述；Gemini Live 与开源框架的分层不同，不可直接套用。
- 代价与不适用：**省下的是语音处理，加上的是编排**。应用侧要自己承担后端生命周期、
  权限与确认、任务状态持久化；`gpt-live-1` 还默认**不转写用户语音**，要自己监听事件拼接。
- 来源：[gpt-live.md](notes/gpt-live.md)、[field-reports.md](notes/field-reports.md)
- 最近核对：2026-09-19 / `gpt-live-1`

### C2 级联与端到端未收敛，两条路线在轮次控制上甚至方向相反

2026 年生产仍以级联 STT→LLM→TTS 为主；端到端在"延迟主导、工具面浅"的短对话增长快。
没有一方绝对更快——工程良好的级联可以快过部分端到端模型。
**轮次控制上出现两条相反路线**：厂商博客侧说趋势是从能量阈值 VAD 迁往专门的轮次模型；
OpenAI 工程稿走的是反方向——**移除独立的轮次检测器**，让语音模型自身控制对话流。

- 适用范围：2026 年 9 月的状态；两条路线都没有跨方案的对照实测。
- 代价与不适用：级联换来可观测、可换模型、成本可控，代价是延迟累加与转录丢失副语言信息；
  端到端换来副语言与栈简单，代价是可观测性差、工具面浅、模型不可替换。
  OpenAI 那条路线把代价转移给应用——要自己从重叠且歧义的音频流里分离出离散消息。
- 来源：[architecture.md](notes/architecture.md)、[gpt-live.md](notes/gpt-live.md)
- 最近核对：2026-09-19

### C3 决定体验的是轮次控制，而它在电话场景有已证实的静默失效

barge-in 要求自用户开口到冲掉已缓冲音频低于 150ms；轮次间隙工程口径 200–450ms
（该区间的学术出处只能追到 Stivers et al. 2009 的"人类自然间隙众数 0ms、中位 100ms、均值 208ms"，
**450ms 上限在论文里无直接支撑**）。四种失败模式：过早切断、漏切、双讲、打断处理失败。

- 适用范围：以下两条是一手工程证据，非厂商自述。
- 代价与不适用：**8kHz 是电话线路的标准采样率**，而 Pipecat 的轮次检测组件曾因五处硬编码 16kHz 假设
  在 8kHz 下**静默给出错误预测**——错判不报错。**backchannel 会被当成打断**：
  印地语/泰卢固语的"haa/hmm"与中文的"嗯/对/不是"有两条独立来源报告同一失效，
  说明这是 VAD-only 方案的通用弱点，不是某语言特例。这两类失败的**真实发生频率没有任何独立数据**。
- 来源：[field-reports.md](notes/field-reports.md)、[architecture.md](notes/architecture.md)、[evaluation.md](notes/evaluation.md)
- 最近核对：2026-09-19

### C4 报价与真实成本差 2–5 倍，且按分钟计费与业务目标反向

广告价通常只是平台费或语音层；把 STT/LLM/TTS/电话/平台五层叠齐，公开口径落在 $0.12–0.25/min。
隐藏项：静音计费、并发限制、HIPAA 附加（+15–30%）；打断会丢弃已付费但未播放的 TTS 音频，
轮次控制差的 agent 多烧 10–30% 字符。

- 适用范围：以上为厂商与竞争者互评口径，**无独立实测**。
- 代价与不适用：**按通话时长计费与"尽快解决"的业务目标反向**——十分钟没解决的通话比九十秒解决的更贵。
  自托管"可压到 $0.05/min 以下"至今**没有独立依据**：唯一带可核对方法论的拆解来自一家卖 GPU 云的厂商
  （$0.02932/min，核心是"并发是分母"，10 路并发时成本高 18 倍），且**不含电话线路费与运维人力**。
- 来源：[platforms.md](notes/platforms.md)、[field-reports.md](notes/field-reports.md)
- 最近核对：2026-09-19

### C5 美国联邦目前没有通话内强制 AI 披露义务，但另外四项是现行的

**FCC 24-17（2024-02-08）确认 AI 生成语音属 TCPA 的 "artificial or prerecorded voice"**，且不为
"等同真人客服"的技术留豁免口子。现行义务：通话**开始**须报出主叫实体身份（联系电话可在通话中或结束时给，
不要求同时在开始报出）；商业外呼需 PEWC；罚则每次 $500、故意最高 $1500、按次累加无上限，
**另有 TRACED Act 下 FCC 行政罚没单次最高约 $10,000 这条独立路径**。
加州 AB 2905 要求告知使用 AI 语音，但**没有规定固定文案**。
EU AI Act Article 50(1) 于 **2026-08-02 生效**（存量系统过渡到 2026-12-02），含"情境已明显可知是 AI 则免告知"的例外。

- 适用范围：**本条不是法律意见**，只核实公开说法各自的原文依据。
- 代价与不适用：三处广为流传但**查下来不成立**的说法——① 释令"明确涵盖实时对话式 AI/LLM agent"，
  原文从未用这些术语，是推断；② "PEWC 同意条款须明确提及 AI"实为 **2024-08 NPRM 的提议，
  截至 CRS 报告 R48941（2026-05-12）未成为最终规则**，且被列为"长期项目"；
  ③ AB 2905 的"具体披露措辞"与"$500 专设罚款"均无对应条文。
  另：跨州录音同意的一方/双方划分真实存在，但**没有 AI 通话专属条款**；
  中国《人工智能生成合成内容标识办法》（2025-09-01 施行）全文**未出现"电话/呼叫/外呼"**，
  "覆盖 AI 外呼"未获证实。
- 来源：[telephony-compliance.md](notes/telephony-compliance.md)
- 最近核对：2026-09-19 / FCC 24-17、FCC 24-84（NPRM 状态）
- 状态标记：待核实——NPRM 那条的 RIN 编号存在矛盾；录音同意的州名单未逐州核验

### C6 厂商自测数字缺独立复现，唯一可比的第三方数字差一个数量级

OpenAI 称 `gpt-live-1` 在 Full Duplex Bench 上比 `gpt-realtime-2.1` 高约 **30 个百分点**。
该基准的官方 GitHub 不登记这两个模型；四篇相关论文的投稿日期**全部早于 `gpt-live-1` 的发布日**，
逻辑上不可能测过它。唯一可比的第三方数字（Artificial Analysis 同名分项，只覆盖 v1/v1.5 子集）：
**97.3% vs 96.1%，差约 1.2 个百分点**——方向一致，幅度差一个数量级。

- 适用范围：不构成对 OpenAI 说法的直接证伪（测试条件、精确版本、子集范围都可能不同，
  且该榜单方法论未公开到可逐条核对）。
- 代价与不适用：**「75.7% 盲测偏好」这个被广泛引用的数字，两次抓官方原文都没找到**，
  来源未闭合，闭合前不应引用。凡引用厂商性能数字时，应同时注明其为自测且无复现。
- 来源：[evaluation.md](notes/evaluation.md)、[gpt-live.md](notes/gpt-live.md)
- 最近核对：2026-09-19

### C7 四套学术基准互不可比，且都没测到生产条件

FDB v1/v3、IHBench、DuplexWorld、τ-Voice 的构造对象、语音真实性、指标算法两两不同：
同名"turn-taking"在 FDB 是二值均值 TOR、在 DuplexWorld 是 on-time curve、在 τ-Voice 是 Yield Rate，
**数字不能跨基准换算**。只有 FDB v1 过了同行评审（ASRU 2025）。

- 适用范围：截至 2026-09 的公开基准。
- 代价与不适用：**没有一篇报告延迟长尾（p99），全部只报均值**；口音绝大多数靠 TTS persona 模拟
  （τ-Voice 自承 "suggestive rather than definitive"），FDB v3 是唯一用真实非母语说话人的但只有 12 人；
  DuplexWorld 声明完全不用真实人声。IHBench 与 τ-Voice 在 limitations 里明写需要真实部署验证——
  **"真实电话线路上的完整生产条件"是学术侧集体承认的空白**。另：FDB v1 列 17 个被评测模型，
  实际跑出结果的只有 4 个。
- 来源：[evaluation.md](notes/evaluation.md)
- 最近核对：2026-09-19

### C8 `gpt-live-1` 的能力边界由设计固定，且迁移有实测到的破坏性差异

仅 audio/text 进出，**不支持 image/video**；知识截止 2025-07-31；只走 `v1/live/sessions`，
Chat Completions、Responses、**Realtime** 等端点全不支持；**无结构化输出、无微调**；
并发按 tier 25–500。**它不是 Realtime 的继任者**——官方 deprecations 页全页没有它，
列的是 `gpt-realtime-2.1`（2027-01-20）。

- 适用范围：官方文档与发布稿；**上下文窗口、最大会话时长、精确语言清单在七处官方材料中体系性未载**
  （模型页、入门指南、cookbook、定价页、三篇博客），这是"读遍了没找到"，不是没查。
- 代价与不适用：**打断不会自动取消后端工作**，两名开发者分别实测到委托后 **30 秒**与 **2 分钟**的轮次延迟；
  **默认不转写用户语音**；从 Realtime 迁移会遇到 `response.done` 输出恒空、每轮触发两次
  `response.completed`、`session.update`/`response.cancel`/`input_audio_buffer.clear` 不可用；
  生产调参者报告**委托触发准确性与语音自然度此消彼长**。不委托后端时它自己"回答浅、偶尔怪"。
- 来源：[gpt-live.md](notes/gpt-live.md)、[field-reports.md](notes/field-reports.md)
- 最近核对：2026-09-19 / `gpt-live-1`

### C9 自托管可行，但"能自托管"不等于"自托管功能对等"

Pipecat 与 LiveKit Agents 都可自托管，LiveKit 的媒体服务器、Agents SDK、SIP bridge 均 Apache 2.0。

- 适用范围：以下代价为一手 GitHub 证据。
- 代价与不适用：**LiveKit 自托管会丢失云端专有的自适应打断模型**，只能退回纯 VAD
  （该 issue 无维护者回应、无 workaround）；其电话延迟投诉被**关闭为 "not planned"**。
  Pipecat 在真实电话部署首轮延迟实测 4–5 秒、多参与者响应错位未解决、
  **官方明确不提供生产级自托管部署蓝图**。两者没有任何受控对照实测。
  另：issue 被关闭不等于问题已解决，只能证明被真实报告过。
- 来源：[field-reports.md](notes/field-reports.md)、[platforms.md](notes/platforms.md)
- 最近核对：2026-09-19 / Pipecat v0.0.65–0.0.97

### C10 中文与非英语是独立风险，且本轮查遍仍无独立实测

OpenAI 官方体系内查不到 `gpt-live-1` 的语言清单，只有一句"某些语言可能有非母语口音或流利度缺口"。
Gemini 的语言数**官方三处自相矛盾**（总览 70 / 技术规格 99 / Firebase 89+），无解释。

- 适用范围：中文生态（MiniMax、阶跃星辰、声网、开源 TTS）确实活跃，但**全部是厂商自述**。
- 代价与不适用：方言实测、中英混说错误率、国内实时语音 API 的第三方测试**一条都没找到**——
  这是"查过多个方向仍未找到"，不是没查。唯一较可信的一手中文材料是一篇通用 ASR 工程博客
  （非完整 agent），给出定性踩坑：专有名词误识别、中英混说被搅乱、远场混响、多人重叠。
  **中文场景的可用性目前只能靠自己实测确定，没有可依的公开数据。**
- 来源：[platforms.md](notes/platforms.md)、[field-reports.md](notes/field-reports.md)
- 最近核对：2026-09-19

### C11 行业流传的两个失败率数字引用链断裂，不可使用

「无 RAG grounding 时每 10 万通约 340 起客户可见事件」追溯到一家销售 Voice AI 的公司 CEO 的博客，
该文把数字归给 "a 2026 digital compilation"——**不具名、无链接、查无实据**。
「60% 的部署在 90 天内失败」溯源到另一家竞品厂商，文末自承来源为泛指的"行业分析"，不点名。

- 适用范围：这两个数字本身。
- 代价与不适用：**本轮没有找到任何独立研究机构、学术论文或第三方审计**对"语音 agent 幻觉导致客户
  可见事件"这一指标做过测量——不是找到了更好的数字，是这个指标目前**根本没有可核实的公开数据**。
  引用任何失败率数字前应先溯源到底。
- 来源：[field-reports.md](notes/field-reports.md)
- 最近核对：2026-09-19
