# 实时语音通话首轮调研：版图、主张核查与证据溯源（2026-09-19）

**取代状态：** 当前有效，未被取代

- 执行者与日期：Claude Code 会话（主）+ 四个并行只读调研 subagent，应设计者要求，2026-09-19 单日完成
- 调查范围：以"实时打电话"为题，覆盖语音模型能力、链路架构、产品版图、电话接入、法规义务、
  评测基准与生产失败模式。**不含实际 API 调用、不含真实通话测试、不含我方自行实测**。
- 输入与方法：两阶段——先由主会话做一轮宽扫（WebSearch/WebFetch 聚合），标出缺口；
  再按缺口派四路 subagent 定向深挖一手材料，回收后由主会话交叉核对、修订、收敛。
- 处置的既有结论：首次调查

## 完整报告正文

### 调查从"对象是否存在"开始

"GPT-Live"这个名字由设计者口述给出，而本会话的知识截止早于其发布日。因此第一步不是描述它，
而是**先核实存在性**：两次检索命中官方站点、多家媒体与 HN 原帖，确认 TypeSafe 之外确有
OpenAI 于 2026-09-10 在 API 发布的 `gpt-live-1`。这一步与本工作区另一个 topic 的做法一致——
对象名由人口述、模型无先验知识时，"先证存在"与"直接描述"的分岔就在这里。

随后发现一个必须先辨明的名称混淆：**ChatGPT 消费端的「GPT-Live」功能**与 **API 的 `gpt-live-1` 模型**
被多篇文章混用同一个名字，以致出现"没有公开 API、电话线路 coming soon"这类说法。
本包一律以官方文档页为准区分二者。

### 第一阶段（宽扫）：得到版图，也踩了三个坑

宽扫得到了基本版图——语音层与推理层分离的架构、级联与端到端两条路线、延迟预算、
托管平台的价格区间、SIP 接入形态、法规轮廓、失败模式分类。但这一轮的材料几乎全部来自
**厂商技术博客与竞争者互评**，且大量是搜索摘要而非原文。后来被证明踩了三个坑：

1. **引用了一个引用链断裂的数字。** "无 RAG grounding 时每 10 万通约 340 起客户可见事件"——
   看起来精确、带小数点、像是有出处，实际溯源到一家卖 Voice AI 的公司 CEO 的博客，
   而该文把数字归给 "a 2026 digital compilation"，一个不具名、无链接、查无实据的"汇编"。
   **精确的数字比模糊的说法更容易骗过快速检索**，因为它看起来已经被人验证过了。
2. **把一项尚未成为最终规则的提议当成了现行义务。** "PEWC 同意条款须明确提及 AI"实为
   2024-08 NPRM（FCC 24-84）的提议内容；截至 CRS 报告 R48941（2026-05-12）仍未成最终规则，
   且被列为"长期项目、12 个月内不预期推进"。**厂商的合规营销文章系统性地把提议写成要求**，
   因为那样更能推动购买。
3. **引用了一个一手查无实据的性能数字。** "75.7% 盲测偏好"被多家二手报道归为 OpenAI 自述，
   但两次抓取官方原文（含一次要求逐字输出的重试）均只见 "strongly preferred" 的定性表述。

三个坑的共同点：**都不是因为查得少，是因为查的全是二手**。这一轮的每份 notes 末尾都留了「局限」，
那些局限后来成了第二阶段的任务书。

### 第二阶段（定向深挖）：四路并行

按来源域切成四路，互不重叠，每路都带同一套纪律（来源立场标注、一手二手分开、两面都要有证据、
不准替我方挑方案、只写任务区）：

**一手规格路**——用第三方反向代理绕过 `openai.com` 的 403，取到两篇官方长文，
并发现一篇此前完全没记录的 **API 专属发布稿**。关键产出：

- 从入门指南**一手确认 `gpt-live-1` 支持 SIP**（此前只有二手转述），并发现官方 SIP 指南的地址已漂移
  （旧址 301 到一个 404 页面）。
- 从 deprecations 页**一手确认 `gpt-live-1` 不是 Realtime 的继任者**，全页没有它。
- 从工程稿拿到此前完全没有的实现事实：媒体前端**从 Python asyncio 改写为 Go**、
  "新系统的 p95 匹配前一系统的 p50"、**轮次判定的做法是移除独立检测器**而非换更好的检测器、
  启动从六个网络往返减到一个。
- 从 cookbook 评测指南拿到一句对做 harness 的人最要紧的话：
  "The evaluation harness must therefore align audio and events on a continuously advancing timeline
  instead of assuming clean, alternating turns."——**全双工下"干净的交替轮次"这个假设不成立**。
- 一条**强负面结论**：`gpt-live-1` 的上下文窗口、最大会话时长、精确语言清单，
  在模型页、入门指南、cookbook、定价页、三篇发布博客共**七处官方材料中体系性未载**。
  这是"读遍了没找到"，不是"没找对页面"。
- 一处**官方自相矛盾**：Gemini 支持语言数在总览页写 70、技术规格页写 99、Firebase 写 89+，
  三处打架且无解释。按纪律记为来源冲突，不挑一个采用。

**学术评测路**——真读四篇论文原文。关键产出：

- 四套基准**测的不是同一件事**：同名"turn-taking"在 FDB 是二值均值 TOR、在 DuplexWorld 是
  on-time curve、在 τ-Voice 是 Yield Rate，**数字不能跨基准换算**。只有 FDB v1 过了同行评审。
- **没有一篇报告延迟长尾（p99）**，全部只报均值；口音绝大多数靠 TTS persona 模拟，
  τ-Voice 自承 "suggestive rather than definitive"；DuplexWorld 声明完全不用真实人声。
  IHBench 与 τ-Voice 在 limitations 里明写需要真实部署验证——
  **"真实电话线路上的生产条件"是学术侧集体承认的空白。**
- 对 OpenAI 那句"高 30 个百分点"的核查结果最有力：该基准官方 GitHub 不登记这两个模型；
  **四篇论文的投稿日期全部早于 `gpt-live-1` 的发布日，逻辑上不可能测过它**；
  唯一可比的第三方数字是 **97.3% vs 96.1%，差 1.2 个百分点**。方向一致，幅度差一个数量级。
- 顺带挖出工程口径"200–450ms"的学术源头：Stivers et al. 2009 (PNAS)，10 语言自然对话，
  **总体众数 0ms、中位 100ms、均值 208ms**。论文从未出现"200–450ms"这个区间，
  **450ms 上限无直接支撑**，也没有中间文献做过这个映射。
- 另一处容易被忽略的落差：FDB v1 列出 17 个"被评测模型"，**实际跑出结果的只有 4 个**。

**法规路**——回到 FCC、CFR、USC、加州法条与 EU AI Act 原文。它纠正了第一阶段的实质错误：

- 成立：FCC 24-17 第 5 段确认 AI 生成语音属 TCPA，第 6 段不留"等同真人"的豁免口子；
  通话开始须报实体身份（**但联系电话可在通话中或结束时给，不要求同时在开始报出**——
  第一阶段把两者都塞进"开始"是不准确的）；罚则 $500／故意 $1500／按次累加无上限，
  **另有 TRACED Act 下行政罚没单次最高约 $10,000 这条此前完全没覆盖的更重路径**；
  EU AI Act Art. 50(1) 于 2026-08-02 生效，存量系统过渡到 2026-12-02，含"情境已明显可知则免告知"的例外。
- 推翻或降级：释令"明确涵盖实时对话式 AI"是**推断而非条文**；PEWC 那条**是提议不是规则**；
  AB 2905 **无固定披露文案**、"$500 罚款"来自既有通用罚则；跨州录音同意**没有 AI 专属条款**；
  中国标识办法全文**未出现"电话/呼叫/外呼"**，"覆盖 AI 外呼"未获证实。

**开发者实测路**——去 HN、OpenAI 官方论坛、GitHub issue 找真正动过手的人。产出最"脏"也最有用：

- 委托后端的延迟风险**在真实使用中兑现**：两名独立开发者分别报告 **30 秒**与 **2 分钟**的轮次延迟。
  此前"打断不自动取消后端工作"只是文档审计推出的架构提醒，现在有了后果。
- `gpt-live-1` **默认不转写用户语音**；从 Realtime 迁移有多处破坏性差异
  （`response.done` 恒空、每轮两次 `response.completed`、三个常用事件不可用）。
- 生产调参者的观察：**委托触发准确性与语音自然度此消彼长**——"越调越不像人"。
- 电话场景的静默杀手：Pipecat 的轮次检测组件曾因**五处硬编码 16kHz 假设在 8kHz 下静默误判**，
  而 8kHz 正是电话线路的标准采样率。
- **"可以自托管"不等于"自托管功能对等"**：LiveKit 自托管会丢失云端专有的自适应打断模型，
  只能退回纯 VAD；其电话延迟投诉被维护者**关闭为 "not planned"**。
- **跨语言互证**：印地语/泰卢固语的 backchannel 被误判为打断，与中文"嗯/对/不是"的同类报告
  来自两个独立非厂商来源——说明这是 VAD-only 方案的通用弱点，不是某语言特例。
- 把第一阶段那个数字**溯源到底**，确认引用链是断的；另一个流传的"60% 部署 90 天内失败"同样无具名来源。

### 交叉核对时的几个判断

- **新增了一个可信度档位：「一手·经代理」。** 经第三方反代取回、再经工具内置摘要模型抽取的内容，
  比搜索引擎转述可信（确实访问了该 URL、是抽取而非复述），但**不是原始字节**，
  可能漏抽或改写。引用其逐字措辞前若判断重要，应重取原文。
- **竞争者互评的处理办法**：这块几乎没有中立来源——"Vapi vs Bland"由 Retell 发布、
  "Retell vs Vapi"由 Bland 发布。采信规则定为：**各家说对手的短处可参考，说自己最好不采信**。
- **同一说法出现多次不构成多个独立来源**：一批 SEO 站的同题文章高度同源于发布稿，本包不采信。
- **两面都记**：容易被批评淹没的一点是，OpenAI 消费端发布稿**主动写了**"某些语言可能有非母语口音
  或流利度缺口"这类对自己不利的限制条款，而面向开发者的 API 稿反而没有对应段落。
  这两件事都真实，只记一件都会失真。

## 本轮结论

收敛后的十一条见 [research.md](../research.md)。本轮最值得带走的三句：

1. **"实时打电话"不是一个模型，是一条链路**；买到语音层只解决中间一段，省下的是语音处理，
   加上的是编排、后端生命周期与状态持久化。
2. **这块的瓶颈已经不是技术可行性，是证据质量**：厂商自测无复现、学术基准互不可比且没测到生产条件、
   流传的失败率数字有的引用链是断的。
3. **硬事实集中在三处**：能力边界（模态、端点、无结构化输出、七处未载的上下文/时长/语言）、
   计费结构（广告价只是地板，按分钟计费与业务目标反向）、法规义务（联邦目前**没有**通话内强制
   AI 披露，但身份告知、PEWC、州法与 EU AI Act 是现行的）。

## 本轮局限

- **未执行任何实际 API 调用或真实通话**：所有延迟、限额、计费行为均属未验证。
- **两篇 OpenAI 官方长文非原始字节**（经反代 + 摘要两层转换），`web.archive.org` 本环境不可达，
  无法交叉验证。
- **中文缺口未填上**：查过多个方向仍无独立实测，方言与中英混说的量化数据一条都没找到。
- **失败模式只有"存在"，没有"多频繁"**：8kHz 误判与 backchannel 误打断都只有定性的一手报告，
  没有任何频率数字，且本轮确认这个指标目前没有可核实的公开数据。
- **四路 subagent 的报告是模型输出，不是证据**：本轮对其给出的关键 URL 与结论做了抽样核对，
  但未逐条重取原文；凡未核对的条目已在各 notes 中按来源档位标注。
- **法规部分不是法律意见**，只核实了公开说法各自的原文依据；实际合规需执业律师按业务形态出具。
- **时效性**：对象发布于本轮取证前九天，社区判断尚未沉淀，二手文章高度同源。
  一个月后回看，可用的独立证据大概率比现在多。
