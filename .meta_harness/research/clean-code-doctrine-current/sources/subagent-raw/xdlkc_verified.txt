ID 2087538351175799108 | Wed Aug 12 13:55:02 +0000 2026 |@unclebobmartin | reply_to: VibeCoderMcSwag 2087352551389720717 | views 205
I just tell my agents to write failing tests first and write the production code that passes them second.  They do this tolerably well -- just like people.

Then I make sure they run coverage, CRAP, and Mutation tests to drive the test coverage to as close to 100% as possible.

I also have the agents build three kinds of tests.  Unit tests, which I don't look at much, Gherkin acceptance tests that I subject to slightly more scrutiny, and slightly more scrutinized QA procedures that test the system at the UI.

Without unit tests I have found that the agents create too many regressions.  They are recoverable, but they are frustrating.  Without the acceptance test I have found that the agents lose the separation between UI and business rules.  That's correctable, but I'd rather enforce it early.  Without the QA procedures I find that the agents deliver perfectly good software that works at the API, but not at the UI.

I learned this all by trial and error; and I could still be wrong.  But that's the course I'm currently on.

See http://github.com/unclebob/swarm-forge for a lot more detail on this.

I ran the negative test experiment.  Interesting.   repo below.

Abstract written by grok:

We wrote Hunt the Wumpus eight times from empty: four testing disciplines, with and without forcing CRAP below 4. Every run passed the same 25 acceptance cases. The programs were not the same. Discipline changed both the unit suite and the shape of the source. Three laws grew a layered immutable hunt; test-last left a small program with a few fat functions; bundling named every function and kept the domain off stdout; none produced a BASIC-style listing with no unit tests. CRAP then split functions and added tests until every score was under 4. It raised coverage (and invented a whole suite when there had been none) and made every program harder to read. It did not improve design. Mutation, run afterward against each frozen tree, wrote a second suite aimed at operators, not a different Wumpus. Acceptance never distinguished any of this.
