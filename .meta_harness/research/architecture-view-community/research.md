# 社区视图的表达、导航与布局

## 范围

问题是如何让架构师从全局进入局部，并核对图上的关系。
本轮只读官方页面，另执行 elkjs 0.12.0 的有限探针。
这些资料没有验证本仓库的领域边界、运行绑定或架构符合性。

## 当前结论

### 分层与标记能说明图在表达什么，不能替图补出架构事实

C4 区分系统、容器、组件和代码视图。标记指南要求图名、范围、图例、元素种类及有方向的关系说明。
Structurizr 的过滤视图从已有视图选择元素和关系，不为过滤另定义架构。

- 范围：官方方法和功能说明，2026-10-03 读取。
- 代价：读者需要理解每一级的含义。目录聚合没有足够依据映射为进程或部署容器。
  这是本仓库输入与该方法的差异，不是对 C4 能力的否定。
- 来源：[E1](evidence.md#e1表达与过滤)。

### 折叠、焦点和邻接限制展示量，保留明细仍要由消费者承担

dependency-cruiser v18.5.0 提供目录折叠、焦点及邻接深度选项。
这些选项处理展示范围，不增加 Cordis 服务或装配事实。

- 范围：官方 CLI 说明，未在本轮重跑其抽取器。
- 代价：折叠隐藏内部结构。只看折叠图不能确定细粒度的循环、作用域或生命周期。
  本轮未独立验证这些选项对架构师工作量的改善。
- 来源：[E2](evidence.md#e2目录折叠与焦点)。

### ELK 负责几何布局，仍需渲染、状态管理与可读性核对

elkjs 0.12.0 提供可内联的浏览器 bundle。layered 算法计算节点位置、标签位置和边路由。
本机三节点循环、四条边探针获得了坐标和路由。它没有判定这些边的含义。

- 范围：官方说明与有限本机执行，不是性能或最优布局证明。
- 代价：官方 bundle 为 1,609,707 字节。无 worker 的执行可能阻塞页面。
  官方 README 列出了增量布局和模块接入问题，不能承诺切换后几何位置稳定。
  本机默认模拟 worker 的 terminateWorker 调用失败，布局结果本身已生成；本视图未使用该调用。
- 来源：[E3](evidence.md#e3elk-版本与探针)。

### 矩阵和关系图可表达同一组直接依赖，但方向必须明确

NDepend 将 DSM 的表头对应到图节点，将非空单元格对应到图关系。
Lattix 支持从列读或从行读依赖，默认方向与另一种方向的含义不同。
本仓库探针的总览为 12 组、41 条聚合关系；关系图适应一屏后标签过小。

- 范围：官方描述及本次截图，不代表所有图都比矩阵难读。
- 代价：矩阵需要读者先理解行列方向；路径和多种关系仍需详情。
  聚合后的对称形状不能直接证明成员级循环或设计分层。
  两家厂商的可扩展性和发现缺陷宣传未作为本轮实效结论。
- 来源：[E4](evidence.md#e4矩阵与关系图)。
