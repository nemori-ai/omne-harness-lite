# 有限图片观察能支持多强的估算结论

- 调查对象与日期：2026-09-29，四个精确 Sol/Luna ID，经 OpenRouter 固定 `openai` 路由。
- 消费者：模型适配纵线的图片计量实现及真实认证。
- 当前结论：六个基础型号样本没有越过原研究余量；两个 Pro 请求完成，但其输入计费统计不足以验证上下文预测。有限样本没有给出通用误差上界。

## 问题与区分条件

研究代理把每图贡献记为 `ceil(ceil(width / 32) * ceil(height / 32) * 1.2)`，并以 `o200k_base` 对图片 URL 替换为 `[image]` 后的完整 JSON 计数。研究原件使用既有 Astra helper；这些固定图尺寸没有触及 Astra 缩放或 patch 上限，因而在这些样本上恰等于上述原始尺寸公式。两者在更大尺寸不一定等价。

需要区分三件事：请求能否完成、实际上下文计量是否可识别、代理预测是否足够接近。Pro 的请求成功不同时回答后两项；无缓存字段的简单相加也不等于当前规范的完整输入。

## 当前结论

### 六个基础型号样本的完整输入为21、1239、7109

每个基础型号各发送一张 65×65、1024×1024、2049×2903 合成 PNG，固定短文本、`low` effort、`max_tokens:512`，未发送显式 detail。六次均 `complete`，上游型号及 serving provider 与请求相符。

| 型号 | 图片 | 预测输入 | 原准入值 | 实际完整输入 | 预测减实际 |
| --- | --- | ---: | ---: | ---: | ---: |
| Sol | 65×65 | 101 | 368 | 21 | 80 |
| Sol | 1024×1024 | 1319 | 1707 | 1239 | 80 |
| Sol | 2049×2903 | 7188 | 8163 | 7109 | 79 |
| Luna | 65×65 | 102 | 369 | 21 | 81 |
| Luna | 1024×1024 | 1320 | 1708 | 1239 | 81 |
| Luna | 2049×2903 | 7189 | 8164 | 7109 | 80 |

观察中的 `observedInput.kind` 是 `from_usage`；完整输入为互斥的 `input_tokens + cache_read_tokens + cache_write_tokens`。例如 Sol 的两张大图分别为 `3 + 0 + 1236` 与 `3 + 0 + 7106`，不能漏掉 cache write。六次原成本按十进制精确合计 `$0.02221195`。

- 适用范围：精确冻结输入、研究 binding、当时路由；来源见 [六次基础型号实验](evidence.md#六次基础型号实验)。
- 推断：这些不同尺寸为图像贡献随 patch 数增长提供有限经验依据；不是 Sol/Luna 上游精确算法的身份确认。
- 代价与不适用：79–81 的残差混合 tokenizer、最终 JSON 和私有封装差异，不能当作可扣除常数。未测格式、长宽比、接近窗口极限的图片、多图、历史与工具组合的实际误差均不能由六点推出。余量是调用配置，本次未据样本重新拟合。

### 两个Pro请求的1431不能当作上下文长度

Sol Pro 与 Luna Pro 各发送 64×64、256×32 两图，均完成且返回精确型号／OpenAI。Sol Pro 原用量 I1431、O47（reasoning18），费用 `$0.003332`；Luna Pro I1431、O25（reasoning0），费用 `$0.0001556`。两者的观察范围均为 `unavailable/scope_unknown`，故上下文残差与准入是否覆盖实际上下文没有可计算结论。

- 适用范围：两个 pair 请求；来源见 [两次 Pro 实验](evidence.md#两次-pro-实验)。
- 推断：模式身份支持讨论同基础模型代理的适用假设，但本次只观察到请求接受及计费事实。
- 代价与不适用：不存在对应 Pro 无图基线；不能把与基础型号 I25 的差值归因为图像预处理，更不能把 1431 拟合为上下文开销。完整上下文校准仍缺计量范围依据。

### 原始尺寸代理超出样本范围时仍是估算假设

[第一方材料](evidence.md#第一方材料)列出命名模型的 patch 家族规则和 Pro 模式身份，但所核资料没有给出四个 Sol/Luna 精确型号的图片预处理等价保证。该“未找到”是资料边界，不证明上游不存在内部规则。

- 适用判断依赖：实际图片有可信尺寸；相同可见输入协议仍可用于经验代理；与基础型号对应的 Pro 模式不使代理失去全部相关性。这些是实现估算的假设，不是精确模板或上界。
- 代价与不适用：原始尺寸算法不会反映未知缩放，较大图可能过估；也没有证据排除某些输入低估。将 Astra 的 30,000 patch 上限移植成 Sol/Luna 容量事实、限制成测试 PNG SHA 白名单、或把 4 MiB 项目供给值称为上游上限，均超出此证据。
- 本机格式、尺寸解析、历史保留和准入负控能够验证实现性质；它们不能代替真实图片预处理观测。

## 采用与后续核对

本包只记录事实与适用限制。估算及配置余量政策已有 D-101，该决定不因此获得新的精确性保证。源码、型号别名、提供方、模式计费或图像规则变化时，需要重新核对受影响观察；先前冻结收据不改写。
