# Qwen3.8 public-template continuation evidence (2026-09-28)

This note is implementation evidence for the two exact open leaves `qwen/qwen3.8-2.4t-a95b` and `qwen/qwen3.8-27b` through the fixed OpenRouter `alibaba` route. It does not adopt an OpenRouter-to-Alibaba conversion policy.

- Pinned public `chat_template.jinja` at Qwen/Qwen3.8-2.4T-A95B commit `207bd685a7e3696cfaff12ded7c6a7ea0f88c996` and Qwen/Qwen3.8-27B commit `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0` use Jinja `tojson` for tool definitions and non-string tool arguments. Independent Jinja2 3.1.6 rendering escapes Chinese and emoji to `\\u` sequences, sorts keys by Unicode code point, and rejects a history with no user query outside a wrapped `<tool_response>`. The pinned template and `reference-render.py` produce the same 552-token Unicode/two-call/consecutive-result prompt for both leaves. This checks a public template projection, not the private serving conversion.
- [Alibaba's Chat Completions documentation](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions) lists Qwen3.8 open leaves among models with `xhigh` default and says `high` and `max` map to `xhigh`, while `none` disables thinking. [Alibaba's Responses documentation](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-responses) repeats the model mapping. [OpenRouter's Qwen3.8 article](https://openrouter.ai/blog/insights/qwen-3-8/) reports HTTP 200 for `high`, `max`, and `minimal` on four tested models, and `none` success on its 27B/Alibaba route. [OpenRouter's parameter documentation](https://github.com/OpenRouterTeam/docs/blob/main/api_reference/parameters.mdx) gives the general effort vocabulary. These sources do not disclose how OpenRouter transforms `reasoning.effort` for this exact route. An accepted response or zero reasoning tokens does not reveal the actual prompt prefix. The meter therefore cannot claim the Alibaba direct mapping for OpenRouter requests with explicit effort.
- Qwen3.8-27B's pinned `preprocessor_config.json` specifies `Qwen3VLProcessor`, `Qwen2VLImageProcessorFast`, patch 16, temporal patch 2, merge 2, shortest edge 65,536 pixels, and longest edge 16,777,216 pixels. The template only emits image/video pad markers; it does not account for image grids, resizing, video frame selection, or OpenRouter-to-Alibaba preprocessing. [Alibaba's Chat Completions documentation](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions) and [visual-understanding guide](https://help.aliyun.com/en/model-studio/vision-model/) supply a narrower unscaled-image formula; the subsequent [vision evidence note](2026-09-28-vision-and-effort-evidence.md) bounds an **estimated** inline-PNG subset. Remote images, resized images, video, and unverified provider conversion still lack a usable projection.
- The six other fixed Qwen IDs have no corresponding pinned public tokenizer/template evidence in the adopted research. Their wire projection can be tested, but the two open leaves' tokenizer and template must not be reused by model-family name.

Release evidence for explicit effort: a versioned OpenRouter adapter/Alibaba serving mapping for the exact model/provider pair, or controlled calls with a prompt-count oracle that discriminates the candidate template prefixes, followed by owner adoption. Full media release needs an exact preprocessing mapping for inline/remote images and video on the fixed route, plus image/video fixtures across sizes and token accounting. The current unscaled inline-PNG subset needs controlled actual-route usage before certification; other media remain `unavailable`.
