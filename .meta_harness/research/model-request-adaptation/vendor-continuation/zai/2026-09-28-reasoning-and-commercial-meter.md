# Z.AI selected-route reasoning and commercial meter source check

Checked 2026-09-28 for the fixed OpenRouter `z-ai/fp8` GLM-5.2/5.3/Flash routes, `alibaba` GLM-5.3-Prime, and `z-ai/fp8` GLM-5.3-FlashX. This is a targeted source read, with no credential, paid request, or selected-route prompt observation. The prior pinned public templates/tokenizer and route facts are in the parent topic's [input-meter report](../../reports/2026-09-28-input-meter-sources.md) and [route report](../../reports/2026-09-28-zai-route-facts.md).

## Direct observations

- The [Z.AI GLM-5 repository](https://github.com/zai-org/GLM-5) enumerates public GLM-5.3, GLM-5.3-Flash and GLM-5.2 model downloads and says the GLM-5.3/Flash chat-template `clear_thinking` default is `false` when omitted. That is the public local-template default, not a statement about OpenRouter's selected provider route.
- The [pinned GLM-5.3 template](https://huggingface.co/zai-org/GLM-5.3/blob/aca966e4e02791568aa6a4ced368624b3d897f42/chat_template.jinja) consumes `reasoning_content`. The [pinned Flash template](https://huggingface.co/zai-org/GLM-5.3-Flash/blob/eb9eb208eb0d988989d07a6a12d0fdeb5f52574a/chat_template.jinja) does likewise. Their public template behavior supports the existing text/tool subset, but it does not identify the OpenRouter server conversion from historical `reasoning`/`reasoning_details` or the selected route's `clear_thinking` value.
- [OpenRouter's GLM-5.3 page](https://openrouter.ai/z-ai/glm-5.3) instructs callers to replay complete `reasoning_details`. This supports retaining the ordered details on the wire; it does not say how those JSON members enter Z.AI's prompt or whether the selected endpoint clears previous thinking. The project's final planner sends those fields without rewriting them to `reasoning_content`.
- [OpenRouter's FlashX page](https://openrouter.ai/models/z-ai/glm-5.3-flashx-20260918) calls FlashX a high-speed Flash variant. It supplies no token vocabulary, chat-template identity, or exact input-accounting relation. The [GLM-5 repository](https://github.com/zai-org/GLM-5) does not list a public FlashX checkpoint; the [Prime page](https://openrouter.ai/z-ai/glm-5.3-prime) likewise does not establish a public tokenizer/template mapping for its selected Alibaba route. This is a source gap, not a proof that such mappings do not exist.

## Constrained experiment and limits

The executable [eight-case probe](../../../../../packages/model/pi-ai-transport/tests/fixtures/zai/reasoning-mapping-probe.mjs) is a diagnostic candidate for the single approved paid owner. One GLM-5.3 `z-ai/fp8` seed obtains a real selected-route response. Up to three follow-ups keep the same full assistant content and prior user/system context, varying only historical reasoning: absent, actual plain `reasoning`, or complete ordered `reasoning_details`. Plain/details cases are skipped if that representation is absent or cannot be reconstructed losslessly from the seed stream. Two Prime and two FlashX cases keep a complete synthetic assistant tool-call/result history fixed while varying one final user text length. All eight request exact provider order, disable fallback, stream usage, and have at most one send each. The tool reserves each send in the existing ledger, writes private raw evidence before settlement, and stops on missing cost, incomplete stream, or provider mismatch. It has no retry.

For GLM-5.3, reported `prompt_tokens` differences can distinguish some hypotheses: no observed difference from control is consistent with clearing or ignoring history; positive differences are consistent with preserving at least some material. Neither pattern alone proves the private `reasoning_content` conversion, token equivalence to the public template, or a stable `clear_thinking` setting. Cache-read counts, provider identity, final request hashes, response errors and completion state must be reviewed alongside deltas. A source-level mapping or a stronger controlled counterexample remains necessary before the current three meters accept historical reasoning. GLM-5.2 and Flash remain separate exact-model gates.

For Prime and FlashX, a two-point usage difference establishes only that the selected route charged additional input tokens under this one controlled text change. It cannot validate the GLM-5.3/Flash tokenizer alias, a reliable upper bound, or a production estimated algorithm. A later model-specific candidate would need independent held-out text/tool/history cases, a stated error envelope and explicit caller margin, then the production final-plan/public/service checks. No such binding is claimed by this source read or probe fixture.
