# Google Flash local meter source follow-up — 2026-09-28

Scope: `google/gemini-3.7-flash` and `google/gemini-3.8-flash` via OpenRouter `google-ai-studio`; public source reading only. This note does not adopt a tokenizer or an estimate policy.

- [OpenRouter 3.8 providers](https://openrouter.ai/google/gemini-3.8-flash/providers) and [3.7 providers](https://openrouter.ai/google/gemini-3.7-flash/providers), retrieved 2026-09-28 by page/search reading, name Google AI Studio and Google Vertex. They show route listing, not a successful request under the exact provider slug or an actual input count.
- [Google python-genai local loader at the investigated fixed revision](https://github.com/googleapis/python-genai/blob/6d012889752f65c1a51d0ad6e5970fc97d19c4ca/google/genai/_local_tokenizer_loader.py) and [current main page](https://github.com/googleapis/python-genai/blob/main/google/genai/_local_tokenizer_loader.py), read 2026-09-28, list Gemma 3 mappings for earlier Gemini 2.x/3 preview and Gemma 4 for Gemini 3.1/3.5 variants. The inspected mapping tables do not list the exact 3.7/3.8 names. This is absence in those tables, not a proof that no local estimator can be constructed.
- [Google token guide](https://ai.google.dev/gemini-api/docs/tokens) states that text, tools, image, audio and video consume tokens, gives media examples and model-specific token-count calls. Its 3.8 example uses an authenticated remote client. These statements do not specify OpenRouter's final Chat Completions conversion or a complete offline algorithm for either target model.
- [OpenRouter prompt-caching guide](https://openrouter.ai/docs/guides/best-practices/prompt-caching) shows `usage.prompt_tokens` and `prompt_tokens_details.cached_tokens` as distinct response fields. Its Gemini sections mix implicit and explicit descriptions for model generations; they do not settle the exact two selected routes' accounting. [OpenRouter response caching](https://openrouter.ai/docs/guides/features/response-caching) says response-cache hits can report zero billable usage, a confounder for any calibration using a repeated request.

The resulting unresolved observation is the per-model, per-provider relationship between a source-derived tokenizer over *all* projected input parts and the input tokens reported on the exact OpenRouter route. The current source readings permit a bounded comparison experiment, but no claimed exact, conservative-bound or estimated meter is established by them alone.
