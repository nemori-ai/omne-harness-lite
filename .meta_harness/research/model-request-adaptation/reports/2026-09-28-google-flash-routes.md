# Google Gemini 3.8 / 3.7 Flash route facts — 2026-09-28

Scope: `google/gemini-3.8-flash` and `google/gemini-3.7-flash` through OpenRouter Chat Completions, with the Google AI Studio and Google Vertex provider slugs. Sources were retrieved via web search on 2026-09-28; the observations below are source statements, not paid route certification. The model and provider listings can change after this date.

| Fact | Primary source and interpretation |
| --- | --- |
| Exact target IDs and routes | [OpenRouter 3.8 model page](https://openrouter.ai/google/gemini-3.8-flash/providers) and [3.7 model page](https://openrouter.ai/google/gemini-3.7-flash) list both models and Google AI Studio / Google Vertex providers. [OpenRouter provider routing documentation](https://openrouter.ai/docs/guides/overview/auth/byok#byok-with-provider-ordering) uses `google-vertex`; the existing 2026-09-27 public ledger snapshot records `google-ai-studio` on both models. The model pages separately display flex/priority service tiers. |
| Modalities and token figures | [Google 3.8 model card](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash) and [3.7 model card](https://ai.google.dev/gemini-api/docs/models/gemini-3.7-flash) each list text, image, video, audio and PDF input, text output, 1,048,576 input tokens and 65,536 output tokens. PDF is a file format, rather than a modality in this project's four-value vocabulary. OpenRouter's model pages agree on the broad modalities and context. These are upstream figures; they do not state this project's bounded offer. |
| Reasoning | [Google thinking guide](https://ai.google.dev/gemini-api/docs/thinking) lists `low`, `medium`, `high` for both models; `minimal` is unsupported. [OpenRouter model pages](https://openrouter.ai/google/gemini-3.8-flash/providers) expose the `reasoning` request object. The provider-specific OpenRouter translation and live acceptance of each value were not observed here. |
| Sampling | [Google's 3.8 migration guidance](https://ai.google.dev/gemini-api/docs/latest-model) says to remove `temperature`, `top_p` and `top_k`; [Google's 3.5 guidance](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.5) extends the recommendation across Gemini 3.x. The OpenRouter model pages still list `temperature`, `top_p` and `seed` as generic request parameters. The documentation does not establish a tested per-route acceptance domain for them. |
| Output count | OpenRouter's model pages list the `max_tokens` request field; the Google model cards list a 65,536 output-token limit. Neither source establishes how a value above a particular endpoint's current limit is reported through OpenRouter. |
| Cache | [Google caching guide](https://ai.google.dev/gemini-api/docs/caching) says implicit caching is enabled by default for Gemini 2.5+ and specifically lists 3.8 and 3.7 Flash with a 4,096-token eligibility threshold. [OpenRouter prompt-caching guide](https://openrouter.ai/docs/guides/best-practices/prompt-caching) describes implicit Gemini caching and also describes an older explicit Gemini flow. The documentation does not establish an exact OpenRouter cache hit, TTL, accounting result or per-route guarantee for these two model revisions. |

Unobserved here for either model: per-provider current route parameter acceptance, cache hit/retention/accounting, multimodal and tool/reasoning signature replay on paid streams, provider-specific output refusal and billing. The existing 2026-09-27 ledger is evidence for earlier probes, not for a new implementation revision.
