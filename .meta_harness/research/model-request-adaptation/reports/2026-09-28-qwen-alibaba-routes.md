The preserved per-model controlled run records two warm reads for each of the eight models, the `alibaba` provider, and whether the request sent explicit controls. The exact archived Qwen Max request under `openrouter-research.tar.gz` (`families-02/9b5e53bd-cdbf-470f-b16d-1adc1987f704.json`) has `request.messages[0].content[0].cache_control = {type:"ephemeral",ttl:"5m"}` and HTTP 200; `tools/model-probe/src/run.mjs` puts the configured control on the system text block. [OpenRouter's SDK type](https://github.com/OpenRouterTeam/ai-sdk-provider/blob/1b22b05352cb0f9243a6c3fdd326038dd3705544/src/types/openrouter-chat-settings.ts#L137-L144) also accepts the `5m` wire value. These facts justify the declared narrow request shape; warm reads alone do not prove the control was honored, nor that a cached value actually survived for five minutes. The [current prompt caching guide](https://openrouter.ai/docs/guides/best-practices/prompt-caching) omits these eight exact names from its explicit-support examples. Its list is not treated as an assertion of per-model absence, and the route declarations remain subject to a fresh controlled probe.

The only per-model effort observations applied beyond the local archive are OpenRouter's [Qwen 3.8 route experiment](https://openrouter.ai/blog/insights/qwen-3-8/) on September 11: Max and 2.4T rejected `none`, all four tested models accepted `high` and `max`, and 27B accepted `none` through Alibaba. The reported Flash `none` result was through Makora. Values such as upstream `minimal` are outside the accepted unified `ReasoningEffort` domain, so this implementation cannot pass them under that name. The fixed route's unverified values are dropped with `droppedParameters` history, not called unsupported by the upstream model.

Every route uses a marked `user` system reminder, passes `maxOutputTokens` unchanged, and declares only a bounded subset of unified parameters. Temperature, topP, seed, stopSequences, frequencyPenalty, presencePenalty and unregistered `extra` are intentionally dropped with traceability pending per-route value-domain evidence; no model ability conclusion follows. The existing OpenRouter planner fixes provider order to exactly `["alibaba"]`, disables fallbacks and requires parameters, and preserves paired tools and reasoning history in the controlled text fixture. No Qwen-specific public implementation revision or official `ModelDefinition` is published by this file. Input-only token ceilings, output maxima, actual multimodal constraints and complete media encoding are not established here; the known image/video modalities must not be silently reduced to text to make profiles appear complete.

Local validation used Node 24.18.0, pnpm 10.28.1 and this worktree's `pnpm install --frozen-lockfile --ignore-scripts`; `pnpm run build`, package build, sequential package typecheck, 19 targeted tests and scoped Prettier check passed.
