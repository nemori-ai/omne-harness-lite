# 工作区修订的技术影响核对

调查于 2026-09-27，输入修订与范围见 [入口](README.md)。当前结论：**四个既有规格包的工作区部分不能直接承载新产品定义；reload 核心协议已符合；其余主要是尚未设计的工作区接入，而非已完成治理、执行或会话窄口需要整体重做。**

## 核对方法与边界

以本轮十份 PF 的增量为准，沿 catalog 精确依赖、covers 的来源定位和 realization 实际采用版本回读正文。covers 的存在只用于找来源，不当作覆盖已成立；原 `reviewed` 状态不在本轮提升。PF-001 本轮未升 rev，但其 `data.identity-values/v1` 是资产模型直接消费的身份依据，纳入传播核对。

已完成的契约不等于对应 PF 已全量技术设计。下表中的“未发现冲突”仅指这次产品增量与所列既有条款，不是整个 PF 已交付。[来源记录](evidence.md)区分逐条原文和推断。

## 当前结论

### 工作区身份与清单规则存在确定冲突

[身份与清单原文](evidence.md#身份与清单)仍要求不同租户挂同目录形成两份互不可见工作区，工作区键是租户加目录；清单显式列举，未列的文件不进入求值。新产品允许同一逻辑工作区和实例跨租户使用，并要求双命名空间、根约定目录发现、登记嵌套路径与一律排除软链接。两种语义不能由相同输入规则同时表达。

受影响的既有包为 `data.identity-values/v1`、`data.asset-model/v2、v3`、`capability.asset-evaluation/v2、v3`。包括身份、carrier 资产身份导法与归属、输入一致性条件、清单形状与读入、配值丢弃规则及对应 Schema／场景／形式表达。不是把 `tenant` 字段删掉或给旧清单多加一个目录就能声明兼容：会话求值的租户身份仍然需要，资源身份和访问资格也仍然分开。

适用范围：确认原语义与产品增量不一致，不裁定新的身份结构或协议。冻结边界意味着语义更新必须使用新版本；PF-020 技术设计尚未展开，本轮没有给这些版本起草替代规范。

代价与消费者：AM3、AE3 的既有 core 实现和证据只证明旧输入模型；资产运行时仍有精确采用 AM2／AE2 的消费者，不能只修改最新版本就声称整链升级。后续修订需要沿实际消费条款复核，不能给所有依赖 identity-values 的账号、组织或客户端契约机械升版。

### 显式 reload 与校验失败保留旧数据已有契约承载

[注册表原文](evidence.md#重载与求值时点)已经规定按类别 reload、全部检查通过且装配清单追加成功才提交；失败不换表。每次尝试重新求值时明确沿用最近装配或 reload 读入的工作区内容，**不重新读目录**。因此 PF-014 本次纠正“reload 总是完整重装配”的旧产品表述，没有造成新协议缺口；PF-004、006 的文件变更不静默加载原则也不要求推翻该协议。

适用范围：不把已有治理权限现读、通知收窄和 MCP 动作刷新误改成“全部等 reload”；它们与本地资产文件刷新是不同输入。失败保留旧数据不等于任何故障下任意旧正文永远可恢复，重启后目录已变、旧正文不可取时，既有 S-25／S-33 仍有明确 `unavailable` 边界。

代价与不适用：真实工作区输入提供者尚缺，现有协议充分不代表新的双目录发现与 merge 已实现；注册表节点 A-2 与 CLI 的 C-3 必须在接入时保持此时点边界。PF-004 完整装配生命周期仍有自己的未完成范围。

### 兼容 hook 的落地层冲突而翻译与技能包格式仍可复用

[兼容与技能原文](evidence.md#兼容与技能)表明 `hooks-import/v2` 是接收显式配置的翻译面；`skill-package/v2、v3` 定义包、资源与脚本，没有要求技能永远处于 agent 文件系统之外。新兼容开关、目录选择、来源冲突和本地覆盖属于尚未闭合的工作区读入链。

但 `hooks-import/v2` S-9 规定工作区来源 hook 落在租户层并设置 `disabled`；`asset-evaluation/v2、v3` S-17 也明说导入成租户格持有。PF-020 明定兼容候选仍进入工作区层。这是第三处确定冲突：旧显式导入路径不能直接代表新原位置兼容加载；`hooks-import` 的落地交接、AE 的该项例外与节点 HI-N5 需要随新读入契约演进。此判断不要求删除历史独立导入用例，也不预定新的启用字段。

适用范围：当前 hook 事件翻译和技能包格式可继续按所采用版本使用；这不是对未来 Codex／Claude 方言的兼容确认。兼容来源打开不等于仓库命令获得执行许可，hook 的租户显式启用规则仍成立；`Skills().exec_script` 仍仅能执行声明脚本，普通 Files／Shell 的权限没有被放宽。Skill 契约性质表 P-4 的旧“文件系统视野之外”来源理由已经过时；包内路径不得逃逸的性质本身不变。这是冻结文档的解释差异，不能借本轮改写旧版正文或声称需要重做包格式。

### 治理与会话窄口没有承诺完整工作区产品

[窄口与应用范围](evidence.md#既有窄口与应用范围)只覆盖资产流转、会话租户读取、进程执行或治理入口等各自范围。共享工作区不是 PF-003 的资产复制；跨租户共享实例也不改变一个会话捕获一个租户身份。工作区登记／解除关系／销毁级联、attach、多 worktree 与组织参与限制尚无完整契约；现有窄口的缺席不能靠应用节点自行补成这些协议。

适用范围：当前治理 CLI、中心入口和 Docker 部署接受仍按原边界成立；不能因此宣称已经实现 PF-016 rev10、PF-017 rev6 的工作区增量。
