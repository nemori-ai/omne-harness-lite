# Jev 保证什么、不保证什么，代价在哪

- 调查对象与日期：TypeSafe AI `jev-1.13.0`，2026-09-15 发布；取证 2026-09-19（两轮，同日）
- 消费者：待出现（2026-09-19 设计者要求调查，面向模型路由与系统内决策点选型）
- 最近核对：2026-09-19 / `jev-1.13.0`
- 当前结论：类型安全是数学保证且确实兑现，事实正确性没有任何额外保证；置信度整体可用但按问题类型
  差异极大；准确率强任务依赖；速度与成本优势缺少同类基线对照，因此尚不知其中多少来自模型本身。
  机制层面的接口语义已由官方文档讲清，架构与训练方法仍未公开——官方对训练只给出了优化目标，
  目前最实质的架构解读来自社区黑盒探测，不是厂商确认。

## 问题与区分条件

要区分四件被厂商措辞合并的事：**输出格式合法**、**输出事实正确**、**置信度可用于路由**、
**比通用模型更快更省**。第四点还要再分：快过自回归文本生成是同义反复（它不生成文本），
真正的区分条件是快过 constrained decoding 与小型微调分类器——这一项当前无任何证据。

第二轮补的是另一组区分：**接口语义**（一次请求里 state 与问题怎么组织、置信度从哪来、能不能弃权）、
**架构**（并行产出到底怎么实现）、**训练方法**（RLCD 是什么）三者的公开程度完全不同，
被"厂商未公开技术细节"一句话合并了。用途侧同样要分：**官方主张的用途**、
**官方自己写下的不适用**、**社区真的跑起来的场景**、**社区声称要做的场景**，四者证据强度依次递减。

会改变边界的观察：一份在独立语料上复现的校准曲线；一次与小分类器的同任务对照；
厂商公开架构或权重（CEO 已提及"考虑写论文"）；英语以外语言的实测数字；
一份跑满一个月以上的生产使用报告。

## 当前结论

### Jev 保证输出符合预定义 schema，不保证该输出事实正确

schema 合法性由构造保证，厂商图表中的 0% 幻觉率是推导出来的而非测出来的——其原话是
"Our number is not empirical. Schema matching is guaranteed, thus we can confidently add 0% into the plots."
发布讨论中的核心反驳未被推翻：模型仍可返回一个格式合法而内容完全错误的值，CEO 承认
"type-safety and hallucination are intrinsically related" 但未收回宣传措辞。

- 适用范围：对 `jev-1.13.0` 的结构化输出成立；「永不幻觉」这一措辞在事实正确性上不成立。
- 代价与不适用：把类型安全当正确性使用的系统，错误会以「格式正确的错误决策」形式静默通过，
  不产生解析异常——这类失败在只测解析成功率的链路上完全不可见。
- 来源：[E1](evidence.md#e1-官方发布)、[E3](evidence.md#e3-hn-发布讨论)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 置信度整体可用，但按问题类型差异达一个数量级以上

唯一的独立测试（3600 条，跨四个公开分类数据集）测得：置信度 ≥0.9 时约 92% 正确、覆盖 73% 样本；
但校准误差 yes/no 0.012、pick-one 0.086、rating scale 0.254，最好与最差相差约 20 倍。
该测试还指出 Choice 的 confidence 并非独立训练量，而是 top choice 对随机猜测的重标定。
厂商侧至今没有论文、可靠性曲线或 ECE 数字。

- 适用范围：该测试所用的四个数据集与三类问题形态；未覆盖本项目的真实语料。
- 代价与不适用：单一置信阈值不能横跨问题类型使用；评分量表类问题按 yes/no 的阈值经验设置会系统性偏差。
- 来源：[E4](evidence.md#e4-独立预注册测试)、[E3](evidence.md#e3-hn-发布讨论)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 准确率强任务依赖，与前沿模型互有胜负

同一份独立测试的两个真实任务里排序翻转：提交信息分类（800 条）Jev 65.8% 居首，
知识库分类（450 条）Jev 90.7% 落到第三，六对两两排序中五对翻转。
解析失败率 Jev 0/800，其余模型 0–2/800。

- 适用范围：单人仓库语料，56.5% 的提交带 `Co-Authored-By: Claude` 标记，对 Claude 系构成污染；
  测试作者明确声明"不要当作可复现的 benchmark"。
- 代价与不适用：不能据此预判它在任意分类任务上的相对位置；换一个任务形态结论可能反转。
- 来源：[E4](evidence.md#e4-独立预注册测试)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 能力边界由设计固定，不随使用方式放宽

不生成任何文本或字符串；输出只有类型化值与概率，**不给出理由**；仅接受文本（字符串、JSON 对象或
文本数组），不支持图像、音频、视频；英语为主要训练语言，含 CJK 在内的其他语言"handled but not
equally well"；不做按客户微调，定制只经请求参数。上下文为 64k tokens/请求（state 加全部问题）
与 32k（state 加最长的单个问题）两档预算，OpenRouter 页面只标 32K。

弃权一项已由第二轮一手确认：模型侧**没有**弃权语义，官方文档要求调用方自己往选项里加
`other` 或 `none of the above`，Noul 则以 0.5 表示真实的不确定，API 字段表中无任何
unknown / needs_review 字段。即「不知道」不是模型的一种输出，而是调用方必须自己设计进选项空间的东西。

- 适用范围：`jev-1.13.0` 的文档陈述。弃权一项为**读遍官方概念、原语与 API 三处后的确认**，
  非构造反例验证；每请求问题数仍只有"受 token 预算限制"一句，二手汇总所称"每请求 32 问、
  每 choice 64 选项"仍无一手依据，与发布稿的 "cardinality up to 255" 三处口径未统一。
- 代价与不适用：需要解释、需要中文高准确率、需要多模态或需要模型自行说"不知道"的场合都不适用；
  非文本输入必须由调用方先行转成文本或结构化字段，这部分工作量转移到系统侧。
  弃权要自建，意味着"低置信时怎么办"完全落在调用方：选项空间、阈值与兜底路径都得系统侧自己定义，
  模型不会替你留这一档。
- 来源：[E2](evidence.md#e2-官方文档)、[E5](evidence.md#e5-openrouter-可得性)、
  [E7](evidence.md#e7-官方概念与机制文档)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 厂商自曝的失败模式集中在数量、时间与多跳，且是定性的

官方为 `jev-1.13` 单列了一页「jaggedness」，自述这一版不可靠的地方：不能可靠计数（且
"error grows with the size of the thing being counted"）；"not a calculator"；
"reads dates as text, not as ordered quantities"，在比较、时长与混合格式上不可靠；
hex、RGB 等数值表示差，无法判断两值是否接近；"multiple hops of reasoning costs accuracy"；
state 里掺入与决策无关的内容会让准确率下降；措辞上"answers the question you wrote, not the one
you meant"。最值得注意的一条是**结构性的**：肯定问与其否定问的概率不保证和为可预测的值。

- 适用范围：厂商对 `jev-1.13` 这一版的自述，**全部为定性描述，没有一个数字、没有阈值**，
  也未说明这些判断出自何种内部测试。该页未声明完整性，因此不能当作弱点的穷尽清单。
- 代价与不适用：凡涉及计数、算术、日期与数值比较的判断，必须在调用方用代码做掉，只把语义判断留给模型；
  肯定/否定两问的概率不能互相校验，也不能据此构造"自洽性检查"——这条会让一类常见的兜底设计失效；
  长 state 不是免费的，塞进无关上下文会同时付出 token 与准确率两笔代价。
- 来源：[E8](evidence.md#e8-官方自述的能力不均)
- 最近核对：2026-09-19 / `jev-1.13.0`
- 附带处置：上一轮列为「流传说法、未经一手确认」的「不会算术」「把日期当文本」两条，由此获得一手确认。

### 速度与成本的数字全部来自厂商，且缺少同类基线

70–500ms 端到端、40–200x faster、workflow evals 的 193.6x / 444.6x，均为 TypeSafe 自述，
对照组是 GPT-5.6 Terra、GPT-6 Astra、Fable 5.1、DeepSeek 等文本生成模型。
发布讨论指出这是拿不同问题类别作比：一个小型微调分类器也能达到类似延迟，
而与 constrained decoding、小分类器的对照至今无人给出。Doom 演示被指喂的是预结构化的游戏状态坐标
而非像素感知。厂商自认无法证明定价未被补贴（"We can't prove it isn't subsidized"）。

- 适用范围：这些数字作为「厂商在其自选任务上的测量」成立，不支持「同等能力下快 40–200 倍」的推广。
- 代价与不适用：把该倍数作为选型依据前，缺口是与真正替代品的对照，而不是与前沿 LLM 的对照。
- 来源：[E1](evidence.md#e1-官方发布)、[E3](evidence.md#e3-hn-发布讨论)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 架构与训练方法未公开，权重不开放

公开程度**分三层，不是一句"未公开"**：接口语义有完整文档（见下一条）；架构完全保留，CEO 在发布讨论中
两次明说 "close to the chest"，第二次补了一句"考虑写论文"，仍非承诺；训练只给了优化目标，方法从未说明
（见后一条）。社区推测为"constrained 或 diffusion-like decision model"，属推测不属观察。
本地部署无承诺。可第三方复现的是评测面：公开 evals 面板（含分歧案例与完整查询）与一个开源 adapter，
后者可让他人在竞品模型上重跑同一套对比；不可复现的是架构、训练方法与内部 workflow evals。

- 适用范围：截至 2026-09-19 的公开信息。架构一项为**读遍官方文档全导航后未找到**，
  非构造反例验证不存在——官方发论文即失效。
- 代价与不适用：无法离线评估、无法自行微调、无法在断网或自有硬件上运行；
  模型行为变化只能通过版本号与外部观测发现。
- 来源：[E1](evidence.md#e1-官方发布)、[E3](evidence.md#e3-hn-发布讨论)、
  [E6](evidence.md#e6-二手技术综述)、[E7](evidence.md#e7-官方概念与机制文档)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 官方把机制讲到接口语义为止：说清了怎么用，没说怎么实现

官方文档给全的是一次请求内部的语义：一个 `state` 对一组具名问题，所有问题看同一份 state、
**彼此独立评估**，一个问题的答案不会成为另一个问题的隐藏上下文；state 只接受字符串、JSON 对象或
文本数组；三个原语各自的返回形状固定——Choice 给 `choice` 加全选项概率分布加 `confidence`，
概率**被约束在给定选项集内**，Score 给有序档位上的位置（答案可落在两档之间），Noul 只给一个 0–1 概率
且**没有独立的 confidence 字段**。其中最该记住的一条是：`confidence` 不是模型另外输出的量，官方原话是
"a statistic computed from the probability distribution the answer already gives you"——
它是从概率分布算出来的统计量，与 [E4](evidence.md#e4-独立预注册测试) 的独立观察吻合。
官方对阈值只给方法不给数字："A confidence threshold is not one number."，要求按后果分级并用自己的数据调。

机制描述到此为止。并行产出**怎么实现**、用什么架构、多大规模、什么 tokenizer，官方一字未提。

- 适用范围：2026-09-19 的官方文档状态。"未提架构"是**按完整导航逐项判断后读遍未找到**——
  可能涉及的只有 `concepts/` 与 `introduction/` 两组，均已读。
- 代价与不适用：能据此写对调用代码，不能据此预判性能与失败边界；
  `confidence` 既然是导出统计量，它就只反映分布有多集中，**不携带任何关于"模型是否见过这类输入"的信息**，
  把它当作分布外检测使用会落空；同请求内问题互不可见，意味着需要串联判断的场合必须拆成多次请求，
  延迟与计费都按次累加。
- 来源：[E7](evidence.md#e7-官方概念与机制文档)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 训练只公布了优化目标，RLCD 的方法从未说明

RLCD 展开为 Reinforcement Learning for Calibrated Decisions。官方说明的是**目标**：
概率 "optimized against outcomes to reflect uncertainty"，且 "Higher probability should correspond
to a greater chance that the answer is correct."（0.2 的预测约 20% 发生，0.8 约 80%）。
官方给出的理由是路线选择而非技术细节——他们判断大规模自动化将由 AI 对 AI、AI 对软件的交互主导，
因而机器接口比聊天接口重要；并以此对照 RLHF（优化人类偏好，导致 mode dropping）与
RLVR（产出的推理模型强于数学但更慢更贵）。

**方法一侧完全空白**：预训练底座、数据来源（发布稿 FAQ 列了"Where does our training data come from?"
一问，正文无答案）、损失与奖励形式、模型规模、是否蒸馏，全无陈述。HN 上有人给过机制直觉——
对"答案为否却给出 {yes: 0.9} 的分布"重罚、对 {yes: 0.6} 轻罚——但这是评论者的推想，无任何来源，
不能当作 RLCD 的实际实现。同一线程里有人直接点明："System One hasn't said how RLCD works."

检索时注意一处陷阱：学术界另有一个 RLCD（Reinforcement Learning from Contrastive Distillation，
arXiv 2307.12950，2023），做的是无人类反馈的对齐，与 TypeSafe 的 RLCD **只是缩写相同，方法与目的均不同**。

- 适用范围：截至 2026-09-19 的公开信息；官方称模型是 "zero-shot" 而非 "instruction-tuned"。
- 代价与不适用：无法判断校准是训练目标带来的还是架构带来的——**厂商未做、社区也未做任何消融**；
  因此"因为用了 RLCD 所以置信度可信"这一推理链在任何一环都没有证据支撑，
  能支撑置信度的只有外部实测（[E4](evidence.md#e4-独立预注册测试)、
  [E10](evidence.md#e10-社区黑盒架构分析)），与训练方法无关。
- 来源：[E7](evidence.md#e7-官方概念与机制文档)、[E3](evidence.md#e3-hn-发布讨论)、
  [E13](evidence.md#e13-rlcd-命名碰撞)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 目前最实质的架构解读来自社区黑盒探测，不是厂商确认

一位独立作者（Archer Hume，2026-09-17）用 10,000 次以上 API 调用做行为探测，给出的模型是
"a causal transformer (likely using sparse MoE) repurposed for decisions: shared-state encoding,
isolated question suffixes, and direct probability readouts instead of text generation."
支撑它的观测是具体的：问题间 token 计费精确可加、超过约 100 问后延迟几乎不再增长、服务端耗时随输入
token 线性而随问题数亚线性（共享 state 加问题后缀）；塞进一个无关的 "weather" 选项能把两个选项的
对数比从 +0.38 压到 +0.11，且在 10 个区块上复现（选项在打分前**相互作用**，不是逐项独立打分）；
把 secret 放在兄弟问题里得 0.00、移进共享 state 得 0.90（问题间确实隔离）；445 次分词探测显示自定义
tokenizer，不匹配公开模型也不匹配 o200k；MMLU 样本上算得 ECE 0.0313。作者自行把结论分成
「厂商已公布 / 实验观测 / 推断 / 推测」四档，并写明 "the sparse backbone is the least certain part"。

同一时间，HN 上另有人认为就是 constrained decoding。**两说并存，本包不裁决**。

- 适用范围：单人单轮的黑盒实验，本项目未复现其中任何一次探测；结论是"哪种架构假设与这些行为相容"，
  不是"架构是什么"。与 constrained decoding 猜想直接冲突，冲突本身照实记录。
- 代价与不适用：可以拿它预期外部行为（问题数增加的边际延迟、选项集变化对概率的影响），
  **不能**拿它做容量规划或成本模型——这些数字随版本与服务端调度变化，且无人复现。
- 来源：[E10](evidence.md#e10-社区黑盒架构分析)、[E3](evidence.md#e3-hn-发布讨论)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 官方把用途定义为「软件内的判断点」，而不适用写在另一页

官方用途索引给五类定位：后台跑百万次的自动化、实时应用（自称 150ms，"faster than human perception"）、
大数据上的 AI map-reduce、通用验证（"Verify the input prompt, extractions, reasoning traces,
tool calls, or inputs of any other AI"），以及 **Harness Engineering**（"model routing, semantic
context retrieval, LLM error detection and guardrails"）。任务类型十项：分类、检测、打分、路由、
搜索、检索、排序、验证、ML 特征抽取、结构化抽取；行业纵向十九项；配方 25 篇（自洽性、并行提问、
重排序、逐行语义查找、结构恢复、function calling、知识图谱实体对齐、RAG 段落分类、引用复核、
LLM 护栏、日期抽取、层级分类等），另有四篇模式（推测性 fan-out、置信度门控路由、复合评分、意图路由）。
官方还发了面向 Claude Code、Codex 的 agent skill，指导 agent 去代码库里找"可用判断替换脆弱代码"的位置。

官方的构建主张很明确：代码拥有控制流，模型只出现在需要"programmable common sense"或解释非结构化数据的
地方；反对 agent 自选下一步的 `while` 循环形态，理由是 "every loop introduces another opportunity to
go off the rails"；宽问题要拆成原子问题；多个独立答案用确定性规则或加权和组合，或把概率当特征喂给
下游的经典 ML 模型；不确定的交给人或更贵的推理模型。

- 适用范围：厂商主张，**无一个数字、无一条对照**。记一条负面观察：用途索引页通篇没有"不适合"一节，
  不适用的场合写在另一页（[E8](evidence.md#e8-官方自述的能力不均)）——只读其一会得到片面印象。
- 代价与不适用：这些用途的共同前提是**判断点已经被拆成有限选项或有序档位**；
  拆题、定选项、定阈值、组合概率、设计兜底，这些工作全部留在调用方，
  官方文档把它们讲成方法，但没有一项由模型承担。
- 来源：[E9](evidence.md#e9-官方用途索引与配方清单)、[E1](evidence.md#e1-官方发布)
- 最近核对：2026-09-19 / `jev-1.13.0`

### 社区真的跑起来的集中在三簇，其余是声称

有实际数字可查的只有三份，且各自的证据强度必须分开看：

| 场景 | 实际观察 | 谁做的、强度 |
|---|---|---|
| 批量判定/匹配 | 9,081 对商品匹配候选，约 150 行代码，**$0.32**、13 分 22 秒（6 并发）；49% 驳回、21% 确认、30% 落在自建的弃权选项；手工复核 50 条中 48 条合理 | 独立作者，自陈运营竞品；**唯一做了人工复核的一份**，样本 50 条且由本人判定 |
| 批量质量筛查 | 37 篇文档 × 21 问 = 777 次判断，**0.7 秒内**、约四分之一美分 | 发布当日初体验；作者自己写明 "whether you'd trust those results is another question" |
| Agent harness | 接进 LangChain 的两处：模型路由、工具调用执行前的风险护栏 | LangChain 官方博客，**带商业动机**；性能数字转述自厂商，非自行测量 |

三者之外是声称：一份 586 星的 awesome-list 收了 31 个用例、11 个独立实现、9 个生态集成
（维护者对交易、家居自动化等高风险域明确标注仅限 dry-run）；一篇无来源的开发者文章列了浏览器 agent
选 DOM、游戏 AI、护栏、编码 agent 的上下文裁剪、按区块决策的交易机器人；HN 上另有人**声明打算做**
垃圾/钓鱼检测、家谱匹配、家居路由、合同校验、agent 工作流的语义分支。

把这些合起来看，社区注意力集中在三个方向：**给 LLM 或 agent 当护栏与路由器**、
**把"每行成本"压到让全量判定变得可行**、**塞进实时循环里做逐帧/逐块决策**。第三簇目前几乎全是演示与压测。

- 适用范围：发布后四天内的快照；三份使用记录**都不是对照实验**——无基线、无预注册、无第二人复核，
  任务与规模互不可比，成本数字不可外推（三者均未完整披露 state 大小与问题数）。
- 代价与不适用：成本优势兑现的前提是判定任务本身能被拆成结构化问题，拆不动的场合这笔账不成立；
  "全量跑"会把原先靠抽样掩盖的错误全部暴露到下游，因此三份记录里**唯一做了复核的那份也只敢把结论
  标为"仅供参考"**；发布周的社区样本对长期稳定性没有任何信息。
- 来源：[E11](evidence.md#e11-社区实际使用记录)、[E12](evidence.md#e12-社区用例汇总与开发者叙述)、
  [E3](evidence.md#e3-hn-发布讨论)
- 最近核对：2026-09-19 / `jev-1.13.0`
