# TypeSafe Jev：结构化决策模型的能力与边界

这项调查要区分的是：Jev 保证的「类型安全」到底覆盖到哪里、它的置信度在什么条件下可信、
它相对通用模型换来了什么又付出了什么，以及**官方把机制与训练讲到了哪里、剩下的由谁在推**。
当前观察支持「schema 合法性是数学保证」，不支持「输出事实正确」；
支持「在某类分类任务上与前沿模型可比」，不支持「普遍更准」；
支持「接口语义有完整官方文档」，不支持「架构或训练方法已知」——后者目前最实质的解读来自社区黑盒探测，
不是厂商确认。

- 调查对象与基线：TypeSafe AI `jev-1.13.0`（`jev-latest`、`jev-preview` 均指向它），2026-09-15 发布；
  OpenRouter 侧为 `typesafe/jev-1.13`。全部来源取证日 2026-09-19，分两轮（发布周主张核查 →
  机制、训练与用途补全）。
- 消费者：待出现。2026-09-19 由设计者要求调查，面向未来的模型路由与系统内决策点选型；
  尚无提案、决定或提供者设计引用本包。
- 最近核对：2026-09-19 / `jev-1.13.0`，见 [changelog](changelog.md) rev 1–8

## 准入核对

调查对象与版本明确，全部结论可回溯到带 URL 与抓取日期的来源，一手（厂商自述、官方文档、
发布讨论原帖、模型托管页、学术论文）与二手（媒体、博客汇总、社区 awesome-list）分别标注。

主要局限：**两轮均未执行任何实际 API 调用**，因此延迟、限额与计费行为全部未验证，
"文档说的不等于实现做的"这一条无法检验；架构与训练方法厂商仍未公开，社区的黑盒解读未经复现，
且与另一种猜想直接冲突（本包不裁决）；校准与准确率的独立证据仍只有一份单人预注册测试；
与同类替代（constrained decoding、小型微调分类器）的对照完全空白；
中文/CJK 已检索未发现任何实测；全部社区证据产生于发布后四天内，无长期运行记录。

结构选择：两轮论证都明显多于收敛后的结论，按篇幅轴各留一份报告原貌；
第二轮发生结论变更，按时间轴建 `changelog.md`；证据升至十三条后在 `evidence.md` 顶部加了索引表，
分节标题仍足以导航，未触发来源轴，因此不拆 `notes/`。
