## rev 6 — 2026-09-19 · 补充

**架构的最强公开解读来自一次社区黑盒探测，并且它与 HN 上的另一种猜想直接冲突。**

- 受影响结论：新增「[目前最实质的架构解读来自社区黑盒探测，不是厂商确认](research.md#目前最实质的架构解读来自社区黑盒探测不是厂商确认)」
- 触发：设计者要求"官方没有说明就查社区的解读或推测"
- 原结论：无，此前未覆盖——首轮只记了"社区推测为 constrained 或 diffusion-like decision model"一句
- 新结论：Archer Hume 以 10,000+ 次 API 调用做行为探测，给出"共享 state 编码 ＋ 问题后缀隔离 ＋
  直接概率读出的 causal transformer（可能 sparse MoE）"，并自行把主张分成已公布/观测/推断/推测四档；
  支撑观测具体可查（token 计费可加、约 100 问后延迟不再增长、假选项注入把对数比从 +0.38 压到 +0.11、
  可见性隔离 0.00 对 0.90、445 次分词探测、ECE 0.0313）。同时 HN 上另有人认为就是 constrained decoding，
  **两说并存，本包不裁决**。
- 证据差异：新增 [E10](evidence.md#e10-社区黑盒架构分析)；
  [E3](evidence.md#e3-hn-发布讨论) 第二次抓取补入与之冲突的 constrained decoding 猜想。
  冲突本身写进两条证据的「支持范围」，不静默挑一个。

## rev 5 — 2026-09-19 · 补充

**RLCD 官方只公布了优化目标，方法一侧完全空白；另有一个同名的学术方法容易误检。**

- 受影响结论：新增「[训练只公布了优化目标，RLCD 的方法从未说明](research.md#训练只公布了优化目标rlcd-的方法从未说明)」
- 触发：设计者要求调查"官方怎么训练的说明"
- 原结论：无，此前未覆盖——首轮只记了"训练用 RLCD"五个字，且把它与架构合并在一条里
- 新结论：官方给出目标（概率对齐真实正确率，0.2 约 20%、0.8 约 80%）与路线理由（机器接口重于聊天接口，
  并对照 RLHF 的 mode dropping 与 RLVR 的慢而贵），但预训练底座、数据来源、损失与奖励形式、
  模型规模、是否蒸馏全无陈述；HN 上的奖励形式描述是评论者推想，不能当实现引用。
  据此，"因为用了 RLCD 所以置信度可信"这条推理链在任何一环都没有证据支撑。

## rev 4 — 2026-09-19 · 补充

**接口语义其实有完整文档，此前被"未公开技术细节"一句盖住了。**

- 受影响结论：新增「[官方把机制讲到接口语义为止：说清了怎么用，没说怎么实现](research.md#官方把机制讲到接口语义为止说清了怎么用没说怎么实现)」
- 触发：设计者要求调查"官方对技术原理的说明"
- 原结论：无，此前未覆盖——首轮只读了 `docs/models` 限额页，未进概念与原语文档
- 新结论：一个 `state` 对一组具名问题、所有问题看同一份 state 且彼此独立评估；三原语的返回形状固定；
  Choice 的概率被约束在给定选项集内；Noul 无独立 confidence；**`confidence` 是从概率分布算出的统计量，
  不是另外训练的输出**（与首轮独立测试的观察吻合）；官方对阈值只给方法不给数字。
  并行产出怎么实现、架构、规模、tokenizer 一字未提，且这是按完整导航读遍后未找到。
