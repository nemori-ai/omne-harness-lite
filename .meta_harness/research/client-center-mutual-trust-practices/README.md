# 客户端与自托管控制面之间怎样互相确认身份：业界做法

这项调查回答的是：**一个命令行客户端与一个自托管的控制面（本项目里是据点与治理中心）之间，
业界怎样让客户端确认「连上的是真的服务端」、让服务端确认「来的是谁」**；
每种做法各守住什么、守不住什么、要付什么代价。
它是第二程 D-029（传输绑定接受与防冒充落点）的取证，产品负责人 2026-09-23 把第一版定为「自己人开发与实验迭代用」，
并授权主线按这个基调调研后拍板。

当前观察支持：服务端身份一律靠 TLS 证书加「客户端主动核对」，核对方式只有两条路（CA 链加主机名，或记住指纹）；
持有型令牌是终端用户 API 的通行做法，风险由「必须走 TLS、客户端必须核证书链、短寿命」三条缓解；
把令牌绑到客户端密钥是金融级 API 的加固，有两份 RFC；机器对机器才普遍用双向 TLS。
**不支持**：任何「该选什么」的结论——那归 D-029。

- 最近核对：2026-09-23（首轮）
