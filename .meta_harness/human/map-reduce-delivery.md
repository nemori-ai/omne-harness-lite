# Map-Reduce 式交付推进

本页回答一个问题：一批工作要由几个会话并行推进，这些会话之间又不能通信，怎样分解、派发和集成，才能既快又可靠。

本页是方法说明，不是规则。任务卡、分支、准入和接受由宿主仓库的交付协议与工具链拥有。本页与这些拥有者不一致时，以拥有者为准，并修改本页。

## 用 Map-Reduce 的形状组织并行

这种做法借用 Map-Reduce 的形状。map 是几条互不通信的交付线，下文简称「线」。reduce 是一个专门做集成的会话，即集成节点。

会话之间不协调，所以可靠性来自两条硬规则：

- 同时运行的线，写范围不相交。
- 各线共用的东西在派发前冻结。

只要这两条成立，各线就不需要知道彼此的进度。集成时不出现合并冲突，各线的候选能按固定顺序合入。

## 先判断这批工作是否适用

下面四个条件同时成立时，才适用这种做法：

1. 工作能切成写范围互不相交的几份。
2. 各份共用的接口、规则和不变量能在开工前定下来。
3. 每一份都能用替身独立验证自己，不必等别的份完成。
4. 有一个会话能在最后取得全部候选并做集成。

下面三种情形不适用：

- 工作本身是探索性的，要边做边改共享接口。这时先做一轮串行设计，把共享的部分定下来，再回到本页的做法。
- 几份工作的写范围怎样切都有交集。这说明它们属于同一条线，应交给一个会话串行推进。
- 只有一份工作。没有并行，就没有 map，直接推进即可。

## 三种角色各守一段

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| 派发者 | 冻结共享物，分解出线和波，为每条线写上下文地图与任务信息包，然后派发 | 派发之后不再向线传递新信息 |
| 交付线（map） | 一个独立会话。按任务信息包开工，在自己的写范围内推进到交付，交回候选与交接报告 | 不读别的线的进度，不改写范围外的文件，不改共享物 |
| 集成节点（reduce） | 一个独立会话。按固定顺序合入各线的候选，每合入一条运行一次准入，最后运行联调并确定稳定点 | 不替线补做未完成的工作，不与线通信 |

一条线可以分出子线。子线之间的写范围有重叠，或者后一条子线依赖前一条的结果，所以子线由同一个会话串行推进。一条线始终只由一个会话推进。

会话运行在哪个宿主上不影响这种做法。本地会话、云端会话或另一种 agent harness 都可以担任任何角色，前提是任务信息包与宿主无关。

## 六条不变量

1. **零通信。**线与线之间、线与集成节点之间没有任何通信。同步点只有两个：派发的时刻和交回的时刻。
2. **写范围不相交。**任何两条同时运行的线，写范围没有交集。派发前用脚本核对，不靠人的记忆。
3. **共享物先冻结。**共享物是所有线都会读、但只能有一个写者的东西，例如接口形状、不变量、依赖方向规则和公共值类型。派发者在派发前完成共享物，并固定一个提交号。线不改共享物，需要修改时停下并报告。
4. **任务信息包自包含。**一条线开工所需的全部信息都在它的任务信息包里。一个没有任何上下文的会话，只读这个包就能开工。
5. **基线固定。**同一波的线从同一个基线提交开工，候选也建立在这个基线上。基线在一波之内不前进。
6. **冲突说明分解有错。**集成时出现合并冲突，原因是分解时算错了写范围，不是「解决一下」就能处理的问题。集成节点记录这次冲突，派发者修改线的划分，下一波不再犯同样的错误。

## 分解分五步，每步有可核对的产出

### 冻结共享物

列出本批所有线都依赖的共享物：接口形状、不变量、依赖方向规则、公共值类型和集成入口。逐项完成，合入基线分支，取得冻结提交号。

产出：冻结提交号。派发者把它写进每个任务信息包。

### 列出工作项与写范围

把本批的全部工作项列成一张表。每项写清它要改的目录和文件，精确到成员或正文页。写不清写范围的工作项先拆分，拆到写得清为止。

产出：一张「工作项与写范围」表。

### 用连通分量求线

以工作项为节点，两个工作项的写范围有交集就连一条边，然后求连通分量。一个连通分量就是一条线。

如果一个连通分量太大，一个会话承担不了，就回到第一步：冻结被争用的那个文件，或者把它改归集成节点负责。不要把一个连通分量强行切成两条线，那样会违反不变量 2。

产出：线的清单。用脚本核对任意两条线的写范围交集为空。

### 用拓扑分层求波

以线为节点，一条线需要另一条线的交付结果才能开工，就连一条边，然后做拓扑分层。同一层的线组成一波，并行推进。相邻两波之间做一次集成。

关键路径是耗时最长的一条依赖链。缩短关键路径只有两种办法：

- 把共享物做得更完整，使长线不返工。
- 把长线内部切成子线，由同一个会话串行推进。

产出：波次表，以及标出的关键路径。

### 每波结束时集成

集成节点按固定顺序合入候选：依赖少的先合入，关键路径上的线最后合入。每合入一条运行一次准入。一波的候选全部处理完后，集成节点运行联调，确定这一波的稳定点。稳定点是下一波的基线。

产出：稳定点提交号和集成报告。

## 每条线拿到一张上下文地图和一个任务信息包

每条线有一个目录，里面放两个纯文本文件。这两个文件不依赖派发者会话的记忆，也不依赖任何一种 agent harness 的私有机制。

### 上下文地图告诉线读什么、读到哪里停

各线的上下文地图共用一份主体，每条线再加一节本线附录。上下文地图包含：

- 冻结提交号，本批不变量的原文。宿主为不变量提供机读标识时，一并写出。
- 系统领域地图、协作图和顶层架构图的位置。
- 本线要读的拥有者正文，精确到文件和行，按「先读什么、读到哪里停」排序。
- 本线最容易踩的耦合，例如哪个维度不能决定另一个维度，哪个外部领域的概念不能进入本领域的契约。
- 相邻线的接口：它们提供什么，需要什么。上下文地图不给相邻线的实现细节。

### 任务信息包写清能改什么、做到什么算完

任务信息包包含下面七项：

- 任务卡号与修订、基线提交、分支、路线和完成目标。这些字段与宿主仓库的任务绑定机制一致。
- 写范围：本线独占的路径清单。
- 禁写清单：冻结的共享物、别的线的写范围、留给集成节点的文件。
- 交付边界与验收标准，每条都能核对。
- 允许使用的替身和测试入口、本线的自测命令、准入命令。
- 停止条件，见[交付线遇到这些情形就停下](#交付线遇到这些情形就停下)。
- 交回格式，见[交回候选和一份四节报告](#交回候选和一份四节报告)。

### 派发前做一次自包含检查

派发者找一个没有任何上下文的会话，只给它这两个文件，然后问三个问题：

1. 从哪个提交开工？
2. 能改哪些文件？
3. 做到什么程度算完成？

三个问题都答得出，这个任务信息包才合格。

## 交付线遇到这些情形就停下

线在下列情形停下，写报告交回，不绕过去：

- 需要修改共享物。
- 需要修改写范围外的文件。
- 发现设计与不变量冲突。
- 任务信息包里的验收标准互相矛盾，或者与拥有者正文矛盾。
- 需要相邻线的实现细节才能继续。

停下不是失败。报告把问题交给派发者，由派发者决定修改共享物、修改线的划分还是修改任务信息包。线不替派发者做这个决定。

在写范围之内，线自己做出一切判断，不请示。零通信意味着请示没有人回答。

## 交回候选和一份四节报告

线交回一个候选和一份交接报告。报告固定分四节：

1. 做了什么：逐条对照交付边界与验收标准，写明达到或未达到，并给出证据。
2. 没做什么：每个未达到的项缺什么，线为什么停下。
3. 发现的冲突：与共享物、与不变量、与相邻线接口的冲突，写明文件和行。
4. 给集成节点的提示：合入时要注意的顺序、依赖和已知的脆弱点。

报告只陈述事实。「达到」是线对照验收标准的自查结果，不是接受。线不给自己的交付判定通过，接受归有资格的负责人。

## 集成节点按固定协议工作

1. 读全部候选和交接报告，不读各线的工作过程。
2. 按每波集成时的固定顺序合入。每合入一条运行一次准入。某条候选准入不通过时，集成节点不合入它，也不修改它的代码来补救。这条线退回下一波重做。依赖它的候选同样不合入，不依赖它的候选继续按顺序合入。
3. 出现合并冲突时，按不变量 6 处理：记录冲突，退回分解，不在集成节点手工解决冲突。
4. 处理完全部候选后运行联调，走完整路径。联调中的每一跳，已经交付真实实现的就用真实实现，尚未交付的用各线共用的替身。集成报告写明哪些跳用了替身。
5. 确定稳定点，写集成报告：合入顺序、每一步的结果、退回的线和分解错误清单。

集成节点不与任何线通信。它发现的问题写进下一波的任务信息包，不发给当前波的线。

## 按情形处理失败

| 情形 | 处理 |
| --- | --- |
| 一条线失联，没有交回 | 这一波不等它。它的工作项原样进入下一波，基线换成新的稳定点 |
| 一条线改了写范围外的文件 | 准入拒绝这条线的整个候选。线在自己的写范围内重做。越界的改动丢弃，确有需要时作为冲突报告交给派发者 |
| 一条线报告共享物需要修改 | 当前波继续。共享物的修改排进下一波的冻结步骤。依赖这项修改的线等到下一波 |
| 集成时出现合并冲突 | 按不变量 6 处理 |
| 联调失败 | 按失败的那一跳找到负责它的线，问题写进下一波的任务信息包。集成节点不修复 |

## 宿主仓库要提供四样机制

这种做法不定义任务卡、分支、准入或接受。这些由宿主仓库的交付协议与工具链拥有。这种做法只要求宿主提供下面四样机制：

- 任务绑定能记录基线、分支和写范围。
- 准入能核对候选是否越出写范围。
- 一份从线到目录的登记，供列出写范围和求线两步读取写范围。
- 一个联调入口，供每波集成时走完整路径。

缺哪一样，就先补哪一样，再采用这种做法。

## 派发前检查清单

- [ ] 共享物已冻结，有冻结提交号。
- [ ] 工作项表的每一项，写范围都精确到文件。
- [ ] 线的清单中任意两条线的写范围交集为空，已用脚本核对。
- [ ] 已画出波次表，已标出关键路径。
- [ ] 每条线的任务信息包都通过了自包含检查。
- [ ] 已写好集成节点的合入顺序和联调命令。
- [ ] 宿主的四样机制都已具备。
