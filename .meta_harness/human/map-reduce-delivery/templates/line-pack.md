# 线包模板

Reduce 从线父卡上本波 attempt 的 binding、已接受依据和当前波生成本包，发在线父卡上。Line 首次开工和恢复时读本包和线父卡。本包只保存本次事实与引用，不授予额外权限。协作规则归[集成清单](../../../../docs/engineering/integration.md#集成节点的清单)，线父分支与闭包门槛归[线父分支](../../../../docs/engineering/integration.md#线父分支)。线会话的工作方式归 `line` 技能的 `references/work-paradigm.md`。

每个占位都替换成实际值。不适用的项写原因。命令放在 `sh` 代码块里，派发前在本机同布局演练。只读本包和线父卡，Line 就能确定 F、写范围、本波要交什么、什么不做、事实来源、交回入口、等待命令和停止条件。缺一项时，reduce 先补齐再派发。

## 分工：Reduce 定什么，线定什么

Reduce 每波给线三样：本包、线父卡上本波的一个 attempt、首次消息或 delta。

- Reduce 在本包里定目标、边界与验收：本线里程碑要达到什么，本波交什么、用什么判据、明确不做什么、哪些设计点要 Reduce 批复、何时停止。理由：这些决定牵动别的线和整个里程碑。
- 线负责人定拆分与调度：怎样拆闭包、排顺序、派子代理、并行，以及线内的合并与联调。理由：离代码最近的人最清楚怎样切得干净。
- 本包不列闭包队列。附录的「建议闭包与依赖」只作参考，不建 Issue。默认本波只有线父卡上的一个 attempt。已有载体卡、或确有独立跟踪需要时，本波可以另有几张卡，第 1 节逐张列出，线负责人一次认领，只开一个集成 PR。理由：卡越多，中间的无效时间越多。

Reduce 写本包时，把力气花在第 2、3 节。边界写清楚，线才不会自行扩大范围或推迟交付。

### 3.5 停止条件

- 期限：<本波交回期限。到期时 reduce 核对事实，沉默保持 unknown>
- 成果与判据都达到时停止，交回 ready。核心保证守住后，剩余边角写成已知限制，不追加机制。
- 需要做 3.2 里的事，或需要越过本包的边界时，停止依赖部分，交回时写明。
- 缺必要的全局输入、授权或共享物修改时，暂停依赖部分，继续无依赖工作。没有工作可继续时，交回 blocked 或 failed，然后停写。零差异不造空 PR。
- 普通评论、超时和旧 attempt 都不授予返工。只有 redo delta 使本线同波重做。
- 只有明确的 terminal delta 结束本线。预案里没有后续任务不是终态。

## 6. 交回与等待

- 波末：本波的闭包都合入父分支后，父分支只跑一次准入，经一次 gate 合入线轨道。PR 的「所含的卡」列线父卡的 revision 与本波 attempt，再逐张列本波其他卡的 revision 与 attempt。顺序归 `integration.md`「线父分支」。
- 关注清单：执行中前台并行关注的事归 `line` 技能 `references/work-paradigm.md`「执行中前台并行关注的事」。
- 交回物：父分支进线轨道的 PR、提升 PR（零差异时都没有）、线父卡上本波的一份五节交接报告、线父卡上的一条交回记录。交回记录首行是 `<!-- line-handoff -->`。固定项归[线会话记录](../../../../docs/engineering/integration.md#线会话记录)。交回记录发布后，Line 停写。
- 遇阻：用同一个入口交回 blocked 或 failed，写清原因和已完成部分，然后停写。
- 无远端通路：<在本机保存交回记录的位置，及打开供人带回的办法。不声称已发布>
- 状态注：<`tmp/line-<线>/state.md` 的实际路径>
- 事件接收器：<本机事件文件、接收器拥有者、配置位置。不写频道地址。接收器健康不阻止开工>

交回与等待命令：

```sh
<发布交回记录的命令>
<等线父卡下一条 delta 的 wait-cli 命令，带 --timeout>
```

等待命令作为前台阻塞的工具调用运行。不加 `nohup`、`&`、`setsid` 或 `disown`，不用后台任务模式。超时（退出码 3）后，先读回一次本线父卡的 delta，没有未处理的就用同一 `--since` 立即重跑。等待失败（退出码 2）时，Line 在状态注写 unknown，等人转告。唯一的后台进程是本机事件接收器。
