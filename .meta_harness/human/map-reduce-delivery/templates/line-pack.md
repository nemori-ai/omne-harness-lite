# 线包模板

**用途：**派发者为一条线写的自包含输入。线会话只读本包和最新一条[线状态注](line-state.md)就能开工或接续。用法见[范式](../README.md#派发前)。

本包不依赖派发者会话的记忆，也不依赖任何一种 agent harness 的私有机制。复制本模板后，删掉尖括号里的说明，按本线的实际情况填写。不适用的项写「不适用」和理由，不要删掉。

本包分两部分：线级部分在一条线的生命周期内基本不变，卡级部分每张卡一份。

---

## 线级部分

### 1. 线与队列

| 项 | 内容 |
| --- | --- |
| 交付线 | <宿主登记的交付线 ID 与名称> |
| 线父卡 | <线父卡的链接。线会话认领它，`line-delta` 与 `line-state` 都发在它的评论里> |
| 领域 | <本线所有卡共享的领域。队列跨了领域，就拆成两条线> |
| 队列 | <按顺序列出本线的卡与所在波。标出依赖别的线的卡，以及它等待的产物> |
| 机器与重轻 | <本线在哪台机器的哪个位置，是重测试线还是轻线> |

### 2. 冻结物

| 项 | 内容 |
| --- | --- |
| 冻结头 | <提交号。本线所有卡的 taskBase> |
| 共享物清单 | <接口形状、不变量、依赖方向规则、公共值类型、锁文件、集成入口。本线只读，不改> |
| 本批不变量原文 | <逐条写出。宿主为不变量提供机读标识时一并写出> |
| 契约新增符号的归属 | <本线本波可以在哪些契约成员上新增符号。其他契约成员只读> |
| 契约基线 | <里程碑起点登记的契约基线位置。规则见宿主正文，在本仓库见[里程碑内的规则](../../../../docs/engineering/integration.md#里程碑内的规则)> |

### 3. 上下文地图

按「先读什么、读到哪里停」排序。每项精确到文件和行。

- 系统领域地图、协作图和顶层架构图的位置。
- 本线要读的拥有者正文。
- 本线最容易踩的耦合：本线的契约不能引用哪个相邻领域的内部类型，哪个外部概念不能进入本领域的契约。
- 相邻线的接口：它们提供什么，需要什么。不给相邻线的实现细节。

### 4. 已知事实与出处

每条事实一行。出处必须是冻结头上的文件和行，或者冻结头可读到的卡评论。没有核过的标「未核」，由线自己核。

| 事实 | 出处（冻结头上） | 状态 |
| --- | --- | --- |
| <事实> | <`路径:行` 或评论链接> | 已核 或 未核 |

### 5. 承重假设与信号

承重假设是一旦为假就会改变本线计划的假设。每条配一个可观察的信号。

| 假设 | 为假时的后果 | 信号（怎样观察到它为假） |
| --- | --- | --- |
| <假设> | <后果> | <信号> |

### 6. 写集与读集

| 项 | 内容 |
| --- | --- |
| 写集 | <从任务绑定生成的路径清单，不手抄> |
| 读集 | <写集内成员依赖的包的传递闭包，加上本包引用的正文页。从冻结头的依赖图取得> |
| 禁写清单 | <冻结的共享物、别的线的写范围、留给集成节点的文件> |
| 交叉检查结果 | <写写交集与读写交叉的检查命令及其结果> |

### 7. 测试名额与准入命令

| 项 | 内容 |
| --- | --- |
| 名额 | <所有测试与准入命令经哪个名额机制排队。同机的会话用同一个系统用户与同一把锁> |
| 自测命令 | <本线的自测命令> |
| 准入命令 | <宿主的准入命令。在本仓库，见[每一步的命令](../../../../docs/engineering/integration.md#每一步的命令)> |
| 替身与测试入口 | <允许使用的替身和测试入口> |

### 8. 状态注与增量

- 每张卡交回后，在线父卡发一条线状态注，格式见[线状态注模板](line-state.md)。
- 认领线父卡时记下起点评论号。在三个读取时点拉取 `<!-- line-delta -->` 评论，按序号去重，格式见 [line-delta 模板](line-delta.md)。
- 队列全部被阻塞时定时轮询，周期：<reduce 每卡服务时间的两倍，初值，按实测调整>。

### 9. 停止条件

线在下列情形暂停受影响的部分，继续不受影响的工作，并在交回报告中写明：

- 需要修改共享物，或修改写范围外的文件。
- 发现设计与不变量冲突。
- 验收标准互相矛盾，或者与拥有者正文矛盾。
- 需要相邻线的实现细节才能继续。
- 缺少产品规则、采用依据或必要权限。
- 必须做破坏性的契约改动。
- 评审修复轮超过 2 轮仍未闭合。

### 10. 交回期限与租约

- 交回期限：<日期或时长>。
- 租约：<2 倍中位线时长，初值>。以线分支的最后推送时间观测。租约过期，旧 attempt 作废。

## 卡级部分

每张卡一份。字段与宿主仓库的任务绑定机制一致。

| 项 | 内容 |
| --- | --- |
| 任务卡与修订 | <卡的链接、修订号、attempt> |
| 基线、分支、路线、完成目标 | <taskBase、分支名、路线、完成目标> |
| 写范围 | <本卡独占的路径，取自任务绑定> |
| 交付边界与验收标准 | <逐条列出，每条都能核对> |
| 已知未决项 | <哪些问题尚未裁定，本卡怎样避开它们> |
| 依赖 | <本卡依赖的已入轨产物及其在冻结头或最新 `line-delta` 中的位置> |
| 交回格式 | [交回报告模板](handoff-report.md) |

## 自包含检查

派发者找一个没有任何上下文的会话，只给它本包，然后问四个问题。四个问题都答得出，本包才合格。

1. 从哪个提交开工？
2. 能改哪些文件？
3. 做到什么程度算完成？
4. 包里的每条事实出处在哪里？
