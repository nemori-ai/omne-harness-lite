# 交接报告模板

**用途：**线会话交回一张卡的候选时，随候选发在卡评论里的报告。集成节点只读候选和这份报告，不读线的工作过程。用法见[范式](../README.md#线内)。

本仓库交回报告固定五节，与 `claim` 的[任务信息包](../../../agents/skills/claim/canonical/references/task-pack.md)一致。第五节逐轮保存评审、修复、复验、返工原因和证据。无评审或返工时明确说明，不编造记录。ready/blocked/failed 都使用本报告。已有差异给 PR/head，零差异允许无 PR。

报告只陈述事实。「达到」是线对照验收标准的自查结果，不是接受。线不给自己的交付判定通过，接受归有资格的负责人。

复制下面的代码块作为评论正文。整线本波交完后，线父卡上的交回记录另按[线会话记录](../../../../docs/engineering/integration.md#线会话记录)发布。

```markdown
## 交接报告

- 卡：<卡、修订、当前 attempt>
- 候选：<PR 链接与 head 提交号>
- taskBase：<提交号>
- 结果：<ready、blocked 或 failed>
- 停写：<本线交回记录发布后停写。未发布时写明原因>

### 1. 做了什么

<把 `plan.md` 进度总览的最终状态原样贴在这里：进度条一行、当前一行、切片表>

| 验收项 | 达到或未达到 | 证据 |
| --- | --- | --- |
| <验收项> | <结果> | <命令与退出码、输出尾部或摘要、文件与行、或链接。判据要求的证据贴在本评论里，原件太大时贴摘要和关键行，并写明原件位置与哈希> |

### 2. 没做什么

- <每个未达到的项缺什么，线为什么停下>

### 3. 发现的冲突

- <与共享物、与不变量、与相邻线接口的冲突。写明文件和行>
- <包内事实与冻结头不一致的地方>

### 4. 给集成节点的提示

- <合入时要注意的顺序、依赖和已知的脆弱点>
- <本卡的产物被哪条线引用>

### 5. 评审闭合

- 评审：<评审子代理的类别，每次评审报告的全文或链接>
- 修复轮：<轮数。每轮一行：结论、修了什么、复验命令/结果/候选 head，返工原因（规格、分解、过时输入、评审发现、环境、不稳定测试之一）>
- 未闭合的发现：<无，或逐条列出并说明理由>
- 准入：<在线内推进时写「全量准入留给集成节点」。自己跑了准入时写在哪个提交上运行、命令、退出码、日志尾部或摘要与关键行、日志的位置与哈希。只写任务 tmp 中的位置时，接受者不据它判断，规则见[提交成果供接受](../../../../docs/engineering/agent-delivery.md#5-提交成果供接受)>
```
