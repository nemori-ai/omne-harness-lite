# 综合：交付做法的原则、分解规则与度量

**状态：调研综合。**本文是 [Map-Reduce 式交付推进](../README.md) 的推导材料，不是规则。它把五篇调研合成原则与来源对照、做法与依据、代码分解规则、度量账本和跨里程碑对比协议。标「待核」的结论来自调研中标「未核」的条目，采用前要复核。本文的数值都是初值，按实测调整。宿主有权规定的事以宿主规则为准，本文列出的做法落在范式的主线或「本包建议」一节，见下文「落点」一栏。

## 原则与来源对照

| 编号 | 原则 | 来源 |
| --- | --- | --- |
| P1 | 智能并行，写入单线程。每个写范围同一时刻只有一个写者。并行的是阅读、评审和候选 | [实践 §0、§1][PM §4] |
| P2 | 零通信把大部分协调成本挪到 reduce，另一部分落在人的裁决上。reduce 串行量约为 `n·S̄`（`n` 是本波卡数），随卡数线性增长，每波卡数的上限约为 `ρ·L_max/S̄` | [PM §4 Brooks 行][调度 §1.2、§6.2] |
| P3 | 结构层可算，语义层算不全。写集、读集、依赖边和契约型变能在派发前机器判定。合并后的行为只能靠测试与人兜底 | [分解 结论先行、§4] |
| P4 | 写集不交不等于可串行化。A 线读了 B 线要改的东西，两边都能过准入，合起来会坏，这是 write skew，范式称为读写交叉。派发前要声明读集。过时输入是另一类错误，靠事实出处核对来防 | [调度 §3.1][分解 §3 对应表、§6 3.2] |
| P5 | 里程碑首波就走 walking skeleton，用最薄的端到端切片在 reduce 走通一次 | [PM §1、§4 Walking skeleton 行、§5.1] |
| P6 | 契约基线在里程碑起点确定。波的收口不重建契约基线。经有权者批准的破坏性改动，按宿主规则补登记受影响成员的基线 | [调度 §3.3][分解 §3 对应表、§4][PM §2 取舍] |
| P7 | 追求约束的利用率，不追求线的利用率。约束是集成节点所在机器和人的注意力。agent 空闲几乎不花钱 | [PM §3 TOC 行、§4][调度 §2.3] |
| P8 | 验证左移到线。线交回时已评审闭合、已在冻结头上跑过准入，集成节点的准入成为复核 | [实践 §4、§6 #1][调度 §5.2][PM §5.3] |
| P9 | 派发用的事实只从冻结头读，线包里每条事实写明出处。写范围只从任务绑定生成 | [实践 §2 陈旧与冲突的处理、§6 #4、#5][PM §5.2 DoR 行][调度 §3.1] |
| P10 | 小样本用效应量和控制图判断，不做显著性检验。判断前先登记假设 | [度量 一句话结论、§1.1、§2] |

P9 的推导：冻结头相当于快照，线读到的一切都应当来自同一快照，否则就是读了另一个时刻的数据 [调度 §3.1]。实践中线包会陈旧，可行的做法是包里只放指针与提交号，开工时用当前头校验 [实践 §2、§6 #5]，派发时机器核对输入基线 [PM §5.2]。写范围从任务绑定生成，对应把自包含判据做成可机检的派发条件 [实践 §6 #4]。

P10 的一个例子：METR 的 RCT 里，开发者用 AI 实测慢 19%，自评却快 20% [度量 §1.1]。

## 做法与依据

「落点」一栏写这项做法在范式页的位置。「主线」表示它不与宿主规则冲突，直接写在范式的流程里。「建议 Bx」表示它在范式的「本包建议」一节，宿主采用前不生效。

| 阶段 | 做法 | 依据 | 落点 |
| --- | --- | --- | --- |
| 派发前 | 写范围从任务绑定生成。另声明读集：写范围内成员依赖的包的传递闭包，加上包里引用的正文页。检查同波两两满足 `WS(a) ∩ RS(b) = ∅` | [调度 §3.1][分解 §6 3.2] | 主线 |
| 派发前 | 在冻结头的依赖图上做 DSM 分区，即把依赖图的强连通分量收缩成块，再拓扑排序。同一块不拆给两条线。跨线依赖边只能指向冻结的契约成员 | [PM §2 DSM 行][分解 §2、§6 1.1、5.2] | 主线 |
| 派发前 | 自包含检查加一问：包里每条已知事实在冻结头上的出处。没有出处的标「未核」，由线自己核 | P9 | 主线 |
| 派发前 | 冻结契约新增的命名空间：每个契约成员本波只归一条线新增符号。合并前对各线快照的新增集求交 | [分解 §3 对应表、§6 4.2] | 主线 |
| 派发前 | 里程碑开工前冻结假设表、方案版本表与工期预测。每条线写出承重假设，各配一个可观察的信号 | [度量 §3、§6.3][PM §1 ABP 行、§5.1] | 主线 |
| 线内 | 线内自评审：开 PR 后派新上下文的评审子代理，只报正确性与需求缺口，修复轮上限 2 轮，超过就停下报告 | [实践 §4、§6 #3][PM §5.3] | 主线 |
| 线内 | 线内自准入：在冻结头上经测试名额跑宿主准入，交回时附通过日志 | [调度 §5.2][实践 §6 #1] | 主线 |
| 线内 | 全部测试与准入经机器级名额排队 | [实践 §6 #6] | 主线 |
| 线内 | 同机一重一轻，每台机器至多一条重测试线 | [调度 §1.1 CPOP、Graham 异常] | 主线 |
| 线内 | 线协调者每张卡派新上下文的工作子代理。修复第 2 轮换新子代理。每张卡交回后与每次压缩前写状态注 | [实践 §2 原则与「陈旧与冲突的处理」] | 主线（线级记录本身是建议 B8） |
| 交回 | 交接报告加第五节「评审闭合」，每轮修复记一条返工原因 | [度量 §6.3] | 建议 B7 |
| reduce | 按交回先后处理，只受「被引用的先合」约束。几张卡同时就绪时，失败概率高或影响面大的先合 | [调度 §1.3、§3.2] | 建议 B1 |
| reduce | 拆成同步、准入、gate、接受记录四段，每段记起止时刻。目标每卡 ≤ 20 分钟。准入占大头，流水线化的收益上限约 1.25 倍，主要杠杆是缩短准入时长和降低准入次数 | [调度 §5.1] | 主线 |
| reduce | 「已交回、未接受」的卡数 `Q ≤ 4`，reduce 利用率 `ρ = λ·S̄ ≤ 0.75`。每波卡数 `n ≤ ρ·L_max/S̄`，按上一波实测值算 | [调度 §6.2][PM §3 Kingman、Kanban 行] | 主线 |
| reduce | backpressure：`Q` 超限时调度者不补空座位，直到队列回落 | [调度 §2.3][PM §5.3] | 主线 |
| reduce | 每次同步之后、准入之前，一律重生成派生物。线会话换到新 taskBase 时也一样 | 同步会带进别人对派生物源文件的改动，使派生物过期 | 主线 |
| reduce | 批量合并只在线内准入后 reduce 侧准入失败率 `p ≤ 0.05` 时开启，批大小 2–3，失败就二分剔除 | [调度 §5.2][实践 §3] | 建议 B3 |
| reduce | 冲突按四类记账。共享登记文件上的冲突单列为基础设施冲突，改用生成器产出 | [分解 §6 3.1] | 建议 B2 |
| reduce | 准入不通过时，调度者登记同一修订的新 attempt，评审报告写进派发记录作输入，派到任一座位 | [调度 §4 幂等行] | 建议 B4 |
| 波的收口 | 本波收口提交成为下一波的冻结头。契约基线不重建 | P6 | 主线 |
| 波的收口 | 骨架常驻：每波 reduce 末尾跑一次薄场景。已交付的跳用真实实现，其余用替身。替身跳数应逐波减少 | [PM §1] | 主线 |
| 波的收口 | 下一波的输入经线父卡评论 `line-delta` 送达，线会话在读取时点自己取 | [实践 §2] 的 just-in-time retrieval | 建议 B8 |
| 破坏性改动 | 线内只做兼容开发，破坏性改动在 reduce 由一张卡一次完成 | [调度 §2.3、§3.3] | 建议 B6 |
| 失联 | 租约以被动观测的信号为心跳，attempt 号作 fencing token。只在宿主提供可靠信号与原子认领时可参考 | [调度 §2.2、§4] | 建议 B5 |

## 代码分解规则

### 写范围从目录改成 DSM 分区加读集

1. 在冻结头上取依赖图。依赖图可以由依赖检查工具导出，例如 dependency-cruiser。
2. 写集取任务绑定的写范围，两两求交，有交集就不派发。
3. 读集取写集内成员的工作区依赖的传递闭包，加上任务包引用的正文页。检查 `WS ∩ RS`。
4. 同一强连通分量的成员归一条线。共享登记文件（barrel、包清单、锁文件、文档登记表）列为共享路径，由生成器产出或留给集成节点修改 [分解 §3 对应表]。
5. 切片大小以「只依赖冻结基线就能独立通过自己的 gate」为判据 [分解 §5]。

### 可加性的机器判定边界

对象是契约成员的 API 快照，累计对里程碑起点的契约基线比较。可加与破坏的规则正文归宿主。在本仓库，见[可加改动](../../../../docs/engineering/integration.md#可加改动)。下表只说明哪些判定能交给机器。

| 改动 | 判定 | 谁判 |
| --- | --- | --- |
| 新增导出、新增类型、新增可选输入字段、新增输出字段 | 可加 | 机器：快照差异只有新增 |
| 函数参数类型放宽 | 可加 | 机器。TypeScript 的方法签名参数是双变，要另行检查 |
| 返回值类型收窄 | 可加 | 机器 |
| 删导出、加必填输入字段、输入收窄、输出放宽 | 破坏，拒绝 | 机器 |
| 输出位置的枚举或判别联合加成员 | 按政策交人。消费方的穷尽 `switch` 会坏 | 人，机器只负责标出 |
| 签名不变、行为改变（默认值、错误语义、顺序、时序） | 机器判不了 | 人加行为测试 |
| 同一波两条线新增同名符号 | 碰撞，拒绝 | 机器：对快照新增集求交 |
| 快照没有覆盖的再导出与包导出字段 | 盲区 | 机器补覆盖 |

依据：[分解 §4 可判定边界表、§6 4.1–4.3]。

### 冲突四分类与分解错误的定义

分解错误：派发时的分解（写集、读集、冻结集、包内事实）本可在派发前发现，却在交回后才暴露的问题。按两个维度记账。

| 现象类 | 判定 | 算分解错误吗 |
| --- | --- | --- |
| 基础设施冲突 | 文本冲突落在共享登记文件上 | 不算。计入共享名单的缺漏 |
| build 冲突 | 合并后类型检查或构建失败，各线单独都通过 | 算 |
| test 冲突 | 合并后测试失败，各线单独都通过 | 算 |
| 语义潜伏 | 端到端场景或后续卡才暴露 | 算 |

| 原因类 | 机器能否在派发前拦下 |
| --- | --- |
| 越界：改了写范围外的文件 | 能。准入核写范围 |
| 读写交叉：A 读 B 写 | 能，有了读集检查之后 |
| 过时输入：包内事实不是冻结头上的事实 | 部分能。出处检查能拦，内容错误不能 |
| 漏冻结：共享物没进冻结集 | 部分能。DSM 跨线边检查能拦 |

依据：[分解 §6 3.1、3.2][调度 §6.3]。核心比值是「派发前拦下数 ÷ 交回后发现数」。

## 度量账本

交付账本是三张派生表：卡级、波级、里程碑级。一个版本化的脚本从原始事件派生它们。定义改了就对历史重算 [度量 §3]。字段取自 [度量 §6.1、§6.3]、[调度 §0、§6.3]、[实践 §6 #8] 与 [PM §5]。

本节的 `p` 指 reduce 侧单次准入失败率 [调度 §0]。首次通过率指 reduce 侧准入只跑一次且通过的卡数 ÷ 卡数。

粒度约束：看板的日期字段若是天粒度，就算不出 reduce 分钟级的服务时间。分钟级时刻取事件时间（派发评论、PR 创建、gate 运行、接受评论）和准入日志。机器级测试账本若不记卡号，要先收齐各台机器的账本，再按时间段与工作树对卡。

「门」指二值判定，不过就不合入。「观察」只进报告，不设目标 [度量 §4]。

### 卡级

每张卡一行，attempt 数作字段。

| 字段 | 来源 | 计算 | 门或观察 |
| --- | --- | --- | --- |
| card、attempts、line、kind、wave、milestone | 卡、看板、任务绑定 | 原值 | 维度 |
| plan_version、change_ids | 派发记录 | 派发时的方案版本 | 维度 |
| t_dispatch、t_deliver、t_integrating、t_accept | 派发记录、PR 创建或交回记录、gate 运行开始、接受记录 | 事件时间 | 原始事实 |
| cycle_days | 看板 | 接受日减派发日 | 观察 |
| t_in_line | 同上 | t_deliver − t_dispatch（小时） | 观察 |
| t_in_reduce | 同上 | t_accept − t_deliver（小时）。再拆成排队 W = t_sync − t_deliver 与服务 S | 观察 |
| t_sync | 集成节点开始同步时留下的机读记录 | 事件时间。同步不留记录就是工具缺口 | 原始事实 |
| S_sync、S_admit、S_gate、S_accept | 集成节点打点、准入日志、gate 运行 | 各段起止之差（分钟） | 观察 |
| a、admit_fail | 准入日志、测试账本 | 准入运行次数；失败次数 | 观察 |
| first_pass | 同上 | reduce 侧 a = 1 且通过 | 观察 |
| map_admission_evidence | 交回记录 | 附了准入通过日志为真 | 门（交回格式） |
| map_fix_rounds、reduce_fix_rounds | 交回记录、派发记录 | 计数 | 观察 |
| rework_cause[] | 每轮修复一条 | 取值：spec、decomposition、stale_input、review_finding、env、flaky | 观察 |
| findings_by_severity、review_density | 评审报告、PR 差异 | 每千行改动的发现数，分阻断与非阻断 | 观察 |
| decomp_errors[] | 集成节点记录 | 每条带现象类、原因类、detected_at ∈ {pre_dispatch, post_delivery} | 观察 |
| decision_requested_at、decided_at | 卡评论的机读标记 | 等待 = 两者之差；占周期的比例 | 观察 |
| tokens_in/out、cost_usd，按角色（工作子代理、评审、协调层、reduce） | 会话用量导出 | 求和 | 观察 |
| session_restarts | 线状态注 | 线会话被替换的次数 | 观察 |
| named_exceptions | 接受记录 | 具名例外的次数 | 观察 |
| contract_change 申报值与实测值 | PR 的契约变化申报、API 快照累计核对 | 申报低于实测即违规 | 门（宿主规则要求时） |
| 宿主检查结果 | 宿主的检查命令 | 宿主现有硬线 | 门 |

线级另记 coordinator_tokens（协调层 token）。预期工作子代理每卡的 token 不随队列位置上升。反向信号：队列后段卡的过时输入类分解错误上升，说明 `line-delta` 没有把状态带够。

### 波级

| 字段 | 来源 | 计算 | 门或观察 |
| --- | --- | --- | --- |
| n、P | 本波卡数；座位数 | 原值 | 维度 |

## 跨里程碑对比协议

### 事前假设登记

每个里程碑开工前（第一张卡派发前）冻结假设表，提交号或评论链接写进里程碑记录（宿主的里程碑或基线记录）。每条假设一行，字段为 id、change_id、指标与方向、预期幅度、对照、反向信号。模板见 [hypotheses.md](../templates/hypotheses.md)。依据：[度量 §3、§6.2] 第 3 条；[PM §1 ABP 行]。

### 方案版本化

方案版本表一行一项调整，字段为 `plan_version, change_id, effective_date, scope, metric, expected_direction, rationale, source`。每个里程碑取一个方案版本代号。里程碑中途改方案时升小版本，记为共干预。每张卡挂派发时的 `plan_version`。作用范围之外的卡自动成为该调整的对照组 [度量 §3]。模板见 [plan-changes.md](../templates/plan-changes.md)。

### 分析方法

1. 卡级连续序列：把相邻几个里程碑的卡按 t_accept 排成一条序列，画 XmR 图，在 plan_version 切换处分段。适用指标是 cycle_days、t_in_reduce、fix_rounds。限值常数 2.66、3.268 与信号规则待核。波级每个里程碑只有几个点，不画控制图，只描述。
2. 两个里程碑比较：报中位数差、P85、Vargha-Delaney Â12（或 Cliff's δ = 2Â12 − 1），附 bootstrap 95% 区间（对卡重抽样 2000 次，初值）。不报 p 值 [度量 §2]。
3. 判定：三条同时满足才判「改善」或「回归」：XmR 出现信号；Â12 区间不含 0.5；方向与事前假设一致。只满足一两条记「迹象」，下个里程碑继续看 [度量 §2] 小样本纪律第 1–2 条。
4. 对照序列：只对作用范围有限的调整成立。作用于全部卡的调整（例如会话拓扑变更、评审位置变更）在里程碑内部没有对照组，只能与上一里程碑做前后比较，不做 DiD。只影响部分线的调整（例如读集检查），可以用未受影响的线做描述性 DiD [度量 §2 DiD 行]。

### 报告骨架

骨架见 [milestone-report.md](../templates/milestone-report.md)。它综合了 [度量 §6.2] 的九节与改善、回归、无变化、迹象四张表。

### 说明边界

- 每个里程碑只有十几张卡。Â12 区间会很宽，预期多数结论落在「迹象」。
- 同一指标上有多项调整时，结论只能归到这组调整整体。
- 两个里程碑的工作类型不同（例如一个允许破坏性改动，另一个只许可加改动），属于构念效度的威胁，报告必须写明。
- 回填字段缺失就标缺失，不估填 [度量 §6.3]。
