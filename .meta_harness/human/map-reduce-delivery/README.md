# Map-Reduce 式交付推进

本页是给人的学习与使用地图，不授予执行、接受或发布权限。当前工程责任归[集成清单](../../../docs/engineering/integration.md#集成节点的清单)，精确状态和恢复归[负责人状态](../../../docs/engineering/map-reduce-states.md)，命令和编码归[dev-flow](../../../tools/dev-flow/src/delivery/README.md)。技能把规则变成阶段动作；模板只保存本次输入和证据。

## 术语

Reduce 是同一里程碑的唯一持续协调与集成会话，也是人唯一的设计联系点。Line 是在同一会话跨波持续的一条线的负责人，按正式决定工作或轮空。它负责的范围可以覆盖一个或几个领域。内部 map 节点只承担本次节点，不是常驻线。线父卡承载线包、delta 与交回记录。R(w) 是当前正式收口，F 是实际读回的冻结基线。

## 先判断这批工作是否适用

适用于已接受输入明确、跨线写集可分离、跨线依赖能经冻结基线承接的工作。不能把未定全局设计、权限缺口或隐含消费者迁移交给 Line 波中来问。拆不出独立责任时，先在 reduce 完成分解。

## 思维模型

### Map-Reduce 的形状

当前正式波从 F 向各 active Line 派输入；Line 自主执行并交 ready/blocked/failed；reduce 持续收件，单写集成并验证整体，准备下一输入后放行。常驻线逐个 reduce 续接，idle 也在等待链中。

### 递归的分形结构

Reduce 与 Line 是相对的角色。一个线会话对上一级 Reduce 是 Line；它在线内也可以再做一次 map-reduce，对自己派出的常驻下级线担任 Reduce。每一层的形状都一样：冻结输入、并行执行、交回、集成、放行。对上一级，这条线仍只在开工与交回两个边界协调；人仍只与最上一级的 Reduce 讨论设计。这是负责人认可的方向，嵌套的具体做法还没有设计，设计之前线会话不设常驻下级线。待设计的问题见[负责人状态的术语](../../../docs/engineering/map-reduce-states.md#术语)。

### 协调成本大多挪到 reduce

Reduce 负责全局设计、跨线的消费者迁移与实现、跨线联调、冲突及交出后的问题。线内跨领域的集成与联调归 Line，交回的批次在线内已经接通。Line 波中不与人或其他线讨论方案，不通过普通评论向 reduce 求方案。常规集成失败由 reduce 处置，不能回到旧 line-return 修复循环。

### 约束是集成节点所在机器与人的注意力

轨道变更单写，但接收和监督不中断。处理 A 时 B 和其他信号持久落盘。审批、权限和人类决定不因工具自动化扩大。

### 结构层可算，语义层算不全

写范围求交、序号、摘要和 schema 校验提供结构事实。是否履约、可接受、具有授权仍由相应拥有者判断。绿测或文件存在不授予接受。

### 写集不交不等于可串行化

跨域语义、消费者、共享状态和外部副作用仍需要明确责任。Reduce 核对公开契约与输入基线，不能只按目录分工。

## 十条原则

1. 每个里程碑只有一个 reduce 会话对接人，外部 Line 跨波保留会话。
2. Line 只有开工读取输入、结束执行交结果两个协调边界。
3. 波内输入冻结，本线可决事项自主决定，不消费新评论/设计。
4. 硬阻塞提前结束，交 blocked/failed 并停写，零差异不造空 PR。
5. 交回、实际合入和整波放行分别读回。
6. 交回后问题归 reduce；同波 redo 必须先更正输入并登记新 attempt。
7. 正式当前一波、预规划后一波，远期路线图不授予开工。
8. 后继卡及全部存续线 delta 先于关闭本波收口卡，关闭收口卡即放行。
9. idle 逐个收口继续等待；只有明确 terminal 才结束。
10. 未知副作用先恢复，未观测的机器或宿主行为保持未验证。

## 三种角色与会话

| 职责 | 承担者与边界 |
| --- | --- |
| 目标、必要授权与具名接受 | 人通过唯一 reduce 会话作实际需要的决定 |
| 全局协调、迁移和集成 | 同一里程碑同一个 reduce；提问先过必要性、复杂度、自主可决策性三问 |
| 本线本波执行 | 常驻 Line 读完整输入后自主细化、实施、线内集成与联调和验证，结果交出后停写 |

### 线会话内部：连贯归协调层，新鲜归工作层

Line 保存当前授权、冻结输入、已消费 delta 和未完成操作。恢复读线父卡上最后一条 delta 与自己最后一条交回记录，不能从会话记忆重建成功。子任务按本次授权分派，内部节点不跨波持有线责任。实施、独立评审、QA 和有权接受分别记录。

## 流程

### 派发前

Reduce 为每条参加线在线父卡上登记本波的一个 attempt，并在线包里写已接受依据、本线里程碑的目标与验收、本波的交付边界、写集、局部裁量和期限。不为线建工作卡。线父卡保存线包、delta、交回、每波的交接报告与长期责任。开波先把 F 同步到线轨道，保存 FI 结果与固定同步点。线负责人从同步后的线轨道头建本波的线父分支，在它的工作树上对本波的 attempt 运行 `start`。后一波只保留预案。线包足以使新 Line 独立判断入口、可写范围、完成条件、两个边界和失败出口。

每线首次从[初始消息模板](templates/line-initial-dispatch.md)生成临时文件，路径为 `tmp/milestone-<id>/dispatch/<line>-r<revision>.md`。Reduce 在本机同布局演练消息里的每条命令，演练证据交给校验。正文第一段先列 `line`、`pstack:poteto-mode`、`asd-ste100`，以及实际工作树的 `AGENTS.md`、`docs/orientation.md`、线级上下文地图和拥有者入口。校验后，已授权本机协作的 Reduce 经 mirasim 创建或定位线会话，直接发送并读回，分别记录发送、收到与认领。没有直接通信授权或能力时，才打开供人原样转发。后续波用 delta，不新建 Line 会话。

### 线内

首次与恢复读 `line` 技能及状态正文。Reduce 每波给线三样：线包、线父卡上本波的一个 attempt、首次消息或 delta。Reduce 定目标、边界与验收，线负责人定怎样拆闭包与调度。开工时线负责人核对 binding 与线轨道实际同步点，建父分支并在它的工作树上运行 `start`。闭包达到门槛后合入父分支，不跑准入，不开 PR。本波的闭包都合入后，父分支只跑一次准入，经一次 gate 进入线轨道，规则见[线父分支](../../../docs/engineering/integration.md#线父分支)。本波另有几张卡时，线负责人一次认领，只开一个集成 PR。全机准入一次一个，由 `scripts/with-test-slot.mjs` 的运行名额排队保证；准入命令自动排队，不需要人工互斥。名额的覆盖缺口由 L-ENG 核实。整波验证归 Reduce。波内自主推进，必要缺口先停止依赖部分。

使用五节[交接报告](templates/handoff-report.md)：做了什么、没做什么、发现的冲突、给集成节点的提示、评审闭合。第五节逐轮列结论、修复、复验、返工原因与证据；无评审或返工时明确说明。父分支合入线轨道后，Line 开提升 PR（零差异时没有 PR），在线父卡发一条交回记录，然后停写，用一条等待命令等下一条 delta。无工作可继续时，Line 用同一个入口交 blocked 或 failed。

### reduce

Reduce 用 `wait-cli` 盯提升 PR 就绪与各线父卡的交回记录。一次接管一个提升 PR，在隔离候选上承担交回后的全部迁移和集成修复。同一轨道同时只有一个写者，其他信号保留积压，不以空队列认定完成。

Line 交 blocked 或 failed 后，reduce 有两种处置：发一条 redo delta，或接管剩余工作。redo 先更正输入并登记新 attempt。普通评论不是 redo。处置不需要另写记录。

### 波收口

验证成果、调整预案、创建并读回后继任务及收口卡 R(w+1)、为每条存续线发布 delta、按收口卡自身的交付条件接受并读回、关闭本波收口卡。关闭收口卡是放行动作。只看到关闭事件不等于放行。任一存续线缺 delta 或未知状态都阻止放行。同一次收口的所有 delta 引用同一个最终 F。

## 增量协议

[Delta](templates/line-delta.md) 给出原候选到最终候选改动与原因、外域变化、迁移、最终 F、下一任务与验收，以及 Line 下一步等待的对象。首行标记 `<!-- line-delta -->`。Line 的交回记录首行标记 `<!-- line-handoff -->`。两种记录是人读评论，固定项归[集成清单](../../../docs/engineering/integration.md#线会话记录)。

Line 只在允许边界按发布顺序读 delta。交回或接受不触发新输入。active 核对最终 F 的 FI 结果，从同步后的线轨道头建本波线父分支，闭包分支从父分支开出；idle 继续等待；redo 按新 attempt 同波重做；明确 terminal 交最终报告。空任务、预案无后续都不等于终态。恢复逐条补读漏过的 delta，不跳波。

工具、技能和策略固定版本整体采用。跨机运行显式目标 repo 与本机事件文件。等待命令失败时，Line 记录状态并等人转告。

## 按情形处理失败

输入缺口先自主查证，缺全局决定则交 blocked 或 failed 并停写。集成错误由 reduce 处理。reduce 接管后 Line 继续等待下一条 delta；redo delta 才使 Line 同波按新 attempt 重做。网络未知、写权冲突、日志损坏和工具结果丢失时，先保存操作与目标，读回实际结果再决定。明确停止保存结果，停止不能冒充完成。

## 度量与对比

度量回答一个问题：这次的方案调整让哪些指标改善了，哪些回归了。每个字段先分清它是「门」还是「观察」。门是二值判定，不过就不合入。观察只进报告，不设目标。观察指标设成目标，就会被博弈。

账本是三张派生表：卡级、波级、里程碑级。一个版本化的脚本从原始事件派生它们。指标定义改了，就对历史重算。全部字段、来源与计算见 [research/synthesis.md](research/synthesis.md#度量账本)。

| 粒度 | 主要字段 | 门 | 观察 |
| --- | --- | --- | --- |
| 卡 | 派发、交回、进入集成、接受四个时刻。线内时长。reduce 排队与四段服务时长。准入次数与失败次数。线内与 reduce 侧修复轮数。每轮修复的返工原因。评审发现密度。分解错误（现象类、原因类、发现时点）。人裁决的请求与决定时刻。按角色的 token 与成本。线会话被替换的次数 | 宿主现有的检查。交回附准入日志。契约变化的申报值不低于实测值 | 其余全部字段 |
| 波 | 卡数、座位数。冻结时长与波时长。线时长的最大、中位、最小值。reduce 占比。到达率、排队时长、队列长度。队列超限次数。空座位时间。骨架真实跳数比。派发前拦下与交回后发现的分解错误之比。重派次数。承重假设信号的触发次数 | 无 | 全部 |
| 里程碑 | 方案版本与共干预。周期、线内时长、reduce 时长的中位数与 P85。reduce 侧准入失败率。首次通过率。修复轮分布与返工原因占比。人裁决等待。每张接受卡的成本。首次端到端通过的时刻比例。最后一波才发现的集成缺陷比例。工期预测的命中百分位 | 无 | 全部 |

观察指标成对来读：吞吐对返工率，周期对评审发现密度，成本对首次通过率。

调度者用队列控制派发节奏：「已交回、未接受」的卡数 `Q ≤ 4`，reduce 利用率 `ρ = λ·S̄ ≤ 0.75`，其中 `λ` 是交回到达率。`Q` 超限时调度者不补空座位，直到队列回落。这就是 backpressure。零通信下集成节点不能叫线放慢，只能由调度者少派。

### 跨里程碑对比协议

1. 第一张卡派发前，冻结[事前假设表](templates/hypotheses.md)。每条假设写明对应的方案调整、指标与方向、预期幅度、对照和反向信号。
2. 每项方案调整在[方案版本表](templates/plan-changes.md)登记一行。每张卡挂派发时的方案版本。里程碑中途改方案就升小版本，记为共干预。作用范围之外的卡自动成为该调整的对照组。
3. 把卡级连续指标按接受时刻排成一条跨里程碑的序列，画 XmR 图，在方案版本切换处分段。限值常数取 2.66 与 3.268，这两个常数与信号规则都待核，采用前对照 Wheeler 原书。
4. 在两个里程碑之间报中位数差、P85 和 Vargha-Delaney Â12，附 bootstrap 95% 区间，不报 p 值。波级每个里程碑只有几个点，只描述，不画控制图。
5. 三条同时满足才判「改善」或「回归」：XmR 出现信号，Â12 区间不含 0.5，方向与事前假设一致。只满足一两条记为「迹象」，下个里程碑继续看。
6. 按[里程碑报告模板](templates/milestone-report.md)写报告。

说明边界：

- 每个里程碑只有十几张卡，Â12 区间会很宽。预期多数结论落在「迹象」。
- 同一指标上有多项调整时，结论只能归到这组调整整体。
- 两个里程碑的工作类型不同（例如一个允许破坏性改动，另一个只许可加改动），属于构念效度的威胁，报告必须写明。
- 回填不出的字段标缺失，不估填。

## 本包建议、宿主采用前不生效的做法

研究材料保留在 [research](research/README.md)。其调度、度量或分解建议只有宿主明确采用才生效，不能覆盖当前工程规则、权限与状态语义。历史研究不继续授权旧触发。

## 行为边界

协作工具不做宿主消息注入、不扩大审批权、不自动修改个人全局模型配置。requested model 与 observed model 分别记录，宿主不暴露观测值时为 unknown。双宿主配置存在不表示实际加载或续接验证完成。

## 宿主仓库要提供的机制

固定工具/协议/技能/策略版本，明确 repo、事件文件、独立接收器拥有者、持久 journal 与原 shell 结果续接。Codex 和 Claude Code 均有角色默认配置；只有完成各宿主实际验证才声明已加载。Cursor 保留既有投影，新增运行保证按证据说明。

## 派发前检查清单

- 真实 binding、F、目标与非目标、写集与局部裁量完整，自包含输入可读。
- 当前正式 R 存在，active 与 idle 明确，后继 unknown 与 terminal 分开。
- 两个边界、blocked 与 failed 交回、同波 redo 与恢复步骤完整。
- 模型策略两宿主配置与当前宿主解析有版本及证据。
- 首次消息的生成、演练、校验与通信分别有事实；直接通信记录发送、收到、认领，人工回退记录打开与转发。未发生不虚报。
- 当前交付与全部存续线 delta 名单和期限齐备。
