# @omne-harness/benchmarks

## 总体架构

benchmarks 放性能评测的套件。一个套件问被测对象一件事：给出代价模型、负载、场景、门与对照。判定、运行环境记录、结果与报告归设施 [`tools/perf-harness`](../tools/perf-harness/SPEC.md)；本成员只带来「问的是什么」。本成员不发布。

入口是根脚本 `pnpm run perf`（`src/cli.ts`）。`run` 与 `compare` 会排进整机的运行名额再跑。

## 领域边界

本成员拥有：套件的清单、每个套件的代价模型与门的期望值、负载与样本的生成、驱动被测对象的办法、计数基线（`baselines/`）。

本成员不拥有：

- 判定与可比性：归设施。
- 读数怎样数：归 [`packages/storage/SPEC.md`](../packages/storage/SPEC.md) 的「读数」与[服务端应用规格](../apps/harness-server/SPEC.md)的「实验装配」。

## 口径

- 一步：Agent 的一次模型请求。从这次请求到达出站的边算起，到下一次请求到达为止；一轮的最后一步到这一轮的终结条目写下为止。一步里有这一次模型结果的写入、它带出的工具调用与结果的写入、下一次请求的构造。实验装配在每次请求到达时写一行 `lab-step`，相邻两行的读数相减就是一步的读写量。
- 一次存储读、一次提交：见[存储的规格](../packages/storage/SPEC.md#读数)。

## 原则与约束

- 评测不改变被测对象：读数由产品自己给，场景经实验装配与命令行客户端这两个公开入口驱动。本成员不导入产品成员的源码，也不从产品的测试目录导入。
- 评测只在自己起的实例上产生负载。
- 评测不进准入。
