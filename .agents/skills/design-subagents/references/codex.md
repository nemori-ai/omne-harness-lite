# Codex：原生定义与运行面

核对日期：2026-09-12。以下是当前[官方 custom agents 规范](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)的适配说明；生成前检查目标 CLI 版本与文档是否仍匹配。

## 原生文件

项目定义位于 `.codex/agents/<name>.toml`，个人定义位于 `~/.codex/agents/`。
每个文件定义一个角色；`name` 决定身份，文件名保持同名便于定位。

| 字段 | 本技能如何使用 |
|---|---|
| `name`、`description` | 必填；描述可分派的职责和使用时机，避免与独立评审角色混淆 |
| `developer_instructions` | 必填；共享角色正文与已选模型适配的最终组合 |
| `model` | 可选；精确目标已确定时填写，否则保留继承并标为中性草稿 |
| `model_reasoning_effort` | 可选；核对目标模型支持值，不机械沿用另一个模型的 effort |
| `sandbox_mode` | 使用宿主支持的沙箱模式；只读角色可考虑 `read-only` |
| `mcp_servers`、`skills.config` | 按官方配置机制控制所需能力；不对应 Claude 的同名或近似字段 |

当前规范允许其他受支持的 `config.toml` 配置项。需要列表之外的字段时查官方配置，
不要把本页当完整 Schema，也不要把 Claude 的 `tools` 列表、`permissionMode`、
`skills` 数组、`effort` 或 `maxTurns` 原样搬过来。

## 模型选择和上下文

当前官方规则中，角色文件内的 model / effort 优先于派发值；文件未设时，再看
显式派发、`[agents]` 默认及父会话值。只设置新 model 可能保留原 effort，需核对
组合。不能仅凭派发参数声称已经覆盖角色文件固定的模型。

共享角色正文应要求读取适用的 AGENTS.md 与任务必要材料。主会话已阅读某文件、
已调用某 skill，不证明当前子会话已有这些内容。派发工具是否支持角色类型、
模型覆盖或历史继承，由实际暴露的工具接口决定。

仓库存在某个 TOML 文件不表示当前调用面已经注册它。若调用面只能派发普通 agent，
在原任务允许时可显式交接完整角色指令与任务材料；报告为普通 agent 的角色交接，
不能冒充原生具名角色运行，更不能声称继承了未应用的沙箱或工具限制。

## 权限与验证

`workspace-write` 不等于“仅可写 docs/”。角色文本中的允许路径由行为遵循；
需要强制路径限制时须另核对真实宿主配置。支持文档写入的设计角色不能无条件套用
只读沙箱。提交、推送、部署与继续派发也不能因为工具可调用就自动获得授权。

交付时分别验证 TOML 可解析、必要字段、共享职责保留、模型适配依据以及当前宿主
的角色发现与实际配置。实际启动会运行模型时只在授权范围做；缺少加载或运行证据
就标为未验证，不用静态检查代替。
