## 确定实际目标

先完成[宿主支持核对](model-support.md)，再收录该模型的官方指导、模板或引用。
未确认当前宿主支持时，停止模型专属材料的编写；可继续中性角色契约。

分别记录编写者所在宿主、目标运行宿主、目标模型的提供方与精确 ID。这三个维度
不同：Claude agent 可以编写 Codex 文件，Codex agent 也可以编写 Claude 文件。
经代理提供的模型名称不能证明底层提供方、能力或兼容性。

从宿主真实版本、账户/提供方配置和调用面确认模型及 effort 支持。`inherit` 或省略
model 适合可复用中性草稿，但不能据此声称已针对某个模型完成优化。发现请求的模型
不可用时报告缺口，不静默替换模型、降低推理强度或更改主力模型。

用精确模型名查询官方资料，打开正文并确认标题/适用范围。滚动的 latest 页面、
同家族说明、旧链接重定向到新指南都需要再次核对。API 已发布、宿主支持、当前账号
可用、当前会话能派发是四个不同事实。

有官方文档 MCP 就用其搜索与读取；否则访问对应官方站点。使用 OpenAI Docs skill
时遵循它的信息路由；该 skill 不可用时仍可按本技能的[来源索引](sources.json)访问
官方页面，不依赖另一个特定宿主才有的工具名。

## 什么可以变化

共享角色契约保持稳定；模型适配仅处理观察到的表达和执行倾向，例如说明的密度、
例子的数量、进展消息、输出结构、检索触发和过度自检。官方建议不是模型刻板印象，
也不是让所有任务复制同一套提示段的命令。

可优先试验“删除多余重复”，再判断是否需要补充一句有针对性的说明。对会逐字遵循
指令的模型，要核对多个文件、skills 和系统提示之间是否冲突。需要具体示例时使用
一个能区分错误与正确行为的例子；不要堆积与职责无关的 few-shot 样例。

不要要求展示完整思维链。交付应包含结论、必要的简短理由、证据与不确定性。
推理强度、thinking、verbosity、工具协议等首先是目标运行面的配置问题，不能
仅靠“多思考”“进入 pro 模式”等文字开启，也不能发明跨宿主同名字段。

下列变化属于角色契约变更，不能藏在模型优化里：允许原本禁止的写入、跳过必需
规格/计划、对关键歧义直接猜测、取消暂停条件、增加批准权、放宽成果完整性。
若官方示例建议某种通用自治政策，也要按当前用户与角色授权重新裁剪。

## 用证据更新

用[适配记录](../assets/templates/model-adaptation.md)保存精确目标、来源和日期、
观察到的问题、拟改文字、预计行为变化及验证范围。区分官方建议、本项目判断和
本项目实测；缺乏专属指导时明确使用家族级建议或中性基线，留下未验证项。

一次先改变一个主要因素，例如只改提示或只改 effort；用同一职责与任务条件比较。
若同时更换宿主、模型、工具和提示，结论只能属于整套配置，不能归因到某个单独因素。

角色正常案例之外，必须关注关键歧义会不会猜、越界请求会不会执行、无歧义小任务
会不会被过度阻塞、恢复后会不会把假设当事实。公开示例用于开发调优，不能充作留出集。
详细方法见[验证](validation.md)。

发布新模型不要求重写所有提示；精确目标变化、文档变化、行为反例或成本异常才
触发相关适配复核。移除开发防御辅助或切换主力模型时，继续遵循项目已有的
[防御演化](../../../../docs/maintenance/defensive-evolution.md)与
[开发模型评估](../../../../docs/evaluation/README.md)，不在此另立较弱的准入体系。
