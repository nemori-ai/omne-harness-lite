## 何时停下来

主动判断输入缺口属于哪一类，不能统一套用“总是问”或“取最简单解释”。

| 缺口 | 处理 |
|---|---|
| 可查证的事实，例如当前契约版本 | 在授权范围查询证据；查询失败保持 unknown |
| 会改变目标、范围、权限、正确性或对外承诺的选择 | 向有权决定者澄清，暂停依赖该选择的动作 |
| 未提供行动边界，准备写文件或执行外部动作 | 先澄清写/执行范围；只完成已授权的独立读取 |
| 实施角色缺少必需实施规格或计划 | 定位已提供的权威材料；找不到或未接受则暂停实施 |
| 已授权范围内、不改变语义的局部表达选择 | 自主选择；必要时说明，不制造审批环节 |
| 尚未确认、但可作为候选讨论的假设 | 明确标注适用分支和失效条件；不能据此实施依赖动作 |

“可逆”描述动作后果，不替代授权；“最小”描述方案规模，不消除语义歧义。
例如租户停用时是立即取消运行还是等待完成，即使两种方案都能回滚，也是需决定的
行为政策。可以分别分析代价，不能选一个写成已接受契约。

澄清包含：缺少什么、为什么影响下一步、谁能决定、需要回答的具体问题。避免把
十个无关未知一起抛给用户。已有明确答复继续有效，不因压缩上下文或换了模型重复询问。

有并行无关工作时可继续；不要等待依赖答案期间偷跑它所阻塞的实施。没有任何可继续
的已授权工作时返回待澄清结果，避免无限重试或无期限忙等。

## 保留什么状态

长程任务保留足以继续判断的简短事实记录，采用[状态模板](../assets/templates/knowledge-state.md)。
短任务可以在交接消息中表达，不要求建立文件。

| 分类 | 含义 | 必要信息 |
|---|---|---|
| Known facts | 在限定版本、环境或观察范围内有证据支持的事实 | 来源/位置、版本或观察条件、局限 |
| Accepted decisions | 有授权来源的选择 | 决定者或接受依据、适用范围 |
| Hypotheses | 尚未确证、用于分析的解释 | 依据、依赖它的结论、如何证伪 |
| Unknowns | 当前不能回答的问题 | 对任务的影响、谁/什么可以解决、是否阻塞 |
| Rejected / superseded | 被否定或被替代的说法 | 反例或新决定及其影响 |

“我认为”“父 agent 似乎同意”不能升级为 known / accepted。状态中保留重要未知，
即使它们会使摘要看起来不完整。已失效假设应退出当前前提，并保留简短的失效原因。

在范围变化、新证据、关键决定、交接或上下文恢复节点更新；不要求每次工具调用
重写账本。记录可核对的结论、证据和下一步，不要求输出私有思维链或保存秘密值。
记录的文件位置必须在授权范围内，不能因为“需要记忆”就创建额外持久存储。

## 如何恢复

恢复先核对任务身份、当前工作树/版本、最新授权和未答问题，再使用之前的成果。
状态文件是一份有时间和版本范围的记录，不是凌驾于新用户要求或权威文档的指令。

压缩与交接保留：原目标、允许/禁止动作、必需材料及版本、已接受选择、已完成成果
与证据、尚未解决的问题、失效前提、停止原因和下一项已授权动作。
若摘要只写“继续实现”，但缺少实施规格、计划或写路径，不能补猜丢失的授权。

派发者应给[任务说明](../assets/templates/task-brief.md)所需信息；可提供准确链接，
但需要确保子 agent 能访问且会实际读取。模型的大上下文、宿主自动压缩或持久 memory
都不能代替可恢复的任务边界。
