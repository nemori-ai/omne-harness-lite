## 四种不同的证据

| 层级 | 能支持的结论 | 不能支持的结论 |
|---|---|---|
| 静态检查 | 文件可解析、必要字段存在、共享正文与生成结果一致、目标有宿主支持记录 | 提示含义正确、权限已强制、宿主已加载 |
| 宿主发现/加载 | 目标版本识别角色，应用了所观察的配置 | 账户必然可调用、模型遵循角色边界 |
| 独立前向试用 | 一个独立 agent 在给定任务和材料下能使用该技能形成符合要求的产物 | 所有模型、所有宿主、未来长程任务都可靠 |
| 精确目标运行评估 | 给定模型/effort/宿主/提示/工具组合在测量范围内的行为 | 无条件正确、自动获准切换主力模型 |

脚本的 PASS 只指第一层；运行模型不应成为普通文档检查的隐含步骤。当前用户授权
若只包括编写资产，可以做离线结构验证与允许范围内的独立试用；额外收费调用、
真实外部副作用或主力模型切换继续遵循原授权边界。

## 行为验证

[公开场景](../assets/evaluation/cases.json)包含原始任务、fixture 和可观察判据，
覆盖范围、歧义、必要输入、恢复状态、宿主支持与模型适配。这是开发样例，不是冻结
留出集。按当前角色选择相关场景，再补充未用于提示调优的新任务。

测试技能时，让独立 agent 用技能完成一次真实编写/适配任务，提供必要原始材料和
明确暂存目录；不要把预计答案或待修问题塞进任务。原始输出与产物留给验收者核对。
测试生成角色时，则使用生成的完整角色指令和正常任务消息，不给它看判分标准。

观察具体动作：是否写了禁止路径、是否自行补造规格/计划、是否对关键歧义先执行
后询问、是否把假设升级为事实、是否在已完成后扩大任务，以及普通明确任务是否被
无谓阻塞。单看最终回答里写“我遵守边界”不足以判定通过。

长程验证至少包含一个恢复节点：保存任务状态，改变一个关键前提或保留未答问题，
用恢复材料继续，核对它是否重读权威版本、保留未知、停止失效的依赖动作。
不要求为测试制造无意义的长文本；测试的是语义恢复，不是 token 数。

比较不同模型时保持角色职责、授权、任务和判据一致；允许有记录的模型适配段，
但不能为某个模型降低门槛。保留角色源和生成文件 hash、宿主版本、请求/实际模型、
effort、工具/权限、输入和输出、观察到的动作、成本/时延与未覆盖范围。

## 维护与退出

一次反例优先修正其真实归属：任务交接漏信息、角色缺边界、宿主权限未生效、模型
适配不当或评估误判。不能把所有失败都转成永久 system prompt 禁令。

复核来源时先更新[宿主支持](model-support.md)，再更新对应模型材料。官方行为建议
变化或更强模型出现，可以比较保留、精简、移除某项提示辅助；用户要求的职责、
行动边界、必要材料和停止规则仍保留清晰定义。

涉及本项目开发主力模型采用或防御辅助退出时，使用现有
[开发模型评估](../../../../docs/evaluation/README.md)。本技能的样例和脚本不另创
采用授权，不宣称模型已经永远内化某个约束。
