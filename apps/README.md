# 产品应用

**当前为空。**

这里放可启动的产品应用及其装配入口。各应用在自己的成员目录维护 `package.json`、
`src/`、启动配置与测试，消费 [packages/](../packages/README.md) 中的公开能力；
可复用行为由所属包维护。应用目录不自动等于微服务，也不要求为每个接口创建独立应用。
完整归属规则见[源码布局](../docs/workspace.md)。

## 为什么是空的

2026-09-20 与 [packages/](../packages/README.md) 一同回退到骨架。此前这里有一个
`local-harness` 装配基线，它组合的那批提供者及其契约随旧设计链一并退役了。

装配是**最后一层**：它要先有包，包要先有规格。正式设计目前停在产品设计阶段，
这三层一层都还没落地，**留着一份装配基线只会让人误以为已经可以启动**。

原件在 Git 历史里：

```sh
git log --oneline -- apps/local-harness
```

## 什么时候会有内容

等规格与提供包就位、确实需要一个可启动入口时建立。那时它要说明实际的提供者选择、
配置接入、挂载、就绪与退出关系，并引用所消费的包。
