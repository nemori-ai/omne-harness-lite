# 发行应用 `@omne-harness/harness-server`

## 总体架构

发行应用回答一个问题：一份发行怎样把各领域的提供者装成一棵 Cordis 树，作为一个服务进程运行、对外开放，并有序地停下来。它自己不拥有领域规则。它拥有的是装配：装哪些行，配置怎样进来，行与行之间谁能看见谁，状态放在哪里，什么时候开始接请求，停的时候按什么次序收场。

| 部分           | 回答的问题                                                                                                                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 装配入口与装载 | 两层插件树怎样从配置得出，装载前查什么，受信名对哪一行可见，一行什么时候算就绪                                                                                                                           |
| 行声明         | 一行装哪个插件、提供与依赖哪些名字、带不带关闭阶段、关闭句柄由谁登记                                                                                                                                     |
| 入口对象       | 不属于任何行、由入口在第一行装载之前安装的受信对象：主体的签发与核验、时钟、存储宿主、授权与信任来源                                                                                                     |
| 关闭协调器     | 计划停止时各阶段的次序、共用的截止时间、排空与关闭报告                                                                                                                                                   |
| 各行的适配     | 把一个领域成员的工厂接到树上，并填入它要的端口                                                                                                                                                           |
| 应用自己的组合 | 只有装配者同时看得见两边时才成立的组合：Session 与 Agent 的授权政策、动作的当前权限依据、Model 的宿主权威、发行内置 Tool 的来源权威、Tool 等待与人工介入的决策方、日程的同意与额度、工具调用的领域上下文 |
| 本机单用户档   | 一个人在自己的宿主上运行服务时，配置与状态放在哪里，怎样配置一次之后一直复用                                                                                                                             |

进程入口按子命令分三条路。`serve` 先把发行层与运维层叠成最终配置，校验配置并取得状态目录的独占锁，做完装载前检查、准备好租户目录之后安装入口对象，然后按树的次序逐行装载。全部启用行 ACTIVE 之后，入口按登记次序调用各行的 `start`，接入行开始监听，服务开始接请求。停止请求到达后，关闭协调器按 entry、排空、business、composition、storage 的次序收场，写出关闭报告，撤除根，进程以报告决定的退出码结束。`s0` 用标记替身装载同一张行表，只检查装配本身，启动之后自动停止。`setup` 为本机单用户档配置一次。

## 领域边界

本应用拥有：

- 行表：发行装哪些行，每行用哪种实现（真件、契约替身、标记替身），发行层为每行写哪些配置。行 id 与受信成员的唯一源是[应用装配](../../docs/architecture/runtime/application-assembly.md)页；行快照与受信表从它生成，不手改。
- 配置怎样进来：发行层与运维层两层；运维者能做的三种操作；配置在边界上的严格校验；跨行必须相等的配置。
- 状态目录与它的独占锁；本机单用户档的配置位置、状态位置与凭据保管库的位置。
- 受信名的可见范围，以及入口对象。
- 对外开放哪些协议：装了哪个接入行，就开放哪个协议。
- 启动与关闭的次序，以及关闭报告。
- 上表列出的应用自己的组合。Session 与 Agent 的政策表、系统维护授予表与发行内置 Tool 清单是本应用的源码事实。

本应用不拥有：各领域的规则。会话、Agent、Model、Tool、执行环境、身份与授权、资产与设置、治理、Context、人工介入、接入、遥测与存储的规则在各自包组的规格里，本规格不抄。Cordis 只提供机制：插件树、依赖注入与作用域效应；业务含义与收场次序由领域与本应用组织。

它需要别人提供的：每一行需要对应领域的提供者，经该领域的 Cordis 契约取得。点名几项：主体的签发与核验、租户成员事实与当前登录核对来自[身份](../../packages/identity/SPEC.md)；秘密保管来自[资产与设置](../../packages/assets/SPEC.md)的本机保管库；事务域、组合登记与提交来自[存储](../../packages/storage/SPEC.md)；租户治理实例来自[治理](../../packages/governance/SPEC.md)；遥测运行时来自[遥测](../../packages/telemetry/SPEC.md)。

## 心智模型

把本应用想成一块接线板加一份合闸与拉闸的规程。领域是电器，各自知道自己做什么。接线板决定插哪些电器、哪根线只通给哪个插座（受信可见）、总闸什么时候合上（全部 ACTIVE 之后才 `start`）、拉闸按什么次序（先断入口，再让在途的做完，再停业务，最后关组合与存储）。接线板上不做电器的事：一条领域规则出现在本应用里，就是放错了地方。本应用里留下的只有谁和谁接、按什么次序、信谁。

应用自己的组合是有界的例外。只有两边互不认识、而装配者同时看得见两边时，组合才归本应用：授权政策要同时认识 Session、Agent 与身份；Tool 的等待要接到人工介入；一个动作的当前权限要把治理、设置、资产与会话的事实放进一次读。组合仍然只用各拥有者的公开端口，不读别人的私有表，不另存一份别人的事实。

进程是一次运行，不是事实的来源。入口闭包与各行里的表（租户治理实例表、待清租户表、按调用的见证表）都是可丢的活体，重启之后事实从各拥有者的耐久记录接着来。重启之后唯一要证明的是「上一个进程确实不在了」，这由状态目录的独占锁给出。

最容易想错的地方：

- ACTIVE 不是能接请求。全部行 ACTIVE 且全部 `start` 成功之后才接请求；PENDING 不会因为超时变成 FAILED。
- 受信可见不是权限。隔离只防按名误取，每次调用的资格照样核；同一进程里反射遍历能取到受信实例，这不在保证之内。
- 发行配置写了 allow 不等于放行。静态规则只决定「可以继续判断」，放行要当前权限的读数。
- 关闭报告 settled 才是平滑退出。disposer 的结果只进诊断。
- 运维者层的数值是配置，不是答案。缺了就启动失败，代码不猜一个数。

## 应然设计

### 自动压缩组合

发行装配提供满足 [Agent 压缩消费契约](../../packages/agent/SPEC.md#上下文压缩服务)的默认服务，以及输入读取、任务存储、结果保管与 Session 联合提交的适配。服务通过 Cordis 依赖注入，可以替换为企业私有提供者；业务协议不依赖提供者位于本机或远端，也不借 Loop extension 注入。

真实发行入口在预算需要压缩时自动调用服务，采用完整消息后补入完整合法 Context，在同一 Session、同一 Run 内继续原工作。服务缺席、来源不可读、结果未知与预算失败各按所属契约交回，不以无操作实现或空历史冒充成功。冻结任务与在途结果仍归原权威，重新装配只改变后续采用，不能将旧任务静默转给新提供者。

长会话组合须核对实际历史读取、传输与存储规模，使用真实日志证明原始历史仍可查看；替身装配检查不替代发行行为、默认算法效果或恢复验证。

### 两层树与配置

- 树只有发行层与运维层两层；租户与组织不是树的层。运维操作只有三种：替换一行的整份配置、停用一行、在已有锚点行之后插入允许名单里的行。替换不改变一行的作用域；运维者插入的行可见集合为空，也不能插入真件的导出。
- 配置是 JSON，先按未知类型解析，再在边界上同步严格校验。未知键、非法值、重复行 id、未知插件导出、未知运维目标与异步 schema 都在装载前拒绝。行的插件只取自显式的允许名单，不按输入字符串动态导入。按路径导入只有一处：`plugin-server` 行导入一个租户在持的 plugin 的文件，路径在这一版于本机的包目录之内，导入之前核过文件的字节等于清单写的摘要。
- 发行层不写数值默认值，也不写含宿主路径与端口的字段；这些由运维者层给，缺了就以配置错误退出，不由代码补。运维者替换一行时写出整份配置，发行层在这一行写的值要重抄。
- 在会话存储组合之下提交的行（`session-handoff`、`agent-journal`）只配置组合版本。存储清单的摘要只有一个来源：运行着的代码从存储目录算出的值，行自己取，发行配置里不写。
- 跨行必须相等的配置在任何插件装载之前核对，不等就退出 2 并写明哪两行哪一项：Model 记录行与宿主行的结果页目标与空闲读时长；Model 记录行与会话存储行的组合版本；发送阶段的准备配置与准备行；发送阶段的档案配置与档案行。存储行的命令上限不小于 Tool 暂停内容所需的上界，Tools 的回复与页预算不超过 Tool 运行时的内联阈值（否则带页的回复会再被卸载，正文到不了模型），也在这里核。
- 工厂行（宿主文件、遥测）由入口按每次运行绑定。它们的导出只能站在自己的行 id 上，运维者不能插入，只能替换配置。

### 行声明与可见性

- 真件与契约替身经行声明进入。声明给出行 id、实现种类、提供与依赖的名字、关闭承载；名字只取定义包导出的键常量。真件只装在它声明的行 id 上；真件与契约替身不依赖标记替身，也不得到占位对象。
- 声明的依赖必须包含被包装插件自己的字面依赖，不符时模块装入即失败。包装插件在同一个行 fiber 里转交被包装插件的配置与插件体，不建子 fiber。
- 装载前检查在零个插件体运行、零个入口对象安装之前决定，失败退出 2：受信名不在该行的可见集合里；同一提供者组的名字不由同一行提供；真件装在别的行 id 上；真件依赖标记替身；入口对象承载的行没有对应的入口对象模块；同一个名字有两个入口对象模块；发行层引用没有声明的导出。
- 每个受信名有入口私有的隔离标签。列为可见的行能注入它，得到入口创建的那个实例；根上的插件体按名取值得到 `undefined`；根上的同名提供者与子树提供者并存时，子树消费者得到子树实现；同一作用域里第二个同名提供者失败，不静默覆盖。子 fiber 消费的受信名也列入该行的可见集合。
- 受信名在源码里只有两种读法：入口对象经入口的受信读口读；行在自己被列为可见的上下文里读。签发主体的调用只出现在受信配置列出的文件里。
- 标记替身行需要、而没有任何行或入口对象提供的名字，入口给一个占位对象。真实消费者缺入口对象或缺提供行时停在 PENDING，并写出缺的名字。
- 运行时对象（主体权威、Model 组合、责任域）不进配置、树记录与服务表。按调用现取的端口不写进依赖；它缺席时，用到它的操作答不可用，行照常 ACTIVE。

### 入口对象

- 入口对象按注册表次序安装，晚于装载前检查与状态锁，早于第一行。一个名字只有一个模块；名字取定义包的键常量；受信与否由受信表决定，模块不自报。
- 安装只构造服务定义的子类，不提供普通值。安装抛出时不装载任何行，退出 3。入口对象的值不进任何输出。
- 一次运行内共享的对象只经入口的一次性共享表取得；同一个键第二次给出不同的构造时，安装失败。
- 主体签发者只交给受信持有者：入口的主体模块与接入行。系统主体按组件名签发；组件名只用来在授予表里定位，不是凭据。

### 就绪与启动

- 入口读每一行实际的 fiber 状态，不把插件调用的返回当作 ACTIVE。直接缺项与阻塞链分开报告；PENDING 与 FAILED 同时出现时都报，整体为失败；就绪超时不把 PENDING 改成 FAILED，LOADING 超时单独报告。构造时的检查在启动时以 FAILED 可见，不推迟到首次使用。
- 全部启用行 ACTIVE 之后，私有屏障只调用一次。随后按关闭次序的逆序（storage、composition、business、entry）、同一阶段内按登记次序调用 `start`。每个阶段开始前、每个 `start` 调用前都查停止状态：进入停止状态之后不再调用新的 `start`。启动期一个 `start` 抛出时进入停止状态，走整套有序关闭，该句柄记为失败。
- 服务只在全部启用行 ACTIVE 且全部 `start` 成功之后接请求。接入行在自己的 `start` 里才开始监听，所以有行 PENDING 时端口不监听。
- `serve` 在最终配置与装载前检查通过之后、入口对象安装之前，为启用的会话存储行自动准备租户目录。全新的存储根独占创建并写合法的空登记表；已有的根必须有合法登记表，缺表、损坏或半初始化都失败，不补空表。准备失败时不安装入口对象、不运行行体，退出 3，诊断不带文件内容与异常原文。

### 状态目录的独占锁

- `serve` 的一次运行在配置解析与跨行核对通过之后、树的任何部分运行之前，取得状态目录上的独占锁，保持到运行结束。锁是操作系统持有的文件锁：一步取得，进程无论怎样结束都由系统释放，不涉及时间戳、进程号与残留文件。另一个进程持有同一个状态目录时，退出 2 并说明目录在用；目录放不下锁时，退出 2。
- 持有这把锁就证明：在同一份记录上工作过的更早的进程都已结束，它们的实例与驱动也随之结束。发行自己的 Agent 宿主行、Tool 记录行凭它判断一个实例失联，Model 宿主行凭它判断一个调用失联，所以重启之后，上一个进程留下的在途工作可以被接手（[Agent 的接手](../../packages/agent/SPEC.md#接手)、[Model 的那一问](../../packages/model/SPEC.md#活体失联与那一问)、[Tool 的收场](../../packages/tool/SPEC.md#活体失联与收场)）。
- 证据在每次判断时现取锁：锁没有持有，就没有证据，什么都不判为失联。调用方给了自己的插件表时，它自己的这几行没有这份证明，也什么都不判为失联。
- 这把锁是租约的退化情形：持有者活着就不过期，持有者一死就失效。多宿主部署换成带期限的租约时，换的是证据的来源，领域一侧不变。

### 进程输出与退出

- stdout 每行一条完整 JSON 记录，只有一个写者：入口交给这次运行的记录写函数。装配记录、日志桥与遥测的 stdout 出口都经它写出，次序就是调用次序。`serve` 写出关闭报告之后 stdout 封口，之后到达的记录改写到 stderr，每条一行完整 JSON，所以关闭报告一定是 stdout 的最后一行。
- 入口对象的值、登录证明、凭据、秘密与请求正文不进 stdout 与 stderr。
- 退出码：0 表示启动全部 ACTIVE 且关闭 settled（`serve` 还要求停止来自请求）；1 是未预期的内部错误；2 是配置、解析、装载前检查与用法错误，也含状态目录不可用或在用、本机没有完成配置；3 是有行 FAILED、启动期 `start` 抛出、租户目录准备失败或入口对象安装失败；4 是仍有 PENDING 或没有完成的 LOADING；5 是启动成功而关闭 incomplete。启动码非零时取启动码。
- 结果报出之后进程立即结束：先等 stdout 与 stderr 把已写的内容交给系统，再以结果的退出码退出，不等残留的定时器或端口。
- `serve` 等停止请求：SIGINT、SIGTERM（能投递的平台上），或可选的标准输入关闭。Windows 上别的进程只能靠关闭标准输入让它停下。`s0` 写出启动结果之后自动请求停止。

### 有序关闭

- 本节只适用于计划停止。意外退出与非计划卸载时，各行的 disposer 只发起停止，结果只进诊断，不算有序关闭成功。
- 要参加关闭的行登记一个句柄，声明阶段 entry、business、composition 或 storage。登记落在行 fiber 上，有两种承载：行体承载由包装插件在行体返回之后登记；入口对象承载由入口对象在被该行调用的方法里，经调用方的上下文登记。fiber 撤除时自动退登记，插件体重跑之后协调者只持有新句柄。登记被拒时该行 FAILED。
- 再次请求停止返回同一个结果，不再调用任何句柄。
- 全部阶段共用一个截止时间 D：开始停止时的单调时钟加配置的关闭期限。一个阶段的全部句柄结束或到达 D 之后，才开始下一阶段。同一阶段内按依赖的逆序：一行提供的服务被同阶段另一行直接或间接注入时，提供方在注入方结束之后才停；互相依赖的不分先后，没有依赖关系的同时停。原因是提供方停下会卸载它的服务，注入方的收尾会被打断。到达 D 还没结束的记 incomplete，抛出的记 failed，协调者都继续下一阶段。
- entry 阶段之后、business 阶段之前做一步排空：并发调用带排空的句柄，让它不再接新的工作、把已经接到的做完，上限是排空期限。这一步里其他各行都还活着；排空用掉的时间不从 D 里扣。带排空的是 Model 宿主行：模型调用是挂在本进程连接上的付费请求，中止它，花掉的钱换不回结果，重启之后也认不回结局；所以先关上受理，等已受理的调用收场、结果推送完，再停调用方。排空期间新的模型调用答不可用，调用方按依赖不可用等待；到期限还在途的调用由 `stop` 中止，结局是未知。
- composition 阶段得到会话存储组合的关闭结果，分别保留目录与 SQL 实例的结果。storage 阶段关闭存储宿主保存的每一个控制口，全部关好才答 settled。存储提供者自己的关闭期限来自它的行配置，不来自 D，所以它的值不大于 D。
- business 阶段之后、composition 阶段之前，入口结算宿主文件：停周期维护，等已排队的维护，显式卸载宿主提供者行，等卸载完成后补维护，再做最终维护；结果作为关闭报告的附录。超过 D 时附录为不可用，迟到的结果只进诊断。
- storage 阶段之后、报告确定之前，入口关闭遥测：先把日志桥切到关闭后态，再在剩余期限内把遥测运行时的队列排空到本地出口。抛出或到达 D 只影响附录。
- 报告逐句柄列出结果，加上没有登记的预期登记者（not-registered）与停止之前已随行撤除的句柄（disposed-before-stop）。只有全部为 settled 时整体才是 settled。报告写出即确定，之后才通知存储句柄报告已确定；报告确定之后才结束的句柄只写诊断。最后撤除 Cordis 根。附录不参与整体结果与退出码。
- 协调者不关闭业务连接，不回滚提交；SQL 连接与 Worker 只由存储提供者关闭。整体 incomplete 时，进程不报告平滑退出成功；下次启动时，未决的工作由原拥有者按原身份认回。

### 授权政策：Session 与 Agent 的访问检查

- 授权行提供四个服务：Session 访问检查、Agent 访问检查、动作准入，以及受信的系统动作授权。它们共用依赖，一起装载，一起撤除；依赖每次调用重新读，不缓存任何允许。行撤除之后，旧引用答不可用。
- 一次访问检查在第一次等待之前把请求固定成计划，然后按次序判断，一步不通过就给出结论：按操作查表（只认自有属性，原型链上的键答拒绝）；核对固定绑定（变更命令的种类等于操作，命令里的会话与租户等于目标与访问的会话与租户，目标的种类等于该操作定义的种类）；按主体的形状选列；核租户；核工作绑定；取格（按输入种类或事实种类取分支）；按格调用依赖。拒绝格不调用依赖；等待产品规则的格写成拒绝格。
- 主体分三列：登录主体 L（代租户行事，工作拥有者是身份登录），会话工作主体 W（代租户行事，工作拥有者是会话，工作是会话标识），系统主体 S。形状只用来选列，不授予资格。L 与 W 的租户必须等于访问的租户；W 的目标是会话时，它的工作必须等于目标会话，目标是租户时只核租户。例外只有政策表里标为「同租户可读」的只读操作（`directory.list`、`history.begin`、`history.next`）：W 可以读同一租户的任何会话，供 `Sessions` 工具用（会话产品正文：人和 agent 用同一批读取）。写、待处理、等待中的调用、去向与后台调用不在例外里。Agent 的 `receive-result` 另认 Model 宿主签发的工作主体 M，按 W 的成员格判断，只核租户；M 做别的 Agent 操作一律拒绝。
- 放行只有两种：成员（租户准入核验主体并读当前成员事实）与矩阵（系统动作授权按核主体、矩阵行、授予记录、参数的固定次序判断）。依赖答允许、拒绝或不可用时原样映射；拒绝不带原因，不披露会话是否存在；依赖抛出或答复不在契约内时答不可用，诊断是固定文字，不含异常原文。
- 每个操作在每一列的裁决是源码里的政策表，不经配置改变。成员格对租户角色中立：问租户准入时要求的资格为空，所以租户角色不决定任何 Session 或 Agent 操作。
- Agent 使用会话工作主体查询原消息交接（`read-message-handoff`），供准备未知、依赖暂时不可用与重建后认回。目标仅为 execution 或 input-entry；每次仍核主体和当前租户成员资格。登录主体、系统主体和跨租户主体不因此获得查询权；读取原结果不授予新采用资格。
- 系统维护授予表随版本内置，按系统主体的组件名定位。运维者只能收紧它：收回一项，或给一项设到期。不能新增，不能改用途、主体或作用域。表外的记录标识、多余的成员、`revoked: false`、空对象或不是 UTC 时刻的到期，都让行启动失败。到期在每次判断时读注入的身份时钟，时钟答不出时答不可用，不放行。收紧同时作用于两个访问检查的系统格与系统动作授权。撤权从下一次检查起生效，不阻止已经得到允许的那次提交。
- 会话逐权限配值走专门的登录政策：只有实际签发、核验通过、当前仍是目标租户成员的登录主体，并且原登录仍有效、登录账号等于目标租户的账号，才能进入。资格材料在第一次等待之前固定，绑定原租户、会话、操作、完整命令摘要、期望的权限修订与政策引用；普通的允许证据不能代替它。原操作没有已提交的回执时，依据来源再做一次登录核验；已提交的由 Session 按回执认回，不重新铸造资格。

### 动作准入与当前权限

- 动作准入只放行会话工作主体，主体由原身份权威核验并代请求租户行事。一个动作放行，当且仅当三件事同时成立：身份当前合格；有匹配的静态允许规则而没有匹配的静态禁止；当前权限的读数解释为允许。静态禁止在读权限之前就终结。依赖缺席使对应的一项为假，不制造空约束。
- 动作规则是部署配置的不可变快照。规则按工具定义名精确匹配，不匹配模型给的原名，所以一条规则覆盖多命令工具的全部命令，禁止不能被某个命令绕过；可选地逐项匹配采用的拥有者、名字、修订与摘要。禁止优先于一切允许，与顺序无关。没有规则、没有匹配、带命名权限读取的请求答判不了：这个部署对它给不出结论，再问一遍也一样。动作准入对 Agent 的答复里，不可用只指暂时的：准入、身份核对或当前权限的依赖此刻不在，或权限依据此刻读不出；Agent 收到它会等着再问。别的给不出结论的情形都答判不了，Agent 收到它整批不运行。抛出的异常、形状不对或契约之外的答复算判不了，不算不可用。没点名已知命令的调用不进动作准入，由可信请求来源以原因和工具指南作答。
- 一次权限检查是一次读：核主体与当前租户成员资格；由受信映射把动作映射成权限请求与目标地址（地址不证明目标存在）；请原拥有者认回这个动作（Agent 的动作）；在租户域的一个快照里执行只读的参加者命令，得出租户域的依据；读组织层的设置来源；作答。它不发提交，不开始治理操作，不占身份或设置的预留。
- 放行判断只读，不发提交。放行的结论、授权引用与这次用掉的单次授权，由 Agent 在准入的那一次提交里经会话的写入者一起记下。之后的设置变化只影响之后的放行判断，所以这次提交不断言依据未变。Tool 调用的受理不读也不断言任何授权依据。
- 结构解释先于询问处理：已知的禁止仍是拒绝，结构上不可用仍是不可用；只有结构上允许而需要人决定的，才按会话发布的询问处理决定拒绝、跳过询问继续，或问人。问人时动作准入答要人决定并带放行卡片的草稿，卡由 Agent 的卡片轮次出给人。询问视图在读权限事实之前复制一份；它的租户、会话、权限修订与来源必须等于这次检查读到的会话权限事实，旧的发布拿不到新的依据。
- 读数不是可以复用的执行许可：每次放行判断重取依赖、读当前事实。放行之后 Agent 交出调用，Tool 启动时不再判许不许，只现核目标此刻还在会话的工具视图里、驻留与调用方式相符（常驻的直接调，非常驻的经 `Tools` 转发）；目标不在或不符时这次启动被拒，读不到视图时不启动。
- 动作准入的适配是放行这件事的组合承担者，只有它同时认识各方。一次准入依次：向 Tool 问这个调用的动作；每个事务域读一次（治理域取动作所属关口与载体关口在租户层的结果，会话域取运行模式、会话层配值与有关的授权表达，身份域取成员事实），三处并行，一批动作共用这一次读，按关口去重；调授权的放行判断；要人决定时用授权生成的卡片内容出草稿；带着人的答复再来时，照授权的效果表逐项执行（向会话追加授权表达，或写租户层权限值），再读、再判断。
- 一趟判断共用的读只在这一趟里有效：同一批动作的第一遍是一趟，其中同一个关口的会话层配值与本会话授权只读一次。带着人的答复来的动作不共用，它读自己的单次授权与答复刚写下的东西。第一遍之后重问还在等人的动作是另一趟，读得到第一遍写下的授权。
- 授权表达由动作准入的适配交给会话写：它以受理入口的调用者身份交一条会话命令，写入者仍然只有会话。接入策略只在两件事都成立时放行这一笔：调用者是这个会话的工作主体；命令点名的卡在人工介入里读得到，人选的选项与表达的来源就是这张卡上的答复。单次授权登记在 Agent 的这一个动作上，写下它真正执行的目标与生效参数摘要：直接调用时是调用自己，经 `Tools` 携带时是被携带的目标。准入的重判现读它，动作、目标、参数摘要三项都相等才认，所以同一个动作直接调与经 `Tools` 调，用的是同一笔。认下的那一笔与放行的结论、授权引用一起记进这次准入的提交，一个动作只有一次放行，所以一笔单次授权至多用一次。这一轮终结时，会话把它从当前的授权里退掉。
- 本会话放行所管的关口与依据在出卡时定下：准入把关口的能力身份、关口键与此刻裁定的修订写在卡上，卡片端口把它随所选项原样交回，准入用它写授权表达，接入策略核表达里的关口与依据就是卡上的那一个。所以同一张卡的答复重做时写下的是同一笔。裁定的修订属于关口，不随哪一次调用来问而变；设置变过之后旧的依据不再等于当前修订，这笔授权不再算。
- 「始终放行」与「始终禁止」经租户设置的同一张面写：准入按动作所属关口的声明找到设置项，自动档与禁止档取自声明里各值的效果。这张面在登录主体之外只多认一种资格：会话的工作主体可以读一项；写一项时必须带着卡与答复，接入策略到人工介入读回这张卡，人选的就是这一档、答复的凭据相同才放行。别的设置面不认这种资格。出卡时准入先读这一项：可编辑并且值在上界之内的那一档才给出，读不到时这一次准入答不可用。写入的操作身份由卡的答复与读到的修订派生；租户已经是这个值时不写。写入结果未知、冲突或暂不可用时准入答不可用，带着同一个答复再来。写不成时如实留痕：始终放行落成一笔以这个答复为来源的单次授权，这一次照常重判；始终禁止只拒绝这一次，类别是「本次没有放行」，原因记为没写成，不追加撤回。始终禁止写成之后再追加本会话对这个关口的撤回，这个动作以「已被禁止」拒绝。
- 读量有预算，用例守着：一批动作的准入，每个事务域至多读一次，与动作数无关；每个动作的启动不读任何授权依据；人答复之后到发起，至多两次提交（效果一次，卡片结论一次）。进程里可以留一份「依据修订到结论」的对照，用前先比修订，丢了重算。
- 发行内置的每个工具按它的定义声明的关口各得一项调用权限：一道关口一项，覆盖归它的那些命令，取值是禁止、询问、自动，缺省值取定义里写的；工具没有声明关口时是一项，覆盖全部命令，缺省询问。权限的能力身份是工具，关口标识取自定义。不设关口的命令不生成权限，准入对它不读权限、不调放行判断；这一类只认发行清单点名的命令；清单点名的是 Ask 的提问。准入的适配只在放行判断答要人决定时向 Tool 要这次调用的放行详情，把它连同关口的名字交给卡的内容函数；Tool 答没有或给不出时照常出卡。权限声明与解释映射属于不可变的发行，版本由内容摘要推出，可变的租户配值不进摘要：声明的版本覆盖整份工具（采用、模块、定义与关口），有没有关口都一样，它也是工具资产正文的版本，正文变了版本必变；权限设置定义的版本只由设置定义本身的内容推出，实现换代而关口的声明不变时设置定义不变，已有的配值与组织层来源照旧有效。关口的声明变了时，发行作为定义的拥有者，在安装中对存过配值的租户目标按[可核验的变更映射](../../packages/assets/SPEC.md#设置声明与目录)做一次显式 rebase：新旧两份设置定义里一项的声明（规范文本）一字不差，就保留它的配值与锁定；声明改了的项和新定义里删掉的项丢弃，回到缺省；提交留一条 rebase 的变化记录。rebase 是维护动作：发行的设置准备以维护资格直接提交，不经身份预留；这个入口只交给安装方，租户与工具用的写入面没有它。代码改了某道关口下命令的实际影响、又要人重新决定，就必须改这道关口的声明。换成另一份资产（同名替换）不继承旧来源的配值与授予。
- 每个租户的治理实例由应用的实例表管理：同一租户同一时刻只有一次打开在途，别的租户不排在它后面。目录答「没登记过」是正常情形，答不可用，不计失败。治理宿主声明一个窄端口「确保这个租户的事务域已登记」，由会话存储行适配；只有租户层设置读写面准入调用者之后才经它登记，别的路径只开启已登记租户。端口缺席时照旧；登记答不可用或抛出时答不可用。目录读不到、准备抛出，或打开没有创建出运行时，算一次失败：计数、上报阶段与这个阶段给出的原因（短文本，不带秘密），到再试时刻之前答不可用；到时刻之后的第一次调用先关闭失败那次打开仍持有的东西，再重新准备；关闭没有收场就不准备新的，关闭责任不丢。等待时长是可替换的策略。治理在第一次有调用需要它时打开，工具治理的安装有界并发；租户登记与服务就绪都不在后台预先打开：一次打开的提交数随工具数增长，预先为每个租户打开，和前台的提交共用同一份存储写入预算。实例表是可丢的活体，不是第二份业务状态。

### Model 的宿主权威

- Model 宿主权威在入口闭包里持有本运行的 Model 组合：原受理的读许可、一次记录激活的附着、唯一的执行通道、宿主绑定与推送账本。服务表上只露出 `resolve`；记录行与宿主行各按运行取自己的窄口。无关插件拿不到签发者、成员事实读口、资格表的写口或通道。
- `resolve` 有四步，任一步失败都不跳过后面的步骤去补造结果：在一次读许可里读原受理；核受理的租户与调用、当前成员资格、原发起者指向当前的成员记录；签发并登记 M（工作拥有者是 Model，工作是调用标识）；准备执行通道，失败时撤掉 M 的登记。关系核对在签发之前，所以核对不成立或依据读不到时，签发者不签出任何主体。
- 重启之后，本运行没有记录的调用凭状态锁接手：服务把状态锁的判断交给模型记录行的首次执行运行（`adopt`），它证明更早的进程都已结束；有这份证据，`resolve` 才以新的执行代次接手上一个进程留下的调用，没有就答不可用。启动扫描以部署扫描主体枚举租户，每个租户由入口签发一个扫描主体：它只许做恢复读取，只在它的租户里，只能由入口捕获。
- 资格回调是同步的，而主体核验与成员事实读取是异步的。L 与 W 的受理点是宿主行包装的命令：每个方法先核验、读成员事实、登记，再调用，最后释放；M 的受理点是 `resolve`。同步回调只查已登记的捕获：没有捕获答不可用；核验拒绝、非成员、租户不符或宿主已退役答拒绝。各动作允许哪些主体是源码里的矩阵，登录主体只有只读的动作。
- 凭据由供应商、层与用途确定，租户取自调用。准备时选层：本租户层有任何一项就选它，层内缺项或读不出时准备失败，不回退官方层；本租户层为空且档案是官方档案时选官方层；凭据服务缺席、拒绝或不可用时准备失败。选定的层写进请求；发送在围栏内只读这一层，不重新选层。准备之后层变得不可用时，发送在围栏内拒绝，不向上游发出字节。
- 一家供应商只有一个凭据项时才能发送。正文声明多项而没有说明每一项怎样放进请求时，装配拒绝这个供应商。
- 宿主行是 business 阶段的行体承载：撤除宿主子 fiber 就是成员的有序关闭。释放执行时先撤除记录行的发送子 fiber、等发送资源关闭，再关闭通道；之后取通道答不可用，不交出已关闭的通道。资格表的宿主绑定项在通道关闭与宿主退役时整表清空，上界是一个通道、一代宿主内的调用数。
- 登录主体可以用自己的身份取模型的公共流并订阅，只读已有的调用，不能新建调用。组合把一段观察包在捕获里，按检查间隔重新准入，新捕获成立之后才放掉旧的；重新准入失败就结束观察。订阅的中止只收订阅，不取消模型调用。
- 代租户行事的登录主体按调用读本租户的 Tool 调用：状态、过程流、结果页、输出正文、账目与诊断，都是只读的口，诊断页与 `tool/v1` 用的就是这些。受理、认回操作、控制、按附件读内容、交付、恢复、写入与开始要这次调用的会话工作主体。
- 发行树装三份网关引擎。OpenRouter 的官方档案覆盖 OpenAI、Anthropic、Qwen，以及 Kimi、DeepSeek、GLM 三个家族。每个公开的型号都须能由请求准备行和发送行按档案采用的同一修订绑定。具体型号与适配依据归 [Model 的家族记录](../../packages/model/SPEC.md#传输与家族)。
- 请求准备的限额与余量按家族分开配置。发送行与准备行的家族配置须一致，任一家族不等就按跨行配置不等处理。
- 模型类读者能读到哪些块由注册清单里消费者类为模型的需要绑定决定。发行树为 `session.modes` 登记这样一条绑定。

### Tool 的运行时组与发行内置工具

- Tool 运行时组每次运行只建一次，五行各在自己的 fiber 装同一组插件。整组的运维者配置只在记录行，缺任何一项记录行装载失败；同一次运行里换配置再建也失败，不悄悄沿用旧配置。其余四行等记录行建好再装。业务停止时执行器行关闭这一组：执行宿主退役，不再接新的作者执行。
- 发行内置作者（Shell、Files、Tools、TodoItems、BkgToolCalls、Web、Ask、Skills、Screen，以及日历的 Calendar、日程的 Schedules、通知的 Notifications、会话的 Sessions、派发的 Agents、工作区的 SwitchWorkspace、看拓展树的 OmneExtensionPoints、管拓展的 OmneExtensions）来自不可变的发行清单。清单每一项写明它的来源包：Tool 自带的作者来自工具定义包，领域带来的工具来自该领域的工具包。清单的构成规则只有一处，生成脚本与启动快照都用它。启动时先按包产物清单逐个重算来源包的摘要，全等才从刚核对过的包根导入模块，不经包名解析；再重建整份清单比较。任何一项不等时快照不可用：来源权威的两个方法都答不可用，记一条警告，启动照常；读失败的结果不留，停一段之后，下一次核验触发重读，读完之前仍答不可用。存储隔离区里要发行事实的参加者只读清单数据：用主线程钉进模块地址的代次，从清单字段重算代次摘要比对，相等才用，不在隔离区重做产物核验、不导入工具包。主线程已按产物核过这一代，隔离区信它钉的代次摘要，与信它钉的成员代码摘要是同一份信任。
- 来源权威的核验只为官方层、清单内的资产、证据全等且代次为当前代次的请求铸出已核验的权威，返回从快照构造的冻结值。登记准入只接受本运行签发的登记者对象本身。官方作者只能由登记者装载：发行的工具宿主行装好之后以系统作用域预装全部作者，租户的采用点只读已装的作者。预装失败只记警告，目录里没有这个作者，调用答不可用。
- 发行内置工具在每个租户治理里的资产、组织层设置来源与贡献都归发行。每次打开租户治理时，安装方先把每个工具各自收敛到当前发行，工具之间并发，同时在途的工具数有配置的上限；每个工具内部按下面的次序：资产发布当前版本，持有选中当前版本（停用的持有也换，停用照旧，已移除的不动）；组织层的设置来源采用当前发行的定义，只在定义身份相同时采用，组织留下的授予不动；这一步不迁移组织层的配值，成立的前提是组织层没有配值的写入口，加写入口的改动要让换定义与配值的 rebase 同做；然后登记当前声明。全部工具都有了结局才往下走：有一个没登记成，等其余都结束再答这一阶段的失败。全部登记之后、采用之前，安装方按状态对账（工具之间同样并发），不看这一次换没换版本：对每个带设置定义的工具只读一次它的值投影，不提交。存着的配值与当前定义不符时，按页列出这个资产的版本，逐个读声明，找定义引用与存着的相同的那一版，拿它的设置定义作旧定义，做「动作准入与当前权限」一节写的那次 rebase；只在真要 rebase 时提交。所以换完版本、rebase 之前进程中断的，下次打开时照样做成。翻完所有版本都找不到时，不动这个目标，记一条警告，写明租户、工具与存着的定义引用，这个工具照旧判不了，别的工具与治理照常打开。读不出值投影或版本、或 rebase 没有提交成时，目标留在原状，记一条警告，写明租户、工具与没做成的那一步，下次打开再对账。目录完整与否只在收敛之后、采用之前判。官方工具的定义换代之后，同一个状态上的治理照常打开。上一代次的租约由治理的关闭与代次隔离退出，安装方不撤。
- 工具宿主行只从受信快照取固定模块、构造值与上下文，不按调用参数导入；交给加载器的始终是快照里的固定模块。非空的环境声明经 schema 提供者按执行环境契约公开的 schema 校验，只有 valid 才通过。
- 可用性判断只取已核的来源：快照、主体核验（必须是本租户的会话工作主体）、清单条目、确认的文本消费者材料。设施依赖只报装配在场，不核宿主的前提。
- 可信 Tool 请求来源每次调用现取主体、定义、请求方作用域（会话快照里最新且未结束的作用域，以协调者调用方类读）、作用域归属、设置采用与元能力命令的可用性；缺席答不可用，不符答拒绝。命令的可用性来自命令在定义里声明的调用条件与会话经 Runtime Context 发布的事实，和询问处理无关。装配只做一件事：把条件的名字对到会话发布的事实上，三个名字：`person-present`（会话有人值守）、`person-answers`（此刻能向人要答复）、`dispatched`（本会话是一次派发建出的子会话）。哪个命令要哪个条件写在各工具自己的定义里，装配里没有工具名或命令名的表。给模型的命令表在采用点按同一份条件裁剪。不可用时调用不运行，以命令名与原因作答。请求只带定义的采用引用与名字，不带定义本身。Tool 收件时按名字取的当前定义由受信的发行快照答：快照不受信时答不可用，不答没有。等待方式只从调用参数 `run_in_background` 读：值为布尔 `true` 时请求带 `mode: 'background'`，其余都是前台；这次调用许不许后台由 Tool 受理时判，请求来源不替它判。
- 一次调用的时限在受理之前从运维者给发行工具的设置算出：工具声明了 `foregroundMs` 时得到前台上限，声明了 `backgroundAfterMs` 且这次调用许可后台时得到转后台阈值；Shell 声明的阈值缺省是 60 秒，跑满就转后台。阈值只在运维者这一层，租户不能改。设置读不出、或求值不完整时，这次调用不受理，以原因作答。
- 每次调用带一句意图与按命令算出的标签，由请求来源在受理前从调用参数取出：带命令的工具缺意图时不受理，以命令名与原因作答；其余参数错误照常在运行时判。
- 需要环境的工具，可信 Tool 请求来源在每次调用时以协调者类读者读「会话工作目录」这个需要，把读到的目录、工作区与实例写进固定请求。读到「选了但用不了」、缺项，或者这个会话的作用域没有登记这个块时，这次调用在受理之前就被答掉：模型收到一条不可用的说明，什么都不执行，这一步照常走完。它不作为依据不可用让调用等着：会话工作目录只在下一步开始之前换值，等着的这一步到不了那里；没有登记的块等多久也不会有。读这个需要的服务不在或读取本身不成时，才是依据不可用。受理时还照会话工作目录与「工作区之外的文件」这项设置算出这次调用的文件范围，一并钉进固定请求。没有选工作区的会话不划范围：不读这项设置，读与写都不限，默认目录只是工具在哪里干活；附着了工作区的会话，都不许时读与写都限在实例的根，许读时只限写，许读写时都不限；这项设置读不到时调用答不可用，不当成许，也不当成不许。这项设置是 Runtime Context 里租户这一层的块 `workspace.outside-files`：行 `workspace-outside-files` 登记它，每次读时经租户的独立设置现取，读不到答不可用；同一行提供读它的服务 `workspaceOutsideFiles`，以协调者类读者经租户这一层的作用域读，读不到时答原因。入口只问这个服务，不认识治理的设置服务；这一行不在时调用答不可用。它不经会话的作用域读：会话登记了哪些块与需要是创建时写进会话日志的，已有的会话没有这一项。`Tools` 的调用自己不需要环境，会话有可用的工作目录时也钉一个，它转发的目标调用继承这同一个值，不另读。`SwitchWorkspace` 同样不需要环境、有可用的工作目录时也钉一个：它拿钉住的那个工作区当「当前工作区」。
- SwitchWorkspace 的绑定是两步的组合承担者：先把目标认成一个实例，目标是同一份资源的新物化时先关联它；再以这个会话的主体向会话提交更换。两步分别如实答复：第一步成了、第二步没成时说明实例已关联而会话没有更换，同一个目标再调一次可以完成。「当前工作区」是这次调用的固定请求里钉住的那一个，也就是这一步模型被告知的那一个；请求里没有时，一个还不是实例的目录被拒绝。更换的提交和人在命令行里选工作区是同一种会话声明，操作号由调用导出，所以同一次调用重放不会提交两次；应用的会话策略只为这一种声明放行这个会话自己的主体。它带的是这个会话的主体，不取得会话租户本来没有的资格。
- 工作区的装配行把成员资格读口与动作准入适配成工作区声明的端口，把工作区的附着核验适配成会话的工作区目标端口，把文件系统型与 Git 型登记到管理类型登记面。会话工作目录的块与它的需要绑定随创建时的上下文登记进会话作用域。
- BkgToolCalls 的绑定（`src/rows/tool-bindings/background-calls.ts`）把工具的列出、读输出与停止接到会话的工作面：每次调用现取主体核验与会话面，只看这次调用所在会话的后台调用；按短号找已经结算的调用也走会话；停止以 agent 的名义发起，答复是「已请求」，不写成已停。依据不在时答不可用。
- 领域带来的工具要的领域服务（日历计算服务、日程的命令与查询服务、通知的发送、收件、订阅与目录服务、会话的服务与搜索服务）由工具绑定行注入，按请求交给对应的作者；服务不在时这个工具的调用答不可用，别的工具照常。工具调用的领域上下文由本应用解析：所有者取调用的租户与账号，行事者取会话工作主体与来源会话；解析出的租户与调用的租户不一致时拒绝。工具结果详情的读取只放行同一租户的主体。
- 来源资格只认本租户的会话工作主体。并发范围每个 Run 一个，授予按调用的租户与范围键重算核对，所以两个 Run 互不排队，同一个键在别的租户下被拒绝。
- 环境只有宿主机落点。文件范围取自这次调用固定请求里钉住的那一份，随落点交给执行环境；作者拿到的工作目录取自钉住的目录。固定请求带了工作区实例时，环境计划在取落点之前向工作区核验一次这个租户的资格。未获准，或实例已经不在钉住的目录上，这次调用照常得到落点，但围栏里什么都没有：它的每一个文件与命令操作都被设施守卫答未授权，调用以拒绝收场。环境计划本身不因此失败，因为 Tool 对计划的失败只是停下，调用没有结局。依据不可用时计划答不可用，Tool 过后再试。设施守卫核主体、原调用与这次调用的文件范围，按操作是读还是写取对应的根，检查请求里的每一个路径字段；起始目录按写的根判；那一侧不限时不判；带了路径字段而值不是路径时答拒绝。一个路径在一个根内要两条都成立：不跟随任何链接时，按段落在根下；解析后的真实位置在根的真实路径内。查不了真实位置时按根外处理。判断只用于放行，不改写请求里的路径。
- 按调用的见证、原调用表与账本视图只随调用的终态释放：提交了结清，或之后读到已结清。表的大小随在途的调用数，不随累计的调用数增长。
- 存储的命令上限必须容得下 Tool 暂停内容的三笔提交：上限小于三者里按存放形式最大一项的两倍时，启动失败。有了这条关系，记录仓不会因为大小而确定地拒绝暂停的提交。
- 结果读回的参数预算归发行，不归运维者，模型参数不能覆盖它。改这个预算时要保留未到期的旧引用可读。
- 正文保管的许可时长、时钟偏差与孤儿宽限是部署参数，由运维者显式给出；宽限与最长保留都要大于许可时长加两倍偏差，否则拒绝启动。
- 正文清扫按到期时刻只访问到点的租户，每租户每批有上界：先删正文字节，再在账本记回收；中途崩溃之后重跑得到相同结果。失败按递增的退避再试，退避有封顶，成功后清零。启动时全量清扫一次，这是恢复。待清租户表是可丢的活体。
- Tool 的生命周期观察投影成一个遥测事件，只带阶段、失败类别、条目数与字节数，不带正文、程序 data、路径或异常原文。遥测不参与结果交接、清理或准入；它的失败不改变 Tool 的答复。

### Tool 等待与人工介入

- Ask 暂停之后，等待由人工介入保管。决策方实现 Tool 的决策桥，与会话组合同一个事务域。来源带会话与 Run 时，登记与答复在同一笔提交里核对会话没有归档、该 Run 仍在进行。
- 登记从原调用的恢复读取取等待的请求原文，按人工介入的等人决定契约解码，不合契约答不合格；再核对它的摘要等于等待的证据。两个人工介入操作的身份由调用加等待派生，重送认回原结果。登记被原工作守卫拒绝时答冲突，Tool 把它当作确定的拒绝。原操作查询只读：按待办的动作重建同一条命令认回；人工介入已封口的答 excluded，其余答 unknown。
- 全部卡片都有决定时，决定证据是请求与全部决定引用的摘要，不含修订。接手之后按登记的卡片顺序给出整批答复。接手回包未知或被拒都答不可用，Tool 不据此接受决定。失效的原因随等待关闭的原因；还没答的卡变失效，已答而没接手的卡保持已决定。
- 唤醒只是提示：答复成为有效决定之后，请实例宿主重调度原调用；提示丢了，执行器的周期恢复扫描按待办标记找回它，所以丢了唤醒不丢事实。
- 谁能读、谁能答，由注入的受众函数给出。还没有事务域的租户按同一条资格规则判断读者。
- Agent 的卡片端口与 Tool 共用同一个人工介入宿主、受众与登记主体：一轮请求登记成一个请求，每项一张卡；准备、登记与作废的身份由执行、通道与轮次一起派生（通道与轮次的标识在每个执行里都会重复），按原操作身份与输入摘要认回；读到已决定而没接手的卡时，绑定接收者、接手、确认交接。
- 人工介入宿主是卡有变化的信号来源：它在每个租户的人工介入应用的每一次写落定之后（成功、失败、未知、抛出都算），告诉这个租户的监听者卡可能变了；读不发信号。监听者按租户文本订阅，租户的应用还没建时也能订阅。宿主关闭时告诉全部监听者来源关了，之后的订阅立刻听到关闭。信号只在内存里，人工介入的接入行把它接给观察 `observe-cards`。

### 会话存储与部署

- 租户目录只增不删；读、解析与查找不登记租户。放行的创建先完成存储组合登记，再写目录文件，最后发布内存快照。不同租户的登记可以交错：每次在同一个同步发布序列里，以最新快照加上本次的租户写盘，所以并发登记不互相覆盖；同一租户的并发调用共用一次在途登记。写目录先写临时文件、刷盘、改名，再刷盘目录。目录文件只能有一个写者。
- 行启动时按目录快照逐个确认租户当前的组合登记，全部成功才发布服务；登记失败或最终仍未知使行失败。关闭先拒绝新登记，迟到的确认不发布快照。
- 目录里没有的租户没有会话。经委派视图的会话读与非创建的提交，对这样的租户答拒绝，与「会话不存在」是同一个结局；不答依据不可用，因为那会披露租户从没建过会话，并诱使调用者重试。这样的租户列会话、列已归档的会话都得到完整的空页。访问裁定仍在先。
- 部署枚举每次按调用现取系统动作授权；它缺席或答不可用时枚举答不可用；不是系统主体的调用者在问授权之前就答拒绝。只有允许之后才读一次完整快照，修订与条目来自同一次读取。
- 会话日志的每一批新写出恰有一条提交叫醒，认回不叫醒。会话存储行在发布服务之前把通知接口登记在自己的存储上，停止或卸载时注销；Agent 日志行注入同一个存储，所以它写出的批也报到这里。会话提供者行只监听。
- 进程启动时，会话提供者行以扫描主体枚举部署里的租户，为每个租户绑定恢复扫描者，所以有待办而没有新提交的租户也被找回。枚举失败时只按提交叫醒绑定，并记一条诊断。
- 权限配值的提交依据每次按调用现取应用的后端；后端缺席答不可用，不阻止会话服务启动；未登记的租户先答拒绝。后端只给出依据的计划，不授予业务权限。

### 信任入口与作用域归属

- 作用域归属由一份按运行共享的来源回答：先问会话上下文适配行的作用域查找，它答不出时问会话存储行的受信作用域归属，再经会话主体绑定核对同一租户与同一会话，才答已绑定。未绑定、未知与不可用各自保持；两个来源都缺席时答不可用。应用不解码作用域摘要，不读会话的私有索引。Runtime Context 信任与执行环境的可信绑定共用这一份来源。
- Runtime Context 的读者只接受会话工作主体：核验身份，租户相同，工作等于作用域所属的会话。生产者只接受会话模式主体与固定的模式生产者；供值时从该作用域所属的会话取协调者主体，再核验一次。
- 执行环境的普通授权先核主体是代租户主体、租户等于访问的租户，再按动作核作用域绑定与原获取。恢复授权逐次委派受信来源；没有来源时不开放恢复。授权的当前性只保护读取方 fiber 的进程代次，在第一次等待之前捕获，退役之后的旧答案不再当前。
- 环境授权对按保留范围观察答拒绝。授予哪个观察身份，由接上观察的装配决定。

### 接入

- 接入行只在回环地址上明文监听，不接受监听地址的配置；端口不接受 0。监听在 `start` 时打开，在 entry 阶段最先关闭：停止接新连接，给每个活动观察发结束，等在途请求写完答复，再关闭全部连接。
- `plugin-access` 行开放 `plugin/v1`。「要装哪几份 plugin」有两个来源，合成一个：
  - 这个租户持有的 plugin。行按调用现取租户的本机资产（`tenantAssets`）：先问这个租户有没有资产可言；它的事务域从没登记过时，它什么都不持有，答空表，不答取不到；登记过的照[取自资产的一组](../../packages/plugin/SPEC.md#取自资产的一组)读。文件的字节从那一版已发布的目录里按段读：已发布的版本不再变，所以只读要的那一段，不读整个文件；文件的大小与列出来的不同时答取不到。那一版在本机没有目录时，才经包的读口整份读。资产的变化信号（`assetChanges`）来了就叫监听。这两个服务不在时答取不到。一个租户读到的那一组留着用，到它的资产变了为止（凭的是同一个变化信号；信号不在时不留，每次重读）；没读到的答复不留。
  - 运维者配置的开发目录（行配置 `devDirectory`，绝对路径；缺省不开，不开时给空表）：目录下每个子目录是一份，对所有租户给同一组。它是给开发者用的来源，不是租户的资产。
  - 读法与看变化的规矩归[包组规格](../../packages/plugin/SPEC.md#接入插件与来源)。一个名字在两个来源里都有时，这个名字一份都不装。
- 租户的本机资产多答一问 `standing(租户)`：事务域登记过、没登记过、不知道（目录读不到、抛出、或交回了别的租户的域）。「没登记过」是事实，不是读不到：读的一方据此答「什么都不持有」。它不打开资产，也不登记。
- 发行的 coding 定义常驻带这两个工具，提示词有一节 `extensions` 讲什么时候用它们：用户要改的是应用自己（它的样子、它能做什么）而不是项目时，先在拓展树上找到地方，在一个目录里写成文件（本机已有的一份可以用绝对路径就地发布），问影响，再发布；撤回用禁用。这一节不写任何类别与点的名字。提示词的 `environment` 一节讲「会话工作目录」这一块的三种状态各意味着文件能到哪里：没有工作区时目录只是相对路径从哪算起、读写不限，附着了工作区时出不出得去是用户的设置、被拦的调用会说明，用不了时调用会说原因；并要求模型在调用被拒之前不说一个路径够不着。角色一句不把工作目录说成「被授权的工作区」。
- `plugin-notification` 这一行让拓展成为通知的一个来源 `extensions.changes`，只有一种持续事项 `load-failed`：这个租户在持并启用的一份 plugin，有连着的客户端对在持的那一版报了装不上或停掉了。事项的主题写成 `plugin:<名字>`，标题带上客户端说的原因，几个客户端都装不上时写个数；从什么时候起是第一次看见它的时刻，不见了再出现重新记。装上了、被禁用了、或报它的客户端走了，事项就没了。在持的或回报有一边读不到时答不知道。另有两种一次性事件 `point-added`、`category-added`：所有行起来之后这一行记下服务端此刻声明的点与登记的类别，之后登记表一变，多出来的每个点与每个类别以来源 `extensions.changes` 自己的身份发给每个已登记的租户（列租户用 `tenantDomainScannerPrincipal`）；事件标识就是「类型:名字」，同一个再出现是认回，不重复。不见了或说明变了的不发。
- 工具 `OmneExtensionPoints` 的每次调用看到的拓展树由绑定给：发问者的作用域是这次调用行事的那个租户的，模型给不了租户；服务端那棵读登记表此刻的样子，客户端那棵读 `plugin-access` 行记着的这个租户的回报（服务 `pluginReports`）；两样都按调用现取，取不到时答读不到，不答成空。修订号是这个进程里登记表变化的计数，进程的标识是启动后第一次用到时取的一个随机数；所有租户共用一份计数。
- 工具 `OmneExtensions` 的每次调用要的东西由绑定给，都按调用现取：资产的三个面；一个目录读成一个包（准入照文件工具的那一次核验：固定请求可能是一份副本，工作区的身份从它的文本重新读出再问工作区的拥有者；路径从这次调用被准入的工作目录算起，也可以是绝对的，能到哪里照这次调用钉住的文件范围：读一个目录按读判，`export` 往一个目录里写按写判，都按链接跟到底之后真实落在哪里判，范围之外的答「在范围之外」，工具说明是「工作区之外的文件」这项设置拦的，什么都不读不写；名字以点开头的文件不算；每个文件按列出时的摘要打开，对不上答材料不可用）；影响与生效情况问这个类别登记时带的口，没带的问资产给的缺省，都换成这次调用行事的那个租户再问，问题里写的租户不看。绑定里不出现任何类别的名字。
- 取回（`export`）时绑定把在持的一版写进这次调用的工作目录里的一个目录：只在目标不存在或里面没有文件时写（名字以点开头的不算文件）；已有文件时什么都不写，与在持的一版相同答相同，不同答差在哪些路径（改了的、缺的、多出来的，至多十个）。先写在目标旁边再挪进去，有一个文件读不出就什么都不留，为它建的上级目录也撤掉。路径不是相对的、跟着链接出了工作目录、或已经是一个文件，答没有；在持的一版里有路径想走出自己目录的，不写。
- `plugin-host` 这一行登记 Plugin 与皮肤两个类别（皮肤的契约是 Plugin 的契约再收窄，影响与生效情况用同一份）；来源给装载方的一组是这两类在持的合起来。登记 Plugin 类别时把它要的三样端口接到这棵树上：在持的 plugin 读自 `tenantAssets`，服务端的点读自登记表（类别的点收这一类的新建方式，别的点收它声明的数据或代码），客户端的回报读自 `pluginReports`；三样都按调用现取，所以这一行不注入它们。
- `plugin-access` 行在进程里记着每个连着的客户端最后报的样子，每个租户至多 `reportsPerTenant` 个客户端（缺省 32）；客户端的观察结束就去掉，进程重启后为空。它不落盘：这是客户端的投影，客户端在就会再报。
- 一个登录同时开着的要登录的观察有上限（配置项 `observation.perLogin`），缺省 16；整个实例的上限缺省 1000。缺省要盖得住一个客户端常驻的观察再加上它同时看着的会话：桌面应用一页常驻四条（待你决定、通知、资产、要装的 plugin），每看着一段会话再占一条。16 是这四条加上同时看着的几段会话之后，再留一倍以上的余量；一个登录占得再多，也过不了整个实例的上限。名额满了，入口对新开的观察答依据不可用并记诊断 `access.observation-full`，已经开着的不受影响。
- 接入行在自己的作用域里装接入登记表。一个领域的接入行把自己的协议挂上去即开放，卸下即撤下；装哪些接入行由发行决定，有贡献不等于开放。
- 会话的接入行取 Session 时用两个调用方类：受理（管理与工作面）与读者（历史面）。调用方类是装配事实，不授予资格。身份操作、设置与 Tool 查询每次调用现取，缺席答依据不可用，入口照常接收其他操作。会话诊断的接入行的投影种类与两个上限一起给或一起不给。
- 人工介入的接入行的入口主体只在同一次请求的登录识别成功、并且目标租户的账号等于识别出的账号之后签发；签发者自己再核一次账号相等。入口主体的工作是固定文本，所以同一租户的入口主体引用稳定，与哪一次登录无关。
- 管道诊断成为遥测事件 `omne.access.diagnostic`，系统作用域，只带诊断码、路径（不带查询串与片段）与操作名；协议冲突的诊断另带挂了同一份协议的两个实例的名字。不带租户、请求正文、凭据或错误原文。

### 设置、秘密与 Web 凭据

- 秘密保管行装载时不读不建文件，每次调用才打开保管库。文件缺失或读不出时行仍 ACTIVE，读面答不可用、写面答没写入，文件字节不变。它不缓存，所以运维者在本机的写入与服务里的写入互相可见。
- 设置行的登记跟随发行装载：一个发行工具的定义在工具宿主装好它的作者之后才可知，设置行在每次读登记表时对照受信的发行快照，把新知道的定义登记进去。持有用具体的资产引用，所以同名而不同的两份资产推出不同的秘密目标。
- 设置的管理只对代该租户行事的登录主体开放。写入与读取恒在行事租户的租户范围；公开操作没有通往官方范围或使用面的路径。
- `assets/v1` 的设置端口由两个面并成：秘密项归设置行，普通项与权限项归治理行的租户层读写面。查看与清除先问秘密面；秘密值只交给秘密面，别的值只交给目录面，送错了答不合格；列表秘密项在前，一页可以跨两段。秘密项的修订恒为 `'0'`，带别的修订写入答冲突。秘密面只用保管库与登记表，所以还没建过会话的租户也能查看、设置、清除自己的秘密项。目录面要用租户的事务域：它准入调用者之后，先确保这个租户的事务域已登记，再读目录，所以还没建过会话的租户也列得出完整的目录。没准入的调用不登记。登记答不可用时列表整体答依据不可用，不拿秘密项充数。客户端对依据不可用的读会自己再试，答成「成功但不完整」反而会被当成结果留住。只含秘密项的页自己是完整的。
- 写 Web 的 key 与 Web 附着读 key 用同一份持有编码，本应用里只有这一份。有没有 key 只由保管现读。Web 的用途与 Model 的用途按键精确匹配，互相取不到。秘密只出现在设置写入的请求里，不进持久记录、固定请求或工具结果。没有任何一层配了 key 时，search 答未配置并指出要配哪一项，fetch 照常。
- 领域声明的独立设置（日历的时区与生效日历）由声明它的领域经贡献口带来，治理行不导入声明方；每个租户按贡献口的当前清单逐组开通独立目标，一组开通不了只这一组不可用，别的组、资产设置与租户的治理照常。租户层的读写面对独立目标与资产目标用同一套操作列出、查看、写入与清除，列出时调用方说要哪一种。默认值来自声明本身。声明不带治理项与秘密项，所以独立目标的写入走设置自己的当前，不走治理快照；写入的分流按目标的种类，治理目录只收带治理项的目标。
- 租户层设置的写入以该租户的一个稳定主体行事，原操作的根只取决于租户与账号，不取决于哪一次登录：重新登录后重送同一操作，认回同一次写入。
- Web 附着的选层顺序是租户、组织、官方。引用在调用开始时选定；中途被清除时这次调用失败，不改选别的层。

### 日历与日程

- 日历行在系统范围的事务域登记日历的组合，组合里另有本应用的授权参加者。供应用日历的本地提供者，建供应运行器与来源适配器：启动时以系统归属导入发行种子一次（幂等），之后按运行器的间隔跟进各来源；只向日历政策声明的来源发 HTTPS 请求，断网时刷新失败，覆盖内的查询照常。运行器的间隔与排空时限是部署配置。供应的授权端口只放行本应用的系统归属。日历行提供查询、计算与供应三个服务。查询资格答「是这个租户的有效成员」；健康经健康投影端口以系统归属读供应应用。
- 日历的生效环境经租户级作用域读：日历行登记块 `calendar.environment`，值从这个租户的独立设置读，绑定到这个租户的独立目标；读不到答不可用。日历行另登记块 `calendar.supply-risk`，值由供应健康算出。行 `calendar-notification` 登记 `calendar-adapters` 的来源 `calendar.supply`，并把块 `calendar.supply-risk` 不经翻译绑到通知的「一组持续事项」；去掉它，日历照常。
- 发行检查 `check:calendar-release`（`scripts/calendar-release.mjs`）以当天（UTC 日期，或 `--at` 给的日期）调日历的 `inspectCalendarRelease` 判发行带的种子：有阻止项或没声明接受的警告退出 1；警告在声明文件（`--accept-warnings`，`{ accepted: [{ calendar, reason }] }`）里逐条写明接受，声明文件接受阻止项、点名发行没带的日历或重复点名都算非法，与参数不对一样退出 2。提升到 `stable` 之前跑它（`omne-card` 的提升节）。
- 日程行按租户取日程后端：租户的事务域没有登记时先经租户域登记端口登记，再登记日程的组合并建后端；活体按租户缓存，可丢。登记答不可用时，调用答不可用，没有提交。
- 日程的资格与额度是本应用的组合。权威端口在每次管理决定时读行事者是 owner 还是 agent，并核它此刻的资格；它不读放行，不判许不许：agent 的动作在发起时已由放行判断判过。安排记创建者：owner 记 user；agent 记 agent，连同它所在的会话与这次工具调用，由工具绑定经运行时注入从这次调用的上下文取得；系统原生的记 system。权威端口只读，不写锁。
- 日程守卫参加者与日程同一个事务：核对守卫要求等于命令的重算，按所有者与作者计非终态安排的占额，容量取部署配置，超额答容量超出；盖决定时刻。

### 通知

- 通知行装一个提供者，服务全部租户。每个租户的通知存在这个租户自己的事务域里：第一次问到时取它的域，没登记就先经租户域登记端口登记，再在那里登记通知的存储组合；组合的摘要从存储目录现算。取到的域不是这个租户自己的、域取不到、组合算不出或登记被拒时，这个租户没有绑定，领域答依据不可用；没有绑定不缓存，下一次再问。
- 资格是本应用的一张表，只看行事者。owner 以 `owner.posts` 发送，读与处置人的收件箱，为人设订阅，管人的投递去处。agent 以 `agent.posts` 发送，读与处置自己会话的收件箱，为自己设订阅。两者都能列目录。能被点名的收件人是人与行事者自己。别的都拒绝。行事者由受信的适配给：接入行给 owner，工具绑定给这次调用验证过的会话。
- 往应用自己的界面投递时披露全文；往别的去处只披露标题。
- agent 的订阅许不许在发起时已由放行判断判过，通知不读放行。订阅记创建者，取法与日程相同。持续事项的读者答「读到了，没有事项」。
- 来源 `owner.posts` 由本应用登记：owner 自己写的一条，只能点名人，agent 不能订阅它，人的缺省是强。
- 策略是一整份，只由运维者层给；发行层的这一行不写任何值。缺失或不合规则时这一行装载失败，发行树不就绪。
- 到期扫描在启动时与定期各做一遍，以部署扫描主体枚举租户；目录读不到时这一轮不扫描。
- 通知接入行把 `notification/v2` 挂上入口。登录能为租户行事时行事者是 owner。通知的服务面与变化源按调用现取，取不到答依据不可用，协议不撤下。
- Notifications 的绑定（`src/rows/tool-bindings/notifications.ts`）每次调用现取主体核验与通知的服务：发出者与对象是这次调用验证过的会话，来源是 `agent.posts`，因果深度是 0。主体核验不过或服务不在时工具答不可用。
- Sessions 的绑定（`src/rows/tool-bindings/sessions.ts`）每次调用现取会话的读面（经 `reader` 调用方）与历史搜索：主体与租户是这次调用的，模型给不了；主体不是这个租户核验过的会话工作主体时答拒绝，不读；读面或搜索不在时答不可用。两个能力 `session.read`、`session.search` 对应会话服务与搜索服务。
- Agents 的绑定（`src/rows/tool-bindings/agents.ts`）每次调用现取派发服务、Agent 定义目录与会话目录的读面（经 `reader` 调用方）：哪个会话在派发、交报告、发消息取自这次调用核验过的会话工作主体，模型给不了；派发的身份由租户、这个会话与这次调用的引用派生。主体不是这个租户核验过的会话工作主体时答依据不可用，不问派发。目录以本会话作参照读，每行带它与本会话的关系。这个工具不声明必需能力：派发行不在时工具照常提供，每个命令答依据不可用，调用不挂着等。
- 去掉通知行与通知接入行，发行树照常启动，会话照常对话，别的工具照常；`notification/v2` 不挂上。Notifications 仍在发行清单与 agent 定义里，它的两个能力对应的服务不在，所以不可用。
- 媒体是六行：`media-storage-sql` 把媒体的元数据绑在 SQL 存储上，每个租户一个事务域，第一次问到时登记媒体的存储组合；`media-image` 提供有界的图像编解码；`media` 提供保管服务与存放的登记表；`media-storage-local` 向登记表登记本机文件存放，根目录由运维者层给；`media-sweep` 在启动时与每个节拍用部署扫描主体枚举租户，逐个调清扫，一个节拍没跑完不起下一个；`media-access` 把 `media/v1` 挂上入口。大小上限、分片大小、上传与暂存的期限、请求版本缓存的容量、图像的解码预算是这几行的配置，都有缺省值。
- 媒体的服务面按调用现取。只装接入行时 `media/v1` 挂着，每个操作答依据不可用。本机存放那一行不在时，开始上传答依据不可用，已有引用的描述照常、读字节答依据不可用。
- 去掉媒体的六行，发行树照常启动，纯文字的会话照常；`media/v1` 不挂上。
- `media-model-source` 这一行把媒体接到 Model 的读媒体端口上，提供 `modelMediaSource`；`model-records` 行的发送子插件在物化时按引用读，每次读时现取，不注入。去掉这一行或媒体的各行，带媒体引用的请求答依据不可用，纯文字的请求照常发出。
- `media-tool-store` 这一行把媒体接到 Tool「存产出」的端口上，提供 `toolMediaStore`；`tool-environments` 行的环境适配在作者每次交出产出时现取，`tool-bindings` 行在判一个命令可不可用时看它在不在，都不注入。去掉这一行或媒体的各行，结果带图片的命令（`Files` 的 `open`）在原位不可用并说明原因，别的命令照常。
- `media-converters` 这一行让转换件定义成为资产：向资产登记类别 `converter`，并提供 `mediaConverterDefinitions`。发行版自带的两份（语音 `voice` 与 PDF `application-pdf`）由这一行放成点 `media.converters` 上整个部署这一层的条目。求值的层是官方层与这个租户的那一层，都从点上读；租户发布同名的一份就用租户的，禁用之后回到官方的那一份，没有官方同名时答不需要。资产页只列租户在持的，列不出官方的这两份。去掉这一行，「备好表示」答依据不可用，不答不需要。
- 两个转换引擎各是一行：`media-engine-transcribe` 登记 `voice.transcribe`，用这次转换的租户在 OpenRouter 上配的凭据，没配用部署的，都没配答引擎不可用；`media-engine-pdf` 登记 `pdf.extract-text`。去掉一行，指向它的定义生效时答引擎不可用，不答不需要。
- 屏幕：`execution-host` 行装载时按所在的系统选屏幕后端（`execution-environment-host-local` 的 `hostScreen`），选到且屏幕清单自洽才让宿主提供者提供 `screen`，并记下这一行提供了哪些设施；配置里写 `screen: false` 时不找后端。`execution-command` 行多装 `screen` 的设施声明。发行工具 `Screen` 声明能力 `screen.read`：它在不在看宿主行有没有提供 `screen`。所在的系统没有后端时，`Screen` 是已知不可用（原因 `dependency-unavailable:screen.read`）。
- 已知不可用的工具留在原位：模型调用它时，受理处答一段带原因的文字（`<工具> is not available now (<原因>). Continue without it.`），不启动、不解析参数，这一轮照常往下走。目录答不出可不可用时仍是依据不可用。
- 会话换型号时，`session-access` 这一行按这段会话的历史判目标可不可选：它以这个会话的协调者主体读这个会话的模型视图（登录的主体无权读模型视图；前提是会话接入已经核过这次登录可以对这个会话行事），只读这一个会话、只为算出历史的原生要求，再交给档案求值。型号盖不住时以模态不符拒绝并带回它读不了的块；模型视图读不到时答依据不可用，不当成空历史放行。`sessionWorkPrincipals` 因此是这一行按调用读的受信名。建会话没有历史，只按文字判。
- 受理前处理是两行：`session-before-intake` 提供登记面 `session.before-intake`；`media-intake` 在媒体的服务与登记面都在时登记处理件 `media.references`，任一个不在就撤回。会话提供者每次受理现取来源声明与处理件，不写 `admission`。去掉 `media-intake` 或媒体的各行，登记面上没有媒体的处理件：带内容引用的输入不被受理，纯文字的会话照常。去掉 `session-before-intake`，成员本人的输入都不被受理，直到它回来。

### Skill

- Skill 行按租户提供 Skill 的目录与读取两个服务：每个租户一套 Skill 服务，建在这个租户唯一的一份本机资产上，本机资产从租户资产行取，Skill 行不自己开；Skill 这一类由这一行装的贡献插件放进拓展点；活体按租户缓存，可丢；同一租户并发的第一次调用只建一套。租户域没有登记或查不到时这次调用答不可用，不缓存失败。行卸载后答不可用。
- 读取判定只认这个租户的会话工作主体；主体的真伪由 `Skills` 的绑定在每次工具调用时核验一次。
- 租户资产行按租户给这个租户唯一的一份本机资产，按调用现取；同一租户并发的第一次调用只开一份，开好时登记资产的存储组合、跑一次包的恢复扫描。治理行与 Skill 行都从它拿，不自己开：两份本机资产各自恢复，会删掉对方刚换入、还没提交的版本目录。一个租户域的已发布包放在状态目录下 `assets/<事务域名的 UTF-8 十六进制>/`，一个域一个根。行卸载时关闭它开的每一份。
- 资产的发布服务由租户资产行提供，按调用现取这个租户的那一份本机资产；授权端口问「这个主体能不能为这个租户行事」，用身份的核验器与资格读口作答，每次调用问一次。
- `Skills` 的绑定把 Skill 的答复翻成工具的答复：无权与没有是同一个答复；已禁用的说明原因；读到一半版本换了叫调用方重读；依据读不出答不可用，不答没有。搜索结果在绑定里翻页，游标绑定这次检索的规范化查询与排好序的条目，结果变了旧游标作废。
- 治理行的管理视图捕获排除哪些类别，每次调用从类别拓展点现取：拓展点上在、正文契约不带设置钩子的那些。一类的持有是不是设置目标，由这一类的正文契约说，治理行不写死类别；Skill 的正文契约不带设置钩子，它的持有不进治理的捕获、不占捕获的上界；撤下的类别不在拓展点上，不被排除，它的设置照常列出。

### 采用来源

- 创建会话时，常驻工具由部署映射条目列出；首次定义取自受信的发行快照，不取自调用方。任何一项拿不到材料（快照不受信、名字不在清单里、登记表缺席、某个工具没有唯一的活贡献），整份答不可用，不留下部分常驻工具。创建自己声明了映射以外的常驻工具时答 invalid。
- 采用规划每次调用现取登记表与换代协调者，只采用唯一的活贡献，不按序号选版；已有的能力不再输出首次定义。登记口缺席、快照失败、已记录的键或首次形状解释不了、必要的定义缺失，整份答不可用。加载前已经发生的外部效果不因规划失败而撤销。
- 创建时的模式注册用一个隔离的初始准备视图：按会话原来的算法绑定本次创建的作用域，只允许这一次准备，不允许提交或读者，完成后关闭。准备记录与创建在同一个会话批次里提交；原操作重传按完整的原输入与准备正文认回原守卫，不要求当前映射，也不重新准备。
- 开始一轮的准备里，会话选了工作区时向工作区采用一次来源读取，键由这一轮的标识导出，布局取类别登记点那一刻的清单。采用答不可用时不挡这一轮开始，这一轮工作区层读不到。`Skills` 的每次调用按当前这一轮导出同一个键，作为不解释的作用域交给 Skill；Skill 的层来源列表是租户层加这个键对应的工作区层，内容按资产引用分发到租户的内容库或工作区的读口。没有选工作区的会话没有工作区层。
- 实时 Context 只在模式注册提交、并经会话上下文适配行确认应用之后供值。每个租户的模式生产者按租户装配一次，并发请求共享装配结果；生产者只保存可丢的发布状态。

### 拓展件

- 拓展件类别经资产的类别拓展点贡献，资产的包根目录由装配给出。
- 每个资产类别登记时连同它的点一起声明，发行里是七个：技能 `skill.skills`、转换件 `media.converters`、工具 `tool.tools`、模型供应商 `model.providers`、Agent 定义 `agent.definitions`、Plugin `plugin.plugins` 与皮肤 `plugin.skins`（后两个由 `plugin-host` 行登记）。发行自带的定义由带来它的那一行放成点上整个部署这一层的条目：两条转换件、模型供应商、发行清单里的每个工具、配置里每一条 Agent 定义的映射。
- `tenant-assets` 这一行把每个租户在持的定义对到点上：打开一个租户的资产时对一次，之后由本机提供者在每次有变化的提交交回之前对。条目的作用域只取自打开的是哪个租户的资产。这一行另给出 `layerSources(租户)`：这个租户的官方与租户两层的来源，候选从点上读，列出读账；技能、转换件与资产的管理服务都用它。租户的资产打不开、上一次没能把持有放上登记表，或这个租户在这个类别的持有还在等类别登记时，租户那一层答读不出。类别的组成变了，这一行把每个打开的租户的持有再对一遍。
- Agent 定义的目录对表里的每条定义，从这个租户的 `layerSources` 取候选并求值：发行的那一份胜出，这个租户才看得到它；读不出时答不知道，派发照此答不可用。
- 「租户启用的拓展件」这一块随会话创建登记进会话的作用域，读者类是协调者。没有登记这一块的作用域读不到它，读取方按读不到处理，不按没有成员处理。
- Agent 的「租户启用的拓展件」端口由适配行实现：以协调者类读者读这一块，再用拓展件领域导出的纯函数筛出这个位置的成员并排序。适配行不自己写筛选与排序的规则。
- 命令型调用的运行位置由适配行按访问身份取得：会话取自会话工作主体，作用域取自会话当前的上下文作用域，工作目录是会话工作目录。取不到时答不可用。
- 解释器表是操作者设置。表里没有的名字不可用。
- 租户设置面答一项设置的归属，由目标的种类推出：独立目标归它的提供者与定义；资产目标按这一层持有记录里的类别与名字，不查发行清单，不只认工具。
- `plugin-server` 行把每个已登记的租户在持并启用的 plugin 装在服务端，规则归 [plugin 的规格](../../packages/plugin/SPEC.md#服务端的装载方)。这一行可见的受信名只有 `tenantDomainScannerPrincipal`，只用来列出已登记的租户；plugin 的 fiber 长在把它也隔离掉的上下文里。起来之后逐个跟上已登记的租户；登记表变了再列一次，跟上之后才登记的租户；一个租户的资产变了，重算它要装的。它声明 `plugin.ports` 与 `plugin.guest-forms` 两个点。
- 一份 plugin 带着的定义（例如技能）放在那个类别的点上，项是这份 plugin 在持那一版的 `HeldItem` 加 `within`。`tenant-assets` 行的租户这一层列出时，在账本的那一页里按账本的次序并上点上这个租户范围里带 `within` 而账本没有的项，游标仍是名字。Skill 行的适配见到 `within`：正文用技能的正文契约在那个子目录上读出（这份 plugin 发布时已整份判过），读口只看得见那个子目录，本机目录的提示指到版本目录下的那个子目录。
- 借给 plugin 的口与收 plugin 代码的点由各自的拥有者放：`plugin-notification` 行放口 `notifications`（发一条通知，进的是通知自己的发送入口，上下文的租户是持有这份 plugin 的租户，行事者是 owner）；`plugin-access` 行放 `access.protocols` 的客人写法（翻法归 plugin，做成那个点的一项用入口导出的 `protocolItem`）；`server-entry` 行把资产的 `scopeOfLayer` 作为「租户的范围」交给入口。
- 服务端的底存在运维者给的目录里（`floorDirectory`，本机档是状态目录下 `plugin-floor/`），一个租户一个文件，文件名是租户名的 UTF-8 十六进制。文件先写到旁边再改名替换，进程在任何时刻没了，留下的都是完整的一份。从第一次去装到这一次安定，文件记着「在装」；每一份都有了结局、服务又撑过两秒才算安定。有序的停止把「在装」改回去，不算倒下。被底停掉时诊断写明租户与停掉的几份。

### 派发

- 派发行装一个提供者，服务全部租户；每个租户的派发登记存在这个租户自己的事务域里。它的三个贡献成员各自成行：会话的三个输入来源与对会话的调用、Tool 的报告等待契约与桥、工具 `Agents`。宿主不在时只有那一行不启动；去掉全部派发行，其余行照常启动。
- 派发以系统主体办事，持有建会话、送输入、读去向三行用途的授予；授予随派发行安装，卸下时撤销。它对会话的每次调用都带被维护的那个租户。
- 派发要的分叉点由装配接到会话的分叉点读口：受理 `spawn` 时读出派发方此刻的分叉点，建子会话时把它放进会话的创建。定不下来时如实答原因，派发拒绝这一次 `spawn`。视图在两步之间被压缩换代不影响：分叉点指的那个代际的行还在。

### 其他各行

- 常驻引用桥接行以原入口主体、系统作用域读会话的引用页，投影整页。任何失败答不可用，不返回空页或部分页，不回退缓存。行撤除时把全部未决的读取结算为不可用，不等下游，迟到的结果不改变结算。
- 会话适配行的协调者主体每次调用由受信的会话工作主体签发，缺席答不可用，不调用 Agent 入口。
- Request Context 的来源登记只放行会话工作主体为它自己的会话登记 Agent Context 的来源：作用域所属的会话经受信的作用域查找与会话主体绑定核对，必须等于主体的工作。
- 会话的租户缺省模式取自部署映射条目，条目必须仍代表创建时记下的那一份模式采用；条目改名、移除或改了缺省时答不可用，不用当前的缺省代替。
- 身份行的操作、租户成员事实与治理端口出自同一个提供者实例、同一份记录，所以治理端口上的撤销与切换对登录识别立即生效。
- Agent 宿主行要求联合提交里有消息：本发行的日志只以消息联合提交把 Agent 的消息写进会话历史，少了它，工具消息会漏出历史而不报错，所以缺它时行装载失败。
- 宿主文件的责任域由每次运行的入口创建，保留在入口闭包里，行重载共用同一个域。周期维护串行，行重载不新建周期；一次维护抛出只记诊断，之后的周期照常。
- 遥测行的禁用实现是在场的实现，不是缺席，发射行照常 ACTIVE。发射行注入遥测，把成员已有的观察回调接上。记录按所属工作的租户作用域，系统作用域的操作按系统作用域；既没有租户、又不是系统作用域的记录不落到系统作用域，计为无效。日志桥在装载任何行之前登记，导出不高于 WARN 的消息；本行以 node 实现就绪时才把日志交给运行时，禁用时直写，不缓冲。输出在启动时固定，改出口或预算要重启。

### 本机单用户档

- 一个人在自己的宿主上运行服务：配置一次，之后 `serve` 不带参数就能启动；Windows 与 Linux 用同一套命令。只有省略运维者层或状态目录时，入口才读本机的配置。
- 位置只依赖平台、环境变量与用户目录：设了服务主目录变量时用它下面的 config 与 state，这个变量必须是绝对路径，否则退出 2；没设时 Windows 用本地应用数据目录，其他平台按 XDG。命令行客户端为读默认地址重复了这条规则，两处要同时改。
- 配置文件里没有秘密，除存储线程上限之外也没有运维者层的数值。数值留在代码里，所以新的发行带来新的数值时，用户不必再配置。凭据唯一的去处是状态目录下的保管库；配置文件写成之前保管库已经存在。
- 凭据只从标准输入读，不经参数或环境变量；凭据、它的哈希或前缀不出现在任何输出、配置或错误文字里；未知参数不回显。
- 已有的设置不被静默覆盖：与要用的不同而没有显式要求重新配置时，退出 2 并逐项列出旧值与新值。不合格的配置文件只有显式重置才替换。保管库读不出时不报保留；显式替换凭据时，读不出的保管库被重建，并警告各租户自己的秘密设置不再存在。配置从不删除目录或链接。运行时遇到绑定存在而读不出，调用仍以凭据失败结束，不回落到默认凭据。
- POSIX 上配置与状态目录只给本用户（0700），配置文件 0600，保管库按保管库自己的权限护栏。Windows 上不改访问控制列表，保护来自用户目录的继承，所以保管库必须在用户目录之下。
- `serve` 实际打开保管库确认可读，确认工作区是目录，再生成运维者层：从发行层每行的配置开始叠加本档的键，不重抄发行层拥有的值，本档的键与发行层同一行的键不重叠。本档的工作区设置是默认目录：没有附着工作区的会话，会话工作目录取它的真实路径；真实路径只在内存里用。Shell 与 Files 的构造值里没有目录。
- Shell 进程不继承服务进程的环境。它的环境是配置文件里在配置时按白名单取的变量，加上指向宿主状态目录的临时目录。名字像秘密的变量不进 Shell 的环境：手工写进配置的，`serve` 以配置不合格拒绝，生成运维者层时再滤一次。经宿主服务管理器起的进程归服务管理器，不归执行环境。
- Windows 上 PowerShell 以只作用于这一个进程的执行策略启动，并带一段把控制台编码与读文件的缺省编码设为 UTF-8 的前导；不改机器或用户的任何设置。

### 发行验收

- `acceptance/` 在发行装配上跑持续场景，对应[工具执行的产品验收页](../../.meta_harness/design/product/tool-execution/acceptance.md)的 S4 到 S16。场景起真实的发行树（真实的 Session、Agent、Tool 与 SQLite 存储），模型换成脚本化网关，命令行用构建后的 `omne`。先在仓库根构建 `pnpm --workspace-concurrency=1 --filter @omne-harness/harness-server... -r run build`，再运行 `pnpm --filter @omne-harness/harness-server run acceptance`。
- S4：模型让一条长命令发起即后台。前台位置得到占位，这一轮结束。命令结束后，历史里有一条来源为后台工具执行、带命令输出的提醒，并自动开始新的一轮。账本里这次调用只启动一次，会话里这次调用的账目与账本一致，不因转后台多出一份。
- S5：两条长命令都在后台。`omne calls stop --reason` 停其中一条，回执是受理；之后 `omne calls show` 读到 `stopped` 与 `interrupted`。会话里留一条带原因的停止提醒，被停的那条的结局写明谁停的；这两条都不开新的一轮，另一条照常完成并叫醒 agent。
- S6：人用 `omne calls background` 把一条正在前台跑的命令转后台，前台得到占位，这一轮接着往下走。
- S7：一条许可后台的命令跑满阈值，自动转后台，占位写明原因是阈值，命令只启动一次。
- S8：一条不许可后台的调用跑到前台上限，前台得到被中断的结果；这条场景只在 Linux 上跑。
- S9、S10、S11：插队（`omne interrupt-input`）遇到许可后台的命令、不许可后台的调用（Ask）与模型回复。S9：命令转后台，同一轮承接插队并收尾。S10：Ask 被撤回，前台得到说明原因的结果。S11 标为跳过：被中断回复中已到达的内容不保留。
- S12、S13：取消一轮。前台命令被撤回；后台命令不受影响，它的结局开新的一轮。
- S14：归档一个有后台命令的会话。答复写明撤回了一项后台调用；命令的结局照存，不回会话；会话只在已归档的列表里，撤销归档后回到平常的列表。
- S15、S16：agent 用 BkgToolCalls 列出、停止后台调用，带位置续读输出；读取不改变结果与账目。
- 每条场景在标准输出写一行 JSON：`result` 为 `PASS` 或 `FAIL`，`observed` 是判定用到的观察。断言失败时以非零退出码结束。等待只等实际条件，单个条件最多等两分钟。
- 场景要求宿主能运行 `/bin/sh` 的一次性命令。它们不证明跨进程恢复、真实模型或多租户隔离。

真实模型矩阵检验整套系统经真实网关时的行为：一个会话里用一个型号多轮，或交替换两家的型号多轮，量每次发出的缓存读取与写入、推理状态有没有被略去或被上游丢弃。它的规则见[质量论证](../../docs/architecture/assurance.md#真实模型矩阵)。

## 原则与约束

- 本应用只装配。一条领域规则出现在这里时，先问它的拥有者是谁，写进拥有者的规格。
- 组合只用公开端口：不读别的领域的私有表，不另存一份别人的事实，不为一个领域加特例。
- 缺了就是缺了：依赖缺席、来源读不到、配置缺项，答不可用或启动失败；不默认放行，不补空表，不由代码猜一个数。
- 每次调用现取。受信对象只经入口给，不经配置；运行时对象不进树，也不进输出。
- 策略数值是配置，代码里只有初值；发行层不写数值。
- 一处定义：行 id 与受信表源于应用装配页；发行内置工具的构成规则只在一处；秘密的持有编码只在一处。
- 隔离不是权限。受信可见只防按名误取，资格每次核。
