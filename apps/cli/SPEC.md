# @omne-harness/cli

## 总体架构

终端应用 `omne` 回答一个问题：一个人或一段脚本在 shell 里怎样驱动一个 Harness Server。一行命令变成一次公开操作，答复变成标准输出上的一个结果和一个退出码。它是一个不对外发布的应用，只有一个成员。

| 部分               | 回答的问题                                                            |
| ------------------ | --------------------------------------------------------------------- |
| 进程入口与参数解析 | 这行参数是帮助、版本、一个登记的命令，还是用法错误                    |
| 命令目录与帮助     | 有哪些命令，各要哪些选项；帮助文本从目录生成                          |
| 命令执行           | 一个命令怎样读本地状态、经 SDK 发出一次公开操作、在答复之后改本地状态 |
| 本地状态           | 状态目录在哪、何时创建；登录状态文件与会话归属记录怎样读写            |
| 凭据读取           | 账号凭据与秘密设置项怎样从终端或管道读进来，而不留在别处              |
| 输出与退出码       | 结果对象怎样写，退出码怎样从答复算出                                  |
| 构建身份与打包     | 版本从哪来；构建产物怎样打成归档                                      |

进程入口把参数交给解析。帮助与版本在解析处短路，不碰本地状态。其余参数按命令目录找到一个命令；命令先检查选项，再读本地状态，再经 SDK 发出请求；答复回来后按需要改本地状态，最后写结果并给出退出码。

## 领域边界

本应用拥有：进程入口 `omne`、参数解析、命令目录与帮助文本、状态目录的解析与创建、登录状态文件 `login.json` 与会话归属记录 `sessions.json`、凭据与秘密的读取、人读与机读的呈现、退出码，以及构建身份文件。

本应用不拥有任何领域规则。操作有哪些字段、各种 `outcome` 的含义与判断次序归[接入的公开契约](../../packages/access/SPEC.md#判断次序)；哪些地址可以作为服务地址、请求怎样承载归 SDK 与[HTTP 承载](../../packages/access/SPEC.md#http-承载)；本机服务端配置文件的位置与形状归 harness-server；身份、会话、人工介入与设置项的规则归各自的包组。本应用不导入服务端的任何包，不导入公开契约，不导入 Cordis。

本应用需要别人做的：

| 需要                                           | 对方           | 本应用需要它做什么                                                                                        |
| ---------------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------- |
| 治理、会话与 HITL 三个位置的客户端与 HTTP 适配 | 接入（SDK）    | 发送这三个位置的消息并关联答复；把命令需要的消息类型与构造入口重新导出；拒绝不是回环 `http:` 的地址       |
| 本机单用户档的配置文件                         | harness-server | 给出本机服务的端口。本应用只读其中的 `port`，并在自己这里重复文件位置的规则，因为一个应用不导入另一个应用 |

本应用为别人提供的：状态目录的两个公开函数（解析与创建），供别的程序复用。

## 心智模型

把 `omne` 想成服务端的一个瘦客户端。服务端是事实的权威；本机只存两样东西：一份登录证明，和「哪个会话归哪个租户」的记录。前者让之后的命令能以这份登录行事，后者存在是因为会话标识推不出租户。两份都是客户端自己的记录，丢了就重新登录，或在命令上写明租户。

一次命令就是一次公开操作。命令不重试，不猜结果：没有可信答复就是结果不确定，写出来、退出 `5`，把本次用过的标识交给调用者；调用者要重做同一件事，就带着这些标识再跑一次，服务端按标识认回。

最容易想错的三处。对已有会话的请求，租户是会话的归属租户，不是登录状态里当前选择的租户。帮助、版本与用法错误不碰状态目录，连路径都不解析。人读输出只是呈现，读不全时仍然要用退出码说清楚，不能因为已经打出了一些内容就当作成功。

## 应然设计

### 参数与用法错误

- 只有单独的 `--help` 与单独的 `--version` 是成功路径；带上任何别的参数都不再短路。其余参数必须以一个登记的命令开头。
- 命令的选项都写成 `--名字 值`，可以出现在命令名之后的任意位置；`--名字=值`、重复的选项、不属于该命令的选项、多余的位置参数都是无法识别的参数。开关（例如 `--json`）不带值，重复出现也是无法识别。一个值是下一个词，即使它以 `-` 开头，除非那个词本身是该命令的选项。
- 先读完整行参数再判缺项：有无法识别的词时报无法识别，不报缺少选项。
- `--home <目录>` 可以出现在命令名之前或之后，解析后不再留在命令的参数里。
- 用法错误只写标准错误，退出 `2`，不发送请求，不读凭据，不创建状态目录。命令自己的用法错误消息以命令名开头。

### 帮助与版本

- 帮助文本由命令目录生成，不是另一份手写文档。它只列每个命令的必需选项。新增一个命令就是在目录里登记一条，帮助随之变化。
- 版本取构建写在产物旁的身份文件，不读 `package.json`、git 或别的产物。打印的版本跟随实际运行的产物。身份文件缺失、不可读或内容不合时，`--version` 写身份错误并退出 `1`，不抛出异常。只有 `--version` 读身份文件。
- 帮助、版本与用法错误三条路径不解析、不创建、不修改任何状态目录，`OMNE_HOME` 指向什么都一样。

### 服务地址

服务地址依次取：`--server`；环境变量 `OMNE_SERVER`；会话命令与治理命令取登录状态里记下的签发地址；`register` 与 `login` 取本机服务端配置文件给出的端口，地址是 `http://127.0.0.1:<port>`；最后是默认地址 `http://127.0.0.1:8787`，与 harness-server 本机配置的默认端口相同。

- 本机配置文件不存在时取下一项。文件存在却读不出端口，或指明位置的环境变量不是绝对路径时，命令退出 `1` 并写一行原因，不读凭据，不发请求。
- SDK 的适配拒绝一个地址时，按用法错误处理，退出 `2`。

### 状态目录

- 状态目录依次取：去掉首尾空白后非空的 `--home`；去掉首尾空白后非空的 `OMNE_HOME`；`$HOME/.omne`。只有空白的 `--home` 跳到下一项；`OMNE_HOME` 存在但为空是错误，不退回默认目录；没有家目录也是错误。解析只算路径，不访问文件系统。
- 创建只在路径缺失时建出目录与缺失的上级，新建的目录权限 `0700`。路径被普通文件或别的非目录占用、上级不是目录、没有权限时答错误并带系统错误码，不删除占用者，不抛出异常。
- 只有 `login` 创建状态目录，而且在发出请求之前创建；创建失败就不发凭据。其余命令只读目录，目录不存在时退出 `1`，不创建。`register` 不碰状态目录，带 `--home` 是用法错误。

### 凭据与秘密

- 账号凭据与秘密设置项都不从命令行读，因为命令行会进入进程列表与 shell 历史。
- 标准输入是终端时，先在标准错误写提示，再不回显地读一行；终端关不掉回显时退出 `1`，不退回带回显的读取。标准输入不是终端时读到第一个换行或输入结束。读到空串退出 `2`，不发请求。
- 凭据与秘密只进入请求。它们不进入标准输出、标准错误（提示除外）、状态目录与错误文本。写秘密设置项的结果只回显请求编号、租户与配置时刻。

### 登录状态

- `login.json` 是唯一持有登录证明的地方。写入经同目录的临时文件再改名，失败时旧文件原样；文件权限 `0600`，已有目录的权限不改。
- 在 POSIX 上，读文件之前核权限：组或其他用户有任何权限位时退出 `1`。Windows 上不收紧也不检查访问控制，因为那里的权限位说明不了访问控制表。
- 文件不存在是「没有登录」，内容不是预期形状是「登录状态无效」，两者都退出 `1` 且不创建目录。登录证明过期或被撤销由服务端答 `denied`，命令照常输出结果。
- `login` 签发成功而写不下文件时，照常输出结果（去掉登录证明），在标准错误写原因，退出 `1`。这份登录在本机没有持有者，同一账号可以凭输出里的登录标识撤销它。
- 切换当前租户只在答复 `succeeded` 时改写文件里的租户，其余结果与结果不确定都不改；切换只影响之后的命令。撤销本登录且答复 `succeeded` 或 `no-change` 时删除 `login.json`，不删状态目录与会话归属记录；文件已不在不算失败；不知道本登录的标识时是用法错误，不发请求。

### 会话归属

- 会话的归属租户在创建时定下，之后不变。新建会话以当前选择的租户行事；创建成功后在 `sessions.json` 里记下「会话标识到归属租户」，别的内容不存，写法同登录状态。
- 对已有会话的请求，租户依次取 `--tenant`、归属记录；两者都没有是用法错误，不发请求，绝不回落到当前选择的租户。给了 `--tenant` 就不读记录。
- 记录文件不存在是没有记录。读不出、形状不对或含不是租户文本的值是本地失败，退出 `1`，不当作没有记录：坏掉的文件不能让一个已知的会话看起来未知。
- 新建会话在发请求之前先读记录，文件坏了就不发，免得建出一个记不下的会话。会话已建而记录写不下时，照常输出结果，退出 `1`，之后对它的命令要带 `--tenant`。

### 命令与操作

- 每个命令对应公开契约的一个操作，命令名等于操作名，经 SDK 发出。字段、结局与判断次序以公开契约为准，本应用不另加规则。
- 命令为每次执行生成新的消息标识；创建、接受、输入、控制与答复的标识缺省时也各生成一个新值。调用者要重做同一次意图，用对应的选项传回原值；消息标识不必沿用。
- 治理命令与设置命令以登录状态里的租户行事，不接受别的租户。命令在读登录状态之前先检查选项。服务端声明本部署不提供某个操作时答 `stage-not-provided`，命令照常输出，退出 `3`，不当作错误。
- 设置命令只读写行事租户自己这一层；部署默认由运维者在本机写，本应用不提供写它的路径。

### HITL 命令

- 列卡、读卡与答复三个命令的租户取 `--tenant`，没有时取登录状态里的租户。列卡一次只读一页，带会话时是该会话的卡，不带时是待办池。
- 答复的选项、原话与跳过恰好给出一个。答复标识缺省时生成；同一次答复的重试必须传回原来的答复标识，新的标识是一次新的答复。三种成功的答复都退出 `0`。

### 分页读取

读历史与读诊断投影一次读完一个会话，规则相同：

- 只有第一页的请求带筛选与页大小；之后每页只带上一页答复里的游标原文，因为公开契约拒绝游标旁的这些字段。每页用新的消息标识。
- 只有页报告读完才算读完，空页不算。诊断页里的缺口是结果的一部分，不改变退出码，不写标准错误。
- 读不完整时仍输出已经读到的部分，在标准错误写停在哪一页、为什么，退出码非零：停在某页的结局按结局映射；没有可信答复为 `5`；答复不是该种页、缺游标、游标不前进或页数超过上限为 `1`。
- 缺省输出给人读，不是 JSON；加 `--json` 时输出一个结果对象。诊断的人读输出用拥有者自己的词写原因，不含供应商错误原文、消息正文或工具参数；来源没有给出的值写 `unknown`，有原因时带上原因。

### 命令结果与退出码

- 命令向标准输出写一个结果对象加换行，人读的分页读取除外。结果对象带：收到可信答复还是结果不确定；收到时带结局与答复体（登录的答复体去掉登录证明）；总是带本次发送用到的各个标识，让调用者能用原标识重做。
- 标准输出不含登录证明、凭据、签发者与游标密钥。标准错误只在本地失败、凭据提示、用法错误与结果不确定时有内容。结果不确定或结局为 `unknown` 时，标准错误另写一行「结果不确定」。
- 退出码：`0` 成功或无变化；`1` 本地失败（身份文件、状态目录、登录状态、会话归属记录、凭据读取、标准输出写入）；`2` 用法错误，含服务地址不合法；`3` 其余非成功结局；`4` 依据不可用，稍后可再试；`5` 结果不确定或结局为 `unknown`。`3` 到 `5` 只由答复与结局决定，不由 HTTP 状态码决定。成功之后写不下本地文件时退出 `1`，优先于 `0`。
- 进程设置退出码而不立即退出，等标准输出写完。

### 构建身份与安装闭包

- 构建先清空产物，编译，再把包名与版本写进产物旁的身份文件。
- 运行时依赖只有 SDK；构建产物只导入 Node 内置模块、同一产物里的模块与 SDK。`bin` 指向带 `node` shebang 的入口，发布只带产物。
- 打包在自己的临时目录里构建，再写出一个新的归档；它不删除、不改写本应用的产物，所以运行产物的测试可以同时进行。打包与构建脚本是同一组步骤，改一处要同时改另一处。归档是构建产物，不安装命令，不上传。
- 终端界面只属于表现层：同一个命令在终端与管道上得到同一个结果与退出码。

## 原则与约束

- 服务端是事实的权威。本机只存登录证明与会话归属，不缓存服务端的事实，不替服务端判断。
- 结果不知道就是不知道：不重发，不写成成功或失败，交出原标识让调用者认回。
- 秘密只进请求。新增任何输出、日志或本地文件，先确认它不带凭据、登录证明与秘密。
- 本地失败与服务端结局分开报：本地写不下用 `1`，服务端结局用 `0`、`3`、`4`、`5`，不混用。
- 命令目录是帮助与解析的唯一来源；新增命令只在目录里登记，帮助测试的夹具随之更新。
- 只依赖 SDK。需要的消息类型由 SDK 重新导出，不直接导入公开契约或服务端包。
- 本平台规则只对 macOS 与 Linux 作承诺；Windows 上路径、错误码与文件权限的差异写在对应规则里。

| ------ | ------------------------------------------------------------------------------------------ | -------------------------------------------------------- | -------------------------------------------------------------------------- |
| CLI-01 | 帮助、版本与用法错误不解析、不创建、不修改任何状态目录                                     | 只想看帮助的人在家目录里被建出目录，或已有目录被改动     | `help-version`、`usage-errors` 的进程用例                                  |
| CLI-02 | 只有 `login` 创建状态目录，且在发出请求之前创建；创建失败不发凭据                          | 签发成功却无处保存证明；别的命令留下空目录               | `commands` 用例的状态目录规则；`state-directory` 用例                      |
| CLI-03 | 帮助文本由命令目录生成，与夹具逐字相同                                                     | 帮助与实际接受的参数不一致                               | `catalog`、`parse-argv`、`help-version` 用例对 `tests/fixtures` 的帮助文本 |
| CLI-04 | 退出码 `3` 到 `5` 只由答复与结局决定                                                       | 同一结局在不同承载下得到不同退出码，脚本误判             | 退出码映射函数的穷尽分支；`commands` 用例的退出码表                        |
| CLI-05 | 结果不确定时退出 `5` 并在标准错误注明，不写成成功或失败                                    | 调用者把可能已生效的操作当作没发生而换标识重做           | `commands`、`read-history` 用例                                            |
| CLI-06 | 凭据、登录证明与秘密不出现在标准输出、标准错误（提示除外）、状态目录的其他文件与错误文本里 | 秘密泄漏到日志、终端记录或别的文件                       | `commands`、`setting-command`、`login-state` 用例                          |
| CLI-07 | 对已有会话的请求，租户是归属租户，从不回落到当前选择的租户                                 | 请求以错误的租户行事，被拒或作用到别的租户               | `session-owner-tenant` 用例                                                |
| CLI-08 | 坏掉的会话归属记录是失败，不是没有记录；坏记录时不发新建会话的请求                         | 已知会话被当作未知，或建出一个记不下的会话               | `session-owners`、`session-owner-tenant` 用例                              |
| CLI-09 | 登录状态与会话归属记录经临时文件加改名写入，失败时旧文件不变；文件权限 `0600`              | 写到一半的文件让之后的命令全部失败；别的用户读到登录证明 | `login-state`、`session-owners` 用例                                       |
| CLI-10 | 在 POSIX 上，组或其他用户有权限位的 `login.json` 被拒绝                                    | 被别人读过的登录证明继续被使用                           | `login-state` 与 `commands` 用例（Windows 上跳过）                         |
| CLI-11 | 分页读取的后续请求只带游标；读不完整时退出码非零                                           | 服务端答协议拒绝；不完整的历史被当作完整                 | `read-history`、`read-session-diagnostics` 用例                            |
| CLI-12 | 运行时依赖只有 SDK，构建产物只导入 Node 内置模块、同产物模块与 SDK                         | 安装闭包里混进服务端包，命令行工具无法单独安装           | `package-boundary` 用例                                                    |
| CLI-13 | 打包不删除、不改写本应用的构建产物                                                         | 并行运行的产物测试读到半成品                             | `packaging` 用例                                                           |
