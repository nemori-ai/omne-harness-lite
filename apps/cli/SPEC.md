# @omne-harness/cli

## 总体架构

终端应用 `omne` 回答一个问题：一个人或一段脚本在 shell 里怎样驱动一个 Harness Server。一行命令变成一次公开操作，答复变成标准输出上的一个结果和一个退出码。它是一个不对外发布的应用，只有一个成员。

| 部分               | 回答的问题                                                            |
| ------------------ | --------------------------------------------------------------------- |
| 进程入口与参数解析 | 这行参数是帮助、版本、一个登记的命令，还是用法错误                    |
| 命令目录与帮助     | 有哪些命令，各要哪些选项；帮助文本从目录生成                          |
| 命令执行           | 一个命令怎样读本地状态、经协议客户端发出一次公开操作、在答复之后改本地状态 |
| 本地状态           | 状态目录在哪、何时创建；登录状态文件与会话归属记录怎样读写            |
| 凭据读取           | 账号凭据与秘密设置项怎样从终端或管道读进来，而不留在别处              |
| 输出与退出码       | 结果对象怎样写，退出码怎样从答复算出                                  |
| 构建身份与打包     | 版本从哪来；构建产物怎样打成归档                                      |

进程入口把参数交给解析。帮助与版本在解析处短路，不碰本地状态。其余参数按命令目录找到一个命令；命令先检查选项，再读本地状态，再经协议客户端发出请求；答复回来后按需要改本地状态，最后写结果并给出退出码。

## 领域边界

本应用拥有：进程入口 `omne`、参数解析、命令目录与帮助文本、状态目录的解析与创建、登录状态文件 `login.json` 与会话归属记录 `sessions.json`、凭据与秘密的读取、人读与机读的呈现、退出码，以及构建身份文件。

本应用不拥有任何领域规则。操作有哪些字段、各种 `outcome` 的含义与判断次序归各领域的协议契约与[接入的公开契约](../../packages/access/SPEC.md#判断次序)；请求怎样承载、一次调用有哪两种本地结果归 SDK 的客户端核心与[HTTP 承载](../../packages/access/SPEC.md#http-承载)；本机服务端配置文件的位置与形状归 harness-server；身份、会话、人工介入、会话诊断与设置项的规则归各自的包组。本应用只导入 SDK 的客户端核心、公开契约的共同部分、下表的协议契约与命令领域的纯契约；不导入服务端的任何包，不导入接入插件，不导入 Cordis。命令领域的纯契约只用来在发输入之前认出所见，认的规则仍归命令领域。

本应用需要别人做的：

| 需要                                           | 对方           | 本应用需要它做什么                                                                                        |
| ---------------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------- |
| 协议客户端核心与 HTTP 传输                     | 接入（SDK）    | 由协议契约得到协议客户端；发送一次调用并关联答复；答复为两种本地结果之一时如实交出：不确定，或确定没有发出 |
| 身份、会话、会话诊断、人工介入、资产、工具、日程、日历、通知、模型、工作区、用量、媒体十三个协议契约 | 各领域         | 操作、正文、结局与身份要求的定义；本应用只用其中命令对应的操作                                            |
| 识别一段输入点名了什么 | 命令（纯契约） | 按会话此刻的清单认出开头的命令与引用，交出所见；发输入时随输入交出，回执里写明 |
| 本机单用户档的配置文件                         | harness-server | 给出本机服务的端口。本应用只读其中的 `port`，并在自己这里重复文件位置的规则，因为一个应用不导入另一个应用 |

本应用为别人提供的：状态目录的两个公开函数（解析与创建），供别的程序复用。

## 心智模型

把 `omne` 想成服务端的一个瘦客户端。服务端是事实的权威；本机只存两样东西：一份登录证明，和「哪个会话归哪个租户」的记录。前者让之后的命令能以这份登录行事，后者存在是因为会话标识推不出租户。两份都是客户端自己的记录，丢了就重新登录，或在命令上写明租户。

一次命令就是一次公开操作。命令不重试，不猜结果：没有可信答复就是结果不确定，写出来、退出 `5`，把本次用过的标识交给调用者；调用者要重做同一件事，就带着这些标识再跑一次，服务端按标识认回。请求确定没有发出（连不上，或协议没挂着），或服务端明确答「挂着的协议里没有这个操作」，是另一回事：那是依据不可用，退出 `4`，什么也没有发生，可以稍后再跑。后一种多半是服务端比命令行旧。

最容易想错的三处。对已有会话的请求，租户是会话的归属租户，不是登录状态里当前选择的租户。帮助、版本与用法错误不碰状态目录，连路径都不解析。人读输出只是呈现，读不全时仍然要用退出码说清楚，不能因为已经打出了一些内容就当作成功。

## 应然设计

### 参数与用法错误

- 只有单独的 `--help` 与单独的 `--version` 是成功路径；带上任何别的参数都不再短路。其余参数必须以一个登记的命令开头。
- 命令的选项都写成 `--名字 值`，可以出现在命令名之后的任意位置；`--名字=值`、重复的选项、不属于该命令的选项、多余的位置参数都是无法识别的参数。只有命令点名可以重复的选项例外，现在是发输入与插队的 `--attach`：它的值按给出的次序成一列。开关（例如 `--json`）不带值，重复出现也是无法识别。一个值是下一个词，即使它以 `-` 开头，除非那个词本身是该命令的选项。
- 先读完整行参数再判缺项：有无法识别的词时报无法识别，不报缺少选项。
- `--home <目录>` 可以出现在命令名之前或之后，解析后不再留在命令的参数里。
- 用法错误只写标准错误，退出 `2`，不发送请求，不读凭据，不创建状态目录。命令自己的用法错误消息以命令名开头。

### 帮助与版本

- 帮助文本由命令目录生成，不是另一份手写文档。它只列每个命令的必需选项。新增一个命令就是在目录里登记一条，帮助随之变化。
- 版本取构建写在产物旁的身份文件，不读 `package.json`、git 或别的产物。打印的版本跟随实际运行的产物。身份文件缺失、不可读或内容不合时，`--version` 写身份错误并退出 `1`，不抛出异常。只有 `--version` 读身份文件。
- 帮助、版本与用法错误三条路径不解析、不创建、不修改任何状态目录，`OMNE_HOME` 指向什么都一样。

### 服务地址

服务地址依次取：`--server`；环境变量 `OMNE_SERVER`；会话命令与治理命令取登录状态里记下的签发地址；`register` 与 `login` 取本机服务端配置文件给出的端口，地址是 `http://127.0.0.1:<port>`；最后是默认地址 `http://127.0.0.1:8787`，与 harness-server 本机配置的默认端口相同。

- 本机配置文件不存在时取下一项。文件存在却读不出端口，或指明位置的环境变量不是绝对路径时，命令退出 `1` 并写一行原因，不读凭据，不发请求。
- 命令行自己只接受回环地址：协议是 `http:`，主机是 `127.0.0.1` 或 `localhost`，没有用户信息、路径、查询与片段。别的地址在建传输之前被拒绝，按用法错误处理，退出 `2`，不读凭据，不发请求。

### 状态目录

- 状态目录依次取：去掉首尾空白后非空的 `--home`；去掉首尾空白后非空的 `OMNE_HOME`；`$HOME/.omne`。只有空白的 `--home` 跳到下一项；`OMNE_HOME` 存在但为空是错误，不退回默认目录；没有家目录也是错误。解析只算路径，不访问文件系统。
- 创建只在路径缺失时建出目录与缺失的上级，新建的目录权限 `0700`。路径被普通文件或别的非目录占用、上级不是目录、没有权限时答错误并带系统错误码，不删除占用者，不抛出异常。
- 只有 `login` 创建状态目录，而且在发出请求之前创建；创建失败就不发凭据。其余命令只读目录，目录不存在时退出 `1`，不创建。`register` 不碰状态目录，带 `--home` 是用法错误。

### 凭据与秘密

- 账号凭据与秘密设置项都不从命令行读，因为命令行会进入进程列表与 shell 历史。
- 标准输入是终端时，先在标准错误写提示，再不回显地读一行；终端关不掉回显时退出 `1`，不退回带回显的读取。标准输入不是终端时读到第一个换行或输入结束。读到空串退出 `2`，不发请求。
- 凭据与秘密只进入请求。它们不进入标准输出、标准错误（提示除外）、状态目录与错误文本。写秘密设置项的结果只回显请求编号、租户与配置时刻。

### 登录状态

- `login.json` 是唯一持有登录证明的地方。写入经同目录的临时文件再改名，失败时旧文件原样；文件权限 `0600`，已有目录的权限不改。
- 在 POSIX 上，读文件之前核权限：组或其他用户有任何权限位时退出 `1`。Windows 上不收紧也不检查访问控制，因为那里的权限位说明不了访问控制表。
- 文件不存在是「没有登录」，内容不是预期形状是「登录状态无效」，两者都退出 `1` 且不创建目录。登录证明过期或被撤销由服务端答 `denied`，命令照常输出结果。
- `login` 签发成功而写不下文件时，照常输出结果（去掉登录证明），在标准错误写原因，退出 `1`。这份登录在本机没有持有者，同一账号可以凭输出里的登录标识撤销它。
- 切换当前租户只在答复 `succeeded` 时改写文件里的租户，其余结果与结果不确定都不改；切换只影响之后的命令。撤销本登录且答复 `succeeded` 或 `no-change` 时删除 `login.json`，不删状态目录与会话归属记录；文件已不在不算失败；不知道本登录的标识时是用法错误，不发请求。

### 会话归属

- 会话的归属租户在创建时定下，之后不变。新建会话以当前选择的租户行事；创建成功后在 `sessions.json` 里记下「会话标识到归属租户」，别的内容不存，写法同登录状态。
- 对已有会话的请求，租户依次取 `--tenant`、归属记录；两者都没有是用法错误，不发请求，绝不回落到当前选择的租户。给了 `--tenant` 就不读记录。
- 记录文件不存在是没有记录。读不出、形状不对或含不是租户文本的值是本地失败，退出 `1`，不当作没有记录：坏掉的文件不能让一个已知的会话看起来未知。
- 新建会话在发请求之前先读记录，文件坏了就不发，免得建出一个记不下的会话。会话已建而记录写不下时，照常输出结果，退出 `1`，之后对它的命令要带 `--tenant`。

### 命令与操作

- 日历与日程的命令按协议分组：`calendar <命令>` 与 `schedule <操作>`。日历的两个只读操作各一个命令，日期问题按种类各一个命令（判一天、数工作日、平移、列出、取第几个），参数只有日期与个数，没有日历与版本；日程的读操作各一个命令，Job 的读也是：列一份安排或整个租户的 Job 与处置，看一份 Job；取消一份 Job 与直接发起一份 Job 各一个命令，带 `--query` 时认回原来的写；建与管理的每个动作各一个命令（改名、改文字、改草稿、替换、转正、暂停、恢复、停止、丢弃），带 `--query` 时按同一个客户端编号认回原来的写；列表缺省不列终态，`--all` 才列。日程的定义从一个 JSON 文件读，原样交给服务端，本应用不解读它。
- 通知的命令是 `notification <动作>`，行事的是租户的 owner，收件箱是人的那一个。`send` 以 owner 自己的来源 `owner.posts` 发一条并点名 owner，缺省由命令生成发送标识并在输出的 `request` 里写出来；给了 `--event` 就用给的，同一个标识同样的内容再发是认回。结果不知道时退出 `5`，标准错误另写一行怎样用 `sent` 按同一个标识查。`sent` 查原来那次发送，不发。`list` 缺省只列未了结的前 20 条，`--all` 列全部，`--after` 接着上一页。`show` 读一条。`seen`、`done`、`dismiss`、`restore` 是同一个操作的四个取值。`sources` 列来源与事件类型。订阅、节拍与投递去处不在命令行里。

- 每个命令对应一个协议契约的一个操作，命令名等于操作名，经协议客户端发出。字段、结局与判断次序以协议契约为准，本应用不另加规则。
- 登录证明放 `Authorization` 头。操作要求以租户行事时，租户放 `omne-acting-tenant` 头；别的操作不带租户头。注册与登录不带任何身份头。
- 协议客户端对不合契约的消息体拒绝发出；命令把它当作用法错误，退出 `2`。
- 答复体照线上收到的原样打印：命令写出的是服务端说的，不是本地编解码之后的值。答复合不合契约仍由协议客户端判。
- 命令为每次执行生成新的消息标识；创建、接受、输入、控制与答复的标识缺省时也各生成一个新值。调用者要重做同一次意图，用对应的选项传回原值；消息标识不必沿用。
- 治理命令与设置命令以登录状态里的租户行事，不接受别的租户。命令在读登录状态之前先检查选项。服务端声明本部署不提供某个操作时答 `stage-not-provided`，命令照常输出，退出 `3`，不当作错误。
- 发输入可以加 `--after-run`：一轮在跑时这句话等这一轮结束再交入，正文带 `afterRun: "yes"`；插队不收这个开关。
- 发输入与插队（`send-input`、`interrupt-input`）发同一种正文，共用受理标识与输入标识的生成，插队的答复多一个 `as`：`interrupt` 是交给了当前这一轮，`ordinary` 是当时没有一轮、按普通输入受理。
- 文字里有斜杠时，发输入与插队先读这个会话的清单，用命令领域的识别函数认出所见，随输入交出；回执的 `request.seen` 写所见（开头的命令与引用的全名，都没有就是空的），清单读不到时写 `unknown` 并且不带所见。服务端按当下的清单再认，对不上就拒收并写明原因。
- 发输入与插队可以带附件：`--attach <文件>` 可以给多次，`--text` 与 `--attach` 至少给一样。命令先把每个文件读进来（类型取文件名的后缀，与 `media put` 相同；后缀认不出是用法错误，读不出是本地失败，这两种都在发出任何请求之前停下），再照 `media put` 的三步逐个上传，然后发一条用户消息：文字块在前（有文字时），每份附件一个带内容引用的块跟在后面，图片、语音、其余文件各是自己的种类。某一份上传没有成时命令停下，打印那一次的答复，并在标准错误写明哪个文件没有被收下、输入没有发出。
- 归档与撤销归档（`archive-session`、`unarchive-session`）是会话的控制，控制标识缺省时生成，重做同一次意图要传回原值。`list-sessions` 读行事租户没有归档的会话，`list-archived-sessions` 读已归档的；两个命令的每一行都带会话的关系（`main`、`child`、`handoff`）、父会话或交接的来源、根、层、值守与定义，都能用 `--relation`、`--parent`、`--attendance`、`--definition` 筛选，取值不认识是用法错误。两个命令的租户都取 `--tenant`，没有时取登录状态里的租户；只把给了的筛选放进正文。`list-archived-sessions` 另有这些筛选：`--since`（含）、`--before`（不含）按协议的时刻规则读，读不懂是用法错误；`--by` 只认 `person`、`auto`、`parent`；`--title` 是标题里的字；`--limit` 与 `--cursor` 同分页读取。
- 设置命令只读写行事租户自己这一层；部署默认由运维者在本机写，本应用不提供写它的路径。
- 设置命令缺省指资产的设置项；加 `--independent` 指独立设置：`setting list --independent` 列出本租户的独立设置，`setting show|set|unset --independent <提供者>/<定义> <项>` 指到一项。两种不一起列。
- `setting set` 写普通项时，值可以从命令行读一个 JSON 值，原样交给服务端，由设置按声明校验；秘密项仍从终端或管道读，不从命令行读。
- 资产协议的操作要租户、分页与修订号，命令不为此加参数：租户取登录状态里的租户；`setting list` 在命令里读完全部页，只有第一页之后的请求带上一页的游标，任何一页不是成功就以该页的结局收口，一页不推进游标是本地失败，退出 `1`；`setting set` 与 `setting unset` 先读这一项取得修订号，再带着它写，每次写用新的操作标识。读不到这一项就不写，如实报读的结局。写入被答修订冲突时命令如实报冲突，不自己重试。`setting show` 的人读输出对秘密项分两层写「已设置」「未设置」「已吊销」「读不出」四种状态，不含配置时刻，因为资产协议的答复不带它；不是秘密项时写明项的种类，请用 `--json` 读。
- 选模型（`select-model`）是会话的控制，带会话与目标路由名，控制标识缺省时生成。答复未知时，重做同一次意图要传回原来的控制标识。
- 列出模型（`list-models`）经协议 `model/v1` 问 Model，租户缺省取登录的那一个。读模型选择（`read-model-selection`）答一个会话当前选中的路由名。建会话可以带 `--model`。发输入与插队可以带 `--model`：先调选模型，控制标识由提交标识得出（`model:` 加提交标识），所以重做同一条命令只选一次；选不上就不发输入，标准输出是选模型的答复，标准错误写明输入没有发出。
- 选工作区（`select-workspace`）是会话的控制，带会话与目标：`--workspace` 与 `--instance`，或 `--none` 表示不要工作区。控制标识的规矩同选模型。读工作区选择（`read-workspace-selection`）答一个会话站在哪个工作区实例，以及此刻开始一步时的工作目录与状态（默认、附着、用不了）。建会话（`create-session`）可以带 `--workspace` 与 `--instance`，两个一起给或都不给。
- 工作区命令按协议分组：`workspace register <目录>`、`workspace list`、`workspace show <工作区>`、`workspace associate <工作区> <目录>`、`workspace dissociate <工作区> <实例>`、`workspace grant <工作区> <租户>`、`workspace grant-admin|revoke-admin <工作区> <租户>`、`workspace remove <工作区> <租户>`、`workspace leave <工作区>`、`workspace destroy <工作区>`。租户取登录状态里的租户。目录在客户端解析成绝对路径再发出，本机解析得出真实路径时发真实路径：它指的是服务端所在节点上的目录。`register` 可以带 `--type` 指定管理类型。`destroy` 不带 `--yes` 时只说明它了结登记与全部关系、不删除目录，然后退出 `2`。提交结果不确定时退出 `5`，并把操作标识打印在标准错误里；同一条命令加 `--resume <操作标识>` 先认回原结局。
- 资产命令按协议分组：`asset categories`、`asset list <类别>`、`asset show <类别>:<名字>`、`asset create <类别>:<名字>`、`asset enable|disable|remove <类别>:<名字>`、`asset watch`。它对任何类别相同，命令里没有类别的名字。租户取登录状态里的租户；`list` 在命令里读完全部页，规则同 `setting list`。
- `asset create` 两种给法，恰好给一种：`--data` 给一段 JSON 或 `@文件`，原样交给服务端；`--dir` 给一个本机目录。`--dir` 是三个操作的合成：遍历目录里的普通文件，包内路径用 `/`；先开始，照答复给的段长与各路径已收到的字节数逐段追加，最后提交；三步用同一个操作标识。目录里有符号链接或别的读不了的条目时报错退出，一个字节也不传，不悄悄跳过。本机不判上限，被拒的原因照服务端答的打印。
- `asset enable`、`disable`、`remove` 先看这一份取得持有引用，再带着它提交；看不到就不提交，如实报读的结局。`remove` 不带 `--yes` 时只说明移除不可逆、设置会退出，然后退出 `2`。
- 资产命令的提交结果不确定时退出 `5`，并把操作标识打印在标准错误里；同一条命令加 `--resume <操作标识>` 先认回原结局，`create --dir` 没提交过时从已收到的地方续传。`asset watch` 开着观察，每收到一帧打印一行，直到被中断。
- MCP 命令按协议 `mcp/v1`：`mcp list` 一行一个接入点（名字、连接、凭据、能不能用、动作数，用不了的那格写原因）；`mcp show <名字>` 分行写这些，再加清单取到没有与各动作的名字、摘要和能不能用，没取到的写原因；`mcp refresh <名字>` 让服务端刷新一次清单，写结果一行（已发布、被后一次取代、已取消，或失败与原因）。租户取登录状态里的租户。都带 `--json` 输出原始答复。原因的字面与 agent 搜工具时看到的一致，由服务端写，命令不另写。没有这个接入点与它对你不可用，答得一样（`not-visible`，退出 `3`）。刷新失败退出 `3`；结果不知道时退出 `5`，用 `mcp show` 认回，不重发。
- 媒体命令按协议 `media/v1`：`media put --file <路径>` 把一个本机文件传成一份媒体并打印内容引用；`media get --ref <引用的 JSON> --out <路径>` 把一份媒体读回成文件；`media describe --ref <引用的 JSON>` 读它的状态与媒体事实。租户取登录状态里的租户。
- `media put` 是三个操作的合成：开始上传，照答复给的分片大小从答复说的下一个序号起逐片追加，最后带着整份文件的摘要提交。媒体类型取文件名的后缀（png、jpg、jpeg、webp、wav、pdf），后缀认不出时要给 `--media-type`，不给就报用法错误，一个字节也不传。上传的名字由命令自己起；结果不确定时退出 `5`，并把这个名字打印在标准错误里，同一条命令加 `--upload <名字>` 从服务端说的地方接着传，已提交的再提交一次得到同一个引用。
- `media get` 逐页读到没有下一页才写文件，中途被拒时不留半份文件，照服务端答的打印并退出 `3`；写不了文件退出 `1`。打印的是读回的字节数、媒体类型与摘要。

### HITL 命令

- 列卡、读卡与答复三个命令走人工介入协议，租户取 `--tenant`，没有时取登录状态里的租户。列卡一次只读一页，带会话时是该会话的卡，不带时是待办池。读到系统放行卡时，在机读的结果之外，人读的通道逐行打印工具与命令、动作所属关口的名字、动作由程序发起时的一行来源、五档各管多大，以及放行详情的条目；带种类的值不打印，卡上写着工具没能给出详情时照实打印这一句。
- 答复的选项、原话与跳过恰好给出一个。答复标识缺省时生成；同一次答复的重试必须传回原来的答复标识，新的标识是一次新的答复。三种成功的答复都退出 `0`。

### 调用命令

- `calls` 带一个动作：`list`、`stop`、`background` 走会话协议的 `list-background-calls`、`stop-call`、`background-call`，按会话找归属租户，规则同其余会话命令；`stop` 与 `background` 只指工具调用，控制标识缺省时生成，`stop` 可带 `--reason`。`show`、`output`、`children` 走工具协议的 `read-call`、`read-call-result`、`read-call-output`、`list-call-children`，按调用引用读，租户取 `--tenant`，没有时取登录状态里的租户。
- `--call` 可以给调用引用，也可以给本会话的短号（如 `b2`）：给短号时要带 `--session`，命令先列这个会话的后台调用找到引用，找不到退出 `3`。
- `list` 缺省给人读，每项一行：短号、状态、意图、动作与输出的最后一行，有停止时写明谁停的、停到哪一步、原因；加 `--json` 时输出答复对象。
- `show` 缺省给人读：阶段与关系、终局、结果版本、效果，每个控制一行。控制进度用工具协议的原词，受理写成 `stop accepted`，只有工具证实停下才写 `stopped`，未知写 `unknown`；加 `--json` 时输出结果对象。
- `children` 列出一次调用之下的子调用，读完位置表的每一页，每个位置一行：序号、状态词、工具名与命令、动作预览、子调用的引用（还没交出的位置没有）。状态词用工具协议的原词。这次调用没有子调用时写明没有。读到一半失败时，已读到的照常打印，原因写到标准错误。
- `output` 是分页读取，按下一节的规则：结果版本缺省时先读一次调用取得。调用还没收场时读它的输出正文：已有的部分打到标准输出，下一次从哪里接着读（`--after <位置>`）写到标准错误；给了 `--after` 时只读那之后的新内容。只打印给人看的文本块，别的块只写一行种类。

### 分页读取

读历史（会话协议）与读诊断投影（会话诊断协议）一次读完一个会话，规则相同：

- 只有第一页的请求带筛选与页大小；之后每页只带上一页答复里的游标原文，因为公开契约拒绝游标旁的这些字段。每页用新的消息标识。
- 只有页报告读完才算读完，空页不算。诊断页里的缺口是结果的一部分，不改变退出码，不写标准错误。
- 读不完整时仍输出已经读到的部分，在标准错误写停在哪一页、为什么，退出码非零：停在某页的结局按结局映射；没有可信答复为 `5`；请求确定没有发出为 `4`；答复不是该种页、缺游标、游标不前进或页数超过上限为 `1`。
- 缺省输出给人读，不是 JSON；加 `--json` 时输出一个结果对象。读历史的人读输出里，消息里一块非文字的内容（图片、语音、文件）写成方括号里的种类、媒体类型与大小，后面跟它行内的文字兜底（有的话）；不读它的字节。诊断的人读输出用拥有者自己的词写原因，不含供应商错误原文、消息正文或工具参数；来源没有给出的值写 `unknown`，有原因时带上原因。
- 读历史加 `--inherited` 时，第一页请求带上它：一个分叉出的会话先读出它接着做的那段对话，再读它自己的条目。人读输出里，条目所属的会话每变一次就多一行说明（`--- inherited: session <会话> ---`、`--- this session ---`）；`--json` 里这些条目各带 `inheritedFrom`。没有分叉的会话加不加都一样。

### 搜历史

`omne search` 搜登录租户全部会话的历史（会话协议的 `search-history`）。`--text`、`--words`、`--regex` 三选一：一个原样的字面词、空白分开的几个词（都出现才算）、一条正则。范围用 `--sessions`（逗号分开）、`--archived all|only|none`、`--since` 与 `--before`；类型用 `--kinds`（`user`、`assistant`、`tool`、`reminder`、`internal`、`compaction`，逗号分开）与 `--any-visibility`（缺省只搜模型可读的）；另有 `--case-sensitive`、`--limit`、`--cursor`。

- 缺省只读一页，每个命中一行：时刻、会话与位置、种类、命中处前后的一小段（命中写在方括号里）。加 `--all` 时顺着游标读到底；每页都带同一份查询与上一页的游标。
- 一页没搜完时退出码仍是 `0`，原因写到标准错误：预算用完、最新的一段日志没读完或索引正在建，连同还没读完的会话数与建到哪了；不把没搜完写成没有命中。还有下一页时把游标写到标准错误。
- 某页的结局不是成功时，已经读到的命中照常输出，标准错误写停在哪一页与服务端答的内容，退出码按结局映射。加 `--json` 时标准输出只有一个结果对象。

### 命令结果与退出码

- 命令向标准输出写一个结果对象加换行，人读的分页读取除外。结果对象带：`result` 是收到可信答复（`response`）、结果不确定（`uncertain`）还是请求确定没有发出（`unavailable`）；收到时带结局与答复体，答复体是服务端线上写的内容（登录的答复体去掉登录证明）；总是带本次发送用到的各个标识，让调用者能用原标识重做。
- 标准输出不含登录证明、凭据、签发者与游标密钥。标准错误只在本地失败、凭据提示、用法错误、结果不确定与说得出原因的「没有发出」时有内容。请求确定没有发出时，标准输出仍只写结果对象；命令这时读一次服务端的可用性，取第一帧就停，这条命令的协议不在服务时在标准错误写一行原因：服务端没有提供这份协议，服务端提供的是它的别的主版本，或服务端上有两份在抢、都没有在服务。服务端不说可用性、连不上，或它其实在服务这份协议时，不多写。被答了的命令不问可用性；一次运行至多问一次。结果不确定或结局为 `unknown` 时，标准错误另写一行「结果不确定」。
- 退出码：`0` 成功或无变化；`1` 本地失败（身份文件、状态目录、登录状态、会话归属记录、凭据读取、标准输出写入）；`2` 用法错误，含服务地址不合法；`3` 其余非成功结局；`4` 依据不可用，稍后可再试：服务端答 `basis-unavailable`，或请求确定没有发出；`5` 结果不确定或结局为 `unknown`。`3` 到 `5` 只由答复、本地结果与结局决定，不由 HTTP 状态码决定。成功之后写不下本地文件时退出 `1`，优先于 `0`。
- 进程设置退出码而不立即退出，等标准输出写完。

### 构建身份与安装闭包

- 构建先清空产物，编译，再把包名与版本写进产物旁的身份文件。
- 运行时依赖只有 SDK、公开契约、命令用到的协议契约与命令领域的纯契约；构建产物只导入 Node 内置模块、同一产物里的模块与它们。`bin` 指向带 `node` shebang 的入口，发布只带产物。
- 打包在自己的临时目录里构建，再写出一个新的归档；它不删除、不改写本应用的产物，所以运行产物的测试可以同时进行。打包与构建脚本是同一组步骤，改一处要同时改另一处。归档是构建产物，不安装命令，不上传。
- 终端界面只属于表现层：同一个命令在终端与管道上得到同一个结果与退出码。

## 原则与约束

- 服务端是事实的权威。本机只存登录证明与会话归属，不缓存服务端的事实，不替服务端判断。
- 结果不知道就是不知道：不重发，不写成成功或失败，交出原标识让调用者认回。
- 秘密只进请求。新增任何输出、日志或本地文件，先确认它不带凭据、登录证明与秘密。
- 本地失败与服务端结局分开报：本地写不下用 `1`，服务端结局用 `0`、`3`、`4`、`5`，不混用。
- 命令目录是帮助与解析的唯一来源；新增命令只在目录里登记，帮助测试的夹具随之更新。
- 只依赖 SDK 的客户端核心、公开契约、命令用到的协议契约与命令领域的纯契约；不导入服务端包与接入插件。
- 本平台规则只对 macOS 与 Linux 作承诺；Windows 上路径、错误码与文件权限的差异写在对应规则里。
