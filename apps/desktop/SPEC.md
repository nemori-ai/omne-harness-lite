# @omne-harness/desktop

## 总体架构

桌面应用回答一个问题：一个人怎样在窗口里使用系统，而页面从不持有登录证明。它由两半组成：页面是界面外壳、登录界面与客户端的 Cordis 树；宿主替页面持有登录，经一座窄桥把页面的请求转给服务端入口，并把构建好的页面发给浏览器。宿主可以是本机的 Node 进程，也可以是桌面外壳的主进程；两者实现同一座桥，页面不变。

| 部分     | 回答的问题                                                                           |
| -------- | ------------------------------------------------------------------------------------ |
| 共享类型 | 桥长什么样：页面能向宿主要什么，宿主怎样答；页面与宿主之间的字节                     |
| 宿主核心 | 登录会话怎样持有登录证明、怎样决定一个页面请求能不能发出、带什么凭据；与桌面外壳无关 |
| 本机宿主 | 本机进程怎样把桥经同源 HTTP 交给页面，怎样发出页面的静态文件                         |
| 页面     | 桥在页面这一侧怎样接到客户端的树；外壳、登录界面与工作区的视图怎样装起来             |

页面经桥的「调用」与「观察」通道发出请求；宿主核心按自己认识的协议契约核对目标，按登录会话的状态带上凭据，再经连接发往服务端入口。登录与退出不走普通调用：页面把凭据交给桥，宿主核心发出登录操作并保存证明，页面只得到结果。

## 领域边界

本应用拥有：登录会话（状态与登录证明）、桥的通道与字节、宿主的转发规则、界面外壳、工作区的视图列表与装配。

本应用不拥有：身份、会话与设置项的规则与协议，它们归各自的包组与协议契约；连接、客户端的树与协议客户端怎样随可用性长出与收回，归接入的客户端核心与客户端装配；对话界面与设置界面归各自领域的界面模块。外壳不认识任何领域；装配文件是页面里唯一点名领域的地方。

本应用需要别人做的：

| 需要             | 对方                     | 本应用需要它做什么                                                                                 |
| ---------------- | ------------------------ | -------------------------------------------------------------------------------------------------- |
| 客户端核心与连接 | 接入（SDK 与客户端装配） | 给出传输接口与连接插件；客户端的树随服务端入口挂着的协议长出与收回协议客户端；给出登录状态源的接口 |
| 协议契约         | 身份、会话、资产         | 声明每个操作与观察的身份要求，以及哪些操作携带凭据；宿主与页面读同一份清单                         |
| 界面模块         | 会话、资产               | 给出对话视图与设置视图，接收协议客户端与当前租户                                                   |
| 服务端入口       | 接入（服务端）           | 按协议名、主版本与名字承载调用与观察；在身份协议上答复登录、注销与当前租户                         |

本应用不为别的包组实现端口。

## 心智模型

把宿主想成一个只认识几份协议契约的看门人，把页面想成一个拿不到钥匙的访客。钥匙是登录证明，只在宿主的登录会话里。页面能做的只有五件事：发一次调用，开一个观察，交出凭据要求登录，要求退出，看登录状态。宿主对每个调用与观察只问三件事：这个目标是不是我认识的契约里声明过的；它是不是一个携带凭据的操作；按现在的登录状态它该带什么凭据。

登录会话是一个有四个状态的聚合，事件与状态的每一格都有确定的答复。最容易想错的三处。退出总会删掉本机的证明，哪怕服务端是否注销不确定。一次 `denied` 不等于登录失效：它只触发一次探测，探测也答 `denied` 才算。页面发往宿主的请求失败时，页面证明不了字节没有发出，除非宿主在转发前就拒绝了它。

外壳与视图之间的关系是「挂没挂着」：一个视图要的协议挂着，它才有标签；协议撤了，视图随之卸下。切换标签只是藏起别的视图，不是卸下，所以看一眼设置不会打断对话里正在进行的一轮。

## 应然设计

### 登录会话

登录会话在宿主进程里，独占登录证明。状态四个：未登录、登录中、已登录、退出中，用四个互不相交的类型表示；登录证明只是「已登录」「退出中」两个类型的字段。

| 事件                             | 未登录                                       | 登录中                                             | 已登录                               | 退出中                                                                             |
| -------------------------------- | -------------------------------------------- | -------------------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------- |
| 应用启动，读本机保存的登录证明   | 读到就进「已登录」，读不到留在「未登录」     | 不可达                                             | 不可达                               | 不可达                                                                             |
| 页面请求登录                     | 进「登录中」，发出登录操作                   | 拒绝：正在登录                                     | 拒绝：已经登录                       | 拒绝：正在退出                                                                     |
| 登录的答复是成功                 | 不可达                                       | 保存登录证明，进「已登录」。只告诉页面「登录成功」 | 不可达                               | 不可达                                                                             |
| 登录的答复是其他结果，或结果未知 | 不可达                                       | 回「未登录」。把结果如实告诉页面，未知就说未知     | 不可达                               | 不可达                                                                             |
| 页面请求退出                     | 直接答「已经退出」                           | 拒绝：正在登录                                     | 进「退出中」，发出注销操作           | 拒绝：正在退出                                                                     |
| 注销的答复是成功或无变化         | 不可达                                       | 不可达                                             | 不可达                               | 删掉登录证明，进「未登录」                                                         |
| 注销的答复是其他结果，或结果未知 | 不可达                                       | 不可达                                             | 不可达                               | 仍然删掉本机的登录证明，进「未登录」。告诉页面：本机已退出，服务端是否已注销不确定 |
| 身份协议明确答复登录已失效       | 不变                                         | 不可达                                             | 删掉登录证明，进「未登录」，通知页面 | 删掉登录证明，进「未登录」                                                         |
| 页面请求一次普通调用             | 不带登录证明发出。需要登录的操作由服务端拒绝 | 同左                                               | 带上登录证明发出                     | 拒绝：正在退出                                                                     |

- 登录操作是身份协议的签发登录，注销是撤销登录，目标是这次登录自己的登录标识。行事租户取签发成功体里的租户。
- 登录的结果对页面只有四种：登录成功；统一认证失败答认证失败；`unknown` 与本地的结果不确定答未知；其余（字节没发出、依据不可用、本部署不提供、协议拒绝、契约读不出的消息体）答不可用。
- 「拒绝」在桥的结果类型里没有自己的值：登录被拒答不可用，退出被拒答未知。页面只在未登录时给登录、已登录时给退出，正常使用碰不到。
- 登录或注销的调用抛出异常而不是给出答复时，登录会话不停在中间状态：登录回「未登录」；注销仍然删掉本机的证明，进「未登录」。异常原样抛给调用方。
- 「身份协议明确答复登录已失效」的判定：一次带登录证明的调用答 `denied`，或带登录证明的观察以 `denied` 被拒或结束之后，登录会话用同一个证明查一次当前租户；它也答 `denied`，才是这个事件。同一时刻至多一次探测在途；结果不缓存，下一次 `denied` 再探。探测答复到达时登录会话已不再持有这个证明，事件不作用。注销在途时探测先把状态带回「未登录」，注销的答复到达时不再改变状态，结果仍按上表告诉页面。
- 一个宿主进程服务一个用的人：登录会话在进程里只有一个。保存登录证明的地方是一个可替换的凭据仓库。

### 转发规则

- 宿主只转发它认识的契约里声明的操作与观察。认识的契约是 `access/v1` 加页面的树带着的那一份协议清单，页面与宿主读同一份。目标按协议名、主版本与名字三样精确比对，带路径的名字到不了别的操作。不认识的协议、认识的协议里没有声明的名字、标了携带凭据的操作，一律答「字节没发出」，不带任何东西发往服务端。
- 「带上登录证明发出」按契约里这个操作或观察的身份要求带：不要身份的什么都不带；要登录的只带登录证明；要行事租户的带登录证明与行事租户。
- 「拒绝：正在退出」的普通调用与观察答「字节没发出」，客户端核心读作不可用。

### 宿主给页面的通道

- 桥有五条通道：调用、观察、登录、退出、登录状态。调用的答复是传输的三种结果之一：答复了（结果与体）、没发出、不确定。观察的答复是一条事件流，一帧一个事件，最后一个事件写观察怎样结束；页面断开，宿主取消这个观察。登录与退出的答复只有结果字段。登录状态先给当前状态，变了再给。其余 `GET` 是构建好的页面静态文件。
- 宿主只监听回环地址。`POST` 只收 JSON；`Host` 头必须是回环名字（`127.0.0.1`、`localhost`、`[::1]`），端口不核，因为挡住重绑定页面的是名字，经端口转发打开时浏览器看到的是另一个端口；有 `Origin` 头时必须同源。页面的 HTML 带内容安全策略：只许自己的脚本与样式，只许连同源。
- 登录证明与密码不进日志，不进错误信息。宿主的日志一事一行：被拒的请求只写方法、路径与 `Host`、`Origin` 两个头；失败的请求只写方法、路径与失败的种类，不写错误的原文，因为原文可能引用消息体。日志从不写消息体、证明或密码。
- 页面发往宿主的请求失败时，只有宿主在转发前答出的拒绝能证明字节没有发出；其余失败，调用答不确定。

### 页面

- 客户端的 Cordis 树装着连接插件（传输与登录状态都是桥）与清单里每份协议的协议客户端。登录状态流断开后，页面按退避重新跟上；读到「暂时没有可读的」时按可配置的再问策略等待，次数与总时长都有上界。
- 外壳：顶栏显示应用名、连接状态、当前租户与退出登录；没登录只显示登录门；连不上服务时显示「连不上服务」，连接按退避重连；登录门或工作区需要的协议没挂着时显示「这项能力暂时不可用」。
- 工作区的视图：装配文件给出视图的列表，每个视图有标识、标题、要的协议与怎样画。外壳给每个协议都挂着的视图一个标签，缺省选第一个；一个也没有时显示「这项能力暂时不可用」。选中视图的协议撤了，回到第一个还在的视图。切换只藏起别的视图，不卸下；协议撤了的视图随之卸下。
- 视图有两个：对话（会话协议，会话界面）与设置（资产协议，设置界面）。服务端没挂资产协议时没有设置这个标签。
- 登录界面：注册经普通调用，登录经桥的登录；交出凭据后表单立即清空；失败如实显示。登录之后查一次当前租户，交给每个视图。

## 原则与约束

- 登录证明不进页面。新增任何通道、答复字段、日志或错误文本，先确认它不带登录证明与密码。
- 页面与共享类型不导入宿主一侧，也不导入 Node 内置；宿主一侧不导入页面；外壳不导入任何领域。
- 宿主是看门人，不是代理：只转发声明过的目标，拿不准就答「没发出」，不猜着放行。
- 宿主核心与桌面外壳无关；换宿主只换承载桥的那一层，页面与宿主核心不变。
- 结果不知道就是不知道：页面证明不了没发出的，答不确定；注销结果不确定时如实告诉页面。
- 视图随协议「挂没挂着」出现与卸下；能不能用由服务端在每次调用时判断。
- 新增一个领域的视图只改装配文件与协议清单，外壳不变。

## 不变式

| 编号  | 永远成立的性质                                                     | 违反的后果                                           | 由什么守                                                                        |
| ----- | ------------------------------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------- |
| DT-01 | 登录证明与密码不出现在页面收到的任何答复、日志与错误信息里         | 页面里的脚本或日志读到登录证明                       | 登录与退出答复的类型只有结果字段；`web-host` 用例的证明哨兵；`page-bridge` 用例 |
| DT-02 | 页面与共享类型不导入宿主一侧与 Node 内置；外壳不导入任何领域       | 证明经共享代码流进页面；外壳被某个领域绑住           | `boundaries` 用例                                                               |
| DT-03 | 登录会话恰在四个状态之一；登录证明只是已登录与退出中两种状态的字段 | 未登录时仍带着证明发请求                             | 四个互不相交的状态类型；`login-session` 用例每个可达格一条                      |
| DT-04 | 宿主只转发认识的契约里声明的目标，从不转发携带凭据的操作           | 页面经桥调到未声明的操作，或替页面把证明交给别的操作 | `login-session` 用例                                                            |
| DT-05 | 退出总会删掉本机的登录证明，注销结果不确定时也一样                 | 页面以为已退出，宿主仍持有可用的证明                 | `login-session` 用例                                                            |
| DT-06 | 只有探测也答 `denied` 才判登录失效；同一时刻至多一次探测在途       | 一次越权调用就把人登出，或探测风暴                   | `login-session` 用例                                                            |
| DT-07 | 宿主只收回环名字的 `Host`、JSON 的 `POST` 与同源的 `Origin`        | 重绑定页面或别的站点经浏览器驱动宿主                 | `web-host` 用例                                                                 |
| DT-08 | 页面断开即取消对应的观察                                           | 服务端为已经不在的页面一直保持观察                   | `web-host` 用例                                                                 |
| DT-09 | 切换视图不卸下视图；协议撤了的视图卸下                             | 看一眼设置就断掉对话的观察；或撤了的协议还留着界面   | `shell` 用例                                                                    |
| DT-10 | 页面的再问策略的等待次数与总时长有上界                             | 读不到时页面无界地轮询                               | `read-retry` 用例                                                               |
