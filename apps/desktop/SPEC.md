# @omne-harness/desktop 行为规格

本文件拥有桌面应用在公开类型以外的必要行为。依据是 [RFC-0015](../../docs/rfcs/RFC-0015-access-dynamic-registration.md) 第 6 节「客户端」、第 10 节「桌面应用」与第 13 节「桌面应用主进程里的登录会话」，交付卡 #1267。

这一程的宿主是本机的一个 Node 进程（`src/web-host/`），不是 Electron 主进程。宿主里和 Electron 无关的一半在 `src/main-core/`，将来主进程原样用。页面（`src/page/`）只拿到 `src/shared/host-bridge.ts` 的 `HostBridge`。

## 登录会话

登录会话是宿主进程里的聚合（`src/main-core/login-session.ts`），独占登录证明。状态四个：未登录、登录中、已登录、退出中，用四个互不相交的类型表示；登录证明只是「已登录」「退出中」两个类型的字段。

| 事件 | 未登录 | 登录中 | 已登录 | 退出中 |
| --- | --- | --- | --- | --- |
| 应用启动，读本机保存的登录证明 | 读到就进「已登录」，读不到留在「未登录」 | 不可达 | 不可达 | 不可达 |
| 页面请求登录 | 进「登录中」，发出登录操作 | 拒绝：正在登录 | 拒绝：已经登录 | 拒绝：正在退出 |
| 登录的答复是成功 | 不可达 | 保存登录证明，进「已登录」。只告诉页面「登录成功」 | 不可达 | 不可达 |
| 登录的答复是其他结果，或结果未知 | 不可达 | 回「未登录」。把结果如实告诉页面，未知就说未知 | 不可达 | 不可达 |
| 页面请求退出 | 直接答「已经退出」 | 拒绝：正在登录 | 进「退出中」，发出注销操作 | 拒绝：正在退出 |
| 注销的答复是成功或无变化 | 不可达 | 不可达 | 不可达 | 删掉登录证明，进「未登录」 |
| 注销的答复是其他结果，或结果未知 | 不可达 | 不可达 | 不可达 | 仍然删掉本机的登录证明，进「未登录」。告诉页面：本机已退出，服务端是否已注销不确定 |
| 身份协议明确答复登录已失效 | 不变 | 不可达 | 删掉登录证明，进「未登录」，通知页面 | 删掉登录证明，进「未登录」 |
| 页面请求一次普通调用 | 不带登录证明发出。需要登录的操作由服务端拒绝 | 同左 | 带上登录证明发出 | 拒绝：正在退出 |

实现的读法：

- 登录操作是 `identity/v1` 的 `issue-login`，注销是 `revoke-login`（目标是这次登录自己的 `loginId`）。行事租户取 `issue-login` 成功体的 `tenantId`。
- 登录的结果对页面只有四种：`signed-in`；`uniform-auth-failure` 答 `auth-failed`；`unknown` 与本地的 `uncertain` 答 `unknown`；其余（字节没发出、`basis-unavailable`、`stage-not-provided`、`protocol-rejected`、契约写不出的消息体）答 `unavailable`。
- 「拒绝」在接缝四的结果类型里没有自己的值：登录被拒答 `unavailable`，退出被拒答 `unknown`。页面只在未登录时给登录、已登录时给退出，所以正常使用碰不到。
- 「拒绝：正在退出」的普通调用答「字节没发出」，客户端核心得到 `unavailable`。观察同样。
- 「身份协议明确答复登录已失效」：一次带登录证明的调用答 `denied`，或带登录证明的观察以 `denied` 被拒或结束之后，登录会话用同一个登录证明调一次 `query-current-tenant`；它也答 `denied`，就是这个事件。同一时刻至多一次探测在途；结果不缓存，下一次 `denied` 再探。探测答复到达时登录会话已不再持有这个登录证明，事件不作用。
- 注销在途时探测先把状态带回「未登录」：注销的答复到达时不再改变状态，结果仍按上表告诉页面。

## 宿主给页面的通道

`src/main-core/` 给出页面一侧的传输（`LoginSession.transport`）。宿主（`src/web-host/server.ts`）把它与登录会话经同源 HTTP 交给页面：

| 地址 | 内容 |
| --- | --- |
| `POST /bridge/call` | 一次调用。答复是传输的三种结果之一：答复了（结果与体）、没发出、不确定 |
| `POST /bridge/observe` | 开一个观察。答复是 SSE：一帧一个事件，最后一个事件写观察怎样结束。页面断开，宿主取消这个观察 |
| `POST /bridge/login` | 凭据。答复只有结果 |
| `POST /bridge/logout` | 无。答复只有结果 |
| `GET /bridge/login-state` | SSE。先给当前状态，变了再给 |
| 其余 `GET` | 构建好的页面静态文件 |

守住「登录证明不进页面」：

1. 「调用」拒绝转发契约里标了 `carriesCredential` 的操作（宿主认识的契约：`identity/v1`、`session/v1`、`access/v1`），答「没发出」。
2. 「登录」「退出」的答复只有结果字段。
3. 页面与共享类型不导入 `src/main-core/`、`src/web-host/` 与 Node 内置（用例 `tests/boundaries.spec.ts` 守）。
4. 登录证明与密码不进日志，不进错误信息。宿主的日志只写启动地址与请求失败的路径。

宿主只监听回环地址；`POST` 只收 `application/json`，`Host` 头必须是回环地址加自己的端口，有 `Origin` 头时必须同源。页面的 HTML 带内容安全策略：只许自己的脚本与样式，只许连同源。

## 页面

- 客户端的 Cordis 树：`connectionPlugin`（传输与登录状态都是桥）、`identity/v1` 与 `session/v1` 的协议客户端。
- 装配文件 `src/page/assembly.tsx` 是唯一导入领域（协议契约与领域界面）的地方。外壳（`src/page/shell/`）不导入任何领域。
- 外壳：顶栏（应用名、连接状态、当前租户、退出登录）；没登录只显示登录门；连不上服务时显示「连不上服务」，连接按退避重连；登录门或工作区需要的协议没挂着时显示「这项能力暂时不可用」。
- 登录界面：注册（`register-and-activate`，经普通调用）与登录（经桥的 `login`）；交出凭据后表单清空；失败如实显示。登录之后用 `query-current-tenant` 取当前租户，交给会话界面。

## 已知限制

- 一个宿主进程服务一个用的人：登录会话是进程里的单例。
- 凭据保存这一程只在宿主进程的内存里（`memoryCredentialStore`），进程重启要重新登录。接口 `CredentialStore` 已留好，操作系统加密保存以后实现。
- 宿主不认识的协议的操作照常转发：`carriesCredential` 只能对宿主认识的契约核对。
- 页面到宿主的请求失败时，页面不能证明字节没有发出，调用答 `uncertain`。
